# API 店頭買取管理 — 店頭買取受注コメント更新

## 業務ロジック

### 更新の判定順序

| 順序 | 判定 | 結果 |
|------|------|------|
| 1 | 認証用トークンを検証できないとき | 認証拒否（HTTP 401）とする |
| 2 | 指定した受注IDに該当する店頭買取受注が無いとき | 該当なし（HTTP 404）とする |
| 3 | コメントの項目自体が送られていないとき | 入力不正（HTTP 400）とし、「コメントを入力してください」を返す |
| 4 | 上記のいずれにも該当しないとき | コメントを更新し、あわせて更新担当者に認証した管理者会員を設定する |

コメントの項目が空文字で送られたときは未指定として扱わず、コメントを空にして更新する。

### 認証の判定

認証用トークンの署名方式はHS256とする。トークンに含まれる利用者IDから管理者会員を引き、トークンが無いとき・署名が不正なとき・該当する管理者会員が無いときは、いずれも認証拒否（HTTP 401）とする。

## 入出力

| 種類 | 内容 |
|------|------|
| 入力 | 更新対象の店頭買取受注のID（エンドポイントのパス・必須）、認証用トークン（リクエストヘッダ・必須） |
| 失敗時出力 | 認証できないときはHTTP 401、受注が無いときはHTTP 404、コメントが送られていないときはHTTP 400 |

### 入出力: 受け付けるパス

エンドポイントは拡張子 `.json` の付いたパスと、付かないパスの双方を同じ処理として受け付ける。

### 入出力: 永続化

| 操作 | 契機 |
|------|------|
| 更新 | 認証と対象の確認を通過し、コメントが送られているとき。店頭買取受注のフリーコメントと更新担当者 |
