# API 店頭買取管理 — 店頭買取受注コメント更新

## 概要

買取アプリ（MTGバイヤー）が店頭買取受注のフリーコメントを更新するためのAPIである。pf-api（買取連携用のAPIアプリケーション）が提供するJSON APIで、受注IDで対象を特定し、コメントと更新担当者を保存する。

本書は実装手順ではなく、誰が・いつ・どの条件で・結果どうなるかを読むためのリバース詳細設計とする。確認値はpf-apiのコメント更新処理、ルート定義（`config/routes.yaml`）、店頭買取受注を扱うエンティティ、共通の認証処理を正とする。

本機能のカスタマイズ区分は現行踏襲で、挙動の参照リポはpf-apiとする。DB関連の記述（テーブル名・列名・永続化先）はec-cube-enterpriseを正とする。

対象はJSON APIエンドポイントであり、ブラウザ向けの画面を持たない。本文ではフレームワークのコントローラ型名やメソッド名を主説明としない。「利用者視点の入口」にHTTPメソッドとパスパターンを書く。

---

## 本書で扱うこと

- 受注IDによる店頭買取受注の特定と、フリーコメント・更新担当者の保存
- 認証、対象なし、コメント未入力時の応答

## 本書で扱わないこと

以下は本書では仕様確定せず、実装または別APIの設計を正とする。

- 店頭買取受注そのものの登録・査定・ステータス更新（各店頭買取APIの設計を正とする）
- ネット買取受注のコメント更新（ネット買取受注コメント更新APIの設計を正とする）
- トークンの発行（買取アプリ用ログインの設計を正とする）

---

## リニューアル移行時の扱い

コメントと更新担当者の更新挙動は現行（pf-api）を正とし、永続化に関わるテーブル・列名は移行先（ec-cube-enterprise）を正とする。

| 区分 | 現行（pf-api） | 移行先（ec-cube-enterprise） |
|------|----------------|------------------------------|
| 店頭買取受注 | dtb_otc_buy_order（フリーコメント・更新担当者を保持） | 同一スキーマ（dtb_otc_buy_order） |
| 更新担当者 | dtb_member（member_id） | dtb_member（id）。会員の主キー名がidになる |

更新する列（フリーコメント・更新担当者）と入力検証（コメント未指定で入力不正）はリニューアル後も同じ前提とするが、更新担当者として記録する会員の主キー名が現行のmember_idから移行先のidへ変わる。

## 利用者視点の入口

| 入口 | URLエンドポイント | 期待されるふるまい |
|------|--------------------|--------------------|
| 店頭買取受注のコメント更新 | `PUT /admin/otcBuyOrder/{id}/freeComment` | 受注IDの店頭買取受注のフリーコメントと更新担当者を保存し、成功時はコード200のJSONを返す。 |
| 同上（拡張子あり別名） | `PUT /admin/otcBuyOrder/{id}/freeComment.json` | 上と同一処理。 |

応答形式はJSON。呼び出し元は買取アプリ（MTGバイヤー）。

---

## 認証・認可

| 観点 | 内容 |
|------|------|
| 認証方式 | `jwt-token`ヘッダのJWTを検証し、ペイロードの利用者IDから管理者会員を引く。署名方式はHS256。 |
| 認証失敗時 | ヘッダ欠落・署名不正・該当する管理者会員なしのいずれも認証拒否（HTTP 401）とする。 |
| 認可 | 認証した管理者会員が更新担当者として記録される。呼び出し可能なクライアントは買取アプリ。 |

トークン原値・署名シークレットは本書に記載しない。

---

## 処理フロー

### 店頭買取受注のコメントを更新する（PUT `/admin/otcBuyOrder/{id}/freeComment`）

1. `jwt-token`ヘッダのトークンを検証し、管理者会員を特定する。検証できない場合は認証拒否（HTTP 401）とする。
2. パスの受注IDで店頭買取受注を1件取得する。該当が無い場合は該当なし（HTTP 404）とする。
3. リクエストのコメントが未指定（null）の場合は入力不正（HTTP 400）とし、エラーメッセージを返す。
4. 店頭買取受注のフリーコメントを指定値で更新し、更新担当者に認証した管理者会員を設定して保存する。
5. コード200のJSONを返す。

## 業務ルール・計算

| 項目 | 内容 |
|------|------|
| 更新対象 | リクエストで指定されたID・入力値に対応する業務データを対象にする。対象特定、入力不正、認証・認可の判定順序は処理フローとバリデーションの各節を正とする。 |
| 更新方法 | 入力値を対象データへ上書きまたは追加登録する。履歴登録や関連データ更新がある場合は入出力の副作用およびDBカラムの節を正とする。 |
| 計算処理 | 本APIでは金額・税・ポイント・在庫数量の再計算や丸めを行わない。ステータスやコメント等の更新は、実装で定義された遷移・存在確認・担当者判定に従う。 |
| 応答値 | 成功時は処理結果コードまたは更新後に取得した値を返す。レスポンス値は本API内で独自集計せず、保存結果または取得結果をJSON応答へ整形する。 |

## 入出力

### リクエスト

| パラメータ | 位置 | 型 | 必須／任意 | 説明 |
|------------|------|----|-----------|------|
| `id` | パス | integer | 必須 | 更新対象の店頭買取受注ID。 |
| `free_comment` | ボディ（フォーム値） | string | 必須 | 設定するフリーコメント。未指定（null）の場合は入力不正（HTTP 400）となる。 |
| `jwt-token` | ヘッダ | string | 必須 | 認証用のJWTトークン。 |

### レスポンス（成功）

HTTP 200。

| フィールド | 型 | 説明 |
|------------|----|------|
| `code` | integer | 処理結果コード。成功時は200。 |

### レスポンス（失敗）

| HTTPステータス | 条件 | 本文の形 |
|----------------|------|----------|
| 401 | トークン欠落・署名不正・該当する管理者会員なし | 認証拒否（本文を持たない） |
| 404 | 受注IDに該当する店頭買取受注が無い | 該当なし（本文を持たない） |
| 400 | コメント（`free_comment`）が未指定 | `{code, errors}`（`errors`は「コメントを入力してください」） |

### サンプルレスポンス

成功時の応答例。

```json
{
  "code": 200
}
```

### 副作用

店頭買取受注のフリーコメントと更新担当者を更新する（DB更新）。参照のみではない。

応答はJSON応答整形を経て返す。プロパティはcamelCase、日時はISO8601とする。

## バリデーション

| 項目 | 内容 |
|------|------|
| `free_comment` | 必須。未指定（null）の場合は入力不正（HTTP 400）とし、「コメントを入力してください」を返す。空文字や文字数の上限はpf-api側では判定しない。 |
| `id` | パスの受注ID。該当する店頭買取受注が無い場合は該当なし（HTTP 404）とする。 |

## データ整合性

| 観点 | 内容 |
|------|------|
| 参照時点 | 更新時点で存在する店頭買取受注を対象に更新する。 |
| 更新範囲 | フリーコメントと更新担当者のみを更新する。受注の他項目・ステータスは本APIでは変更しない。 |
| 同時更新 | 同一受注への同時更新に対する排他制御は本APIでは持たない。 |

## 権限・認可

| 利用者状態 | 店頭買取受注コメント更新 |
|------------|--------------------------|
| 認証済みの管理者会員 | コメントと更新担当者を更新できる。 |
| 未認証・トークン不正 | 認証拒否（HTTP 401）となり、更新できない。 |

## エラー処理

| エラー内容 | 処理 |
|------------|------|
| 認証不可 | 認証拒否（HTTP 401）とする。 |
| 受注が存在しない | 該当なし（HTTP 404）とする。 |
| コメント未指定 | 入力不正（HTTP 400）とし、「コメントを入力してください」を返す。 |

## 排他制御・トランザクション

本APIはフリーコメントと更新担当者の更新を行う。楽観ロック・悲観ロックの対象は持たず、同一受注への同時更新は後勝ちとなる。
