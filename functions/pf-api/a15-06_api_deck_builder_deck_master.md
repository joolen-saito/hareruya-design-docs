# API デッキビルダー — マスタ検索

## 概要

デッキビルダーアプリが、カード検索やデッキ編集の選択肢として用いる各種マスタ情報を取得するためのAPIである。deck-api（デッキビルダー用のAPIアプリケーション）が提供するJSON APIで、URLのパスで指定したマスタ名に対応するマスタの全件を返す。

本書は実装手順ではなく、誰が・いつ・どの条件で・結果どうなるかを読むためのリバース詳細設計とする。確認値はdeck-apiのマスタ取得処理、ルート定義（`config/routes.yaml`）、対象マスタのリポジトリを正とする。本機能のカスタマイズ区分は現行踏襲であり、挙動はデッキビルダーAPI（deck-api）の実装を参照し、DB関連の記述はec-cube-enterpriseを正とする。

対象はJSON APIエンドポイントであり、ブラウザ向けの画面を持たない。本文ではフレームワークのコントローラ型名やメソッド名を主説明としない。「利用者視点の入口」にHTTPメソッドとパスパターンを書く。

---

## 本書で扱うこと

- パスで指定したマスタ名から公開対象マスタを特定し、全件を返すふるまい
- 公開しないマスタ・サブテーブルを持つマスタ・フォーマットマスタの扱いの違い
- 該当マスタが無い場合のふるまい

---

## 本書で扱わないこと

以下は本書では仕様確定せず、実装または別APIの設計を正とする。

- 各マスタの個々のカラム定義の網羅（対象マスタのスキーマを正とする）
- カード検索・アーキタイプ検索（別APIの設計を正とする）
- マスタ値の登録・更新（マスタ管理側の設計を正とする）

---

## リニューアル移行時の扱い

DB関連の記述はec-cube-enterpriseを正とする。挙動の参照元であるデッキビルダーAPI（deck-api）は提供リポジトリに含まれないため、現行deck-apiと移行先ec-cube-enterpriseでスキーマが異なる場合はec-cube-enterpriseを正とし、確認できない差異はec-cube-enterprise実装で要確認とする。ec-cube-enterpriseでは、フォーマット（`mtb_format`）にデッキビルダー対象フラグ（`deckbuilder_flg`）を持ち、カード種別（`mtb_cardtype`）・色（`mtb_color`）・レアリティ（`mtb_rarity`）・サブタイプ（`mtb_subtype`）・キャンペーンタグ（`mtb_campaign_tag`）・デッキタグ（`mtb_deck_tag`）等のマスタ群と、カテゴリ・タグの親子（サブテーブルを持つ`dtb`系）を持つ。各マスタの個々の列名はec-cube-enterpriseの当該マスタ定義を正とし、現行との列差は要確認とする。

| 観点 | 現行（deck-api） | 移行先（ec-cube-enterprise） |
|------|------------------|------------------------------|
| フォーマット対象フラグ | deck-api実装で要確認 | フォーマット（`mtb_format`）の`deckbuilder_flg` |
| 公開対象マスタの集合 | deck-api実装で要確認 | `mtb`系マスタ全般と追加公開の`dtb`系。権限・カード・カード詳細は非公開 |
| サブテーブルを持つマスタ | カテゴリ・タグ | カテゴリ・タグ（親子の`dtb`系を含めて取得） |

| 用語 | 説明 |
|------|------|
| マスタ | カード種別・色・レアリティ・フォーマット・デッキタグなど、選択肢の元となる固定的なデータ群。 |
| 公開しないマスタ | 本APIで返さないマスタ。権限・カード・カード詳細が該当する。 |

## 利用者視点の入口

| 入口 | URLエンドポイント | 期待されるふるまい |
|------|--------------------|--------------------|
| マスタ検索 | `GET /master/{name}` | パスのマスタ名に対応するマスタの全件を、ラッパとともに返す。公開対象でない、または存在しないマスタ名は該当なし（HTTP 404）とする。 |

応答形式はJSON。呼び出し元はデッキビルダーアプリ。

## 認証・認可

| 観点 | 内容 |
|------|------|
| 認証方式 | 認証を行わない。本APIは`jwt-token`ヘッダを参照せず、トークン検証も会員・プレイヤーの照合も行わない。 |
| 認証失敗時 | 認証処理を持たないため、認証起因の拒否（HTTP 401）を返さない。 |
| 認可 | 呼び出し可能なクライアントはデッキビルダーアプリ。利用者の状態によらず参照できる公開マスタを返す。 |

トークン原値・署名シークレットは本書に記載しない。

## 処理フロー

### マスタを取得する（GET `/master/{name}`）

1. パスのマスタ名を受領し、アンダースコア区切りをキャメルケースへ変換した上で先頭を大文字化したマスタ識別名を組み立てる。
2. マスタ識別名が追加公開対象（カテゴリ・カテゴリ並び順・会員区分・割引カード条件・タグ並び順）であれば`Dtb`系のマスタ、それ以外は`Mtb`系のマスタを対象とする。
3. 対象マスタのクラスが存在しない、または公開しないマスタ（権限・カード・カード詳細）に該当する場合は、該当なし（HTTP 404）として`{code, message}`形式のJSONを返す。
4. マスタ識別名がフォーマットの場合は、デッキビルダー対象フラグが立つフォーマットのみを取得する。
5. マスタ識別名がサブテーブルを持つマスタ（カテゴリ・タグ）の場合は、サブテーブルを含めて取得する。
6. それ以外は全件を取得する。
7. 取得結果を`code`と`results`のラッパに包んで返す（HTTP 200）。

---

## 集計条件

本APIは指定マスタの全件取得であり、件数集計・ページングを行わない。対象範囲は次のとおり。

| 指標 | 集計の要点 |
|------|------------|
| 取得対象 | パスで指定したマスタの全件。フォーマットのみデッキビルダー対象フラグが真の行に限定する。 |
| 結合 | カテゴリ・タグはサブテーブルを含めて取得する。それ以外は単一マスタの全件取得。 |
| 並び順 | 各マスタのリポジトリの既定取得順に従う。本APIで明示の並び替えは行わない。 |
| ページング | 行わない。全件を一括で返す。 |

## 入出力

### リクエスト

| パラメータ | 位置 | 型 | 必須／任意 | 説明 |
|------------|------|----|-----------|------|
| name | パス | string | 必須 | マスタ名。アンダースコア区切りの文字列を受け取り、内部でキャメルケース化・先頭大文字化してマスタ識別名に変換する。対象は`Mtb`系マスタ全般（例: カード種別・サブタイプ・レアリティ・色・フォーマット・デッキタグ・キャンペーンタグ・特殊種別）と、追加公開対象の`Dtb`系（カテゴリ・カテゴリ並び順・会員区分・割引カード条件・タグ並び順）。権限・カード・カード詳細は公開しない。 |

### レスポンス（成功）

HTTP 200。応答はラッパオブジェクトを持つ。

| フィールド | 型 | 説明 |
|------------|----|------|
| code | integer | 処理結果コード。成功時は200。 |
| results | array | マスタ行の配列。要素は対象マスタの公開プロパティで構成するオブジェクト。 |
| results[].（各プロパティ） | 対象マスタ依存 | 各マスタのエンティティで公開設定されたプロパティ。キー名はcamelCase。フォーマットなら識別子・日本語名・英語名・デッキビルダー対象フラグ等、色なら識別子・名称等、マスタごとに構成が異なる。 |

サブテーブルを持つマスタ（カテゴリ・タグ）では、要素内に子要素の配列を含む。

### レスポンス（失敗）

| HTTPステータス | 条件 | 本文の形 |
|----------------|------|----------|
| 404 | マスタ名に対応するクラスが存在しない、または公開しないマスタ（権限・カード・カード詳細）を指定した | `{code: 404, message: "Not Found"}` |
| 500 | 取得処理中の例外 | 共通例外処理に委ねる |

### サンプルレスポンス

成功時の応答例（フォーマットマスタを取得した場合の代表値。プロパティ構成は対象マスタに依存する）。

```json
{
  "code": 200,
  "results": [
    {
      "id": 1,
      "nameJp": "スタンダード",
      "nameEn": "Standard",
      "deckbuilderFlg": true
    },
    {
      "id": 2,
      "nameJp": "モダン",
      "nameEn": "Modern",
      "deckbuilderFlg": true
    }
  ]
}
```

### 副作用

無し（参照のみ）。取得クエリには結果キャッシュ（既定の保持時間つき）を用いるが、業務データの更新・履歴・通知は行わない。

応答はJSON応答整形を経て返す。プロパティはcamelCase、日時はISO8601、`serialize_null`は有効とする。

## 業務ルール・計算

- 検索・一覧・取得条件はリクエストパラメータ、ログイン状態、公開状態、店舗・支店条件、既存リポジトリの絞り込み順序を正とする。
- 件数、ページ番号、表示順は既存実装のデフォルトと上限に従い、取得後に業務値を再計算しない。
- 金額、ポイント、数量、ステータス、日時はDBまたは連携元の永続化済み値を返却し、レスポンス生成時の丸め・補正は行わない。
- 条件に一致しない、権限がない、または非公開のデータは空結果または既存のエラー形式で返す。

## データ整合性

| 観点 | 内容 |
|------|------|
| 参照時点 | 呼び出し時点のマスタを返す。結果キャッシュの保持時間内は同一内容を返すことがある。本APIはデータを更新しない。 |
| 一覧と詳細 | 本APIは一覧（全件）のみを返し、単一マスタ行の詳細取得は持たない。 |

## DBカラム

機能に直接関係する列のみ記載する。型や一覧の細部はスキーマを参照する。

テーブル名・列名はec-cube-enterpriseのマスタ定義を正とする。

| テーブル | 列 | メモ |
|----------|-----|------|
| フォーマットマスタ（`mtb_format`） | デッキビルダー対象フラグ（`deckbuilder_flg`） | フォーマット取得時に真の行のみを対象とする。 |
| 各対象マスタ（`mtb`系・追加公開の`dtb`系） | 公開対象プロパティ | 応答`results`要素の各キーに対応する。マスタごとに構成が異なる。 |

### DB操作

本機能は参照系（検索）であり、DBへの登録・更新・削除は行わない。テーブル名は ec-cube-enterprise を正典とする。

| 操作種別 | 対象テーブル | 契機・条件 |
|---------|--------------|------------|
| 検索 | mtb_format | 検索条件に合致するレコードを抽出する。 |
