# API デッキビルダー — ユーザー情報参照

## 概要

デッキビルダーアプリが、ログイン中の自分のユーザー情報（ニックネーム・プロフィール・デッキユーザーID）を取得するためのAPIである。deck-api（デッキビルダー用のAPIアプリケーション）が提供するJSON APIで、`jwt-token`ヘッダのトークンから特定したプレイヤーの公開向け情報を返す。

本書は実装手順ではなく、誰が・いつ・どの条件で・結果どうなるかを読むためのリバース詳細設計とする。確認値はdeck-apiのユーザー情報参照処理、ルート定義（`config/routes.yaml`）、プレイヤーを扱うエンティティ、共通の認証処理を正とする。

本機能のカスタマイズ区分は現行踏襲であり、挙動はデッキビルダー用APIの現行実装（deck-api）を、DB関連はec-cube-enterpriseの実装を正とする。

対象はJSON APIエンドポイントであり、ブラウザ向けの画面を持たない。本文ではフレームワークのコントローラ型名やメソッド名を主説明としない。「利用者視点の入口」にHTTPメソッドとパスパターンを書く。

---

## 本書で扱うこと

- 認証したプレイヤー自身のニックネーム・プロフィール・デッキユーザーIDの取得
- 認証、該当なし時の応答

---

## 本書で扱わないこと

以下は本書では仕様確定せず、実装または別APIの設計を正とする。

- デッキユーザーIDを指定した他ユーザー情報の参照（同一エンドポイントの`deck_user_id`指定の分岐は他ユーザー情報参照APIの設計を正とする）
- ユーザー情報の変更（ユーザー情報変更APIの設計を正とする）
- トークンの発行（デッキビルダー用ログインの設計を正とする）
- プレイヤーの本名・メールアドレス・ポイント等、本APIの応答に含めない項目

---

## リニューアル移行時の扱い

DB関連の記述はec-cube-enterpriseの実装を正とする。挙動は現行のデッキビルダー用API（deck-api）を正とする。現行と移行先でプレイヤーテーブルの主キー列名が異なる。

| 観点 | 現行（deck-api） | 移行先（ec-cube-enterprise） |
|------|------------------|------------------------------|
| プレイヤーテーブル | `dtb_player` | `dtb_player` |
| プレイヤーの主キー列 | `player_id` | `id` |
| 応答に用いる列 | `customer_id`・`nickname`・`profile`・`deck_user_id` | 同一の列名（差分なし） |

応答3項目（ニックネーム・プロフィール・デッキユーザーID）の取得元列は現行と移行先で同一であり、主キー列名（現行`player_id`、移行先`id`）のみ異なる。移行に伴う応答仕様の変更は本書では確定しない。

## 用語

| 用語 | 説明 |
|------|------|
| プレイヤー | デッキビルダーの利用者。会員（顧客）に紐づき、`aud`の顧客IDで特定する。 |
| ニックネーム | プレイヤーの表示名。本APIではユーザー名として返す。 |
| プロフィール | プレイヤーの自己紹介文。 |
| デッキユーザーID | プレイヤーを外部から参照するための公開用の短い識別子。 |

---

## 利用者視点の入口

| 入口 | URLエンドポイント | 期待されるふるまい |
|------|--------------------|--------------------|
| 自分のユーザー情報参照 | `GET /user` | `jwt-token`ヘッダから特定したプレイヤーのニックネーム・プロフィール・デッキユーザーIDを、コード200のJSONで返す。 |

応答形式はJSON。呼び出し元はデッキビルダーアプリ。クエリパラメータ`deck_user_id`を付けた場合は他ユーザー情報参照の分岐となり、本書では扱わない。

---

## 認証・認可

| 観点 | 内容 |
|------|------|
| 認証方式 | `jwt-token`ヘッダのJWTを検証し、ペイロードの`aud`の顧客IDから顧客IDに対応するプレイヤーを引く。署名方式はHS256。 |
| 認証失敗時 | ヘッダ欠落・署名不正・該当するプレイヤーなしのいずれも認証拒否（HTTP 401）とする。本文は`{code, message}`で返す。 |
| 認可 | 認証したプレイヤー自身の情報のみを返す。呼び出し可能なクライアントはデッキビルダーアプリ。 |

トークン原値・署名シークレットは本書に記載しない。

---

## 処理フロー

### 自分のユーザー情報を取得する（GET `/user`）

1. クエリの`deck_user_id`を確認する。`deck_user_id`が指定されている場合は他ユーザー情報参照の分岐に進む（本書では扱わない）。
2. `deck_user_id`が未指定の場合、`jwt-token`ヘッダのトークンを検証し、`aud`の顧客IDからプレイヤーを特定する。検証できない、または該当するプレイヤーがない場合は認証拒否（HTTP 401）とし、`{code, message}`を返す。
3. 特定したプレイヤーが取得できない場合は入力不正（HTTP 400）とし、`{code, message}`（メッセージは「Invalid request parameters」）を返す。
4. プレイヤーのニックネーム・プロフィール・デッキユーザーIDを連想配列に詰め、コード200のJSONで返す。

## 業務ルール・計算

| 項目 | 内容 |
|------|------|
| 対象データ | リクエストで指定されたID・条件に一致するデータを取得対象とする。抽出条件と該当なし時の扱いは処理フロー・入出力の各節を正とする。 |
| 計算処理 | 本APIでは金額・税・ポイント・在庫数量の再計算や丸めを行わない。DBまたはリポジトリから取得した値をJSON応答へ整形して返す。 |
| 応答値 | 応答フィールドは取得時点の値を返す。表示用の加工やフロントエンド側の表示制御は呼び出し元クライアントの設計を正とする。 |

---

## 入出力

### リクエスト

| パラメータ | 位置 | 型 | 必須／任意 | 説明 |
|------------|------|----|-----------|------|
| `jwt-token` | ヘッダ | string | 必須 | 認証用のJWTトークン。検証して`aud`の顧客IDからプレイヤーを引く。 |
| `deck_user_id` | クエリ | string | 任意 | 指定すると他ユーザー情報参照の分岐となり、認証を行わずデッキユーザーIDでプレイヤーを引く。本書では未指定の自分参照のみを扱う。 |

### レスポンス（成功）

HTTP 200。応答本体はラッパオブジェクトで、JSONキーはsnake_caseで組み立てる。

| フィールド | 型 | 説明 |
|------------|----|------|
| `code` | integer | 処理結果コード。成功時は200。 |
| `user_name` | string | プレイヤーのニックネーム。未設定の場合はnull。 |
| `profile` | string | プレイヤーのプロフィール。未設定の場合はnull。 |
| `deck_user_id` | string | プレイヤーのデッキユーザーID。未設定の場合はnull。 |

### レスポンス（失敗）

| HTTPステータス | 条件 | 本文の形 |
|----------------|------|----------|
| 401 | `jwt-token`ヘッダ欠落・署名不正・`aud`に該当するプレイヤーなし | `{code, message}`（`message`は「Access Token is incorrect」または「Authentication failed」） |
| 400 | 認証は通ったが対象プレイヤーが取得できない | `{code, message}`（`message`は「Invalid request parameters」） |

### サンプルレスポンス

成功時の応答例（実装確認値に基づく代表値）。

```json
{
  "code": 200,
  "user_name": "デッキ太郎",
  "profile": "スタンダードを中心に遊んでいます。",
  "deck_user_id": "AB12CD34"
}
```

### 副作用

無し（参照のみ）。

応答はJSON応答整形を経て返す。本APIは連想配列を組み立てて返すため、JSONキーは実装で記述したsnake_case（`code`・`user_name`・`profile`・`deck_user_id`）となり、エンティティのプロパティ名（camelCase）はそのままは現れない。`serialize_null`は有効で、未設定項目はnullで返す。

## データ整合性

| 観点 | 内容 |
|------|------|
| 参照時点 | 呼び出し時点のプレイヤー情報を返す。本APIはデータを更新しない。 |
| 一覧と詳細 | 本APIは単一プレイヤーの参照のみで、一覧は返さない。 |

## DBカラム

機能に直接関係する列のみ記載する。型や一覧の細部はスキーマを参照する。

テーブル名・列名はec-cube-enterpriseを正とする。プレイヤーの主キー列は移行先で`id`（現行`player_id`）。

| テーブル | 列 | メモ |
|----------|-----|------|
| プレイヤー（`dtb_player`） | 顧客ID（`customer_id`） | `aud`の顧客IDでプレイヤーを特定する。 |
| プレイヤー（`dtb_player`） | ニックネーム（`nickname`） | 応答の`user_name`に用いる。 |
| プレイヤー（`dtb_player`） | プロフィール（`profile`） | 応答の`profile`に用いる。 |
| プレイヤー（`dtb_player`） | デッキユーザーID（`deck_user_id`） | 応答の`deck_user_id`に用いる。 |

### DB操作

本機能は参照系（検索）であり、DBへの登録・更新・削除は行わない。テーブル名は ec-cube-enterprise を正典とする。

| 操作種別 | 対象テーブル | 契機・条件 |
|---------|--------------|------------|
| 検索 | dtb_player | 検索条件に合致するレコードを抽出する。 |

## 権限・認可

| 利用者状態 | ユーザー情報参照 |
|------------|------------------|
| 認証済みのプレイヤー | 自分のニックネーム・プロフィール・デッキユーザーIDを取得できる。 |
| 未認証・トークン不正 | 認証拒否（HTTP 401）となり、取得できない。 |

## エラー処理

| エラー内容 | 処理 |
|------------|------|
| 認証不可 | 認証拒否（HTTP 401）とし、`{code, message}`を返す。 |
| 対象プレイヤーが取得できない | 入力不正（HTTP 400）とし、「Invalid request parameters」を返す。 |

## ログ・監査

### ログに出してはいけないもの

- JWTトークンの原値
- 署名シークレット（`auth_magic`）
- パスワード
- Cookie値・セッションIDの完全値

## 排他制御・トランザクション

本APIは参照のみであり、楽観ロック・悲観ロックの対象は持たない。
