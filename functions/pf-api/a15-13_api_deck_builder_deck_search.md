# API デッキビルダー — デッキ情報検索

## 概要

デッキビルダーアプリの利用者が、検索条件に一致するデッキの一覧と総件数を取得するためのAPIである。deck-api（デッキビルダー用のAPIアプリケーション）が提供するJSON APIで、フォーマット・アーキタイプ・期間・タグ・採用カードなどの条件で絞り込み、ページング付きでデッキ一覧を返す。公開検索と自分のデッキ検索の2モードを持つ。

本書は実装手順ではなく、誰が・いつ・どの条件で・結果どうなるかを読むためのリバース詳細設計とする。確認値はdeck-apiのデッキ検索処理、ルート定義（`config/routes.yaml`）、デッキ検索処理（デッキリポジトリ）、デッキを扱うエンティティ、共通の認証処理を正とする。

本機能のカスタマイズ区分は現行踏襲とする。挙動はdeck-api（デッキビルダー用APIアプリケーション）の実装を確認値とし、DB関連の記述（テーブル名・列名・永続化先）はec-cube-enterpriseの実装を正とする。

対象はJSON APIエンドポイントであり、ブラウザ向けの画面を持たない。本文ではフレームワークのコントローラ型名やメソッド名を主説明としない。「利用者視点の入口」にHTTPメソッドとパスパターンを書く。

---

## 本書で扱うこと

- 検索条件に一致するデッキ一覧と総件数の取得
- 公開検索（公開デッキ）と自分のデッキ検索（プレイヤー所有デッキ）のモード切り替え
- フォーマット・アーキタイプ・期間・タグ・キャンペーンタグ・採用カード等による絞り込み
- ページング（`per_page`・`page`・`total_count`）と結果キャッシュ
- 自分のデッキ検索時の認証

---

## 本書で扱わないこと

以下は本書では仕様確定せず、実装または別APIの設計を正とする。

- デッキ1件の参照（デッキ情報参照APIの設計を正とする）
- デッキの新規登録・更新・削除（デッキ情報登録・デッキ情報更新・デッキ情報削除の各APIの設計を正とする）
- カード採用枚数集計・メタゲーム・直近大会等の集計系API
- トークンの発行（デッキビルダー用ログインの設計を正とする）

## リニューアル移行時の扱い

デッキビルダー関連テーブルは、現行（deck-api）と移行先（ec-cube-enterprise）で同一スキーマであり、テーブル名も一致する。本機能の検索・絞り込みに関わる主な対応は次のとおり。

| 項目 | 現行（deck-api） | 移行先（ec-cube-enterprise） | 差分・注意 |
|------|------------------|------------------------------|-----------|
| デッキ本体 | `dtb_deck` | `dtb_deck` | 同一テーブル名。 |
| 公開範囲 | 応答の`scope_id`。DB上は公開区分（`disp_id`）・非公開フラグ（`private_flg`）・閲覧用トークン（`display_token`） | 同一 | 公開検索は公開区分が公開のデッキを対象とする。列名`scope_id`はDBに存在しない。 |
| 論理削除 | 削除日時（`deleted_at`）が無い行のみ対象 | 削除日時（`deleted_at`）が無い行のみ対象 | 物理削除は行わない。 |
| レギュレーション違反 | レギュレーション違反フラグ（`regulation_violation_flg`） | 同一列 | 既定では違反デッキを除外する。 |
| 並び順 | 作成日時（`create_date`）の降順 | 同一列・同一順 | キャンペーンタグの並びは`mtb_campaign_tag.sort_no`を用いる。 |

現行と移行先でスキーマに差はなく、移行時に追加・改廃する絞り込み列は本書では確認していない。

| 用語 | 説明 |
|------|------|
| 公開検索 | 公開デッキを対象とする検索モード（`mode=public`）。 |
| 自分のデッキ検索 | 認証プレイヤーが所有するデッキを対象とする検索モード（`mode=private`）。 |
| 大会デッキ・ユーザーデッキ | デッキ種別。大会由来のデッキとユーザー作成のデッキ。 |
| キャンペーンタグ | デッキに付与するタグ。開催前・開催中・開催後の状態を持つ。 |

## 利用者視点の入口

| 入口 | URLエンドポイント | 期待されるふるまい |
|------|--------------------|--------------------|
| デッキ情報の検索 | `GET /decks` | 検索条件に一致するデッキ一覧と総件数を、ページング付きで返す。自分のデッキ検索モードでは認証を要する。 |

応答形式はJSON。呼び出し元はデッキビルダーアプリ。

## 認証・認可

| 観点 | 内容 |
|------|------|
| 認証方式 | `jwt-token`ヘッダのJWTを検証し、ペイロード`aud`の顧客IDからプレイヤーを引く。署名方式はHS256。 |
| 認証の要否 | 公開検索（`mode=public`）は認証不要で公開デッキを返す。自分のデッキ検索（`mode=private`）は認証必須で、失敗時は認証拒否（HTTP 401）とする。 |
| 認可 | 自分のデッキ検索では認証プレイヤーが所有するデッキのみを対象とする。呼び出し可能なクライアントはデッキビルダーアプリ。 |

トークン原値・署名シークレットは本書に記載しない。

## 処理フロー

### デッキ情報を検索する（GET `/decks`）

1. クエリパラメータを既定値とともに受領する。
2. モードが自分のデッキ検索（`private`）の場合は`jwt-token`ヘッダのトークンを検証し、プレイヤーを特定する。検証できない場合は認証拒否（HTTP 401）とする。公開検索（`public`）の場合は認証を行わない。
3. 検索条件でデッキを絞り込む。公開検索は公開デッキ、自分のデッキ検索は認証プレイヤー所有デッキを対象とする。デッキ種別フラグがいずれも対象外の場合は空の一覧と総件数0を返す。
4. 作成日時の降順で並べ、ページング（`page`・`per_page`）で1ページ分を取得する。`cache_key`がある場合は一覧・件数の結果をキャッシュする。
5. デッキタグ・キャンペーンタグを各デッキに整形して付与し、総件数とともにコード200・メッセージで返す。

## 集計条件

| 指標 | 集計の要点 |
|------|------------|
| 対象データ | 削除日時が無いデッキ。公開検索は公開（`scope_id=1`）デッキ、自分のデッキ検索は認証プレイヤー所有デッキ。 |
| デッキ種別 | `event_deck_flag`で大会デッキ、`user_deck_flag`でユーザーデッキを対象に含める。いずれも対象外なら空・総件数0を返す。 |
| 結合 | フォーマット・アーキタイプ・代表カード画像・プレイヤー・デッキタグ・キャンペーンタグを結合する。採用カード条件指定時はボード別に採用カードを結合する。 |
| 絞り込み | フォーマット・アーキタイプ・作成期間・更新期間・タグ・キャンペーンタグ・利用者ID・利用者名・大会名・大会期間・参加人数・優勝・上位8・レギュレーション違反・採用カードで絞り込む。 |
| 一意化 | デッキIDで一意化する（`GROUP BY`）。 |
| 並び順 | 作成日時の降順。 |
| ページング | `page`・`per_page`で区切る。`per_page`は最大100に丸める。 |
| 総件数 | 同一条件で重複排除したデッキIDの件数を別途数えて返す。 |
| キャッシュ | `cache_key`がある場合、一覧と件数の結果を一定時間キャッシュする。 |

### レスポンス（失敗）

| HTTPステータス | 条件 | 本文の形 |
|----------------|------|----------|
| 401 | `mode=private`でトークン欠落・署名不正・該当プレイヤーなし | `{code, message}`（messageは「Access Token is incorrect」「Authentication failed」） |

公開検索は認証なしで成功し、条件不一致時は空の`decks`と`total_count=0`を返す。

### 副作用

無し（参照のみ）。`cache_key`指定時に一覧・件数の結果キャッシュを書き込むが、業務データの更新は行わない。

応答はJSON応答整形を経て返す。プロパティはJSONキーに準じ、日時はISO8601、`serialize_null`は有効とする。

## バリデーション

| 項目 | 内容 |
|------|------|
| `mode` | `public`または`private`のみを受け付ける。既定は`public`。 |
| `per_page`・`page` | 数字のみを受け付ける。既定は`per_page=20`・`page=1`。`per_page`は最大100に丸める。 |
| `format`・`archetype`・`tag`・`campaign_tag_ids`・`cards` | 配列で指定された場合のみ絞り込み条件として用いる。 |
| 認証 | `mode=private`のときのみトークンを検証し、未充足時は認証拒否（HTTP 401）とする。 |

## 業務ルール・計算

- 検索・一覧・取得条件はリクエストパラメータ、ログイン状態、公開状態、店舗・支店条件、既存リポジトリの絞り込み順序を正とする。
- 件数、ページ番号、表示順は既存実装のデフォルトと上限に従い、取得後に業務値を再計算しない。
- 金額、ポイント、数量、ステータス、日時はDBまたは連携元の永続化済み値を返却し、レスポンス生成時の丸め・補正は行わない。
- 条件に一致しない、権限がない、または非公開のデータは空結果または既存のエラー形式で返す。

## データ整合性

| 観点 | 内容 |
|------|------|
| 参照時点 | 呼び出し時点のデータを返す。本APIはデータを更新しない。 |
| キャッシュ | `cache_key`指定時は一定時間キャッシュした結果を返すため、キャッシュ有効期間内は最新内容と一致しないことがある。 |
| 一覧と件数 | 一覧（ページング後）と総件数（重複排除した全件数）は同一条件から算出するため整合する。 |

### DB操作

本機能は参照系（検索）であり、DBへの登録・更新・削除は行わない。テーブル名は ec-cube-enterprise を正典とする。

| 操作種別 | 対象テーブル | 契機・条件 |
|---------|--------------|------------|
| 検索 | dtb_deck / dtb_deck_card / mtb_campaign_tag / mtb_deck_tag | 検索条件に合致するレコードを抽出する。 |

## 権限・認可

| 利用者状態 | デッキ情報検索 |
|------------|----------------|
| 任意の利用者（公開検索） | 公開デッキを検索できる。 |
| 認証済みのプレイヤー（自分のデッキ検索） | 自身が所有するデッキを検索できる。 |
| 未認証・トークン不正（自分のデッキ検索） | 認証拒否（HTTP 401）となり、検索できない。 |

## エラー処理

| エラー内容 | 処理 |
|------------|------|
| 認証不可（`mode=private`） | 認証拒否（HTTP 401）とし、`{code, message}`を返す。 |
| 条件不一致・対象外のデッキ種別 | 空の`decks`と`total_count=0`を返す（HTTP 200）。 |
