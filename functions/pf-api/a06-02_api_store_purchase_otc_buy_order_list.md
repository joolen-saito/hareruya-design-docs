# API 店頭買取管理 — 店頭買取受注一覧取得

## 概要

買取アプリ（MTGバイヤー）が、査定対象となる店頭買取受注の一覧を取得するためのAPIである。pf-api（買取連携用のAPIアプリケーション）が提供するJSON APIで、商品到着から成立・キャンセル前までの状態にある店頭買取受注を抽出し、受注ごとの基本情報と申込者情報をまとめて返す。認証した管理者会員が店舗に紐づく場合は、その店舗の受注に絞り込む。

本書は実装手順ではなく、誰が・いつ・どの条件で・結果どうなるかを読むためのリバース詳細設計とする。確認値はpf-apiの店頭買取受注一覧取得処理、ルート定義（`config/routes.yaml`）、店頭買取受注を扱うエンティティとリポジトリ、店頭買取ステータスマスタ、共通の認証処理を正とする。

本機能のカスタマイズ区分はカスタマイズで、挙動の参照リポはpf-apiとする。DB関連の記述（テーブル名・列名・永続化先）はec-cube-enterpriseを正とする。

対象はJSON APIエンドポイントであり、ブラウザ向けの画面を持たない。本文ではフレームワークのコントローラ型名やメソッド名を主説明としない。「利用者視点の入口」にHTTPメソッドとパスパターンを書く。

## 本書で扱うこと

- 成立・キャンセル前までの状態にある店頭買取受注の抽出条件
- 認証した管理者会員の所属店舗による絞り込み
- 受注一覧の応答フィールドと申込者情報のネスト構造
- 認証

## リニューアル移行時の扱い

抽出条件・絞り込み・応答整形の挙動は現行（pf-api）を正とし、永続化に関わるテーブル・列名は移行先（ec-cube-enterprise）を正とする。店頭買取受注の各表は現行・移行先で同名だが、店舗の参照モデルが異なる。

| 区分 | 現行（pf-api） | 移行先（ec-cube-enterprise） |
|------|----------------|------------------------------|
| 店頭買取受注 | dtb_otc_buy_order | 同一スキーマ（dtb_otc_buy_order） |
| 店頭買取ステータスマスタ | mtb_otc_buy_order_status | 同一スキーマ（mtb_otc_buy_order_status） |
| 受注の店舗列 | dtb_otc_buy_order.shop_id（店舗マスタmtb_shopへ） | dtb_otc_buy_order.base_info_id（BaseInfo＝dtb_base_infoへ） |
| 絞り込みに使う所属店舗 | 認証会員の会員サブ（dtb_member_sub）のshop_id | 会員サブ（dtb_member_sub）は廃止。会員（dtb_member）のbase_info_idおよびmember_base_infoを参照する |
| 職業・国・都道府県・本人確認・適格請求書発行事業者口座 | 職業・国・都道府県マスタ、本人確認、dtb_qualified_invoice_issuer_account | 同一スキーマ（mtb_job・mtb_country・mtb_pref・mtb_identification・dtb_qualified_invoice_issuer_account） |
| 査定担当者（会員名） | dtb_member（member_id） | dtb_member（id） |

抽出する店頭買取ステータス（商品到着・査定中・振込前・保留・査定再開）と応答フィールド・住所連結ロジックはリニューアル後も同じ前提とするが、所属店舗での絞り込みが会員サブ（dtb_member_sub）のshop_idから会員（dtb_member）のbase_info_idへ移る。移行先での店舗絞り込みの実装はec-cube-enterprise実装で要確認とする。

## 認証・認可

| 観点 | 内容 |
|------|------|
| 認証方式 | `jwt-token`ヘッダのJWTを検証し、ペイロードの利用者IDから管理者会員を引く。署名方式はHS256。 |
| 認証失敗時 | ヘッダ欠落・署名不正・該当する管理者会員なしのいずれも認証拒否（HTTP 401）とする。 |
| 認可 | 呼び出し可能なクライアントは買取アプリ。認証した管理者会員に店舗が紐づく場合はその店舗の受注に絞り込み、紐づかない場合は店舗による絞り込みを行わず査定対象の受注を一律に返す。 |

トークン原値・署名シークレットは本書に記載しない。

## 処理フロー

### 店頭買取受注一覧を取得する（GET `/admin/otcBuyOrders.json`）

1. `jwt-token`ヘッダのトークンを検証し、管理者会員を特定する。検証できない場合は認証拒否（HTTP 401）とする。
2. 認証した管理者会員の会員サブ情報を引き、所属店舗IDを得る。会員サブ情報が無い場合は店舗IDをnullとする。
3. 店頭買取ステータスが商品到着・査定中・振込前・保留・査定再開のいずれかの店頭買取受注を、受注ID昇順で取得する。店舗IDが得られた場合はその店舗の受注に限定する。
4. 取得した受注を受注単位に整形し、受注の基本情報と申込者情報をネストした配列を組み立てて返す。
5. 該当する受注が無い場合は空配列を返す。

## 集計条件

| 指標 | 集計の要点 |
|------|------------|
| 抽出対象 | 店頭買取ステータスが商品到着（5）・査定中（6）・振込前（7）・保留（8）・査定再開（9）のいずれかの店頭買取受注。それ以外の状態（成立・キャンセル・ダブルチェック済・データ出力済）は除外する。 |
| 結合 | 受注に店頭買取ステータス・職業マスタ・国マスタを内部結合し、会員（査定担当者）・都道府県マスタ・本人確認・適格請求書発行事業者口座を左結合する。 |
| 絞り込み | 認証した管理者会員に所属店舗がある場合は、その店舗に一致する受注のみに絞り込む。所属店舗が無い場合は絞り込まない。 |
| 住所連結 | 国が日本（国ID 392）の場合は都道府県名・住所1・住所2を半角空白区切りで連結する。日本以外の場合は国名・住所2・住所1の順で連結する。 |
| 一意化 | 受注IDごとに1要素へ整形する。受注の基本情報と申込者情報を1件に集約する。 |
| 並び順 | 受注ID昇順。 |
| ページング | 行わない。該当する受注を全件返す。 |

## 入出力

### リクエスト

| パラメータ | 位置 | 型 | 必須／任意 | 説明 |
|------------|------|----|-----------|------|
| `jwt-token` | ヘッダ | string | 必須 | 認証用のJWTトークン。 |

本APIは認証用の`jwt-token`ヘッダ以外のリクエストパラメータを持たない。所属店舗による絞り込みは認証した管理者会員から決定し、クライアントは指定しない。

### レスポンス（成功）

HTTP 200。応答本体は受注ごとのオブジェクトを要素とする配列であり、ラッパオブジェクトや件数フィールドを持たない。各要素は次のフィールドを持つ。

| フィールド | 型 | 説明 |
|------------|----|------|
| （応答本体） | array | 査定対象の店頭買取受注の配列。該当が無い場合は空配列。 |
| `otcBuyOrderId` | integer | 店頭買取受注ID。 |
| `assessmentId` | integer | 査定ID。 |
| `applyDate` | string | 申込日時。ISO8601形式の日時文字列。 |
| `freeComment` | string | 受注に付与されたフリーコメント。未設定の場合はnull。 |
| `memberName` | string | 査定担当者の会員名。紐づく会員が無い場合はnull。 |
| `otcOrderStatusId` | integer | 店頭買取ステータスのID。 |
| `returnSupply` | integer | 返送品の扱いを表す区分値。 |
| `callFlg` | boolean | 連絡要否のフラグ。 |
| `adultFlg` | boolean | 成人区分のフラグ。 |
| `playingFlg` | boolean | プレイ用区分のフラグ。 |
| `orderStatusName` | string | 店頭買取ステータスの名称。 |
| `identificationId` | integer | 本人確認のID。未登録の場合は0。 |
| `qualifiedInvoiceIssuerFlg` | boolean | 適格請求書発行事業者の該当フラグ。 |
| `qualifiedInvoiceIssuerConfirmationFlg` | boolean | 適格請求書発行事業者の確認済みフラグ。 |
| `qualifiedInvoiceIssuerCode` | string | 適格請求書発行事業者の登録番号。紐づく口座が無い場合はnull。 |
| `customerInfo` | object | 申込者情報のオブジェクト。 |
| `customerInfo.firstName` | string | 申込者の名。 |
| `customerInfo.lastName` | string | 申込者の姓。 |
| `customerInfo.birth` | string | 申込者の生年月日。ISO8601形式の日時文字列。 |
| `customerInfo.telNo` | string | 申込者の電話番号。 |
| `customerInfo.zipcode` | string | 申込者の郵便番号。 |
| `customerInfo.jobName` | string | 申込者の職業名。 |
| `customerInfo.address` | string | 申込者の住所。国に応じて都道府県名または国名と住所1・住所2を半角空白区切りで連結した文字列。 |

### レスポンス（失敗）

| HTTPステータス | 条件 | 本文の形 |
|----------------|------|----------|
| 401 | トークン欠落・署名不正・該当する管理者会員なし | 認証拒否（本文を持たない） |
| 500 | 受注取得・整形処理中の例外 | 共通例外処理に委ねる |

## 業務ルール・計算

- 検索・一覧・取得条件はリクエストパラメータ、ログイン状態、公開状態、店舗・支店条件、既存リポジトリの絞り込み順序を正とする。
- 件数、ページ番号、表示順は既存実装のデフォルトと上限に従い、取得後に業務値を再計算しない。
- 金額、ポイント、数量、ステータス、日時はDBまたは連携元の永続化済み値を返却し、レスポンス生成時の丸め・補正は行わない。
- 条件に一致しない、権限がない、または非公開のデータは空結果または既存のエラー形式で返す。

## データ整合性

| 観点 | 内容 |
|------|------|
| 参照時点 | 呼び出し時点で査定対象の状態にある店頭買取受注を返す。本APIはデータを更新しない。 |
| 抽出範囲 | 店頭買取ステータスが商品到着・査定中・振込前・保留・査定再開の受注のみを返す。状態が変わった受注は次回以降の取得結果から外れる。所属店舗で絞り込む場合は他店舗の受注を含まない。 |
| 一覧と詳細 | 本APIは一覧の受注基本情報と申込者情報のみを返し、受注明細（買取代表カード・個別入力商品・在庫）は含まない。明細の整合は店頭買取受注詳細更新APIの設計を正とする。 |

## 権限・認可

| 利用者状態 | 店頭買取受注一覧取得 |
|------------|----------------------|
| 認証済みで店舗に紐づく管理者会員 | その店舗の査定対象の店頭買取受注一覧を取得できる。 |
| 認証済みで店舗に紐づかない管理者会員 | 店舗による絞り込みなしで査定対象の店頭買取受注一覧を取得できる。 |
| 未認証・トークン不正 | 認証拒否（HTTP 401）となり、取得できない。 |
