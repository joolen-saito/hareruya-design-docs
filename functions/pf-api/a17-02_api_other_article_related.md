# API その他 — 記事IDに関連する記事情報を取得

## 概要

記事IDを指定して、その記事に関連する記事情報を取得するAPIである。pf-apiが提供するJSON APIである。

本書は実装手順ではなく、誰が・いつ・どの条件で・結果どうなるかを読むためのリバース詳細設計とする。確認値はpf-apiの関連記事取得処理、ルート定義、記事を扱うリポジトリを正とする。

対象はJSON APIエンドポイントであり、ブラウザ向けの画面を持たない。

本機能のカスタマイズ区分は現行踏襲であり、挙動は現行実装（pf-api）を参照し、DB関連はec-cube-enterpriseを正とする。

---

## 本書で扱うこと

- 記事IDに関連する記事情報の取得

---

## 本書で扱わないこと

以下は本書では仕様確定せず、実装または別機能の設計を正とする。

- 検索クエリに一致する記事の取得（記事検索取得を正とする）
- 記事本体（WordPress）の管理
- 関連の判定ロジックの詳細（実装を確認値とする）

---

## リニューアル移行時の扱い

記事連携テーブルは現行（pf-api）と移行先（ec-cube-enterprise）でスキーマが同一の構成である。DB関連の記述は移行先を正とする。関連の判定に用いる共有（同一デッキ・アーキタイプ・カード・イベント詳細）は、記事との中間テーブル（`dtb_article_deck`・`dtb_article_archetype`・`dtb_article_card`・`dtb_article_event_detail`）の一致で評価する。基準記事の特定には `dtb_article.wp_post_id` を用い、記事は `dtb_article.deleted_at` による論理削除で削除済みは対象外とする。応答の `hasSameDeck`・`hasSameArchetype`・`hasSameCard`・`hasSameEventDetail` は各中間テーブルの共有有無に対応する。

---

## 利用者視点の入口

| 入口 | URLエンドポイント | 期待されるふるまい |
|------|--------------------|--------------------|
| 記事IDに関連する記事情報取得 | `GET /article/related/{id}` | 当該記事IDに関連する記事情報をJSONで返す。 |

応答形式はJSON。

---

## 処理フロー

### 関連記事を取得する（GET `/article/related/{id}`）

1. パスの記事IDを受け取る。
2. 記事のリポジトリから、当該記事に関連する記事情報を取得する。
3. 関連記事情報をJSONで返す。

---

## 集計条件

| 指標 | 集計の要点 |
|------|------------|
| 取得対象 | 指定記事IDに関連する記事。関連の判定は実装を確認値とする。 |

---

## 入出力

### リクエスト

| パラメータ | 位置 | 型 | 必須／任意 | 説明 |
|------------|------|----|-----------|------|
| `id` | パス | integer | 必須 | 基準となる記事のWP投稿ID。この記事に関連する記事を抽出する。 |
| `limit` | クエリ | integer | 任意 | 取得上限件数。未指定時は20件。 |

### レスポンス（成功）

HTTP 200。

関連記事の配列を返す。同一デッキ・アーキタイプ・カード・イベント詳細のいずれかを共有する記事を関連とみなし、共有度の高い順に並ぶ。各要素は以下のフィールドを持つ。

| フィールド | 型 | 説明 |
|------------|----|------|
| `wpPostId` | integer | 関連記事のWP投稿ID。 |
| `hasSameDeck` | integer | 基準記事と同一デッキを共有するか（1／0）。 |
| `hasSameArchetype` | integer | 基準記事と同一アーキタイプを共有するか（1／0）。 |
| `hasSameCard` | integer | 基準記事と同一カードを共有するか（1／0）。 |
| `hasSameEventDetail` | integer | 基準記事と同一イベント詳細を共有するか（1／0）。 |

### レスポンス（失敗）

| HTTPステータス | 条件 | 本文の形 |
|----------------|------|----------|
| 404 | 関連記事なし（結果が空） | `{code, message}`（"Not Found"） |

### サンプルレスポンス

成功時の応答例（実装確認値に基づく代表値）。

```json
[
  {
    "wpPostId": 2002,
    "hasSameDeck": 1,
    "hasSameArchetype": 1,
    "hasSameCard": 0,
    "hasSameEventDetail": 0
  },
  {
    "wpPostId": 2010,
    "hasSameDeck": 0,
    "hasSameArchetype": 0,
    "hasSameCard": 1,
    "hasSameEventDetail": 0
  }
]
```

### 副作用

無し（参照のみ）。

応答はJSON応答整形を経て返す。プロパティはcamelCase、日時はISO8601とする。

## 業務ルール・計算

- 検索・一覧・取得条件はリクエストパラメータ、ログイン状態、公開状態、店舗・支店条件、既存リポジトリの絞り込み順序を正とする。
- 件数、ページ番号、表示順は既存実装のデフォルトと上限に従い、取得後に業務値を再計算しない。
- 金額、ポイント、数量、ステータス、日時はDBまたは連携元の永続化済み値を返却し、レスポンス生成時の丸め・補正は行わない。
- 条件に一致しない、権限がない、または非公開のデータは空結果または既存のエラー形式で返す。

## データ整合性

| 観点 | 内容 |
|------|------|
| 参照時点 | 呼び出し時点の記事情報を返す。本APIはデータを更新しない。 |

---

## DBカラム

テーブル名・列名はec-cube-enterpriseを正とする。

| テーブル | 列 | メモ |
|---------|-----|------|
| 記事（`dtb_article`） | `id`・`wp_post_id`・`deleted_at` | 基準記事の特定（`wp_post_id`）と論理削除判定に用いる。 |
| 記事関連（`dtb_article_deck`・`dtb_article_archetype`・`dtb_article_card`・`dtb_article_event_detail`） | 記事ID・関連先ID | 共有有無の判定に用いる中間テーブル。応答の `hasSameDeck` 等に対応する。 |

### DB操作

本機能は参照系（検索）であり、DBへの登録・更新・削除は行わない。テーブル名は ec-cube-enterprise を正典とする。

| 操作種別 | 対象テーブル | 契機・条件 |
|---------|--------------|------------|
| 検索 | dtb_article / dtb_article_archetype / dtb_article_card / dtb_article_deck / dtb_article_event_detail | 検索条件に合致するレコードを抽出する。 |
