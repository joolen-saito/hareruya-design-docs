# API 店頭買取管理 — 店頭買取受注詳細更新

## 業務ロジック

### 更新対象の特定

指定された受注IDの店頭買取受注1件を更新対象とする。該当が無いときは該当なし（HTTP 404）とする。受注の現在のステータスや担当者による更新制限は本APIでは課さない。

### 明細の入れ替え

受注に紐づく既存の明細・個別入力商品・在庫・在庫履歴を削除したうえで、送られた明細を1件ずつ登録する。商品規格IDが空の明細は個別入力商品として登録し、商品規格IDがある明細は明細として登録する。いずれも部門IDがあり該当部門が存在するときだけ部門を設定する。商品規格に紐づく明細は商品規格ごとに数量を集計し、在庫と在庫履歴を作る。

### 買取合計金額

明細の単価×数量を合算し、10円単位へ切り上げた額を買取合計金額とする。

### 受注への反映

受注にステータス・買取合計金額・明細・個別入力商品・在庫を設定する。査定担当者には認証した管理者会員を、更新日時には現在日時を設定する。指定ステータスが成立（1）のときは成立日時を、それ以外のときはキャンセル日時を現在日時に設定する。受注が適格請求書発行事業者に該当するときだけ、確認済みフラグを指定値で更新する。

更新前と指定ステータスが異なるときは、ステータス変更履歴を1件登録する。

### エラー時の扱い

| エラー内容 | 処理 |
|------------|------|
| 認証不可 | 認証拒否（HTTP 401）とする |
| 受注が存在しない | 該当なし（HTTP 404）とする |
| 入力検証エラー | 入力不正（HTTP 400）とし、全メッセージを`errors`配列で返す。削除・登録・保存は行わない |
| 削除・登録・保存処理中の例外 | 共通例外処理に委ねる（HTTP 500相当） |

検証エラーは複数件をまとめる。受注全体の検証と明細各件の検証を合算した全メッセージを返す。

## 入出力

| 種類 | 内容 |
|------|------|
| 入力 | 更新対象の受注ID、更新後のステータス、査定明細の配列、適格請求書発行事業者の確認済みフラグ、認証トークン |
| 成功時出力 | HTTP 200。処理結果コード200 |
| 失敗時出力 | HTTP 401（認証不可）、HTTP 404（受注なし）、HTTP 400（入力検証エラー）、HTTP 500（処理中の例外） |

### 入力: リクエスト

| パラメータ | 位置 | 型 | 必須／任意 | 説明 |
|------------|------|----|-----------|------|
| `id` | パス | integer | 必須 | 更新対象の店頭買取受注ID |
| `order_status` | ボディ | integer | 必須 | 更新後の店頭買取ステータスID。店頭買取ステータスマスタに存在する値であること |
| `order_details` | ボディ | array | 必須 | 査定明細の配列。1件以上であること |
| `order_details[].product_class_id` | ボディ | integer | 任意 | 商品規格ID。空のときは個別入力商品として扱う。整数のみ |
| `order_details[].name` | ボディ | string | 必須 | 商品名。最大65535文字 |
| `order_details[].quantity` | ボディ | integer | 任意 | 数量。整数のみ |
| `order_details[].price` | ボディ | integer | 任意 | 単価。整数のみ |
| `order_details[].sell_price` | ボディ | integer | 任意 | 販売価格。整数のみ |
| `order_details[].section_id` | ボディ | integer | 任意 | 部門ID。該当部門が存在する場合のみ設定する。整数のみ |
| `qualified_invoice_issuer_confirmation_flg` | ボディ | boolean | 任意 | 適格請求書発行事業者の確認済みフラグ。受注が適格請求書発行事業者に該当する場合のみ反映する |
| `jwt-token` | ヘッダ | string | 必須 | 認証用のトークン |

ボディの項目はフォーム値として受け取り、明細各項目のキーはスネークケースで指定する。

### 出力: レスポンス（成功）

| フィールド | 型 | 説明 |
|------------|----|------|
| `code` | integer | 処理結果コード。成功時は200 |

```json
{
  "code": 200
}
```

### 出力: レスポンス（失敗）

| HTTPステータス | 条件 | 本文の形 |
|----------------|------|----------|
| 401 | トークン欠落・署名不正・該当する管理者会員なし | 認証拒否（本文を持たない） |
| 404 | 受注IDに該当する店頭買取受注が無い | 該当なし（本文を持たない） |
| 400 | ステータス未指定 | `errors`に「ステータスを選択してください。」を含む |
| 400 | ステータスIDが店頭買取ステータスマスタに存在しない | `errors`に「MtbOtcBuyOrderStatusに{指定ID}が見つかりません。」を含む |
| 400 | 明細が未指定または空 | `errors`に「1つ以上の商品を選んでください。」を含む |
| 400 | 明細の商品名が未入力 | `errors`に商品名必須の検証メッセージを含む |
| 400 | 明細の商品名が最大長超過 | `errors`に「商品名は、 65535 以下で入力してください。」を含む |
| 400 | 明細の商品規格ID・数量・単価・販売価格・部門IDが整数でない | `errors`に該当項目の整数形式メッセージを含む |
| 500 | 削除・登録・保存処理中の例外 | 共通例外処理に委ねる |

```json
{
  "code": 400,
  "errors": [
    "1つ以上の商品を選んでください。"
  ]
}
```

### 入出力: 永続化

| 操作 | 契機 |
| --- | --- |
| 削除 | 更新時に、受注に紐づく既存の明細・個別入力商品・在庫・在庫履歴を削除する |
| 追加 | 送られた明細から、明細・個別入力商品・在庫・在庫履歴を登録する |
| 追加 | 更新前と指定ステータスが異なるとき、ステータス変更履歴を1件登録する |
| 更新 | 受注のステータス・買取合計金額・査定担当者・更新日時・成立日時またはキャンセル日時、確認済みフラグを更新する |
