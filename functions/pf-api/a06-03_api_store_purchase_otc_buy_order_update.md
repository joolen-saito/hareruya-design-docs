# API 店頭買取管理 — 店頭買取受注詳細更新

## 業務ロジック

### 更新対象の特定

指定された受注IDの店頭買取受注1件を更新対象とする。該当が無いときは該当なし（HTTP 404）とする。受注の現在のステータスや担当者による更新制限は本APIでは課さない。

### 部門の設定と実在庫の集約

明細・個別入力商品には、部門IDが指定され、かつ該当する部門が存在するときだけ部門を設定する。該当する部門が無い部門IDは無視し、部門なしで登録する。

実在庫は商品規格ごとに数量を合算して1件にまとめる。同じ商品規格の明細が複数送られたときも、実在庫は商品規格につき1件になる。実在庫履歴には合算後の数量・査定担当者・現在日時を記録する。

### 買取合計金額

送られた査定明細すべて（個別入力商品を含む）について単価×数量を合算し、10円単位へ切り上げた額を買取合計金額とする。

### 受注への反映

査定担当者には認証した管理者会員を、更新日時には現在日時を設定する。適格請求書発行事業者に該当する受注のときだけ、確認済みフラグを指定値で更新する（該当しない受注では、指定されても更新しない）。

更新前と指定ステータスが異なるときだけ、ステータス変更履歴を1件登録する。同じステータスが指定されたときは履歴を残さない。

### エラー時の扱い

| エラー内容 | 処理 |
|------------|------|
| 認証不可 | 認証拒否（HTTP 401）とする |
| 受注が存在しない | 該当なし（HTTP 404）とする |
| 入力検証エラー | 入力不正（HTTP 400）とし、全メッセージを`errors`配列で返す。削除・登録・保存は行わない |
| 削除・登録・保存処理中の例外 | 共通例外処理に委ねる（HTTP 500相当） |

検証エラーは複数件をまとめる。受注全体の検証と明細各件の検証を合算した全メッセージを返す。

## 入出力

### 入力: リクエスト

| パラメータ | 位置 | 型 | 必須／任意 | 説明 |
|------------|------|----|-----------|------|
| `jwt-token` | ヘッダ | string | 必須 | 認証用のトークン |

### 出力: レスポンス（失敗）

| HTTPステータス | 条件 | 本文の形 |
|----------------|------|----------|
| 401 | トークン欠落・署名不正・該当する管理者会員なし | 認証拒否（本文を持たない） |
| 404 | 受注IDに該当する店頭買取受注が無い | 該当なし（本文を持たない） |
| 400 | ステータス未指定 | `errors`に「ステータスを選択してください。」を含む |
| 400 | ステータスIDが店頭買取ステータスマスタに存在しない | `errors`に「MtbOtcBuyOrderStatusに{指定ID}が見つかりません。」を含む |
| 400 | 明細が未指定または空 | `errors`に「1つ以上の商品を選んでください。」を含む |
| 400 | 明細の商品名が未入力 | `errors`に商品名必須の検証メッセージを含む |
| 400 | 明細の商品名が最大長超過 | `errors`に「商品名は、 65535 以下で入力してください。」を含む |
| 400 | 明細の商品規格ID・数量・単価・販売価格・部門IDが整数でない | `errors`に該当項目の整数形式メッセージを含む |
| 500 | 削除・登録・保存処理中の例外 | 共通例外処理に委ねる |

```json
{
  "code": 400,
  "errors": [
    "1つ以上の商品を選んでください。"
  ]
}
```
