# API デッキビルダー — 他ユーザー情報参照

## 概要

デッキビルダーアプリが、デッキユーザーIDを指定して他のプレイヤーの公開向け情報（ニックネーム・プロフィール・デッキユーザーID）を取得するためのAPIである。deck-api（デッキビルダー用のAPIアプリケーション）が提供するJSON APIで、自分参照と同一のエンドポイントを用い、クエリの`deck_user_id`の有無で分岐する。`deck_user_id`を指定した場合は認証を行わず、デッキユーザーIDに一致するプレイヤーを引いて返す。

本書は実装手順ではなく、誰が・いつ・どの条件で・結果どうなるかを読むためのリバース詳細設計とする。確認値はdeck-apiのユーザー情報参照処理、ルート定義（`config/routes.yaml`）、プレイヤーを扱うエンティティ、共通の認証処理を正とする。

本機能のカスタマイズ区分は現行踏襲であり、挙動はデッキビルダー用APIの現行実装（deck-api）を、DB関連はec-cube-enterpriseの実装を正とする。

対象はJSON APIエンドポイントであり、ブラウザ向けの画面を持たない。本文ではフレームワークのコントローラ型名やメソッド名を主説明としない。「利用者視点の入口」にHTTPメソッドとパスパターンを書く。

---

## 本書で扱うこと

- デッキユーザーIDを指定した他プレイヤーの公開向け情報（ニックネーム・プロフィール・デッキユーザーID）の取得
- 該当なし時の応答
- 自分参照（`deck_user_id`未指定）との分岐の違い

---

## 本書で扱わないこと

以下は本書では仕様確定せず、実装または別APIの設計を正とする。

- 自分自身のユーザー情報参照（`deck_user_id`未指定の分岐はユーザー情報参照APIの設計を正とする）
- ユーザー情報の変更（ユーザー情報変更APIの設計を正とする）
- トークンの発行（デッキビルダー用ログインの設計を正とする）
- プレイヤーの本名・メールアドレス・ポイント等、本APIの応答に含めない項目

---

## リニューアル移行時の扱い

DB関連の記述はec-cube-enterpriseの実装を正とする。挙動は現行のデッキビルダー用API（deck-api）を正とする。現行と移行先でプレイヤーテーブルの主キー列名が異なる。

| 観点 | 現行（deck-api） | 移行先（ec-cube-enterprise） |
|------|------------------|------------------------------|
| プレイヤーテーブル | `dtb_player` | `dtb_player` |
| プレイヤーの主キー列 | `player_id` | `id` |
| 検索キー・応答に用いる列 | `deck_user_id`・`nickname`・`profile` | 同一の列名（差分なし） |

検索キー（デッキユーザーID）と応答3項目の取得元列は現行と移行先で同一であり、主キー列名（現行`player_id`、移行先`id`）のみ異なる。移行に伴う応答仕様の変更は本書では確定しない。

## 用語

| 用語 | 説明 |
|------|------|
| プレイヤー | デッキビルダーの利用者。会員（顧客）に紐づく。 |
| デッキユーザーID | プレイヤーを外部から参照するための公開用の短い識別子。本APIの検索キーとなる。 |
| 他ユーザー情報参照 | 自分以外のプレイヤーをデッキユーザーIDで参照する分岐。 |

---

## 利用者視点の入口

| 入口 | URLエンドポイント | 期待されるふるまい |
|------|--------------------|--------------------|
| 他ユーザー情報参照 | `GET /user?deck_user_id={deckUserId}` | クエリのデッキユーザーIDに一致するプレイヤーのニックネーム・プロフィール・デッキユーザーIDを、コード200のJSONで返す。認証は行わない。 |

応答形式はJSON。呼び出し元はデッキビルダーアプリ。自分参照と専用ルートは分かれておらず、同一の`GET /user`のクエリ`deck_user_id`の有無で分岐する。専用のエンドポイントや管理向けコントローラは持たない。

---

## 認証・認可

| 観点 | 内容 |
|------|------|
| 認証方式 | クエリに`deck_user_id`が指定されている場合、本分岐では`jwt-token`の検証を行わない。デッキユーザーIDだけでプレイヤーを引く。 |
| 認証失敗時 | 本分岐は認証を行わないため、トークンに起因する認証拒否（HTTP 401）は発生しない。 |
| 認可 | デッキユーザーIDを知る任意の呼び出し元が、そのプレイヤーの公開向け情報（ニックネーム・プロフィール・デッキユーザーID）を取得できる。呼び出し可能なクライアントはデッキビルダーアプリ。 |

トークン原値・署名シークレットは本書に記載しない。

---

## 処理フロー

### 他ユーザー情報を取得する（GET `/user?deck_user_id={deckUserId}`）

1. クエリの`deck_user_id`を確認する。指定されている場合は本分岐に進む。
2. デッキユーザーIDに一致するプレイヤーを1件取得する。認証は行わない。
3. 該当するプレイヤーがない場合は入力不正（HTTP 400）とし、`{code, message}`（メッセージは「Invalid request parameters」）を返す。
4. プレイヤーのニックネーム・プロフィール・デッキユーザーIDを連想配列に詰め、コード200のJSONで返す。

## 業務ルール・計算

| 項目 | 内容 |
|------|------|
| 対象データ | リクエストで指定されたID・条件に一致するデータを取得対象とする。抽出条件と該当なし時の扱いは処理フロー・入出力の各節を正とする。 |
| 計算処理 | 本APIでは金額・税・ポイント・在庫数量の再計算や丸めを行わない。DBまたはリポジトリから取得した値をJSON応答へ整形して返す。 |
| 応答値 | 応答フィールドは取得時点の値を返す。表示用の加工やフロントエンド側の表示制御は呼び出し元クライアントの設計を正とする。 |

---

## 入出力

### リクエスト

| パラメータ | 位置 | 型 | 必須／任意 | 説明 |
|------------|------|----|-----------|------|
| `deck_user_id` | クエリ | string | 必須（本分岐） | 参照対象プレイヤーのデッキユーザーID。指定すると本分岐となる。 |
| `jwt-token` | ヘッダ | string | 任意 | 本分岐では検証しない。`deck_user_id`を指定する限り認証は行わない。 |

### レスポンス（成功）

HTTP 200。応答本体はラッパオブジェクトで、JSONキーはsnake_caseで組み立てる。

| フィールド | 型 | 説明 |
|------------|----|------|
| `code` | integer | 処理結果コード。成功時は200。 |
| `user_name` | string | プレイヤーのニックネーム。未設定の場合はnull。 |
| `profile` | string | プレイヤーのプロフィール。未設定の場合はnull。 |
| `deck_user_id` | string | プレイヤーのデッキユーザーID。未設定の場合はnull。 |

### レスポンス（失敗）

| HTTPステータス | 条件 | 本文の形 |
|----------------|------|----------|
| 400 | `deck_user_id`に一致するプレイヤーがない | `{code, message}`（`message`は「Invalid request parameters」） |

該当なし時はHTTP 404ではなく入力不正（HTTP 400）で返す点に注意する。本分岐は認証を行わないため、トークンに起因するHTTP 401は発生しない。

### サンプルレスポンス

成功時の応答例（実装確認値に基づく代表値）。

```json
{
  "code": 200,
  "user_name": "デッキ花子",
  "profile": "リミテッドが好きです。",
  "deck_user_id": "ZZ99YY88"
}
```

### 副作用

無し（参照のみ）。

応答はJSON応答整形を経て返す。本APIは連想配列を組み立てて返すため、JSONキーは実装で記述したsnake_case（`code`・`user_name`・`profile`・`deck_user_id`）となり、エンティティのプロパティ名（camelCase）はそのままは現れない。`serialize_null`は有効で、未設定項目はnullで返す。

## DBカラム

機能に直接関係する列のみ記載する。型や一覧の細部はスキーマを参照する。

テーブル名・列名はec-cube-enterpriseを正とする。プレイヤーの主キー列は移行先で`id`（現行`player_id`）。

| テーブル | 列 | メモ |
|----------|-----|------|
| プレイヤー（`dtb_player`） | デッキユーザーID（`deck_user_id`） | クエリの`deck_user_id`で対象プレイヤーを特定する。応答の`deck_user_id`にも用いる。 |
| プレイヤー（`dtb_player`） | ニックネーム（`nickname`） | 応答の`user_name`に用いる。 |
| プレイヤー（`dtb_player`） | プロフィール（`profile`） | 応答の`profile`に用いる。 |

### DB操作

本機能は参照系（検索）であり、DBへの登録・更新・削除は行わない。テーブル名は ec-cube-enterprise を正典とする。

| 操作種別 | 対象テーブル | 契機・条件 |
|---------|--------------|------------|
| 検索 | dtb_player | 検索条件に合致するレコードを抽出する。 |
