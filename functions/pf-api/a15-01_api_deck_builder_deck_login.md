# API デッキビルダー — ログイン

<!-- リバース詳細設計書（API・機能単位）。deck-api が提供する会員ログインAPI。 -->

## 概要

デッキビルダーアプリの利用者が会員のメールアドレスとパスワードでログインし、以降のAPI呼び出しに使うアクセストークンを取得するためのAPIである。deck-api（デッキビルダー用のAPIアプリケーション）が提供するJSON APIで、受け取ったメールアドレスとパスワードを会員データと照合し、認証成功時にアクセストークンとセッションIDを返す。

本書は実装手順ではなく、誰が・いつ・どの条件で・結果どうなるかを読むためのリバース詳細設計とする。既存実装のふるまい、参照するデータ、判定境界、副作用を確認し、仕様の確からしさを把握することを目的とする。確認値はdeck-apiのログイン処理、入力フォーム定義、トークン生成処理、ルート定義（`config/routes.yaml`）、照合先の会員データを正とする。

本機能のカスタマイズ区分は現行踏襲であり、挙動はデッキビルダー用APIの現行実装（deck-api）を、DB関連はec-cube-enterpriseの実装を正とする。

対象はJSON APIエンドポイントであり、ブラウザ向けの画面を持たない。本文ではフレームワークのコントローラ型名やメソッド名を主説明としない。「利用者視点の入口」にHTTPメソッドとパスパターンを書く。

## リニューアル移行時の扱い

DB関連の記述はec-cube-enterpriseの実装を正とする。挙動は現行のデッキビルダー用API（deck-api）を正とする。現行と移行先で会員テーブルの主キー列名・会員ステータスの持ち方が異なる。

| 観点 | 現行（deck-api） | 移行先（ec-cube-enterprise） |
|------|------------------|------------------------------|
| 会員テーブル | `dtb_customer` | `dtb_customer` |
| 会員の主キー列 | `customer_id` | `id`（プレイヤー側からは`customer_id`で参照） |
| 会員ステータス | `status`列で本会員判定 | `customer_status_id`列（会員ステータスマスタを参照）で本会員判定 |
| 削除フラグ | `del_flg` | `del_flg`（同一） |
| メールアドレス・パスワード・ソルト | `email`・`password`・`salt` | 同一の列名（差分なし） |

会員照合の挙動（本会員かつ未削除のみを対象とする等）は現行と移行先で同じだが、会員ステータスは現行が`status`列、移行先が`customer_status_id`列である点が異なる。移行に伴うトークン仕様・Cookie仕様の変更は本書では確定しない。

## 利用者視点の入口

| 入口 | URLエンドポイント | 期待されるふるまい |
|------|--------------------|--------------------|
| デッキビルダーアプリからのログイン | `POST /user/login` | メールアドレスとパスワードを検証・照合し、成功時はアクセストークンとセッションIDのJSONを返す。入力不正は入力不正（HTTP 400）、照合不一致は認証拒否（HTTP 401）のJSONを返す。 |

応答形式はJSON。呼び出し元はデッキビルダーアプリ。

## 認証・認可

| 観点 | 内容 |
|------|------|
| 本APIの認証 | 本APIはトークン取得の入口であり、`jwt-token`ヘッダを要求しない。未認証のクライアントが呼び出せる。 |
| 照合先 | メールアドレスで会員を引き、入力パスワードを会員のソルトでハッシュ化した値と保存値を突合する。会員は有効状態（ステータスが本会員）かつ未削除のものに限る。 |
| トークン発行 | 認証成功時、署名付きJWTを発行する。ペイロードは発行者・利用者ID（会員ID＝`aud`）・発行時刻を持つ。署名方式はHS256。 |
| 以降の認可 | 呼び出し元は受け取ったアクセストークンを以降のdeck-apiの`jwt-token`ヘッダに付与する。各APIはトークンの`aud`（会員ID）からプレイヤーを引いて認可する（各APIの設計を正とする）。 |
| 認証失敗時 | 該当会員が無い、またはパスワードが一致しない場合は認証拒否（HTTP 401）とする。 |

トークン原値・署名シークレット・パスワードは本書に記載しない。

## 処理フロー

### 会員ログインを行う（POST `/user/login`）

1. リクエストボディから`id`（メールアドレス）と`password`を受け取る。
2. 入力をログインフォームへ投入し検証する。必須・形式の検証に失敗した場合は入力不正（HTTP 400）のJSONを返す。
3. メールアドレス・有効状態（本会員）・未削除の条件で会員を引く。該当が無い場合は認証拒否（HTTP 401）のJSONを返す。
4. 入力パスワードを会員のソルトでハッシュ化し、会員の保存パスワードと突合する。一致しない場合は認証拒否（HTTP 401）のJSONを返す。
5. 一致した場合、会員IDを利用者IDとするアクセストークンを発行する。
6. トークンを有効期限付きのCookieに設定し、セッションを開始する。
7. コード200・成功メッセージ・アクセストークン・セッションIDのJSONを返す。

## 入出力

### リクエスト

| パラメータ | 位置 | 型 | 必須／任意 | 説明 |
|------------|------|----|-----------|------|
| `id` | ボディ（フォーム値） | string | 必須 | 会員のメールアドレス。メールアドレス形式であること。会員照合のキーに用いる。 |
| `password` | ボディ（フォーム値） | string | 必須 | 会員のパスワード。半角の表示可能文字（`!`から`~`の範囲）のみで構成すること。 |

認証ヘッダは不要である。`jwt-token`ヘッダを付与しなくても呼び出せる。フォームはCSRF検証を行わず、定義外の追加項目を許容する。

### レスポンス（成功）

HTTP 200。

| フィールド | 型 | 説明 |
|------------|----|------|
| `code` | integer | 結果コード。成功時は200。 |
| `message` | string | 結果メッセージ。成功時は`Authentication success`。 |
| `access_token` | string | 発行したアクセストークン。以降のdeck-apiの`jwt-token`ヘッダに用いる。 |
| `session_id` | string | 開始したセッションのID。 |

### レスポンス（失敗）

| HTTPステータス | 条件 | 本文の形 |
|----------------|------|----------|
| 400 | 必須未入力・メールアドレス形式不正・パスワード形式不正など入力検証に失敗 | `{code, message}`（`message`は`Required fields have not been filled in. Or the input format is incorrect`） |
| 401 | 該当会員が無い、またはパスワードが一致しない | `{code, message}`（`message`は`ID or password does not match`） |
| 500 | 処理中の例外 | deck-apiの共通例外処理に委ねる |

### サンプルレスポンス

成功時の応答例（秘匿値はプレースホルダ）。

```json
{
  "code": 200,
  "message": "Authentication success",
  "access_token": "<accessToken>",
  "session_id": "<sessionId>"
}
```

### 副作用

アクセストークンを有効期限付きのCookieに設定する。Cookie名は設定キー`cookie_name`と`token_name`を結合した名称とし、有効期限は設定キー`jwt_expire_days`の日数に基づく。セッションを開始する。会員・プレイヤー等の業務データは更新しない。

応答はJSON応答整形を経て返す。プロパティはcamelCase、日時はISO8601、`serialize_null`は有効とする。

## バリデーション

| 項目 | 内容 |
|------|------|
| `id`（メールアドレス） | 必須。未入力時のメッセージは`Enter your Email address.`。メールアドレス形式であること（MX・ホスト検査はしない）。形式不正時のメッセージは`Enter a valid email address in the Email field`。未充足は入力不正（HTTP 400）の共通メッセージで返す。 |
| `password` | 必須。未入力時のメッセージは`Enter your password.`。半角の表示可能文字（`!`から`~`の範囲）のみで構成すること。形式不正時のメッセージは`Enter in alphanumeric characters`。未充足は入力不正（HTTP 400）の共通メッセージで返す。 |

検証は会員照合の前に行う。検証に1件でも失敗すると、項目別メッセージではなく共通メッセージ`Required fields have not been filled in. Or the input format is incorrect`を持つ入力不正（HTTP 400）を返す。

## 業務ルール・計算

- 認証判定は既存のID、パスワード、会員・管理者状態、利用可否フラグを正とし、認証成功時のみセッションまたはトークンを発行・更新する。
- 認証失敗、退会・停止・権限不足の場合は業務データを更新せず、既存のエラー形式で返す。
- ログイン時に金額・ポイント・在庫などの業務値は計算しない。

## データ整合性

| 観点 | 内容 |
|------|------|
| 参照時点 | 照合する会員データはログイン呼び出し時点の値である。 |
| トークン | 発行時点の利用者ID（会員ID）を内包する。deck-apiはトークンを保存しない。 |
| 対象会員 | 有効状態（本会員）かつ未削除の会員のみを照合対象とする。それ以外は該当無しとして認証拒否（HTTP 401）になる。 |

## DBカラム

機能に直接関係する列のみ記載する。型や一覧の細部はスキーマを参照する。

テーブル名・列名はec-cube-enterpriseを正とする。現行（deck-api）と異なる列は移行先名を主とし現行名を括弧で添える。

| テーブル | 列 | メモ |
|----------|-----|------|
| 会員（`dtb_customer`） | メールアドレス（`email`） | 照合のキー。リクエストの`id`と突合する。 |
| 会員（`dtb_customer`） | 会員ID（移行先`id`、現行`customer_id`） | トークンの利用者ID（`aud`）に用いる。プレイヤー側からは`customer_id`で参照する。 |
| 会員（`dtb_customer`） | パスワード（`password`）・ソルト（`salt`） | 入力パスワードをソルトでハッシュ化し保存値と突合する。 |
| 会員（`dtb_customer`） | 会員ステータス（移行先`customer_status_id`、現行`status`）・削除フラグ（`del_flg`） | 有効状態（本会員）かつ未削除のみを対象とする条件。 |

### DB操作

永続化の正は ec-cube-enterprise（テーブル名・操作は ec-cube-enterprise を正典）。当ドメインは承認ワークフローを介さず persist/flush で直接確定する（承認ワークフローは在庫機能固有）。

| 操作種別 | 対象テーブル | 契機・条件 |
|---------|--------------|------------|
| 登録/更新 | dtb_customer | 当機能が行う登録・更新で対象テーブルを直接保存する（不要な削除は含まない）。確定は persist/flush による即時反映。DB=ec-cube-enterprise を正典とする。 |

## 権限・認可

| 利用者状態 | ログイン |
|------------|----------|
| 未認証のクライアント | ログインのために呼び出せる。資格情報が正しい場合のみアクセストークンを取得できる。 |
| 資格情報が誤りのクライアント | 認証拒否（HTTP 401）となり、トークンを取得できない。 |
| 入力が不正なクライアント | 入力不正（HTTP 400）となり、照合に進まない。 |

## エラー処理

| エラー内容 | 処理 |
|------------|------|
| 入力検証の失敗 | コード400・共通メッセージ`Required fields have not been filled in. Or the input format is incorrect`のJSONを返す。 |
| 該当会員なし・パスワード不一致 | コード401・メッセージ`ID or password does not match`のJSONを返す。会員が無い場合とパスワードが一致しない場合で同じメッセージを返し、いずれかを区別しない。 |
| 処理中の例外 | deck-apiの共通例外処理に委ねる。本API独自のフォールバック文言は設けない。 |

## ログ・監査

### ログに出してはいけないもの

- パスワード
- アクセストークンの原値
- 署名シークレット（`auth_magic`）
- Cookie値・セッションIDの完全値

## 排他制御・トランザクション

本APIは会員の参照とトークン発行・応答整形のみであり、業務トランザクションを張ってデータを更新しない。楽観ロック・悲観ロックの対象は持たない。
