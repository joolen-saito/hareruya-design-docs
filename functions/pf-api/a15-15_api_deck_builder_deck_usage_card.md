# API デッキビルダー — 採用枚数情報参照

## 概要

デッキビルダーアプリが、指定フォーマットで採用率（採用枚数）の高いカードの集計情報を取得するためのAPIである。deck-api（デッキビルダー用のAPIアプリケーション）が提供するJSON APIで、集計範囲内の公開・大会デッキを対象に、カードごとの平均採用枚数を算出して上位から返す。土地カードに限定する／除外する切り替え、アーキタイプ・ボードによる絞り込みに対応する。

本書は実装手順ではなく、誰が・いつ・どの条件で・結果どうなるかを読むためのリバース詳細設計とする。確認値はdeck-apiの採用枚数取得処理、ルート定義（`config/routes.yaml`）、フォーマットマスタ・デッキを扱うリポジトリを正とする。

本機能のカスタマイズ区分は現行踏襲とする。挙動はdeck-api（デッキビルダー用APIアプリケーション）の実装を確認値とし、DB関連の記述（テーブル名・列名・永続化先）はec-cube-enterpriseの実装を正とする。

対象はJSON APIエンドポイントであり、ブラウザ向けの画面を持たない。本文ではフレームワークのコントローラ型名やメソッド名を主説明としない。「利用者視点の入口」にHTTPメソッドとパスパターンを書く。

---

## 本書で扱うこと

- 指定フォーマットでのカード別平均採用枚数の集計と上位抽出
- 土地カードの限定／除外の切り替え（`type`）
- アーキタイプ（`archetype_id`）・ボード（`board_id`）による絞り込み
- フォーマット該当なし時の応答

---

## 本書で扱わないこと

以下は本書では仕様確定せず、実装または別APIの設計を正とする。

- メタゲームのアーキタイプ別件数集計（メタゲーム情報参照APIの設計を正とする）
- 個々のデッキの内容・カード構成の参照（デッキ詳細参照APIの設計を正とする）
- カードマスタそのものの参照・検索（カード関連APIの設計を正とする）

## リニューアル移行時の扱い

デッキビルダー関連テーブルは、現行（deck-api）と移行先（ec-cube-enterprise）で同一スキーマであり、テーブル名も一致する。本機能の集計に関わる主な対応は次のとおり。

| 項目 | 現行（deck-api） | 移行先（ec-cube-enterprise） | 差分・注意 |
|------|------------------|------------------------------|-----------|
| フォーマットマスタ | `mtb_format`。メタゲーム分析日数（`meta_range`）・基本地形混在フラグ（`include_basic_flg`） | 同一テーブル・列名 | 土地限定かつ基本地形混在フラグが偽のとき基本土地を除外する。 |
| デッキ本体 | `dtb_deck`。公開区分（`disp_id`）・イベント日（`event_date`）・デッキ種別（`deck_type_id`）・アーキタイプ（`archetype_id`） | 同一列名 | 集計対象は公開区分が公開かつデッキ種別が大会のデッキ。 |
| 採用カード | `dtb_deck_card`。カード（`card_id`）・ボード（`board_id`）・枚数（`count`） | 同一テーブル・列名 | ボード絞り込みと採用枚数集計に用いる。 |
| カードマスタ・カード画像 | `mtb_card`・`mtb_card_image` | 同一テーブル名 | 応答のカード名称・並び順・画像URLに用いる。 |

現行と移行先でスキーマに差はなく、移行時に追加・改廃する集計列は本書では確認していない。

| 用語 | 説明 |
|------|------|
| フォーマット | 対戦の構築ルール区分。集計の単位。 |
| 採用枚数 | 集計範囲内のデッキで各カードが採用された枚数を、カード種別・特殊タイプの重複を加味して平均化した値。 |
| 土地カード | カード種別が土地のカード。`type`が`land`のときは土地のみ、それ以外のときは土地以外を対象とする。 |
| ボード | メインボード・サイドボードなどデッキ内の区分。`board_id`で絞り込む。 |

## 利用者視点の入口

| 入口 | URLエンドポイント | 期待されるふるまい |
|------|--------------------|--------------------|
| 採用枚数情報参照 | `GET /deck/usage_card/{formatId}` | パスのフォーマット識別子について、集計範囲内の公開・大会デッキからカード別の平均採用枚数を集計し、上位から最大件数分をコード200のJSONで返す。 |

応答形式はJSON。呼び出し元はデッキビルダーアプリ。

## 認証・認可

| 観点 | 内容 |
|------|------|
| 認証方式 | 本APIは認証を行わない。`jwt-token`ヘッダの検証・プレイヤーの特定をいずれも行わず、誰でも呼び出せる参照系である。 |

トークン原値・署名シークレットは本書に記載しない。

## 処理フロー

### 採用枚数情報を取得する（GET `/deck/usage_card/{formatId}`）

1. パスの`formatId`に一致するフォーマットを取得する。該当が無い場合（または`formatId`が空）は該当なし（HTTP 404）とし、「format not found」を返す。
2. クエリの`type`・`count`・`archetype_id`・`board_id`を受け取る。`type`が`land`のときは土地カードのみ、それ以外のときは土地以外のカードを集計対象とする。`count`が未指定の場合は既定値20件とする。
3. 集計範囲内の公開・大会デッキを対象に、カードごとの採用枚数合計を、カード種別数と特殊タイプ数で除した平均採用枚数として算出する。`archetype_id`・`board_id`が指定された場合はその条件で絞り込む。
4. 平均採用枚数の降順で並べ、上位から最大`count`件を抽出する。
5. カード別の集計結果（`cards`）をコード200のJSONで返す。

---

## 集計条件

| 指標 | 集計の要点 |
|------|------------|
| 対象データ | デッキのうち、対象フォーマットに属し、公開区分が公開で、デッキ種別が大会のものを対象とする。 |
| 集計範囲 | イベント日が、現在からフォーマットのメタ範囲日数前の0時0分から本日23時59分59秒までの範囲にあるものを対象とする。 |
| 土地の限定／除外 | `type`が`land`のときは土地カードのみを対象とする。土地限定かつフォーマットが基本土地を含めない設定のときは基本土地特殊タイプを除外する。`type`が`land`以外のときは土地以外を対象とする。 |
| 絞り込み | `archetype_id`を指定したときは当該アーキタイプのデッキに限定する。`board_id`を指定したときは当該ボードのカードに限定する。 |
| 集計単位 | カード（`card_id`）でグループ化し、採用枚数合計をカード種別数と特殊タイプ数で除した平均採用枚数（`count`）を算出する。 |
| 並び順・件数 | 平均採用枚数の降順、次いでカラー順、英語名の昇順で並べ、上位から最大`count`件（既定20件）に絞る。 |

## 入出力

### リクエスト

| パラメータ | 位置 | 型 | 必須／任意 | 説明 |
|------------|------|----|-----------|------|
| `formatId` | パス | integer | 必須 | 集計対象のフォーマット識別子。一致するフォーマットが無い場合は該当なし（HTTP 404）となる。 |
| `type` | クエリ | string | 任意 | `land`のとき土地カードのみ、それ以外のとき土地以外を対象とする。 |
| `count` | クエリ | integer | 任意 | 返すカードの上限件数。未指定の場合は20件。 |
| `archetype_id` | クエリ | integer | 任意 | 指定したアーキタイプのデッキに限定する。 |
| `board_id` | クエリ | integer | 任意 | 指定したボードのカードに限定する。 |

本APIは認証用の`jwt-token`ヘッダを必要としない。

### レスポンス（成功）

HTTP 200。応答本体はラッパオブジェクトで、JSONキーはsnake_caseで組み立てる。

| フィールド | 型 | 説明 |
|------------|----|------|
| `code` | integer | 処理結果コード。成功時は200。 |
| `cards` | array | カード別の採用枚数集計の配列。平均採用枚数の降順。 |
| `cards[].id` | integer | カード識別子。 |
| `cards[].name_jp` | string | カードの日本語名。 |
| `cards[].name_en` | string | カードの英語名。 |
| `cards[].image_jp` | string | カードの日本語版画像のURL。該当が無いときはnull。 |
| `cards[].image_en` | string | カードの英語版画像のURL。該当が無いときはnull。 |
| `cards[].count` | integer | 平均採用枚数（採用枚数合計をカード種別数・特殊タイプ数で除した値、整数化）。 |

### レスポンス（失敗）

| HTTPステータス | 条件 | 本文の形 |
|----------------|------|----------|
| 404 | `formatId`に一致するフォーマットが無い（または`formatId`が空） | `{code, message}`（`message`は「format not found」） |
| 500 | 集計処理中の例外 | 共通例外処理に委ねる |

### サンプルレスポンス

成功時の応答例（実装確認値に基づく代表値）。

```json
{

  "cards": [

      "name_en": "Island",

    {
```

### 副作用

無し（参照のみ）。

応答はJSON応答整形を経て返す。本APIは連想配列を組み立てて返すため、JSONキーは実装で記述したsnake_case（`code`・`cards`・`name_jp`・`image_jp`等）となる。`serialize_null`は有効で、未設定項目はnullで返す。

## バリデーション

| 項目 | 内容 |
|------|------|
| `formatId` | パス必須。一致するフォーマットが無い場合は該当なし（HTTP 404）とし、「format not found」を返す。 |
| `type` | 任意。`land`のときのみ土地限定として扱い、それ以外の値・未指定は土地以外として扱う。形式の追加検証は行わない。 |
| `count` | 任意。未指定の場合は20件を上限とする。形式の追加検証は行わない。 |
| `archetype_id`・`board_id` | 任意。指定時に集計対象を絞り込む。存在チェックは集計クエリの結合・条件で扱う。 |

## 業務ルール・計算

- 検索・一覧・取得条件はリクエストパラメータ、ログイン状態、公開状態、店舗・支店条件、既存リポジトリの絞り込み順序を正とする。
- 件数、ページ番号、表示順は既存実装のデフォルトと上限に従い、取得後に業務値を再計算しない。
- 金額、ポイント、数量、ステータス、日時はDBまたは連携元の永続化済み値を返却し、レスポンス生成時の丸め・補正は行わない。
- 条件に一致しない、権限がない、または非公開のデータは空結果または既存のエラー形式で返す。

## データ整合性

| 観点 | 内容 |
|------|------|
| 参照時点 | 呼び出し時点の集計範囲・デッキ状況に基づく集計結果を返す。本APIはデータを更新しない。 |
| 一覧と詳細 | 本APIはカード別の集計のみを返し、個々のデッキ内容との一致は保証しない。 |
