# API 店頭買取管理 — 部門一覧を取得

## 概要

公開対象の部門の一覧を取得するAPIである。pf-apiが提供するJSON APIで、MTGバイヤー（買取アプリ）から呼ばれる。

本書は実装手順ではなく、誰が・いつ・どの条件で・結果どうなるかを読むためのリバース詳細設計とする。確認値はpf-apiの部門一覧取得処理、ルート定義、部門マスタを扱うリポジトリを正とする。

カスタマイズ区分は現行踏襲。挙動の参照リポは現行の買取連携API（pf-api）とし、DB関連はec-cube-enterpriseを正とする。現行と移行先で異なる点は「リニューアル移行時の扱い」に集約する。

対象はJSON APIエンドポイントであり、ブラウザ向けの画面を持たない。

---

## 本書で扱うこと

- 公開対象の部門一覧の取得

## 本書で扱わないこと

以下は本書では仕様確定せず、実装または別機能の設計を正とする。

- 固定価格部門の取得（固定価格部門取得を正とする）
- 部門の管理（部門管理を正とする）

## リニューアル移行時の扱い

現行（pf-api）と移行先（ec-cube-enterprise）でエンドポイントとDBスキーマの確認値が異なる。挙動は現行を正とし、DB関連は移行先を正とする。

| 観点 | 現行（pf-api） | 移行先（ec-cube-enterprise） |
|------|----------------|------------------------------|
| エンドポイント | `GET /section.json` | `GET /{api_v1_route}/admin/sections.json`（API版数プレフィックス付き。プレフィックスは`eccube_api_v1_route`で決まる） |
| 部門マスタのテーブル | 部門マスタ（現行スキーマで要確認） | `mtb_section` |
| 公開対象の判定列 | 公開状態の列（現行スキーマで要確認） | `mtb_section.visible`（表示フラグ） |
| 並び順 | 部門コード昇順 | ec-cube-enterprise 実装で要確認 |

応答フィールド名（`section_id`・`name`・`code`）はAPI契約であり、移行先でのフィールド名・並び順はec-cube-enterprise実装で要確認とする。

## 利用者視点の入口

| 入口 | URLエンドポイント | 期待されるふるまい |
|------|--------------------|--------------------|
| 部門一覧を取得 | `GET /section.json` | 公開対象の部門一覧を、コードとメッセージとともにJSONで返す。 |

応答形式はJSON。MTGバイヤーから呼ばれる。

---

## 処理フロー

### 部門一覧を取得する（GET `/section.json`）

1. 部門マスタのリポジトリから公開対象の部門を取得する。
2. コード（200）・メッセージ・部門一覧をJSONで返す。

---

## 集計条件

| 指標 | 集計の要点 |
|------|------------|
| 取得対象 | 公開対象の部門。 |

---

## 入出力

### リクエスト

本APIはリクエストパラメータを持たない。

### レスポンス（成功）

HTTP 200。公開対象の部門一覧を返す。

| フィールド | 型 | 説明 |
|------------|----|------|
| `code` | integer | 処理結果コード。成功時は200。 |
| `message` | string | 処理結果メッセージ。成功時は"get sections success"。 |
| `sections` | array | 部門の配列。各要素は以下のフィールドを持つ。 |
| `sections[].section_id` | integer | 部門ID。 |
| `sections[].name` | string | 部門名。 |
| `sections[].code` | string | 部門コード。並び順はこのコードの昇順とする。 |

### レスポンス（失敗）

本実装は失敗ステータスを返さない（公開対象が無い場合は空配列の`sections`を返す）。

### サンプルレスポンス

成功時の応答例（実装確認値に基づく代表値）。

```json
{
  "code": 200,
  "message": "get sections success",
  "sections": [
    { "section_id": 1, "name": "シングルカード", "code": "01" },
    { "section_id": 2, "name": "ボックス・パック", "code": "02" }
  ]
}
```

### 副作用

無し（参照のみ）。

応答はJSON応答整形を経て返す。プロパティはcamelCase、日時はISO8601とする。

## 業務ルール・計算

- 検索・一覧・取得条件はリクエストパラメータ、ログイン状態、公開状態、店舗・支店条件、既存リポジトリの絞り込み順序を正とする。
- 件数、ページ番号、表示順は既存実装のデフォルトと上限に従い、取得後に業務値を再計算しない。
- 金額、ポイント、数量、ステータス、日時はDBまたは連携元の永続化済み値を返却し、レスポンス生成時の丸め・補正は行わない。
- 条件に一致しない、権限がない、または非公開のデータは空結果または既存のエラー形式で返す。

|------|------|
| 参照時点 | 呼び出し時点の公開対象の部門を返す。本APIはデータを更新しない。 |

## DBカラム

DB関連の記述はec-cube-enterpriseの実装を正とする。

| テーブル | 列 | メモ |
|---------|-----|------|
| 部門マスタ（`mtb_section`） | `visible`（表示フラグ） | 公開対象の抽出に使用する。 |
| 部門マスタ（`mtb_section`） | `id`・`name`・`code` | 応答内容（部門ID・部門名・部門コード）に使用する。 |

### DB操作

本機能は参照系（検索）であり、DBへの登録・更新・削除は行わない。テーブル名は ec-cube-enterprise を正典とする。

| 操作種別 | 対象テーブル | 契機・条件 |
|---------|--------------|------------|
| 検索 | mtb_section | 検索条件に合致するレコードを抽出する。 |
