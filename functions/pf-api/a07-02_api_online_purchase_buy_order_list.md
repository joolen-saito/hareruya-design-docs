# API ネット買取管理 — ネット買取受注一覧取得

## 概要

買取アプリ（MTGバイヤー）が、査定対象となるネット買取受注の一覧を取得するためのAPIである。pf-api（買取連携用のAPIアプリケーション）が提供するJSON APIで、商品到着から査定完了前までの状態にあるネット買取受注を抽出し、受注ごとの基本情報と申込者情報をまとめて返す。

本書は実装手順ではなく、誰が・いつ・どの条件で・結果どうなるかを読むためのリバース詳細設計とする。確認値はpf-apiのネット買取受注一覧取得処理、ルート定義（`config/routes.yaml`）、ネット買取受注を扱うエンティティとリポジトリ、共通の認証処理を正とする。

本機能のカスタマイズ区分は現行踏襲であり、挙動の参照リポはpf-api、DB関連（テーブル名・列名・永続化先）の記述はec-cube-enterpriseを正とする。

対象はJSON APIエンドポイントであり、ブラウザ向けの画面を持たない。本文ではフレームワークのコントローラ型名やメソッド名を主説明としない。「利用者視点の入口」にHTTPメソッドとパスパターンを書く。

## 本書で扱うこと

- 商品到着から査定完了前までの状態にあるネット買取受注の抽出条件
- 受注一覧の応答フィールドと申込者情報のネスト構造
- 認証

## リニューアル移行時の扱い

現行（pf-api）と移行先（ec-cube-enterprise）の差を記録する。挙動は現行（pf-api）を正とし、DB関連はec-cube-enterpriseを正とする。

| 観点 | 現行（pf-api） | 移行先（ec-cube-enterprise） |
|------|----------------|------------------------------|
| ネット買取受注テーブル | `dtb_buy_order`。受注IDの主キー列は `buy_order_id`。 | `dtb_buy_order`。受注IDの主キー列は `id`。応答の `netBuyOrderId` の取得元列名が現行と異なる。 |
| 申込日時の列 | `order_date`。 | `order_date`。同一。 |
| フリーコメントの列 | `memo`。応答の `freeComment` に用いる。 | `memo`。同一。 |
| 住所の列 | `addr01`・`addr02` と都道府県マスタを連結（`addr03` 列なし）。 | `addr01`・`addr02`・`addr03` を持つ。本一覧の住所連結は `addr01`・`addr02` と都道府県名のみで現行と同じ。`addr03` は本APIの応答では用いない。 |
| 会員テーブルの主キー | `dtb_member` の主キー列は `member_id`。会員名は `name`。 | `dtb_member` の主キー列は `id`。会員名は `name`。結合キー列名が現行と異なる。 |
| 買取受注ステータスマスタ | `mtb_buy_order_status` に1〜13のステータスを定義。抽出は商品到着（2）・査定中（10）・保留（11）・査定再開（12）。 | `mtb_buy_order_status` に1〜16を定義（入庫完了14・未登録在庫15・入庫待ち16を追加）。本APIの抽出条件のステータスID（2・10・11・12）は変わらない。 |
| エンドポイントの配置 | サイトルート直下 `/admin/buyOrders.json`。 | APIバージョンのルートプレフィックス（設定キー `eccube_api_v1_route`）配下に配置される。パス末尾 `admin/buyOrders.json` は同じ。 |

## 用語

| 用語 | 説明 |
|------|------|
| ネット買取受注 | ネット経由で受け付けた買取の受注。受注IDで一意に特定する。 |
| 査定対象 | 商品到着・査定中・保留・再開のいずれかの状態にある受注。本APIの抽出対象。 |
| 申込者情報 | 受注ごとの氏名・電話番号・郵便番号・住所をまとめた情報。 |
| 買取受注ステータス | 受注の進行状態を表すマスタ値。 |

## 利用者視点の入口

| 入口 | URLエンドポイント | 期待されるふるまい |
|------|--------------------|--------------------|
| ネット買取受注一覧の取得 | `GET /admin/buyOrders.json` | 査定対象の状態にあるネット買取受注を受注ID昇順で抽出し、受注ごとの基本情報と申込者情報の配列を返す。該当が無い場合は空配列を返す。 |

応答形式はJSON。呼び出し元は買取アプリ（MTGバイヤー）。

## 認証・認可

| 観点 | 内容 |
|------|------|
| 認証方式 | `jwt-token`ヘッダのJWTを検証し、ペイロードの利用者IDから管理者会員を引く。署名方式はHS256。 |
| 認証失敗時 | ヘッダ欠落・署名不正・該当する管理者会員なしのいずれも認証拒否（HTTP 401）とする。 |
| 認可 | 呼び出し可能なクライアントは買取アプリ。認証した管理者会員に紐づく絞り込みは行わず、査定対象の受注を一律に返す。 |

トークン原値・署名シークレットは本書に記載しない。

## 処理フロー

### ネット買取受注一覧を取得する（GET `/admin/buyOrders.json`）

1. `jwt-token`ヘッダのトークンを検証し、管理者会員を特定する。検証できない場合は認証拒否（HTTP 401）とする。
2. 買取受注ステータスが商品到着・査定中・保留・再開のいずれかであるネット買取受注を、受注ID昇順で取得する。
3. 取得した受注を受注単位に整形し、受注の基本情報と申込者情報をネストした配列を組み立てて返す。
4. 該当する受注が無い場合は空配列を返す。

---

## 集計条件

| 指標 | 集計の要点 |
|------|------------|
| 抽出対象 | 買取受注ステータスが商品到着・査定中・保留・再開のいずれかのネット買取受注。それ以外の状態（受付・成立・キャンセル等）は除外する。 |
| 結合 | 受注に紐づく会員（申込者を登録した会員）と都道府県マスタを左結合する。住所は都道府県名・住所1・住所2を半角空白区切りで連結する。 |
| 一意化 | 受注IDごとに1要素へ整形する。受注に複数の明細があっても受注単位で1件に集約する。 |
| 並び順 | 受注ID昇順。 |
| ページング | 行わない。該当する受注を全件返す。 |

## 入出力

### リクエスト

| パラメータ | 位置 | 型 | 必須／任意 | 説明 |
|------------|------|----|-----------|------|
| `jwt-token` | ヘッダ | string | 必須 | 認証用のJWTトークン。 |

本APIは認証用の`jwt-token`ヘッダ以外のリクエストパラメータを持たない。

### レスポンス（成功）

HTTP 200。応答本体は受注ごとのオブジェクトを要素とする配列であり、ラッパオブジェクトや件数フィールドを持たない。各要素は次のフィールドを持つ。

| フィールド | 型 | 説明 |
|------------|----|------|
| （応答本体） | array | 査定対象のネット買取受注の配列。該当が無い場合は空配列。 |
| `netBuyOrderId` | integer | ネット買取受注ID。 |
| `applyDate` | string | 申込日時。ISO8601形式の日時文字列。 |
| `freeComment` | string | 受注に付与されたフリーコメント。未設定の場合はnull。 |
| `memberName` | string | 申込者を登録した会員名。紐づく会員が無い場合はnull。 |
| `netOrderStatusId` | integer | 買取受注ステータスのID。 |
| `customerInfo` | object | 申込者情報のオブジェクト。 |
| `customerInfo.firstName` | string | 申込者の名。 |
| `customerInfo.lastName` | string | 申込者の姓。 |
| `customerInfo.telNo` | string | 申込者の電話番号。 |
| `customerInfo.zipcode` | string | 申込者の郵便番号。 |
| `customerInfo.address` | string | 申込者の住所。都道府県名・住所1・住所2を半角空白区切りで連結した文字列。 |

### レスポンス（失敗）

| HTTPステータス | 条件 | 本文の形 |
|----------------|------|----------|
| 401 | トークン欠落・署名不正・該当する管理者会員なし | 認証拒否（本文を持たない） |
| 500 | 受注取得・整形処理中の例外 | 共通例外処理に委ねる |

### サンプルレスポンス

成功時の応答例（実装確認値に基づく代表値。個人情報は最小限の代表値とする）。

```json
[
  {
    "netBuyOrderId": 1001,
    "applyDate": "2026-06-01T10:30:00+09:00",
    "freeComment": null,
    "memberName": "買取担当 太郎",
    "netOrderStatusId": 2,
    "customerInfo": {
      "firstName": "一郎",
      "lastName": "山田",
      "telNo": "0312345678",
      "zipcode": "1000001",
      "address": "東京都 千代田区千代田 1-1"
    }
  }
]
```

### 副作用

無し（参照のみ）。

応答はJSON応答整形を経て返す。プロパティはcamelCase、日時はISO8601、`serialize_null`は有効とする。

## 業務ルール・計算

- 検索・一覧・取得条件はリクエストパラメータ、ログイン状態、公開状態、店舗・支店条件、既存リポジトリの絞り込み順序を正とする。
- 件数、ページ番号、表示順は既存実装のデフォルトと上限に従い、取得後に業務値を再計算しない。
- 金額、ポイント、数量、ステータス、日時はDBまたは連携元の永続化済み値を返却し、レスポンス生成時の丸め・補正は行わない。
- 条件に一致しない、権限がない、または非公開のデータは空結果または既存のエラー形式で返す。

## データ整合性

| 観点 | 内容 |
|------|------|
| 参照時点 | 呼び出し時点で査定対象の状態にあるネット買取受注を返す。本APIはデータを更新しない。 |
| 抽出範囲 | 買取受注ステータスが商品到着・査定中・保留・再開の受注のみを返す。状態が変わった受注は次回以降の取得結果から外れる。 |
| 一覧と詳細 | 本APIは一覧の受注基本情報と申込者情報のみを返し、受注明細（買取代表カード・個別入力商品）は含まない。明細の整合は査定終了処理APIの設計を正とする。 |

## DBカラム

機能に直接関係する列のみ記載する。型や一覧の細部はスキーマを参照する。

列名はec-cube-enterpriseを正とし、現行（pf-api）と異なるものは括弧で添える。

| テーブル | 列 | メモ |
|----------|-----|------|
| ネット買取受注 `dtb_buy_order` | 受注ID `id`（現行 `buy_order_id`） | 抽出対象の特定・並び順・応答の`netBuyOrderId`に用いる。 |
| ネット買取受注 `dtb_buy_order` | 申込日時 `order_date` | 応答の`applyDate`に用いる。 |
| ネット買取受注 `dtb_buy_order` | 姓 `last_name`・名 `first_name` | 応答の`customerInfo.lastName`・`customerInfo.firstName`に用いる。 |
| ネット買取受注 `dtb_buy_order` | 電話番号 `tel_no` | 応答の`customerInfo.telNo`に用いる。 |
| ネット買取受注 `dtb_buy_order` | 郵便番号 `zipcode` | 応答の`customerInfo.zipcode`に用いる。 |
| ネット買取受注 `dtb_buy_order` | 住所1 `addr01`・住所2 `addr02` | 都道府県名と連結して応答の`customerInfo.address`に用いる。 |
| ネット買取受注 `dtb_buy_order` | フリーコメント `memo` | 応答の`freeComment`に用いる。 |
| ネット買取受注 `dtb_buy_order` | 買取受注ステータスID `buy_order_status_id` | 抽出条件・応答の`netOrderStatusId`に用いる。 |
| 会員 `dtb_member` | 会員名 `name` | 応答の`memberName`に用いる。主キー列は移行先 `id`（現行 `member_id`）。 |
| 都道府県マスタ `mtb_pref` | 都道府県名 `name` | 住所の連結に用いる。 |

### DB操作

本機能は参照系（検索）であり、DBへの登録・更新・削除は行わない。テーブル名は ec-cube-enterprise を正典とする。

| 操作種別 | 対象テーブル | 契機・条件 |
|---------|--------------|------------|
| 検索 | dtb_buy_order / dtb_member / mtb_pref | 検索条件に合致するレコードを抽出する。 |

| 利用者状態 | ネット買取受注一覧取得 |
|------------|------------------------|

## ログ・監査

### ログに出してはいけないもの

- JWTトークンの原値
- 署名シークレット（`auth_magic`）
- Cookie値・セッションIDの完全値
- 申込者の氏名・電話番号・郵便番号・住所などの個人情報
