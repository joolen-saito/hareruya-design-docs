# API 店頭買取管理 — 店頭買取受注ステータス更新

## 概要

買取アプリ（MTGバイヤー）が店頭買取受注のステータスを更新するためのAPIである。pf-api（買取連携用のAPIアプリケーション）が提供するJSON APIで、受注IDで対象を特定し、指定したステータスへ更新するとともに査定担当者・更新日時とステータス変更履歴を保存する。

本書は実装手順ではなく、誰が・いつ・どの条件で・結果どうなるかを読むためのリバース詳細設計とする。確認値はpf-apiのステータス更新処理、ルート定義（`config/routes.yaml`）、店頭買取受注・店頭買取ステータスマスタ・店頭買取ステータス変更履歴を扱うエンティティ、共通の認証処理を正とする。カスタマイズ区分はカスタマイズで、挙動の参照リポはpf-api、DB関連はec-cube-enterpriseを正とする。

対象はJSON APIエンドポイントであり、ブラウザ向けの画面を持たない。本文ではフレームワークのコントローラ型名やメソッド名を主説明としない。「利用者視点の入口」にHTTPメソッドとパスパターンを書く。

- 受注IDによる店頭買取受注の特定と、ステータス・査定担当者・更新日時の保存
- ステータス変更履歴の登録
- 認証、対象なし、無効なステータス、査定終了後・他担当者査定中の更新可否判定と応答

| 観点 | 内容 |

## 処理フロー

### 店頭買取受注のステータスを更新する（PUT `/admin/otcBuyOrder/{id}/status.json`）

1. `jwt-token`ヘッダのトークンを検証し、管理者会員を特定する。検証できない場合は認証拒否（HTTP 401）とする。
2. パスの受注IDで店頭買取受注を1件取得する。該当が無い場合は該当なし（HTTP 404）とする。
3. 更新前のステータスを保持する。
4. リクエストのステータスID（`status`）で店頭買取ステータスマスタを引く。該当が無い場合は入力不正（HTTP 400）とし「正しい店頭買取ステータスIDを入力してください」を返す。
5. 更新前ステータスが査定終了に該当する場合は更新不可とし、入力不正（HTTP 400）を返す。指定ステータスが査定中・査定再開のときは「この査定はすでに終了しているため開くことができません。」、それ以外は「この査定はすでに終了しているためステータスの更新に失敗しました。」を返す。
6. 更新前ステータスが査定中・査定再開で、かつ指定ステータスも査定中・査定再開で、その受注の査定担当者が認証した管理者会員と異なる場合は、入力不正（HTTP 400）とし「この受注は「（査定担当者名）」が査定中です。」を返す。
7. 更新前ステータスと指定ステータスが異なる場合のみ、受注のステータス・査定担当者・更新日時を更新し、ステータス変更履歴を1件登録する。更新前後が同じステータスのときは更新も履歴登録も行わない。
8. コード200のJSONを返す。

## 入出力

### リクエスト

| パラメータ | 位置 | 型 | 必須／任意 | 説明 |
|------------|------|----|-----------|------|
| `id` | パス | integer | 必須 | 更新対象の店頭買取受注ID。 |
| `status` | ボディ（フォーム値） | integer | 必須 | 設定する店頭買取ステータスID。店頭買取ステータスマスタに存在する値であること。 |
| `jwt-token` | ヘッダ | string | 必須 | 認証用のJWTトークン。 |

店頭買取ステータスマスタに登録されているステータスIDは、成立（1）・キャンセル（2）・ダブルチェック済（3）・データ出力済（4）・商品到着（5）・査定中（6）・振込前（7）・保留（8）・査定再開（9）である。これらに存在しないIDを指定した場合は入力不正（HTTP 400）となる。

### レスポンス（成功）

HTTP 200。

| フィールド | 型 | 説明 |
|------------|----|------|
| `code` | integer | 処理結果コード。成功時は200。更新前後が同じステータスでも200を返す。 |

### レスポンス（失敗）

| HTTPステータス | 条件 | 本文の形 |
|----------------|------|----------|
| 401 | トークン欠落・署名不正・該当する管理者会員なし | 認証拒否（本文を持たない） |
| 404 | 受注IDに該当する店頭買取受注が無い | 該当なし（本文を持たない） |
| 400 | 指定ステータスIDが店頭買取ステータスマスタに存在しない | `{code, errors}`（`errors`は「正しい店頭買取ステータスIDを入力してください」） |
| 400 | 更新前ステータスが査定終了で、指定ステータスが査定中・査定再開 | `{code, errors}`（`errors`は「この査定はすでに終了しているため開くことができません。」） |
| 400 | 更新前ステータスが査定終了で、指定ステータスがそれ以外 | `{code, errors}`（`errors`は「この査定はすでに終了しているためステータスの更新に失敗しました。」） |
| 400 | 査定中・査定再開の受注を、査定担当者本人以外が査定中・査定再開へ更新 | `{code, errors}`（`errors`は「この受注は「（査定担当者名）」が査定中です。」） |
| 500 | 保存処理中の例外 | 共通例外処理に委ねる |

### サンプルレスポンス

成功時の応答例。

```json
{
  "code": 200
}
```

### 副作用

更新前後でステータスが異なる場合に、店頭買取受注のステータス・査定担当者・更新日時を更新し（DB更新）、ステータス変更履歴を1件登録する。履歴には受注ID・更新後ステータスID・更新担当者ID・登録日時を記録する。参照のみではない。更新前後が同じステータスのときは更新も履歴登録も行わない。

応答はJSON応答整形を経て返す。プロパティはcamelCase、日時はISO8601、`serialize_null`は有効とする。

## バリデーション

| 項目 | 内容 |
|------|------|
| `status` | 必須。店頭買取ステータスマスタに存在するIDであること。存在しない場合は入力不正（HTTP 400）とし、「正しい店頭買取ステータスIDを入力してください」を返す。 |
| ステータス遷移（査定終了） | 更新前が査定終了に該当する場合は更新できない。入力不正（HTTP 400）とし、指定先が査定中・査定再開かどうかでメッセージを切り替える。 |
| ステータス遷移（査定中の占有） | 更新前と指定先がいずれも査定中・査定再開で、査定担当者が認証会員と異なる場合は更新できない。入力不正（HTTP 400）とし、査定担当者名を含むメッセージを返す。 |
| `id` | パスの受注ID。該当する店頭買取受注が無い場合は該当なし（HTTP 404）とする。 |

| 観点 | 内容 |
|------|------|
| 参照時点 | 更新時点で存在する店頭買取受注と店頭買取ステータスマスタを対象に判定・更新する。 |

| 操作種別 | 対象テーブル | 契機・条件 |
|---------|--------------|------------|
| 登録/更新 | dtb_otc_buy_order / dtb_otc_buy_order_status_history / mtb_otc_buy_order_status | 当機能が行う登録・更新で対象テーブルを直接保存する（不要な削除は含まない）。確定は persist/flush による即時反映。DB=ec-cube-enterprise を正典とする。 |

## 権限・認可

| 利用者状態 | 店頭買取受注ステータス更新 |
|------------|----------------------------|
| 認証済みの管理者会員 | ステータス遷移の制約を満たす範囲でステータス・査定担当者・更新日時を更新できる。 |

## エラー処理

| エラー内容 | 処理 |
|------------|------|
| 認証不可 | 認証拒否（HTTP 401）とする。 |
| 受注が存在しない | 該当なし（HTTP 404）とする。 |
| ステータスIDが不正 | 入力不正（HTTP 400）とし、「正しい店頭買取ステータスIDを入力してください」を返す。 |
| 査定終了後の更新 | 入力不正（HTTP 400）とし、指定先に応じて「この査定はすでに終了しているため開くことができません。」または「この査定はすでに終了しているためステータスの更新に失敗しました。」を返す。 |
| 他担当者が査定中の受注の査定開始 | 入力不正（HTTP 400）とし、「この受注は「（査定担当者名）」が査定中です。」を返す。 |
| 保存処理中の例外 | 共通例外処理に委ねる（HTTP 500相当）。 |

## ログ・監査

ステータス変更の履歴は店頭買取ステータス変更履歴として永続化する（受注ID・更新後ステータスID・更新担当者ID・登録日時）。アプリケーションログとは別のDB上の業務履歴である。

### ログに出してはいけないもの

- JWTトークンの原値
- 署名シークレット（`auth_magic`）
- Cookie値・セッションIDの完全値

## 排他制御・トランザクション

本APIはステータス更新と履歴登録を行う。楽観ロック・悲観ロックの対象は持たず、同一受注への同時更新は後勝ちとなる。査定中・査定再開の占有は査定担当者の比較による業務判定であり、DBレベルのロックではない。
