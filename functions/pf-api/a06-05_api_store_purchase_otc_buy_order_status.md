# API 店頭買取管理 — 店頭買取受注ステータス更新

## 業務ロジック

### 認証と担当者

トークンを検証して管理者会員を特定する。トークンの欠落・署名不正・該当する管理者会員なしのいずれのときも認証拒否（HTTP 401）とする。認証した管理者会員を査定担当者として記録する。査定中・査定再開の受注を査定中・査定再開へ更新できるのは、その受注の査定担当者本人だけである。呼び出し元は買取アプリで、トークンの原値と署名の秘密値は本書に記載しない。

### 更新の判定順序

| 順序 | 判定 | 結果 |
| --- | --- | --- |
| 1 | 認証できるか | できないなら認証拒否（HTTP 401） |
| 2 | 受注IDに該当する店頭買取受注があるか | 無ければ該当なし（HTTP 404） |
| 3 | 指定ステータスIDが店頭買取ステータスに存在するか | 存在しなければ入力不正（HTTP 400） |
| 4 | 更新前ステータスが査定終了か | 査定終了なら更新せず入力不正（HTTP 400）。指定先が査定中・査定再開のときとそれ以外で文言を分ける |
| 5 | 更新前が査定中・査定再開で、指定も査定中・査定再開か | その受注の査定担当者が認証した管理者会員と異なるなら入力不正（HTTP 400） |
| 6 | 更新前ステータスと指定ステータスが異なるか | 異なるときだけ更新する。同じときは更新も履歴登録も行わず処理結果コード200を返す |

### 更新の内容

更新前後のステータスが異なるときは、受注のステータス・査定担当者・更新日時を更新し、ステータス変更履歴を1件登録する。金額・税・ポイント・在庫数量の再計算や丸めは行わない。応答は本APIで集計せず、処理結果コードを返す。

### 店頭買取ステータス

登録されているステータスIDは、成立（1）・キャンセル（2）・ダブルチェック済（3）・データ出力済（4）・商品到着（5）・査定中（6）・振込前（7）・保留（8）・査定再開（9）である。これらに存在しないIDを指定したときは入力不正（HTTP 400）とする。

### エラー時の扱い

| 事象 | 扱い |
| --- | --- |
| 認証不可 | 認証拒否（HTTP 401）とする。本文を持たない |
| 受注が存在しない | 該当なし（HTTP 404）とする。本文を持たない |
| ステータスIDが不正 | 入力不正（HTTP 400）とし、エラー内容を含むJSONを返す |
| 査定終了後の更新 | 入力不正（HTTP 400）とし、指定先に応じた文言を返す |
| 他担当者が査定中の受注の査定開始 | 入力不正（HTTP 400）とし、査定担当者名を含む文言を返す |
| 保存処理中の例外 | 共通の例外処理に委ねる（HTTP 500相当） |

## 入出力

| 種類 | 内容 |
| --- | --- |
| 入力 | 店頭買取受注ID、設定する店頭買取ステータスID、認証用トークン |
| 成功時出力 | HTTP 200。処理結果コード。更新前後が同じステータスでも200を返す |
| 失敗時出力 | HTTP 401（認証不可）、HTTP 404（受注なし）、HTTP 400（入力不正・状態不整合・担当者不一致）、HTTP 500（保存処理中の例外） |

### 入出力: リクエスト

| パラメータ | 位置 | 型 | 必須／任意 | 説明 |
| --- | --- | --- | --- | --- |
| `id` | パス | integer | 必須 | 更新対象の店頭買取受注ID |
| `status` | ボディ（フォーム値） | integer | 必須 | 設定する店頭買取ステータスID。店頭買取ステータスに存在する値であること |
| 認証トークン | ヘッダ | string | 必須 | 管理者会員を特定するためのトークン |

### 入出力: 永続化

| 操作 | 契機 |
| --- | --- |
| 更新 | 更新前後のステータスが異なるとき、店頭買取受注のステータス・査定担当者・更新日時を更新する |
| 追加 | 同じ契機で、ステータス変更履歴を1件登録する |
