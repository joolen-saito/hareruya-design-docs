# API デッキビルダー — デッキ情報参照

## 概要

デッキビルダーアプリの利用者が、デッキIDを指定して1件のデッキ情報を参照するためのAPIである。deck-api（デッキビルダー用のAPIアプリケーション）が提供するJSON APIで、Redis一時保存（下書き）があればそれを、無ければデータベースのデッキ情報を返す。公開範囲に応じて参照可否を判定する。

本書は実装手順ではなく、誰が・いつ・どの条件で・結果どうなるかを読むためのリバース詳細設計とする。確認値はdeck-apiのデッキ取得処理、ルート定義（`config/routes.yaml`）、デッキ情報取得処理（デッキリポジトリ・Redis一時保存取得）、デッキを扱うエンティティ、共通の認証処理を正とする。

本機能のカスタマイズ区分は現行踏襲とする。挙動はdeck-api（デッキビルダー用APIアプリケーション）の実装を確認値とし、DB関連の記述（テーブル名・列名・永続化先）はec-cube-enterpriseの実装を正とする。

対象はJSON APIエンドポイントであり、ブラウザ向けの画面を持たない。本文ではフレームワークのコントローラ型名やメソッド名を主説明としない。「利用者視点の入口」にHTTPメソッドとパスパターンを書く。

---

## 本書で扱うこと

- デッキIDによる1件のデッキ情報の参照
- Redis一時保存（下書き）優先・データベースフォールバックの取得順
- 公開範囲（公開・非公開・限定公開）に応じた参照可否の判定
- 採用カード・タグ・キャンペーンタグを含む応答内容
- 該当なし時の応答

---

## 本書で扱わないこと

以下は本書では仕様確定せず、実装または別APIの設計を正とする。

- デッキの新規登録・更新・削除（デッキ情報登録・デッキ情報更新・デッキ情報削除の各APIの設計を正とする）
- 複数デッキの検索・一覧（デッキ情報検索APIの設計を正とする）
- カード採用枚数集計・メタゲーム等の集計系API
- トークンの発行（デッキビルダー用ログインの設計を正とする）

## リニューアル移行時の扱い

デッキビルダー関連テーブルは、現行（deck-api）と移行先（ec-cube-enterprise）で同一スキーマであり、テーブル名も一致する。本機能の参照に関わる主な対応は次のとおり。

| 項目 | 現行（deck-api） | 移行先（ec-cube-enterprise） | 差分・注意 |
|------|------------------|------------------------------|-----------|
| デッキ本体 | `dtb_deck` | `dtb_deck` | 同一テーブル名。 |
| 公開範囲 | 応答の`scope_id`。DB上は公開区分（`disp_id`、公開区分マスタ`mtb_disp`）・非公開フラグ（`private_flg`）・閲覧用トークン（`display_token`）の組み合わせ | 同一。`disp_id`・`private_flg`・`display_token` | 列名`scope_id`はDBに存在しない。応答キーとDB列の対応に注意する。 |
| 採用カード等 | `dtb_deck_card`・`dtb_maybe_card`・`dtb_attraction_card`・`dtb_sticker_card` | 同名の各テーブル | ボード別の採用カードを結合する点も同一。 |
| デッキタグ・キャンペーンタグ | `mtb_deck_tag`・`mtb_campaign_tag`（多対多） | 同名の各テーブル | キャンペーンタグの開催期間は`view_start_date`・`view_end_date`で保持する。 |
| 論理削除 | 削除日時（`deleted_at`） | 削除日時（`deleted_at`） | 物理削除は行わない。 |

現行と移行先でスキーマに差はなく、移行時に追加・改廃する列は本書では確認していない。

| 用語 | 説明 |
|------|------|
| デッキ | プレイヤーが作成するカードの組み合わせ。デッキIDで一意に特定する。 |
| 公開範囲 | デッキの公開区分。公開（1）・非公開（2）・限定公開（3）。 |
| 限定公開トークン | 限定公開デッキを閲覧するための識別子。`display_token`で照合する。 |
| 下書き | Redisに一時保存された未確定の更新内容。 |

## 利用者視点の入口

| 入口 | URLエンドポイント | 期待されるふるまい |
|------|--------------------|--------------------|
| デッキ情報の参照 | `GET /deck/{id}` | デッキIDの下書きまたはデータベース上のデッキ情報を、公開範囲に応じた可否判定のうえで返す。参照不可・該当なしの場合は該当なし（HTTP 404）とする。 |

応答形式はJSON。呼び出し元はデッキビルダーアプリ。

---

## 認証・認可

| 観点 | 内容 |
|------|------|
| 認証方式 | `jwt-token`ヘッダのJWTを検証し、ペイロード`aud`の顧客IDからプレイヤーを引く。署名方式はHS256。本APIではトークンが無くても公開デッキは参照できる。 |
| 認証失敗時 | トークンが無効・該当プレイヤーなしの場合でも本API自体は認証拒否を即返さず、公開範囲の判定に用いる。トークンが有効でない場合は所有者扱いとならない。 |
| 認可 | 公開デッキは誰でも参照できる。非公開デッキは所有者本人のみ参照できる。限定公開デッキは限定公開トークン一致時、または所有者本人のみ参照できる。 |

トークン原値・署名シークレット・限定公開トークン原値は本書に記載しない。

---

## 処理フロー

### デッキ情報を参照する（GET `/deck/{id}`）

1. クエリの限定公開トークン（`display_token`）を受領する。
2. デッキIDに対応するRedis一時保存（下書き）を取得する。
3. 下書きがある場合は公開範囲を判定する。公開デッキはそのまま返す。非公開デッキはトークン検証で所有者本人と確認できる場合のみ返す。限定公開デッキは限定公開トークン一致、または所有者本人の場合のみ返す。可否を満たす場合はコード200・メッセージを付与して返す。満たさない場合は該当なし（HTTP 404）とする。
4. 下書きが無い場合はデータベースからデッキIDの情報を取得する。
5. データベースのデッキについても同じ公開範囲判定を行う。可否を満たす場合はコード200・メッセージを付与して返す。満たさない、または該当が無い場合は該当なし（HTTP 404、「Deck is not found」）とする。

---

## 集計条件

本APIは1件のデッキ情報を参照するものであり、件数集計・並び替えは行わない。採用カードは複数ボード（メイン・サイド・統率領域・メイビー・アトラクション・ステッカー）と不明カードを結合して配列で返すが、ページングは行わない。

## 入出力

### リクエスト

| パラメータ | 位置 | 型 | 必須／任意 | 説明 |
|------------|------|----|-----------|------|
| `id` | パス | integer | 必須 | 参照対象のデッキID。 |
| `display_token` | クエリ | string | 任意 | 限定公開デッキの閲覧用トークン。限定公開デッキの参照可否判定に用いる。 |
| `jwt-token` | ヘッダ | string | 任意 | 認証用のJWTトークン。非公開・限定公開デッキを所有者として参照する場合に必要。 |

### レスポンス（成功）

HTTP 200。応答はデッキ情報のキーと、付与する`code`・`message`を含む。

| フィールド | 型 | 説明 |
|------------|----|------|
| `code` | integer | 処理結果コード。成功時は200。 |
| `message` | string | 処理結果メッセージ。成功時は「Get deck success」。 |
| `deck_name` | string | デッキ名。 |
| `format_id` | integer | フォーマットの識別子。 |
| `format_name_jp` | string | フォーマット名（日本語）。 |
| `format_name_en` | string | フォーマット名（英語）。 |
| `archetype_id` | integer | アーキタイプの識別子。 |
| `archetype_name_jp` | string | アーキタイプ名（日本語）。 |
| `archetype_name_en` | string | アーキタイプ名（英語）。 |
| `card_id` | integer | 代表カードのカードID。 |
| `card_image` | string | 代表カード画像のURL。 |
| `deck_type` | string | デッキ種別。 |
| `scope_id` | integer | 公開範囲（1・2・3）。 |
| `deck_private_flag` | boolean | 非公開フラグ。 |
| `event_name_jp` | string | 大会名（日本語）。大会デッキの場合に値を持つ。 |
| `event_name_en` | string | 大会名（英語）。 |
| `event_date` | string | 大会日付。 |
| `player_name` | string | プレイヤー名（大会デッキの場合）。 |
| `result` | string | 成績。 |
| `ranking` | integer | 順位。 |
| `source_url` | string | 出典URL。 |
| `create_date` | string | 作成日時。 |
| `update_date` | string | 更新日時。 |
| `display_token` | string | 限定公開トークン。 |
| `deck_user_id` | string | 所有プレイヤーのデッキ利用者ID。 |
| `nickname` | string | 所有プレイヤーのニックネーム（ユーザーデッキの場合）。 |
| `deck_tags` | array | デッキタグの配列。各要素は`id`・`name_jp`・`name_en`。タグがある場合に含める。 |
| `campaign_tags` | array | キャンペーンタグの配列。各要素は`id`・`name_jp`・`name_en`・`is_during`（開催前0・開催中1・開催後2）。 |
| `cards` | array | 採用カードの配列。各要素は`id`・`name_jp`・`name_en`・`image_jp`・`image_en`・`cardtypes`（整数配列）・`colors`（整数配列）・`mana_value`・`count`・`board_id`・`is_sticker`・`is_attraction`・`is_unknown`。 |

下書き（Redis）から返す場合は、`cards`の要素は`count`・`board_id`を含むカード情報、`campaign_tags`は開催状態付きの配列となり、フォーマット名・アーキタイプ名・代表カード画像をマスタから補完して返す。

### レスポンス（失敗）

| HTTPステータス | 条件 | 本文の形 |
|----------------|------|----------|
| 404 | デッキが存在しない、または公開範囲の判定で参照不可 | `{code, message}`（messageは「Deck is not found」） |

本APIは公開デッキを認証なしで返すため、トークン欠落のみを理由に401を返すことはない。

### 副作用

無し（参照のみ）。Redis一時保存を読み取るが、本APIでは書き込み・削除を行わない。

応答はJSON応答整形を経て返す。プロパティはJSONキーに準じ、`serialize_null`は有効とする。

## 業務ルール・計算

- 検索・一覧・取得条件はリクエストパラメータ、ログイン状態、公開状態、店舗・支店条件、既存リポジトリの絞り込み順序を正とする。
- 件数、ページ番号、表示順は既存実装のデフォルトと上限に従い、取得後に業務値を再計算しない。
- 金額、ポイント、数量、ステータス、日時はDBまたは連携元の永続化済み値を返却し、レスポンス生成時の丸め・補正は行わない。
- 条件に一致しない、権限がない、または非公開のデータは空結果または既存のエラー形式で返す。

## データ整合性

| 観点 | 内容 |
|------|------|
| 参照時点 | 呼び出し時点のデータを返す。本APIはデータを更新しない。 |
| 取得順 | Redis一時保存（下書き）を優先し、無ければデータベースのデッキ情報を返す。 |
| 下書きとデータベース | 下書きがある場合は確定前の内容を返すため、データベースの確定内容と一致しないことがある。 |

## DBカラム

機能に直接関係する列のみ記載する。型や一覧の細部はスキーマを参照する。

| テーブル | 列 | メモ |
|----------|-----|------|
| デッキ（`dtb_deck`） | デッキID（`id`） | 対象の特定に用いる。 |
| デッキ（`dtb_deck`） | デッキ名（`deck_name`）・公開区分（`disp_id`）・非公開フラグ（`private_flg`）・閲覧用トークン（`display_token`）・作成日時（`create_date`）・更新日時（`update_date`） | 応答に含める。応答の`scope_id`は公開区分・非公開フラグ・閲覧用トークンから組み立てる。 |
| デッキ（`dtb_deck`） | 大会名（`event_name_jp`・`event_name_en`）・大会日付（`event_date`）・成績（`result`）・順位（`ranking`）・出典URL（`source_url`）・プレイヤー名（`player_name`） | 大会デッキの応答に含める。 |
| 採用カード（`dtb_deck_card`）・メイビーカード（`dtb_maybe_card`）・アトラクションカード（`dtb_attraction_card`）・ステッカーカード（`dtb_sticker_card`） | デッキ（`deck_id`）・カード（`card_id`）・ボード（`board_id`）・枚数（`count`） | 採用カードの応答に結合する。 |
| デッキタグ（`mtb_deck_tag`）・キャンペーンタグ（`mtb_campaign_tag`） | タグID（`id`）・名称（`name_jp`・`name_en`）・開催期間（`view_start_date`・`view_end_date`） | タグ配列として応答に含める。 |

### DB操作

本機能は参照系（検索）であり、DBへの登録・更新・削除は行わない。テーブル名は ec-cube-enterprise を正典とする。

| 操作種別 | 対象テーブル | 契機・条件 |
|---------|--------------|------------|
| 検索 | dtb_attraction_card / dtb_deck / dtb_deck_card / dtb_maybe_card / dtb_sticker_card / mtb_campaign_tag 等 | 検索条件に合致するレコードを抽出する。 |

## 権限・認可

| 利用者状態 | デッキ情報参照 |
|------------|----------------|
| 任意の利用者（公開デッキ） | 参照できる。 |
| 所有者本人（非公開・限定公開デッキ） | 参照できる。 |
| 限定公開トークン一致の利用者（限定公開デッキ） | 参照できる。 |
| 上記以外（非公開・限定公開デッキで所有者でなくトークン不一致） | 該当なし（HTTP 404）となり、参照できない。 |

---

## エラー処理

| エラー内容 | 処理 |
|------------|------|
| デッキが存在しない | 該当なし（HTTP 404、「Deck is not found」）とする。 |
| 公開範囲の判定で参照不可 | 該当なし（HTTP 404、「Deck is not found」）とし、存在の有無を区別しない。 |

## ログ・監査

### ログに出してはいけないもの

- JWTトークンの原値
- 署名シークレット（`auth_magic`）
- 限定公開トークンの原値
- Cookie値・セッションIDの完全値

## ページネーション

本APIは1件のデッキを参照するものであり、`per_page`・`total_count`等のページングを持たない。

## 排他制御・トランザクション

本APIは参照のみであり、楽観ロック・悲観ロックの対象は持たない。
