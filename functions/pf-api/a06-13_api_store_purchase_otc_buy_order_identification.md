# API 店頭買取管理 — 本人確認更新

## 業務ロジック

### 更新の判定順序

| 順序 | 判定 | 結果 |
|------|------|------|
| 1 | トークンを検証して管理者会員を特定できるか | 特定できないときは認証拒否（HTTP 401）とする |
| 2 | パスの受注IDで店頭買取受注を取得できるか | 取得できないときは該当なし（HTTP 404）とする |
| 3 | 証明書IDが本人確認証明書マスタに存在するか | 存在しないときは入力不正（HTTP 400）とし、エラーメッセージを返す |
| 4 | 上記をすべて通過したとき | 本人確認証明書を設定して保存し、処理結果コード200を返す |

呼び出し可能なクライアントは買取アプリである。トークンの署名方式はHS256とする。トークン原値・署名シークレットは本書に記載しない。

### 更新する内容

店頭買取受注に本人確認証明書を設定し、更新担当者に認証した管理者会員を、更新日時に現在時刻を設定する。更新できたときは処理結果コード200だけを返す。金額・税・ポイント・在庫数量の再計算や丸めは行わない。応答は保存結果を整形して返し、本API内で独自に集計しない。

### エラー時の扱い

| エラー内容 | 処理 |
|------------|------|
| 認証できないとき | 認証拒否（HTTP 401）とする |
| 受注が存在しないとき | 該当なし（HTTP 404）とする |
| 証明書IDが不正なとき | 入力不正（HTTP 400）とし、「正しい証明書IDを入力してください」を返す |

## 入出力

| 種類 | 内容 |
| --- | --- |
| 入力 | 店頭買取受注ID、本人確認証明書のID、認証用トークン。証明書IDは必須で、未指定のときは入力不正となる |
| 成功時出力 | 更新できたときはHTTP 200。処理結果コード200 |
| 失敗時出力 | 認証拒否（HTTP 401）、該当なし（HTTP 404）、入力不正（HTTP 400） |

### 入力: リクエスト

| パラメータ | 位置 | 型 | 必須／任意 | 説明 |
|------------|------|----|-----------|------|
| `id` | パス | integer | 必須 | 更新対象の店頭買取受注ID |
| `identification` | ボディ（フォーム値） | integer | 必須 | 設定する本人確認証明書のID。本人確認証明書マスタに存在しない値のときは入力不正（HTTP 400）となる |
| `jwt-token` | ヘッダ | string | 必須 | 認証用のトークン |

### 出力: レスポンス

| フィールド | 型 | 説明 |
|------------|----|------|
| `code` | integer | 処理結果コード。成功したときは200 |

| HTTPステータス | 条件 | 本文の形 |
|----------------|------|----------|
| 401 | トークン欠落・署名不正・該当する管理者会員なしのとき | 認証拒否（本文を持たない） |
| 404 | 受注IDに該当する店頭買取受注が無いとき | 該当なし（本文を持たない） |
| 400 | 証明書IDが本人確認証明書マスタに存在しないとき（未指定を含む） | `{code, errors}`（`errors`は「正しい証明書IDを入力してください」） |

### 入出力: 永続化

| 操作 | 契機 |
| --- | --- |
| 更新 | 本人確認更新（本人確認証明書・更新担当者・更新日時） |
