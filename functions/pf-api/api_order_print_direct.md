# API 受注管理 — 注文印刷（印刷情報送信・印刷済み更新）

## 概要

店頭のスタック用紙プリンタ（印刷クライアント）が、印刷対象の受注からスタック用紙の印刷情報を取得し、印刷完了後に該当受注のステータスを印刷済み相当へ更新するためのAPIである。pf-api（受注・買取連携用のAPIアプリケーション）が提供するエンドポイントで、リクエストパラメータ`ConnectionType`の値によって動作が2系統に分岐する。

本書は実装手順ではなく、誰が・いつ・どの条件で・結果どうなるかを読むためのリバース詳細設計とする。確認値はpf-apiの注文印刷処理、ルート定義（`config/routes.yaml`）、受注の印刷情報取得処理、店頭注文番号の参照、受注ステータスのマスタ定義を正とする。

本機能のカスタマイズ区分はカスタマイズで、挙動の参照リポはpf-api、DB関連の記述はec-cube-enterpriseを正とする。

本エンドポイントの応答はJSONではなく、印刷情報を表すXML（`GetRequest`系）または空応答（`SetResponse`系）である。本文ではフレームワークのコントローラ型名やメソッド名を主説明としない。「利用者視点の入口」にHTTPメソッドとパスパターンを書く。

本書は次の2つの機能を1つのエンドポイントとして扱う。

- A05-01 注文印刷_印刷情報をプリンタへ送信（`ConnectionType`が`GetRequest`の分岐）
- A05-02 注文印刷_該当受注のステータスを印刷済みに変更（`ConnectionType`が`SetResponse`の分岐）

- 印刷対象受注の抽出と、スタック用紙の印刷情報（XML）の生成・送信（`GetRequest`）

- 印刷情報のXMLログファイルへの書き出しという副作用

## リニューアル移行時の扱い

挙動は現行（pf-api）を正とし、DBスキーマは移行先のec-cube-enterpriseを正とする。現行と移行先で次の差がある。

| 観点 | 現行（pf-api） | 移行先（ec-cube-enterprise） |
|------|----------------|------------------------------|
| 受注補助情報の配置 | 注文番号・スマレジコード・ブラウザ印刷フラグ・確定日時等を補助表`dtb_order_sub`に分離して持つ。 | 同等の列を受注`dtb_order`へ統合する（`order_number`・`smaregi_code`・`browser_print_flg`・`confirm_date`等）。補助表は持たない。 |
| 印刷済み（ピック中）への更新 | 受注ステータスの更新と補助表の確定日時更新で印刷済み相当を表す。 | 受注`dtb_order`の`picking_date`・`pick_finish_date`・`browser_print_flg`で印刷・ピック状態を保持する。 |
| 店頭注文番号（待ち番号） | 補助表`dtb_order_sub`の`waiting_number`で持つ。 | 店頭注文番号`dtb_order_number`の`value`（および受注`dtb_order`の`order_number`）で持つ。 |
| 配送方法の判別 | 配送`dtb_shipping`の配送方法で店頭受取・スムーズ店頭受取を判別する。 | 同一スキーマ。`dtb_shipping`の配送方法で判別する。 |

応答形式（XML・空応答）とプリンタ向けレイアウトは移行後も挙動仕様としてpf-apiを正とする。

| 用語 | 説明 |
|------|------|
| スタック用紙 | 店頭で受注内容を印字するロール紙。1受注ごとに1枚分の印刷情報を生成する。 |

| 印刷ログファイル | 印刷不具合検証のために生成した印刷情報のXMLを保存するファイル。 |

## 処理フロー

### 印刷情報を送信する（GET `/order/print/direct`、`ConnectionType`が`GetRequest`）

1. リクエストの`ConnectionType`を読み、値が`GetRequest`であることを判定する。
2. 印刷対象の受注一覧を取得する。店頭受取で注文受領の受注、スムーズ店頭受取で所定の支払方法かつ未確定・未出荷・未取消・未受領・店頭予約日なし・スマレジコードありの受注、ブラウザ印刷フラグが立つ受注を対象とし、最大10件を取得する。
3. 受注ごとに、注文日・合計金額・店頭注文番号・スマレジコード・問い合わせ有無・注文詳細URLを組み立て、1受注分の印刷情報（`ePOSPrint`要素）を生成する。配送がスムーズ店頭受取の場合は合計金額欄を「スムーズ店頭受取」とする。
4. 全受注分を束ねたスタック用紙の印刷情報XMLを生成する。対象受注が無い場合はXMLを生成せず空文字とする。
5. 生成した印刷情報が空でない場合、印刷不具合検証のため印刷情報のXMLをログファイルへ書き出す（副作用）。
6. 印刷情報XMLを応答本体としてストリーム送信する。応答のContent-Typeは`application/octet-stream`とする。

### 印刷済みステータスへ更新する（POST `/order/print/direct`、`ConnectionType`が`SetResponse`）

1. リクエストの`ConnectionType`を読み、値が`SetResponse`であることを判定する。
2. POSTで受け取った`ResponseFile`のXMLを解析する。解析に失敗した場合は内容とエラーを記録して更新を行わずに戻る。
3. XMLの直接印刷結果が偽、または印刷結果要素が1件も無い場合は内容を記録して更新を行わずに戻る。
4. 印刷結果要素ごとに、印刷ジョブIDの先頭部分から受注IDを取り出し、対象受注を特定する。受注が見つからない場合はエラーを記録して次の要素へ進む。
5. 対象受注の補助情報のブラウザ印刷フラグが立っている場合は、そのフラグを倒すだけに留める。立っていない場合は受注のステータスをピック中へ更新し、補助情報の確定日時に現在時刻を設定する。
6. 各受注の更新を反映する。
7. 空の本文（HTTP 200、`text/xml`）を返す。

## 入出力

### リクエスト

| パラメータ | 位置 | 型 | 必須／任意 | 説明 |
|------------|------|----|-----------|------|
| `ConnectionType` | クエリまたはボディ | string | 必須 | 動作の分岐。`GetRequest`で印刷情報送信、`SetResponse`でステータス更新。いずれにも一致しない場合は処理を行わず本文を返さない。 |
| `ResponseFile` | ボディ | string | `SetResponse`時に必須 | プリンタが返した印刷結果のXML文字列。直接印刷結果の真偽と印刷結果要素（印刷ジョブID）を含む。`SetResponse`の更新対象の特定に用いる。 |

`ConnectionType`はGET・POSTいずれのリクエストからも取得する。`ResponseFile`はPOST本文から取得する。

### レスポンス（成功）

応答はJSONではない。分岐ごとに応答形式が異なる。

| 分岐 | HTTPステータス | Content-Type | 本体 |
|------|----------------|--------------|------|
| `GetRequest`（A05-01） | 200 | `application/octet-stream` | スタック用紙の印刷情報XMLをストリーム送信する。対象受注が無い場合は空のデータ。 |
| `SetResponse`（A05-02） | 200 | `text/xml; charset=utf-8` | 空の本文（本文長0）。 |

`GetRequest`が返すXMLの構造は次のとおり。

| 要素 | 説明 |
|------|------|
| `PrintRequestInfo` | ルート要素。バージョン属性を持ち、配下に受注ごとの`ePOSPrint`を並べる。 |
| `ePOSPrint` | 受注1件分の印刷情報。印刷先・タイムアウト・印刷ジョブID（受注ID）と印字レイアウトを持つ。 |
| `ePOSPrint/Parameter/printjobid` | 印刷ジョブID。受注IDを用いる。`SetResponse`での受注特定に対応する。 |
| `ePOSPrint/PrintData` | 印字レイアウト。店頭注文番号・注文詳細URLのQRコード・注文日・注文番号・お客様名・合計金額・スマレジコードのバーコード・各種チェック欄を含む。 |

### レスポンス（失敗）

本エンドポイントは認証・入力検証による明示的なエラー応答を組み立てない。異常時のふるまいは次のとおり。

| HTTPステータス | 条件 | 本文の形 |
|----------------|------|----------|
| 200 | `GetRequest`で対象受注が無い | 空のデータ（XML本体を持たない） |
| 200 | `SetResponse`で`ResponseFile`の解析失敗、直接印刷結果が偽、印刷結果要素が無い、または受注が見つからない | 空の本文。更新は行わず、内容とエラーをログに記録する。 |
| （応答なし） | `ConnectionType`が`GetRequest`・`SetResponse`のいずれにも一致しない | 応答を組み立てず本文を返さない。 |
| 500 | 印刷情報生成中・データ取得中・ファイル書き出し中の例外 | 共通例外処理に委ねる |

### 副作用

本エンドポイントは参照のみではなく、次の副作用を持つ。

- 印刷ログファイルの書き出し（`GetRequest`）。生成した印刷情報が空でない場合、印刷情報のXMLをログ保存ディレクトリ（`var/log/print_logs/`配下）にタイムスタンプと一意名を付けたファイルとして書き出す。ディレクトリが存在しない場合は作成する。
- 受注ステータスの更新（`SetResponse`）。印刷結果に含まれる受注について、ブラウザ印刷フラグが立つ場合はフラグを倒し、立たない場合は受注のステータスをピック中へ更新し、補助情報の確定日時に現在時刻を設定する。これらはデータベースへの更新である。

応答はXMLまたは空応答であり、JSON応答整形・camelCaseのプロパティ命名は適用しない。

## バリデーション

本エンドポイントはフォーム型やマスタ存在チェックによる入力検証を行わない。`ConnectionType`が想定値（`GetRequest`・`SetResponse`）に一致しない場合は処理を行わず応答を組み立てない。`SetResponse`では`ResponseFile`のXML解析に失敗した場合と直接印刷結果が偽・印刷結果要素なしの場合に更新を行わずログに記録して戻る。

## データ整合性

| 観点 | 内容 |
|------|------|
| 参照時点 | `GetRequest`は呼び出し時点の印刷対象受注（最大10件）を取得して印刷情報を返す。 |
| 更新の有無 | `GetRequest`は受注ステータスを更新しない（印刷ログファイルの書き出しのみ）。`SetResponse`は受注ステータスと補助情報を更新する。 |
| 取得と更新の一致 | `GetRequest`で抽出した受注集合と`SetResponse`で更新される受注集合は同一トランザクションで保証されない。`SetResponse`はプリンタが返した`ResponseFile`の印刷ジョブID（受注ID）を基準に対象を特定する。 |
| 印刷とステータスの関係 | `GetRequest`は印刷情報を返した時点では受注を未印刷のまま残し、`SetResponse`を受け取って初めてピック中へ更新する。両者の呼び出しの間に受注が変化し得る。 |

## DBカラム

機能に直接関係する列のみ記載する。移行先（ec-cube-enterprise）の名称を主とし、現行（pf-api）で配置が異なる列は括弧で添える。型や一覧の細部はスキーマを参照する。

現行は注文番号・スマレジコード・ブラウザ印刷フラグ・確定日時等を補助表`dtb_order_sub`に持つが、移行先はこれらを受注`dtb_order`へ統合する。

| テーブル | 列 | メモ |
|----------|-----|------|
| 受注`dtb_order` | 受注ID | 印刷ジョブIDと注文詳細URLに用いる。`SetResponse`の対象特定にも用いる。 |
| 受注`dtb_order` | 受注ステータス（`order_status_id`） | 印刷対象抽出の条件、および`SetResponse`でピック中へ更新する対象。 |
| 受注`dtb_order` | `picking_date`・`pick_finish_date` | `SetResponse`でピック中へ更新する際に設定する。 |
| 受注`dtb_order` | 注文日（`order_date`） | 印刷情報の注文日欄。 |
| 受注`dtb_order` | 注文者氏名・氏名カナ | 印刷情報のお客様名欄（カナを優先し、無ければ氏名）。 |
| 受注`dtb_order` | 合計金額（`payment_total`） | 印刷情報の合計金額欄。スムーズ店頭受取時は文言に置換する。 |
| 受注`dtb_order` | `order_number`（現行は補助表`dtb_order_sub`の`order_number`） | 印刷情報の注文番号欄。抽出条件で注文番号ありを必須とする。 |
| 受注`dtb_order` | `smaregi_code`（現行は`dtb_order_sub`） | 印刷情報のバーコードに用いる。抽出条件にも用いる。 |
| 受注`dtb_order` | `browser_print_flg`（現行は`dtb_order_sub`） | 印刷対象抽出の条件。`SetResponse`では立つ場合にフラグを倒すだけに留める。 |
| 受注`dtb_order` | `confirm_date`（現行は`dtb_order_sub`） | `SetResponse`でステータス更新時に現在時刻を設定する。抽出条件では未設定を要求する。 |
| 受注`dtb_order` | 出荷日時・取消日時・受領日時・店頭予約日時（現行は`dtb_order_sub`の各日時列） | スムーズ店頭受取の抽出条件で未設定を要求する。 |
| 店頭注文番号`dtb_order_number` | `value`（現行は補助表`dtb_order_sub`の`waiting_number`） | 印刷情報の店頭注文番号欄。受注IDで引く。 |
| 配送`dtb_shipping` | 配送方法 | 店頭受取・スムーズ店頭受取の判別。抽出条件と合計金額欄の文言切替に用いる。 |

### DB操作

本機能は参照系（検索・出力）であり、DBへの登録・更新・削除は行わない。テーブル名は ec-cube-enterprise を正典とする。

| 操作種別 | 対象テーブル | 契機・条件 |
|---------|--------------|------------|
| 検索 | dtb_order / dtb_order_number / dtb_order_sub / dtb_shipping | 検索条件に合致するレコードを抽出する。抽出結果を所定フォーマットでファイル出力する。 |

## エラー処理

| エラー内容 | 処理 |
|------------|------|
| `ConnectionType`が想定値に一致しない | 処理を行わず応答を組み立てない。 |
| `GetRequest`で対象受注が無い | 空のデータを返す。ログファイルの書き出しも行わない。 |
| `SetResponse`で`ResponseFile`の解析失敗 | 内容とエラーをログに記録し、更新を行わずに戻る。 |
| `SetResponse`で直接印刷結果が偽・印刷結果要素なし | 内容をログに記録し、更新を行わずに戻る。 |
| `SetResponse`で受注が見つからない | 該当受注IDのエラーをログに記録し、その要素を飛ばして次へ進む。 |
| 印刷情報生成・データ取得・ファイル書き出し中の例外 | 共通例外処理に委ねる（HTTP 500相当）。 |

---

## ログ・監査

`SetResponse`では、`ResponseFile`の解析失敗・直接印刷結果が偽・印刷結果要素なし・受注が見つからない場合に、その内容やエラーをログへ記録する。`GetRequest`では、生成した印刷情報のXMLを印刷不具合検証用のログファイル（`var/log/print_logs/`配下）へ書き出す。

### ログに出してはいけないもの

- JWTトークンの原値
- 署名シークレット（`auth_magic`）
- Cookie値・セッションIDの完全値

---

## 排他制御・トランザクション

`GetRequest`は受注を更新せず、ロックの対象を持たない。`SetResponse`は受注ごとに更新を反映するが、印刷結果に含まれる受注集合に対する明示的な悲観ロック・楽観ロックは設けていない。`GetRequest`で抽出した受注と`SetResponse`で更新する受注は別リクエストであり、同一トランザクション境界で保証しない。
