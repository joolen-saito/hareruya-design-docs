# API カード管理 — 検索クエリに一致するカード情報1件を取得

## 概要

検索クエリ（パラメータ）に一致するカード情報を1件取得するAPIである。pf-apiが提供するJSON APIで、指定した条件に合致するカードを1件返す。

本書は実装手順ではなく、誰が・いつ・どの条件で・結果どうなるかを読むためのリバース詳細設計とする。確認値はpf-apiのカード検索取得処理、ルート定義、カードマスタを扱うリポジトリを正とする。

本機能のカスタマイズ区分は現行踏襲であり、挙動はpf-apiの現行実装を、DB関連はec-cube-enterpriseの実装を正とする。

対象はJSON APIエンドポイントであり、ブラウザ向けの画面を持たない。

---

## 本書で扱うこと

- 検索クエリ（パラメータ）に一致するカード1件の取得
- 該当が無い場合の応答

---

## 本書で扱わないこと

以下は本書では仕様確定せず、実装または別機能の設計を正とする。

- カードID・カード詳細IDによる取得（各APIを正とする）
- 検索条件の項目仕様（実装を確認値とする）

## リニューアル移行時の扱い

DB関連の記述はec-cube-enterpriseの実装を正とする。挙動は現行のpf-api実装を正とする。

| 観点 | 現行（pf-api） | 移行先（ec-cube-enterprise） |
|------|----------------|------------------------------|
| カードマスタのテーブル | `mtb_card` | `mtb_card`（同一スキーマ） |
| 検索・応答に用いる列 | カード名（`name_jp`・`name_en`） | 同一の列名（差分なし） |
| カード画像URL | 画像情報から組み立てる導出値（永続化列ではない） | 同一の扱い |

カードマスタは現行と移行先でテーブル名・主な列名が同一であり、永続化スキーマの差はない。移行に伴うAPIの応答仕様の変更は本書では確定しない。

## 利用者視点の入口

| 入口 | URLエンドポイント | 期待されるふるまい |
|------|--------------------|--------------------|
| 検索クエリに一致するカード1件取得 | `GET /card`（クエリパラメータで条件指定） | 条件に一致するカードを1件JSONで返す。該当が無い場合は404を返す。 |

応答形式はJSON。条件はクエリパラメータで渡す。

---

## 処理フロー

### カードを検索取得する（GET `/card`）

1. クエリパラメータの検索条件を受け取る。
2. カードマスタのリポジトリから、条件に一致するカードを1件取得する。
3. 取得できない場合はコード404・「Not Found」のJSONを返す。
4. 取得できた場合はカード情報をJSONで返す。

---

## 集計条件

| 指標 | 集計の要点 |
|------|------------|
| 取得対象 | クエリパラメータの条件に一致するカード。 |
| 件数 | 1件を返す（一致がある場合）。 |

---

## 入出力

### リクエスト

| パラメータ | 位置 | 型 | 必須／任意 | 説明 |
|------------|------|----|-----------|------|
| `name` | クエリ | string | 必須 | カード名。日名・英名・日名/英名・英名/日名の形を受け取る。分割カードは`+`で繋ぐ入力を想定し、内部で`/`に置換する。本パラメータが空のときは該当なしとして扱う。 |
| `lang` | クエリ | string | 任意 | カード言語。`ja`のとき日本語、それ以外は英語として並び順の優先言語に用いる。 |

### レスポンス（成功）

HTTP 200。

条件に一致するカードを1件返す。リポジトリのネイティブクエリが返すスカラ結果で、以下のフィールドを持つ。

| フィールド | 型 | 説明 |
|------------|----|------|
| `id` | integer | カードID。 |
| `nameJp` | string | カード名（日）。 |
| `nameEn` | string | カード名（英）。 |
| `image_url` | string | カード画像のURL。 |

### レスポンス（失敗）

| HTTPステータス | 条件 | 本文の形 |
|----------------|------|----------|
| 404 | 該当カードなし（一致が無い、または`name`が空相当） | `{code, message}`（"Not Found"） |

### サンプルレスポンス

成功時の応答例（実装確認値に基づく代表値）。

```json
{
  "id": 12345,
  "nameJp": "稲妻",
  "nameEn": "Lightning Bolt",
  "image_url": "https://example.com/images/card/12345.jpg"
}
```

### 副作用

無し（参照のみ）。

応答はJSON応答整形を経て返す。プロパティはcamelCase、日時はISO8601とする。

## 業務ルール・計算

- 検索・一覧・取得条件はリクエストパラメータ、ログイン状態、公開状態、店舗・支店条件、既存リポジトリの絞り込み順序を正とする。
- 件数、ページ番号、表示順は既存実装のデフォルトと上限に従い、取得後に業務値を再計算しない。
- 金額、ポイント、数量、ステータス、日時はDBまたは連携元の永続化済み値を返却し、レスポンス生成時の丸め・補正は行わない。
- 条件に一致しない、権限がない、または非公開のデータは空結果または既存のエラー形式で返す。
