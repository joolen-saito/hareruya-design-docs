# API ネット買取管理 — ネット買取注文の査定終了処理

## 概要

買取アプリ（MTGバイヤー）が、ネット買取注文の査定を終え、査定結果（買取明細とステータス）を確定するためのAPIである。pf-api（買取連携用のAPIアプリケーション）が提供するJSON APIで、受注IDで対象を特定し、送られた明細から買取代表カード・個別入力商品を登録・更新・削除し、合計額と買取受注ステータスを更新する。ステータスが変わった場合はステータス履歴も登録する。

本書は実装手順ではなく、誰が・いつ・どの条件で・結果どうなるかを読むためのリバース詳細設計とする。確認値はpf-apiのネット買取注文の査定終了処理、ルート定義（`config/routes.yaml`）、ネット買取受注を扱うエンティティとリポジトリ、入力検証用のエンティティと制約、共通の認証処理を正とする。本機能のカスタマイズ区分は現行踏襲であり、挙動はpf-apiの実装を参照し、DB関連（テーブル・列）の記述はec-cube-enterpriseを正とする。

対象はJSON APIエンドポイントであり、ブラウザ向けの画面を持たない。本文ではフレームワークのコントローラ型名やメソッド名を主説明としない。「利用者視点の入口」にHTTPメソッドとパスパターンを書く。

## 処理フロー

### ネット買取注文の査定を終了する（PUT `/admin/buyOrder/{id}.json`）

1. `jwt-token`ヘッダのトークンを検証し、管理者会員を特定する。検証できない場合は認証拒否（HTTP 401）とする。
2. パスの受注IDでネット買取受注を1件取得する。該当が無い場合は該当なし（HTTP 404）とする。
3. ボディのステータス（`order_status`）と明細配列（`order_details`）を受け取り、入力検証する。ステータスは選択必須かつ買取受注ステータスマスタに存在すること、明細配列は1件以上必須であること、各明細は商品名必須・数量／単価／商品規格ID／買取カテゴリが整数であることを検証する。検証エラーが1件以上あれば入力不正（HTTP 400）とし、エラーメッセージの配列を返す。
4. 明細を1件ずつ処理する。商品規格IDが`0`の明細は個別入力商品として、同名の既存があれば更新し、無ければ新規に作る。それ以外は商品規格から買取代表カードを特定し、同一条件の既存があれば更新し、無ければ新規に作って既存明細から申込時買取価格を引き継ぐ。各明細の単価×数量を合計額に加算する。
5. 受注に既存登録されているカードのうち、まとめ買取商品は申込時買取価格を削除し、サプライ・パック相当（カード詳細IDが未設定）の明細は合計額に加算して保持する。
6. 合計額を10円単位で切り上げ、受注にステータス・合計額・買取代表カード・個別入力商品・更新担当者・更新日時を設定する。今回保持しない既存の買取代表カード・個別入力商品とそれに紐づく申込時買取価格を削除する。
7. 更新前後でステータスが変わった場合は、受注のステータスと更新日時を再設定し、ステータス履歴を1件登録する。
8. ここまでを1つのトランザクションで確定する。処理中に例外が発生した場合はロールバックし、内部エラー（HTTP 500）とし、エラーメッセージの配列を返す。
9. 成功時はコード200のJSONを返す。

## 入出力

### リクエスト

| パラメータ | 位置 | 型 | 必須／任意 | 説明 |
|------------|------|----|-----------|------|
| `id` | パス | integer | 必須 | 更新対象のネット買取受注ID。該当が無い場合は該当なし（HTTP 404）。 |
| `order_status` | ボディ（フォーム値） | integer | 必須 | 設定する買取受注ステータスID。未指定は入力不正（HTTP 400）。買取受注ステータスマスタに存在しないIDも入力不正（HTTP 400）。 |
| `order_details` | ボディ（フォーム値） | array | 必須 | 明細の配列。空・配列以外は入力不正（HTTP 400）。各要素は`product_class_id`・`name`・`quantity`・`price`・`purchase_category`等のキーを持つ。 |
| `jwt-token` | ヘッダ | string | 必須 | 認証用のJWTトークン。 |

各明細（`order_details`の要素）が持つキーは次のとおり。

| キー | 型 | 必須／任意 | 説明 |
|------|----|-----------|------|
| `product_class_id` | string（整数文字列） | 任意 | 商品規格ID。`0`の明細は個別入力商品として扱う。整数以外は入力不正（HTTP 400）。 |
| `name` | string | 必須 | 商品名。未指定は入力不正（HTTP 400）。最大65535。 |
| `quantity` | string（整数文字列） | 任意 | 数量。整数以外は入力不正（HTTP 400）。 |
| `price` | string（整数文字列） | 任意 | 単価。整数以外は入力不正（HTTP 400）。 |
| `purchase_category` | string（整数文字列） | 任意 | 買取カテゴリ。整数以外は入力不正（HTTP 400）。 |
| `language_id`、`condition_id`、`foil_flg` | 各種 | 任意 | 買取代表カードの言語・状態・フォイル区分。明細処理で参照する。 |

### レスポンス（成功）

HTTP 200。

| フィールド | 型 | 説明 |
|------------|----|------|
| `code` | integer | 処理結果コード。成功時は200。 |

### レスポンス（失敗）

| HTTPステータス | 条件 | 本文の形 |
|----------------|------|----------|
| 401 | トークン欠落・署名不正・該当する管理者会員なし | 認証拒否（本文を持たない） |
| 404 | 受注IDに該当するネット買取受注が無い | 該当なし（本文を持たない） |
| 400 | ステータス・明細の入力検証に1件以上失敗 | `{code, errors}`（`errors`は検証メッセージの配列） |
| 500 | 更新処理中の例外（ロールバック後に返す） | `{code, errors}`（`errors`は例外メッセージの配列） |

### サンプルレスポンス

成功時の応答例。

```json
{
  "code": 200
}
```

入力検証失敗時の応答例。

```json
{
  "code": 400,
  "errors": [
    "ステータスを選択してください。",
    "1つ以上の商品を選んでください。"
  ]
}
```

### 副作用

ネット買取受注を更新する（DB更新）。具体的には次を行う。

- 受注の買取受注ステータス・合計額・更新担当者・更新日時を更新する。
- 送られた明細から買取代表カード・個別入力商品を登録・更新する。今回保持しない既存の買取代表カード・個別入力商品と、それに紐づく申込時買取価格を削除する。まとめ買取商品は申込時買取価格のみ削除する。
- 更新前後でステータスが変わった場合は、ステータス履歴を1件登録する（履歴に受注ID・ステータスID・更新担当者・登録日時を記録する）。

参照のみではない。応答はJSON応答整形を経て返す。プロパティはcamelCase、日時はISO8601、`serialize_null`は有効とする。

## バリデーション

| 項目 | 内容 |
|------|------|
| `order_status` | 必須。未指定は「ステータスを選択してください。」を返す。買取受注ステータスマスタに存在しないIDは「MtbBuyOrderStatusに（値）が見つかりません。」を返す。いずれも入力不正（HTTP 400）。 |
| `order_details` | 配列かつ1件以上必須。空・配列以外は「1つ以上の商品を選んでください。」を返す（HTTP 400）。 |
| 明細の`name` | 必須かつ最大65535。未指定は入力不正（HTTP 400）。超過時は「商品名は、（上限）以下で入力してください。」を返す。 |
| 明細の`product_class_id` | 整数のみ。整数以外は「商品規格IDは、整数で入力してください。」を返す（HTTP 400）。 |
| 明細の`quantity` | 整数のみ。整数以外は「数量は、整数で入力してください。」を返す（HTTP 400）。 |
| 明細の`price` | 整数のみ。整数以外は「単価は、整数で入力してください。」を返す（HTTP 400）。 |
| 明細の`purchase_category` | 整数のみ。整数以外は「買取カテゴリは、整数で入力してください。」を返す（HTTP 400）。 |

検証はステータス・明細全体と各明細を順に行い、収集したエラーメッセージを1つの配列にまとめる。1件以上あれば入力不正（HTTP 400）とし、更新は行わない。

## データ整合性

| 観点 | 内容 |
|------|------|
| 参照時点 | 更新時点で存在するネット買取受注を対象に更新する。受注が無い場合は該当なし（HTTP 404）とする。 |
| 更新範囲 | ステータス・合計額・買取代表カード・個別入力商品・更新担当者・更新日時を更新し、ステータス変更時は履歴を登録する。受注のその他項目は本APIでは変更しない。 |
| 合計額 | 送られた明細の単価×数量と、保持するサプライ・パック相当の明細額を合算し、10円単位で切り上げて確定する。 |
| 同時更新 | 同一受注への同時更新に対する楽観ロック・悲観ロックは持たない。後勝ちとなり、同時実行時は明細の削除・登録が競合し得る。 |

## エラー処理

## ログ・監査

### ログに出してはいけないもの

- 署名シークレット（`auth_magic`）

## 排他制御・トランザクション

本APIは受注の明細・合計額・ステータスの更新とステータス履歴の登録を1つのトランザクションで行う。明細の取得・登録・削除、受注の更新、履歴の登録までを1トランザクションとし、処理中に例外が発生した場合はロールバックして内部エラー（HTTP 500）を返す。楽観ロック・悲観ロックの対象は持たず、同一受注への同時更新は後勝ちとなる。
