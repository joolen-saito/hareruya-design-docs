# API 商品管理 — ポップアップ用カード情報取得（旧商品ID）

## 概要

旧商品IDと言語を指定して、記事内ポップアップ用の商品情報を取得するAPIである。pf-apiが提供するJSON APIで、旧システムの商品IDと言語を用いる呼び出しに対応する。

本書は実装手順ではなく、誰が・いつ・どの条件で・結果どうなるかを読むためのリバース詳細設計とする。確認値はpf-apiの旧商品IDと言語によるポップアップ取得処理、ルート定義、商品規格を扱うリポジトリを正とする。

本機能のカスタマイズ区分は現行踏襲で、挙動の参照リポはpf-api、DB関連の記述はec-cube-enterpriseを正とする。

対象はJSON APIエンドポイントであり、ブラウザ向けの画面を持たない。

実装上は旧商品IDと言語から商品規格のポップアップ用情報を取得する。

---

## 本書で扱うこと

- 旧商品IDと言語によるポップアップ用商品情報の取得
- 該当が無い場合の応答

---

## 本書で扱わないこと

以下は本書では仕様確定せず、実装または別機能の設計を正とする。

- 言語指定なしの旧商品IDによるポップアップ取得（ポップアップ用商品情報取得（旧商品ID）を正とする）
- 現行商品ID・カードIDによるポップアップ取得（各APIを正とする）

---

## リニューアル移行時の扱い

挙動は現行（pf-api）を正とし、DBスキーマは移行先のec-cube-enterpriseを正とする。現行と移行先で次の差がある。

| 観点 | 現行（pf-api） | 移行先（ec-cube-enterprise） |
|------|----------------|------------------------------|
| 旧商品ID | カードマスタ`mtb_card`の`old_product_id`（日本語）・`old_en_product_id`（英語）で引く。 | 同一スキーマ。`mtb_card.old_product_id`・`mtb_card.old_en_product_id`で引く。 |
| 言語 | 言語マスタ`mtb_language`の`code`で判別する。 | 同一スキーマ。`mtb_language.code`で判別する。 |
| 商品規格の補助列 | カードコンディション・言語・帯URL等を補助表`dtb_product_sub_class`に分離して持つ。 | 同等の列を商品規格`dtb_product_class`へ統合する。補助表は持たない。 |

応答フィールドの命名（camelCase）は移行後も挙動仕様としてpf-apiを正とする。

---

## 利用者視点の入口

| 入口 | URLエンドポイント | 期待されるふるまい |
|------|--------------------|--------------------|
| 旧商品IDと言語によるポップアップ用商品情報取得 | `GET /popup/old/{lang}/{oldProductId}` | 旧商品IDと言語に対応するポップアップ用商品情報をJSONで返す。該当が無い場合は404を返す。 |

応答形式はJSON。

---

## 処理フロー

### 旧商品IDと言語で取得する（GET `/popup/old/{lang}/{oldProductId}`）

1. パスの旧商品ID・言語を受け取る。
2. 商品規格のリポジトリから、旧商品ID・言語に対応するポップアップ用商品情報を取得する。
3. 取得できない場合はコード404・「Not Found」のJSONを返す。
4. 取得できた場合は商品情報をJSONで返す。

## 業務ルール・計算

| 項目 | 内容 |
|------|------|
| 対象データ | リクエストで指定されたID・条件に一致するデータを取得対象とする。抽出条件と該当なし時の扱いは処理フロー・入出力の各節を正とする。 |
| 計算処理 | 本APIでは金額・税・ポイント・在庫数量の再計算や丸めを行わない。DBまたはリポジトリから取得した値をJSON応答へ整形して返す。 |
| 応答値 | 応答フィールドは取得時点の値を返す。表示用の加工やフロントエンド側の表示制御は呼び出し元クライアントの設計を正とする。 |

---

## 入出力

### リクエスト

| パラメータ | 位置 | 型 | 必須／任意 | 説明 |
|------------|------|----|-----------|------|
| `lang` | パス | string | 必須 | 言語区分。`jp`または`en`を想定する（言語優先順の判定に用いる）。 |
| `oldProductId` | パス | integer | 必須 | 旧商品ID。カードの旧商品IDまたは旧英語商品IDと突き合わせる。 |

### レスポンス（成功）

HTTP 200。条件に合致する商品規格を一件返す。

| フィールド | 型 | 説明 |
|------------|----|------|
| `productId` | integer | 商品ID。 |
| `name` | string | 商品名。 |
| `productClassId` | integer | 商品規格ID。 |
| `price01` | string | 通常価格。Doctrineのdecimal値のため数値文字列で返す。 |
| `price02` | string | 販売価格。Doctrineのdecimal値のため数値文字列で返す。 |
| `stock` | string | 在庫数。Doctrineのdecimal値のため数値文字列で返す。 |
| `nameEn` | string | 英語商品名。 |
| `subFileName` | string | 商品規格画像のファイル名。該当が無い場合はnull。 |
| `fileName` | string | 商品画像のファイル名。該当が無い場合はnull。 |
| `weeklySold` | string | 週間販売数。集計（SUM）結果のため数値文字列で返す。 |

### レスポンス（失敗）

| HTTPステータス | 条件 | 本文の形 |
|----------------|------|----------|
| 404 | 該当する商品規格が無い | `{code, message}`（"Not Found"） |

### サンプルレスポンス

成功時の応答例（実装確認値に基づく代表値）。

```json
{
  "productId": 100001,
  "name": "サンプルカード",
  "productClassId": 200001,
  "price01": "500.00",
  "price02": "480.00",
  "stock": "12.00",
  "nameEn": "Sample Card",
  "subFileName": "sub_sample.jpg",
  "fileName": "sample.jpg",
  "weeklySold": "3"
}
```

### 副作用

無し（参照のみ）。

応答はJSON応答整形を経て返す。プロパティはcamelCase、日時はISO8601とする。

## DBカラム

移行先（ec-cube-enterprise）の名称を主とし、現行（pf-api）の配置が異なる場合は括弧で添える。

| テーブル | 列 | メモ |
|---------|-----|------|
| カードマスタ`mtb_card` | `old_product_id`・`old_en_product_id` | 旧商品IDの引き当てに使用する。 |
| 言語マスタ`mtb_language` | `code` | 言語の判別に使用する。 |
| 商品規格`dtb_product_class` | `language_id`・`belt_url`・`price01`・`price02`（現行は補助列を補助表`dtb_product_sub_class`に持つ） | 取得条件・応答内容に使用する。 |
| 商品`dtb_product` | `name`・`name_en` | 応答の商品名に使用する。 |
| 在庫`dtb_product_stock` | 在庫数 | 応答の`stock`に使用する。 |

### DB操作

本機能は参照系（検索）であり、DBへの登録・更新・削除は行わない。テーブル名は ec-cube-enterprise を正典とする。

| 操作種別 | 対象テーブル | 契機・条件 |
|---------|--------------|------------|
| 検索 | dtb_product / dtb_product_class / dtb_product_stock / dtb_product_sub_class / mtb_card / mtb_language | 検索条件に合致するレコードを抽出する。 |
