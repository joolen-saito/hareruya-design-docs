# API ネット買取管理 — ネット買取受注コメント更新

## 概要

買取アプリ（MTGバイヤー）がネット買取受注のフリーコメントを更新するためのAPIである。pf-api（買取連携用のAPIアプリケーション）が提供するJSON APIで、受注IDで対象を特定し、コメントと更新担当者を保存する。

本書は実装手順ではなく、誰が・いつ・どの条件で・結果どうなるかを読むためのリバース詳細設計とする。確認値はpf-apiのコメント更新処理、ルート定義（`config/routes.yaml`）、ネット買取受注を扱うエンティティ、共通の認証処理を正とする。

本機能のカスタマイズ区分は現行踏襲であり、挙動の参照リポはpf-api、DB関連（テーブル名・列名・永続化先）の記述はec-cube-enterpriseを正とする。

対象はJSON APIエンドポイントであり、ブラウザ向けの画面を持たない。本文ではフレームワークのコントローラ型名やメソッド名を主説明としない。「利用者視点の入口」にHTTPメソッドとパスパターンを書く。

---

## 本書で扱うこと

- 受注IDによるネット買取受注の特定と、フリーコメント・更新担当者の保存
- 認証、対象なし、コメント未入力時の応答

---

## 本書で扱わないこと

以下は本書では仕様確定せず、実装または別APIの設計を正とする。

- ネット買取受注そのものの登録・査定・ステータス更新（ネット買取受注ステータス更新APIおよび各買取APIの設計を正とする）
- 店頭買取受注のコメント更新（店頭買取受注コメント更新APIの設計を正とする）
- トークンの発行（買取アプリ用ログインの設計を正とする）

## リニューアル移行時の扱い

現行（pf-api）と移行先（ec-cube-enterprise）の差を記録する。挙動は現行（pf-api）を正とし、DB関連はec-cube-enterpriseを正とする。

| 観点 | 現行（pf-api） | 移行先（ec-cube-enterprise） |
|------|----------------|------------------------------|
| ネット買取受注テーブル | `dtb_buy_order`。受注IDの主キー列は `buy_order_id`。 | `dtb_buy_order`。受注IDの主キー列は `id`。対象特定のキー列名が現行と異なる。 |
| フリーコメントの保存列 | `memo`。 | `memo`。同一。 |
| 更新担当者の保存列 | `dtb_buy_order.member_id`。会員テーブル `dtb_member` の主キー `member_id` を参照する。 | `dtb_buy_order.member_id`。会員テーブル `dtb_member` の主キー `id` を参照する。参照先の主キー列名が現行と異なる。 |
| エンドポイントの配置 | サイトルート直下 `/admin/buyOrder/{id}/freeComment.json`。 | APIバージョンのルートプレフィックス（設定キー `eccube_api_v1_route`）配下に配置される。パス末尾 `admin/buyOrder/{id}/freeComment.json` は同じ。 |

## 用語

| 用語 | 説明 |
|------|------|
| ネット買取受注 | ネットで行う買取の受注。受注IDで一意に特定する。 |
| フリーコメント | ネット買取受注に付与する自由記述のコメント。受注のメモ列に保存する。 |
| 更新担当者 | コメントを更新した管理者会員。トークンから特定する。 |

## 利用者視点の入口

| 入口 | URLエンドポイント | 期待されるふるまい |
|------|--------------------|--------------------|
| ネット買取受注のコメント更新 | `PUT /admin/buyOrder/{id}/freeComment.json` | 受注IDのネット買取受注のフリーコメントと更新担当者を保存し、成功時はコード200のJSONを返す。 |

応答形式はJSON。呼び出し元は買取アプリ（MTGバイヤー）。ネット買取受注のコメント更新には拡張子なしの別名ルートは存在せず、`.json`付きのみを定義する。

## 認証・認可

| 観点 | 内容 |
|------|------|
| 認証方式 | `jwt-token`ヘッダのJWTを検証し、ペイロードの利用者IDから管理者会員を引く。署名方式はHS256。 |
| 認証失敗時 | ヘッダ欠落・署名不正・該当する管理者会員なしのいずれも認証拒否（HTTP 401）とする。 |
| 認可 | 認証した管理者会員が更新担当者として記録される。呼び出し可能なクライアントは買取アプリ。 |

トークン原値・署名シークレットは本書に記載しない。

---

## 処理フロー

### ネット買取受注のコメントを更新する（PUT `/admin/buyOrder/{id}/freeComment.json`）

1. `jwt-token`ヘッダのトークンを検証し、管理者会員を特定する。検証できない場合は認証拒否（HTTP 401）とする。
2. パスの受注IDでネット買取受注を1件取得する。該当が無い場合は該当なし（HTTP 404）とする。
3. リクエストのコメント（`free_comment`）が未指定（null）の場合は入力不正（HTTP 400）とし、エラーメッセージを返す。
4. ネット買取受注のメモ（フリーコメント）を指定値で更新し、更新担当者に認証した管理者会員を設定して保存する。保存はトランザクション内で行う。
5. コード200のJSONを返す。

## 業務ルール・計算

| 項目 | 内容 |
|------|------|
| 更新対象 | リクエストで指定されたID・入力値に対応する業務データを対象にする。対象特定、入力不正、認証・認可の判定順序は処理フローとバリデーションの各節を正とする。 |
| 更新方法 | 入力値を対象データへ上書きまたは追加登録する。履歴登録や関連データ更新がある場合は入出力の副作用およびDBカラムの節を正とする。 |
| 計算処理 | 本APIでは金額・税・ポイント・在庫数量の再計算や丸めを行わない。ステータスやコメント等の更新は、実装で定義された遷移・存在確認・担当者判定に従う。 |
| 応答値 | 成功時は処理結果コードまたは更新後に取得した値を返す。レスポンス値は本API内で独自集計せず、保存結果または取得結果をJSON応答へ整形する。 |

## 入出力

### リクエスト

| パラメータ | 位置 | 型 | 必須／任意 | 説明 |
|------------|------|----|-----------|------|
| `id` | パス | integer | 必須 | 更新対象のネット買取受注ID。 |
| `free_comment` | ボディ（フォーム値） | string | 必須 | 設定するフリーコメント。未指定（null）の場合は入力不正（HTTP 400）となる。 |
| `jwt-token` | ヘッダ | string | 必須 | 認証用のJWTトークン。 |

### レスポンス（成功）

HTTP 200。

| フィールド | 型 | 説明 |
|------------|----|------|
| `code` | integer | 処理結果コード。成功時は200。 |

### レスポンス（失敗）

| HTTPステータス | 条件 | 本文の形 |
|----------------|------|----------|
| 401 | トークン欠落・署名不正・該当する管理者会員なし | 認証拒否（本文を持たない） |
| 404 | 受注IDに該当するネット買取受注が無い | 該当なし（本文を持たない） |
| 400 | コメント（`free_comment`）が未指定 | `{code, errors}`（`errors`は「コメントを入力してください」） |
| 500 | 保存処理中の例外 | `{code, errors}`（`errors`は例外メッセージ。トランザクションはロールバックする） |

### サンプルレスポンス

成功時の応答例。

```json
{
  "code": 200
}
```

### 副作用

ネット買取受注のメモ（フリーコメント）と更新担当者を更新する（DB更新）。参照のみではない。更新はトランザクション内で確定し、例外時はロールバックする。

応答はJSON応答整形を経て返す。プロパティはcamelCase、日時はISO8601、`serialize_null`は有効とする。

|------|------|

## データ整合性

| 観点 | 内容 |
|------|------|
| 参照時点 | 更新時点で存在するネット買取受注を対象に更新する。 |
| 更新範囲 | メモ（フリーコメント）と更新担当者のみを更新する。受注の他項目・ステータスは本APIでは変更しない。 |
| 同時更新 | 同一受注への同時更新に対する排他制御は本APIでは持たない。 |

## DBカラム

機能に直接関係する列のみ記載する。型や一覧の細部はスキーマを参照する。

列名はec-cube-enterpriseを正とし、現行（pf-api）と異なるものは括弧で添える。

| テーブル | 列 | メモ |
|----------|-----|------|
| ネット買取受注 `dtb_buy_order` | 受注ID `id`（現行 `buy_order_id`） | 受注の特定に用いる。 |
| ネット買取受注 `dtb_buy_order` | メモ（フリーコメント） `memo` | 更新対象。指定値で上書きする。 |
| ネット買取受注 `dtb_buy_order` | 更新担当者 `member_id` | 認証した管理者会員（`dtb_member`）を記録する。 |

### DB操作

永続化の正は ec-cube-enterprise（テーブル名・操作は ec-cube-enterprise を正典）。当ドメインは承認ワークフローを介さず persist/flush で直接確定する（承認ワークフローは在庫機能固有）。

| 操作種別 | 対象テーブル | 契機・条件 |
|---------|--------------|------------|
| 登録/更新 | dtb_buy_order / dtb_member | 当機能が行う登録・更新で対象テーブルを直接保存する（不要な削除は含まない）。確定は persist/flush による即時反映。DB=ec-cube-enterprise を正典とする。 |

## 権限・認可

| 利用者状態 | ネット買取受注コメント更新 |
|------------|----------------------------|
| 認証済みの管理者会員 | コメントと更新担当者を更新できる。 |
| 未認証・トークン不正 | 認証拒否（HTTP 401）となり、更新できない。 |

## エラー処理

| エラー内容 | 処理 |
|------------|------|
| 認証不可 | 認証拒否（HTTP 401）とする。 |
| 受注が存在しない | 該当なし（HTTP 404）とする。 |
| コメント未指定 | 入力不正（HTTP 400）とし、「コメントを入力してください」を返す。 |
| 保存処理中の例外 | 処理失敗（HTTP 500）とし、例外メッセージを返す。トランザクションをロールバックする。 |

## 排他制御・トランザクション

本APIはメモ（フリーコメント）と更新担当者の更新をトランザクション内で行う。楽観ロック・悲観ロックの対象は持たず、同一受注への同時更新は後勝ちとなる。
