# API 受注管理 — 注文印刷（印刷情報の送信）

## 業務ロジック

### 印刷対象の受注

次のいずれかに当たる受注を、1回の要求につき最大10件まで取り出す。

| 対象 | 条件 |
| --- | --- |
| 店頭受取の受注 | 注文番号が採番済みで、対応状況が注文受領のとき |
| スムーズ店頭受取の受注 | 所定の支払方法（クレジット決済・支払いなし）で、対応状況が購入処理中でなく、確定日時・注文確定日・出荷日・取消日・受領日・店頭予約日がいずれも未設定で、スマレジコードが採番済みのとき |
| ブラウザ印刷を指定した受注 | 補助情報のブラウザ印刷フラグが立つとき |

1件の受注に配送が複数あっても、印刷情報は受注1件につき1枚にまとめる。

### 印刷内容の決定

| 印刷欄 | 決め方 |
| --- | --- |
| お客様名 | カナ氏名（姓と名を空白でつなぐ）を印刷する。カナ氏名が無いときは氏名を印刷する |
| 店頭注文番号 | 受注に店頭注文番号が採番されていないときは空欄にする |

### 印刷データの保存

送信する印刷データXMLが空でないとき、同じ内容をAPIサーバのアプリケーション配下の `var/log/print_logs/` にファイルとして保存する。ファイル名は `print_YYYYMMDD_HHMMSS_<一意ID>.xml` とし、要求1回につき1ファイルを作る。保存先のディレクトリが無いときは作成する。印刷データXMLが空のときは保存しない。

## 入出力

### 応答の形式

印刷情報は本文をストリーム送信する。応答の内容種別（Content-Type）は application/octet-stream とする。
