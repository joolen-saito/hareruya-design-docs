# API 受注管理 — 注文印刷（印刷情報送信・印刷済み更新）

## 業務ロジック

### 呼び出し元

呼び出すのは店頭のスタック用紙プリンタ（印刷クライアント）である。本エンドポイントは認証の判定を持たず、未認証で実行できる（確認値）。認証判定を持たないため、認証失敗による拒否は返さない。利用者の照合も行わない。

### 動作の分岐

接続種別が印刷情報要求のときは印刷情報を送信し、印刷結果応答のときは印刷済みへの更新を行う。いずれにも一致しない値のときは処理を行わず、応答を組み立てない。接続種別はGET・POSTのいずれの要求からも読み取る。

### 印刷対象の受注

次のいずれかに当たる受注を最大10件取得する。

- 店頭受取で注文受領の受注
- スムーズ店頭受取で、所定の支払方法かつ未確定・未出荷・未取消・未受領・店頭予約日なし・スマレジコードありの受注
- ブラウザ印刷フラグが立つ受注

対象受注が無いときは印刷情報を生成せず、空のデータを返す。

### 印刷情報の組み立て

受注ごとに、注文日・合計金額・店頭注文番号・スマレジコード・問い合わせ有無・注文詳細URLを組み立て、1受注分の印刷情報を生成する。配送がスムーズ店頭受取のときは、合計金額欄を「スムーズ店頭受取」とする。全受注分を束ねてスタック用紙の印刷情報を生成する。生成した印刷情報が空でないときは、印刷不具合の検証のため印刷情報を記録する。

### 印刷済みへの更新

受け取った印刷結果を解析し、印刷結果要素ごとに印刷ジョブIDの先頭部分から受注IDを取り出して対象受注を特定する。対象受注の補助情報のブラウザ印刷フラグが立っているときは、そのフラグを倒すだけに留める。立っていないときは受注のステータスをピック中へ更新し、補助情報の確定日時に現在時刻を設定する。

本APIでは金額・税・ポイント・在庫数量の再計算や丸めを行わない。ステータスの更新は、実装で定義された遷移・存在確認に従う。

### エラー時の扱い

| エラー内容 | 処理 |
|------------|------|
| 接続種別が想定値に一致しない | 処理を行わず応答を組み立てない |
| 印刷情報要求で対象受注が無い | 空のデータを返す。印刷情報の記録も行わない |
| 印刷結果応答で印刷結果の解析に失敗 | 内容とエラーを記録し、更新を行わずに戻る |
| 印刷結果応答で直接印刷結果が偽・印刷結果要素なし | 内容を記録し、更新を行わずに戻る |
| 印刷結果応答で受注が見つからない | 該当受注IDのエラーを記録し、その要素を飛ばして次へ進む |
| 印刷情報生成・データ取得・記録の書き出し中の例外 | 共通例外処理に委ねる（HTTP 500相当） |

## 入出力

### 入出力: リクエスト

| パラメータ | 位置 | 型 | 必須／任意 | 説明 |
|------------|------|----|-----------|------|
| ConnectionType | クエリまたはボディ | string | 必須 | 動作の分岐。`GetRequest`で印刷情報送信、`SetResponse`でステータス更新。いずれにも一致しない場合は処理を行わず本文を返さない |
| `ResponseFile` | ボディ | string | `SetResponse`時に必須 | プリンタが返した印刷結果のXML文字列。直接印刷結果の真偽と印刷結果要素（印刷ジョブID）を含む。更新対象の特定に用いる |

### 入出力: レスポンス（成功）

応答はJSONではない。分岐ごとに応答形式が異なる。

| 分岐 | HTTPステータス | Content-Type | 本体 |
|------|----------------|--------------|------|
| `GetRequest`（A05-01） | 200 | `application/octet-stream` | スタック用紙の印刷情報XMLをストリーム送信する。対象受注が無い場合は空のデータ |
| `SetResponse`（A05-02） | 200 | `text/xml; charset=utf-8` | 空の本文（本文長0） |

印刷情報要求が返すXMLの構造は次のとおり。

| 要素 | 説明 |
|------|------|
| `PrintRequestInfo` | ルート要素。バージョン属性を持ち、配下に受注ごとの印刷情報要素を並べる |
| `ePOSPrint` | 受注1件分の印刷情報。印刷先・タイムアウト・印刷ジョブID（受注ID）と印字レイアウトを持つ |
| `ePOSPrint/Parameter/printjobid` | 印刷ジョブID。受注IDを用いる。印刷結果応答での受注特定に対応する |
| `ePOSPrint/PrintData` | 印字レイアウト。店頭注文番号・注文詳細URLのQRコード・注文日・注文番号・お客様名・合計金額・スマレジコードのバーコード・各種チェック欄を含む |

応答本体の代表例（実装確認値に基づくXML構造。受注IDなどは代表値）。

```xml
<?xml version="1.0" encoding="utf-8"?>
<PrintRequestInfo Version="3.00">
  <ePOSPrint>
    <Parameter>
      <devid>local_printer</devid>
      <timeout>10000</timeout>
      <printjobid>1000001</printjobid>
    </Parameter>
    <PrintData>
      <epos-print xmlns="http://www.epson-pos.com/schemas/2011/03/epos-print">
        <text lang="ja"/>
        <page>
          <text>店頭注文番号</text>
          <symbol type="qrcode_model_2">https://example.test/admin/order/1000001/edit</symbol>
          <text>注文番号</text>
          <text>20260603-0001</text>
          <text>お客様名</text>
          <text>テスト 太郎</text>
          <text>合計金額</text>
          <text>\1,500</text>
          <barcode type="jan13">4900000000000</barcode>
        </page>
        <cut type="feed"/>
      </epos-print>
    </PrintData>
  </ePOSPrint>
</PrintRequestInfo>
```

### 入出力: レスポンス（失敗）

認証・入力検証による明示的なエラー応答は組み立てない。

| HTTPステータス | 条件 | 本文の形 |
|----------------|------|----------|
| 200 | 印刷情報要求で対象受注が無い | 空のデータ（XML本体を持たない） |
| 200 | 印刷結果応答で解析失敗、直接印刷結果が偽、印刷結果要素が無い、または受注が見つからない | 空の本文。更新は行わず、内容とエラーを記録する |
| （応答なし） | 接続種別が想定値のいずれにも一致しない | 応答を組み立てず本文を返さない |
| 500 | 印刷情報生成中・データ取得中・記録の書き出し中の例外 | 共通例外処理に委ねる |

### 入出力: 永続化

| 操作 | 契機 |
| --- | --- |
| 更新 | 印刷結果応答で、ブラウザ印刷フラグが立つ受注はそのフラグを倒す |
| 更新 | 印刷結果応答で、ブラウザ印刷フラグが立たない受注はステータスをピック中にし、補助情報の確定日時に現在時刻を設定する |
