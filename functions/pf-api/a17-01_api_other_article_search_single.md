# API その他 — 検索クエリに一致する記事情報1件を取得

## 概要

検索クエリ（パラメータ）に一致する記事情報を1件取得するAPIである。pf-apiが提供するJSON APIである。

本書は実装手順ではなく、誰が・いつ・どの条件で・結果どうなるかを読むためのリバース詳細設計とする。確認値はpf-apiの記事検索取得処理、ルート定義、記事を扱うリポジトリを正とする。

対象はJSON APIエンドポイントであり、ブラウザ向けの画面を持たない。記事本体は別途WordPress側で管理し、本APIは連携用の記事情報を返す。

本機能のカスタマイズ区分は現行踏襲であり、挙動は現行実装（pf-api）を参照し、DB関連はec-cube-enterpriseを正とする。

---

## 本書で扱うこと

- 検索クエリ（パラメータ）に一致する記事1件の取得
- 該当が無い場合の応答

---

## 本書で扱わないこと

以下は本書では仕様確定せず、実装または別機能の設計を正とする。

- 記事IDに関連する記事の取得（関連記事取得を正とする）
- 記事本体（WordPress）の管理
- 記事登録（記事登録処理を正とする）

---

## リニューアル移行時の扱い

記事連携テーブルは現行（pf-api）と移行先（ec-cube-enterprise）でスキーマが同一の構成である。DB関連の記述は移行先を正とし、確認できた対応を以下に記録する。応答のうち関連カード・アーキタイプ・デッキ・イベント詳細は記事との中間テーブル（`dtb_article_card`・`dtb_article_archetype`・`dtb_article_deck`・`dtb_article_event_detail`）を介して取得する。記事は `dtb_article.deleted_at` による論理削除であり、削除済みは応答対象外とする。

| 応答フィールド | 移行先の列（`dtb_article`） |
|----------------|------------------------------|
| `articleId` | `id` |
| `wpPostId` | `wp_post_id` |
| `wpTypeId` | `wp_type_id` |
| `url` | `url` |
| `updateDate` | `update_date` |
| `createDate` | `create_date` |

## 利用者視点の入口

| 入口 | URLエンドポイント | 期待されるふるまい |
|------|--------------------|--------------------|
| 検索クエリに一致する記事1件取得 | `GET /article`（クエリパラメータで条件指定） | 条件に一致する記事を1件JSONで返す。該当が無い場合は404を返す。 |

応答形式はJSON。条件はクエリパラメータで渡す。

---

## 処理フロー

### 記事を検索取得する（GET `/article`）

1. クエリパラメータの検索条件を受け取る。
2. 記事のリポジトリから、条件に一致する記事を1件取得する。
3. 取得できない場合はコード404のJSONを返す。
4. 取得できた場合は記事情報をJSONで返す。

## 集計条件

| 指標 | 集計の要点 |
|------|------------|
| 取得対象 | クエリパラメータの条件に一致する記事。 |
| 件数 | 1件を返す（一致がある場合）。 |

---

## 入出力

### リクエスト

| パラメータ | 位置 | 型 | 必須／任意 | 説明 |
|------------|------|----|-----------|------|
| `wpPostId` | クエリ | integer | 必須 | WP投稿ID。これに一致する記事を1件取得する。 |

### レスポンス（成功）

HTTP 200。

条件に一致する記事情報を1件返す。シリアライズ対象は公開指定のプロパティのみで、以下を含む。

| フィールド | 型 | 説明 |
|------------|----|------|
| `articleId` | integer | 記事ID。 |
| `wpPostId` | integer | WP投稿ID。 |
| `wpTypeId` | integer | WP種別ID。 |
| `url` | string | URL。 |
| `updateDate` | string | 更新日時。 |
| `createDate` | string | 作成日時。 |
| `cards` | array | 関連カードの一覧。 |
| `archetypes` | array | 関連アーキタイプの一覧。 |
| `decks` | array | 関連デッキの一覧。 |
| `eventDetails` | array | 関連イベント詳細の一覧。 |

削除日時（`deletedAt`）は公開対象外であり、応答に含まれない。

### レスポンス（失敗）

| HTTPステータス | 条件 | 本文の形 |
|----------------|------|----------|
| 404 | 該当記事なし | `{code, message}`（"Not Found"） |

### サンプルレスポンス

成功時の応答例（実装確認値に基づく代表値）。

```json
{
  "articleId": 1001,
  "wpPostId": 2001,
  "wpTypeId": 1,
  "url": "https://example.com/article/2001",
  "updateDate": "2026-06-01T12:00:00+09:00",
  "createDate": "2020-01-01T00:00:00+09:00",
  "cards": [],
  "archetypes": [],
  "decks": [],
  "eventDetails": []
}
```

### 副作用

無し（参照のみ）。

応答はJSON応答整形を経て返す。プロパティはcamelCase、日時はISO8601とする。

## 業務ルール・計算

- 検索・一覧・取得条件はリクエストパラメータ、ログイン状態、公開状態、店舗・支店条件、既存リポジトリの絞り込み順序を正とする。
- 件数、ページ番号、表示順は既存実装のデフォルトと上限に従い、取得後に業務値を再計算しない。
- 金額、ポイント、数量、ステータス、日時はDBまたは連携元の永続化済み値を返却し、レスポンス生成時の丸め・補正は行わない。
- 条件に一致しない、権限がない、または非公開のデータは空結果または既存のエラー形式で返す。

## DBカラム

テーブル名・列名はec-cube-enterpriseを正とする。

| テーブル | 列 | メモ |
|---------|-----|------|
| 記事（`dtb_article`） | `id`・`wp_post_id`・`wp_type_id`・`url`・`update_date`・`create_date`・`deleted_at` | 取得条件・応答内容に使用する。`wp_post_id` を検索条件に用いる。`deleted_at` は論理削除で、応答対象外。 |
| 記事関連（`dtb_article_card`・`dtb_article_archetype`・`dtb_article_deck`・`dtb_article_event_detail`） | 記事ID・関連先ID | 応答の関連カード・アーキタイプ・デッキ・イベント詳細に用いる中間テーブル。 |

### DB操作

本機能は参照系（検索）であり、DBへの登録・更新・削除は行わない。テーブル名は ec-cube-enterprise を正典とする。

| 操作種別 | 対象テーブル | 契機・条件 |
|---------|--------------|------------|
| 検索 | dtb_article / dtb_article_archetype / dtb_article_card / dtb_article_deck / dtb_article_event_detail | 検索条件に合致するレコードを抽出する。 |
