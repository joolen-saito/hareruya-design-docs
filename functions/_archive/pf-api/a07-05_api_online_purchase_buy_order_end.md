## 用語

| 用語 | 説明 |
|------|------|
| ネット買取受注 | ネット経由で受け付けた買取の受注。受注IDで一意に特定する。 |

## 副作用（設計書からは削除・2026-08-19）

### 副作用
ネット買取受注を更新する（DB更新）。具体的には次を行う。
- 受注の買取受注ステータス・合計額・更新担当者・更新日時を更新する。
- 送られた明細から買取代表カード・個別入力商品を登録・更新する。今回保持しない既存の買取代表カード・個別入力商品と、それに紐づく申込時買取価格を削除する。まとめ買取商品は申込時買取価格のみ削除する。
- 更新前後でステータスが変わった場合は、ステータス履歴を1件登録する（履歴に受注ID・ステータスID・更新担当者・登録日時を記録する）。
参照のみではない。応答はJSON応答整形を経て返す。プロパティはcamelCase、日時はISO8601、`serialize_null`は有効とする。

### 権限・認可
| 利用者状態 | ネット買取注文の査定終了処理 |
|------------|------------------------------|
| 認証済みの管理者会員 | 受注の明細・合計額・ステータスを更新できる。更新担当者・履歴に記録される。 |
| 未認証・トークン不正 | 認証拒否（HTTP 401）となり、更新できない。 |
---
### 排他制御・トランザクション
本APIは受注の明細・合計額・ステータスの更新とステータス履歴の登録を1つのトランザクションで行う。明細の取得・登録・削除、受注の更新、履歴の登録までを1トランザクションとし、処理中に例外が発生した場合はロールバックして内部エラー（HTTP 500）を返す。楽観ロック・悲観ロックの対象は持たず、同一受注への同時更新は後勝ちとなる。
