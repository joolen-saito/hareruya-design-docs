## 副作用（設計書からは削除・2026-08-19）

### 副作用
更新前後でステータスが異なる場合に、ネット買取受注のステータス・更新担当者・更新日時を更新し（DB更新）、ステータス変更履歴を1件登録する。履歴には受注ID・更新後ステータスID・更新担当者ID・登録日時を記録する。参照のみではない。更新はトランザクション内で確定し、例外時はロールバックする。更新前後が同じステータスのときは更新も履歴登録も行わない。
応答はJSON応答整形を経て返す。プロパティはcamelCase、日時はISO8601、`serialize_null`は有効とする。

### ログ・監査
ステータス変更の履歴は買取ステータス履歴として永続化する（受注ID・更新後ステータスID・更新担当者ID・登録日時）。アプリケーションログとは別のDB上の業務履歴である。
#### ログに出してはいけないもの
- JWTトークンの原値
- 署名シークレット（`auth_magic`）
- Cookie値・セッションIDの完全値

### 権限・認可
| 利用者状態 | ネット買取受注ステータス更新 |
|------------|------------------------------|
| 認証済みの管理者会員 | ステータス遷移の制約を満たす範囲でステータス・更新担当者・更新日時を更新できる。 |
| 査定中・査定再開の受注の査定担当者本人 | 同受注を査定中・査定再開へ更新できる。 |
| 査定中・査定再開の受注の担当者以外 | 同受注を査定中・査定再開へ更新できない（HTTP 400）。 |
| 未認証・トークン不正 | 認証拒否（HTTP 401）となり、更新できない。 |
---
### 排他制御・トランザクション
本APIはステータス更新と履歴登録を1つのトランザクション内で行い、例外時はロールバックする。楽観ロック・悲観ロックの対象は持たず、同一受注への同時更新は後勝ちとなる。査定中・査定再開の占有は担当者比較による業務判定であり、DBレベルのロックではない。
