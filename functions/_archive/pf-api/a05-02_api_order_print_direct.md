## 用語

| 用語 | 説明 |
|------|------|
| スタック用紙 | 店頭で受注内容を印字するロール紙。1受注ごとに1枚分の印刷情報を生成する。 |
| 印刷情報 | プリンタが解釈するXML。`ePOSPrint`要素ごとに1受注分の印字レイアウトを持つ。 |
| 店頭注文番号 | 店頭受取の受注に紐づく待ち番号。印刷情報の店頭注文番号欄に印字する。 |
| ブラウザ印刷フラグ | 受注の補助情報が持つフラグ。ブラウザ経由の印刷待ち受注を印刷対象に含める判定に用いる。 |
| 印刷ログファイル | 印刷不具合検証のために生成した印刷情報のXMLを保存するファイル。 |

## 副作用（設計書からは削除・2026-08-19）

### 副作用
本エンドポイントは参照のみではなく、次の副作用を持つ。
- 印刷ログファイルの書き出し（`GetRequest`）。生成した印刷情報が空でない場合、印刷情報のXMLをログ保存ディレクトリ（`var/log/print_logs/`配下）にタイムスタンプと一意名を付けたファイルとして書き出す。ディレクトリが存在しない場合は作成する。
- 受注ステータスの更新（`SetResponse`）。印刷結果に含まれる受注について、ブラウザ印刷フラグが立つ場合はフラグを倒し、立たない場合は受注のステータスをピック中へ更新し、補助情報の確定日時に現在時刻を設定する。これらはデータベースへの更新である。
応答はXMLまたは空応答であり、JSON応答整形・camelCaseのプロパティ命名は適用しない。

### データ整合性
| 観点 | 内容 |
|------|------|
| 参照時点 | `GetRequest`は呼び出し時点の印刷対象受注（最大10件）を取得して印刷情報を返す。 |
| 更新の有無 | `GetRequest`は受注ステータスを更新しない（印刷ログファイルの書き出しのみ）。`SetResponse`は受注ステータスと補助情報を更新する。 |
| 取得と更新の一致 | `GetRequest`で抽出した受注集合と`SetResponse`で更新される受注集合は同一トランザクションで保証されない。`SetResponse`はプリンタが返した`ResponseFile`の印刷ジョブID（受注ID）を基準に対象を特定する。 |
| 印刷とステータスの関係 | `GetRequest`は印刷情報を返した時点では受注を未印刷のまま残し、`SetResponse`を受け取って初めてピック中へ更新する。両者の呼び出しの間に受注が変化し得る。 |

## 0203に無い定型節（設計書からは削除・2026-08-19）

### ログ・監査
`SetResponse`では、`ResponseFile`の解析失敗・直接印刷結果が偽・印刷結果要素なし・受注が見つからない場合に、その内容やエラーをログへ記録する。`GetRequest`では、生成した印刷情報のXMLを印刷不具合検証用のログファイル（`var/log/print_logs/`配下）へ書き出す。
#### ログに出してはいけないもの
- JWTトークンの原値
- 署名シークレット（`auth_magic`）
- Cookie値・セッションIDの完全値
