#### エッジケース
| ケース | 扱い |
|--------|------|
| 存在しない `id` で編集 GET | ルート引数のマスタ読み込みに失敗し 404 となる。 |
| DELETE の CSRF 不正 | アクセス拒否（HTTP 403）。 |
| 名称の重複で DB が一意を返す | フォーム側の単純検証より後に検知され、`admin.error.non_unique` と再描画。 |
| 商品にだけ紐付き、まだ注文明細に載っていない | 削除処理は実行されず `admin.tag.delete.failed` と一覧へリダイレクトする。マスタ行は残る。 |
| 注文明細側の関連のみが残っている | 注文明細との結合があると判定されれば `admin.order_tag.delete.failed` と一覧へリダイレクトする。 |

### データ整合性
| 観点 | 内容 |
|------|------|
| 一覧とフォーム | 一覧は全件クエリからのページネーション結果。フォームはルート `id` の 1 行または新規用の未保存インスタンス。同一画面でもデータ起源が別になる。 |
| 商品側の関連 | `dtb_product_tag_sales_analysis` が 1 件でもあれば当該タグを削除しない。一覧の内容と DB は GET 読み込み時点での整合。 |
| 注文明細側の関連 | `dtb_order_item_tag_sales_analysis` が 1 件でも連結されていれば削除しない。 |
| 同時更新 | 楽観ロックは持たない。後続の UPDATE が単純に上書きされる。 |

### ログ・監査
| タイミング | 記録内容 |
|------------|----------|
| 本画面のみに閉じた専用ログ | コントローラに明示は無く、フラッシュと HTTP 状態が利用者への主なフィードバックになる。売上分析タグ更新 CSV は別コントローラでログ開始・完了を書く実装がある。 |

- なりすまし対策トークン

本機能ではログイン試行回数などの試行制限を独自に増やさない。

### セッション
#### 本機能におけるセッション
| 観点 | 内容 |
|------|------|
| GET 表示時 | `admin.product.tag_sales_analysis.page_no` と `admin.product.tag_sales_analysis.page_count` を更新する。 |
| POST 側 | 一覧再構築に同キーを読むのみで、入力値本体はフォームオブジェクト側に載る。 |
#### セッションへ保存しない情報
恒久化する入力文字列だけを別キーへ退避する処理はしない。送信失敗時は POST 済みデータがフォームに残る。
---
### Cookie
本機能単体での特別仕様 Cookie は無い。管理画面共通のセッション Cookie が前提になる。
---
### 排他制御・トランザクション
当画面では明示トランザクションや楽観バージョン列は利用しない。`flush` がコミット単位となる。並行編集では後続保存が単純上書きしうる。
