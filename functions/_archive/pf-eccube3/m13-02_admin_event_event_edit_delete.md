## 用語

| 用語 | 説明 |
|------|------|
| イベント | イベント管理で登録される大会・大会企画の1レコード。テーブルは`dtb_event`。 |
| イベント詳細（日程） | 1つのイベントにぶら下がる開催日程の1レコード。テーブルは`dtb_event_detail`。 |
| 申込 | 1つの日程に対する申込の1レコード。テーブルは`dtb_event_entry`。 |
| デッキ登録 | 1つの日程に登録されたデッキ。日程削除可否の判定に用いる。 |
| 公開状態 | イベントの公開・非公開を表す状態（公開状態マスタ`Disp`）。 |
| 申込状況 | 申込が確定（参加）状態かどうか。申込人数表示は参加状態の件数を数える。 |

#### エッジケース
| ケース | 扱い |
|--------|------|
| 更新対象のイベントがすでに削除済み | 更新時は403。 |
| 申込済み日程があり支払方法を変更しようとした | 変更不可エラーを表示し直前画面へ戻す。永続化しない。 |

| デッキ登録済み日程を一括削除に含める | デッキ登録エラーを表示し直前画面へ戻す。当該リクエストでの削除を行わない。 |
| 申込済み日程を一括削除に含める | 申込エラーを表示し直前画面へ戻す。 |
| 日程一括削除で削除対象IDが空 | 404。 |
| バナーURLに`admin.hareruyamtg.com`を含む | 検証エラーとして扱い再描画する。 |

### データ整合性
| 観点 | 内容 |
|------|------|
| 参照時点 | 編集画面の表示値・申込人数は、画面表示時に読み取った値である。表示後の更新は自動反映しない。 |
| 更新後の整合性 | 更新成功後は編集画面へリダイレクトし、最新のイベントと日程を読み直して表示する。 |
| 削除の整合性 | イベント削除は日程が無いことを前提とする。日程一括削除はデッキ登録・申込が無い日程に限る。これにより参照されている子レコードを伴う削除を避ける。 |
| 一覧との整合性 | 削除後の検索結果ページの件数・行は一覧機能（M13-01）の検索条件に従う。 |
