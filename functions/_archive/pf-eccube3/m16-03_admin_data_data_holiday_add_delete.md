### データ整合性
| 観点 | 内容 |
|------|------|
| 一覧とマスタ | 一覧は常に `mtb_holiday` の現在状態を日付昇順で読む。追加・削除の直後はリダイレクト GET で再読込される。 |
| 祝日マスタとイベント詳細フラグ | 追加時は同日開始のイベント詳細へ祝日フラグオンを書き込む。削除時はオフにする。イベント開始日時が別日へ変更済みであれば、その変更結果とフラグの整合は別機能の保存処理に依存する。 |
| トランザクション | 祝日の flush とイベント詳細の複数 flush が別単位である。途中失敗時の原子性はフレームワーク既定と DB 設定に依存し、本書では個別トランザクション境界までを確認値とする。 |

## 0203に無い定型節（設計書からは削除・2026-08-19）

#### 入力項目（手入力による追加のみ）
追加フォームは初期表示では DOM 上非表示でも、一覧 GET 時にトークン付きで生成される。
| 項目名 | 必須／任意 | 最大長 | 初期値 | 保存先・扱い |
|--------|------------|--------|--------|----------------|
| 祝日名 | 必須 | 64 文字（ウィジェット `maxlength` および Symfony Length max と一致） | 空（プレースホルダ「名称」） | `mtb_holiday.name`。NotBlank、最大 64。 |
| 日付 | 必須 | 単一行日付入力、`yyyy-MM-dd` | 空の単一行フィールド | `mtb_holiday.date`。Symfony の date 型、`datetime` 入力、`single_text`。フォームに Symfony の Length は無いが DB は date 型列である。 |
補足: 日付が同一の行が既に存在する場合、追加は拒否されプラグインの重複メッセージが表示される。
