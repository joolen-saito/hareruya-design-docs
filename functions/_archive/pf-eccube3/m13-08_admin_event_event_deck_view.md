## 用語

| 用語 | 説明 |
|------|------|
| デッキ | 申込プレイヤーが登録したカード構成。テーブルは`dtb_deck`。メイン・サイドのカード一覧を符号化した文字列を持つ。 |
| メインデッキ | デッキのメイン部分のカード一覧。 |
| サイドボード | デッキのサイド部分のカード一覧。 |
| カードリスト | デッキの符号化文字列をカード名・枚数の配列に復号したもの。復号はカード関連のユーティリティで行う。 |
| 申込検索条件セッション | イベント申込一覧（M13-06）が保持する検索条件。デッキ表示の抽出条件として読む。セッションキーは`admin.event_entry.search`。 |
| プレイヤー名 | デッキに登録されたプレイヤー名。未設定時は会員の氏名カナ（カナ姓・カナ名）を用いる。 |

## 0203に無い定型節（設計書からは削除・2026-08-19）

#### エッジケース
| ケース | 扱い |
|--------|------|
| 申込検索条件セッションが無い | 検索条件を空として扱い、登録デッキ取得の結果に従う。 |
| デッキが0件 | デッキリストに何も表示しない（印刷ボタンのみ）。 |
| デッキのプレイヤー名が空 | 会員のカナ姓・カナ名を半角空白で連結して表示する。 |
| メインが40枚を超える | 40枚ごとにページを分け、ページ番号と総ページ数を表示する。 |
| サイドボードが無い | サイド一覧を空として表示する。 |
---
### データ整合性
| 観点 | 内容 |
|------|------|
| 参照時点 | デッキ表示の内容は画面表示時にデータベースから読み取った値である。表示後のデッキ・申込の更新は自動反映しない。 |
| 申込一覧との整合性 | デッキ表示の対象は申込一覧の検索条件セッションに基づく。申込一覧で検索した後に条件を変えずに開けば、同一条件の対象を扱う。検索条件をセッションから読むため、別タブでの検索条件変更があれば表示対象が変わり得る。 |
| 読み取り専用 | 本画面はデッキ・申込・台帳を更新しない。 |

### セッション
#### 本機能におけるセッション
| 観点 | 内容 |
|------|------|
