## 用語

| 用語 | 説明 |
|------|------|
| イベント | イベント管理で登録される大会・大会企画の1レコード。テーブルは`dtb_event`。 |
| イベント詳細 | 1つのイベントにぶら下がる開催日程の1レコード。テーブルは`dtb_event_detail`。開催日Fromや開催日Toの絞り込みはこの開始日時を参照する。 |
| 検索条件セッション | 表示件数、検索条件、ページ番号、ソートキー、並び順を保持するセッション領域。セッションキー接頭辞は`admin.event`。 |
| ルール適用度 | イベントに紐づくルール適用度マスタ（`MtbRel`）。検索条件の1つ。 |
| フォーマット | イベントに紐づくフォーマットマスタ（`MtbFormat`）。1イベントに複数紐づき得る。検索条件の1つ。 |

## 0203に無い定型節（設計書からは削除・2026-08-19）

#### エッジケース
| ケース | 扱い |
|--------|------|
| イベント名が空白・カンマのみ | 分割後の各語が空になり、イベント名条件を追加しない。 |
| 開催日FromとToが逆転 | 両条件をANDで適用するため、該当が無ければ0件になる。範囲整合のバリデーションは行わない。 |
| 開催日条件があり詳細が無いイベント | 詳細を左外部結合するが開催日条件は詳細列を参照するため、詳細が無いイベントは開催日条件に一致せず除外される。 |
| 並び順に不正値 | 並び順エラーを表示し初期表示へ戻す。 |
| 最終ページのデータが削除され表示対象が無くなった | ページ番号を1つ前に補正して表示する。 |
| 該当0件 | 「検索条件に該当するデータがありませんでした。」を表示する。 |
---
### データ整合性
| 観点 | 内容 |
|------|------|
| 参照時点 | 一覧の件数と行は、検索実行時にデータベースから読み取った値である。表示後にイベントが更新・削除されても表示中の一覧は自動更新しない。 |
| 検索条件の保持 | 検索条件・表示件数・ソートキー・並び順・ページ番号はセッションに保存し、ページ送り・再表示で復元する。一覧初期表示（`/event/list`）ではこれらを削除する。 |
| 一覧と編集の整合性 | 一覧の行から編集・削除へ遷移した後の値の正は、遷移先（M13-02）の処理時点のデータとする。 |
| 件数と行の整合性 | 件数は`count(e)`で求め、表示行はページネーターが取得する。詳細・フォーマットの左外部結合により内部のSQL行は重複し得るが、表示はイベント単位で行う。 |

### セッション
#### 本機能におけるセッション
| 観点 | 内容 |
|------|------|
| 一覧初期表示（`/event/list`） | `admin.event.search`、`admin.event.search.page_no`、`admin.event.search.page_count`を削除する。 |
| 検索・ページ送り時 | 検索条件（`admin.event.search`）、ページ番号（`admin.event.search.page_no`）、ソートキー（`admin.event.sort`）、並び順（`admin.event.order`）、表示件数（`admin.event.search.page_count`）を保存する。 |
#### セッションへ保存しない情報
イベント本体の永続データはセッションへ保存しない。保存するのは検索条件・表示状態のみとする。
