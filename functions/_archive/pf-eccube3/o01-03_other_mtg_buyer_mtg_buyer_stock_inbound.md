## 用語

| 用語 | 説明 |
|------|------|
| 入庫 | 買取で取得した商品を在庫（ProductStock）へ登録すること。買取受注が入庫済みへ遷移する際に行う。 |
| 買取在庫 | 入庫の作業単位として買取受注に紐づく在庫行。`dtb_buy_order_stock`。 |
| 在庫履歴 | 入庫に伴う数量変化の履歴。`dtb_buy_order_stock_history`。 |
| 入庫待ち | 入庫前の状態。`mtb_buy_order_status` の入庫待ち（移行先で値 16）。 |
| 入庫済み | 入庫完了の状態。入庫済み（移行先で値 14）。 |
| 商品在庫 | 商品規格ごとの在庫（ProductStock）。入庫により増加する。 |

---

## 参考

MTGバイヤーは本リポジトリ外の外部アプリ。入庫専用の外部API（pf-api）は存在せず、入庫は ec-cube-enterprise の入庫サービス（買取在庫→商品在庫の反映・在庫履歴作成）として、ステータス遷移（入庫待ち→入庫済み）または一括入庫バッチで実行される。DBスキーマ・ステータス定義は ec-cube-enterprise（`DtbBuyOrderStock`／`DtbBuyOrderStockHistory`／`Master\MtbBuyOrderStatus`）を正とする。査定は O01-01／O01-02 を正とする。

### データ整合性
| 観点 | 内容 |
|------|------|
| 買取在庫と商品在庫 | 入庫により買取在庫の数量が商品在庫へ反映される。入庫履歴の更新前後数量で変化を追跡できる。 |
| ステータスと入庫 | 入庫処理はステータス遷移に連動する。入庫済みの受注は入庫処理が実行済みであることを表す。 |
| 二重入庫 | 同一受注の再入庫を避けるため、ステータスにより実行済みを判定する。詳細な冪等性保証は ec-cube-enterprise の入庫サービス実装を正とする。 |
