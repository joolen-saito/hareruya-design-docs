## 用語

| 用語 | 説明 |
|------|------|
| ネット買取受注 | オンライン申込の買取受注。`dtb_buy_order` に保存される。店頭買取受注（`dtb_otc_buy_order`）とは別物。 |
| メインカード | ネット買取査定の商品明細。`dtb_buy_main_card` に保存される。商品規格・言語・カード状態・Foil可否・買取区分などを持つ。 |
| 個別入力商品 | 商品規格に紐づかない手入力の買取商品。`dtb_buy_order_indivisual_input_product` に保存される。 |
| ステータス | ネット買取受注の対応状況。`mtb_buy_order_status`。値の定義は ec-cube-enterprise を正とする。 |
| 査定担当者 | 査定を確定した管理者（メンバー）。 |

---

## 参考

MTGバイヤーは本リポジトリ外の外部アプリ。EC-CUBE側の確認値は pf-api のネット買取系コントローラ（`BuyOrderController` ほか、`config/routes.yaml`）と HareruyaEc プラグインのネット買取業務を正とする。DBスキーマは ec-cube-enterprise の `DtbBuyOrder`／`DtbBuyMainCard`／`DtbBuyOrderIndivisualInputProduct`／`Master\MtbBuyOrderStatus` を正とする。店頭買取は O01-01、入庫は O01-03 を正とする。

### データ整合性
| 観点 | 内容 |
|------|------|
| 受注と明細 | 査定確定（PUT buyOrder）は明細・個別入力商品を全置換するため、同じ受注に再送すると送信内容で上書きされる。 |
| 合計金額 | 受注の買取合計金額は明細から再計算した値で保存する。明細と合計が一致する。 |
| ステータス履歴 | ステータス更新時に履歴を1件追加する。受注の現在ステータスと履歴の最新が一致する。 |
| 店頭買取との分離 | ネット買取（`dtb_buy_order*`）と店頭買取（`dtb_otc_buy_order*`）は別テーブル系統で、相互に上書きしない。 |

### 排他制御・トランザクション
査定確定・ステータス更新は対象受注の明細・履歴更新をまとめて行う。同時更新の競合保証は本書では切らない。明細の全置換により、同一受注への再送は後勝ちとなる。
