## 用語

| 用語 | 説明 |
|------|------|
| 申込 | 1つの日程に対する申込の1レコード。テーブルは`dtb_event_entry`。 |
| 申込プレイヤー | 申込に紐づくプレイヤーの1レコード。イベント申込検索の集計単位。テーブルは`dtb_entry_player`。 |
| デッキ | 申込に対して登録されたデッキ。デッキ登録検索の集計単位。テーブルは`dtb_deck`。 |
| 検索モード | 検索フォームの選択肢。`entriedEvent`（イベント申込検索）または`registedDeck`（デッキ登録検索）。 |
| 検索条件セッション | 表示件数、検索条件、ページ番号、ソートキー、並び順を保持するセッション領域。セッションキー接頭辞は`admin.event_entry`。 |
| イベント詳細ID | 特定の日程を指す識別子。イベント詳細指定表示で1日程に絞った申込一覧を表示する。 |

## 0203に無い定型節（設計書からは削除・2026-08-19）

#### エッジケース
| ケース | 扱い |
|--------|------|
| 検索モードと整合しないソートキー | 当該モードの既定ソートキーへ補正する。 |
| 並び順に不正値 | 並び順エラーを表示し初期表示へ戻す。 |
| 検索条件もセッションも無い | 初期表示へ戻す。 |
| 最終ページのデータが削除され表示対象が無くなった | ページ番号を1つ前に補正して表示する。 |
| イベント詳細指定表示 | 検索モードを`entriedEvent`に固定して特定日程に絞り込む。 |
| 該当0件 | 0件として一覧を描画する。 |
---
### データ整合性
| 観点 | 内容 |
|------|------|
| 参照時点 | 一覧の件数と行は検索実行時にデータベースから読み取った値である。表示後の申込・デッキの更新は自動反映しない。 |
| 検索条件の保持 | 検索条件・表示件数・ソートキー・並び順・ページ番号はセッション（接頭辞`admin.event_entry`）に保存し、ページ送り・再表示・デッキ表示・CSV出力で参照する。 |
| デッキ表示・CSVとの整合性 | デッキ表示（M13-08）とCSV出力は、申込一覧の検索条件セッションを読んで対象を決める。検索後に条件を変えずに開けば同一条件の対象を扱う。 |
| 件数と行の整合性 | 件数は検索モードに応じた件数取得で求め、表示行はページネーターが取得する。 |

## 0203に無い定型節（設計書からは削除・2026-08-19）

### ログ・監査
| タイミング | 記録内容 |
|------------|----------|
| 一覧表示・検索 | 本機能単体では業務監査ログを追加で書く処理は持たない。CSV出力時のログはCSV機能の範囲とする。 |
#### ログに出してはいけないもの
- セッション識別子の完全値
- なりすまし対策トークンやCookieの原値
- プレイヤーの個人情報の本文
---
### 権限・認可
| 利用者状態 | 申込一覧の表示・検索 |
|------------|----------------------|
| 未ログイン | 管理画面共通のログイン誘導に従う。 |
| 管理メンバーでログイン済み | 管理画面のアクセス制御がイベント管理のURLを許可するときに到達する。 |
---
### セッション
#### 本機能におけるセッション
| 観点 | 内容 |
|------|------|
| 一覧初期表示（`/entry/list`） | `admin.event_entry.search`、`admin.event_entry.search.page_no`、`admin.event_entry.search.page_count`を削除する。 |
| 検索・ページ送り・詳細指定時 | 検索条件（`admin.event_entry.search`）、ページ番号（`admin.event_entry.search.page_no`）、ソートキー（`admin.event_entry.sort`）、並び順（`admin.event_entry.order`）、表示件数（`admin.event_entry.search.page_count`）を保存する。 |
#### セッションへ保存しない情報
申込・デッキの永続データはセッションへ保存しない。保存するのは検索条件・表示状態のみとする。
