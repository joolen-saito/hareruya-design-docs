## 並び順と永続化の対応

1. 各スロットごとにフォーム「並び順」の整数値を読む。
2. 並び順の値をキーとして、当該スロットの画像 URL・リンク・表示タイプ・言語・alt のフォームフィールド名を値とするマップを組み立てる。
3. キーで昇順ソートする。
4. ソート後のエントリに 1 から通し番号を振り直す。
5. その後、主キー id が k である `mtb_top_banner` 行に、通し番号 k に対応したフォーム値を書き込む。

この対応は「主キーが 1 からの連番で欠番がない」前提で整合する。並び順の重複はクライアント脚本で送信を阻むが、サーバー側では重複検証をしない。

#### エッジケース
| ケース | 扱い |
|--------|------|
| 並び順が空または重複 | クライアント脚本が submit を中止する。サーバーは重複を検知しない。 |
| 主キー id に欠番があるデータセット | 並べ替え結果と id の対応ロジックが崩れるリスクがある（初期マイグレーションは連番前提）。 |
| アップロード検証失敗かつ店舗絞り込み表示 | エラー再描画では画像一覧をルート直下のみ読む実装箇所があり、一覧が画面モードと不一致になる場合がある。 |
| 画像 URL はあるが言語が未選択 | 言語集合が空でも保存処理は続行しうる。フロントの結合条件により表示されない場合がある。 |
---
### データ整合性
| 観点 | 内容 |
|------|------|
| DB とストレージ | アップロードはストレージのみ更新する。バナー設定で画像 URL を手入力しない限り、新規ファイルとスロットは自動連携しない。 |
| 一覧の並び | 表示はストレージの LastModified 降順。バナー設定の並び順とは独立。 |
| 同時更新 | 複数利用者が同一スロットを更新した場合、後勝ちでフラッシュされる一般的な ORM 挙動に依存する（楽観ロックは持たない）。 |

## 0203に無い定型節（設計書からは削除・2026-08-19）

#### 入力項目
同一画面上で `mtb_top_banner` の行数分、以下の項目セットが繰り返す（マイグレーションでは 15 スロットを初期化）。画面ラベルは各行で共通である。
| 項目名 | 必須／任意 | 最大長 | 初期値 | 保存先・扱い |
|--------|------------|--------|--------|----------------|
| 画像URL | 任意 | 255 文字（フォームの長さ制約あり）。参照禁止ホスト文字列は検証で拒否 | DB の `mtb_top_banner.image_url` | カラム `image_url`。空は許容。 |
| リンク先URL | 任意 | 255 文字（フォームの長さ制約あり） | DB の `mtb_top_banner.link` | カラム `link`。未入力時は空文字を保存。 |
| 言語 | 任意 | チェックボックス複数（選択肢は日本語・英語の ID に対応） | DB が保持する言語関連の現行選択 | 中間テーブル `dtb_top_banner_language` を通じた `mtb_language` との多対多を置換。 |
| 表示タイプ | 任意 | ドロップダウン（値 0 または 1） | DB の `disp_type` | カラム `disp_type`。0 は「非表示」、1 は「表示」のラベルがフォームに付く。 |
| 画像alt属性 | 任意 | フォームは単行テキストで長さ制約なし（DB は text 型） | DB の `mtb_top_banner.image_alt` | カラム `image_alt`。 |
| 並び順 | 任意（送信時は脚本で空禁止） | integer 型入力 | 初期表示では当該行の `id` と同じ値が入る Twig 指定がある | DB 列ではなく、保存時の並べ替えにのみ利用。 |
画像アップロード用フォーム（バナー設定フォームとは別）
| 項目名 | 必須／任意 | 最大長 | 初期値 | 保存先・扱い |
|--------|------------|--------|--------|----------------|
| 店舗 | POST 時は未選択可（全店舗ルート）。初期表示フォームでは単一選択が必須に近い設定が二重指定されている | — | 店舗絞り込み GET では該当店舗 | ストレージパス `banner/` と `banner/{htmlClassName}/` の選択にのみ利用。DB 更新はしない。 |
| 画像のアップロード | アップロード時は実質必須 | 520000 バイト以下、GIF／JPEG／PNG | なし | ストレージへ保存。ファイル名は実装側で一意化される経路があり、アップロード完了でも `mtb_top_banner` は自動では更新されない。 |

### ログ・監査
当コントローラが専用の監査ログを出力する記述は見当たらない。オブジェクトストレージや Web サーバ側の標準ログはインフラ設定を正とする。
#### ログに出してはいけないもの
- パスワード
- なりすまし対策トークン
- Cookie 値
- セッション ID の完全値
- Remember Me トークンの原値
---
### 権限・認可
| 利用者状態 | トップバナー画面・POST・DELETE |
|------------|-------------------------------|
| 管理画面にログインし当ナビへ到達できる運用者 | 画面表示・保存・アップロード・削除の HTTP 処理へ到達できる（細部は管理画面共通の認可設定を正とする）。 |
| 未ログインまたは共通ルールで拒否される利用者 | 管理画面の共通挙動に従い当パスへ到達しない。 |
---
### 排他制御・トランザクション
明示の楽観ロック・悲観ロックはない。Doctrine の単一トランザクションとしてフラッシュされる範囲に依存する。
