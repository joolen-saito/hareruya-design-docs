## 用語

| 用語 | 説明 |
|------|------|
| 権限 | マスタ上の管理者区分。Member が持ち、拒否ルールは権限ごとに紐づく。 |
| 拒否URL | 管理画面のベースからの相対パスとして解釈される文字列。画面上は「管理ベースURL／以降からのURL」と案内される。先頭に `/` を含める例が示される。 |
| 権限ロール | `dtb_authority_role` に対応するエンティティ。1行は「どの権限に対し、どのパス接頭辞を拒否するか」を表す。 |
| AuthorityVoter | ログイン済み Member について、当該権限に登録された拒否パスと現在リクエストのパスが前方一致するかを検査し、一致すればアクセス拒否を返す投票者。 |

---

## インターフェース上の前提・非保証

| 項目 | 内容 |
|------|------|
| パスの正規化 | 利用者が入力する拒否URLの末尾スラッシュの有無により、ナビ判定と投票者判定で期待が一致しない場合がある。実装は値のそのままの連結による。 |
| システム情報画面との関係 | システム情報・PHP情報の閲覧画面は別コントローラであり、本機能のフォームとは独立している。 |

## 0203に無い定型節（設計書からは削除・2026-08-19）

#### バリデーション補足（フォームイベント）
| 条件 | 内容 |
|------|------|
| 権限が空で拒否URLだけある | 権限欄に「権限が選択されていません。」 |
| 権限があり拒否URLが空 | 拒否URLに「拒否URLが入力されていません。」 |
#### エッジケース
| ケース | 扱い |
|--------|------|
| 登録済み行をすべて削除して送信 | 既存行はすべて削除され、有効な権限＋URLの組がなければ権限ロールは0件になる。 |
| 同一権限に複数の拒否URL | 各行が独立したレコードとして保存され、拒否判定はループで順に試される。 |
| 拒否URLに正規表現として解釈困難な文字列 | 投票者はまずスラッシュをエスケープする方式でマッチし、例外時は `preg_quote` による方式へフォールバックする。 |
---
### データ整合性
| 観点 | 内容 |
|------|------|
| 一覧と保存結果 | 保存成功後は再GETで一覧が読み直される。保存中に他セッションが同テーブルを変えた場合の直列化はアプリケーションレベルでは保証しない。 |
| ナビ非表示と実際の拒否 | グローバルは「フルURL文字列」、ナビ側の比較は階層id連結や `path()` 生成URLとの包含判定であり、投票者のパス前方一致とは文字列の作り方が異なる。メニューに出ても直接URLで開ける可能性や、逆に非表示でも境界条件では差が出る余地は実装差として残る。 |
| Creator・日時 | マッピングでは作成者・作成日時・更新日時は非NULL。標準コントローラは保存時にこれらを直接セットしない。既存行の属性はエンティティに残るが、全件削除後の再登録で新規行のみになる場合、環境やプラグインの事前処理に依存し得る。 |

## 0203に無い定型節（設計書からは削除・2026-08-19）

### 入力項目
| 項目名 | 必須／任意 | 最大長 | 初期値 | 扱い |
|--------|------------|--------|--------|------|
| 権限 | 実質必須 | マスタに依存 | 既存行は登録済みの権限 | 権限マスタから選択する。拒否URLとの組でのみ保存する。 |
| 拒否URL | 実質必須 | 4000文字（現行 pf-eccube3 は上限なしのテキスト） | 既存行は登録済みの値 | 権限との組でのみ保存する。 |
権限と拒否URLのどちらか一方だけを入力した行は保存しない。既に登録済みの行で片方が空になった場合は削除する。
