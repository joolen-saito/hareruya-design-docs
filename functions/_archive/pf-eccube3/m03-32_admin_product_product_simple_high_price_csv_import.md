## 0203に無い定型節（設計書からは削除・2026-08-19）

#### エッジケース
| ケース | 扱い |
|--------|------|
| 同一 CSV または DB 状態で複数規格コード行が競合すると判定されるとき | `breakAll` とエラーによりトランザクション全体が中止 |
| CSV の商品コードにはマッチがあるが対象となる高額条件を満たさないとき | メッセージストアへのエラー行だけで先へ進む。トランザクションは `breakAll` が無ければインポータ式によりコミットされうる。コントローラはエラー検知ゆえ完了フラッシュと履歴 INSERT を行わない。 |
| セールフラグが真側と偽側の両セットが同コードに並存しうる | 実装順が「セール側を優先」のため、そのコードは基準のみ更新となる |
| 基準価格列が論理的には空であっても通過しない | Symfony 側必須と列バリデータの Required で止まり `breakAll` |
| メッセージストアでの info と error の両立 | UI フラッシュにおいて両方載りうる。履歴および成功フラッシュは結果エラー無しのみ |
---
### データ整合性
| 観点 | 内容 |
|------|------|
| トランザクション境界 | CSV ひとつの取込はひとつのトランザクション。`breakAll` で打ち切った場合はすべて失われる。打ち切りが無ければユーザー向けエラー文言が複数でもコミットが通るインポータ式になりうる。 |
| Doctrine cache | 定期的な `clear()` により、同一リクエスト内で以前にロード済みであったエンティティと DB 状態の乖離がありうることを利用者側で追うときはクエリログや再読込試験へ委ねる。 |
| UI の成功表示とデータ | `CsvImportResult#hasError` が偽じゃないときは画面上は「登録完了」系の文言を出力しない。また取込履歴も追加しない。 |
