## 用語

| 用語 | 説明 |
|------|------|
| 商品規格 | 商品に紐づく言語・状態などの単位。在庫数は規格単位で持つ。テーブルは `dtb_product_class` と `dtb_product_stock`、拡張情報は `dtb_product_sub_class`。 |
| 増減させる在庫数 | 現在の在庫数へ加算する差分。負数で減算もできる。フォームキー `stock_change`。 |
| 在庫変動理由 | 履歴に残す自由記述のメモ。フォームキー `stock_change_memo`。 |
| 在庫変動理由区分 | 入荷・マスタ更新などの区分マスタ。フォームキー `stock_change_type_id`。 |
| 在庫変更履歴 | 在庫を変えた記録。テーブル `dtb_stock_history`。 |

## 0203に無い定型節（設計書からは削除・2026-08-19）

#### エッジケース
| ケース | 扱い |
|--------|------|
| 商品未選択で開く | 「商品が選択されていません。」を表示し商品検索一覧へ戻す。 |
| 選択した規格が送信時に削除済み | 「…：対象の商品は既に削除されています。」を表示しエラー扱いとする。当該行は更新しない。 |
| 増減数0の行 | 更新せず履歴も残さない。理由欄は空でもよい。 |
| 新在庫数が負になる行 | 「…：在庫がマイナスになる更新はできません。」を表示し全体を更新しない。 |
| 新在庫数が上限超過の行 | 「…：在庫の合計が…を超える更新はできせん。」を表示し全体を更新しない。 |
| 在庫変動理由が上限超過 | 刷新後は16384文字超でSymfonyのLengthエラー。現行pfは「ID …：在庫変動理由は最大65535バイト以下で入力してください。」を表示し全体を更新しない。 |
---
### データ整合性
| 観点 | 内容 |
|------|------|
| 規格在庫と規格本体 | 同一更新で `dtb_product_stock.stock` と `dtb_product_class.stock` を同じ新在庫数に揃える。 |
| 履歴との整合 | 更新成立した規格ごとに在庫変更履歴を1件作る。変更前在庫と変更後在庫を記録する。 |
| 同時更新 | 本画面は表示時点の在庫を現在庫として計算する。送信までに他処理が在庫を変えた場合、その差分は考慮しない。 |
| 支店連携 | 永続化確定後に支店へ更新を通知する。連携の到達保証は連携機能側の設計を正とする。 |

## 0203に無い定型節（設計書からは削除・2026-08-19）

### 入力項目
| 項目名 | 必須／任意 | 最大長 | 初期値 | 扱い |
|--------|------------|--------|--------|------|
| 増減させる在庫数 | 必須 | 整数10桁。新しい在庫数の上限は9桁（999999999） | 0 | 負の値で減算する。 |
| 在庫変動理由区分 | 必須 | マスタに依存 | 区分マスタの先頭 | 単一選択とする。入庫・マスタ更新で増減させる在庫数が正の場合は入荷集計にも加える。 |
| 在庫変動理由 | 増減させる在庫数が0以外のとき必須 | 16384文字（現行 pf-eccube3 は65535バイト） | 空 | 未入力で更新が成立した場合は既定の文言を記録する。 |
| 仕入単価 | 在庫変動区分が入庫のとき必須 | 数値 | 空 | 入庫以外では入力しない。 |
| 承認通知先メンバー | 必須 | — | 空 | 1人以上を選択する。 |
