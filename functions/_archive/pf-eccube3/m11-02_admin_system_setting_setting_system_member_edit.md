## 0203に無い定型節（設計書からは削除・2026-08-19）

#### エッジケース
| ケース | 扱い |
|--------|------|
| 編集でパスワードをプレースホルダのまま送信 | 退避した暗号化パスワードをそのまま保存する。ソルトの新規生成と再ハッシュは行わない。 |
| 新規でログインIDが既存と重複 | 一意制約によりエラーとなり保存が成立しない。 |
| スマレジ用アカウントを有効化したが他に有効な行がある | メンバー自体は保存済みのまま、エラーメッセージを積み編集画面へ戻す。スマレジ用フラグは反映しない。 |
| 所属店舗を未選択で保存 | 現行は所属店舗を空にできる（補助表補助管理者アカウントテーブルの店舗ID（現行）を空）。移行先の管理者アカウントテーブルの所属店舗IDは非NULLのため、移行時は所属店舗の必須化を要検討。 |
| 編集対象が存在しない | 404 応答となる（現行は補助メンバー情報が無い場合も 404）。 |

### データ整合性
| 観点 | 内容 |
|------|------|
| 編集画面とDB | 編集GETではパスワード列をプレースホルダで上書きしたあとフォームに載せるため、画面上のパスワード欄はDBの暗号文と一致しない。 |
| 所属店舗・スマレジ等の保存先 | 移行先は所属店舗（`base_info_id`）・スマレジ用アカウント（`smaregi_member_flg`）を管理者アカウントテーブル本体に保存する（本書のDB記述はこれを正とする）。現行 pf-eccube3 はメンバー保存に成功した後、補助表補助管理者アカウントテーブル（現行）に保存する。 |
| スマレジ用アカウントの一意性 | 有効なスマレジ用アカウントは全メンバーで1件までとする。重複時はメンバー保存後にエラーで差し戻し、スマレジ用フラグの反映を見送る。 |
| 認証情報との関係 | ログイン中トークンのユーザー実体は編集画面描画前に元のログインメンバーへ戻すため、編集対象の一時エンティティがトークンに残らない。 |
| 一覧との関係 | 保存後の表示は一覧（M11-01）に反映される。一覧の並び・削除は M11-01 を正とする。 |
