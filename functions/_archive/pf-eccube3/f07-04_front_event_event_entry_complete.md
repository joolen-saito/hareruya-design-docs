## 用語

| 用語 | 説明 |
|------|------|
| イベント詳細 | 申込対象の開催日程1件。主対象1件に別日程を追加できる。 |
| 別日程の同イベント | 主対象と同じイベントで申込可能な他の開催日程。まとめて申込できる。 |
| 申込 | 1件のイベント詳細に対する申込データ。チーム戦では複数選手を紐づける。 |
| 申込選手 | 申込に紐づく参加者。ログイン会員と、チーム戦のメンバー（メールのみの仮選手）。 |
| 申込状況 | 申込のステータス。エントリー済み・決済中・取消などがある。 |
| 支払番号 | 申込群に共通で振る決済識別子。`EV`＋作成日時＋申込IDで生成する。 |
| チーム人数 | イベントのチームメンバー数。1より大きいとチーム戦として席次・メンバーメールを入力する。（※Excel基本設計 0214 識別ID:1-12 により廃止。刷新後は実装しない。チーム戦フラグへ変更） |

#### エッジケース
| ケース | 扱い |
|--------|------|

| チームメンバーメール重複・席次不正 | 支払方法選択へエラー付きで戻す。 |
| 非同期でない申込登録 | 不正要求（HTTP400）として扱う。 |
| 決済結果が異常 | 決済キャンセルへリダイレクトする。 |
| 登録途中で例外 | トランザクションをロールバックし例外を再送出する。 |

| 観点 | 内容 |
|------|------|
| 申込の原子性 | 申込・申込選手・申込履歴の作成と支払番号採番は1トランザクションで確定し、例外時はロールバックする。 |
| 申込と管理画面 | 確定した申込は管理画面側のイベント申込として現れる。本書では管理側の編集は扱わない。 |

| 定員 | 詳細表示時点の残り予約数は概算で、申込登録時に悲観ロックで再判定する。表示と確定の差は登録側を正とする。 |
| メール送信 | チーム戦の招待メールは申込登録の中で送る。個別の送信失敗時の扱いは実装を確認値とする。 |

#### 入力項目
| 項目名 | 必須／任意 | 最大長 | 初期値 | 保存先・扱い |

| 別日程の同イベント選択 | 任意 | — | 主対象のみ選択 | 追加対象のイベント詳細ID（`details[]`）。同一イベント・参加可能を検証し合計参加費に加える。 |
| 支払い方法 | 有料時必須 | — | イベントの支払方法の先頭 | フォームキー`payment`（支払方法ID）。正しい支払方法でなければ申込登録で不正要求。無料時は提示しない。 |
| 席次 | チーム戦時必須 | 1～2桁の数値 | ログイン会員は先頭席、他は未選択 | `team_members[i][seat]`。数値・チーム人数以内・重複なしを検証し、申込選手の席次に保存する。 |
| チームメンバーメールアドレス | チーム戦時必須 | 半角表示可能文字 | 空 | `team_members[i][address]`。メール形式・半角・重複なし・ログイン会員と非同一を検証し、メールのみの仮選手として保存する。 |
| 申込確定チェック | 支払方法選択で必須 | — | 未チェック | チェックボックス（永続化しない）。チェックしないと「支払いへ進む」を送信できない。 |

| タイミング | 記録内容 |

- なりすまし対策トークン
- Cookie値
- セッションIDの完全値

### 権限・認可
| 利用者状態 | 申込各段階 |
|------------|------------|
| 未ログイン | 申込・支払方法選択・申込登録はログイン会員の選手情報を前提とするため利用できない。会員ログインへの誘導は会員ログイン機能を正とする。 |
| ログイン済み会員 | 自身の選手情報で申込できる。申込済み・受付期間外はイベント詳細へ戻る。 |
申込・支払方法選択・申込確認・申込登録はログイン会員を前提とする。完了・決済戻りは申込群の支払番号・対象詳細で扱う。

### 排他制御・トランザクション
申込登録は申込・申込選手・申込履歴の作成と支払番号採番を1トランザクションで確定し、例外時はロールバックする。定員判定は申込登録時に悲観ロックつきで再評価し、定員超過の同時申込を防ぐ。
