## 0203に無い定型節（設計書からは削除・2026-08-19）

#### エッジケース
| ケース | 扱い |
|--------|------|
| FAXをすべて空にする | 検証は通る。DBの各列は空文字として保存される。 |
| FAXを1つまたは2つだけ入力 | 電話番号3分割用フォーム種別の検証でエラーとなり保存しない。 |
| 当フォームに無い `dtb_help` の列 | 既存行を読み込んでからマッピングするため、当フォームが触らない列は送信前の値が保持される（別機能で変更されていなければそのまま残る）。 |
| `law_zipcode`・国マスタ側の参照列 | 当フォームに項目が無く、保存処理でも更新されない。 |
---
### データ整合性
| 観点 | 内容 |
|------|------|
| 管理画面と DB | 検証成功後の `flush` で、フォームが対象とする `law_*` 項目および関連マスタ参照が DBに反映される。 |
| 管理画面とフロント | フロントの「特定商取引法に基づく表記」は同一リポジトリの取得メソッドで読み込んだエンティティを描画するため、保存後の再読込では同一行の内容が表示される。 |
| フロントの表示抑止 | Twig 側で各項目を「定義済み」などとして条件表示する。値が無い／未定義に近い状態では当該 DL 行自体を出さないことがある（実装どおり）。FAXは「`law_fax01` が定義かつ非空」のときのみ表示。 |
| ラベル文言 | 管理画面とフロントで一部ラベルが異なる（例: `law_term01` は管理で「商品代金以外の必要料金」、フロント見出しは「商品以外の必要代金」。`law_term05` は「引き渡し時期」と「引渡し時期」）。 |

当機能専用の監査ログ出力はコード上は前提としない。一般的なアプリケーションログ・Web サーバログは環境に依存する。

- CSRF トークン原値
- Cookie値
- セッション ID の完全値
