## 用語

| 用語 | 説明 |
|------|------|
| レイアウト | フロント画面のテンプレート上の各セクションへ、どのブロックをどの順で配置するかをまとめた単位。端末種別と名称を持つ。テーブルは`dtb_layout`。 |
| ブロック | テンプレートに差し込む部品。レイアウト管理ではブロックの中身を編集せず、配置先と並び順だけを扱う。 |
| ブロック配置 | あるレイアウトで、あるブロックがどのセクションの何番目に置かれるかを表す行。テーブルは`dtb_block_position`。 |
| セクション | テンプレート上の配置先領域。head内、body直後、header、contents_top、side_left、main_top、main_bottom、side_right、contents_bottom、footer、drawer、body直前の各領域と、未使用ブロック置き場がある。各セクションは配置ID（target_id）を持つ。 |
| 未使用ブロック | どのセクションにも配置していないブロック。配置IDは0で、保存時は配置行を作らない。 |
| 端末種別 | レイアウトが対象とする端末。PCとモバイルがあり、端末種別マスタ（`mtb_device_type`）のPCはid10、モバイルはid2。 |
| ページ割り当て | レイアウトとページの紐付け。テーブルは`dtb_page_layout`。割り当てがあるレイアウトは削除できない。 |
| 既定レイアウト | プレビュー用・トップページ用・下層ページ用の3つの固定レイアウト。一覧で削除ボタンを出さない。 |

## 0203に無い定型節（設計書からは削除・2026-08-19）

#### エッジケース
| ケース | 扱い |
|--------|------|
| 編集対象のレイアウトidが存在しない | 存在しない（HTTP404）として扱う。 |
| 配置済みブロックが無い新規・編集 | 全ブロックを未使用ブロックとして表示する。 |
| すべてのブロックを未使用にして保存 | 配置行を1件も作らない。フロントには配置済みブロックが無い状態になる。 |
| 割り当てページがあるレイアウトの削除 | 削除せず警告フラッシュを積み一覧へ戻す。 |
| 既定レイアウト（id0・1・2） | 一覧で削除ボタンを出さない。 |
| プレビューでページ未選択のまま送信 | クライアント側でアラートを出し送信を中止する。 |
| プレビュー対象ページが見つからない／商品詳細で表示商品が無い | 存在しない（HTTP404）として扱う。 |
| コードプレビューをAjax以外で要求 | 不正な要求（HTTP400）として扱う。 |

### データ整合性
| 観点 | 内容 |
|------|------|
| 一覧と編集 | 一覧はプレビュー用固定レイアウトを除く全件。編集はid指定で配置・ブロックごと取得する。 |
| ブロック配置 | 保存のたびに当該レイアウトの配置を全削除して再作成する。途中失敗時の整合はトランザクション境界の実装を正とする。 |
| ドラッグ＆ドロップと送信 | 画面上の並びと隠しフィールドの行番号・配置先は、移動確定時のクライアント処理で同期する。送信されるのはこの隠しフィールド値である。 |
| プレビューと保存 | 画面プレビューは保存処理を伴うため、プレビュー実行時点でレイアウトとブロック配置が更新される。 |
| キャッシュ | 保存・削除のたびにDoctrineキャッシュを削除する。フロント表示への反映タイミングはキャッシュ実装を正とする。 |
| 割り当てページ | レイアウトとページの紐付け自体の編集はページ設定機能の範囲とし、本機能は削除可否判定で参照するだけである。 |

## 0203に無い定型節（設計書からは削除・2026-08-19）

#### 入力項目
| 項目名 | 必須／任意 | 最大長 | 初期値 | 保存先・扱い |
|--------|------------|--------|--------|----------------|
| レイアウト名 | 必須 | Symfony Length制約は無し（DBは255文字） | 新規は空、既存はDB値 | `dtb_layout.layout_name`（フォームキー`name`）。空のとき未入力検証でエラー。 |
| 端末種別 | 任意（フォーム上required無効）だが未入力は検証エラー | — | 新規はマスタの選択肢、既存はDB値を表示のみ | `dtb_layout.device_type_id`（フォームキー`DeviceType`）。端末種別マスタ参照。未入力検証あり。既存編集では隠しフィールドで現値を保持。 |
| プレビュー対象ページ | 任意 | — | 未選択 | 永続化しない（フォームキー`Page`、mapped無効）。当該レイアウトに割り当て済みページから選び、プレビュー先の判定にだけ使う。 |
| ブロック配置（各ブロック） | 任意 | — | 既存配置または全件未使用 | `dtb_block_position`（`block_id`・`section`・`block_row`・`layout_id`）。隠しフィールド`block_id_<n>`・`section_<n>`・`block_row_<n>`・`name_<n>`の連番で送信。保存時に旧配置を全削除して再作成する。 |
最大長のレイアウト名は、コアのスキーマで`dtb_layout.layout_name`が255文字の文字列型である値を記載する。フォーム側のLength制約は無いため、入力上限はDB列長に依存する。運用環境でスキーマを上書きしている場合はその環境の値が正とする。

### 権限・認可
| 利用者状態 | レイアウト管理 |
|------------|----------------|
| 未認証 | 利用不可。管理領域の認証要件に従いログイン等へ誘導される。 |
| 管理者として認証済み | レイアウトの一覧・新規・編集・削除・プレビュー・コードプレビューを利用できる。 |
| メンバーの権限設定 | 管理画面メニュー単位の表示・操作可否は管理画面全体の権限設計に従う。本機能固有の追加権限分岐は持たない。 |
---
### セッション
#### 本機能におけるセッション
| 観点 | 内容 |
|------|------|
| 一覧・編集・保存・削除 | 本機能の処理として検索条件等のセッション更新は行わない。フラッシュメッセージはフレームワークのフラッシュ領域に積む。 |
#### セッションへ保存しない情報
ブロック配置・レイアウト内容はセッションへ持たず、永続化層と送信フォーム値で扱う。
