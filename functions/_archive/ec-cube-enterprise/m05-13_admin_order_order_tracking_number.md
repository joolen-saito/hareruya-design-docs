## 用語

| 用語 | 説明 |
|------|------|
| 問い合わせ番号 | 配送業者の伝票番号・トラッキング番号。画面ラベルは「送り状No.」、ツールチップやCSV列では「お問い合わせ番号（出荷伝票番号）」と表現する。 |
| 出荷 | 1受注に紐づく出荷単位。1受注は複数の出荷を持ち得る。問い合わせ番号は出荷単位で保持する。 |
| 受注一覧 | 出荷行を一覧表示する管理画面。1行が1出荷に対応する。 |
| 受注編集 | 1受注の明細・出荷情報を編集する管理画面。出荷情報の中に問い合わせ番号欄を持つ。 |
| 出荷情報 | 出荷を表す台帳。問い合わせ番号は出荷情報の伝票番号列に保存する。 |

## 0203に無い定型節（設計書からは削除・2026-08-19）

#### エッジケース
| ケース | 扱い |
|--------|------|
| 値が空（受注一覧の非同期保存） | 文字種検証が空文字に一致せず検証エラーとなり保存しない。空での消去はこの経路では成立しない。 |
| 値が空（受注編集フォーム） | 任意項目のため空のまま保存し得る。空文字または未設定として伝票番号列を更新する。 |
| 全角英数字を入力（受注一覧） | 半角へ変換してから検証するため、半角英数字とハイフンの範囲なら保存される。 |
| 全角英数字を入力（受注編集フォーム） | 半角変換を行わないため、半角英数字とハイフン以外と判定され検証エラーとなる。 |
| ハイフン以外の記号・空白を含む | いずれの経路でも文字種検証エラーとなり保存しない。 |
| 最大長を超える | 文字数超過の検証エラーとなり保存しない。上限は経路により255／200と異なる。 |
| 存在しない出荷識別子（非同期保存） | 出荷の取得に失敗し、フレームワークの未検出応答となる。 |
---
### データ整合性
| 観点 | 内容 |
|------|------|
| 一覧と編集の一致 | 受注一覧と受注編集はいずれも同一の出荷情報の伝票番号列を参照・更新する。片方で保存した値は、他方を次に開いたときの初期値に反映される。 |
| 参照時点 | 一覧・編集とも画面表示時点の永続化済みの値を表示する。他者が更新しても表示中の画面は自動更新しない。 |
| 最大長の差 | 非同期保存は255文字まで、編集フォームは200文字までを許す。200文字を超え255文字以下の値は非同期保存でのみ保存され、その出荷を編集フォームで再保存する際に最大長検証に掛かり得る。 |
| 同時更新 | 出荷単位の上書き保存であり、同一出荷を複数の管理者が同時に保存した場合は後勝ちとなる。ロックは取らない。 |

## 0203に無い定型節（設計書からは削除・2026-08-19）

#### 入力項目
| 項目名 | 必須／任意 | 最大長 | 初期値 | 保存先・扱い |
|--------|------------|--------|--------|----------------|
| 送り状No.（受注一覧の出荷行） | 任意 | 255文字（`eccube_stext_len`確認値255） | 当該出荷の現在の保存値または空 | 出荷テーブルの送り状No.。送信キー`tracking_number`。半角変換後に文字種`/^[0-9a-zA-Z-]+$/u`と最大長を検証。非同期で1出荷ずつ保存。 |
| 送り状No.（受注編集の出荷情報） | 任意 | 200文字（`eccube_mtext_len`確認値200） | 当該出荷の現在の保存値または空 | 出荷テーブルの送り状No.。フォーム項目`Shipping.tracking_number`。文字種`/^[0-9a-zA-Z-]+$/u`と最大長を検証し、受注編集フォーム送信で保存。 |
最大長の確認値は`app/config/eccube/packages/eccube.yaml`の`eccube_stext_len`（255）と`eccube_mtext_len`（200）に基づく。運用環境で上書きされている場合はその環境の値が正とする。保存先列出荷テーブルの送り状No.はスキーマ上は最大255文字の文字列・null許容である。

## 0203に無い定型節（設計書からは削除・2026-08-19）

### 権限・認可
| 利用者状態 | 問い合わせ番号の入力・保存 |
|------------|---------------------------|
| 未認証 | 利用不可。管理用ファイアウォールにより管理側URLへ到達できずログインへ誘導される。 |
| 管理者として認証済み | 受注一覧・受注編集から問い合わせ番号を入力・保存できる。 |
| 受注機能以外の操作権限 | 問い合わせ番号の保存自体は受注画面の到達可否に従う。対応状況変更・メール送信などの可否は各機能の権限設計に従う。 |
---
### 排他制御・トランザクション
本機能は問い合わせ番号の保存で楽観ロック・悲観ロックを取らない。出荷単位の上書き保存であり、同一出荷への同時保存は後勝ちとなる。受注編集フォーム経由の保存トランザクションの境界は受注編集機能の設計を正とする。
