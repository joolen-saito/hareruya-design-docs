## 用語

| 用語 | 説明 |
|------|------|
| user_data領域 | 操作対象のルートディレクトリ。アプリケーションの`html/user_data`に固定する。ファイル管理の全操作はこの配下に限定する。 |
| カレントディレクトリ | 一覧表示の対象となっている、user_data領域配下の現在位置。ツリーやパンくず、フォルダ名リンクで移動する。 |
| ディレクトリツリー | 右側に表示する、user_data配下のフォルダ階層。フォルダのみで構成し、ファイルは含めない。 |
| jailパス | 画面表示やリンクに使う、user_data領域の絶対パスを取り除いた相対表現。先頭が空になる場合は`/`として扱う。 |
| 許可拡張子 | アップロードを許可するファイル拡張子の一覧。`eccube_file_uploadable_extensions`で定義する。 |
| アップロード制限 | 環境変数`ECCUBE_RESTRICT_FILE_UPLOAD`を1にすると、ファイル管理を含むアップロード系URLをメニューから外し、アクセスを拒否する仕組み。 |

## 0203に無い定型節（設計書からは削除・2026-08-19）

#### エッジケース
| ケース | 扱い |
|--------|------|
| カレントディレクトリ指定が領域外・`..`を含む | 領域外として扱い、user_data領域のトップを起点に表示する。 |
| アップロード先（`now_dir`）が領域外 | アップロード先不正のエラーを表示し、保存しない。 |
| 複数ファイルの一部が検証に外れる | 外れたファイルのみスキップし、通ったファイルは保存する。成功件数は実際に保存できた件数を表示する。 |
| 同一の検証エラーが複数ファイルで発生 | 同一文言は1回だけ表示する。 |
| 同名ファイルの再アップロード | ファイル名の重複を妨げず、同名で上書き保存する（同名フォルダがある場合のみ拒否）。 |
| フォルダ作成で同名のファイル・フォルダが既存 | 「既に使用されています」を表示し作成しない。 |
| 空でないフォルダの削除 | 画面上で削除ボタンを無効化する。 |
| 削除対象が`/`・空・未指定 | 削除せずファイル管理画面へ戻る。 |
| ダウンロード対象名が記号類のみで整形後に空 | ファイル名指定なしの添付としてダウンロードさせる。 |
| 表示・ダウンロードで領域外・存在しないパス | 見つからない（HTTP404）として扱う。 |
---
### データ整合性
| 観点 | 内容 |
|------|------|
| 参照時点 | 一覧・ツリーは画面表示時にファイルシステムを走査した結果である。表示後に他操作でファイルが増減しても、表示中の一覧は自動更新しない。 |
| ファイルシステムとアダプタの整合性 | アップロード成功時はファイルシステムとストレージアダプタの双方へ書き込む。削除時は双方から削除する。アダプタ側に対象が存在しない削除では、その旨をログに残しファイルシステムの削除は続行する。両者の完全同期は本書では保証しない。 |
| 同名処理 | フォルダ作成は同名重複を拒否する。ファイルアップロードは同名フォルダのみ拒否し、同名ファイルは上書きとなる。 |
| 公開URLとの整合性 | パスコピーや表示・ダウンロードで参照する公開パスは、user_data配下の相対パス（jail表現）に基づく。実体ファイルの有無は参照時点のファイルシステムに従う。 |

## 0203に無い定型節（設計書からは削除・2026-08-19）

#### 入力項目
| 項目名 | 必須／任意 | 最大長 | 初期値 | 保存先・扱い |
|--------|------------|--------|--------|----------------|
| ファイルを追加 | アップロード操作時は必須 | 拡張子は許可一覧（jpg, jpeg, png, gif, webp, svg, ico, html, htm, js, css, txt, pdfの13種）に限定。サイズ上限はPHP・Webサーバ設定に依存し本書では確定しない | 未選択 | フォームキー`file`。複数選択可。カレントディレクトリ（`now_dir`）配下へ原ファイル名で保存し、あわせてストレージアダプタへアップロードする。ファイル名は英数字・半角スペース・`_-.()`のみ許可し、先頭ピリオド・同名フォルダ・許可外拡張子は保存しない。未選択時は「選択されていません」。 |
| フォルダを追加 | フォルダ作成操作時は必須 | 文字数の上限はフォーム上で課さない。ファイルシステムのフォルダ名上限に依存 | 空 | フォームキー`create_file`。テキスト入力。カレントディレクトリ配下に同名フォルダを作成する。英数字・アンダースコア・ピリオド・ハイフンのみ許可、先頭ピリオド禁止、空不可、既存名と重複不可。永続化はファイルシステム上のディレクトリ作成で、DBには保存しない。 |
ファイルとフォルダの登録先はデータベースではなくファイルシステム（user_data配下）である。アップロードしたファイルはストレージアダプタにも連携する。

## 0203に無い定型節（設計書からは削除・2026-08-19）

### 権限・認可
| 利用者状態 | ファイル管理画面 |
|------------|-------------------|
| 未認証 | 利用不可。管理領域の認証要件に従いログイン等へ誘導される。 |
| 管理者として認証済み・アップロード制限が無効 | ファイル管理画面を表示し、アップロード・フォルダ作成・削除・表示・ダウンロードを行える。 |
| アップロード制限が有効（`ECCUBE_RESTRICT_FILE_UPLOAD`が1） | ファイル管理メニューを表示しない。各URLへ到達してもアクセス拒否（HTTP403）として扱う。 |
| メニュー権限で当該URLが拒否対象 | ナビゲーションから当該メニューを除外する。 |
---
### セッション
| 観点 | 内容 |
|------|------|
| アップロード制限の案内 | 情報メッセージを一度だけ表示するため、フラッシュメッセージのセッション領域を用いる。 |
| 結果メッセージ | アップロード・作成・削除の成功はフラッシュメッセージとしてセッション経由で表示する。 |
| カレントディレクトリ | カレントディレクトリやツリー開閉状態は、セッションではなくフォームの隠しフィールド（`tree_select_file`・`now_dir`・`tree_status`）で引き継ぐ。 |
---
### 排他制御・トランザクション
本機能はファイルシステムとストレージアダプタを操作し、データベースの楽観ロック・悲観ロックは対象としない。複数管理者が同時にアップロード・作成・削除する場合の競合は、ファイルシステムおよびアダプタの整合に依存し、本書ではロックによる排他を保証しない。
