## 用語

| 用語 | 説明 |
|------|------|
| マスタ候補 | Doctrine のメタデータ走査で得られる、画面のプルダウンに載り得るエンティティ一覧。 |
| マスタキー | プルダウンおよび hidden 項目に用いる、FQCN をハイフン区切りにした識別子（例: `Eccube-Entity-Master-Sex`）。保存時にバックスラッシュへ戻してクラス名とする。 |
| 編集コレクション | 保存用フォームの `data` 配列。1要素が1行に対応し、`id` と `name` を持つ。 |
| 行キー | 編集コレクションの配列キー。一覧初期表示ではおおむねエンティティの主キーと一致するが、新規追加行は末尾採番となる。削除相当の処理ではこのキーで `find` する。 |
| 除外クラス | プルダウン候補から明示的に除くエンティティ。`OrderStatus`、`OrderStatusColor`、`CustomerOrderStatus`、`MtbColorSequence`、`Country` の各定義クラス名がコード上で列挙される。 |

## 拡張イベント（確認値）

以下の識別子がコントローラから dispatch される。リスナーがビルダやフォームへフィールドを足す、完了時にレスポンスを差し替える、といった拡張が想定される。

- マスタ選択フォーム生成直前
- マスタ選択 POST 検証成功直後（ここでレスポンスが返ればリダイレクトに代わる）
- 編集フォーム生成直前（一覧表示フロー）
- 編集初期化時（保存アクション）
- 保存 `flush` 成功直後

イベント識別子の定数表記はソースのイベント定義クラスを正とする。本書では route 名と同様、Symfony サービス名やリスナークラス名は列挙しない。

## 0203に無い定型節（設計書からは削除・2026-08-19）

#### エッジケース
| ケース | 扱い |
|--------|------|
| 同一送信内で同じ ID が複数行 | 各行の ID フィールドに重複エラーが付く。翻訳キーは `admin.setting.system.master_data.duplicate_id`。 |
| 主キーとして 0 を使う | 自動テスト上、名称を伴う 0 の保存や、ID 0 行の削除が確認されている。整数解釈および DB 制約に従う。 |
| `flush` が例外 | エラーフラッシュを積み、リダイレクトは同様に行う。トランザクションの扱いは永続化層の既定に従う。 |
| 無効なマスタキーでパス引数だけ開く | マッピング例外を握り潰し、編集表が出ない状態に寄せ得る。 |
| プルダウンでは選べない除外マスタ | 保存処理は hidden のマスタキー文字列を解釈するため、リクエストを構築できれば当該クラスを対象に保存し得る。画面導線では選べない旨と、管理画面認可内の運用を前提とする。 |
| 具象マスタの追加列 | 本画面の保存処理は `id`・`name`・`sort_no` のみをセットする。その他の列は変更しない。新規行の追加列は DB デフォルト・Doctrine の初期状態に従う。 |
---
### データ整合性
| 観点 | 内容 |
|------|------|
| 一覧と DB | 一覧表示は `flush` 直後のリダイレクト先で再クエリするため、成功時は保存結果と一致する。 |
| 参照整合性 | 削除は `remove` と `flush` に依存し、参照先が残ると例外となりエラーフラッシュに落ちる。 |
| 同時更新 | 行バージョンや楽観ロックは持たない。同時編集は後勝ちになる。 |
| キャッシュ | 一部マスタエンティティに ORM キャッシュ指定がある。キャッシュ整合の詳細は Doctrine とエンティティ定義を正とする。 |
