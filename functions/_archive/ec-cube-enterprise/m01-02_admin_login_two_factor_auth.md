## 用語

| 用語 | 説明 |
|------|------|
| 管理者 | 管理メンバー。本機能では Symfony Security 上で管理者としてログイン済みの主体を指す。 |
| システム 2FA | アプリ設定により、二段階認証機能全体を有効にするスイッチ。無効時は追加認証や画面誘導を行わない。 |
| 個別 2FA 有効 | メンバーごとの `two_factor_auth_enabled`。有効時のみ追加認証の対象となる。 |
| TOTP 用秘密鍵 | 認証アプリとサーバが共有する秘密。DB に保持し、設計書やログに原値を書かない。 |
| デバイス トークン | 認証アプリが表示する 6 桁のワンタイムコードとして入力される値。 |
| 追加認証 | パスワード成功後、6 桁トークンを検証する画面・処理。 |
| 初回設定 | 個別 2FA が ON だが秘密鍵が未設定のときに、QR 等を用いて秘密鍵を登録する画面・処理。 |
| 認証済み Cookie | トークン検証または秘密鍵登録成功後に付与され、一定期間追加認証を省略する HTTPOnly Cookie。 |
| 本人の再設定 | 既に秘密鍵がある状態で、新しい秘密鍵に付け替える操作。認証済み Cookie があるときにのみ当該画面を利用できる。 |

#### エッジケース
| ケース | 扱い |
|--------|------|
| システム 2FA が無効 | 個別 2FA や秘密鍵の状態にかかわらず追加認証を要求しない。 |
| 個別 2FA が OFF | システム 2FA が有効でも当該管理者には追加認証を要求しない。 |
| 個別 2FA が ON で秘密鍵が未設定 | 初回設定画面へ誘導し、秘密鍵登録完了まで保護された管理画面を利用できない。 |
| 初回設定画面へ秘密鍵設定済み管理者がアクセス | 追加認証画面へ送る。未認証状態での秘密鍵再設定を防ぐ。 |
| 本人再設定時に認証済み Cookie が無効 | ホーム画面相当へ送られ、その後ガードにより追加認証または初回設定へ誘導される。 |
| Cookie 有効期間が切れた | 次回の保護画面アクセス時に追加認証または初回設定が必要になる。 |
| 同一管理者が複数ブラウザを使う | 認証済み状態はブラウザの Cookie と管理者の秘密鍵に依存する。複数ブラウザ同時利用を排他する要件は持たない。 |
---
### データ整合性
| 観点 | 内容 |
|------|------|
| 秘密鍵と Cookie | 認証済み Cookie は管理者 ID と秘密鍵から検証される。秘密鍵を更新した場合、旧秘密鍵に基づく Cookie や認証アプリのトークンは有効な認証材料として扱われない。 |
| DB 更新とレスポンス | 初回設定または本人再設定では、秘密鍵保存と認証済み Cookie 付与が成功時の副作用になる。保存失敗時の扱いはフレームワークおよび永続化層の例外処理に委ねる。 |
| メンバー管理との整合性 | 個別 2FA の ON/OFF はメンバー管理で変更される。変更後の追加認証要求は、次回以降の管理画面アクセス時の判定に従う。 |
| 時刻との整合性 | TOTP 検証はサーバ時刻とライブラリの許容範囲に依存する。本書では許容ウィンドウの数値を仕様固定しないが、実装確認値は前後 2 ステップ（`TwoFactorAuthService::verifyCode` が `verifyCode($authKey, $token, 2)` を呼ぶ）。 |
| 外部連携との整合性 | 本機能は外部認証サービスや通知 API を呼び出さない。TOTP 秘密鍵と認証済み Cookie の範囲で判定する。 |

### 権限・認可
| 利用者状態 | 保護された管理画面 | 追加認証・初回設定 |
|------------|--------------------|--------------------|
| 未ログインで管理者でない | 管理ログインの対象。本書では詳述しない。 | 対象外。 |

| システム 2FA OFF | 追加認証なしで利用可。 | 誘導されない。 |
| 管理者、個別 2FA ON、認証済み Cookie 有効 | 利用可。 | 不要。 |
| 管理者、個別 2FA ON、認証済み Cookie 無効、秘密鍵あり | 追加認証完了まで利用不可。 | 追加認証画面で検証。 |
| 管理者、個別 2FA ON、認証済み Cookie 無効、秘密鍵なし | 初回設定完了まで利用不可。 | 初回設定画面で登録。 |
| 本人の再設定 | 認証済み Cookie がある場合のみ当該画面へ到達しやすい。 | Cookie 無効時はホーム画面へ送られ、ガードで再び追加認証または初回設定へ。 |

### 試行制限
追加認証画面への POST は、本番向けレート制限設定にてユーザー単位で 5 回 / 30 分の上限が掛かりうる。
初回設定および再設定画面の POST が同一制限に含まれるかは実装のルート定義に従い、必要ならソースで確認する。
| 観点 | 扱い |
|------|------|
| 対象 | 追加認証画面の POST を中心に、実装が定義した経路。 |
| 超過時 | 制限によりリクエストが拒否される。表示文言は「表示メッセージ」の試行制限表を正とする。 |

### セッション
#### 本機能におけるセッション
| 観点 | 内容 |
|------|------|
| 追加認証判定 | 二段階認証の成立・否認は主に認証済み Cookie と DB の秘密鍵で判定する。 |
| OTP 保持 | 管理セッション内に OTP を保持する要件は本書の範囲では扱わない。 |
| 認証済み状態 | 追加認証済み状態は Cookie で保持する。セッションキー名や保存形式は本機能の仕様として固定しない。 |
#### セッションへ保存しない情報
OTP、秘密鍵、認証済み Cookie の値を業務データとしてセッションに載せない方針と解釈できる。判定と保持は Cookie 側で足りる。

### Cookie
#### 二段階認証済み Cookie
以下は現行実装での確認事項である。移行時は「ブラウザが管理画面パス配下で一定期間追加認証を省略できる」ことが成立するかを確認する。
| 項目 | 内容 |
|------|------|
| 名称 | 環境変数 `ECCUBE_2FA_COOKIE_NAME` を経由して決まるパラメータ。既定の確認はコード定数および `eccube.yaml` で行う。実装確認値は `eccube_2fa`。 |
| 値の意味 | JSON 形式で複数管理者 ID 分のエントリを保持しうる。各エントリに検証用ハッシュと更新時刻を含む。 |
| 検証 | エントリのハッシュが当該管理者の ID と秘密鍵から導かれる期待値と一致し、かつ有効期限設定を満たすこと。 |
| 有効期限 | 環境変数 `ECCUBE_2FA_EXPIRE` の日数。実装確認値は 14 日（付与時刻＋14×24×60×60 秒）。0 のときは Cookie の expires がセッション扱いに近い。 |
| Path | アプリケーションのベースパスと管理画面ルートセグメントに連動。 |
| HttpOnly | true |
| Secure | SSL 強制設定が有効なとき true。 |
| SameSite | SSL 強制設定が有効なとき、`None` が使われる実装がある。 |
アプリログに Cookie 値やハッシュ原値を載せない。
