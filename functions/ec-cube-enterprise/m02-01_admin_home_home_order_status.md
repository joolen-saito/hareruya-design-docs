# m02-01_admin_home_home_order_status（管理画面_トップ受注状況）

管理画面ホームに表示される、受注ステータス別件数の要約と受注一覧への導線。

## 概要

管理画面ホームの受注状況は、管理者がログイン後に最初に見るダッシュボード上で、マスタに定義された受注ステータスごとの受注件数を一覧表示し、受注一覧へ遷移して同じステータスで絞り込んだ状態から業務を始められるようにする機能である。日本語ロケールではカード見出しが「注文状況」となるが、本書では設計上の呼称として「受注状況」と記す。

本書は実装手順ではなく、誰が・いつ・どの条件で・結果どうなるかを読むためのリバース詳細設計とする。
既存実装のふるまい、参照するデータ、表示ルール、拡張による差し替え可能性を確認し、仕様の確からしさを把握することを目的とする。

対象はブラウザ経由の管理画面ホームの一ブロックである。売上グラフ用の非同期取得やショップ状況ブロック、在庫・商品・会員数の集計は別機能として切り離す。

本書では Symfony の route 名、URL パス、Controller 構成は扱わない。
代わりに、ホーム画面表示、受注状況カード、ステータス行クリック、カード見出しクリックといった利用者視点の入口ごとに期待されるふるまいを記載する。

本機能のカスタマイズ区分は標準であり、挙動・画面とも移行先のec-cube-enterpriseの実装を正とする。DB関連の記述（テーブル名・列名・集計列）もec-cube-enterpriseを正とする。

## 本書で扱うこと

- ホーム画面表示時に、既定の除外ルールに従って「表示対象の受注ステータス」と「ステータス別件数」がどのように決まるか
- 除外対象ステータスを拡張処理が上書きする場合があること
- 件数がデータベース上のどの情報に基づくか（全件集計であり期間絞り込みが無いこと）
- 件数が存在しないステータス行をゼロ表示として描画するルール
- ステータス行またはカード見出しから受注一覧へ遷移したとき、受注一覧の検索条件にどう反映する場合があるか（入口としての役割に限る）
- 受注ステータスマスタの並びと表示名の扱い
- 本ブロックに固有の Ajax 取得、永続化の更新、監査ログが無いことの明示
- 受け入れテストで確認されている表示・件数・遷移の範囲

## 処理フロー

### ホーム画面表示・除外リストの確定

1. 管理者がホーム画面にアクセスしたとする。
2. システムは受注状況用の除外ステータス配列を用意する。既定では次の区分が除外に含まれる。キャンセル、出荷完了、決済処理中、購入処理中、返品に相当する識別子。
3. ホーム表示向けの拡張フックにより、プラグイン等が上記配列を差し替える場合がある。差し替え後の配列が、その後の件数取得とマスタ行の取得の両方に使われる。
4. 別の拡張フックが、ホームに渡す最終的なコンテキスト（件数マップ、表示用ステータス一覧、ほかダッシュボード他ブロック用の値）をイベント引数として公開する。拡張処理が受注状況に関わる配列を上書きした場合、以降の画面表示は上書き後の値に従う。

### ステータス別件数の取得

1. 確定した除外リストに含まれない受注ステータス識別子のみを対象に、受注台帳をデータベースへ問い合わせて件数を集計する。問い合わせは識別子ごとの件数にグループ化した読み取りである。
2. 集計結果は「受注ステータス識別子と対になる件数」の対応表として保持される。除外されたステータスに属する受注は件数に含めない。
3. 期間による絞り込み、会員、宛先、支払方法、店舗などの業務的条件は課さない。台帳に存在する受注行を対象とする。

### 表示用ステータス一覧の取得と画面への合成

1. 確定した除外リストに含まれない受注ステータスについて、マスタから一覧を取得する。並びはマスタの表示順の昇順である。
2. 画面はこの一覧の各行について件数を表示する。件数対応表に当該識別子が無い場合は 0 を表示する。よってマスタに存在し除外されていないステータスは、台帳に一件も無くても行として残る。

### カード見出しから受注一覧へ

1. 利用者が受注状況カードの見出しリンクを押下する。
2. 受注一覧へ遷移する。本リンク経路ではステータス識別子をクエリに載せる設計にはしない。
3. 以降の一覧の検索条件の初期化・セッション復元は、受注一覧機能の実装に従う。

### ステータス行から受注一覧へ

1. 利用者が特定のステータス行を押下する。
2. 受注一覧へ遷移し、そのステータスの識別子がクエリとして付与される。
3. 受注一覧の初回表示ロードでは、クエリにステータス識別子がある場合、検索条件のステータスにその識別子が含まれる形でフォームが組み立てられ、同条件がセッション上の検索条件として保存される場合がある。以降のページ送りや戻りは受注一覧のセッション復元ルールに従う。

## 集計条件

| 指標 | 集計の要点 |
|------|------------|
| ステータス別件数 | 受注台帳を受注ステータス識別子でグループ化し、除外リストに含まれないステータスの受注 ID を数える。期間、会員、支払方法、配送先、店舗などの絞り込みは課さない。 |
| 表示対象ステータス | 受注ステータスマスタから、除外リストに含まれない行を表示順昇順で取得する。マスタに存在し除外されていないステータスは、該当受注が 0 件でもカードに表示する。 |

除外リストは既定値を持つが、拡張処理が差し替えた場合は、差し替え後のリストを件数集計と表示対象ステータスの双方に適用する。

## ホーム画面組み立て時の判定順序

| 順序 | 判定 | 結果 |
|------|------|------|
| 1 | 除外リストの既定値がある | 拡張フックが配列を書き換えた場合は、最終的な配列が以降すべてに使われる。 |
| 2 | 件数集計 | 除外に含まれるステータス識別子を持つ受注行は集計から除く。 |
| 3 | 表示行のマスタ取得 | 除外に含まれるステータス識別子はマスタ行としても出さない。 |
| 4 | 行と件数の合成 | マスタ行の識別子ごとに件数対応表を参照し、無ければ 0。 |

## 業務ルール・計算

| 項目 | 内容 |
|------|------|
| 件数単位 | 受注台帳の行を受注ステータス識別子単位で数える。金額計算、税計算、丸め処理は行わない。 |
| 除外条件 | 既定ではキャンセル、出荷完了、決済処理中、購入処理中、返品に相当するステータスを表示対象と件数集計から除外する。拡張処理が除外リストを差し替えた場合は、そのリストを確認値とする。 |
| 表示順 | ステータス行の順序は受注ステータスマスタの表示順に従う。件数の多い順には並べ替えない。 |
| 表示値 | 件数対応表に存在しないステータスは 0 件として表示する。 |
| リンク時の条件 | ステータス行からの遷移では当該ステータス識別子を一覧へ渡す。見出しからの遷移ではステータス条件を付与しない。 |

### エッジケース

| ケース | 扱い |
|--------|------|
| マスタに存在し、該当受注が 0 件のステータス | 除外リストに含まれなければ、行を表示し、件数は 0 とする。 |
| 除外リストに含まれるステータス | 件数集計にも表示対象ステータスにも含めない。 |
| 受注台帳に存在するがマスタ一覧に出ないステータス | カードの行として表示されないため、利用者は本ブロックから当該ステータス件数を確認できない。 |
| ステータス行押下前に受注一覧の検索条件が残っている | 本ブロックはクエリでステータスを渡すだけであり、既存検索条件の上書きやマージは受注一覧機能の実装に従う。 |
| 表示後に受注ステータスが更新された | 表示中の件数は自動更新しない。ホーム画面再表示時に再集計される。 |

## データ整合性

| 観点 | 内容 |
|------|------|
| 参照時点 | 受注状況の件数は、ホーム画面表示時にデータベースから読み取った結果である。表示後に受注が作成・更新されても、表示中の数値は自動更新しない。 |
| 件数とマスタ | 件数集計と表示対象ステータスは同一の除外リストを使う。ただし、受注台帳の読み取りとマスタの読み取りを単一の業務トランザクションで固定する要件は持たない。 |
| 一覧との整合性 | ステータス行から受注一覧へ遷移した後の検索条件、一覧件数、ページング、セッション復元は受注一覧機能の実装に従う。本ブロックの件数と一覧上の件数の完全一致は保証しない。 |
| 更新との整合性 | 本ブロックは参照のみであり、受注やステータスマスタを更新しない。受注更新との排他制御や再集計タイミングは各更新機能の設計を正とする。 |
| 外部連携との整合性 | 外部連携やバッチにより受注が更新される場合の反映タイミングは、外部連携機能またはバッチ機能の設計を正とする。本ブロックは表示時点の永続化済みデータだけを読む。 |

### DB操作

永続化の正は ec-cube-enterprise（テーブル名・操作は ec-cube-enterprise を正典）。当ドメインは承認ワークフローを介さず persist/flush で直接確定する（承認ワークフローは在庫機能固有）。

| 操作種別 | 対象テーブル | 契機・条件 |
|---------|--------------|------------|
| 登録/更新 | dtb_order / mtb_order_status | 当機能が行う登録・更新で対象テーブルを直接保存する（不要な削除は含まない）。確定は persist/flush による即時反映。DB=ec-cube-enterprise を正典とする。 |

## 試行制限

本機能では試行制限を扱わない。

---

## ログ・監査

| タイミング | 記録内容 |
|------------|----------|
| 受注状況カードの表示のみ | 本ブロック単体では業務監査ログを追加で書く処理は持たない。 |
| 受注一覧へ遷移後 | 一覧画面や検索の監査は受注一覧機能の範囲とする。 |

### ログに出してはいけないもの

- セッション識別子の完全値
- トークンや Cookie の原値
- 個人情報に該当する受注の詳細本文を、件数表示の説明に書くこと

本機能は件数のみを表示するため、設計書上も個別受注の識別子や住所を例示しない。

---

## セッション

### 本機能におけるセッション

| 観点 | 内容 |
|------|------|
| ホーム画面表示時 | 受注状況ブロックのためだけにセッションを更新しない。 |
| 受注一覧へ遷移後 | 受注一覧側の実装に従い、検索条件がセッションに保存される場合がある。キー名・形式は受注一覧機能の現行実装を確認値とし、本機能の仕様として固定しない。 |

---

## Cookie

本機能は受注状況表示のためだけに新たな Cookie を設定しない。ブラウザのセッション Cookie はフレームワークおよび管理画面全体の認証に用いられる。

---

## 排他制御・トランザクション

本ブロックの件数表示は参照のみであり、業務トランザクションを張って受注を変更しない。受注台帳に対する楽観ロックや悲観ロックの対象ではない。
同時に複数の管理者がホームを開いても、ロックを取り合う要件は持たない。
