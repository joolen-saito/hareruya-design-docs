# m02-04_admin_home_home_shop_status（管理画面_トップショップ状況）

管理画面ホームに表示される、在庫切れ商品数・取扱商品数・本会員数の要約と、商品一覧・会員一覧への導線。

## 概要

管理画面ホームのショップ状況は、管理者がログイン後に最初に見るダッシュボード上で、商品マスタと会員マスタに基づく3種類の件数を提示し、必要に応じて該当する一覧画面へ遷移して業務を始められるようにする機能である。

本書は実装手順ではなく、誰が・いつ・どの条件で・結果どうなるかを読むためのリバース詳細設計とする。
既存実装のふるまい、参照するデータ、集計境界、拡張による差し替え可能性を確認し、仕様の確からしさを把握することを目的とする。

対象はブラウザ経由の管理画面ホームの「ショップ状況」ブロックである。受注ステータス別件数、売上サマリ・グラフ、プラグイン案内、お知らせ iframe は別機能として切り離す。

本書では Symfony の route 名、Controller 構成は扱わない。
URL エンドポイントは利用者視点の入口に限り、実装確認値として記載する。

本機能のカスタマイズ区分は標準であり、挙動・画面とも移行先のec-cube-enterpriseの実装を正とする。DB関連の記述（テーブル名・列名・集計列）もec-cube-enterpriseを正とする。

## 処理フロー

### ホーム画面表示・ショップ状況用集計

1. 管理者がホーム画面にアクセスしたとする。
2. システムはデータベースへ問い合わせ、在庫切れ商品数・取扱商品数・本会員数をそれぞれ集計する。詳細は後述の「集計条件」を参照する。
3. ホーム表示組み立ての終盤で、ダッシュボード全体向けの拡張イベントが発火し、イベント引数として受注状況・売上サマリに加え、上記の3指標も渡される。
4. 画面へ渡す最終的なテンプレート変数は、イベント dispatch の直前に保持したローカル変数から組み立てられる。リスナーがイベント引数内の集計値を書き換えても、dispatch 後にその引数から再読込しない限り、画面表示は自動では変わらない。

### 在庫切れ商品数から商品一覧へ

1. 利用者が在庫切れ商品数の行を押下する。
2. システムは商品一覧向けの検索条件セッションに、「在庫なし」に相当する条件だけを格納した連想配列を保存する。既存の検索条件は本処理ではマージせず、当該セッション領域をこの配列で上書きする。
3. 商品一覧の1ページ目へリダイレクトする。
4. 以降の一覧の検索UI・件数・ページ送りは商品一覧機能の実装に従う。

### 取扱商品数から商品一覧へ

1. 利用者が取扱商品数の行を押下する。
2. 商品一覧へ遷移する。ショップ状況側では検索条件セッションを更新しない。
3. 以降の一覧の初期状態は商品一覧機能の実装に従う。

### 会員数から会員一覧へ

1. 利用者が会員数の行を押下する。
2. システムは会員一覧向けの検索条件セッションに、「本会員」に相当する会員ステータス条件だけを格納した連想配列を保存する。既存の検索条件は本処理ではマージせず、当該セッション領域をこの配列で上書きする。
3. 会員一覧の1ページ目へリダイレクトする。
4. 以降の一覧の検索UI・件数・ページ送りは会員一覧機能の実装に従う。

## 集計条件

| 指標 | 集計の要点 |
|------|------------|
| 在庫切れ商品数 | 商品とその商品規格を内部結合する。規格について `stock_unlimited` が偽、かつ `stock` が 0、かつ `visible` が真である行が存在する商品について、商品 ID を一意に数える。商品本体のステータスでさらに絞り込む条件は課していない。 |
| 取扱商品数 | 商品のステータスが「公開」または「非公開」に属する商品を数える。「廃止」は対象外とする。 |
| 本会員数 | 会員のステータスが本会員である行のみを数える。 |

グローバルフィルタや永続化層の共通規則による対象行の扱いは、各共通機能の設計を正とする。本書ではその詳細を列挙しない。

## 業務ルール・計算

| 項目 | 内容 |
|------|------|
| 在庫切れ商品数 | 商品規格単位で在庫無制限でなく、在庫数量が 0、かつ表示対象の規格を抽出し、その規格を持つ商品 ID を一意に数える。同じ商品に複数の在庫切れ規格がある場合も、商品数としては 1 件で数える。 |
| 取扱商品数 | 商品ステータスが公開または非公開の商品を数える。廃止ステータスの商品は数えない。 |
| 本会員数 | 会員ステータスが本会員の会員を数える。仮会員、退会、その他の会員ステータスは数えない。 |
| 表示形式 | 3 指標はいずれも整数件数として表示し、画面では桁区切りを適用する。金額計算、税計算、丸め処理は行わない。 |
| リンク時の条件 | 在庫切れ商品数からの遷移では在庫なし条件を保存する。会員数からの遷移では本会員条件を保存する。取扱商品数からの遷移では検索条件を保存しない。 |

### エッジケース

| ケース | 扱い |
|--------|------|
| 商品規格を持たない商品 | 在庫切れ商品数では商品規格と内部結合するため数えない。取扱商品数では商品規格の有無を条件にしないため、商品ステータスが公開または非公開なら数える。 |
| 在庫無制限の商品規格 | 在庫数量が 0 でも在庫切れ商品数には数えない。 |
| 在庫数量が 0 ではない商品規格 | 在庫数量が正数、負数、NULL のいずれでも、在庫数量 0 の条件に一致しないため在庫切れ商品数には数えない。 |
| 非表示の商品規格 | 在庫数量が 0 でも在庫切れ商品数には数えない。 |
| 1 商品に複数の在庫切れ商品規格がある | 商品 ID を一意に数えるため、在庫切れ商品数では 1 件として数える。 |
| 廃止ステータスの商品 | 取扱商品数には数えない。在庫切れ商品数では商品本体のステータスを条件にしないため、表示対象の在庫切れ商品規格があれば数える。 |
| 仮会員・退会会員 | 本会員数には数えない。 |
| 該当データが 0 件 | 件数は 0 として表示する。 |
| 在庫切れ商品数のリンク押下前に商品一覧検索条件が残っている | 既存の検索条件をマージせず、在庫なし条件だけの検索条件で上書きする。 |
| 会員数のリンク押下前に会員一覧検索条件が残っている | 既存の検索条件をマージせず、本会員条件だけの検索条件で上書きする。 |
| 取扱商品数のリンク押下前に商品一覧検索条件が残っている | ショップ状況側では検索条件セッションを更新しない。遷移後の初期状態は商品一覧機能の既定動作に従う。 |

## データ整合性

| 観点 | 内容 |
|------|------|
| 参照時点 | ショップ状況の3指標は、ホーム画面表示時にそれぞれデータベースから読み取った件数である。表示後に商品・商品規格・会員が更新されても、表示中の数値は自動更新しない。 |
| 指標間の整合性 | 3 指標はそれぞれ独立した問い合わせ結果であり、同一トランザクションでスナップショットを固定しない。 |
| 一覧との整合性 | 在庫切れ商品数は商品単位で数える。一覧側の表示単位、検索条件、ページング、検索条件解除後の状態との件数一致は保証しない。取扱商品数と本会員数も、遷移後の一覧機能側の検索条件と表示ルールを正とする。 |
| 更新との整合性 | 本ブロックは参照のみであり、商品、商品規格、会員の更新は行わない。更新処理との排他制御や再集計タイミングは各更新機能の設計を正とする。 |
| 外部連携との整合性 | 在庫や会員情報を外部連携で更新する場合の反映タイミングは、外部連携機能またはバッチ機能の設計を正とする。本ブロックは表示時点の永続化済みデータだけを読む。 |

|------|--------------|------------------|
| 在庫切れ商品数 | 商品一覧向けの検索条件セッションへ、在庫なしに相当する条件を保存する。 | 商品一覧の1ページ目で、保存した在庫なし条件を初期条件として扱う。 |
| 取扱商品数 | ショップ状況側では検索条件セッションを書き換えない。 | 商品一覧の初期状態は商品一覧機能の既定動作に従う。 |
| 会員数 | 会員一覧向けの検索条件セッションへ、本会員に相当する条件を保存する。 | 会員一覧の1ページ目で、保存した本会員条件を初期条件として扱う。 |

各遷移は別ウィンドウや非同期差し替えではなく、通常の管理画面内ページ遷移として扱う。遷移後の一覧における検索結果件数、表示列、ページ送り、検索条件の保持・解除は、それぞれ商品一覧・会員一覧の機能範囲とする。

## エラー処理

| エラー内容 | 処理 |
|------------|------|
| データベース読み取りの障害 | アプリケーションの共通例外処理に委ねる。本ブロック専用の利用者向けメッセージは設けない。 |
| 表示直後に台帳が変化 | ホーム表示時点のスナップショットであり、リアルタイムダッシュボードではない。一覧へ遷移した時点の件数・行との一致は保証しない。 |

## 試行制限

本機能では試行制限を扱わない。

## ログ・監査

| タイミング | 記録内容 |
|------------|----------|
| ショップ状況カードの表示のみ | 本ブロック単体では業務監査ログを追加で書く処理は持たない。 |
| 一覧へ遷移後 | 一覧画面の操作・検索の監査は各一覧機能の範囲とする。 |

### ログに出してはいけないもの

- セッション識別子の完全値
- トークンや Cookie の原値
- 個人情報に該当する会員・商品の詳細本文を、件数表示の説明に書くこと

本機能は集計件数のみを扱うため、設計書上も個別レコードの識別子や住所を例示しない。

---

## セッション

### 本機能におけるセッション

| 観点 | 内容 |
|------|------|
| ホーム画面表示時 | ショップ状況ブロックの表示のためだけにセッションを更新しない。 |
| 在庫切れ商品数のリンク経由 | 商品一覧向け検索条件のセッションキーに、在庫なしに相当する配列が保存される。 |
| 会員数のリンク経由 | 会員一覧向け検索条件のセッションキーに、本会員ステータスに相当する配列が保存される。 |
| 取扱商品数のリンク経由 | ショップ状況処理では検索条件セッションを更新しない。 |

キー名の正確な文字列・他機能との共有仕様は、商品一覧・会員一覧の実装を確認値とする。

---

## Cookie

本機能はショップ状況表示のためだけに新たな Cookie を設定しない。ブラウザのセッション Cookie はフレームワークおよび管理画面全体の認証に用いられる。

---

## 排他制御・トランザクション

本ブロックの件数表示は参照のみであり、業務トランザクションを張って商品・会員を変更しない。
同時に複数の管理者がホームを開いても、ロックを取り合う要件は持たない。
