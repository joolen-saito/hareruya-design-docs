# m09-09_admin_content_content_maintenance（管理画面_コンテンツ管理_メンテナンス管理）

管理画面のメンテナンス管理で、SHOP公開側の機能を一時停止し、管理画面と管理者のみアクセス可能な状態へ切り替える機能。

## 概要

メンテナンス管理は、管理者がコンテンツ管理配下のメンテナンス管理画面から、メンテナンスモードの有効化と無効化を1つのボタンで切り替える機能である。有効化すると、プロジェクト直下にメンテナンス目印ファイルを生成し、公開側フロント（SHOP）のリクエストを503応答へ振り替えて停止する。管理画面のパスへのアクセスと、メンテナンス用トークンを持つ管理者のフロントアクセスは継続できる。

本機能のカスタマイズ区分は標準であり、挙動・DB関連ともに ec-cube-enterprise の実装を正とする。本機能はメンテナンス状態をファイルシステム上の目印ファイルで保持し、業務テーブルへ保存しないため、DBスキーマを持たない。

本書は実装手順ではなく、誰が・いつ・どの条件で・結果どうなるかを読むためのリバース詳細設計とする。既存実装のふるまい、参照するファイル、判定境界、副作用、拡張による差し替え可能性を確認し、仕様の確からしさを把握することを目的とする。

対象はブラウザ経由の管理画面メンテナンス管理画面と、その切り替えがフロント停止に及ぼす範囲である。プラグインのインストール・有効・無効・削除時に自動で切り替わる自動メンテナンスの内部処理、キャッシュ管理画面からの自動解除は、本書の主題とせず別機能を正とする。

本書ではSymfonyのルートnameの網羅、Controllerのメソッド単位の解剖は扱わない。URLエンドポイントは利用者視点の入口に限り、実装確認値として記載する。管理画面プレフィックスは環境変数 `ECCUBE_ADMIN_ROUTE`に由来し、設定キー `eccube_admin_route`として解決される。本書では `%eccube_admin_route%`で示す。

## 本書で扱うこと

- メンテナンス管理画面を開いたとき、現在のメンテナンス状態に応じて表示するボタンが切り替わること
- 有効化ボタン押下時にメンテナンス目印ファイルを生成すること、無効化ボタン押下時に同ファイルを削除すること
- メンテナンスモード有効時に、公開側フロントのリクエストが503応答へ振り替わり、管理画面パスは継続してアクセスできること
- 認証済み管理者にメンテナンス用トークンのCookieを付与し、トークン一致時はフロントも継続閲覧できること
- メンテナンス管理画面およびメニュー表示が、設定キー `eccube_allow_maintenance_mode`で有効化されている環境でのみ利用できること
- 有効化・無効化の操作後に表示するフラッシュメッセージ

## リニューアル移行時の扱い

本機能はカスタマイズ区分が標準であり、挙動・DB関連ともに ec-cube-enterprise の実装を正とする。

| 観点 | 現行（pf-eccube3） | 移行先（ec-cube-enterprise） |
|------|--------------------|------------------------------|
| メンテナンス状態の保持 | ファイルシステム上の目印ファイル（DBではない） | 同一。目印ファイルの有無で判定する。 |
| 永続化先 | 業務テーブルへ保存しない | 同一。DB列を持たない。 |

本機能はデータベースへ保存しないため、テーブル名・列名の差分、論理削除・物理削除の差、補助表の有無といった移行差は発生しない。

## 利用者視点の入口

メンテナンス管理画面と切り替え操作は、メンテナンス許可フラグが真の環境でのみ到達できる。偽の環境では入口のルート自体が条件不成立となり、メニューにも表示しない。

| 入口 | URLエンドポイント | 期待されるふるまい |
|------|--------------------|--------------------|
| メンテナンス管理画面を開く | `GET /%eccube_admin_route%/content/maintenance` | 現在のメンテナンス状態を読み取り、無効中は有効化ボタン、有効中は無効化ボタンを表示する。 |
| 切り替えボタンを押下 | `POST /%eccube_admin_route%/content/maintenance` | 送信値に応じてメンテナンスモードを有効化または無効化し、同画面へリダイレクトしてフラッシュメッセージを表示する。 |
| メンテナンス許可フラグが偽の環境 | `GET /%eccube_admin_route%/content/maintenance` | ルート条件が成立せず到達できない。コンテンツ管理メニューにもメンテナンス管理を表示しない。 |
| 公開側フロントを開く（メンテナンス有効中・トークン不一致） | `GET /` などの公開側URL | 503応答へ振り替わり、メンテナンス中の案内画面を表示する。 |

## 処理フロー

### メンテナンス管理画面の表示

1. 管理者がメンテナンス管理画面を開く。
2. システムはメンテナンス目印ファイルの有無を確認し、現在のメンテナンス状態を判定する。
3. 状態が無効なら有効化ボタン（送信値 `on`）を、有効なら無効化ボタン（送信値 `off`）を表示する。

### 有効化（無効→有効）

1. 無効状態で利用者が有効化ボタンを押下し、送信値 `maintenance=on`でPOSTする。
2. システムはなりすまし対策トークンを検証する。
3. 現在が無効、かつ送信値が `on`の場合、メンテナンスモードを強制的に有効化する。モード識別子は空文字とし、目印ファイルに「空文字:32文字トークン」を書き込む。
4. 成功フラッシュ「メンテナンスモードを有効にしました。」を登録し、メンテナンス管理画面へリダイレクトする。
5. 応答の生成時、認証済み管理者にはメンテナンス用トークンのCookie（`maintenance_token`、Secure属性付き）を付与する。

### 無効化（有効→無効）

1. 有効状態で利用者が無効化ボタンを押下し、送信値 `maintenance=off`でPOSTする。
2. システムはなりすまし対策トークンを検証する。
3. 現在が有効、かつ送信値が `off`の場合、メンテナンスモードを即時に無効化する。モード識別子の一致を確認せず強制的に目印ファイルを削除する。
4. 成功フラッシュ「メンテナンスモードを無効にしました。」を登録し、メンテナンス管理画面へリダイレクトする。
5. 応答の生成時、メンテナンスが無効になったため、メンテナンス用トークンのCookieを破棄する。

### 公開側フロントの停止と管理者の継続閲覧

1. 公開側エントリポイントは、リクエストごとにメンテナンス目印ファイルの有無を確認する。
2. ファイルが存在し、リクエストパスが管理画面プレフィックス配下でない場合、メンテナンス用トークンの一致を判定する。
3. リクエストのCookie `maintenance_token`が目印ファイル内のトークンと一致しない、またはCookieが無い場合、HTTP 503応答を返し、メンテナンス中の案内画面を表示してアプリ本体の処理を行わない。
4. リクエストパスが管理画面プレフィックス配下の場合は、メンテナンス有効中でも停止せず、アプリ本体の処理へ進む。
5. Cookieのトークンが目印ファイル内のトークンと一致する場合は、公開側フロントでも停止せずアプリ本体の処理へ進む。

## メンテナンス切り替え時の判定順序

| 順序 | 判定 | 結果 |
|------|------|------|
| 1 | なりすまし対策トークンが不正 | フォーム検証に失敗し、切り替えを行わない。 |
| 2 | 現在が無効、かつ送信値が `on` | メンテナンスモードを有効化し、有効化フラッシュを表示する。 |
| 3 | 現在が有効、かつ送信値が `off` | メンテナンスモードを無効化し、無効化フラッシュを表示する。 |
| 4 | 上記いずれにも該当しない（現在が有効で送信値 `on`、現在が無効で送信値 `off` 等） | 状態を変更せず、フラッシュも表示せずにメンテナンス管理画面へリダイレクトする。 |

表示するボタンは現在状態に対応する送信値のみを送るため、通常の操作では順序2または順序3のいずれかに該当する。

公開側フロントの停止判定は上記とは独立し、目印ファイルの有無とパス・Cookieトークンの一致で行う。

| 順序 | 判定 | 結果 |
|------|------|------|
| 1 | 目印ファイルが存在しない | 停止せずアプリ本体へ進む。 |
| 2 | リクエストパスが管理画面プレフィックス配下 | 停止せずアプリ本体へ進む。 |
| 3 | Cookieトークンが目印ファイルのトークンと一致 | 停止せずアプリ本体へ進む。 |
| 4 | 上記いずれにも該当しない | HTTP 503応答を返し、メンテナンス中の案内画面を表示する。 |

## 業務ルール・計算

| 項目 | 内容 |
|------|------|
| 状態判定 | メンテナンス目印ファイルが存在すれば有効、存在しなければ無効とする。データベースの状態は参照しない。 |
| 手動有効化のモード識別子 | 本画面からの有効化はモード識別子を空文字で書き込む。プラグイン由来の `auto_maintenance` 系とは識別子で区別する。 |
| 手動無効化の強制削除 | 本画面からの無効化はモード識別子の一致を確認せず、強制的に目印ファイルを削除する。自動メンテナンス中であっても本画面の操作で解除できる。 |
| トークン生成 | 有効化のたびに32文字のランダム文字列を生成し、目印ファイルへ書き込む。再有効化のたびにトークンは変わる。 |
| 公開側停止範囲 | メンテナンス有効中、管理画面プレフィックス配下でない公開側フロントのリクエストを503へ振り替える。トークン一致の管理者は対象外とする。 |
| 利用可否の前提 | メンテナンス許可フラグが真の環境でのみ、画面・メニュー・切り替えを利用できる。本機能では金額・税・件数の計算は行わない。 |

本機能は入力フォームへ値を保存しないため、入力項目に紐づく5列表は持たない。送信値は表示中のボタンに固定された隠しフィールド `maintenance`（`on` または `off`）のみとする。

### エッジケース

| ケース | 扱い |
|--------|------|
| 無効状態で送信値 `off`が届く | 判定順序のいずれにも該当せず、状態を変更せずフラッシュも出さずにリダイレクトする。 |
| 有効状態で送信値 `on`が届く | 同上。状態を変更しない。 |
| 自動メンテナンス中に本画面で無効化 | モード識別子を確認せず強制削除するため、自動メンテナンス中でも目印ファイルを削除し無効化する。 |
| 目印ファイルへの書き込み・削除が失敗 | ファイル操作の例外はアプリの共通例外処理に委ねる。本画面専用のフォールバック文言は設けない。 |
| メンテナンス有効中に管理者がフロントを閲覧 | トークン一致のCookieを持つため停止せず閲覧できる。Cookieが無い、または別ブラウザでは503となる。 |
| メンテナンス許可フラグが偽 | 画面・メニュー・切り替えのいずれも利用できない。 |

## データ整合性

| 観点 | 内容 |
|------|------|
| 状態の保存先 | メンテナンス状態はデータベースではなくファイルシステム上の目印ファイルで保持する。複数サーバ構成では、各サーバのファイルシステムにファイルが共有されない限り状態が一致しない。 |
| 画面表示との整合 | 表示するボタンは画面表示時点の目印ファイル有無に基づく。表示後に他経路（プラグイン操作・別管理者）で状態が変わっても、表示中のボタンは自動更新しない。 |
| トークンとCookieの整合 | 再有効化でトークンが変わるため、以前のトークンを持つCookieは一致せず公開側で停止対象になる。管理者は再度管理画面へアクセスして新しいトークンのCookieを受け取る。 |
| 自動メンテナンスとの整合 | 自動メンテナンスの有効・無効タイミングは別機能の処理に従う。本画面は識別子を問わず目印ファイルの有無のみで判定・削除する。 |

---

## API/バッチ結果

| 種類 | 内容 |
|------|------|
| API | 本画面の切り替えは専用APIを呼び出さない。ファイル生成・削除をサーバ側で行い、同画面へリダイレクトする。キャッシュ管理・プラグイン操作からのajax解除経路は別機能とする。 |
| バッチ | 本画面はバッチを起動しない。 |
| 失敗時 | ファイル操作の成否を本画面で個別判定せず、例外はアプリの共通例外処理に委ねる。 |

## 入出力

| 種類 | 内容 |
|------|------|
| 入力 | メンテナンス管理画面のGET要求、および隠しフィールド `maintenance`（`on` または `off`）となりすまし対策トークンを含むPOST要求。 |
| 成功時出力 | サーバ側で目印ファイルを生成または削除し、メンテナンス管理画面へリダイレクトして成功フラッシュを表示する。 |
| 失敗時出力 | なりすまし対策トークン不正時は切り替えを行わない。ファイル操作失敗時はアプリの共通例外処理に委ねる。 |
| 副作用 | 目印ファイルの生成・削除。公開側フロントの503振り替えの有効・無効化。認証済み管理者へのメンテナンス用トークンCookieの付与・破棄。 |

## 権限・認可

| 利用者状態 | メンテナンス管理画面・切り替え |
|------------|--------------------------------|
| 未認証 | 利用不可。管理領域の認証要件に従いログイン等へ誘導される。 |
| 管理者として認証済み・許可フラグが真 | メンテナンス管理画面を閲覧し、切り替えを実行できる。応答時にメンテナンス用トークンCookieを受け取る。 |
| 許可フラグが偽 | ルート条件が成立せず画面に到達できない。メニューにも表示しない。 |
| 権限管理での個別制限 | 管理画面の権限管理設定により、コンテンツ管理配下の表示・操作可否は別レイヤで制御される。詳細は権限管理機能を正とする。 |

公開側フロントへのアクセス可否は、メンテナンス有効中はトークン一致の有無で決まる。管理者はトークンCookieにより継続閲覧でき、一般利用者は503となる。

## 画面遷移

| 条件 | 遷移先 |
|------|--------|
| メンテナンス管理画面を開く | 同一画面にメンテナンスモードのカードを表示。 |
| 有効化ボタンを押下 | メンテナンス管理画面へリダイレクト。有効化フラッシュを表示。 |
| 無効化ボタンを押下 | メンテナンス管理画面へリダイレクト。無効化フラッシュを表示。 |
| 公開側フロントへアクセス（有効中・トークン不一致） | 503応答のメンテナンス案内画面。 |

切り替えは別ウィンドウや非同期差し替えではなく、通常の管理画面内ページ遷移として扱う。遷移後はフラッシュメッセージを1度だけ表示する。

## エラー処理

| エラー内容 | 処理 |
|------------|------|
| なりすまし対策トークン不正 | フォーム検証に失敗し、切り替えを行わずに画面を再表示する。利用者向け文言は表示メッセージ節に従い、本画面専用の追加文言は設けない。 |
| 目印ファイルの生成・削除失敗 | アプリの共通例外処理に委ねる。本画面専用のフォールバック文言は設けない。 |
| 公開側フロントのメンテナンス遮断 | エラーではなく仕様として503応答とメンテナンス案内画面を返す。 |

## ログ・監査

| タイミング | 記録内容 |
|------------|----------|
| メンテナンス切り替え | 本画面の切り替え自体は業務監査ログを追加で書く処理を持たない。アクセスログ・例外ログはアプリ共通の仕組みに従う。 |

### ログに出してはいけないもの

- メンテナンス用トークンの原値
- Cookie `maintenance_token`の値
- なりすまし対策トークン
- セッション識別子の完全値

メンテナンス用トークンは公開側停止の判定に用いる秘密情報のため、設計書本文にも原値・サンプル値を記載しない。

## セッション

本機能はメンテナンス状態の保持にセッションを用いない。状態はファイルシステム上の目印ファイルで保持する。なりすまし対策トークンはフォーム送信時にフレームワークが検証する範囲とする。

---

## Cookie

### メンテナンス用 Cookie

| 項目 | 内容 |
|------|------|
| Cookie 名 | `maintenance_token`（実装確認値）。原値は記載しない。 |
| 付与条件 | メンテナンス有効中、かつ認証済み管理者の応答時に、目印ファイル内のトークンを値として付与する。Secure属性を付ける。 |
| 破棄条件 | メンテナンスが無効のときは応答時にCookieを破棄する。ログアウト成功時にも破棄する。 |
| 用途 | 公開側フロントで、リクエストのCookieと目印ファイル内トークンの一致を判定し、管理者の継続閲覧を許可する。 |

ブラウザのセッションCookieはフレームワークおよび管理画面全体の認証に用いられる。本機能はメンテナンス用トークンのCookieのみを追加で扱う。

---

## 排他制御・トランザクション

本機能はファイルの生成・削除で状態を切り替えるため、業務トランザクションを張らない。複数管理者が同時に切り替えた場合のファイル操作の競合はファイルシステムの挙動に委ねる。楽観ロック・悲観ロックの対象は持たない。
