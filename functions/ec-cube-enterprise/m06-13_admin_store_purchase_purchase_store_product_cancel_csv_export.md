## 1. 買取商品（キャンセル）CSV

### 機能の目的と役割

キャンセルされた店頭買取商品をCSV出力する。

本機能のカスタマイズ区分は新規実装であり、基本設計仕様書を正典とする。リニューアル先 ec-cube-enterprise の店頭買取（OTC）には、本機能に相当する買取商品一覧（キャンセル）CSVが実装されていない（基本設計の注記どおりPh2対応でPh1未実装）。店頭買取のCSV出力種別は古物台帳入力用CSV・買取商品一覧CSV・戻しリストCSV／PDFに限られ、キャンセル数を出力する種別は存在しない。したがってDB関連の記述は基本設計仕様書を正とし、ec-cube-enterprise の実装で確定すべき列は実装で要確認とする。

### 入出力仕様

| 種類 | 内容 |
|------|------|
| 入力 | 管理画面の検索条件、フォーム入力、CSVアップロード、または画面操作。 |
| 出力 | 画面表示、CSV/PDFダウンロード、登録完了/エラー表示。 |
| 副作用 | 対象データの登録・更新、CSV取込履歴、在庫履歴、ステータス履歴の記録。 |

### 開始条件、終了条件

| 種類 | 内容 |
|------|------|
| 開始条件 | 管理画面にログイン済みの利用者が対象メニューまたは操作を実行する。 |
| 終了条件 | 画面表示、ファイル出力、登録完了、またはエラー表示が完了する。 |

### 判定条件

- Excel設計書に記載された対象条件、検索条件、CSV出力条件、登録条件を正とする。
- Excel設計書に未記載のURLエンドポイント、DBカラム、実処理順序は `../ec-cube-enterprise` の実装を正とする。
- 権限、ログイン状態、管理画面プレフィックスなどの共通判定は共通設計および実装側のセキュリティ設定に従う。

### プロセスフロー

1. 利用者または外部システムが対象機能を開始する。
2. 入力値、検索条件、アップロードファイル、またはリクエスト本文を受け付ける。
3. Excel設計書に定義された対象データを取得し、実装側の検証・権限・状態条件を適用する。
4. 登録・更新・出力・連携のいずれかの主処理を実行する。
5. 成功時は結果画面、CSV/PDF/APIレスポンス、またはバッチ結果を返す。失敗時はエラー内容を返し、更新が必要な処理では不整合が残らないように扱う。

### ビジネスロジック

- **Excel設計優先**: 仕様の目的、対象データ、出力項目、表示項目、業務上の条件は `excel_to_html/output` の設計書を正とする。
- **実装補完**: Excel設計に書かれていないURLエンドポイント、DBカラム、トランザクション、サービス分割、非同期処理は `../ec-cube-enterprise` の実装を正とする。
- **対象機能の要点**: キャンセルされた店頭買取商品をCSV出力する。
- 実装補完の注意: ネット買取（Purchase）側には売却数・キャンセル数を切り替えて出力する買取商品一覧CSV（ルート `admin_purchase_csv_export_product_list`、クエリ `type=notSale` でキャンセル数）が存在するが、これは本機能（店頭買取）とは別系統である。店頭買取のキャンセルCSVは ec-cube-enterprise に未実装のため、列・出力規則は基本設計仕様書を正とする。

### 状態・データ更新

| 対象 | 内容 |
|------|------|
| 主データ | 管理画面の対象業務データを参照し、登録系では対象データと履歴を更新する。 |
| 履歴・ログ | 必要に応じてCSV取込履歴、在庫履歴、ステータス履歴、API受信履歴、アプリケーションログを作成・更新する。 |
| DB関連実装確認値 | 本機能はCSV出力のみでDB更新を行わない。店頭買取のキャンセルCSVは ec-cube-enterprise に未実装のため、永続化先・列名は ec-cube-enterprise 実装で要確認とする。基本設計が示す出力項目（商品コード・キャンセル数・商品名・販売価格・買取価格・言語ID・略称タグ・レアリティ・状態）は、店頭買取注文（`dtb_otc_buy_order` 系）と買取明細・商品規格・状態マスタから組み立てる想定だが、対応列の確定は実装側に委ねる。前段で挙げた `dtb_buy_order.cancel_date` は ec-cube-enterprise 実装に存在しない列のため確認値として扱わない。 |

### 例外処理

- **入力不備**: 必須項目、CSVヘッダ、CSV行、APIリクエスト本文、検索条件が不正な場合はエラーとして処理し、登録・更新対象を確定しない。
- **対象なし**: 検索条件や対象IDに該当するデータがない場合は、空の一覧、空CSV、またはエラーレスポンスとして扱う。扱いの細部は対象画面/API/バッチの実装に従う。
- **状態不整合**: 既に処理済み、キャンセル済み、承認不可、在庫不足など状態条件に合わない場合は処理対象外またはエラーとする。
- **外部連携失敗**: スマレジ等の外部連携で失敗した場合は、実装側の再連携・エラーログ・エラーメール・ステータス更新仕様を正とする。

### 関連設計への接続点

- 画面項目、CSV列、PDFレイアウト、APIリクエスト/レスポンスの詳細は、参照元Excel設計書の該当シートを正とする。
- URLエンドポイントとDBカラムは `../ec-cube-enterprise` の Controller Route、Entity、Repository、Migration、Service 実装を正とする。

## リニューアル移行時の扱い

本機能は新規実装であり、対応する現行（pf-eccube3）実装も移行先（ec-cube-enterprise）実装も無い。基本設計仕様書ではPh2対応とされ、Ph1では実装しないと明記されている。

### フェーズ2対応（フェーズ1では実装不要）

本書は現行実装からのリバースであり、以下は現行挙動として記述しているが、Excel基本設計がフェーズ2対応としている。フェーズ1では実装・テストの対象外とする。

- 買取商品一覧（キャンセル）CSV出力（※Excel基本設計 0205「買取商品一覧（キャンセル）CSV出力」はフェーズ2対応。フェーズ1では実装しない）。機能まるごとフェーズ2対応。Excel原文: 「買取商品一覧（キャンセル）CSVはPh2で対応するため、Ph1では実装しない」（0205 【新規】買取商品一覧（キャンセル）CSV出力項目）

- 移行先 ec-cube-enterprise の店頭買取（OTC）に実装済みのCSV出力種別は、古物台帳入力用CSV・買取商品一覧CSV・戻しリストCSV／PDFである。キャンセル数を出力する買取商品一覧（キャンセル）CSVは未実装である。
- 同名の機能はネット買取（Purchase）側に売却数／キャンセル数切替として存在するが、店頭買取とはデータ系統が異なるため流用前提としない。
- DB関連（永続化先・列名・型・関連）は ec-cube-enterprise 実装で要確認とする。現時点で `dtb_buy_order.cancel_date` のような列を確認値として確定しない。
