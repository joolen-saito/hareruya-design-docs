# A06-16（店頭買取情報ダブルチェック者更新）

## 業務ロジック

### 更新の契機と対象

MTGバイヤーで登録したダブルチェック者を店頭買取受注へ連携する。MTGバイヤーの画面でダブルチェック者を選び、更新ボタンを押したときに呼び出される。

更新対象は、呼び出しで指定された店頭買取受注1件とする。指定に該当する受注が無いときはエラーとし、更新しない。

### ダブルチェック者の登録

リクエストで指定されたメンバーIDの担当者を、対象受注のダブルチェック者として登録する。

ダブルチェック者は受注の承認情報として、役割「ダブルチェック」で保持する。あわせて、誰が割り当てたか（更新者）を保持する。

### 更新者と更新日時

対象受注に、更新を行った担当者と更新日時を記録する。

### 同一メンバーの禁止

更新者とダブルチェック者が同一の場合はエラーとし、登録しない。

### 処理の開始と終了

API呼び出しを受け付け、認証を通過したときに開始する。応答を返し、必要なデータ更新が完了した時点で終了する。

### エラー時の扱い

| エラー内容 | 処理 |
|------------|------|
| リクエスト本文の必須項目が不正 | エラーとして処理し、更新対象を確定しない |
| 指定IDに該当する受注が無い | エラー応答とする |
| 更新者とダブルチェック者が同一 | エラーとし、登録しない |
| 既に処理済み・キャンセル済み・承認不可など状態条件に合わない | 処理対象外またはエラーとする |

スマレジ等の外部連携で失敗したときの扱い（再連携、エラーログ、エラーメール、ステータス更新）は本機能では定めない。

## 入出力

| 種類 | 内容 |
|------|------|
| 入力 | MTGバイヤーまたは外部システムからのAPIリクエスト |
| 成功時出力 | HTTP 200。レスポンスデータは持たない |
| 失敗時出力 | エラー応答。更新は行わない |

### 入出力: 接続仕様

| 項目 | 内容 |
| --- | --- |
| エンドポイントURL | 基本設計では `/api/otcBuyOrder/{id}/doublecheck.json`。移行先ではAPI版数のプレフィックスを付けた管理配下の `/admin/otcBuyOrder/{id}/doubleCheckMember.json` とする |
| プロトコル | HTTP |
| メソッド | PUT |
| 認証の有無 | 有 |
| 認証方式 | IP制限、トークン |
| リクエスト書式 | 基本設計の記載はクエリだが、リクエストパラメータのサンプルはJSON形式のボディで示されており、移行先もリクエストボディで受け取る |
| レスポンス書式 | JSON（ただしレスポンスデータは持たない） |

### 入力: リクエスト

| パラメータ | 位置 | 型 | 必須／任意 | 説明 |
|------------|------|----|-----------|------|
| 店頭買取受注ID | パス | — | 必須 | 更新対象の店頭買取受注。型の定めは基本設計に無い |
| メンバーID | ボディ | 数値(整数) | 必須 | ダブルチェック者として登録する担当者。入力例 1000 |

### 出力: レスポンス

| ステータスコード | 条件 | 本文 |
|------------------|------|------|
| 200 | ダブルチェック者の更新が完了したとき | レスポンスデータを持たない |

### 入出力: 永続化

| 操作 | 契機 |
| --- | --- |
| 追加 | 指定されたダブルチェック者を、役割「ダブルチェック」の承認情報として登録する |
| 更新 | 対象受注の更新者と更新日時を更新する |
| 追加 | 必要に応じてAPI受信履歴を記録する |

## 表示メッセージ

本機能は画面を持たない。処理結果はAPIレスポンスで返す。
