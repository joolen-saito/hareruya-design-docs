# m09-01_admin_content_content_news（管理画面_新着情報管理）

管理画面のコンテンツ管理配下で、フロントTOPページ等に表示する新着情報の一覧表示・新規登録・編集・削除を行う機能。

## 概要

新着情報管理は、管理者がフロント向けに告知する新着情報を登録・編集・削除し、公開状態と公開日時を管理するための機能である。各新着情報は公開日時・タイトル・リンクURL・本文・公開状態を持ち、フロント側の新着情報表示はこの登録内容を参照する。

本書は実装手順ではなく、誰が・いつ・どの条件で・結果どうなるかを読むためのリバース詳細設計とする。既存実装のふるまい、参照するデータ、判定境界、副作用、拡張による差し替え可能性を確認し、仕様の確からしさを把握することを目的とする。

本機能のカスタマイズ区分は標準であり、挙動・DBともにec-cube-enterpriseの新着情報管理を正とする。DB関連の記述はec-cube-enterpriseを正典とする。

対象はブラウザ経由の管理画面のコンテンツ管理「新着情報管理」である。フロント側で新着情報を一覧・抜粋表示する処理は別機能として切り離す。

管理画面プレフィックスは環境変数`ECCUBE_ADMIN_ROUTE`を基にした設定値`eccube_admin_route`で決まる。本書では入口のパスを`%eccube_admin_route%`で示す。ルート識別子の網羅は本文では扱わず、利用者視点の入口にHTTPメソッドとサイトルートからのパスパターンを実装確認値として記載する。

- 新着情報一覧の抽出条件・並び順・ページング単位
- 新規登録・編集画面の入力項目と保存先、初期値、検証ルール
- 公開状態（公開／非公開）と公開日時の扱い
- リンクURL未入力時に「別ウィンドウで開く」設定が無効へ戻る実装
- 登録成功・削除成功・削除失敗時のメッセージと画面遷移
- 削除時の確認モーダル、なりすまし対策トークン検証、関連データ存在時のエラー扱い
- 保存・削除完了時のDoctrineキャッシュ削除と作成日時・更新日時・作成者の自動設定
- 一覧表示・編集初期化・編集完了・削除完了の各タイミングで拡張イベントがディスパッチされ、プラグイン等が差し込めること

## 利用者視点の入口

| 入口 | URLエンドポイント | 期待されるふるまい |
|------|--------------------|--------------------|
| ナビから新着情報一覧を開く | `GET /%eccube_admin_route%/content/news` | 登録済みの新着情報が公開日時の新しい順に並ぶ。各行に公開日時・公開状態・タイトルと、編集・削除の導線がある。0件なら見出し行のみ表示する。 |
| 一覧の2ページ目以降を開く | `GET /%eccube_admin_route%/content/news/page/{page_no}` | 指定ページの新着情報を1ページ10件単位で表示する。 |
| 「新規作成」ボタンを押す | `GET /%eccube_admin_route%/content/news/new` | 新規登録用の編集画面が開く。公開日時には現在日時が初期表示される。 |

| 未ログインまたは認可で拒否される利用者 | 上記パス（到達前） | 管理画面の共通ルールに従いアクセスできない（詳細は管理画面認証・認可の実装を正とする）。 |

## 処理フロー

### 一覧を開く（GET）

1. 管理画面の認証・認可の各ルールを通過する。
2. 全件取得用のクエリを組み立て、公開日時の降順、同一公開日時では識別子の降順で並べる。
3. 一覧初期化イベントをディスパッチする（プラグイン等がクエリビルダを参照・加工できる）。
4. 1ページ10件でページングし、テンプレートを描画する。

### 新規登録画面を開く（識別子が新規）

1. 新規の新着情報を組み立て、公開日時に現在日時を設定する。
2. フォームビルダーを生成し、編集初期化イベントをディスパッチする。
3. フォームを構築する。POSTでなければテンプレートを描画する。

### 既存編集画面を開く（識別子が既存）

1. 識別子で新着情報を取得する。取得できなければ見つからない扱い（HTTP404）とする。
2. 以降はフォームビルダー生成・編集初期化イベント・フォーム構築まで新規と同様に進む。POSTでなければテンプレートを描画する。

### 「登録」押下（POST、検証成功）

1. フォームをリクエストで処理する。
2. 検証成功時、リンクURLが空であれば「別ウィンドウで開く」設定を無効に揃える。
3. 新着情報を永続化する。新規ならこの時点で識別子が採番される。作成日時・更新日時・作成者は永続化前のDoctrineイベントで設定される。
4. 編集完了イベントをディスパッチする。
5. 管理画面向け成功メッセージを積む。
6. Doctrineの二次キャッシュを削除する。
7. 当該新着情報の編集画面へリダイレクトする。

### 「登録」押下（POST、検証失敗）

1. フォームをリクエストで処理する。
2. 検証失敗時、同一編集テンプレートを再描画する。成功メッセージは積まない。

### 削除実行（DELETE）

1. なりすまし対策トークンを検証する。失敗時はアクセス拒否（HTTP例外）となる。
2. 識別子で対象の新着情報を取得する。取得できなければ見つからない扱い（HTTP404）になる。
3. 削除処理を試みる。成功時は削除完了イベントをディスパッチし、成功メッセージを積み、二次キャッシュを削除する。
4. 削除中に例外が発生した場合は、対象タイトルを差し込んだ関連データ存在エラーのメッセージを積む。
5. 一覧へリダイレクトする。

## 業務ルール・計算

| 項目 | 内容 |
|------|------|
| 一覧の対象 | 公開・非公開を問わず登録済みの全新着情報。管理画面側では公開日時による絞り込みは行わない。 |
| 一覧の並び | 公開日時の降順を主、識別子の降順を従とする。 |
| ページング単位 | 1ページ10件（既定ページ件数の確認値）。 |
| 新規の公開日時初期値 | 新規登録画面表示時の現在日時。 |
| 公開状態 | 公開（保存値は真）／非公開（保存値は偽）の2択。新規の初期選択は公開（DB既定が真）。 |
| 別ウィンドウで開くの整合 | リンクURLが空の場合、保存直前に「別ウィンドウで開く」を無効（偽）へ揃える。 |
| 本文のHTML | 本文は保存時にHTML浄化（purify）を通す。HTMLタグの利用は可能だが、浄化により一部の記述は除去・整形される。 |
| 計算 | 金額計算・税計算・丸めは行わない。 |

### 入力項目

| 項目名 | 必須／任意 | 最大長 | 初期値 | 保存先・扱い |
|--------|------------|--------|--------|----------------|
| 公開日時 | 必須 | — | 新規は現在日時、既存はDB値 | `dtb_news.publish_date`。秒まで含む日時。下限は0003-01-01より前を不正日付として拒否する。 |
| タイトル | 必須 | 200文字 | 既存値または空 | `dtb_news.title`。DB列は255文字だが、フォーム検証は200文字（`eccube_mtext_len`確認値）。 |
| URL | 任意 | 200文字 | 既存値または空 | `dtb_news.url`。DB列は4000文字。入力時はURL形式制約。フォーム検証は200文字（`eccube_mtext_len`確認値）。 |
| 別ウィンドウで開く | 任意 | — | 既存値または未チェック（偽） | `dtb_news.link_method`。チェック時に真。URL未入力時は保存直前に偽へ上書きする。 |
| 本文 | 任意 | 3000文字 | 既存値または空 | `dtb_news.description`。複数行入力（textarea、表示行数8）。HTML浄化を通す。フォーム検証は3000文字（`eccube_ltext_len`確認値）。 |
| 公開状態 | 必須 | — | 新規は公開、既存はDB値 | `dtb_news.visible`。公開で真、非公開で偽を保存する。 |

最大長の数値はコア設定の`eccube_mtext_len`（確認値200）、`eccube_ltext_len`（確認値3000）を記載する。運用環境で上書きされている場合はその環境の値が正とする。

### エッジケース

| ケース | 扱い |
|--------|------|
| 編集対象の識別子が存在しない | 見つからない扱い（HTTP404）となる。新規相当の扱いにはならない。 |
| 削除対象の識別子が存在しない | 見つからない扱い（HTTP404）となる。 |
| 削除時に関連データがある等で例外発生 | 関連データ存在エラーのメッセージを積み、一覧へリダイレクトする。物理削除は完了しない。 |
| URL未入力で別ウィンドウチェックあり | 保存直前に別ウィンドウ設定を偽へ揃える。 |
| 公開日時が下限より前 | 不正日付として検証エラーになり保存しない。 |
| 一覧が0件 | 見出し行のみ表示し、明細行を出さない。 |

## データ整合性

| 観点 | 内容 |
|------|------|
| 一覧と編集 | 一覧は全件（公開・非公開とも）を公開日時降順で表示する。編集は識別子指定で取得した行を対象とする。 |
| フロント表示との整合 | 管理側の一覧は公開日時による絞り込みをしない。フロント側の表示・抜粋・公開日時判定は別機能の実装を正とし、本機能の一覧表示と一致を保証しない。 |
| 二次キャッシュ | 保存・削除の成功時にDoctrineの二次キャッシュを削除する。これにより次回読み取りで最新状態を反映する。 |
| 作成日時・更新日時・作成者 | 永続化直前のDoctrineイベントで、新規時は作成日時・更新日時、更新時は更新日時が設定される。管理者ログイン下では作成者がログインユーザに設定される。 |
| 同時更新 | 楽観ロックによる版管理は持たない。複数管理者が同一新着情報を同時編集した場合は最後に保存した内容が残る。 |

### DB操作

永続化の正は ec-cube-enterprise（テーブル名・操作は ec-cube-enterprise を正典）。当ドメインは承認ワークフローを介さず persist/flush で直接確定する（承認ワークフローは在庫機能固有）。

| 操作種別 | 対象テーブル | 契機・条件 |
|---------|--------------|------------|
| 登録/更新 | dtb_news | 当機能が行う登録・更新で対象テーブルを直接保存する（不要な削除は含まない）。確定は persist/flush による即時反映。DB=ec-cube-enterprise を正典とする。 |

| 一覧見出し | 公開日時／公開状態／タイトル | 一覧表示時の見出し行。 |
| 公開状態（一覧・選択肢） | 公開／非公開 | 一覧の各行および編集画面の公開状態選択。 |
| 削除確認（モーダル見出し） | 削除します | 削除アイコン押下時。 |
| 削除確認（モーダル本文） | この操作はあとから取り消すことができません。「（対象タイトル）」を削除してよろしいですか？ | 削除アイコン押下時。対象タイトルを差し込む。 |
| ツールチップ（URL） | この新着情報の詳細な内容を記したウェブページある場合、URLを入力します。外部サイトのURLなどを利用することもできます。 | 編集画面のURL見出しにマウスオーバー時。 |
| ツールチップ（本文） | HTMLタグが利用可能です。 | 編集画面の本文見出しにマウスオーバー時。 |

### エラー・警告（インライン）

| 表示文言（日本語） | 表示条件（利用者視点） | 表示位置 | 備考 |
|-------------------|----------------------|----------|------|
| 入力されていません。 | 必須項目（公開日時・タイトル）が未入力 | 各項目直下 | キー`This value should not be blank.` |
| 不正な日付です。 | 公開日時が下限より前 | 公開日時欄直下 | キー`form_error.out_of_range` |
| URL形式・最大長の違反文言 | URLが形式不正、または各項目が最大長超過 | 各項目直下 | 文言はコア検証メッセージカタログを正とする |

| 表示文言（日本語） | 表示条件 | 備考 |

## 権限・認可

| 利用者状態 | 一覧表示 | 編集画面 | 登録 | 削除 |
|------------|----------|----------|------|------|
| 未ログイン（一般利用者） | 管理画面の共通認証により拒否 | 同左 | 同左 | 同左 |
| ログイン済み管理者（通常） | 許可 | 許可 | 許可 | トークン検証成功時に許可 |
| ログイン済みだが認可で当該パスが拒否 | 拒否 | 拒否 | 拒否 | 拒否 |

新着情報の編集・削除可否は管理画面共通の認可に従う。本機能固有の権限分岐は持たない。

## 画面遷移

| 条件 | 遷移先 |
|------|--------|
| 一覧で「新規作成」を選択 | 新着情報の編集画面（新規） |
| 一覧でタイトルまたは編集アイコンを選択 | 当該新着情報の編集画面 |
| 一覧で削除アイコンを選択 | 同一画面で確認モーダルを表示 |
| 編集で登録に成功 | 当該新着情報の編集画面（識別子付き） |
| 編集で検証失敗 | 同一編集画面 |
| 編集画面で「新着情報管理」リンク | 新着情報一覧 |
| 削除が完了 | 新着情報一覧 |
| 削除が失敗 | 新着情報一覧 |

### 遷移時に引き継ぐ状態

| 起点 | 遷移前の処理 | 遷移後の初期状態 |
|------|--------------|------------------|
| 登録成功 | フラッシュバッグへ成功メッセージを追加 | 編集画面表示時にメッセージが一度表示される |
| 削除成功・削除失敗 | フラッシュバッグへ成功またはエラーメッセージを追加 | 一覧表示時にメッセージが一度表示される |

---

## エラー処理

| エラー内容 | 処理 |
|------------|------|
| フォーム検証エラー | 同一編集画面を再表示し、項目ごとのエラーを表示する。 |
| 編集・削除対象が存在しない | 見つからない扱い（HTTP404）とする。 |
| なりすまし対策トークン不正（削除） | アクセス拒否（HTTP例外）。 |
| 削除中の例外（関連データ存在等） | 対象タイトルを差し込んだエラーメッセージを積み、一覧へリダイレクトする。エラーログを出力する。 |

## 試行制限

本機能では試行制限を扱わない。

## ログ・監査

| タイミング | 記録内容 |
|------------|----------|
| 削除開始時 | 対象の識別子を含む削除開始ログを出力する。 |
| 削除完了時 | 対象の識別子を含む削除完了ログを出力する。 |
| 削除失敗時 | 対象の識別子と例外情報を含むエラーログを出力する。 |
| 登録・編集成功時 | 管理画面向け成功フラッシュ（メッセージキー）。アプリケーションログ専用の記録は当機能のコア実装からは読み取らない。 |

### ログに出してはいけないもの

- パスワード
- なりすまし対策トークンやそれに類する秘密値
- Cookie値
- セッションIDの完全値

## セッション

### 本機能におけるセッション

| 観点 | 内容 |
|------|------|
| 成功・エラーメッセージ | リダイレクト後の編集画面や一覧で一度表示するためにフラッシュバッグへ格納する。 |

### セッションへ保存しない情報

新着情報の本文やフォームの下書きをセッションへ長期保存する処理は当機能では行わない。

---

## Cookie

本機能単体で特有のCookieは定義しない。セッションCookieは管理画面全体の実装を正とする。

---

## 排他制御・トランザクション

当機能のコア実装はDoctrineの典型パターンによる永続化であり、新着情報を楽観ロックで版管理する実装は持たない。複数管理者が同一新着情報を同時編集した場合の結果は最後に保存された内容が残る。
