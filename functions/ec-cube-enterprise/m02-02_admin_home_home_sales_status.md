# m02-02_admin_home_home_sales_status（管理画面_トップ売上状況）

管理画面ホームに表示される、期間別の売上金額・件数のサマリと、週間・月間・年間の売上金額棒グラフ。

## 概要

管理画面ホームの売上状況は、管理者がログイン後に最初に見るダッシュボード上で、受注台帳に基づく売上金額と売上件数を期間ごとに集計して提示する機能である。画面上部には「今月」「今日」「昨日」のサマリがサーバ側レンダリングで示され、その下のタブでは週間・月間・年間の推移を棒グラフで表示する。グラフ用データはページ表示後にブラウザから非同期で取得される。

本書は実装手順ではなく、誰が・いつ・どの条件で・結果どうなるかを読むためのリバース詳細設計とする。
既存実装のふるまい、参照するデータ、集計境界、拡張による差し替え可能性を確認し、仕様の確からしさを把握することを目的とする。

対象はブラウザ経由の管理画面ホームの「売上状況」ブロックである。受注ステータス別件数のカード、ショップ状況ブロック、プラグイン案内、お知らせ iframe は別機能として切り離す。

本書では Symfony の route 名、URL パス、Controller 構成は扱わない。
代わりに、ホーム画面表示、売上サマリの表示、グラフデータの非同期取得、タブ切替、権限に至れない利用者といった利用者視点の入口ごとに期待されるふるまいを記載する。

本機能のカスタマイズ区分は標準であり、挙動・画面とも移行先のec-cube-enterpriseの実装を正とする。DB関連の記述（テーブル名・列名・集計列）もec-cube-enterpriseを正とする。

## 処理フロー

### ホーム画面表示・売上対象外リストの確定

1. 管理者がホーム画面にアクセスしたとする。
2. システムは売上集計用の売上対象外ステータス配列を用意する。既定ではキャンセル、決済処理中、購入処理中、返品を除外する。注文受領、入金待ち、対応中、出荷完了、入金済み、出荷指示、ピック中、店頭予約、ピック完了、引渡し済みは、既定の売上集計対象に含まれる。
3. 売上向けの拡張フックにより、プラグイン等が上記配列を差し替える場合がある。差し替え後の配列が、その後のサマリ集計とグラフ用データ取得の双方に使われる。
4. ホーム全体のコンテキストを公開する別の拡張フックにより、売上サマリを含むダッシュボード値が最終的に上書きされる場合がある。拡張処理が値を上書きした場合、画面表示は上書き後の値に従う。

### 売上サマリの取得

1. 「今日」について、当日 0 時から翌日 0 時未満の `order_date` を持つ受注のうち、既定実装では注文受領、入金待ち、対応中、出荷完了、入金済み、出荷指示、ピック中、店頭予約、ピック完了、引渡し済みの受注を対象に、`payment_total` の合計と件数を求める。
2. 「昨日」について、前日の日付で同様の境界を用いて合計と件数を求める。
3. 「今月」について、当月 1 日 0 時から翌月 1 日 0 時未満の `order_date` を持つ受注のうち、既定実装で売上集計対象となるステータスの受注を対象に、合計と件数を求める。終端日の解釈は実装が用いる相対日付指定に依存し、タイムゾーンは永続化層および実行環境の設定に従う。
4. 問い合わせ結果が無い場合、実装は空の結果として扱い、画面は 0 を表示する。

### 売上グラフ用データの取得と変換

1. ブラウザがホーム画面表示後、グラフ用データを非同期で要求する。
2. サーバは再度売上対象外リストを拡張フックで確定したうえで、次の三つの区間について、確定後の売上集計対象ステータスの受注を読み取り、日付または年月単位のバケットに売上金額と件数を累積する。
   - 週間相当。当日から見て過去にさかのぼった約一週間の範囲と当日現在までの upper bound を持つ区間。バケットキーは日単位である。
   - 月間相当。当月 1 日から現在までの区間。バケットキーは日単位である。
   - 年間相当。現在から過去にさかのぼった約一年と現在までの区間。バケットキーは年月単位である。
3. 各区間について、範囲内の各日または各年月キーに対し、売上が無い期間も値が 0 のバケットとして用意される。これによりグラフの横軸ラベルが欠けない。
4. 返却される JSON は三つのバケット集合からなる配列であり、画面側はこれを順に週間・月間・年間の canvas に対応付けて棒グラフを生成する。

### 画面への描画

1. 売上サマリはテンプレートが通貨表示および件数の桁区切りを適用して出力する。
2. グラフは売上金額のみを縦棒として表示する。ツールチップは通貨記号付きで値を整形する。
3. 非同期取得が完了すると読み込みインジケータが非表示となる。取得に失敗した場合も読み込み表示は消えるが、グラフは描画されない。

## 集計条件

| 指標 | 集計の要点 |
|------|------------|
| 今月の売上金額・件数 | 当月 1 日 0 時から翌月 1 日 0 時未満の `order_date` を持ち、売上対象外ステータスに含まれない受注について、`payment_total` の合計と受注件数を求める。 |
| 今日の売上金額・件数 | 当日 0 時から翌日 0 時未満の `order_date` を持ち、売上対象外ステータスに含まれない受注について、`payment_total` の合計と受注件数を求める。 |
| 昨日の売上金額・件数 | 前日 0 時から当日 0 時未満の `order_date` を持ち、売上対象外ステータスに含まれない受注について、`payment_total` の合計と受注件数を求める。 |
| 週間グラフ | 当日を含む過去約一週間の区間を日単位バケットに分け、各日に売上金額と件数を累積する。画面では売上金額のみを棒グラフに使う。 |
| 月間グラフ | 当月 1 日から現在までの区間を日単位バケットに分け、各日に売上金額と件数を累積する。画面では売上金額のみを棒グラフに使う。 |
| 年間グラフ | 現在から過去約一年の区間を年月単位バケットに分け、各月に売上金額と件数を累積する。画面では売上金額のみを棒グラフに使う。 |

売上対象外ステータスは既定値を持つが、拡張処理が差し替えた場合は、差し替え後のリストをサマリ集計とグラフ用データ取得の双方に適用する。

## 売上集計における判定順序

| 順序 | 判定 | 結果 |
|------|------|------|
| 1 | 売上対象外リストの既定値がある | 拡張フックが配列を書き換えた場合は、最終的な配列がサマリおよびグラフの両方に使われる。 |
| 2 | 受注ステータス | 既定実装ではキャンセル、決済処理中、購入処理中、返品を金額・件数のいずれにも含めない。それ以外の注文受領、入金待ち、対応中、出荷完了、入金済み、出荷指示、ピック中、店頭予約、ピック完了、引渡し済みは含める。 |
| 3 | 期間境界 | `order_date` が各区間の開始以上かつ終了条件を満たす受注のみを対象とする。グラフではバケットキーへ変換したうえで累積する。 |

## 業務ルール・計算

| 項目 | 内容 |
|------|------|
| 売上金額 | 条件に一致する受注の `payment_total` を合計する。税、送料、値引、手数料の内訳は本ブロックでは再計算しない。 |
| 売上件数 | 条件に一致する受注行を数える。受注明細行数、商品点数、配送件数では数えない。 |
| 除外条件 | 既定ではキャンセル、決済処理中、購入処理中、返品に相当するステータスを除外する。拡張処理が除外リストを差し替えた場合は、そのリストを確認値とする。 |
| 期間境界 | サマリは今日、昨日、今月の境界で `order_date` を判定する。グラフは週間・月間・年間ごとの区間をバケット化する。 |
| 表示形式 | 金額は通貨表示として整形し、件数は整数として表示する。画面上の棒グラフは売上金額だけを系列にする。 |

### エッジケース

| ケース | 扱い |
|--------|------|
| 該当受注が 0 件 | サマリは金額・件数とも 0 として表示する。グラフは期間内の各バケットを 0 で埋める。 |
| 売上対象外ステータスの受注 | 金額・件数のいずれにも含めない。 |
| `payment_total` が 0 の受注 | ステータスと期間条件に一致する場合、売上件数には含め、売上金額には 0 として加算する。 |
| 表示後に受注が更新された | 表示中のサマリとグラフは自動更新しない。ホーム画面再表示またはグラフ再取得時の読み取り結果に従う。 |
| サマリ取得時点とグラフ取得時点の間に受注が変わった | サマリとグラフは別リクエストで取得されるため、同一スナップショットで一致することは保証しない。 |
| グラフ用 JSON に件数が含まれる | 画面の棒グラフ描画では売上金額のみを使う。件数は当該グラフの表示系列として扱わない。 |

## データ整合性

| 観点 | 内容 |
|------|------|
| 参照時点 | 売上サマリはホーム画面 HTML 表示時に読み取った結果である。グラフ用データはページ表示後の Ajax で別途読み取る。 |
| サマリとグラフ | サマリとグラフは同一トランザクションで固定しない。表示直後に受注が更新された場合、両者の値が一致しない場合がある。 |

| 更新との整合性 | 本ブロックは参照のみであり、受注台帳やマスタを更新しない。受注更新との排他制御や再集計タイミングは各更新機能の設計を正とする。 |
| 外部連携との整合性 | 外部連携やバッチにより受注が更新される場合の反映タイミングは、外部連携機能またはバッチ機能の設計を正とする。本ブロックは読み取り時点の永続化済みデータだけを読む。 |

| 種類 | 内容 |
|------|------|
| API | 売上サマリはホーム画面 HTML レンダリング時にサーバ側で取得する。グラフ用データはページ表示後に管理画面内の Ajax として JSON を取得する。 |

| 成功時出力 | 売上サマリを含む HTML。続いてグラフ用の JSON 配列。 |
| 失敗時出力 | グラフ用データが Ajax 要件を満たさない場合、グラフデータは取得できず JSON エラー相当の本文が返る。サマリはホーム描画時に既に決まっている。データベース障害時はアプリケーションの共通例外処理に委ねられ、ホーム全体が表示されないことがある。 |
| 副作用 | 本ブロックの処理だけを見ると、受注台帳やマスタを更新しない。グラフ取得でもセッションを本ブロック専用に書き換えない。 |

## DBカラム

当機能に直接関係する列のみを以下に列挙する。型や一覧の細部はスキーマを参照する。

| テーブル | 列 | メモ |
|----------|-----|------|
| dtb_order | order_date | 期間フィルタおよびグラフバケットのキーに用いる。タイムゾーン付き日時として保持される。 |
| dtb_order | payment_total | 売上金額の合計に用いる。 |
| dtb_order | order_status_id | 受注ステータス。売上対象外リストとの照合に用いる。 |

### DB操作

永続化の正は ec-cube-enterprise（テーブル名・操作は ec-cube-enterprise を正典）。当ドメインは承認ワークフローを介さず persist/flush で直接確定する（承認ワークフローは在庫機能固有）。

| 操作種別 | 対象テーブル | 契機・条件 |
|---------|--------------|------------|
| 登録/更新 | dtb_order | 当機能が行う登録・更新で対象テーブルを直接保存する（不要な削除は含まない）。確定は persist/flush による即時反映。DB=ec-cube-enterprise を正典とする。 |

## バリデーション

| 項目 | 内容 |
|------|------|
| 利用者入力 | 本ブロックはフォームを持たない。売上サマリは表示のみ。 |
| Ajax 妥当性 | サーバは XMLHttpRequest であり、かつ CSRF 検証に通る場合にのみグラフ用データを返す。詳細はフレームワークおよび管理画面共通テンプレートの確認値とする。 |
| 集計の空 | 該当受注が無いとき、サマリは 0 表示。グラフバケットは期間内キーを 0 で埋める。 |

## 権限・認可

| 利用者状態 | 売上状況ブロック |
|------------|------------------|
| 未認証 | 利用不可。管理領域の認証要件に従う。 |
| 管理者として認証済み | 売上サマリとグラフデータを取得・閲覧できる。 |
| より細かいロールで売上閲覧を制限する要件 | ホーム実装単体では個別の売上閲覧権限分岐は設けず、管理領域への到達可否に依存する。追加制御が必要な場合は別設計とする。 |

## 画面遷移

| 条件 | 遷移先 |
|------|--------|
| ホーム画面を開く | 同一画面内に売上状況を表示。 |
| 週間・月間・年間タブ操作 | 同一画面内のタブ表示切替。サーバへの追加遷移はない。 |
| グラフ取得失敗 | 同一画面のまま。グラフ未描画。 |

## エラー処理

| エラー内容 | 処理 |
|------------|------|
| グラフ用 Ajax が CSRF または XMLHttpRequest 条件を満たさない | グラフデータを返さない。フロントは失敗コールバックが実質空のため利用者向けメッセージは出さない。 |
| データベース読み取りの障害 | アプリケーションの共通例外処理に委ねる。本ブロック専用の利用者向けメッセージは設けない。 |
| 表示直後に台帳が変化 | サマリとグラフは同一瞬間のスナップショットではない。リアルタイムダッシュボードではない。 |

## ログ・監査

### ログに出してはいけないもの

- CSRF トークンの原値や Cookie の原値
- セッション識別子の完全値
- 個別受注の識別子や住所など、ダッシュボードの説明に不要な個人情報の列挙

本機能は集計値のみを扱うため、設計書上も個別受注の内容を例示しない。

## Cookie

本機能は売上表示のためだけに新たな Cookie を設定しない。ブラウザのセッション Cookie はフレームワークおよび管理画面全体の認証に用いられる。

---

## 排他制御・トランザクション

本ブロックの売上表示とグラフデータ生成は参照のみであり、業務トランザクションを張って受注を変更しない。受注台帳に対する楽観ロックや悲観ロックの対象ではない。
同時に複数の管理者がホームを開いても、ロックを取り合う要件は持たない。
