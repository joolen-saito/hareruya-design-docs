# f06-19_front_member_mypage_credit_card（フロント_会員_クレジットカード情報登録・変更）

ログイン会員がマイページで、決済代行に預けた登録済みクレジットカードの有無を表示し、新規登録・差し替え・削除を行う機能。決済プラグインSlnPayment42が提供する。

## 概要

会員クレジットカード情報の登録・変更は、ログイン済みのフロント会員がマイページ配下のカード編集画面で、決済代行に保管したカード情報の登録状況を確認し、新しいカードの登録、既存カードの差し替え、登録済みカードの削除を行えるようにする機能である。

本書は実装手順ではなく、誰が・いつ・どの条件で・結果どうなるかを読むためのリバース詳細設計とする。既存実装のふるまい、参照するデータ、判定境界、副作用、外部の決済代行との連携範囲を確認し、仕様の確からしさを把握することを目的とする。

対象はブラウザ経由のフロントのマイページ配下にあるカード編集画面である。本画面の利用にはフロントの会員ログイン（完全認証）が前提であり、未ログインや簡易認証のみの状態では利用できない。クレジットカードの原番号・有効期限・セキュリティコード・トークンは画面入力または決済代行への送信のために一時的に扱うだけで、自社データベースには保持しない。保持するのは会員と決済代行側会員枠を対応づける識別子のみである。

本書ではルート識別子の網羅やController構成は主題としない。URLエンドポイントは利用者視点の入口に限り、サイトルートからのパスパターンを実装確認値として記載する。

本機能のカスタマイズ区分は標準である。リニューアル後の標準機能であり、挙動・DB関連とも ec-cube-enterprise の決済プラグインSlnPayment42の実装を正とする。

## 本書で扱うこと

- カード編集画面表示時に、決済代行へ会員照会して登録済みカードの有無と内容を表示するふるまい
- 新規カード登録・差し替え時に、画面でトークンを生成し、トークンを決済代行へ送って会員枠へカードを登録するふるまい
- 登録済みカード削除時に、決済代行の会員枠を無効化し、自社側の会員枠識別子を進めるふるまい
- カード番号・有効期限・セキュリティコード・名義などの画面入力項目と、その検証
- 会員と決済代行会員枠を対応づける識別子だけを自社データベースに保持し、カード原番号・トークンを保持しないこと
- 画面に表示する登録済みカードのマスク表示
- 操作結果のフラッシュ文言、画面遷移、権限

## 用語

| 用語 | 説明 |
|------|------|

| 会員枠 | 決済代行側で会員ごとに作られるカード保管枠。会員照会・登録・変更・無効はこの枠に対して行う。 |

| マスク表示 | 画面に出すカード番号を、先頭を伏字にして末尾4桁だけ見せる表示。 |

## 利用者視点の入口

フロントのパスは、本店では`/{_locale}/...`、支店では`/{_locale}/{_shop}/...`の形を取る。`{_locale}`はロケール、`{_shop}`は店舗セグメントで、いずれも実装のルート要件で決まる確認値とする。本機能は管理画面プレフィックスを用いない。

| 入口 | URLエンドポイント | 期待されるふるまい |
|------|--------------------|--------------------|
| カード編集画面を開く | `GET /{_locale}{_shop}/mypage/sln_edit_card` | 会員ログイン済みなら、決済代行へ会員照会し、登録済みカードがあればマスク表示と有効期限を表示し、カード入力フォームを表示する。 |
| カード登録・差し替えを送信 | `POST /{_locale}{_shop}/mypage/sln_edit_card` | 画面で生成したトークンを送信し、決済代行の会員枠へカードを登録または差し替える。完了後はカード編集画面へ戻る。 |
| カード削除を送信 | `POST /{_locale}{_shop}/mypage/sln_edit_card` | 削除指示として送信し、決済代行の会員枠を無効化する。完了後はカード編集画面へ戻る。 |
| 未ログイン・簡易認証のみ | `GET /{_locale}{_shop}/mypage/sln_edit_card` | カード編集画面を表示せず、マイページ入口へ誘導する。 |
| 会員登録機能が無効な店舗 | `GET /{_locale}{_shop}/mypage/sln_edit_card` | カード会員登録を使わない設定のとき、ページを表示せず未検出（HTTP404）として扱う。 |

登録と削除は同一URLへのPOSTで、画面のトークン欄の値で分岐する。削除指示は専用の値（削除を表す固定文字列）をトークン欄へ入れて送信する。

## フロント挙動

| 観点 | 内容 |
|------|------|
| 表示要素 | 画面見出しは「マイページ/登録済クレジットカード」。登録済みカードがある場合は、マスクしたカード番号と「有効期限:◯◯年 ◯◯月」、およびカード情報削除ボタンを表示する。続けてカード番号、カード有効期限（月・年の選択）、設定により表示されるカード名義（姓・名）、セキュリティコード、生月日、電話番号下4桁の入力欄と、カード情報登録ボタンを表示する。 |
| JS挙動 | カード情報登録ボタン押下時に、入力欄ごとのクライアント側チェックを順に実行する。チェックを通ると入力欄をいったん画面上で空にし、処理中表示へ切り替えたうえで、外部のトークン生成スクリプトを呼んでトークンを取得する。取得したトークンを隠し欄へ入れてフォームを送信する。トークン生成スクリプトの読み込み失敗や呼び出し時例外のときは、決済通信障害の警告を出してマイページへ戻す。 |
| クライアント側チェック | カード番号は未入力・数字以外・桁数（14桁未満または16桁超）を弾く。有効期限は月・年の未選択を弾く。カード名義は未入力・カタカナ以外を弾く。セキュリティコードは未入力・数字以外・3桁未満を弾く。生月日は未入力・数字以外・4桁以外を弾く。電話番号下4桁は未入力・数字以外・4桁以外を弾く。いずれも画面上の各欄直下にメッセージを出し、欄の枠を赤くする。 |
| 削除挙動 | カード情報削除ボタン押下時に、トークン隠し欄へ削除を表す固定文字列を入れてフォームを送信する。二重送信防止のため、送信開始後は再押下時に処理中である旨のダイアログを出す。 |
| CSS・レイアウト | マイページ共通の枠とフォームレイアウトを使い、入力補助文（本人名義の利用、セキュリティコードの位置、生月日や電話番号の説明）を各欄に添える。条件によりカード名義・セキュリティコード・生月日・電話番号の各欄を表示するかどうかをプラグイン設定で切り替える。 |
| モーダル・ポップアップ | 専用モーダルは持たない。通信障害・入力不備・二重送信時はブラウザのダイアログまたは画面上メッセージで知らせる。 |

## 処理フロー

### カード編集画面表示

1. 会員がカード編集画面のURLにアクセスする。
2. 完全認証済みでなければ、画面を表示せずマイページ入口へ遷移する。
3. カード会員登録を使わない設定のときは、ページを未検出（HTTP404）として扱う。
4. 画面表示用に登録・削除フォームを組み立てる。購入時専用の項目（カード登録チェック、支払方法、請求者氏名・メール）は本画面のフォームから取り除く。
5. 決済代行へ会員照会を送る。会員枠が有効な状態のとき、その内容を登録済みカードとして受け取り、マスクしたカード番号と有効期限を画面へ渡す。照会で例外が出た場合は登録済みカード無しとして表示を続ける。
6. トークン生成スクリプトのURLと認証コード、登録済みカードの有無、3Dセキュア利用有無、有効期限の年・月などを画面へ渡して表示する。

### カード登録・差し替え送信

1. 会員がカード情報を入力し、カード情報登録ボタンを押す。
2. クライアント側チェックを通ると、画面で外部スクリプトがトークンを生成し、隠し欄へトークンを入れてフォームを送信する。
3. サーバ側は送信を受け、トークン欄が削除指示でないこと、フォーム検証を通ることを確認する。
4. 決済代行へ会員照会し、会員枠の登録状況に応じて、会員枠へのカード変更、無効解除後の変更、または会員枠の新規作成のいずれかでトークンによるカード登録を行う。
5. 登録に成功したら「カード情報を更新しました」をフラッシュに積み、カード編集画面へ戻す。
6. 検証に失敗したときは「入力項目をご確認ください。」をフラッシュに積み、カード編集画面へ戻す。
7. 決済処理上の業務エラーが出たときは、その内容のフラッシュを積み、決済通知ログとエラーログへ記録し、必要に応じて管理者宛にエラーメールを送り、カード編集画面へ戻す。
8. 通信などの想定外エラーのときは「通信エラーが発生しました、後ほどお試しください。」をフラッシュに積み、カード編集画面へ戻す。

### カード削除送信

1. 会員がカード情報削除ボタンを押す。
2. 画面はトークン欄へ削除を表す固定文字列を入れてフォームを送信する。
3. サーバ側はトークン欄が削除指示であることを判定し、決済代行の会員枠を無効化する。無効化に成功したら、自社側の会員枠識別子の枝番を進める。
4. 「カード情報を更新しました」をフラッシュに積み、カード編集画面へ戻す。
5. 業務エラー・想定外エラーのときは、登録時と同じくフラッシュとログで扱い、カード編集画面へ戻す。

## 登録・削除送信時の判定順序

| 順序 | 判定 | 結果 |
|------|------|------|
| 1 | 完全認証済みでない | 画面を表示せずマイページ入口へ遷移する。 |
| 2 | カード会員登録を使わない設定 | 未検出（HTTP404）として扱う。 |
| 3 | トークン欄が削除指示 | 会員枠を無効化し、会員枠識別子を進める。完了後カード編集画面へ戻る。 |
| 4 | フォーム検証が成功し、トークンに値がある | トークンで会員枠へカードを登録・差し替える。完了後カード編集画面へ戻る。 |
| 5 | フォーム検証が成功し、トークンが空 | カード登録を行わずカード編集画面へ戻る。 |
| 6 | フォーム検証が失敗 | 「入力項目をご確認ください。」を表示しカード編集画面へ戻る。 |

登録・差し替え時の会員枠の選び方は、決済代行への会員照会で得た登録状況により分岐する。有効またはカード無効なら会員枠のカード変更、ログイン回数無効または会員無効なら無効解除後にカード変更（失敗時は会員枠を無効化）、会員削除済みなら会員枠を新規作成する。会員枠が無ければ新規作成する。

### フラッシュ・トースト

本機能はカード編集画面の上部に警告色のフラッシュを表示する。文言は次のとおりで、いずれも処理結果としてカード編集画面へ戻った直後に1度だけ表示する。

| 表示文言（日本語） | 表示条件 |
|-------------------|----------|
| `カード情報を更新しました` | カード登録・差し替え・削除が成功したとき。 |
| `入力項目をご確認ください。` | サーバ側のフォーム検証に失敗したとき。 |
| `通信エラーが発生しました、後ほどお試しください。` | 想定外の通信などの例外が出たとき。 |
| 決済処理上のエラー内容（例: カード登録失敗の理由を含む文言） | 決済代行とのやり取りで業務エラーが出たとき。 |

## 業務ルール・計算

| 項目 | 内容 |
|------|------|
| 認証前提 | 完全認証済みの会員のみ操作できる。会員はログイン中の自分のカードだけを対象とし、他会員のカードは扱わない。 |
| 会員枠識別子の組み立て | 会員枠識別子は、会員ごとの枝番と会員IDから組み立てる。枝番は会員枠を作り替えるたびに進める。会員枠のパスワードに相当する値は会員IDとアプリ固有値から導出し、画面・設計書・ログに原値を出さない。 |
| 登録・差し替えの分岐 | 決済代行への会員照会で得た登録状況により、会員枠のカード変更・無効解除後の変更・会員枠の新規作成を選ぶ。 |
| 削除の扱い | 削除は決済代行の会員枠の無効化として行い、成功時に自社側の会員枠識別子の枝番を進める。自社側にカード明細行は持たない。 |
| カード情報の非保持 | カード原番号・有効期限・セキュリティコード・トークンは、画面入力と決済代行への送信のためだけに一時的に扱う。自社データベースには保持しない。 |
| 業務計算 | 金額計算・与信金額の算出は本機能では行わない。決済代行側の会員枠管理に委ねる。 |

### 入力項目

| 項目名 | 必須／任意 | 最大長 | 初期値 | 保存先・扱い |
|--------|------------|--------|--------|----------------|
| カード番号 | 任意（登録時はクライアント側で必須扱い） | 16桁（フォーム属性とサーバ側Length） | 空 | 自社保存なし。画面でトークン生成に使い送信値は破棄する。半角数字のみ。 |
| カード有効期限（月） | 任意（登録時は必須扱い） | 2桁。1〜12の選択 | 空 | 自社保存なし。トークン生成に使う。 |
| カード有効期限（年） | 任意（登録時は必須扱い） | 4桁。当年から10年先までの選択 | 空 | 自社保存なし。トークン生成に使う。当年より過去・当年で当月より前は送信後チェックで弾く。 |
| カード名義（姓） | 任意（名義欄を表示する設定では登録時に必須扱い） | 10文字 | 空 | 自社保存なし。トークン生成に使う。半角・全角カタカナのみ。 |
| カード名義（名） | 任意（同上） | 10文字 | 空 | 自社保存なし。トークン生成に使う。半角・全角カタカナのみ。 |
| セキュリティコード | 任意（セキュリティコード欄を表示する設定では登録時に必須扱い） | 4桁 | 空 | 自社保存なし。決済代行への認証補助に使い、画面・ログ・設計書に値を出さない。半角数字のみ。 |
| 生月日 | 任意（生月日欄を表示する設定では登録時に必須扱い） | 4桁固定（MMDD） | 空 | 自社保存なし。決済代行への認証補助に使う。半角数字のみ。 |
| 電話番号下4桁 | 任意（電話番号欄を表示する設定では登録時に必須扱い） | 4桁固定 | 空 | 自社保存なし。決済代行への認証補助に使う。半角数字のみ。 |
| トークン | 任意（登録時は値あり、削除時は削除を表す固定文字列） | — | 空 | 自社保存なし。隠し欄。値があれば会員枠へ登録、削除指示なら会員枠を無効化する。 |

カード番号・セキュリティコードの最大長はフォーム定義の確認値（カード番号16桁、セキュリティコード4桁）とする。各欄の表示有無はプラグイン設定の認証補助項目とセキュリティコード利用有無で決まる。登録時の実質必須はクライアント側チェックで担保し、サーバ側フォーム定義では各入力欄は任意（NotBlankなし、桁・形式のみ）である。

### エッジケース

| ケース | 扱い |
|--------|------|
| 登録済みカードがある状態で新しいカードを登録 | 会員枠のカード変更として差し替える。会員枠が無効状態なら無効解除後に変更し、失敗時は会員枠を無効化する。 |
| 会員枠が決済代行側で削除済み | 会員枠を新規作成してカードを登録する。 |
| 会員照会が例外で失敗（表示時） | 登録済みカード無しとして表示を続ける。 |
| トークンが空のまま送信 | カード登録を行わずカード編集画面へ戻る。 |
| 削除指示のトークンで送信 | フォーム検証を待たずに会員枠の無効化を実行する。 |
| 画面表示のカード番号 | 末尾4桁以外を伏字にしたマスク表示のみを出す。原番号は画面に出さない。 |

## データ整合性

| 観点 | 内容 |
|------|------|
| 表示の参照時点 | 登録状況は画面表示時の会員照会で決済代行から取得した値である。表示後に決済代行側で状態が変わっても、表示中の内容は自動更新しない。 |
| 自社側の保持範囲 | 自社側は会員と会員枠を対応づける識別子（会員IDと枝番、更新日時）のみを保持する。カード番号・有効期限・名義・トークンは保持しない。 |
| カード明細の正 | 登録済みカードの番号・有効期限などの明細は決済代行側を正とする。自社側はマスク表示のために照会結果を一時的に使うだけである。 |
| 削除後の整合性 | 削除は会員枠の無効化として行い、成功時に自社側の枝番を進める。決済代行側の無効化と自社側の枝番更新は別操作のため、いずれかが失敗した場合の整合は処理結果のエラー扱いに従う。 |

---

## API/バッチ結果

| 種類 | 内容 |
|------|------|
| API | 本機能は決済代行へHTTPで会員照会・会員登録・会員変更・会員無効化のリクエストを送る。入力は会員枠識別子とトークン等、実行条件は会員ログインとカード会員登録の有効設定である。成功時は応答コードが正常を示し、画面へ結果を反映する。失敗時は応答コードに応じた業務エラーとして扱い、フラッシュとログに記録する。通信自体が失敗した場合は通信エラーとして扱う。 |
| バッチ | 本機能はバッチを起動しない。 |
| 再実行 | 登録・削除は会員が画面から再操作できる。再操作時は再度会員照会を行い、その時点の登録状況に応じて分岐する。 |

決済代行の接続先・暗号鍵・電文項目の具体値は本書では扱わない。

## 画面遷移

| 条件 | 遷移先 |
|------|--------|
| カード編集画面を開く（完全認証済み） | 同一画面にカード状況と入力フォームを表示。 |
| 未ログイン・簡易認証のみで開く | マイページ入口。 |
| カード会員登録が無効な設定で開く | 未検出（HTTP404）。 |
| カード登録・差し替えを送信 | カード編集画面へ戻る（リダイレクト）。 |
| カード削除を送信 | カード編集画面へ戻る（リダイレクト）。 |
| 業務エラー・通信エラー | カード編集画面へ戻る（リダイレクト）。 |

|------|--------------|------------------|
| 登録・削除の送信 | 処理結果のフラッシュをカード用の領域へ積む。 | カード編集画面でフラッシュを1度表示し、最新の登録状況を再照会して表示する。 |

## エラー処理

利用者向けの表示文言は「表示メッセージ」を正とする。本節は処理方針を記載する。

| エラー内容 | 処理 |
|------------|------|
| 完全認証済みでない | カード編集画面を表示せずマイページ入口へ遷移する。 |
| カード会員登録が無効な設定 | 未検出（HTTP404）として扱う。 |
| フォーム検証の失敗 | カード登録を行わず、検証不備のフラッシュを積んでカード編集画面へ戻す。 |
| 決済代行との業務エラー | エラー内容のフラッシュを積み、決済通知ログとエラーログへ記録する。システムエラー区分のときは管理者宛にエラーメールを送る。カード編集画面へ戻す。 |
| 通信などの想定外エラー | 通信エラーのフラッシュを積み、サーバログへ記録してカード編集画面へ戻す。 |
| 表示時の会員照会失敗 | 登録済みカード無しとして表示を続ける。 |

## 試行制限

本機能では試行制限を扱わない。連続操作の抑止は、画面側の二重送信防止と決済代行側の制御に委ねる。

## ログ・監査

| タイミング | 記録内容 |
|------------|----------|
| 決済代行とのやり取り | カード操作の通知ログを記録する。送信データのうちカード番号は末尾4桁以外を伏字にし、有効期限・会員枠パスワードは伏字にして記録する。 |
| 業務エラー発生時 | エラー名・概要をエラーログへ記録し、システムエラー区分のときは管理者宛にエラーメールを送る。 |
| 想定外エラー発生時 | 例外概要をサーバログへ記録する。 |

### ログに出してはいけないもの

- カード原番号（記録は末尾4桁のマスク表示のみ）
- カード有効期限の原値
- セキュリティコード
- カードトークンの原値
- 会員枠パスワードに相当する値の原値
- 決済代行の接続情報・暗号鍵
- Cookie値・セッションIDの完全値

## セッション

### 本機能におけるセッション

| 観点 | 内容 |
|------|------|
| 操作結果の受け渡し | 登録・削除・検証不備・エラーの結果文言を、カード用のフラッシュ領域へ一時的に積む。カード編集画面で1度表示して消える。 |
| 会員認証 | 会員のログイン状態はフロントの会員認証基盤が保持する。本機能はその完全認証状態を参照するだけで、認証用のセッションを直接更新しない。 |

### セッションへ保存しない情報

カード番号・有効期限・セキュリティコード・トークン・会員枠パスワードはセッションへ保存しない。

## Cookie

本機能はカード編集のために新たなCookieを設定しない。会員ログイン状態の保持に用いるCookieはフロントの会員認証基盤の管理範囲とし、本書では扱わない。

---

## 排他制御・トランザクション

本機能は楽観ロック・悲観ロックの対象を持たない。

- カード登録・差し替え・削除は決済代行への会員枠操作が主処理で、自社側は会員枠識別子の枝番更新のみを行う。
- 決済代行側の操作と自社側の枝番更新は別操作のため、いずれかが失敗した場合の整合は処理結果のエラー扱いに従う。
- 同一会員が複数画面から同時に操作する場合の競合制御は、この機能では扱わない。
