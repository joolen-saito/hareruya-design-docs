# m09-08_admin_content_content_cache（管理画面_コンテンツ管理_キャッシュ管理）

管理画面のコンテンツ管理にあるキャッシュ管理画面で、管理者がボタン操作によりアプリケーションのキャッシュを削除する機能。

## 概要

キャッシュ管理は、本番環境にTwigファイルなどを差し替えた際に画面表示へ反映させるため、管理者がボタン押下でアプリケーションのキャッシュを削除できるようにする機能である。削除はSymfonyのキャッシュ全体を対象とし、レスポンス送出後に実行する。

本機能のカスタマイズ区分は標準であり、挙動・DB関連ともに ec-cube-enterprise の実装を正とする。本機能はアプリケーションキャッシュの削除のみを行い、業務テーブルへ保存しないため、DBスキーマを持たない。

本書は実装手順ではなく、誰が・いつ・どの条件で・結果どうなるかを読むためのリバース詳細設計とする。既存実装のふるまい、削除されるキャッシュの範囲、メンテナンスモードとの関係、表示メッセージ、副作用を確認し、仕様の確からしさを把握することを目的とする。

対象はブラウザ経由の管理画面のキャッシュ管理画面である。

管理画面プレフィックスは環境により変わるため、本書では`%eccube_admin_route%`で表す。値は`eccube.yaml`の`eccube_admin_route`（環境変数`ECCUBE_ADMIN_ROUTE`由来）で決まる。bind名やSymfonyのルートnameの網羅は本文では扱わず、必要な照合値は「調査補助」に隔離する。

| 観点 | 現行（pf-eccube3） | 移行先（ec-cube-enterprise） |
|------|--------------------|------------------------------|

| 用語 | 説明 |
|------|------|
| キャッシュ削除 | 本画面のボタン押下で起動する、アプリケーションキャッシュの一括削除。実体はレスポンス送出後にキャッシュ削除コマンドを実行する処理である。 |

## 処理フロー

### キャッシュ管理画面の表示

1. 管理者がキャッシュ管理画面を開く。
2. システムは空のフォーム（なりすまし対策トークンのみ）を生成し、説明文と削除ボタンを表示する。
3. この時点ではキャッシュ削除を行わない。

### キャッシュ削除ボタン押下

1. 利用者がキャッシュ削除ボタンを押下し、同一URLへPOSTする。
2. システムはなりすまし対策トークンを検証する。送信が妥当でない場合はキャッシュ削除を行わず画面を再表示する。
3. メンテナンスモード許可設定が有効な場合、自動メンテナンスモードへ切り替える。無効な場合は切り替えない。
4. キャッシュ削除を予約する。この時点では削除コマンドを実行せず、レスポンス送出後に実行する予約だけを行う。
5. メンテナンスモード許可設定が有効な場合、メンテナンス解除フラグのフラッシュを登録する。
6. 削除完了のフラッシュメッセージを登録し、同一画面を再表示する。
7. レスポンス送出が完了した後、予約に従いキャッシュ削除コマンドを実行する。あわせてopcache・APC・WinCacheのユーザーキャッシュをリセットする。
8. メンテナンスモード許可設定が有効な場合、再表示された画面のJSがメンテナンス解除エンドポイントへ非同期POSTし、自動メンテナンスモードを解除する。

## 業務ルール・計算

| 項目 | 内容 |
|------|------|
| 削除対象 | Symfonyのキャッシュ削除コマンドにより、アプリケーションキャッシュ全体を削除する。コマンドはキャッシュのウォームアップを伴わない指定で実行する。 |
| 追加のリセット | キャッシュ削除コマンドの実行に続けて、opcache・APCユーザーキャッシュ・APCキャッシュ・WinCacheユーザーキャッシュを、それぞれの関数が利用可能な環境でのみリセットする。 |
| 実行タイミング | ボタン押下時は削除を予約するだけで、実際の削除はレスポンス送出後のカーネル終了処理で実行する。画面再表示の応答自体は削除完了を待たずに返る。 |
| メンテナンス連動 | メンテナンスモード許可設定が有効な場合に限り、削除前に自動メンテナンスモードへ切り替え、削除完了画面の表示後にJSの非同期要求で解除する。設定が無効な場合はメンテナンスモードを操作しない。 |
| 計算 | 本機能では集計・金額計算・丸めなどの業務計算を行わない。 |

本画面は利用者が値を入力して保存・更新するフォーム項目を持たないため、入力項目の表は扱わない。送信はなりすまし対策トークンを伴うボタン操作のみである。

### エッジケース

| ケース | 扱い |
|--------|------|
| なりすまし対策トークンが不正・欠落 | キャッシュ削除を予約せず、メンテナンスモードも操作しない。削除完了のフラッシュも登録せず画面を再表示する。 |
| メンテナンスモード許可設定が無効 | メンテナンスモードへの切り替え・解除を行わず、キャッシュ削除のみ予約する。解除用JSも動作しない。 |
| opcache等の拡張が無効な環境 | 利用できないリセット関数は呼ばず、キャッシュ削除コマンドの実行のみ行う。 |
| 連続してボタンを押下 | 押下のたびに削除を予約し、各レスポンス送出後に削除コマンドを実行する。 |

## API/バッチ結果

| 種類 | 内容 |
|------|------|
| API | 本機能は外部APIを呼び出さない。メンテナンス解除エンドポイントへの非同期POSTは同一アプリケーション内の管理側エンドポイントへの要求である。 |
| バッチ | 本機能は定期バッチを起動しない。キャッシュ削除はレスポンス送出後のカーネル終了処理で、キャッシュ削除コマンドを内部実行する形で行う。 |
| 成功時の扱い | キャッシュ削除コマンドの実行結果は画面に反映しない。利用者には押下直後に削除完了のフラッシュを表示する。削除コマンドの出力は画面へ返さない。 |
| 失敗時の扱い | 削除はレスポンス送出後に実行するため、削除コマンドが失敗しても利用者画面には削除完了のフラッシュが既に表示された状態となる。本画面は削除コマンドの成否を判定して画面へ通知しない。失敗時の例外処理はアプリケーションの共通処理に委ねる。 |
| 再実行時の扱い | 再度ボタンを押下すれば再びキャッシュ削除を予約し、レスポンス送出後に削除コマンドを実行する。 |

## 排他制御・トランザクション

本機能はキャッシュ削除であり、業務テーブルに対する楽観ロック・悲観ロックの対象を持たない。同時に複数の管理者が削除を実行しても、業務データのロックを取り合う要件は持たない。メンテナンスモードの切り替えはデータベーストランザクションではなくファイル操作で行う。
