# A01-01（スマレジ連携処理）

## 業務ロジック

### 連携の目的

スマレジの在庫が変動するタイミングで、EC-CUBEとスマレジをスマレジプラットフォームAPIを介して連携させる。トリガーとなるポイントに合わせて、APIやWebhookを活用して連携させる。

### 3つの連携方式

在庫におけるスマレジとの連携は、大きく分けて次の3方式とする。

| 方式 | 向き | 使う場面 |
| --- | --- | --- |
| 1: Webhook | スマレジ → EC-CUBE | スマレジ側で在庫変動があった場合。取引完了、取引キャンセル（全キャンセル） |
| 2: API個別 | EC-CUBE → スマレジ | CSV登録等の一括処理ではない管理画面操作で、スマレジ側の在庫変動が発生した場合 |
| 3: Patch一括 | EC-CUBE → スマレジ | CSV登録等の一括処理で、スマレジ側の在庫変動が発生した場合 |

### 操作ごとの連携方式

| 操作場所 | 機能名 | 方式 | 概要 |
| --- | --- | --- | --- |
| スマレジ | スマレジで取引完了時 | 1: Webhook | スマレジで受注した結果による在庫変動結果をWebhookで受信し、スマレジ在庫数を減らす |
| スマレジ | スマレジで取引全キャンセル | 1: Webhook | スマレジでの受注が全キャンセルされた結果をWebhookで受信し、スマレジ在庫数を戻す |
| 管理画面 | 在庫編集 | 2: API個別 | 在庫場所区分がスマレジの場合に編集結果をスマレジ側に反映する。実行できる件数上限を設定し、上限を越えたらエラーを表示してCSV登録を促す |
| 管理画面 | 在庫一括編集 | 2: API個別 | 在庫場所区分がスマレジの場合に編集結果をスマレジ側に反映する。実行できる件数上限を設定し、上限を越えたらエラーを表示してCSV登録を促す |
| 管理画面 | 在庫変更CSV登録 | 3: Patch一括 | 在庫区分がスマレジの場合に編集結果をスマレジ側に反映する |
| 管理画面 | 在庫移動指示 | 2 または 3 | スマレジ在庫に入庫する場合、その移動指示結果を入庫済みになったタイミングで反映する |
| 管理画面 | 在庫移動指示 | 2 または 3 | スマレジ在庫から出庫する場合、その移動指示結果を出庫承認済みになったタイミングで反映する |
| 管理画面 | 分割結合（分割） | 2 または 3 | スマレジ在庫から分割するために、福袋やオリパを出庫にする |
| 管理画面 | 分割結合（分割） | 2 または 3 | スマレジ在庫に福袋やオリパを分割した結果を入庫する |
| 管理画面 | 分割結合（結合） | 2 または 3 | スマレジの在庫から福袋やオリパを作るための商品を出庫する |
| 管理画面 | 分割結合（結合） | 2 または 3 | スマレジの在庫に結合した福袋やオリパを入庫する |
| 管理画面 | 棚卸し | 3: Patch一括 | スマレジの在庫を棚卸した場合、結果をスマレジ側に反映する |

「2 または 3」の操作は、上限件数を閾値にして方式を決める。閾値を越えたらPatch一括処理、越えなかったらAPI個別とする。

### スマレジからの受信（Webhook方式）

スマレジで取引完了もしくは取引全キャンセルが発生したことを契機に、Webhookが発動する。

1. スマレジがスマレジ在庫変動履歴IDをEC-CUBEへ送信する。
2. EC-CUBEが在庫変動履歴IDで取引詳細を要求する。
3. スマレジが在庫変動履歴情報を返す。

在庫変動履歴情報のIDは商品と店舗の組合せでしかまとめて取得できないため、取引商品種類数分だけ取得の要求を繰り返す。EC-CUBE側の処理は非同期で実行する。

### EC-CUBEからスマレジへの反映

管理画面操作による在庫変更では、EC-CUBEが在庫相対値更新でスマレジの在庫を更新し、スマレジがAPIのレスポンスを返す。

管理画面操作による在庫変更CSV登録では、EC-CUBEが在庫一括相対値更新でデータを登録し、スマレジが処理結果をURLに返す。

### 受信した在庫変更履歴の反映

取得したスマレジ在庫変更履歴情報をもとに、EC-CUBE上のスマレジ在庫情報を更新する。

- 在庫区分が 02: 売上のときは出庫処理、12: 返品のときは入庫処理を実施する。
- 情報更新処理を実施するのは在庫区分が 02: 売上と 12: 返品のときだけで、それ以外の在庫区分は無視する。
- 店頭受取分の商品IDの場合、スマレジ側の在庫は変動しないので無視する。
- スマレジの在庫変動履歴IDは、EC-CUBE側の在庫変動履歴に紐づけて保存する。在庫変動履歴の登録そのものは「在庫変動時の履歴作成について」を正とする。

### レート制限

スマレジ側のレート制限（スロットリング）は秒間50回が上限になるが、理論上1秒間にレジ25台（在庫・受注処理で2回として仮定）が同時決済するところまで対応可能である。レート制限を超えた場合もエラーレスポンスで待機時間が返ってくるので、リトライ処理が可能である。

### 開始条件と終了条件

| 種類 | 内容 |
| --- | --- |
| 開始条件 | API呼び出しを受け付け、認証（IP制限）を通過する |
| 終了条件 | レスポンスを返し、必要なデータ更新または非同期処理の投入が完了する |

### 例外の扱い

| 区分 | 扱い |
| --- | --- |
| 入力不備 | APIリクエスト本文が不正な場合はエラーとして処理し、登録・更新対象を確定しない |
| 対象なし | 対象IDに該当するデータがない場合はエラーレスポンスとして扱う |
| 状態不整合 | 既に処理済み、キャンセル済み、承認不可、在庫不足など状態条件に合わない場合は処理対象外またはエラーとする |
| 外部連携失敗 | スマレジ等の外部連携で失敗した場合は、再連携・エラーログ・エラーメール・ステータス更新の対象とする |

## 入出力

| 種類 | 内容 |
| --- | --- |
| 入力 | 外部システムまたはMTGバイヤーからのAPIリクエスト |
| 成功時出力 | ステータスコードのみを返す（レスポンス本文は持たない） |
| 失敗時出力 | エラーを表す応答を返す。更新が必要な処理では不整合が残らないように扱う |

### 入出力: 接続仕様

| 項目 | 内容 |
| --- | --- |
| エンドポイントURL | `/smaregi/stocks` |
| プロトコル | HTTP |
| メソッド | POST |
| 認証の有無 | 有 |
| 認証方式 | IP制限 |
| リクエスト書式 | JSON |
| レスポンス書式 | なし（ステータスコードのみ） |

### 入出力: Webhook受信データ

| 項目名 | 型 | 必須 | 入力例 | 備考 |
| --- | --- | --- | --- | --- |
| 契約ID | String | 〇 | — | スマレジの契約ID |
| イベント名 | String | 〇 | pos:stock | 取引のイベント名固定 [pos:transactions] |
| アクション | String | 〇 | edited | edited: 更新、bulk-update: 一括更新 |
| 在庫変動履歴IDリスト | int[] | 〇 | — | 在庫変更履歴ID・商品ID・店舗IDの3つの情報のセットを1配列データとした配列リスト |

データサンプル上の名称は、契約IDが contractId、イベント名が event、アクションが action、在庫変動履歴IDリストが ids で、配列の要素は id・productId・storeId の3値を持つ。

### 入出力: 永続化

受信したWebhookは、契約ID・スマレジイベントID・イベント・アクション・リクエストヘッダー・リクエストボディ・受信日時とともに受信履歴として記録し、処理の開始日時・完了日時・ステータスを更新する。

在庫処理では、API対象の在庫・買取およびスマレジ連携対象のデータを作成・更新・参照する。あわせて、CSV取込履歴・在庫履歴・ステータス履歴・API受信履歴を必要に応じて作成・更新する。

## 表示メッセージ

本機能は画面を持たず、応答はステータスコードのみのため、画面に表示するメッセージを持たない。
