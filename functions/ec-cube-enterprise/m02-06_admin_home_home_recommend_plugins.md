# m02-06_admin_home_home_recommend_plugins（管理画面_トップおすすめプラグイン）

管理画面ホームに表示される、おすすめプラグイン一覧、プラグイン詳細モーダル、オーナーズストアへの導線。

## 概要

管理画面ホームのおすすめプラグインは、管理者がダッシュボード上でオーナーズストア上の推奨プラグインを確認し、詳細確認、無料プラグインのインストール確認、有料プラグイン購入、オーナーズストア検索へ進めるようにする機能である。

本書は実装手順ではなく、誰が・いつ・どの条件で・結果どうなるかを読むためのリバース詳細設計とする。
既存実装のふるまい、外部 API から取得するデータ、表示条件、失敗時の扱い、副作用、拡張による差し替え可能性を確認し、仕様の確からしさを把握することを目的とする。

対象はブラウザ経由の管理画面ホームの「おすすめのプラグイン」ブロックである。プラグイン検索画面、認証キー設定、インストール確認以降の Composer 実行、プラグイン有効化・無効化・削除は別機能として切り離す。

本書では Symfony の route 名、URL パス、Controller 構成は扱わない。
代わりに、ホーム画面表示、プラグイン詳細表示、インストール確認・購入・オーナーズストア検索への遷移といった利用者視点の入口ごとに期待されるふるまいを記載する。

本機能のカスタマイズ区分は標準であり、挙動・画面とも移行先のec-cube-enterpriseの実装を正とする。DB関連の記述（テーブル名・列名）もec-cube-enterpriseを正とする。

---

## 本書で扱うこと

- ホーム画面表示時に、おすすめプラグイン一覧をどの外部連携から取得し、どの情報を画面に表示するか
- 取得したプラグインごとに、インストール済み・アップデートあり・購入が必要といった状態をどの条件で判定するか
- プラグイン名または画像を押下したときに詳細モーダルを表示し、モーダル内でどの導線を出し分けるか
- おすすめ一覧の取得に失敗した場合、ホーム画面表示を継続し、プラグイン行を表示しないこと
- 本ブロックに固有の DB 更新、キャッシュ更新、専用の業務監査ログが無いことの明示

## リニューアル移行時の扱い

本機能はカスタマイズ区分が標準であり、リニューアル後はec-cube-enterpriseの標準実装を正とする。挙動・画面・DBスキーマとも移行先のec-cube-enterpriseに基づいて記述しており、現行（pf-eccube3）独自の差分は本書では仕様確定しない。

本書のDBカラム節で参照するテーブル・列（`dtb_base_info`の`authentication_key`、`dtb_plugin`の`source`・`version`）は、いずれもec-cube-enterpriseのエンティティ定義で実在を確認した名称である。外部プラグインAPI通信に用いる認証キーは`authentication_key`、インストール済み判定の突き合わせ元は`source`、アップデート判定の比較値は`version`であり、いずれも移行先の列名と一致する。現行リポと移行先でスキーマが食い違う列は本機能の参照範囲には見当たらないため、移行先の名称をそのまま正とする。確認できない差分が生じた場合は推測でスキーマを補わず、ec-cube-enterprise実装で要確認とする。

## 処理フロー

### ホーム画面表示・おすすめ一覧取得

1. 管理者がホーム画面にアクセスしたとする。
2. システムは受注状況、売上状況、ショップ状況を組み立て、ホーム表示組み立て完了時の拡張イベントを発火する。
3. 拡張イベントの後に、おすすめプラグイン一覧を外部のプラグイン API から取得する。
4. 外部 API へは、プラグイン認証キー、現在のサイト URL、EC-CUBE バージョンをヘッダとして送信する。認証キー原値は本書では扱わない。
5. 外部 API のレスポンスを配列として読み込み、各プラグインにインストール状態と対応バージョン判定を付与する。
6. 取得・加工に成功した場合、テンプレートへおすすめプラグイン配列を渡す。
7. 外部 API 通信またはレスポンス処理でプラグイン API 例外が発生した場合、例外はホーム表示処理内で握りつぶし、テンプレートへ空配列を渡す。
8. テンプレートは配列内の各プラグインを一覧表示し、プラグインごとの詳細モーダルを出力する。

### インストール状態の付与

1. システムはローカルに登録済みのプラグインを全件取得する。
2. 各おすすめプラグインの状態を、初期値として「未インストール・未購入扱い」にする。
3. ローカルプラグインの取得元 ID が外部 API のプラグイン ID と一致する場合、「インストール済み」にする。
4. インストール済みで、ローカルのバージョンが外部 API のバージョンより古い場合、「アップデートあり」にする。
5. 外部 API 上で未購入かつ購入が必要なプラグインの場合、「未購入の有料プラグイン」にする。この判定はインストール済み・アップデートあり判定の後に評価され、条件に一致した場合は表示状態を上書きする。
6. 現在の EC-CUBE バージョンが外部 API の対応バージョン一覧に含まれるかを判定し、詳細モーダルの警告表示に使う。

### 詳細モーダル表示

1. 利用者がプラグイン画像または名称を押下する。
2. ブラウザは対象プラグイン ID に対応する詳細モーダルを同一画面上で開く。
3. モーダルには API 取得値とインストール状態に基づく詳細情報、警告、導線を表示する。
4. 利用者が閉じるボタンまたはキャンセルボタンを押下すると、モーダルを閉じてホーム画面へ戻る。サーバ通信は発生しない。

### インストール確認・購入・外部 URL への導線

1. 無料または入手可能な未インストールプラグインの場合、モーダルの主導線としてインストール確認へのリンクを表示する。
2. インストール済みで更新が不要なプラグインの場合、モーダルの主導線は「インストール済み」の状態表示になる。
3. インストール済みで外部 API 上のバージョンが新しいプラグインの場合、モーダルの主導線としてアップデート確認へのリンクを表示する。
4. 未購入の有料プラグインの場合、モーダルの主導線として外部ストア購入用フォームの送信ボタンを表示する。フォームはプラグイン ID と公開鍵を送信し、外部ストアを別ウィンドウで開く。
5. 問い合わせ URL またはマニュアル URL がある場合、モーダル内に外部リンクを表示する。押下時は別ウィンドウで開く。

## 集計条件

本機能では DB レコードの件数集計を行わない。
ただし、おすすめプラグイン配列の各要素に対して、ローカル登録済みプラグイン全件との突き合わせを行い、表示状態を算出する。

| 指標 | 集計の要点 |
|------|------------|
| おすすめプラグイン件数 | 外部 API が返した配列件数をそのまま表示対象件数とする。ホーム画面側で件数表示は行わない。 |
| ローカルプラグイン突き合わせ | ローカルの登録済みプラグイン全件を取得し、外部 API のプラグイン ID とローカルの取得元 ID が一致するかをプラグインごとに確認する。 |

## インストール状態判定順序

| 順序 | 判定 | 結果 |
|------|------|------|
| 1 | 外部 API から取得したプラグインを処理対象にする | 初期状態を「未インストール・未購入扱い」にする。 |
| 2 | ローカル登録済みプラグインの取得元 ID が外部 API のプラグイン ID と一致する | 「インストール済み」にする。 |
| 3 | 手順 2 に一致し、ローカルのバージョンが外部 API のバージョンより古い | 「アップデートあり」にする。 |
| 4 | 外部 API 上で未購入、かつ購入が必要である | 「未購入の有料プラグイン」にする。 |
| 5 | 現在の EC-CUBE バージョンが対象プラグインの対応バージョン一覧に含まれる | 対応バージョン警告を表示しない。 |
| 6 | 現在の EC-CUBE バージョンが対象プラグインの対応バージョン一覧に含まれない | 詳細モーダル内に非対応の警告を表示する。 |

画面上の主導線はインストール状態に応じて変わる。未インストール・未購入扱いでは「入手する」、インストール済みでは「インストール済み」、アップデートありでは「アップデート」、未購入の有料プラグインでは「購入する」を表示する。

## 業務ルール・計算

| 項目 | 内容 |
|------|------|
| 外部 API の取得先 | 設定値で定義されたプラグイン API の基底 URL に、おすすめ取得用のエンドポイントを連結して取得する。実 URL は環境値を確認値とし、本書では仕様固定しない。 |
| 送信ヘッダ | プラグイン認証キー、現在のサイト URL、EC-CUBE バージョンを送信する。認証キーの原値は表示・記録しない。 |
| 通信タイムアウト | 外部 API 通信にはタイムアウトが設定されている。タイムアウトまたは HTTP 200 以外はプラグイン API 例外として扱う。 |
| レスポンスの扱い | 外部 API から返却された JSON を配列として扱い、ホーム画面側では推薦順や絞り込みを変更しない。 |
| バージョン比較 | ローカルプラグインのバージョンが外部 API のバージョンより小さい場合、アップデートありと判定する。 |
| 対応バージョン | 現在の EC-CUBE バージョンが、外部 API 取得値の対応バージョン一覧に含まれるかで判定する。 |
| 価格表示 | モーダルでは価格を税込表記として表示する。無料プラグインではダウンロード数も表示する。 |

### エッジケース

| ケース | 扱い |
|--------|------|
| 外部 API が空配列を返す | おすすめプラグイン行は表示しない。カード下部のオーナーズストアリンクは表示する。 |
| 外部 API 通信に失敗する | ホーム画面表示を継続し、おすすめプラグイン行は表示しない。本カード内にエラー文言は表示しない。 |
| HTTP ステータスが 200 ではない | プラグイン API 例外として扱い、ホーム画面では空配列表示にフォールバックする。 |
| ローカルプラグインが 0 件 | すべてのおすすめプラグインは、購入要否判定を除き、未インストール・未購入扱いから判定する。 |
| 同じ取得元 ID のローカルプラグインが複数ある | 実装上は全件を走査し、一致したものに基づき状態を上書きする。重複登録時の正規化や一意制約は本機能では扱わない。 |
| 未購入かつ購入が必要なプラグインが、ローカル取得元 ID とも一致する | 購入要否判定が後段で評価されるため、表示状態は「購入する」側に上書きされる。 |
| 対応バージョン一覧に現在バージョンが含まれない | 一覧行は表示する。詳細モーダルに非対応警告を表示する。 |
| 問い合わせ URL またはマニュアル URL が空 | 該当する外部リンクボタンは表示しない。 |
| プラグイン画像が空 | 一覧の画像は API 取得値をそのまま参照する。詳細モーダルでは代替画像を表示する。 |

## データ整合性

| 観点 | 内容 |
|------|------|
| 参照時点 | おすすめプラグイン一覧はホーム画面表示時に外部 API から取得した結果である。表示後に外部ストア側の推薦内容やローカルプラグイン状態が変わっても、表示中の内容は自動更新しない。 |
| 外部 API との整合性 | 推薦対象、並び順、価格、説明、対応バージョンは外部 API の返却値を正とする。ホーム画面側では返却値の内容を業務的に補正しない。 |
| ローカルプラグインとの整合性 | インストール状態は、ホーム画面表示時点のローカル登録済みプラグインと外部 API 取得値の突き合わせ結果である。インストール確認以降で状態が変わった場合、次回ホーム表示までカード内表示は更新しない。 |
| 一覧と詳細の整合性 | 一覧行と詳細モーダルは同じ API 取得配列から同一 HTML 内に出力する。同一表示内では、対象プラグインの名称・説明・画像・状態は同じ取得値に基づく。 |
| 更新との整合性 | 本ブロック自体はプラグインのインストール、購入、アップデート、DB 更新を実行しない。各導線の遷移後の整合性は、オーナーズストア検索・インストール確認・購入機能の設計を正とする。 |

## API/バッチ結果

| 種類 | 内容 |
|------|------|
| API | ホーム画面表示時に外部プラグイン API へおすすめ一覧取得の GET 通信を行う。入力は認証キー、サイト URL、EC-CUBE バージョンを含むヘッダであり、クエリ条件は付与しない。成功時はおすすめプラグイン配列を取得し、表示用状態を付与する。 |
| API 失敗時 | 通信失敗、HTTP 200 以外、実行結果 false はプラグイン API 例外として扱う。ホーム画面では例外を捕捉し、空配列として表示を継続する。 |
| バッチ | 本ブロックはバッチを起動しない。外部 API やローカルプラグイン情報が別処理で更新済みの場合、次回のホーム画面表示時にその時点の値を読む。 |
| 再実行 | ホーム画面を再表示すると、外部 API への取得処理も再度実行する。カード内に手動更新ボタンはない。 |

| 成功時出力 | おすすめプラグインカード、プラグイン行、詳細モーダル、状態別の導線。 |
| 失敗時出力 | 外部 API 取得失敗時は、おすすめプラグイン行を表示しない。ホーム画面全体の表示は継続する。本カード専用のエラーメッセージは出さない。 |
| 副作用 | ホーム画面表示のみでは DB を更新しない。外部 API へサイト情報と認証キーを含む通信を行い、通信情報をログへ出力する。購入導線では外部ストアへのフォーム送信が発生する。 |

## DBカラム

当機能に直接関係する列のみを以下に列挙する。型や一覧の細部はスキーマを参照する。

| テーブル | 列 | メモ |
|----------|-----|------|
| dtb_base_info | authentication_key | 外部プラグイン API 通信と購入フォーム送信で用いる認証キー。原値は設計書に記載しない。 |
| dtb_plugin | source | 外部 API のプラグイン ID と突き合わせ、インストール済み判定に用いる。 |
| dtb_plugin | version | 外部 API のプラグインバージョンと比較し、アップデートあり判定に用いる。 |

### DB操作

本機能は参照系（検索）であり、DBへの登録・更新・削除は行わない。テーブル名は ec-cube-enterprise を正典とする。

| 操作種別 | 対象テーブル | 契機・条件 |
|---------|--------------|------------|
| 検索 | dtb_base_info / dtb_plugin | 検索条件に合致するレコードを抽出する。 |

## 画面遷移

| 条件 | 遷移先 |
|------|--------|
| ホーム画面を開く | 同一画面内におすすめプラグインカードを表示する。 |
| プラグイン画像または名称を押下 | 同一画面上で詳細モーダルを開く。画面遷移は発生しない。 |
| 詳細モーダルで「入手する」または「アップデート」を押下 | 管理画面内のインストール確認へ遷移する。 |
| 詳細モーダルで「購入する」を押下 | 外部ストアの購入導線を別ウィンドウで開く。 |
| 詳細モーダルで問い合わせ・マニュアルリンクを押下 | 外部 URL を別ウィンドウで開く。 |
| 詳細モーダルでキャンセルまたは閉じるを押下 | ホーム画面上でモーダルを閉じる。 |
| カード下部の「オーナーズストア」を押下 | 管理画面内のオーナーズストア検索へ遷移する。 |

各遷移後の検索条件、インストール確認、購入、Composer 実行、フラッシュメッセージ、状態更新は、それぞれ遷移先機能の範囲とする。

## エラー処理

| エラー内容 | 処理 |
|------------|------|
| 外部 API 通信失敗 | ホーム画面表示処理内で例外を捕捉し、おすすめプラグイン配列を空にする。本カード内にエラー文言は表示しない。 |
| HTTP 200 以外または通信結果 false | プラグイン API 例外として扱い、ホーム画面では空配列表示にフォールバックする。 |
| レスポンス項目欠落 | 本カード側に専用の欠落時フォールバックは定義しない。テンプレートまたは共通例外処理の実装結果を確認値とする。 |
| インストール確認遷移先での API 失敗 | 遷移先機能のエラー処理に委ねる。本カードでは仕様確定しない。 |
| 購入先での失敗 | 外部ストアおよび購入機能の範囲とし、本カードでは仕様確定しない。 |

## 試行制限

本機能では試行制限を扱わない。ホーム画面を再表示するたびに、おすすめ一覧取得の外部 API 通信を実行する。

## ログ・監査

| タイミング | 記録内容 |
|------------|----------|
| 外部 API 通信後 | HTTP 通信情報をアプリケーションログに出力する。 |
| おすすめプラグインカードの表示のみ | 本ブロック単体では業務監査ログを追加で書く処理は持たない。 |
| インストール確認・購入・検索への遷移後 | 遷移先画面の操作・実行ログは各機能の範囲とする。 |

### ログに出してはいけないもの

- プラグイン認証キーの原値
- セッション識別子の完全値
- CSRF トークンや Cookie の原値
- 外部ストア購入フォームに含まれる公開鍵の具体値

本機能の設計書では、認証キーや公開鍵の具体値を例示しない。

## セッション

本機能はおすすめプラグインカードの表示、詳細モーダル表示、オーナーズストアリンク押下のためだけに専用セッションを更新しない。
カード下部のオーナーズストア検索へ遷移した後の検索条件セッションは、オーナーズストア検索機能の範囲とする。

---

## Cookie

本機能はおすすめプラグインカードの表示のためだけに新たな Cookie を設定しない。ブラウザのセッション Cookie はフレームワークおよび管理画面全体の認証に用いられる。

---

## 排他制御・トランザクション

本ブロックのホーム画面表示は参照と外部 API 通信のみであり、業務トランザクションを張ってプラグインや基本情報を更新しない。
同時に複数の管理者がホームを開いても、本ブロック内でロックを取り合う要件は持たない。
