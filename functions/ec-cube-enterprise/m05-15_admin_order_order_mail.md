# 受注管理 — 受注詳細メール通知

受注詳細画面から1件の受注に対し、メールテンプレートを選んで件名・本文を編集し、確認画面を経て注文者へメールを送信する機能。送信内容は送信履歴として記録する。

## 概要

管理画面の受注編集画面から派生するメール通知は、対象の受注1件について、注文者宛に任意のタイミングでメールを送信するための機能である。利用者はテンプレートを選択して件名・本文の初期値を読み込み、件名と本文を編集し、確認画面で内容を見たうえで送信する。送信が完了すると受注編集画面へ戻り、送信内容を送信履歴として残す。

本書は実装手順ではなく、誰が・いつ・どの条件で・結果どうなるかを読むためのリバース詳細設計とする。既存実装のふるまい、参照するデータ、判定境界、副作用、拡張による差し替え可能性を確認し、仕様の確からしさを把握することを目的とする。

対象はブラウザ経由の管理画面で、受注編集画面のメール送信履歴ブロックから「メールを作成」で開く、受注1件分のメール通知画面である。

管理画面プレフィックスは環境により変わるため、本書では `%eccube_admin_route%` で示す。プレフィックスは設定値 `eccube_admin_route` により決まり、ルート定義のパスへ展開される。具体値はその環境の設定を確認値とする。本書の本文ではルート名の網羅やコントローラのメソッド解剖は扱わず、「利用者視点の入口」に HTTP メソッドとサイトルートからのパスパターンを実装確認値として書く。

本機能のカスタマイズ区分は標準であり、挙動・画面およびDB（永続化先のテーブル・列）はともに ec-cube-enterprise の実装を正とする。

---

## 本書で扱うこと

- 受注編集画面から受注1件分のメール通知画面を開いたときの初期表示と入力項目
- メールテンプレートを選択したとき（モード `change`）に件名と本文の初期値を読み込み直すふるまい
- 件名・本文を編集して確認画面へ進むとき（モード `confirm`）のふるまいと確認画面の表示
- 送信実行（モード `complete`）でのメール送信、送信履歴の記録、受注編集画面への遷移
- 入力項目の必須・任意、本文の Twig 構文検証、選択テンプレートの本文が見つからない場合の扱い
- 送信メールの宛先・差出人・BCC・返信先・件名の組み立て元、利用者向けの画面メッセージ
- 本機能が受注ステータスや在庫など他の台帳を更新しないこと

---

## 本書で扱わないこと

以下は本書では仕様確定せず、実装または別機能の設計を正とする。

- 受注詳細から開く一括手動メール送信、受注一覧からの一括メール送信（M05-06 系）。配送IDを起点に複数受注へ送る経路は別機能とする。
- 自動送信メールの設定・テンプレート編集（受注ステータス変更時などに自動で送るメールの管理）
- メールテンプレートマスタ自体の登録・編集・削除（本機能では既存テンプレートを選択するのみ）
- 受注編集画面本体の入力項目・保存処理、受注ステータス変更
- 管理画面ログイン・認可・IP制限・CSRFトークンの仕様の詳細（名称・値の環境依存を含む）
- メール配送基盤（メーラー・トランスポート）の送達保証、再送、バウンス処理
- 受注編集画面のメール送信履歴ブロックでの過去メール閲覧モーダルの表示仕様（履歴を記録する側のみ扱う）

---

## リニューアル移行時の扱い

本機能は標準機能のため、現行と移行先（ec-cube-enterprise）で固有のスキーマ差分は生じない。永続化先のメールテンプレート（`dtb_mail_template`）・メール送信履歴（`dtb_mail_history`）・受注（`dtb_order`）は ec-cube-enterprise のスキーマを正とし、同一スキーマとして扱う。送信履歴の受注参照（`dtb_mail_history.order_id`）・宛先会員参照（`dtb_mail_history.customer_id`）・店舗基本情報参照（`dtb_mail_history.base_info_id`）も ec-cube-enterprise の定義に従う。現行実装との差異が判明した場合は ec-cube-enterprise 実装を正とする。

## 用語

| 用語 | 説明 |
|------|------|
| 受注 | 注文1件。`dtb_order` の1行に対応し、注文者の氏名・住所・メールアドレス・購入商品・対応状況などを持つ。 |
| メールテンプレート | 件名と本文テンプレート（Twigファイル名）を持つマスタ。`dtb_mail_template` に保持される。本機能では選択のみ行う。 |
| 本文（テンプレート本文） | テンプレートの Twig ファイルを当該受注で描画した文字列。編集領域に初期表示され、利用者が編集できる。 |
| 送信履歴 | 送信したメールの件名・本文・送信日時・宛先会員・受注を記録した行。`dtb_mail_history` に保持され、受注編集画面の「メール送信履歴」に一覧表示される。 |
| 確認画面 | 件名・本文を編集不可で再表示し、送信前に内容を確認させる画面。 |
| モード | 同一URLへのPOSTで処理を分岐させる隠しパラメータ。テンプレート変更（`change`）・確認（`confirm`）・送信（`complete`）・戻る（`back`、明示処理なし）を取る。 |

## 利用者視点の入口

| 入口 | URLエンドポイント | 期待されるふるまい |
|------|--------------------|--------------------|
| 受注編集画面のメール送信履歴ブロックで「メールを作成」を押す | `GET /%eccube_admin_route%/order/{id}/mail` | 当該受注1件分のメール通知画面が開く。送信先情報と空のメール入力欄を表示する。テンプレート未選択のため件名・本文は初期状態とする。 |
| テンプレート選択を変更する | `POST /%eccube_admin_route%/order/{id}/mail`（モード `change`、選択イベントで自動送信） | 選択テンプレートの件名と、当該受注で描画した本文を入力欄へ読み込み直し、同一画面を再表示する。本文の描画元が見つからない場合はエラーメッセージを表示する。 |
| 「送信内容を確認」を押す | `POST /%eccube_admin_route%/order/{id}/mail`（モード `confirm`） | 入力検証に成功すれば、件名・本文を編集不可で再表示する確認画面へ進む。失敗すれば編集画面に留まり項目エラーを表示する。 |
| 確認画面で「送信」を押す | `POST /%eccube_admin_route%/order/{id}/mail`（モード `complete`） | 注文者へメールを送信し、送信内容を送信履歴に記録し、成功メッセージを積んで受注編集画面へ遷移する。 |
| 確認画面で「メール通知」リンク（戻る）を押す | `POST /%eccube_admin_route%/order/{id}/mail`（モード `back`） | 明示的な分岐処理は無く、編集画面の初期描画に戻る。 |
| 編集画面で「受注登録」リンクを押す | `GET /%eccube_admin_route%/order/{id}/edit` | メールを送信せず受注編集画面へ戻る。 |
| 未ログインまたは権限・IP制限で拒否される利用者 | 上記パス（到達前） | 管理画面の共通ルールに従いアクセスできない（詳細は管理画面認証・認可の実装を正とする）。 |

## 処理フロー

### メール通知画面を開く（GET）

1. 管理画面の認証・権限・IP制限の各ルールを通過する。
2. URLの受注識別子で受注1件を取得する。取得できない場合はアクセスできない（受注は必須パラメータとして解決される）。
3. 当該受注に紐づく送信履歴を取得する。
4. メール入力フォームを組み立て、初期化イベントをディスパッチする（プラグイン等がフォームへ差し込める）。
5. テンプレート未選択・件名空・本文空の編集画面を描画する。

### テンプレートを選択し件名・本文を読み込む（POST、モード `change`）

1. フォームをリクエストで処理する。
2. テンプレート選択フィールドが妥当な場合のみ進む。
3. 選択テンプレートのファイル名を本文テンプレートとする。ファイル名が無い場合は既定の受注メールテンプレートを用いる。
4. 当該受注を渡して本文テンプレートを描画し、本文の初期値を作る。描画元が見つからない場合はエラーメッセージを積み、本文は空のままとする（後述「表示メッセージ」）。
5. フォームを再生成し、テンプレート変更イベントをディスパッチする。
6. 件名フィールドに選択テンプレートの件名をセットし、本文フィールドに描画結果をセットして編集画面を再描画する。

### 送信内容を確認する（POST、モード `confirm`）

1. フォームをリクエストで処理する。
2. 送信済みかつ検証成功であれば、件名・本文を編集不可（freeze）にしたフォームを再構築する。
3. 件名・本文を確認用に表示する確認画面を描画する。本文は改行を反映して表示する。
4. 検証失敗時は確認画面へ進まず、編集画面に留まり項目エラーを表示する。

### 送信する（POST、モード `complete`）

1. フォームをリクエストで処理する。
2. 送信済みかつ検証成功であれば、フォームデータと本文を取り出す。
3. 件名・本文を用いて注文者宛にメールを送信する（宛先・差出人等は後述「業務ルール・計算」を参照）。
4. 送信したメールの件名・本文・送信日時・宛先会員・受注を送信履歴として保存する。
5. 送信完了イベントをディスパッチする。
6. 成功メッセージを積み、受注編集画面へリダイレクトする。

### 戻る・その他のモード（POST、モード `back` ほか）

1. テンプレート変更・確認・送信のいずれにも該当しないモードでは、分岐処理を行わない。
2. 現在のフォーム状態で編集画面を再描画する。

## 業務ルール・計算

| 項目 | 内容 |
|------|------|
| 対象受注 | URLの受注識別子で解決した1件のみ。複数受注・配送単位の束ねは行わない。 |
| テンプレート選択の効果 | 選択時に件名・本文の初期値を読み込み直す。選択は本文・件名の永続化を伴わず、入力欄への反映のみ。 |
| 本文テンプレートの決定 | 選択テンプレートのファイル名を用いる。ファイル名が無い場合は既定の受注メールテンプレートを用いる。 |
| 件名の初期値 | 選択テンプレートの件名を件名欄へ反映する。 |
| 送信件名の組み立て | 送信時の実際の件名は「[ショップ名] 入力件名」の形に組み立てる。ショップ名は店舗基本情報から取る。 |
| 送信先（宛先） | 当該受注のメールアドレス宛に送る。 |
| 差出人・BCC・返信先・Return-Path | 差出人は店舗基本情報の送信元アドレスとショップ名。BCC は店舗基本情報の送信元アドレス。返信先・Return-Path は店舗基本情報の該当アドレス。 |
| 本文の扱い | 編集後の本文をプレーンテキスト本文として送る。本機能はHTML本文を組み立てない。 |
| 受注台帳への影響 | 本機能は受注ステータス・在庫・金額などを更新しない。送信履歴の追加のみを副作用とする。 |

### 入力項目

| 項目名 | 必須／任意 | 最大長 | 初期値 | 保存先・扱い |
|--------|------------|--------|--------|----------------|
| テンプレート | 任意 | — | 未選択（プレースホルダ「選択してください」） | フォームキー `template`。`dtb_mail_template` から識別子昇順で選択肢を構成。エンティティにはマップせず、件名・本文初期値の読み込みにのみ使う。選択変更でモード `change` を自動送信する。 |
| 件名 | 必須 | フォーム上限なし（DBは255文字。送信時に「[ショップ名] 」が前置される） | 空。テンプレート選択時に当該テンプレートの件名を反映。 | フォームキー `mail_subject`。空不可の検証。送信時に組み立てた件名で送信し、`dtb_mail_history.mail_subject` に記録。 |
| 本文 | 任意（構文検証あり） | フォーム上限なし（描画結果の長さに依存） | 空。テンプレート選択時に当該受注で描画した本文を反映。 | フォームキー `tpl_data`（複数行入力。画面はaceエディタ表示）。エンティティにはマップしない。Twig構文検証を行う。送信本文として用い、`dtb_mail_history.mail_body` に記録。 |

件名の255文字はメール送信履歴・テンプレートの該当列のスキーマ長を確認値とする。フォーム側に明示的な最大長制約は持たない。本文はテンプレート描画結果を初期値とし、利用者が編集できる。

### エッジケース

| ケース | 扱い |
|--------|------|
| テンプレート未選択のまま件名・本文を直接入力して確認・送信 | テンプレートは任意のため、件名が入力済みで本文の構文が妥当なら確認・送信できる。 |
| テンプレートのファイル名が空 | 既定の受注メールテンプレートで本文を描画する。 |
| 本文テンプレートのファイルが見つからない | エラーメッセージを表示し、本文は空のまま編集画面を再描画する。 |
| 本文に不正な Twig 構文 | 構文検証でエラーとなり、確認・送信に進めない。 |
| 件名が空 | 必須検証でエラーとなり、確認・送信に進めない。 |
| 受注にメールアドレスが無い | 送信処理は当該受注のメールアドレスを宛先とする。アドレスが空の場合の送達可否はメール基盤の範囲とする。 |
| 送信履歴の宛先会員 | 送信履歴には当該受注の会員を関連付ける。会員に紐づかない受注（ゲスト購入等）では会員参照が空となり得る。 |

---

## データ整合性

| 観点 | 内容 |
|------|------|
| 送信内容と送信履歴 | 送信履歴には、実際に送信したメールの件名（ショップ名前置を含む組み立て後）と本文を記録する。画面入力そのままではなく送信メッセージの値を保存する。 |
| 送信履歴と受注編集画面 | 送信完了後に受注編集画面へ戻ると、送信履歴ブロックへ当該履歴が一覧表示される。表示順・件名リンクのモーダル表示は受注編集画面側の実装を正とする。 |
| テンプレート選択と保存 | テンプレート選択は件名・本文の初期化に使うだけで、テンプレートマスタやその選択状態を更新しない。 |
| 受注データの参照時点 | 送信先情報・本文の差し込み値は、画面表示・送信の各時点で受注から読み取った値である。表示後に受注が更新されても表示中の値は自動更新しない。 |

---

本機能ではAPI呼び出し・バッチ実行を扱わない。メール送信はアプリケーション内のメール送信処理を直接呼び出す。

### DB操作

| 操作種別 | 対象テーブル | 契機・条件 |
|---------|--------------|------------|
| 登録/更新 | dtb_mail_history / dtb_mail_template / dtb_order | 当機能が行う登録・更新で対象テーブルを直接保存する（不要な削除は含まない）。確定は persist/flush による即時反映。DB=ec-cube-enterprise を正典とする。 |

## 画面遷移

| 条件 | 遷移先 |
|------|--------|
| 受注編集画面で「メールを作成」を選択 | メール通知の編集画面 |
| 編集画面でテンプレートを変更 | 同一編集画面（件名・本文を読み込み直して再表示） |
| 編集画面で「送信内容を確認」が検証成功 | メール通知の確認画面 |
| 編集画面で検証失敗 | 同一編集画面（項目エラー表示） |
| 確認画面で「メール通知」（戻る） | メール通知の編集画面 |
| 確認画面で「送信」が成功 | 受注編集画面 |
| 編集画面で「受注登録」リンク | 受注編集画面（メール送信なし） |

### 遷移時に引き継ぐ状態

| 起点 | 遷移前の処理 | 遷移後の初期状態 |
|------|--------------|------------------|
| 送信成功 | 送信履歴を追加し、成功フラッシュをフラッシュバッグへ格納する。 | 受注編集画面で成功メッセージが一度表示され、送信履歴ブロックに当該履歴が並ぶ。 |

---

## エラー処理

| エラー内容 | 処理 |
|------------|------|
| 件名未入力・本文の Twig 構文不正 | 同一編集画面を再表示し、項目ごとのエラーを表示する。確認・送信へ進まない（文言は「表示メッセージ」を正とする）。 |
| 本文テンプレートの読み込み失敗 | エラーメッセージを積み、本文を空のまま編集画面を再描画する。 |
| 本文描画時のその他例外 | 画面には出さず、警告ログのみ記録する。本文は空となる。 |
| メーラーの送達失敗 | 致命ログを記録する。画面上は成功扱いで受注編集画面へ遷移する。 |
| 受注識別子が存在しない | 受注が解決できずアクセスできない。専用の利用者向け文言は本機能では持たない。 |

## ログ・監査

| タイミング | 記録内容 |
|------------|----------|
| 送信開始時 | 受注管理通知メール送信開始の情報ログ。 |
| 送信完了時 | 受注管理通知メール送信完了の情報ログ。 |
| 本文テンプレート読み込み失敗時 | 警告ログ（例外メッセージ）。 |
| メーラー送達失敗時 | 致命ログ（例外メッセージ）。 |
| 送信成功時（業務記録） | 送信履歴に件名・本文・送信日時・宛先会員・受注・店舗基本情報を記録する。 |

### ログに出してはいけないもの

- パスワード
- CSRFトークンやそれに類する秘密値
- Cookie値
- セッションIDの完全値

送信履歴には件名・本文・宛先会員が残るため、本書ではメール本文・個人情報の具体値を例示しない。

## セッション

### 本機能におけるセッション

| 観点 | 内容 |
|------|------|
| 成功メッセージ | 送信成功後の受注編集画面で一度表示するためにフラッシュバッグへ格納する。 |

## Cookie

本機能単体で特有のCookieは定義しない。セッションCookieは管理画面全体の実装を正とする。

## 排他制御・トランザクション

本機能のメール送信・送信履歴記録は、当該受注を版本管理する楽観ロックを持たない。送信履歴は新規行の追加であり、既存受注を更新しないため、同一受注に対する複数管理者の同時送信は、それぞれ独立した送信・履歴行として処理される。
