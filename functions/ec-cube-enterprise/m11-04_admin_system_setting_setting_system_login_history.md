# m11-04_admin_system_setting_setting_system_login_history（管理画面_ログイン履歴）

管理画面システム情報設定配下のログイン履歴一覧で、管理画面ログインの試行記録を検索・閲覧する機能。

## 概要

ログイン履歴は、管理画面へのログイン試行で記録された行を、ログインID・IPアドレス・ログイン試行日時・成功失敗区分とともに一覧で閲覧し、期間や成功失敗などの条件で絞り込むための参照機能である。記録の発生源は認証処理側であり、本機能はその記録を読み取って表示する。

本書は実装手順ではなく、誰が・いつ・どの条件で・結果どうなるかを読むためのリバース詳細設計とする。
既存実装のふるまい、参照するデータ、検索条件、表示列、副作用を確認し、仕様の確からしさを把握することを目的とする。

本機能のカスタマイズ区分は標準であり、挙動・DB関連ともにリニューアル後（ec-cube-enterprise）の標準実装を正とする。

対象はブラウザ経由の管理画面のログイン履歴一覧である。履歴を生成する認証成功・失敗の判定そのものは別機能とし、本書では確認できる範囲で記録の発生源を整理する。

管理画面プレフィックスは環境変数`ECCUBE_ADMIN_ROUTE`を`eccube.yaml`の`eccube_admin_route`へ束ねた値で決まる。本書では`%eccube_admin_route%`で示し、ホスト名やクエリを含む具体URLは書かない。Symfonyのルートname、Controllerの構成は本文の主題としない。

- キーワード検索と詳細検索の各条件が、どの列にどう作用するか
- 一覧の表示列（ID・ログインID・IPアドレス・ログイン試行日時・成功失敗区分）
- 検索条件・ページ番号・表示件数がセッションへ保存され、再表示時に引き継がれること
- 成功失敗区分の値と画面表示の対応
- 履歴行を生む操作が認証成功・認証失敗であることの整理（記録の確定は別機能）

以下は本書では仕様確定せず、実装または別機能の設計を正とする。

- 管理画面の認証・認可の共通基盤、左ナビゲーション全体の構成

- マルチテナント・店舗文脈による参照範囲の絞り込み詳細（永続化層の共通規則を正とする）

## リニューアル移行時の扱い

- 本機能のカスタマイズ区分は標準であり、リニューアル後（ec-cube-enterprise）の標準実装を挙動・DBともに正とする。
- ログイン履歴は ec-cube-enterprise の標準テーブル `dtb_login_history` と区分マスタ `mtb_login_history_status` に保存する。`dtb_login_history` はテナント文脈を表す `base_info_id` 列を含む標準スキーマである。
- 区分マスタの保存値は失敗が0、成功が1で、ec-cube-enterprise の標準初期データと同一とする。
- 現行（pf-eccube3／EC-CUBE3系）に相当する一覧画面・テーブル構成との差がある場合は、移行時に ec-cube-enterprise の標準スキーマへ揃える。現行との具体差は ec-cube-enterprise 実装を正として移行設計で確認する。

## 処理フロー

### 一覧表示

1. 利用者がログイン履歴一覧を開く。
2. 表示件数はセッションキー`eccube.admin.login_history.search.page_count`から取得し、未保存ならアプリ既定の表示件数を用いる。リクエストに有効な`page_count`があり、かつ表示件数マスタに一致する場合はその値を採用し、同セッションキーへ保存する。
3. ページ番号付きURLまたは`resume`での再表示では、保存済みの検索条件`eccube.admin.login_history.search`と保存済みページ番号を読み出して絞り込む。
4. ページ番号も再表示指定もない初回表示では、検索条件を空にしてセッションへ保存し、1ページ目を全件対象で表示する。
5. 絞り込み結果を作成日時の降順、同一日時内はID降順で並べ、ページ送りして一覧表に表示する。

### 検索実行

1. 利用者が検索条件を入力して検索ボタンを押す。
2. 入力値の検証に成功した場合、検索条件をセッション`eccube.admin.login_history.search`へ保存し、ページ番号を1へ初期化してセッションへ保存する。
3. 保存した条件で絞り込み、1ページ目を表示する。検索結果件数を画面に表示する。
4. 入力値の検証に失敗した場合は一覧を出さず、詳細検索ブロックを開いた状態で再描画し、条件の見直しを促す表示にする。この場合は検索条件をセッションへ保存しない。

### ページ送り・表示件数変更

1. ページャのリンクまたは表示件数プルダウンで遷移する。
2. ページ番号はURLの値をセッション`eccube.admin.login_history.search.page_no`へ保存する。表示件数は前述の判定でセッションへ保存する。
3. 保存済みの検索条件のまま、指定ページ・指定件数で一覧を表示する。

## 集計条件

| 指標 | 集計の要点 |
|------|------------|
| 一覧対象 | `dtb_login_history`の全行を基点に、検索条件で絞り込む。成功・失敗の双方を含む。 |

| 項目 | 内容 |

| 並び順 | ログイン試行日時の降順、同一日時内はID降順。 |

### 入力項目

| 項目名 | 必須／任意 | 最大長 | 初期値 | 保存先・扱い |
|--------|------------|--------|--------|----------------|
| ログインID・IPアドレス | 任意 | 255文字 | 空 | 検索フォームのキー`multi`。スペース除去後の値で`dtb_login_history.user_name`または`client_ip`に部分一致。永続化はしない。`eccube_stext_len`（255）でLength検証。 |
| ログインID | 任意 | 255文字 | 空 | 検索フォームのキー`user_name`。`dtb_login_history.user_name`に部分一致。永続化はしない。`eccube_stext_len`（255）でLength検証。 |
| IPアドレス | 任意 | 255文字 | 空 | 検索フォームのキー`client_ip`。`dtb_login_history.client_ip`に部分一致。永続化はしない。`eccube_stext_len`（255）でLength検証。 |
| ログイン試行日(開始) | 任意 | 日時 | 空 | 検索フォームのキー`create_datetime_start`。`dtb_login_history.create_date`の下限（以上）。単一テキストの日時ピッカー。下限`0003-01-01`の範囲検証。 |
| ログイン試行日(終了) | 任意 | 日時 | 空 | 検索フォームのキー`create_datetime_end`。`dtb_login_history.create_date`の上限（未満）。単一テキストの日時ピッカー。下限`0003-01-01`の範囲検証。 |
| ステータス | 任意 | — | 全解除 | 検索フォームのキー`Status`。複数選択チェックボックス。選択した区分（失敗0／成功1）のいずれかに一致で絞り込む。 |

最大長の255は`eccube.yaml`の`eccube_stext_len`の確認値であり、環境で上書きされる場合はその値に従う。期間欄はカレンダー付き日時入力であり、文字数ではなく日時値として扱う。

### エッジケース

| ケース | 扱い |
|--------|------|
| 検索条件をすべて空で検索 | 全件を対象に並び順で表示する。 |
| キーワードに前後・途中のスペースを含む | スペースを除去した連結文字列で部分一致する。 |
| ステータスを未チェック | 区分での絞り込みをせず、成功・失敗の双方を表示する。 |
| 期間の終了のみ指定 | ログイン試行日時が終了指定値より前の行を対象とする。 |
| 期間の開始のみ指定 | ログイン試行日時が開始指定値以上の行を対象とする。 |
| 検索結果が0件 | 一覧表を出さず、0件メッセージを表示する。 |
| 表示件数に不正値を渡す | 表示件数マスタに一致しないため採用せず、保存済みまたは既定の件数で表示する。 |
| 管理者削除済みの履歴行 | 履歴行のログインID・IPアドレス・区分は保持されるため一覧に表示する。管理者参照は削除時にNULLとなる。 |

## データ整合性

| 観点 | 内容 |
|------|------|
| 参照時点 | 一覧は表示要求時点で`dtb_login_history`から読み取った行である。表示後に新たな試行が記録されても表示中の一覧は自動更新しない。 |
| 記録との整合性 | 表示する履歴は認証処理側が記録した行であり、本機能は更新しない。記録の有無・内容は認証機能の設計を正とする。 |
| 失敗履歴の保存失敗 | 失敗履歴の書き込みに失敗した場合は履歴行が作られず、認証機能側でサーバログに記録される。本機能はその場合に該当行を表示しない。 |
| 表示列との整合性 | 一覧の各列は履歴行の保存値をそのまま表示する。ログインIDは試行時の入力文字列であり、現在の管理者レコードのログインIDと一致するとは限らない。 |
| 件数との整合性 | 検索結果件数はページネーション部品が数えた総件数であり、表示中ページの行数とは別である。 |

| 成功時出力 | 検索条件に一致する履歴行を、ID・ログインID・IPアドレス・ログイン試行日時・成功失敗区分の列でページ表示する。 |
| 失敗時出力 | 検索条件の検証失敗時は一覧を出さず、詳細検索を開いた状態で見直しメッセージを表示する。 |
| 副作用 | 検索条件・ページ番号・表示件数のセッション保存のみ。台帳・履歴の更新はしない。 |

## 画面遷移

| 条件 | 遷移先 |
|------|--------|
| 一覧を開く | 同一画面にログイン履歴一覧を表示。 |
| 検索ボタンを押下 | 同一画面に1ページ目の検索結果を表示。 |
| ページャを押下 | 同一画面に指定ページの結果を表示。 |
| 表示件数プルダウンを変更 | 同一画面に1ページ目を指定件数で表示。 |
| 検証エラー | 同一画面に詳細検索を開いた状態で見直しメッセージを表示。 |

### 遷移時に引き継ぐ状態

| 起点 | 遷移前の処理 | 遷移後の初期状態 |
|------|--------------|------------------|
| 検索実行 | 検証成功時に検索条件をセッションへ保存し、ページ番号を1へ初期化して保存する。 | 保存条件の1ページ目を表示する。 |
| ページ送り | URLのページ番号をセッションへ保存する。 | 保存済み検索条件のまま指定ページを表示する。 |
| 表示件数変更 | マスタに一致する件数をセッションへ保存する。 | 保存条件の1ページ目を指定件数で表示する。 |
| 前回条件で再表示 | セッションの検索条件・ページ番号を読み出す。 | 保存済み条件・ページで一覧を再表示する。 |

## エラー処理

利用者向けの表示文言は「表示メッセージ」を正とする。本節は処理方針のみを記載する。

| エラー内容 | 処理 |
|------------|------|
| 検索条件の検証失敗 | 一覧を出さず、詳細検索を開いた状態で再描画する。検索条件はセッションへ保存しない。 |
| 検索結果0件 | 一覧表を出さず、0件メッセージを表示する。 |
| 表示件数の不正値 | 採用せず、保存済みまたは既定の件数で表示する。 |
| データ読み取りの障害 | アプリケーションの共通例外処理に委ねる。本機能専用の利用者向けメッセージは設けない。 |

## ログ・監査

| タイミング | 記録内容 |
|------------|----------|
| ログイン履歴一覧の表示・検索 | 本機能は参照であり、業務監査ログを追加で書く処理を持たない。 |
| 履歴行の生成（参考） | ログイン成功時は認証後リクエストの副作用として成功区分の履歴を記録する。ログイン失敗時は認証失敗イベントで失敗区分の履歴を記録する。いずれも認証機能側の処理であり、本機能の出力ではない。 |

履歴行は、管理画面のログイン試行という操作によって生まれる。成功はログイン確定処理、失敗は認証失敗時の記録であり、記録の確定仕様は認証機能の設計を正とする。

### ログに出してはいけないもの

- パスワード
- なりすまし対策トークン
- Cookie値
- セッションIDの完全値
- Remember Meトークンの原値

ログインIDとIPアドレスは履歴の表示項目として一覧に出すが、設計書では具体値を例示しない。

## セッション

### 本機能におけるセッション

| 観点 | 内容 |
|------|------|
| 検索実行時 | 検証成功時に`eccube.admin.login_history.search`へ検索条件を保存し、`eccube.admin.login_history.search.page_no`を1へ初期化して保存する。 |
| ページ送り時 | `eccube.admin.login_history.search.page_no`にURLのページ番号を保存する。 |
| 表示件数変更時 | `eccube.admin.login_history.search.page_count`にマスタ一致の件数を保存する。 |
| 初回・条件なし表示時 | 検索条件を空にして保存し、ページ番号を1にする。 |

キー名は現行実装の確認値であり、名称一致を確認する場合はソースコードを確認する。

### セッションへ保存しない情報

パスワード・Cookie値・秘匿値は保存しない。保存するのは検索条件・ページ番号・表示件数のみとする。

## 排他制御・トランザクション

本機能は一覧表示と検索のみの参照であり、業務データを更新しない。楽観ロック・悲観ロックの対象は持たない。複数の管理者が同時に一覧を開いても、ロックを取り合う要件はない。
