## 1. 低価格帯カード価格変更CSV登録

### 機能の目的と役割

CSVで指定された商品規格の基準価格、必要に応じて販売価格を更新する。

本機能のカスタマイズ区分は新規実装である。対応する現行実装が無いため、画面・項目・処理条件は基本設計仕様書（参照元 Excel）を正とし、DB関連の記述（テーブル名・列名・保存先）は ec-cube-enterprise を正とする。ec-cube-enterprise には基準価格変更CSV登録（標準価格取込）の同等実装があるため、保存先テーブル・列はその実装に合わせる。

### 入出力仕様

| 種類 | 内容 |
|------|------|
| 入力 | 管理画面の検索条件、フォーム入力、CSVアップロード、または画面操作。 |
| 出力 | 画面表示、CSV/PDFダウンロード、登録完了/エラー表示。 |
| 副作用 | 対象データの登録・更新、CSV取込履歴、在庫履歴、ステータス履歴の記録。 |

### 開始条件、終了条件

| 種類 | 内容 |
|------|------|
| 開始条件 | 管理画面にログイン済みの利用者が対象メニューまたは操作を実行する。 |
| 終了条件 | 画面表示、ファイル出力、登録完了、またはエラー表示が完了する。 |

### 判定条件

- Excel設計書に記載された対象条件、検索条件、CSV出力条件、登録条件を正とする。
- Excel設計書に未記載のURLエンドポイント、DBカラム、実処理順序は `../ec-cube-enterprise` の実装を正とする。
- 権限、ログイン状態、管理画面プレフィックスなどの共通判定は共通設計および実装側のセキュリティ設定に従う。

### プロセスフロー

1. 利用者または外部システムが対象機能を開始する。
2. 入力値、検索条件、アップロードファイル、またはリクエスト本文を受け付ける。
3. Excel設計書に定義された対象データを取得し、実装側の検証・権限・状態条件を適用する。
4. 登録・更新・出力・連携のいずれかの主処理を実行する。
5. 成功時は結果画面、CSV/PDF/APIレスポンス、またはバッチ結果を返す。失敗時はエラー内容を返し、更新が必要な処理では不整合が残らないように扱う。

### ビジネスロジック

- **Excel設計優先**: 仕様の目的、対象データ、出力項目、表示項目、業務上の条件は `excel_to_html/output` の設計書を正とする。
- **実装補完**: Excel設計に書かれていないURLエンドポイント、DBカラム、トランザクション、サービス分割、非同期処理は `../ec-cube-enterprise` の実装を正とする。
- **対象機能の要点**: 低価格帯カード価格変更をCSVで行えます。
- **実装確認値**: 実装側には同系統の高額商品価格変更CSV登録があり、低価格帯はExcelの基準価格変更CSVアップロード記載を正とする。

### 状態・データ更新

| 対象 | 内容 |
|------|------|
| 主データ | 管理画面の対象業務データを参照し、登録系では対象データと履歴を更新する。 |
| 履歴・ログ | 必要に応じてCSV取込履歴、在庫履歴、ステータス履歴、API受信履歴、アプリケーションログを作成・更新する。 |
| DB関連実装確認値 | dtb_product_class.standard_price, dtb_product_class.price02, dtb_csv_import_history.member_id |

### 例外処理

- **入力不備**: 必須項目、CSVヘッダ、CSV行、APIリクエスト本文、検索条件が不正な場合はエラーとして処理し、登録・更新対象を確定しない。
- **対象なし**: 検索条件や対象IDに該当するデータがない場合は、空の一覧、空CSV、またはエラーレスポンスとして扱う。扱いの細部は対象画面/API/バッチの実装に従う。
- **状態不整合**: 既に処理済み、キャンセル済み、承認不可、在庫不足など状態条件に合わない場合は処理対象外またはエラーとする。
- **外部連携失敗**: スマレジ等の外部連携で失敗した場合は、実装側の再連携・エラーログ・エラーメール・ステータス更新仕様を正とする。

### 関連設計への接続点

- 画面項目、CSV列、PDFレイアウト、APIリクエスト/レスポンスの詳細は、参照元Excel設計書の該当シートを正とする。
- URLエンドポイントとDBカラムは `../ec-cube-enterprise` の Controller Route、Entity、Repository、Migration、Service 実装を正とする。

## リニューアル移行時の扱い

- 本機能は新規実装であり、現行リポ（pf-eccube3）に対応画面が無い。基準価格変更の基本設計（参照元 Excel「基準価格変更CSVアップロード」）を正とする。
- 基準価格・販売価格の保存先: 移行先 ec-cube-enterprise では基準価格を dtb_product_class.standard_price、販売価格を dtb_product_class.price02 として規格テーブルで保持する。本書のDB関連の記述はこの統合後スキーマを正とする。
- 取込履歴: 取込履歴は dtb_csv_import_history に記録する（種別・ファイル名・作業者 member_id・日時）。ec-cube-enterprise の標準価格取込（基準価格）と同一スキーマである。
- 取込種別ID・専用取込経路: 低価格帯カード（基準価格変更）専用の取込種別ID・コントローラ・取込ハンドラは ec-cube-enterprise の取込種別マスタに固有定数として見当たらない。既存の標準価格取込（PRODUCT_STANDARD_PRICE_IMPORT_CSV_ID）を流用するか専用種別を追加するかは ec-cube-enterprise 実装で要確認とする。

### フェーズ2対応（フェーズ1では実装不要）

本書は現行実装からのリバースであり、以下は現行挙動として記述しているが、Excel基本設計がフェーズ2対応としている。フェーズ1では実装・テストの対象外とする。

- 低価格帯カード価格変更CSV（出力・登録）（※Excel基本設計 0204「低価格帯カード価格変更CSV（出力・登録）」はフェーズ2対応。フェーズ1では実装しない）。機能まるごとフェーズ2対応。Excel原文: 「Ph2で対応」（0204 低価格帯カード価格変更CSV出力）
