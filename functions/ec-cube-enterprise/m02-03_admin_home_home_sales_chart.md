# m02-03_admin_home_home_sales_chart（管理画面_トップ売上状況グラフ）

管理画面ホームに表示される、週間・月間・年間の売上金額推移を示す棒グラフ。

## 概要

管理画面ホームの売上状況グラフは、管理者がログイン後に最初に見るダッシュボード上で、受注台帳に基づく売上金額の推移を週間・月間・年間の3区間に分けて棒グラフで提示する機能である。グラフ用データはホーム画面表示後にブラウザから非同期で取得され、週間・月間・年間それぞれの canvas へ縦棒グラフとして描画される。週間・月間・年間はタブで切り替え、切替自体ではサーバへ再問い合わせしない。

本書は実装手順ではなく、誰が・いつ・どの条件で・結果どうなるかを読むためのリバース詳細設計とする。
既存実装のふるまい、参照するデータ、集計境界、描画方式、拡張による差し替え可能性を確認し、仕様の確からしさを把握することを目的とする。

対象はブラウザ経由の管理画面ホームの売上状況グラフである。今月・今日・昨日の売上サマリ数値、受注状況カード、ショップ状況、プラグイン案内、お知らせ iframe は別機能として切り離す。グラフと同じ受注集計の対象外ステータスや`payment_total`の扱いは売上サマリと共通であり、その既定集合・拡張差し替え・サマリとの関係は m02-02_admin_home_home_sales_status.md を正とし、本書では区間バケットとグラフ描画に限定して記載する。

管理画面プレフィックスは`eccube.yaml`の`eccube_admin_route`で決まり、本書ではURLエンドポイントを`%eccube_admin_route%`で示す。Symfonyのroute名、Controllerクラス名・メソッド名は本文の主説明にしない。

本機能のカスタマイズ区分は標準であり、挙動・画面とも移行先のec-cube-enterpriseの実装を正とする。DB関連の記述（テーブル名・列名・集計列）もec-cube-enterpriseを正とする。

- ホーム画面表示後にグラフ用データを非同期取得する契機と、取得結果をどの canvas へ対応づけるか
- 週間・月間・年間それぞれの集計区間の開始・終了境界とバケット単位

## 処理フロー

### ホーム画面表示・グラフ領域の初期描画

1. 管理者がホーム画面にアクセスしたとする。
2. サーバはホーム画面のHTMLを組み立て、売上状況カードに週間・月間・年間のタブと、各タブに対応する空のcanvas、読み込み中インジケータを出力する。この時点ではグラフは未描画である。
3. ページ読み込み完了後、ブラウザがグラフ用データを非同期で要求する。

### 売上グラフ用データの取得と変換

1. ブラウザがグラフ用データを非同期で要求する。要求はXMLHttpRequestであり、管理画面共通のAjax設定によりCSRFトークンが付与される。
2. サーバはXMLHttpRequestかつCSRFが妥当かを判定する。いずれかを満たさない場合はHTTP400で`{"status":"NG"}`を返し、以降の集計を行わない。
3. 条件を満たす場合、サーバは売上対象外ステータスを拡張フックで確定したうえで、次の三つの区間について確定後の売上集計対象の受注を読み取り、バケットに売上金額と件数を累積する。
   - 週間相当。当日0時から現在時刻までの区間。開始は当日から過去へ約一週間さかのぼった日とし、バケットキーは日単位（`Y/m/d`）である。
   - 月間相当。当月1日0時から現在時刻までの区間。バケットキーは日単位（`Y/m/d`）である。
   - 年間相当。現在時刻から過去へ約一年さかのぼった月の1日0時から現在時刻までの区間。バケットキーは年月単位（`Y/m`）である。
4. 各区間について、開始日から終了日まで1日ずつ進めながらバケットを初期化し、各バケットの売上金額と件数を0で用意する。年間区間ではバケットキーが年月単位のため、同一月内の各日が同一キーへ集約され、結果として月単位のバケットになる。
5. 範囲内の各受注を、その受注日をバケットキー書式へ変換して該当バケットへ加算する。売上金額はバケットの値へ加算し、件数はバケットの件数を1増やす。
6. 三つのバケット集合を週間・月間・年間の順に並べた配列をJSONで返す。

### 画面への描画

1. ブラウザは返却された配列を順に`chart-0`・`chart-1`・`chart-2`へ対応づける。
2. 各バケット集合について、キーを横軸ラベル、売上金額を縦棒の値とする棒グラフを生成する。件数はバケットに含まれるが、棒グラフの系列としては使わない。
3. 縦棒の系列ラベルは売上金額を示す文言とする。
4. 非同期取得が完了すると読み込み中インジケータを非表示にする。取得に失敗した場合も読み込み表示は消えるが、グラフは描画されない。

## 集計条件

| 指標 | 集計の要点 |
|------|------------|
| 週間グラフ | 当日から過去へ約一週間さかのぼった日0時から現在時刻までの`order_date`を持ち、売上対象外ステータスに含まれない受注を、日単位（`Y/m/d`）のバケットへ集計する。各日に売上金額と件数を累積し、画面では売上金額のみを棒グラフに使う。 |
| 月間グラフ | 当月1日0時から現在時刻までの`order_date`を持ち、売上対象外ステータスに含まれない受注を、日単位（`Y/m/d`）のバケットへ集計する。各日に売上金額と件数を累積し、画面では売上金額のみを棒グラフに使う。 |
| 年間グラフ | 現在時刻から過去へ約一年さかのぼった月の1日0時から現在時刻までの`order_date`を持ち、売上対象外ステータスに含まれない受注を、年月単位（`Y/m`）のバケットへ集計する。各月に売上金額と件数を累積し、画面では売上金額のみを棒グラフに使う。 |

各区間とも開始日時以上かつ終了日時以下の`order_date`を対象とし、両端を含む範囲条件で受注を読み取る。終了日時は取得処理開始時の現在時刻である。タイムゾーンは永続化層および実行環境の設定に従う。売上対象外ステータスの既定集合と拡張差し替えは m02-02_admin_home_home_sales_status.md を正とする。

## 業務ルール・計算

| 項目 | 内容 |
|------|------|
| グラフ系列 | 棒グラフの縦棒は売上金額のみを用いる。バケットの件数はJSONに含まれるが、グラフの系列としては使わない。 |
| 売上金額の累積 | バケット単位で、条件に一致する受注の`payment_total`を加算する。税、送料、値引、手数料の内訳は本グラフでは再計算しない。 |
| バケットの初期化 | 各区間について開始日から終了日まで1日ずつ進めてバケットキーを生成し、売上金額・件数を0で初期化する。これにより売上が無い期間も横軸ラベルとして残る。 |
| 年間の月集約 | 年間区間はバケットキーを年月（`Y/m`）で生成するため、日単位で進めても同一月の各日が同一キーへ集約される。結果として年間グラフは月単位の棒になる。 |
| 表示形式 | ツールチップと縦軸目盛りは通貨記号を前置し、3桁区切りのカンマを付す。縦軸目盛りは整数値のときのみラベルを表示する。横軸ラベルはバケットキー（週間・月間は`Y/m/d`、年間は`Y/m`）をそのまま用いる。 |

本グラフは入力フォームを持たないため、保存・更新に紐づく入力項目表は持たない。タブ切替は表示領域の切替のみであり、サーバへ送る入力値を生成しない。

### エッジケース

| ケース | 扱い |
|--------|------|
| 該当受注が0件 | 各区間のバケットはすべて0で埋まる。横軸ラベルは区間内の各日（年間は各月）が残り、棒の高さは0になる。 |
| 売上対象外ステータスの受注 | バケットへ加算しない。除外集合の確定は m02-02_admin_home_home_sales_status.md を正とする。 |
| `payment_total`が0の受注 | ステータスと期間条件に一致する場合、バケットの件数を1増やし、売上金額には0を加算する。棒グラフでは高さ0として扱う。 |
| 売上が無い日・月 | 0で初期化済みのバケットが残り、横軸ラベルが欠けない。 |
| 月末・月またぎ | 週間・月間は日単位のためバケットが日ごとに並ぶ。年間は年月単位のため、同一月内の受注が同一バケットへ集約される。 |
| 表示後に受注が更新された | 描画済みのグラフは自動更新しない。ホーム画面再表示時に再度非同期取得した結果に従う。 |
| グラフ用JSONに件数が含まれる | 棒グラフ描画では売上金額のみを使う。件数は当該グラフの表示系列として扱わない。 |

## データ整合性

| 観点 | 内容 |
|------|------|
| 参照時点 | グラフ用データはホーム画面表示後のAjaxで読み取った結果である。三つの区間は同一リクエスト内で順に集計され、終了境界はいずれも取得処理開始時の現在時刻に基づく。 |
| サマリとグラフ | 今月・今日・昨日の売上サマリはホーム画面HTML表示時に読み取り、グラフは別リクエストで読み取る。両者を同一トランザクションで固定せず、表示直後に受注が更新された場合は値が一致しないことがある。 |

| 更新との整合性 | 本グラフは参照のみであり、受注台帳やマスタを更新しない。受注更新との排他制御や再集計タイミングは各更新機能の設計を正とする。 |
| 外部連携との整合性 | 外部連携やバッチにより受注が更新される場合の反映タイミングは、外部連携機能またはバッチ機能の設計を正とする。本グラフは読み取り時点の永続化済みデータだけを読む。 |

| 副作用 | 本グラフの処理だけを見ると、受注台帳やマスタを更新しない。グラフ取得でもセッションを本グラフ専用に書き換えない。 |

## DBカラム

当機能に直接関係する列のみを以下に列挙する。型や一覧の細部はスキーマを参照する。

| テーブル | 列 | メモ |
|----------|-----|------|
| dtb_order | order_date | 期間フィルタおよびバケットキーへの変換元に用いる。タイムゾーン付き日時として保持される。 |
| dtb_order | payment_total | バケットの売上金額の累積に用いる。 |
| dtb_order | order_status_id | 受注ステータス。売上対象外リストとの照合に用いる。 |

### DB操作

永続化の正は ec-cube-enterprise（テーブル名・操作は ec-cube-enterprise を正典）。当ドメインは承認ワークフローを介さず persist/flush で直接確定する（承認ワークフローは在庫機能固有）。

| 操作種別 | 対象テーブル | 契機・条件 |
|---------|--------------|------------|
| 登録/更新 | dtb_order | 当機能が行う登録・更新で対象テーブルを直接保存する（不要な削除は含まない）。確定は persist/flush による即時反映。DB=ec-cube-enterprise を正典とする。 |

## バリデーション

| 項目 | 内容 |
|------|------|
| 利用者入力 | 本グラフはフォームを持たない。タブ切替は表示領域の切替のみで、サーバへ送る入力値を持たない。 |

## 権限・認可

| 利用者状態 | 売上状況グラフ |
|------------|----------------|
| 未認証 | 利用不可。管理領域の認証要件に従う。グラフ用データのAjaxにも到達できない。 |
| 管理者として認証済み | グラフ用データを取得・閲覧できる。 |
| より細かいロールで売上閲覧を制限する要件 | ホーム実装単体では個別の売上閲覧権限分岐を設けず、管理領域への到達可否に依存する。追加制御が必要な場合は別設計とする。 |

## 画面遷移

| 条件 | 遷移先 |
|------|--------|
| ホーム画面を開く | 同一画面内に売上状況グラフ領域を表示。 |
| 週間・月間・年間タブ操作 | 同一画面内のタブ表示切替。サーバへの追加遷移はない。 |
| グラフ取得成功 | 同一画面のまま、各canvasに棒グラフを描画。 |
| グラフ取得失敗 | 同一画面のまま。グラフ未描画。利用者向けメッセージは表示しない。 |

本グラフは画面遷移時に検索条件・セッション・フラッシュメッセージ等を引き継がない。タブ切替は別ウィンドウや非同期差し替えではなく、同一ページ内の表示切替として扱う。

## エラー処理

| エラー内容 | 処理 |
|------------|------|
| グラフ用AjaxがCSRFまたはXMLHttpRequest条件を満たさない | グラフデータを返さず、HTTP400でステータスNGのJSONを返す。フロントは失敗コールバックが実質空のため利用者向けメッセージは出さない。 |
| データベース読み取りの障害 | アプリケーションの共通例外処理に委ねる。本グラフ専用の利用者向けメッセージは設けない。 |
| 表示直後に台帳が変化 | 描画済みのグラフは同一瞬間のスナップショットではない。リアルタイムダッシュボードではない。 |

本グラフは利用者向けの画面メッセージを表示しない。読み込み中インジケータ以外に、正常・エラー・フラッシュの文言を生成しない。

本グラフは集計値のみを扱うため、設計書上も個別受注の内容を例示しない。

## Cookie

本機能はグラフ表示のためだけに新たなCookieを設定しない。ブラウザのセッションCookieはフレームワークおよび管理画面全体の認証に用いられる。

## 排他制御・トランザクション

本グラフのデータ生成は参照のみであり、業務トランザクションを張って受注を変更しない。受注台帳に対する楽観ロックや悲観ロックの対象ではない。
同時に複数の管理者がホームを開いても、ロックを取り合う要件は持たない。
