# m01-01_admin_login_login（管理画面_認証機能）

## 概要

管理画面ログインは、登録済みの管理者を本人確認し、管理画面を利用できる状態にする機能。

本機能のカスタマイズ区分は標準であり、挙動・DB関連ともec-cube-enterpriseを正とする。

本書は実装手順ではなく、誰が・いつ・どの条件で・結果どうなるかを読むためのリバース詳細設計とする。
既存実装のふるまい、状態、参照するデータ、判定境界、永続化、副作用を確認し、仕様の確からしさを把握することを目的とする。

対象はブラウザ経由の管理画面ログイン。

本書では Symfony の route 名、Controller 構成は扱わない。
URL エンドポイントは利用者視点の入口に限り、実装確認値として記載する。

## リニューアル移行時の扱い

本機能はリニューアル移行対象である。Cookie 名、セッションキー名、保存形式は現行実装の確認値として記録し、機能仕様として固定しない。

移行時に保証する対象は、名称ではなく次のふるまいである。

- 管理者ログイン状態をブラウザ単位で保持する。
- 未ログインで保護された管理画面へアクセスした場合、ログイン画面へ誘導する。
- 管理者としてログイン済みの場合、保護された管理画面を利用できる。
- 二段階認証が必要な管理者は、追加認証完了まで保護された管理画面を利用できない。
- 明示ログアウト時に管理者としての認証状態を終了する。
- Remember Me が有効な場合、保存済み情報により管理ログイン状態を再確立する。
- ログイン成功履歴と最終ログイン日時更新が実行される。

次の項目は現行実装の確認値として本書に記録する。名称一致を確認する場合は、設計書ではなくソースコードを確認する。

- Cookie 名
- セッションキー名
- セッション内の保存形式
- Remember Me トークンのサーバ側保存キー
- Cookie 値、セッション ID、Remember Me トークンの原値

| 用語 | 説明 |
|------|------|
| 管理者 | 管理メンバー。ログインにより管理画面への業務操作が許される主体。 |
| 管理セッション | 管理者として認証済みであることをブラウザに紐付けて保持する状態。 |

| Remember Me | Cookie とサーバ側の保存情報を用いて、一定期間ログイン状態を再確立する仕組み。 |
| 試行制限 | ログイン失敗などの条件により、一時的にログイン送信を拒否または遅延させる制御。 |

## 利用者視点の入口

| 入口 | URLエンドポイント | 期待されるふるまい |
|------|--------------------|--------------------|
| 管理ログイン画面 | `GET /%eccube_admin_route%/login` | 未ログイン時にログイン ID・パスワード入力画面を表示する。 |
| ログイン送信 | `POST /%eccube_admin_route%/login` | 入力値、CSRF、試行制限、管理者状態、パスワードを評価し、認証可否を判定する。 |
| 保護された管理画面 | `GET /%eccube_admin_route%/...` | 未ログインまたは追加認証未完了の場合、業務画面を表示せずログインまたは追加認証へ誘導する。 |
| ログアウト | `GET /%eccube_admin_route%/logout` | 管理セッションを終了し、ログイン画面へ戻す。 |
| Remember Me 再開 | `GET /%eccube_admin_route%/login` | Cookie とサーバ側情報により、管理ログイン画面でログイン状態を再確立する。 |

## 処理フロー

### ログイン画面表示

1. 利用者が管理ログイン URL にアクセスする。
2. 既に管理者としてログイン済みなら、ログイン画面を表示せずホーム画面へ遷移する。
3. 未ログインなら、ログイン ID・パスワード入力画面を表示する。
4. 未ログインで保護された管理 URL に来た場合も、ログイン画面へ誘導する。

### ログイン送信

1. 利用者がログイン ID・パスワードを送信する。
2. 入力不足、なりすまし対策トークン不整合、試行制限に該当する場合はログインを成立させず、ログイン画面でエラーまたは制限状態にする。ログイン送信は Symfony Security の `form_login` が受けるため、入力不足はログインフォームの `NotBlank` ではなく認証失敗として扱う。
3. ログイン ID から管理者を特定する。
4. 管理者が存在しない、停止中、ログイン不可の場合は認証エラーにする。
5. パスワードを照合する。
6. パスワード不一致の場合は認証エラーにする。
7. ID・パスワード認証が成功し、追加認証が不要な場合は、管理セッションを作成し、ホーム画面へ遷移する。
8. ID・パスワード認証が成功し、二段階認証が必要な場合は、業務画面へ入る前に追加認証へ誘導する。

### ログイン後

1. ログイン成功・失敗はログイン履歴に残る。
2. 成功時は最終ログイン日時も更新される。
3. Remember Me Cookie を持つ状態で管理画面へアクセスした場合は、管理ログイン画面へリダイレクトして認証状態を再確立する。
4. 無操作時間が設定値を超えた場合、自動ログアウト扱いとなり再ログインが必要になる。
5. 明示ログアウト時は管理セッションを終了し、ログイン画面へ戻る。

## ログイン送信時の判定順序

| 順序 | 判定 | 結果 |
|------|------|------|
| 1 | ログイン ID またはパスワードが未入力 | ログインを成立させず、ログイン画面に戻す。通常のフォームバリデーションではなく認証失敗として扱う。 |
| 2 | なりすまし対策トークンが不整合 | 認証せずログイン画面に戻す。 |
| 3 | 試行制限に該当 | ログインを成立させず、制限状態を表示する。 |
| 4 | ログイン ID に一致する管理者が存在しない | 認証エラーとして扱う。 |
| 5 | 管理者が停止中またはログイン不可 | 認証エラーとして扱う。 |
| 6 | パスワードが不一致 | 認証エラーとして扱う。 |
| 7 | ID・パスワード認証成功、かつ追加認証が必要 | 追加認証画面へ誘導する。 |
| 8 | ID・パスワード認証成功、かつ追加認証が不要 | 管理セッションを確立し、ホーム画面へ遷移する。 |

認証エラー時の画面表示は、次の2行のみとする（詳細は「表示メッセージ」の認証失敗（2行）を参照）。

```
ログインできませんでした。
入力内容に誤りがないかご確認ください。
```

管理者の存在有無、停止状態、ログイン不可状態、パスワード不一致は画面上では区別しない。内部的な失敗理由区分はログイン履歴またはサーバログで扱う。

```
ログインできませんでした。
入力内容に誤りがないかご確認ください。
```

上記2行は、ログイン ID 未入力・パスワード未入力・存在しない ID・停止中・ログイン不可・パスワード不一致・CSRF 不整合のいずれでも同じである。失敗理由ごとに文言は変わらない。

| 事象 | ログイン画面上の表示 |
|------|----------------------|
| ID・パスワード認証成功（追加認証不要） | 成功メッセージなし。ホーム画面へ遷移する |

本機能のログイン処理は `addFlash` 等で固定の成功・失敗メッセージをセットしない。画面上部アラートに出る文言は、他機能が事前にセッションへ保存した内容のみである。

## 業務ルール・計算

| 項目 | 内容 |
|------|------|
| 認証対象 | 管理者として登録され、ログイン可能な状態の管理メンバーだけを認証対象とする。一般フロント会員は管理画面の認証主体ではない。 |
| 判定順序 | 入力不足、CSRF、試行制限、管理者存在、有効状態、パスワード照合、追加認証要否の順にログイン成立可否を判定する。 |
| 失敗時表示 | 管理者の存在有無、停止状態、ログイン不可状態、パスワード不一致は画面上では詳細に区別しない。表示文言は「表示メッセージ」の認証エラー表を正とする。 |
| 成功時副作用 | 管理セッションを確立し、ログイン履歴と最終ログイン日時の更新対象にする。Remember Me が有効な場合は Cookie とサーバ側保存情報により再確立できる。 |
| 試行制限 | 固定窓方式でログイン ID と IP アドレス、または IP アドレス単体を単位に送信回数を制御する。 |
| 業務計算 | 本機能では金額、件数、在庫などの業務計算を行わない。 |

### 入力項目

| 項目名 | 必須／任意 | 最大長 | 初期値 | 保存先・扱い |
|--------|------------|--------|--------|--------------|
| ログイン ID | 必須（いずれか未入力は認証失敗として扱う） | 実装確認値 50 文字（`LoginType` の `eccube_id_max_len`） | 空 | 認証照合用の送信値。管理者レコードのログイン ID 列へはこの送信だけでは書き込まない。 |
| パスワード | 必須（同上） | 実装確認値 50 文字（`LoginType` の `eccube_password_max_len`） | 空 | 照合用。画面・ログ・設計書に原値を出さない。永続化はハッシュ等の不可逆値のみ。 |
| CSRF トークン | 必須 | — | フォーム生成時に埋め込み | フレームワークが検証する。不一致は受理しない。 |
| なりすまし対策トークン | 必須（機能有効時。フィールドが無い場合は認証失敗） | — | フォーム生成時に埋め込み | フレームワークまたはセキュリティコンポーネントの検証に従う。 |

### エッジケース

| ケース | 扱い |
|--------|------|
| ログイン ID またはパスワード未入力 | 通常のフォーム送信エラーではなく、認証基盤の失敗としてログイン画面へ戻す。画面上は「ログインできませんでした。」＋「入力内容に誤りがないかご確認ください。」（2行）。 |
| 管理者が存在しない | 認証エラーとして扱い、画面上は上記2行のみ（詳細理由を区別しない）。 |
| 管理者が停止中またはログイン不可 | 認証エラーとして扱い、画面上は上記2行のみ。 |
| パスワード不一致 | 認証エラーとして扱い、画面上は上記2行のみ。 |
| 試行制限超過 | ログインを成立させず、画面上は「ログイン試行回数を超えました。しばらくして再度お試しください。」または「ログイン試行回数が多すぎます。{N}分後に再度お試しください。」 |
| ログイン済みでログイン画面を開く | ログイン画面を表示せずホーム画面へ誘導する。 |
| 二段階認証が必要 | ID・パスワード認証が成功しても、追加認証完了まで保護された管理画面を利用できない。 |
| Remember Me Cookie だけがある | 管理ログイン画面への遷移を経て、Cookie とサーバ側情報により認証状態を再確立する。 |

## データ整合性

| 観点 | 内容 |
|------|------|
| 管理者状態 | 認証時点で有効な管理者だけがログインできる。認証後に管理者状態が変更された場合の扱いは、以降の認可・セッション検証の実装に従う。 |
| セッションと Cookie | 管理ログイン状態はブラウザ単位のセッション Cookie とサーバ側セッションに依存する。Remember Me は別の Cookie とサーバ側保存情報によりログイン状態を再確立する。 |
| ログイン履歴 | ログイン成功・失敗はログイン履歴に保存する。失敗履歴保存に失敗した場合は認証結果そのものとは切り離してサーバログに記録する。 |
| 最終ログイン日時 | 成功時は管理者の最終ログイン日時を更新する。成功履歴保存や最終ログイン日時更新に失敗した場合は、明示的に握りつぶさず例外として扱う。 |
| 二段階認証との整合性 | 二段階認証が必要な管理者は、ID・パスワード認証後に追加認証へ進む。追加認証の詳細は二段階認証機能の設計を正とする。 |

| 種類 | 内容 |
|------|------|
| API | 本機能はブラウザ経由の管理ログインを対象とし、API ログインは扱わない。 |
| バッチ | 本機能はバッチを起動しない。管理者状態やパスワードが別処理で変更済みの場合、次回ログイン送信時にその時点の永続化済みデータを読む。 |

## DBカラム

ログインと監査に直接関係する列のみを以下に列挙する。型の細部はスキーマを参照する。停止中の判定は、管理者ロード時に有効状態の管理者のみを対象にすることで行う。

| テーブル | 列 | メモ |
|---------|-----|------|
| dtb_member | login_id | ログイン識別子。 |
| dtb_member | password | パスワード照合に用いる保存値。平文ではなくハッシュ等の不可逆値として扱う。ログや設計書に原値を書かない。 |

### DB操作

当機能が行う永続化操作を以下に示す。テーブル名は ec-cube-enterprise を正とする。

| 操作種別 | 対象テーブル | 契機・条件 |
|---------|--------------|------------|
| 登録 | dtb_login_history | 認証成功時に成功区分（status_id=1）で履歴を1件登録する。 |
| 登録 | dtb_login_history | 認証失敗時に失敗区分（status_id=0）で履歴を1件登録する。ログイン ID から管理者を特定できない失敗では member_id を NULL とする。 |
| 更新 | dtb_member | 認証成功時に login_date（最終ログイン日時）を更新する。認証失敗時は更新しない。 |

## バリデーション

| 項目 | 内容 |
|------|------|
| login_id | ログインフォーム定義では必須。最大長はアプリ共通の ID 最大長設定（実装確認値 50 文字）に従う。 |
| password | ログインフォーム定義では必須。最大長はアプリ共通のパスワード最大長設定（実装確認値 50 文字）に従う。管理ログインには文字数下限の事前チェックは無い（最小桁チェックは顧客ログイン専用の実装であり、管理ログインには適用しない）。 |
| CSRF | ログイン送信に付与したトークンを認証基盤側で検証する。 |
| 画面上の入力不備 | ログイン画面のフォーム定義上は必須制約を持つ。ログイン送信は認証基盤の `form_login` が受けるため、送信時は通常のフォーム送信処理ではなく認証処理として判定する。 |

Symfony Form の自動 CSRF はログインフォームでは無効化され、画面上の `_csrf_token` を用いる。
CSRF トークンの生成・保管方式はフレームワークの管理範囲とし、本書では業務データとして扱わない。

## 試行制限

試行制限は、ログイン失敗などの条件によりログイン送信を一時的に拒否または遅延させる制御である。

管理ログインは Symfony Security の `login_throttling` を使用する。
固定窓方式で 5 回 / 30 分の上限を持ち、Redis の rate limiter cache に状態を保存する。

| 観点 | 扱い |
|------|------|
| 判定タイミング | ログイン送信時、認証成立前に評価する。 |
| 判定単位 | ログイン ID と IP アドレスの組み合わせ、および IP アドレス単体。 |
| 制限時の結果 | ログインを成立させず、ログイン画面で制限状態を表示する。 |
| 解除条件 | 固定窓の 30 分経過により消費済みトークンが解消される。 |
| 成功時リセット | ログイン成功時に対象リミッターをリセットする。 |

## ログ・監査

| タイミング | 記録内容 |
|------------|----------|
| ログイン成功 | 管理者 ID、ログイン ID、成功区分、送信元 IP、店舗文脈、履歴日時をログイン履歴に保存し、管理者の最終ログイン日時を更新する。 |
| ログイン失敗 | 入力されたログイン ID、失敗区分、送信元 IP、店舗文脈、履歴日時をログイン履歴に保存する。 |
| 試行制限 | Symfony Security の試行制限として処理する。ログイン履歴には失敗区分のみを保存し、制限理由は保存しない。 |
| 失敗履歴保存失敗 | 例外概要、管理者 ID、ログイン ID、ステータス ID、送信元 IP、店舗文脈、日時をサーバログに記録する。 |
| ログアウト・自動ログアウト | Symfony Security のログアウト処理としてセッションを終了する。ログイン履歴には保存しない。 |

ログイン失敗の画面表示では失敗理由を詳細に出さない。
ログイン履歴には成功／失敗区分、入力されたログイン ID、管理者 ID、送信元 IP、店舗文脈、日時を記録する。失敗理由の詳細区分はログイン履歴には保存しない。

### ログに出してはいけないもの

- パスワード
- なりすまし対策トークン
- Cookie 値
- セッション ID の完全値
- Remember Me トークンの原値

## 排他制御・トランザクション

ログイン処理は注文登録や在庫更新のような業務データ更新ではないため、楽観ロック・悲観ロックの対象は持たない。

- 管理セッション作成が主処理。
- ログイン履歴・最終ログイン日時更新は監査用の副作用。
- 失敗履歴の保存に失敗しても、認証結果そのものとは切り離してサーバログに記録する。
- 成功履歴保存・最終ログイン日時更新はログイン後リクエストの副作用として実行され、失敗時に明示的に握りつぶされない。
- 同一管理者の複数ブラウザ同時ログインを禁止する要件は、この機能では扱わない。
