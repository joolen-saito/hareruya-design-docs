# m09-06_admin_content_content_js（管理画面_コンテンツ管理_JavaScript管理）

管理画面のコンテンツ管理配下で、店舗フロント全ページへ読み込まれるカスタマイズ用JavaScriptファイル（customize.js）の内容を編集画面のエディタで編集し、保存する機能である。

## 概要

JavaScript管理は、管理者がフロント共通テンプレートから読み込まれるカスタマイズ用JavaScriptの中身を画面上のコードエディタで編集し、登録ボタンで保存する機能である。保存先はデータベースの設定値ではなく、フロント側公開ディレクトリ配下のJavaScriptファイル1本である。保存と同時に、ファイルアダプタ経由でフロントのテーマ公開ディレクトリへも同名ファイルを配置する。

本機能のカスタマイズ区分は標準であり、挙動・DB関連ともに ec-cube-enterprise の実装を正とする。本機能は永続化先がサーバ上のJavaScriptファイルとフロント公開先であり、データベースへは保存しないため、DBスキーマを持たない。

本書は実装手順ではなく、誰が・いつ・どの条件で・結果どうなるかを読むためのリバース詳細設計とする。既存実装のふるまい、参照するファイル、保存経路、副作用、フロントへの出力経路を確認し、仕様の確からしさを把握することを目的とする。

対象はブラウザ経由の管理画面のJavaScript管理画面である。コントローラのメソッド単位の解剖は本文の主題としない。本文ではルート識別子の網羅は扱わず、利用者視点の入口にHTTPメソッドとサイトルートからのパスパターンを書く。管理画面プレフィックスは環境変数で決まる値であり、本書では設定キー `eccube_admin_route` のプレースホルダ `%eccube_admin_route%` で示す。

## リニューアル移行時の扱い

本機能はカスタマイズ区分が標準であり、挙動・DB関連ともに ec-cube-enterprise の実装を正とする。

| 観点 | 現行（pf-eccube3） | 移行先（ec-cube-enterprise） |
|------|--------------------|------------------------------|
| 永続化先 | サーバ上のカスタマイズ用JavaScriptファイルとフロント公開先。DB列を持たない。 | 同一。DB列を持たない。編集対象は `eccube_html_dir` 配下 `/user_data/assets/js/customize.js`、配置先は `/html/user_data/assets/js/customize.js`。 |
| DBスキーマ | 該当テーブル・列なし | 該当テーブル・列なし（永続化はファイルのみのため、現行と移行先でDB差分は無い） |
| 機能区分 | フロント全ページ共通のカスタマイズ用JavaScriptの編集 | 標準機能として ec-cube-enterprise が実装を保持する |

本機能はデータベースへ保存しないため、テーブル名・列名の差分、論理削除・物理削除の差、補助表の有無といった移行差は発生しない。

## 処理フロー

### 画面を開く（GET）

1. 管理画面の認証・権限・IP制限の各ルールを通過する。
2. ファイルアップロードの利用頻度に関する案内メッセージを、未表示であれば1回だけ管理画面向け情報メッセージとして積む。
3. コード入力1つを持つフォームを組み立てる。コード入力は必須指定をフォーム側では付与しない（required=false）。
4. 編集対象ファイル `eccube_html_dir` 配下 `/user_data/assets/js/customize.js` が存在し、かつ書き込み可能であれば、その内容をコード入力の初期値として設定する。いずれかを満たさない場合は初期値を設定せず空のまま表示する。
5. テンプレートを描画する。エディタへフォーム値を流し込んで表示する。

### 登録押下（POST、書き込み成功）

1. 送信されたコード入力でフォームを処理する。
2. フォームが送信済みかつ妥当であれば保存処理へ進む。
3. 編集対象ファイルへコード入力の内容を書き出す（ファイルが無ければ作成、あれば上書き）。
4. 管理画面向けの保存完了メッセージを積む。
5. 既定のファイルアダプタを取得し、編集対象ファイルをフロント公開先 `/html/user_data/assets/js/customize.js` としてファイル名 `customize.js` で配置する。
6. 同一のJavaScript管理画面へリダイレクトする。

### 登録押下（POST、書き込み失敗）

1. 送信されたコード入力でフォームを処理する。
2. 編集対象ファイルへの書き出しで入出力例外が発生した場合、保存に失敗した旨のエラーメッセージを画面に表示する。
3. 同内容をアプリケーションログにエラーとして記録する（対象ファイルパスと例外を含む）。
4. リダイレクトせず同一画面のテンプレートを描画する。保存完了メッセージは積まない。

### フロント側の読み込み

1. フロント共通テンプレートが、フロント公開先のJavaScriptアセットを読み込むスクリプトタグを出力する。
2. 配置済みの `customize.js` がフロント全ページで読み込まれる。

## 業務ルール・計算

| 項目 | 内容 |
|------|------|
| 読み込み条件 | 編集対象ファイルが存在し、かつ書き込み可能なときに限り、その内容をエディタへ初期表示する。書き込み不可・不存在なら空表示。 |
| 保存単位 | コード入力1つの内容をそのまま1ファイルへ書き出す。差分管理・履歴は持たない。常に全文上書きである。 |
| 保存経路 | まず管理サーバ上の編集対象ファイルへ書き出し、続いてファイルアダプタでフロント公開先へ配置する2段の経路である。 |
| 必須表示と検証の差 | 画面のコード見出しには必須バッジを表示するが、フォーム側のコード入力は必須指定を付与しない。空文字でも検証を通過し、空内容で上書き保存され得る。 |
| 構文チェックの扱い | 構文エラーの検知と登録ボタン非活性はブラウザ側のエディタ機能である。サーバ側ではJavaScript構文の妥当性を検証しない。 |
| フロント反映 | 保存とフロント公開先への配置が成功すれば、以後フロント全ページの読み込み対象が更新後の内容になる。 |

### 入力項目

| 項目名 | 必須／任意 | 最大長 | 初期値 | 保存先・扱い |
|--------|------------|--------|--------|----------------|
| コード | 任意（画面表示は必須バッジ、フォームは required=false） | フォーム上限なし（Symfony Length制約なし）。保存先はファイルのためDB列長の制約は受けない。 | 編集対象ファイルが存在し書き込み可能なら当該ファイル内容、そうでなければ空 | `eccube_html_dir` 配下 `/user_data/assets/js/customize.js` へ全文書き出し（フォームキー `js`、複数行入力）。書き込み成功後、ファイルアダプタでフロント公開先 `/html/user_data/assets/js/customize.js`（ファイル名 `customize.js`）へ配置する。DBへは保存しない。 |

コード入力は複数行入力（textarea）であり、画面ではAceエディタで覆って編集する。送信時にエディタの現在値が非表示textareaへ書き戻されてサーバへ送られる。

### エッジケース

| ケース | 扱い |
|--------|------|
| 編集対象ファイルが存在しない | エディタは空で表示する。登録すると新規にファイルを作成して書き込む。 |
| 編集対象ファイルが存在するが書き込み不可 | 既存内容を初期表示しない（空表示）。登録時の書き込みで入出力例外となればエラーメッセージを表示する。 |
| コードを空文字で登録 | フォーム検証を通過し、空内容でファイルを上書きする。フロント公開先も空内容で配置する。 |
| ブラウザ側でJavaScript構文エラーを検知 | 登録ボタンが非活性となり送信できない。サーバ側では構文の妥当性を検証しない。 |
| ファイル書き込み中の入出力例外 | 保存完了メッセージを積まず、保存失敗メッセージを表示し、アプリケーションログにエラーを記録する。 |

## データ整合性

| 観点 | 内容 |
|------|------|
| 編集対象ファイルとフロント公開先 | 登録成功時は編集対象ファイルへ書き込んだ後にフロント公開先へ配置する。配置段階で例外が発生した場合、編集対象ファイルは更新済みでフロント公開先が未更新となる不一致が起き得る。 |
| 画面表示と保存値 | 画面初期表示は編集対象ファイルの内容を読む。保存後はリダイレクトで再表示し、保存後の内容を読み直す。 |
| 同時編集 | 複数管理者が同時に登録した場合、最後に書き込んだ内容がファイルに残る。版管理・楽観ロックは持たない。 |
| フロント反映タイミング | フロントは各ページ表示時にフロント公開先のアセットを読み込む。ブラウザキャッシュやCDNの反映遅延は本機能の管理範囲外とする。 |

|------------|----------|------|
| 未ログイン（一般利用者） | 管理画面の共通認証により拒否 | 同上 |
| ログイン済み管理者（通常） | 許可（権限マスタ・IP制限を通過する場合） | 許可 |
| ログイン済みだが権限マスタで当該パスが拒否 | 拒否 | 拒否 |

本画面に固有の追加権限判定はコントローラ実装からは読み取らない。アクセス可否は管理画面共通の認証・認可ルールに従う。

## 画面遷移

| 条件 | 遷移先 |
|------|--------|
| ナビからJavaScript管理を開く | 同一画面にエディタとフォームを表示。 |
| 登録に成功 | 同一のJavaScript管理画面（リダイレクトで再表示）。 |
| 登録で書き込み失敗 | 同一画面に留まる（リダイレクトしない）。 |
| フッタの戻る導線を押下 | コンテンツ管理のページ管理一覧。 |

### 遷移時に引き継ぐ状態

| 起点 | 遷移前の処理 | 遷移後の初期状態 |
|------|--------------|------------------|
| 登録成功 | 保存完了メッセージをフラッシュバッグへ追加してからリダイレクト | リダイレクト後の同一画面で保存完了メッセージを1度表示し、保存後のファイル内容をエディタへ再読込する |

---

## エラー処理

| エラー内容 | 処理 |
|------------|------|
| 編集対象ファイルへの書き込み入出力例外 | 保存失敗メッセージを画面に表示し、同一画面を再描画する。アプリケーションログへ対象ファイルパスと例外を記録する。表示文言は表示メッセージ節を正とする。 |
| 編集対象ファイルが不存在・書き込み不可 | 画面表示時は初期値を設定せず空表示とする。例外は発生させない。 |
| 認証・権限・IP制限による拒否 | 管理画面共通の認証・認可ルールに委ねる。本機能固有の利用者向け文言は設けない。 |

---

## ログ・監査

| タイミング | 記録内容 |
|------------|----------|
| 書き込み入出力例外時 | 保存失敗メッセージ相当の内容と、対象ファイルパス・例外をアプリケーションログにエラーとして記録する。 |
| 正常保存時 | 管理画面向けの保存完了フラッシュ（メッセージキー）を積む。アプリケーションログ専用の追加記録は当機能の実装からは読み取らない。 |

### ログに出してはいけないもの

- パスワード
- なりすまし対策トークン
- Cookie値
- セッションIDの完全値

---

## 排他制御・トランザクション

本機能はファイルの全文上書きであり、Doctrineの業務トランザクションや楽観ロック・悲観ロックの対象は持たない。複数管理者が同一ファイルを同時に登録した場合、最後に書き込んだ内容が残る。
