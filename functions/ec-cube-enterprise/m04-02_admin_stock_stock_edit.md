# 在庫管理 — 在庫編集機能

## 業務ロジック

### 在庫編集と承認の関係

商品規格単位かつ店舗（在庫区分）ごとに在庫数を編集する。在庫一覧の商品名リンクから対象の規格在庫を指定して在庫承認（編集）画面を開き、在庫変動区分（入庫／廃棄）・在庫増減数・在庫変動理由・仕入単価を入力して登録する。

登録は在庫へ即時反映せず、承認機能へ投入する。

- 入庫: 在庫編集承認情報を未承認で登録して承認待ちにする。在庫数の反映は在庫承認一覧での承認時に行い、登録時点では在庫も在庫変動履歴も更新しない。
- 廃棄: 登録時点で在庫を減算（在庫ロック）し、在庫変動履歴も即時に作成したうえで承認待ちにする。

あわせて、対象在庫の在庫変動履歴の表示と、承認者への通知メール送信を行う。

### 在庫変動履歴一覧の表示

在庫変動履歴（対象の規格在庫の直近30件）と、承認待ち入庫詳細（承認状態が未承認の入庫）の両方を、同一形式の行に整形して結合する。

- 表示順: 各行の基準日時の降順。基準日時は承認日時・登録日時・作成日時の優先順で決まる（承認日時が未設定なら登録日時を用いる）。結合後に上位30件へ切り詰める。
- 在庫数のマスク: 承認フローを持つ区分（在庫編集・在庫一括編集・在庫変動CSV取込）かつ未承認の加算系（入庫）の行は、変更前在庫と変更後在庫を「-」でマスクする。減算系（廃棄）は登録時に即時減算済みのため、変更前在庫・変更後在庫をそのまま表示する。
- 承認者: 承認済みの行は承認者名を、未承認の承認フロー行は「承認待ち」を表示する。

### 入力値の整合チェック

各項目単位の必須・範囲の検証（入出力の入力項目を参照）に加えて、在庫変動区分と在庫増減数・現在在庫の組み合わせを検証する。いずれも登録せず入力エラーとする。

| 条件 | 判定 |
| --- | --- |
| 入庫で在庫増減数が1未満 | エラー |
| 廃棄で在庫増減数が-1超（負数でない） | エラー |
| 入庫で「現在在庫＋在庫増減数」が在庫増減数の最大値を超過 | エラー |
| 廃棄で廃棄数（絶対値）が現在在庫を超過 | エラー |

廃棄を選んだときに仕入単価を入力不可とするのは画面側の制御である。サーバ側は廃棄時に入力された仕入単価を在庫計算に使わない（減算では総在庫のみが減る）。

### 登録処理の順序

1. 対象の規格在庫から店舗を取得し、登録フォームを生成して送信値を受け取る。
2. 未送信または検証エラーのときは、保存失敗のメッセージを表示して同じ画面を再表示する。
3. ログインしているメンバーが対象店舗の在庫を編集する権限を持つか確認する。権限が無いときは権限エラーのメッセージを表示して再表示し、登録しない。
4. 以降を単一のトランザクションで行う。途中で例外が起きたときはすべてを取り消す。
   1. 在庫変動履歴のソース種別を「在庫編集」として取得する。
   2. **在庫編集承認情報を登録する。** 店舗・在庫変動区分詳細・承認状態＝未承認・登録日時＝現在日時・登録者＝ログインメンバーを設定し、承認日時と承認者は空とする。ここで在庫編集承認IDが採番される。
   3. **在庫編集承認詳細を登録する。** 採番した承認情報・対象の規格在庫・編集数＝在庫増減数・在庫変動理由・仕入単価（未入力は0）・出庫総原価・登録者・変更前在庫数・変更前仕入単価を設定する。
   4. **廃棄のときだけ在庫へ即時反映する（在庫ロック）。** 変更後在庫数・変更後総原価・変更後原価単価を算出して規格在庫の在庫数と総原価を更新し、続けて在庫変動履歴を登録する。履歴には変更前在庫・変更後在庫・在庫増減数、原価の変更前後、在庫変動理由、ソース種別＝在庫編集、履歴のソースIDとして在庫編集承認ID、登録者と操作者名を設定する。入庫のときはこの手順を行わない。
   5. **在庫承認一覧へ登録する。** 承認一覧で承認行為を行えるように、店舗・在庫区分・ソース種別＝在庫編集・ソースID＝在庫編集承認ID・在庫変動区分詳細・承認状態＝未承認・登録日時・登録者・対象商品規格数＝1・合計在庫増減数＝在庫増減数・変更前総原価を設定し、承認日時と承認者は空とする。
5. 登録が成功し、承認通知先メンバーが指定されていれば、各メンバーへ在庫管理承認通知メールを送る。
6. 保存完了のメッセージを表示し、在庫承認（編集）画面へリダイレクトする。

承認状態は未承認・承認済・却下の3値で、本機能が登録する在庫編集承認情報と在庫承認一覧はいずれも未承認で登録する。

### 在庫変動理由の個別更新

一覧に並んだ行の在庫変動理由だけを、画面遷移せずに書き換える。

- 非同期リクエスト以外で呼ばれたときは、保存失敗として 400 を返す。
- 在庫変動理由と、更新対象を示すID（在庫変動履歴の行、または承認待ち入庫詳細の行）を受け取る。ID は排他で、両方を指定したときも両方とも指定しないときも 400 とする。
- 在庫変動履歴を対象にしたとき: その履歴が当該の規格在庫を参照し、ソース種別が在庫編集または在庫一括編集で、かつ区分が入庫または廃棄の場合だけ編集できる。在庫変動理由・更新者・更新日時を更新する。
- 承認待ち入庫詳細を対象にしたとき: その詳細が当該の規格在庫を参照し、承認情報が未承認で、かつ区分が入庫の場合だけ編集できる。在庫変動理由・更新者・更新日時を更新する。
- 成功したときは、成功した旨と、表示用に整形した在庫変動理由（欠品理由があれば結合したもの）を返す。対象が不正・別の在庫を参照している・編集できる条件を満たさないときは 400 とし、それ以外の例外は 500 とする。

### 分岐と遷移

| 状況 | 挙動 |
| --- | --- |
| 指定された規格在庫が存在しない | 画面を表示せず 404 とする（画面表示・登録のいずれも同じ） |
| 未送信または入力エラー | リダイレクトせず、保存失敗のメッセージを付けて在庫承認（編集）画面を再表示する |
| 編集権限を持たない店舗の在庫 | 権限エラーのメッセージを付けて再表示し、登録しない |
| 登録成功 | 保存完了のメッセージを表示し、在庫承認（編集）画面へリダイレクトする |
| 登録処理中の例外 | 変更をすべて取り消し、例外の内容をエラーとして表示して再表示する。在庫・在庫変動履歴・承認情報のいずれも確定しない |

## 入出力

### 入力: 在庫編集の登録フォーム

在庫変動区分の選択肢は、入庫と廃棄の在庫変動区分詳細に限る。

| 画面上の項目 | 必須 | 入力チェック |
| --- | --- | --- |
| 在庫変動区分 | 必須 | 入庫・廃棄の区分詳細のみ選択できる |
| 在庫変動理由 | 必須 | 複数行入力。設定された最大文字数（16384文字）以下 |
| 在庫増減数 | 必須 | 設定された最小値以上・最大値以下の数値 |
| 仕入単価 | 任意 | 設定された最小値以上・最大値以下の数値。未入力のときは登録時に0として扱う |
| 承認部署 | 任意 | 対象店舗のメンバーが属する部署から選ぶ。承認通知先メンバーを絞り込むための画面上の指定 |
| 承認通知先メンバー | 必須 | 1件以上。候補は対象店舗の承認権限を持つメンバー |

### 出力: 在庫承認（編集）画面

対象の商品・商品規格・規格在庫・店舗の各情報と、登録フォーム、在庫変動履歴一覧を表示する。一覧の並びとマスクは業務ロジックの「在庫変動履歴一覧の表示」による。

### 出力: 在庫管理承認通知メール

登録が成功したとき、指定された承認通知先メンバーそれぞれへ送る。本文には在庫承認一覧のURLを含める。データの更新は伴わない。

### 入出力: 永続化

| 対象 | 更新内容 |
| --- | --- |
| 在庫編集承認情報 | 登録（未承認）。承認状態・承認者・承認日時を保持する |
| 在庫編集承認詳細 | 登録。編集数・在庫変動理由・仕入単価・出庫総原価・変更前在庫数・変更前仕入単価を保持する |
| 在庫承認一覧 | 登録（未承認）。承認一覧画面で承認行為を行うための集約行（対象商品規格数＝1・合計在庫増減数・変更前総原価など） |
| 規格在庫（在庫数・総原価） | 廃棄のときだけ登録時点で更新する（在庫ロック）。入庫は承認後に反映する |
| 在庫変動履歴 | 廃棄のときだけ登録時点で登録する。変更前在庫・変更後在庫・在庫増減数・在庫変動理由・原価の変更前後・ソース種別・在庫編集承認IDを保持する。入庫は承認時に登録する |
| 在庫編集に紐づくCSVファイル | 在庫編集へ添付するCSVの管理用で、主にCSV取込経由の在庫編集で使う。本画面の手入力による登録では使用しない（実装要確認） |
