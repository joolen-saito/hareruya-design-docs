## リニューアル移行時の扱い

本機能のカスタマイズ区分は新規実装であり、基本設計仕様書を正典とする。対応するec-cube-enterprise実装が存在するため、DB関連はec-cube-enterprise実装に合わせる。

戻しリストCSVはネット買取のルート`admin_purchase_csv_export_return_list`で出力する。データ取得は買取注文リポジトリの棚戻しリスト用SQL（`DtbBuyOrderRepository::getBuyOrderRestockListCsvExportData`）であり、実在庫は`dtb_buy_order_stock`、買取注文は`dtb_buy_order`、規格は`dtb_product_class`、棚番は`dtb_shelf_number`を参照する。金額の閾値は本店の店舗基本情報`dtb_base_info`の`expensive_threshold1`・`expensive_threshold2`・`expensive_threshold3`を参照する。店頭買取の`dtb_otc_buy_order`・`dtb_otc_buy_order_stock`は別系統であり本機能では参照しない。本機能はCSV出力（参照のみ）でありDB更新を伴わない。

### 機能の目的と役割

ネット買取の棚戻し業務用リストをCSV出力する。

### 入出力仕様

| 種類 | 内容 |
|------|------|
| 入力 | 管理画面の検索条件、フォーム入力、CSVアップロード、または画面操作。 |
| 出力 | 画面表示、CSV/PDFダウンロード、登録完了/エラー表示。 |
| 副作用 | 対象データの登録・更新、CSV取込履歴、在庫履歴、ステータス履歴の記録。 |

### 開始条件、終了条件

| 種類 | 内容 |
|------|------|
| 開始条件 | 管理画面にログイン済みの利用者が対象メニューまたは操作を実行する。 |
| 終了条件 | 画面表示、ファイル出力、登録完了、またはエラー表示が完了する。 |

### 判定条件

- Excel設計書に記載された対象条件、検索条件、CSV出力条件、登録条件を正とする。
- Excel設計書に未記載のURLエンドポイント、DBカラム、実処理順序は `../ec-cube-enterprise` の実装を正とする。
- 権限、ログイン状態、管理画面プレフィックスなどの共通判定は共通設計および実装側のセキュリティ設定に従う。

### プロセスフロー

1. 利用者または外部システムが対象機能を開始する。
2. 入力値、検索条件、アップロードファイル、またはリクエスト本文を受け付ける。
3. Excel設計書に定義された対象データを取得し、実装側の検証・権限・状態条件を適用する。
4. 登録・更新・出力・連携のいずれかの主処理を実行する。
5. 成功時は結果画面、CSV/PDF/APIレスポンス、またはバッチ結果を返す。失敗時はエラー内容を返し、更新が必要な処理では不整合が残らないように扱う。

### ビジネスロジック

- **Excel設計優先**: 仕様の目的、対象データ、出力項目、表示項目、業務上の条件は `excel_to_html/output` の設計書を正とする。
- **実装補完**: Excel設計に書かれていないURLエンドポイント、DBカラム、トランザクション、サービス分割、非同期処理は `../ec-cube-enterprise` の実装を正とする。
- **対象機能の要点**: ネット買取の棚戻し業務用リストをCSV出力する。
- **実装確認値**: ネット買取の棚戻しリストサービス（`BuyOrderRestockListService`）と棚戻しリストCSVエクスポータ（`BuyOrderRestockListCsvExportService`）、ルート`admin_purchase_csv_export_return_list`を実装確認値とする。店頭買取側の`OtcBuyOrderRestockListService`はネット買取の本機能とは別系統である。

### 状態・データ更新

| 対象 | 内容 |
|------|------|
| 主データ | 管理画面の対象業務データを参照し、登録系では対象データと履歴を更新する。 |
| 履歴・ログ | 必要に応じてCSV取込履歴、在庫履歴、ステータス履歴、API受信履歴、アプリケーションログを作成・更新する。 |
| DB関連実装確認値 | 参照テーブル: `dtb_buy_order_stock`（実在庫）、`dtb_buy_order`（買取注文）、`dtb_product_class`（規格）、`dtb_shelf_number`（棚番）、`dtb_base_info`（本店の金額閾値`expensive_threshold1`〜`expensive_threshold3`）。本機能はCSV出力（参照のみ）でありDB更新は行わない。店頭買取の`dtb_otc_buy_*`系ではない。列詳細は `../ec-cube-enterprise` の Entity / Repository を正とする。 |

### 例外処理

- **入力不備**: 必須項目、CSVヘッダ、CSV行、APIリクエスト本文、検索条件が不正な場合はエラーとして処理し、登録・更新対象を確定しない。
- **対象なし**: 検索条件や対象IDに該当するデータがない場合は、空の一覧、空CSV、またはエラーレスポンスとして扱う。扱いの細部は対象画面/API/バッチの実装に従う。
- **状態不整合**: 既に処理済み、キャンセル済み、承認不可、在庫不足など状態条件に合わない場合は処理対象外またはエラーとする。
- **外部連携失敗**: スマレジ等の外部連携で失敗した場合は、実装側の再連携・エラーログ・エラーメール・ステータス更新仕様を正とする。

### 関連設計への接続点

- 画面項目、CSV列、PDFレイアウト、APIリクエスト/レスポンスの詳細は、参照元Excel設計書の該当シートを正とする。
- URLエンドポイントとDBカラムは `../ec-cube-enterprise` の Controller Route、Entity、Repository、Migration、Service 実装を正とする。
