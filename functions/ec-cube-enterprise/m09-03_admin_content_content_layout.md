# コンテンツ管理 — レイアウト管理

管理画面のコンテンツ管理にあるレイアウト管理。ページに配置するブロックを、テンプレートのセクションごとに割り当てたレイアウトとして作成・編集・削除し、プレビューする機能。

## 概要

レイアウト管理は、管理者がフロント画面のテンプレート上の各セクション（head内、header、メインの上下、サイド左右、footer、drawerなど）へブロックをドラッグ＆ドロップで配置し、その配置一式をレイアウトとして登録・編集・削除できるようにする機能である。各レイアウトは端末種別（PCまたはモバイル）を持ち、ページに割り当てると、そのページの表示時にこの配置が使われる。

本書は実装手順ではなく、誰が・いつ・どの条件で・結果どうなるかを読むためのリバース詳細設計とする。既存実装のふるまい、参照するデータ、判定境界、副作用、拡張による差し替え可能性を確認し、仕様の確からしさを把握することを目的とする。

本機能のカスタマイズ区分は標準であり、挙動・DBともにec-cube-enterpriseのレイアウト管理を正とする。DB関連の記述はec-cube-enterpriseを正典とする。

対象はブラウザ経由の管理画面のレイアウト管理（一覧・新規・編集・削除・コードプレビュー・画面プレビュー）である。ページとレイアウトの紐付けを編集するページ設定、ブロック自体の編集、フロント側でのレイアウト描画は別機能として切り離す。

管理画面プレフィックスは環境変数`ECCUBE_ADMIN_ROUTE`（既定`admin`）から決まる`eccube_admin_route`パラメータで置き換わるため、本書ではパスを`%eccube_admin_route%`で示す。コントローラのメソッド単位の解剖は本文の主題としない。

---

## 本書で扱うこと

- レイアウト一覧の表示対象と表示順、削除ボタンの出し分け
- レイアウトの新規作成・編集の入口、入力項目、保存時のブロック配置の再構築
- ブロックをセクションへ配置するドラッグ＆ドロップとコンテキストメニュー操作（上へ移動・下へ移動・セクション移動）のクライアント挙動
- 各セクションの種別と内部の配置ID（target_id）の対応
- ブロックのコードプレビュー（Ajax取得）と画面プレビュー（別タブで開く）のふるまい
- 削除できないレイアウト（既定レイアウト、ページが割り当て済みのレイアウト）の境界
- 保存・削除時のフラッシュメッセージとDoctrineキャッシュ削除

---

## 本書で扱わないこと

以下は本書では仕様確定せず、実装または別機能の設計を正とする。

- Symfonyのルート名・コントローラクラス名・メソッド名の一覧
- 管理画面へのログイン・権限設定・認可の詳細仕様
- ブロックの作成・編集・削除（ブロック管理機能）
- ページとレイアウトの割り当てを編集するページ設定機能
- フロント画面でレイアウトとブロックを実際に描画する処理
- 端末種別マスタ自体の管理
- Doctrineキャッシュ・テンプレートキャッシュの内部実装
- なりすまし対策トークンの生成・保管方式

## リニューアル移行時の扱い

本機能はカスタマイズ区分が標準であり、挙動・DBともにec-cube-enterpriseのレイアウト管理を正とする。永続化先はec-cube-enterpriseのレイアウトテーブル（dtb_layout）、ブロック配置テーブル（dtb_block_position）、ページ割り当てテーブル（dtb_page_layout）であり、本書のDBカラム節・入力項目の保存先はこの実装に一致する。レイアウト名（dtb_layout.layout_name）・端末種別（dtb_layout.device_type_id）・配置先セクション（dtb_block_position.section）・配置ブロック（dtb_block_position.block_id）・並び順（dtb_block_position.block_row）・ページ割り当て（dtb_page_layout.page_id・dtb_page_layout.layout_id）はec-cube-enterprise実装で確認した名称であり、現行と移行先で同一スキーマとする。

## 用語

| 用語 | 説明 |
|------|------|
| レイアウト | フロント画面のテンプレート上の各セクションへ、どのブロックをどの順で配置するかをまとめた単位。端末種別と名称を持つ。テーブルは`dtb_layout`。 |
| ブロック | テンプレートに差し込む部品。レイアウト管理ではブロックの中身を編集せず、配置先と並び順だけを扱う。 |
| ブロック配置 | あるレイアウトで、あるブロックがどのセクションの何番目に置かれるかを表す行。テーブルは`dtb_block_position`。 |
| セクション | テンプレート上の配置先領域。head内、body直後、header、contents_top、side_left、main_top、main_bottom、side_right、contents_bottom、footer、drawer、body直前の各領域と、未使用ブロック置き場がある。各セクションは配置ID（target_id）を持つ。 |
| 未使用ブロック | どのセクションにも配置していないブロック。配置IDは0で、保存時は配置行を作らない。 |
| 端末種別 | レイアウトが対象とする端末。PCとモバイルがあり、端末種別マスタ（`mtb_device_type`）のPCはid10、モバイルはid2。 |
| ページ割り当て | レイアウトとページの紐付け。テーブルは`dtb_page_layout`。割り当てがあるレイアウトは削除できない。 |
| 既定レイアウト | プレビュー用・トップページ用・下層ページ用の3つの固定レイアウト。一覧で削除ボタンを出さない。 |

## 利用者視点の入口

| 入口 | URLエンドポイント | 期待されるふるまい |
|------|--------------------|--------------------|
| レイアウト一覧を開く | `GET /%eccube_admin_route%/content/layout` | 登録済みレイアウトを端末種別降順・id昇順で一覧表示する。各レイアウトに割り当て済みページを折りたたみで表示する。 |
| 新規作成を押下 | `GET /%eccube_admin_route%/content/layout/new` | 空のレイアウト編集画面を開く。端末種別を選択でき、ブロックは全件が未使用ブロックに並ぶ。 |
| 新規作成を保存 | `POST /%eccube_admin_route%/content/layout/new` | 検証を通れば新規レイアウトとブロック配置を保存し、作成した編集画面へリダイレクトする。 |
| レイアウト名を押下（編集） | `GET /%eccube_admin_route%/content/layout/{id}/edit` | 指定レイアウトの編集画面を開く。配置済みブロックを各セクションへ、未使用ブロックを未使用欄へ表示する。 |
| 編集を保存 | `POST /%eccube_admin_route%/content/layout/{id}/edit` | 検証を通れば名称と配置を更新し、同じ編集画面へリダイレクトする。 |
| 削除を押下（確認後） | `DELETE /%eccube_admin_route%/content/layout/{id}/delete` | 削除可能なら削除し一覧へ戻る。割り当てページがある場合は削除せず警告を表示する。 |
| プレビューを押下 | `POST /%eccube_admin_route%/content/layout/{id}/preview` | 選択したページの種別に応じたフロント画面をプレビュー付きで別タブに開く。 |
| ブロックのコードプレビューを開く | `GET /%eccube_admin_route%/content/layout/view_block` | Ajaxで指定ブロックのテンプレートソースをJSONで返し、モーダル内のエディタへ表示する。 |
| 非管理者・未認証 | 上記の各管理側URL | 管理領域の認証・認可要件に従い、画面へ到達できない。 |

## フロント挙動

| 観点 | 内容 |
|------|------|
| 一覧の表示要素 | レイアウトごとにカードを表示し、端末種別がPCならデスクトップアイコン、それ以外はモバイルアイコンを付ける。カード見出しにレイアウト名（編集へのリンク）、削除ボタン（出し分けあり）、開閉ボタンを置く。展開すると割り当て済みページ名（ページ編集へのリンク）を一覧する。割り当てが無いときは「ページが登録されていません」と表示する。 |
| 一覧の削除モーダル | 削除ボタン押下で確認モーダルを開く。モーダル表示時にJavaScriptが、押下したボタンのdata-url・data-messageから削除リンクのhrefと確認文言を差し替える。確認ボタンはDELETEメソッドのリンクとして動作する。 |
| 編集の表示要素 | レイアウト概要カードに名称入力欄と端末種別、ブロック編集カードに各セクションの枠と未使用ブロック欄を表示する。各セクション枠にはセクション名（head内・header等）を見出しとして出す。ブロックが無いセクションには「ブロックをドラッグ＆ドロップ」のプレースホルダを表示する。 |
| ドラッグ＆ドロップ | jQuery UI sortableで、各セクション枠と未使用ブロック欄のあいだをブロックがドラッグで移動できる。connectWithで全セクションを相互接続する。移動・並び替えの確定時に、各ブロックの隠しフィールド（配置先のtarget-id、行番号block-row、先頭判定のfirstクラス）を更新する。空になったセクションへはプレースホルダを差し込み、ブロックが入ったセクションからはプレースホルダを除去する。 |
| コンテキストメニュー | 各ブロックの三点メニューを押すとポップオーバーで「上に移動」「下に移動」「セクションに移動」「コードプレビュー」を表示する。上下移動は同一セクション内で前後のブロックと入れ替え、移動後に行番号を再採番する。セクション移動はモーダルで移動先セクションを選ばせ、選んだセクションへブロックを移し行番号を再採番する。 |
| 未使用ブロックの検索 | 未使用ブロック欄上部の検索入力に文字を入れると、入力に一致しない未使用ブロックを絞り込み表示する。サーバ問い合わせはしない。 |
| コードプレビューのモーダル | ブロックのコードプレビューを開くと、Ajaxでブロックのテンプレートソースを取得し、読み取り専用のコードエディタ（ace、twigモード）へ表示する。失敗時はステータス文言をエディタへ表示する。モーダルのコード編集ボタンは、ダミーのブロックID（9999999999）を実ブロックIDへ置換したブロック編集画面のURLへ遷移する。 |
| 画面プレビュー | 編集画面でプレビュー対象ページを選び、プレビューボタンを押すと、フォームの送信先をプレビューURLへ、targetを別タブへ一時変更して送信し、送信後に元の編集URL・同一タブへ戻す。ページ未選択のときは「プレビューするページを選択してください」のブラウザアラートを出し送信しない。プレビューブロックは編集対象にページ候補があるときだけ表示する。 |
| 入力項目 | 名称はテキスト入力1欄。端末種別は新規時はプルダウン選択、既存編集時は値を表示し隠しフィールドで保持する。ブロック配置は各ブロックごとの隠しフィールド群（名称・ブロックID・配置先・行番号）として送信する。 |

### フロントエンド側ビジネスロジック

| 起点 | 参照する値 | 判定順序 | 更新する表示値・送信値 | サーバ側再検証 |
|------|------------|----------|--------------------------|----------------|
| ドラッグ＆ドロップ完了 | 配置先セクション、ブロックID、セクション内順序 | 移動先セクションと並び順を読み取り、空セクションのプレースホルダ有無を更新する。 | 各ブロックの配置先target-id、行番号block-row、先頭判定firstクラスを更新する。 | ブロック存在、レイアウト存在、配置先妥当性、重複はサーバ側で保存時に判定する。 |
| 上下移動メニュー押下 | 同一セクション内の前後ブロック | 上下に隣接ブロックがある場合だけ入れ替える。 | セクション内の表示順と行番号を再採番する。 | 保存時にサーバ側で送信順を正として保存可否を判定する。 |
| セクション移動確定 | 移動対象ブロック、移動先セクション | 選択されたセクションへブロックを移し、元・先の空表示を調整する。 | 配置先と行番号を更新する。 | 保存時にサーバ側で配置先と対象ブロックを検証する。 |
| 未使用ブロック検索入力 | 検索文字列、未使用ブロック名 | 入力文字列に一致しないブロックを非表示にする。 | 表示・非表示だけを切り替える。送信値は更新しない。 | 再検証なし。保存時は実際に送信された配置情報をサーバ側で判定する。 |
| コードプレビュー押下 | ブロックID | Ajaxでプレビュー用エンドポイントを呼び出す。 | モーダル内の読み取り専用エディタにテンプレートソースまたは失敗文言を表示する。 | Ajax要求か、ブロックIDが存在するか、読込可能かをサーバ側で判定する。 |
| 画面プレビュー押下 | プレビュー対象ページ選択値、編集フォーム | ページ未選択ならアラートを出して送信しない。選択済みなら送信先とtargetを一時的に差し替える。 | 別タブへプレビュー送信し、送信後に編集画面の送信先とtargetへ戻す。 | プレビュー表示可否、ページ存在、レイアウト反映内容はサーバ側で判定する。 |
| 削除ボタン押下 | 削除ボタンのdata-urlとdata-message | 対象レイアウトの削除確認モーダルを開く。 | モーダル内の削除実行リンクと確認文言を差し替える。 | 削除対象、初期データ削除制限、トークン、権限はサーバ側で判定する。 |

## 処理フロー

### レイアウト一覧表示

1. 管理者が一覧を開く。
2. システムはレイアウトを取得する。プレビュー用の固定レイアウト（id0）は一覧から除外する。
3. 取得結果を端末種別降順、id昇順で並べる。PCはモバイルより前に並ぶ。
4. 各レイアウトについて、割り当て済みページを折りたたみ内に表示する。既定レイアウト（id0・1・2）には削除ボタンを表示しない。

### レイアウト新規作成・編集表示

1. 管理者が新規作成または編集を開く。
2. 新規の場合は空のレイアウトを用意する。編集の場合は指定idのレイアウトを配置とブロックごと取得し、見つからなければ存在しない（HTTP404）として扱う。
3. 配置済みブロックがあればそれを除いた残りを未使用ブロックとし、無ければ全ブロックを未使用ブロックとする。
4. 名称・端末種別・プレビュー対象ページのフォームを組み立て、各セクションへ配置済みブロックを、未使用欄へ未使用ブロックを並べて表示する。

### レイアウト保存（新規・編集共通）

1. 管理者が登録ボタンで送信する。
2. なりすまし対策トークンとフォーム検証を通す。名称が未入力なら検証エラーで保存しない。
3. 検証を通れば、まずレイアウト本体（名称・端末種別）を保存する。
4. 当該レイアウトの既存ブロック配置をすべて削除する。
5. 送信されたブロックごとの隠しフィールド（ブロックID・配置先・行番号）を順に読み、配置先が未使用（target_id0）の行とブロックIDが取れない行は除外し、残りをブロック配置として作成する。
6. Doctrineキャッシュを削除する。
7. プレビュー送信でない通常保存のときは、保存しましたのフラッシュを積み、編集画面へリダイレクトする。

### 画面プレビュー

1. 管理者がプレビューボタンで送信する。送信先はプレビューURLである。
2. システムはプレビューモードで保存処理と同じ流れを実行し、レイアウトとブロック配置を更新する。
3. 選択ページを取得し、見つからなければ存在しない（HTTP404）として扱う。
4. ページの編集種別が既定以上で、URLが商品詳細のときは、表示中の商品を1件取り、その商品詳細をプレビュー付きで開く。表示商品が無ければ存在しない（HTTP404）として扱う。
5. 商品詳細以外の既定以上のページは、そのページURLをプレビュー付きで開く。
6. それ以外のページは利用者データ用ルートへ、対象ページURLとプレビュー指定を付けて開く。
7. プレビューでは保存しましたのフラッシュを積まない。

### レイアウト削除

1. 管理者が削除を確認して送信する。
2. なりすまし対策トークンを検証する。
3. 当該レイアウトに割り当てページがあると削除不可と判定し、関連データがあるため削除できない旨の警告を積み一覧へ戻す。
4. 削除可能なら削除し、削除しましたのフラッシュを積み、Doctrineキャッシュを削除して一覧へ戻す。

### ブロックのコードプレビュー取得

1. クライアントがコードプレビューを開いたときにAjaxでブロックIDを送る。
2. Ajaxでない要求は不正な要求（HTTP400）として扱う。
3. ブロックIDが無いと不正な要求（HTTP400）として扱う。
4. ブロックが見つからなければ存在しない（HTTP404）として扱う。
5. ブロックのテンプレートソースを読み、ブロックIDとソースをJSONで返す。

## 業務ルール・計算

| 項目 | 内容 |
|------|------|
| 一覧の対象 | プレビュー用固定レイアウト（id0）を除く全レイアウトを対象とする。端末種別降順・id昇順で並べる。 |
| 削除可否 | 割り当てページが1件でもあるレイアウトは削除しない。既定レイアウト（id0・1・2）は一覧で削除ボタンを表示しない。 |
| ブロック配置の再構築 | 保存のたびに当該レイアウトの既存配置を全削除し、送信値から作り直す。差分更新はしない。 |
| 未使用ブロックの扱い | 配置先が未使用（target_id0）の行とブロックIDが取れない行は配置として保存しない。 |
| 行番号 | 各セクション内のブロックの並び順は、クライアントが0始まりで再採番した行番号（block_row）として送信し、保存する。表示時はこの行番号の昇順で並べる。 |
| 端末種別 | レイアウトはPCまたはモバイルのいずれかの端末種別を持つ。新規時は選択、既存編集時は変更せず保持する。 |

### 入力項目

| 項目名 | 必須／任意 | 最大長 | 初期値 | 保存先・扱い |
|--------|------------|--------|--------|----------------|
| レイアウト名 | 必須 | Symfony Length制約は無し（DBは255文字） | 新規は空、既存はDB値 | `dtb_layout.layout_name`（フォームキー`name`）。空のとき未入力検証でエラー。 |
| 端末種別 | 任意（フォーム上required無効）だが未入力は検証エラー | — | 新規はマスタの選択肢、既存はDB値を表示のみ | `dtb_layout.device_type_id`（フォームキー`DeviceType`）。端末種別マスタ参照。未入力検証あり。既存編集では隠しフィールドで現値を保持。 |
| プレビュー対象ページ | 任意 | — | 未選択 | 永続化しない（フォームキー`Page`、mapped無効）。当該レイアウトに割り当て済みページから選び、プレビュー先の判定にだけ使う。 |
| ブロック配置（各ブロック） | 任意 | — | 既存配置または全件未使用 | `dtb_block_position`（`block_id`・`section`・`block_row`・`layout_id`）。隠しフィールド`block_id_<n>`・`section_<n>`・`block_row_<n>`・`name_<n>`の連番で送信。保存時に旧配置を全削除して再作成する。 |

最大長のレイアウト名は、コアのスキーマで`dtb_layout.layout_name`が255文字の文字列型である値を記載する。フォーム側のLength制約は無いため、入力上限はDB列長に依存する。運用環境でスキーマを上書きしている場合はその環境の値が正とする。

### エッジケース

| ケース | 扱い |
|--------|------|
| 編集対象のレイアウトidが存在しない | 存在しない（HTTP404）として扱う。 |
| 配置済みブロックが無い新規・編集 | 全ブロックを未使用ブロックとして表示する。 |
| すべてのブロックを未使用にして保存 | 配置行を1件も作らない。フロントには配置済みブロックが無い状態になる。 |
| 割り当てページがあるレイアウトの削除 | 削除せず警告フラッシュを積み一覧へ戻す。 |
| 既定レイアウト（id0・1・2） | 一覧で削除ボタンを出さない。 |
| プレビューでページ未選択のまま送信 | クライアント側でアラートを出し送信を中止する。 |
| プレビュー対象ページが見つからない／商品詳細で表示商品が無い | 存在しない（HTTP404）として扱う。 |
| コードプレビューをAjax以外で要求 | 不正な要求（HTTP400）として扱う。 |

## データ整合性

| 観点 | 内容 |
|------|------|
| 一覧と編集 | 一覧はプレビュー用固定レイアウトを除く全件。編集はid指定で配置・ブロックごと取得する。 |
| ブロック配置 | 保存のたびに当該レイアウトの配置を全削除して再作成する。途中失敗時の整合はトランザクション境界の実装を正とする。 |
| ドラッグ＆ドロップと送信 | 画面上の並びと隠しフィールドの行番号・配置先は、移動確定時のクライアント処理で同期する。送信されるのはこの隠しフィールド値である。 |
| プレビューと保存 | 画面プレビューは保存処理を伴うため、プレビュー実行時点でレイアウトとブロック配置が更新される。 |
| キャッシュ | 保存・削除のたびにDoctrineキャッシュを削除する。フロント表示への反映タイミングはキャッシュ実装を正とする。 |
| 割り当てページ | レイアウトとページの紐付け自体の編集はページ設定機能の範囲とし、本機能は削除可否判定で参照するだけである。 |

### DB操作

永続化の正は ec-cube-enterprise（テーブル名・操作は ec-cube-enterprise を正典）。当ドメインは承認ワークフローを介さず persist/flush で直接確定する（承認ワークフローは在庫機能固有）。

| 操作種別 | 対象テーブル | 契機・条件 |
|---------|--------------|------------|
| 登録/更新 | dtb_block_position / dtb_layout / dtb_page_layout | 当機能が行う登録・更新で対象テーブルを直接保存する（不要な削除は含まない）。確定は persist/flush による即時反映。DB=ec-cube-enterprise を正典とする。 |

| 項目 | 内容 |

### 遷移時に引き継ぐ状態

| 起点 | 遷移前の処理 | 遷移後の初期状態 |
|------|--------------|------------------|
| 保存成功 | レイアウトと配置を保存し、保存しましたのフラッシュを積む。 | 編集画面で保存後の配置とフラッシュを表示する。 |
| 削除（不可） | 警告フラッシュを積み、削除しない。 | 一覧で警告を表示し、対象レイアウトは残る。 |
| プレビュー | プレビューモードで保存処理を実行し配置を更新する。フラッシュは積まない。 | 別タブでプレビュー付きのフロント画面を表示する。 |

## エラー処理

| エラー内容 | 処理 |
|------------|------|
| 編集・プレビュー対象のレイアウト／ページが見つからない | 存在しない（HTTP404）として扱う。 |
| プレビュー対象が商品詳細で表示商品が無い | 存在しない（HTTP404）として扱う。 |

## 排他制御・トランザクション

本機能は楽観ロック・悲観ロックの対象を持たない。保存時は当該レイアウトの配置を全削除して再作成する流れであり、同一レイアウトを複数管理者が同時に保存した場合の整合はトランザクション境界の実装を正とする。
