# m05-16_admin_order_order_shop_memo（管理画面_受注編集_ショップ用メモ登録）

受注編集（詳細）画面の右カラムに置かれた「ショップ用メモ欄」へ、ショップ運営者が確認するためのメモを入力し、受注情報の保存に同梱して登録する機能。

## 概要

管理画面の受注編集（詳細）画面に配置されたショップ用メモ欄は、ショップ運営者が当該受注について社内で確認するためのメモを自由文で入力し、保存できるようにする機能である。入力した内容はフロント画面（購入者側）には表示しない。

本書は実装手順ではなく、誰が・いつ・どの条件で・結果どうなるかを読むためのリバース詳細設計とする。既存実装のふるまい、保存先、入力制約、保存経路、副作用を確認し、仕様の確からしさを把握することを目的とする。

対象はブラウザ経由の管理画面の受注編集（詳細）画面のうち、ショップ用メモ欄（ロケールキー `admin.common.shop_memo`）への入力と保存に限定する。メモの保存は受注編集の保存処理（M05-11受注編集）に同梱されるため、本書はメモ欄の挙動・保存先・制約のみを切り出して扱い、受注編集全体の処理は受注編集の設計を正とする。

管理画面プレフィックスは環境変数 `ECCUBE_ADMIN_ROUTE` を `eccube.yaml` の `eccube_admin_route` が受け取って決まる。ルート定義上は `%eccube_admin_route%` として展開される。本文ではルート名の網羅やコントローラ実装の手順は扱わず、「利用者視点の入口」に HTTP メソッドとサイトルートからのパスパターンを実装確認値として記載する。

本機能のカスタマイズ区分は標準であり、挙動・画面およびDB（永続化先のテーブル・列）はともに ec-cube-enterprise の実装を正とする。

- 受注編集（詳細）画面の「ショップ用メモ欄」がどのフォーム項目・保存先列に対応するか
- メモ欄の入力種別、必須／任意、フォーム上の最大長、保存先 `dtb_order.note` の桁、未入力時の扱い
- メモ欄の入力内容が受注編集の保存（受注編集の登録 POST）に同梱して永続化される経路
- メモ欄の内容がフロント画面（購入者側）に表示されないこと
- メモ欄のツールチップ文言

- メモを表示・検索・出力する他画面（受注一覧、CSV出力など）の表示ルール

## リニューアル移行時の扱い

本機能は標準機能のため、現行と移行先（ec-cube-enterprise）で固有のスキーマ差分は生じない。ショップ用メモの保存先である受注（`dtb_order.note`）は ec-cube-enterprise のスキーマを正とし、同一スキーマとして扱う。`dtb_order.note` は文字列型・桁4000・NULL許容（ec-cube-enterprise 実装確認値）であり、フォーム側の最大長（`eccube_ltext_len` 確認値3000文字）の方が小さいため、保存可能な実効上限はフォーム側で決まる。現行実装との差異が判明した場合は ec-cube-enterprise 実装を正とする。

## 利用者視点の入口

| 入口 | URLエンドポイント | 期待されるふるまい |
|------|--------------------|--------------------|
| 既存受注の編集（詳細）画面を開く | `GET /%eccube_admin_route%/order/{id}/edit` | 受注編集画面が開き、右カラムに「ショップ用メモ欄」カードが展開状態で表示される。テキストエリアには当該受注の既存メモが初期表示される。 |
| 新規受注の登録画面を開く | `GET /%eccube_admin_route%/order/new` | 新規受注の登録画面が開き、ショップ用メモ欄は空で表示される。 |
| ショップ用メモを入力して「登録」を押す | `POST /%eccube_admin_route%/order/{id}/edit` または `POST /%eccube_admin_route%/order/new` | 受注情報の保存に同梱してメモが保存される。検証成功時はメモを含む受注が永続化され、同一受注の編集画面へリダイレクトする。検証失敗時は同一画面に留まり、入力したメモは再表示される。 |
| 未ログイン・権限不足・IP制限で拒否される利用者 | 上記パス（到達前） | 管理画面の共通認証・認可ルールにより受注編集画面に到達できないため、メモ欄も利用できない。 |

ショップ用メモ欄は受注編集（詳細）画面の一部であり、メモ単独の専用URLは持たない。表示・保存とも受注編集のエンドポイントを共有する。

## 処理フロー

### 受注編集画面を開いたとき（GET、メモ欄の初期表示）

1. 管理画面の認証・権限・IP制限の各ルールを通過する。
2. 既存受注の編集では識別子で受注を取得し、フォームを生成する。ショップ用メモ欄には受注の現行メモ（`dtb_order.note`）が初期値として載る。新規受注の登録ではメモ欄は空で表示される。
3. 受注編集テンプレートを描画し、右カラムにショップ用メモ欄カードを表示する。

### ショップ用メモを入力して「登録」を押したとき（POST、メモ欄の保存）

1. 受注編集フォームをリクエストで処理する。ショップ用メモ欄の入力値はフォーム項目 `note` として受注に束ねられる。
2. フォーム検証を行う。ショップ用メモ欄については最大長（3000文字）の制約を満たすかを判定する。違反時は同一編集画面を再表示し、メモを含む入力値が再表示される。
3. 検証成功時、受注編集の保存処理（購入フローの prepare・commit を含む同一DBトランザクション）の中で受注を永続化する。ショップ用メモは受注の他項目とともに同じ flush で `dtb_order.note` に保存される。メモ単独の保存処理・専用 flush は持たない。
4. 保存成功後、同一受注の編集画面へリダイレクトする。

## 業務ルール・計算

| 項目 | 内容 |
|------|------|
| メモの保存契機 | 受注編集の「登録」押下時に、受注情報の保存に同梱して保存する。メモだけを単独で保存する経路は持たない。 |
| メモの保存単位 | 受注1件につきメモ1件。`dtb_order.note` の1列に自由文を保持する。 |
| 未入力時 | 任意項目のため空のまま保存できる。空入力時は当該列が空（NULL許容列）として保持される。 |
| フロント表示 | ショップ運営者の確認用であり、購入者側のフロント画面には表示しない。 |
| 計算処理 | メモに対する金額計算・丸め・集計は行わない。 |

### 入力項目

| 項目名 | 必須／任意 | 最大長 | 初期値 | 保存先・扱い |
|--------|------------|--------|--------|----------------|
| ショップ用メモ欄 | 任意 | フォーム上限3000文字（Length制約 `eccube_ltext_len`、`eccube.yaml` 確認値3000）。保存先列は最大4000文字 | 既存受注はDB現行値、新規受注は空 | `dtb_order.note`（フォームキー `note`）。複数行入力のテキストエリア。受注編集の保存処理に同梱して永続化する。未入力は許容する。 |

最大長はフォームの Length制約が `eccube_ltext_len`（`app/config/eccube/packages/eccube.yaml` の確認値3000）であり、保存先列 `dtb_order.note` は文字列型で桁4000である。運用環境で `eccube_ltext_len` が上書きされている場合はその環境の値が正とする。出荷用メモ欄（`admin.order.shop_memo_for_shipped`、フォームキーは出荷側の `note`）は本項目とは別であり、本書では扱わない。

### エッジケース

| ケース | 扱い |
|--------|------|
| メモ未入力で登録 | 任意項目のため空のまま保存する。 |
| メモが3000文字を超える | フォームの最大長検証でエラーとなり保存しない。同一編集画面を再表示する。 |
| 改行を含むメモ | 複数行入力のテキストエリアのため改行を含めて保存する。 |
| 受注編集の他項目で検証失敗 | 受注全体が保存されないため、メモも保存されない。入力したメモは再表示される。 |

## データ整合性

| 観点 | 内容 |
|------|------|
| 編集画面と保存値 | 編集画面の初期表示は永続化済みの `dtb_order.note` を読む。保存成功後の再表示も同一列を読むため一致する。 |
| 受注全体との整合 | メモは受注の他項目と同一トランザクション・同一 flush で保存されるため、登録成功時はメモと受注他項目が一括で確定する。途中で検証・購入フローのエラーが起きた場合は受注全体が保存されず、メモも確定しない。 |
| 他画面との整合 | メモを参照する他画面（受注一覧・CSV等）の表示・抽出ルールは各機能の設計を正とする。本書は編集画面での入力・保存のみを扱う。 |
| 同時編集 | 複数管理者が同一受注を同時編集した場合の結果は、受注編集の保存処理（最後にflushされた内容）に従う。メモ専用の排他制御は持たない。 |

## DBカラム

当機能に直接関係する列のみを以下に列挙する。型や一覧の細部はスキーマを参照する。

| テーブル | 列 | メモ |
|----------|-----|------|
| dtb_order | note | ショップ用メモ欄の保存先。文字列型、桁4000、NULL許容。フォーム項目 `note` に対応。 |
| dtb_order | update_date | 受注編集の保存時に更新される。メモ更新もこの保存に含まれる。 |

出荷用メモ欄は出荷側の列に保存され、本表には含めない（M05-17の対象）。

### DB操作

永続化の正は ec-cube-enterprise（テーブル名・操作は ec-cube-enterprise を正典）。当ドメインは承認ワークフローを介さず persist/flush で直接確定する（承認ワークフローは在庫機能固有）。

| 操作種別 | 対象テーブル | 契機・条件 |
|---------|--------------|------------|
| 登録/更新 | dtb_order | 当機能が行う登録・更新で対象テーブルを直接保存する（不要な削除は含まない）。確定は persist/flush による即時反映。DB=ec-cube-enterprise を正典とする。 |

## 排他制御・トランザクション

ショップ用メモは受注編集の保存処理と同一トランザクションで永続化される。メモ専用の楽観ロック・悲観ロックは持たない。同時編集時の結果は受注編集の保存処理（最後にflushされた内容）に従う。
