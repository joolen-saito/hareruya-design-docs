# m09-02_admin_content_content_file（管理画面_コンテンツ管理_ファイル管理）

管理画面のコンテンツ管理にあるファイル管理。公開領域のuser_data配下に対し、画像ファイル等のアップロード、フォルダ作成、ファイル・フォルダの削除、ファイルの表示・ダウンロードを行う。

## 概要

ファイル管理は、管理者がuser_data配下のディレクトリツリーをたどりながら、画像ファイル等のアップロード、フォルダの新規作成、ファイル・フォルダの削除、ファイルの表示とダウンロードを1画面で行うための機能である。アップロードしたファイルは公開URLとして参照でき、各ファイルの公開パスをコピーする補助も持つ。

本書は実装手順ではなく、誰が・いつ・どの条件で・結果どうなるかを読むためのリバース詳細設計とする。既存実装のふるまい、参照するディレクトリ、許可・拒否の判定境界、ディレクトリトラバーサル対策、ファイル名・拡張子の検証、副作用を確認し、仕様の確からしさを把握することを目的とする。

本機能のカスタマイズ区分は標準であり、挙動はec-cube-enterpriseのファイル管理を正とする。本機能はファイル・フォルダをデータベースへ保存しないため、DB関連の永続化記述は持たないが、永続化に関わる記述が生じる場合はec-cube-enterpriseを正典とする。

対象はブラウザ経由の管理画面のファイル管理画面である。操作対象のルート領域はアプリケーションの`html/user_data`配下に固定する。

管理画面プレフィックスは環境変数`ECCUBE_ADMIN_ROUTE`由来の`eccube_admin_route`で決まり、`app/config/eccube/packages/eccube.yaml`の`eccube_admin_route`に展開される。本書では入口節で`%eccube_admin_route%`プレースホルダとして示す。コントローラのメソッド単位の解剖は本文の主題としない。

## 本書で扱うこと

- ファイル管理画面の表示時に、どのディレクトリを起点とし、どの範囲のファイル・フォルダ一覧とディレクトリツリーを表示するか
- ファイルアップロード時の保存先、許可する拡張子、拒否するファイル名・拡張子、同名フォルダ存在時の扱い、複数ファイルの成功件数表示
- フォルダ作成時の名前の検証（使用可能文字、先頭ピリオド禁止、既存名重複）
- ファイル・フォルダ削除時のトークン検証、空フォルダ以外の削除可否、ストレージアダプタへの削除連携
- ファイルの表示（別タブ）とダウンロードの境界、ダウンロード時のファイル名エンコード
- user_data配下に閉じ込めるためのディレクトリトラバーサル対策（`..`を含むパスと領域外パスの拒否）
- アップロード機能の無効化（環境変数によるファイル管理メニュー非表示とアクセス拒否）
- 画面に表示するフォルダツリー・パンくず・パスコピーなどのフロント挙動

## 本書で扱わないこと

以下は本書では仕様確定せず、実装または別機能の設計を正とする。

- Symfonyのroute名・Controllerクラス名・メソッド名の網羅
- 管理画面へのログイン、認証、二段階認証、権限ロール設定の詳細
- ストレージアダプタ（S3等）の接続・認証・同期の内部仕様。本書ではアップロード成功時と削除時にアダプタへ連携する事実のみ扱う
- ブロック管理・ページ管理・CSS管理・JS管理・テンプレート管理など、同じアップロード制限対象に含まれる他機能の詳細
- 画像のサムネイル生成・リサイズ・最適化
- ファイルサイズの上限（PHPやWebサーバ側のアップロード上限）の具体値

## リニューアル移行時の扱い

本機能はカスタマイズ区分が標準であり、挙動はec-cube-enterpriseのファイル管理を正とする。本機能はファイル・フォルダをデータベースへ保存せず、操作対象はファイルシステム（user_data配下）に限られるため、テーブル名・列名の移行差分は持たない。アップロード制限の環境変数（ECCUBE_RESTRICT_FILE_UPLOAD）、許可拡張子（eccube_file_uploadable_extensions）、ストレージアダプタ連携の挙動はec-cube-enterprise実装を正とする。

## 用語

| 用語 | 説明 |
|------|------|
| user_data領域 | 操作対象のルートディレクトリ。アプリケーションの`html/user_data`に固定する。ファイル管理の全操作はこの配下に限定する。 |
| カレントディレクトリ | 一覧表示の対象となっている、user_data領域配下の現在位置。ツリーやパンくず、フォルダ名リンクで移動する。 |
| ディレクトリツリー | 右側に表示する、user_data配下のフォルダ階層。フォルダのみで構成し、ファイルは含めない。 |
| jailパス | 画面表示やリンクに使う、user_data領域の絶対パスを取り除いた相対表現。先頭が空になる場合は`/`として扱う。 |
| 許可拡張子 | アップロードを許可するファイル拡張子の一覧。`eccube_file_uploadable_extensions`で定義する。 |
| アップロード制限 | 環境変数`ECCUBE_RESTRICT_FILE_UPLOAD`を1にすると、ファイル管理を含むアップロード系URLをメニューから外し、アクセスを拒否する仕組み。 |

## 利用者視点の入口

管理画面プレフィックスは環境変数で決まるため、以下はサイトルートからのパスパターンで示す。

| 入口 | URLエンドポイント | 期待されるふるまい |
|------|--------------------|--------------------|
| ファイル管理画面を開く | `GET /%eccube_admin_route%/content/file_manager` | user_data領域を起点に、カレントディレクトリのファイル・フォルダ一覧、ディレクトリツリー、パンくずを表示する。アップロード欄とフォルダ作成欄も表示する。 |
| フォルダへ移動 | `POST /%eccube_admin_route%/content/file_manager` | 選択したフォルダをカレントディレクトリとして同画面を再表示する。`mode`は空（移動）で送信する。 |
| ファイルをアップロード | `POST /%eccube_admin_route%/content/file_manager` | `mode=upload`で送信し、選択したファイルをカレントディレクトリへ保存する。成功件数を表示し、検証に外れたファイルはエラー文を表示する。 |
| フォルダを作成 | `POST /%eccube_admin_route%/content/file_manager` | `mode=create`で送信し、入力したフォルダ名でカレントディレクトリ配下に新規フォルダを作成する。 |
| ファイル・フォルダを削除 | `DELETE /%eccube_admin_route%/content/file_delete` | なりすまし対策トークン検証後、対象がuser_data配下なら削除し、削除時のカレントディレクトリで一覧へ戻る。 |
| ファイルを表示 | `GET /%eccube_admin_route%/content/file_view?file=...` | 対象ファイルがuser_data配下なら別タブでファイル内容を返す。領域外なら見つからない（HTTP404）として扱う。 |
| ファイルをダウンロード | `GET /%eccube_admin_route%/content/file_download?select_file=...` | 対象がuser_data配下のファイルなら添付ファイルとしてダウンロードさせる。フォルダや領域外は見つからない（HTTP404）として扱う。 |
| アップロード制限が有効な状態でアクセス | 上記の各URL | アップロード制限が有効なとき、ファイル管理メニューを表示せず、URLへ到達してもアクセス拒否（HTTP403）として扱う。 |
| 非管理者・未認証 | 上記の管理側URL | 管理画面の認証要件に従い、本画面に到達できない。 |

ファイルの表示・ダウンロードのリンクは、一覧の各ファイル行から開く。フォルダ移動・アップロード・フォルダ作成は同一URL（file_manager）への`mode`付きPOSTで処理する。

## フロント挙動

| 観点 | 内容 |
|------|------|
| 表示要素 | 画面上部に「ファイル・フォルダを追加」カード（ファイル選択欄とアップロードボタン、フォルダ名入力欄と作成ボタン）、その下にパンくず、左側に「このフォルダ内のファイル」一覧、右側に「フォルダ構成」ツリーを表示する。一覧の各行はアイコン、名前、サイズ、更新日時、操作ボタンで構成する。 |
| 一覧の表示分け | フォルダ行はフォルダアイコンと名前リンク（押下で移動）を表示し、操作は削除のみとする。ファイル行は拡張子に応じたアイコン（画像拡張子はサムネイル背景）と、パスコピー・表示・ダウンロード・削除の操作を表示する。トップ階層以外では、一覧先頭に親ディレクトリへ戻る行を表示する。 |
| ファイル選択欄 | 複数ファイル選択に対応する（`multiple`）。アップロードボタン押下で`mode=upload`をフォームに設定して送信する。 |
| フォルダ作成欄 | フォルダ名のテキスト入力。作成ボタン押下で`mode=create`をフォームに設定して送信する。プレースホルダは「フォルダ名」。 |
| ディレクトリツリー | サーバから渡すツリーデータをもとに、user_dataを根としたフォルダ階層をJavaScriptで構築する。フォルダ名押下で当該フォルダへ移動（`tree_select_file`に設定して送信）する。フォルダのみ表示し、ファイルは含めない。 |
| パンくず | カレントディレクトリのパスを分解し、各階層をリンクとして表示する。階層押下で当該フォルダへ移動する。 |
| パスコピー | ファイル行のコピーボタン押下で、公開URL入力欄を表示してフォーカスし、ブラウザのコピーを実行する。コピー後はツールチップを「パスをコピーしました」相当の文言へ切り替える。 |
| 削除モーダル | 削除ボタン押下でモーダルを開き、対象名を含む確認文を表示する。モーダルの削除ボタンは削除URLへトークン付きでDELETE相当のリクエストを送る。空でないフォルダの削除ボタンは無効化（disabled）して押せない。 |
| ドラッグ操作 | ドラッグ＆ドロップによるファイル移動・アップロードは実装しない。 |

### フロントエンド側ビジネスロジック

| 起点 | 参照する値 | 判定順序 | 更新する表示値・送信値 | サーバ側再検証 |
|------|------------|----------|--------------------------|----------------|
| ディレクトリツリーのフォルダ押下 | ツリー上のフォルダパス | 選択フォルダを現在位置として扱い、移動用のhidden値に設定する。 | `tree_select_file`に対象フォルダを設定して送信する。 | 対象パスが許可ルート配下か、存在するか、操作可能かをサーバ側で判定する。 |
| パンくず押下 | パンくずの階層パス | 押下した階層を移動先として扱う。 | 移動先パスを送信値に設定する。 | 許可ルート外への移動、存在しないパス、ファイル指定はサーバ側で排除する。 |
| パスコピー押下 | 対象ファイルの公開URL | URL入力欄を表示してフォーカスし、ブラウザのコピー処理を実行する。 | 画面上のツールチップ文言をコピー完了表示に切り替える。送信値は更新しない。 | 再検証なし。ファイルの存在と表示URLは画面表示時点のサーバ生成値を正とする。 |
| 削除ボタン押下 | 対象名、削除URL、フォルダ空判定 | 空でないフォルダなら削除ボタンを押せない。押せる対象では削除確認モーダルを開く。 | モーダルの確認文と削除実行先を対象用に差し替える。 | 対象の存在、ディレクトリ空判定、削除権限、トークンはサーバ側で再判定する。 |
| アップロードファイル選択 | ファイル入力の選択ファイル | ブラウザ側ではファイル選択のみ行う。 | ファイル入力の送信値を設定する。 | サイズ、拡張子、保存先、上書き可否はサーバ側で検証する。 |

## 処理フロー

### ファイル管理画面の表示

1. 管理者がファイル管理画面を開く。
2. アップロード制限の案内を一度だけ情報メッセージとして表示する。
3. カレントディレクトリを決める。`tree_select_file`で指定された相対パスがuser_data配下であればそのディレクトリ、そうでなければuser_data領域のトップを起点とする。
4. ディレクトリツリー（user_data配下のフォルダ階層）と、カレントディレクトリ直下のファイル・フォルダ一覧、パンくず用データを組み立てる。
5. 一覧はカレントディレクトリ直下（深さ0）のフォルダとファイルを名前順に並べる。各フォルダには空かどうかの判定を付与する。各ファイルにはサイズ・更新日時・拡張子を付与する。
6. 画面を表示する。

### フォルダ移動

1. 利用者がツリーのフォルダ名、パンくず、または一覧のフォルダ名を押下する。
2. 移動先パスを`tree_select_file`に設定して`mode`空でPOST送信する。
3. サーバは移動先がuser_data配下であることを確認し、当該ディレクトリをカレントディレクトリとして一覧・ツリーを再表示する。配下でなければトップを起点に戻す。

### ファイルアップロード

1. 利用者がファイルを選択し、アップロードボタンを押下する。`mode=upload`でPOST送信する。
2. ファイル未選択のときは「選択されていません」を表示して終了する。
3. 保存先はカレントディレクトリ（`now_dir`）とする。`now_dir`がuser_data配下でなければアップロード先不正としてエラーを表示し終了する。
4. 選択ファイルごとに次を検証する。順序は、同名フォルダ存在チェック、ファイル名の使用可能文字チェック、先頭ピリオド禁止チェック、拡張子の許可チェックとする。いずれかに外れたファイルはエラー文言を記録し、そのファイルをスキップする。同一文言は重複して表示しない。
5. 検証を通ったファイルをカレントディレクトリへ保存し、ストレージアダプタへもアップロードする。保存に失敗したファイルはアップロード失敗の文言を記録する。
6. 成功件数が1件以上のとき、「○件のファイルをアップロードしました。(成功/選択件数)」を成功メッセージとして表示する。

### フォルダ作成

1. 利用者がフォルダ名を入力し、作成ボタンを押下する。`mode=create`でPOST送信する。
2. フォルダ名を検証する。空のとき、使用できない文字を含むとき、ピリオドで始まるときは、それぞれのエラー文言を表示して終了する。
3. 作成先はカレントディレクトリ（`now_dir`）とし、user_data配下でなければトップを起点とする。
4. 同名のファイル・フォルダが既に存在するときは「既に使用されています」を表示して終了する。
5. 重複がなければフォルダを作成し、「作成しました」を表示する。作成に失敗したときはアップロード失敗の文言を表示する。

### ファイル・フォルダ削除

1. 利用者が一覧の削除ボタンを押下し、モーダルの削除を確定する。削除URLへトークン付きでDELETE相当のリクエストを送る。
2. なりすまし対策トークンを検証する。
3. 対象パスが空、未指定、または`/`のときは、削除せずファイル管理画面へ戻る。
4. 対象がuser_data配下であることを確認する。配下のとき、ファイルシステム上に存在すればストレージアダプタからの削除とファイルシステムからの削除を行い、「削除しました」を表示する。あわせて選択パスに対応するアダプタ側エントリも削除する。
5. 削除実行時のカレントディレクトリ（対象の親ディレクトリ）を表示するよう、ファイル管理画面へ戻る。

### ファイル表示

1. 利用者がファイル行の表示ボタンを押下する。別タブで表示URLを開く。
2. 対象ファイルがuser_data配下であればファイル内容をそのまま返す。配下でなければ見つからない（HTTP404）として扱う。

### ファイルダウンロード

1. 利用者がファイル行のダウンロードボタンを押下する。
2. 対象がuser_data配下かつディレクトリでないファイルのとき、添付ファイルとしてダウンロードさせる。ファイル名に通常文字以外しか含まれない場合は記号類を除去した結果が空になるため、ファイル名指定なしの添付として返す。それ以外はUTF-8でエンコードしたファイル名を付けて返す。
3. 対象がフォルダ、または領域外のときは見つからない（HTTP404）として扱う。

| アップロード制限が有効な状態でのアクセス | ファイル管理画面に到達せず、アクセス拒否（HTTP403）として扱う。 |

|---|---|---|---|---|---|

## 業務ルール・計算

| 項目 | 内容 |
|------|------|
| 操作領域の固定 | 全操作の対象ルートをuser_data領域（`html/user_data`）に固定する。カレントディレクトリ・移動先・アップロード先・削除対象・表示/ダウンロード対象は、いずれもこの配下であることを確認してから処理する。 |
| ディレクトリトラバーサル対策 | 対象パスに`..`を含む場合は領域外とみなして拒否する。実パスがuser_data領域の実パスで始まらない場合も領域外として拒否する。 |
| フォルダ名の使用可能文字 | 英数字、アンダースコア、ピリオド、ハイフンのみを許可する。これら以外を含むと使用できない文字として拒否する。 |
| フォルダ名の先頭ピリオド禁止 | ピリオドで始まる名前は拒否する。 |
| フォルダ名の必須 | フォルダ名は空にできない。 |
| アップロードファイル名の使用可能文字 | 英数字、半角スペース、アンダースコア、ハイフン、ピリオド、丸括弧のみを許可する。これら以外を含むと拒否する。 |
| アップロードファイルの先頭ピリオド禁止 | ピリオドで始まるファイルは拒否する。 |
| 許可拡張子 | 小文字化した拡張子が許可一覧に含まれるファイルのみアップロードできる。許可一覧は`eccube_file_uploadable_extensions`で、jpg, jpeg, png, gif, webp, svg, ico, html, htm, js, css, txt, pdfとする。一覧は設定で上書きできる。 |
| 同名フォルダとの衝突 | アップロードファイル名と同名のフォルダがカレントディレクトリに存在するとき、そのファイルはアップロードしない。 |
| 削除対象の制限 | 空・未指定・`/`の選択は削除しない。フォルダは空でない場合、画面上の削除ボタンを無効化して削除させない。 |
| 成功件数表示 | アップロードは選択ファイルごとに検証し、成功件数と選択件数を「成功/選択」の形で表示する。 |
| 計算 | 金額計算・税計算・丸めは行わない。ファイルサイズは人が読める単位へ整形して表示する。 |

### 入力項目

| 項目名 | 必須／任意 | 最大長 | 初期値 | 保存先・扱い |
|--------|------------|--------|--------|----------------|
| ファイルを追加 | アップロード操作時は必須 | 拡張子は許可一覧（jpg, jpeg, png, gif, webp, svg, ico, html, htm, js, css, txt, pdfの13種）に限定。サイズ上限はPHP・Webサーバ設定に依存し本書では確定しない | 未選択 | フォームキー`file`。複数選択可。カレントディレクトリ（`now_dir`）配下へ原ファイル名で保存し、あわせてストレージアダプタへアップロードする。ファイル名は英数字・半角スペース・`_-.()`のみ許可し、先頭ピリオド・同名フォルダ・許可外拡張子は保存しない。未選択時は「選択されていません」。 |
| フォルダを追加 | フォルダ作成操作時は必須 | 文字数の上限はフォーム上で課さない。ファイルシステムのフォルダ名上限に依存 | 空 | フォームキー`create_file`。テキスト入力。カレントディレクトリ配下に同名フォルダを作成する。英数字・アンダースコア・ピリオド・ハイフンのみ許可、先頭ピリオド禁止、空不可、既存名と重複不可。永続化はファイルシステム上のディレクトリ作成で、DBには保存しない。 |

ファイルとフォルダの登録先はデータベースではなくファイルシステム（user_data配下）である。アップロードしたファイルはストレージアダプタにも連携する。

### エッジケース

| ケース | 扱い |
|--------|------|
| カレントディレクトリ指定が領域外・`..`を含む | 領域外として扱い、user_data領域のトップを起点に表示する。 |
| アップロード先（`now_dir`）が領域外 | アップロード先不正のエラーを表示し、保存しない。 |
| 複数ファイルの一部が検証に外れる | 外れたファイルのみスキップし、通ったファイルは保存する。成功件数は実際に保存できた件数を表示する。 |
| 同一の検証エラーが複数ファイルで発生 | 同一文言は1回だけ表示する。 |
| 同名ファイルの再アップロード | ファイル名の重複を妨げず、同名で上書き保存する（同名フォルダがある場合のみ拒否）。 |
| フォルダ作成で同名のファイル・フォルダが既存 | 「既に使用されています」を表示し作成しない。 |
| 空でないフォルダの削除 | 画面上で削除ボタンを無効化する。 |
| 削除対象が`/`・空・未指定 | 削除せずファイル管理画面へ戻る。 |
| ダウンロード対象名が記号類のみで整形後に空 | ファイル名指定なしの添付としてダウンロードさせる。 |
| 表示・ダウンロードで領域外・存在しないパス | 見つからない（HTTP404）として扱う。 |

## データ整合性

| 観点 | 内容 |
|------|------|
| 参照時点 | 一覧・ツリーは画面表示時にファイルシステムを走査した結果である。表示後に他操作でファイルが増減しても、表示中の一覧は自動更新しない。 |
| ファイルシステムとアダプタの整合性 | アップロード成功時はファイルシステムとストレージアダプタの双方へ書き込む。削除時は双方から削除する。アダプタ側に対象が存在しない削除では、その旨をログに残しファイルシステムの削除は続行する。両者の完全同期は本書では保証しない。 |
| 同名処理 | フォルダ作成は同名重複を拒否する。ファイルアップロードは同名フォルダのみ拒否し、同名ファイルは上書きとなる。 |
| 公開URLとの整合性 | パスコピーや表示・ダウンロードで参照する公開パスは、user_data配下の相対パス（jail表現）に基づく。実体ファイルの有無は参照時点のファイルシステムに従う。 |

## API/バッチ結果

| 種類 | 内容 |
|------|------|
| API | 本機能は外部公開APIを提供しない。アップロード成功時と削除時に、内部のストレージアダプタへファイルのアップロード・削除を依頼する。 |
| バッチ | 本機能はバッチを起動しない。 |
| 失敗時 | ファイル保存の失敗はアップロード失敗の文言を表示する。アダプタ側に削除対象が存在しない場合はログに記録し、ファイルシステムの削除は続行する。 |

## 入出力

| 種類 | 内容 |
|------|------|
| 入力 | ファイル管理画面の表示要求、フォルダ移動・アップロード・フォルダ作成のPOST、削除のDELETE、表示・ダウンロードのGET。アップロードはmultipart形式でファイルを受け取る。 |

## DBカラム

本機能はファイル・フォルダをデータベースに保存しない。操作対象はファイルシステム（user_data配下）であり、当機能に直接対応するテーブル・列は持たない。

## バリデーション

| 項目 | 内容 |
|------|------|
| フォルダ名（作成） | 空不可。英数字・アンダースコア・ピリオド・ハイフンのみ許可。ピリオドで始まる名前は不可。既存の同名ファイル・フォルダがある場合は不可。 |

## 画面遷移

| 条件 | 遷移先 |
|------|--------|
| ファイル管理画面を開く | 同一画面にカレントディレクトリの一覧・ツリーを表示。 |
| フォルダ名・ツリー・パンくずを押下 | 当該フォルダをカレントディレクトリとして同画面を再表示。 |
| アップロード・フォルダ作成を実行 | 同画面を再表示し、結果メッセージを表示。 |
| 削除を実行 | 削除時のカレントディレクトリ（対象の親）でファイル管理画面を再表示。 |
| 表示を押下 | 別タブでファイル内容を表示。 |
| ダウンロードを押下 | 添付ファイルとしてダウンロード。画面は遷移しない。 |

### 遷移時に引き継ぐ状態

| 起点 | 遷移前の処理 | 遷移後の初期状態 |
|------|--------------|------------------|
| フォルダ移動・アップロード・作成 | カレントディレクトリ（`tree_select_file`／`now_dir`）とツリー開閉状態（`tree_status`）をフォームで送る。 | 送ったカレントディレクトリを起点に一覧・ツリーを再表示する。 |
| 削除 | 対象の親ディレクトリを`tree_select_file`に設定してリダイレクトする。 | 親ディレクトリをカレントディレクトリとして一覧を表示する。 |

各遷移は通常の管理画面内ページ遷移として扱う。表示のみ別タブで開く。

## エラー処理

| エラー内容 | 処理 |
|------------|------|
| ファイル未選択 | 「選択されていません」を表示し保存しない。文言は表示メッセージ節を正とする。 |
| フォルダ名の検証違反 | 使用不可文字・先頭ピリオド・空・重複に応じた文言を表示し作成しない。 |
| アップロードファイルの検証違反 | 同名フォルダ・使用不可文字・先頭ピリオド・許可外拡張子に応じた文言を表示し当該ファイルをスキップする。 |
| 保存・作成の失敗 | アップロード失敗の文言を表示し、内部エラーをログに記録する。 |
| アップロード先・操作先が領域外 | アップロードはアップロード先不正を表示。表示・ダウンロード・削除は見つからない（HTTP404）または無処理として扱う。 |
| なりすまし対策トークン不正（削除） | トークン検証に失敗した削除は実行しない。 |
| アップロード制限が有効なアクセス | アクセス拒否（HTTP403）として扱う。 |

## ログ・監査

| タイミング | 記録内容 |
|------------|----------|
| アップロード保存の失敗 | 失敗の内部メッセージをログに記録する。 |

### ログに出してはいけないもの

- なりすまし対策トークンの原値
- セッション識別子の完全値
- Cookie値
- ファイル内容そのもの

## セッション

| 観点 | 内容 |
|------|------|
| アップロード制限の案内 | 情報メッセージを一度だけ表示するため、フラッシュメッセージのセッション領域を用いる。 |
| 結果メッセージ | アップロード・作成・削除の成功はフラッシュメッセージとしてセッション経由で表示する。 |
| カレントディレクトリ | カレントディレクトリやツリー開閉状態は、セッションではなくフォームの隠しフィールド（`tree_select_file`・`now_dir`・`tree_status`）で引き継ぐ。 |

## Cookie

本機能はファイル管理のために新たなCookieを設定しない。ブラウザのセッションCookieはフレームワークおよび管理画面全体の認証に用いられる。

---

## 排他制御・トランザクション

本機能はファイルシステムとストレージアダプタを操作し、データベースの楽観ロック・悲観ロックは対象としない。複数管理者が同時にアップロード・作成・削除する場合の競合は、ファイルシステムおよびアダプタの整合に依存し、本書ではロックによる排他を保証しない。
