# バッチ イベント管理 — コンビニ支払チェックバッチ

## 概要

コンビニ決済で入金待ちのイベント申込を対象に、決済サービスへ取引状況を照会して申込みステータスを整合させるバッチである。コマンドライン（コンソールコマンド）から実行する。照会結果に応じてステータスを更新または申込みを取り除き、想定外のエラーは管理者へまとめて通知する。

本書は実装手順ではなく、誰が・いつ・どの条件で・結果どうなるかを読むためのリバース詳細設計とする。確認値はpf-eccube3（EC-CUBE3系）のHareruyaEcプラグインの決済チェックバッチ（コンビニ支払チェック処理）、イベント申込を扱うリポジトリ、決済照会・申込履歴処理、エラー通知メール送信処理を正とする。

本機能のカスタマイズ区分は現行踏襲であり、挙動の確認はpf-eccube3を参照し、DB関連の記述はec-cube-enterpriseを正とする。

対象はコンソールコマンドであり、ブラウザ経由の画面を持たない。

本文ではフレームワークのコマンド型名やサービス型名を主説明としない。実行はコンソールのバッチコマンドで行う。

## リニューアル移行時の扱い

現行（pf-eccube3のHareruyaEcプラグイン）と移行先（ec-cube-enterprise）の差を記録する。永続化先の正典はec-cube-enterpriseとする。

| 観点 | 現行（pf-eccube3） | 移行先（ec-cube-enterprise） |
|------|--------------------|------------------------------|
| イベント申込テーブル | dtb_event_entry | dtb_event_entry（同名・概ね同一スキーマ） |
| イベント申込の主キー列 | event_entry_id | id |
| 申込履歴テーブル | dtb_entry_history | dtb_entry_history（同名・概ね同一スキーマ） |
| 申込ステータス列 | entry_status_id（ステータスマスタ参照） | entry_status_id（同一） |
| 決済番号列 | payment_no | payment_no（同一） |
| 決済種別 | payment_id（決済参照） | payment_id（同一） |
| 論理削除 | deleted_at | deleted_at（同一） |
| バッチ起動方式 | コンソールコマンド `entry:batch checkCvsPayment` | ec-cube-enterprise実装で要確認 |

イベント申込・申込履歴のテーブルは現行と移行先で同名・概ね同一スキーマであり、主キー列名のみ差がある。バッチの起動方式（コマンド名・実行基盤）は移行先で異なる可能性があり、ec-cube-enterprise実装で要確認とする。

## 処理フロー

### コンビニ支払チェックを実行する（`entry:batch checkCvsPayment`）

1. コンビニ決済で入金待ちのイベント申込を抽出する。
2. 対象が0件の場合は、対象が無い旨を返して終了する。
3. 申込みごとに決済サービスへ取引を照会し、結果のメッセージと新ステータスを得る。
4. 取引が存在しない場合は当該申込みの記録を取り除く。入金が確認できた場合は新ステータスへ更新する。
5. 直前と同じ決済番号の申込みは、前回の照会結果に従って同様の処理を行う。
6. 取引不在・未完了以外の想定外エラーは1つにまとめ、管理者へ通知メールを送信する。
7. 申込履歴を記録し、更新を確定する。

## DBカラム

機能に直接関係する列のみ記載する。型や一覧の細部はスキーマを参照する。

列名はec-cube-enterpriseを正とし、現行（pf-eccube3）と異なる場合は括弧で添える。

| テーブル | 列 | メモ |
|---------|-----|------|
| dtb_event_entry（イベント申込） | entry_status_id（申込ステータス）・payment_no（決済番号）・payment_id（決済種別） | 抽出・照会・更新に使用する。 |
| dtb_entry_history（申込履歴） | event_entry_id（申込み参照）・entry_status_id | 処理結果を記録する。 |

### DB操作

本機能は参照系（検索）であり、DBへの登録・更新・削除は行わない。テーブル名は ec-cube-enterprise を正典とする。

| 操作種別 | 対象テーブル | 契機・条件 |
|---------|--------------|------------|
| 検索 | dtb_entry_history / dtb_event_entry | 検索条件に合致するレコードを抽出する。 |

## エラー処理

| エラー内容 | 処理 |
|------------|------|
| コマンド名が未指定・不一致 | 処理を行わずに終了する。 |
| 対象0件 | 対象が無い旨を返して終了する。 |
| 取引不在・未完了 | 記録の除去等の所定処理を行い、メッセージを収集する。 |
| 想定外エラー | 重複を除いてまとめ、管理者へ通知する。 |
