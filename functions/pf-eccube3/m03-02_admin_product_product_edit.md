# M03-02（商品編集機能）

## 概要

商品編集機能は、管理画面の商品管理で既存商品の基本データ（商品名・販売価格・各種コメント・SHOP専用備考欄など）を1画面で読み込んで更新する機能である。商品の新規登録は本プラグインの運用では廃止されており、編集（更新）が本書の対象である。

本書は実装手順ではなく、誰が・いつ・どの条件で・結果どうなるかを読むためのリバース詳細設計とする。既存実装のふるまい、参照するデータ、判定境界、永続化、副作用を確認し、仕様の確からしさを把握することを目的とする。

本機能のカスタマイズ区分は「カスタマイズ」であり、画面の挙動・入力検証の参照は現行リポ（pf-eccube3）、DB関連（テーブル名・列名・保存先・扱い）は ec-cube-enterprise を正とする。

対象はブラウザ経由の管理画面の商品編集画面（商品基本情報の表示と更新）である。商品規格（価格・在庫・状態などの規格単位データ）の登録・編集は別機能（M03-09）とし、本書では正としない。商品画像の追加用XHR、カード詳細検索モーダル、複製・削除・確認ボタンの遷移先処理本体は概要に留める。

管理画面プレフィックスは設定キー`admin_route`で決まる。ルート定義は`/'.$app['config']['admin_route'].'/...`の形でパスを組み立てるため、本書ではパスを`{admin_route}`で表す。コントローラのメソッド名・ルートbind名は本文の主説明としない。

---

## 本書で扱うこと

- 商品編集画面表示時に、商品本体と商品付加情報（商品サブ）の現行値がフォームへ載るふるまい
- 編集画面で更新できる基本情報の入力項目、必須・任意、保存先
- 更新送信時の処理順序（カテゴリ・画像・タグ・売上分析タグの再登録、支店システム連携、成功時の遷移）
- 商品ステータス欄が規格の有無により表示・非表示で切り替わること
- 新規登録が運用上廃止されていること、および編集画面に残る複製・削除・確認・規格設定の導線の役割

---

## 本書で扱わないこと

以下は本書では仕様確定せず、実装または別機能の設計を正とする。

- 商品規格（販売価格・買取価格・在庫・状態など規格単位）の登録・編集（M03-09を正とする）
- 商品検索一覧、検索条件セッション、ページング、一括更新、CSV取込・出力
- 商品画像のS3保存方式、一時ディレクトリの仕様、画像順序の内部表現
- カード詳細検索モーダルのカード検索ロジック、ヒット結果の表示仕様
- 商品の複製・削除・フロント確認表示の各遷移先処理本体
- 支店システム連携APIの通信仕様・失敗時リトライ
- 商品種別（通常・ダウンロード等）による販売情報の分岐

## リニューアル移行時の扱い

現行（pf-eccube3）と移行先（ec-cube-enterprise）で、編集・保存対象の永続化スキーマに次の差がある。画面の挙動は現行を正とし、DB列名・保存先は移行先を正とする。

### Excel基本設計により廃止された仕様（刷新後は実装不要）

本書は現行実装からのリバースであり、以下は現行挙動として記述しているが、Excel基本設計が廃止を宣言している。刷新後は実装しない。

- 複製ボタン（※Excel基本設計 0204 識別ID:26 により廃止。刷新後は実装しない）。削除。

| 対象 | 現行（pf-eccube3） | 移行先（ec-cube-enterprise） |
|------|----------------------|--------------------------------|
| 商品付加情報 | 別テーブル `dtb_product_sub`（商品名（英）・各説明（英・買取）・カード詳細参照・購入グループ・略称タグ・割引率・買取減額率・販売制限・サイズ・重量など）に分離 | `dtb_product` 本体へ統合。`name_en`・`description_detail_en`・`buy_description_detail`・`buy_description_detail_en`・`card_detail_id`・`sell_group_id`・`storage_code_id`・`discount_id`・`buy_discount_id`・`region_restriction_id`・`size`・`weight`・`cardset_id` を商品本体が直接保持し、`dtb_product_sub` は存在しない |
| カード詳細参照 | `dtb_card_detail` を参照 | カード詳細マスタ `mtb_card_detail` を `dtb_product.card_detail_id` から参照 |
| 商品タグ | `dtb_product_tag.tag`（タグ列） | `dtb_product_tag.tag_id`（FK列） |
| 商品カテゴリの並び順 | `dtb_product_category.rank` を保持 | `dtb_product_category` は `rank` 列を持たず、本店／支店を表す `base_info_id` を持つ。並び順列は移行先では持たない |
| 商品画像の並び順 | `dtb_product_image.rank` | `dtb_product_image.sort_no` |

並び順キー（現行 `rank`／移行先 `sort_no`）と、カテゴリの並び順列廃止に注意する。`dtb_product` 本体の `name`・`description_detail`・`search_word`・`free_area`・`note`・`product_status_id`・`update_date` は現行と移行先で同一スキーマである。

## 用語

| 用語 | 説明 |
|------|------|
| 商品本体 | 商品ID・商品名・商品説明・カテゴリ・タグ・検索ワード・ステータス・ショップ用メモなど、コア商品テーブルが持つ基本データ。 |
| 商品付加情報 | 本プラグインが商品に付与する拡張データ。商品名（英）、各説明（英・買取）、カード詳細情報、購入グループ、サイズ、重量、割引率、買取減額率、販売制限、略称タグ、売上分析タグなどを持つ。現行（pf-eccube3）は別テーブル `dtb_product_sub` に対応し、移行先（ec-cube-enterprise）は `dtb_product` 本体へ統合する。 |
| カード詳細情報 | 商品に紐づくカードの版・レアリティ等を指す参照。商品編集画面ではモーダルで指定し、隠しフィールドにIDを保持する。 |
| SHOP専用備考欄 | 画面右下のショップ用メモ欄。フロントへ出さない管理用メモを保存する。 |
| 規格設定 | 商品規格（規格単位の価格・在庫・状態）の編集導線。本画面からは別画面へ遷移する。 |

## 利用者視点の入口

| 入口 | URLエンドポイント | 期待されるふるまい |
|------|--------------------|--------------------|
| 商品編集画面を開く | `GET /{admin_route}/product/product/{id}/edit` | 指定IDの商品本体と商品付加情報を読み込み、基本情報フォームに現行値を載せて表示する。商品が存在しなければ見つからない（HTTP404）。 |
| 商品を登録（更新）ボタン押下 | `POST /{admin_route}/product/product/{id}/edit/update` | 入力値を検証し、合格時に基本情報・カテゴリ・画像・タグ・売上分析タグを保存し、更新完了後に同じ編集画面へ戻す。 |
| 商品画像の追加（非同期） | `POST /{admin_route}/product/product/image/add` | XHRで画像ファイルを受け取り、一時ディレクトリへ保存してファイル名をJSONで返す。XHR以外・非画像・ファイルなしは不正要求として拒否する。 |
| 規格設定へ遷移 | `GET /{admin_route}/product/product/{id}/class/list` | 商品規格一覧へ遷移する。規格の編集はM03-09を正とする。 |
| 新規登録画面 | `GET /{admin_route}/product/product/new` | 実装上はルートが残るが、運用では新規登録を廃止している。本書では編集を対象とする。 |

新規登録の送信ルート`POST /{admin_route}/product/product/new/create`は編集と同一の更新処理を共有する実装だが、運用では新規登録を行わない方針である。

## フロント挙動

| 観点 | 内容 |
|------|------|
| 表示要素 | 左カラムに基本情報カードとフリーエリアカード、右カラムに商品ステータス・各操作ボタン・登録日／更新日・ショップ用メモ欄を表示する。商品IDは更新時のみ表示する。 |
| JS 挙動 | 商品画像はドラッグ＆ドロップとファイル選択でアップロードでき、追加用XHRで一時保存後にサムネイルへ反映する。画像はソート可能で並び順を隠しフィールドに保持する。タグは開閉アコーディオンで選択欄を表示する。カード指定ボタンでカード検索モーダルを開く。フリーエリアはWYSIWYGエディタとして表示する。 |
| CSS・レイアウト | 横型Bootstrapフォームテーマ。画像ドロップ領域は写真用の枠で表示する。 |
| モーダル・ポップアップ | カード検索モーダルをカード指定ボタンで開く。モーダル内で検索し、選択したカード詳細のIDを隠しフィールドへ反映する。複製・削除ボタンは確認ダイアログ文言を伴う。 |
| 商品ステータスの表示切替 | 商品ステータス欄は、商品に規格が1件以上ある場合のみ表示する。規格が無い場合は`display: none`で隠す。 |

## 処理フロー

### 商品編集画面を表示する

1. 利用者が商品編集画面を開く。
2. 商品IDから商品付加情報を読み込み、見つからなければ見つからない（HTTP404）とする。
3. 商品本体・商品付加情報を編集フォームへ束ね、登録済みの画像ファイル名・カテゴリ・タグ・売上分析タグを各欄の初期値として設定する。
4. 商品に規格があるかを判定し、商品ステータス欄の表示・非表示に用いる。
5. 商品付加情報のカード詳細から日本語のカードラベルを組み立てて表示する。
6. 検索フォーム・カード詳細検索モーダル用フォームを併せて生成し、画面を表示する。

### 商品を更新する

1. 利用者が商品を登録（更新）ボタンを押下する。
2. 編集フォームへ入力値を受け取り、検証する。
3. 検証に失敗した場合は、同じ編集画面を再表示する（入力値とエラーを保持）。
4. 検証に合格した場合、カード詳細IDの指定があれば該当カード詳細を商品付加情報へ設定する。
5. 商品本体と商品付加情報を永続化対象にする。
6. 商品カテゴリを一度全削除してから、選択カテゴリとその上位カテゴリを採番付きで再登録する。
7. 追加画像をS3へアップロードし、カード由来画像をコピーし、画像レコードを登録し、削除対象画像を除去する。
8. 画像の並び順を登録する。
9. 商品タグを一度全削除してから、選択タグを重複排除して再登録する。
10. 売上分析タグを選択内容で置き換える。
11. 商品本体の更新日時を現在時刻にし、永続化を確定する。
12. 支店システムへ当該商品の更新を通知する。
13. 「登録が完了しました。」の成功フラッシュを設定し、同じ商品の編集画面へリダイレクトする。

### 商品画像を追加する（非同期）

1. XHR以外の要求は不正要求（HTTP400）とする。
2. アップロードファイルが配列で存在しない、または0件なら不正要求（HTTP400）とする。
3. 各ファイルのMIMEが画像以外なら対応していないメディア種別（HTTP415）とする。
4. 元拡張子を保ったユニークなファイル名で一時ディレクトリへ移動し、ファイル名一覧をJSONで返す。

## 業務ルール・計算

| 項目 | 内容 |
|------|------|
| カテゴリ再登録 | 更新のたびに既存の商品カテゴリを全削除し、選択カテゴリと各上位カテゴリを一意化して採番付きで登録し直す。 |
| タグ再登録 | 更新のたびに既存の商品タグを全削除し、選択タグを重複排除して登録し直す。 |
| 売上分析タグ | 選択された売上分析タグの集合で既存内容を置き換える。 |
| 画像並び順 | 送信された並び順情報をもとに各画像レコードの並び順を更新する。 |
| 商品ステータス表示 | 規格が1件以上ある商品のみステータス欄を表示する。規格が無い間は公開操作をさせない。 |
| 金額・在庫計算 | 本画面では販売価格・在庫の計算や丸めを行わない。価格・在庫は商品規格（M03-09）で扱う。 |
| 新規登録 | 編集と同一の更新処理を新規登録ルートが共有するが、運用では新規登録を廃止している。 |

### エッジケース

| ケース | 扱い |
|--------|------|
| 規格を持たない商品 | 商品ステータス欄を隠す。基本情報の保存自体は可能。 |
| 商品カテゴリ未選択 | `NotBlank`違反として検証失敗。同じ編集画面を再表示する。 |
| 追加直後に削除した画像 | 削除対象として送信されても対応する画像レコードが無いため、その画像はスキップする。 |
| カード詳細ID未指定 | 商品付加情報のカード詳細を更新しない。 |
| 売上分析タグを空で送信 | 送信内容（空集合）で置換する。 |

## データ整合性

| 観点 | 内容 |
|------|------|
| 参照時点 | 編集画面表示時にDBから読み取った商品本体・付加情報・関連（カテゴリ・タグ・画像・売上分析タグ）の現行値を初期表示する。 |
| カテゴリ・タグの整合性 | 更新時は全削除後に再登録するため、送信内容が確定値となる。送信に含まれない既存カテゴリ・タグは残らない。 |
| 画像との整合性 | 追加・コピー・削除・並び順の各操作を反映後に永続化する。S3への保存と画像レコード登録は同一更新処理内で行う。 |
| 一覧・規格との整合性 | 一覧の表示値、規格単位の価格・在庫・状態との一致は本画面の責務外であり、商品検索一覧・M03-09を正とする。 |
| 支店連携との整合性 | 更新確定後に支店システムへ更新通知する。支店側への反映タイミングは支店連携機能の設計を正とする。 |

---

## API/バッチ結果

| 種類 | 内容 |
|------|------|
| API | 更新確定後に支店システムへ当該商品の更新を通知する。商品画像追加はXHRで一時保存しファイル名をJSONで返す。 |
| バッチ | 本機能はバッチを起動しない。 |
| 失敗時 | 検証失敗時は同じ編集画面を再表示する。画像追加XHRの不正要求・非画像・ファイルなしはそれぞれ不正要求または対応しないメディア種別として拒否する。 |

### DB操作

永続化の正は ec-cube-enterprise。商品系は承認ワークフローを介さず persist/flush で直接確定する（在庫の承認ワークフローとは別系統。`ProductController`・各CSVサービスで確認）。

| 操作種別 | 対象テーブル | 契機・条件 |
|---------|--------------|------------|
| 登録/更新 | dtb_product / dtb_product_category / dtb_product_image / dtb_product_sub / dtb_product_tag / mtb_card_detail | 当機能が行う登録・更新で対象テーブルを直接保存する（不要な削除は含まない）。確定は persist/flush による即時反映。DB=ec-cube-enterprise を正典とする。 |

## セッション

商品編集画面では検索条件等の一覧状態を本機能から更新しない。成功フラッシュは管理画面共通の仕組みに依存する。商品検索に戻るリンクは検索一覧のページ番号セッションを参照する。

---

## Cookie

管理画面のセッションCookieのみを正とし、本機能用の追加Cookieは定義しない。

---

## 排他制御・トランザクション

更新処理は商品本体・付加情報・関連の保存を同一更新処理内でflush・commitする。画面側に楽観ロックの版情報は持たない。
