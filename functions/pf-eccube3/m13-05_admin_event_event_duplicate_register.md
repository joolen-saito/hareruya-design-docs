# M13-05（複製新規）

管理画面「イベント管理」で、登録済みイベントの内容をフォームへ複製した状態で新規登録画面を開き、別のイベントとして登録できるようにする機能である。

## 概要

複製新規は、既存イベントの編集画面から複製新規ボタンを押すことで、複製元イベントの入力値を引き継いだ新規登録フォームを表示する機能である。表示時点で複製元の値をフォームに載せるだけであり、保存は新規登録として行う。日程・申込・登録者などは引き継がない。

本書は実装手順ではなく、誰が・いつ・どの条件で・結果どうなるかを読むためのリバース詳細設計とする。既存実装が複製する項目と複製しない項目、表示と保存の関係、副作用を確認し、仕様の確からしさを把握することを目的とする。

対象はブラウザ経由の管理画面イベント複製新規画面である。本機能は晴れる屋向けプラグインで提供され、EC-CUBE3系のSilexアプリケーション上で動作する。管理画面プレフィックスはアプリケーション設定`admin_route`（`$app['config']['admin_route']`）で決まり、ルートはこの値を連結して登録される。確認観点はイベント用サービスプロバイダのルート登録とする。

複製新規の画面表示は、新規登録・編集と同一のフォーム生成・テンプレート（`eventdetail.twig`）を用いる。入力項目の詳細・検証・保存後の永続化はM13-02を正とし、本書は複製時に引き継ぐ値と引き継がない値、保存経路の違いに範囲を限定する。一覧検索はM13-01、申込検索はM13-06、デッキ表示はM13-08を正とする。

本機能のカスタマイズ区分はカスタマイズである。挙動の参照リポはpf-eccube3（HareruyaEcプラグイン）の現行実装とし、DB関連（永続化先のテーブル名・列名、DBカラム節、保存先・扱い、副作用のDB更新）はec-cube-enterpriseを正とする。現行と移行先でスキーマが異なる箇所はリニューアル移行時の扱いに集約する。

---

## 本書で扱うこと

- 複製新規ボタンから複製新規画面を開いたときの、複製元イベントの値の引き継ぎ
- 複製される項目（イベント情報の入力値）と複製されない項目（日程・申込・登録者・採番）
- 複製新規画面の保存が新規登録として扱われること
- 存在しない複製元IDのときのふるまい

---

## 本書で扱わないこと

以下は本書では仕様確定せず、実装または別機能の設計を正とする。

- イベント情報の入力項目・最大長・検証・保存後の永続化（M13-02を正とする）
- イベント一覧の検索・ページング（M13-01を正とする）
- イベント申込の検索・登録（M13-06を正とする）
- デッキ表示（M13-08を正とする）
- 日程（イベント詳細）の登録ルール
- 管理画面へのアクセス制御、ログイン、権限設定の詳細

## 処理フロー

### 複製新規画面を表示する

1. 管理者が編集画面で複製新規ボタンを押す。
2. パスの複製元IDで複製元イベントを読む。存在しなければ404とする。
3. パスのIDは渡されない（複製ルートはIDを持たない）ため、日程の読み込み・申込人数の集計は行わない。
4. 複製元イベントを初期データとしてイベント登録フォーム（フォーム名`admin_event_detail`）を生成する。
5. テンプレートを描画する。IDを渡さないため、画面は新規登録モードとして表示される。送信先は新規登録（`admin_event_create`）になる。

### 複製新規画面を保存する

1. 複製新規画面の保存は新規登録の送信経路に入る。
2. 新規イベントを用意し、フォームにリクエストを反映して検証する（M13-02の新規登録フロー）。
3. 登録者IDにログイン中の管理者IDを設定し、新規イベントとして永続化する。
4. 完了メッセージを表示し、登録したイベントの編集画面へリダイレクトする。

## 集計条件

複製新規の画面表示では一覧件数の集計や金額計算を行わない。日程ごとの申込人数の集計も行わない（複製ルートではパスのIDを持たないため）。

## 業務ルール・計算

| 項目 | 内容 |
|------|------|
| 複製する項目 | 複製元イベントの入力フォームに対応する値。イベント名（日・英）、略称（日・英）、店舗、会場、フォーマット、ルール適用度、公開状態、バナーURL（日・英）、定員、チーム人数、参加費、賞品（日・英）、備考（日・英）、支払方法。これらは複製元イベントのエンティティをフォームの初期データに用いることで、初期値として画面に載る。 （※チーム人数は Excel基本設計 0214 識別ID:1-12 により廃止。刷新後は複製対象に含めない） |
| 複製しない項目（採番・登録者） | イベントID（保存時に新規採番）、登録者ID（保存時にログイン中の管理者IDで設定）。複製元の登録者は引き継がない。 |
| 複製しない項目（日程・申込） | 日程（イベント詳細）、申込、デッキ登録は複製しない。複製ルートではパスのIDを渡さず日程を読み込まないため、画面に日程一覧は表示されず、保存しても新規イベントには日程が紐づかない。 |
| 保存経路 | 複製新規画面はIDを持たないため新規登録扱いとなり、保存は新規登録の送信先（`admin_event_create`）に送られる。複製元イベントは更新されない。 |

### 複製対象の一覧

| 項目名 | 複製時の扱い |
|--------|--------------|
| イベント名・略称（日・英） | 複製元の値を初期値として載せる。 |
| 店舗・会場・フォーマット・ルール適用度・公開状態 | 複製元の値を初期値として載せる。 |
| バナーURL（日・英） | 複製元の値を初期値として載せる。 |
| 定員・チーム人数・参加費 | 複製元の値を初期値として載せる。 |
| 賞品（日・英）・備考（日・英） | 複製元の値を初期値として載せる。 |
| 支払方法 | 複製元の値を初期値として載せる。 |
| イベントID | 載せない。保存時に新規採番。 |
| 登録者ID | 載せない。保存時にログイン中の管理者IDを設定。 |
| 日程（イベント詳細）・申込・デッキ登録 | 引き継がない。 |

各項目の最大長・必須／任意・検証・保存先はM13-02の「入力項目」を正とする。複製新規では初期値が複製元の値になる点のみが新規登録と異なる。

### エッジケース

| ケース | 扱い |
|--------|------|
| 存在しない複製元IDで複製新規を開く | 404。 |
| 複製元ID指定が1未満や非整数 | ルートの制約（1以上の整数）に一致せず到達しない。 |
| 複製新規画面で入力を変更せず保存 | 複製元と同じ入力値で新規イベントを1件登録する。複製元は変更しない。 |
| 複製新規画面の保存で検証失敗 | 新規登録と同様に登録失敗エラーを表示し、テンプレートを再描画する。 |
