# M04-31（棚卸計画）

棚卸計画の新規登録と更新を行い、棚卸名・備考を保存して棚卸計画一覧・編集画面へ導く機能。

## 概要

棚卸計画は、店頭在庫の棚卸作業を計画単位で管理するための機能であり、本書では棚卸計画の新規登録と更新（棚卸名・備考の保存）を中心に扱う。新規登録画面で棚卸名と備考を入力して登録すると、登録した計画の編集画面へ遷移する。編集画面では同じ項目を更新できる。棚卸計画一覧から新規登録・編集の各画面へ入る。

本書は実装手順ではなく、誰が・いつ・どの条件で・結果どうなるかを読むためのリバース詳細設計とする。HareruyaEc プラグインの実装を確認値とする。

本機能のカスタマイズ区分はカスタマイズである。挙動は現行リポpf-eccube3のHareruyaEcプラグイン実装を参照し、DB関連の記述はec-cube-enterpriseを正とする。

対象はブラウザ経由の管理画面に限定する。管理画面プレフィックスは HareruyaEc プラグインの設定キー `admin_route` で決まるため、本書では `%eccube_admin_route%` で示す。

本書の本文ではコントローラのメソッド名は主題としない。ルート bind 名は調査補助へ退避する。

---

## 本書で扱うこと

- 棚卸計画一覧・新規登録画面・編集画面の入口
- 棚卸名・備考の入力ルールと検証（棚卸名の必須・桁数・名称重複、備考の桁数）
- 新規登録・更新の処理フローと、登録後の編集画面への遷移
- 在庫反映済みの計画は更新不可とする判定
- 一覧画面に表示する棚卸計画の項目

---

## 本書で扱わないこと

以下は本書では仕様確定せず、実装または別機能の設計を正とする。

- 棚卸商品CSV登録・CSV出力（編集画面に付随するが別操作。実装を正とする）
- 棚卸詳細の在庫確認・在庫差異の確定（棚卸詳細編集の別機能）
- 棚卸結果の在庫反映確認・在庫反映の実行（在庫反映の別機能）
- 棚卸計画一覧の検索・ページングの内部仕様（検索一覧の共通処理を正とする）
- 管理画面の認証・ログイン・権限マスタの詳細

## リニューアル移行時の扱い

棚卸計画の永続化テーブルは、現行（pf-eccube3のHareruyaEcプラグイン）と移行先（ec-cube-enterprise）で同一スキーマである。両者ともテーブルは `dtb_inventory_plan`、棚卸名は列 `name`、備考は列 `memo`、作業者は列 `member_id`、在庫反映日は列 `stock_reflectioned_date`、在庫反映処理中フラグは列 `reflecting_flg`、件数表示は列 `product_count`・`product_registered_count`・`product_stock_diff_count` であり、列名・用途に差はない。

桁数の上限値（棚卸名255文字・備考1024文字）は現行プラグインの設定キー `inventory_plan.length.name` / `inventory_plan.length.memo` による確認値である。移行先 ec-cube-enterprise では棚卸名が列 `name`（最大255文字）で一致し、備考の列 `memo` はテキスト型（固定上限なし・NULL許容）であるため、備考の桁数制限は移行先では緩和される点が現行との差となる。

## 処理フロー

### 棚卸計画を新規登録する

1. 一覧の新規登録ボタンから新規登録画面を開き、棚卸名・備考を入力する。
2. 「登録」を押すとIDなしの登録ルートへ送信する。
3. 新規の計画オブジェクトを用意し、フォームを検証する。
4. 検証エラーなら「棚卸計画を登録できませんでした。」を表示し、新規登録画面を再表示する。
5. 検証を通れば作業者に現在の管理者を設定して永続化する。
6. 「棚卸計画を登録しました。」を表示し、登録した計画の編集画面へリダイレクトする。

### 棚卸計画を更新する

1. 編集画面で棚卸名・備考を変更し、IDつきの更新ルートへ送信する。
2. 対象計画を取得できないときは404とする。
3. 対象計画に在庫反映日が設定済みなら「在庫反映済みのため、更新できません。」を表示し、編集画面へリダイレクトする。
4. フォームを検証する。検証エラーなら「棚卸計画を登録できませんでした。」とフォームエラー内容を表示し、編集画面へリダイレクトする。
5. 検証を通れば作業者に現在の管理者を設定して永続化する。
6. 「棚卸計画を更新しました。」を表示（更新成功時のフラッシュは登録完了文言を用いる実装値）し、編集画面へリダイレクトする。

更新成功時のフラッシュは設定キー `admin.inventory_plan.save.complete`（「棚卸計画を登録しました。」）を用いる。更新専用の完了文言（`update.complete`）はロケールに定義があるが本経路では用いない（実装確認値）。

## 集計条件

本機能（棚卸名・備考の登録・更新）では件数・合計の集計を行わない。一覧に表示する商品数・計上済み商品数・差異あり商品数は計画に保持された値を表示する。これらの値の更新は棚卸詳細・CSV登録・在庫反映の各機能の範囲とする。

---

## 業務ルール・計算

| 項目 | 内容 |
|------|------|
| 棚卸名の重複 | 同じ棚卸名の計画が既に存在するとき登録・更新を不可とし、「この棚卸名は既に使用されています。」を表示する。 |
| 在庫反映済みの保護 | 在庫反映日が設定済みの計画は更新できない。 |
| 作業者の設定 | 登録・更新の成立時に、現在ログイン中の管理者を作業者として設定する。 |
| 本機能の計算 | 棚卸名・備考の保存では業務計算を行わない。 |

### 入力項目

| 項目名 | 必須／任意 | 最大長 | 初期値 | 保存先・扱い |
|--------|------------|--------|--------|----------------|
| 棚卸名 | 必須 | 最大255文字（設定キー `inventory_plan.length.name`） | 新規は空、編集は現行値 | `dtb_inventory_plan.name`（フォームキー `name`）。同名の計画が存在すると名称重複エラー。 |
| 備考 | 任意 | 最大1024文字（設定キー `inventory_plan.length.memo`）。複数行入力（textarea） | 新規は空、編集は現行値 | `dtb_inventory_plan.memo`（フォームキー `memo`）。 |

棚卸名は HTML 上は必須だが、フォーム制約としては桁数上限と名称重複の検証を持つ。送信時の作業者は入力ではなくログイン中の管理者から設定する。

### エッジケース

| ケース | 扱い |
|--------|------|
| 棚卸名が同名で既存 | 名称重複エラーを表示し登録・更新しない。 |
| 在庫反映済みの計画を更新 | 在庫反映済みエラーを表示し更新しない。 |
| 更新対象IDが存在しない | 404として扱う。 |
| 新規登録の検証エラー | 新規登録画面を再表示する。 |
| 更新の検証エラー | 編集画面へリダイレクトしエラー内容を表示する。 |

| 観点 | 内容 |
|------|------|

## ログ・監査

| タイミング | 記録内容 |
|------------|----------|
| 登録・更新の成立 | 計画に作業者IDを保持する。棚卸名・備考の保存では追加の業務監査ログを書かない。 |

棚卸商品CSV登録・在庫反映は別機能で開始・完了をログに記録する。

### ログに出してはいけないもの

- パスワード
- なりすまし対策トークン
- Cookie 値
- セッション ID の完全値
- Remember Me トークンの原値

## 排他制御・トランザクション

棚卸名・備考の登録・更新は計画1件の永続化で確定する。在庫反映処理では反映処理中フラグ（`reflecting_flg`）やロックを扱うが、これは在庫反映の別機能の範囲とする。本書の登録・更新では明示的なロックを取らず、在庫反映済みの計画を更新不可とする判定で整合を保つ。
