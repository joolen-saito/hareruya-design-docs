# ご注文方法指定 — 注文情報の入力・確認・注文

## 概要

ご注文方法指定画面において、ロック済みカートをもとに受注情報を作成し、お届け先・配送方法・お支払い方法・ポイント利用・要望欄などの注文情報を入力・確認し、最終的に注文を確定する機能である。配送業者の変更、お支払い方法の変更、お届け先の選択を同一画面の部分送信で反映し、最終送信で購入処理（受注確定）まで行う。

本書は実装手順ではなく、誰が・いつ・どの条件で・結果どうなるかを読むためのリバース詳細設計とする。確認値はpf-eccube3（EC-CUBE3系）のHareruyaEcプラグインの購入処理、テンプレート（`Shopping/index.twig`）、購入処理サービスを正とする。

本機能のカスタマイズ区分はカスタマイズであり、挙動の確認は現行リポ（pf-eccube3）の実装を参照する。DB関連の記述はリニューアル移行先の ec-cube-enterprise を正とする。

対象はブラウザ経由のフロント（購入手続き）に限定する。フロントのルートはロケールセグメント付きで提供され、サイトルートからのパスパターンは`/{_locale}`配下になる（`/{_locale}`はサービスプロバイダのマウントで決まる確認値）。

コントローラのメソッド単位の解剖は本文の主題としない。本文ではルートbind名の網羅を主説明とせず、「利用者視点の入口」にHTTPメソッドとサイトルートからのパスパターンを書く。

---

## 本書で扱うこと

- ロック済みカートから受注情報を作成し、ご注文方法指定画面を表示する流れ
- お届け先選択・配送業者変更・お支払い方法変更・ポイント利用・要望欄入力の各部分送信
- 最終送信（確認・注文確定）での購入処理と完了画面への遷移
- 会員・非会員（ゲスト購入）・未ログインの分岐
- 入力・確認・注文の段階で受注情報・セッションが引き継ぐ状態

---

## 本書で扱わないこと

以下は本書では仕様確定せず、実装または別機能の設計を正とする。

- 買い物かごの表示・数量更新（F04-01 買い物かごを正とする）
- 注文確定後の購入完了処理（受注ステータス判定・メール・在庫・ポイント反映・完了画面）はカートの決済〜購入完了機能（f04-04_front_cart_shopping_complete）を正とする
- 配送先の新規登録・変更（F04-03 注文時の配送先登録・変更を正とする。本書は選択結果の反映のみ触れる）
- 各決済手段の内部仕様、ポイント計算サービスの内部仕様
- ログイン・非会員登録画面（購入手続き内のログイン・非会員入口）の認証仕様

## リニューアル移行時の扱い

受注明細テーブルは、現行（pf-eccube3）の dtb_order_detail に対し、移行先（ec-cube-enterprise）では dtb_order_item に名称が変わる。本書のDB記述は移行先名称 dtb_order_item を主とし、現行名を括弧で添える。受注 dtb_order（支払方法・手数料 charge・割引 discount・メッセージ message・受注ステータス等）、配送 dtb_shipping、お届け先住所 dtb_customer_address は移行先でも同名で同一に扱う。注文確定後の購入完了処理（受注ステータス判定・メール・在庫・ポイント反映・完了画面）はカートの決済〜購入完了機能（F04-04）を正とする。

| 用語 | 説明 |
|------|------|
| 受注情報 | 購入処理中の注文1件。注文確定前の処理中ステータスで作成する。 |

| プレオーダーID | 処理中の受注を識別する値。Cookieに保存する。 |
| カートロック | 購入手続きへ進む際にカートを確定状態へ移した状態。 |

## 利用者視点の入口

| 入口 | URLエンドポイント | 期待されるふるまい |
|------|--------------------|--------------------|
| ご注文方法指定を開く | `GET /{_locale}/shopping` | ロック済みカードから受注情報を作成または取得し、ご注文方法指定画面を表示する。未ログインかつ非会員未登録ならログインへ誘導する。 |
| 配送業者を変更 | `POST /{_locale}/shopping/delivery` | 配送方法の選択を受注へ反映し、ご注文方法指定画面へ戻る。 |
| お支払い方法・要望・ポイントを変更 | `POST /{_locale}/shopping/payment` | お支払い方法・要望欄・ポイント利用を受注へ反映し、合計を再計算してご注文方法指定画面へ戻る。 |
| お届け先を選択 | `POST /{_locale}/shopping/shipping/{id}` | 選択したお届け先を配送先へ反映し、配送料・合計を再計算してご注文方法指定画面へ戻る。 |
| お届け先変更（メッセージ送信） | `POST /{_locale}/shopping/shipping_change/{id}` | 要望欄を保存し、お届け先設定一覧へ遷移する。 |
| 確認・注文確定 | `POST /{_locale}/shopping/confirm` | 入力を検証し、購入処理を行って受注を確定し、購入完了画面へ遷移する。 |
| 注文エラー画面 | `GET /{_locale}/shopping/shopping_error` | 受注情報が無いなどの異常を案内する。 |

ご注文方法指定の各部分送信はいずれも処理後にご注文方法指定画面（`GET /{_locale}/shopping`）へ戻る。最終送信のみ購入完了画面へ遷移する。

## 処理フロー

### ご注文方法指定を表示する（GET `/{_locale}/shopping`）

1. 表示ロケールをセッションに保存する。
2. カートがロックされていない、またはカートが空のときは買い物かごへ戻す。
3. 処理中ステータスの受注情報を取得する。無ければ受注情報を作成する。
   - 未ログインかつ非会員未登録ならログイン画面へ誘導する。
   - 非会員登録済みまたは会員なら、その顧客で受注情報を作成し、プレオーダーIDをCookieへ保存し、明細サブ情報を作成し、ポイント使用量0で登録する。
4. 受注を最新化し、受注IDをセッションへ保存する。
5. 配送・支払フォームを組み立て、受注金額がマイナスなら注文エラーへ遷移する。
6. 配送先が複数の場合、複数配送設定が無効ならエラーで買い物かごへ戻し、有効なら一度だけ複数配送の案内を表示する。
7. お届け先一覧・税相当額などを渡してご注文方法指定画面を表示する。

### 配送業者を変更する（POST `/{_locale}/shopping/delivery`）

1. カート・受注情報を確認する。POST以外はご注文方法指定へ戻す。
2. ポイント使用量を0で登録し直し、合計を再計算する。
3. フォーム送信時は配送データを受注へ反映して保存し、ご注文方法指定画面へ戻る。

### お支払い方法・要望・ポイントを変更する（POST `/{_locale}/shopping/payment`）

1. 受注情報を確認する。POST以外はご注文方法指定へ戻す。
2. ポイント利用指定からポイント使用量を登録し、合計を再計算する。
3. お支払い方法が有効なら受注へ設定し手数料を反映する。無効なら支払いを未設定にして手数料を0にする。
4. 要望欄を受注へ保存し、ポイント使用量を再更新して合計を再計算し保存する。
5. ご注文方法指定画面へ戻る。

### お届け先を選択する（POST `/{_locale}/shopping/shipping/{id}`）

1. カートを確認する。
2. 選択されたお届け先IDを、リクエスト・セッション・Cookieの順で取得する。未選択ならご注文方法指定へ戻す。
3. 当該顧客のお届け先住所を取得する。存在しなければお届け先が見つからない旨で扱う。
4. 配送先情報を更新し、国内・国外で郵便番号の設定を切り替える。
5. 配送方法をリセットし、ポイント使用量0で再登録、配送料を設定して合計を再計算し保存する。
6. 選択したお届け先IDをセッションとCookieへ保存し、ご注文方法指定画面へ戻る。

### 確認・注文を確定する（POST `/{_locale}/shopping/confirm`）

1. 表示ロケールをセッションから復元する。
2. カート・受注情報を確認する。受注情報が無ければ注文エラーへ遷移する。POST以外は買い物かごへ戻す。
3. フォームを検証し、お支払い方法が有効なら購入処理に進む。
4. トランザクション内でお支払い方法の一致を検証し、ポイント使用量を登録し、購入処理（受注確定）を行ってコミットする。
5. 購入処理の例外時はロールバックして注文エラーへ遷移する。
6. カートを空にし、受注IDをセッションへ保存し、ポイントを使用して購入完了画面へ遷移する。
7. 検証エラー時はご注文方法指定画面を再描画する。

---

## `注文確定` 時の判定順序

| 順序 | 判定 | 結果 |
|------|------|------|
| 1 | カートがロックされているか | 未ロックなら買い物かごへ戻す |
| 2 | 処理中の受注情報があるか | 無ければ注文エラーへ遷移する |
| 3 | リクエストがPOSTか | POST以外は買い物かごへ戻す |
| 4 | フォーム検証とお支払い方法の妥当性 | 不備なら同画面を再描画する |
| 5 | お支払い方法が受注の保持値と一致するか | 不一致なら注文エラーへ遷移する |
| 6 | 購入処理が成功するか | 失敗ならロールバックして注文エラーへ遷移する |
| 7 | 上記を通過 | カートを空にし、受注IDを保存し、購入完了画面へ遷移する |

## 業務ルール・計算

| 項目 | 内容 |
|------|------|
| 受注作成の前提 | カートがロックされ、かつ空でないこと。処理中ステータスの受注が無いときに新規作成する。 |
| 合計の構成 | 小計＋送料＋手数料−割引を合計とし、税相当額を別に算出して表示する。 |
| ポイント利用 | ポイント利用ありなら入力ポイント数、なしなら0をポイント使用量として登録し、合計を再計算する。 |
| お支払い方法 | 注文金額合計によって選択肢が変わるため、合計計算後にフォームを組み立てる。無効な支払いは未設定とし手数料0にする。 |
| お支払い方法の整合 | 注文確定時に受注の保持する支払方法とフォームの支払方法が一致することを検証する。 |
| 配送料 | お届け先選択時に配送料を設定し、合計を再計算する。国内・国外で郵便番号の扱いを分ける。 |
| 複数配送 | 配送先が複数で複数配送設定が無効なら買い物かごへ戻す。有効なら案内を一度表示する。 |

### 入力項目

| 項目名 | 必須／任意 | 最大長 | 初期値 | 保存先・扱い |
|--------|------------|--------|--------|----------------|
| お届け先 | 必須 | 選択（会員のアドレス帳から1件） | セッション・Cookieの直近選択、または受注の現配送先 | 配送先（`dtb_shipping`）へ反映。選択IDは`hareruya_ec.shopping.customer_address_id`（セッション）とお届け先IDのCookieに保存。 |
| 配送業者 | 必須 | 選択（お届け先地域などで変動） | 受注の現配送方法 | 配送方法を受注へ設定。配送料と合計を再計算する。 |
| 配送日時 | 任意 | 選択 | 未選択 | 配送指定として受注へ反映する。都道府県と配送方法から指定可能な時間帯を求める。 |
| お支払い方法 | 必須 | 選択（合計金額により変動） | 受注の現支払方法 | 受注の支払方法・手数料へ反映（`dtb_order`）。無効選択時は未設定・手数料0。 |
| ポイント利用有無 | 任意 | チェック | なし | ポイント使用量の登録に用いる。論理キー `pointpay`。 |
| 利用ポイント数 | 任意 | 数値 | 0 | ポイント利用ありのとき使用量として登録する。論理キー `pointpay_num`。合計を再計算する。 |
| 要望欄 | 任意 | メッセージ欄（実装上の上限はフォーム種別に依存） | 空 | 受注のメッセージへ保存（`dtb_order`）。論理キー `message`。 |

最大長の具体値はフォーム種別と`constant.yml.dist`等の確認値を正とする。お届け先・配送業者・お支払い方法は選択肢であり、選択肢の母集合は受注の地域・金額条件で変わる。

### エッジケース

| ケース | 扱い |
|--------|------|
| 未ログインかつ非会員未登録 | ログイン画面へ誘導する。 |

## データ整合性

| 観点 | 内容 |
|------|------|
| カートと受注 | ロック済みカートから受注情報を作成し、注文確定でカートを空にする。 |
| 受注とセッション | 受注IDをセッションに保持し、各部分送信・確認で同一受注を参照する。 |
| お届け先選択 | セッションとCookieに直近のお届け先IDを保存し、お届け先選択入口で参照する。 |
| 合計再計算 | 配送業者・お支払い方法・ポイント・お届け先の変更ごとに合計を再計算して保存する。 |
| 確定後 | 注文確定で受注は確定し、購入完了処理（別機能）が当該受注を参照する。 |

## DBカラム

機能に直接関係する列のみ記載する。型や一覧の細部はスキーマを参照する。

| テーブル | 列 | メモ |

| `dtb_order` | 支払方法・手数料・割引・小計・合計・メッセージ・受注ステータス | お支払い方法・要望欄・合計の反映先。注文確定で受注を確定する。 |
| `dtb_shipping` | 配送先住所・配送方法・配送料・郵便番号 | お届け先選択・配送業者変更の反映先。 |
| `dtb_order_item`（現行 `dtb_order_detail`） | 受注明細 | カートから受注明細を作成する。移行先（ec-cube-enterprise）では `dtb_order_item`。 |
| `dtb_customer_address` | お届け先住所 | 会員のアドレス帳。お届け先選択の母集合。 |

### DB操作

永続化の正は ec-cube-enterprise（テーブル名・操作は ec-cube-enterprise を正典）。当ドメインは承認ワークフローを介さず persist/flush で直接確定する（承認ワークフローは在庫機能固有）。

| 操作種別 | 対象テーブル | 契機・条件 |
|---------|--------------|------------|
| 登録/更新 | dtb_customer_address / dtb_order / dtb_order_detail / dtb_order_item / dtb_shipping | 当機能が行う登録・更新で対象テーブルを直接保存する（不要な削除は含まない）。確定は persist/flush による即時反映。DB=ec-cube-enterprise を正典とする。 |

| 条件 | 遷移先 |

### 遷移時に引き継ぐ状態

| 起点 | 遷移前の処理 | 遷移後の初期状態 |
|------|--------------|------------------|
| ご注文方法指定の初回表示 | 受注情報を作成し、受注IDをセッション・プレオーダーIDをCookieへ保存する | 各部分送信が同一受注を参照する |
| お届け先選択 | お届け先IDをセッション・Cookieへ保存する | 次回表示時に直近のお届け先を参照する |
| 注文確定 | カートを空にし、受注IDをセッションへ保存し、ポイントを使用する | 購入完了処理（別機能）が受注IDを参照する |
