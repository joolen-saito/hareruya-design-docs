# m06-07_admin_store_purchase_purchase_store_history_select_csv_export（管理画面_店頭買取管理_買取商品履歴_選択CSV出力）

## 概要

管理画面の「店頭買取管理」メニュー「買取商品履歴」で検索結果が表示されたうえで、一覧のチェックボックスで選んだ店頭買取実在庫履歴を、固定レイアウトのCSVとしてダウンロード応答で返す機能である。画面上のCSVメニュー表示名は「選択した商品履歴取得」である。同一エンドポイントは検索結果全件出力（別パラメータ）も受け付けるが、本書の主題は選択出力に限定する。

本書は実装手順ではなく、誰が・いつ・どの条件で・結果どうなるかを読むためのリバース詳細設計とする。カスタマイズ区分はカスタマイズであり、現行挙動の参照は店頭買取管理の現行実装があるpf-eccube3（HareruyaEcプラグイン）、DB関連はec-cube-enterpriseを正とする。現行と移行先のスキーマ差は後述の「リニューアル移行時の扱い」にまとめる。

対象はブラウザ経由の管理画面に限定する。

コントローラのメソッド名は本文の主題としない。本文ではルートbind名やSymfonyのルートnameの網羅は主説明としない。「利用者視点の入口」にHTTPメソッドとサイトルートからのパスパターンを書く。コード探索でbind名が必要なときだけ「調査補助」へ書く。

## 処理フロー

### 選択CSVをダウンロードする（POST `admin_otcbuyorder_history_export`、`export_type`が`check_export`）

1. 管理画面の認証・共通制約を通過する。
2. `set_time_limit(0)` で実行時間制限を解除する。
3. リクエストボディから`export_type`を読む。`check_export`でなければ本フローは対象外である。
4. リクエストボディから`otcBuyOrderHistoryIds`をすべて取得する。欠損または空のとき、管理画面向けエラーフラッシュに固定文言「1つ以上の商品を選択してください」を積み、セッションキー`eccube.admin.otcbuyorder_history.search.page_no`の値（無ければ1）をページ番号として`admin_otcbuyorder_history_page`へリダイレクトする。
5. 取得したID配列を整数化する。
6. 店頭買取実在庫履歴の識別子集合で再利用可能な取得クエリを組み、合算された並び順（店頭買取受注の買取成立日時の降順、続いて履歴の作成日時の降順）でエンティティを読み、行配列へ変換する。IDが1件もヒットしなくても例外にはせず、データ行は0件とする。
7. `StreamedResponse`のコールバック内で共通CSV出力サービスを開き、ヘッダ行（固定日本語列順）、続いてデータ行を書き、閉じる。
8. 応答ヘッダに`Content-Type: application/octet-stream`と`Content-Disposition: attachment`（ファイル名接頭辞`otc_buy_order_history_`と日時`YmdHis`と拡張子`.csv`）を付与する。
9. ストリーム応答オブジェクト生成時点で情報ログに固定メッセージとファイル名を書く。

### `export_type`が期待値以外のとき

1. 引数不正として例外を送出する。以降の応答はフレームワークと環境設定に従う。

## 出力列とデータの対応

ヘッダ行は次の順序の日本語名である。データ行は同順に値を並べる。

| ヘッダ（日本語） | 内容 |
|------------------|------|
| 査定番号 | 店頭買取受注の査定ID。 |
| 会員ID | 会員が紐付くときそのID。非会員などで紐付かないとき空文字。 |
| 申込者 | 会員が紐付くとき、会員氏名の文字列化。紐付かないとき空文字（画面一覧は受注の氏名を表示しうるため、本章末の整合性参照）。 |
| 商品コード | 規格のコード。 |
| 商品名 | 商品の名称。 |
| 基準価格 | 規格の基準価格（数値をそのまま文字列化）。 |
| 買取価格 | 実在庫の仕入単価。 |
| 買取店舗 | 受注の店舗表示名。未設定時空文字。 |
| 作業者 | 履歴に記録された管理者の表示名。 |
| 買取数 | 実在庫の買取数量。 |
| 増減数 | 履歴の変更後数量から変更前数量を減じた値。 |
| 買取日時 | 受注の買取成立日時を「`Y年m月d日 H時i分`」形式で出力。無ければ空文字（画面一覧はキャンセル日を併用しうるため、本章末の整合性参照）。 |

## 選択CSV出力時の判定順序

| 順序 | 判定 | 結果 |
|------|------|------|
| 1 | `export_type`が`check_export`か | 否なら本フロー対象外。 |
| 2 | `otcBuyOrderHistoryIds`に1件以上あるか | 否ならフラッシュとリダイレクト。 |
| 3 | 整数化したIDで履歴が取得できるか | 0件でもCSVはヘッダのみで返す。 |

## 業務ルール・計算

| 項目 | 内容 |
|------|------|
| 増減数 | 変更後数量マイナス変更前数量。いずれかが未設定のときPHPの減算規則に従う。 |
| CSVの数値列 | 金額・数量・増減は文字列セルとして出力され、画面のように三位区切りは施さない。 |
| 行の並び | 買取成立日時降順、履歴作成日時降順。利用者のチェック順は保持しない。 |

### 入力項目

| 項目名 | 必須／任意 | 最大長 | 初期値 | 保存先・扱い |
|--------|------------|--------|--------|----------------|
| CSVダウンロードの種別 | 必須 | 実装で文字長検証なし | 空（送信直前にJSが設定） | リクエストボディキー`export_type`。本機能は値`check_export`。 |
| 商品履歴の行選択 | `check_export`時は実質必須 | — | いずれも未チェック | リクエストボディキー`otcBuyOrderHistoryIds`（配列）。`dtb_otc_buy_order_stock_history.id`に対応。未選択時はリダイレクトしDBを更新しない。 |

検索フォーム側の画面ラベル別の最大長・ Symfony 制約の一覧は、買取商品履歴画面全体の設計で扱うか、フォーム型とDTOを確認値とする。

### エッジケース

| ケース | 扱い |
|--------|------|
| 存在しないIDのみ送信 | 例外にせず、ヘッダのみのCSVを返す。 |
| 取得できた履歴の店頭買取受注に会員が無い | 会員ID・申込者は空。 |
| 受注に買取成立日時が無い | 買取日時列は空。 |
| `export_type`欠損・不正値 | 不正値は例外。欠損は`match`のデフォルトに落ち例外となる。 |

## データ整合性

| 観点 | 内容 |
|------|------|
| 一覧との対応 | 同一履歴IDについて、商品コード・商品名・基準価格・買取単価・店舗・作業者・数量・増減の根拠は同一エンティティグラフを参照する。 |
| 一覧と異なりうる列 | 申込者は一覧が受注の氏名を表示し、CSVは会員紐付け時のみ会員氏名を出す。買取日時は一覧が成立日時なければキャンセル日を表示し、CSVは成立日時のみを使う。 |
| ダウンロード後の再検索 | CSVはダウンロード時点のDB快照に基づく。再検索まで一覧と完全一致を保証しない。 |

## 入出力

| 種類 | 内容 |
|------|------|
| 入力 | POSTボディの`export_type`（`check_export`）、`otcBuyOrderHistoryIds`（整数IDの配列）。セッションは選択出力では参照しない。 |
| 成功時出力 | `StreamedResponse`。本文はCSV。先頭行はヘッダ、以降はデータ。セルの文字列は共通CSV出力サービス経由で、設定キー`eccube_csv_export_encoding`に従いUTF-8から変換される。エンコーディングがUTF-8に読み替えられるときはBOMを先頭に付与する。区切り文字は`eccube_csv_export_separator`。応答の`Content-Type`は`application/octet-stream`固定である。 |
| 失敗時出力 | ID未選択時は302とエラーフラッシュ。`export_type`不正時は例外に依存。 |
| 副作用 | 参照のみで在庫・履歴・受注を更新しない。情報ログにファイル名を残す。 |
