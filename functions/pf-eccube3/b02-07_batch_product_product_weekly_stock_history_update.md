# バッチ 商品管理 — 週間在庫履歴更新

## 概要

全商品規格について、1週間前から11週間前までの各週末時点の在庫数を在庫履歴からたどって集計し、CSVファイルへ出力するバッチである。コマンドライン（コンソールコマンド）から実行する。支店の在庫移動リコメンドで使うためのデータを集計する位置づけである。

本書は実装手順ではなく、誰が・いつ・どの条件で・結果どうなるかを読むためのリバース詳細設計とする。確認値はpf-eccube3（EC-CUBE3系）のHareruyaEcプラグインの商品バッチ（週間在庫履歴CSV出力処理）、在庫履歴・商品在庫を扱うリポジトリ、出力パスの設定キーを正とする。カスタマイズ区分はカスタマイズであり、挙動の参照リポはpf-eccube3、DB関連はec-cube-enterpriseを正とする。

対象はコンソールコマンドであり、ブラウザ経由の画面を持たない。

本文ではフレームワークのコマンド型名やサービス型名を主説明としない。実行はコンソールのバッチコマンドで行う。

## リニューアル移行時の扱い

現行（pf-eccube3）の挙動と移行先（ec-cube-enterprise）の差を記録する。挙動は現行リポを正とし、DB関連はec-cube-enterpriseを正とする。

| 観点 | 現行（pf-eccube3） | 移行先（ec-cube-enterprise） |
|------|--------------------|------------------------------|
| 出力先 | 集計結果をCSVファイル（`weekly_stock_history.csv`）へ出力し、DBは更新しない。 | 集計結果を一時テーブル`dtb_weekly_stock_history_temp`へINSERTし、本テーブル`dtb_weekly_stock_history`へコピーするDB方式。CSV出力ではない。 |
| 一時テーブルの形 | テーブルを持たない。CSVの1行に商品規格IDと週次在庫列を並べる。 | `dtb_weekly_stock_history_temp`が商品在庫ID（`product_stock_id`）単位で`stock_01`〜`stock_11`（1週間前〜11週間前の在庫数）を持つ。 |
| 在庫履歴の関連キー | 在庫履歴を商品規格ID（`product_class_id`）で参照する記述。 | 在庫履歴`dtb_stock_history`は商品在庫ID（`product_stock_id`）で関連づき、商品在庫`dtb_product_stock`経由で商品規格（`product_class_id`）に至る。 |
| 集計の刻み | 商品規格ごとに在庫履歴を1件ずつ取得する。 | 商品在庫IDの範囲を20000件ずつ区切ってINSERTし、本テーブルへ置き換える。 |
| スマレジ在庫の合算 | 扱わない。 | 基本設計では「ECとスマレジの在庫を合算して登録する」とあるが、ec-cube-enterprise実装ではスマレジ在庫の取り込みが未実装でEC在庫のみを対象とする（要確認）。 |

## 処理フロー

### 週間在庫履歴更新を実行する（`product:batch exportWeeklyStockHistoryCsv`）

1. メモリ制限と実行時間制限を解除し、SQLロガーを無効化する。
2. 商品在庫から全商品規格IDの一覧を取得する。
3. 商品規格ごとに、1週前から11週前までの各週について、当日から対象週数を引いた日付以前で最も新しい在庫履歴の在庫を取得する。
4. 対象の在庫履歴が無い週は在庫を0として扱う。
5. 商品規格IDと週次在庫を1行にまとめ、集計結果に積む。
6. 出力先のCSVファイルを書き込みモードで開き、ヘッダ行を出力する。
7. 集計結果の各行をCSVへ書き込み、ファイルを閉じる。

## 業務ルール・計算

| 項目 | 内容 |
|------|------|
| 集計単位 | 商品規格単位（商品規格ID）。全商品規格を対象とする。 |
| 集計値 | 各週末時点の在庫数（その時点以前で最も新しい在庫履歴の在庫）。 |
| 週の範囲 | 1週前から11週前まで（11週分）。 |
| 在庫履歴なし | その週の在庫を0とする。 |
| 出力形式 | CSV。ヘッダは商品規格IDと週ごとの在庫列。 |

---

## 集計条件

| 指標 | 集計の要点 |
|------|------------|
| 対象データ | 商品在庫に存在する全商品規格ID。 |
| 各週の在庫 | 当日から対象週数を引いた日付以前で作成日が最も新しい在庫履歴の在庫を1件取得する。 |
| 集計期間 | 当日基準で1週前から11週前までの各週末。 |
| 欠損時 | 該当する在庫履歴が無い場合は0とする。 |

## データ整合性

| 観点 | 内容 |
|------|------|
| 多重実行 | ロックは持たない。同一出力ファイルへ同時書き込みが起きると内容が壊れる可能性がある。 |
| 途中失敗・再実行 | 書き込みモードで開くため再実行で全件上書きされ、正常完了すれば最新内容に収束する。 |
| 参照時点 | 実行時点の商品規格一覧と在庫履歴を対象とする。週末時点は当日からの相対週で算出する。 |

## DBカラム

機能に直接関係する列のみ記載する。型や一覧の細部はスキーマを参照する。

列名はec-cube-enterpriseを正とする。現行（pf-eccube3）と異なる場合は移行先名を主とし現行名を括弧で添える。

| テーブル | 列 | メモ |
|----------|-----|------|
| `dtb_product_stock` | `id`・`product_class_id`・`stock` | 集計対象の商品在庫と商品規格IDを取得する。 |
| `dtb_stock_history` | `product_stock_id`（現行は`product_class_id`参照）・`stock`・`create_date` | 各週末時点の在庫の取得に使用する。移行先では商品在庫IDで関連づく。 |
| `dtb_weekly_stock_history_temp` | `product_stock_id`・`stock_01`〜`stock_11` | 移行先の集計一時テーブル（現行はCSV出力で該当テーブルを持たない）。 |
| `dtb_weekly_stock_history` | `product_stock_id`・`stock_01`〜`stock_11` | 移行先の集計本テーブル（現行はCSV出力で該当テーブルを持たない）。 |

### DB操作

永続化の正は ec-cube-enterprise（テーブル名・操作は ec-cube-enterprise を正典）。当ドメインは承認ワークフローを介さず persist/flush で直接確定する（承認ワークフローは在庫機能固有）。

| 操作種別 | 対象テーブル | 契機・条件 |
|---------|--------------|------------|
| 登録/更新 | dtb_product_stock / dtb_stock_history / dtb_weekly_stock_history / dtb_weekly_stock_history_temp | 当機能が行う登録・更新で対象テーブルを直接保存する（不要な削除は含まない）。確定は persist/flush による即時反映。DB=ec-cube-enterprise を正典とする。 |

## 排他制御・トランザクション

ロックファイルによる多重起動防止は持たない。長時間処理に備えてメモリ制限と実行時間制限を解除し、商品規格ごとに処理しながらキャッシュをクリアしてメモリを管理する。出力はCSVファイルへの書き込みのみでDBトランザクションは持たない。本バッチは楽観ロック・悲観ロックの対象を持たない。
