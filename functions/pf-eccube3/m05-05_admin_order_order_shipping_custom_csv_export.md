# 受注管理 — 配送カスタムCSV出力

## 概要

管理画面の受注一覧から、あらかじめ店舗設定で定義した「配送」用カスタムCSVフォーマットを選び、現在の受注検索条件に合致する受注データを配送単位で行に分割し、ストリーミングでCSVファイルを返す機能である。標準の配送CSV（店舗設定の固定列セット）とは別系統であり、フォーマットごとの拡張定義と任意列構成を用いる。

本書は実装手順ではなく、誰が・いつ・どの条件で・結果どうなるかを読むためのリバース詳細設計とする。実装の確認値は ec-cube-enterprise の管理画面コア（Symfony 属性ルート）を正とする。

対象はブラウザ経由の管理画面に限定する。

本機能のカスタマイズ区分はカスタマイズである。現行挙動は pf-eccube3 のHareruyaEcプラグイン実装を参照し、リニューアル移行後の挙動とDBは ec-cube-enterprise を確認値とする。DB関連の記述は ec-cube-enterprise を正とする。

コントローラのメソッド名は本文の主題としない。本文ではルートbind名やSymfonyのルートnameの網羅は主説明としない。「利用者視点の入口」にHTTPメソッドとサイトルートからのパスパターンを書く。コード探索でbind名が必要なときだけ「調査補助」へ書く。

## リニューアル移行時の扱い

現行 pf-eccube3 は HareruyaEc プラグインで配送カスタムCSV（CSV拡張定義と中間テーブル）を実装し、移行先 ec-cube-enterprise はこれをコア機能として持つ。DB関連は ec-cube-enterprise を正とし、本書のテーブル・列名は移行先名で記す。現行と移行先で列名が異なる箇所は次のとおり。

| 項目 | 現行 pf-eccube3（HareruyaEc） | 移行先 ec-cube-enterprise |
|------|-------------------------------|----------------------------|
| 出力列の有効フラグ | `dtb_csv.enable_flg` | `dtb_csv.enabled` |
| 出力列の並び順キー | `dtb_csv.rank` | `dtb_csv.sort_no` |
| CSV種別の参照列 | `dtb_csv.csv_type` | `dtb_csv.csv_type_id` |
| 中間テーブルの並び順キー | `dtb_csv_csv_extension.rank` | `dtb_csv_csv_extension.rank`（同一） |
| 拡張定義の論理削除 | `dtb_csv_extension.deleted_at` | `dtb_csv_extension.deleted_at`（同一） |

本書のDBカラム節・出力方式・データ整合性のDB部分は移行先 ec-cube-enterprise の名称に合わせている。現行名は上表で対応づける。

## 処理フロー

### 受注一覧でフォーマットを選んでダウンロードする（`admin_custom_export`）

1. 管理画面の認証・共通制約を通過する。
2. パスパラメータの `csvExtensionId` でCSV拡張行を取得する。存在しなければアクセス拒否（HTTP404相当）の例外となる。
3. 中間テーブル経由で、紐づくCSV列定義を rank 昇順、同順位は列定義側の `sort_no` 昇順で読み込み、拡張にセットする。
4. PHPの実行時間制限を無効にする。
5. ORMのSQLロガーを無効にする。
6. `StreamedResponse` のコールバック内で、次を順に実行する。
   - 拡張定義とCsv種別をCsvエクスポート処理へ渡す。
   - ヘッダ行を出力する。各列の見出しはCSV列定義の表示名。
   - リクエストから受注検索用のクエリビルダを組み立てる。入力はセッションキー `eccube.admin.order.search` に保持された配列を受注検索フォーム型へ流し込んだ結果である。
   - クエリビルダをページング出力用に登録する。1ページあたり100件で走査する。
   - 各ページで得られる各行は受注エンティティである。Csv種別が配送の場合、受注に対し「配送カスタムCSV用」の行出力処理を適用する（後述）。
   - 各ページの走査後、ORMのユニットオブエンティティをクリアし、次ページへ進む。
7. 応答の `Content-Type` は `application/octet-stream`、ファイル名は接頭辞 `shipping_` と現在日時（`YmdHis`）と拡張子 `.csv`。
8. 情報ログに、出力ファイル名を記録する。

### 配送Csv種別における1受注・複数配送の行の組み立て

1. 対象受注に紐づく配送コレクションを列挙する。
2. 配送の件数だけ、以下を繰り返す。
3. 各CSV列定義について、まず受注エンティティに対してフィールド解決を試みる。エンティティ種別またはフィールドが一致せず値が得られない場合はヌルとなり、その列について配送エンティティへ再度解決を試みる。
4. ヌル以外の文字列が得られた場合、配送への二重ルックアップは行わない。空文字が得られた場合もヌルではないため、配送へフォールバックしない。
5. 論理値は `1` または `0`、日付は設定の日付書式、参照コレクションは設定の複数値区切り文字で連結、といった共通の整形が、列定義と実体の型の組み合わせに従い適用される。
6. 列の並びは、手順「受注一覧でフォーマットを選んでダウンロードする」のステップ3で確定した順である。

### 検索条件が一覧の最新検索と一致しない場合

1. カスタムCSVのリクエストは一覧の「検索」ボタンを再度押さなくても、セッションに残った最後の検索条件を読む。
2. セッションにキーが無い場合は空配列を検索フォームへ渡した正規化結果が使われ、受注リポジトリの検索データ経路は受注一覧初期表示と整合する。

## 集計条件

本機能は売上集計や件数サマリを出さない。抽出対象は、受注一覧と同じ検索データに基づく受注クエリの結果集合である。データ行数は、抽出された各受注の配送件数の合計になる。

| 指標 | 集計の要点 |
|------|------------|
| 行の単位 | 配送。同一受注で配送がN件なら最大N行。 |
| 検索条件 | セッション `eccube.admin.order.search` 由来の受注管理向け検索データ。 |
| 除外 | 標準CSVと異なる追加除外は行わない。検索側の制約に従う。 |

---

## 出力方式における判定順序（列ごとの値の帰属）

| 順序 | 判定 | 結果 |
|------|------|------|
| 1 | 列定義のエンティティ種別とフィールドで、受注から値が取れるか | 取れたらその値（整形後）を列に採用し、配送は見ない。 |
| 2 | 受注側がヌル（種別不一致・フィールド欠落・関連未解決など） | 配送から同じ列定義で解決を試みる。 |

## 業務ルール・計算

| 項目 | 内容 |
|------|------|
| 行分割 | 受注カスタムCSVが「明細ごと」に行を分けるのに対し、配送カスタムCSVは「配送ごと」に行を分ける。 |
| 列の由来 | 設定した列が受注エンティティを指せば受注値、配送エンティティを指せば通常は手順2のフォールバックで配送値。いずれも該当しなければ空欄相当の出力になる。 |

本機能では受注金額の再計算や税の再割り当てといった業務計算は行わない。表示するのは当該時点で永続化された属性の参照結果である。

### エッジケース

| ケース | 扱い |
|--------|------|
| 存在しない `csvExtensionId` | コントローラはアクセス拒否（HTTP404相当）。 |
| 検索ヒット0件 | ヘッダ行のみのファイルとなる。 |
| 配送が1件の受注 | その受注についてデータ行は1行。 |
| 列定義が受注フィールドのみで、配送固有の列が無い | 各行とも受注由来の値が重複して出力されうる（配送件数ぶんの繰り返し行）。 |
| UTF-8以外のエンコーディング設定 | BOMは付かない。文字変換は設定のエンコーディングへ向けて行う。 |

## データ整合性

| 観点 | 内容 |
|------|------|
| 一覧との一致 | 抽出条件は受注一覧の検索セッションに依存する。一覧を開かずにブックマークからCSVだけ実行した場合、セッション未初期化時は一覧初期表示と同じ正規化がかかる。 |
| 同時更新 | ストリーム中に他操作で受注が更新されても、ページングとクリアの都合により、途中ページのスナップショットに一貫性があるとは限らない。 |
| 設定変更 | ダウンロード直前に列定義が変われば、その定義がそのリクエストに適用される。 |

## DBカラム

本機能は参照のみで、当機能が新規に書き込む列はない。間接的に関係する保存領域の例として、拡張・列定義・中間の紐づけ・Csv種別マスタがある。列の詳細はスキーマ定義を参照する。

| テーブル | 列 | メモ |
|---------|-----|------|
| `dtb_csv_extension` | `id`, `csv_type_id` 等 | ルートパラメータで指定する行。Csv種別が配送であることが配送カスタムCSVの前提。 |
| `dtb_csv_csv_extension` | `rank` 等 | 列の並びに使う。 |
| `dtb_csv` | 表示名、エンティティ種別、フィールド名等 | ヘッダとデータ解決の鍵。 |

### DB操作

本機能は参照系（検索・出力）であり、DBへの登録・更新・削除は行わない。テーブル名は ec-cube-enterprise を正典とする。

| 操作種別 | 対象テーブル | 契機・条件 |
|---------|--------------|------------|
| 検索 | dtb_csv / dtb_csv_csv_extension / dtb_csv_extension | 検索条件に合致するレコードを抽出する。抽出結果を所定フォーマットでファイル出力する。 |
