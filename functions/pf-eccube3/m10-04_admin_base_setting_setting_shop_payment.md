# 店舗設定 — 支払方法管理（支払方法・手数料・利用条件）

## 概要

管理画面の「店舗設定」配下において、支払方法マスタの一覧表示・表示順の入替・論理削除、および支払方法ごとの登録・編集（支払方法名、手数料、購入金額に応じた利用条件の上下限、ロゴ画像）を扱う機能である。ブロックタイトルは「ショップ設定」、サブタイトルは「支払方法管理」である。コアの「基本情報設定（SHOPマスター）」で編集する店舗基本情報（`dtb_base_info`）とは別画面であり、本条は支払方法（`dtb_payment`）に特化する。

利用者が「店舗設定（基本設定）」と称する場合、多くは店舗設定メニュー配下の一画面として本機能を含めて指す。実装上は基本情報画面と支払方法画面は分離している。

本書は実装手順ではなく、誰が・いつ・どの条件で・結果どうなるかを読むためのリバース詳細設計とする。pf-eccube3コア実装を確認値とする。同一ルート名でプラグインが管理画面のコントローラやテンプレートを差し替えている場合は、その環境の実装を正とする。

対象はブラウザ経由の管理画面に限定する。

本機能のカスタマイズ区分は現行踏襲であり、画面・処理の挙動は現行リポ（pf-eccube3）の実装を確認値とし、DB関連（テーブル名・列名・型・保存先）は ec-cube-enterprise を正とする。

本書の本文ではルート名の網羅やコントローラ実装の手順は扱わない。ただし「利用者視点の入口」には、HTTP メソッドとサイトルートからの相対パスを `{admin_route}` を含む形で記載する（ホスト名・絶対 URL は書かない）。

## 本書で扱うこと

- 支払方法一覧の抽出条件、列表示（支払方法名・手数料・利用条件）、表示順（ランク）と「上へ」「下へ」による隣接行との入替
- 一覧での論理削除および削除後の残存行のランクの詰め直し
- 新規登録時の既定値（ランク、削除フラグ、固定フラグ、手数料設定可否フラグ）
- 編集画面の入力項目、動的に出し分ける手数料欄、利用条件の相互検証、ロゴ画像の非同期アップロードと登録時のファイル移動
- 登録成功時のリダイレクト先とフラッシュメッセージ、検証失敗時の再描画
- 画像POSTがAjaxに限定されること、MIME種別が`image`接頭でない場合のエラー扱い
- 論理削除・表示順変更リクエストにおけるCSRFトークン検証
- 保存イベント購読（Doctrine）による作成日時・更新日時・作成者の自動設定
- 一覧表示後・編集フォーム初期化時・編集保存後・画像追加後・削除完了後にイベントがディスパッチされ、拡張が差し込めること

---

## 本書で扱わないこと

以下は本書では仕様確定せず、実装または別機能の設計を正とする。

- 管理画面ログイン、セッション、フォームCSRFの仕様の詳細（名称や値の環境依存を含む）
- フロントのカート・購入フローにおける支払方法の絞り込み（配送方法との組合せ）、選択時の手数料・合計金額への反映、注文への支払方法紐付けの詳細
- 配送方法編集画面で「利用できる支払方法」をチェックする処理（別機能）
- `charge_flg`・`fix_flg`を業務要件として誰がいつどう変更するかの運用（DB上の値の意味は実装から読み取れる範囲に限り記載する）
- 導入プラグインによるフォーム拡張・コントローラ差し替えの差分の完全列挙

## リニューアル移行時の扱い

現行（pf-eccube3）の挙動を踏襲しつつ、永続化先は移行先（ec-cube-enterprise）の `dtb_payment` に合わせる。テーブル名は同一だが、主キー名・並び順キー・削除方式・フラグ列に差がある。当書の各列名は移行先の名称を主とし、現行名を括弧で添える。

| 観点 | 現行（pf-eccube3） | 移行先（ec-cube-enterprise） |
|------|--------------------|------------------------------|
| 主キー | `payment_id` | `id` |
| 並び順 | `rank`（整数。大きい値が先頭側） | `sort_no`（smallint・unsigned） |
| 削除方式 | `del_flg`（論理削除フラグ） | `visible`（boolean。表示制御。false が一覧非表示に相当） |
| 固定フラグ | `fix_flg`（smallint） | `fixed`（boolean） |
| 手数料設定可否 | `charge_flg`（smallint。1で手数料入力、2で0強制） | 該当列が見当たらない（ec-cube-enterprise 実装で要確認） |
| 手数料・利用条件金額 | `charge`・`rule_min`・`rule_max`（decimal(10,0)） | 同名列。型は decimal(12,2)・unsigned |
| 英語名 | 無し | `payment_method_en`（支払方法(英)）が追加されている |
| 決済種別 | 無し | `method_class` が追加されている |

現行の論理削除（`del_flg`）は移行先では表示フラグ（`visible`）に置き換わる点、現行の手数料設定可否（`charge_flg`）に対応する移行先列が見当たらない点が主な差分である。入力項目・DBカラム節の現行列名は現行挙動の確認用に残し、移行先の永続化先は本節および「DBカラム」節の移行先名を正とする。

## 用語

| 用語 | 説明 |
|------|------|
| 支払方法 | 支払い手段の1件。`dtb_payment`の1行。画面上は「支払方法」列に支払方法名（`payment_method`に相当する属性）が出る。 |
| 手数料 | 当該支払方法に紐づく手数料金額。`charge_flg`が手数料設定可のときフォームで必須。不可のとき保存直前に0に正される。 |
| 利用条件 | 購入金額の下限・上限。フォームでは金額2欄。未入力や片方のみ入力が許容される。両方入力かつ上限が下限未満のときエラー。 |
| 表示順（ランク） | 一覧の並びとフロントでの支払候補の並びに使われる整数。大きい値ほど一覧の先頭に近い並びで取得する実装である。 |
| 固定フラグ | `fix_flg`。値が1の行だけ、一覧のドロップダウンから編集・削除への通常リンクが有効になる。1以外は遷移しない見た目の錨になる。 |
| 手数料設定可否フラグ | `charge_flg`。値1なら手数料を金額入力として編集する。値2なら手数料欄はhiddenとなり、保存時に手数料0を保存する。 |
| 論理削除 | `del_flg`を削除済み値に更新し、一覧取得から除外する。物理削除は当機能では行わない。 |
| 管理者 | 管理画面にログイン可能な管理者アカウント。保存時イベントで作成者に設定されるのはトークンがあり`ROLE_ADMIN`が付与されている場合に限る。 |

## 利用者視点の入口

| 入口 | URLエンドポイント | 期待されるふるまい |
|------|--------------------|---------------------|
| ナビから支払方法一覧を開く | `GET /{admin_route}/setting/shop/payment` | 論理削除されていない支払方法だけが表示順のルールに従って表形式で並ぶ。各列に支払方法名・手数料・利用条件文言・操作メニューがある。 |
| 「支払方法を新規入力」 | `GET /{admin_route}/setting/shop/payment/new` | 新規用の登録・編集画面が開く。ランクは既存の最大ランクに1を足した値が既定になる。手数料設定可否・固定フラグは新規既定で手数料編集可・編集削除可になる。 |
| 一覧から編集へ進む（固定フラグが編集可） | `GET /{admin_route}/setting/shop/payment/{id}/edit` | 当該行の現在値がフォームに載る。手数料設定可否に応じて手数料が金額入力かhiddenか切り替わる。 |
| 一覧から編集・削除を選ぶ（固定フラグが編集不可） | —（リンク無効） | リンクは効かない見た目の錨のみである。 |
| 「登録」を押す | `POST /{admin_route}/setting/shop/payment/new` または `POST /{admin_route}/setting/shop/payment/{id}/edit` | 検証成功なら永続化ののち成功メッセージとともに一覧へ戻る。失敗なら同じ編集画面でエラーが出る。 |
| 一覧で削除を実行する | `DELETE /{admin_route}/setting/shop/payment/{id}/delete` | トークンが伴う削除要求になる。対象が存在すれば論理削除・ランク詰め・成功メッセージ。存在しなければ警告メッセージのみで一覧へ戻る。 |
| 「上へ」 | `PUT /{admin_route}/setting/shop/payment/{id}/up` | トークンが伴う更新要求。一覧上で一つ上のランクの行が存在すればランクを入替え成功メッセージ。隣が無ければエラーメッセージ。いずれものち一覧へ戻る。 |
| 「下へ」 | `PUT /{admin_route}/setting/shop/payment/{id}/down` | 同上（一つ下のランクとの入替）。 |
| ロゴ画像を非同期アップロード | `POST /{admin_route}/setting/shop/payment/image/add`（マルチパートのフィールド名は実装を正とする） | 画像であれば一時保存ディレクトリへ保存され、ファイル名がJSONで返る。画像以外のMIMEは要求が失敗する。 |
| 未ログインまたは権限・IP制限で拒否される利用者 | 上記パス（到達前） | 管理画面の共通ルールに従いアクセスできない（詳細は管理画面認証・認可の実装を正とする）。 |

## フロント挙動

| 観点 | 内容 |
|------|------|
| 表示要素（一覧） | 見出し「支払方法」。表頭は「支払方法」「手数料」「利用条件」、操作列。利用条件は下限金額（下限が0以下なら「0」と表示）、「〜」、上限（上限が0より大きければ「上限円」、上限がNULLなら「無制限」、それ以外の上限値は上限文言を付けない実装）。手数料・下限・上限はTwig上で数値整形は行わずプロパティ値をそのまま出す。 |
| 表示要素（フッタ） | ボタン「支払方法を新規入力」。 |
| 表示要素（編集） | 見出し「支払方法登録・編集」。テキスト「支払方法」、手数料は`charge_flg`が1のとき金額入力ラベル「手数料」、利用条件は2つの金額入力を「〜」で挟む。ロゴはラベル「ロゴ画像」と補足「620px以上推奨」、ドラッグ領域・サムネイル列・hiddenとファイルinput・「ファイルをアップロード」リンク。右カラムに「登録」ボタン。「一覧に戻る」リンク。 |
| JS挙動（編集） | jQuery File Uploadで画像を非同期POST。成功時に一時保存パスでサムネイルを描画しhiddenにファイル名を格納。開始時に既存サムネとhiddenを消す。削除アイコンで該当行とhiddenを空にする。受け付け拡張子は正規表現でgif/jpeg/png。最大ファイルサイズは10000000バイト。検証失敗時はアラートで画像でないかサイズ超過を示す。失敗時もアラート。既存保存画像は保存ディレクトリのURL、新規アップロードは一時ディレクトリのURLでプレビューする。 |
| JS挙動（一覧） | 本機能では一覧のドラッグ並べ替えやモーダル確認は扱わない。 |
| CSS・レイアウト | 編集はBootstrap横型フォームテーマ。画像アップロード用にfileupload系CSSとjQuery UIスムーズテーマを読み込む。 |
| モーダル・ポップアップ | 管理画面の独自モーダルは使わない。 |
| 入力項目 | 必須・任意・検証の対応は「業務ルール・計算」「バリデーション」を正とする。 |
| 拡張フィールド枠 | 編集画面でフォームイテレータのうち名前が`plg`で始まらない追加項目を「extra-form」欄にループ表示する構造がある。 |

## 処理フロー

### 一覧を開く（GET）

1. 管理画面の認証・権限・IP制限の各ルールを通過する。
2. 論理削除フラグが未削除の支払方法だけを、表示順の降順で取得する。
3. イベントをディスパッチする（プラグイン等が一覧データを参照できる）。
4. テンプレートを描画する。

### 新規登録・編集画面を開く（GET）

1. 識別子が新規用のとき、リポジトリが新規エンティティを用意する。表示順は現存行の最大表示順に1を加えた値。論理削除フラグは未削除、固定フラグと手数料設定可否フラグはいずれも「編集可／手数料編集可」側の既定にする。
2. 識別子が既存のとき、同識別子の行を読む（見つからない場合の制御は本書では深入りしない）。
3. フォームビルダを生成し、初期化イベントをディスパッチする（フィールド追加等の拡張点）。
4. フォームにエンティティをバインドする。手数料設定可否に応じてフォーム組み立て段階で手数料フィールドの種別が決まる。
5. 既存のロゴファイル名を別変数としてテンプレートへ渡し、プレビューURLの切替に使う。
6. テンプレートを描画する。

### 「登録」押下（POST、検証成功）

1. フォームを処理する。
2. 手数料設定可否が「手数料固定（不可）」のとき、手数料を数値0に置換する。
3. ロゴ画像hiddenにファイル名があり、かつそのファイルが一時保存ディレクトリに存在するとき、本保存ディレクトリへ名前を変えずに移動する。存在しないときは移動を試みない。
4. 永続化しフラッシュする。
5. 保存完了イベントをディスパッチする。
6. 登録完了の成功フラッシュを積み、一覧へリダイレクトする。

### 「登録」押下（POST、検証失敗）

1. フォームを処理する。
2. 同一編集テンプレートを再描画する。成功フラッシュは積まない。

### ロゴ画像追加（Ajax POST）

1. 要求がAjaxでないときは不正要求として扱う。
2. マルチパートのファイル部品から画像を取り出し、MIME種別が`image`で始まらなければUnsupported系のHTTPエラーとする。
3. 推定拡張子と日時・一意接頭辞からファイル名を組み立て、一時保存ディレクトリへ保存する。
4. イベントをディスパッチしたうえで、最終的なファイル名をJSONで返す。

### 削除（DELETE系、トークン検証あり）

1. CSRFトークンを検証し、無効なら拒否する。
2. 対象識別子の行を読む。無ければ削除用フラッシュを積み一覧へ戻る。
3. 対象を論理削除し、表示順を0にする。
4. 論理削除されていない全行を表示順の昇順で取り直し、1から順にランクを振り直す（削除行は除く）。
5. フラッシュし、削除完了イベントをディスパッチする。
6. 削除成功フラッシュを積み一覧へ戻る。

### 表示順を上へ（PUT系、トークン検証あり）

1. CSRFトークンを検証する。
2. 対象行の表示順を読む。表示順が1大きい行を探し、存在すれば二者の表示順を入替え、成功フラッシュを積む。無ければ上移動エラーフラッシュを積む。
3. 一覧へ戻る。

### 表示順を下へ（PUT系、トークン検証あり）

1. CSRFトークンを検証する。
2. 対象行の表示順を読む。表示順が1小さい行を探し、存在すれば二者の表示順を入替え、成功フラッシュを積む。無ければ下移動エラーフラッシュを積む。
3. 一覧へ戻る。

## 登録・更新フォームにおける判定順序

| 順序 | 判定 | 結果 |
|------|------|------|
| 1 | Symfonyフォームのフィールド単体の制約 | 違反時はフィールドエラー |
| 2 | 利用条件下限・上限の両方が空でないかつ上限が下限未満 | 下限欄にメッセージを付ける |
| 3 | 手数料設定可否が不可 | 保存直前に手数料0を強制 |

## 業務ルール・計算

| 項目 | 内容 |
|------|------|
| 一覧の対象 | 論理削除されていない行のみ。取得時の並びは表示順の降順。 |
| 新規の表示頭側 | 既存のうち最大表示順に1を加えた値を新規行に付与する。既存が0件なら表示順は1。 |
| 手数料 | 手数料設定可のとき0以上の数字文字列として必須。桁は設定`int_len`（コアの`constant.yml.dist`では9）を上限として長さと数字パターンを検証する。不可のときUIはhiddenとなり保存時に0に置換される。 |
| 利用条件 | 下限・上限は任意。入力がある場合は非負整数文字列として桁上限と数字パターンを満たす必要がある。両方入力かつ上限が下限未満ならエラー。 |
| ロゴ | 任意。非同期受け付けは画像MIMEとサイズ・拡張子のクライアント側制限がある。サーバ側は画像MIME接頭判定を追加で行う。登録時は一時から本保存への移動のみで、ファイル内容の再検証は移動の有無に留まる。 |

### 入力項目

| 項目名 | 必須／任意 | 最大長 | 初期値 | 保存先・扱い |
|--------|------------|--------|--------|----------------|
| 支払方法 | 必須 | Symfony Length制約は無し（DBはtext） | 既存行の現行値／新規は空に近い状態 | `payment_method` に相当する列。空白不可。 |
| 手数料 | 条件付き必須 | 数字として `int_len` 桁まで（コア確認値 9） | DB現行値／新規はフォーム送信値に依存 | `charge`。手数料設定不可のとき保存直前に 0。可のときは必須。不可のときフォーム上は hidden。 |
| 利用条件（下限） | 任意 | 数字として `int_len` 桁まで | DB現行値 | `rule_min`。空は未設定扱い。 |
| 利用条件（上限） | 任意 | 数字として `int_len` 桁まで | DB現行値 | `rule_max`。空は NULL になり得る。一覧では NULL を「無制限」表示に使う。 |
| ロゴ画像（ファイル） | 任意 | クライアント最大約 10MB | なし | アップロード成功で一時ディレクトリに保存。hidden にファイル名。登録成功で本保存ディレクトリへ移動。 |
| 手数料設定可否（hidden） | 任意 | — | DB現行値／新規は手数料編集可の既定 | 現行 `charge_flg`（移行先に該当列が見当たらない。ec-cube-enterprise 実装で要確認）。hidden。利用者が改ざんした場合でも保存処理で手数料 0 強制の分岐に載る可能性がある。 |
| 固定フラグ（hidden） | 任意 | — | DB現行値／新規は編集可の既定 | `fixed`（現行 `fix_flg`。移行先は boolean）。hidden。サーバ側で保存拒否はしない。一覧の導線制御に使う。 |

### エッジケース

| ケース | 扱い |
|--------|------|
| 固定フラグが編集不可の行 | 一覧では編集・削除リンクが無効化される。識別子を直接指定して編集画面へ来た場合でもサーバは固定フラグだけを理由に保存を拒否しない。 |
| 利用条件の上限が0以下または未入力で上限のみ | 一覧の利用条件列では上限側の「〜上限円」「無制限」が付かないことがある。 |
| 削除対象が存在しない | 削除用フラッシュを積み一覧へ戻る。永続化はしない。 |
| 表示順入替で隣接行が存在しない | エラーフラッシュを積み、ランクは変えない。 |
| 画像ファイルが一時領域に無いまま登録 | 画像移動は行われず、hiddenの値だけがそのまま保存され得る。 |

## データ整合性

| 観点 | 内容 |
|------|------|
| 一覧と編集 | 編集は識別子で読んだ行を正とする。一覧後に他管理者が変更した場合、編集画面は古い値から上書きし得る。 |
| 論理削除と配送 | 論理削除は支払行のフラグのみ更新する。配送方法側の中間テーブル参照の整合は別機能の責務である。 |
| 手数料一覧表示 | 一覧は保存値をそのまま表示する。グルーピングや通貨記号は当テンプレートでは付けない。 |
| 時刻・作成者 | 新規挿入時に作成日時・更新日時を現在時刻で埋め、管理者トークンがあれば作成者を現在の管理者にする。更新時は更新日時のみ自動更新する。 |

### DB操作

永続化の正は ec-cube-enterprise（テーブル名・操作は ec-cube-enterprise を正典）。当ドメインは承認ワークフローを介さず persist/flush で直接確定する（承認ワークフローは在庫機能固有）。

| 操作種別 | 対象テーブル | 契機・条件 |
|---------|--------------|------------|
| 登録/更新 | dtb_payment | 当機能が行う登録・更新で対象テーブルを直接保存する（不要な削除は含まない）。確定は persist/flush による即時反映。DB=ec-cube-enterprise を正典とする。 |

## バリデーション

| 項目 | 入力種別 | ルール・扱い |
|------|----------|--------------|
| 支払方法 | text | 必須。NotBlank。 |
| 手数料 | money（条件付き）またはhidden | 手数料設定可のとき必須。非負整数文字列。`int_len`桁上限。手数料不可のときhiddenで単体検証は効かないが保存で0に置換。 |
| 利用条件（下限・上限） | money | 任意。それぞれ非負整数文字列と桁上限。両方入力かつ上限が下限未満ならPOST_BINDで下限にエラー。 |
| ロゴ（ファイル） | file（マップなし） | 任意。非同期側は画像MIME。 |
| CSRF | hidden | 通常フォーム送信は標準トークン。削除・表示順は別トークン名で検証する実装である。無効時は拒否。 |

## 権限・認可

| 利用者状態 | 一覧・編集・登録 |
|------------|------------------|
| 管理画面未認証 | 管理画面の認証フローへ。 |
| `ROLE_ADMIN`を持ち、拒否URLに該当しない | 表示・保存・論理削除・表示順変更が可能。 |

## 画面遷移

| 条件 | 遷移先 |
|------|--------|
| 登録成功 | 支払方法一覧（GET）。 |
| 登録失敗 | 同一編集画面の再描画。 |
| 削除成功・対象不存在・表示順変更成功・失敗 | いずれも支払方法一覧（GET）。 |
| 未認証・拒否 | 管理画面のログインまたはエラー表示（フレームワーク設定を正とする）。 |

|------|--------------|------------------|
| 登録・削除・順序変更後 | 成功またはエラーに応じたフラッシュを積む | 一覧再表示でメッセージが見える。 |

## セッション

本機能が独自のセッションキーを読み書きする処理は持たない。管理画面セッションの仕様は管理画面ログインの設計を正とする。

---

## Cookie

本機能は独自の業務用Cookieを設定しない。セッション用Cookieは別機能・フレームワーク範囲とする。

---

## 排他制御・トランザクション

- 楽観ロック・バージョン列は持たない。複数管理者が同時に保存した場合は最後の保存が残る。
- 当画面の保存・削除・順序入替は明示的なトランザクション境界を張らず、Doctrineの単回または複数回のflushに従う。
