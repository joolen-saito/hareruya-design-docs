# F06-25（店頭モニターに受注管理から登録した番号札を表示）

## 概要

店頭の店内モニターに、商品準備が完了した注文の呼び出し番号（番号札）を一覧表示する機能である。モニター画面は一定間隔で注文番号取得APIをポーリングし、ピック完了済みの数字の番号札と、受注管理側で登録したアルファベットの番号札を取得して画面へ並べる。前回より新しい番号が増えたときは呼び出し音を鳴らす。表示枠を超える場合は連続する数字をまとめて整形する。

本書は実装手順ではなく、誰が・いつ・どの条件で・結果どうなるかを読むためのリバース詳細設計とする。確認値はpf-eccube3（EC-CUBE3系）のHareruyaEcプラグインの注文番号表示処理、注文番号表示テンプレート（`Waiting/waiting_number.twig`）、ポーリング用JS（`Block/js/waiting_get_js.twig`・モニター用`waiting_monitor.js`）、注文番号取得処理、番号札を扱うリポジトリを正とする。

本機能のカスタマイズ区分はカスタマイズであり、画面・挙動の参照はpf-eccube3を正とし、永続化（テーブル・列）に関する記述はリニューアル移行先のec-cube-enterpriseを正とする。

対象はブラウザ経由のフロント（店内モニター画面）に限定する。フロントのルートはサイトルート直下に言語別プレフィックス`/{_locale}`を付けて公開する。

本文ではフレームワークのコントローラ型名やメソッド名を主説明としない。ルートbind名の網羅は主説明とせず、「利用者視点の入口」にHTTPメソッドとサイトルートからのパスパターンを書く。

---

## 本書で扱うこと

- 店内モニター画面の入口とポーリングによる注文番号の取得・表示
- 表示対象の番号札（数字・アルファベット）の集計条件
- 表示最大件数を超えた場合の整形と、間の出荷完了番号の補完
- 新着時の呼び出し音

---

## 本書で扱わないこと

以下は本書では仕様確定せず、実装または別機能の設計を正とする。

- 数字の番号札を採番する受注側の処理（店頭注文の受注時に番号を生成する。受注・購入機能を正とする）
- アルファベットの番号札を登録・削除する受注管理の管理画面（番号札管理機能を正とする）
- 受注ステータス（ピック完了・出荷完了等）の遷移そのもの（受注管理機能を正とする）

## リニューアル移行時の扱い

現行（pf-eccube3）と移行先（ec-cube-enterprise）でのDB関連の差を記録する。本機能は表示専用で永続化を行わないため、参照先の名称をec-cube-enterpriseに合わせる。

| 観点 | 現行（pf-eccube3） | 移行先（ec-cube-enterprise） |
|------|--------------------|------------------------------|
| 数字の番号札 | `dtb_waiting_number`（`waiting_number`・`order_id`） | 同名テーブル・同名列が存在。加えて拠点参照`base_info_id`を持つ（拠点別の採番・表示に用いる）。 |
| アルファベットの番号札 | `dtb_waiting_tag`（`waiting_tag`） | 同名テーブル・同名列が存在。加えて拠点参照`base_info_id`を持つ。 |
| 受注ステータスの参照 | 受注テーブル（`dtb_order`）の受注ステータス | 同一スキーマ（`dtb_order`が存在）。 |
| 採番カウンタ | （現行は要確認） | `dtb_waiting_number_counter`（`current_value`・`base_info_id`）を持つ。移行後は拠点別カウンタで採番する。現行の採番方式との対応はec-cube-enterprise実装で要確認。 |

## 用語

| 用語 | 説明 |
|------|------|
| 番号札（数字） | 店頭注文に採番される数値の呼び出し番号。受注ステータスがピック完了のものを表示する。 |
| 番号札（アルファベット） | 受注管理側で登録するアルファベットの番号札。常に全件表示する。 |
| ピック完了 | 商品準備が完了した受注ステータス。表示対象の数字番号札の条件。 |
| 出荷完了 | 受け渡し済みの受注ステータス。表示枠超過時の補完判定に使う。 |
| 店内モニター | 店頭に設置する表示専用画面。第1・第2の2画面がある。 |

## 利用者視点の入口

| 入口 | URLエンドポイント | 期待されるふるまい |
|------|--------------------|--------------------|
| 店内モニター画面（第1） | `GET /{_locale}/waiting_number_1` | 注文番号表示画面を表示し、JSが注文番号取得APIをポーリングして番号札を並べる。 |
| 店内モニター画面（第2） | `GET /{_locale}/waiting_number_2` | 第1と同一の表示画面を表示する。 |
| 注文番号取得API | `GET /{_locale}/waiting_api/get_waiting` | ピック完了済みの数字番号札とアルファベット番号札の配列をJSONで返す。 |

`/{_locale}`は言語別プレフィックスである。第1・第2のモニターは同一テンプレートを表示する。利用者操作は無く、画面表示後はJSが自動でAPIを呼ぶ。

## フロント挙動

| 観点 | 内容 |
|------|------|
| 表示要素 | 番号表示枠（最大25区画の入力欄）に番号札を順に表示する。表示件数に応じて区画の大きさと文字サイズを切り替える。新着検知用の音声要素と、店内Wi-Fiパスワード表示用の要素を持つ。 |
| JS挙動 | 画面読込時に注文番号取得APIを1回呼び、以後10秒ごとにポーリングする。取得結果が前回より新しい番号を含む場合は呼び出し音を鳴らす。取得結果を表示枠へ流し込み、件数に応じて区画・文字サイズを調整する。取得失敗時は表示を変えない。 |
| CSS・レイアウト | モニター専用のスタイルを読み込む。番号件数で区画幅と文字サイズを段階的に変える。4文字以上の番号は文字サイズを縮める。 |
| モーダル・ポップアップ | モーダルは無い。新着時に音声を再生する。 |

Wi-Fiパスワード表示はモニター用JSが時刻に基づき定期更新する。注文番号表示とは独立した補助表示である。

---

## 処理フロー

### モニター画面を表示する（GET `/{_locale}/waiting_number_1`・`/waiting_number_2`）

1. 注文番号表示画面を表示する。番号表示枠・音声要素・ポーリング用JSを読み込む。

### ポーリングで番号札を取得する（JSが定期実行）

1. 画面読込時に注文番号取得APIを呼び、その後10秒ごとに呼ぶ。
2. 取得結果が前回リストより新しい番号を含むなら呼び出し音を鳴らす。
3. 取得結果を現在リストへ更新する。
4. 取得結果を表示枠へ流し込み、件数に応じて区画・文字サイズを調整する。
5. 取得が失敗した場合は表示を変えない。

### 注文番号取得API（GET `/{_locale}/waiting_api/get_waiting`）

1. 受注ステータスがピック完了の数字番号札を取得する。
2. アルファベットの番号札を全件（ID昇順）取得する。
3. 数字とアルファベットの合計が表示最大件数を超える場合は、数字番号札のあいだに位置する出荷完了済みの番号も補完して並べる（連続性の確保のため）。
4. 数字番号札・アルファベット番号札の順に並べた配列をJSONで返す。

## 業務ルール・計算

| 項目 | 内容 |
|------|------|
| 数字番号札の対象 | 受注ステータスがピック完了の注文に採番された番号札を対象とする。 |
| アルファベット番号札の対象 | 登録済みのアルファベット番号札を全件（ID昇順）対象とする。 |
| 並び順 | 数字番号札を先に、アルファベット番号札を後に並べる。 |
| 表示最大件数 | 設定値`waiting_monitor_max_size`（=25）を上限とする。 |
| 出荷完了の補完 | 数字とアルファベットの合計が上限を超える場合、直前に並べた数字の次番号からピック完了の次番号の手前までがすべて出荷完了なら、その区間の番号も並べる。 |
| クライアント側の整形 | 上限を超える場合、JSが連続する数字を「開始〜終了」にまとめて区画数を圧縮する。アルファベットは単独で並べる。 |
| 新着判定 | 取得結果が前回より長い、または前回に含まれない要素があるとき新着とみなし音を鳴らす。 |

本機能は利用者入力のフォームを持たないため入力項目は無い。

### エッジケース

| ケース | 扱い |
|--------|------|
| ピック完了の数字が0件 | アルファベット番号札のみを返す。 |
| 合計が上限以下 | 補完・整形を行わずそのまま並べる。 |
| 間の番号に未出荷が含まれる | その区間は補完しない。 |
| API取得失敗 | 表示を変更しない（前回表示を維持）。 |

## データ整合性

| 観点 | 内容 |
|------|------|
| 表示の鮮度 | 10秒ごとのポーリング時点での受注ステータス・番号札を反映する。受注側の更新からモニター反映まで最大1ポーリング分の遅延がある。 |
| 数字とアルファベット | 取得時点の受注ステータスと登録済み番号札を併せて返す。両者の整合は取得時点のDB状態に依存する。 |
| 補完区間 | 区間内番号がすべて出荷完了の場合のみ補完するため、未確定の区間は表示しない。 |

## DBカラム

機能に直接関係する列のみ記載する。型や一覧の細部はスキーマを参照する。

| テーブル | 列 | メモ |
|---------|-----|------|
| `dtb_waiting_number` | `waiting_number` | 数字の番号札。表示対象の数字。 |
| `dtb_waiting_number` | `order_id` | 紐づく受注。受注ステータスの判定に結合する。 |
| `dtb_waiting_number` | `base_info_id` | 拠点参照（ec-cube-enterpriseで保持。拠点別の採番・表示に用いる）。 |
| `dtb_waiting_tag` | `waiting_tag` | アルファベットの番号札。全件表示対象。 |
| `dtb_waiting_tag` | `base_info_id` | 拠点参照（ec-cube-enterpriseで保持）。 |
| `dtb_order` | 受注ステータス | ピック完了・出荷完了の判定に用いる（番号札取得時に結合）。 |

### DB操作

永続化の正は ec-cube-enterprise（テーブル名・操作は ec-cube-enterprise を正典）。当ドメインは承認ワークフローを介さず persist/flush で直接確定する（承認ワークフローは在庫機能固有）。

| 操作種別 | 対象テーブル | 契機・条件 |
|---------|--------------|------------|
| 登録/更新 | dtb_order / dtb_waiting_number / dtb_waiting_tag | 当機能が行う登録・更新で対象テーブルを直接保存する（不要な削除は含まない）。確定は persist/flush による即時反映。DB=ec-cube-enterprise を正典とする。 |
