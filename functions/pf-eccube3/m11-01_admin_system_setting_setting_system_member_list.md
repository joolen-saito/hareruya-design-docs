# システム設定 — メンバー管理一覧（システム情報設定/設定）

## 概要

管理画面の「システム情報設定」配下において、管理ログイン用の管理者アカウント（メンバー）を一覧表示し、各行から登録・編集・削除・表示順の入れ替えへ誘導する一覧機能である。ページタイトルブロックは「システム設定」、サブタイトルおよび一覧ボックス見出しは「メンバー管理」として表示される。

本書は実装手順ではなく、誰が・いつ・どの条件で・結果どうなるかを読むためのリバース詳細設計とする。対象は pf-eccube3 のメンバー一覧（index）と、一覧から実行する削除・上へ・下への各操作とする。一覧（index）はコア実装のままで、HareruyaEcプラグインによる一覧の上書きはない。登録・編集フォームの詳細は「メンバー管理」（M11-02）を正とする。

挙動・画面・処理フローの参照ソースツリーは pf-eccube3 を正とする。ただしDB関連の記述（テーブル名・列名・型・制約・関連・永続化先、DBカラム節、データ整合性のDB部分、副作用のDB更新）は、リニューアル後システムである ec-cube-enterprise の実装を正とする。両者でスキーマが食い違う点は「リニューアル移行時の扱い」に明記する。URLエンドポイントは管理画面コントローラのルート定義（`AdminControllerProvider`）で確認した利用者視点の入口として記載する。管理画面プレフィックスは `ADMIN_ROUTE`（`path.yml` の `admin_route`）で決まる。本書ではコントローラクラス名・ルートbind名は本文に置かない。

---

## 本書で扱うこと

- メンバー一覧の表示項目、並び順、件数・ページングの有無
- 一覧から新規登録・編集・削除・上へ・下へへ向かう利用者視点の導線と結果メッセージ
- 削除時の表示順繰り下げ、上へ・下へによる隣接行との表示順入れ替え
- ログイン中メンバー自身の行に対する削除リンクの非表示、先頭・末尾行での上へ・下へリンクの非表示
- 一覧初期化イベントおよび削除前後イベントによる拡張点（名称はコード内の `EccubeEvents` 定数を参照）

---

## 本書で扱わないこと

以下は本書では仕様確定せず、実装または別機能の設計を正とする。

- メンバーの登録・編集フォームの項目、検証、パスワード・ソルトの扱い、保存処理（「メンバー管理」M11-02 を正とする）
- 管理画面へのログイン、セッション、CSRF の名称形式、Remember Me、パスワードポリシー全般の詳細
- 権限マスタ（`mtb_authority`）の各行が拒否するパスの対応関係（「権限管理」画面および権限制御の実装を正とする）
- 管理画面 IP 制限やファイアウォールの判定順序の詳細
- ログイン認証時に参照する「稼働」マスタ値と非稼働メンバーの扱いの網羅（ログイン処理の実装を正とする）
- 本機能以外が `dtb_member` を更新する経路（バッチ、他画面、直接SQL）の一覧

## リニューアル移行時の扱い

- 基本設計の機能仕様（同シート上部）に記載される、所属・権限による絞り込み・ソート、および表示リストへの項目追加（デフォルト検索表示店舗、編集可能店舗、自動ログアウト、二段階認証など）は、リニューアル後の追加仕様である。現行の pf-eccube3 のコア一覧には実装されていない。pf-eccube3 の一覧は名前・所属・権限・稼働の4列と操作メニューのみで構成し、検索フォーム・絞り込みセレクト・ソートリンク・追加列は持たない。
- DB関連の記述は ec-cube-enterprise を正とする。挙動説明・画面構成は現行（pf-eccube3）の確認値だが、DBスキーマは移行先（ec-cube-enterprise）に合わせる。現行と移行先の主な差は次のとおり。
  - 表示順キー: 現行は `dtb_member.rank`、移行先は `dtb_member.sort_no`。いずれも降順で並べる。本書のDB記述は `sort_no` を正とする。
  - 削除方式: 現行は `dtb_member.del_flg` を立てる論理削除、移行先は `del_flg` 列を持たず物理削除である。本書のDB記述は物理削除（`del_flg` なし）を正とする。
  - 所属: 現行は `dtb_member.department` のテキスト、移行先は `dtb_member.department_id`（`mtb_department` 参照）のマスタFKである。一覧の「所属」列は移行先ではマスタ名称を表示する。
  - メールアドレス・所属店舗・デフォルト検索表示店舗・二段階認証・自動ログアウトは、移行先では `dtb_member` 本体の列（`email`、`base_info_id`、`default_search_base_info_id`、`two_factor_auth_enabled`、`is_auto_logout`）として存在する。編集可能店舗は移行先の結合表 `dtb_member_base_info` に保持する。現行ではこれらの列・表は存在しない（所属店舗・スマレジは現行プラグインの補助表 `dtb_member_sub` で代替）。これらは一覧の追加列・絞り込みの裏付けとなる。
- 移行時は、本書の現行挙動・画面と機能仕様（マトリックスでない一覧の追加列・絞り込み）、および現行↔移行先のスキーマ差分を移行設計で吸収する。

## 用語

| 用語 | 説明 |
|------|------|
| メンバー | 管理画面へログインするアカウント。`dtb_member` に保存される。フロントの会員（顧客）とは別物である。 |
| 表示順 | `dtb_member.sort_no` によるメンバー一覧の表示順。一覧は `sort_no` の降順で並べ、値が大きい行が先頭に来る（DB列は ec-cube-enterprise を正とする。現行 pf-eccube3 は `rank`）。 |
| 稼働 | `mtb_work` のマスタ項目。ログイン可否の判定に利用される値がコアに定義されている。一覧ではマスタ名称を「稼働」列に表示する。 |
| 権限 | `mtb_authority` のマスタ項目。パス単位の拒否リストと組み合わせて管理画面のアクセスを制御する（詳細は権限管理機能を正とする）。一覧ではマスタ名称を「権限」列に表示する。 |
| 所属 | メンバーの所属。移行先では `dtb_member.department_id`（`mtb_department` 参照）のマスタ名称を「所属」列に表示する（現行 pf-eccube3 は `department` のテキスト値）。 |
| 削除 | `dtb_member` の対象行を物理削除し、削除対象より大きい `sort_no` の行を繰り下げる扱い。移行先は `del_flg` 列を持たない（現行 pf-eccube3 は `del_flg` を立てる論理削除。差は移行時の扱いを参照）。 |

| 操作メニューから編集を開く | `GET /%admin_route%/setting/system/member/{id}/edit` | 選択した行のメンバー登録・編集画面（既存）へ遷移する。詳細は「メンバー管理」（M11-02）を正とする。 |
| ログイン中メンバー自身の行で削除を見る | —（一覧上リンク非表示） | 自分自身の行では削除がリンクにならず、文言のみが表示される。削除を実行できない。 |
| 他行の削除を実行する | `DELETE /%admin_route%/setting/system/member/{id}/delete` | 対象行を削除し、削除対象より大きい `sort_no` の行を繰り下げる。成功メッセージののち一覧へ遷移する。保存失敗時はエラーメッセージののち一覧へ遷移する。 |

| 存在しないIDで削除を実行する | `DELETE /%admin_route%/setting/system/member/{id}/delete` | 対象が見つからない場合は削除警告メッセージを積み、一覧へ遷移する。404 にはしない。 |

## フロント挙動

| 観点 | 内容 |
|------|------|
| 表示要素 | 一覧テーブルの列は、名前、所属、権限（マスタ名称）、稼働（マスタ名称）、操作メニュー。各行の操作メニューはドロップダウンで、編集・削除・上へ・下へを表示する。画面下部に新規登録ボタンを置く。検索フォーム・絞り込みセレクト・ソートリンクは持たない。 |
| 表示条件付き要素 | 削除は、行のメンバーがログイン中メンバー自身の場合はリンクにせず文言のみとし、それ以外はトークン付きの削除リンクとする。上へは先頭行で出さず、下へは末尾行で出さない。 |
| JS 挙動 | 一覧テンプレートに `changeAction` 関数が定義されているが、当該テンプレート内で呼び出しはなく、本機能の主操作には使われない確認値である。削除・上へ・下へは共通スクリプトにより、`data-method` とトークン用属性を付与した疑似フォーム送信で DELETE または PUT を行う。削除リンクは共通スクリプトの既定の確認ダイアログに従い、上へ・下へは `data-confirm="false"` を付けて確認ダイアログを出さない。 |
| CSS・レイアウト | 管理画面標準の Bootstrap 系テーブル・ドロップダウンメニューを用いる。 |
| モーダル・ポップアップ | Bootstrap モーダルは用いず、削除確認はブラウザの確認ダイアログに依存する。 |
| 入力項目 | 一覧画面は検索・絞り込みの入力項目を持たない。登録・編集フォームの入力項目は本機能では扱わない。 |

## 処理フロー

### 一覧を開く（GET）

1. 管理画面の認証・認可・ネットワーク制限などの前置処理を通過する（詳細は管理画面基盤の実装を正とする）。
2. `dtb_member` を `sort_no` 降順のみの条件で取得する。削除済みの行は取得対象から除外する（移行先は物理削除のため対象行自体が存在しない。現行 pf-eccube3 は `del_flg` フィルタで除外）。稼働状態による絞り込みは行わない。
3. 空のフォームビルダを生成し、一覧向け初期化イベントをディスパッチする。プラグイン等がビルダや一覧に干渉し得る。コアの一覧テンプレートはフォーム行を描画しないため、ビルダへ項目を足しても画面に出ない限り利用者視界には効かない。
4. テンプレートにフォームビュー（コアでは実質空に近い）とメンバー配列を渡して描画する。件数集計・ページング処理は行わない。

### 上へ（PUT）

1. トークンを検証する。無効ならアクセス拒否となる。
2. 対象メンバーを取得する。無ければ 404 とする。
3. PUT のとき、上へ処理を呼ぶ。自身の `sort_no` より 1 大きい行と `sort_no` を交換する。隣が存在しないなどで処理できない場合は失敗とする。
4. 成否に応じて成功またはエラーメッセージを積み、一覧へリダイレクトする。

### 下へ（PUT）

上へと同様に、自身の `sort_no` より 1 小さい行と `sort_no` を交換する。先頭・末尾などで隣接行が無い場合は失敗とし、エラーメッセージを積む。

### 削除（DELETE）

1. トークンを検証する。無効ならアクセス拒否となる。
2. 対象メンバーを取得する。見つからない場合は削除警告メッセージを積み、一覧へリダイレクトする（404 にはしない）。
3. 見つかった場合は削除前イベントをディスパッチし、削除処理を呼ぶ。削除対象より大きい `sort_no` の全行を 1 つ繰り下げたうえで、対象メンバーを物理削除する（移行先は `del_flg` を持たない。現行 pf-eccube3 は `del_flg` を立て `rank` を 0 にする論理削除）。
4. 成功時は削除完了イベントをディスパッチし、成功メッセージを積む。失敗時はエラーメッセージを積む。
5. 一覧へリダイレクトする。

## 集計条件

| 指標 | 集計の要点 |
|------|------------|
| 一覧の並び | `dtb_member` を `sort_no` 降順で並べ替える。件数表示やページングは行わない。 |
| 一覧の対象 | 削除されていないメンバーを対象とする（移行先は物理削除のため削除済み行は存在しない）。稼働・非稼働の区別による絞り込みはしない。 |
| 削除時の繰り下げ | 削除対象より大きい `sort_no` の全行を 1 つ繰り下げる。 |
| 上へ・下への入れ替え | 対象行の `sort_no` と、隣接する `sort_no`（上へは +1、下へは -1）の行とで `sort_no` を交換する。 |

## 主操作時の判定順序

| 順序 | 判定 | 結果 |
|------|------|------|
| 1 | 削除・上へ・下へのトークンが有効か | 無効ならアクセス拒否応答とし、以降を実行しない。 |
| 2 | 対象メンバーが存在するか（上へ・下へ） | 存在しなければ 404 応答とする。 |
| 3 | 対象メンバーが存在するか（削除） | 存在しなければ削除警告メッセージを積み一覧へ戻る。404 にはしない。 |
| 4 | 削除・入れ替えの保存が成功したか | 成功なら完了メッセージ、失敗ならエラーメッセージを積み一覧へ戻る。 |

## 業務ルール・計算

本機能では金額集計や税率計算は行わない。一覧画面は入力フォームを持たないため、入力項目の検証は行わない。登録・編集フォームの入力項目は「メンバー管理」（M11-02）を正とする。

### エッジケース

| ケース | 扱い |
|--------|------|
| 削除後の一覧 | 移行先は物理削除であり、削除された行は一覧結果に含まれない（現行 pf-eccube3 は `del_flg` を立てる論理削除で行自体は残る）。 |
| 削除対象が存在しない | 対象が見つからず、削除警告メッセージを積んで一覧へ戻る。404 にはしない。 |
| 上へ・下へで隣接行が無い | 先頭行の上へ、末尾行の下へは一覧上にリンクを出さない。仮に隣接行が無い状態で実行された場合は失敗としてエラーメッセージを積む。 |
| ログイン中メンバー自身の行の削除 | 一覧では削除をリンクにせず文言のみとする。サーバ側で同一IDを特別拒否するコードはコアに無い。 |
| 非稼働メンバー | 一覧は稼働条件なしで取得するため、非稼働メンバーも表示される。ログイン可否の判定はログイン処理を正とする。 |

## データ整合性

| 観点 | 内容 |
|------|------|
| 一覧とDB | 一覧表示は取得直前の `dtb_member` の内容を反映する。並びは `sort_no` 降順のみで、削除済みは除外する。 |
| 表示順の一意性 | 入れ替え・削除は隣接または該当範囲の `sort_no` 更新で整合を取る設計だが、同時操作による競合時の保証は本書では切らない。 |
| 一覧とログイン可否 | 一覧は稼働条件なし取得のため、非稼働メンバーも表示され得る。実際のログイン可否は認証処理の判定を正とする。 |
| 一覧と編集画面 | 一覧の表示値は当該行の `dtb_member` 現行値である。編集画面側の表示・保存は M11-02 を正とする。 |

DB関連は ec-cube-enterprise の実装を正とする（SKILL 手順 1c）。下表は一覧・削除・順序変更に直接関係する列のみを記載する。

| テーブル | 列 | メモ |
|---------|-----|------|
| dtb_member | id | 主キー。自動採番。一覧の各行・操作リンクのID指定に用いる（移行先のPK列名は `id`。現行 pf-eccube3 は `member_id`）。 |
| dtb_member | name | 名前。「名前」列に表示する。 |
| dtb_member | department_id | 所属。`mtb_department` 外部キー。「所属」列にマスタ名称を表示する（現行 pf-eccube3 は `department` テキスト列）。 |
| dtb_member | authority_id | `mtb_authority` 外部キー。「権限」列にマスタ名称を表示する。 |
| dtb_member | work_id | `mtb_work` 外部キー。「稼働」列にマスタ名称を表示する。 |
| dtb_member | sort_no | 表示順。一覧は降順。削除時は削除対象より大きい表示順の行を繰り下げる。上へ・下へで隣接行と交換する（現行 pf-eccube3 は `rank`）。 |
| dtb_member | update_date | 更新日時。順序変更時に更新され得る確認値。 |
| mtb_department | id / name | 所属マスタ。一覧の「所属」列の表示名称を提供する。 |
| mtb_authority | id / name | 権限マスタ。一覧の「権限」列の表示名称を提供する。 |

本機能単体で新種の Cookie を設定したり解釈したりする処理は持たない。セッション Cookie は管理画面ログインの枠組みに依存する。

## 排他制御・トランザクション

削除・上へ・下へはリポジトリ処理で `sort_no` 更新・削除と flush を行い、トランザクション内でコミットまたはロールバックする。行レベルの楽観ロック列は持たない（DB列・削除方式は ec-cube-enterprise を正とする）。
