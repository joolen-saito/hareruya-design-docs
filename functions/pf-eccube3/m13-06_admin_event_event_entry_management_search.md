# M13-06（イベント申込検索）

管理画面「イベント管理」のイベント申込一覧で、登録済みの申込を申込者・支払・開催日時などの条件で検索し、申込（または登録デッキ）を一覧表示する機能である。

## 概要

イベント申込検索は、管理者がイベント申込を絞り込み、一覧から申込の編集・一括編集・CSV出力・デッキ表示などへ進むための入口となる機能である。検索は「イベント申込検索」と「デッキ登録検索」の2モードを持ち、選択したモードにより集計対象（申込プレイヤー単位かデッキ単位か）とソートキーが切り替わる。検索条件・表示件数・ソート条件はセッションに保持し、ページ送りや再表示で復元する。

本書は実装手順ではなく、誰が・いつ・どの条件で・結果どうなるかを読むためのリバース詳細設計とする。既存実装のふるまい、参照するデータ、2モードの分岐、検索条件の保持、ページング、ソートの挙動を確認し、仕様の確からしさを把握することを目的とする。

対象はブラウザ経由の管理画面イベント申込一覧である。本機能は晴れる屋向けプラグインで提供され、EC-CUBE3系のSilexアプリケーション上で動作する。管理画面プレフィックスはアプリケーション設定`admin_route`（`$app['config']['admin_route']`）で決まり、ルートはこの値を連結して登録される。確認観点は申込用サービスプロバイダのルート登録とする。

イベント一覧検索はM13-01、イベント編集/削除はM13-02を正とする。申込の新規登録・編集・一括編集・CSV出力・CSV取込・デッキ表示（別ウィンドウ）は本書では扱わない。デッキ表示画面の中身はM13-08を正とする。

本機能のカスタマイズ区分はカスタマイズである。挙動の参照リポはpf-eccube3（HareruyaEcプラグイン）の現行実装とし、DB関連（永続化先のテーブル名・列名、DBカラム節、保存先・扱い、副作用のDB更新）はec-cube-enterpriseを正とする。現行と移行先でスキーマが異なる箇所はリニューアル移行時の扱いに集約する。

## 処理フロー

### 申込一覧を初期表示する

1. 管理者が申込一覧を開く。
2. 検索フォーム（フォーム名`admin_entry_list`）を生成する。
3. 検索条件セッション（`admin.event_entry.search`、`admin.event_entry.search.page_no`、`admin.event_entry.search.page_count`）を削除する。
4. 一覧結果を空、ページ番号1、表示件数を既定として一覧テンプレートを描画する。イベント検索モーダル・一括編集モーダルの呼び出し用フォームも渡す。

### 検索フォームを送信して絞り込む

1. 管理者が条件と検索モードを選び、検索ボタンを押す。
2. 検索フォームを生成し、リクエストを反映する。
3. ソートキー・並び順を決める。優先順位はリクエスト、セッション、既定の順。並び順が`ASC`／`DESC`以外なら並び順エラーを表示し初期表示へ戻す。
4. 表示件数を決める。リクエストの`page_count`がマスタに存在すれば採用しセッションへ保存する。
5. フォームから検索条件を取り出す。空でセッションに条件が残っていれば復元する。条件もセッションも無ければ初期表示へ戻す。
6. 検索条件にソートキー・並び順を付与し、検索モードに応じてクエリビルダと件数を取得する（後述の集計条件）。
7. 最終ページのデータ削除等で当該ページに表示対象が無くなった場合、ページ番号を1つ前に補正する。
8. ページ番号・検索条件・ソートキー・並び順・表示件数をセッションへ保存する。
9. ページネーターで該当ページを取得し、一覧テンプレートを描画する。検索モードに応じてソートキー候補を切り替える。

### イベント詳細指定表示（特定日程の申込一覧）

1. パスのイベント詳細IDを検索フォームのイベント詳細IDに設定する。
2. ソート・並び順は既定とする。
3. 表示件数を決め、検索条件をセッションへ保存する。
4. 検索モードを`entriedEvent`（イベント申込検索）に固定し、申込プレイヤーのクエリビルダで該当ページを取得して一覧テンプレートを描画する。

### ページ送り・表示件数変更・ソート変更

1. ページ送り等のリンクは検索処理と同じ処理を呼ぶ。
2. リクエストにフォーム検索条件が無いため、セッションの検索条件を復元して再検索する。
3. リクエストの`sort`・`order`・`page_count`があれば優先して反映する。

## 集計条件

| 指標 | 集計の要点 |
|------|------------|
| イベント申込検索（`entriedEvent`） | 申込プレイヤー（`dtb_entry_player`）を集計単位とし、申込プレイヤーリポジトリのクエリビルダ・件数取得を用いる。ソートキーがデッキ登録用のキーに該当する場合は申込用の既定キー（`default`）へ補正する。 |
| デッキ登録検索（`registedDeck`） | デッキ（`dtb_deck`）を集計単位とし、デッキリポジトリのクエリビルダ・件数取得を用いる。ソートキーが申込用のキーに該当する場合はデッキ用の既定キー（`deckDate`）へ補正する。 |
| ソートキー候補 | イベント申込検索では申込用ソートキー（`default`＝申込ID、`entryDate`＝申込日時、`entryStatus`＝申込状況など）、デッキ登録検索ではデッキ用ソートキー（`deckDate`、`deckUpdate`、`startDate`など）を一覧のソートメニューに出す。 |

## 業務ルール・計算

| 項目 | 内容 |
|------|------|
| 検索モード | 検索モードによって集計対象（申込プレイヤー単位／デッキ単位）と既定ソートキーが切り替わる。モードはフォーム必須項目。 |
| ソートキー補正 | 選んだモードと整合しないソートキー（他モード用のキー）が来た場合、当該モードの既定ソートキーへ補正する。 |
| イベント名検索 | イベント名の語による絞り込み（申込・デッキの検索クエリ側で処理）。 |
| 開催日時 | 開催日時From・Toで日程の開始日時を絞り込む。Fromは初期値として当日0時を持つ。 |
| 表示形式 | 件数は整数で表示する。金額計算・税計算・丸めは行わない。 |

### 検索フォームの入力項目

| 項目名 | 必須／任意 | 最大長 | 初期値 | 保存先・扱い |
|--------|------------|--------|--------|----------------|
| イベント名 | 任意 | 一行テキスト（フォーム上の`Length`なし） | 空 | 検索条件キー`multi`。永続化しない。イベント名等への絞り込み。 |
| 申込状況 | 任意 | セレクト（複数） | 未選択 | 検索条件キー`entry_status`。申込状況マスタ（`MtbEntryStatus`）。 |
| 支払方法 | 任意 | セレクト（複数） | 未選択 | 検索条件キー`payment`。支払方法（`Payment`）の所定ID群、ランク昇順。 |
| 支払番号 | 任意 | 64文字（`entry.length.payment_no`、`maxlength`属性） | 空 | 検索条件キー`paymentNo`。 |
| プレイヤー名 | 任意 | 255文字（`entry.length.name`、`maxlength`属性） | 空 | 検索条件キー`player`。 |
| DCIナンバー | 任意 | 複数行入力（textarea） | 空 | 検索条件キー`dci_no`。 |
| 開催日時From | 任意 | 日時（`single_text`、設定の日時書式） | 当日0時 | 検索条件キー`date.from`。日程の開始日時の下限。 |
| 開催日時To | 任意 | 日時（`single_text`、設定の日時書式） | 空 | 検索条件キー`date.to`。日程の開始日時の上限。 |
| 確認済 | 任意 | 複数選択（展開） | 未選択 | 検索条件キー`confirm_flg`。選択肢は確認済（保存値`true`）・未確認（保存値`false`）。 |
| デッキ登録有無 | 任意 | 複数選択（展開） | 未選択 | 検索条件キー`deckEntried`。選択肢は登録済（保存値`true`）・未登録（保存値`false`）。 |
| 店舗 | 任意 | セレクト（複数） | 未選択 | 検索条件キー`shop`。店舗マスタ（`MtbShop`）。 |
| 検索モード | 必須 | 選択（展開） | イベント申込検索 | 検索条件キー`searchMode`。選択肢はイベント申込検索（保存値`entriedEvent`）・デッキ登録検索（保存値`registedDeck`）。 |
| イベント詳細ID | 任意 | 整数（10桁以内、`Regex`） | 空 | 検索条件キー`event_detail_id`。特定日程に絞る。イベント詳細指定表示ではパス値を設定する。 |

最大長の数値はプラグイン設定（`config.yml`の`entry.length`）の確認値を記載する。運用環境で上書きされている場合はその環境の値が正とする。

### エッジケース

| ケース | 扱い |
|--------|------|
| 検索モードと整合しないソートキー | 当該モードの既定ソートキーへ補正する。 |
| 並び順に不正値 | 並び順エラーを表示し初期表示へ戻す。 |
| 検索条件もセッションも無い | 初期表示へ戻す。 |
| 最終ページのデータが削除され表示対象が無くなった | ページ番号を1つ前に補正して表示する。 |
| イベント詳細指定表示 | 検索モードを`entriedEvent`に固定して特定日程に絞り込む。 |
| 該当0件 | 0件として一覧を描画する。 |

## データ整合性

| 観点 | 内容 |
|------|------|
| 参照時点 | 一覧の件数と行は検索実行時にデータベースから読み取った値である。表示後の申込・デッキの更新は自動反映しない。 |
| 検索条件の保持 | 検索条件・表示件数・ソートキー・並び順・ページ番号はセッション（接頭辞`admin.event_entry`）に保存し、ページ送り・再表示・デッキ表示・CSV出力で参照する。 |
| デッキ表示・CSVとの整合性 | デッキ表示（M13-08）とCSV出力は、申込一覧の検索条件セッションを読んで対象を決める。検索後に条件を変えずに開けば同一条件の対象を扱う。 |
| 件数と行の整合性 | 件数は検索モードに応じた件数取得で求め、表示行はページネーターが取得する。 |

## API/バッチ結果

本機能ではAPI呼び出し・バッチ実行を扱わない。検索結果の一覧表示のためにデータベースを読み取るのみである。イベント検索モーダル・プレイヤー検索モーダルの非同期取得は本書では扱わない。

| 成功時出力 | 検索フォームと、該当時は申込（またはデッキ）一覧テーブルを含むHTMLをサーバ側で描画する。 |
| 失敗時出力 | 並び順不正時は並び順エラーを表示し初期表示へ戻す。 |
| 副作用 | 検索条件セッションへの書き込み（検索・ページ送り・詳細指定時）または削除（初期表示時）。台帳の更新は行わない。 |

## DBカラム

当機能の検索条件・表示・集計に直接関係する代表的な列のみを記載する。型や一覧の細部、検索クエリの結合詳細はスキーマと各リポジトリ実装を正とする。列名はec-cube-enterpriseを正とし、現行（pf-eccube3）と異なる場合は現行名を括弧で添える。

| テーブル | 列 | メモ |
|---------|-----|------|
| `dtb_event_entry` | `id`（現行`event_entry_id`）、`event_detail_id`、`entry_status_id`、`payment_id` | 申込検索・申込状況・支払方法の絞り込み、既定ソート。 |
| `dtb_entry_player` | `id`（申込プレイヤーの識別列）、`event_entry_id`、`player_id` | イベント申込検索の集計単位。 |
| `dtb_deck` | `id`（現行`deck_id`）、`create_date`、`update_date`、`event_detail_id` | デッキ登録検索の集計単位とソートキー。開催日のソートは`dtb_event_detail.start_date`との結合で行う。 |
| `dtb_event_detail` | `id`（現行`event_detail_id`）、`start_date` | 開催日時の絞り込み、特定日程の指定。 |
| `dtb_event` | `name_jp`、`name_en`、`base_info_id`（現行`shop_id`） | イベント名・店舗の絞り込み。 |

### DB操作

永続化の正は ec-cube-enterprise（テーブル名・操作は ec-cube-enterprise を正典）。当ドメインは承認ワークフローを介さず persist/flush で直接確定する（承認ワークフローは在庫機能固有）。

| 操作種別 | 対象テーブル | 契機・条件 |
|---------|--------------|------------|
| 登録/更新 | dtb_deck / dtb_entry_player / dtb_event / dtb_event_detail / dtb_event_entry | 当機能が行う登録・更新で対象テーブルを直接保存する（不要な削除は含まない）。確定は persist/flush による即時反映。DB=ec-cube-enterprise を正典とする。 |

## 画面遷移

| 条件 | 遷移先 |
|------|--------|
| 一覧を開く | 同一画面に検索フォームを表示。 |
| 検索フォーム送信 | 同一画面に検索結果一覧を表示。 |
| ページ送り・件数変更・ソート | 同一画面に再検索結果を表示。 |
| イベント詳細指定表示 | 同一画面に特定日程の申込一覧を表示。 |
| デッキ表示ボタン | デッキ表示画面を別ウィンドウで開く（M13-08）。 |
| CSV出力 | 申込CSVのダウンロード（本書では扱わない）。 |
| 申込の編集リンク | 申込編集画面（本書では扱わない）。 |

### 遷移時に引き継ぐ状態

| 起点 | 遷移前の処理 | 遷移後の初期状態 |
|------|--------------|------------------|
| 検索フォーム送信・ページ送り | 検索条件・表示件数・ソートキー・並び順・ページ番号をセッション（`admin.event_entry`）へ保存する。 | 同条件で一覧を再描画する。 |
| 一覧初期表示（`/entry/list`） | 検索条件セッションを削除する。 | 検索フォームのみを表示し結果は表示しない。 |
| デッキ表示・CSV出力 | 申込一覧の検索条件セッションを読む。 | 同一条件の対象でデッキ表示・CSVを生成する。 |

本機能は申込検索のために新たなCookieを設定しない。セッションCookieは管理画面共通の仕組みを正とする。
