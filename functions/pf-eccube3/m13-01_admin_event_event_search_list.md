# M13-01（イベント一覧検索）

管理画面「イベント管理」のイベント一覧で、登録済みのイベントをイベント名・開催日・会場・フォーマット・ルール適用度の条件で検索し、該当イベントを一覧表示する機能である。

## 概要

イベント一覧検索は、管理者が登録済みのイベントを絞り込み、一覧から編集・削除・新規登録へ進むための入口となる機能である。検索条件・表示件数・ソート条件はセッションに保持し、ページ送りや再表示で復元する。

本書は実装手順ではなく、誰が・いつ・どの条件で・結果どうなるかを読むためのリバース詳細設計とする。既存実装のふるまい、参照するデータ、検索条件の保持、ページング、ソートの挙動を確認し、仕様の確からしさを把握することを目的とする。

カスタマイズ区分はカスタマイズであり、挙動の参照リポはpf-eccube3、DB関連の記述はec-cube-enterpriseを正とする。

対象はブラウザ経由の管理画面イベント一覧である。本機能は晴れる屋向けプラグインで提供され、EC-CUBE3系のSilexアプリケーション上で動作する。管理画面プレフィックスはアプリケーション設定`admin_route`（`$app['config']['admin_route']`）で決まり、ルートはこの値を連結して登録される。確認観点はプラグインのルート登録（イベント用サービスプロバイダ）とする。

イベントの編集・削除はM13-02、複製新規はM13-05、申込検索はM13-06、デッキ表示はM13-08を正とする。本書ではコントローラのメソッド単位の解剖を主題としない。

- イベント一覧の初期表示と、検索フォーム送信による絞り込みのふるまい
- 検索条件（イベント名・開催日From／To・会場・フォーマット・ルール適用度）の判定

- ページング、最終ページのデータ消失時の前ページ表示
- 一覧から編集・削除・新規登録への導線（入口としての役割に限る）

現行（pf-eccube3）と移行先（ec-cube-enterprise）の差を記録する。DB関連はec-cube-enterpriseを正とする。検索・ページング・ソートの挙動は現行（pf-eccube3）を正とする。

| 観点 | 現行（pf-eccube3） | 移行先（ec-cube-enterprise） |

| イベント名の桁 | `name_jp`・`name_en`は最大255文字 | `name_jp`・`name_en`は最大155文字。桁が縮小する。 |
| 開催日Fromの参照列 | `dtb_event_detail.start_date` | 同名の`start_date`。同一。 |

| 用語 | 説明 |
|------|------|
| イベント | イベント管理で登録される大会・大会企画の1レコード。テーブルは`dtb_event`。 |
| イベント詳細 | 1つのイベントにぶら下がる開催日程の1レコード。テーブルは`dtb_event_detail`。開催日Fromや開催日Toの絞り込みはこの開始日時を参照する。 |

| フォーマット | イベントに紐づくフォーマットマスタ（`MtbFormat`）。1イベントに複数紐づき得る。検索条件の1つ。 |

## 利用者視点の入口

| 入口 | URLエンドポイント | 期待されるふるまい |
|------|--------------------|--------------------|
| イベント一覧を開く | `GET /%admin_route%/event/list` | 検索フォームを表示し、検索条件セッションを初期化する。一覧結果は表示しない。 |
| 検索フォームを送信 | `POST /%admin_route%/event/search/{page_no}` | 検索条件で絞り込み、該当イベントを一覧表示する。条件・表示件数・ソートをセッションに保存する。 |
| ページ送り・表示件数変更・ソート変更 | `GET /%admin_route%/event/page/{page_no}` | セッションの検索条件を復元し、指定ページ・件数・ソートで再検索して表示する。 |
| 新規登録ボタン | `GET /%admin_route%/event/new` | イベント登録フォームへ遷移する（M13-02の範囲）。 |
| 行の編集リンク | `GET /%admin_route%/event/{id}/edit` | イベント編集画面へ遷移する（M13-02の範囲）。 |
| 行の削除リンク | `DELETE /%admin_route%/event/{id}/delete` | イベント削除を実行する（M13-02の範囲）。 |

`/event/search/{page_no}`はGETとPOSTの両方を受け付けるルート（`match`）として登録される。一覧テンプレートのフォームはPOSTで送信する。

## 処理フロー

### イベント一覧を初期表示する

1. 管理者がイベント一覧を開く。
2. 検索フォームを生成する。フォーム名は`admin_event_list`、CSRF保護は無効。
3. 検索条件セッション（`admin.event.search`、`admin.event.search.page_no`、`admin.event.search.page_count`）を削除する。
4. ソート参照用にイベントリポジトリをセットする。
5. 一覧結果を空、ページ番号を1、表示件数を既定（`default_page_count`）として一覧テンプレートを描画する。検索結果テーブルは描画しない。

### 検索フォームを送信して絞り込む

1. 管理者が検索条件を入力し、検索ボタンを押す。
2. 検索フォームを生成し、リクエストを反映する。
3. ソートキーを決める。優先順位はリクエストの`sort`、次にセッションのソートキー、無ければ既定（`default`）。並び順も同様にリクエストの`order`、セッション、既定（`DESC`）の順で決める。並び順が`ASC`／`DESC`（大文字小文字可）以外なら並び順エラーを表示し、初期表示へ戻す。
4. 表示件数を決める。優先はセッション値、無ければ既定。リクエストの`page_count`がページ表示件数マスタに存在する値なら採用しセッションへ保存する。
5. フォームから検索条件を取り出す。検索条件が空でセッションに条件が残っていれば、それを復元して再構築する。条件もセッションも無ければ初期表示へ戻す。
6. 検索条件にソートキー・並び順を付与し、イベントリポジトリで検索クエリと件数を取得する。
7. 最終ページのデータ削除等で当該ページに表示対象が無くなった場合（件数が前ページまでの件数と一致する場合）、ページ番号を1つ前に補正する。
8. ページ番号・検索条件・ソートキー・並び順・表示件数をセッションへ保存する。
9. ページネーターで該当ページを取得し、一覧テンプレートを描画する。

### ページ送り・表示件数変更・ソート変更

1. ページ送り・表示件数・ソートのリンクは検索処理と同じ処理を呼ぶ。
2. リクエストにフォーム検索条件が無いため、セッションの検索条件を復元して再検索する。
3. リクエストの`sort`・`order`・`page_count`があればそれを優先して反映する。

## 集計条件

| 指標 | 集計の要点 |
|------|------------|
| 検索結果件数 | 検索条件で絞り込んだイベント（`dtb_event`の`e`）の件数。件数取得は同一の検索クエリビルダに対し`count(e)`を実行する。イベント詳細・フォーマットを左外部結合するため、開催日条件やフォーマット条件で同一イベントが複数行に展開され得るが、件数は`count(e)`で求める。 |

## 業務ルール・計算

| 項目 | 内容 |
|------|------|
| イベント名検索 | 入力値の全角空白を半角化したうえで、半角空白・全角空白・カンマで分割する。分割した各語について、イベント名（日）・イベント名（英）・略称（日）・略称（英）の4列に対する部分一致（前後ワイルドカード）をORで結び、語ごとの条件をANDで結ぶ。 |
| 開催日From | 入力日時以降にイベント詳細の開始日時があるイベントを対象とする（`ed.startDate >= From`）。 |
| 開催日To | 入力日付に1日加算した日時より前にイベント詳細の開始日時があるイベントを対象とする（`ed.startDate < To+1日`）。実質、指定日を含む日までを対象とする。 |
| フォーマット | 指定フォーマットIDがイベントのフォーマットに含まれるイベントを対象とする（フォーマット結合の`ef.formatId`との一致）。 |
| ルール適用度 | 指定ルール適用度IDに一致するイベントを対象とする（`e.rel`）。 |
| 会場 | 指定会場に一致するイベントを対象とする（`e.venue`）。 |
| 店舗 | 一覧検索フォームには店舗欄が定義されるが、一覧テンプレートでは表示せず、検索クエリでも条件に用いない。 |
| ソート | ソートキーは`default`（イベントID）または`eventName`（イベント名・日）。並び順はソートキーごとに指定の昇順／降順を適用する。 |
| 表示形式 | 件数は整数で表示する。一覧の行はイベントIDとイベント名（日と英を半角空白で連結）で構成する。金額計算・税計算・丸め処理は行わない。 |

### 検索フォームの入力項目

| 項目名 | 必須／任意 | 最大長 | 初期値 | 保存先・扱い |
|--------|------------|--------|--------|----------------|
| イベント名 | 任意 | `stext_len`（確認値50、`Length`の最大に適用） | 空 | 検索条件キー`multi`。永続化しない。イベント名（日）・イベント名（英）・略称（日）・略称（英）への部分一致検索に用いる。 |
| 開催日From | 任意 | 日付（`yyyy-MM-dd`） | 現在日時から`search_form.default_from_term`（確認値`-3 month`）を適用した日 | 検索条件キー`start_date_from`。永続化しない。`dtb_event_detail.start_date`の下限。 |
| 開催日To | 任意 | 日付（`yyyy-MM-dd`） | 空 | 検索条件キー`start_date_to`。永続化しない。`dtb_event_detail.start_date`の上限（指定日に1日加算した未満）。 |
| フォーマット | 任意 | セレクト（単一） | 未選択 | 検索条件キー`formats`。永続化しない。フォーマットマスタ（`MtbFormat`）。`dtb_event_format.format_id`との一致。 |
| 会場 | 任意 | セレクト（単一） | 未選択 | 検索条件キー`venue`。永続化しない。会場マスタ（`MtbVenue`）。`dtb_event.venue_id`との一致。 |
| ルール適用度 | 任意 | セレクト（単一） | 未選択 | 検索条件キー`rel`。永続化しない。ルール適用度マスタ（`MtbRel`）。`dtb_event.rel_id`との一致。 |

最大長の数値はプラグイン設定およびコア設定の確認値を記載する。運用環境で上書きされている場合はその環境の値が正とする。店舗欄（キー`shop`）はフォーム定義に存在するが一覧画面では表示・利用しない。

### エッジケース

| ケース | 扱い |
|--------|------|
| イベント名が空白・カンマのみ | 分割後の各語が空になり、イベント名条件を追加しない。 |
| 開催日FromとToが逆転 | 両条件をANDで適用するため、該当が無ければ0件になる。範囲整合のバリデーションは行わない。 |
| 開催日条件があり詳細が無いイベント | 詳細を左外部結合するが開催日条件は詳細列を参照するため、詳細が無いイベントは開催日条件に一致せず除外される。 |
| 並び順に不正値 | 並び順エラーを表示し初期表示へ戻す。 |
| 最終ページのデータが削除され表示対象が無くなった | ページ番号を1つ前に補正して表示する。 |
| 該当0件 | 「検索条件に該当するデータがありませんでした。」を表示する。 |

## データ整合性

| 観点 | 内容 |
|------|------|
| 参照時点 | 一覧の件数と行は、検索実行時にデータベースから読み取った値である。表示後にイベントが更新・削除されても表示中の一覧は自動更新しない。 |
| 検索条件の保持 | 検索条件・表示件数・ソートキー・並び順・ページ番号はセッションに保存し、ページ送り・再表示で復元する。一覧初期表示（`/event/list`）ではこれらを削除する。 |
| 一覧と編集の整合性 | 一覧の行から編集・削除へ遷移した後の値の正は、遷移先（M13-02）の処理時点のデータとする。 |
| 件数と行の整合性 | 件数は`count(e)`で求め、表示行はページネーターが取得する。詳細・フォーマットの左外部結合により内部のSQL行は重複し得るが、表示はイベント単位で行う。 |

## DBカラム

当機能の検索条件・表示に直接関係する列のみを記載する。型や一覧の細部はスキーマを参照する。

| テーブル | 列 | メモ |
|---------|-----|------|
| `dtb_event` | `id`（現行: `event_id`） | 一覧表示、既定ソートのキー。 |
| `dtb_event` | `name_jp`、`name_en` | イベント名検索と一覧表示。`eventName`ソートは`name_jp`。移行先は最大155文字。 |
| `dtb_event` | `short_name_jp`、`short_name_en`（ec-cube-enterprise 実装で要確認） | 現行のイベント名検索の対象列。移行先の`dtb_event`に該当列が見当たらない。 |
| `dtb_event` | `rel_id` | ルール適用度検索。 |
| `dtb_event` | `venue_id` | 会場検索。 |
| `dtb_event_detail` | `start_date` | 開催日From・To検索の参照列。 |
| `dtb_event_format` | `format_id` | フォーマット検索の参照列。中間表`dtb_event_format`。 |

### DB操作

本機能は参照系（検索）であり、DBへの登録・更新・削除は行わない。テーブル名は ec-cube-enterprise を正典とする。

| 操作種別 | 対象テーブル | 契機・条件 |
|---------|--------------|------------|
| 検索 | dtb_event / dtb_event_detail / dtb_event_format | 検索条件に合致するレコードを抽出する。 |

| 検索フォーム送信 | 同一画面に検索結果一覧を表示。 |
| ページ送り・件数変更・ソート | 同一画面に再検索結果を表示。 |
| 新規登録ボタン | イベント登録画面（M13-02）。 |
| 行の編集リンク | イベント編集画面（M13-02）。 |
| 行の削除リンク | 削除実行後、検索結果ページへ戻る（M13-02）。 |

### 遷移時に引き継ぐ状態

| 起点 | 遷移前の処理 | 遷移後の初期状態 |
|------|--------------|------------------|
| 検索フォーム送信・ページ送り | 検索条件・表示件数・ソートキー・並び順・ページ番号をセッションへ保存する。 | 同条件で一覧を再描画する。ページ送りはセッションの条件を復元する。 |
| 一覧初期表示（`/event/list`） | 検索条件セッションを削除する。 | 検索フォームのみを表示し、結果は表示しない。 |

## エラー処理

| エラー内容 | 処理 |
|------------|------|
| 並び順が不正 | 並び順エラーを表示し初期表示へ戻す。 |
| 検索クエリビルダが想定外（クエリビルダでも配列でもない） | HTTP404。 |
| 検索条件もセッションも無い | 初期表示へ戻す。 |
| データベース読み取りの障害 | アプリケーションの共通例外処理に委ねる。 |

- なりすまし対策トークンやCookieの原値

## セッション

### 本機能におけるセッション

| 観点 | 内容 |
|------|------|
| 一覧初期表示（`/event/list`） | `admin.event.search`、`admin.event.search.page_no`、`admin.event.search.page_count`を削除する。 |
| 検索・ページ送り時 | 検索条件（`admin.event.search`）、ページ番号（`admin.event.search.page_no`）、ソートキー（`admin.event.sort`）、並び順（`admin.event.order`）、表示件数（`admin.event.search.page_count`）を保存する。 |

### セッションへ保存しない情報

イベント本体の永続データはセッションへ保存しない。保存するのは検索条件・表示状態のみとする。

---

## Cookie

本機能はイベント一覧表示のために新たなCookieを設定しない。セッションCookieは管理画面共通の仕組みを正とする。

---

## 排他制御・トランザクション

本機能の一覧検索は参照のみであり、業務トランザクションを張らない。同時に複数の管理者が検索してもロックを取り合う要件は持たない。
