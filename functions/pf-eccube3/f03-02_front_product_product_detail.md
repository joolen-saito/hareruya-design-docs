# F03-02（商品詳細）

## 概要

フロントの商品詳細は、利用者が選んだ1商品について、言語（日本語・英語）とコンディションの組ごとの価格・在庫を一覧表示し、カードの情報・関連デッキ・同名商品・お気に入り・入荷通知・カート追加への導線を提供する画面である。表示の起点は商品IDであり、商品が存在しない場合は404とする。閲覧した商品はブラウザのCookieに履歴として記録する。

本書は実装手順ではなく、誰が・いつ・どの条件で・結果どうなるかを読むためのリバース詳細設計とする。確認値はpf-eccube3（EC-CUBE3系）のHareruyaEcプラグインの商品詳細処理、商品詳細データ取得、テンプレート（`Product/detail.twig`）、オプション（`condition_display_min_price`）を正とする。本機能のカスタマイズ区分はカスタマイズであり、画面挙動の参照リポはpf-eccube3、DB関連の記述はec-cube-enterpriseを正とする。

対象はブラウザ経由のフロントに限定する。フロントのルートはロケールを先頭に付けた`/{_locale}`配下に配置される。

本文ではフレームワークのコントローラ型名やメソッド名を主説明としない。本文ではルートbind名の網羅は主説明とせず、「利用者視点の入口」にHTTPメソッドとサイトルートからのパスパターンを書く。コード探索でbind名が必要なときだけ「調査補助」へ書く。

---

## 本書で扱うこと

- 商品詳細画面の入口（商品ID指定、旧コードからの転送）
- 言語・コンディションごとの価格・在庫の出し分け
- 初期表示する言語・規格の決定
- 商品が存在しない場合の扱い
- 閲覧履歴のCookie記録（最近見た商品の蓄積。表示側はF03-06を正とする）
- お気に入り・入荷通知・カート追加・同名商品・関連デッキへの導線（各機能の設計を正とする）

- お気に入りの登録・解除処理（お気に入り機能の設計を正とする）

- 商品一覧・詳細検索（F03-01・F03-03 を正とする）
- カード情報・デッキ検索の内部仕様

## リニューアル移行時の扱い

本機能は閲覧と履歴Cookie記録が主で、商品テーブルを更新しない。画面挙動はpf-eccube3を確認値とし、DB関連はec-cube-enterpriseを正とする。現行と移行先で次の差がある。

| 観点 | 現行（pf-eccube3） | 移行先（ec-cube-enterprise） |
|------|--------------------|------------------------------|
| 商品の公開・削除 | 商品`dtb_product`に公開状態`status`と論理削除フラグ`del_flg` | `dtb_product`に`del_flg`は無く、公開状態は商品ステータス`product_status_id`（区分`mtb_product_status`）で表す。 |
| 在庫・価格 | `dtb_product_class`の`stock`・`price02` | 同一スキーマ。 |
| 商品規格の拡張属性 | 言語・コンディション・高額コード・買取価格 | `dtb_product_class`の`language_id`・`card_condition_id`・`high_price_code`・`buy_price`として保持。 |
| お気に入り | 言語・選手情報付きのお気に入り商品 | お気に入り商品`dtb_favorite_product`（`product_id`・`player_id`・`language_id`）として保持。標準の`dtb_customer_favorite_product`とは別表。 |
| コンディション表示下限 | オプション`condition_display_min_price` | `mtb_option`の`option_key`=`condition_display_min_price`として保持。 |
| 閲覧履歴 | ブラウザCookie`history`に保持（サーバ台帳に保存しない） | 同一（Cookie保持、移行対象外）。 |

## 用語

| 用語 | 説明 |
|------|------|
| 商品規格 | 商品とコンディション・言語・フォイル等の組で価格・在庫を持つ単位。詳細では言語・規格ごとに価格・在庫を表示する。 |
| コンディション | カードの状態区分。良品（`NM`）や`HP`等の状態コードを持つ。 |
| 言語 | 商品規格の言語区分。日本語（`JP`）・英語（`EN`）等。 |
| 高額コード | 商品規格に付く別在庫区分の識別子（`highPriceCode`）。表示時にコンディションへ併記する。 |
| コンディション表示下限価格 | 良品以外のコンディションを価格表で表示する下限価格（オプション`condition_display_min_price`、確認値 100 円）。 |
| 閲覧履歴 | 商品詳細を開いた商品IDの並び。ブラウザのCookieに保持する。 |

## 利用者視点の入口

| 入口 | URLエンドポイント | 期待されるふるまい |
|------|--------------------|--------------------|
| 商品詳細を開く | `GET /{_locale}/products/detail/{id}`（`id`は数値） | 当該商品の詳細を、言語・コンディションごとの価格・在庫とともに表示する。 |
| 言語・規格を指定して開く | `GET /{_locale}/products/detail/{id}?lang=JP&class=（規格）` | 初期表示する言語・規格を指定して詳細を表示する。 |
| 旧商品コードから開く | `GET /{_locale}/forward/{oldCode}` | 旧コードを新商品IDへ対応づけ、対応する商品詳細へ転送する。対応がなければトップへ転送する。 |

フロントのページであり管理画面プレフィックスは付かない。ロケールは`/{_locale}`の先頭区切りで決まる。

## フロント挙動

| 観点 | 内容 |
|------|------|
| 表示要素 | 商品名・画像、言語・コンディションごとの価格・在庫の表、状態（コンディション）の説明への導線、価格・総在庫の要約、お気に入りボタン、入荷通知・カート追加の操作、同名商品、関連デッキ、買取リンク。 |
| JS挙動 | 言語・規格の切替で表示する価格・在庫・画像を切り替える。お気に入り・入荷通知・カート追加は各機能の非同期処理を呼ぶ。 |
| CSS・レイアウト | PC用とスマートフォン用で価格表・絞り込みの並びを切り替える。 |
| モーダル・ポップアップ | ログイン用モーダルを内包する。 |

良品以外のコンディションは、価格がコンディション表示下限価格以上のときに価格表へ表示する。コンディションには高額コードがある場合に併記する。

## 処理フロー

### 商品詳細を開く

1. ロケールを確定する（取り扱い外のロケールは日本語とする）。
2. 商品IDから商品詳細データを取得する。取得できない場合は404とする。
3. 裏面カードがある場合は裏面の画像情報を取得する。
4. 言語・規格ごとに価格・在庫を集計する。良品の日本語価格を優先して代表価格・総在庫を決め、良品の日本語がない場合は良品の英語価格・在庫を用いる。
5. 初期表示する言語を決める。クエリ`lang`があればそれを、なければロケールに応じて日本語または英語を初期言語とする。初期言語に該当規格がなければ先頭の言語にする。
6. 初期表示する規格を決める。クエリ`class`が該当規格になければ先頭の規格にする。
7. カード情報がある場合は、フォーマットごとの関連デッキと同名商品を取得する。
8. 閲覧履歴のCookieへ当該商品IDを先頭へ追加する（後述）。
9. 日本語ページのとき、英語ページが存在するかを判定して設定する。
10. ログイン会員の場合、言語ごとにお気に入り登録済みかを判定する。
11. 詳細テンプレートへ各値を渡して描画する。

### 旧コードから転送する

1. 旧商品コードに対応する新商品コードの対応を取得する。対応がなければトップへ転送する。
2. 対応する商品を取得し、対応する商品詳細（商品ID・言語）へ転送する。商品が見つからなければトップへ転送する。

## 集計条件

| 指標 | 集計の要点 |
|------|------------|
| 代表価格 | 良品（`NM`）の日本語規格の最大価格を代表価格とする。良品の日本語価格が0のときは良品の英語規格の最大価格を用いる。 |
| 総在庫 | 代表価格に日本語を採用したときは日本語規格の在庫合計、英語を採用したときは英語規格の在庫合計とする。 |
| 価格表の表示対象 | 良品（`NM`）の規格、または価格がコンディション表示下限価格以上の規格を表示する。 |
| 買取リンク表示 | 良品かつ買取価格が下限以上で高額コードがない規格があるとき、買取リンクを表示する。 |

## 業務ルール・計算

| 項目 | 内容 |
|------|------|
| 言語・コンディションの出し分け | 言語・コンディションの組ごとに価格・在庫を表示する。良品以外は価格がコンディション表示下限価格以上のときに表示する。 |
| 高額コードの併記 | 商品規格に高額コードがある場合、コンディション表示に高額コードを併記する。 |
| 初期言語の決定 | クエリ`lang`が最優先。なければロケールが日本語なら`JP`、それ以外は`EN`。該当規格がなければ先頭言語。 |
| 初期規格の決定 | クエリ`class`が該当規格にあればそれ。なければ初期言語の先頭規格。 |
| 代表価格・総在庫 | 良品の日本語を優先、なければ良品の英語で算出する。価格は桁区切りで表示する。 |
| お気に入り判定 | ログイン会員かつ会員に紐づく選手情報があるとき、言語ごとに登録済みかを判定する。未ログインまたは選手情報がないときは未登録扱い。 |

本機能は閲覧と表示の出し分けが主であり、登録・更新は閲覧履歴Cookieを除き各導線先の機能に委ねる。

### エッジケース

| ケース | 扱い |
|--------|------|
| 商品が存在しない | 404とする。 |
| 良品の日本語価格が0 | 代表価格・総在庫を良品の英語規格で算出する。 |
| クエリの言語・規格が該当しない | 先頭の言語・規格を初期表示とする。 |
| 未ログイン | お気に入りは全言語で未登録扱いとする。 |
| 旧コードに対応がない／対応商品が見つからない | トップへ転送する。 |

## DBカラム

機能に直接関係する列のみ記載する。型や一覧の細部はスキーマを参照する。

| テーブル | 列 | メモ |
|---------|-----|------|
| `dtb_product` | 商品名・公開状態（`product_status_id`） | 詳細表示の対象商品。ec-cube-enterpriseは論理削除列`del_flg`を持たず、公開状態は商品ステータスで表す。 |
| `dtb_product_class` | `stock` / `price02` | 在庫・価格の表示と代表価格・総在庫の集計に用いる。 |
| `dtb_product_class` | `language_id` / `card_condition_id` / `high_price_code` / `buy_price` | 言語・コンディションの出し分け、高額コード併記、買取リンク判定に用いる。 |
| お気に入り商品 `dtb_favorite_product` | `product_id` / `player_id` / `language_id` | ログイン会員の言語ごとのお気に入り登録状態の判定に用いる。標準の`dtb_customer_favorite_product`とは別表。 |
| `mtb_option` | `option_key`=`condition_display_min_price` | 良品以外のコンディションの価格表表示の下限（確認値 100 円）。 |

### DB操作

永続化の正は ec-cube-enterprise（テーブル名・操作は ec-cube-enterprise を正典）。当ドメインは承認ワークフローを介さず persist/flush で直接確定する（承認ワークフローは在庫機能固有）。

| 操作種別 | 対象テーブル | 契機・条件 |
|---------|--------------|------------|
| 登録/更新 | dtb_customer_favorite_product / dtb_favorite_product / dtb_product / dtb_product_class / mtb_option | 当機能が行う登録・更新で対象テーブルを直接保存する（不要な削除は含まない）。確定は persist/flush による即時反映。DB=ec-cube-enterprise を正典とする。 |

## Cookie

### 閲覧履歴のCookie

| 項目 | 内容 |
|------|------|
| Cookie名 | `history`（確認値）。値（商品IDの並び）は本書に記載しない。 |
| 記録タイミング | 商品詳細を開いたとき、当該商品IDを履歴の先頭へ追加する。 |
| 重複の扱い | 同じ商品IDが履歴にある場合は一度取り除いてから先頭へ追加する。 |
| 上限 | 履歴は先頭から最大件数（確認値 18 件）に切り詰める。 |
| 有効期限・経路 | 有効期限を設定して保存する（確認値は約2年・全パス）。 |
| 表示側 | 履歴Cookieからの最近見た商品の表示はF03-06を正とする。 |

履歴Cookieの原値（商品IDの並び）は本書に記載しない。
