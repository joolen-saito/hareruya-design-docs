# ネット買取管理 — 買取情報編集（買取詳細）

## 業務ロジック

### 買取詳細の表示

買取IDに対応する買取注文が無いときは404とする。

選んで買取の明細は、キャンセル行が先頭に来る並びで表示する。個別入力商品もキャンセル行を優先した並びで表示する。実在庫は一覧用の並びで表示する。画面には、買取注文・依頼者のプレイヤー情報・まとめて買取の合計価格・買取状況の履歴・買取状況の名称を表示する。

### 保存の判定順序

| 順序 | 判定・処理 | 結果 |
|------|------------|------|
| 1 | 保存後の買取状況が入庫済みへ変わるとき | 入庫待ちから入庫済みへの更新を先に試み、成功したときだけ後続で入庫処理を行う |
| 2 | 選んで買取の明細 | 既存行は査定価格と売却だけを更新する。新規行は選取区分として紐付ける |
| 3 | まとめて買取・個別入力の明細 | 売却だけを更新する |
| 4 | 適格請求書 | 事業者区分を入力値で更新し、非事業者のときは登録番号を空文字にする |
| 5 | 買取状況の変更 | 受付時点の買取状況から変わっているときだけ買取状況を付け替え、履歴を残す |
| 6 | 変更前が振込完了のとき | 個別入力の売却・数量・規格の紐付けを見て、次の買取状況を入庫待ちまたは未登録在庫ありへ自動で遷移し、履歴を残す |
| 7 | 初回の査定内容承諾のとき | 既存の実在庫行をすべて削除し、選んで買取とまとめて買取の明細の売却状況から実在庫を作り直す |
| 8 | 実在庫の増減 | 増減が0でない規格だけを処理する。数量が負になる組み合わせは例外とする。按分計算で小計を更新し、履歴行を追加する |
| 9 | 入庫の対象になったとき | 手動のネット買取由来の入庫処理を実行する |
| 10 | 変更前が振込完了で、振込完了の履歴が初回のとき | 変更を確定したあとに振込完了メールを送る |

数量が負になる組み合わせでは変更を確定しない。

### 実在庫の編集可否

実在庫の増減を許すのは、買取状況が「査定内容承諾」から「入庫待ち」までの7つのいずれかのときだけとする。それ以外の買取状況で増減が0以外のときは、買取状況の欄にエラーを表示する。

### 買取状況変更の条件

| 変更内容 | 条件 |
|----------|------|
| 振込依頼済みへ変更するとき | 身分証を選択していること。査定合計が設定値（確認値10000）以上のときは、会員にプレイヤーがあり、本人確認が完了していること |
| 入庫済みから他の買取状況へ変更するとき | 変更できない |

### 値の取り方

まとめて買取の査定価格・数量・状態は、保存時に売却以外を保存済みの値で優先し、入力からは変更しない。

査定合計の表示は、選んで買取・まとめて買取・個別入力の売却区分と金額・数量から画面側で再計算する。

### エラー時の扱い

| エラー内容 | 処理 |
|------------|------|
| 買取IDに該当する買取注文が無い | 404とする |
| 入力の検証エラー | 買取詳細を再表示し、エラーを表示する。保存しない |
| 編集できない買取状況で実在庫の増減があるとき | 買取状況の欄にエラーを表示する |
| 振込依頼済みへの変更で身分証・本人確認が足りないとき | 同上 |
| 入庫済みからの買取状況変更 | 同上 |
| 実在庫の数量が矛盾するとき | 変更を確定しない |

## 入出力

| 種類 | 内容 |
|------|------|
| 入力 | 買取ID。保存時は買取詳細・口座・適格請求書・実在庫の各入力と、なりすまし対策トークン |
| 成功時出力 | 買取詳細画面へ遷移し、完了メッセージを1件表示する |
| 失敗時出力 | 買取詳細画面を再表示し、入力項目のエラーを表示する |

### 入出力: 永続化

| 操作 | 契機 |
|------|------|
| 更新 | 保存時。選んで買取の査定価格・売却、まとめて買取と個別入力の売却、事業者区分と登録番号、買取状況 |
| 追加 | 買取状況が変わったとき。買取状況の履歴 |
| 削除・追加 | 初回の査定内容承諾のとき。実在庫を作り直す |
| 更新・追加 | 実在庫の増減があるとき。小計の更新と履歴行の追加 |
| 削除 | サプライ品の明細を削除したとき |
| 追加 | 実在庫を登録したとき |
