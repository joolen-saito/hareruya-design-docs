# デッキ管理 — デッキ CSV 出力

## 概要

HareruyaEc プラグインが管理画面のデッキ検索一覧から、一覧のチェックボックスで選択したデッキ ID に対応するデータを CSV ファイルとしてダウンロード応答で返す機能である。運用フォーマット用の標準出力と、旧サイト連携向けにカード明細まで行単位で展開する別形式の 2 系統がある。

本書は実装手順ではなく、誰が・いつ・どの条件で・結果どうなるかを読むためのリバース詳細設計とする。pf-eccube3 配下の HareruyaEc プラグインのソースを確認値とする。

本機能のカスタマイズ区分は現行踏襲である。挙動は現行リポ（pf-eccube3 の HareruyaEc プラグイン）を参照し、DB関連は ec-cube-enterprise を正とする。

対象はブラウザ経由の管理画面に限定する。

コントローラのメソッド名は本文の主題としない。本文ではルートbind名やSymfonyのルートnameの網羅は主説明としない。「利用者視点の入口」にHTTPメソッドとサイトルートからのパスパターンを書く。コード探索でbind名が必要なときだけ「調査補助」へ書く。

---

## リニューアル移行時の扱い

- ec-cube-enterprise にデッキ関連テーブル一式が実装されており、本機能の出力対象は移行先に存在する。
- デッキ（`dtb_deck`）の主キー列名が異なる。移行先 ec-cube-enterprise では `id`、現行 pf-eccube3 では `deck_id` である。本書が `dtb_deck.deck_id` と記す主キー参照は、移行先では `dtb_deck.id` に対応する。デッキ内カード（`dtb_deck_card`）側の外部キー列は現行・移行先とも `deck_id` のままである。
- デッキの出力対象列（`disp_id`、`private_flg`、`text_main`、`text_side`、`old_deck_id`、`event_detail_id` ほか）は現行と同一スキーマである。
- 旧サイトレイアウトで繰り返し行のソースとするデッキ内カード（`dtb_deck_card`、列 `deck_id`、`board_id`、`card_id`、`count`）、および表示フラグ変換で参照する表示マスタ（`mtb_disp`）は移行先に存在し同一スキーマである。

## 利用者視点の入口

| 入口 | URLエンドポイント | 期待されるふるまい |
|------|-------------------|---------------------|
| 検索結果が 1 件以上あり、デッキにチェックを付けて「CSV出力」（標準）を押す | `POST /{admin_route}/deck/csvexport` | `deckId[]` が送信され、選択デッキ分の標準レイアウト CSV がダウンロードされる。 |
| 同一覧で「CSV出力（旧サイト）」相当のボタンを押す（翻訳キーは `admin.btn.csvexport_old`） | `POST /{admin_route}/deck/csvexport_old` | 同上で旧サイトレイアウトの CSV が返る。 |
| 一覧はあるがチェックなしでいずれかの CSV ボタンを押す | （同一 POST 先への送信は送信前のアラートで止まる） | 画面上はクライアントのアラートで中断する。送信をねじ曲げて空送信したときのサーバ挙動は「処理フロー」を参照。 |
| 検索結果ボックス自体が無い（件数未定義） | （ボタン描画領域に到達しない） | CSV 出力ボタンは検索結果一覧が存在するときのみ表示される。 |

送信元の HTML は一括編集用フォームであり、標準のアクションは一括編集とは別ルートであるが、両 CSV ボタンは属性 `formaction` でそれぞれ `m15-02_admin_deck_deck_csv_export` / `m15-02_admin_deck_deck_csv_export_old` にのみ差し替えて送信する。

## フロント挙動

| 観点 | 内容 |
|------|------|
| 表示要素 | 「CSV出力」「旧サイト出力」ボタンは検索結果サマリーで件数が正のときに描画される。各行に `name="deckId[]"` のチェックボックスがある。ヘッダの `#allCheck` で `deckId` 属性を持つ行チェックボックスを一括オン／オフする。 |
| JS 挙動 | `#csvexport` と `#csvexport_old` のクリックで、チェック済み件数が 0 ならブラウザ `alert("CSV出力するデッキをひとつ以上選択してください。")` を出して `false` を返し、送信しない。チェックがある場合のみ、約 500ms 後に `type=submit` 全要素へ `pointer-events` を空文字で戻す `setTimeout` が走る（直前への無効化は同一ブロックには無い）。 |
| CSS・レイアウト | 本機能だけの固有スタイルは無く、共通の一覧・ボタンスタイルに従う。 |
| モーダル・ポップアップ | CSV 送信前の確認ダイアログは無い（一括編集とは別処理）。 |

一括編集フォーム経由であるため、`bulk_update` フォーム種別について EC-CUBE／Symfony が既定で付ける CSRF 用の隠しフィールドがリクエストに含まれる。CSV 送信時にも同じフォームが送られるため、当該保護がある場合はトークン付きとなる（フォーム種別のソース上の構成を確認値とする）。

## 処理フロー

### 標準レイアウト CSV をダウンロードする（POST `m15-02_admin_deck_deck_csv_export`）

1. 管理画面の認証および共通 middleware を通過する。
2. PHP の実行時間制限を無効にする（`set_time_limit(0)`）。
3. ORM の SQL ロガーを無効にする。
4. リクエストボディから `deckId` を取得する。HTML では `deckId[]` だが、`Request::request->get('deckId')` で取得する実装であり、チェックされていれば配列として届く。
5. `deckId` が `empty()` に該当する場合、`admin.csv.error.export.require` をフラッシュして `Referer` ヘッダの URL へ HTTP リダイレクトする。
6. サービス側で標準レイアウト用ヘッダ定義つきでエクスポート処理を実行する。
7. リポジトリで `dtb_deck.deck_id IN (...)` に該当するデッキを取得する。JOIN で代表カード画像からカード名（英）を読むための関連が張られる。結果が PHP の論理値で偽となる空配列ならランタイム例外としメッセージキーは `admin.csv.error.export.not_registered`。
8. 各デッキについて 1 CSV データ行へ変換する。統率者名は統率者ボード（ボード種別値 3）に紐づくカードあれば英語名を、無ければ空文字とする。
9. ストリーミング応答を組み立てる。標準レイアウトでは組み込みの CSV エクスポート用サービス経由で、開く、UTF-8 の BOM を書く、論理キー行（連想配列のキーを `array_keys` で得た並び）、データ行の順に出力し、閉じる。
10. 応答ヘッダの `Content-Type` は設定 `csv_export_encoding` に基づき `text/csv;charset=…` とする（値が SJIS-win 系なら Charset 文字列だけ `windows-31j` に読み替える）。`Content-Disposition` は `attachment` とファイル名を付ける。
11. ファイル名は接頭辞 `deck_`、`YmdHis`、拡張子 `.csv`。情報ログへファイル名メッセージキーごと出力する応答オブジェクトが返る。実装ではコールバック内で送信も試みられる。

### ランタイム例外が送出されたとき（標準・旧サイト共通）

1. サーバ側の catch でメッセージ文字列をフラッシュエラーへ積み、`Referer` へ HTTP 302 などで返す。
2. ダウンロードは開始されない。

### 旧サイト向けレイアウト CSV をダウンロードする（POST `m15-02_admin_deck_deck_csv_export_old`）

手順は標準出力とほぼ同じだが、次が異なる。

- ヘッダ定義および行変換は旧サイト仕様に切り替える。
- データ行生成時、各デッキについて `dtb_deck_card` をカードと結び付けて列挙し、カードごとに 1 データ行出力する。その際アーキタイプの「旧システム用 ID」を読み取り、空ならランタイム例外で翻訳キー `admin.csv.error.data.old_archetype` のメッセージを構成する。
- `format_by_age` 列には、紐付くフォーマットの主キーが標準（ソース上 `mtb_format` の標準規制 ID 整数 1）に等しい場合はリテラル `KLD_M19` を、それ以外は `Archive` を連結用文字列へ使う規則で埋める実装となる。
- ストリーム書き込みはコア CSV サービスではなく標準関数で `php://output` に直接書き込み、`Content-Type` やファイル名ヘッダ付与は共通ヘルパに委ねる。

### POST の ID と DB の整合

- クエリ結果が空だけがエラー条件である。部分的に存在しない ID が混じっていも、ほかが 1 件以上ヒットしていれば処理は進み、ヒットしない ID は出力に現れない。

## 集計条件

本機能では販売金額のような業務集計は行わない。出力される行は、標準レイアウトでは取得できたデッキの件数分、旧サイトレイアウトでは該当デッキに紐づくデッキカード行の合計分である。

---

## 業務ルール・計算

本機能に店舗設定のような自由入力項目表は無いため `### 入力項目` は置かない。入力は一覧チェック結果とそれに伴うフォーム隠しフィールドのみであり、送信仕様は「入出力」に集約する。

| 項目 | 内容 |
|------|------|
| 送信デッキ ID | POST `deckId`（配列）。未選択送信時サーバ側はフラッシュ後 `Referer` へリダイレクトする。クライアントは未選択送信を既定では止める。 |
| 標準・旧共通のヒット可否 | IN リストにヒットした行が集合として空である場合のみ「未登録」系メッセージで失敗させる。 |
| 並び順 | リポジトリのクエリ結果の順序規則は利用者がチェックした表示順と一致するとは限らない。 |
| `event_date` 列の整形 | DateTime が無ければ空文字。あれば書式は `Y-m-d H:i:s`。 |
| 表示フラグ列（標準レイアウト） | マスタ `disp_id` を取込妥当値（0 と 1）へ写像する変換表による。写像に無い値のときのセル値はソース上の未定義インデックス挙動に依存するため、運用データが表示／非表示のいずれかであることを前提としたい場合はコードとデータ両面で確認すること。 |

### エッジケース

| ケース | 扱い |
|--------|------|
| 旧サイト形式で、アーキタイプに旧 ID が載っていない | 処理は例外で中止しフラッシュ経由で戻す。 |
| 旧サイト形式で、あるデッキに `dtb_deck_card` が 1 件も無い | そのデッキからはデータ行が増えず、結果 CSV に当該デッキの行が出ないことがある（実装どおり単調に列挙するのみ）。 |
| 旧サイト形式で、フォーマットが未設定であるデッキ | ソース上、年代別フォーマット列構築でフォーマット参照を行っており、この状態は実行時致命エラーに至りうる。データ前提で回避するか、コード修正が別途必要であることを確認値とする。 |
| 標準形式で統率カード複数があるデータ | 「最初の統率ボード検索」を想定していないクエリであり、名前は 1 件分に相当する結果に依存する。 |

## データ整合性

| 観点 | 内容 |
|------|------|
| 一覧との対応 | 出力対象はチェック済みデッキ ID のみであり、一覧の検索結果全件自動出力ではない。 |
| リストのソース | メイン／サイド列は画面上の一覧サマリーではなく、永続化されたテキスト列をそのまま返す（正規化テーブル側と逐語一致しないこともありうる）。 |
| 標準レイアウトと旧サイトレイアウトの行数対応 | 標準では概ねデッキ 1 行。旧サイトではカード行数だけ増える。同一デッキの情報はカードごとに列で繰り返す形になる。 |

## 入出力

| 種類 | 内容 |
|------|------|
| 入力 | POST。チェック済み一覧から送られる `deckId[]`。一括編集フォームのその他項目は送信されるが、このルート側で読んで業務処理に使われない実装になっている（確認値としてボディサイズ増に留意）。 |
| 成功時出力（標準） | `deck_XXXXXXXX.csv`。先頭 BOM はコア側の UTF-8 BOM 処理に従う。フィールド出力は設定 `csv_export_separator` と `csv_export_encoding` に従いコアサービス経由で行う。 |
| 成功時出力（旧サイト） | ファイル名規則は同じ接頭辞＋タイムスタンプ。BOM は UTF-8 のバイト連列を明示的に先頭出力する。RFC4180 に近い区切り文字で `fputcsv` する構成とし、 Charset ヘッダは標準側と共通ヘルパの同一論理となる。 |
| 失敗時出力 | `admin.csv.error.export.require` を含むフラッシュおよび `Referer` ヘッダのリダイレクト、またはランタイム例外メッセージのフラッシュと同様のリダイレクト。 |
| 副作用 | 読取りのみ。ログにファイル名相当の情報を残す経路がある。データ更新はしない。 |

## DBカラム

機能は ORM とリポジトリ経由で参照する为主な列のみ示す。

| テーブル | 列 | メモ |
|----------|-----|------|
| `dtb_deck` | 主キー `id`（現行 pf-eccube3 は `deck_id`）ほか一覧で表示していた属性に相当する多数の列 | 出力の主体。 |
| `dtb_deck` | `disp_id`、`private_flg`、`text_main`、`text_side`、`old_deck_id`、`event_detail_id` ほかイベント・成績系 | CSV 標準レイアウトへ直接転写または軽変換。 |
| `dtb_deck_card` | `deck_id`、`board_id`、`card_id`、`count` | 旧サイトレイアウトの繰り返し行ソース。標準レイアウトでは一覧生成に使わない。 |
| マスタ `mtb_disp` とエンティティ上の関連 | `id` と表示・非表示定数との対応 | 表示フラグ列の標準レイアウト変換で利用。 |

### DB操作

本機能は参照系（検索・出力）であり、DBへの登録・更新・削除は行わない。テーブル名は ec-cube-enterprise を正典とする。

| 操作種別 | 対象テーブル | 契機・条件 |
|---------|--------------|------------|
| 検索 | dtb_deck / dtb_deck_card / mtb_disp | 検索条件に合致するレコードを抽出する。抽出結果を所定フォーマットでファイル出力する。 |

## 権限・認可

| 利用者状態 | CSV 標準出力ルート `POST /{admin_route}/deck/csvexport` | CSV 旧サイト出力ルート `POST /{admin_route}/deck/csvexport_old` |
|------------|------------------------|-----------------------------|
| 管理画面共通ルートで認証済みで、当メニューを開ける運用権限がある管理者 | 操作でき、一覧と同種のデータ読取りのみを伴う応答となる。 | 同上。 |

ファイヤウォールでのロール粒度はプラグイン外の共通設定側の確認値とし、本文では名称を増やして断定しない。

## 画面遷移

| 条件 | 遷移先 |
|------|--------|
| 正常に CSV が組み立てられた | CSV 応答のみ。ブラウザはダウンロード状態となり一覧 HTML の再マウントは通常行わない。 |
| ID 未取得や例外 | HTTP フラッシュ後、`Referer` で示される前画面へ戻り、一覧を再読込するような通常の管理方式に従う。 |

## エラー処理

| エラー内容 | 処理 |
|------------|------|
| 選択デッキ ID が空 | `admin.csv.error.export.require` を表示用メッセージとして積み、`Referer` へ HTTP リダイレクト。 |
| DB にヒットしない | メッセージキー `admin.csv.error.export.not_registered` を例外経由で積む。 |
| 旧サイトレイアウトにおける旧アーキタイプ ID 未取得 | メッセージキー `admin.csv.error.data.old_archetype` で実体化される本文を積む。 |
