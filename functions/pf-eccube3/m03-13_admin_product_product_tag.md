# 商品管理 — タグ登録/編集

## 概要

`dtb_tag`（商品タグマスタ）を管理画面で新規登録・編集し、一覧・ページ送り・表示件数変更とあわせて同一画面に配置する機能である。ナビゲーション上の名称は「タグ登録/編集」である。優先表示用の規格紐付けは保存処理のなかで `dtb_tag_sort` を再構成する。

本書は実装手順ではなく、誰が・いつ・どの条件で・結果どうなるかを読むためのリバース詳細設計とする。確認値は ec-cube-enterprise コアの管理画面「商品タグ」ルート群、タグフォーム定義、保存処理サービス、Twig テンプレート `tag.twig`、および `dtb_tag` と `dtb_tag_sort` を扱うリポジトリを正とする。HareruyaEc プラグインのカード管理系とは別系統である。カスタマイズ区分は現行踏襲であり、現行挙動は pf-eccube3 を参照し、DB関連（テーブル名・列名・型・制約・関連）は ec-cube-enterprise を正とする。

対象はブラウザ経由の管理画面に限定する。

本文ではフレームワークのコントローラ型名やメソッド名を主説明としない。本文ではルートbind名やSymfonyのルートnameの網羅は主説明としない。「利用者視点の入口」にHTTPメソッドとサイトルートからのパスパターンを書く。コード探索でbind名が必要なときだけ「調査補助」へ書く。

## リニューアル移行時の扱い

現行（pf-eccube3）と移行先（ec-cube-enterprise）のDBスキーマを比較した結果は次のとおり。相違が判明した場合は ec-cube-enterprise 実装を正とする。

| 観点 | 現行（pf-eccube3） | 移行先（ec-cube-enterprise） |
|------|--------------------|------------------------------|
| タグ本体 | `dtb_tag`（`name`・`name_en`・`sort_no`・`free_area_jp`・`free_area_en`・`priority_products`・`hide_normal_products_flg`・`title_jp`・`title_en`・`description_jp`・`description_en`） | 同一スキーマ。一覧の並び順キーは `sort_no` 昇順。 |
| 優先表示の補助表 | `dtb_tag_sort`（`tag_id`・`product_class_id`・`` `rank` ``） | 同一スキーマ。補助表は移行先にも存在する。優先表示の並びキーは `` `rank` `` で一致。 |
| 削除方式 | 保存時は当該 `tag_id` の `dtb_tag_sort` を物理削除して再挿入。タグ本体は紐付けが無いとき物理削除 | 同一。論理削除列は持たない。 |

## 処理フロー

### 画面を表示する（GET 各ルート）

1. 管理画面の認証・権限チェックを通過する。ロールに `deny_url` が `/product/tag` のエントリがあれば、パス先頭が `/{admin_route}/product/tag` に一致する要求は拒否される。
2. ルートに `id` が無い、またはルート引数としてマスタ行が解決されない場合は新規用の空インスタンスをフォームに載せる。ルート `…/product/tag/{id}` ではパスの `id` から既存行がフォームに載る。
3. セッション `admin.product.tag.page_no` に、引数 `page_no` があればその値、なければ既存セッション値、初期値 1 を書き込む。
4. 表示件数はクエリ `page_count` があれば整数化してセッション `admin.product.tag.page_count` に格納。無ければセッション値、なければ 10。
5. `dtb_tag` を `sort_no` 昇順でクエリし、アプリケーションのページネータで（上記ページ番号・件数）分割してテンプレートへ渡す。

### 登録・更新する（POST `m03-13_admin_product_product_tag_store`）

1. 管理画面の認証・権限を通過する。
2. パスに `id` があれば既存のタグ行を取得し、なければ新規インスタンスでタグ用フォームを生成し、POST を取り込む。
3. 未送信または検証失敗時、フラッシュに `admin.register.failed` を積み、直前のページ番号・件数で一覧を再構成して同テンプレートを返す（リダイレクトしない）。
4. 検証成功時、タグ保存用のトランザクション処理に渡す。処理はトランザクション内で次のとおり。
   - タグ行を persist し flush し、主キーを得る。
   - `dtb_tag_sort` について当該 `tag_id` を DQL delete で一括削除する。
   - `priority_products` 文字列を `\r\n` で分割し、空要素を除き、先頭から順に一意化する。
   - コード列が空でなければ、各コードについて「当該タグが付いた商品の規格」「規格コード一致」「visible が true」の条件で規格を検索し、見つからないコードがあると例外を投げ、メッセージは `admin.error.not_exist_code`（コードとタグ名を埋める）。
   - 見つかった規格ごとに `dtb_tag_sort` 行を作成する。ランクは「列の長さ − 現在のインデックス」で、先頭のコードが最も大きい rank となる。
   - 成功時 commit する。例外時は rollback し再送出する。
5. 保存処理が例外で終わった場合、例外メッセージをフラッシュに積み、同テンプレートを返す。
6. 成功時、フラッシュに `admin.register.complete` を積み、`m03-13_admin_product_product_tag` へリダイレクトする。リダイレクト引数に保存後の主キー `id` を渡すため、生成 URL にはクエリ `?id=` が付く。

### 削除する（DELETE `m03-13_admin_product_product_tag_delete`）

1. 共通のトークン検証（`isTokenValid`）を通過する。
2. 当該タグに `dtb_product_tag` 行が 1 件でもあれば、`admin.tag.delete.failed` をフラッシュし `m03-13_admin_product_product_tag` へリダイレクト（パスパラメータ `id` は付けない）。
3. 紐付けが無ければ永続化層でタグ本体を削除予約し、`dtb_tag_sort` を `tag_id` で一括 DELETE し、flush する。DB 制約等で失敗した場合は `admin.common.delete_error_foreign_key` をフラッシュする。
4. いずれの場合も `m03-13_admin_product_product_tag` へリダイレクトし、第 3 引数として `id` を渡す実装になっている（削除成功後はインスタンス上の主キー値がクエリに乗る）。

| 指標 | 集計の要点 |
|------|------------|
| 一覧総件数 | `dtb_tag` 全件を `sort_no` 昇順で対象とし、表示件数で分割する。 |

## 登録・更新時の判定順序

| 順序 | 判定 | 結果 |
|------|------|------|
| 1 | フォーム送信の有無とフィールド検証 | 失敗ならエラーフラッシュと再描画。 |
| 2 | トランザクション開始後、タグ行の persist・flush | 主キーを確定する。 |
| 3 | 当該タグ ID の `dtb_tag_sort` 全削除 | 古い優先順位を消す。 |
| 4 | 優先商品コード列を分割・一意化し、各コードの規格解決 | 欠けるコードがあれば例外（rollback）。 |
| 5 | 各行を rank 付きで insert し commit | 成功時は成功フラッシュへ遷移。 |

## 業務ルール・計算

| 項目 | 内容 |
|------|------|
| 一覧の並び | `sort_no` 昇順。一覧の並び替え UI は無く、フォームの「並び順」で制御する。 |
| 優先表示の rank | 入力テキストの先頭に近いコードほど大きい rank。行数を `n`、0 始まりインデックスを `i` とすると rank は `n − i`。 |
| 優先表示の対象規格 | 渡したコードが「表示中の規格」かつ「当該タグが商品に付いている」必要がある。登録直後の新規タグでは、まだ商品に付いていないため優先コードを保存しても規格解決に失敗し得る。 |

### 入力項目

| 項目名 | 必須／任意 | 最大長 | 初期値 | 保存先・扱い |
|--------|------------|--------|--------|----------------|
| 名称(日) | 必須 | 255（フォームの文字数上限） | 新規は未入力、編集は `dtb_tag.name` | `dtb_tag.name`。空白不可。 |
| 名称(英) | 必須 | 255 | 新規は未入力、編集は `dtb_tag.name_en` | `dtb_tag.name_en`。空白不可。 |
| 並び順 | 必須 | 整数（フレームワークの整数入力種別の範囲に従う） | 編集は `dtb_tag.sort_no`、新規は未設定に依存 | `dtb_tag.sort_no`。空白不可。 |
| フリーエリア(日) | 任意 | フォーム側の文字数上限なし（DB `TEXT`） | 編集は `dtb_tag.free_area_jp` | 複数行テキスト。 |
| フリーエリア(英) | 任意 | フォーム側の文字数上限なし（DB `TEXT`） | 編集は `dtb_tag.free_area_en` | 複数行テキスト。プレースホルダは翻訳キーに依存。 |
| 優先表示商品 | 任意 | フォーム側の文字数上限なし（DB `TEXT`） | 編集は `dtb_tag.priority_products` 文字列 | 保存時のみ `\r\n` 分割。単一の LF のみの改行は区切りとして split されない実装。プレースホルダは商品規格コードの改行入力を示す。 |
| タイトル(日) | 任意 | 255（フォームの文字数上限） | 編集は `dtb_tag.title_jp` | 1 行テキスト。 |
| タイトル(英) | 任意 | 255 | 編集は `dtb_tag.title_en` | 1 行テキスト。 |
| 説明(日) | 任意 | 4000（フォームの文字数上限） | 編集は `dtb_tag.description_jp` | 複数行テキスト。 |
| 説明(英) | 任意 | 4000 | 編集は `dtb_tag.description_en` | 複数行テキスト。 |

### エッジケース

| ケース | 扱い |
|--------|------|
| 新規タグに優先商品コードだけ入力 | 規格検索は「タグが商品に付いている」条件を含むため、該当なしで例外となり rollback する。 |
| 改行が LF のみ | `\r\n` 分割のため 1 行として扱われる。 |
| 同一コードを複数行 | `array_unique` 維持順で 1 回だけ使う。 |
| 削除時に商品タグ紐付けあり | DB 削除は行わずエラーメッセージを出して一覧へ戻る。 |
| `hide_normal_products_flg` | フォーム型に存在するが当画面に無い。POST に無い場合の更新挙動に注意する。 |

## データ整合性

| 観点 | 内容 |
|------|------|
| 一覧とフォーム | 一覧は常に DB 現行の全タグからページ分割したスナップショット。フォームはルート `id` で特定した 1 行（新規時は空）。同一画面でも一覧行とフォーム内容が別エンティティ由来である。 |
| 保存と `dtb_tag_sort` | 保存成功後、当該タグ ID のソート行は入力に完全一致する集合に置き換わる。空入力ならソート行は 0 件。 |
| 同時更新 | 楽観ロックは持たない。後勝ちで flush される。 |

### DB操作

永続化の正は ec-cube-enterprise。商品系は承認ワークフローを介さず persist/flush で直接確定する（在庫の承認ワークフローとは別系統。`ProductController`・各CSVサービスで確認）。

| 操作種別 | 対象テーブル | 契機・条件 |
|---------|--------------|------------|
| 登録/更新 | dtb_tag / dtb_tag_sort | 当機能が行う登録・更新で対象テーブルを直接保存する（不要な削除は含まない）。確定は persist/flush による即時反映。DB=ec-cube-enterprise を正典とする。 |

## 画面遷移

| 条件 | 遷移先 |
|------|--------|
| 表示件数変更 | 同一パターンの GET に `page_count` クエリを付けてフルロード。 |

### 遷移時に引き継ぐ状態

| 起点 | 遷移前の処理 | 遷移後の初期状態 |
|------|--------------|------------------|
| GET 表示 | `page_no` と `page_count` をセッションに書く | 次回 POST 失敗時の再描画でも同セッション値で一覧を組む。 |
| 登録成功リダイレクト | 成功フラッシュを積む | 一覧は再読込。クエリ `id` は付くが、ルートに `{id}` が無いためパスに基づくマスタ行解決は行われず、フォームは新規空のまま表示されやすい（実装確認値。クエリだけでは ORM のルート引数解決の対象外）。 |

## エラー処理

| エラー内容 | 処理 |
|------------|------|
| フォーム検証失敗 | `admin.register.failed` を表示し同ページ。 |
| 優先コード解決失敗 | 例外メッセージ（翻訳済み）を表示し rollback 後に同ページ。 |
| その他保存例外 | 例外メッセージ文字列をフラッシュに載せ同ページ。 |
| タグ削除時に商品紐付けあり | `admin.tag.delete.failed`。 |
| 削除の DB 例外 | `admin.common.delete_error_foreign_key`。 |

## 試行制限

本機能では試行制限を扱わない。

---

## ログ・監査

| タイミング | 記録内容 |
|------------|----------|
| 本画面固有のログ出力 | 実装しない。フラッシュと例外メッセージが主な利用者向け手掛かり。 |

### ログに出してはいけないもの

- パスワード
- なりすまし対策トークン
- Cookie 値
- セッション ID の完全値
- Remember Me トークンの原値

---

## セッション

### 本機能におけるセッション

| 観点 | 内容 |
|------|------|
| GET 表示時 | `admin.product.tag.page_no` と `admin.product.tag.page_count` を更新する。 |
| POST 失敗時 | 直前の GET で書いたページ番号・件数で一覧を再構築する。 |

### セッションへ保存しない情報

フォームの入力値そのものをセッションに退避する処理は無い。失敗時は送信済み POST をフォームに再バインドする。

---

## Cookie

本機能だけを切り出した特別な Cookie 操作は無い。管理画面のセッション Cookie は共通仕様に従う。

---

## 排他制御・トランザクション

保存処理は明示的にトランザクションを張り、タグ本体の flush と `dtb_tag_sort` の再生成を同一トランザクションに収める。一覧表示や GET 処理に楽観ロックは無い。
