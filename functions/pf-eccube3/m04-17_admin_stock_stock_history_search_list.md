# 在庫管理 — 在庫履歴検索/一覧

商品の価格変更履歴と在庫変更履歴を、共通の検索フォームで条件指定して2つの一覧として表示する画面。

## 概要

在庫履歴検索/一覧は、価格・在庫一覧画面で検索条件を指定し、価格変更履歴の一覧と在庫変更履歴の一覧を同一画面に並べて表示する機能である。検索条件・表示件数・ソート条件はセッションに保持し、ページ送り後も同一条件で再検索する。価格一覧は検索の共通処理が組み立て、在庫一覧は同じ検索条件をもとに別途追加で組み立てる。

本書は実装手順ではなく、誰が・いつ・どの条件で・結果どうなるかを読むためのリバース詳細設計とする。HareruyaEc プラグインの実装と、検索一覧を駆動する共通処理（SearchControllerTrait）を確認値とする。

本機能のカスタマイズ区分はカスタマイズであり、挙動は現行リポ pf-eccube3（HareruyaEc プラグイン）を参照し、DB関連は ec-cube-enterprise を正とする。

対象はブラウザ経由の管理画面に限定する。管理画面プレフィックスは HareruyaEc プラグインの設定キー `admin_route` で決まるため、本書では `%eccube_admin_route%` で示す。

本書の本文ではコントローラのメソッド名は主題としない。ルート bind 名は調査補助へ退避する。

## 本書で扱うこと

- 価格・在庫一覧画面を開く入口と、検索フォーム送信・ページ送りの挙動
- 検索条件（日付帯・在庫変更理由・商品検索条件・汎用ワード）の指定と保持
- 価格変更履歴一覧と在庫変更履歴一覧の2表の列構成と件数表示
- 検索条件・表示件数・ソート条件のセッション保持キー
- 他画面から商品ID・状態コード・言語を渡して呼ばれた場合の絞り込み

## 本書で扱わないこと

以下は本書では仕様確定せず、実装または別機能の設計を正とする。

- CSVダウンロード（在庫履歴CSV出力は M04-18 を正とする。価格履歴CSV出力は別機能）
- 買取/販売価格履歴（別コントローラの別機能）
- 商品検索フォーム本体の各項目仕様（m03-01_admin_product_product_search_list を正とする）
- 在庫変更履歴・価格変更履歴の生成元（在庫一括編集・CSV取込・受注処理など各更新機能）
- 管理画面の認証・ログイン・権限マスタの詳細

## リニューアル移行時の扱い

挙動は現行リポ pf-eccube3 を正とし、永続化に関わるテーブル・列は移行先 ec-cube-enterprise を正とする。在庫変更履歴のスキーマは現行と移行先で差があるため、移行先名を主とし現行名を括弧で添える。

| 観点 | 現行（pf-eccube3 / HareruyaEc） | 移行先（ec-cube-enterprise） |
|------|--------------------------------|------------------------------|
| 在庫変更履歴の主キー | stock_history_id | id（在庫履歴ID） |
| 在庫変更履歴の備考列 | memo | stock_change_reason（在庫変動理由(備考)）。欠品理由は shortage_reason |
| 在庫変更理由区分の参照 | stock_change_type_id で在庫変更履歴に直接ひもづく | stock_change_type_detail_id（在庫変動理由明細）で参照する。理由名は引き続き mtb_stock_change_type を参照 |
| 状態列のメモ元 | dtb_product_sub_class.memo | ec-cube-enterprise に dtb_product_sub_class 相当のテーブルが見当たらない（ec-cube-enterprise 実装で要確認） |
| 規格コード列 | dtb_product_class.code | dtb_product_class の列名は product_code（Doctrine プロパティは code） |

現行の絞り込み・表示挙動は pf-eccube3 を正とし、上記スキーマ差は移行時に ec-cube-enterprise へ合わせる。移行先で対応列を確認しきれない箇所は推測でスキーマ化せず「ec-cube-enterprise 実装で要確認」とする。

## 利用者視点の入口

| 入口 | URLエンドポイント | 期待されるふるまい |
|------|--------------------|--------------------|
| 価格・在庫一覧を開く | `GET /%eccube_admin_route%/product/history` | 検索フォームを初期表示し、検索条件セッションを消去して一覧は空で表示する。 |
| 「検索する」で送信 | `POST /%eccube_admin_route%/product/history/search/1` | 条件を検証・保持し、価格一覧と在庫一覧を1ページ目で組み立てて表示する。 |
| ページネーションでNページへ | `GET /%eccube_admin_route%/product/history/search/{page_no}` | セッションの検索条件で価格一覧のNページ目を表示する。 |
| 表示件数プルダウン変更 | `GET /%eccube_admin_route%/product/history/search/1?page_count=…` | ページマスタに存在する件数ならセッションへ保存し、その件数で分割する。 |
| 価格一覧のCSVダウンロード | `GET /%eccube_admin_route%/product/history/price/export` | 価格変更履歴のCSVを出力する（本書では扱わない）。 |
| 在庫一覧のCSVダウンロード | `GET /%eccube_admin_route%/product/history/stock/export` | 在庫変更履歴のCSVを出力する（M04-18 を正とする）。 |

検索フォームの送信先は常にページ番号1の検索ルートである。ページ送り・表示件数変更は検索ルートへの GET である。

## フロント挙動

| 観点 | 内容 |
|------|------|
| 表示要素 | 上部に検索フォーム。汎用ワード入力（プレースホルダは商品名・カード名・商品コード・備考）と、初期で開いた詳細検索枠。詳細枠には日付（開始・終了）、在庫変更理由（複数選択）、商品検索由来の項目（カテゴリ、種別、エキスパンション、レアリティ、言語、状態、Foil、プロモ、販売価格帯、在庫帯）を表示する。下部に価格変更履歴の件数見出しと表、続いて在庫変更履歴の件数見出しと表、各表にページネーション。 |
| JS 挙動 | 日付入力に日時ピッカー、複数選択に select2 を適用する。検索条件クリアのリンクでフォーム入力を初期化する。ソート表示用のスクリプトを読み込む。 |
| CSS・レイアウト | 管理画面共通の検索ボックスと結果テーブルのスタイル。詳細検索枠は初期表示で開く。 |
| モーダル・ポップアップ | 本機能ではモーダル・トーストを表示しない。 |

## 処理フロー

### 価格・在庫一覧を開く（初期表示）

1. 利用者が価格・在庫一覧を開く。
2. 検索条件・ページ番号・表示件数のセッションを消去する。
3. 検索フォームを空で初期化し、価格一覧・在庫一覧とも空で画面を表示する。

### 検索する・ページ送りする

1. 「検索する」または件数変更・ページ送りで検索ルートへ届く。
2. 価格履歴は販売価格のみを対象とするフラグを立てる。
3. 検索フォームを組み立てる。フォームは送信時にエラーが無いとき、共通処理は一覧を空にした初期相当を返す分岐に入る（共通処理の妥当時分岐の実装挙動を確認値とする）。
4. リクエストの並び順が想定外（ASC・DESC 以外）のときは並び順エラーを表示して初期表示へ戻す。
5. 表示件数はリクエスト値がページマスタに存在すればセッションへ保存し、無ければセッションまたは既定件数を使う。
6. 検索条件はフォーム値、無ければセッション値を復元して用いる。他画面から渡された商品ID・状態コード・言語があれば検索条件へ補う。
7. 価格変更履歴の検索用クエリと件数を組み立て、ページネーションで価格一覧を作る。
8. 検索条件・ページ番号・表示件数・ソート条件をセッションへ保存する。
9. 続いて在庫一覧を追加で組み立てる。セッションの表示件数・ページ番号が無いときは在庫一覧を空配列とする。あれば同じ検索フォームから検索条件を復元し、在庫変更履歴の検索用クエリでページネーションを作る。
10. 価格一覧と在庫一覧の両方を画面へ渡して表示する。

## 集計条件

| 指標 | 集計の要点 |
|------|------------|
| 価格一覧の件数 | 価格変更履歴に検索条件を適用した件数。共通処理が件数取得経路で数える。 |
| 在庫一覧の件数 | 在庫変更履歴に検索条件を適用した件数。ページネータがクエリに対して数える。在庫履歴クエリは件数取得時に `sh` を数える経路を持つ。 |
| 在庫一覧の対象 | 在庫変更履歴を、規格・規格拡張・商品・受注補助・状態・言語・操作者へ結合して並べる。 |

## 業務ルール・計算

| 項目 | 内容 |
|------|------|
| 日付帯 | 開始は当日0時以降、終了はその日を含めるため終了日の翌日0時未満として扱う（共通の履歴クエリ補助による）。 |
| 在庫変更理由 | 選択がある場合のみ、在庫変更履歴の理由区分で絞り込む。 |
| 在庫帯 | 検索条件の在庫開始・終了があれば、在庫変更履歴の変更後在庫数で下限・上限を付ける。 |
| 他画面パラメータ優先 | 商品ID・状態コード（カード状態コード）・言語が渡された場合は、その条件だけで在庫一覧を絞り、商品ID指定時は登録日降順・状態昇順で並べる。 |
| 状態表示 | 規格拡張のメモがあればメモを、無ければ状態名を状態列に表示する。 |
| 本機能の計算 | 履歴の集計・再計算は行わない。表示は履歴に記録済みの値をそのまま用いる。 |

### 入力項目

| 項目名 | 必須／任意 | 最大長 | 初期値 | 保存先・扱い |
|--------|------------|--------|--------|----------------|
| 汎用ワード | 任意 | フォーム上の桁制約なし | 空 | 商品名・カード名・商品コード・備考への横断検索に用いる。フォームキー `multi`。検索条件セッション `admin.history.search` に保持。 |
| 日付（開始） | 任意 | `yyyy-MM-dd` の単一行日付 | 空 | 在庫・価格変更履歴の登録日下限。フォームキー `date_from`。 |
| 日付（終了） | 任意 | `yyyy-MM-dd` の単一行日付 | 空 | 登録日上限。終了日を含める。フォームキー `date_to`。 |
| 在庫変更理由 | 任意 | — | 無選択 | 区分マスタの複数選択。在庫変更履歴の理由区分で絞る。フォームキー `stock_change_type_id`。 |
| 商品検索条件（カテゴリ・種別・エキスパンション・レアリティ・言語・状態・Foil・プロモ・販売価格帯・在庫帯） | 任意 | 商品検索フォームに準ずる | 商品検索フォームの既定 | 埋め込みの商品検索フォーム（`product`）の各キー。価格・在庫一覧の絞り込みに用いる。詳細は m03-01_admin_product_product_search_list を正とする。 |

検索フォームはなりすまし対策トークンの検証を無効化している（履歴検索の照会用フォームとして設定）。CSRF 検証無効は照会フォームの設定であり、更新は行わない。

### エッジケース

| ケース | 扱い |
|--------|------|
| 初回表示（検索前） | セッションを消去し、価格一覧・在庫一覧とも空で表示する。 |
| 表示件数・ページ番号がセッションに無い状態で在庫一覧を作ろうとする | 在庫一覧を空配列として扱う。 |
| 並び順が想定外の値 | 並び順エラーを表示し初期表示へ戻す。 |
| 検索結果0件 | 「検索条件に該当するデータがありませんでした。」を各表で表示する。 |
| 他画面から商品ID・状態コード・言語が渡る | その条件だけで絞り、通常の検索フォーム条件は適用しない。 |

## データ整合性

| 観点 | 内容 |
|------|------|
| 価格一覧と在庫一覧 | 同一画面の2表は同じ検索条件をもとにするが、別クエリ・別ページネーションである。件数・ページは表ごとに独立する。 |
| 表示時点 | 各一覧は表示時点で履歴テーブルを読んだ結果である。表示後の更新は自動反映しない。 |
| 履歴と現在値 | 履歴は変更時点の値を記録したもので、商品の現在在庫・現在価格との一致は保証しない。 |

本機能は参照系（検索・出力）であり、DBへの登録・更新・削除は行わない。テーブル名は ec-cube-enterprise を正典とする。

| 操作種別 | 対象テーブル | 契機・条件 |

- Cookie 値

- Remember Me トークンの原値

## セッション

### 本機能におけるセッション

| 観点 | 内容 |
|------|------|
