# 店舗設定 — 店舗基本設定（SHOPマスター/旧ショップマスター）

## 概要

管理画面の「店舗設定」配下において、ショップの基本情報・送料関連オプション・会員・フロント向けオプション・在庫表示・地図用の緯度経度を、単一の編集画面から一覧し、入力内容を永続化する機能である。画面見出し上は「基本情報設定」「SHOPマスター」として表示される。

本書は実装手順ではなく、誰が・いつ・どの条件で・結果どうなるかを読むためのリバース詳細設計とする。既存実装のふるまい、参照するデータ、判定境界、副作用、プラグイン拡張の差し込み点を確認し、仕様の確からしさを把握することを目的とする。

対象はブラウザ経由の管理画面に限定する。

本機能のカスタマイズ区分は現行踏襲であり、画面・処理の挙動は現行リポ（pf-eccube3）の実装を確認値とし、DB関連（テーブル名・列名・型・保存先）は ec-cube-enterprise を正とする。

本書では Symfony のルート名、URL パス、コントローラクラス名は扱わない。

---

## 本書で扱うこと

- 上記画面の表示内容（セクション構成、入力項目、送信ボタン、補助スクリプトの有無）
- 入力値の検証ルールと、エラー時・成功時の利用者に見える結果
- 保存先（店舗基本情報エンティティ／テーブル）と、保存時に自動で更新される項目（更新日時など）
- 保存完了後の画面遷移と成功メッセージ
- 認可（管理画面へのログイン要否、権限マスタによる URL 拒否、管理画面 IP 制限の有無）
- 店舗基本情報の参照経路（全画面共通の Twig グローバル、Doctrine の結果キャッシュとクリア条件）に起因する再表示の一致／不一致
- プラグイン等によるフォーム拡張（表示初期化時・保存完了時のイベント、画面上の追加フィールド枠）
- 当画面で保存するオプション項目が、フロントの会員・カート・購入・商品一覧・メールなどに与える利用者視点の影響の要点（当画面の範囲外の詳細挙動は別機能側の実装を正とする）

---

## 本書で扱わないこと

以下は本書では仕様確定せず、実装または別機能の設計を正とする。

- 管理画面ログイン、セッション、CSRF、パスワードや Remember Me の Cookie 仕様の詳細（値の形式・名称の環境依存含む）
- 各メールテンプレートごとの宛先・ヘッダの組み立ての全分岐（送信元メール、問い合わせ受付メール、返信受付メール、送信エラー受付メールのいずれをどのテンプレートでどう使うかの網羅はメール送信処理・テンプレート実装を正とする）
- 送料無料条件（金額・個数）を同時に満たした場合の評価順序や論理（AND／OR）の厳密な定義（購入・送料計算ロジックの実装を正とする）
- 税率・税ルール（商品単独税率オプション `option_product_tax_rule` は店舗基本情報に存在するが、当画面フォームには含まれない。編集対象外。税込表示・税額計算は税ルール・商品機能の実装を正とする）
- `authentication_key` など、当画面で編集しない店舗基本情報の列の業務的意味と利用箇所の一覧
- プラグイン（サンプル: HareruyaEc 等）によるサービス差し替え後のメール・購入処理の差分の完全列挙

## リニューアル移行時の扱い

現行（pf-eccube3）の挙動を踏襲しつつ、永続化先は移行先（ec-cube-enterprise）の `dtb_base_info` に合わせる。テーブル名は現行・移行先とも `dtb_base_info` で同一だが、列構成に差がある。当書の各列名は移行先の名称を主とし、現行名を括弧で添える。

| 観点 | 現行（pf-eccube3） | 移行先（ec-cube-enterprise） |
|------|--------------------|------------------------------|
| 郵便番号 | `zip01`＋`zip02`＋`zipcode` の分割列 | `postal_code` 単一列（長さ8）に統合 |
| 電話番号 | `tel01`〜`tel03` の分割列 | `phone_number` 単一列（長さ14）に統合 |
| FAX | `fax01`〜`fax03` の分割列 | `fax_number` 単一列（長さ14）に統合 |
| 都道府県 | `pref`（マスタID列） | `pref_id`（都道府県マスタへの外部キー） |
| 在庫切れ非表示 | `nostock_hidden` | `option_nostock_hidden` に改称 |
| 緯度・経度 | `latitude`・`longitude` | 標準には該当列が見当たらない（ec-cube-enterprise 実装で要確認） |
| 送料無料条件（金額） | decimal スケール0 | `delivery_free_amount` は decimal(12,2) |
| 各オプション | smallint の 0／1 | boolean 型（`option_*`） |
| 英語表記 | 無し | `address_en`・`business_hour_en` 等の英語列が追加されている |

入力項目表の「保存先・扱い」に出る列名は現行（pf-eccube3）の挙動説明として残すが、永続化先の正は本節および「DBカラム」節の移行先名とする。

## 処理フロー

### 画面を開く（GET）

1. 管理画面の認証・IP 制限・権限拒否の各ルールを通過する。
2. 保存済みの店舗基本情報を識別子既定で取得する。
3. 画面表示用に、取得した実体の複製を切り離し、Twig グローバルとして登録する。編集対象の実体とは別参照とする。
4. フォームを店舗基本情報実体にバインドして組み立てる。組み立ての途中で、イベントディスパッチャにより表示前フックが走り、プラグイン等がフィールド追加・変更を行う場合がある。
5. テンプレートを描画し、入力フォームと登録ボタンを表示する。

### 「登録」押下（POST、検証成功）

1. フォームをリクエストで処理する。
2. 検証が成功した場合、店舗基本情報実体を永続化し、ユニットオブワークをフラッシュする。
3. 保存完了後のフックが走り、プラグイン等が追加処理を行う場合がある。
4. 管理画面向け成功メッセージを積む。
5. 店舗基本設定画面自身へリダイレクトする（GET で再表示）。

### 「登録」押下（POST、検証失敗）

1. フォームをリクエストで処理する。
2. 検証が失敗した場合、同一テンプレートを再描画し、各項目のエラーを表示する。成功メッセージは積まない。
3. Twig グローバルに載せた複製はリクエスト開始時点のスナップショットのままである。フォームに載った入力値・エラーと、グローバル側の店舗名等が一致しない場合がある（バリデーション失敗時の表示差の確認値）。

入力項目ごとに、画面ラベル（項目名）、必須／任意、最大長、初期値、および検証・保存列の要点を表の列に分ける。初期値は、初回表示時にフォームへ載る値を指し、当機能では `dtb_base_info` を識別子既定で読み込んだ行の各列の現行値である。

最大長列の数値は、コア付属の `src/Eccube/Resource/config/constant.yml.dist` における既定（`stext_len` 50、`mtext_len` 200、`lltext_len` 99999、`price_len` 8、`zip01_len` 3・`zip02_len` 4、`address1_len`・`address2_len` 各 32、`tel_len` 5・`tel_len_min` 1）を確認値として記載する。運用環境で `app/config` 等により上書きされている場合は、その環境の値が正とする。

### エッジケース

| ケース | 扱い |
|--------|------|
| いずれかのメール項目が空、他は入力 | 4項目とも NotBlank のためエラー。複数項目エラーが同時に表示される（E2E で明示）。 |
| 電話の一部のみ入力 | 「3分割の一部だけ入力」になりエラー（専用メッセージ）。 |
| 郵便番号の片方だけ入力 | 各フィールドの Type/Length によりエラーになる。 |
| 送料無料金額に負数・非数 | エラー。 |
| バリデーション失敗中にヘッダ等で店名を表示 | グローバルは編集前スナップショットのため、フォーム内の店名とずれることがある。 |
| 店舗基本情報の結果キャッシュ | 取得クエリは結果キャッシュを使う。設定で結果キャッシュクリアが有効なら、店舗基本情報の更新後に結果キャッシュ全削除が走る場合がある。無効なら TTL 内は古いスナップショットが読まれる可能性がある（実装・設定を確認値とする）。 |

## データ整合性

| 観点 | 内容 |
|------|------|
| 一覧と詳細 | 当画面は単一レコード編集のみ。一覧との突合は不要。 |
| 全画面の店舗名など | 通常リクエストでは Twig グローバル用に店舗基本情報を読み込む。表示値は読み込み時点の値。 |
| 保存直後 | 同一管理者がリダイレクト後に開き直した画面では、永続化後の値が読み込まれる。キャッシュ設定により、別ワーカー・別リクエストで一瞬古い値が読まれる可能性は否定しない（実装を確認値とする）。 |
| 同時更新 | 楽観ロックは持たない。後勝ちで実体が上書きされる。 |

### DB操作

永続化の正は ec-cube-enterprise（テーブル名・操作は ec-cube-enterprise を正典）。当ドメインは承認ワークフローを介さず persist/flush で直接確定する（承認ワークフローは在庫機能固有）。

| 操作種別 | 対象テーブル | 契機・条件 |
|---------|--------------|------------|
| 登録/更新 | dtb_base_info | 当機能が行う登録・更新で対象テーブルを直接保存する（不要な削除は含まない）。確定は persist/flush による即時反映。DB=ec-cube-enterprise を正典とする。 |

## バリデーション

| 項目 | 内容 |
|------|------|
| CSRF | フレームワーク標準のトークン検証に従う。 |
| 必須・形式 | 前章「業務ルール・計算」および郵便番号・住所・電話の各複合フィールド型の規則に従う。 |
| 送信元メールアドレス（From） | 必須。厳密メール。フォーム上は任意表示でもサーバでは必須。 |
| 問い合わせ受付メールアドレス（From・ReplyTo） | 必須。同上。 |
| 返信受付メールアドレス（ReplyTo） | 必須。同上。 |
| 送信エラー受付メールアドレス（ReturnPath） | 必須。同上。 |
| 取り扱い商品（テキストエリア） | 任意。99999文字まで（`lltext_len` 既定）。 |
| メッセージ（テキストエリア） | 任意。99999文字まで（同上）。 |
| 上記ラジオ7項目 | いずれも無効か有効の選択。未送信時は既存保存値が表示される。 |

## 権限・認可

| 利用者状態 | 画面表示・保存 |
|------------|----------------|
| 管理画面未認証 | 管理画面の認証フローへ。 |
| `ROLE_ADMIN` を持つ管理者で、拒否 URL に該当しない | 表示・保存とも可能。 |
| `ROLE_ADMIN` を持つが、権限マスタの拒否パターンに現在パスが一致 | 拒否。 |
| 管理画面 IP 許可リストが設定されており、クライアント IP が含まれない | 拒否（設定がある場合のみ）。 |

注: メニューでリンクが非表示でも、パスを直接指定した要求に対しては Voter によりアクセス拒否となる場合がある。非表示と拒否は別レイヤで判定する。

## 画面遷移

| 条件 | 遷移先 |
|------|--------|
| 保存成功 | 同一の店舗基本設定画面（GET）。 |
| 保存失敗 | 同一画面の再描画（POST 処理結果として同一テンプレート）。 |
| 未認証・拒否 | 管理画面のログインまたはエラー表示（フレームワーク・セキュリティ設定に従う）。 |

### 遷移時に引き継ぐ状態

| 起点 | 遷移前の処理 | 遷移後の初期状態 |
|------|--------------|------------------|
| 保存成功→リダイレクト | 成功フラッシュを積む | 再表示直後、画面上部に成功メッセージが出る。 |

## セッション

本機能が独自のセッションキーを読み書きする処理は持たない。管理画面セッションの仕様は管理画面ログインの設計を正とする。

---

## Cookie

本機能は独自の業務用Cookieを設定しない。Remember Meや管理画面セッション用Cookieは別機能・フレームワーク範囲とする。

---

## 排他制御・トランザクション

- 楽観ロック・バージョン列は持たない。複数管理者が同時に保存した場合は最後の保存が残る。
- 当画面の保存処理は明示的なトランザクション境界を張らず、単回 `flush` で永続化する。失敗時の部分更新有無は例外種別と ORM 挙動に従う。

## 参考（フロントへの影響の読み取りガイド）

本節は当画面が保持するオプションがフロントでどのような論理に接続されやすいかのガイドである。個別の分岐の正典は各画面・サービス実装とする。

| 設定 | 利用者（来店客）視点で効きやすい領域 |
|------|--------------------------------------|
| 送信元メールアドレス（From） | 件名・本文テンプレート、送信元ヘッダ。 |
| 問い合わせ・返信・エラー受付メール（各項目） | 問い合わせ・返信・バウンス等の宛先・Reply-To・Return-Path。詳細はメール送信処理を正とする。 |
| 店名 | サイト表示名・メール件名プレフィックス等。 |
| 送料無料（金額・個数） | カート・購入フローの送料表示・無料化判定。 |
| 商品ごとの送料 | 規格単位の送料加算の有無。 |
| 複数配送 | カートの配送分割・商品種別混在可否・チェックアウト画面の流れ。 |
| 仮会員 | 会員登録後のメール確認フローの要否。 |
| マイページ注文状況表示 | 注文履歴まわりの表示。 |
| お気に入り | 商品詳細・マイページでのお気に入り機能の可否。 |
| 自動ログイン（Remember Me） | ログイン画面の「記憶する」の扱い。Cookie 詳細は管理画面ログイン・フロントログイン設計を正とする。 |
| 在庫切れ非表示 | 商品一覧・検索での在庫なし商品の扱い。 |
