# M08-08（手動メール通知）

## 概要

管理画面「会員管理」で、特定の会員に対してメールを手動で作成・送信する機能である。会員編集画面や会員一覧の操作メニューから対象会員を指定して開き、会員向けメールテンプレートを選ぶと件名と本文がテンプレートから差し込まれ、必要に応じて編集して送信する。送信したメールは会員のメール送信履歴として記録する。

本書は実装手順ではなく、誰が・いつ・どの条件で・結果どうなるかを読むためのリバース詳細設計とする。確認値はpf-eccube3（EC-CUBE3系）のHareruyaEcプラグインの手動メール通知処理、メール送信サービス（手動メール送信）、手動メール通知テンプレート（`Customer/manual_mail.twig`）を正とする。

本機能のカスタマイズ区分はカスタマイズであり、画面・挙動の確認はpf-eccube3を参照し、DB関連の記述（テーブル名・列名・保存先）はec-cube-enterpriseを正とする。

対象はブラウザ経由の管理画面に限定する。会員検索・一覧（M08-01を正とする）、会員登録・編集（M08-04を正とする）、メール一括送信（会員へのメール一括送信を正とする）、メール送信履歴の閲覧（メール送信履歴を正とする）、メールテンプレートの管理（メールテンプレート管理を正とする）は別機能とする。

本文ではフレームワークのコントローラ型名やメソッド名を主説明としない。管理画面プレフィックスはコア設定`admin_route`で決まり、環境により変わる。「利用者視点の入口」にHTTPメソッドとサイトルートからのパスパターンを書く。コード探索でルートbind名が必要なときだけ「調査補助」へ書く。

---

## 本書で扱うこと

- 対象会員を指定した手動メール作成画面の表示
- メールテンプレートの選択と件名・本文の差し込み
- 件名・本文を編集して送信する流れ
- 送信時の宛先・差出人・控えの扱い
- 送信したメールのメール送信履歴への記録

---

## 本書で扱わないこと

以下は本書では仕様確定せず、実装または別機能の設計を正とする。

- メール一括送信（複数会員への一括送信を正とする）
- メールテンプレートの作成・編集（メールテンプレート管理を正とする）
- メール送信履歴の一覧・絞り込み表示（メール送信履歴を正とする）
- 買取向けの手動メール送信（買取の手動メール送信を正とする）
- メール本文の文字コード変換・送信基盤の内部仕様（フレームワーク・メール基盤を正とする）

## リニューアル移行時の扱い

現行（pf-eccube3、HareruyaEcプラグイン）と移行先（ec-cube-enterprise）でのDB関連の差を記録する。挙動は現行を確認値とし、永続化先の名称はec-cube-enterpriseを正とする。

| 観点 | 現行（pf-eccube3） | 移行先（ec-cube-enterprise） |
|------|--------------------|------------------------------|
| 送信したメールの記録 | HareruyaEcプラグインのメール送信履歴に1件記録 | 会員向けメール送信履歴テーブル`dtb_user_mail_history`（会員`customer_id`、テンプレート`template_id`、件名`subject`、本文`mail_body`、送信日時`send_date`）。同表は作成者列`creator_id`を持つが、手動メールでの設定有無はec-cube-enterprise実装で要確認 |
| メールテンプレート | 会員向けベースのテンプレートを参照 | テンプレートマスタ`dtb_mail_template`（件名`mail_subject`、ヘッダ`header`、フッタ`footer`、本文ファイル`file_name`、キー`mail_key`） |
| 差出人・控え | 店舗の基本情報 | 店舗基本情報`dtb_base_info`のメールアドレス |
| 会員の宛先・氏名 | `dtb_customer` | `dtb_customer.email`・`name01`・`name02`（同一） |

## 利用者視点の入口

| 入口 | URLエンドポイント | 期待されるふるまい |
|------|--------------------|--------------------|
| 会員を指定して手動メールを開く | `GET /{admin_route}/customer/manual_mail`（クエリで会員IDを指定） | 対象会員の手動メール作成画面を表示する。テンプレート未選択なら本文・件名は空。 |
| テンプレートを選んで開く | `GET /{admin_route}/customer/manual_mail/{customerId}/{templateId}` | 指定テンプレートの件名・本文を差し込んだ作成画面を表示する。 |
| 手動メールを送信する | `POST /{admin_route}/customer/manual_mail/{customerId}/{templateId}` | 件名・本文を検証し、対象会員へ送信して送信履歴を記録し、同じ作成画面へ戻る。 |

管理画面プレフィックスはコア設定`admin_route`で決まり、環境により変わるためプレースホルダで示す。会員ID指定が無い場合・会員が存在しない場合はページが見つからない扱い（404）とする。

| 観点 | 内容 |
|------|------|
| 表示要素 | 見出し「手動メール送信」、会員名、メールテンプレートの選択、件名、本文（テンプレート選択時のみ複数行入力）、送信ボタン、会員編集画面に戻るリンク。 |
| JS挙動 | メールテンプレートの選択を変更すると、選択したテンプレートIDを付けた手動メールURLへ遷移して件名・本文を差し込む。テンプレート未選択へ戻すと会員IDのみ付けたURLへ遷移する。 |

メールテンプレート選択は1欄。件名は1欄。本文はテンプレート選択時に表示する複数行入力（textarea）で、テンプレートのヘッダ・フッタは隠し入力として送信に含める。

## 処理フロー

### 手動メール作成画面を表示する（GET `/{admin_route}/customer/manual_mail`・`/{admin_route}/customer/manual_mail/{customerId}/{templateId}`）

1. 管理画面の認証・権限を通過する。
2. 会員IDを取得する。会員ID指定が無い場合はページが見つからない扱い（404）とする。
3. 会員IDで会員を取得する。存在しない場合はページが見つからない扱い（404）とする。
4. テンプレートID指定がある場合、会員向けベース（会員・会員英語・ベースなし）に該当するテンプレートのみを対象とする。該当が無い場合はページが見つからない扱い（404）とする。
5. テンプレートのヘッダ・フッタ・会員・店舗基本情報を差し込んで本文を組み立てる。
6. メール作成フォームを生成し、選択中テンプレートをセットする。
7. 作成画面を表示する。

### 手動メールを送信する（POST `/{admin_route}/customer/manual_mail/{customerId}/{templateId}`）

1. フォームを送信状態で受け取り、検証する。
2. 検証に通った場合、対象会員へ手動メールを送信する。差出人と控え（Bcc）は店舗基本情報のメールアドレス、宛先は会員のメールアドレス、件名と本文は送信内容を用いる。
3. 送信したメールをメール送信履歴として記録する（件名・本文・送信日時・会員・テンプレート）。
4. 送信成功を表示する。
5. 同じ会員・テンプレートの作成画面へ戻る。

## 業務ルール・計算

| 項目 | 内容 |
|------|------|
| 対象会員 | パスまたはクエリの会員IDで特定する1名。会員ID無し・会員なしは404。 |
| 対象テンプレート | 会員向けベース（会員・会員英語・ベースなし）に該当するテンプレートのみ選択対象とする。該当しないテンプレートIDは404。 |
| 件名・本文の差し込み | テンプレート選択時に件名と、ヘッダ・フッタ・会員・店舗基本情報を差し込んだ本文を組み立てる。 |
| 宛先・差出人・控え | 宛先は会員のメールアドレス、差出人と控え（Bcc）は店舗基本情報のメールアドレス、返信先・返送先も店舗基本情報のメールアドレスを用いる。 |
| 送信履歴 | 送信のたびにメール送信履歴を1件記録する。会員・テンプレート・件名・本文・送信日時を保持する。手動メールでは作成者の記録は持たない。 |

本機能は会員データ自体の更新は行わない。メール送信と履歴記録を行う。

### 入力項目

| 項目名 | 必須／任意 | 最大長 | 初期値 | 保存先・扱い |
|--------|------------|--------|--------|----------------|
| メールテンプレート | 任意 | 選択 | 未選択（指定があればそのテンプレート） | フォームキー`template`。会員向けベースのテンプレートのみ対象。選択で件名・本文を差し込む。 |
| 件名 | 必須 | メール作成フォームに準ずる | テンプレートの件名 | フォームキー`mail[subject]`。送信メールの件名。 |
| 本文 | 必須 | 複数行入力（textarea、20行） | テンプレートから組み立てた本文 | フォームキー`mail_body`。送信メールの本文。テンプレート選択時のみ表示。 |
| ヘッダ・フッタ | テンプレート由来 | 隠し入力 | テンプレートのヘッダ・フッタ | フォームキー`mail[header]`・`mail[footer]`。本文組み立てに用いる。 |

最大長はメール作成フォームの確認値とする。本文はテンプレートを選択して初めて入力欄が表示される。

### エッジケース

| ケース | 扱い |
|--------|------|
| 会員ID指定なし | ページが見つからない扱い（404）。 |
| 存在しない会員ID | ページが見つからない扱い（404）。 |
| 会員向けベース外のテンプレートID | ページが見つからない扱い（404）。 |
| テンプレート未選択で表示 | 件名・本文の入力欄は出さない（本文textareaはテンプレート選択時のみ）。 |
| 検証失敗で送信 | 送信せず同じ作成画面へ戻す。 |

## データ整合性

| 観点 | 内容 |
|------|------|
| 送信と履歴 | 送信成功時にメール送信履歴を1件記録する。履歴は送信時点の件名・本文・送信日時を保持する。 |
| テンプレートとの関係 | 履歴は送信に用いたテンプレートを参照する。テンプレート本文の後日変更は履歴に遡及しない。 |
| 宛先 | 会員のメールアドレスを送信時点で読む。送信後に会員のメールが変わっても送信済みメールには影響しない。 |

本機能ではバッチ実行を扱わない。メール送信はメール送信基盤を通じて行う。送信基盤の失敗時の扱いはメール基盤を正とする。

## DBカラム

機能に直接関係する列のみ記載する。型や一覧の細部はスキーマを参照する。

| テーブル | 列 | メモ |
|---------|-----|------|
| `dtb_customer` | `email`、`name01`、`name02` | 宛先と画面の会員名表示。 |
| メールテンプレート（`dtb_mail_template`） | `mail_subject`（件名）、`header`（ヘッダ）、`footer`（フッタ）、`file_name`（本文ファイル）、`mail_key` | 件名・本文の差し込み、対象テンプレート判定。 |
| メール送信履歴（`dtb_user_mail_history`） | `customer_id`（会員参照）、`template_id`（テンプレート参照）、`subject`（件名）、`mail_body`（本文）、`send_date`（送信日時） | 送信のたびに1件記録する。作成者列`creator_id`の手動メールでの設定有無はec-cube-enterprise実装で要確認。 |
| 店舗基本情報（`dtb_base_info`） | 各メールアドレス・店舗名 | 差出人・控え・返信先・返送先。 |

### DB操作

永続化の正は ec-cube-enterprise（テーブル名・操作は ec-cube-enterprise を正典）。当ドメインは承認ワークフローを介さず persist/flush で直接確定する（承認ワークフローは在庫機能固有）。

| 操作種別 | 対象テーブル | 契機・条件 |
|---------|--------------|------------|
| 登録/更新 | dtb_base_info / dtb_customer / dtb_mail_template / dtb_user_mail_history | 当機能が行う登録・更新で対象テーブルを直接保存する（不要な削除は含まない）。確定は persist/flush による即時反映。DB=ec-cube-enterprise を正典とする。 |
