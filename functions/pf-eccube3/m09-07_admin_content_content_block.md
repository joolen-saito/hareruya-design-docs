# コンテンツ管理 — ブロック管理

## 概要

管理画面コンテンツ管理のブロック管理は、レイアウト上に配置するブロックの属性（ブロック名・ファイル名）と、ブロックのテンプレート本文（Twig）を一覧から選んで編集する機能である。EC-CUBE コアのブロック管理を、HareruyaEc プラグインが新規作成・編集・更新の各操作で差し替えている。

本書は実装手順ではなく、誰が・いつ・どの条件で・結果どうなるかを読むためのリバース詳細設計とする。一覧表示・削除はコアのブロック管理実装、新規作成・編集フォームの表示・保存は HareruyaEc のブロック管理実装を確認値とする。

本機能のカスタマイズ区分はカスタマイズであり、挙動は現行リポ（pf-eccube3）を正とし、DB関連（テーブル名・列名・保存先）は ec-cube-enterprise を正とする。現行と移行先で `dtb_block` の列構成が異なるため、本書のDB記述は移行先名を主とし現行名を括弧で添える。差分は「リニューアル移行時の扱い」に集約する。

対象はブラウザ経由の管理画面コンテンツ管理のブロック管理に限定する。ブロックのページへの配置（レイアウト管理）、ページ管理、CSS管理、JavaScript管理、ファイル管理は別機能として切り離す。

管理画面プレフィックスは設定キー `admin_route`（`path.yml` の `${ADMIN_ROUTE}` 由来）で決まる。本書ではパスを `/{admin_route}/` のプレースホルダで示し、ルート bind 名は調査補助に隔離する。コントローラのメソッド名は本文の主説明としない。

- ブロック一覧の表示対象と表示項目
- ブロック新規作成フォーム・編集フォームの表示と入力項目
- ブロック属性の保存と、テンプレート本文（Twig）のブロックファイル保存

## リニューアル移行時の扱い

本機能はカスタマイズ区分がカスタマイズである。挙動は現行リポ（pf-eccube3 の HareruyaEc 実装・コア実装）を正とし、DBスキーマは移行先 ec-cube-enterprise を正とする。`dtb_block` の列は現行（EC-CUBE 3 系）と移行先（ec-cube-enterprise）で名称・型が異なる。ec-cube-enterprise の `dtb_block` 実装で確認した差分を以下に記す。

| 項目 | 現行（pf-eccube3、EC-CUBE 3 系） | 移行先（ec-cube-enterprise） |
|------|----------------------------------|------------------------------|
| ブロック名 | `dtb_block.name` | `dtb_block.block_name` |
| 削除可否区分 | `dtb_block.deletable_flg`（整数。削除可能=正の値、削除不可=0） | `dtb_block.deletable`（真偽値。削除可能=真、削除不可=偽） |
| ロジック区分 | `dtb_block.logic_flg`（整数。新規作成は0） | `dtb_block.use_controller`（真偽値。コントローラ実行ブロックか否か） |
| ファイル名 | `dtb_block.file_name` | `dtb_block.file_name`（同一） |
| 端末種別 | `dtb_block.device_type_id` | `dtb_block.device_type_id`（同一。`device_type_id` と `file_name` の複合一意制約あり） |
| ブロックファイルパス | 該当列なし（テンプレート本文はファイルへ書き出し） | `dtb_block.path`（移行先で追加。現行に対応列が無い） |

テンプレート本文を `dtb_block` に保存しない点は現行・移行先で共通である。移行先で追加された `path` 列に対応する現行列は無い。本文中のDB記述は移行先名を主とし、現行名を括弧で添える。

| 入口 | URLエンドポイント | 期待されるふるまい |

## 処理フロー

### ブロック一覧を表示する

1. PC 端末種別を取得する。
2. 検索語が入力されている場合は、ブロック名・ファイル名を部分一致条件にする。
3. その端末種別のブロックを ID 降順で取得する。
4. 一覧表示完了の拡張イベントを発火し、ブロック一覧を渡す。
5. 一覧テンプレートを描画する。

### 新規作成フォームを表示する

1. ブロック ID 未指定で新規ブロックを生成し、PC 端末種別・ロジック区分（0）・削除可否区分（削除可能）を設定する。
2. ブロック用フォームを組み、初期化完了イベントを発火する。イベント結果でテンプレート本文の初期値を上書きできる。
3. ブロックデータ欄に、設定ファイル群から見つかった既定テンプレートの内容を初期表示する。見つからなければ空文字を初期表示する。
4. 編集フォームを描画する。

### 編集フォームを表示する

1. ブロック ID から該当ブロックを取得する。該当が無ければ見つからない扱い（HTTP 404）とする。
2. 削除可否区分が削除不可のとき、アクセス拒否（HTTP 403）とする。
3. ブロック用フォームを組み、初期化完了イベントを発火する。イベント結果でテンプレート本文を上書きできる。
4. ブロックデータ欄に読込先ファイルの内容を初期表示する。読込先はアプリのブロック領域・プラグイン既定・コア既定の順に探す。
5. 編集フォームを描画する。

### 新規作成を送信する

1. 初期化完了イベントを発火し、フォームに送信値を反映する。
2. 検証が通らなければ同一フォームを再描画する。
3. 検証済みなら、フォーム内容でブロック情報を更新し、データベースへ保存する。
4. テンプレート本文をアプリのブロック領域のファイルへ書き出す。
5. キャッシュを破棄する。
6. 編集完了イベントを発火し、登録完了メッセージを追加する。
7. 登録したブロックの編集画面へリダイレクトする。

### 編集を送信する

1. ブロック ID から該当ブロックを取得する。削除不可ブロックのときアクセス拒否（HTTP 403）とする。
2. 初期化完了イベントを発火し、フォームに送信値を反映する。
3. 検証が通らなければ同一フォームを再描画する。
4. 検証済みなら、フォーム内容でブロック情報を更新し、データベースへ保存する。
5. テンプレート本文をアプリのブロック領域のファイルへ書き出す。ファイル名が変更され旧ファイルが存在すれば旧ファイルを削除する。
6. キャッシュを破棄し、編集完了イベントを発火し、登録完了メッセージを追加する。
7. 編集画面へリダイレクトする。

## 業務ルール・計算

本機能では金額計算・件数集計を行わない。ブロック属性の検証と、テンプレート本文のブロックファイル保存が主な処理である。

| 項目 | 内容 |
|------|------|
| 保存先 | テンプレート本文はアプリのブロック領域へ書き出す。読込はアプリのブロック領域・プラグイン既定・コア既定の順に探す。 |
| ファイル名の一意性 | 同一端末種別でファイル名が重複するとき検証エラーとする。編集時は自身の ID を除外して重複判定する。 |
| 編集・削除の制限 | 削除可否区分が削除不可のブロックは編集・更新でアクセス拒否（HTTP 403）とし、削除も行わない。 |
| 一覧の対象 | PC 端末種別のブロックを ID 降順で表示する。検索語がある場合はブロック名・ファイル名を部分一致で絞り込む。 |

### 入力項目

| 項目名 | 必須／任意 | 最大長 | 初期値 | 保存先・扱い |
|--------|------------|--------|--------|----------------|
| ブロック名 | 必須 | 255文字（`NotBlank` と `Length`） | 新規は空、編集は現行値 | `dtb_block.block_name`（現行 `name`）。キー `name`。 |
| ファイル名 | 必須 | 255文字（`NotBlank`・`Length`・正規表現） | 新規は空、編集は現行値 | `dtb_block.file_name`。キー `file_name`。半角英数字と `_ /` のみ許可。テンプレート本文の書き出しファイル名になる。 |
| ブロックデータ | 任意 | フォーム上限なし。ファイルへ書き出す | 新規は既定テンプレート内容、編集は読込先ファイル内容 | テーブルには保存せず Twig ファイルへ書き出す。キー `block_html`（`mapped` 偽）。改行コードを変換して書き込む。 |

最大長の数値は `src/Eccube/Resource/config/constant.yml.dist` の確認値とする。運用環境で上書きされている場合はその環境の値が正とする。端末種別とブロック ID は隠し項目として送信し、ブロック ID はキー `id`、端末種別はキー `DeviceType` で扱う。

### エッジケース

| ケース | 扱い |
|--------|------|
| 削除不可ブロックの編集・更新 | アクセス拒否（HTTP 403）。 |
| 削除不可ブロックの削除 | レコード・ファイルとも削除しない。 |
| 編集でファイル名を変更 | 新ファイルへ書き出し、旧ファイルが存在すれば削除する。 |
| 削除対象が存在しない ID | 削除対象なしメッセージを出して一覧へ戻る。 |
| 削除でテンプレートが変更済み | レコードは削除するが、ファイル名が一致しない場合は対象ファイルが残る場合がある。 |

## データ整合性

| 観点 | 内容 |
|------|------|
| 属性とファイルの整合 | ブロック属性はデータベース、テンプレート本文はファイルへ分けて保存する。保存はデータベース更新のあとにファイル書き出しを行う。両者の整合は保存処理の成否に依存する。 |
| 一覧と編集の整合 | 一覧は保存後の最新レコードを ID 降順で読む。本文の表示は読込先ファイルの現行内容を反映する。 |
| キャッシュ | 保存・削除のあとキャッシュを破棄する。テンプレートのキャッシュが古いまま残り続ける設計にはしない。 |

## DBカラム

当機能に直接関係する列のみを記載する。型や一覧の細部はスキーマを参照する。

列名は移行先 ec-cube-enterprise を主とし、現行（pf-eccube3）名を括弧で添える。

| テーブル | 列 | メモ |
|---------|-----|------|
| `dtb_block` | `block_name`（現行 `name`）、`file_name` | ブロック属性の主項目。 |
| `dtb_block` | `deletable`（現行 `deletable_flg`） | 削除可否区分。移行先は真偽値、現行は整数（削除可能=正の値、削除不可=0）。 |
| `dtb_block` | `use_controller`（現行 `logic_flg`） | ロジック区分。移行先は真偽値、現行は整数（新規作成時は 0 で生成）。 |
| `dtb_block` | `device_type_id` | 端末種別。PC を対象とする。`file_name` との複合一意制約を持つ。 |
| `dtb_block` | `path` | 移行先 ec-cube-enterprise で追加されたブロックファイルパス列。現行に対応列は無い。 |

テンプレート本文は `dtb_block` には保存せず、ブロックの Twig ファイルへ書き出す。

### DB操作

永続化の正は ec-cube-enterprise（テーブル名・操作は ec-cube-enterprise を正典）。当ドメインは承認ワークフローを介さず persist/flush で直接確定する（承認ワークフローは在庫機能固有）。

| 操作種別 | 対象テーブル | 契機・条件 |
|---------|--------------|------------|
| 登録/更新 | dtb_block | 当機能が行う登録・更新で対象テーブルを直接保存する（不要な削除は含まない）。確定は persist/flush による即時反映。DB=ec-cube-enterprise を正典とする。 |

---

## バリデーション

| 項目 | 内容 |
|------|------|
| ブロック名 | `NotBlank`、`Length`（255文字）。 |
| ファイル名 | `NotBlank`、`Length`（255文字）、正規表現（半角英数字と `_ /`）、送信後の重複判定。 |
| ブロックデータ | フォーム制約なし。任意入力。 |

---

## 権限・認可

| 利用者状態 | ブロック管理の一覧・フォーム・削除 |
|------------|----------------------------------|
| 未ログイン | 管理画面共通のログイン誘導に従う。 |
| 管理メンバーでログイン済み | アクセス制御リストが URL を許可するときに到達する。削除不可ブロックの編集・更新はアクセス拒否（HTTP 403）。 |

---

## 画面遷移

| 条件 | 遷移先 |
|------|--------|
| 一覧の新規入力を押下 | 新規作成フォーム。 |
| 一覧の編集を押下 | 該当ブロックの編集フォーム。削除不可ブロックはアクセス拒否（HTTP 403）。 |
| 新規作成保存成功 | 登録したブロックの編集画面。 |
| 編集保存成功 | 同ブロックの編集画面。 |
| 削除成功 | ブロック一覧。 |
| 検証失敗 | 同一フォームを再描画。 |

---

## エラー処理

| エラー内容 | 処理 |
|------------|------|
| フォーム検証エラー | 同一フォームを再描画し、フィールドにエラーを表示する。文言は表示メッセージ節を正とする。 |
| ファイル名重複 | ファイル名欄に重複エラーを付与する。 |
| 対象ブロック無し | 見つからない扱い（HTTP 404）。 |
| 削除不可ブロックの編集・更新 | アクセス拒否（HTTP 403）。 |
| 対象ブロック無し（削除） | 削除対象なしメッセージを出して一覧へ戻る。 |

---

## ログ・監査

| タイミング | 記録内容 |
|------------|----------|
| 保存・削除 | 本機能固有の業務監査ログは追加しない。登録完了・削除完了は画面フラッシュで通知する。 |

### ログに出してはいけないもの

- なりすまし対策トークンの完全値
- セッション識別子の完全値
- Cookie の原値

---

## セッション

本機能は一覧の検索条件をセッションに載せない。検索ボックスの入力はGETリクエスト内で部分一致条件として扱い、成功・失敗メッセージは管理画面共通のフラッシュ機構に依存する。

---

## Cookie

管理画面のセッション Cookie のみを正とし、本機能用の追加 Cookie は定義しない。

---

## 排他制御・トランザクション

ブロック属性の保存はデータベースの永続化に任せ、画面側に楽観ロックの版情報は持たない。ブロックファイルの書き出しはデータベース保存後に行う。
