# バッチ インフラ — S3のファイルを自サーバに転送

## 概要

S3バケットの所定プレフィックスのファイルを、稼働中のアプリケーションサーバ（コンテナ）のローカルディレクトリへ同期するインフラバッチである。cronで定期実行し、テンプレートとユーザーデータのファイルをS3から取得して反映する。変更があった場合はファイルの所有者・権限を設定し、アプリケーションのキャッシュをクリアする。

本書は実装手順ではなく、誰が・いつ・どの条件で・結果どうなるかを読むためのリバース詳細設計とする。機能一覧上のカスタマイズ区分は「現行踏襲」だが、本書本文は現行 pf-eccube3 の実装をリバースしたものではない。本機能はインフラバッチであり、確認値は移行先 ec-cube-enterprise のコンテナ用cron定義（`dockerbuild/eccube/crontab`）と同期スクリプト（`dockerbuild/eccube/file_sync_command.sh`）を正とする。挙動・DBとも出典は ec-cube-enterprise である。

対象はコンソール（シェルスクリプト）であり、ブラウザ経由の画面を持たない。本文ではスクリプト内部のコマンド列を逐次転載せず、ふるまいを記述する。

---

## リニューアル移行時の扱い

- 本機能はオブジェクトストレージ（S3）とアプリケーションサーバ間のファイル同期を行うインフラバッチであり、業務データのテーブル（DBスキーマ）を持たない。したがってDBスキーマ上の現行↔移行先の差分は無い。
- 挙動・確認値は移行先 ec-cube-enterprise のコンテナ定義（cron・同期スクリプト）を正とする。現行（pf-eccube3）側に固有の別実装がある場合の差分のみ、判明時に本節へ追記する。
- 同期対象（テンプレート・ユーザーデータのプレフィックス）、所有者・権限設定、キャッシュクリアの挙動は ec-cube-enterprise のスクリプト実装を正とする。

## 利用者視点の入口

| 入口 | 実行方法 | 期待されるふるまい |
|------|----------|--------------------|
| cronによる定期実行 | 毎分（`* * * * * /usr/local/bin/file_sync_command`） | S3の所定プレフィックスをローカルディレクトリへ同期し、変更時は権限設定とキャッシュクリアを行う。 |

本機能はHTTPで届く画面を持たない。実行スケジュール自体はcron定義・運用設定を正とする。実装上は毎分起動である。

## 処理フロー

### S3から自サーバへ同期する（`/usr/local/bin/file_sync_command`）

1. 実行開始をログに記録する。
2. ロックファイルの作成を試みる。既に存在する場合は、保持中のプロセスを記録して処理を終了する（多重起動防止）。
3. ロックを取得できた場合、次の3経路をS3からローカルへ同期する。各同期はS3を基準とし、ローカル側の余分なファイルを削除する（タイムスタンプ厳密一致で差分判定）。
   - テンプレートの既定データ
   - テンプレートのユーザーデータ
   - HTMLのユーザーデータ
4. いずれかの経路で変更があった場合、変更ファイルをログに出力し、対象ディレクトリの所有者・権限を設定する。
5. アプリケーションのキャッシュをクリアする。
6. 同期結果の一時ログファイルを削除する。
7. ロックファイルを削除し、終了をログに記録する。
8. 変更が無かった場合は、変更なしを記録して権限設定・キャッシュクリアを行わずに終了する。

## 業務ルール・計算

| 項目 | 内容 |
|------|------|
| 同期方式 | S3を基準にローカルを一致させる。ローカルの余分なファイルは削除する。差分判定はタイムスタンプの厳密一致による。 |
| 変更検知 | 同期結果の一時ログが空でなければ「変更あり」とみなし、権限設定とキャッシュクリアを行う。 |
| 権限設定 | 変更があった経路についてのみ、所有者をWebサーバ実行ユーザーに設定し、ディレクトリにグループ継承を付与する。 |
| エンドポイント切替 | S3エンドポイントの指定有無により、署名なし・エンドポイント指定の同期に切り替える（ローカル検証環境向け）。 |

## API・バッチ結果

| 種類 | 内容 |
|------|------|
| 入力 | なし（cron起動。対象プレフィックス・バケットは環境変数）。 |
| 実行条件 | ロックファイルを取得できること。取得できない場合は実行しない。 |
| 成功結果 | S3の内容がローカルへ反映される。変更時は権限設定とキャッシュクリアが行われる。 |
| 失敗結果 | ロック取得失敗時は同期せず終了する。各同期・権限設定・キャッシュクリアの結果はログに記録する。 |
| 再実行時 | 毎分起動で繰り返し実行される。同期は冪等であり、変更が無ければファイルは更新されない。 |

---

## 入出力

| 種類 | 内容 |
|------|------|
| 入力 | S3バケットの3プレフィックス（テンプレート既定・テンプレートユーザーデータ・HTMLユーザーデータ）。バケット名・エンドポイントは環境変数。 |
| 成功時出力 | ローカルディレクトリ（テンプレート既定・テンプレートユーザーデータ・HTMLユーザーデータ）の更新。変更時は権限設定とキャッシュクリア。 |
| 失敗時出力 | ロック取得失敗・各処理の結果をログに記録する。 |
| 副作用 | ローカルファイルの更新・削除、所有者・権限の変更、アプリケーションキャッシュのクリア、ロックファイルの作成と削除、CloudWatchおよびローカルログへの出力。 |

---

## データ整合性

| 観点 | 内容 |
|------|------|
| 同期の基準 | S3を正とし、ローカルをS3に一致させる。ローカルでの直接変更は次回同期で上書き・削除され得る対象となる。 |
| 多重実行 | ロックファイルにより同時実行を防ぐ。ロックを取得できない実行は同期を行わない。 |
| 反映タイミング | 毎分の同期で反映する。S3更新から最大で次回起動までの遅延が生じる。 |
| キャッシュ | 変更検知時にキャッシュクリアを行い、反映後の表示に同期内容を反映する。 |

---

## DBカラム

本バッチはファイル同期であり、データベースの更新を行わない。直接関係するテーブル列は持たない。

---

## エラー処理

| エラー内容 | 処理 |
|------------|------|
| ロックファイルを取得できない（多重起動） | 同期を行わず、失敗理由と保持中プロセスをログに記録して終了する。 |
| 同期・権限設定・キャッシュクリアの結果 | ログに記録する。各処理の詳細な失敗時挙動はコマンド・インフラの動作に委ねる。 |

---

## ログ・監査

| タイミング | 記録内容 |
|------------|----------|
| 実行開始・終了 | 開始・終了・ロック取得・解放を記録する。 |
| 変更検知時 | 変更ファイル数・変更ファイル一覧・権限設定・キャッシュクリアの実行を記録する。 |
| 多重起動時 | 失敗理由と保持中プロセスを記録する。 |

ログはローカルログとCloudWatchの双方へ出力する。

### ログに出してはいけないもの

- S3の認証情報・アクセスキー
- 環境変数に含まれる秘密値
- Cookie値・セッションIDの完全値

---

## 排他制御・トランザクション

ロックファイルにより多重起動を防ぐ。データベーストランザクションは扱わず、楽観ロック・悲観ロックの対象は持たない。
