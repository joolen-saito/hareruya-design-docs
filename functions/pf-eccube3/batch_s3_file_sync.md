# バッチ インフラ — S3のファイルを自サーバに転送

## 業務ロジック

### 多重起動の防止

実行時にロックを取得する。既にロックが存在するときは同期を行わず、保持中の処理を記録して終了する。

### 同期する対象

ロックを取得できたときに、次の3経路をS3からローカルへ同期する。

| 経路 |
| --- |
| テンプレートの既定データ |
| テンプレートのユーザーデータ |
| HTMLのユーザーデータ |

### 同期の方式

S3を基準としてローカルを一致させる。ローカルにある余分なファイルは削除する。差分はタイムスタンプの厳密な一致で判定する。S3の接続先の指定があるときは、署名なしで接続先を指定する方式に切り替える。ローカルの検証環境向けの切り替えである。

### 変更があったときの後処理

同期の結果が空でないときを変更ありとみなし、変更したファイルを記録したうえで、変更があった経路について所有者をWebサーバの実行ユーザーに設定し、ディレクトリにグループの継承を付与する。続いてアプリケーションのキャッシュを消す。

変更が無かったときは、変更なしを記録し、権限の設定とキャッシュの削除を行わずに終了する。

いずれの場合も、終了時に同期結果の一時記録とロックを削除する。

### 実行の繰り返し

毎分起動する。同期は冪等であり、変更が無ければファイルを更新しない。

### エラー時の扱い

| エラー内容 | 処理 |
|------------|------|
| ロックを取得できない（多重起動） | 同期を行わず、理由と保持中の処理を記録して終了する |
| 同期・権限設定・キャッシュ削除の結果 | 記録する。個々の失敗時のふるまいはコマンドとインフラの動作による |

## 入出力

| 種類 | 内容 |
|------|------|
| 入力 | 起動引数を取らない。同期元のバケットと3つの経路、接続先は環境の設定から取る |
| 成功時出力 | テンプレート既定・テンプレートユーザーデータ・HTMLユーザーデータの各ローカル領域を更新する。変更があったときは権限の設定とキャッシュの削除を行う |
| 失敗時出力 | ロックを取得できないときは同期せず終了する。各処理の結果を記録する |
