# カード管理 — カード CSV 登録（取込）

## 概要

HareruyaEc プラグインが管理画面に提供する「カード登録 CSV, TSV」画面である。利用者がアップロードしたファイルの 1 行目を論理キー（例: `name_jp`）として解釈し、カードマスタとカード詳細・関連マスタ紐付けを登録または更新する。区切りは拡張子が `tsv` のときタブ、それ以外はコア設定の CSV 区切り文字を使う。

本書は実装手順ではなく、誰が・いつ・どの条件で・結果どうなるかを読むためのリバース詳細設計とする。pf-eccube3 に配置された HareruyaEc プラグインのソースを確認値とする。

本機能のカスタマイズ区分はカスタマイズである。現行挙動は pf-eccube3 の HareruyaEc プラグインを参照し、永続化に関わるテーブル名・列名などのDB関連は ec-cube-enterprise を正とする。

対象はブラウザ経由の管理画面に限定する。

コントローラのメソッド名は本文の主題としない。本文ではルートbind名やSymfonyのルートnameの網羅は主説明としない。「利用者視点の入口」にHTTPメソッドとサイトルートからのパスパターンを書く。コード探索でbind名が必要なときだけ「調査補助」へ書く。

## 処理フロー

### 画面を表示する（GET `admin_card_csv`）

1. 管理画面の認証・共通制約を通過する。
2. フォーム型 `admin_csv_import` で空のフォームを生成し、リクエストを取り込む。
3. 取込対象列の論理キーと説明の連想配列をテンプレートに渡し、Twig を描画する。

### ファイルを取り込む（POST `m14-05_admin_card_card_csv_import`）

1. 管理画面の認証・共通制約を通過する。
2. 取込処理用オブジェクトを生成し、同じく `admin_csv_import` のフォームを生成して `handleRequest` する。
3. 共有のフォーム検証ヘルプで CSRF を検証し、不合格ならアクセス拒否（HTTP 403）として扱われ得る。検証エラー時はエラーメッセージをフラッシュに積み、`admin_card_csv` へリダイレクトする応答を組み立てるが、`import` 側がこの戻り値で処理を打ち切るかは呼び出し元の実装次第である（実装を確認値とする）。
4. フォームからアップロードファイルを取得する。
5. 情報ログ「カードCSV登録開始」を出す。
6. ファイルを一時ディレクトリ（`csv_temp_realdir`）に保存し、内容を読み込んで文字コード変換・改行正規化・BOM・ゼロ幅文字の除去を行う。拡張子が `tsv` なら区切りはタブ、そうでなければ `csv_import_delimiter` を使い、ヘッダ行を 0 行目とする `CsvImportService` を構築する。失敗時は `false` となり、その場合はリダイレクトで GET 画面へ戻る。
7. 想定キー一覧とファイルのヘッダ配列を比較する。比較から除外する論理キーは `old_product_id`、`old_en_product_id`、`card_detail_id` である。一致しない場合は翻訳キー `admin.csv.error.format.header` をメッセージとする例外を投げる（翻訳は例外生成時点では行わない）。
8. ヘッダ列数を基準に、データが 1 行以上あるか、各行の列数がヘッダと一致するかを後続のループで検証する。データ 0 行は `admin.csv.error.data.empty`。
9. ORM の SQL ロガーを無効にし、トランザクションを開始する。
10. 各行について、必須列（後述）を検証し、英語カード名の `//` を `/` に置換した文字列で既存カードを検索する。無ければ新規カードとして生成する。
11. 行の値に応じてカード共通項目・タイプ・色・フォーマット・詳細・画像等を更新し、都度 `flush` する。100 行ごとに ORM キャッシュを解放する。
12. 全行処理後に再度キャッシュ解放を行い、サービス内で `commit` を呼ぶ。コントローラでも `commit` を呼ぶ。
13. 成功時、情報ログ「カードCSV登録完了」とフラッシュ成功キー `admin.register.complete` を積む。
14. 更新対象になったカード ID の配列（重複排除後）を引数に、支店更新通知サービスを呼ぶ。通信失敗時はエラーテーブル登録とログに留まり、取込自体の成功フラッシュは打ち消さない。
15. 一時ファイルを削除してから `admin_card_csv` へリダイレクトする。

### 取込中に検証例外または実行時例外が出たとき

1. トランザクションを `rollback` する。
2. 情報ログに例外メッセージを残す。
3. 例外メッセージをそのまま管理画面エラーフラッシュに積む（多くの経路では事前に `trans` 済みの文言が入る）。
4. 一時ファイル削除を試み、`admin_card_csv` へリダイレクトする。

## カード CSV 取込時の判定順序

| 順序 | 判定 | 結果 |
|------|------|------|
| 1 | CSRF・フォーム・ファイル必須・サイズ・MIME | 不合格ならエラー扱いでアップロード画面へ戻すか、HTTP 403。 |
| 2 | 一時保存と `CsvImportService` 構築 | 失敗時はリダイレクトのみ（追加フラッシュはこの分岐では積まない）。 |
| 3 | ヘッダの論理キー列（除外列適用後）が想定と完全一致 | 違反時は `admin.csv.error.format.header`。 |
| 4 | データ行が 1 行以上 | 違反時は `admin.csv.error.data.empty`。 |
| 5 | 各行の列数がヘッダ列数と一致 | 違反時は `admin.csv.error.format.body`（行番号付き）。 |
| 6 | 必須論理キーが空でない（`cmc` は後段で空を 0 扱いするため例外ルールあり） | 違反時は `admin.csv.error.data.require`。 |
| 7 | 参照マスタ（色・タイプ・セット等）に英名が存在 | 欠ける場合は `admin.csv.error.data.not_registered`。 |
| 8 | トランザクションコミットと支店通知 | 成否はログ・支店エラー表に分割される。 |

## 業務ルール・計算

| 項目 | 内容 |
|------|------|
| 既存判定 | 英語カード名は `//` を `/` に直した値で `mtb_card` 相当を検索する。ヒットしなければ新規。 |
| 日本語名ほか（条件付き） | `name_jp` が空でない行だけ、`＋` を `/` に置換して日本語名・アリーナ日本語名・日本語ルールテキストを上書きする。空の行ではこれらは更新されない。 |
| マナコスト | `White`→`W` 等の置換と `{` `}`→`(` `)` を行ってから保存する。 |
| CMC | レイアウト値により解釈が変わる。`Split` は `/` 区切りの数値を合計。`Flip` は先頭片方。`Double Faced,Meld` は `Meld` としてレイアウトマスタを引く。空の `cmc` は必須チェックから外れ、数値変換時は 0 扱いになり得る。 |
| 多値列 | `color`、`cardtype`、`subtype`、`specialtype`、`color_identity` は `,` または `/` で分割し、重複を除いてマスタ英名と照合する。同一英語カード名の 2 行目以降では、直前に登録した集合で上書きしない実装がある（配列 `registeredCards` による分岐）。 |
| フォーマット | CSV の `format` はカンマ区切り英名。行に含まれない既存の合法性付きフォーマット紐付けは削除する。新規・継続行はレガル制限に紐づけて保存する。ソースコメントに、禁止・制限のみのフォーマットを CSV だけでは再現できない旨の TODO がある。 |
| プロモーション | 空なら非プロモ定数に戻す。 |
| イラストレータ | マスタに無い英名は新規マスタ行を作成して紐付ける。 |
| 画像 URL | 日本語・英語・表側のみ更新。`card_detail_id` が行に無いときは `null` 条件で既存画像を探す実装になり、意図しない行との突合になる余地がある（実装を確認値とする）。 |
| 裏面詳細 ID | 空なら `null`。値があるとき対象行が無ければエラー。 |
| 色順 | 名前でマスタ検索。空なら外部キーを `null`。 |
| keyword_ability | ヘッダには含まれるが登録処理では読まない。 |

### 入力項目

| 項目名 | 必須／任意 | 最大長 | 初期値 | 保存先・扱い |
|--------|------------|--------|--------|----------------|
| CSV, TSVファイル選択 | 必須 | ファイルサイズ上限は `csv_size` MB（`constant.yml.dist` では 5）。MIME は `text/plain`、`text/csv`、`text/tab-separated-values`、`application/vnd.ms-excel` のいずれかとして検証される | 未選択 | フォーム項目キー `import_file`。永続化は行わず、一時ディレクトリへ保存したうえで取込パイプラインへ渡す。空ファイルはフォーム層の `NotBlank` により通常は弾かれる。 |

### エッジケース

| ケース | 扱い |
|--------|------|
| ヘッダのみでデータ行がない | `admin.csv.error.data.empty`。 |
| ヘッダ列数とデータ列数が異なる | 該当行番号付きで `admin.csv.error.format.body`。 |
| 英語名が同一の複数データ行 | 同一カードに対する更新となる。タイプ・色等は最初に触れた行の結果が `registeredCards` により保持され、後続行では変更されない場合がある。 |
| 支店通知失敗 | DB 取込は完了済み。失敗内容を支店更新エラーに残しログに JSON を出す。 |
| Windows かつ PHP7 かつパス区切りが `\` | 一時読込後に UTF-8 検出時は `SJIS-win` へ一度変換する分岐がある。 |

## DBカラム

| テーブル | 列（概念） | メモ |
|---------|------------|------|
| `mtb_card` | 名称・テキスト・マナ・CMC・パワー／タフネス／忠誠度・色順外部キー 等 | カード共通。 |
| `mtb_card_detail` | セット・レア・レイアウト・フレーバー・番号・各種フラグ・裏面 ID 等 | 行単位で作成または更新。 |
| `dtb_card_format` | カード ID・フォーマット ID・制限区分 | フォーマット列に無い既存行は削除されうる。 |
| 画像・中間 | `mtb_card_image` 等 | 言語 ID と表裏フラグで日本語・英語表を更新。 |

### DB操作

永続化の正は ec-cube-enterprise（テーブル名・操作は ec-cube-enterprise を正典）。当ドメインは承認ワークフローを介さず persist/flush で直接確定する（承認ワークフローは在庫機能固有）。

| 操作種別 | 対象テーブル | 契機・条件 |
|---------|--------------|------------|
| 登録/更新 | dtb_card_format / mtb_card / mtb_card_detail / mtb_card_image | 当機能が行う登録・更新で対象テーブルを直接保存する（不要な削除は含まない）。確定は persist/flush による即時反映。DB=ec-cube-enterprise を正典とする。 |

## 画面遷移

| 条件 | 遷移先 |
|------|--------|
| GET で画面を開く | `admin_card_csv` の同一テンプレート。 |
| POST が成功 | フラッシュ成功を伴い `admin_card_csv` へ HTTP リダイレクト。 |
| POST が失敗（例外・フォームエラー扱い） | フラッシュエラーを伴い `admin_card_csv` へ HTTP リダイレクト。 |
| CSRF 不正 | 共有ヘルプでは HTTP 403 が投げられ得る。 |

### 遷移時に引き継ぐ状態

| 起点 | 遷移前の処理 | 遷移後の初期状態 |
|------|--------------|------------------|
| 取込 POST 完了 | 一時ファイル削除、ORM トランザクション終了 | 空フォームとフォーマット表のみの GET。フラッシュに成功または失敗。 |

カード検索用セッション `admin.card.*` は本取込では主に参照しない。

## エラー処理

| エラー内容 | 処理 |
|------------|------|
| フォーム・ファイル検証 |  field エラーをフラッシュに載せる、`admin_card_csv` へ戻る経路（戻り値の扱いは実装を確認値とする）。 |
| ヘッダ不一致 | 例外メッセージ `admin.csv.error.format.header`、ロールバック、エラーフラッシュ。 |
| 行形式・必須・マスタ欠落 | 対応する翻訳メッセージを例外で発生させ、同様にロールバックとフラッシュ。 |
| 一時ファイル処理失敗 | `CsvImportService` 構築失敗時はフラッシュを増やさずリダイレクトのみの分岐がある。 |

| 支店通知成功 | 情報ログにカード ID 連結。 |
| 支店通知失敗 | 情報ログに失敗と JSON。 |

### ログに出してはいけないもの

- パスワード
- CSRF トークン原値
- セッション ID の完全値
- クッキー値

## 排他制御・トランザクション

POST 取込ではコントローラがトランザクションを開始し、例外時はロールバックする。登録ループ内では行単位で `flush` し、ループ後にサービス内でも `commit` を呼ぶ実装になっている。コントローラでも `commit` を呼ぶため、アクティブなトランザクションが残らない環境では二度目の `commit` が例外になり得る。実装を確認値とする。

行ロック・悲観ロック・楽観ロック・ロックファイルは使用しない。ロールバック対象や部分反映の扱いは本節のトランザクション境界と例外時の記載を正とする。
