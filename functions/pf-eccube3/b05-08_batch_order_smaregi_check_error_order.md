# バッチ 受注管理 — スマレジEC受注連携エラー再連携

## 概要

スマレジ連携でエラーになっているEC受注を対象に、会員のポイントをスマレジへ再連携（リトライ）するバッチである。コマンドライン（コンソールコマンド）から実行する。リクエスト数の上限に配慮し、受注ごとに短いインターバルを挟む。

本書は実装手順ではなく、誰が・いつ・どの条件で・結果どうなるかを読むためのリバース詳細設計とする。確認値はpf-eccube3（EC-CUBE3系）のHareruyaEcプラグインのスマレジバッチ（連携エラー受注の再連携処理）、受注サブ・選手情報を扱うリポジトリ、スマレジポイント連携処理を正とする。

カスタマイズ区分は現行踏襲であり、挙動はpf-eccube3を参照し、DB関連の記述はec-cube-enterpriseを正とする。

対象はコンソールコマンドであり、ブラウザ経由の画面を持たない。

本文ではフレームワークのコマンド型名やサービス型名を主説明としない。実行はコンソールのバッチコマンドで行う。

## リニューアル移行時の扱い

再連携の挙動は現行pf-eccube3を踏襲し、DB関連の永続化先はec-cube-enterpriseを正とする。現行で受注サブの補助表に持つスマレジ連携状態は、移行先では受注本体へ統合される。

| 観点 | 現行（pf-eccube3） | 移行先（ec-cube-enterprise） |
|------|--------------------|------------------------------|
| 再連携の挙動 | 連携エラー受注を抽出し会員ポイントを再連携し、成否でフラグ・エラーメッセージを更新する。 | 同等の挙動を踏襲する（挙動はpf-eccube3を正とする）。 |
| スマレジ連携エラーフラグ・エラーメッセージの保持 | 受注サブ（`dtb_order_sub` の `smaregi_error_flg`・`point_error_message`）。 | 受注本体（`dtb_order` の `smaregi_error_flg`・`point_error_message`）。補助表 `dtb_order_sub` は移行先に存在せず `dtb_order` へ統合される。 |
| 会員のスマレジID・ポイント | 選手情報（`dtb_player` の `smaregi_id`・`point`）。 | 同一スキーマ（`dtb_player` の `smaregi_id`・`point`）。 |

| 用語 | 説明 |
|------|------|
| 受注サブ | 受注の拡張情報。スマレジ連携エラーフラグ・エラーメッセージを保持する。 |
| 選手情報 | 会員に紐づく拡張情報。スマレジID・ポイントを保持する。 |
| 再連携 | エラーになった連携をやり直すこと。 |

## 利用者視点の入口

| 入口 | 実行方法 | 期待されるふるまい |
|------|----------|--------------------|
| コンソールのバッチコマンド | `smaregi:batch checkSmaregiErrorOrder` | スマレジ連携エラーのEC受注について、会員ポイントの連携をリトライし、成否で状態を更新する。 |

本機能はHTTPで届く画面を持たない。コマンド名が一致しない場合は処理を行わずに終了する。

---

## 処理フロー

### スマレジEC受注連携エラー再連携を実行する（`smaregi:batch checkSmaregiErrorOrder`）

1. スマレジ連携エラーのEC受注（受注サブと会員）を取得する。
2. 受注ごとに、会員のスマレジIDとポイントでスマレジポイント連携をリトライする。
3. 連携が成功した場合は受注サブの連携エラーフラグを解除する。
4. 連携が失敗した場合は受注サブにエラーメッセージを記録する。
5. リクエスト上限に配慮し、受注ごとに短いインターバルを挟む。
6. すべての更新を確定する。

## 業務ルール・計算

| 項目 | 内容 |
|------|------|
| 対象 | スマレジ連携エラーフラグが立っているEC受注。 |
| 成否の反映 | 成功でエラーフラグ解除、失敗でエラーメッセージ記録。 |
| 流量制御 | 1秒あたりのリクエスト上限を超えないよう受注ごとにインターバルを挟む。 |

## API/バッチ結果

| 種類 | 内容 |
|------|------|
| バッチ | 入力はコマンド名。成功時は連携エラー受注のポイント連携をリトライし、結果で状態を更新する。対象が無ければ何もせず完了する。 |
| API | スマレジへ会員ポイントを再連携する。成功で連携完了、失敗でエラー内容を保持する。 |

| 副作用 | スマレジポイント連携、受注サブの連携状態更新。 |

## DBカラム

機能に直接関係する列のみ記載する。型や一覧の細部はスキーマを参照する。

| テーブル | 列 | メモ |
|---------|-----|------|
| `dtb_order`（受注。現行は受注サブ `dtb_order_sub`） | `smaregi_error_flg` | 対象抽出と成功時の解除に使用する。 |
| `dtb_order`（受注。現行は受注サブ `dtb_order_sub`） | `point_error_message` | 失敗時に記録する。 |
| `dtb_player`（選手情報） | `smaregi_id`・`point` | 連携の入力に使用する。 |

### DB操作

本機能は参照系（検索）であり、DBへの登録・更新・削除は行わない。テーブル名は ec-cube-enterprise を正典とする。

| 操作種別 | 対象テーブル | 契機・条件 |
|---------|--------------|------------|
| 検索 | dtb_order / dtb_order_sub / dtb_player | 検索条件に合致するレコードを抽出する。 |

## データ整合性

| 観点 | 内容 |
|------|------|
| 連携状態 | 連携成功でエラーフラグを解除し、失敗でエラー内容を保持する。次回実行で再試行できる。 |

---

## エラー処理

| エラー内容 | 処理 |
|------------|------|
| コマンド名が未指定・不一致 | 処理を行わずに終了する。 |
| 連携失敗 | 受注サブへエラーメッセージを記録し、エラーフラグを残す。 |

## ログ・監査

| タイミング | 記録内容 |
|------------|----------|
| 開始・完了 | 開始・完了のコンソール出力（日時付き）。 |
| 連携失敗 | エラーメッセージを受注サブに記録する。 |

### ログに出してはいけないもの

- スマレジ連携の認証情報

## 排他制御・トランザクション

受注ごとに連携結果を反映し、最後に更新を確定する。本バッチは楽観ロック・悲観ロックの対象は持たない。流量制御のため受注ごとにインターバルを挟む。
