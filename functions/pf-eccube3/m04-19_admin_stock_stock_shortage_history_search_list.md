# M04-19（欠品履歴検索/一覧）

受注時に在庫不足で計上できなかった欠品の履歴を、日付帯で検索して一覧表示する画面。

## 概要

欠品履歴検索/一覧は、受注処理などで在庫が不足し欠品となった記録を、登録日の日付帯で検索して一覧表示する機能である。検索条件・表示件数・ソート条件はセッションに保持し、ページ送り後も同一条件で再検索する。一覧の各行は商品規格編集画面・受注編集画面へのリンクを持つ。

本書は実装手順ではなく、誰が・いつ・どの条件で・結果どうなるかを読むためのリバース詳細設計とする。HareruyaEc プラグインの実装と、検索一覧を駆動する共通処理（SearchControllerTrait）を確認値とする。

本機能のカスタマイズ区分はカスタマイズである。画面・処理の挙動は現行リポ（pf-eccube3 の HareruyaEc プラグイン）を参照し、DB関連（永続化先のテーブル名・列名・制約）は ec-cube-enterprise を正とする。現行と移行先でスキーマが異なる箇所は「リニューアル移行時の扱い」に集約する。

対象はブラウザ経由の管理画面に限定する。管理画面プレフィックスは HareruyaEc プラグインの設定キー `admin_route` で決まるため、本書では `%eccube_admin_route%` で示す。

本書の本文ではコントローラのメソッド名は主題としない。ルート bind 名は調査補助へ退避する。

---

## 本書で扱うこと

- 欠品履歴一覧を開く入口と、検索フォーム送信・ページ送りの挙動
- 日付帯（開始・終了）の指定と保持、登録日での絞り込み
- 一覧の列構成と件数表示、各行から規格編集・受注編集への遷移
- 検索条件・表示件数・ソート条件のセッション保持キー

---

## 本書で扱わないこと

以下は本書では仕様確定せず、実装または別機能の設計を正とする。

- 欠品履歴のCSV出力（本機能には存在しない。後述の「本書で扱わないこと」末尾参照）
- 欠品履歴の生成（受注処理で在庫不足が起きたときの記録）
- 規格編集画面・受注編集画面の仕様（各機能を正とする）
- 管理画面の認証・ログイン・権限マスタの詳細

本機能には欠品履歴のCSV出力ルート・エクスポート処理が存在しない。CSV出力が必要な場合は別機能の追加実装を要する。

## リニューアル移行時の扱い

DB関連は ec-cube-enterprise を正とする。現行（pf-eccube3 の HareruyaEc プラグイン）と移行先（ec-cube-enterprise）でスキーマ・仕様が異なる主な点を記録する。確認できない点は推測せず要確認として残す。

| 観点 | 現行（pf-eccube3） | 移行先（ec-cube-enterprise） |
|------|--------------------|------------------------------|
| 欠品履歴の主キー | `stockout_history_id` | `dtb_stockout_history.id` |
| 商品コード列 | `dtb_product_class.code` | `dtb_product_class.product_code` |
| 店舗の保持 | 欠品履歴に店舗列を持たない | `dtb_stockout_history.base_info_id`（店舗）を持つ |
| 状態列のメモ | `dtb_product_sub_class.memo` | 商品サブ規格テーブルが存在しない（ec-cube-enterprise 実装で要確認） |
| 欠品理由 | 列として保持しない | 基本設計（M04-19シート）は欠品理由列の追加を求める。`dtb_stock_history.shortage_reason` 等が該当（ec-cube-enterprise 実装で要確認） |

基本設計（M04-19シート）が描く店舗・在庫区分・登録元・欠品時販売価格・欠品理由・最終更新者などの追加列は、現行 pf-eccube3 の欠品履歴一覧には未実装である。これらは移行先 ec-cube-enterprise 実装側の仕様であり、本書では現行挙動のみを扱い、追加仕様は「本書で扱わないこと」と本節に集約する。

## 利用者視点の入口

| 入口 | URLエンドポイント | 期待されるふるまい |
|------|--------------------|--------------------|
| 欠品履歴一覧を開く | `GET /%eccube_admin_route%/product/stockout/history` | 検索フォームを初期表示し、検索条件セッションを消去して一覧は空で表示する。 |
| 「検索する」で送信 | `POST /%eccube_admin_route%/product/stockout/history/search/1` | 日付帯を検証・保持し、欠品履歴一覧を1ページ目で組み立てて表示する。 |
| ページネーションでNページへ | `GET /%eccube_admin_route%/product/stockout/history/search/{page_no}` | セッションの検索条件で一覧のNページ目を表示する。 |
| 表示件数プルダウン変更 | `GET /%eccube_admin_route%/product/stockout/history/search/1?page_count=…` | ページマスタに存在する件数ならセッションへ保存し、その件数で分割する。 |
| 一覧の商品名リンク | `GET /%eccube_admin_route%/product/product/{id}/class/{classId}/edit`（別タブ） | 規格編集画面へ遷移する。 |
| 一覧の受注番号リンク | 受注編集画面（別タブ） | 受注編集画面へ遷移する。 |

検索フォームの送信先は常にページ番号1の検索ルートである。ページ送り・表示件数変更は検索ルートへの GET である。

## 処理フロー

### 欠品履歴一覧を開く（初期表示）

1. 利用者が欠品履歴一覧を開く。
2. 検索条件・ページ番号・表示件数のセッションを消去する。
3. 検索フォームを空で初期化し、一覧は空で画面を表示する。

### 検索する・ページ送りする

1. 「検索する」または件数変更・ページ送りで検索ルートへ届く。
2. リクエストの並び順が想定外（ASC・DESC 以外）のときは並び順エラーを表示して初期表示へ戻す。
3. 表示件数はリクエスト値がページマスタに存在すればセッションへ保存し、無ければセッションまたは既定件数を使う。
4. 検索条件はフォーム値、無ければセッション値を復元して用いる。
5. 欠品履歴の検索用クエリと件数を組み立て、ページネーションで一覧を作る。
6. 検索条件・ページ番号・表示件数・ソート条件をセッションへ保存する。
7. 一覧を画面へ渡して表示する。

## 業務ルール・計算

| 項目 | 内容 |
|------|------|
| 日付帯（開始） | 開始が指定されたとき、登録日がその日時以降を対象とする。 |
| 日付帯（終了） | 終了が指定されたとき、終了日を含めるため終了日の翌日0時未満を対象とする。 |
| 状態表示 | 規格拡張のメモがあればメモを、無ければ状態名を状態列に表示する。 |
| 本機能の計算 | 欠品履歴の集計・再計算は行わない。表示は履歴に記録済みの値をそのまま用いる。 |

### 入力項目

| 項目名 | 必須／任意 | 最大長 | 初期値 | 保存先・扱い |
|--------|------------|--------|--------|----------------|
| 日付（開始） | 任意 | `yyyy-MM-dd` の単一行日時 | 空 | 欠品履歴の登録日下限。フォームキー `date_from`。検索条件セッション `admin.stockout_history.search` に保持。 |
| 日付（終了） | 任意 | `yyyy-MM-dd` の単一行日時 | 空 | 登録日上限。終了日を含める（翌日0時未満）。フォームキー `date_to`。 |

検索フォームはなりすまし対策トークンの検証を無効化している（履歴検索の照会用フォームとして設定）。CSRF 検証無効は照会フォームの設定であり、更新は行わない。

### エッジケース

| ケース | 扱い |
|--------|------|
| 初回表示（検索前） | セッションを消去し、一覧を空で表示する。 |
| 日付未指定で検索 | 日付帯の絞り込みを付けず、検索条件に一致する欠品履歴を表示する。 |
| 並び順が想定外の値 | 並び順エラーを表示し初期表示へ戻す。 |
| 検索結果0件 | 「検索条件に該当するデータがありませんでした。」を表示する。 |

## データ整合性

| 観点 | 内容 |
|------|------|
| 表示時点 | 一覧は表示時点で欠品履歴テーブルを読んだ結果である。表示後の更新は自動反映しない。 |
| 履歴と現在値 | 欠品履歴は欠品発生時点の記録であり、商品の現在在庫・受注の現在状態との一致は保証しない。 |
| リンク先との整合 | 規格編集・受注編集のリンク先で値が変わっても、一覧は再読込まで履歴時点の表示を保つ。 |

## DBカラム

当機能の一覧が参照する列を示す。テーブル名・列名は ec-cube-enterprise を正とし、現行（pf-eccube3）と異なる場合は移行先名を主として現行名を括弧で添える。型の細部はスキーマを参照する。

| テーブル | 列 | メモ |
|----------|-----|------|
| dtb_stockout_history | id（現行 stockout_history_id）, stockout, order_id, product_class_id, base_info_id, member_id, create_date | 欠品履歴の表示・絞り込み。 |
| dtb_product_class | product_code（現行 code） | 規格コード（商品コード列）。 |
| dtb_product | name, id | 商品名表示・規格編集リンク。 |
| dtb_product_sub_class（現行のみ。ec-cube-enterprise 実装で要確認） | memo | 状態列のメモ。移行先に商品サブ規格テーブルが見当たらない。 |
| mtb_card_condition | code | 状態列の表示。 |
| mtb_language | name_jp | 言語列。 |
| dtb_member | name | 登録者列。 |
| （受注補助） | order_number | 受注番号列・受注編集リンク。 |

### DB操作

本機能は参照系（検索・出力）であり、DBへの登録・更新・削除は行わない。テーブル名は ec-cube-enterprise を正典とする。

| 操作種別 | 対象テーブル | 契機・条件 |
|---------|--------------|------------|
| 検索 | 欠品履歴テーブル（現行 dtb_stockout_history。移行先の名称は ec-cube-enterprise 実装で要確認） | 検索条件に合致する欠品履歴を抽出し、一覧表示する。 |
