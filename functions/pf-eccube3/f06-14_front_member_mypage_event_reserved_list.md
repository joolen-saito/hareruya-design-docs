# 会員 — 予約済み大会一覧

## 概要

ログイン済み会員が、自分が申し込んだ大会（イベント）の一覧を閲覧し、各大会の詳細へ遷移できる機能である。マイページ系の「予約済み大会一覧」から入り、会員に紐づく選手情報を起点に、キャンセル以外の申込を開催日時の新しい順で表示する。各行にイベント名、フォーマット、開催日時、ステータス（決済中・イベント終了・申込状態）を並べ、イベント名からイベント詳細へ遷移する。一覧からデッキ登録一覧・マイページへも遷移できる。

本書は実装手順ではなく、誰が・いつ・どの条件で・結果どうなるかを読むためのリバース詳細設計とする。確認値はpf-eccube3（EC-CUBE3系）のHareruyaEcプラグインのイベント申込履歴処理、テンプレート（`Mypage/event_history.twig`）、イベント申込リポジトリの取得処理を正とする。

本機能のカスタマイズ区分はカスタマイズである。挙動の参照リポはpf-eccube3とし、DB関連の記述（テーブル名・列名・永続化先・副作用のDB更新）は ec-cube-enterprise を正とする。現行と移行先のスキーマ差は「リニューアル移行時の扱い」に集約する。

対象はブラウザ経由のフロント（会員マイページ）に限定する。フロントのルートは`/{_locale}`配下にマウントされ、URLは`/{_locale}/mypage/events`の形をとる。

本文ではフレームワークのコントローラ型名やメソッド名を主説明としない。本文ではルートbind名の網羅は主説明とせず、「利用者視点の入口」にHTTPメソッドとサイトルートからのパスパターンを書く。コード探索でbind名が必要なときだけ「調査補助」へ書く。

## 本書で扱うこと

- 予約済み大会一覧の入口と表示
- 一覧の抽出条件（会員に紐づく選手情報の申込、キャンセル除外）・並び順
- 各行のフォーマット・開催日時・ステータス表示
- イベント詳細・デッキ登録一覧・マイページへの遷移
- 未ログイン・申込0件の扱い

## 本書で扱わないこと

以下は本書では仕様確定せず、実装または別機能の設計を正とする。

- イベント詳細・イベント申込・決済そのものの仕様（イベント機能を正とする）
- 大会デッキ登録編集（大会デッキ登録編集機能を正とする）
- 予約済みチーム大会一覧（チーム席順変更系の別画面を正とする）

## リニューアル移行時の扱い

現行（pf-eccube3）の挙動を正としつつ、DB関連は移行先（ec-cube-enterprise）を正とする。確認できた差は次のとおり。

| 観点 | 現行（pf-eccube3） | 移行先（ec-cube-enterprise） |
|------|--------------------|------------------------------|
| イベント申込テーブル | イベント申込（HareruyaEc） | 申込（`dtb_event_entry`）。申込状態は申込状況マスタ参照（`entry_status_id` → `mtb_entry_status`）。 |
| 選手情報と申込参加者 | 選手情報の識別子で申込を抽出 | 申込参加者（`dtb_entry_player`）が選手情報（`dtb_player`）と申込（`dtb_event_entry`）を関連づける。抽出は選手情報（`dtb_player`）を起点とする。 |
| イベント詳細・イベント | イベント詳細・イベント | イベント詳細（`dtb_event_detail`、開催日時 `start_date`・終了予定 `end_date`）、イベント（`dtb_event`、`name_jp`／`name_en`）。 |
| 論理削除の方式 | 削除フラグ（`del_flg` 等）による論理削除 | イベント系・選手系は削除日時（`deleted_at`）による論理削除とする。キャンセル除外は申込状態（`mtb_entry_status`）で判定する点は移行後も同じ。 |
| 申込状態の名称表示 | 申込状態の名称 | 申込状況マスタの名称（`name`）・英語名称（`name_en`）を言語に応じて表示する。 |

移行先での具体的なキャンセル判定・並び順実装は ec-cube-enterprise 実装で要確認とし、本書では現行挙動を正とする。

## 利用者視点の入口

| 入口 | URLエンドポイント | 期待されるふるまい |
|------|--------------------|--------------------|
| マイページの「予約済み大会一覧」ブロック | `GET /{_locale}/mypage/events` | 会員自身の申込（キャンセル除外）を開催日時の新しい順に表示する。 |

フロントのページであり管理画面プレフィックスは付かない。`/{_locale}/mypage`配下は会員ログインを要する。本一覧はページングを持たず、申込全件を一覧表示する。

## フロント挙動

| 観点 | 内容 |
|------|------|
| 表示要素 | 見出し「予約済み大会一覧」、一覧見出し（イベント名・フォーマット・開催日時・ステータス）、各申込行（フォーマットアイコン・イベント名リンク・開催日時・ステータス）、申込が無い場合の案内、「デッキ登録」ボタン、「マイページ」ボタン。 |
| JS挙動 | 本機能ではJSによる非同期取得や動的な表示切替を扱わない。 |
| CSS・レイアウト | フォーマットはコードに対応するアイコンで表示する。決済中はエラー系の見た目、申込完了は完了系の見た目で示す。PC・スマホでフォーマット表示位置を切り替える。 |
| モーダル・ポップアップ | 本画面専用のモーダルは無い。 |

ステータスは申込状態に応じて表示を切り替える。申込状態が決済中（識別子1）のときは「決済中」と決済案内のヘルプリンクを表示する。それ以外はイベントが終了済みなら「イベント終了」、未終了なら申込状態の名称を表示する。

---

## 処理フロー

### 予約済み大会一覧を表示する（GET `/{_locale}/mypage/events`）

1. 会員ログインを要求し、ログイン会員に紐づく選手情報を特定する。
2. 当該選手情報の識別子で、キャンセル以外の申込を取得する。
3. 取得した申込を開催日時の新しい順でテンプレートへ渡して表示する。
4. 申込が1件も無い場合は「予約済みの大会はありません。」と表示する。

## 業務ルール・計算

| 項目 | 内容 |
|------|------|
| 一覧の対象 | 申込は選手情報に紐づく。常にログイン会員自身の申込のみを対象とする。 |
| キャンセル除外 | 申込状態がキャンセルのものは一覧に含めない。 |
| 並び順 | 開催日時の降順（新しい大会が上）。 |
| ステータス表示 | 決済中・イベント終了・申込状態名称を条件に応じて出し分ける。 |
| フォーマット表示 | イベントの各フォーマットのコードに対応するアイコンを並べて表示する。 |

本機能では一覧表示に伴う入力フォームを持たないため、`### 入力項目`の表は持たない。

## DBカラム

機能に直接関係する列のみ記載する。型や一覧の細部はスキーマを参照する。

テーブル・列名は ec-cube-enterprise を正とする。

| テーブル | 列 | メモ |
|---------|-----|------|
| 選手情報（`dtb_player`） | 会員参照・選手識別子（`id`） | 申込取得の抽出キー。会員から特定する。 |
| 申込参加者（`dtb_entry_player`） | 選手参照（`player_id`）・申込参照（`event_entry_id`） | 選手情報と申込を関連づける。一覧の抽出経路。 |
| イベント申込（`dtb_event_entry`） | 申込状態参照（`entry_status_id`） | キャンセル除外とステータス表示。申込状況マスタ（`mtb_entry_status`）を参照する。 |
| イベント詳細（`dtb_event_detail`） | 開催日時（`start_date`）・終了予定（`end_date`） | 並び順とイベント終了判定。 |
| イベント（`dtb_event`） | 名称（`name_jp`／`name_en`）・フォーマット参照 | イベント名・フォーマットアイコンの表示。 |

### DB操作

本機能は参照系（検索）であり、DBへの登録・更新・削除は行わない。テーブル名は ec-cube-enterprise を正典とする。

| 操作種別 | 対象テーブル | 契機・条件 |
|---------|--------------|------------|
| 検索 | dtb_entry_player / dtb_event / dtb_event_detail / dtb_event_entry / dtb_player / mtb_entry_status | 検索条件に合致するレコードを抽出する。 |
