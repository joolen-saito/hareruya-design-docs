# o01-02_other_mtg_buyer_mtg_buyer_online_purchase（その他_MTGバイヤー_ネット買取）

MTGバイヤー（買取端末のアプリ）の「ネット買取」は、ネット買取の受注を一覧から選び、届いたカードを査定して、査定結果をECCUBEへ登録する機能である。受注・商品の情報はすべてECCUBEのAPIから取得し、査定結果もAPIで送る。アプリ自身は受注を保存しない。

本書はアプリ側のふるまいを定める。呼び出すAPIの応答内容と更新内容は、各APIの設計書（A06-01、A06-06〜A06-08、A06-11、A06-12、A07-01〜A07-07）を正とする。

## 業務ロジック

### 入口

| 観点 | 扱い |
| --- | --- |
| 入口 | ログイン後の業務選択画面にある「ネット買取」 |
| 利用できる店舗 | ログインした利用者の所属店舗名が「トーナメントセンター 東京」のときだけ利用できる。それ以外の店舗の利用者の場合は、灰色で表示して利用できなくする |
| 所属店舗名の取得元 | ログインAPI（A06-01）の応答に含まれる所属店舗名 |
| 実行したとき | お客様選択画面（ネット買取）へ移る |

| 受注一覧を取得できたとき、個別入力商品を取得 | POST | `api/v1/admin/buyOrderIndivisualInputProduct.json` | `ids`（ネット買取受注IDをカンマで連結） | A07-07 |
| 査定を開始するとき、中断するとき、査定状態を更新 | PUT | `api/v1/admin/buyOrder/{ネット買取受注ID}/status.json` | `status`（状態ID） | A07-04 |

### お客様選択画面（ネット買取）

画面を開いたときと「更新」を実行したときに、次の順で取得する。

| 順 | 処理 |
| --- | --- |
| 1 | 受注一覧を取得する |
| 2 | まとめて買取の商品IDを取得する |
| 3 | 手順1で得た全受注のIDを渡して、申込カードを取得する |
| 4 | 同じIDを渡して、個別入力商品を取得する |
| 5 | 申込カードと個別入力商品を、ネット買取受注IDが一致する受注へひも付ける |
| 6 | 一覧を取得結果で置き換える |

一覧の1行は1受注で、次を表示する。

| 表示項目 | 値 |
| --- | --- |
| 買取番号 | ネット買取受注ID |
| 申込日時 | 受注の申込日時 |
| お客様名 | 受注のお客様名 |
| 買取カテゴリ | まとめて買取を含む受注の場合は「まとめて買取」。含まない受注の場合は空 |
| 査定担当者 | 受注の査定担当者名 |
| フリーコメント | 受注のフリーコメント |
| 査定状況 | 受注の状態が商品到着・査定中・査定中断・査定再開のときに、それぞれの状況を示す画像を出す。それ以外の状態では何も出さない |

「まとめて買取を含む」と判定するのは、次のいずれかに当たる受注である。

| 条件 |
| --- |
| 申込カードの中に、商品IDがまとめて買取の商品IDと一致するものがある場合 |
| 申込カードの中に、買取カテゴリがまとめて買取のものがある場合 |
| 個別入力商品が1件以上ある場合 |

商品IDがまとめて買取の商品IDと一致する申込カードは、判定に使ったあと受注の申込カードから除く。査定表には載せない。

### 受注の選択と査定の開始

一覧から受注を1件指定したとき、その受注の状態を更新してから査定画面へ移る。

| 選んだ受注の状態 | 扱い |
| --- | --- |
| 査定中断の場合 | 「「{お客様の姓 名}」の受注を開きますか？」と確認する。「いいえ」なら何もしない。「はい」なら状態を査定再開へ更新する |
| 上記以外の場合 | 確認せずに、状態を査定中へ更新する |

状態の更新に成功したときは、中断時に保管した査定途中のデータ（後述）を取り寄せ、査定画面（ネット買取査定）へ移る。保管したデータが無い受注の場合もそのまま移る。保管先がエラーを返した場合（権限のエラー、保管先の内部エラーなど）も、保管したデータが無い場合と同じ扱いにして査定画面へ移る。状態の更新に失敗したとき、または保管先と通信できなかったときは、査定画面へ移らず、一覧を取得し直す。保管先と通信できなかった場合はメッセージを表示しない。

### 査定で使う状態ID

| 状態 | 状態ID | アプリが送る場面 |
| --- | --- | --- |
| MTGBuyer査定完了 | 3 | 査定完了を登録するとき |
| 査定中 | 10 | 査定中断以外の受注を選んだとき |
| 査定中断 | 11 | 査定を中断するとき、お客様を切り替えるとき、ログアウトするとき、アプリを終了するとき |
| 査定再開 | 12 | 査定中断の受注を選び、確認に「はい」と答えたとき |

### 査定表の初期表示

査定画面を開いたとき、査定表を次の順で決める。

| 条件 | 査定表の内容 |
| --- | --- |
| その受注の査定途中のデータが端末にある場合 | 査定途中のデータを読み込む。削除済みの行は削除済みのまま持ち、査定表には表示しない |
| 査定途中のデータが無い場合 | 受注の申込カードと個別入力商品から作る（下表） |

申込カードから行を作るときは、申込カードの商品IDをまとめて渡して商品情報を取得する。

| 行の項目 | 申込カードの行 | 個別入力商品の行 |
| --- | --- | --- |
| 枚数 | 申込カードの枚数 | 個別入力商品の枚数 |
| 買取価格 | 申込カードに査定後の価格があればその価格。無ければ、申込カードの状態に対応する申込時買取価格。それも無ければ0 | 個別入力商品の金額 |
| 言語 | 申込カードの言語 | 日本語（JP） |
| 状態 | 申込カードの状態（1=NM、2=SP、3=MP、4=HP） | NM |
| フォイル | 申込カードのフォイル区分。未設定の場合はノーマル。査定表では、フォイルの場合は「○」、ノーマルの場合は「-」と表示する | ノーマル（査定表の表示は「-」） |
| 買取カテゴリ | 申込カードの買取カテゴリ | まとめて買取 |
| 商品名 | 商品情報の日本語の商品名 | 個別入力商品の名称 |
| 商品コード・商品規格ID・基準価格・レアリティ・略称タグ・プロモ | 商品情報のうち、商品ID・言語・状態・フォイル区分が申込カードと一致する規格の値。プロモは、プロモーションのあるカードの場合は「○」、無い場合は「-」。商品コード・商品規格ID・レアリティ・略称タグは行に持つだけで、査定表には表示しない | 設定しない（プロモは「-」） |

| ケース | 扱い |
| --- | --- |
| 商品情報の取得結果が0件の場合 | 申込カードの行を1行も作らない。個別入力商品の行だけを作る |
| 商品情報の中に、申込カードの商品IDが無い場合 | その申込カードの行を作らない |
| 商品IDはあるが、言語・状態・フォイル区分の一致する規格が無い場合 | 行は作るが、商品名・商品コードなどは空のままにする。商品規格IDは0になる |
| 商品情報を取得するAPIと通信できなかった場合、または応答を商品情報として読み取れなかった場合 | 失敗の内容をメッセージで表示し、申込カードの行を1行も作らない。個別入力商品の行だけを作る |

### 査定表の行の追加と買取価格

ネット買取のときだけ、査定表に買取カテゴリの列を出し、行ごとに「選んで買取」「まとめて買取」を設定できる。列の見出しの絞り込みが「選んで買取」「まとめて買取」のときは、査定表をその買取カテゴリの行だけにする。「全て表示」のときは絞らない。基準価格・基準小計・部門の列は、ネット買取のときは出さない。

| 追加の方法 | 買取価格 | 買取カテゴリ |
| --- | --- | --- |
| カードを読み取り、またはカード名で検索して「登録する」を実行したとき | 登録するカードが受注の申込カードに含まれ（商品ID・言語・フォイル区分が一致）、登録する状態の申込時買取価格があれば、その申込時買取価格。無ければ商品情報の買取価格 | まとめて買取 |
| 「個別入力する」で追加したとき | 入力した価格 | まとめて買取 |
| 「1円」「2円」「5円」「10円」で追加したとき | 指定した金額。商品名は「{金額}円商品」。枚数は、追加するときに入力させた枚数 | まとめて買取 |

カード情報の欄には、選択中のカードが受注の申込カードに含まれる（商品ID・言語・フォイル区分が一致する）ときに申込時買取価格を表示する。選択中の状態に対応する申込時買取価格がある場合はその価格を、無い場合は申込時買取価格の先頭の1件を表示する。申込カードに含まれないとき、または申込時買取価格が1件も無いときは表示しない。

「個別入力する」では、商品名・価格・枚数を必須とする。基準価格と部門は入力させない。

行を追加・複製・削除したとき、枚数や買取価格を変えたとき、査定表を初期化したときは、そのつど査定途中のデータを端末に保存する。受注・商品のデータは端末に保存しない。端末に保存するのは査定途中のデータだけである。

### フリーコメントの更新

査定画面のお客様情報欄で「コメント更新」を実行したとき、欄に入力されているフリーコメントでフリーコメントの更新を呼び出す。成功した場合も失敗した場合も、画面は査定画面のままである。

### 査定完了

「査定完了」の操作は、ネット買取の査定画面にだけ出す。

| 順 | 処理 |
| --- | --- |
| 1 | 「査定を完了します。よろしいですか？」と確認する。「いいえ」の場合は何もしない |
| 2 | 査定表から削除済みの行を除く |
| 3 | 残った行を、商品規格ID・商品名・言語・状態・フォイル区分・買取価格・買取カテゴリがすべて同じもの同士でまとめ、枚数を合計する |
| 4 | 状態ID 3（MTGBuyer査定完了）を `order_status`、まとめた査定明細の並びを `order_details` として、JSONで送る |
| 5 | 成功した場合は、保管してある査定途中のデータと端末の査定途中のデータを消し、お客様選択画面（ネット買取）へ移る。保管してあるデータを消せなかった場合も、端末のデータを消してお客様選択画面（ネット買取）へ移る |

査定明細1件として送る項目は次のとおり。

| 項目 | 値 |
| --- | --- |
| `product_class_id` | 商品規格ID。個別入力や金額指定で追加した行の場合と、申込カードから作った行で一致する規格が無かった場合は0 |
| `name` | 商品名 |
| `quantity` | まとめた行の枚数の合計 |
| `price` | 買取価格 |
| `language_id` | 言語ID |
| `condition_id` | 状態（1=NM、2=SP、3=MP、4=HP） |
| `purchase_category` | 買取カテゴリ（1=選んで買取、2=まとめて買取） |

フォイル区分は送らない。ECCUBE側が商品規格IDから求める。

登録に失敗したときは査定画面にとどまり、査定表と査定途中のデータを残す。「査定完了」は、送信中は実行できず、応答を受け取ったときは成功・失敗にかかわらず再び実行できる。

### 査定の中断と再開

次の操作をすると、査定途中のデータを保管し、受注の状態を査定中断（状態ID 11）へ更新する。

| 操作 | 移動先 |
| --- | --- |
| 「査定を中断する」を実行したとき | 業務選択画面 |
| 「お客様切り替え」を実行したとき | お客様選択画面（ネット買取） |
| 「ログアウト」を実行したとき | ログイン画面 |
| アプリのウィンドウを閉じたとき | アプリを終了する |

| 観点 | 扱い |
| --- | --- |
| 保管するデータ | 査定表の全行（削除済みの行を含む）。受注ごとに1ファイル（ファイル名は「n{ネット買取受注ID}.csv」）で、端末の外のファイル保管先（Amazon S3）へ置く |
| 保管に成功したとき | 「査定を中断します。現在の査定データをサーバにアップロードしました。」と表示する |
| 端末に査定途中のデータが無いとき | 保管を行わず、成功として扱う |
| 保管または状態の更新に失敗したとき | 続けるかを確認する。「はい」なら移動する。「いいえ」なら査定画面にとどまる |
| 再開 | 査定中断の受注を一覧で指定したとき、保管したデータを端末へ取り寄せ、査定表へ復元する。どの端末から開いた場合も同じ内容になる |
| 査定完了したとき | 保管したデータを消す |

### エラー時の扱い

| 事象 | 扱い |
| --- | --- |
| 受注一覧・まとめて買取の商品ID・申込カード・個別入力商品のいずれかの取得に失敗した場合 | メッセージを表示し、一覧は取得前の内容のままにする |
| 状態の更新でECCUBEがエラーを返した場合 | ECCUBEが返したエラー文言の1件目を表示する |
| 状態の更新で通信に失敗した場合 | 「サーバエラー：査定ステータスの更新に失敗しました。」と表示する |
| 査定完了の登録に失敗した場合（エラー応答・通信失敗） | 「サーバエラー：査定完了の登録に失敗しました。」と表示し、査定画面にとどまる |
| フリーコメントの更新に失敗した場合（エラー応答・通信失敗） | 「サーバエラー：フリーコメントの登録に失敗しました。」と表示する |

## 入出力

| 種類 | 内容 |
| --- | --- |
| 入力 | ログイン利用者の認証トークンと所属店舗名、ECCUBEから取得する受注一覧・申込カード・個別入力商品・商品情報、ファイル保管先から取り寄せた査定途中のデータ、査定者の操作（カードの登録、枚数・買取価格・買取カテゴリの変更、行の削除、フリーコメント） |
| 成功時出力 | ECCUBEへの状態の更新・フリーコメントの更新・査定完了の登録、査定途中のデータの保管と削除 |
| 失敗時出力 | メッセージの表示。ECCUBEへ送る内容は変えない |

### 入出力: 永続化

アプリはECCUBEのデータベースを直接は更新しない。受注・査定明細・状態変更履歴の登録・更新は、アプリが呼び出した各API（A07-03〜A07-05）が行う。

| 操作 | 契機 |
| --- | --- |
| 更新しない | 受注一覧・申込カード・個別入力商品・商品情報を取得したとき |
| 更新（APIが行う） | 状態の更新を呼び出したとき、受注の状態 |
| 更新（APIが行う） | フリーコメントの更新を呼び出したとき、受注のフリーコメント |
| 登録・更新（APIが行う） | 査定完了の登録を呼び出したとき、受注の状態と査定明細 |
