# F06-26（店頭PC用アカウントで通常会員と異なる制御）

## 概要

店頭PC用に用意した会員アカウント（店内アカウント）に対し、通常会員と異なるアクセス制御を行う機能である。店頭PC用アカウントは会員の顧客グループで識別し、許可IPアドレス以外からのアクセスは即時ログアウトさせる。また、店頭対面接客に不要なフロント機能（会員情報変更・退会・配送先登録・お問い合わせ・購入・デッキ登録・買取など）では、店頭フロント区分が立つ顧客グループの会員に対し共通エラー画面を返してアクセスを遮断する。店頭注文を確定すると店内モニター表示用の番号札を採番する点も通常会員と異なる。

本書は実装手順ではなく、誰が・いつ・どの条件で・結果どうなるかを読むためのリバース詳細設計とする。確認値はpf-eccube3（EC-CUBE3系）のHareruyaEcプラグインのIPアクセス制限処理（`IpSecurityEvent`）、顧客グループによるページアクセス制限処理（`CustomerGroupEvent`）、イベント登録（`event.yml`）、顧客グループ判定リポジトリ、設定オプションを正とする。

本機能のカスタマイズ区分はカスタマイズであり、画面・挙動の参照はpf-eccube3を正とし、永続化（テーブル・列）に関する記述はリニューアル移行先のec-cube-enterpriseを正とする。

対象はブラウザ経由のフロント全般に作用する横断制御である。フロントのルートはサイトルート直下に言語別プレフィックス`/{_locale}`を付けて公開する。

本文ではフレームワークのコントローラ型名やメソッド名を主説明としない。ルートbind名の網羅は主説明とせず、制御の効く境界を「利用者視点の入口」に書く。

---

## 本書で扱うこと

- 店頭PC用アカウント（店内アカウント）の識別方法
- 許可IP以外からのアクセス時の即時ログアウト
- 店頭フロント区分の顧客グループに対するフロント機能のアクセス遮断
- 店頭注文時の番号札採番という通常会員との差異

---

## 本書で扱わないこと

以下は本書では仕様確定せず、実装または別機能の設計を正とする。

- 顧客グループ・許可IPの管理画面設定の仕様（プラグイン設定機能を正とする）
- 各遮断対象機能（会員情報変更・配送先・お問い合わせ・購入・デッキ登録・買取など）の本体仕様（各機能の設計を正とする）
- 支店店頭用アカウント（支店店頭フロント区分）の制御は本書の主題としない（同型の制御として参照のみ）
- 店内モニターでの番号札表示そのもの（店頭呼び出し番号表示機能を正とする）

## リニューアル移行時の扱い

現行（pf-eccube3）と移行先（ec-cube-enterprise）でのDB関連の差を記録する。挙動は現行を正とし、永続化先の名称はec-cube-enterpriseを正とする。

| 観点 | 現行（pf-eccube3） | 移行先（ec-cube-enterprise） |
|------|--------------------|------------------------------|
| 店頭フロント区分 | 顧客グループの店頭フロント区分フラグ | `dtb_customer_group.shop_front_flg`。立っている会員を対象フロント機能で遮断する。 |
| 支店店頭フロント区分 | 顧客グループの支店店頭フロント区分フラグ | `dtb_customer_group.branch_shop_front_flg`（別区分。本書では主題としない）。 |
| 会員から顧客グループの参照 | 選手情報から顧客グループへの参照 | `dtb_player.customer_group_id`（顧客グループへの参照）。 |
| 許可IPの設定 | オプション設定（キー`otc_account_ip`） | `mtb_option`の`option_key`=`otc_account_ip`・`option_value`にカンマ区切りで保持。同一スキーマ。 |
| 店頭注文の番号札 | `dtb_waiting_number`へ採番・保存 | 同名テーブルが存在し同一スキーマ。拠点参照`base_info_id`を持つ。 |

店内アカウントの識別に用いる顧客グループ区分（店内アカウント）の保持方法は、ec-cube-enterpriseの`dtb_customer_group`に明示の区分列が見当たらないため、`shop_front_flg`による判定か顧客グループ値での判定かをec-cube-enterprise実装で要確認とする。

## 用語

| 用語 | 説明 |
|------|------|
| 顧客グループ | 会員（選手情報）に紐づく区分。通常・店内アカウント等を持つ。 |
| 店頭PC用アカウント | 顧客グループが店内アカウントの会員。店頭PCでの利用を前提とする。 |
| 店頭フロント区分 | 顧客グループが持つフラグ。立っている場合に対象フロント機能を遮断する。 |
| 許可IPリスト | 店頭用アカウントのアクセスを許可するIPアドレスの一覧。設定値で保持する。 |
| 番号札 | 店頭注文確定時に採番する店内モニター表示用の番号。 |

## 利用者視点の入口

| 入口 | URLエンドポイント | 期待されるふるまい |
|------|--------------------|--------------------|
| 店頭PC用アカウントでの任意のフロントアクセス | 任意の`GET/POST /{_locale}/…`（応答生成後の共通後処理） | 店内アカウントのとき、許可IP以外ならログアウトへリダイレクトする。 |
| 遮断対象フロント機能へのアクセス | 例: `… /{_locale}/mypage/change`、`… /{_locale}/contact`、`… /{_locale}/mypage/delivery`、`… /{_locale}/deckentry/…`、購入・買取系など | 店頭フロント区分の会員のとき、共通エラー画面（店頭用アカウントでは利用できません）を返し本来の画面を表示しない。 |
| 店頭注文の確定 | 購入確定処理（購入機能側） | 店内アカウントの受注では番号札を採番する（通常会員では採番しない）。 |

`/{_locale}`は言語別プレフィックスである。IPによる即時ログアウトは応答生成後の共通後処理で全フロントに作用する。機能別の遮断は各対象機能のコントローラ実行前処理で作用する。

## 処理フロー

### 許可IP以外を即時ログアウトする（応答生成後の共通後処理）

1. ログイン中の利用者が会員かを確認する。会員でなければ何もしない。
2. 当該会員の顧客グループを取得する。
3. 顧客グループが店内アカウントの場合のみIP判定を行う。
4. アクセス端末のIPアドレスを取得する（転送元ヘッダがあればその先頭、無ければ接続元）。
5. 設定の許可IPリストを取得する。リストが空、または端末IPがリストに含まれない場合はログアウトへリダイレクトする。
6. 許可IPに含まれる場合は通常どおり応答を返す。

### 店頭フロント区分の会員を遮断する（対象機能のコントローラ実行前処理）

1. ログイン中の利用者が会員かを確認する。会員でなければ何もしない。
2. 当該会員の顧客グループを取得する。
3. 顧客グループの店頭フロント区分が立っている場合、共通エラー画面を応答として設定し、本来のコントローラ処理に進ませない。
4. 店頭フロント区分が立っていない場合は通常どおり当該機能を実行する。

### 店頭注文時の番号札採番（購入確定処理）

1. 受注を確定する際、会員の顧客グループが店内アカウントかを判定する。
2. 店内アカウントの場合のみ、当該受注に対し番号札を採番して保存する。
3. 店内アカウントでない場合は番号札を採番しない。

## 業務ルール・計算

| 項目 | 内容 |
|------|------|
| 店頭PC用アカウントの識別 | 会員に紐づく選手情報の顧客グループが店内アカウント（顧客グループ区分の店内アカウント）であることをもって識別する。 |
| 許可IPの判定 | 店内アカウントのアクセス時、設定の許可IPリスト（カンマ区切り）に端末IPが含まれるかを判定する。含まれない、またはリストが空なら即時ログアウトする。 |
| 端末IPの取得 | 転送元ヘッダがあればその先頭の値、無ければ接続元を端末IPとして用いる。 |
| 機能遮断の判定 | 顧客グループの店頭フロント区分が立っている会員を、対象フロント機能で遮断する。店内アカウントは当該区分が立つ。 |
| 番号札採番 | 受注確定時に会員が店内アカウントなら番号札を採番する。通常会員では採番しない。 |
| 通常会員との差異 | 通常会員はIP判定・機能遮断の対象外であり、受注確定時に番号札を採番しない。 |

本機能は利用者入力のフォームを持たないため入力項目は無い。

### エッジケース

| ケース | 扱い |
|--------|------|
| 未ログイン・非会員 | IP判定・機能遮断とも何もしない。 |
| 店内アカウントだが許可IPリストが空 | 即時ログアウトする。 |
| 店内アカウントで許可IP内から遮断対象外の機能へアクセス | 通常どおり利用できる。 |
| 店内アカウントが遮断対象機能へアクセス | 共通エラー画面を返す。 |

## DBカラム

機能に直接関係する列のみ記載する。型や一覧の細部はスキーマを参照する。

| テーブル | 列 | メモ |
|---------|-----|------|
| `dtb_customer_group` | （店内アカウント識別の区分） | 店頭PC用アカウントの識別に用いる。ec-cube-enterpriseに明示の区分列が見当たらず、`shop_front_flg`または顧客グループ値での判定かはec-cube-enterprise実装で要確認。 |
| `dtb_customer_group` | `shop_front_flg` | 店頭フロント区分。立っている場合に対象フロント機能を遮断する。店内アカウントは立つ。支店向けは`branch_shop_front_flg`。 |
| `dtb_player` | `customer_group_id` | 会員（選手情報）から顧客グループを引くために使う。 |
| `mtb_option` | `option_key`=`otc_account_ip`／`option_value` | 許可IPリスト（カンマ区切り）を保持する。 |
| `dtb_waiting_number` | （受注に紐づく行） | 店内アカウントの受注確定時に番号札を採番・保存する。ec-cube-enterpriseでは拠点参照`base_info_id`を持つ。 |

### DB操作

永続化の正は ec-cube-enterprise（テーブル名・操作は ec-cube-enterprise を正典）。当ドメインは承認ワークフローを介さず persist/flush で直接確定する（承認ワークフローは在庫機能固有）。

| 操作種別 | 対象テーブル | 契機・条件 |
|---------|--------------|------------|
| 登録/更新 | dtb_customer_group / dtb_player / dtb_waiting_number / mtb_option | 当機能が行う登録・更新で対象テーブルを直接保存する（不要な削除は含まない）。確定は persist/flush による即時反映。DB=ec-cube-enterprise を正典とする。 |

## 権限・認可

| 利用者状態 | フロントアクセスの可否 |
|------------|------------------------|
| 未ログイン・非会員 | 本機能の制御対象外。通常の認可に従う。 |
| 通常会員 | IP判定・機能遮断の対象外。受注確定で番号札を採番しない。 |
| 店頭PC用アカウント（許可IP内・非遮断機能） | 利用できる。受注確定で番号札を採番する。 |
| 店頭PC用アカウント（許可IP外） | 即時ログアウトする。 |
| 店頭PC用アカウント（遮断対象機能） | 共通エラー画面を返し利用できない。 |

遮断対象には会員情報変更・退会・配送先登録・お問い合わせ・パスワード再発行・入荷通知一覧・ポイント履歴・購入履歴・配送変更・購入手続き・デッキ登録・買取などのフロント機能が含まれる（コントローラ実行前処理で遮断）。

## 排他制御・トランザクション

本機能はアクセス制御が主であり、店内アカウント受注確定時の番号札採番は購入確定処理のトランザクションに含まれる。本機能では楽観ロック・悲観ロックの対象は持たない。
