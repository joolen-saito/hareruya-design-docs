# F06-01（仮会員登録）

## 概要

新規会員登録は、未ログインの利用者が会員情報を入力し、確認画面を経て仮会員として登録したうえで、登録したメールアドレス宛に本会員化（アクティベート）用のURLを記載した仮会員登録完了メールを送信する機能である。本店からの登録に加え、支店から会員登録画面へ遷移した場合は遷移元の店舗名をセッションに記録する。入力・確認・仮登録・完了メール送信までを本書の範囲とし、メールのURLを開いて本会員へ昇格するアクティベート処理は別機能（本会員登録）を正とする。

本書は実装手順ではなく、誰が・いつ・どの条件で・結果どうなるかを読むためのリバース詳細設計とする。確認値はpf-eccube3（EC-CUBE3系）のHareruyaEcプラグインの会員登録処理、会員登録テンプレート（`Entry/index.twig`・`Entry/confirm.twig`・`Entry/complete.twig`と各英語版`*.en.twig`）、会員登録完了画面、会員登録フォーム種別とその拡張、ブラックリスト判定、仮会員登録完了メール送信処理を正とする。

本機能のカスタマイズ区分はカスタマイズで、画面・処理フローの挙動は現行リポ（pf-eccube3）を参照し、DB関連（テーブル名・列名・保存先）は ec-cube-enterprise を正とする。本機能は言語切替で英語表示へ到達できるため、表示メッセージに英語文言を併記する。

対象はブラウザ経由のフロント（会員登録）に限定する。フロントのページは言語別パスセグメント`/{_locale}`を前提とし、本書のパスは`/{_locale}`配下の確認値として記載する。実装上のルート登録はサイトルート直下であり、言語セグメントの付与はフロント共通のロケール処理に従う。

本文ではフレームワークのコントローラ型名やメソッド名を主説明としない。ルートbind名の網羅は主説明とせず、「利用者視点の入口」にHTTPメソッドとサイトルートからのパスパターンを書く。コード探索でbind名が必要なときだけ「調査補助」へ書く。

## 本書で扱うこと

- 会員登録画面・会員登録確認画面・仮会員登録完了画面の入口と画面遷移
- 入力フォームの項目・必須・最大長・初期値と保存先
- 確認から仮登録（complete）までの判定順序と副作用
- 支店から遷移した場合の店舗名のセッション記録
- ブラックリスト該当時の遷移
- 仮会員設定（仮会員を経るか否か）による完了後の分岐
- 利用者に表示するメッセージ

## 用語

| 用語 | 説明 |
|------|------|
| 仮会員 | 入会申込はしたが本会員化前の会員。ログイン不可の状態。 |
| 本会員 | アクティベート済みでログイン可能な会員。 |
| 秘密キー | 会員ごとに発行される一意のキー。アクティベートURLに含む。 |

| 仮会員設定 | 店舗基本情報の設定。有効な場合は仮会員登録完了メールを送り完了画面を表示し、無効な場合は登録後すぐ本会員化URLへ遷移させる。 |
| ブラックリスト | 会員登録を拒否する対象を登録したリスト。該当時は登録エラー画面へ遷移する。 |

| 入口 | URLエンドポイント | 期待されるふるまい |
|------|--------------------|--------------------|
| 会員登録画面 | `GET /{_locale}/entry` | 会員情報入力フォームを表示する。支店からの遷移時は店舗名をセッションに記録する。 |
| 「同意する」ボタン（確認へ） | `POST /{_locale}/entry`（`mode=confirm`） | 入力を検証し、問題なければ確認画面を表示する。検証エラー時は入力画面を再表示する。 |
| 「登録する」ボタン（仮登録実行） | `POST /{_locale}/entry`（`mode=complete`） | 会員・住所・選手情報を作成し、仮会員設定に応じて完了画面または本会員化URLへ遷移する。 |
| 確認画面の「戻る」ボタン | `POST /{_locale}/entry`（`mode=back`） | 入力画面へ戻る。 |
| 仮会員登録完了画面 | `GET /{_locale}/entry/complete` | 仮会員状態である旨と本会員登録の案内を表示する（仮会員設定が有効なときの遷移先）。 |

| 観点 | 内容 |
|------|------|
| 表示要素 | 会員登録画面は見出し「会員情報登録」と入力フォーム（お名前、お名前（フリガナ）、電話番号、FAX、メールアドレス、メールアドレス（確認）、国、郵便番号、住所、パスワード、パスワード（確認）、生年月日、性別、会社名、職業、MTG Companion登録名）、「同意する」ボタン、トップへ戻るリンク。確認画面は見出し「会員情報登録確認」と入力値の確認表示、「登録する」「戻る」ボタン。完了画面は見出し「新規会員登録（完了）」と仮会員状態・本会員登録の案内。 |
| JS挙動 | ログインID（メールアドレス）とパスワードが一致する場合は送信を成立させない判定を持つ。郵便番号・住所などの入力補助は共通フォーム部品に従う。本機能固有の非同期取得は扱わない。 |
| CSS・レイアウト | 必須項目にはチェック画像（`alt="必須"`）を付す。利用者の挙動理解に影響する分岐表示は、国の選択に応じた郵便番号・都道府県欄の表示切替である。 |

国の選択により入力欄が変わる。日本以外（または海外を示す都道府県）の場合は、3分割の郵便番号欄に代えて単一の郵便番号欄（`zipcode`）を表示し、都道府県欄を隠す。日本の場合は3分割郵便番号欄を表示する。

## 処理フロー

### 会員登録画面を表示する（GET `/{_locale}/entry`）

1. 新規の会員情報を生成し、会員登録フォームを組み立てる。国コードは送信値またはクエリから決める。
2. クエリ`shop`がある場合、その店舗名を支店用セッションキーに記録する。
3. `isChange`指定時、またはフォームが送信状態でない・検証に通らない場合は、会員登録画面（`Entry/index.twig`）を表示する。

### 確認画面を表示する（POST `mode=confirm`）

1. 送信フォームを検証する。
2. ログインID（メールアドレス）とパスワードが一致する場合は登録へ進まず、会員登録画面を再表示する。
3. 検証に通った場合になりすまし対策トークンを再生成する。
4. フォームを確定表示（freeze）に組み替え、確認画面（`Entry/confirm.twig`）を表示する。

### 仮登録を実行する（POST `mode=complete`）

1. 送信フォームを検証する。検証エラー時・ID＝パスワード時は会員登録画面を再表示する。
2. ソルトを生成し、パスワードを暗号化し、一意の秘密キーを採番し、国を設定する。
3. ブラックリストに該当する場合は登録を行わず、登録エラー画面へリダイレクトする。
4. 会員住所・住所サブ・選手情報を作成する。海外の場合は住所に郵便番号を設定する。
5. 会員・会員住所・住所サブ・選手情報を保存して確定する。
6. 支店システムへ当該会員の更新を通知する。
7. 仮会員設定が有効な場合は仮会員登録完了メールを送信し、仮会員登録完了画面（`/{_locale}/entry/complete`）へリダイレクトする。
8. 仮会員設定が無効な場合は本会員化URL（`/{_locale}/entry/activate/{secret_key}`）へリダイレクトする。

### 仮会員登録完了画面を表示する（GET `/{_locale}/entry/complete`）

1. 仮会員状態である旨と、メール内のURLから本会員登録を行う案内を表示する。

---

## 仮登録実行時の判定順序

| 順序 | 判定 | 結果 |
|------|------|------|
| 1 | フォーム検証に通るか | 通らないなら会員登録画面を再表示する |
| 2 | ログインID（メールアドレス）とパスワードが同一でないか | 同一なら登録へ進まず会員登録画面を再表示する |
| 3 | ブラックリストに該当しないか | 該当するなら登録せず登録エラー画面へリダイレクトする |
| 4 | 上記を通過 | 会員・住所・選手情報を作成・確定し、支店連携後に仮会員設定に応じて完了画面または本会員化URLへ遷移する |
| 5 | 仮会員設定が有効か | 有効なら仮会員登録完了メールを送信し完了画面へ。無効なら本会員化URLへ遷移する |

| ID＝パスワードの禁止 | メールアドレスとパスワードが同一の場合は登録へ進めない。 |
| ブラックリスト判定 | 仮登録実行時に会員情報がブラックリストに該当するかを判定し、該当時は登録せず登録エラー画面へ遷移する。 |
| 仮会員設定による分岐 | 仮会員設定が有効なら完了メールを送り完了画面を表示する。無効なら登録後すぐ本会員化URLへ遷移し本会員化を行わせる。 |
| 秘密キー | 仮登録時に一意の秘密キーを採番し、本会員化URLに用いる。 |
| 選手情報の同時作成 | 会員作成時に選手情報を同時作成し、氏名（日本語・英語）・メールアドレスを設定する。 |
| 支店からの遷移 | クエリ`shop`がある場合、店舗名を支店用セッションキーに記録する。 |
| 業務計算 | 本機能では金額・件数・在庫などの業務計算を行わない。 |

### 入力項目

| 項目名 | 必須／任意 | 最大長 | 初期値 | 保存先・扱い |
|--------|------------|--------|--------|----------------|
| お名前 | 必須 | 姓名各欄は氏名用フォーム部品の上限に従う | 空 | `dtb_customer`の姓（`name01`）・名（`name02`）。フォームキー`name`。選手情報の日本語姓名にも設定する。 |
| お名前（フリガナ） | 必須 | カナ用フォーム部品の上限に従う | 空 | `dtb_customer`のカナ（`kana01`／`kana02`）。フォームキー`kana`。 |
| 電話番号 | 必須 | 電話番号3分割用フォーム部品の各欄上限に従う | 空 | `dtb_customer`の電話番号。フォームキー`tel`。 |
| FAX | 任意 | 電話番号3分割用フォーム部品の各欄上限に従う | 空 | `dtb_customer`のFAX番号。フォームキー`fax`。 |
| メールアドレス | 必須 | メール用フォーム部品の上限に従う（再入力一致を要する） | 空 | `dtb_customer`のメールアドレス（`email`）。フォームキー`email`（確認再入力を含む）。選手情報のメールにも設定する。 |
| メールアドレス（確認） | 必須 | 同上 | 空 | メールアドレスとの一致を検証する。不一致は「同じメールアドレスを入力してください。」。 |
| 国 | 必須 | 選択（国マスタ） | 日本語表示時は日本、英語表示時は未選択 | フォームキー`country`。都道府県との整合を検証する。海外の場合は単一郵便番号欄を表示する。 |
| 郵便番号 | 必須 | 日本は3＋4桁の分割欄、海外は郵便番号欄（住所サブの郵便番号長設定に従う） | 空 | フォームキー`zip`（日本）または`zipcode`（海外）。海外時は会員住所の郵便番号へ設定する。 |
| 住所 | 必須 | 住所用フォーム部品の上限に従う | 空 | `dtb_customer`の都道府県（`pref_id`。現行は`pref`）・住所（`addr01`／`addr02`）。フォームキー`pref`・`addr01`・`addr02`。 |
| パスワード | 必須 | パスワード用フォーム部品の上限に従う（再入力一致を要する） | 空 | `dtb_customer`のパスワード（`password`）・ソルト（`salt`）。フォームキー`password`。ソルトで暗号化した不可逆値のみ保存する。原値を記載しない。 |
| パスワード（確認） | 必須 | 同上 | 空 | パスワードとの一致を検証する。不一致は「同じパスワードを入力してください。」。 |
| 生年月日 | 必須 | 年・月・日の選択（年は当年から所定年数前まで） | 未選択 | `dtb_customer`の生年月日（`birth`）。フォームキー`birth`。未来日を不可とする。 |
| 性別 | 任意 | 選択（性別マスタ） | 未選択 | `dtb_customer`の性別（`sex_id`。現行は`sex`）。フォームキー`sex`。 |
| 会社名 | 任意 | 短文用の最大長（`stext_len`の確認値、既定255文字） | 空 | `dtb_customer`の会社名（`company_name`）。フォームキー`company_name`。 |
| 職業 | 任意 | 選択（職業マスタ） | 未選択 | `dtb_customer`の職業（`job_id`。現行は`job`）。フォームキー`job`。 |
| MTG Companion登録名 | 任意 | 各欄128文字 | 空 | 会員本体には保存せず、選手情報の英語姓名（`first_name_en`／`last_name_en`）として保存する。フォームキー`first_name_en`・`last_name_en`。 |

最大長は各共通フォーム部品の上限に従う。具体文字数は`src/Eccube/Resource/config/constant.yml.dist`の該当キー（`stext_len`・`mtext_len`等）を確認値とする。MTG Companion登録名は会員登録フォーム拡張で追加され、各128文字の上限を持つ。

### エッジケース

| ケース | 扱い |
|--------|------|
| メールアドレスとパスワードが同一 | 登録へ進めず会員登録画面を再表示する。 |
| ブラックリストに該当 | 会員を作成せず登録エラー画面へリダイレクトする。 |
| 国と都道府県の不整合 | 国欄に整合エラーを表示し登録しない。 |
| 海外の国を選択 | 3分割郵便番号欄に代えて単一郵便番号欄を表示し、会員住所へ郵便番号を設定する。 |
| 仮会員設定が無効 | 完了画面を経ず、登録後すぐ本会員化URLへ遷移する。 |
| `mode`が`confirm`・`complete`・`back`以外 | いずれの分岐にも入らず会員登録画面を表示する。 |

| 観点 | 内容 |

| 会員・住所・選手情報 | 仮登録実行時、会員・会員住所・住所サブ・選手情報を同一トランザクションで保存・確定する。 |

### DB操作

永続化の正は ec-cube-enterprise（テーブル名・操作は ec-cube-enterprise を正典）。当ドメインは承認ワークフローを介さず persist/flush で直接確定する（承認ワークフローは在庫機能固有）。

| 操作種別 | 対象テーブル | 契機・条件 |
|---------|--------------|------------|
| 登録/更新 | dtb_customer / dtb_player | 当機能が行う登録・更新で対象テーブルを直接保存する（不要な削除は含まない）。確定は persist/flush による即時反映。DB=ec-cube-enterprise を正典とする。 |

## 画面遷移

| 条件 | 遷移先 |
|------|--------|
| 会員登録画面の表示 | 会員登録画面（`GET /{_locale}/entry`） |
| 「同意する」押下（`mode=confirm`）・検証通過 | 会員情報登録確認画面（同一URL再描画） |
| 「同意する」押下・検証エラー | 会員登録画面（エラー付き再描画） |
| 「戻る」押下（`mode=back`） | 会員登録画面 |
| 「登録する」押下（`mode=complete`）・仮会員設定有効 | 仮会員登録完了画面（`/{_locale}/entry/complete`へリダイレクト） |
| 「登録する」押下・仮会員設定無効 | 本会員化URL（`/{_locale}/entry/activate/{secret_key}`へリダイレクト） |
| ブラックリスト該当 | 登録エラー画面（`/{_locale}/entry/regist_error`へリダイレクト） |
| 完了画面・会員登録画面のトップへ戻るリンク | 支店指定があれば支店トップ、なければ本店トップ |

### 遷移時に引き継ぐ状態

| 起点 | 遷移前の処理 | 遷移後の初期状態 |
|------|--------------|------------------|
| 支店から会員登録画面へ遷移 | クエリ`shop`の店舗名を支店用セッションキーに記録する | 完了画面のトップへ戻る先を支店トップに切り替える |

- 秘密キーの完全値
- なりすまし対策トークン
- Cookie値
- セッションIDの完全値

## 排他制御・トランザクション

仮登録実行時の会員・会員住所・住所サブ・選手情報の作成は同一トランザクションで確定する。本機能では楽観ロック・悲観ロックの対象は持たない。
