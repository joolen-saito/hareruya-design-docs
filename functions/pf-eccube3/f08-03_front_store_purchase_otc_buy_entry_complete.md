# F08-03（店頭買取査定申込登録確認〜完了）

## 概要

店頭買取の査定申込みにおいて、入力された申込情報を確認し、必要に応じて会員仮登録を行い、査定申込みを登録して査定番号を付与し、完了画面を表示する機能である。確認画面の表示、メールアドレスの重複・パスワード一致のチェック、適格請求書発行事業者の登録番号検証、申込登録、完了表示までを扱う。申込情報の入力自体はF08-02（店頭買取査定申込情報入力）が扱う。

本書は実装手順ではなく、誰が・いつ・どの条件で・結果どうなるかを読むためのリバース詳細設計とする。確認値はpf-eccube3（EC-CUBE3系）のHareruyaEcプラグインの店頭買取査定申込処理、テンプレート（`OtcBuy/confirm.twig`・`OtcBuy/complete.twig`と各英語版`*.en.twig`）、査定申込・会員登録・状態履歴の各処理を正とする。

本機能のカスタマイズ区分はカスタマイズで、画面・処理フローの挙動は現行リポ（pf-eccube3）を参照し、DB関連（テーブル名・列名・保存先）は ec-cube-enterprise を正とする。本機能は言語切替で英語表示へ到達できるため、表示メッセージに英語文言を併記する。

対象はブラウザ経由のフロント（店頭買取査定申込）に限定する。フロントのルートはロケールセグメント付きで提供され、サイトルートからのパスパターンは`/{_locale}`配下になる（`/{_locale}`はサービスプロバイダのマウントで決まる確認値）。店舗は申込ページのパス内の店舗識別名（`{name}`）で特定する。

コントローラのメソッド単位の解剖は本文の主題としない。本文ではルートbind名の網羅を主説明とせず、「利用者視点の入口」にHTTPメソッドとサイトルートからのパスパターンを書く。

## 処理フロー

### 確認・登録する（`/{_locale}/otcbuy/{name}/confirm`）

1. 店舗を特定する。無ければ404とする。
2. セッションの入力データとリクエストの入力データをマージし、申込フォームと適格請求書発行事業者フォームを組む。
3. 適格請求書発行事業者が「はい」かつ登録番号が不正なら、申込フォーム画面を再表示する。
4. エントリー開始かつ申込フォーム送信でない、かつ登録番号未送信などの前提を満たさないときはエントリーへ戻す。
5. メールアドレスが入力されている場合、既登録メールか、メールとパスワードが同一かを判定する。いずれかに該当すれば会員登録フォーム画面を該当フラグ付きで再表示する。
6. 確認モードのときは、フォームを表示専用（freeze）で組み直し、確認画面を表示する。
7. 会員登録モードのときは会員仮登録を実行し、登録結果（成功・失敗）を保持する。
8. エントリーフラグをセッションから除去する。
9. 申込みに状態（完了前）・成年フラグ・申込日・更新日・店舗を設定する。氏名カナが無ければ氏名で補完する。国が日本以外なら都道府県を国外に設定する。
10. 適格請求書発行事業者の登録番号があれば申込みへ紐づけ、自由記述に所定コメントを付加して登録する。
11. ログイン中なら会員IDを申込みへ設定する。
12. 申込テーブルをロックし、査定番号（申込日・店舗ID・連番）を採番して申込みを登録し、ロックを解除する。
13. 状態履歴に完了前の状態を記録する。
14. 査定IDをセッションへ保存し、完了画面へ遷移する（会員登録ありのときは登録結果をクエリに付ける）。

### 完了を表示する（`/{_locale}/otcbuy/{name}/complete`）

1. セッションから査定IDを取得する。無ければエントリーへ戻す。
2. セッションの査定IDを除去する。
3. 査定IDから申込みを取得し、自動遷移の秒数（オプション値）を取得する。
4. 完了画面を表示する。会員登録の結果はクエリから受け取る。

## `査定申込み確認・登録` 時の判定順序

| 順序 | 判定 | 結果 |
|------|------|------|
| 1 | 店舗が存在するか | 無ければ404 |
| 2 | 適格請求書発行事業者ありで登録番号が妥当か | 不正なら申込フォーム画面を再表示 |
| 3 | エントリー開始かつ申込フォーム送信などの前提を満たすか | 満たさなければエントリーへ戻す |
| 4 | メールが既登録か、メールとパスワードが同一か | 該当すれば会員登録フォーム画面を再表示 |
| 5 | 確認モードか | 確認モードなら確認画面を表示 |
| 6 | 会員登録モードか | 会員仮登録を実行し結果を保持 |
| 7 | 上記を通過 | 申込みを登録し、査定番号を採番して完了画面へ遷移 |

## 業務ルール・計算

| 項目 | 内容 |
|------|------|
| 店舗特定 | パスの店舗識別名から店舗を特定する。無ければ404とする。 |
| 入力データのマージ | セッションの入力データとリクエストの入力データをマージして確認・登録に用いる。 |
| メール重複 | 入力メールが既登録なら会員仮登録できないものとして会員登録フォームへ差し戻す。 |
| メールとパスワード同一 | 同一なら会員登録フォームへ差し戻す。 |
| 成年判定 | 生年月日から成年・未成年を判定し成年フラグへ設定する。未成年は完了画面で保護者同意書を案内する。 |
| 氏名カナ補完 | 氏名カナが無い場合は氏名で補完する。 |
| 都道府県の国外設定 | 国が日本以外のときは都道府県を国外に設定する。 |
| 適格請求書発行事業者 | 登録番号があれば申込みへ紐づけ、自由記述に所定コメントを付加する。 |
| 査定番号 | 申込日（年月日）・店舗ID（2桁）・連番を連結して採番する。採番中は申込テーブルをロックする。 |
| 状態 | 登録時に完了前の状態を付け、状態履歴に記録する。 |
| 会員仮登録 | 会員登録モードのときに実行する。ブラックリスト該当なら登録しない。 |

入力項目の一覧と各検証はF08-02を正とする。本機能は確認・判定・登録の判定境界を扱う。

## データ整合性

| 観点 | 内容 |
|------|------|
| 入力とセッション | 確認・登録は、F08-02でセッションへ保存した入力データとリクエストをマージして用いる。 |
| 査定IDの一回性 | 登録時に査定IDをセッションへ保存し、完了画面で取得後に除去する。再表示時は査定IDが無くエントリーへ戻る。 |

| 状態履歴 | 申込登録と同時に完了前の状態を履歴へ記録する。 |
| 会員登録と連携 | 会員仮登録が成功した場合、関連情報の登録と支店システムへの連携、確認メール送信を行う（詳細は別機能）。 |

### DB操作

永続化の正は ec-cube-enterprise（テーブル名・操作は ec-cube-enterprise を正典）。当ドメインは承認ワークフローを介さず persist/flush で直接確定する（承認ワークフローは在庫機能固有）。

| 操作種別 | 対象テーブル | 契機・条件 |
|---------|--------------|------------|
| 登録/更新 | dtb_customer / dtb_otc_buy_order / dtb_otc_buy_order_status_history / dtb_qualified_invoice_issuer_account | 当機能が行う登録・更新で対象テーブルを直接保存する（不要な削除は含まない）。確定は persist/flush による即時反映。DB=ec-cube-enterprise を正典とする。 |

## 画面遷移

| 条件 | 遷移先 |
|------|--------|
| 店舗識別名が該当なし | 404 |
| 登録番号が不正 | 申込フォーム画面（再表示） |
| エントリー前提を満たさない | エントリー画面 |
| メール既登録／メールとパスワード同一 | 会員登録フォーム画面（再表示） |
| 確認モード | 確認画面 |

| 確認画面の「戻る」 | 申込フォーム |
| 完了画面に査定IDなし | エントリー画面 |

### 遷移時に引き継ぐ状態

| 起点 | 遷移前の処理 | 遷移後の初期状態 |
|------|--------------|------------------|

| 完了表示 | セッションの査定IDを除去する | 完了画面の再訪・自動遷移時は査定IDが無くエントリーへ戻る |

## 排他制御・トランザクション

査定番号の採番時に申込テーブルをロックし、採番後にロックを解除する。これにより連番の整合を取る。本機能では楽観ロックの版情報を画面に持たない。
