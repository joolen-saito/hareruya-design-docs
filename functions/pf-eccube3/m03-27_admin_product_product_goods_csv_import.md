# m03-27_admin_product_product_goods_csv_import（管理画面_商品管理_グッズ商品CSV登録）

## 概要

管理画面の「商品管理」配下「商品CSV管理」から開く「グッズ商品CSV登録」（画面ラベルは翻訳キー `admin.product.product_goods_csv_upload`、日本語確認値は「グッズ商品CSV登録」）は、雛形 CSV のダウンロード・UTF-8 想定の列定義に沿ったファイルのアップロード・取込履歴の閲覧を 1 画面で扱う。取込処理はサプライ・グッズ・予約グッズ・情報商材向けのカテゴリ区分を列で受け取り、商品本体・規格・カテゴリ・タグ・画像・価格履歴・在庫枠などを更新または新規作成する。コントローラ上のログ文言は「グッズ・サプライ・情報商材」と総称している。

本書は実装手順ではなく、誰が・いつ・どの条件で・結果どうなるかを読むためのリバース詳細設計とする。確認値は ec-cube-enterprise の `src/Eccube` 配下とする。

本機能のカスタマイズ区分はカスタマイズである。現行挙動は pf-eccube3（HareruyaEc プラグイン）を参照し、永続化に関わるテーブル名・列名などのDB関連は ec-cube-enterprise を正とする。

対象はブラウザ経由の管理画面に限定する。グッズ商品の CSV ストリーム出力は別ルート（設計書 `m03-04_admin_product_product_goods_csv_export.md`）を正とする。

コントローラのメソッド名は本文の主題としない。本文ではルートbind名やSymfonyのルートnameの網羅は主説明としない。「利用者視点の入口」にHTTPメソッドとサイトルートからのパスパターンを書く。コード探索でbind名が必要なときだけ「調査補助」へ書く。

## 処理フロー

### アップロード画面を表示する（GET `m03-27_admin_product_product_goods_csv_import`）

1. 管理画面の認証・共通制約を通過する。
2. フォーム種別 `admin_csv_import`（クラス `CsvImportType`）でフォームを生成し、`handleRequest` する（GET では未送信）。
3. クエリ `page_count` またはセッションキー `admin.product.product_goods_csv.page_count` から表示件数を解決する。既定 10。指定可能値はコントローラ定数どおり 10, 50, 100, 300, 500, 1000, 2000, 10000, 12000。不正値は 10 に落とす。クエリで有効値が来たときだけセッションへ保存する。
4. クエリ `page_no` またはセッションキー `admin.product.product_goods_csv.page_no` からページ番号を解決し、セッションへ保存する。
5. `mtb_csv_import_type.id = 2` の取込履歴を作成日時降順でページネーション取得する。
6. `getCsvHeaderForTemplateDownload()` でフォーマート表用の「項目名→説明」連想配列を渡し、必須キー一覧は `getRequiredCsvHeaderLabels()`、POST 先ルート名、雛形ルート名、履歴ページ用ルート名などをテンプレートへ渡して描画する。

### 雛形をダウンロードする（GET `admin_product_goods_csv_template`）

1. 管理画面の認証・共通制約を通過する。
2. `csvTemplateStreamedResponse` により、`getCsvHeader()` のキー順で 1 行目のみを書き出すストリーム応答を返す。`Content-Type` は `application/octet-stream`、ファイル名は `product_goods.csv`。説明文の列はファイルには含めず、キー（日本語列名）のみが 1 行目に並ぶ。

### CSV を取り込む（POST `admin_product_goods_csv_upload`）

1. 管理画面の認証・共通制約を通過する。
2. PHP の実行時間制限を解除する（`set_time_limit(0)`）。
3. ログイン利用者を取得し、フォーム種別 `admin_csv_import` で `handleRequest` する。
4. フォームが妥当でなければ各エラーを管理者向けフラッシュエラーに積み、`m03-27_admin_product_product_goods_csv_import` へリダイレクトする。
5. `import_file` が無ければキー `admin.common.csv_invalid_format` をフラッシュし、同上へリダイレクトする。
6. アップロード内容の改行ベース概算行数が `5010` 以上なら（抽象コントローラ定数 `ADMIN_CSV_IMPORT_MAX_ROWS`）、`admin.csv.error.upload.maxrecord` をフラッシュし、同上へリダイレクトする。
7. 情報ログ「グッズ・サプライ・情報商材CSV登録開始」を出す。
8. 取込ハンドラ（グッズ商品 CSV 用）と共通 `CsvImporter` を生成し、ログイン利用者を渡して `import` する。ファイルは一時ディレクトリ（`eccube_csv_temp_realdir`）へ移動され、拡張子が `tsv` のとき区切りはタブ、それ以外は設定 `eccube_csv_import_delimiter`（配布確認値はカンマ）。囲み文字は `eccube_csv_import_enclosure`。
9. `import` 内では、`CsvImportService` で 1 行目をヘッダとして読めること、2 行目以降にデータがあることを事前検証する。失敗時はエラー配列のみ返し DB は触れない。
10. 事前検証を通過したら DB トランザクションを開始し、行ロックタイムアウトをハンドラの値（既定 5 秒）に設定する。データ行ごとに列数一致・各列バリデーション・行バリデータ（価格整合、スマレジ条件付き必須、廃止時在庫、スマレジ OFF 時在庫など）を実行する。`breakAll` のとき処理を打ち切り、`skipRow` のとき当該行のみスキップする。
11. 行処理では商品本体の INSERT/UPDATE、カテゴリ差し替え、タグ差し替え、規格の INSERT/UPDATE、規格画像差し替え（指定時）、売上分析タグ差し替え、価格履歴追加、新規規格時の店舗×在庫場所の在庫行初期化などを行う。100 行境界で ORM の flush と clear が走る（`CsvImporter::DEFAULT_FLUSH_PER_LINES`）。ループ後に再度 flush/clear する。
12. トランザクションの成否は `CsvImporter` 内の判定式に従う（メッセージストアのエラー件数と `breakAll` の有無の組み合わせ）。コミットされた場合のみ `onAfterImport` が成功扱いとなり、スマレジ連携コーディネータの取込後処理が成功フラグ付きで呼ばれる。失敗時はロールバックし、コーディネータは失敗フラグで呼ばれる。
13. 取込結果にエラーメッセージ配列があれば「異常終了」ログと各メッセージをフラッシュに積む。無ければ成功フラッシュ `admin.common.csv_upload_complete`、取込履歴 INSERT（種別 ID 2、クライアント側ファイル名、作業者 ID）、情報ログに件数を出す。
14. いずれにせよ `m03-27_admin_product_product_goods_csv_import` へリダイレクトする。

## 取込時の判定順序（概要）

| 順序 | 判定 | 結果 |
|------|------|------|
| 1 | フォーム妥当性・ファイル必須 | 失敗時はエラーフラッシュしアップロード画面へリダイレクト。 |
| 2 | 概算行数が 5010 未満か | 以上なら最大行超過メッセージでリダイレクト。 |
| 3 | ヘッダ行・データ行の存在（`CsvImporter` 事前検証） | 失敗時はエラーをフラッシュ。DB 変更なし。 |
| 4 | 各行の列数・列バリデーション・行バリデータ | `breakAll` なら打ち切り。 |
| 5 | 行ごとの存在チェック（商品 ID 更新時の存在・規格件数・新規時の商品コード重複など） | 不整合は `skipRow` とメッセージが多い。 |
| 6 | トランザクションコミット可否（`CsvImporter` の式） | 失敗時ロールバック。コントローラは結果の `hasError()` で成功フラッシュ・履歴挿入の可否を決める。 |

## 業務ルール・計算

| 項目 | 内容 |
|------|------|
| 商品カテゴリ | マップ上、サプライ・グッズ・予約グッズ・情報商材系のカテゴリ ID に制限する選択検証を付ける。対象 ID 集合が空のときは必須化・選択検証を付けない分岐がある。登録時は指定カテゴリに加え祖先カテゴリを付与する（画面登録と同様の経路）。 |
| 商品規格の状態区分 | グッズ商品はカード状態が「ニアミント」固定で新規規格 INSERT に用いる。 |
| 価格 | CSV の販売・買取・基準価格は文字列から固定小数の床関数で整数化する。 |
| セール中規格の販売価格 | 既存規格の `sale_flg` が有効のとき、UPDATE では CSV の販売価格の代わりに基準価格で `price02` を上書きする。 |
| 商品公開ステータスとスマレジ | ステータスが非公開または廃止のとき、スマレジ連携フラグを無効に強制する。 |
| 規格画像 | 列が空または未指定のときは画像を差し替えない。指定時は日本語固定の規格画像差し替え API を呼ぶ。 |
| 新規規格 | 店舗マスタ（公開中）×在庫場所の直積だけ `dtb_product_stock` 行を 0 在庫で作る。 |

本機能では締め日や税計算の業務ループは行わない。

### CSV列（1行目の日本語ヘッダ名と役割）

コントローラ `getCsvHeader()` の行列順を正とする。説明欄はフォーマット表に表示され、雛形ファイルの 1 行目には列名のみが出力される。規格テーブルへのマッピングは取込ハンドラの実装に従い、次のとおり抜けがある。

| 列名（1行目） | 必須（フォーマット表） | 処理上の要点 |
|---------------|-------------------------|----------------|
| 商品ID | 任意（説明: 新規は空、更新時必須） | 値があるとき既存商品 UPDATE。空なら新規商品 INSERT。存在しない ID はエラーで全体中断。 |
| 商品コード | 必須 | 新規時は既存規格コードと重複不可。規格 INSERT/UPDATE のコードに用いる。 |
| 言語(ID) | 必須 | 規格の言語に保存。 |
| 商品公開ステータス | 必須 | 商品ステータス。値は説明表の通り公開・非公開・廃止の区分。 |
| 支店の商品公開ステータス | 必須 | 0/1 の支店公開。 |
| 商品名(日)／商品名(英) | 必須 | 商品名（日英）。 |
| サイズ／重量 | 必須 | サイズ文字列・重量（グラム）。 |
| 商品説明(日)／商品説明(英)／買取商品説明(日)／買取商品説明(英) | 任意 | 商品説明系。 |
| 検索ワード | 任意 | 検索用テキスト。 |
| 規格画像 | 任意 | ファイル名の列挙。空なら画像更新なし。 |
| 商品カテゴリ(ID) | 必須（実装上、有効カテゴリ集合が空のときは必須化されない） | 2・4・5 系の区分 ID。複数はカンマ。 |
| 購入グループ名称 | 必須 | 名称で購入グループを引き、商品へ関連付ける。 |
| 略称タグ(ID) | 任意 | 略称タグ。 |
| 売上分析タグ(ID) | 任意 | 複数はカンマ。 |
| タグ(ID) | 任意 | 複数はカンマ。 |
| 発送日目安(ID) | 任意 | 列定義・検証はあるが、当ハンドラの規格 INSERT/UPDATE 引数には載らず、`dtb_product_class` の発送目安へは反映されない（実装確認値）。 |
| カードセット(ID) | 任意 | 商品側のカードセット ID。 |
| 販売制限数 | 任意 | 規格の販売制限。 |
| 基準価格／販売価格／買取価格 | 必須 | 規格の価格。行バリデータで販売と買取の整合を検証。 |
| 地域別販売制限 | 任意 | 0 または空は日英両サイト、1 は日本語のみ、2 は英語のみの説明がコントローラに付く。 |
| スマレジ連携フラグ／スマレジ商品コード／部門ID | 条件付き必須 | 連携 ON 時は商品コード・部門が必須になる行バリデータを通す。 |
| フリーエリア | 任意 | 商品フリーエリア。 |

### エッジケース

| ケース | 扱い |
|--------|------|
| 更新対象の商品 ID が存在しない | エラーメッセージを積み `breakAll`。トランザクションはロールバック方向。 |
| 更新対象商品の規格がちょうど 1 件でない | 当該行を `skipRow`（他行は続行され得る）。 |
| 新規で商品コードが既存と重複 | 当該行 `skipRow`。 |
| スマレジ商品コードの一意制約違反 | 当該行 `skipRow`。 |
| カード詳細や割引 ID など既存商品の付帯情報 | 更新時は既存の値を引き継ぎ、CSV からは変更しない。 |

## データ整合性

| 観点 | 内容 |
|------|------|
| 一覧・詳細との一致 | 取込直後の一覧表示は別画面の検索条件・キャッシュに依存する。本画面は CSV 取込後の即時一覧整合を保証しない。 |

### DB操作

永続化の正は ec-cube-enterprise。商品系は承認ワークフローを介さず persist/flush で直接確定する（在庫の承認ワークフローとは別系統。`ProductController`・各CSVサービスで確認）。

| 操作種別 | 対象テーブル | 契機・条件 |
|---------|--------------|------------|

## バリデーション

| 項目 | 内容 |
|------|------|
| フォーム | `import_file` は NotBlank とファイルサイズ上限。 |
| 行 | 列数は定義列数と一致。各列は `ColumnDefinitions` の型・必須。行バリデータで価格整合、スマレジ条件付き必須、廃止ステータス時の在庫、スマレジ OFF 後の在庫などを検証。 |
| データ行前処理 | ヘッダ行必須・データ 1 行以上必須。 |

## 画面遷移

| 条件 | 遷移先 |
|------|--------|
| GET 成功 | 同一 URL で HTML（アップロード画面）。 |
| POST 完了（成否問わず） | `GET /{admin_route}/product/product_goods_csv_upload` へリダイレクト。 |

### 遷移時に引き継ぐ状態

| 起点 | 遷移前の処理 | 遷移後の初期状態 |
|------|--------------|------------------|
| アップロード画面でページング | `page_count` または `page_no` をセッションへ保存 | 次回以降の同画面で既定の件数・ページが復元される。 |
| POST 取込 | フラッシュメッセージを積む | リダイレクト先でトースト／アラート相当として表示される。 |

## エラー処理

| エラー内容 | 処理 |
|------------|------|
| フォーム不正 | 各メッセージをフラッシュし、アップロード画面へリダイレクト。 |
| ファイル未選択 | `admin.common.csv_invalid_format` をフラッシュ。 |
| 行数超過 | `admin.csv.error.upload.maxrecord` をフラッシュ。 |
| CSV 事前検証失敗 | 定義済みメッセージをフラッシュ。 |
| 行単位のエラー | メッセージをフラッシュ。コミット可否は `CsvImporter` の判定に従う。 |

## ログ・監査

| タイミング | 記録内容 |
|------------|----------|
| 取込開始 | 情報ログ「グッズ・サプライ・情報商材CSV登録開始」。 |
| 取込異常終了（結果にエラー） | 情報ログ「グッズ・サプライ・情報商材 異常終了」。 |
| 取込成功 | 情報ログ「グッズ・サプライ・情報商材」に件数。 |

### ログに出してはいけないもの

- パスワード
- なりすまし対策トークン
- Cookie 値
- セッション ID の完全値
- Remember Me トークンの原値

## Cookie

本機能固有の Cookie は持たない。セッション用 Cookie は管理画面共通の挙動に従う。

---

## 排他制御・トランザクション

- 取込は `CsvImporter` が 1 トランザクション内で全データ行を処理する（例外時はロールバックを試行）。
- 楽観ロック版管理番号は当機能の UI では扱わない。
- 行ロックタイムアウトはハンドラが 1〜30 秒の範囲で返す前提（既定 5 秒）。
