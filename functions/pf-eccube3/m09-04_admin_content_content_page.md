# コンテンツ管理 — ページ管理

## 概要

管理画面コンテンツ管理のページ管理は、フロントに表示する各ページの属性（ページ名・URL・ファイル名・metaタグ等）と、そのページのテンプレート本文（Twig）を一覧から選んで編集する機能である。EC-CUBE コアのページ管理を、HareruyaEc プラグインが新規作成・編集・更新の各操作で差し替えている。

本書は実装手順ではなく、誰が・いつ・どの条件で・結果どうなるかを読むためのリバース詳細設計とする。一覧表示・削除はコアのページ管理実装、新規作成・編集フォームの表示・保存は HareruyaEc のページ管理実装を確認値とする。

本機能のカスタマイズ区分はカスタマイズであり、画面・挙動の確認値は現行リポ（pf-eccube3、HareruyaEcプラグイン）を正とし、DB関連（テーブル名・列名・保存先・副作用のDB更新）はec-cube-enterpriseを正とする。現行と移行先でページ情報のスキーマが大きく異なるため、差分は「リニューアル移行時の扱い」に集約する。

対象はブラウザ経由の管理画面コンテンツ管理のページ管理に限定する。レイアウト管理（ブロックの配置）、CSS管理、JavaScript管理、ファイル管理、キャッシュ管理は別機能として切り離す。

管理画面プレフィックスは設定キー `admin_route`（`path.yml` の `${ADMIN_ROUTE}` 由来）で決まる。本書ではパスを `/{admin_route}/` のプレースホルダで示し、ルート bind 名は調査補助に隔離する。コントローラのメソッド名は本文の主説明としない。

---

## 本書で扱うこと

- ページ一覧の表示対象と表示項目
- ページ新規作成フォーム・編集フォームの表示と入力項目
- ページ属性の保存と、テンプレート本文（Twig）のファイル保存先がデータ種別で分かれること
- 編集不可ページ（初期投入データ）で URL・ファイル名が保持されること
- 保存後のキャッシュ破棄とリダイレクト
- ユーザー作成ページの削除可否

## 本書で扱わないこと

以下は本書では仕様確定せず、実装または別機能の設計を正とする。

- レイアウト管理（`m09-03_admin_content_content_layout`）でのブロック配置
- ファイル管理・キャッシュ管理・CSS管理・JavaScript管理の動作
- フロント側でのページ描画、ルーティング解決、テンプレート継承の詳細
- 端末種別（PC以外）ごとのページ管理。本機能は PC 端末種別を対象に固定する
- 管理画面のログイン・権限設定の詳細仕様

## リニューアル移行時の扱い

本機能はカスタマイズ区分がカスタマイズであり、画面・挙動の確認値は現行リポ（pf-eccube3、HareruyaEcプラグイン）を正とする。一方、DB関連（テーブル名・列名・保存先・副作用のDB更新）はec-cube-enterpriseを正とする。現行ではページ本体を dtb_pagelayout に保持するが、移行先のec-cube-enterpriseではページ本体を dtb_page に保持し、dtb_page_layout はページとレイアウトの結合表になる。本書のDBカラム節・入力項目の保存先・用語は移行先名称を主とし、現行名称を括弧で添える。

| 観点 | 現行（pf-eccube3） | 移行先（ec-cube-enterprise） |
|------|---------------------|------------------------------|
| ページ本体テーブル | dtb_pagelayout（ページ属性とページ自体を保持） | dtb_page |
| ページ名列 | dtb_pagelayout.name | dtb_page.page_name |
| 編集可否区分列 | dtb_pagelayout.edit_flg（0=利用者作成 / 1=プレビュー / 2=初期投入） | dtb_page.edit_type。区分値の対応はec-cube-enterprise実装で要確認 |
| 端末種別列 | dtb_pagelayout.device_type_id（PC等を保持） | dtb_page に端末種別列なし。移行先は端末種別を持たない（要確認） |
| URL・ファイル名・author・description・keyword・meta_robots・meta_tags | dtb_pagelayout の同名列 | dtb_page の同名列 |
| 追加metaタグの長さ | フォーム上限99999文字（lltext_len） | dtb_page.meta_tags は4000文字。フォーム上限とDB列長の差はec-cube-enterprise実装で要確認 |
| dtb_pagelayout / dtb_page_layout の役割 | dtb_pagelayout がページ本体 | dtb_page_layout（アンダースコア区切り）はページとレイアウトの結合表（page_id・layout_id・sort_no） |

テンプレート本文（Twig）をファイルへ書き出す挙動は現行・移行先とも変わらず、ページ属性のみがDBへ保存される。

## 用語

| 用語 | 説明 |
|------|------|
| ページ | フロントの一画面に対応する登録情報。ページ名・URL・ファイル名・metaタグ等の属性と、テンプレート本文を持つ。テーブルは `dtb_page`（現行 `dtb_pagelayout`）。 |
| 編集可否区分 | ページが利用者作成か初期投入かを示す区分。現行は `dtb_pagelayout.edit_flg`（値 0=利用者作成 / 1=プレビュー / 2=初期投入）、移行先は `dtb_page.edit_type`。移行先の区分値の対応はec-cube-enterprise実装で要確認。 |
| テンプレート本文 | ページの Twig ファイルの中身。フォーム上は本文入力欄に対応し、保存時にファイルへ書き出す。 |
| 端末種別 | 表示端末の区分。本機能では PC 端末種別を取得して対象とする。 |

## 利用者視点の入口

| 入口 | URLエンドポイント | 期待されるふるまい |
|------|--------------------|--------------------|

| 行の削除を押下 | `DELETE /{admin_route}/content/page/{id}/delete` | 利用者作成ページのときファイルとレコードを削除し、一覧へ戻る。初期投入ページは削除しない。 |

## フロント挙動

| 観点 | 内容 |
|------|------|
| 表示要素 | 一覧は検索ボックスと、ページ名・ルーティング名・URL・ファイル名・レイアウト名の5列、操作ドロップダウンを並べる。編集フォームはページ名・URL・ファイル名・author・description・keyword・robots・追加metaタグの各入力欄と、テンプレート本文の複数行入力欄を持つ。 |
| JS 挙動 | 一覧の操作はドロップダウンメニューで開く。削除リンクは確認ダイアログ「このページを削除してもよろしいですか？」を出し、`data-method="delete"` でHTTP DELETE 相当の送信を行う。専用のリッチエディタや非同期保存は持たない。 |
| CSS・レイアウト | 管理画面共通のテーブル風レイアウトと横型フォームテーマを使う。テンプレート本文欄は行数15・等幅小サイズで表示する。 |
| モーダル・ポップアップ | 削除確認のダイアログ以外のモーダルは持たない。 |
| 入力項目 | テンプレート本文は複数行入力（textarea）であり、リッチテキスト化やプレビュー切替は行わない。 |

| 起点 | 参照する値 | 判定順序 | 更新する表示値・送信値 | サーバ側再検証 |
|------|------------|----------|--------------------------|----------------|
| 削除リンク押下 | 対象ページの削除URL、確認文言 | 確認ダイアログを表示し、承認された場合だけ削除送信へ進む。 | `data-method="delete"`の送信を実行する。フォーム値は更新しない。 | ページ存在、削除可否、初期ページ制限、トークン、権限はサーバ側で判定する。 |

## 処理フロー

### ページ一覧を表示する

1. PC 端末種別を取得する。
2. 検索語が入力されている場合は、ページ名・ルーティング名・URL・ファイル名・レイアウト名を部分一致条件にする。
3. その端末種別のページを ID 昇順で取得する。ID が 0 のレコードは一覧から除外する。
4. 一覧表示完了の拡張イベントを発火し、ページ一覧を渡す。
5. 一覧テンプレートを描画する。

### 新規作成フォームを表示する

1. ページ ID 未指定で新規ページを生成し、PC 端末種別と編集可否区分（利用者作成）を設定する。
2. ページ用フォームを組み、初期化完了イベントを発火する。
3. テンプレート本文欄に、設定ファイル群から見つかった既定テンプレートの内容を初期表示する。見つからなければ空文字を初期表示する。
4. 編集フォームを描画する。

### 編集フォームを表示する

1. ページ ID から該当ページを取得する。該当が無ければ見つからない扱い（HTTP 404）とする。
2. ページ用フォームを組み、初期化完了イベントを発火する。
3. テンプレート本文欄に、データ種別に応じた読込先のファイル内容を初期表示する。初期投入データはアプリのテンプレート・プラグイン既定・コア既定の順に探す。利用者作成データはユーザーデータ領域から探す。
4. 編集フォームを描画する。`editable` は初期投入データのとき偽、利用者作成のとき真とする。

### 新規作成を送信する

1. フォームに送信値を反映する。
2. 検証が通らなければ同一フォームを再描画する。
3. 検証済みなら、フォーム内容でページ情報を更新し、データベースへ保存する。
4. テンプレート本文をファイルへ書き出す。書き出し先は初期投入データならアプリのテンプレート領域、利用者作成データならユーザーデータ領域とする。
5. キャッシュを破棄する。
6. 編集完了イベントを発火し、登録完了メッセージを追加する。
7. 登録したページの編集画面へリダイレクトする。

### 編集を送信する

1. フォームに送信値を反映する。
2. 検証が通らなければ同一フォームを再描画する。
3. 検証済みなら、フォーム内容でページ情報を更新する。編集可否区分が初期投入データのとき、URL とファイル名は更新前の値で保持する。
4. データベースへ保存する。
5. 初期投入データでないときだけテンプレート本文をファイルへ書き出す。ファイル名が変更され旧ファイルが存在すれば旧ファイルを削除する。
6. キャッシュを破棄し、編集完了イベントを発火し、登録完了メッセージを追加する。
7. 編集画面へリダイレクトする。

## 業務ルール・計算

本機能では金額計算・件数集計を行わない。ページ属性の検証と、テンプレート本文のファイル保存先の振り分けが主な処理である。

| 項目 | 内容 |
|------|------|
| 保存先の振り分け | テンプレート本文は、初期投入データならアプリのテンプレート領域、利用者作成データならユーザーデータ領域へ書き出す。 |
| 初期投入データの保持 | 編集時、初期投入データは URL とファイル名を更新前の値で保持し、ページ名のみ更新を許す。 |
| URL の一意性 | 同一端末種別で URL が重複するとき検証エラーとする。新規は ID なし、編集は自身の ID を除外して重複判定する。 |
| 一覧の対象 | PC 端末種別かつ ID が 0 でないページを ID 昇順で表示する。検索語がある場合はページ名・ルーティング名・URL・ファイル名・レイアウト名を部分一致で絞り込む。 |

### 入力項目

| 項目名 | 必須／任意 | 最大長 | 初期値 | 保存先・扱い |
|--------|------------|--------|--------|----------------|
| 名称 | 必須 | 255文字（`NotBlank` と `Length`） | 新規は空、編集は現行値 | `dtb_page.page_name`（現行 `dtb_pagelayout.name`）。キー `name`。 |
| URL | 必須 | 255文字（`NotBlank`・`Length`・正規表現） | 新規は空、編集は現行値 | `dtb_page.url`（現行 `dtb_pagelayout.url`）。キー `url`。半角英数字と `_ - /` のみ許可。末尾 `/` 不可。初期投入データは更新前の値を保持。 |
| ファイル名 | 必須 | 255文字（`NotBlank`・`Length`・正規表現） | 新規は空、編集は現行値 | `dtb_page.file_name`（現行 `dtb_pagelayout.file_name`）。キー `file_name`。半角英数字と `_ - /` のみ許可。テンプレート本文の書き出しファイル名になる。初期投入データは更新前の値を保持。 |
| 本文 | 必須 | フォーム上限なし。ファイルへ書き出す | 新規は既定テンプレート内容、編集は読込先ファイル内容 | テーブルには保存せず Twig ファイルへ書き出す。キー `tpl_data`（`mapped` 偽）。改行コードを変換して書き込む。 |
| author | 任意 | 255文字（`Length`） | 編集は現行値 | `dtb_page.author`（現行 `dtb_pagelayout.author`）。キー `author`。 |
| description | 任意 | 255文字（`Length`） | 編集は現行値 | `dtb_page.description`（現行 `dtb_pagelayout.description`）。キー `description`。 |
| keyword | 任意 | 255文字（`Length`） | 編集は現行値 | `dtb_page.keyword`（現行 `dtb_pagelayout.keyword`）。キー `keyword`。 |
| robots | 任意 | 255文字（`Length`） | 編集は現行値 | `dtb_page.meta_robots`（現行 `dtb_pagelayout.meta_robots`）。キー `meta_robots`。 |
| 追加metaタグ | 任意 | 99999文字（`lltext_len`、`Length`） | 編集は現行値 | `dtb_page.meta_tags`（現行 `dtb_pagelayout.meta_tags`）。キー `meta_tags`。複数行入力（textarea）。移行先のDB列長は4000文字でフォーム上限と異なる（ec-cube-enterprise実装で要確認）。 |

最大長の数値は `src/Eccube/Resource/config/constant.yml.dist` の確認値とする。運用環境で上書きされている場合はその環境の値が正とする。端末種別とページ ID は隠し項目として送信し、ページ ID はキー `id`、端末種別はキー `DeviceType` で扱う。

### エッジケース

| ケース | 扱い |
|--------|------|
| ファイル名が未設定のページ | 一覧のページ編集リンクを無効化する。 |
| 初期投入データの編集 | URL・ファイル名は更新前の値を保持し、テンプレート本文のファイル書き出しは行わない。 |
| 編集でファイル名を変更 | 新ファイルへ書き出し、旧ファイルが存在すれば削除する。 |
| 削除対象が初期投入データ | レコード・ファイルとも削除しない。 |
| 削除対象が存在しない ID | 削除対象なしメッセージを出して一覧へ戻る。 |

## データ整合性

| 観点 | 内容 |
|------|------|
| 属性とファイルの整合 | ページ属性はデータベース、テンプレート本文はファイルへ分けて保存する。保存はデータベース更新のあとにファイル書き出しを行う。両者の整合は保存処理の成否に依存する。 |
| 一覧と編集の整合 | 一覧は保存後の最新レコードを ID 昇順で読む。本文の表示は読込先ファイルの現行内容を反映する。 |
| キャッシュ | 保存・削除のあとキャッシュを破棄する。テンプレートのキャッシュが古いまま残り続ける設計にはしない。 |

## DBカラム

当機能に直接関係する列のみを記載する。型や一覧の細部はスキーマを参照する。

| テーブル | 列 | メモ |
|---------|-----|------|
| `dtb_page`（現行 `dtb_pagelayout`） | `page_name`（現行 `name`）、`url`、`file_name` | ページ属性の主項目。 |
| `dtb_page`（現行 `dtb_pagelayout`） | `author`、`description`、`keyword`、`meta_robots`、`meta_tags` | メタ情報。 |
| `dtb_page`（現行 `dtb_pagelayout`） | `edit_type`（現行 `edit_flg`） | 編集可否区分。利用者作成・プレビュー・初期投入を表す。移行先の区分値の対応はec-cube-enterprise実装で要確認。 |
| `dtb_pagelayout`（現行のみ） | `device_type_id` | 現行は端末種別を保持しPCを対象とする。移行先の `dtb_page` に端末種別列は無い（要確認）。 |

テンプレート本文は `dtb_page`（現行 `dtb_pagelayout`）には保存せず、Twig ファイルへ書き出す。移行先ではページとレイアウトの紐付けを `dtb_page_layout`（page_id・layout_id・sort_no）が担う。

### DB操作

永続化の正は ec-cube-enterprise（テーブル名・操作は ec-cube-enterprise を正典）。当ドメインは承認ワークフローを介さず persist/flush で直接確定する（承認ワークフローは在庫機能固有）。

| 操作種別 | 対象テーブル | 契機・条件 |
|---------|--------------|------------|
| 登録/更新 | dtb_page / dtb_page_layout / dtb_pagelayout | 当機能が行う登録・更新で対象テーブルを直接保存する（不要な削除は含まない）。確定は persist/flush による即時反映。DB=ec-cube-enterprise を正典とする。 |

## セッション

本機能は一覧の検索条件をセッションに載せない。検索ボックスの入力はGETリクエスト内で部分一致条件として扱い、成功・失敗メッセージは管理画面共通のフラッシュ機構に依存する。

## Cookie

管理画面のセッション Cookie のみを正とし、本機能用の追加 Cookie は定義しない。

## 排他制御・トランザクション

ページ属性の保存はデータベースの永続化に任せ、画面側に楽観ロックの版情報は持たない。テンプレートのファイル書き出しはデータベース保存後に行う。
