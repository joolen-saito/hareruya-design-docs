# 商品管理 — 商品規格登録/編集

## 業務ロジック

### 規格の登録・編集画面を表示する

1. 利用者が新規登録画面または編集画面を開く。
2. 商品IDから商品付加情報を読み込み、見つからなければ見つからない（HTTP404）とする。
3. 編集（`classId`あり）では指定規格を読み込み、見つからなければ見つからない（HTTP404）とする。新規（`classId`なし）では既定値（在庫0、在庫無制限なし、通常種別など）を持つ空の規格を用意する。
4. 編集フォームを生成し、代表画像の選択肢と現行の代表画像を初期値として設定する。
5. 編集時かつ規格が削除可能な場合は削除ボタンを表示する。

### 規格を更新する

1. 利用者が商品規格を登録ボタンを押下する。
2. 入力値を受け取り、検証する。
3. 検証に失敗した場合は「登録できませんでした。」のエラーを設定し、同じ画面を再表示する。
4. 検証に合格した場合、規格を永続化対象にする。
5. 既存の規格・画像関連を削除し、送信された代表画像と並び順で画像関連を作り直す。
6. 在庫レコードへ在庫数を反映する。
7. 在庫数が変更されている場合、在庫変動区分・理由をもとに在庫履歴を記録し、支店側へ在庫更新を通知する。入荷区分またはマスタ更新区分で在庫が増加した場合は、増分を各段階の在庫予約数へ加算する。
8. 販売価格または買取価格が変更されている場合、価格履歴を記録する。
9. 在庫が0から正数へ増えた場合、当該規格について入荷通知メールを送る。
10. 規格の更新日時を現在時刻にし、永続化を確定する。
11. 支店システムへ当該商品の更新を通知する。
12. 「登録が完了しました。」の成功フラッシュを設定し、同じ規格の編集画面へリダイレクトする。

### 規格を削除する

1. 削除可能でない（最後の1件）場合は不正要求（HTTP400）とする。
2. 規格を論理削除し、永続化を確定する。
3. 支店システムへ当該商品の更新を通知し、規格一覧へリダイレクトする。

---

### 主処理時の判定順序（更新）

| 順序 | 判定 | 結果 |
|------|------|------|
| 1 | フォーム検証 | 不備なら「登録できませんでした。」を設定し同一画面を再表示。 |
| 2 | 在庫数が変更されたか | 変更時は在庫履歴を記録し支店へ在庫更新を通知。 |
| 3 | 在庫変動区分が入荷またはマスタ更新で在庫が増加したか | 増分を各段階の在庫予約数へ加算。 |
| 4 | 販売価格または買取価格が変更されたか | 変更時は価格履歴を記録。 |
| 5 | 在庫が0から正数へ増えたか | 入荷通知メールを送信。 |

---

| 項目 | 内容 |
|------|------|
| 言語・状態の固定 | 編集では言語・状態を変更せず読み取り表示する。新規登録でのみ選択する。 |
| 在庫履歴 | 在庫数が変わったときのみ、在庫変動区分・理由を伴って記録する。 |
| 在庫予約数の加算 | 在庫変動区分が入荷またはマスタ更新で在庫が増加したとき、増分を在庫予約数01・03〜10へ加算する。 |
| 価格履歴 | 販売価格または買取価格が変わったときのみ記録する。 |
| 入荷通知 | 在庫数が0から正数へ増えたときのみ、当該規格について入荷通知メールを送る。 |
| 削除可否 | 規格が最後の1件のときは削除しない。 |

### エラー時の扱い

| エラー内容 | 処理 |
|------------|------|
| 商品が存在しない | 見つからない（HTTP404）。 |
| 規格が存在しない（編集） | 見つからない（HTTP404）。 |
| フォーム検証失敗 | 「登録できませんでした。」を設定し同じ画面を200で再表示する。 |
| 在庫数・在庫無制限が両方未設定 | 在庫無制限欄にエラーを付与し再表示する。 |
| 最後の1規格の削除 | 不正要求（HTTP400）。 |
---

## 入出力

| 種類 | 内容 |
|------|------|
| 入力 | GETは商品IDと規格ID。POSTはフォーム名`m03-09_admin_product_product_class_edit`、CSRFトークン、`multipart`の画像関連隠しフィールド。 |
| 成功時出力 | 規格・在庫・履歴の更新、成功フラッシュ、同じ規格の編集画面への302リダイレクト。 |
| 失敗時出力 | 検証失敗時は200で同じ画面を再描画し「登録できませんでした。」を表示する。 |
