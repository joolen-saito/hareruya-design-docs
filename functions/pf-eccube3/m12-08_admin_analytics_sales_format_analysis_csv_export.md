# 分析 — フォーマット売上分析CSVダウンロード

## 概要

フォーマット売上分析のCSVダウンロードは、CSVダウンロードの送信に含まれる集計月でフォーマット（売上分析タグ）ごとの日別売上を集計し直し、画面の日別の売上表と同じ集計結果をCSVとしてストリーミング出力する機能である。

本書は実装手順ではなく、誰が・いつ・どの条件で・結果どうなるかを読むためのリバース詳細設計とする。確認値はpf-eccube3（EC-CUBE3系）のHareruyaEcプラグインのフォーマット売上分析のエクスポート処理、売上分析タグ集計用リポジトリ、CSV出力サービスを正とする。本機能のカスタマイズ区分はカスタマイズであり、挙動は現行リポpf-eccube3を参照し、DB関連の記述はec-cube-enterpriseを正とする。現行と移行先でテーブル名・列の所在が異なる箇所は「リニューアル移行時の扱い」に集約する。

対象はブラウザ経由の管理画面に限定する。本文ではフレームワークのコントローラ型名やメソッド名を主説明としない。管理画面プレフィックスは環境により変わる（`admin_route`）。「利用者視点の入口」にHTTPメソッドとサイトルートからのパスパターンを書く。

集計条件・一覧表示はM12-07で扱う。本書はCSV出力の入口・出力列・ファイル形式と、集計条件が一覧と一致することを扱う。

## リニューアル移行時の扱い

挙動は現行リポpf-eccube3を正とし、DB関連はec-cube-enterpriseを正とする。CSV出力はM12-07の集計と同じ列を参照するため、スキーマ差はM12-07と同じである。

| 観点 | 現行（pf-eccube3） | 移行先（ec-cube-enterprise） |
|------|--------------------|------------------------------|
| 注文明細テーブル | `dtb_order_detail` | `dtb_order_item`（`price`・`quantity` は同名） |
| 明細と売上分析タグの紐づき | `dtb_order_detail_sub_tag_sales_analysis`（`order_detail_id`） | `dtb_order_item_tag_sales_analysis`（`order_item_id`） |
| カード明細の判別列 | 規格サブ `dtb_product_sub.card_detail_id` | `dtb_product.card_detail_id`（商品本体に統合） |
| フォーマットの並び順 | `mtb_tag_sales_analysis.rank` | `mtb_tag_sales_analysis.rank`（同名） |

詳細はM12-07の「リニューアル移行時の扱い」を正とする。移行先に該当が見当たらない箇所は「ec-cube-enterprise 実装で要確認」と残す。

## 処理フロー

### 集計結果CSVを出力する（`/{admin_route}/analysis/format_sales/export`）

1. 管理画面の認証・権限を通過する。
2. 検索フォームへ送信値を取り込み、集計月を取得する。
3. 集計月をもとに、フォーマット（売上分析タグ）ごと、および売上分析タグに紐づかない区分ごとの日別売上を集計する（M12-07と同じ集計）。
4. CSV出力サービスを開き、BOMを出力する。
5. 先頭に「日」、続けて各フォーマットの名称、末尾に「合計」を並べたヘッダ行を出力する。
6. 日別の売上表を日ごとに1行で出力する。日に続けて各フォーマットの売上、末尾に当日の日別合計を出力する。
7. CSV出力サービスを閉じる。

## 集計条件

| 指標 | 集計の要点 |
|------|------------|
| 集計の同一性 | M12-07の集計実行と同じ売上分析タグ集計用リポジトリ・集計月で集計する。対象データ・結合・除外・集計単位・期間はM12-07の集計条件と一致する。 |
| 条件の取得元 | 集計月はCSVダウンロードの送信値とする。検索条件セッションは参照しない。 |
| 出力対象 | 日別の売上表（日・各フォーマット・日別合計）を出力する。フォーマットごとの合計・平均の表はCSVに含めない。 |

集計の対象データ・期間・除外条件の詳細はM12-07の集計条件を正とする。

## 業務ルール・計算

| 項目 | 内容 |
|------|------|
| ヘッダ行 | 先頭を「日」とし、各フォーマットの名称を続け、末尾に「合計」を置く。フォーマットの並びはM12-07と同じく売上分析タグの`rank`昇順、その後に「その他(カード)」「その他」とする。 |
| データ行 | 日に続けて各フォーマットの売上を出力し、末尾に当日の日別合計を出力する。 |
| 値の算出 | 日別売上・日別合計の算出はM12-07の集計と同一とする。 |

本機能は集計月のみを入力とし、その他の入力項目に紐づく表を持たない。

## データ整合性

| 観点 | 内容 |
|------|------|
| 参照時点 | 画面表示またはCSV・帳票出力の実行時点で検索条件に一致するデータを参照する。本機能は参照・出力を主とし、業務データを更新しない。 |

| 同時更新 | 出力中に他処理が対象データを更新した場合のスナップショット保証は持たない。行ロックを取得せず、読み取り時点の値を出力する。 |

## DBカラム

機能に直接関係する列のみ記載する。型や一覧の細部はスキーマを参照する。M12-07の集計で参照する列に一致する。テーブル名・列名はec-cube-enterpriseを正とし、現行（pf-eccube3）と異なる場合は現行名を括弧で添える。

| テーブル | 列 | メモ |
|---------|-----|------|
| dtb_order | order_date, status | 集計期間・日別集計・キャンセル除外。 |
| dtb_order_item（現行 dtb_order_detail） | price, quantity | 売上金額の算出。 |
| dtb_order_item_tag_sales_analysis（現行 dtb_order_detail_sub_tag_sales_analysis） | tag_sales_analysis_id, order_item_id（現行 order_detail_id） | 明細と売上分析タグの紐づき。 |
| dtb_product（現行 dtb_product_sub） | card_detail_id | その他(カード)・その他の判別。 |
| mtb_tag_sales_analysis | rank, name | フォーマットの並び順・列名。 |

### DB操作

本機能は参照系（検索・出力）であり、DBへの登録・更新・削除は行わない。テーブル名は ec-cube-enterprise を正典とする。

| 操作種別 | 対象テーブル | 契機・条件 |
|---------|--------------|------------|
| 検索 | dtb_order / dtb_order_detail / dtb_order_detail_sub_tag_sales_analysis / dtb_order_item / dtb_order_item_tag_sales_analysis / dtb_product 等 | 検索条件に合致するレコードを抽出する。抽出結果を所定フォーマットでファイル出力する。 |
