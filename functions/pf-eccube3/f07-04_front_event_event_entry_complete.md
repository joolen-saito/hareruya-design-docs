# F07-04（大会申込～完了）


### Excel基本設計により廃止された仕様

刷新後は実装しない。現行実装のふるまいは本書に残すが、刷新後の実装・テストの対象外とする。

| 廃止の識別 | 刷新後に実装しないふるまい |
| --- | --- |
| Excel基本設計 0214 識別ID:1-12 により廃止 | チーム人数（整数）がチーム戦フラグ（真偽）へ変わり、人数を持たなくなるため、ログイン会員以外の人数分のメンバーメールの入力と検証、メールだけの仮選手の作成、チームメンバー招待メールの送信、未承認状態での申込選手の登録、招待リンクからのチームメンバー認証を実装しない |
| Excel基本設計 0214 識別ID:4-1 により廃止 | 申込画面での席次の入力・検証と、申込選手への席次の設定 |
| Excel基本設計 0214 識別ID:4-3 により廃止 | チームメンバー認証（招待メールのリンクから未承認の申込選手を承認する現行のふるまい） |

## 業務ロジック

### 申込対象の選択

イベント詳細が存在しないときはページが見つからない（HTTP404）として扱う。受付期間外、またはログイン会員が申込済みのときはイベント詳細（F07-03）へ戻す。

別日程の同イベントとして扱うのは、ログイン会員の選手情報で申込可能なものだけである。

### 支払方法の選択

主対象を指定せずに（同一イベントの別時間帯をまとめて申し込む導線から）来たときは、選択された対象の先頭を主対象として扱い、残りを追加対象とする。

主対象が存在しないときはHTTP404、受付期間外・申込済みのときはイベント詳細へ戻す。追加対象がすべて同一イベントかつすべて参加可能でないときは不正要求（HTTP400）として扱う。

合計参加費が0円のときは支払方法を提示しない。前段の検証エラーは各欄に表示する。

### 申込内容の確認

なりすまし対策トークンを検証する。主対象が存在しないときはHTTP404、受付期間外・申込済みのときはイベント詳細へ戻す。追加対象が同一イベント・参加可能でないときはHTTP400として扱う。

チーム戦（チーム人数が1より大きい）のときはメンバーメールと席次を検証する。重複メール・席次不正・ログイン会員と同一メールはエラーとし、支払方法選択へエラー付きで戻す。

### 申込の登録

非同期要求でのみ受け付ける。申込対象は主対象と追加対象である。登録はトランザクション内で行い、例外時はロールバックして再送出する。

| 順序 | 判定 | 結果 |
|------|------|------|
| 1 | 非同期要求か | 非同期でなければ不正要求（HTTP400） |
| 2 | 申込フォームが妥当か | 不正ならエラーログを記録し不正要求（HTTP400） |
| 3 | 全対象が同一イベントかつ参加可能（定員ロックつき）か | 満たさなければ不正要求（HTTP400） |
| 4 | 合計が0円か、正しい支払方法があるか | 0円はエントリー済み、支払方法ありは決済中、いずれでもなければ不正要求（HTTP400） |
| 5 | チーム戦のメンバー数・重複が妥当か | 数が合わない・重複があるときは不正要求（HTTP400） |
| 6 | チーム戦のメンバーメール・席次が妥当か | 不正なら支払方法選択へエラー付きで戻す |
| 7 | 上記を通過 | 申込・申込選手・申込履歴を作成、チーム戦は招待メール送信、支払番号を採番してコミット |

申込対象ごとに申込と申込選手（ログイン会員と仮選手）を作成する。支払番号は申込群に共通で、`EV`・先頭申込の作成日時（年月日と時分。時は12時間表記）・ハイフン・10桁ゼロ詰めの申込ID をこの順に連結した値である。

登録結果は、無料のときは完了画面用の対象詳細IDを、有料のときは支払番号と金額を返す。

### 申込可否の判定

| 項目 | 内容 |
| --- | --- |
| 申込対象の同一性 | 主対象と追加対象はすべて同一イベントの日程に限る。違反は不正要求（HTTP400） |
| 受付期間 | 事前予約の受付が有効な日程で、事前予約開始日時以降・事前予約終了日時以前であること。各段階で再判定する |
| 定員 | 申込済み人数（チーム人数換算）が定員未満であること。申込登録時は悲観ロックつきで再判定する |
| 重複申込 | ログイン会員の選手情報が当該イベント詳細に申込済みでないこと |
| 合計参加費 | 0円は無料申込、1円以上は支払方法必須 |
| 申込状況 | 無料はエントリー済み、有料は決済中で作成する。決済完了で確定、キャンセルで取消側へ |

### 決済後の扱い

外部決済の結果を復号して取得する。結果コードが正常でないときは決済ログにエラーを記録し、決済キャンセルへ戻す。正常なときは支払番号で申込を取得し、決済確認処理で申込状況を確定する。確定に失敗したときは決済ログにエラーを記録する。

決済キャンセルでは、支払番号で申込を取得し、決済確認処理で申込を取消側に整える。

### エラー時の扱い

| エラー内容 | 処理 |
|------------|------|
| イベント詳細が存在しない | ページが見つからない（HTTP404）として扱う |
| 受付期間外・申込済み | イベント詳細（F07-03）へ戻す |
| 申込対象が異イベント・参加不可 | 不正要求（HTTP400）として扱う |
| 支払方法が不正・空（有料） | 不正要求（HTTP400）として扱う |
| チームメンバーメール・席次の不正 | 支払方法選択へエラー付きで戻す |
| 非同期でない申込登録 | 不正要求（HTTP400）として扱う |
| 登録途中の例外 | トランザクションをロールバックし例外を再送出する |
| 決済結果が異常 | 決済ログにエラーを記録し、決済キャンセルへ戻す |

メール・席次の必須未入力は妥当性検証で不正として扱い、支払方法選択へエラー付きで戻す。

## 入出力

| 種類 | 内容 |
|------|------|
| 入力 | 申込対象のイベント詳細ID群、支払方法、チームメンバーの席次・メール、なりすまし対策トークン、決済の戻り結果 |
| 成功時出力 | 各段階の画面、申込登録の応答（完了画面用／決済用）、申込完了画面 |
| 失敗時出力 | ページが見つからない（HTTP404）、不正要求（HTTP400）、イベント詳細への遷移、支払方法選択へのエラー付き差し戻し、決済キャンセル画面 |
