# M03-31（セール用価格変更CSV登録）

## 概要

セール用価格変更CSV登録機能は、管理画面の商品管理で、商品IDと言語ごとに販売価格・買取価格・セールフラグ・帯URL・タグをCSVで一括更新する機能である。アップロード画面でCSVを選択して送信し、サーバ側で1行ずつ検証・取込し、対象商品の規格の価格などを更新する。

本書は実装手順ではなく、誰が・いつ・どの条件で・結果どうなるかを読むためのリバース詳細設計とする。既存実装のふるまい、参照するデータ、判定境界、永続化、副作用を確認し、仕様の確からしさを把握することを目的とする。

本機能のカスタマイズ区分は現行踏襲である。挙動は現行リポ pf-eccube3 の実装を参照し、DB関連の記述（テーブル名・列名・保存先・副作用のDB更新）は ec-cube-enterprise を正とする。価格変更CSV登録は ec-cube-enterprise にも同等実装がある。

対象はブラウザ経由の管理画面のセール用価格変更CSVアップロード画面と取込処理である。CSVエクスポート（雛形・出力）、価格変更（簡易）CSVや高額商品価格CSVなど他の価格系CSVは別機能とし、本書では正としない。買取価格の割引計算式の詳細は概要に留める。

管理画面プレフィックスは設定キー`admin_route`で決まる。ルート定義は`/'.$app['config']['admin_route'].'/...`の形でパスを組み立てるため、本書ではパスを`{admin_route}`で表す。コントローラのメソッド名・ルートbind名は本文の主説明としない。

## リニューアル移行時の扱い

- 買取価格・セールフラグ・帯URL・高額商品コードの保存先: 現行 pf-eccube3 ではこれらを規格補助テーブル（dtb_product_sub_class）に分けて持つが、移行先 ec-cube-enterprise では規格テーブル dtb_product_class に統合している。本書のDBカラム節・保存先の記述は移行先 dtb_product_class を正とする。
- 規格の販売価格列: 現行・移行先とも価格列は dtb_product_class.price02 で同一である。
- 商品タグの紐付け列: 現行 pf-eccube3 は dtb_product_tag の tag 列、移行先 ec-cube-enterprise は dtb_product_tag の tag_id 列で保持する。本書は移行先の tag_id を正とする。
- 商品の存在確認: 現行 pf-eccube3 は dtb_product.del_flg で論理削除を判定するが、移行先 ec-cube-enterprise の dtb_product に del_flg 列は無く、商品ステータス・公開状態で扱う。存在判定の列は ec-cube-enterprise 実装で要確認とする。
- 価格履歴・取込履歴: dtb_price_history・dtb_csv_import_history は現行と移行先で同一スキーマである。

## 処理フロー

### アップロード画面を表示する

1. 利用者がアップロード画面を開く。
2. CSVインポートフォームを生成し、フォーマット表のヘッダ定義を組み立てる。
3. 直近の取込履歴を読み、画面を表示する。

### CSVをアップロードして取込する

1. 利用者がCSVを選択してアップロードボタンを押下する。
2. タイムアウトを無効化する。
3. フォーム検証（ファイル必須・サイズ上限・CSVのMIME）を行う。不合格ならエラーを設定し、同じ画面を再表示する。
4. CSVの行数を数え、上限（5010行）以上なら上限超過エラーを設定し、同じ画面を再表示する。
5. 取込処理を開始する。ファイルを一時保存し、文字コードと改行を正規化する。
6. ヘッダ行が無い、または2行目以降にデータが無い場合は、それぞれフォーマットエラー・データなしエラーとして取込を中止する。
7. データベースのトランザクションを開始し、1行ずつ次の順序で処理する。
   - 行検証（必須・形式・商品の存在・販売価格と買取価格の大小）。商品が存在しない場合などは取込全体を中止する。
   - 行取込（商品タグの全削除・再登録、対象規格の販売価格・買取価格・セールフラグ・帯URLの更新、価格に変更があれば価格履歴の記録）。
8. エラーが無ければトランザクションを確定し、エラーがあればロールバックする。
9. 取込が成功した場合、支店システムへ取込対象の商品更新を通知する。
10. 取込成功時は成功フラッシュを設定し、取込履歴へファイル名を記録する。失敗時は履歴を記録しない。
11. 取込結果（エラー一覧・成功フラグ）と取込履歴を載せて、同じ画面を表示する。

## CSVファイル形式

列の見出しと必須・任意は以下のとおり。順序はフォーマット表の定義に従う。

| 列名 | 必須／任意 | 内容 |
|------|------------|------|
| 商品ID | 必須 | 更新対象の商品。存在しない商品IDは取込全体を中止する。 |
| 言語(ID) | 必須 | 対象規格を絞る言語区分。 |
| 販売価格 | 必須 | 基準販売価格。状態別の割引率を適用して規格ごとの販売価格を算出する。 |
| 買取価格 | 必須 | 基準買取価格。状態別の買取減額率・買取価格表を適用して規格ごとの買取価格を算出する。 |
| セールフラグ | 任意 | 0はセールではない、1はセールである。未指定は0として扱う。 |
| 帯URL | 任意 | 規格の帯URL。空のときはURLを設定しない（NULL）。 |
| タグ(ID) | 任意 | カンマ区切りで複数指定可能。指定内容で商品タグを置き換える。 |

## 業務ルール・計算

| 項目 | 内容 |
|------|------|
| 取込単位 | 商品IDと言語の組み合わせで対象規格を抽出し、各規格の価格を更新する。 |
| 高額商品の除外 | 高額商品コードを持つ規格は本CSVの更新対象から外す。 |
| 販売価格の算出 | 基準販売価格に規格の割引率を適用して規格ごとの販売価格を算出する。 |
| 買取価格の算出 | 状態がNMの規格は基準買取価格をそのまま用いる。買取減額率が設定された規格は減額率で算出する。買取価格表の対象は表に従う。表の対象外は状態別の既定割合で算出する。計算式の詳細は本書で確定しない。 |
| タグ更新 | 行ごとに当該商品のタグを全削除し、CSVのタグIDで登録し直す。 |
| 価格履歴 | 販売価格または買取価格が変更された規格についてのみ価格履歴を記録する。変更なしでは記録しない。 |
| セールフラグ・帯URL | CSVのセールフラグ（未指定は0）と帯URL（空はNULL）を規格へ反映する。 |
| 行数上限 | CSVが5010行以上のときは取込しない。 |

価格の最大桁・買取価格表の数値・状態別レートは取込側の実装と買取価格表マスタを正とする。

## 主処理時の判定順序（1行ごと）

| 順序 | 判定 | 結果 |
|------|------|------|
| 1 | 必須列・形式の検証 | 不備の行はエラーを記録する。 |
| 2 | 販売価格と買取価格の大小（買取価格が販売価格を上回る） | エラーを記録する。 |
| 3 | 商品IDの存在 | 存在しない場合はエラーを記録し取込全体を中止する。 |
| 4 | 行取込 | タグ再登録、対象規格の価格・セールフラグ・帯URLの更新、価格変更時の履歴記録。 |

## データ整合性

| 観点 | 内容 |
|------|------|
| トランザクション | 1ファイルの取込は単一のトランザクションで行い、エラーがあれば全体をロールバックする。成功時のみ確定する。 |
| タグの整合性 | 行ごとに商品タグを全削除して再登録するため、CSVの指定が確定値になる。CSVに含まれないタグは残らない。 |
| 価格履歴との整合性 | 価格が変わった規格のみ履歴を記録する。 |

| 支店連携との整合性 | 取込成功時にトランザクション確定後、支店システムへ取込対象の商品更新を通知する。反映タイミングは支店連携機能の設計を正とする。 |
| 単票編集との整合性 | 規格単票編集（M03-09）とは別経路であり、最後に確定した内容が現行値となる。 |

## DBカラム

本機能が直接更新する代表的な列のみを記載する。型の細部はスキーマを参照する。

列名は移行先 ec-cube-enterprise を主とし、現行 pf-eccube3 と異なる場合は現行名を括弧で添える。

| テーブル | 列 | メモ |
|---------|-----|------|
| `dtb_product_class` | `price02` | 規格の販売価格。算出値で更新する。現行・移行先で同一。 |
| `dtb_product_class` | `update_date` | 更新日時。 |
| `dtb_product_class`（現行 `dtb_product_sub_class`） | `buy_price` | 規格の買取価格。算出値で更新する。移行先では規格テーブルに統合。 |
| `dtb_product_class`（現行 `dtb_product_sub_class`） | `sale_flg` | セールフラグ。未指定は非セール。 |
| `dtb_product_class`（現行 `dtb_product_sub_class`） | `belt_url` | 帯URL。空のときはNULL。 |
| `dtb_product_class`（現行 `dtb_product_sub_class`） | `high_price_code` | 取込対象判定に用いる（高額商品は対象外）。 |
| `dtb_product_tag` | `product_id`、`tag_id`（現行 `tag`）、`creator_id`、`create_date` | 行ごとに全削除・再登録する。 |
| `dtb_product` | `product_id`（存在確認列は現行 `del_flg`。移行先に del_flg 列は無く ec-cube-enterprise 実装で要確認） | 商品の存在確認に用いる。 |

価格履歴は専用テーブル dtb_price_history へ記録する。取込対象の抽出には商品・規格・割引・買取減額率・カード詳細の各テーブルを結合する。

### DB操作

永続化の正は ec-cube-enterprise。商品系は承認ワークフローを介さず persist/flush で直接確定する（在庫の承認ワークフローとは別系統。`ProductController`・各CSVサービスで確認）。

| 操作種別 | 対象テーブル | 契機・条件 |
|---------|--------------|------------|
| 登録/更新 | dtb_price_history / dtb_product / dtb_product_class / dtb_product_sub_class / dtb_product_tag | 当機能が行う登録・更新で対象テーブルを直接保存する（不要な削除は含まない）。確定は persist/flush による即時反映。DB=ec-cube-enterprise を正典とする。 |

## エラー処理

利用者向けの表示文言は「表示メッセージ」を正とする。本節は処理方針を記載する。

| エラー内容 | 処理 |
|------------|------|
| ファイル未選択・サイズ超過・MIME不一致 | フォーム検証エラーを設定し、取込せず同じ画面を再表示する。 |
| 行数上限超過 | 上限超過エラーを設定し、取込せず再表示する。 |
| ヘッダ不一致・データなし | フォーマットエラー・データなしエラーとして取込を中止する。 |
| 必須未入力・形式不正の行 | 当該行のエラーを記録する。 |
| 販売価格より買取価格が大きい行 | 当該行のエラーを記録する。 |
| 商品IDが存在しない行 | 当該行のエラーを記録し、取込全体を中止しロールバックする。 |

| `ファイルを選択してください。` | ファイル未選択でアップロードしたとき。キー`admin.csv.error.upload.require`。 | 画面上部のフラッシュ領域 |
| `CSVファイルは {N} MB以下でアップロードしてください。` | ファイルサイズが上限を超えたとき。キー`admin.csv.error.upload.maxsize`。 | 画面上部のフラッシュ領域 |
| `ファイル形式が異なります。CSVファイルをアップロードしてください。` | MIMEがCSVでないとき。キー`admin.csv.error.upload.mime`。 | 画面上部のフラッシュ領域 |
| `{N} 行を超えるCSVファイルは登録できません。` | 行数が上限以上のとき。`{N}`は上限値。キー`admin.csv.error.upload.maxrecord`。 | 画面上部のフラッシュ領域 |

### 取込時のエラー一覧（画面内）

| 表示文言（日本語） | 表示条件 |
|-------------------|----------|
| `CSVのフォーマットが一致しません。` | ヘッダ行が無いとき。キー`admin.csv.error.format.header`。 |
| `CSVデータが存在しません。` | データ行が無いとき。キー`admin.csv.error.data.empty`。 |
| `{N} 行目の販売価格は買取価格より大きい価格を設定してください。` | 買取価格が販売価格を上回る行。キー`admin.csv.error.product.price_valid`。 |
| `{N} 行目の {列名} ではデータを取得できません。` | 商品IDが存在しない行など。キー`admin.csv.error.product.not_exists`。 |

`{N}`は行番号、`{列名}`は列の見出しを示す。取込時の行エラーは画面内のエラー一覧として表示する。

## 試行制限

本機能では試行制限を扱わない。ログイン枠の共通制限を正とする。

---

## ログ・監査

| タイミング | 記録内容 |
|------------|----------|
| 取込開始 | 「セール用価格変更CSV登録開始」。 |
| 取込完了 | 「セール用価格変更CSV登録完了」と取込件数。 |
| 取込異常終了 | 「セール用価格変更CSV登録 異常終了」。 |
| 取込成功時 | 取込履歴にファイル名・日時・作業者を記録する。 |

### ログに出してはいけないもの

- なりすまし対策トークン・セッション識別子の完全値
- Cookie値
- アップロードCSVの全行の生データ

---

## セッション

本機能では検索条件等の一覧状態を更新しない。成功・エラーフラッシュは管理画面共通の仕組みに依存する。

---

## Cookie

管理画面のセッションCookieのみを正とし、本機能用の追加Cookieは定義しない。

---

## 排他制御・トランザクション

取込は単一トランザクションで行い、行検証エラーがあれば全体をロールバックする。取込中は行ロックのタイムアウトを設定する。一定件数ごとにflushしてメモリを解放する。取込成功時はトランザクションを確定したうえで支店連携を通知する。
