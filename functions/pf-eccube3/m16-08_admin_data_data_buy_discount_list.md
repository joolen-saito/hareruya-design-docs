# データ管理 — 買取減額率一覧

## 概要

HareruyaEc プラグインが管理画面の「データ管理」から提供する、買取用の減額率マスタ（行）× カード状態マスタのコード（列）に対応する減額率（数値）を矩形式で一覧表示する閲覧専用画面である。交差情報は `dtb_buy_discount_card_condition` を読み、その組み合わせが無いセルには固定文言「未定義」を出す。

本書は実装手順ではなく、誰が・いつ・どの条件で・結果どうなるかを読むためのリバース詳細設計とする。カスタマイズ区分は「現行踏襲」。画面・挙動は pf-eccube3 に配置された HareruyaEc プラグインのソースを確認値とし、DB関連（テーブル・列・型・制約・関連）は ec-cube-enterprise の実装を正とする。本機能のマスタは両リポで同一スキーマである。

対象はブラウザ経由の管理画面に限定する。

本文ではフレームワークのコントローラ型名やメソッド名を主説明としない。本文ではルートbind名やSymfonyのルートnameの網羅は主説明としない。「利用者視点の入口」にHTTPメソッドとサイトルートからのパスパターンを書く。コード探索でbind名が必要なときだけ「調査補助」へ書く。

## リニューアル移行時の扱い

- 本機能の DB は現行（pf-eccube3 の HareruyaEc プラグイン）と移行先（ec-cube-enterprise コア）で同一スキーマである。`mtb_buy_discount`・`mtb_card_condition`・`dtb_buy_discount_card_condition` のテーブル名・列名・型は一致するため、DB記述はそのまま移行先の正とする。
- 画面・挙動は現行（pf-eccube3）の確認値。買取減額率（行）×カード状態コード（列）のマトリクス閲覧という機能は移行先でも同等で、現行はプラグイン提供、移行先はコア提供である。
- 現行と移行先でスキーマ差・挙動差は確認されていない。差が生じた場合のみ本節に追記する。

## フロント挙動

| 観点 | 内容 |
|------|------|
| 表示要素 | Twig の `{% block title %}` は「買取減額率管理」、`{% block sub_title %}` は「買取減額率一覧」。親ナビの項目名は「買取減額率一覧」であり、タイトル帯の「買取減額率管理」とは文言が一部異なる。表は Bootstrap の `table table-striped`。左端ヘッダは「名称」。以降の列ヘッダは、`mtb_card_condition` を取得した順に `code` のみ（和名や英名は出さない）。各行の第一データ列は対応する `mtb_buy_discount` の名称。それ以降のセルは、交差があるとき PHP が渡した浮動小数（`dtb_buy_discount_card_condition.rate` に由来）を Twig がそのまま文字列変換した形で出力し、桁区切りや `%` は付けない。交差が無いセルは「未定義」。 |
| JS 挙動 | `buy_discount.twig` 側に `<script>` ブロックやインライン処理はなく、本画面単体での動的処理はしない。共通管理画面フレームの JS に依存する範囲に留める。 |
| CSS・レイアウト | 表ラッパーに `table-responsive with-border`。本テンプレート単体での追加スタイル読み込み指定はない（親フレームの既定に従う）。 |
| モーダル・ポップアップ | 定義しない。 |

補足。表頭行のひとつの要素 id はテンプレート上 `news_list_box__list_header` という識別子になっており、ニュース機能由来の名前と食い違っている。表示内容には効かない。

## 処理フロー

### 一覧を表示する（GET `admin_buy_discount_list`）

1. 管理画面の認証・共通制約を通過する。
2. `mtb_card_condition` に対応するエンティティをリポジトリの `findAll()` で読み込む。
3. `mtb_buy_discount` に対応するエンティティを同様に `findAll()` で読み込む。
4. `dtb_buy_discount_card_condition` の全行を `findAll()` で読み込む。
5. `dtb_buy_discount_card_condition` ごとに、カード状態 ID と買取減額率 ID をキーの二段配列 `$buyDiscountMap[cardConditionId][buyDiscountId]` に浮動小数 `rate` を格納する（同一キーへの二重代入は後勝ち）。
6. 上記データを Twig に渡し、`buyDiscounts` と `cardConditions` の二重ループで表を出力する。
7. 各セルでは `buyDiscountMap[condition.id][buyDiscount.id]` が定義されていれば値を、その他は「未定義」を表示する。
8. サーバ側はこのリクエスト中にフラッシュやセッション検索状態を設定する処理を持たない。

## 業務ルール・計算

画面上のセル値は入力変換計算ではなく、`dtb_buy_discount_card_condition.rate` の参照である。並べ替え・丸め・百分率への換算は行わない。

本機能ではフォームによる入力・保存を行わないため、`### 入力項目` は置かない。

### エッジケース

| ケース | 扱い |
|--------|------|
| 買取減額率マスタが 0 件 | `buyDiscounts` ループが回らず、ヘッダと空の tbody だけが描画される。 |
| カード状態マスタが 0 件 | 列ヘッダは「名称」のみになり、すべてのデータ行も名称列のみになる。 |
| 交差行が無い | 名称列だけ値が並び、その他すべてのセルは「未定義」。 |
| 同一 `(buy_discount_id, card_condition_id)` に複数行が論理的に存在し得ない | 複合主鍵であり、一意制約側の前提。一覧は `findAll()` の順にマップへ入れ、`foreach` で上書きが起きれば最後に読んだ行の `rate` が残る運用となる（通常は複数行は想定されない）。 |
| 浮動小数の表示形式 | Twig の単純出力のため、`0.95` と `0.949999999` のような桁落ち気味の表現がブラウザ上に見え得る。 |

## データ整合性

| 観点 | 内容 |
|------|------|
| 一覧と DB | 当該 GET 処理で読んだ 3 集合の結果をその場で組み立てている。一覧表示中は他利用者の更新との整合をロックしない。 |
| 欠損交差と「未定義」 | 「未定義」は永続データの NULL フラグではなく、マップにキーが無いことの結果としての表示のみである。 |
| 状態マスタの列並び | 列順はカード状態の `findAll()` の帰順に従う。リポジトリに明示的な `ORDER BY` は無いため、実際の並びは永続実装およびドライバの挙動に依存する。 |

## DBカラム

一覧描画と直接関係する列のみ記載する。型の細部はスキーマ・マッピングを参照する。

| テーブル | 列 | メモ |
|----------|-----|------|
| `mtb_card_condition` | `id`, `code` | 列見出しは `code`。マップおよびセル選択に `id` を使う。 |
| `mtb_buy_discount` | `id`, `name` | 行のラベル。 |
| `dtb_buy_discount_card_condition` | `buy_discount_id`, `card_condition_id`, `rate` | セルへの数値ソース。複合主鍵で組み合わせを一意化。 |

### DB操作

本機能は参照系（検索）であり、DBへの登録・更新・削除は行わない。テーブル名は ec-cube-enterprise を正典とする。

| 操作種別 | 対象テーブル | 契機・条件 |
|---------|--------------|------------|
| 検索 | dtb_buy_discount_card_condition / mtb_buy_discount / mtb_card_condition | 検索条件に合致するレコードを抽出する。 |

## 調査補助（ソース上の名前）
