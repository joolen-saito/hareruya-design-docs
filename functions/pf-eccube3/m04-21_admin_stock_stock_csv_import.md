# M04-21（在庫変更CSV登録）

商品コードと在庫増減数を並べたCSVをアップロードし、変更理由を添えて各規格の在庫数を一括で増減する取込画面。

## 概要

在庫変更CSV登録は、商品コードと在庫増減数の2列からなるCSVファイルと共通の変更理由を受け取り、1行ずつ該当規格の在庫数を増減して更新する機能である。更新ごとに在庫変更履歴を記録し、在庫が0から増えた規格には入荷通知メールを送り、更新後在庫を支店へ通知する。画面にはアップロードフォーム、ファイルフォーマット表、雛形ダウンロード、取込履歴を表示する。

本書は実装手順ではなく、誰が・いつ・どの条件で・結果どうなるかを読むためのリバース詳細設計とする。HareruyaEc プラグインの実装を確認値とする。

本機能のカスタマイズ区分はカスタマイズである。画面・処理の挙動は現行リポ（pf-eccube3 の HareruyaEc プラグイン）を参照し、DB関連（永続化先のテーブル名・列名・制約）は ec-cube-enterprise を正とする。現行と移行先でスキーマが異なる箇所は「リニューアル移行時の扱い」に集約する。

対象はブラウザ経由の管理画面に限定する。管理画面プレフィックスは HareruyaEc プラグインの設定キー `admin_route` で決まるため、本書では `%eccube_admin_route%` で示す。

本書の本文ではコントローラのメソッド名は主題としない。ルート bind 名は調査補助へ退避する。

## リニューアル移行時の扱い

DB関連は ec-cube-enterprise を正とする。現行（pf-eccube3 の HareruyaEc プラグイン）と移行先（ec-cube-enterprise）でスキーマが異なる主な点を記録する。確認できない点は推測せず要確認として残す。

| 観点 | 現行（pf-eccube3） | 移行先（ec-cube-enterprise） |
|------|--------------------|------------------------------|
| 在庫変更履歴の主キー | 機能内で `dtb_stock_history` を直接 INSERT | `dtb_stock_history.id` |
| 履歴と規格の関連 | `dtb_stock_history.product_class_id` | 規格在庫経由 `dtb_stock_history.product_stock_id` を持つ |
| 履歴の理由メモ列 | `dtb_stock_history.memo` | `dtb_stock_history.stock_change_reason` |
| 履歴の理由区分 | `dtb_stock_history.stock_change_type_id` | `dtb_stock_history.stock_change_type_detail_id` |
| 入荷集計の保持 | `dtb_product_sub_class.stock_up_quantity` | 商品サブ規格テーブルが存在せず `dtb_stock_up_quantity` テーブルで保持（ec-cube-enterprise 実装で要確認） |
| 規格の論理削除 | `dtb_product_class.del_flg` | 公開フラグ `dtb_product_class.visible`（del_flg を持たない） |

移行先 ec-cube-enterprise の在庫変更履歴は原価単価・総原価・承認者・登録者などの列を追加で持つ。本書は現行 pf-eccube3 の取込挙動を扱い、移行先で追加される列・履歴項目は本節に集約する。

## 処理フロー

### 画面表示

1. 利用者が在庫変更CSVアップロード画面を開く。
2. アップロードフォームと変更理由欄、フォーマット表（商品コード・在庫増減数）、雛形リンク、在庫変更CSV種別の取込履歴を表示する。

### アップロード

1. 利用者がCSVファイルと変更理由を送信する。タイムアウトは無効化する。
2. フォームを検証する。ファイル未選択・サイズ超過・形式不一致・変更理由未入力・変更理由超過があれば、エラーをフラッシュに並べて同一画面を再表示する。
3. 直近に同じファイル名で在庫変更CSVを取り込んでいれば「直近でアップロードされたファイル名です。ファイルを確認してください。」を表示して中止する。
4. ファイルの行数が上限（5010行）以上なら「…行を超えるCSVファイルは登録できません。」を表示して中止する。
5. 取込を開始する（ログに開始を記録）。変更理由を取込ハンドラへ渡す。
6. 1行ずつ取り込む。各行の処理は後述の判定順序に従う。
7. 取込にエラーがあれば異常終了をログに記録し、結果のエラー行を画面に表示する。
8. エラーが無ければ「商品登録CSVファイルをアップロードしました。」を表示し、件数つきで完了をログに記録し、ファイル名を在庫変更CSVの取込履歴に追加する。
9. 取込完了後、入荷対象があれば入荷通知メールを送り、更新後在庫を支店へ通知する。
10. 結果（成功フラッシュまたはエラー行）を同一画面で表示する。

## 在庫変更CSV取込時の判定順序（1行あたり）

| 順序 | 判定 | 結果 |
|------|------|------|
| 1 | 在庫増減数が0 | 更新不要として行をスキップする。 |
| 2 | 商品コードから規格を更新ロックして取得 | 取得不能なら処理を中断する。商品コードが見つからなければマスタ未存在エラー、2件以上見つかれば商品コード重複エラー、ロック取得失敗なら更新ロックタイムアウトエラー。 |
| 3 | 更新後在庫数＝現在庫＋増減数が0未満 | 在庫不足エラーとして処理を中断する。 |
| 4 | 更新後在庫数が在庫上限を超える | 更新後在庫の桁数検証でエラーとして処理を中断する。 |
| 5 | 上記を通過 | 規格拡張の入荷集計に増減数を加算し、規格在庫と規格本体の在庫数を更新後在庫で更新し、在庫変更履歴を1件追加する。 |

更新後在庫が0より大きく、更新前在庫が文字列の0だった規格は入荷通知の対象に加える。更新成立した規格は支店通知の対象に加える。エラーが起きた行があると以後の取込は中断する。

## 集計条件

| 指標 | 集計の要点 |
|------|------------|
| 取込対象行 | CSVの各データ行。在庫増減数が0の行は更新せずスキップする。 |
| 入荷通知対象 | 更新前在庫が0で更新後在庫が正に転じた規格を集める。取込成功かつ対象があれば入荷通知メールを送る。 |
| 支店通知対象 | 更新が成立した規格IDと更新後在庫を集めて支店へ通知する。 |

## 業務ルール・計算

| 項目 | 内容 |
|------|------|
| 新在庫数の計算 | 更新後在庫数＝現在庫＋在庫増減数。 |
| 商品コードの解決 | 削除フラグが立っていない商品・規格のうち、商品コードが一致する規格を1件取得する。2件以上は重複エラー。 |
| 履歴の理由メモ | 取込全体で共通の変更理由を各履歴のメモに保存する。 |
| 履歴の理由区分 | 在庫変更履歴の理由区分はマスタ更新区分とする。 |
| 入荷集計の加算 | 更新成立時、規格拡張の入荷集計に増減数を加算する。 |
| 上限・下限 | 更新後在庫が0未満になる行はエラー。更新後在庫が在庫桁数上限を超える行はエラー。 |

### 入力項目

| 項目名 | 必須／任意 | 最大長 | 初期値 | 保存先・扱い |
|--------|------------|--------|--------|----------------|
| CSVファイル選択 | 必須 | ファイルサイズ上限は設定 `csv_size`（MB）。形式はCSV相当 | 未選択 | アップロードファイル。フォームキー `import_file`（未マッピング）。必須・サイズ・形式（MIME）を検証。 |
| 変更理由 | 必須 | 最大1024文字（設定キー `inventory_plan.length.memo`） | 空 | フォームキー `memo`。各行の在庫変更履歴の理由列に共通で保存（移行先 `dtb_stock_history.stock_change_reason`、現行 `dtb_stock_history.memo`）。 |

CSVの本文は次の2列で、いずれも必須である。

| CSV列 | 内容 |
|-------|------|
| 商品コード | `dtb_product_class.product_code`。規格の特定キー。 |
| 在庫増減数 | 現在庫への加算差分。0はスキップ。 |

フォーマット表のヘッダは「商品コード（必須）」「在庫増減数（必須）」の2列を表示する。

### エッジケース

| ケース | 扱い |
|--------|------|
| 在庫増減数0の行 | 更新せずスキップする。 |
| 商品コードが見つからない | マスタ未存在エラーで取込を中断する。 |
| 商品コードが2件以上一致 | 商品コード重複エラーで取込を中断する。 |
| 更新ロックが取れない | 更新ロックタイムアウトエラーで取込を中断する。 |
| 更新後在庫が負 | 在庫不足エラーで取込を中断する。 |
| 更新後在庫が上限超過 | 桁数検証エラーで取込を中断する。 |
| 同名ファイルの再取込 | 直近同名なら取込前に中止する。 |
| 行数が上限以上 | 行数上限エラーで取込前に中止する。 |

## データ整合性

| 観点 | 内容 |
|------|------|
| 規格在庫と規格本体 | 同一更新で規格在庫 `dtb_product_stock.stock` と規格本体 `dtb_product_class.stock` を更新後在庫に揃える。 |
| 履歴との整合 | 更新成立した規格ごとに在庫変更履歴を1件作る。変更前在庫・変更後在庫・操作者を記録する。 |
| 取込の中断 | エラー行で取込全体を中断する。中断時点までの永続化はトランザクションの境界に従う（取込基盤の実装を正とする）。 |
| 同時更新 | 行ごとに規格在庫へ更新ロックを取得してから更新する。ロックが取れない場合はタイムアウトエラーとする。 |
| 支店連携 | 取込完了後に更新後在庫を支店へ通知する。連携の到達保証は連携機能側の設計を正とする。 |

## DBカラム

当機能に直接関係する列のみを示す。テーブル名・列名は ec-cube-enterprise を正とし、現行（pf-eccube3）と異なる場合は移行先名を主として現行名を括弧で添える。型の細部はスキーマを参照する。

| テーブル | 列 | メモ |
|----------|-----|------|
| dtb_product_class | id, product_code, stock, price02, visible（現行 del_flg） | 規格の特定・在庫更新。履歴の販売価格に `price02` を用いる。 |
| dtb_product | id | 公開・有効な商品の規格に限定（現行は del_flg で判定）。 |
| dtb_product_stock | stock | 規格在庫の在庫数を更新後在庫で更新。 |
| dtb_stock_up_quantity（現行 dtb_product_sub_class.stock_up_quantity。ec-cube-enterprise 実装で要確認） | （入荷集計の列） | 入荷集計の加算。 |
| dtb_stock_history | id, product_stock_id（現行 product_class_id）, stock, old_stock, sell_price, stock_change_reason（現行 memo）, stock_change_type_detail_id（現行 stock_change_type_id）, member_id, create_date | 在庫変更履歴を追加。 |
| dtb_csv_import_history | id, file_name, csv_import_type_id, member_id, create_date | 取込種別・ファイル名・登録者・登録日。 |

### DB操作

永続化の正は ec-cube-enterprise（テーブル名・操作は ec-cube-enterprise を正典）。確定できない経路は要確認とする。

| 操作種別 | 対象テーブル | 契機・条件 |
|---------|--------------|------------|
| 登録 | dtb_csv_import_history | CSV取込の実行ごとに取込履歴を1件登録する。 |
| 更新 | dtb_product_stock / dtb_product_class | 取込行の在庫数を更新する。ec-cube-enterprise では在庫書込が承認ワークフロー（dtb_stock_edit_approval 系）を経る場合があり、取込経路の永続化モデルは ec-cube-enterprise 実装で要確認。 |
| 登録 | dtb_stock_history | 在庫更新ごとに在庫変更履歴を登録する（即時記録か承認後かは M04-03 のDB操作に準じ要確認）。 |

## ログ・監査

| タイミング | 記録内容 |
|------------|----------|
| 取込開始 | 「在庫変更CSV登録開始」を記録。 |
| 取込完了 | 「在庫変更CSV登録完了」と件数を記録。取込履歴にファイル名を追加。 |
| 取込異常終了 | 「在庫変更CSV登録 異常終了」を記録。 |
| 各行の更新成立 | 在庫変更履歴に変更前在庫・変更後在庫・理由メモ・操作者を記録。 |

操作者は在庫変更履歴の `member_id` に保持する。

### ログに出してはいけないもの

- パスワード
- なりすまし対策トークン
- Cookie 値
- セッション ID の完全値
- Remember Me トークンの原値

## 排他制御・トランザクション

行ごとに該当規格の在庫へ更新ロックを取得してから在庫数を更新する。ロックが取れない場合はタイムアウトとして当該行をエラーにし取込を中断する。取込全体のトランザクション境界は取込基盤の実装を正とする。
