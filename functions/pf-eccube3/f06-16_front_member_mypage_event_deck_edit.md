# F06-16（大会デッキ登録編集）

## 概要

ログイン済み会員が、申し込んだ大会（イベント）に登録するデッキを編集・提出する機能である。デッキ登録一覧などからイベント詳細単位の編集画面に入り、フォーマットを選択し、メインボード・サイドボードのカードリスト（半角数字＋半角スペース＋カード名の行）を入力して提出する。提出時にカードリストの書式・カードを検証し、書式に誤りがあれば入力を保持したまま編集画面へ戻す。書式が通れば登録済みデッキを上書き、または新規にデッキを作成し、デッキ確認画面（枚数・カードの確認）へ遷移する。

本書は実装手順ではなく、誰が・いつ・どの条件で・結果どうなるかを読むためのリバース詳細設計とする。確認値はpf-eccube3（EC-CUBE3系）のHareruyaEcプラグインの大会デッキ編集・更新処理、テンプレート（`Mypage/deckentry.twig`）、カードリスト解析のユーティリティ処理、メッセージ（`message.ja.yml`）を正とする。

本機能のカスタマイズ区分はカスタマイズである。挙動の参照リポはpf-eccube3とし、DB関連の記述（テーブル名・列名・永続化先・副作用のDB更新）は ec-cube-enterprise を正とする。現行と移行先のスキーマ差は「リニューアル移行時の扱い」に集約する。

対象はブラウザ経由のフロント（会員マイページ）に限定する。フロントのルートは`/{_locale}`配下にマウントされ、URLは`/{_locale}/deckentry/{eventDetailId}/edit`などの形をとる。

本文ではフレームワークのコントローラ型名やメソッド名を主説明としない。本文ではルートbind名の網羅は主説明とせず、「利用者視点の入口」にHTTPメソッドとサイトルートからのパスパターンを書く。コード探索でbind名が必要なときだけ「調査補助」へ書く。

## リニューアル移行時の扱い

現行（pf-eccube3）の挙動を正としつつ、DB関連は移行先（ec-cube-enterprise）を正とする。確認できた差は次のとおり。

| 観点 | 現行（pf-eccube3） | 移行先（ec-cube-enterprise） |
|------|--------------------|------------------------------|
| デッキ本体 | デッキ（`dtb_deck`、メイン `text_main`／サイド `text_side`） | 同一名のデッキ（`dtb_deck`）。メイン `text_main`・サイド `text_side` に加え統率 `text_command` を持つ。フォーマット `format_id`・選手 `player_id`・イベント詳細 `event_detail_id`・表示区分 `disp_id`・デッキ種別 `deck_type_id`・編集者 `member_id` を関連で持つ。 |
| デッキカード | デッキカード（`dtb_deck_card`、ボード区分・カード・枚数） | デッキカード（`dtb_deck_card`、デッキ `deck_id`・カード `card_id`・ボード区分 `board_id`（`mtb_board`）・枚数 `count`）。 |
| デッキの所有者 | 選手情報に紐づく | デッキは選手情報（`dtb_player`）へ `player_id` で紐づく。 |
| 論理削除の方式 | 削除フラグ（`del_flg` 等）による論理削除 | デッキ系・イベント系は削除日時（`deleted_at`）による論理削除とする。上書き時の既存カード除去は物理削除で行う点は移行後も要確認。 |
| 登録可否判定の列 | デッキ登録フラグ・締切フラグ | イベント詳細（`dtb_event_detail`）の `deck_regist_flg`・`deadline_flg`・締切日時 `deck_regist_deadline` で判定する。 |

移行先での書式検証・上書き再構築の実装詳細は ec-cube-enterprise 実装で要確認とし、本書では現行挙動を正とする。

## 処理フロー

### デッキ編集画面を表示する（GET `/{_locale}/deckentry/{eventDetailId}/edit`）

1. 会員ログインを要求し、ログイン会員に紐づく選手情報を特定する。選手情報が無い場合は存在しない（HTTP404）として処理する。
2. イベント詳細を取得し、デッキ登録可否を判定する。問題があれば存在しない（HTTP404）として処理する。
3. 当該選手情報・イベント詳細の登録済みデッキをフォーマット別に取得する。
4. 書式エラーでのリダイレクト直後は、セッションに退避した入力（メイン・サイド・エラー）を復元し、セッションから削除する。
5. マイデッキ取得指定（`deckId`）があれば、デッキ情報取得APIで取得し、本人のデッキであればメイン・サイドの入力をマイデッキの内容で上書きし、選択フォーマットを合わせる。
6. フォーマット別サジェストファイル・マイデッキ一覧・選択中フォーマット等とともに編集画面を表示する。

### デッキを提出する（POST `/{_locale}/deckentry/{eventDetailId}/update`）

1. なりすまし対策トークンを検証する。
2. ログイン会員に紐づく選手情報を特定する。選手情報が無い場合は存在しない（HTTP404）。
3. 選択フォーマットを確定する。フォーマットが確定できない場合は存在しない（HTTP404）。
4. デッキ登録可否を判定する。問題があれば存在しない（HTTP404）。
5. メイン・サイドの入力をアリーナ形式から実カード名へ変換する。
6. メイン・サイドのカードリストを解析し、書式・カードを検証する。
7. 書式に誤りがある場合は、入力（メイン・サイド・エラー内容）をセッションへ退避し、編集画面（同一イベント詳細・選択フォーマット）へリダイレクトする。デッキは登録しない。
8. 書式が通った場合、当該イベント詳細・選手情報・フォーマットに登録済みデッキがあれば上書き（既存カードを除去して再登録）し、無ければ新規にデッキを作成する。
9. メイン・サイドのカードをデッキに登録し、編集者をクリアして保存する。
10. デッキ登録完了メールを送信する。
11. デッキ確認画面（`/{_locale}/deckentry/{deckId}/check`）へ遷移する。

## デッキ提出時の判定順序

| 順序 | 判定 | 結果 |
|------|------|------|
| 1 | なりすまし対策トークンが正当か | 不正ならアクセス拒否（フレームワークの検証による） |
| 2 | 選手情報が特定できるか | できないなら存在しない（HTTP404） |
| 3 | 選択フォーマットが確定できるか | できないなら存在しない（HTTP404） |
| 4 | イベント詳細が登録可（存在・登録フラグ有効・締切前）か | 不可なら存在しない（HTTP404） |
| 5 | メイン・サイドの書式が正しいか | 誤りなら入力を保持して編集画面へ戻す（登録しない） |
| 6 | 上記を通過 | デッキを上書きまたは新規作成し、確認画面へ遷移 |

カードの枚数（最小／最大）・禁止・制限などの判定はデッキ確認画面で行い、本機能では書式（行形式・カード存在・登録枚数の妥当性）を検証する。

## 業務ルール・計算

| 項目 | 内容 |
|------|------|
| 登録可否 | イベント詳細が存在し、デッキ登録フラグが有効で、締切前のときのみ登録できる。いずれかを満たさないと存在しない（HTTP404）。 |
| フォーマット選択 | 構築デッキ数が1のときはフォーマットを隠し項目で1つに固定し、複数のときラジオで選ばせる。提出時に選択フォーマットを確定する。 |
| 上書き／新規 | 当該イベント詳細・選手情報・フォーマットの登録済みデッキがあれば上書き、無ければ新規作成する。 |
| 書式検証 | メイン・サイドを行ごとに「半角数字＋半角スペース＋カード名」として解析し、誤りがあれば登録しない。 |
| 入力保持 | 書式エラー時は入力とエラー内容をセッションへ退避し、編集画面で復元する。 |
| 編集者クリア | 提出時にデッキの編集者を未設定にする。 |
| 完了メール | 登録成功後にデッキ登録完了メールを送信する。送信の成否は画面表示に反映しない。 |

### 入力項目

| 項目名 | 必須／任意 | 最大長 | 初期値 | 保存先・扱い |
|--------|------------|--------|--------|----------------|
| フォーマット | 構築デッキ数が複数のとき必須／1つのときは固定 | — | 既定は選択中フォーマットまたは先頭フォーマット | フォームキー`format`（フォーマット識別子）。提出時に確定し、当該フォーマットのデッキを登録する。確定できない場合は存在しない（HTTP404）。 |
| メインボード | 任意（書式が通れば登録） | テキストエリア。フォーム上限なし（DBはテキスト型） | 登録済みデッキのメインカードリスト。書式エラー戻り時は退避入力。マイデッキ取得時はその内容 | フォームキー`deckMain`。複数行入力。アリーナ形式から実カード名へ変換し、行ごとに書式・カードを検証してデッキのメインカードへ登録する。誤りがあれば登録しない。 |
| サイドボード | 任意（書式が通れば登録） | テキストエリア。フォーム上限なし（DBはテキスト型） | 登録済みデッキのサイドカードリスト。書式エラー戻り時は退避入力。マイデッキ取得時はその内容 | フォームキー`deckSide`。複数行入力。アリーナ形式から実カード名へ変換し、行ごとに書式・カードを検証してデッキのサイドカードへ登録する。誤りがあれば登録しない。 |

カード選択欄（カード名・ボード・枚数）はメイン／サイドのテキストエリアへ行を追加するための入力補助であり、提出値そのものはメイン・サイドのテキストエリアの内容とする。マイデッキ取得時の`deckId`はGETクエリで受け取り、本人のデッキのときのみ入力欄へ反映する。

| テーブル | 列 | メモ |
|---------|-----|------|
| デッキ（`dtb_deck`） | 選手参照（`player_id`）・イベント詳細参照（`event_detail_id`）・フォーマット参照（`format_id`） | 上書き対象の特定キー。 |
| デッキ（`dtb_deck`） | メインカードリスト（`text_main`）・サイドカードリスト（`text_side`） | 提出したカードリスト文字列を保存する。統率 `text_command` は本機能では扱わない。 |
| デッキ（`dtb_deck`） | 表示区分（`disp_id`）・デッキ種別（`deck_type_id`）・編集者（`member_id`） | 新規作成時は非公開・大会用デッキ種別で作成し、提出時に編集者をクリアする。 |
| デッキカード（`dtb_deck_card`） | デッキ参照（`deck_id`）・ボード区分（`board_id`、`mtb_board`）・カード（`card_id`）・枚数（`count`） | 解析結果をメイン・サイドのボードごとに登録する。上書き時は既存を除去する。 |
| イベント詳細（`dtb_event_detail`） | デッキ登録フラグ（`deck_regist_flg`）・締切フラグ（`deadline_flg`）・登録締切日時（`deck_regist_deadline`） | 登録可否判定に用いる。 |

### DB操作

永続化の正は ec-cube-enterprise（テーブル名・操作は ec-cube-enterprise を正典）。当ドメインは承認ワークフローを介さず persist/flush で直接確定する（承認ワークフローは在庫機能固有）。

| 操作種別 | 対象テーブル | 契機・条件 |
|---------|--------------|------------|
| 登録/更新 | dtb_deck / dtb_deck_card / dtb_event_detail / mtb_board | 当機能が行う登録・更新で対象テーブルを直接保存する（不要な削除は含まない）。確定は persist/flush による即時反映。DB=ec-cube-enterprise を正典とする。 |

## バリデーション

| 項目 | 内容 |
|------|------|
| フォーマット | 提出時にイベントのフォーマットから選択値を確定する。確定できないと存在しない（HTTP404）。 |
| メインボード | 行ごとに「半角数字＋半角スペース＋カード名」として解析する。書式に誤りがあれば登録せず編集画面へ戻す。 |
| サイドボード | メインボードと同じ書式で解析・検証する。 |
| なりすまし対策トークン | 提出時に検証する。 |
| 登録可否 | イベント詳細の存在・登録フラグ・締切で判定する。 |

枚数（最小／最大）・禁止・制限などのカード単位の検証はデッキ確認機能を正とする。

## 権限・認可

| 利用者状態 | デッキ編集画面 | デッキ提出（更新） |
|------------|----------------|--------------------|
| 未ログイン | アクセス不可。会員ログインへ誘導する。 | アクセス不可。会員ログインへ誘導する。 |
| ログイン済み会員（選手情報あり） | 自分の選手情報のデッキのみ編集可能。登録不可イベントは存在しない（HTTP404）。 | 自分の選手情報のデッキのみ提出可能。 |
| ログイン済み会員（選手情報なし） | 存在しない（HTTP404）。 | 存在しない（HTTP404）。 |

## 画面遷移

| 条件 | 遷移先 |
|------|--------|
| デッキ登録一覧などの編集リンク | デッキ編集画面（`GET /{_locale}/deckentry/{eventDetailId}/edit`） |
| 「マイデッキを取得」（フォーマット選択） | デッキ編集画面（`?deckId=…&format=…`、入力欄へ反映） |
| 「デッキリストを提出する」・書式OK | デッキ確認画面（`/{_locale}/deckentry/{deckId}/check`へ遷移） |
| 「デッキリストを提出する」・書式エラー | デッキ編集画面（同一イベント詳細・選択フォーマット、入力保持で再表示） |
| 登録不可・選手情報なし・フォーマット未確定 | 存在しない（HTTP404） |
| 「キャンセル」リンク | イベント一覧（`/{_locale}/events`） |

### 遷移時に引き継ぐ状態

| 起点 | 遷移前の処理 | 遷移後の初期状態 |
|------|--------------|------------------|
| 提出・書式エラー | メイン・サイドの入力とエラー内容をセッションへ退避する | 編集画面でメイン・サイドの入力とエラー見出しを復元し、退避値はセッションから削除する |

---

## エラー処理

| エラー内容 | 処理 |
|------------|------|
| なりすまし対策トークン不正 | アクセス拒否（フレームワークの検証による）。 |
| 選手情報なし・登録不可イベント・フォーマット未確定 | 存在しない（HTTP404）。 |
| メイン・サイドの書式エラー | 登録せず入力を保持して編集画面へ戻す。表示文言は表示メッセージ節を正とする。 |
| 未ログインアクセス | 会員ログインへ誘導する（会員ログイン機能を正とする）。 |

---

## ログ・監査

本機能はデッキ編集・提出に固有の監査ログを主目的としない。登録確定後にデッキ登録完了メールの送信を行う。

### ログに出してはいけないもの

- なりすまし対策トークン
- Cookie値
- セッションIDの完全値

---

## セッション

### 本機能におけるセッション

| 観点 | 内容 |
|------|------|
| 書式エラー時の入力退避 | 提出の書式エラー時に、メイン・サイドの入力とエラー内容をセッションへ退避する。 |
| 編集画面表示時の復元 | 編集画面表示時に退避値を読み出して入力欄・エラー見出しへ反映し、セッションから削除する。 |

### セッションへ保存しない情報

なりすまし対策トークンの原値・Cookie値はセッションの設計対象として本書では原値を記載しない。

---

## 排他制御・トランザクション

提出時のデッキ上書きは既存カードの除去と再登録を保存で確定する。本機能では楽観ロック・悲観ロックの対象は持たない。
