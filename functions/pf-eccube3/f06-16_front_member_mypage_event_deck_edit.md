# F06-16（大会デッキ登録編集）

## 業務ロジック

### 登録できる条件

会員ログインを要求し、ログイン会員に紐づく選手情報を特定する。選手情報が無いときは画面を表示しない。

イベント詳細が存在し、デッキ登録フラグが有効で、締切前のときだけ登録できる。いずれかを満たさないときは画面を表示しない。

### 画面の内容

見出し「登録デッキ編集」、会員氏名と「様」、利用ガイドリンク、イベント名（フォーマット併記）・開催日時・DCIナンバー・お名前、フォーマット選択、カード選択（カード名入力・サジェスト・ボード選択・枚数選択）、メインボードとサイドボードの入力欄、入力形式の注意事項、「デッキリストを提出する」・「キャンセル」を表示する。

フォーマットは、イベントの構築デッキ数が1のときは隠し項目として1つに固定し、複数のときはラジオで選ばせる。カード名入力にはフォーマット別のサジェストを用いる。

デッキリストのインポートはテキストを貼り付けるモーダルで受け付ける。マイデッキ一覧はフォーマット絞り込みとページ送りを持つモーダルで表示する。モーダルを閉じても画面は遷移しない。

### 入力の書式

メインボードとサイドボードは複数行の入力とする。1行は「半角数字＋半角スペース＋カード名」とする。全角数字・全角スペースは使用できない。カード名は日本語・英語のいずれかとする。

### マイデッキの取り込み

マイデッキを指定したときは、そのデッキの内容でメインボードとサイドボードの入力を上書きし、選択フォーマットを合わせる。本人のデッキでないときは上書きしない。

### 提出の判定順序

| 順序 | 判定 | 結果 |
|------|------|------|
| 1 | なりすまし対策トークンが正当か | 不正なら受け付けない |
| 2 | 選手情報が特定できるか | できないなら画面を表示しない |
| 3 | 選択フォーマットが確定できるか | できないなら画面を表示しない |
| 4 | イベント詳細が登録可（存在・登録フラグ有効・締切前）か | 不可なら画面を表示しない |
| 5 | メイン・サイドの書式が正しいか | 誤りなら登録せず、入力を保持して編集画面へ戻す |
| 6 | 上記を通過 | デッキを上書きまたは新規作成し、確認画面へ遷移する |

### 提出したときの登録内容

メイン・サイドの入力をアリーナ形式から実カード名へ変換したうえで解析する。

当該イベント詳細・選手情報・フォーマットの登録済みデッキがあれば、既存のカードを取り除いてから登録し直す。無いときは新規にデッキを作る。提出時にデッキの編集者を未設定にする。

登録が終わったらデッキ登録完了メールを送信する。送信の成否は画面表示に反映しない。

### 他機能との境界

枚数の最小・最大、禁止カード、制限カードの判定はデッキ確認画面で行う。本機能が検証するのは行の書式、カードの存在、登録枚数の妥当性である。

### エラー時の扱い

書式に誤りがあるときは、入力とエラー内容を保持して編集画面へ戻す。デッキは登録しない。未ログインのときは会員ログインへ誘導する。

## 入出力

| 種類 | 内容 |
|------|------|
| 入力 | 選択フォーマット、メインボード、サイドボード、なりすまし対策トークン、マイデッキ取り込み時の対象デッキ。 |
| 成功時出力 | デッキの上書きまたは新規登録、デッキ確認画面への遷移、デッキ登録完了メールの送信。 |
| 失敗時出力 | 書式エラー時は入力を保持した編集画面。選手情報なし・登録不可・フォーマット未確定のときは画面を表示しない。 |

### 入出力: 永続化

| 操作 | 契機 |
| --- | --- |
| デッキの登録 | 登録済みデッキが無い状態での提出 |
| デッキの更新（既存カードの削除と再登録） | 登録済みデッキがある状態での提出 |
