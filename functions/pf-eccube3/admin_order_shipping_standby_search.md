# admin_order_shipping_standby_search（管理画面_受注管理_出荷指示リスト検索）

## 業務ロジック

### 初期表示

検索画面を開いた時点では一覧を作らない。ページ件数は既定の表示件数とし、一覧領域は描画しない。過去に保持した検索条件があっても、初期表示では復元しない。

### 並び順の決定

ソートキーはリクエストの指定を優先し、指定が無ければ前回の指定、それも無ければ既定とする。並び順も同様に、リクエストの指定、前回の指定、既定の降順の順で決める。ソートキーは既定が出荷指示リストのID、ほかに作成日時・更新日時を指定できる。未知のソートキーは既定へ戻す。並び順は大文字化して比較し、昇順以外はすべて降順として適用する。並び順の指定が昇順・降順のいずれとも一致しないときは並び順エラーを表示し、一覧を載せない初期表示の状態へ戻る。

### 表示件数の決定

指定された表示件数が表示件数マスタのいずれかと一致するときだけ採用し、以降の検索へ引き継ぐ。許容外の値は無視し、前回の値または既定の表示件数を用いる。マスタの集合に現在の表示件数が含まれないときは調整する。

### 検索条件の引き継ぎ

送信された検索条件が得られないときは、前回保持した検索条件を復元して検索する。どちらも得られないときは一覧を作らない初期表示に戻る。検索実行時は、ページ番号・検索条件・ソートキー・並び順・表示件数を次回以降のために保持する。ページ番号だけを指定して開いたときは、保持した検索条件から一覧を再構築する。

### 検索条件の適用順

値が空とみなされる条件は句を付けない。すべての入力が実質空のときは、並び順のみを適用した一覧になる。

| 順序 | 画面上の項目 | 条件 |
|------|--------------|------|
| 先頭固定 | 並び順 | ソートキーは既定が出荷指示リストのID、ほかに作成日時・更新日時。未知キーは既定に戻す。並び順は昇順以外をすべて降順として適用する |
| 1 | 出荷指示リストID | 出荷指示リストのIDが完全一致 |
| 2 | 注文番号 | 該当受注が1件でも含まれる出荷指示リストだけを残す |
| 3 | 作成日（開始） | 作成日時が指定日以上 |
| 4 | 作成日（終了） | 作成日時が指定日以下 |
| 5 | 更新日（開始） | 更新日時が指定日以上 |
| 6 | 更新日（終了） | 更新日時が指定日以下 |
| 7 | 受注種別 | チェック済みの受注種別のいずれかに一致するものだけを残す。未選択なら条件を付けない |

### 件数と重複

一覧の総件数は、一覧と同一の検索条件から求めるため一覧と一致する。注文番号での絞り込みは受注を結合するため行が増えうるが、出荷指示リスト単位で一意化する。

### ページング

指定されたページ番号と表示件数で分割する。検索実行の開始時はページ番号を1とする。総件数と現在ページの組み合わせが空ページになるときは、ページ番号を1減らして再度分割する。

## 入出力

| 種類 | 内容 |
|------|------|
| 入力 | 出荷指示リストID、注文番号、作成日・更新日の期間、受注種別、ページ番号、表示件数、ソートキー、並び順 |
| 成功時出力 | 検索条件に一致する出荷指示リストの一覧、ページ送り、表示件数の選択肢 |
| 失敗時出力 | 並び順が不正なときは並び順エラーを表示し、一覧を載せない初期表示に戻る |

本機能は検索と一覧表示のみで、データを更新しない。
