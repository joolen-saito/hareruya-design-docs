# 会員 — 会員情報変更

## 概要

ログイン済み会員が、自分の会員情報（氏名・カナ・メールアドレス・パスワード・住所・電話番号・生年月日・性別・国・MTG Companion登録名など）を編集して更新する機能である。同一URLでフォームを表示し、送信内容が妥当であればパスワードや選手情報を更新し、店舗POS（スマレジ）へ会員情報更新を連携し、支店システムへ通知したうえで会員情報変更完了画面へ遷移する。本機能には独立した確認画面はなく、編集画面の送信で直接更新する。

本書は実装手順ではなく、誰が・いつ・どの条件で・結果どうなるかを読むためのリバース詳細設計とする。確認値はpf-eccube3（EC-CUBE3系）のHareruyaEcプラグインの会員情報変更処理、会員情報変更テンプレート（`Mypage/change.twig`）、会員登録フォーム種別（`entry`）とその拡張、選手情報・配送先を扱うリポジトリ、スマレジ連携サービスを正とする。

本機能のカスタマイズ区分はカスタマイズである。挙動の参照リポはpf-eccube3とし、DB関連の記述（テーブル名・列名・永続化先・副作用のDB更新）は ec-cube-enterprise を正とする。現行と移行先のスキーマ差は「リニューアル移行時の扱い」に集約する。

対象はブラウザ経由のフロント（会員マイページ）に限定する。フロントのルートはサイトルート直下に言語別プレフィックス`/{_locale}`を付けて公開する。

本文ではフレームワークのコントローラ型名やメソッド名を主説明としない。ルートbind名の網羅は主説明とせず、「利用者視点の入口」にHTTPメソッドとサイトルートからのパスパターンを書く。

- 入力項目とバリデーション、未変更パスワードの扱い
- 更新時の副作用（パスワード再設定、選手情報更新、本人確認ステータスの未確認化、既定配送先への反映、スマレジ連携、支店連携）

## 本書で扱わないこと

以下は本書では仕様確定せず、実装または別機能の設計を正とする。

- 会員ログイン認証そのもの（未ログイン時の誘導は会員ログイン機能を正とする）
- スマレジ連携サービス・支店連携サービスの内部仕様
- 配送先の新規登録・編集の独立機能（配送先登録機能を正とする。本書は既定配送先への氏名・住所反映のみ）
- オンライン本人確認の仕様（本人確認機能を正とする。本書はステータスの未確認化のみ）
- 会員情報変更完了画面の文面詳細（完了画面テンプレートを正とする）

## リニューアル移行時の扱い

現行（pf-eccube3）の挙動を正としつつ、DB関連は移行先（ec-cube-enterprise）を正とする。確認できた差は次のとおり。

| 観点 | 現行（pf-eccube3） | 移行先（ec-cube-enterprise） |
|------|--------------------|------------------------------|
| 郵便番号の列構成 | 国内は分割（`zip01`／`zip02`）、海外は `zipcode` | 会員（`dtb_customer`）は単一の `postal_code`（国内）と `abroad_postal_code`（国外郵便番号）に統合する。 |
| 住所の列構成 | `addr01`／`addr02` | `addr01`／`addr02`／`addr03` の3列を持つ。 |
| 会員の論理削除 | 削除フラグ（`del_flg`） | `del_flg` を維持する（同一方式）。 |
| 選手情報の本人確認ステータス | 選手情報（`dtb_player`）のステータス列 | 本人確認ステータス（`dtb_player.identity_confirm_status_id`）で保持し、住所・氏名・生年月日の変更で未確認へ戻す。選手情報は削除日時（`deleted_at`）による論理削除とする。 |
| 選手情報の英字・和文氏名 | 英字姓・名 | `first_name_en`／`last_name_en`（英字）、`first_name_jp`／`last_name_jp`（和文）に保持する。 |
| 既定配送先 | 配送先（`dtb_customer_address`）の既定フラグ行 | 既定フラグ行（`dtb_customer_address`）。郵便番号は `postal_code`／`abroad_postal_code`、届け先名称は `address_name` 列に統合する。 |

スマレジ連携・支店連携の移行後実装は ec-cube-enterprise 実装で要確認とし、本書では現行挙動を正とする。

## 利用者視点の入口

| 入口 | URLエンドポイント | 期待されるふるまい |
|------|--------------------|--------------------|
| マイページの「会員情報変更」 | `GET /{_locale}/mypage/change` | 現在の会員情報を初期表示した編集フォームを表示する。 |
| 「変更する」送信 | `POST /{_locale}/mypage/change` | 入力が妥当でスマレジ連携に成功すると会員情報を更新し、会員情報変更完了画面へリダイレクトする。妥当でない場合・連携失敗時は同画面を再表示する。 |
| 国・本人確認状態の再描画 | `POST /{_locale}/mypage/change`（`isChange`または`countryCode`付き） | 入力を保持したまま編集フォームを再描画する（国に応じた住所項目の切替）。更新は行わない。 |

`/{_locale}`は言語別プレフィックスである。`/mypage`配下は会員ログインを要する。同一URLでGETの初期表示とPOSTの更新・再描画を受ける。クエリ`shop`が付く場合は支店指定をセッションへ保存する。

## フロント挙動

| 観点 | 内容 |
|------|------|
| 表示要素 | 見出し「会員情報変更」。氏名（姓・名）、カナ（姓・名）、メールアドレス（確認用と2欄）、国、郵便番号、都道府県、住所、電話番号、生年月日、性別、パスワード（確認用と2欄）、MTG Companion登録名（英字姓・名）などの編集欄と「変更する」ボタンを表示する。 |
| JS挙動 | 国の選択に応じて住所項目（日本の郵便番号・都道府県／海外の郵便番号）を切り替えるため、`isChange`・`countryCode`を伴う再描画を行う。会員IDとパスワードが同一の状態を画面側で判定して案内する。 |
| CSS・レイアウト | 会員登録系のスタイルを用いる。利用者の挙動理解に影響する分岐は国による住所項目の切替である。 |
| モーダル・ポップアップ | 本画面専用のモーダルは無い。 |

メールアドレスは確認用を含む2欄で、両欄一致を要する。パスワードも確認用を含む2欄で、初期表示はマスク用の既定値を載せ、未変更ならパスワードを更新しない。MTG Companion登録名は選手情報側へ保存する英字姓・名の2項目である。

## 処理フロー

### 会員情報変更画面を表示する（GET `/{_locale}/mypage/change`）

1. クエリ`shop`があれば支店指定をセッションへ保存する。
2. ログイン会員を複製して保持し、表示用のパスワード欄にはマスク用の既定値を載せる。
3. 会員登録フォーム種別で編集フォームを生成し、現在の会員情報を初期表示する。
4. 送信状態でないため、編集フォームを表示する。選手情報の英字氏名も初期表示する。

### 会員情報を更新する（POST `/{_locale}/mypage/change`）

1. ログイン会員を複製して保持する。
2. フォームを検証する。`isChange`付き、または未送信・検証不成立の場合は、認証ユーザを複製で戻し、編集フォームを再描画する。更新は行わない。
3. 検証に通り、かつ会員IDとパスワードが同一でない場合に更新を進める。なりすまし対策トークンを再生成し、会員編集開始の情報ログを記録する。
4. パスワード欄がマスク用の既定値のままなら従前のパスワードを維持する。変更されている場合はソルトを用意して暗号化し再設定する。
5. 国を会員へ設定する。
6. 選手情報のメール・英字氏名・和文氏名・更新日時を更新する。
7. 国・郵便番号・都道府県・住所が変更され、現在の本人確認ステータスが確認済みまたは簡易書留確認済みなら、本人確認ステータスを未確認へ戻す。
8. 氏名・カナ・生年月日が変更され、現在のステータスが確認済みなら、本人確認ステータスを未確認へ戻す。
9. 既定フラグが立つ配送先へ会員の氏名・カナ・郵便番号・住所・国・都道府県・会社名・電話番号を反映する。
10. スマレジへ会員情報更新を連携する。失敗した場合は更新を中止し、エラーメッセージを表示して編集フォームを再描画する。
11. 連携成功時は変更を確定し、会員編集完了の情報ログと会員編集ログ（会員ID）を記録する。
12. 支店システムへ当該会員の更新を通知する。
13. 会員情報変更完了画面へリダイレクトする。

## 業務ルール・計算

| 項目 | 内容 |
|------|------|
| パスワード未変更の判定 | 表示時にパスワード欄へマスク用の既定値を載せ、送信値が既定値のままなら従前パスワードを維持する。変更時はソルトを用意して暗号化し再設定する。 |
| 会員 IDとパスワードの同一判定 | 会員IDとパスワードが同一の場合は更新を進めず、編集フォームを再描画する。 |
| 国と都道府県の整合 | 日本と海外の組み合わせ不整合を送信後の検証で拒否する。 |
| 本人確認ステータスの未確認化 | 住所系（国・郵便番号・都道府県・住所）の変更時は確認済み・簡易書留確認済みから未確認へ戻す。氏名・カナ・生年月日の変更時は確認済みから未確認へ戻す。 |
| 既定配送先への反映 | 既定フラグが立つ配送先へ会員の氏名・カナ・住所・電話番号・会社名等を反映する。 |
| スマレジ連携の前提 | スマレジ会員情報更新の成功を更新確定の前提とする。失敗時は確定しない。 |

| メールアドレス | 必須 | フォーム上限なし（メール形式） | 現在のメール | `dtb_customer.email`。フォームキー`email`（確認用2欄、両欄一致）。選手情報のメール（`dtb_player`）にも反映する。 |

| 都道府県 | 国により必須 | 選択式 | 現在の都道府県（海外は海外固定） | `dtb_customer.pref_id`。フォームキー`pref`。住所系変更で本人確認ステータスを未確認化。 |
| 住所（市区町村番地・建物名等） | 必須 | 実装の住所検証に従う | 現在の住所 | `dtb_customer.addr01`／`addr02`／`addr03`（現行は`addr01`／`addr02`）。フォームキー`addr01`／`addr02`。住所系変更で本人確認ステータスを未確認化。 |
| 電話番号 | 必須 | 電話番号分割形式 | 現在の電話番号 | `dtb_customer.tel01`／`tel02`／`tel03`。フォームキー`tel`。既定配送先へも反映。 |

| 性別 | 任意 | 選択式 | 現在の性別 | `dtb_customer.sex_id`。フォームキー`sex`。 |

最大長の根拠は`src/Eccube/Resource/config/constant.yml.dist`の確認値（`name_len`=16、`kana_len`=25、`stext_len`=50、`birth_max`=110）と、HareruyaEcの設定（海外郵便番号10文字）。環境で上書きされている場合は注記が必要である。

| ケース | 扱い |
|--------|------|

## データ整合性

| 観点 | 内容 |
|------|------|
| 会員と選手情報 | 更新時、会員情報と選手情報の更新を同一の確定処理で反映する。 |
| 既定配送先 | 既定フラグが立つ配送先へ会員の氏名・住所等を反映する。既定でない配送先は変更しない。 |
| スマレジ | スマレジ会員情報更新の成功を更新確定の前提とする。失敗時はDBを変更しないため、画面表示とDBは更新前のまま一致する。 |
| 支店システム | 更新確定後に通知する。支店側反映の時点整合は本書では保証しない。 |

|---------|-----|------|
| `dtb_customer` | `name01` / `name02` / `kana01` / `kana02` | 氏名・カナ。既定配送先へも反映。 |
| `dtb_customer` | `email` | メールアドレス。選手情報にも反映。 |
| `dtb_customer` | `password` / `salt` | 未変更時は維持、変更時はソルト生成のうえ暗号化。原値・ハッシュは不可逆値として扱う。 |
| `dtb_customer` | `country_id` / `pref_id` / `postal_code` / `abroad_postal_code` / `addr01` / `addr02` / `addr03` | 国・住所。現行は`zip01`／`zip02`／`zipcode`・`addr01`／`addr02`。変更時に本人確認ステータスへ影響。 |
| `dtb_customer` | `tel01` / `tel02` / `tel03` / `birth` / `sex_id` / `company_name` | 電話番号・生年月日・性別・会社名。 |
| `dtb_player` | `email` / `first_name_en` / `last_name_en` / `first_name_jp` / `last_name_jp` / `update_date` | 選手情報を更新する。和文氏名は`first_name_jp`／`last_name_jp`。 |
| `dtb_player` | `identity_confirm_status_id` | 本人確認ステータス。住所・氏名・生年月日の変更で未確認へ戻す。 |
| `dtb_customer_address` | 既定配送先行（届け先名称は`address_name`、郵便番号は`postal_code`／`abroad_postal_code`） | 既定フラグが立つ行へ会員の氏名・住所等を反映。 |

### DB操作

永続化の正は ec-cube-enterprise（テーブル名・操作は ec-cube-enterprise を正典）。当ドメインは承認ワークフローを介さず persist/flush で直接確定する（承認ワークフローは在庫機能固有）。

| 操作種別 | 対象テーブル | 契機・条件 |
|---------|--------------|------------|
| 登録/更新 | dtb_customer / dtb_customer_address / dtb_player | 当機能が行う登録・更新で対象テーブルを直接保存する（不要な削除は含まない）。確定は persist/flush による即時反映。DB=ec-cube-enterprise を正典とする。 |

## バリデーション

| 項目 | 内容 |
|------|------|
| 氏名・カナ | 必須。最大長は会員登録フォームに準じる。 |
| メールアドレス | 必須・メール形式。確認用2欄の一致を要する。 |
| パスワード | 確認用2欄の一致を要する。未変更（マスク値のまま）なら更新しない。 |
| 国・都道府県 | 必須。日本と海外の組み合わせ不整合を送信後検証で拒否する。 |
| 住所 | 必須。住所形式の検証を行う。 |
| 生年月日 | 必須。未来日は不可。年範囲は当年から110年前まで。 |
| MTG Companion登録名 | 任意。各128文字以内。 |
| なりすまし対策トークン | 更新POSTで検証し、検証通過時に再生成する。 |

## 画面遷移

| 条件 | 遷移先 |
|------|--------|
| マイページの「会員情報変更」 | 会員情報変更画面（`GET /{_locale}/mypage/change`） |
| 更新成功（検証通過・連携成功） | 会員情報変更完了画面（`mypage_change_complete`へリダイレクト） |
| 検証不成立・未送信・`isChange`／`countryCode`付き | 会員情報変更画面の再描画（入力保持） |
| スマレジ連携失敗 | 会員情報変更画面の再描画（エラーメッセージ付き） |

### 遷移時に引き継ぐ状態

| 起点 | 遷移前の処理 | 遷移後の初期状態 |
|------|--------------|------------------|
| クエリ`shop`付きの表示 | 支店指定をセッションへ保存する | 支店指定をセッションに保持したまま編集フォームを表示する |
| 国切替の再描画 | 入力値を保持し国に応じた住所項目を構成する | 入力値を保ったまま住所項目を切り替えて再描画する |

## エラー処理

| エラー内容 | 処理 |
|------------|------|
| 入力の検証エラー | 各項目直下にエラーを表示し編集フォームを再描画する。更新しない。 |
| 国・都道府県の不整合 | 国にエラーを付し再描画する。 |
| スマレジ連携失敗 | 更新を確定せずエラーメッセージを表示して再描画する。表示文言は表示メッセージ節を正とする。 |
| 未ログインアクセス | 会員ログインへ誘導する（会員ログイン機能を正とする）。 |

## ログ・監査

| タイミング | 記録内容 |

- Cookie値
- セッションIDの完全値

## 排他制御・トランザクション

更新時の会員情報・選手情報・既定配送先の更新は同一の確定処理で反映する。スマレジ連携の成功を確定の前提とし、失敗時はDBを変更しない。本機能では楽観ロック・悲観ロックの対象は持たない。
