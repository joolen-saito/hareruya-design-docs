# 受注管理 — 受注情報編集

## 業務ロジック

### 編集画面の表示

指定した受注が存在しないときは表示しない。受注に付帯情報がまだ無いときはこの時点で作り、担当者に操作した本人を設定する。

画面には、受注時の価格と現在の価格が違う商品の一覧、明細ごとの棚番号、明細ごとの商品名と言語・状態・Foil、店頭注文番号、配送業者ごとのお届け時間、受注一覧しきい値金額の 1 と 2 をあわせて渡す。

明細ごとの欠品数量・担当者・棚番号は明細の付帯情報から読む。付帯情報を持たない明細は欠品数量を `0` として扱う。棚番号が未設定の明細には棚番号を渡さない。

受注時の価格と現在の販売価格が違う明細は、商品規格ごとに商品名を集めて画面へ渡す。価格が同じ明細は渡さない。

発生ポイント・使用ポイント・ポイント付与率は、付帯情報が未設定のときに `0` として渡す。ポイントのエラー文言と送り状No.は、未設定のときは空のまま渡す。

店頭注文番号は受注IDから探し、見つからないときは渡さない。新規登録のときは探さない。

担当者は、削除済みであっても表示できるように読み出す。

会員検索と商品検索の入力欄を同じ画面に持つ。

### 会員の呼び出し

会員IDを 1 件指定して会員の内容を呼び出す。非同期の要求でないときは受け付けない。

指定したIDに一致する会員が無いときは、未検出として返す。

返すのは会員ID・氏名・カナ・郵便番号・都道府県・住所・メールアドレス・電話番号・FAX番号・会社名・最終購入日時・購入回数・購入金額・メモである。

最終購入日時は `Y/m/d H:i:s` の形式とし、未設定のときは空文字を返す。都道府県が未設定のときは都道府県を空で返す。メモが未設定のときは空文字を返す。購入金額は通貨の表記に整える。

### 商品の検索

商品IDとカテゴリを条件に商品を検索する。カテゴリを指定したときは、そのカテゴリに属する商品だけに絞る。非同期の要求でないときは何も返さない。

検索したときは条件とページ番号をセッションへ保存する。ページを送ったときは保存した条件で検索し、条件を指定し直さない。

1 ページの件数は既定の表示件数とする。画面から件数を変えることはできない。

商品ごとに、その商品の商品規格を選択肢とする商品コードの欄を作る。選択肢が 1 件のときも欄を作る。

### 操作の種類

編集画面からの操作は次の 4 つに分かれ、それぞれ別の経路で処理する。

| 操作 | 経路 | 対象 |
| --- | --- | --- |
| 受注の新規登録・編集の表示 | 受注編集（新規は受注ID無し、編集は受注IDを数字で指定） | 画面表示のみ |
| 受注全体の更新 | 受注更新 | 明細・金額・日付・会員情報・ポイントを含む全項目 |
| 対応状況だけの更新 | 対応状況更新 | 対応状況と、それに連動する日付のみ |
| 日付の消去 | 日付消去（消去対象を経路上で指定） | 指定した 1 つの日付のみ |

日付消去で指定できるのは、キャンセル日・入金日・注文確定日・店頭予約日・出荷指示日・出荷日の 6 つだけである。これ以外を指定した経路は受け付けない。

### 更新の順序

受注全体の更新は次の順で行う。前の段階の結果が後の段階に影響する。

1. 編集前の受注分を、会員の累計注文金額から差し引く。
2. 編集前の受注分を在庫に戻す。在庫を管理しない商品は対象外とする。
3. 明細ごとの欠品数量の変動を記録する。変わったものは欠品履歴を作る。
4. 数量から欠品数を差し引く。
5. 明細から金額を再計算する。
6. 更新後の受注分を会員の累計注文金額に加える。
7. 更新後の受注分を在庫から差し引く。
8. 本店の在庫が変わったことを支店へ知らせる。
9. 画面から取り除かれた明細を削除する。数量が 0 の明細は削除しない。

### 更新できないとき

| 条件 | 判定値 | ふるまい |
| --- | --- | --- |
| 合計金額が上限を超える | 上限は 9999999999。設定ファイルで変更できる | 明細を作り直さず、手数料の欄にエラーを出す |
| 明細の数量が在庫数を超える | 在庫数から数量と欠品による自動変更分を引いた値が 0 未満のとき | その時点で処理を打ち切り、編集画面を作り直して表示する。エラー文言には該当する商品コードが入る |
| 入力に不備がある | フォームの検証エラー | 更新しない |

合計金額の上限を超えた場合も、在庫の戻しと累計注文金額の増減はすでに実行済みである。入力に不備があるときも同じで、ここまでの計算は更新しない場合でも先に走る。

### 更新する項目

支払方法、配送業者、お届け時間、受注日、出荷指示日、入金日、注文確定日、出荷日、キャンセル日、会員情報、ポイントの使用と発生を更新する。

担当者は操作した本人に付け替え、あわせて送り状No.も更新する。

### 配送商品の作り直し

受注全体の更新では、配送先が持つ配送商品をすべて削除してから、更新後の明細をもとに作り直す。数量を変えただけのときも作り直す。

作り直す配送商品には、商品・商品規格・商品名・商品コード・規格分類名・規格名・価格・数量を写す。商品名は商品の名称を写すため、明細に記録した受注時の商品名とは違う値になることがある。

配送先を複数持つ受注では、すべての配送先に同じ配送商品を入れる。配送先ごとに明細を分けることはできない。

合計金額が上限を超えたときは、配送商品を作り直さない。

### ポイントの再計算

発生ポイントは、次の 2 つをどちらも満たすときだけ画面の入力値から計算し直す。満たさないときは画面の入力値をそのまま使う。

- 支払方法の名称に「店頭支払」を含まない。店頭支払と店頭支払(店内PC)はどちらも名称に含むため、まとめて対象外になる。
- 小計が編集前と変わったか、ポイント付与率が編集前と変わった。

計算式は次のとおりで、小数点以下は切り捨てる。

    発生ポイント = floor((小計 − 使用ポイント) × ポイント付与率 ÷ 100)

小計から使用ポイントを引いた値が 0 以下のときは、計算せず 0 とする。

### ポイントの付与とスマレジ連携

| 処理 | 実行条件 |
| --- | --- |
| ポイントを付与し、スマレジ側のポイントを加算する | 更新後の対応状況が出荷完了(5) または 引き渡し済み(11) で、かつ更新前の対応状況がそのどちらでもないとき |
| スマレジへ連携する | 受注にスマレジ取引が紐づいていて、更新後の対応状況がキャンセル(3) でないとき |
| 会員の購入回数と購入金額を更新する | 受注に会員が紐づいているとき |

もともと出荷完了または引き渡し済みだった受注を再度更新しても、ポイントは重ねて付与しない。

### 対応状況だけの更新

変更前と変更後の対応状況が同じときは、何もせず編集画面へ戻る。異なるときだけ以下を行う。

受注日・入金日と、注文確定日・出荷日・キャンセル日・店頭予約日を、更新後の対応状況に応じて現在日時で埋める。

| 更新後の対応状況 | 現在日時を入れる日付 |
| --- | --- |
| 出荷完了(5) | 配送先の発送日、および出荷日 |
| 入金済(6) | 入金日 |
| ピック中(10) | 注文確定日 |
| 店頭予約(12) | 店頭予約日 |
| キャンセル(3) | キャンセル日。ただし既にキャンセル日が入っているときは上書きせず、キャンセル処理も行わない |

配送先の発送日と入金日は、更新前と更新後の対応状況が異なるときだけ入れる。担当者は操作した本人に付け替える。

ポイントの付与とスマレジ連携の条件は、受注全体の更新と同じである。

### キャンセルしたときの処理

キャンセル日を新たに入れたときだけ、次を行う。

1. 明細ごとに在庫を戻す。在庫変動メモには注文番号を含む定型文を残す。
2. 商品規格別の週間販売数を、受注日とキャンセル日の日数差に応じて戻す。
3. 受注付帯情報の獲得ポイントを 0 にする。
4. 当該受注のポイント履歴をすべて削除し、削除した変動量の合計を求める。
5. 合計が 0 のときはここで終わる。0 でないときは会員の保持ポイントから合計を差し引き、同じ量をスマレジへ連携する。
6. スマレジからの応答に結果が含まれないときは、応答内容を退避してスマレジ連携エラーの印を立てる。

週間販売数の戻し先は日数差で決まる。日数差は受注日とキャンセル日を日付単位に丸めて求める。区分は段階的で、短い区分に該当したものは長い区分にも反映する。

| 受注日からの日数差 | 戻す集計欄 |
| --- | --- |
| 当日(0日) | 当日欄と、3日以内欄以降のすべて |
| 翌日(1日) | 翌日欄と、3日以内欄以降のすべて |
| 3日以内 | 3日以内欄以降のすべて |
| 7日以内 | 7日以内欄以降のすべて |
| 28日以内 | 28日以内欄以降のすべて |
| 90日以内 | 90日以内欄以降のすべて |
| 180日以内 | 180日以内欄以降のすべて |
| 365日以内 | 365日以内欄 |

### 日付の消去

日付消去は 1 回の操作で 1 つの日付だけを空にする。消去したあとは受注編集画面へ戻る。消去できるのはキャンセル日・入金日・注文確定日・店頭予約日・出荷指示日・出荷日の 6 つで、消去に伴う在庫やポイントの調整は行わない。

## 入出力

| 種類 | 内容 |
|------|------|
| 入力 | 受注全体の更新は明細・金額・日付・会員情報・ポイントを含む全項目。対応状況だけの更新は対応状況。日付の消去は消去する日付。 |
| 成功時出力 | 更新の反映と、指定された戻り先画面または受注編集画面への遷移。 |
| 失敗時出力 | 更新せず受注編集画面に留まる。指定した受注が存在しないときは表示しない。 |

### 入出力: 永続化

| 操作 | 契機 |
| --- | --- |
| 受注・受注付帯情報・受注明細・配送先の更新 | 受注全体の更新、対応状況だけの更新、日付の消去 |
| 配送商品の削除と再登録 | 受注全体の更新。既存の配送商品をすべて消してから明細から作り直す |
| 在庫の更新 | 受注全体の更新（戻しと引き落とし）、キャンセル時の戻し |
| 欠品履歴の登録 | 明細ごとの欠品数量が編集前と変わったとき |
| 会員の累計注文金額・購入回数・購入金額の更新 | 受注に会員が紐づいているとき |
| 商品規格別の週間販売数の更新 | キャンセル日を新たに入れたとき |
| ポイント履歴の削除と会員保持ポイントの更新 | キャンセル日を新たに入れたとき |
| 支店への在庫更新通知 | 受注全体の更新、キャンセル時の在庫戻し |
| スマレジへの連携 | ポイント付与時、キャンセル以外の更新時、キャンセル時のポイント戻し時 |
