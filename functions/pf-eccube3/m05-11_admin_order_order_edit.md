# 受注管理 — 受注情報編集

## 業務ロジック

### 編集画面の表示

受注時の価格と現在の販売価格が違う明細は、商品規格ごとに商品名を集めて画面へ渡す。価格が同じ明細は渡さない。

発生ポイント・使用ポイント・ポイント付与率は、受注の付帯情報が未設定のときに 0 として扱う。送り状No.とポイント連携エラーの文言は、未設定のときは空のままとする。

担当者は、削除済みであっても表示できるように読み出す。

### 会員の呼び出し

会員IDを 1 件指定して、その会員の内容を注文者情報の入力欄へ呼び出す。指定したIDに一致する会員が無いときは、未検出として返す。

一致する会員が無いときは、注文者情報の入力欄を変更せず、「search customer(by id) failed.」と表示する。

最終購入日時は 年/月/日 時:分:秒 の形式とし、未設定のときは空にする。購入金額は通貨の表記に整える。

### 商品の検索

商品検索の条件とページ番号は、検索したときに保持する。ページを送ったときは保持した条件で検索し、条件を指定し直さない。

1 ページの件数は既定の表示件数とし、画面から件数を変えることはできない。

### 更新の順序

受注全体の更新は次の順で行う。前の段階の結果が後の段階に影響する。

1. 編集前の受注分を、会員の累計注文金額から差し引く。
2. 編集前の受注分を在庫に戻す。在庫を管理しない商品は在庫の増減の対象外とする。
3. 更新後の受注分を会員の累計注文金額に加える。
4. 更新後の受注分を在庫から差し引く。欠品による自動変更分もあわせて差し引く。
5. 本店の在庫が変わったことを支店へ知らせる。
6. 画面から取り除かれた明細を削除する。画面に残したまま数量を 0 にした明細は削除しない。

受注全体の更新でも対応状況だけの更新でも、担当者は操作した本人に付け替える。

### 更新できないとき

| 条件 | 判定値 | ふるまい |
| --- | --- | --- |
| 合計金額が上限を超える | 上限は 9999999999 | 配送商品を作り直さず、手数料の欄にエラーを出す |
| 明細の数量が在庫数を超える | 在庫数から数量と欠品による自動変更分を引いた値が 0 未満のとき | その時点で処理を打ち切り、編集画面を作り直して表示する。エラー文言には該当する商品コードが入る |

合計金額が上限を超えたときと、入力に不備があるときは、受注を更新しないまま、支店への在庫更新通知だけが先に送られる。明細の数量が在庫数を超えたときは、通知も送らない。

### 配送商品の作り直し

受注全体の更新では、配送先が持つ配送商品をすべて削除してから、更新後の明細をもとに作り直す。数量を変えただけのときも作り直す。

作り直す配送商品には、商品・商品規格・商品名・商品コード・規格分類名・規格名・価格・数量を写す。商品名は商品の名称を写すため、明細に記録した受注時の商品名とは違う値になることがある。

配送先を複数持つ受注では、すべての配送先に同じ配送商品を入れる。配送先ごとに明細を分けることはできない。

### ポイントの再計算

発生ポイントを計算し直すときは、次の式で求める。小数点以下は切り捨てる。

    発生ポイント = (小計 − 使用ポイント) × ポイント付与率 ÷ 100

小計から使用ポイントを引いた値が 0 以下のときは、計算せず 0 とする。

### ポイントの付与とスマレジ連携

| 処理 | 実行条件 |
| --- | --- |
| ポイントを付与し、スマレジ側のポイントを加算する | 更新後の対応状況が出荷完了または引き渡し済みで、かつ更新前の対応状況がそのどちらでもないとき |
| スマレジへ連携する | 受注にスマレジ取引が紐づいていて、更新後の対応状況がキャンセルでないとき |

### 対応状況だけの更新

変更前と変更後の対応状況が同じときは、何も更新せず編集画面へ戻る。

キャンセルへ変えたとき、既にキャンセル日が入っている受注では、キャンセル日を上書きせず、キャンセルに伴う処理も行わない。

ポイントの付与とスマレジ連携の条件は、受注全体の更新と同じである。

### キャンセルしたときの処理

キャンセル日を新たに入れたときだけ、次を行う。

- 在庫を戻したことを在庫変動の履歴に残す。メモには注文番号を含む定型文を入れる。
- 商品規格別の週間販売数を、受注日とキャンセル日の日数差に応じて戻す。
- 削除したポイント履歴の変動量を合計する。合計が 0 でないときは、会員の保持ポイントから合計を差し引き、同じ量をスマレジへ連携する。合計が 0 のときは、会員の保持ポイントにもスマレジにも触れない。
- スマレジからの応答に結果が含まれないときは、応答内容を退避してスマレジ連携エラーの印を立てる。

週間販売数の戻し先は日数差で決まる。日数差は受注日とキャンセル日を日付単位に丸めて求める。区分は段階的で、短い区分に該当したものは長い区分にも反映する。

| 受注日からの日数差 | 戻す集計欄 |
| --- | --- |
| 当日(0日) | 当日欄と、3日以内欄以降のすべて |
| 翌日(1日) | 翌日欄と、3日以内欄以降のすべて |
| 3日以内 | 3日以内欄以降のすべて |
| 7日以内 | 7日以内欄以降のすべて |
| 28日以内 | 28日以内欄以降のすべて |
| 90日以内 | 90日以内欄以降のすべて |
| 180日以内 | 180日以内欄以降のすべて |
| 365日以内 | 365日以内欄 |

### 日付の消去

日付の消去では、消去に伴う在庫・ポイント・対応状況の調整は行わない。

## 入出力

| 種類 | 内容 |
|------|------|
| 入力 | 受注全体の更新は受注編集画面の全項目。対応状況だけの更新は変更後の対応状況。日付の消去は消去する日付。 |
| 成功時出力 | 更新を反映し、受注編集画面へ遷移する。 |
| 失敗時出力 | 更新せず受注編集画面に留まる。指定した受注が存在しないときは画面を表示しない。 |

### 入出力: 永続化

| 操作 | 契機 |
| --- | --- |
| 配送商品の削除と再登録 | 受注全体の更新。既存の配送商品をすべて消してから明細から作り直す |
| 在庫変動履歴の登録 | 受注全体の更新で在庫数が変わったとき、キャンセル時の在庫戻し |
| 会員の購入回数の更新 | 受注に会員が紐づいているとき |
| 商品規格別の週間販売数の更新 | キャンセル日を新たに入れたとき |
| 会員の保持ポイントの更新 | キャンセル日を新たに入れたときで、削除したポイント履歴の変動量の合計が 0 でないとき |
| 支店への在庫更新通知 | 受注全体の更新、キャンセル時の在庫戻し |
| スマレジへの連携 | ポイント付与時、キャンセル以外の更新時、キャンセル時のポイント戻し時 |
