# メンバー管理（システム情報設定／設定）

## 概要

管理画面の「システム情報設定」配下において、管理ログイン用の管理者アカウントを一覧表示し、登録・編集・削除・表示順の入れ替えを行う機能である。ページタイトルブロックは「システム設定」、サブタイトルは「メンバー管理」として表示される。ナビゲーション上の親ラベルは「システム情報設定」、子は「メンバー管理」である。

本書は実装手順ではなく、誰が・いつ・どの条件で・結果どうなるかを読むためのリバース詳細設計とする。既存実装のふるまい、参照するデータ、判定境界、副作用、フックによる拡張点を確認し、仕様の確からしさを把握することを目的とする。

対象は EC-CUBE 3 系コアのうち、ブラウザ経由の管理画面に限定する。参照するソースツリーは pf-eccube3 を正とする。

本書では Symfony のルート名、コントローラクラス名は扱わない。URL エンドポイントは `../ec-cube-enterprise` の Controller ルート定義で確認した利用者視点の入口として記載する。

---

## 本書で扱うこと

- メンバー一覧、新規登録・編集、削除、上へ・下への各操作の利用者視点の流れと結果メッセージ
- 一覧の並び、表示順入れ替え、削除時の表示順繰り下げ
- 登録・編集フォームの項目、検証、保存時のパスワード・ソルトの扱い
- カスタマイズ項目として追加される所属店舗、メールアドレス、デフォルト検索表示店舗、編集可能店舗、二段階認証、自動ログアウト設定、スマレジ用アカウントの扱い
- 編集権限を保持するメンバーだけが登録・編集できる制御
- 編集画面表示時のセキュリティトークン上のユーザー復元
- 削除・順序変更・無効 CSRF 時の応答の違い、削除対象不在時のフラッシュの扱い
- 永続化先 `dtb_member` と、新規作成時の作成者・作成日時を設定する共通Doctrineサブスクライバとの関係
- プラグイン等が利用する管理画面用イベントのディスパッチタイミング（名称はコード内の `EccubeEvents` 定数を参照）

---

## 本書で扱わないこと

以下は本書では仕様確定せず、実装または別機能の設計を正とする。

- 管理画面へのログイン、セッション、CSRF の名称形式、Remember Me、パスワードポリシー全般の詳細
- 権限マスタ（`mtb_authority`）の各行が拒否するパスの対応関係（「権限管理」画面および `AuthorityRole` 周辺の実装を正とする）
- 管理画面 IP 制限やファイアウォールの判定順序の詳細
- ログイン認証時に参照する「稼働」マスタ値（`Work::WORK_ACTIVE_ID`）と非稼働メンバーの扱いの網羅（ログイン処理の実装を正とする）
- 同じコードベースにバンドルされるプラグインが、メンバー新規・編集のルーティング先やテンプレート、フォーム項目を差し替える場合の差分。その場合は当該プラグインの実装を正とする
- 本機能以外が `dtb_member` を更新する経路（バッチ、他画面、直接SQL）の一覧

## 用語

| 用語 | 説明 |
|------|------|
| メンバー | 管理画面へログインするアカウント。`dtb_member` に保存される。フロントの会員（顧客）とは別物である。 |
| 表示順 | `dtb_member.sort_no` によるメンバー一覧の表示順。一覧は `sort_no` の降順で並べ、値が大きい行が先頭に来る。 |
| 稼働 | `mtb_work` のマスタ項目。ログイン可否の判定に利用される値（`Work::WORK_ACTIVE_ID`）がコアに定義されている。一覧ではマスタ名称を「稼働」列に表示する。 |
| 権限 | `mtb_authority` のマスタ項目。パス単位の拒否リストと組み合わせて管理画面のアクセスを制御する（詳細は権限管理機能を正とする）。 |
| 所属店舗 | メンバーの所属店舗。登録・編集画面では単一選択で指定する。 |
| デフォルト検索表示店舗 | 店舗絞り込みを持つ検索一覧画面で、当該メンバーの初期絞り込みとして利用する店舗。 |
| 編集可能店舗 | 在庫・受注・店頭買取・イベントのデータを編集できる店舗範囲。複数店舗を選択できる。 |
| 自動ログアウト設定 | ログイン後に無操作状態が続いた場合、時間経過で自動ログアウトさせるためのメンバー単位設定。制限時間は追加システム設定で管理する。 |
| スマレジ用アカウント | スマレジ連携時の更新ユーザーとして利用する管理者アカウントを識別する設定。 |
| 削除 | `dtb_member` の行を削除し、削除対象より大きい `sort_no` の行を繰り下げる。 |

## 利用者視点の入口

| 入口 | URLエンドポイント | 期待されるふるまい |
|------|--------------------|---------------------|
| ナビからメンバー一覧を開く | `GET /%eccube_admin_route%/setting/system/member` | 登録済みメンバーが `sort_no` 降順の表で表示される。各行に名前・所属・権限名・稼働名が表示され、操作メニュー（編集、削除、上へ、下へ）と新規登録ボタンがある。 |
| 新規登録を開く | `GET /%eccube_admin_route%/setting/system/member/new` | 編集権限を保持するメンバーの場合、空のメンバー向けフォームが表示され、登録ボタンと一覧へ戻るリンクがある。 |
| 既存行の編集を開く | `GET /%eccube_admin_route%/setting/system/member/{id}/edit` | 編集権限を保持するメンバーの場合、選択したメンバーの各項目がフォームに表示される。パスワード欄には設定ファイル上のプレースホルダ文字列が入った状態で表示される。 |
| 登録ボタンで送信する | `POST /%eccube_admin_route%/setting/system/member/new` または `POST /%eccube_admin_route%/setting/system/member/{id}/update` | 編集権限を保持するメンバーだけが実行できる。検証に成功すれば保存され、成功メッセージののち編集画面へ遷移する。失敗時はエラーメッセージを表示し、編集画面へ戻る。 |
| 自分と同一IDの行について削除を選ぶ | —（一覧上リンク非表示） | 一覧では削除リンクが無効表示となり、他行と同様の削除用リンクにならない。 |
| 他行の削除を実行する | `DELETE /%eccube_admin_route%/setting/system/member/{id}/delete` | 対象行を削除し、削除対象より大きい `sort_no` の行を繰り下げる。成功メッセージののち一覧へ遷移する。外部キー制約違反または例外時はエラーメッセージののち一覧へ遷移する。 |
| 上へ・下へを実行する | `PUT /%eccube_admin_route%/setting/system/member/{id}/up`、`PUT /%eccube_admin_route%/setting/system/member/{id}/down` | 隣接する `sort_no` の行と表示順を入れ替える。成功すれば成功メッセージ、失敗すればエラーメッセージののち一覧へ遷移する。先頭・末尾の行では当該リンクは一覧上に出さない。 |
| 存在しないIDで編集を開く | `GET /%eccube_admin_route%/setting/system/member/{id}/edit` | 404 応答となる。 |

## 処理フロー

### 一覧を開く（GET）

1. 管理画面の認証・認可・ネットワーク制限などの前置処理を通過する（詳細は管理画面基盤の実装を正とする）。
2. `dtb_member` の全件を、ソート条件が `sort_no` 降順のみの条件で取得する。
3. 空のフォームビルダを生成し、一覧向け初期化イベントをディスパッチする。プラグイン等がビルダや一覧に干渉し得る。コアの一覧テンプレートはフォーム行を描画しないため、ビルダへ項目を足しても画面に出ない限り利用者視界には効かない。
4. テンプレートにフォームビュー（コアでは実質空に近い）とメンバー配列を渡して描画する。

### 新規登録・編集を開く（GET）

1. 前置処理を通過する。
2. 編集権限を確認する。編集権限を保持していないメンバーは登録・編集を実行できない。
3. 編集で ID 指定がある場合、該当メンバーを取得する。無ければ 404 とする。あれば退避用に暗号化済みパスワードを保持し、エンティティのパスワードに設定ファイルの `default_password` 値を代入してフォーム表示用にする。新規の場合は空のメンバーエンティティを生成する。
4. ログイン中メンバーをクローンし、永続化コンテキストから切り離す（セッション上のユーザー実体と編集対象の混在を避けるための確認値）。
5. フォームビルダ（管理者メンバー型）をメンバーに紐づけて生成し、編集向け初期化イベントをディスパッチする。
6. フォームには標準項目に加え、所属店舗、メールアドレス、デフォルト検索表示店舗、編集可能店舗、二段階認証、自動ログアウト設定、スマレジ用アカウントを表示する。所属は自由入力ではなく所属マスターデータを参照した単一選択とする。
7. フォームを描画する前に、セキュリティトークンのユーザーへクローンしたログイン中メンバーを戻す。
8. テンプレートを描画する。

### 登録ボタン押下（POST、検証成功）

1. フォームをリクエストで処理する。
2. 編集権限を保持していることを確認する。編集権限を保持していない場合は保存しない。
3. 検証成功時、編集かつ入力パスワードが `default_password` のままなら退避していた暗号化パスワードを戻す。それ以外はソルト未設定ならランダムソルトを生成し、エンコーダでパスワードをハッシュ化してセットする。
4. 所属、デフォルト検索表示店舗、編集可能店舗、二段階認証、自動ログアウト設定、スマレジ用アカウントをフォーム値に基づいて保存対象へ反映する。編集可能店舗は複数登録を可能とする。
5. 登録時は `MemberCreateAction`、編集時は `MemberEditAction` を呼ぶ。成功時は編集完了イベントをディスパッチし、成功メッセージを積み、登録時は作成したメンバーの編集画面へ、編集時は同じ編集画面へリダイレクトする。
6. 保存処理で例外が発生した場合はエラーメッセージを積み、登録時は同一フォームを再表示し、編集時は同じ編集画面へリダイレクトする。

### 登録ボタン押下（POST、検証失敗）

1. フォームをリクエストで処理する。
2. 同一編集テンプレートを再表示し、項目エラーを表示する。成功メッセージは積まない。
3. 描画前にセキュリティトークンのユーザーをクローンしたログイン中メンバーへ戻す。

### 上へ（PUT、CSRF 有効）

1. CSRF トークンを検証する。無効ならアクセス拒否例外となる。
2. 対象メンバーを取得する。無ければ 404。
3. リポジトリの上へ処理を呼ぶ。自身の `sort_no` より 1 大きい行と `sort_no` を交換する。隣が存在しないなどで例外が出た場合はエラーメッセージを積む。
4. 成否に応じて成功またはエラーメッセージを積み、一覧へリダイレクトする。

### 下へ（PUT）

上へと同様に、自身の `sort_no` より 1 小さい行と `sort_no` を交換する。

### 削除（DELETE、CSRF 有効）

1. CSRF トークンを検証する。無効ならアクセス拒否例外となる。
2. 対象メンバーを取得する。無ければ 404 応答となる。
3. リポジトリの削除処理を呼ぶ。削除対象より大きい `sort_no` の全行を 1 つ繰り下げたうえで、対象メンバーを削除する。
4. 成功時は削除完了イベントをディスパッチし、成功メッセージを積む。外部キー制約違反またはその他例外時はエラーメッセージを積む。
5. 一覧へリダイレクトする。

## 集計条件

| 指標 | 集計の要点 |
|------|------------|
| 一覧の並び | `dtb_member` を `sort_no` 降順で並べ替える。件数表示やページングは行わない。 |
| 新規時の表示順 | 既存行の最大 `sort_no` に 1 を加えた値を割り当てる。既存行が無い場合は 1 を割り当てる。 |

## 保存処理（リポジトリ）の成否

| 順序 | 判定 | 結果 |
|------|------|------|
| 1 | 新規登録時、最大 `sort_no` + 1 を設定し、パスワードをハッシュ化して `dtb_member` を保存する | 例外なく完了すればコミット。例外時はロールバックし、呼び出し元でエラーメッセージを表示する。 |
| 2 | 編集時、パスワードが既定プレースホルダと異なる場合のみ再ハッシュし、`dtb_member` と編集可能店舗を保存する | 例外なく完了すればコミット。例外時はロールバックし、呼び出し元でエラーメッセージを表示する。 |
| 3 | 上へ・下へで隣接 `sort_no` 行が見つからない | 例外となり、呼び出し元でエラーメッセージを表示する。 |

一覧や編集画面のメッセージは、上表の true/false と、フォーム検証・CSRF の結果に応じて積まれる。

## 業務ルール・計算

本機能では金額集計や税率計算は行わない。

### 入力項目

| 項目名 | 必須／任意 | 最大長 | 初期値 | 保存先・扱い |
|--------|------------|--------|--------|----------------|
| 名前 | 必須 | 50 文字 | 新規は空、編集はDB現行値 | `dtb_member.name`。空白不可・長さ検証あり。 |
| 所属店舗 | 条件付き必須 | （店舗マスタに依存） | 新規はログイン中メンバーの所属店舗、編集はDB現行値 | フォーム項目 `baseInfo`。テナント系権限の場合に選択必須。保存先は `dtb_member.base_info_id`。テナント権限より上位の場合はモール店舗を設定する。 |
| 所属 | 必須 | （所属マスタに依存） | 新規は空、編集はDB現行値 | フォーム項目 `department`。自由入力ではなく所属マスターデータを参照する単一選択。保存先は `dtb_member.department_id`。 |
| ログインID | 必須 | 4〜50 文字 | 新規は空、編集はDB現行値 | `dtb_member.login_id`。空白不可・長さ・印字可能文字＋空白の正規表現検証あり。エンティティ単位の一意制約検証により重複時はエラー（メッセージは実装の翻訳メッセージを正とする）。 |
| メールアドレス | 必須 | 255 文字 | 新規は空、編集はDB現行値 | メンバーのメールアドレス。 |
| パスワード | 必須 | 4〜50 文字（確認欄も同条件） | 新規は空、編集は `default_password` が入った表示 | 平文は永続化せず、保存前にソルト付きハッシュへ変換する。編集で入力が `default_password` のままなら既存ハッシュを維持する。 |
| 権限グループ | 必須 | （マスタに依存） | 先頭の空選択 | フォーム項目 `Authority`。保存先は `dtb_member.authority_id`。ゲスト・会員権限は選択不可。 |
| デフォルト検索表示店舗 | 任意 | （店舗マスタに依存） | 新規は空、編集はDB現行値 | フォーム項目 `defaultSearchBaseInfo`。保存先は `dtb_member.default_search_base_info_id`。店舗絞り込みがある検索一覧画面でデフォルトの店舗絞り込みに利用する。 |
| 編集可能店舗 | 任意 | （店舗マスタに依存） | 新規は空、編集はDB現行値 | フォーム項目 `editableBaseInfos`。保存先は `dtb_member_base_info.member_id` / `base_info_id`。複数店舗を登録でき、在庫・受注・店頭買取・イベントのデータ編集範囲に利用する。 |
| 稼働 | 必須 | （マスタに依存） | フォームバインド時のエンティティ初期状態 | フォーム項目 `Work`。保存先は `dtb_member.work_id`。 |
| 二段階認証 | 任意 | — | 無効 | フォーム項目 `two_factor_auth_enabled`。保存先は `dtb_member.two_factor_auth_enabled`。保存後の追加認証要否は二段階認証機能を正とする。 |
| 自動ログアウト設定 | 任意 | — | false | フォーム項目 `isAutoLogout`。保存先は `dtb_member.is_auto_logout`。チェック時、ログイン後に無操作状態が続いた場合の自動ログアウト対象とする。 |
| スマレジ用アカウント | 任意 | — | false | フォーム項目 `smaregiMemberFlg`。保存先は `dtb_member.smaregi_member_flg`。スマレジ連携時の更新ユーザーとして利用するアカウントを指定する。 |

長さの数値はコア付属の `src/Eccube/Resource/config/constant.yml.dist` の既定（`stext_len` 50、`id_min_len` 4、`id_max_len` 50）を確認値とする。運用環境で上書きされている場合はその環境の値が正とする。`default_password` は編集画面のプレースホルダおよび「パスワード未変更」判定に使われる文字列であり、環境設定で与えられる。

### エッジケース

| ケース | 扱い |
|--------|------|
| 編集でパスワードを `default_password` のまま送信 | 退避した暗号化パスワードをそのまま保存する。ソルトの新規生成と再ハッシュは行わない。 |
| 新規でログインIDが既存と重複 | フォーム検証でエラーとなり保存処理へ進まない。 |
| 編集権限を保持しないメンバー | 登録・編集はできない。画面上では登録ボタンを押せない状態とする。 |
| 削除後の一覧 | 削除は物理削除であり、削除済み行は一覧結果に含まれない。 |
| 削除対象が存在しない | ルート引数のエンティティ解決に失敗し、404 応答となる。 |
| 「自分」と同一IDの行の削除 | 一覧ではリンクを出さない。サーバ側で同一IDを特別拒否するコードはコアに無い。 |

## データ整合性

| 観点 | 内容 |
|------|------|
| 一覧とDB | 一覧表示は取得直前の `dtb_member` の内容を反映する。並びは `sort_no` 降順のみ。 |
| 編集画面とDB | 編集GETではパスワード列をプレースホルダで上書きしたあとフォームに載せるため、画面上のパスワード欄はDBの暗号文と一致しない。 |
| 表示順の一意性 | 入れ替え・削除は隣接または全行更新で整合を取る設計だが、同時操作による競合時の保証は本書では切らない。 |
| 認証情報との関係 | ログイン中トークンのユーザー実体は編集画面描画前に元のログインメンバーへ戻すため、編集対象の一時エンティティがトークンに残らない。 |
| 一覧とログイン可否 | 認証時のメンバー読込は稼働マスタの定数IDと組み合わせて絞る。一覧は条件なし取得のため、非稼働メンバーも表示され得る。 |
| 編集可能店舗 | 在庫・受注・店頭買取・イベントの各データは、ログイン中メンバーに紐づく編集可能店舗の範囲で編集可能とする。店舗参照範囲の制御はサイト全体で共通とする。 |
| デフォルト検索表示店舗 | メンバーにデフォルト検索表示店舗が登録されている場合、店舗絞り込みを持つ検索一覧画面の初期表示条件として利用する。 |

### DB操作

永続化の正は ec-cube-enterprise（テーブル名・操作は ec-cube-enterprise を正典）。当ドメインは承認ワークフローを介さず persist/flush で直接確定する（承認ワークフローは在庫機能固有）。

| 操作種別 | 対象テーブル | 契機・条件 |
|---------|--------------|------------|
| 登録/更新 | dtb_base_info / dtb_member / dtb_member_base_info / mtb_authority / mtb_work | 当機能が行う登録・更新で対象テーブルを直接保存する（不要な削除は含まない）。確定は persist/flush による即時反映。DB=ec-cube-enterprise を正典とする。 |

## 権限・認可

| 利用者状態 | メンバー一覧・登録・編集・削除・順序変更 |
|------------|------------------------------------------|
| 未ログイン | 管理画面の認証フローへ誘導される（詳細は管理画面ログインを正とする）。 |
| ログイン済み（編集権限あり） | メンバー一覧、登録、編集、削除、順序変更を操作できる。さらに権限マスタにより特定パスが拒否されている場合は当画面も含め拒否され得る（権限管理の設定を正とする）。 |
| ログイン済み（編集権限なし） | 一覧参照は到達経路の認可に従うが、登録・編集の実行はできない。登録ボタンは押せない状態とする。 |
| ネットワーク制限外のクライアント | 管理画面全体の拒否ポリシーに従う。 |

## 画面遷移

| 条件 | 遷移先 |
|------|--------|
| 一覧から新規登録リンク | メンバー登録・編集画面（新規）。 |
| 一覧から編集リンク | メンバー登録・編集画面（既存）。 |
| 登録成功 | 作成したメンバーの編集画面。 |
| 登録処理失敗（保存処理で例外） | 同一の登録・編集画面。 |
| 編集成功・編集処理失敗 | 同一メンバーの編集画面。 |
| 検証失敗 | 同一の登録・編集画面。 |
| 戻るリンク | メンバー一覧。 |
| 削除・上へ・下への完了・失敗 | メンバー一覧。 |
| 編集で ID 非存在 | エラー画面（404）。 |

### 遷移時に引き継ぐ状態

| 起点 | 遷移前の処理 | 遷移後の初期状態 |
|------|--------------|------------------|
| 保存成功 | 成功フラッシュを積む | 一覧が再読込されメッセージが表示される。 |
| 順序・削除 | 成功または失敗フラッシュを積む | 一覧が再読込されメッセージが表示される。 |
| 削除対象不在 | ルート引数のエンティティ解決に失敗する | 404 応答となる。 |
| 登録・編集画面を描画 | セキュリティトークンのユーザーをログイン中メンバーへ戻す | 以降の画面は通常のログインコンテキストである。 |

## エラー処理

| エラー内容 | 処理 |
|------------|------|
| フォーム検証エラー | 同一フォームを再表示。成功フラッシュは積まない。 |
| 編集権限なし | 登録・編集を実行しない。利用者向け表示は管理画面の権限エラーまたはボタン無効状態に従う。 |
| CSRF トークン不正（削除・上へ・下へ） | アクセス拒否応答。 |
| 保存・削除・順序変更の処理失敗 | エラーフラッシュを積む。登録保存失敗は同一画面を再表示し、編集保存失敗は同一編集画面へリダイレクトし、削除・順序変更失敗は一覧へリダイレクトする。 |
| 編集対象 ID が存在しない | 404。 |

## ログ・監査

本コントローラ内では専用の監査ログ出力を行わない。汎用アプリケーションログやアクセスログへの記録は基盤設定を正とする。

### ログに出してはいけないもの

- パスワードの平文
- CSRF トークンの原値
- Cookie 値
- セッション ID の完全値
- Remember Me トークンの原値

## セッション

### 本機能におけるセッション

| 観点 | 内容 |
|------|------|
| フラッシュメッセージ | 保存・削除・上下移動の結果を管理画面向けキーで積む。削除対象不在時はルート引数のエンティティ解決に失敗するため、本機能側で削除済み警告キーは積まない。 |
| 編集画面の表示・検証失敗後の再表示 | セキュリティトークン上のユーザーが編集対象エンティティで上書きされないよう、描画直前にログイン中メンバーを復元する。 |

### セッションへ保存しない情報

本機能が新たにセッションキーを定義して検索条件などを保存する処理は持たない。

## Cookie

本機能単体で新種の Cookie を設定したり解釈したりする処理は持たない。セッション Cookie は管理画面ログインの枠組みに依存する。

## 排他制御・トランザクション

登録・編集は Action 内で DB トランザクションを張り、コミットまたはロールバックする。削除・上へ・下へはリポジトリ処理で更新・削除と flush を行う。行レベルの楽観ロック列は持たない。
