# API 受注管理 — 店頭注文番号取得

## 概要

店内モニター（店頭注文番号表示画面）が、ピック済みになった店頭注文番号のリストを取得するためのAPIである。pf-eccube3のHareruyaEcプラグインが提供するJSON APIで、ピック完了ステータスの注文に紐づく注文番号札（数字）と、注文番号札（アルファベット）を1つの配列にまとめて返す。

本書は実装手順ではなく、誰が・いつ・どの条件で・結果どうなるかを読むためのリバース詳細設計とする。確認値はHareruyaEcプラグインの店頭注文番号取得処理、フロントのルート登録（ControllerProvider）、注文番号テーブル・注文番号札テーブル・受注ステータスを正とする。

本機能のカスタマイズ区分はカスタマイズで、挙動の参照リポはpf-eccube3（HareruyaEcプラグイン）とする。DB関連の記述（テーブル名・列名・永続化先）はec-cube-enterpriseを正とする。

対象はJSON APIエンドポイントであり、ブラウザ向けの画面を持たない。本文ではフレームワークのコントローラ型名やメソッド名を主説明としない。「利用者視点の入口」にHTTPメソッドとパスパターンを書く。

---

## 本書で扱うこと

- ピック完了ステータスの注文に紐づく注文番号札（数字）の取得
- 注文番号札（アルファベット）の取得と連結
- 画面表示最大件数を超える場合の出荷完了番号の補完

## 用語

| 用語 | 説明 |
|------|------|
| 注文番号札（数字） | 注文ごとに採番した数値の呼び出し番号。注文番号テーブルが注文IDと対で保持する。 |
| 注文番号札（アルファベット） | 数値とは別に管理する英字の呼び出し番号。注文番号札テーブルが保持する。 |
| ピック完了 | 受注ステータスのうちピック済みを指す状態。 |
| 出荷完了 | 受注ステータスのうち出荷を終えた状態。表示件数超過時の補完判定に用いる。 |

## 利用者視点の入口

| 入口 | URLエンドポイント | 期待されるふるまい |
|------|--------------------|--------------------|
| 店頭注文番号リストの取得 | `GET /{_locale}/waiting_api/get_waiting` | ピック完了の注文番号札（数字）と注文番号札（アルファベット）を1配列にまとめて返す。 |

応答形式はJSON。呼び出し元は店内モニター（店頭注文番号表示画面）からの定期取得。フロントのルートは言語識別子`{_locale}`配下にマウントされる。

## 処理フロー

### 店頭注文番号リストを取得する（GET `/{_locale}/waiting_api/get_waiting`）

1. ピック完了ステータスの注文に紐づく注文番号札（数字）の一覧を取得する。注文番号テーブルと受注を注文IDで結合し、受注ステータスがピック完了の行に限定する。
2. 注文番号札（アルファベット）の一覧をID昇順で取得する。
3. 数字の件数とアルファベットの件数の合計が画面表示最大件数を超える場合は、出荷完了ステータスの注文番号札（数字）も取得し、欠番の補完を行う。直前に追加した番号の次から対象番号の手前までの連番がすべて出荷完了であれば、その間の番号を配列に加える。超えない場合は補完を行わない。
4. ピック完了の注文番号札（数字）を配列へ順に追加する。
5. 注文番号札（アルファベット）を配列の末尾へ順に追加する。
6. 数字と英字を含む1つの配列をJSONで返す（HTTP 200）。

## 集計条件

| 指標 | 集計の要点 |
|------|------------|
| ピック完了の注文番号札（数字） | 注文番号テーブルと受注を注文IDで結合し、受注ステータスがピック完了の行のみを対象とする。並び順は注文番号テーブルの既定（主キー順）。 |
| 注文番号札（アルファベット） | 注文番号札テーブルの全件をID昇順で取得する。 |
| 出荷完了の補完 | ピック完了と英字の合計件数が画面表示最大件数（既定25）を超える場合のみ、ピック完了番号の間にある欠番を、その区間がすべて出荷完了のときに補完する。 |

## 入出力

### リクエスト

本APIはリクエストパラメータを持たない。パスパラメータ`{_locale}`は言語識別子であり、取得対象の絞り込みには用いない。

### レスポンス（成功）

HTTP 200。応答本体はラッパオブジェクトを持たず、注文番号を要素とする1次元配列である。

| フィールド | 型 | 説明 |
|------------|----|------|
| （応答本体） | array | 注文番号の配列。先頭側にピック完了の注文番号札（数字、表示件数超過時は間の出荷完了番号を含む）、末尾側に注文番号札（アルファベット）を連結する。数字要素はinteger、英字要素はstringとなる。 |

### レスポンス（失敗）

| HTTPステータス | 条件 | 本文の形 |
|----------------|------|----------|
| 500 | 取得処理中の例外 | 標準例外ハンドラに委ねる |

入力検証・認証判定を行わないため、400・401は発生しない。該当データが無い場合は空配列を200で返す。

### サンプルレスポンス

成功時の応答例（代表値）。

```json
[101, 102, 103, "A", "B"]
```

### 副作用

無し（参照のみ）。本APIはデータを更新しない。

応答はJSON応答整形を経て返す。応答本体は配列であり、`Content-Type`は`application/json`を明示する。
