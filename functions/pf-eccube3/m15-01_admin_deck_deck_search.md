# デッキ管理 — デッキ検索・一覧

## 概要

HareruyaEc プラグインが管理画面に提供する「デッキ管理」において、大会用デッキ（`dtb_deck` のうちデッキ種別が大会用のもの）を多数の条件で絞り込み、一覧・ページ送り・並び替えする機能である。検索条件・ページ番号・表示件数・ソートはセッションに保持し、GET での再表示時に復元する。一覧上から CSV 出力・一括削除・一括編集の導線が接続されているが、それら個別処理の検証や CSRF の例外の列挙は本書の主題としない。

本書は実装手順ではなく、誰が・いつ・どの条件で・結果どうなるかを読むためのリバース詳細設計とする。pf-eccube3 配下の HareruyaEc プラグイン実装を確認値とする。EC-CUBE コア単体では当ルートは存在しない。

本機能のカスタマイズ区分はカスタマイズである。挙動は現行リポ（pf-eccube3 の HareruyaEc プラグイン）を参照し、DB関連は ec-cube-enterprise を正とする。

対象はブラウザ経由の管理画面に限定する。コントローラのメソッド名の列挙は本文の主題としない。本文ではルートbind名やSymfonyのルートnameの網羅は主説明としない。「利用者視点の入口」にHTTPメソッドとサイトルートからのパスパターンを書く。コード探索でbind名が必要なときだけ「調査補助」へ書く。

## リニューアル移行時の扱い

- ec-cube-enterprise にデッキ関連テーブル一式が実装されており、本機能の検索対象は移行先に存在する。
- デッキ（`dtb_deck`）の主キー列名が異なる。移行先 ec-cube-enterprise では `id`、現行 pf-eccube3 では `deck_id` である。本書が `dtb_deck.deck_id`（主キー）と記す箇所は、移行先では `dtb_deck.id` に対応する。中間テーブル（`dtb_deck_deck_tag`、`dtb_article_deck`、`dtb_deck_campaign_tag`）の外部キー列は現行・移行先とも `deck_id` のままである。
- デッキのその他の検索対象列（`deck_name`、`format_id`、`archetype_id`、`disp_id`、`private_flg`、`event_date`、`ranking`、`win_count`、`loss_count`、`draw_count`、`result`、`event_name_jp`、`event_name_en`、`player_name`、`dci_no`、`member_id`、`deck_type_id`、`event_detail_id`、`old_deck_id` ほか）は現行と同一スキーマである。論理削除列 `deleted_at` を現行・移行先とも持つ。
- 移行先 `dtb_deck` には現行に無い追加列（`player_id`、`card_image_id`、`display_token` 等）があるが、本機能の検索条件では参照しない。
- カード条件で結合するデッキ内カード（`dtb_deck_card`、列 `deck_id`、`card_id`、`board_id`、`count`）は移行先に存在し同一スキーマである。

## 利用者視点の入口

| 入口 | URLエンドポイント | 期待されるふるまい |
|------|--------------------|--------------------|
| ナビからデッキ一覧を開く | `GET /{admin_route}/deck` | 検索フォームを表示する。結果エリアは「検索実行前」相当（件数ヘッダは出ない）。デッキ検索用セッションの一部を削除する。 |
| 条件を入力して「検索」送信 | `POST /{admin_route}/deck/search/1`（フォーム action は常に `page_no=1`） | 条件がセッションに保存され、1 ページ目の一覧が返る。CSRF は検索フォーム種別で無効化されている。 |
| ソート項目と昇順・降順を選ぶ | `GET /{admin_route}/deck/search/1?sort=…&order=…` | ソートがセッションに保存され、1 ページ目から該当順で一覧する。 |
| ページリンクから N ページ目へ | `GET /{admin_route}/deck/search/{page_no}` | 直前の検索条件とソートをセッションから復元し、N ページ目を表示する。 |
| 表示件数を変える | `GET /{admin_route}/deck/search/1?page_count=…` | `mtb_page_max` に存在する件数ならセッションに保存し、その件数でページ分割する。 |
| 行のデッキ詳細リンク／編集 | `GET /{admin_route}/deck/{id}` | デッキ編集画面へ遷移する（別機能）。 |

## 処理フロー

### デッキ一覧を初期表示する（GET `admin_deck_list`）

1. 管理画面の認証・共通制約を通過する。
2. セッションから `admin.deck.search`、`admin.deck.search.page_no`、`admin.deck.search.page_count` を削除する（`admin.deck.sort`・`admin.deck.order` は残りうる）。
3. フォーム名 `admin_search_deck` で検索フォームを生成し、`deck.twig` を描画する。ページネーションは空配列、`page_no` は 1、`page_count` は設定 `default_page_count`。ソートキー一覧はデッキレポジトリから取得する。
4. イベント日 From はフォーム種別の既定データとして「現在日時から設定 `HareruyaEc.const.search_form.default_from_term`（確認値 `-3 month`）だけシフトした日付」が入る。

### 検索・一覧を表示する（GET または POST `m15-01_admin_deck_deck_search`）

1. 管理画面の認証・共通制約を通過する。
2. デッキ用レポジトリ参照をセットする。
3. フォーム `admin_search_deck` を生成する。送信前に「有効」とみなされると空一覧で返す分岐があるが、未送信の通常経路では続行する。
4. リクエストをフォームに取り込む。
5. クエリパラメータまたはセッションから `sort` を決める。優先順はリクエスト、なければセッション、なければ既定値 `default`。
6. 同様に `order` を決める。既定は `DESC`。
7. `order` が正規表現 `^(ASC|DESC|asc|desc)$` に一致しない場合、管理画面エラー `admin.error.sort` を積み、`admin_deck_list` と同様の初期化処理へ進む（検索条件・ページ関連セッションのみ削除され、`admin.deck.sort` と `admin.deck.order` は削除されない）。
8. ページマスタを全件取得し、許容される表示件数の一覧を得る。
9. 表示件数はセッションの `admin.deck.search.page_count` があればそれを使い、なければ設定 `default_page_count`（確認値 10）。リクエストに `page_count` があり、かつページマスタの名前と一致すればセッションへ上書き保存する。
10. フォームから送信データが得られない場合、セッション `admin.deck.search` のビューデータから復元する。ビューと検索データの両方が欠ける場合は `admin_deck_list` と同等の初期表示へフォールバックする。
11. 検索データに `sort`・`order` を合成する。
12. レポジトリが検索データからクエリビルダを構築する。別メソッドで同一条件の件数を取得する。現在ページが最終ページかつそのページのデータが削除済みなどで件数とページの関係がずれる場合、実装はページ番号を 1 減らして調整する。
13. セッションへ `admin.deck.search.page_no`、`admin.deck.search`、`admin.deck.sort`、`admin.deck.order`、`admin.deck.search.page_count` を書き込む。
14. アプリケーションのページネータでクエリビルダをページ分割する（デッキ一覧では `wrap-queries` を有効にするオプションが指定されている）。Twig を描画する。

## 検索実行時の判定順序（グローバル除外）

以下は利用者が入力しない前提でもクエリに適用される。

| 順序 | 判定 | 結果 |
|------|------|------|
| 1 | イベント詳細との結合条件 | イベント詳細が無いデッキは残す。イベント詳細がある場合は、その開始日時が現在より前である行だけが結合対象となり、開始が未来のイベントにだけ紐づくデッキは結果から除外される。 |
| 2 | デッキ種別 | 大会用デッキ種別定数に一致する行だけを残す。ユーザー作成デッキ種別などは除外される。 |

## 業務ルール・計算

検索フォーム入力はセッションへ保存されるが、`dtb_deck` を更新しない。送信値からクエリビルダへの対応は次のとおりである。

| 項目 | 内容 |
|------|------|
| 複数トークン検索 | デッキ名・大会名・戦績文字列・DCI・プレイヤー名は、半角／全角スペースおよびカンマで分割した各トークンについて、対象列へ部分一致条件を付ける。トークン間は論理 AND（いずれかの列への一致でそのトークンは充足）。同一トークン内の複数列は論理 OR。 |
| 複数 ID | デッキ ID・イベント ID は同様に分割し、数値だけを抽出して IN 検索する。非数値トークンは無視される。 |
| フォーマット・アーキタイプ・表示マスタ・色 | 選択されたマスタ行への IN 一致。色はアーキタイプ経由で色マスタと結合して絞り込む。 |
| プライベート | ラジオがちょうど 1 選択のときだけ、その真偽値で一致させる。未選択または両方選択のときは条件を付けない。 |
| イベント日 | From のみ指定ならその日 0 時以上。To のみ指定なればその日 23:59:59 以下。両方あれば範囲。 |
| 順位・勝敗引き分け | それぞれ From／To に整数が入っていれば下限・上限を付ける。 |
| デッキタグ | 選択された各タグについて、`dtb_deck` とタグの関連がすべて存在する行だけを残す（論理 AND）。 |
| カード名 | デッキに含まれるカードの日本語名または英語名が、入力文字列と完全一致する行だけを残す（LIKE ではない）。 |
| 旧デッキ ID | 文字列一致（単純等価）。 |
| 店舗 | イベント詳細経由でイベントが店舗マスタと結合され、その店舗が選択値と一致する行だけを残す。イベント詳細が無いデッキはこの条件では基本的に絞り込まれない。 |
| 登録管理者 | `dtb_deck.member_id` が選択された管理者アカウント ID と一致する行だけを残す。 |

本機能では業務計算（税・ポイント等）は行わない。

### 入力項目

| 項目名 | 必須／任意 | 最大長 | 初期値 | 保存先・扱い |
|--------|------------|--------|--------|----------------|
| デッキ ID | 任意 | 文字列 50（設定 `stext_len`。環境で上書きされうる） | 空 | フォームキー `deck_id`。数字・カンマ・スペースのみ許容する正規表現。分割後に数値だけ IN。保存しない。 |
| 旧デッキ ID | 任意 | フォーム上限なし（長さ制約なし） | 空 | フォームキー `old_deck_id`。一致時のみ絞り込み。保存しない。 |
| フォーマット | 任意 | —（複数選択） | 未選択 | フォームキー `formats`。空でなければ IN。保存しない。 |
| 色 | 任意 | —（チェック複数） | すべてオフ | フォームキー `color`。アーキタイプとの結合で絞り込み。保存しない。 |
| アーキタイプ | 任意 | —（複数選択） | 未選択 | フォームキー `archetypes`。保存しない。 |
| 表示／非表示 | 任意 | —（マスタ値のチェック複数） | すべてオフ | フォームキー `disp`。保存しない。 |
| プライベート | 任意 | —（はい／いいえのラジオ複数選択可能な見た目） | 未選択 | フォームキー `private`。選択が 1 つのときのみ `dtb_deck.private_flg` で絞り込み。保存しない。 |
| イベント日（開始） | 任意 | 日付 1 件（`yyyy-MM-dd` ウィジェット） | 現在から `-3 month`（設定 `HareruyaEc.const.search_form.default_from_term`） | フォームキー `event_date_from`。時刻はクエリ側で 00:00:00 に丸める。保存しない。 |
| イベント日（終了） | 任意 | 同上 | 空 | フォームキー `event_date_to`。23:59:59 に丸める。保存しない。 |
| 大会名 | 任意 | 文字列 50（`stext_len`） | 空 | フォームキー `event_name`。日本語大会名・英語大会名の両列へトークンごとの部分一致 OR、トークン間 AND。保存しない。 |
| 順位（下限／上限） | 任意 | Symfony integer（画面 attr は最小 1） | 空 | フォームキー `ranking_from`／`ranking_to`。保存しない。 |
| 戦績 | 任意 | 文字列 50（`stext_len`） | 空 | フォームキー `result`。保存しない。 |
| 勝ち数（下限／上限） | 任意 | Symfony integer（画面 attr は最小 0） | 空 | フォームキー `win_count_from`／`win_count_to`。保存しない。 |
| 負け数（下限／上限） | 任意 | 同上 | 空 | フォームキー `loss_count_from`／`loss_count_to`。保存しない。 |
| 引き分け数（下限／上限） | 任意 | 同上 | 空 | フォームキー `draw_count_from`／`draw_count_to`。保存しない。 |
| デッキ名 | 任意 | 文字列 50（`stext_len`） | 空 | フォームキー `deck_name`。保存しない。 |
| DCI 番号 | 任意 | 文字列 50（`stext_len`）、かつ数字のみ | 空 | フォームキー `dci_no`。保存しない。 |
| プレイヤー名 | 任意 | 文字列 50（`stext_len`） | 空 | フォームキー `player_name`。保存しない。 |
| カード | 任意 | 文字列 200（設定 `mtext_len`） | 空 | フォームキー `card`。カードマスタ英日名との完全一致でデッキを結合絞り込み。入力補助用 data-list URL を持つ。保存しない。 |
| デッキタグ | 任意 | —（複数選択） | 未選択 | フォームキー `deck_tags`。AND 条件。保存しない。 |
| イベント ID | 任意 | 文字列 50（`stext_len`）、数字・カンマ・スペース | 空 | フォームキー `event_id`。イベント詳細側のイベント ID で IN。保存しない。 |
| 店舗 | 任意 | —（単一選択） | 未選択 | フォームキー `shop`。保存しない。 |
| 登録管理者 | 任意 | —（単一選択） | 未選択 | フォームキー `member`。保存しない。 |

フォーム種別にはフォームキー `latest`（ラベルは翻訳キー `form.deck.latest.*`）も定義されているが、一覧テンプレートでは出力しておらず、レポジトリの検索処理でも参照しない。したがって画面からは通常操作できず、クエリにも効かない。

検索フォームは CSRF 保護を無効にしている（プラグインのフォーム種別の既定）。

### エッジケース

| ケース | 扱い |
|--------|------|
| ソートキーが不正 | `admin.error.sort` を表示し、`admin_deck_list` と同様に検索条件・ページ関連セッションを削除したうえで一覧初期画面へ戻る（ソート・並び順のセッションキーは削除しない）。 |
| セッションに検索条件がなく GET のみ | 一覧初期表示へフォールバックする。 |
| ページ番号がルート制約に合わない | ルートにマッチしないため到達しない（別経路の 404 に依存）。 |
| プライベートを複数選択 | 絞り込みを付けない。 |
| 未来開始のイベントにのみ紐づくデッキ | グローバル結合・WHERE により結果に含まれない。 |
| 表示件数パラメータがマスタ外 | セッションを更新せず、直前の表示件数を使う。 |

## データ整合性

| 観点 | 内容 |
|------|------|
| 一覧と詳細 | 一覧は検索時点の DB 状態を読む。詳細画面で更新後、一覧へ戻ればセッションが残っていれば古い条件のまま再検索されうる。 |
| 大会開始時刻 | 「開始が未来のイベントに紐づくデッキは一覧に出ない」ため、一覧と「イベント詳細をそのまま見た期待」とはずれる場合がある。 |
| 件数と一覧 | 件数取得と一覧クエリは同一ビルダ経路を踏む設計であり、通常は件数とページ内容が対応する。 |

## 入出力

| 種類 | 内容 |
|------|------|
| 入力 | HTTP クエリ／フォーム POST の検索条件、`sort`、`order`、`page_no`、`page_count`。 |
| 成功時出力 | HTML（検索フォーム＋該当時は一覧テーブル・ページネーション）。 |
| 失敗時出力 | 不正ソート時はフラッシュエラーと初期画面。レポジトリがクエリビルダ以外を返した場合は HTTP 404（通常の検索経路では発生しない想定）。 |
| 副作用 | セッション更新（検索条件・ページ・ソート・表示件数）。 |

## 画面遷移

| 条件 | 遷移先 |
|------|--------|
| 行リンク／編集メニュー | デッキ編集（GET `/{admin_route}/deck/{id}`） |

### 遷移時に引き継ぐ状態

| 起点 | 遷移前の処理 | 遷移後の初期状態 |
|------|--------------|------------------|
| 一覧から別画面へ（検索結果を維持して戻る場合） | セッションに検索条件・ページ番号等が残る | `m15-01_admin_deck_deck_search` の GET で復元される |
| 削除完了後のリダイレクト（実装） | セッション `admin.deck.search.page_no` があればそのページへ、なければ `admin_deck_list` | ページ番号は削除結果に応じてトレイト側で減算されうる |

本機能では試行制限を扱わない。

## ログ・監査

本機能固有のアプリケーションログ規約はコードからは限定できない。一覧・検索そのものは標準のアクセスログに残りうる。

### ログに出してはいけないもの

- パスワード
- なりすまし対策トークン
- Cookie 値
- セッション ID の完全値
- Remember Me トークンの原値

## セッション

### 本機能におけるセッション

| 観点 | 内容 |
|------|------|
| 検索一覧を開く GET `admin_deck_list` | `admin.deck.search`、`admin.deck.search.page_no`、`admin.deck.search.page_count` を削除する。`admin.deck.sort` と `admin.deck.order` は削除しない。 |
| 検索実行後 | `admin.deck.search.page_no`、`admin.deck.search`、`admin.deck.sort`、`admin.deck.order`、`admin.deck.search.page_count` を保存する。 |

### セッションへ保存しない情報

パスワードやクレジットカード番号など、検索フォームに無い項目は保存しない。

## 調査補助（ソース位置）

grep やコード検索の手がかりとして、`DeckServiceProvider`、`SearchControllerTrait`、`SearchDeckType`、`DtbDeckRepository::getQueryBuilderBySearchData`、`Resource/template/admin/Deck/deck.twig`、`Resource/template/admin/assets/js/deck-search.js` を参照するとよい。

### HTTPルート名とパス（コード探索用・旧入口節より退避）

- `admin_deck_list` … `GET` … `/{admin_route}/deck`（検索フォームの初期表示。セッションキー `admin.deck.search`・`admin.deck.search.page_no`・`admin.deck.search.page_count` を削除する。`admin.deck.sort` と `admin.deck.order` は削除しない。一覧結果は空のまま（件数未定義）。）
- `m15-01_admin_deck_deck_search` … `GET, POST` … `/{admin_route}/deck/search/{page_no}`（`page_no` は正規表現 `^[1-9][0-9]*$`（1 以上の整数）。検索実行後の一覧、ソート変更、ページ送り、表示件数変更、GET によるセッション復元。）
