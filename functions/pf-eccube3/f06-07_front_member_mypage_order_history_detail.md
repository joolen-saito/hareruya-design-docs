# F06-07（購入履歴詳細）

## 概要

購入履歴詳細は、ログイン済み会員が購入履歴一覧から選んだ自身の注文1件の明細を確認する機能である。注文番号・注文日・出荷日・金額内訳（商品金額合計・送料・手数料・ポイント使用値引き・注文金額合計・発生ポイント）・送り主・支払方法・配送方法・コンビニ等の決済情報・お届け先・注文明細を表示する。当該注文が他会員のものであれば表示しない。詳細からも再購入を行える。

本書は実装手順ではなく、誰が・いつ・どの条件で・結果どうなるかを読むためのリバース詳細設計とする。確認値はpf-eccube3（EC-CUBE3系）のHareruyaEcプラグインの購入履歴詳細処理、購入履歴詳細テンプレート（`Mypage/shopping_history_detail.twig`）、注文・注文サブ・配送・決済を扱うリポジトリと税計算処理を正とする。

本機能のカスタマイズ区分はカスタマイズであり、画面・処理フロー・表示メッセージの挙動はpf-eccube3を参照リポとする。DB関連（テーブル名・列名・保存先）はec-cube-enterpriseを正とする。

対象はブラウザ経由のフロント（会員マイページ）に限定する。フロントのページは言語別パスセグメント`/{_locale}`を前提とし、本書のパスは`/{_locale}`配下の確認値として記載する。`/mypage`配下は会員ログインを要する。

本文ではフレームワークのコントローラ型名やメソッド名を主説明としない。ルートbind名の網羅は主説明とせず、「利用者視点の入口」にHTTPメソッドとサイトルートからのパスパターンを書く。

## リニューアル移行時の扱い

DB関連の記述はec-cube-enterpriseを正とする。注文ヘッダ（`dtb_order`）の金額内訳列（`customer_id`・`order_date`・`payment_total`・`subtotal`・`delivery_fee_total`・`charge`・`discount`）は現行（pf-eccube3）と移行先（ec-cube-enterprise）で同一スキーマである。

使用ポイント・発生ポイントの保持先が現行と移行先で異なる。現行は注文の補助テーブル`dtb_order_sub`の`spended_points`・`gained_points`に保持する。移行先（ec-cube-enterprise）では補助テーブルを持たず、注文ヘッダ（`dtb_order`）の`gained_points`（ポイント発生）・`spended_points`（ポイント使用）列に直接保持する。本書のDB記述は移行先の保持先（`dtb_order`の同名列）を主とし、現行の補助テーブル名（`dtb_order_sub`）を括弧で添える。

注文明細の保持先テーブル名も異なる。現行の`dtb_order_detail`は移行先では`dtb_order_item`に相当する（`product_name`・`quantity`は同名、商品規格は`product_class_id`の関連）。

詳細表示は参照のみで業務データを更新しないため、移行に伴う保存処理の差分は生じない。

## 処理フロー

### 購入履歴詳細を表示する（GET `/{_locale}/mypage/shopping_history/detail/{id}`）

1. 会員ログインを要求する。未ログインの場合は会員ログインへ誘導する（会員ログイン機能を正とする）。
2. 注文IDが無い場合は見つからない（HTTP404）として扱う。
3. 注文IDから注文と注文明細を取得する。
4. 注文が取得できない、または注文の会員がログイン会員と一致しない場合は見つからない（HTTP404）として扱う。
5. 注文明細の商品規格、注文サブ、配送、決済情報、税額計算結果を取得する。
6. 注文番号・金額内訳・送り主・支払方法・配送方法・決済情報・お届け先・注文明細を表示する。

### 再購入する（POST `/{_locale}/mypage/shopping_history/repurchase`）

1. 購入履歴一覧機能と共通の入口で、注文IDを受け取りカート投入内容を返す（購入履歴一覧機能を正とする）。

## 詳細表示時の判定順序

| 順序 | 判定 | 結果 |
|------|------|------|
| 1 | 会員ログイン済みか | 未ログインなら会員ログインへ誘導する |
| 2 | 注文IDがあるか | 無いなら見つからない（HTTP404） |
| 3 | 注文IDで注文を取得できるか | 取得不可なら見つからない（HTTP404） |
| 4 | 注文の会員がログイン会員と一致するか | 不一致なら見つからない（HTTP404） |
| 5 | 上記を通過 | 金額内訳・決済情報・お届け先・注文明細を表示する |

注文の存在有無と所有者不一致は、いずれも見つからない（HTTP404）として扱い、画面上で理由を区別しない。

## 業務ルール・計算

| 項目 | 内容 |
|------|------|
| 表示対象 | ログイン会員自身の注文のみを表示する。他会員の注文は見つからない（HTTP404）として扱う。 |
| 金額内訳 | 商品金額合計・送料・手数料・ポイント使用（値引き）・注文金額合計（税込み）・発生ポイントを表示する。使用・発生ポイントは注文サブの保持値（0のときは0ポイント）を表示する。 |
| 税額 | 商品金額合計・送料・手数料の合計から割引を引いた額に対し税計算を行い表示する。 |
| 決済情報 | 支払方法に応じてコンビニ番号・オンライン決済番号等を表示する。 |
| 言語別表示 | 言語が英語の場合はコンビニ一覧を英語表記で表示する。 |
| 業務計算 | 金額の再集計は行わず、注文・注文サブの保持値と税計算結果を表示する。 |

本機能は一覧から遷移する詳細表示が主で、利用者入力のフォームを持たない。注文IDはパスで受け取る。
