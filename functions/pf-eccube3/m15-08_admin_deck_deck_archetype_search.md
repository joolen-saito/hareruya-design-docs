# pf-eccube3 — デッキ管理 — アーキタイプ検索条件

## 概要

HareruyaEc プラグインの管理画面「デッキ一覧」検索フォームにおいて、アーキタイプマスタを複数選択して `dtb_deck` を絞り込む条件と、フォーマット・色チェックボックスとの連動表示（クライアント側）を取りまとめたものである。検索結果一覧・ページ送り・ソート・セッション保持はデッキ検索全体の処理に属するが、本書はアーキタイプ条件とその周辺の実装確認値に焦点を当てる。

本書は実装手順ではなく、誰が・いつ・どの条件で・結果どうなるかを読むためのリバース詳細設計とする。本機能のカスタマイズ区分はカスタマイズであり、挙動は現行リポ pf-eccube3 に配置された HareruyaEc プラグイン実装を確認値とし、DB関連は ec-cube-enterprise を正とする。

対象はブラウザ経由の管理画面に限定する。コントローラのメソッド名は本文の主説明としない。本文ではルートbind名やSymfonyのルートnameの網羅は主説明としない。「利用者視点の入口」にHTTPメソッドとサイトルートからのパスパターンを書く。コード探索でbind名が必要なときだけ「調査補助」へ書く。

## リニューアル移行時の扱い

デッキ・アーキタイプの各テーブルは移行先（ec-cube-enterprise）でもコア標準のエンティティとして取り込まれている。検索条件が参照する DB 列名は移行先を正とする。

| 観点 | 現行（pf-eccube3） | 移行先（ec-cube-enterprise） |
|------|---------------------|-------------------------------|
| デッキ本体テーブル | `dtb_deck`。主キー列は `deck_id` | `dtb_deck`。主キー列は `id` |
| アーキタイプ参照 | `dtb_deck.archetype_id`（アーキタイプ外部キー） | 同名 `dtb_deck.archetype_id` |
| アーキタイプ本体 | `dtb_archetype`。主キー列は `archetype_id` | `dtb_archetype`。主キー列は `id` |
| アーキタイプの色 | アーキタイプ用の色多対多中間表 | `dtb_archetype_color`（`archetype_id`・`color_id`）、色マスタは `mtb_color` |

検索フォームのアーキタイプ複数選択・色連動・セッション保持・ページ送りなどの挙動面は現行 pf-eccube3 実装を正とする。検索ビューデータのセッションキー名は実装上の確認値であり、移行後の互換は ec-cube-enterprise 実装で要確認とする。

## 利用者視点の入口

| 入口 | URLエンドポイント | 期待されるふるまい |
|------|--------------------|---------------------|
| ナビからデッキ一覧を開く | `GET /{admin_route}/deck` | 検索フォームのみ表示。デッキ検索関連セッションはクリアされる。アーキタイプは未選択。 |
| フォーマット・色を変えてからアーキタイプを選び、「検索」を押す | `POST /{admin_route}/deck/search/1` | 送信されたアーキタイプ ID の集合とほかの条件で一覧が絞られる。条件とページ情報がセッションに保存される。 |
| 検索結果からページリンクで N ページ目へ | `GET /{admin_route}/deck/search/{page_no}` | セッションに保存された検索ビューデータから条件を復元し、同じアーキタイプ条件で N ページ目を表示する。 |
| ソートまたは表示件数を変える | `GET /{admin_route}/deck/search/1?sort=…&order=…` または `?page_count=…` | 並び順または 1 ページあたり件数が更新され、アーキタイプ条件はセッションから維持される（ソート不正時は別フロー）。 |

## フロント挙動

| 観点 | 内容 |
|------|------|
| 表示要素 | 検索フォーム 1 行目右側に、アーキタイプ用の複数選択セレクト（DOM ID `admin_search_deck_archetypes`）。一覧結果の各行にもアーキタイプ表示欄があるが、検索条件の説明とは別である。 |
| JS 挙動 | `deck-search.js` が `#admin_search_deck_archetypes` に select2（`allowClear: true`）を付与する。`#admin_search_deck_formats` の変更および `#admin_search_deck_color` 内チェック変更時に、(1) アーキタイプセレクトを一時 `disabled`、(2) 全 `option` を一旦 `disabled`、(3) 選択中フォーマットに応じた CSS クラス `format_id_{id}` でフィルタ、(4) 色が 1 つも選ばれていなければフォーマット一致オプションのみ有効化、(5) 色が選ばれていれば `color_id_{id}` とフォーマットの両方に一致するオプションのみ有効化、(6) 有効オプションを先頭へ移動、(7) select2 を再設定、(8) アーキタイプセレクトを再有効化、の順で実行する。「すべてクリア」ではフォーマット・アーキタイプ・デッキタグの select2 を空にし、その他入力はリセットするが、無効化状態のオプションの仕様まではサーバーと同期しない。 |
| CSS・レイアウト | select2 の CDN CSS、および `eventlist.css` をデッキ一覧テンプレートが読み込む。 |
| モーダル・ポップアップ | アーキタイプ検索条件専用のモーダルはない。 |

## 処理フロー

### アーキタイプを含む条件で検索する（POST `m15-01_admin_deck_deck_search`、page_no は 1）

1. 管理画面の認証・共通制約を通過する。
2. デッキ用レポジトリ参照がトレイトによりセットされる。
3. フォーム `admin_search_deck` がリクエストを取り込む。CSRF はこのフォーム型では無効である。
4. ソートキー・昇降順・ページマスタ・表示件数がセッションとクエリから決まる。昇降順が `ASC`/`DESC`（大小無視）以外ならエラーを積み、`admin_deck_list` と同等の初期化へ遷移する。
5. 検索データがこのリクエストで得られない場合はセッション `admin.deck.search` のビューデータから復元する。
6. レポジトリが検索データでクエリビルダを組み立てる。`archetypes` が空でなければ `d.archetype` が選択エンティティ集合に含まれる行だけを残す。
7. 件数カウントと一覧ページネーションが実行され、セッションに `admin.deck.search`、`admin.deck.search.page_no`、`admin.deck.sort`、`admin.deck.order`、`admin.deck.search.page_count` が保存される。

### フォーマットまたは色を変更した直後（ブラウザ内）

1. `deck-search.js` の `archetypeFilter` が非同期タイマーで実行される。
2. アーキタイプの選択肢のうち、現在のフォーマット選択と色チェックに合致しないものは選択できない状態（`disabled`）になる。フォーマット未選択時は「すべてのフォーマットオプション」を対象にクラス選択子を組む。
3. 既に選択済みのアーキタイプがこの操作で `disabled` のまま残る場合でも、ブラウザが無効オプションを送信しないため、送信値から漏れる可能性がある。サーバー側は送信された ID のみで IN 検索する。

## アーキタイプ・色を同時指定したときの判定順序

| 順序 | 判定 | 結果 |
|------|------|------|
| 1 | デッキ検索共通 | 大会開始日時が現在より未来のイベントに紐づくデッキは結果から除外する。leftJoin と条件で表現される。ユーザ作成デッキ種別（`deckTypeId` がイベント型以外）は除外する。 |
| 2 | アーキタイプ複数選択 | 1 つ以上選ばれていれば、`dtb_deck` のアーキタイプ参照がそのいずれかに一致する行だけを残す（論理和）。 |
| 3 | 色複数選択 | 1 つ以上選ばれていれば、デッキのアーキタイプが持つ色コレクションの ID が、そのいずれかに一致するよう結合する（論理和）。 |
| 4 | その他の条件 | フォーマットその他のフィルタが追加される。フォーマットとアーキタイプの整合はサーバー側では強制しない。 |

## 業務ルール・計算

| 項目 | 内容 |
|------|------|
| 選択肢ラベル | 各アーキタイプは「日本語名とフォーマット日本語名を組み合わせた文字列」（エンティティの `getNameWithFormatNameJp`）として表示される。 |
| 選択肢のデータ源 | アーキタイプ一覧は Doctrine のクエリビルダで、アーキタイプと色を join して取得する。グローバルなソフト削除フィルタが有効なら、削除済みアーキタイプは一覧に現れない想定である。 |
| フォーマットとの関係（サーバー） | フォーマット複数選択は `dtb_deck.format` に対する IN である。アーキタイプ IN とは独立して適用される。矛盾する組み合わせは 0 件になる。 |
| 色との関係（サーバー） | 色条件があるときデッキのアーキタイプへ結合し、アーキタイプが持つ色のいずれかが選択色に含まれることを要求する。アーキタイプ IN と同時指定時は両方を満たす必要がある。 |

本機能では金額計算やランキング算出は行わない。

### 入力項目

| 項目名 | 必須／任意 | 最大長 | 初期値 | 保存先・扱い |
|--------|------------|--------|--------|----------------|
| アーキタイプ | 任意 | —（複数選択のエンティティ参照。テキスト入力の長さ制約はフォーム項目としては適用されない） | 未選択 | 送信値は検索処理にのみ使用し、マスタテーブルを更新しない。検索ビューデータはセッションキー `admin.deck.search` に保存され、キー `archetypes` として復元される。フォームフィールド名は `admin_search_deck[archetypes][]`。 |

### エッジケース

| ケース | 扱い |
|--------|------|
| アーキタイプを 1 つも選ばない | `archetypes` が空集合のため、アーキタイプによる追加の WHERE は付かない。 |
| アーキタイプを複数選ぶ | `IN` により、いずれかに一致するデッキがヒットする。 |
| 色のみ指定しアーキタイプは未指定 | アーキタイプへの結合は色条件のために行われ、その色を持つアーキタイプのデッキに限定される。 |
| フォーマットで絞った結果と、アーキタイプ選択がクライアント表示上矛盾 | サーバーは送信されたアーキタイプ ID とフォーマット ID の両方を適用する。0 件になり得る。 |

| 観点 | 内容 |
|------|------|
| 一覧と検索条件 | 同一リクエストサイクルで組み立てたクエリと件数カウントは同一の検索データを使う。 |

## DBカラム

アーキタイプ条件が直接参照するデッキ側の外部キーは `dtb_deck.archetype_id`（実装での参照プロパティは `dtb_deck` のアーキタイプ関連）。アーキタイプ側の色は多対多の関連テーブル経由で結合される。列の型や関連テーブル名の細部はスキーマを参照する。

| テーブル | 列 | メモ |
|---------|-----|------|
| `dtb_deck` | `archetype_id` | IN 条件の対象の一端。 |
| `dtb_archetype` | `id`（現行 `archetype_id`） | 選択肢および結合の基点となる主キー。 |
| `dtb_archetype_color` | `archetype_id`・`color_id` | 色条件で結合する多対多中間表。色マスタは `mtb_color`。 |

### DB操作

本機能は参照系（検索）であり、DBへの登録・更新・削除は行わない。テーブル名は ec-cube-enterprise を正典とする。

| 操作種別 | 対象テーブル | 契機・条件 |
|---------|--------------|------------|
| 検索 | dtb_archetype / dtb_archetype_color / dtb_deck / mtb_color | 検索条件に合致するレコードを抽出する。 |

## ログ・監査

アーキタイプ条件固有のログ出力は設計の対象としない。デッキ検索全体で共通のログがあればそれに従う。

### ログに出してはいけないもの

- パスワード
- なりすまし対策トークン
- Cookie 値
- セッション ID の完全値
- Remember Me トークンの原値

### HTTPルート名とパス（コード探索用・旧入口節より退避）

- `admin_deck_list` … `GET` … `/{admin_route}/deck`（検索フォームの初期表示。セッションキー `admin.deck.search`・`admin.deck.search.page_no`・`admin.deck.search.page_count` を削除する。一覧結果は空のままである。）
- `m15-01_admin_deck_deck_search` … `GET, POST` … `/{admin_route}/deck/search/{page_no}`（`page_no` は正の整数（ルートの assert `^[1-9][0-9]*$`）。検索実行・一覧・ソート・ページ送り・表示件数変更、GET によるセッションからの検索条件復元。フォームの action は `page_no=1` 固定。）
