# バッチ 受注管理 — 店頭注文番号初期化

## 概要

店頭注文番号テーブルの全レコードを削除し、採番カウンタを初期値に戻すバッチである。コマンドライン（コンソールコマンド）から実行する。店頭販売で利用者へ提示する整理番号（店頭注文番号）は、店頭注文番号テーブルへ採番のたびに追加され、テーブルの自動採番値で連番が決まる。本バッチはこのテーブルを空にし、自動採番値を1へ戻すことで、次回以降の店頭注文番号を最初の番号から再採番できる状態にする。

本書は実装手順ではなく、誰が・いつ・どの条件で・結果どうなるかを読むためのリバース詳細設計とする。確認値はpf-eccube3（EC-CUBE3系）のHareruyaEcプラグインの受注バッチ（店頭注文番号初期化処理）、店頭注文番号を扱うリポジトリを正とする。カスタマイズ区分はカスタマイズであり、挙動の参照リポはpf-eccube3、DB関連はec-cube-enterpriseを正とする。

対象はコンソールコマンドであり、ブラウザ経由の画面を持たない。

本文ではフレームワークのコマンド型名やサービス型名を主説明としない。実行はコンソールのバッチコマンドで行う。

---

## 本書で扱うこと

- バッチの起動方法（コンソールコマンド）
- 店頭注文番号テーブルの全削除と採番カウンタの初期化
- 初期化に伴うデータ消失と再採番の挙動

- 店頭注文番号を表示する整理番号モニタ画面（画面側の設計を正とする）
- バッチの起動スケジュール（運用・ジョブ設定を正とする）

---

## リニューアル移行時の扱い

現行（pf-eccube3）の挙動と移行先（ec-cube-enterprise）の差を記録する。挙動は現行リポを正とし、DB関連はec-cube-enterpriseを正とする。

| 観点 | 現行（pf-eccube3） | 移行先（ec-cube-enterprise） |
|------|--------------------|------------------------------|
| 採番方式 | 店頭注文番号テーブル`dtb_waiting_number`の自動採番値（AUTO_INCREMENT）で連番を決める。 | 採番カウンタを専用テーブル`dtb_waiting_number_counter`（`base_info_id`・`current_value`）で保持する。`dtb_waiting_number`は`id`・`base_info_id`・`order_id`・`waiting_number`を持つ。 |
| 採番のリセット対象 | `ALTER TABLE dtb_waiting_number AUTO_INCREMENT = 1`でテーブルの自動採番値を1へ戻す。 | カウンタ列`dtb_waiting_number_counter.current_value`を初期値へ戻す方式が想定される（バッチの存在・初期化手順はec-cube-enterprise実装で要確認）。 |
| 整理番号の受注側保持 | 受注サブテーブル`dtb_order_sub`の`waiting_number`に保持する。 | 補助表`dtb_order_sub`を持たず、受注`dtb_order`の`waiting_number`（店舗販売用整理番号）に統合している。 |

## 用語

| 用語 | 説明 |
|------|------|
| 店頭注文番号 | 店頭販売で利用者へ提示する整理番号。店頭注文番号テーブルの自動採番値で連番が決まる。 |
| 店頭注文番号テーブル | 採番済みの店頭注文番号と紐づく受注IDを保持するテーブル（`dtb_waiting_number`）。 |
| 採番カウンタ | テーブルの自動採番値（AUTO_INCREMENT）。次に採番する番号を決める。 |

## 処理フロー

### 店頭注文番号初期化を実行する（`order:batch truncateWaitingNumber`）

1. 店頭注文番号テーブルの全レコードを削除する。
2. 店頭注文番号テーブルの採番カウンタを1へ戻す。
3. 処理を終了する。

抽出条件による絞り込みはなく、テーブル全体を対象とする。対象が0件の場合も削除文と採番カウンタ初期化を実行し、結果として空のテーブルと初期化済みのカウンタになる。

## 入出力

| 種類 | 内容 |
|------|------|
| 入力 | コマンド名。 |
| 成功時出力 | 店頭注文番号テーブルの全削除と採番カウンタの初期化。 |
| 失敗時出力 | 例外発生時はコンソールへ例外が伝播する。本バッチ独自のログ・通知は行わない。 |
| 副作用 | 店頭注文番号テーブルのレコード消失と採番カウンタのリセット。 |

このバッチは破壊的であり、テーブル内の店頭注文番号と紐づく受注IDの対応はすべて失われる。実行後は過去に提示済みの整理番号を本テーブルから参照できなくなり、採番は最初の番号から再開する。実行タイミングの妥当性は運用を正とする。

## データ整合性

| 観点 | 内容 |
|------|------|
| 多重実行 | ロックを持たない。複数同時実行でも結果は空テーブル・カウンタ1で同一になる。 |
| 途中失敗・再実行 | 削除と採番カウンタ初期化は別の文として順に実行する。削除のみ成功してカウンタ初期化前に中断した場合でも、再実行で空テーブル・カウンタ1に収束する。 |
| 参照時点 | 実行時点の店頭注文番号テーブルの全レコードを対象とする。 |
| データ消失 | 削除した店頭注文番号と受注IDの対応は復元しない。整理番号モニタ等の参照先は実行後に空となる。 |

## DBカラム

機能に直接関係する列のみ記載する。型や一覧の細部はスキーマを参照する。

テーブル・列名はec-cube-enterpriseを正とする。現行（pf-eccube3）と異なる場合は移行先名を主とし現行名を括弧で添える。

| テーブル | 列 | メモ |
|----------|-----|------|
| `dtb_waiting_number` | `waiting_number` | 店頭注文番号。現行は自動採番値で初期化時にAUTO_INCREMENTを1へ戻す。 |
| `dtb_waiting_number` | `order_id` | 紐づく受注ID。全レコード削除の対象。 |
| `dtb_waiting_number_counter` | `current_value` | 移行先の採番カウンタ（現行はテーブルのAUTO_INCREMENTで代替。初期化対象はこの列となる見込み、ec-cube-enterprise実装で要確認）。 |

### DB操作

永続化の正は ec-cube-enterprise（テーブル名・操作は ec-cube-enterprise を正典）。当ドメインは承認ワークフローを介さず persist/flush で直接確定する（承認ワークフローは在庫機能固有）。

| 操作種別 | 対象テーブル | 契機・条件 |
|---------|--------------|------------|
| 登録/更新 | dtb_waiting_number / dtb_waiting_number_counter | 当機能が行う登録・更新で対象テーブルを直接保存する（不要な削除は含まない）。確定は persist/flush による即時反映。DB=ec-cube-enterprise を正典とする。 |

## 排他制御・トランザクション

ロックファイル等による多重起動防止は行わない。削除と採番カウンタ初期化は1トランザクションでまとめた更新ではなく、それぞれ独立した文として実行する。長時間処理向けの実行時間制限解除や逐次フラッシュは行わない。本バッチは楽観ロック・悲観ロックの対象を持たない。
