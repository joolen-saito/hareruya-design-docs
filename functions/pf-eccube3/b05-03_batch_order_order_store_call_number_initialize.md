# バッチ 受注管理 — 店頭注文番号初期化

## 業務ロジック

### 対象と処理

対象は店頭注文番号の全件とする。日付や状態による絞り込みは、いずれの場合も行わない。

| 順序 | 処理 | 内容 |
| --- | --- | --- |
| 1 | 全件削除 | 件数によらず、店頭注文番号を全件削除する |
| 2 | 採番カウンタの初期化 | 削除が終わったときに、次回の採番値を 1 へ戻す |

対象が0件のときも、削除と採番カウンタの初期化を実行する。結果は、店頭注文番号が無い状態と、初期化済みの採番カウンタだけになる。

何度実行したときも結果は同じになる。冪等である。

集計と金額計算は、いずれの場合も行わない。

### 実行の影響

このバッチは破壊的である。店頭注文番号と紐づく受注IDの対応は、いずれの場合もすべて失われる。実行した後は、過去に提示済みの整理番号を店頭注文番号から引けなくなる。採番は、次に発番したときだけ最初の番号から再開する。実行タイミングの妥当性は、いずれの場合も運用を正とする。

### エラー時の扱い

| 事象 | 扱い |
|------------|------|
| コマンド名が未指定・不一致のとき | 処理を行わずに終了する |
| 対象が0件のとき | 削除と採番カウンタの初期化を実行し、店頭注文番号が無い状態・カウンタ 1 で完了する |
| 削除または初期化の途中で例外が起きたとき | 例外を捕捉せず処理を中断し、コンソールへ伝える。本バッチ独自の通知は行わない |

## 入出力

| 種類 | 内容 |
|------|------|
| 入力 | コマンド名。引数は使わない。実行条件は特に無く、対象が0件でも実行できる。 |
| 成功時出力 | 店頭注文番号が全件無くなり、採番カウンタが 1 へ戻る。 |
| 失敗時出力 | 例外が起きたときは処理が中断し、コンソールへ例外が伝わる。 |

### 入出力: 永続化

| 操作 | 契機 |
| --- | --- |
| 削除 | 実行のたびに、店頭注文番号を全件削除する |
| 更新 | 全件削除の後に、次回の採番値を 1 へ戻す |

## 表示メッセージ

この機能は、いずれの場合も画面のメッセージを扱わない。
