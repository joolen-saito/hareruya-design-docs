# m05-04_admin_order_order_shipping_csv_export（管理画面_受注管理_配送CSV出力）

## 概要

管理画面の「受注管理」受注一覧から、CSV種別が配送（`mtb_csv_type`のID確認値`CsvType::CSV_TYPE_SHIPPING`、整数値4）の出力項目定義にしたがってファイルをダウンロード応答として返す機能である。一覧UIの翻訳キー`admin.order.shipping_csv.download`では「出荷CSVダウンロード」と表示される。抽出対象の受注集合は、受注一覧と同一のセッション検索条件で決まる。

本書は実装手順ではなく、誰が・いつ・どの条件で・結果どうなるかを読むためのリバース詳細設計とする。確認値とするソースは `src/Eccube/Controller/Admin/Order/OrderController.php`、`src/Eccube/Service/CsvExportService.php`、`src/Eccube/Resource/template/admin/Order/index.twig`、`app/config/eccube/packages/eccube.yaml` とする。

対象はブラウザ経由の管理画面に限定する。

本機能のカスタマイズ区分はカスタマイズである。配送CSV出力は標準のEC-CUBE系受注CSV出力で、移行先 ec-cube-enterprise にも同名ルートで実装される。現行挙動は pf-eccube3 のHareruyaEcプラグイン実装を参照し、リニューアル移行後の挙動とDBは ec-cube-enterprise を確認値とする。DB関連の記述は ec-cube-enterprise を正とする。

コントローラの公開関数一覧は本文の主題としない。本文ではルートbind名やSymfonyのルートnameの網羅は主説明としない。「利用者視点の入口」にHTTPメソッドとサイトルートからのパスパターンを書く。コード探索でbind名が必要なときだけ「調査補助」へ書く。

本書のDBカラム節・処理フローのDB記述は移行先 ec-cube-enterprise の名称（`sort_no`・`enabled` 等）に合わせている。現行名は上表で対応づける。

## 処理フロー

### CSVをダウンロードする（GET `admin_order_export_shipping`）

1. 管理画面の認証・共通制約を通過する。
2. PHPの実行時間制限を無効にする（`set_time_limit(0)`）。
3. ORMのSQLロガーを無効にする（引数なしの`setSQLLogger()`呼び出し）。
4. `StreamedResponse`のコールバック内で次項から実行する。
5. CSV出力サービスを`CsvType::CSV_TYPE_SHIPPING`で初期化し、`enabled`が真の`dtb_csv`行だけを`sort_no`昇順で読み込む。
6. リクエストとセッションの`eccube.admin.order.search`から受注検索フォーム相当のデータを組み立て、管理画面向け受注検索のクエリビルダを取得する。
7. ヘッダ行を出力する。初期化後に有効列が1件も無い場合は論理例外により失敗する（コールバック実行時）。
8. データ行について、クエリ結果をページサイズ100件ずつpaginatorで取得し、各ページ処理後にエンティティマネージャを`clear`する。
9. 各受注について`OrderItems`を列挙し、各受注明細につき1行を組み立てる。
10. 1列ごとに、出力サービスの「CSV定義行とエンティティのフィールドが一致するときだけ値を取り出す」処理を、順に受注本体・当該受注明細・当該受注明細に紐付く配送（存在するとき）へ適用する。いずれでも値が取れなければセルは空になる。
11. 列ごとの処理のあと、イベント識別子 `admin.order.csv.export.order` でイベントをディスパッチし、プラグインが同じ行データへ介入できる。
12. 組み立てた行をCSVとして書き込み、ページループ・受注明細ループを終えるまで繰り返す。
13. 応答ヘッダに `Content-Type: application/octet-stream` と `Content-Disposition: attachment`（ファイル名は `shipping_` + `YmdHis` + `.csv`）を付与する。
14. ストリーム開始前に情報ログへ「配送CSV出力ファイル名」とファイル名を記録する。

## 集計条件

本機能は売上集計を行わない。出力対象は「受注検索ビューデータを入力として管理画面向けに構築した受注クエリ」に一致する受注であり、その集合は受注一覧と同一の検索状態に依存する。抽出結果が0件でもヘッダのみのCSVを返しうる。

| 指標 | 集計の要点 |
|------|------------|
| 出力される受注件数 | 検索クエリに一致する受注。ページングはサーバ内部で100件ずつ処理するだけであり、CSVの行数とは別次元である。 |
| 出力されるCSV行数 | 対象各受注の`OrderItems`の件数の合計（受注明細ゼロの受注は行を増やさない）。 |

## 業務ルール・計算

| 項目 | 内容 |
|------|------|
| 列セットと順序 | `csv_type_id`が配送種別の`dtb_csv`のうち`enabled`が真の行のみ。順序は`sort_no`昇順。表示ヘッダは各行の`disp_name`。 |
| セル値の型変換 | 日時は設定`eccube_csv_export_date_format`で文字列化する。真偽値は`1`または`0`。関連が単体エンティティなら参照フィールドで1値を取る。関連がコレクションなら参照フィールドごとの値を設定`eccube_csv_export_multidata_separator`で連結する。スカラーはそのまま文字列化してエンコード処理へ渡す。 |
| 文字コードとBOM | 出力ストリームはUTF-8から設定`eccube_csv_export_encoding`へ変換する。設定値がUTF-8（大文字小文字無視）のときは先頭にBOMを書く。 |
| 区切り文字 | `eccube_csv_export_separator`を`fputcsv`の区切りとして用いる。エスケープはバックスラッシュ、囲みは二重引用符の確認値である。 |

本機能ではフォームPOSTを伴わないため、`### 入力項目`の表は置かない。

### エッジケース

| ケース | 扱い |
|--------|------|
| 有効な出力列が0件 | ヘッダ出力時点で論理例外となり、応答はエラー系となる。 |
| 検索結果が0件 | ヘッダのみのファイルを返す確認値である。 |
| 受注明細に配送が無い | 配送エンティティ向けの列は、受注・受注明細からも解決できなければ空セルとなる。 |
| 同一配送に複数明細がある | 明細ごとに行が分かれ、配送由来の列は同一値が繰り返し出力される。 |

## データ整合性

| 観点 | 内容 |
|------|------|
| 一覧との一致 | 出力対象受注の集合は、セッション検索条件が一覧と共有される限り一覧のクエリと整合する。一覧が配送単位の複数行であっても、CSVは受注明細単位の別粒度である。 |
| 参照時点 | ストリーム処理中にページごとにエンティティマネージャをクリアするため、長時間出力でもメモリ再利用優先の実装である。同一実行内でDBが変わった場合、後続ページの内容は読み直し後の状態となる。 |
| DBの更新 | 読み取りのみであり、受注・配送・明細を更新しない。 |

## DBカラム

当機能は実行時に`dtb_csv`と`mtb_csv_type`を読むほか、受注検索に依存する多数のテーブルをJOINしうる。列一覧の細部はスキーマおよび`m05-01_admin_order_order_search_list.md`を正とし、本書では「出力列が参照しうるフィールドは`dtb_csv.entity_name`と`field_name`の組で決まる」とだけ示す。

| テーブル | 列 | メモ |
|---------|-----|------|
| `dtb_csv` | `csv_type_id`, `entity_name`, `field_name`, `reference_field_name`, `disp_name`, `sort_no`, `enabled` | 配送種別かつ`enabled`が出力対象。 |
| （セッション） | `eccube.admin.order.search`に保存される検索条件の各キー | 受注一覧と共有。 |

### DB操作

本機能は参照系（検索・出力）であり、DBへの登録・更新・削除は行わない。テーブル名は ec-cube-enterprise を正典とする。

| 操作種別 | 対象テーブル | 契機・条件 |
|---------|--------------|------------|
| 検索 | dtb_csv / mtb_csv_type | 検索条件に合致するレコードを抽出する。抽出結果を所定フォーマットでファイル出力する。 |
