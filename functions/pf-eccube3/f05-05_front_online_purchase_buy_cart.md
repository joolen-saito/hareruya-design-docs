# F05-05（ネット買取カート）

## 概要

ネット買取で買取を希望する商品をカートに保持し、カート内商品の一覧・数量変更・削除・合計買取価格の表示を行う機能である。買取商品一覧・詳細の「カートに追加」から非同期で商品クラス単位に追加し、買取希望品カート画面で数量を再計算して買取手続きへ進む。買取カートはセッションに保持し、商品の追加・更新・削除・合計算出を通じて整える。

本書は実装手順ではなく、誰が・いつ・どの条件で・結果どうなるかを読むためのリバース詳細設計とする。確認値はpf-eccube3（EC-CUBE3系）のHareruyaEcプラグインの買取カート処理（表示・追加・削除・更新・合計算出）、カートテンプレート（`Purchase/cart.twig`）、買取共通JS（`Block/js/purchase_js.twig`）、ロケールメッセージ（`message.ja.yml`）を正とする。

カスタマイズ区分はカスタマイズとする。挙動の参照リポはpf-eccube3（現行）とし、DB関連（テーブル名・列名・型・制約・関連、DBカラム節、保存先・扱い、データ整合性のDB部分）は ec-cube-enterprise を正とする。買取カート自体はセッション保持でDB列を持たない。

対象はブラウザ経由のフロント（ネット買取）に限定する。フロントのルートはロケールプレフィックス`/{_locale}`配下にマウントされ、買取機能は`/purchase`配下にマウントされる。

本文ではフレームワークのコントローラ型名やメソッド名を主説明としない。本文ではルートbind名の網羅は主説明とせず、「利用者視点の入口」にHTTPメソッドとサイトルートからのパスパターンを書く。コード探索でbind名が必要なときだけ「調査補助」へ書く。

## リニューアル移行時の扱い

現行（pf-eccube3）と移行先（ec-cube-enterprise）のDBスキーマ差分を記録する。カート操作はセッション上で行いDB列を持たないため、参照する商品データの保持先のみ差分となる。挙動は現行の確認値を正とし、永続化先の名称は移行先（ec-cube-enterprise）を正とする。

| 項目 | 現行（pf-eccube3） | 移行先（ec-cube-enterprise） | 備考 |
|------|--------------------|------------------------------|------|
| 買取価格の保持単位 | 商品サブクラス（`dtb_product_sub_class`）の `buy_price` | 商品クラス（`dtb_product_class`）の `buy_price` | 単価・小計・合計の算出に参照する。移行先では商品サブクラスを商品クラスへ統合する。 |
| カートの保持キー | 商品クラスID（`product_class_id`） | `dtb_product_class.id`（`product_class_id`） | カートはセッション上に商品クラスIDと数量の組のみ保持する。 |
| 「まとめて買取」判定 | 商品ID（`dtb_product.id`） | `dtb_product.id` | 同一スキーマ。 |

同一商品の数量上限（20点）はカート処理側の設定値であり、移行先の値は ec-cube-enterprise 実装で要確認とする。

## 処理フロー

### 買取希望品カートを表示する（GET `/{_locale}/purchase/cart`）

1. セッションから買取カートを取得する。カートが無い場合は商品なし・合計なしのカート画面を表示する。
2. カート内の商品クラスIDから対象の商品サブクラスを取得する。
3. 「まとめて買取」の商品がカートに含まれるか判定する。
4. 合計買取価格を算出する。算出時にカートへ残らない商品（対象データが無い商品）は除く。
5. カート内商品・合計・まとめて買取の有無とともにカート画面を表示する。

### カートに追加する（POST `/{_locale}/purchase/add`）

1. 商品クラスIDと数量（既定1）を受け取る。商品クラスIDが空ならエラー応答（HTTP500相当）を返す。
2. 既に同一商品がカートにある場合は数量を加算する。
3. 加算後の数量が同一商品の上限（20点）を超える場合は、上限超過のJSON（メッセージ付き、状態`overlimit`、HTTP400）を返す。
4. 上限以内なら商品クラスごとに数量をセッションへ保存する。

### カート内商品を削除する（PUT `/{_locale}/purchase/{id}/remove`）

1. なりすまし対策トークンを検証する。
2. セッションのカートに当該商品が無い場合はカート表示へ戻す。
3. 当該商品をカートから外し、カート表示へ戻す。

### 数量を更新する（POST `/{_locale}/purchase/update`）

1. 入力された数量一覧で各商品の数量を更新する。
2. 数量が数字でない・1未満の商品はカートから外す。
3. いずれかの数量が上限（20点）を超える場合は上限超過のメッセージを要求エラーに積み、更新を中断する。
4. 更新後、カート表示へ戻す。

## 業務ルール・計算

| 項目 | 内容 |
|------|------|
| 同一商品の数量上限 | 同一商品はカートに20点まで。追加・更新で超える場合はそれぞれ上限超過として扱う。 |
| 数量の正規化 | 更新時、数字でない・1未満の数量はカートから外す。 |
| 合計算出 | 買取価格×数量の総和を税込小計として表示する。対象データが無い商品は除外する。 |
| 追加時の既定数量 | 数量未指定時は1とする。 |
| まとめて買取の案内 | 「まとめて買取」がカートに含まれる場合はカート用JSを読み込まず、案内に従う扱いとする。 |

### 入力項目

| 項目名 | 必須／任意 | 最大長 | 初期値 | 保存先・扱い |
|--------|------------|--------|--------|----------------|
| 数量（カート追加） | 任意 | 同一商品20点まで（上限超過はHTTP400） | 1 | 追加リクエストのキー`quantity`。商品クラス（`product_class_id`）ごとにセッションの買取カートへ保存。 |
| 数量（カート内更新） | 必須 | 同一商品20点まで（超過は更新中断） | カート現在値 | 更新リクエストのキー`qty[商品クラスID]`。数字以外・1未満は当該商品をカートから外す。表示は3桁。 |

カートはセッションに保持し、削除はなりすまし対策トークン付きのリンクで行う。

### エッジケース

| ケース | 扱い |
|--------|------|
| 商品クラスID未指定で追加 | エラー応答（HTTP500相当）を返す。 |
| 既存商品の再追加 | 数量を加算し、上限超過なら上限超過応答を返す。 |
| 数量を0・非数値に更新 | 当該商品をカートから外す。 |
| 数量更新で上限超過 | 上限超過メッセージを要求エラーに積み、更新を中断する。 |
| 削除対象がカートに無い | カート表示へ戻す（変更しない）。 |
| 合計算出時に対象データ無し | 当該商品をカートから除外して算出する。 |

## DBカラム

機能に直接関係する列のみ記載する。型や一覧の細部はスキーマを参照する。買取カート自体はセッション保持でDB列を持たない。テーブル・列名は ec-cube-enterprise を正とする。現行（pf-eccube3）の保持単位は括弧で添える。

| テーブル | 列 | メモ |
|---------|-----|------|
| `dtb_product_class`（現行は商品サブクラス `dtb_product_sub_class`） | `buy_price` | 単価・小計・合計の算出に用いる。 |
| `dtb_product_class` | `id`（`product_class_id`） | カートの保持キー。 |
| `dtb_product` | `id` | 「まとめて買取」判定に用いる。 |

### DB操作

永続化の正は ec-cube-enterprise（テーブル名・操作は ec-cube-enterprise を正典）。当ドメインは承認ワークフローを介さず persist/flush で直接確定する（承認ワークフローは在庫機能固有）。

| 操作種別 | 対象テーブル | 契機・条件 |
|---------|--------------|------------|
| 登録/更新 | dtb_product / dtb_product_class / dtb_product_sub_class | 当機能が行う登録・更新で対象テーブルを直接保存する（不要な削除は含まない）。確定は persist/flush による即時反映。DB=ec-cube-enterprise を正典とする。 |
