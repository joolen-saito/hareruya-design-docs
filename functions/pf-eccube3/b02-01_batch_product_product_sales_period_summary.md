# バッチ 商品管理 — 期間別販売数集計

## 概要

商品マスターの一覧画面に表示する販売数を、期間別（前日・直近3日・週・月・90日・180日・365日）に集計し、商品規格サブの販売数列へ反映するバッチである。コマンドライン（コンソールコマンド）から実行する。集計は受注詳細の数量を受注日と受注ステータスで絞り込んで行う。

本書は実装手順ではなく、誰が・いつ・どの条件で・結果どうなるかを読むためのリバース詳細設計とする。確認値はpf-eccube3（EC-CUBE3系）のHareruyaEcプラグインの商品バッチ（販売数集計処理）、受注詳細・商品規格サブを扱うリポジトリを正とする。本機能のカスタマイズ区分はカスタマイズであり、現行挙動はpf-eccube3を参照し、DB関連の記述はec-cube-enterpriseを正とする。

対象はコンソールコマンドであり、ブラウザ経由の画面を持たない。

本文ではフレームワークのコマンド型名やサービス型名を主説明としない。実行はコンソールのバッチコマンドで行う。

- 受注詳細から期間別販売数を集計する条件
- 商品規格サブの販売数列への反映
- 対象が無い場合の挙動

## リニューアル移行時の扱い

現行（pf-eccube3）と移行先（ec-cube-enterprise）でDBスキーマが次のとおり異なる。挙動は現行を踏襲し、DB関連の記述は移行先を正とする。

| 観点 | 現行（pf-eccube3） | 移行先（ec-cube-enterprise） |
|------|--------------------|------------------------------|
| 受注詳細テーブル | `dtb_order_detail` | `dtb_order_item`（列 `product_class_id`・`quantity` は同名） |
| 受注ステータス列 | `dtb_order.status` | `dtb_order.order_status_id`（受注日 `order_date` は同名） |
| 販売数の反映先 | 商品規格サブ `dtb_product_sub_class` の販売数列 | 補助表を設けず商品規格 `dtb_product_class` の `order_quantity_01`〜`order_quantity_08` に統合（列名は同じだが保持テーブルが異なる） |

## 利用者視点の入口

| 入口 | 実行方法 | 期待されるふるまい |
|------|----------|--------------------|
| コンソールのバッチコマンド | `product:batch updateProductSummary` | 受注詳細から期間別の販売数を集計し、商品規格サブの販売数列を更新する。 |

本機能はHTTPで届く画面を持たない。コマンド名が一致しない場合は処理を行わずに終了する。

---

## 処理フロー

### 期間別販売数集計を実行する（`product:batch updateProductSummary`）

1. 実行時間制限を解除し、SQLロガーを無効化する。
2. 受注詳細を商品規格単位で集計し、期間別販売数（前日・3日・週・月・90日・180日・365日）の一覧を取得する。
3. 対象が無い場合は更新を行わずに終了する。
4. 集計結果の行ごとに、商品規格サブの販売数列を更新する。
5. 100件ごとに変更を反映しキャッシュをクリアしながら処理する。
6. 残りの変更を反映して終了する。

## 業務ルール・計算

| 項目 | 内容 |
|------|------|
| 集計単位 | 商品規格単位（商品規格ID）。 |
| 集計値 | 受注詳細の数量の合計。 |
| 除外条件 | 受注ステータスがキャンセル・処理中の受注は各期間の合計から除外する。 |
| 反映先 | 商品規格サブの販売数列（前日・3日・週・月・90日・180日・365日）。当日相当の列は0で初期化する。 |

---

## 集計条件

| 指標 | 集計の要点 |
|------|------------|
| 対象データ | 受注詳細と受注を結合し、受注日が当日から366日前以降の受注詳細に限定して集計する。 |
| 結合 | 受注詳細と受注を受注IDで結合する。 |
| 除外 | 受注ステータスがキャンセル・処理中の受注を各期間合計から除く。 |
| 集計期間 | 当日基準で前日・直近3日・7日・28日・90日・180日・365日の各区間。 |
| 一意化 | 商品規格IDでグループ化する。 |

## API・バッチ結果

| 種類 | 内容 |
|------|------|
| 入力 | コマンド名。引数は取らない。 |
| 実行条件 | 集計対象期間内に受注詳細が存在すること。 |
| 成功結果 | 商品規格サブの販売数列が最新の集計値で更新される。 |
| 失敗結果 | 途中失敗時は反映済みの行のみ更新が残る。 |
| 再実行時 | 実行時点のデータで再集計し、対象商品規格の販売数列を上書きする。重複加算は起きない。 |

---

## 入出力

| 種類 | 内容 |
|------|------|
| 入力 | コマンド名。 |
| 成功時出力 | 商品規格サブの販売数列の更新。 |
| 失敗時出力 | エラーメッセージのコンソール出力。途中で止まった場合は反映済みの行のみ更新が残る。 |
| 副作用 | 商品規格サブの更新。 |

---

## データ整合性

| 観点 | 内容 |
|------|------|
| 多重実行 | ロックは持たない。同時実行時は同一行を上書きするため最後の更新値が残る。 |
| 途中失敗・再実行 | 上書き更新のため再実行で正しい集計値に収束する。部分反映は次回実行で回収される。 |
| 参照時点 | 実行時点の受注・受注詳細を対象とする。 |

---

## DBカラム

機能に直接関係する列のみ記載する。型や一覧の細部はスキーマを参照する。

| テーブル | 列 | メモ |
|----------|-----|------|
| `dtb_order_item`（現行 `dtb_order_detail`） | `product_class_id`・`quantity` | 集計の集計単位・集計値。 |
| `dtb_order` | `order_date`・`order_status_id`（現行 `status`） | 期間判定・除外判定に使用する。 |
| `dtb_product_class`（現行は商品規格サブ `dtb_product_sub_class`） | `order_quantity_01`〜`order_quantity_08` | 期間別販売数の反映先。`order_quantity_01`は0で初期化する。移行先では商品規格に統合する。 |

### DB操作

本機能は参照系（検索）であり、DBへの登録・更新・削除は行わない。テーブル名は ec-cube-enterprise を正典とする。

| 操作種別 | 対象テーブル | 契機・条件 |
|---------|--------------|------------|
| 検索 | dtb_order / dtb_order_detail / dtb_order_item / dtb_product_class / dtb_product_sub_class | 検索条件に合致するレコードを抽出する。 |

## 排他制御・トランザクション

ロックファイルによる多重起動防止は持たない。長時間処理に備えて実行時間制限を解除し、100件ごとに変更を反映しキャッシュをクリアしてメモリを管理する。本バッチは楽観ロック・悲観ロックの対象を持たない。
