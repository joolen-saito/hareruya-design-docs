# 会員 — お問い合わせ履歴（一覧・詳細）

## 概要

ログイン済み会員が、自分が過去に送信したお問い合わせの一覧と、その1件ごとの詳細を閲覧する機能である。マイページトップの「お問い合わせ履歴」ブロックから一覧へ入り、一覧の各件名リンクから詳細へ遷移する。いずれも閲覧専用で、当画面からの編集・送信・削除は行わない。

本書はTODOリストの「お問い合わせ履歴」（F06-23）と「お問い合わせ履歴詳細」（F06-24）の2機能を、同一コントローラ・同一データを参照する一連の閲覧機能として1冊にまとめる。

本書は実装手順ではなく、誰が・いつ・どの条件で・結果どうなるかを読むためのリバース詳細設計とする。確認値はpf-eccube3（EC-CUBE3系）のHareruyaEcプラグインのお問い合わせ処理（一覧・詳細）、テンプレート（`Contact/history.twig`・`Contact/history_detail.twig`）、お問い合わせを扱うリポジトリを正とする。

本機能のカスタマイズ区分は現行踏襲であり、画面・挙動の参照はpf-eccube3を正とし、永続化（テーブル・列）に関する記述はリニューアル移行先のec-cube-enterpriseを正とする。

対象はブラウザ経由のフロント（会員マイページ）に限定する。

本文ではフレームワークのコントローラ型名やメソッド名を主説明としない。本文ではルートbind名の網羅は主説明とせず、「利用者視点の入口」にHTTPメソッドとサイトルートからのパスパターンを書く。コード探索でbind名が必要なときだけ「調査補助」へ書く。

## リニューアル移行時の扱い

現行（pf-eccube3）と移行先（ec-cube-enterprise）でのDB関連の差を記録する。本機能は参照のみで永続化を行わないため、参照先の名称をec-cube-enterpriseに合わせる。

| 観点 | 現行（pf-eccube3） | 移行先（ec-cube-enterprise） |
|------|--------------------|------------------------------|
| お問い合わせの格納先 | お問い合わせテーブル（`dtb_contact`） | 同一スキーマ（`dtb_contact`が存在）。 |
| 並び順・絞り込みキー | お問い合わせ番号（`id`）、会員参照 | `dtb_contact.id`（降順）、`dtb_contact.customer_id`（会員絞り込み）。 |
| 表示項目の列 | 送信日時・件名参照・氏名・本文 | `dtb_contact.create_date`／`subject_id`（件名マスタ参照）／`name01`・`name02`／`body`。同名列が存在し同一スキーマ。 |

## 利用者視点の入口

| 入口 | URLエンドポイント | 期待されるふるまい |
|------|--------------------|--------------------|
| マイページトップの「お問い合わせ履歴」ブロック | `GET /contact/history` | ログイン会員自身のお問い合わせを新しい順に一覧表示する。総件数と各件の日時・件名・お問い合わせ番号を出す。 |
| 一覧の件名リンク | `GET /contact/history/{id}/detail` | 当該お問い合わせ1件の詳細（日時・件名・番号・氏名・本文）を表示する。 |
| 一覧の「マイページ」ボタン | `GET /mypage`（マイページトップ） | マイページトップへ戻る。 |
| 詳細の「戻る」リンク | ブラウザ履歴を1つ戻る（`history.go(-1)`） | 直前の画面（通常は一覧）へ戻る。サーバへのリクエストは発生しない。 |

フロントのページであり管理画面プレフィックスは付かない。`/contact/history`配下は会員ログインを要する。

## フロント挙動

| 観点 | 内容 |
|------|------|
| 表示要素 | 一覧は見出し「お問い合わせ履歴一覧」、会員氏名、総件数（「N件」）、各件の送信日時（`Y年m月d日 H:i`）・件名（リンク）・お問い合わせ番号、「マイページ」ボタン。詳細は見出し「お問い合わせ履歴詳細」、会員氏名、送信日時（`Y/m/d H:i`）・件名・お問い合わせ番号、問い合わせ者氏名、本文（改行を反映して表示）、「戻る」リンク。 |
| JS挙動 | 詳細の「戻る」はブラウザ履歴を1つ戻すリンクのみ。非同期取得や動的な表示切替は扱わない。 |
| CSS・レイアウト | 詳細画面で問い合わせ表示用の追加スタイルを読み込む。利用者の挙動理解に影響する分岐表示はない。 |
| モーダル・ポップアップ | 本画面専用のモーダルは無い。 |

一覧は0件でも見出しと総件数「0件」を表示する（後述）。

## 処理フロー

### お問い合わせ履歴一覧を表示する（GET `/contact/history`）

1. 会員ログインを要求する。ログイン会員を特定する。
2. お問い合わせを、当該会員のものに絞り、お問い合わせ番号（ID）の降順で取得する。
3. 一覧テンプレートへ会員と一覧を渡し、総件数と各件を表示する。

### お問い合わせ履歴詳細を表示する（GET `/contact/history/{id}/detail`）

1. 会員ログインを要求する。ログイン会員を特定する。
2. パスの`id`と当該会員の両方に一致するお問い合わせ1件を取得する。
3. 詳細テンプレートへ会員と当該お問い合わせを渡し、日時・件名・番号・氏名・本文を表示する。

## 業務ルール・計算

| 項目 | 内容 |
|------|------|
| 並び順 | 一覧はお問い合わせ番号（ID）の降順（新しい順）で表示する。 |
| 件数 | 総件数は当該会員のお問い合わせ件数。0件のときも「0件」を表示する。 |
| 件名表示 | 件名はお問い合わせ種別マスタの日本語名称を表示する。 |
| 日時書式 | 一覧は`Y年m月d日 H:i`、詳細は`Y/m/d H:i`で送信日時を表示する。 |

本機能では業務計算を行わない。入力フォームを持たないため入力項目は無い。

### エッジケース

| ケース | 扱い |
|--------|------|
| お問い合わせが0件 | 一覧見出しと「0件」を表示し、明細を出さない。 |
| 他会員のIDを詳細URLに指定 | 会員条件で絞るため当該お問い合わせは取得できない。自分以外の内容は表示しない。 |
| 存在しないIDを詳細URLに指定 | 取得結果が無く、当該お問い合わせの内容は表示しない。 |

## DBカラム

機能に直接関係する列のみ記載する。型や一覧の細部はスキーマを参照する。

| テーブル | 列 | メモ |
|---------|-----|------|
| `dtb_contact` | `id` | お問い合わせ番号。一覧の並び順キー（降順）、詳細の絞り込みキー。 |
| `dtb_contact` | `customer_id` | 会員ごとの絞り込みキー。 |
| `dtb_contact` | `create_date` | 送信日時として表示する。 |
| `dtb_contact` | `subject_id` | 件名マスタへの参照。件名の名称を表示する。 |

| `dtb_contact` | `body` | 詳細で本文として表示する。 |

### DB操作

本機能は参照系（検索）であり、DBへの登録・更新・削除は行わない。テーブル名は ec-cube-enterprise を正典とする。

| 操作種別 | 対象テーブル | 契機・条件 |
|---------|--------------|------------|
| 検索 | dtb_contact | 検索条件に合致するレコードを抽出する。 |
