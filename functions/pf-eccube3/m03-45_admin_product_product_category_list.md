# 商品管理 — カテゴリ一覧

## 概要

管理画面「商品管理」配下で、カテゴリツリーを辿りながら階層ごとの一覧を表示し、同一画面上で子カテゴリの新規入力・既存ノードの編集・並べ替え・削除確認・カテゴリCSVのダウンロードおよびCSV項目設定画面への遷移を行う機能である。ルート階（親なし）は直下ノードのみの一覧であり、画面上部の入力フォームは出ない。

本書は実装手順ではなく、誰が・いつ・どの条件で・結果どうなるかを読むためのリバース詳細設計とする。ec-cube-enterprise のコア実装および `dtb_category` 周りのリポジトリを確認値とする。

本機能のカスタマイズ区分はカスタマイズである。画面・処理の挙動は現行リポ（pf-eccube3）の実装を参照し、DB関連（テーブル名・列名・保存先・副作用のDB更新）は ec-cube-enterprise を正とする。

対象はブラウザ経由の管理画面に限定する。

コントローラのメソッド名は本文の主題としない。本文ではルートbind名やSymfonyのルートnameの網羅は主説明としない。「利用者視点の入口」にHTTPメソッドとサイトルートからのパスパターンを書く。コード探索でbind名が必要なときだけ「調査補助」へ書く。

## リニューアル移行時の扱い

本書のDB記述は移行先 ec-cube-enterprise の `dtb_category` を正とする。本機能が読み書きする列は移行先ですべて `dtb_category` に実在を確認した。現行 pf-eccube3 では一部の拡張列を補助表に分離している。

| 観点 | 現行（pf-eccube3） | 移行先（ec-cube-enterprise） |
|------|--------------------|------------------------------|
| 英語名・各種拡張列 | 補助表 `dtb_category_sub`（英語名は `name_en`、非表示フラグ等） | `dtb_category` に統合（`category_name_en`・`front_search_hide_flg`・`branch_hide_flg`・`banner_image`・`icon_image`・`html_ja`・`html_en`・`search_parameters` を実在確認） |
| 兄弟の並び順キー | `rank`（`dtb_category_sort` 等の補助での `rank` を用いる経路がある） | `dtb_category.sort_no`（降順。実在確認済み） |
| 階層・親子 | `dtb_category` の `parent_category_id`・`hierarchy` | 同一 |

並び順キーは現行が `rank`、移行先が `sort_no` であり取り違えない。基本設計が描く本機能固有の追加仕様は無い。現行側の補助表と移行先列の正確な対応は pf-eccube3 実装で要確認とする。

## 処理フロー

### ルート直下一覧を開く（`GET admin_product_category`）

1. 管理画面認証済み状態で共通制約を通過する。
2. 親を null とし、`getList(null)` が返す直下カテゴリ配列と、すべてのルートおよび深さ 5 段まで関連を結合順序付けで取得した `TopCategories`、`buildBreadcrumbIds(null)` が空になるパラメータを Twig へ渡す。
3. フォームオブジェクトは空のビルダで作られ、Twig はフォーム開始タグ自体を出力しないため、リストとツリーと CSV 関連ボタンのみとなる。

### 親配下一覧を開く（`GET admin_product_category_show`）

1. パスの `parent_id` が論理上不整合なら 404 とする。
2. 対象親と新規エンティティ（階層は親より 1、`Parent` が設定済み）から `CategoryType` でフォームを組み、アクションは `POST admin_product_category_create` とする画像アップロード許可フラグあり。
3. `getList(親)` と `TopCategories`、パンくず用 ids、対象一覧 ID を渡すイベントでフォーム構築を差し込めるようにする。
4. 兄弟一覧および右ツリーを同一テンプレートで描く。

### 編集一覧を開く（`GET admin_product_category_edit`）

1. パスで取得した対象ノードの親および本人をセットし、アクションが `POST admin_product_category_update`、画像アップロードは無効のフォームを渡す。
2. `Categories` は `getList(編集対象の親)` により兄弟全体を並べ、`isCategoryEdit` 真で変換ボタン文言が更新側になる。
3. パンくずは `TargetCategory.path` で祖先を辿るループで出力するため、親 id が null でないときは祖先リンクまで含める。

### 子を作成するまたは更新する POST

1. 対応するフォーム種とアクションへ `handleRequest` する。未送信または検証 NG のとき、この GET と同構成の Twig を 200 で返す。
2. 検証済み作成フローのみ、アップロード可能ファイルをディスクへ移し、MIME が image で始まること、許可拡張子のみ、異常時はフォームエラーおよび移動済みファイルを取り除き再表示する。
3. 送信完了前に現在階層が設定 `eccube_category_nest_level`（確認値 5）を超えないかを検証し、`hierarchy` が設定値より大きいなら `BadRequestHttpException` により HTTP 400 とする実装にある。
4. リポジトリの `save` で永続化し、作成完了イベントを通知し、`admin.common.save_complete` と同一メッセージ体系の成功フラッシュを載せ、`CacheUtil::clearDoctrineCache` を実行する。
5. 親が無い保存後は一覧ルート、`Parent` がいれば `GET …/category/{parent_id}` へHTTPリダイレクトする。

### 並べ替え Ajax（`POST admin_product_category_sort_no_move`）

1. `XMLHttpRequest` でないときは異常応答（HTTP 400）とする。
2. メタヘッダまたは標準名前のフィールドにある CSRF トークンを検証する。無効時は共通メソッドがアクセス拒否（HTTP 403）となる。
3. POST ボディからトークンフィールドキーを除外し残りキーをカテゴリ primary key、値を整数 `sort_no` として順にセットしフラッシュまで行う。その後Doctrineキャッシュを破棄する。
4. HTTP 応答本体は字面 `Successful` のテキスト返却のみで、画面上の並び順は送信時点と一致している前提となる。

### 削除（`DELETE admin_product_category_delete`）

1. 疑似メソッド付きのアンカーが CSRF 属性を備え共通スクリプトで DELETE に変換する前提とする。
2. 共通トークン検証後、主キーで対象不明なときはフラッシュを消し直し、既に削除された旨を警告フラッシュのみのうち一覧へ。
3. 対象があるときはログを開始し削除リポジトリを試みる。成功時 sibling の `sort_no` を削除対象より大きいものから 1 減ずる更新を先にクエリ実行し、その後論理削除に相当する `remove`。成功フラッシュおよびキャッシュ無効。
4. 例外時は名前を埋め込んだ共通外部キーエラー文言がエラー枠フラッシュとなる。
5. リダイレクト先は削除対象がルートだったか否かにより一覧ルートまたは親の `show` とする。

### CSV 出力（`GET admin_product_category_export`）

1. 実行時間無制限化し、Doctrine の SQL Logger を構成から外す運用にある。
2. CSV タイプがカテゴリでソート昇順になったうち、`enabled` 真の項目だけをヘッダ行にする。
3. すべてのカテゴリをソートのみ降順 `sort_no` で列挙し、ID リストで商品カウントのマップを一度に読み込むルートによって `dtb_csv.field_name` が定数値 `target_product_count` のとき列を数値へ差し替え、それ以外は汎用のセル読取で埋めるストリームを返す。
4. Content-Disposition のファイル名に現在日時連結をログするが本文は転送しないまでに留める。

## 並べ替え処理の論理順序（Ajax）

| 順序 | 判定 | 結果 |
|------|------|------|
| 1 | ブラウザの Ajax フラグがあるか | 無ければ HTTP 400。 |
| 2 | CSRF トークンの妥当性 | 無効時は共通ルールによりアクセス拒否。 |
| 3 | 送信キー一覧がカテゴリ id と整合する整数か | foreach で cast 済みセットしフラッシュまで行う設計にある。異常入力の防御はリポジトリの find が null のとき未定義セットに落ちない前提を置く運用にある。 |

## 削除時および保存時の論理順序

| 順序 | 判定 | 結果 |
|------|------|------|
| 1 | DELETE 側 CSRF とメソッド | 不備時は共通ルールの拒否。 |
| 2 | 削除対象 id の実在 | 無ければ警告フラッシュのうち一覧のみ。 |
| 3 | 保存時に階層が設定上限以内か | `eccube_category_nest_level < hierarchy` なら HTTP 400（`BadRequestHttpException`）。 |
| 4 | DELETE の DB | `sort_no` 繰り下げクエリ実行後削除。外部キーエラーはエラーメッセージ。 |

## 業務ルール・計算

一覧の並び順はクエリ側で既に決まっている。クライアントで視覚的に並べ替え確定すると、初期表示だった各データ属性 `data-sort-no` を数値化し昇順並べ替えのうえ末尾から読むことで大きい表示ランク値を並べ順の先頭行へ順に割り当てる。そのため画面上の並びと表示ランクの大小関係を概ね維持する実装にある。

親が存在する状態での新規入力は親の `sort_no - 1` を基準として新規行に `sort_no + 1` を与え、その後既存より大きい `sort_no` を一括増分するクエリにより空きを確保する。ルートでの新規は画面フォーム経路としては提供しない。

親が存在する状態でのチェックおよびテキスト系はSymfonyと設定で以下の表となる。画像はSymfonyの画像制約（最大サイズおよび MIME）とサーバ側での拡張子ホワイトリストで二段がある。

### 入力項目

| 項目名 | 必須／任意 | 最大長 | 初期値 | 保存先・扱い |
|--------|------------|--------|--------|----------------|
| カテゴリ名（日） | 必須 | `eccube_stext_len`（確認値として 255 文字、`Length` と一致） | 新規は空または編集は DB 現在値の表示名相当 | `dtb_category.category_name`。未入力および超過時はSymfonyエラーとなり一覧は送信失敗状態で再度描く。フォームタイプ本体の名前空間接頭辞は管理者向け規約に統一されている。 |
| カテゴリ名（英） | 任意 | `eccube_stext_len` と同様 | 新規なら空または現行値 | `dtb_category.category_name_en`。桁超過のみ Symfony Length。 |
| フロント非表フラグ | 任意（チェック） | boolean | チェック状態は現在 DB の真偽 | `dtb_category.front_search_hide_flg`。 |
| 支店非表示フラグ | 任意（チェック） | boolean | 同上 | `dtb_category.branch_hide_flg`。 |
| 最新セット用バナー画像 | 任意 | 画像ファイル（Symfonyは最大サイズ確認値として 10M、MIME が jpeg/png/gif。またサーバー側でも `image/` 接頭および拡張子 gif/jpeg/jpg/png） | アップロード無しまたはプレビュー生成後 | `banner_image`、`banner_image_file` はアップロード用にマップされ無いときは処理スキップ。保存先ファイルは `eccube_save_image_dir` に `category` サブディレクトリ。相対キーへ `category/日時別名`。編集および一覧のみではテンプレート上アップロード不可。Hidden の `banner_image` は並列に存在することをフォーム許可フラグにより制御。 |

### エッジケース

| ケース | 扱い |
|--------|------|
| 無効な `parent_id` | 404 とし HTML エラー。 |
| ルートのみの画面 | 画面上部入力カードおよび画像ドロップゾーン関連スクリプトは表示されず、リストとツリーと CSV だけ。ルートへの新規登録経路としての POST はルート用意されないため拒否となる。 |
| 子または商品との紐づけがあるときの削除 | モーダル起点の削除ボタンは `disabled` クラス付与で視覚的に押せなくするが、コンソール等から送信したときは Doctrine の外部キーエラーに相当する例外によりエラーメッセージのフラッシュとともに親一覧へ。 |
| 一覧は空 | 並べ替えスクリプトは要素ゼロに対しても並べ換えコンテナのみ初期化し、並べ換え処理はユーザー操作が無いうちは送信されない。 |
| Ajax 並べ替え成功後応答のみ | `.always()` は Backdrop削除のみであり、画面上の並びはすで確定状態で送信している前提となる。サーバー異常応答でも UI が元並びへ戻るロジックは無いことを実装読みにより確認する運用にある。 |

本機能における業務上の複利計算などはしない。

| 観点 | 内容 |
|------|------|
| 一覧結果とクエリキャッシュ | リポジトリの `getList` はDoctrine のクエリおよび結果キャッシュ秒数により保持時間が決まり、並べ替えや保存削除のたびに一覧を返す側でDoctrineキャッシュ破棄を呼ぶ。そのため通常操作連鎖において画面上の再読込結果とキャッシュのみ参照の結果が短期的にずれ続ける設計にならない。 |
| メインリストとツリー | メインリストは現在親に対応するフラット一覧、サイドツーは複数JOINで読み込む深さ依存の並び順のため、両者の兄弟順序説明では必ずクエリ順序をソースで照合するとよいが、同一親内の並び順は共通で `sort_no` 降順とする。 |

---

## API/バッチ結果

本機能ではブラウザ外の公開 API とバッチ起動本体を扱わない（CSVストリームはあくまで管理画面ユーザー操作に紐づく同期レスポンスである）。

## 入出力

| 種類 | 内容 |
|------|------|
| 入力 | GET で親 id または編集 id。POST で Symfony によるフォーム名空間および CSRF と画像バイナリ。Ajax POST で並べ順に対応する id と sort_no の平面マップおよびヘッダ CSRF。 |
| 成功時出力 | HTML 一覧画面、削除や保存後 HTTP 302 リダイレクトおよび成功フラッシュ。Ajax は本文 `Successful`。CSV は Attachment 名前付きファイル。 |
| 失敗時出力 | 検証失敗により同一 Twig。Ajax 非対応の並べ替え POST は HTTP 400。CSRF 異常は共通のアクセス拒否。保存時の階層超過は HTTP 400。削除外部キーエラーはフラッシュエラー文言。削除対象なし時はフラッシュのみ。 |
| 副作用 | Doctrine永続およびキャッシュ削除。画像ファイルの生成または失敗時の unlink。クエリ並べかえおよび削除時sort繰り下げ。処理ログ関数呼び出し。 |

## 画面遷移

| 条件 | 遷移先 |
|------|--------|
| 親リンクまたはリスト上の名前リンク | `GET /{admin_route}/product/category/{id}` で階層を一段深める。 |
| パンくずの「すべてのカテゴリ」 | `GET /{admin_route}/product/category` でルート直下へ戻す。 |
| 編集送信成功 | HTTP 302 で親コンテキストの show またはトップ一覧。作成送信成功時は親 show。 |
| 削除成功および失敗両方とも | HTTP 302 で親コンテキストの show またはトップ一覧。検索状態はセッションに依存しない一覧のためクエリ状態を引き継がない。 |
| CSVおよび設定ボタン | 同一ウィンドウで該当GETへ。CSVはダウンロードのみで画面遷移を伴わない。 |

### 遷移時に引き続く状態

| 起点 | 遷移前の処理 | 遷移後の初期状態 |
|------|--------------|------------------|
| 保存成功フラッシュを積む | 成功フラッシュをセットしキャッシュ削除 | GET先は最新DBを読んだ一覧となる。フラッシュのみ残る検索状態は無いのが通常一覧と異なるが本機能固有。 |

## エラー処理

| エラー内容 | 処理 |
|------------|------|
| フォーム入力検証 | 同一 Twig 200 としエラー一覧をSymfonyが描画する。 |
| Ajax非対応の並べ替えPOST | HTTP 400 とする明示分岐がある。 |
| CSRF異常による共通アクセス拒否 | HTTP 状態は Symfony のアクセス拒否相当。 |
| 階層が `eccube_category_nest_level` を超える保存試行 | HTTP 400。画面上はエラーページ体系に依存する運用にある。 |
| 画像アップロードのあらゆる種類の異常・ディレクトリ不可 | 送信フォーム側に共通アップロードエラー文言のエントリをセットし再描画。必要なとき移動済みファイルをunlink。 |

## セッション

本機能の一覧状態はクエリのみで復元でき、リスト用のユーザー別検索条件キーを読み書きしない。フラッシュのみセッションのバッグに依存する。

### セッションへ保存しない情報

並べ替え中の並びのみがクライアントDOMにのみ存在していたあいだの状態は送信完了までサーバー側に自動保存しない。

## Cookie

共通のセッションCookieのみを経由した管理画面状態を利用する詳細は `m01-01_admin_login_login` 側の共通設計および実行時設定を正とし、一覧固有の名前を増やさない。

## 排他制御・トランザクション

一覧の単純並べ替えは単一回の flush における複数行更新のみでロックメタ情報を画面上に載せない。PostgreSQL と新規 ID 自動採番のあいだの整合はリポジトリがテーブルを排しシーケンスを追いつかせてから INSERT までを同一ユニットにまとめる分岐のみ持つ。この画面の編集競合におけるユーザー向け競合検知機能は別途持たない。

## 調査補助（grep）

本書の論理説明とは切り離し、ソース照合には次のようなパスの探索が効くことがあるが、機能の可否は環境プラグイン差し込みも含む全体で確かめること。

```
src/Eccube/Controller/Admin/Product/CategoryController.php
src/Eccube/Resource/template/admin/Product/category.twig
src/Eccube/Repository/CategoryRepository.php
src/Eccube/Form/Type/Admin/CategoryType.php
```

### HTTPルート名とパス（コード探索用・旧入口節より退避）

- `admin_product_category` … `GET` … `/{admin_route}/product/category`（親なし（ルート直下）一覧の表示。上部の入力カードは出さない。）
- `admin_product_category_show` … `GET` … `/{admin_route}/product/category/{parent_id}`（指定親の子一覧を表示し、空のフォームから子カテゴリを新規作成できる。親が存在しない id なら 404。）
- `admin_product_category_edit` … `GET` … `/{admin_route}/product/category/{id}/edit`（指定 id の編集フォームと、同一親を持つ兄弟ノード一覧を表示する。）
- `admin_product_category_create` … `POST` … `/{admin_route}/product/category/{parent_id}`（子カテゴリの新規登録送信。検証や画像処理の後、`GET …/category/{parent_id}` にリダイレクトする。）
- `admin_product_category_update` … `POST` … `/{admin_route}/product/category/{id}/edit`（既存カテゴリ更新送信。妥当なら親の一覧へ、`GET …/product/category` または `GET …/category/{parent_id}` にリダイレクトする。）
- `admin_product_category_delete` … `DELETE` … `/{admin_route}/product/category/{id}/delete`（アンカー経由で CSRF と疑似 DELETE を送り、削除する。）
- `admin_product_category_sort_no_move` … `POST` … `/{admin_route}/product/category/sort_no/move`（一覧で並べ替えた結果に合わせ、兄弟間の表示ランク `sort_no` を一括書き換える Ajax 向けエンドポイント（XMLHTTP 限定）。）
- `admin_product_category_export` … `GET` … `/{admin_route}/product/category/export`（CSV タイプカテゴリで有効な列定義に従い、全カテゴリ行と商品件数オプション列をストリーム出力する。）
