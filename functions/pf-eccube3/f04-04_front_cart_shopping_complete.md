# カート — 決済〜購入完了

## 業務ロジック

### 画面構成

購入完了画面は、見出し「ご注文完了」、御礼メッセージ、注文番号、合計・送料・購入商品の情報で構成する。本画面に入力フォームは無く、本画面専用のモーダルも無い。店頭受取のときは完了表示を店頭向けに切り替える。

### 注文番号の表示

呼び出し番号があるときはTC注文番号（＝呼び出し番号）を、無いときはご注文番号（8桁）を表示する。

### 注文の確定

注文内容を確定して受注データを作成し、以降の完了処理で参照できるよう受注を引き継ぐ。ポイントを使用したうえで購入完了画面へ遷移する。

### 購入完了時の判定順序

| 順序 | 判定 | 結果 |
|------|------|------|
| 1 | 引き継いだ受注があるか | 無ければトップページへ戻す |
| 2 | 受注ステータスが注文受領または入金待ちか | いずれでもなければ購入処理異常のアラートメールを送信し、引き継いだ受注情報を初期化して購入処理エラー画面を表示する |
| 3 | SPLINKS決済で対応する決済記録があるか | SPLINKS支払いだが記録が無ければ受注ステータスを処理中へ戻し、決済記録不整合のエラー画面を表示する |
| 4 | 上記を通過 | 完了処理を行い購入完了画面を表示する |

### 完了処理の内容

判定を通過した受注について、受注番号（8桁）と呼び出し番号を取得し、受注明細ごとに商品の売上分析タグを受注明細へ登録して完了画面用の商品情報を組み立てる。表示ロケールの調整が必要なときは、ロケールを合わせたURLへ遷移する。購入完了の初期化イベントが応答を返したときはその応答を返す。SPLINKS決済のときはこの時点でポイントを使用する。注文完了メールを送信し、在庫数を更新する。消費ポイントがあるときはスマレジポイント連携を別プロセスで実行する。購入完了タグログを送信し、引き継いだ受注情報を初期化して購入処理完了を記録する。

異常時は引き継いだ受注情報を初期化し、更新による再通知を避ける。

### エラー時の扱い

| エラー内容 | 処理 |
|------------|------|
| 引き継いだ受注が無い | トップページへ戻す |
| 受注ステータスが注文受領・入金待ち以外 | アラートメールを送信し、受注情報を初期化して購入処理エラー画面を表示する |
| SPLINKS決済で決済記録なし | 受注を処理中へ戻し、決済記録不整合のエラー画面を表示する |

## 入出力

| 種類 | 内容 |
|------|------|
| 入力 | 引き継いだ受注、注文確定時の注文内容 |
| 成功時出力 | 購入完了画面、注文完了メールの送信、在庫更新、ポイント・タグログ連携 |
| 失敗時出力 | 受注ステータス異常・決済記録不整合のエラー画面、受注を引き継いでいないときはトップページへの遷移 |

### 入出力: 永続化

| 操作 | 契機 |
| --- | --- |
| 追加 | 注文確定時に受注データを作成する |
| 追加 | 完了処理で受注明細へ商品の売上分析タグを登録する |
| 更新 | 完了処理で在庫数を更新する。決済記録不整合のときは受注ステータスを処理中へ戻す |
