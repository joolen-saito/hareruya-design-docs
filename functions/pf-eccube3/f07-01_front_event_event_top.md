# F07-01（イベント大会TOP）

店舗ごとに、選択した月のイベントをカレンダーと日付リストで表示する、フロントのイベント大会TOP画面である。

## 概要

イベント大会TOPは、利用者が店舗と月を選び、その店舗で開催されるマジック：ザ・ギャザリングの大会を、月間カレンダーと日付ごとのリストで一覧する機能である。表示対象は選択中の店舗・選択中の月に開催されるイベントに限定し、店舗の切替・前月翌月の切替・過去大会の開閉・日付へのスクロール移動を提供する。同一日・同一イベントが複数の日程を持つ場合は、1日内に重複表示しないよう束ねたうえで、複数日程イベントは日別画面（F07-01の日別表示）へ、単一の日程は詳細画面（F07-03）へ誘導する。

本書は実装手順ではなく、誰が・いつ・どの条件で・結果どうなるかを読むためのリバース詳細設計とする。確認値はpf-eccube3（EC-CUBE3系）のHareruyaEcプラグインのイベント一覧（TOP）処理・日別イベント処理、テンプレート（`Event/index.twig`・`Event/daily.twig`）、イベント詳細リポジトリの月間取得処理を正とする。本機能のカスタマイズ区分はカスタマイズであり、挙動の参照リポはpf-eccube3、DB関連はec-cube-enterpriseを正とする。

対象はブラウザ経由のフロントに限定する。フロントのルートはロケールを先頭に持つ`/{_locale}`配下にあり、イベントは`/{_locale}/events`配下にまとまる。

本文ではフレームワークのコントローラ型名やメソッド名を主説明としない。本文ではルートbind名の網羅は主説明とせず、「利用者視点の入口」にHTTPメソッドとサイトルートからのパスパターンを書く。コード探索でbind名が必要なときだけ「調査補助」へ書く。

本機能はカスタマイズ区分がカスタマイズである。現行挙動はpf-eccube3のHareruyaEcプラグインを正とし、DBスキーマと移行後の扱いはec-cube-enterpriseを正とする。イベント関連テーブルはec-cube-enterpriseに移行済みであり、現行と移行先で次の差がある。

| 観点 | 現行（pf-eccube3） | 移行先（ec-cube-enterprise） |
|------|----------------------|--------------------------------|
| 店舗での絞り込み | `dtb_event.shop_id`で店舗を絞り込み、店舗マスタ`mtb_shop`を参照する。 | `dtb_event`に`shop_id`列、`mtb_shop`テーブルが無い。`dtb_event`は会場`venue_id`（会場マスタ`mtb_venue`）と店舗テナント文脈`base_info_id`を持つ。店舗単位の絞り込みをどの列で行うかはec-cube-enterprise実装で要確認。 |
| 開催日程テーブル | `dtb_event_detail`（`event_id`・`start_date`・`disp_id`）。 | 同一スキーマ。`dtb_event_detail`に`event_id`・`start_date`・`disp_id`が存在する。 |
| 表示区分・祝日 | 表示区分`disp_id`、祝日`mtb_holiday`。 | 同一スキーマ。表示区分マスタ`mtb_disp`、祝日`mtb_holiday`が存在する。 |
| 論理削除 | `dtb_event`・`dtb_event_detail`とも`deleted_at`を持つ。 | 同一。`deleted_at`を持つ。 |

店舗クッキーの名称・属性は現行実装の確認値として記録し、機能仕様として固定しない。

## 処理フロー

### イベント大会TOP・月間表示（GET `/{_locale}/events`）

1. クエリの`shop`、無ければクッキーの`shop`、いずれも無ければ既定店舗（ID＝1）を表示店舗とする。クエリで店舗が指定され、クッキーと異なる場合はクッキー`shop`を更新する。
2. 表示店舗が存在しなければページが見つからない（HTTP404）として扱う。
3. クエリの`shop`・`date`がいずれも無ければTOP判定を真とし、画面タイトルの出し分けに用いる。
4. クエリの`date`、無ければ当月を表示月（`Ym`）とする。
5. 表示店舗・表示月で月間イベント詳細を取得する。詳細は後述の「集計条件」を参照する。
6. 当月の祝日を取得し、日付セルの装飾に用いる。
7. 当月の日付イテレータを生成し、各日付の表示用イベント配列を初期化する。
8. 取得したイベント詳細を開催日ごとに整理する。同一日・同一イベントが2件目以降に現れたら複数日程として束ね、同一日内では同一イベントを重複表示しない。
9. 月間カレンダーと日付リストを表示する。月初日が当日より前なら過去の大会を持つ、月末日が当日以降なら今後の大会を持つと判定し、過去の大会ブロックの開閉表示に用いる。

### 複数日程イベントを日別表示する（GET `/{_locale}/events/{eventId}/{eventDate}/`）

1. `eventId`が空ならページが見つからない（HTTP404）として扱う。
2. `eventDate`が`Ymd`形式なら当該日を終端日とし、過去日なら過去フラグを立てる。`all`なら当日を起点とする。いずれでもなければHTTP404とする。
3. 当該イベント・当該期間の開催日程を取得する。
4. 該当が1件なら、その詳細画面（F07-03）へリダイレクトする。
5. 該当が0件なら、当該イベントの最新開催日程の詳細画面へリダイレクトする。最新日程も無ければHTTP404とする。
6. 該当が複数件なら、日別画面で開催日程の一覧を表示する。ログイン会員のとき選手情報を渡す。

## 集計条件

| 指標 | 集計の要点 |
|------|------------|
| 月間表示のイベント詳細 | イベント詳細とイベントを内部結合し、イベントの店舗が表示店舗であること、イベントの表示区分が表示であること、イベント詳細の表示区分が表示であること、イベント詳細の開催日が表示月の月初0時から月末23時59分59秒に含まれることで抽出する。開催日昇順・イベント詳細ID昇順で並べる。 |
| 同一日内の束ね | 同一開催日に同一イベントの詳細が2件以上あれば複数日程として束ね、同一日内で同一イベントは1回だけ表示する。 |
| 祝日 | 表示月の祝日を取得し、日付セルの装飾に用いる。 |
| 日別表示の抽出 | 当該イベントIDで、終端日（指定日）まで、過去日でない限り当日以降の開催日程を、開催日昇順で抽出する。表示区分が表示の日程に限る。 |

月間表示の取得はクエリキャッシュ・結果キャッシュを併用し、店舗ごとのキー（`event_index_{店舗ID}`）で一定時間キャッシュする。表示中の数値や一覧が、キャッシュ有効期間内の更新を即時に反映しない場合がある。

## DBカラム

機能に直接関係する列のみ記載する。型や一覧の細部はスキーマを参照する。

テーブル名・列名はec-cube-enterpriseを正とし、現行（pf-eccube3）と異なる場合は括弧で添える。

| テーブル | 列 | メモ |
|---------|-----|------|
| `dtb_event` | `venue_id`／`base_info_id`（現行は`shop_id`） | 表示店舗での絞り込みに用いる。現行は`shop_id`、移行先は`shop_id`を持たず会場`venue_id`・店舗テナント文脈`base_info_id`を持つ。絞り込み列はec-cube-enterprise実装で要確認。 |
| `dtb_event` | `disp_id` | イベントの表示区分。表示のみ対象。 |
| `dtb_event_detail` | `event_id` | イベントとの結合・束ねのキー。 |
| `dtb_event_detail` | `start_date` | 開催日。月間抽出・並び順・複数日程判定に用いる。 |
| `dtb_event_detail` | `disp_id` | イベント詳細の表示区分。表示のみ対象。 |
| `mtb_venue`（現行は`mtb_shop`） | 店舗・会場参照 | 表示店舗の存在確認・名称表示に用いる。移行先に`mtb_shop`が無く会場マスタ`mtb_venue`・店舗基本情報で扱う。ec-cube-enterprise実装で要確認。 |
| `mtb_holiday` | 祝日日付 | 当月祝日の日付セル装飾に用いる。 |

### DB操作

永続化の正は ec-cube-enterprise（テーブル名・操作は ec-cube-enterprise を正典）。当ドメインは承認ワークフローを介さず persist/flush で直接確定する（承認ワークフローは在庫機能固有）。

| 操作種別 | 対象テーブル | 契機・条件 |
|---------|--------------|------------|
| 登録/更新 | dtb_event / dtb_event_detail / mtb_holiday / mtb_shop / mtb_venue | 当機能が行う登録・更新で対象テーブルを直接保存する（不要な削除は含まない）。確定は persist/flush による即時反映。DB=ec-cube-enterprise を正典とする。 |

### ログに出してはいけないもの

- Cookie値（店舗クッキーの値を含む）
- セッションIDの完全値

---

## セッション

本機能はTOP・日別表示のためにセッションを更新しない。表示店舗の保持はセッションではなくクッキー`shop`で行う。

---

## Cookie

### イベント大会TOPのクッキー

| 項目 | 内容 |
|------|------|
| クッキー名 | `shop`（確認値）。表示店舗IDを保持する。 |
| 更新条件 | クエリで店舗が指定され、現在のクッキー値と異なる場合に更新する。クエリ指定が無いときは更新しない。 |
| 既定 | クエリ・クッキーともに無ければ既定店舗（ID＝1）を表示する。 |

クッキーの属性・有効期間の正確な値は実装を確認値とする。

## 排他制御・トランザクション

本画面の月間表示・日別表示は参照のみであり、業務トランザクションを張らない。同時アクセス時のロック要件は持たない。
