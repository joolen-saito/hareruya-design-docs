# 商品管理 — 高額商品価格変更CSV登録

## 概要

管理画面の「商品管理」から「商品CSV管理」にある「高額商品価格変更CSVアップロード」において、アップロードした CSV で商品規格ごとの基準価格（セール状態に応じて販売価格）を更新し、結果をフラッシュで示しつつ完了時のみ取込履歴を書き込む機能である。一覧の見出し訳語キー `admin.product.simple_high_price_csv` の確認値は「高額商品価格変更CSVアップロード」とする。

本書は実装手順ではなく、誰が・いつ・どの条件で・結果どうなるかを読むためのリバース詳細設計とする。確認値は EC-CUBE Enterprise の `src/Eccube` 配下および `app/config` の同梱設定を正とする。

本機能のカスタマイズ区分はカスタマイズである。挙動は現行リポ pf-eccube3 の実装を参照し、DB関連の記述（テーブル名・列名・保存先・副作用のDB更新）は ec-cube-enterprise を正とする。高額商品価格変更CSV登録は ec-cube-enterprise にも同等実装がある。

対象はブラウザ経由の管理画面に限定する。

コントローラのメソッド名は本文の主題としない。本文ではルートbind名やSymfonyのルートnameの網羅は主説明としない。「利用者視点の入口」にHTTPメソッドとサイトルートからのパスパターンを書く。コード探索でbind名が必要なときだけ「調査補助」へ書く。

## リニューアル移行時の扱い

- 基準価格・販売価格の保存先: 現行 pf-eccube3 では規格テーブルおよび規格補助テーブル（dtb_product_sub_class）に価格列が分かれるが、移行先 ec-cube-enterprise では基準価格 dtb_product_class.standard_price と販売価格 dtb_product_class.price02 を規格テーブルに統合している。本書のDBカラム節・保存先の記述は移行先 dtb_product_class を正とする。
- 取込履歴: dtb_csv_import_history は現行と移行先で同一スキーマである。
- 取込種別ID: 高額商品価格変更（簡易）取込は ec-cube-enterprise の取込種別マスタで ID 7（SIMPLE_HIGH_PRICE_IMPORT_CSV_ID）に対応する。

## 処理フロー

### アップロード画面を開く（GET `admin_product_simple_high_price_csv_upload`）

1. 管理画面の認証および共通処理を通過する。
2. 管理者 CSV インポート用フォーム種別の空オブジェクトを作り現在リクエストでバインドする（クエリのみのときは状態はほぼ初期のまま）。
3. アップロード履歴ページング状態をクエリおよびセッションから解決する。セッションキーは `admin.product.simple_high_price_csv.page_count` と `admin.product.simple_high_price_csv.page_no`。既定ページサイズだけ本コントローラから 50 と明示するため、リストに無いクエリまたは初回既定は 50 件方向に寄るが、詳細ルールは `AbstractController#getCsvImportHistoryPaginationParams` の実装式に従う（許容候補は 10〜12000 を含む離散集合）。
4. `mtb_csv_import_type.id` が定数 `SIMPLE_HIGH_PRICE_IMPORT_CSV_ID`（数値で 7）に一致する取込履歴だけを並べ、`PaginatorInterface` で表示する。
5. 共通テンプレートへフォーム、その他前述の情報を渡す。

### CSV 雛形を取得する（GET `admin_product_simple_high_price_csv_template`）

1. 共通のストリーム応答ヘルパーで、`CsvExportService` を挟みヘッダ配列はコントローラ内 `getCsvHeader()` の連想キー並びのみを出力し、応答ヘッダに `attachment; filename=simple_high_price_template.csv` を載せる（MIME は `application/octet-stream`）。

### CSV を取込む（POST `admin_product_simple_high_price_import`）

1. ログイン済み管理者オブジェクトを作業主体として読むが、処理本体はサービス側で完結させるだけで管理者レコードへの直接変更はしない（取込履歴のみ利用者のアイディを参照渡しする）。
2. 送信を管理者 CSV フォーム種別でバインドする。Symfony フォーム検証エラーがある場合、`admin` のエラーフラッシュにそれぞれ積んでリダイレクトだけ行い取込はしない。
3. `import_file` が null であれば `admin.common.csv_invalid_no_data` を `admin` エラーフラッシュに載せてリダイレクトして終える。
4. アップロードファイル全体を読み、二重引用符に囲まれた改行を除いた換算で改行数を数えるコントローラメソッドの戻りが `ADMIN_CSV_IMPORT_MAX_ROWS`（5010）以上なら、翻訳キー `admin.csv.error.upload.maxrecord` でエラーを出してリダイレクトのみ行いインポータは起動しない。
5. アプリログの info に「高額商品価格変更CSV登録開始」を書く。
6. `SimpleHighPriceImportHandler`（リポジトリ注入構成）と汎用 `CsvImporter`（エンティティマネージャ、翻訳、共通設定インポーザ、ログイン管理者）を構成し、アップロードファイルで `import` を呼ぶ。
7. `CsvImportResult` に info メッセージがあれば、コントローラは各文を warning フラッシュに積む（訳済み文字列配列）。
8. 結果にエラー配列がある場合、アプリログ info に「高額商品価格変更CSV登録 異常終了」を書く。各エラーを error フラッシュに積む。エラーが空のときだけ、`admin.register.complete` を成功フラッシュに積む。成功時はさらに「高額商品価格変更CSV登録完了」と処理件数を info ログに書き、`dtb_csv_import_history` に 1 行追加する処理を呼ぶ。種別 ID は `SIMPLE_HIGH_PRICE_IMPORT_CSV_ID`。ファイル名列はブラウザが付けたオリジナル名。
9. 成否問わず最終的には `GET admin_product_simple_high_price_csv_upload` へリダイレクトする。

### インポータ内部の共通順序（確認値）

1. 一時ディレクトリは設定 `eccube_csv_temp_realdir`。拡張子がトランスフォーム済みでも `SplFileObject` で開いたうえ、`CsvImportService` に読み込ませる。拡張子が実質 `tsv` のとき区切り文字はタブ、それ以外は `eccube_csv_import_delimiter`。囲み文字は `eccube_csv_import_enclosure`。
2. 行 1 をヘッダとみなせないか、ヘッダの直後にデータ行が存在しないときはインポータは処理を開始せず、メッセージストアだけ返す。
3. トランザクション開始および行ロック秒数設定（既定 5 秒）。
4. 各行について `onValidateRow` と `onReadRow` がハンドラに委ねられる。
5. トランザクション成否はインポータ内の式 `(messageStore のエラー件数が 0) または (breakAll が一度も無い)` に従ってコミットが選ばれる。そのため、ユーザー向けエラー文字列が複数行ぶん積まれても `breakAll` が無ければコミットされうる。この交差状態は結果オブジェクトの `hasError` と完了フラッシュおよび履歴 INSERT の有無で利用者側にも現れる（「データ整合性」節を参照）。
6. ループインデックスが 100 で割れる位置で flush と clear が挟まれる既定動作により、Doctrine のユニット内メモリ使用量を抑える。

### 検証フェーズ固有（高額用ハンドラ）

1. Base ハンドラは列スキーマと物理列の一致および各列のバリデータ必須列を評価して、失敗したらその場で `breakAll` する。
2. 追加処理として、このハンドラは商品コードの存在チェックおよび「同一規格コード列で 2 件以上」を拒否して `breakAll` する。拒否すると当該行でトランザクション全体が中止され、既に読み済みでも反映されずロールバック対象となる。

### 行更新フェーズ固有（見付け順と SQL）

CSV の基準価格列はインポータ標準処理で検証済みのうえ、`onReadRow` 内でも数値へ落としている。非数だった場合でもカストで 0 とする式が読み込み後にあるが、検証済み経路でのみ到達することが通常である。

処理の優先は次である。

| 順序 | 論理状態 | アクション |
|------|----------|------------|
| 1 | 「セールフラグが真の高額対象規格」を商品コード単位で存在する場合 | UPDATE は `standard_price` と更新日のみ。`price02` は触らない。同時に info 種のメッセージキーで行番号付き注意をユーザー向けキューへ積む。 |
| 2 | 「セールフラグが偽またはヌルの高額対象規格」を商品コード単位で存在する場合 | `standard_price` と `price02` を同値で上書きし、更新日を記録する。 |
| 3 | 両方とも満たさないとき | メッセージストアへエラー扱いの文字列として日本語説明鍵が積まれ、当該行は DB 側更新はしないが `breakAll` は呼ばずループ継続のままとなる。結果オブジェクト側はそのメッセージをエラー配列にも載せ、`hasError` が真となる。前述のインポータ成功条件にも注意。 |

親商品状態・高額コード・公開状態との SQL 完全一致は規格側リポジトリの文字列クエリにある。

## 業務ルール・計算

本機能における恒久フォーム入力はファイルと CSRF トークンのみであり、画面上の入力列はほぼ存在しない説明のみである。ファイル以外の入力条件は共通フォーム側のチェックボックス項目がウィジェット化されていなく操作できない状態である。

### CSV 列（画面上の項目名および実データ意味）

説明文言はコントローラのヘッダ定義が空による。

| 項目名 | 必須／任意 | 最大長 | 初期値 | 保存先・扱い |
|--------|------------|--------|--------|----------------|
| ファイル（CSV アップロード） | 必須 | Symfony アップロード制約により `eccube_csv_size`（設定では数値 5、単位としてメガバイト制約文言に使われる実装である）による上限がある | 選択なし | 取込パイプラインへ送られ、処理後削除される |
| （CSV の列見出し）商品コード | 必須 | 文字列カラムであり追加の桁数バリデータはハンドラ定義に無く、実質は必須の空でないチェックのみ | 入力ファイルに依存 | 規格のコード列およびリポジトリ SQL の `product_code` 調整済みクエリ側に渡る |
| （CSV の列見出し）基準価格 | 必須 | 符号なし数値チェックおよび整数の桁チェックにより最大 9 桁相当（`NumericMaxLengthValidator(9)`） | 入力ファイルに依存 | 処理先によって `dtb_product_class.standard_price` と、場合により `dtb_product_class.price02` を同値で上書き |

### エッジケース

| ケース | 扱い |
|--------|------|
| 同一 CSV または DB 状態で複数規格コード行が競合すると判定されるとき | `breakAll` とエラーによりトランザクション全体が中止 |
| CSV の商品コードにはマッチがあるが対象となる高額条件を満たさないとき | メッセージストアへのエラー行だけで先へ進む。トランザクションは `breakAll` が無ければインポータ式によりコミットされうる。コントローラはエラー検知ゆえ完了フラッシュと履歴 INSERT を行わない。 |
| セールフラグが真側と偽側の両セットが同コードに並存しうる | 実装順が「セール側を優先」のため、そのコードは基準のみ更新となる |
| 基準価格列が論理的には空であっても通過しない | Symfony 側必須と列バリデータの Required で止まり `breakAll` |
| メッセージストアでの info と error の両立 | UI フラッシュにおいて両方載りうる。履歴および成功フラッシュは結果エラー無しのみ |

## データ整合性

| 観点 | 内容 |
|------|------|
| トランザクション境界 | CSV ひとつの取込はひとつのトランザクション。`breakAll` で打ち切った場合はすべて失われる。打ち切りが無ければユーザー向けエラー文言が複数でもコミットが通るインポータ式になりうる。 |
| Doctrine cache | 定期的な `clear()` により、同一リクエスト内で以前にロード済みであったエンティティと DB 状態の乖離がありうることを利用者側で追うときはクエリログや再読込試験へ委ねる。 |
| UI の成功表示とデータ | `CsvImportResult#hasError` が偽じゃないときは画面上は「登録完了」系の文言を出力しない。また取込履歴も追加しない。 |

## DBカラム

機能が直接変更しうる主な列のみ列挙する。型細部はスキーマおよびエンティティを参照すること。

| テーブル | 列 | メモ |
|---------|-----|------|
| `dtb_product_class` | `standard_price` | UPDATE 両分岐共通 |
| `dtb_product_class` | `price02` | セール外（NULL および偽側）のみ同値代入 |
| `dtb_product_class` | `update_date` | アプリ共通のタイムスタンプ関数でセット |
| `dtb_csv_import_history` | （ファイル名、作成日時、種別、アップロード者 FK） | 成功時のみ 1 行追加 |

インポータ種別の主キー定数値は確認値としてマスタ側 ID 7（`SIMPLE_HIGH_PRICE_IMPORT_CSV_ID`）とする。

### DB操作

永続化の正は ec-cube-enterprise。商品系は承認ワークフローを介さず persist/flush で直接確定する（在庫の承認ワークフローとは別系統。`ProductController`・各CSVサービスで確認）。

| 操作種別 | 対象テーブル | 契機・条件 |
|---------|--------------|------------|
| 登録/更新 | dtb_csv_import_history / dtb_product_class | 当機能が行う登録・更新で対象テーブルを直接保存する（不要な削除は含まない）。確定は persist/flush による即時反映。DB=ec-cube-enterprise を正典とする。 |

## エラー処理

| エラー内容（代表） | 処理 |
|--------------------|------|
| フォーム送信が Symfony 側で妥当で無いとき | admin フラッシュを積んだうえ、アップロード画面へだけ戻り、インポータは開始しない |

## ログ・監査

| タイミング | 記録内容 |
|------------|-----------|
| 取込処理が始まろうとした直後 | 「高額商品価格変更CSV登録開始」という info メッセージ |
| `CsvImporter` がエラー状態で戻ってきた | 「高額商品価格変更CSV登録 異常終了」という info メッセージ |
| `hasError` が偽であった | 「高額商品価格変更CSV登録完了」と件数付きログ |
| アプリ共通のクエリログ等 | アプリ側設定により変動し本書対象外 |

### ログに出してはいけないもの

- ログイン資格情報
- アップロード済みファイルの丸ごとの内容ログ（開発例外時のダンプ運用などは開発ルール側で管理）

一般的な一覧に加え、ユーザーがアップロードした売価の原文が監査ログに残る構成かどうかはロガーラッパ側に依存するので本ファイルでは断言しない。

## Cookie

標準 Symfony セッションクッキー側の共通振る舞いのみで、本機能専用の追加 Cookie は無い説明のみとする。

---

## 排他制御・トランザクション

- 開始からコミット／ロールバックまでひとつのトランザクションにまとめる汎用実装であり、Doctrine の楽観ロック版管理は明示しない。
- 行ロックタイムアウトを秒既定でセットするのみで、SKU 粒度のロックは DB の UPDATE とトランザクション隔離により委ねられる。

---

## 調査補助（grep）

設計読者がコード検索するときは、Symfony ではルート名前 `admin_product_simple_high_price_*`、`SimpleHighPriceImportHandler`、`ProductSimpleHighPriceCsvController`、および規格側に `existsProductClassByProductCodeAndSaleFlg` と `replaceStandardPriceOnly` と `replaceStandardPriceAndPrice02` と `existsByProductCode` と `isProductCodeUnique` の文字の存在を確認すると本文と対応関係が取りやすい。

### HTTPルート名とパス（コード探索用・旧入口節より退避）

- `admin_product_simple_high_price_csv_upload` … `GET` … `/{admin_route}/product/simple_high_price/csv_upload`（アップロードフォーム、フォーマット説明（コントローラが渡すヘッダ定義のみ）、取込 POST 先、雛形リンク、CSV 取込履歴ページネーションを表示する。）
- `admin_product_simple_high_price_import` … `POST` … `/{admin_route}/product/simple_high_price/import`（送信ファイルを検証したうえで取込を実行する。処理後は常に `GET admin_product_simple_high_price_csv_upload` へ HTTP リダイレクトする。）
- `admin_product_simple_high_price_csv_template` … `GET` … `/{admin_route}/product/simple_high_price/csv_template`（CSV ヘッダ行のみの雛形を添付応答として返す。フォームとは別リンクで到達する。）
