# M12-01（日別/月別集計 集計一覧表示）

## 概要

分析・集計メニューの日別集計・月別集計は、管理者が指定した集計タイプ（日次/月次）・集計日範囲・表示項目に従い、注文・明細・会員・来客の各指標を期間単位で集計し、一覧表で提示する機能である。

本書は実装手順ではなく、誰が・いつ・どの条件で・結果どうなるかを読むためのリバース詳細設計とする。本機能のカスタマイズ区分はカスタマイズであり、現行挙動の確認値はpf-eccube3（EC-CUBE3系）のHareruyaEcプラグインの分析・集計（日次/月次集計）処理、集計用リポジトリ、検索フォーム種別、一覧テンプレートを正とする。DB関連の記述は ec-cube-enterprise の実装を正とする。

対象はブラウザ経由の管理画面に限定する。本文ではフレームワークのコントローラ型名やメソッド名を主説明としない。管理画面プレフィックスは環境により変わる（`admin_route`）。「利用者視点の入口」にHTTPメソッドとサイトルートからのパスパターンを書く。

CSVダウンロードはM12-02で扱う。本書は集計一覧の表示までを扱う。

---

## 本書で扱うこと

- 日次集計・月次集計の初期表示時に設定される検索条件の既定値
- 検索条件（集計タイプ・集計日・利用端末・表示項目）の指定による集計結果一覧の表示
- 集計の対象データ・結合・除外条件・集計単位・期間の取り扱い
- 一覧に表示する列と合計行の算出

---

## 本書で扱わないこと

以下は本書では仕様確定せず、実装または別機能の設計を正とする。

- 集計結果のCSVダウンロード（M12-02を正とする）
- 受注/売上分析、入荷通知依頼、フォーマット売上分析の各集計（M12-03〜M12-08を正とする）
- 管理画面へのアクセス制御・ログイン・権限設定の詳細（認証は別設計を正とする）
- 受注・会員・商品の各台帳の更新業務（各機能を正とする）

## リニューアル移行時の扱い

- 本機能のカスタマイズ区分はカスタマイズであり、現行（pf-eccube3／HareruyaEc プラグイン）の集計挙動を正としつつ、DB関連の記述は ec-cube-enterprise を正とする。
- 受注の集計対象列のうち、現行は注文明細を `dtb_order_detail`、受注ステータスを `dtb_order.status` で参照する。ec-cube-enterprise では注文明細テーブルが `dtb_order_item`、受注ステータスが `dtb_order.order_status_id`（受注ステータスマスタへの外部キー）に相当する。本書のDBカラム節は移行先名を主とし、現行名を括弧で添える。
- 会員の集計対象テーブル `dtb_player`（登録日 `create_date`、メールマガジン配信フラグ `mail_magazine_flg`）は現行・移行先（ec-cube-enterprise）で同一スキーマであり、移行先でもそのまま参照する。
- 注文日 `order_date`・顧客 `customer_id`・利用端末 `device_type_id`、明細の `price`・`quantity`・`product_code`・`product_name` は現行・移行先で同名であり、テーブル名のみ上記の差がある。
- 本集計機能（HareruyaEc の日次/月次集計）自体は現行プラグインのカスタマイズであり、ec-cube-enterprise 側の集計画面・集計ロジックの有無と差は移行設計で確認する。

## 利用者視点の入口

| 入口 | URLエンドポイント | 期待されるふるまい |
|------|--------------------|--------------------|
| サイドメニュー「日別集計」 | `GET/POST /{admin_route}/analysis/summary/daily` | 集計タイプ日次、集計日を当月初日〜当月末日とした検索画面を表示する。 |

## フロント挙動

| 観点 | 内容 |
|------|------|
| 表示要素 | 検索条件のアコーディオン、検索ボタン、集計結果テーブル。集計結果がある場合は日付列に続けて選択した表示項目の列を並べ、最終行に合計行を表示する。購買率の列は値に`%`を付けて表示する。 |
| 入力項目 | 商品名（日/英）・商品コードのテキスト欄、集計タイプのラジオ、集計日From・To、利用端末のチェックボックス、表示項目（注文）のチェックボックス、表示項目（明細）のチェックボックス。表示項目には「全て選択」のチェックボックスを併設する。 |
| JS挙動 | 日付入力にデートタイムピッカーを適用する。表示項目の「全て選択」チェックで配下のチェックボックスを一括切替する。集計値の非同期取得は行わない。 |
| モーダル・ポップアップ | 本機能専用のモーダルは無い。 |

## 処理フロー

### 検索画面初期表示（`/{admin_route}/analysis/summary/daily` または `/monthly`）

1. 管理画面の認証・権限を通過する。
2. 検索条件セッションを破棄する。
3. 集計日Fromに当月初日、集計日Toに当月末日を設定する。
4. URLに`daily`を含む場合は集計タイプを日次にする。含まない場合は集計タイプを月次にし、集計日Fromを2か月前へ繰り上げる。
5. 検索フォームを表示する。集計結果は空とする。

### 集計実行・一覧表示（`/{admin_route}/analysis/summary/result`）

1. 検索フォームへ送信値を取り込む。
2. 検索条件を検索条件セッションへ保存する。
3. 選択した表示項目から、画面に出す列の見出しを組み立てる。
4. 集計用リポジトリへ検索条件と表示項目を渡し、期間単位の集計結果と合計を取得する。
5. 集計結果一覧と合計行を同一画面に表示する。

## 集計条件

| 指標 | 集計の要点 |
|------|------------|
| 集計単位 | 集計タイプが日次なら注文日を`%Y/%m/%d`、月次なら`%Y/%m`でグループ化する。会員数の集計は会員の登録日（`create_date`）を同じ単位でグループ化する。 |
| 期間 | 集計日Fromから集計日Toまで。来客数の基準となる注文の抽出では、集計日Toに23時間59分59秒を加えて当日終端まで含める。 |
| 来客数・購買数・購買率 | 注文を集計日範囲で抽出し、期間単位の注文件数（購買数）を数える。来客数は期間・会員単位でまとめた注文者数を数える。購買率は来客数を購買数で割り100倍して小数点以下を切り捨てる。 |
| 注文・注文確認・入金・出荷指示・出荷・キャンセル | 注文と注文明細を結合し、期間単位で件数・金額・平均単価を算出する。注文は全件、その他の指標は対象の注文ステータスに該当する明細のみを件数・金額に算入する。 |
| 商品別（明細） | 注文と注文明細を結合し、商品名・商品コードの絞り込みを加えたうえで、明細の件数・金額・平均単価を期間単位で算出する。 |
| 会員数・メールニュース登録数 | 会員（`dtb_player`）を登録日の期間単位でグループ化し、登録数とメールマガジン登録フラグが立つ件数を数える。 |
| リピート注文数 | 注文回数が2回以上の会員の注文を、期間単位で件数として数える。 |
| 利用端末 | 利用端末が指定された場合、来客数・注文・商品別・リピート・来客者数の各副問い合わせに端末IDの絞り込みを加える。 |

平均単価は金額合計を数量合計で割った値とし、表示時に切り上げる。期間内で集計結果が無い日付・月は、件数等を0で補完して一覧に並べる。

---

## 業務ルール・計算

| 項目 | 内容 |
|------|------|
| 件数・金額の算入条件 | 注文確認は受注ステータスが新規受付・入金待ち・保留、入金は決済処理中、出荷指示は出荷準備・ピッキング、出荷は出荷済み・対応済み、キャンセルはキャンセルの各ステータスに属する明細のみを算入する。 |
| 平均単価 | 金額合計を数量合計で割る。表示時は切り上げる。 |
| 購買率 | 来客数を購買数で割り100倍し、小数点以下を切り捨てる。購買数が0の場合は0とする。 |
| 合計行 | 一覧の各列について期間分を合算する。購買率の合計は来客数合計を購買数合計で割り100倍して切り上げる。日付列・購買率列は単純合算の対象外とする。 |
| 期間の補完 | 集計結果に存在しない日付・月は、表示項目の各列を0として一覧へ補完する。 |
| 商品名・商品コードの絞り込み | 入力語を空白・カンマで分割し、商品コードまたは商品名の部分一致のいずれかに合致する明細を商品別の集計対象とする。 |

### 入力項目

| 項目名 | 必須／任意 | 最大長 | 初期値 | 保存先・扱い |
|--------|------------|--------|--------|----------------|
| 商品名（日/英）・商品コード | 任意 | 短文相当（`stext_len`） | 空 | フォームキー `multi`。商品別集計の商品コード・商品名の部分一致条件に使う。検索条件セッションへ保存。 |
| 集計タイプ | 必須 | — | 入口が`daily`なら日次、それ以外は月次 | フォームキー `summary_type`。値は`daily`/`monthly`。集計単位を決める。 |
| 集計日From | 必須 | 日付 | 日次は当月初日、月次は2か月前の初日 | フォームキー `summary_date_from`。集計対象の注文日下限。 |
| 集計日To | 必須 | 日付 | 当月末日 | フォームキー `summary_date_to`。集計対象の注文日上限。集計時に当日終端まで加算する。 |
| 利用端末 | 任意 | — | 未選択 | フォームキー `device_type`。端末マスタの複数選択。各副問い合わせの端末ID絞り込み。 |
| 表示項目（注文） | 任意 | — | 未選択 | フォームキー `columns_order`。来客数・注文・リピート注文数・会員数・注文確認・入金・出荷指示・出荷・キャンセルから複数選択。 |
| 表示項目（明細） | 任意 | — | 未選択 | フォームキー `columns_product`。商品別の注文・注文確認・入金・出荷指示・出荷・キャンセルから複数選択。 |

本フォームはなりすまし対策トークンを使わない（`csrf_protection`を無効化）。最大長の根拠は`constant.yml.dist`等の確認値とし環境上書きを注記する。

### エッジケース

| ケース | 扱い |
|--------|------|
| 集計対象が0件 | 集計結果が無い日付・月の列を0で補完する。 |
| 購買数が0の日付・月 | 購買率を0とする。 |
| 当日の会員登録が無い | 会員数・メールニュース登録数をNULLから0へ補正する。 |
| 表示項目を未選択 | 日付列のみの一覧となる。 |
| 平均単価の数量合計が0 | 算出式が成立しない明細は集計対象の件数・金額に算入しないため、平均単価は対象明細に依存する。 |

## データ整合性

| 観点 | 内容 |
|------|------|
| 参照時点 | 集計結果は検索実行時にデータベースから読み取った値である。表示後に受注・会員が更新されても表示中の数値は自動更新しない。 |
| CSVとの整合性 | 集計実行で検索条件をセッションへ保存する。CSVダウンロードは同じセッションの検索条件で再集計するため、直近の検索条件と同条件の集計となる。 |
| 一覧と合計の整合性 | 合計行は表示中の集計結果を合算した値であり、別問い合わせの再集計ではない。 |
| 更新との整合性 | 本機能は参照のみで台帳を更新しない。 |

## DBカラム

機能に直接関係する列のみ記載する。テーブル名・列名は ec-cube-enterprise を正とし、現行 pf-eccube3 と異なる場合は現行名を括弧で添える。型や一覧の細部はスキーマを参照する。

| テーブル | 列 | メモ |
|---------|-----|------|
| dtb_order | order_date | 集計単位・期間抽出の基準。 |
| dtb_order | order_status_id（現行 status） | 指標ごとの受注ステータス絞り込み。受注ステータスマスタへの外部キー。 |
| dtb_order | customer_id | 来客数・リピート注文数の集計に使用。 |
| dtb_order | device_type_id | 利用端末の絞り込み。 |
| dtb_order_item（現行 dtb_order_detail） | price, quantity | 金額・平均単価の算出。 |
| dtb_order_item（現行 dtb_order_detail） | product_code, product_name | 商品別集計の絞り込み。 |
| dtb_player | create_date | 会員数の集計単位。現行・移行先で同一スキーマ。 |
| dtb_player | mail_magazine_flg | メールニュース登録数の集計。現行・移行先で同一スキーマ。 |

### DB操作

本機能は参照系（検索）であり、DBへの登録・更新・削除は行わない。テーブル名は ec-cube-enterprise を正典とする。

| 操作種別 | 対象テーブル | 契機・条件 |
|---------|--------------|------------|
| 検索 | dtb_order / dtb_order_detail / dtb_order_item / dtb_player | 検索条件に合致するレコードを抽出する。 |
