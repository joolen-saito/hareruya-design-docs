# F06-11（買取一覧）

## 概要

ログイン済み会員が、自分が行った買取依頼の履歴を一覧で閲覧する機能である。マイページ系の「買取履歴」から入り、会員に紐づく買取注文を依頼の新しい順にページングして表示する。各行に買取依頼日、オーダーID、買取依頼内容の要約（えらんで買取・まとめて買取の代表商品とほか件数）、申込時買取金額合計、処理状態（状態画像）を並べ、オーダーIDと状態画像から買取履歴詳細へ遷移する。

Excel基本設計上の機能名は「買取一覧」とする。現行画面の見出し・実装上の呼称である「買取履歴一覧」は、実装確認値として本文中に残す。

本書は実装手順ではなく、誰が・いつ・どの条件で・結果どうなるかを読むためのリバース詳細設計とする。確認値はpf-eccube3（EC-CUBE3系）のHareruyaEcプラグインの買取履歴一覧処理、テンプレート（`Mypage/purchase_history.twig`）、買取注文リポジトリの取得処理を正とする。

本機能のカスタマイズ区分はカスタマイズである。画面・処理の挙動はpf-eccube3を参照し、DB関連（テーブル名・列名・制約・関連）はec-cube-enterpriseを正とする。

対象はブラウザ経由のフロント（会員マイページ）に限定する。フロントのルートは`/{_locale}`配下にマウントされ、URLは`/{_locale}/mypage/purchase_history`の形をとる。

本文ではフレームワークのコントローラ型名やメソッド名を主説明としない。本文ではルートbind名の網羅は主説明とせず、「利用者視点の入口」にHTTPメソッドとサイトルートからのパスパターンを書く。コード探索でbind名が必要なときだけ「調査補助」へ書く。

- 申込時買取金額合計・処理状態の表示

## リニューアル移行時の扱い

DB関連はec-cube-enterpriseを正とする。現行（pf-eccube3）と移行先（ec-cube-enterprise）のスキーマ差を次のとおり記録する。

| 観点 | 現行（pf-eccube3） | 移行先（ec-cube-enterprise） |
|------|---------------------|------------------------------|
| 買取注文の主キー | `dtb_buy_order.buy_order_id` | `dtb_buy_order.id`（主キー列名が変わる）。会員参照は `customer_id`、状態参照は `buy_order_status_id`。 |
| 買取代表カード | `dtb_buy_main_card`（列 `count`・`sale_flg`・`purchase_category`・`price`・`product_id`・`language_id`） | 同一スキーマ（同テーブル・同列構成。主キーは `id`、注文参照は `buy_order_id`）。 |
| 個別入力商品 | `dtb_buy_order_indivisual_input_product`（列 `quantity`・`sale_flg`・`name`・`price`） | 同一スキーマ（同テーブル・同列構成。主キーは `id`、注文参照は `buy_order_id`）。 |
| 処理状態の参照先 | `dtb_buy_order.buy_order_status_id` | 同じく `buy_order_status_id`。状態マスタを参照する。 |

買取注文の主キー列名以外は現行・移行先で同一構成である。

## 利用者視点の入口

| 入口 | URLエンドポイント | 期待されるふるまい |
|------|--------------------|--------------------|
| マイページの「買取履歴」ブロック | `GET /{_locale}/mypage/purchase_history` | 日本語版のマイページに表示し、押下すると会員自身の買取注文を新しい順に1ページ目を表示する。英語版のマイページではこの入口を表示しない。 |
| ページ送りリンク（最初・数字・最後） | `GET /{_locale}/mypage/purchase_history?page=（番号）` | 指定ページの買取履歴を表示する。 |
| 表示件数の選択 | `GET /{_locale}/mypage/purchase_history?pageSize=（10/20/50/100）` | 1ページあたりの表示件数を切り替えて表示する。 |
| オーダーID・処理状態画像 | `GET /{_locale}/mypage/purchase_history/detail/{id}` | 当該買取注文の買取履歴詳細へ遷移する。 |
| 「マイページ」ボタン | `GET /{_locale}/mypage` | マイページトップへ戻る。 |

フロントのページであり管理画面プレフィックスは付かない。`/{_locale}/mypage`配下は会員ログインを要する。一覧は検索フォーム（メソッドGET）内に置かれ、`page`・`pageSize`をクエリで受け取る。

## フロント挙動

| 観点 | 内容 |
|------|------|
| 表示要素 | 見出し「買取履歴一覧」、会員氏名と「様」、表示件数セレクト、件数範囲・総件数、ページ送り、一覧（買取依頼日・オーダーID・買取依頼内容・申込時買取金額合計・処理状態）、「マイページ」ボタン。 |
| JS挙動 | 履歴用スクリプトを読み込み、表示件数セレクトの変更をページサイズの隠し項目へ反映してGET送信する。 |
| CSS・レイアウト | 処理状態は状態識別子に対応する画像で示す。オーダーIDは7桁ゼロ詰めで表示する。 |
| モーダル・ポップアップ | 本画面専用のモーダルは無い。 |

買取依頼内容は、えらんで買取・まとめて買取の順に、売却対象かつ数量のある代表商品を1件だけ表示し、同区分の残り件数を「ほか○件」として示す。商品の言語・状態（買取用コード）があれば角括弧で併記する。

---

## 処理フロー

### 買取履歴一覧を表示する（GET `/{_locale}/mypage/purchase_history`）

1. 会員ログインを要求し、ログイン会員を特定する。
2. GETクエリ一式を受け取り、ページ番号・1ページ件数を決定する（既定はページ1・10件）。
3. 論理削除フィルタについて、商品・商品規格を対象外に設定し、削除済みの商品・規格も一覧に表示できるようにする。
4. 当該会員の買取注文を依頼の新しい順で取得し、ページングする。
5. 取得した買取注文・会員・クエリをテンプレートへ渡して表示する。

## 集計条件

| 指標 | 集計の要点 |
|------|------------|
| 買取履歴一覧 | ログイン会員の買取注文を対象とする。買取代表カードと処理状態を結合する。並びは買取注文識別子の降順、同一注文内の代表カードは申込価格の降順。 |
| ページング | `page`・`pageSize`で分割する。`pageSize`の選択肢は10・20・50・100。 |
| 買取依頼内容の要約 | えらんで買取・まとめて買取の区分ごとに、売却対象（売却フラグが偽でない）かつ数量のある代表商品を1件抽出し、残りを「ほか○件」とする。 |
| 申込時買取金額合計 | 買取注文の申込時買取金額合計を表示する。 |
| 削除済み商品の表示 | 商品・商品規格の論理削除フィルタを一時的に外し、削除済みでも一覧に表示する。 |

## 業務ルール・計算

| 項目 | 内容 |
|------|------|
| 一覧の対象 | 常にログイン会員自身の買取注文のみを対象とする。 |
| 並び順 | 買取注文識別子の降順（新しい依頼が上）。 |
| 買取依頼内容 | えらんで買取・まとめて買取の各区分で代表商品を1件表示し、残りを「ほか○件」とする。売却対象でない、または数量0の商品は対象から除く。 |
| オーダーID表示 | 買取注文識別子を7桁ゼロ詰めで表示する。 |
| 処理状態 | 処理状態識別子に対応する状態画像を表示する。 |
| 削除済み商品 | 商品・規格が論理削除済みでも一覧に表示する。 |

本機能では一覧表示に伴う入力フォームを持たないため、`### 入力項目`の表は持たない。ページ・表示件数はGETクエリで受け取る。

### エッジケース

| ケース | 扱い |
|--------|------|
| 買取履歴0件 | 件数を0件として一覧領域を空で表示し、件数範囲を0～として表示する。 |
| 区分に対象商品が無い | その区分の代表商品行を表示しない。 |
| 商品が論理削除済み | 論理削除フィルタを外して名称等を表示する。 |

## DBカラム

機能に直接関係する列のみ記載する。型や一覧の細部はスキーマを参照する。テーブル名・列名はec-cube-enterpriseの実装を正とする。

| テーブル | 列 | メモ |
|---------|-----|------|
| 買取注文（`dtb_buy_order`） | `customer_id` | 一覧の抽出キー。会員（顧客）を参照する。 |
| 買取注文（`dtb_buy_order`） | `id` | 並び順・オーダーID表示・詳細遷移キー。現行（pf-eccube3）の列名は `buy_order_id`。 |

| 操作種別 | 対象テーブル | 契機・条件 |
