# バッチ 商品管理 — 期間別入庫数集計

## 概要

在庫履歴から入庫数を期間別（前日・直近3日・週・2週・3週・月・90日・180日・365日）に集計し、商品規格サブの入庫数列へ反映するバッチである。コマンドライン（コンソールコマンド）から実行する。入庫数は在庫履歴のうち在庫変動区分が入庫・マスタ更新のもので、在庫が増加した分を対象に集計する。

本書は実装手順ではなく、誰が・いつ・どの条件で・結果どうなるかを読むためのリバース詳細設計とする。確認値はpf-eccube3（EC-CUBE3系）のHareruyaEcプラグインの商品バッチ（入庫数集計処理）、在庫履歴・商品規格サブを扱うリポジトリを正とする。本機能のカスタマイズ区分はカスタマイズであり、現行挙動はpf-eccube3を参照し、DB関連の記述はec-cube-enterpriseを正とする。

対象はコンソールコマンドであり、ブラウザ経由の画面を持たない。

本文ではフレームワークのコマンド型名やサービス型名を主説明としない。実行はコンソールのバッチコマンドで行う。

- バッチの起動スケジュール（運用・ジョブ設定を正とする）

## リニューアル移行時の扱い

挙動は現行（pf-eccube3）を踏襲し、DB関連の記述は移行先（ec-cube-enterprise）を正とする。在庫履歴・入庫数の保持構造が次のとおり異なる。

| 観点 | 現行（pf-eccube3） | 移行先（ec-cube-enterprise） |
|------|--------------------|------------------------------|
| 在庫履歴の商品規格参照 | `dtb_stock_history.product_class_id`（商品規格を直接保持） | `dtb_stock_history.product_stock_id` 経由で在庫 `dtb_product_stock.product_class_id` を参照（商品規格IDを直接持たない） |
| 在庫変動区分 | `dtb_stock_history.stock_change_type_id` | `dtb_stock_history.stock_change_type_detail_id` と履歴登録元 `history_source_type` に分かれる |
| 入庫数の反映先 | 商品規格サブ `dtb_product_sub_class` の入庫数列 | 専用表 `dtb_stock_up_quantity` の `stock_up_quantity_01`〜`stock_up_quantity_10`（列名は同じだが補助表が分離） |

在庫増加分（旧在庫を上回る差分）を入庫とみなす集計ロジックは現行を踏襲する。移行先の在庫変動区分による対象判定の対応はec-cube-enterprise実装で要確認とする。

## 用語

| 用語 | 説明 |
|------|------|
| 入庫数 | 在庫履歴で在庫が増加した分を期間別に合計した値。 |
| 在庫変動区分 | 在庫履歴の変動理由の区分。入庫・マスタ更新などがある。 |
| 商品規格サブ | 商品規格ごとの集計値（販売数・入庫数など）を保持する拡張テーブル。 |

## 利用者視点の入口

| 入口 | 実行方法 | 期待されるふるまい |
|------|----------|--------------------|
| コンソールのバッチコマンド | `product:batch updateProductSummaryForStockUp` | 在庫履歴から期間別の入庫数を集計し、商品規格サブの入庫数列を更新する。 |

本機能はHTTPで届く画面を持たない。コマンド名が一致しない場合は処理を行わずに終了する。

---

## 処理フロー

### 期間別入庫数集計を実行する（`product:batch updateProductSummaryForStockUp`）

1. 実行時間制限を解除し、SQLロガーを無効化する。
2. 在庫履歴を商品規格単位で集計し、期間別入庫数（前日・3日・週・2週・3週・月・90日・180日・365日）の一覧を取得する。
3. 対象が無い場合は更新を行わずに終了する。
4. 集計結果の行ごとに、商品規格サブの入庫数列を更新する。
5. 100件ごとに変更を反映しキャッシュをクリアしながら処理する。
6. 残りの変更を反映して終了する。

## 業務ルール・計算

| 項目 | 内容 |
|------|------|
| 集計単位 | 商品規格単位（商品規格ID）。 |
| 集計値 | 在庫履歴で在庫が増加分（在庫が旧在庫を上回る分）の合計。 |
| 対象区分 | 在庫変動区分が入庫・マスタ更新の在庫履歴。 |
| 反映先 | 商品規格サブの入庫数列（前日・3日・週・月・90日・180日・365日・2週・3週）。当日相当の列は0で初期化する。 |

---

## 集計条件

| 指標 | 集計の要点 |
|------|------------|
| 対象データ | 作成日が当日から366日前以降で、在庫変動区分が入庫・マスタ更新の在庫履歴。 |
| 集計値 | 在庫が旧在庫を上回る場合にその差分を入庫数として加算する。 |
| 集計期間 | 当日基準で前日・直近3日・7日・14日・21日・28日・90日・180日・365日の各区間。 |
| 一意化 | 商品規格IDでグループ化する。 |

## API・バッチ結果

| 種類 | 内容 |
|------|------|
| 入力 | コマンド名。引数は取らない。 |
| 実行条件 | 集計対象期間内に入庫・マスタ更新の在庫履歴が存在すること。 |
| 成功結果 | 商品規格サブの入庫数列が最新の集計値で更新される。 |
| 失敗結果 | 途中失敗時は反映済みの行のみ更新が残る。 |
| 再実行時 | 実行時点のデータで再集計し、対象商品規格の入庫数列を上書きする。重複加算は起きない。 |

---

## 入出力

| 種類 | 内容 |
|------|------|
| 入力 | コマンド名。 |
| 成功時出力 | 商品規格サブの入庫数列の更新。 |
| 失敗時出力 | エラーメッセージのコンソール出力。途中で止まった場合は反映済みの行のみ更新が残る。 |
| 副作用 | 商品規格サブの更新。 |

---

## データ整合性

| 観点 | 内容 |
|------|------|
| 多重実行 | ロックは持たない。同時実行時は同一行を上書きするため最後の更新値が残る。 |
| 途中失敗・再実行 | 上書き更新のため再実行で正しい集計値に収束する。部分反映は次回実行で回収される。 |
| 参照時点 | 実行時点の在庫履歴を対象とする。 |

## DBカラム

機能に直接関係する列のみ記載する。型や一覧の細部はスキーマを参照する。

| テーブル | 列 | メモ |
|----------|-----|------|
| `dtb_stock_history` | `stock`・`old_stock`、商品規格は `product_stock_id` 経由（現行 `product_class_id` を直接保持） | 集計単位と入庫数（在庫増加分）の算出に使用する。 |
| `dtb_stock_history` | `create_date`・`stock_change_type_detail_id`（現行 `stock_change_type_id`） | 期間判定・対象区分判定に使用する。 |
| `dtb_stock_up_quantity`（現行は商品規格サブ `dtb_product_sub_class`） | `stock_up_quantity_01`〜`stock_up_quantity_10` | 期間別入庫数の反映先。`stock_up_quantity_01`は0で初期化する。移行先では専用表に分離する。 |

### DB操作

本機能は参照系（検索）であり、DBへの登録・更新・削除は行わない。テーブル名は ec-cube-enterprise を正典とする。

| 操作種別 | 対象テーブル | 契機・条件 |
|---------|--------------|------------|
| 検索 | dtb_product_sub_class / dtb_stock_history / dtb_stock_up_quantity | 検索条件に合致するレコードを抽出する。 |

## 排他制御・トランザクション

ロックファイルによる多重起動防止は持たない。長時間処理に備えて実行時間制限を解除し、100件ごとに変更を反映しキャッシュをクリアしてメモリを管理する。本バッチは楽観ロック・悲観ロックの対象を持たない。
