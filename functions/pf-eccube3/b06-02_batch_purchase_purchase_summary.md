# バッチ 買取管理 — 買取集計バッチ

## 概要

店頭買取の取引データを集計日単位で集計し、店舗・部門ごとの買取金額・売価金額を買取集計テーブルへ登録するバッチである。コマンドライン（コンソールコマンド）から実行する。集計日の店頭買取データを店舗・部門単位で合算し、同じ集計日の既存集計を削除してから当日分を登録し直す。集計対象の中に部門が未設定の商品がある場合は、その一覧を管理者へ通知メールで送る。

本書は実装手順ではなく、誰が・いつ・どの条件で・結果どうなるかを読むためのリバース詳細設計とする。確認値はpf-eccube3（EC-CUBE3系）のHareruyaEcプラグインの買取集計バッチ、店頭買取・買取集計を扱うリポジトリ、通知メール送信処理を正とする。

カスタマイズ区分はカスタマイズであり、挙動はpf-eccube3を参照し、DB関連の記述はec-cube-enterpriseを正とする。

対象はコンソールコマンドであり、ブラウザ経由の画面を持たない。

本文ではフレームワークのコマンド型名やサービス型名を主説明としない。実行はコンソールのバッチコマンドで行う。

## 本書で扱うこと

- バッチの起動方法（コンソールコマンド）と集計日引数
- 集計日の店頭買取データの店舗・部門単位の集計
- 既存集計の削除と当日分の登録
- 部門未設定商品がある場合の管理者通知メール
- 集計中エラー時のロールバックとエラー通知メール

## リニューアル移行時の扱い

集計・登録の挙動は現行pf-eccube3を踏襲し、DB関連の永続化先はec-cube-enterpriseを正とする。店舗参照キーが現行と移行先で異なる。

| 観点 | 現行（pf-eccube3） | 移行先（ec-cube-enterprise） |
|------|--------------------|------------------------------|
| 集計・登録の挙動 | 集計日の店頭買取を店舗・部門単位で集計し、当日分の既存集計を入れ替える。 | 同等の挙動を踏襲する（挙動はpf-eccube3を正とする）。 |
| 店舗参照キー | 独自店舗マスタ参照の `shop_id`（`dtb_otc_buy_order`・`dtb_otc_buy_order_summary`）。 | `base_info_id`（店舗基本情報 `dtb_base_info` 参照）。`dtb_otc_buy_order`・`dtb_otc_buy_order_summary` とも `shop_id` から `base_info_id` へ変わる。 |
| 集計結果の永続化先 | `dtb_otc_buy_order_summary`。 | 同名テーブル。店舗参照キーのみ `base_info_id` へ変わる。 |
| 明細・個別入力商品の集計元 | `dtb_otc_buy_order_detail`・`dtb_otc_buy_order_indivisual_input_product`。 | 同名・同等スキーマ（`section_id`・`price`・`original_quantity`／`quantity`・`sell_price` 等）。 |

## 用語

| 用語 | 説明 |
|------|------|
| 店頭買取 | 店頭で商品を買い取る取引。店頭買取テーブルと明細に記録する。 |
| 集計日 | 集計対象とする1日。引数で指定するか、未指定なら前日を用いる。 |
| 部門 | 商品を分類する区分。集計の単位の一つ。 |
| 買取金額 | 買い取った金額。単価と数量から算出する。 |
| 売価金額 | 販売予定の金額。単価と数量から算出する。 |
| 買取集計 | 店舗・部門・集計日ごとに買取金額・売価金額を合算した結果。買取集計テーブルへ登録する。 |
| 部門未設定商品 | 集計対象の明細のうち部門が設定されていない商品。 |

## 利用者視点の入口

| 入口 | 実行方法 | 期待されるふるまい |
|------|----------|--------------------|
| コンソールのバッチコマンド | `otcBuyOrder:batch updateSummary [YYYY-MM-DD]` | 集計日の店頭買取データを店舗・部門単位で集計し、当日分の既存集計を入れ替える。部門未設定商品があれば管理者へ通知メールを送る。 |

引数に集計日（`YYYY-MM-DD`形式）を1つ指定できる。引数を省略した場合は前日を集計日とする。本機能はHTTPで届く画面を持たない。コマンド名が一致しない場合は処理を行わずに終了する。

## 処理フロー

### 買取集計を実行する（`otcBuyOrder:batch updateSummary`）

1. 実行時間制限を解除し、メール送信用の経路を準備し、トランザクションを開始する。
2. 集計日を決める。引数が指定されていればその日付、無ければ前日を用いる。いずれも当日0時0分0秒を起点とする。
3. 集計日の店頭買取データを店舗・部門単位で集計し、買取金額・売価金額の合計を得る。
4. 同じ集計日の既存の買取集計を削除する。
5. 集計結果を買取集計テーブルへ一括登録する。集計結果が0件の場合は登録を行わない。
6. 集計日の店頭買取の中から部門未設定商品の一覧を取得する。
7. 部門未設定商品がある場合は、その一覧を管理者へ通知メールで送る。
8. トランザクションをコミットする。

集計または登録の途中で例外が発生した場合は、登録をロールバックし、エラー内容を添えた集計エラー通知メールを管理者へ送る。

## 業務ルール・計算

| 項目 | 内容 |
|------|------|
| 集計日の起点 | 引数指定時はその日付の0時0分0秒。未指定時は前日の0時0分0秒。 |
| 集計区間 | 集計日の0時0分0秒から23時59分59秒まで。完了日が区間内の店頭買取を対象とする。 |
| 対象ステータス | 完了・ダブルチェック済み・入力済みの店頭買取を対象とする。 |
| 買取金額 | 明細・個別入力商品それぞれで単価と数量を掛けて算出し合算する。 |
| 売価金額 | 明細・個別入力商品それぞれで売価単価と数量を掛けて算出し合算する。 |
| 端数調整分 | 査定合計金額の1の位切り上げ分を、オプションで指定した特定部門の買取金額として加える。当該分の売価金額は0とする。 |
| 集計単位 | 店舗と部門の組み合わせごとに合算する。 |
| 数量条件 | 明細は元数量が0より大きい行、個別入力商品は数量が0より大きい行を集計対象とする。 |

## 集計条件

| 指標 | 集計の要点 |
|------|------------|
| 対象データ | 集計区間内に完了日を持つ店頭買取の明細と個別入力商品。 |
| 結合 | 店頭買取と明細・個別入力商品を結合する。部門未設定判定では明細から商品・商品規格・商品マスタを結合する。 |
| ステータス条件 | 完了・ダブルチェック済み・入力済みの店頭買取に限定する。 |
| 除外条件 | 明細は元数量が0以下の行、個別入力商品は数量が0以下の行を除外する。端数調整分は買取金額が0より大きい取引のみを加算する。 |
| 集計期間 | 集計日の0時0分0秒から23時59分59秒までの1日。 |
| 集計単位 | 店舗ID・部門IDの組み合わせ。買取金額・売価金額をそれぞれ合計する。 |

## API・バッチ結果

| 種類 | 内容 |
|------|------|
| 入力 | コマンド名と任意の集計日引数（`YYYY-MM-DD`）。 |
| 実行条件 | 集計対象の店頭買取が無い場合も実行できる。 |
| 成功結果 | 同じ集計日の既存集計を削除し、当日分の集計を登録する。部門未設定商品があれば管理者へ通知メールを送る。 |
| 失敗結果 | 集計・登録途中の例外時は登録をロールバックし、エラー内容を添えた集計エラー通知メールを管理者へ送る。 |
| 再実行時 | 同じ集計日で再実行すると既存の当日分集計を削除してから登録し直すため、当日分が重複しない。冪等である。 |

外部システムへの連携は行わない。

---

## 入出力

| 種類 | 内容 |
|------|------|
| 入力 | コマンド名と任意の集計日引数。 |
| 成功時出力 | 集計日の既存集計の削除と当日分集計の買取集計テーブルへの登録。部門未設定商品がある場合の管理者通知メール。 |
| 失敗時出力 | 登録のロールバックと集計エラー通知メールの送信。 |
| 副作用 | 買取集計テーブルの当日分レコードの入れ替え、通知メール送信。 |

集計結果はファイルではなく買取集計テーブル（`dtb_otc_buy_order_summary`）へ登録する。部門未設定商品の通知メールには商品名・商品コードの一覧を本文に載せる。

## データ整合性

| 観点 | 内容 |
|------|------|
| 多重実行 | ロックファイル等による多重起動防止は行わない。同じ集計日を同時に実行すると、双方が削除と登録を行い当日分が重複し得る。 |
| 途中失敗・再実行 | 削除と登録を1トランザクションで行い、例外時はロールバックする。再実行で同じ集計日の集計を入れ替えるため重複しない。 |
| 参照時点 | 実行時点の店頭買取データを集計対象とする。 |
| 削除と登録の範囲 | 削除・登録の対象は指定集計日の当日分に限る。他日の集計は変更しない。 |

機能に直接関係する列のみ記載する。型や一覧の細部はスキーマを参照する。

| テーブル | 列 | メモ |

本機能は参照系（検索）であり、DBへの登録・更新・削除は行わない。テーブル名は ec-cube-enterprise を正典とする。

| 操作種別 | 対象テーブル | 契機・条件 |
|---------|--------------|------------|
| 検索 | dtb_otc_buy_order / dtb_otc_buy_order_detail / dtb_otc_buy_order_indivisual_input_product / dtb_otc_buy_order_summary | 検索条件に合致するレコードを抽出する。 |

## エラー処理

| エラー内容 | 処理 |
|------------|------|
| コマンド名が未指定・不一致 | 処理を行わずに終了する。 |
| 集計対象が0件 | 既存の当日分集計を削除し、登録は行わず完了する。 |
| 集計・登録中の例外 | 登録をロールバックし、エラー内容を添えた集計エラー通知メールを管理者へ送る。 |
| 通知メール宛先が未設定 | メールを送らずに当該メール処理を終了する。 |

## ログ・監査

| タイミング | 記録内容 |
|------------|----------|
| 起動 | バッチコマンドの起動時に日時付きのコンソール出力を行う。 |
| 部門未設定商品通知メール | 送信開始・送信完了・件数、宛先未設定時の送信せず終了をログに記録する。 |

### ログに出してはいけないもの

- パスワード
- トークン・接続秘密値
- メール送信の認証情報
- Cookie値・セッションIDの完全値

## 通知

| 観点 | 内容 |
|------|------|
| 送信条件 | 集計対象に部門未設定商品があるとき部門未設定商品通知メールを送る。集計・登録途中で例外が発生したとき集計エラー通知メールを送る。 |
| 宛先 | オプションに設定された買取集計通知用メールアドレス（カンマ区切り）を宛先とする。宛先が未設定の場合は送信しない。宛先の決まり方はオプション管理を正とする。 |
| 本文 | 部門未設定商品通知メールは商品名・商品コードの一覧を載せる。集計エラー通知メールは例外メッセージを載せる。 |

---

## 排他制御・トランザクション

ロックファイル等による多重起動防止は行わない。集計結果の削除と登録は1トランザクションで囲み、例外時はロールバックする。長時間処理に備えて実行時間制限を解除する。本バッチは楽観ロック・悲観ロックの対象を持たない。
