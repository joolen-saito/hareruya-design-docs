# F06-06（購入履歴一覧）

## 概要

購入履歴一覧は、ログイン済み会員が自身の注文（購入）の履歴を一覧で確認する機能である。会員の注文を新しい順にページングして表示し、各行に注文日・注文番号・注文内容・注文金額合計・支払方法・処理状態を出す。注文番号のリンクから購入履歴詳細へ遷移し、注文内容から再購入（カートへの再投入）を行える。処理中（カート操作中相当）の注文は一覧から除外する。

本書は実装手順ではなく、誰が・いつ・どの条件で・結果どうなるかを読むためのリバース詳細設計とする。確認値はpf-eccube3（EC-CUBE3系）のHareruyaEcプラグインの購入履歴一覧処理、購入履歴一覧テンプレート（`Mypage/shopping_history.twig`）、会員の注文を取得するリポジトリ、注文番号取得処理を正とする。

本機能のカスタマイズ区分はカスタマイズであり、画面・処理フローの挙動はpf-eccube3を参照リポとする。DB関連（テーブル名・列名・保存先）はec-cube-enterpriseを正とする。

対象はブラウザ経由のフロント（会員マイページ）に限定する。フロントのページは言語別パスセグメント`/{_locale}`を前提とし、本書のパスは`/{_locale}`配下の確認値として記載する。`/mypage`配下は会員ログインを要する。

本文ではフレームワークのコントローラ型名やメソッド名を主説明としない。ルートbind名の網羅は主説明とせず、「利用者視点の入口」にHTTPメソッドとサイトルートからのパスパターンを書く。

## リニューアル移行時の扱い

DB関連の記述はec-cube-enterpriseを正とする。注文ヘッダ（`dtb_order`）の列名（`customer_id`・`order_status_id`・`order_date`・`payment_total`）は現行（pf-eccube3）と移行先（ec-cube-enterprise）で同一スキーマである。

注文明細の保持先テーブル名は現行と移行先で異なる。現行の注文明細テーブル`dtb_order_detail`は、移行先（ec-cube-enterprise）では`dtb_order_item`に相当する。注文内容・再購入に用いる`product_name`・`quantity`は同名の列、商品規格は`product_class_id`の関連で保持する。本書のDB記述は移行先名（`dtb_order_item`）を主とし、現行名（`dtb_order_detail`）を括弧で添える。

一覧表示・再購入内容の取得は参照のみで業務データを更新しないため、移行に伴う保存処理の差分は生じない。

## 利用者視点の入口

| 入口 | URLエンドポイント | 期待されるふるまい |
|------|--------------------|--------------------|
| マイページの「購入履歴」ブロック | `GET /{_locale}/mypage/shopping_history` | 会員ログインを要し、会員の注文を新しい順にページングして一覧表示する。 |
| ページ送り | `GET /{_locale}/mypage/shopping_history?page={n}` | 指定ページの注文一覧を表示する。 |
| 注文番号リンク | `GET /{_locale}/mypage/shopping_history/detail/{id}` | 当該注文の購入履歴詳細へ遷移する（購入履歴詳細機能を正とする）。 |

| 領収書発行 | `GET /{_locale}/mypage/shopping_history/printOrderReceipt/{id}` | 領収書発行画面を表示する。 |

`/mypage`配下は会員ログインを要する。一覧は当該会員の注文のみを対象とする。

| 観点 | 内容 |
|------|------|
| 表示要素 | 見出し「購入履歴一覧」、件数表示（全件数・現在の表示範囲）、ページ送り、注文一覧（列: 注文日、注文番号、注文内容、注文金額合計、支払方法、処理状態）、各注文の「この注文内容で再度購入する」操作。 |
| JS挙動 | 再購入は非同期で当該注文の商品・数量をカート投入用に取得する。処理状態は状態に応じた画像で表示する。 |

注文内容には注文明細の商品名を列挙する。注文金額合計・支払方法・処理状態は注文ごとに表示する。

## 処理フロー

### 購入履歴一覧を表示する（GET `/{_locale}/mypage/shopping_history`）

1. 会員ログインを要求する。未ログインの場合は会員ログインへ誘導する（会員ログイン機能を正とする）。
2. クエリからページ番号・1ページ件数を決める（既定は1ページ目・10件）。
3. 当該会員の注文を、処理中の注文を除外して新しい順（注文IDの降順）に取得する。
4. ページングして、対象注文の注文番号を取得する。
5. 件数・一覧・ページ送りを表示する。

### 再購入する（POST `/{_locale}/mypage/shopping_history/repurchase`）

1. 注文IDを受け取る。注文IDが無い場合は不正要求（HTTP404）とする。
2. ログイン会員と注文IDで注文を特定する。該当が無い場合は不正要求（HTTP404）とする。
3. 注文明細の商品・数量からカート投入用の内容を組み立てる。
4. 成功とカート投入内容をJSONで返す。

## 集計条件

| 指標 | 集計の要点 |
|------|------------|
| 一覧対象 | ログイン会員の注文。処理中（カート操作中相当のステータス）の注文を除外する。 |
| 並び順 | 注文IDの降順（新しい順）。 |
| ページング | 1ページ10件（既定）。ページ番号・1ページ件数はクエリで指定できる。 |
| 件数 | 全件数を表示し、現在ページの表示範囲を併記する。 |

---

## 業務ルール・計算

| 項目 | 内容 |
|------|------|
| 抽出条件 | 当該会員の注文のうち、処理中の注文を除外する。 |
| 並び順 | 新しい注文を先頭にする（注文IDの降順）。 |
| 注文番号 | 一覧対象の注文IDから注文番号を取得し、リンク表示・詳細遷移に用いる。 |
| 再購入 | 過去の注文明細の商品・数量をカート投入用の内容として返す。投入後の手続きはカート・購入機能を正とする。 |
| 業務計算 | 一覧では注文金額合計を注文の保持値から表示する。集計の再計算は行わない。 |

本機能は一覧表示が主で、利用者入力のフォームを持たない。再購入は注文IDをパラメータで受け取る。

### エッジケース

| ケース | 扱い |
|--------|------|
| 注文が0件 | 件数0として一覧を空表示する。 |
| 処理中の注文のみ | 処理中を除外するため一覧に表示しない。 |
| 再購入で注文IDが無い | 不正要求（HTTP404）とする。 |
| 再購入で他会員の注文IDを指定 | 当該会員の注文として特定できず不正要求（HTTP404）とする。 |
| 未ログイン | 会員ログインへ誘導する。 |

| 観点 | 内容 |
|------|------|
| 一覧対象会員 | 一覧は当該会員の注文のみを参照する。 |

## DBカラム

機能に直接関係する列のみ記載する。型や一覧の細部はスキーマを参照する。

| テーブル | 列 | メモ |
|---------|-----|------|
| `dtb_order` | `customer_id` | 会員ごとの絞り込みキー。 |
| `dtb_order` | `order_status_id` | 処理中の注文を除外する条件、および処理状態の表示に用いる。 |
| `dtb_order` | `order_date` | 注文日の表示。 |
| `dtb_order` | `payment_total`（金額合計） | 注文金額合計の表示。 |
| `dtb_order_item`（現行 `dtb_order_detail`） | `product_name` / `product_class_id` / `quantity` | 注文内容の表示、再購入のカート投入内容。移行先では注文明細を`dtb_order_item`で保持する。 |

### DB操作

本機能は参照系（検索）であり、DBへの登録・更新・削除は行わない。テーブル名は ec-cube-enterprise を正典とする。

| 操作種別 | 対象テーブル | 契機・条件 |
|---------|--------------|------------|
| 検索 | dtb_order / dtb_order_detail / dtb_order_item | 検索条件に合致するレコードを抽出する。 |
