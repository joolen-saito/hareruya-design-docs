# F06-10（ポイント履歴）

## 概要

ログイン済み会員が、自分の獲得ポイント・利用ポイントの履歴を一覧で閲覧する機能である。マイページ系の「ポイント履歴」から入り、会員に紐づくポイント履歴を発行日の新しい順にページングして表示する。あわせて現在の保有ポイントと、次に失効するポイントの見込みを表示する。獲得（プラス）・利用（マイナス）の符号、注文番号、有効期限、備考を一覧に並べる。

本書は実装手順ではなく、誰が・いつ・どの条件で・結果どうなるかを読むためのリバース詳細設計とする。確認値はpf-eccube3（EC-CUBE3系）のHareruyaEcプラグインのポイント履歴一覧処理、テンプレート（`Mypage/point_history.twig`）、ポイント履歴リポジトリの取得・失効算定処理を正とする。

本機能のカスタマイズ区分はカスタマイズである。画面・処理の挙動はpf-eccube3を参照し、DB関連（テーブル名・列名・制約・関連）はec-cube-enterpriseを正とする。

対象はブラウザ経由のフロント（会員マイページ）に限定する。フロントのルートは`/{_locale}`配下にマウントされ、URLは`/{_locale}/mypage/point_history`の形をとる。

本文ではフレームワークのコントローラ型名やメソッド名を主説明としない。本文ではルートbind名の網羅は主説明とせず、「利用者視点の入口」にHTTPメソッドとサイトルートからのパスパターンを書く。コード探索でbind名が必要なときだけ「調査補助」へ書く。

## 利用者視点の入口

| 入口 | URLエンドポイント | 期待されるふるまい |
|------|--------------------|--------------------|
| マイページの「ポイント履歴」ブロック | `GET /{_locale}/mypage/point_history` | 会員自身のポイント履歴を新しい順に1ページ目を表示する。 |

## フロント挙動

| 観点 | 内容 |
|------|------|
| 表示要素 | 見出し「ポイント履歴一覧」、会員氏名と「様」、現在のポイント、次に消失するポイント（額と失効日）、表示件数セレクト、件数範囲・総件数、ページ送り、履歴一覧（利用or獲得日・注文番号・ポイント・有効期限・備考）、「マイページ」ボタン。 |
| JS挙動 | 履歴用スクリプトを読み込み、表示件数セレクトの変更をページサイズの隠し項目へ反映してGET送信する。 |
| CSS・レイアウト | 獲得（プラス）と利用（マイナス）でポイント値の表示色を切り替える。現在ポイント・失効見込みは強調表示する。 |
| モーダル・ポップアップ | 本画面専用のモーダルは無い。 |

履歴行のポイント値は、プラスのとき先頭に「+」を付けて表示し、マイナスはそのまま表示する。有効期限はプラスの履歴にのみ表示する。注文番号は注文に紐づく履歴のみリンク表示する。

---

## 処理フロー

### ポイント履歴一覧を表示する（GET `/{_locale}/mypage/point_history`）

1. 会員ログインを要求し、ログイン会員と選手情報を特定する。
2. GETクエリ一式を受け取り、ページ番号・1ページ件数を決定する（既定はページ1・10件）。
3. 当該会員のポイント履歴を発行日の新しい順（同日は履歴識別子の新しい順）で取得し、ページングする。
4. 選手情報の現在ポイントを起点に、次に失効するポイント履歴（失効見込み）を算定する。
5. 取得した履歴のうち注文に紐づくものについて、表示用の注文番号をまとめて取得する。
6. 現在ポイント・失効見込み・一覧・注文番号・クエリをテンプレートへ渡して表示する。

## 集計条件

| 指標 | 集計の要点 |
|------|------------|
| ポイント履歴一覧 | ログイン会員のポイント履歴を対象とする。並びは発行日の降順、同日は履歴識別子の降順。 |
| ページング | `page`・`pageSize`で分割する。`pageSize`の選択肢は10・20・50・100。 |
| 現在ポイント | 選手情報の保有ポイント値を表示する。 |
| 失効見込み | 失効日数の設定から失効基準日を求め、基準日以降の獲得（プラス）履歴を新しい順に保有ポイントへ充当し、保有ポイントを使い切る履歴の失効分を算定する。同日の複数履歴は合算する。保有ポイントが0の場合は失効見込みを持たない。 |
| 注文番号 | 注文に紐づく履歴の注文識別子をまとめて注文番号へ変換する。 |

## 表示メッセージ

### 常時表示（正常・静的）

本機能は英語ロケール（`Mypage/point_history.en.twig`）に対応するため、英語文言を併記する。

| 種別 | 表示文言（日本語） | 表示文言（英語） | 条件 |
|------|-------------------|------------------|------|
| 現在ポイント | 現在のポイント：（保有ポイント）ポイント | Current Points : （保有ポイント） Points | 一覧表示時に常時 |
| 失効見込み | 次に消失するポイント：（失効見込み額）ポイント（失効日） | Next Points to be Expired: （失効見込み額） Points （失効日） | 失効見込みがある場合 |
| 件数表示 | （開始）~（終了）件 ／ （総件数）件あります | [（開始） ~ （終了）] ／ （総件数） Items | 一覧表示時に常時 |

失効見込みが無い場合（保有ポイント0など）は失効額・失効日を表示しない。本機能はフォーム送信に伴うフラッシュ・インラインエラーを生成しない。

## 業務ルール・計算

| 項目 | 内容 |
|------|------|
| 一覧の対象 | 常にログイン会員自身のポイント履歴のみを対象とする。 |
| 並び順 | 発行日の降順、同日は履歴識別子の降順。 |
| 獲得・利用の表示 | 増減値がプラスは「+」付き、マイナスはそのまま表示し、色で区別する。 |
| 有効期限 | プラス（獲得）の履歴にのみ有効期限を表示する。失効日数の設定から発行日を起点に算定する。 |
| 失効見込み | 保有ポイントを新しい獲得履歴から充当し、使い切る履歴を失効見込みとする。表示額は失効見込み額と保有ポイントの小さい方とする。 |
| 注文番号 | 注文に紐づく履歴は注文番号をリンク表示し、押下で注文詳細を別タブで開く。 |

本機能では一覧表示に伴う入力フォームを持たないため、`### 入力項目`の表は持たない。ページ・表示件数はGETクエリで受け取る。

### エッジケース

| ケース | 扱い |
|--------|------|
| ポイント履歴0件 | 件数を0件として一覧領域を空で表示する。 |
| 保有ポイントが0 | 失効見込みを算定せず、失効見込み表示を出さない。 |
| 失効基準日より古い獲得のみ | 基準日以降の獲得が無いため失効見込みを得ない。 |
| 注文に紐づかない履歴 | 注文番号欄を空とする。 |

### DB操作

永続化の正は ec-cube-enterprise（テーブル名・操作は ec-cube-enterprise を正典）。当ドメインは承認ワークフローを介さず persist/flush で直接確定する（承認ワークフローは在庫機能固有）。

| 操作種別 | 対象テーブル | 契機・条件 |
|---------|--------------|------------|
| 登録/更新 | dtb_player / dtb_point_history | 当機能が行う登録・更新で対象テーブルを直接保存する（不要な削除は含まない）。確定は persist/flush による即時反映。DB=ec-cube-enterprise を正典とする。 |
