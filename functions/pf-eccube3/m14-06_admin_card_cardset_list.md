# カード管理 — カードセット一覧

## 概要

HareruyaEc プラグインが管理画面に提供する「カードセット管理」において、カードセットマスタを表形式で一覧し、ページ送り・表示件数・並び順を切り替え、新規登録・編集・削除・画像ダウンロード（セット別／言語別）・ブロックマスタ参照への導線をまとめて置く画面である。一覧の抽出条件は実装上当該マスタの全件であり、キーワード検索やステータス絞り込みは持たない。

本書は実装手順ではなく、誰が・いつ・どの条件で・結果どうなるかを読むためのリバース詳細設計とする。pf-eccube3 に配置された HareruyaEc プラグインのソースを確認値とする。コア単体では当ルートは存在しない。

本機能のカスタマイズ区分は現行踏襲である。現行挙動は pf-eccube3 の HareruyaEc プラグインを参照し、永続化に関わるテーブル名・列名などのDB関連は ec-cube-enterprise を正とする。

対象はブラウザ経由の管理画面に限定する。コントローラのメソッド名は本文の主説明としない。本文ではルートbind名やSymfonyのルートnameの網羅は主説明としない。「利用者視点の入口」にHTTPメソッドとサイトルートからのパスパターンを書く。コード探索でbind名が必要なときだけ「調査補助」へ書く。

## リニューアル移行時の扱い

DB関連の記述は ec-cube-enterprise の実装を正とする。一覧が参照するカードセットマスタと表示件数マスタは現行（pf-eccube3）と移行先（ec-cube-enterprise）で同一のテーブル名・列名であり、同一スキーマである。

| 観点 | 現行（pf-eccube3） | 移行先（ec-cube-enterprise） |
|------|---------------------|-------------------------------|
| カードセットマスタ | `mtb_cardset`（`release_date`/`symbol_image`/`code`/`name_jp`/`name_en`/`special_flg`/`display_side_menu_flg`/`branch_display_flg`） | 同一スキーマ（`mtb_cardset`、列名一致）。 |
| 表示件数マスタ | `mtb_page_max`（`name` を表示件数候補に使用） | 同一スキーマ（`mtb_page_max`）。 |

並び順（リリース日／セット英名の昇降順）・表示件数・ページングの挙動とセッションキーは現行（pf-eccube3）を参照する。移行先でもテーブル・列は同名である。

## 利用者視点の入口

| 入口 | URLエンドポイント | 期待されるふるまい |
|------|--------------------|--------------------|
| サイドメニュー「カードセット管理」 | `GET /{admin_route}/cardset` | 直前のページ番号・表示件数・並び順をセッションから読み直すが、クエリ `resume` が `1` でない場合は当該 3 種のセッションキーを削除してから初期化する。既定の並びはリリース日の新しい順。一覧を描画する。 |
| 同じ入口で検索中断からの再開を想定したアクセス | `GET /{admin_route}/cardset?resume=1` | ページ番号・表示件数・並び順のセッションを消さず、保持値で一覧を組み立てる。 |
| ページャのリンク | `GET /{admin_route}/cardset/{page_no}`（必要に応じ `pageCount`・`sortSelect` をクエリに付与） | セッションとクエリから表示件数・並び順を決め、該当ページの行を表示する。 |
| 表示件数ドロップダウンで別件数を選ぶ | `GET /{admin_route}/cardset/1?…&pageCount=…&sortSelect=…` | クエリの `pageCount` が `mtb_page_max.name` のいずれかと一致する場合のみセッションと実表示に反映する。ページは 1 にリセットするリンクとなる。 |
| 並び順ドロップダウンで別順を選ぶ | `GET /{admin_route}/cardset/1?…&pageCount=…&sortSelect=…` | クエリの `sortSelect` が定義済み 4 文言のいずれかと完全一致する場合のみセッションと一覧順に反映する。 |
| 表の「編集」 | `GET /{admin_route}/cardset/{id}/edit` | カードセット編集画面へ遷移する。 |
| 表メニューの「削除」 | `DELETE /{admin_route}/cardset/{id}/delete` | 別処理。成功時は一覧のページへ戻る。 |
| 「新規登録」 | `GET /{admin_route}/cardset/new` | 新規登録フォームへ遷移する。 |
| 「ブロックの追加」 | `GET /{admin_route}/…`（マスタデータ閲覧ルート `admin_hareruya_masterdata_view`、エンティティ指定でカードセットブロック） | ブロックマスタの管理画面へ遷移する。 |
| 「画像ダウンロード（セット別）」 | `POST /{admin_route}/cardset/download` | チェックされたセット ID の一覧を送り、別処理が ZIP 応答またはエラー後リダイレクトを返す。 |
| 「画像ダウンロード（言語別）」 | `POST /{admin_route}/cardset/download_lang` | 同上（言語別の取りまとめ）。 |

## 処理フロー

### 一覧を表示する（`admin_cardset` または `admin_cardset_page`）

1. 管理画面の認証・共通制約を通過する。
2. フォーム種別 `card_set` の空フォームを生成し、一覧 POST 用に CSRF フィールドを得る（一覧では入力項目はトークンのみ実質利用）。
3. `page_no` が URL に無い（ルート `admin_cardset`）かつクエリ `resume` が整数 `1` でない場合、セッションから `eccube.admin.cardset.page_no`、`eccube.admin.cardset.pageCount`、`eccube.admin.cardset.sortSelect` を削除する（コアの有効フラグとしても同値が使われる）。
4. `mtb_page_max` を全件取得する。
5. 表示件数はセッションの `eccube.admin.cardset.pageCount` があればそれを使い、無ければ設定 `default_page_count`。リクエストに `pageCount` があり数値であり、かつ `mtb_page_max` のいずれかの `name` と文字列一致する場合、その値に更新してセッションへ保存する。
6. 並び順の候補は固定の 4 文言（リリース日の昇順／降順、セット英名の昇順／降順）。現在値はセッションの `eccube.admin.cardset.sortSelect` があればそれを使い、無ければ「リリース日（降順）」。リクエストに `sortSelect` があり、4 候補のいずれかと完全一致する場合、その値に更新してセッションへ保存する。
7. カードセット用リポジトリの `select` に現在の並び順ラベルを渡し、全件を配列として取得する。クエリは当該エンティティに対する `orderBy` のみで、WHERE による絞り込みは行わない。
8. `page_no` は URL 引数が無ければ `1`。アプリケーションのページネータで `wrap-queries` 有効のまま分割する。
9. セッションに `eccube.admin.cardset.page_no`、`eccube.admin.cardset.pageCount`、`eccube.admin.cardset.sortSelect` を書き戻す。
10. Twig `card_set.twig` を描画する。

## 業務ルール・計算

本機能の一覧画面では永続化する入力フォーム項目を持たない。登録・更新の入力項目と最大長はカードセット編集画面の設計を正とする。

| 項目 | 内容 |
|------|------|
| 一覧の対象行 | カードセットマスタの全レコード。 |
| 並び順 | リリース日の昇順／降順、またはセット名（英）の昇順／降順。いずれも単一プロパティのみ。 |
| 画像ダウンロード POST | フォーム名 `cardsetIds[]` のチェック値が送られる。一覧画面の定義外の本文では空配列のとき `[0]` に置き換えて処理が進む実装があり、プロモーション用の特別扱いに繋がる。詳細は画像ダウンロードの実装を正とする。 |

本機能では集計・合算・価格計算などの業務計算を行わない。

## データ整合性

| 観点 | 内容 |
|------|------|
| 一覧と DB | 表示リクエスト時点のコミット済みデータを読む。悲観・楽観ロックは一覧取得に使わない。 |

## 調査補助（grep向け）

### HTTPルート名とパス（コード探索用・旧入口節より退避）

- `admin_cardset` … `GET, POST` … `/{admin_route}/cardset`（一覧の表示。クエリで表示件数・並び順を切り替え可能。POST はフォームの既定 action（CSRF 付き）。画像ダウンロード系ボタンは `formaction` で別ルートへ送る。）
- `admin_cardset_page` … `GET, POST` … `/{admin_route}/cardset/{page_no}`（同上。`page_no` は 1 以上の整数（ルートの assert）。ページ送りや表示件数・並び順変更時の URL。）
