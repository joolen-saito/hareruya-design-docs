# M09-10（支店トップページ管理）

## 概要

支店トップページ管理は、支店ごとのトップページに表示するバナー画像、バナーに紐づくタグ、タイル配置、タイル属性、タイルタグを管理者が編集する機能である。対象支店を選択して画面を開き、支店共通設定を適用するか、支店固有のトップページ設定を保存するかを選ぶ。リニューアル後は限定品タグ2項目を画面の表示・送信対象から除外する。

本書は実装手順ではなく、誰が・いつ・どの条件で・結果どうなるかを読むためのリバース詳細設計とする。確認値は`../ec-cube`の管理画面トップページ管理コントローラ、フォーム、Twig、支店トップ表示コントローラを正とする。

本機能のカスタマイズ区分はカスタマイズであり、挙動は現行リポ（ec-cube のカスタマイズ実装）を正とし、DB関連（テーブル名・列名・保存先）は ec-cube-enterprise を正とする。`dtb_base_info`・`dtb_tile`・`mtb_tile_type`・`dtb_tag` は ec-cube-enterprise にも実装があり、`dtb_tile` の支店参照列が現行と異なる。差分は「リニューアル移行時の扱い」に集約する。

管理画面プレフィックスは設定キー`eccube_admin_route`で決まる。本書ではパスを`/{admin_route}/`のプレースホルダで示す。

---

## 本書で扱うこと

- 支店を選択して支店トップページ管理画面を表示すること
- 支店共通設定を適用するフラグだけを保存すること
- 支店固有のバナー画像、バナータグ、タイル設定を保存すること
- 画像ファイルをS3の`banner/top/{支店省略名}`配下へアップロードし、既存画像を置き換えること
- タイル位置の重複、タイル属性とタグの組み合わせを検証すること
- 管理画面JavaScriptによるサムネイル表示、支店共通設定時の入力無効化、ピックアップ商品選択時のタグ入力無効化

---

## 本書で扱わないこと

- タグマスタそのものの登録・編集
- 商品に対するタグ付け
- S3サービスの認証設定、バケットポリシー、実ファイル配信経路
- 支店マスタの登録・編集
- フロント支店トップページのHTML詳細レイアウト
- 管理画面ログイン、管理権限、CSRF共通処理の詳細

## リニューアル移行時の扱い

本機能はカスタマイズ区分がカスタマイズである。挙動は現行リポ（ec-cube のカスタマイズ実装）を正とし、DBスキーマは移行先 ec-cube-enterprise を正とする。ec-cube-enterprise の各エンティティで確認した差分を以下に記す。

| 項目 | 現行（ec-cube カスタマイズ） | 移行先（ec-cube-enterprise） |
|------|------------------------------|------------------------------|
| 支店共通設定フラグ | `dtb_base_info.common_setting_flg` | `dtb_base_info.common_setting_flg`（同一） |
| タイル配置ランダムフラグ | `dtb_base_info.random_tile_flg` | `dtb_base_info.random_tile_flg`（DB列は同一。リニューアル後の管理画面では項目除去） |
| バナー画像パス | `dtb_base_info.banner_image` | `dtb_base_info.banner_image`（同一） |
| バナー画像タグ・限定品タグ | `dtb_base_info.banner_image_tag`、`limited_items_tag01`、`limited_items_tag02` | DB列は同一。管理画面ではバナー画像タグのみ編集対象、限定品タグ2項目は項目除去 |
| タイルの支店参照 | `dtb_tile.shop_id` | `dtb_tile.base_info_id` |
| タイル位置・属性・タグ | `dtb_tile.section`、`tile_type_id`、`tag_id` | 同一 |
| タイル属性マスタ・タグ | `mtb_tile_type`、`dtb_tag` | 同一 |

`dtb_base_info`・`mtb_tile_type`・`dtb_tag` は現行と移行先でスキーマが同一である。`dtb_tile` の支店参照列のみ、現行 `shop_id` に対し移行先は `base_info_id` を用いる。本文中のDB記述は移行先名を主とし、現行名を括弧で添える。

## 用語

| 用語 | 説明 |
|------|------|
| 支店 | `dtb_base_info`で表現される店舗単位。画面の支店選択で対象を切り替える。 |
| 支店共通設定 | 対象支店のトップページ表示で共通店舗の設定を参照させるためのフラグ。保存時にこのフラグが有効なら、他の入力値は保存対象にしない。 |
| バナー画像 | 支店トップページに表示するバナー画像。ファイルはS3の`banner/top/{支店省略名}`配下に保存し、`dtb_base_info.banner_image`には保存後のパスを保持する。 |
| バナータグ | バナー画像に紐づけるタグ。`dtb_base_info.banner_image_tag`で保持する。 |
| タイル | 支店トップページの商品表示枠。リニューアル後は4つのタイル位置（上段左、上段右、下段左、下段右）を持つ。現行の5位置から、上段中央は上段右、下段中央は下段右へ対応し、現行の下段右枠は廃止する。 |
| タイル属性 | タイルの商品抽出種別。フォーマット別特集、最新エキスパンション、ピックアップ商品、その他を扱う。 |
| タイルタグ | タイル属性がピックアップ商品以外のときに商品抽出へ使うタグ。ピックアップ商品の場合はタグを使わない。 |

## フロント挙動

| 観点 | 内容 |
|------|------|
| 表示要素 | 支店選択カード、トップページ設定カード、登録ボタンを表示する。トップページ設定カードには支店共通設定、バナー画像、バナーリンクタグ、タイル設定4枠を表示する。リニューアル後はタイル配置のランダム化、限定品①タグ、限定品②タグを使用しない。 |
| バナー画像 | 既存画像がある場合はサムネイルを表示し、ファイル選択ボタンを隠す。ファイルを選択するとブラウザ上の一時URLでサムネイルを差し替え、既存画像パスのhidden値を空にする。サムネイルの削除アイコンを押すとサムネイル、選択ファイル、既存画像パスを空に戻す。 |
| タイル設定 | 既存タイル数が4枠未満の場合、画面読み込み時にプロトタイプから不足分のタイルフォームを生成し、タイル位置を上段左、上段右、下段左、下段右の順に初期設定する。 |
| 支店共通設定 | 支店IDが0の画面では支店共通設定チェックボックスを無効表示する。支店IDがある画面では変更可能とする。 |
| 非同期処理 | 保存は通常のフォームPOSTで行う。画像の事前アップロード、タイルの非同期保存、タグ検索の非同期更新は行わない。 |

### フロントエンド側ビジネスロジック

| 起点 | 参照する値 | 判定順序 | 更新する表示値・送信値 | サーバ側再検証 |
|------|------------|----------|--------------------------|----------------|
| 支店選択変更 | 支店選択セレクトの値。空なら0。 | 変更後の値を取得し、管理画面のトップページ管理URL末尾に付与する。 | 画面遷移だけを行い、フォーム値は送信しない。 | 遷移後のGETでURLのIDに対応する支店を読み込む。 |
| 画像ファイル選択 | ファイル入力の選択ファイル、既存バナー画像hidden値。 | 選択ファイルが0件なら何もしない。1件以上なら既存バナー画像hidden値を空にし、一時URLでサムネイルを表示する。 | 送信時は新しいファイルが`image_file`に入り、既存画像パスは空になる。 | サーバ側でファイルサイズ5MB、許可拡張子、S3保存可否を検証する。 |
| サムネイル削除 | サムネイル削除アイコン、ファイル入力、既存バナー画像hidden値。 | 削除アイコン押下時にサムネイルを消し、ファイル選択欄を再表示する。 | ファイル入力と既存バナー画像hidden値を空にする。 | 支店共通設定が無効で画像が空の場合、サーバ側でバナー画像エラーになる。 |
| 支店共通設定切替 | 支店共通設定チェックボックス。 | チェックありならトップページ固有設定の入力を無効化し、チェックなしなら再度有効化する。 | 画像ファイル、バナータグ、タイル設定の各入力のdisabled属性を切り替える。 | サーバ側ではPOST値の共通設定フラグが真なら他項目を保存せず、共通設定フラグだけ保存する。 |
| タイル属性変更 | 各タイルのタイル属性ID。ピックアップ商品IDは4。 | 選択値がピックアップ商品なら同じ行のタイルタグを空にして無効化する。ピックアップ商品以外ならタイルタグを有効化する。 | タイルタグの選択値とdisabled属性を切り替える。 | サーバ側でもピックアップ商品以外でタグが空なら保存せずエラーにする。 |
| 画面初期化 | 既存タイルフォーム数、リニューアル後タイル位置4枠、支店共通設定、各タイル属性。 | 不足タイルフォームを4枠まで生成し、生成後に共通設定とタイル属性に応じてdisabled制御を実行する。 | 未設定タイルの送信項目を追加し、タイル位置を上段左、上段右、下段左、下段右の順で初期化する。 | サーバ側ではタイル位置重複とタグ必須条件を検証する。 |

## 処理フロー

### 支店トップページ管理画面を表示する

1. URLの支店IDで支店情報を取得する。
2. 支店情報をデータとしてトップページ管理フォームを生成する。
3. 送信値がある場合はフォームへ反映する。
4. 支店IDが0以外なら支店選択欄に対象支店を設定する。
5. フォームビューと支店IDをテンプレートへ渡し、トップページ管理画面を表示する。

### 支店共通設定を保存する

1. POSTされた`common_setting_flg`を真偽値に変換する。
2. 対象支店の支店共通設定フラグへ保存する。
3. フラグが有効の場合は支店情報だけを永続化して`flush`する。
4. 保存完了メッセージを設定し、同じ支店のトップページ管理画面へリダイレクトする。
5. バナー画像、バナータグ、タイル設定は保存しない。

### 支店固有設定を保存する

1. POSTされたフォーム値をトップページ管理フォームへ反映する。
2. バナー画像の上書き処理を行う。
3. 既存画像をそのまま使う場合は既存画像パスを保存値とする。
4. 新規画像がある場合は既存画像をS3から削除し、新規画像をS3の`banner/top/{支店省略名}`へアップロードして保存後パスを取得する。
5. 画像が空、またはS3保存に失敗した場合はエラーメッセージを設定し、DB保存せず同じ画面へ戻る。
6. タイルごとにタイル位置の重複を検査する。重複があれば保存せずエラーで戻る。
7. タイル属性がピックアップ商品以外でタイルタグが空なら、保存せずエラーで戻る。
8. 新規タイルには対象支店を設定する。
9. 対象支店へタイルを追加し、バナー画像パスとバナータグを設定する。
10. 支店情報を永続化して`flush`する。
11. 保存完了メッセージを設定し、同じ支店のトップページ管理画面へリダイレクトする。

### 支店トップ表示への反映

1. フロントトップ表示は現在の支店情報を取得する。
2. 支店共通設定フラグが有効な場合は、共通店舗IDの支店情報を表示元として使う。
3. 表示元支店のタイルを読み込み、タイル属性がピックアップ商品ならピックアップ商品を3件取得する。
4. ピックアップ商品以外のタイルはタイルタグがあればタグに紐づく商品規格を3件取得し、タグがなければ空配列にする。
5. 未設定のタイル位置は、リニューアル後の4枠（上段左、上段右、下段左、下段右）を対象に補完する。
6. リニューアル後の支店トップページではタイル配置ランダム化を行わない。

## 業務ルール・計算

本機能では金額・税・ポイント計算を行わない。主な業務ルールは支店共通設定、画像保存、タイル位置、タイル属性とタグの整合である。

| 観点 | 内容 |
|------|------|
| 支店共通設定優先 | 支店共通設定フラグが有効なPOSTでは、トップページ固有設定を検証・保存せず、共通設定フラグだけを保存する。 |
| バナー画像必須 | 支店共通設定が無効の場合、既存画像を維持するか新規画像を選択する必要がある。既存画像も新規画像もない場合は保存しない。 |
| 画像置換 | 新規画像を選択した場合、既存画像がS3に存在すれば削除してから新規画像をアップロードする。 |
| タイル数 | 画面上は4つのタイル位置を扱う。既存タイルが4件未満でもJavaScriptで不足分を生成する。 |
| タイル位置 | 4つのタイルは異なる位置を選択する必要がある。重複があれば保存しない。 |
| タイルタグ | タイル属性がピックアップ商品の場合はタグを使わない。ピックアップ商品以外はタグ必須とし、空なら保存しない。 |
| フロント表示件数 | 支店トップ表示では各タイルの商品規格を最大3件取得する。 |
| 未設定タイル補完 | フロント表示時に未設定のタイル位置があれば、リニューアル後の4枠を対象に補完する。補完条件は支店トップページ側の表示設計を正とする。 |
| ランダム配置 | リニューアル後の支店トップページではタイル配置ランダム化を行わない。現行のランダム配置フラグは移行後の表示制御対象にしない。 |

| 限定品②タグ | 対象外 | - | - | Excel項目表では「※カスタマイズ対応、項目を除去」。`dtb_base_info.limited_items_tag02` は現行DB列として残るが、本画面では表示・送信対象にしない。 |
| タイル位置 | 必須 | 上段左、上段右、下段左、下段右 | 既存タイルのDB現行値。生成分はリニューアル後の4位置を順に設定 | `dtb_tile.section`。同一支店内で重複不可。現行5位置から、上段中央は上段右、下段中央は下段右へ対応し、現行の下段右枠は廃止する。 |
| タイル属性 | 必須 | タイル属性マスタの選択肢 | 既存タイルのDB現行値 | `dtb_tile.tile_type_id`。ピックアップ商品IDは4。 |
| タイルタグ | 条件付き必須 | タグマスタの選択肢 | 既存タイルのDB現行値 | `dtb_tile.tag_id`。ピックアップ商品以外では必須。ピックアップ商品ではJavaScriptが空にしてdisabledにする。 |

### エッジケース

| ケース | 扱い |
|--------|------|
| 支店IDが0 | 支店共通設定チェックボックスをdisabled表示する。フォーム自体は表示する。 |
| 支店共通設定を有効にして登録 | 共通設定フラグだけを保存し、画像・タグ・タイル設定は検証も保存もしない。 |
| 既存画像を維持して登録 | 既存画像パスと送信hidden値が一致し、新規ファイルがなければ既存画像パスをそのまま保存する。 |
| 既存画像を削除しただけで登録 | 画像が空として扱われ、バナー画像必須エラーで保存しない。 |
| 新規画像アップロード時に既存画像削除後のS3保存が失敗 | DB保存せずエラーで戻る。S3上の既存画像は削除済みの可能性がある。 |
| タイル位置重複 | DB保存せずエラーで戻る。 |
| ピックアップ商品以外でタグ未選択 | DB保存せずエラーで戻る。 |

## データ整合性

| 観点 | 内容 |
|------|------|
| 支店単位 | 保存対象はURLの支店IDで取得した支店情報である。タイル新規行には同じ支店を設定する。 |
| 共通設定と個別設定 | 支店共通設定が有効な場合、フロント表示は共通店舗IDの設定を参照する。対象支店の個別バナー・タイルは保存処理で更新しない。 |
| バナー画像とDB | S3保存後のパスをDBへ保存する。S3削除・アップロードとDB保存は単一トランザクションで一体化していない。 |
| タイル位置 | アプリケーション側で重複を検出して保存を止める。DB上にも同一支店・同一位置の一意性制約がある。 |
| タイルタグ | 管理画面JavaScriptとサーバ側検証の両方で、ピックアップ商品以外のタグ必須を担保する。 |
| フロント表示 | 支店トップ表示は保存済みの支店情報を読み込む。リニューアル後は4つのタイル位置を固定順で扱い、タイル配置ランダム化による表示順変更は行わない。 |

### DB操作

永続化の正は ec-cube-enterprise（テーブル名・操作は ec-cube-enterprise を正典）。当ドメインは承認ワークフローを介さず persist/flush で直接確定する（承認ワークフローは在庫機能固有）。

| 操作種別 | 対象テーブル | 契機・条件 |
|---------|--------------|------------|
| 登録/更新 | dtb_base_info / dtb_tag / dtb_tile / mtb_tile_type | 当機能が行う登録・更新で対象テーブルを直接保存する（不要な削除は含まない）。確定は persist/flush による即時反映。DB=ec-cube-enterprise を正典とする。 |

## 排他制御・トランザクション

| 観点 | 内容 |
|------|------|
| トランザクション境界 | 明示トランザクションは開始しない。支店情報とタイルは1回の`flush`でDBへ反映する。支店共通設定だけを保存する分岐も1回の`flush`で確定する。 |
| S3とDB | S3画像削除・アップロードはDBの`flush`より前に実行する。S3操作とDB保存は同一トランザクションではないため、S3操作後にDB保存で例外が起きてもS3操作はロールバックされない。 |
| ロック | 支店情報、タイル、タグに対する行ロック・悲観ロック・楽観ロック・ロックファイルは使用しない。同じ支店を同時更新した場合は後から確定したDB値が残る。 |
| 例外時 | `flush`前の例外ではDB更新は確定しない。`flush`後の例外では確定済みDB更新は戻らない。S3で削除・保存済みのファイル操作はDBロールバック対象ではない。 |
