# バッチ 会員管理 — スマレジ使用ポイント連携

## 概要

指定した受注で使用したポイントを、スマレジ側の会員ポイントへ反映（減算連携）するバッチである。コマンドライン（コンソールコマンド）から、対象の受注IDを引数に指定して実行する。購入完了処理や購入完了再処理から別プロセスとして呼び出される。

本書は実装手順ではなく、誰が・いつ・どの条件で・結果どうなるかを読むためのリバース詳細設計とする。確認値はpf-eccube3（EC-CUBE3系）のHareruyaEcプラグインのスマレジバッチ（使用ポイント連携処理）、受注サブ・選手情報を扱うリポジトリ、スマレジポイント連携処理を正とする。カスタマイズ区分は現行踏襲であり、挙動はpf-eccube3を参照し、DB関連の記述（テーブル名・列名・永続化先）はec-cube-enterpriseを正とする。

対象はコンソールコマンドであり、ブラウザ経由の画面を持たない。

本文ではフレームワークのコマンド型名やサービス型名を主説明としない。実行はコンソールのバッチコマンドで行う。

## リニューアル移行時の扱い

挙動の参照は現行（pf-eccube3）、DB関連の記述は移行先（ec-cube-enterprise）を正とする。最大の差は受注の拡張情報の保持先である。

| 項目 | 現行（pf-eccube3） | 移行先（ec-cube-enterprise） |
|------|--------------------|------------------------------|
| 受注の拡張情報（消費ポイント・連携エラー） | 補助テーブル受注サブ`dtb_order_sub`に保持 | 補助表を廃し受注`dtb_order`へ統合。`spended_points`（ポイント使用）・`point_error_message`（ポイント連携エラーメッセージ）・`smaregi_error_flg`（スマレジ連携エラーフラグ） |
| 会員のスマレジID | プレイヤー拡張テーブルのスマレジID | `dtb_player`の`smaregi_id`（スマレジID） |

現行は消費ポイントと連携エラー情報を受注サブ`dtb_order_sub`に保持するが、移行先ec-cube-enterpriseでは補助表を持たず、これらを受注`dtb_order`の列（`spended_points`・`point_error_message`・`smaregi_error_flg`）へ統合している。本文の挙動説明にある「受注サブ」は現行の保持先を指す。

## 用語

| 用語 | 説明 |
|------|------|
| 使用ポイント | 受注で使用したポイント。スマレジへ減算で反映する。 |
| 受注サブ | 受注の拡張情報。消費ポイント・連携エラー状態を保持する。 |
| 選手情報 | 会員に紐づく拡張情報。スマレジIDを保持する。 |

## 利用者視点の入口

| 入口 | 実行方法 | 期待されるふるまい |
|------|----------|--------------------|
| コンソールのバッチコマンド | `smaregi:batch updatePoint <受注ID>` | 指定受注の使用ポイントをスマレジ会員ポイントへ減算連携する。失敗時はエラーを記録する。 |

本機能はHTTPで届く画面を持たない。受注IDが未指定または数値でない場合は処理を行わずに終了する。購入完了処理・購入完了再処理から別プロセスで呼び出される。

---

## 処理フロー

### スマレジ使用ポイント連携を実行する（`smaregi:batch updatePoint <受注ID>`）

1. 引数の受注IDが未指定または数値でない場合は処理を終了する。
2. 受注IDから受注サブと会員（選手情報）を取得する。
3. 会員のスマレジIDに対し、受注の消費ポイント分を減算してスマレジへ連携する。
4. 連携が成功した場合は終了する。
5. 連携が失敗した場合は受注サブにエラーメッセージを記録し、連携エラーフラグを立てて保存する。

## 業務ルール・計算

| 項目 | 内容 |
|------|------|
| 連携量 | 受注の消費ポイントを負の値（減算）としてスマレジへ連携する。 |
| 失敗時の記録 | 連携失敗時はエラーメッセージとエラーフラグを受注サブに残し、後続の再連携対象とする。 |

## API/バッチ結果

| 種類 | 内容 |
|------|------|
| バッチ | 入力はコマンド名と受注ID。受注IDが不正なら何もせず終了する。成功時はスマレジへ使用ポイントを反映する。 |
| API | スマレジへ会員ポイントを減算連携する。失敗時はエラー内容を受注サブに保持する。 |

## DBカラム

機能に直接関係する列のみ記載する。型や一覧の細部はスキーマを参照する。

| テーブル | 列 | メモ |
|---------|-----|------|
| `dtb_order`（現行は受注サブ`dtb_order_sub`） | `spended_points`（ポイント使用。現行の消費ポイント） | 連携する減算量に使用する。 |
| `dtb_order`（現行は受注サブ`dtb_order_sub`） | `point_error_message`（ポイント連携エラーメッセージ）・`smaregi_error_flg`（スマレジ連携エラーフラグ） | 失敗時に記録する。 |
| `dtb_player`（選手情報） | `smaregi_id`（スマレジID） | 連携先会員の特定に使用する。 |

### DB操作

永続化の正は ec-cube-enterprise（テーブル名・操作は ec-cube-enterprise を正典）。当ドメインは承認ワークフローを介さず persist/flush で直接確定する（承認ワークフローは在庫機能固有）。

| 操作種別 | 対象テーブル | 契機・条件 |
|---------|--------------|------------|
| 登録/更新 | dtb_order / dtb_order_sub / dtb_player | 当機能が行う登録・更新で対象テーブルを直接保存する（不要な削除は含まない）。確定は persist/flush による即時反映。DB=ec-cube-enterprise を正典とする。 |
