# 商品管理 — 買取/販売価格履歴（検索・一覧・CSV出力）

## 概要

管理画面「商品管理」配下から開く、`dtb_price_history` を対象とする買取価格・販売価格・基準価格の変動履歴の検索・一覧表示および CSV ダウンロードである。キーワード・商品属性・日付レンジ・変更後の価格帯などで絞り込み、ページ分割して表示する。検索ビューデータ・ページ番号・表示件数・ソート項目の文字列はセッションにも保存される一方、クエリ本体の並びは実装上ほぼ固定である。

本体実装はアプリケーションコード（`src/Eccube` 配下の管理画面ルートおよびテンプレート）に置かれ、`eccube_nav.yaml` で商品メニューの子として参照される。

本書は実装手順ではなく、誰が・いつ・どの条件で・結果どうなるかを読むためのリバース詳細設計とする。

本機能のカスタマイズ区分は現行踏襲である。挙動の参照は現行リポ pf-eccube3 の HareruyaEc プラグイン実装を正とし、DB関連は ec-cube-enterprise を正とする。現行と移行先のスキーマ差は「リニューアル移行時の扱い」へ集約する。

対象はブラウザ経由の管理画面のみとする。

本文では Symfony のコントローラ型やメソッド名を主題としない。本文ではルートbind名やSymfonyのルートnameの網羅は主説明としない。「利用者視点の入口」にHTTPメソッドとサイトルートからのパスパターンを書く。コード探索でbind名が必要なときだけ「調査補助」へ書く。

## リニューアル移行時の扱い

DB関連の正典は ec-cube-enterprise とする。挙動は現行リポ pf-eccube3 の HareruyaEc プラグインを正とし、移行先との差は本節へ集約する。

| 観点 | 現行（pf-eccube3） | 移行先（ec-cube-enterprise） |
|------|--------------------|------------------------------|
| 価格履歴の主キー列 | `dtb_price_history` の主キーは `price_history_id`。 | 主キーは `id`。本書の DBカラム・JOIN 記述は移行先の `id` を正とする。 |
| 基準価格の列 | `dtb_price_history` に `standard_price`／`old_standard_price` 列が無く、販売価格・買取価格の履歴のみを保持する。 | `standard_price`（基準価格）と `old_standard_price`（変更前基準価格）が加わる。本書の基準価格レンジ検索・基準価格列は移行先の列を正とする。 |
| 商品規格への参照 | `product_class_id` は商品規格の主キー `product_class_id` を参照する。 | `product_class_id` は商品規格の主キー `id` を参照する（参照先マスタの主キー名が `id` へ変更）。列名 `product_class_id` 自体は同じ。 |
| 並び順・登録者・日時 | `sell_price`／`old_sell_price`／`buy_price`／`old_buy_price`／`member_id`／`create_date` を保持。並びは作成日時降順。 | 同名の列。同一スキーマである（基準価格列を除く）。 |

`dtb_price_history` の `product_class_id`／`sell_price`／`old_sell_price`／`buy_price`／`old_buy_price`／`member_id`／`create_date` は現行と移行先で同名である（主キー名と基準価格列の差分を除く）。

## 処理フロー

### 初回にフォームだけ表示する（GET `m03-23_admin_product_product_buy_sale_price_history`）

1. 管理画面の認証および共通処理を通過する。
2. 本機能の検索フォーム種別で空入力のフォームを生成して Twig を返す。`pagination` は `null` を渡す。表示件数候補はコントローラ内配列により 10,50,100,300,500,1000,2000,10000,12000。初期表示件数字列は設定 `eccube_default_page_count` の文字列表現。

### 検索および一覧を更新する（POST または復元済みセッション付き GET `m03-23_admin_product_product_buy_sale_price_history_search`）

1. 管理画面の認証および共通処理を通過する。
2. `page_no` が 1 以上のとき、GET クエリに `product_id` または `code` があれば、セッションの検索ビューデータ配列へ同キーの値をマージして保存してから処理を進める（送信ボディ側の入力ではない）。
3. 管理画面共通の検索トレイトの `search` に従い、ページ番号セッション、ソート用文字列、`order`、`page_count`、検索ビューを載せたセッションキー関連を読み書きする。
4. フォームの `handleRequest` で送信が無いときは、セッションに保存済みの検索ビューデータを `FormUtil::submitAndGetData` でフォームへ再入力し、その配列データをクエリ入力として使う。
5. `dtb_price_history` を基点に検索入力から組んだクエリビルダをページャへ渡し、一覧と送信後の検索フォームビューを返す。
6. 表示ページが最終ページのみを指しており総件数の境界上で行がなくなった場合、トレイト内の補正で 1 つ前のページ番号へ再ページングする。

### CSV をダウンロードする（GET `m03-23_admin_product_product_buy_sale_price_history_export`）

1. 管理画面の認証を通過する。
2. セッションキー `eccube.admin.product.buy_sale_price_history.search` が無い場合、管理フラッシュへ「検索条件を指定してからCSVをダウンロードしてください。」を積み、`GET /{admin_route}/product/buy_sale_price_history` へHTTP リダイレクト応答を返す。
3. PHP の実行時間制限を無制限へ寄せ、`getQueryBuilderForExport` で一覧と同じクエリを組む（フォーム種別作成時のみ `csrf_protection` は無効化される）。
4. PHP のチャンク送出型 HTTP 応答のコールバック内で BOM 処理は共通サービスに任せ、ヘッダ行とデータ行を逐次出力する。
5. ファイル名は `buy_sale_price_` と実行時刻から `YmdHis` で `.csv`。`Content-Type` は `application/octet-stream`。`Attachment` で同名を提示する。

## 集計条件

一覧および CSV での対象集合は共通のクエリであり、論理削除や公開状態は商品／規格側の結合および商品履歴向け共通クエリ付与関数が載せた条件により間接的に効く。

| 指標 | 集計の要点 |
|------|------------|
| 該当件数 | ページングコンポーネントの総件数。NULL だった `pagination` が初回表示で渡る場合でも Twig 側でコンテナのみ描画される。 |
| CSV 行数 | ストリーム内で iterate された履歴エンティティ数。ページングは掛けない。 |

並び順は履歴作成日時の降順および履歴行 ID の降順がクエリ側で固定になる（共通処理に渡されるキー一覧が固定であり、共通クエリ関数内でも降順のみが適用される）。

利用者やトレイトが URL に持ち込む `sort` および `order` のクエリ値は、この機能のクエリ組み関数では読まれずセッション保持に留まる（実装を確認値とする）。

---

### 一覧・CSV 共通のクエリ構成上の順序の要点

1. `dtb_price_history` をルートとし、商品規格および商品へ内部結合する。カード詳細およびカードは multi 入力時のみ左結合で追加され得る。登録管理者は作成者側の外部キーにより会員へ左結合する。
2. 共通関数がテキスト multi、カテゴリ、ステータス、セット、レアリティ、言語、状態、箔、プロモ、登録日付レンジ、ソート順を処理する。
3. 共通関数の処理のあと、`product` 配下キーにより変更後側の値で `sellPrice`・`buyPrice`・`standardPrice` に下限および上限レンジ条件を別々に付ける。いずれの境界も入力が空で無いときのみ有効。
4. プロモ検索については共通関数が、`promotion` 配列の要素数ちょうど 1 のときだけ `promotion_flg` へ写像する選択肢のみをクエリへ付与する。

## 業務ルール・計算

本機能自体は画面上で価格を再計算しない。一覧は DB の履歴値をそのまま数値または空表示に近い形で出力するのみである。

複合キーワードは共通関数により半角／全角スペースおよびカンマでトークン化され、トークンごとに複数カラムの部分一致および、数値条件を満たす場合のみ商品本体の整数主キー完全一致を OR で足し込む規則に従う。トークンの最大長チェックなどは共通関数側の規則による。

検索側の変更後／変更前の別ではなく変更後側の現在値にのみレンジが掛かるため、変更前のみに値がある履歴より、変更後側が NULL の行は売買単独のレンジ指定では結果から落ちやすい（SQL の NULL と比較は真にならない）。

### 入力項目

| 項目名 | 必須／任意 | 最大長 | 初期値 | 保存先・扱い |
|--------|------------|--------|--------|----------------|
| 商品名（日/英）・カード名（日/英）・商品 ID・商品コード | 任意 | テキストフィールドおよび共通関数の規則に従う（トークン化・部分一致対象複数）。 | 空白 | `multi` が空で無いとき共通関数により `dtb_product`、`dtb_product_class`、`dtb_card`、`mtb_card` 側の名前・コード・整数 ID と OR 結合。セッションの検索ビューデータに保持。フォーム側 CSRF は無効。 |
| 日付（履歴の登録レンジ） | 任意 | 日単位ウィジェット。 | 両方とも空 | `date_from` 以上および `date_to` の翌日未満（`modify('+1 days')` される）として `dtb_price_history.create_date` に適用。`date_to` 単独では当日終端が翌日頭で打ち切られる。セッション保持。ラベル翻訳は「日付」が使われる。 |
| 商品カテゴリ | 任意 | 複数選択。 | Placeholder が「すべての商品」（マスタ一覧）。 | `dtb_product.ProductCategories` 経由の inner join と DISTINCT。選択が空で無いときだけ。セッション保持。 |
| 表示ステータス | 任意 | チェックグループ複数選択。 | 既定値が公開表示と非表示グループ由来のセット（廃止はクエリ側で除外）。 | `dtb_product.Status` が IN。入力は検索ビューデータとしてセッションに保存される。 |
| エキスパンション | 任意 | 複数選択。 | 空 | `mtb_cardset` 側が IN。入力は検索ビューデータとしてセッションに保存される。 |
| レアリティ | 任意 | チェック複数選択。 | 無指定 | `mtb_rarity` が IN。入力は検索ビューデータとしてセッションに保存される。 |
| 言語 | 任意 | チェック複数選択日本語／英語／その他コード。 | 無指定。「その他」は定数リストに無いものへ `NOT IN`。 | 規格レコードに紐づく言語識別子が条件になる。入力は検索ビューデータとしてセッションに保存される。 |
| 状態（NM〜その他の区分） | 任意 | チェック複数。 | コード定数一覧のうち NM 単体既定 | 規格側の状態識別子が IN。未選択時との差はマスタ側既定値による。入力は検索ビューデータとしてセッションに保存される。 |
| 箔種別（一般 UI 文言） | 任意 | チェック複数。 | 無指定 | `mtb_card_detail.foil_flg` が IN。入力は検索ビューデータとしてセッションに保存される。 |
| プロモ | 任意 | 「プロモ／ノーマル」のチェックグループ複数になるが、共通関数では配列長 1 のときだけ `promotion_flg` 条件になる。 | 無指定または単一のみ解釈 | 複数チェック状態は「条件付与無し」の挙動に近い。入力は検索ビューデータとしてセッションに保存される。 |
| 基準価格（変更後側のレンジ） | 任意 | 価格列。アプリ共通 `eccube_price_len`。設定値確認例として `eccube.yaml` では 8 桁運用記述あり。 | 空 | `ph.standardPrice` が下限および上限それぞれ指定時のみ。整数キャスト。入力は検索ビューデータとしてセッションに保存される。ラベルは「基準価格」。 |
| 販売価格（変更後側のレンジ） | 任意 | 同上。 | 空 | `ph.sellPrice`。NULL 行は比較で落ちやすい。セッション保持。 |
| 買取価格（変更後側のレンジ） | 任意 | 同上。 | 空 | `ph.buyPrice`。同上。セッション保持。 |

補足: 商品詳細検索の型が持ち合わせているが当テンプレートでは見せていない入力は多数ある。クエリだけを見た場合トップレベルでセッションに残り得る `product_id` や `code` は、共通の組みクエリ関数からは読まれない。セッションキーへの格納はするが一覧の絞り込みへは載らない（実装を確認値とする）。

### エッジケース

| ケース | 扱い |
|--------|------|
| 履歴レコードが買取のみ変化 | `sell_price` が NULL のまま。販売価格下限を指定すると当該行はヒットしない。 |
| 履歴レコードが販売のみ変化 | 買取下限指定で同様。 |
| セッション未初期化で CSV を叩く | リダイレクトとフラッシュエラー文言固定。 |
| ソート欄への不正値 | HTTP 並びクエリにより `ASC`/`DESC` 以外が来たときトレイトがエラー翻訳キーを積んで初期一覧へループ代入呼び出しで戻る。 |
| 表示件数に未知の値 | セッション保持値および設定既定へフォールバックし、既知リストに合わせ直す。 |

## データ整合性

| 観点 | 内容 |
|------|------|
| 一覧と CSV | 入力条件およびセッションの検索ビューデータが同一ならクエリ構成は同等（エクスポートは iterate のため順序や遅延ロードタイミングは別）。 |
| 変更前後の値 | 履歴行ごとに片側のみ NULL の列があり得る。一覧は Twig でそのまま描画されるため画面上は空セルになり得る。CSV は空セルと文字列整数の切替関数で空文字に落とす。 |
| 同時更新 | 検索中に他利用者が価格変更しても一覧は読取時点のスナップショットであり、自動更新はしない。 |

## DBカラム

当機能では主に参照する論理構造のみ列挙する。型細部はスキーマ定義およびマイグレーションを正とする。

| テーブル | 列 | メモ |
|----------|-----|------|
| `dtb_price_history` | `product_class_id` | 規格単位での履歴所有者。JOIN の起点。 |
| `dtb_price_history` | `sell_price` `old_sell_price` `buy_price` `old_buy_price` `standard_price` `old_standard_price` | 変更後が NULL を許し、共通レンジ条件は変更後のみを見る。 |
| `dtb_price_history` | `member_id` | 登録者。左結合済み一覧で名前表示。 |
| `dtb_price_history` | `create_date` | 登録順ソートおよび日付レンジ。 |
| `dtb_product_class` | `code`、`memo`、`language`、`card_condition` に対応する列 | CSV・一覧での表示に使う。 |

### DB操作

本機能は参照系（検索）であり、DBへの登録・更新・削除は行わない。テーブル名は ec-cube-enterprise を正典とする。

| 操作種別 | 対象テーブル | 契機・条件 |
|---------|--------------|------------|
| 検索 | dtb_price_history / dtb_product_class | 検索条件に合致するレコードを抽出する。 |

| 条件 | 遷移先 |

| ナビまたは URL で初期一覧 | 同一機能内の検索フォームのみ。 |
| 「検索」送信成功 | POST 送信先は `search/1`。同一機能内で HTML を返す。 |
| ページリンク | `search/{page_no}` で同一機能内で HTML を返す。 |
| CSV がセッション未設定 | HTTP リダイレクトで初期一覧ルートへ遷移。 |
| 並びクエリ異常終了処理 | HTTP リダイレクトおよびエラー系フラッシュで検索フォームが再描画される経路となる。 |

### 遷移時に引き継ぐ状態

| 起点 | 遷移前の処理 | 遷移後の初期状態 |
|------|---------------|---------------------|
| 検索送信後のページリンク | `eccube.admin.product.buy_sale_price_history` プリフィクスで始まるセッション変数へ、検索ビュー・並び・ページ番号・表示件数などが書き込まれる。 | 次ページでも同じ条件に基づく結果が返る。 |
| 他画面などからクエリのみ付いた GET | GET クエリの `product_id` または `code` が、セッション上の検索ビューのトップレベルへ追記される。 | 共通の履歴クエリ関数はそれらキーを読まないため一覧の実質的絞り込み条件には載らず、復元済み入力と組み合わさったままとなる。URL のページャー側はクエリへ `product_id` / `code` を付け直すテンプレート記述のみある（実装を確認値とする）。 |

## 試行制限

本機能ではレートリミットをサーバ機能としては設けない（実装コード上のカウント制限処理はない）。

---

## ログ・監査

本機能専用の追加監査イベントはソース上は目立たない。CSV 処理は共通 CSV サービスに準じる。

### ログに出してはいけないもの

- パスワード
- なりすまし対策トークンの原値
- Cookie の値およびセッション ID の全桁
- カード所有者・利用者住所など本画面に無い項目を無闇にログへ増やさない運用規範は別資料を正とする

---

## セッション

### 本機能におけるセッション

セッションキー接頭辞は `eccube.admin.product.buy_sale_price_history`。続くサフィックスとして検索本体配列、`page_no`、`page_count`、並び項目名、並び昇降がトレイト内の文字列で固定される。

| 観点 | 内容 |
|------|------|
| 送信成功時およびページ移動後 | `search` に相当するキーへ検索ビューやページ関連キーを更新する。 |
| 検索状態が無い状態で CSV に直接アクセス | `search` に相当する値が無いと CSV は拒否応答となり転送される。 |

### セッションへ保存しない情報

画面上の入力以外のブラウザ全般や外部計測用トークンの保存処理はコード上はしない。

---

## Cookie

Symfony によるセッション用 Cookie の共通仕様のみ。本機能だけの独自 Cookie は置かない。

---

## 排他制御・トランザクション

本機能は一覧参照およびストリーム CSV の読取が主であり画面から履歴へ書き込まない。悲観的ロックなどは行わない。

### HTTPルート名とパス（コード探索用・旧入口節より退避）

- `m03-23_admin_product_product_buy_sale_price_history` … `GET` … `/{admin_route}/product/buy_sale_price_history`（検索フォームのみの初回表示。一覧表は用意されず、`pagination` が空のとき「該当なし」のメッセージ相当が出る構造となる。）
- `m03-23_admin_product_product_buy_sale_price_history_search` … `GET, POST` … `/{admin_route}/product/buy_sale_price_history/search/{page_no}`（検索送信（フォームは 1 ページ目向け）、ページャーによるページ移動、`page_count` による表示件数切替、`product_id` または `code` のクエリ付きでの再開。）
- `m03-23_admin_product_product_buy_sale_price_history_export` … `GET` … `/{admin_route}/product/buy_sale_price_history/export`（現在セッションに保存済みの検索ビューデータと同一条件での CSV ストリーム出力。検索済みセッションが無いときはフラッシュエラーつきで一覧初期 URL へリダイレクトする。）
