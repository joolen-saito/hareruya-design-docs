# 商品管理 — 商品規格一覧

管理画面「商品管理」配下から到達する、特定商品に紐づく商品規格を一覧表示し、規格ごとの編集へ遷移する画面である。コアの一覧と、公開状態が「廃止」の規格のみを並べた折りたたみブロックを分ける。EC-CUBE Enterprise のコントローラと Twig、および商品規格用レポジトリのクエリが確認値となる。

## 概要

単一商品 ID をパスで受け取り、その商品に属する規格を2系統の表で読み取り専用に表示する。上部カードには商品名、「新規登録」により規格新規入力画面へ進む。その下の一覧はクエリ側で公開状態および言語・カード状態の NULL により絞られた集合であり、並び順は実装既定に従う。

本書は実装手順ではなく、誰が・いつ・どの条件で・結果どうなるかを読むためのリバース詳細設計とする。
既存実装のふるまい、参照するデータ、判定境界、副作用、拡張による差し替え可能性を確認し、仕様の確からしさを把握することを目的とする。

本機能のカスタマイズ区分はカスタマイズである。画面・処理の挙動は現行リポ（pf-eccube3）の実装を参照し、DB関連（テーブル名・列名・参照関係）は ec-cube-enterprise を正とする。

対象はブラウザ経由の管理画面における商品規格一覧表示に限定する。規格の新規作成・編集・削除・規格行列の初期化、商品本体の編集、その他一覧画面とのことは別範囲とする。

コントローラのメソッド単位の解剖は本文の主題としない。本文ではルートbind名やSymfonyのルートnameの網羅は主説明としない。「利用者視点の入口」にHTTPメソッドとサイトルートからのパスパターンを書く。コード探索でbind名が必要なときだけ「調査補助」へ書く。

## リニューアル移行時の扱い

一覧の抽出条件（公開状態が廃止以外か否か、カード状態・言語が非NULL）と並び順自体は現行と移行先で同等だが、規格に紐づく属性の永続化先スキーマが異なる。

| 観点 | 現行（pf-eccube3） | 移行先（ec-cube-enterprise） |
|------|--------------------|------------------------------|
| 規格本体 | `dtb_product_class` | `dtb_product_class` |
| 言語・カード状態の参照 | 補助表 `dtb_product_sub_class` の `language_id`・`card_condition_id` | `dtb_product_class` の `language_id`・`card_condition_id` に統合（補助表は廃止。実在確認済み） |
| 公開状態 | 規格側マスタ参照（廃止＝マスタ値 3） | 同一の判定値（マスタ値 3） |

移行先では補助表 `dtb_product_sub_class` が廃止され、言語・状態・各価格などの列は `dtb_product_class` に統合される。一覧が読む列名は移行先では `dtb_product_class` 側になる。基本設計が描く本機能固有の追加仕様は無い。

## 処理フロー

### アクティブ一覧と廃止一覧を表示する（GET または POST `admin_product_product_class`）

1. 管理者が規定のアクセス経路により当パスへ到達する。
2. システムはパス `{id}` から親商品エンティティを解決する。存在しない場合は応答が 404 となる。
3. アクティブ集合は次をすべて満たす規格行から取得する実装確認値となる。親の商品 ID が一致する、`dtb_product_class` 左相当の規格側の公開状態関連がマスタ値「廃止」と一致しない、かつ規格側のカード状態参照が NULL でない、かつ規格側の言語参照が NULL でない。
4. 廃止集合は親の商品 ID が一致する、規格側の公開状態関連がマスタ値「廃止」と一致する、かつカード状態参照および言語参照が NULL でない規格から取得する実装確認値となる。
5. 取得した両集合を Twig に渡し、件数および表をレンダする。件数ヘッダの個数はアクティブ集合の要素長と一致する実装となる。
6. `return_product_list` クエリが真と解釈される値であれば、フッタ左の戻りリンク先が商品一覧になり、クエリに `resume=1` が付く。そうでなければフッタ左は商品編集の URL となる。

## 集計条件

| 指標 | 集計の要点 |
|------|------------|
| アクティブ一覧に含めるか | `dtb_product_class` 相当の親商品 ID と一致すること。規格側の関連する公開状態マスタの主キーが定数値 3 と等しくないこと（NULL が付いた行は、この不等号条件により WHERE から外れる結果になる）。規格側のカード状態外部キーと言語外部キーが両方とも非 NULL（内部結合側の要件）。 |
| 廃止一覧に含めるか | 親商品 ID と一致し、規格側の関連する公開状態マスタが定数値 3 と一致し、同上の NULL でないフィルタを満たすこと。 |
| 画面上の並び順 | アクティブ・廃止とも、アルゴリズム順に言語昇順（実体の join 済みオブジェクト昇順として付与されている）、続いてカード状態昇順、続いて規格側の売価列降順、規格側の主キー昇順となる実装確認値となる。 |
| 「検索結果」件数 | アクティブ集合の PHP 配列長をそのまま翻訳のプレースホルダに渡すため、アクティブに含まれない規格および廃止ブロックのみの規格は数に入らない。 |

規格側の `visible` フラグによる除外はクエリになく、非表示規格でも上記状態・NULL フィルタを満たせば両表どちらかに載りうる。商品登録画面上の規格ミニ一覧は `visible` で絞っている別テンプレート経路であり、両者の載る行集合は同一であると断言しない。

## 一覧表示時の列と値の対応（閲覧専用）

画面上の項目名と永続データの読み筋を表で示す。ラベルの正確な和文・英訳はロケールのメッセージリソースが正であり、一覧で翻訳キーを直接表示していない項目（スマレジの ON と OFF）は字形がソース字面に従う。

| 列の見出し（ロケール上の論理ラベル） | ソース上の読み筋 |
|--------------------------------------|------------------|
| 公開状態（アクティブ表のみ） | 規格の公開状態関連があれば名前、無ければ空文字連結。マスタ未定義との組合せにより空セルになりうる。 |
| 言語 | 言語マスタがあれば `nameJp`。無ければ空。 |
| 状態 | カード状態マスタがあれば `code`。無ければ空だがクエリは非 NULL で寄せている。 |
| スマレジ連携フラグ（アクティブ表のみ） | フラグが真なら Twig 字面で `ON`、偽なら `OFF`。 |
| 商品コード | 規格のコード列値。未設定または空値相当ならセル空白。 |
| 在庫数 | `stock_unlimited` が真ならロケールの「無制限」短文。偽なら在庫数を表示するが Twig は null または偽値相当を 0 数字に読み替えているため、画面上は 0 以上の整数になる。 |
| 販売制限数 | 設定があれば数値として表示するが、 Twig は偽評価のとき空文字となる。 |
| 基準価格・販売価格・買取価格（円系ラベル） | それぞれ規格側の標準価格、売価、買取列。 Twig は未設定または偽相当のとき空セルとなり、それ以外は `number_format`。 |

## 業務ルール・計算

本機能は規格一覧の参照表示のみであり、`### 入力項目` に相当する画面上の入力と永続書き込みの対応は持たない。税額・割引計算などの算出も行わない。

---

## データ整合性

- リストの両表は一覧表示時点のクエリ結果にのみ依拠し、画面上で数値や名称をユーザーが編集する手段は無い。そのため一覧表示中は永続データと表示のずれは、他セッションの更新または同一利用者による別タブ・別画面の変更があった場合にのみ生じうる。
- アクティブと廃止に二重計上しない。各行は規格側の公開状態値がマスタ値 3 と等しいか否かにより一方のみに載るクエリとなる。
- 規格側の公開状態または言語またはカード状態がクエリ要件を欠く行は両表ともに載らず、画面上も件数にも含まれない。

| 観点 | 内容 |
|------|------|
| トランザクション境界 | 本機能は参照・出力を主とし、業務データ更新用の明示トランザクションを開始しない。ロールバック対象となるDB更新を持たない。 |
| ロック | 行ロック・悲観ロック・楽観ロック・ロックファイルを使用しない。出力中の同時更新は読み取り時点の値に依存する。 |
| 例外時 | 出力または表示処理中に例外が発生した場合、未送信の出力は完了しない。DB更新のロールバック対象は無い。 |
