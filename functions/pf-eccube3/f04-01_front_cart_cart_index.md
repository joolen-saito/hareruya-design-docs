# F04-01（買い物かご）

## 概要

買い物かご画面において、カートに入っている商品の一覧と数量・金額を表示し、数量更新・商品削除・カート一括削除・購入手続きへの導線を提供する機能である。受注の確定や決済は行わず、カートの内容を確認・調整する範囲に限定する。

本書は実装手順ではなく、誰が・いつ・どの条件で・結果どうなるかを読むためのリバース詳細設計とする。確認値はpf-eccube3（EC-CUBE3系）のHareruyaEcプラグインの買い物かご処理、テンプレート（`Cart/index.twig`）、カートサービスを正とする。

本機能のカスタマイズ区分はカスタマイズであり、挙動の確認は現行リポ（pf-eccube3）の実装を参照する。DB関連の記述はリニューアル移行先の ec-cube-enterprise を正とする。

対象はブラウザ経由のフロント（カート）に限定する。フロントのルートはロケールセグメント付きで提供され、サイトルートからのパスパターンは`/{_locale}`配下になる（`/{_locale}`はサービスプロバイダのマウントで決まる確認値）。

コントローラのメソッド単位の解剖は本文の主題としない。本文ではルートbind名の網羅を主説明とせず、「利用者視点の入口」にHTTPメソッドとサイトルートからのパスパターンを書く。コード探索でbind名が必要なときだけ「調査補助」へ書く。

---

## 本書で扱うこと

- 買い物かご画面の表示内容（商品一覧・単価・数量・小計・合計・送料無料案内）
- 数量の更新（再計算）と商品の削除、カート一括削除の挙動
- カートに商品を追加するXHR入口（外部からのカート追加API的経路）と数量増減
- 購入手続きへ進む際のカートロックと遷移
- 単一購入グループでないカート（同時注文不可）の判定と案内

---

## 本書で扱わないこと

以下は本書では仕様確定せず、実装または別機能の設計を正とする。

- ご注文方法指定・注文情報の入力・確認（F04-02 注文情報の入力・確認・注文を正とする）
- 注文確定〜購入完了（カートの決済〜購入完了機能を正とする）
- 入荷通知依頼の業務ルール詳細（マイページの入荷通知依頼一覧機能を正とする。本書はカート画面からの依頼XHRの挙動のみ触れる）
- 商品検索・商品詳細・おすすめ表示の内部仕様

## リニューアル移行時の扱い

買い物かごはセッションに保持し、永続化に関わるテーブルとしては商品規格 dtb_product_class、基本情報 dtb_base_info（送料無料金額・送料無料個数）、入荷通知依頼 dtb_product_request を参照する。これらは現行（pf-eccube3）と移行先（ec-cube-enterprise）で同一スキーマである。買い物かご画面からの入荷通知依頼XHRの登録・取消は入荷通知依頼テーブル dtb_product_request を更新するが、依頼上限・論理削除等の業務ルール詳細は入荷時通知（F03-07）を正とする。注文情報の入力・確認・確定は別画面（F04-02）を正とする。

## 利用者視点の入口

| 入口 | URLエンドポイント | 期待されるふるまい |
|------|--------------------|--------------------|
| 買い物かごを開く | `GET /{_locale}/cart` | カート内商品一覧・数量・金額・送料無料案内を表示する。購入グループが複数のときは同時注文不可の案内を表示する。 |
| 再計算（数量更新） | `POST /{_locale}/cart/update` | 入力した数量でカートを更新し、買い物かご画面へ戻る。数量0以下は当該商品を削除する。 |
| 商品の削除 | `PUT /{_locale}/cart/remove/{productClassId}` | 当該商品をカートから取り除き、買い物かご画面へ戻る。 |
| 数量を1増やす | `PUT /{_locale}/cart/up/{productClassId}` | 当該商品の数量を1増やし、買い物かご画面へ戻る。 |
| 数量を1減らす | `PUT /{_locale}/cart/down/{productClassId}` | 当該商品の数量を1減らす。0未満になる場合は削除し、買い物かご画面へ戻る。 |
| カート一括削除 | `GET /{_locale}/cart/clear` | カートの内容を全て空にし、買い物かご画面へ戻る。 |
| 購入手続きへ進む | `POST /{_locale}/cart/buystep` | 数量を更新し、追加メッセージが無ければカートをロックして注文情報入力へ遷移する。メッセージがあれば買い物かごへ戻る。 |
| カートに商品を追加（XHR） | `POST /{_locale}/cart/add` | 1商品をカートへ追加し、カート内容をJSONで返す。 |
| カートに商品を一括追加（XHR） | `POST /{_locale}/cart/add_bulk` | 商品の配列をカートへ追加し、カート内容をJSONで返す。 |
| カートに追加して表示 | `POST /{_locale}/cart/add_show` | 1商品を追加し、買い物かご画面へリダイレクトする。 |
| カート内容取得（XHR） | `GET /{_locale}/cart/get` | カート内容をJSONで返す。CORS用ヘッダを付与する。 |
| 入荷通知依頼（XHR） | `POST /{_locale}/cart/pushReceive` | 対象商品の入荷通知依頼を登録または取消し、結果をJSONで返す。 |
| プリフライト | `OPTIONS /{_locale}/cart/get`、`OPTIONS /{_locale}/cart/add` | CORS許可ヘッダを返して終了する。 |

数量の更新・削除・増減後はいずれも買い物かご画面（`GET /{_locale}/cart`）へ戻る。

| 観点 | 内容 |

| JS挙動 | 数量スピン、カート用JS、リターゲティング・おすすめ表示用JSをインクルードする。入荷通知依頼はXHRで結果メッセージを受け取る。 |
| モーダル・ポップアップ | 本画面専用のモーダルは持たない。 |

## 処理フロー

### 買い物かごを表示する（GET `/{_locale}/cart`）

1. カートサービスから購入グループを取得し、複数ある場合は同時注文不可のエラーをカートに追加し、フラッシュに購入グループ情報を保存する。
2. 基本情報の送料無料金額・送料無料個数を参照し、送料無料の到達状況（無料か、残り金額、残り個数）を求める。
3. カート内容・送料無料判定をテンプレートに渡して買い物かご画面を表示する。

### 数量を更新する（POST `/{_locale}/cart/update`）

1. 送信された数量配列を順に処理する。
2. 数量が1未満の商品はカートから削除する。
3. それ以外は当該商品の数量を指定値に設定して保存する。
4. 買い物かご画面へリダイレクトする。

### 数量を増減する（PUT `/{_locale}/cart/up`・`/{_locale}/cart/down`）

1. なりすまし対策トークンを検証する。
2. 増減処理を行い保存する。減算で0未満になる場合は削除する。
3. 例外時はリクエストエラーを追加する。
4. 買い物かご画面へリダイレクトする。

### 商品を削除する（PUT `/{_locale}/cart/remove/{productClassId}`）

1. なりすまし対策トークンを検証する。
2. 当該商品を削除して保存する。
3. 買い物かご画面へリダイレクトする。

### カートを一括削除する（GET `/{_locale}/cart/clear`）

1. カートを空にして保存する。
2. 買い物かご画面へリダイレクトする。

### 購入手続きへ進む（POST `/{_locale}/cart/buystep`）

1. 送信された数量でカートを更新する。
2. 販売個数制限超過などでフラッシュメッセージが追加された場合は、買い物かご画面へ戻りメッセージを表示する。
3. メッセージが無ければカートをロックして保存し、注文情報入力（ご注文方法指定）へ遷移する。

### カートに追加する（POST `/{_locale}/cart/add`・`/{_locale}/cart/add_bulk`・`/{_locale}/cart/add_show`）

1. リクエストボディまたはパラメーターから商品規格IDと数量を取り出す。
2. 商品をカートへ追加して保存する。追加失敗時はリクエストエラーを追加する。
3. `add`・`add_bulk`はカート内容をJSONで返す。`add_show`は買い物かご画面へリダイレクトする。

## 業務ルール・計算

| 項目 | 内容 |
|------|------|
| 行の金額 | 商品ごとの金額は単価×数量とし、カートアイテムの金額を表示する。 |
| 合計 | 合計（税込）はカートの合計金額を表示する。 |
| 送料無料判定（金額） | 送料無料金額が設定され、合計が無料金額以上なら送料無料とする。未満なら不足額を案内する。 |
| 送料無料判定（個数） | 送料無料個数が設定され、合計個数が無料個数以上なら送料無料とする。未満なら不足個数を案内する。 |
| 数量更新の下限 | 更新時に数量が1未満の商品はカートから削除する。 |
| 購入グループ単一性 | 購入グループが2つ以上になると同時注文できない。カート画面でエラーを表示する。 |
| カートロック | 購入手続きへ進む際にカートをロックし、注文処理中の整合を取る。 |

本機能は新規保存・更新のフォームを持たないため、保存対象の入力項目表は持たない。数量入力欄は更新・増減・削除の操作対象であり、新規データの登録項目ではない。

### エッジケース

| ケース | 扱い |
|--------|------|
| カートが空 | 空カートの案内を表示し、購入手続きボタンを出さない。 |
| 数量に0以下を入力して再計算 | 当該商品を削除する。 |
| 購入グループが複数 | 同時注文不可のエラーを表示する。購入手続きでメッセージがあれば買い物かごへ戻す。 |
| 入荷通知依頼が既登録 | 同一依頼が存在する場合は取消（削除）として扱う。 |

## DBカラム

機能に直接関係する範囲のみ記載する。型や一覧の細部はスキーマを参照する。

| テーブル | 列 | メモ |
|---------|-----|------|
| カート | （セッション保持） | カートはセッションに保持し、商品規格と数量を持つ。 |
| `dtb_product_class` | 商品規格 | 表示・追加・更新の対象。`product_class_id`で識別する。 |
| `dtb_base_info` | 送料無料金額・送料無料個数 | 送料無料案内の判定に用いる。 |
| `dtb_product_request` | 入荷通知依頼 | 入荷通知依頼XHRで登録・削除する。 |

### DB操作

永続化の正は ec-cube-enterprise（テーブル名・操作は ec-cube-enterprise を正典）。当ドメインは承認ワークフローを介さず persist/flush で直接確定する（承認ワークフローは在庫機能固有）。

| 操作種別 | 対象テーブル | 契機・条件 |
|---------|--------------|------------|
| 登録/更新 | dtb_base_info / dtb_product_class / dtb_product_request | 当機能が行う登録・更新で対象テーブルを直接保存する（不要な削除は含まない）。確定は persist/flush による即時反映。DB=ec-cube-enterprise を正典とする。 |

| 購入手続きへ進む（メッセージあり） | 買い物かご画面 |
| 「他の商品を見る」 | トップページ |
| カート追加（add_show） | 買い物かご画面 |

### 遷移時に引き継ぐ状態

| 起点 | 遷移前の処理 | 遷移後の初期状態 |
|------|--------------|------------------|
| 購入手続きへ進む | 数量を更新し、メッセージが無ければカートをロックして保存する | 注文情報入力側がロック済みカートを参照する |
| 購入グループ複数 | フラッシュに購入グループ情報を保存する | 買い物かご画面でエラーを表示する |

---

## エラー処理

| エラー内容 | 処理 |
|------------|------|
| カート追加・更新の例外 | リクエストエラーを追加し、JSON返却または買い物かご再表示する。 |
| 購入グループ複数 | 同時注文不可のエラーを表示する。 |
| 入荷通知依頼で対象商品が存在しない | 失敗メッセージをJSONで返す。 |
| 入荷通知依頼で未ログイン | ログインを促すメッセージをJSONで返し、参照元URLをセッションに保存する。 |

表示文言は表示メッセージ節を正とする。

---

## ログ・監査

| タイミング | 記録内容 |
|------------|----------|
| カート追加・加算・減算・削除の開始と完了 | 商品規格IDと数量の情報ログ。 |
| カート追加・増減のエラー | エラーメッセージの情報ログ。 |

### ログに出してはいけないもの

- なりすまし対策トークン
- Cookie値
- セッションIDの完全値

---

## セッション

### 本機能におけるセッション

| 観点 | 内容 |
|------|------|
| カート | 追加・更新・削除のたびに保存する。 |
| 購入グループ情報 | 複数購入グループ検出時にフラッシュへ保存する。 |
| 入荷通知依頼の参照元 | 未ログイン時に参照元URLを保存する。 |

### セッションへ保存しない情報

決済の機微情報はセッションへ保存しない。

---

## 排他制御・トランザクション

本機能では楽観ロック・悲観ロックを持たない。購入手続きへ進む際のカートロックは、注文処理中のカート確定を表す状態であり、データベースのロックとは別である。
