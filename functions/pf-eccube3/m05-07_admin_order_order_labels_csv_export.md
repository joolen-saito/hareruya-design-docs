# m05-07_admin_order_order_labels_csv_export（管理画面_受注管理_送り状CSV出力）

## 概要

管理画面の受注一覧、および出荷指示の編集画面から、チェックした行に対応する出荷単位の情報を固定レイアウトの CSV としてダウンロード応答で返す機能である。画面上のボタン文言は翻訳キー `admin.order.output_labels_Export` で「送り状出力」と表示される。コメントや情報ログでは「送り状CSV」と呼ばれる。列集合は `dtb_csv` や店舗の配送 CSV 設定とは無関係で、サービス内のヘッダー定数で固定される。

本書は実装手順ではなく、誰が・いつ・どの条件で・結果どうなるかを読むためのリバース詳細設計とする。ec-cube-enterprise のコア実装を確認値とする。

対象はブラウザ経由の管理画面に限定する。

本機能のカスタマイズ区分は現行踏襲である。現行挙動は pf-eccube3 のHareruyaEcプラグイン実装を参照し、リニューアル移行後の挙動とDBは ec-cube-enterprise を確認値とする。DB関連の記述は ec-cube-enterprise を正とする。

コントローラのメソッド名は本文の主題としない。本文ではルートbind名やSymfonyのルートnameの網羅は主説明としない。「利用者視点の入口」にHTTPメソッドとサイトルートからのパスパターンを書く。コード探索でbind名が必要なときだけ「調査補助」へ書く。

## 利用者視点の入口

| 入口 | URLエンドポイント | 期待されるふるまい |
|------|--------------------|---------------------|
| 受注一覧で行をチェックし「送り状出力」を押す | `POST /{admin_route}/standby/labels` | フォームに含まれる `ids[]`（出荷 ID）について、該当データがあれば 1 受注につき最大 1 データ行の CSV がダウンロードされる。 |
| 出荷指示編集で行をチェックし「送り状出力」を押す | `POST /{admin_route}/standby/labels` | チェック済み行から `data-shipping-id` を読み取り、同一名の hidden `ids[]` をフォームに付け足してから送信する。出荷 ID の列表が手順どおり送られる。 |
| 受注一覧でチェック無しのまま送信しようとする | （クリック時点で送信しない） | クライアントの `alert` で「チェックボックスが選択されていません」と返し、`preventDefault` する。 |
| `ids` が空または非配列でサーバに届く | `GET` または `POST` いずれも同エンドポイント | HTTP 404 応答となる。 |

出荷指示側のスクリプトは送信前に `$('#form_bulk').removeAttr('target')` する。受注一覧側は `target` を消さないため、直前の別操作で `form_bulk` に `target` が残っていると、ダウンロードの開き方が意図と異なる場合がある（実装を確認値とする）。

## 処理フロー

### CSV をダウンロードする（`admin_labels_export`）

1. 管理画面の認証・共通制約を通過する。
2. `set_time_limit(0)` で PHP の実行時間制限を無効にする。
3. リクエストから `ids` を取得する。配列でない、または空配列のとき HTTP 404 を返す。
4. エクスポート種別文字列 `labels` と `ids` を渡し、送り状 CSV 用エクスポータを呼ぶ。
5. エクスポータは `StreamedResponse` を生成する。コールバック内で共通の CSV エクスポートサービスを開き、UTF-8 の場合は BOM を付与する実装に従う。
6. ヘッダ行を `fputcsv` で 1 行書く。列名はサービス定数 `CSV_TYPES['labels']['header']` の順序どおりである。
7. 受注リポジトリの「ラベル CSV 用」取得処理に出荷 ID 配列を渡し、返った各行について `fputcsv` する。0 件のときはヘッダのみのファイルとなる。
8. ストリームを閉じる。
9. ファイル名は接頭辞 `labels_` と日時（`YmdHis`）と拡張子 `.csv` を連結する。
10. 応答ヘッダに `Content-Type: application/octet-stream` と `Content-Disposition: attachment; filename=…` を付与する。
11. リクエスト処理の流れのなかで情報ログに「送り状CSV出力完了」とファイル名が記録される。

### 不正なエクスポート種別をコードから渡した場合

1. エクスポータは例外を送出する。通常の受注画面からは種別文字列 `labels` 以外は呼ばれない。

## 集計条件

| 指標 | 集計の要点 |
|------|------------|
| 商品総重量 | 受注に結合した各受注明細について「商品マスタの重量 × 数量」を積み上げ、同一受注 ID でグループ化した合計値を 1 行に載せる。出荷 ID だけがクエリの絞り込み条件である。 |

---

## データ取得クエリの要点

- 受注を起点に、都道府県マスタ・会員・受注明細・商品・出荷・配送方法を結合する。
- 出荷の主キーが `ids` に含まれる行に限定する。
- 受注 ID でグループ化するため、同一受注に複数の出荷が `ids` に含まれる場合、SQL 上は 1 行に畳み込まれる。データ行の配送先などは受注に紐づく出荷コレクションの先頭要素を参照する実装であり、どの出荷 ID に対応する行かと一致しない場合がある（実装を確認値とする）。
- 受注明細と商品の内部結合のため、該当する明細が存在しない受注は結果に現れない。

---

## 出力列と値の対応（業務ルール）

ヘッダ行の並びは送り状CSV用エクスポータ内の固定配列どおりである。データ行は取得処理が同じ順序で `row` に値を追加する。

| 列名（ヘッダ） | 内容 |
|----------------|------|
| 注文番号 | 受注の注文番号。 |
| 注文金額合計 | 受注合計。 |
| 注文者氏名〜注文者電話番号 | 受注の注文者情報。電話は `tel01`〜`tel03` の連結。部署列は空文字固定。 |
| 贈り主氏名〜贈り主電話番号 | 注文者と同一の文字列を繰り返し立てる。部署列は空文字固定。 |
| 注文コメント | 受注メッセージ。 |
| 注文備考(社内用) | 受注備考。 |
| 備考(内部用) | 空文字固定。 |
| 注文確定日〜配送希望時間帯 | 注文日時、確定日時、受注に紐づく出荷日時、配送日・時間帯。日時は `Y/m/d H:i:s`、無ければ空。 |
| 商品金額合計 | 受注小計。 |
| 送料・送料(税抜) | いずれも受注の送料合計と同一値。 |
| 手数料・手数料(税抜) | いずれも受注の手数料と同一値。 |
| のし・ラッピング手数料、のし・ラッピング手数料(税抜)、送料・手数料税率 | 空文字固定。 |
| 配送先番号 | 数値リテラル `1` 固定。 |
| 荷物問い合わせURL | 空文字固定。 |
| 送り状No. | 空文字固定（追跡番号列はヘッダに存在するが値は埋めない）。 |
| 配送先氏名〜配送先電話番号 | 出荷のお届け先。部署名は空文字固定。電話は連結。 |
| 郵便種別 | 配送方法マスタの主キーがリポジトリ定義に存在するときだけマッピング値を立てる。例として ID `3` は `0`、ID `4` は `8`。それ以外は空。 |
| 発送方法 | 配送方法名。 |
| 発送先国コード | 出荷の国があれば 2 文字の国コード、無ければ空。 |
| 商品総重量 | クエリで集計した重量。 |
| 発送方法コード | 配送方法 ID がリポジトリの別マップに存在するときコード文字列、それ以外は空。例として ID `8` は `111`、`9` は `521`、`11` は `321`。 |

マップのキーはソース上は文字列だが、取得 ID は整数でも参照される（実装を確認値とする）。

## 業務ルール・計算

本機能では画面フォームからの永続化更新は行わない。CSV の値のうち税抜と思われる列に税込と同一数値を載せる部分はリポジトリ実装どおりであり、会計上の意味は本書で確定しない。

### 入力項目

| 項目名 | 必須／任意 | 最大長 | 初期値 | 保存先・扱い |
|--------|------------|--------|--------|----------------|
| （チェックボックスに紐づく出荷の選択） | 送信時は実質必須 | 文字数上限はフォーム上もサーバ上も専用制約なし（配列要素は出荷 ID の整数） | 受注一覧では各行の出荷 ID が `value`。 | POST パラメータ名 `ids[]`。未選択のままではクライアントで送信を止める。 |

本機能は店舗設定フォームの保存を持たない。一覧から渡るのはチェックされた出荷 ID の列表のみである。

### エッジケース

| ケース | 扱い |
|--------|------|
| POST の `ids` が空または非配列 | HTTP 404 応答。 |
| `ids` に存在しない出荷 ID のみが含まれる | データ行は 0 件となり、ヘッダのみの CSV を返す（エラーにしない）。 |
| 同一受注に複数出荷があり、複数 ID を同時に選ぶ | クエリは受注 ID で畳み込み、データ行は 1 行にまとまりうる。配送先などは受注に紐づく出荷コレクションの先頭参照に依存する。 |
| 受注に商品明細が無く結合に合わない | 結果セットに現れない。 |
| クライアントの `target` が前操作のまま残る（受注一覧） | 新しいタブや別ウィンドウでダウンロードが開く場合がある（実装を確認値とする）。 |

## データ整合性

| 観点 | 内容 |
|------|------|
| 一覧の表示値と CSV | CSV は実行時点で DB を再取得して組み立てる。一覧表示直後に別セッションでデータが変わっていれば CSV は変更後の内容となる。 |
| 出荷単位の一意性 | クエリは受注単位で畳み込む。複数出荷を同時に選んだ場合、出力される配送先は受注に紐づく出荷コレクションの先頭に依存し、選択した各行 ID との 1 対 1 対応は保証されない。 |
| 受注明細なし | 商品明細の結合に合致しない受注は行として返らない。 |
