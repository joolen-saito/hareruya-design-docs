# バッチ 商品管理 — 在庫初期化

## 概要

指定した受注日の範囲の受注をたどり、各受注詳細の商品規格について、受注分の在庫減算を表す在庫履歴を作成するバッチである。コマンドライン（コンソールコマンド）から実行する。在庫履歴が整っていない時点の受注について、受注前の最新在庫を基準に受注後在庫を算出し、初期の在庫履歴を作成する位置づけである。

本書は実装手順ではなく、誰が・いつ・どの条件で・結果どうなるかを読むためのリバース詳細設計とする。確認値はpf-eccube3（EC-CUBE3系）のHareruyaEcプラグインの商品バッチ（在庫履歴作成処理）、受注・受注サブ・在庫履歴を扱うリポジトリを正とする。本機能のカスタマイズ区分はカスタマイズであり、現行挙動はpf-eccube3を参照し、DB関連の記述はec-cube-enterpriseを正とする。

対象はコンソールコマンドであり、ブラウザ経由の画面を持たない。

本文ではフレームワークのコマンド型名やサービス型名を主説明としない。実行はコンソールのバッチコマンドで行う。

---

## 本書で扱うこと

- バッチの起動方法（コンソールコマンドと開始日・終了日の引数）
- 受注日範囲の受注から在庫履歴を作成する条件
- すでに登録済みの在庫履歴の重複登録防止
- 引数不足・対象が無い場合の挙動

## 本書で扱わないこと

以下は本書では仕様確定せず、実装または別機能・運用の設計を正とする。

- 受注・受注詳細そのものの作成（受注処理を正とする）
- 通常の入庫・在庫反映による在庫履歴の作成（入庫処理・在庫反映処理を正とする）
- 期間別入庫数の集計（別バッチの設計を正とする）
- バッチの起動スケジュール（運用・ジョブ設定を正とする）

## リニューアル移行時の扱い

挙動は現行（pf-eccube3）を踏襲し、DB関連の記述は移行先（ec-cube-enterprise）を正とする。受注詳細と在庫履歴のスキーマが次のとおり異なる。

| 観点 | 現行（pf-eccube3） | 移行先（ec-cube-enterprise） |
|------|--------------------|------------------------------|
| 受注詳細テーブル | `dtb_order_detail` | `dtb_order_item`（列 `product_class_id`・`quantity`・`price` は同名） |
| 在庫履歴の商品規格参照 | `dtb_stock_history.product_class_id`（直接保持） | `dtb_stock_history.product_stock_id` 経由で在庫 `dtb_product_stock.product_class_id` を参照 |
| 在庫変動区分 | `dtb_stock_history.stock_change_type_id`（受注） | `dtb_stock_history.stock_change_type_detail_id` と `history_source_type` に分かれる |
| メモ列 | `dtb_stock_history.memo`（注文番号・価格を含む文言） | `dtb_stock_history.stock_change_reason`（在庫変動理由(備考)） |

重複登録防止に用いるメモ文言の一致判定は、移行先では `stock_change_reason` を対象とする。在庫減算の区分への対応はec-cube-enterprise実装で要確認とする。

## 用語

| 用語 | 説明 |
|------|------|
| 在庫履歴 | 商品規格ごとの在庫変動を記録するレコード。変動前後の在庫・変動区分・メモを持つ。 |
| 受注分の在庫減算 | 受注により在庫が減ったことを表す在庫変動。変動区分は受注。 |
| 最新在庫履歴 | 対象受注の受注日より前で最も新しい在庫履歴。基準在庫として参照する。 |

---

## 利用者視点の入口

| 入口 | 実行方法 | 期待されるふるまい |
|------|----------|--------------------|
| コンソールのバッチコマンド | `product:batch insertStockHistory <開始日> <終了日>` | 指定した受注日範囲の受注をたどり、受注分の在庫減算の在庫履歴を作成する。 |

本機能はHTTPで届く画面を持たない。コマンド名が一致しない場合は処理を行わずに終了する。開始日・終了日の2引数が無い場合は、その旨を出力して処理を行わずに終了する。

---

## 処理フロー

### 在庫初期化を実行する（`product:batch insertStockHistory <開始日> <終了日>`）

1. 引数が2つ未満の場合は、開始日と終了日の指定を促すメッセージを出力して終了する。
2. 引数の開始日・終了日を日時として解釈し、その範囲の受注を受注日の昇順で取得する。
3. 受注ごとに受注サブを取得し、受注詳細を順にたどる。
4. 受注詳細の商品規格について、受注日より前の最新在庫履歴を取得する。
5. 最新在庫履歴が無い商品規格は処理をスキップする。
6. 注文番号と価格を含むメモを生成し、同じ商品規格・同じメモの在庫履歴がすでに登録済みなら、その旨を出力して次へ進む。
7. 未登録の場合、最新在庫を基準に受注数量を減算した在庫履歴を作成し、登録結果を出力して反映する。

## 業務ルール・計算

| 項目 | 内容 |
|------|------|
| 対象 | 引数の開始日・終了日の受注日範囲に含まれる受注の受注詳細。 |
| 基準在庫 | 受注日より前の最新在庫履歴の在庫。これが無い商品規格はスキップする。 |
| 受注後在庫 | 基準在庫から受注詳細の数量を減算した値。 |
| 変動区分 | 受注（在庫減算）として登録する。 |
| メモ | 注文番号と価格を含む受注減算用の文言を設定する。 |
| 重複防止 | 同じ商品規格でメモに同一文言を含む在庫履歴が存在する場合は登録しない。 |

---

## API・バッチ結果

| 種類 | 内容 |
|------|------|
| 入力 | コマンド名と開始日・終了日の2引数。 |
| 実行条件 | 開始日・終了日の2引数が指定され、範囲内に受注が存在し、対象商品規格に基準となる最新在庫履歴があること。 |
| 成功結果 | 未登録の受注詳細について受注分の在庫減算の在庫履歴が作成される。 |
| 失敗結果 | 引数不足時はメッセージを出力して何もしない。途中失敗時は登録済みの行のみ残る。 |
| 再実行時 | 商品規格とメモ文言による重複判定で、すでに登録済みの在庫履歴は再登録しない。 |

---

## 入出力

| 種類 | 内容 |
|------|------|
| 入力 | コマンド名、開始日、終了日。 |
| 成功時出力 | 受注分の在庫減算の在庫履歴の作成。処理経過のコンソール出力（受注ID・受注詳細ID・商品名）。 |
| 失敗時出力 | 引数不足メッセージ、または例外時のエラーメッセージのコンソール出力。 |
| 副作用 | 在庫履歴の追加。 |

---

## データ整合性

| 観点 | 内容 |
|------|------|
| 多重実行 | ロックは持たない。重複登録は商品規格とメモ文言の一致判定で防ぐ。 |
| 途中失敗・再実行 | 在庫履歴は受注詳細ごとに反映する。再実行しても登録済みの行は重複判定でスキップされ、未登録の行のみが回収される。 |
| 参照時点 | 基準在庫は受注日より前の最新在庫履歴を参照する。実行順は受注日の昇順。 |

## DBカラム

機能に直接関係する列のみ記載する。型や一覧の細部はスキーマを参照する。

| テーブル | 列 | メモ |
|----------|-----|------|
| `dtb_order` | `order_date` | 引数の範囲による受注抽出と基準在庫の判定に使用する。 |
| `dtb_order_item`（現行 `dtb_order_detail`） | `product_class_id`・`quantity`・`price` | 対象商品規格・減算数量・メモの価格に使用する。 |
| `dtb_stock_history` | `stock`・`old_stock`・`sell_price`、商品規格は `product_stock_id` 経由（現行 `product_class_id` を直接保持）、`stock_change_type_detail_id`（現行 `stock_change_type_id`）、`stock_change_reason`（現行 `memo`） | 作成する在庫履歴の各値。変動区分は受注（在庫減算）。 |
| `dtb_stock_history` | `create_date` | 受注日を作成日として登録する。 |

### DB操作

永続化の正は ec-cube-enterprise（テーブル名・操作は ec-cube-enterprise を正典）。当ドメインは承認ワークフローを介さず persist/flush で直接確定する（承認ワークフローは在庫機能固有）。

| 操作種別 | 対象テーブル | 契機・条件 |
|---------|--------------|------------|
| 登録/更新 | dtb_order / dtb_order_detail / dtb_order_item / dtb_stock_history | 当機能が行う登録・更新で対象テーブルを直接保存する（不要な削除は含まない）。確定は persist/flush による即時反映。DB=ec-cube-enterprise を正典とする。 |

## エラー処理

| エラー内容 | 処理 |
|------------|------|
| コマンド名が未指定・不一致 | 処理を行わずに終了する。 |
| 開始日・終了日の引数不足 | 指定を促すメッセージを出力して終了する。 |
| 基準在庫が無い商品規格 | 当該商品規格をスキップする。 |
| 重複登録 | すでに登録済みの旨を出力して次へ進む。 |
| 処理中の例外 | エラーメッセージをコンソールに出力する。 |

## ログ・監査

| タイミング | 記録内容 |
|------------|----------|
| 引数不足 | 開始日・終了日の指定を促すメッセージのコンソール出力。 |
| 登録済み検知 | 受注ID・受注詳細ID・商品名と登録済みの旨のコンソール出力。 |
| 在庫履歴登録 | 受注ID・受注詳細ID・商品名のコンソール出力。 |
| 開始・完了 | 開始・完了のコンソール出力（日時付き）。 |

### ログに出してはいけないもの

- パスワード
- トークン・接続秘密値
- Cookie値・セッションIDの完全値

---

## 排他制御・トランザクション

ロックファイルによる多重起動防止は持たない。在庫履歴は受注詳細ごとに作成して反映する。重複登録は商品規格とメモ文言の一致判定で防ぐ。本バッチは楽観ロック・悲観ロックの対象を持たない。
