# m03-26_admin_product_product_card_csv_import（管理画面_商品管理_カード商品CSV登録）

## 概要

管理画面の「商品管理」→「商品CSV管理」→「カード商品CSV登録」から開く画面で、カード詳細に紐付く商品および規格・関連マスタを CSV で一括登録または更新する機能である。雛形 CSV の 1 行目は日本語の列見出しであり、商品一覧から出力する「カード商品CSV出力」（別ルート）と同一の列集合・並びを前提とする。

本書は実装手順ではなく、誰が・いつ・どの条件で・結果どうなるかを読むためのリバース詳細設計とする。確認値は EC-CUBE Enterprise の `src/Eccube` 配下とする。

本機能のカスタマイズ区分はカスタマイズである。現行挙動は pf-eccube3（HareruyaEc プラグイン）を参照し、永続化に関わるテーブル名・列名などのDB関連は ec-cube-enterprise を正とする。

対象はブラウザ経由の管理画面に限定する。

コントローラのメソッド名は本文の主題としない。本文ではルートbind名やSymfonyのルートnameの網羅は主説明としない。「利用者視点の入口」にHTTPメソッドとサイトルートからのパスパターンを書く。コード探索でbind名が必要なときだけ「調査補助」へ書く。

## 処理フロー

### アップロード画面を表示する（GET `m03-26_admin_product_product_card_csv_import`）

1. 管理画面の認証・共通制約を通過する。
2. 管理者向け CSV 取込フォーム種別の空フォームを組み立て、リクエストをバインドする。
3. クエリ `page_count` が許容リストに含まれる場合のみセッションキー `admin.product.product_card_csv.page_count` に保存する。含まれない場合はセッション値または既定 10 を採用する。
4. `page_no` はクエリまたはセッション `admin.product.product_card_csv.page_no` から決め、セッションへ書き戻す。
5. 取込種別がカード商品 CSV の履歴だけを対象とするクエリビルダをページネーションし、テンプレートへ渡す。

### 雛形をダウンロードする（GET `admin_product_card_csv_template`）

1. 管理画面の認証・共通制約を通過する。
2. 静的メソッドが返す「列見出し→説明文」の連想配列について、`array_keys` の並びで 1 行目だけを書いた CSV をストリーミング応答する。ファイル名は `product_card.csv`。`Content-Type` は `application/octet-stream`。

### CSV を取込む（POST `admin_product_card_csv_upload`）

1. `set_time_limit(0)` で PHP の実行時間制限を解除する。
2. ログイン利用者を取込処理の更新者として渡す前提を満たす。
3. 管理者向け CSV 取込フォーム種別を組み立てて送信をバインドする。妥当でなければフォームエラーをフラッシュに積み、`GET m03-26_admin_product_product_card_csv_import` へリダイレクトする。
4. `import_file` が null なら共通キー `admin.common.csv_invalid_format` をフラッシュし、同様にリダイレクトする。
5. アップロードファイル全文から、ダブルクォート内の改行を除いたうえでの改行数を数え、その値が抽象コントローラ定数 `ADMIN_CSV_IMPORT_MAX_ROWS`（5010）以上なら `admin.csv.error.upload.maxrecord` をパラメータ付きでフラッシュし、リダイレクトする。
6. 情報ログにカード商品登録 CSV 開始を書く。
7. 汎用インポータにハンドラを渡してファイルを取込む（詳細は次節）。
8. 返却結果にエラー配列が 1 件でもあれば情報ログに異常終了を書き、各メッセージをエラーフラッシュに積む。
9. エラーが無ければ成功フラッシュ（キー `admin.common.csv_upload_complete`）、完了ログ（件数付き）、取込履歴 INSERT（種別 ID はカード商品 CSV 用定数、ファイル名はクライアントオリジナル名、利用者 ID）を行う。
10. 常に `GET m03-26_admin_product_product_card_csv_import` へリダイレクトする。

### 汎用インポータ内部（確認値）

1. アップロードファイルを設定の CSV 一時ディレクトリへ移し、逐次読込できるファイルハンドルとして開く。拡張子が `tsv` のときはタブ区切り、それ以外は設定 `eccube_csv_import_delimiter` と `eccube_csv_import_enclosure` を使う。
2. 1 行目をヘッダとみなせなければエラー集合を返して終了する。ヘッダのみでデータ行が無ければエラー集合を返して終了する。
3. DB 接続でトランザクションを開始し、行ロックタイムアウトをハンドラが返す秒数（既定 5）に設定する。
4. データ行ごとに「列数一致」「各列の単体検証」「行単位検証」を通過させたうえでハンドラの行処理へ進む。100 行ごとに flush と clear を挟む（既定）。
5. 全行処理後、flush と clear を再度行う。
6. メッセージストアのエラー件数が 0 であるか、全体中断フラグが立っていないときだけコミットする。それ以外はロールバックする。
7. ハンドラの「取込後フック」を呼ぶ。成功時はこのタイミングで接続の commit が再度呼ばれる実装になっている（内部で保留されていた変更の取り扱いと整合させるため）。
8. 処理件数・エラー配列・情報配列を結果オブジェクトに載せて返す。

## 集計条件

本機能では売上集計や一覧件数の算出は行わない。履歴一覧は「CSV 取込種別がカード商品」の履歴行を時系列クエリでページングするだけである。

## 行処理時の判定順序（概要）

| 順序 | 判定 | 結果 |
|------|------|------|
| 1 | ヘッダ・データ行の存在 | 不備時はインポート開始前にエラー応答し DB は変更不要 |
| 2 | 各行の列数とヘッダ名 | 不一致や未定義列名時は全体中断 |
| 3 | 各列の必須・型・マスタ存在・複数値形式 | 失敗時は全体中断 |
| 4 | 販売価格と買取価格の大小 | 買取が販売を上回るとエラーで全体中断 |
| 5 | 更新モードかつ公開ステータスを廃止に変更するときの在庫有無 | 在庫が 1 件でも残っているとエラーで全体中断 |
| 6 | カード詳細 ID の検索 | 不存在はエラーで全体中断。複数件ヒットもエラーで全体中断 |
| 7 | 更新対象商品 ID の実在 | 指定があるのに不存在なら全体中断 |
| 8 | 同一カード詳細を別商品が既に保有 | メッセージを積み当該行はスキップ（後述のコミット条件により他行は反映され得る） |
| 9 | 新規商品かつ全状態の商品コード事前チェック | 重複があれば当該行スキップ |
| 10 | 規格保存での一意制約違反 | 例外によりロールバック対象になり得る |

### 価格・規格まわりの補足

- 販売価格・買取価格・基準価格は取込時に床関数相当で整数化される。
- 各カード状態について、既存規格があれば UPDATE、なければ INSERT とし、新規 INSERT 時は全店舗×在庫場所の在庫行を数量 0 で作成する。
- 既存規格がセールフラグ OFF のとき、CSV の基準価格がそのまま販売価格へ反映される。セールフラグ ON のときは販売価格は CSV より既存値が優先される。
- 販売／買取が変化した規格だけ価格履歴行を追加する（新規規格は常に履歴を追加）。
- ネイティブ SQL で規格を収集するとき、`high_price_code` が付いた高額品規格は結合対象外とする。

### エッジケース

| ケース | 扱い |
|--------|------|
| 全体中断フラグが付いた検証エラー | トランザクションはロールバックされ、結果オブジェクトにエラーが載る |
| 同一カード詳細を持つ別商品が既にいる（自分自身を除く） | エラーメッセージを積み当該行のみスキップ。中断フラグは立てない |
| 新規で生成予定の商品コードがいずれかの状態ですでに存在 | 同上（スキップ） |
| 取込結果オブジェクトにエラーが 1 件でもある | フラッシュはすべてエラー側のみで、成功メッセージと取込履歴 INSERT は行わない |
| 一部行のみスキップされ、かつ中断なしでコミットされた場合 | DB は成功行ぶん更新済みでも、画面はエラーのみを見せ、履歴にも残らない |
| インポータ内部で未捕捉例外 | ロールバック後に例外が再送出され、コントローラ側では成功／失敗フラッシュのどちらも付けないケースがあり得る |

## データ整合性

| 観点 | 内容 |
|------|------|
| 一覧との一致 | 画面は CSV のプレビューを保持しない。取込後は別画面の商品一覧などで確認する必要がある。 |

## DBカラム

（関連テーブル全体の列辞典ではなく、当機能が直接書き換えの起点となるものだけを挙げる。）

| テーブル | 列 | メモ |
|---------|-----|------|
| `dtb_product` | 複数 | 名称・説明・ステータス・割引・カード詳細 FK などを INSERT／UPDATE |
| `dtb_product_category` | 複数 | 商品に対するカテゴリ紐付けを置換 |
| `dtb_product_tag` 系 | 複数 | タグを置換 |
| `dtb_product_class` | 複数 | 規格・価格・コード・スマレジ関連列など |
| `dtb_product_stock` | 複数 | 新規規格時に初期 0 で増設 |
| `dtb_price_history` | 複数 | 価格変更の履歴 |
| `dtb_csv_import_history` | 複数 | 成功時のみ INSERT |

### DB操作

永続化の正は ec-cube-enterprise。商品系は承認ワークフローを介さず persist/flush で直接確定する（在庫の承認ワークフローとは別系統。`ProductController`・各CSVサービスで確認）。

| 操作種別 | 対象テーブル | 契機・条件 |
|---------|--------------|------------|
| 登録/更新 | dtb_csv_import_history / dtb_price_history / dtb_product / dtb_product_category / dtb_product_class / dtb_product_stock 等 | 当機能が行う登録・更新で対象テーブルを直接保存する（不要な削除は含まない）。確定は persist/flush による即時反映。DB=ec-cube-enterprise を正典とする。 |

## エラー処理

| エラー内容 | 処理 |
|------------|------|
| フォーム不正・ファイル未選択 | 該当キーをフラッシュしリダイレクト |
| 行数上限超過 | `admin.csv.error.upload.maxrecord` をフラッシュしリダイレクト |
| ヘッダのみ・列数不一致などインポータ事前検証 | 結果オブジェクト経由でエラーメッセージをフラッシュ |
| 行ごとの検証・業務エラー | メッセージを結果へ集約しフラッシュ（コミット可否は中断フラグとトランザクション節を参照） |

## Cookie

管理画面のセッション維持に用いる Cookie は、サイト全体のセッション設定に従う。本機能固有の Cookie は置かない。

## 排他制御・トランザクション

- インポータが DB トランザクションを張り、エラー状況に応じてコミットまたはロールバックする。
- 行ロックタイムアウトはハンドラの既定秒数に設定される。
- 楽観ロック版本機能は当 CSV 取込専用には実装されていない。
