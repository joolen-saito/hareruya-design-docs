# カード管理 — カード情報 CSV 出力

## 概要

HareruyaEc プラグインが管理画面の「カード管理」検索一覧から、チェックボックスで選んだカード ID を対象に、カードマスタおよびカード詳細に相当する列を並べた CSV ファイルをダウンロード応答として返す機能である。ヘッダ行は項目の論理キー（例: `name_jp`）であり、商品 CSV のように店舗設定で項目を並べ替える仕組みは使わない。

本書は実装手順ではなく、誰が・いつ・どの条件で・結果どうなるかを読むためのリバース詳細設計とする。pf-eccube3 に配置された HareruyaEc プラグインのソースを確認値とする。

本機能のカスタマイズ区分はカスタマイズである。現行挙動は pf-eccube3 の HareruyaEc プラグインを参照し、永続化に関わるテーブル名・列名などのDB関連は ec-cube-enterprise を正とする。

対象はブラウザ経由の管理画面に限定する。

コントローラのメソッド名は本文の主題としない。本文ではルートbind名やSymfonyのルートnameの網羅は主説明としない。「利用者視点の入口」にHTTPメソッドとサイトルートからのパスパターンを書く。コード探索でbind名が必要なときだけ「調査補助」へ書く。

## リニューアル移行時の扱い

DB関連の記述は ec-cube-enterprise の実装を正とする。出力が参照するカードマスタ・カード詳細・関連マスタは現行（pf-eccube3 の HareruyaEc プラグイン）と移行先（ec-cube-enterprise）で同一のテーブル名・列名であり、同一スキーマである。

| 観点 | 現行（pf-eccube3） | 移行先（ec-cube-enterprise） |
|------|---------------------|-------------------------------|
| カード共通列の源泉 | `mtb_card` | 同一スキーマ（`mtb_card`）。 |
| 行複製単位 | `mtb_card_detail` | 同一スキーマ（`mtb_card_detail`）。 |
| 関連マスタ・画像 | カラー・タイプ・フォーマット・固有色・`mtb_card_image`・プロモーション等 | 同一スキーマ。 |

出力列の論理キーと並びは現行挙動（pf-eccube3）を参照し、移行先でも同じカードマスタ構造を読む。

## 利用者視点の入口

| 入口 | URLエンドポイント | 期待されるふるまい |
|------|--------------------|---------------------|
| 検索結果が 1 件以上あり、一覧でカードをチェックして「CSV出力」を押す | `POST /{admin_route}/card/csvexport` | 選択したカード ID がフォームデータとして送られ、該当データの CSV がブラウザにダウンロードされる。 |
| 検索結果エリアが無い・件数ゼロ | （ボタン自体が描画されない） | CSV 出力ボタンは検索結果ボックス内にのみ配置されるため、この入口からは実行できない。 |

同一 HTML フォームの既定の `action` は検索用の `POST /{admin_route}/card/search/1` であるが、「CSV出力」ボタンは `formaction` で `m14-02_admin_card_card_csv_export` にだけ差し替えて送信する。

## フロント挙動

| 観点 | 内容 |
|------|------|
| 表示要素 | 「CSV出力」ボタンは検索結果ヘッダ付近にあり、`pagination.totalItemCount > 0` のときだけ表示される。各行に `name="cardIds[]"` のチェックボックスがある。表頭チェック `#allCheck` で `[cardId]` 属性を持つチェックボックスを一括オンオフする。 |
| JS 挙動 | 「CSV出力」クリック後、約 500ms は `type=submit` の `pointer-events` を空にして多重送信しにくくし、その後解除する。クライアント側で CSV の内容や件数は検証しない。 |
| CSS・レイアウト | 本機能専用の追加スタイルはない。 |
| モーダル・ポップアップ | 出力前の確認ダイアログはない。 |

検索フォームはカード検索機能側の実装どおり CSRF を無効にした型で生成されているため、「CSV出力」送信にも検索フォームと同じく CSRF トークンフィールドは付かない（一括削除ボタン側だけ別途トークンを抱える実装がある）。

## 処理フロー

### CSV をダウンロードする（POST `m14-02_admin_card_card_csv_export`）

1. 管理画面の認証・共通制約を通過する。
2. PHP の実行時間制限を無効にする（`set_time_limit(0)`）。
3. ORM の SQL ロガーを無効にする。
4. リクエストボディから `cardIds` を取得する（配列形式の `cardIds[]`）。
5. `cardIds` が PHP の `empty()` で真と判定される場合、サービス層はフラッシュにメッセージキー `admin.csv.error.export.card` を積み、`m14-01_admin_card_card_search` へリダイレクト応答を組み立てる。ページ番号はセッションキー `admin.card.search.page_no` があればそれを使い、無ければルート既定に委ねる。
6. コントローラは手順 5 の戻り値が「空」と判定された場合にのみ、別メッセージ `admin.csv.error.export.require` を積み `Referer` へ HTTP リダイレクトする。手順 5 がリダイレクトオブジェクトを返す場合、`empty()` は偽になり、この分岐には入らない実装順序になっている（実装を確認値とする）。
7. リポジトリで `id` が渡された集合に含まれるカードマスタを取得する。1 件も得られなければ `RuntimeException` とし、メッセージは翻訳キー `admin.csv.error.export.not_registered` を経由する。
8. 取得した各カードについて、共通列を配列で組み立てたうえで、紐付くカード詳細ごとに行を複製し、詳細固有の列を末尾に連結する。キーワード能力列は現状常に空文字を立てる。
9. `StreamedResponse` のコールバック内でコアの CSV エクスポートサービスを用い、開く・UTF-8 の BOM を書く・ヘッダ行（論理キーを `array_keys` で取得した順）・データ行を順に書き込み・閉じる。
10. ファイル名は接頭辞 `cards_` と日時（`YmdHis`）と拡張子 `.csv` を連結したものとする。
11. 応答ヘッダに CSV 向けの `Content-Type`（設定 `csv_export_encoding` に応じた charset。値が `SJIS-win` のときは `windows-31j` に読み替え）と `Content-Disposition: attachment` を付与する。
12. ストリーム送信後、情報ログにファイル名を記録する応答を返す（コールバック内で送信が走る実装になっている）。

### 取得 ID の一部のみ DB に存在するとき

1. 手順 7 の取得は「存在する ID 分」だけ返す。存在しない ID が混在しても、この段階ではエラーにしない。
2. すべての指定 ID が存在しなければ手順 7 の例外に至る。

### 変換中に `RuntimeException` が送出されたとき

1. コントローラはメッセージ文字列をフラッシュに積み、`Referer` へリダイレクトする。

## 出力列とデータの対応（業務ルール）

ヘッダ行の並びはコントローラ内の連想配列のキー順に依存する。データ行は同一順で値を並べる。

### カード単位で共通する列（カード詳細の反復ごとに同じ値が繰り返される）

| 論理キー | 内容 |
|----------|------|
| `name_jp` | カード名（日本語）。DB 値をそのまま出力する。 |
| `name_en` | カード名（英語）。 |
| `arena_format_name_jp` | アリーナ表示名（日本語）。 |
| `arena_format_name_en` | アリーナ表示名（英語）。 |
| `text_jp` | ルールテキスト（日本語）。 |
| `text_en` | ルールテキスト（英語）。 |
| `mana_cost` | マナコスト文字列。 |
| `cmc` | 点数で見たマナコスト。 |
| `power` | パワー。 |
| `toughness` | タフネス。 |
| `loyalty` | 忠誠度。 |
| `color` | 関連カラーを英名で読み、コンマで連結する（単一値ならコンマなし）。 |
| `cardtype` | カードタイプも同様に英名をコンマ連結する。 |
| `subtype` | サブタイプも同様。 |
| `specialtype` | 特殊タイプも同様。 |
| `keyword_ability` | 現行実装では空文字固定（ソースに TODO コメントがある）。 |
| `format` | カードに紐付くフォーマットを英名で読み、コンマ連結。 |

### カード詳細ごとに変わる列（1 詳細につき 1 データ行）

| 論理キー | 内容 |
|----------|------|
| `set` | セットの英名。未設定なら空文字。 |
| `rarity` | レアリティの英名。 |
| `illustrator` | イラストレータの英名。 |
| `layout` | レイアウトの英名。 |
| `flavor_jp` | フレーバー（日本語）。 |
| `flavor_en` | フレーバー（英語）。 |
| `card_no` | カード番号。 |
| `promotion` | プロモーションの英名。 |
| `foil_flg` | Foil フラグを整数キャストした値。 |
| `promotion_flg` | プロモフラグを整数キャストした値。 |
| `image_jp` | 画像コレクションのうち言語が日本語かつ表側の最初の要素の URL。無ければ空文字。 |
| `image_en` | 同上（英語）。 |

ソース上、`convertExportCsvRows` 末尾に「詳細なし」分岐があるが、代入先変数名などに不整合があり、実行経路によっては未定義変数参照や列数不足が起きうる。実装を確認値とし、詳細なしデータの運用可否はコードレビューと実行検証に委ねる。

## 業務ルール・計算

- 出力対象は画面・APIで確定した検索条件、権限、店舗・支店条件に一致するレコードに限定する。
- 金額・数量・日時・ステータスは参照時点の永続化済み値をそのまま出力し、CSV生成時に再計算・補正しない。
- 文字コード、列順、ヘッダ、空値表現は既存CSV仕様を正とし、該当値がない項目は空欄として扱う。
- 件数上限やページングの有無は呼び出し元の検索条件・既存実装に従い、出力途中で対象データが更新されても再読込による整合補正は行わない。

## データ整合性

| 観点 | 内容 |
|------|------|
| 一覧との対応 | 出力対象は一覧にチェックを付けたカード ID のみであり、検索でヒットした全件を自動では出力しない。 |
| 複数詳細 | 1 カードに複数のカード詳細があるとき、共通列は同一値のまま行が複製される。 |
| 指定 ID と返却件数 | POST に含まれるが DB に無い ID は静かに無視され、残りが空ならエラーとなる。 |
| 並び順 | リポジトリの `findBy` に依存し、利用者が一覧で選んだ順序の再現は保証しない。 |

## 入出力

| 種類 | 内容 |
|------|------|
| 入力 | `POST`。ボディに `cardIds[]`（整数文字列の配列）。 |
| 成功時出力 | `text/csv` のストリーム。ファイル名は `cards_YmdHis.csv` 形式。先頭に UTF-8 BOM。フィールド値は設定のエンコーディングへ変換したうえで `fputcsv` により出力され、区切り文字は設定 `csv_export_separator`。 |
| 失敗時出力 | フラッシュメッセージ付きで検索一覧または Referer へ HTTP リダイレクト（経路は実装どおり）。 |

## DBカラム

出力はエンティティ経由であり、参照される主なテーブルは次のとおりである。列の網羅と型はマッピングを参照する。

| テーブル | 列（概念） | メモ |
|---------|------------|------|
| `mtb_card` | 名称・テキスト・マナ・パワー／タフネス／忠誠度・色順など | カード共通列の源泉。 |
| `mtb_card_detail` | セット・レア・レイアウト・フレーバー・カード番号・フラグ・裏面 ID など | 行複製単位。 |
| 関連マスタ・中間 | カラー・タイプ・フォーマット・固有色・画像・プロモーション等 | 英名連結や画像 URL 解決に利用。 |

### DB操作

本機能は参照系（検索・出力）であり、DBへの登録・更新・削除は行わない。テーブル名は ec-cube-enterprise を正典とする。

| 操作種別 | 対象テーブル | 契機・条件 |
|---------|--------------|------------|
| 検索 | mtb_card / mtb_card_detail | 検索条件に合致するレコードを抽出する。抽出結果を所定フォーマットでファイル出力する。 |

## 画面遷移

| 条件 | 遷移先 |
|------|--------|
| 出力成功 | ブラウザがファイルをダウンロードする。一覧ページへ自動で戻す処理はレスポンス本体には含めない。 |
| ID 未取得などでサービスがリダイレクトを返した場合 | `m14-01_admin_card_card_search`（ページ番号はセッションがあればそれを使用）。 |
| コントローラが Referer へリダイレクトする場合 | 直前の管理画面 URL（ヘッダが欠けると不整合がありうる）。 |

### 遷移時に引き継ぐ状態

検索条件・ページングはカード検索のセッションに残る。CSV 出力はそれらを読み直して絞り込み直しはしない。

## エラー処理

| エラー内容 | 処理 |
|------------|------|
| `cardIds` が空 | フラッシュ `admin.csv.error.export.card`。`m14-01_admin_card_card_search` へのリダイレクト応答を組み立てる（手順は「処理フロー」参照）。 |
| コントローラの `empty($cardIds)` が真 | フラッシュ `admin.csv.error.export.require`、`Referer` へリダイレクト。 |
| 対象カードが存在しない | 例外メッセージをフラッシュし `Referer` へリダイレクト。 |
| その他 `RuntimeException` | 同上。 |
