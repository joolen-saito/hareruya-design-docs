# イベント管理 — イベント申込詳細・編集

## 概要

イベント管理において、既存のイベント申込1件の内容を表示し、申込状況・支払金額・参加プレイヤー・席順・チームメンバー確認を編集して更新する機能である。同一テンプレートが新規申込登録の入力にも使われるが、本書は既存申込の詳細表示（`GET …/entry/{eventEntryId}/edit`）と更新送信（`…/entry/{eventEntryId}/update`）に範囲を限定する。

本書は実装手順ではなく、誰が・いつ・どの条件で・結果どうなるかを読むためのリバース詳細設計とする。確認値はpf-eccube3（EC-CUBE3系）のHareruyaEcプラグインのイベント申込詳細表示・更新処理、申込詳細フォーム、申込・申込プレイヤー・申込履歴の永続化を正とする。

本機能のカスタマイズ区分はカスタマイズである。挙動の参照リポはpf-eccube3（HareruyaEcプラグイン）の現行実装とし、DB関連（永続化先のテーブル名・列名、DBカラム節、入力項目の保存先・扱い、副作用のDB更新）はec-cube-enterpriseを正とする。現行と移行先でスキーマが異なる箇所はリニューアル移行時の扱いに集約する。

対象はブラウザ経由の管理画面に限定する。

本文ではフレームワークのコントローラ型名やメソッド名を主説明としない。管理画面プレフィックスは環境により変わり、プラグイン設定の`admin_route`で決まる。「利用者視点の入口」にHTTPメソッドとサイトルートからのパスパターンを書く。

## 本書で扱うこと

- 既存イベント申込の詳細表示
- 申込状況・支払金額・参加プレイヤー・席順・確認フラグの編集と更新
- プレイヤー検索モーダルによる参加者の差し替え
- 申込履歴の記録、支払会員・支払方法の扱い

## 本書で扱わないこと

以下は本書では仕様確定せず、実装または別機能の設計を正とする。

- 新規申込登録（M13-12を正とする）
- イベント申込一覧・検索（イベント申込一覧機能を正とする）
- CSV出力・一括登録（M13-09・M13-13を正とする）
- イベント・日程そのものの登録（イベント新規登録・日程登録を正とする）
- プレイヤー・会員マスタの編集

## リニューアル移行時の扱い

表示・更新・差分反映の挙動は現行（pf-eccube3）を正とし、永続化先の列名は移行先（ec-cube-enterprise）を正とする。

### Excel基本設計により廃止された仕様（刷新後は実装不要）

本書は現行実装からのリバースであり、以下は現行挙動として記述しているが、Excel基本設計が廃止を宣言している。刷新後は実装しない。

- 席順（※Excel基本設計 0214 識別ID:4-1 により廃止。刷新後は実装しない）。参加プレイヤー表の席順セレクトと、その変更をプレイヤー情報リスト（JSON）へ反映する挙動、`dtb_entry_player.seat_order`の更新は行わない。
- DCIナンバー（※Excel基本設計 0214 識別ID:4-2 により廃止。刷新後は実装しない）。参加プレイヤー表のDCIナンバー列は表示しない。
- チームメンバー確認済み（※Excel基本設計 0214 識別ID:4-3 により廃止。刷新後は実装しない）。確認済チェックと、`dtb_entry_player.confirm_flg`の更新は行わない。

| 観点 | 現行（pf-eccube3） | 移行先（ec-cube-enterprise） |
|------|---------------------|------------------------------|
| 論理削除 | `dtb_event_entry`・`dtb_entry_player`とも`deleted_at`による論理削除 | 同一方式（`deleted_at`による論理削除を維持） |
| 申込の主キー列 | `dtb_event_entry.event_entry_id` | `dtb_event_entry.id`（主キー列名を`id`に統一。更新対象列`entry_status_id`・`price`、参照列`payment_id`・`paying_customer_id`・`payment_no`は同名維持） |
| 申込プレイヤーの主キー列 | `dtb_entry_player`の識別列 | `dtb_entry_player.id`（参照列`event_entry_id`・`player_id`、更新対象`confirm_flg`・`seat_order`は同名維持） |

## 処理フロー

### 申込詳細を表示する（`GET …/entry/{eventEntryId}/edit`）

1. 会員のソフトデリートを除外対象にし、プレイヤーのソフトデリートを無効化して読み込む。
2. 申込が存在しなければ404とする。存在すれば紐づくイベント詳細・イベントを得る。
3. チーム人数と既存参加者数の大きい方の行数で参加者行を用意し、参加者情報リスト（JSON）と申込状況・支払方法・支払金額をフォームへ初期設定する。
4. 席順アルファベット一覧が参加者数より少ない場合は404とする。
5. 詳細テンプレートを返す。

### 申込を更新する（`…/entry/{eventEntryId}/update`）

1. 申込詳細フォームを送信として処理する。申込が存在しなければ404。
2. 未送信のときは更新失敗を表示し、編集画面へ戻す。
3. 検証NGのとき、支払金額が不正なら金額メッセージ、参加者重複なら重複メッセージ、その他は更新失敗を表示し、編集画面を再描画する。
4. 検証OKのとき、申込状況など編集対象の値を申込へ反映する（支払方法・支払会員などは更新対象から除外する）。
5. 申込履歴を1件記録し、申込を更新する。
6. 参加者リストと突き合わせ、継続参加者は確認フラグ・席順の変更があれば更新、外れた参加者は削除、追加された参加者は新規に登録する。
7. 成功を表示し、同じ申込の編集画面へリダイレクトする。

## 業務ルール・計算

| 項目 | 内容 |
|------|------|
| 申込状況 | 申込状況マスタから選択する。更新時に申込へ反映する。 |
| 支払方法 | フォーム上で無効化されており、編集画面からは変更しない。 |
| 支払金額 | 半角数字のみ。更新時に申込へ反映する。 |
| 参加プレイヤー | 隠しフィールドのプレイヤー情報リスト（JSON、要素はプレイヤーID・確認フラグ・席順）で管理し、継続・追加・削除を更新時に反映する。 |
| 参加者の重複 | 同一プレイヤーが他申込・同日程で重複する場合は申込重複として検証で弾く。 |
| 申込履歴 | 更新成功のたびに申込履歴を1件記録する。 |

### 入力項目

| 項目名 | 必須／任意 | 最大長 | 初期値 | 保存先・扱い |
|--------|------------|--------|--------|----------------|
| 申込状況 | 必須 | 選択（申込状況マスタの単一選択） | 現在の申込状況 | `dtb_event_entry.entry_status_id`。フォームキー`entryStatus`。申込状況マスタの参照。 |
| 支払方法 | 必須（フォーム無効化のため画面からは変更不可） | 選択（クレジット・コンビニ・管理者の単一選択） | 現在の支払方法 | `dtb_event_entry.payment_id`。フォームキー`payment`。`disabled`指定で送信値は採用しない。 |
| 支払金額 | 必須 | 半角数字のみ（通貨JPY・小数なし） | 現在の支払金額 | `dtb_event_entry.price`。フォームキー`price`。半角数字以外は検証エラー。 |
| 参加プレイヤー情報 | 必須 | JSON文字列（プレイヤーID・確認フラグ・席順の配列） | 既存参加者から生成したJSON | `dtb_entry_player`の`player_id`・`confirm_flg`・`seat_order`へ展開。フォームキー`entryPlayerList`。重複検証あり。 |
| プレイヤー検索語 | 任意 | テキスト（検索用、保存しない） | 空 | フォームキー`search`。モーダル検索の入力。永続化しない。 |

支払会員・イベント名・店舗・会場・フォーマット・支払番号は読み取り専用表示であり、入力項目ではない。最大長の数値は申込詳細フォームの実装確認値とする。

## データ整合性

| 観点 | 内容 |
|------|------|
| 表示と更新 | 表示時に組んだ参加者行と、更新時のプレイヤー情報リストを突き合わせて差分反映する。表示後に別操作で参加者が変わった場合は更新時のリストを正とする。 |
| 申込と申込プレイヤー | 申込本体の更新後に参加者の追加・更新・削除を行う。両者は同一リクエスト内で反映する。 |
| 申込履歴 | 更新成功時に履歴を1件追加する。表示は履歴を変更しない。 |

## DBカラム

機能に直接関係する列のみ記載する。型や一覧の細部はスキーマを参照する。列名はec-cube-enterpriseを正とし、現行（pf-eccube3）と異なる場合は現行名を括弧で添える。

| テーブル | 列 | メモ |
|---------|-----|------|
| `dtb_event_entry` | `id`（現行`event_entry_id`） | 申込の特定キー。 |
| `dtb_event_entry` | `entry_status_id` | 申込状況。更新対象。 |
| `dtb_event_entry` | `price` | 支払金額。更新対象。 |
| `dtb_event_entry` | `payment_id`、`paying_customer_id`、`payment_no` | 編集画面では更新対象外（表示・固定）。 |
| `dtb_entry_player` | `id`（識別列）、`event_entry_id`、`player_id`、`confirm_flg`、`seat_order` | 参加者の追加・更新・削除対象。 |
| `dtb_entry_history` | `event_entry_id`、`entry_status_id`、`member_id`、`create_date` | 更新成功時に1件追加。 |

### DB操作

永続化の正は ec-cube-enterprise（テーブル名・操作は ec-cube-enterprise を正典）。当ドメインは承認ワークフローを介さず persist/flush で直接確定する（承認ワークフローは在庫機能固有）。

| 操作種別 | 対象テーブル | 契機・条件 |
|---------|--------------|------------|
| 登録/更新 | dtb_entry_history / dtb_entry_player / dtb_event_entry | 当機能が行う登録・更新で対象テーブルを直接保存する（不要な削除は含まない）。確定は persist/flush による即時反映。DB=ec-cube-enterprise を正典とする。 |
