 M14-06 カードセット一覧 / カード管理 — カードセット一覧 
 概要 
 HareruyaEc プラグインが管理画面に提供する「カードセット管理」において、カードセットマスタを表形式で一覧し、ページ送り・表示件数・並び順を切り替え、新規登録・編集・削除・画像ダウンロード（セット別／言語別）・ブロックマスタ参照への導線をまとめて置く画面である。一覧の抽出条件は実装上当該マスタの全件であり、キーワード検索やステータス絞り込みは持たない。 
 本書は実装手順ではなく、誰が・いつ・どの条件で・結果どうなるかを読むためのリバース詳細設計とする。pf-eccube3 に配置された HareruyaEc プラグインのソースを確認値とする。コア単体では当ルートは存在しない。 
 本機能のカスタマイズ区分は現行踏襲である。現行挙動は pf-eccube3 の HareruyaEc プラグインを参照し、永続化に関わるテーブル名・列名などのDB関連は ec-cube-enterprise を正とする。 
 対象はブラウザ経由の管理画面に限定する。コントローラのメソッド名は本文の主説明としない。本文ではルートbind名やSymfonyのルートnameの網羅は主説明としない。「利用者視点の入口」にHTTPメソッドとサイトルートからのパスパターンを書く。コード探索でbind名が必要なときだけ「調査補助」へ書く。 
 リニューアル移行時の扱い 
 DB関連の記述は ec-cube-enterprise の実装を正とする。一覧が参照するカードセットマスタと表示件数マスタは現行（pf-eccube3）と移行先（ec-cube-enterprise）で同一のテーブル名・列名であり、同一スキーマである。 
 観点 現行（pf-eccube3） 移行先（ec-cube-enterprise） カードセットマスタ mtb_cardset （ release_date / symbol_image / code / name_jp / name_en / special_flg / display_side_menu_flg / branch_display_flg ） 同一スキーマ（ mtb_cardset 、列名一致）。 表示件数マスタ mtb_page_max （ name を表示件数候補に使用） 同一スキーマ（ mtb_page_max ）。 
 並び順（リリース日／セット英名の昇降順）・表示件数・ページングの挙動とセッションキーは現行（pf-eccube3）を参照する。移行先でもテーブル・列は同名である。 
 利用者視点の入口 
 入口 URLエンドポイント 期待されるふるまい サイドメニュー「カードセット管理」 GET /{admin_route}/cardset 直前のページ番号・表示件数・並び順をセッションから読み直すが、クエリ resume が 1 でない場合は当該 3 種のセッションキーを削除してから初期化する。既定の並びはリリース日の新しい順。一覧を描画する。 同じ入口で検索中断からの再開を想定したアクセス GET /{admin_route}/cardset?resume=1 ページ番号・表示件数・並び順のセッションを消さず、保持値で一覧を組み立てる。 ページャのリンク GET /{admin_route}/cardset/{page_no} （必要に応じ pageCount ・ sortSelect をクエリに付与） セッションとクエリから表示件数・並び順を決め、該当ページの行を表示する。 表示件数ドロップダウンで別件数を選ぶ GET /{admin_route}/cardset/1?…&pageCount=…&sortSelect=… クエリの pageCount が mtb_page_max.name のいずれかと一致する場合のみセッションと実表示に反映する。ページは 1 にリセットするリンクとなる。 並び順ドロップダウンで別順を選ぶ GET /{admin_route}/cardset/1?…&pageCount=…&sortSelect=… クエリの sortSelect が定義済み 4 文言のいずれかと完全一致する場合のみセッションと一覧順に反映する。 表の「編集」 GET /{admin_route}/cardset/{id}/edit カードセット編集画面へ遷移する。 表メニューの「削除」 DELETE /{admin_route}/cardset/{id}/delete 別処理。成功時は一覧のページへ戻る。 「新規登録」 GET /{admin_route}/cardset/new 新規登録フォームへ遷移する。 「ブロックの追加」 GET /{admin_route}/… （マスタデータ閲覧ルート admin_hareruya_masterdata_view 、エンティティ指定でカードセットブロック） ブロックマスタの管理画面へ遷移する。 「画像ダウンロード(セット別)」 POST /{admin_route}/cardset/download チェックされたセット ID の一覧を送り、別処理が ZIP 応答またはエラー後リダイレクトを返す。 「画像ダウンロード(言語別)」 POST /{admin_route}/cardset/download_lang 同上（言語別の取りまとめ）。 
 フロント挙動 
 観点 内容 表示要素 ページタイトルは「カードセット管理」。単一フォーム内に、右上から「画像ダウンロード(言語別)」「画像ダウンロード(セット別)」、 admin_cardset_new への「新規登録」見出しリンク、カードセットブロック用マスタ画面への「ブロックの追加」、表示件数ドロップダウン、並び順ドロップダウン、表（チェック、リリース日、シンボル画像、略称、セット名日英、特殊セット・サイドメニュー表示・支店表示の各アイコン列、行メニュー）、条件付きでページネーション（ pager.twig 、 admin_cardset_page ）。 JS 挙動 表頭チェック #allCheck で [cardsetId] 属性を持つ行チェックを一括オンオフする。「画像ダウンロード」系クリック時、少なくとも 1 行が選択されていれば確認なしで送信を継続する。1 件も選択されていない場合は 確認('プロモカード一覧をダウンロードしますか?') を出し、肯定時に tre を返す記述がある（識別子未定義のためブラウザでは参照エラーになり得る）。否定時は false を返して送信を止める。 CSS・レイアウト デフォルトフレームと Bootstrap 横型フォームテーマ。管理画面標準アイコン（タグ・三点メニュー）。 モーダル・ポップアップ 専用モーダルはなく、プロモダウンロード確認のみブラウザの confirm に依存する。 
 処理フロー 
 一覧を表示する（ admin_cardset または admin_cardset_page ） 
 管理画面の認証・共通制約を通過する。 フォーム種別 card_set の空フォームを生成し、一覧 POST 用に CSRF フィールドを得る（一覧では入力項目はトークンのみ実質利用）。 page_no が URL に無い（ルート admin_cardset ）かつクエリ resume が整数 1 でない場合、セッションから eccube.admin.cardset.page_no 、 eccube.admin.cardset.pageCount 、 eccube.admin.cardset.sortSelect を削除する（コアの有効フラグとしても同値が使われる）。 mtb_page_max を全件取得する。 表示件数はセッションの eccube.admin.cardset.pageCount があればそれを使い、無ければ設定 default_page_count 。リクエストに pageCount があり数値であり、かつ mtb_page_max のいずれかの name と文字列一致する場合、その値に更新してセッションへ保存する。 並び順の候補は固定の 4 文言（リリース日の昇順／降順、セット英名の昇順／降順）。現在値はセッションの eccube.admin.cardset.sortSelect があればそれを使い、無ければ「リリース日（降順）」。リクエストに sortSelect があり、4 候補のいずれかと完全一致する場合、その値に更新してセッションへ保存する。 カードセット用リポジトリの select に現在の並び順ラベルを渡し、全件を配列として取得する。クエリは当該エンティティに対する orderBy のみで、WHERE による絞り込みは行わない。 page_no は URL 引数が無ければ 1 。アプリケーションのページネータで wrap-queries 有効のまま分割する。 セッションに eccube.admin.cardset.page_no 、 eccube.admin.cardset.pageCount 、 eccube.admin.cardset.sortSelect を書き戻す。 Twig card_set.twig を描画する。 
 集計条件 
 指標 集計の要点 一覧の総件数 mtb_cardset 相当の全行を対象とし、リポジトリの select が返す配列の要素数と一致する。除外条件は実装していない。 ページ内の行 ページネータが決める連続範囲の部分集合。同一ソートキー値の安定順は保証しない（二次ソートキーは指定されていない）。 
 業務ルール・計算 
 本機能の一覧画面では永続化する入力フォーム項目を持たない。登録・更新の入力項目と最大長はカードセット編集画面の設計を正とする。 
 項目 内容 一覧の対象行 カードセットマスタの全レコード。 並び順 リリース日の昇順／降順、またはセット名（英）の昇順／降順。いずれも単一プロパティのみ。 画像ダウンロード POST フォーム名 cardsetIds[] のチェック値が送られる。一覧画面の定義外の本文では空配列のとき [0] に置き換えて処理が進む実装があり、プロモーション用の特別扱いに繋がる。詳細は画像ダウンロードの実装を正とする。 
 本機能では集計・合算・価格計算などの業務計算を行わない。 
 データ整合性 
 観点 内容 一覧と DB 表示リクエスト時点のコミット済みデータを読む。悲観・楽観ロックは一覧取得に使わない。 他画面との一覧 編集・削除・CSV やバッチが別トランザクションで更新した内容は、次回の一覧表示またはページ遷移まで画面に自動反映されない。 ソートの一意性 同一リリース日や同一英名が複数ある場合、MySQL 実装の不定順に依存し、画面は順序保証を追加しない。 
 API/バッチ結果 
 本機能では外部 HTTP API 呼び出しやバッチコマンドの起動を扱わない。 
 入出力 
 種類 内容 入力 GET クエリ resume 、 pageCount 、 sortSelect 。一覧フォーム POST 時は CSRF トークン。ダウンロードボタン POST 時は上記に加え cardsetIds[] 。 成功時出力 HTML 一覧。ダウンロード POST の成功時は ZIP ファイルの応答（別処理）。 失敗時出力 本節の一覧表示では専用のバリデーションエラー画面はなく、ダウンロード・削除は別ルートのフラッシュメッセージとリダイレクトを正とする。 副作用 セッションの 3 キー更新。ダウンロード成功後の一時ディレクトリ削除はコントローラ終了イベントで行われる。 
 DBカラム 
 一覧の列に直接関係する列のみ示す。型の細部は Doctrine の dcm を参照する。 
 テーブル 列 メモ mtb_cardset id 行チェック値・リンクに使用。 mtb_cardset release_date 画面上 Y/m/d で整形。 mtb_cardset symbol_image 有れば画像 URL、無ければプレースホルダコメント。 mtb_cardset code 略称列。 mtb_cardset name_jp , name_en 同一セルに改行で併記。 mtb_cardset special_flg , display_side_menu_flg , branch_display_flg 真のときタグアイコン表示。 
 DB操作 
 本機能は参照系（検索）であり、DBへの登録・更新・削除は行わない。テーブル名は ec-cube-enterprise を正典とする。 
 操作種別 対象テーブル 契機・条件 検索 mtb_cardset 検索条件に合致するレコードを抽出する。 
 バリデーション 
 項目 内容 表示件数 クエリ値が mtb_page_max.name のいずれにも一致しなければ無視し、手順 5 以前の値がそのまま使われる。 並び順 4 文言以外の sortSelect は無視される。 一覧表示リクエスト 画面単体ではフォーム送信検証は行わない（空の card_set フォーム）。 
 権限・認可 
 利用者状態 カードセット一覧（表示・ページ送り・件数・並び順） 行メニューからの編集・削除 画像ダウンロード POST 管理画面に入れない利用者 当 URL へ到達しない（共通の管理画面ガードに従う） 同上 同上 管理画面に入れる利用者 到達した場合、ソース上この URL 専用の追加 DENY を確認していない 各ルートの共通ガードに従う 同上 
 画面遷移 
 条件 遷移先 「新規登録」 admin_cardset_new 行メニュー「編集」 admin_cardset_edit 行メニュー「削除」完了後 admin_cardset_page のセッション保持ページ番号 「ブロックの追加」 admin_hareruya_masterdata_view （エンティティキーでカードセットブロック） 画像ダウンロード失敗など（実装側の分岐） admin_cardset_page のセッション保持ページ番号へリダイレクトしフラッシュ表示 
 遷移時に引き継ぐ状態 
 起点 遷移前の処理 遷移後の初期状態 一覧表示のたび eccube.admin.cardset.* を最新のページ・件数・並びで上書き 後続の一覧 GET で再利用される GET /cardset で resume なし 上記 3 キーをクリアしてから初期値で再構築 既定件数・既定並び・ページ 1 相当の挙動に戻る 
 エラー処理 
 エラー内容 処理 表示件数・並び順クエリが不正 無視され、セッションまたは既定値が使われる。画面上に専用エラーは出さない。 画像ダウンロードで対象画像や ZIP が生成できない 別処理が管理画面用エラーメッセージを積み、一覧ページへリダイレクトする。 削除時に子カード詳細が存在 エラーメッセージを積み、 Referer へリダイレクトする。 
 試行制限 
 本機能ではログイン試行や API レートの個別制限を扱わない。 
 ログ・監査 
 一覧表示そのものに特化した独自の監査ログは実装を確認した範囲では設けていない。画像ダウンロードや削除のログは別処理に従う。 
 ログに出してはいけないもの 
 パスワード なりすまし対策トークン Cookie 値 セッション ID の完全値 Remember Me トークンの原値 
 セッション 
 本機能におけるセッション 
 観点 内容 保存タイミング 一覧処理の末尾で毎回 eccube.admin.cardset.page_no 、 eccube.admin.cardset.pageCount 、 eccube.admin.cardset.sortSelect を保存する。 クリア GET で page_no が URL に含まれないルートへ入り、かつ resume が 1 でないとき、上記 3 キーを削除する。 
 セッションへ保存しない情報 
 行チェックのオンオフ 検索キーワード（本画面に検索欄が無い） 
 Cookie 
 本機能は一覧表示専用の Cookie を新たに書き込まない。セッション Cookie は管理画面共通の仕組みに従う。 
 排他制御・トランザクション 
 一覧取得は参照のみであり、当画面表示処理がトランザクション境界や行ロックを張る実装は持たない。
