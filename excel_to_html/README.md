# Excel to HTML Converter

Excel仕様書を、ブラウザで読みやすいHTMLへ変換するツールです。`input` フォルダ内のExcelファイルをまとめて読み込み、1ブックにつき1つのタブ付きHTMLを `output` フォルダへ生成します。

Excelの見た目を完全再現するのではなく、表を読みやすいHTMLレイアウトに整えます。Excel内の画像は、アンカーセル付近の行に埋め込み画像として表示します。配色・レイアウトは設計書HTML群（`.cursor/skills` の `doc-html-render` / `html-sidebar` / `html-sidebar-color`）と同じ、暖色＋clay/oliveの2アクセントと左サイドバー（シート一覧）に揃えています。

## 使い方

1. このディレクトリへ移動します。

```bash
cd /home/y-saito/Developments/tools/excel_to_html
```

2. 変換したいExcelファイルを `input/` に置きます。
3. uvで変換を実行します。

```bash
uv run python convert.py
```

入力/出力フォルダを指定する場合:

```bash
uv run python convert.py --input-dir path/to/excel --output-dir path/to/html
```

`uv run` が `pyproject.toml` の依存関係を自動で解決するため、pipでの事前インストールは不要です。

## 対応形式

- `.xlsx`
- `.xlsm`
- `.xltx`
- `.xltm`

## 変換内容

- Excel上で表示状態のシートだけをExcel上の順番で出力します。非表示/veryHiddenシートはHTML本文・左サイドバー・検証対象から除外します。
- 左サイドバーのシート一覧でシートを切り替えできます。
- 表示シートのセル値、結合セル、改行、シート順を保持します。
- Excelの方眼レイアウトに引きずられないよう、内容のない行・列はまるごと省きます。結合セルの結合範囲は、残った行・列に合わせて再計算します。
- 表はHTMLとして読みやすい余白、控えめな罫線、交互背景、横スクロールで表示します。
- 画像はHTMLへbase64埋め込みします。画像バイトと座標（EMU）は同一の DrawingML `<pic>` から取得し、openpyxlの画像列挙には依存しません（列挙数がDrawingMLの`<pic>`数とズレることがあるため）。
- 画像同士が重なっている場合は、ExcelのDrawingML上の重なり順を保った1つの画像レイヤー群として描画します（例: 背景画像の上に細いバナー画像を重ねるケース）。
- 画面遷移図やフロー図のように画像ではなくExcel図形（矩形ノード＋コネクタ）で作られた図は、DrawingMLの接続関係（遷移元・遷移先）を使って、読みやすいHTML/SVGの遷移図と遷移一覧へ再構成します。
- テキストボックス/図形内の文字（画面イメージ上の番号注釈、図形内の注釈など）も抽出します。openpyxlはこれらを読まないため、パッケージ内のDrawingMLを直接パースしています。抽出したテキストは番号ピンの復元・画面遷移図の再構成・番号pin対応台帳に使いますが、**「図形・テキストボックス内テキスト」全件表はHTMLへ出力しません**（出力除外規約）。非出力にした図形は `output/shape_textbox_sheets.csv` へ全件記録します。全件表を出したい場合は `convert.py` の `RENDER_SHAPE_TEXT_SECTION` を `True` に戻します。
- **「番号pin対応台帳」もHTMLへ出力しません**（出力除外規約）。pinごとの対応状態・画像割当・重複は `output/pin_ledger_sheets.csv` へ全件記録します。台帳を再びHTMLへ出したい場合は `convert.py` の `RENDER_PIN_LEDGER_SECTION` を `True` に戻します。
- 後段注入の「実装差分追補」節も出力しません（出力除外規約）。`endpoint-supplement` スキルの `build` が既存HTMLから節と装飾CSSを取り除き、`verify` が不在を検査します。route突合の正本は `endpoint_reports/` に残ります。
- Excel上で**取り消し線が引かれた文章は出力しません**（出力除外規約）。セル（run単位・セル継承）でも図形・テキストボックス内テキスト（DrawingMLの `strike`）でも同じ扱いで、取り消し線部分だけを落として残りは出力します。除去の結果テキストが空になったセル・図形は出力対象から外れます。従来どおり取り消し線付きで表示したい場合は `convert.py` の `RENDER_STRUCK_TEXT` を `True` に戻します。
- 機能仕様書Markdownを追記統合する場合、一部の節（概要・リニューアル移行時の扱い・調査補助・DBカラムなど共通13節）と、区分限定の節・列（画面系の「API/バッチ結果」、フロント以外の「フロント挙動」、管理画面の列「画面上の文言(英語)」）はHTMLへ出力しません。対象一覧は `.cursor/skills/output-exclusion-policy/SKILL.md` を正本とします。Excel由来の本文は対象外で、除外はHTML表示のみ・Markdown正本は変更しません。
- 機能仕様にあたる見出し（「機能について」「処理概要」「機能仕様」など）は強調表示し、アンカー付きの独立セクションとして画面項目定義テーブルと区別します。各シート冒頭にこれらへのジャンプリンクを表示します。
- グラフ、条件付き書式、印刷範囲は完全再現しません。画面遷移図はExcel上の見た目や線形状を再現するのではなく、抽出した遷移関係を安定したカード型レイアウトに組み直します。検出できた未対応要素はHTML末尾の「未変換要素」に表示します。

## レイアウト図のナンバリング ↔ 識別IDの連携

画面イメージ上の番号ピン（`(1-2)`,`(1)` 等のテキストボックス）を画像の正しい位置へ復元し、画面項目定義テーブルのNo.（識別ID）と相互リンクします。

- 入れ子グループの変換を全段適用してピン・画像の絶対EMU座標を求め、画像上の%位置へ写します。
- 番号ピンは最近接の画像へ割り当てます（左マージンに少しはみ出すピンも拾えるよう、箱の外でも近ければ許容しクランプ）。
- 「画像あり＋正規化した番号の60%以上が項目表No.に一致」するシートだけを画面イメージとみなしてオーバーレイします（画像ではなくExcel図形で作られた画面遷移図は、別途HTML/SVG図として復元します）。
- 番号ピン `id="pin-<シート>-<No>"` と項目行 `id="item-<シート>-<No>"` を相互リンクし、`:target` で双方をハイライトします。
- 画像に乗せられない番号（図形描画の画面・注記など）は、`pin-<シート>-<No>` を持たないため項目表からの逆リンクを張りません（デッドリンク防止）。項目行の `id="item-<シート>-<No>"` は維持し、番号の対応状況は `output/pin_ledger_sheets.csv`（番号pin対応台帳。HTMLへは非出力）で全件確認できます。

## 変換の検証

`uv run python verify.py` で、生成HTMLが正本Excelを正しく反映しているかを機械検証します（不合格なら非ゼロ終了）。

- セル値カバレッジ（目標100%）とは別に、`independent_cells.py` が正本Excelを `convert.py` と独立に読み、取り消し線モデルの突合とセル座標（`data-excel-ref`）単位の文言照合を行います。カバレッジ判定だけでは変換器と検証器が同じ誤りをして見逃す（共倒れ）ため、この独立検証を合否に含めます。
- 表示シートのシート網羅、セル値カバレッジ（目標100%）、画像網羅（`<pic>`数＝埋め込み数）、画面遷移図の再構成（元コネクタ数・抽出遷移数）、リンク整合（デッドリンク0）、番号ピンの非欠落（HTMLに台帳が無いことと、`pin_ledger_sheets.csv` にシート単位で全件記録されていることの両方）、非表示シートがHTMLに出ていないことを確認します。
- あわせて出力除外規約（`.cursor/skills/output-exclusion-policy/SKILL.md`）も検証します。取り消し線の文章・図形テキスト全件表・実装差分追補がHTMLに無いこと、除外した図形が `shape_textbox_sheets.csv` に全件記録されていること、Markdown由来ブロック内に除外対象の見出し・列が残っていないことを確認します。

```bash
uv run python verify.py
```
