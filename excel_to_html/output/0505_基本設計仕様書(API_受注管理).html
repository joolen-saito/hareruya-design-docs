本店・支店のシステムを統合するので、注文印刷情報のAPIも処理を一本化する。

本店のプリンタはエンドポイントURLに店舗IDを追加する必要があるので、設定変更が必要

本店・支店のシステムを統合するので、支店側のプリンタに設定されているエンドポイントURLはドメインが変更となるので全て設定変更が必要

現状は印刷完了ステータスに更新するAPI (A05-02)と処理を受けるメソッドが共通で、クエリ「ConnectionType」で処理が分岐しているので、

A05-02とエンドポイントを分ける

現状/order/print/direct?ConnectionType=GetRequestGETで受信
/order/print/direct?ConnectionType=SetResponsePOSTで受信※ RoutingでGetとPostで登録を行なっているが、同じメソッドを登録している

機能仕様処理概要（★はカスタマイズ項目）

★ 各店舗に設置されているプリンタから定期的(間隔:30秒)にこのAPIにアクセス(エンドポイントURL変更)

URLに店舗ID(shop_id)を引数として持つ

・バーコードが印刷されていない問題が発生しないようにするため、注文データをXML形式にする前に受注データにスマレジの商品コードが存在するかどうか確認する

スマレジの商品コードが存在しない場合はスマレジコードが採番されていない可能性があるため何もしない

・店舗IDからその店舗の未印刷の注文データを抽出し、各注文データごとに印刷できるようにプリンタ仕様に合わせてXMLの書式にして返す。

未印刷データがなければ空文字''を返す

※ プリンタのxmlの仕様 https://www2.epson.jp/support/manual/SDP_UM_JA_REVW.ZIP

・印刷データXMLをログに出力する

現行仕様

A05-01 注文印刷_印刷情報をプリンタへ送信 / API 受注管理 — 注文印刷（印刷情報送信・印刷済み更新）

業務ロジック

呼び出し元

呼び出すのは店頭のスタック用紙プリンタ（印刷クライアント）である。本エンドポイントは認証の判定を持たず、未認証で実行できる（確認値）。認証判定を持たないため、認証失敗による拒否は返さない。利用者の照合も行わない。

動作の分岐

接続種別が印刷情報要求のときは印刷情報を送信し、印刷結果応答のときは印刷済みへの更新を行う。いずれにも一致しない値のときは処理を行わず、応答を組み立てない。接続種別はGET・POSTのいずれの要求からも読み取る。

印刷対象の受注

次のいずれかに当たる受注を最大10件取得する。

  • 店頭受取で注文受領の受注
  • スムーズ店頭受取で、所定の支払方法かつ未確定・未出荷・未取消・未受領・店頭予約日なし・スマレジコードありの受注
  • ブラウザ印刷フラグが立つ受注

対象受注が無いときは印刷情報を生成せず、空のデータを返す。

印刷情報の組み立て

受注ごとに、注文日・合計金額・店頭注文番号・スマレジコード・問い合わせ有無・注文詳細URLを組み立て、1受注分の印刷情報を生成する。配送がスムーズ店頭受取のときは、合計金額欄を「スムーズ店頭受取」とする。全受注分を束ねてスタック用紙の印刷情報を生成する。生成した印刷情報が空でないときは、印刷不具合の検証のため印刷情報を記録する。

印刷済みへの更新

受け取った印刷結果を解析し、印刷結果要素ごとに印刷ジョブIDの先頭部分から受注IDを取り出して対象受注を特定する。対象受注の補助情報のブラウザ印刷フラグが立っているときは、そのフラグを倒すだけに留める。立っていないときは受注のステータスをピック中へ更新し、補助情報の確定日時に現在時刻を設定する。

本APIでは金額・税・ポイント・在庫数量の再計算や丸めを行わない。ステータスの更新は、実装で定義された遷移・存在確認に従う。

エラー時の扱い

エラー内容処理
接続種別が想定値に一致しない処理を行わず応答を組み立てない
印刷情報要求で対象受注が無い空のデータを返す。印刷情報の記録も行わない
印刷結果応答で印刷結果の解析に失敗内容とエラーを記録し、更新を行わずに戻る
印刷結果応答で直接印刷結果が偽・印刷結果要素なし内容を記録し、更新を行わずに戻る
印刷結果応答で受注が見つからない該当受注IDのエラーを記録し、その要素を飛ばして次へ進む
印刷情報生成・データ取得・記録の書き出し中の例外共通例外処理に委ねる（HTTP 500相当）

入出力

入出力: リクエスト

パラメータ位置型必須／任意説明
ConnectionTypeクエリまたはボディstring必須動作の分岐。GetRequestで印刷情報送信、SetResponseでステータス更新。いずれにも一致しない場合は処理を行わず本文を返さない
ResponseFileボディstringSetResponse時に必須プリンタが返した印刷結果のXML文字列。直接印刷結果の真偽と印刷結果要素（印刷ジョブID）を含む。更新対象の特定に用いる

入出力: レスポンス（成功）

応答はJSONではない。分岐ごとに応答形式が異なる。

分岐HTTPステータスContent-Type本体
GetRequest（A05-01）200application/octet-streamスタック用紙の印刷情報XMLをストリーム送信する。対象受注が無い場合は空のデータ
SetResponse（A05-02）200text/xml; charset=utf-8空の本文（本文長0）

印刷情報要求が返すXMLの構造は次のとおり。

ePOSPrint/PrintData印字レイアウト。店頭注文番号・注文詳細URLのQRコード・注文日・注文番号・お客様名・合計金額・スマレジコードのバーコード・各種チェック欄を含む

入出力: レスポンス（失敗）

認証・入力検証による明示的なエラー応答は組み立てない。

HTTPステータス条件本文の形
200印刷情報要求で対象受注が無い空のデータ（XML本体を持たない）
200印刷結果応答で解析失敗、直接印刷結果が偽、印刷結果要素が無い、または受注が見つからない空の本文。更新は行わず、内容とエラーを記録する

500印刷情報生成中・データ取得中・記録の書き出し中の例外共通例外処理に委ねる

入出力: 永続化

操作契機

A05-02 注文印刷_該当受注のステータスを印刷済みに変更 / API 受注管理 — 注文印刷（印刷情報送信・印刷済み更新）

業務ロジック

動作の分岐

接続種別 ConnectionType の値で動作が分かれる。

接続種別の値動作
GetRequest印刷情報を送信する
SetResponse印刷済みステータスへ更新する
上記のいずれにも一致しないとき処理を行わず、応答を組み立てない

印刷対象の受注

印刷情報の送信では、次のいずれかに当たる受注だけを対象とし、最大10件を取得する。

対象条件
店頭受取の受注対応状況が注文受領のとき
スムーズ店頭受取の受注所定の支払方法で、未確定・未出荷・未取消・未受領・店頭予約日なし・スマレジコードありのとき
ブラウザ印刷を指定した受注補助情報のブラウザ印刷フラグが立つとき

受注ごとに注文日・合計金額・店頭注文番号・スマレジコード・問い合わせ有無・注文詳細URLを組み立て、1受注分の印刷情報とする。配送がスムーズ店頭受取のときは、合計金額欄を「スムーズ店頭受取」とする。全受注分を束ねてスタック用紙の印刷情報XMLとする。

対象受注生成する印刷情報
1件以上あるとき受注ごとの印刷情報を束ねたXML。XMLをログファイルへ書き出す（印刷不具合の検証に用いる記録）
1件も無いときXMLを生成せず空文字とする。ログファイルの書き出しも行わない

印刷済みステータスへの更新

受け取った印刷結果のXMLを解析する。印刷結果要素ごとに、印刷ジョブIDの先頭部分から受注IDを取り出して対象受注を特定する。

対象受注の状態更新内容
補助情報のブラウザ印刷フラグが立っているときフラグを倒すだけに留め、対応状況は変えない
補助情報のブラウザ印刷フラグが立っていないとき対応状況をピック中へ更新し、補助情報の確定日時に現在時刻を設定する

認証を行わない

本エンドポイントは認証処理を行わない。他の管理系APIが用いる共通の認証処理を経由せず、未認証のまま実行できる。認証の判定を持たない限り、認証失敗による拒否（HTTP401）は返さない。呼び出し元は店頭のスタック用紙プリンタだけで、利用者の照合は行わない。

金額・在庫の再計算

金額・税・ポイント・在庫数量の再計算と丸めは、いずれの分岐でも行わない。

エラー時の扱い

事象扱い
接続種別が想定値のいずれにも一致しないとき処理を行わず、応答を組み立てない
印刷情報の送信で対象受注が無いとき空のデータを返す
印刷結果XMLの解析に失敗したとき更新を行わずに戻る
直接印刷結果が偽のとき、または印刷結果要素が1件も無いとき更新を行わずに戻る
印刷ジョブIDに対応する受注が見つからないときその要素を除き、次の要素へ進む
印刷情報生成・データ取得・ファイル書き出し中に例外が起きたとき共通例外処理に委ねる（HTTP500相当）

入出力

種類内容
入力接続種別（ConnectionType）。クエリとボディのいずれからも受け取る。必須。印刷済み更新のときは、印刷結果XML（ResponseFile）をボディで受け取る。印刷結果XMLは直接印刷結果の真偽と、印刷ジョブIDを持つ印刷結果要素を含む。
成功時出力印刷情報の送信は HTTP200、Content-Type は application/octet-stream で、印刷情報XMLをストリーム送信する。対象受注が無いときは空のデータ。印刷済み更新は HTTP200、Content-Type は text/xml; charset=utf-8 で、本文長0の空応答。
失敗時出力認証・入力検証による明示的なエラー応答を組み立てない。更新できないときも空の本文を返す。例外のときは HTTP500 相当。

出力: 印刷情報XMLの構造

要素内容
PrintRequestInfoルート要素。バージョン属性を持ち、配下に受注ごとの ePOSPrint を並べる
ePOSPrint受注1件分の印刷情報。印刷先・タイムアウト・印刷ジョブID・印字レイアウトを持つ
印刷ジョブID受注ID。印刷済み更新で受注を特定するときに用いる
印字レイアウト店頭注文番号、注文詳細URLのQRコード、注文日、注文番号、お客様名、合計金額、スマレジコードのバーコード、各種チェック欄

入出力: 永続化

操作契機
更新印刷済み更新で、ブラウザ印刷フラグが立っていないときに、受注の対応状況をピック中へ、補助情報の確定日時を現在時刻へ設定する
更新印刷済み更新で、ブラウザ印刷フラグが立っているときに、そのフラグを倒す

A05-03 店頭注文番号取得 / API 受注管理 — 店頭注文番号取得

業務ロジック

返す番号の構成

ピック完了の注文に紐づく注文番号札（数字）を先頭側に、注文番号札（アルファベット）を末尾側に並べた1つの配列を返す。数字はピック完了の受注に限定して取得し、アルファベットは識別子の昇順で取得する。該当が無いときは空配列を返す。

欠番の補完

数字の件数とアルファベットの件数の合計が画面表示の最大件数を超えるときだけ、出荷完了の注文番号札（数字）も取得して欠番を補う。直前に加えた番号の次から対象番号の手前までの連番がすべて出荷完了であれば、その間の番号を配列に加える。最大件数を超えないときは補完しない。

認証

本APIは認証を要求しない。認証判定を行わないため、未認証でも取得できる。呼び出し元は店内モニターの表示画面であり、利用者の資格情報による絞り込みは行わない。

エラー時の扱い

エラー内容処理
取得処理中の例外標準例外ハンドラに委ねる（HTTP 500相当）
該当データなしエラーとせず、空配列をHTTP 200で返す

入出力

種類内容
入力リクエストパラメータを持たない。パスの言語識別子は取得対象の絞り込みに使わない
成功時出力HTTP 200。注文番号を要素とする1次元配列。数字要素は整数、英字要素は文字列となる
失敗時出力取得中の例外はHTTP 500として標準例外ハンドラに委ねる。入力検証と認証判定を行わないため、400・401は発生しない

複数受注購入パターン

ECCUBEにすでに存在する受注を複数同時に店頭に持ってきた時

ex) 　店頭PC購入を複数回行い、レジに来る　店頭受取の会員が店頭PC購入でついで買いをする

基本ルール

・ECCUBE上の受注レコードを全て、ステータスを「引き渡し済み」にする
・全ての受注データを統合した新規受注データを新規作成する。既存の受注データには移行先の新規受注データIDを登録する。
・この組合せに加え、店舗内でのついで買いも同時に発生している場合は、そのデータも統合する。
・会員状態も登録する。非会員であれば、「非会員」として登録・更新する
・カスタマイズ対象の追加連携項目をECCUBEの受注データに登録する
・配送方法は店頭受取とする
・注文日に店頭受取注文の注文日を設定する。複数の店頭受取受注データが存在する場合は一番若いものを注文日とする。

返品

購入後、返品される

基本ルール

・一部返金の想定は不要。
・対象の受注データのステータスを「キャンセル」にする

ただし、取消(cancelDivision)が1の場合と、打消し(disposeDivision)が1の場合で処理が分岐する

disposeDivisionが1の場合、打消元取引IDから検索

cancelDivisionが1の場合、取引IDから検索

スマレジの詳細な支払方法を取得することはできないため、スマレジで取り込んだ取引情報の支払方法はすべて「店頭支払」とする

現行仕様

A05-04 スマレジ受信処理 / API 受注管理 — スマレジ受信処理（ポイント履歴取得）

業務ロジック

認証と呼び出し元

このAPIは認証トークンを要求しない。認証の判定を行わないため、未認証でも処理を実行する。呼び出し元はスマレジと転送経路であり、利用者の資格情報による絞り込みは行わない。

支店システムへ転送するときは、受信した連携用ヘッダをそのまま転送先へ引き継ぐ。連携用ヘッダは転送先へ渡す資格情報であり、呼び出し元の認証には使わない。ヘッダの値は本書に記載しない。

取引区分ごとの処理

受信した内容から取引ヘッダと取引明細を取り出し、取引区分で処理を分ける。

取引区分処理
取消会員ポイントを取消の方向に補正し、取引に一致するポイント履歴を削除する
打消付与ポイントと利用ポイントの正負を反転したうえで取消と同様に補正し、対象のポイント履歴を削除する
通常取引会員ポイントを加減算し、付与と利用のポイント履歴をそれぞれ登録する。続いて取引明細の各行を処理する

取引明細の振り分け

店舗コードは、オプション設定のスマレジ店舗IDが 3 桁に満たないときはゼロ埋めして整形した値とする。

商品コードの店舗コードが自店舗と一致する行だけ、対象の注文を出荷完了に反映する。一致しない行は支店分として記録し、自店舗では注文を更新しない。

支店分の明細が 1 件でもあるときは、支店システムのスマレジ受信APIへ明細を転送する。転送結果に更新件数が含まれるときは合算し、含まれないときは合算しない。

更新件数

応答に返す更新件数は、会員ポイント・ポイント履歴・出荷完了の反映の件数に、支店転送の結果件数が得られるときはそれも合算した値とする。

会員が見つからないとき、対象のポイント履歴が無いとき、対象の注文が無いときは、その処理の更新件数を 0 として処理を続ける。

エラー時の扱い

エラー内容処理
受信内容を解釈できない、取引ヘッダが足りない、処理中に例外が起きた標準の例外処理に委ねる（HTTP 500 相当）
会員が見つからない・対象履歴が無い・対象注文が無いエラーとせず、その処理の更新件数を 0 として続け、HTTP 200 を返す
支店転送の結果に件数が含まれない転送エラーとして扱い、件数を合算せずに処理を続ける

入出力

種類内容
入力取引ヘッダと取引明細を含む受信内容、スマレジの処理名、支店転送用の連携ヘッダ
成功時出力HTTP 200。更新件数を 1 件の要素として返す
失敗時出力受信内容を解釈できないとき、取引ヘッダが足りないとき、処理中に例外が起きたときは HTTP 500

入出力: 受信内容

パラメータ位置型必須／任意説明
paramsボディstring必須取引ヘッダと取引明細を含む。取引ヘッダは会員ID・付与ポイント・利用ポイント・取引ヘッダID・取消区分・打消区分などを持つ
proc_nameボディstring任意スマレジの処理名。支店転送のときはそのまま引き継ぐ
X_contract_idヘッダstring任意支店転送のときに転送先へ引き継ぐ契約ID
X_access_tokenヘッダstring任意支店転送のときに転送先へ引き継ぐアクセストークン
{_locale}パスstring必須言語識別子。処理対象の絞り込みには使わない

入力の検証と認証の判定を行わないため、HTTP 400 と HTTP 401 は発生しない。

入出力: 永続化

操作契機
更新会員ポイントを、取消・打消・通常取引のいずれかで補正したとき
追加付与と利用のポイント履歴を、通常取引のとき
削除取引に一致するポイント履歴を、取消または打消のとき
更新対象の注文を、商品コードの店舗コードが自店舗と一致するとき出荷完了に反映する
