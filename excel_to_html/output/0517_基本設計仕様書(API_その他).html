機能名
検索クエリに一致する記事情報1件を取得
概要
記事情報1件を取得
処理概要（★はカスタマイズ項目）

GET　POST　PUT　DELETE　PATCH　OPTIONS　HEAD　有　無　〇

エンドポイントURL

/article.json

プロトコル　HTTP　メソッド　GET　認証の有無　無　認証方式　無　リクエスト書式　クエリ　レスポンス書式　JSON

カスタマイズ説明

機能仕様処理概要（★はカスタマイズ項目）

・WordPressから参照されるEC-CUBEのAPI
・WPの投稿IDを元に記事情報1件検索しJSON出力する。

リクエストパラメータ

項目名型必須最大文字数
または最大値		入力例備考
WPの投稿ID数値（整数）〇-14659.0jaもしくはenのいずれか

リクエストパラメータサンプル

/article.json?wpPostId=14659

ステータスコード

コード　説明

200.0　正常

404.0　該当データがない場合

レスポンスデータ

名前型説明
article_id数値（整数）記事ID
wp_post_id数値（整数）WPの投稿ID
wp_type_id数値（整数）WP種別ID
url文字型URL
deleted_at日時（YYYY/MM/DD HH:MM）削除日時
update_date日時（YYYY/MM/DD HH:MM）更新日時
cardsオブジェクト記事情報に紐づくカード情報
archetypesオブジェクト記事情報に紐づくアーキタイプ情報
decksオブジェクト記事情報に紐づくデッキ情報

A17-01 検索クエリに一致する記事情報1件を取得 / API その他 — 検索クエリに一致する記事情報1件を取得

概要

検索クエリ（パラメータ）に一致する記事情報を1件取得するAPIである。pf-apiが提供するJSON APIである。

本書は実装手順ではなく、誰が・いつ・どの条件で・結果どうなるかを読むためのリバース詳細設計とする。確認値はpf-apiの記事検索取得処理、ルート定義、記事を扱うリポジトリを正とする。

対象はJSON APIエンドポイントであり、ブラウザ向けの画面を持たない。記事本体は別途WordPress側で管理し、本APIは連携用の記事情報を返す。

本機能のカスタマイズ区分は現行踏襲であり、挙動は現行実装（pf-api）を参照し、DB関連はec-cube-enterpriseを正とする。

本書で扱うこと

  • 検索クエリ（パラメータ）に一致する記事1件の取得
  • 該当が無い場合の応答

本書で扱わないこと

以下は本書では仕様確定せず、実装または別機能の設計を正とする。

  • 記事IDに関連する記事の取得（関連記事取得を正とする）
  • 記事本体（WordPress）の管理
  • 記事登録（記事登録処理を正とする）

リニューアル移行時の扱い

記事連携テーブルは現行（pf-api）と移行先（ec-cube-enterprise）でスキーマが同一の構成である。DB関連の記述は移行先を正とし、確認できた対応を以下に記録する。応答のうち関連カード・アーキタイプ・デッキ・イベント詳細は記事との中間テーブル（dtb_article_card・dtb_article_archetype・dtb_article_deck・dtb_article_event_detail）を介して取得する。記事は dtb_article.deleted_at による論理削除であり、削除済みは応答対象外とする。

概要

外部連携先（任意門・PointGranter）からの呼び出しを受けて、スマレジの取引APIへ中継し、取引更新時に会員のポイントを付与してポイント履歴を登録するAPIである。pf-eccube3（EC-CUBE3系）のHareruyaEcプラグインが買取アプリ用APIの一部として提供するJSON APIである。

本機能のカスタマイズ区分は現行踏襲であり、挙動は現行実装（pf-eccube3）を参照し、DB関連はec-cube-enterpriseを正とする。

本書は実装手順ではなく、誰が・いつ・どの条件で・結果どうなるかを読むためのリバース詳細設計とする。確認値はpf-eccube3のPointGranter連携処理、ルート定義（買取アプリ用APIのルート登録）、スマレジ顧客連携サービス、会員ポイント・ポイント履歴を扱うリポジトリを正とする。

対象はJSON APIエンドポイントであり、ブラウザ向けの画面を持たない。本文ではフレームワークのコントローラ型名やメソッド名を主説明としない。「利用者視点の入口」にHTTPメソッドとパスパターンを書く。

本書で扱うこと

  • 連携先からの取引要求のスマレジ取引APIへの中継
  • 取引更新時の会員ポイント付与とポイント履歴の登録
  • ヘッダ・パラメータ不足時、連携結果が不正な場合の応答

本書で扱わないこと

以下は本書では仕様確定せず、実装または別機能の設計を正とする。

  • スマレジ取引APIそのものの仕様・応答構造（スマレジ連携の設計・連携先仕様を正とする）
  • 任意門・PointGranter側の処理仕様
  • ポイントの利用・失効・他経路での付与（ポイント機能・各バッチの設計を正とする）

リニューアル移行時の扱い

現行（pf-eccube3、EC-CUBE3系）と移行先（ec-cube-enterprise、EC-CUBE4系）でポイント関連のスキーマが異なる。DB関連の記述は移行先を正とし、確認できた対応を以下に記録する。

処理フロー

PointGranter連携を行う（POST /admin_api/point_granter）

  1. リクエストヘッダの契約ID・アクセストークンと、本文の処理名・パラメータを受け取る。いずれかが欠落する場合は入力不正（HTTP 400）とし、空の本文を返す。
  2. 契約ID・アクセストークンを付与して、スマレジ顧客連携サービスへ処理名とパラメータを渡し、取引APIへ中継する。
  3. 中継結果に結果キーが含まれない場合は入力不正（HTTP 400）とし、結果をそのまま返す。
  4. 処理名が取引更新（transaction_upd）の場合、パラメータの先頭行から会員（スマレジ会員IDで特定）を引く。会員が見つからない場合はポイント付与を行わず、コード200で結果を返す。
  5. 会員が見つかった場合、会員ポイントに付与ポイントを加算し、ポイント履歴（会員・増減ポイント・メモ・発生日時・ポイント種別）を登録して保存する。
  6. 中継結果をコード200で返す。

応答値成功時は処理結果コードまたは更新後に取得した値を返す。レスポンス値は本API内で独自集計せず、保存結果または取得結果をJSON応答へ整形する。

処理フロー

商品IDで商品詳細を取得する（GET /product/detail/{productId}）

  1. パスの商品IDと、クエリの言語を受け取る。言語が未指定の場合は日本語を既定とする。

  4. 各明細について週間販売数を合算する。
  5. 各明細のうち、良品（NM）または価格が表示下限以上のものだけを商品規格として加え、画像はファイル名からURLへ変換して並べる。

リニューアル移行時の扱い

DB関連はec-cube-enterpriseを正とする。商品（dtb_product）・商品規格（dtb_product_class）・商品規格画像（dtb_product_class_image）・カード（mtb_card）・カード詳細（mtb_card_detail）はec-cube-enterpriseに同名で実在する。一方、本APIが現行（pf-api）で参照する商品サブクラス（dtb_product_sub_class）のビューと商品サブクラス画像（dtb_product_sub_class_image）は、ec-cube-enterpriseでは商品規格・商品規格画像（dtb_product_class_image）系へ再編されており同名ビューを確認できない。商品名検索・一意化・画像URL生成に用いる該当テーブル・列はec-cube-enterprise実装で要確認とする。挙動（検索条件・コンディション絞り込み・最大100件・該当なし時の応答）は現行（pf-api）を正とする。

処理フロー

商品名で商品詳細を取得する（GET /product/search）

  1. クエリの商品名を受け取る。未指定の場合は該当なし（HTTP 404）とする。
  2. 商品名から対象の商品ID群を取得する。該当が無い場合は該当なし（HTTP 404）とする。
  3. 対象の商品サブクラス情報を取得する。該当が無い場合は該当なし（HTTP 404）とする。
  4. 商品ID・言語・高額商品コードの組み合わせを単位に商品をまとめ、商品ごとにカテゴリ・地域制限・商品名を設定する。カード詳細を持つ商品は商品名の先頭に言語コードを付す。
  5. 各商品規格について、良品（NM）または価格が表示下限以上のものだけを商品規格として加え、画像はファイル名からURLへ変換して並べる。商品の件数が100件に達した時点で打ち切る。
  6. 商品ごとに、その他コンディションの表示可否を判定し、表示しない場合は良品（NM）の規格のみに絞る。
  7. コード200と商品配列をJSONで返す。

指標集計の要点
対象商品商品名に該当する商品サブクラスから、商品ID・言語・高額商品コードの組み合わせで一意化する。
表示する商品規格コンディションが良品（NM）の規格、または価格が表示下限（設定値）以上の規格のみを含める。

  • 検索・一覧・取得条件はリクエストパラメータ、ログイン状態、公開状態、店舗・支店条件、既存リポジトリの絞り込み順序を正とする。
