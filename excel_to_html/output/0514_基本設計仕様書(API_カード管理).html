処理概要（★はカスタマイズ項目）

カスタマイズ説明

・カスタマイズ要件
・MTGマスターデータの各テーブルで使用する「rank」列を「sort_no」に名称変更し、レスポンスデータ内の該当列も同様に変更する
・カード情報「固有色」が追加されるため、レスポンスデータ内に「color_identities」を追加する
・カード詳細情報「Foil」の設定値が増えるため、レスポンスデータ内の「foil_flg」を「foil」に変更する
・カード詳細情報「フレーム」が追加されるため、レスポンスデータ内に「frame」を追加する
・カード詳細情報「プロモフラグ」は「プロモ種別」に包含されるため、レスポンスデータ内の「promotion_flg」を除去する
・カスタマイズ要件に記載の内容以外は現行踏襲とする

機能仕様処理概要（★はカスタマイズ項目）

・指定されたカードIDでカード情報を返す
★カード情報「固有色」が追加されるため、レスポンスデータ内に以下1~4を追加する

1　color_identities

2　color_identities.id

3　color_identities.name_jp

4　color_identities.name_en

★以下のように、カード情報「Foil」の設定値に新しく 「2: 特殊」 が追加されるため、レスポンスデータの 「card_details.foil_flg」 を「card_details.foil」へ変更

現行仕様

A14-01 カードIDからカード情報を取得 / API カード管理 — カードIDからカード情報を取得

業務ロジック

応答に含めない関連情報

カードに紐づく情報のうち、カードタグ・キーワード能力・記事・デッキ収録カードは応答の対象ではなく、応答に一切現れない。カードIDで該当するカードが見つかった場合、応答対象の情報は条件を付けずにすべて返す。

入出力

値が無い項目の扱い

値が設定されていない項目も応答から省略せず、項目名を残したまま「値なし」として返す。関連情報が1件も無い場合も項目自体は残り、空の一覧として返る。

該当するカードが無いときの応答本文

該当するカードが存在しないときの応答本文は、コードとメッセージの2項目だけを持つJSONで、メッセージは「Not Found」の固定文字列。カード情報の項目は1つも含まれない。

A14-03 検索クエリに一致するカード情報1件を取得 / API カード管理 — 検索クエリに一致するカード情報1件を取得

業務ロジック

カード名の突き合わせ

カード名は完全一致で突き合わせる。前方一致・部分一致では該当しない。日本語名と英語名の両方を受け取ったときは、いずれか一方だけに一致するカードも該当として扱う。

分割カードは + でつないだ入力を想定する。カード名はURLデコードしたうえで日英に分け、そのあと + を / に置き換えて突き合わせる。%2B は + として解釈する。

カード名が一致しても、カード詳細・カードセット・カード画像のいずれかを持たないカードは該当として扱わない。

複数一致したときの選び方

条件に一致するカードが複数あるとき、および同じカードがカード画像を複数持つときは、次の優先順で並べた先頭の1件だけを返す。応答のカード画像URLもこの並びで決まる。

  1. 優先言語のカード画像を持つもの
  2. 特殊版でないもの
  3. 発売日が新しいもの
  4. フォイルでないもの
  5. プロモーションでないもの

優先言語は日本語と英語の2つで、カード言語に ja 以外の値を指定したときも英語になる。

入出力

入出力: 該当が無いときの応答本文

該当が無いときの応答本文は、コードとメッセージ「Not Found」を持つ。

表示メッセージ
