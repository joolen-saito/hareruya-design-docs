A16-01 トップバナーIDのトップバナー情報を取得 / API データ管理 — トップバナーIDのトップバナー情報を取得

概要

トップバナーIDを指定してトップバナー情報を取得するAPIである。pf-apiが提供するJSON APIである。TODOリストの「コンテンツ管理」（A08-01）と「データ管理」（A16-01）の同一エンドポイントをまとめる。

本書は実装手順ではなく、誰が・いつ・どの条件で・結果どうなるかを読むためのリバース詳細設計とする。確認値はpf-apiのトップバナー取得処理、ルート定義、トップバナーマスタを扱うリポジトリを正とする。本機能のカスタマイズ区分は現行踏襲であり、挙動はpf-apiの実装を参照し、DB関連（テーブル・列）の記述はec-cube-enterpriseを正とする。

対象はJSON APIエンドポイントであり、ブラウザ向けの画面を持たない。

本書で扱うこと

  • トップバナーIDによるトップバナー情報の取得
  • 該当が無い場合の応答

本書で扱わないこと

以下は本書では仕様確定せず、実装または別機能の設計を正とする。

  • 指定言語のトップバナー一覧取得（一覧取得APIを正とする）
  • トップバナーの設定・管理（トップバナー管理を正とする）

リニューアル移行時の扱い

本機能は現行踏襲であり、挙動の参照は現行のpf-api、DB関連の正はec-cube-enterpriseとする。テーブル名・列名は現行と移行先で一致する。移行先ではトップバナーマスタに表示用の追加列があるが、本APIの応答項目（ID・画像URL・リンク・表示タイプ・関連言語）には影響しない。

項目現行（pf-api）移行先（ec-cube-enterprise）扱い
トップバナーマスタmtb_top_banner（id・image_url・link・disp_type）mtb_top_banner（id・image_url・link・disp_typeに加え、image_alt・sort_no）同名テーブル。移行先は alt属性（image_alt）と表示順（sort_no）の列を持つ。本APIの応答には含めない。
言語関連dtb_top_banner_language（top_banner_id・language_id）dtb_top_banner_language（top_banner_id・language_id）同一スキーマ。トップバナーと言語の多対多関連。
言語マスタmtb_language（id・name_jp・name_en・code）mtb_language（id・name_jp・name_en・code・sort_no）同名テーブル。移行先は並び順（sort_no）の列を持つ。応答の言語名・言語コードに用いる。

利用者視点の入口

入口URLエンドポイント期待されるふるまい
トップバナーIDのトップバナー情報取得GET /topBanner/{id}トップバナーIDに対応するトップバナー情報をJSONで返す。該当が無い場合は404を返す。

応答形式はJSON。

処理フロー

トップバナー情報を取得する（GET /topBanner/{id}）

  1. パスのトップバナーIDを受け取る。
  2. トップバナーマスタのリポジトリから当該IDのトップバナーを取得する。
  3. 取得できない場合はコード404のJSONを返す。
  4. 取得できた場合はトップバナー情報をJSONで返す。

業務ルール・計算

項目内容
対象データリクエストで指定されたID・条件に一致するデータを取得対象とする。抽出条件と該当なし時の扱いは処理フロー・入出力の各節を正とする。
計算処理本APIでは金額・税・ポイント・在庫数量の再計算や丸めを行わない。DBまたはリポジトリから取得した値をJSON応答へ整形して返す。
応答値応答フィールドは取得時点の値を返す。表示用の加工やフロントエンド側の表示制御は呼び出し元クライアントの設計を正とする。

入出力

リクエスト

パラメータ位置型必須／任意説明
idパスinteger必須取得対象のトップバナーID。

レスポンス（成功）

HTTP 200。

フィールド型説明

レスポンス（失敗）

HTTPステータス条件本文の形

データ整合性

DBカラム

機能に直接関係する範囲のみ記載する。テーブル名・列名はec-cube-enterpriseを正とする。

テーブル列メモ

操作種別対象テーブル契機・条件

権限・認可

排他制御・トランザクション

本APIは参照のみであり、楽観ロック・悲観ロックの対象は持たない。
