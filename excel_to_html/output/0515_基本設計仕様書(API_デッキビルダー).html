A15-01 ログイン ／ API デッキビルダー — ログイン

業務ロジック

認証の判定順序

順序判定結果
1メールアドレスとパスワードが必須・形式を満たすか満たさないときは入力不正として返す
2メールアドレスに一致し、本会員かつ未削除の会員があるか無いときは認証拒否として返す
3入力パスワードを会員のソルトでハッシュ化した値が保存値と一致するか一致しないときは認証拒否として返す
4上記を通過アクセストークンを発行する

会員が無いときとパスワードが一致しないときで同じメッセージを返し、いずれであるかを区別しない。

トークンの発行

会員IDを利用者IDとする署名付きのアクセストークンを発行する。内容は発行者・利用者ID（会員ID）・発行時刻とする。署名方式はHS256とする。

トークンは有効期限付きのCookieに設定し、セッションを開始する。

トークンの原値・署名シークレット・パスワードは本書に記載しない。

以降の認可

呼び出し元は受け取ったアクセストークンを、以降のデッキビルダーAPIの認証ヘッダに付与する。各APIはトークンの利用者ID（会員ID）からプレイヤーを引いて認可する。認可の内容は各APIの設計を正とする。

認証の要否

本APIはトークン取得の入口であり、認証ヘッダを要求しない。未認証のクライアントが呼び出せる。なりすまし対策トークンの検証は行わず、定義外の追加項目を許容する。

更新しないもの

ログイン時に金額・ポイント・在庫などの業務値は計算しない。認証失敗、退会・停止・権限不足のときは業務データを更新しない。

入出力

種類内容
入力会員のメールアドレス（必須、メールアドレス形式）と会員のパスワード（必須、半角の表示可能文字のみ）。
成功時出力HTTP 200。結果コード200、結果メッセージ、発行したアクセストークン、開始したセッションのID。
失敗時出力入力検証に失敗したときはHTTP 400。会員が無いかパスワードが一致しないときはHTTP 401。いずれも結果コードと結果メッセージを返す。処理中の例外はデッキビルダーAPIの共通例外処理に委ねる。

入出力: 永続化

会員・注文・ポイントなどの業務データは更新しない。

A15-03 ユーザー情報参照 ／ API デッキビルダー — ユーザー情報参照

業務ロジック

取得対象

デッキユーザーIDの指定が無いときは、認証したプレイヤー自身の情報を返す。返す値はニックネーム・プロフィール・デッキユーザーIDで、いずれも未設定のときはnullとする。デッキユーザーIDの指定があるときは他ユーザー情報参照の分岐となり、本書では扱わない。

認証

認証用トークンのヘッダを検証し、対象者の顧客IDからプレイヤーを特定する。署名方式はHS256である。ヘッダ欠落・署名不正・該当するプレイヤーなしのいずれも認証拒否（HTTP 401）とする。認証を通ったのちに対象プレイヤーを取得できないときは入力不正（HTTP 400）とする。

呼び出し可能なクライアントはデッキビルダーアプリである。返すのは認証したプレイヤー自身の情報だけである。トークン原値・署名シークレットは本書に記載しない。

エラー時の扱い

エラー内容処理
認証不可認証拒否（HTTP 401）とし、コードとメッセージを返す
対象プレイヤーが取得できない入力不正（HTTP 400）とし、「Invalid request parameters」を返す

入出力

種類内容
入力認証用トークンのヘッダ（必須）。デッキユーザーID（任意、指定すると他ユーザー情報参照の分岐となる）
成功時出力HTTP 200。処理結果コードとニックネーム・プロフィール・デッキユーザーIDを含むラッパオブジェクト。キーは区切り記号付きの小文字で組み立てる
失敗時出力認証できないときはHTTP 401で「Access Token is incorrect」または「Authentication failed」。対象プレイヤーを取得できないときはHTTP 400で「Invalid request parameters」

出力: フィールド

フィールド型説明
codeinteger処理結果コード。成功時は200。
user_namestringプレイヤーのニックネーム。未設定の場合はnull。
profilestringプレイヤーのプロフィール。未設定の場合はnull。
deck_user_idstringプレイヤーのデッキユーザーID。未設定の場合はnull。

成功時の応答例（実装確認値に基づく代表値）。

{
  "code": 200,
  "user_name": "デッキ太郎",
  "profile": "スタンダードを中心に遊んでいます。",
  "deck_user_id": "AB12CD34"
}

入出力: 永続化

本APIは業務データを更新しない。

A15-04 他ユーザー情報参照 ／ API デッキビルダー — 他ユーザー情報参照

業務ロジック

取得できる条件

クエリにデッキユーザーIDが指定されているときは、この分岐で処理する。デッキユーザーIDに一致するプレイヤーを1件取得する。該当するプレイヤーがないときは入力不正（HTTP 400）とし、メッセージ「Invalid request parameters」を返す。該当が無いときもHTTP 404ではなく入力不正（HTTP 400）で返す。

認証を行わない分岐

デッキユーザーIDを指定するときは認証トークンを検証しない。トークンに起因する認証拒否（HTTP 401）は発生しない。デッキユーザーIDを知る呼び出し元であれば、そのプレイヤーの公開向け情報だけを取得できる。公開向け情報はニックネーム・プロフィール・デッキユーザーIDとする。呼び出せるのはデッキビルダーアプリだけである。トークンの原値と署名の秘密値は本書に記載しない。

値の取り方

金額・税・ポイント・在庫数量の再計算と丸めを行わない。取得できたときは、その値をそのまま応答へ整形して返す。応答の各項目は取得時点の値とし、未設定のときはnullとする。表示用の加工と表示制御は呼び出し元の設計による。応答本体はラッパオブジェクトで、キーはスネークケースで組み立てる。

エラー時の扱い

事象扱い
デッキユーザーIDに一致するプレイヤーがないとき入力不正（HTTP 400）とし、メッセージ「Invalid request parameters」だけを返す

入出力

種類内容
入力デッキユーザーID（クエリ、この分岐では必須）。認証トークン（ヘッダ）は任意で、この分岐では検証しない
成功時出力HTTP 200。処理結果コード200と、プレイヤーの公開向け情報
失敗時出力HTTP 400。処理結果コードとメッセージ「Invalid request parameters」

出力: プレイヤーの公開向け情報

項目型内容
ニックネームstring未設定のときはnull
プロフィールstring未設定のときはnull
デッキユーザーIDstring未設定のときはnull

入出力: 永続化

本APIはデータを更新しない。

A15-05 ユーザー情報変更 ／ API デッキビルダー — ユーザー情報変更

業務ロジック

更新対象

認証トークンの利用者識別子に対応する顧客からプレイヤーを特定し、そのプレイヤー自身の情報のみを更新する。他プレイヤーの情報は更新できない。トークンを検証できないとき、該当するプレイヤーが無いときは認証拒否（HTTP 401）とする。

更新する内容

プレイヤーのニックネームを受け取ったユーザー名で、プロフィールを受け取った値で更新する。ユーザー名が未指定のときは入力不正（HTTP 400）とし、更新しない。プロフィールが未指定のときはnullとして保存する。更新中に例外が発生したときは更新を取り消し、処理失敗（HTTP 500）として例外メッセージを返す。

金額・税・ポイント・在庫数量の再計算や丸めは行わない。トークン原値・署名シークレットは本書に記載しない。

エラー時の扱い

エラー内容処理
認証不可認証拒否（HTTP 401）とし、処理結果コードとメッセージを返す
ユーザー名未指定入力不正（HTTP 400）とし、「Invalid request parameters」を返す
更新中の例外更新を取り消し、処理失敗（HTTP 500）として例外メッセージを返す

入出力

種類内容
入力認証トークン、ユーザー名、プロフィール
成功時出力HTTP 200。処理結果コード200とメッセージ「Update user information」
失敗時出力HTTP 401（認証不可）、HTTP 400（ユーザー名未指定）、HTTP 500（更新中の例外）

入力: リクエスト

パラメータ位置型必須／任意説明

user_nameボディstring必須設定するニックネーム。未指定（null）の場合は入力不正（HTTP 400）となる
profileボディstring任意設定するプロフィール。未指定の場合はnullとして保存する

出力: レスポンス（成功）

応答本体のJSONキーはスネークケースで組み立てる。

フィールド型説明
codeinteger処理結果コード。成功時は200
messagestring結果メッセージ。成功時は「Update user information」
{
  "code": 200,
  "message": "Update user information"
}

出力: レスポンス（失敗）

HTTPステータス条件本文の形

400ユーザー名が未指定（null）メッセージは「Invalid request parameters」
500更新中に例外が発生（保存失敗）メッセージは例外メッセージ。更新は取り消す

入出力: 永続化

操作契機
更新ユーザー情報変更時に、プレイヤーのニックネームとプロフィールを更新する

A15-06 マスタ検索 ／ API デッキビルダー — マスタ検索

業務ロジック

取得するマスタの決定

受け取ったマスタ名はアンダースコア区切りの文字列とし、キャメルケースへ変換して先頭を大文字にしたマスタ識別名に読み替える。追加公開対象（カテゴリ・カテゴリ並び順・会員区分・割引カード条件・タグ並び順）のときは業務データ側のマスタを、それ以外のときは区分値のマスタを対象とする。マスタ識別名に対応するマスタが存在しないとき、または公開しないマスタ（権限・カード・カード詳細）を指定したときは、該当なしとして扱う。

取得の範囲

対象マスタ取得する範囲
フォーマットデッキビルダー対象の区分が立つものだけ
カテゴリ・タグサブテーブルを含めて取得する
上記以外全件を取得する

認証

認証を行わない。トークンの検証も会員・プレイヤーの照合も行わないため、認証を理由とする拒否は返さない。呼び出し元はデッキビルダーアプリで、利用者の状態によらず参照できる公開マスタを返す。

応答の値

条件・公開状態・絞り込みの順序は取得元のマスタの定義に従う。件数・並び順は取得後に再計算しない。金額・ポイント・数量・ステータス・日時は保存済みの値をそのまま返し、応答生成時の丸め・補正は行わない。条件に一致しないデータは空の結果として返す。

エラー時の扱い

事象扱い
公開対象でない、または存在しないマスタ名コード404とメッセージを持つJSONを返す
取得処理中の例外共通の例外処理に委ねる（HTTP 500相当）

入出力

種類内容

成功時出力HTTP 200。処理結果コードとマスタ行の配列
失敗時出力HTTP 404（公開対象でない・存在しないマスタ名）、HTTP 500（取得処理中の例外）

入出力: リクエスト

nameパスstring必須マスタ名。アンダースコア区切りの文字列を受け取り、キャメルケース化・先頭大文字化してマスタ識別名に変換する。対象は区分値マスタ全般（カード種別・サブタイプ・レアリティ・色・フォーマット・デッキタグ・キャンペーンタグ・特殊種別など）と、追加公開対象の業務データ側マスタ（カテゴリ・カテゴリ並び順・会員区分・割引カード条件・タグ並び順）。権限・カード・カード詳細は公開しない

入出力: 応答フィールド

フィールド型説明
codeinteger処理結果コード。成功時は200
resultsarrayマスタ行の配列。要素は対象マスタの公開プロパティで構成するオブジェクト
results[].（各プロパティ）対象マスタ依存各マスタで公開設定されたプロパティ。キー名はcamelCase。構成はマスタごとに異なり、フォーマットなら識別子・日本語名・英語名・デッキビルダー対象の区分、色なら識別子・名称などとなる

サブテーブルを持つマスタ（カテゴリ・タグ）では、要素内に子要素の配列を含む。

本機能はデータを更新しない。

A15-07 アーキタイプ検索 ／ API デッキビルダー — アーキタイプ検索

認証

A15-17 デッキ登録インポート ／ API デッキビルダー — デッキ登録インポート

業務ロジック

登録対象

パスにデッキ識別子を持たないときは新規デッキを対象とする。既存デッキの取得と所有者の照合は行わない。認証したプレイヤーを新規デッキの所有者として登録する。

カードリストの解読

フォーマットの識別子からフォーマットを取得し、そのフォーマットの統率者使用設定に応じてカードリストを解読する。カードリストは枚数とカード名の行を並べた形式とする。未指定または空のときは空のカード配列として扱う。

カードリストの行数が500行を超えるときは入力不正（HTTP 400）とする。

カード名が一致せず解読できない行があるときは、登録は完了させたうえで処理結果コードを206に切り替え、該当行の行番号を返す。行番号は0から数える。

登録の可否

解読したカードとデッキ名・公開区分・アーキタイプ等で新規デッキを組み立て、検証を通過したときだけ保存する。検証エラーは入力不正（HTTP 400）、その他の例外は処理失敗（HTTP 500）とする。

保存したときは、当該デッキの下書きとして保持している一時保存も削除する。

応答の内容

新規デッキの識別子を返す。公開区分が限定公開のときだけ、表示用トークンをあわせて返す。限定公開以外のときは表示用トークンを返さない。

他機能との境界

認証用トークンを検証し、トークンに含まれる顧客IDからプレイヤーを引く。署名方式はHS256とする。トークンが無い、署名が不正、該当するプレイヤーが無いときは、いずれも認証拒否（HTTP 401）とする。呼び出し可能なクライアントはデッキビルダーアプリとする。トークンの原値と署名シークレットは本書に記載しない。

エラー時の扱い

カードリストの解読

カードリストは、枚数とカード名の行を並べたテキストである。指定されたフォーマットの統率者使用設定に応じて解読し、カードの配列に変換する。カードリストの行数の上限は500行で、超過時は入力不正（HTTP 400）とする。カードリストが未指定または空のときは、空のカード配列として扱う。

カード名が一致せず解読できない行があるときも更新は完了させ、処理結果コードを206に切り替えて該当行の行番号を応答に含める。行番号は0始まりとする。
