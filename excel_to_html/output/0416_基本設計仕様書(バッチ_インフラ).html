カスタマイズ説明

概要

記事管理サーバのWordpress主要ファイルをS3へ転送・同期

機能

記事管理サーバのWordpressファイルにあるファイル群をS3バケットに保存されているWordpressファイルに転送・同期する

実行環境

記事(Wordpress)用EC2インスタンス

機能仕様処理概要（★はカスタマイズ項目）

同期対象

・同期対象は下記ディレクトリ内にある全ファイルを同期を行う

[Wordpress Rootディレクトリ]/wp-content/themes

Wordpressのテーマ(晴れる屋の記事ブログページデザインなど)が保存されているディレクトリ

[Wordpress Rootディレクトリ]/wp-content/plugins

Wordpressで使用されているプラグイン(記事画像をS3に保存するプラグインなど)が保存されているディレクトリ

・同期の際、下記のような条件で同期が行われる
・ファイルやディレクトリの作成・更新日(タイムスタンプ)の同期チェック(exact-timestamps)

ローカルとS3のファイルで作成・更新日(タイムスタンプ)が一致しないときにはファイルの同期が行われる

・ファイルやディレクトリが削除された場合の同期(delete)

ローカル内のディレクトリもしくはファイルがない場合、同様にS3内にあるファイル・ディレクトリが削除される

実行トリガー　Crontab　実行タイミング　毎分

入力データ元　記事管理サーバ内Wordpress該当ディレクトリ　出力先(フォーマット)　AWS S3

概要

機能

晴れる屋EC-CUBEのWAFで不正アクセスと判断されたログを取得し

処理結果をS3にアップロードおよびSlack通知を行う

実行環境

バッチ処理用EC2インスタンス

機能仕様処理概要（★はカスタマイズ項目）

機能仕様処理内容

・晴れる屋EC-CUBEのWAFで不正アクセスした際に生成されるログを元に、前日分のログ統合・集計を行う。
・対象のサーバは下記の通りになります
サーバ種別ロードバランサ―名WAF名S3ログ転送先
本店ECフロントサーバ(ECFront)ELB-EC-ProdIP_Block_ListS3://aws-waf-logs-prod-hareruyaec

本店ECフロントサーバ読込専用(ECReadFront)

デッキ構築SPAサーバ(PROD_DeckSPA)

デッキAPI(PROD_Deckbuilder-API)　PROD-deckbuilder-api　Rate-Base-blocker-for-deckapi　S3://aws-waf-logs-prod-deckapi

・下記のサーバは集計の対象外となります
サーバ種別ロードバランサ―名WAF名S3ログ転送先
記事サーバ(Article)ELB-Article-ProdArticle_IP_Block-
APIサーバ(PROD_API)API-Prod--
ステージング用ECフロントサーバSTG-Branch-Admin-ELBstg-all-search-blocker-
・S3に保存されているログから前日分の不正アクセスログをローカルに一時保存する。

取得先S3パス S3://[ログ保存先バケット]/AWSLogs/641007440821/WAFLogs/ap-northeast-1/IP_Block_List/[YYYY]/[MM]/[DD]

※上記パス以降の時刻ディレクトリ(HH/MM)をすべて取得

・取得したログを1日分のログファイルに纏め、gzip形式でファイルを圧縮してS3に保存する

保存先S3パス S3://[ログ保存先バケット]/YYMMDD_result.gz

・1日分のログファイルから、ブロックしたIPアドレスおよび出現回数を集計する
・集計結果を2通りの処理を行う
・集計結果をファイルに保存して、S3に保存する

保存先S3パス S3://[ログ保存先バケット]/YYMMDD_attach

・集計結果をSlack通知用メールサービスを使い、Slackチャンネルに通知する

実行トリガー　スケジュール起動(Step Functions)　実行タイミング　毎日4時

概要
月末に店舗・商品規格ごとに一部の事項を抽出し、集計結果をS3に保存する
処理概要（★はカスタマイズ項目） 処理内容

カスタマイズ説明

概要

月初に店舗・在庫場所・商品規格ごとに一部の事項を抽出し、結果をS3に保存する

本店支店含め全店舗出力を行う

実行環境

バッチ処理用EC2インスタンス

機能仕様処理概要（★はカスタマイズ項目）

機能仕様処理内容

①　本番DBの最新スナップショットを取得する

★現行はprd-branch-db-clusterという名称でスナップショットの検索を行い、最新のものを取得しているが、リニューアル後の環境に合わせる

②　一時的なDBクラスタとインスタンスの作成

・抽出したスナップショットからクラスタを復元
・名前はmonthly-inventory-checkとする
・クラスタ内にDBインスタンスを作成する
・名前はrestore-for-inventoryとする
・データベースが完全に立ち上がり利用可能になるまで30分のスリープを入れる ※30分で終わらないようであれば延ばす

③　一時的なDBインスタンスに対してクエリを実行し、実行結果をZIPに圧縮する

・以下の条件で取得を行う
★商品規格の公開フラグが1: 公開となっているもの（現行だとvisibleを見ているので、見るカラムを変更する）
★商品在庫に紐づく店舗が閉店でないこと（現行だとテスト店舗フラグを見ているが、テスト店舗フラグはなくなるので、見るカラムを変更する）
★本店支店含め全店舗出力を行う（現行は本店と支店でDBが分かれていたためそれぞれ出力していたが、リニューアル後は統一されるため全店舗出力を行う）
・出力項目は以下とする
・商品コード
・販売価格
・買取価格
・店舗名
★在庫区分名（ECCUBEまたはスマレジ、在庫は店舗ごと在庫区分ごとに持つため必要となる）
・在庫数
・並び順は以下とする
・店舗IDの昇順、在庫区分名（EC、スマレジの順）
・ZIPファイルの名前は以下とする
★stock_YYYYMMDD.txt.zip（現行はbranch_YYYYMMDD.txt.zipだが、支店のみの在庫を出すわけではないため）

④　③で作ったZIPファイルをS3にアップロードする

・アップロード先のバケットはs3://inventorycheck/とする

⑤　②で作成した一時的なDBクラスタとインスタンスを削除する

実行トリガー　スケジュール起動(Step Functions)　実行タイミング　毎月1日 午前1時

概要

EC-CUBE 同期ディレクトリ処理バッチ

機能

実行環境

ECサーバFargate

※ECRからECサーバFargateを読み込みFargateで実行

※バッチ処理用EC2インスタンスからAWS Systems Manager Run Commandを使ってバッチ起動

機能仕様処理概要（★はカスタマイズ項目）

機能仕様処理内容

・ファイル同期処理スキップ

同じバッチが同時に起動しないように、ロックファイル有無チェックを行い、存在する場合には処理を終了する。

存在しない場合には、ロックファイルを作成し、バッチが終了(強制終了・異常終了含む)した場合にファイル削除を行う。

★S3バケットとEC-CUBE特定ディレクトリの同期処理

下記S3パスおよびディレクトリおよびファイルの同期処理を行う

・S3パス : s3://[S3バケット名]/app/template/default　→　EC-CUBE 同期ディレクトリ : /var/ec-cube/app/template/default
・S3パス : s3://[S3バケット名]/app/template/user_data　→　EC-CUBE 同期ディレクトリ : /var/ec-cube/app/template/user_data
・S3パス : s3://[S3バケット名]/html/user_data　→　EC-CUBE 同期ディレクトリ : /var/ec-cube/html/user_data
★S3パス : s3://[S3バケット名]/html/sitemap.xml　→　EC-CUBE 同期ディレクトリ : /var/ec-cube/html/sitemap.xml
※カスタマイズ時にサイトマップ同期も当スクリプトに追加
※S3バケット名は環境設定で指定します
・同期条件および処理は以下の通り
・S3内ファイルに新しいファイルがある場合、ファイルダウンロードを行う
・S3内ファイルと同期ディレクトリ内ファイルの更新タイムスタンプが違っている場合、ファイルダウンロードする(exact-timestampsオプション)
・S3内にあったファイルが削除された場合、同期ディレクトリ内にあるファイルも削除する(deleteオプション)
・同期対象のファイルがあった場合、下記の処理を行う
・同期ログをCloudWatchへ送信
・ファイル権限の再設定
・EC-CUBEのキャッシュクリア

実行トリガー　起動直後・EC2経由の実行(AWS Systems Manager Run Command)　実行タイミング　毎分

概要

晴れる屋フロント側のサイトマップを作成し、S3バケットにアップロードを行う

機能

晴れる屋トップページからリンクを辿りながらアクセス可能なURLのリストからサイトマップファイルを作成し、S3にファイルをアップロードする、

実行環境

バッチ処理用EC2インスタンス

機能仕様処理概要（★はカスタマイズ項目）

前提条件

・EC-CUBEの標準機能ではなく、公開されているコード(オープンソース)を利用

(現在のEC-CUBEシステムでも利用していることを確認済み)

Sitemap-Generator-Crawler

機能仕様処理内容

・Sitemap-Generator-Crawlerを使ったサイトマップ作成
・晴れる屋トップページ(https://www.hareruyamtg.com/)にアクセスし、取得ページを解析しアクセス可能なリンクURLを抽出
・抽出したリンクURLにアクセスにして更にリンクURLを取得してそのURLにアクセスする処理を繰り返す
・抽出するリンク先がなくなり次第、今までアクセスしたURLリストを使い、サイトマップファイルを作成する
※全部のリンクを取得するように設定(階層設定なし)
・但し、以下のページおよびそれ以降のページは取得しない
・管理ページ
・商品検索ページ(日本語・英語)
・カードリスト購入ページ(日本語・英語)
・デッキ検索ページ(日本語・英語)
・イベント情報(日本語・英語)
・前回(昨日)のサイトマップと今回作成したサイトマップを比較し、差異がある場合はS3にアップロードする
★カスタマイズ前に使用していたバッチで行っていた「サイトマップの ping エンドポイント」は2023年にサービス終了しているため

カスタマイズ後のバッチには含めない

https://developers.google.com/search/blog/2023/06/sitemaps-lastmod-ping?hl=ja#sitemap-ping

本番データベースのスナップショットからステージング用にカスタマイズし、ステージングデータベースを作成する

機能仕様処理概要（★はカスタマイズ項目）

機能仕様処理内容

・本番データベースのスナップショットを取得する
・テンポラリデータベースを作成し、本番データベースのスナップショットを挿入する
・テンポラリデータベースからスマレジIDおよびスマレジトークンを削除する

・ステージングデータベースにステージング用スマレジIDを追加する
・本番S3バケットにある商品画像をステージングS3バケットにある商品画像と同期を行う

S3バケット s3://filepool-resized/productのファイル内容を s3://stg-filepool-resized/product へ同期

・本番S3バケットにある絵文字(シンボル)をステージングS3バケットにある絵文字(シンボル)と同期を行う

S3バケット s3://filepool-resized/setのファイル内容を s3://stg-filepool-resized/set へ同期

・個人情報はマスク処理を行う

追記情報

・データベースのスナップショットやリストア処理が必要であり、バッチ内に処理待ち時間(インターバル)が含まれているため

概要

データベース内でデッドロックを感知した場合、管理者メールアドレスに通知を行う

機能

注文テーブルでデッドロック発生時、管理者メールアドレスにデッドロック発生通知および詳細情報を送信する

デッドロックとは、複数のものが互いに相手が持っているものを待っている状態のことです。

この状態になると、誰も先に進むことができず、全体が停止してしまいます。

※このバッチではデッドロック解除処理は含まれておらず、手動で解除する必要がある
