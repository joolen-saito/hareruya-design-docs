→店頭受取注文商品スマレジ連携（名称変更）
概要
スマレジ用商品コードの登録と連携を行う
処理概要（★はカスタマイズ項目）

カスタマイズ説明

・注文番号のコピー処理をバッチから除外する
・注文番号の採番処理を新たなデータベースに合わせて変更する（MySQL→PostgreSQL）
・スマレジ連携APIについて、呼び出しを廃止予定のスマレジAPIからプラットフォームAPIに変更

機能仕様処理概要（★はカスタマイズ項目）

・現行でこのバッチは以下の2つの処理を行っている
・採番された注文番号を注文情報へコピーする処理

（注文ステータスが変更されたときに実行されるMySQLのトリガーで注文番号が注文番号採番専用テーブルにて採番されるため、コピーを行う）

・店頭受取注文の場合、スマレジ側に注文した商品の情報を連携する

現行

DB　Mysql

【開発申し送り】現在のトリガーSQL（MySQLに設定されている）

IF OLD.status IN (7, 8) AND NEW.status IN (1, 2) THEN

INSERT IGNORE INTO dtb_order_number(order_id) VALUES(OLD.order_id);

END IF;

上記の処理の理由とカスタマイズ理由

・注文が完了した順番で注文番号を付けたいため、注文IDとは別に注文番号を採番している
・注文番号を連番で採番する際、MySQLのPKを連番で採番する機能を使っているため、

新たなテーブル(dtb_order_number)を作成し採番を行っている

・採番用のテーブル(dtb_order_number)にデータ登録をする処理でデッドロックが起こる可能性はあるため、

データ登録の処理をなくした形にしたい

リニューアル後

DB　PostgreSQL

【開発申し送り】リニューアル後のトリガーSQL

IF OLD.status IN (7, 8) AND NEW.status IN (1, 2) THEN

NEW.order_number := nextval('order_number_seq');

END IF;

以上のカスタマイズにより、注文番号登録バッチから注文番号登録の処理を削除する

元々、注文番号登録バッチという名称であるがリニューアル後は注文番号登録を行わないため、

バッチ名称は「店頭受取注文商品スマレジ連携バッチ」に変更する。

支店側の「スマレジ商品登録バッチ」が同じ役割を持っており、今回本店で実装されるため不要になるので、実装を引き継ぐ形とする。

【開発申し送り】支店と本店のバッチを見比べながら作成する

★注文番号のコピー処理をバッチから除外する
★注文番号の採番処理（トリガー）を新たなデータベースに合わせて変更する（MySQL→PostgreSQL）
★以下の注文を対象にスマレジ商品コードの採番とスマレジ連携を行う

※現行の支店のスマレジ商品連携バッチと同仕様にする

※本店側のバッチは注文番号採番を行った注文に対してスマレジ連携を行っていたが、

連携時のエラーエラーメッセージをコンソールに出力する

種類内容
入力コマンド名

入出力: 永続化

機能仕様処理概要（★はカスタマイズ項目）

・購入完了メールの再送信と完了画面処理の再実施を行うバッチ
・ポイント利用のクレカ決済で、購入完了画面へ遷移する前にブラウザバックするとポイント減算されない不具合のため
・MySQLの名前付きロック機能で注文テーブルにロック（同一バッチで同時に処理しないようにする）をかける
・毎分起動されるため、前の処理が終わっていない場合（ロックを取得できない場合）は処理を終了する
★PostgreSQLではアドバイザリロック（勧告的ロック）で実現する
・処理対象として注文完了メールが送られていない注文を取得
・注文ステータスが「新規」「入金待ち」「ピック中」

・ポイント履歴を作成し、ポイント残高を減らす
・ポイント使用後のポイント残高をスマレジに連携する
★スマレジ連携APIについて、呼び出しを廃止予定のスマレジAPIからプラットフォームAPIに変更
・取得した処理対象の注文について、在庫履歴の登録を行う
・在庫履歴の登録は注文時に登録する内容と同様とする
・在庫自体は注文確認の時点で減らされているため、ここでは履歴の登録のみ行う

※在庫を減らす処理は本体とGMOプラグインに入っているが、履歴の登録は晴れる屋様のカスタマイズなので、本体やプラグインに手を入れないよう

注文完了画面で行っている

・取得した処理対象の注文について、注文完了メールを送信する
・メール送信後、メール送信履歴を登録する

B05-02 購入完了手続き再処理 / バッチ 受注管理 — 購入完了手続き再処理

業務ロジック

実行できる条件

同名のバッチが実行中のときは、未完了である旨を出力して終了する。開始時に排他の取得を試み、取得できないときは異常として終了する。二重に実行しない。

対象の受注

メールが未送信の受注を取得する。対象が無いときは何もせずに完了する。

受注1件ごとの処理

順序判定結果
1受注サブに消費ポイントがあり、かつポイント履歴が無いときポイント処理を行う
2受注サブに消費ポイントがあり、かつポイント履歴があるときポイント処理を重ねて行わない
3消費ポイントがあるときスマレジのポイント連携を別プロセスで実行する
4ポイントの処理を終えたとき8桁の受注番号を取得し、在庫履歴と販売数を更新して確定する
5更新を確定したとき注文完了メールを再送信する
6処理中に例外が発生したとき当該受注の更新を巻き戻し、エラーメッセージを出力して次の受注へ進む

受注ごとに処理をまとめて確定し、1件の失敗を他の受注へ波及させない。

再送するメールの言語

会員の都道府県が海外のときは英語、それ以外のときは日本語で再送する。

エラー時の扱い

事象扱い

排他を取得できないとき異常として終了する
受注の処理で例外が発生したとき当該受注を巻き戻し、エラーメッセージを出力して次の受注へ進む

B05-03 店頭注文番号初期化 / バッチ 受注管理 — 店頭注文番号初期化

業務ロジック

対象と処理

対象は店頭注文番号の全件とする。日付や状態による絞り込みは、いずれの場合も行わない。

順序処理内容
1全件削除件数によらず、店頭注文番号を全件削除する
2採番カウンタの初期化削除が終わったときに、次回の採番値を 1 へ戻す

対象が0件のときも、削除と採番カウンタの初期化を実行する。結果は、店頭注文番号が無い状態と、初期化済みの採番カウンタだけになる。

何度実行したときも結果は同じになる。冪等である。

集計と金額計算は、いずれの場合も行わない。

実行の影響

B05-08 スマレジEC受注連携エラー再連携 / バッチ 受注管理 — スマレジEC受注連携エラー再連携

業務ロジック

対象

スマレジ連携エラーフラグが立っているEC受注を対象とし、受注の連携情報と会員を取得する。対象が無ければ何もせず完了する。

再連携

受注ごとに、会員のスマレジIDとポイントでスマレジポイント連携をリトライする。成功したときは受注の連携エラーフラグを解除する。失敗したときは受注の連携情報へエラーメッセージを記録し、エラーフラグを残す。すべての更新を確定する。

流量制御

1秒あたりのリクエスト上限を超えないよう、受注ごとに短いインターバルを挟む。

エラー時の扱い

エラー内容処理
実行時の指定が本バッチと一致しない処理を行わずに終了する
連携失敗受注の連携情報へエラーメッセージを記録し、エラーフラグを残す

入出力

種類内容
入力バッチの実行指定
成功時出力連携に成功した受注のエラーフラグ解除
失敗時出力連携に失敗した受注へのエラーメッセージ記録

スマレジへは会員ポイントを再連携する。成功で連携完了、失敗でエラー内容を保持する。

入出力: 永続化

操作契機
更新再連携に成功したとき、受注の連携エラーフラグを解除する
更新再連携に失敗したとき、受注の連携情報へエラーメッセージを記録する

表示メッセージ

メッセージID表示位置画面上の文言表示条件後続処理

本バッチは画面へメッセージを表示しない。

B05-09 スマレジ取引連携エラー再連携 / バッチ 受注管理 — スマレジ取引連携エラー再連携

業務ロジック

取引情報の取得

スマレジ接続設定（接続先URL等）をオプションマスタから取得する。現在時刻を基準に取引参照のパラメータを組み立て、スマレジの取引参照を呼び出す。取得に失敗したときは失敗内容をログとコンソールに出力し、異常終了（戻り値1）する。取得結果が空のときは何もせず正常終了する。

連携の更新

取得結果があるときは、取引情報をもとに対応するスマレジ取引の連携を更新する。

エラー時の扱い

エラー内容処理
実行時の指定が本バッチと一致しない処理を行わずに終了する
取引情報の取得失敗失敗内容をログ・コンソールに出力し異常終了する
取得結果が空何もせず正常終了する

入出力

種類内容
入力バッチの実行指定、スマレジ接続設定
成功時出力取引連携の更新。結果が空のときは更新なし
失敗時出力取得失敗内容のログ・コンソール出力（異常終了）

入出力: 永続化

操作契機
更新取引情報を取得できたとき、対応するスマレジ取引の連携を更新する
