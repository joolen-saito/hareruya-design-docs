A02-01 ポップアップ用商品情報取得 / API 商品管理 — ポップアップ用商品情報取得

概要

記事内に表示する商品ポップアップ用に、商品IDと言語を指定して商品情報を取得するAPIである。pf-api（記事・買取連携用のAPIアプリケーション）が提供するJSON APIで、記事サイト等から呼び出される。

本書は実装手順ではなく、誰が・いつ・どの条件で・結果どうなるかを読むためのリバース詳細設計とする。確認値はpf-apiの商品ポップアップ取得処理、ルート定義（config/routes.yaml）、商品規格を扱うリポジトリを正とする。

本機能のカスタマイズ区分は現行踏襲であり、挙動の確認はpf-apiを参照する。DB関連の記述はec-cube-enterpriseを正とする方針だが、当機能が参照する商品サブ規格・カード詳細・カードコンディション等のHareruya独自テーブルはec-cube-enterpriseに該当が見当たらないため、現行（pf-api）の名称を残し「ec-cube-enterprise実装で要確認」とする。

対象はJSON APIエンドポイントであり、ブラウザ向けの画面を持たない。

本文ではフレームワークのコントローラ型名やメソッド名を主説明としない。「利用者視点の入口」にHTTPメソッドとパスパターンを書く。

本書で扱うこと

  • 商品IDと言語によるポップアップ用商品情報の取得
  • 該当が無い場合の応答

本書で扱わないこと

以下は本書では仕様確定せず、実装または別機能の設計を正とする。

  • 記事サイト側のポップアップ表示の仕様
  • 商品の登録・編集（商品管理を正とする）
  • ポップアップ用カード情報取得・旧商品IDによる取得（各APIを正とする）

リニューアル移行時の扱い

現行（pf-api）と移行先（ec-cube-enterprise）の差を記録する。永続化先の正典はec-cube-enterpriseとするが、当機能が参照するテーブルの一部はec-cube-enterpriseに該当が見当たらない。

商品規格dtb_product_class（price01・price02・stock）dtb_product_class（同名・price01・price02・stock を確認値とする）

商品規格（dtb_product_class）は現行と移行先で同名。商品サブ規格をはじめとするHareruya独自のカード関連テーブルはec-cube-enterpriseに対応する実装が見当たらないため、現行（pf-api）の名称を主とし、推測でスキーマ化せずec-cube-enterprise実装で要確認とする。

応答形式はJSON。記事サイト等のクライアントから呼び出される。

処理フロー

ポップアップ用商品情報を取得する（GET /popup/product/{lang}/{productId}）

  1. パスの商品ID・言語を受け取る。
  2. 商品規格のリポジトリから、当該商品ID・言語のポップアップ用商品情報を取得する。
  3. 取得できない場合はコード404・メッセージ「Not Found」のJSONを返す。
  4. 取得できた場合は商品情報をJSONで返す。

業務ルール・計算

計算処理本APIでは金額・税・ポイント・在庫数量の再計算や丸めを行わない。DBまたはリポジトリから取得した値をJSON応答へ整形して返す。
