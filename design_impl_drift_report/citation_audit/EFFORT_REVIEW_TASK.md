# 改修区分と工数見積の批判的レビュー

各乖離指摘に「何を直すことになるか」の区分(①〜⑧)と工数を付けた。
これは**語のスコアによる機械分類**であり、1件ずつ人が読んで決めたものではない。
無作為30件の自己点検で5〜6件(約2割)が誤分類で、**誤りは重い区分へ寄る傾向**があった。

あなたの仕事は**その分類と工数を疑い、誤りを見つけること**である。追認は目的ではない。

## 区分の定義と代表工数（実装のみ・人日）

| 区分 | 名称 | 直す対象 | 下限 | 標準 | 上限 |
|---|---|---|---:|---:|---:|
| 1 | 外部インタフェース契約 | URL・HTTPメソッド・ステータス・レスポンス本文・CSV列/ヘッダ・コマンド名 | 0.25 | 0.5 | 1.5 |
| 2 | 画面表示 | 文言・ラベル・表示項目・並び・活性制御（Twig/翻訳ファイルの修正で済む範囲） | 0.1 | 0.25 | 0.5 |
| 3 | データ永続化 | 保存先テーブル/カラム・永続値・削除方式。**マイグレーションや既存データ移行を伴う** | 1.0 | 3.0 | 8.0 |
| 4 | 入力検証 | 必須・桁・形式・範囲・重複・相関チェックの追加/修正 | 0.25 | 0.5 | 1.5 |
| 5 | 業務ロジック | 抽出条件・計算・ステータス遷移・分岐の修正 | 0.5 | 2.0 | 5.0 |
| 6 | 未実装機能 | 画面・ルート・バッチ・処理**そのもの**の新規実装 | 2.0 | 5.0 | 15.0 |
| 7 | 外部連携・副作用 | スマレジ/S3/SFTP/メール送信/支店通知/監査ログの追加・変更 | 1.0 | 3.0 | 8.0 |
| 8 | 実行制御 | トランザクション境界・排他・実行環境設定・同期/非同期 | 0.5 | 2.0 | 5.0 |

工数はすべて**実装のみ**。テスト・レビュー・設計書改訂・リリース作業は含めない。

## 判定の考え方

**区分は「指摘の話題」ではなく「直すために触るもの」で決める。**

よくある誤りのパターン:
- 在庫・価格・ポイントという語が出るだけで ⑤業務ロジック にしている。
  実際は翻訳ファイル1行の修正なら ②。
- 「〜が実装されていない」という書き方だけで ⑥未実装機能 にしている。
  実際はフォームの初期値1行なら ②、バリデータ1個なら ④。
- バリデータの追加なのに ⑤ にしている（正しくは ④）。
- 画面のモーダル表示なのに ⑤ にしている（正しくは ②）。
- DBへ書く話なのに ⑦ にしている（マイグレーションを伴うなら ③）。

**逆方向（軽く見積もりすぎ）も探すこと。**
- ②に分類されているが、実は表示のために新しいデータ取得経路が要る → ⑤や⑥。
- ①に分類されているが、URLを変えると連携先(MTGバイヤー等)の改修も要る → 工数は上限側。

## 工数の見積もり方

区分の代表値をそのまま使うのではなく、**この1件を実際に直すなら何人日か**を答える。
判断材料は `差分内容` `設計期待値` `実装参照` と、必要なら実コードを開いて確かめた範囲。

- 触るファイルが1つで、既存の似た実装をコピーできる → 下限側
- 影響範囲が複数画面・複数経路に及ぶ、既存データの移行が要る、
  外部システムとの調整が要る、仕様の確認が先に要る → 上限側
- **仕様が確定していない（設計が矛盾している等）ものは工数を出さず `needsDecision: true`**

## 出力

指示されたJSONファイルに **Write して** 書き込む。

```json
{
  "packetId": "...",
  "results": [
    {
      "rowId": 123,
      "authorCat": "5",
      "verdict": "UPHELD",
      "correctedCat": null,
      "effortDays": 2.0,
      "effortBasis": "何を触るか。触るファイル数・既存実装の流用可否・影響範囲",
      "needsDecision": false,
      "reason": "区分をそう判断した根拠",
      "confidence": "high"
    }
  ]
}
```

- `verdict`: `UPHELD`（区分が正しい）/ `REFUTED`（誤り）/ `UNSURE`
- `correctedCat`: REFUTED のとき正しい区分番号("1"〜"8")。それ以外は null
- `effortDays`: **この1件の実装工数(人日)**。区分の代表値に引きずられず自分で見積もる
- `needsDecision`: 仕様が決まっておらず見積不能なら true（`effortDays` は 0 でよい）
- `confidence`: `high` / `medium` / `low`

findings 全件について返すこと（欠落禁止）。
