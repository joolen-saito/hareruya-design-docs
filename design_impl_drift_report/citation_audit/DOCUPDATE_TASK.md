# 設計書（正本Excel）の最新化工数の見積

乖離指摘 1,007件（クローズ済を除く）について、**設計書側にどんな作業が発生し、何人日か**を見積もる。
実装をどう直すかではなく、**設計書をどう直すか**だけを判断する。

## 前提: 正本はExcel、HTMLは生成物

| 役割 | パス |
|---|---|
| **正本Excel（編集対象）** | `/home/y-saito/Developments/hareruya-design-docs/excel_to_html/input/*.xlsx` |
| 生成HTML（読む用・編集対象ではない） | `/home/y-saito/Developments/hareruya-design-docs/excel_to_html/output/*.html` |
| 変換ツール | `excel_to_html/convert.py`（`uv run python convert.py`）、検証は `verify.py` |
| 実装 | `/home/y-saito/Developments/ec-cube-enterprise` |

**HTMLを直接編集しても次の変換で消える。** 直すのは常にExcelのセル・図形・画像である。
したがって見積もる対象は「該当シートの該当セル/表/画像をどう直すか」の作業量。

HTML再生成と検証は書籍単位でまとめて行うため、**1件ごとの見積には含めない**（別途固定費として集計する）。

## 判定する2つのこと

### 1. `docWork` — 設計書側にどんな作業が要るか

| 値 | 意味 |
|---|---|
| `NONE` | 設計書は現状で正しい。実装を直せば済み、**設計書は触らない** |
| `ADD` | 設計書に記述が無い。項目表・処理概要などに**書き足す** |
| `FIX` | 設計書に記述はあるが、採用する仕様と食い違う。**既存記述を直す** |
| `IMAGE` | 画面レイアウト**画像の差し替え**が要る（Excelに貼られた画像の描き直し） |
| `RESOLVE` | 正本の中で記述同士が矛盾している（項目表と画像、本文と注記など）。**どちらが正かを決めて片方を直す** |
| `UNSURE` | 判断できない |

**重要な原則:**
- `根拠区分 = SPEC_BACKED`（設計書に裏付けがある）＝ 原則 `NONE`。
  設計書は正しく、実装が追いついていないだけ。
  ただし設計書の記述が曖昧・不完全で、実装に合わせて**明確化**が要るなら `FIX`。
- `根拠区分 = LEGACY_BACKED`（設計書に記述が無く旧実装に根拠）＝ 原則 `ADD`。
  移行後も必要な挙動なら、設計書の記述漏れとして書き足す必要がある。
  ただし**その挙動を移行後に残さない**と読めるなら `NONE`。
- 表示文言・ラベル・画面項目の追記は、テキストの表に足すだけで済むのか、
  **レイアウト画像も描き直しになるのか**を区別する（後者は `IMAGE`）。

### 2. `docEffortDays` — Excel編集の工数（人日）

**この1件のために、該当シートを開いて直す作業**の量。目安:

| 作業 | 目安 |
|---|---|
| 既存の表に1行足す／セルの文言を1つ直す | 0.05〜0.1 |
| 項目表に複数行・条件付きの記述を足す | 0.1〜0.25 |
| 処理概要・業務ルールの節を書き起こす | 0.25〜0.5 |
| 画面レイアウト画像の差し替え（実画面の取得＋貼り直し＋位置調整） | 0.5〜1.0 |
| 正本内部の矛盾解消（影響範囲の確認＋関係箇所の統一） | 0.25〜1.0 |
| シート新設（機能ごと丸ごと無い） | 1.0〜3.0 |

**同じシートに複数の指摘がまとまっている場合、2件目以降は安くなる**（シートを開く手間が1回で済む）。
パケット内で同一 `設計書参照` の行が並んでいたら、その分を反映してよい（理由に書くこと）。

`docWork = NONE` のときは `docEffortDays: 0`。
`RESOLVE` は、裁定そのもの（どちらが正かを決める会議・確認）は含めず、**決まった後の反映作業**だけを見積もる。

## 絶対の禁止事項

- 引用・確認内容の捏造をしないこと。実際に開いて確認したものだけを書く。
- 確認していないことを「確認した」と書かない。
- 実装側の修正工数と混同しないこと。**ここで見積もるのは設計書の編集だけ**である。

## 出力

指示されたJSONファイルに **Write して** 書き込む。

```json
{
  "packetId": "...",
  "results": [
    {
      "rowId": 123,
      "docWork": "ADD",
      "docEffortDays": 0.1,
      "target": "0202_基本設計仕様書(在庫管理機能).xlsx / 在庫編集 シートの画面項目表",
      "reason": "旧実装にしかない上限件数の扱いを、項目表の備考へ1行足す。既存の行構成をそのまま使える。",
      "sharedWithRows": [124, 125],
      "confidence": "high"
    }
  ]
}
```

- `target`: 直す対象（ブック名 / シート名 / 表や図の位置）。分かる範囲で具体的に
- `sharedWithRows`: 同じシートでまとめて直せる他の rowId（無ければ空配列）
- `confidence`: `high` / `medium` / `low`

findings 全件について返すこと（欠落禁止）。
