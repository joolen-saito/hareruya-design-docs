# 影響区分の判定基準（ふるまい・動作・I/Oに影響するか）

各乖離指摘を、**その差分が外部から観測できるか**で分類する。
「外部」とは、利用者・運用者・連携先・永続データなど、システムの外側から見える面すべてを指す。

## NO_IMPACT（ふるまい・動作・I/Oに影響しない）

差分がコード内部の事情に閉じており、**同じ入力に対して同じ出力・同じ副作用**になるもの。

| 該当例 | 補足 |
|---|---|
| クラス名・メソッド名・プロパティ名・ローカル変数名 | 外部に露出しない限り |
| 定数名・列挙子名 | **値**が同じであること |
| DIサービスID・名前空間・ファイル配置・ディレクトリ構成 | |
| ルート**名**（`name:` 属性）のみの差 | **パスが同じ**であること |
| Twigのブロック名・テンプレート分割の仕方 | 出力HTMLが同じであること |
| サーバ側セッションキー名 | Cookie名・画面・APIに出ないこと |
| 実装場所・責務の置き場所（Controller直書き vs Service抽出 等） | |
| コメント・PHPDoc |  |
| テストコードのみの差 | 本体の挙動に影響しないこと |
| 設計書側の記述漏れだけで、実装の挙動は設計と同一 | |

## IMPACT（影響する）

外部から観測できる差。**迷ったらこちら**。

| 該当例 |
|---|
| 画面の表示文言・ラベル・項目・並び順・活性/非活性・表示有無 |
| HTTPのパス・メソッド・ステータス・ヘッダ・レスポンスボディのキー/型/値 |
| DBのスキーマ・保存先テーブル/カラム・永続値・削除/更新の有無 |
| CSV/ファイル出力の列・順序・書式・文字コード |
| メール送信の有無・宛先・件名・本文 |
| 外部システム連携の呼び出し有無・パラメータ |
| バリデーションの有無・条件・エラーメッセージ |
| 権限・認証・アクセス制御 |
| トランザクション境界・ロールバック範囲・再実行可能性 |
| バッチの起動条件・処理対象・副作用 |
| フォーム名／input の name 属性（HTTPリクエストのキーになる） |
| CSRFトークンの有無 |
| 監査・運用要件のあるログ出力 |
| 性能特性が桁で変わるもの（N+1・全件走査など） |

## UNSURE

情報が足りず、外部観測可能かどうか判断できないもの。**推測で NO_IMPACT にしない。**

## 判定上の注意

- **「軽微」と「影響しない」は違う。** 表示文言が1文字違うのは軽微だが、
  画面出力が変わるので IMPACT である。実害の大小は別の軸（`再検証_実害`）で扱う。
- **「未実装」は原則 IMPACT。** 機能が無いこと自体が挙動差になる。
  例外は「設計が実装場所だけを指定していて、別の場所で同じ挙動が実現済み」の場合。
- **ログは既定で IMPACT 寄り**に扱う（ファイル出力＝I/O）。
  ただし障害調査用の内部デバッグログのみで、運用・監査要件が無いと確認できるものは NO_IMPACT でよい。
- 「内部識別子だけの差」に見えても、それが **画面・API・DBに露出**していないかを必ず確認する。
