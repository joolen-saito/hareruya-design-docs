# Backlog「不具合（バグ）」対応中チケットの改修工数見積

Backlog プロジェクト `ECCUBE_HARERUYA` の、カテゴリ「不具合（バグ）」かつ
状態が着手済み未完了（処理中／実装中(25%)／レビュー中(80%)）のチケット 255件について、
**1件ずつ改修区分と工数を見積もる**。

## チケットの構造

本文はおおむね次の見出しで構成されている。読むべきは「期待される挙動」と「現在の挙動」。

```
# 基本情報【必須】   分類 / 機能 / 課題カテゴリ / 設計書
# 期待される挙動【必須】
# 現在の挙動【必須】
# 補足情報【任意】   設計書該当箇所・実装該当箇所
```

**1枚のチケットに複数の不具合がまとめられていることがある。** その場合は `itemCount` に件数を書き、
工数は合計で答える。

## 改修区分（実装を直す側の分類）

| 区分 | 名称 | 直す対象 | 下限 | 標準 | 上限 |
|---|---|---|---:|---:|---:|
| 1 | 外部インタフェース契約 | URL・HTTPメソッド・ステータス・レスポンス本文・CSV列/ヘッダ・コマンド名 | 0.25 | 0.5 | 1.5 |
| 2 | 画面表示 | 文言・ラベル・表示項目・並び・活性制御（Twig/翻訳ファイルで済む範囲） | 0.1 | 0.25 | 0.5 |
| 3 | データ永続化 | 保存先テーブル/カラム・永続値・削除方式。**マイグレーションや既存データ移行を伴う** | 1.0 | 3.0 | 8.0 |
| 4 | 入力検証 | 必須・桁・形式・範囲・重複・相関チェック | 0.25 | 0.5 | 1.5 |
| 5 | 業務ロジック | 抽出条件・計算・ステータス遷移・分岐 | 0.5 | 2.0 | 5.0 |
| 6 | 未実装機能 | 画面・ルート・バッチ・処理**そのもの**の新規実装 | 2.0 | 5.0 | 15.0 |
| 7 | 外部連携・副作用 | スマレジ/S3/SFTP/メール送信/支店通知/監査ログ | 1.0 | 3.0 | 8.0 |
| 8 | 実行制御 | トランザクション境界・排他・実行環境設定・同期/非同期 | 0.5 | 2.0 | 5.0 |

**区分は「話題」ではなく「直すために触るもの」で決める。**
在庫や価格の話でも翻訳ファイル1行なら 2。「実装されていない」と書いてあってもフォーム初期値1行なら 2、
バリデータ1個なら 4。

## 工数

区分の代表値に引きずられず、**このチケットを実際に片付けるなら何人日か**を答える。
判断が要るときは実コード `/home/y-saito/Developments/ec-cube-enterprise` を開いて範囲を確かめる。

- 触るファイルが1つで既存実装を流用できる → 下限側
- 複数画面・複数経路に及ぶ、データ移行が要る、外部システム調整が要る → 上限側
- 仕様が確定していない（設計が矛盾、要確認と書かれている等）→ `needsDecision: true`、工数は0

工数は**実装のみ**。テスト・レビュー・リリース作業は含めない。

## 状態の扱い

`実装中(25%)` `レビュー中(80%)` のチケットは**着手済み**なので、
残りの工数（remaining）を答える。`処理中` は未着手とみなして全量を答える。

## 絶対の禁止事項

- 引用・確認内容の捏造をしないこと。実際に開いて確認したものだけを書く。
- 確認していないことを「確認した」と書かない。
- 本文に情報が足りず判断できないときは `confidence: low` にし、その旨を reason に書く。
