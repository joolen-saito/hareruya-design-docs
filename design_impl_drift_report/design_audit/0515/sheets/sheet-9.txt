A15-09 デッキ情報登録 ／ API デッキビルダー — デッキ情報登録
業務ロジック
認証と所有者
認証用トークンを検証し、トークンが持つ顧客IDからプレイヤーを特定する。トークン欠落・署名不正・該当プレイヤーなしのいずれの場合も認証拒否とする。認証したプレイヤーが登録したデッキの所有者になる。呼び出せるクライアントはデッキビルダーアプリに限る。トークン原値・署名シークレットは本書に記載しない。
保存の判定順序
順序	判定	結果
1	認証できるか	認証できないときは登録せず認証拒否とする
2	採用カードの整合性	満たさないときは登録せず入力不正とする
3	フォーマット・アーキタイプ・公開範囲・代表カード画像・キャンペーンタグの解決	解決した内容からレギュレーション違反を判定する
4	デッキ本体の整合性	満たさないときは登録せず入力不正とする
5	デッキ本体と採用カードの保存	1 件のまとまりとして保存し、途中で例外が起きたときはすべて取り消す
採用カードの扱い
採用カードは配置ボードごとに、採用カード・メイビー・アトラクション・ステッカーとして組み立てる。配置ボードはメイン 1・サイド 2・統率領域 3・メイビー 4・アトラクション 5・ステッカー 6 のいずれかとする。
代表カード画像と限定公開トークン
代表カード画像の指定が無いときは、アーキタイプの画像などで補う。
限定公開トークンが未設定のときは、発番したデッキIDから閲覧用トークンを作って保存する。公開範囲が限定公開のときだけ、閲覧用トークンを応答に含める。
値の取り方
金額・税・ポイント・在庫数量の再計算と丸めは行わない。デッキ名の指定が無いときは値なしで保存する。
入出力
種類	内容
入力	認証用トークンと、デッキ名・フォーマット・アーキタイプ・公開範囲・代表カード画像・キャンペーンタグ・採用カード
成功時出力	HTTP 200。処理結果コード 200、処理結果メッセージ「Deck register success」、発番したデッキID。公開範囲が限定公開のときは閲覧用トークンも返す
失敗時出力	認証できないときは HTTP 401、整合性を満たさないときは HTTP 400、保存中に例外が起きたときは HTTP 500。いずれも処理結果コードとメッセージを返す
入出力: 登録内容
パラメータ	位置	型	必須／任意	説明
jwt-token	ヘッダ	string	必須	認証用トークン
deck_name	ボディ	string	任意	デッキ名。指定が無いときは値なしで保存する
format_id	ボディ	integer	任意	フォーマットの識別子。空でないときだけ解決し、レギュレーション判定に使う
archetype_id	ボディ	integer	任意	アーキタイプの識別子。空でないときだけ解決する
scope_id	ボディ	integer	任意	公開範囲。公開 1・非公開 2・限定公開 3
image_card_id	ボディ	integer	任意	代表カード画像のカード。指定が無いときはアーキタイプの画像などで補う
campaign_tag_ids	ボディ	integer または array	任意	キャンペーンタグの識別子。単一値と配列のどちらでも受け付ける
cards	ボディ	array	任意	採用カードの配列
cards[].card_id	ボディ	integer	任意	採用カード
cards[].board_id	ボディ	integer	採用カードを指定したときは必須	配置ボード
cards[].count	ボディ	integer	採用カードを指定したときは必須	採用枚数
入出力: 永続化
操作	契機
追加	デッキ本体と採用カードを、整合性の検証をすべて満たしたとき
追加	限定公開トークンが未設定のときの閲覧用トークン
リニューアル後の仕様
表示メッセージ
本APIは画面へ文言を表示しない。応答に含める処理結果メッセージは入出力の節に示す。
