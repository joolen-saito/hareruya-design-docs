機能名
注文印刷_該当受注のステータスを印刷済みに変更
概要
プリンタから送信されてきた受注IDに対してステータスをピック中にする
処理概要（★はカスタマイズ項目）
GET　POST　PUT　DELETE　PATCH　OPTIONS　HEAD　有　無　〇
エンドポイントURL
/order/prints/status/printed
プロトコル　HTTP　メソッド　POST　認証の有無　有　認証方式　IP制限　リクエスト書式　XML　レスポンス書式　なし
(ステータスコードのみ)
カスタマイズ説明
現状はピック中ステータスに更新するAPI (A05-02)と処理を受けるメソッドが共通で、クエリ「ConnectionType」で処理が分岐しているので、A05-02とエンドポイントを分ける
本店・支店のシステムを統合するので、注文印刷情報のAPIも処理を一本化する。
本店のプリンタはエンドポイントURLを変更するので、設定変更が必要
本店・支店のシステムを統合するので、支店側のプリンタに設定されているエンドポイントURLはドメインが変更となるので全て設定変更が必要
プリンタ側でエラーがあった場合、XMLの中にエラーコードが返ってくるので、ログに追記する
機能仕様処理概要（★はカスタマイズ項目）
★ 各店舗に設置されているプリンタで印刷が完了したらこのAPIにアクセスし、印刷完了した受注ID情報全てをプリンタの仕様に則ったXMLで送信(エンドポイントURL変更)
・送信されてきたXML情報から取引IDを全て抽出し、その受注IDのステータスをピック中にする
※ 受注IDを持っているので、情報として店舗IDは不要
★ プリンタ側でエラーがあった場合、レスポンスデータの中にエラーコードが返ってくるので、ログに追記する
※ 　基本書式(XML)を満たしていない、印刷結果の情報がない等、根本的な問題があった場合はログに追記する仕組みは既存にもあるが、
印刷結果の詳細を参照してエラーの有無を確認していない
リクエストパラメータ
項目名	型	必須	最大文字数
または最大値	入力例	備考
印刷結果(XML)	文字型	〇			プリンタの仕様に沿った言語(フォーマット)で記述された印刷結果
何かしら印刷に失敗した場合、この印刷結果に理由が記載される
引数は「ResponseFile」で届く。
印刷結果XML概要
印刷データを一意に定める値として受注情報IDを送信しているので、印刷結果も同じ値が返ってくる
印刷結果として、成功(true)/失敗(false)が返ってくる
失敗の場合のみ、失敗理由(code)が返ってくる
※エラーコードは下記の通り
Code　原因
EPTR_AUTOMATICAL　高密度印字の連続印刷
EPTR_BATTERY_LOW　バッテリーの残量が無い
EPTR_COVER_OPEN　カバーが開いている
EPTR_CUTTER　カッターに異物がある
EPTR_MECHANICAL　メカ駆動中のエラーなど
EPTR_REC_EMPTY　用紙が無い
EPTR_UNRECOVERABLE　低電圧
EX_BADPORT　・プリンターがオンライン時に強制送信モードを実行した
・プリンターがオフラインで印刷できない
・登録情報不正
・デバイスの電源が入っていない
・デバイスが接続されていない
・他のデバイス制御ソフトが存在
EX_TIMEOUT　・時間内に処理が完了できなかった
・1メソッドで大量のデータを送った
・スタイルシートに問題がある
SchemaError　要求メッセージが不正
DeviceNotFound　・出力先デバイスにアクセスできない
・指定したデバイスが存在しない
・サーバーダイレクトプリント対応プリンターの登録を確認
PrintSystemError　サーバーダイレクトプリント対応プリンターにアクセスできない
ERROR_WAIT_EJECT　用紙除去待ち
EX_SPOOLER　印刷キューに空き容量が無い
JobNotFound　指定のジョブIDが存在しない

現行仕様
A05-02 注文印刷_該当受注のステータスを印刷済みに変更 / API 受注管理 — 注文印刷（印刷情報送信・印刷済み更新）
業務ロジック
動作の分岐
接続種別 ConnectionType の値で動作が分かれる。
接続種別の値	動作
GetRequest	印刷情報を送信する
SetResponse	印刷済みステータスへ更新する
上記のいずれにも一致しないとき	処理を行わず、応答を組み立てない
印刷対象の受注
印刷情報の送信では、次のいずれかに当たる受注だけを対象とし、最大10件を取得する。
対象	条件
店頭受取の受注	対応状況が注文受領のとき
スムーズ店頭受取の受注	所定の支払方法で、未確定・未出荷・未取消・未受領・店頭予約日なし・スマレジコードありのとき
ブラウザ印刷を指定した受注	補助情報のブラウザ印刷フラグが立つとき
受注ごとに注文日・合計金額・店頭注文番号・スマレジコード・問い合わせ有無・注文詳細URLを組み立て、1受注分の印刷情報とする。配送がスムーズ店頭受取のときは、合計金額欄を「スムーズ店頭受取」とする。全受注分を束ねてスタック用紙の印刷情報XMLとする。
対象受注	生成する印刷情報
1件以上あるとき	受注ごとの印刷情報を束ねたXML。XMLをログファイルへ書き出す（印刷不具合の検証に用いる記録）
1件も無いとき	XMLを生成せず空文字とする。ログファイルの書き出しも行わない
印刷済みステータスへの更新
受け取った印刷結果のXMLを解析する。印刷結果要素ごとに、印刷ジョブIDの先頭部分から受注IDを取り出して対象受注を特定する。
対象受注の状態	更新内容
補助情報のブラウザ印刷フラグが立っているとき	フラグを倒すだけに留め、対応状況は変えない
補助情報のブラウザ印刷フラグが立っていないとき	対応状況をピック中へ更新し、補助情報の確定日時に現在時刻を設定する
認証を行わない
本エンドポイントは認証処理を行わない。他の管理系APIが用いる共通の認証処理を経由せず、未認証のまま実行できる。認証の判定を持たない限り、認証失敗による拒否（HTTP401）は返さない。呼び出し元は店頭のスタック用紙プリンタだけで、利用者の照合は行わない。
金額・在庫の再計算
金額・税・ポイント・在庫数量の再計算と丸めは、いずれの分岐でも行わない。
エラー時の扱い
事象	扱い
接続種別が想定値のいずれにも一致しないとき	処理を行わず、応答を組み立てない
印刷情報の送信で対象受注が無いとき	空のデータを返す
印刷結果XMLの解析に失敗したとき	更新を行わずに戻る
直接印刷結果が偽のとき、または印刷結果要素が1件も無いとき	更新を行わずに戻る
印刷ジョブIDに対応する受注が見つからないとき	その要素を除き、次の要素へ進む
印刷情報生成・データ取得・ファイル書き出し中に例外が起きたとき	共通例外処理に委ねる（HTTP500相当）
入出力
種類	内容
入力	接続種別（ConnectionType）。クエリとボディのいずれからも受け取る。必須。印刷済み更新のときは、印刷結果XML（ResponseFile）をボディで受け取る。印刷結果XMLは直接印刷結果の真偽と、印刷ジョブIDを持つ印刷結果要素を含む。
成功時出力	印刷情報の送信は HTTP200、Content-Type は application/octet-stream で、印刷情報XMLをストリーム送信する。対象受注が無いときは空のデータ。印刷済み更新は HTTP200、Content-Type は text/xml; charset=utf-8 で、本文長0の空応答。
失敗時出力	認証・入力検証による明示的なエラー応答を組み立てない。更新できないときも空の本文を返す。例外のときは HTTP500 相当。
出力: 印刷情報XMLの構造
要素	内容
PrintRequestInfo	ルート要素。バージョン属性を持ち、配下に受注ごとの ePOSPrint を並べる
ePOSPrint	受注1件分の印刷情報。印刷先・タイムアウト・印刷ジョブID・印字レイアウトを持つ
印刷ジョブID	受注ID。印刷済み更新で受注を特定するときに用いる
印字レイアウト	店頭注文番号、注文詳細URLのQRコード、注文日、注文番号、お客様名、合計金額、スマレジコードのバーコード、各種チェック欄
入出力: 永続化
操作	契機
更新	印刷済み更新で、ブラウザ印刷フラグが立っていないときに、受注の対応状況をピック中へ、補助情報の確定日時を現在時刻へ設定する
更新	印刷済み更新で、ブラウザ印刷フラグが立っているときに、そのフラグを倒す
