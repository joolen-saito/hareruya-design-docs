スマレジで取引完了時(決済完了時)のwebhookの受信処理

カスタマイズ説明
Webhookの仕様が廃止予定のスマレジAPIからプラットフォームAPIに変更
Webhookでの返値が取引IDのみになるので,別途APIを叩いて取引詳細を取得する
本店・支店の処理を統合
本店側でスマレジのwebhookを受けて、その後さらに支店側にデータをAPIで送っている処理を廃止し、webhookからの受信のみで本店・支店のデータ連携を実行する
ポイントの更新情報以外の取引情報もECCUBEと連携するように改修する
新規連携項目はリクエストパラメータに記載(★が追加項目)
取引状態によって連携方法が分岐
・スムーズ店頭受取 or 店頭受取　・会員状態　・ついで買いの有無　・店頭PC購入かどうか

★3. スマレジの取引詳細をECCUBEに登録
主要購入パターン
店舗で通常発生しやすい購入パターン
基本ルール
・ECCUBEにすでに存在している受注データがあれば、スマレジの商品IDからECCUBE上の受注データを検索する
※スマレジに「購入商品が纏まっている１点もの(ユニークな)商品」として登録されているので、そのスマレジの商品IDで検索可能
・スムーズ店頭受取以外のスマレジにある取引データはECCUBEに新規受注データとして新規作成する。この新規データは出荷完了で登録し、
配送情報は使用用途がないので未登録とする
・ECCUBEの既存受注データはそのデータのステータスを、スムーズ店頭受取であれば「出荷完了」それ以外の店頭受取は「引き渡し済み」にする
・ついで買いが発生した場合は、「既存の受注データ + ついで購入」の受注データを新規作成する。既存の受注データには移行先の新規受注データIDを登録する。
※既存の受注データはスマレジ上では「複数の商品(カードA,カードB,カードC等)の入った一つの商品(部門カラムに6:店頭受取)」として登録されているので、
複数のカード情報を解いた上で一つずつ明細(子データ)として紐づけて新規受注データとする
・会員状態も登録する。非会員であれば、「非会員」として登録・更新する
・カスタマイズ対象の追加連携項目をECCUBEの受注データに登録する

複数受注購入パターン
ECCUBEにすでに存在する受注を複数同時に店頭に持ってきた時
ex) 　店頭PC購入を複数回行い、レジに来る　店頭受取の会員が店頭PC購入でついで買いをする
基本ルール
・ECCUBE上の受注レコードを全て、ステータスを「引き渡し済み」にする
・全ての受注データを統合した新規受注データを新規作成する。既存の受注データには移行先の新規受注データIDを登録する。
・この組合せに加え、店舗内でのついで買いも同時に発生している場合は、そのデータも統合する。
・会員状態も登録する。非会員であれば、「非会員」として登録・更新する
・カスタマイズ対象の追加連携項目をECCUBEの受注データに登録する
・配送方法は店頭受取とする
・注文日に店頭受取注文の注文日を設定する。複数の店頭受取受注データが存在する場合は一番若いものを注文日とする。
返品
購入後、返品される
基本ルール
・一部返金の想定は不要。
・対象の受注データのステータスを「キャンセル」にする
ただし、取消(cancelDivision)が1の場合と、打消し(disposeDivision)が1の場合で処理が分岐する
disposeDivisionが1の場合、打消元取引IDから検索
cancelDivisionが1の場合、取引IDから検索

現行仕様
A05-04 スマレジ受信処理 / API 受注管理 — スマレジ受信処理（ポイント履歴取得）
業務ロジック
認証と呼び出し元
このAPIは認証トークンを要求しない。認証の判定を行わないため、未認証でも処理を実行する。呼び出し元はスマレジと転送経路であり、利用者の資格情報による絞り込みは行わない。
支店システムへ転送するときは、受信した連携用ヘッダをそのまま転送先へ引き継ぐ。連携用ヘッダは転送先へ渡す資格情報であり、呼び出し元の認証には使わない。ヘッダの値は本書に記載しない。
取引区分ごとの処理
受信した内容から取引ヘッダと取引明細を取り出し、取引区分で処理を分ける。
取引区分	処理
取消	会員ポイントを取消の方向に補正し、取引に一致するポイント履歴を削除する
打消	付与ポイントと利用ポイントの正負を反転したうえで取消と同様に補正し、対象のポイント履歴を削除する
通常取引	会員ポイントを加減算し、付与と利用のポイント履歴をそれぞれ登録する。続いて取引明細の各行を処理する
取引明細の振り分け
店舗コードは、オプション設定のスマレジ店舗IDが 3 桁に満たないときはゼロ埋めして整形した値とする。
商品コードの店舗コードが自店舗と一致する行だけ、対象の注文を出荷完了に反映する。一致しない行は支店分として記録し、自店舗では注文を更新しない。
支店分の明細が 1 件でもあるときは、支店システムのスマレジ受信APIへ明細を転送する。転送結果に更新件数が含まれるときは合算し、含まれないときは合算しない。
更新件数
応答に返す更新件数は、会員ポイント・ポイント履歴・出荷完了の反映の件数に、支店転送の結果件数が得られるときはそれも合算した値とする。
会員が見つからないとき、対象のポイント履歴が無いとき、対象の注文が無いときは、その処理の更新件数を 0 として処理を続ける。
エラー時の扱い
エラー内容	処理
受信内容を解釈できない、取引ヘッダが足りない、処理中に例外が起きた	標準の例外処理に委ねる（HTTP 500 相当）
会員が見つからない・対象履歴が無い・対象注文が無い	エラーとせず、その処理の更新件数を 0 として続け、HTTP 200 を返す
支店転送の結果に件数が含まれない	転送エラーとして扱い、件数を合算せずに処理を続ける
入出力
種類	内容
入力	取引ヘッダと取引明細を含む受信内容、スマレジの処理名、支店転送用の連携ヘッダ
成功時出力	HTTP 200。更新件数を 1 件の要素として返す
失敗時出力	受信内容を解釈できないとき、取引ヘッダが足りないとき、処理中に例外が起きたときは HTTP 500
入出力: 受信内容
パラメータ	位置	型	必須／任意	説明
params	ボディ	string	必須	取引ヘッダと取引明細を含む。取引ヘッダは会員ID・付与ポイント・利用ポイント・取引ヘッダID・取消区分・打消区分などを持つ
proc_name	ボディ	string	任意	スマレジの処理名。支店転送のときはそのまま引き継ぐ
X_contract_id	ヘッダ	string	任意	支店転送のときに転送先へ引き継ぐ契約ID
X_access_token	ヘッダ	string	任意	支店転送のときに転送先へ引き継ぐアクセストークン
{_locale}	パス	string	必須	言語識別子。処理対象の絞り込みには使わない
入力の検証と認証の判定を行わないため、HTTP 400 と HTTP 401 は発生しない。
入出力: 永続化
操作	契機
更新	会員ポイントを、取消・打消・通常取引のいずれかで補正したとき
追加	付与と利用のポイント履歴を、通常取引のとき
削除	取引に一致するポイント履歴を、取消または打消のとき
