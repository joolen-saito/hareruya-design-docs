カスタマイズ説明
Webhookの仕様が廃止予定のスマレジAPIからプラットフォームAPIに変更

本店・支店の処理を統合
本店側でスマレジのwebhookを受けて、その後さらに支店側にデータをAPIで送っている処理を廃止し、webhookからの受信のみで本店・支店のデータ連携を実行する

新規連携項目はリクエストパラメータに記載(★が追加項目)
取引状態によって連携方法が分岐

★3. スマレジの取引詳細をECCUBEに登録
主要購入パターン
店舗で通常発生しやすい購入パターン
基本ルール
・ECCUBEにすでに存在している受注データがあれば、スマレジの商品IDからECCUBE上の受注データを検索する
※スマレジに「購入商品が纏まっている１点もの(ユニークな)商品」として登録されているので、そのスマレジの商品IDで検索可能
・スムーズ店頭受取以外のスマレジにある取引データはECCUBEに新規受注データとして新規作成する。この新規データは出荷完了で登録し、
配送情報は使用用途がないので未登録とする
・ECCUBEの既存受注データはそのデータのステータスを、スムーズ店頭受取であれば「出荷完了」それ以外の店頭受取は「引き渡し済み」にする
・ついで買いが発生した場合は、「既存の受注データ + ついで購入」の受注データを新規作成する。既存の受注データには移行先の新規受注データIDを登録する。
※既存の受注データはスマレジ上では「複数の商品(カードA,カードB,カードC等)の入った一つの商品(部門カラムに6:店頭受取)」として登録されているので、
複数のカード情報を解いた上で一つずつ明細(子データ)として紐づけて新規受注データとする
・会員状態も登録する。非会員であれば、「非会員」として登録・更新する
・カスタマイズ対象の追加連携項目をECCUBEの受注データに登録する

ex) 　店頭PC購入を複数回行い、レジに来る　店頭受取の会員が店頭PC購入でついで買いをする
基本ルール
・ECCUBE上の受注レコードを全て、ステータスを「引き渡し済み」にする
・全ての受注データを統合した新規受注データを新規作成する。既存の受注データには移行先の新規受注データIDを登録する。
・この組合せに加え、店舗内でのついで買いも同時に発生している場合は、そのデータも統合する。
・会員状態も登録する。非会員であれば、「非会員」として登録・更新する
・カスタマイズ対象の追加連携項目をECCUBEの受注データに登録する
・配送方法は店頭受取とする
・注文日に店頭受取注文の注文日を設定する。複数の店頭受取受注データが存在する場合は一番若いものを注文日とする。
返品
購入後、返品される
基本ルール
・一部返金の想定は不要。
・対象の受注データのステータスを「キャンセル」にする
ただし、取消(cancelDivision)が1の場合と、打消し(disposeDivision)が1の場合で処理が分岐する
disposeDivisionが1の場合、打消元取引IDから検索
cancelDivisionが1の場合、取引IDから検索

現行仕様
A05-04 スマレジ受信処理 / API 受注管理 — スマレジ受信処理（ポイント履歴取得）
業務ロジック
取引区分ごとのポイント処理
受信した内容から取引ヘッダと取引明細を取り出し、取引区分で処理を分ける。
取引区分	処理
取消	会員の保有ポイントから付与ポイントを差し引き、利用ポイントを戻す。取引に一致するポイント履歴を削除する
打消	付与ポイントと利用ポイントの正負を反転したうえで取消と同じ補正を行い、対象のポイント履歴を削除する
通常取引	会員の保有ポイントに付与ポイントを加え、利用ポイントを差し引く。付与ポイントが 0 より大きいときは付与の履歴を、利用ポイントが 0 より大きいときは利用の履歴を、購入によるポイントとして登録する。0 のときはその履歴を登録しない
登録する履歴の備考には、付与のときは「店舗付与」、利用のときは「店舗使用」と記録する。
注文への反映にともなうスマレジへのポイント連携
取引明細の商品コードに対応する注文が複数あるときは、いちばん新しい注文を対象とする。
注文へ反映するとき、その時点の日時を、注文の確定日と出荷日、および注文に紐づく各配送の出荷日として記録する。スマレジ用として登録されている担当者があるときは、その担当者を注文の担当者として記録する。
反映した注文に付与ポイントが記録されているときは、その付与ポイントを会員の保有ポイントに加え、購入によるポイントの履歴としてその注文とともに登録する。付与ポイントが未設定または 0 のときは加算も履歴の登録も行わない。
付与ポイントが 0 のとき（スマレジ側で決済とポイント付与が済んでいるとき）はスマレジへ送らない。0 でないときは、会員のスマレジ会員IDあてに付与ポイントをスマレジへ送る。使用ポイントは EC からの注文時に連携済みのため送らない。
スマレジからの応答に正常な結果が含まれないときは、その注文にスマレジ連携のエラー内容と、連携エラーである印を記録する。処理は中断しない。
エラー時の扱い
エラー内容	処理
会員が見つからない	ポイントの補正も履歴の登録・削除も行わず、エラーとせずに処理を続ける
取消・打消で対象のポイント履歴が無い	ポイントの補正も履歴の削除も行わず、エラーとせずに処理を続ける
入出力
入出力: 永続化
操作	契機
更新	会員の保有ポイントを、取消・打消・通常取引のいずれかで補正したとき
追加	購入によるポイントの履歴を、通常取引で付与ポイントまたは利用ポイントが 0 より大きいとき
削除	取引に一致するポイント履歴を、取消または打消のとき
更新	会員の保有ポイントを、注文へ反映するときにその注文の付与ポイントが 0 でないとき
追加	購入によるポイントの履歴を、注文へ反映するときにその注文の付与ポイントが 0 でないとき
更新	注文に、確定日と出荷日、各配送の出荷日を、注文へ反映したとき
更新	注文の担当者を、スマレジ用の担当者が登録されているとき
更新	注文に、スマレジへのポイント連携が正常に終わらなかったときのエラー内容と連携エラーの印
