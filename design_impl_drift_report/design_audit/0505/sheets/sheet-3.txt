機能名
注文印刷_印刷情報をプリンタへ送信
概要
アクセスしてきた店舗のプリンタに対して印刷情報を返す
処理概要（★はカスタマイズ項目）
GET　POST　PUT　DELETE　PATCH　OPTIONS　HEAD　有　無　〇
エンドポイントURL
/order/prints/{店舗ID}
プロトコル　HTTP　メソッド　GET　認証の有無　有　認証方式　IP制限　リクエスト書式　クエリ　レスポンス書式　XML
カスタマイズ説明
本店・支店のシステムを統合するので、注文印刷情報のAPIも処理を一本化する。
本店のプリンタはエンドポイントURLに店舗IDを追加する必要があるので、設定変更が必要
本店・支店のシステムを統合するので、支店側のプリンタに設定されているエンドポイントURLはドメインが変更となるので全て設定変更が必要
現状は印刷完了ステータスに更新するAPI (A05-02)と処理を受けるメソッドが共通で、クエリ「ConnectionType」で処理が分岐しているので、
A05-02とエンドポイントを分ける
現状	/order/print/direct?ConnectionType=GetRequest	GETで受信
	/order/print/direct?ConnectionType=SetResponse	POSTで受信	※ RoutingでGetとPostで登録を行なっているが、同じメソッドを登録している
機能仕様処理概要（★はカスタマイズ項目）
★ 各店舗に設置されているプリンタから定期的(間隔:30秒)にこのAPIにアクセス(エンドポイントURL変更)
URLに店舗ID(shop_id)を引数として持つ
・バーコードが印刷されていない問題が発生しないようにするため、注文データをXML形式にする前に受注データにスマレジの商品コードが存在するかどうか確認する
スマレジの商品コードが存在しない場合はスマレジコードが採番されていない可能性があるため何もしない
・店舗IDからその店舗の未印刷の注文データを抽出し、各注文データごとに印刷できるようにプリンタ仕様に合わせてXMLの書式にして返す。
未印刷データがなければ空文字''を返す
※ プリンタのxmlの仕様 https://www2.epson.jp/support/manual/SDP_UM_JA_REVW.ZIP
・印刷データXMLをログに出力する
リクエストパラメータ
項目名	型	必須	最大文字数
または最大値	入力例	備考
店舗ID	数値(整数)	〇		123	受取店舗の店舗ID(shop_id)
リクエストパラメータサンプル
/order/prints/123
ステータスコード
コード　説明
200　正常終了
404　店舗ID(shop_id)が無い、整数以外の型、存在しない店舗ID(shop_id)　※支店での処理を踏襲
レスポンスデータ
名前	型	説明
印刷データ(XML)	文字型	専用の言語(フォーマット)で記述された印刷レイアウトデータを注文データ数分出力
印刷データの動的変更部分については、別表「印刷レイアウトデータの動的変更箇所」参照のこと
印刷位置や罫線情報については、サンプルデータを参照のこと
印刷レイアウトデータの動的変更箇所
名前	型	説明
受注情報ID	数値(整数)	注文詳細URLと生成と、印刷情報データを一意に定めるXML向けの情報として使用
店頭注文番号	文字型	店頭注文番号
注文詳細URL	文字型	管理画面の受注詳細情報ページのURL。QRコードにして印刷する
備考	文字型	受注情報の問合せに値があれば、「問い合わせ有」と表示。それ以外は空欄
注文日	日付（YYYY/MM/DD）	注文日
注文番号	数値(整数)	注文番号
お客様名	文字型	お客様名
合計金額	数値(整数)	注文の合計金額。ただしスムーズ店頭受取の場合、「スムーズ店頭受取」と表示
変更後金額	数値(整数)	スマレジコード。バーコードにして印刷
高額	文字型	固定値で「□」を出力
※内部処理としてはデータを差し込んでいるが、差し込むデータが現状固定値で「□」になっている

現行仕様
A05-01 注文印刷_印刷情報をプリンタへ送信 / API 受注管理 — 注文印刷（印刷情報の送信）
業務ロジック
印刷対象の受注
次のいずれかに当たる受注を、1回の要求につき最大10件まで取り出す。
対象	条件
店頭受取の受注	注文番号が採番済みで、対応状況が注文受領のとき
スムーズ店頭受取の受注	所定の支払方法（クレジット決済・支払いなし）で、対応状況が購入処理中でなく、確定日時・注文確定日・出荷日・取消日・受領日・店頭予約日がいずれも未設定で、スマレジコードが採番済みのとき
ブラウザ印刷を指定した受注	補助情報のブラウザ印刷フラグが立つとき
1件の受注に配送が複数あっても、印刷情報は受注1件につき1枚にまとめる。
印刷内容の決定
印刷欄	決め方
お客様名	カナ氏名（姓と名を空白でつなぐ）を印刷する。カナ氏名が無いときは氏名を印刷する
店頭注文番号	受注に店頭注文番号が採番されていないときは空欄にする
入出力
応答の形式
印刷情報は本文をストリーム送信する。応答の内容種別（Content-Type）は application/octet-stream とする。
