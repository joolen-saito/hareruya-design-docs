## 2026-08-21 に直した抽出の欠落

1. `Source:` 以降を全部 SOURCE 扱いにしていたため、Markdown起点の設計書（0000/0215/0216/0417/0508/0515）の
   本文がまるごと母集合から落ちていた（0216 は 7要求 → 180要求）。見出し行とパス行の2行だけを SOURCE にした。
2. `lib_design_doc.sheet_index` が sheet-panel 以外の構造を持つ設計書で例外になっていた。
   `<section class="doc-section">` と、セクションを持たない資料（0000_共通仕様）に対応した。

## 進め方（2026-08-21 以降：ワークフローで並列化）

1. `python3 audit_batches.py --doc <key>` で残りバッチを見る（1バッチ = 7シート = 判定7＋反証7の14エージェント）
2. `python3 audit_batches.py --doc <key> --emit <n>` の JSON を Workflow の args に渡して実行する
   （スクリプトは `design-audit-sheets`。判定→反証のパイプライン）
3. 各エージェントは `design_audit/<key>/parts/<sheet>.tsv` を書き、
   `python3 audit_part.py check --doc <key> --sheet <sheet>` が OK になるまで直す
4. 全シートが揃ったら `python3 audit_part.py merge --doc <key>` → `python3 design_audit_harness.py build --doc <key>`
5. 判定の規約は `AUDIT_JUDGING_RULES.md`（全エージェントが必読）

機械ゲート: 引用の実在／実装参照の実在／**MATCHEDの実装引用の実在**／判定漏れ0。
MATCHEDのゲートが無いと「全部MATCHED」が素通りするため、並列化の前提として 2026-08-21 に追加した。


## 2026-08-21 決定: 不具合調査は正本が固まるまで止める

正本HTML設計書の粒度が変われば調査結果も変わる（利用者判断）。再生成が全冊で終わるまで
②不具合調査を進めない。**0202 の判定（53シート・掲載161件）は暫定であり、やり直す。**

理由: 0202 は現行仕様由来の要求が 3.8% しかない（0203は32.2%、0204は33.5%）。
在庫管理の主要11機能で業務ロジックと入出力が正本から欠落しており、その範囲の
未実装・実装違いは原理的に検出できていない。再生成後に inventory からやり直す。

再生成の手順は excel_to_html/REGENERATION_RUNBOOK.md。

## 0202 の偽陽性率の抜き取り検査（2026-08-21）

集約後の掲載161件から24件（P1は全件11、P2/P3は各5件を等間隔で抽出）を反証専任エージェントにかけた。
指示は「裏づけるな、壊しにかかれ。迷ったら取り下げ寄りに倒せ」。

| 結果 | 件数 |
| --- | ---: |
| 取り下げ（REFUTED） | **0** |
| 一部（PARTIAL） | 3 |
| 維持（STANDS） | 21 |

**指摘そのものは1件も崩せなかった。** 規約の基準（取り下げ率2割超なら判定やり直し）に照らして
やり直しは不要。旧監査（8/20・掲載35件）のほうが取りこぼしていたと判断する。

**ただし重要度は緩かった。P1 14件中3件が過大で、是正して11件にした。**
- sheet-23-R088/R091: 実装実態が事実誤認だった。欠落ルートは本番では
  IgnoreRoutingNotFoundExtension.php:75-84 が /404?bind= のURLへ差し替えるため一覧は描画できる。
  判定も NOT_IMPLEMENTED → DRIFT へ是正（リンクは出るが遷移できない）
- sheet-14-R502/R503: 差分の在庫戻しは実装済みでデータ整合性は壊れない → P2
- sheet-31-R017: 切り下げても在庫は負にならず、取込後に手作業修正と承認ゲートがある → P2
- sheet-32-R125: 検索プルダウンが全店舗を出す件は M11-03 2-3 が参照を認めているため指摘から外し、
  更新操作に限定した

**教訓**: P1 の付け方は放っておくと緩む。冊ごとに P1 は全件を反証にかけること。
指摘が正しくても重要度が過大なら、対応の優先順位を歪めるので過剰指摘と同じ害がある。
