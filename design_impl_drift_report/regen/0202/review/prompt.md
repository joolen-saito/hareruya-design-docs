## 検証してほしい主張（著者の主張。1つずつ真偽を判定せよ）

**主張1**: 再生成後のHTMLに、正本Excelの内容の欠落は無い。旧HTMLから消えた3144行は、すべて
(a) 図形・テキストボックス内テキスト全件表、(b) 実装差分追補、(c) 取り消し線、のいずれかの
**規約による意図的な非出力**で説明でき、説明できない消失は0行である。

**主張2**: 取り消し線の除去は規約どおりで、過剰除去はない。全文が取り消し線だったセル23件が
HTMLから消えたが、これは規約 `.cursor/skills/output-exclusion-policy/SKILL.md` に沿う。
→ **Excel上で実際には取り消し線が引かれていないセル・runが、誤って除去されていないか**を疑って確認せよ。

**主張3**: `verify.py` の「セル値カバレッジ 100.00% (13708/13708)」は、欠落が無いことの証拠になる。
→ **ここは特に疑ってよい。** `verify.py` の期待値は `convert.apply_strike_exclusion()` を呼んで作られており、
変換器と同じ取り消し線モデルを共有している（verify.py の 2) cell-text coverage 付近）。
**変換器の取り消し線判定が誤っていた場合、検証器も同じ誤りをするので検出できない**のではないか。
そうであれば「100%」は欠落が無いことの証拠として不十分である。この論点を最優先で検証せよ。

**主張4**: `共通処理!D13` が本文(`<p class="doc-p">`)から小見出し(`<h4 class="doc-h doc-h-sub">`)へ変わったのは、
取り消し線除去で本文が24字以下になり `convert.py` の見出し判定（`len(first_text) <= 24` かつ句読点で終わらない）
を満たしたためである。これは規約違反ではなく副作用である。
→ この説明が正しいか、また他に同種の反転が0202内に無いかを確認せよ。

**主張5**: 図形テキスト台帳 `shape_textbox_sheets.csv` は 0202 の1177行と 0203 の649行の計1826行で、
0202 の非出力図形は全件記録されている（黙って消えた図形は無い）。

## 判定規約（レビュー時の制約）

- **HTML設計書に書かれていないことを欠落として指摘しない。** 正本はExcel（およびその変換HTML）である。
- 規約で意図的に非出力と決めた種類（取り消し線／図形テキスト全件表／実装差分追補／Markdown由来の除外節・列）は
  **欠落ではない**。これらを「消えている」と指摘しないこと。規約の正本は上記 output-exclusion-policy。
- 変換の見た目・配色・レイアウトの好みは対象外。実装手段の好みも対象外。
- 未再生成の他43本のHTMLが規約違反であることは既知なので指摘対象外。0202 だけを見よ。
- 指摘は**この再生成の正しさに直接効くもの**に限る。

## 出力形式

指摘が無ければ `NONE` の1語だけを出力する。指摘がある場合は1件ずつ次の形式で書く。

```
判定: <事実の誤り | 事実の欠落 | 検証の不備>
主張: <著者の主張のどれか>
実際: <file:line もしくは セル座標 を伴う具体的事実>
修正案: <結論を先に置いた1〜2文>
```

## レビューの縛り（2026-08-19 ユーザー指示・R2以降に適用）

- **codexは2巡まで。** 2巡で `NONE` に到達しなくても打ち切る。

  レビューのたびに現行仕様の記述が増える事態を避ける。加筆要求・スコープ論・実装手段の提案は書かないこと。
