# 敵対レビュー依頼: 節の除去で「設計内容」が失われていないかの検証

あなたはレビュアーである。著者ではない。ファイルを書き換えず、read-only で読むだけでよい。
指摘が無ければ `NONE` の1語だけを出力する。

## 背景

機能設計書（`functions/**/*.md`）から、HTML設計書へ出さないと決めた節を正本ごと除去した。
除去した内容は `functions/_archive/<区分>/<同名ファイル>` へ退避してある（消してはいない）。
除去は累積で約1万行ある。廃止宣言とフェーズ2対応の明記が巻き添えで消えた事故が2件あり、
それは台帳検証（superseded-spec / phase2-spec）が検出して復元済みである。

**知りたいのは「台帳に載らない設計内容が失われていないか」だけ**である。

## レビュー対象

- 抽出パケット: `/home/y-saito/Developments/hareruya-design-docs/design_impl_drift_report/regen/removal_audit/packet.md`
  （10機能ぶん。各機能について「退避先にあり、現在の正本のどこにも同じ文字列が無い行」を機械抽出したもの）
- 全候補: `/home/y-saito/Developments/hareruya-design-docs/design_impl_drift_report/regen/removal_audit/candidates.tsv`
  （3,175行 / 404機能。パケットはこの一部）
- 現在の正本と退避先はパケット内にパスを書いてある。両方を読んで突き合わせること。

## 判定の基準

**失われた＝次の両方を満たす場合だけ**である。

1. その行が **機能のI/Oかふるまい**（入力・出力・判定条件・分岐・業務ルール・画面に出る文言）を述べている
2. 同じ事実が、現在の正本のどこにも書かれていない（言い換えを含めて無い）

## 失われたと判定してはいけないもの（意図的に外した）

- 実装手段: クラス名・メソッド名・ファイル名・イベント名・セッションキー・翻訳キー・設定キー・DB物理名
- 定型節: 副作用 / 入力項目 / エッジケース / データ整合性 / 権限・認可 / セッション / Cookie /
  ログ・監査 / ログに出してはいけないもの / 排他制御・トランザクション / 試行制限 /
  明細の並び / 出力: 画面の項目 / 出力: 一覧の列 / 中身の無い「入出力: 永続化」
- 廃止宣言・フェーズ2対応の明記（台帳検証が別途担保しており、2件は復元済み）
- 節の見出しそのものが消えたこと（3分類へ寄せた結果であり、内容が残っていれば問題ない）
- 概要・用語・参考・調査補助・改訂履歴などの補助記述

## 記述の粒度（重要）

復元を提案する場合、**0203_基本設計仕様書(受注管理機能) に埋め込まれている正本の粒度と書き方を守る**こと。
手本: `/home/y-saito/Developments/hareruya-design-docs/functions/pf-eccube3/m05-01_admin_order_order_search_list.md`

- 結論を先に置く。1事実1文。体言止めを混ぜてよい。
- 実装手段を書かない。DB物理名を書かない（論理名で書く）。
- **過大に追記しない。** 1件の復元提案は原則1〜2文まで。表が要る場合も列は最小限にする。
- 元の文章をそのまま戻すのではなく、上記の粒度へ言い換えた案を書く。
