# 不具合調査の観点

正本HTML設計書と実装（`ec-cube-enterprise`）を突き合わせ、乖離を洗い出す調査の**観点**をまとめる。
判定者が従う手順そのものは [AUDIT_JUDGING_RULES.md](AUDIT_JUDGING_RULES.md)、進捗は [AUDIT_PROGRESS.md](AUDIT_PROGRESS.md)。

- 対象: 正本HTML設計書 45冊 / 機械抽出した **40,178要求**
- 実施: `design_audit_harness.py`（母数の抽出と検証）＋ `audit_part.py`（シート単位の検証）
- 数値は 0202（在庫管理機能）の 41/53シート・4,463要求を判定した時点のもの（2026-08-21）

---

## 1. 何と何を突き合わせるか

**一方向の突合**である。

| | 何を正とするか |
| --- | --- |
| 設計 | `excel_to_html/output/*.html`（正本HTML設計書）**これだけ** |
| 実装 | `ec-cube-enterprise`（ee）の HEAD **だけ** |

- **正本に書かれていないことは指摘にできない。** 判定行の設計根拠は正本本文に逐語で存在することを機械が照合する。
- **現行ソース（pf-eccube3 等）は実装としては一切見ない。** 正本の区分「現行仕様」は pf をリバースした記述だが、
  それは**踏襲すべき要求**として読み、実装は常に ee で確かめる。
- 実装参照は ee 内に実在するファイル:行であることを機械が検査する。

## 2. 母集合の作り方

正本HTMLから機械抽出した1行を1要求とする。**判定漏れ0**を機械で強制し、全要求に判定が付くまで成果物は出せない。
取り込まない要求も理由付きで OUT_OF_SCOPE / UNVERIFIABLE として必ず残す。

判定は6値。0202・4,463要求での分布:

| 判定 | 件数 | 意味 | 掲載 |
| --- | ---: | --- | :---: |
| MATCHED | 2,721 | 設計どおり実装されている | — |
| OUT_OF_SCOPE | 1,235 | 見出し・前置き・Ph2宣言など実装対象の記述でない | — |
| DRIFT | 273 | 実装はあるが設計と違う | ○ |
| NOT_IMPLEMENTED | 137 | 設計の要求に対応する実装が無い | ○ |
| DESIGN_ISSUE | 84 | 正本内部で記述が矛盾し、設計裁定待ち | — |
| UNVERIFIABLE | 13 | 実行時挙動・実データに依存し静的解析では確定できない | — |

## 3. 「不具合」とみなす範囲 — **I/O とふるまいに限る**

DRIFT / NOT_IMPLEMENTED には、I/O とふるまいのどちらかの明示を必須にしている。

| 種別 | 見るもの | 0202での件数 |
| --- | --- | ---: |
| **IO** | 画面に出る項目・ラベル・選択肢・初期値／CSVの出力列と値／メッセージ文言／入力制限（必須・桁・最大値） | 90 |
| **ふるまい** | 検索の絞り込み結果・並び順／エラー判定の有無／遷移先／保存される値／在庫・金額の増減／メール送信の有無／権限判定の有無 | 71 |

### 指摘にしないもの

| 対象外にするもの | 理由 | 強制 |
| --- | --- | --- |
| 実装手段の差 | 通信方式・内部配線・クラス名・呼び出し順・join の種類など。結果の言葉で書けないなら指摘を取り下げる | 機械（build を落とす） |
| 応答にも画面にも出ない内部挙動 | 例: パスワードのソルト生成方式 | 規約 |
| 現行仕様に書かれた現行ソースの不具合・不用意な副作用 | 踏襲対象ではない。ただし機能として定義された挙動（警告表示・並び順・据え置き時間等）は要求として扱う | 規約 |
| 現行仕様とリニューアル後の仕様が食い違う箇所 | **後者が優先**。現行仕様側は対象外（例: 在庫一覧の「絞り込みを持たない」） | 規約 |
| 正本が Ph2 と宣言している機能 | 例: 在庫切れ／在庫警戒リストCSV出力の70要求すべて | 規約 |
| ★書きの識別IDずれ | 追加する列は項目表側で決まり実装は追随済み | 機械（自動で対象外へ） |
| 見出し・表の見出し行・区分行・前置き・運用想定・背景説明 | 要求ではない | 規約 |

## 4. 実際に何を読んで判定するか

**正本側はテキストと画像の両方。** レイアウト図の文言は base64 埋め込み画像の中にあることが多く、
画像を見ずに「実装が無い」と判定すると誤る（0201 で実際に1件、この理由で判定を訂正した）。

**実装側**はコントローラ・フォーム型・Twig・リポジトリ・サービス・`messages.ja.yaml` / `validators.ja.yaml`・
マイグレーション（マスタデータ）・JS まで。grep が0件でも「無い」と即断せず、別の綴り・別の命名で3回以上引く。

指摘の根拠になった正本の区分（0202・掲載161件）:

| 区分 | 件数 |
| --- | ---: |
| 項目定義（画面項目表） | 101 |
| 機能仕様 | 46 |
| 現行仕様 | 12 |
| 本文・要件説明 | 2 |

画面項目表からの指摘が最多。項目表は「何がどう表示され、何を入力でき、どこまで制限するか」を
最も細かく定めているため。

## 5. 重要度は業務影響で決める

機能名で機械的に決めない。**影響と迂回可否**で判断する。

| 重要度 | 定義 | 0202での件数 |
| --- | --- | ---: |
| **P1** | 業務が回らず商売が止まる／データ整合性が壊れる／手作業でも代替できない | 11 |
| **P2** | 迂回すれば回る（手作業・再実行・別経路）が、正しさ・効率・顧客体験を損なう | 69 |
| **P3** | 業務は回る（見出し・ボタン文言・列名の相違／並び順・桁区切りの相違） | 81 |

例:
- 在庫振替で在庫が負数になる → **P1**（データ整合性が壊れる）
- CSV一括登録で結合元在庫が黙って切り下げられる → **P2**（取込後に手作業修正と承認ゲートがある）
- 一覧の列見出しが「コード」でなく「商品コード」 → **P3**

**指摘が正しくても重要度が過大なら、対応の優先順位を歪めるので過剰指摘と同じ害がある。**

## 6. 1つの実装欠陥は1件として数える

設計書は同じ1つの欠陥を、項目表・機能仕様・現行仕様・入出力の各所で繰り返し要求している。
要求の数だけ指摘に割ると、実態の何倍もの件数になる。

そのため各指摘に `根本原因` キーを付け、**「実装のどこが1箇所直れば全部消えるか」**でまとめる。
直す単位が別なら別のキーにする（別々の欠陥を1件に見せるのは過小報告であり、同じくらい悪い）。

0202では **指摘410件 → 167キー → 掲載161件**（225件を代表へ折り畳み）。折り畳んだ要求IDは代表行に全件併記する。

| 根本原因の例 | 畳んだ数 |
| --- | ---: |
| 在庫用カスタムCSVの出力項目が未登録 | 25 |
| 在庫移動・振替明細に登録当時の値を保存していない | 15 |
| 在庫変更CSV登録が廃棄の在庫減算と履歴作成を行わない | 13 |
| 出庫日時・入庫日時を書き込む処理が無い | 10 |

## 7. 判定を検証する仕組み

| 段 | 何を担保するか |
| --- | --- |
| **機械ゲート** | ①設計根拠の逐語引用が正本に実在する ②実装参照が ee に実在するファイル:行 ③**MATCHED も実装の位置を1つ以上示す** ④判定漏れ0 |
| **反証段**（1シート1エージェント） | 別の書き手が指摘を壊しにかかる。過剰指摘の摘発を最優先とし、MATCHED も2割抜き取って引用行が主張を支えているか確認する |
| **抜き取り検査**（設計書1冊ごと） | P1は全件、P2/P3は各5件を反証専任にかける。**取り下げ率が2割を超えたら、その冊は判定からやり直す** |

③が無いと「全部 MATCHED」が捏造ゼロゲートを素通りするため、並列化の前提として必須。

0202での抜き取り検査（24件）: 取り下げ **0** / 一部 3 / 維持 21。
指摘そのものは1件も崩れなかった一方、P1 は 14件中3件が過大で、是正して11件にした。

## 8. この観点では捕まえられないもの

| 捕まえられないもの | 理由 |
| --- | --- |
| 実行時の挙動（性能・並行性・実データ依存） | 静的解析のため。UNVERIFIABLE に落とす |
| 設計にも実装にも無い抜け | 突合なので、両方に無ければ見えない |
| ee 自身をリバースした設計書の乖離 | 0215・0216 など区分「刷新仕様」は ee のリバース。突合が構造上ほぼ循環するため、指摘が出なくても「一致している」ではなく「差が出ない作り」と読む |
| 実装にあって設計に無いもの | 本調査の対象外。必要なら別の観点として追加する |
