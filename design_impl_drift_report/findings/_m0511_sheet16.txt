 詳細設計書 
 M05-11 受注情報編集 / m05-11_admin_order_order_edit（管理画面_受注管理_受注情報編集） 
 概要 
 既存受注を開き、注文者・お届け先・商品明細・金額構成・ステータス等を変更し、検証のうえ保存する機能である。同一テンプレートとフォーム種別で受注新規登録ルートも提供されるが、本書の主眼は既存IDを指定する編集ルートとその画面ふるまいとする。 
 本書は実装手順ではなく、誰が・いつ・どの条件で・結果どうなるかを読むためのリバース詳細設計とする。ec-cube-enterpriseのコア実装を確認値とする。 
 対象はブラウザ経由の管理画面に限定する。コントローラのメソッド名は本文の主題としない。本文ではルートbind名やSymfonyのルートnameの網羅は主説明としない。「利用者視点の入口」にHTTPメソッドとサイトルートからのパスパターンを書く。コード探索でbind名が必要なときだけ「調査補助」へ書く。 
 本機能のカスタマイズ区分はカスタマイズであり、挙動は現行リポ（pf-eccube3）の実装を確認値とし、DB関連（テーブル名・列名・保存先）はec-cube-enterpriseを正とする。 
 リニューアル移行時の扱い 
 本機能はカスタマイズ区分がカスタマイズであり、挙動は現行リポ（pf-eccube3）、DBスキーマはec-cube-enterpriseを正とする。本書が参照する受注（dtb_order）・出荷（dtb_shipping）・受注明細（dtb_order_item）の主要列は、ec-cube-enterpriseの実装で実在を確認した。確認した列には、受注側のステータス（order_status_id）・各種日時（payment_date、confirm_date、shipping_date、cancel_date、update_date）・金額系（discount、delivery_fee_total、charge）・ポイント系（use_point、add_point、gained_points、spended_points、point_percentage）・スマレジメモ（smaregi_memo）・住所系（addr01〜addr03、postal_code、abroad_postal_code）、出荷側の追跡番号（tracking_number）・出荷日（shipping_date）、受注明細側の欠品数量（stockout）を含む。並び順キー・論理削除と物理削除の方式・補助テーブルの有無について、現行（pf-eccube3）と移行先（ec-cube-enterprise）の差分は本書では確認していないため、相違が判明した場合はec-cube-enterprise実装を正とする。 
 利用者視点の入口

 処理フロー 
 編集画面を表示する（GET m05-11_admin_order_order_edit ） 
 管理画面の認証済みセッションを要する。 id により受注を取得する。実装は商品明細の結合・閾値用ソートを含む専用クエリを用いる。該当が無ければ HTTP 404。 編集前スナップショットを受注のクローンと明細参照コレクションで保持する。 受注フォームビルダを組み立て、拡張イベント（initialize）を送出する。 フォームをリクエストに束ね、税表示タイプ未設定の明細へ既定の税表示区分を補う。 POST でないため、送信後処理には入らず、会員検索・商品検索フォーム、配送時間 JSON、価格閾値オプション、店頭待ち番号、商品サブ情報マップ等の表示用データとともにテンプレートを返す。 
 フォームを送信する（POST、共通前提） 
 フォームが submit されたとき、 OrderItems コレクションが妥当でなければ以降の mode 分岐に入らず、そのまま再表示する。 mode=status_change のときは「受注ステータス変更」経路のみ実行し、編集画面へリダイレクトして終える（後述）。 mode=clear_date のときは指定 target の日付フィールドを null にし flush、成功フラッシュ後、編集画面へリダイレクトする（後述）。 上記以外では、送料・手数料・値引きを含む明細の税・小計・合計を calculate() で再計算し、Symfony フォーム検証（ $form->isValid() ）で妥当性を確認する。現行実装（pf-eccube3 / HareruyaEc）は EC-CUBE4 系の PurchaseFlow を用いない。 validate の警告は管理フラッシュに積み、エラーがあれば欠品側のメモリ変更をロールバックし、エラーメッセージをフラッシュに積む。 mode=register でかつフォーム全体が妥当で、かつ validate にエラーが無いときだけ登録トランザクションに入る。それ以外の POST はここで終わり、同画面を再表示する（validate 結果は反映済み）。 
 登録する（POST かつ mode=register 、かつ検証成功） 
 情報ログに受注登録開始を書く。 配送・明細の店舗参照を揃え、トランザクション内で persist ／ flush により永続化する（現行実装に PurchaseFlow の prepare/commit は無い）。 commit 後も店舗 ID を配送・明細に再付与する。 受注ステータスが編集前と異なり、かつ新ステータスが「出荷完了」相当の ID のとき、未出荷の配送に出荷日時を立て、 gainPoints （会員加算とスマレジ側加算の両系統）を呼ぶ。その後ステータスを一旦旧値に戻し、ステートマシンで新ステータスへ遷移させる。 新規受注なら作成日時・更新日時と配送の日時を埋め、既存なら更新日時のみ更新する。永続化し、新規の場合は採番の都合で早期 flush する。 スナップショットにあってフォームから消えた明細を削除する。受注番号処理を走らせ、会員がいれば購入サマリを更新する。フォームのポイント割合・使用・獲得を反映するが、支払方法名に特定文字列が含まれず、小計または割合が変わったときは小計と割合から獲得ポイントを再計算する。 スマレジ取引コードがあり、かつキャンセル以外のステータスなら、スマレジ API に商品系の後処理 POST を行う。 トランザクション成功後、完了イベントを送出し、成功フラッシュを積み、情報ログに完了を書く。フォームの return_link がサイト内パスとして解釈できればそのルートへ、できなければ編集画面へリダイレクトする。 明細再計算・フォーム検証系の例外はエラーフラッシュのみで再表示。ステートマシン矛盾はログに例外を残し、旧新ステータス名入りの短いエラーメッセージをフラッシュする。 
 ステータスだけ更新する（POST かつ mode=status_change ） 
 旧新いずれかが欠ける、または同一 ID なら検証なしで編集画面へリダイレクトする。 フォーム全体が妥当でない場合も同様にリダイレクトする。 新ステータスが「出荷完了」へ変わるとき受注および全配送の出荷日時を現在時刻にする。新キャンセルで既存が非キャンセルかつキャンセル日未設定ならキャンセル日を立てる。新入金／新ピック中でも同様に専用日付を初回だけ立てる。 ステータスを旧値に戻したうえでステートマシン適用、会員係の更新者・更新日時を flush。出荷完了への変化ならポイント加算とスマレジ加算を再度呼ぶ。キャンセル以外かつスマレジコードがあるなら API POST。 新ステータスがキャンセルなら専用完了メッセージ、それ以外は汎用保存完了メッセージをフラッシュし、編集画面へリダイレクトする。 
 日付をクリアする（POST かつ mode=clear_date ） 
 クエリ target が許可リスト（ピック中日、入金日、確定日、出荷指示日、出荷日、キャンセル日、店頭予約）に一致するときだけ該当フィールドを null にし、出荷日クリアは全配送の出荷日も null にする。 一致しない target は何も変えず編集画面へリダイレクトする。 成功時は更新者・更新日時を更新して flush し、保存完了系フラッシュを積んで編集画面へリダイレクトする。 
 集計条件 
 本機能は売上ダッシュボードの集計を行わない。商品一覧の並びは受注取得クエリ側で価格閾値に応じた並び替えを含む。 
 指標 集計の要点 商品追加モーダルの検索 POST 直後は 1 ページ目固定。以降 GET はセッションキー eccube.admin.order.product.search の条件と page_no を使う。店舗は編集対象受注の店舗 ID、在庫ロケは定数で EC-CUBE 側ロケを指定する。 会員検索 POST 直後はページ 1。キーワードを multi に、会員状態は正会員に限定する。条件は eccube.admin.order.customer.search に保存する。 
 登録処理時の判定順序 
 順序 判定 結果 1 OrderItems コレクションがフォーム上妥当か 否なら mode に関わらず以降の分岐に進まない。 2 mode が status_change / clear_date か はいなら専用経路で終了。 3 明細再計算・フォーム検証にエラーがあるか はいなら register でも永続化しない。欠品差分はメモリ上で戻す。 4 mode=register かつフォーム全体妥当か いいえなら再表示。 5 トランザクション内の flush 成功か 失敗ならメッセージをフラッシュして再表示。 
 業務ルール・計算 
 受注明細のうち商品種別は 1 行以上必須。0 件なら OrderItemsErrors にエラーを付与する。 欠品数が増えると、その差分だけ注文数量から減算する。減算結果が負にならないよう 0 に切りつめる。差分がある明細では担当者を現ログイン管理者に付け替え、欠品履歴行を persist する。明細再計算・検証がエラーなら数量・担当者・履歴をメモリ上戻す。 送料・手数料・値引きは validate 時のみ一時明細として Order に載せ、本体フィールドの文字列金額から作る。値引きは正の入力を負の明細金額に変換し、非課税種別を付ける。 ポイント獲得数は登録確定直前にフォーム優先で載せ替えつつ、決済方法名に定数文字列が含まれず小計または割合が変わったときは「税込小計 − 利用ポイント」が正のときだけ切り捨て整数で再計算する。 
 本機能独自の定期バッチ集計はない。

 利用者状態 画面・操作 未ログイン（管理者） 管理ログインへ誘導（ファイアウォール既定）。 ログイン済み管理者 編集画面と関連 XHR、納品書出力へ到達可とする。細かいロール制約は本リポジトリの security.yaml にアクセス制御一覧が無いため、権限制御プラグインやサーバ設定がある場合は別途確認する。 
 画面遷移 
 条件 遷移先 保存成功、 return_link 解釈可 解釈された内部ルート 保存成功、上記以外 m05-11_admin_order_order_edit 同一 ID 受注一覧／一覧再開リンク admin_order または admin_order_page （セッションのページ番号） 配送編集（複数・単一の導線） admin_shipping_edit （未保存警告モーダル経由可） メール作成 m05-15_admin_order_order_mail 納品書印刷 admin_order_print_delivery_slips を新窓 
 遷移時に引き継ぐ状態 
 起点 遷移前の処理 遷移後の初期状態 未保存のまま別画面へ移る確認モーダルで保存を選ぶ return_link と隠し mode=register を付与して submit 保存成功なら return_link 先、失敗なら編集画面にエラー 会員／商品検索モーダル POST 条件をセッションキーへ保存 次ページ GET は同条件を読み戻す 
 エラー処理 
 エラー内容 処理 受注不存在 HTTP 404（編集 GET）。 Ajax CSRF／非 XHR 会員検索は HTTP 400、商品検索は空配列応答の実装。 明細再計算・検証例外 メッセージをフラッシュし、同一編集画面を再表示。 ステータス遷移不可 短い管理メッセージとログ。 
 試行制限 
 本機能ではフィールド単位の試行制限は設けない。管理ログインのスロットリングは管理画面ファイアウォール共通。 
 ログ・監査 
 タイミング 記録内容 登録開始／完了 情報ログに受注 ID。 ステータス遷移失敗 エラーログに例外内容。 return_link 不正 警告ログにメッセージ。 
 ログに出してはいけないもの 
 パスワード なりすまし対策トークン Cookie 値 セッション ID の完全値 Remember Me トークンの原値 
 セッション 
 本機能におけるセッション 
 観点 内容 会員検索 eccube.admin.order.customer.search と ...page_no を更新する。 商品検索 eccube.admin.order.product.search と ...page_no を更新する。 一覧戻り eccube.admin.order.search.page_no を読んでページリンクを組み立てる。 
 セッションへ保存しない情報 
 カード番号など決済の機微情報は当機能の検索条件に載せない。 
 Cookie 
 管理画面セッション Cookie および Remember Me の名称は環境設定に従う。当機能が独自 Cookie を追加しない。 
 排他制御・トランザクション 
 登録とステータス更新の本体はラップドトランザクション内で実施する。在庫処理は悲観ロック等を含みうる。編集画面同士の楽観ロック UUID は当画面では持たない。 
 調査補助 
 実装追跡用に、起点 PHP パスは src/Eccube/Controller/Admin/Order/EditController.php 、テンプレートは src/Eccube/Resource/template/admin/Order/edit.twig 、フォームは src/Eccube/Form/Type/Admin/OrderType.php および ShippingType.php / OrderItemType.php を参照する。
