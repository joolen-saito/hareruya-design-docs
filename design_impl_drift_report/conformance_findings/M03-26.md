【指摘内容】
　（仕様）CSVフォーマット 識別ID15 商品カテゴリ(ID)は、カンマ区切りの複数ID指定を許容するが、「単体カード・予約シングル・インフォメーション商品の subtree に入る ID のみ許容」し、それ以外のカテゴリIDは不可とする。
　実装のカテゴリID検証（CategoryIdValidator::validate）は categoryMap->contains() を呼ぶのみで、contains() は array_key_exists により dtb_category 全件（loadCategories は del_flg を持たず dtb_category を無条件 SELECT）の存在確認しか行いません。特定3ルート（単体カード・予約シングル・インフォメーション商品）配下の subtree へ絞り込む条件が Validator にも persistProductCategory（親カテゴリ付与のみ）にも存在せず、src/Eccube/Service/Csv 配下・CategoryMap を全走査しても「単体カード/予約シングル/インフォメーション/subtree/ルート限定」を示す定数・条件はヒットしませんでした。そのため subtree 外のマスタ存在カテゴリIDが検証を通過し得ます。確認お願いします。（設計根拠: excel_to_html/output/0204_基本設計仕様書(商品管理).html#sheet-8 詳細設計『CSV 列』表・商品カテゴリ(ID)行（本文『単体カード・予約シングル・インフォメーション商品の subtree に入る ID のみ許容』, L2496） ／ 実装: src/Eccube/Service/Csv/Importer/Validator/Repository/CategoryIdValidator.php:48-68 / src/Eccube/Util/CategoryMap.php:53-56(contains)・157-184(loadCategories) / src/Eccube/Service/Csv/Importer/Event/ProductCardImportHandler.php:619-628）

【指摘内容】
　（仕様）基準価格・セールフラグ処理: 新規登録の場合はセールフラグ無効(セール外)として処理し（パターン1-1: セールフラグ無効(0)/通常商品）、CSV識別ID25『基準価格』の値を商品データの『販売価格』と『基準価格』の両方へ反映する。
　実装の更新分岐（691-702）はセールフラグOFF時に $sellPrice = $newStandardPrice で price02（販売価格）を基準価格由来値へ上書きし、パターン1-1を満たします。しかし新規INSERT分岐（749-768）では price02 に $sellPrice（=PriceUtil::discount で割引適用したCSV『販売価格』列値, line 675）をそのまま設定し、基準価格（newStandardPrice）での上書きを行っていません（standardPrice のみ newStandardPrice を保存）。新規登録行は insert 分岐に入るため、基準価格≠販売価格のCSVでは設計と異なる price02 が保存されます。確認お願いします。（設計根拠: excel_to_html/output/0204_基本設計仕様書(商品管理).html#sheet-8 ★基準価格・セールフラグの処理について（『新規登録の場合、セールフラグ無効(セール外)の処理を行う』／パターン(1-1)『基準価格の値を販売価格・基準価格に反映』, L2364-2368） ／ 実装: src/Eccube/Service/Csv/Importer/Event/ProductCardImportHandler.php:749-768(新規INSERT分岐), 675($sellPrice算出), 696-701(更新分岐のみの上書き)）
