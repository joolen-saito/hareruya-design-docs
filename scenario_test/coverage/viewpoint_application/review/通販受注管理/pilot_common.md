## 指摘対象外

- 期待値の根拠が設計書の中で食い違っている箇所（契約の known_limits や台帳に「食い違い」と書いたもの）は、裁定待ちとして期待結果から外している。外したこと自体は指摘しない。食い違っていないのに外している場合は指摘する。
- テストデータの論理ID（ST-…）や数量・金額などの実行用の具体値（原典の業務ルールの閾値以外）。
- 表現の好み、粒度の提案、手順書のフォーマット（生成スクリプトの共通の形）。
- 他の業務（通販以外）。

## 出力形式

指摘が無ければ `NONE` の 1 語だけを出力する。指摘があれば 1 件ごとに次の形式で、重要度の高い順に書き、最後に件数を書く。

```
### 指摘 N
- 対象: （テストID / 契約ID / シナリオID / 台帳の観点ID）
- 主張: （成果物に書かれていること）
- 実際: （根拠。ファイル名:行 と原文の短い引用）
- 判定: 事実の誤り / 根拠の逸脱 / 捏造 / 抜け / 実行できない / 判定の誤り / その他
- 修正案: （結論を先に、一文で）
```
