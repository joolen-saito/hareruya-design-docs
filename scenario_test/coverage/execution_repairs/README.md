# シナリオテスト 実施手順の修正結果

更新日: 2026-10-09

[品質と業務成立を判断するための完了基準](../../システムテストの目的と完了基準.md)に従い、[経路の必須判定を追加した最新の修正結果](../business_goal_review/README.md)も反映しています。準備・判定根拠の不足で業務成立を確認できない経路は、テスト設計未完了です。

業務フロー・HTML設計書に基づき、全129シナリオの準備・操作・期待結果を修正し、**1,574テスト項目・830工程**へ再生成しました。修正前の1,552項目と97指摘は、すべて対応先または整理理由を記録しています。

**全件を実施可能とする状態には、まだ至っていません。** 1,023項目は記載された環境・データ・既知実装差の確認条件付き、551項目は原本・業務条件・先行工程等の確定待ちです。保留を含むシナリオは57件、そのうち経路全体の項目が保留のものは57件です。同じ不足資料が複数項目に影響するため、保留件数にはその重複影響を含みます。

実機で業務テストを実施した結果ではありません。ローカル環境の起動と、管理画面・フロント・メール確認画面のHTTP到達は確認しました。

## 修正内容

- 誤った画面や機能を、HTMLで確認した登録・検索・CSV・承認操作へ変更。登録者と承認者、顧客と管理者を区別しました。
- 初回採番と既存データを区別し、同じ受注・商品・移動・査定の実IDを後工程へ引き継ぎます。準備データを毎工程で作り直す指示を撤去しました。
- 受入数量、欠品、原価、再査定後の成立数量、出荷CSVとメール、期限、データパターンの変更値を準備・操作・期待結果で揃えました。
- 個別項目では必要な先行操作を展開し、経路実施中は既存の証跡と現在状態を引き継ぐようにしました。
- 承認等11工程を追加し、非会員にオンライン申込一覧を要求する2工程と、キャンセル後の番号札の二重削除1工程を整理しました。
- 非会員の当日受付で存在しないオンライン由来の連鎖4件を除外し、売上等の必要な成果物の照合は保持しました。重複した追加判定の統合先も対応表で追跡できます。
