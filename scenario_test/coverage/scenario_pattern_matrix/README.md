# シナリオパターンのマトリクス

業務条件の値ごとに、どのシナリオ（○）・テストケース（△）が通っているかを表にし、どれも通っていない値（抜け）を見つける。抜けを示すところまでで、シナリオは足さない。

全10業務（外部連携の2本を除く131本）。全業務の集計・判断待ち・抜けの一覧は [00_全業務の集計.md](00_全業務の集計.md)。業務ごとの表は `<業務>/matrix.md`、抜けは `<業務>/gaps.tsv`（2026-10-30）。

## ファイル

| ファイル | 中身 | 書く人 |
|---|---|---|
| `<業務>/factors.tsv` | 業務条件と値。扱い（対象／適用外／他業務／他層／判断待ち）と、出典ファイルの文の引用 | 人 |
| `<業務>/mapping.tsv` | シナリオ（○）またはテストケース（△）が通る値と、根拠の引用 | 人 |
| `<業務>/matrix.md`・`matrix.tsv`・`gaps.tsv` | 上の2つから作った表 | 機械 |
| `<業務>/review/`・`_review/<組>/` | codex の敵対レビューの観点・出力・扱い（通販は業務のフォルダ、他の9業務は3業務ずつの組。観点は `_review/make_prompt.py` で作る） | 人 |
| `00_全業務の集計.md` | 全業務の判定の件数・判断待ち・抜け | 機械 |

## 作り直し

```bash
python3 scenario_test/tools/build_pattern_matrix.py 通販受注管理 SCN-TSUHAN-   # 業務ごと
python3 scenario_test/tools/summarize_pattern_matrix.py                    # 全業務の集計
```

次のどれかが外れると、表を出さずに止まる。

- 条件の引用が出典ファイルの1行の中にそのままある（設計書HTMLはタグを外して比べる。行番号は毎回求め直す。HTMLを作り直すと行がずれるため）
- ○の引用がシナリオ本体に、△の引用がそのテストケースの行にそのままある
- △の引用が「前提条件」列か操作手順の【準備確認】にしか無いものは認めない（準備の定型文で通したことにしない）
- 扱いが「対象」の値にだけ対応を付ける

## 対応を付ける基準

- その値を条件として設定する／その値の結果を判定するときだけ付ける。
- 付けない：準備の定型文、業務フローの原文をなぞっただけの文、外したと書かれた値、計算で当てはめた値、条件の文はあっても対象のデータを用意していないケース（例：キャンセル済みの受注を除外すると判定するが、キャンセル済みの受注を用意していない）。
- 1画面・1機能の中の入力の違いや画面内の自動切り替えは条件にしない（結合テストの範囲）。結合テストで確かめている業務条件は「他層」とし、ケースIDを備考に書く。
