# 業務完遂可否の事前検証（机上）

シナリオテストどおりにシステムを動かしたとき、業務フローの各工程が実行できるかを、実機を使わずに判定した台帳。

- 生成: `python3 scenario_test/tools/build_feasibility_ledger.py`
- 出力: `feasibility_by_step.tsv`（工程単位・878行）/ `feasibility_by_scenario.tsv`（シナリオ単位・158行）
- 判定は既存の一次資料からの機械読み取りのみ。推測で埋めた欄は無い。

## 判定材料

| 材料 | 使い方 |
|---|---|
| `scenario_test/scenario/SCN-*.md` の `## メインフロー` | 工程ごとの「利用画面・機能」。機能No／「専用の機能設計書なし」／「EC-CUBE操作なし」／「業務判断」が原典側に明示されている |
| `design_impl_drift_report/drift_findings_list_open.tsv` | 機能No単位の未解決乖離1,244件（未実装436・実装違い808／全件が未対応または部分対応・HEAD `da9c2ba276` 時点） |
| `functions/**/*.md` | 機能Noの設計書が実在するか（390機能No） |
| `scenario_test/scenario/09_設計ギャップ差し戻しリスト.md` | 人手調査済みの設計ギャップ（G1〜G3） |
| `scenario_test/test_items/all_scenario_test_items.tsv` | 工程に対応するテストID |

## 判定の意味と、断定していないこと

| 判定 | 断定の強さ |
|---|---|
| 実行不能(設計書が見つからない) | **断定**。09で人手調査し、機能設計書が見つからないと確認済みの工程だけに付く。根拠列に該当のG番号が入る |
| 判定不能(実行手段が未特定) | **断定しない**。SCNの「専用の機能設計書なし」は、生成器が08トリアージでUNKNOWN/未収載の工程に出すラベル（`generate_scenarios.py:1389`）で、**設計書の不在を確認したものではない**。09と同じ調査をすれば「別の設計書にある／未設計／手作業」のどれかに決まる |
| 要確認(未実装指摘あり) | **断定しない**。乖離指摘は機能No単位で、その工程の操作に当たるかまでは特定していない。指摘の観点列を見て人が判断する |
| 要注意(実装違い指摘あり) | 同上 |
| 実行可(乖離指摘なし) | 使う機能に未解決指摘が無いことを示すだけで、実機で通ることの保証ではない |

## この台帳で分かった、既存資料の不足

`09_設計ギャップ差し戻しリスト.md` は影響範囲を「8工程 / 21シナリオ」としているが、実行手段が未特定の工程は
**14種・35工程・29シナリオ**ある。差の6種・16工程・13シナリオは同リストで調査されていない。

| 業務 | 未調査の工程 | 工程数 |
|---|---|---:|
| 店頭買取 | 店舗商品準備（バーコード印刷・Excelマクロ実行を含む） | 6 |
| 通販受注管理 | お客様対応（EC-CUBEでの対応） | 3 |
| 在庫管理 | 安価カード在庫補充作業 | 3 |
| 価格管理 | 価格反映作業（EC-CUBEへの価格変更反映） | 2 |
| 商品登録・編集 | デッキリスト作成（ECサイトのデッキ構築より作成） | 1 |
| 在庫管理 | 低額以外棚卸作業 | 1 |

09と同じ様式で設計側に差し戻せば、「実行不能」か「別設計書にある」か「手作業」かが確定する。

## 限界

- 実機で動かした結果ではない。実装乖離の指摘は機能単位で、工程単位の可否までは決まらない。
- 代替フロー・異常系分岐の工程は対象外。SCNの `## 代替フロー` 表には「利用画面・機能」列が無く、
  機能Noが原典側で特定されていないため、メインフロー878工程だけを判定した。
- データ連鎖列（`実行可能/要確認/終端`）は参考値。業務フロー図のデータ遷移線の結線状況であり、
  実行可否そのものではない（詳細は `scenario/12_優先差し戻しリスト.md`）。
