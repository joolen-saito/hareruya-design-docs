# シナリオテスト 具体化TSV（結合テストと同形式）

`scenario_test/test_items/all_scenario_test_items.tsv`（11列・1,067行）を、結合テストの具体化TSV
`integration_test/e2e/exec/tsv/*_concretized.tsv` と同じ列構成・同じ整形規則へ機械変換したもの。

- 生成: `python3 scenario_test/tools/emit_scenario_concretized_tsv.py`
- 出力: `scenario_test/exec/tsv/sti-<業務コード>_concretized.tsv`（業務別10本）
- 元TSVからの決定的な導出のみで、値の新規創作は行っていない。

## 列構成（14列）

先頭13列は結合テスト具体化TSVと同一。14列目のみシナリオ層固有。

| # | 列 | 結合テストとの差分 |
|---:|---|---|
| 1-6 | 機能名 / テストID / I/FID / テスト観点 / 優先度 / テスト項目名 | 元TSVの値を転記（I/FIDの `-` は `—` に統一） |
| 7 | 前提条件 | 12キーの構造化ブロブを1行に再構成 |
| 8 | 使用シード | **新設**。元は前提条件に内包されていた実値を分離 |
| 9 | 入力データ/リクエスト内容 | 1行化 |
| 10 | 操作手順/実行方法 | セル内改行を除去し `1. … 2. …` に平坦化 |
| 11 | 期待結果／レスポンス | 文末を「〜こと」で統一 |
| 12 | 自動検証（内部: session/DB/URL） | **新設**。全行 `—`（下記） |
| 13 | 実行方法 | **新設**。確認対象から導出（下記） |
| 14 | 確認対象 | シナリオ層固有。結合テスト形式に受け皿が無いため末尾に保持 |

## 変換規則

- **前提条件**: 元の12キーのうち、他列と重複するものを落として再構成する。
  - 残す: 元シナリオID / 経路ID・経路種別 / 主アクター / 前提差分 / 関連システム
  - 落とす: 業務（機能名に内包）・業務経路条件（前提差分に内包）・最終業務状態（期待結果に内包）・
    データパターンID/種別（入力データ列へ）・シードデータ（使用シード列へ）
- **使用シード**: 前提条件の「シードデータ:」以降を逐語で転記。結合テスト側の `SEED-*` のような
  ID体系はシナリオ層に存在しないため、実値（`担当者アカウント=st-user-…` 等）をそのまま置く。
- **操作手順**: 冗長な先頭行「担当者: X」は前提条件の主アクターと重複するため除去し、
  従属行「対象: …」は直前の手順へ併合する。手順の番号と本文は保持。
- **自動検証（内部）**: シナリオ層は業務要件の充足を画面・現物で観測する層で、元データに
  内部状態（session/DB/URL）の観測仕様が存在しない。捏造を避けるため全行 `—` とする。
- **実行方法**: シナリオ層に自動実行ハーネスは無いため全行「手動」。確認手段の種別を
  確認対象から機械導出して括弧で補記する（複数種別にまたがる行は先頭種別＋「ほか」）。

  | 確認対象に含まれる語 | 実行方法 | 件数 |
  |---|---|---:|
  | 現物・現品 | 手動（現物確認） | 284 |
  | 外部システム / 外部アプリ | 手動（外部システム確認） | 153 |
  | 送信されたメール / メール，通知 | 手動（メール/通知確認） | 44 |
  | 出力されたCSV / CSV，帳票 | 手動（CSV/帳票確認） | 118 |
  | 上記以外 | 手動（EC-CUBE画面確認） | 468 |

## 生成時のハードゲート

`emit_scenario_concretized_tsv.py` は以下を満たさない場合エラー終了する。

- 入力1,067行 = 出力の合計行数（取りこぼし0）
- 全行が14列
- セル内に改行・タブが残っていない

## 既知の元データ品質問題（本変換では是正していない）

- **データパターン種別と経路種別の不整合**: 前提条件の `経路種別` は 主要代替568/正常代表430/業務異常69 だが、
  入力データの `データパターン種別` は 1,033行が「正常系 代表」で固定されている（603行が不整合）。
- **主アクターと項目名の担当者不一致**: 項目名から担当者を抽出できた878行のうち166行で、
  項目名の担当者（例「店舗チームが〜」）と `主アクター`（例「トレードチーム」）が食い違う。

いずれも元TSVの生成側（`scenario_test/tools/build_all.py` 系）の問題であり、テスト内容の書き換えに
あたるため本変換では触れていない。
