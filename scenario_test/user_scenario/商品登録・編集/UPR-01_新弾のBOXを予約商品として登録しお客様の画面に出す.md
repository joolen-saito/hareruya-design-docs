# UPR-01 新弾のBOXを予約商品として登録し、お客様の画面に出す

| 項目 | 内容 |
|---|---|
| 利用者 | トレードチームの担当者（登録担当。現状版は顧客戦略チーム）→ お客様 |
| 目的 | 新弾の発表を受け、カードセット・略称タグ・商品カテゴリを先に登録し、新弾のBOXを予約用の購入グループのグッズ商品としてCSVで登録して、公開にした商品がお客様の画面（本店。本店・支店がどちらも公開なら支店も）に出ることを確かめる |
| 種類 | 正常 |
| マトリクスの行 | `matrix_UPR-01/matrix.md` のT01（本店の商品公開ステータス＝公開・支店の商品公開ステータス＝公開）。商品カテゴリは複数指定、カテゴリの新規登録は画面で登録する |
| もとのシナリオ | SCN-PRODUCT-001 |

## 前提

- 共通の決まり：`../L4を流すときの共通の決まり.md` を先に読む（試験データの名前にシナリオIDを付ける・共有の設定は元に戻す・バッチの起動・店舗の読み替えなど）
- システムの外で済んでいること：新弾の発表（発売1か月半前）。BOXの商品画像をS3へ保存済み（CSVの規格画像に画像の保存先を書く）
- 用意するデータ（試験用の値。設計書の値ではない）
  - 登録担当：管理画面で、カード管理・商品管理・カテゴリを編集できる権限を持つ担当者
  - カードセット：「シナリオ試験セットZ」（英名「Scenario Test Set Z」、略称は半角英数字、リリース日は発売日）
  - 略称タグ：名称「STZ」、並び順は任意の数、アルファベット順ソートフラグは付けない
  - 商品カテゴリ：新規に登録する「シナリオ試験 予約カテゴリ」（日・英の名称）。商品には、すでにある「予約サプライ・グッズ」（カテゴリ番号4。開発環境の決め打ちの値で、商品の初期データの名前は「予約サプライ・グッズ」。流す前に、カテゴリ一覧の「CSVダウンロード」で番号と名前を確かめる。2026-11-26 codex のレビュー）とこの新カテゴリの2つを指定する
  - 購入グループ：「予約BOX用（シナリオ試験）」。購入グループ登録/編集で、予約商品フラグを付けたものを用意する（開発環境の購入グループには予約商品フラグが付いたものが無い。フィードの予約商品の判定はこの値による）
  - 商品：グッズ「シナリオ試験BOX」（商品コード「UPR01-BOX」、基準価格・販売価格 15,000円、買取価格 10,000円、販売制限数（購入上限数）2、購入グループ「予約BOX用（シナリオ試験）」、スマレジ連携フラグは無効、商品公開ステータス＝公開、支店の商品公開ステータス＝公開）。グッズ商品CSVに1行書く
  - お客様：ログインしなくても見られる範囲で確かめる（商品詳細と検索）
- グッズ商品CSVの取り込みは、同じ商品コードを2回は登録できない。試験をやり直すときは商品コードを変える。行ごとに別の商品コード（T01は「UPR01-BOX」、T02〜T04は「UPR01-BOX-T02」〜「UPR01-BOX-T04」）と商品名にする
