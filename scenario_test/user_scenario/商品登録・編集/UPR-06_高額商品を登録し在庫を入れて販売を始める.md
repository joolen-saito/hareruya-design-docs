# UPR-06 高額商品（個別登録商品）を登録し、在庫を入れて販売を始める

| 項目 | 内容 |
|---|---|
| 利用者 | トレードチームの担当者（登録担当）→ 在庫の承認者 → お客様 |
| 目的 | #ナンバー等の個別登録商品（高額商品）について、商品画像を用意し、カードデータがあるかを確かめ（無ければカードを新規登録）、商品と規格を登録し、在庫を入れて承認を受け、商品公開ステータスを公開にして、お客様の画面に出ることを確かめる。規格のスマレジ連携フラグ（連携しない／連携する）の保存結果も確かめる |
| 種類 | 正常 |
| マトリクスの行 | `matrix_UPR-06/matrix.md` のT01（カードデータが登録済み・規格のスマレジ連携フラグ＝連携しない（OFFのまま））。公開の仕方は「規格を登録してから商品編集画面で公開」、在庫の入れ方は「在庫編集画面で入庫」を前提にする |
| もとのシナリオ | SCN-PRODUCT-006・011 |

## 前提

- 共通の決まり：`../L4を流すときの共通の決まり.md` を先に読む（試験データの名前にシナリオIDを付ける・共有の設定は元に戻す・バッチの起動・店舗の読み替えなど）
- システムの外で済んでいること：高額商品がある。商品画像をスキャンや写真撮影で用意し（業務フロー10 6-1）、S3へ保存済み。商品が店に入荷している
- 用意するデータ（試験用の値。設計書の値ではない）
  - 登録担当と、在庫の承認者（別の担当者。承認権限があり、登録担当の承認通知先に入る）
  - カード：行ごとに別のカードを使う（同じカードの商品は2つ登録できず、「未登録」の条件も保つため）。登録済みの行は、T01「シナリオ試験カードH」・T02「シナリオ試験カードH2」（英名「Scenario Test Card H」「Scenario Test Card H2」。UPR-02 と同じ手順で、この試験の前にカード登録CSVで登録しておく）。未登録の行は、T03「シナリオ試験カードM」・T04「シナリオ試験カードM2」（英名「Scenario Test Card M」「Scenario Test Card M2」）を、手順2で画面から登録する（前もって登録しない）。以降の「シナリオ試験カードH」は、行のカード名に読み替える
  - 商品（T01）：「シナリオ試験カードH」を高額商品として登録する。カード商品CSVの値：言語＝日本語、基準価格 250円（割引率「4」で、NM 250円・SP 230円・MP 200円・HP 180円の4規格ができる。NMの値を、手順5で20,000円に直す）、買取価格 100円、販売制限数1、購入グループ「通常商品」、商品カテゴリ1つ、商品公開ステータス＝非公開、支店の商品公開ステータス＝非公開。規格（NM）に付ける高額商品コード「#UPR06T01」、基準価格・販売価格 20,000円、買取価格 15,000円
  - 在庫：1点（個別登録商品なので1点）。在庫編集画面で、在庫変動区分「入庫」で入れる
- 商品はカード商品CSVで新規登録する（商品編集画面からは新規登録できない）。新実装では、CSVで商品と規格が一緒にできるので、業務フローの「商品マスターから商品の設定ページ（商品登録）へ」「規格設定へ行き、新規登録から情報を登録する」は、CSVで登録された商品と規格を開いて高額商品の情報を足す形になる（`scenario_list.md` の確かめたこと）
- 在庫が承認されるまでは在庫0。登録担当と承認者は別の担当者

## 操作の流れと期待値

| # | 操作する人と操作 | 期待値（画面で見えること） |
|---|---|---|
| 1 | システムの外の作業：高額商品の画像をスキャンや写真撮影で用意する（6-1） | 画面の変化は無い |
| 2 | 登録担当：管理画面のカード管理＞カード一覧で、「シナリオ試験カードH」を検索する（6-2 カードデータの有無の確認） | 1件出る（カードデータが登録済みなので、カードの登録は行わず、商品の登録へ進む）。カード編集画面でカード詳細IDを控える |
| 3 | 登録担当：カード商品CSVを作り（システムの外）、商品管理＞商品CSV管理＞カード商品CSV登録で、ファイルを選んで「CSVファイルをアップロード」を押し、確認の画面（「カード商品CSVをアップロードします。よろしいですか？」）で「確認」を押す（6-3） | 「CSVファイルをアップロードしました」が管理画面の上部に出て、CSVインポート履歴が1件増える。商品が新規に登録される |
| 4 | 登録担当：商品管理＞商品一覧で「シナリオ試験カードH」を検索し、商品編集画面を開く。個別登録するカードに用意した商品画像を追加して、「商品を登録」を押す（6-4） | 検索結果に1件。商品公開ステータスは「非公開」、支店の商品公開ステータスは「非公開」（新規は非公開）。規格は4件（NM・SP・MP・HP。割引率「4」で、基準価格・販売価格はNM 250円・SP 230円・MP 200円・HP 180円）で在庫0。画像を追加して保存すると「保存しました」が出て、画像が表示される |
| 5 | 登録担当：商品編集画面の「規格設定」を押して、NMの規格を開く（個別登録商品として使うのはNMの規格。SP・MP・HPの規格は在庫0のまま使わない。判断待ち 2）。高額商品コード「#UPR06T01」・基準価格20,000円・販売価格20,000円・買取価格15,000円・販売制限数1を入れ、スマレジ連携フラグは「連携しない」のままにして、「商品規格を登録」を押す（6-4） | NMの基準価格を250円から20,000円に変えたので、「閾値(300円)をまたぐ価格変更がされたので、スマレジ連携フラグを確認してください」の確認が出る（連携フラグがOFFのため。閉じると保存が続く）。「保存しました」が出る。規格一覧で、高額商品コード・価格が入力値になり、スマレジ連携フラグは「連携しない」、スマレジ商品コードは空 |
| 6 | 登録担当：管理画面の在庫管理＞在庫一覧で「シナリオ試験カードH」を検索する（在庫一覧は規格ごとに出る）。高額商品のNM規格の、店舗「本店」・在庫区分EC（本店のEC在庫）の行の操作から「在庫編集」を開き、在庫変動区分「入庫」で、高額商品のNM規格の本店EC在庫に1点を入れ、承認通知先（所属・メンバー）に承認者を選んで登録する（6-5。tobe版の在庫の入れ方は在庫編集画面または在庫変更CSV登録） | 在庫編集承認一覧に、承認状態「未承認」で登録される。承認者のメールアドレスに通知メールが届く。この時点で在庫は0のまま（承認されるまで入庫は在庫に入らない）。商品規格画面では在庫を変えられない |
| 7 | 承認者：在庫管理＞在庫編集承認一覧で、登録担当が登録した行にチェックを入れ、「一括承認」を押す（設計書の画面項目は「承認」）。確認の画面で「承認する」を押し、最後の確認「本当に承認してもよろしいですか？」で「OK」を押す | 登録した行は、登録者がログイン中のユーザーではないので、チェックボックスが出て選べる。承認状態が「承認済」になる。登録担当に承認ステータス変更のメールが届く。商品の在庫が1になる |
| 8 | 登録担当：商品編集画面を開き、商品公開ステータスを「公開」にして「商品を登録」を押す（規格を登録してから公開の操作をする） | 「保存しました」が出る。商品公開ステータスが「公開」になる。支店の商品公開ステータスは「非公開」のまま |
| 9 | システムの外の作業：特集ページへの記載や告知を、販売開始に合わせて行う（6-6） | 画面の変化は無い |
| 10 | お客様：本店の商品詳細を、商品IDで直接開く | 商品詳細が開き、価格20,000円・在庫1が出る。支店の商品詳細は開かない（支店が非公開） |
| 11 | 登録担当：管理画面の商品管理＞ユニサーチフィード作成で「フィードファイルを更新する」を押し、ユニサーチ側の取り込みが終わるまで待つ（外部サービス）。お客様：本店のヘッダーの検索欄に「シナリオ試験カードH」と入れて検索する | 「ユニサーチフィードの作成を開始しました。」が出る。取り込みのあと、本店の検索結果に商品が出て、在庫1・価格20,000円が表示される。フィードに載る前は検索に出ない（UPR-01 の手順9と同じ）。支店の検索結果には出ない |

## 終わったあとに確かめること

| 確かめる場所 | 期待値 |
|---|---|
| 在庫一覧の在庫変動履歴 | 入庫1点が、変更前0・変更後1で残る |
| スマレジ連携 | 連携しない規格なので、スマレジに商品は登録されない。EC-CUBEからスマレジへの在庫連携は行わない |
| SP・MP・HPの規格（個別登録商品として使わない規格） | 在庫0のまま残る（在庫を入れず、削除も非公開もしない。設計書に定めが無いので、判断待ち 2 の決着のとおりこの扱い）。お客様の本店の商品詳細で、この3規格は在庫が無く売れない（買い物かごに入れられない）。実際の表示を記録する（設計書に表示の定めが無いので、合否は付けない） |
