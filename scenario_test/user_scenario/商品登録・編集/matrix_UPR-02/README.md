# 商品登録・編集の予約シングルの販売準備（UPR-02）

IPA「高信頼化ソフトウェアのための開発手法ガイドブック」(2010) の表6-9〜6-11と同じ手順で作る。

1. 因子・水準表（FL表）: `fl_table.tsv`。トレードチームがCSVで決める値（カードの登録の状態・公開ステータス・カテゴリの指定）を因子にした
2. 禁則表: `prohibitions.tsv`。ありえない組は無い（空）
3. 組み合わせテストマトリクス: `matrix.md` / `matrix.tsv`。`build_matrix.py` が作る。1行が1本のシナリオになる
4. 例外の差し込み表: `exceptions.tsv`。エラーや中断は、正常な値と混ぜず、条件に合う行へ1つずつ差し込む

## 範囲

- 公式のカードリスト公開から、カード登録CSV・カード商品CSVの取り込み、商品マスターで確かめるところまで（業務フロー2-1〜2-9）。登録後の商品情報編集（2-10）は、マトリクスに入れず `../scenario_list.md` のL3に書いた
- 発売日1週間前のプレリリース業務（2-11）は店舗チームの別の作業。ここでは扱わない
- 各行の期待値：カード商品CSVの値どおりに商品・規格が登録され、本店・支店の公開状態と購入上限数（全行で設定）が商品マスター・商品編集画面で確かめられる。公開にした商品は、本店が公開なら本店の画面に、本店と支店がどちらも公開なら支店の画面にも出る
- 購入上限数は因子にしない。予約商品は購入上限数を規格に必ず登録する（業務フロー10 2-9「予約商品なので購入上限数も規格にて登録する」）ので、全行で設定する
- 因子に入れなかったもの：カードの状態（登録するのはNMだけ。業務フロー2-6「バリエーションとしてはNMしか登録しない想定」）、スマレジ連携（NMは自動判定の対象外。0204 カード商品CSV登録「販売価格が300円以上かつ状態がNM以外の規格である場合は自動でスマレジ連携を行う」）、カード画像（画像のパスはCSVに入れる。S3への保存はシステムの外）

## 実装・設計書で確かめたこと（2026-11-03）

- 商品の新規登録は、商品編集画面からはできない。新実装の商品編集は、商品IDが無い（新規）アクセスに「見つからない」を返す。このためUPR-02の商品登録はカード商品CSV登録で行う（設計書 0204 商品登録編集「商品新規登録のURL…にアクセスすると、404(Page Not Found)エラーを返す」）
- 公開ステータスの数値は設計書内・設計書と新実装で食い違うため、行では数字でなく名前（公開・非公開）で書く（`../scenario_list.md` の食い違い）

## まとめた水準

なし（どの水準も処理が違う）。主な根拠：新規カードと登録済みカードは新規登録か更新かが違い、本店公開・支店公開のステータスは公開と非公開で店舗の画面への出る出ないが違う。カテゴリ1つとカンマ区切りの複数は設定の処理が違う。
