# 商品登録・編集の発売日の通常商品への切り替え（UPR-03）

IPA「高信頼化ソフトウェアのための開発手法ガイドブック」(2010) の表6-9〜6-11と同じ手順で作る。

2026-11-09：シナリオの本文に「／」で並べていた値を、1回ずつ流すテストに分けるために作った（IPA 6.3.1・6.3.2。依頼者決定）。値と期待値は本文に書いてあったものを水準ごとに分けただけで、新しい期待値は作っていない。

## 範囲

- 発売日に予約商品を通常商品へ切り替えるところ（業務フロー3-1・3-2）。購入グループを予約用のものから通常商品へ替える
- 因子は「切り替える商品とその規格のセール状態」だけ。更新時の規格のセール状態（セール外／セール中）は更新用カード商品CSV（シングル）のときの話で、予約BOX（グッズ商品CSV）には本文に書かれていないので、組み合わせず、2つの水準にした（予約BOXは2026-11-09に外した）
- 予約BOXの切り替えは、業務フローの工程には無く、仕組みの確認として通す（scenario_list.md の決着 2026-11-09）

## 期待結果の決まり

- 規格がセール外：基準価格と販売価格がどちらもCSVの値になる
- 規格がセール中：基準価格だけが更新され、販売価格は変わらない
- 予約BOX：購入グループが通常商品のものになり、お客様が通常商品として注文できる

※因子が1〜2つのとき、`tools/build_matrix.py` は網羅率の分母が0になって止まる（2026-11-09時点）。この表は、割り算の前に分母0を100％として扱い、因子が1つのときは水準ごとに1行にする以外は `build_matrix.py` と同じ手順の写しで作った。道具が直れば、下のコマンドで同じ表ができる。

## 外した因子・水準（2026-11-09 依頼者決定：画面の操作の違い）

業務の流れも結果も分かれない画面操作の違いは、組み合わせ表から外し、結合テストに任せる（依頼者決定）。値と期待値は消しただけで、新しく作っていない。

- 水準A3「予約BOX（グッズ商品CSV登録で購入グループを予約用でないものへ替える）」を外した。カード商品CSVと入口が違うだけで、通常商品へ切り替わる結果は同じ。行は3から2になった。
