# UPR-05 入荷した商品の在庫を入れ、承認を受け、公開して販売を始める

| 項目 | 内容 |
|---|---|
| 利用者 | トレードチームの担当者（登録担当）→ 在庫の承認者 → トレードチームの担当者 → お客様 |
| 目的 | 登録済みの商品が入荷したあと、在庫変更CSVで在庫を入れ、承認者の承認で商品の在庫に入れ、非公開の商品は商品公開CSVで公開に直して、お客様の画面に出ることを確かめる（現状版は在庫更新のCSVと公開のCSVを同じ流れで取り込む） |
| 種類 | 正常 |
| マトリクスの行 | `matrix_UPR-05/matrix.md` のT01（商品が非公開だった（商品公開CSVで公開に直す））。T02は既に公開されていた。例外E1（承認者が却下する）・E2（登録した本人が承認しようとする）は1つずつ別のテスト |
| もとのシナリオ | 今のシナリオには無い（SCN-PRODUCT-004・010は4-3まで）。在庫の入れ方・承認の詳細は UZK-01 |

## 前提

- 共通の決まり：`../L4を流すときの共通の決まり.md` を先に読む（試験データの名前にシナリオIDを付ける・共有の設定は元に戻す・バッチの起動・店舗の読み替えなど）
- システムの外で済んでいること：商品が店に入荷している
- UPR-04 の終点を使う
  - T01（非公開だった）：UPR-04 の T03 の終点（オリパ「シナリオ試験オリパB」、商品コード「UPR04-T03」、連携無効、商品公開ステータス＝非公開、支店の商品公開ステータス＝公開、在庫0）。商品IDを控えている
  - T02（既に公開されていた）：UPR-04 の T01 の終点（「シナリオ試験サプライA」、商品コード「UPR04-T01」、商品公開ステータス＝公開、支店＝非公開、在庫0）
  - 例外E1・E2：まだ入庫していない商品を使う（T01 で在庫を入れたあとの商品は使えない。UPR-04 の T03 と同じ手順で、別の商品コード・商品名の商品を足して用意する）
- 用意するデータ（試験用の値。設計書の値ではない）
  - 登録担当と、在庫の承認者（別の担当者。在庫編集の承認権限があり、登録担当の承認通知先に入る）。登録した本人は承認できない
  - 入庫：在庫変更CSVで5点（在庫変動区分は入庫、仕入単価を書く）。ファイル名は、過去1か月以内に登録した在庫変更CSVと別の名前にする（同じ名前だと「過去1か月以内に同じファイル名の在庫変更CSVが登録されています。」が出る）
- 在庫が承認されるまでは在庫0のまま

## 操作の流れと期待値

| # | 操作する人と操作 | 期待値（画面で見えること） |
|---|---|---|
| 1 | システムの外の作業：商品が入荷した | 画面の変化は無い |
| 2 | 登録担当：管理画面の在庫管理＞在庫一覧で、商品名「シナリオ試験オリパB」を検索し、「在庫情報CSV出力」を押す（業務フロー10 4-7の「グッズ・サプライ情報商材登録CSVで登録した商品を絞り込み、在庫インポート用CSVのもとになるCSVを出力する」。業務フローはカスタムCSV出力。画面には「在庫情報カスタムCSV出力」もある） | 検索結果に商品が出る（在庫0）。CSVがダウンロードされ、「シナリオ試験オリパB」の商品コードが入っている |
| 3 | 登録担当：在庫インポート用CSVを作る（システムの外の作業。4-7）。出力したCSVの商品コードを使い、在庫増減数5、仕入単価を書く（列は商品コード・在庫増減数・仕入単価） | 画面の変化は無い |
| 4 | 登録担当：在庫管理＞在庫変更CSV登録で、店舗「本店」・在庫場所「EC」（フロントは表示中の店舗のEC在庫を見る）・在庫変動区分「入庫」・在庫変動理由を選び、承認通知先（所属・メンバー）に承認者を選んで、手順3のCSVを選び、「一括登録を実行」を押す（4-8） | 登録される。在庫変更CSV登録履歴（承認テーブルの情報）に、ファイル名・店舗/在庫場所・対象商品規格数1・合計在庫増減数5・在庫変動区分「入庫」・登録者が出て、承認状態は「承認待ち」。在庫編集承認一覧には、承認ステータス「未承認」で出る。承認者のメールアドレスに通知メールが届く。この時点で在庫は0のまま（承認されるまで入庫は在庫に入らない） |
| 5 | 承認者：管理画面の在庫管理＞在庫編集承認一覧を開く。登録担当が登録した行にチェックを入れ、「一括承認」を押す（設計書の画面項目は「承認」）。確認の画面（「この操作はあとから取り消すことができません。選択した内容を確認してください。」）で「承認する」を押し、最後の確認「本当に承認してもよろしいですか？」で「OK」を押す | 登録した行は、登録者がログイン中のユーザーではないので、チェックボックスが出て選べる。承認状態が「承認済」になり、承認日・承認者が出る。登録担当のメールアドレスに承認ステータス変更のメールが届く |
| 6 | 登録担当：商品管理＞商品一覧で「シナリオ試験オリパB」の在庫を見る | 在庫が5になっている（承認で入庫が在庫に入る）。在庫一覧の在庫変動履歴に、入庫5点・変更前0・変更後5が残る |
| 7 | 登録担当：商品公開CSVを作る（システムの外。4-7。商品ID・商品公開ステータス「公開」・支店の商品公開ステータス「公開」の3列）。商品管理＞商品CSV管理＞商品公開CSV登録で、ファイルを選び「CSVファイルをアップロード」を押し、確認の画面（「商品公開CSVをアップロードします。よろしいですか？」）で「確認」を押す（4-9「非公開商品だった場合公開設定に変更する」） | 「登録が完了しました。」が出る。商品編集画面で、商品公開ステータスが「公開」、支店の商品公開ステータスが「公開」になる。商品公開CSV登録は新規登録をしない（商品が増えない） |
| 8 | お客様：本店の商品詳細を、商品IDで直接開く。続けて、支店のサイトで同じ商品の詳細を開く | 本店の商品詳細が開き、価格・在庫5が出る。本店・支店がどちらも公開なので、支店の商品詳細も開く |
| 9 | お客様：本店のヘッダーの検索欄に「シナリオ試験オリパB」と入れて検索する（ユニサーチのフィードを送る前） | 検索結果に商品が出ない（公開にしただけでは、次のフィードがユニサーチに載るまで検索に出ない。0件の案内は「お探しの商品は見つかりませんでした」。新実装の商品一覧の表示で、設計書の一覧領域の文言とは違うので、出た文言を記録する） |
| 10 | 登録担当：管理画面の商品管理＞ユニサーチフィード作成で「フィードファイルを更新する」を押す。ユニサーチ側の取り込みが終わるまで待つ（外部サービス）。お客様：本店・支店のサイトで、手順9と同じ語で検索する | 「ユニサーチフィードの作成を開始しました。」が出る。取り込みのあと、本店・支店の検索結果に商品が出て、在庫5・価格が表示される。フィードの行の中身は UTH-01 の手順8で確かめる |
