# 商品登録・編集のスタン落ちの商品情報の変更（UPR-10）

IPA「高信頼化ソフトウェアのための開発手法ガイドブック」(2010) の表6-9〜6-11と同じ手順で作る。

2026-11-09：シナリオの本文に「／」で並べていた値を、1回ずつ流すテストに分けるために作った（IPA 6.3.1・6.3.2。依頼者決定）。値と期待値は本文に書いてあったものを水準ごとに分けただけで、新しい期待値は作っていない。

## 範囲

- スタン落ちが決まったときの、商品の親カテゴリーの変更（カード商品はカード商品CSV登録、グッズはグッズ商品CSV登録）とカードのリーガリティの変更（カード一覧から出した対象カードのCSVを直し、カード登録CSVで取り込む）。tobe版のみ（業務フロー10の9-1〜9-6）
- 因子は「スタン落ちで直す内容」だけ。リーガリティは使用可・制限・禁止の3値をそれぞれ別のテストにした（商品の親カテゴリーの変更はカード商品とグッズで取り込む画面が違うので2つ）

## 期待結果の決まり

- 親カテゴリー：商品の親カテゴリが新しいカテゴリに変わる。次のフィードを作って送るまでは、ユニサーチの検索のカテゴリは古いまま（旧カテゴリでは出る）で、次のフィードのあとに旧カテゴリで出ず新カテゴリで出る
- リーガリティ：使用可能フォーマットの列に書けば「使用可」、使用制限フォーマットの列に書けば「制限」、使用禁止フォーマットの列に書けば「禁止」になる（0208 カード登録CSV 識別ID 18〜20）

※因子が1〜2つのとき、`tools/build_matrix.py` は網羅率の分母が0になって止まる（2026-11-09時点）。この表は、割り算の前に分母0を100％として扱い、因子が1つのときは水準ごとに1行にする以外は `build_matrix.py` と同じ手順の写しで作った。道具が直れば、下のコマンドで同じ表ができる。
