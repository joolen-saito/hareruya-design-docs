# 商品登録・編集の新商品（既製品・オリパ・デッキセット）の登録（UPR-04）

IPA「高信頼化ソフトウェアのための開発手法ガイドブック」(2010) の表6-9〜6-11と同じ手順で作る。

1. 因子・水準表（FL表）: `fl_table.tsv`。新商品の種類と、グッズ商品CSVに書く値（スマレジ連携・公開ステータス・カテゴリの指定）を因子にした
2. 禁則表: `prohibitions.tsv`。ありえない組は無い（空）
3. 組み合わせテストマトリクス: `matrix.md` / `matrix.tsv`。`build_matrix.py` が作る。1行が1本のシナリオになる
4. 例外の差し込み表: `exceptions.tsv`。エラーや中断は、正常な値と混ぜず、条件に合う行へ1つずつ差し込む

## 範囲

- tobe版（業務フロー10）の4-1〜4-5まで。商品画像の用意（4-1）、デッキセットのデッキリスト作成（4-2・4-3）、インポート用CSV作成（4-4）、グッズ商品CSV登録（4-5）。終点は商品マスターで商品・規格・部門が確かめられるところ
- 在庫の登録・販売開始（4-6〜4-9）は入荷まで状態が待つのでUPR-05に分けた
- 部門更新CSV（現状版4-6）は、tobe版では「グッズ・サプライ情報商材登録CSV内に部門を登録できるようになるため不要」（業務フロー10 図の注記）。tobe版を優先し、部門はグッズ商品CSVに書く

## 実装・設計書で確かめたこと（2026-11-03）

- 商品の新規登録は商品編集画面からできず、CSV登録で行う（UPR-02のREADMEと同じ）
- 公開ステータスの数値は設計書内・設計書と新実装で食い違うため、行では数字でなく名前（公開・非公開）で書く
- オリパとデッキセットでCSVの書き方が変わるかは設計書に無い。画像の用意（オリパはデザインチーム）とデッキリストの作成（デッキセットだけ）が違うだけとして、行の因子は種類のままにした

## まとめた水準

なし（どの水準も処理が違う）。主な根拠：既製品・オリパ・デッキセットは作り方（画像依頼・デッキリスト作成）が違い、スマレジ連携の有効・無効は部門・スマレジ商品コードの必須の有無が違う。公開・非公開は店舗の画面への出る出ないが違う。
