# UPR-10 スタン落ちで、商品のカテゴリとカードのリーガリティを直す

| 項目 | 内容 |
|---|---|
| 利用者 | トレードチームの担当者（登録担当） |
| 目的 | スタン落ちが決まったあと、カテゴリCSVで親カテゴリを直して商品カテゴリの紐づけを修正し、商品CSVのカテゴリを差し替えて取り込み、商品の親カテゴリが新しいカテゴリに変わることを確かめる。カードのリーガリティは、カード一覧から出したCSVを直してカード登録CSVで取り込み、使用可・制限・禁止が変わることを確かめる。tobe版のみ（現状版の業務フロー09には無い） |
| 種類 | 正常 |
| マトリクスの行 | `matrix_UPR-10/matrix.md` のT01（商品の親カテゴリーを変更する（カード商品はカード商品CSV登録））。T02はグッズ、T03〜T05はカードのリーガリティ（使用可・制限・禁止） |
| もとのシナリオ | SCN-PRODUCT-009 |

## 前提

- 共通の決まり：`../L4を流すときの共通の決まり.md` を先に読む（試験データの名前にシナリオIDを付ける・共有の設定は元に戻す・バッチの起動・店舗の読み替えなど）
- システムの外で済んでいること：スタン落ち（スタンダードで使えなくなるセットが出る）が決まった
- 用意するデータ（試験用の値。設計書の値ではない）
  - 登録担当：管理画面で、商品管理・カード管理を編集できる権限を持つ担当者
  - カテゴリ（UPR-01 の手順3と同じ手順で登録する）：最上位のカテゴリ「シナリオ試験 スタンダード」「シナリオ試験 モダン」、「シナリオ試験 スタンダード」の子のカテゴリ「シナリオ試験 セットZカテゴリ」。カテゴリ番号を控える
  - 商品（T01）：UPR-02 の T06 の終点の「シナリオ試験カードJ6」（公開・公開）。T01 の手順1〜11の「シナリオ試験カードJ」は「シナリオ試験カードJ6」に読み替える（T03 のリーガリティの対象カードの「シナリオ試験カードJ」は、UPR-02 の T01 のカードで別）。商品カテゴリを「シナリオ試験 スタンダード」と「シナリオ試験 セットZカテゴリ」の2つにしておく。ユニサーチのフィードが取り込み済みで、本店のカテゴリの絞り込みで商品が出る
  - カードのリーガリティ（T03〜T05）：フォーマット「Standard」（フォーマット管理にあるフォーマット。英名は開発環境の値で確かめる）。T03：カード「シナリオ試験カードJ」の「Standard」が制限になっている。T04：カード「シナリオ試験カードH」が使用可になっている。T05：カード「シナリオ試験カードM」が使用可になっている（カード編集画面の「リーガリティ」で設定しておく）
- 在庫・価格は変えない。商品公開ステータスは変わらない
- カード商品CSV・カテゴリCSVの列は、出力したCSVの並びのまま使う
