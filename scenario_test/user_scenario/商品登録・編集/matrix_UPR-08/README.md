# 商品登録・編集の既存商品の編集と公開・非公開の切り替え（UPR-08）

IPA「高信頼化ソフトウェアのための開発手法ガイドブック」(2010) の表6-9〜6-11と同じ手順で作る。

2026-11-09：シナリオの本文に「／」で並べていた値を、1回ずつ流すテストに分けるために作った（IPA 6.3.1・6.3.2。依頼者決定）。値と期待値は本文に書いてあったものを水準ごとに分けただけで、新しい期待値は作っていない。

## 範囲

- 商品編集画面で既存の商品を1件編集し、公開・非公開を切り替えるところ（業務フロー09・10の5-1）
- 因子：本店の商品公開ステータスの変更（公開にする／非公開にする／廃止にする／変えない）、支店の商品公開ステータスの変更（公開にする／非公開にする／変えない）
- 本店も支店も「変えない」行は、商品名などの編集だけをするテスト（業務フローの「商品情報の編集」）。それ以外の行は単体の公開・非公開の切り替え
- 禁則：なし（2026-11-09 codex指摘で X1・X2 を外した）。設計書が変更を禁じるのは「廃止で更新された場合、以降」の変更で、同じ更新で本店を廃止にしながら支店の公開ステータスを変える組は禁じていない。本店・支店の公開ステータスは別の項目（0204）
- 廃止（在庫が無いとき）は設計書の定めで、業務フロー5-1には無い。在庫が残る商品を非公開にするとエラーになる（新実装の制約。設計書は廃止だけを書く）。廃止・連携を外す操作に伴うスマレジの商品の削除はUSM-09

## 期待結果の決まり

- 商品編集画面の保存後、商品情報の変更と公開状態がお客様の画面に反映される
- 廃止（在庫が無いとき）にした商品は、以降は変更できない。在庫が残ると廃止できない

※因子が1〜2つのとき、`tools/build_matrix.py` は網羅率の分母が0になって止まる（2026-11-09時点）。この表は、割り算の前に分母0を100％として扱い、因子が1つのときは水準ごとに1行にする以外は `build_matrix.py` と同じ手順の写しで作った。道具が直れば、下のコマンドで同じ表ができる。
