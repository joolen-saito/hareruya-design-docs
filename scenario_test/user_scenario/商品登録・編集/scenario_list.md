# 商品登録・編集：シナリオ一覧（L2）

シナリオ1本は「起点の業務イベントから、業務として完了した状態になるまで」とする。担当者が替わっても切らない（トレードチーム→在庫の承認者→お客様の画面）。日をまたぎ、システムの状態が何かを待つもの（予約商品が発売日を待つ、商品が入荷を待つ）は別の1本にする。ただし、日をまたぐのがシステムの外の作業だけで、システムの状態が何も待たないとき（公式サイトからの画像取得、S3への画像保存、委託販売の申し込みと契約など）は分けない。条件違いはL3のバリエーションとして、組み合わせテストマトリクス（ペアワイズ）で絞る。

商品は、新規登録を商品編集画面からできない（下記）。新規登録はカード商品CSV登録・グッズ商品CSV登録で行い、既存商品の変更は商品編集画面とCSV登録で行う。

### 設計書との食い違い（設計書の不足。起票はしない）

- 公開ステータスの数値：0204 カード商品CSVフォーマット・グッズ商品CSVフォーマットは「1: 非公開 2:公開 3:廃止」、0204 商品公開CSVフォーマットは「1: 非公開 2:公開」とし、同じシートの注記では廃止を「2 - 廃止」と書く（同じシートの中で食い違う）。新実装は1=公開、2=非公開、3=廃止。支店の公開ステータスも、カード商品CSVフォーマットは「0: 非公開 1:公開」、商品公開CSVフォーマットは「1: 非公開 2:公開」と書き、新実装は0=非公開、1=公開。このシナリオ一覧では数字でなく名前で書いた。商品管理から注文確認メールまでの一覧（UPM）もこの一覧と同じく数字でなく名前で書いており、表記は揃っている。結合テストは設計書の値（2=公開）で進める決めがある（`PROGRESS.md` の商品登録・編集の項）が、設計書と新実装のどちらを正とするかは依頼者への確認事項のまま
- 商品の新規登録：業務フロー1-3・6-4は商品マスターの新規登録（設定ページ）と書くが、0204 商品登録編集は新規登録のアクセスを禁止する
- 高額商品：tobe版の図は「2-4～2-6を行う」だけで、商品登録（2-7〜2-9）に触れない。パターン6の題は「在庫変更CSV登録で増やす」、6-5は「在庫編集画面で在庫を更新する」と書き、方法が2つある。どちらも設計書にあるのでL3に入れた
- スマレジ連携の解除：0204 は非公開・廃止に変えると連携を外すと定めるが、新実装のカード・グッズ商品CSV登録は廃止のときだけ連携を外し、非公開ではCSVの連携フラグ（カードは既存の連携）を維持する。商品編集画面は非公開でも解除する。UPR-09（CSV）では連携が残りうる
- 在庫が残る商品の非公開化：新実装の商品編集は「在庫がある商品規格は非公開にできません」とエラーにするが、設計書は廃止だけを書く
- 廃止の商品：0204 商品登録編集は廃止後の変更を禁じるが、新実装のカード・グッズ商品CSV登録は廃止の商品も更新できる（商品公開CSV登録は処理しない）
- 在庫の承認：業務フロー（現状版・tobe版）の4-7・4-8、6-5には在庫の承認が書かれていないが、0202は在庫変更CSV登録・在庫編集とも承認（在庫編集承認一覧）を要件にしている
- 予約BOXの発売日の切り替え：業務フロー3-1・3-2は更新用カード商品CSV（シングルカード）だけを書く。予約BOXを通常商品に切り替える工程は書かれていない
- 業務フロー10の番号：4-6・4-7・4-8が2回ずつ以上現れる（デッキセットの在庫登録、デッキセット以外の在庫登録、在庫CSV出力など）
- 今のシナリオ SCN-PRODUCT-009 の「Standard=使用不可」は、0208 の値（使用可・制限・禁止）に無い
