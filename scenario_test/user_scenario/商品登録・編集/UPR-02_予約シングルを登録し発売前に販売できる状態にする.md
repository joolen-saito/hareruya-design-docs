# UPR-02 予約シングルを登録し、発売前に販売できる状態にする

| 項目 | 内容 |
|---|---|
| 利用者 | トレードチームの担当者（登録担当。現状版は顧客戦略チーム）→ ITチーム（画像パス対応表）→ お客様 |
| 目的 | 公式のカードリストが公開されたあと、カード登録CSVでカードを登録・更新し、カード商品CSVで予約シングルの商品・規格を登録して、本店・支店の公開ステータス・購入上限数・カテゴリ・スマレジ連携の自動判定が登録値どおりになり、公開にした商品がお客様の画面に出ることを確かめる |
| 種類 | 正常 |
| マトリクスの行 | `matrix_UPR-02/matrix.md` のT01（未登録のカード（新規に登録する）・本店の商品公開ステータス＝公開・支店の商品公開ステータス＝非公開・商品カテゴリ1つ・状態がNM（NM規格は300円以上でも連携の対象にならない）。割引率は開発環境の初期データの「割引率4」を使い、NM・SP・MP・HPの4規格ができる）。購入上限数は全行で設定する |
| もとのシナリオ | SCN-PRODUCT-002 |

## 前提

- 共通の決まり：`../L4を流すときの共通の決まり.md` を先に読む（試験データの名前にシナリオIDを付ける・共有の設定は元に戻す・バッチの起動・店舗の読み替えなど）
- システムの外で済んでいること：公式サイトからカードリストが公開された（発売週の2週間前）。カードリストの作成、カード画像の取得とS3への保存、ITチームによるカード画像パス対応表の作成（業務フロー10 2-1〜2-3）。カード画像のパスはCSVに入れる
- UPR-01 の手順1・3の終点を使う：カードセット「シナリオ試験セットZ」、商品カテゴリ「シナリオ試験 予約カテゴリ」（番号を控えておく）。商品カテゴリを複数指定する行は、もう1つ「シナリオ試験 レアリティカテゴリ」を同じ手順で登録しておく（業務フロー10 2-8「商品カテゴリーをレアリティ別などにして入力してもらう」）
- 用意するデータ（試験用の値。設計書の値ではない）
  - 登録担当：管理画面で、カード管理・商品管理を編集できる権限を持つ担当者
  - カード：「シナリオ試験カードJ」（英名「Scenario Test Card J」、レアリティ・レイアウト・画像URL（英語）は必須、カードセット「シナリオ試験セットZ」）。カード登録CSVに1行書く。登録済みのカードの行（T04〜T06）は、同じ英名のカードをこの試験の前に登録しておく
  - 行ごとのカード：同じカードの商品は2つ登録できず、同じカードの新規の行は飛ばされるので、行ごとに別のカードを使う。T01「シナリオ試験カードJ」（英名「Scenario Test Card J」）、T02〜T08は「シナリオ試験カードJ2」〜「シナリオ試験カードJ8」（英名「Scenario Test Card J2」〜「Scenario Test Card J8」）。カードの状況が「登録済み」の行（T04・T05・T06）のカード（J4・J5・J6）は、この試験の前に、カード登録CSVで登録しておく。「未登録」の行（T01・T02・T03・T07・T08）のカードは、前もって登録せず、手順3で新規に登録する。以降の手順・L3の表の「シナリオ試験カードJ」は、行のカード名に読み替える（商品名・検索語・商品コードも同じ）
  - 購入グループ：「予約シングル用（シナリオ試験）」。予約商品フラグを付けたもの（UPR-01 と同じ。開発環境には無いので用意する）
  - 割引率：開発環境の初期データの割引率のうち「割引率4」（名称「4」）を、全行で使う。この割引率には状態NM・SP・MP・HPの4つがあり（率はNM 100%・SP 90%・MP 80%・HP 70%）、カード商品CSVの取り込みは、選んだ割引率にある状態を全部回して規格を作る。初期データの割引率は55件すべてに4つの状態があり、NMだけの割引率は作れない（販売割引率一覧は一覧だけで、登録・編集の画面が無い）。規格の基準価格は、NMはCSVの基準価格のまま、SP・MP・HPは「CSVの基準価格×率を10円単位で切り上げ」（新実装の基準価格の計算）。新規登録は、販売価格も基準価格と同じ値になる
  - 商品（T01）：「シナリオ試験カードJ」（言語＝日本語、基準価格 300円（NM 300円・SP 270円・MP 240円・HP 210円の4規格ができる）、買取価格 100円、販売制限数（購入上限数）4、購入グループ「予約シングル用（シナリオ試験）」、商品カテゴリ1つ、商品公開ステータス＝公開、支店の商品公開ステータス＝非公開）。カード商品CSVに1行書く。カード詳細IDは手順4で控えた値
- カード商品CSVは、商品IDを空にして新規登録する。同じカードの商品が登録済みの行は飛ばされる
- 在庫は0のまま（在庫を入れて売り始めるのは UPR-05 の入荷後）
- 例外E7（取り込みの件数の境目）は、5009件の別々のカードをカード登録CSVで登録して流す。用意が重いので、T01〜T08・ほかの例外とは別枠にして、環境に余裕のあるときに流す（用意の手順は L3の表のE7）

## 操作の流れと期待値

| # | 操作する人と操作 | 期待値（画面で見えること） |
|---|---|---|
| 1 | システムの外の作業：カードリストの作成、カード画像のS3保存、画像パス対応表の作成（ITチーム） | 画面の変化は無い。以降のCSVに、対応表の画像パスを書く |
| 2 | 登録担当：管理画面のカード管理＞カード一覧で、カードを1件チェックして「CSV出力」を押す（登録用CSVのフォーマットの入手。2-4）。続けて、カードを選ばずに「CSV出力」を押す | 1件選んだときは、CSVがダウンロードされ、列の並びがカード登録CSVのフォーマット表と同じ（1対1）。カードを選ばないと「1つ以上のカードを選択してください。」が出てダウンロードされない |
| 3 | 登録担当：カード一覧の「CSV取り込み」を押し、カードCSVアップロードの画面で、「シナリオ試験カードJ」の1行を書いたカード登録CSV（拡張子CSV）を選んで「CSVファイルをアップロード」を押す（2-5・2-6。画像のパスは画像パス対応表の値） | 「登録が完了しました。」が出る。カード一覧に「シナリオ試験カードJ」が出て、カード編集画面で、カードセット「シナリオ試験セットZ」への紐づけと画像が確かめられる。カード詳細ID（カード編集画面の「カード詳細ID: 数字」）を控える。EC-CUBEでの画像の登録作業は要らない（S3のリンクを紐づける）。規格は、カードの登録では作られず、カード商品CSVの割引率で決まる（手順6） |
| 4 | 登録担当：商品管理＞商品CSV管理＞カード商品CSV登録を開き、「雛形ファイルダウンロード」を押す（2-7）。続けて商品管理＞カテゴリ登録/編集の「CSVダウンロード」を押して、カテゴリ番号を調べる | 雛形は、見出しだけを1行書いたCSVで、見出しの並びが画面のフォーマット表（項目名・説明・必須のバッジ）と同じ。カテゴリのCSVに「シナリオ試験 予約カテゴリ」が出る。メニュー名（カード商品CSV登録）と画面の見出し（カード商品登録CSVアップロード）が違う（業務フロー10 2-7の注記と同じ。記録） |
| 5 | 登録担当：カード商品CSVを作る（システムの外。2-8）。商品カテゴリ(ID)にカテゴリ番号1つ、購入グループ名称、販売制限数4、カード詳細(ID)に手順3の値を書く。カード商品CSV登録の画面で、ファイルを選んで「CSVファイルをアップロード」を押し、確認の画面（「カード商品CSVをアップロードします。よろしいですか？」）で「確認」を押す（2-9） | 「CSVファイルをアップロードしました」が管理画面の上部に出て、カード商品CSV登録の画面に戻る。CSVインポート履歴に、ファイル名・アップロード日時・作業者の行が1件増える。この取り込みで商品画像も同時に登録される（S3の画像を参照する） |
| 6 | 登録担当：商品管理＞商品一覧で「シナリオ試験カードJ」を検索し、商品編集画面と規格設定を開く | 検索結果に1件。商品編集画面で、商品名（日・英）・購入グループ「予約シングル用（シナリオ試験）」・商品カテゴリ1件・商品公開ステータス「公開」・支店の商品公開ステータス「非公開」が、CSVに書いた値で表示される。規格は4件（NM・SP・MP・HP）で、基準価格・販売価格がどちらも、NM 300円・SP 270円・MP 240円・HP 210円（新規の登録はセール外で、基準価格が販売価格にも入る。SP・MP・HPは基準価格300円×率を10円単位で切り上げ）、販売制限数4、在庫0。規格の画像が登録されている。商品IDを控える |
| 7 | 登録担当：規格設定の画面で、規格のスマレジ連携フラグ・スマレジ商品コード・部門を見る。続けて、カード商品CSV登録の画面のCSVインポート履歴で、この取り込みのスマレジ連携の欄を見る | 4規格とも、スマレジ連携フラグが「連携しない」のまま、スマレジ商品コードは空、部門は設定されない（NMは300円以上でも連携の対象にならず、SP・MP・HPは販売価格が300円未満のため対象にならない）。CSVインポート履歴のスマレジ連携（新規）・スマレジ連携状態は「対象なし」。スマレジ側に商品が登録される結果の確かめは USM-08 |
| 8 | お客様：本店の商品詳細を、手順6で控えた商品IDで直接開く。続けて、支店のサイトで同じ商品の詳細を開く | 本店の商品詳細が開き、商品名・価格（NMの300円など）が出る。支店の商品公開ステータスが非公開なので、支店の商品詳細は開かない（本店・支店がどちらも公開のときだけ支店の画面に出る） |
| 9 | 登録担当：管理画面の商品管理＞ユニサーチフィード作成を開き、「フィードファイルを更新する」を押す。ユニサーチ側の取り込みが終わるまで待つ（外部サービス。時間の期待値は置かない）。お客様：本店のヘッダーの検索欄に「シナリオ試験カードJ」と入れて検索する。続けて支店のサイトで同じ語で検索する | 「ユニサーチフィードの作成を開始しました。」が出る。取り込みのあと、本店の検索結果に「シナリオ試験カードJ」が出る（カード言語・状態「NM」・価格300円）。支店の検索結果には出ない。フィードに載る前は、検索に出ない（UPR-01 の手順9と同じ。公開にしただけではすぐ出ない） |

## 終わったあとに確かめること

| 確かめる場所 | 期待値 |
|---|---|
| カード商品CSV登録の画面に同じCSVをもう一度アップロードする | 同じカードの商品が登録済みなので、その行は飛ばされ、商品が重ならない（例外E3と同じ） |
| 商品一覧の「シナリオ試験カードJ」 | 購入上限数（販売制限数）は4のまま。在庫は0（UPR-05 で入れる） |
