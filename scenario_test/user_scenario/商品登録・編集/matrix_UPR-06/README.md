# 商品登録・編集の高額商品の登録と販売開始（UPR-06）

IPA「高信頼化ソフトウェアのための開発手法ガイドブック」(2010) の表6-9〜6-11と同じ手順で作る。

2026-11-09：シナリオの本文に「／」で並べていた値を、1回ずつ流すテストに分けるために作った（IPA 6.3.1・6.3.2。依頼者決定）。値と期待値は本文に書いてあったものを水準ごとに分けただけで、新しい期待値は作っていない。

## 範囲

- 高額商品（個別登録商品）を登録し、規格・在庫を入れ、公開にして販売を始めるところ（業務フロー09の6-1〜6-5／10の6-1〜6-6）
- 因子：カードデータ（登録済み／未登録で画面から登録）、規格のスマレジ連携フラグ（公開の仕方と在庫の入れ方は2026-11-09に外した。下記）（連携しない／連携する）
- 例外（★）：なし（承認後のスマレジ連携が失敗する例外E1は2026-11-18に外した。下記）
- 「CSV新規登録で直接公開」は、本文が「カード商品CSV・グッズ商品CSVで公開を指定して新規登録」と書くので2つの水準に分けた

## 期待結果の決まり

- 規格を登録してから商品編集画面で公開：新規は非公開で登録され、公開の操作のあと公開になる
- CSVで公開を指定して新規登録：規格もCSVで登録され、新規から公開になる
- カードデータが登録済み：カードの登録（2-4〜2-9）を行わずに商品の登録へ進み、商品が登録される
- 未登録で画面から登録：カード新規登録の画面（M14-04）でカード情報を登録し、カード一覧に出る
- 未登録でCSVから登録：カード登録CSVを取り込み、同じカード名（英語）のカードが未登録ならカードが新規登録される。その後にカード商品CSVで商品を登録する
- 在庫編集画面：在庫変動区分を「入庫」にして数を登録し、承認者が在庫編集承認一覧で承認するまで在庫が0のままで、承認後に入った数になる
- 在庫変更CSV登録：在庫情報CSV出力で出したCSVの商品コードを使って在庫増減数を書いた在庫変更CSVを取り込み、承認者が承認するまで在庫が変わらず、承認後に入った数になる
- 連携しない：スマレジ連携の対象にならず、スマレジに商品が登録されない。連携する：保存するとスマレジ連携が行われる

## 外した因子・水準（2026-11-09 依頼者決定：画面の操作の違い）

業務の流れも結果も分かれない画面操作の違いは、組み合わせ表から外し、結合テストに任せる（依頼者決定）。値と期待値は消しただけで、新しく作っていない。

- 因子A「公開の仕方」を因子ごと外した（規格登録後に商品編集画面で公開／カード商品CSV／グッズ商品CSVで公開を指定して新規登録）。到達する状態は同じで、入口の違い。前提：規格を登録してから商品編集画面で公開にする。
- 因子C「在庫の入れ方」を因子ごと外した（在庫編集画面／在庫変更CSV登録）。どちらも承認後に在庫が増える入口の違い。前提：在庫編集画面で入庫する。
- 因子Bの水準B3「未登録で、カード登録CSVで登録」を外した。画面（M14-04）と入口が違うだけ。
- 行は9から4になった。例外E1（承認後のスマレジ連携失敗）は2026-11-18に外した（下記）。
