# 商品登録・編集の複数公開・非公開切り替え（UPR-09）

IPA「高信頼化ソフトウェアのための開発手法ガイドブック」(2010) の表6-9〜6-11と同じ手順で作る。

1. 因子・水準表（FL表）: `fl_table.tsv`。商品の種類（取り込む画面）と、商品を切り替える前後の「本店×支店の公開状態」を因子にした
2. 禁則表: `prohibitions.tsv`。切り替える前と後が同じ組（切り替えにならない）4件
3. 組み合わせテストマトリクス: `matrix.md` / `matrix.tsv`。`build_matrix.py` が作る。1行が1本のシナリオ（1つの商品の切り替え）になる
4. 例外の差し込み表: `exceptions.tsv`。エラーや中断は、正常な値と混ぜず、条件に合う行へ1つずつ差し込む

## 範囲

- 商品マスターで対象を検索し、「カード商品CSV出力」「グッズ商品CSV出力」でCSVを出し、公開ステータスの列を直して「カード商品CSV登録」「グッズ商品CSV登録」で取り込むところから、本店・支店のお客様の画面で見え方が変わるところまで（業務フロー8-1〜8-3）
- 各行の期待値（お客様の画面）：本店の画面に出る＝本店が公開。支店の画面に出る＝本店と支店がどちらも公開
- 「公開」と「非公開」の切り替えだけを扱う。廃止はE3・E4の例外だけ。変更前が廃止の商品は水準に入れていない（E3）
- 廃止の商品の扱い：新実装のカード・グッズ商品CSV登録は、廃止の商品も更新できるよう絞り込まない（コード中のコメント）。一方、商品公開CSV登録は廃止の商品の行を処理しない。設計書（0204 商品登録編集）は廃止後の変更を禁じる。設計書を優先して期待値を書き、食い違いを記録した
- 因子に入れなかったもの：CSVに入れる商品の数（切り替えの結果は1商品ごとに決まる）、スマレジ連携（非公開に変えると連携が外れる。設計書の文は下記。公開の切り替えとは別に、結合テストで確かめる）

## 実装・設計書で確かめたこと（2026-11-03）

- 本店×支店の見え方：0204 商品登録編集「両方とも『公開』が選択されている場合のみ、支店の画面に商品を表示する」。新実装の支店トップの商品取得（セール中の商品）は、本店のステータスが公開であることと、支店の公開ステータスが公開であることの両方を条件にしている（ほかの画面の取得は確かめていない）
- 商品公開ステータスを非公開・廃止に変えたとき、設計書ではスマレジ連携が外れる（0204 カード商品CSV登録「ステータス変更によるスマレジ連携解除」、グッズ商品CSV登録「ステータス変更による無効化」）。新実装のカード・グッズ商品CSV登録は、廃止のときだけ連携を外し、非公開では外さない（連携フラグを維持する。カード商品CSV登録の連携フラグの決定、グッズ商品CSV登録の連携フラグの決定のコード）ので、設計書と食い違う。連携済みの商品を非公開にする例外E5で確かめる
- 公開ステータスの数値は設計書内で食い違うため、CSVの値は数字でなく名前（公開・非公開）で書く。食い違いの内容は `../scenario_list.md` の「設計書との食い違い」に書いた

## まとめた水準

なし（どの水準も処理が違う）。主な根拠：カード商品CSVとグッズ商品CSVは取り込む画面・項目が違い、本店・支店の公開ステータスの4通りは、支店の画面に商品が出る（両方公開）・出ない（それ以外）が違い、設計書が「本店非公開なら支店公開でも出ない」など理由ごとに書き分けている。
