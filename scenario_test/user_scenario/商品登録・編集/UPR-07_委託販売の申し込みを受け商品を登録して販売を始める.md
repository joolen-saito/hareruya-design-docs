# UPR-07 委託販売の申し込みを受け、委託販売の商品を登録して販売を始める

| 項目 | 内容 |
|---|---|
| 利用者 | お客様（委託販売の申し込み）→ トレードチーム（契約・画像）→ トレードチーム（登録担当。UPR-06 と同じ）→ 在庫の承認者 → お客様 |
| 目的 | お客様が委託販売品のページから申し込み、トレードチームが依頼を確認して契約し、商品画像を用意したあと、高額商品の登録と同じ流れで委託販売の商品を登録し、在庫を入れて承認を受け、公開して、お客様の画面に出ることを確かめる。契約に至らないときは商品を登録しない |
| 種類 | 正常（申し込みから販売開始まで） |
| マトリクスの行 | マトリクスは無い（値を並べておらず、7-5は UPR-06 と同じ流れのため。`scenario_list.md` の「UPR-07は値を並べていないので作らない」）。手順の値は UPR-06 の T01（カードデータ登録済み・連携しない）と同じ |
| もとのシナリオ | SCN-PRODUCT-007 |

## 前提

- 共通の決まり：`../L4を流すときの共通の決まり.md` を先に読む（試験データの名前にシナリオIDを付ける・共有の設定は元に戻す・バッチの起動・店舗の読み替えなど）
- システムの外で済んでいること：委託販売品のページ（お客様に見えるページ）と、申し込み用のGoogleフォームがある。申し込む商品（お客様が預ける高額なカード）がある
- 用意するデータ（試験用の値。設計書の値ではない）
  - お客様（委託者）：試験 次郎（申し込みに使う連絡先は試験用の値）
  - 登録担当と、在庫の承認者（別の担当者。承認権限があり、登録担当の承認通知先に入る）
  - 商品：UPR-06 と同じ形の値。「シナリオ試験カードN」（英名「Scenario Test Card N」。登録済みのカード）を委託販売の高額商品として登録する。基準価格・販売価格 30,000円（UPR-06 の手順5と同じく、CSVでは250円で登録し、手順7で直す）、買取価格 20,000円（CSVでは100円）、販売制限数1、高額商品コード「#UPR07」、商品公開ステータス＝非公開、支店の商品公開ステータス＝非公開、商品カテゴリ1つ、購入グループ「通常商品」。在庫は1点
- 委託販売の商品を表す項目は設計書に定めが無い。新実装には売上分析タグ「委託販売品」があるが、判断待ち 1 の決着のとおり、委託販売の商品に付ける（手順7の後の手順7aで付ける）。ほかは UPR-06 と同じ項目で登録する
- 在庫が承認されるまでは在庫0。登録担当と承認者は別の担当者

## 操作の流れと期待値

| # | 操作する人と操作 | 期待値（画面で見えること） |
|---|---|---|
| 1 | お客様（委託者）：委託販売品のページにアクセスし、「委託販売の申し込みはこちら」を押す（7-1。システムの外：委託販売品のページ） | 申し込み用のGoogleフォームが開く。外部のページの見え方は記録だけで、合否は付けない |
| 2 | お客様（委託者）：Googleフォームに、委託販売の依頼の情報を入力して送る（7-2。システムの外） | 依頼がトレードチームに届く。EC-CUBEの画面の変化は無い |
| 3 | トレードチーム：委託販売の依頼を確認し、内容に応じて希望者と委託販売の契約を行う（7-3。システムの外） | 契約が成立する。EC-CUBEの画面の変化は無い。契約に至らないときは、手順4以降へ進まず、商品を登録しない（L3の表） |
| 4 | トレードチーム：商品画像をスキャンや写真撮影で用意する（7-4。システムの外） | 画面の変化は無い |
| 5 | 登録担当：高額商品の登録（UPR-06 の手順2・3）と同じに、カード一覧で「シナリオ試験カードN」があることを確かめ、商品管理＞商品CSV管理＞カード商品CSV登録でカード商品CSV（基準価格250円、割引率「4」。買取価格100円。UPR-06 の手順3と同じ）をアップロードする（確認の画面で「確認」）（7-5） | カード一覧に1件出る。「CSVファイルをアップロードしました」が出て、CSVインポート履歴が1件増える。商品が新規に登録され、商品公開ステータスは「非公開」、支店の商品公開ステータスは「非公開」、規格は4件（NM 250円・SP 230円・MP 200円・HP 180円。割引率「4」）で在庫0 |
| 6 | 登録担当：商品編集画面で、用意した商品画像を追加して「商品を登録」を押す（UPR-06 の手順4と同じ） | 「保存しました」が出て、画像が表示される |
| 7 | 登録担当：規格設定でNMの規格を開き（SP・MP・HPの規格は在庫0のまま使わない。UPR-06 の判断待ち2）、高額商品コード「#UPR07」・基準価格・販売価格30,000円・買取価格20,000円・販売制限数1を入れ、スマレジ連携フラグは「連携しない」のままにして「商品規格を登録」を押す（UPR-06 の手順5と同じ） | NMの基準価格を250円から30,000円に変えたので、「閾値(300円)をまたぐ価格変更がされたので、スマレジ連携フラグを確認してください」の確認が出る（連携フラグがOFFのため。閉じると保存が続く）。「保存しました」が出て、規格一覧で、高額商品コード・価格が入力値になる |
| 7a | 登録担当：商品編集画面の「売上分析タグ」で「委託販売品」にチェックを入れて「商品を登録」を押す（委託販売の商品の印。設計書に区別の記述は無いが、新実装の初期データにあるタグ） | 「保存しました」が出て、商品編集画面の売上分析タグに「委託販売品」が付いている |
| 8 | 登録担当：在庫管理＞在庫一覧で「シナリオ試験カードN」を検索する（在庫一覧は規格ごとに出る）。高額商品のNM規格の、店舗「本店」・在庫区分EC（本店のEC在庫）の行の操作から「在庫編集」を開き、在庫変動区分「入庫」で、高額商品のNM規格の本店EC在庫に1点を入れ、承認通知先（所属・メンバー）に承認者を選んで登録する（UPR-06 の手順6と同じ） | 在庫編集承認一覧に承認状態「未承認」で登録される。承認者に通知メールが届く。在庫は0のまま |
| 9 | 承認者：在庫編集承認一覧で、登録担当が登録した行にチェックを入れ、「一括承認」を押し、確認の画面で「承認する」を押し、最後の確認で「OK」を押す（UPR-06 の手順7と同じ） | 承認状態が「承認済」になり、登録担当に承認ステータス変更のメールが届く。商品の在庫が1になる |
| 10 | 登録担当：商品編集画面で商品公開ステータスを「公開」にして「商品を登録」を押す（規格を登録してから公開の操作をする） | 「保存しました」が出て、商品公開ステータスが「公開」になる |
| 11 | お客様：本店の商品詳細を、商品IDで直接開く。続けて、登録担当：商品管理＞ユニサーチフィード作成で「フィードファイルを更新する」を押し、取り込みが終わるまで待つ（外部サービス）。お客様：本店のヘッダーの検索欄に「シナリオ試験カードN」と入れて検索する | 商品詳細が開き、価格30,000円・在庫1が出る。「ユニサーチフィードの作成を開始しました。」が出る。取り込みのあと、検索結果に商品が出る（フィードに載る前は出ない）。支店の画面には出ない（支店が非公開） |

## 終わったあとに確かめること

| 確かめる場所 | 期待値 |
|---|---|
| 商品一覧 | 管理画面の商品管理＞商品一覧で、検索の条件の「売上分析タグ」の「委託販売品」にチェックを入れて検索すると、「シナリオ試験カードN」が出る（付けていない商品は出ない）。商品編集画面にも売上分析タグ「委託販売品」が付いている |
| スマレジ連携 | 連携しない規格なので、スマレジに商品は登録されない |

## L3で変わるところ（このシナリオにマトリクスは無い）

手順の番号は上の「操作の流れと期待値」。UPR-06 の行の値（カードデータの状態・スマレジ連携フラグ）は、そのまま使える。

| 場合 | 変わるところ |
|---|---|
| 契約に至らない（7-3の分岐） | 手順3：トレードチームが依頼を確認し、契約に至らないと判断する（システムの外）。手順4以降は行わない。商品一覧に「シナリオ試験カードN」の商品が出ない（登録されない）。お客様の画面にも出ない |
| カードデータが未登録 | UPR-06 の T03・T04 と同じ。手順5の前に、カード一覧の「新規登録」でカードを登録する（「保存しました」が出て、カード一覧に出る） |
| 規格のスマレジ連携フラグ＝連携する | UPR-06 の T02・T04 と同じ。手順7で、スマレジ連携フラグを「連携する」にし、スマレジ商品コードと部門を入れる（閾値の確認は出ない。保存するとスマレジ連携が行われる） |
| 在庫の入れ方が在庫変更CSV登録 | 手順8：在庫変更CSV登録で、商品コード・在庫増減数1・仕入単価を書いたCSVを取り込む（承認は手順9と同じ）。UPR-06 の判断待ち1と同じく、組み合わせ表には入れない |

例外：マトリクスが無いので例外の表は無い。
