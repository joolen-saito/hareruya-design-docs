# UPT-10 レジで取消・打消しが登録され、完了済みの取引のポイントが元に戻る

| 項目 | 内容 |
|---|---|
| 利用者 | お客様 → 店舗チーム（スマレジのレジ。試験環境）→ スマレジ → EC（取り込み）→ 店舗チーム（管理画面で確かめる）→ お客様（マイページ） |
| 目的 | 完了済みの取引（UPT-03）に対して、レジで取消または打消しの取引が登録されたとき、元の取引の付与・使用の履歴が削除され、会員の保有ポイントが取引の前の値に戻る（逆の履歴は残さない）。付与も使用も0の取引は何もしない。マイページの履歴から取引の行が消える。ポイント専用の取引（加算・減算）の取消・打消しも、受注を持たない履歴を削除して残高を戻す |
| 種類 | 正常（組み合わせ表の11行。1行が1回流すテスト1本）＋例外3件 |
| マトリクスの行 | `matrix_UPT-10/matrix.md` のT11（取消・通常の取引（使用と付与の両方）・レジだけで買った取引）。T01〜T10 と例外 E1〜E3 は「L3で変わるところ」 |
| もとのシナリオ | なし（0505 A05-04 の取消・打消しのポイントの扱い、0203 別添「スマレジ決済後返品処理について」から組み立てた）。元の取引の完了と値は UPT-03、受注のキャンセル・スマレジ在庫の戻りは USM-02、店頭受取の受注の返品は UOR-10 |

## 前提

- 共通の決まり：`../L4を流すときの共通の決まり.md` を先に読む（試験データの名前にシナリオIDを付ける・共有の設定は元に戻す・バッチの起動・店舗の読み替えなど）

- システムの外で済んでいること：スマレジの試験環境に、本店に対応する店舗とレジが使える状態でそろっている。会員のお客様がスマレジの会員番号を持つ（UMB-02）。お客様が返品（取消）または打消しを申し出る
- 取り込みは非同期で、ECの処理が終わるまで待つ（待つのは時刻でなく完了まで）
- 用意するデータ（試験用の値。設計書の値ではない）
  - 会員：行ごとに別の本会員 `upt-10-tNN@example.test`（代表は `upt-10-t11@example.test`、お名前「試験 十一郎」）。UMB-01 の手順1〜7と UMB-02 の手順1〜2で、この試験専用に作る（スマレジの会員が作られている）。保有ポイントは、管理画面の会員編集の「ポイント管理・履歴一覧」の「ポイント履歴追加（キャンペーン、特別対応）」で、増減量 5,000・ポイント発行日（今日）・備考「キャンペーン」を付与しておく（UMB-10 の準備1と同じ操作）
  - 商品・受注：UPT-03 の前提と同じ（グッズ「シナリオ試験ショーケース品 UPT10」・商品コード `UPT10-G01`・単価800円。持ち込む受注は UOR-02 の用意）。名前だけ UPT-10 に変える
  - 元の取引：行ごとに、次の UPT-03 の行と同じ流し方で、取消・打消しの前に完了させておく（会員・商品名だけ UPT-10 のもの）：付与だけ＝UPT-03 のT01（持ち込みはT13）、使用だけ＝T14（持ち込みはT02）、付与と使用の両方＝T03（持ち込みはT15）、ポイント加算＝T05、ポイント減算＝T12
  - 店舗チームの担当者：管理画面（受注管理・会員管理）とスマレジのレジを使える
  - 手順の前に控える値：元の取引のあとの保有ポイントとポイント履歴の行数、元の取引の取引ID・付与ポイント（N）・使用ポイント（M）
