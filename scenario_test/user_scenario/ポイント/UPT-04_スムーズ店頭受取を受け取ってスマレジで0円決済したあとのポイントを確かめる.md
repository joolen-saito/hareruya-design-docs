# UPT-04 スムーズ店頭受取を買い、受け取ってスマレジで0円決済したあとのポイントを確かめる

| 項目 | 内容 |
|---|---|
| 利用者 | お客様（会員）→ 店舗チーム → スマレジ（システムの外）→ EC → お客様（マイページ） |
| 目的 | 本店のスムーズ店頭受取（クレジットカード決済）の注文を、お客様が受け取りに来て、スマレジで0円決済する。元の受注が「出荷完了」になる。ヘルプは「商品お受取後にオンラインアカウントに付与」と書く。付与ポイントが保有ポイント・ポイント履歴に、スマレジの取引の付与値のとおりに付く（額の計算はスマレジ側）。EC注文時にポイントを使ったときは、使用の行が二重にならない |
| 種類 | 正常（組み合わせ表は無い。代表の1本＋L3の1件） |
| マトリクスの行 | なし（組み合わせ表は無い。`matrix_UPT-04/` は作っていない）。L3 は `scenario_list.md` の UPT-04 の L3 欄（付与あり（受取後）／EC注文時のポイント使用：使える・無し）を1つずつ別のテストにした（R1・R2）。代表は「ポイントを使わない」（R1） |
| もとのシナリオ | なし（0304・ヘルプのスムーズ店頭受取のポイントの記述から組み立てた）。注文から受け取りまでの流れは UOR-01 のT03・UOR-03、取引のポイントの反映の値は UPT-03、スマレジの取引の取り込みは USM-01 のT01 |

## 前提

- 共通の決まり：`../L4を流すときの共通の決まり.md` を先に読む（試験データの名前にシナリオIDを付ける・共有の設定は元に戻す・バッチの起動・店舗の読み替えなど）
- スマレジ側の操作は、スマレジの試験環境で行う（2026-11-24 決定）。スマレジの画面の見え方は記録だけにし、合否はEC側の値（ECの画面・履歴・ポイント）で付ける。取引完了の通知（Webhook）が開発環境のECに届くときはそのまま流し、届かないときは、試験の担当者が用意するHTTPクライアントで通知（取引IDだけ）を代わりにECへ送ってよい。どちらで流したかを記録に残す（USM-01 と同じ決まり）
- システムの外で済んでいること：スマレジの試験環境に、本店に対応する店舗とレジが使える状態でそろっている。お客様は身分証明書（試験用の氏名が確かめられるもの）を持参する
- 購入するEC：本店のEC（店舗ID 1。画面によって「Hareruya」「トーナメントセンター 東京」と出る）。配送方法は「スムーズ店頭受取」
- 用意するデータ（試験用の値。設計書の値ではない）
  - 会員：R1 `upt-04-r1@example.test`、R2 `upt-04-r2@example.test`（お名前「試験 四郎」）。UMB-01 の手順1〜7と UMB-02 の手順1〜2で、この試験専用に作る（スマレジの会員が作られている）。国内の住所を登録済み。顧客グループは通常会員（還元率1%）。SPLINKSの試験環境のクレジットカードを1枚登録済み
  - 保有ポイント：管理画面の会員編集の「ポイント管理・履歴一覧」の「ポイント履歴追加（キャンペーン、特別対応）」で、R1 は 2,000、R2 は 3,000 を付与する（増減量・ポイント発行日（今日）・備考「キャンペーン」。UMB-10 の準備1と同じ操作）
  - 商品・注文：UOR-01 のT03の前提と同じ商品（カードを1状態・数量2）で、スムーズ店頭受取の注文を、クレジットカード決済で作り、店舗がスタック用紙でピックして「ピック完了」にしておく（UOR-01 の手順1〜10。UOR-03 の起点と同じ）。商品の名前・商品コードは、UOR-01 の前提のものをこのシナリオ専用に作る（試験データの名前にシナリオIDを付ける）
  - 店舗チームの担当者：管理画面（受注管理・会員管理）とスマレジのレジを使える
  - 手順の前に控える値：会員の保有ポイントとポイント履歴の行数、受注の「ポイント使用」「ポイント発生」「ポイント還元率(%)」
- 画面の名前・文言は新実装の表示で書く。設計書の名前と違うときは「（設計書：…）」を添える。メッセージの文言は設計書の文言を期待値にし、新実装の文言が違えば不合格として記録する
