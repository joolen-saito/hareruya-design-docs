# ポイント：シナリオ一覧（L2）

ポイントを貯める（付与）・使う（償還）・戻す（取り消し）・失効させる経路は、各業務のシナリオにばらばらに出てくる。ここでは経路を1行ずつ洗い出し（`## ポイントの経路の網羅`）、既存のシナリオで付与・使用の数や時点まで確かめているものはそのIDを書き、確かめていないものだけを UPT のシナリオ（L2）として足した。管理画面のポイント付与・スマレジ連携・失効・通知は既存の USM・UCY・UMB・UEV が持つので、重ねて作らない。

シナリオ1本は「起点の業務イベントから、業務として完了した状態になるまで」とする。担当者が替わっても切らない（お客様→通販チーム→管理画面→スマレジ→マイページ・メール）。日をまたいでシステムの状態を待つもの（毎日0:00のバッチなど）は別の1本にする。ポイントの値（付与額・使用額・残高・履歴の行）を手で数えた期待値と突き合わせることを、各シナリオの終点にする。前提データ（会員・商品・店舗・顧客グループの還元率・スマレジ会員IDなどのマスタ）はシナリオから外す。

| 階層 | 単位 | ポイントでの置き場所 |
|---|---|---|
| L1 業務領域 | シナリオのグループ | ポイント（貯める・使う・戻す・失効） |
| L2 シナリオ | 起点イベント→業務完了 | `## シナリオ一覧` の1行 |
| L3 バリエーション | 条件違い・例外 | `matrix_UPT-01/`・`matrix_UPT-03/`・`matrix_UPT-05/`・`matrix_UPT-07/`・`matrix_UPT-08/`・`matrix_UPT-10/`（それぞれUPT-01・03・05・07・08・10）と、各行の「L3」欄 |
| L4 ステップ | 画面操作と確認 | （まだ書かない） |

ポイントの基本の決まり（正本の引用は `## 実装と設計書で確かめたこと`）：1ポイントは1円。付与は出荷完了のとき（（小計−使用ポイント）×顧客グループの還元率、切り捨て）。使用は注文を確定したとき（SPLINKS決済は購入完了画面の表示時）。有効期限は発行日から183日。

## ポイントの経路の網羅

区分は貯める（付与）・使う（償還）・戻す（取り消し・返品）・失効（有効期限・通知・残高の訂正）・表示。「シナリオ」は既存のID（`tools/check_refs.py` で実在を確かめた）か UPT。既存のIDだけの行は、そのシナリオが付与・使用の数や時点まで確かめているもの。UPT を含む行は、既存では数や時点を確かめていないため足したもの。

### 判断待ち（何を見ても決まらなかったもの）

1. 「利用可能ポイント」の定義：設計書 0304 (6-6) は「会員の保有ポイントと利用可能ポイントの小さい方」と書くだけで、利用可能ポイントの算出を書かない。新実装は商品金額＋送料＋手数料（送料・手数料にも充てられる）としている。期待値は新実装のとおり（見たもの：0304 1655行、index.twig 567〜568行、PointProcessor.php 155〜160行。現行 pf-eccube3 のポイント処理は付与・使用の部分だけ読み、上限は確かめきれなかった）
2. スムーズ店頭受取でポイントを使えるか・受取後に付与されるか：ヘルプ（日本語 494行・英語 492行）は「スムーズ店頭受取でもポイントを使える・付与は受取後」と書くが、新実装は店頭受取・スムーズ店頭受取の注文画面でポイント欄を隠す（店頭受取受注管理の判断待ちと同じ）。0円決済の取引でスマレジが付与を返すかも決まらない。UPT-04・UPT-06 の期待値は判断待ち（見たもの：0304 1637〜1640行、index.twig 122・604〜610行、SmaregiOrderPointApplier.php 78〜100行、help_onlineshop.twig 494行・en.twig 492行、UOR の scenario_list.md）
