# UPT-09 ポイントを使った注文の決済が、ポイント分を引かずに請求された注文を、通知で見つける

| 項目 | 内容 |
|---|---|
| 利用者 | 運用担当 → ポイント利用未反映チェックのバッチ（システム。毎時10分）→ 管理者（メール） |
| 目的 | ポイントを使った注文のうち、決済代行の請求額が購入金額合計か支払合計と一致していて、設計書の条件に合う注文を、バッチが見つけ、管理者に注文のIDを一覧にしたメールで知らせる。通知先が未設定のときは、メールを送らず終了する。条件に合わない注文は通知しない |
| 種類 | 正常（組み合わせ表は無い。代表の1本＋L3の8件） |
| マトリクスの行 | なし（組み合わせ表は無い。`matrix_UPT-09/` は作っていない）。L3 は `scenario_list.md` の UPT-09 の L3 欄の項目（対象になる／ならない（請求額が値引き後・値引きが0・備考あり・欠品履歴あり・1時間より前の入金）・通知先が未設定・異常で処理が止まる）を1つずつ別のテストにした（R1〜R8）と、設計書の条件の読み（R9）。代表は「対象になる」（R1） |
| もとのシナリオ | なし（業務フローには無い。設計書 0405 B05-07 による）。購入の流れは UTS-01・UPT-05、決済代行の請求額の見え方は UTS-02 の「ソニーペイメントサービス決済情報」 |

## 前提

- 共通の決まり：`../L4を流すときの共通の決まり.md` を先に読む（試験データの名前にシナリオIDを付ける・共有の設定は元に戻す・バッチの起動・店舗の読み替えなど）
- システムの外で済んでいること：SPLINKSの試験環境に接続できる。管理者の通知先に使う試験用のメールの受け口（メールを読めるアドレス）がある
- バッチは毎時10分に動く設計だが、時刻は待たずに手で起動する（2026-11-26 決定。起動のしかたは根拠の欄）。バッチは環境の中の対象の注文を全部調べる作りで、直近1時間以内に支払われた注文だけが対象。合否はこの試験の注文で付け、環境のほかの注文の件数は記録にする。用意したあと1時間以内に起動する（支払日時が1時間より前になると対象から外れる）
- 共有の設定を一時的に変える：追加システム設定（設定＞店舗設定＞追加システム設定）の「ポイント利用が反映されない決済の送信先メールアドレス」。**流す前に今の値を確かめて控える。空のときだけ試験用のアドレスを入れ（カンマ区切りで複数入れられる）、確かめ終わったら元の値（空）に戻して、戻ったことを設定の画面で確かめる**（`../L4を流すときの共通の決まり.md`）。設定済みのときは変えない（その宛先の受信箱で確かめられないときは、メールが届くことの確かめを記録にする）
- 用意するデータ（試験用の値。設計書の値ではない）
  - 会員：行ごとに別の本会員 `upt-09-rNN@example.test`（代表は `upt-09-r1@example.test`、お名前「試験 九郎」）。UMB-01 の手順1〜7と UMB-02 の手順1〜2で、この試験専用に作る。国内の住所を登録済み。SPLINKSの試験環境のクレジットカードを1枚登録済み。保有ポイントは、管理画面の会員編集の「ポイント管理・履歴一覧」の「ポイント履歴追加（キャンペーン、特別対応）」で 3,000 を付与する（UMB-10 の準備1と同じ操作）
  - 商品：グッズ「シナリオ試験グッズ UPT09」（商品コード `UPT09-G01`・単価1,000円（税込）・公開・在庫20・販売制限なし）。グッズ商品CSVで登録し、在庫変更CSV登録と承認で在庫を入れる（UPR-04・UPR-05 の手順）
  - 注文：会員が数量3（小計3,000円）・登録済みクレジットカード決済・使用ポイント 1,000 で買った注文（UPT-05 のT07と同じ流れ。購入完了で入金済み）。注文の金額を P0（商品金額 ＋ 送料 ＋ 手数料）とする（支払うのは P0 − 1,000）。ご注文番号と、受注情報編集の画面のアドレスの末尾の番号（受注のID。メールに出る番号）を控える
  - 書き換えて用意する状態（画面の操作では作れない状態のため。試験で作ったデータに限って書き換えてよい：共通の決まり「画面の操作で作れない状態の用意」。2026-11-27 決定）：下の「対象になる注文の状態」。書き換える項目（論理名）は、購入金額合計・支払合計・ポイント値引き（購入金額割引）・備考・欠品履歴・決済状態の金額（「ソニーペイメントサービス決済情報」の金額）・支払日時
  - 店舗チームの担当者：管理画面の受注管理・システム設定を使えるアカウント
  - 手順の前に控える値：追加システム設定の通知先の今の値、受注の支払日時・備考・「ソニーペイメントサービス決済情報」の金額
- 画面の名前・文言は新実装の表示で書く。設計書の名前と違うときは「（設計書：…）」を添える

対象になる注文の状態（設計書 0405 B05-07 の入力データの条件。すべてを満たす）：
1. 直近1時間以内に支払われた（支払日時が起動の1時間前から起動の時点まで）
2. 購入金額合計と支払合計が異なる
3. 注文番号がある
4. 備考が空（値の無い状態。空の文字ではない。設計書は「備考がNULL」で、新実装も値の無い状態で探すので、空の文字を入れた注文は対象にならない）
5. ポイント値引き（購入金額割引）がある（1,000円）
6. 紐づく欠品履歴が無い
7. 購入金額合計と支払合計の大きい方が、小さい方にポイント値引きを加えた値と一致しない
8. 決済代行の請求額（「ソニーペイメントサービス決済情報」の金額）が、購入金額合計か支払合計のどちらかと一致する（Excel 由来の入力データ検索条件：決済会社出力の情報に「購入金額合計もしくは支払合計」のテキストが含まれる。決済状態を持たない注文は対象にならない）
9. 論理削除されていない

用意する値の例（代表の行 R1）：購入金額合計 ＝ P0、支払合計 ＝ P0 − 500、ポイント値引き ＝ 1,000、決済の請求額 ＝ P0（大きい方）。大きい方 P0 ≠ 小さい方 + 値引き（P0 − 500 + 1,000 ＝ P0 + 500）で条件7を満たす。

## L3で変わるところ（組み合わせ表は無い。1つずつ別のテストにする）
