# UPT-01 通販チームが購入済みの注文を出荷完了にして、付与ポイントが会員の保有ポイント・ポイント履歴に付く

| 項目 | 内容 |
|---|---|
| 利用者 | 通販チーム（管理画面）→（出荷実績CSV）→ スマレジ（システムの外）→ お客様（マイページ・メール） |
| 目的 | 購入済み（UPT-05・UTS-01。付与予定が付いた）の注文を、通販チームが出荷完了にする。出荷完了の前は保有ポイントが変わらず、付与予定と「※獲得ポイントは商品出荷時に有効になります。」の注記だけが出る。出荷完了のあと、保有ポイントが（小計−使用ポイント）×顧客グループの還元率（切り捨て）だけ増え、ポイント履歴に付与の行が注文番号つきで残り、スマレジのポイントも同じ量が増える。付与が0のときは履歴を作らない |
| 種類 | 正常（組み合わせ表の12行。1行が1回流すテスト1本）＋例外6件 |
| マトリクスの行 | `matrix_UPT-01/matrix.md` のT02（通常会員（還元率1%）・小計より少なく使う・還元率で割り切れる小計10,000円）。T01・T03〜T12 と例外 E1〜E4・E6・E7 は「L3で変わるところ」 |
| もとのシナリオ | なし（通販の購入から出荷 UTS-01 の出荷完了の部分を、付与額・時点まで数える一本として足した）。購入そのものは UTS-01・UPT-05、スマレジへの加算の失敗と再連携は UTS-14・USM-17、取り消しでの戻しは UPT-07、受注の内容を変えたときの再計算は UPT-02 |

出荷完了にする操作は、出荷実績インポートでCSVを取り込む（業務フローの主な手順）。受注情報編集での出荷完了と受注一覧の一括変更は、入口の違いなので外した（2026-11-09 依頼者決定）。

## 前提

- 購入するEC：本店のEC（店舗ID 1。画面によって「Hareruya」「トーナメントセンター 東京」と出る）。配送方法は「ゆうパック」
- 用意するデータ（試験用の値。設計書の値ではない）
  - 会員：行ごとに別の本会員 `upt-01-tNN@example.test`（NN は行の番号。代表は `upt-01-t02@example.test`、お名前「試験 一郎」）。UMB-01 の手順1〜7と UMB-02 の手順1〜2で、この試験専用に作る。国内の住所を登録済み。SPLINKSの試験環境のクレジットカードを1枚登録済み
  - 顧客グループ（行の条件 A）：A1 は通常会員（還元率1%）。A2 は SCG取引用（還元率5%）、A3 は還元率0%の顧客グループ（Sekappy用。海外代理販売用・集換社アカウントも処理は同じ）。A2・A3 の行は、管理画面の会員管理で会員編集を開き、「顧客グループ」を替えて「登録」を押す（UMB-21 の手順4）。その顧客グループに結び付く支払方法・配送方法で購入できないときは、その行を「実施不可（流せない）」として記録する
  - 保有ポイント：管理画面の会員編集の「ポイント管理・履歴一覧」の「ポイント履歴追加（キャンペーン、特別対応）」で付与する（UMB-10 の準備1と同じ操作）。B1・B2 の行は 3,000、B3・B4 の行は 20,000
  - 商品：D1 はグッズ「シナリオ試験グッズ UPT01 A」（商品コード `UPT01-G01`・単価10,000円（税込））、D2 はグッズ「シナリオ試験グッズ UPT01 B」（商品コード `UPT01-G02`・単価12,345円（税込））。どちらも公開・在庫10・販売制限なし。グッズ商品CSVで登録し、在庫変更CSV登録と承認で在庫を入れる（UPR-04・UPR-05 の手順）。数量1で小計は10,000円・12,345円
  - 送料・手数料：小計が30,000円に届かないので送料は1円以上かかる。ご注文内容の確認に出た値を控え、送料＋手数料を F、支払総額（小計＋送料＋手数料）を P と書く。登録済みクレジットカード決済の手数料は0円
  - 使用ポイント（行の条件 B）：B1 は 0。B2 は 1,000。B3 は 小計＋1（D1 は 10,001、D2 は 12,346。支払総額 P より少なく、F が2円以上のとき成り立つ。F が1円以下の行は「実施不可（流せない）」）。B4 は P（全額ポイント支払い）
  - 支払方法：B1〜B3 は「登録済みクレジットカード決済」、B4 は「全額ポイント支払い」
  - 通販チームの担当者：管理画面の受注管理・出荷指示リスト・出荷実績インポート・会員管理を使えるアカウント
  - 手順の前に控える値：会員の保有ポイントとポイント履歴の行数、受注の付与予定ポイント
- 画面の名前・文言は新実装の表示で書く。設計書の名前と違うときは「（設計書：…）」を添える。メッセージの文言は設計書の文言を期待値にし、新実装の文言が違えば不合格として記録する
