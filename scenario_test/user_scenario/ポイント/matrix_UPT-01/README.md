# 通販で買い、出荷完了でポイントが付く（UPT-01）

IPA「高信頼化ソフトウェアのための開発手法ガイドブック」(2010) の表6-9〜6-11と同じ手順で作る（`通販/matrix/README.md` と同じ）。

1. 因子・水準表（FL表）: `fl_table.tsv`
2. 禁則表: `prohibitions.tsv`（この表は禁則なし。因子どうしに成り立たない組が無い）
3. マトリクス: `matrix.md` / `matrix.tsv`（`tools/build_matrix.py` が作る。1行が1本のシナリオ＝購入済み（UPT-05・UTS-01）の注文を通販チームが出荷処理に進めて出荷完了にし、お客様の残高・履歴に付与が出るまで）
4. 例外の差し込み表: `exceptions.tsv`

## 範囲

- 付与の額と付与の時点を確かめる。購入そのもの（支払方法・配送方法・金額の上限）は UTS-01、スマレジへの加算の失敗と再連携は UTS-14・USM-17、取り消し・返品での戻しは UPT-07、受注の内容を変えたときの再計算は UPT-02
- 支払方法は、付与の計算も時点も変わらないので水準にしない（`## まとめた水準`）。行ごとの支払方法は、ポイントの使い方（B）に合う支払方法を UTS-01 のマトリクスから選ぶ（B4 は全額ポイント支払い、B1〜B3 はクレジットカード決済）
- 店頭受取・スムーズ店頭受取は UPT-03・UPT-04、支店・店内アカウントは UPT-06

## 期待値の決まり（行ごとに当てはめる）

付与ポイント ＝ 小計 − 使用ポイント が 0 以下なら 0、そうでなければ (小計 − 使用ポイント) × 顧客グループの還元率（%）÷ 100 の小数点以下を切り捨てた値（0203 受注情報編集 現行仕様「ポイントの再計算」）。送料・手数料は小計に入らず、付与の対象外（新実装 src/Eccube/Service/PurchaseFlow/Processor/PointProcessor.php 242〜256行は小計だけを使う。設計書は小計と書くだけで、送料・手数料を除くとは書かない。scenario_list.md の食い違い）。

| 例（A × B × D） | 小計 | 使用 | 付与ポイント |
|---|---|---|---|
| A1（1%）× B1 × D1 | 10,000円 | 0 | 100 |
| A1（1%）× B1 × D2 | 12,345円 | 0 | 123 |
| A1（1%）× B2 × D2 | 12,345円 | 1,000 | 113（(12,345−1,000)×1%＝113.45） |
| A2（5%）× B1 × D2 | 12,345円 | 0 | 617（12,345×5%＝617.25） |
| A2（5%）× B2 × D1 | 10,000円 | 2,000 | 400 |
| A1/A2/A3 × B3・B4 | 5,000円（送料込みで5,500円） | 5,200〜5,500 | 0（小計−使用が0以下） |
| A3（0%）× 任意 | — | — | 0 |

各行の終点（目で確かめる結果）：
- 出荷完了にする前：ご注文内容の確認画面と、マイページの注文履歴詳細に付与予定（「ポイント発生」）が出る。履歴詳細に「※獲得ポイントは商品出荷時に有効になります。」が出る（0304 注文購入履歴詳細 F06-07）。残高・マイページのポイント履歴には増えない
- C1（出荷実績CSV）またはC2（受注編集）で出荷完了にしたあと：会員の保有ポイントが付与分だけ増える。ポイント履歴に、増減量＋付与ポイントの行が1つ、注文番号つきで残る（種別は購入によるポイント取得）。付与が0のときは履歴を作らない（0203 出荷実績インポート登録「付与ポイントが空のとき、0のときはポイントを付与しない」）。スマレジの会員ポイントも同じ量だけ増える（UTS-14）
- 出荷完了メールが届く。メール（新実装の日本語・英語のテンプレート）に付与ポイントの行が無い（使用ポイントの行だけある）（`scenario_list.md` の食い違い）

## 実装で確かめたこと（2026-11-05）

- 付与は「出荷完了」への更新で1回だけ。受注編集・出荷実績CSVの2経路：`src/Eccube/Controller/Admin/Order/EditController.php` 725・778・890・913行、`src/Eccube/Controller/Admin/Order/OrderCsvController.php` 349行。対応状況が「引き渡し済み」への更新では付与の処理が無い（設計書 0203 は出荷完了または引き渡し済み。scenario_list.md の食い違い）
- 還元率は会員の顧客グループの還元率。商品別の付与率は使われていない（`src/Eccube/Service/PointHelper.php` の注記「商品別ポイントは未実装」）
- 開発環境の顧客グループの還元率は、通常会員1・SCG取引用5・店内アカウント0・Sekappy用0・支店用店内アカウント0・海外代理販売用0・集換社アカウント0（DBダンプ 2026-09-07）。店舗基本情報のポイント設定は全店舗で有効、ポイントの換算は1ポイント1円（同）

## まとめた水準

- A3 還元率0%の顧客グループ：Sekappy用・海外代理販売用・集換社アカウント。付与は0で履歴も作らず、流れ・表示が同じため1つにまとめた。顧客グループごとに選べる支払方法・配送方法は違う（UTS-01）が、ポイントの付与の処理は還元率だけで決まる（PointProcessor.php 242〜256行）ため分けない
- 支払方法（クレジットカード決済・登録済みクレジットカード決済・コンビニ決済・郵便振替・銀行振込・代金引換）：付与の計算は小計と使用ポイントと還元率だけで決まり、出荷完了にする時点も同じ。入金待ち・注文受領など購入直後の状態は違うが、出荷完了へ進めば同じ（UTS-01・UTS-16）ため水準にしない。店頭支払だけは付与が0になる（例外E2）
