# UMB-14 お客様がお問い合わせを送り、会員は履歴で確かめる

| 項目 | 内容 |
|---|---|
| 利用者 | お客様（会員・未ログイン）→ メール（本人宛・受付側） |
| 目的 | お客様がお問い合わせの画面で件名を選んで入力し、確認画面を経て送信する。完了画面（「お問い合わせが完了いたしました。ご利用ありがとうございました。」）が出て、本人のメールアドレスと受付側（店舗または件名ごとの受付アドレス）に同じ内容のメールが届く。会員は、お問い合わせ履歴の一覧と詳細で、問い合わせ日時・お問い合わせ種別・お問い合わせ番号・内容を確かめられる |
| 種類 | 正常（組み合わせ表の16行）＋例外7件 |
| マトリクスの行 | `matrix_UMB-14/matrix.md` のT01（件名＝通販に関するお問い合わせ・お客様＝ログインした会員）。T02〜T16 は「L3で変わるところ」 |
| もとのシナリオ | なし（今のシナリオに対応が無い） |

## 前提

- 共通の決まり：`../L4を流すときの共通の決まり.md` を先に読む（試験データの名前にシナリオIDを付ける・共有の設定は元に戻す・バッチの起動・店舗の読み替えなど）
- 用意するデータ（試験用の値。設計書の値ではない）
  - 会員：本会員「会員管理試験 問合せ UMB-14」（姓「会員管理試験」・名「問合せ UMB-14」、メールアドレス `umb14-member@example.test`、電話番号は試験用の番号）。フロントで会員登録して本会員にする（UMB-01・UMB-02 の手順。メールの受け口で本登録のメールを読める）。お問い合わせを1件も送っていない状態で始める
  - 未ログインの行（C2）で使う送り主：メールアドレスは行ごとに `umb14-guest-t02@example.test` のように行番号を入れた、会員でないアドレス（受け口で読める）。例外E7だけは上の会員のメールアドレスを使う
  - 件名の選択肢：流す前に、お問い合わせ画面の件名の選択肢を確かめて控える（開発環境の設定の値。設計書の一覧は8件、開発環境は7件で「協賛関連」が無い。環境を作り直すと変わりうる）。付帯情報の欄の名称は件名ごとに違う（通販＝注文番号、ネット買取＝買取番号、その他＝注文番号もしくは買取番号、ほかは欄なし）
  - 店舗：店舗の欄（A3・A4）とイベント実施店舗（A5）では、本店（店舗ID 1）を選ぶ（開発環境では店舗を新しく作らない）。選択肢には閉店・非公開の店舗は出ない
  - 受付側の宛先：流す前に、通販・その他＝ショップ基本情報の受付アドレス、ネット買取・委託販売・デッキ構築機能・記事・動画＝件名ごとの受付アドレス、店舗でのお買い物・イベント＝選んだ店舗の受付アドレス（店舗に無ければ件名の受付アドレス）を設定の画面で確かめて控え、それぞれ試験用のメールの受け口で読めるか確かめる。読めない宛先は、手順5を「実施不可（流せない）」として記録し、合否は本人宛のメール（手順4）で付ける
  - 手順の前に控える値：会員のお問い合わせ履歴の件数（0件で始める）、受け口の各宛先の件数
- 画面の名前・文言は新実装の表示で書く。表示言語は日本語で流す（英語表示は結合テストで確かめる。依頼者決定 2026-11-09）

## 操作の流れと期待値

| # | 操作する人と操作 | 期待値（画面で見えること） |
|---|---|---|
| 1 | お客様（会員）：ログインし、マイページの「お問い合わせ」を開く | 見出し「お問い合わせ」とパンくずが出る。「ご利用案内はこちら」のバナー、件名の選択肢（初期値は先頭の「通販に関するお問い合わせ」）が出る。氏名（姓・名）・電話番号・メールアドレスに、会員の値が初めから入っている。件名が通販なので、付帯情報の欄（ラベル「注文番号」）が出て、店舗の欄・お問い合わせ詳細は出ない |
| 2 | お客様（会員）：注文番号欄に試験用の番号（例 `UMB14-T01-0001`）、お問い合わせ内容に試験用の文章（例「シナリオ試験 UMB-14 T01」）を入れ、「確認画面へ」を押す | 確認画面に進む。「下記の内容で送信してもよろしいでしょうか？よろしければ「送信する」へお進みください。」が出て、件名（通販に関するお問い合わせ）・注文番号・氏名・電話番号・メールアドレス・内容が入力どおりに並ぶ。「送信する」と「戻る」のボタンが出る |
| 3 | お客様（会員）：「送信する」を押す | お問い合わせ完了の画面に進み、「お問い合わせが完了いたしました。ご利用ありがとうございました。」が出る。「ホームへ戻る」のリンクが出る |
| 4 | お客様（会員）：本人のメールアドレスの受け口を開く | 件名「【晴れる屋】お問い合わせを受付いたしました」のメールが1通届く。本文は「（姓） （名） 様」で始まり、「お問い合わせありがとうございます。」「以下のお問い合わせについて、受付いたしました。」のあと、「■注文番号：」に入れた番号、「■お名前」「■電話番号」「■メールアドレス」「■お問い合わせの内容：」に入力した内容が並ぶ（店舗の行は、店舗を選ばない件名では出ない） |
| 5 | 店舗チーム：控えた受付側の宛先（通販はショップ基本情報の受付アドレス）の受け口を開く | 手順4と同じ件名・本文のメールが1通届く（本人宛のコピー。受付側にも同じ内容が届く） |
| 6 | お客様（会員）：マイページの「お問い合わせ履歴」を開く | 見出し「お問い合わせ履歴一覧」と、総件数「1件」が出る。一覧に、問い合わせ日時（日本語の一覧の書式「Y年m月d日 H:i」。例 2026年11月27日 14:05。0306 の現行仕様の定めで、Excel 由来の欄に書式の定めは無い）・お問い合わせ種別（通販に関するお問い合わせ）・「（お問い合わせ番号：〈番号〉）」が1件出る |
| 7 | お客様（会員）：一覧の1件を押す | 「お問い合わせ履歴詳細」が開き、問い合わせ日時・お問い合わせ種別・お問い合わせ番号、「（姓） （名） 様」、入力した内容（入力時の改行を反映）が出る。「戻る」で一覧に戻る |

## 終わったあとに確かめること

| 確かめる場所 | 期待値 |

## L3で変わるところ（マトリクスの他の行・例外）

手順の番号は上の「操作の流れと期待値」。1回ずつ流す。同じ会員で複数の行を流すと前の行の分が履歴に残るので、行ごとに履歴の件数の期待値は「流した行の分」で数える。会員でない送り主（C2）の行は手順1を「ログインしないで、ヘッダーのメニューの「お問い合わせ」から画面を開く」に、手順6・7を「履歴は会員だけ（ログインしないと開けない）。一致する会員がいないアドレスなので、どの会員の履歴にも出ない」に替える（C2 の氏名・電話番号・メールアドレスは自分で入力する。画面に初期値は入らない）。
