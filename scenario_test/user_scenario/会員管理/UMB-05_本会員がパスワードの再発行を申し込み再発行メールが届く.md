# UMB-05 本会員がパスワードの再発行を申し込み、再発行メールが届く

| 項目 | 内容 |
|---|---|
| 利用者 | お客様（パスワードを忘れた本会員）→ メール |
| 目的 | パスワードを忘れた会員が、ログイン画面の「パスワードをお忘れの方はこちら」からメールアドレスを送ると、再発行メールの送信完了画面が出て、本会員には再設定のURL入りのメール（URLは発行から24時間有効）が届く。URLを使った再設定は UMB-25 |
| 種類 | 正常（代表の1本）＋ L3の3件（組み合わせ表は無い） |
| マトリクスの行 | なし（会員の状態と入力の種類を1つずつ確かめる。効き合う因子が無いのでマトリクスは作らない） |
| もとのシナリオ | なし |

## 前提

- 共通の決まり：`../L4を流すときの共通の決まり.md` を先に読む（試験データの名前にシナリオIDを付ける・共有の設定は元に戻す・バッチの起動・店舗の読み替えなど）
- システムの外で済んでいること：なし
- 用意するデータ（試験用の値。設計書の値ではない）
  - 本会員：お名前「試験 会員UMB05」、メールアドレス `umb05-t01@example.test`、パスワード「Umb05Test-2026」。UMB-01 の手順1〜7（仮会員にする）と UMB-02 の手順1〜2（メールの本登録のURLを開いて本会員にする）で、この試験専用に作る
  - 仮会員（R1用）：`umb05-r1@example.test`。UMB-01 の手順1〜5で仮会員にしたまま（本登録のURLは開かない）
  - 登録のないメールアドレス（R2用）：`umb05-r2@example.test`（会員を作らない）
  - 手順の前に控える値：メール受け口の `umb05-t01@example.test` の件数（本会員登録完了のメール1通）
- 画面の名前・文言は新実装の表示で書く

## L3で変わるところ（組み合わせ表は無い。1つずつ別のテストにする）

手順の番号は上の「操作の流れと期待値」。

| 行 | 条件 | 変わるところ |
|---|---|---|
| R1 | 仮会員のメールアドレス | 手順2：メールアドレス `umb05-r1@example.test` を入れて「次のページへ」を押す。本会員のときと同じ完了画面（「パスワード再発行メールの送信が完了しました。」）が出る（会員の有無・種別を画面で区別しない）。手順3：メール受け口には再設定のメールが届かない（同じ時間帯に、手順2〜3の本会員 `umb05-t01@example.test` には届いたことを確かめてから、届かないと判定する）。手順4・5は流さない |
| R2 | 登録のないメールアドレス | 手順2：メールアドレス `umb05-r2@example.test` を入れて「次のページへ」を押す。同じ完了画面が出る（会員の有無を区別しない。F06-04-MSG-001）。手順3：メールは届かない（上のR1と同じ判定のしかた）。手順4・5は流さない |
| R3 | メールアドレスの形式が正しくない | 手順2：メールアドレスに「umb05-r3」（@の無い値）を入れて「次のページへ」を押す。完了画面へは進まず、入力画面に留まり、メールアドレス欄の直下にエラーの文言が出る（設計書は「メールアドレス(1-2)の直下にエラー文言を表示する」とだけ定め、文言を持たない。新実装の文言「有効なメールアドレスではありません。」を記録する）。メールは送られない |

## 記録（判断待ちではない。合否は設計書の期待値で付け、新実装の動きは記録する）

- 設計書の再発行画面の案内に「※新しくパスワードを発行いたしますので、お忘れになったパスワードはご利用できなくなります。」とあるが、機能仕様は申し込みの時点ではパスワードを変えない。新実装も申し込みでは変えない（手順5）。案内の文は、URLで再設定したあとのことと読める。手順5は設計書の機能仕様のとおりを期待値にした
- 設計書の再設定画面の案内は「半角英数字記号 8文字以上,32文字以内」だが、新実装は12〜50文字（`scenario_list.md` に記録済み。UMB-25 で確かめる）
- 再発行を申し込んだメールアドレスが会員でないときのログ（設計書：ログを保存する）は画面で確かめない
