# 会員管理のブラックリスト（UMB-23）

IPA「高信頼化ソフトウェアのための開発手法ガイドブック」(2010) の表6-9〜6-11と同じ手順で作る。

1. 因子・水準表（FL表）: `fl_table.tsv`
2. 禁則表: `prohibitions.tsv`
3. 組み合わせテストマトリクス: `matrix.md` / `matrix.tsv`。`build_matrix.py` が作る。1行が1本のシナリオになる
4. 例外の差し込み表: `exceptions.tsv`。エラーや中断（★の手順）は正常な値と混ぜず、条件に合う行へ1つずつ差し込む

## 範囲

- 店舗チームが管理画面でブラックリストを登録し、同じ氏名・電話番号・住所のお客様が、会員登録・会員情報の変更・配送先の登録をしようとすると断られる（0207 M08-13、0306 F06-01・F06-18・F06-20）。削除すると登録できる
- ブラックリストは項目（氏名・電話番号・住所）とキーワードの組。会員の氏名（姓＋名）・電話番号（3つの欄を続けた文字列）・住所（都道府県＋住所1＋住所2）から空白を除いた文字列と、完全一致で照合する
- ネット買取の会員登録で使う（0207 M08-13）とあるが、0305（ネット買取）の定めは範囲外のため、ここでは3つの場面（B1〜B3）だけを確かめる
- 1行は「項目（A）のキーワードを登録しておき、場面（B）で、入力（C）のしかたで進める」手順

## 期待結果の決まり（行ごとに当てはめる）

| 入力（C） | 期待 |
|---|---|
| C1 空白を除いて完全に一致 | 断られる。会員は登録されない／変更・登録が確定しない |
| C2 空白が混じっている（空白を除くと一致） | 断られる（入力の空白は取り除いて照合する） |
| C3 一部だけ一致（部分一致） | 断られず、登録・変更・登録できる |

| 場面（B） | 断られるときの画面 |
|---|---|
| B1 新規会員登録 | 登録エラー画面：「ご入力いただいた内容は使用できません。もう一度、登録ページへアクセスして登録情報の変更をお願いいたします。」（F06-01-MSG-001） |
| B2 会員情報の変更 | 判断待ち（`scenario_list.md` の判断待ち#1）。会員情報が変更されないことまでを確かめる |
| B3 配送先の登録 | 判断待ち（同上）。配送先が登録されないことまでを確かめる |

- 照合の対象：A1 氏名は姓と名を続けた文字列、A2 電話番号は3つの欄を続けた文字列（ハイフンなし）、A3 住所は都道府県・住所1・住所2を続けた文字列
- ブラックリスト自体の登録・編集・削除（0207 M08-13）の入力エラーは、`exceptions.tsv` で確かめる（項目未選択・電話番号に数字以外・重複）。キーワードは保存前に、半角・全角の空白をすべて取り除く
- 配送先は、氏名・電話番号・住所のどれかが一致したとき断る（0306 F06-20（確認）の定め）

## 実装で確かめたこと（2026-11-05）

- 会員登録・会員情報変更・配送先登録のいずれも、ブラックリストに当たると登録エラー画面（`Entry/regist_error`）へ移る：`src/Eccube/Controller/Front/EntryController.php` 148〜158行目、`.../Mypage/ChangeController.php` 128〜141行目、`.../Mypage/DeliveryController.php` 231〜243行目。画面の文言は `messages.ja.yaml` 460行目「ご入力いただいた内容は使用できません。」
- 設計書は、会員情報の変更では「会員情報更新エラー画面に遷移する」（0306 F06-18 機能仕様）と「会員情報変更画面に留まる」（F06-18-MSG-001）で食い違い、配送先の登録では「会員情報登録エラー画面に遷移する」（0306 F06-20 確認）。新実装は変更・配送先とも登録時と同じ登録エラー画面（判断待ち#1）

## まとめた水準

- 項目（A）：氏名・電話番号・住所は照合の対象が別（姓名・3つの欄・都道府県と住所）なので分けた
- 場面（B）：画面が違うので分けた（B1 登録、B2 変更、B3 配送先）
