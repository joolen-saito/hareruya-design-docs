# UMB-19 店舗チームが会員にメールを手動で通知する

| 項目 | 内容 |
|---|---|
| 利用者 | 店舗チーム（管理画面の会員一覧・会員編集・手動メール通知）→ メール（会員） |
| 目的 | 店舗チームが会員検索の一覧、または会員編集から「メール通知」を開く。テンプレートを選ぶと件名と本文が入り、確認画面でプレビューして送信すると、会員にメールが届き、「メール送信が完了しました。」が出て会員編集に戻る。会員のメール配信履歴に残る |
| 種類 | 正常（組み合わせ表は作らない。代表1本＋L3の表の行）＋例外（入力の検証に通らない・選べないテンプレート） |
| マトリクスの行 | 組み合わせ表は無い（因子が無い。`scenario_list.md` の L3 欄）。以下の行は「表外の具体例」 |
| もとのシナリオ | SCN-ONLINE-KAITORI-ネット買取処理お客様-002（身分証問題ないか：会員マスター手動メール通知）の手動メール通知の部分。ネット買取の本人確認で問題があったときの再申請の依頼は、この機能を使う（UNK-02） |

## 前提

- 共通の決まり：`../L4を流すときの共通の決まり.md` を先に読む（試験データの名前にシナリオIDを付ける・共有の設定は元に戻す・バッチの起動・店舗の読み替えなど）
- 用意するデータ（試験用の値。設計書の値ではない）
  - 会員：本会員「会員管理試験 手動通知 UMB-19」（メールアドレス `umb19-member@example.test`）。フロントで会員登録して本会員にする（UMB-01・UMB-02。メールの受け口で読める）。メール配信履歴は0件で始める
  - 使うテンプレート：メールテンプレート「【通販/日】白紙テンプレ(アカウント用)」（件名「【晴れる屋】お問い合わせについて」。会員ベースの本文）。初期データにあるもの（app/DoctrineMigrations/sql/baseline_database_records.sql）。流す前に、設定のメールテンプレートの一覧に、この名前のテンプレートがあるか確かめる
  - 店舗チームの担当者：会員管理の会員一覧・会員編集・手動メール通知を使える
  - 手順の前に控える値：会員の受け口の件数、会員のメール配信履歴の件数
- 画面の名前・文言は新実装の表示で書く（設計書の「テンプレ選択」は新実装では「テンプレート」、「確認」ボタンは「確認」）

## 操作の流れと期待値

| # | 操作する人と操作 | 期待値（画面で見えること） |
|---|---|---|
| 1 | 店舗チーム：管理画面の会員管理＞会員一覧で、この試験の会員を検索し、お名前のリンクから会員編集を開き、「手動メール通知」を押す | 「手動メール通知」の画面が開く。会員名（この試験の会員の名前）、「テンプレート」の選択（初めは未選択）、「件名」「本文」の欄、「会員編集に戻る」と「確認」のボタンが出る。件名と本文は空欄 |
| 2 | 店舗チーム：「テンプレート」で「【通販/日】白紙テンプレ(アカウント用)」を選ぶ | 画面が更新され、件名に「【晴れる屋】お問い合わせについて」が入る。本文に、冒頭の「（姓）　（名）　様」、テンプレートのヘッダの文（「いつもお世話になっております。晴れる屋です。」など）、「■お客様の情報」の氏名とメールアドレス（この試験の会員の値）、フッタの文（店舗の連絡先）が入る |
| 3 | 店舗チーム：本文の末尾に試験用の1行「UMB-19 の手動メール通知（試験用）」を足して「確認」を押す | 確認の画面が出る。会員名・テンプレート名・件名・本文（足した1行を含む）が表示される（プレビュー）。「会員編集に戻る」のリンクと「メール送信」のボタンが出る |
| 4 | 店舗チーム：「メール送信」を押す | 会員編集の画面に戻り、「メール送信が完了しました。」が出る |
| 5 | お客様（会員）：受け口を開く | 件名「【晴れる屋】お問い合わせについて」のメールが1通届く。本文は、確認画面で見た本文のとおり（足した1行を含む） |
| 6 | 店舗チーム：会員編集の「送信履歴」を押す | 「メール配信履歴」に1件出る。処理日は今日、通知メール欄はテンプレートの件名「【晴れる屋】お問い合わせについて」、件名欄も同じ。件名のリンクを押すと、件名と手順5の本文がポップアップで出る |

## 終わったあとに確かめること

| 確かめる場所 | 期待値 |
|---|---|
| 会員の受け口 | 1通増える（重複して届かない） |
| メール配信履歴 | 1件増える。会員そのものの情報（氏名・状態など）は変わらない |
| 店舗の送信元アドレスへの写し | 新実装は写し（控え）を店舗の送信元アドレスにも送る。読める受け口があれば記録する（合否は会員宛のメールで付ける） |

## L3で変わるところ（組み合わせ表の他の行・例外）

手順の番号は上の「操作の流れと期待値」。1回ずつ流す。

| 行 | 条件 | 変わるところ（期待値） |
|---|---|---|
| M01 | 会員一覧の行の操作メニューから開く | 手順1：会員一覧で、この試験の会員の行の操作メニューから「メール通知」を選ぶ。手順1と同じ「手動メール通知」の画面が開く（会員編集の「手動メール通知」ボタンと同じ画面） |
| M02 | 選べるテンプレート | 手順1：「テンプレート」の選択肢を開く。会員向けのテンプレート（会員用・会員用の英語・ベースなし）だけが出る。自動で送るメールのテンプレート（「【販売/日】仮会員登録」「【販売/日】会員本登録」など）は出ない。名称の昇順に並ぶ |
| M03 | 件名・本文を直して送る | 手順3：件名を「【晴れる屋】UMB-19 試験」に書き換え、本文も書き換えて確認・送信する。確認画面・届いたメール・履歴の件名と本文が、書き換えた内容どおり（テンプレートの文のままではない）。履歴の通知メール欄はテンプレートの件名のまま、件名欄は書き換えた件名 |
| M04 | 入力の検証に通らない | 手順3：件名を空にして「確認」を押す。確認画面に進まず作成画面に戻る。通らなかった理由は画面に出ず、件名と本文は選んだテンプレートの初期値に戻る（編集していた内容は保持されない）。メールは送られない |
| M05 | 「会員編集に戻る」 | 手順3の確認画面で「会員編集に戻る」を押す。メールは送られず、会員編集の画面に戻る。受け口も履歴も増えない |
| M06 | テンプレートを選ばずに確認する | 手順2を行わず、件名・本文を入れて「確認」を押す。テンプレートは必須なので確認画面に進まず、作成画面に戻る（M04と同じ扱い） |
| M07 | 選べないテンプレートの指定 | 手順2で、選べるテンプレート以外（自動で送るメールのテンプレート）の番号を画面のアドレスに入れて開く操作は、画面の通常の操作では作れない（選択肢に出ない）。実施不可（流せない）として記録する |
| M08 | ネット買取の本人確認で問題があったときの再申請の依頼 | UNK-02 の手順で、会員にこの機能を使い、オンライン失敗のテンプレート（例「オンライン失敗　≪期限切れ≫」）で送る。手順は上と同じで、テンプレートと件名（「【晴れる屋 ネット買取】オンライン本人確認が正しく行えませんでした」）が替わる |

例外：このシナリオに例外の差し込み表は無い（組み合わせ表が無い）。M04〜M07 が例外にあたる。
