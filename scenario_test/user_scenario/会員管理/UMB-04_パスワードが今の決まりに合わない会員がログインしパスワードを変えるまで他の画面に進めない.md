# UMB-04 パスワードが今の決まりに合わない会員がログインし、パスワードを変えるまで他の画面に進めない

| 項目 | 内容 |
|---|---|
| 利用者 | お客様（旧サイトから移行した会員。本店のサイト） |
| 目的 | 今のパスワードの決まり（半角英数記号12〜50文字、メールアドレスと同じ値は不可）に合わないパスワードの会員がログインすると、ログイン自体は成功するが、パスワード設定の画面へ移る。パスワードを変えるまでは、ログインが必要な画面へのリンクを押してもこの画面に戻る。パスワードを変えると、マイページなど通常の画面が開ける。変更の完了後にブラウザの「戻る」で再送信しても、マイページへ移る |
| 種類 | 正常（代表の1本）＋ L3の3件（組み合わせ表は無い） |
| マトリクスの行 | なし（因子が無いのでマトリクスは作らない） |
| もとのシナリオ | なし。通販の購入の途中でログインしたときの確認は UTS-01 の例外E8（購入が止まる・続けられるまで）。ここではアカウントの側から確かめる |

## 前提

- 共通の決まり：`../L4を流すときの共通の決まり.md` を先に読む（試験データの名前にシナリオIDを付ける・共有の設定は元に戻す・バッチの起動・店舗の読み替えなど）
- システムの外で済んでいること：なし
- 起点の会員（この試験の前提）：パスワードが今の決まりに合わない本会員。会員登録・会員情報変更・パスワードの再設定・管理画面の会員編集のどの画面の操作も12文字以上を要求するので、画面からは作れない（依頼者決定 2026-11-09：他層）。旧サイトから移行した会員（パスワードが12文字未満のもの）が居る環境で通す。流す前に、その環境で使える移行会員のメールアドレスと旧パスワードを控える（以下 `umb04-t01@example.test` と書く）。そのような会員が環境に居ないときは、このシナリオは「実施不可（流せない）」として記録する（開発者ツールで通信を書き換えるなどの手段は使わない）
- 用意するデータ（試験用の値。設計書の値ではない）
  - 手順4で付ける新しいパスワード：「Umb04Newpass-2026」（12文字以上・メールアドレスと違う値）。移行会員の新しいパスワードを変えたあとは、控えた旧パスワードではログインできなくなる。やり直すときは別の移行会員を使う
  - 例外のR2用：今の決まりに合う本会員 `umb04-r2@example.test`（UMB-01 の手順1〜7とUMB-02 の手順1〜2で、この試験専用に作る。パスワードは「Umb04Test-2026」）
  - 手順の前に控える値：会員のログインできるメールアドレスと旧パスワード
- 画面の名前・文言は新実装の表示で書く。0306 パスワード設定（ポリシー違反用）は、固定メッセージの文言を設計書に持たない（画像だけ）ので、メッセージの文言は新実装の表示を記録する

## 記録（判断待ちではない。合否は設計書の期待値で付け、新実装の動きは記録する）

- 起点の会員は画面では作れない（決着 2026-11-09）。移行会員が居る環境で通し、居なければ「実施不可（流せない）」と記録する

- 固定メッセージ（識別ID 1）の文言は設計書の文字に無い。新実装の文言の先頭が「[リニューアル日]」の文字のまま出るときは記録する
