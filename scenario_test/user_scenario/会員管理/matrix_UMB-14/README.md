# 会員管理のお問い合わせ（UMB-14）

IPA「高信頼化ソフトウェアのための開発手法ガイドブック」(2010) の表6-9〜6-11と同じ手順で作る。

1. 因子・水準表（FL表）: `fl_table.tsv`
2. 禁則表: `prohibitions.tsv`
3. 組み合わせテストマトリクス: `matrix.md` / `matrix.tsv`。`build_matrix.py` が作る。1行が1本のシナリオになる
4. 例外の差し込み表: `exceptions.tsv`。エラーや中断（★の手順）は正常な値と混ぜず、条件に合う行へ1つずつ差し込む

## 範囲

- お客様が「お問い合わせ」で件名を選び、入力→確認→送信し、お問い合わせ履歴で確かめる（0306 F06-22・F06-23・F06-24）。送ったお問い合わせは、受付側（店舗ごとの受付アドレス）と、お客様のメールアドレスにも同じ内容が届く
- イベントのキャンセル申込（A5）は、イベント管理 UEV-03 の起点（申込画面ではなく、お問い合わせフォーム）。ここではフォームの入力・送信・履歴までを確かめ、キャンセル済みにする作業は UEV-03
- 1行は「件名（A）を、表示言語（B）で、会員か未ログインか（C）のお客様が、送信して、履歴（会員のとき）で確かめる」手順

## 期待結果の決まり（行ごとに当てはめる）

| 件名（A） | 入力する欄 | 送信のあと |
|---|---|---|
| A1 通販 | 注文番号欄（任意） | 受付側と本人にメールが届く。完了画面に「お問い合わせが完了いたしました。ご利用ありがとうございました。」 |
| A2 ネット買取 | 買取番号欄（任意） | 同上 |
| A3 店舗でのお買い物 | お問い合わせ店舗選択（閉店・非公開の店舗は出ない） | 選んだ店舗の受付アドレス（無ければ件名の受付アドレス、それも無ければショップ基本情報）に届く |
| A4 イベントについて | お問い合わせ店舗選択 | 同上 |
| A5 イベントのキャンセル申込 | イベント名・実施店舗・開催日・開始時間・キャンセル理由・（その他の理由）・アンケート。キャンセル期限の案内が出る | 入力値が項目名つきで内容に転記されて届く。履歴詳細にイベント名・店舗・日付・開始時間・キャンセル期限・理由が出る |
| A6 委託販売・デッキ構築機能 | 付帯情報も店舗欄も無い | 件名ごとの受付アドレスに届く |
| A7 記事・動画 | 同上 | 同上 |
| A8 その他 | 注文番号または買取番号欄（任意） | 同上 |

| 他の因子 | 期待 |
|---|---|
| B2 英語 | 電話番号は1欄。件名は英語の名称がある4件（通販／店舗でのお買い物・イベント／記事・動画／その他）だけが出る。完了画面は英語の文言（「Thank you very much for your time.…」）。履歴の日時は m/d/Y H:i |
| C1 会員 | 氏名・電話番号・メールアドレスが会員の値で初期入力される。履歴に載る |
| C2 未ログイン | 自分で入力する。入力メールアドレスと一致する本会員がいれば、その会員の履歴に載る（例外E7） |

- 履歴（会員のみ）：お問い合わせ番号の降順。一覧に問い合わせ日時・お問い合わせ種別・お問い合わせ番号、詳細に内容（改行を反映）。日本語の日時は一覧が「Y年m月d日 H:i」、詳細が「Y/m/d H:i」
- 英語の行（B2）は、英語の名称がある件名だけ（A2・A6 と組み合わせない。禁則）

## 実装で確かめたこと（2026-11-05）

- 件名は開発環境の設定（DBダンプ 2026-09-07 の問い合わせ件名）に7件：通販・ネット買取・店舗でのお買い物・イベント・委託販売・デッキ構築機能・記事・動画・その他。設計書の一覧にある8つ目「協賛関連」は開発環境に無い（`scenario_list.md` の食い違い）
- 付帯情報の名称（開発環境の設定）：通販＝注文番号、ネット買取＝買取番号、その他＝注文番号もしくは買取番号、ほかは無し。店舗欄があるのは「店舗でのお買い物・イベント」だけ。英語の名称があるのは通販／店舗でのお買い物・イベント／記事・動画／その他の4件
- 開発環境の件名の設定はDBダンプの値で、環境を作り直すと変わりうる。行を実行する前に、画面の件名の選択肢で確かめる

## まとめた水準

- A6 委託販売とデッキ構築機能に関するお問い合わせ：1つにまとめた。開発環境の設定で、どちらも付帯情報の名称が空・店舗欄なし・英語の名称なしで、同じ入力欄・同じ受付の流れになるため（記事・動画は英語の名称があり、英語ページに出るので別の水準 A7）
- A3（お買い物）とA4（イベントについて）：設計書に違いの定めが無く（「店舗でのお買い物について」の確認だけが定義されている）、分けたままにした（迷ったら分ける）
