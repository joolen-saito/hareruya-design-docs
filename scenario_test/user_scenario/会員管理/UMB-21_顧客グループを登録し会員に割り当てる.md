# UMB-21 店舗チームが顧客グループを登録し、会員に割り当てる・使われているグループは削除できない

| 項目 | 内容 |
|---|---|
| 利用者 | 店舗チーム（管理画面の顧客グループ管理・会員編集） |
| 目的 | 店舗チームが管理画面の顧客グループ管理で、名称・ポイント還元率・店内注文専用アカウント／支店店内注文専用アカウントの区分・使える支払方法を入れて登録すると「保存しました」が出て一覧に載る。会員編集で会員に割り当てると、その区分の制御がかかる（UMB-22）。会員が1件でも入っているグループは削除できず、いないグループは削除できる（「削除しました」） |
| 種類 | 正常（組み合わせ表は作らない。代表1本＋L3の表の行）＋例外（会員のいるグループの削除・入力の誤り） |
| マトリクスの行 | 組み合わせ表は無い（区分と支払方法は登録の入力にとどまる。`scenario_list.md` の L3 欄）。以下の行は「表外の具体例」 |
| もとのシナリオ | なし（今のシナリオに対応が無い） |

## 前提

- 共通の決まり：`../L4を流すときの共通の決まり.md` を先に読む（試験データの名前にシナリオIDを付ける・共有の設定は元に戻す・バッチの起動・店舗の読み替えなど）
- 用意するデータ（試験用の値。設計書の値ではない）
  - 会員：本会員「会員管理試験 グループ UMB-21」（メールアドレス `umb21-member@example.test`）。フロントで会員登録して本会員にする（UMB-01・UMB-02）。顧客グループは初めは「通常会員」
  - 登録する顧客グループ（試験用の値）：名称「シナリオ試験グループ UMB-21」、ポイント還元率 `3`、店内注文専用アカウント・支店店内注文専用アカウントはどちらもチェックしない、使える支払方法は「銀行振込」と「郵便振替」。（開発環境の既存のグループ「通常会員」「店内アカウント」「支店用店内アカウント」などは触らない）
  - 店舗チームの担当者：会員管理の顧客グループ管理・会員編集を使える
  - 手順の前に控える値：顧客グループの一覧の件数と、会員の顧客グループ（通常会員）
- 画面の名前・文言は新実装の表示で書く。使い終わったグループは、手順7の削除で残さない

## 操作の流れと期待値

| # | 操作する人と操作 | 期待値（画面で見えること） |
|---|---|---|
| 1 | 店舗チーム：管理画面の会員管理＞顧客グループ管理を開く | 見出し「顧客グループ編集」（上に「顧客グループ管理」）が出る。入力のカードの見出しは「新規追加」。名称・ポイント還元率(%)・店内注文専用アカウントと支店店内注文専用アカウントのチェック・支払方法のチェックが並び、下の一覧に既存の顧客グループ（列「名称」「ポイント率」「支払方法」「削除」）が出る |
| 2 | 店舗チーム：名称・ポイント還元率・支払方法（銀行振込・郵便振替）を入れて「登録」を押す | 「保存しました」が出て、顧客グループ管理の画面に戻り、入力欄は「新規追加」の状態（空）に戻る。一覧に「シナリオ試験グループ UMB-21」が、ポイント率「3」、支払方法「銀行振込・郵便振替」（選んだ2つ）で載る |
| 3 | 店舗チーム：一覧の「シナリオ試験グループ UMB-21」の名称を押し、ポイント還元率を `5` に変えて「登録」を押す | 名称を押すと、入力欄にそのグループの値が入り、カードの見出しは「編集」になる。登録すると「保存しました」が出て、新規追加の状態に戻る。一覧のポイント率が「5」になる |
| 4 | 店舗チーム：会員管理＞会員一覧でこの試験の会員を検索し、会員編集を開く。「顧客グループ」を「シナリオ試験グループ UMB-21」に替えて「登録」を押す | 「保存しました」が出る。会員編集を開き直すと、顧客グループが「シナリオ試験グループ UMB-21」になっている。区分のチェックを付けていないグループなので、会員のログインや画面の開き方は変わらない（区分を付けたグループの制御は UMB-22） |
| 5 | 店舗チーム：顧客グループ管理で、「シナリオ試験グループ UMB-21」の行の「削除」を押す | モーダルが開き、「削除します」と「シナリオ試験グループ UMB-21を削除してもよろしいですか？」、「キャンセル」「削除」のボタンが出る |
| 6 | 店舗チーム：確認で「削除」を押す | エラー「この購入グループは商品で使用されているため、 シナリオ試験グループ UMB-21 は削除することができません。」が出る（会員が入っているグループは削除できない）。顧客グループ管理の画面に戻り、一覧にグループが残っている。文言は設計書（M08-12-MSG-002）どおりで、顧客グループ・会員の話と合わない（設計書の食い違いに記録済み） |
| 7 | 店舗チーム：手順4の会員の顧客グループを「通常会員」に戻して「登録」を押し、顧客グループ管理で「シナリオ試験グループ UMB-21」の「削除」→確認の「削除」を押す | 会員は「保存しました」。グループの削除は「削除しました」が出て、一覧から「シナリオ試験グループ UMB-21」が消える（会員のいないグループは削除できる）。会員の顧客グループは「通常会員」に戻っている |

## L3で変わるところ（組み合わせ表の他の行・例外）

手順の番号は上の「操作の流れと期待値」。1回ずつ流す。作ったグループは、行ごとに最後に削除して残さない。

| 行 | 条件 | 変わるところ（期待値） |
|---|---|---|
| G01 | 新規（代表） | 代表の手順2 |
| G02 | 既存の編集（名称を押して） | 代表の手順3 |
| G03 | 削除の確認 | 代表の手順5・7 |
| G04 | 会員のいるグループの削除（エラー） | 代表の手順6 |
| G05 | 店内注文専用アカウントの区分を付けて登録 | 手順2：名称「シナリオ試験グループ UMB-21 店内」、「店内注文専用アカウント」にチェックを入れて登録する。「保存しました」。名称を押して開き直すと、チェックが入っている。会員に割り当てたときの画面の制御（許可IPのログイン・画面の制限）は UMB-22 で確かめる（手順4は、割り当てずに、グループの登録と削除だけを行う） |
| G06 | 支店店内注文専用アカウントの区分を付けて登録 | G05と同じで、「支店店内注文専用アカウント」にチェックを入れる。制御は UMB-22 |
| G07 | ポイント還元率が0 | 手順2：ポイント還元率を `0` にして登録する。「保存しました」。一覧のポイント率が「0」 |
| G08 | ポイント還元率が0以上の整数でない（空・`-1`・`1.5`） | 手順2：ポイント還元率を空・`-1`・`1.5` にそれぞれ入れて登録を押す。保存されず、ポイント還元率の欄の下にエラーが出て、同じ画面（一覧つき）が再表示される（エラーの文言は新実装の表示を記録する）。一覧にグループは増えない |
| G09 | 名称が空 | 手順2：名称を空にして登録を押す。保存されず、名称の欄の下に必須のエラー（「入力されていません。」）が出て、同じ画面が再表示される |
| G10 | 支払方法を1つも選ばない | 手順2：支払方法のチェックをすべて外して登録する。設計書は支払方法を必須としない（必須の印が無い）ので、保存される。一覧の支払方法の欄は空になる（新実装で保存できない場合は、画面の表示を記録して不合格にする） |
| G11 | 削除に失敗する（「関連するデータがあるため「（名称）」を削除できませんでした」） | 会員が登録されていないグループの削除でデータの結び付きで失敗する場合の文言（M08-12-MSG-004）。画面の操作では起こせないので、この行は「実施不可（流せない）」として記録する |

例外：このシナリオに例外の差し込み表は無い（組み合わせ表が無い）。G04・G08〜G11 が例外にあたる。
