# 会員管理の管理画面の会員編集（UMB-16）

IPA「高信頼化ソフトウェアのための開発手法ガイドブック」(2010) の表6-9〜6-11と同じ手順で作る。

1. 因子・水準表（FL表）: `fl_table.tsv`
2. 禁則表: `prohibitions.tsv`
3. 組み合わせテストマトリクス: `matrix.md` / `matrix.tsv`。`build_matrix.py` が作る。1行が1本のシナリオになる
4. 例外の差し込み表: `exceptions.tsv`。エラーや中断（★の手順）は正常な値と混ぜず、条件に合う行へ1つずつ差し込む

## 範囲

- 店舗チームが管理画面の会員検索から会員を開き、「会員登録/編集」で情報を変える（0207 M08-04）。変えた項目と変える前の本人確認ステータスで、本人確認ステータスが自動で未確認になるか、管理者が選び直したときの身分証有効期限、問題のある会員の利用停止（仮会員にして退会区分に記入）を確かめる
- 管理画面から会員を新規登録する機能は廃止（0207 M08-04 カスタマイズ要件「新規登録機能は廃止」）。新実装にも新規登録の入口が無い（`src/Eccube/Controller/Admin/Customer/CustomerEditController.php` の経路は会員を指定した編集だけ）。したがって新規登録は作らない
- 顧客分析タグの登録・フロントでの会員のオプトイン／オプトアウトはフェーズ2（`functions/phase2_specs.json` の 0207-M08-04）。範囲外
- オンライン本人確認の画面（身分証の写真・確認済みに変更するボタン）は UNK-02・UNK-10。配送先は UMB-17、ポイントは USM-15・UMB-10
- 1行は「本人確認ステータス（A）の会員の、項目（B）を変え、ステータスの選び直し（C）・会員の状態（D）を指定して、保存する」手順

## 期待結果の決まり（行ごとに当てはめる）

| 変更前（A） | 住所（B1） | お名前・フリガナ・生年月日（B2） | それ以外だけ（B3） |
|---|---|---|---|
| A1 未確認 | 未確認のまま | 未確認のまま | 未確認のまま |
| A2 確認中 | 確認中のまま | 確認中のまま | 確認中のまま |
| A3 オンライン本人確認済み | 確認ダイアログのあと、未確認に変わる | 同左 | オンライン本人確認済みのまま |
| A4 簡易書留確認済み | 確認ダイアログのあと、未確認に変わる | 簡易書留確認済みのまま（ダイアログなし） | 簡易書留確認済みのまま |

- 確認ダイアログ：「本人確認用情報に変更があるため本人確認ステータスを未確認に変更します。よろしいですか？ 本人確認用情報：お名前、お名前(フリガナ)、住所、生年月日」。OKで未確認に書き換えて保存、キャンセルは送信しない（例外E1・E2）
- 保存すると「保存しました」が出て、会員の編集画面が開く
- 未確認に変わるとき（A3・A4 の確認ダイアログのあと、C2）、身分証有効期限が入っていれば空欄になる（0207 M08-04 機能仕様。新実装 `CustomerEditController.php` 186〜191行目）。マイページの会員情報変更（UMB-11）では空にならない（`ChangeController.php` に処理が無い。UNK-14 の「会員情報の変更で未確認に戻っても有効期限は消えない」と合う）。期限の確かめ方は、オンライン本人確認のモーダルの身分証有効期限の初期表示
- C2（未確認に選び直す）：本人確認ステータスが未確認になり、身分証有効期限が入っていれば空欄になる。未確認の会員（A1）では選び直しの意味が無いので行に入れない（禁則P1）
- D2：会員の状態を仮会員にして退会区分に記入して保存する。その会員はログインできず（例外E7）、会員検索の「退会区分」（部分一致）で見つかる。会員検索の画面側は UMB-15
- 住所とは、国・郵便番号・海外用郵便番号・都道府県・住所1・住所2・住所3（0207 は住所3を追加）

## 実装で確かめたこと（2026-11-05）

- 管理画面の確認ダイアログの条件は、国・郵便番号・都道府県・住所1・住所2・住所3の変更（オンライン確認済み・簡易書留確認済み）と、氏名・フリガナ・生年月日の変更（オンライン確認済みだけ）：`src/Eccube/Resource/template/admin/Customer/edit.twig` 36〜64行目
- 管理画面のパスワードは最小12・最大32文字：`src/Eccube/Form/Type/Admin/CustomerType.php` 131〜151行目、`app/config/eccube/packages/eccube.yaml` 109行目（設計書 M08-04 識別ID 23・24 の最大文字数32と一致）
- 会員の状態（仮会員・本会員）は、開発環境の設定で「仮会員」「本会員」の2つ（DBダンプ 2026-09-07）。0207 M08-04 の項目表に会員の状態の項目が無いが、新実装の編集フォームには状態の項目がある（`scenario_list.md` の食い違い）

## まとめた水準

- 本人確認に使わない項目（B3）：電話番号・FAX・会社名・メールマガジン配信フラグ・ショップ用メモなどを1つにまとめた。0207 M08-04 現行仕様「本人確認ステータスの自動降格」の表に、これらは入っておらず、どれを変えても流れ・確認ダイアログ・期待値が変わらないため
- 住所の項目（B1）：国・郵便番号・海外用郵便番号・都道府県・住所1・住所2・住所3は、同じ確認ダイアログ・同じ結果なので1水準
