# UMB-02 仮会員がメールのURLを開いて本会員になり、ログインした状態になる

| 項目 | 内容 |
|---|---|
| 利用者 | お客様（仮会員）→ メール → （スマレジ。USM-12）→ 店舗チーム（管理画面で会員を確かめる） |
| 目的 | 仮会員が、仮会員登録完了メールの本登録のURLを開いて本会員になり、本登録完了画面が出て、会員登録完了メールが届き、その会員でログインした状態になる。マイページに会員番号とバーコードが出る。同じURLをもう一度開くと「完了済みです。」が出る |
| 種類 | 正常（代表＝URLが正しい）＋ L3の3件（組み合わせ表は無い） |
| マトリクスの行 | なし（URLの状態は1つずつ独立で、効き合う因子が無いのでマトリクスは作らない） |
| もとのシナリオ | なし |

## 前提

- 共通の決まり：`../L4を流すときの共通の決まり.md` を先に読む（試験データの名前にシナリオIDを付ける・共有の設定は元に戻す・バッチの起動・店舗の読み替えなど）
- システムの外で済んでいること：なし
- 起点の会員：UMB-01 のT01の終点（仮会員機能が有効で、仮会員になり、仮会員登録完了メールが届いたところ）。このシナリオ専用に、UMB-01 の手順1〜5を、メールアドレス `umb02-t01@example.test`・お名前（名）「会員UMB02」で流して作る（UMB-01 の入力値のうち、メールアドレスと名だけを替える）。L3のR1〜R3用に、同じ手順でもう2人（`umb02-r2@example.test`・`umb02-r3@example.test`）を仮会員にしておく
- 用意するデータ（試験用の値。設計書の値ではない）
  - 店舗チームの担当者：管理画面の会員管理を使えるアカウント
  - スマレジは試験環境を使う（本会員になるとスマレジの会員が作られる。作られ方・失敗は USM-12。ここでは会員番号が付くことだけ見る）
  - 手順の前に控える値：メール受け口の `umb02-t01@example.test` の件数（仮会員登録完了メール1通）、管理画面の会員一覧で見た会員種別（「仮会員」）
- 画面の名前・文言は新実装の表示で書く

## L3で変わるところ（組み合わせ表は無い。1つずつ別のテストにする）

手順の番号は上の「操作の流れと期待値」。

| 行 | 条件 | 変わるところ |
|---|---|---|
| R1 | URLの秘密キーの文字が英数字以外（URLは手で作る。仮会員は `umb02-r2@example.test` を使ってよい） | 手順1の代わりに、ブラウザのアドレス欄に、本登録のURLの秘密キー（英数字の並び）の部分を英数字以外の文字（例：`abc_123`）に替えたURLを入力して開く。「アクセスできません」の画面が出て、本会員にはならない（会員種別は「仮会員」のまま。ログイン状態にもならない）。画面の説明文は、設計書が「お探しのページはアクセスができない状況にあるか、移動もしくは削除された可能性があります。」（F06-02 共通エラー画面）、新実装が「有効期限が切れているか、無効なURLです。」で違う。期待値は設計書の文言とし、新実装の文言が出たら不合格として記録する。「トップページへ」でトップが開く |
| R2 | 仮会員が見つからない（秘密キーが英数字だが、どの仮会員のものでもない） | 手順1の代わりに、秘密キーを英数字の別の値（例：`zzzz0000`）にしたURLを開く。「完了済みです。」「既に会員登録が完了されております。」が出る（0306 本会員登録：秘密キーで未本会員を取得できないときの表示）。会員は作られず、ログイン状態にもならない |
| R3 | 未ログインで入荷お知らせを申し込んだ画面の戻り先が残っている | 手順の前：ログアウトした状態で、UMB-08 の用意した「在庫0の公開商品」の商品詳細を開き、「入荷通知」を押す（ログインを促す案内「入荷通知を依頼する場合ログインしてください」が出る）。続けて同じブラウザで、ログイン画面の「会員情報登録」から `umb02-r3@example.test` で仮会員登録し（UMB-01 の手順1〜4）、メールの本登録のURLを開く（手順1）。本登録完了画面は出ず、入荷お知らせを申し込んだ商品詳細の画面が開く（0306 本会員登録 現行仕様「完了後の遷移先」）。会員は本会員になり、ログインした状態（ヘッダーに保有ポイントが出る）。戻り先は消えるので、手順5と同じように同じURLを開き直すと「完了済みです。」が出る |
