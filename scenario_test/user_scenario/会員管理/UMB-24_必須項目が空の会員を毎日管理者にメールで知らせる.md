# UMB-24 毎日4:05のバッチが、必須項目が空の会員を管理者にメールで知らせる

| 項目 | 内容 |
|---|---|
| 利用者 | バッチ（毎日4:05。試験では手で起動する）→ 管理者（メール） |
| 目的 | 退会者を除く会員のうち、必須の項目（国・都道府県・氏名の姓と名・電話番号の3つの欄・メールアドレス・住所1・住所2・住所3・郵便番号）が1つでも空の会員がいれば、管理者に、会員IDと各項目の値の一覧（空の項目は「null」）のメールが届く。いなければ何も送らない。バッチは通知だけで、会員の情報を直さない |
| 種類 | 正常（組み合わせ表は作らない。代表1本＋L3の表の行）＋例外（退会者・仮会員・該当なし） |
| マトリクスの行 | 組み合わせ表は無い（空の項目は1つずつ独立。`scenario_list.md` の L3 欄）。以下の行は「表外の具体例」 |
| もとのシナリオ | なし（今のシナリオに対応が無い。0408 B08-04 から起こした） |

## 前提

- 共通の決まり：`../L4を流すときの共通の決まり.md` を先に読む（試験データの名前にシナリオIDを付ける・共有の設定は元に戻す・バッチの起動・店舗の読み替えなど）
- バッチは毎日4:05に動く設計（0408 B08-04）だが、時刻は待たず、手で起動する（起動のしかたは根拠の欄）。バッチは環境の中の対象の会員を全部処理する。共有の開発環境には、日本の会員のほとんどが住所3を空で登録していて、ほかの試験の会員も一緒に一覧に載る。合否はこの試験の会員の行（会員ID・値）が一覧に載るか載らないかで付け、一覧の総数・環境の件数は記録にする
- 共有の開発環境の設定を一時的に変える（管理者の宛先）。共通の決まりどおり、流す前に今の値を確かめて控え、必要なときだけ変え、終わったら元の値に戻して、戻ったことを設定の画面で確かめる（手順6）
  - 設定＞店舗設定＞追加システム設定の「必須項目が空欄である会員送信メールアドレス」（初期データの値は `it_common@hareruyamtg.com`。設計書も同じ）。空のときは管理者へのメールは送られない。設定済みでも、試験の受け口で読めない宛先のときは、試験用のアドレス `umb24-admin@example.test` に替える。試験の受け口で読める宛先のときは変えない
- 用意するデータ（試験用の値。設計書の値ではない）
  - 会員（行ごとに1人、この試験専用。本会員「会員管理試験 空欄R01 UMB-24」〜「空欄R11 UMB-24」、メールアドレス `umb24-r01@example.test`〜`umb24-r11@example.test`）。R10は住所1を空にする会員（R10a：「空欄R10a UMB-24」、`umb24-r10a@example.test`）と、住所2を空にする会員（R10b：「空欄R10b UMB-24」、`umb24-r10b@example.test`）の2人を用意する（R10の `umb24-r10@example.test` は使わない）。フロントで会員登録して作る（UMB-01・UMB-02）。R01は住所3を入れないで登録する（日本の会員は住所3が空でも登録できる）
  - 空の項目の用意：R02〜R11（R10a・R10bを含む。R11は郵便番号）は、行の条件の項目だけを空にした会員を、この試験で作った会員に限り、開発環境で書き換えて用意する（国・姓・電話番号・メールアドレス・住所1・住所2・郵便番号は、画面の操作では空にできない）。住所3は R01 のほかの行では、必ず値を入れておく（住所3の空が重ならないように、R01 以外は住所3に試験用の値を入れる）。書き換えの対象は試験で作った会員だけで、ほかの人の会員は書き換えない
  - 店舗チームの担当者：管理画面の会員一覧・追加システム設定を使える。運用の担当者（バッチを起動できる）
  - 手順の前に控える値：各会員の会員ID（会員一覧で確かめる）、管理者の受け口の件数、追加システム設定の今の値
- 画面の名前・文言は新実装の表示で書く

## 操作の流れと期待値

| # | 操作する人と操作 | 期待値（画面で見えること） |
|---|---|---|
| 1 | 店舗チーム：設定＞店舗設定＞追加システム設定を開き、「必須項目が空欄である会員送信メールアドレス」の今の値を控える。読めない宛先のときは `umb24-admin@example.test` に替えて保存する | 今の値が控えられる。替えたときは保存の完了の表示が出て、開き直すと替えた値になっている |
