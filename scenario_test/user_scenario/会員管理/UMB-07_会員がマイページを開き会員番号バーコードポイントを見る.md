# UMB-07 会員がマイページを開き、会員番号・バーコード・ポイントを見る

| 項目 | 内容 |
|---|---|
| 利用者 | お客様（会員。本店のサイト）→（店頭のレジ。システムの外） |
| 目的 | ログインした会員がマイページを開き、機能メニュー、会員番号、バーコード、保有ポイント、期限の近いポイントが出る。バーコードは5分のタイマーで、0になると「コードの有効期限が切れました。」と「再表示する」に変わり、押すとまた5分間出る |
| 種類 | 正常（代表の1本）＋ L3の4件（組み合わせ表は無い） |
| マトリクスの行 | なし（変わる因子が無いのでマトリクスは作らない） |
| もとのシナリオ | なし |

店頭でバーコードを読み取り、会員を特定してスマレジの取引が EC の購入履歴・ポイントに入る部分は、会員管理もスマレジ連携（USM-01 は取引の取り込み以降を扱う）も扱っておらず、どのシナリオにも無い抜け（`scenario_list.md` の食い違いに記録済み）。このシナリオはバーコードの表示までを確かめる。通知の表示はフェーズ2で対象外。

## 前提

- 共通の決まり：`../L4を流すときの共通の決まり.md` を先に読む（試験データの名前にシナリオIDを付ける・共有の設定は元に戻す・バッチの起動・店舗の読み替えなど）
- システムの外で済んでいること：なし
- 用意するデータ（試験用の値。設計書の値ではない）
  - 会員：お名前「試験 会員UMB07」、メールアドレス `umb07-t01@example.test`、パスワード「Umb07Test-2026」の本会員。UMB-01 の手順1〜7と UMB-02 の手順1〜2で、この試験専用に作る。スマレジの会員番号が付いていること（付かないときは USM-12 の手順で原因を確かめ、記録する）
  - 保有ポイント：管理画面で付与して作る（下の準備1・2）。合計500 pt。うち300 pt は発行から100日前（有効期限は発行日の183日後で、あと83日）、200 pt は今日付け
  - 店舗チームの担当者：管理画面の会員管理（会員編集・ポイント管理）を使えるアカウント
  - 手順の前に控える値：会員の保有ポイント（準備のあと500 pt）
- 画面の名前・文言は新実装の表示で書く。設計書の名前と違うときは「（設計書：…）」を添える

## L3で変わるところ（組み合わせ表は無い。1つずつ別のテストにする）
