# UMB-18 店舗チームが選んだ会員にメールを一括送信し、会員ごとの配信履歴で確かめる

| 項目 | 内容 |
|---|---|
| 利用者 | 店舗チーム（管理画面の会員一覧・メール一括送信）→ メール（会員）→ 店舗チーム（メール配信履歴） |
| 目的 | 店舗チームが会員検索で会員をチェックして、メール一括送信を押す。件名（設計書の名前は「タイトル」）と本文を入れて確認→送信すると、選んだ会員1人につき1通が同じ件名・本文で届き、完了画面が出る。各会員のメール配信履歴に、件名・本文・処理日が残り、テンプレートで絞り込め、件名を押すと件名と本文がポップアップで出る。テンプレートを使わない通知メールは「テンプレート無し」と出る |
| 種類 | 正常（組み合わせ表は作らない。代表1本＋L3の表の行）＋例外（会員を選ばずに押す・確認画面で戻る） |
| マトリクスの行 | 組み合わせ表は無い（因子が無い。`scenario_list.md` の L3 欄）。以下の行は「表外の具体例」 |
| もとのシナリオ | なし（今のシナリオに対応が無い） |

## 前提

- 共通の決まり：`../L4を流すときの共通の決まり.md` を先に読む（試験データの名前にシナリオIDを付ける・共有の設定は元に戻す・バッチの起動・店舗の読み替えなど）
- 用意するデータ（試験用の値。設計書の値ではない）
  - 会員3人（フロントで会員登録して本会員にする。UMB-01・UMB-02 の手順。メールの受け口で読める）：本会員「会員管理試験 一括A UMB-18」（`umb18-a@example.test`）・「一括B UMB-18」（`umb18-b@example.test`）・「一括C UMB-18」（`umb18-c@example.test`、送らない会員）。名前に「UMB18」を含める（検索で絞るため）
  - 送るメール（試験用の文）：件名「シナリオ試験の一括メール UMB-18」、本文「UMB-18 のお知らせです。（試験用）」（本文は2行にする。1行目と2行目）
  - 店舗チームの担当者：会員管理の会員一覧・メール一括送信・メール配信履歴を使える
  - 手順の前に控える値：A・B・Cの受け口の件数、A・Bのメール配信履歴の件数
- 画面の名前・文言は新実装の表示で書く（設計書の「タイトル」は新実装では「件名」、「送信内容を確認」ボタンは同名）

## 操作の流れと期待値

| # | 操作する人と操作 | 期待値（画面で見えること） |
|---|---|---|
| 1 | 店舗チーム：管理画面の会員管理＞会員一覧で、フリーワード「UMB18」で検索し、A・Bの行にチェックを入れる。「その他」から「メール一括送信」を押す | 検索結果に3件（A・B・C）が出る。メール一括送信の画面が開き、件名と本文の入力欄と「送信内容を確認」のボタンが出る |
| 2 | 店舗チーム：件名と本文を入れて「送信内容を確認」を押す | 確認の画面が出る。「メール内容」に入力した件名と本文（改行つき）が出る。「配信対象者」に、会員IDの昇順で、A・Bの2人（会員ID・お名前。お名前は姓と名を空白1個でつないだ値。お名前は会員編集へのリンク）だけが出る。「戻る」「メール送信」のボタンが出る |
| 3 | 店舗チーム：「戻る」を押し、そのあともう一度「送信内容を確認」を押す | 入力画面に戻り、入力した件名と本文のまま表示される（入力は消えない）。もう一度確認の画面に進める |
| 4 | 店舗チーム：確認の画面で「メール送信」を押す | 完了の画面に進み、「メール送信完了しました」が出る（送った件数・失敗した件数・宛先の一覧は出ない）。「会員一覧」のリンクが出る |
| 5 | お客様（会員A・B・C）：それぞれのメールアドレスの受け口を開く | AとBに、それぞれ1通が届く。件名は「シナリオ試験の一括メール UMB-18」、本文は入力した2行そのまま（ヘッダ・フッタの付加や、会員ごとの差し込みは無い）。Cには届かない（A・Bに届いたことを確かめたうえで判定する）。差出人の表示名は店名 |
| 6 | 店舗チーム：「会員一覧」のリンクで会員一覧に戻り、フリーワード「UMB18」で検索し直して、Aの行の「メール履歴」のアイコンを押す | 「メール配信履歴」の画面が開く。「テンプレートで絞り込む」（初期は「すべてのメールを表示する」）と、処理日（yyyy/mm/dd）・通知メール・件名の列が出る。今回の送信の行が1件出て、処理日は今日、通知メールは「テンプレート無し」、件名は「シナリオ試験の一括メール UMB-18」 |
| 7 | 店舗チーム：件名のリンクを押す | ポップアップが開き、件名と、送った本文が出る。「閉じる」で閉じる |
| 8 | 店舗チーム：Cの会員のメール配信履歴を開く | 今回の送信の行が出ない（Cには送っていない）。Bの履歴には手順6と同じ行が1件出る |

## 終わったあとに確かめること

| 確かめる場所 | 期待値 |
|---|---|
| 会員の受け口 | A・Bに1通ずつ（重複して届かない）。Cは増えない |
| メール配信履歴 | A・Bに1件ずつ増える。Cは増えない。履歴の件名・本文は送ったとおり |
| 会員そのもの | 変わらない（会員の状態・氏名・本人確認ステータスなどは更新されない） |
| 店舗の送信元アドレスへの写し | 新実装は写し（宛先とは別の控え）を店舗の送信元アドレスにも送る。読める受け口があれば、1通届くことを記録する（合否は会員宛のメールで付ける） |

## L3で変わるところ（組み合わせ表の他の行・例外）

手順の番号は上の「操作の流れと期待値」。1回ずつ流す。

| 行 | 条件 | 変わるところ（期待値） |
|---|---|---|
| B01 | 会員を選ばずに「メール一括送信」を押す | 手順1：どの会員にもチェックを入れずに、「その他」から「メール一括送信」を押す。ダイアログ「チェックボックスが選択されていません」が出て、会員一覧に留まる。メール一括送信の画面には進まない |
| B02 | 確認画面で戻る | 代表の手順3のとおり（入力した件名と本文が維持される） |
| B03 | 履歴をテンプレートで絞り込む | 前の準備：Aに、UMB-19 の手順でテンプレート「【通販/日】白紙テンプレ(アカウント用)」の手動メールを1通送っておく。手順6：Aの履歴に2件（一括の分は「テンプレート無し」、手動の分は通知メール欄に件名「【晴れる屋】お問い合わせについて」）出る。「テンプレートで絞り込む」でそのテンプレートを選ぶと、選んだ時点で（ボタンを押さなくても）絞り込まれ、手動の1件だけが出て、選択が絞り込み欄に残る。「すべてのメールを表示する」に戻すと2件に戻る |
| B04 | 件名のポップアップ | 代表の手順7のとおり（B03の手動の行でも、件名と本文が出る） |
| B05 | 存在しない会員の履歴 | 手順6：履歴の画面のアドレスの会員IDを存在しない番号に替えて開く。ページが見つからない扱い（404）になり、一覧も絞り込み欄も出ない（画面の名前は問わない） |
| B06 | 送信の結果（成功・失敗の件数） | 設計書の現行仕様のとおり、完了画面には出ない（件数を期待値にしない）。一致する会員のいないIDで中断する・同じIDを重ねると重ねた回数だけ送る、という動きは、画面の通常の操作では作れないので、この試験に入れない（実施不可（流せない）） |

例外：このシナリオに例外の差し込み表は無い（組み合わせ表が無い）。B01・B05 が例外にあたる。
