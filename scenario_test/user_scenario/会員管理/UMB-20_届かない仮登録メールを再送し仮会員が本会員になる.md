# UMB-20 届かない仮登録メールを店舗チームが再送し、仮会員が本会員になる

| 項目 | 内容 |
|---|---|
| 利用者 | 店舗チーム（管理画面の会員検索）→ メール → お客様（UMB-02） |
| 目的 | 仮登録のメールが届かないと連絡を受けて、店舗チームが会員検索の一覧で、仮会員の「仮会員メール再送」を選ぶ。確認（「仮登録メールを再送してもよろしいですか？」）でOKとすると、その仮会員だけに仮会員登録のメール（本登録のURL入り）が再送され、再送完了のメッセージが出て会員一覧に戻る。仮会員がそのURLで本会員になれる（UMB-02）。会員のデータは変わらず、メール配信履歴に1件残る |
| 種類 | 正常（組み合わせ表は作らない。代表1本＋L3の表の行）＋例外（存在しない・削除済みの会員） |
| マトリクスの行 | 組み合わせ表は無い（因子が無い。`scenario_list.md` の L3 欄）。以下の行は「表外の具体例」 |
| もとのシナリオ | なし（今のシナリオに対応が無い） |

## 前提

- 共通の決まり：`../L4を流すときの共通の決まり.md` を先に読む（試験データの名前にシナリオIDを付ける・共有の設定は元に戻す・バッチの起動・店舗の読み替えなど）
- 用意するデータ（試験用の値。設計書の値ではない）
  - 仮会員X：「会員管理試験 再送X UMB-20」（メールアドレス `umb20-x@example.test`）。フロントで会員登録し（UMB-01）、仮登録のメールのURLは開かないで仮会員のまま残す。受け口に届いた最初の仮登録メールは、届かなかったものとして扱い、読まないでおく（件数だけ控える）
  - 仮会員Z：「会員管理試験 再送Z UMB-20」（`umb20-z@example.test`）。Xと同じ手順で作り、再送しない（再送が「その仮会員だけ」に届くことを確かめるための会員）
  - 本会員Y：「会員管理試験 再送Y UMB-20」（`umb20-y@example.test`）。本会員のまま（再送の操作が出ないことを確かめる）
  - 開発環境では仮会員機能が全店舗で有効（設定の確認は UMB-01）。本登録のメールのURLは、流す前に、開発環境のドメインになっているか確かめる。本番のドメインに決め打ちされているときは、URLの道筋の部分だけを開発環境のアドレスに替えて開く（記録する）
  - 店舗チームの担当者：会員管理の会員一覧を使える
  - 手順の前に控える値：X・Y・Zの受け口の件数、Xのメール配信履歴の件数
- 画面の名前・文言は新実装の表示で書く

## 操作の流れと期待値

| # | 操作する人と操作 | 期待値（画面で見えること） |
|---|---|---|
| 1 | 店舗チーム：管理画面の会員管理＞会員一覧で、フリーワード「UMB20」で検索し、Xの行の操作メニューを開く | 3件（X・Y・Z）が出る。Xの行の操作メニューに「編集」「削除」「メール通知」「仮会員メール再送」が出る。Yの行の操作メニューには「仮会員メール再送」が出ない（仮会員の行にだけ出る） |
| 2 | 店舗チーム：Xの行の「仮会員メール再送」を押す | モーダルが開き、「仮会員メールを再送します。」「仮登録メールを再送してもよろしいですか？」と、「キャンセル」「送信」のボタンが出る |
| 3 | 店舗チーム：「キャンセル」を押す | モーダルが閉じ、会員一覧のまま。メールは送られない（Xの受け口は増えない） |
| 4 | 店舗チーム：もう一度「仮会員メール再送」を押し、「送信」を押す | 会員一覧に戻り、「メールを送信しました」が出る（設計書は「再送完了メッセージ」。文言は設計書に定めが無く、新実装の文言を期待値にする） |
| 5 | お客様（仮会員X）：受け口を開く | 件名「【晴れる屋】仮会員登録が完了しました」のメールが1通増える。本文は「（姓）　（名）　様」で始まり、本会員登録を促す文（「現在は仮登録の状態となっております。」「本会員登録を完了するには下記URLにアクセスしてください。」）と、「URL：」の下に本登録用のURLが入っている。YとZの受け口は増えない（Zに届かないことは、Xに届いたのを見てから判定する） |
| 6 | お客様（仮会員X）：メールの本登録用のURLを開く | UMB-02 の本登録の手順どおり、本会員になってログインした状態になる（本会員登録完了の画面。「会員登録が完了しました」のメールが届く）。外部（スマレジ）の見え方は記録だけにする |
| 7 | 店舗チーム：会員一覧でフリーワード「UMB20」を検索し直し、Xの会員種別・氏名・メールアドレスと、Xのメール配信履歴を見る | Xは「本会員」になり、氏名・メールアドレス・電話番号などは再送の前と同じ。Xの「メール履歴」に、手順4の再送の1件（処理日は今日、通知メール欄は「【晴れる屋】仮会員登録が完了しました」、件名欄も同じ）が出る。Zは仮会員のまま、履歴は増えていない |

## 終わったあとに確かめること

| 確かめる場所 | 期待値 |
|---|---|
| X・Y・Zの受け口 | Xだけに再送の1通（本登録後の登録完了の1通は別）。Y・Zは増えない |
| 会員のデータ | 再送そのものでは、氏名・メールアドレス・会員の状態（仮会員）は変わらない（本会員になるのは手順6の本登録による） |
| メール配信履歴 | 再送の分が1件。送った件名・本文を件名のリンクで確かめられる |
| 店舗の送信元アドレスへの写し | 新実装は写し（控え）を店舗の送信元アドレスにも送る。読める受け口があれば記録する（合否はXへのメールで付ける） |

## L3で変わるところ（組み合わせ表の他の行・例外）

手順の番号は上の「操作の流れと期待値」。1回ずつ流す。

| 行 | 条件 | 変わるところ（期待値） |
|---|---|---|
| R01 | 仮会員の行にだけ「仮会員メール再送」が出る | 手順1のとおり（Yの行に出ない） |
| R02 | 英語で登録した仮会員にも日本語のテンプレートで送る | 前の準備：フロントを英語表示にして会員登録し、仮会員W（`umb20-w@example.test`）を作る。手順4：Wの行から再送する。手順5：Wに届くメールは、英語ではなく日本語のテンプレート（件名「【晴れる屋】仮会員登録が完了しました」）で送られる（再送は日本語のテンプレートだけを使う） |
| R03 | 存在しない会員への再送 | 手順4：会員一覧を開いたまま、別の画面でその会員（例 Z）を削除（UMB-15 の削除）してから、先に開いてあった一覧のZの行から再送を押す。ページが見つからない扱い（404）になり、メールは送られない（画面の名前は問わない）。なお会員を指定せずにアドレスだけ替える操作は、確認用の値が付くため作れず、実施不可（流せない） |
| R04 | 退会済みの会員への再送 | 手順4：会員一覧を開いたまま、別のブラウザで、その会員（仮会員は退会操作が無いので、本登録して本会員にした会員V）がマイページから退会（UMB-13）してから、先に開いてあった一覧のVの行を使う。ただし一覧の行に「仮会員メール再送」が出るのは仮会員の行だけなので、本会員を退会させて再送を押す操作は作れない。この行は「実施不可（流せない）」として記録する（退会済みは一覧に出ない） |

例外：このシナリオに例外の差し込み表は無い（組み合わせ表が無い）。R03・R04 が例外にあたる。顧客分析タグの登録はフェーズ2で対象外。
