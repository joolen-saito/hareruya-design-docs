# UMB-17 店舗チームが管理画面で会員の配送先を追加・変更・削除する

| 項目 | 内容 |
|---|---|
| 利用者 | 店舗チーム（管理画面の会員編集・配送先編集）→ お客様（マイページの配送先で見え方を確かめる） |
| 目的 | 店舗チームが会員編集の「お届け先住所」から配送先を追加・変更・削除する。追加・変更すると「保存しました」が出て配送先の編集画面が開き、削除すると「削除しました」が出て会員編集に戻る。管理画面の配送先の内容が、マイページの配送先（UMB-12）と同じになる。既定の配送先（会員情報住所）には編集・削除の操作が出ない |
| 種類 | 正常（組み合わせ表は作らない。代表1本＋L3の表の行）＋例外（配送先名称が空・削除できない） |
| マトリクスの行 | 組み合わせ表は無い（国と操作は入力欄の違いにとどまる。`scenario_list.md` の L3 欄）。以下の行は「表外の具体例」 |
| もとのシナリオ | なし（今のシナリオに対応が無い） |

## 前提

- 共通の決まり：`../L4を流すときの共通の決まり.md` を先に読む（試験データの名前にシナリオIDを付ける・共有の設定は元に戻す・バッチの起動・店舗の読み替えなど）
- 用意するデータ（試験用の値。設計書の値ではない）
  - 会員：本会員「会員管理試験 配送先 UMB-17」（メールアドレス `umb17-member@example.test`）。フロントで会員登録して本会員にする（UMB-01・UMB-02）。お届け先は会員情報の住所（既定）だけの状態で始める
  - 追加する配送先（試験用の値）：配送先名称「シナリオ試験の配送先 UMB-17」、国「日本」、配送先氏名（姓「会員管理試験」・名「配送先 UMB17」）、電話番号（試験用の番号）、郵便番号・都道府県・住所1・住所2（日本の住所。例 `160-0023`・東京都・新宿区西新宿・試験用の番地）。海外用の行（L3 の D02）：国「日本以外」（例 アメリカ合衆国）、海外用郵便番号、住所3
  - 店舗チームの担当者：会員管理の会員一覧・会員編集を使える
  - 手順の前に控える値：会員の配送先の件数（会員編集の「お届け先住所」とマイページの配送先の一覧の件数）
- 画面の名前・文言は新実装の表示で書く。設計書の「配送先」と、新実装の画面の名前「お届け先登録」「お届け先情報」「お届け先住所」は同じ機能（手順は新実装の名前で書く）

## 操作の流れと期待値

| # | 操作する人と操作 | 期待値（画面で見えること） |
|---|---|---|
| 1 | 店舗チーム：管理画面の会員管理＞会員一覧で、この試験の会員を検索し、お名前のリンクから会員編集を開く。「お届け先住所」の欄を開く | 「お届け先住所」の表に、会員情報の住所（既定。名称の列に「会員情報住所」）が1件出る。既定の配送先の行には、編集・削除の操作が出ない。「お届け先住所を追加」のボタンが出る |
| 2 | 店舗チーム：「お届け先住所を追加」を押し、配送先名称・国・氏名・電話番号・郵便番号・都道府県・住所1・住所2を入れて「登録」を押す | 「お届け先登録」の画面（見出し「お届け先情報」）が開き、入力欄に必須の印が出る。登録すると「保存しました」が出て、同じ配送先の編集画面が開く（配送先一覧には戻らない）。入れた値が欄に残っている |
| 3 | 店舗チーム：「会員登録」のボタン（会員編集に戻る）を押し、「お届け先住所」を見る | 表が2件になり、追加した配送先が、名称・氏名・氏名カナ・住所・電話番号・会社名の列に入力どおりに出る。追加した配送先の行には編集と削除の操作が出る |
| 4 | お客様（会員）：マイページの「配送先の新規登録・変更」を開く | 配送先の一覧に、会員情報の住所と、管理画面で追加した配送先（名称「シナリオ試験の配送先 UMB-17」）が出る。氏名・住所・電話番号が管理画面の値と同じ（UMB-12 のマイページの配送先と同じ内容） |
| 5 | 店舗チーム：会員編集の追加した配送先の名称（リンク）を押し、住所1と電話番号を別の値に変えて「登録」を押す | 「保存しました」が出て、同じ配送先の編集画面が開き、変えた値が出る。会員編集の表とマイページの一覧も変えた値になる |
| 6 | 店舗チーム：会員編集で、追加した配送先の行の削除の操作を押す | 確認「この操作はあとから取り消すことができません。「シナリオ試験の配送先 UMB-17」を削除してよろしいですか？」が出る。キャンセルで閉じ、配送先は残る |
| 7 | 店舗チーム：もう一度削除の操作を押し、確認で「削除」を押す | 「削除しました」が出て、会員編集の画面に戻る。表は会員情報の住所の1件に戻る。マイページの一覧からも消える |

## 終わったあとに確かめること

| 確かめる場所 | 期待値 |
|---|---|
| 会員編集の「お届け先住所」 | 会員情報の住所（既定）の1件だけ。既定の配送先の内容（氏名・住所・電話番号）は変わらない |
| マイページの配送先の一覧 | 管理画面と同じ内容（手順4・5・7で確かめた） |
| 会員の氏名・住所（会員情報） | 変わらない（配送先の追加・変更・削除は会員情報を書き換えない） |

## L3で変わるところ（組み合わせ表の他の行・例外）

手順の番号は上の「操作の流れと期待値」。1回ずつ流す。

| 行 | 条件 | 変わるところ（期待値） |
|---|---|---|
| D01 | 国が日本（代表） | 代表の行 |
| D02 | 国が日本以外（海外用の郵便番号・住所3） | 手順2：国を「日本以外」（例 アメリカ合衆国）にすると、海外用郵便番号が入力でき（国が日本以外のとき必須）、郵便番号1・2は入力しない。都道府県は日本の都道府県の選択肢のままだが、国が日本以外のときは入力不可（入力した場合の扱いは、新実装の画面で確かめて記録する）。住所3も入れる。「保存しました」。手順3：一覧の郵便番号の欄は海外用郵便番号、国名が出る（都道府県が海外のときは、郵便番号と都道府県の代わりに海外用郵便番号と国名を表示する）。手順4：マイページの一覧も同じ |
| D03 | 変更（手順5） | 代表のとおり |
| D04 | 削除（手順6・7） | 代表のとおり |
| D05 | 配送先名称が空（必須） | 手順2：配送先名称を空にして「登録」を押す。保存されず、配送先名称の欄に必須のエラーが出て、入力した内容は残る。名称を入れ直すと保存できる |
| D06 | 「郵便番号から自動入力」（管理画面には残る機能） | 手順2：郵便番号1・2に `160`・`0023` を入れて「郵便番号から自動入力」を押すと、都道府県と住所1が、郵便番号に対応する値で自動で入る（住所の候補は外部の郵便番号の参照を使うので、入る値は記録にし、合否は都道府県と住所1に値が入ることで付ける） |
| D07 | 関連するデータがあって削除できない（「関連するデータがあるため「（名称）」を削除できませんでした」） | 新実装は、配送先を削除する印を付ける更新だけで、関連データで止まる作りに見えない。画面の操作では起こせないので、この行は「実施不可（流せない）」として記録する |
| D08 | お届け先の登録数が上限（20件）に達している | 手順1：「お届け先住所を追加」のボタンが出ず、「お届け先登録の上限の20件に達しています。お届け先を入力したい場合は、削除か変更を行ってください。」が出る（会員の配送先を20件にするには、手順2を繰り返して19件追加する。時間がかかるので、この行は最後に流す） |

例外：このシナリオに例外の差し込み表は無い（組み合わせ表が無い）。D05・D07・D08 が例外にあたる。
