# UMB-06 再発行メールのURLを24時間を超えて開くと、使えない

| 項目 | 内容 |
|---|---|
| 利用者 | お客様（パスワード再発行のメールを受けた本会員）→ メール |
| 目的 | パスワード再発行のメールのURLを、発行から24時間を超えてから開くと、再設定画面の代わりにエラー画面が出て、パスワードは変わらない。もう一度再発行を申し込むと、新しいメールで設定できる |
| 種類 | 正常（代表の1本）＋ L3の3件（組み合わせ表は無い） |
| マトリクスの行 | なし（因子が無いのでマトリクスは作らない） |
| もとのシナリオ | なし |

## 前提

- 共通の決まり：`../L4を流すときの共通の決まり.md` を先に読む（試験データの名前にシナリオIDを付ける・共有の設定は元に戻す・バッチの起動・店舗の読み替えなど）
- システムの外で済んでいること：なし
- 起点：UMB-05 の代表の行の手順1〜3の終点（再発行を申し込み、再設定のURL入りのメールが届いたところ）。この試験専用に、メールアドレス `umb06-t01@example.test` の本会員（パスワード「Umb06Test-2026」。UMB-01 の手順1〜7とUMB-02 の手順1〜2で作る）で、UMB-05 の手順1〜3を流す。メールのURLを控える。R1・R2・R3用に、それぞれ別の本会員（`umb06-r1@example.test`・`umb06-r2@example.test`・`umb06-r3@example.test`）で同じ手順を流す
- 用意するデータ（試験用の値。設計書の値ではない）
  - 期限切れの用意：時計を進める方法は用意せず、24時間待たない。試験で作った会員に限り、開発環境で、会員のリセットキーの有効期限の日時を書き換えてよい（共通の決まり。他の会員は触らない）。「24時間を超えた」状態は、有効期限を今より1時間前の日時にして作る（発行から25時間たった状態に当たる）
  - 手順の前に控える値：書き換える前のリセットキーの有効期限の日時（発行日時の24時間後）
- 期限は24時間（開発環境の設定）。ちょうど24時間は有効、24時間を超えると期限切れ。ちょうど24時間の境目は実時間では確かめられないので、R3で「期限の1分前は開ける」ことだけ確かめる
- 画面の名前・文言は新実装の表示で書く
