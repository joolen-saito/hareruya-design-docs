# UMB-22 店頭PC用アカウントが、許可されたIPからだけ使え、制限された画面を開けない

| 項目 | 内容 |
|---|---|
| 利用者 | 店舗のお客様（店頭PCのアカウント：店内アカウント・支店用店内アカウント）。比べるために通常会員。許可IPは店舗チームが管理画面で設定する |
| 目的 | 店頭PCのアカウントでログインしたとき、許可されたIPアドレスではログインでき、許可されていないIPアドレスではログインした直後にログアウトされる。ログインできたとき、会員向けの画面（会員情報変更・購入履歴・ポイント履歴・お問い合わせなど）は「店頭用アカウントでは利用できません。」とだけ出て開けない。本店の注文は店内アカウントで可、支店用店内アカウントでは不可（支店用店内アカウントは本店の注文だけが止まり、22画面は制限されない）。通常会員にはどれも制限がかからない |
| 種類 | 正常（組み合わせ表の11行）＋例外6件 |
| マトリクスの行 | `matrix_UMB-22/matrix.md` のT01（店内アカウント・許可されたIPアドレス・制限される画面）。T02〜T11 は「L3で変わるところ」 |
| もとのシナリオ | なし（今のシナリオに対応が無い）。注文を確定して店頭モニターに番号を出す部分は UOR-06（F06-25 店頭注文呼び出し番号表示も UOR-06・UOR-08・UOR-11） |

## 前提

- 共通の決まり：`../L4を流すときの共通の決まり.md` を先に読む（試験データの名前にシナリオIDを付ける・共有の設定は元に戻す・バッチの起動・店舗の読み替えなど）

- 用意するデータ（試験用の値。設計書の値ではない）
  - 会員3人（フロントで会員登録して本会員にする。UMB-01・UMB-02）：「会員管理試験 店内 UMB-22」（`umb22-otc@example.test`）・「会員管理試験 支店用 UMB-22」（`umb22-branch@example.test`）・「会員管理試験 通常 UMB-22」（`umb22-normal@example.test`）。管理画面の会員編集の「顧客グループ」を、順に「店内アカウント」「支店用店内アカウント」「通常会員」にして登録する（顧客グループの名前は環境の設定。区分は店内アカウント＝店内注文専用アカウント、支店用店内アカウント＝支店店内注文専用アカウントのチェックで見分ける。UMB-21）
  - 許可IP：管理画面の設定＞基本情報設定＞基本設定の「ネットワーク設定」の「店頭用アカウントIPアドレス( , 区切り)」（設計書の名前は「モール設定＞店舗登録」の店舗ごとのIPアドレス）。この欄は本店（店舗ID 1）の設定。流す前に今の値を控える。サーバーから見える、流す端末のIPアドレス（以下「端末のIP」）は、開発環境の管理者に確かめる（ネットワークの構成によって、端末の手元のIPと違う）

  - 注文手続き（C3）で使う商品：本店で販売中で在庫のある商品を1つ（開発環境の既存の商品。カートに入れて注文手続きの画面を開くだけで、注文は確定しない）
  - 店舗チームの担当者：管理画面の会員編集と、設定＞基本情報設定＞基本設定を使える
  - 手順の前に控える値：「店頭用アカウントIPアドレス」の今の値（元の値）
- 画面の名前・文言は新実装の表示で書く。許可IPの設定の場所は、設計書は「管理画面＞モール設定＞店舗登録」、新実装は「設定＞基本情報設定＞基本設定」の「ネットワーク設定」（手順は新実装の表示で書く）
