# UMB-10 ポイントが増減したあと、管理画面とマイページのポイント履歴が取引と一致して見える

| 項目 | 内容 |
|---|---|
| 利用者 | 店舗チーム（管理画面。ポイントの付与と履歴の確認）／お客様（マイページ。購入でポイントを使い、履歴を見る） |
| 目的 | ポイントの付与・購入での使用・注文キャンセルでの戻し・期限切れの失効のあとで、店舗チームが会員のポイント履歴を、会員がマイページのポイント履歴を開き、各行が元の取引から手で数えた値と一致する（増減量。マイページはプラスに「+」。発行日。有効期限は発行日の183日後。注文によるものは注文番号）。保有ポイントは選手情報の残高で、履歴の合計とは別に表示する。マイページに現在のポイントと次に消失するポイントが出る。履歴が無いときは「ポイント履歴はありません。」 |
| 種類 | 正常（代表の1本）＋ L3の5件（組み合わせ表は無い） |
| マトリクスの行 | なし（表示件数・ページ・言語は互いに独立で、効き合う因子が無いのでマトリクスは作らない） |
| もとのシナリオ | なし。ポイントの付与・失効の処理は USM-15・USM-19・USM-20、付与・使用・戻し・失効の値の確かめは UPT-01・UPT-05・UPT-07・UPT-08・UPT-10、レジの取引は UPT-03。このシナリオは、それらの取引でできた履歴の見え方を突き合わせる |

## 前提

- 共通の決まり：`../L4を流すときの共通の決まり.md` を先に読む（試験データの名前にシナリオIDを付ける・共有の設定は元に戻す・バッチの起動・店舗の読み替えなど）
- システムの外で済んでいること：なし
- 用意するデータ（試験用の値。設計書の値ではない）
  - 会員：お名前「試験 会員UMB10」、メールアドレス `umb10-t01@example.test`、パスワード「Umb10Test-2026」の本会員。UMB-01 の手順1〜7と UMB-02 の手順1〜2で、この試験専用に作る。ポイントの履歴が1行も無い（保有ポイント0）。お届け先は国内の住所（UMB-01 の入力値）
  - 購入する商品：グッズ「シナリオ試験ポイントグッズ UMB10」（商品コード `UMB10-G01`・販売価格 2,000円（税込）・公開・在庫5・販売制限なし。グッズ商品CSVで登録し、在庫変更CSV登録と承認で在庫を入れる。UPR-04・UPR-05 の手順と同じ）
  - 店舗チームの担当者：管理画面の会員管理（会員編集・ポイント管理）を使えるアカウントと、通販の受注を確かめられるアカウント
  - 手順の前に控える値：会員の保有ポイント（0）、履歴の行数（0）
- 管理画面の「ポイント履歴追加（キャンペーン、特別対応）」の備考は自由な文字ではなく選択式（「キャンペーン」「特別対応」。`src/Eccube/Form/Type/Admin/CustomerPointType.php`）。付与の行は、備考の文字ではなく、増減量と発行日で見分ける
- ポイントの数え方（この試験の元の取引）：下の準備で、次の5つの取引を作る。保有ポイントは、取引eのあとが 1,000 ＋ 500 ＋ 400 − 200 ＝ 1,700、取引fのあとが 1,500
  - 取引a：付与 +1,000（発行日は今日から10日前、備考「キャンペーン」）
  - 取引b：付与 +500（発行日は今日、備考「特別対応」）
  - 取引c：付与 +400（発行日は今日から200日前＝期限（発行日の183日後）を過ぎている。備考「キャンペーン」）。失効の元になる
  - 取引d：通販の購入でのポイント使用 −200（注文番号が付く。この注文は残す）。ほかに、使用 −300 の注文（注文d2）を作って、あとで取り消す
  - 取引e（戻し）：注文d2のキャンセル。使用300が戻り、注文d2の履歴が消える（UPT-07）
  - 取引f（失効）：ポイント失効のバッチ。失効額 ＝ 残高 − 期限内の付与の累計 ＝ 1,700 − (1,000 ＋ 500) ＝ 200。「有効期限切れによる失効」の行（−200）が残る（UPT-08）
- 画面の名前・文言は新実装の表示で書く。設計書の名前と違うときは「（設計書：…）」を添える
- 失効のバッチは環境の中の対象の会員を全部処理する。合否はこの試験の会員の値（残高・履歴）で付け、ほかの会員の件数は記録にする。バッチは毎日0:00に動く設計だが、時刻は待たず手で起動する（起動のしかたは根拠の欄）。失効の対象はスマレジの会員番号を持つ会員（UMB-02 で本会員になった会員は持つ）。取引cの発行日を過去にできないときは、試験で作った会員の履歴に限り、開発環境で発行日を200日前に書き換えて用意してよい（共通の決まり）
