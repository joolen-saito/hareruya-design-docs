## 閉じたときに残ったもの

### 判断待ち（依頼者の決定待ち。期待値は決めていない）
- スムーズ店頭受取（本店・店頭受取を含む）でポイントを使えるか・受取後に付与されるか（ポイントの判断待ち2、UPT-04。UXB-06・UOR-01・UOR-03）。UXB-16 は新実装に合わせて全額ポイントの行を作らない（禁則X2・X6・X34・X46）
- 入金を確認した受注を入金済みにする担当者と時点、代金引換の受け取り拒否・代金の回収の反映、返品の物の流れ（通販の判断待ち）
- 受注一覧の一括変更でのキャンセル・出荷完了と付与・履歴の扱い、受注情報編集のキャンセルでの使用ポイントの二重戻しの疑い（ポイントの UPT-07。未検証）
- ポイントグランター端末の再送で二重付与になるか（外部連携 UEX-13）。印刷失敗の再印刷が設計書の意図か、店頭PCも印刷対象か（UEX-14）
- ついで買い・店頭購入の受注時原価（粗利益高）、集計バッチの時刻、Redash の状態名の読み替え
- 公開ステータスの数値の向き（設計書と新実装で逆）、セールバナー差し替え（業務フロー11 1-5）がトップバナー管理かどうか
- 振替・貸出・返却のスマレジ反映、0501 方式2・3 の新実装での有無、記事とデッキの紐付けを区間にするか、統合仕入れと自動入庫の二重入庫

### どこにも無い抜け
- 入金済みを通らない受注の入金日が設計書の基準日表に書かれていない（新実装の動作を期待値にして記録）
- 店頭でマイページのバーコードを読んだスマレジ取引が会員の購入履歴に入る部分（GAP-01）、予約商品の通し（GAP-02）、棚卸・廃棄・振替等の通し（GAP-03）、店頭系の期限前のお客様依頼による取り消し（GAP-06）

### ほかのフォルダへの影響（他フォルダは書き換えていない）
- MTGバイヤー UMG-09 の取り込み先の判断待ちは、仕入れ業務 USH-02 の在庫変更CSVの列と一部同じ。MTGバイヤー側にも相互参照を足せる
- 業務周期 UCY-10 は仕入れ業務の取り込み時刻の論点と同じ（相互参照を足せる）。業務周期の表に載っていない ID は作業一覧の1節のとおり
- 通販の判断待ち8・9、ポイント UPT-07 の例外E1 と、業務横断 UXB-02・UXB-03 の参照が対になっている
