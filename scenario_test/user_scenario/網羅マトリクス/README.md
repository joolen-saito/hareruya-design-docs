# 網羅マトリクス（業務フローの工程×シナリオ、業務条件×シナリオ）

依頼者の指示（2026-11-05）「マトリクスで整理して抜け漏れがないか確認できるようにしたい」。軸は「業務フローの工程×シナリオ」と「業務条件×シナリオ」、形式は Excel。

- 見るもの：`網羅マトリクス.xlsx`（シート：集計／工程×シナリオ／業務条件×シナリオ／抜けの一覧）。横軸はシナリオのフォルダ（業務ごと＋横断・通しシナリオ）、セルは通るシナリオID。判定の色：通る＝緑、抜け＝赤、判断待ち＝黄、それ以外（見出し・システムの外・範囲外・適用外・他業務・他層）＝灰
- 抜けは示すだけで、シナリオは足していない

## ファイル（業務ごとのフォルダ）

## 作り直し
```bash
cd scenario_test/user_scenario
python3 -I tools/build_coverage_matrix.py steps   # 業務フローが変わったとき
python3 -I tools/build_coverage_matrix.py check   # ゲート
uv run --with openpyxl python -I tools/build_coverage_matrix.py xlsx 網羅マトリクス/網羅マトリクス.xlsx
```
ゲート：steps が業務フローと一致／対応のシナリオIDが実在／引用がそのシナリオ自身のテキスト（scenario_list.md のそのIDの行、そのIDの L4、matrix_<ID>/、通しシナリオはフォルダ全体。業務フローパターンの網羅・対象外・判断待ち・食い違い・関係の節は数えない）にそのままある／対象の工程・値にだけ対応を付ける。

## 業務パターン×シナリオの〇表（2026-11-09）

依頼者の要望「数量・金額・決済・返品・キャンセルなどのパターンを列にして、シナリオごとに〇を付け、抜け漏れがパッとわかるようにしたい」に応えた表。

- ファイル：`パターン×シナリオ.xlsx`（業務ごとに1シート＋「見方」）。道具は `tools/build_pattern_matrix.py`。
- 行＝シナリオ（その業務のシナリオ。下は通しシナリオなど他フォルダのシナリオ（フォルダの列に書く。色は付けない））。列＝ factors.tsv の値を 分類 → 業務条件 → 値 の3段で並べる。最下行が〇の数で、0 の列（赤）が抜け。
- 〇の元：`cond_map.tsv`（値ごとに1本）＋`pattern_map.tsv`（各シナリオが通す値を全部）。どちらも引用はそのシナリオ自身の本文から（ほかのシナリオの行の文は使えない。〇表ではこれを機械で止める）。
- 列の分類：`pattern_cols.tsv`（条件ID→分類）。分類の並びは道具の ORDER（数量・金額・決済・配送…）。
- 網羅マトリクス.xlsx も pattern_map の〇を「通る」に数える。
- 2026-11-09 に「根拠のある軸を足す」（依頼者決定）で、数量の単数・複数、金額の境目、取り消し・返品の全部／一部などの軸を足した（factors.tsv の備考「2026-11-09 パターン軸の追加」）。codex 3巡で根拠を確かめ（36→12→4件）、Excel 由来の部分に根拠が無い軸・根拠の文から分け方が言えない軸を消した。記録は `パターン軸レビュー/`。
- 結果：抜け16列（通販2・店頭受取1・商品登録3・在庫管理5・ネット買取1・仕入れ1・デッキ登録3）。
- 2026-11-09 依頼者「足す」→15列を各シナリオの L3 に手順と期待値で足し、商品登録・編集 A3-3（カード詳細が2件以上見つかる）は新実装で作れないので適用外にした。各業務の `review/パターン抜け反映_2026-11-09.md`（差分 .diff）。codex 2巡（2件→NONE）。抜けは0列。

- 〇の元：各業務の `level_map.tsv`（組み合わせ表の水準→値）・`exc_map.tsv`（例外→値）・`test_map.tsv`（シナリオで決まっている値、または特定の1本）。「シナリオのマトリクス」の値は道具が自動で対応を付ける。
