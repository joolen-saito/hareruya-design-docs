## 〇の付け方

- level_map：USM-01 の組み合わせ表の水準（購入パターン・店舗・持ち込む件数）。UOR-02 の購入パターンの水準（パターン2・3、複数受注）。UOR-10 の返品の水準（取消／打消し、②／③）。
- exc_map：USM-01 の例外 E1〜E3 → D4。
- test_map：UOR-03（パターン1）・通しシナリオ UTH-05/T28〜T30（パターン1）・UOR-07 の4行（会員／非会員×ついで買い＝パターン4〜7）・USM-02（①）。

## 抜け

〇の無い列（対象の値）は無い（抜け0）。ただし次のとおり、1本しか通していない値がある（テストは足していない）。

- D4-1・D4-2・D4-3、D6-1 は各1本（例外1本ずつ、USM-02 が1本）。
- D6-1 は USM-02 だけ。USM-02 は組み合わせ表の無い1本のシナリオなので、返品の取引の種類（取消／打消し：D5）を USM-02 側で分けて通していない（D5 の〇は店頭受取の UOR-10 から）。レジだけの購入の返品を、取消と打消しの両方で通すテストは今のところ無い。
- USM-02 の「会員／非会員（非会員はポイントが動かない）」は列にしていない。0505 に返品時の会員・非会員の扱いを分ける記述が見つからず、設計書の表から言えないため（USM-02 のシナリオ一覧の L3 の記述だけが根拠）。

## 列にしなかったもの（根拠が無い、または分かれ目でない）

- 支払方法：スマレジで取り込んだ取引の支払方法はすべて「店頭支払」（0505）。1つしか無いので分かれ目ではない。
- USM-04〜23（在庫・商品・部門・会員・ポイントの連携）は店舗販売の購入パターンではなく、別の業務（在庫・商品登録・会員・ポイント）の連携なのでこの表の列にしていない。USM-05（取引の取りこぼし）も購入パターンの違いではなく、再連携のしくみの確認。

## 同時に直したもの（店頭受取受注管理 D6-5）

店頭受取受注管理の factors.tsv の D6-5「店頭PC購入（会員・非会員、ついで買いの有無）」は1つの値に4つの場合が混ざっていたので、0505 のパターン4〜7に合わせて4つに分けた：D6-5=パターン4（会員・ついで買いなし）、D6-6=パターン5（会員・ついで買いあり）、D6-7=パターン6（非会員・ついで買いなし）、D6-8=パターン7（非会員・ついで買いあり）。〇は UOR-07 の組み合わせ表の4行（会員×ついで買い）と USM-01/T07・T09・T10・T13 から付け直した。cond_map・pattern_map の D6-5 も4つに分けた。

## 重なりと出し分けの見直し（2026-11-10）

同日の依頼者決定（重なりはまとめる／出し分けは外す・止まるものは例外で残す）の基準で、この表の列を見直した。結果は変更なし。

- D1 購入パターン：パターンごとに受注・在庫・ポイントの動きが違う（業務が分かれる）。残す
- D2 店舗（本店／支店）：支店は別システム（EC-CUBE（支店））で受け取り、スムーズ店頭受取を選べない。店舗が購入パターンの範囲と処理を分けるので残す
- D3 持ち込む受注の数：複数件は統合した新規受注を作る（業務が分かれる）。残す
- D4 取り込みの異常：取り込みが止まる・失敗する例外。残す
- D5 返品の取引の種類（取消／打消し）：受注の探し方（取引ID／打消元取引ID）の違いで、結果はどちらも受注キャンセル。迷ったが、設計書 0505 が別の処理として書く（Excel由来）ので残した。外すなら店頭受取受注管理 D11-1・D11-2 と matrix_UOR-10 の因子Aも同時に直す
- D6 在庫の戻し方：返品する取引に何が入っていたか（①②③）で在庫の戻し方が変わる。購入パターン D1 と似た分けだが、返品の処理の条件なので残した
