# ネット買取の申込から入庫までの通し（UTH-02）

IPA「高信頼化ソフトウェアのための開発手法ガイドブック」(2010) の表6-9〜6-11と同じ手順で作る。FL表は `fl_table.tsv`、禁則表は `prohibitions.tsv`、例外の差し込み表は `exceptions.tsv`、マトリクスは `matrix.md`・`matrix.tsv`（`tools/build_matrix.py` が作る）。1行が、お客様の申込から入庫（またはカードの返送）まで通す1回の試験になる。

## 範囲

- 業務フロー14（ネット買取）の全パターン（1 申込から郵送まで・2 カード受け取りから振込まで・3 簡易書留による本人確認・4 カード仕入れ業務）を、1行で「始まりから終わりまで」通す。ユニサーチの買取商品検索 → 申込 → 郵送（システムの外）→ オンライン本人確認 → 商品到着 → MTGバイヤーでの査定と査定金額の挿入 → 査定内容メール → お客様の承諾 → 簡易書留（必要なとき）→ 振込依頼 → 振込完了 → 入庫（買取商品一覧CSVを仕入れ業務へ渡すところまで）。全部の明細を売却しない行は、着払いの返送で終わる
- 待ちの状態は切らずに区間の境目として通す（郵送・商品到着待ち、お客様の承諾待ち、簡易書留の受領待ち、経理の振込待ち、15時のバッチ待ち）。境目で確かめる状態は `../scenario_list.md` の区間の表に書いた
- 各区間の細部（カートに入れる画面、振込口座・口座種別・箱数・適格請求書、価格下限未満のカードの一括選択、個別入力商品の登録の細部、MTGバイヤーの査定表の操作）は、今のシナリオ UNK-01〜14・UMG-02〜10 とそのマトリクスに任せる。このマトリクスは「つなぎ目で値が引き継がれ、利用者に見えるか」と「パターンで流れが変わるところ」を因子にした
- 振込の受け取りは銀行振込だけ。ポイントで受け取る経路は、業務フロー14・設計書・新実装のどれにも無いので因子にしない（`../scenario_list.md` の確かめたこと）
- 振込失敗・戻しリスト・身分証有効期限切れ通知バッチは、業務フロー14に無い（設計書0206・0408から起こした）ので、行にせず例外で差し込む（戻しリストは行に入れない）

## 因子の選び方

| 因子 | 業務フローのパターンとの対応 |
|---|---|
| A 商品の選び方 | パターン1（1-1）。えらんで買取とまとめて買取の別が、査定（2-6 まとめて買取の欄）と承諾の明細に引き継がれる。パック・サプライは査定で管理画面から足す |
| B 商品の探し方（ユニサーチ） | パターン1（1-1）。買取側の検索条件（買取価格1円以上・NM・高額商品コードなし・予約商品でない）と並び順が入り口で違う |
| C 本人確認の進め方 | パターン1（1-5〜1-15）。端末（PC／スマートフォン）、身分証の種類（マイナンバーカードだけ裏面が無い）、問題あり→再申請、今回は申請しない（確認済みの会員が前に済ませている場合と、未確認のままの場合。D で決まる） |
| D 本人確認の状態と査定金額 | パターン3（3-2）。確認済みまたは1万円未満は簡易書留が要らない。未確認で1万円以上は簡易書留（3-3〜3-8） |
| E 承諾の仕方 | パターン2（2-8〜2-11）。お客様の承諾／自動承諾（管理画面で査定内容承諾にする）。査定承諾メールの有無が違う |
| F 売却の内訳 | パターン2（2-12・2-18・2-19）。全部売却／一部売却しない／全部売却しない（振込せず返送） |
| G 査定の進め方 | パターン2（2-4〜2-6）。中断・再開の有無 |
| H 個別入力商品 | パターン2（2-16）。振込完了のあとの状態が入庫待ち／未登録在庫ありに分かれる |
| I 入庫の仕方 | パターン2（2-17）・パターン4（4-1）。15時のバッチ／手動の入庫済み／入庫しない |
| J 職業・生年月日 | パターン1（1-2）。申込画面に入力欄が出る／出ない。職業と生年月日は欄ごとに「未登録の場合に表示する」ので、登録済み・両方未登録・職業だけ未登録・生年月日だけ未登録の4水準 |

## 禁則について

- 全部売却しない（F3）と未確認・1万円以上（D4）の組は、業務フロー3-2の判定が売却する明細の有無を条件にしないので、禁則にせず行に入れた（判断待ち。`../scenario_list.md`）
- 全部売却しない（F3）と個別入力商品あり（H2）は禁則：売却しない個別入力商品は実在庫を登録できず、入庫待ちに進まない

## 代表の行について

- L4 の手順は、最も標準的な水準の組（T29：まとめて買取あり・カテゴリから探す・スマートフォンでマイナンバーカード・確認済みで1万円以上・お客様が承諾・全部売却・個別入力商品なし・15時のバッチ・職業と生年月日は登録済み）で書いた。割り付けの結果にこの組が無かったので、例外E09（査定内容連絡済みでない買取は承諾できない）の差し込み元の条件にこの組の全水準を書いて、行を1行足した（matrix.md に「例外用の行を足した」と出る）。E09 自体は E1 だけが要る条件だが、代表の行に差し込むために全水準を書いている
