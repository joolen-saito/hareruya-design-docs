# UTH-02 ネット買取：カードを探して申し込み、本人確認・査定・承諾・振込を経て入庫され、仕入れ業務へ渡る

| 項目 | 内容 |
|---|---|
| 利用者 | 会員のお客様（国内）→ 店舗チームの担当者（会員管理・ネット買取管理）→ MTGバイヤーの買取担当者（所属店舗が「トーナメントセンター 東京」）→ 経理（システムの外）→ バッチ（15時）→ メール |
| 目的 | 売りたいカードをユニサーチの買取検索で探して申し込み、郵送し、オンライン本人確認を済ませ、MTGバイヤーで査定された金額が買取に入り、お客様が承諾して、振込を経て、買取したカードが本店の在庫に入る。買取番号・明細・金額・本人確認の状態が、つなぎ目の画面・メール・CSVで同じ値で引き継がれる |
| 種類 | 正常（通し） |
| マトリクスの行 | `matrix_UTH-02/matrix.md` のT29（えらんで買取（カード）とまとめて買取を一緒に・カテゴリから探す・スマートフォンでマイナンバーカードを撮影して問題なし・オンライン本人確認済みで査定金額1万円以上・お客様がマイページで承諾・全部の明細を売却する・査定を中断しない・個別入力商品なし・15時のバッチで入庫・職業と生年月日は登録済み） |
| もとのシナリオ | SCN-ONLINE-KAITORI-001〜010（ネット買取UNK-01〜UNK-12をつないだもの） |

既存の一覧の各区間は、`ネット買取/` のUNK-01（申込）・UNK-02（本人確認）・UNK-03（査定）・UNK-04（承諾・振込依頼）・UNK-08（振込完了）・UNK-12（実在庫の登録）・UNK-09（入庫）、`MTGバイヤー/` のUMG-01〜UMG-04、`会員管理/` のUMB-16にある。ここは、その区間のつなぎ目で値が引き継がれて、お客様の画面・メール・店舗チームの画面・MTGバイヤーに出ることを通しで確かめる。例外の細部は既存のIDを参照する。

## 前提

- システムの外で済んでいること：買取するカードの現物（お客様の手元にある）。ユニサーチに買取側の商品情報のフィードが送信済み（買取価格・カード状態・高額商品コード・予約フラグ。商品登録からフィード送信までの区間は商品登録の通し）。MTGバイヤーの端末と買取担当者（所属店舗が「トーナメントセンター 東京」）。経理の振込は実際には行わない（振込が済んだ連絡を受けたことにする）
- 用意するデータ（試験用の値。設計書の値ではない）
  - 会員：試験 花子（本会員、メールアドレス `uth-02@example.test`、国内（東京都）の住所を登録済み、職業と生年月日は登録済み、本人確認ステータスは未確認、スマートフォンで撮影できる）
  - 買取するカード：「シナリオ試験カードA」（日本語・NM・買取価格4,000円）を2枚、「シナリオ試験カードB」（日本語・NM・買取価格1,500円）を1枚、まとめて買取（専用商品）に入れるカード数枚（MTGバイヤーで読み取れない個別入力商品は、代表の行では足さない。H2の行で足す）
  - 査定の結果：カードAは4,000円×2、カードBは1,500円×1。えらんで買取だけで9,500円になるので、まとめて買取の分を足して10,000円以上になるようにカードを選ぶ（まとめて買取の査定結果は、別に画面の値を控える）。査定金額合計は10,000円以上（まとめて買取の査定結果を含め、画面の値を控える）（本人確認が必要な買取金額は、開発環境の設定で10,000円）
  - 申込の入力：振込口座＝試験用の口座（銀行名・支店名・普通・口座番号7桁・口座名義）、箱数＝1、買取の承諾方法＝査定結果を確認してから承諾する、適格請求書発行事業者＝いいえ
  - 店舗チームの担当者（管理画面の会員編集・ネット買取管理の権限がある）、MTGバイヤーの買取担当者

- 用意しないもの：振込口座の実在、郵送の実物
