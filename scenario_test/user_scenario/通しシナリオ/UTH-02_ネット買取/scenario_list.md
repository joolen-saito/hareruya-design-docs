# ネット買取（業務フロー14全体）の通しシナリオ：シナリオ一覧（UTH-02）

業務フロー14（ネット買取）のシート全体を、お客様の買取カード検索・申込から、郵送・到着、本人確認、MTGバイヤーでの査定、査定金額の挿入、お客様の承諾と返送、簡易書留、振込、入庫・仕入れ業務へ渡すところまで、1本で通す。今のシナリオ（ネット買取 UNK、MTGバイヤー UMG、在庫管理 UZK、会員管理 UMB、ポイント UPT、スマレジ連携 USM、業務横断 UXB）は消さず、「区間」として参照する。区間の細部（例外・境界）は今のシナリオとそのマトリクスに任せ、通しでは「区間のつなぎ目で値が正しく引き継がれ、お客様と店舗チームに見えるか」と「業務フローのパターン（本人確認の進め方・簡易書留の要否・承諾の仕方・売却の内訳・入庫の仕方）で流れが変わるところ」を確かめる。

待ちの状態（カードの郵送と商品到着、お客様の承諾、簡易書留の受領、経理の振込、15時のバッチ）があっても切らない。待ちは「区間の境目」として書き、そこで確かめる状態を期待値にする。

### 設計書との食い違い（設計書の不足。起票はしない）

今のシナリオ（ネット買取 UNK・MTGバイヤー UMG・業務横断 UXB）に記録済みのものは、結論を変えずに引き継ぐ。ここでは通しで新しく分かったものを先に書く。

- 業務フロー14 2-5 の「査定前」のステータスが、ネット買取の状態（注文・商品到着・査定中…）に無い。業務フロー3-2 の「買取価格が1万以上」の「買取価格」が、査定金額合計か、お客様が承諾した（売却する明細の）金額かを、設計書が書かない。新実装は保存された金額（通常は査定金額合計。承諾後にサプライ品を削除すると承諾金額）で比べる（上の確かめたこと）。売却しない明細を含む買取で、査定金額合計は1万円以上だが承諾金額は1万円未満になる場合の扱いが決まらない
- ユニサーチの高額商品コードの条件が、0305 では高額商品コードの検索条件が「現在仕様確認中」のまま。新実装は「高額商品コードなし」の値を付ける
- 全部の明細を売却しない買取に、簡易書留による本人確認を送るかが決まらない（業務フロー3-2 は承諾メール受領のあとで判定し、3-8 は2-11以降へ戻るが、売却しない買取は振込依頼にならない）
- 業務フロー1-7・1-8 の「本人確認受付通知メール」は、設計書では本人確認申請完了メールの返信先とBccに買取専用メールアドレスを入れる仕様。メールの種類が1つか2つかが業務フローと設計書で読み取れない
- ネット買取のシナリオ（UNK）に記録済み：2-7 の「査定未完了なら連絡済みにできない」が設計書・実装に無い。自動承諾の動きの定義が状態図の矢印だけ。査定承諾メールの記載が0305・0206に無く、自動承諾には出ない。全部売却しないときの買取の状態が無い。キャンセル済みの業務が無い。0601 にネット買取の査定画面の設計書が無い。3-2 の「DBに登録されていないため利用ごとに身分証の提出が必要」と0206の振込依頼済みの条件が合わない。振込依頼済みを経ない状況変更は身分証明書・本人確認の検査を通らない。身分証有効期限切れ通知バッチの設計書内の食い違い（未設定／未確認）と、通知メールの文面が実際の状態と合わない点
- MTGバイヤー（UMG）に記録済み：査定中の受注を別の査定者が開くときの設計書内の食い違い（同じ状態なら成功か、担当者が違えばエラーか）

## 判断待ち

見たが決まらなかったこと。依頼者または設計の確認が要る。

- 買取依頼者の身分証明書の種類を登録しただけで「本人確認の証明がある」と言えるか。新実装の振込依頼済みの検査は、この欄が空でないかだけを見て、証明の画像や書類が提出されているかは見ない。申込・本人確認の処理から、この欄へ自動で書く箇所は見つからない。通しでは、全行で店舗チームが手で選んで保存する手順を置いた（見たもの：0206 買取情報編集(1-19)、新実装のフォームと検査、ネット買取 `scenario_list.md` の判断待ち）
