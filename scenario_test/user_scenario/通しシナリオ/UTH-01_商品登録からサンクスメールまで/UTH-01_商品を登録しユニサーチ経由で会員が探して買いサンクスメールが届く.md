## 前提

- 環境：ユニサーチの接続先が設定されている環境で行う（新実装は、検索の接続先が空だとユニサーチを使わずEC内の検索に切り替える。その環境では手順6の「載る前は出ない」、手順10・11のユニサーチの並び順・案内は成り立たず、公開した商品がEC内の検索で出る）
- システムの外で済んでいること：カードの商品画像をS3へ保存済み。カードが入荷している。ユニサーチ側の設定（検索対象の項目）は済んでいる。フィードの取り込みと索引づくりはユニサーチ側が行う（システムの外）
- 用意するデータ（試験用の値。設計書の値ではない）
  - 登録担当と、在庫の承認者（別の担当者。承認権限があり、登録担当の承認通知先に入る）
  - 会員：試験 花子（メールアドレス `upth01@example.test`、国内（東京都）の住所を登録済み、保有ポイント10,000）。本店と支店で会員は共通
  - 商品：シングルカード「シナリオ試験カードH」（日本語版、状態NM、基準価格・販売価格3,000円、商品の割引率100%、購入グループ「通常商品」、商品名（英）を入れる、カードセット「シナリオ試験セットX」のカテゴリ、商品公開ステータス＝非公開、支店の商品公開ステータス＝非公開）をカード商品CSVに1行書く。入庫は在庫編集画面で3点
  - 比較用の商品：「シナリオ試験カードI」（別のカードセット「シナリオ試験セットY」。セットYのリリース日がセットXより新しい。公開・在庫あり・ユニサーチに反映済み）。並び順を見るために、同じ語「シナリオ試験カード」で2件以上出るようにする
  - 設定：送料無料金額は30,000円（開発環境の値）。2点（6,000円）なので送料無料にならない
- 時間の決まり：この行は非公開で登録するので、手順5で公開にするまでフィードに載らない。手順5〜7は続けて行い、定時のバッチ（毎時15分）が間に入らないようにする（入ると手順6の「載る前」が確かめられない）
- 在庫が承認されるまでは在庫0。登録担当と承認者は別の担当者

### フィードの行で確かめること（手順8）

設計書の期待値は「取得条件」と「フィードTSV」の項目。設計書に無い点（先頭の項目名の行・区切り・在庫の中身）は新実装の事実で、合否は付けず「記録」とする。

| 確かめる項目 | 期待値（設計書・商品マスターの登録値との一致） | 参考（新実装。記録） |
|---|---|---|
| ファイル | TSVをgzに固めたファイルと、そのMD5値を入れたdoneファイルが、指定のディレクトリにできる（0404 実行結果詳細）。出力先のファイルの読み取り・更新・削除の権限が全員にある | gzのMD5値がdoneファイルの中身と同じ。ファイル名は作成日時を含む |
| 行 | 「シナリオ試験カードH」の行がNMの規格の1行だけ（取得条件：販売価格1円以上・公開・NMのみ） | 先頭に項目名の行がある（41項目）。区切りはタブ |
| 商品・商品名・商品名（英） | 商品マスターの商品ID・商品名・商品名（英）と同じ | 商品名にタブ・改行が入らない |
| 言語・価格・カード状態 | 日本語・3,000・NM | 価格は販売価格 |
| 画像URL | 商品画像の1枚目（複数あるときは1枚目）。S3のパス | — |
| カードセット・カードセット名・リリース日 | カードセット「シナリオ試験セットX」のID・名前・リリース日 | リリース日は「YYYY-MM-DDTHH:MM:SSZ」の形 |
| 在庫 | 在庫ありを検索できる値（設計書：在庫数。NM以外の状態の在庫も合計して送る） | 在庫が1以上ある店舗のID（この行は本店）を^Aで区切る。設計書の「在庫数」と違う（食い違い） |
| カテゴリ | 階層をつけて、深い方を先頭に送る。フォーマット＞シリーズ＞カードセットまで（レアリティの階層は送らない） | 階層は\x05、複数カテゴリは\x01で区切る |
| セールフラグ・高額商品コード・予約商品フラグ・支店表示フラグ | 0・空・0・0（セール外・高額でない・予約でない・本店だけ公開） | — |
| 商品コード・規格ID・買取金額・タグ・色・レアリティなど | 商品マスター・カード情報の登録値と同じ。複数の値は^Aで区切る | — |

## 注文確認メール（サンクスメール）で確かめること（手順18）

商品管理から注文確認メールまでのUPM-01と同じ考え方。設計書に件名・本文の定めが無いので、設計書の期待値は「注文と一致する」ことと、設計書に書かれた点だけ。参考は新実装のテンプレートで、合否は付けず「記録」とする。

| 確かめる項目 | 期待値（設計書・注文との一致） | 参考（新実装のテンプレート。記録） |
|---|---|---|
| 届く通数 | 注文完了メールが1通。コンビニ決済の行は、支払方法に関するメールが別で送られるので、あわせて確かめる（下の注） | — |
| 宛先 | 会員のメールアドレス（設計書に定めが無い：記録） | 受注のメールアドレス宛て。店舗の代表アドレスにも控え |
| 件名 | 設計書に定めが無い（記録）。管理画面のメール設定で変えられる | 「[店名] 晴れる屋をご利用いただきありがとうございます。」 |
| ご注文番号 | 手順17の購入完了画面の8桁のご注文番号と同じ（メールの受注番号は8桁のゼロ埋め） | 【ご注文番号】 |
| 商品・数量・金額 | 「シナリオ試験カードH」・数量2・単価3,000円・合計6,000円（手順14〜16の値と一致） | 【ご注文明細】に「価格：3,000円 x 数量：2 = 合計：6,000円」の形 |
| お買上金額 | 商品金額合計6,000円・送料・手数料0円・ポイント使用・注文金額合計（税込）0円が、手順16の値と一致する | 【お買上金額】 |
| お支払方法 | 「全額ポイント支払い」（手順16の選択。支払いなしのテンプレート）。テンプレートは支払方法ごとに違う | 【お支払方法】。ヘッダーの案内（文言は設計書に無い：記録） |

| 言語 | 日本語（日本語のサイトで買い、国内のお届け先） | 日本語のテンプレート |
| ヘッダー・フッター | 管理画面の自動送信メール・メール設定で設定した本文上部・本文下部が入る（文言は設計書に無い：記録） | 支払方法ごとの案内、店舗の連絡先 |

注：コンビニ決済（O3）の行では、業務フロー16の1-5「コンビニ決済の場合は支払方法に関するメールが別で送付される」とあるため、注文完了メールのほかに支払方法に関するメール（支払の案内）が届くかを確かめる。通数・件名・本文は設計書に定めが無く、送り元（EC・SPLINKS）も設計書から決まらないので、届いたメールの送り元・件名・内容を記録する。
