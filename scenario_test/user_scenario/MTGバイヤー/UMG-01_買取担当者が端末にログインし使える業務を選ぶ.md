# UMG-01 買取担当者が買取端末にログインし、使える業務（店頭買取・ネット買取・入庫モード）を選ぶ

| 項目 | 内容 |
|---|---|
| 利用者 | 買取担当者（買取端末。外部の Windows アプリ。試験端末を人が操作する）→ 運用担当（EC管理画面で控えと確かめ） |
| 目的 | 買取担当者が買取端末にログインIDとパスワードを入れてログインし、業務選択画面を出す。店頭買取・入庫モードはどの店舗の担当者も選べる。ネット買取は、ログインの応答の所属店舗名が「トーナメントセンター 東京」のときだけ選べる。ログインに失敗したときは、端末が文言を出してログインできない。ログインしただけでは EC の買取・メンバー・店舗の値は変わらない |
| 種類 | 正常（1本）＋L3の具体例（組み合わせ表は無い。1つずつ別のテストにする） |
| マトリクスの行 | なし（組み合わせ表は無い）。L3 は `scenario_list.md` の UMG-01 の L3 欄の項目を1つずつ別のテストにした |
| もとのシナリオ | なし（業務フロー06 1-2・14 2-4 の入口）。設計書 0601 O01-01「入口」、0506 A06-01 買取アプリ用ログイン、機能設計書 O01-02「入口」 |

端末の画面の見え方は外部システム（買取端末アプリ）の表示なので記録だけにする。合否は EC 側の値（管理画面のメンバー管理・基本設定の店名・店頭買取管理の買取一覧）で付ける（2026-11-24 決定）。手順の期待値は「（端末。記録）」と「（EC。合否）」に分けて書く。

## 前提

- 共通の決まり：`../L4を流すときの共通の決まり.md` を先に読む（試験データの名前にシナリオIDを付ける・共有の設定は元に戻す・バッチの起動・店舗の読み替えなど）
- システムの外で済んでいること：買取端末（試験端末）が開発環境の EC につながる設定になっていて、人が操作できる。端末の外部サービスへの接続（カードの読み取り機器・印刷）はこのシナリオでは使わない
- 店舗：開発環境では店舗を新しく作らない。本店は店舗ID 1（画面によって「Hareruya」「トーナメントセンター 東京」と出る）。「本店以外の店舗」の行は、流す前に既存の店舗から1つ選び、店舗ID と画面に出る名前を控えて、以降の「支店」を読み替える
- 用意するデータ（試験用の値。設計書の値ではない）
  - 買取担当者X：メンバー管理で所属店舗＝本店・稼働。ログインIDとパスワードを控える
  - 買取担当者Y：所属店舗＝上で選んだ支店・稼働。ログインIDとパスワードを控える
  - 本店の店名：管理画面の設定＞基本情報設定＞基本設定の「店名」。開発環境のダンプ（2026-09-07）の値は「Hareruya」で、機能設計書 O01-02 が決める文字列「トーナメントセンター 東京」と一致しない。ネット買取を選べる行（L3 の「店名が一致する」）を流すときだけ、共通の決まりの「共有の開発環境の設定を一時的に変えるとき」のとおり、流す前に今の値を控え、「トーナメントセンター 東京」に変え、終わったら控えた値に戻して、戻ったことを同じ画面で確かめる（2026-11-09 決着：必要なら店舗名を管理画面で用意して端末側で別途確認する）。支店の店名は変えない
  - 手順の前に控える値：メンバー管理の担当者X・Yの所属店舗と稼働、基本設定の店名、店頭買取管理＞買取一覧の検索結果の件数（買取店舗＝本店）
- 画面の名前・文言は新実装の表示で書く。端末の文言は機能設計書 O01-01〜O01-03 と 0506 A06-01 の表示メッセージ

## L3で変わるところ（組み合わせ表は無い。1つずつ別のテストにする）

手順の番号は上の「操作の流れと期待値」。金額・数量は無い。ログインの失敗は、成功した操作のあとではなくログイン画面から1回ずつ流す。

| 行 | 条件 | 変わるところ |
|---|---|---|
| L1 | 店名が「トーナメントセンター 東京」と一致する（担当者X。本店の店名を一時的に変える） | 手順1：流す前の店名を控える。店名を「トーナメントセンター 東京」に変えて保存し、設定の画面で変わったことを確かめる。手順2：（端末。記録）業務選択画面で「ネット買取」も選べる（灰色でない）。（EC。合否）店名の文字列が「トーナメントセンター 東京」で、端末の判定と整合。手順3の代わりに「ネット買取」を選ぶと、お客様選択画面（ネット買取）が出る（受注の一覧は UMG-02）。終わったら店名を控えた値に戻し、基本設定で戻ったことを確かめる。出し分けは端末アプリの動きで、EC が確かめるのは店名の値まで（2026-11-09 決着：他層） |
| L2 | 本店以外の店舗の担当者Y | 手順2：（端末。記録）業務選択画面が出る。ネット買取は、支店の店名が「トーナメントセンター 東京」と一致しないので灰色（店頭買取・入庫モードは選べる）。手順3：（EC。合否）端末の一覧に出る受注は、買取店舗＝その支店の受注だけ（UMG-02）。本店の受注は出ない |
| L3 | ログインIDとパスワードを空にしてログインする | （端末。記録）「ログインIDまたはパスワードが入力されていません」が出てログインできない（0506 A06-01-MSG-001）。（EC。合否）終わったあとの確かめるものが、手順1の控えのまま |
| L4 | ログインIDが無い（メンバー管理に無いIDを入れる） | （端末。記録）「ログインIDまたはパスワードが正しくありません」が出てログインできない（0506 A06-01-MSG-002）。（EC。合否）EC の値は控えのまま。メンバー管理に、入れたIDのメンバーが作られていない |
| L5 | パスワードが違う（担当者Xの正しいログインIDに、違うパスワードを入れる） | （端末。記録）「ログインIDまたはパスワードが正しくありません」が出てログインできない（0506 A06-01-MSG-003。ログインIDが無いときと同じ文言）。（EC。合否）EC の値は控えのまま |
| L6 | 所属店舗が無い管理者（店舗名・住所が空） | メンバー登録の所属店舗は必須の欄で、画面の操作では所属店舗の無いメンバーを作れない。この行の条件は作れないので実施不可（流せない）。結合テストへは回さない |
| L7 | ネット買取が選べない店舗の担当者が、ネット買取を使おうとする | L2 のとおり。灰色のネット買取は押せない。押せないこと（端末の表示）は記録だけで、EC には何も送られない（EC。合否：ネット買取管理の買取一覧の値は控えのまま） |

## 記録（判断待ちではない。合否は設計書の期待値で付け、新実装の表示は記録する）

- 端末が応答の所属店舗名を画面に出すかは設計書に無い。出るときは記録する
