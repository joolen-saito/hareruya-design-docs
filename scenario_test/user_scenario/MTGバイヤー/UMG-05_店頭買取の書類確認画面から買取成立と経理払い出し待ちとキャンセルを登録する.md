# UMG-05 店頭買取の書類確認画面から買取成立・経理払い出し待ち・買取キャンセルを登録し、EC に結果が入る

| 項目 | 内容 |
|---|---|
| 利用者 | 店舗チーム（買取端末。試験端末を人が操作する）→ レジ（スマレジ出金。システムの外）→ EC管理画面（確かめ）→ 経理チーム（メールを受け取る） |
| 目的 | お客様が査定結果を承諾したあと、店舗チームが書類確認画面で「買取成立」「経理払い出し待ち」「買取キャンセル」のどれかを登録し、EC の買取に結果が入る。買取成立：買取詳細に端末取引ID（出金コード）・合計金額（10円単位に切り上げ）・明細・ダブルチェック者・査定担当者が出て、登録済みの商品は実在庫（買取価格・小計）になり、個別入力商品が無ければ入庫待ち、有れば未登録在庫ありになる（履歴は買取成立と続く状態の2件）。経理払い出し待ち：経理チームに「店頭買取振込依頼 【査定ID: XXXXX】」のメールが届き、端末取引IDは送られない。買取キャンセル：買取の状況が買取キャンセルになる |
| 種類 | 正常（代表1本＝経理払い出し待ち）＋L3の具体例（組み合わせ表は無い。1つずつ別のテストにする） |
| マトリクスの行 | なし（組み合わせ表は無い）。L3 は `scenario_list.md` の UMG-05 の L3 欄の項目を1つずつ別のテストにした。査定表の作り方は `matrix_UMG-03/` |
| もとのシナリオ | SCN-KAITORI-001・003・004（前段）。業務フロー06 の1-6〜1-9・07 の1-6〜1-9。設計書 0601 O01-01「書類確認」、0506 A06-03 店頭買取情報更新。通しシナリオ UTH-03 の手順13〜21と食い違わないよう、同じ商品・金額で書いた。起点は店頭買取 UKA-01・UKA-03 の終盤 |

端末の画面の見え方（書類確認画面・メッセージ・一覧）は外部システム（買取端末アプリ）の表示なので記録だけにし、合否は EC 側の値（買取一覧・買取詳細・古物台帳入力用CSV・経理チームのメール・商品の在庫）で付ける（2026-11-24 決定）。スマレジのレジ画面も外部サービスなので記録だけにする。期待値は「（端末。記録）」と「（EC。合否）」に分けて書く。

## 前提

- 共通の決まり：`../L4を流すときの共通の決まり.md` を先に読む（試験データの名前にシナリオIDを付ける・共有の設定は元に戻す・バッチの起動・店舗の読み替えなど）
- システムの外で済んでいること：買取端末（試験端末）が使え、店舗チームの担当者のアカウントでログインできる。カードの現物（名前の検索で足すので、読み取り機器は使わない）。お客様の身分証の見本。レジ（スマレジ）の出金は、買取成立の行だけ使う（使えないときは下の「端末取引IDの値」のとおり）。印刷は印刷機を使わず、書類確認画面に合意書・買取証明書が出ることを確かめる
- 店舗：開発環境では店舗を新しく作らない。本店（店舗ID 1。画面によって「Hareruya」「トーナメントセンター 東京」と出る）の担当者で流す
- 用意するデータ（試験用の値。設計書の値ではない）
  - 買取担当者X（本店所属）、ダブルチェック者になる担当者（メンバーIDを控える）。経理チームのメールの受け口：追加システム設定の「査定払い出しの経理部門通知メールアドレス」が、試験で読める受け口になっている（開発環境は設定済み。値はこの文書に書かない）。流す前に値が受け口を指しているか確かめる。指していないときだけ、共通の決まりのとおり控えて変え、終わったら戻して戻ったことを確かめる
  - 商品（登録済み。手順は UKA-04 の手順2〜3と同じ。商品コードは登録時に自動で付く：共通の決まり）：「試験カードP」＝日本語・NM・非Foil、買取価格5,000円・基準価格（販売価格）8,000円。「試験カードQ」＝日本語・HP、買取価格100円・基準価格200円。個別入力の行（K2・K4）の商品：「個別入力カードZ」（商品マスターに無い商品。価格300円・枚数1・基準価格500円・部門は選択欄から1つ）
  - 受注：行ごとに1件ずつ、お客様（非会員「MTGバイヤー試験 太郎」。成年。国＝Japan・職業を選ぶ）の店頭買取査定申込（UKA-01 の手順1〜4・UTH-03 の手順1〜6）。適格請求書発行事業者の行（K9）は、申込で適格請求書発行事業者確認を「はい」にして登録番号を入れる（UTH-03 の L3 と同じ）。端末で UMG-02 の手順2〜4（ログイン・店頭買取・受注を選ぶ・身分証スキャン）まで進めて査定画面を開き、P×2・Q×3を足し（UMG-03）、ダブルチェック者を更新する（UMG-08）
  - 端末取引IDの値（買取成立の行）：スマレジのレジで、買取金額を出金する取引（取引区分が出金）を登録して取引IDを控える（レジの画面の見え方は記録だけ）。レジが使えないときは、試験用の整数（例：900001）を取引IDとして入れる。EC はスマレジの出金取引と突き合わせない（設計書に処理が無い）。端末取引IDは数字だけ入力できる
  - 手順の前に控える値：受注の買取一覧のステータス・買取詳細のステータス変更履歴の行数、商品P・Qの在庫と総原価、経理チームの受け口の件数
- 画面の名前・文言は新実装の表示で書く
