# UMG-09 買取担当者が入庫モードで商品コードと枚数の一覧を作り、在庫登録用のCSVを出す

| 項目 | 内容 |
|---|---|
| 利用者 | 買取担当者（買取端末。カードの読み取りはシステムの外。試験端末を人が操作する）→ 店舗チーム（EC管理画面で商品の値と在庫を確かめ） |
| 目的 | 買取担当者が業務選択画面で入庫モードを選び、カードを足して（読み取り・名前の検索）「CSV形式で出力する」を押す。出力方法（通販/支店システム用・ネット買取用）に応じたファイル名・列のCSVが端末の指定フォルダに出る。CSV の商品コード・商品名・基準価格・買取価格などは、EC の商品の値と一致する。出力すると作業途中のデータが消える。入庫モードは受注にもお客様にもひも付かず、EC の在庫・買取は変わらない |

| マトリクスの行 | `matrix_UMG-09/matrix.md` のT02（出力方法＝通販/支店システム用・所属店舗＝それ以外の店舗・一覧の行＝通常の行だけ・同じ商品の行＝同じ商品が複数行にある）。T01・T03〜T06 と例外E1〜E8は「L3で変わるところ」 |
| もとのシナリオ | なし（業務フローの入庫モードの記述は、07 の仕入作業 2-1・2-4・2-5「通販_支店システム用CSV」の帳票）。機能設計書 O01-03（入庫モード。Excel の設計書が無く、現行ソース（買取端末アプリ）から起こしたもの）。業務フロー07 のその後（打ち込み・価格更新・価格ソート）は通しシナリオ UTH-03 の手順28〜34（システムの外が中心） |

端末の画面の見え方（一覧・メッセージ・フォルダ）と、端末が作る CSV のファイルの形（ファイル名・文字コード・列数・列の並び・引用符）は外部システム（買取端末アプリ）の表示・出力なので記録にとどめる。合否は EC 側の値で付ける：CSV の商品コード・商品名・基準価格・買取価格・状態などが、管理画面の商品の値（手順の前に控える）と一致するか、EC の在庫・買取が変わらないか（2026-11-24 決定）。期待値は「（端末。記録）」と「（EC。合否）」に分けて書く。

## 前提

- 共通の決まり：`../L4を流すときの共通の決まり.md` を先に読む（試験データの名前にシナリオIDを付ける・共有の設定は元に戻す・バッチの起動・店舗の読み替えなど）
- システムの外で済んでいること：買取端末（試験端末）が使え、CSV を保存するフォルダがある。カードの読み取りは、読み取り機器を使わず名前の検索で足す（読み取りは端末の物理操作でシステムの外）。出力した CSV をどのシステムのどの機能へ取り込むかは、アプリでは定められていない（取り込みは対象外：下の記録）
- 店舗：開発環境では店舗を新しく作らない。本店（店舗ID 1。画面によって「Hareruya」「トーナメントセンター 東京」と出る）の担当者で流す。開発環境の本店の店名は「Hareruya」で、所属店舗＝それ以外の店舗の行（T02・T05）はそのまま流せる。所属店舗＝「トーナメントセンター 東京」の行（T01・T04）は、UMG-01 の L1 のとおり、流す前に今の店名を控え、本店の店名を「トーナメントセンター 東京」に変え、終わったら控えた値に戻して戻ったことを基本設定で確かめる（2026-11-09 決着：他層。列の出し分けは端末アプリの動きで、記録だけ）
- 用意するデータ（試験用の値。設計書の値ではない）
  - 買取担当者X（本店所属）
  - 商品（登録済み。手順は UKA-04 の手順2〜3と同じ。商品コードは登録時に自動で付く：共通の決まり。商品画像・買取価格と部門を結び付けておく）：「試験カードP」＝日本語・NM・非Foil、買取価格5,000円・基準価格（販売価格）8,000円。「試験カードQ」＝日本語・HP、買取価格100円・基準価格200円
  - 手順の前に控える値：商品P・Qの商品コード・商品名・基準価格・買取価格・状態・言語・略称タグ・レアリティ（管理画面の商品一覧・商品編集）と在庫、買取一覧（店頭・ネット）の件数、店名
- 画面の名前・文言は新実装の表示で書く
