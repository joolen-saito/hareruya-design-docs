# UMG-08 買取担当者が査定中に、受注のフリーコメントとダブルチェック者を更新する

| 項目 | 内容 |
|---|---|
| 利用者 | 買取担当者（買取端末。試験端末を人が操作する）→ 店舗チーム（EC管理画面で確かめ） |
| 目的 | 買取担当者が査定画面で「コメント更新」またはダブルチェック者の「更新」を押すと、フリーコメントが EC に反映され「フリーコメントを更新しました。」が出る（店頭の買取詳細のフリーコメント・ネットの買取情報編集のメモ）。店頭は、ダブルチェック者が EC に反映され「ダブルチェック者を更新しました。」が出て、買取詳細のダブルチェック者に出る。失敗は「サーバエラー：フリーコメントの登録に失敗しました。」「サーバエラー：ダブルチェック者の登録に失敗しました。」。買取の状態は変わらない |
| 種類 | 正常（代表1本＝店頭）＋L3の具体例（組み合わせ表は無い。1つずつ別のテストにする） |
| マトリクスの行 | なし（組み合わせ表は無い）。L3 は `scenario_list.md` の UMG-08 の L3 欄の項目（店頭／ネット、コメントを空にして更新、ダブルチェック者が空・数値以外・存在しないメンバーID）を1つずつ別のテストにした |
| もとのシナリオ | なし（業務フローの1-3「ダブルチェックの実施」の記録）。設計書 0601 O01-01「お客様情報とフリーコメント・ダブルチェック者」、0506 A06-04（店頭買取情報コメント更新）・A06-16（ダブルチェック者更新）、0507 A07-03（ネット買取受注コメント更新）。通しシナリオ UTH-03 の手順13・21、UKA-01 の手順11と食い違わないよう、同じ操作で書いた |

端末の画面の見え方（メッセージ・欄）は外部システム（買取端末アプリ）の表示なので記録だけにし、合否は EC 側の値（買取詳細のフリーコメント・ダブルチェック者・最終更新者・ステータス変更履歴、買取情報編集のメモ）で付ける（2026-11-24 決定）。期待値は「（端末。記録）」と「（EC。合否）」に分けて書く。

## 前提

- 共通の決まり：`../L4を流すときの共通の決まり.md` を先に読む（試験データの名前にシナリオIDを付ける・共有の設定は元に戻す・バッチの起動・店舗の読み替えなど）
- システムの外で済んでいること：買取端末（試験端末）が使え、端末のネットワーク接続を外してつなぎ直せる。ネットの行は、UMG-01 の L1 のとおり担当者の所属店舗名が「トーナメントセンター 東京」と一致するよう本店の店名を一時的に変え、終わったら戻す
- 店舗：開発環境では店舗を新しく作らない。本店（店舗ID 1。画面によって「Hareruya」「トーナメントセンター 東京」と出る）の担当者で流す
- 用意するデータ（試験用の値。設計書の値ではない）
  - 買取担当者X（本店所属）。もう1人、ダブルチェック者になる担当者Y（メンバー管理に稼働でいる。メンバーIDと画面に出る名前を控える。Xとは別の人）
  - 受注：店頭は、非会員「MTGバイヤー試験 太郎」の店頭買取査定申込（UKA-01 の手順1〜4）を、端末で UMG-02 の手順2〜4まで進めて査定画面を開いたもの（フリーコメントは申込のときのまま。適格請求書発行事業者の申込ではないので空）。ネットは UMG-04 のT02の受注（商品到着）を、査定画面を開いたところまで進めたもの
  - 商品（手順5で使う。UMG-05 と同じ）：「試験カードP」＝日本語・NM・買取価格5,000円・基準価格8,000円、「試験カードQ」＝日本語・HP・買取価格100円・基準価格200円（手順は UKA-04 の手順2〜3）。身分証の見本（自動車運転免許証。両面）
  - 手順の前に控える値：受注の買取詳細のフリーコメント・ダブルチェック者・最終更新者・ステータス変更履歴の行数（ネットは買取情報編集のメモ）
- 画面の名前・文言は新実装の表示で書く。設計書に文言が無く新実装にだけある文言（ダブルチェック者が存在しないときの文言）は、新実装の文言を期待値にする

## L3で変わるところ（組み合わせ表は無い。1つずつ別のテストにする）

手順の番号は上の「操作の流れと期待値」。行ごとに別の受注を使い、流し始めの状態を控える。EC に何も送られない行は、「EC。合否」が手順1の控えのままであることで確かめる。

| 行 | 条件 | 変わるところ |
|---|---|---|
| C1 | 店頭・フリーコメントとダブルチェック者を更新（代表） | 上の手順1〜5 |
| C2 | ネット・フリーコメントを更新 | 起点：ネットの受注（査定画面を開いたところ）。ネットにはダブルチェック者の欄が無い（店頭買取のときだけ出す）。手順3：「身分証コピー済み・確認済み」を入れて「コメント更新」。（端末。記録）「フリーコメントを更新しました。」。（EC。合否）ネット買取管理の買取情報編集のメモ（管理者用メモの欄）が「身分証コピー済み・確認済み」になる。買取状況は「査定中」のまま・履歴の行数は控えのまま。ダブルチェック者の確かめは行わない |
| C3 | コメントを空にして更新 | 手順3のあとで、フリーコメントの欄を空にして「コメント更新」を押す（店頭・ネット）。（端末。記録）「フリーコメントを更新しました。」。（EC。合否）フリーコメント（ネットはメモ）が空になる（空文字は未指定として扱わず、空にして更新する：0506 A06-04）。ステータス・履歴は控えのまま |
| C4 | ダブルチェック者が空 | 手順4で欄を空のまま「更新」を押す。（端末。記録）「ダブルチェック者のIDを入力してください。」が出て、何も送らない（UKA-01 E12）。（EC。合否）ダブルチェック者は手順1の控えのまま（空）。最終更新者も控えのまま |
| C5 | ダブルチェック者が数値でない | 手順4で欄に「abc」を入れて「更新」を押す。（端末。記録）「ダブルチェック者のIDは数値で入力してください。」が出て、何も送らない（UKA-01 E13）。（EC。合否）ダブルチェック者・最終更新者は控えのまま |
| C6 | 存在しないメンバーID | 手順4で、メンバー管理に無い大きな数（例：99999999）を入れて「更新」を押す。（端末。記録）EC が返したエラー文言の1件目が出る。設計書は文言を定めず、新実装は「ダブルチェック者が見つかりません」を返す。この文言を期待値にする（2026-11-09 決着）。（EC。合否）ダブルチェック者・最終更新者は控えのまま |
| C7 | フリーコメントの更新が失敗する | 手順3の直前に端末のネットワーク接続を外して「コメント更新」を押す。（端末。記録）「サーバエラー：フリーコメントの登録に失敗しました。」が出て、査定画面のまま。（EC。合否）フリーコメントは控えのまま。つなぎ直して押し直すと手順3のとおりになる |
| C8 | ダブルチェック者の更新が失敗する | 手順4の直前にネットワーク接続を外して「更新」を押す。（端末。記録）「サーバエラー：ダブルチェック者の登録に失敗しました。」が出て、査定画面のまま。（EC。合否）ダブルチェック者・最終更新者は控えのまま。つなぎ直して押し直すと手順4のとおりになる |

## 記録（判断待ちではない。合否は設計書の期待値で付け、新実装の表示は記録する）
