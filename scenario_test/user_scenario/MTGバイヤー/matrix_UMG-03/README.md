# MTGバイヤーの査定表に商品を足す（UMG-03）

IPA「高信頼化ソフトウェアのための開発手法ガイドブック」(2010) の表6-9〜6-11と同じ手順で作る。`fl_table.tsv`（因子・水準）→ `prohibitions.tsv`（禁則）→ `matrix.md`・`matrix.tsv`（`build_matrix.py` が作る）。エラーや中断は `exceptions.tsv` に1つずつ差し込む。

## 範囲

- 担当者が査定表に商品を足し、買取価格が決まるまで。カードの読み取り・名前検索・個別入力・金額指定の4つの追加方法と、ネット買取の申込カードとの関係
- 店頭買取の査定表づくりの流れ全体（本人確認から買取成立まで）は UKA-01（`店頭買取/matrix_UKA-01/` の因子G「買取品の中身」）。ここでは店頭買取は水準X1の1つにして、店頭買取で変わる列（基準価格・基準小計・部門）と個別入力の必須項目を確かめる
- 部門の「MTGBuyer表示フラグ」と固定価格商品部門IDの設定は前提データ。表示が非表示の部門は個別入力の部門の選択肢に出ず、固定価格商品部門IDが無いと金額指定の部門を取れない（0506 A06-11・A06-12）
- ネット買取の査定完了で EC に査定金額が入る部分は UMG-04（`matrix_UMG-04/`）
- カードの読み取り（バーコード・カメラ）は端末の物理操作でシステムの外。EC との間で取る商品情報（カード詳細IDまたはカード名で商品・規格・買取価格・基準価格・在庫を取る）から対象にする

## 因子の作り方

- 因子X「買取の種類と、足すカードの申込カードとの関係」は、買取の種類（店頭／ネット）と申込カードとの関係が従属するので1つの因子にした。申込カードがあるのはネット買取だけで、突き合わせるのはカードの読み取り・名前検索で足すときだけ（O01-02「査定表の行の追加と買取価格」）
- 画面で選ぶ言語・フォイルは、合う規格があるか無いかだけが処理を分ける（無いときは例外E4）。値そのものの違い（JP/EN、フォイル/ノーマル）は流れ・処理・表示が変わらないので水準にしていない

## まとめた水準（2026-11-05 依頼者決定「種類別のフローや処理が変わらないならまとめて」）

| 因子 | まとめた水準 | 代表 | 根拠（変わらない理由） |
|---|---|---|---|
| B 追加の方法 | 金額指定の「1円」「2円」「5円」「10円」 | 1円 | 「買取価格は指定した金額。商品名は「{金額}円商品」。基準価格は金額の10倍。部門は固定価格部門。枚数は、追加するときに入力させた枚数。商品規格IDは0」（0601 O01-01「査定表」）。どの金額も同じ式で、画面・処理・送る項目が変わらない。金額の違いは買取価格の値だけ |
| F 状態 | SP・MP・HP | SP | 「状態（1=NM、2=SP、3=MP、4=HP）」。状態で変わるのは、状態ごとの申込時買取価格・買取価格の値だけで、流れ・処理が同じ（O01-02「査定表の初期表示」「査定表の行の追加と買取価格」）。NMは個別入力の行の状態になるので分けた |

分けたままにしたもの：B1（読み取り）とB2（名前検索）。呼ぶ処理（カード詳細IDで1種の商品情報／カード名で前方一致検索）と、空白だけ・0件のときの扱いが違う。

## 禁則

- P1〜P8：申込カードとの突き合わせ（含まれる＋申込時買取価格あり／含まれるが選んだ状態の申込時買取価格なし／含まれない）は、カードの読み取り・名前検索で足すネット買取の行だけ。X5は個別入力・金額指定の行を表す
- 個別入力・金額指定でNM以外の状態を選んだ組は禁則にしない。買取端末は両方とも同じ登録処理で、登録した行の状態に画面で選んでいる状態を入れる（front-application MTGBuyer の AssessmentTable.cs:99-123、MainWindowViewModel.cs:1191-1192。ローカルのソースは古い可能性がある）

## 実装と設計書で確かめたこと

- 商品情報の取得は、商品画像・カード詳細・レアリティ・買取価格と部門を持つ付随情報・言語・状態のどれかが結び付いていない規格を応答から除き、高額商品コードの入った商品も取らない（0506 A06-06・A06-07・A06-08）。査定で出ない商品は、商品の登録状況に原因がある（例外E5）
- 同じカード・カード詳細・言語・状態の組に商品規格が複数あるとき、応答に残るのは後から取った1件で、どれが残るかは定まらない（0506 A06-06・A06-08。判断待ちとして `../scenario_list.md` に記録）
- 基準価格は商品規格の販売価格（0601 O01-01「査定表」）。在庫は、設計書では「ログイン者の所属店舗のEC在庫」を取る（0506 A06-06 カスタマイズ説明）
- 新実装は MTGバイヤーが呼ぶ全ての商品情報の取得を実装している（`../scenario_list.md` の連携の網羅）
