| 項目 | 内容 |

## 前提

- 共通の決まり：`../L4を流すときの共通の決まり.md` を先に読む（試験データの名前にシナリオIDを付ける・共有の設定は元に戻す・バッチの起動・店舗の読み替えなど）
- システムの外で済んでいること：買取端末（試験端末）が2台使える（一覧に査定中・査定再開の受注を残す行で、別の担当者の端末を使う）。カードの現物（読み取り機器は使わず名前の検索で足す）と、お客様の身分証の見本（自動車運転免許証。両面）。ネット買取の行で使う担当者は、UMG-01 の L1 のとおり、ログインの応答の所属店舗名が「トーナメントセンター 東京」と一致するようにしておく（本店の店名を一時的に変え、終わったら戻す）
- 店舗：開発環境では店舗を新しく作らない。本店は店舗ID 1（画面によって「Hareruya」「トーナメントセンター 東京」と出る）。他店舗の行は、流す前に既存の店舗から店舗識別子を持つ支店を1つ選び、店舗ID・画面の名前・店舗識別子を控えて、以降の「支店」を読み替える
- 用意するデータ（試験用の値。設計書の値ではない）
  - 買取担当者X（本店所属）、買取担当者Y（本店所属。別の担当者）、買取担当者Z（支店所属）。いずれも端末にログインでき、管理画面の店頭買取管理を使える。もう1人、ダブルチェック者になる担当者（メンバーIDを控える）は UKA-01 と同じ
  - 店頭の受注（お客様：非会員「MTGバイヤー試験 太郎」。生年月日は成年。国＝Japan、職業を選ぶ。店頭買取査定申込を店舗識別子 tc の入口で行う。手順は UKA-01 の手順1〜4・UTH-03 の手順1〜6と同じ）
    - S1：本店・査定前（代表）。S2：本店・査定中断にしたもの（R2）。S3：本店・端末2で担当者Yが査定中にしたまま査定画面に置くもの（R3）。S4：本店・端末2で担当者Yが査定再開にしたまま査定画面に置くもの（R4）。S5：支店の入口で申込んだ査定前の受注（R5）。S6：本店・査定前で、端末1の一覧に出したあとに別の端末で経理払い出し待ちまで進めるもの（R9）
  - 商品（登録済み。カード登録CSV→カード商品CSVの手順は UKA-04 の手順2〜3と同じ。商品コードは登録時に自動で付く：共通の決まり）
    - 「試験カードP」：日本語・NM・非Foil。買取価格5,000円、基準価格（販売価格）8,000円。「試験カードQ」：日本語・HP。買取価格100円、基準価格200円。どちらも買取価格の部門が設定され、査定端末の部門の選択肢に出る（UMG-03 の前提）。買取価格は商品の規格の値で、端末の査定表に出る値を控える。違うときは、試験で作った商品に限り規格の買取価格を直してから流す
  - ネットの受注：N1＝UNK-01 のT04の終点（えらんで買取のカードA×2＋まとめて買取。会員E4）を UNK-03 の手順2で「商品到着」にしたもの。N2＝UNK-01 のT01の終点（えらんで買取のカードA×2だけ。会員E3）を同じく「商品到着」にしたもの。カードA・まとめカードMは UNK-03 の前提と同じ
  - 手順の前に控える値：S1の買取一覧のステータス・買取詳細のステータス変更履歴の行数、ネットの買取一覧のN1・N2の買取状況と履歴の行数、店頭買取管理の買取一覧で買取店舗＝本店・各ステータスの査定ID
- 画面の名前・文言は新実装の表示で書く。設計書と新実装の文言が違うときは、期待値は設計書の文言にし、新実装の文言が出たら不合格として記録して食い違いに書く

## L3で変わるところ（組み合わせ表は無い。1つずつ別のテストにする）

手順の番号は上の「操作の流れと期待値」。行ごとに別の受注で流し、流し始めの状態を控える。同じ担当者で複数の行を流すと前の行の分が一覧に残るので、件数の期待値は、その行で作った受注だけに限る。

| 行 | 条件（店頭／ネット・選ぶ受注の状態・担当者・店舗など） | 変わるところ |
|---|---|---|
| R1 | 店頭・査定前・本人（代表） | 上の手順1〜8 |
| R2 | 店頭・査定中断の受注S2を選ぶ（本人） | 流し始め：S2は担当者Xが査定中にして「査定を中断する」で中断したもの（UMG-07）。手順3：S2を選ぶと「「（お客様の姓 名）」の受注を開きますか？」が出る。「はい」で、（EC。合否）ステータス「査定再開」、査定担当者・最終更新者＝担当者X、履歴に「査定再開」が1件増える。（端末。記録）保管した査定表が復元され、身分証スキャン画面へ移る。別の端末で開いたときは身分証の画像が無いので、撮り直す（UKA-01 E23）。確認で「いいえ」を選ぶと何も起きない（R15。（EC。合否）履歴の行数・ステータスは控えのまま）。再開した受注は、同じ査定を続けるあいだは査定再開のまま（手順6で買取キャンセル等へ進む。`scenario_list.md` の食い違いの節） |
| R3 | 店頭・査定中の受注S3（別の担当者Yが端末2で査定画面を開いている）を担当者Xが選ぶ | 流し始め：S3はステータス「査定中」、査定担当者＝Y。端末1の一覧を更新したあとS3を選ぶ。（EC。合否）「更新前と同じ状態」なので何も更新されず成功する：ステータス「査定中」・査定担当者＝Y・履歴の行数は控えのまま。（端末。記録）担当者Xの端末は身分証スキャン画面へ進む（2人の担当者が同じ受注を同時に査定できる。UKA-01 E9。`scenario_list.md` の食い違い）。本人（担当者Xが端末2でも査定中にしたS3を端末1で選ぶ）の場合も同じ（何も更新しない） |
