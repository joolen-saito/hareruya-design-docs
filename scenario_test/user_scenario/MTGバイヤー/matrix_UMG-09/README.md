# 入庫モードで商品コードと枚数の一覧を作り、在庫登録用のCSVを出す（UMG-09）

IPA「高信頼化ソフトウェアのための開発手法ガイドブック」(2010) の表6-9〜6-11と同じ手順で作る。`fl_table.tsv`（因子・水準）→ `prohibitions.tsv`（禁則。今回は無い）→ `matrix.md`・`matrix.tsv`（`build_matrix.py` が作る）。エラーや中断は `exceptions.tsv` に1つずつ差し込む。

## 範囲

- 買取担当者が MTGバイヤーの入庫モードで、カードを読み取って（またはカード名で検索して）商品コードと枚数の一覧を作り、CSVとして端末へ出力するまで。入庫モードは受注にもお客様にもひも付かず、EC の在庫を直接は更新しない（O01-03「入出力: 永続化」）
- カードの読み取り・出力したCSVを手で EC に取り込む操作は、取り込み先がアプリで定められていないので対象外（`../scenario_list.md` の判断待ち）。ここは「どんな内容のCSVが出るか」を確かめる
- 因子は担当者が選ぶ・状況で決まるもの：出力方法（2）・所属店舗（2）・一覧の行（3）・同じ商品の行（2）。出力方法・所属店舗で列が変わり、出力方法で出さない行が変わる（効き合う）

## 期待値（各テストに共通）

- ファイル名：通販/支店システム用は「通販_支店システム用{14桁の日時}.csv」、ネット買取用は「ネット買取用{14桁の日時}.csv」。文字コードShift_JIS、カンマ区切り、すべての値を二重引用符で囲む、1行目は見出し行
- 通販/支店システム用の列：所属店舗が「トーナメントセンター 東京」なら商品コード・在庫増減数、それ以外なら商品コード・商品名・在庫数。ネット買取用は店舗にかかわらず9列（商品コード・在庫増減数・商品名・基準価格・買取価格・言語ID・略称タグ・レアリティ・状態）
- 商品名は「【{言語}】{商品名}」（例：【JP】稲妻）。在庫増減数・在庫数は一覧の枚数
- 出力すると端末の作業途中のデータが消え、保存先のフォルダが開く

## 禁則が無い理由

4因子とも担当者または状況で決まり、設計書（機能設計書O01-03）に、一方の水準が他方を選べなくする記述は見つからない。ネット買取用で商品コードが空の行を出すこと、通販/支店システム用で出さないことは、禁則でなく水準C3の期待値の違いとして扱う。

## 実装と設計書で確かめたこと

- 入庫モードの機能設計書（O01-03）は、Excel基本設計に当たる設計書が無く、現行ソース（買取端末アプリ）から起こしたもの。0601 には入庫モードの記述が無い（`../scenario_list.md` の食い違い）
- 所属店舗名「トーナメントセンター 東京」の取得元はログインの応答の所属店舗名。開発環境（ダンプ 2026-09-07）の本店の店舗名は「Hareruya」で、この文字列と一致しない（`../scenario_list.md` の判断待ち）。このため、水準B1（トーナメントセンター 東京）を開発環境で作れるかは、ログインの応答の店舗名で決まる
- 商品コードが空の行がどう生じるかは、設計書にもソースにも書かれていない（出さない条件だけが書かれている）。C3 の行を作る方法が決まらないときは、C3 を通すテストを保留にする
