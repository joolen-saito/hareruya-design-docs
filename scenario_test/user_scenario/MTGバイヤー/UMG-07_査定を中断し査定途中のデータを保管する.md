## 前提

- 共通の決まり：`../L4を流すときの共通の決まり.md` を先に読む（試験データの名前にシナリオIDを付ける・共有の設定は元に戻す・バッチの起動・店舗の読み替えなど）
- システムの外で済んでいること：買取端末（試験端末）が使え、端末のネットワーク接続を外してつなぎ直せる。保管先（ファイル保管先）は外部サービスで、中身を確かめられるときだけ記録する。ネットの行は、UMG-01 の L1 のとおり担当者の所属店舗名が「トーナメントセンター 東京」と一致するよう本店の店名を一時的に変え、終わったら戻す
- 店舗：開発環境では店舗を新しく作らない。本店（店舗ID 1。画面によって「Hareruya」「トーナメントセンター 東京」と出る）の担当者で流す
- 用意するデータ（試験用の値。設計書の値ではない）
  - 買取担当者X（本店所属）
  - 商品：「試験カードP」＝日本語・NM・買取価格5,000円・基準価格8,000円、「試験カードQ」＝日本語・HP・買取価格100円・基準価格200円（UMG-05 と同じ。手順は UKA-04 の手順2〜3）。ネットは「試験カードA」×2の申込（UMG-04 の前提と同じ。NM の申込時買取価格4,000円）と「試験カードM」（NM・305円）
  - 受注：行ごとに1件。店頭は、非会員「MTGバイヤー試験 太郎」の店頭買取査定申込（UKA-01 の手順1〜4）を、端末で UMG-02 の手順2〜4まで進めて査定画面を開いたもの。ネットは UMG-04 のT02の受注（商品到着）を、査定画面を開いたところまで進めたもの
  - 手順の前に控える値：受注の買取一覧のステータス・ステータス変更履歴の行数、買取金額、商品P・Q・A・Mの在庫
- 画面の名前・文言は新実装の表示で書く
