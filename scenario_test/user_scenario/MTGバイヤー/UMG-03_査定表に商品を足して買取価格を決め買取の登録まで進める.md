# UMG-03 買取担当者が査定表に商品を足して買取価格を決め、買取の登録まで進む（店頭買取・ネット買取共通）

| 項目 | 内容 |
|---|---|
| 利用者 | 買取担当者（買取端末。カードの読み取りはシステムの外。試験端末を人が操作する）→ 店舗チーム（EC管理画面で確かめ） |
| 目的 | 買取担当者が査定画面で、カードを読み取る・名前で検索する・個別入力する・金額を指定して査定表に商品を足し、買取価格が決まる。店頭は基準価格・基準小計・部門の列、ネットは買取カテゴリの列が出る。買取価格は、ネットで申込カードに含まれるカードなら、画面で選んだ状態の申込時買取価格があればその価格、無ければ（含まれないときも）商品情報の買取価格。足した行は、店頭は経理払い出し待ち（UMG-05）・ネットは査定完了（UMG-04）の登録で EC の明細・金額になり、管理画面の買取詳細の値と一致する |
| 種類 | 正常（組み合わせ表の12行のうち10行を流す。2行は作れない）＋例外9件 |
| マトリクスの行 | `matrix_UMG-03/matrix.md` のT05（追加の方法＝カード名を入れて検索し「登録する」・買取の種類＝店頭買取・画面で選んでいる状態＝NM）。T01〜T12 の他の行と例外E1〜E9、部門まわりの条件（P1・P2）は「L3で変わるところ」 |
| もとのシナリオ | SCN-KAITORI-003・007（店頭買取の査定表）、SCN-ONLINE-KAITORI-003・007（ネット買取の査定）。業務フロー06 の1-2〜1-8・14 の2-4〜2-6。設計書 0601 O01-01「査定表」、機能設計書 O01-02「査定表の初期表示」「査定表の行の追加と買取価格」、0506 A06-06・A06-08・A06-11・A06-12 |

端末の画面の見え方（査定表の行・列・メッセージ）は外部システム（買取端末アプリ）の表示なので記録だけにし、合否は EC 側の値（管理画面の買取詳細・買取情報編集の明細・買取金額・基準価格）で付ける（2026-11-24 決定）。期待値は「（端末。記録）」と「（EC。合否）」に分けて書く。通しシナリオ UTH-03 の手順12（店頭の査定表）と食い違わないよう、同じ商品の名前・金額で書いた。

## 前提

- 共通の決まり：`../L4を流すときの共通の決まり.md` を先に読む（試験データの名前にシナリオIDを付ける・共有の設定は元に戻す・バッチの起動・店舗の読み替えなど）
- システムの外で済んでいること：買取端末（試験端末）が使える。カードの現物（読み取りの行で使う。読み取りは端末の物理操作でシステムの外）。ネットの行は、UMG-01 の L1 のとおり、担当者の所属店舗名が「トーナメントセンター 東京」と一致するよう本店の店名を一時的に変え、終わったら戻す
- 店舗：開発環境では店舗を新しく作らない。本店（店舗ID 1。画面によって「Hareruya」「トーナメントセンター 東京」と出る）の担当者で流す
- 用意するデータ（試験用の値。設計書の値ではない）
  - 買取担当者X（本店所属）。もう1人、ダブルチェック者になる担当者（メンバーIDを控える）
  - 商品（カード登録CSV→カード商品CSVで登録済み。手順は UKA-04 の手順2〜3と同じ。カード商品CSVは NM・SP・MP・HP の4つの規格を作り、商品コードは登録時に自動で付く：共通の決まり。どれも商品画像を結び付けておく（結び付けないと検索に出ない：例外E5）。買取価格・販売価格は商品の規格の値で、試験で作った商品に限り、規格の値を下の値に直してから流す）
    - 「試験カードP」（店頭。日本語・非Foil）：NM＝買取価格5,000円・基準価格（販売価格）8,000円、SP＝買取価格4,000円・基準価格6,400円。どちらも買取価格の部門が設定され、端末の部門の選択肢に出る
    - 「試験カードA」（ネット。UNK-01 の「ネット買取試験カードA」と同じ作り方）：申込のとき NM＝買取価格4,000円・SP＝買取価格3,000円にしておく。申込のあとで、商品情報の NM を4,500円・SP を3,500円に直す（申込時買取価格と現在の商品情報の買取価格を区別するため）。「試験カードB」（ネット。申込に含めない）：NM＝1,500円・SP＝1,200円。
  - ネットの受注（T03・T04・T07〜T09・T12 で使う）：行ごとに1件ずつ、ネット買取/UNK-01 のT04の申込（会員E4「ネット買取試験 四郎」が、「試験カードA」を数量2の「えらんで買取」と、まとめて買取の専用商品1点を申し込む。申込に含まれるカードはA×2だけ）を、カードAの価格を上のとおりにしてから行い、UNK-03 の手順2で管理画面から「商品到着」にしたもの。この受注は、カードAの申込時買取価格がNM＝4,000円・SP＝3,000円で、申込にまとめて買取がある。T03・T07（申込カードに含まれる）はカードA、T04・T08（含まれない）は申込に無い「試験カードB」を足す。管理画面の買取情報編集で、申込時買取価格の欄を控える
  - 店頭の受注：行ごとに1件ずつ、非会員「MTGバイヤー試験 太郎」（成年）の店頭買取査定申込（UKA-01 の手順1〜4）。端末で UMG-02 の手順2〜4（ログイン・店頭買取・受注を選ぶ・身分証スキャン）まで進めて査定画面を開く
  - 手順の前に控える値：商品P・A・B・Gの規格ごとの買取価格・販売価格・商品コード、買取一覧の件数、受注のステータス変更履歴の行数、商品の在庫
- 画面の名前・文言は新実装の表示で書く

## L3で変わるところ（マトリクスの他の行・例外）

手順の番号は上の「操作の流れと期待値」。1回ずつ流す。同じ受注で複数の行を流さない（行ごとに別の受注にする）。ネットの行は、手順3の代わりに下の操作を行い、手順5・6の代わりに「査定完了」（確認「査定を完了します。よろしいですか？」で「はい」）を押して、買取情報編集で確かめる。金額は前提の値。
