# デッキ登録の新規デッキ登録（UDK-01）

IPA「高信頼化ソフトウェアのための開発手法ガイドブック」(2010) の表6-9〜6-11と同じ手順で作る。

1. 因子・水準表（FL表）: `fl_table.tsv`。利用者が画面で選ぶもの・変わるものを因子にし、設計書の文を根拠に持つ
2. 禁則表: `prohibitions.tsv`。ありえない組み合わせ
3. 組み合わせテストマトリクス: `matrix.md` / `matrix.tsv`。`build_matrix.py` が作る。1行が1本のシナリオになる
4. 例外の差し込み表: `exceptions.tsv`。エラーや中断（★の手順）は、正常な値と混ぜず、条件に合う行へ1つずつ差し込む

## 範囲

- 顧客戦略チームが、外部大会などで活躍したデッキを管理画面に登録し、お客様のデッキ検索に載せるところまで（業務フロー18 パターン1の1-1〜1-4）。1-1のデッキ内容の取得（EVENT COVERAGEなど）はシステムの外
- デッキ種別は「event」（大会デッキ）で登録する。「user」で登録した場合は例外EX5に入れた
- 各行の期待値：デッキが登録され、管理画面のデッキ一覧で見つかる（外部大会は大会開始時刻で除外されない。店舗イベントは開催済みなので、大会開始時刻を過ぎている）。お客様のデッキ検索の見え方は、公開状態とデッキリストの公開状態で決まる
  - 公開：デッキ検索結果に出る（アーキタイプが設定され、開催日が当日23時59分59秒以前）。デッキリストを非公開にした行は、一覧に非公開の印が付き、デッキ詳細のカードリストは出ない。デッキリストを公開にした行は、デッキ詳細にカードリストが出る
  - 限定公開：デッキ検索結果には出ないが、デッキ詳細は見られる
  - 非公開：デッキ検索結果にもデッキ詳細にも出ない（デッキ詳細はHTTP 404）
- D2（開催済みの店舗イベント）は、画面入力ではデッキ編集画面のイベント検索から日程を選び、CSVではイベント詳細IDの列に書く（CSVにイベント検索のポップアップは無い）。大会名（日・英）と開催日は、どちらの登録方法でも必須
- 1-2のタグ登録・1-3のアーキタイプ登録は、無いときだけ行い、登録したタグ・アーキタイプをそのデッキに付ける
- 因子に入れなかったもの：アーキタイプのCSV一括登録（0212 アーキタイプ登録CSVアップロード）、デッキの複製・一括編集・一括削除・CSV出力（業務フロー18に無い）、フォーマットの違い（統率者戦のときの統率者の入力など。結合テストで確かめる）

## 実装・設計書で確かめたこと（2026-11-03）

- 管理画面のデッキ一覧は、大会デッキ（event）だけを出し、イベント詳細に紐づくデッキは大会開始時刻を過ぎたものだけを出す。紐づかないデッキ（外部大会）は開始時刻で除外されない（0212 デッキ一覧(検索入力) 処理概要・現行仕様、新実装のデッキ検索の条件）
- お客様のデッキ検索結果に出るのは、公開・大会デッキ・アーキタイプ設定済み・開催日が当日以前のデッキ。限定公開のデッキ詳細は見られ、非公開とユーザーデッキは404（0309 F09-02・F09-06、新実装のデッキ検索・デッキ詳細）
- CSV取り込みの存在しないタグ名は、新実装が読み飛ばす（EX8）。デッキ登録CSVの表示フラグは0・1のみ（禁則X1）
- CSV取り込みは、枚数がフォーマットの規定に反すると登録を中止する（EX11）。画面入力は警告つきで保存できる（EX4）。新実装も、表示かつデッキリスト公開の行で枚数違反があれば処理を中止する（DeckUpdateImportHandler の枚数検証）

## まとめた水準

なし（どの水準も処理が違う）。主な根拠：タグ・アーキタイプの有り無しは事前登録の手順が違い、画面入力とCSV取り込みは入口の画面が違う。外部大会とイベント検索は入力方法が違う。公開状態3種・デッキリスト公開は表示の出る出ないが違う。
