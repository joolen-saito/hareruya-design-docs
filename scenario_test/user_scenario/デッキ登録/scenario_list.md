### 設計書との食い違い（設計書の不足。起票はしない）

- 直近の大会管理：設計書は「識別ID1-5のいずれかが入力されている場合は必須」（5項目は開催日・フォーマット・イベント名（日）・イベント名（英）・参加人数）。新実装は5項目とも任意で、一部だけ入力しても保存できる（確かめたのは入力フォームの定義と更新の処理。項目をまたぐ検証は見つからなかった）
- 設計書 0306 大会デッキ登録編集は、新規提出時に「公開設定(非公開)、デッキタイプ(イベント)を設定して保存する」と書き、新実装（公開状態「非公開」・デッキリスト非公開）と一致する。設計書に無いのは、上書き提出（登録済みデッキの上書き更新）で公開状態を変えないこと（公開済みのデッキを会員の再提出で内容が変えられるか）だけ
- デッキ検索TOPのメタゲームの集計は、新実装がアーキタイプの公開状態が「公開」のものに限る。0309 F09-01 の集計条件（大会デッキ・公開）にアーキタイプの公開状態が無い。デッキ検索結果（F09-02）は、新実装も設計書もアーキタイプの公開状態を見ない
- デッキ登録CSVの枚数検証：設計書は行の公開状態に関わらず、枚数違反をエラーにして登録を中止する（0212 デッキ登録CSVアップロード）。新実装は表示かつデッキリスト公開の行だけ検証し、非表示または非公開の行は枚数違反でも取り込む。マトリクスUDK-01のEX12。
- デッキ登録CSV：設計書は「デッキリスト公開の場合はデッキリストを登録する」。新実装は、表示フラグが非表示（0）のデッキもカードの行を作らず、表示かつデッキリスト公開のときだけ作る
- 0212 デッキ一覧の「ユーザ作成のデッキ」が何を指すか（デッキ種別 user のマイデッキ）が書かれていない。業務フロー18 の2-2「デッキを検索」と読み違えやすい
- 0212 デッキ編集の機能No欄が「M15-02（正しくは M15-05）」、直近の大会管理が「F06-10（正しくは M15-11）」と設計書内で訂正されている（Excelの機能No欄の誤記）

### 判断待ち

- UDK-02（2-1 の位置づけ）：業務フロー18のパターン2の2-1は「入賞者にオンラインでデッキリストを登録してもらう」だが、UDK-02 は開催前の参加者が同じ画面でする提出を2-1として扱う。イベント登録から開催まで（UEH-01〜04）・通しシナリオ UTH-04 も同じく、参加者の提出を2-1、開催後の更新・公開を2-2に割り当てて揃った（以前の UEH の「対象外」は解消）。残る未決は、2-1 の「入賞者に」を提出者のうち入賞者だけと読むか、提出者全員と読むか。見たもの：業務フロー18 33行・イベント登録から開催まで/review/dispositions_R1.md #4・R3.md の影響欄
- UDK-02 と UEV-07（起点の重なり）：どちらも申込済みの会員が「デッキ登録」を押す起点。中身（提出・メール・状態）は UDK-02、ボタンの出る・出ない条件は UEV-07、と分担しているが、どちらに寄せるかは取りまとめで確かめる（イベント管理の同名の判断待ちと対）
- UDK-03：更新時のエラー（書式の誤り・必須の未入力）をお客様に聞けないときの扱い（業務フロー2-2「可能ならお客様に聞くなどして修正する」の反対側）。見たもの：業務フロー18の2-2の注記、0212 デッキ編集・デッキ一覧の機能仕様と表示メッセージ、新実装のデッキ編集の入力フォーム。どれにも、聞けないときにデッキを非公開のまま置く・削除する等の定めが無い。エラーを直せなければ更新自体ができず非公開のままになる、というシステムの動きだけが言える。運用上の扱い（聞けないときに放置するか、期限を決めるか）は依頼者の裁定を待つ
