# デッキ登録の直近の大会（UDK-04）

IPA「高信頼化ソフトウェアのための開発手法ガイドブック」(2010) の表6-9〜6-11と同じ手順で作る。`fl_table.tsv`（因子・水準）、`prohibitions.tsv`（禁則）、`exceptions.tsv`（例外）から `build_matrix.py` が `matrix.md`・`matrix.tsv` を作る。1行が1本のテスト。

## 範囲

- 顧客戦略チームが直近の大会管理で大会を登録し、デッキ検索TOPの「直近の大会」に出すところまで（業務フロー18 3-1）
- 各行の期待値：デッキ検索TOPの「直近の大会」に、登録した大会の開催日・フォーマット・大会名・参加人数が出る。入力を消去した行は出ず、1件も無ければ直近の大会の区画ごと出ない（0309 F09-01「直近の大会」。開催日が設定され、日本語名と英語名がどちらも空でない行だけを、識別子の昇順に出す）
- 5行は最初から固定で用意されていて、行を書き換えて登録する（行は増えない）。5行すべて使用済みのときは、既存の行を上書きする。行を空に戻すには「消去」
- 操作する行の数は、設計書の「5大会まで」の下限（1行）と上限（5行）を水準にした。使用済みと空が混じる状態（A2）と、すべて空（A1）・すべて使用済み（A3）で、登録・上書き・消去ができる行が変わる

## 分ける前の記述（2026-11-09にテストを値ごとに分けた。網羅マトリクスの引用の元）

分ける前のL3は、次のとおり1つの文に値を並べていた。

登録する行の数（1行〜5行）。使用済みの行を別の大会で上書きする。入力を消去して行を空に戻す。一部の項目だけ入力して保存する（設計書はエラー。新実装は保存できる。下記の食い違い）。マトリクスは作らない（組み合わせて効き合う因子が無い）

この文の値は、いまは次のように別々のテストになっている。登録する行の数（1行・5行）はC1・C2、空の行への登録はB1、上書きはB2、消去はB3、一部の項目だけ入力して保存するはEX1。

## 実装・設計書で確かめたこと

- 設計書は直近の大会の5項目（開催日・フォーマット・イベント名（日）・イベント名（英）・参加人数）を「識別ID1-5のいずれかが入力されている場合は必須」とする。新実装は5項目とも任意で、一部だけ入力しても保存できる（入力フォームの定義と更新の処理で確かめた。項目をまたぐ検証は見つからなかった）。EX1はこの食い違いを記録するための例外
