# デッキ登録のオンライン入力されたデッキの公開（UDK-03）

IPA「高信頼化ソフトウェアのための開発手法ガイドブック」(2010) の表6-9〜6-11と同じ手順で作る。

1. 因子・水準表（FL表）: `fl_table.tsv`。利用者が画面で選ぶもの・変わるものを因子にし、設計書の文を根拠に持つ
2. 禁則表: `prohibitions.tsv`。ありえない組み合わせ（この業務では無い）
3. 組み合わせテストマトリクス: `matrix.md` / `matrix.tsv`。`build_matrix.py` が作る。1行が1本のシナリオになる
4. 例外の差し込み表: `exceptions.tsv`。エラーや中断（★の手順）は、正常な値と混ぜず、条件に合う行へ1つずつ差し込む

## 範囲

- 大会が開催されたあと、顧客戦略チームが、入賞者が会員ページでオンライン入力したデッキ（UDK-02で提出したもの）を管理画面のデッキ一覧で探し、アーキタイプ・タグなどを入力して更新し、公開するところまで（業務フロー18 パターン2の2-2）
- 前提：デッキは大会デッキ（event）・公開状態「非公開」・デッキリスト非公開・アーキタイプ未設定で、大会開始時刻を過ぎている（UDK-02の終点の状態＋大会の開催）
- 各行の期待値：デッキ一覧に更新後の公開状態が出る。お客様のデッキ検索の見え方は公開状態とデッキリストの公開状態で決まる
  - 公開：デッキ検索結果に出る（開催日が当日23時59分59秒以前・アーキタイプ設定済み）。デッキリストを非公開のままにした行は、一覧に非公開の印が付き、デッキ詳細のカードリストは出ない。タグを付けた行は、そのタグで絞り込んだ検索結果に出る
  - 限定公開：デッキ検索結果には出ないが、デッキ詳細は見られる
  - 公開にしないまま更新を終える（非公開のまま）のは、公開が完了しない中断なので行に入れず、例外EX8に置いた
  - 非公開のアーキタイプを選んだ行（C2）：デッキ検索結果には出る（デッキ検索結果の条件にアーキタイプの公開状態は無い）。デッキ検索TOPのメタゲームの集計からは外れる（新実装の動き。設計書に定めが無い。scenario_list.md の食い違い）
- 「更新時にエラーがある場合は、可能ならお客様に聞くなどして修正する」（2-2）のお客様への確認は、システムの外。お客様に聞けないときの扱いは業務フローにも設計書にも無い（scenario_list.md の判断待ち）
- 探し方は、デッキ管理の「デッキ一覧」だけを因子にしない。イベント管理の「イベント申込一覧」の「デッキ登録を検索」は、デッキ表示（印刷用）を開くだけで公開状態を変えられないので、例外EX1に書いた
- 因子に入れなかったもの：検索条件の違い（イベント名・プレイヤー名・イベント詳細IDなど。どれで探しても同じデッキが同じ編集画面に着く。デッキ一覧のイベント開催日（From）の初期値は3か月前なので、古い大会は日付を直して探す）、順位・成績・参加人数の入力（公開の流れを変えない）

## 実装・設計書で確かめたこと（2026-11-03）

- 会員が提出したデッキは、デッキ種別が大会デッキ（event）で作られるので、デッキ一覧（大会デッキだけを出す）に大会開始後に出る。「ユーザ作成のデッキは検索結果に表示しない」の「ユーザ作成」は、デッキビルダーで会員が作ったマイデッキ（デッキ種別 user）のこと。2-2の「デッキ一覧で探す」と食い違わない（0306 大会デッキ登録確認～完了「デッキ種別（大会）」・大会デッキ登録編集のマイデッキ一覧、新実装のデッキ登録処理とデッキ検索の条件、現行のデッキAPIのデッキ種別の扱い）
- 会員のデッキ提出（新実装）は、フォーマット・カードリスト・大会の情報だけを入れてデッキを作り、アーキタイプは設定しない。そのため2-2の更新でアーキタイプを選ぶ必要がある（EX2。設計書 0212 デッキ編集 (5) はアーキタイプを必須とする）
- お客様のデッキ検索結果の条件（公開・大会デッキ・アーキタイプ設定済み・開催日が当日以前）にアーキタイプの公開状態は無い。デッキ検索TOPのメタゲーム集計は、新実装がアーキタイプの公開も条件にする

## まとめた水準

なし（どの水準も処理が違う）。主な根拠：公開・限定公開・非公開のアーキタイプ選択、デッキリスト公開・非公開、タグ有無は、いずれも選択肢・表示の出る出ないが変わる（水準が2〜3つだけで、種類違いで処理が同じものは無い）。
