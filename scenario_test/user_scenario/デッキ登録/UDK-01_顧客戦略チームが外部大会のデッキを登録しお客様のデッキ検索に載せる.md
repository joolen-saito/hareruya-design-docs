| 項目 | 内容 |

| 目的 | 外部大会などで活躍したデッキの内容が分かったとき、顧客戦略チームが、該当するデッキタグ・アーキタイプが無ければ先に登録し、デッキ一覧の「新規登録」からデッキを登録する。管理画面のデッキ一覧でそのデッキが見つかり、公開のデッキはお客様のデッキ検索結果とデッキ詳細に出る。非公開・限定公開・デッキリスト非公開の行は、見える範囲が公開状態のとおりに変わることを確かめる |

デッキは管理画面のデッキ一覧の「新規登録」から1件ずつ入力して登録する（CSV取り込みは入口の違いなので外した。`matrix_UDK-01/README.md`）。会員がオンラインで提出するデッキは UDK-02、開催後の更新・公開は UDK-03。お客様のデッキ検索・デッキ詳細・一括購入そのものの機能の確かめ（0309）は結合テストで行い、ここでは登録したデッキが出る・出ないを確かめる。

## 前提

- 共通の決まり：`../L4を流すときの共通の決まり.md` を先に読む（試験データの名前にシナリオIDを付ける・共有の設定は元に戻す・バッチの起動・店舗の読み替えなど）
- システムの外で済んでいること：外部大会などで活躍したデッキの内容（デッキリスト・大会名・開催日・順位・成績）を EVENT COVERAGE などで取得している（業務フロー18の1-1）。この試験では、下の「デッキリスト」と「大会」の値を取得済みの内容として使う
- 用意するデータ（試験用の値。設計書の値ではない）
  - 顧客戦略チームの担当者（管理画面のデッキ管理の「デッキ一覧」「アーキタイプ一覧」「デッキタグ一覧」を使える。大会が「晴れる屋の開催済みのイベント」の行は、イベント管理の「イベント一覧」でイベントを登録できる権限も使う）
  - 店舗の読み替え（大会が「晴れる屋の開催済みのイベント」の行だけ）：流す前に、開発環境の既存の店舗から、イベントの開催店舗にでき、担当者に編集権限を付けられる店舗を1つ選び、店舗IDと画面に出る名前を控える。店舗は新しく作らない（本店は店舗ID 1で、画面によって「Hareruya」「トーナメントセンター 東京」と出る）。以下の「店舗A」は、控えた名前に読み替える
  - カード（デッキに入れる）：カード登録CSVで先に登録する15枚。名前は「シナリオ試験登録デッキ札01」〜「シナリオ試験登録デッキ札15」（英名「Scenario Test Entry Deck Card 01」〜「Scenario Test Entry Deck Card 15」。名前に括弧・スラッシュを入れない）。カード登録CSVの列：カード名（日本語・英語）・レアリティ・レイアウト・画像URL（英語）は必須（レアリティ・レイアウトは既存のカードに入っている値と同じ書き方にする）、カードセットは開発環境の既存のものから1つ選ぶ（流す前にカードセット一覧で名前を確かめる）、**使用可能フォーマットに「Standard」**（フォーマットの英語名）を入れる。使用可能フォーマットを入れないと、デッキ登録のとき「フォーマットの範囲から外れています」の警告が出て、この試験の「警告なし」の期待値が成り立たない。カードは1行1枚（15行）
  - カードの商品コードは使わない（デッキにはカード名で入れる。カードの商品を登録する必要はない）
  - デッキリスト（フォーマット＝スタンダード。「枚数 カード名」の形で1行ずつ）
    - メインボード（60枚）：「4 シナリオ試験登録デッキ札01」から「4 シナリオ試験登録デッキ札15」まで15行（各4枚）
    - サイドボード（15枚）：「4 シナリオ試験登録デッキ札01」「4 シナリオ試験登録デッキ札02」「4 シナリオ試験登録デッキ札03」「3 シナリオ試験登録デッキ札04」の4行
    - 統率：空
    - 流すときはカード名の後ろにシナリオIDが付く（例「シナリオ試験登録デッキ札01 UDK-01」）。デッキリストの行も付けた名前で書く
  - デッキタグ：既にあるタグ（水準A1）は、デッキ管理の「デッキタグ一覧」を開き、MTGマスターデータ管理の一覧にある既存のタグから1つ選ぶ（例「プロツアー」。流す前に一覧で確かめ、名前を控える）。無いタグ（水準A2）は、日本語名「シナリオ試験デッキタグ」・英語名「Scenario Test Deck Tag」（32文字以内）・表示順＝一覧のどの行の表示順とも重ならない値（一覧の最大の表示順より大きい値）で登録する
  - アーキタイプ：既にあるアーキタイプ（水準B1）は、流す前にアーキタイプ一覧の「新規登録」で用意しておく（下の手順3と同じ操作。名前は「シナリオ試験登録アーキタイプB1」・英名「Scenario Test Entry Archetype B1」）。無いアーキタイプ（水準B2）は、日本語名「シナリオ試験登録アーキタイプ」・英語名「Scenario Test Entry Archetype」・フォーマット＝スタンダード・公開状態＝公開で、手順3で登録する
  - 大会（水準D1：外部大会）：大会名（日）「シナリオ試験 外部大会」・大会名（英）「Scenario Test External Tournament」・開催日＝実行日の前日12:00。手で入れる
  - 大会（水準D2：晴れる屋の開催済みのイベント）：下の準備P2で、開催日が実行日の前日のイベント「シナリオ試験 開催済み大会」（英語名 Scenario Test Finished Tournament）を登録する
  - デッキ名：「シナリオ試験デッキ T05」（行ごとに行番号を変える。流すときはシナリオIDが付く）。プレイヤー名「Scenario Test Player」・順位 1・成績「優勝」・イベント参加人数 64
  - 公開状態・デッキリストの公開状態は、行ごとに「L3で変わるところ」の水準にする。代表の行（T05）は、公開状態＝公開・デッキリストの公開状態＝公開（デッキリストの非公開のチェックを付けない）
- 画面の名前・文言は新実装の表示で書く（設計書の名前が違うときは、期待値のところに設計書の名前を添える）。メッセージの文言は設計書の文言を期待値にし、新実装の文言が違えば不合格として記録する

## L3で変わるところ（マトリクスの他の行・例外）

手順の番号は上の「操作の流れと期待値」。1回ずつ別のテストとして流す。条件の列は `matrix_UDK-01/matrix.md` のとおり（A＝デッキタグ、B＝アーキタイプ、D＝大会、E＝デッキの公開状態、F＝デッキリストの公開状態）。デッキ名・イベント名・アーキタイプ名・タグの名前は、行ごとに末尾の行番号を変える（同じ名前を使い回すと検索結果に前の行のデッキが混ざる）。

見える範囲の確かめ方（行共通）：お客様のデッキ検索は、公開のデッキだけを「デッキ検索結果」に出す（0309 F09-02）。限定公開のデッキは検索結果に出ず、デッキ詳細は開ける。非公開のデッキは検索結果にもデッキ詳細にも出ない（デッキ詳細はHTTP 404）。限定公開・非公開の行の「デッキ詳細」は、管理画面のデッキ編集画面の画面アドレスの番号（デッキID）を控え、お客様の画面でデッキ詳細のアドレス（`/deck/<デッキID>/show/`）を開いて確かめる。
