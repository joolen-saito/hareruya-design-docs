# デッキ登録の会員のデッキリスト提出（UDK-02）

IPA「高信頼化ソフトウェアのための開発手法ガイドブック」(2010) の表6-9〜6-11と同じ手順で作る。

1. 因子・水準表（FL表）: `fl_table.tsv`。利用者が画面で選ぶもの・変わるものを因子にし、設計書の文を根拠に持つ
2. 禁則表: `prohibitions.tsv`。ありえない組み合わせ（この業務では無い）
3. 組み合わせテストマトリクス: `matrix.md` / `matrix.tsv`。`build_matrix.py` が作る。1行が1本のシナリオになる
4. 例外の差し込み表: `exceptions.tsv`。エラーや中断（★の手順）は、正常な値と混ぜず、条件に合う行へ1つずつ差し込む

## 範囲

- イベントに申し込んだ会員が、デッキ登録編集画面でデッキリストを提出し、デッキ登録完了画面と完了メールで登録を確かめるところまで（業務フロー18 パターン2の2-1）
- イベントの申込そのもの（申込画面・決済・申込完了画面のデッキ登録ボタン）はイベント管理のUEV-02で扱う。このマトリクスは、デッキ登録編集画面から先のデッキリストの入れ方・提出の回・内容・フォーマットの数を扱う。入口がマイイベント・デッキ登録の一覧でも申込完了画面でも、デッキ登録編集画面から先は同じ
- 表示言語（日本語・英語）はUEV-02の因子にあるため入れない。入力形式の注意書きの英語版が別にあるのは設計書どおり（0306 大会デッキ登録編集 表示メッセージ）
- 各行の期待値：デッキ登録完了画面（「デッキ登録完了」）が出て、完了メールが届き、マイイベント・デッキ登録の一覧が「デッキ登録済み」になる。初回（B1）はデッキが新しくできる。上書き（B2）はデッキの数が増えず、前のカードの行が消えて内容が入れ替わる。C2の行は、確認画面にメインボード・サイドボードごとのエラーが出る。D2の行は、フォーマット選択エリアが出て、選んだフォーマットごとに登録済みの内容が切り替わる
- 初回に提出したデッキは、公開状態が「非公開」で、デッキリストも非公開で保存される（新実装）。お客様のデッキ検索には出ない。上書き提出（B2）は既存の公開状態・デッキリストの公開状態を変えず、カードリストだけを入れ替える（UDK-03で公開したあとの上書きなら、公開中のまま内容が変わる）。公開はUDK-03で行う

## 実装・設計書で確かめたこと（2026-11-03）

- 提出の判定順序（選手情報→フォーマット→イベント詳細が登録可か→書式）と、書式の誤りだけが登録を止め、枚数・禁止カードの誤りは確認画面の警告にとどまること：0306 大会デッキ登録編集・大会デッキ登録確認～完了の現行仕様と、新実装のデッキ登録の入口（書式の誤りだけを差し戻し、メール送信の失敗は記録して登録は成立させる）が一致する
- 新しくできるデッキ：新実装は、デッキ種別を大会（event）、公開状態を非公開、デッキリストを非公開にして作る（上書きのときは公開状態を変えない）。設計書 0306 大会デッキ登録編集も「公開設定(非公開)、デッキタイプ(イベント)を設定して保存する」と書き、一致する（上書きのときの公開状態は設計書に無い）
- マイデッキ：「ユーザー作成デッキ」（デッキビルダーで会員が作ったデッキ）の一覧から取り込む（0306 マイデッキ一覧は本人が作成したデッキ。新実装は選手のデッキ種別がユーザーのデッキを探す）

## まとめた水準

なし（どの水準も処理が違う）。主な根拠：直接入力・アリーナ形式貼り付け・マイデッキ取り込みは操作と画面（ポップアップ）が違い、初回提出と上書きは既存カード行の削除と作り直しの有無が違う。フォーマット適合の可否はエラー表示が違う。フォーマット数でフォーマット選択エリアの出る出ないが違う。
