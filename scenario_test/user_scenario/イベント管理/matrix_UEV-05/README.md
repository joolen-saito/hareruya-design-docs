IPA「高信頼化ソフトウェアのための開発手法ガイドブック」(2010) の表6-9〜6-11と同じ手順で作る。`fl_table.tsv`（因子・水準）、`prohibitions.tsv`（禁則。無い）、`exceptions.tsv`（例外）から `build_matrix.py` が `matrix.md`・`matrix.tsv` を作る。1行が1本のテスト。

## 範囲

- 決済画面から戻らなかった申込（決済中のまま30分以上たった申込）を、決済処理中チェックバッチ（10分ごと）が取引照会して、確定・削除・保留にするところまで（0413 B13-01）
- 処理対象：申込ステータスが「決済中」・支払番号が登録済み・申込日時がバッチ起動時間の30分以上前
- 各行の期待値（取引照会の結果で決まる）
  - A1 取引が成立：申込ステータスが「申込済み」になり、申込履歴が追加され、会員にクレジット決済完了メールが届く。
  - A2 取引が存在しない・失敗：申込が削除され（論理削除）、枠が戻る
  - A3 照会がエラーのレスポンスコード：申込は決済中のまま保留になる
  - EX1 取引照会の処理自体でエラー：イベント決済確認エラー通知メールが管理者に届く
- 決済中の申込が残る理由（B）は、設計書の「通信障害や決済画面からの離脱で申込完了画面へ遷移しなかった申込」の2つ
- 取引照会の対象にする申込の数（C）は、1件と、複数件（決済番号の順に処理する）
