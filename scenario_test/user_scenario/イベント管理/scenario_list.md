# イベント管理：シナリオ一覧（L2）

シナリオ1本は「起点の業務イベントから、業務として完了した状態になるまで」とする。担当者が替わっても切らない（お客様→店舗チーム→トレードチーム→外部システム→メール）。日をまたぎ、システムの状態が何かを待つもの（受付期間、開催日、決済の結果待ち、キャンセルの申し出）は別の1本にする。条件違いはL3のバリエーションとして、組み合わせテストマトリクス（ペアワイズ）で絞る。

| 階層 | 単位 | イベント管理での置き場所 |
|---|---|---|
| L1 業務領域 | シナリオのグループ | イベントの登録〜開催〜参加ポイント |
| L2 シナリオ | 起点イベント→業務完了 | この表の1行 |
| L3 バリエーション | 条件違い・例外 | `matrix_UEV-01/`・`matrix_UEV-02/`・`matrix_UEV-06/` と、各行の「L3」欄 |
| L4 ステップ | 画面操作と確認 | （まだ書かない） |

### 判断待ち（何を見ても決まらなかったもの）

1. 期限（前日23時59分）を過ぎたキャンセルの申し出：お問い合わせフォームは期限を確かめず、業務フロー・設計書にも期限後の扱い（断る・返金するか）が無い。ヘルプ・フォームは期限だけを示す。UEV-03は期限の前に限った
2. 店舗の都合による中止：業務フロー・設計書に手順・申込者への連絡・返金の記述が無い。UEV-08は、設計書にある道具（申込一覧の一括編集・日程の公開状態・CSV出力）から組み立てた。日程は、申込があると削除できない（0214・新実装）ので、非公開にする手順に限った。連絡と返金（要否と手段）は、業務フロー08の2-6〜2-8がお客様の「キャンセル申込」を起点とする工程で、店舗都合の中止での扱いが決まらない。決済中の申込：一括編集は取引を照会せず、決済の結果の確認（戻りの処理・バッチ）は決済中の申込だけが対象なので、先にキャンセル済みにすると成否を確かめられない。決済中の扱いも決まらず、UEV-08の完了対象に含めない
3. 開催日を過ぎたあとの返金（開催後のキャンセル）と、売上登録（スマレジ）の取り消し：設計書に無い
4. まとめて決済した一部の日程だけを取り消すときの返金額・方法：申込は日程ごとに別で参加費を持つが、決済は支払番号が共通の1回で、設計書に部分返金の定めが無い（UEV-03のC2）

5. UEV-06 の禁則 X1（ルールが厳しい × デッキ登録なし）・X5（厳しい × 当日に登録）：業務フロー3-1・3-3 を根拠にしているが、0214 のイベントの「ルール適用度」（単一選択）と日程の「デッキ登録あり」（チェックボックス）は互いを制約しない。イベント登録から開催まで（UEH-01・02）は、設計書に定めが無いとして同じ組を禁則にしていない。UEV-06 の禁則を見直すか（組を許して期待値を記録とするか）は未決。なお、オンライン受付でない × ルールが厳しい（C1）は、C1 が「全員分の出力」（3-1。R143 のオンライン受付の続きに置かれ、R144 は「競技イベントの場合」）と「登録デッキの確認」（3-3。R156 は「ルールが厳しい場合」）の別の条件を1つの水準にまとめたもので、オンライン受付のないイベントでは前者が無く後者だけが残る。禁則にはしていない（X1・X4・X5 の重なりで、この組の行はもともと成り立たず、マトリクスの行には出ない）。C1 を2つの水準に分けるかは、通しシナリオ UTH-04 のように競技イベントとルールの厳しさを別の因子にするか含めて未決。見たもの：業務フロー08 3-1・3-3、0214 イベント編集の項目、イベント登録から開催まで/review/dispositions_R1.md #3・R3.md
6. UEV-07・UEV-06 と、デッキ登録 UDK-02・イベント登録から開催まで（UEH）の重なり：(a) UEV-07 の起点は「マイイベント・デッキ登録の一覧で『デッキ登録』『デッキ編集』を押す」だけ（22行）。UDK-02 の起点は一覧「または申込完了画面」からの操作（デッキ登録/scenario_list.md 17行）で、起点が重なるのは一覧からの登録に限り、申込完了画面からの登録は UDK-02 側だけに位置づける。UEV-07 は一覧のボタンの出る・出ない条件、UDK-02 は提出の中身（デッキリストの入れ方・提出の回・内容）を主にしており、どちらに寄せるかは取りまとめで確かめる（イベント登録から開催まで UEH-03 は中身を UDK-02、条件を UEV-07 に任せる）。(b) UEV-06 の「会員登録済み×申込時にデッキ登録」は UEH-01（申込直後にデッキを登録）と、「オンライン受付でない×新規会員×当日にデッキを登録」の行は UEH-04（オンライン受付なしのイベントで当日に会員登録してデッキを登録）と、開催日の受付〜ポイント付与が重なる。「オンライン受付×会員登録済み×当日にデッキを登録」の行（`matrix_UEV-06/matrix.md` のT03）は UEH-04（オンライン受付なし）にも UEH-03（開催日の前の登録）にも当たらず、UEV-06 だけが通す。UEV-06 に寄せるか UEH に寄せるかも未決（現状は両方で通し、EX2〜EX4 の期待値は共通）
7. UEV の参加ポイント（UEV-06）の額と付与の運用：額は端末側で決まり EC に定めが無い（イベントの種類ごとの額・日程ごとの付与・付与のタイミング）。イベント登録から開催まで（UEH）の判断待ちと同じ論点で、UEH の L4 は試験用の値（50）を使う。売上登録（3-8）の EC への取り込みが無い点（食い違いに記録済み）も合わせて設計書の不足
