# UEV-09 店舗チームが管理画面のイベント新規申込登録で、プレイヤーの申込を登録する

| 項目 | 内容 |
|---|---|
| 利用者 | 店舗チーム（管理画面で申込を登録する。お客様は画面を触らない） |
| 目的 | 店舗チームが、管理画面のイベント申込登録で、権限のある店舗のオンライン受付ありの日程を探して「新規登録」を押し、プレイヤーを選んで申込を登録する。申込は「申込済み」・支払方法「管理者追加」・支払金額＝参加費で登録され、「保存しました」が出る。イベント申込一覧に載り、申込の数が1件増えて定員の空きが1つ減る。カード決済は通らず、決済中の状態もできない |
| 種類 | 正常（組み合わせ表なし。この1本）＋例外4件 |
| マトリクスの行 | なし。組み合わせ表は作らない（効き合う因子が2つに満たない。シナリオ一覧のL3の欄のとおり）。代表の1本は参加費が有料のイベント。参加費が無料でも、申込状況は申込済み・支払方法は管理者追加で変わらず、支払金額は参加費（無料は0円）になる（「L3で変わるところ」） |
| もとのシナリオ | なし（今のシナリオ SCN-EVENT-* に無く、2026-11-18 のレビュー指摘「イベント申込はフロントと管理画面のどちらからも可能」で足した）。業務フロー08に無い申込のもう1つの入口で、フロントからの申込はUEV-02（業務フロー08のシート「イベント受付(オンライン受付)」＃2-1）。設計書は0214のM13-11（イベント申込登録検索）・M13-12（イベント新規申込登録） |

管理画面で登録した申込のキャンセル・返金の扱いは設計書に定めが無いので、シナリオに入れない。開催日の受付はUEV-06。

## 前提

- 共通の決まり：`../L4を流すときの共通の決まり.md` を先に読む（試験データの名前にシナリオIDを付ける・共有の設定は元に戻す・バッチの起動・店舗の読み替えなど）
- システムの外で済んでいること：なし（外部の決済は通らない）
- 日程の日時は、実行日の1日の中で通せるように決める（試験用）。管理画面の登録は、オンライン受付の期間に関係なく行える。日時は実行時刻に合わせて前後にずらしてよい
- 用意するデータ（試験用の値。設計書の値ではない）
  - 店舗の読み替え：流す前に、開発環境の既存の店舗から、イベントの開催店舗にでき、店舗チームの担当者に編集権限を付けられる店舗を1つ選び、店舗IDと画面に出る名前を控える。店舗は新しく作らない（本店は店舗ID 1で、画面によって「Hareruya」「トーナメントセンター 東京」と出る）。以下の「店舗A」は、控えた名前に読み替える
  - 店舗チームの担当者（開催店舗「店舗A」の編集権限がある。メンバーのデフォルト表示の店舗が店舗A）
  - 会員：試験 十郎（本会員、メールアドレス `uev-09@example.test`、国内（東京都）の住所を登録済み、選手情報あり。プレイヤー検索で名前から探せる）、試験 十一郎（メールアドレス `uev-09-b@example.test`、同じ条件。例外EX2で使う）
  - イベント「シナリオ試験 スタンダード大会（有料）」（英語名 Scenario Test Standard Tournament）：店舗＝店舗A、フォーマット＝スタンダード、ルール適用度＝競技、イベント規模＝定番イベント、公開状態＝公開、定員＝8、チーム戦＝オフ、支払方法＝クレジットカード決済、参加費＝1,000円
  - 日程1：開始＝実行日20:00、受付あり（受付時間 19:30〜19:50）、デッキ登録あり・デッキ登録締切＝実行日19:00、デッキ登録を終了するはオフ、オンライン受付あり（開始＝実行日0:00、終了＝実行日19:00）、定員8・参加費1,000円・公開状態は親イベントを引き継ぐ
- 申込のあるイベント・日程は削除できないので、試験が終わったあとにイベントを消す場合は、申込を片付けてから行う
