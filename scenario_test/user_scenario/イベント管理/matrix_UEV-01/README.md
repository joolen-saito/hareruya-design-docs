# イベント管理のイベント登録（UEV-01）

IPA「高信頼化ソフトウェアのための開発手法ガイドブック」(2010) の表6-9〜6-11と同じ手順で作る。

1. 因子・水準表（FL表）: `fl_table.tsv`。利用者が画面で選ぶもの・変わるものを因子にし、設計書の文を根拠に持つ
2. 禁則表: `prohibitions.tsv`。ありえない組み合わせ
3. 組み合わせテストマトリクス: `matrix.md` / `matrix.tsv`。`build_matrix.py` が作る。1行が1本のシナリオになる
4. 例外の差し込み表: `exceptions.tsv`。エラーや中断（★の手順）は、正常な値と混ぜず、条件に合う行へ1つずつ差し込む

## 範囲

- 店舗チームがイベントを新規登録し、日程を追加し、バナーを設定して、お客様向けのイベント大会TOPに載るところまで（業務フロー1-1〜1-6）。権限のある店舗のメンバーが操作する
- 各行の期待値：イベント大会TOP（イベント一覧・日別・月別カレンダー）に、公開のイベントの公開の日程が出る。非公開・限定公開のイベント、非公開の日程は出ない。バナーを登録した行は、バナー設定の店舗・言語・表示タイプに合うとき、バナースライダーにも出る（バナー設定の枠はイベントに結び付かない。設計書 0307 は「開催日当日または開催前で、かつ公開状態のイベントに登録されているバナーを表示する」とするが、新実装のバナー検索には店舗・言語・表示タイプ・画像URLの条件だけがあり、イベントの公開状態・開催日の条件は無い。scenario_list.md の食い違い）。イベント編集のバナーURLは大会詳細の最上段に出る（日程が公開のとき）。特別イベント・大型イベントは特別イベントのグループ、おすすめイベントはおすすめのグループ、それ以外は定番のグループに出る。無料イベントはアイコンが付く
- 画面に出るのは、同じ店舗・同じ月の取得結果が60秒間キャッシュされる環境では、登録の60秒後以降（0307 イベント大会TOP 業務ロジック）
- 因子に入れなかったもの：複製新規（M13-05。業務フローに無い）、イベントCSV一括登録（業務フロー1-2に「CSVで一括登録するように運用切り替えを検討中」とあるだけで、まだ運用していない）、フォーマット・ルール適用度・フリー入力エリア（表示する文言が変わるだけで、業務の流れは変わらない）、バナー画像の作成（デザイン室。システムの外）

## 実装・設計書で確かめたこと（2026-11-03）

- 限定公開：設計書に画面側の出し分けが無い。新実装は、イベントと日程の両方が「公開」のときだけイベントTOP・詳細・別日程の候補に出す（新実装 DtbEventDetailRepository の表示条件）。限定公開は非公開と同じに見える
- イベント規模：0214「大型イベント 特別イベント デイリーイベント おすすめイベント」、0307「特別・おすすめ・定番」、開発環境の規模マスタ「おすすめ・定番・特別・大型」。デイリー＝定番と読んだ
- バナーは2か所ある。イベント編集のバナーURL（日・英）は大会詳細の最上段、バナー設定の15枠はイベントTOPのバナースライダー（0307 イベント大会TOP「バナー設定に設定されているイベントバナーから店舗と表示タイプが「スライド」で検索し表示する」）
- Wordpressのイベントカレンダー・バナーは、業務フロー08にWordpressの処理が無く、設計書にも出典が無いので入れない
- 繰返日程追加で作った日程は親イベントの公開状態になる。あとから日程編集で非公開にする場合は水準D2（A1の日程登録・日程編集）で扱う

## まとめた水準

なし（どの水準も処理が違う）。主な根拠：イベント規模の大型は新実装の検索カードに専用タグ（_search_event_card.twig の LARGE_ID 分岐）が付き特別と表示が違う。公開・非公開・限定公開は表示の出る出ないが違う。日程の追加方法・日程の公開状態・有料無料・チーム戦（人／組）も画面・処理が違う。
