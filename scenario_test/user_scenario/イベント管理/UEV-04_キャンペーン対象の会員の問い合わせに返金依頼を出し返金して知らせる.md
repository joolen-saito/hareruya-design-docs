# UEV-04 キャンペーン対象の会員が問い合わせ、店舗チームが返金依頼を出し、トレードチームが返金して知らせる

| 項目 | 内容 |
|---|---|
| 利用者 | お客様（申込済みの会員。キャンセルはしない）→ 店舗チーム（返金依頼フォームの入力・返金完了の連絡。システムの外）→ トレードチーム（返金処理。システムの外）→ メール |
| 目的 | キャンペーン対象（タイトルホルダー・女性などへの割引キャンペーン）の会員が、申込済みのまま問い合わせて返金対応を受ける。システムの中で通るのはお問い合わせの送信と受付だけで、返金依頼・返金処理・返金完了の連絡はシステムの外。返金の前後で、申込・定員・ポイントがECで変わらないことを確かめる |
| 種類 | 正常（組み合わせ表なし。この1本だけ） |
| マトリクスの行 | なし。シナリオ一覧のL3の欄は「—」（キャンペーン対象の有無で分かれる業務フローの分岐は、対象「有」だけをこのシナリオで通し、「無」はそのまま次のイベント受付～実施へ進む＝UEV-06）。キャンペーンの種類（タイトルホルダー・女性など）は割引の対象の違いで、システムの処理は変わらないのでまとめた |
| もとのシナリオ | SCN-EVENT-005（後段）。業務フロー08（イベント管理）のシート「イベント受付(オンライン受付)」＃2-9〜2-14 |

返金の手段はシステムの外（業務フローのシートに使うシステムの記載が無い。図形にSPLINKSのレーンはあるが矢印が無い）。新実装にも、イベントの返金・返金完了メールの処理は無い。

## 前提

- 共通の決まり：`../L4を流すときの共通の決まり.md` を先に読む（試験データの名前にシナリオIDを付ける・共有の設定は元に戻す・バッチの起動・店舗の読み替えなど）
- システムの外で済んでいること：キャンペーンの割引の運用（対象の会員にどの値引きをするかは店舗の運用で、システムに設定は無い）。参加者が使うクレジットカード（試験環境ではSPLINKSの試験決済画面で決済できるもの）。店舗チームが問い合わせのメールを見られる受信箱。返金依頼フォームの入力・返金処理・返金完了のメール送信（店舗チーム・トレードチームの手作業）
- 日程の日時は、実行日の1日の中で通せるように決める（試験用）。順序は、オンライン受付の開始＜申込を行う時刻＜オンライン受付の終了＜日程の開始
- 用意するデータ（試験用の値。設計書の値ではない）
  - 店舗の読み替え：流す前に、開発環境の既存の店舗から、イベントの開催店舗にでき、店舗チームの担当者に編集権限を付けられる店舗を1つ選び、店舗IDと画面に出る名前を控える。店舗は新しく作らない（本店は店舗ID 1で、画面によって「Hareruya」「トーナメントセンター 東京」と出る）。以下の「店舗A」は、控えた名前に読み替える
  - 店舗チームの担当者（開催店舗「店舗A」の編集権限がある）
  - 会員：試験 次郎（本会員、メールアドレス `uev-04@example.test`、国内（東京都）の住所を登録済み、選手情報あり、保有ポイントは手順に入る前の値を控える）。キャンペーン対象（タイトルホルダー）であることは、問い合わせの文面で示す
  - イベント「シナリオ試験 スタンダード大会（有料）」（英語名 Scenario Test Standard Tournament）：店舗＝店舗A、フォーマット＝スタンダード、ルール適用度＝競技、イベント規模＝定番イベント、公開状態＝公開、定員＝8、チーム戦＝オフ、支払方法＝クレジットカード決済、参加費＝1,000円
  - 日程1：開始＝実行日20:00、受付あり（受付時間 19:30〜19:50）、デッキ登録あり・デッキ登録締切＝実行日19:00、デッキ登録を終了するはオフ、オンライン受付あり（開始＝実行日0:00、終了＝実行日19:00）、定員8・参加費1,000円・公開状態は親イベントを引き継ぐ
- 試験が終わったあとにイベントを消す場合は、申込のある日程は削除できないので、片付けてから行う
