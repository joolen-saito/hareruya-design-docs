# 在庫管理の届いた在庫移動の入庫承認（UZK-07）

IPA「高信頼化ソフトウェアのための開発手法ガイドブック」(2010) の表6-9〜6-11と同じ手順で作る（FL表→禁則表→2因子間網羅の組み合わせ）。エラー・中断は `exceptions.tsv` で条件に合う行へ1つずつ差し込む。

## 範囲

- 移動中の在庫移動が入庫先に届き、入庫確認で差分を登録し、入庫承認申請→入庫承認で「入庫完了」になるまで（終点。開発環境の表示名は「入庫済み」）。出庫側は UZK-06
- 行ごとに、入庫完了後の在庫と原価の変化（出庫元・入庫先それぞれ）を確かめる。差分があるとき出庫元店舗のメーリングリストへ通知メールが送られ、入庫完了になった商品は入荷通知を行う（0202 在庫移動・振替登録 編集 (移動) 入庫承認画面）
- 入庫先が本店でも支店でも、設計書の入庫の処理は同じ。本店は「いったんすべて3Fに入庫し、あとで統合仕入れで振り分ける」ので、入庫先の違いは因子にしない（0202 在庫移動・振替登録 編集(振替) 入庫時振り分けについて）

## 実装・設計書で確かめたこと（2026-11-03）

- 入庫の状態：入庫承認待ち→入庫完了（開発環境「入庫済み」）。入庫再確認で移動中に戻る。別添資料の状態遷移概要（2025-09-18）の「差し戻し」系は、あとの改訂（2026-02-06）で入庫承認待ち・入庫再確認に置き換わり、開発環境にも無い
- 新実装に入庫承認・入庫再確認・入庫承認申請・差分商品の追加を行う処理がある（在庫移動の入庫承認の各処理）
- 差分の向きと在庫・原価の扱い（不足・過剰で出庫元に差し引ける／差し引けない）は設計書に式と例がある。マトリクスの各行で、入庫先の在庫数・総原価が設計書の式どおりになることを期待値にする。出庫元の在庫・原価が変わるのは不足と、過剰で差し引ける場合だけで、差し引けない過剰（B4）では出庫元は何もしない（0202 入庫承認画面「引き当てできないので何もしない」）

## まとめた水準

なし（どの水準も処理が違う）。主な根拠：欠品の有無は実移動点数が違い、差分なし・不足・過剰（出庫元から差し引ける・差し引けない）・商品の種類違いは設計書が処理を別に定めている。画面登録・CSV登録・差分を登録しないも入口と処理が違う。
