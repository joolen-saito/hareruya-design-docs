# UZK-05 在庫を結合してオリパ・福袋・詰め合わせなどを作り、承認して入庫する

| 項目 | 内容 |
|---|---|
| 利用者 | トレードチーム／商品管理チームの担当者（結合先の商品を登録→結合登録・結合元の登録・欠品の登録）→ 在庫の承認者（別の担当者） |
| 目的 | 結合して作る商品（オリパ・福袋・デッキセット・詰め合わせ）を結合先に選んで結合登録し、結合元の商品を登録して（必要なら欠品を登録して）承認申請し、承認者の承認で結合元の在庫が減り、結合先の在庫が増えて入庫完了（画面の表示は「入庫済み」）になる。却下すると結合元の在庫が戻る |
| 種類 | 正常（承認）／却下 |
| マトリクスの行 | `matrix_UZK-05/matrix.md` のT02（結合して作る商品＝オリパ・福袋（結合元は6種類以上）・結合元の欠品登録＝あり・結合の承認結果＝承認）。T01・T03〜T06は「L3で変わるところ」 |
| もとのシナリオ | SCN-ZAIKO-022・029・030 |

## 前提

- 共通の決まり：`../L4を流すときの共通の決まり.md` を先に読む（試験データの名前にシナリオIDを付ける・共有の設定は元に戻す・バッチの起動・店舗の読み替えなど）
- システムの外で済んでいること：結合して作る商品（オリパ）の商品登録（業務フロー12の1-④-1。商品登録・編集の UPR-04 と同じ手順）。ピック作業・結合作業（カードを集めて袋に詰める）は、この試験では画面の外の作業
- 用意するデータ（試験用の値。設計書の値ではない。行ごとに別の商品を使う）
  - 結合先：オリパ「シナリオ試験オリパD」（商品コード「UZK05-T02-OR」、5枚入り、本店・EC-CUBE在庫）。在庫0
  - 結合元（6種類）：カード「シナリオ試験カードF1」〜「F6」（商品コード「UZK05-T02-F1」〜「F6」）。それぞれ在庫20・原価単価20円・総原価400円
  - 登録担当（トレードチーム）と、在庫の承認者（別の担当者。承認通知先に入る）
- 結合数：10（5枚入りを10個＝カード50枚）。結合元在庫数：F1〜F4が各10、F5・F6が各5（合計50）

## 操作の流れと期待値

| # | 操作する人と操作 | 期待値（画面で見えること） |
|---|---|---|
| 1 | 登録担当：管理画面の在庫管理＞在庫一覧で、商品名「シナリオ試験オリパD」を検索し、店舗「本店」・在庫区分EC-CUBEの行にチェックを入れ、「在庫結合登録」を押す（業務フロー12の1-④-2。設計書は結合先を選んで結合登録する形で、業務フロー図の「結合元を選んで結合先を選ぶ」とは順序が違う。設計書を優先） | 「在庫結合 新規登録」の画面が開く。結合先商品に、商品名・商品コード・在庫数0が出る。ステータスの欄は「-」。結合数の入力欄が必須で出る |
| 2 | 登録担当：結合数に10を入れ、「登録」を押す | 「在庫結合を開始しました。」が出る。結合元を登録する画面に変わり、ステータスが「新規登録」になる。ステータス変更履歴に「新規登録」が残る。結合先の在庫は0のまま |
| 3 | 登録担当：「結合元商品登録」（商品の検索の画面）から「シナリオ試験カードF1」〜「F6」を1つずつ決定し、結合元在庫数にF1〜F4は10、F5・F6は5を入れる（1-④-2。内容がランダムな商品なので、結合元は5種類ではなく6種類以上） | 結合元商品の一覧に6商品が並ぶ。結合元商品（結合元在庫数の合計）が50、総原価の合計が1,000円になる。結合元在庫数が各商品の在庫数を超えるとエラーになる（この手順では超えない）。この時点では結合元の在庫は減らない |
| 4 | 登録担当：画面下の「結合元商品登録」を押す（1-④-2「結合元の在庫をおさえる」） | 欠品を入力する画面（在庫結合 欠品入力）に変わり、ステータスが「結合元登録」になる。結合元の在庫が減る：F1〜F4は在庫10、F5・F6は在庫15。結合元の総原価の合計に合わせて仕入総価格が決まる |
| 5 | 登録担当：ピックして結合元のカードを集め、F6が1枚足りないことが分かったので（欠品あり。ピックと検品はシステムの外の作業。1-④-3）、F6の行の欠品点数に1を入れて「欠品登録」を押す | 欠品点数が仮登録され、「欠品登録」ボタンが「取り消し」に変わる。欠品点数が結合元在庫数（5）以上だと登録できない（「欠品点数は結合元在庫数（5点）より小さく入力してください。」）。仮登録の間は在庫は変わらない |
| 6 | 登録担当：承認通知先（所属・メンバー）に承認者を選び、「承認申請」を押し、確認（「この操作はあとから取り消すことができません。在庫結合計画を承認申請してよろしいですか？」）で承認申請を実行する | 「承認申請しました。」が出る。ステータスが「結合承認待ち」になり、結合の承認の画面（在庫結合 承認）に変わる。承認者に通知メールが届く。F6に欠品1点が登録され、在庫履歴にF6の「欠品減算(結合)」と「欠品加算(結合)」（欠品による減算／加算 在庫結合分割番号）の2行が残る（欠品の調整。F6の在庫は15のまま） |
| 7 | 承認者：在庫管理＞在庫分割結合一覧で、種別「結合」・ステータス「結合承認待ち」の結合（手順6のもの）のIDを押し、結合の承認の画面を開く。「承認」を押し、確認（「この操作はあとから取り消すことができません。在庫結合を承認してよろしいですか？」）で「承認する」を押す（1-④-4） | 承認の画面で、結合先オリパの結合数10、結合元6商品の数量とF6の欠品点数1が確かめられる。承認すると「承認しました。」が出て、ステータスが「入庫済み」（設計書の「入庫完了」）になり、結合承認日・結合承認者が出る |
| 8 | 承認者：在庫管理＞在庫一覧で、結合先オリパと結合元6商品の在庫・原価を確かめる。在庫履歴一覧で「UZK05-T02-OR」を検索する | オリパの在庫が0から10になる。総原価は980円（結合元の総原価の合計1,000円から、欠品1点の原価20円を除いた額。原価単価98円）。F1〜F4は在庫10、F5・F6は在庫15。オリパに「結合(加算)」（在庫結合による加算 結合元：… 結合先：UZK05-T02-OR 在庫結合分割番号：…）、結合元に「結合(減算)」の履歴が残る |
| 9 | 承認者：在庫分割結合一覧で同じ結合を検索し、「在庫分割結合CSV出力」を押す | 結合が1行でCSVに出る。列「分割元・結合先商品名」に「シナリオ試験オリパD」、列「分割元・結合先点数」に結合数10が入る（ほかにID・タイプ・店舗・在庫区分の列。0202 在庫分割結合情報CSV出力 M04-14） |
| 10 | 商品管理チーム：結合先のオリパの商品を公開にする。次のフィードがユニサーチに載ったあとに検索する（結合の承認の時点では検索に出ない。公開とフィードは UPR-04・UPR-05・UTH-01 の区間②③⑥⑦） | 公開して次のフィードが載るまでは、お客様の検索に出ない。載ったあとは検索結果に在庫10で出る |
