# UZK-10 棚卸結果を取り込み、差異を確認して在庫に反映する

| 項目 | 内容 |
|---|---|
| 利用者 | 店舗の担当者（棚卸）→ 棚卸結果を取り込む担当者 → 在庫反映の権限のある人 |
| 目的 | 棚卸計画に棚卸の結果（棚卸数量）を登録し、差異のある商品の差異を確認し、権限のある人が在庫反映を実行して、差異のあった商品の在庫が増減し、棚卸計画に在庫反映日が入って、計画が編集できなくなる |
| 種類 | 正常／例外（反映できない場合） |
| マトリクスの行 | `matrix_UZK-10/matrix.md` のT04（業務フローのパターン＝棚卸作業・棚卸商品の在庫差異＝差異あり（差異確認＆完了ボタンで確認済みにする）・既定の在庫数を超える分の扱い＝送ると決めた分がない）。T01〜T03と例外E1〜E5は「L3で変わるところ」 |
| もとのシナリオ | SCN-ZAIKO-006・019・038 |

## 前提

- 共通の決まり：`../L4を流すときの共通の決まり.md` を先に読む（試験データの名前にシナリオIDを付ける・共有の設定は元に戻す・バッチの起動・店舗の読み替えなど）
- UZK-09 の終点を使う（棚卸計画が作られ、棚卸商品が3つ登録されている状態。在庫反映日は空）。T04は UZK-09 のT04（棚卸名「シナリオ試験棚卸04（UZK09-T04）」、商品コード「UZK09-T04-A」〜「C」）の終点を使う。ここでは商品の在庫を A=5、B=3、C=2、原価単価はどれも100円（総原価はそれぞれ500・300・200円）とする。T01〜T03も UZK-09 の同じ番号の行の終点
- 用意するデータ（試験用の値。設計書の値ではない）
  - 棚卸数量（店舗の棚卸の結果）：A=5（差異なし）、B=4（1点多い＝差異+1）、C=1（1点少ない＝差異-1）
  - 棚卸結果を取り込む担当者と、在庫反映の権限のある人（別の担当者でよい。棚卸計画の店舗の編集権限がある）
- 画面の名前は新実装の表示で書く（設計書の「棚卸在庫確認」は画面の「棚卸在庫確認」、「棚卸在庫反映」は「棚卸在庫反映」）
