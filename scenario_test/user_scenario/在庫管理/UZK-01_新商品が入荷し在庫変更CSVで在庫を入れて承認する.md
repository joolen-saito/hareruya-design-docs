# UZK-01 新商品が入荷し、在庫変更CSVで在庫を入れて承認する

| 項目 | 内容 |
|---|---|
| 利用者 | トレードチームの担当者（在庫変更CSVを作って登録する）→ 在庫の承認者（別の担当者）。入荷待ちを登録した会員のお客様は、入荷通知メールの確認だけ |
| 目的 | 商品登録を終えた新商品が入荷したあと、在庫情報CSVを出して在庫変更CSVを作り、在庫変更CSV登録で取り込み、承認者の承認で在庫に入れる。却下すると在庫は変わらない |
| 種類 | 正常（承認）／却下 |
| マトリクスの行 | `matrix_UZK-01/matrix.md` のT01（在庫変更CSVの作成先＝本店システム用（店舗を本店にして取り込む）・在庫編集承認の結果＝承認済）。T02は「L3で変わるところ」 |
| もとのシナリオ | SCN-ZAIKO-001 |

## 前提

- 共通の決まり：`../L4を流すときの共通の決まり.md` を先に読む（試験データの名前にシナリオIDを付ける・共有の設定は元に戻す・バッチの起動・店舗の読み替えなど）
- システムの外で済んでいること：商品の登録（商品登録・編集の UPR-04 の T01 と同じ手順。新弾以外の新商品）と、商品が店に入荷していること。この試験用の値は設計書の値ではない
- 用意するデータ（行ごとに別の商品を用意する。入庫すると在庫が0でなくなり、同じ商品を続けて使えないため）
  - 商品：サプライ「シナリオ試験サプライZ」商品コード「UZK01-T01」（T02は「UZK01-T02」。商品名は末尾の数字だけ変える）。在庫0・本店で公開
  - 登録担当と、在庫の承認者（別の担当者。在庫編集の承認権限があり、登録担当の承認通知先に入る。登録した本人は承認できない）
  - 会員：「試験 三郎」（メールアドレス `uzk01@example.test`、本会員）。入荷通知メールの許可（システム設定）が有効
  - 入庫：在庫変更CSVで5点（列は商品コード・在庫増減数・仕入単価。仕入単価は300円）。ファイル名は、過去1か月以内に登録した在庫変更CSVと別の名前にする（同じ名前だと「過去1か月以内に同じファイル名の在庫変更CSVが登録されています。」が出る）
- 在庫が承認されるまでは在庫0のまま
- 画面の名前は新実装の画面の表示で書く。設計書の名前が違うものは添える（例：在庫検索一覧＝画面は「在庫一覧」）

## 操作の流れと期待値

| # | 操作する人と操作 | 期待値（画面で見えること） |
|---|---|---|
| 1 | システムの外の作業：商品が入荷した | 画面の変化は無い |
| 2 | お客様：本店にログインし、商品一覧で「シナリオ試験サプライZ」を探し、在庫が無いので「入荷時に通知」を押し、確認のポップアップで依頼する（入荷通知は UZK-02 で細かく確かめる。ここは手順9で「通知が2通目にならない」ことを確かめる前提づくり） | ボタンが「通知待ち」に変わる |
| 3 | 登録担当：管理画面の在庫管理＞在庫一覧で、商品名「シナリオ試験サプライZ」を検索し、「在庫情報CSV出力」を押す（業務フロー12の1-①-1「在庫検索一覧から在庫変更CSV用のCSVを出力する」。画面には「在庫情報カスタムCSV出力」もあるが、ここは「在庫情報CSV出力」） | 検索結果に商品が出る（在庫0）。CSVがダウンロードされ、商品コード「UZK01-T01」が入っている（列は商品ID・商品名・コード・店舗・在庫区分・基準価格・販売価格・買取価格・在庫・原価単価・総原価など） |
| 4 | 登録担当：在庫変更CSVを作る（システムの外の作業。1-①-2「インポート用CSVに手動で商品の原価と数量を入れてインポートCSVを作成する」）。出力したCSVの商品コードを使い、在庫増減数5・仕入単価300を書く（列は商品コード・在庫増減数・仕入単価） | 画面の変化は無い。在庫情報CSVの列と在庫変更CSVの列は同じ形でないので、商品コードだけを移して2列を書き足す |
| 5 | 登録担当：在庫管理＞在庫変更CSV登録を開く。店舗「本店」・在庫場所「EC-CUBE」・在庫変動区分「入庫/問屋仕入」を選び、在庫変動理由に「新商品入荷」と書き、承認通知先（所属・メンバー）に承認者を選ぶ。「ファイルを選択」で手順4のCSVを選び、「一括登録を実行」を押す（1-①-3「在庫変更」） | 登録される。「在庫変更CSV登録履歴（承認テーブルの情報を参照）」に、ファイル名・店舗/在庫場所「本店/EC-CUBE」・対象商品規格数1・合計在庫増減数5・在庫変動区分「入庫」・登録者が出て、承認状態は「承認待ち」。在庫編集承認一覧には、承認状態「未承認」・承認対象「在庫変更CSV登録」で出る。承認者のメールアドレスに通知メールが届く。この時点で在庫は0のまま（入庫は承認されるまで在庫に入らない） |
| 6 | 承認者：在庫管理＞在庫編集承認一覧を開く。登録担当が登録した行にチェックを入れ、「一括承認」を押す（設計書の画面項目は「承認」）。確認の画面（「この操作はあとから取り消すことができません。選択した内容を確認してください。」）に出る明細を確かめ、「承認する」を押し、最後の確認「本当に承認してもよろしいですか？」で「OK」を押す（1-①-4「承認」） | 登録した行は、登録者がログイン中のユーザーではないので、チェックボックスが出て選べる。確認の画面の明細に、商品名・商品コード「UZK01-T01」・変更前在庫0・変更後在庫5・在庫増減数5・仕入単価300・総原価増減数1,500が出る。承認すると承認状態が「承認済」になり、承認日・承認者が出る。登録担当のメールアドレスに承認ステータス変更のメールが届く |
| 7 | 登録担当：在庫管理＞在庫一覧で「UZK01-T01」の商品を検索し、店舗「本店」・在庫区分EC-CUBEの行の在庫・原価単価・総原価を見る。続けて、その行の「在庫変動履歴」を開く | 在庫が5、原価単価300、総原価1,500になっている。在庫変動履歴に、入庫（子区分「問屋仕入」）の行（変更前在庫数0・変更後在庫数5・増減数5）が残る。在庫履歴一覧（在庫管理＞在庫履歴一覧）で商品コード「UZK01-T01」を検索しても同じ行が出る |
| 8 | お客様：メールの受信箱（`uzk01@example.test`）を開く。続けて、本店のフロントで商品一覧から「シナリオ試験サプライZ」を探す | 在庫が0から5になったので入荷通知メール（【販売】在庫入荷通知）が1通届く（細かい確かめは UZK-02）。商品一覧に在庫5が出る |
| 9 | 登録担当：手順3〜6と同じ操作で、同じ商品に在庫変更CSVを2回目として入庫3点（別のファイル名）取り込み、承認者が承認する。続けて、お客様の受信箱を見る | 承認で在庫が8になる。在庫が1以上ある商品の入庫の承認なので、入荷通知メールは新しく届かない（入荷通知は在庫が0から1以上になったときだけ送る。通知後も入荷待ち商品一覧の「通知待ち」は残る。新実装の動き。設計書に定めが無く記録） |
