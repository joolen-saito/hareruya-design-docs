# 在庫管理の入荷・仕入れしたカードの在庫変更CSV登録と承認（UZK-02）

IPA「高信頼化ソフトウェアのための開発手法ガイドブック」(2010) の表6-9〜6-11と同じ手順で作る（FL表→禁則表→2因子間網羅の組み合わせ）。1行が1回ずつ流すテスト1本で、行の中の水準は条件ごとに1つ（2026-11-09 に scenario_list.md の L3 欄で「／」で並べていた値を分けた）。

## 範囲

- 入荷・仕入れしたカードを打ち込み、在庫変更CSVを登録して承認（または却下）されるまで。手順の前段は UZK-01 と同じ
- 承認で本店のEC在庫が0から1以上になったとき、入荷待ちを登録した本会員に入荷通知メールが届くことを、承認される行の1本で確かめる（前提と受信の確認は scenario_list.md の UZK-02 の行）

## まとめた水準

なし（どの水準も処理が違う）。主な根拠：既存商品入荷・仕入れ作業・パック開封後の打ち込みは業務フローの別の工程で、依頼して登録するか自分で登録するかは登録者が違い、承認・却下は承認状態の遷移が違う。
