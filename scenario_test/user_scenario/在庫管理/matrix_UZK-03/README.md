# 在庫管理の分割先が分かっている商品の分割と承認（UZK-03）

IPA「高信頼化ソフトウェアのための開発手法ガイドブック」(2010) の表6-9〜6-11と同じ手順で作る（FL表→禁則表→2因子間網羅の組み合わせ）。1行が1回ずつ流すテスト1本で、行の中の水準は条件ごとに1つ（2026-11-09 に scenario_list.md の「分割先が1商品だけ／2商品登録して片方を削除」などの並びを分けた）。

## 範囲

- 分割対象の商品を在庫検索一覧で選んで分割登録し、分割先を登録して承認申請→承認（または却下）されるまで。分割先が1件も無いときの承認申請エラーは、分割先が1商品だけのときの対比として scenario_list.md に書いたもので、このマトリクスの水準にはしない
- スマレジへの在庫の反映は行わない（EC-CUBEからスマレジへの在庫連携は行わない：2026-11-18 レビュー指摘）

## まとめた水準

なし（どの水準も処理が違う）。主な根拠：ボックスのパック分割とデッキセットなどの解体は元の商品の種類が違い、分割先の画面登録とCSV登録は入口が違い、1商品だけ・削除は分割先の明細が違い、承認・却下は分割元の在庫が減るか戻るかが違う。

## 禁則

分割先商品の削除は、画面で登録した分割先商品に出る削除ボタンで行う（scenario_list.md の UZK-03 の行）ので、CSVで登録する水準とは組まない。
