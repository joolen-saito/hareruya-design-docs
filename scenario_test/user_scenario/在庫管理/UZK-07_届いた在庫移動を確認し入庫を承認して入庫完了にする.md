# UZK-07 届いた在庫移動を確認し、入庫を承認して入庫完了にする

| 項目 | 内容 |
|---|---|
| 利用者 | 入庫先の担当者（トレード／店舗／支店。着荷の解体・検品・入庫確認・承認申請）→ 入庫承認者（別の担当者）。差分があるとき、出庫元は通知メールを受け取る |
| 目的 | 移動中の荷物が届いたあと、入庫確認で数量を確かめ（差分があれば登録し）、承認申請して入庫承認を受け、入庫完了（画面の表示は「入庫済み」）にする。入庫先の在庫が増える。差分があれば出庫元へ通知メールが届く |
| 種類 | 正常（入庫承認）／例外（入庫再確認など） |
| マトリクスの行 | `matrix_UZK-07/matrix.md` のT01（出庫時の欠品＝なし・入庫時の差分＝差分なし・差分の登録方法＝差分を登録しない）。T02〜T10と例外E1〜E3は「L3で変わるところ」 |
| もとのシナリオ | SCN-ZAIKO-002〜005 |

## 前提

- 共通の決まり：`../L4を流すときの共通の決まり.md` を先に読む（試験データの名前にシナリオIDを付ける・共有の設定は元に戻す・バッチの起動・店舗の読み替えなど）
- UZK-06 の終点を使う（ステータス「移動中」の在庫移動）。商品コードを行ごとに「UZK07-T01」〜「UZK07-T10」に変えて、UZK-06 のT01（欠品なし）またはT03（欠品あり）と同じ手順で、移動中まで進めておく。区分はEC-CUBE
  - T01〜T05（欠品なし）：UZK-06 のT01の終点。出庫元＝試験支店・入庫先＝本店バックヤード（3F。トレード宛。UZK-06の店舗の対応）。移動点数3・出庫総原価300円（原価単価100円）。出庫元の在庫は登録時に5から2へ減っている。入庫先の本店バックヤードの在庫0。送り状No.登録済み
  - T06〜T10（欠品あり）：UZK-06 のT03の手順で、欠品点数1を登録して承認された終点（移動点数3・欠品点数1・実移動点数2）。出庫元の在庫は2
  - T04・T09（出庫元に在庫が無く差し引けない過剰）だけ、出庫元の登録前の在庫を3にしておき、移動点数3で出庫元の在庫を0にする
- 入庫先の入庫確認の担当者と、入庫承認者（別の担当者。承認権限があり、承認通知先に入る）
- システムの外で済んでいること：荷物が届き、解体・検品した（手順1）。画面の名前は新実装の表示で書く。完了の状態は設計書「入庫完了」・画面「入庫済み」
