# UZK-04 分割先が分からない商品を開封し、分割先を登録して承認する

| 項目 | 内容 |
|---|---|
| 利用者 | トレードチームの担当者（分割登録・開封・打ち込み・分割先の登録。安価なカードは商品管理チームが打ち込む）→ 在庫の承認者（別の担当者） |
| 目的 | パックを開封する（またはオリパを解体する）とき、先に分割元だけを分割登録して在庫を押さえ、開封して出たカードを分割先として登録して承認申請し、承認者の承認で分割元の在庫が減り、分割先のカードの在庫が増えて入庫完了（画面の表示は「入庫済み」）になる。却下すると分割元の在庫が戻る |
| 種類 | 正常（承認）／却下 |
| マトリクスの行 | `matrix_UZK-04/matrix.md` のT01（分割元の商品＝新品パックを開封してシングルカードとして登録する・分割の承認結果＝承認）。T02〜T04は「L3で変わるところ」 |
| もとのシナリオ | SCN-ZAIKO-028・031 |

## 前提

- 共通の決まり：`../L4を流すときの共通の決まり.md` を先に読む（試験データの名前にシナリオIDを付ける・共有の設定は元に戻す・バッチの起動・店舗の読み替えなど）
- システムの外で済んでいること：なし（開封の作業は手順3で行う）
- 用意するデータ（試験用の値。設計書の値ではない。行ごとに別の商品を使う）
  - 分割元：パック「シナリオ試験パックB」（商品コード「UZK04-T01-PK」、本店・EC-CUBE在庫）。在庫5・総原価2,000円（原価単価400円）。T02〜T04は別の商品コード
  - 分割先（開封して出たカード。どれも在庫0。買取価格は分割先の仕入総価格を決めるのに使う）：「シナリオ試験カードB1」（商品コード「UZK04-T01-C1」、買取価格100円）、「シナリオ試験カードB2」（「UZK04-T01-C2」、買取価格50円）、「シナリオ試験カードB3」（「UZK04-T01-C3」、買取価格30円）
  - 登録担当（トレードチーム）と、在庫の承認者（別の担当者。承認通知先に入る）
- 分割する数：1パック。開封の結果：カードB1が1枚、B2が1枚、B3が2枚（分割先在庫数）

## 操作の流れと期待値

| # | 操作する人と操作 | 期待値（画面で見えること） |
|---|---|---|
| 1 | 登録担当：管理画面の在庫管理＞在庫一覧で、商品名「シナリオ試験パックB」を検索し、店舗「本店」・在庫区分EC-CUBEの行にチェックを入れ、「在庫分割登録」を押す（業務フロー12の1-③-1。分割元のパックを選択） | 「在庫分割 新規登録」の画面が開く。分割元商品に、在庫数5・原価単価400・総原価2,000が出る |
| 2 | 登録担当：分割数に1を入れ、「保存」を押す（1-③-2「分割先を選択せずに分割データを登録」） | ステータスが「新規登録」の編集画面に変わる。分割元パックの在庫が5から4に減り、総原価が1,600円になる。分割先はまだ無い（「分割先が登録されていません」）。ステータス変更履歴に「新規登録」が残る |
| 3 | システムの外の作業：パックを開封し、出たカードをソートして打ち込み、別の担当者がWチェックする（1-③-3。他業務と同じ。安価なカードは商品管理チームが打ち込む）。開封の結果はカードB1が1枚、B2が1枚、B3が2枚 | 画面の変化は無い。分割元は新規登録のまま（日をまたぐ作業の間も、システムの状態は変わらず待っている） |
| 4 | 登録担当：分割先の商品を1つずつ追加する。「分割先を登録」から「シナリオ試験カードB1」を決定して分割先在庫数1、B2を決定して1、B3を決定して2を入れる（1-③-4・1-③-5。インポートファイルによる登録は結合テストで確かめる） | 分割先商品一覧に3商品が並ぶ。分割点数（分割先在庫数の合計）が4になる。まだ保存されていない |
| 5 | 登録担当：承認通知先に承認者を選び、「承認申請」を押し、確認で承認申請を実行する | 「承認申請しました。」が出る。ステータスが「分割承認待ち」になり、分割の承認の画面に変わる。承認者に通知メールが届く。分割先の仕入総価格が、分割先の買取金額の比率で按分されて決まる：カードB1が191円、B2が95円、B3が114円（合計400円＝分割元の出庫総原価。分割数1の分、総原価2,000円×1÷5＝400円。四捨五入のあとの端数1円は、買取価格が最も高いB1に足す）。承認申請より前は仕入総価格は決まらない |
| 6 | 承認者：在庫管理＞在庫分割結合一覧で、種別「分割」・ステータス「分割承認待ち」の分割（手順5のもの）のIDを押し、分割の承認の画面を開く。「承認」を押し、確認で「承認する」を押す（1-③-6「パックの数に対するカードの数が正しければ入庫済みにする」） | 承認の画面で、分割元パックの分割数1と、分割先3商品の数量（1・1・2）が出る。承認すると「分割の承認が完了しました。」が出て、ステータスが「入庫済み」になり、承認日・承認者が出る |
| 7 | 承認者：在庫管理＞在庫一覧で、分割元パックと分割先3商品の在庫・原価を確かめる | パックBの在庫4（総原価1,600円）のまま。カードB1の在庫1・総原価191円、B2の在庫1・総原価95円、B3の在庫2・総原価114円（原価単価57円）。分割先の在庫が増える |
| 8 | 承認者：在庫管理＞在庫履歴一覧で、パックとカード3商品のコードを検索する | パックに「分割(減算)」、カードB1・B2・B3に「分割(加算)」の履歴が残る（在庫変動理由に「在庫分割による減算/加算 分割元：UZK04-T01-PK 分割先：…」の形）。変更前・変更後の在庫が手順2・7の数と合う |
