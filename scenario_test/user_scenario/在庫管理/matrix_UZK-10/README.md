# 在庫管理の棚卸結果の取り込みと在庫反映（UZK-10）

IPA「高信頼化ソフトウェアのための開発手法ガイドブック」(2010) の表6-9〜6-11と同じ手順で作る（FL表→禁則表→2因子間網羅の組み合わせ）。1行が1回ずつ流すテスト1本で、行の中の水準は条件ごとに1つ（2026-11-09 に scenario_list.md の L3 欄で「／」で並べていた値を分けた）。

## 範囲

- 棚卸の数量を登録し、差異を確認して在庫に反映するまで。反映できない場合（在庫反映済み・商品数0・計上済み0・数が合わない・差異が未確認）は正常な値と組み合わせず、`exceptions.tsv` で1つずつ差し込む
- 既定の在庫数を超えて送ると決めた分は、在庫移動の登録（UZK-06 と同じ画面）でトレードチーム宛（本店3F）の店舗間移動として出庫承認待ちになるところまで確かめる。既定の在庫数の数値は店舗の運用で決める（システムの外）
- スマレジへの在庫の反映は行わない（EC-CUBEからスマレジへの在庫連携は行わない：2026-11-18 レビュー指摘）

## まとめた水準

なし（どの水準も処理が違う）。主な根拠：画面登録と棚卸商品数量登録CSVは入口が違い、差異の有無は差異確認＆完了ボタンの出方が違う。業務フローの棚卸業務（物品移動）と棚卸作業は別のパターンとして1本ずつ流す。
