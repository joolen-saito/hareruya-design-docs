IPA「高信頼化ソフトウェアのための開発手法ガイドブック」(2010) の表6-9〜6-11と同じ手順で作る（FL表→禁則表→2因子間網羅の組み合わせ）。1行が1回ずつ流すテスト1本で、行の中の水準は条件ごとに1つ（2026-11-09 に scenario_list.md の L3 欄で「／」で並べていた値を分けた）。

## 範囲

- 棚卸の範囲を決め、棚卸計画を作って棚卸商品を登録するまで（在庫反映日は空のまま）。数量の登録・差異の確認・在庫反映は UZK-10
- 手つかずピックが少ないときのTCチーム・通販チームの確認はシステムの外

## まとめた水準

なし（どの水準も処理が違う）。主な根拠：低額棚卸と低額以外は始め方（ファイルのダウンロード／トリガーファイル）が違い、画面登録と棚卸詳細登録CSVは入口が違い、手つかずピックが多いときは商品管理チームが範囲を照合する。業務フローの棚卸業務（物品移動）と棚卸作業は別のパターンとして1本ずつ流す。
