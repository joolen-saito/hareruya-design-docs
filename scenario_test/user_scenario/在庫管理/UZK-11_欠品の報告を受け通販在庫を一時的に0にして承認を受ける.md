# UZK-11 欠品の報告を受け、通販在庫を一時的に0にして承認を受ける

| 項目 | 内容 |
|---|---|
| 利用者 | TCチーム／通販チームの担当者（欠品の報告）→ トレードチーム・商品管理チームの担当者（欠品対応・在庫編集の登録）→ 在庫の承認者（別の担当者） |
| 目的 | 店舗や通販から欠品の報告が上がったとき、対象カードの通販在庫がある場合は、在庫編集で在庫変動区分「廃棄(欠品)」を登録して通販在庫を一時的に0にし、現物が売れないようにする。在庫は登録の時点で0に減り、承認で確定する。却下すると登録前の数に戻る。通販在庫が無いときは在庫を0にする登録をしない |
| 種類 | 正常（承認）／却下／通販在庫なし |
| マトリクスの行 | `matrix_UZK-11/matrix.md` のT01（欠品商品の通販在庫＝ある（在庫を一時的に0にして承認を受ける）・在庫編集の承認の結果＝承認済（在庫は0のまま確定する））。T02・T03は「L3で変わるところ」 |
| もとのシナリオ | SCN-ZAIKO-016・020 |

## 前提

- 共通の決まり：`../L4を流すときの共通の決まり.md` を先に読む（試験データの名前にシナリオIDを付ける・共有の設定は元に戻す・バッチの起動・店舗の読み替えなど）
- システムの外で済んでいること：なし（欠品の報告・欠品対応表の更新は手順1・2の外の作業）。非公開にする方法は新実装に無く、通さない（依頼者の決定：新実装に合わせる）
- 用意するデータ（試験用の値。設計書の値ではない）
  - 商品：カード「シナリオ試験カードL01」（商品コード「UZK11-T01」、NM・日本語、本店・公開）。本店のEC-CUBE在庫（通販在庫）が3・原価単価100円（総原価300円）。T02は「UZK11-T02」（同じ在庫3）、T03は「UZK11-T03」（本店のEC-CUBE在庫0）
  - 登録担当（トレードチームまたは商品管理チーム）と、在庫の承認者（別の担当者。承認権限があり、承認通知先に入る）
- 在庫は本店のEC-CUBE在庫を通販在庫として扱う（フロントは表示中の店舗のEC在庫を見る）

## 操作の流れと期待値

| # | 操作する人と操作 | 期待値（画面で見えること） |
|---|---|---|
| 1 | TCチームまたは通販チームの担当者：欠品が見つかったことを報告する。欠品対応表が更新され、トレードチームと商品管理チームが欠品対応を行う（業務フロー12の8-1。システムの外の作業。この時点で一時欠品状態になる） | 画面の変化は無い |
| 2 | 登録担当：2Fの商品棚を探しても該当カードが見つからないときは補充を検討する（補充する場合は必ずトレード社員の許可が必要。システムの外の作業。8-2） | 画面の変化は無い |
| 3 | 登録担当：管理画面の在庫管理＞在庫一覧で「UZK11-T01」を検索し、店舗「本店」・在庫区分EC-CUBE（通販在庫）の在庫を確かめる（8-3「在庫検索一覧から、在庫を確認する」） | 在庫が3。通販在庫があるので、在庫を一時的に0にする手順に進む |
| 4 | 登録担当：その行の操作から「在庫編集」を開き、在庫変動区分「廃棄/廃棄(欠品)」を選び、在庫変動理由に「欠品のため一時的に0」と書き、在庫増減数に-3を入れ、承認通知先（所属・メンバー）に承認者を選んで「登録する」を押す（8-3「対象カードの通販在庫がある場合は在庫を一時的に0にし、現物カードが売れないようにする」） | 在庫編集承認一覧に、承認状態「未承認」で登録される。承認者に通知メールが届く。**在庫は承認を待たず、登録の時点で0に減る**（廃棄の区分は在庫をロックする。計算は「登録時点での在庫数＋在庫増減数（マイナスの値）」）。在庫一覧の在庫が0、総原価が0円。在庫履歴に、廃棄の行（変更前3・変更後0・増減数-3、区分は廃棄(欠品)）が残る。承認前（この時点）で在庫が0になっていることを確かめる |
| 5 | お客様：本店のフロントで商品一覧から「シナリオ試験カードL01」を探し、商品の詳細を開く | 在庫が0なので購入できない（「カートに入れる」が出ない、または在庫なしの表示。現物カードが売れない）。購入できる状態にはならない |
| 6 | 承認者：在庫管理＞在庫編集承認一覧を開く。登録担当が登録した行にチェックを入れ、「一括承認」を押す。確認の画面で「承認する」を押し、最後の確認「本当に承認してもよろしいですか？」で「OK」を押す（8-3「在庫を0にする場合は承認が必要となる」） | 登録した行は、登録者がログイン中のユーザーではないので、チェックボックスが出て選べる。承認状態が「承認済」になり、承認日・承認者が出る。登録担当のメールアドレスに承認ステータス変更のメールが届く |
| 7 | 登録担当：在庫一覧で「UZK11-T01」の在庫を確かめる。在庫履歴一覧で同じ商品コードを検索する | 在庫は0のまま確定する（承認で変わらない）。在庫履歴の行は、手順4の1行のまま（承認で増えない） |

## 終わったあとに確かめること

| 確かめる場所 | 期待値 |
|---|---|
| 在庫編集承認一覧 | 手順4の登録が承認状態「承認済」。承認対象「在庫編集」 |
| 次の流れ | 補填カードの捜索・最終欠品の対応は UZK-12。在庫を一時的に0にした欠品商品を、カードが見つかったあとに戻す手順（承認の要否・在庫変動区分）は、業務フローにも設計書にも無いので、この試験の終点に入れない（scenario_list.md の食い違いに記録済み） |
| スマレジへの在庫の反映 | 確かめない（EC-CUBEからスマレジへの在庫連携は行わない：2026-11-18 レビュー指摘） |
