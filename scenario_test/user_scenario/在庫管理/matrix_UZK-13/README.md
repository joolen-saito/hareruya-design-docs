# 在庫管理の安価カードの在庫補充作業（UZK-13）

IPA「高信頼化ソフトウェアのための開発手法ガイドブック」(2010) の表6-9〜6-11と同じ手順で作る（FL表→禁則表→2因子間網羅の組み合わせ）。1行が1回ずつ流すテスト1本で、行の中の水準は条件ごとに1つ（2026-11-09 に scenario_list.md の L3 欄で「／」で並べていた値を分けた）。

## 範囲

- 安価カードの補充作業を始め、現在庫データをダウンロードし、補充用ファイルを作って、価格が付くカードは在庫移動（発送）で入庫完了、付かないカードは在庫変更依頼から在庫変更CSV登録の承認までを通す。この2経路は排他（scenario_list.md の UZK-13 の行）
- 補充用ファイルの作業（ファイルの並べ替え・バックヤード残数の反映）はシステムの外

## まとめた水準

なし（どの水準も処理が違う）。主な根拠：補充用ファイルのパターン1とパターン2は使うファイルが違い、価格が付くカードは在庫移動、付かないカードは在庫変更CSV登録で、付かない補充分を0円で入庫してから2F通販在庫へ移す経路は総原価の動きが違う。
