# UZK-15 廃棄する商品の在庫を減らし、承認を受ける

| 項目 | 内容 |
|---|---|
| 利用者 | 在庫を持つ各部署の担当者（在庫編集の登録）→ 在庫の承認者（別の担当者） |
| 目的 | 状態の変化・イベント賞品などで廃棄が発生したとき、在庫一覧から在庫編集を開き、在庫変動区分を廃棄の区分にして在庫を減らす。廃棄は登録（申請）の時点で在庫が減り、承認者の承認で確定する。却下されると在庫が戻る |
| 種類 | 正常（承認）／却下／例外（在庫を超える数） |
| マトリクスの行 | `matrix_UZK-15/matrix.md` のT03（廃棄の在庫変動区分＝廃棄(他事業移動)・在庫編集承認の結果＝承認済（在庫は減ったまま確定する）・廃棄する点数＝一部を廃棄する（在庫が5の商品に-2を入れて3が残る））。T01・T02・T04〜T10と例外E1は「L3で変わるところ」 |
| もとのシナリオ | SCN-ZAIKO-024 |

## 前提

- 共通の決まり：`../L4を流すときの共通の決まり.md` を先に読む（試験データの名前にシナリオIDを付ける・共有の設定は元に戻す・バッチの起動・店舗の読み替えなど）
- システムの外で済んでいること：廃棄する商品が決まっている（状態の変化・イベントの賞品など。業務フロー12の15-1。廃棄は在庫を有する各部署がそれぞれ行う）
- 用意するデータ（試験用の値。設計書の値ではない。行ごとに別の商品を使う）
  - 商品：カード「シナリオ試験カードP03」（商品コード「UZK15-T03」）。本店のEC-CUBE在庫が5・原価単価100円（総原価500円）。行ごとにコードを変える（T01は「UZK15-T01」…「UZK15-T10」）。全数を廃棄する行（T01・T04・T06・T07・T10）も在庫5で、-5を入れて0にする
  - 登録担当（在庫を持つ部署の担当者）と、在庫の承認者（別の担当者。承認権限があり、承認通知先に入る）
- 在庫増減数は-1以下で入れる（廃棄の場合は-1以下。0やプラスの数はエラー）

## 操作の流れと期待値

| # | 操作する人と操作 | 期待値（画面で見えること） |
|---|---|---|
| 1 | システムの外の作業：状態の変化やイベントの賞品などで廃棄が発生した（業務フロー12の15-1） | 画面の変化は無い |
| 2 | 登録担当：管理画面の在庫管理＞在庫一覧で「UZK15-T03」を検索し、店舗「本店」・在庫区分EC-CUBEの行の操作から「在庫編集」を開く（15-1「廃棄商品検索」。0202 在庫検索一覧(検索結果) 2-4） | 在庫編集の画面が開く。商品名・商品コード・店舗・在庫区分・在庫5・原価単価100・総原価500が出る。在庫変動内容として、在庫変動区分・在庫変動理由・在庫増減数・承認通知先の入力欄が出る |
| 3 | 登録担当：在庫変動区分「廃棄/廃棄(他事業移動)」を選び、在庫変動理由に「他事業へ移動のため」と書き、在庫増減数に-2を入れ、承認通知先（所属・メンバー）に承認者を選んで「登録する」を押す（15-2「在庫変動理由を廃棄にして在庫を減らす」「在庫変動理由が廃棄の場合は承認が必要」。例外E1） | 在庫編集承認一覧に、承認状態「未承認」で登録される。承認者に通知メールが届く。**廃棄は申請の時点で在庫が減る**（在庫をロックする）。在庫一覧で在庫が5から3になり、総原価が300円（原価単価100円）になる。在庫履歴に、廃棄の行（区分「廃棄(他事業移動)」・変更前5・変更後3・増減数-2）が残る。業務フローは「承認者が承認すると在庫が減る」と書くが、設計書の申請時に減る動きで確かめる（※5） |
| 4 | 承認者：在庫管理＞在庫編集承認一覧を開く。登録担当が登録した行にチェックを入れ、「一括承認」を押す。確認の画面で「承認する」を押し、最後の確認「本当に承認してもよろしいですか？」で「OK」を押す（15-2「廃棄商品在庫変動承認」） | 登録した行は、登録者がログイン中のユーザーではないので、チェックボックスが出て選べる。承認状態が「承認済」になり、承認日・承認者が出る。登録担当に承認ステータス変更のメールが届く |
| 5 | 登録担当：在庫一覧で「UZK15-T03」の在庫を確かめる。在庫履歴一覧で同じ商品コードを検索する | 在庫は3のまま確定する（承認で変わらない）。在庫履歴は手順3の1行のまま増えない |

## L3で変わるところ（マトリクスの他の行・例外）

手順の番号は上の「操作の流れと期待値」。在庫増減数は、一部を廃棄する行は-2（5→3）、全数を廃棄する行は-5（5→0）。却下の手順：承認者が「一括却下」を押し、確認の画面の却下理由に「試験の却下」と書いて「却下する」を押し、最後の確認「本当に却下してもよろしいですか？」で「OK」を押す。却下すると、承認状態が「却下済」になり、在庫が登録前の数に戻る（却下時点での在庫数＋（在庫増減数×−1））。在庫履歴に「廃棄(却下)」（廃棄却下による戻し 在庫編集ID：…）が残る。
