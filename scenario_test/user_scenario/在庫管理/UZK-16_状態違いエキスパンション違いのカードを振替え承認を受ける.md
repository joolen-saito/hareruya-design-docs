# UZK-16 状態違い・エキスパンション違いのカードを振替え、承認を受ける

| 項目 | 内容 |
|---|---|
| 利用者 | 在庫を持つ各部署の担当者（登録者。トレードチーム・支店・店舗チームなど）→ 承認者（登録者とは別の担当者） |
| 目的 | 在庫移動の入庫やフロア間移動のあとに、数量以外の差異（状態違い・エキスパンション違い）が見つかったとき、在庫一覧で振替元の商品を選んで在庫振替を登録し、承認者の承認で、振替元の在庫が減り、振替先の商品の在庫が増えて入庫完了（画面の表示は「入庫済み」）になる。却下されると振替元の在庫が戻る |
| 種類 | 正常（承認）／却下／例外（登録者本人は承認できない） |
| マトリクスの行 | `matrix_UZK-16/matrix.md` のT01（振替が必要になった起点と担当＝在庫リコメンドで入庫したあと数量以外の差異があり、トレードチームが振替を登録する・振替の承認結果＝承認）。T02〜T08と例外E1は「L3で変わるところ」 |
| もとのシナリオ | SCN-ZAIKO-025（005） |

## 前提

- 共通の決まり：`../L4を流すときの共通の決まり.md` を先に読む（試験データの名前にシナリオIDを付ける・共有の設定は元に戻す・バッチの起動・店舗の読み替えなど）
- システムの外で済んでいること：在庫移動で入庫したカードに、数量以外の差異（状態が違う）が見つかった（業務フロー12の2-17・16-1）。
- 前段の移動は、このシナリオの中で用意する（UZK-07・UZK-08の終点の商品とは別の商品を使う。操作は同じ）。振替元の商品・在庫は、前段の移動の入庫数で決まる
  - T01・T02：UZK-07のT01の手順（試験支店→本店バックヤード（3F。トレード宛）・EC-CUBE・移動点数3・差分なし・入庫済み）を、商品「UZK16-T01-NM」（出庫元の在庫3）で行う。もう1つ「UZK16-T01-NM2」は移動点数2（出庫元の在庫2）で行う。入庫後の本店バックヤードの在庫は3と2、原価単価100円
- 用意するデータ（試験用の値。設計書の値ではない。行ごとに別の商品を使う）。振替は同じ店舗・同じ在庫区分の中で行う
  - 振替元：カード「シナリオ試験カードQ01（NM）」（商品コード「UZK16-T01-NM」）。本店バックヤードのEC-CUBE在庫3・原価単価100円（総原価300円）
  - 振替先：同じカードの状態違い「シナリオ試験カードQ01（SP）」（商品コード「UZK16-T01-SP」）。本店バックヤードのEC-CUBE在庫0
  - 登録者（トレードチームの担当者）と、承認者（別の担当者。振替の承認権限がある）。支店の振替（T03・T04）では、試験支店の在庫の承認権限を持つ担当者を用意する
- 複数の商品を選んで一度に登録できる。この試験では、振替元を2つ（「UZK16-T01-NM」と「UZK16-T01-NM2」。後者は在庫2・振替先「UZK16-T01-SP2」）選ぶ
- 画面の名前は新実装の表示で書く（設計書の「在庫移動・振替登録 編集(振替)」は画面の「在庫振替」）。完了の状態は設計書「入庫完了」・画面「入庫済み」
