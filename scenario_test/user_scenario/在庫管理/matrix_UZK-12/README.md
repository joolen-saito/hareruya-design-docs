# 在庫管理の欠品カードの捜索対応（UZK-12）

IPA「高信頼化ソフトウェアのための開発手法ガイドブック」(2010) の表6-9〜6-11と同じ手順で作る（FL表→禁則表→2因子間網羅の組み合わせ）。1行が1回ずつ流すテスト1本で、行の中の水準は条件ごとに1つ（2026-11-09 に scenario_list.md の L3 欄で「／」で並べていた値を分けた）。

## 範囲

- 欠品の捜索依頼が届き、通販在庫スペースなどを確認して、補填カードが見つかって対応完了とするか、見つからず最終欠品として返金処理等を行うまで
- 17:30以降の依頼の振り分け（店内注文・事前は当日、通販・大口・社内移動は翌日）と、捜索を担当するチームの振り分け（レア度でトレード／商品管理）は、システムを触らない分岐なので水準にしない（網羅マトリクスの扱いは適用外）。返金は通販の UTS-02

## まとめた水準

なし（どの水準も処理が違う）。主な根拠：補填用のカードが無いときと欠品理由が特定できそうなときは確認する場所と順が違い、補填カードが見つかるときは了承を得て対応完了（システムの状態は変わらない）、見つからないときは最終欠品として返金処理等を行う。業務フローの欠品対応の2つのパターン（欠品報告から／欠品対応依頼の捜索対応）は始まりが違うので1本ずつ流す。
