# 在庫管理の在庫の結合と承認（UZK-05）

IPA「高信頼化ソフトウェアのための開発手法ガイドブック」(2010) の表6-9〜6-11と同じ手順で作る（FL表→禁則表→2因子間網羅の組み合わせ）。1行が1回ずつ流すテスト1本で、行の中の水準は条件ごとに1つ（2026-11-09 に scenario_list.md で「／」で並べていた値を分けた）。

## 範囲

- 結合して作る商品（オリパ・福袋・デッキセット・詰め合わせ）を登録し、結合元を登録して承認申請→承認（または却下）されるまで
- スマレジへの在庫の反映は行わない（EC-CUBEからスマレジへの在庫連携は行わない：2026-11-18 レビュー指摘）。結合先の商品が検索に出るのは公開とフィードのあと（scenario_list.md の UZK-05 の行）

## まとめた水準

なし（どの水準も処理が違う）。主な根拠：ランダム商品は6種類以上の結合元を選ぶ決まりがあり、ランダムでない商品・詰め合わせは作り方が違う。結合元の画面登録とCSV登録は入口が違い、欠品登録の有無は結合元の在庫の減り方が違い、承認・却下は結合元の在庫が減るか戻るかが違う。

## 外した因子・水準（2026-11-09 依頼者決定：画面の操作の違い）

業務が回るかを確かめるシナリオテストでは、業務の流れが分かれない画面操作の違い（画面かCSVか・作り方・出力形式・確認表示）は組み合わせ表から外し、結合テストに任せる。

- 因子 B「結合元の登録方法」を外した。理由：結合元を画面で登録するかCSVで登録するかは入力方法の違い。前提として残す代表：結合元は画面で登録する。
- 作り直し後：6行（2026-11-09 以前は6行）。rows=6 pair=100.00% (16/16) triple=50.00% (6/12)
- この節より上の文章（範囲・まとめた水準など）に外した因子・水準の名前が残る場合は、上の決定が優先する。
