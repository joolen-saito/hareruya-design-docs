# 在庫管理の分割先が分からない商品の開封と分割承認（UZK-04）

IPA「高信頼化ソフトウェアのための開発手法ガイドブック」(2010) の表6-9〜6-11と同じ手順で作る（FL表→禁則表→2因子間網羅の組み合わせ）。1行が1回ずつ流すテスト1本で、行の中の水準は条件ごとに1つ（2026-11-09 に scenario_list.md で「／」で並べていた値を分けた）。

## 範囲

- パックなど分割先が分からない商品を分割登録し、開封作業のあとで中身のカードを分割先として登録して承認申請→承認（または却下）されるまで
- スマレジへの在庫の反映は行わない（EC-CUBEからスマレジへの在庫連携は行わない：2026-11-18 レビュー指摘）

## まとめた水準

なし（どの水準も処理が違う）。主な根拠：パック開封とオリパの解体は分割元の商品の種類が違い、画面登録とCSV登録は入口が違い、承認・却下は分割元の在庫が減るか戻るかが違う。

## 外した因子・水準（2026-11-09 依頼者決定：画面の操作の違い）

業務が回るかを確かめるシナリオテストでは、業務の流れが分かれない画面操作の違い（画面かCSVか・作り方・出力形式・確認表示）は組み合わせ表から外し、結合テストに任せる。

- 因子 B「分割先の登録方法」を外した。理由：分割先を画面で登録するかCSVで登録するかは入力方法の違い。前提として残す代表：分割先は画面で登録する。
- 作り直し後：4行（2026-11-09 以前は4行）。rows=4 pair=100.00% (4/4) triple=100.00% (0/0)
- この節より上の文章（範囲・まとめた水準など）に外した因子・水準の名前が残る場合は、上の決定が優先する。
