# UZK-12 欠品カードを捜索し、補填できれば対応を終え、見つからなければ最終欠品にする

| 項目 | 内容 |
|---|---|
| 利用者 | 商品管理チーム／トレードチームの担当者（捜索）→ お客様（補填の確認。システムの外）→ 通販チーム（最終欠品の返金） |
| 目的 | 欠品の捜索依頼（欠品対応依頼）が届いたあと、補填用のカードや直近の在庫変動・通販在庫スペース・受注マスターを確かめて捜索し、補填カードが見つかればお客様の了承で対応完了、見つからなければ最終欠品としてお客様への対応・返金（通販のUTS-02）に進む。捜索結果はラインワークスで共有する（システムの外）。システムの受注・在庫の状態は、この捜索では変わらない |
| 種類 | 正常（補填・最終欠品の両方） |
| マトリクスの行 | `matrix_UZK-12/matrix.md` のT03（業務フローのパターン＝欠品対応（欠品報告から捜索依頼・補填・最終欠品まで）・捜索対応の進み方＝補填カードが見つかり、お客様に確認して了承を得て対応完了とする）。T01・T02・T04〜T08は「L3で変わるところ」 |
| もとのシナリオ | SCN-ZAIKO-017・035〜037・040・041 |

## 前提

- 共通の決まり：`../L4を流すときの共通の決まり.md` を先に読む（試験データの名前にシナリオIDを付ける・共有の設定は元に戻す・バッチの起動・店舗の読み替えなど）
- UZK-11 の終点（T01）を使う。商品「UZK12-T03」は、UZK-11 のT01と同じ手順で通販在庫を一時的に0にして承認を受けた商品（カード「シナリオ試験カードM01」NM・本店・在庫0・在庫履歴に「廃棄(欠品)」の行が1行）。行ごとに商品コードを変える（T01は「UZK12-T01」…）
- 用意するデータ（試験用の値。設計書の値ではない）
  - 補填用のカード：同じカードの状態違い「シナリオ試験カードM01（SP）」（商品コード「UZK12-T03-SP」、在庫2）。T01・T05は補填用のカードが無い
  - 通販の受注：この商品を含む受注（注文番号は試験の前に控える。UTS-03 の欠品登録の前提の受注に当たる）
  - 担当者：商品管理チームの担当者（捜索）、トレードチームの担当者
- 欠品対応依頼スプレッドシートと、ラインワークスでの共有は、システムの外

## 操作の流れと期待値

| # | 操作する人と操作 | 期待値（画面で見えること） |
|---|---|---|
| 1 | 通販チーム：欠品対応依頼スプレッドシートに、欠品の捜索依頼品（商品・理由・受注）を書く。商品管理チーム／トレードチームの担当者が、依頼内容を確認する（業務フロー12の8-4・11-1。17:30以降に商品管理へ依頼した場合は、店内注文または事前は当日、通販・大口・社内移動は翌日対応。システムの外の作業） | 画面の変化は無い |
| 2 | 担当者：捜索するカードのレア度で担当を決める（8-5・11-1。トレードチーム：スタン範囲のR以上、買取価格の付くカード、スタンダードとトレードのバックヤードにあるもの。商品管理チーム：U、C、基本土地、詰め合わせ系の金額がつかないカード。システムの外の作業） | 画面の変化は無い。この試験のカードはU（商品管理チームの担当） |
| 3 | 商品管理チームの担当者：補填カードを捜索する。バックヤードや仕入れ作業中のカード、同一商品の状態違いの中から探す（8-6・11-1「バックヤード、仕入れ作業中カードの中からの「補填」を基本線として対応」）。管理画面の在庫管理＞在庫一覧で、状態違いの商品「UZK12-T03-SP」の在庫を確かめる | 在庫一覧に補填用のカードが出て、在庫2が確かめられる（この時点では補填のカードは在庫のまま。システムの状態は変えない） |
| 4 | 商品管理チームの担当者：補填カードが見つかったので、お客様に確認して了承を得る（システムの外の作業。メールまたは電話。8-6「カードがあればお客様に確認し、対応完了とする」） | 画面の変化は無い。お客様が了承した |
| 5 | 商品管理チームの担当者：対応完了として、捜索結果をラインワークスで共有し、欠品対応表を更新する（11-3。システムの外の作業） | 画面の変化は無い。受注・在庫の状態は変わらない（この捜索で受注のステータス・在庫は動かさない） |
| 6 | 商品管理チームの担当者：念のため、在庫管理＞在庫履歴一覧で欠品カードのコード「UZK12-T03」を検索し、受注管理の受注一覧で注文番号を検索する | 在庫履歴に、手順の前の「廃棄(欠品)」の行（変更前3・変更後0）だけが残り、新しい行は増えない。受注は欠品登録前の注文のままで、ステータスが勝手に変わっていない（受注側の欠品登録は通販のUTS-03、返金は通販のUTS-02） |

## 終わったあとに確かめること

| 確かめる場所 | 期待値 |
|---|---|
| 受注・在庫の状態 | 手順1〜5の前後で変わらない（補填のカードは、お客様の了承後、通常の受注の編集・出荷の流れで出荷する。通販の範囲） |
| スマレジへの在庫の反映 | 確かめない（EC-CUBEからスマレジへの在庫連携は行わない：2026-11-18 レビュー指摘） |
