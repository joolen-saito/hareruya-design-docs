# 在庫管理の欠品報告による通販在庫の一時的な0への変更と承認（UZK-11）

IPA「高信頼化ソフトウェアのための開発手法ガイドブック」(2010) の表6-9〜6-11と同じ手順で作る（FL表→禁則表→2因子間網羅の組み合わせ）。1行が1回ずつ流すテスト1本で、行の中の水準は条件ごとに1つ（2026-11-09 に scenario_list.md の L3 欄で「／」で並べていた値を分けた）。

## 範囲

- 店舗や通販から欠品の報告を受け、通販在庫がある場合は在庫変動区分「廃棄(欠品)」で在庫を0にする在庫編集を登録し、承認（または却下）されるまで。通販在庫が無いカードでは在庫を0にする登録をしない
- 非公開にする方法は新実装に無く通さない（scenario_list.md の※4、依頼者の決定）。スマレジへの在庫の反映は行わない（EC-CUBEからスマレジへの在庫連携は行わない：2026-11-18 レビュー指摘）

## まとめた水準

なし（どの水準も処理が違う）。主な根拠：通販在庫があるときは在庫編集の登録・承認（または却下）があり、通販在庫が無いときは登録も承認も発生しない。承認で在庫は確定し、却下で登録前の数に戻る。

## 禁則

通販在庫が無いときは在庫を0にする登録をしないので、在庫編集の承認も発生しない（承認の結果の水準 B1・B2 とは組まない）。通販在庫があるときは登録するので、「登録しない」（B3）とは組まない。
