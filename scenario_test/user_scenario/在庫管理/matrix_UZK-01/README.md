# 在庫管理の新商品入荷と在庫変更CSVの承認（UZK-01）

IPA「高信頼化ソフトウェアのための開発手法ガイドブック」(2010) の表6-9〜6-11と同じ手順で作る（FL表→禁則表→2因子間網羅の組み合わせ）。1行が1回ずつ流すテスト1本で、行の中の水準は条件ごとに1つ（2026-11-09 に scenario_list.md の L3 欄で「／」で並べていた値を分けた）。

## 範囲

- 登録済みの新商品が入荷し、在庫変更CSVを登録して承認（または却下）されるまで。手順の前段（在庫検索一覧の在庫情報CSV出力で商品コードを取り、在庫変更CSVを作る）と、承認後の在庫の確かめ方は scenario_list.md の UZK-01 の行のとおり
- スマレジへの在庫の反映は行わない（EC-CUBEからスマレジへの在庫連携は行わない：2026-11-18 レビュー指摘）。このマトリクスは承認状態の遷移を確かめる
- 既に在庫が1以上ある商品の入庫が承認されても入荷通知は届かない（0から1以上になったときだけ送る）ことは、承認される行の1本で確かめる

## まとめた水準

なし（どの水準も処理が違う）。主な根拠：本店システム用と支店システム用はCSVを取り込む店舗が違い、100件以上の増減は確認のモーダルが出るかどうかが違い、承認・却下は承認状態の遷移が違う。
