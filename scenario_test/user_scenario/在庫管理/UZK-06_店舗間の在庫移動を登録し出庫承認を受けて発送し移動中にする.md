# UZK-06 店舗間の在庫移動を登録し、出庫承認を受けて発送し、移動中にする

| 項目 | 内容 |
|---|---|
| 利用者 | 出庫元の担当者（トレード／通販／支店。在庫移動の登録・欠品の登録・承認申請）→ 出庫承認者 → 移動指示を作る担当 → 梱包・発送（システムの外） |
| 目的 | 在庫リコメンド・成田への間引き・支店からの依頼・成田からの戻し・別部署の発送依頼などで、在庫を店舗間で動かす。在庫移動を登録して出庫元の在庫を減らし、出庫承認を受け、移動指示を作って送り状CSVを出し、送り状No.を登録して「移動中」にする。出庫承認で却下されたときは「却下」になり、出庫元の在庫が戻る |
| 種類 | 正常（出庫承認→移動中）／例外（却下など） |
| マトリクスの行 | `matrix_UZK-06/matrix.md` のT01（出庫元→入庫先＝支店→本店3F＝本店バックヤード（在庫リコメンドで支店がトレード宛の本店3Fへ送る）・在庫区分＝EC-CUBE・移動点数＝2点以上・出庫時の欠品登録＝欠品なし）。T02〜T13と例外E1〜E7・E9・E10は「L3で変わるところ」 |
| もとのシナリオ | SCN-ZAIKO-002〜005・007〜009・015 |

## 前提

- システムの外で済んでいること：なし（ピック・ラベル印字・梱包は手順で行う。同じ日の作業なので分けない）
- 用意するデータ（試験用の値。設計書の値ではない。行ごとに別の商品を使う）
  - 商品：カード「シナリオ試験カードH01」（商品コード「UZK06-T01」、NM・日本語）。出庫元の「試験支店」のEC-CUBE在庫が5・原価単価100円（総原価500円）。入庫先の本店バックヤード（3F。トレードチーム宛）のEC-CUBE在庫は0。行ごとにコードを変える（T02は「UZK06-T02」…）
  - 店舗の対応（決着 2026-11-26。scenario_list.md の※3と業務フロー12の作業内容）：「本店3F」「3F」「B2F（地下2F）」は本店バックヤード、「2F」は本店（トレードは3F、店舗の売り場・ショーケースは2F、在庫の置き場は地下2F）。トレードチーム宛の入庫先は本店バックヤード
- 店舗：本店（店舗ID 1。画面により「Hareruya」「トーナメントセンター 東京」と出る）、試験支店（開発環境の試験用の支店）、成田店（成田倉庫）。支店システムは存在しないので、支店の在庫移動も同じ管理画面で行う
  - 担当者：出庫元の登録担当、出庫承認者（別の担当者。承認権限があり、承認通知先に入る）、移動指示を作る担当（本店の担当。出庫元店舗の編集権限が要る）
- 移動点数3（出庫元の在庫5以下）。送り状No.は「UZK06-0001」（試験用の値）
- 画面の名前は新実装の表示で書く（設計書の「在庫移動・振替登録 編集(移動)」は画面の「在庫移動・振替登録」、一覧は「在庫移動振替一覧」。在庫検索一覧は「在庫一覧」）。完了の状態は設計書「入庫完了」・画面「入庫済み」
