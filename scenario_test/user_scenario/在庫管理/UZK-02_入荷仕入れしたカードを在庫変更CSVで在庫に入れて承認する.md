# UZK-02 入荷・仕入れしたカードを打ち込み、在庫変更CSVで在庫に入れて承認する

| 項目 | 内容 |
|---|---|
| 利用者 | トレードチーム／商品管理チームの担当者（打ち込み・Wチェック）→ インポート担当者 → 在庫の承認者。入荷待ちを登録した会員のお客様（入荷通知メールの確認） |
| 目的 | 仕入れや入荷で届いた既存商品のカードを打ち込み、Wチェックで差異を直し、在庫変更CSV登録で取り込み、承認者の承認で在庫に入れる。0から1以上になったときだけ入荷通知メールが届く |
| 種類 | 正常（承認）／却下 |
| マトリクスの行 | `matrix_UZK-02/matrix.md` のT03（入荷の種類＝仕入れ作業（打ち込みファイルのWチェックで差異があれば直す）・在庫変更CSVの登録者＝打ち込み担当がインポート担当者へ依頼して登録する・在庫編集承認の結果＝承認済）。入荷通知は、承認済みの行のうちこの行で確かめる。T01・T02・T04は「L3で変わるところ」 |
| もとのシナリオ | SCN-ZAIKO-018・033 |

## 前提

- 共通の決まり：`../L4を流すときの共通の決まり.md` を先に読む（試験データの名前にシナリオIDを付ける・共有の設定は元に戻す・バッチの起動・店舗の読み替えなど）
- システムの外で済んでいること：仕入れたカードが届いている。並び順ファイル（バックヤードの管理で使う並び順の一覧）が手元にある
- 用意するデータ（試験用の値。設計書の値ではない。行ごとに別の商品を使う）
  - 商品：既存の公開中のカード「シナリオ試験カードP03」（商品コード「UZK02-T03」、NM・日本語）。在庫0（T01は「UZK02-T01」、T02は「UZK02-T02」、T04は「UZK02-T04」）。商品の登録は商品登録・編集の UPR-04 と同じ手順で済ませておく
  - 打ち込み担当、インポート担当者、在庫の承認者（3人は別の担当者。承認者は在庫編集の承認権限があり、インポート担当者の承認通知先に入る）。T02・T04はインポート担当者を置かず、商品管理の担当者が自分で登録する
  - 会員：「試験 四郎」（メールアドレス `uzk02@example.test`、本会員）。入荷通知メールの許可（システム設定）が有効
  - 出力項目設定「通常作業用」（商品一覧のカスタムデータCSVダウンロードで選ぶ設定）：運用で作る設定。少なくとも、商品を見分ける列「商品コード」と、本店のEC-CUBE在庫の列「在庫(通販+TC東京)」を入れておく（UZK-14・UZK-13と同じ内容）
  - 入庫：在庫変更CSVで6点（列は商品コード・在庫増減数・仕入単価。仕入単価は80円）。ファイル名は、過去1か月以内に登録した在庫変更CSVと別の名前にする
- 在庫が承認されるまでは在庫0のまま
