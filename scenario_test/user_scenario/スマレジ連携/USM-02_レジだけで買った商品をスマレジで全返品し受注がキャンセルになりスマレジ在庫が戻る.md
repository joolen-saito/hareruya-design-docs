# USM-02 レジだけで買った店頭商品（店頭受取を含まないスマレジ決済）を、スマレジで全返品し、受注がキャンセルになってスマレジ在庫が戻る

| 項目 | 内容 |
|---|---|
| 利用者 | お客様（会員または非会員）→ 店舗チーム（スマレジのレジ。試験環境）→ スマレジ → EC（取り込み）→ 店舗チーム・通販チーム（管理画面で確かめる）→ お客様（マイページ。会員のとき） |
| 目的 | レジだけで買った店頭商品（USM-01 のパターン8・9の取引が済んでいる）を、お客様が全部返品したいと申し出て、店舗がスマレジで全返品の取引（取消または打消し）を登録し、ECに取り込まれて、取引から作った受注が「キャンセル」になり、スマレジ在庫が戻って在庫履歴に「スマレジ返品」が残り、会員のポイントが戻ることを、EC側の値で確かめる。ECの受注情報編集画面では返品の操作ができない |
| 種類 | 正常（会員・取消の1本）＋ L3の3件（表外の具体例）＋例外1件 |
| マトリクスの行 | なし（組み合わせ表は無い。`scenario_list.md` のL3の欄にある、会員／非会員と、返品の取引の種類（取消／打消し）の組を、代表1本＋表外の具体例3件にした）。代表は「会員・取消」 |
| もとのシナリオ | なし（0203 別添資料「スマレジ決済後返品処理について」①、0505 A05-04 の返品から組み立てた） |

店頭受取・店頭PCの受注を含む返品（②③。ついで買いを含む）はEC在庫も戻るので UOR-10。付与・使用ポイントの戻しの値の細かい確かめ（履歴の削除・保有ポイントが取引の前に戻る）は UPT-10。取り込みが届かなかった返品を再連携で取り込むのは USM-05。

## 前提

- 共通の決まり：`../L4を流すときの共通の決まり.md` を先に読む（試験データの名前にシナリオIDを付ける・共有の設定は元に戻す・バッチの起動・店舗の読み替えなど）
- スマレジ側の操作は、スマレジの試験環境で行う（2026-11-24 決定）。スマレジの画面の見え方は記録だけにし、合否はEC側の値で付ける。取引完了・返品の通知（Webhook）が開発環境のECに届くときはそのまま流し、届かないときは、試験の担当者が用意するHTTPクライアントで通知（取引ID）を代わりにECへ送ってよい。どちらで流したかを記録に残す（共通の決まり「外部のシステムから EC への要求」。2026-11-27 決定）
- システムの外で済んでいること：USM-01 のT14の終点まで済んでいる（本店で会員・試験 太郎がレジだけで「シナリオ試験ショーケース品B USM-01」を1点、ポイント100を使って買い、取引から作った受注が「出荷完了」。ショーケース品BのEC側のスマレジ在庫は10から9に減っている）。お客様が全部の商品を返品したいと申し出る
- 用意するデータ（試験用の値。設計書の値ではない）
  - 引き渡し済みの取引：USM-01 のT14で控えた取引ID・取引の合計・付与ポイント・使用ポイント、受注の注文番号。取り込まれた受注は「出荷完了」
  - 在庫：ショーケース品BのEC側のスマレジ在庫は9（返品後に10へ戻ることを確かめる）
  - 会員：試験 太郎（`usm-01@example.test`。保有ポイントは取引のあとの値を控える）
  - 表外の具体例の用意：非会員の行は USM-01 のT16の終点、打消しの行は、USM-01 の代表の行をもう一度流して別の取引（取引IDを控える）を作る
  - 店舗チームの担当者：管理画面（受注管理・商品管理の在庫・会員管理）と、スマレジのレジを使える
- 返品は全部だけ（一部返金は想定しない。0505）

## L3で変わるところ（表外の具体例・例外）

組み合わせ表は無い。手順の番号は上の「操作の流れと期待値」。1回ずつ別のテストとして流す。「流し始めの状態」は、対象の取引が「出荷完了」の受注として取り込まれていること。

| 行 | 条件（会員・返品の取引の種類） | 変わるところ |
|---|---|---|
| 表外 R1 | 会員・取消 | 代表の行 |
| 表外 R2 | 非会員・取消 | 前提：USM-01 のT16の終点（レジだけ・非会員の取引）。手順1：会員の画面は無い（会員の保有ポイントは控えない）。手順3：新しい受注が「キャンセル」。会員状態は「非会員」のまま。手順5：スマレジ在庫が戻る。手順6：ポイントは動かない（非会員）。手順7：非会員にマイページは無く、確かめない |
| 表外 R3 | 会員・打消し | 手順2：該当の取引を、打消し（打消元の取引を打ち消す）として登録する。手順3：打消元の取引IDで対応する受注を探して、手順1の受注が「キャンセル」になる（受注一覧の検索はスマレジ取引IDに打消元の取引IDを入れる）。ならなければ不合格として記録する。手順5〜7：代表と同じ。記録：新実装は、打消しで、打消元の取引と打消の取引の2件がスマレジに残り、受注を取り消すきっかけは打消の取引だけ（設計書は打消元の取引IDで検索すると書く。どちらの読み方でも受注が「キャンセル」になることを期待値にする） |

## 判断待ち

なし（USM-01 の判断待ち 1 のうち、本店だけで流すこのシナリオには関係しない）。

記録（判断待ちではない。合否は付けず、実際の画面・値を記録する）：
- スマレジでの「取消」と「打消し」のレジの操作の呼び方は設計書に無い（0505 は取引の種類で定める）。合否は、スマレジの取引の種類がECに届いて対応する受注が「キャンセル」になることだけ（UOR-10 の判断待ち 1 と同じ決着）
- 返品後のポイントの正確な増減は、付与額の計算がスマレジ側のため、取引の付与値・使用値と同じことだけを合否にする（UOR-10 の判断待ち 3 と同じ決着）

設計書との食い違い（起票しない）：
- 打消しの区分の値：0505 は「打消しの区分が1なら打消元取引IDで探す」と書く。新実装は、打消元の取引（区分1）と打消の取引（区分2）が残り、受注を取り消すきっかけは区分2の取引だけ。表外 R3・R4 は、どちらの読み方でも受注が「キャンセル」になることを期待値にし、ならなければ不合格として記録する
- 業務フロー05 には返品の工程が無い（`scenario_list.md` に記録済み）
