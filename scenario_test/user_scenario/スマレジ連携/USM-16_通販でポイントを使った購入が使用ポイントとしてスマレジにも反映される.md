# USM-16 通販でポイントを使って購入し、使用ポイントがスマレジのポイントにも反映される

| 項目 | 内容 |
|---|---|
| 利用者 | お客様（会員。本店のサイト）→ EC → スマレジ（試験環境。システムの外）→ 通販チーム（管理画面で注文を確かめる） |
| 目的 | 会員が通販でポイントを使って注文を確定すると、会員のECの保有ポイントが使用分だけ減り、スマレジの会員のポイントも使用分だけ減って一致する。スマレジへの通信が失敗したときは、注文にエラー内容と連携エラーの印が残る（その後の再連携は USM-17）。注文番号が無い・該当の受注が無いときは、何もせず終了する |
| 種類 | 正常（代表の1本）＋ L3の3件（組み合わせ表は無い） |
| マトリクスの行 | なし（組み合わせ表は無い。`matrix_USM-16/` は作っていない）。L3 は `scenario_list.md` の USM-16 の L3 欄の項目（スマレジへの通信の失敗・注文IDが無い／該当なし）を1つずつ別のテストにした（R1〜R3） |
| もとのシナリオ | なし（業務フローには無い）。購入の流れは UTS-01 の手順1〜9、使用ポイントの値（保有ポイント・履歴・注文確認メール）の確かめは UPT-05 が受け持つ。ここは使用ポイントのスマレジへの連携に絞る |

スマレジの試験環境の画面の見え方は外部サービスなので記録だけにし、合否は EC 側の値（購入完了画面・保有ポイント・受注編集の「ポイントエラーメッセージ」・ジョブ一覧）で付ける。

## 前提

- システムの外で済んでいること：スマレジの試験環境に接続できる。スマレジの試験環境の管理画面で会員のポイントを見られること。R1（スマレジへの通信が失敗する）の用意は試験環境の担当者に頼む（システムの外。UTS-14 の手順2と同じ扱い）
- 購入するEC：本店のEC（UTS-01 と同じ）
- 用意するデータ（試験用の値。設計書の値ではない）
  - 会員：お名前「試験 会員USM16」、メールアドレス `usm16-t01@example.test`、パスワード「Usm16Test-2026」の本会員。国内の住所を登録済み。UMB-01 の手順1〜7と UMB-02 の手順1〜2、USM-12 の手順で、この試験専用に作る。スマレジの会員が作られている。R1用に `usm16-r1@example.test` を同じ手順で作る。保有ポイント：どちらも、USM-15 の代表の手順（ポイント履歴追加（キャンペーン、特別対応）で増減量 3000・備考「USM-16 付与」）で 3,000 にしておく。スマレジの会員のポイントも 3,000 になっている（スマレジの管理画面で確かめて控える。記録）
  - 商品：グッズ「シナリオ試験ポイントグッズ USM16」（商品コード `USM16-G01`・単価15,000円（税込）・公開・在庫10・販売制限なし・購入制限数なし。グッズ商品CSVで登録し、在庫変更CSV登録と承認で在庫を入れる。UMB-10 の前提と同じ手順）。数量2で商品金額合計30,000円になり、送料無料金額（30,000円）に届く
  - 送料・手数料の前提：ゆうパックは30,000円以上で送料0円。銀行振込の手数料は0円。したがって注文金額合計は 30,000円 − 使用ポイント1,000 ＝ 29,000円（税込）
  - 通販チームの担当者：管理画面にログインでき、受注管理（受注情報検索・受注情報編集）を使えるアカウント
  - 手順の前に控える値：会員の保有ポイント（3,000）、スマレジの会員のポイント（3,000。記録）、ジョブ一覧の先頭の行（番号）
- 画面の名前・文言は新実装の表示で書く。設計書の名前と違うときは「（設計書：…）」を添える

## 記録（判断待ちではない。合否は設計書の期待値で付け、新実装の動きは記録する）

- 設計書は使用ポイントの連携を、購入完了の処理のあとに別のバッチ（注文IDを渡して起動）として動かすと定める。新実装は、購入の確定のあとに非同期のジョブとして投入し、失敗すると会員単位の再収束の依頼を積む（設計書の「注文にエラーフラグを立てる」と見え方が違う。受注編集の「要再収束」の印で確かめる。R1）
- 使用ポイントの値（保有ポイント・履歴・注文確認メール・購入履歴の表示）の細部は UPT-05 が確かめる。ここは「減った量がスマレジにも反映される」ことに絞る
- 支払方法は、決済の外部画面を挟まない「銀行振込」にした（UMB-10 の準備4と同じ。連携の確かめに要るのは使用ポイントの消費だけ）。クレジットカード決済で流す場合は UTS-01 の手順7・9のとおり
- 二重に減る見込み：購入のときのジョブと、手で起動するバッチ（R2・R3 以外で注文の番号を指定したとき）は、どちらも使用ポイントを相対で減らして送り、同じ注文の送信済みの判定が無い。ジョブが成功したあとや、待機中のジョブがあとで成功するときにバッチを起動すると、スマレジの会員のポイントは二重に減る（ECの保有ポイントは減らない）。そのため手順6はジョブの完了か失敗を確かめてから決める。スマレジ側は記録、合否はEC側の値で付ける
- スマレジの会員のポイントの見え方・取引としての記録は外部サービスの見え方（記録だけ）

設計書との食い違い（起票しない）
- 連携失敗の印：設計書は「注文のスマレジ連携エラーフラグ」と「ポイント連携エラーメッセージ」。新実装は受注編集の「ポイントエラーメッセージ」と「要再収束」の印（`scenario_list.md` の USM-16 の L3 欄は、設計書の言い方で書いてある。UTS-14 と同じ扱い）
- 注文の番号が数値でないときの終わり方：設計書の現行仕様は「連携を行わずに終了する」、新実装は異常終了の扱い（R3。会員のポイントは変わらない点は同じ）
