# スマレジ連携：シナリオ一覧（L2）

スマレジ（店頭POS）との連携は、各業務のシナリオにばらばらに出てくる。ここでは業務フローの分岐と設計書のスマレジ連携の処理を1行ずつ洗い出し（`## スマレジ連携の網羅`）、既存のシナリオで確かめられているものはそのIDを書き、足りないものだけを USM のシナリオ（L2）として足した。

シナリオ1本は「起点の業務イベントから、業務として完了した状態になるまで」とする。担当者が替わっても切らない（お客様→店舗チーム→スマレジ→EC管理画面）。日をまたぎ、システムの状態が何かを待つもの（毎時・10分ごとの再連携バッチ、夜間のバッチ）は別の1本にする。既存の業務のシナリオ（UOR・UZK・UPR・UPC・UTS・UEV・UKA）を区間として使ってよい。前提データ（会員・商品・店舗・スマレジの接続設定などのマスタ）はシナリオから外す。

| 階層 | 単位 | スマレジ連携での置き場所 |
|---|---|---|
| L1 業務領域 | シナリオのグループ | スマレジ連携（取引・在庫・商品・会員・ポイント） |
| L2 シナリオ | 起点イベント→業務完了 | `## シナリオ一覧` の1行 |
| L3 バリエーション | 条件違い・例外 | `matrix_USM-01/`（USM-01）と、各行の「L3」欄 |
| L4 ステップ | 画面操作と確認 | （まだ書かない） |

## スマレジ連携の網羅

方向は、EC→スマレジ（ECの操作・バッチがスマレジを更新する）、スマレジ→EC（レジの操作・取引がECを更新する）、両方向、なし（スマレジの操作だけで、ECに連携しない）。「通すシナリオ」は既存のID（`tools/check_refs.py` で実在を確かめた）か USM。
