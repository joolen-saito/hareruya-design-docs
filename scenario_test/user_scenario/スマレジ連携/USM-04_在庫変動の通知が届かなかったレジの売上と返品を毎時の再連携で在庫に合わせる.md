# USM-04 スマレジの在庫変動のWebhookが取りこぼされ、毎時の再連携で在庫が合う

| 項目 | 内容 |
|---|---|
| 利用者 | 店舗チーム（スマレジのレジ。試験環境）→ スマレジ → 再連携のバッチ（システム）→ 店舗チーム・通販チーム（管理画面の在庫検索一覧・在庫履歴で確かめる） |
| 目的 | レジで売上・返品があったのに、ECにスマレジの在庫変動の通知（Webhook。スマレジ側にリトライが無い）が届かなかったとき、毎時16分に動く再連携のバッチが、直近5時間の在庫変動のうち在庫区分が「売上」「返品」で、ECに登録されていないものを取り込み、EC側のスマレジ在庫と在庫履歴がレジの取引と合うことを確かめる。店頭受取分の商品は取り込まない |
| 種類 | 正常（代表の1本＝売上）＋ L3の5件（表外の具体例）＋例外1件 |
| マトリクスの行 | なし（組み合わせ表は無い。`scenario_list.md` のL3の欄にある、在庫区分（売上／返品／それ以外）・期間（5時間より前）・登録済み・店頭受取分を、代表1本＋表外の具体例にした） |
| もとのシナリオ | なし（設計書 0501 A01-02「スマレジwebhook連携エラー再連携」から組み立てた） |

## 前提

- 共通の決まり：`../L4を流すときの共通の決まり.md` を先に読む（試験データの名前にシナリオIDを付ける・共有の設定は元に戻す・バッチの起動・店舗の読み替えなど）
- スマレジ側の操作は、スマレジの試験環境で行う（2026-11-24 決定）。スマレジの画面の見え方は記録だけにし、合否はEC側の値（在庫検索一覧・在庫履歴）で付ける
- 通知が届かない状態の作り方：スマレジ試験環境の通知（Webhook）の送り先の設定を、試験の間だけ止められるときに、止めてからレジの操作をし、操作が済んだら元に戻す（止めた時刻と戻した時刻を記録する）。止められないときは、「通知が届かなかった状態」を作れないので、その行は「実施不可（流せない）」として記録する（判断待ち 1）。ECの設定は変えない
- バッチの流し方：毎時16分のバッチは、時刻を待たず手で起動する（起動のしかたは根拠の欄。期間を指定しないときは、起動した時刻から5時間前までを対象にする）。このバッチは環境の中の対象を全部処理するので、合否はこの試験の商品の在庫・履歴で付け、再連携の件数などは記録にする。完了の表示は、「スマレジ在庫変動再連携処理が完了しました。」（対象期間・対象の件数・失敗の件数つき）
- システムの外で済んでいること：スマレジの試験環境に試験用の店舗とレジがそろっている
- 用意するデータ（試験用の値。設計書の値ではない）
  - 商品：グッズ「シナリオ試験ショーケース品C USM-04」（商品コード `USM04-G01`、単価800円（税込））。グッズ商品CSV登録でスマレジ連携フラグ「連携する」・部門・スマレジ商品コードを書いて登録し、スマレジに商品ができたことを確かめてある（USM-08）。EC側のスマレジ在庫は在庫変更CSV登録（在庫区分はスマレジ）と承認で10、スマレジの管理画面でも同じ商品の在庫を10にしておく（EC からスマレジへの在庫連携は行わないので、両方を別々に整える）
  - 店頭受取の商品（表外 R5 用）：UOR-01 で作った店頭受取の注文のスマレジ商品（スタック用紙のバーコードの商品）
  - 店舗チームの担当者：管理画面（商品管理の在庫検索一覧・在庫履歴）と、スマレジのレジを使える
- レジの取引は会員を指定しなくてよい（このシナリオはスマレジ在庫だけを確かめる。受注・ポイントは USM-01・USM-05）
