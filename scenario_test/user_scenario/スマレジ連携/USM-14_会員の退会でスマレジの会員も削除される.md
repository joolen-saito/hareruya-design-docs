# USM-14 会員が退会し、スマレジの会員も削除される

| 項目 | 内容 |
|---|---|
| 利用者 | お客様（本会員）→ EC（フロント）→ スマレジ（試験環境。システムの外）→ メール → 店舗チーム（管理画面で確かめる） |
| 目的 | 本会員が退会を確定すると、スマレジの会員が削除され、ECの退会が確定する（退会完了画面・退会完了メール・ログインできなくなる）。スマレジの削除に失敗したときは、退会せず確認画面に戻り、エラーが出る（会員も選手情報も変わらない） |
| 種類 | 正常（代表の1本）＋ L3の1件（組み合わせ表は無い） |
| マトリクスの行 | なし（組み合わせ表は無い。`matrix_USM-14/` は作っていない）。L3 は `scenario_list.md` の USM-14 の L3 欄の項目（スマレジの削除に失敗）を別のテストにした（R1） |
| もとのシナリオ | なし（業務フローには無い。設計書 0306 退会による）。退会画面の文言・メール・ログインできないことの細部は UMB-13 で確かめる。ここはスマレジの会員の削除に絞る |

スマレジの試験環境の画面の見え方は外部サービスなので記録だけにし、合否は EC 側の値（退会完了画面・メール・ログインの可否・管理画面の会員一覧）で付ける。

## 前提

- 共通の決まり：`../L4を流すときの共通の決まり.md` を先に読む（試験データの名前にシナリオIDを付ける・共有の設定は元に戻す・バッチの起動・店舗の読み替えなど）
- システムの外で済んでいること：スマレジの試験環境に接続できる。スマレジの試験環境の管理画面で会員を探して見られること。スマレジの試験環境のレジで会員バーコードを読み取れること。R1（スマレジの削除に失敗する）の用意は試験環境の担当者に頼む（システムの外。UTS-14 の手順2と同じ扱い）
- 用意するデータ（試験用の値。設計書の値ではない）
  - 会員：お名前「試験 会員USM14」、メールアドレス `usm14-t01@example.test`、パスワード「Usm14Test-2026」の本会員。UMB-01 の手順1〜7と UMB-02 の手順1〜2、USM-12 の手順で、この試験専用に作る。スマレジの会員が作られている（マイページに会員番号が出る）。進行中の注文・買取は無い。R1用に別の会員 `usm14-r1@example.test` を同じ手順で作る
  - 店舗チームの担当者：管理画面の会員管理（会員一覧）を使えるアカウント
  - 手順の前に控える値：マイページの会員番号（以下「控えた会員番号」）、管理画面の会員一覧の総件数、スマレジの管理画面の会員の一覧で控えた会員番号の会員が1件あること（記録）
- 画面の名前・文言は新実装の表示で書く。設計書の名前と違うときは「（設計書：…）」を添える

## 記録（判断待ちではない。合否は設計書の期待値で付け、新実装の動きは記録する）

- スマレジに会員がすでに無い（検索で見つからない・存在しない）ときの扱いは、設計書に定めが無い。新実装は「削除する対象が無い」ものとして退会を妨げない作りに見える。このシナリオでは用意しない
- 管理画面の会員編集で会員種別を「退会」にして保存する経路は、退会の確定とは別の処理（UMB-16）で、このシナリオでは流さない
- スマレジの会員が消えたあとの、スマレジ側の過去の取引・ポイントの扱いは外部サービスの見え方（記録だけ）
- 退会完了メールの運営アドレスのBCCは、BCC先の受け口が見られるときだけ確かめる（UMB-13）

設計書との食い違い（起票しない）
- `scenario_list.md` に記録済みのもの以外に新しいものは無い（スマレジの削除に失敗したときの退会の中止は、設計書と新実装が合っている）
