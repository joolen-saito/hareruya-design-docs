# USM-12 仮会員が本会員登録し、スマレジの会員が作られる

| 項目 | 内容 |
|---|---|
| 利用者 | お客様（仮会員）→ メール → EC（フロント）→ スマレジ（試験環境。システムの外）→ 店舗チーム（管理画面で確かめる） |
| 目的 | 仮会員が仮会員登録完了メールの本登録のURLを開くと、スマレジに会員が新規登録され、会員の番号がECの会員情報に控えられて本会員になる。マイページに会員番号とバーコードが出て、店頭のレジで会員として使える。スマレジへの登録に失敗したときは本会員にならない（エラー画面）。すでにスマレジの番号を持つ仮会員は、登録済みとして止まる |
| 種類 | 正常（代表の1本）＋ L3の2件（組み合わせ表は無い） |
| マトリクスの行 | なし（組み合わせ表は無い。`matrix_USM-12/` は作っていない）。L3 は `scenario_list.md` の USM-12 の L3 欄の項目を1つずつ別のテストにした（R1・R2） |
| もとのシナリオ | なし（業務フローには無い。設計書 0306 本会員登録による）。本登録の画面・メールの細部は UMB-02 で確かめる。ここはスマレジとの連携に絞る |

スマレジの試験環境の画面の見え方は外部サービスなので記録だけにし、合否は EC 側の値（本登録完了画面・マイページ・管理画面の会員情報・届いたメール）で付ける。

## 前提

- 共通の決まり：`../L4を流すときの共通の決まり.md` を先に読む（試験データの名前にシナリオIDを付ける・共有の設定は元に戻す・バッチの起動・店舗の読み替えなど）
- システムの外で済んでいること：スマレジの試験環境に接続できる（会員を作れる状態）。スマレジの試験環境の管理画面で会員を探して見られること。スマレジの試験環境のレジで会員バーコードを読み取れること。R1（スマレジへの登録に失敗する）の用意は試験環境の担当者に頼む（システムの外。UTS-14 の手順2と同じ扱い）
- 起点の会員：UMB-01 の手順1〜5で仮会員になり、仮会員登録完了メールが届いたところ。このシナリオ専用に、メールアドレス `usm12-t01@example.test`・お名前（名）「会員USM12」で作る（UMB-01 の入力値のうち、メールアドレスと名だけを替える。電話番号は 03-5532-7517、フリガナ（セイ）「シケン」・（メイ）「カイイン」）。R1用に `usm12-r1@example.test`、R2用に `usm12-r2@example.test` も同じ手順で仮会員にしておく
- 用意するデータ（試験用の値。設計書の値ではない）
  - 店舗チームの担当者：管理画面の会員管理（会員一覧・会員編集）を使えるアカウント
  - 手順の前に控える値：管理画面の会員一覧で見た会員種別（「仮会員」）と、会員編集の「スマレジID」（空）、メール受け口の `usm12-t01@example.test` の件数（仮会員登録完了メール1通）
- 画面の名前・文言は新実装の表示で書く。設計書の名前と違うときは「（設計書：…）」を添える
