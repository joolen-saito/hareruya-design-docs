# USM-15 管理者が会員にポイントを付与・減算し、スマレジの会員のポイントも合わせる

| 項目 | 内容 |
|---|---|
| 利用者 | 店舗チーム・通販チーム（管理画面の会員管理）→ EC → スマレジ（試験環境。システムの外）→ お客様（マイページで保有ポイントを見る） |
| 目的 | 管理者が会員編集の「ポイント管理・履歴一覧」からポイントを付与（キャンペーン・特別対応、余剰入金・注文金額変更の返金）・減算すると、会員の保有ポイントとポイント履歴が増減し、スマレジの会員のポイントも同じ量だけ更新される。注文番号が会員のものでないとき・付与後の残高が0未満になるときは付与しない。スマレジへの連携に失敗したときは、ポイント履歴を追加せず残高も更新しない |
| 種類 | 正常（代表の1本）＋ L3の7件（組み合わせ表は無い） |
| マトリクスの行 | なし（組み合わせ表は無い。`matrix_USM-15/` は作っていない）。L3 は `scenario_list.md` の USM-15 の L3 欄の項目（付与の種類・増減量の正負・注文番号の該当なし・残高が0未満・連携の失敗）を1つずつ別のテストにした（R1〜R7） |
| もとのシナリオ | なし（業務フローには無い。設計書 0207 ポイント付与による）。付与したあとの履歴の見え方（管理画面とマイページの並び・有効期限）は UMB-10、付与・使用・戻し・失効の値の確かめは UPT-01・UPT-05・UPT-07・UPT-08 で確かめる。ここはスマレジの会員のポイントとの一致に絞る |

スマレジの試験環境の画面の見え方は外部サービスなので記録だけにし、合否は EC 側の値（保存のメッセージ・ポイント残高・ポイント履歴・マイページの現在のポイント・ジョブ一覧）で付ける。

## 記録（判断待ちではない。合否は設計書の期待値で付け、新実装の動きは記録する）

- `scenario_list.md` の USM-15 の L3 欄は付与の種類を「通常／キャンペーン・特別対応／返金」と書くが、設計書の「ポイント付与」の画面（0207 ポイント付与）は、キャンペーン・特別対応と返金の2つの入口を選ぶ画面で、「通常」という種類の画面は無い。このシナリオでは、2つの入口（4つの備考）を行にした（R1〜R3 と代表）。組み合わせ表は無いので、シナリオ一覧は変えていない
- 見出しの違い：新実装の返金の画面の見出し・設計書の機能名は「…ご送金」、設計書の画面名・備考の選択肢は「…ご返金」と、設計書の中でも表記が揺れる。画面の表示を記録する
- 管理画面の付与は、増減量の上限を「スマレジ連携に合わせる」と設計書が書く（最大 999999999）。上限の値は試験に入れない
