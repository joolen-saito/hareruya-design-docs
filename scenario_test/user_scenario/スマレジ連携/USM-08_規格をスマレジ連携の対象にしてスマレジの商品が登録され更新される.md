# USM-08 規格をスマレジ連携の対象にし、スマレジの商品が新規登録・更新される

| 項目 | 内容 |
|---|---|
| 利用者 | トレードチーム・顧客戦略チームの担当者（登録担当）→ 管理画面 → スマレジ（試験環境） |
| 目的 | 規格をスマレジ連携の対象にする（商品編集・商品規格の登録・編集・カード商品CSV・グッズ商品CSV・買取・基準価格一括編集・価格変更CSVのどれか）と、スマレジに商品が新規登録（スマレジ側に無いとき）または更新（あるとき）され、商品名に言語・規格が付き、単価は基準価格（税込）、部門が連携されることを確かめる。一括の結果は非同期に返り、CSVインポート履歴の「スマレジ連携状態」に出る。代表の行は、カード商品CSVでシングルカードを新規に登録し、基準価格と状態から連携フラグが自動でONになる |
| 種類 | 正常（代表の1本＝カード商品CSV）＋ L3の表外の具体例9件＋例外3件 |
| マトリクスの行 | なし（組み合わせ表は無い。`scenario_list.md` のL3の欄にある、操作の種類・スマレジ側の商品の有無・商品コードの付け方・連携フラグの条件・300円をまたぐ確認・セール用CSV を、代表1本＋表外の具体例と例外にした） |
| もとのシナリオ | なし（設計書 0204 別添資料「スマレジ連携対象商品」「スマレジ連携 商品連携項目」から組み立てた） |

価格CSVの自動判定そのもの（価格変更CSVの値の計算）は UPC-05、新商品のCSV登録の流れは UPR-04（グッズ）・UPR-02（予約シングル）。このシナリオは、登録・更新のあとに「スマレジの商品がどうなったか」をEC側の値（規格設定・CSVインポート履歴）とスマレジの商品一覧の突き合わせで確かめる。

## 前提

- 共通の決まり：`../L4を流すときの共通の決まり.md` を先に読む（試験データの名前にシナリオIDを付ける・共有の設定は元に戻す・バッチの起動・店舗の読み替えなど）
- スマレジ側の確かめは、スマレジの試験環境で行う（2026-11-24 決定）。スマレジの商品一覧の見え方は記録だけにし、合否は「スマレジに登録された値（商品名・単価・部門・商品コード）」と「EC側の値（規格設定・CSVインポート履歴）」の突き合わせで付ける
- 非同期の処理は、完了まで待つ（待つのは時刻でなく完了まで。CSVインポート履歴の「スマレジ連携状態」が「完了」になるまで）
- システムの外で済んでいること：スマレジの試験環境に試験用の店舗がある。スマレジの部門「ショーケース品」（シングルカードのNM以外の部門）が、EC側に登録され、スマレジに連携済みである（商品管理の部門登録/編集。確かめは USM-10）
- 用意するデータ（試験用の値。設計書の値ではない）
  - カード：「シナリオ試験カードK USM-08」（英名「Scenario Test Card K USM-08」、レアリティ・レイアウト・画像URL（英語）は必須、カードセット「シナリオ試験セットZ」）。カード登録CSVに1行書く
  - カード商品：言語＝日本語、状態は割引率「4」（NM100%・SP90%・MP80%・HP70%）で4つの規格、基準価格 500円（4規格の基準価格は NM 500・SP 450・MP 400・HP 350円。どれも300円以上）、買取価格 100円、購入グループ「通常商品」、商品カテゴリ1件、商品公開ステータス＝公開
  - 設定：スマレジ連携フラグを自動でONにする基準価格のしきい値は300円（新実装の設定値。開発環境も同じ）
  - 登録担当：管理画面で、商品管理（商品一覧・商品CSV管理・部門）を編集できる権限を持つ担当者
- カードの商品コード（スマレジ商品コードではない）は、登録のときに新実装が自動で作る。流すときは、商品一覧で実際の商品コードを控えて読み替える（共通の決まり）。グッズは商品コードを指定できる

## 終わったあとに確かめること

| 確かめる場所 | 期待値 |
|---|---|
| カード商品CSV登録の画面に同じCSVをもう一度アップロードする | 同じカードの商品が登録済みなので、その行は飛ばされる。スマレジに商品が増えない（UPR-02 の例外E3と同じ） |

## L3で変わるところ（表外の具体例・例外）

組み合わせ表は無い。手順の番号は上の「操作の流れと期待値」。1回ずつ別のテストとして流す。商品・カード・商品コードは行ごとに別にする（同じ商品コードは重ねて登録できない）。

| 行 | 条件（操作の種類・スマレジ側の商品・商品コード） | 変わるところ |
|---|---|---|
| 表外 R1 | カード商品CSV・スマレジ側に商品が無い（新規）・シングルカードの商品コードは自動採番 | 代表の行 |
| 表外 R2 | 商品規格の登録・編集の画面で、連携フラグをONにして保存（スマレジ側に商品が無い→新規登録） | 前提：基準価格が300円未満のシングルカード（カード商品CSVで登録。4規格のスマレジ連携フラグはすべて「連携しない」）。手順：規格設定でNMの規格を開き、スマレジ連携フラグを「連携する」にし、部門に「ショーケース品」を入れて保存する（シングルカードのスマレジ商品コードの欄は入力できず、連携をONにして保存すると自動で6桁の番号が振られる。0204 商品規格登録編集 識別ID 4）。保存のあと、自動で振られたスマレジ商品コードを控える。期待値：「保存しました」が出る。スマレジにNMの商品が新規に登録される（商品名・単価・部門・商品コードがEC側の値と同じ）。手動でONにした場合は、300円未満でも連携する（強制的に連携） |

| 表外 R8 | セール用価格変更CSV・セール用高額商品価格変更CSV | 代表の終点の商品に、セール用価格変更CSVを取り込む（UPC-01）。期待値：スマレジの単価は変わらない（セール価格は連携しない。別添「セール価格は連携しないため不要」）。CSVインポート履歴のスマレジ連携状態は「対象なし」 |
| 表外 R9 | 300円をまたぐ価格変更の確認のダイアログ | 前提：基準価格290円のシングルカード（SP・MP・HPの基準価格は270・240・210円で、連携フラグはすべて「連携しない」）。手順：規格設定でSPの規格を開き、基準価格を320円に変えて保存しようとする。期待値：「閾値(300円)をまたぐ価格変更がされたので、スマレジ連携フラグを確認してください」のダイアログが出る（画面の確認のダイアログ。新実装は保存の送信のときに出す）。連携フラグが「連携する」の規格の基準価格を300円未満に下げるときも、同じダイアログが出る。ダイアログを閉じて保存すると、SPは基準価格が300円以上のSPなので、保存のあとスマレジ連携フラグが自動で「連携する」になり、スマレジ商品コードが自動で振られる（0204 別添 規格登録：シングルカードは300円以上でフラグをONにする）。NMの規格を使うときは、NMは自動でONにならないので、保存のあとも「連携しない」のまま。下げる側（連携する規格を300円未満にする）は、ダイアログが出ても、一度でも条件を満たした規格は手動でOFFにしない限り「連携する」のまま |
