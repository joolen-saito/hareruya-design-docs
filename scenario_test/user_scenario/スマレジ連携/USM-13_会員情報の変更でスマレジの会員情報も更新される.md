# USM-13 会員が会員情報を変更し、スマレジの会員情報も更新される

| 項目 | 内容 |
|---|---|
| 利用者 | お客様（本会員）→ EC（フロント）→ スマレジ（試験環境。システムの外）→ 店舗チーム（管理画面で確かめる） |
| 目的 | 本会員がマイページの会員情報変更で氏名・電話番号を変えて「変更する」を押すと、変更が確定して完了画面が出て、スマレジの会員の氏名・電話番号も同じ値に更新される。スマレジへの更新に失敗したときは、変更を確定せず編集画面に戻り、エラーが出る |
| 種類 | 正常（代表の1本）＋ L3の2件（R2 は対象外）（組み合わせ表は無い） |
| マトリクスの行 | なし（組み合わせ表は無い。`matrix_USM-13/` は作っていない）。L3 は `scenario_list.md` の USM-13 の L3 欄の項目を1つずつ別のテストにした（R1・R2） |
| もとのシナリオ | なし（業務フローには無い。設計書 0306 会員情報変更による）。変更画面の入力チェック・本人確認ステータスの扱いは UMB-11 で確かめる。ここはスマレジへの更新に絞る |

スマレジの試験環境の画面の見え方は外部サービスなので記録だけにし、合否は EC 側の値（完了画面・マイページ・管理画面の会員情報・ジョブ一覧）で付ける。

## 前提

- 共通の決まり：`../L4を流すときの共通の決まり.md` を先に読む（試験データの名前にシナリオIDを付ける・共有の設定は元に戻す・バッチの起動・店舗の読み替えなど）
- システムの外で済んでいること：スマレジの試験環境に接続できる。スマレジの試験環境の管理画面で会員を探して見られること。R1（スマレジへの更新に失敗する）の用意は試験環境の担当者に頼む（システムの外。UTS-14 の手順2と同じ扱い）
- 用意するデータ（試験用の値。設計書の値ではない）
  - 会員：行ごとに別の本会員（`usm13-t01@example.test`・R1用に `usm13-r1@example.test`）。お名前（姓）「試験」・（名）「会員USM13」、フリガナ（セイ）「シケン」・（メイ）「カイイン」、電話番号 03-5532-7517、パスワード「Usm13Test-2026」、住所は UMB-01 の入力値。UMB-01 の手順1〜7と UMB-02 の手順1〜2、USM-12 の手順で、この試験専用に作る。スマレジの会員が作られている（マイページに会員番号が出る）
  - 店舗チームの担当者：管理画面の会員管理（会員編集）を使えるアカウント
  - 変える値（代表）：お名前（名）を「会員USM13」から「会員USM13改」に、電話番号を 03-5532-7517 から 03-5532-0000 に。ほかの項目（フリガナ・住所・メールアドレス・パスワード欄）は触らない（パスワード欄はマスクの初期値のまま）
  - 手順の前に控える値：マイページの会員番号、マイページの「会員情報編集」に入っている値（お名前・電話番号）、スマレジの会員の氏名・電話番号（スマレジの管理画面で見る。記録）、ジョブ一覧の先頭の行（番号）
- 画面の名前・文言は新実装の表示で書く。設計書の名前と違うときは「（設計書：…）」を添える

## 記録（判断待ちではない。合否は設計書の期待値で付け、新実装の動きは記録する）

- 新実装は、スマレジへの更新が失敗しても会員情報の変更を確定する（R1）。設計書の「スマレジへの更新に成功したときだけ確定する」と動きが違う（食い違いとして残す）
- スマレジに送るのは氏名・フリガナ・電話番号の変更だけ。住所だけの変更はスマレジに送られない（UMB-11 が確かめる。このシナリオでは氏名・電話番号だけ変える）
- 設計書の画面名「会員情報変更」に対し、新実装のマイページのメニューは「会員情報編集」（画面の見出しは「会員情報変更」）
- 手順6のジョブ一覧は EC が残す記録。開けない環境では手順3〜5で合否を付ける
- スマレジの会員の氏名・フリガナの形（姓名の並び・空白の有無）は設計書に定めが無い。記録だけ

設計書との食い違い（起票しない）
- スマレジへの更新が失敗したときの扱い：設計書は確定しないと定め、新実装は確定する（`scenario_list.md` の USM-13 の L3 欄に失敗の動きとして記録済み。UMB-11 の E4 と同じ論点）
