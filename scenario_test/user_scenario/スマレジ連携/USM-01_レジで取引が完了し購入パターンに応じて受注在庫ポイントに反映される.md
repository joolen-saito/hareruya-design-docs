# USM-01 レジ（スマレジ）で取引が完了し、購入パターンに応じてECの受注・在庫・ポイントに反映される

| 項目 | 内容 |
|---|---|
| 利用者 | お客様（会員または非会員）→ 店舗チーム（スマレジのレジ。試験環境）→ スマレジ → EC（取り込み）→ 店舗チーム・通販チーム（管理画面で確かめる）→ お客様（マイページ。会員のとき） |
| 目的 | レジで取引が完了したあと、購入パターン（0505の1〜9）に応じて、ECの受注（持ち込んだ元の受注の状態と、取引から作る新しい受注）・スマレジ在庫・会員のポイントが取引のとおりに反映されることを、EC側の値で確かめる。代表の行は、レジだけの買い物（持ち込む受注なし）を会員が使用ポイント付きで買うパターン |
| 種類 | 正常（組み合わせ表の17行を1回ずつ流す）＋例外3件 |
| マトリクスの行 | `matrix_USM-01/matrix.md` のT14（購入パターン8：店頭購入・レジだけ（会員）・本店・表の条件は持ち込む受注1件だが、レジだけの買い物は持ち込む既存の受注が無く、両立しない。T14〜T17は、レジの取引から新しく作られる受注1件として流す。判断待ち 2 の決着 2026-11-27）。ほかの16行（T01〜T13・T15〜T17）と例外E1〜E3は「L3で変わるところ」 |
| もとのシナリオ | なし（今のシナリオ SCN-* に無い。設計書 0505 A05-04 の購入パターン表から組み立てた） |

店頭受取・スムーズ店頭受取・店頭PCの注文を持ち込む行（T01〜T13）の、注文からピック完了までは UOR-01・UOR-06 を区間として使い、引き渡しの操作と取り込み後の画面の確かめは UOR-02・UOR-03・UOR-07 と同じ。このシナリオは、17行すべてで「取り込まれた結果（受注・在庫・ポイント・マイページ）が購入パターンのとおりか」を確かめる。返品は USM-02、取り込みが届かなかったときの再連携は USM-05。会員のポイントの値の細かい確かめ（付与・使用の計算）は UPT-03、返品での戻しは UPT-10。

## 前提

- 共通の決まり：`../L4を流すときの共通の決まり.md` を先に読む（試験データの名前にシナリオIDを付ける・共有の設定は元に戻す・バッチの起動・店舗の読み替えなど）
- スマレジ側の操作は、スマレジの試験環境で行う（2026-11-24 決定）。スマレジの画面の見え方は記録だけにし、合否はEC側の値（EC の画面・EC が残した履歴・EC のポイントや在庫）で付ける
- 取引完了の通知（Webhook）の流し方：スマレジ試験環境の取引完了の通知が開発環境のECに届くときは、そのまま流す。届かないときは、試験の担当者が用意するHTTPクライアントで取引完了の通知（取引IDだけ）を代わりにECへ送ってよい（ECが取引の詳細をスマレジから取得する）。どちらで流したかを記録に残す（共通の決まり「外部のシステムから EC への要求」。2026-11-27 決定）
- システムの外で済んでいること：スマレジの試験環境に、試験用の店舗（本店に対応するスマレジ店舗）とレジが使える状態でそろっている。会員のお客様が、スマレジの会員番号を持つ（会員登録でスマレジに会員が作られている。UMB-02）
- 用意するデータ（試験用の値。設計書の値ではない）
  - 店舗の読み替え：本店は店舗ID 1（画面によって「Hareruya」「トーナメントセンター 東京」と出る）。「支店」と書く行（T03・T05・T07・T09・T11・T13・T15・T17）は、流す前に、スマレジ店舗IDとスマレジ店舗コードが設定された既存の支店を選び、店舗IDと画面に出る名前を控えて読み替える。店舗は新しく作らない。開発環境は本店だけ店舗IDが設定済みで（`scenario_list.md`）、該当する支店が無いときは、その行を「実施不可（流せない）」として記録する（判断待ち 1）
  - 会員：試験 太郎（本会員、メールアドレス `usm-01@example.test`、スマレジの会員番号あり）。保有ポイントは、手順に入る前に十分あるように付与しておく（使用ポイント100を使うため）。非会員の行（T10〜T13・T16・T17）では会員を指定せずにレジを通す
  - 商品：グッズ「シナリオ試験ショーケース品B USM-01」（商品コード `USM01-G01`、単価800円（税込）、本店の店頭の商品）。グッズ商品CSV登録でスマレジ連携フラグ「連携する」・部門（スマレジに連携済みの部門）・スマレジ商品コードを書いて登録し、スマレジに商品ができたことを確かめてある（USM-08）。EC側のスマレジ在庫は在庫変更CSV登録（在庫区分はスマレジ）と承認で10にし、スマレジの管理画面でも同じ商品の在庫を10にしておく（EC からスマレジへの在庫連携は行わないので、両方を別々に整える）
  - 支店で売る行（T03・T05・T07・T09・T11・T13・T15・T17）の在庫：読み替えた支店のEC側にも、同じ商品「シナリオ試験ショーケース品B USM-01」のスマレジ区分の在庫の行が要る（新実装は、スマレジの店舗IDに対応するECの店舗とその店舗のスマレジ区分の在庫の行を探し、行が無ければ反映せずに終わる。本店の在庫10だけでは支店の売上が反映されない）。支店の在庫を在庫変更CSV登録（在庫区分はスマレジ、店舗は読み替えた支店）と承認で10にし、スマレジの管理画面でも支店の店舗の在庫を10にする。手順1で、支店のEC側のスマレジ在庫と在庫履歴の行数を控え、手順5・L3の在庫の期待値は支店の値で見る（本店の在庫は動かない）
  - スマレジ用アカウント：システム設定のメンバー管理で、1人だけ「スマレジ用アカウント」にしたメンバー（0201）。受注の担当者になる
  - 店舗チームの担当者：管理画面（受注管理・商品管理の在庫・会員管理）と、スマレジのレジを使える
  - 手順の前に控える値：会員の保有ポイントとポイント履歴の行数、商品「シナリオ試験ショーケース品B USM-01」のEC側のスマレジ在庫（10）と在庫履歴の行数
- 取り込みは非同期で、ECの処理が終わるまで待つ（待つのは時刻でなく完了まで。新実装は管理画面とは別の Messenger の画面に、ジョブの「完了」「失敗」が出る）
