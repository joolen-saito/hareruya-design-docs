# ポイントグランターの端末販売の受信（連携内容の種類）（USM-23）

2026-11-09 の依頼者の指摘（1回のテストに同じ条件の値を混ぜない）で、これまでシナリオ本文に並べていた値を、IPA「高信頼化ソフトウェアのための開発手法ガイドブック」(2010) 6.3.1（表6-9〜6-11）の組み合わせ表の因子・水準にした。1行が1回ずつ流すテスト1本。例外は6.3.2に合わせて1つずつ別のテスト（E1…）にした。

期待値はシナリオ本文（`../scenario_list.md` のL3と終点）にすでにあるものを水準・例外ごとに分けただけで、新しい期待値は作っていない。

## 範囲

- ポイントグランター（外部）の端末が、端末販売の内容をECのAPIへ送り、ECがスマレジへ中継して、先頭1件だけ会員のポイントに反映するまで（0517 A17-03）
- 連携内容の種類（1行・複数行・付与ポイントが負・増減が0）を別の行にする。1行の通常の付与はUEV-06・UXB-15と同じ動きなので、A1は基準の行
- 受信そのものの失敗（会員を特定できない・必須項目欠け・中継失敗・POST以外・接続情報が無効）は例外として1つずつ差し込む
