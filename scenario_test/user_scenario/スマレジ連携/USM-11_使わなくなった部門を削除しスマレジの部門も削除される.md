# USM-11 部門を削除し、スマレジの部門も削除される

| 項目 | 内容 |
|---|---|
| 利用者 | トレードチームの担当者（登録担当）→ 管理画面（部門登録/編集）→ スマレジ（試験環境） |
| 目的 | 使わなくなった部門を削除すると、ECの部門が削除され、スマレジの部門も削除されることを、EC側の値で確かめる。商品の規格などに使われている部門は削除できず、スマレジの部門も残る |
| 種類 | 正常（代表の1本＝部門登録/編集の画面で削除）＋ L3の表外の具体例4件 |
| マトリクスの行 | なし（組み合わせ表は無い。`scenario_list.md` のL3の欄にある、削除の操作（部門CSV入力のみ）・スマレジ側の削除に失敗したとき（設計書に定めが無い）を、代表1本＋表外の具体例にした） |
| もとのシナリオ | なし（設計書 0204「部門登録」（M03-18）の削除・別添「スマレジ部門連携項目」・別添「呼び出しAPIについて」から組み立てた） |

`scenario_list.md` の起点は、もとは「部門CSVで削除する」だった（2026-11-27 に画面の削除ボタンへ直した）。部門CSV（部門登録CSVアップロード）の項目に削除の指定が無く、新実装の取り込みは登録・更新だけをする。削除の手順は、設計書にも新実装にも定めがある部門登録/編集の画面の削除ボタンで書いた（判断待ち 1 の決着 2026-11-27）。部門の登録・更新は USM-10。

## 前提

- 共通の決まり：`../L4を流すときの共通の決まり.md` を先に読む（試験データの名前にシナリオIDを付ける・共有の設定は元に戻す・バッチの起動・店舗の読み替えなど）
- スマレジ側の確かめは、スマレジの試験環境で行う（2026-11-24 決定）。スマレジの部門一覧の見え方は記録だけにし、合否は「スマレジの部門が残る／消える」の記録とEC側の値（部門一覧・メッセージ）の突き合わせで付ける
- システムの外で済んでいること：スマレジの試験環境に試験用の店舗がある
- 用意するデータ（試験用の値。設計書の値ではない）
  - 削除する部門：部門名「シナリオ試験部門C USM-11」、部門コード「910111」（数字のみ。ほかの部門と重ならない値）、免税区分「対象外」。USM-10 の T01 と同じ操作で登録し、スマレジに連携済みであることを確かめてある。商品の規格・買取に使っていない
  - 削除できない部門（表外 R3）：部門名「シナリオ試験部門D USM-11」、部門コード「910112」。同じく登録し、USM-08 で作ったカード（商品規格）に、規格設定で部門として設定してある（部門が商品規格に使われている状態）
  - 登録担当：管理画面で、商品管理（部門登録/編集）を編集できる権限を持つ担当者

## 操作の流れと期待値（起点：使わなくなった部門を削除する。代表の行：部門登録/編集の画面の削除ボタン）

| # | 操作する人と操作 | 期待値（画面で見えること） |
|---|---|---|
| 1 | 登録担当：商品管理＞部門登録/編集を開き、部門一覧で「シナリオ試験部門C USM-11」の行（IDを控える）を確かめる。スマレジの試験環境の部門一覧でも、部門コード「910111」の部門を確かめる | 一覧に、ID・部門名・部門コード「910111」・免税区分「対象外」・MTGBuyer表示フラグの行がある。スマレジにも部門がある（記録） |
| 2 | 登録担当：手順1の行の「削除」ボタンを押す | 部門名を示した確認のダイアログが出る（承諾したときだけ削除する。0204 M03-18 現行仕様の節）。ダイアログの文言は設計書に無く、画面の文言を記録する |
| 3 | 登録担当：ダイアログを承諾する | 「削除しました」が出て、部門一覧に遷移する。一覧から手順1の行が消える |
| 4 | 登録担当：スマレジの試験環境の部門一覧で、部門コード「910111」の部門を探す | スマレジの部門が削除されている（見つからない。論理削除の見え方は記録）。ECの部門と同時に削除される（別添「部門削除できる機能」） |
| 5 | 登録担当：手順1と同じ部門名・部門コードで、もう一度新規に登録する（USM-10 の T01 の手順2） | 「保存しました」が出て、一覧に増える（削除済みなので重複にならない）。スマレジに部門が新規に登録される（部門IDは手順1のものと別。記録）。確かめたあと、この部門は削除してよい（試験データの片付け） |

## 終わったあとに確かめること

| 確かめる場所 | 期待値 |
|---|---|
| 部門一覧 | 手順1の部門が無い（手順5で作り直した部門を片付けたあと） |
| 規格設定・商品一覧 | この部門に紐づく商品規格は無かったので、規格の部門の表示は変わらない |

## L3で変わるところ（表外の具体例）

組み合わせ表は無い。手順の番号は上の「操作の流れと期待値」。1回ずつ別のテストとして流す。

| 行 | 条件（削除の操作・結果） | 変わるところ |
|---|---|---|
| 表外 R1 | 部門登録/編集の画面の削除ボタン・削除できる部門 | 代表の行 |
| 表外 R2 | 削除のダイアログで取り消す | 手順2のあと、ダイアログで取り消す（承諾しない）。期待値：何も起きない（部門は一覧に残り、「削除しました」は出ない）。手順4：スマレジの部門は残る。手順3・5は行わない |
| 表外 R3 | 部門が商品規格に使われている（削除できない） | 前提：「シナリオ試験部門D USM-11」（商品規格に設定済み）。手順1：一覧に行がある。手順2・3：削除を承諾する。期待値：「この部門は商品規格が使用されているため、シナリオ試験部門D USM-11 は削除することができません。」が出て、部門一覧に遷移する。一覧に行が残る。手順4：スマレジの部門も残る（EC・スマレジのどちらも削除されない）。手順5は行わない。店頭買取の買取依頼・個別入力商品・サマリに使われている部門も、それぞれ削除できない（文言は「この部門は買取依頼が使用されているため、〜は削除することができません。」「…買取依頼個別入力商品が使用されているため…」「…買取依頼サマリが使用されているため…」。買取のデータを作る UKA-01 などの区間のあとに同じ手順で確かめる。ここでは文言だけ記録） |
| 表外 R4 | 部門CSV入力で削除する（`scenario_list.md` の起点） | **実施不可（流せない）**：部門CSV（部門登録CSVアップロード）の項目（ID・部門名・部門コード・免税区分・MTGBuyer表示フラグ）に削除の指定が無く、新実装の取り込みは登録・更新だけを行う。画面の操作で起こせない。期待値（記録）は、別添「呼び出しAPIについて」12（部門CSV入力）に削除の欄があり、CSVで削除したとき、ECの部門とスマレジの部門がどちらも削除されること |
| 表外 R5 | スマレジ側の削除に失敗したとき | **実施不可（流せない）**：スマレジとの通信を失敗させる手段が設計書に無く、スマレジの接続設定は共有の環境のため、画面の操作で起こせない。期待値（記録）：設計書に定めが無い。新実装は、スマレジの削除に失敗したとき、ECの削除も取り消し、「スマレジへの部門連携に失敗したため、シナリオ試験部門C USM-11の削除を取り消しました。時間をおいて再度削除してください。」を出す（部門は一覧に残る） |

例外：組み合わせ表の例外の差し込み表は無い。例外の2件（表外 R4・R5）は上の表に書いた。
