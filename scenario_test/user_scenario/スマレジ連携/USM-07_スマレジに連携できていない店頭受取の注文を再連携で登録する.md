# USM-07 スマレジへの連携が済んでいない店頭受取の注文が、10分ごとの再連携で登録される

| 項目 | 内容 |
|---|---|
| 利用者 | 再連携のバッチ（システム）→ スマレジ（試験環境）→ 管理者（エラーメール）→ 店舗（スタック用紙）。確かめるのは店舗チーム（管理画面・スマレジの商品一覧） |
| 目的 | USM-06 で商品または在庫が未連携のまま残った注文（スマレジ商品コードがあり、削除していない）を、10分ごとの再連携が、未連携の区分に応じてスマレジに登録し、連携済みの印が付くことを確かめる。失敗した区分は未連携のまま残り、失敗のたびに管理者にエラーメールが届く。スマレジ商品コードが無い注文・削除済みの注文は再連携の対象にならない |
| 種類 | 正常（代表の1本＝商品・在庫とも未連携の注文を再連携して成功）＋ L3の表外の具体例6件 |
| マトリクスの行 | なし（組み合わせ表は無い。`scenario_list.md` のL3の欄にある、未連携の区分（商品のみ／在庫のみ／両方）・再連携の成否・対象外・通知先の未設定を、代表1本＋表外の具体例にした） |
| もとのシナリオ | なし（設計書 0405 B05-04「スマレジ商品再連携」から組み立てた。業務フロー05に工程は無い） |

## 前提

- 共通の決まり：`../L4を流すときの共通の決まり.md` を先に読む（試験データの名前にシナリオIDを付ける・共有の設定は元に戻す・バッチの起動・店舗の読み替えなど）
- スマレジ側の確かめは、スマレジの試験環境で行う（2026-11-24 決定）。スマレジの商品一覧の見え方は記録だけにし、合否は「スマレジに登録された値」と「EC側の注文の値」の突き合わせ、エラーメール、スタック用紙の印刷、受注一覧の対応状況で付ける
- システムの外で済んでいること：USM-06 の前提と同じ（本店にスタック用紙のプリンタ、スマレジの試験環境に本店に対応する店舗）
- 用意するデータ（試験用の値。設計書の値ではない）
  - 未連携の注文：USM-06 の T03 の終点（本店の店頭受取の注文を確定し、スマレジの商品登録を失敗させ、商品・在庫とも未連携のまま残っている。エラーメールが届いている）。注文番号・注文の合計金額・会員の姓カナ・名カナ（「シケン」「タロウ」）を控えてある
  - 時刻の用意：再連携は注文の時刻に関係なく未連携の注文を対象にするので、注文が確定して30分より後の状態にする。待たずに、試験で作ったこの注文に限り、開発環境で注文日を1時間前に書き換えて用意してよい（共通の決まり）。書き換えた値と元の値を控える
  - 追加システム設定：「スマレジ店舗受取用部門ID」は元の値に戻してあり、戻ったことを画面で確かめてある（USM-06 T03 の最後の手順）。「スマレジ通信エラー通知メールアドレス」は試験用の受け口に向いている（USM-06 の前提と同じ。判断待ちは USM-06 の判断待ち 2）
  - 店舗チームの担当者：管理画面（受注管理）を使える。管理者の受け口（エラーメールを読める）
- バッチの流し方：10分ごとのバッチは、時刻を待たず手で起動する（起動のしかたは根拠の欄）。このバッチは環境の中の未連携の注文を全部処理するので、合否はこの試験の注文で付け、件数は記録にする。ECの処理が終わるまで待つ（待つのは時刻でなく完了まで）
