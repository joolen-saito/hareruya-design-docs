# USM-06 店頭受取の注文の商品がスマレジに登録される

| 項目 | 内容 |
|---|---|
| 利用者 | お客様（会員）→ 店頭受取注文商品スマレジ連携のバッチ（システム）→ スマレジ（試験環境）→ 管理者（エラーメール）→ 店舗（スタック用紙） |
| 目的 | 店頭受取（本店・支店）・スムーズ店頭受取の注文を確定したあと、10分おきのバッチが、スマレジ店舗IDとスマレジ店舗コードが設定された店舗の注文にスマレジ用の商品コード（バーコード）を付け、スマレジに注文の商品（商品名・部門・金額）と在庫（1）を登録することを確かめる。スマレジの店舗IDが無い店舗の注文は連携しない。失敗したときは管理者にエラーメールが届く |
| 種類 | 正常（組み合わせ表の3行を1回ずつ流す）＋ L3の表外の具体例5件 |
| マトリクスの行 | `matrix_USM-06/matrix.md` のT01（スマレジ商品の連携＝店舗のスマレジ店舗ID・店舗コードが登録済みで、連携が成功しスマレジ商品コードが採番される）。ほかの2行（T02：店舗ID未登録で連携されない／T03：連携が失敗し、エラーメールを送って後から再連携の対象になる）と表外の具体例は「L3で変わるところ」 |
| もとのシナリオ | なし（業務フロー05 1-1・2-1・3-1・4-1 の「スマレジ連動バーコード」と、設計書 0405 B05-01 から組み立てた） |

注文からスタック用紙の印刷・ピック完了までは UOR-01（このシナリオは、その注文の商品がスマレジに登録されるところ）。失敗して未連携のまま残った注文を、あとから10分ごとに再連携するのは USM-07。

## 前提

- 共通の決まり：`../L4を流すときの共通の決まり.md` を先に読む（試験データの名前にシナリオIDを付ける・共有の設定は元に戻す・バッチの起動・店舗の読み替えなど）
- スマレジ側の確かめは、スマレジの試験環境で行う（2026-11-24 決定）。スマレジの商品一覧の見え方は設計書に定めが無いので、見えた値を記録し、合否は「スマレジに登録された値（商品名・部門・金額・在庫・商品コード）」と「EC側の注文の値（注文者のカナの氏名・注文の合計金額・注文番号・スタック用紙のバーコード）」の突き合わせで付ける（UOR の決着 A3 と同じ決まり）
- バッチの流し方：10分おきのバッチは、時刻を待たず手で起動する（起動のしかたは根拠の欄）。対象は、バッチを起動した時刻から30分前以降に確定した注文なので、注文を確定してから30分以内に起動する。バッチは環境の中の対象を全部処理するので、合否はこの試験の注文で付け、件数は記録にする。完了の表示は「店頭受取注文スマレジ連携処理が完了しました。」。ECの処理（スマレジへの登録）が終わるまで待つ（待つのは時刻でなく完了まで）
- システムの外で済んでいること：本店にスタック用紙のプリンタ（30秒おきにECへ問い合わせる設定）がある。スマレジの試験環境に本店に対応するスマレジの店舗がある。スマレジの店舗の商品一覧を見られる
- 用意するデータ（試験用の値。設計書の値ではない）
  - 店舗の読み替え：本店は店舗ID 1（画面によって「Hareruya」「トーナメントセンター 東京」と出る。スマレジ店舗IDとスマレジ店舗コードが設定済み）。「スマレジ店舗IDが無い店舗」（T02）と「支店」（L3の表外）は、流す前に既存の店舗から条件に合う店舗を選び、店舗IDと画面に出る名前を控えて読み替える。店舗は新しく作らない。条件に合う店舗が無いときは、その行を「実施不可（流せない）」として記録する
  - 会員：試験 太郎（本会員、メールアドレス `usm-06@example.test`、姓カナ「シケン」・名カナ「タロウ」、国内の住所）。UOR-01 と同じ会員でよい（注文ごとに注文番号で見分ける）
  - 商品：シングルカード「シナリオ試験カードA USM-06」（UOR-01 と同じ条件。単価1,200円・EC在庫あり）。数量2で注文する
  - 追加システム設定の「スマレジ通信エラー通知メールアドレス」（設計書の名前は「スマレジ通信エラー送信メールアドレス」）：エラーメールの確かめ（T03）の前に、設定＞基本情報設定＞追加システム設定で今の値を確かめて控える。試験用の受け口（メールを読める宛先）でなければ、試験の間だけ受け口の宛先に変え、終わったら控えた値に戻して戻ったことを画面で確かめる（共通の決まりのとおり。判断待ち 2）
  - 店舗チームの担当者：管理画面（受注管理）を使える。管理者の受け口（エラーメールを読める）

## L3で変わるところ（マトリクスの他の行・例外）

手順の番号は上の「操作の流れと期待値」。1回ずつ別のテストとして流す。注文は行ごとに別にして、注文番号を控える（同じ会員で複数の行を流すと前の行の注文が一覧に残るので、注文番号で探す）。

| 行 | 条件（スマレジ商品の連携） | 変わるところ |
|---|---|---|
| T01 | 店舗のスマレジ店舗ID・店舗コードが登録済みで、連携が成功する | 代表の行 |
| T02 | 店舗のスマレジ店舗IDまたは店舗コードが未登録で、連携されない | 前提：スマレジ店舗IDまたはスマレジ店舗コードが未設定の既存の支店を選び（設計書：支店では店頭受取だけ選べる）、その支店のサイトの会員で、本店と同じ手順で店頭受取の注文をする。手順1：支店のサイトで「購入する」（支店は「注文する」ボタンの文言が「購入する」になる。0304）。手順3：バッチを起動する。完了の表示は出る。手順4：スマレジにこの注文の商品は登録されない（探しても0件）。手順5：スタック用紙は印刷されず、対応状況は「注文受領」のまま（スマレジの商品コードが付かない。UOR-01 の例外E4と同じ）。エラーメールも届かない（エラーではなく、連携しない店舗の注文）。手順6：もう一度起動しても同じ |
| T03 | 連携が失敗し、エラーメールを送って後から再連携の対象になる | 前提：エラーメールの宛先が受け口になっていること（上の「用意するデータ」）。手順3の前に、設定＞基本情報設定＞追加システム設定の「スマレジ店舗受取用部門ID」の今の値を控え、スマレジに無い部門IDに一時的に変えて保存する（スマレジの商品登録を失敗させるため。判断待ち 2）。手順3：バッチを起動する。完了の表示は出る。手順4：スマレジにこの注文の商品は登録されない。手順4のあと：管理者の受け口に、件名「スマレジ通信エラー」のメールが届く。本文に、エラーの種類の文（エラーコードの先頭の数字で、1＝「スマレジとの認証に失敗しました。」、2＝「スマレジの設定に失敗しました。」、3・4＝「データエラーが発生しました。」、それ以外＝「例外エラーが発生しました。」）、注文番号（手順1の番号）、処理名、エラーコード、エラーの内容が出る（実際のエラーコードと文を記録）。手順5：スタック用紙が印刷されるかは、設計書に定めが無い（新実装はスマレジの商品コードの採番を、スマレジへの登録より先に行う）ので、記録とする。手順の最後：追加システム設定の「スマレジ店舗受取用部門ID」を控えた値に戻し、戻ったことを画面で確かめる。そのあと、注文から30分以内ならバッチをもう一度起動し、スマレジに商品が登録されて、手順4・5と同じになる（未連携のまま残った注文が再連携の対象になる）。30分を過ぎた未連携の注文の再連携は USM-07 |
| 表外 R1 | スムーズ店頭受取（本店）の注文 | 手順1：配送方法を「スムーズ店頭受取」、お支払い方法をクレジットカード決済にして注文する（UOR-01 のスムーズ店頭受取の流れ）。手順4：スマレジの商品の金額は0円（固定）。商品名・部門・在庫・商品コードは代表と同じ |
| 表外 R2 | 店頭PCのアカウント（店内アカウント）の注文 | 前提：UOR-06 の注文（店内アカウントで本店の店頭PCから注文）。手順4：スマレジの商品名は「店頭注文: 店頭注文番号 のご注文」の形（店頭注文番号が入る）。金額は注文の合計金額。部門・在庫・商品コードは代表と同じ。店頭注文番号は UOR-06 で控えた値 |

| 表外 R5 | エラーコードの種類（認証・設定・データ・その他）で通知の文が変わる | T03で起きた1種類は、その実際のエラーコードの先頭の数字に対応する文であることを確かめる（上のT03の期待値）。残りの種類は、スマレジの応答のエラーコードを画面の操作で選べないので、**実施不可（流せない）**として記録する |
