# USM-21 注文完了メールが送られていない注文が、毎分の再処理でポイント・在庫履歴・完了メールまで補われる

| 項目 | 内容 |
|---|---|
| 利用者 | お客様（購入）→ 再処理のバッチ（システム。毎分）→ スマレジ（試験環境。システムの外）→ お客様（メール）・通販チーム（管理画面で確かめる） |
| 目的 | 注文完了メールが送られていない注文（対応状況が「注文受領」「入金待ち」「ピック中」で、注文日時が起動の5分前〜1分前）に、再処理のバッチが注文完了メールを送る。ポイントの使用が注文に記録されているのにポイント履歴が無い注文は、ポイント履歴を作って保有ポイントを減らし、使用後のポイントをスマレジにも連携する。在庫履歴を登録する（在庫そのものは注文確認の時点で減っているので履歴だけ） |
| 種類 | 代替（購入の途中で止まった注文の回復。代表の1本）＋ L3の7件（組み合わせ表は無い） |
| マトリクスの行 | なし（組み合わせ表は無い。`matrix_USM-21/` は作っていない）。L3 は `scenario_list.md` の USM-21 の L3 欄の項目（ポイント使用あり・履歴の有無／なし、注文の状態、注文日時、メール送信履歴が既にある、同時に動いて前の処理が終わっていない）を1つずつ別のテストにした（R1〜R7） |
| もとのシナリオ | なし（業務フローには無い。設計書 0405 B05-02 による）。購入の流れは UTS-01、使用ポイントのスマレジ連携は USM-16・USM-17 |

スマレジの試験環境の画面の見え方は外部サービスなので記録だけにし、合否は EC 側の値（バッチの完了の表示・届いたメール・ポイント履歴と保有ポイント・在庫履歴）で付ける。

## 前提

- 共通の決まり：`../L4を流すときの共通の決まり.md` を先に読む（試験データの名前にシナリオIDを付ける・共有の設定は元に戻す・バッチの起動・店舗の読み替えなど）
- システムの外で済んでいること：スマレジの試験環境の管理画面で会員のポイントを見られること
- バッチは毎分動く設計だが、時刻は待たずに手で起動する（2026-11-26 決定。起動のしかたは根拠の欄）。**対象の注文は、注文日時が起動の5分前から1分前までのものだけ**なので、注文を作る（または注文日時をそろえる）のと同じ流れで、注文のあと1分以上5分以内に起動する。バッチは環境の中の対象の注文を全部処理する作りで、ほかの会員の注文にも届く。合否はこの試験の会員・注文の値で付け、対象の件数は記録にする
- 起点の用意（注文完了メールが送られていない注文）：画面の操作で作れるかどうかを、流す前に確かめる。
  - 手段A（設計書の例）：会員が、クレジットカード決済（SPLINKSの試験環境）でポイントを使って購入し、購入完了画面へ遷移する前にブラウザバックする。購入のあと、お客様のメール受け口に注文完了メールが無く、受注情報編集の対応状況が「注文受領」「入金待ち」「ピック中」のどれかで、会員のポイントが減っていなければ用意できた。新実装は購入の確定の処理の中でメールとポイントの処理まで行うので、この状態にならない（メールが届く・ポイントが減る）ことがある。ならなかったときは手段Bにする
  - 手段B：試験で作った注文に限り、開発環境で次を書き換えて用意してよい（共通の決まり「画面の操作で作れない状態の用意」。2026-11-27 決定。UPC-08 の注文日時・UMB-24 の会員の用意と同じ扱い）。(1) 通常の購入（UTS-01 の手順1〜3）で注文を作る。(2) 注文に紐づく注文完了メールの送信履歴を消す（メール受け口のメールは消えないので、届いた通数は控えて差し引く）。(3) 使用ポイントがある行は、その注文に紐づくポイント使用の履歴を消し、会員の保有ポイントを使用前の値に戻す（スマレジの会員のポイントは書き換えない）。(4) 注文日時を、起動する時刻の2〜3分前にそろえる (5) 通常の購入の連携（使用ポイント -1,000）が成功した時点で、スマレジの会員のポイントはすでに 2,000 に減っていて、手段Bはスマレジの残高を戻さない。流し始めの値として、スマレジの管理画面でスマレジの会員のポイントを確かめて控える（以下「スマレジの流し始めの値」。代表は 2,000 の見込み。ECの保有ポイント 3,000 とは食い違った状態で始まる。記録）
  - どちらの手段でも作れないときは、この行は実施不可（流せない）として記録する
- 用意するデータ（試験用の値。設計書の値ではない）
  - 会員：どれも本会員（UMB-01 の手順1〜7と UMB-02 の手順1〜2、USM-12 の手順で、この試験専用に作る。スマレジの会員が作られている）。代表 `usm21-t01@example.test`（お名前（名）「会員USM21」）。行ごとに別の会員：R1 `usm21-r1@example.test`、R2 `usm21-r2@example.test`、R3 `usm21-r3@example.test`、R4 `usm21-r4@example.test`、R5 `usm21-r5@example.test`、R6 `usm21-r6@example.test`。保有ポイントは、ポイントを使う会員（代表・R1・R3・R4・R5）は USM-15 の代表の手順（増減量 3000・備考「USM-21 付与」）で 3,000。スマレジの会員のポイントも 3,000（記録）
  - 商品：グッズ「シナリオ試験ポイントグッズ USM21」（商品コード `USM21-G01`・単価15,000円（税込）・公開・在庫20・販売制限なし。USM-16 の前提と同じ手順で登録）。数量2で商品金額合計30,000円（送料0円）。ポイントを使う注文は使用ポイント1,000で注文金額合計29,000円（USM-16 と同じ。お支払い方法は「銀行振込」）

  - 代表の注文：会員 `usm21-t01` が「シナリオ試験ポイントグッズ USM21」を数量2・銀行振込・使用ポイント1,000で買った注文（対応状況は「入金待ち」）。起点の用意のあと、注文完了メールは無く、ポイント使用の履歴は無く、保有ポイントは 3,000（減っていない）、受注の使用ポイントは 1,000。注文番号を控える（以下「控えた注文番号」）
