# USM-10 部門を登録・更新し、スマレジの部門に反映される

| 項目 | 内容 |
|---|---|
| 利用者 | トレードチームの担当者（登録担当）→ 管理画面（部門登録/編集・部門更新のCSV）→ スマレジ（試験環境） |
| 目的 | 部門を新しく使う・変更する（部門登録の画面）ときに、スマレジに部門が新規登録・更新され（部門名・部門コード・税区分「税込」・ポイント対象など）、商品の部門を直す（現状版の業務フロー09 4-6「CSVをアップロードし部門更新を行う」＝部門更新CSV登録 M03-35。依頼者の決定で試験する）ときは、CSVの商品コードに合う商品規格の部門が更新され、取込履歴（種別は部門更新）が残り、スマレジ連携の対象の規格はスマレジの商品の部門も更新されることを、EC側の値で確かめる |
| 種類 | 正常（組み合わせ表の5行を1回ずつ流す）＋例外2件 |
| マトリクスの行 | `matrix_USM-10/matrix.md` のT01（操作と対象＝部門登録の画面で、スマレジに部門が無い部門を登録する）。ほかの4行（T02〜T05）と例外E1・E2は「L3で変わるところ」 |
| もとのシナリオ | なし（設計書 0204「部門登録」「部門更新CSV登録」と別添「スマレジ部門連携項目」から組み立てた） |

部門登録CSVアップロード（M03-20）の新規・更新は、部門登録の画面と入口が違うだけなので組み合わせ表から外した（2026-11-09 依頼者決定）。部門の削除は USM-11。商品をスマレジ連携の対象にする操作は USM-08。

## 前提

- 共通の決まり：`../L4を流すときの共通の決まり.md` を先に読む（試験データの名前にシナリオIDを付ける・共有の設定は元に戻す・バッチの起動・店舗の読み替えなど）
- スマレジ側の確かめは、スマレジの試験環境で行う（2026-11-24 決定）。スマレジの部門・商品の一覧の見え方は記録だけにし、合否は「スマレジに登録された値（部門名・部門コード・商品の部門）」と「EC側の値（部門一覧・規格設定・取込履歴）」の突き合わせで付ける
- 非同期の処理（部門更新CSVでスマレジの商品の部門を直す処理）は、完了まで待つ（待つのは時刻でなく完了まで。取込履歴の「スマレジ連携状態」が「完了」になるまで）
- システムの外で済んでいること：スマレジの試験環境に試験用の店舗がある。この部門コードがスマレジにまだ無い（T01の新規）
- 用意するデータ（試験用の値。設計書の値ではない）
  - 部門（T01で作る）：部門名「シナリオ試験部門A USM-10」、部門コード「910101」（数字のみ。ほかの部門と重ならない値）、免税区分「対象外」、MTGBuyer表示フラグ（初期値のチェックあり）
  - 部門（T03〜T05で使う）：部門名「シナリオ試験部門B USM-10」、部門コード「910102」（T01と同じ要領で登録し、スマレジに連携済み）
  - 規格（T03・T05）：スマレジ連携の対象の規格＝USM-08 の手順1〜5で作ったシングルカード「シナリオ試験カードM USM-10」のSPの規格（連携フラグ「連携する」・スマレジ商品コードあり）。商品コードを控える（カードの商品コードは自動で付く。共通の決まり）
  - 規格（T04）：スマレジ連携の対象でない規格＝基準価格が300円未満のシングルカード「シナリオ試験カードN USM-10」のNMの規格（連携フラグ「連携しない」）。商品コードを控える
  - 登録担当：管理画面で、商品管理（部門登録/編集・商品CSV管理）を編集できる権限を持つ担当者
