# USM-22 スマレジの取引のあと、会員検索と会員編集でスマレジの購入回数・金額を確かめる

| 項目 | 内容 |
|---|---|
| 利用者 | 店舗チーム（レジ。スマレジの試験環境）→ スマレジ → EC → 店舗統括・顧客戦略（管理画面の会員検索・会員編集） |
| 目的 | 会員がレジだけで買い物をしたあと、管理画面の会員検索一覧で「スマレジ購入金額」「スマレジ購入回数」の範囲（開始・終了）で会員を探せ、会員編集の画面に「スマレジ累計購入回数」「スマレジ累計購入金額」が出て、値が会員のレジの取引の件数・合計と合う。取引が無い会員は 0。非会員の取引は数えない。取引を返品すると集計から外れ、件数・金額が減る（新実装の動き） |
| 種類 | 正常（代表の1本）＋ L3の6件（組み合わせ表は無い） |
| マトリクスの行 | なし（組み合わせ表は無い。`matrix_USM-22/` は作っていない）。L3 は `scenario_list.md` の USM-22 の L3 欄の項目（検索：金額のみ／回数のみ／両方／範囲外、取引が無い会員、非会員の取引、取引の返品のあと）を1つずつ別のテストにした（代表が金額のみ、R1〜R6） |
| もとのシナリオ | なし（業務フローには無い。設計書 0207 会員検索一覧・会員登録編集による）。レジの取引の反映（購入パターン8）の細部は USM-01、返品は USM-02 が受け持つ。ここは会員の集計の値と検索に絞る |

スマレジの試験環境の画面の見え方は外部サービスなので記録だけにし、合否は EC 側の値（会員検索の結果・会員編集の累計・受注情報検索の受注）で付ける。

## 前提

- 共通の決まり：`../L4を流すときの共通の決まり.md` を先に読む（試験データの名前にシナリオIDを付ける・共有の設定は元に戻す・バッチの起動・店舗の読み替えなど）
- システムの外で済んでいること：スマレジの試験環境のレジで、会員の番号（マイページのバーコード）を読み取って会計できる。スマレジの試験環境の取引の通知がECに届く状態
- このシナリオが数えるもの：設計書は会員の購入回数・金額の算出のしかたを定めない（記録）。累計（購入回数・金額）と、それを使う会員検索の結果は、設計書から合否の値として言えないので、合否を付けない記録の値にする（0207 の識別ID 27〜30・41・42 は項目の名前を定めるだけ）。試験の取引2件の件数と合計から見込む値は 2回・5,500円。レジだけの取引から作られる受注は、設計書（0505 スマレジ受信処理 F63「この新規データは出荷完了で登録する」）も新実装も「出荷完了」で作る。新実装の累計の集計は「引渡し済み」の受注だけを数えるので、「出荷完了」の受注は入らず、累計は 0回・0円のままになる見込み。見えた値を記録し、手順はそのまま先へ進む（検索の手順7・R1〜R6 も、見込みの値で検索し、出る・出ないを記録する）。合否を付けるのは受注の状態（出荷完了）など、設計書に定めのある値だけ
- 用意するデータ（試験用の値。設計書の値ではない）
  - 会員：どれも本会員（UMB-01 の手順1〜7と UMB-02 の手順1〜2、USM-12 の手順で、この試験専用に作る。スマレジの会員が作られている）。代表 `usm22-t01@example.test`（お名前（名）「会員USM22」）、R4 `usm22-r4@example.test`（取引なし）
  - 商品：グッズ「シナリオ試験レジグッズ USM22」（商品コード `USM22-G01`・単価1,100円（税込）・公開・在庫20・販売制限なし。スマレジ連携を有効にした商品。USM-01 の購入パターン8（T14）の前提と同じ手順で登録する）
  - 店舗チームの担当者：管理画面の会員管理（会員一覧・会員編集）と受注管理（受注情報検索）を使えるアカウント
  - 取引（代表の会員）：レジで会員 `usm22-t01` の番号を読み取り、「シナリオ試験レジグッズ USM22」を、取引a：数量2（合計 2,200円）、取引b：数量3（合計 3,300円）で会計する（どちらもレジだけの買い物。USM-01 のT14と同じ流れ）。したがって、2回の取引の件数は 2、合計は 5,500円
  - 手順の前に控える値：会員の「スマレジ累計購入回数」「スマレジ累計購入金額」（0・0）、受注情報検索でスマレジ取引IDが付く受注の件数
- 画面の名前・文言は新実装の表示で書く。設計書の名前と違うときは「（設計書：…）」を添える

## L3で変わるところ（組み合わせ表は無い。1つずつ別のテストにする）

手順の番号は上の「操作の流れと期待値」。検索の行は、手順6まで済んだ代表の会員で流す。累計と検索の結果は、どの行も記録のみ（見込みの値は回数 2・金額 5,500円）。どの行も、検索の欄に会員のメールアドレスを入れて、ほかの会員が混ざらないようにする。

| 行 | 条件 | 変わるところ |
|---|---|---|
| R1 | 検索：回数のみ | 手順7の代わりに、「スマレジ購入回数」の開始に 2、終了に 2 を入れ、金額は空にして検索する。会員が1件出る（回数 2 が範囲に入る）。開始に 3 だけを入れると出ない（3 以上でない）。終了に 1 だけを入れても出ない |
| R2 | 検索：両方 | 手順7の代わりに、「スマレジ購入金額」の開始 5000・終了 6000 と、「スマレジ購入回数」の開始 2・終了 2 を両方入れて検索する。会員が1件出る（両方の条件を満たす）。金額は範囲に入り、回数だけ範囲外（開始 3）にすると出ない |
| R3 | 検索：範囲外 | 手順7の代わりに、「スマレジ購入金額」の開始に 6000、終了に 7000 を入れて検索する。記録のみ：累計が見込みどおり 5,500円なら会員は出ない（範囲に入らない）。「検索結果がありません」などの表示は記録する |
| R4 | 取引が無い会員（0） | 会員 `usm22-r4@example.test`（取引なし）を使う。手順1・4・6：回数が「0回」、金額が「0円」のまま。手順7の代わりに、「スマレジ購入金額」の開始 0、終了 0 で検索すると会員が出る（0 が範囲に入る）。開始 1 以上にすると出ない |
| R5 | 非会員の取引（会員に紐づかず数えない） | 手順6まで済んだ代表の会員の値（回数 2・金額 5,500円）を控える。レジで、会員の番号を読み取らずに（非会員のまま）、同じ商品を数量1で会計する（USM-01 のパターン9）。ECに取引が届いたあと、受注情報検索に、注文者が会員でない受注が1件増える（記録）。代表の会員編集：回数・金額が手順の前の値から変わらないことを記録する（会員に紐づかない取引は数えない見込み。合否は付けない）。ほかの会員の累計も、この取引では変わらない |
| R6 | 取引の返品のあと | 手順6まで済んだ代表の会員の値を控える。USM-02 の手順で、取引b（数量3・3,300円）をスマレジで全返品する。ECに届いたあと、その受注の対応状況が「キャンセル」になる（USM-02）。代表の会員編集：回数・金額の変化を記録する（記録のみ。返品した取引の分が外れれば、見込みは回数 1回・金額 2,200円。設計書に返品後の定めは無く、合否は付けない。新実装は、もともと「出荷完了」のレジだけの受注を数えない見込みで、0のまま変わらない）。手順7の検索：見込みどおりなら、開始 5000・終了 6000 では出なくなり、開始 2200・終了 2200 で出る（記録） |
