# UOR-03 お客様が受け取りに来て、支払い済みのスムーズ店頭受取（本店）の商品を、身分証明書を確かめて引き渡す

| 項目 | 内容 |
|---|---|
| 利用者 | 会員のお客様（国内）→ 店舗チーム → スマレジ → EC（取り込み） |
| 目的 | クレジットカード決済で支払い済みのスムーズ店頭受取の商品を、身分証明書・注文日・名前を確かめて引き渡し、スマレジで0円決済して、受注が「出荷完了」になる |
| 種類 | 正常（組み合わせ表は無い。1本） |
| マトリクスの行 | なし（`scenario_list.md` のとおり1本。バリエーションの条件は下の「L3で変わるところ」） |
| もとのシナリオ | SCN-ORDER-003 |

## 前提

- 共通の決まり：`../L4を流すときの共通の決まり.md` を先に読む（試験データの名前にシナリオIDを付ける・共有の設定は元に戻す・バッチの起動・店舗の読み替えなど）
- システムの外で済んでいること：UOR-01 の終点まで済んでいる（スムーズ店頭受取の注文がピック完了で、商品とスタック用紙がレジ裏にある）
- 用意するデータ（試験用の値。設計書の値ではない）
  - 会員：試験 太郎（`uor-03@example.test`）。本店のスムーズ店頭受取を、クレジットカード決済で「シナリオ試験カードA」数量2（単価1,200円）で注文済み。受注は「ピック完了」。注文番号・注文日を控えてある。受注の金額は決済済み
  - 店舗チームの担当者：管理画面とスマレジのレジを使える。お客様は身分証明書（試験用の氏名が確かめられるもの）を持参する
- スマレジの商品（スタック用紙のバーコードの商品）は金額0円で登録されている（UOR-01 手順6）

## 操作の流れと期待値

| # | 操作する人と操作 | 期待値（画面で見えること） |
|---|---|---|
| 1 | お客様：来店し、身分証明書・注文日・名前を示す。店舗チーム：管理画面の受注情報検索で対応状況「ピック完了」の受注を探し、スタック用紙と突き合わせる | 注文日・お名前・ご注文番号が、スタック用紙・受注情報と一致する。身分証明書の氏名が受注のお名前と同じ（システムの外の確認）。対応状況は「ピック完了」、支払方法は「クレジットカード決済」、配送方法は「スムーズ店頭受取」 |
| 2 | 店舗チーム：受注一覧で、支払方法「支払いなし」と「クレジットカード決済」・配送方法「スムーズ店頭受取」で検索し、手順1の受注を選んで「納品書印刷（日本語）」を押す | 検索結果に手順1の受注が出る。納品書が画面に表示され、ご注文番号・商品・数量・金額が受注と同じ。「印刷する」を押すとブラウザの印刷ダイアログが開く（0203 納品書印刷（日本語））。納品書の出力に失敗したときのメッセージは出ない |
| 3 | 店舗チーム：商品をお客様に渡し、納品書にサインをもらう（システムの外の作業） | 画面の変化は無い。受注一覧の対応状況は「ピック完了」のまま |
| 4 | 店舗チーム：スマレジのレジで、スタック用紙のバーコードを読み、0円で決済する（スムーズ店頭受取のため決済済みだが、スマレジ上では0円決済） | スマレジの取引が合計0円で完了する |
| 5 | （システム）スマレジの取引完了がECに届き、ECが取引の詳細を取り込む。店舗チーム：管理画面の受注情報検索で、手順1のご注文番号を検索する | 同じ受注が「出荷完了」になる（元の受注がそのまま出荷完了になる。スマレジの取引から新しい受注は作られず、一覧に同じご注文番号の受注が1件だけ出る） |
| 6 | お客様：マイページの購入履歴を開く | 注文の処理状態の画像が、スムーズ店頭受取の受け取り済みを表す画像になる。0304 別添は、スムーズ店頭受取の出荷完了の画像は使わず（×）、「購入済み」の画像（○）を使うとする。画像のため、見た目を記録する |
| 7 | 店舗チーム：会員の保有ポイントとポイント履歴を見る | 付与は、受取後にスマレジの取引の付与値が会員に反映される（付与値が0なら増えない。額の計算はスマレジ側。ポイントのUPT-04）。保有ポイントの増減が、スマレジの取引の付与値と同じ |
