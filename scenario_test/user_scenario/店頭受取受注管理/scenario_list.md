# 店頭受取受注管理：シナリオ一覧（L2）

シナリオ1本は「起点の業務イベントから、業務として完了した状態になるまで」とする。担当者が替わっても切らない（お客様→店舗チーム→スマレジ→通販チーム）。日をまたぎ、受注の状態が何かを待つもの（ピック完了のまま受け取りを待つ取り置き、取り置き期限の超過、夜間のバッチ）は別の1本にする。店頭受取は、注文からピック完了までと、お客様が受け取りに来る引き渡しと、期限を過ぎてのキャンセルを分ける。条件違いはL3のバリエーションとして、組み合わせテストマトリクス（ペアワイズ）で絞る。

### 店頭受取に当てはまる表示事項の判断（まとめ）

詳細と根拠は `legal_check.md`。申込みは通販と同じ画面で確定ボタンを押して行うので、画面の表示事項は通販と同じ物差しで確かめる。当てはまる：分量・販売価格と支払総額・支払の時期と方法（店頭支払は受け取りのとき、クレジットカード決済は注文のとき）・引渡時期（受取店舗と取り置き期間）・申込みの撤回と解除。当てはまらない：申込期間（予約商品を扱わないため）、定期購入などの条件付き表示。店頭PC（UOR-06）は確認項目を付けるが、通信販売の表示義務が及ぶかは法務の判断（判断待ち）。
