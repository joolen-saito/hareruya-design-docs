# UOR-09 受け取りが済んだ・キャンセルした店頭受取の商品を、夜間にスマレジから削除する

| 項目 | 内容 |
|---|---|
| 利用者 | スマレジ連携のバッチ（システム）。結果は店舗チーム（管理画面・スマレジ）と管理者（エラーメール）が確かめる |
| 目的 | 毎日4時にバッチが動き、「キャンセル」「引き渡し済み」「出荷完了」の受注に付いたスマレジの商品が削除され、EC側に削除済みの印が付く（印は管理画面に出ないので、スマレジから商品が消えることで確かめる）。連携に失敗した受注は管理者にエラーメールが届く |
| 種類 | 正常（夜間バッチ） |
| マトリクスの行 | `matrix_UOR-09/matrix.md` のT01（キャンセル：スマレジ商品を削除する）。業務フロー05 1-10 の「情報削除」 |
| もとのシナリオ | SCN-ORDER-001〜008 の各最後の工程 |

## 前提

- 共通の決まり：`../L4を流すときの共通の決まり.md` を先に読む（試験データの名前にシナリオIDを付ける・共有の設定は元に戻す・バッチの起動・店舗の読み替えなど）
- システムの外で済んでいること：スマレジの店舗が登録済み。バッチは毎日4時に動く設定（試験では同じバッチを手で起動してよい）
- 用意するデータ（試験用の値。設計書の値ではない）
  - キャンセルの受注（UOR-04で作った受注）：スマレジの商品コードが付いていて、削除済みの印が付いていない。スマレジの商品一覧に、この注文の商品「シケン タロウ 様のご注文」が残っている
  - 比べるための受注：対応状況が「ピック完了」の受注1件（スマレジの商品コードあり）。対象の状態でないので、削除されない

## 操作の流れと期待値

| # | 操作する人と操作 | 期待値（画面で見えること） |
|---|---|---|
| 1 | 店舗チーム：バッチの前に、スマレジの商品一覧で、キャンセルの受注の商品と、比べるための受注（ピック完了）の商品を探す | どちらの商品もスマレジの商品一覧にある |
| 2 | （システム）毎日4時にバッチが動く。または試験として同じバッチを起動する | エラーなく終わる。対象は、スマレジの商品コードがあり、削除済みの印が付いておらず、注文の状態が対象の状態の受注。新実装のバッチは、対象の受注ごとにスマレジの商品の削除を依頼として積んで終わり、スマレジへの削除は別の処理が順に行う（待つ時間は設計書に無い） |
| 3 | 店舗チーム：削除の依頼が処理されるのを待ってから、スマレジの商品一覧で、手順1の2つの商品を探す | キャンセルの受注の商品は、スマレジから削除されている（論理削除）。ピック完了の受注の商品は残っている |
| 4 | 店舗チーム：管理画面でキャンセルの受注を開く | 対応状況は「キャンセル」のまま変わらない。EC の受注に付く削除済みの印（0405 実行結果詳細「注文データの削除フラグを立てる」）は管理画面に表示が無いので、画面では確かめない（削除は手順3のスマレジの商品一覧で確かめる） |
| 5 | （システム）手順3で削除を確かめたあと、同じバッチをもう一度起動する | 削除済みの受注は対象にならず、スマレジへの連携は行われない（エラーメールも届かない） |
