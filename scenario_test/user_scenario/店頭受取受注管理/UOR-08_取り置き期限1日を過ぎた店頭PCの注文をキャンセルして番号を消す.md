# UOR-08 取り置き期限（1日間）を過ぎた店頭PCの注文をキャンセルし、店頭モニターから番号を消し、翌日に商品を戻す

| 項目 | 内容 |
|---|---|
| 利用者 | 店舗チーム（管理画面・店頭モニター） |
| 目的 | 注文日を含めて1日間を過ぎても受け取りに来ない店頭PCの注文を、店舗の人が「キャンセル」にし、店頭モニターから店頭注文番号を消し、翌日にまとめてピックした商品を元の場所に戻す |
| 種類 | 正常（期限超過のキャンセル） |
| マトリクスの行 | `matrix_UOR-08/matrix.md` のT01（本店：ピック完了・キャンセル・出荷完了に合わせて店頭モニターの番号が自動で表示・削除される）。業務フロー05 4-6〜4-9 を通す |
| もとのシナリオ | SCN-ORDER-008 |

## 前提

- 共通の決まり：`../L4を流すときの共通の決まり.md` を先に読む（試験データの名前にシナリオIDを付ける・共有の設定は元に戻す・バッチの起動・店舗の読み替えなど）
- システムの外で済んでいること：UOR-06 の終点まで済んでいる（店頭PCの注文がピック完了で、店頭モニターに店頭注文番号が出ている）。お客様は受け取りに来ていない
- 取り置き期限（1日間）を過ぎた受注は、試験で作った受注に限り、開発環境で注文日を期限より前に書き換えて用意する（2026-11-26 依頼者「おすすめどおり」。設計書に試験用の手段が無い）
- 用意するデータ（試験用の値。設計書の値ではない）
  - 店頭PCの注文：本店・店内アカウントで「シナリオ試験カードA」を数量2（単価1,200円）で注文済み。支払方法は店頭支払。店頭注文番号（TC注文番号）と注文番号を控えてある。受注は「ピック完了」で、注文日を含めて1日間を過ぎている（注文日の翌日以降）。在庫は5から3に減っている
  - 店舗チームの担当者：管理画面で本店の受注を編集できる権限を持つ
- 注文日の翌日以降の受注の用意の方法：UOR-04の判断待ち 1と同じ（設計書に試験用に注文日を古くする方法は無い）
