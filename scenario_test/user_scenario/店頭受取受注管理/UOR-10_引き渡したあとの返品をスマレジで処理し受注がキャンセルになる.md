# UOR-10 引き渡したあとの返品をスマレジで処理し、受注がキャンセルになる

| 項目 | 内容 |
|---|---|
| 利用者 | 会員のお客様 → 店舗チーム → スマレジ → EC（取り込み）→ 店舗チーム・通販チーム（管理画面で確かめる） |
| 目的 | お客様が引き渡し済みの商品の返品を申し出て、店舗がスマレジで全返品の取引を登録し、ECに取り込まれて、スマレジの取引から作った受注が「キャンセル」になり、EC在庫（ついで買いがあるときはスマレジ在庫も）が戻り、ポイントが戻る |
| 種類 | 正常 |
| マトリクスの行 | `matrix_UOR-10/matrix.md` のT02（返品の取引の種類＝取消・店頭受取注文＋ついで買いのスマレジ決済：スマレジ在庫とEC在庫を戻す・引き渡した注文＝店頭受取の注文） |
| もとのシナリオ | （SCN-ORDER は無い。0203 別添「スマレジ決済後返品処理について」・0505 A05-04 の返品） |

## 前提

- 共通の決まり：`../L4を流すときの共通の決まり.md` を先に読む（試験データの名前にシナリオIDを付ける・共有の設定は元に戻す・バッチの起動・店舗の読み替えなど）
- システムの外で済んでいること：UOR-02 のT02の終点まで済んでいる（店頭受取の商品をスマレジで決済して引き渡し済み）。お客様が全部の商品を返品したいと申し出る
- 用意するデータ（試験用の値。設計書の値ではない）
  - 引き渡し済みの注文：元の受注は「引き渡し済み」、スマレジの取引から作った新しい受注は「出荷完了」。明細は店頭受取分「シナリオ試験カードA」数量2（単価1,200円）とついで買い分「シナリオ試験ショーケース品B」数量1（単価800円）。取引ID・取引の合計を控えてある
  - 在庫：カードAのEC在庫は3（注文で5から減ったまま）、ショーケース品Bのスマレジ在庫は9
  - 会員：試験 太郎（保有ポイントを控える）
- 返品は全部だけ（一部返金は想定しない）

## 判断待ちだったこと（2026-11-26 すべて決着。依頼者「おすすめどおり」。一覧は `../判断待ち_L4_店頭受取受注管理.md`）

1. （決着 2026-11-26 依頼者「おすすめどおり」）スマレジでの「取消」と「打消し」の操作の呼び方と手順：0505 は取引の取消（取消の区分）と打消取消（打消しの区分）を処理の分岐として定めるが、スマレジのレジ画面での操作は設計書に無い。見たもの：0505 A05-04 のWebhookの取引種別（取消・打消取消）。決めたこと：スマレジの操作は試験の準備として、スマレジの取引の種類（取消・打消し）がECに届いて、対応する受注が見つかることだけを合否にする
2. （決着 2026-11-26 依頼者「おすすめどおり」）T05・T06 の水準「店頭受取とついで買い」は取引の種類（取消／打消し）を決めない：組み合わせ表は、この水準を「返品の取引の種類」の因子に置いている（取引の種類と別の話）。決めたこと：取消で通す。組み合わせ表は変えていない（報告に書く）
3. （決着 2026-11-26 依頼者「おすすめどおり」）返品後のポイントの正確な増減：付与額の計算はスマレジ側。決めたこと：ポイント履歴で、返品の取引に紐付く履歴が戻ることを確かめ、額は取引の付与値と同じことだけを合否にする
