# 商品管理から注文確認メールまで：シナリオ一覧（L2）

バックオフィスで商品を用意し（登録・価格・在庫・公開）、お客様の画面に出し、お客様が買って、注文確認メールが届くまでを、それだけで読んで流せる通しのシナリオにする。商品登録・編集（UPR）・価格管理（UPC）・在庫管理（UZK）・通販（UTS-01）・業務横断（UXB-13）に分かれている区間を、1本につなぎ直したもの。各業務の一覧は書き換えず、区間ごとに既存のIDを参照する。

## シナリオの単位（切る場所と切らない場所）

シナリオ1本は「起点の業務イベントから、業務として完了した状態になるまで」。起点は「バックオフィスで商品を用意する（登録・価格・在庫・公開）」、終点は「お客様に注文確認メールが届き、その内容が注文と一致する」とする。担当者が替わっても切らない（トレードチーム→在庫の承認者→顧客戦略チーム→お客様）。

| 場所 | 扱い | 理由 |
|---|---|---|
| 在庫の入庫承認（登録した本人は承認できず、承認者が別の担当者） | 切らない。1本の中に承認者の手順を入れる | 承認待ちの状態は担当者が替わるだけで、日をまたいで何かを待つ状態ではない（営業日内に承認者が処理する運用）。UPR-05・UZK-01と同じ扱い。承認が遅れて、承認前のお客様の画面を見る場合は例外X01・X02として差し込む |
| 商品が入荷するのを待つ | 前提として扱う（起点は「入荷した商品の在庫を入れる」） | 入荷はシステムの外の物流で、システムの状態が待つのではない（UZK-01・UPR-05の起点と同じ） |
| 予約商品が発売日を待つ | 範囲外。別の1本（UPR-03・UTS-04） | 日をまたぎ、システムの状態（予約用の購入グループ）が発売日を待つ |
| 郵便振替・銀行振込・コンビニ決済の入金待ち | 購入完了と注文確認メールまでをこのシナリオの終点にし、入金確認から先は別の1本（UTS-16・UTS-17・UTS-18） | 日をまたぎ、受注の状態（入金待ち／注文受領）が入金を待つ |
| セールの取り下げ（取り下げは火曜日・更新は水曜日の別の作業） | 別の1本（UPM-06） | 業務フロー11の1-4が取り下げと更新を別の作業にし、取り下げの時点でセール中の状態が後日の作業を待つ。UPM-02はセール開始から注文確認メールまでで終える |
| 出荷（通販チームのピック・梱包・出荷完了メール） | 範囲外（UTS-01） | 終点を「注文確認メール」に定めた |
| 画像のS3保存・画像パス対応表・公式サイトのカードリスト | システムの外。起点の前提として書く | システムを触らない作業 |

### 設計書との食い違い（設計書の不足。起票はしない）

- 注文確認メールの件名・本文の項目・文言を定める設計書が無い（宛先・件名・本文の項目・支払方法ごとの案内・店舗への控え・英語本文の税額）。0304 は「注文完了メールを送信します」、0405 は再送の条件、0209 はヘッダー・フッターの編集だけを書く。新実装のテンプレートが事実上の仕様になっている。期待値は「注文と一致する」だけを書いた
- 注文確認メールの宛先を設計書は書かない（出荷完了メールだけ「注文のメールアドレス・店舗の代表アドレスに控え」と書く：0203 出荷実績インポート登録）。新実装は注文確認メールも同じ宛先
- 注文確認メールの言語：0405 は再送のとき「会員の都道府県が海外のときは英語」と書くが、購入時の言語の決め方は書かない。新実装は購入時のサイトの言語（日本語なら日本語、それ以外は英語）で選ぶので、海外のお届け先を日本語サイトで買うと日本語のメールになり、国内の会員が英語サイトで買うと税額つきの英語のメールになる。再送は呼び出し側の指定の言語で、設計書の「会員の都道府県が海外のとき」と決め方が違う。この一覧の期待値は新実装の決め方で置いた（UPM-01の言語R2・UPM-05の言語F2）
- 英語のメールの注文番号・日付の書式（日付は月/日/年、注文番号の桁）は設計書に無い。0405 は「受注番号は8桁のゼロ埋め」とだけ書く
- 公開ステータスの数字：商品登録・編集/scenario_list.md の食い違いと同じ（0204 カード商品CSVフォーマットは「1: 非公開 2:公開 3:廃止」、新実装は1＝公開）。この一覧では名前で書いた
- 販売制限数（商品規格・CSV）と購入上限数（買い物かご）、販売制限（商品登録編集の項目名）と地域別販売制限（CSVの項目名）：同じ値を指すと読んだが、設計書に対応づけが無い
- 0304 ご注文方法指定は店頭受取の支払方法を「店頭支払」と書くが、受注に「店頭支払」の購入完了メールを送るかは書かれていない（新実装は店頭支払のテンプレートで送る）
- 0304 決済~購入完了は「受注ステータスが注文受領または入金待ち」を完了の条件とするが、クレジットカード決済の購入直後の状態（新実装は入金済み）に触れない。この一覧は新実装の状態を書き、設計書が決まるまで合否は購入完了画面とメールの有無で見る
