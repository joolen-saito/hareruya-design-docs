# 商品管理から注文確認メールまでの本店の購入（UPM-01）

IPA「高信頼化ソフトウェアのための開発手法ガイドブック」(2010) の表6-9〜6-11と同じ手順で作る。FL表は `fl_table.tsv`、禁則表は `prohibitions.tsv`、例外の差し込み表は `exceptions.tsv`、マトリクスは `matrix.md`・`matrix.tsv`（`tools/build_matrix.py` が作る）。1行が1本のシナリオ（L3）になる。

## 範囲

- 本店のオンラインショップで、国内のお届け先に、日本語または英語のサイトで、会員が買うところまで。商品を用意する（CSV登録・価格・在庫の入庫と承認・公開）ところから、注文確認メールが届くまでを1行で通す
- 海外のお届け先は `../matrix_UPM-05/`。支店と公開状態の切り替えはUPM-03、価格を変える操作はUPM-02、購入上限数・在庫不足などの買えない場合はUPM-04（どれも `../scenario_list.md`）
- 予約商品（発売日待ち）は日をまたいでシステムの状態が待つので範囲に入れない（UPR-03・UTS-04）。同梱・店頭受取・スムーズ店頭受取・店頭支払は店頭受取受注管理（UOR-01）・通販（UTS-16）で扱う
- 郵便振替・銀行振込・コンビニ決済の行は、購入完了と注文確認メールまでで終点。入金を待つ先はUTS-16（郵便振替・銀行振込）・UTS-17（コンビニ決済）・UTS-18・20・21（入金が無いとき・入金を待たない出荷準備）。クレジットカード決済・登録済みクレジットカード決済・全額ポイント支払い・代金引換の行は、購入完了と注文確認メールを終点にする（出荷はUTS-01）

## 因子の流用元

購入の因子（探し方・カートに入れる画面・数量・配送方法・支払方法・ポイント・金額・備考・言語）は `通販/matrix/fl_table.tsv`（2026-11-05 時点）から流用した（各水準の扱い欄に流用元の水準IDを書いた）。バックオフィス側の因子（商品の種類・在庫の入れ方・公開の仕方・販売価格）はこのマトリクスで足した。禁則は通販のX5・X12・X19〜X22・X37・X43・X49〜X52を、この因子に合わせて流用した。

代金引換（I6）は支払額（商品金額合計＋送料＋手数料330円−ポイント使用）が29,999円以内のときだけ選べる（設計書 0304 ご注文方法指定 業務ロジック「お支払い方法の選択肢は、使用ポイントを差し引いた注文金額合計によって変わる」、新実装の支払方法の絞り込み）。送料無料金額以上は、代金引換が選べる支払額（29,999円以内）にならない水準K2（ポイントを使わない・少なく使う・全額ポイント）と、ポイントの一部使用で支払額が上限以内になる水準K3に分け、重ならないようにした。K2では代金引換は組まない（禁則X3）。K3はポイントの一部使用（J2）だけと組む（禁則X12・X13）。ゆうパケットが消えるのはK2と同じ（X14）。

## 実装で確かめたこと（2026-11-05）

- 注文確認メールのテンプレートは支払方法ごと・言語ごとに別（開発環境の設定 2026-09-07：クレジットカード決済・登録済みクレジットカード決済・コンビニ決済・郵便振替・銀行振込・代金引換・店頭支払・支払いなし（全額ポイント支払い）の各日本語・英語）。件名はテンプレートの件名の前に「[店名] 」が付く。宛先は受注のメールアドレス、同じ内容が店舗の代表アドレスにも控えとして送られる。根拠は新実装のメール送信の処理（受注メールの送信。支払方法のテンプレートを選び、件名・宛先・控えを設定する処理）
- 設計書は注文確認メールの件名・本文の項目を書いていない（0304 F04-04 は「注文完了メールを送信します」、0405 B05-02 は再送の条件、0209 M10-08・M10-09 はヘッダー・フッターの編集だけ）。このため、メールの期待値は「注文と一致する」ことだけを書き、項目と文言は新実装の事実として参考に書く（`../UPM-01_*.md`）
