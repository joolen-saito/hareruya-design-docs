# UPM-02 セール価格で買い、注文確認メールの金額がセール価格になる

| 項目 | 内容 |
|---|---|
| 利用者 | トレードチームの担当者（商品と在庫を登録する）→ 在庫の承認者 → 顧客戦略チームの担当者（セール価格にする）→ 会員のお客様（国内） |
| 目的 | 登録したカードをセール価格に切り替え、お客様がセール価格で買い、注文確認メールの金額がセール価格で届く（セール開始の場合） |
| 種類 | 正常 |
| マトリクスの行 | `matrix_UPM-01/matrix.md` のT25（シングルカード・在庫変更CSV登録・登録のときから公開・セール中・在庫と同じ数・キーワード検索・商品一覧から・ゆうパック・コンビニ決済・ポイントをためる・送料無料金額以上・配送希望なし・備考あり・日本語） |
| もとのシナリオ | SCN-PRICE-001・005、SCN-PRODUCT-004 |

このシナリオはセールの**開始**から注文確認メールまで。セールの取り下げ（日をまたいで別に行う作業）は UPM-06、通常商品の基準価格変更は L3（下記）で終点が違う。

## 前提

- システムの外で済んでいること：カードの商品画像をS3へ保存済み。カードが入荷している。セール品の選定（UPC-01の1-1〜1-3）は済み、価格を書いたCSVができている
- 用意するデータ（試験用の値。設計書の値ではない）
  - トレードチームの登録担当、在庫の承認者（別の担当者）、顧客戦略チームの担当者
  - 会員：試験 花子（メールアドレス `upm-02@example.test`、国内（東京都）の住所を登録済み）
  - 商品：シングルカード「シナリオ試験カードB」（言語＝日本語、状態＝NM、基準価格・販売価格20,000円、購入グループ「通常商品」、商品カテゴリを1件）。商品公開ステータス＝公開、支店の商品公開ステータス＝非公開で登録する
  - 入庫：在庫変更CSV登録で2点。セール価格 17,000円（CSVのセールフラグ1、買取価格も入れる）。送料無料金額は30,000円（開発環境の値）

## 操作の流れと期待値

| # | 操作する人と操作 | 期待値（画面で見えること） |
|---|---|---|
| 1 | 登録担当：管理画面の商品管理で「カード商品CSV登録」を開き、商品IDを空にしたCSV（「シナリオ試験カードB」1行・基準価格20,000円・販売価格20,000円・商品公開ステータス＝公開）を選んでアップロードする | 「CSVファイルをアップロードしました」が出て、CSVの取込履歴が1件増える |
| 2 | 登録担当：商品マスターで「シナリオ試験カードB」を検索し、商品編集画面と規格設定を開く | 商品公開ステータスは「公開」。規格は1件で、基準価格・販売価格がどちらも20,000円、セールフラグは無効、在庫は0 |
| 3 | 登録担当：商品管理の「在庫変更CSV登録」で、入庫2点のCSVを承認通知先に承認者を選んで取り込む | 在庫編集承認一覧に「未承認」で登録され、承認者に通知メールが届く。在庫は0のまま |
| 4 | 承認者：在庫編集承認一覧で登録された行を選び、「承認」→確認の「本当に承認してもよろしいですか」でOKを押す | 承認状態が「承認済」になり、登録担当に承認ステータス変更のメールが届く。商品マスターの在庫が2になる |
| 5 | 顧客戦略チームの担当者：「セール用価格変更CSV登録」で、商品ID・言語ID・販売価格17,000円・買取価格・セールフラグ「1」（セールである）のCSVを取り込む | エラーが出ずに取り込みが終わる。商品編集画面の規格設定で、セールフラグが有効、基準価格20,000円、販売価格17,000円になっている。買取・販売価格履歴に変更前後の価格が1件残る |
| 6 | お客様：本店のトップページを開き、ログインして、ヘッダーの商品検索欄に「シナリオ試験カードB」を入れて検索する | エラーが出ずにログインでき、商品一覧に「シナリオ試験カードB」が出る。「Sale」ラベル、カード言語「日本語」、状態「NM」、在庫2、価格17,000円（セール価格）が表示される。商品数の初期値は1 |
| 7 | お客様：商品数をプラスで2にして「カートに追加」を押す | 画面右下に「カートに追加しました：」が出て、商品一覧の画面に留まる。在庫2より多い数にはできない |
| 8 | お客様：買い物かごを開く | 数量2・小計34,000円（17,000円×2）・「現在送料無料です。」・「合計(税込)」・「購入手続きへ」が出る |
| 9 | お客様：「購入手続きへ」を押し、ご注文方法指定画面で、配送方法「ゆうパック」・支払方法「コンビニ決済」を選び、備考欄に文を書く。ポイントは「ポイントをためる」のまま | お届け先に登録済みの住所、ご注文の商品に数量2が出る。ご注文内容の確認に、商品金額合計34,000円・送料0円・手数料0円・注文金額合計（税込）34,000円が出る（送料無料）。注文ボタンの文言の変わり方は、設計書の「支払方法によって文言の変更をする」に当たる表示として記録する |
| 10 | お客様：注文金額合計（税込）を控え、確定のチェックボックスにチェックを入れ、注文のボタンを押す。コンビニ決済の画面（試験環境ではSPLINKSの試験決済画面）で決済の手続きを済ませる | 購入完了画面が開き、「ご注文完了」「ご注文ありがとうございました。」8桁のご注文番号、「注文完了メールをお送りしました。届かない場合はお手数ですが当店のヘルプページを御覧ください。」が出る。ご注文番号を控える。コンビニでの入金はまだ無い（入金から先はUTS-17） |
| 11 | お客様：メールの受信箱（`upm-02@example.test`）を開く | 注文完了メールが1通届いている。内容は次の「注文確認メールで確かめること」で確かめる |
| 12 | お客様：マイページの注文購入履歴を開く | 手順10のご注文番号の注文が出て、店舗が「オンラインショップ」、支払方法が「コンビニ決済」、注文金額合計が34,000円 |

## 注文確認メールで確かめること（手順11）

設計書に件名・本文の定めが無いので、設計書の期待値は「注文と一致する」ことと、設計書に書かれた点だけ。参考欄は新実装のテンプレートの項目で、合否は付けず「記録」とする。

| 確かめる項目 | 期待値（設計書・注文との一致） | 参考（新実装のテンプレート。記録） |
|---|---|---|
| 届く通数 | 注文完了メールが1通 | — |
| ご注文番号 | 手順10の購入完了画面の8桁のご注文番号と同じ | 【ご注文番号】 |
| 商品・数量・金額 | 「シナリオ試験カードB」・数量2・単価17,000円（セール価格。基準価格20,000円ではない）・合計34,000円。手順8・9の値と一致する | 【ご注文明細】に「価格：17,000円 x 数量：2 = 合計：34,000円」の形 |
| お買上金額 | 商品金額合計34,000円・送料0円・手数料0円・ポイント使用0・注文金額合計（税込）34,000円。手順9の値と一致する | 【お買上金額】 |
| お支払方法 | 「コンビニ決済」（手順9の選択）。テンプレートは支払方法ごとに違う（設計書：支払方法ごとに定めたテンプレート） | 【お支払方法】。ヘッダーに、コンビニでの支払い方法を確かめるリンクと支払期日（注文日を含めて7日目の15時）の案内 |
| 配送方法・希望日時 | 「ゆうパック」・配送希望日時は指定なし | 【配送方法】【配送希望日】「希望無し」 |
| 注文時備考 | 手順9で書いた備考の文 | 【注文時備考】 |
| お届け先・お客様情報 | 登録済みの住所・氏名・電話番号が一致する | 【ご注文明細】のお届け先、【お客様情報】 |
| 宛先・件名・言語 | 宛先は会員のメールアドレス。件名は設計書に定めが無い（記録）。日本語のサイトで買い、国内のお届け先なので日本語 | 「[店名] 晴れる屋をご利用いただきありがとうございます。」 |

## L3で変わるところ（価格の変え方ごとに終点が違う）

| 価格の変え方 | 終点（お客様の画面・注文確認メール） |
|---|---|
| セール用価格変更CSV登録でセール開始（このシナリオ） | 商品一覧に「Sale」ラベルとセール価格が出て、注文・メールの金額がセール価格 |
| 基準価格変更CSV登録で通常商品の価格を変える（UPC-05） | 新しい販売価格（基準価格と同じ）が出る。「Sale」ラベルは出ない（セール商品ではない）。注文・メールの金額が新しい販売価格 |
| セール中の商品に基準価格変更CSV登録 | 基準価格だけ更新し、販売価格は変わらない（エラーにしない）。「Sale」ラベルと販売価格はそのまま。注文・メールの金額も販売価格のまま |
| セールの取り下げ | UPM-06 |

- 購入の条件：UPM-01のマトリクスの行を使う。セール中の行は、`matrix_UPM-01/matrix.md` の販売価格が「セール中」の行
- 高額商品の価格変更CSV：UPC-05のL3
- スマレジ連携：セール用価格変更CSVの自動判定に使う価格は設計書で決まらない（`価格管理/scenario_list.md` の判断待ち）。このシナリオの終点には影響しない
