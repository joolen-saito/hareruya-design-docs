# UPM-04 購入上限数のある商品を上限の数だけ買い、注文確認メールの数量が注文と一致する

| 項目 | 内容 |
|---|---|
| 利用者 | トレードチームの担当者（商品と在庫を登録する）→ 在庫の承認者 → 会員のお客様（国内） |
| 目的 | 購入上限数のあるカードを登録し、在庫の承認前は買えず、承認後は上限を超える数量を買い物かごで入れられないことを確かめ、上限の数だけ全額ポイントで買い、注文確認メールの数量・金額が注文と一致する |
| 種類 | 正常（上限・在庫の境目）。買えない場合の例外はL3で通す |
| マトリクスの行 | `matrix_UPM-01/matrix.md` のT30（シングルカード・在庫編集画面・登録のときから公開・通常価格・購入上限数と同じ数・詳細検索・商品詳細から・ゆうパック・全額ポイント支払い・ポイントを全額使う・送料無料金額以上・配送希望なし・備考なし・日本語） |
| もとのシナリオ | SCN-PRODUCT-004、SCN-TSUHAN-お客様EC購入フロー-001の在庫の異常系 |

## 前提

- システムの外で済んでいること：カードの商品画像をS3へ保存済み。カードが入荷している
- 用意するデータ（試験用の値。設計書の値ではない）
  - トレードチームの登録担当、在庫の承認者（別の担当者）
  - 会員：試験 花子（メールアドレス `upm-04@example.test`、国内（東京都）の住所を登録済み、保有ポイント40,000）
  - 商品：シングルカード「シナリオ試験カードD」（言語＝日本語、状態＝NM、基準価格・販売価格16,000円、購入グループ「通常商品」、販売制限数＝2、商品カテゴリを1件）。商品公開ステータス＝公開、支店の商品公開ステータス＝非公開で登録する
  - 入庫：在庫編集画面で3点（在庫＞購入上限数）。送料無料金額は30,000円（開発環境の値）

## 操作の流れと期待値

| # | 操作する人と操作 | 期待値（画面で見えること） |
|---|---|---|
| 1 | 登録担当：管理画面の商品管理で「カード商品CSV登録」を開き、商品ID空・商品公開ステータス＝公開・販売制限数＝2のCSV（「シナリオ試験カードD」1行）をアップロードする | 「CSVファイルをアップロードしました」が出て、CSVの取込履歴が1件増える。商品編集画面で商品公開ステータスが「公開」。規格設定で在庫が0、販売制限数が2 |
| 2 | 登録担当：在庫編集画面で入庫（在庫変動区分「入庫」）・在庫増減数3を入れ、承認通知先に承認者を選んで登録する | 在庫編集承認一覧に「未承認」で登録され、承認者に通知メールが届く。在庫は0のまま |
| 3 | お客様：本店のサイトにログインし、ヘッダーの詳細検索で商品名「シナリオ試験カードD」を探す | 商品一覧に商品が出るが、在庫は0で、商品数の欄と「カートに追加」ボタンが出ない（承認前は買えない） |
| 4 | 承認者：在庫編集承認一覧で、登録担当が登録した行を承認する（確認の「本当に承認してもよろしいですか」でOK） | 「承認済」になり、登録担当に承認ステータス変更のメールが届く。商品の在庫が3になる |
| 5 | お客様：詳細検索で「シナリオ試験カードD」を探し直し、商品名を押して商品詳細を開く | 商品一覧・商品詳細にカード言語「日本語」・状態「NM」・在庫3・価格16,000円が出て、商品数とカートに追加ボタンが出る。Saleラベルは出ない |
| 6 | お客様：商品詳細で商品数を2にして「カートに追加」を押し、買い物かごを開く | 「カートに追加しました：」が出る。買い物かごに数量2・小計32,000円・「現在送料無料です。」が出る |
| 7 | お客様：買い物かごで数量を3にしようとする | 購入上限数（2）を超える数量は入れられない（在庫は3あるが、購入上限数のほうで止まる）。数量は2のまま。小計は32,000円のまま |
| 8 | お客様：「購入手続きへ」を押し、ご注文方法指定画面を開く | お届け先に登録済みの住所、ご注文の商品に「シナリオ試験カードD」数量2が出る |
| 9 | お客様：配送方法に「ゆうパック」を選ぶ。配送希望日時は指定なし。備考は書かない。「ポイントを使う」にして、使用ポイントに注文金額合計（32,000）と同じ数を入れて更新する | ご注文内容の確認に、商品金額合計32,000円・送料0円（送料無料金額以上）・手数料0円・ポイント使用（値引き）・注文金額合計（税込）が出る。使用ポイントが支払うべき金額以上になったので、支払方法の選択肢が「全額ポイント支払い」だけになる |
| 10 | お客様：注文金額合計（税込）とご注文内容を控える。確定のチェックボックスにチェックを入れ、注文のボタンを押す | 購入完了画面が開き、「ご注文完了」「ご注文ありがとうございました。」8桁のご注文番号、「注文完了メールをお送りしました。届かない場合はお手数ですが当店のヘルプページを御覧ください。」が出る。ご注文番号を控える |
| 11 | お客様：メールの受信箱（`upm-04@example.test`）を開く | 注文完了メールが1通届いている。内容は次の「注文確認メールで確かめること」で確かめる |
| 12 | お客様：マイページの注文購入履歴を開く | 手順10のご注文番号の注文が出て、店舗が「オンラインショップ」、注文金額合計が手順10で控えた金額と同じ。マイページのポイント残高が、使った分だけ減っている |

## 注文確認メールで確かめること（手順11）

設計書に件名・本文の定めが無いので、設計書の期待値は「注文と一致する」ことと、設計書に書かれた点だけ。参考欄は新実装のテンプレートの項目で、合否は付けず「記録」とする。

| 確かめる項目 | 期待値（設計書・注文との一致） | 参考（新実装のテンプレート。記録） |
|---|---|---|
| 届く通数 | 注文完了メールが1通 | — |
| ご注文番号 | 手順10の購入完了画面の8桁のご注文番号と同じ | 【ご注文番号】 |
| 商品・数量・金額 | 「シナリオ試験カードD」・数量2（購入上限数と同じ。3ではない）・単価16,000円・合計32,000円。手順6〜9の値と一致する | 【ご注文明細】に「価格：16,000円 x 数量：2 = 合計：32,000円」の形 |
| お買上金額 | 商品金額合計32,000円・送料0円・手数料0円・ポイント使用32,000・注文金額合計（税込）が、手順9の値と一致する。全額ポイントなので支払う金額は0 | 【お買上金額】のポイント使用(値引き)に使ったポイント |
| お支払方法 | 「全額ポイント支払い」（手順9で選択肢が1つになった支払方法）。テンプレートは支払方法ごとに違う（支払金額なしのテンプレート）。メールの【お支払方法】の表示は設計書に定めが無い（記録） | ヘッダーに「ご入金は必要ございません。」と出荷のご案内 |
| 配送方法・希望日時 | 「ゆうパック」・配送希望日時は指定なし | 【配送方法】【配送希望日】「希望無し」【配送希望時間帯】「希望無し」 |
| 注文時備考 | 書いていないので空 | 【注文時備考】 |
| 宛先・件名・言語 | 宛先は会員のメールアドレス。件名は設計書に定めが無い（記録）。日本語 | 「[店名] 晴れる屋をご利用いただきありがとうございます。」 |

## L3で変わるところ

- 数量：購入上限数と同じ数／在庫と同じ数（在庫＜上限のとき、在庫より多くは入れられない）／在庫が0になった商品は商品数の欄・カートに追加が出ない
- 例外（`matrix_UPM-01/matrix.md` の差し込み）
  - X07：別のお客様が先に買って在庫が注文数より少なくなると、「（商品名）」の在庫が足りません。が出て購入完了画面が出ない。買い物かごに商品が残り、注文確認メールは届かない
  - X08：ご注文方法指定を開いたあとに、管理画面でその商品が非公開になると、購入は完了せずシステムエラーの画面へ移り、カート内の商品はそのまま。注文確認メールは届かない
  - X09：買い物かごで購入上限数より多くできない（手順7）
  - X10：30分を過ぎてから注文を確定すると買い物かご画面へ戻る
  - X15：購入グループが違う商品が同じカートにあると購入手続きへ進めない
  - X17：買い物かごの最後の商品を削除すると「現在カート内に商品はございません。」が出る
- 入庫を却下したとき（X04）：在庫は増えず、登録担当に却下理由つきのメールが届く。お客様の画面は在庫0のまま
