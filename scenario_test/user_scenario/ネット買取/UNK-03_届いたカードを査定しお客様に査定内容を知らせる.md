# UNK-03 届いたカードを査定し、お客様に査定内容を知らせる

| 項目 | 内容 |
|---|---|
| 利用者 | 店舗チーム（管理画面で商品到着にする）→ MTGバイヤーの買取担当者（査定端末。外部の Windows アプリ。試験端末を人が操作する）→ 店舗チーム（査定内容メールを手動で送り、査定内容連絡済みにする）→ メール（お客様） |
| 目的 | 郵送されたカードが届き、店舗チームが商品到着にし、MTGバイヤーで査定して査定金額が買取に入り（MTGBuyer査定完了）、お客様に査定内容メールが届いて買取の状況が査定内容連絡済みになる。マイページの買取履歴に「査定が完了しました。50%」が出る。明細・金額が、MTGバイヤー・管理画面・マイページで一致する |
| 種類 | 正常（組み合わせ表の6行）＋例外1件 |
| マトリクスの行 | `matrix_UNK-03/matrix.md` のT01（査定する品＝カード（仕分けで「価格が付く」カード）・査定の途中経過＝中断せずに査定を終える・まとめて買取＝含む・個別入力商品＝なし）。T02〜T06 と例外は「L3で変わるところ」 |
| もとのシナリオ | SCN-ONLINE-KAITORI-003・004・007・008（査定の部分）。業務フロー14の2-1〜2-7。査定の細部は MTGバイヤー/UMG-04（`matrix_UMG-04/`）が担い、このシナリオはその前後（商品到着にする・査定内容メール）を通す |

## 前提

- 共通の決まり：`../L4を流すときの共通の決まり.md` を先に読む（試験データの名前にシナリオIDを付ける・共有の設定は元に戻す・バッチの起動・店舗の読み替えなど）
- 起点の買取（状況「注文」。システムの外でカードが届いた状態）
  - T01・T04：UNK-01 のT04の終点（えらんで買取のカードA×2＋まとめて買取。会員E4「ネット買取試験 四郎」）。申込時買取価格はカードAが4,000円
  - T02・T03・T06：UNK-01 のT01の終点（えらんで買取のカードA×2だけ。会員E3「ネット買取試験 三郎」）
  - T05：UNK-01 のT04の終点（T01と同じ形。T05 は管理画面でサプライ品を足す）
  - どの行も、この試験専用に1件ずつ作る。カードAは UNK-01 の前提の「ネット買取試験カードA」
- 用意するデータ（試験用の値。設計書の値ではない）
  - 試験カード（MTGバイヤーで査定できるように、カード登録CSV・カード商品CSVで登録済み。手順は 店頭買取/UKA-04 の手順2〜3と同じ）：「ネット買取試験まとめカードM」（買取価格300円。T01・T04・T05 の「まとめて買取」に読み取って足す。3枚）、「ネット買取試験カードF」（T03・T04 の「価格が付くかもしれない」試験カード1枚。他のカードと商品名・状態・言語・フォイルが違うものにする。英語・SP・フォイル。買取価格1,200円）
  - サプライ品（T05・T06）：「ネット買取試験サプライS」（グッズ商品として登録済み。手順は 商品登録・編集/UPR-04 の手順3〜4と同じ）。管理画面で選んで買取に追加し、査定価格2,000円・数量1を入れる
  - 個別入力商品（T02・T03・T05）：MTGバイヤーの「個別入力する」で、商品名「ネット買取試験個別カードZ」・価格700円・枚数1を入れる（MTGバイヤーで査定できないものは個別入力商品になる）
  - 店舗チームの担当者：管理画面のネット買取管理を使え、手動メール通知を使える。MTGバイヤーの買取担当者：所属店舗が「トーナメントセンター 東京」（ネット買取は所属店舗がこの店舗の担当者だけが選べる）
  - 手順の前に控える値：買取番号（管理画面は7桁）、買取状況「注文」、買取詳細のステータス変更履歴の行数、商品の在庫（カードA・M・F・Z）
- システムの外：カードの郵送、仕分け（「価格が付く」「価格が付くかもしれない」「価格が絶対につかない」を表計算で分ける。業務フロー14 2-3。T03・T04 は「価格が付くかもしれない」とした試験カード1枚を査定に通す）
- 画面の名前・文言は新実装の表示で書く
