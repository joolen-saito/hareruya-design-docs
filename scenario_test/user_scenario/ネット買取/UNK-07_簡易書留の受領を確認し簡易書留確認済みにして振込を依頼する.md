# UNK-07 簡易書留の受領を確認し、簡易書留確認済みにして振込を依頼する

| 項目 | 内容 |
|---|---|
| 利用者 | 店舗チーム（追跡番号の確認）→ 店舗チーム（会員管理で本人確認ステータスを変更）→ 店舗チーム（買取情報編集で振込依頼済み・入金CSV）→ 経理（入金CSVを受け取る。システムの外） |
| 目的 | 簡易書留送付済みの買取について、追跡番号でお客様が簡易書留を受け取ったことを確かめ、会員の本人確認ステータスを「簡易書留確認済み」にして、買取の状況を「振込依頼済み」にし、入金CSVを経理に渡す |
| 種類 | 正常（組み合わせ表の1行）＋例外1件 |
| マトリクスの行 | `matrix_UNK-07/matrix.md` のT01（簡易書留の受領＝追跡番号でお客様が簡易書留を受け取ったことを確認できた・買取依頼者の身分証明書の種類＝登録済み・会員の本人確認ステータスの更新＝会員管理で簡易書留確認済みにする） |
| もとのシナリオ | SCN-ONLINE-KAITORI-005。業務フロー14の3-6〜3-8 |

## 前提

- 共通の決まり：`../L4を流すときの共通の決まり.md` を先に読む（試験データの名前にシナリオIDを付ける・共有の設定は元に戻す・バッチの起動・店舗の読み替えなど）
- 起点の買取：UNK-06 のT01の終点（本店のネット買取・状況「簡易書留送付済み」。えらんで買取のカードA×2＋カードD×2・査定金額合計10,000円・査定承諾金額合計10,000円。会員「ネット買取試験 六郎」は本人確認ステータス「未確認」。買取依頼者の身分証明書の種類は「自動車運転免許証」を登録済み）。この試験専用に1件作る（例外E1も別に1件作る）
- システムの外で済んでいること：簡易書留の発送。お客様の受け取り（追跡番号の照会は、日本郵便の追跡の画面で人が見る。外部サービスの画面の見え方は記録だけにし、合否は EC 側の値で付ける）
- 店舗チームの担当者：ネット買取管理と会員管理（会員の編集）を使える
- 手順の前に控える値：買取番号、買取詳細のステータス変更履歴の行数、会員の本人確認ステータス（未確認）
- 画面の名前・文言は新実装の表示で書く

## 操作の流れと期待値

| # | 操作する人と操作 | 期待値（画面で見えること） |
|---|---|---|
| 1 | （システムの外）店舗チーム：追跡番号で、お客様が簡易書留を受け取ったことを確かめる（業務フロー14 3-6・3-7） | システムの外。買取の状況は「簡易書留送付済み」のまま |
| 2 | 店舗チーム：管理画面の会員管理＞会員一覧で会員を検索し、会員編集を開いて、本人確認ステータスを「簡易書留確認済み」にして「登録」を押す（業務フロー14 3-7「会員情報の本人確認ステータスを「簡易書留確認済み」に変更」） | 「保存しました」が出る。会員編集の本人確認ステータスが「簡易書留確認済み」になる。氏名・住所などの本人確認用情報は変えていないので、確認のダイアログ（「本人確認用情報に変更があるため本人確認ステータスを未確認に変更します。よろしいですか？」）は出ない。買取一覧の本人確認の列は、新実装は「書留確認済み」と出る（記録） |
| 3 | 店舗チーム：ネット買取管理＞買取一覧で買取番号を検索し、買取詳細を開いて、買取依頼者情報の身分証明書が「自動車運転免許証」で登録済みであることを確かめる | 身分証明書は「自動車運転免許証」（未登録だと金額によらず振込依頼済みにできない。UNK-04 の例外E4） |
| 4 | 店舗チーム：「買取状況」を「振込依頼済み」にして「保存」を押す（業務フロー14 3-8「振込依頼作業へ」） | 「登録が完了しました。」が出る。買取状況が「振込依頼済み」になり、ステータス変更履歴に「振込依頼済み」が1行増える（査定金額合計10,000円・1万円以上でも、会員が簡易書留確認済みで、身分証明書が登録済みなので検査を通る）。マイページの処理状態は設計書では「買取査定を承諾しました。80%」のまま（新実装は「振込待ち」） |
| 5 | 店舗チーム：買取一覧でこの買取にチェックを入れ、ダウンロードの「入金CSV」を出して、経理に渡す（業務フロー14 3-8。経理の振込はシステムの外） | 見出し「受注番号」「送料」「査定額」「銀行名」「支店名」「口座種別」「口座番号」「受取人口座名義」「振込金額」「オンライン本人確認区分」。買取番号（前ゼロなし）、査定額10,000円、振込金額＝送料＋10,000円、申込時の口座、オンライン本人確認区分「簡易書留確認済み」が出る |
