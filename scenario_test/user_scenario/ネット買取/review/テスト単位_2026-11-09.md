## 判断に迷ったもの

- **UNK-02 の B2-1／B2-2**：問題ありの2種類は流れが同じ（README の「まとめた水準」）。問題ありの2行に1つずつ割り当てた。
- **UNK-01 の A3-1／V1-1 など**：例外が同じ条件の別の値を持つもの（A3-2＝500円未満、V1-2＝ログインしていない）は、行の水準にせず「このテストだけ」で割り当てた。
- **UNK-04 の帳票（D13）**：入金CSVと買取商品（キャンセル）CSVは1本に1つなので、一部売却しない行はキャンセルCSV、全部売却する行は入金CSVにした。UTH-02 も同様（返送で終わる行・売却しない明細のある行はキャンセルCSV、全部売却して手動入庫の行は入金CSV、全部売却して15時バッチの行は買取商品一覧CSV）。
- **UTH-02 の P（業務フローパターン）**：通しの1本は4パターンを通るが、1本に1つしか付けられない。決め手の分岐で1つに割り当てた（簡易書留＝P-03、返送で終わる＝P-02、本人確認の申請あり＝P-01、それ以外＝P-04）。
- **UTH-02 の本人確認ステータス（D1）**：問題ありで再申請する行（C3）は、確認中のまま（D1-2）にした。確認済みになる側は問題なしの行で通る。
- **UNK-09 の P-02／P-04**：バッチの行を P-04（買取商品一覧CSVを仕入れ業務へ渡す側）、手動の行を P-02（14-2の2-17）にした。
- **単一水準の因子**：`build_matrix.py` は因子が2つ以下だと止まるので、UNK-05〜UNK-13 に、本文の起点の文をそのまま使った水準が1つだけの因子を足した。

## 担当外で直す必要があるもの（直していない）

1. **UNK-04 の C1-6**：C1-2（1万円以上かつ確認中）と同じ内容の重複で、同じテストに2つ付けられない。factors.tsv の C1-6 を外すか C1-2 と統合する。
2. **UTH-02 の D4-1**：査定の中断（D4-1）と再開（D4-2）が同じ行に並ぶ。中断だけの例外が無いので、D4-2 を再開の行に付け、D4-1 は付いていない（UTH-02 に例外を足すか、cond_map の整理が要る）。
3. **UCY-08 の D7-1／D7-2**：1本のテストに同じ条件の値が並ぶ（業務周期側で分ける）。
4. **業務横断／MTGバイヤー の scenario_list.md**：UNK-04 の例外E3 を指す記述があれば、E3（未確認）とE7（確認中）に分かれたことに合わせる。
