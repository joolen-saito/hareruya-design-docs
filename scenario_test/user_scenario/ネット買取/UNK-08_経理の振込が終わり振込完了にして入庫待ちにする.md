# UNK-08 経理の振込が終わり、振込完了にして入庫待ちにする

| 項目 | 内容 |
|---|---|
| 利用者 | 経理（振込作業。システムの外）→ 店舗チーム（買取情報編集で振込完了にする）→ メール（お客様） |
| 目的 | 経理チームから振込完了の連絡を受け、店舗チームが買取の状況を「振込完了」にして保存する。個別入力商品の実在庫がすべて登録済みなら「入庫待ち」、未登録が残れば「未登録在庫あり」になる。初めて振込完了にしたときだけ、お客様に振込完了メールが届く。マイページの処理状態が「振込を完了しました。100%」になる。振込完了後に差額が分かったときは、追加の払い出しをシステムの外で管理し、買取情報のメモに書く |
| 種類 | 正常（組み合わせ表の4行）＋例外0件 |
| マトリクスの行 | `matrix_UNK-08/matrix.md` のT01（振込完了の履歴＝初めて振込完了にする（振込完了メールを自動送信）・個別入力商品の実在庫登録＝全部登録済み（入庫待ちになる）・振込完了後の差額＝差額あり）。T02〜T04 は「L3で変わるところ」 |
| もとのシナリオ | SCN-ONLINE-KAITORI-004・008。業務フロー14の2-15〜2-17。振込が失敗した場合は UNK-11 |

## 前提

- 共通の決まり：`../L4を流すときの共通の決まり.md` を先に読む（試験データの名前にシナリオIDを付ける・共有の設定は元に戻す・バッチの起動・店舗の読み替えなど）
- 起点の買取（状況「振込依頼済み」。経理が振込を終えた連絡を受けた状態にする。実際の振込は行わない）
  - T01：UNK-04 のT01の終点（えらんで買取のカードA×2＋カードB×2のうちカードBを売却しない。査定金額合計11,000円・査定承諾金額合計8,000円・会員「オンライン本人確認済み」・身分証明書「自動車運転免許証」登録済み・個別入力商品なし）
  - T02：UNK-04 のT03の終点（えらんで買取のカードA×2・カードB×1と個別入力商品の個別カードZ×1（売却する・実在庫は未登録）。査定金額合計10,200円・会員「簡易書留確認済み」・身分証明書登録済み）
  - T03：T01と同じ形の買取（UNK-04 のT01の終点）に、この手順の手順3を1回行って入庫待ちにしたもの（過去に振込完了にした履歴がある）。手順の前の状況は「入庫待ち」
  - T04：T02と同じ形の買取に、この手順の手順3を1回行って未登録在庫ありにしたもの（過去に振込完了にした履歴がある）。手順の前の状況は「未登録在庫あり」
  - どれもこの試験専用に1件ずつ作る
- 店舗チームの担当者：ネット買取管理を使える。会員のメールの受け口を確かめられる
- 手順の前に控える値：買取番号、買取詳細のステータス変更履歴の行数（「振込完了」の行の有無）、メモの内容、会員のメール送信履歴の件数、商品の在庫（カードA・B・Z）
- 画面の名前・文言は新実装の表示で書く。カードA＝4,000円、カードB＝1,500円、個別カードZ＝700円（UNK-03・UNK-04 の前提）

## 操作の流れと期待値

| # | 操作する人と操作 | 期待値（画面で見えること） |
|---|---|---|
| 1 | （システムの外）経理：振込作業を行い、完了したらトレードチームに完了報告を出す（業務フロー14 2-15）。実際の振込は行わない | システムの外。買取の状況は「振込依頼済み」のまま。T03は開始の状況が「入庫待ち」、T04は「未登録在庫あり」で、どちらも手順の前の状況のまま |
| 2 | 店舗チーム：管理画面のネット買取管理＞買取一覧で買取番号を検索し、買取詳細を開く | 買取状況「振込依頼済み」。ステータス変更履歴に「振込完了」の行は無い（T01・T02。T03・T04 は、すでに「振込完了」の行がある）。買取情報の実在庫情報にカードA×2（T01）。T03・T04の開始の状況は、T03が「入庫待ち」、T04が「未登録在庫あり」（過去に振込完了にして、保存のあとに自動で変わった状況。「振込依頼済み」ではない）。ステータス変更履歴には「振込完了」の行がすでにある |
| 3 | 店舗チーム：「買取状況」を「振込完了」にして「保存」を押す（業務フロー14 2-16） | 「登録が完了しました。」が出る。個別入力商品がなく（または全部実在庫登録済みで）、買取状況は「入庫待ち」になる（「振込完了」を経て自動で入庫待ち）。ステータス変更履歴に「振込完了」「入庫待ち」の2行が増える。振込完了日が出る。実在庫が未登録の個別入力商品がある買取は「未登録在庫あり」になる（T02・T04） |
| 4 | お客様：振込完了メールを開き、マイページの買取履歴を開く | 件名「【晴れる屋 ネット買取】振込完了のご連絡とアンケートご協力のお願い」のメールが届く（買取番号・承諾日・買取承諾明細・振込金額の内訳が載る。返信先とBccの買取専用メールアドレスにも届く）。マイページの処理状態が設計書では「振込を完了しました。100%」（新実装は「買取完了」。記録）。振込完了日が出る。会員のメール送信履歴が1件増える |
| 5 | 店舗チーム：買取一覧と買取詳細で、買取状況を確かめる | 買取状況「入庫待ち」（「振込完了」のまま残らない）。商品の在庫は手順の前の値のまま（入庫は UNK-09 の15時のバッチ、または手動入庫） |
| 6 | 店舗チーム（T01・T04のみ）：振込完了のあとにカードの規格誤りが分かった想定で、買取詳細のメモに「追加払い出し対応：差額500円（カード規格誤り。EC-CUBE外で管理）」と書いて「保存」を押す（設計書の例外運用） | 「登録が完了しました。」が出る。メモに追加払い出し対応が保存される。買取状況は変わらない（T01は入庫待ち、T04は未登録在庫あり）。カードの規格の変更は在庫移動で振替える（ステータスの差し戻しは行わない）。差額の払い出しは EC-CUBE の外で管理し、システムに払い出しの記録は増えない |

## L3で変わるところ（マトリクスの他の行・例外）

手順の番号は上の「操作の流れと期待値」。1回ずつ流す。

| 行 | 条件（振込完了の履歴・個別入力商品の実在庫登録・振込完了後の差額） | 変わるところ |
|---|---|---|
| T01 | 初めて振込完了にする・全部登録済み（入庫待ちになる）・差額あり | 代表の行（手順1〜6） |
| T02 | 初めて振込完了にする・未登録が残る（未登録在庫ありになる）・差額なし | 起点はUNK-04 のT03の終点。手順3：買取状況が「未登録在庫あり」になる（個別カードZが実在庫未登録のため）。ステータス変更履歴は「振込完了」「未登録在庫あり」の2行。手順4：振込完了メールは届く（初回）。手順5：買取状況「未登録在庫あり」。買取詳細の個別入力商品情報に個別カードZの「実在庫情報登録」ボタンが残る。手順6は行わない。15時のバッチの対象にならない（実在庫の登録は UNK-12） |
| T03 | 過去に振込完了にした履歴がある（メールを再送しない）・全部登録済み・差額なし | 起点は「入庫待ち」の買取（過去に振込完了にした履歴あり）。手順2：履歴に「振込完了」の行がある。手順3：「買取状況」を「振込完了」にして保存する。期待値：「登録が完了しました。」。買取状況は再び「入庫待ち」。履歴に「振込完了」「入庫待ち」がもう1組増える。手順4：**振込完了メールは再送されない**（会員のメール受け口に新しいメールが届かず、会員のメール送信履歴も増えない。二度メールが飛ばないよう、過去に振込完了にしたステータス変更履歴がある場合は送らない）。手順6は行わない |
| T04 | 過去に振込完了にした履歴がある・未登録が残る・差額あり | 起点は「未登録在庫あり」の買取（個別カードZは未登録。過去に振込完了にした履歴あり）。手順3：保存すると、買取状況は再び「未登録在庫あり」。履歴に「振込完了」「未登録在庫あり」がもう1組増える。手順4：振込完了メールは再送されない。手順6：差額のメモを書いて保存する（買取状況は未登録在庫ありのまま） |

例外：このシナリオに例外の差し込み表は無い（`matrix_UNK-08/exceptions.tsv` は見出しだけ）。
