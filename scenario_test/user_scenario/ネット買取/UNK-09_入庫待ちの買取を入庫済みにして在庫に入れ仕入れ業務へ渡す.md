# UNK-09 入庫待ちの買取を入庫済みにして在庫に入れ、仕入れ業務へ渡す

| 項目 | 内容 |
|---|---|
| 利用者 | バッチ（毎日15時の買取自動入庫）／店舗チーム（手動で入庫済みにする）→ 店舗チーム（在庫と履歴を確かめ、買取商品一覧CSVを出す）→ 仕入れ業務へ渡す（システムの外の打ち込みファイル作成・バックログ依頼） |
| 目的 | 入庫待ちの買取が入庫済みになり、買取した商品が本店のEC-CUBEの在庫に売却した数だけ増え、在庫履歴が残る。入庫済みの買取の買取商品一覧CSVを出して、仕入れ業務に渡す（在庫は自動入庫の1回分だけ増え、統合仕入れには足さない。依頼者決定 2026-11-07） |
| 種類 | 正常（組み合わせ表の2行）＋例外2件 |
| マトリクスの行 | `matrix_UNK-09/matrix.md` のT01（入庫済みにする方法＝毎日15時のバッチで自動・入庫前の買取＝入庫待ちの買取・出力する帳票＝買取商品一覧CSV）。T02（手動）は「L3で変わるところ」 |
| もとのシナリオ | SCN-ONLINE-KAITORI-006。業務フロー14の2-17・4-1〜4-4（4-2〜4-4 はシステムの外） |

## 前提

- 共通の決まり：`../L4を流すときの共通の決まり.md` を先に読む（試験データの名前にシナリオIDを付ける・共有の設定は元に戻す・バッチの起動・店舗の読み替えなど）
- 起点の買取（状況「入庫待ち」。この試験専用に1件ずつ作る）
  - T01・T02：UNK-08 のT01の終点（本店のネット買取・えらんで買取のカードA×2（売却する・買取金額4,000円・小計8,000円）、カードBは売却しない。査定承諾金額合計8,000円・状況「入庫待ち」。実在庫情報にカードA×2）
  - 例外E2：UNK-08 のT02の終点（個別カードZの実在庫が未登録の「未登録在庫あり」の買取）
- バッチは毎日15時に動く設計（0406 B06-01）だが、時刻は待たず、手で起動する（2026-11-26 決定）。買取自動入庫のバッチは、店頭買取とネット買取の入庫待ちの両方を処理する1本のため、共有の開発環境にある他の入庫待ちの買取も同時に入庫される。合否は、この試験の買取番号に由来する履歴（変更前と変更後の差）で付け、在庫の総数や一覧の件数は記録にする
- 入荷通知メールを確かめるとき（共有の設定「入荷通知メールの許可」）：流す前に今の値を確かめ、「送らない」のときだけ「送る」に変える（「送る」なら変えない）。確かめ終わったら元の値に戻す（手順9）
- 店舗チームの担当者：ネット買取管理・在庫管理（在庫一覧・在庫履歴一覧）を使え、買取一覧のダウンロードを使える
- 手順の前に控える値：カードAの本店のEC在庫・総原価・原価単価、買取詳細のステータス変更履歴の行数・入庫日（空）・棚戻し済み（未）、在庫履歴一覧のカードAの行数
- 画面の名前・文言は新実装の表示で書く。ネット買取は本店（店舗ID 1。画面によって「Hareruya」「トーナメントセンター 東京」と出る）のEC在庫に入る

| 4 | 店舗チーム：在庫管理＞在庫一覧でカードAの本店のEC在庫・総原価を見る | この買取に由来する増加分は、EC在庫が2、総原価が8,000円（手順5の履歴で確かめる）。在庫の総数・総原価・原価単価は、他の試験の入庫待ちの買取に同じ商品があると増えるので記録にし、合否は手順5の履歴で付ける |
| 5 | 店舗チーム：在庫管理＞在庫履歴一覧で、カードAの商品コードを検索し、登録元IDがこの買取を指す行を探す | この買取に由来する履歴（登録元IDがこの買取を指すもの）が1行増える。検索結果の行数は合否に使わない（バッチは入庫待ちのネット買取を全部処理し、買取ごと・実在庫ごとに履歴を作るので、同じカードAを含む別の買取があると行が増える。記録にする）。その行は、入庫先が本店・在庫場所「EC-CUBE」、在庫変動数2、変更前在庫・変更後在庫の差が2、在庫変動理由「買取/ネット買取」（画面は「区分/内訳」の形。初期データは区分「買取」・内訳「ネット買取」）、在庫変動理由の文言「ネット買取による入庫 買取番号：（買取番号の数字）」、仕入単価は買取単価4,000円。登録元は「買取自動入庫バッチ」、登録元IDは買取番号（設計書 0406 B06-01 のネット買取の入庫。手動入庫の設計書 0206 は「査定ID」と書く。手順T02の記述とそろえて記録する。新実装は買取のIDの数字を残す）、操作者「システム」。変更前総原価・変更後総原価が小計8,000円の分だけ増える。カードBは売却しないのでこの買取由来の行が無い |
| 6 | 店舗チーム：買取一覧でこの買取にチェックを入れ、ダウンロードの「買取商品一覧CSV」を出す（業務フロー14 4-1「その後打ち込みファイル用のデータを出力する」） | 見出し「商品コード」「在庫増減数」「商品名」「販売価格」「買取価格」「言語ID」「略称タグ」「レアリティ」「状態」。カードAの行（在庫増減数2・買取価格4,000円・状態NM・言語ID1。販売価格は商品規格の現在の基準価格）が出る。売却しないカードBは出ない（キャンセルCSVに出る） |

## 終わったあとに確かめること

| 確かめる場所 | 期待値 |
|---|---|
| 買取詳細のステータス変更履歴・入庫日 | バッチで入庫済みにしたとき、入庫済みの履歴の行・入庫日が付くかは、設計書（0406 B06-01）に定めが無い（記録）。新実装のバッチは状態を更新するだけで、履歴を残さない見込み（読んだコードからの推定）。入庫日が出なければ記録し、先へ進む。T02（手動）は履歴に「入庫済み」が増え、入庫日が出る |
| 棚戻し済み | 「未」のまま（入庫では変わらない。戻しリストを出したときに付く。UNK-13） |
| 入庫先 | この買取に由来する履歴の入庫先が本店のEC在庫である（ネット買取は本店に入る）。同じバッチの起動で店頭買取の入庫待ちも処理され、その店舗の在庫が変わるので、本店以外の店舗の在庫の増減は合否に使わず記録にする |

## 記録（判断待ちではない）
