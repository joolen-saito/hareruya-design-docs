# ネット買取：シナリオ一覧（L2）

シナリオ1本は「起点の業務イベントから、業務として完了した状態になるまで」とする。担当者が替わっても切らない（お客様→店舗チーム→MTGバイヤー→経理→メール）。日をまたぎ、システムの状態が何かを待つもの（商品の到着待ち、お客様の承諾待ち、経理の振込待ち、簡易書留の受領待ち、入庫のバッチ待ち）は別の1本にする。ただし、日をまたぐのがシステムの外の作業だけで、システムの状態が何も待たないとき（お客様の郵送、カードの仕分け、返送作業など）は分けない。条件違いはL3のバリエーションとして、組み合わせテストマトリクス（ペアワイズ）で絞る。

| 階層 | 単位 | ネット買取での置き場所 |
|---|---|---|
| L1 業務領域 | シナリオのグループ | ネット買取（申込〜入庫） |
| L2 シナリオ | 起点イベント→業務完了 | この表の1行 |
| L3 バリエーション | 条件違い・例外 | `matrix_UNK-01/`（申込）・`matrix_UNK-02/`（オンライン本人確認）・`matrix_UNK-04/`（承諾から振込依頼）と、各行の「L3」欄 |
| L4 ステップ | 画面操作と確認 | 各シナリオの「操作の流れと期待値」（まだ書かない） |

### 判断待ち（見たが決まらなかったこと。依頼者または設計の確認が要る）

- 買取依頼者の身分証明書の種類を登録しただけで、本人確認の証明（提出された身分証）があると言えるか。0206 の買取情報編集の欄(1-19)は「未登録・自動車運転免許証・パスポート…」から選ぶ身分証の種類で、新実装・現行とも買取依頼者情報の編集ボタンで選んで保存できる（管理画面の編集の処理）。振込依頼済みの検査は、この欄が空でないかだけを見て、証明の画像が提出されているかは見ない。申込・本人確認の処理から、この欄へ自動で書く箇所は見つからない。開発環境のDBダンプ（2026-09-07）では買取1,002件のうち981件に値がある。見たもの：0206 買取情報編集(1-19)、新実装の買取情報編集のフォームと画面のスクリプト、買取受注を作る処理、DBダンプの買取の件数
- 1万円未満で会員が未確認のとき、身分証の提出を何で確かめるか。業務フロー3-2の注「DBに登録されていないため利用ごとに身分証の提出が必要」は、提出の方法（画像／郵送の写し）を書かない。システムが検査するのは買取情報の身分証明書の種類が選ばれているかだけ。見たもの：業務フロー14 R199〜202、0206、0305、新実装の検査
- 業務フロー14 2-4の注「カードをスタンダード範囲か範囲外か仕分けをおこなっている」（スタンダード範囲／範囲外）の期待値。仕分けの基準・結果の置き場・システムでの扱いが、設計書（0206・0507・0601）にも、新実装にも見つからない。見たもの：業務フロー14 2-4の行、0206・0507・0601の本文（該当語なし）、新実装のソース（買取の処理に該当なし）。シナリオを作らず抜けのまま残す（網羅マトリクスの値 B9-1・B9-2）
- 査定（MTGバイヤー）で価格が付かなかったカード（「価格が付くかもしれない」として査定に通したが付かない場合）を、買取情報の明細にどう残すか。設計書・業務フローに定めが見つからない（網羅マトリクスの値 B8-2 は通す手順までを UNK-03 に足し、結果の期待値は判断待ち）

### 設計書との食い違い（設計書の不足。起票はしない）

- 業務フロー2-7の「査定が未完了の場合、査定内容連絡済みにステータス変更できない」が、0206 にも実装にも無い（上の対象外）
- 自動承諾の動きが、0206 の状態図の矢印（MTGBuyer査定完了→自動承諾→査定内容連絡済み・査定内容承諾）だけで、文章の定義が無い。0305 の申込は「選択した内容を自動承諾の設定に反映する」までしか書かない。実装は印だけで、状態は人が変える
- 査定承諾メール（業務フロー2-9）は現行・新実装とも送るが、0305 買取履歴詳細・0206 買取情報編集に送信の記載が無い。自動承諾にこのメールが出るかも書かれていない（新実装は出ない）
- 全部の明細を売却しないときの買取の状態・終点が、設計書に無い（キャンセル済みになるのか、査定内容承諾のままかが決まっていない）
- キャンセル済みにする業務（起点・手順）が設計書・業務フローに無い
- 0601 MTGバイヤーの設計書（Excel）はネット買取の査定画面を含まない（「店頭買取査定」だけ）。ただし、ネット買取の査定画面（O01-02）は現行ソースから起こした機能設計書があり（Excel の設計書は無く、この機能設計書が正本）、画面の動き（中断・再開の画面操作、まとめて買取の取り込み）はそれと 0507 の API の記述で決まる。UMG-04・UMG-07・UMG-10（MTGバイヤー/scenario_list.md）が通す。「設計書が無い」という食い違いは、Excel の設計書が無いことだけが残り、画面の動きを決める設計書が無いという意味では解消
- 業務フロー3-2の注「DBに登録されていないため利用ごとに身分証の提出が必要」と、0206 の「振込依頼済みにできない」条件（身分証明書の未登録、1万円以上は未確認・確認中）が合わない。簡易書留確認済みの会員が次の買取でも簡易書留を要るのか読み取れない（新実装は要らない動き）
- 振込依頼済みの検査は、状況を振込依頼済みに変えるときだけ働く。振込依頼済みを経ずに振込完了などへ直接変えると、身分証明書・本人確認の検査を通らない（新実装・現行の入力検査。0206 は「振込依頼済みステータスに変更時」としか書かない）。依頼者の指示「本人確認証明は必須」と合わせるなら、検査を振込依頼済みより後の状況にも掛ける決めが要る
- 身分証有効期限の消え方：会員がマイページで会員情報を変えて本人確認が未確認に戻っても、身分証有効期限は消えない（会員管理 UMB-11）。管理画面の会員登録/編集（UMB-16）で未確認に変わるとき（確認ダイアログのあと、または選び直し）は、身分証有効期限が空欄になる（新実装 CustomerEditController.php:185〜192）。UNK-14 は期限が残った未確認の会員も対象に拾うので、この違い（マイページ変更では期限が残り、管理画面では消える）が通知の対象に残る会員の差になる
- 身分証有効期限切れ通知バッチは、0408 の更新仕様がオンライン本人確認済みの会員の状態を「0(未設定)」にするとし、同じシートの通知メールの文は「ステータスは「未確認」に切り替わっています」と書く（設計書の中で食い違う）。新実装は「未確認」に戻す。「未設定」は本人確認ステータスの選択肢に無い
- 通知メールの文面は、状態や期限によらず全会員同じ（0408「本文に会員ごとの差し込みは無く、すべての会員に同じ文面を送る」）で、「ステータスは「未確認」に切り替わっています」と書く。簡易書留確認済みや、もともと未確認の会員にも同じ文が届くので、実際の状態と合わない
- 同じ通知メールは「現在進行中のお取引がある場合は身分証を更新いただくまで取引を進めることはできません」と全取引の停止を告げるが、新実装の振込依頼済みの検査は、金額が1万円未満なら会員の状態を見ない。つまり期限切れで未確認に戻った会員でも、買取情報に身分証明書の種類が入っていれば、1万円未満の買取は振込依頼済みにできる
- 確認済みにするときの身分証有効期限が過去の日付でも通るか、設計書に決まりが無い（0207 M08-10 は日付として読めないときだけエラー）
- 身分証有効期限切れ通知バッチは、有効期限があることだけで対象を選ぶ（新実装 `DtbPlayerRepository` の抽出は「身分証有効期限日が対象日以前」だけ）。オンライン本人確認の再申請は状態を確認中にするが有効期限は消さないので、期限が残る確認中の会員も未確認になる。0408 はオンライン本人確認の会員の更新としか書かず、確認中の扱いが設計書に無い（設計書の不足）
- 本人確認が済んだあとに会員が氏名・住所・生年月日を変えると未確認に戻る（0306・0207）が、すでに申込済みの買取は申込時の氏名・住所の写しのまま振込依頼まで進める（新実装は検査しない）

- UNK-14 の期限切れ後の変更先：0408 身分証有効期限切れ通知の Excel 由来の記述どうしが食い違う。更新仕様はオンライン本人確認の場合に本人確認ステータスを「0(未設定)」へ更新する（0408:1678。Excel 参照 C41）が、同じシートの通知メール文は「ステータスは「未確認」に切り替わっています」と書く（0408:1686。Excel 参照 D49）。どちらも Excel 由来で優先順位（Excel 由来＞表示メッセージ節＞現行仕様節）では決まらない。更新仕様どおりなら期待値は「未設定（0）」だが、本人確認ステータスの選択肢に「未設定」は無く、新実装は「未確認」に戻す。UNK-14 の期待値は新実装（未確認）にし、更新仕様（未設定）との食い違いは食い違いの項に記録済み。どちらを正とするかは判断待ち
- 統合仕入れとの二重入庫：ネット買取は入庫済みになった時点で自動で在庫に入る（UNK-09）ので、統合仕入れの在庫変更CSVに同じカードを入れると二重になる。仕入れ業務（USH）の判断待ちと同じ論点（0202 在庫移動・振替登録 編集(振替) が「店頭買取と同じ動作」か「現行踏襲の統合仕入れ」かを未決）。UNK-09 の「仕入れ業務へ渡す」はこの判断待ちが決まるまで確定しない
