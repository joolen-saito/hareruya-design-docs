# ネット買取のお客様の申込（UNK-01）

IPA「高信頼化ソフトウェアのための開発手法ガイドブック」(2010) の表6-9〜6-11と同じ手順で作る。

1. 因子・水準表（FL表）: `fl_table.tsv`。お客様が申込の画面で選ぶもの・変わるものを因子にし、設計書の文を根拠に持つ
2. 禁則表: `prohibitions.tsv`
3. 組み合わせテストマトリクス: `matrix.md` / `matrix.tsv`。`build_matrix.py` が作る。1行が1本のシナリオになる
4. 例外の差し込み表: `exceptions.tsv`。エラーや中断は、マトリクスの行に1つずつ差し込んで別のシナリオにする

エラーになる値は、正常な値と混ぜて組み合わせない。混ぜると、先にエラーになった値に隠れてほかの値が確かめられないため。

## 範囲

- 本店のネット買取で、会員がカートに商品を入れ、買取依頼内容を記入して申し込み、買取依頼完了画面と買取受付メールが出るところまで。非会員は申し込めない（0305「買取カートに商品があり、会員としてログイン済みであることを…前提とする」）
- 郵送（システムの外）以降は UNK-03 以降で扱う。本人確認は UNK-02、簡易書留は UNK-06・UNK-07
- 買取価格が500円未満の商品はカートに入れられない（0305）ので、用意する商品は500円以上にする。まとめて買取の商品は専用の1商品で、価格表示は「システム都合」（実際の査定金額とは関係ない）

- 申込は、会員の本人確認の状態に関わらず通る（因子K）。確定の判定は買取カート・ログイン・入力の妥当性だけで、本人確認の状態を見ない（0305「確定時の判定順序」）。本人確認の証明が要るのは、あとで振込依頼済みにするとき（UNK-04）。完了画面に「オンライン本人確認について」の案内がある（0305「買取依頼完了」(3)）

## 実装で確かめたこと（2026-11-03）

- 箱数：新実装の設定は最小1・最大20・警告基準3。警告は申込みを妨げない（H2）
- 職業・生年月日の入力欄：新実装は、会員情報の職業が空のときは職業欄、生年月日が空のときは生年月日欄をそれぞれ出し、どちらも入力必須。両方が空なら両方出る。水準E2は両方が未登録、E3は職業だけ、E4は生年月日だけが未登録のとき（0305(11)(12)は各欄を未登録のときに別々に出し、出た欄は入力必須）
- 承諾方法：選んだ内容は買取受注の自動承諾の印として保存されるだけで、申込の時点で状態は変わらない（新実装・現行 pf-eccube3 とも）。承諾方法に応じた後の動きは UNK-04 で扱う
- 申込の確定で、買取受注は状態「注文」で登録される（0305 業務ロジック「買取受注は状態「注文」で登録し」）

## 外した因子・水準（2026-11-09 依頼者決定：画面の操作の違い）

業務の流れが分かれない画面操作の違いは、シナリオテストの組み合わせ表に入れず結合テストに任せる（依頼者決定）。この表から外した：

- 外した因子：B 商品の探し方／C カートに入れる画面／G 口座種別／H 箱数
- 理由：B・C・Gは入口・入力方法の違いで後の流れも結果も同じ（決定2）。H箱数の3箱以上の警告は表示だけで申込みを妨げない（READMEの警告基準の記述）。
- 外したあとの前提（代表）：探し方はトップページのコーナーから（先頭の水準）。カートに入れる画面は商品詳細（まとめて買取は専用の1商品を詳細画面から入れるため）。口座種別は普通。箱数は警告が出ない1〜2箱。
- 外した例外：なし（禁則X1「商品一覧×まとめて買取だけ」は、商品一覧の水準を外したので消えた）
- 行数：21行 → 20行（`matrix.tsv`）。2因子間の網羅は100%
- 上の本文に、外した因子を使った説明（因子の一覧・期待結果の表・まとめた水準の表）が残る場合は、経緯の記録として残してある。いまの表は `fl_table.tsv` が正

## 外した因子・水準（2026-11-10 依頼者決定：お客様の入力が保存されるだけの違い）

お客様が入力した内容が受注や会員情報に保存されるだけの違いは、備考欄・任意項目・お届け先の登録のしかたと同じく、業務の流れが分かれないので組み合わせ表に入れず結合テストに任せる（依頼者決定）。期待値は消しただけで、新しく作っていない。

- 外した因子：F 振込口座（登録済みの口座が初期値／新しい口座を入力）／G 口座種別（普通・当座・貯蓄）／H 箱数（1〜2箱／3箱以上）／J 適格請求書発行事業者（いいえ／はい（登録番号を入れる））
- 理由：どれもお客様が入れた内容が買取受注に保存されるだけで、そのあとの作業・担当・結果（振込・入庫・メール・本人確認）が変わらない。口座種別と箱数は 2026-11-09 の codex レビューで一度戻したが、外し直した。適格請求書は店頭買取と違い、ネット買取では確認済みにする作業が無い
- 外した例外：E6（適格請求書で「はい」を選び、登録番号を入力しない）／E7（登録番号に全角の文字を入れる）。どちらも入力画面の確かめだけ
- 残した例外：E5（銀行名を入力せずに申込む。振込口座の入力そのものは申込に必須で、選び方の違いではないため）
- 付け替えた例外：なし
- 代表として残した手順：振込口座を入力する（会員に登録済みの口座があれば初期値のまま。口座種別は普通）。箱数は1〜2箱、適格請求書発行事業者は「いいえ」
- 行数：21行 → 20行（`matrix.tsv`）。2因子間の網羅は100%
- 作り直し：`build_matrix.py` で作り直した。旧T##と新T##の対応は `review/画面操作の除外_2026-11-09.md` の 2026-11-10 追記
