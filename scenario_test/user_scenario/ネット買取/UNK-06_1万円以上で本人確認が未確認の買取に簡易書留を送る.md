# UNK-06 1万円以上で本人確認が未確認の買取に簡易書留を送る

| 項目 | 内容 |
|---|---|
| 利用者 | お客様（承諾）→ 店舗チーム（買取情報編集・手動メール通知）→ メール → 簡易書留の発送（システムの外） |
| 目的 | 本人確認が未確認の会員が、査定金額合計が1万円以上の査定を承諾したあと、店舗チームが買取状況を簡易書留送付済みにして、お客様に簡易書留を送る旨のメールを送り、簡易書留を発送する。ちょうど10,000円は「1万円以上」の側（簡易書留を送る）、1万円未満（9,999円以下）の買取は簡易書留が要らず、未確認のままでも振込依頼済みに進める |
| 種類 | 正常（組み合わせ表の2行）＋例外0件 |
| マトリクスの行 | `matrix_UNK-06/matrix.md` のT01（査定合計＝ちょうど10,000円・会員の本人確認ステータス＝未確認・買取依頼者の身分証明書の種類＝登録済み）。T02（9,999円）は、この行の条件は作れないので実施不可（流せない）（新実装は査定の合計を10円単位に切り上げる）。表外の参考の確かめ（9,990円）を「L3で変わるところ」に分けて書く |
| もとのシナリオ | SCN-ONLINE-KAITORI-005。業務フロー14の3-1〜3-5 |

## 前提

- 共通の決まり：`../L4を流すときの共通の決まり.md` を先に読む（試験データの名前にシナリオIDを付ける・共有の設定は元に戻す・バッチの起動・店舗の読み替えなど）
- 起点の買取（状況「査定内容連絡済み」。この試験専用に1件ずつ作る）：UNK-03 の手順で作る。申込はUNK-01、査定は UNK-03 のとおり
  - T01：えらんで買取のカードA（4,000円）×2＋「ネット買取試験カードD」（買取価格1,000円）×2。査定金額合計はちょうど10,000円（8,000＋2,000）
  - 表外の参考の確かめ（T02の代わり。行の条件9,999円は作れない）：えらんで買取のカードA（4,000円）×2＋「ネット買取試験カードE」（買取価格1,990円）×1。査定金額合計9,990円（8,000＋1,990）。査定金額合計は査定完了で10円単位に切り上げられる（新実装。MTGバイヤーのAPIと管理画面の再計算のどちらも）ので、9,999円という値は作れない。1万円未満で最も近い作れる値9,990円で、「1万円未満の側」を確かめる
  - カードD・Eは、カードA・Bと同じ手順（カード登録CSV→カード商品CSV。店頭買取/UKA-04 の手順2〜3）で登録する。会員E3相当の本会員「ネット買取試験 六郎」（`unk06-t01@example.test`。T02は `unk06-t02@example.test`）、本人確認ステータスは未確認
- 用意するデータ：店舗チームの担当者（ネット買取管理・手動メール通知を使える）
- 手順の前に控える値：買取番号、買取詳細の査定金額合計・ステータス変更履歴の行数、会員の本人確認ステータス（未確認）
- 画面の名前・文言は新実装の表示で書く

## 操作の流れと期待値

| # | 操作する人と操作 | 期待値（画面で見えること） |
|---|---|---|
| 1 | お客様：マイページの買取履歴で、この買取の詳細を開き、全部の明細を「売却する」のまま「承諾する」を押す（業務フロー14 3-1「2-1から2-10までは同じ業務」。承諾の手順は UNK-04 の手順1〜3と同じ） | 「査定内容を承諾しました。」が出る。買取状況が「査定内容承諾」になる。査定承諾金額合計10,000円。お客様に「【晴れる屋 ネット買取】査定承諾メール」が届く。本人確認が未確認でも承諾できる（承諾は本人確認の状態を見ない） |
| 2 | 店舗チーム：管理画面のネット買取管理＞買取一覧で買取番号を検索し、買取詳細を開いて、査定金額合計と会員の本人確認の状態を確かめる（業務フロー14 3-2 簡易書留対応判定「買取価格が１万以上でかつ本人確認未確認か判定する」） | 買取一覧の本人確認の列は「未確認」。買取詳細の査定金額合計はちょうど10,000円（「1万円以上」に含まれる側）。会員は未確認なので、簡易書留による本人確認が要る |
| 3 | 店舗チーム：買取依頼者情報の「編集」を押し、身分証明書で「自動車運転免許証」を選んで「保存」を押す（身分証明書の種類は登録済みにしておく。業務フロー14 3-2の注「利用ごとに身分証の提出が必要」） | 「登録が完了しました。」が出る。身分証明書が「自動車運転免許証」になる |
| 4 | 店舗チーム：確かめとして、「買取状況」を「振込依頼済み」にして「保存」を押す | 更新されず、買取状況は「査定内容承諾」のまま。管理画面の上部に「会員の本人確認ステータスが未確認です。」が出る（査定金額合計10,000円は「1万円以上」。ちょうどの値も含む）。ステータス変更履歴は増えない |
| 5 | 店舗チーム：「買取状況」を「簡易書留送付済み」にして「保存」を押す（業務フロー14 3-3） | 「登録が完了しました。」が出る。買取状況が「簡易書留送付済み」になり、ステータス変更履歴に「簡易書留送付済み」が1行増える。メールは自動では出ない（新実装の買取情報編集の保存で自動送信するのは振込完了メールだけ） |
| 6 | 店舗チーム：買取詳細の「手動メール通知」を押し、手動メール通知の入力画面でテンプレ選択に「【買取/日】到着後、未確認者への書留送付」を選び、件名・本文を確かめて「確認」→「送信」を押す（業務フロー14 3-3「お客様に本人確認のため簡易書留を送付する旨のメールを出す」） | 確認画面を経て「メールを送信しました。」が出る。件名「【晴れる屋 ネット買取】書留送付のご連絡」のメールが届く（本文に「書留を送付させていただきます」と簡易書留を送る旨がある） |
| 7 | お客様：メールを受け取り、マイページの買取履歴を開く（業務フロー14 3-4） | メールが届いている。処理状態は設計書では「買取査定を承諾しました。80%」（新実装の表示は「振込待ち」。記録） |
| 8 | （システムの外）店舗チーム：簡易書留を作成してお客様へ発送する（業務フロー14 3-5） | システムの外。買取の状況は「簡易書留送付済み」のまま（受領の確認は UNK-07） |
