# ネット買取の承諾から振込依頼まで（UNK-04）

IPA「高信頼化ソフトウェアのための開発手法ガイドブック」(2010) の表6-9〜6-11と同じ手順で作る。手順と表の役割は `../matrix_UNK-01/README.md` と同じ。

## 範囲

- 査定内容連絡済みの買取について、承諾（お客様がマイページで承諾、または自動承諾の買取を店舗チームが管理画面で査定内容承諾にする）→ 買取の内容を確認 → 一部の明細を売却しない場合は返送対象を確認 → 振込依頼済みにして入金CSVを経理に渡すところまで
- 振込依頼済みにできる買取だけを組み合わせる。1万円以上で本人確認が未確認のときは簡易書留（UNK-06・UNK-07）、全部の明細を売却しないときは返送（UNK-05）、確認中で1万円以上は振込依頼済みにできない（例外E3）
- 全行で、買取依頼者の身分証明書（買取情報の身分証明書欄）が登録済みであることを前提にする。登録が無いと、金額によらず振込依頼済みにできない（例外E4）。会員の本人確認の状態（未確認・確認中・オンライン本人確認済み・簡易書留確認済み）は、1万円以上のときだけ振込依頼済みの条件になる。つまり1万円未満は、会員が未確認でも身分証明書が登録済みなら進める（2026-11-05 の見直し）
- 振込依頼済みのあとは経理の振込を待つので、ここで終わる。振込完了は UNK-08

## まとめた水準

なし。会員の本人確認の状態（D）の4水準は、振込依頼済みの検査の結果（未確認・確認中は1万円以上でエラー）では確認済み2種類が同じだが、入金CSVの「オンライン本人確認区分」には4つの状態名がそれぞれ別の値で出る（0206「入金CSV出力項目」(10)「未確認/確認中/オンライン本人確認済み/簡易書留確認済みのいずれか」。新実装の入金CSVも本人確認の状態名を出す）。終点の入金CSVの期待値が変わるので、分けたままにする（R5指摘）。

分けたままにしたもの：承諾の仕方（A）・明細の種類（B）・売却の内訳（C）・本人確認の状態（D）・買取金額（E）・価格下限未満の一括選択（F）。

## 実装で確かめたこと（2026-11-03）

- 振込依頼済みへの変更で、新実装は(1)買取依頼者の身分証明書が未登録ならエラー、(2)金額が10,000円以上で会員が未確認または確認中ならエラー、の順に確かめ、(1)でエラーになると(2)は確かめない（買取情報編集の入力検査。例外E3は身分証明書が登録済みの前提）。確認中を未確認と同じに扱うので、設計書の「未確認または確認中」と合う
- お客様の承諾（A1）：各明細の売却可否を保存し、状態を査定内容承諾にして履歴に残し、実在庫を作り直し、査定承諾メールを送る
- 自動承諾（A2）：自動承諾の印は表示にしか使われず、状態を自動で動かす処理は新実装にも現行（pf-eccube3）にも無い。店舗チームが買取情報編集で査定内容承諾に変えると、初めて査定内容承諾にするときだけ実在庫が作られる（0206「二度実在庫を作成しないように、過去に査定内容承諾済みにしたステータス変更履歴がある場合は…行わない」）。この経路では査定承諾メールは送られない（管理画面の保存の処理が送るのは振込完了メールだけ）
- 売却状態は「する」「しない」「未定」の3つで、買取商品（キャンセル）CSVは「しない」だけを出す（0206 買取一覧）
- 入金CSV（振込担当者用）は買取一覧で選んだ買取について出す（0206 買取一覧）

## 例外E3・E4の差し込み先

例外E3は、差し込み先の行の本人確認の状態と買取金額を、例外の条件（会員が未確認または確認中で、買取金額が1万円以上）に置き換えて行う。組み合わせ表では未確認・確認中と1万円以上の組が禁則（X1・X2）なので、差し込み先の行は手順の置き場所を示すだけである。
