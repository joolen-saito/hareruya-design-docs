# UAN-07 商品を非公開・廃止にすると、毎日3時のバッチで入荷通知依頼が取り消される

| 項目 | 内容 |
|---|---|
| 利用者 | 会員（入荷通知を依頼）→ 登録担当（商品を非公開・廃止にする）→ 運用の担当者（入荷通知キャンセルのバッチを手で起動）→ 顧客戦略（入荷通知依頼一覧で確認） |
| 目的 | 商品または商品規格を非公開・廃止にしたあと、毎日3時の入荷通知キャンセルのバッチが、その商品の入荷通知依頼を取り消し、入荷通知依頼一覧の「通知待ち」から外れることを確かめる。バッチが動く前は依頼はそのまま。同じ日に2回動かしても重複して取り消さない |
| 種類 | 正常（組み合わせ表の4行）＋例外1件 |
| マトリクスの行 | `matrix_UAN-07/matrix.md` の T01（依頼の単位＝商品規格への依頼・非公開にした対象＝商品・公開ステータス＝廃止）。T02〜T04 と例外 E1 は「L3で変わるところ」 |
| もとのシナリオ | なし（今のシナリオ SCN-* に分析・集計のものは無い。0404 B02-02 から起こした） |

## 前提

- 共通の決まり：`../L4を流すときの共通の決まり.md` を先に読む（試験データの名前にシナリオIDを付ける・共有の設定は元に戻す・バッチの起動・店舗の読み替えなど）
- システムの外で済んでいること：なし
- バッチは毎日3:00に動く設計（0404 B02-02）だが、時刻は待たず、手で起動する（起動のしかたは根拠の欄）。バッチは環境の中の対象を全部処理する。共有の開発環境ではほかの試験の入荷通知依頼も一緒に取り消される。合否はこの試験の商品の値（入荷通知依頼一覧の通知待ち・削除）で付け、完了の表示の件数は記録にする
- 用意するデータ（試験用の値。設計書の値ではない。名前の後ろにシナリオIDと行の番号を付けて作る）
  - 担当者：登録担当（商品の編集・非公開・廃止ができるメンバー）。顧客戦略（入荷通知依頼一覧を使えるメンバー）。運用の担当者（バッチを起動できる）
  - 商品：行ごとに別のシングルカード「分析試験カード UAN-07 T01」（行の番号を末尾に付ける）。カード登録CSV→カード商品CSVで登録する（UPM-02 の手順0・1と同じ。基準価格 500円。4規格 NM・SP・MP・HP ができ、商品コードは新実装が自動で作る）。商品公開ステータスは「公開」。在庫は 0 のまま（入荷通知のボタンが出る）
  - 会員：「試験 九郎」（メールアドレス `uan-07@example.test`、本会員）
- 公開ステータスの決まり（0404 B02-02）：商品データまたは商品規格データの商品公開ステータスが非公開・廃止のとき、入荷通知キャンセル扱いにする。商品規格への依頼は規格または商品が非公開・廃止のとき、商品まとめての依頼は商品が非公開・廃止のときだけ取り消す。取り消しは、依頼に取り消した日時を入れる（論理削除）。廃止にした商品は、そのあと編集できない（参照だけ）。在庫があると廃止できないので、在庫は 0 のままにする
- 取り消した依頼は、入荷通知依頼一覧の「通知待ち」から外れる。「削除」には数えない（Excel 0211「ユーザー自身が通知取り消しを行った件数」に従う。新実装は取り消した日時のある依頼を数えるので不合格になり得る。決着した論点 #2）

## L3で変わるところ（マトリクスの全4行と例外1件。1回ずつ流す）

行ごとに別の商品を使う。依頼の出し方（P2）・非公開にする対象・公開ステータス（手順1）が変わる。

| 行 | 条件（依頼の単位・非公開にした対象・公開ステータス） | 変わるところ |
|---|---|---|
| T01 | 商品規格への依頼・商品・廃止 | 代表の行 |
| T02 | 商品規格への依頼・商品規格だけ（商品は公開のまま）・非公開 | 手順1：商品公開ステータスは「公開」のまま、商品編集画面の規格設定で、依頼した規格（NM）の公開ステータスを「非公開」にして保存する。手順4：商品の行は 通知待ち 0・削除 0（規格が非公開なので、規格への依頼が取り消される） |
| T03 | 商品まとめてへの依頼・商品・非公開 | P2：商品詳細の商品まとめての入荷通知を押して依頼する（確認で「OK」）。手順1：商品公開ステータスを「非公開」にして保存する（廃止ではないので、そのあとも商品編集画面を開ける）。手順4：商品の行は 通知待ち 0・削除 0（商品が非公開なので、商品まとめての依頼が取り消される） |
| T04 | 商品まとめてへの依頼・商品規格だけ（商品は公開のまま）・廃止 | P2：T03 と同じ（商品まとめて）。手順1：商品公開ステータスは「公開」のまま、規格（NM）の公開ステータスを「廃止」にして保存する（規格を廃止にできるか画面で確かめ、廃止にできなければ、この行は「実施不可（流せない）」として記録する。「非公開」に替えると行の条件を満たさないので、替えて流さない）。手順4：商品まとめての依頼は商品の状態だけを見るので、取り消されず、商品の行は 通知待ち 1・削除 0 のまま（新実装の動作。設計書に書かれていない。期待値は新実装の動作を記録し、設計書の不足として残す） |
| E1 | 例外：同じ日にバッチを2回動かす | 手順3のあと、続けてバッチをもう一度手で起動する。期待値：2回目は、この試験の依頼を取り消さない（完了の表示の件数にこの試験の依頼は含まれない。取り消した日時は1回目のまま。重複して取り消さない）。手順4の値（通知待ち 0・削除 0）は変わらない（0404 現行仕様「既に論理削除済みの行が再び対象になることはなく、重複して削除することもない」） |

## 判断待ち

開いた項目は無い（`../scenario_list.md` の決着した論点 #2 で決まっている）。記録（判断待ちではない）：

1. 古い版（0404 B02-02 の現行仕様の節）は「紐づく商品規格・商品が削除済み」を対象とする。改訂後の節（公開ステータスが非公開・廃止）に従った
2. 商品まとめての依頼で、規格だけ非公開・廃止にしたときの扱い（T04）は設計書に書かれていない。新実装は商品の状態だけを見る。期待値は新実装の動作（取り消さない）にし、設計書の不足として記録する
3. バッチの取り消しを「削除」に数えるかは、Excel 0211 に従い数えない。新実装は数えるので、手順4は不合格になり得る
