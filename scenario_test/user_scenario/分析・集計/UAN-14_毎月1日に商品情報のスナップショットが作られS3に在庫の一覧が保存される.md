# UAN-14 毎月1日に商品情報のスナップショットが作られ、S3に在庫の一覧が保存される

| 項目 | 内容 |
|---|---|
| 利用者 | 運用の担当者（バッチを手で起動。バッチ用の環境で行う）→ 在庫チェックの担当（S3から一覧を取得して中身を見る。システムの外） |
| 目的 | 毎月1日1時のバッチが、DBの最新スナップショットから一時的なDBを作り、公開の商品規格・営業中の店舗の在庫（商品コード・販売価格・買取価格・店舗名・在庫区分名・在庫数）を抜き出して、S3に「stock_年月日.txt.zip」として保存し、一時的なDBを消すことを確かめる。中身が、そのスナップショットの時点の公開の商品・営業中の店舗の在庫と一致する |
| 種類 | 正常（代表の1本）。組み合わせ表は作らない（`../scenario_list.md` の L3 の欄にそう書いてある。出力の中身は店舗・在庫区分・公開の別で変わる）。L3で変わるところ3本と例外2件 |
| マトリクスの行 | 組み合わせ表の無いシナリオ。代表＝V1（公開の商品・営業中の店舗の在庫が、並び順どおりに出る）。V2〜V3 と例外 E1・E2 は「L3で変わるところ」 |
| もとのシナリオ | なし（今のシナリオ SCN-* に無い。0416 B16-06 から起こした） |

## 前提

- 共通の決まり：`../L4を流すときの共通の決まり.md` を先に読む（試験データの名前にシナリオIDを付ける・共有の設定は元に戻す・バッチの起動・店舗の読み替えなど）
- システムの外で済んでいること：S3（保存先）・DBのスナップショット・一時的なDBの作成と削除は、バッチ用の環境（AWS）の機能で、ブラウザの画面の試験では確かめられない。この L4 の手順は、バッチを起動できる環境（DB のクラスタの最新スナップショットを使える・S3に書ける権限がある・設定が済んでいる）で、運用の担当者が行う。そのような環境が無ければ、この L4 は「実施不可（流せない）」として記録する（S3・一時DBの作成削除は環境依存。`../scenario_list.md` の UAN-14 の備考）
- バッチは毎月1日1時に動く設計（0416 B16-06）だが、時刻は待たず、手で起動する（起動のしかたは根拠の欄）。一時的なDBが使えるようになるまで待つ時間があるので、完了まで長くかかる（設計書は30分のスリープを入れ、30分で終わらなければ延ばす）。時間の期待値は置かない
- バッチは「最新のスナップショット」を使うので、試験データを作ったあとに、DB のスナップショットを取り直してからバッチを起動する（スナップショットを取る権限が無ければ、試験データが載らないので、その行は確かめられず、実施不可として記録する）
- 用意するデータ（試験用の値。設計書の値ではない。名前の後ろにシナリオIDを付けて作る）
  - 担当者：登録担当と在庫の承認者。運用の担当者（バッチの起動とスナップショットの取得ができる）。在庫チェックの担当（S3から取得できる）
  - 店舗：本店（店舗ID 1）。支店は、既存の店舗から本店以外の営業中の店舗を1つ選び、店舗IDと画面に出る名前を控える（以下「支店A」）。閉店した店舗が既存にあれば控える（V3 で使う）。店舗は新しく作らない
  - 商品：グッズ「分析試験グッズ UAN-14 A」（商品コード「UAN14-G01」、販売価格 3,300円、買取価格 1,000円、公開）・「分析試験グッズ UAN-14 B」（商品コード「UAN14-G02」、販売価格 2,200円、買取価格 500円、非公開）。グッズ商品CSVで登録する（UPR-04 のグッズ商品CSVを取り込む手順と同じ。買取価格はCSVの列に書く）。在庫は在庫変更CSVで、UAN14-G01 を本店の EC-CUBE 在庫に 12点・本店のスマレジ在庫に 7点・支店Aの EC-CUBE 在庫に 4点、UAN14-G02 を本店の EC-CUBE 在庫に 9点入れる（UZK-01 の手順3〜6と同じ。仕入単価 300円）
- 出力の決まり（0416 B16-06）：公開の商品規格だけ。在庫に紐づく店舗が閉店でないもの。本店・支店とも全店舗。出力項目は 商品コード・販売価格・買取価格・店舗名・在庫区分名（ECCUBE またはスマレジ。Excel 由来の 0416 F37）・在庫数。並びは店舗IDの昇順、在庫区分名（EC-CUBE、スマレジの順）。ZIPの名前は「stock_年月日.txt.zip」（年4桁・月2桁・日2桁。実行した日）。中は同名の「stock_年月日.txt」（タブ区切り・UTF-8・先頭に見出し行）の1ファイルだけ。保存先は S3 のバケット「inventorycheck」

## 操作の流れと期待値（起点：毎月1日1時にバッチが動く。代表：V1 公開の商品・営業中の店舗の在庫が並び順どおりに出る）

| # | 操作する人と操作 | 期待値（画面で見えること） |
|---|---|---|

## L3で変わるところ（組み合わせ表は無い。確かめを3本と例外2件に分ける。1回ずつ流す）

| 行 | 条件 | 変わるところ |
|---|---|---|
| V1 | 公開の商品・営業中の店舗 | 代表の行 |
| V2 | 公開の規格だけが出る | P1 に追加：UAN14-G01 の規格を、商品編集画面の規格設定の公開ステータスで「非公開」にして保存する（UPR-08 の手順3と同じ操作。公開の判定は商品規格に共通で、店舗・在庫区分ごとには分けられない）。P2 のスナップショットを取り直し、バッチを起動する。期待値：手順4で、UAN14-G01 の行が、その規格の全店舗・全在庫区分の行（本店 EC-CUBE・本店スマレジ・支店A EC-CUBE の3行）とも出なくなる。ほかの公開の商品の行は変わらない |
| V3 | 閉店した店舗の在庫は除く | 既存の閉店した店舗に在庫のある商品があれば、その店舗の行が出ない（在庫に紐づく店舗が閉店でないものだけ）ことを手順4の代わりに確かめる。閉店した店舗に試験の在庫を入れられなければ（画面の操作で入れられない）、この行は「実施不可（流せない）」として記録する（店舗は新しく作らない） |
| E1 | 例外：設定が足りない | バッチ用の環境で、必要な設定（本番のクラスタの名前・サブネット・セキュリティ・パラメータグループ・DBの種類・インスタンスの規格・DBのユーザーとDB名・保存先）のどれか1つを外して起動する。期待値：足りない設定の名前を示すエラーを出して異常終了し、AWS にもDB にも触れない（後片付けも行わない）。設定を外せない環境では、実施不可（流せない）として記録する |
| E2 | 例外：スナップショットが無い・インスタンスが使えるようにならない | 「<本番クラスタ> のスナップショットが見つかりません」（スナップショットが無い）、「インスタンスが利用可能になりません」（待っても使えない）で異常終了する。画面の操作・環境の操作で起こせないので、実施不可（流せない）として記録する（開発者ツールで書き換えるなどはしない） |

## 判断待ち

開いた項目は無い（`../scenario_list.md` の UAN-14 の備考で、結合テストでは確かめにくい扱い）。記録（判断待ちではない）：

2. 在庫区分名は、設計書（Excel 由来の 0416 B16-06 F37）が「ECCUBEまたはスマレジ」と定める。新実装の抽出（query.sql）は「EC-CUBE」と出す。期待値は設計書の「ECCUBE」にし、「EC-CUBE」が出たら不合格として記録し、設計書との食い違いに書く
