# 分析・集計の店頭買取の買取集計（UAN-12）

IPA「高信頼化ソフトウェアのための開発手法ガイドブック」(2010) の表6-9〜6-11と同じ手順で作る。

1. 因子・水準表（FL表）: `fl_table.tsv`
2. 禁則表: `prohibitions.tsv`
3. 組み合わせテストマトリクス: `matrix.md` / `matrix.tsv`。`build_matrix.py` が作る。1行が1本のシナリオになる
4. 例外の差し込み表: `exceptions.tsv`。エラーや中断（★の手順）は正常な値と混ぜず、条件に合う行へ1つずつ差し込む

## 範囲

- 毎日3時の買取集計バッチ（0406 B06-02）が前日に買取成立した分を店舗・部門ごとに集計し、管理画面の「買取集計データ」（0205 M06-08）とそのCSV（M06-09）に出るか。買取は店頭買取のシナリオ（UKA-01・UKA-10）の手順で作る
- 日別・月別集計（`matrix_UAN-02/`）の買取件数・買取金額とは別の集計。対象が同じとは限らない（日別・月別集計は買取成立日が入っているもの、買取集計は下のステータス）

## 期待結果の決まり（行ごとに当てはめる）

- 対象：買取成立日が集計対象日の買取で、ステータスが買取成立・入庫済み・未登録在庫あり・入庫待ちのもの。査定中などの成立前、管理者取消は数えない
- 買取金額＝明細と個別入力商品のそれぞれの単価×数量の合計。販売金額＝買取当時の販売価格（登録済みの商品は基準価格、個別入力商品はMTGBuyerで入力した価格）の合計
- 金額指定の端数（買取合計金額から明細と個別入力商品の金額を引いた分）は、特定の部門の買取金額に入り、販売金額は0
- 並び：「集計」は部門コードの昇順、「日別」は日付の昇順・部門コードの昇順。部門が無い行は部門名が「未設定」
- 買取店舗の初期値はログインした管理者の既定の検索表示店舗。管理者取消にすると、買取成立日の当日分が作り直されて外れる（バッチを待たない）
- CSVは日別と同じ内容。金額は桁区切りなしの整数
- バッチは日付を指定して流せる（引数なしは前日）。指定した日の集計を消して作り直す。部門未設定商品の通知は、集計対象日に成立した買取のすべてが対象で、管理者取消でも届く

## 実装で確かめたこと（2026-11-05）

- 集計の対象のステータスは、買取成立・入庫済み・未登録在庫あり・入庫待ち（`src/Eccube/Entity/Master/MtbOtcBuyOrderStatus.php` 66〜71行目）。ステータスを変えて対象に出入りがあったときだけ、当日分を作り直す（`Service/Admin/OtcBuyOrder/RecalculateSummaryAction.php` 36〜37行目）

## まとめた水準

なし（どの水準も処理が違う）。主な根拠：集計対象のステータス（買取成立・入庫待ちなど）・管理者取消・査定中は集計に入る・入らないが違い、登録済み商品・個別入力商品・端数は販売価格の決まりが違う。買取店舗・部門の選び方は絞り込みの結果が違い、画面とCSVは出力の形が違う。
