# UAN-12 店頭買取が成立した分が、毎日3時の買取集計バッチで部門別に集計され、買取集計データの画面とCSVに出る

| 項目 | 内容 |
|---|---|
| 利用者 | 店頭買取の担当者・お客様（UKA-01・UKA-10 の操作で買取を作る）→ 運用の担当者（買取集計バッチを手で起動）→ 店舗統括・経理（管理画面の買取集計データ）→ CSV |
| 目的 | 毎日3時のバッチが前日に買取成立した分を店舗・部門ごとに集計し、管理画面の「買取集計データ」とそのCSVに、部門ごとの買取金額・販売金額（期間全体と日別）が、買取から手で計算した値どおりに出ることを確かめる。管理者取消の買取は外れ、部門が未設定の商品があれば管理者に通知が届く |
| 種類 | 正常（組み合わせ表の9行）＋例外5件 |
| マトリクスの行 | `matrix_UAN-12/matrix.md` の T01（買取の状態＝集計の対象のステータス（買取成立・入庫待ち・未登録在庫あり・入庫済み）・買取の中身＝登録済みの商品だけ・買取店舗＝別の店舗を選ぶ・部門＝全部門）。T02〜T09 と例外 E2〜E6 は「L3で変わるところ」 |
| もとのシナリオ | なし（今のシナリオ SCN-* に分析・集計のものは無い。0406 B06-02・0205 M06-08・M06-09 から起こした）。日別・月別集計（UAN-02）の買取件数・買取金額とは別の集計（対象のステータスが違う） |

## 前提

- 共通の決まり：`../L4を流すときの共通の決まり.md` を先に読む（試験データの名前にシナリオIDを付ける・共有の設定は元に戻す・バッチの起動・店舗の読み替えなど）
- システムの外で済んでいること：なし（買取は UKA-01 の操作でこの L4 の準備として作る。出金・端末取引のスマレジの画面は記録だけにし、合否は EC 側の値で付ける）
- バッチは毎日3:00に動く設計（0406 B06-02）だが、時刻は待たず、日付を指定して手で起動する（引数なしは前日。起動のしかたは根拠の欄）。バッチは環境の中のその日の店頭買取を全部集計するので、共有の開発環境ではほかの試験の買取も一緒に集計される。合否は、この試験で作った部門（名前が「分析試験部門 UAN-12 …」）の行の値で付け、集計に載った買取の総数・ほかの部門の行は記録にする
- 店頭買取の集計は、ステータスを変えて集計の対象に出入りがあったとき（買取成立・管理者取消など）、買取成立日の当日分をその場で作り直す（0205 ステータス変更の再集計）。バッチを待たずに画面に出ることがある。バッチを流したあとの値で比べる
- 用意するデータ（試験用の値。設計書の値ではない。名前の後ろにシナリオIDを付けて作る）
  - 担当者：店舗チームの担当者（店頭買取の査定）。経理・店舗統括（買取集計データを使えるメンバー。所属・既定の検索表示店舗は本店＝店舗ID 1）。運用の担当者（バッチを起動できる）。管理者（部門未設定商品の通知を受け取る）
  - 店舗：本店（店舗ID 1）。支店は、流す前に既存の店舗から本店以外の店舗を1つ選び、店舗IDと画面に出る名前を控える（以下「支店A」。支店所属の店舗チームの担当者で査定する）。店舗は新しく作らない
  - 部門：商品管理＞部門登録/編集で「分析試験部門 UAN-12 α」「分析試験部門 UAN-12 β」「分析試験部門 UAN-12 γ」を作る（部門コードを控える）。金額指定の「10円」は既存の固定価格部門に入る
  - 商品（カード登録CSV→カード商品CSV。UPM-02 の手順0・1と同じ）：「分析試験カードA UAN-12」（日本語・NM。買取価格 800円、基準価格 1,500円。部門 α）、「分析試験カードB UAN-12」（日本語・HP。買取価格 100円、基準価格 400円。部門 β）。商品に部門を付けるには、商品管理＞商品CSV管理の「部門登録CSVアップロード」（雛形ファイルダウンロードと同じ見出しのCSV）を使う。買取価格・基準価格が上の値と違うときは、試験で作った商品に限り、規格の価格を上の値に直してから流す
  - 個別入力商品（B2 の行）：「分析試験未登録カードZ UAN-12」（商品マスターに無い商品。価格 300円・枚数1・基準価格 500円・部門は選択欄から γ を選ぶ）
  - 金額指定（B3 の行）：「10円」を3枚（買取価格 10円・基準価格 100円。部門は固定価格部門）
  - 買取の内容（UKA-01 と同じ組み立て）：A×2枚・B×3枚が基本。B2 の行は個別入力商品 Z×1 を足す。B3 の行は金額指定「10円」×3 を足す
  - 経理チームのメールアドレス：追加システム設定の「査定払い出しの経理部門通知メールアドレス」が試験で読める受け口になっている（出金を経理に頼む場合のみ。UKA-01 の前提と同じ）。部門未設定商品の通知先：集計バッチの通知の宛先設定（追加システム設定）が設定済みであること（空のときは通知は送られない）。変えるときは、流す前に値を控え、終わったら元の値に戻して戻ったことを画面で確かめる（共通の決まり）
  - 試験日（S）：流す日。買取成立日は S
- 手で計算した買取金額・販売金額（買取1件。買取金額＝明細と個別入力商品の単価×数量の合計。販売金額＝買取当時の販売価格（登録済みの商品は基準価格、個別入力商品は入力した値）の合計）

| 部門 | 買取の中身（行の B） | 買取金額 | 販売金額 |
|---|---|---|---|
| 分析試験部門 UAN-12 α | カードA 2枚（B1・B2・B3 共通） | 800×2＝1,600 | 1,500×2＝3,000 |
| 分析試験部門 UAN-12 β | カードB 3枚（B1・B2・B3 共通） | 100×3＝300 | 400×3＝1,200 |
| 分析試験部門 UAN-12 γ | 個別入力商品 Z 1枚（B2 の行だけ） | 300×1＝300 | 500×1＝500 |
| 固定価格部門 | 金額指定「10円」3枚（B3 の行だけ） | 10×3＝30 | 100×3＝300 |

  - 端数調整分：買取合計金額から明細と個別入力商品の金額を引いた端数。この L4 の買取は10円単位でそろえてあるので 0（端数が 0 以下の買取は計上しない）
- 並び（0205 買取集計データ）：「集計」（期間全体）は部門コードの昇順、「日別」は日付の昇順・部門コードの昇順。部門が無い行は部門名が「未設定」

## L3で変わるところ（マトリクスの全9行と例外5件。1回ずつ流す）

## 判断待ち

開いた項目は無い（`../scenario_list.md` の決着した論点・設計書の網羅で決まっている）。記録（判断待ちではない）：

1. 日別・月別集計（UAN-02）の買取件数・買取金額は「買取成立日が入っているもの（管理者取消を除く）」、買取集計データは「買取成立・入庫済み・未登録在庫あり・入庫待ち」。同じ買取でも対象が同じとは限らない
2. 部門未設定の通知は、成立後に管理者取消になった買取でも届く（集計画面には出ない）。通知先の設定が空のときは通知を送らない
3. 金額指定の端数は特定の部門の買取金額に入る。この L4 の買取は 10円単位で端数が 0 なので、端数の部門の行は出ない。端数が出る買取（買取合計が明細と個別入力の合計と違う）を画面の操作で作れなければ、その確かめは「実施不可（流せない）」として記録する
4. 買取店舗の初期値はログインした管理者の既定の検索表示店舗
