## 前提

- 共通の決まり：`../L4を流すときの共通の決まり.md` を先に読む（試験データの名前にシナリオIDを付ける・共有の設定は元に戻す・バッチの起動・店舗の読み替えなど）
- システムの外で済んでいること：なし。サイトの言語は日本語サイトで通す（2026-11-09 依頼者決定：画面の操作の違い）。GTM・GA の設定は作っていない（結合テストの GA連携の観点でも「GTM設定待ち」）ので、確かめるのは受け渡し領域の中身まで
- 確かめ方：購入完了の画面（注文完了画面）を表示した直後に、ブラウザの開発者ツール（コンソール）で、ページ内の受け渡し領域（設計書 0310 の「連携の仕組み」にある領域）の中身を一覧表示して見る。値の名前は設計書 0310 F10-02 の「積む値」の表の項目のとおり（この L4 では「受注ID」「配送方法の名称」「商品小計」「消費税」「送料合計」「購入者のメールアドレス」「商品の並び」と書く）。開発者ツールで通信や値を書き換えることはしない（見るだけ）
- 用意するデータ（試験用の値。設計書の値ではない。名前の後ろにシナリオIDを付けて作る）
  - 担当者：顧客戦略（ブラウザで確かめる人）。登録担当と在庫の承認者
  - 会員：「試験 十郎」（メールアドレス `uan-09@example.test`、本会員、国内（東京都）の住所を登録済み）。海外の配送方法の行（EMS・Small packet）は、別の会員「試験 十一郎」（`uan-09-os@example.test`、本会員、海外の住所を登録済み。UMB-02 の手順と同じ登録）を使う。ポイント：会員編集の「ポイント履歴追加（キャンペーン、特別対応）」から 100,000ポイントを付与しておく（UMB-10 の準備1と同じ操作。全額ポイントで払う行のため）
  - 商品：グッズ「分析試験グッズ UAN-09 A」（商品コード「UAN09-G01」、販売価格 3,300円（税込）。税抜単価 3,000円）・グッズ「分析試験グッズ UAN-09 B」（商品コード「UAN09-G02」、販売価格 2,200円（税込）。税抜単価 2,000円）。シングルカード「分析試験カード UAN-09」（基準価格 5,500円。NM 5,500円・SP 4,950円。UPM-02 の手順0・1と同じカード登録CSV→カード商品CSV。同じ商品の2つの規格で「同じ商品が別の行」にするため）。在庫は在庫変更CSVで、各商品（カードは NM・SP）に 50点を入れて承認（UZK-01 の手順3〜6と同じ）。税率10%の商品。受注の明細で単価（税抜）を確かめて控える
  - 送料：国内は商品合計 30,000円以上で無料（開発環境の値）。それ未満は送料がかかるので、購入確認の画面（ご注文内容の確認）に出た送料を控える。海外の送料は、購入確認の画面に出た値を控える（国・重さで決まる）
  - 購入：本店のサイト、お支払い方法は「コンビニ決済」（全額ポイントで払う行は「全額ポイント支払い」）、ポイントは使わない（ためる）（行の条件で変わる）
- 積まれる値（0310 F10-02 の表）。1つの要素にまとめて積む

| 項目 | 値 |
|---|---|
| 受注ID | ご注文番号（8桁に満たないときは左を0で埋める。8桁を超えるときはそのまま） |
| 配送方法の名称 | 受注の1件目のお届け先に設定された配送方法の名称 |
| 商品小計 | 税込単価×数量を、受注明細の全行について合計した金額。送料・手数料・値引き・ポイント利用を反映しない |
| 消費税 | 常に 0（消費税がかかる注文でも 0） |
| 送料合計 | 受注の送料合計（0円のときは 0） |
| 購入者のメールアドレス | 注文完了画面を表示した時点でログインしている会員のメールアドレス |
| 商品の並び | 受注明細1行につき1件を、受注明細の並び順で。1件は 商品コード・商品名・カテゴリ（常に空）・税抜の単価・数量。同じ商品が別の行にあってもまとめない |

- 会員ID（0310 F10-01）：ログインしているとき、会員IDを数値のまま1項目だけ積む。氏名・メールアドレスは積まない。ログインしていないときは何も積まない
- 税抜の単価×数量の合計は、消費税がかかる注文では「商品小計」（税込）と一致しない
