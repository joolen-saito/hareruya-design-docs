# 分析・集計の入荷通知依頼のバッチによる取り消し（UAN-07）

IPA「高信頼化ソフトウェアのための開発手法ガイドブック」(2010) の表6-9〜6-11と同じ手順で作る。

1. 因子・水準表（FL表）: `fl_table.tsv`
2. 禁則表: `prohibitions.tsv`
3. 組み合わせテストマトリクス: `matrix.md` / `matrix.tsv`。`build_matrix.py` が作る。1行が1本のシナリオになる
4. 例外の差し込み表: `exceptions.tsv`。エラーや中断（★の手順）は正常な値と混ぜず、条件に合う行へ1つずつ差し込む

## 範囲

- 商品を非公開・廃止にしたあと、毎日3:00の入荷通知キャンセルのバッチ（0404 B02-02）が、その商品の入荷通知依頼を取り消すか。起点は商品の公開・非公開の切り替え（UPR-08）
- 取り消した依頼は、入荷通知依頼の画面（UAN-06）の通知待ちから外れる。「削除」に数えるかは判断待ち（`scenario_list.md`）
- 依頼の作り方は UAN-06 の `README.md` と同じ

## 期待結果の決まり（行ごとに当てはめる）

| 依頼の単位（A） | 非公開にした対象（B） | バッチのあと |
|---|---|---|
| 商品規格への依頼 | 商品 | 取り消される（非公開・廃止のどちらも） |
| 商品規格への依頼 | 商品規格だけ | 取り消される |
| 商品まとめての依頼 | 商品 | 取り消される |
| 商品まとめての依頼 | 商品規格だけ | 取り消されない（新実装の動作。設計書に書かれていない） |

- 取り消すとは、依頼に取り消した日時を入れること（画面では入荷通知の依頼が消えた扱い）
- バッチが動く前（公開ステータスを変えた当日のうち）は、依頼はそのまま

## 実装で確かめたこと（2026-11-05）

- 規格への依頼は規格または商品が非公開・廃止のとき、商品まとめての依頼は商品が非公開・廃止のときだけ取り消す（`src/Eccube/Repository/DtbProductRequestRepository.php` 561〜599行目）
- 古い現行仕様（0404 B02-02 の現行仕様の節）は「紐づく商品規格・商品が削除済み」を対象とする。改訂後の節（公開ステータスが非公開・廃止）に従った

## まとめた水準

なし（どの水準も処理が違う）。主な根拠：0204 基本設計 1561行「商品公開ステータスが廃止で更新された場合、以降の商品情報を変更できなくする。参照は可能。」で、廃止は非公開と流れが違う（廃止後は編集できない）。依頼単位（A）・対象（B）も取り消す・取り消さないが変わる。
