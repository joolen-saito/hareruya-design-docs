# 分析・集計のフォーマット売上分析（UAN-05）

IPA「高信頼化ソフトウェアのための開発手法ガイドブック」(2010) の表6-9〜6-11と同じ手順で作る。

1. 因子・水準表（FL表）: `fl_table.tsv`
2. 禁則表: `prohibitions.tsv`
3. 組み合わせテストマトリクス: `matrix.md` / `matrix.tsv`。`build_matrix.py` が作る。1行が1本のシナリオになる
4. 例外の差し込み表: `exceptions.tsv`。エラーや中断（★の手順）は正常な値と混ぜず、条件に合う行へ1つずつ差し込む

## 範囲

- 管理画面の「フォーマット売上分析」（M12-07）と「フォーマット売上分析 CSV出力」（M12-08）で、売上分析タグ別の日別売上が、取引のシナリオで作った受注と合うか。売上分析タグが付いた商品の売上は、タグごとの行に出る
- 日別・月別集計と違い、出荷完了の受注だけを数えるのではない。受注日が集計月に属し、キャンセルでない受注を数える（0211 フォーマット売上分析 集計一覧(検索項目)の現行仕様）

## 期待結果の決まり（行ごとに当てはめる）

- 行：売上分析タグを表示順の昇順で並べ、続けて「その他(カード)」「その他」。「合計」の行。売上の無い日は0
- 日ごとの売上＝その日に受注した明細の単価×数量の合計（送料・値引きは入らない）
- 平均＝月内売上合計÷当月日数（小数点以下切り捨て）。合計の平均は、各行の平均の合計
- 数えない受注：キャンセル（D2）、引き渡し済みの元の受注（D3。置き換わったスマレジ由来の受注が代わりに数えられる）
- 集計対象：通販（B1）は配送方法が店頭受取系・なし以外、店舗（B2）は店頭受取系またはなし（0211 フォーマット売上分析 集計一覧(検索項目) の★の定義）
- CSV（F2）は日別の表だけ。合計・平均の表は出ない。金額は桁区切りなしの数値

## 実装で確かめたこと（2026-11-05）

- 新実装は、キャンセル以外の受注を受注日で数える。置き換わった元の受注は除く（`src/Eccube/Repository/OrderRepository.php` 2074行目・2130行目、113行目）
- 「その他(カード)」「その他」の分け方は、商品がカードかどうか（`FormatSalesController.php` 233行目）
- 通販・店舗とも外すと「集計対象(通販)・集計対象(店舗)のいずれか1つ以上を選択してください」（`Form/Type/Admin/Analysis/FormatSalesType.php` 58〜70行目）。設計書に文言は無い
- 平均は切り捨て（`FormatSalesController.php` 288行目）

## まとめた水準

なし（どの水準も処理が違う）。主な根拠：31日・30日・2月は当月日数で割る平均の値が違い（切り捨て）、売上分析タグの有無・カード・カード以外は行の出し分けが違う。キャンセル・引き渡し済みの元の受注は集計の対象外などで処理が違う。通販・店舗・店頭PC・スマレジだけの購入も受注の作られ方が違う。
