# 価格管理：シナリオ一覧（L2）

シナリオ1本は「起点の業務イベントから、業務として完了した状態になるまで」とする。担当者が替わっても切らない（顧客戦略チーム→トレードチーム→管理画面→お客様の画面・支店・スマレジ）。日をまたぎ、システムの状態が何かを待つもの（毎週水曜のお気に入り通知、毎日0時の販売数の集計）は別の1本にする。価格管理は、分析・確認（システムを触るのは売上分析や商品CSVの出力まで）→価格変更の共有→CSVの取り込み→お客様の画面で価格が変わる、までを1本とする。セール品の取り下げと新セール登録は、システムの状態が何も待たない（セールに期間の設定が無く、CSVを取り込んだときに切り替わる）ので分けない。条件違いはL3のバリエーションとして、組み合わせテストマトリクス（ペアワイズ）で絞る。

| L4 ステップ | 画面操作と確認 | （まだ書かない） |

### 判断待ち

- セール用価格変更CSVのスマレジ連携フラグの自動判定に使う価格：自動判定があることは確定（0204 HTML 5950・7984行目）。判定を基準価格（買取・基準価格一括編集と同様）で行うのか、セールの販売価格で行うのかは、同じ別添資料の7866行目が「買取・基準価格一括編集と同様」と「セール価格は連携しないため不要」を併記し決まらない。新実装は換算後の販売価格。`matrix_UPC-01/` はD・Eの行で結果を記録する。商品管理から注文確認メールまでのUPM-02は、この判断がシナリオの終点（セール価格での購入と注文確認メールの金額）に影響しないとして、セール用価格変更CSVの期待値にスマレジ連携の有無を書かない
- セールバナー差し替え（業務フロー1-5）が、本店のトップバナー管理（0213 M16-01）で行うものか：業務フローに画面名が無く、設計書にも対応づけが無い。UPC-01 では差し替えの手順だけ置く。トップバナー管理のバナーの出方の期待値は外部連携のUEX-04にあるが、1-5との対応づけが決まるまで、UPC-01 の期待値としては採用しない（外部連携の判断待ちも同じ）

### 設計書との食い違い（設計書の不足。起票はしない）

- 業務フロー11 のパターン2は、索引表（R7）が「価格調整対応（日次・スタンダート価格調整）」、本文の見出し（R64）が「価格調整対応（日次・売り上げによる価格調整）」と書く。網羅の表は索引表の名前を写した
- 0204 基準価格変更CSVアップロード（機能仕様）はセール中の商品の買取価格を「変更できる」と書くが、0204 基準価格変更CSVフォーマットは「セール中商品の販売価格、買取価格は変更できない」と書く。アップロードの文・同じフォーマットの手順の文・新実装は更新するので、更新するとした
- 0204 セール用価格変更CSVアップロードは、通常商品×通常（CSVのセールフラグ0）を「販売価格、買取価格は変更できない」と書きつつ、手順で「買取価格を、CSVに設定されている買取価格に更新する」と書く。手順の文と新実装に従い、買取価格は更新するとした
- 0204 別添資料_スマレジ連携対象商品（7866行目）のセール用価格変更CSV登録の行は、「買取・基準価格一括編集と同様」と「セール価格は連携しないため不要」を併記し、判定に使う価格（基準価格かセールの販売価格か）が読み取れない。新実装は換算後の販売価格が300円以上のNM以外の規格で連携フラグを自動でONにする。セールを取り下げて価格が基準価格へ戻るときのスマレジ連携は、設計書に書かれていない
- 0204 基準価格変更CSVアップロードの表示メッセージの後続処理が「セール用価格変更CSVアップロード画面に遷移する」と書かれている（基準価格変更CSVの画面のはず）。また、買取価格が上回るエラーの文言は設計書が「販売価格は買取価格より…」、新実装は「基準価格は買取価格より…」
- 業務フロー11 2-4「販売価格の上昇調整のみ」の制約は、設計書にも新実装にも無い（下げる価格も取り込める）。業務の運用の決まりと読んだ
- 0404 お気に入り商品セール通知は、本文で「セール商品がある場合は毎日送信する」と書き、実行タイミングは「毎週水曜17:30」と書く。実行タイミングの表記に従った
- 業務フロー11 1-5 セールバナー差し替えを行う画面が書かれていない。0213 データ管理 バナー設定(トップバナー管理)（HTML 1027-1028行目）は「本店フロントのトップ画面に表示されるスライドを設定」、0301 フロント_トップ（1232行目）は「管理画面＞トップバナー管理で設定された画像を表示する」と書くが、セールバナーがこの画面で差し替えるものかは書かれていない
- 「通常作業用」というカスタムデータCSVの名前は設計書に無い。カスタムCSV出力設定で作る定義の名前と読んだ
- 設計書は基準価格変更CSVの取り込み成功後に支店システムへ通知するとするが、新実装の基準価格変更CSV・セール用CSVの取り込みには通知が無い（セール用は未移植のコメントのみ）
- 設計書は、高額商品コードが付いた規格だけの行を「エラーにはならず成功として数える」とするが、新実装の基準価格変更CSVは、更新対象の規格が無い行を「該当する商品規格がありません」のエラーにする
- 設計書（0204 グッズ商品CSV登録）は規格を「一律NM規格」で登録・更新すると書く。グッズにはNM以外の規格が無いので、スマレジ連携のNM以外の規格の条件はグッズに当てはまらない（`matrix_UPC-05/` の禁則）
