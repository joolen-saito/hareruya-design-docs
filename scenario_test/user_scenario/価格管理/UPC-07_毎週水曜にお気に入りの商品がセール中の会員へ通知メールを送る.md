# UPC-07 毎週水曜に、お気に入りに入れた商品がセール中の会員へ、通知メールを送る

| 項目 | 内容 |
|---|---|
| 利用者 | お気に入り通知のバッチ（システム。試験では手で起動する）→ 会員（メール）。準備でセールを開始する顧客戦略チームの担当者 |
| 目的 | 毎週水曜17:30のお気に入り商品セール通知バッチが、セール中のお気に入り商品を会員ごとに1通へまとめて通知することを確かめる。対象外の会員（仮会員・退会済み・店内アカウント）・セール中のお気に入りが無い会員・お気に入りに登録した言語とは別の言語の側だけがセール中の会員には届かない |
| 種類 | 正常（組み合わせ表の1行）＋例外3件 |
| マトリクスの行 | `matrix_UPC-07/matrix.md` のT01（セール中のお気に入りの数＝1商品）。T02〜T04と例外E1〜E3は「L3で変わるところ」 |
| もとのシナリオ | なし（今のシナリオ SCN-PRICE-* に無く、0404 B02-05 から足した。業務フローに無い。セールの更新日（水曜）に合わせた通知） |

## 前提

- 共通の決まり：`../L4を流すときの共通の決まり.md` を先に読む（試験データの名前にシナリオIDを付ける・共有の設定は元に戻す・バッチの起動・店舗の読み替えなど）
- バッチは時刻を待たず手で起動してよい（定時は毎週水曜17:30。起動のしかたは「根拠」の欄のファイル）
- バッチは環境の中の対象を全部処理する。ほかの試験の会員のお気に入りがセール中なら、その会員にもメールが出る。合否はこの試験の会員のメールと、この試験の商品の値で付け、完了の表示の件数（環境の全部の会員の分。何名に送ったか）は記録にし、合否はこの試験の会員のメールが届くか・届かないかで付ける。ほかの人の会員の受信箱は見ない
- 用意するデータ（試験用の値。設計書の値ではない）
  - 担当者：管理画面で、商品管理・商品CSV管理を使える顧客戦略チームの担当者。運用の担当者（バッチを起動できる）
  - 会員：試験 花子（メールアドレス `upc-07@example.test`、本会員、会員グループ「通常会員」、国内（東京都）の住所）。フロントの会員登録で作り、本登録メールのリンクで本会員にする（試験の会員をフロントで登録してよい）。例外のテストごとに別の会員を使う（メールアドレスは `upc-07-e1@example.test`・`upc-07-e2@example.test`・`upc-07-e3@example.test`）
  - 商品：シングルカード「シナリオ試験お気に入りカード」（英名「Scenario Test Favorite Card」、言語＝日本語、状態＝NM、基準価格・販売価格 400円、買取価格 100円、割引率「4」＝NM100%・SP90%・MP80%・HP70%、商品公開ステータス＝公開）。4規格の基準価格は NM 400・SP 360・MP 320・HP 280円。セール用価格変更CSVで、販売価格 360円・セールフラグ 1 でセールにする（NM 360・SP 324→330・MP 288→290・HP 252→260円）。お気に入りには、商品の言語「日本語」で登録する
  - お気に入りの機能が使えること（お気に入りは100件まで）
- メールの受信箱：`upc-07@example.test` のメールを読める手元の受け口（メールはECが送るもの。届くか・件名・本文で合否を付ける。受け口の画面の見え方は記録）

手順の番号は上の「操作の流れと期待値」。行ごとに別の会員・別の商品を使う（会員は `upc-07-t02@example.test` のように、商品名は「シナリオ試験お気に入りカード」に行の番号を付ける）。手順1（バッチ）は全行で同じ。ほかの行の完了の表示の件数は記録にする。

## 判断待ち

開いた項目は無い。確かめたこと（記録）：

1. 完了の表示：設計書の現行仕様は、開始と完了の2行を出すと書くが（処理件数は含まない）、新実装は完了の1行に送った会員の数を含める。期待値は新実装の文言とし、件数は記録にする
2. 設計書は本文で「セール商品がある場合は毎日送信する」と書き、実行タイミングは「毎週水曜17:30」と書く。実行タイミングの表記に従った（設計書内の食い違い）
3. 送信済みの判定は無く、起動のたびに送る（設計書の現行仕様）。この試験は、メールが何通も出るのを避けるため、バッチを1回しか起動しない
4. 会員グループの名前：設計書の現行仕様の「店内注文専用アカウント」「支店店内注文専用アカウント」に当たる開発環境の名前は「店内アカウント」「支店用店内アカウント」（初期データ）。流す前に、会員グループの一覧で確かめる
5. 退会済みの会員の作り方：画面（マイページの退会手続き）で作る。退会した会員が通知の対象外になるかは、手順1のあとの受信箱で確かめる

設計書との食い違い（起票しない）：

- 通知メールのお気に入り一覧のリンク先：新実装の初期データのメールテンプレートは本番のドメインに決め打ち。設計書（0404 B02-05）はメールの本文のリンク先を定めない（記録）
- 実行タイミングと「毎日送信する」の記述（設計書内）
- 会員グループの名前（設計書の現行仕様と開発環境の初期データ）
