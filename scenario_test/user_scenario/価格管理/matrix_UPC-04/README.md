# 価格管理のイレギュラー調整（UPC-04）

IPA「高信頼化ソフトウェアのための開発手法ガイドブック」(2010) の表6-9〜6-11と同じ手順で作る。

2026-11-09：シナリオの本文に「／」で並べていた値を、1回ずつ流すテストに分けるために作った（IPA 6.3.1・6.3.2。依頼者決定）。値と期待値は本文に書いてあったものを水準ごとに分けただけで、新しい期待値は作っていない。

## 範囲

- 急な価格調整のきっかけ（突発の事象／希少なカードを仕入れた場合）ごとに1本。価格の反映は `../matrix_UPC-05/` の行で確かめる（シナリオ一覧のL3）
- 突発の事象の「大会後・新商品発表・禁止改定・トレンドの変化のどれか」は、本文が「どれか」と1件を決めると書いているので、水準を分けない

## 期待結果の決まり

- 突発の事象：急ぎの調整が要るカードを1件決め（SNSなどの情報はシステムの外）、在庫数を見て価格を決め、価格変更CSVで反映して、お客様の画面にそのカードの新しい価格が出る
- 希少なカードを仕入れた場合：そのカードの状態や市場の状況に応じた価格を新たに設定（新設）または調整し、価格変更CSVで反映して、お客様の画面に設定した価格が出る（業務フロー4-1 R108〜R111）

※因子が1〜2つのとき、`tools/build_matrix.py` は網羅率の分母が0になって止まる（2026-11-09時点）。この表は、割り算の前に分母0を100％として扱い、因子が1つのときは水準ごとに1行にする以外は `build_matrix.py` と同じ手順の写しで作った。道具が直れば、下のコマンドで同じ表ができる。

## 作り直し
