# 価格管理のセール用価格変更CSVの取り込み（UPC-01）

IPA「高信頼化ソフトウェアのための開発手法ガイドブック」(2010) の表6-9〜6-11と同じ手順で作る。

1. 因子・水準表（FL表）: `fl_table.tsv`。セール担当者がCSVに書く値と、対象商品の今の状態を因子にした
2. 禁則表: `prohibitions.tsv`。セールにしない行（セールフラグ0）に割引の掛け方・セール後の並び順の確認を組まない、スタンダードの割引はシングルカードのセールだけ、の7件（2026-11-09 codex指摘）
3. 組み合わせテストマトリクス: `matrix.md` / `matrix.tsv`。`build_matrix.py` が作る。1行が1本のシナリオ（1つの商品のセール取り込み）になる
4. 例外の差し込み表: `exceptions.tsv`。エラーは正常な値と混ぜず、条件に合う行へ1つずつ差し込む

## 範囲

- 「商品CSV管理」の「セール用価格変更CSV」に、セール用のCSVを取り込むところから、お客様の画面・スマレジ連携・お気に入り通知（UPC-07）の手前までの確認（業務フロー11 1-4）
- 業務フロー1-4「セール品の取り下げを先に行い、作業確認後新セール品登録を行う」は、取り下げ（A2×B1）と新セール登録（A1×B2）の2回の取り込みになる。この表の行は1回の取り込みで、2つの行を続けて通す手順はシナリオ一覧のL3に書いた
- 高額商品のセール（セール用高額商品価格変更CSV）は業務フローに工程が無く、対象外

- スマレジ連携：セール用CSVでもシングルカードはスマレジ連携フラグの自動判定がある（0204 セール用価格変更CSVアップロード HTML 5950行目「条件を満たす場合スマレジ連携フラグを有効とする」、機能改修一覧 7984行目「シングルカードのみスマレジ連携フラグ自動判定追加」）。7866行目の「セール価格は連携しない」は、セール価格をスマレジへ送らないという注記と読む。判定に使う価格は、同じ行が「買取・基準価格一括編集と同様」とあるので基準価格（E）と読むが、セール用CSVは基準価格を更新しないため設計書は一貫して判定を基準価格で書き、セール価格は連携しないと明記している。【決着 2026-11-09】期待値は「判定にセール価格（換算後の販売価格＝D）は使わず、登録済みの基準価格（E）が300円以上のシングルカードのNM以外の規格だけが自動でON」。新実装は換算後の販売価格で判定するので、Dが300円以上でEが299円以下の行などで不合格になり得る（Excelを正とし、新実装の動作を結果に記録する）。取り下げ（A2×B1）で基準価格へ戻る価格の連携は、設計書に書かれていない（`../scenario_list.md` の食い違い）

- 販売価格は、CSVの値に割引率を掛けて10円単位で切り上げた額（HTML 6036行目）。連携判定の境界は換算後の価格で見る（Dの水準）
- お客様の画面：商品一覧に「Sale」の表示が出る（セール中のとき）。取り下げて通常商品に戻ると、販売価格は基準価格になる（セール用価格変更CSVアップロード「販売価格を、現在登録済の基準価格からコピーする」）
- 価格履歴に、変わった側の新旧が残る（0204 買取・販売価格履歴検索）

## 実装で確かめたこと（2026-11-03）

- 切り替えの4通りは、新実装のセール用価格変更CSVの取り込みの分岐と同じ（取り下げは基準価格をコピーし、CSVの販売価格があれば「反映されていません」を出す。通常→通常は販売価格を変えず「買取価格のみ更新しています」を出す）
- 通常→通常（A1×B1）で買取価格を更新するか：0204 セール用価格変更CSVアップロードは「通常商品の販売価格、買取価格は変更できない」と書くが、同じ節の手順は「買取価格を、CSVに設定されている買取価格に更新する」。新実装は更新する。手順の文と新実装に従い、更新するとした
- スマレジ連携の食い違い：新実装のセール用CSVの取り込みは、換算後の販売価格が300円以上でNM以外の規格のとき連携フラグを自動でONにする（`ProductPriceImportHandler.php` 382-385行目・469-471行目）。Excel（0204 別添資料 D12・G29・Q29・S29）は基準価格で判定するとし、セール価格は連携しないと書く。【決着 2026-11-09】Excelを正とし、新実装は不合格になり得る（確認 組2 #24）

## まとめた水準

なし（どの水準も処理が違う）。主な根拠：セールフラグの有無で販売価格を変えられるかが違い、シングルカードとそれ以外はスマレジ連携フラグの自動ONが違う。換算後の価格が299円以下か300円以上かで連携の判定が違い、タグ・帯URLの空にする・書くは更新結果が違う。

## 外した因子・水準（2026-11-10 依頼者決定：出し分けだけで業務フローは分かれない）

業務が回るかを確かめるシナリオテストでは、業務フローは分かれず、画面の表示・並びの出し分けだけが変わる条件は組み合わせ表から外し、結合テストに任せる。お客様や担当者が「買えない・進めない」になるものは残す。

- 因子 I「トップバナー管理のセールバナー」（表示／非表示／画像URLが空）を外した。理由：バナーがスライドに出る・出ないの表示の出し分けだけで、セールの取り込みも購入も同じに進む（買えなくなるわけではない）。セールバナーを差し替える作業そのもの（業務フロー11 1-5）は L3 に残す
- 因子 J「セール後のユニサーチの価格（検索の並び）の確認時点」（次のフィードまで／あと）を外した。理由：検索結果の並び順が次のフィードで変わるだけの表示の出し分けで、一覧の価格と「Sale」の表示は現在の値で出て購入も進む。禁則 X5〜X7（J と B の組）も外した（禁則は7件から4件）
- 作り直し後：9行（2026-11-09 の16行から）。rows=9 pair=100.00% (137/137) triple=69.84% (403/577)。例外 E1〜E3 は差し込み元の行が T01・T03・T02 になった
- この節より上の文章（見直しの節など）に I・J の名前が残る場合は、上の決定が優先する
