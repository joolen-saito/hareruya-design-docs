## 前提

- 共通の決まり：`../L4を流すときの共通の決まり.md` を先に読む（試験データの名前にシナリオIDを付ける・共有の設定は元に戻す・バッチの起動・店舗の読み替えなど）
- システムの外で済んでいること：他サイトの取引価格や自店の受注などの情報収集（買取価格は参照しない）。売上過多かどうかの判断（判断の基準は業務フローにも設計書にも無く、システムの外の人の作業）。支店システムは存在しないので、取り込み後の支店システムへの通知は手順にも期待値にも置かない
- 販売価格の上げ下げ：業務フロー11 ＃2-4は「販売価格の上昇調整のみ」と書くが、この制約は設計書にも新実装にも無い（下げる値も取り込める）。業務の運用の決まりと読み、このシナリオは上げる値で流す
- 用意するデータ（試験用の値。設計書の値ではない）
  - 担当者：管理画面で、分析・集計（受注売上分析）と商品管理・商品CSV管理を使える顧客戦略チームの担当者。在庫の承認者（別の担当者）
  - カテゴリ：商品管理＞カテゴリ登録/編集で新規に登録する「シナリオ試験売上カテゴリ」（日・英の名称）。カテゴリの集計の確かめ（T02）で、ほかの商品が混ざらないようにするための専用カテゴリ
  - 商品：シングルカード「シナリオ試験売上過多カード」（英名「Scenario Test Heavy Seller Card」、言語＝日本語、状態＝NM、基準価格・販売価格 500円、買取価格 100円、割引率「4」＝NM100%・SP90%・MP80%・HP70%、商品カテゴリは「シナリオ試験売上カテゴリ」、商品公開ステータス＝公開、支店の商品公開ステータス＝非公開）。基準価格 500円なので、4規格の基準価格・販売価格は NM 500・SP 450・MP 400・HP 350円（どれも300円以上なので、SP・MP・HPのスマレジ連携フラグは登録のときにONになる）。在庫はNMの規格に5点
  - 会員：試験 太郎（メールアドレス `upc-02@example.test`、国内（東京都）の住所を登録済み）
  - 前日の売上：試験 太郎が、このカードのNMの規格を2点（500円×2＝1,000円）買った注文を1件。注文日を前日にそろえる（下の準備のP5）
  - 価格変更用CSV：「基準価格変更CSVアップロード」の雛形ファイルダウンロードと同じ見出し（商品ID・言語ID・基準価格・買取価格）
- 商品を新しく登録するので、同じカードの商品が既にあると行は飛ばされる。やり直すときはカード名と商品名を変える（名前の後ろの番号）

4. 業務フロー11 ＃2-4「販売価格の上昇調整のみ」：システムに制約は無い
