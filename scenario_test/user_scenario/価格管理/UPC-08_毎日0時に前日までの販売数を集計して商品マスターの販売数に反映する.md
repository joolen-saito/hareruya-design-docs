## 前提

- 共通の決まり：`../L4を流すときの共通の決まり.md` を先に読む（試験データの名前にシナリオIDを付ける・共有の設定は元に戻す・バッチの起動・店舗の読み替えなど）
- バッチは時刻を待たず手で起動してよい（定時は毎日0:00。起動のしかたは「根拠」の欄のファイル）。販売数は、この試験で起動する直前の時刻を実行日として集計する
- バッチは環境の中の対象を全部処理する。ほかの試験の受注も一緒に集計される。合否はこの試験の商品の値で付け、完了の表示は記録（件数は出ない）
- 試験で作った注文の注文日時は、開発環境で書き換えて、決めた日（実行日の何日前）の12時にそろえる（日付の部分だけで期間を判定するので、時刻は見ない。試験で作った注文だけを書き換える）
- 用意するデータ（試験用の値。設計書の値ではない）
  - 担当者：管理画面で、商品管理・設定（カスタムCSV出力設定）を使える顧客戦略チームの担当者。在庫の承認者（別の担当者）。運用の担当者（バッチを起動できる）
  - 商品：シングルカード「シナリオ試験販売数カード」（英名「Scenario Test Sales Count Card」、言語＝日本語、状態＝NM、基準価格・販売価格 300円、買取価格 100円、割引率「4」、商品公開ステータス＝公開、支店の商品公開ステータス＝非公開）。NMの規格を確かめる。在庫はNMの規格に10点
  - 会員：試験 三郎（メールアドレス `upc-08@example.test`、国内（東京都）の住所を登録済み）
  - 注文：次の3件（いずれもNMの規格。購入は本店のサイトで、商品IDで開く商品詳細から。UPM-02 の手順7〜10と同じ手順：ゆうパック・コンビニ決済・ポイントをためる）。注文A：実行日に買う 1点（注文日はそのまま）。注文B：2点（注文日を実行日の前日にそろえる）。注文C：4点（注文日を実行日の2日前にそろえる）
  - 作業用のカスタムデータCSV：設定＞基本情報設定＞カスタムCSV出力設定で作る出力名「販売数確認」（CSV種別＝商品。出力する項目＝商品ID・商品コード・状態コード・在庫数・前日販売数・3日間販売数・1週間販売数・1ヵ月間販売数・90日間販売数・180日間販売数・365日間販売数）
- 期間の数え方（設計書の現行仕様）：前日は実行日の前日1日分だけ。それ以外の期間は、実行日から所定の日数を遡った日以降の受注（実行日当日も含む）。遡る日数は、3日間が3日、1週間が7日、1ヶ月が28日、90日間・180日間・365日間がその日数。期間の判定は受注日時の日付部分だけで行い、時刻は見ない。キャンセルと決済処理中の受注は除く。閉店した店舗は除く

## 判断待ち

開いた項目は無い。確かめたこと（記録）：

1. 当日の列：設計書の現行仕様は「当日分の販売数の列は毎回0で初期化する」と書くが、新実装は、当日の販売数を受注のたびに加算し、日次のバッチは当日の列を更新しない。この試験は当日の列を合否に使わず、画面の値を記録する
2. 対象の明細が無い集計単位：設計書は前回値が残ると書き、新実装は集計の前に既存の行を消す（上の「表外の確かめ」。食い違いとして記録）
3. 集計の対象の本店・支店・スマレジの振り分け（元のEC受注を外し、スマレジ由来の受注を計上する・計上日の決め方）は、スマレジ連携のシナリオ（USM）の範囲で、この試験では確かめない
4. 設計書の期間の名前は「昨日・3日間・1週間・1か月・90日間・180日間・365日間」、新実装の画面は「前日・3日間・1週間・1ヶ月・90日間・180日間・365日間」（表記の違いだけ）

設計書との食い違い（起票しない）：

- 当日の列の初期化（設計書は毎回0、新実装は更新しない）
- 対象の明細が無い集計単位の前回値（設計書は残る、新実装は消える見込み）
- 完了の表示（設計書の現行仕様は開始と完了の2行・実行時刻つき、新実装は完了の1行）
