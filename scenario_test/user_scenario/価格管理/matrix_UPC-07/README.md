# 価格管理のお気に入りのセール通知（UPC-07）

IPA「高信頼化ソフトウェアのための開発手法ガイドブック」(2010) の表6-9〜6-11と同じ手順で作る。

2026-11-09：シナリオの本文に「／」で並べていた値を、1回ずつ流すテストに分けるために作った（IPA 6.3.1・6.3.2。依頼者決定）。値と期待値は本文に書いてあったものを水準ごとに分けただけで、新しい期待値は作っていない。

## 範囲

- 毎週水曜17:30のバッチが、セール中のお気に入り商品を会員ごとに1通へまとめて通知するところ（0404 B02-05）
- 因子：セール中のお気に入りの数（会員の住所は2026-11-09に外した）（1商品／複数商品）。会員は別々に用意する
- 通知しないもの：会員の状態が仮会員・退会済み・店内注文専用アカウントは例外（★）として1つずつ別のテストにした。別の言語の側だけがセール中、セール中の商品が無い会員は、通知の対象になる商品の数に関わる（例外の差し込み先の行の「1商品／複数商品」と矛盾する）ので、「セール中のお気に入りの数」の水準（B3・B4）にした

## 期待結果の決まり

- 1商品：その商品を載せた1通。複数商品：会員ごとに1通へまとめる
- 例外の期待値は `exceptions.tsv` のとおり

※因子が1〜2つのとき、`tools/build_matrix.py` は網羅率の分母が0になって止まる（2026-11-09時点）。この表は、割り算の前に分母0を100％として扱い、因子が1つのときは水準ごとに1行にする以外は `build_matrix.py` と同じ手順の写しで作った。道具が直れば、下のコマンドで同じ表ができる。

## 外した因子・水準（2026-11-09 依頼者決定：画面の操作の違い）

業務の流れも結果も分かれない画面操作の違いは、組み合わせ表から外し、結合テストに任せる（依頼者決定）。値と期待値は消しただけで、新しく作っていない。

- 因子A「会員の住所（日本／国外）」を因子ごと外した。通知メールの言語（日本語／英語）が違うだけで、通知の有無・宛先・まとめ方は同じ。
- 行は8から4になった。例外E1〜E3の差し込み元（B1）は残る。
