# UPC-01 セール品を選び、取り下げと新セール登録をして、お客様の画面にセール価格を出す

| 項目 | 内容 |
|---|---|
| 利用者 | 顧客戦略チームの担当者（セール担当・ジャンル担当）→ 管理画面 → 店舗・支店（リスト共有はシステムの外）→ お客様 |
| 目的 | セール前の土日に、セール品の候補を商品マスターのCSVで見て、取り下げるセール品と新しいセール品を決め、セール用価格変更CSVで取り下げを先に取り込み、確認してから新セールを取り込み、お客様の画面（本店）で、取り下げた商品は通常商品に戻って販売価格が基準価格になり、新セール品は「Sale」付きでセール価格で出ることを確かめる。セールバナーをトップバナー管理で差し替えて本店トップのスライドに出す |
| 種類 | 正常（組み合わせ表の2行を続けて流す）＋例外3件 |
| マトリクスの行 | `matrix_UPC-01/matrix.md` のT04（取り下げ：今のセール状態＝セール中・CSVのセールフラグ＝0・シングルカード・換算後の販売価格＝299円以下・登録済みの基準価格＝300円以上・タグ列＝空・帯URL列＝空・割引の掛け方＝該当なし）を先に流し、確認してから、T02（新セール登録：通常商品・CSVのセールフラグ＝1・シングルカード・CSVの値は299円以下だが換算後は300円以上・登録済みの基準価格＝300円以上・タグ列＝空・帯URL列＝書く・スタンダードの1〜2％程度の割引）を流す。ほかの7行（T01・T03・T05〜T09）と例外E1〜E3は「L3で変わるところ」 |
| もとのシナリオ | SCN-PRICE-001 |

購入と注文確認メールの金額は、このシナリオの商品ではなく別の試験データで確かめる。同じ種類の価格の区間を確かめる参照先は、取り下げのあとが UPM-06（基準価格で買う）、セール開始のあとが UPM-02（セール価格で買う）。新セールの登録はこのシナリオが持つ（UPM-06 には入れない）。

## 前提

- 共通の決まり：`../L4を流すときの共通の決まり.md` を先に読む（試験データの名前にシナリオIDを付ける・共有の設定は元に戻す・バッチの起動・店舗の読み替えなど）
- システムの外で済んでいること：セール品選定依頼のメールを送る・受け取る作業（業務フロー11 ＃1-1）。セールに使うバナー画像のファイル。支店システムは存在しないので、取り込み後の支店システムへの通知は手順にも期待値にも置かない
- 取り下げを先に行い、作業確認後に新セールを登録する（業務フロー11 ＃1-4。試験的に取り下げは火曜日・更新は水曜日に行っている）。セールに期間（開始日・終了日）は無く、CSVを取り込んだときに切り替わるので、日をまたぐ待ちはシステムに無い
- 用意するデータ（試験用の値。設計書の値ではない）
  - 担当者：管理画面で、商品管理・商品CSV管理・データ管理（トップバナー管理）・設定（カスタムCSV出力設定）を使える顧客戦略チームの担当者。在庫の承認者（別の担当者）
  - タグ：商品管理＞タグ登録/編集で作る「シナリオ試験セールタグA」「シナリオ試験セールタグB」（名称（日）・（英）を入れる）。登録後の一覧でタグの番号（ID）を控える
  - 取り下げる商品X：シングルカード「シナリオ試験セール終了カード」（英名「Scenario Test Sale End Card」、言語＝日本語、状態＝NM、基準価格 500円、買取価格 100円、割引率「4」＝NM100%・SP90%・MP80%・HP70%、商品公開ステータス＝公開、支店の商品公開ステータス＝非公開）。基準価格 500円なので、4規格の基準価格はNM 500・SP 450・MP 400・HP 350円（どれも300円以上なので、SP・MP・HPのスマレジ連携フラグは登録のときにONになる）。セール中にする：販売価格 NM 400円（SP 360・MP 320・HP 280円）、セールフラグ有効、帯URL、タグA
  - 新セールにする商品Y：シングルカード「シナリオ試験新セールカード」（英名「Scenario Test New Sale Card」、同じ条件、基準価格 300円、買取価格 100円）。4規格の基準価格・販売価格は NM 300・SP 270・MP 240・HP 210円（スマレジ連携フラグは全部OFF）。通常商品で、タグAが付いている
  - 在庫：2商品とも、NMの規格に2点（お客様の画面に出すため。在庫変更CSV登録で取り込み、承認する）
  - 作業用のカスタムデータCSV：設定＞基本情報設定＞カスタムCSV出力設定で作る出力名「候補選定用」（CSV種別＝商品。出力する項目＝商品ID・商品コード・商品名(日)・状態コード・在庫数・1週間販売数）
  - セールバナー：画像ファイル（GIF・JPG・PNG、520000バイト以下）、リンク先URL（セールの特集ページ。試験用の値）
- 商品を新しく登録するので、同じカードの商品が既にあると行は飛ばされる。やり直すときはカード名と商品名を変える（名前の後ろの番号）

## L3で変わるところ（マトリクスの他の行・例外）

手順の番号は上の「操作の流れと期待値」。行ごとに、流し始めの状態（準備のP2〜P4で用意する値）・取り込むCSVの1行・手順5・8（取り込み）と手順6・9（管理画面）の期待値が変わる。確かめ方は、行ごとに別の商品を使い、手順5〜9（取り下げか新セール登録のどちらか1回）を流す。商品名・商品コードは行ごとに別にする（「シナリオ試験セール終了カード」に行の番号を付ける。例：T01は「…カード T01」）。お客様の画面（手順7・10・11）は、取り込みの後にフィードを作り直して確かめる。価格は、すべて商品の割引率「4」で計算した値（SP＝90%・MP＝80%・HP＝70%、10円単位で切り上げ）。

表の「流し始め」は、P2〜P4で用意する値（タグは前の1つ、帯URLは設定済みか空か、セールの状態）。「期待値」は取り込み後の規格設定・買取/販売価格履歴・アラート。アラートの文言：

- 取り下げ（セール中→セールなし）で、CSVに販売価格があるとき：「N行目: セールフラグを無効にしたため、CSVに設定された販売価格は反映されていません。」
- 通常商品→セールなし（通常のまま）：「N行目: 通常商品のため、販売価格は変更されませんでした。買取価格のみ更新しています。」
- ほかの組（通常→セール・セール中のまま）：アラートなし
