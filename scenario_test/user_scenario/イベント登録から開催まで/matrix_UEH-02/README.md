# イベント登録から開催までの無料イベント（UEH-02）

IPA「高信頼化ソフトウェアのための開発手法ガイドブック」(2010) の表6-9〜6-11と同じ手順で作る。1行が1本のシナリオ（L3）。

1. 因子・水準表（FL表）: `fl_table.tsv`。利用者が画面で選ぶもの・変わるものを因子にし、設計書の文を根拠に持つ
2. 禁則表: `prohibitions.tsv`。ありえない組み合わせ
3. 組み合わせテストマトリクス: `matrix.md` / `matrix.tsv`。`build_matrix.py` が作る。1行が1本のシナリオになる
4. 例外の差し込み表: `exceptions.tsv`。エラーや中断（★の手順）は、正常な値と混ぜず、条件に合う行へ1つずつ差し込む

## 範囲

- 禁則は置かない（R1指摘）：ルールが厳しいイベントでも、デッキ登録なしのイベント・申込時に登録しない参加者はありうる。出力・確認の対象は「デッキ登録されたデッキ」（業務フロー3-1・3-3）なので、登録デッキの無い参加者は出力に載らず、確認するデッキが無いだけで、設定の組み合わせは禁じていない（0214 イベント編集のルール適用度は単一選択、日程の「デッキ登録あり」はチェックボックスで、互いに制約しない）。申込時に登録しない参加者は、開催日に当日登録する（3-6。締切前・終了チェックなしのとき。当日登録のデッキは、開催前の全員分の出力に載らない）

- 店舗チームが、参加費が無料（0円）でオンライン受付ありのイベントと日程を登録して公開し、会員が見つけてオンライン申込（支払なし）をし、デッキ登録ありのイベントでは申込完了画面からデッキを登録し、開催日に申込一覧をCSV出力して受付し、実施し、参加ポイントがつくところまで。有料との違いは、支払方法の欄が出ない・外部の決済画面へ行かない・クレジット決済完了メールが届かない・申込が決済中を通らず最初から申込済みになる、の4点
- 各行の期待値：無料の申込は、申込確認で支払方法の欄が出ず、外部の決済画面へ行かずに申込完了画面（「イベント申込が完了いたしました。」）が出て、申込状況が最初から「申込済み」になる。クレジット決済完了メールは届かない（新実装は、決済の成立のときだけ送る）。ほかの値の引き継ぎ（イベント名・店舗・開催日時・定員・残り予約数・申込一覧・デッキ・ポイント）は有料と同じ
- 申込・デッキ登録は本店のサイトだけで使える（新実装は、この2つの画面を本店専用にし、支店のサイトからは開けない扱いにしている）。この通しは開催店舗を店舗Aとして、本店のサイトで通す（開催店舗が支店のイベントを本店のサイトから申し込む運用は、設計書に明記が無い。scenario_list.md の判断待ち）
- 同じ会員・同じ日程は二重に申し込めない。キャンセル済みは定員に数えない（開発環境の申込状況マスタ）ので、定員に数える設定が有効な申込状況（決済中・入金待ち・申込済み・入金期限切れ・支払番号が存在しない）が定員を使い、キャンセル済みだけが数えない
- 参加費が無料のとき、イベント詳細・TOPの参加費は「無料」（英語は「Free」）。TOPでは無料イベントにアイコンが付く（0307 イベント大会TOP「無料イベントの場合はユーザーにわかるようアイコンで明示する」）
- 日をまたぐ待ちは有料と同じ扱い（日程の日時を実行日に合わせ、1日の中で通す）
- 因子に入れなかったもの：イベント規模・バナー・公開状態（UEV-01・UEH-01）、チーム戦（チームの他メンバーの入力は廃止）、決済（無料には無い）

## 実装・設計書で確かめたこと（2026-11-05）

- 無料の申込：合計参加費が0円のときは支払方法を提示せず、申込状況は「申込済み」（設計書は「エントリー済み」）で作る（0307 大会申込～完了 業務ロジック「合計参加費が0円のときは支払方法を提示しない」「無料はエントリー済み」、新実装の申込の登録の処理）
- 申込完了メール：無料の申込のときにメールを送る定めは設計書に無い。新実装も、申込完了のメールはクレジット決済が成立したときの1種類で、無料の申込は送らない（新実装 決済の戻りの処理の1か所だけがメールを送る）。メールが届かないことは「記録」とし、不具合とは扱わない（scenario_list.md の食い違い）
- デッキ登録完了メールは有料と同じ（UEH-01のREADME）
- 無料の申込でも、定員・二重申込・受付期間の判定は有料と同じ

## まとめた水準

なし（どの水準も処理が違う）。主な根拠：デッキ登録の3水準はボタンの出る出ないとデッキ登録完了メールの有無が違う。日本語・英語は表示が違う。国内・海外の住所はデッキ登録完了メールのテンプレートが違う。別日程のまとめ申込は申込の件数が違う。
