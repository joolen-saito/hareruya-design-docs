# UEH-03 申込後に会員がマイイベント・デッキ登録の一覧からデッキを登録し直し、開催日にデッキを全員分出して確認し、参加ポイントがつく

| 項目 | 内容 |
|---|---|
| 利用者 | 店舗チームの担当者（イベントを登録する・開催日にデッキを出力する）→ 会員のお客様（国内）→ ポイントグランター（外部）→ メール |
| 目的 | 競技イベントに申し込んだ会員が、開催日の前に、マイページのマイイベント・デッキ登録の一覧からデッキを登録（登録済みなら編集）し直し、開催日に店舗チームが申込一覧のデッキ登録を検索してデッキ表示（印刷）で全員分を出し、会員が最後に提出した内容で確認して、実施して、参加ポイントが付く。後日に登録（編集）したデッキの内容が、開催日の出力・確認に引き継がれることを確かめる |
| 種類 | 正常（通し。申込とデッキ登録の間で時間がたつ） |
| マトリクスの行 | `matrix_UEH-03/matrix.md` のT05（無料・登録済みデッキの編集・ルールが厳しい競技イベント・日本語のサイト） |
| もとのシナリオ | SCN-EVENT-007の後日のデッキ登録（イベント管理のUEV-07）と、UEV-06のデッキ全員分の出力・確認をつないだもの |

UEH-01・UEH-02は申込直後にデッキを登録する通し、このシナリオは、申込のあとシステムの状態は変わらず（申込済みのまま）、会員が時間をおいてデッキを登録し直すところを通す。それだけで読んで流せるように、手順は全部書く。

## 前提

- システムの外で済んでいること：イベント計画（業務フロー1-1）。ポイントグランターの端末が、端末販売の内容をECのAPIへ送れる状態
- 日程の日時は、実行日の1日の中で通せるように決める（試験用）。システムの状態は日をまたいで待たない（デッキの登録は、デッキ登録締切の前なら、受付期間が終わっていても、日が変わっても同じ画面でできる）。順序は、オンライン受付の開始＜申込を行う時刻＜デッキを登録し直す時刻＜デッキ登録締切＜日程の開始
- 用意するデータ（試験用の値。設計書の値ではない）
  - 店舗チームの担当者（開催店舗「店舗A」の編集権限がある）
  - 会員：試験 三郎（本会員、メールアドレス `ueh-03@example.test`、国内（東京都）の住所を登録済み、選手情報あり、スマレジの会員作成済み、保有ポイントは手順前の値を控える）
  - イベント「シナリオ試験 スタンダード大会（競技・無料）」（英語名 Scenario Test Standard Competitive Tournament）：店舗＝店舗A、フォーマット＝スタンダード、ルール適用度＝競技、イベント規模＝定番イベント、公開状態＝公開、定員＝8、参加費＝0円
  - 日程：開始＝実行日20:00、受付あり（19:30〜19:50）、デッキ登録あり・デッキ登録締切＝実行日19:00、デッキ登録を終了するはオフ、オンライン受付あり（実行日0:00〜19:00）、定員8・参加費0円・公開状態は親イベントを引き継ぐ
  - デッキリスト：1回目はスタンダードに則したメインボード60枚・サイドボード15枚以内。2回目は1回目からメインボードの4枚を別のカードに入れ替えた内容（試験用）

## L3で変わるところ（マトリクスの他の行・例外）

- 一覧からデッキを登録する回：初回の行（T01・T03）は、準備P3（申込完了画面での登録）を通らず、手順1で一覧に「デッキ未登録」とボタン「デッキ登録」が出る。手順2で初回の提出をし、デッキ登録完了メールは1通、一覧は「デッキ登録済み」・ボタン「デッキ編集」に変わる。デッキの数は1つ増える
- 参加費：有料の行（T01・T02・T06）は、準備P2で支払方法のクレジットカード決済を選び、外部の決済画面で決済し、クレジット決済完了メールが届く（UEH-01の手順7〜10と同じ）。それ以降は同じ
- ルールの厳しさ：厳しくない行（T01・T04・T06）は、手順6のデッキ表示・手順7の照合を通らない（全員分の出力・確認は競技イベントの工程）。手順5の申込一覧の確認は通る
- 表示言語：英語のサイトの行（T02・T03・T06）は、マイイベント・デッキ登録・デッキ登録の画面が英語（デッキ登録のボタンは登録済みでも Decklist）。デッキ登録完了メールは会員の住所で決まる
- 例外：`matrix_UEH-03/matrix.md` の例外EX1〜EX10（締切後・終了チェック・イベント終了で一覧にボタンが出ない、書式の誤りで保存されない、枚数などの内容のエラーでも登録される、メール送信の失敗、ポイント付与の失敗3種）。細部は `イベント管理/` のUEV-07の例外と同じ
