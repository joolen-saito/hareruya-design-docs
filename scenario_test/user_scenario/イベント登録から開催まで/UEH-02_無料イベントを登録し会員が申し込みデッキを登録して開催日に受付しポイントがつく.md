# UEH-02 無料イベントを登録し、会員が決済なしで申し込んでデッキを登録し、開催日に受付・実施して参加ポイントがつく

| 項目 | 内容 |
|---|---|
| 利用者 | 店舗チームの担当者（イベントと日程を登録する・開催日に申込一覧を出す）→ 会員のお客様（国内）→ ポイントグランター（外部）→ メール |
| 目的 | 参加費が無料でオンライン受付ありの競技イベントを登録して公開し、会員が決済なしで申し込み、デッキを登録して、開催日に申込一覧とデッキ表示で受付・確認し、実施して、参加ポイントが会員に付く。有料（UEH-01）との違い（支払方法の欄・決済画面・クレジット決済完了メールが無い）と、値の引き継ぎを確かめる |
| 種類 | 正常（通し） |
| マトリクスの行 | `matrix_UEH-02/matrix.md` のT01（別日程を選ばず1日程だけ申し込む・デッキ登録ありで申込完了画面から登録する・ルールが厳しい競技イベント・日本語のサイト・国内の住所） |
| もとのシナリオ | SCN-EVENT-008（デッキ登録なしの申込）・SCN-EVENT-001・006・011（イベント管理のUEV-01・UEV-02・UEV-06をつないだもの） |

有料の通し（UEH-01）と同じ区間は、同じ画面・同じ値の引き継ぎなので、このシナリオでは無料で変わるところを手順に書く。それだけで読んで流せるように、手順は全部書く。

## 前提

- システムの外で済んでいること：イベント計画（業務フロー1-1）。ポイントグランターの端末が、端末販売の内容をECのAPIへ送れる状態
- 日程の日時は、実行日の1日の中で通せるように決める（試験用）。順序は、オンライン受付の開始＜申込を行う時刻＜オンライン受付の終了＜日程の開始。デッキ登録締切は、デッキを登録する時刻より後
- 用意するデータ（試験用の値。設計書の値ではない）
  - 店舗チームの担当者（開催店舗「店舗A」の編集権限がある）
  - 会員：試験 次郎（本会員、メールアドレス `ueh-02@example.test`、国内（東京都）の住所を登録済み、選手情報あり、スマレジの会員作成済み、保有ポイントは手順前の値を控える）
  - イベント「シナリオ試験 スタンダード大会（無料）」（英語名 Scenario Test Standard Free Tournament）：店舗＝店舗A、フォーマット＝スタンダード、ルール適用度＝競技、イベント規模＝定番イベント、公開状態＝公開、定員＝8、チーム戦＝オフ、支払方法＝クレジットカード決済（初期値のまま。有料の日程が無いので使われない）、参加費＝0円
  - 日程：開始＝実行日20:00、受付あり（19:30〜19:50）、デッキ登録あり・締切＝実行日19:00、オンライン受付あり（実行日0:00〜19:00）、定員8・参加費0円・公開状態は親イベントを引き継ぐ。別日程は登録しない（申込時に登録しない行（デッキ登録の設定がB2）では、開催日の当日登録（業務フロー3-6）が実施（3-3）の後になるので、デッキ登録締切を実施の後（例：実行日23:00）に設定して登録する。設計書は、登録ボタンの条件を「現在日時が「デッキ登録締め切り」の日時より以前」とする）
  - デッキリスト：スタンダードに則したメインボード60枚・サイドボード15枚以内（試験用の内容）

## L3で変わるところ（マトリクスの他の行・例外）

- 申込む日程：別日程もまとめて申し込む行（T04〜T08）は、日程を2つ登録し、手順5で日程2にもチェックを入れる。申込確定画面は2件・合計0円、申込は2件、残り予約数は日程ごとに7。無料なのでメールは届かない。開催日は、申込一覧が2件（日程ごと）で、受付・実施・照合は日程ごとに行う。参加ポイントを日程ごとに付与するかは設計書に定めが無い（記録。scenario_list.md の判断待ち）。デッキ登録は、デッキ登録の設定の水準で分かれる：
  - T04・T07（デッキ登録ありで申込完了画面から登録する）：申込完了画面のデッキ登録ボタンは1つで、先頭の日程のデッキ登録へ進む（新実装の画面。記録）。もう一方の日程のデッキは一覧から登録する（UEH-03）か、登録しない
  - T05・T08（申込完了画面では登録しない）：ボタンは使わず、日程ごとに開催日にイベント詳細から当日登録する
  - T06（デッキ登録なし）：デッキ登録のボタンも一覧からの登録も無い
- デッキ登録の設定
  - 申込完了画面では登録しない行（T02・T05・T08）：手順8・9・14を通らず、手順10の一覧は「デッキ未登録」・ボタン「デッキ登録」。開催日は、手順15の代わりに業務フロー3-6を通る。この行は日程のデッキ登録締切を実施の後に設定しておく（前提）。参加者が、イベント詳細（締切前・終了にチェックなし）の「デッキ登録」から当日登録し、デッキ登録完了画面・デッキ登録完了メールが出て、一覧が「デッキ登録済み」になる。締切後・終了チェックありはボタンが出ず、デッキ無しのまま実施・ポイント付与へ進む（例外EX6）。ルールが厳しい行（T08）では、当日登録のデッキは開催前の全員分の出力に載らない（当日登録後の確認の方法は業務フロー・設計書に定めが無い。記録）。後日に登録し直す通しはUEH-03
  - デッキ登録なしのイベントの行（T03・T06）：「デッキ登録あり」を入れず、デッキ登録のボタンが出ない。ルールが厳しい行（T06）では「デッキ登録を検索」が0件で、出力・確認するデッキが無い
- ルールの厳しさ：厳しくない行（T02・T03・T05・T07）は手順14と照合を通らない
- 表示言語：英語のサイトの行（T02・T03・T04・T07・T08）は、画面が英語で出る（参加費は「Free」）。デッキ登録完了メールは会員の住所で決まる
- 会員の登録住所：デッキ登録完了メールが届くのは、デッキを登録する行（B1・B2の行）だけで、デッキ登録なしの行（T03・T06）には届かない。海外の住所でデッキを登録する行（T02・T04）は、デッキ登録完了メールが英語のテンプレート（件名「[店名] 【Hareruya】Deck submission is complete.」）、国内の住所の行は日本語。サイトの言語と住所が食い違う行（T07・T08：英語のサイト×国内の住所）でも、デッキ登録完了メールの言語は会員の住所で決まる。無料なので申込完了メールは無く、言語は記録で合否は付けない（scenario_list.md の食い違い）
- 例外：`matrix_UEH-02/matrix.md` の例外EX1〜EX10（申込同意なし・定員到達・受付期間の超過・二重申込・デッキ内容のエラー・デッキ登録の締切後・キャンセル済みの申込が申込一覧に載る・ポイント付与の失敗3種）
