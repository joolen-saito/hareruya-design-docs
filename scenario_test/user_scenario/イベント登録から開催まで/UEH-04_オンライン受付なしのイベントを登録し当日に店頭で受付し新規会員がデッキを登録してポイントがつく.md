# UEH-04 オンライン受付なしのイベントを登録し、当日に店頭で受付・実施し、会員登録のない参加者が新規会員登録してデッキを登録し、参加ポイントがつく

| 項目 | 内容 |
|---|---|
| 利用者 | 店舗チームの担当者（イベントと日程を登録する・当日の受付と実施・ポイント付与）→ 参加者（会員登録のないお客様。当日に会員になる）→ ポイントグランター（外部）→ メール |
| 目的 | オンライン受付なし（店頭受付）のイベントを登録して公開し、お客様の画面に申込のボタンが出ないことを確かめ、開催日に店頭で受付・実施し、会員登録のない参加者が新規会員登録してイベント詳細からデッキを登録し、参加ポイントが付く。会員になる前後でデッキ・ポイントが同じ会員に引き継がれることを確かめる |
| 種類 | 正常（通し。ECの申込・決済を通らない） |
| マトリクスの行 | `matrix_UEH-04/matrix.md` のT03（会員登録がなく当日に新規会員登録する・デッキ登録ありのイベント・日本語のサイト） |
| もとのシナリオ | SCN-EVENT-007・010（イベント管理のUEV-01とUEV-06のオンライン受付でない行をつないだもの） |

オンライン受付のイベントは、UEH-01〜UEH-03で通す。このシナリオは、ECでの申込・決済・申込完了メールが無い。会員登録の手順の細部は `会員管理/` のUMB-01（会員登録の申込）・UMB-02（本登録）を参照し、ここでは会員になったことと、そのあとのデッキ・ポイントの引き継ぎだけを確かめる。

- 日程の日時は、実行日の1日の中で通せるように決める（試験用）。順序は、日程の開始＜デッキを登録する時刻＜デッキ登録締切
- 用意するデータ（試験用の値。設計書の値ではない）
  - 店舗チームの担当者（開催店舗「店舗A」の編集権限がある）
  - 参加者：試験 四郎（会員登録なし。登録に使うメールアドレス `ueh-04@example.test`、国内（東京都）の住所。登録後の本会員になる。スマレジの会員は本会員登録で作られる（USM-12））
  - イベント「シナリオ試験 スタンダード店頭大会」（英語名 Scenario Test Standard Walk-in Tournament）：店舗＝店舗A、フォーマット＝スタンダード、ルール適用度＝カジュアル対戦、イベント規模＝定番イベント、公開状態＝公開、定員＝8、チーム戦＝オフ、支払方法＝クレジットカード決済（初期値のまま。オンライン受付が無いので使われない）、参加費＝500円
  - 日程：開始＝実行日20:00、受付あり（19:30〜19:50）、デッキ登録あり・デッキ登録締切＝実行日23:00、デッキ登録を終了するはオフ、オンライン受付あり＝チェックを入れない、定員8・参加費500円・公開状態は親イベントを引き継ぐ

## L3で変わるところ（マトリクスの他の行・例外）

- 参加者の会員状態：会員登録済みの行（T01・T02）は、手順8・9を通らず、手順10で参加者が会員のメールアドレスとパスワードでログインしてから進む。会員登録済みの参加者には会員登録を促さない（業務フロー3-4の分岐は「有」）
- デッキ登録の設定：デッキ登録なしのイベントの行（T02・T04）は、日程の「デッキ登録あり」を入れない。手順5で「デッキ登録」ボタンが出ず、デッキ・デッキ登録完了メール・マイイベント・デッキ登録の一覧の行は生じず（申込もデッキも無いイベントは一覧に載らない）、申込一覧の「デッキ登録を検索」も0件で、手順10〜12・15のデッキの確認を通らない。参加者は会員になるだけで、ポイントは付く
- 表示言語：英語のサイトの行（T01・T04）は、TOP・大会詳細・デッキ登録の画面が英語（デッキ登録のボタンは登録済みでも Decklist、一覧の処理状態は英語名）。デッキ登録完了メールは会員の住所で決まる
- ルールの厳しさは因子に入れない：全員分のデッキの事前出力（3-1）はオンライン受付の工程で、当日登録のデッキは出力の時点でまだ無い（`イベント管理/matrix_UEV-06/` の禁則X4・X5）
- 例外：`matrix_UEH-04/matrix.md` の例外EX1〜EX6（会員登録を断る、デッキ登録の締切後、デッキ内容のエラー、ポイント付与の失敗3種）
