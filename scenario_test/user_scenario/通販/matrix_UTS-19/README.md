# 通販の返品（UTS-19）

IPA「高信頼化ソフトウェアのための開発手法ガイドブック」(2010) の表6-9〜6-11と同じ手順で作る（形は `../matrix/` と同じ）。`fl_table.tsv`・`prohibitions.tsv`・`exceptions.tsv` から `matrix.md`・`matrix.tsv` を `build_matrix.py` が作る。2026-11-05 に依頼者が「決済の返品とキャンセルもシナリオに入れて」と指示したので作った。

## 範囲

- 出荷完了のあと、お客様が商品を受け取り、返品を申し出る。または、代金引換でお客様が受け取りを拒否して荷物が戻る
- 返品という受注の状態は、新実装にあるが、画面から選べず、その状態へ遷移させる処理も見つからなかった（`src/Eccube/Form/Type/Admin/OrderType.php` 470〜472行目で選択肢から外している）。設計書 0203 の「スマレジで購入した商品を返品する場合はキャンセルで対応する」はスマレジの返品の定めで、通販の返品を定めていない（2026-11-05 R4指摘で根拠から外した）。通販の返品の手順は設計書・業務フロー16・17に無い。受注情報編集のキャンセルは状態の制限を書かず、新実装が出荷完了からのキャンセルを許すので、これで返品を扱う（業務横断 UXB-03 と同じ）
- 支払方法は `../matrix/` の水準S1〜S7（S1・S2はA1にまとめた）。返金の方法は支払方法ごとに `../matrix_UTS-02/README.md` の決まりと同じ（出荷完了の時点で入金済みなので「入金済み」の列）。郵便振替・銀行振込・コンビニ決済・代金引換（受け取り後の返品）の行は、振込による返金とポイント付与による返金の二つを確かめる。代金引換は、受け取り後の全部返品（C1）・一部返品（C2）・受け取り拒否（C3）の行がある

## 期待値の決まり

| 経緯・範囲 | 受注の状態 | 在庫 | 使用ポイント | 付与ポイント | 返金 |
|---|---|---|---|---|---|
| お客様の申し出・全部（C1） | 出荷完了→キャンセル | 注文数が戻る（在庫履歴「キャンセル時の在庫戻し」） | 戻る | 戻る（ポイント履歴が削除される） | 支払方法ごとにUTS-02の決まり |
| お客様の申し出・一部（C2） | 変わらない（「一部キャンセルが完了しました」） | キャンセル分だけ増える | 変動なし | 変動なし（付与済みポイントは変わらない。0203 M05-11-MSG-016・017）。ポイント付与による返金で補う | 支払方法ごとにUTS-02の決まり（クレジットカード決済は減額） |
| 代金引換の受け取り拒否・全部 | 出荷完了→キャンセル（資料に定めは無いが、新実装が出荷完了からのキャンセルを許す） | 判断待ち | 判断待ち | 判断待ち | 代金を受け取っていないので返金は無い（判断待ちの確認）。送料・返送費の扱いは資料に無い |

## 実装と設計書で確かめたこと（2026-11-05）

- 出荷完了からのキャンセル：新実装は許す（`app/config/eccube/packages/order_state_machine.php` 200〜211行目）。設計書 0203 は状態の制限を書かない。キャンセルでポイント履歴の削除・保持ポイントの戻し・スマレジへの連携を行う（`src/Eccube/Controller/Admin/Order/EditController.php` 730・918行目付近）
- 返品の申し出の条件：新実装の画面の案内に「商品到着後8日以内にご連絡」「当社の送料負担にて交換または返金（返品）」「お客様のご都合による返品・交換は一切お受けできません」がある（`src/Eccube/Resource/locale/messages.ja.yaml` 1439〜1451行目）。設計書 0303 商品詳細に「返品特約に関する重要事項について」のリンク項目（2-25）があるが内容の記述は無い。返品を受け付ける条件（契約不適合・到着後8日以内。お客様のご都合・9日以上は受け付けない）をB1に明記し、受け付けない申し出を例外E4に入れた
- 受け取り拒否・返送：業務フロー16・17、設計書 0203・0304・0405、新実装のどこにも記述が無い（`受け取り拒否`・`返送` で探して無かった）

## 判断待ち（何を見ても決まらなかったもの）

1. 代金引換の受け取り拒否：荷物が戻ったあとの受注の扱い（キャンセルにする時点、在庫を戻す時期、送料・手数料の扱い）。受注の状態は出荷完了からのキャンセルで確かめ、ほかは決めない
2. 返品の物の流れ（商品の返送の確認、検品、在庫に戻す時点）：業務フローに無い。システムの外の作業として扱い、受注情報編集のキャンセルで在庫が戻る時点だけを確かめる
3. 代金引換の返金（配達時に受け取った代金の返金）の手順：業務フロー16の9「クレジットカード以外の返金対応」（振込・ポイント付与）に従うとして書くが、代金引換を名指しする記述は無い
4. 付与済みポイントの戻し：設計書 0203 は全部のキャンセルで「付与ポイントを戻す」と書く。新実装の状態の遷移の定義はこのイベントを持たないが、受注情報編集の保存でポイント履歴を削除する処理がある（上の根拠）。実機で確かめる
