# UTS-16 銀行振込・郵便振替の入金を確認して、受注を入金済みにし、出荷する

| 項目 | 内容 |
|---|---|
| 利用者 | お客様（銀行・ゆうちょ銀行で振り込む。システムの外）→ 通販チーム（管理画面）→ メール |
| 目的 | 振り込まれた銀行振込（入金待ち）・郵便振替（注文受領）の受注を、通販チームが入金データと突き合わせて「入金済み」にし（入金日が入る）、出荷指示から出荷実績の取り込みまで進めて、お客様に出荷完了メールが届く。発送管理台帳・入金管理台帳の更新はシステムの外 |
| 種類 | 正常 |
| マトリクスの行 | `matrix_UTS-16/matrix.md` の T01（銀行振込・同梱でない）。ほかの行は「L3で変わるところ」 |
| もとのシナリオ | SCN-TSUHAN-002・005・901・913 |
| 購入するEC | 本店のEC（受注は本店の受注） |

## 前提

- 共通の決まり：`../L4を流すときの共通の決まり.md` を先に読む（試験データの名前にシナリオIDを付ける・共有の設定は元に戻す・バッチの起動・店舗の読み替えなど）
- システムの外で済んでいること：UTS-01 の終点（購入完了）まで済んでいる。T01 の前提は UTS-01 の T31 行（会員・銀行振込・ゆうパック・ポイントは使わない・販売制限なしの商品）の終点の受注。受注の対応状況は「入金待ち」、入金日は空。注文完了メールと支払方法のメールは UTS-01 で確かめ済み
- 用意するデータ（試験用の値。設計書の値ではない）
  - 会員：試験 太郎（`uts16-t01@example.test`）。T31 の購入で作った受注の注文番号（8桁）と注文金額合計を控えてある
  - 通販チームの担当者：管理画面で受注情報検索・受注情報編集・出荷指示リスト生成・出荷指示リスト検索・手動メール通知・出荷実績インポート登録を使える
  - 銀行の入金データ：注文金額合計と同じ金額を振り込んだ入金（システムの外で用意する。試験では入金データの代わりに、控えた金額の入金があったものとして扱う）
- 入金を確認する時刻（15時前・15時以降）は待たずに、手で作業を始める（2026-11-26 決定）

## L3で変わるところ（マトリクスの他の行・例外）

手順の番号は上の「操作の流れと期待値」。

| 行 | 条件（支払方法・同梱か） | 変わるところ |
|---|---|---|
| T01 | 銀行振込・同梱でない | 代表の行 |
| T02 | 銀行振込・同梱 | 前提：UTS-01 の T13 行（会員・同梱・銀行振込）の終点の受注（同梱の注文）と、同梱元の受注（銀行振込または郵便振替で、同じ会員の受注。UTS-01 の同梱の前提）の2件。手順1〜5：2件とも銀行振込の入金待ちなら、それぞれ入金を確認して「入金済み」にする（2件とも入金日が入る）。手順2：発送管理台帳に同梱対応・備考を反映する（システムの外。業務フロー 2-6）。手順6〜11：同梱元は代表と同じ（出荷指示リスト生成から出荷実績の取り込み）。同梱の注文は、同梱元といっしょに梱包して同じ集荷に渡し、出荷実績を取り込まず、通販チームが受注情報編集の「変更後のステータス」で「出荷完了」を選び「受注ステータス変更」を押す（業務フロー 4-14）。続けて手動メール通知で、テンプレート「【通販/日】同梱出荷完了」（件名「【晴れる屋】商品を出荷しました」。新実装の初期データ）を選んで件名・本文を直し、「確認」を押して確認画面で「送信」を押す（「メールを送信しました。」）。同梱の注文の出荷完了メールは、この手動メール通知で届く |
| T03 | 郵便振替・同梱でない | 前提：UTS-01 の T28 行（会員・郵便振替・ゆうパック・販売制限は日本国内のみ）の終点の受注。対応状況は「注文受領」。手順1：対応状況「注文受領」・支払方法「郵便振替」で検索する。手順2：郵便の入金データを取得し、郵便入金管理台帳と発送管理台帳の入金日を更新する（業務フロー 3-2）。手順3：現在のステータスは「注文受領」。手順4〜11：代表と同じ（注文受領から「入金済み」へ変わり、入金日が入る）。T28 はポイントを一部使う注文なので、入金の確認でも使用ポイントは戻らず・増えない |
| T04 | 郵便振替・同梱 | 前提：UTS-01 の T01 行（会員・同梱・郵便振替）の終点の受注と、同梱元の受注。手順1〜3：対応状況は「注文受領」。手順2：郵便の入金データを取得する（業務フロー 3-2）。手順4以降：T02 の同梱の流れと同じ |

例外：`matrix_UTS-16/exceptions.tsv` に例外は無い（0件）。

マトリクスの行には無いが、一覧のL3欄にあるもの：予約商品の受注は、入金の確認で通常の手順4のあと、手動メール通知で予約入金のメールを送る（業務フロー 5-1。購入は UTS-04）。テンプレートは「【通販/日】（予約）支払完了　※水色」（件名「【晴れる屋】予約商品のお支払いを確認いたしました」）（新実装の初期データ。設計書に定めは無い）。
