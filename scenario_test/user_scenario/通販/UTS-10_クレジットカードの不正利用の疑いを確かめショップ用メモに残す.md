# UTS-10 クレジットカードの不正利用の疑いがある注文を確かめ、会員のショップ用メモに残す

| 項目 | 内容 |
|---|---|
| 利用者 | 通販チーム（管理画面）。カード会社への照会や本人への連絡は、運用で決まるシステムの外の作業 |
| 目的 | 毎日の確認作業で、不正利用の疑いがあるクレジットカード決済の注文（高額の初回注文・決済の名義人の違い・決済エラーの数）を抜き出して確かめ、確認した会員のショップ用メモに日付と「IDOK」または「OK」を書く |
| 種類 | 正常（確認済みの印を残す） |
| マトリクスの行 | `matrix_UTS-10/matrix.md` のT01（高額の初回注文）。T02（決済の名義人の違い）・T03（決済エラーの数）は「L3で変わるところ」 |
| もとのシナリオ | なし（業務フロー16の3-8から新規に起こした） |

## 前提

- 共通の決まり：`../L4を流すときの共通の決まり.md` を先に読む（試験データの名前にシナリオIDを付ける・共有の設定は元に戻す・バッチの起動・店舗の読み替えなど）
- 購入するEC・扱う受注：本店のECの受注（クレジットカード決済の注文）
- システムの外で済んでいること：なし。確認の結果、疑いが晴れた場合だけを扱う（疑いが残ったときの対応は業務フロー16に無い。判断待ち 3）
- 用意するデータ（試験用の値。設計書の値ではない）
  - 会員：試験 八郎（`uts-10-t01@example.test`）。これまで注文が無く、クレジットカード決済（登録済みカードでない）・ゆうパックで、試験用の「高額」の基準を超える金額の注文を1件した（初回の注文）。ご注文番号を控える。送料は注文の確認画面の値のまま。試験用の「高額」の基準は100,000円以上とする（運用の値は設計書に無い。判断待ち 1）
  - 通販チームの担当者：管理画面で受注管理と会員管理を使える権限を持つ
- 会員のショップ用メモ欄は、確認の前は空
