# UTS-21 入金が無い受注の出荷準備を、入金を待たずに進める

| 項目 | 内容 |
|---|---|
| 利用者 | 通販チーム（管理画面）。ラベル印字・ペアリング・ピック・振り分け・梱包はシステムの外 |
| 目的 | 入金待ち・注文受領のまま（未入金）の受注を、入金の確認を待たずに出荷指示にして、ピッキングリスト・納品書・ラベルを出し、梱包まで準備する。入金の確認は別に進む（UTS-16・UTS-17） |
| 種類 | 正常（未入金の出荷準備） |
| マトリクスの行 | `matrix_UTS-21/matrix.md` のT01（コンビニ決済）。T02（郵便振替）・T03（銀行振込）は「L3で変わるところ」 |
| 扱う受注 | 本店のECの受注（通販は本店のEC。支店のECは配送が無いので扱わない） |
| もとのシナリオ | 003（未入金の受注の側） |
| 業務フロー | 16 通販受注管理の2 発送準備業務（2-1〜2-14。2-5の注「出荷準備は入金が無くても進めており」）。(tobe) の17には2 発送準備業務が無いので16を元にする（2026-11-26 決定） |

## 前提

- 共通の決まり：`../L4を流すときの共通の決まり.md` を先に読む（試験データの名前にシナリオIDを付ける・共有の設定は元に戻す・バッチの起動・店舗の読み替えなど）
- 起点の受注（UTS-01 の終点）：購入が完了し、入金がまだ無い。コンビニ決済・郵便振替は「注文受領」、銀行振込は「入金待ち」。受注の入金日は空
  - 代表の行（T01・コンビニ決済）：UTS-01 の T07（会員・コンビニ決済・ゆうパック・ポイントを使わない・2点以上）の終点
  - T02（郵便振替）：UTS-01 の T28（会員・郵便振替・ゆうパック・日本国内のみの商品）の終点
  - T03（銀行振込）：UTS-01 の T31（会員・銀行振込・ゆうパック・ポイントを使わない）の終点
  - 同梱の行（UTS-01 の T01・T13・T17・T24）は同梱元とまとめる扱いがあり、この試験の「入金待ち・注文受領のまま出荷準備に進める」流れの確認とは別なので使わない（同梱の入金・出荷は UTS-16）
- 用意するデータ（試験用の値。設計書の値ではない）
  - 会員：試験 一郎（`uts-21@example.test`）。上の行で購入した受注を1件。ご注文番号を控える。受注の出荷日は空。ほかに、出荷指示リストの対象になる未発送の受注が混ざらないよう、ご注文番号の範囲は控えた1件だけを指定する
  - 通販チームの担当者：管理画面で受注管理（受注マスター・出荷指示・出荷実績）を使え、本店の受注を編集できる権限を持つ
- 発送準備の作業時刻（8:30・13:00・15:00・18:00）は、時刻を待たずに手で行う（2026-11-26 決定）
- 個別対応の確認（注文備考や受注内容から対応が必要か。業務フロー2-3・2-4）は UTS-01 の L3 で確かめる。ここでは対応が要らない受注で通す
