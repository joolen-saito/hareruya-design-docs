# UTS-17 コンビニ決済の支払が受注に反映され、入金済みになって出荷する

| 項目 | 内容 |
|---|---|
| 利用者 | お客様（コンビニで支払う。システムの外）→ SPLINKS（外部）→ 通販チーム（管理画面）→ メール |
| 目的 | コンビニで支払われた注文が、SPLINKS の入金通知（通知が届かないときは受注情報編集の決済状況照会）で受注に反映されて「入金済み」になり、EC-CUBE の決済情報と SPLINKS の取引情報が一致する。そのあと出荷され、お客様に出荷完了メールが届く |
| 種類 | 正常（通知が届かない流れを T02 で通す） |
| マトリクスの行 | `matrix_UTS-17/matrix.md` の T01（コンビニ決済の入金通知（SPLINKS）） |
| もとのシナリオ | SCN-TSUHAN-002・006 |
| 購入するEC | 本店のEC（受注は本店の受注） |

## 前提

- 共通の決まり：`../L4を流すときの共通の決まり.md` を先に読む（試験データの名前にシナリオIDを付ける・共有の設定は元に戻す・バッチの起動・店舗の読み替えなど）
- システムの外で済んでいること：UTS-01 の終点（購入完了）まで済んでいる。T01 の前提は UTS-01 の T07 行（会員・コンビニ決済・ゆうパック・ポイントは使わない・販売制限なしの商品・複数明細）の終点の受注。受注の対応状況は「注文受領」。注文完了メールと、支払方法（支払先のコンビニ・支払期限）のメールが別に届いていること（業務フロー 1-5。UTS-01 で確かめ済み）
- 用意するデータ（試験用の値。設計書の値ではない）
  - 会員：試験 次郎（`uts17-t01@example.test`）。T07 の購入で作った受注の注文番号（8桁）・注文金額合計・支払先のコンビニを控えてある
  - SPLINKS の試験環境：コンビニ入金の通知を発生させられる（外部サービスの操作はその試験環境の手順による）
  - 通販チームの担当者：管理画面で受注情報検索・受注情報編集・出荷指示リスト生成・出荷指示リスト検索・出荷実績インポート登録を使える
- 15時以降の確認の時刻は待たずに、手で作業を始める（2026-11-26 決定）

## L3で変わるところ（マトリクスの他の行・例外）

手順の番号は上の「操作の流れと期待値」。

| 行 | 条件（入金の取り込み方） | 変わるところ |
|---|---|---|
| T01 | コンビニ決済の入金通知（SPLINKS） | 代表の行 |
| T02 | 入金通知が届かず、受注情報編集の結果照会で取り込む | 手順3：お客様はコンビニで支払うが、SPLINKS の入金通知を EC に届けない（通知が届かない状況を試験環境で作る）。手順4：受注情報検索の対応状況は「注文受領」のまま、入金日は空（通知が無いので自動では変わらない）。手順4の続き：受注情報編集の「ソニーペイメントサービス決済情報」で「決済状況照会」を押す（確認のダイアログが出たらOKを押す）。SPLINKS が支払い済みと答え、金額が受注と同じなら、「保存しました」が出て、取引ステータスが「支払い完了」、対応状況が「入金済み」、入金日が入る。手順5以降は代表と同じ。（新実装にある操作で、設計書・業務フローには無い。判断待ち 1） |

例外：`matrix_UTS-17/exceptions.tsv` に例外は無い（0件）。

マトリクスの行には無いが、一覧のL3欄にあるもの（通知の金額が受注と違うとき、新実装の動き）：入金の通知の金額が受注の注文金額合計と違うと、対応状況は「注文受領」のまま入金済みにならず、通知メール（「受注金額と決済金額が一致していません。」の内容。運用の通知先に届く）が出る。結果照会で金額が違うときは管理画面に「受注金額と決済金額が一致していません。」の警告が出て、対応状況は変わらない。照会の時点でまだ支払われていないとき（SPLINKS が金額を返さない）は、メッセージは出ず、対応状況・取引ステータスとも変わらない。予約商品の受注は、入金の確認のあと手動メール通知で予約入金のメールを送る（業務フロー 5-1。テンプレートの名前は UTS-16 の判断待ち 2）。
