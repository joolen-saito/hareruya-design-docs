# UTS-01 会員が購入し、通販チームが出荷し、お客様に出荷完了が届く

| 項目 | 内容 |
|---|---|
| 利用者 | 会員のお客様 → 通販チーム（管理画面）→ ラベル印字・集荷（システムの外）→ お客様（メール） |
| 目的 | 会員が本店のECで商品を探して買い、注文が受け付けられ、通販チームが出荷準備から出荷実績の取り込みまで進め、お客様に出荷完了が届く（郵便振替・銀行振込・コンビニ決済の注文は購入完了まで。入金の確認からはUTS-16・UTS-17） |
| 種類 | 正常（購入から出荷完了まで）。例外はこのファイル末尾の例外の表 |
| マトリクスの行 | `matrix/matrix.md` のT35（グッズ・数量2点以上・Japan・ゆうパック・ポイントを一部使う・登録済みクレジットカード決済・商品金額合計が送料無料金額以上・日本国内のみ）。購入から出荷完了メール・マイページの「出荷完了」まで通せる行のうち、カード情報の入力画面が無く、送料が0円で、ポイントの消費と連携も確かめられるものを代表にした。ほかの34行と例外18件は「L3で変わるところ」 |
| もとのシナリオ | SCN-TSUHAN-お客様EC購入フロー-001・003・004・007・921・910〜912・915・919・913（同梱）。見本 US-TSUHAN-01（会員がカードを探してクレジットカードで買う）・US-TSUHAN-03（通販チームが注文を出荷しお客様に知らせる）の手順を使い、設計書・新実装と食い違う文言は直した |

## 前提

- 共通の決まり：`../L4を流すときの共通の決まり.md` を先に読む（試験データの名前にシナリオIDを付ける・共有の設定は元に戻す・バッチの起動・店舗の読み替えなど）
- システムの外で済んでいること：なし（ピッキング・梱包・ラベルの貼り付け・集荷は手順の途中で「システムの外」として行う）
- 購入するEC：本店のEC（支店のECは配送方法が店舗受取だけ・支払方法が店頭支払だけなので使わない。0304 ご注文方法指定）
- 用意するデータ（試験用の値。設計書の値ではない）
  - 会員：試験 花子（`uts-01@example.test`）。国内の住所を登録済み。保有ポイント3,000。SPLINKSの試験環境のクレジットカードを1枚登録済み。パスワードは今の決まりに合うもの
  - 商品：グッズ「シナリオ試験グッズA」（単価15,000円（税込）、在庫5、公開、販売制限は「日本国内のみ」、購入制限数なし）。数量2で商品金額合計30,000円になり、送料無料金額（30,000円。ご注文方法指定の案内「1件のご注文に対して、商品合計金額が30,000円以上は送料無料」）に届く。Small packetの上限金額は超えない（50,000円以下）
  - 送料・手数料の前提：ゆうパックは30,000円以上で送料0円。登録済みクレジットカード決済の手数料は0円。したがって注文金額合計は 30,000円 − 使用ポイント1,000 ＝ 29,000円（税込）。この表の金額は、行を替えるときは送料・手数料を足し引きして取り直す
  - 通販チームの担当者：管理画面にログインでき、受注管理・出荷指示リスト・出荷実績インポートを使えるアカウント
  - 他の行のデータ：カード商品「シナリオ試験カードA」（日本語・NM・1,000円・在庫5。数量が在庫と同じ・購入制限数と同じの行は、在庫・購入制限数をその数に合わせて用意する）。グッズ・カードとも、数量の水準と販売制限の水準に合わせて用意する
- 手順2〜9は購入するお客様、手順13以降は通販チームの操作

## L3で変わるところ（マトリクスの全35行）

手順の番号は上の「操作の流れと期待値」。「条件」の列は、商品の種類／数量／お届け先の国／配送方法／ポイント／支払方法／商品金額合計／商品の販売制限の順。どの行も、手順1（ログイン）・5（お届け先は登録済みの住所）・8（最終確認画面）・10・12・13は代表の行と同じ。代表と同じ手順は書かない。金額は手順の前提の考え方で取り直す（送料・手数料を足し引きする）。

| 行 | 条件 | 変わるところ |
