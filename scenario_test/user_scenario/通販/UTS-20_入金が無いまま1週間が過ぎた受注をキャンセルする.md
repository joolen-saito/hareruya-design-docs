# UTS-20 入金が無いまま注文から1週間が過ぎた受注をキャンセルする

| 項目 | 内容 |
|---|---|
| 利用者 | 通販チーム（管理画面）。お客様へはメール（手動メール通知）で連絡する。銀行・ゆうちょ銀行の入金データの確認と発送管理台帳の更新はシステムの外 |
| 目的 | 注文から1週間たっても入金が無い受注を、通販チームが受注情報編集で「キャンセル」にし、在庫と使用ポイントを戻す。コンビニ決済は決済も削除する |
| 種類 | 正常（未入金の期限切れのキャンセル） |
| マトリクスの行 | `matrix_UTS-20/matrix.md` のT01（コンビニ決済・注文受領・ポイントを使っていない）。T02〜T07は「L3で変わるところ」 |
| 扱う受注 | 本店のECの受注 |
| もとのシナリオ | 008（1週間後のキャンセル）・916 |
| 業務フロー | 16 通販受注管理の5 お客様対応（EC-CUBEでの対応）の5-1「キャンセルは受注1週間後に対応、ステータスをキャンセルに変更する」。(tobe) の17には5が無いので16を元にする（2026-11-26 決定） |

## 前提

- 共通の決まり：`../L4を流すときの共通の決まり.md` を先に読む（試験データの名前にシナリオIDを付ける・共有の設定は元に戻す・バッチの起動・店舗の読み替えなど）
- 起点の受注：購入は済み、入金が無いまま注文から1週間（7日）が過ぎている。5日後の準キャンセルの案内（UTS-18）を出していてもよい。UTS-18 で案内のあと入金が無かった受注から続けてもよい
  - 代表の行（T01・コンビニ決済・注文受領・ポイントを使っていない）：UTS-01 の T07（会員・コンビニ決済・ゆうパック・ポイントを使わない・2点以上）の終点
  - コンビニ決済・ポイントを使う（T02）：UTS-01 の T14（コンビニ決済・一部を使う・ゆうパック）の終点
  - 郵便振替・ポイントを使う（T03）：UTS-01 の T28（郵便振替・一部を使う・ゆうパック）の終点
  - 郵便振替・ポイントを使っていない（T04）：UTS-01 の郵便振替でポイントを使わない行は T01（同梱）だけで、同梱は同梱元とまとめる扱いがあり、キャンセルの確認と別になる。同梱でない注文でポイントを使わないものを、UTS-01 の T28 の条件でポイントの欄だけ「使わない」にして用意する（判断待ち 2）
  - 銀行振込・ポイントを使う（T05）：UTS-01 の T05（銀行振込・一部を使う・ゆうパケット）の終点
  - 銀行振込・ポイントを使っていない（T07）：UTS-01 の T31（銀行振込・ためる・ゆうパック）の終点
  - 出荷指示の行（T02・T04・T06）は、その前に UTS-21 を通して出荷指示にした受注（コンビニ決済は UTS-21 の T01、郵便振替は T02、銀行振込は T03 の終点）を使う
- システムの外で済んでいること：銀行・ゆうちょ銀行の入金データ（業務フロー3-1・3-2）に、この受注の入金が無いことを確かめている（コンビニ決済は手順2で EC 側から確かめる）
- 注文日を1週間前にする：注文日が7日以上前の受注は、試験で作った受注に限り、開発環境で注文日を書き換えて用意する（店頭受取の L4 と同じ扱い。2026-11-26 依頼者「おすすめどおり」。設計書に試験用の手段が無い）
- 用意するデータ（試験用の値。設計書の値ではない）
  - 会員：試験 二郎（`uts-20@example.test`）。「シナリオ試験カードA」を数量2で注文済み。在庫は注文のときに5から3に減っている。ポイントを使う行では、注文前のポイント残高が1,000、使用ポイントが300（注文後の残高は700）。注文日が8日以上前
  - 通販チームの担当者：管理画面で本店の受注を編集でき、手動メール通知を使える権限を持つ

| # | 操作する人と操作 | 期待値（画面で見えること） |
|---|---|---|
| 1 | 通販チーム：管理画面の受注管理の受注マスター（受注情報検索）で、対応状況に「注文受領」「入金待ち」を選び、注文日を見て、注文日から1週間（7日）を過ぎた受注を探す | 前提の受注が一覧に出る。対応状況は「注文受領」（銀行振込は「入金待ち」、出荷指示の行は「出荷指示」）。注文日が7日以上前。期限超過のチェックは人が行い、受注が自動でキャンセルになることはない（入金期限の自動管理は設計書0203でPh2へ見送り） |

| 6 | 通販チーム：会員管理の会員編集から「ポイント管理・履歴一覧」を開き、ポイント履歴を見る | 代表の行（ポイントを使っていない）：注文のポイント履歴は無く、残高は注文前と同じ。ポイントを使った行：使用ポイントの履歴が消え、残高が注文前の1,000に戻っている（二重に戻って1,300にならない）。まだ出荷していないので付与ポイントは無い |

## 終わったあとに確かめること

| 確かめる場所 | 期待値 |
|---|---|
| 入金が後から来たとき | 受注はすでにキャンセルなので、入金の確認の対象にしない。返金は UTS-02 の手順（入金後のキャンセル）で扱う（この試験では入金が無いまま通す） |
| スマレジのポイント連携 | 使用ポイントを戻した行は、スマレジのポイントも合う（値の突き合わせは UPT-07） |
