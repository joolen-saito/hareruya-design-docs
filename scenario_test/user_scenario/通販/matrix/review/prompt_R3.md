## 作り方の前提（成果物の制約）

- IPA「高信頼化ソフトウェアのための開発手法ガイドブック」(2010) 6.2節の表6-9（FL表）→表6-10（禁則表）→表6-11（直交表による組み合わせテストマトリクス）と同じ手順。直交表の代わりに、2因子間の組み合わせ（禁則を除く）を全部含むまで行を足す貪欲法で割り付けている。
- シナリオテストは「利用者が画面を操作して目的を果たせるか」を見る。因子は、お客様が購入の画面で選ぶもの・変わるもの。
- エラーになる値は正常な値と組み合わせず、例外表で1つずつ行に差し込む（資料6.3.2の例外シナリオの考え方）。
- 範囲：本店のオンラインショップで、通常の購入グループの会員が買うところまで。

  - 支払はクレジットカード決済（SPLINKS）と全額ポイント支払いだけ（裁定R0と依頼者回答）。コンビニ決済・郵便振替・銀行振込・店頭支払・代金引換は無い
  - 店頭受取・スムーズ店頭受取・支店は別業務。同梱は裁定R11で選択肢に出ない
  - 出荷（通販チームの操作）は別のマトリクスにする
- 設計書に無い決まりは、現行ソース pf-eccube3 で確かめて扱い欄に書いてある。

## 重点観点

1. **根拠の実在**：`fl_table.tsv`・`prohibitions.tsv`・`exceptions.tsv` の引用文が、書かれた設計書・シート（または現行ソース）に実在するか。言い換えで意味が変わっていないか。
2. **禁則の正しさ**：各禁則が正本どおりか。正本で起こりうる組み合わせを誤って禁じていないか。逆に、正本上ありえない組み合わせがマトリクスの行に残っていないか（例：配送方法と国、送料無料とゆうパケット、Small packetの上限金額、荷物の大きさ、全額ポイント支払いとクレジットカード、ポイントと金額の関係など）。行ごとに確かめること。
3. **因子・水準の抜け**：範囲内の購入の画面（商品一覧・商品詳細・買い物かご・ご注文方法指定・配送先の新規登録・決済~購入完了）で、お客様の選択や状態によって画面の表示や結果が変わるのに、因子・水準に入っていないもの。正本の引用を添えること。範囲外のもの（上に挙げた非会員・他の支払方法・店頭受取・支店・同梱・出荷）は指摘しない。
4. **水準の分け方**：同値分割・境界値として妥当か（例：商品金額合計の境界、数量の境界）。
5. **例外表**：差し込み先の条件が例外の成立に必要十分か（例：クレジットカード決済が必要な例外を全額ポイント支払いの行に差し込んでいないか）。期待値が正本どおりか。抜けている例外（購入の画面で利用者が起こしうるエラー・中断）は無いか。結合テスト層で確かめるもの（DBを書き換えないと起きないもの等）は対象外。
6. **網羅率の計算**：`build_matrix.py` の2因子間・3因子間網羅率の数え方が正しいか。禁則を含む組を分母から除いているか。割り付けが禁則を破っていないか。
