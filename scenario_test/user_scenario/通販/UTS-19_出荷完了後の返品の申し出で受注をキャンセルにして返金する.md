# UTS-19 出荷完了のあと、お客様の返品の申し出を受け、受注をキャンセルにして返金する

| 項目 | 内容 |
|---|---|
| 利用者 | お客様→（配送業者：システムの外）→通販チーム（管理画面）→SPLINKS（クレジットカード決済）／経理（振込による返金。システムの外）／会員管理のポイント付与→メール |
| 目的 | 商品を受け取ったお客様の返品の申し出（代金引換は受け取りの拒否・返送も）を受け、通販チームが受注をキャンセルにして在庫・使用ポイント・付与ポイントを戻し、支払方法に合わせて返金し、依頼者に報告する |
| 種類 | 正常（全部の返品・一部の返品・受け取りの拒否）。例外は「L3で変わるところ」の例外 |
| マトリクスの行 | `matrix_UTS-19/matrix.md` のT02（クレジットカード決済・受け取り後の返品・全部を返品・ポイントを使った・3つとも）。T01・T03〜T14と例外E1〜E8は「L3で変わるところ」 |
| 扱う受注 | 本店のECの受注 |
| もとのシナリオ | （新規）業務横断 UXB-03が集計側を確かめる |
| 業務フロー | 16 通販受注管理の5 お客様対応・8 SPLINKS返金処理・9 クレジットカード以外の返金対応。(tobe) の17には5・8・9が無いので16を元にする（2026-11-26 決定）。返品の手順そのものは業務フロー16・17に無く、受注情報編集のキャンセルで扱う（`matrix_UTS-19/README.md`） |

## 前提

- 共通の決まり：`../L4を流すときの共通の決まり.md` を先に読む（試験データの名前にシナリオIDを付ける・共有の設定は元に戻す・バッチの起動・店舗の読み替えなど）
- 起点の受注：UTS-01 の手順で出荷完了になっている受注（お客様は商品を受け取った）。購入するECは本店。受け取りから8日以内にお客様が返品を申し出た
  - 代表の行（T02・クレジットカード決済・全部を返品・ポイントを使った）：UTS-01 の T34（クレジットカード決済（カード情報を入れる）・一部を使う・ゆうパック）の終点（出荷完了）。数量は3で用意する（返品する点数を「1点だけ」と「3つとも」に分けるため）
  - 他の行：UTS-01 の行との対応は下の表。UTS-01 のマトリクスに無い組み合わせは、近い行のポイントの欄だけ変えて用意する（組み合わせ表は変えない。判断待ち 1）
  - 代金引換の受け取り拒否（T12・T14）：UTS-01 の T08（ポイントを使う）・T32（ためる）の購入のあと、出荷完了にした受注。配送業者が荷物を持ち帰り、通販チームに戻る（システムの外）
- システムの外で済んでいること：お客様から返品の申し出が届いている。商品に契約不適合があり、商品到着後8日以内であることを通販チームが確かめている（新実装の画面の案内。設計書・業務フローに返品の条件の定めは無い）。商品の返送・検品・在庫に戻すかの判断（物の流れ）は運用でシステムの外
- 用意するデータ（試験用の値。設計書の値ではない）
  - 会員：試験 三郎（`uts-19@example.test`）。「シナリオ試験カードA」（日本語・NM・単価1,000円（税込）・在庫は注文のとき10から7に減っている）を数量3で注文し、出荷完了になっている。全額ポイント支払いの行（T03・T04）は、保有ポイントをお支払い額（商品の金額＋送料など）以上（例：5,000ポイント）にしておき、お支払い額の全部をポイントで払う（使用ポイント＝お支払い額。0304 ご注文方法指定の使用ポイントの上限は保有ポイントと利用可能ポイントの小さい方で、新実装も保有ポイントを超える使用を止める）。注文前・注文後の残高と使用ポイントを控える。そのほかのポイントを使う行では、注文前のポイント残高が1,000、使用ポイントが300、出荷完了で付与されたポイントは受注情報編集の付与ポイントの値を控える。注文後・出荷完了後の残高も控える（控えた残高を「出荷完了後の残高」と書く）
  - 金額の前提：送料・手数料は注文のとき画面に出た値を控える。一部の返品（数量3→2）で減る金額は、1点分の1,000円（税込）。送料は変わらない前提で、変わるときは受注情報編集の保存後の合計と元の値の差額（判断待ち 2）
  - 通販チームの担当者：管理画面で本店の受注を編集でき、「ソニーペイメントサービス決済情報」の操作と手動メール通知を使える権限を持つ

## 操作の流れと期待値

| # | 操作する人と操作 | 期待値（画面で見えること） |
|---|---|---|
| 1 | お客様：商品を受け取ったあと、商品に契約不適合があるとして、返品を申し出る（メールまたは電話。システムの外） | 画面の変化は無い。通販チームに申し出が届く |
| 2 | 通販チーム：申し出が返品を受け付ける条件（契約不適合・商品到着後8日以内）に合うことを確かめる（システムの外） | 画面の変化は無い（条件に合わないときは例外E4） |
| 3 | 通販チーム：管理画面の受注管理の受注マスター（受注情報検索）で、ご注文番号を入れて検索し、受注情報編集を開く | 前提の受注が1件出る。対応状況は「出荷完了」。出荷日・送り状No.が入っている。「ソニーペイメントサービス決済情報」に、クレジットカード決済の取引ステータスと金額が出る（文言は記録。合否を付けない） |
| 4 | お客様：商品を通販チームへ返送する（配送業者。システムの外） | 画面の変化は無い |
| 5 | 通販チーム：同じ受注情報編集の「ソニーペイメントサービス決済情報」で「取消(返品)処理実行」を押す（「取消(返品)処理実行します。データを変更した場合は先に保存を行ってください。」の確認でOKを押す）（業務フロー8-2「SPLINKSで決済処理を実行」） | 「取消(返品)処理が完了しました」が管理画面に出る。取引ステータスが取り消し済みの表示になる（文言は記録）。SPLINKSの管理画面の見た目は記録（外部の画面は合否を付けない）。受注の対応状況はこの手順では変わらない（「出荷完了」のまま） |
| 6 | 通販チーム：受注情報編集の「変更後のステータス」で「キャンセル」を選び、「受注ステータス変更」を押す。確認のダイアログ「全キャンセル時、在庫数等は以下のように変動します。…在庫数：キャンセル分増加／使用ポイント：払い戻し／付与済みポイント：取り消し」でOKを押す | 「全キャンセルが完了しました。」が管理画面の上部に出る。「現在のステータス」が「キャンセル」になり、キャンセル日が入る。出荷完了からのキャンセルは新実装が許す（設計書 0203 は状態の制限を書かない） |
| 7 | 通販チーム：在庫変動履歴（商品「シナリオ試験カードA」の本店在庫）を見る | 在庫が7から10に戻っている。在庫変動履歴に「キャンセル時の在庫戻し 注文番号：（8桁の注文番号）」が残る。戻る時点は、返送の到着を待たずにキャンセルの操作の時点（物の流れは運用でシステムの外） |

| 9 | 通販チーム：依頼者（お客様の申し出を受けた通販チーム）に、対応完了を報告する（システムの外。業務フロー8-3） | 画面の変化は無い |

### 一部だけ返品する（C2・1点だけ。受注情報編集で数量を3から2にする）

一部の返品は、手順5・6が次に変わる。手順5（決済側）は支払方法ごと、手順6（受注の保存）は共通：

- 手順6（共通）：受注情報編集の明細の数量を3から2に直し、「受注情報を登録」を押す。確認のダイアログ「一部キャンセル時、在庫数等は以下のように変動します。…在庫数：キャンセル分増加／使用ポイント：変動なし／付与予定ポイント：再計算／付与済みポイント：変動なし」でOKを押す。「一部キャンセルが完了しました」が出て、対応状況は「出荷完了」のまま
- 手順7：在庫が1つ増える（7から8）
- 手順8：使用ポイントも付与済みポイントも変動なし（付与済みは、一部の返品では戻らない。0203 M05-11-MSG-016・017）。付与ポイントの戻りは、ポイント付与による返金（会員管理のポイント付与）で補う運用
- 手順10：処理状態は「出荷完了」のまま。手順11：対応状況「キャンセル」では出ない
