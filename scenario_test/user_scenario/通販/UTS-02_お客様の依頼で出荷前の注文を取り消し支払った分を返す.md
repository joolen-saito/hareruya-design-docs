# UTS-02 お客様の依頼で、出荷前の注文を取り消す、または一部を返金し、支払方法に合わせて支払った分を返す

| 項目 | 内容 |
|---|---|
| 利用者 | お客様（依頼はシステムの外）→通販チーム（管理画面）→SPLINKS（クレジットカード決済の請求キャンセル・減額）／経理（振込による返金。システムの外）／会員管理のポイント付与 |
| 目的 | お客様の依頼で、出荷の前の注文を全部取り消す、または一部だけ取り消し（返金し）、支払方法に合わせて支払った分を返し、在庫・使用ポイントを戻して依頼者に報告する |

| マトリクスの行 | `matrix_UTS-02/matrix.md` のT02（クレジットカード決済・出荷指示（入金済み）・全部を取り消す・ポイントを使った・3つとも取り消す）。T01・T03〜T19と例外E1〜E12は「L3で変わるところ」 |
| 扱う受注 | 本店のECの受注 |
| もとのシナリオ | 008・011・016・017・012・018・019・916のお客様の取り消し側 |
| 業務フロー | 16 通販受注管理の5 お客様対応（EC-CUBEでの対応）・8 SPLINKS返金処理（8-1〜8-3）・9 クレジットカード以外の返金対応（9-1〜9-9）。(tobe) の17には5・8・9が無いので16を元にする（2026-11-26 決定） |

## 前提

- 共通の決まり：`../L4を流すときの共通の決まり.md` を先に読む（試験データの名前にシナリオIDを付ける・共有の設定は元に戻す・バッチの起動・店舗の読み替えなど）
- 起点の受注：購入は済み、出荷の前（出荷完了になっていない）。お客様が取り消しまたは返金を依頼してきた。購入するECは本店
  - 代表の行（T02・クレジットカード決済・出荷指示（入金済み）・ポイントを使った）：UTS-01 の T34（クレジットカード決済（カード情報を入れる）・一部を使う・ゆうパック）の購入のあと、UTS-01 の手順で出荷指示リストを生成して「出荷指示」にした受注。数量は3で用意する（取り消す点数を「1点だけ」と「3つとも」に分けるため）
  - 他の行の用意：UTS-01 の行との対応は下の表。UTS-01 のマトリクスに無い組み合わせ（コンビニ決済・郵便振替・銀行振込・代金引換のうち、ポイントを使う／使わないの片方しか無いもの）は、近い行の条件でポイントの欄だけ変えて用意する（組み合わせ表は変えない。判断待ち 1）
  - 入金前の状態（T05・T07・T09・T11・T13・T15・T17・T18・T19）：支払うまで何もしない。入金済みの状態（T06・T08・T10・T12・T14・T16）：UTS-16・UTS-17 の手順で入金済みにする（コンビニ決済は入金通知、郵便振替・銀行振込は入金の確認）。出荷指示の状態：UTS-21（入金前）またはUTS-01の手順（入金済み）で出荷指示リストを作る
- システムの外で済んでいること：お客様から、取り消しまたは返金の依頼が届いている（業務フロー8-1・9-1。通販チームはラインワークス、TC東京はGメール、各店舗の大会は依頼フォーム）
- 用意するデータ（試験用の値。設計書の値ではない）
  - 会員：試験 次郎（`uts-02@example.test`）。「シナリオ試験カードA」（日本語・NM・単価1,000円（税込）・在庫は注文のとき10から7に減っている）を数量3で注文済み。全額ポイント支払いの行（T03・T04）は、保有ポイントをお支払い額（商品の金額＋送料など）以上（例：5,000ポイント）にしておき、お支払い額の全部をポイントで払う（使用ポイント＝お支払い額。0304 ご注文方法指定の使用ポイントの上限は保有ポイントと利用可能ポイントの小さい方で、新実装も保有ポイントを超える使用を止める）。注文前・注文後の残高と使用ポイントを控える。そのほかのポイントを使う行では、注文前のポイント残高が1,000、使用ポイントが300（注文後の残高は700）
  - 金額の前提：送料・手数料は注文のとき画面に出た値を控える（送料は配送方法・商品金額合計で変わる）。一部の取り消し（数量3→2）で減る金額は、1点分の1,000円（税込）。送料は変わらない前提で、変わるときは受注情報編集の保存後の「お支払い合計」と元の値の差額を使う（判断待ち 2）
  - 通販チームの担当者：管理画面で本店の受注を編集でき、「ソニーペイメントサービス決済情報」の操作と手動メール通知を使える権限を持つ

### 一部だけ取り消す（取り消しの範囲 C2・1点だけ。受注情報編集で数量を3から2にする）

一部の取り消しは、手順4・5が次に変わる。手順4（決済側の処理）は支払方法ごと、手順5（受注の保存）は共通：

- 手順5（共通）：受注情報編集の明細の数量を3から2に直し、「受注情報を登録」を押す。確認のダイアログ「一部キャンセル時、在庫数等は以下のように変動します。…在庫数：キャンセル分増加／使用ポイント：変動なし／付与予定ポイント：再計算／付与済みポイント：変動なし」でOKを押す。「一部キャンセルが完了しました」が出て、対応状況は変わらない
- 手順6：在庫が1つ増える（7から8）。在庫変動履歴の文言は設計書の別添に定めが無い見た目の記録（全部のときの「キャンセル時の在庫戻し」とは限らない）
- 手順7：使用ポイントは変動なし（300のまま、残高700）。付与予定ポイントが減る（受注情報編集の付与ポイントの表示で記録）
- 手順9：処理状態は元のまま（キャンセルにならない）。手順10：対応状況「キャンセル」では出ない
