# UTS-09 外部委託した発送の実績を取り込み、委託用の文面の出荷完了メールをお客様に届ける

| 項目 | 内容 |
|---|---|
| 利用者 | 外部の発送業者（システムの外）、通販チーム（管理画面）、お客様（メールとマイページ） |
| 目的 | 発売日に委託先から届いた追跡番号を取り込んで出荷完了にし、委託用の一部変えた文面の出荷完了メールをお客様に届けて、そのあとメールの文面を通常に戻す |
| 種類 | 正常 |
| マトリクスの行 | `matrix_UTS-09/` は無い（因子が1つも無い。テストは1本） |
| もとのシナリオ | SCN-TSUHAN-015 |

## 前提

- 共通の決まり：`../L4を流すときの共通の決まり.md` を先に読む（試験データの名前にシナリオIDを付ける・共有の設定は元に戻す・バッチの起動・店舗の読み替えなど）
- 購入するEC・扱う受注：本店のECの受注（会員が予約のBOXを買い、UTS-08 で委託の準備を済ませた注文）
- 前提に使う別のシナリオの終点：UTS-08 の T01（委託できる受注）の終点（会員 試験 六郎、ご注文番号を控えてある）。受注の状態は変わっていない（受注が出荷指示になる時点は業務フロー16の12にも設計書にも無く、期待値に入れない。通販 scenario_list.md 決着11）
- システムの外で済んでいること：委託先が発売日に集荷・発送を済ませ、追跡番号を晴れる屋に共有する
- 用意するデータ（試験用の値。設計書の値ではない）
  - 追跡番号：`UTS09TRACK0001`（委託先から届いた体で使う。出荷実績インポートは送り状No.を数値かどうか確かめず、文字列のまま保存する）
  - 通販チームの担当者：管理画面で受注管理と、設定のメール設定を使える権限を持つ
- メールの文面の変更は、委託用の一部変更を表す試験用の1行（`【委託発送・試験用】`）を本文の先頭に足す形で行う

## 操作の流れと期待値

| # | 操作する人と操作 | 期待値（画面で見えること） |
|---|---|---|
| 1 | 委託先：発売日に、発送の完了と追跡番号を晴れる屋に共有する（システムの外。業務フロー12-5） | 画面の変化は無い |
| 2 | 通販チーム：もらった追跡番号を使って、見出し「注文番号,出荷日,送り状No.」のインポートデータを作る。控えたご注文番号・発売日の出荷日（例：`2026/12/18 10:00`）・`UTS09TRACK0001` を1行で書く（システムの外。業務フロー12-6） | 画面の変化は無い |
| 3 | 通販チーム：管理画面の設定の「メール設定」で、テンプレートの一覧から出荷完了メール（日本語）のテンプレート「【販売/日】出荷完了」（件名「【晴れる屋】商品を出荷いたしました」。新実装の初期データ）を選び、本文の先頭に `【委託発送・試験用】` の1行を足して「登録」を押す（業務フロー12-7。インポート時のメール文を委託用に一部変更） | 「保存しました」が管理画面の上部に出て、同じテンプレートの編集画面に戻る。本文の先頭に足した1行が出ている |
| 4 | 通販チーム：出荷実績管理の「出荷実績登録CSVアップロード」画面で、「ファイルを選択」から手順2のCSVを選び、「CSVファイルのアップロード」を押す（業務フロー12-8） | 「登録が完了しました。」が管理画面の上部に出て、同じ取り込み画面に戻る（M05-26-MSG-003）。エラーは出ない |
| 5 | 通販チーム：受注情報検索で同じご注文番号を検索し、注文番号から受注情報編集を開く | 対応状況が「出荷完了」になっている。出荷日がCSVの値、送り状No.が `UTS09TRACK0001` になっている |
| 6 | お客様：メールの受信箱（`uts-08-t01@example.test`）を開く | 出荷完了メールが日本語で1通届いている。本文の先頭に `【委託発送・試験用】` の1行がある（顧客に出荷した旨のメールが送付される。業務フロー12-8）。店舗の代表アドレスにも控えが届く |
| 7 | お客様：会員でログインし、マイページの注文購入履歴を開く | 同じご注文番号の注文の処理状態が「出荷完了」の表示になっている |
| 8 | 通販チーム：メール設定で同じテンプレートを開き、本文の先頭の1行を消して元の文面に戻し、「登録」を押す（業務フロー12-9。インポート時のメール文を通常使用に変更） | 「保存しました」が管理画面の上部に出る。本文が手順3の前と同じ文面に戻っている |
