# UTS-03 ピックで一部の欠品が分かり、欠品登録してお客様に連絡し、残りを出荷する

| 項目 | 内容 |
|---|---|
| 利用者 | 通販チームの担当者（管理画面）→ お客様（欠品の連絡と出荷完了のメールを受け取る）→ 通販チームの担当者。在庫の承認者（在庫編集の承認）。ピック・梱包・集荷はシステムの外 |
| 目的 | ピックで商品が足りないと分かったら、受注情報編集の欠品登録で欠品数を登録し、お客様に欠品を連絡して、残りの数量で出荷し、出荷完了メールを届ける |
| 種類 | 正常（一部の欠品。全部の欠品は終点が設計書に無いので入れない） |
| もとのシナリオ | SCN-TSUHAN-914 |
| 業務フロー | 16 通販受注管理：2 発送準備業務（2-11 ピック作業）・4 発送業務（4-1 欠品や要望でイレギュラーがある受注の対応確認）・5-2 欠品の初回対応・6-1。在庫の一時的な0は 12 在庫管理の 8-3 |
| 区間の通し | 購入から出荷指示リスト生成・ピッキングリスト印刷までは UTS-01、出荷完了メールからあとは UTS-01 と同じ。通しは `通しシナリオ/UTH-05_*` の手順11-2 |

## 前提

- 共通の決まり：`../L4を流すときの共通の決まり.md` を先に読む（試験データの名前にシナリオIDを付ける・共有の設定は元に戻す・バッチの起動・店舗の読み替えなど）
- システムの外で済んでいること：ピッキングに使う商品の保管場所の整理。ピックして足りないと分かる作業（現物の確認）。集荷の手配
- 扱う受注：本店のECの受注。UTS-01 のマトリクスでは `matrix/matrix.md` の T19（会員・国内・ゆうパケット・ポイントを使わない・登録済みクレジットカード決済・カードの2つの状態を1つの注文で買う）に合う注文を、UTS-01 の手順（購入〜出荷指示リストの生成〜ピッキングリスト印刷）で用意する。購入直後の対応状況は「入金済み」。この注文は、購入したあと、欠品登録の前までを済ませた状態から始める（受注の対応状況は「出荷指示」）
- 用意するデータ（試験用の値。設計書の値ではない）
  - 会員：試験 一郎（`uts-03@example.test`、国内の住所を登録済み、ポイントは使わない）
  - 商品：本店で公開中、購入グループ「通常商品」。「シナリオ試験カードA」の「NM」（販売価格1,500円、在庫5）と「EX」（1,200円、在庫5）。注文は NM×2・EX×1（商品金額合計4,200円。ゆうパケットの送料を選べる金額）
  - 通販チームの担当者：管理画面にログインでき、受注管理（受注情報検索・受注情報編集・出荷指示リスト検索・手動メール通知・出荷実績インポート登録）と在庫管理を使える
  - 在庫の承認者：在庫編集を登録する担当者と別の担当者（在庫編集は承認を受けて確定する）
  - 欠品連絡の文面：メールテンプレート「【通販/日】欠品連絡」（件名「※要返信【晴れる屋】在庫表示の誤りについて」）が使える状態
- 購入後の在庫：NM=3（5−2）、EX=4（5−1）。注文番号（8桁）は購入完了画面で控える
