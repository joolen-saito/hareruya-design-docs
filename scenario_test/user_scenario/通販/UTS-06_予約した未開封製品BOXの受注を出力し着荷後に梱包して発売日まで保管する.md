# UTS-06 予約した未開封製品（BOXなど）の受注を出力し、着荷後に梱包して発売日まで保管する

| 項目 | 内容 |
|---|---|
| 利用者 | 通販チーム（管理画面）。ラベル印字アプリ・梱包・保管はシステムの外 |
| 目的 | 対応する予約受注（未開封製品）を受注マスターから検索して納品書・ラベルデータを出し、受注時のコメントやショップ用メモを確認し、出荷指示リストを作ってラベル・納品書をペアリングし、商品の着荷後にピック・振り分け・梱包して発売日前日まで保管する |
| 種類 | 正常（予約BOXの発売前の準備） |
| マトリクスの行 | 無い（`scenario_list.md` の L3 欄は「—」。受注データ確認作業は手順4に含める）。受注の購入直後の状態の違い（入金済み／注文受領）は「L3で変わるところ」 |
| 扱う受注 | 本店のECの受注 |
| もとのシナリオ | SCN-TSUHAN-013（前段） |
| 業務フロー | 16 通販受注管理の10 予約受注対応（未開封製品 BOXなど）の10-1〜10-4。(tobe) の17には10が無いので16を元にする（2026-11-26 決定） |

## 前提

- 共通の決まり：`../L4を流すときの共通の決まり.md` を先に読む（試験データの名前にシナリオIDを付ける・共有の設定は元に戻す・バッチの起動・店舗の読み替えなど）
- 起点の受注：UTS-04 の購入（未開封製品の予約・クレジットカード決済）の終点。対応状況は「入金済み」。発売日はまだ先で、商品はまだ着荷していない
  - 代表：UTS-04 の T08 の終点（BOX・クレジットカード決済）
- システムの外で済んでいること：ラベル印字アプリ（ラベルデータを取り込んで印字するアプリ）の用意
- 用意するデータ（試験用の値。設計書の値ではない）
  - 会員：試験 七郎（`uts-06@example.test`）。国内の住所。「【予約】シナリオ試験予約BOXR」（商品コード `UTS06-BOXR`・単価6,000円・購入グループは予約の販売グループ）を数量1で買った受注1件。注文備考に試験用の文言「試験用コメント」を入れて購入する。ご注文番号を控える
  - 通販チームの担当者：管理画面で受注管理（受注情報検索・出荷指示リスト）とカスタムCSVを使える権限を持つ
  - カスタムCSVの出力項目の設定：受注詳細カスタムCSV出力に、全項目を出す設定が1つある（設定の名前は環境による。UTS-08 の判断待ち 2 と同じ）
- 受注マスターで予約受注を探す保存検索の中身は店舗が画面で作る設定で、期待値にしない（通販 `scenario_list.md` 決着12）。ここでは購入商品コードで探す
- 発売前日・発売日の時刻は、時刻を待たずに手で行う（2026-11-26 決定）

## 操作の流れと期待値

| # | 操作する人と操作 | 期待値（画面で見えること） |
|---|---|---|
| 1 | 通販チーム：管理画面の受注管理の受注マスター（受注情報検索）で、「購入商品コード」に `UTS06-BOXR` を入れ、「検索する」を押す（業務フロー10-1「対応を行う予約受注をEC-CUBEの受注マスターから検索し」） | 「検索結果：1件が該当しました」。前提の受注が出る。対応状況は「入金済み」、支払方法は「クレジットカード決済」。購入商品コードは完全一致で絞られる（0203 受注情報検索 一覧(検索入力)） |
| 2 | 通販チーム：一覧の対象の受注にチェックを付け、「その他」から「納品書印刷（日本語）」を押す。続けて同じ受注にチェックを付けたまま、「その他」から「送り状出力」を押す（業務フロー10-1「受注マスターから納品書印刷・ラベルデータ用（送り状CSV）をダウンロード」） | 納品書が新しい画面に出る。ご注文番号・お届け先・購入商品「【予約】シナリオ試験予約BOXR」が載る。送り状（ラベルデータ）のCSVがダウンロードされる。どちらも受注は変わらない（出力だけ） |

| 6 | 通販チーム：受注情報検索で同じご注文番号を検索し直す | 対応状況が「出荷指示」になり、出荷指示日に今日の日時が入っている（0203 出荷指示リスト生成「対象受注のステータスを「出荷指示」に更新する。出荷指示日を現在時刻で登録する。」） |
| 7 | 通販チーム：出荷指示リストの一覧で手順5の行の「…」から「編集」を開き、受注の行にチェックを入れて「納品書印刷（日本語）」を押し、続けて「送り状CSVダウンロード」を押す。ラベル印字時に必要なコメント（「試験用コメント」）の対応をしながら、CSVをラベル印字アプリに取り込んでラベルを印字する（アプリ・コメントの対応はシステムの外。業務フロー10-3） | 日本語の納品書が出る。ご注文番号・お届け先・購入商品が載る。送り状CSVがダウンロードできる。ラベルが印字される（ラベルの見た目はシステムの外のアプリで、記録だけ） |

## L3で変わるところ（マトリクスの他の行・例外）

手順の番号は上の「操作の流れと期待値」。このシナリオに組み合わせ表は無い。一覧の「通る受注ステータス」にある、購入の直後の状態の違いだけを書く（支払方法による。購入直後の状態の定めは `scenario_list.md` の※1）。

| 場合 | 条件 | 変わるところ |
|---|---|---|
| 代表 | クレジットカード決済（購入直後は「入金済み」） | — |
| 注文受領の予約受注 | 全額ポイント・代金引換・郵便振替・コンビニ決済の予約受注（UTS-04 の T10〜T12・T14の終点。銀行振込のT13は「入金待ち」で、入金の確認前も同じ手順で出荷準備を進める） | 前提：UTS-04 の該当の行の終点。手順1：対応状況は「注文受領」（銀行振込は「入金待ち」）。支払方法はその行のとおり。手順2〜4：代表と同じ。手順5：入金が無くても、購入処理中・キャンセル以外なので生成の対象になる（0203 出荷指示リスト生成。UTS-21 と同じ）。手順6：対応状況は「出荷指示」になる。入金日は空のまま。手順9・10：代表と同じ。入金の確認からは UTS-16（郵便振替・銀行振込）・UTS-17（コンビニ決済）。予約商品は入金完了で予約入金のメールが届く |
| 受注時のコメントが無い受注 | 注文備考・ショップ用メモが空 | 手順4：対応が必要なコメントは無い。手順7：コメントの対応は不要で、そのまま印字する。そのほかは代表と同じ |

例外：このシナリオに組み合わせ表は無いので、例外の一覧も無い。
