# UCY-06 3時の買取集計が、前日の買取成立日だけを集め、15時の入庫や成立後の取消があっても合う

| 項目 | 内容 |
|---|---|
| 利用者 | 店舗チーム（店頭買取を成立させる。UKA-01・UKA-02）→ 買取集計のバッチ（システム。試験では手で起動する）→ 経理・店舗統括（管理画面の買取集計データで見る）→ 管理者（部門未設定・集計失敗のメール） |
| 目的 | 毎日3:00の買取集計バッチが、前日の00:00:00〜23:59:59に成立した店頭買取（ステータスは買取成立・入庫済み・未登録在庫あり・入庫待ち）だけを、店舗・成立日・部門ごとに集計し、前日の23:59台に成立した買取は入り、当日の0:00台に成立した買取は入らないことを確かめる。同じ日の集計が既にあれば削除して登録し直し（二重にならない）、15時に入庫待ちが入庫済みになっても数は変わらない |

## 前提

- 共通の決まり：`../L4を流すときの共通の決まり.md` を先に読む（試験データの名前にシナリオIDを付ける・共有の設定は元に戻す・バッチの起動・店舗の読み替えなど）
- バッチは時刻を待たず手で起動してよい（定時は毎日3:00。起動のしかたは「根拠」の欄のファイル）。「毎日3:00の自動実行」は、日付を指定せずに起動する（前日が対象になる）、「日付を指定して集計し直す」は、集計対象日（年-月-日）を指定して起動する。以降、流す日を「実行日」、その前の日を「前日」と呼ぶ
- バッチは環境の中の前日の店頭買取を全部集計する。ほかの試験の買取も一緒に集計される。合否は、この試験の部門（名前に UCY-06 を付けた部門）の行の値で付け、完了の表示と、ほかの部門の行・件数は記録にする
- 買取の用意：UKA-02 の T01 の終点（UKA-01 の T04 の終点を、経理が経理払い出し済みにした買取。本店・店舗ID 1・ステータス「入庫待ち」・買取金額1,900円・「店頭買取試験カードA」×2＝1,600円・「店頭買取試験カードB」×3＝300円）をこの試験専用に作る（商品名の後ろに UCY-06 を付ける）。部門は査定より前に付ける（買取の明細に査定のときの部門が残るため）：UAN-12 の準備P1と同じ手順で、部門「周期試験部門 UCY-06 α」「周期試験部門 UCY-06 β」を作り、カードAにα・カードBにβを付ける。この買取を「買取X」と呼ぶ
- 買取成立日時の書き換え：買取成立日時は買取成立のとき（経理払い出し済み）の今の時刻が入る。試験の時刻（前日の23:59台・当日の0:00台）にするため、試験で作った買取に限り、開発環境で書き換える（2026-11-26 の決まり）。保存の時刻の基準が画面の日時と違うので、書き換えたあとは必ず買取詳細の画面の日時で確かめる
- 買取成立のときに、成立日（実行日）の集計がその場で作られる（0205 ステータス変更）。書き換えのあとも実行日の集計に買取Xが残る場合があるので、この試験は実行日の集計を合否に使わず、記録にする（前日の集計だけで判定する）
- 買取集計データを見る担当者：経理（管理画面の店頭買取管理＞買取集計データを使える。既定の検索表示店舗は本店）。運用の担当者（バッチを起動できる）。管理者（部門未設定・集計失敗のメールを受け取る。例外E5）
- 画面の名前は新実装の表示で書く
