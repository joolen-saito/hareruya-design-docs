# ネット買取の15時の自動入庫の前後（業務周期）（UCY-08）

IPA「高信頼化ソフトウェアのための開発手法ガイドブック」(2010) の表6-9〜6-11と同じ手順で作る（FL表→禁則表→2因子間網羅の組み合わせ）。1行が1回ずつ流すテスト1本で、行の中の水準は条件ごとに1つ（2026-11-09 に scenario_list.md の L3 欄で「／」で並べていた値を分けた）。

## 範囲

- ネット買取が入庫待ちになる時刻（15時の前後）と、手動入庫の有無を別の水準にして、1行ごとに1回ずつ確かめる
- 入庫待ちになる経路（振込完了／個別入力商品の最後の実在庫登録）も別の水準
- 入庫済みになったあとの状況の変更は正常な値と混ぜず、例外 E1 で差し込む
- 店頭買取と同じ実行で処理される（UCY-07）。ネット買取は本店のEC在庫だけ

## 期待値（本文の記述を値ごとに分けただけ。新しい期待値は足していない）

| 入庫待ちになる時刻 | 手動入庫 | 期待値 |
|---|---|---|
| 15時の前 | しない | 15:00の実行時点で入庫待ちのものだけが入庫済みになり、本店のEC在庫が増えて在庫履歴が残る |
| 15時の前 | する | 手動の入庫と同時に動いても二重に入庫されない |
| 15時の後 | しない | 店舗チームが手動で入庫済みにしなければ翌日15:00まで入庫待ち |
| 15時の後 | する | 手動入庫も可能（0206） |

## 分ける前の記述

- シナリオ：ネット買取：15時の自動入庫の前後に入庫待ちになった買取の扱いを確かめる
- 起点：15時の前後に、ネット買取が入庫待ちになる（振込完了、または個別入力商品の最後の実在庫登録）
- 終点（目で確かめる結果）：15:00の実行時点で入庫待ちのものだけが入庫済みになり、本店のEC在庫が増えて在庫履歴が残る。15時の後に入庫待ちになったものは、店舗チームが手動で入庫済みにしなければ翌日15:00まで入庫待ち（手動入庫も可能。0206）。手動の入庫と同時に動いても二重に入庫されない。入庫済みになったあとは他の状況へ変更できない
- 通る状態：入庫待ち→入庫済み。振込依頼済み→入庫待ち
- L3 バリエーション：入庫待ちになる時刻が14:59台／15:00台。振込完了が15時の前／後（UNK-08）。実在庫登録が15時の前／後（UNK-12）。バッチ／店舗チームの手動。店頭買取と同じ実行で処理される
