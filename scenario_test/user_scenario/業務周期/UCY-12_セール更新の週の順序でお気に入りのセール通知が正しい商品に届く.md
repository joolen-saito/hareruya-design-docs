# UCY-12 セール更新の週（火曜の取り下げ・水曜の更新・水曜17:30の通知）の順序で、お気に入りのセール通知が正しい商品に届く

| 項目 | 内容 |
|---|---|
| 利用者 | トレードチーム・顧客戦略チーム（セール品担当。CSVでセールの取り下げ・更新）→ お気に入り通知のバッチ（システム。試験では手で起動する）→ 会員（メール） |
| 目的 | セール前の土日に選定し、火曜に取り下げ、水曜に新セールを登録する週の順序で、火曜に取り下げた商品は通常商品に戻り販売価格が基準価格になること、水曜の更新後は新セール品が「Sale」付きで出ること、水曜17:30のお気に入り通知は、その時点でセール中のお気に入りだけを会員ごとに1通にまとめて送り、取り下げた商品は入らず、取り下げずに残ったセール品は入ることを確かめる。セール中の商品が無い会員には送らない |
| 種類 | 正常（代表の1本）。ほかの条件は「L3で変わるところ」（このシナリオには組み合わせ表が無い。scenario_list.md の L3 欄の条件を、表外の具体例として書く） |
| マトリクスの行 | 組み合わせ表は無い（表外の具体例。代表＝水曜の更新が17:30の前・会員の住所が日本） |
| もとのシナリオ | 区間：UPC-01→UPC-07。取り下げ・新セール登録は UPC-01 の手順5〜11、通知は UPC-07 の手順1〜3と同じ。業務フロー11の1-1〜1-7（1-4に火曜・水曜）。0404 お気に入り商品セール通知 |

## 前提

- 共通の決まり：`../L4を流すときの共通の決まり.md` を先に読む（試験データの名前にシナリオIDを付ける・共有の設定は元に戻す・バッチの起動・店舗の読み替えなど）
- セールの取り下げ（火曜）・更新（水曜）・水曜17:30の通知は、時刻・曜日を待たず手で順に行う（2026-11-26 の決まり）。セールに期間（開始日・終了日）は無く、CSVを取り込んだときに切り替わる。曜日・時刻の確かめは、操作の順序（取り下げ→更新→通知）で行う。「更新が17:30の前／後」は、新セールのCSVを取り込む操作を通知のバッチの起動より前／後に行うことと読み替える
- 通知のバッチは環境の中の対象を全部処理する。ほかの試験の会員のお気に入りがセール中なら、その会員にもメールが出る。合否はこの試験の会員のメールと商品の値で付け、完了の表示の件数（何名に送ったか）は記録にする。ほかの人の受信箱は見ない。届かないことは、同じ処理で届くはずの別の会員（この試験の会員）に届いたのを見てから判定する
- 用意するデータ（試験用の値。設計書の値ではない。名前の後ろに UCY-12 を付ける）
  - 商品X「セール終了カードX UCY-12」：基準価格500円・セール中（販売価格400円。火曜に取り下げる）。商品Y「新セールカードY UCY-12」：基準価格300円・通常商品（水曜に新セールにする）。商品Z「継続セールカードZ UCY-12」：基準価格500円・セール中（販売価格400円。取り下げずに残る）。どれもシングルカード・日本語・NM・割引率「4」・公開・在庫2点（UPC-01 の準備P1〜P5と同じ作り方。Xのセール中は UPC-01 の P4 と同じ取り込み。Zも同じ）
  - 会員M：`ucy12-m@example.test`（本会員。国内の住所）。会員N：`ucy12-n@example.test`（本会員。国内の住所）。お気に入りは、日本語の側：Mは商品X・Y・Zの3つ、Nは商品Xだけ
  - 担当者：顧客戦略チームの担当者（商品管理＞商品CSV管理＞セール用価格変更CSVアップロードを使える）。運用の担当者（バッチを起動できる）
- 取り下げ用CSV・新セール用CSVは、UPC-01 の手順4と同じ見出し（商品ID・言語ID・販売価格・買取価格・セールフラグ・帯URL・タグ(ID)の7列）で作る。取り下げ用：商品Xの行（販売価格280・買取価格100・セールフラグ0・帯URL空・タグ空）。新セール用：商品Yの行（販売価格295・買取価格110・セールフラグ1・帯URLは試験用のURL・タグ空）
- 画面の名前・文言は新実装の表示で書く

## 判断待ち

開いた項目は無い。確かめたこと（記録）：

1. 通知の本文の「お気に入り登録商品一覧」のリンクは、本番のドメイン（`www.hareruyamtg.com`）に決め打ちされている（UPC-07 の記録と同じ）。リンクを開くことは合否に使わず、開発環境の画面を直接開いて確かめる（手順10）
2. 設計書 0404 B02-05 の概要欄は「セール開始日に送信ではなく、セール商品がある場合は毎日送信する」と書き、実行タイミング欄は「毎週水曜17:30」と書く。この L4 は実行タイミング欄に従い、通知は水曜にだけ動くことを期待値にした（手順4：火曜には動かさない）。食い違いは記録のみ
3. 取り下げ（火曜）→更新（水曜）の順序は、業務フロー11 ＃1-4 の「試験的に取り下げは火曜日・更新は水曜日に行っている」運用で、システムに曜日の制限は無い

設計書との食い違い（起票しない）：UPC-01・UPC-07 に記録済みのもの（成功の通知の文言、完了の表示の文言、メールのリンクの決め打ち）がそのまま当てはまる。上の記録2（0404 B02-05 の概要欄と実行タイミング欄）。
