# 店頭買取の買取集計バッチ（業務周期）（UCY-06）

IPA「高信頼化ソフトウェアのための開発手法ガイドブック」(2010) の表6-9〜6-11と同じ手順で作る（FL表→禁則表→2因子間網羅の組み合わせ）。1行が1回ずつ流すテスト1本で、行の中の水準は条件ごとに1つ（2026-11-09 に scenario_list.md の L3 欄で「／」で並べていた値を分けた）。

## 範囲

- 前日に成立した店頭買取（ステータスは買取成立・入庫済み・未登録在庫あり・入庫待ち。設計書 0406）が、店舗・成立日・部門ごとに集計される
- 成立の時刻（前日23:59台／当日0:00台）、実行のしかた（毎日3:00／日付を指定して集計し直す）、同じ日の集計の有無、15時の入庫の有無を別の水準にする
- 集計の対象にならないもの（経理払い出し待ち・管理者取消）、部門が無い商品、対象0件、集計・登録の例外は、正常な値と混ぜず例外で差し込む

## 期待値（本文の記述を値ごとに分けただけ。新しい期待値は足していない）

| 条件 | 期待値 |
|---|---|
| 成立が前日23:59台 | 前日の集計に含まれる |
| 成立が当日0:00台 | 前日の集計に含まれない（前日の00:00:00〜23:59:59の成立だけを集める） |
| 同じ日の集計が既にある | 削除して登録し直す |
| 15時に入庫待ちが入庫済みになる | 集計の対象ステータスの中なので数は変わらない |

## まとめた水準

なし（どの水準も結果が違う）。

## 分ける前の記述

- シナリオ：3時の買取集計が、前日の買取成立日だけを集め、15時の入庫や成立後の取消があっても合う
- 起点：毎日3:00に買取集計のバッチが動く
- 終点（目で確かめる結果）：前日の00:00:00〜23:59:59に買取が成立した店頭買取（ステータスは買取成立・入庫済み・未登録在庫あり・入庫待ち）が、店舗・成立日・部門ごとに集計される。同じ日の集計が既にあれば削除して登録し直す。15時に入庫待ちが入庫済みになっても集計の対象ステータスの中なので数は変わらない。部門が無い商品があれば、商品名と商品コードのエラーメールが届く
- 通る状態：買取ステータス：買取成立／入庫待ち／入庫済み（対象）。管理者取消（対象外）
- L3 バリエーション：成立が前日23:59台／当日0:00台。成立のあと管理者取消にする時刻が3時の前／後（3時の後に取り消した分は、日付を指定して集計し直さない限り前日の集計に残る。自動で直す記述は設計書・新実装に無い）。対象が0件のとき（登録しない）。日付を指定して集計し直す（同じ日の集計は削除して登録し直す）。集計・登録の例外は管理者へ通知
