# 業務周期：シナリオ一覧（UCY）

IPA「高信頼化ソフトウェアのための開発手法ガイドブック」6.3.2 は、シナリオを「業務フロー・業務周期・業務データ」の3つの軸で作るとしている。業務フローの軸は各業務の一覧で作った。この一覧は業務周期の軸で、次の3つを持つ。

1. `## 周期の表`：全業務の全シナリオを、周期（随時・日次・週次・月次・期末・年次・特定日）で並べた表
2. `## シナリオ一覧`：周期の境目で起きるシナリオ（UCY）。日付の切り替え、同じ時刻に動く複数のバッチ、受付・締めの直前と直後、月初。区間は既存のシナリオIDで参照する
3. `## サイクル`：1日・1週・1か月（と新弾の発売日）の中で、どのシナリオがどの順に回るか

## 読み方

- 周期は次のとおり決めた。**随時**＝起点が利用者・担当者の申し出や発生で、周期の定めが無いもの。**日次**＝毎日、または毎日の中で毎分・毎時・数分ごとに繰り返すもの。**週次**＝曜日や「1週間に1回」で決まるもの。**月次**＝月の何回目・何週目で決まるもの。**期末・年次**＝決算・年度・年末年始などで決まるもの。**特定日**＝発売日・開催日・注文日から数える期限など、特定の日付を起点にするもの
- 時刻・曜日・周期は、業務フロー（`scenario_test/markdown/NN_*.md` の行番号）、バッチの設計書（`excel_to_html/output/04xx` の「実行タイミング」）、新実装のソース（`ec-cube-enterprise/` の相対パスと行）の引用を根拠にした。業務フローと設計書・実装が食い違うときは設計書・実装を優先し、「設計書との食い違い」に書いた
- 休日・祝日を理由にした経路は作らない（通販の依頼者裁定R12「休日専用のテスト項目は不要」。`scenario_test/coverage/viewpoint_application/review/通販受注管理/rulings.md`）
- 階層は他の業務と同じ（L1 業務領域 → L2 シナリオ → L3 バリエーション → L4 ステップ）。この一覧はL2とL3まで。UCYの「もとのシナリオ」欄には、区間として通る既存のシナリオIDを書く（旧 SCN-* は無い）
- 分析・集計（UAN）と業務横断（UXB）は周期の表に載せた。UXBの周期は、起点の文と区間のシナリオの周期から決めた
