# 店頭買取の15時の自動入庫の前後（業務周期）（UCY-07）

IPA「高信頼化ソフトウェアのための開発手法ガイドブック」(2010) の表6-9〜6-11と同じ手順で作る（FL表→禁則表→2因子間網羅の組み合わせ）。1行が1回ずつ流すテスト1本で、行の中の水準は条件ごとに1つ（2026-11-09 に scenario_list.md の L3 欄で「／」で並べていた値を分けた）。

## 範囲

- 店頭買取が入庫待ちになる時刻（15時の前後）と、15時の手動入庫の有無を別の水準にして、1行ごとに1回ずつ確かめる
- 入庫待ちになる経路（経理の払い出し／個別入力商品の最後の実在庫登録）、買取を行った店舗（本店／支店）も別の水準
- 未登録在庫ありの買取は15時の対象外。入庫待ちの買取とは混ぜず、例外 E1 で差し込む
- 15時の後の棚戻し（UKA-07）が入庫済みでも出せることは UKA-07 のテストで確かめる（このマトリクスの外）

## 期待値（本文の記述を値ごとに分けただけ。新しい期待値は足していない）

| 入庫待ちになる時刻 | 15時の手動入庫 | 期待値 |
|---|---|---|
| 15時の前 | しない | 15:00の実行時点で入庫待ちのものだけが入庫済みになり、買取を行った店舗のEC在庫が買取数だけ増えて在庫履歴（登録元「買取自動入庫バッチ」・操作者「システム」）が残る |
| 15時の前 | する | 手動の入庫と同時に動いても二重に入庫されない |
| 15時の後 | しない | 手動で入庫済みにしなければ翌日15:00の自動入庫まで入庫待ちのまま |
| 15時の後 | する | 買取管理の権限があり編集可能店舗なら15時の後でも手動で入庫済みにできる（0205） |

## 分ける前の記述

- シナリオ：店頭買取：15時の自動入庫の前後に入庫待ちになった買取の扱いを確かめる
- 起点：15時の前後に、店頭買取が入庫待ちになる（経理払い出し、または個別入力商品の最後の実在庫登録）
- 終点（目で確かめる結果）：15:00の実行時点で入庫待ちのものだけが入庫済みになり、買取を行った店舗のEC在庫が買取数だけ増えて在庫履歴（登録元「買取自動入庫バッチ」・操作者「システム」）が残る。15時の後に入庫待ちになったものは、手動で入庫済みにしなければ翌日15:00の自動入庫まで入庫待ちのまま（買取管理の権限があり編集可能店舗なら15時の後でも手動で入庫済みにでき、0205）。手動の入庫と同時に動いても二重に入庫されない
- 通る状態：入庫待ち→入庫済み。経理払い出し待ち→入庫待ち。未登録在庫あり→入庫待ち
- L3 バリエーション：入庫待ちになる時刻が14:59台／15:00台。経理の払い出し済みが15時の前／後（UKA-02）。最後の実在庫登録が15時の前／後（UKA-04）。手動入庫（UKA-09）を15時ちょうどに押す。本店／支店。15時の後の棚戻し（UKA-07）は入庫済みでも出せる。未登録在庫ありは15時の対象外
