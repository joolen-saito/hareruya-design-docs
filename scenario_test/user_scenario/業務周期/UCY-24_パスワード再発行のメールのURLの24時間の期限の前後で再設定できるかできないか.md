# UCY-24 パスワード再発行のメールのURLの24時間の期限の前後で、再設定できるか・できないかを確かめる

| 項目 | 内容 |
|---|---|
| 利用者 | お客様（パスワード再発行を申し込んだ本会員）→ メール |
| 目的 | パスワード再発行を申し込み、再発行メールのURLを、発行から24時間以内に開くと再設定画面が開いてパスワードを変えられ、24時間を超えてから開くとエラー画面が出てパスワードは変わらないことを確かめる。画面を開いたまま24時間を超えて「変更する」を押したときも、同じエラーになる。期限が切れたあと、もう一度再発行を申し込むと、新しいメールで再設定できる。24時間の待ちは、試験で作った会員のリセットキーの有効期限を書き換えて表す |
| 種類 | 正常（代表の1本）。組み合わせ表は作らない（`../scenario_list.md` の L3 の欄にそう書いてある。条件は期限の前後だけ）。L3で変わるところ4本 |

## 前提

- 共通の決まり：`../L4を流すときの共通の決まり.md` を先に読む（試験データの名前にシナリオIDを付ける・共有の設定は元に戻す・バッチの起動・店舗の読み替えなど）
- このシナリオはバッチを使わない。リセットキーの有効期限は、メール配信（発行）から24時間（開発環境の設定の値。設定の場所は根拠の欄）。時計を進める方法は用意せず、24時間は待たない。試験で作った会員に限り、開発環境で、会員のリセットキーの有効期限の日時を書き換えてよい（共通の決まり。ほかの会員は書き換えない。UMB-06 の前提と同じ）
- 有効期限の判定：新実装は、有効期限が今の時刻以上（有効期限と同時刻なら有効）で、本会員のときだけ有効とし、超えたら無効（エラー画面）。期限ちょうどは、時計を秒まで合わせる手段が無いので試験しない（V4 の期限の1分前の確かめで代える）。「24時間を超えた」状態は、有効期限を今より1時間前の日時にして作る（発行から25時間たった状態に当たる）
- システムの外で済んでいること：なし（メールは試験用の受け口で読む）
- 用意するデータ（試験用の値。設計書の値ではない。名前の後ろにシナリオIDを付けて作る）
  - 会員：本会員（行ごとに1人、この試験専用）。代表 `ucy-24-v1@example.test`（お名前「試験 会員UCY24」。旧パスワード「Ucy24Old-2026a1」）。ほかの行は `ucy-24-v2@example.test`〜`ucy-24-v4@example.test`。UMB-01 の手順1〜7と UMB-02 の手順1〜2で、この試験専用に作る（パスワードは12文字以上・50文字以内で、英字と数字を1つ以上含む）。新しいパスワード（試験用の値）：「Ucy24New-2026b2」
  - メールの受け口：会員のメールアドレスのメールを読める手元の受け口。メールの再設定のURLは、開発環境のドメインになっているか確かめる。本番のドメインに決め打ちされているときは、URLの道筋の部分だけを開発環境のアドレスに替えて開く（記録する）
  - 手順の前に控える値：メールの再設定のURL（行ごとに別のURL）、メールを受けた時刻、書き換える前のリセットキーの有効期限の日時（発行日時の24時間後）
- 画面の名前・文言は新実装の表示で書く。設計書の文言と違えば、期待値は設計書の文言にし、新実装の文言が出たら不合格として記録する

## L3で変わるところ（組み合わせ表は無い。確かめを4本に分ける。1回ずつ流す）

手順の番号は上の「操作の流れと期待値」。行ごとに別の本会員を使う。

| 行 | 条件 | 変わるところ |
|---|---|---|
| V1 | 画面を開いたまま24時間を超えて「変更する」を押す→再発行して再設定 | 代表の行 |
| V2 | 24時間以内に開いて再設定する | 会員 `ucy-24-v2@example.test`。準備P1〜P2のあと、UMB-25 の手順1〜5のとおり（メール受信から24時間以内にURLを開き、メールアドレスと新しいパスワードを入れて「変更する」を押す）。期待値：「パスワードを変更しました。」が出て、ログイン状態にはならず、新しいパスワードでログインでき、旧パスワードではログインできず、同じURLは再び使えない |
| V3 | 24時間を超えてから開く（画面を開いていない） | 会員 `ucy-24-v3@example.test`。準備P1〜P2のあと、手順1・2・4を行わず、手順3（有効期限を今より1時間前に書き換える）だけ行い、手順5（URLを開く）・6・7を流す。期待値：UMB-06 の手順1〜5と同じ。手順5で「アクセスできません」「有効期限が切れているか、無効なURLです。」。パスワードは変わらず、もう一度再発行すると新しいメールで設定できる |

## 判断待ち

開いた項目は無い。確かめたこと（記録）：

1. 24時間の待ちは、開発環境の設定の値（24）で、時計を進める方法は用意せず、リセットキーの有効期限を書き換えて表す（`../scenario_list.md` の L3 欄どおり）
2. 画面を開いたまま24時間を超えて「変更する」を押したときの扱い：設計書 0306 は、フォーム送信時の確認についてExcel由来の機能仕様が期限切れのエラー画面（E-2）を、現行仕様の節が「404 Page Not Found」を書き、食い違う（UMB-06 の R1 に記録済み）。期待値は Excel 由来のE-2のエラー画面（優先順位：Excel 由来の欄が正）。新実装は、フォーム送信時にキーを検索し直してエラー画面を出す見込みで、画面の見え方は記録する
3. メールの再設定のURLが本番のドメインに決め打ちされているかは、流すときに確かめる（決め打ちなら開発環境の画面を直接開く。UMB-25 の前提と同じ）

設計書との食い違い（起票しない）：新しいものは見つからなかった（上の2は UMB-06 に記録済み）。
