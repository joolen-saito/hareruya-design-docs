## L3で変わるところ（組み合わせ表は無い。scenario_list.md の L3 の条件）

手順の番号は上の「操作の流れと期待値」。1回ずつ流す。

| L3の条件 | 変わるところ |
|---|---|
| 注文が15時締めの前／後 | 代表に入っている（注文P1が前、注文P2が後）。15時締めの前の注文は発売日の出荷のチェックシートに入る（出荷指示リストに入る）。15時締めの後〜23時の注文は、システムは止めず予約商品の注文として受け付ける（手順3・4）。チェックシートに載るかは運用で、システムの対象外 |
| 注文がCSV登録の前（22時台）／後（23時台） | 代表に入っている（注文P2が前、注文P3が後）。CSV登録の前の注文は予約商品の注文（単価は注文時の値）、後の注文は通常商品の注文（予約商品と同じ買い物かごで買えない制限が外れる。手順7） |
| 規格がセール外／セール中（UPR-03 の T02） | 別の予約シングル「【予約】シナリオ試験予約カードP2 UCY-11」を使い、UPR-03 の T02 と同じに、規格をセール用価格変更CSV登録で販売価格200円・セールフラグ「1」にしてセール中にしておく（UPM-02 の手順5と同じ操作）。手順5の同じ更新用CSV（基準価格・販売価格600円）を取り込むと、手順6：4規格の基準価格だけが更新され（NM 600円・SP 540円・MP 480円・HP 420円）、販売価格はセール中の値（NM 200円）のまま。手順7・8：CSV登録の後の注文P3の単価は、販売価格のとおり200円（600円ではない）。手順9：注文P1・P2の単価は注文時の値（P1・P2とも注文時の販売価格） |

## 判断待ち

開いた項目は無い。確かめたこと（記録）：

1. 15時締めの後〜23時に入った予約受注の扱い：設計書・業務フローに定めが無く、システムは受注を止めない。チェックシートに載るかはシート作成の運用で、システムの期待値は「受け付けられ、予約商品の注文として残る」まで（判断待ち 組3の5「適用外（運用）」と決着済み）
2. 予約BOX（未開封製品）の切り替えは業務フローに無い。UPR-03 の表外の確かめ（入口の違いとして仕組みの確認）に任せる

設計書との食い違い（起票しない）：UTS-04・UTS-05・UPR-03 に記録済みのもの（予約の購入期間の項目が設計書に無い、出荷指示を消したあとの受注の状態など）がそのまま当てはまる。
