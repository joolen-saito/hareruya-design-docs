## 範囲

- 申込の受付期間の開始・終了、キャンセル期限（前日23:59）、デッキ登録の締切、開催日の23:59:59、決済中30分、デッキ検索の開催日の条件の、それぞれの直前と直後を1行ずつ確かめる
- 「境目と操作の時点」は1つの因子にして、行ごとに値を1つだけにする（受付期間の開始・終了、締切などは境目の種類が違い、直前・直後で結果が違うので、境目と時点を組にして水準にした）
- 操作する人（因子B）：決済中30分以上の申込を照会して申込済み・削除にするのは10分刻みの決済処理中チェックバッチ（システム）なので、A11・A12 の行だけバッチ（B2）、ほかの行は会員（B1）。禁則 X1〜X15 で組む（2026-11-09 codex指摘）
- 同じ決済番号の申込が続き直前の照会が不成立のときは、正常な値と混ぜず例外 E1 で差し込む（A12 の行から）

## 分ける前の記述

- シナリオ：イベントの時刻の境目（申込の受付期間・前日23:59のキャンセル期限・デッキ登録の締切・開催日23:59:59・決済中30分）の直前と直後で、入口が出る・出ないを確かめる
- 起点：受付期間の開始・終了、デッキ登録の締切、イベント前日23:59、開催日23:59:59のそれぞれの直前と直後に、会員が操作する
- 終点（目で確かめる結果）：期間の開始・終了ちょうどは期間内として申込の導線が出る。期間外は申込がイベント詳細へ戻される。デッキ登録は締切を過ぎるとボタンが出ず画面も表示しない。開催日の23:59:59を過ぎると、マイイベントの処理状態が「イベント終了」になる。デッキ検索結果は、公開・大会デッキ・アーキタイプ設定済みで、大会の開催日が当日の23:59:59以下のものだけが載り、開催日が先の大会のデッキは載らない（開催後は公開条件を満たせば載り得る）。決済が30分以上決済中のままの申込は、10分刻みのバッチが成立なら申込済み、不成立なら削除にする。ただし同じ決済番号の申込が続き直前の照会が不成立だったときは、後続の申込は更新も削除もされず決済中のまま残る
- 通る状態：申込状況：決済中→申込済み／削除。マイイベントの処理状態：（申込済み）→イベント終了
- L3 バリエーション：受付期間の開始ちょうど／終了ちょうど／直後。キャンセルの操作が前日23:59／翌日0:00（入口が出ないときはお問い合わせフォーム。イベント管理の整理に従う）。日程の中止（UEV-08）は期限の前後を問わず店舗が決める（会員の申し出の期限とは別）。デッキ登録が締切の前／後、開催日の23:59:59／翌0:00。決済中が29分／30分以上。同じ決済番号の申込が2件続き照会が不成立（後続は決済中のまま）
