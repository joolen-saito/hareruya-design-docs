# USH-03 支店から在庫移動で届いたカードの戻しリストを出し、価格の区分ごとに棚へ戻す

| 項目 | 内容 |
|---|---|
| 利用者 | トレードチーム／店舗チーム（出庫・入庫先の担当。在庫移動振替一覧で戻しリストを出す）→ 棚へ戻す担当（現物の作業。システムの外） |
| 目的 | 支店から在庫移動で届き、ステータスが「移動中」の在庫移動について、在庫移動振替一覧から戻しリストCSVを出す。棚に戻すカードが、入庫先の店舗の高額商品閾値で決まる価格の区分ごと（「●●円未満」「●●円以上▲▲円未満」「■■円以上」）に並び、そのとおりに棚へ戻せる。出力しても在庫移動のステータスと在庫は変わらない |
| 種類 | 正常（1本。組み合わせ表は無い） |
| マトリクスの行 | 無い（2026-11-18 レビュー指摘で `matrix_USH-03/` を外した。移し先 `review/retired_matrix_USH-03/`）。1本のテストとして、移動中の在庫移動の戻しリストCSVを出す |
| L3（組み合わせ表） | 無い（理由は上のとおり。戻しリストの帳票の出し方〔入庫先の店舗・商品の種類・価格の区分〕の違いは数量・金額・在庫のDBの値に影響しない。出力の入力チェック〔振替・対象外の状態・権限のない店舗・複数店舗の同時選択・何も選ばない〕は結合テストに任せる） |
| もとのシナリオ | 無い（新規。業務フロー12の2-18「統合仕入れによる棚戻し」に対応する新システムの戻しリスト。0202 M04-33・M04-34）。15の2-3・3-13とは直接つながらない（scenario_list.md ※5） |

## 前提

- 共通の決まり：`../L4を流すときの共通の決まり.md` を先に読む（試験データの名前にシナリオIDを付ける・共有の設定は元に戻す・バッチの起動・店舗の読み替えなど）
- システムの外で済んでいること：支店から荷物が届き、解体・検品した（UZK-07の手順1と同じ）。棚へ戻すスペース・スリーブ・スプレッドシートが使える
- 起点の在庫移動：UZK-06 のT01の終点（ステータス「移動中」の在庫移動）と同じ形。ただし商品は3つ、1回の在庫移動にまとめる（在庫一覧で3商品の行にチェックを入れて「在庫移動登録」を押し、UZK-06 の手順2〜10と同じ手順で移動中まで進める）。複数の商品を1回の移動にできないときは、商品ごとに3回の在庫移動にし、手順2で3件すべてにチェックを入れる（入庫先の店舗は同じ）
  - 出庫元：試験支店（開発環境の試験用の支店。店舗ID・画面の名前を控えて読み替える）のEC-CUBE在庫。入庫先：本店バックヤード（トレードチーム宛の3F。UZK-06の店舗の対応）のEC-CUBE在庫。入庫先の店舗IDを控える
  - 商品（行ごとに価格の区分を変える。どれもNM・日本語のカード。商品登録・編集の UPM-02 の手順0・1と同じ手順で登録しておく）

| 商品コード | 商品名 | NMの基準価格 | 入庫先の閾値で決まる区分（閾値1＝980円・閾値2＝4800円のとき） |
|---|---|---|---|
| USH03-T01 | シナリオ試験仕入カードM01 | 970円 | 980円未満 |
| USH03-T02 | シナリオ試験仕入カードM02 | 980円 | 980円以上4,800円未満 |
| USH03-T03 | シナリオ試験仕入カードM03 | 4800円 | 4,800円以上 |

  - 出庫元の在庫は登録前に5・原価単価100円。移動点数は3商品とも3、出庫元の在庫は登録時に2へ減っている。入庫先の在庫は0。送り状No.は「USH03-0001」（試験用の値）。欠品なし
  - 商品コードの読み替え（共通の決まり「カードの商品コード」）：カードの商品コードは、カード商品CSVの登録のときにカードの情報から自動で作られ、指定できない。表の「USH03-T01」などは、このL4の中だけの呼び名。カードを登録したあと、商品一覧で商品名の呼び名（「シナリオ試験仕入カードM01」など）を入れて探し、NMの規格の実際の商品コードを控える。在庫一覧の検索・期待値の「USH03-T0x」は、控えた値に読み替える
  - 入庫先の店舗の高額商品閾値1〜3（店舗登録）：流す前に確かめて控える（開発環境の本店・支店は閾値1＝980円・閾値2＝4800円）。控えた値と上の基準価格で、どの区分に入るかを導く。閾値が違うときは、基準価格を閾値の区分をまたぐ値に変えて用意する
  - 3商品に、棚番号を設定しておく（商品管理＞棚番号登録/編集で棚番号を作り、商品の棚番号に付ける。商品管理＞商品CSV管理の棚番号更新CSVアップロードでもよい）。略称タグは付けない
  - 担当者：在庫管理＞在庫移動振替一覧を使え、入庫先の店舗（本店バックヤード）の編集権限がある（トレードチームの担当者）
  - 手順の前に控える値：3商品の出庫元・入庫先のEC-CUBE在庫、在庫移動のステータスと送り状No.
- 画面の名前・文言は新実装の表示で書く（設計書の「在庫移動・振替検索一覧」は画面の「在庫移動振替一覧」。完了の状態は設計書「入庫完了」・画面「入庫済み」。この試験は「移動中」だけを使う）
