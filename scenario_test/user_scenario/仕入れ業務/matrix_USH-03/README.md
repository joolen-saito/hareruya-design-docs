# 仕入れ業務の在庫移動の戻しリスト出力（USH-03）

IPA「高信頼化ソフトウェアのための開発手法ガイドブック」(2010) の表6-9〜6-11と同じ手順で作る（`通販/matrix/README.md` と同じ）。1行が、在庫移動を選んで戻しリストを出し、棚へ戻すまでの1本になる。

## 範囲

- 在庫移動・振替検索一覧から、移動を選んで戻しリストCSV・PDFを出すところまで（棚へ戻すのは現物の作業でシステムの外）
- 選べないもの（振替・対象外の状態・権限のない店舗・複数店舗・何も選ばない）は正常な値と混ぜず、例外の差し込み表で1つずつ差し込む
- 区分の閾値は入庫先の店舗で決まる。サプライ品は「サプライ」（D4）、閾値が未設定の店舗のカード、または基準価格が空のカードは空（D5。本店・支店でも起こる）で、価格帯（D1〜D3）は閾値のある店舗のカードだけ（禁則）

## 実装で確かめたこと（2026-11-03）

- 区分の判定：サプライなら「サプライ」。閾値が無ければ空。あれば「閾値1円未満」「閾値1円以上閾値2円未満」「閾値2円以上」。判定は基準価格（新実装の戻しリストの区分の判定）
- 棚番号は店舗ID1の本店だけ出し、並びも棚番順にするのは本店だけ。支店・本店バックヤードは出さず、棚番でソートしない（新実装の戻しリストの行の整形と並び順）
- 開発環境の閾値（DBダンプ 2026-09-07）：本店・支店は閾値1＝980円・閾値2＝4800円・閾値3は未設定。本店バックヤードは3つとも未設定
- 出力できる在庫移動の状態は、新実装では移動中・入庫承認待ち・入庫完了。設計書には書かれていない（`scenario_list.md` の食い違いに記載）
- 設計書の「●●円未満、●●円以上▲▲円未満、■■円以上、サプライ」は、閾値が2つのときの3区分。閾値3が設定されれば区分が増える（開発環境には無い）

## まとめた水準

なし（どの水準も処理が違う）。主な根拠：戻しリストCSVとPDFは出力の形式が違い、本店・支店・本店バックヤードは棚番号の出る出ないと閾値が違う。ピッキング区分（閾値未満・以上・サプライ・空）は区分の出力が違う。移動の状態は出力できる状態の記載が設計書に無く迷うため分けたまま。
