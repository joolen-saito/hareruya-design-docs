# UKA-01 お客様が査定を申し込み、店頭で査定・承諾して出金し、買取が成立する

| 項目 | 内容 |
|---|---|
| 利用者 | お客様（査定申込）→ 店舗チーム（受付での身分証の受け取りと照合はシステムの外。買取端末で身分証のスキャンと査定）→ レジ（スマレジ出金。出金の方法がレジのとき）／経理（振込依頼メールを受け取る。出金の方法が経理のとき） |
| 目的 | お客様が店頭買取の査定を申し込み、店舗チームが買取端末で本人確認の身分証をスキャンして査定し、お客様が承諾して出金の方法（レジ出金か、経理に頼む）が決まり、買取一覧のステータスが入庫待ち（個別入力商品があれば未登録在庫あり）または経理払い出し待ちになる。金額・明細・人・店舗が、お客様の画面・買取端末・管理画面・メール・CSVで一致する |
| 種類 | 正常（組み合わせ表の28行）＋例外26件 |
| マトリクスの行 | `matrix_UKA-01/matrix.md` のT01（受付＝会員でログイン・成年・適格請求書発行事業者に該当しない・出金＝経理に頼む・買取品＝登録済みの商品に個別入力商品を足す・買取店舗＝本店・ダブルチェック者＝入力する・本人確認書類＝学生証、会社員証）。T02〜T28は「L3で変わるところ」 |
| もとのシナリオ | SCN-KAITORI-001・003・004（前段）。業務フロー06の1-1〜1-9・3-1 |

## 前提

- 共通の決まり：`../L4を流すときの共通の決まり.md` を先に読む（試験データの名前にシナリオIDを付ける・共有の設定は元に戻す・バッチの起動・店舗の読み替えなど）
- システムの外で済んでいること：査定端末（MTGバイヤー。外部の Windows アプリ。試験端末を人が操作する）が使え、店舗チームの担当者のアカウントでログインできる。カードの現物とお客様の身分証の現物（試験用の見本）がある。レジ（スマレジ）は、出金の方法がレジの行（F1）だけ使う
- 店舗：開発環境では店舗を新しく作らない。本店は店舗ID 1（画面によって「Hareruya」「トーナメントセンター 東京」と出る。店舗識別子は tc）。支店の行（H2）は、流す前に既存の店舗から店舗識別子を持つ支店を1つ選び、店舗ID・画面の名前・店舗識別子を控えて、以降の「支店」を読み替える（担当者はその支店所属）
- 用意するデータ（試験用の値。設計書の値ではない）
  - 店舗チームの担当者：本店所属（H2の行は支店所属）で、査定端末にログインでき、管理画面の店頭買取管理を使える。もう1人、ダブルチェック者になる担当者（メンバーIDを控える）
  - 会員（A1の行）：試験用の本会員「店頭買取試験 太郎」（`uka01-member@example.test`。生年月日は成年の行は成年、未成年の行は実行日に17歳になる日）
  - 登録済みの商品（商品マスターに前もって登録。登録の手順は UKA-04 の手順2〜3と同じ）
    - 「店頭買取試験カードA」：日本語・NM・非Foilの規格。買取価格800円、基準価格1,500円。通販商品（日英のNM）
    - 「店頭買取試験カードB」：日本語・HPの規格。買取価格100円。店頭商品（日英のNMでない）
    - 買取価格は商品の規格の値で、査定端末の査定表に出る値を控える。控えた値が上の値と違うときは、試験で作った商品に限り、規格の買取価格を上の値に直してから流す（2026-11-26 決定。試験で作ったデータは開発環境で書き換えてよい）。以降の金額はこの値で書く
  - 個別入力商品（G2の行）：「店頭買取試験未登録カードZ」（商品マスターに無い商品。価格300円・枚数1・基準価格500円・部門は選択欄から1つ選ぶ。買取価格が基準価格より低いので追加できる）
  - 金額指定（G3の行）：「10円」を3枚（買取価格10円・基準価格100円）
  - 買取の内容：A×2枚・B×3枚（買取価格の合計1,900円）。G2の行は個別入力のZ×1（300円）を足して2,200円、G3の行は「10円」×3（30円）を足して1,930円。どれも10円単位で、10円単位への切り上げ（0506 店頭買取情報更新）で変わらない
  - 経理チームのメールアドレス：設定＞店舗設定＞追加システム設定の「査定払い出しの経理部門通知メールアドレス」が、試験で読める受け口になっている（出金の方法が経理の行）
  - 手順の前に控える値：なし（在庫は入庫のあと UKA-05・UKA-09 で確かめる）
- 画面の名前は新実装の表示で書く。管理画面のメニューは「店頭買取管理」＞「買取一覧」（業務フロー06の「買取一覧」。同じ中に「買取商品履歴」「買取集計データ」がある）
- 査定番号は「申込日（年月日）-店舗ID（2桁）-その日その店舗の連番（4桁）」の形（例：20261126-01-0001）。管理画面の買取一覧では「査定ID」、買取詳細では「査定番号」と出る

## L3で変わるところ（マトリクスの他の行・例外）
