# UKA-07 通販商品を、戻しリストを出して価格ソートし、スリーブに入れて棚に戻す

| 項目 | 内容 |
|---|---|
| 利用者 | 店舗チーム（EC-CUBE管理画面→棚戻し・システムの外）。買取管理を使え、編集可能店舗に買取店舗がある担当者 |
| 目的 | 入庫待ちまたは入庫済みの、棚戻し済みでない買取の通販商品（日英のNM）について、買取一覧から戻しリストPDFを出し、出力した買取に棚戻し済みの印が付く。金庫→キャビネット→通販棚の順に価格ソートし、スリーブとステータスシールを付けて棚に戻す |
| 種類 | 正常（組み合わせ表の4行）＋例外3件 |
| マトリクスの行 | `matrix_UKA-07/matrix.md` のT01（出力する買取のステータス＝入庫待ち・買取を行った店舗＝本店（棚番号あり）・棚戻し済みの印＝棚戻し済み（手動入庫の買取で、3-2の戻しリストCSVの出力で先に印が付いた。3-5の戻しリストPDFを同じ買取に出す））。T02〜T04は「L3で変わるところ」。出力形式はPDF（出力形式は結合テストへ。依頼者決定 2026-11-09） |
| もとのシナリオ | SCN-KAITORI-006（06版）。業務フロー06の1-11・1-15、2-1〜2-7 |

## 前提

- 共通の決まり：`../L4を流すときの共通の決まり.md` を先に読む（試験データの名前にシナリオIDを付ける・共有の設定は元に戻す・バッチの起動・店舗の読み替えなど）
- 起点の買取（どれも「店頭買取試験カードA」×2＝800円・日本語・NMの通販商品と、「店頭買取試験カードB」×3＝100円・日本語・HPの店頭商品を含み、買取金額1,900円・数量5。この試験専用に1件ずつ作る）
  - T01：UKA-02 の T01 の終点（本店・入庫待ち）に、UKA-09 の手順2（買取一覧で「戻しリストCSV」を出す）まで行い、棚戻し済みの印が先に付いた買取。ステータス「入庫待ち」・棚戻し済み「済み」
  - T02：UKA-01 の T03 の終点（支店・入庫待ち・棚戻し済み「未」）。流す前に既存の店舗から店舗識別子を持つ支店を1つ選び、店舗ID・画面の名前を控えて、以降の「支店」を読み替える
  - T03：UKA-05 の T01 の終点（本店・入庫済み・棚戻し済み「未」）
  - T04：UKA-09 の手順1〜4と同じ手順で、支店の買取（UKA-01 の T03 の終点＝支店・入庫待ち）を、先に戻しリストCSVを出し（手順2）、買取詳細の「入庫済みにする」で手動で入庫済みにした買取。ステータス「入庫済み」・棚戻し済み「済み」
  - 本店は店舗ID 1（画面によって「Hareruya」「トーナメントセンター 東京」と出る）
- 用意するデータ（試験用の値。設計書の値ではない）
  - 店舗チームの担当者：買取一覧で戻しリストを出せる。編集可能店舗に、起点の買取の買取店舗（T01・T03は本店、T02・T04は支店）がある
  - 店舗登録の高額商品閾値1〜3（本店・支店）：設定済み（戻しリストの商品仕訳の区分に使う）
  - 例外用：入庫待ち・入庫済み以外の買取（UKA-01 の T01の終点＝経理払い出し待ち。E1）、編集可能店舗に入っていない店舗の買取（E2）、本店と支店の2つの買取を同時に選べるユーザー（E3）
  - 手順の前に控える値：「店頭買取試験カードA」の買取店舗のEC在庫
- 画面の名前は新実装の表示で書く

## 操作の流れと期待値

| # | 操作する人と操作 | 期待値（画面で見えること） |
|---|---|---|
| 1 | 店舗チーム：管理画面の店頭買取管理＞買取一覧で、起点の買取を探し、買取詳細を開く。続けて、買取一覧の検索条件の「戻し未完了のみ表示」にチェックを入れて「検索する」を押す（業務フロー06 2-1「入庫済みまたは入庫待ちの棚戻し済みでない買取を選択」） | 買取詳細：T01は棚戻し済み「済み」、ステータス「入庫待ち」。「戻し未完了のみ表示」で検索すると、T01の買取は出ない（棚戻し済みのため）。T01は条件を外して探す。T02・T03は棚戻し済み「未」で、検索結果に出る |
| 2 | 店舗チーム：買取一覧で起点の買取にチェックを入れ、ダウンロードの「戻しリストPDF」を出す（業務フロー06 2-1「棚戻し業務用PDFを出力する」） | エラーにならず、戻しリストの画面が開く（T01・T04は棚戻し済みの買取にも出せる）。商品仕訳（店舗の高額商品閾値ごとの区分とサプライ）、ページング、作成日時、行番号、棚番号（列は出る。支店では値が空）、言語/状態、略称、色/R、数、商品名、価格（基準価格）、ブロックの商品個数の総計が出る。戻しリストには買取の実在庫の商品がすべて出る：A（言語/状態「JP/NM」・数2・価格はAの基準価格）とB（「JP/HP」・数3）。通販商品として戻すのはAの行。並びは、金額閾値の昇順（最後にサプライ）が最優先で、そのあと棚番（本店のみ）・言語（日→英）・状態（NM→HP）の順（例外E1〜E3） |
| 3 | 店舗チーム：「印刷する」を押す | ブラウザの印刷ダイアログが開く（「印刷する」のボタンは印刷範囲に含まれない） |
| 4 | 店舗チーム：買取詳細を開き直し、買取一覧で「戻し未完了のみ表示」にチェックを入れて検索し直す。在庫検索一覧でAを見る | 買取詳細の棚戻し済みが「済み」になる。「戻し未完了のみ表示」の検索結果に、この買取は出ない。ステータスは変わらない（T01・T02は入庫待ち、T03・T04は入庫済み）。AのEC在庫は、入庫待ち（T01・T02）では手順の前の値のまま（戻しリストを出しても入庫されない）、入庫済み（T03・T04）では入庫済みのとき増えた値のまま |
| 5 | 店舗チーム（システムの外）：2Fでの商品の保管場所に応じて価格ソートする。並び順ファイルの「色分け」にある「NM価格 or PLD価格」をコピーし、販売価格の列に「書式設定(R)」で貼り付けて、販売価格に付いた色で、金庫→キャビネット→通販棚の順に並べ替える（業務フロー06 2-5） | システムの外の作業。戻しリストのAの価格と、ファイルの色分けの価格が合う。画面の変化は無い |
| 6 | 店舗チーム（システムの外）：価格ソートが終わったら、それぞれに対応したスリーブ入れと、ステータスシールを貼る（業務フロー06 2-6） | システムの外の作業 |
| 7 | 店舗チーム（システムの外）：棚に戻す（業務フロー06 2-7） | システムの外の作業。通しの終点 |

## 終わったあとに確かめること

| 確かめる場所 | 期待値 |
|---|---|
| 買取一覧のステータス | 変わらない（棚戻し済みはステータスでなく印で持つ） |
| 15時の自動入庫（T01・T02） | 戻しリストを出した入庫待ちの買取も、入庫待ちのままなので15時のバッチの対象に残る（UKA-05。棚戻し済みの印は入庫の条件に入らない） |
| 店頭商品B | 戻しリストに出るが、置き場所は UKA-06 で在庫移動してスマレジに移した商品の分（この試験の買取では移さない）。通販商品として戻すのはAだけ |

## L3で変わるところ（マトリクスの他の行・例外）

| 行 | 条件（出力する買取のステータス・買取を行った店舗・棚戻し済みの印） | 変わるところ |

| T02 | 入庫待ち・支店（棚番号なし）・棚戻し済みでない（戻しリストを出すと印が付く） | 起点を UKA-01 のT03の終点（支店・入庫待ち）にする。手順1：棚戻し済み「未」で、「戻し未完了のみ表示」の検索結果に出る。手順2：棚番号の列は出るが、支店では棚番号の欄は空で、並びは棚番を使わない（0205「支店の場合は棚番のソートは行わない」。支店の高額商品閾値ごとの区分で並ぶ）。手順4：出力したあとに棚戻し済み「済み」。ステータスは「入庫待ち」のまま。手順4の在庫：支店のAは入庫前の値のまま |
