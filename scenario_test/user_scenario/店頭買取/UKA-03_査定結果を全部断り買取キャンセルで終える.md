# UKA-03 査定結果をお客様が全部断り、買取キャンセルで終える

| 項目 | 内容 |
|---|---|
| 利用者 | お客様（査定申込）→ 店舗チーム（受付・買取端末での査定とキャンセルの登録） |
| 目的 | 店舗チームが本人確認の身分証をスキャンして査定したが、お客様が査定結果を全部断り、買取一覧のステータスが「買取キャンセル」になる。通常の明細は残り、キャンセル商品情報は作らない。在庫は増えず、買取集計の対象にならない |
| 種類 | 正常（組み合わせ表の14行）＋例外4件 |
| マトリクスの行 | `matrix_UKA-03/matrix.md` のT01（受付＝会員・査定の経過＝中断せずに査定中のまま全品キャンセル・本人確認書類＝健康保険被保険者証）。T02〜T14は「L3で変わるところ」 |
| もとのシナリオ | SCN-KAITORI-008。業務フロー06の1-1〜1-6 |

## 前提

- 共通の決まり：`../L4を流すときの共通の決まり.md` を先に読む（試験データの名前にシナリオIDを付ける・共有の設定は元に戻す・バッチの起動・店舗の読み替えなど）
- システムの外で済んでいること：査定端末（MTGバイヤー。外部の Windows アプリ。試験端末を人が操作する）が使え、本店所属の店舗チームの担当者のアカウントでログインできる。カードの現物とお客様の身分証の現物（試験用の見本）がある
- 店舗：本店は店舗ID 1（画面によって「Hareruya」「トーナメントセンター 東京」と出る。店舗識別子は tc）。この試験は本店だけで流す（支店でも流れは同じで、UKA-01 の H2 が確かめる）
- 用意するデータ（試験用の値。設計書の値ではない）
  - 会員（A1の行）：試験用の本会員「店頭買取試験 太郎」（`uka03-member@example.test`。成年）。非会員の行は会員登録しない
  - 登録済みの商品：「店頭買取試験カードA」（日本語・NM・買取価格800円・基準価格1,500円）と「店頭買取試験カードB」（日本語・HP・買取価格100円）。UKA-01 の前提と同じ（買取価格が違うときは試験で作った商品に限り直してよい）
  - 買取の内容：A×2枚・B×3枚（査定表の合計1,900円）。お客様はこれを全部断る（一部キャンセルはフェーズ2で見送り）
  - 手順の前に控える値：「店頭買取試験カードA」「店頭買取試験カードB」の本店のEC在庫、買取集計データ（店頭買取管理＞買取集計データ）の集計日＝今日・買取店舗＝本店の合計
- 画面の名前は新実装の表示で書く。査定番号は「申込日（年月日）-店舗ID（2桁）-連番（4桁）」の形
