# UKA-04 未登録在庫のある買取に、商品を登録して実在庫登録し、入庫待ちにする

| 項目 | 内容 |
|---|---|
| 利用者 | 店舗チーム（商品登録→EC-CUBE管理画面で実在庫登録）。編集可能店舗に本店があるユーザー |
| 目的 | 商品マスターに無い商品を個別入力して買い取った買取（ステータス「未登録在庫あり」）に対して、商品マスターに商品を登録し、買取詳細の「実在庫情報登録」で個別入力商品に商品を紐づける。個別入力商品がすべて実在庫登録済みになると、ステータスが「入庫待ち」になる |
| 種類 | 正常（組み合わせ表の2行）＋例外1件 |
| マトリクスの行 | `matrix_UKA-04/matrix.md` のT01（個別入力商品の件数＝1件・登録するユーザー＝編集可能店舗を持つユーザー・起点の買取＝未登録在庫ありの買取）。T02（複数）は「L3で変わるところ」 |
| もとのシナリオ | SCN-KAITORI-004（後段）。業務フロー06の1-9（未登録在庫） |

## 前提

- 共通の決まり：`../L4を流すときの共通の決まり.md` を先に読む（試験データの名前にシナリオIDを付ける・共有の設定は元に戻す・バッチの起動・店舗の読み替えなど）
- 起点の買取（ステータス「未登録在庫あり」）
  - T01：UKA-02 の T02 の終点（UKA-01 の T01 の終点を、経理が経理払い出し済みにした買取）。本店（店舗ID 1。画面によって「Hareruya」「トーナメントセンター 東京」と出る）・買取金額2,200円・数量6。買取品は、登録済みの「店頭買取試験カードA」×2（買取価格800円）・「店頭買取試験カードB」×3（買取価格100円）と、個別入力商品「店頭買取試験未登録カードZ」×1（買取金額300円・基準価格500円）。この試験専用に1件作る
  - T02：T01と同じ形で、個別入力商品を2件にした買取。UKA-01 の T01 の手順10で、個別入力を「店頭買取試験未登録カードZ」（300円・枚数1・基準価格500円）と「店頭買取試験未登録カードY」（400円・枚数1・基準価格600円）の2回行い、UKA-02 の T02 の手順で経理払い出し済みにして作る。買取金額2,600円・数量7（UKA-01 の行は個別入力を1件にしているので、この2件は UKA-04 専用の用意）
- 用意するデータ（試験用の値。設計書の値ではない）
  - 登録担当（店舗チーム）：商品管理を編集でき、買取管理を使え、編集可能店舗に本店がある
  - 編集可能店舗を持たないユーザー（例外E1）：買取管理は使えるが、編集可能店舗に本店が無い
  - カード登録CSV・カード商品CSVの値（登録するカードごと）
    - Z：カード名「店頭買取試験未登録カードZ」（英名「Shop Test Unregistered Card Z」）、レアリティ・レイアウト・画像URL（英語）は必須の値を入れ、カードセットは既存のものから1つ選ぶ。商品は言語＝日本語、基準価格500円、買取価格300円、購入グループ名称「通常商品」、商品カテゴリは既存のカテゴリ1つ（番号は商品管理＞カテゴリ登録/編集の「CSVダウンロード」で調べる）、商品公開ステータス＝非公開。割引率は初期データの「割引率4」（名称「4」。状態NM・SP・MP・HPの4つがあり、率はNM 100%・SP 90%・MP 80%・HP 70%）で、規格は4件でき、基準価格はNM 500円・SP 450円・MP 400円・HP 350円（SP・MP・HPは基準価格×率を10円単位で切り上げ）
    - Y（T02のみ）：カード名「店頭買取試験未登録カードY」（英名「Shop Test Unregistered Card Y」）、基準価格600円、買取価格400円。そのほかはZと同じ
  - カード登録CSVは、カード商品CSVより前に取り込む。同じカードの商品が既にあると、カード商品CSVの行は飛ばされる（カードごとに別の名前を使う）
  - 手順の前に控える値：「店頭買取試験カードA」「店頭買取試験カードB」の本店のEC在庫、買取詳細の査定合計金額とステータス
- 画面の名前は新実装の表示で書く

## 操作の流れと期待値

| # | 操作する人と操作 | 期待値（画面で見えること） |
|---|---|---|
| 1 | 登録担当：管理画面の店頭買取管理＞買取一覧で、起点の買取を探して買取詳細を開く（業務フロー06の1-9） | ステータス「未登録在庫あり」。買取情報の個別入力商品情報にZ（商品コードは「-」・基準価格500円・買取金額300円・数量1・小計300円）があり、実在庫情報登録の列に「実在庫情報登録」ボタンが出る。実在庫情報にはAとBだけが出る（Zは入らない）。査定合計金額は2,200円（T02は2,600円）。ステータスは「未登録在庫あり」のままで、15時の自動入庫の対象にならない |
| 2 | 登録担当：管理画面のカード管理＞カード一覧の「CSV取り込み」を押し、カードCSVアップロードの画面で、Zの1行を書いたカード登録CSV（拡張子CSV）を選んで「CSVファイルをアップロード」を押す（業務フロー06の1-9「商品マスターに商品を登録し」。T02はZとYの2行） | 「登録が完了しました。」が出る。カード一覧に「店頭買取試験未登録カードZ」が出る。カード編集画面で、カードセットとの紐づけが確かめられる。カード詳細ID（カード編集画面の「カード詳細ID: 数字」）を控える |
| 3 | 登録担当：商品管理＞商品CSV管理＞カード商品CSV登録を開き、「雛形ファイルダウンロード」の見出しと同じCSVで、手順2のカード詳細IDを入れた1行を書いたカード商品CSVを選んで「CSVファイルをアップロード」を押し、確認の画面（「カード商品CSVをアップロードします。よろしいですか？」）で「確認」を押す。取り込みが終わったことを、画面のCSVインポート履歴で確かめる | 「CSVファイルをアップロードしました」が管理画面の上部に出て、カード商品CSV登録の画面に戻る。CSVインポート履歴に、ファイル名・アップロード日時・作業者の行が1件増える。エラーの案内は出ない |
| 4 | 登録担当：商品管理＞商品一覧で「店頭買取試験未登録カードZ」を検索し、商品編集画面と規格設定を開く | 検索結果に1件。規格は4件（NM・SP・MP・HP）で、基準価格はNM 500円・SP 450円・MP 400円・HP 350円、在庫0。NMの商品コードを控える |
| 5 | 登録担当：手順1の買取詳細を開き、個別入力商品情報のZの行の「実在庫情報登録」を押す。商品情報登録のモーダルで、商品名・商品ID・商品コードの欄に「店頭買取試験未登録カードZ」を入れ、「検索」を押す。検索結果のZの行で、商品コードのプルダウンから手順4で控えたNMの規格（表示は「商品コード/言語/状態/基準価格」）を選び、「決定」を押す | 管理画面の上部に「実在庫登録が完了しました。」が出て、買取詳細に戻る。個別入力商品情報のZの行：商品コードが選んだNMの商品コードになり、実在庫情報登録の列が「実在庫登録済み」になる。実在庫情報にZ（NM・基準価格500円・買取金額300円・数量1）が増える。実在庫の小計の合計（A 1,600円＋B 300円＋Z 300円＝2,200円）が査定合計金額と一致する。個別入力商品はZだけなので、ステータスは「入庫待ち」になる（ステータス変更履歴の先頭に「入庫待ち」が増える） |
| 6 | 登録担当：買取一覧で同じ買取を探す。在庫検索一覧で「店頭買取試験未登録カードZ」を見る | ステータス「入庫待ち」。Zの在庫は0のまま（入庫は15時の自動入庫＝UKA-05、または入庫済みボタン＝UKA-09 のあと） |

## L3で変わるところ（マトリクスの他の行・例外）

手順の番号は上の「操作の流れと期待値」。1回ずつ流す。

| 行 | 条件（個別入力商品の件数・登録するユーザー・起点の買取） | 変わるところ |
|---|---|---|
| T01 | 1件・編集可能店舗を持つユーザー・未登録在庫ありの買取 | 代表の行（個別入力はZ×1） |
| T02 | 複数（一部だけ登録済みの間は未登録在庫ありのまま。すべて登録すると入庫待ち）・編集可能店舗を持つユーザー・未登録在庫ありの買取 | 起点を、個別入力がZ×1とY×1の2件の買取にする（査定合計金額2,600円。個別入力商品情報に2行、どちらも「実在庫情報登録」ボタン）。手順2：カード登録CSVにZとYの2行を書く。手順3：カード商品CSVにZとYの2行を書く。手順4：ZとYの両方を確かめ、それぞれのNMの商品コードを控える。手順5：まずZだけ実在庫登録する。「実在庫登録が完了しました。」が出て、Zの行が「実在庫登録済み」になり、実在庫情報にZが増えるが、Yの行には「実在庫情報登録」ボタンが残り、ステータスは「未登録在庫あり」のまま（履歴に「入庫待ち」は増えない。15時の自動入庫の対象にならない）。続けてYを実在庫登録する（Yの検索・NMの選択・「決定」）。「実在庫登録が完了しました。」が出て、実在庫情報にYが増え、実在庫の小計の合計（A 1,600円＋B 300円＋Z 300円＋Y 400円＝2,600円）が査定合計金額と一致し、ステータスが「入庫待ち」になる。手順6：ZとYの在庫は0のまま |
