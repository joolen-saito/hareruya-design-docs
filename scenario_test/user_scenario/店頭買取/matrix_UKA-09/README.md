# 15時を待たない手動の入庫済み（UKA-09）

IPA「高信頼化ソフトウェアのための開発手法ガイドブック」(2010) の表6-9〜6-11と同じ手順で作る。手順と表の役割は `../matrix_UKA-01/README.md` と同じ。

## 範囲

- 入庫待ちの買取を、15時の自動入庫の前に、入庫の権限者が買取詳細の入庫済みボタンで入庫済みにし、EC在庫が増え、戻しリストを出した買取が棚戻し済みになるまで
- 編集可能店舗を持たないユーザー（エラー）、個別入力商品の実在庫登録が残っている買取（入庫済みにできない）は例外

- 2026-11-09：本文に同じ条件の値を並べていた（1回ずつ流すテストにするため）ので、値ごとに別の行・例外に分けて作った。期待値は 店頭買取/scenario_list.md の本文にあるものを水準ごとに分けただけで、新しい期待値は足していない
- 禁則：無い

## 作り直し

```
nice python3 -I scenario_test/user_scenario/tools/build_matrix.py scenario_test/user_scenario/店頭買取/matrix_UKA-09
```


## 外した因子・水準（2026-11-09 依頼者決定：画面の操作の違い）

業務の流れが分かれない画面操作の違いは、シナリオテストの組み合わせ表に入れず結合テストに任せる（依頼者決定）。この表から外した：

- 外した因子：C 入庫のしかた（買取詳細の入庫済みボタンの1水準）
- 理由：入口の違い（決定2）。対象の水準が入庫済みボタン1つだけ（CSVで入庫する経路は採らない）で、組み合わせの軸にならない。
- 外したあとの前提（代表）：入庫は買取詳細の入庫済みボタンで行う。
- 外した例外：なし
- 行数：1行 → 1行（`matrix.tsv`）。2因子間の網羅は100%
- 上の本文に、外した因子を使った説明（因子の一覧・期待結果の表・まとめた水準の表）が残る場合は、経緯の記録として残してある。いまの表は `fl_table.tsv` が正
