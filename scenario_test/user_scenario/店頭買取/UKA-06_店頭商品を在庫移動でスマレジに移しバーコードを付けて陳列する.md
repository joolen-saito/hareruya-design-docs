# UKA-06 店頭商品を、買取履歴から在庫移動でスマレジに移し、バーコードを付けて店頭に陳列する

| 項目 | 内容 |
|---|---|
| 利用者 | 店舗チーム（EC-CUBE管理画面→スマレジ→店頭）。買取管理と在庫移動を使え、編集可能店舗に買取店舗がある担当者 |
| 目的 | 入庫済みになった買取の店頭商品（日英のNMでない商品・サプライ）を、買取商品履歴・買取商品一覧CSVで確かめ、在庫移動・振替でEC-CUBEの在庫区分からスマレジの在庫区分へ移し（ECの中の在庫区分の移動）、バーコードを貼って店頭に並べる |
| 種類 | 正常（組み合わせ表の3行） |
| マトリクスの行 | `matrix_UKA-06/matrix.md` のT01（買取価格・種類＝1円〜250円・買取のステータス＝入庫済み・商品の売り先＝店頭商品）。T02（250円より高い）・T03（サプライ）は「L3で変わるところ」 |
| もとのシナリオ | SCN-KAITORI-005。業務フロー06の1-11〜1-14 |

## 前提

- 共通の決まり：`../L4を流すときの共通の決まり.md` を先に読む（試験データの名前にシナリオIDを付ける・共有の設定は元に戻す・バッチの起動・店舗の読み替えなど）
- 起点の買取（ステータス「入庫済み」）：UKA-05 の T01 の終点（UKA-02 の T01 の終点を15時の自動入庫で入庫済みにした買取）。この試験専用に1件作る。買取店舗は本店（店舗ID 1。画面によって「Hareruya」「トーナメントセンター 東京」と出る）
  - T01：買取品は「店頭買取試験カードA」×2（日本語・NM・800円。通販商品）と「店頭買取試験カードB」×3（日本語・HP・買取価格100円。店頭商品）。買取金額1,900円・数量5。UKA-05 の T01 の終点そのまま
  - T02：UKA-05 の T01 の終点と同じ形（UKA-01 の T04 → UKA-02 の T01 → UKA-05 の T01）で、Bの代わりに「店頭買取試験カードC」（日本語・HP・買取価格600円）×2を査定表に入れた買取。買取金額2,800円（A 1,600円＋C 1,200円）・数量4
  - T03：同じ形で、Bの代わりに「店頭買取試験サプライD」（グッズのサプライ・買取価格200円）×5を入れた買取。買取金額2,600円（A 1,600円＋D 1,000円）・数量7
  - 店頭商品の買取価格は、査定表に出る値を控える。条件の価格帯（B＝1円〜250円、C＝250円より高い）に入らないときは、試験で作った商品に限り、規格の買取価格を直してから買取を作る（2026-11-26 決定）
  - Cは、UKA-04 の手順2〜3と同じ手順（カード登録CSV→カード商品CSV）で前もって登録する。サプライDは、グッズ商品CSVで前もって登録する（商品コード「UKA06-D」・購入グループ名称「通常商品」・商品カテゴリは既存のカテゴリ1つ。UPR-04 の手順3〜4と同じ手順）
  - 買取価格が0円の商品は、買取明細にならない前提でこの流れに入れない（`scenario_list.md` ※4）
- 用意するデータ（試験用の値。設計書の値ではない）
  - 店舗チームの担当者：買取管理を使え、在庫移動・振替を登録・確定でき、編集可能店舗に本店がある
  - 手順の前に控える値：店頭商品（T01はB）の本店のEC在庫・総原価・原価単価、本店のスマレジ在庫（在庫区分スマレジ）。期待値の金額は、起点の買取（UKA-05 の終点）が入庫済みになったあとの値、つまりBの本店のEC在庫3・総原価300円（T02のCは在庫2・総原価1,200円、T03のDは在庫5・総原価1,000円）から計算した値。この値になるよう、店頭商品の本店のEC在庫・総原価は、UKA-05 の入庫の前に0にしておく（試験で作った商品に限る）
- 画面の名前は新実装の表示で書く。スマレジ側の在庫は期待値に入れない（EC-CUBEからスマレジへの在庫連携は行わない。2026-11-18 レビュー指摘。在庫管理 UZK-08 と対）
