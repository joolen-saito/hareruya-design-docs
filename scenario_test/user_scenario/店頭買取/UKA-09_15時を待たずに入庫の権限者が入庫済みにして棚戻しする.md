# UKA-09 15時を待たずに、入庫の権限者が入庫済みにして棚戻しする

| 項目 | 内容 |
|---|---|
| 利用者 | 店舗チーム（戻しリストの出力）→ 入庫の権限者（EC-CUBE管理画面。買取管理の権限があり、買取を行った店舗の編集可能店舗を持つユーザー） |
| 目的 | 入庫待ちの買取を、15時の自動入庫を待たずに入庫したいとき、買取詳細の「入庫済みにする」で入庫済みにし、EC在庫を買取数量の1回分だけ増やす。15時のバッチには二重に入庫されない。戻しリストを出した買取は棚戻し済みになる |
| 種類 | 正常（組み合わせ表の1行）＋例外2件 |
| マトリクスの行 | `matrix_UKA-09/matrix.md` のT01（入庫済みボタンを押すユーザー＝買取を行った店舗の編集可能店舗を持つユーザー・入庫前の買取＝入庫待ち（15時の自動入庫の前）・入庫のしかた＝買取詳細の入庫済みボタン） |
| もとのシナリオ | SCN-KAITORI-007。業務フロー06の3-1〜3-5（手動入庫） |

## 前提

- 共通の決まり：`../L4を流すときの共通の決まり.md` を先に読む（試験データの名前にシナリオIDを付ける・共有の設定は元に戻す・バッチの起動・店舗の読み替えなど）
- 起点の買取：UKA-02 の T01 の終点（UKA-01 の T04 の終点を、経理が経理払い出し済みにした買取。業務フロー06 3-1「買取」は UKA-01・UKA-04 が済ませた状態）。本店（店舗ID 1。画面によって「Hareruya」「トーナメントセンター 東京」と出る）・ステータス「入庫待ち」・棚戻し済み「未」・買取金額1,900円・数量5（「店頭買取試験カードA」×2＝800円・「店頭買取試験カードB」×3＝100円）。この試験専用に1件作る
- 15時の自動入庫より前の時刻に流す（手順4で入庫済みボタンを押す。手順7のバッチは手で起動する）
- 用意するデータ（試験用の値。設計書の値ではない）
  - 店舗チームの担当者：買取一覧で戻しリストを出せる（編集可能店舗に本店がある）
  - 入庫の権限者：買取管理の権限があり、編集可能店舗に本店がある
  - 編集可能店舗に本店が無いユーザー（例外E1）：買取管理は使える
  - 例外E2の起点の買取：ステータス「未登録在庫あり」の買取（UKA-02 の T02の終点。個別入力商品の実在庫登録が残っている）
  - 手順の前に控える値：AとBの本店のEC在庫・総原価・原価単価、買取詳細の入庫日時（空）・最終更新者・ステータス変更履歴の行数
- 手動入庫は買取詳細の「入庫済みにする」で行う（0205。依頼者決定 2026-11-07「自動入庫だけで増やす」）。業務フロー06の3-3「在庫インポート用CSV作成」・3-4「在庫変更CSVを登録し、買取商品の入庫を行う」は、同じ商品を買取の入庫とCSVで二重に増やさないため通さない（`scenario_list.md` の設計書との食い違いに記録済み）
- 画面の名前は新実装の表示で書く

## 操作の流れと期待値

| # | 操作する人と操作 | 期待値（画面で見えること） |
|---|---|---|
| 1 | 店舗チーム：管理画面の店頭買取管理＞買取一覧で、起点の買取を探して買取詳細を開く。在庫管理＞在庫一覧で、AとBの本店のEC在庫・総原価・原価単価を控える | ステータス「入庫待ち」、入庫日時は空、棚戻し済み「未」。AとBの在庫は控えた値 |
| 2 | 店舗チーム：買取一覧で、検索条件の「戻し未完了のみ表示」にチェックを入れて「検索する」を押し、一覧に出た手順1の買取にチェックを入れる。ダウンロードの「戻しリストCSV」を出す（業務フロー06の3-2。棚戻し業務用CSVの出力） | 「戻し未完了のみ表示」の検索結果に手順1の買取が出る（入庫待ちで棚戻し済みでないため）。CSVに、AとBの行が出る。列は、ピッキング区分・棚番号（本店のみ）・言語/状態・略称・色/R・数・商品名・基準価格。Aの数＝2、Bの数＝3、言語/状態はAが「JP/NM」、Bが「JP/HP」の形。ステータスは「入庫待ち」のまま |
| 3 | 店舗チーム：買取詳細を開き直す。続けて、買取一覧で「戻し未完了のみ表示」にチェックを入れて検索し直す | 買取詳細の棚戻し済みが「済み」になる（出力したので棚戻し済みの印が先に付く）。「戻し未完了のみ表示」の検索結果に、この買取は出ない |
| 4 | 入庫の権限者：買取詳細の「入庫済みにする」を押す（15時より前） | 管理画面の上部に「保存しました」が出る。ステータスが「入庫済み」になり、入庫日時が入る。買取一覧の最終更新者は、押したユーザーになる（0205 買取詳細）。ステータス変更履歴に「入庫済み」が増える（例外E1・E2） |
| 5 | 入庫の権限者：在庫管理＞在庫一覧で、AとBを検索して本店のEC在庫・総原価を見る。在庫履歴一覧で、AとBの商品コードを検索する（業務フロー06の3-4に当たる入庫の確かめ） | AのEC在庫が2、BのEC在庫が3増え（買取数量の1回分だけ）、総原価がAは1,600円、Bは300円増える。在庫履歴に、AとBの本店・在庫場所「EC-CUBE」の行が1行ずつ増え、在庫変動数A＝2・B＝3、在庫変動理由「買取/店頭買取」（画面は「区分/内訳」の形。初期データは区分「買取」・内訳「店頭買取」）、在庫変動理由の文言「店頭買取による入庫 査定ID：（査定番号）」、仕入単価A＝800円・B＝100円。登録元は設計書では「店頭買取」（新実装のマスターの名前は「店頭買取手動入庫」。同じ手動入庫を指す名前の違いとして記録し、合否は在庫変動理由・数量・単価で付ける）、登録元IDは査定ID |
| 6 | 店舗チーム：買取一覧で手順1の買取にチェックを入れ、ダウンロードの「戻しリストPDF」を出す（業務フロー06の3-5。3-2で出力した買取を対象に出力する） | エラーにならず、戻しリストの画面が開く（棚戻し済みの買取にも出せる）。商品仕訳（店舗の閾値ごとの区分とサプライ）、ページング、作成日時、行番号、棚番号（本店のみ）、言語/状態、略称、色/R、数、商品名、価格（基準価格）、ブロックの商品個数の総計が出て、AとBの行がある。「印刷する」を押すとブラウザの印刷ダイアログが開く。棚戻し済みは「済み」のまま（戻し作業そのものはシステムの外。UKA-07） |
| 7 | 店舗チーム：買取自動入庫のバッチを手で起動し、終わるまで待つ（15時を待たない。2026-11-26 決定。起動のしかたは根拠の欄）。在庫一覧と在庫履歴一覧を見る | 「買取自動入庫が完了しました。」が出る。手順1の買取は入庫済みなので対象にならず、二重に入庫されない。この買取の査定番号に由来する入庫の履歴が増えない（判定はこの査定番号の履歴で付ける。AとBの在庫の数は、他の試験の入庫待ちの買取に同じ商品があると増えるので記録にする）。ステータスは「入庫済み」のまま |
