# UKA-02 経理が振り込み、経理払い出し済みにして買取を成立させる

| 項目 | 内容 |
|---|---|
| 利用者 | 経理（振込依頼メールを受け取り、振込。EC-CUBE管理画面で経理払い出し済みを押す） |
| 目的 | 経理払い出し待ちの買取について、経理が振り込んだあと、買取詳細の「経理払い出し済」ボタンで買取成立にし、続けて入庫待ち（個別入力商品があれば未登録在庫あり）になる。買取成立日時が入り、買取集計の対象に入る |
| 種類 | 正常（組み合わせ表の2行）＋例外2件 |
| マトリクスの行 | `matrix_UKA-02/matrix.md` のT01（個別入力商品＝なし・押す人＝経理の権限があるユーザー・起点の買取＝経理払い出し待ちの買取）。T02（個別入力商品あり）は「L3で変わるところ」 |
| もとのシナリオ | SCN-KAITORI-001（後段）。業務フロー06の1-7（経理が買取詳細から買取成立にする） |

## 前提

- 共通の決まり：`../L4を流すときの共通の決まり.md` を先に読む（試験データの名前にシナリオIDを付ける・共有の設定は元に戻す・バッチの起動・店舗の読み替えなど）
- 起点の買取（経理払い出し待ち。経理に振込依頼メールが届いている）
  - T01：UKA-01 の T04 の終点（会員でログインして申込・未成年・適格請求書発行事業者に該当する・出金＝経理・買取品＝登録済みの商品だけ・本店・ダブルチェック者あり・自動車運転免許証）。買取金額1,900円（「店頭買取試験カードA」×2・「店頭買取試験カードB」×3）・数量5・買取店舗は本店（店舗ID 1。画面によって「Hareruya」「トーナメントセンター 東京」と出る）。この試験専用に UKA-01 の手順で1件作る
  - T02：UKA-01 の T01 の終点（同じ会員・成年・適格請求書発行事業者に該当しない・出金＝経理・買取品＝A×2・B×3に個別入力の「店頭買取試験未登録カードZ」×1を足す・本店・学生証、会社員証）。買取金額2,200円・数量6。この試験専用に UKA-01 の手順で1件作る
  - どちらも、買取一覧のステータスは「経理払い出し待ち」、買取成立日時は空、端末取引IDは空
- システムの外で済んでいること：経理がお客様の銀行口座へ振り込む環境（試験環境では振込は行わず、「振り込んだ」ことにする）
- 用意するデータ（試験用の値。設計書の値ではない）
  - 経理のユーザー：経理払い出し済みの権限があり、買取管理を使え、編集可能店舗に本店がある（権限が足りないと、ボタンを押したあとにエラーになる）
  - 経理の権限が無いユーザー（例外E1）：編集可能店舗に本店はあるが、経理払い出し済みの権限は無い店舗チームの担当者
  - 手順の前に控える値：買取集計データ（店頭買取管理＞買取集計データ）の、集計日＝今日・買取店舗＝本店の部門ごとの買取金額と合計（手順3）
- 画面の名前は新実装の表示で書く

## 操作の流れと期待値

| # | 操作する人と操作 | 期待値（画面で見えること） |
|---|---|---|
| 1 | 経理：経理チームのメールを開く（UKA-01 の手順16で届いたメール） | 件名「店頭買取振込依頼 【査定ID: （起点の買取の査定番号）】」のメールがある。査定IDを控える。振込の金額は、メール本文に項目が無いので、手順3の買取詳細で確かめる |
| 2 | 経理（システムの外）：お客様の銀行口座へ、買取金額（T01は1,900円、T02は2,200円）を振り込む（試験環境では済んだことにする） | システムの外の作業（業務フロー06の1-7）。買取は経理払い出し待ちのまま待つ（区間の境目） |
| 3 | 経理：管理画面の店頭買取管理＞買取一覧で、査定IDに手順1の査定番号を入れて「検索する」を押し、1件を開く。続けて買取集計データで、集計日＝今日・買取店舗＝本店を検索し、部門ごとの買取金額と合計を控える | 一覧に1件。ステータス「経理払い出し待ち」、買取金額が振り込んだ額と同じ。買取詳細（操作履歴）：ステータス「経理払い出し待ち」、買取成立日時は空、端末取引IDは空。ステータス変更履歴（新しい順）の先頭が「経理払い出し待ち」。買取情報の査定合計金額が一覧の買取金額と同じ |
| 4 | 経理：買取詳細の「経理払い出し済」を押す | 確認ダイアログ「経理払出し済みに変更します。よろしいですか？」が出る（設計書 M06-03-MSG-012 の文言。新実装は「払い出し」と書く。設計書との食い違いに記録）。「OK」を押すと、管理画面の上部に「保存しました」が出て、買取詳細に戻る（例外E1・E2。「キャンセル」を選ぶと何も起きない） |
| 5 | 経理：買取詳細を見る。買取一覧でも同じ買取を探す | ステータスは、T01「入庫待ち」、T02「未登録在庫あり」（個別入力商品があるため。実在庫情報登録のボタンが残る）。買取成立日時が入る。ステータス変更履歴（新しい順）：T01は「入庫待ち」「買取成立」「経理払い出し待ち」…、T02は「未登録在庫あり」「買取成立」「経理払い出し待ち」…（買取成立と、続くステータスの2行が増える）。端末取引IDは空のまま（レジ出金でないため）。買取金額・明細・ダブルチェック者・査定担当者は手順3のまま変わらない |
| 6 | 経理：買取集計データで、手順3と同じ条件（集計日＝今日・買取店舗＝本店）で検索する | この買取の金額（T01は1,900円、T02は2,200円）が、買取成立日（今日）の部門ごとの買取金額の合計に加わる（0205 ステータス変更「買取集計対象のステータス（買取成立、入庫済み、未登録在庫あり、入庫待ち）に変更された場合は再集計を行う」）。同じ日・店舗の他の買取が動くと値が変わるので、増えた分が自分の買取の金額と同じかで確かめる |
