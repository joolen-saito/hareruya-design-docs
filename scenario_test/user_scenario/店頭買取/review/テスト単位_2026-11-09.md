## 判断に迷ったもの

- **単一水準の因子**：`build_matrix.py` は因子が2つ以下だと割り算で止まる（3因子の網羅率の分母が0）。UKA-02・04・05・06・08・09・10に、本文の起点の文をそのまま使った水準が1つだけの因子を足した（行の数は変わらない）。
- **査定の中断と再開（D5）**：同じ条件の2つの値なので、UKA-01は例外を2つに分け、UKA-03は「再開」を行の水準、「中断」を例外にした。
- **例外が持つ値と、行の水準が持つ値が同じ条件のとき**（例：登録番号を確認済みの行と、確認せず押す例外）は、行の水準にせず「このテストだけ」（test_map）で割り当てた。例外のテストが元の行の〇を引き継ぐため。
- **UKA-01 の B4-2（経理が必要になる理由＝レジの金額が足りない）**：理由によらず操作は同じなので、経理に頼む行の1つだけに割り当てた（B4-1 は UTH-03 のみ）。
- **UTH-03 の P-01/P-02/P-03**：1本のテストにPは1つだけなので、仕入作業の行（K2）に P-02、棚戻し業務用CSVの行（J3）に P-03、残りの行に P-01 を割り当てた。
- **UTH-03 の B9（PDF／CSV）**：T03・T05・T07 は CSV のあとに PDF も出すが、1本に1つなので CSV（B9-2）にした。
- **UKA-07 の禁則**：棚戻し済み×CSV は作らない（本文は「3-2のCSVのあとに3-5のPDFを出せること」を確かめると書く）。

## 担当外で直す必要があるもの（直していない）

1. **道具 `build_test_pattern_matrix.py`**：例外の読み込みが `E\d+` だけで、`EX\d+`（通しシナリオ UTH-03 の例外EX1〜EX28）を読まない。UTH-03 の例外9件の〇（EX5・EX6・EX7・EX11・EX12・EX14・EX17・EX18・EX25）は `exc_map.tsv` に書いてあるが、いまは「例外が無い」で止まる。正規表現を `EX?\d+` にすれば通る（確認済み）。
2. **UTH-03**：B7-3（カードPは通販商品で、250円超の店頭商品に当たらない。cond_map の対応が違うか、250円超の店頭商品の行が要る）と D5-1（中断だけのテストが無い。UTH-02 の D4-1 も同じ）。
3. **UCY-06（D10-1／D10-2／D10-3）・UCY-07（D7-1／D7-2）**：1本のテストに同じ条件の値が並ぶ。業務周期側で分けるか、cond_map の値を整理する。
4. **業務横断／MTGバイヤー の scenario_list.md**：UKA-01 の例外E10 を指す記述があれば、E10（中断）とE26（再開）に分かれたことに合わせる。
