# 通販商品の戻しリスト出力と棚戻し（UKA-07）

IPA「高信頼化ソフトウェアのための開発手法ガイドブック」(2010) の表6-9〜6-11と同じ手順で作る。手順と表の役割は `../matrix_UKA-01/README.md` と同じ。

## 範囲

- 入庫待ちまたは入庫済みの買取の通販商品について、戻しリストを出し、棚戻し済みの印が付き、価格ソートして棚に戻すまで
- 戻しリストのPDF／CSV、入庫待ち／入庫済み、買取を行った店舗が本店（棚番号あり）／支店（棚番号なし）、棚戻し済みの印の有無（手動入庫の買取で3-2のCSVのあとに3-5のPDFを出す）を因子にした
- 入庫待ち・入庫済み以外の買取、編集可能店舗でない店舗の買取、複数の店舗の同時選択は例外（エラー）

- 2026-11-09：本文に同じ条件の値を並べていた（1回ずつ流すテストにするため）ので、値ごとに別の行・例外に分けて作った。期待値は 店頭買取/scenario_list.md の本文にあるものを水準ごとに分けただけで、新しい期待値は足していない
- 禁則：なし（2026-11-09 codex指摘で P1「棚戻し済み×CSV」を外した）。本文はCSV・PDFのどちらでも棚戻し済みの印が付くとしており（scenario_list.md UKA-07、0205）、組んでよい

## 外した因子・水準（2026-11-09 依頼者決定：画面の操作の違い）

業務の流れが分かれない画面操作の違いは、シナリオテストの組み合わせ表に入れず結合テストに任せる（依頼者決定）。この表から外した：

- 外した因子：A 戻しリストの出力形式（PDF／CSV）
- 理由：出力形式の違い（決定2）。どちらも出力した買取に棚戻し済みの印が付き、出る中身の違いは本文に無い。
- 外したあとの前提（代表）：代表はPDF（業務フロー06の3-5「使用する棚戻し業務用PDF」。06の2-1でもPDF出力）。棚戻し済みの水準の前提に残る「3-2のCSV出力で先に印が付いた」は、手動入庫の買取の前提を述べた本文の記述なのでそのまま残した。
- 外した例外：なし
- 行数：6行 → 4行（`matrix.tsv`）。2因子間の網羅は100%
- 上の本文に、外した因子を使った説明（因子の一覧・期待結果の表・まとめた水準の表）が残る場合は、経緯の記録として残してある。いまの表は `fl_table.tsv` が正
