# スタック用紙の印刷：出し方・受注の状態・印刷結果で、対応状況と再印刷がどうなるか（UEX-15）

IPA「高信頼化ソフトウェアのための開発手法ガイドブック」(2010) の表6-9〜6-11と同じ手順で作る（`通販/matrix/README.md` と同じ）。

1. 因子・水準表（FL表）: `fl_table.tsv`
2. 禁則表: `prohibitions.tsv`
3. マトリクス: `matrix.md` / `matrix.tsv`（`tools/build_matrix.py` が作る。1行が1本のシナリオ＝その受注のスタック用紙をプリンタが印刷し、結果を返すまで）
4. 例外の差し込み表: `exceptions.tsv`

## 範囲

- 店舗のプリンタ（Epson のサーバーダイレクトプリント対応機。システムの外）が EC に問い合わせて印刷データを受け取り（0505 A05-01）、印刷の結果を EC に返す（A05-02）。受注一覧の「スタック用紙印刷」（0203 M05-08）で出し直す
- 注文の種類は、店頭受取とスムーズ店頭受取。店頭PCの注文は UOR-06（自動印刷される／一部の支店は受注一覧から出す）で扱う
- 注文を確定してから最初に自動で印刷されるまでの通常の流れは UOR-01（このマトリクスの C2×A1×D1 は同じ流れの再掲になる）。ここでは、受注一覧からの出し直し・印刷の失敗・ピック中より先の受注の扱いを足す
- プリンタ本体の操作（用紙の入れ替え・電源・接続）と、印刷された紙の見た目は「システムの外」。EC 側で確かめるのは、プリンタが受け取る印刷データと、結果を返したあとの受注の対応状況・注文確定日・印刷の予約の有無

## 期待値の決まり（行ごとの期待値の元）

| 出し方 | 受注の対応状況 | 結果 | 期待値 |
|---|---|---|---|
| C1 受注一覧から | 注文受領 | D1 成功 | 押した時点で印刷予約が入り、対応状況は「ピック中」、注文確定日が入る（0203）。プリンタが印刷して成功を返すと、予約が解除されるだけで対応状況は変わらない（0505「ブラウザ印刷フラグが立っているとき…フラグを倒すだけに留め、対応状況は変えない」）。同じ紙は再び出ない |
| C1 受注一覧から | 入金済み・ピック中・ピック完了 | D1 成功 | 押しても対応状況・注文確定日は変わらない。印刷予約が入り、プリンタが印刷して成功を返すと予約が解除される。同じ紙は再び出ない |
| C1 受注一覧から | 全て | D2 失敗 | 予約は解除されず、対応状況は上の行のまま（新実装 src/Eccube/Service/Admin/Order/UpdatePrintedOrderStatusAction.php 83〜90行目：失敗の要素は更新せずログに残して次へ）。次の問い合わせで同じ紙が再び印刷される |
| C2 自動 | 注文受領（店頭受取・スムーズ店頭受取）／入金済み（スムーズ店頭受取） | D1 成功 | 印刷結果を受けて「ピック中」になり、注文確定日が入る（0505 A05-02「その受注IDのステータスをピック中にする」）。同じ紙は再び出ない |
| C2 自動 | 同上 | D2 失敗 | 対応状況は変わらず、エラーコードがログに残る（0505）。次の問い合わせで再び印刷される（新実装。設計書は「ログに追記する」まで。UEX-14） |

C1 の「注文受領は押した時点でピック中」は、印刷が失敗しても戻らない（0203 の処理は印刷結果と無関係）。受注一覧の画面でピック中になっていても、紙が出ていないことがある（UEX-14）。

## 実装と設計書で確かめたこと（2026-11-05）

- 印刷対象（0505 A05-01 現行仕様節 1184行目付近）：店頭受取＝注文番号が採番済みで注文受領／スムーズ店頭受取＝支払方法がクレジット決済か支払いなしで、購入処理中でなく、確定日時・注文確定日・出荷日・取消日・受領日・店頭予約日が未設定で、スマレジコードが採番済み／ブラウザ印刷フラグが立つ受注。1回の要求で最大10件、新実装は `src/Eccube/Repository/OrderRepository.php` 1875行目
- 結果の更新（A05-02 現行仕様節 1319〜1320行目）：受注1件ごとに確定する。フラグが立っていればフラグを倒すだけ、立っていなければピック中＋注文確定日
- 設計書と新実装の違い：A05-02 の本文は「受注IDのステータスをピック中にする」で、失敗の扱いは「エラーコードをログに追記する」だけ。新実装（同ファイル 57〜60行目と83〜90行目）は失敗の要素を更新しない（再印刷される）。現行 pf-api の説明は「印刷結果の詳細を参照してエラーの有無を確認していない」＝失敗でもピック中にする読み方ができる（食い違いとして `scenario_list.md` に記録）

## まとめた水準

なし（どの水準も処理が違う）。主な根拠：対応状況の4つは、受注一覧からの印刷で対応状況が変わるのが注文受領だけ・自動で拾う対象になるのが注文受領と入金済みだけで、処理が違う。店頭受取とスムーズ店頭受取は自動で拾う条件が違う。
