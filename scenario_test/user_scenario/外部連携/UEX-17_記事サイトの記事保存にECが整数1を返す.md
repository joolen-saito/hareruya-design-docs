# UEX-17 記事サイトが記事を保存するたびに、ECが整数1を返し、記事サイトの保存が続く

| 項目 | 内容 |
|---|---|
| 利用者 | 記事サイトの編集者（WordPress。システムの外）→ EC（API） |
| 目的 | 編集者が記事サイトで記事を保存すると、記事サイトが記事の保存のたびに EC へ通知を送る。EC は整数 1 だけを返す（受け取った内容は使わない。設計書に無く、新実装による期待値）。記事サイトは応答が整数なので保存を続ける（記事サイトの保存の完了はシステムの外）。応答が整数でなければ記事サイトは保存を中断する |
| 種類 | 正常（1本）＋ L3の具体例（組み合わせ表は無い。1つずつ別のテストにする） |
| マトリクスの行 | なし（組み合わせ表は無い）。L3 は `scenario_list.md` の UEX-17 の L3 欄の項目を1つずつ別のテストにした |
| もとのシナリオ | なし（業務フローに無い）。設計書 0517 その他API に記事保存の通知の処理は載っていない。現行 pf-api と新実装の処理が根拠 |

記事サイトの画面の見え方は外部サービスなので記録だけにし、合否は EC が返した値（応答の本文）と、EC に残るもの（残らないこと）で付ける。EC は応答の本文を画面に出さないので、記事サイトが送るのと同じ通知を、試験担当者が用意する HTTP クライアントで EC に送って応答を読む。

## 前提

- 共通の決まり：`../L4を流すときの共通の決まり.md` を先に読む（試験データの名前にシナリオIDを付ける・共有の設定は元に戻す・バッチの起動・店舗の読み替えなど）
- システムの外で済んでいること：記事サイト（WordPress）の試験用の環境があり、記事を保存すると EC の開発環境へ通知が送られる設定になっている。編集者が記事を保存できる。記事サイトの環境が無いときは、手順1・2・4を通らず、EC に対する通知（手順3）だけを流す
- 用意するデータ（試験用の値。設計書の値ではない）
  - 記事サイトの編集者：試験用の記事を新規に保存・更新できるアカウント（記事サイト側。システムの外）
  - 記事：記事サイトの試験用の記事「シナリオ試験記事 UEX-17」（投稿の番号は記事サイトが採番する。以下「投稿番号」。EC の開発環境に同じ投稿番号の記事は無い）
  - EC への通知：記事サイトが送るのと同じ形の「記事保存の通知」（記事の保存の内容を本文に持つ送信）を、試験担当者が用意する HTTP クライアントで EC に送る
  - 手順の前に控える値：EC の開発環境に、この投稿番号の記事が無いこと（記事情報の取得の応答が「見つからない」）
- 画面の名前・文言は新実装の表示で書く。メッセージの文言は設計書の文言を期待値にし、設計書に文言が無く新実装にだけある文言は新実装の文言を期待値にする

| 1 | 記事サイトの編集者（システムの外）：記事「シナリオ試験記事 UEX-17」を新規に作り、保存する。保存のたびに記事サイトが EC へ通知を送る | 記録のみ（合否は付けない。外部サービスの画面の見え方は記録にとどめる：2026-11-26 決定）：記事サイトで保存が最後まで完了したか（保存の完了画面・記事の状態）。EC の応答が整数なので保存は続く。完了しなければ、そのメッセージを記録する |
| 2 | 運用担当：EC のアプリケーションのログを開き、手順1の時刻の前後を見る | 記事保存の通知を受けた記録が残るかは設計書に定めが無く、記録だけ（新実装は受け取った内容を使わず、固定の応答を返すだけ） |
