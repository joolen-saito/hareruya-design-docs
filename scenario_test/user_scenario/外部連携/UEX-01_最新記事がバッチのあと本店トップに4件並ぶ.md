# UEX-01 記事サイトの最新記事が、バッチのあと本店トップに4件並ぶ

| 項目 | 内容 |
|---|---|
| 利用者 | 記事サイトの編集者（WordPress。システムの外）→ 最新記事の取得バッチ（システム。試験では手で起動する）→ お客様（本店のトップ） |
| 目的 | 記事サイトが公開している最新記事（最大20件）をバッチが取得して保存し、本店のトップの「最新記事」の欄に先頭の4件（サムネイル・タイトル。設計書はカテゴリ・著者も）を並べる。1件を押すとその記事の詳細へ、「記事一覧を見る」で記事一覧へ進む。取得に失敗したときは保存済みの一覧を書き換えない |
| 種類 | 正常（取得に成功）。取得に失敗する例外・バッチが一度も成功していない状態・支店のトップは「L3で変わるところ」 |
| マトリクスの行 | 組み合わせ表は作らない（因子は取得の成否だけで、効き合う因子が無い）。L3の値は「L3で変わるところ」の V1〜V5 |
| もとのシナリオ | SCN-EXTERNAL-WordPress最新記事-001。業務フローには無い |

記事サイトの側（記事を公開する・記事サイトの画面）は外部サービス（システムの外）なので、見え方は記録だけにする。合否は、EC が取得して保存した最新記事の一覧と、本店のトップの表示（EC の画面）で付ける。

## 前提

- 共通の決まり：`../L4を流すときの共通の決まり.md` を先に読む（試験データの名前にシナリオIDを付ける・共有の設定は元に戻す・バッチの起動・店舗の読み替えなど）
- システムの外で済んでいること：記事サイトに、公開済みの記事が20件以上ある（編集者が公開する。記事サイトの中身は試験では作らない）
- バッチは時刻を待たず手で起動してよい（周期は設計書に無く、システムの外の運用設定。起動のしかたは「根拠」の欄のファイル）。バッチが取りに行く先は新実装に固定されている記事サイトの公開API（ECの設定では変えられない）。取得する記事は記事サイトの今の公開記事なので、記事の中身は試験で決められない。合否は、この試験でバッチが保存した一覧と本店のトップの表示が一致するかで付ける
- 本店のトップの記事の欄は、一度読み込んだ内容を5分間覚えている（新実装の動き。設計書に定めは無い）。バッチを起動した直後に開いても前の内容のことがあるので、手順3は最大5分の間隔をあけて開き直す
- 用意するデータ（試験用の値。設計書の値ではない）
  - 運用の担当者（バッチを起動できる）
  - 管理画面にログインできる担当者（コンテンツ管理＞ファイル管理を使える）
  - お客様（ログインしなくてよい）
- 画面の名前・文言は新実装の表示で書く（設計書の名前が違うときは、期待値のところに設計書の名前を添える）。メッセージの文言は設計書の文言を期待値にし、新実装の文言が違えば不合格として記録する
- 共有の設定は変えない（記事の欄はブロックの設定どおり）

## L3で変わるところ（組み合わせ表は無い。L3欄の値）

1回ずつ別のテストとして流す。どの行も準備P1・P2を通る。

| 行 | 条件 | 変わるところ |
|---|---|---|
| V1 | 取得に成功（4件表示）。前回の内容と今回の内容を比べる | 代表の行（手順1〜6）。手順3で、P1で控えた前回の4件と今回の4件を比べて、入れ替わったか同じかを記録する（記事サイトに新しい記事が無ければ同じ。合否は手順2の一覧との一致で付け、入れ替わりは記録） |
| V2 | 取得に失敗：記事サイトの応答が200以外／本文が空／JSONの形式が不正の3通り | **実施不可（流せない）**。バッチの取得先は新実装に固定された記事サイトの公開APIで、失敗させる操作が画面・設定に無い（通信を書き換える手段は使わない）。設計書どおりの期待値（記録のために残す）：バッチはエラー内容をコンソールに出し、一覧のファイルは書き換えない（0417：取得失敗はエラー内容をコンソールに出力する。新実装は、200以外・本文が空・JSONの形式が不正のいずれも「Wordpress記事取得バッチ処理でエラーが発生しました: ○○」を出して一覧を保存しない）。トップは前回の記事のまま |
| V3 | バッチが一度も成功していない（一覧のファイルが無い）：記事の欄が空 | 準備P2で、ファイルが見えたときだけ流す。P2で、最新記事の一覧のファイルをダウンロードして控える。手順1の前に、ファイル管理でそのファイルを削除する（試験で用意したものではないが、ダウンロードして控え、終わったらバッチの起動で作り直す。共有のファイルなので、流す間はほかの試験でトップを見ない）。手順3：トップを開く（5分あけて開き直す）。「最新記事」の欄そのものが出ない（新実装：記事が1件も無いとき欄ごと出さない。設計書 0301 (13)は一覧の無い状態の表示を定めない）。終わったら手順1のバッチを手で起動し、完了の表示と、手順3で欄が戻ることを確かめる。ファイルが見えない・削除できないときは実施不可（流せない） |
| V4 | 支店のトップには欄が無い | 手順3のあとに、支店のサイトのトップを開く。設計書（0301 F01-02 支店ECTOP）は最新記事の記載が無く、欄は出ない。新実装の支店のトップに「最新記事」の欄が出るか記録する（出たら不合格として記録。出ない見込みの根拠は無いので、画面で確かめる） |

例外（組み合わせ表が無いので、L3の値として扱う）：コマンド名の未指定・不一致で処理を行わずに終了する（0417）は、操作する人がコマンドを打ち間違えるときの動きで、業務の分かれ目ではないので確かめない。
