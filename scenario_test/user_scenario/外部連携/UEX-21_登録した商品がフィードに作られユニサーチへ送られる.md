# UEX-21 登録した商品が、フィードに作られてユニサーチへ送られる

| 項目 | 内容 |
|---|---|
| 利用者 | 登録担当（管理画面の「フィードファイルを更新する」ボタン）／システム（定時のバッチ）→ ユニサーチ（システムの外） |
| 目的 | 商品が公開され、フィードの作成が始まる（定時のバッチ、または管理画面のボタン）。フィードのTSV（gz）とMD5値を入れたdoneファイルが作られ、ユニサーチへ送られる。載るのは販売価格が1円以上・商品と規格が公開・規格が表示のもの（高額商品でなければNMの規格だけ）。作成中にもう一度ボタンを押すと作成は始まらず「既に作成処理が実行中のため、今回の実行はスキップしました。」が出る。開始できたときは「ユニサーチフィードの作成を開始しました。」（完了の通知ではない） |
| 種類 | 正常（組み合わせ表の6行。1行が1回流すテスト1本）＋ 例外（E1〜E3）＋ 表外の具体例 |
| マトリクスの行 | `matrix_UEX-21/matrix.md` のT01（フィードに載せる商品の条件＝載る商品：販売価格が1円以上・商品と規格が公開・規格が表示〔高額商品でなければNMの規格だけ〕）。T02〜T06 と例外E1〜E3 は「L3で変わるところ」 |
| もとのシナリオ | なし（業務フローに無い）。設計書 0404 バッチ_商品管理「ユニサーチフィード作成」（B02-08）・「ユニサーチフィードTSV」（B02-07）・「ユニサーチフィード送信」（B02-09）。商品の登録から検索・注文までの通しは UTH-01（区間⑥）、検索の見え方は UEX-22 |

ユニサーチの画面・取り込み・索引づくり・検索の順位はシステムの外（外部サービス）なので記録だけにし、合否は EC が作って送る値（フィードのファイルの内容・doneファイル・管理画面のメッセージ・処理のログ）で付ける。フィードの行の細部（項目ごとの値）は通しシナリオ UTH-01 の手順8と同じなので、そちらの「フィードの行で確かめること」を使う。

## 前提

- 共通の決まり：`../L4を流すときの共通の決まり.md` を先に読む（試験データの名前にシナリオIDを付ける・共有の設定は元に戻す・バッチの起動・店舗の読み替えなど）
- 環境：ユニサーチの接続先と送信先（SFTP）が設定されている環境で行う。ここは送信を確かめる試験なので、共有の設定は書き換えない
- システムの外で済んでいること：カードの商品画像をS3へ保存済み。カードが入荷している。ユニサーチ側の取り込み・索引づくりは外部サービスが行う（結果は記録だけ）
- 用意するデータ（試験用の値。設計書の値ではない）
  - 登録担当と、在庫の承認者（別の担当者。承認権限があり、登録担当の承認通知先に入る）
  - 商品：シングルカード「シナリオ試験フィードカード UEX-21」（英名「Scenario Test Feed Card UEX-21」。カード登録CSVで先に登録する。日本語版、基準価格3,000円、購入グループ「通常商品」、商品カテゴリは準備P2で作る「シナリオ試験 フィードセットカテゴリ UEX-21」、商品公開ステータス＝非公開、支店の商品公開ステータス＝非公開）をカード商品CSVに1行書く。商品CSVの割引率は初期データの「4」（NM100%・SP90%・MP80%・HP70%）なので、NM・SP・MP・HPの4規格ができ、価格はNM 3,000円・SP 2,700円・MP 2,400円・HP 2,100円。入庫は在庫編集画面でNMの規格に3点。行ごとに別の商品を使う（名前の後ろに行番号 T01〜T06 を付ける。例「シナリオ試験フィードカード UEX-21 T02」）
  - カードセットとカテゴリ：カードセット「シナリオ試験フィードセット UEX-21」と商品カテゴリ「シナリオ試験 フィードセットカテゴリ UEX-21」。初期データには無いので準備P1・P2で先に作る（商品CSVの商品カテゴリ(ID)は既存のカテゴリの番号しか受け付けない）
  - 運用担当（テスト担当）：開発環境のサーバのフィード出力先とアプリケーションのログを読める人
  - 手順の前に控える値：フィード出力先の今のファイルの一覧（ファイル名・更新日時）、送信先（ユニサーチ）に残るファイルの一覧（読めるとき。読めなければ記録）
- 時間の決まり：定時のバッチ（作成は毎時15分、送信は5分おき。設計書 0404）が間に入っても結果は変わらない（この試験は載る・載らないを手順6のファイルの行で確かめ、検索への反映は確かめない）
- 画面の名前・文言は新実装の表示で書く（設計書の名前が違うときは、期待値のところに設計書の名前を添える）。メッセージの文言は設計書の文言を期待値にし、設計書に文言が無く新実装にだけある文言は新実装の文言を期待値にする

## L3で変わるところ（マトリクスの他の行・例外・表外の具体例）

手順の番号は上の「操作の流れと期待値」。1回ずつ別のテストとして流す。条件の列は `matrix_UEX-21/matrix.md` のとおり。どの行も、準備P1〜P3（カードセット・カテゴリ・カード）は共通で、商品はその行専用のもの（名前の後ろに行番号）を使い、手順6で、その行の商品の行が「ある・ない」を確かめる。

### マトリクスの行

| 行 | 条件 | 変わるところ |
|---|---|---|
| T01 | A1：載る商品 | 代表の行（上の手順1〜7） |
| T02 | A2：販売価格が0円の商品 | 手順1：基準価格を0円にしたCSVで登録する（0円で保存できないときは、入力の結果を記録し、登録後に規格の販売価格を0円に直す）。手順4：公開にする。手順6：この商品の行が無い（販売価格が1円以上のものだけが載る）。ほかの商品が載っていればフィードは作られ、doneファイルもできる |
| T03 | A3：非公開の商品 | 手順4を通らない（商品公開ステータスは「非公開」のまま）。手順6：この商品の行が無い（商品が公開のものだけが載る） |
| T04 | A4：規格が非表示の規格 | 手順4のあと、カード商品CSV登録で、商品ID・NMの規格を指定して商品規格表示フラグを0（非表示）にして取り込む。手順6：この商品の行が無い（規格が表示のものだけが載る。非表示にしたNMの規格は載らず、ほかの状態（SP・MP・HP）の規格も高額商品でないので載らない） |
| T05 | A5：（高額商品でない場合）同一商品・同一言語の中で最も状態がよいもの以外の規格 | 手順6：行はNMの規格の1行だけで、同じ商品のSP・MP・HPの規格の行が無い。手順2〜5は代表と同じ。SP・MP・HP の規格に在庫を入れても（手順3でNMに加えて入庫し承認する）、載らない |
| T06 | A6：（高額商品の場合）高額商品コードが設定されていない規格 | 手順1：高額商品として登録する商品（UTH-01 の行A3の手順1と同じ作り方）を、規格の高額商品コードを空のまま登録する（高額商品コードを入れないで登録できるかを画面で確かめ、できないときは実施不可（流せない）として記録する）。手順4：公開にする。手順6：この商品の行が無い（高額商品は、高額商品コードが設定された規格が、状態を問わず規格ごとに載る。コードが無い規格は載らない） |

| 例外 | 差し込む元の行・条件 | 変わるところ |

| E2 | A1（T01の準備と手順4まで同じ）：手動実行の指定 | 手順5の代わり：運用担当が、ユニサーチ商品フィードのバッチを手動実行の指定を付けて手で起動する（起動のしかたは根拠の欄）。期待値：完了の表示「ユニサーチ商品フィード連携処理が正常に終了しました。」。フィード出力先に gz と done ファイルができる（手順6と同じ）。ユニサーチへは送られない（送信先にこの回のファイルは届かない。ログに「手動実行モードのため、SFTPアップロードをスキップしました。」） |
