# UEX-23 会員が注文を確定すると、購入完了タグログがユニサーチへ送られる

| 項目 | 内容 |
|---|---|
| 利用者 | お客様 → EC → ユニサーチ（システムの外） |
| 目的 | お客様がご注文方法指定の確認画面から注文を確定すると、購入完了画面が出て、購入商品の商品ID・単価・数量が購入完了タグログとしてユニサーチへ送られる。送信に失敗しても注文は完了する（購入完了画面に進み、失敗はログにだけ残る） |
| 種類 | 正常（1本）＋ L3の具体例（組み合わせ表は無い。1つずつ別のテストにする） |
| マトリクスの行 | なし（組み合わせ表は無い）。L3 は `scenario_list.md` の UEX-23 の L3 欄の項目を1つずつ別のテストにした |
| もとのシナリオ | なし（業務フローに無い）。業務フロー16 の 1-4（注文完了）と同じ時点の裏側。設計書 0304 フロント_注文「決済~購入完了」の処理概要。注文の中身（金額・メール）は UTS-01・UTS-04、通しは UTH-01（区間⑩） |

ユニサーチの側（タグログの記録・集計）は外部サービスなので記録だけにし、合否は EC が送る値（処理のログに残る送信の内容・送信の結果）と、EC の画面（購入完了画面・受注）で付ける。ユニサーチ側で記録を見られないときは、送信したことをログで確かめて記録に留める。

## 前提

- 共通の決まり：`../L4を流すときの共通の決まり.md` を先に読む（試験データの名前にシナリオIDを付ける・共有の設定は元に戻す・バッチの起動・店舗の読み替えなど）
- システムの外で済んでいること：ユニサーチの購入完了タグログの受け口が使える状態（外部サービス）
- 環境：ユニサーチの購入完了タグログの送信先が設定されている環境で行う。共有の設定は書き換えない
- 用意するデータ（試験用の値。設計書の値ではない）
  - 会員：試験 八郎（UEX-23）（メールアドレス `uex-23@example.test`、本会員、国内（東京都）の住所を登録済み、保有ポイント10,000）
  - 商品：グッズ「シナリオ試験タグロググッズA UEX-23」（商品コード `UEX23-G01`、販売価格 2,000円（税込）、公開、本店の在庫5、販売制限なし）、グッズ「シナリオ試験タグロググッズB UEX-23」（商品コード `UEX23-G02`、販売価格 1,000円（税込）、同じ条件）。グッズ商品CSV登録→在庫変更CSV登録→在庫の承認→商品公開CSV登録の順（UPM-01 の手順1〜6と同じ操作）
  - 運用担当：開発環境のアプリケーションのログを読める人
  - 設定：送料無料金額は30,000円（開発環境の値）。購入は小額なので送料無料にならない
  - 手順の前に控える値：商品A・商品Bの商品ID（商品マスターの商品ID）と、本店の在庫（5）、会員の保有ポイント（10,000）
- 画面の名前・文言は新実装の表示で書く（設計書の名前が違うときは、期待値のところに設計書の名前を添える）。メッセージの文言は設計書の文言を期待値にし、新実装の文言が違えば不合格として記録する

## 操作の流れと期待値（起点：お客様がご注文方法指定の確認画面から注文を確定する。代表：商品Aを数量2・全額ポイント支払い）

| # | 操作する人と操作 | 期待値（画面・ログで見えること） |
|---|---|---|
| 1 | お客様（試験 八郎（UEX-23））：本店にログインし、ヘッダーの検索欄に「シナリオ試験タグロググッズA UEX-23」を入れて検索する（ユニサーチへの反映のあと。反映していないときは、商品マスターで控えた商品IDで商品詳細を直接開く）。商品数を 2 にして「カートに追加」を押す | 画面右下に「カートに追加しました：」が出る。買い物かごに商品Aが数量2・小計4,000円で出る |
| 2 | お客様：買い物かごから「購入手続きへ」を押す。ご注文方法指定画面で、配送方法に「ゆうパック」を選び、ポイントは「ポイントを使う」で使用ポイントを「商品金額合計＋送料」以上（例：送料を足した額）にして更新する。配送希望日時は指定なし、備考は書かない | 支払方法の選択肢が「全額ポイント支払い」だけになる。ご注文内容の確認に、商品金額合計4,000円・送料（ゆうパックの送料）・手数料0円・ポイント使用（値引き）・注文金額合計（税込）0円が出る（UTH-01 の手順14〜16と同じ） |
| 3 | お客様：確定のチェックボックスにチェックを入れ、注文のボタンを押す | 決済の画面は出ず、購入完了画面が開く。見出し「ご注文完了」、「ご注文ありがとうございました。」、8桁のご注文番号、「注文完了メールをお送りしました。届かない場合はお手数ですが当店のヘルプページを御覧ください。」が出る。ご注文番号を控える |
| 4 | 運用担当：アプリケーションのログで、手順3の時刻の前後の、購入完了タグログの送信の記録を探す | ログに、「購入完了タグログ送信処理」（開始）、「購入完了タグログ送信結果ステータス」（送信先の応答の結果。成功を示す値。外部サービスの応答なので値は記録）、「購入完了タグログ送信処理完了」（送った送信先のアドレスつき）の順に残る。送信先のアドレスの中の購入内容の項目に、商品Aの商品ID・数量「2」・単価「2000」が「商品ID:数量:単価」の形で入っている（この注文に含まれる商品だけ）。「購入完了タグログ送信エラー」は残らない。送信先（ユニサーチ）で記録を見られるときは、同じ内容で記録されているかを記録する（外部サービス。合否は付けない） |
| 5 | 店舗チーム：管理画面の受注管理の受注情報検索で、手順3のご注文番号を検索する | 1件出る。お名前「試験 八郎」・購入金額0円。受注の商品は商品A・数量2・単価2,000円（タグログに送った値と同じ）。購入完了画面・受注・メールは、タグログの送信の成否に関わらず通常どおり（注文の確定とメールの送信は、購入完了タグログの送信より前に済んでいる） |

## L3で変わるところ（組み合わせ表は無い。1つずつ別のテストにする）

手順の番号は上の「操作の流れと期待値」。どの行も、その行専用の注文（会員と商品は代表と同じ。商品の在庫は5のままではなく、前の行で減った残りを控える）で行う。

各行の始めに、その行の保有ポイントを用意する（同じ会員で続けて注文すると、前の行で使った分が減り、使えるポイントは保有ポイントまでなので足りなくなる）。その行の商品金額合計に、ご注文方法指定画面に出るゆうパックの送料を足した額（R1・R2・R4 の商品A数量2は 4,000円＋送料、R3 は 5,000円＋送料。送料は画面の表示を控える）以上の保有ポイントを、管理画面の会員編集の「ポイント確認」から「ポイント履歴追加（キャンペーン、特別対応）」でポイント増減量を入れて足す（UMB-10 の準備1と同じ操作）。足したあと、会員の保有ポイントが必要額以上であることを、管理画面とマイページで確かめて控える。R4 はクレジットカード決済でポイントを使わないので、足さなくてよい。

| 行 | 条件（`scenario_list.md` の L3 欄の項目） | 変わるところ |
|---|---|---|
| R1 | 送信の成功 | 代表の行（上の手順1〜6） |
| R2 | 送信の失敗（注文は完了） | 手順3：ユニサーチの購入完了タグログの受け口が応答しない・接続できない状態で注文を確定する（ユニサーチ側の都合で起こす。共有の開発環境の送信先の設定は書き換えない。起こせないときは、実施不可（流せない）として記録する）。期待値：購入完了画面が通常どおり開く（見出し「ご注文完了」・ご注文番号）。手順4：ログに「購入完了タグログ送信エラー」（送信先に接続できなかった理由つき）が残る。送信先が応答したがエラー（4xx・5xx）のときは、「購入完了タグログ送信結果ステータス」にそのコードが残る（エラーの記録は接続できなかった場合だけ）。手順5・6：受注は作られ、メールも届く。在庫・ポイントも代表と同じに減る。設計書 0304 に送信に失敗したときの定めが無く、新実装は失敗しても注文を完了する（`scenario_list.md` の食い違い） |
| R3 | 複数商品の注文 | 手順1：商品A（数量2）に加えて、商品B（数量1）もカートに入れる。手順2：商品金額合計は5,000円（4,000＋1,000）で、全額ポイント支払い。手順4：送信先のアドレスの購入内容の項目に、2商品が入る（商品A の商品ID:2:2000 と 商品B の商品ID:1:1000 をカンマでつないだ形）。手順5：受注の商品が2明細（A・数量2・単価2,000円、B・数量1・単価1,000円） |
| R4 | 支払方法ごと（注文の中身は UTS-01・UTS-04 の水準に任せる） | 手順2：支払方法に「クレジットカード決済」を選び（ポイントは使わない。注文ボタンの文言は「クレジットカード決済へ」）、手順3：確定のあと、カード情報を入れる画面（試験環境では SPLINKS の試験決済画面）で決済を済ませる。期待値：決済を済ませたあと、購入完了画面が開く。手順4：購入完了タグログの送信の記録と購入内容は代表と同じ（商品A・数量2・単価2000）。決済の画面から戻って購入完了になるまでの時刻と、送信の時刻の前後は、ログの時刻で記録する（設計書に送信の時点の定めは無い）。そのほかの支払方法（銀行振込・郵便振替・代金引換など）は購入完了までの流れが同じなので、確かめるときは行を足す（注文の中身は UTS-01・UTS-04） |
