# UEX-22 会員がサジェストと検索で商品を探し、ユニサーチに載る前は出ず、載ったあとに出る

| 項目 | 内容 |
|---|---|
| 利用者 | お客様 → ユニサーチ（システムの外）→ EC |
| 目的 | お客様が検索欄にカーソルを当てる、またはキーワードを入れて検索する（詳細検索・カテゴリ・絞り込みも）。何も入れないと履歴の候補（全て削除・個別削除ができる）、入力すると候補（最大13行、カードセットは最大3件）が出る。検索結果には、ユニサーチが返した商品を、EC が公開状態・価格・在庫で引き当て直して出す。ユニサーチを使う環境では、フィードに載る前の商品はどの検索にも出ない（0件の案内）。並び順（おすすめ順・発売日順・色順・価格の高い順・低い順）を選べる |
| 種類 | 正常（1本）＋ L3の具体例（組み合わせ表は無い。1つずつ別のテストにする） |
| マトリクスの行 | なし（組み合わせ表は無い）。L3 は `scenario_list.md` の UEX-22 の L3 欄の項目を1つずつ別のテストにした |
| もとのシナリオ | なし（業務フローに無い）。設計書 0303 フロント_商品「商品一覧」（ユニサーチ対応）・0302 フロント_グローバルナビ（サジェスト）。検索の中身（出る・出ない、在庫・価格の表示）は UPM-01・UPM-03・UPM-05、通しは UTH-01（区間⑦⑧）が通す。ここは反映前後・サジェスト・並び順を足す |

ユニサーチの画面・索引づくり・検索の順位の決め方・取り込みまでの時間はシステムの外（外部サービス）なので記録だけにし、合否は EC の画面（お客様の検索結果・候補の表示・案内の文言・商品一覧の価格と在庫）で付ける。

## 前提

- 共通の決まり：`../L4を流すときの共通の決まり.md` を先に読む（試験データの名前にシナリオIDを付ける・共有の設定は元に戻す・バッチの起動・店舗の読み替えなど）
- 環境：ユニサーチの接続先が設定されている環境で行う（新実装は、検索の接続先が空だとユニサーチを使わず EC 内の検索に切り替える。その環境では「載る前は出ない」は成り立たない。R5）
- システムの外で済んでいること：グッズの商品画像をS3へ保存済み。商品が店に入荷している。ユニサーチ側の設定（検索対象の項目）は済んでいる。フィードの取り込みと索引づくりはユニサーチ側が行う
- 用意するデータ（試験用の値。設計書の値ではない）
  - 登録担当と、在庫の承認者（別の担当者。承認権限があり、登録担当の承認通知先に入る）
  - 会員：試験 七郎（UEX-22）（メールアドレス `uex-22@example.test`、本会員、国内（東京都）の住所を登録済み）。検索は未ログインでもできる。この試験はログインして行う（履歴の候補の出方を、手順の前の状態から確かめるため）
  - 商品：グッズ「シナリオ試験検索グッズA UEX-22」（商品コード `UEX22-G01`、販売価格 2,000円（税込）、公開、本店と支店の商品公開ステータスは公開、在庫5）、グッズ「シナリオ試験検索グッズB UEX-22」（商品コード `UEX22-G02`、販売価格 4,000円（税込）、同じ条件、在庫5）。グッズ商品CSV登録（商品公開ステータス＝非公開で登録）→在庫変更CSV登録→在庫の承認→商品公開CSV登録で本店・支店とも公開、の順（UPM-01 の手順1〜6と同じ操作）。商品カテゴリは既存のものを1つ選び、番号を控える
  - 手順の前に控える値：ヘッダーの検索欄の検索履歴（会員のログイン後に履歴が無いこと）
- 時間の決まり：手順1〜3は続けて行い、定時のバッチ（作成は毎時15分）が間に入らないようにする（入ると手順1・2の「載る前」が確かめられない）
- 画面の名前・文言は新実装の表示で書く（設計書の名前が違うときは、期待値のところに設計書の名前を添える）。メッセージの文言は設計書の文言を期待値にし、新実装の文言が違えば不合格として記録する

## L3で変わるところ（組み合わせ表は無い。1つずつ別のテストにする）

手順の番号は上の「操作の流れと期待値」。どの行も、その行専用の商品を使う（名前の後ろに行番号 R1〜R4 を付ける。例「シナリオ試験検索グッズA UEX-22 R1」）。

| 行 | 条件（`scenario_list.md` の L3 欄の項目） | 変わるところ |
|---|---|---|
| R1 | 本店・支店（支店はフィードの支店表示フラグが1の商品だけ） | 商品を2種類用意する：本店と支店の両方で公開（商品C）、本店だけ公開（商品D。支店の商品公開ステータスは非公開）。手順3のあと、手順4の検索を、本店と支店のサイトの両方で行う。期待値：本店は C・D とも出る。支店のサイトは、支店表示フラグが1の商品C だけが出て、商品D は出ない（設計書 0303「支店で検索を行う際は、必ず支店表示フラグを公開で指定する」。支店でもサジェストを使い、商品D はサジェストの候補にも出ない）。支店には、お気に入り・入荷通知の項目が出ない（UPM-03） |
| R2 | 日本語・英語 | 手順4・6を、言語切り替えで英語にしたサイトで行う。期待値：画面の文言が英語表示になる（検索欄の注意書き・並び順の名前・案内）。商品名（英）の検索で見つかるかは、ユニサーチ側の検索対象の設定（他層）なので、結果を記録するだけで合否は付けない（【決着 2026-11-09】）。日本語の語での検索結果は日本語サイトと同じ |
| R3 | 0件・補正語・4,000件超の案内 | 手順4の代わりに次を行う。0件：どの商品にも一致しない語（例：「存在しない語 UEX-22」）で検索：「お探しの商品は見つかりませんでした」。補正語：綴りを違えた語で検索し、ユニサーチが補正した語で結果を返す場合：「"（入れた語）"では商品が見つかりませんでした。」「"（補正された語）"で検索結果を表示しています。」の2行が出て、補正語の結果の商品が出る（新実装の文言。設計書 0303 に文言は無く、出た文言を記録）。4,000件超：広い語（1文字。環境の商品が多いとき）で検索：「ご指定の条件に一致する商品が多すぎます。」「さらに絞り込むための条件を追加してください。」「詳細検索は こちら」（「こちら」は詳細検索のリンク）の案内が出て、一覧は出ない。補正語・4,000件超は、環境の商品の数やユニサーチ側の補正の辞書で決まるので、起こせないときは実施不可（流せない）として記録する |
| R4 | 候補が取れないとき（ユニサーチが応答しない） | 手順2・6の候補の取得、手順4の検索がユニサーチの応答を得られない状態（ユニサーチ側の都合で起こす。共有の開発環境の接続設定は書き換えない。起こせないときは、実施不可（流せない）として記録する）。期待値：候補は出ない（検索欄の入力はできて、「検索」は送れる）。検索結果は「読み込みに失敗しました。」または「一覧の読み込みに失敗しました。」の表示になる（出た文言を記録）。設計書に定めが無く、新実装の動きの記録 |
| R5 | ユニサーチの接続先が空の環境（従来の EC 内の検索） | この環境では、手順1の「載る前は出ない」は当てはまらず、公開・価格・在庫などの EC 内の条件で出る・出ないが決まる（新実装は検索の接続先が空だとユニサーチを使わず EC 内の検索に切り替える）。期待値は UPM-01 などの EC 内検索のもの。共有の開発環境の設定は書き換えないので、接続先が空の環境（別の環境）があるときだけ流し、無いときは実施不可（流せない）として記録する |
| R6 | 並び順：発売日順・色順 | カードを使う（グッズには発売日・色が無い）。準備：カード登録CSVで、色の違う単色のカード3枚（「シナリオ試験検索カード白 UEX-22」＝白、「…青 UEX-22」＝青、「…赤 UEX-22」＝赤。英名も付ける）を、同じカードセット・同じ基準価格（1,000円）・公開・在庫3で、カード商品CSV登録→在庫の承認→商品公開CSV登録→フィード作成（手順3）まで進める（UTH-01 の準備P1〜P3・手順1〜5と同じ操作）。操作：本店で「シナリオ試験検索カード」と検索し、並び順で「色順」を押す。期待値：一覧の表示部分だけが読み直され、「色順」が太字で押せなくなる（設計書 0303 3-2）。順序は白→青→赤（新実装は色の並びの番号の昇順で、色の並びのマスタは 無色・白・青・黒・赤・緑 の順。同じ色の中はカード名の順）。色の並びの数字を文字として並べたときに順序が崩れないかを、実際の順で記録する。発売日順は、カードセットのリリース日が違う2セットのカードで、UTH-01 の手順11と同じ操作（リリース日の新しいセットが上）で確かめる |
| R7 | トップページのタグ検索・商品詳細の同名商品検索（0303 は対象外、新実装はユニサーチを通す） | 準備：同名商品検索はカード商品の詳細だけに出る（0303「商品詳細」。同じカードの番号で探す。グッズの商品A・Bには出ない）。カード登録CSVでカード1枚（「シナリオ試験検索カード UEX-22 R7」）を登録し、カード商品CSV登録（商品コードは新実装が自動で作る。4規格ができる）→在庫の承認→商品公開CSV登録で本店に公開する（UTH-01 の準備P1〜P3・手順1〜5と同じ操作）。操作：反映前（手順3のフィードの前）に、このカードの商品詳細を開き、同名商品の検索（同じカードの別の言語・状態・セットの商品を探す表示）を行い、商品が出る・出ないを記録する。そのあと手順3のフィードを作り、反映後にもう一度行って記録する。トップページのタグ検索も、反映前後に商品が出る・出ないを記録する。設計書 0303 はトップページのタグ検索と同名商品検索をユニサーチ対象外とする一方、新実装はカードのときユニサーチを通す。反映前の出方（出ない）が設計書とずれるかを記録する（`scenario_list.md` に記録済みの食い違い）。合否は付けない |
