# UEX-07 会員がデッキビルダーでデッキを登録し、公開範囲に応じて見える人・入口が変わる

| 項目 | 内容 |
|---|---|
| 利用者 | 会員（デッキビルダー。システムの外。EC会員でログイン）→ 他の会員・未ログインの人 |
| 目的 | 会員がデッキビルダーからEC会員のIDでログインし、カードを検索して採用カードを選び、公開範囲（公開・非公開・限定公開）を決めて保存する。保存したデッキに、デッキIDが付く。公開は誰でも見られ、非公開は本人だけ、限定公開は閲覧用トークン付きの案内を開いた人と本人だけが見られる。見られないときは、デッキが無いときと同じ「見つからない」の結果になる（0515 A15-01・A15-06〜A15-09・A15-12） |
| 種類 | 正常（組み合わせ表の12行。1行が1回流すテスト1本）＋例外7件（1件ずつ別のテスト） |
| マトリクスの行 | `matrix_UEX-07/matrix.md` のT01（公開範囲＝公開・見る人＝所有者本人・デッキの保存の状態＝確定保存のあとに下書きが残っている）。T02〜T12 と例外EX1〜EX7 は「L3で変わるところ」 |
| もとのシナリオ | なし（業務フローに無い） |

デッキビルダーのアプリ本体の画面は外部サービス（システムの外）なので、見え方は記録だけにする。この試験では、アプリの役を、HTTP の呼び出し（コマンドラインなどの HTTP クライアント。設計書の呼び出し先・ヘッダ・本文を指定して送る。ブラウザの開発者ツールで通信を書き換えることはしない）で務め、EC が返す値（HTTP の結果・応答の本文）と EC の管理画面で合否を付ける。アプリの画面で同じ操作をして確かめてもよいが、その画面の見え方は記録だけにする。

  - 下書きのデッキ名：「シナリオ試験デッキ UEX-07 T01 下書き」（下書きが残っている行だけ）
- 呼び出し先と本文の項目は、設計書の項目名（論理名）で書く。本文の項目の実際の名前は根拠の欄のファイルで確かめる
