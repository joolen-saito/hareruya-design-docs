# UEX-08 デッキビルダーで編集中のデッキを下書き保存し、確定保存する

| 項目 | 内容 |
|---|---|
| 利用者 | 会員（デッキビルダー。システムの外） |
| 目的 | 会員が自分のデッキを開いて編集する。下書き保存では、内容が EC 上の下書きに残り、開き直すと下書きが出る（保存済みのデッキは変わらない）。確定保存では、下書きが消えて、公開範囲に従って反映される。他人のデッキは更新できない（0515 A15-10） |
| 種類 | 正常（下書き保存→確定保存の1本）。例外（確定保存時の整合性エラー・所有者でない・存在しない・アクセストークンなし）と、即時保存の指定の書き方は「L3で変わるところ」 |
| マトリクスの行 | 組み合わせ表は作らない（因子は即時保存の指定の有無だけで、ほかと効き合わない）。L3の値は「L3で変わるところ」の V1〜V5 |
| もとのシナリオ | なし（業務フローに無い） |

デッキビルダーのアプリ本体の画面は外部サービス（システムの外）なので、見え方は記録だけにする。この試験では、アプリの役を HTTP の呼び出し（UEX-07 と同じ。コマンドラインなどの HTTP クライアントで、設計書の呼び出し先・ヘッダ・本文を指定して送る）で務め、EC が返す値（HTTP の結果・応答の本文）で合否を付ける。

## L3で変わるところ（組み合わせ表は無い。L3欄の値）

1回ずつ別のテストとして流す。どの行も準備P1と手順1を通り、終わったら手順8で試験のデッキを削除する。

| 行 | 条件 | 変わるところ |
|---|---|---|
| V1 | 即時保存の指定の書き方：偽を明示する／真の文字（「true」「false」などの書き方） | 手順2を、即時保存＝偽（false）を明示して呼び出す。手順2〜4と同じ結果（下書き保存。保存済みは変わらない）になる（設計書 A15-10：偽または指定が無いときは下書き）。続けて手順5を、即時保存＝真（true）で呼び出す（手順5と同じ結果）。数字の「1」「0」など別の書き方は、設計書に定めが無いので確かめない |
| V2 | 確定保存時の整合性エラー（HTTP 400） | 手順2のあと（下書きがある状態）に、手順5を、採用カードのメインボードの「生真面目な補充兵」の採用枚数を0にして呼び出す（即時保存＝真）。HTTP 400（入力不正）で、処理結果コードと検証エラーの内容が返る（設計書 A15-10：採用カードまたはデッキ本体の整合性検証に失敗したときは入力不正）。続けて手順3の参照を呼び出すと、下書き（「…下書き」・3枚）のまま。手順4の自分のデッキ検索は、保存済みの「…保存済み」のまま（確定保存に失敗したので、保存済みのデッキも下書きも変わらない） |
| V3 | 所有者でない（HTTP 401） | 手順2を、会員2のアクセストークンで呼び出す（会員1のデッキID）。HTTP 401・メッセージ「Authentication failed」（設計書 A15-10：対象デッキの所有者でない）。続けて手順3の参照（会員1）で、デッキ名は「…保存済み」のまま（下書きは作られていない）。同じく手順5を会員2で呼び出しても HTTP 401で、デッキは変わらない |
| V4 | 存在しないデッキ（HTTP 404） | 手順2を、存在しないデッキID（例：99999999）で呼び出す。HTTP 404。メッセージは、設計書（A15-10）では「The deck does not exist」。新実装は「Deck is not found」を返す作りに見える（違えば不合格として記録。食い違いに書く） |
| V5 | アクセストークンが無い・不正（HTTP 401） | 手順2を、認証ヘッダを付けずに呼び出す。HTTP 401・メッセージ「Access Token is incorrect」（設計書 A15-10：トークンが無い、署名が不正、該当するプレイヤーが無い）。署名を崩した値（アクセストークンの途中を書き換えたもの）を付けても同じ |

例外（組み合わせ表が無いので、L3の値として扱う）：なし。
