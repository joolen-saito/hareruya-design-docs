# UEX-19 会員がデッキビルダーで条件を絞ってデッキを探し、ページごとに見る

| 項目 | 内容 |
|---|---|
| 利用者 | 会員（デッキビルダー。システムの外）→ EC（API） |
| 目的 | 会員がデッキビルダーで、フォーマット・アーキタイプ・大会名・プレイヤー名・順位・日付などで絞り込み、公開検索または自分のデッキ検索を実行する。条件に一致するデッキが作成日時の新しい順に1ページ分（既定20件・最大100件）返り、総件数はページの指定で変わらない。大会デッキとユーザーデッキは個別に含める・除くを選べ、両方を除くと空の一覧と総件数0が返る。公開検索は条件に一致しなくても成功（200）で空の一覧を返す |
| 種類 | 正常（1本）＋ L3の具体例（組み合わせ表は無い。1つずつ別のテストにする） |
| マトリクスの行 | なし（組み合わせ表は無い）。L3 は `scenario_list.md` の UEX-19 の L3 欄の項目を1つずつ別のテストにした。公開範囲に応じて何が出るか（デッキを1件開く・公開検索・自分のデッキ検索での見え方）は `matrix_UEX-07/` で確かめる |
| もとのシナリオ | なし（業務フローに無い）。設計書 0515 API_デッキビルダー「デッキ情報検索」（A15-13） |

デッキビルダーの画面の見え方は外部サービスなので記録だけにし、合否は EC が返した値（応答の件数・デッキの並び・メッセージ）で付ける。EC の応答は、デッキビルダーが送るのと同じ検索の要求を、試験担当者が用意する HTTP クライアントで EC に送って読む（デッキビルダーの画面に出た一覧との違いは記録）。

## L3で変わるところ（組み合わせ表は無い。1つずつ別のテストにする）

手順の番号は上の「操作の流れと期待値」。どの行も、前提・準備P1のデータのまま、検索の条件だけを変える。大会名を絞らない検索は、環境にある別のデッキも出るので、期待値の件数は「この試験のデッキに限ると」と読み、必ず大会名か名前で絞る。

| 行 | 条件（`scenario_list.md` の L3 欄の項目） | 変わるところ |
|---|---|---|
| R1 | 大会デッキ・ユーザーデッキの含める・除く | 条件：デッキ利用者ID＝会員のデッキユーザーID。「大会デッキを含める」を除くにする：総件数 1（U1）。「ユーザーデッキを含める」を除くにする（大会デッキは含める）：総件数 0・空（この会員のデッキはユーザーデッキだけで、除かれるため）。両方を除くにする：空の一覧・総件数 0・成功（200）。含めるかの指定に空文字・0・false を入れたときは「除く」になり、指定が無いときは「含める」 |
