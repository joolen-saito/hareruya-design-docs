# UEX-03 記事や通販のカード画像にマウスを重ねると、カードの商品情報がポップアップで出る

| 項目 | 内容 |
|---|---|
| 利用者 | 記事サイトの読者・お客様 → EC（画面から呼ぶAPI） |
| 目的 | 記事（または通販）のカード画像にマウスカーソルを置くと、画面の仕組みが EC に商品情報を問い合わせ、カードの商品名・販売価格・在庫数・状態・商品詳細へのリンクを含む商品情報が返る（0502 A02-01〜A02-04）。返るのはシングルカードだけで、グッズ・サプライや存在しない商品は該当なし（404）になる |
| 種類 | 正常（商品IDで日本語）。言語・商品IDの種類・カード情報・グッズ・存在しない商品は「L3で変わるところ」 |
| マトリクスの行 | 組み合わせ表は作らない（因子は呼び出しの種類だけ）。L3の値は「L3で変わるところ」の V1〜V6 |
| もとのシナリオ | なし（業務フローに無い） |

マウスカーソルを置くと呼び出しが起きる側（記事サイトの画面・外部のスクリプト）は外部サービス（システムの外）なので、見え方は記録だけにする。この試験では、その呼び出しを、ブラウザのアドレス欄に設計書の「EC-CUBE側通信URL例」の形のアドレスを入れて開くことで再現し、EC が返す値（応答の本文とHTTPの結果）を、EC の管理画面・商品詳細で見える同じ商品の値と照らして合否を付ける。

## 前提

- 共通の決まり：`../L4を流すときの共通の決まり.md` を先に読む（試験データの名前にシナリオIDを付ける・共有の設定は元に戻す・バッチの起動・店舗の読み替えなど）
- 試験では商品を作らず、開発環境にある商品を使う（呼び出しは読み取りだけで、データを書き換えない）。用意する値（開発環境のダンプ 2026-09-07 の値。設計書の値ではない。流す前に準備P1で確かめ、違うときは環境にある同じ性質の商品に読み替えて控える）

| 値 | 内容 |
|---|---|
| A | 商品ID 14357：《生真面目な補充兵/Solemn Recruit》[AER]（シングルカード。公開中）。規格は日本語と英語それぞれに NM・SP・MP・HP の8つ。カードID 22。旧商品ID「AER000022JN」、旧英語商品ID「AER000022EN」。設計書の例（カードID 22・商品ID 14357・旧商品ID AER000022JN）と同じ |
| B | 商品ID 22498：メタルストレージ KM-L01 Silver（グッズ・サプライ。シングルカードではない。公開中） |
| C | 商品ID 99999999（存在しない商品） |

- 呼び出し先：設計書 0502 の「EC-CUBE側通信URL例」の形。日本語は「開発環境の本店のアドレス」＋日本語のパス＋設計書の商品情報取得の呼び出し先に、商品ID・カードID・旧商品IDのいずれかを渡す形（渡し方は、根拠の欄の設計書の例のとおり）。英語は日本語のパスを英語のパスに替える。設計書は言語の指定の値を「jp」と書く（EC-CUBEサーバのURLでの表記）。呼び出す直前に「根拠」の欄の設計書の例とアドレスの形を照らして組み立てる。認証は不要
- 呼び出しは本店の在庫（本店の在庫と販売価格）で答える作り（新実装）。店舗の読み替えは要らない（本店＝店舗ID 1）
- 画面の名前・文言は設計書の文言を期待値にし、新実装の文言が違えば不合格として記録する。応答の本文は、設計書の項目名（論理名）で書く

## L3で変わるところ（組み合わせ表は無い。L3欄の値）

1回ずつ別のテストとして流す。どの行も準備P1・P2を通る。

| 行 | 条件 | 変わるところ |
|---|---|---|
| V1 | 言語：英語 | 手順1で、英語のパスで商品ID 14357 を呼ぶ。返る規格はP2で決めた英語の呼び出しの規格（在庫・言語・状態の優先の順。英語の規格に在庫があれば言語コードは英語。英語の規格が全て在庫0で日本語に在庫があるときは日本語の規格が返る）。手順2：商品詳細URLは英語のページ（設計書は遷移先の言語を定めない。新実装は要求した言語の商品詳細へ進む。記録） |
| V2 | 商品IDの種類：旧商品ID（0502 A02-03）。日本語の旧商品ID（AER000022JN）と、英語の旧英語商品ID（AER000022EN）。言語は日本語・英語 | 手順1で、旧商品IDを渡して呼び出す。結果は正常で、商品ID 14357 の商品情報（値Aと同じ商品）が返る。旧商品IDは、カードの旧商品IDと旧英語商品IDのどちらか一方に一致すれば対象になる（設計書の現行仕様）。返る規格は旧商品IDの優先順（特殊カードセットでない・プロモでない・カードセットのリリース日が新しい・Foilでない・指定言語…）で選ばれ、複数の商品が該当するときは先頭の1件（値Aのカードには、ほかのカードセットの商品［C20 など］も紐づくので、商品IDが14357でない商品が返ることがある。返った商品が、リリース日の新しいほうの商品かを管理画面で照らして記録する）。設計書の項目表（A02-03）にはFoilフラグがあるが、新実装は旧商品IDの結果にFoilフラグでなくベルトのアドレスを入れる作りに見える（食い違いに書く） |
| V3 | 商品情報ではなくカード情報（0502 A02-02）：カードID 22 | 手順1で、カードIDを渡して呼び出す。結果は正常で、カード22の商品情報が返る（商品ID・商品名・販売価格・在庫数・状態・商品詳細URLなど。設計書 A02-02 のレスポンスデータは、商品情報のFoilフラグの代わりに帯のアドレスを持つ）。返る規格は在庫のある規格を先に、指定言語、Foilでないもの…の順（現行仕様）。V2と同じく、複数の商品が該当するときは先頭の1件 |
| V4 | グッズ・サプライ（シングルカード以外）：商品ID 22498（値B） | 手順1で値Bを呼び出す。結果は該当データなし（404。設計書 0502 A02-01 のステータスコード）。応答の本文は、設計書（表示メッセージの節）では「Not Found」。商品情報は返らない（設計書：商品情報を出力できるのは、シングルカードのみ） |
| V5 | 存在しない商品：商品ID 99999999（値C） | V4と同じ（該当データなし。404）。商品IDの形が正しくない（数字でない・0）ときも該当なし |
| V6 | 言語コードが「ja」「en」以外 | 手順1で、言語を別の値にして呼び出す。商品ID 14357 の商品情報（A02-01）は、設計書が言語コードを「ja」「en」のいずれかとするので、該当データなし（404）になる見込み（新実装の動きを記録。設計書の別の呼び出しは言語が省略のとき英語。V3・V2は省略時に英語として扱う） |

例外（組み合わせ表が無いので、L3の値として扱う）：「EC-CUBE側通信URL例」の形（画面の仕組みが呼ぶ形）で該当なしのとき、新実装は結果が正常（HTTP 200）で、本文に処理結果コード404・メッセージ「Not Found」を入れる作りに見える（設計書の例に当該の結果の定めは無い）。V4・V5を2通りの呼び出しで確かめ、HTTPの結果と本文を記録する（設計書の404に合うのは、設計書のエンドポイントの形で呼んだとき）。

## 判断待ち

なし。

記録（判断待ちではない。合否は付けず、実際の画面・値を記録する）：
- 記事サイト・通販の画面でマウスを置いたときのポップアップの見え方（位置・デザイン）は外部の画面なので記録だけ。設計書にも見え方の定めは無い
- 設計書 0502 の呼び出し先（API サーバのパス）は「外部から API サーバに直接アクセスはできない」と書き、EC-CUBE 経由の通信URL例を示す。新実装は両方の形を EC で受ける。どちらの形で呼んでも、返る値が同じかを記録する
- 在庫数・販売価格は環境の値で変わる。合否は、管理画面・商品詳細に出る同じ規格の値との一致で付ける

設計書との食い違い（起票しない）：
- 該当なしのときの応答：設計書のエンドポイントの形では HTTP 404、画面の仕組みが呼ぶ形（EC-CUBE側通信URL例）では新実装が HTTP 200 の本文で処理結果コード404を返す作りに見える（V4・V5で画面で確かめる）。設計書の例に該当なしの結果の定めは無い
- A02-03（旧商品ID）の応答：設計書はFoilフラグ、新実装は帯のアドレス（V2）
