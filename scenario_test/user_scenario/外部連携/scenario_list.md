# 外部連携：シナリオ一覧（L2）

WordPress（記事サイト）への連携、デッキビルダーのAPI連携、ポイントグランター（PointGranter）連携、プリンタ（スタック用紙）の4系統に、ユニサーチ（商品検索・サジェスト・購入完了タグログのサービス。2026-11-05 作業一覧2 の 3-5 で追加）を足した5系統について、設計書の処理を1行ずつ洗い出し（`## 連携の網羅`）、既存のシナリオで確かめられているものはそのIDを書き、足りないものだけを UEX のシナリオ（L2）として足した（2026-11-05 依頼者指示）。MTGバイヤー（買取端末アプリ）は別フォルダ（UMG）。

シナリオ1本は「起点の業務イベントから、業務として完了した状態になるまで」とする。担当者が替わっても切らない。日をまたぎ、システムの状態が何かを待つもの（バッチが次に動くまで古い一覧のまま、など）は別の1本にする。外部システムの側（WordPress の管理画面・記事サイト、デッキビルダーのアプリの画面、ポイントグランターの端末、プリンタ本体）の操作は「システムの外」とし、ECが送る・受ける値と、EC側で見える結果を期待値にする。前提データ（会員・商品・店舗・デッキ・記事・プリンタの設定などのマスタ）はシナリオから外す。

| 階層 | 単位 | 外部連携での置き場所 |
|---|---|---|
| L1 業務領域 | シナリオのグループ | 外部連携（記事サイト・デッキビルダー・ポイントグランター・プリンタ） |
| L2 シナリオ | 起点イベント→業務完了 | `## シナリオ一覧` の1行 |
| L3 バリエーション | 条件違い・例外 | `matrix_UEX-07/`（UEX-07）・`matrix_UEX-15/`（UEX-15）と、各行の「L3」欄 |
| L4 ステップ | 画面操作と確認 | （まだ書かない） |
