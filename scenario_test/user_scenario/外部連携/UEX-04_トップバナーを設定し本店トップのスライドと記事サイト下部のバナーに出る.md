# UEX-04 トップバナーを設定し、本店トップのスライドと記事サイト下部のバナーに出る

| 項目 | 内容 |
|---|---|
| 利用者 | 顧客戦略チーム（管理画面）→ お客様（本店トップ）→ 記事サイト（システムの外。EC のAPIを呼ぶ） |
| 目的 | 顧客戦略チームが管理画面のトップバナー管理で、バナー画像のアップロードと、バナー設定（画像URL・リンク先URL・言語・表示タイプ・画像alt属性・並び順）の保存をする。設定したバナーが、並び順の小さい順に本店トップのスライドに並ぶ（最大10件）。記事サイトの各ページ下部のバナー部分が呼ぶ EC のAPIには、同じバナーが言語別の一覧とバナーID別に、表示タイプも含めて返る（0213 M16-01・0516 A16-01・A16-02） |
| 種類 | 正常。存在しないバナー・言語コードの不備・画像のアップロードの不備と削除は「L3で変わるところ」 |
| マトリクスの行 | 組み合わせ表は作らない（言語・表示タイプ・画像URLが空・11件以上の出し分けは、業務フローが分かれないので外した。2026-11-10 依頼者決定）。L3の値は「L3で変わるところ」の V1〜V6 |
| もとのシナリオ | なし（業務フロー11 ＃1-5 のセールバナーの差し替えは、価格管理 UPC-01 がこの画面で行う。業務フローの外） |

記事サイトの側（バナーを載せる画面）は外部サービス（システムの外）なので扱わない。記事サイトの役は、ブラウザのアドレス欄に設計書 0516 の呼び出し先を入れて開くことで務め、EC が返す値（応答の本文とHTTPの結果）で合否を付ける。

## 前提

- 共通の決まり：`../L4を流すときの共通の決まり.md` を先に読む（試験データの名前にシナリオIDを付ける・共有の設定は元に戻す・バッチの起動・店舗の読み替えなど）
- 共有の設定を一時的に変える：トップバナーの行は、開発環境で全員が使う設定（本店トップのスライドに出る）。**流す前に、トップバナー管理の1行目と2行目の今の内容（画像URL・リンク先URL・言語・表示タイプ・画像alt属性・並び順）を控え、終わったら控えた内容に戻し、戻ったことを管理画面と本店トップで確かめる**（共通の決まり）。ほかの行は触らない
- 画面の仕様：トップバナー管理は、保存のたびに各行の並び順の値を昇順に並べ直して、1から始まる連番を行に割り振る（新実装・設計書の現行仕様）。このため、保存してもほかの行の並び順の値を変えずに、1行目・2行目の中身だけを入れ替える（並び順の値はその行の連番のまま「1」「2」のままにする）。並び順の欄が重複したり空になったりすると保存できない
- 用意するデータ（試験用の値。設計書の値ではない）
  - 担当者：管理画面で、データ管理（トップバナー管理）を使える顧客戦略チームの担当者
  - 画像ファイル：JPEG（520000バイト以下。例：幅800×高さ450。試験で作る）。ファイル名の後ろにシナリオIDを付ける
  - 設定する値（バナー1・バナー2。流すときは画像alt属性の後ろにシナリオIDが付く）

|---|---|---|---|---|---|---|
| バナー1（1行目に入れる） | 手順2でアップロードした画像のURL | `https://replace-dev.hareruyamtg.com:8443/ja/` | 日本語 | 表示 | シナリオ試験バナー1 | 1 |

  - 画像URL・リンク先URLに試験用でないアドレスを入れない。管理画面のアドレスを含むURLは入れられない（M16-01-MSG-013）

- 手順で使う呼び出し先（設計書 0516）：トップバナー情報取得（バナーIDを渡す）・言語コードに紐づくトップバナー一覧の取得（言語コードを渡す）。いずれも「開発環境の本店のアドレス」の後ろに設計書のエンドポイントを付けて呼ぶ。認証は不要
- 画面の名前・ボタン名は新実装の表示で書く（設計書の名前が違うときは、期待値のところに設計書の名前を添える）。メッセージの文言は設計書の文言を期待値にし、新実装の文言が違えば不合格として記録する

## L3で変わるところ（組み合わせ表は無い。L3欄の値）

1回ずつ別のテストとして流す。どの行も準備P1・P2を通り、終わったら控えた内容に戻す。

| 行 | 条件 | 変わるところ |
|---|---|---|
| V1 | 存在しないバナー（A16-01） | 手順5で、バナーIDを「99999999」にして呼び出す。結果は該当データなし（404）で、本文はコード「404」とメッセージ「Not Found」の2項目（設計書の現行仕様と表示メッセージ）。バナーIDを付けないパス（IDの無い形）で呼ぶと、HTTPの結果が404になる（設計書の現行仕様） |
| V2 | 言語コードが無い・存在しない（A16-02） | 手順6で、言語コードを「ZZ」など存在しない値にして呼び出す。結果は該当データなし（404。設計書 0516 A16-02：言語コード未設定・存在しない）。本文の文言は設計書に定めが無い（記録）。言語コードを小文字（jp）で呼んでも、手順6と同じ内容が返る（記事サイトは小文字で呼ぶ。新実装の動き。設計書の例は大文字で、記録） |
| V3 | 画像のアップロードの不備：画像ファイルを選ばない | 手順1で、ファイルを選ばずに「アップロード」を押す。ファイルの欄の下に「画像ファイルを選択してください。」が出て、送信されない・画面に留まる（M16-01-MSG-010）。画像の一覧は変わらない |
| V4 | 画像のアップロードの不備：GIF・JPEG・PNG以外／520000バイトを超える／店舗を選ばない | 手順1で、(a) テキストファイルを選ぶ：「ファイルがGIF・JPG・PNGではありません。」が出て画面に留まる（M16-01-MSG-011）。(b) 520000バイトを超えるJPEGを選ぶ：「ファイルサイズは{{ limit }}以下にしてください。」の上限の値を埋めた文が出て画面に留まる（M16-01-MSG-012。埋め込まれる値の書き方を記録する）。(c) 店舗を選ばずにアップロードする：「店舗が選択されていません。」が出て画面に留まる（M16-01-MSG-008）。いずれも画像の一覧は増えない。設計書 M16-01 の「アップロードが成功してもトップバナーの登録内容は更新しない」ので、1行目・2行目の内容も変わらない |
| V5 | 並び順が空・重複（保存の不備） | 手順3で、1行目の並び順を空にして「バナー設定」を押す：「並び順が空の項目があります。」が出て保存されない（M16-01-MSG-014）。続けて、1行目の並び順を「2」にする（2行目も「2」）：「並び順が重複しています。」が出て保存されない（M16-01-MSG-015）。本店トップ・呼び出しの結果は、手順3の前のまま |
| V6 | 画像の削除 | 手順2のあと、一覧の、いま上げた画像の「削除」を押す：確認の表示「一度削除したデータは元に戻せません。削除してもよろしいですか？」が出て（M16-01-MSG-016）、「OK」で「削除しました」が出て（M16-01-MSG-005）、一覧から消える。ほかの人の画像は消さない。バナー1・バナー2が、削除した画像のURLを使っているときは、削除したあとスライドの画像が表示されなくなる（画像は消えるがバナーの設定は残る。設計書 M16-01：削除はファイルだけで、登録内容は更新しない）。この手順は手順3〜6のあと、終わったあとの確かめの前に流す |

記録（判断待ちではない。合否は付けず、実際の画面・値を記録する）：
