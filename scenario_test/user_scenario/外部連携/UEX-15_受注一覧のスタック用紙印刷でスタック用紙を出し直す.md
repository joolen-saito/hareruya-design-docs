# UEX-15 受注一覧の「スタック用紙印刷」でスタック用紙を出し直す

| 項目 | 内容 |
|---|---|
| 利用者 | 店舗チーム（管理画面の受注一覧）→ プリンタ（Epson。システムの外）→ EC（API） |
| 目的 | 紙を無くした・汚した、または自動で出なかったため、店舗チームが受注一覧で受注を選んで「スタック用紙印刷」を押す。「印刷予約を受け付けました。」が出る。予約を受け付けた時点で、注文受領の受注だけが「ピック中」になって注文確定日が入り、それ以外の受注は対応状況・注文確定日が変わらない。次のプリンタの問い合わせで、対応状況に関わらず印刷される。印刷が成功すると予約が解除され、同じ紙は再び出ない。失敗すると予約が残り、再び出る |
| 種類 | 正常（組み合わせ表の5行。1行が1回流すテスト1本）＋ 例外（EX3〜EX5） |
| マトリクスの行 | `matrix_UEX-15/matrix.md` のT01（受注の対応状況＝注文受領・注文の種類＝店頭受取・プリンタの印刷結果＝失敗・印刷の出し方＝受注一覧で「スタック用紙印刷」を押す）。T02〜T05 と例外EX3〜EX5 は「L3で変わるところ」 |
| もとのシナリオ | なし。業務フロー05 の 4-1（一部の支店は自動で印刷されないので受注一覧から出す）・1-2。注文を確定してから最初に自動で印刷される通常の流れは UOR-01、失敗して再印刷される流れは UEX-14 |

プリンタ本体の操作（用紙を外す・入れる）と、印刷された紙の見た目は「システムの外」。EC 側で確かめるのは、受注一覧の操作の結果（メッセージ・対応状況・注文確定日）と、プリンタが受け取る印刷データ（EC が返した値）・結果を返したあとの対応状況と再印刷の有無・ログである。
