# UXB-05 店頭受取（本店・支店）の注文が、ピック・引き渡し・スマレジの取引を通り、新しい受注として各集計に出る

| 項目 | 内容 |

| 利用者 | お客様 → 店舗チーム → スマレジ → （バッチ）→ 店舗統括 |
| 目的 | 会員が店頭受取を注文し、元の受注が引き渡し済みになり、スマレジの取引から作られた新しい受注が出荷完了になるまでに、在庫・総原価は購入で減ったまま変わらず、新しい受注の明細に元の受注時原価が複製され、日別・月別集計は新しい受注を元の注文日で数えて元の受注を数えず、受注売上分析・期間別販売数も新しい受注だけを計上することを確かめる（J16・J17・J20・J23）。ピック・引き渡しの細部は UOR-01・UOR-02 に任せる |

| マトリクスの行 | `matrix_UXB-16/matrix.md` のT15（入口＝店頭受取（支店）・在庫の入り方＝店舗間の在庫移動・出口＝完了・分析の見方＝日別・月別集計・総原価の按分＝在庫を売り切る・日＝注文と同じ日・ポイント＝使わない・支払＝通販以外の入口の支払方法）。入口A2・A3×出口C1の行：T09・T14・T15。店頭受取の欠品の行：T10（本店）・T17（支店） |

## 前提

- 共通の決まり：`../L4を流すときの共通の決まり.md` を先に読む（試験データの名前にシナリオIDを付ける・共有の設定は元に戻す・バッチの起動・店舗の読み替えなど）
- 店舗：支店は、流す前に既存の店舗から店舗識別子を持つ支店を1つ選び、店舗ID・画面の名前を控えて読み替える（以下「支店A」）。本店は店舗ID 1。開発環境では店舗を新しく作らない。支店の店頭受取は、支払方法が「店頭支払」だけ・配送方法に「スムーズ店頭受取」が無い・ポイント欄が出ない（UOR-01 のT05）
- 用意するデータ（試験用の値。名前は流すとき後ろに「UXB-05」を付ける）
  - 会員：試験 五郎（`uxb-05@example.test`）。国内の住所を登録済み。スマレジの会員とECの会員が紐付いている（UOR-02 の前提）
  - 商品：グッズ「シナリオ試験グッズV」（商品コード `UXB05-G01`・販売価格10,000円（税込）・本店・支店Aとも公開・販売制限なし）
  - 在庫（総原価の按分E3）：支店AのEC在庫を、店舗間の在庫移動（出庫元は本店。UXB-14 の準備P1（出庫元の在庫の仕入れ・承認）と手順1〜8）で3点・総原価1,500円にする。3点買うと在庫0・総原価0円、受注時原価1,500円（残りの総原価の全部）
  - 注文：支店Aの店頭受取で数量3（商品金額合計30,000円）。お支払い方法は「店頭支払」。送料・手数料の値は注文画面に出た値を控える（店頭受取の送料は設計書に値の定めが無く、実際の表示を記録する。以下「送料S・手数料C」）
  - 店舗チームの担当者：管理画面とスマレジのレジを使える。支店Aの受注を編集できる権限
- 日別・月別集計・受注売上分析・販売数は、同じ日に他の試験の受注も入るので、準備で控えた値との差で合否を付ける（受注売上分析は商品名で絞れるので値そのものを見る）
- 画面の名前・文言は新実装の表示で書く。設計書の名前と違うときは「（設計書：…）」を添える
