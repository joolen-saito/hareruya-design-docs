# 業務横断：シナリオ一覧（L2）

シナリオ1本は「起点の業務イベントから、業務として完了した状態になるまで」とする。ここでは、業務ごとのシナリオ（通販・店頭受取受注管理・店頭買取・ネット買取・在庫管理・仕入れ業務・商品登録・編集・価格管理・イベント管理・分析・集計）を**区間**としてつなぎ、同じデータ（商品・規格・数量・金額・在庫数・総原価・状態・販売数・ポイント）が区間のつなぎ目で正しく引き継がれ、業務が通しで完遂するかを確かめる（IPA「高信頼化ソフトウェアのための開発手法ガイドブック」6.3.2 の「業務データ」の軸、観点 SV-01-02・SV-01-06・SV-04-04・SV-09）。

- 各区間の中の細かい条件違い（配送方法・支払方法・承認の条件など）は、それぞれの業務のシナリオとマトリクスに任せ、ここでは重ねない。ここで見るのは「つなぎ目で値の引き継ぎ方が変わるもの」だけ
- 日をまたぎ、システムの状態が何かを待つもの（買取の入庫待ち、承認待ち、移動中、集計のバッチ待ち）は、AUTHORING.md の単位の決まりどおり、業務ごとのシナリオ（UKA-05・UZK-07 など）が別の1本として切ってある。UXBはその別々のL2を、区間として「つないだ連鎖」であり、待つ位置は区間の境目になる。境目ごとに、待つ間の確かめ（まだ在庫に入らない・まだ集計に出ない）を期待値に入れる（例外E2・E3・E5・E7）。UXB自体は1本のL2ではなく、区間のL2を連ねた通しの流れとして数える
- 前提データ（会員・商品・店舗などのマスタ）は、シナリオから外す。ただし、区間をつなぐ商品の在庫数・総原価・価格は、通しの手順の最初に控える
- 区間のつなぎ目には J01〜 の番号を付け、`## つなぎ目の網羅` に1行ずつ置く

| 階層 | 単位 | 業務横断での置き場所 |

### UXB-16 組み合わせ（`matrix_UXB-16/`）

1行が1本の通しのシナリオ。行ごとに、在庫の入り方（B）の区間→入口（A）の区間→出口（C）の区間→分析（D）の区間を、上のシナリオから選んで通す。区間のつなぎ目の期待値は `matrix_UXB-16/README.md` の「期待結果の決まり」に書いた。

### 設計書との食い違い（設計書の不足。起票はしない）

- 通販の出荷完了後の取り消し（返品）：通販の業務フロー16・17に手順が無い。0203 受注情報編集は状態を限らず「キャンセル：在庫・使用ポイント・付与ポイントを戻す」と書き、新実装は出荷完了からのキャンセルを許す。UXB-03は設計書の文で作った
- ついで買い・店頭購入の受注時原価：設計書は「スマレジ側からは原価情報を取得しない」とだけ書き、日別・月別集計の原価は「受注に保存されている受注時原価の合計」。ついで買い分の原価をどう扱うか（0円で粗利益高に含めるか）は書かれていない。新実装は原価を入れない
- 欠品登録で減る原価：0203 受注情報編集は「在庫調整による減少（欠品）は在庫数を減らすことと合わせ、該当在庫の原価も減らす」と書く一方、別の行で「総原価・総在庫は変動しないが、廃棄により欠品のデータを作成する」と書き、0202 別添は「いったん在庫を戻して欠品として減らす」（正味ゼロ）と書く。通販の裁定R2に従い「在庫・総原価は変わらない」にした
- 店頭受取系の受注に欠品登録をしたとき、スマレジに登録済みの商品（バーコードを印刷したまとめ商品）の内容・金額が更新されるか：0203・0505 に記述が無い（判断待ち1）
- 店頭商品（スマレジの在庫）を売る店頭購入（スマレジだけの取引）を作るシナリオは、スマレジ連携のUSM-01（購入パターン8・9）、返品はUSM-02で作られた。UXB-10の店頭商品の販売・返品の区間はそれを使う（USM-01のついで買い・スムーズ店頭受取を含む複数受注の終点は USM の判断待ち）
- 0505 スマレジ受信処理の「複数の店頭受取受注データが存在する場合は一番若いものを注文日とする」は複数受注の項に書かれ、店頭受取1件の注文日の書き方が無い。対象も「店頭受取注文の注文日」に限られる。新実装は突合した受注（店頭PCを含む）すべてから最も古い日を選ぶので、店頭PCだけを統合する場合の注文日は設計書に無い（UXB-17・※5）
- 日別・月別集計の総売上は「ポイント・クーポンによる値引きは考慮しない（値引き前金額）」だが、スマレジ由来の新しい受注の小計は「取引明細の値引き後小計の合計」（0505）。スマレジ側の明細値引きがあると、総売上が値引き前にならない。設計書にどちらに寄せるかが無い
- 期間別入庫数集計（0402・0404）、日別・月別集計のバッチの時刻など、集計のバッチの実行方法は分析・集計の判断待ち（1・4）のとおり。つなぎ目 J08・J29 の「バッチのあとで見る」の時刻は決まらない

- 今のシナリオ（`scenario_test/scenario/SCN-*`）に、業務をまたぐ通しのものは無い。近いのは、通販の購入→出荷の連鎖（SCN-TSUHAN-購入国内出荷連鎖-921）だけで、UXB-01の①〜③の一部にあたる。ほかは業務ごとに閉じており、在庫・総原価・分析への引き継ぎを確かめるものは無かった
- 各区間の中身は、それぞれの業務のシナリオ（UTS・UOR・UKA・UNK・UZK・USH・UPR・UPC・UEV）と、分析・集計（UAN）にある。ここでは二重に作らず、IDで参照する
- 分析・集計のマトリクス（`matrix_UAN-01`・`matrix_UAN-03`・`matrix_UAN-04` など）は「取引のシナリオの値から手で計算した値と合う」を前提にしている。このフォルダは、その取引の値が前の区間（購入・在庫・原価）から正しく引き継がれることを確かめる
- 結合テストのケース（`integration_test/casegen/cases/`）は、機能ごとの値の確かめ（単体に近い粒度）。このフォルダは機能をまたぐ値の引き継ぎ
