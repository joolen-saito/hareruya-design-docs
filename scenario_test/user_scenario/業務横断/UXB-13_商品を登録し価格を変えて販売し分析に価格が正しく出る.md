# UXB-13 商品を登録し、価格を変更して、販売・分析に価格が正しく出る

| 項目 | 内容 |
|---|---|
| 利用者 | トレードチーム → 顧客戦略チーム → お客様 → 通販チーム → 顧客戦略チーム |
| 目的 | 登録した商品を在庫を入れて公開し、価格を変える前に1件・変えたあとに1件購入されたとき、変更した価格がお客様の画面に出て、購入した受注の価格・受注時価格が購入時点の価格になり、価格を変える前の受注は前の価格のまま受注売上分析・日別・月別集計に出て、販売数が価格調整の判断に戻ることを確かめる（J35〜J39）。価格変更CSVの細部は UPC-05、セールは UPC-01・UPM-02・UPM-06 に任せる |
| 種類 | 正常（代表：販売価格を上げる）。表外の具体例（セールの開始と取り下げ）あり |
| マトリクスの行 | 該当する行なし（`matrix_UXB-16/` に価格の因子が無い）。表外の具体例として扱う |
| もとのシナリオ | 区間：UPR-04またはUPR-06（登録）→UPR-05（在庫・公開）→UXB-01の手順1〜9（旧価格で購入）→UPC-05（価格変更。セールの開始は UPM-02、取り下げは UPM-06）→UXB-01の手順1〜9（新価格で購入）→UAN-04・UPC-08→UPC-02 |

## 前提

- 共通の決まり：`../L4を流すときの共通の決まり.md` を先に読む（試験データの名前にシナリオIDを付ける・共有の設定は元に戻す・バッチの起動・店舗の読み替えなど）
- 購入する店は本店のEC（店舗ID 1）。配送方法は「ゆうパック」。支払は「登録済みクレジットカード決済」（手数料0円）
- カードの商品コード：カード商品CSVには商品コードの列が無く、新実装が登録のときに自動で作る。流すときは、カード登録CSV→カード商品CSVで登録したあと、商品一覧で実際の商品コードを控え、この L4 の呼び名を読み替える。カード商品CSVは4つの規格（NM・SP・MP・HP）を作る。以降はNMの規格を確かめる
- 用意するデータ（試験用の値。名前は流すとき後ろに「UXB-13」を付ける）
  - 会員：試験 十四郎（`uxb-13@example.test`）。国内の住所・SPLINKSの試験環境のクレジットカードを登録済み。通常の顧客グループ。ポイントは使わない
  - 商品：カード「シナリオ試験カードN」（日本語・NM・非Foil。カード登録CSV→カード商品CSVで登録する）。基準価格・販売価格10,000円（NM）・買取価格100円・割引率「4」（NM100%・SP90%・MP80%・HP70%。価格は基準価格×率を10円単位で切り上げ。SP 9,000・MP 8,000・HP 7,000）・商品公開ステータス「公開」・支店の商品公開ステータス「非公開」。カードセットは開発環境の既存のものから1つ選ぶ（流す前にカードセット一覧で名前を確かめる）
  - 在庫（総原価の按分E1）：NMの規格に在庫変更CSVで10点×仕入単価500円（在庫10・総原価5,000円）
  - 価格変更：基準価格を10,000円から12,000円へ（NM 12,000円。SP 10,800・MP 9,600・HP 8,400）。買取価格は100円のまま
  - 購入：旧価格・新価格とも数量3（旧：商品金額合計30,000円、新：36,000円。どちらも送料無料金額30,000円に届くので送料0円）。受注時原価はどちらも1,500円（旧：5,000×3÷10。新：3,500×3÷7）。旧価格の購入のあと在庫7・総原価3,500円、新価格の購入のあと在庫4・総原価2,000円
  - 顧客戦略チームの担当者：商品管理・商品CSV管理・分析・集計を使える。在庫の承認者（別の担当者）。通販チームの担当者
- 日別・月別集計・受注売上分析・販売数は、準備で控えた値との差で合否を付ける（受注売上分析は商品名で絞れるので値そのものを見る）
- 画面の名前・文言は新実装の表示で書く。設計書の名前と違うときは「（設計書：…）」を添える

## 終わったあとに確かめること

| 確かめる場所 | 期待値 |
|---|---|
| 価格履歴・取込履歴 | 価格が変わった規格にだけ行が増え、価格が変わらなかった規格（買取価格）は増えない（J38）。買取/販売価格履歴の変更前→変更後が10,000→12,000円 |
| 受注の価格 | 注文A＝10,000円・注文B＝12,000円。価格の変更が過去の受注の金額・分析の金額を書き換えない |
| 在庫と総原価 | 価格の変更は在庫・総原価に影響しない（在庫4・総原価2,000円は購入2回の結果）。受注時原価は価格でなく総原価から計算される |

## L3で変わるところ（表外の具体例）

マトリクスに価格の行が無いので、表外の具体例として次を1回ずつ流す。手順の番号は上の「操作の流れと期待値」。

| 具体例 | 条件 | 変わるところ |
|---|---|---|
| セールの開始と取り下げ | 価格を上げる代わりに、セールにして取り下げる | 準備のカードは基準価格20,000円（NM。SP 18,000・MP 16,000・HP 14,000）にする。手順1（通常価格で1件。数量1。商品金額合計20,000円に送料がかかるときは、画面の値を控える）のあと、手順3を、セール用価格変更CSV（販売価格17,000円・買取価格100・セールフラグ「1」。UPM-02 の手順5）に替える。手順4：商品一覧に「Sale」ラベルと価格17,000円が出る。手順5：セール価格で1件購入（UPM-02 の手順6〜12。注文確認メールの金額が注文と一致する。メールの件名・本文の項目は設計書が定めず、注文と一致することだけを期待値にする）。受注の価格17,000円・在庫履歴の受注時価格17,000円。そのあと、セールを取り下げる（セール用価格変更CSV。販売価格20,000円・セールフラグ「0」。UPM-06 の手順1）：「Sale」ラベルが消え、価格20,000円。取り下げたあとの購入（UPM-06 の手順2〜9）は基準価格20,000円。手順6：セール中に買った注文の単価が17,000円のまま変わらない（UPM-06 の手順10）。手順7〜8：受注売上分析は、それぞれの受注時の価格（20,000円・17,000円・20,000円）で集計される |

例外：なし（この L4 の例外は、購入の在庫不足を UXB-01 の例外E1、在庫変更CSVの承認前の在庫を UXB-12 の例外E2に任せる）。
