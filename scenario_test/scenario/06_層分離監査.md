# 層分離監査（システムテスト × 結合テスト）

シナリオテスト（システムテスト層）の観点が、結合テスト層（`integration_test/integration-test-viewpoints.md`）の
観点と重複していないかを監査する台帳。**数字を良く見せるための削除・追加（gaming）は禁止**。
残った重複と、委譲先が存在しない穴は、隠さずここに出す。

## 層の分担

| 層 | 担う観点 |
|---|---|
| 結合テスト（IT） | 機構の検証：権限（IT-15）、必須・形式（IT-22）、重複実行（IT-08）、検索0件（IT-23/IT-14）、画面遷移・バック・リロード（IT-03）、数量・金額の反映（IT-33） |
| シナリオテスト（システムテスト） | 業務の検証：業務経路、業務判断、後続作業、最終業務状態、担当者・部署をまたぐ引き継ぎ |

同じ条件でも、ITが「エラー表示され更新されないこと」を見るのに対し、シナリオは「業務が完了扱いにならず、
どの状態で誰に引き渡されるか」を見る。**期待結果が機構の言葉で書かれているものは、シナリオ層の観点ではない。**

## 1. 残存する機構的観点（委譲候補）— 45件

層分離後もシナリオ側に残っている機構的エッジ。業務フロー本文に `検索` / `権限` の語が実在するため
キーワード一致で採用されているが、**期待結果は機構の言葉のまま**（「0件結果を表示し後続の更新操作へ進ませない」
「権限エラーを表示して対象データを更新しない」）であり、業務の最終状態を問うていない。

| 条件 | 延べ件数 | 重複する結合テスト観点 | 判定 |
|---|---|---|---|
| 検索条件に一致する対象データが存在しない | 41 | IT-23 DB操作/検索/実行結果、IT-14 画面表示/0件 | 要判定（委譲候補） |
| 担当者に必要な権限がない | 4 | IT-15 認証・認可/権限範囲/対象データ | 要判定（委譲候補） |

**解消は2択。台帳を埋めるためだけの残置は禁止。**

- **DELEGATE**: `COMMON_EDGE_CASES` から削除し、`## 他層委譲（結合テスト）` の委譲行のみとする。
  影響: エッジ0件SCNが 83 → 約103 に増える（表示は `異常系=-` になるので嘘は生じない）。
- **REWRITE**: 業務の最終状態を問う期待結果に書き換えたうえでシナリオ層に残す。
  例: 「権限が無い担当者は承認できず、**上長へエスカレーションされ受注が保留状態のまま残る**こと」。
  ただし**その業務経路が業務フローに実在する場合に限る**。実在しないなら DELEGATE。

## 2. 業務フロー根拠のない業務エッジ（無条件採用）— 33件

`edge_cases_for()` は業務辞書ケースが2件に満たない場合、キーワード一致しなくても補充する（`len(selected) < 2`）。
この経路で入った33件は、**業務フローにその条件の記載が無い**。業務的にもっともらしいことと、
そのパターンに必要なシステムテストであることは別なので、個別に判定する。

| 条件 | 件数 | 判定 |
|---|---|---|
| 入出庫数量または棚卸数量に差異がある | 13 | 要判定 |
| 出荷対象商品の在庫が不足している | 5 | 要判定 |
| 外部大会情報と登録対象大会が一致しない | 3 | 要判定 |
| 査定結果に不備または対象商品不一致がある | 3 | 要判定 |
| 振込先情報不備または振込不可が発生する | 3 | 要判定 |
| 仕入れ対象データと商品マスタが一致しない | 3 | 要判定 |
| 仕入れ入庫が重複する | 2 | 要判定 |
| お客様が査定結果を承認しない | 1 | 要判定 |

**解消は2択。**

- **KEEP**: 業務フローに当該分岐が実在する（または業務上必須と業務側が判断する）→ 業務フロー Markdown 側に
  分岐を明記し、`edge_cases_from_branch_rows` が拾える状態にする。
- **DROP**: 業務フローに根拠が無い → 業務辞書から外す。`len(selected) < 2` の補充も撤去する。

なお、これらの期待結果（「完了扱いにせず、在庫数と不足理由を確認できる状態にする」等）は**業務の最終状態**を
問うており、IT-33（数量・金額の計算と履歴整合）とは別物である。重複ではないので、重複を理由に消してはならない。

## 3. 委譲先が存在しない穴 — IT-08（重複実行）297件

`## 他層委譲（結合テスト）` で「同一対象に対して同じ処理を重複実行する」を IT-08 へ委譲しているが、
**`integration_test/*_it_cases.md` 全384ファイルに I/FID=IT-08 のテストケースが1件も存在しない**（実測値 0）。

- 観点マスタには IT-08 の観点が実在する（`integration-test-viewpoints.md`：二重サブミット防止、決済連携/二重実行/再送・戻る）。
- つまり**観点はあるがケースが生成されていない**。委譲は現状「委譲先ゼロ」であり、重複実行は
  どの層でも試験されていない。
- 対処は結合テスト側（`hareruya-integration-test-cases`）で IT-08 のケースを生成すること。
  シナリオ層に戻して機構を二重に持つのは層分離に反する。

また、シナリオが紐づける機能Noのうち一部は `*_it_cases.md` 自体が未整備であり、その機能の委譲行も `未整備` になる。

## 4. 対外説明の注意

`03_カバレッジ表.md` の `実行エッジ数` は **このシナリオで実際に実行する業務分岐の延べ件数**であり、
ユニークな異常条件数ではない。層分離の前後（807 → 268）を同一定義の網羅率として比較してはならない。
減った 539 件は、結合テスト層が機能単位ですでに網羅している機構的確認の重複であり、
業務観点（業務フロー由来・業務辞書・パターン固有）は 224 → 223 でほぼ全量を保持している。
