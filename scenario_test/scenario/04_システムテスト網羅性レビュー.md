## 今回のcodex批判レビュー（要約）

codex（`codex exec --sandbox read-only`, gpt-5.5）の主要指摘と対応:

1. **カバレッジ表が未トレース機能を隠している**（`03` の期待機能不足が全行 `-`）。
   → `05_設計書カバレッジ.md` を新設。`functions/**` の全機能Noを
   `covered / area-covered-feature-uncovered / out-of-scope:* / excluded-ph2 / source-backed-uncovered(要判定)` に分類。
2. **非EC-CUBE業務にEC-CUBE画面を誤割当**（例: `SCN-TSUHAN-お客様対応メーラーで-006` に F04/M05）。
   → 強いマーカー（EC-CUBEを使わない/メーラーでのみ/Thunderbirdでのみ、名称「メーラー」）検出時は機能No自動割当を抑止し、観測点を外部側に。
3. **お客様EC購入フローの画面割当ずれ**（トップ/商品一覧が F04 に、F03 が未トレース）。
   → `EXPECTED_FUNCTIONS["通販受注管理"]` に F01-01/F03-01/F03-02/F03-04 を追加。
4. **業務固有エッジケースが汎用ケースに潰れている**（貼替/在庫0枚/SPLINKS）。
   → `PATTERN_EDGE_CASES`（パターン名部分一致）を最優先で適用。
5. **在庫管理の番号重複で追跡が曖昧**（#7/#8 等）。
   → `番号重複警告` 列で可視化し、トレースは業務フローキーで識別。

## 正常系ステップ先頭の是正（見出し行の除外・2026-07-06）

従来、正常系ステップ1がパターン見出し行（＝業務名の繰り返し「…作業を行う」）になり、実際の最初の作業が
ステップ2にずれていた（例: スタン落ち商品変更で、本来先頭の「対象商品データダウンロード」が2番目）。
`is_pattern_header_row`（＃番号がパターン番号と一致＝見出し）を導入し、下位ステップ（N-M）がある場合は
見出し行を正常系ステップから除外。実作業が先頭になった。併せて丸数字サブ番号（10-①/② 等）の
番号除去も是正（「-①として…」の表示崩れを解消）。この結果、見出し疑似ステップが約62件減り、
テスト項目は 834→772。下位ステップを持たないパターン（欠品対応の一部・お客様対応(EC-CUBE)等）は
見出しが唯一のステップのため維持する。
