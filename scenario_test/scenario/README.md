# 業務シナリオテスト

ゴールは、システムが業務に必要な品質を満たし、実際の業務が開始から完了まで回ることを判断できるケースにすることです。[目的と完了基準](../システムテストの目的と完了基準.md)に従い、[各経路の必須判定](../coverage/business_goal_review/route_acceptance.tsv)で業務成立を判定します。

2026-10-09に、業務フロー・HTML設計書と前回監査の97指摘を基に、実施手順と準備を修正しました。現在は **129シナリオ・1,574テスト項目・830業務工程**です。

**全項目を無条件に実施可能とする状態には未達です。** 外部原本、業務条件、再現データ等が未確定の項目は保留として明示しています。最新の件数・解除条件は[修正結果と実施条件](../coverage/execution_repairs/README.md)を確認してください。実機の業務テスト結果は含みません。

各SCNは、開始条件・担当者・データパターン・操作・期待結果・データ連鎖を持ちます。商品・注文・移動等の実IDを工程間で引き継ぎ、登録者と承認者を区別します。`ST-*` は論理名で、実在するアカウントや採番IDではありません。

旧IDの連番だけで新項目を同一と判断しないでください。承認等の追加、誤ったオンライン受付・二重削除の整理により、対応先が変わった項目があります。経路を一度実施した証跡で個別項目を照合し、同じ登録・承認を重複実施しません。

資料で確定できない値や外部マクロの列は創作せず、対象工程と解除条件を残しています。未実装・実装違いの既存指摘は実施時の影響確認対象です。期待結果は設計に固定し、実装差を合格の期待値へ変更しません。
