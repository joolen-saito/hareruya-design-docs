# 業務シナリオテスト

晴れる屋バックオフィス業務フローに対する、**業務横断のシナリオテスト**一式。
`markdown/` に出力された業務フローをトレース起点にし、在庫管理だけでなく店頭受取、買取、
イベント、商品登録、価格管理、通販、デッキ登録までを対象にする。

## 位置づけ（V字モデル）
- フェーズ: **システムテスト〜受入テスト**。
- 検証の対応元（トレース起点）: **業務要件＝業務フロー**（`scenario_test/markdown/*.md`）。
  詳細設計ではない。「作ったものが動くか」ではなく「**業務要件を満たすか**」を見る。

## 機能テストとの違い（軸＝業務）
本リポジトリには既に **機能単位**のテストが揃っている（`integration_test/` の
`m04_01〜34` it_cases / e2e_cases、`e2e/` の Playwright）。シナリオテストはこれと別物で、
**一連の業務フローを端から端まで破綻なく完遂できるか**を、複数画面を横断して検証する。
個々の画面の単体挙動は既存の機能ケースに委ね、本層は**つなぎ目と業務的ゴール**を見る。

## 分類（各シナリオで派生させる）
- **正常系（メインフロー）**: 業務が想定どおり完遂する基本経路。
- **代替系（代替フロー・条件分岐）**: 店舗内移動/店舗間移動、分割先既知/不明 等の正当な分岐。
- **異常系**: 入力エラー・権限不足・在庫超過・承認却下・連携失敗 等。

## 記法・方針
- 期待結果は**仕様（業務フロー／基本設計 `functions/`／観点表 `integration-test-viewpoints.md`）由来**で、
  **画面で観測可能なもの**に限る。実装・POM由来の文言やForm制約をオラクル化しない
  （既存 e2e_cases のオラクル独立方針を踏襲）。
- シナリオの各ステップは、対応する**画面(機能No M04-XX)** と **既存機能ケース**へリンクし再利用する。
- アクター＝人（チーム）、画面＝EC-CUBE管理画面、連携確認＝外部システム（スマレジ等）。

## ファイル構成
| ファイル | 内容 |
|---|---|
| `_TEMPLATE.md` | シナリオ仕様書の項目立て（雛形） |
| `00_アクター一覧.md` | アクター/ロール・役割・権限 |
| `01_シナリオ一覧.md` | シナリオID・業務フロー番号・概要・触れる画面・分類・優先度 |
| `02_トレーサビリティ.md` | 業務フロー ⇔ シナリオ ⇔ 画面(M04) ⇔ 既存ケース の対応表 |
| `SCN-*.md` | 個別シナリオ仕様書 |

## ID 体系
`SCN-<業務コード>-<業務>-<連番>`（例: `SCN-ZAIKO-移動-001`, `SCN-ORDER-店頭受取-001`）。
既存の機能テストID `E2E-M04-XX-NNN` とは別系統で、シナリオから各機能ケースを参照する。
