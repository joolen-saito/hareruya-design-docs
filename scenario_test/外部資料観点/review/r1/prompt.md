# レビュー依頼: シナリオテスト観点（外部資料から整理）R1

あなたは独立したレビュアーです。著者（別のエージェント）が、公開資料だけを根拠に「シナリオテストで確認すべき観点」を整理しました。
誤り・根拠の無い主張・抜け・分類の不備を見つけてください。カレントディレクトリにすべての材料があります。

## 前提

- シナリオテスト＝システムテスト〜受入テスト段階の業務シナリオテスト。利用者（顧客・店舗スタッフ・運用者）の視点で、複数の機能・システムにまたがる一連の業務が完遂できるかを、本番相当の環境で確かめるもの。
- 想定する対象: EC サイトの再構築（購入サイト、管理画面、決済・配送・在庫などの外部連携、バッチ、メール通知。EC パッケージをカスタマイズし、現行システムを置き換える）。
- 依頼者の指示で、社内の作成済みドキュメントは見ずに、IPA などの公開資料だけから観点を集めている。

## 対象

- 成果物: `deliverable/シナリオテスト観点_外部資料.md`
- 根拠台帳: `deliverable/evidence.tsv`（列: 観点ID / 参照（抽出行ID）/ 出典ID / 資料内の区分 / 抽出テキストのファイル名 / PDFページ / 資料内の位置 / 原文抜粋）

## 正本（オラクル）

- 公開資料を機械抽出したテキスト: `txt/` 配下。各ファイル中の `=====PAGE n=====` が PDF のページ番号。出典 ID と資料名・URL の対応は成果物の「6. 出典一覧」にある。
  ファイルと出典の対応: youken=S01, saikouchiku=S02, koushinrai=S03, kyokun/*・kyokun_main・kyokun_digest=S04, hikinou_*=S05, jstqb=S06, cf_*=S07, ec=S08, websecurity=S09, credit=S10, caa=S11, a11y=S12。
- `txt/kyokun/` と `txt/kyokun_main.txt` は、文字化けしていた PDF を Adobe-Japan1 の対応表で機械的に復号したもの。2 文字の順序が入れ替わる箇所（例:「客顧」「確格」）があるが、抽出上の癖なので指摘対象外。表の多くは化けたまま。
- `txt/saikouchiku_images.txt` と `txt/koushinrai_images.txt` は、画像だけの表を著者が目視で書き起こしたもの。元の画像は `img/`（saikouchiku_p146.png, sk146_t313.png, saikouchiku_p147.png, saikouchiku_p103.png, saikouchiku_p190.png, koushinrai_p143〜146.png）。画像を開けるなら書き起こしの誤りも確かめてほしい。
- 根拠台帳の原文抜粋は、空白を除いて `txt/` の該当ページに実在することを機械照合済み。照合の仕組みではなく、**抜粋と出典が観点の主張を本当に支えているか**を見てほしい。
- `candidates/*.tsv` は抽出段階の全候補（約 1,150 件）と、観点に入れなかった「除外候補」（理由は備考列）。抜けの判断や、除外の妥当性の判断に使ってよい。

## 使ってはいけないもの

- このディレクトリの外にあるファイルは開かない。
- ネット検索はできない前提。あなた自身の一般知識（JSTQB、ISO/IEC 25010、IPA 資料、特定商取引法など）による指摘は可。その場合は「一般知識による」と明記し、可能なら `txt/` 内の該当箇所を示す。

## 成果物の制約（指摘対象外）

- 単体テスト・結合テストの観点、脆弱性そのものの検査（XSS・SQL インジェクション等の診断）は意図的に対象外にしている（成果物 4 節）。対象外の判断自体がおかしい場合だけ指摘する。
- 「EC での確認例」列は著者による適用例で、出典の主張ではないと明示している。例が観点から外れている・誤解を招く・法令を誤っている場合は指摘する。例が足りないこと自体は指摘しない。
- 個別のテストケースや手順は書かない方針。観点の粒度で止めている。粒度を細かくする提案は出さない。
- 文体（結論を先に置く、平易な語）は意図的。言い回しの好みの指摘は出さない。

## 重点観点

1. **根拠の忠実性**: 各観点の「確認すること」が、引いている原文抜粋・出典の範囲を超えていないか。出典の主張を一般化しすぎていないか。出典 ID・ページの取り違え。1 節「位置づけ」と 2 節の手書きの出典も含む。
2. **抜け**: `txt/` の資料が明示している観点のうち、シナリオテストで確かめるべきなのに成果物に無いもの。とくに S04 T13（業務シナリオテスト）、S05 非機能要求グレードの項目、S01 7.13（総合テスト計画書）、S02 の現新比較・表3.13、S11 の最終確認画面の表示事項、S03 6.3.2。
3. **範囲の妥当性**: シナリオテストで確かめようのないもの（基盤構成・開発プロセス管理など）が観点に混ざっていないか。逆に、除外したもので確かめるべきものが無いか。
4. **分類の妥当性**: 観点どうしの重複、同じ内容が別分類に分かれている、置き場所の誤り。
5. **法令・規格の記述の正確さ**: 特商法（S11）、クレジットカード・セキュリティガイドライン（S10）、JIS X 8341-3（S12）等の記述が原文どおりか。

## 出力形式

指摘が無ければ `NONE` の 1 語だけを出力する。

指摘があれば、1 件ごとに次の形式で書く。重要度の高い順に並べる。最後に件数を書く。

```
### 指摘 N
- 対象: （観点ID または 節名）
- 主張: （成果物に書かれていること）
- 実際: （根拠。`txt/ファイル名` の PAGE 番号と原文の短い引用、または「一般知識による」）
- 判定: 事実の誤り / 根拠の逸脱 / 抜け / 範囲外の混入 / 分類の不備 / 書き起こしの誤り / その他
- 修正案: （結論を先に、一文で）
```
