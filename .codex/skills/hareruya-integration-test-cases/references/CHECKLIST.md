# 結合試験テストケース チェックリスト

## 入力とスコープ

- [ ] 元設計 HTML の扱うこと・扱わないことと試験範囲が一致している
- [ ] `integration-test-viewpoints.md` の観点が、対象ケースまたは対象外観点のどちらかに整理されている
- [ ] CRUD の削除が対象機能に含まれる場合、削除観点を対象外にしていない
- [ ] 操作起点の画面遷移、ポップアップ、確認ダイアログ、ダウンロード、アップロードなどが対象に含まれている

## TSV 構造

- [ ] 1 行目の列見出しが 10 列固定である
- [ ] `I/FID` が `integration-test-viewpoints.md` の `IT-ID` と一致している
- [ ] `テスト観点` が `小項目` または `中項目` 由来である
- [ ] データ行がすべて 10 列である
- [ ] `テストID` がファイル内で一意である
- [ ] `前提条件`・`入力データ/リクエスト内容`・`操作手順/実行方法`・`期待結果／レスポンス` が同一の重複行がない

## 観点カバレッジ

- [ ] 設計書がDB書込み（登録/更新。例: 履歴登録・最終ログイン日時更新）を持つ機能では、本体に IT-23/IT-26（データベースアクセス）のケースがある
- [ ] 通知/WebSocket（`大項目=通知`）の観点は、リアルタイム通知機能でない限り本体に含まれていない
- [ ] 操作手順がDB・認証系で「対象画面を表示する」一律の定型になっていない

## 文体

- [ ] 期待結果が観測可能な結果で書かれている
- [ ] `UI標準` を含まない
- [ ] `設計書に記載のとおり`、`設計どおり` を含まない
- [ ] 期待結果が 1 行 1 判定である

## 検証

- [ ] `format_tsv.py <ファイル> --check` が成功する
- [ ] `rg -n 'UI標準|\.cursor/docs/テスト観点|設計書に記載のとおり|設計どおり' integration_test` で不要表現が出ない
