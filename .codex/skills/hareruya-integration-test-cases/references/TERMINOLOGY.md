# 結合試験テストケース 用語・文体

## 優先度

- `P1`: 認証、権限、登録・更新・削除、決済、在庫、ポイント、外部連携、バッチ結果など、業務影響が大きい確認。
- `P2`: 検索、一覧、表示、CSV、メール、画面遷移、通常の入力検証など、主要導線の確認。
- `P3`: 補助表示、空状態、任意条件、軽微な境界確認など、影響が限定的な確認。

## 期待結果に書かないこと

- `設計書に記載のとおり`
- `設計どおり`
- `UI標準`
- 特定設計ファイル名だけを合格判定にする表現

期待結果は、画面表示、遷移先、HTTP 応答、DB レコード、ファイル出力、メール送信、ログ、ジョブ結果など、試験で観測できる結果で書く。

## 表現ルール

- TSV の期待結果は 1 行 1 判定とする。
- 複数パターンは別行に分ける。
- `または` で合否条件を曖昧にしない。
- パスワード、トークン、秘密鍵などの原値を書かない。
- 文字列長境界は「最大長」「最大長+1」「最小長」「最小長-1」と書く。
- 試行制限は「一定時間内の連続失敗」「制限中の再試行」のように平易に書く。
