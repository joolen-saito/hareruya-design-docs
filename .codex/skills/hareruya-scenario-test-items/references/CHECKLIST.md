# シナリオテスト項目書チェックリスト

## 入力とスコープ

- [ ] 元シナリオ `SCN-*.md` から生成している
- [ ] 各STIの先頭行が `テスト観点=業務経路` の経路全体シナリオテストケースである
- [ ] 経路全体行が元シナリオの `経路ID`、代表 `DP-*`、`最終業務状態` を参照している
- [ ] 経路全体行の `操作手順/実行方法` が、担当者・画面/機能・対象・操作をセル内に具体展開している
- [ ] `元シナリオの正常系実行手順#...を記載順に実行する` のような参照だけの手順がない
- [ ] 正常系の実行手順が `正常系` のテスト項目になっている
- [ ] 代替/異常系の実行手順が `代替系` または `異常系` のテスト項目になっている
- [ ] 代替/異常系が正常系に混ざっていない
- [ ] シードデータと固定IDが前提条件または入力データに入っている
- [ ] 各テスト項目が元シナリオの `経路ID` を前提条件、入力データ、または操作手順で参照している
- [ ] 各テスト項目が元シナリオの `データパターンID` を前提条件または入力データで参照している

## TSV 構造（結合試験テストケースと同一フォーマット）

- [ ] 1行目の列見出しが11列固定である（`機能名 / テストID / I/FID / テスト観点 / 優先度 / テスト項目名 / 前提条件 / 入力データ/リクエスト内容 / 操作手順/実行方法 / 期待結果／レスポンス / 確認対象`）
- [ ] データ行がすべて11列である
- [ ] `期待結果／レスポンス` が「〜されること。」「〜されないこと。」「〜できること。」「〜であること。」のいずれかで終わっている
- [ ] `確認対象` が期待結果とは別列に分かれている
- [ ] `テストID` がファイル内で一意である
- [ ] `機能名`, `I/FID`, `操作手順/実行方法`, `期待結果／レスポンス` が空でない
- [ ] `I/FID` に当該ステップの機能No（分岐は `-`）が入っている
- [ ] 分岐/異常行の `I/FID` は操作文の画面・機能に一致するものだけを出力し、親シナリオの機能Noを丸ごと割り当てていない
- [ ] `## 関連機能No対応概要` に、SCNの期待/紐づけ機能Noが `テスト項目化 / 参照のみ / 対象外` の状態付きで列挙されている
- [ ] 集約TSVは1物理行1テスト項目であり、データ行数が各STIのTSV行数合計と一致している

## 観点カバレッジ

- [ ] 各シナリオに、元シナリオの分類（正常系/代替系/異常系）に対応する主経路のテスト項目が1件以上ある
- [ ] 各シナリオに、元シナリオの最終業務状態を確認する経路全体行が1件以上ある
- [ ] 代替/異常系の実行手順がある場合、対応する `代替系` または `異常系` のテスト項目が1件以上ある
- [ ] CSV/帳票、メール/通知、外部連携がシナリオにある場合、対応する観点が出力されている
- [ ] データ更新を伴うシナリオでは、ステータス、履歴、件数、金額などの観測可能な期待結果がある

## 文体

- [ ] 期待結果が観測可能な結果で書かれている
- [ ] 期待結果が担当者の操作文ではなく、システム結果として読める受け身・状態・可能表現で書かれている
- [ ] `操作手順/実行方法` に担当者、対象画面、固定データ、業務行動が入っている
- [ ] テスト項目名が「誰が何をするか」を業務目線で表している
- [ ] `UI標準` を含まない
- [ ] `設計書に記載のとおり`、`設計どおり`、`要確認` を含まない
- [ ] `何らか`、`必要に応じ`、`適宜` を含まない
- [ ] テスト項目名が具体的で、単なる `正常確認` ではない

## 検証

- [ ] `validate_test_items.py --repo .` が成功する
- [ ] `validate_scenarios.py --repo . --generated-only` が成功し、STI生成元SCNの経路情報が壊れていない
- [ ] `rg -n 'UI標準|設計書に記載のとおり|設計どおり|要確認|UNRESOLVED|何らか|必要に応じ|適宜|\\.\\.\\.' scenario_test/test_items` で不要表現が出ない
