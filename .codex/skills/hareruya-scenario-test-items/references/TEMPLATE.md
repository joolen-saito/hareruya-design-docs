# シナリオテスト項目書テンプレート

## ファイルパス

- `scenario_test/test_items/STI-<SCN-ID>.md`
- 元シナリオは `scenario_test/scenario/SCN-*.md`

## 冒頭概要（結合試験テストケースと同一構成）

各 Markdown は次の情報を含める。

- H1 見出し `# <業務名> — <シナリオ名> シナリオ試験テストケース`
- 元シナリオへの相対リンク（`元シナリオ: ...`）
- テスト観点の方針行
- 期待結果は試験で観測可能な結果で判定する旨・TSV は 11 列固定で `テストレベル` 列を置かない旨
- `## 関連機能No対応概要` 表（`テスト項目化 / 参照のみ / 対象外` の状態、`I/FID` 出力有無、本シナリオでの主な確認範囲または理由）
- `## テストケースTSV` 見出しと定型前文

## TSV 列構成（11列固定）

```text
機能名	テストID	I/FID	テスト観点	優先度	テスト項目名	前提条件	入力データ/リクエスト内容	操作手順/実行方法	期待結果／レスポンス	確認対象
```

- `期待結果／レスポンス` は業務フローの作業内容にリンクし、システム結果として読める受け身・状態・可能表現にする。文末は **「〜されること。」「〜されないこと。」「〜できること。」「〜であること。」** のいずれかで終える（例:「対象商品CSVをダウンロードできること。」）。
- `確認対象` は観測点を**別列**にする（見やすさのため期待結果に混ぜない）。
- 各シートの先頭行 `STI-<SCN-ID-suffix>-001` は経路全体のシナリオテストケースにする。`テスト観点` は `業務経路`、`テスト項目名` は `経路全体 <経路ID>` を含め、元シナリオの `最終業務状態` を確認する。
| 列 | 記載元 |
|---|---|
| 機能名 | `<業務名> — <シナリオ名>`（元シナリオの表示名） |
| テストID | `STI-<SCN-ID-suffix>-NNN` |
| I/FID | 当該ステップが行使/観測する機能No。通常行はメインフロー「利用画面・機能」、分岐行は操作文と `触れる画面と既存ケース` の一致から割り当てる。経路全体/該当なしは `-` |
| テスト観点 | 業務経路、業務操作、データ更新、CSV/帳票、メール/通知、外部連携、在庫整合、金額整合、業務承認、業務データ整合、業務異常制御 等。**`権限` / `バリデーション` は使わない**（IT-15 / IT-22＝結合テスト層の観点であり、シナリオ側で重ねない） |
| 優先度 | 元シナリオの優先度。異常系は原則 P1 |
| テスト項目名 | その行で何を判定するかが分かる一文（接頭辞に `正常系`/`代替系`/`異常系` と行番号/分岐ID） |
| 前提条件 | 元シナリオ、業務、経路ID/経路種別/経路条件/最終業務状態、主アクター、関連システム、データパターンID、前提差分、シードデータ |
| 入力データ/リクエスト内容 | データパターンID、固定ID、境界値、分岐条件 |
| 操作手順/実行方法 | 人間が実行できる手順。経路全体行は参照だけにせず、経路内の各ステップについて担当者、画面/機能、対象、操作を同じセル内に展開する |
| 期待結果／レスポンス | 1行1判定の観測可能な結果 |

## テストケースTSV

````markdown
## テストケースTSV

以下はタブ区切りで、実質はExcelのCSVと同様に、改行や`"`を含むセルはダブルクォートで囲む。

**1行目**が列見出し（先頭列は `機能名`、**テストレベル列なし**）。**2行目以降**がケース（各11列）。`機能名` 列に業務名とシナリオ名を入れ、`I/FID` 列に当該ステップが行使する機能Noを入れる。`期待結果／レスポンス` は「〜されること。」「〜されないこと。」「〜できること。」「〜であること。」のいずれかで終える。`テストID`で一意に識別する。優先度は **P1／P2／P3**。

前提条件・入力データ・操作手順など、**期待結果以外**の列で複数項目がある場合は、同一セル内でLF改行する。

**期待結果／レスポンスは1行1判定**とする。複数の期待がある場合は行を分割し、**テスト項目名は当該行の判定内容が分かるよう具体化**する。すべての行は `経路ID` を参照し、DPがあるSCNではすべての行が `DP-*` を参照する。`操作手順/実行方法` には `元シナリオの正常系実行手順#1-#3を記載順に実行する` のような参照だけの手順を書かない。

```tsv
機能名	テストID	I/FID	テスト観点	優先度	テスト項目名	前提条件	入力データ/リクエスト内容	操作手順/実行方法	期待結果／レスポンス	確認対象
イベント管理 — イベント受付～実施	STI-EVENT-003-001	-	業務経路	P1	正常系 経路全体 R01: 正常代表として「イベント情報が登録される」を確認する	...	データパターンID=DP-N001	...	イベント情報が登録されること。	一覧・詳細に追加された対象データ
```
````
