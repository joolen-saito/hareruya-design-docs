# 用語・語彙マッピング

## 種別（メッセージの性質）

| ソース | 種別ラベル | 根拠 |
|--------|-----------|------|
| `addSuccess` / `addSuccessOnce` | インフォ(成功) | 正常完了通知。EC-CUBEでは success スタイル |
| `addInfo` / `addInfoOnce` | インフォ | 情報通知 |
| `addWarning` / `addWarningOnce` | 警告 | 注意喚起（処理は継続/条件付き） |
| `addError` / `addErrorOnce` | エラー | 失敗・不許可 |
| `addDanger` / `addDangerOnce` | エラー | 危険操作の失敗（error相当） |
| Form制約 `'message' => ...` | エラー(バリデーション) | 入力検証失敗 |
| JS `confirm(...)` | 確認 | 実行前の可否確認（Yes/No） |
| JS `alert(...)` | 警告 | 実行不可・注意のブロッキング表示 |

## どこに（表示位置）

| コンテキスト | 既定値 | 備考 |
|--------------|--------|------|
| 管理画面フラッシュ（namespace=admin） | 管理画面上部 | ページ上部のアラート帯 |
| フロントフラッシュ（namespace=front） | 画面上部 | |
| フォームバリデーション | 入力項目直下 | 各フィールド下の赤字 |
| JS confirm/alert | 画面中央(ダイアログ) | ブラウザ/SweetAlertダイアログ |

実UIが異なる場合（トースト・右下・モーダル等）は codex がテンプレートを読んで是正する。

## 要素(表示コンポーネント)

`フラッシュメッセージ` / `フォームバリデーション` / `確認ダイアログ` / `警告ダイアログ`。
テンプレートが SweetAlert・トースト等を使う場合は codex が実体へ是正。

## 後続処理（典型パターン）

| パターン | 意味 |
|----------|------|
| 一覧へリダイレクトする | 保存/削除成功後に一覧・詳細へ 302 |
| 同一画面を再表示する | エラーで入力画面に留まる（`render`） |
| 該当処理を中止し画面にとどまる | 権限無し/CSRF不一致等で処理せず戻る |
| 確認後に処理を継続する | confirm で OK を選んだとき |
| 処理を中止する | confirm で Cancel、alert でブロック |

`後続処理` は controller の `return`（redirect/render）や JS の分岐を codex が読んで確定する。
決定的段では `要ソース確認` を入れる。
