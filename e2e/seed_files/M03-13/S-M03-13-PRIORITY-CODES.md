# S-M03-13-PRIORITY-CODES 優先表示入力用規格

- 機能: M03-13／区分: 商品・規格／共有: 共有可／分類: ケースで登録／形式: 画面入力（手順書）

## 状態・属性（シード表の文）

商品IDは登録時に画面が振る（控える。以下、規格コードTAG-A-001、TAG-A-002、TAG-A-003、NOTAG-001、DEL-001の商品の順に〔商品ID-M0313-共有A〕、〔商品ID-M0313-共有B〕、〔商品ID-M0313-共有C〕、〔商品ID-M0313-共有D〕、〔商品ID-M0313-共有E〕）／規格IDは登録時に画面が振る（ケースが参照しないため控えない）／規格コード=TAG-A-001、TAG-A-002、TAG-A-003、NOTAG-001、DEL-001／TAG-A-001、TAG-A-002、TAG-A-003、NOTAG-001の商品と規格は削除されていない／DEL-001の規格は削除済み／規格コードUNKNOWN-999の規格は存在しない／各商品とタグの紐付けは各ケースの専用シードが持つ

## 用途（シード表の文）

共有可。手順で入力する規格コード（P13により改名しない）を持つ商品。どのケースも商品・規格の状態を変えない（タグ保存が書き換えるのはタグ本体と優先表示順だけ）。商品とタグの紐付けは各ケース専用シードで各ケースのタグに対して作る

## 投入方法（シード表の文）

グッズ商品CSV登録画面で、商品IDを空、タグ(ID)を空、商品コードにTAG-A-001、TAG-A-002、TAG-A-003、NOTAG-001、DEL-001をそれぞれ入れ、商品公開ステータスと支店の商品公開ステータスには任意の値、言語(ID)・商品名(日)・商品名(英)・サイズ・重量・商品カテゴリ(ID)・購入グループ名称・基準価格・販売価格・買取価格ほかの必須列には登録できる任意の値を入れた5行のCSVファイルを選択し、「CSVファイルのアップロード」を押す。商品マスターでコードに各規格コードを入れて検索し（公開状態の条件はCSVに入れた商品公開ステータスに合わせる）、検索結果の商品ID列に表示された商品IDを控える（TAG-A-001から順に〔商品ID-M0313-共有A〕、〔商品ID-M0313-共有B〕、〔商品ID-M0313-共有C〕、〔商品ID-M0313-共有D〕、〔商品ID-M0313-共有E〕）。規格コードDEL-001の規格の削除済み状態は画面で指定できない（商品の有効な規格が1件だけのとき、画面は規格の削除を受け付けない）ため、商品IDを控えたあとでDBへ直接設定する。規格コードUNKNOWN-999の規格が登録されているときは、DBへ直接操作して削除する。

## 登録するときの注意

- 上の文のとおりに、画面から（または下のCSVで）登録する。文にない操作は足さない。
- 画面が振る番号は登録した場所で控える。控える呼び名: 〔商品ID-M0313-共有A〕、〔商品ID-M0313-共有B〕、〔商品ID-M0313-共有C〕、〔商品ID-M0313-共有D〕、〔商品ID-M0313-共有E〕
- 承認・削除・取込などで状態が変わるシードは、一度使うと元に戻らない。もう一度試すときは同じ内容で登録し直す（商品コードなどが重なって登録できないときは、前のものが残っていないか確かめる）。
- 取込用のファイル（e2e/seed_files/M03-13/ の下。シード表の文から tools/csv_make.py が組んだもの）:
- S-M03-13-PRIORITY-CODES/setup/setup1.csv（準備用。グッズ商品CSV登録で取り込む）
  - S-M03-13-PRIORITY-CODES/setup/setup1.csv で担当が決めた値・出どころ: そのほかの必須の列(言語(ID)・商品公開ステータス・支店の商品公開ステータス・商品名(日)・商品名(英)・サイズ・重量・商品カテゴリ(ID)・購入グループ名称・基準価格・販売価格・買取価格): 文は「有効な値」。e2e の registerGoodsCsv・registerGoodsProduct が使う値(名前は「M<機能>試験商品<番号>」・サイズ1・重量1・価格は既定値・グッズ直下の先頭カテゴリ・先頭の購入グループ)を入れた




## DBへ直接設定する部分（SQL）

- SQLファイル（流す時点の順）:
  - e2e/seed_files/M03-13/S-M03-13-PRIORITY-CODES/db.sql ← 流す時点: 投入方法の「商品マスターでコードに各規格コードを入れて検索し（公開状態の条件はCSVに入れた商品公開ステータスに…」を終えたあと、次の「規格コードUNKNOWN-999の規格が登録されているときは、DBへ直接操作して…」より前
    - （試し用DB eccubedb_sqltest で確かめた。呼び名を置き換えずに（存在しない番号で）流すと確認で止まる（商品コードDEL-001の規格が1件に決まらない（0件））＝画面で作るデータが無いため。想定どおり。シード表の文（と下の「画面で入れる値」）に書かれた商品コード・店舗名・棚卸名・ファイル名・呼び名から、画面で作るはずの行を試し用に用意して流し、正しい行が期待どおりの値になること（期待1件すべて合う）、用意した行とこのSQLが入れた行のほかは変わらないこと、もう一度流しても同じことを確かめた（変わった行 1）。確かめはすべてロールバックした（行の中身は変えていない。ただし連番（シーケンス）を進める文があると、その値はロールバックしても戻らない））
  - e2e/seed_files/M03-13/S-M03-13-PRIORITY-CODES/db_before.sql ← 流す時点: 画面で登録する前に流す（消すのは 商品コードUNKNOWN-999の規格 だけ。状態・属性が「存在しない」と書く行で、このシードは画面で作らない。そのため登録のあとに流しても、このシードが作った行は消えない）
    - （試し用DB eccubedb_sqltest で確かめた。呼び名を置き換えずに（存在しない番号で）流すと通り、何も変わらない。シード表の文（と下の「画面で入れる値」）に書かれた商品コード・店舗名・棚卸名・ファイル名・呼び名から、画面で作るはずの行を試し用に用意して流し、変わるのが用意した行とこのSQLが入れた行だけであること、もう一度流しても同じことを確かめた（変わった行 4。値の一つ一つが期待どおりかは確かめていない）。確かめはすべてロールバックした（行の中身は変えていない。ただし連番（シーケンス）を進める文があると、その値はロールバックしても戻らない））
- どのファイルも 1つのトランザクション（BEGIN〜COMMIT）。途中で止まれば何も変わらない。商品コード・店舗名などで引く行と、呼び名の番号で指す行は、流す時点で1件に決まることを確かめ、決まらなければ止まる（止まったときのメッセージに実際の件数が出る）。流し直しても壊れない形（同じ行があれば同じ値に揃える／消すのはこのシードの行だけ）で書いてある。全件削除（表全体・取込種別全体を消すもの）は作っていない（下の「SQLを作っていない文」「作れない部分」に、渡したダンプの直後の件数を書いた）。
- 文ごとの流す時点（ファイル）:
  - [1] 規格コードDEL-001の規格の削除済み状態は画面で指定できない（商品の有効な規格が1件だけのとき、画面は規格の削除を受け付けない）ため、商品IDを控えたあとでDBへ直接設定する。 → db.sql（投入方法の「商品マスターでコードに各規格コードを入れて検索し（公開状態の条件はCSVに入れた商品公開ステータスに…」を終えたあと、次の「規格コードUNKNOWN-999の規格が登録されているときは、DBへ直接操作して…」より前）

- 流す前に置き換える呼び名: なし
- 流し方（psql の一例。接続先・利用者・パスワードは自分の環境のものを使い、ここには書かない）: `psql -v ON_ERROR_STOP=1 -h <ホスト> -U <利用者> -d <データベース> -f <上のSQLファイル>`
- 備考:
  - アプリの商品規格の削除は論理削除（公開状態を廃止(3)にし、表示しないにする。行は残る）。同じ形にする。スマレジ連携の削除の呼び出しはしない
