# S-M04-28-DP-DATA-009 複数移動・複数商品の指示データ009

- 機能: M04-28／区分: 在庫移動指示・在庫移動・商品／共有: ケース専用／分類: ケースで登録／形式: 画面入力（手順書）

## 状態・属性（シード表の文）

移動指示IDは在庫移動指示の作成時に画面が振る（控える。以下〔移動指示ID-M0428-009〕）／移動元店舗ID=〔店舗ID-M0428-共有A〕／移動先店舗ID=〔店舗ID-M0428-共有B〕／送り状No.なし／発送状況=未／在庫移動2件が紐づきステータスはどちらも出庫承認済み（在庫移動IDは登録時に画面が振る。控える。〔在庫移動ID-M0428-009A〕=M0428-009-G1（基準価格3500）とM0428-009-G2（基準価格1200）を各1点、〔在庫移動ID-M0428-009B〕=M0428-009-G3（基準価格800）とM0428-009-G4（基準価格2500）を各1点）／基準価格の合計=8000

## 用途（シード表の文）

IT-M04-28-009専用。在庫移動2件・各2商品の指示で注文金額合計・商品金額合計を確かめる

## 投入方法（シード表の文）

1. 管理者（ログインID m0428_admin）でログインし、グッズ商品CSV登録画面で、商品コード「M0428-009-G1」は基準価格3500、「M0428-009-G2」は基準価格1200、「M0428-009-G3」は基準価格800、「M0428-009-G4」は基準価格2500とした4行のCSVを登録する（ほかの必須列には任意の有効な値を入れる。登録すると各店舗に商品在庫が在庫数0でできる）／2. 在庫変更CSV登録画面で対象の店舗に東京店、在庫区分にEC-CUBEを選び、4商品それぞれ在庫増減数1のCSVを登録し（変動の種別・理由・承認通知先は任意の有効な値）、登録者とは別の、東京店を編集可能で承認権限を持つメンバー（以下、承認用管理者）が在庫編集承認一覧でこの申請を承認する／3. 在庫移動振替一覧の在庫移動CSV登録で、出庫元店舗に東京店・出庫元在庫区分にEC-CUBE・入庫先店舗に大阪店・入庫先在庫区分にEC-CUBEを選び、「M0428-009-G1」と「M0428-009-G2」を移動点数1ずつ書いたCSVを登録する。続けて同じ選択で「M0428-009-G3」と「M0428-009-G4」を移動点数1ずつ書いたCSVを登録する（在庫移動が2件できる。1件目を先に登録する）／4. それぞれの在庫移動のピック・出庫承認申請画面で承認通知先に承認用管理者を選び、承認申請ボタンを押す。承認用管理者でログインし、2件それぞれの出庫承認画面で承認ボタンを押す（ステータスが出庫承認済みになる）／5. 管理者（ログインID m0428_admin）でログインし直し、在庫移動振替一覧で2件の行に表示された在庫移動・振替IDを控え（1件目=〔在庫移動ID-M0428-009A〕、2件目=〔在庫移動ID-M0428-009B〕）、2件にチェックを入れて在庫移動指示作成ボタンを押す。在庫移動指示検索画面で在庫移動IDに控えた番号を入れて検索し、結果の行に表示された移動指示IDを控える（〔移動指示ID-M0428-009〕）。送り状No.は登録しない

## 登録するときの注意

- 上の文のとおりに、画面から（または下のCSVで）登録する。文にない操作は足さない。
- 画面が振る番号は登録した場所で控える。控える呼び名: 〔移動指示ID-M0428-009〕、〔店舗ID-M0428-共有A〕、〔店舗ID-M0428-共有B〕、〔在庫移動ID-M0428-009A〕、〔在庫移動ID-M0428-009B〕
- 承認・削除・取込などで状態が変わるシードは、一度使うと元に戻らない。もう一度試すときは同じ内容で登録し直す（商品コードなどが重なって登録できないときは、前のものが残っていないか確かめる）。
