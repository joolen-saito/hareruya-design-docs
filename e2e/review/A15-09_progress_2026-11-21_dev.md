# A15-09 デッキ情報登録 API — 010 は書かなかった（2026-11-21）

## 書いたケース
なし。

## 書かなかったケース
| ケース | 理由 |
| --- | --- |
| 010 | 「プレイヤーが存在しない顧客IDを持つ正規署名済みトークン」が、正規の手段では得られない。実ソースの確認結果は下のとおり |

## 実ソースの確認（ec-cube-enterprise）
- アクセストークンを作る処理（JwtTokenService の createToken）の呼び出しは2か所だけ。デッキビルダーのログイン（LoginAction）と、MTGバイヤー管理のログイン。
- デッキビルダーのログインは、メール・パスワードが合っても、顧客に対応するプレイヤーが無ければ認証失敗（401）を返し、トークンを発行しない。
  つまり、ログイン API では「プレイヤーが存在しない顧客のトークン」は得られない。
- そのほかにトークンを作る画面・API は無い。署名の秘密の値を読む・使う方法は取らない（依頼のとおり）。
- 近道として「プレイヤーのいる試験会員でログインしてトークンを得たあと、その会員のプレイヤーの行を DB から消す」がありうる（トークンは顧客IDだけを持つので、
  消した後は同じトークンが「プレイヤー無し」になる）。プレイヤーは E2E が作った行なので lib/db_write.ts の対象にできるが、
  今回の依頼（「正規の手段で得られないなら書かない」）の範囲を超えるので書かなかった。判断が要る（報告に書いた）。

## 判断待ち
- 上の近道を使ってよいか（E2E が作った試験会員のプレイヤーの行だけを lib/db_write.ts で消す）。使ってよければ、010 と A15-13 の 006 が書ける。
  010 はさらにシード表の「あれば削除」を含むので、config の表への行の追加が要る。

## 流した結果
書いていないので流していない。
