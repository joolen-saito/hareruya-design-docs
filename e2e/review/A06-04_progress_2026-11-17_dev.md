## 正本の外の補い（読み替え）
- 「開発者ツールから PUT で送る」「Network で確かめる」は、ブラウザのページから API サーバーへ要求を送り、送った要求と応答をページに表として出して読む形にした（A06-01 と同じ部品）。フリーコメントは、ケースの文のとおり URL のクエリパラメータで送る。
- API の入口 `/api/…` は `/api/v1/…` に読み替えた（A06-01 と同じ）。003 の拡張子の無いパスは、入口だけを読み替え、拡張子は付けない。
- 有効なトークン（事前準備の「有効な jwt-token を取得している」）は、手順1の前に管理者のログイン API で受け取った。008 の違う鍵のトークンは、環境の鍵と違う試験用の鍵（HS256）でこの端末で作った。
- 試験店舗「A06-04試験店舗」「A06-04AB試験店舗」は試験支店に読み替えた。店頭買取の受注は、試験支店のフロントの店頭買取査定申込（会員登録なし）で作り、査定IDは完了画面の査定番号、受注IDは DB で読んだ（買取一覧の「最後に登録した行」の代わり）。更新前のフリーコメントは、更新前担当の管理者で買取詳細画面から保存した。
- 申込者の電話番号・郵便番号・住所・生年月日・職業は共通の申込の部品の固定の値、査定申込日時・更新日時は申込・保存したときの値（シード表の決まった値は入れない。どのケースも確かめない）。
- 店頭買取ステータス・職業・国・都道府県のマスタは書き換えず、あることを DB で確かめるだけにした。S-A06-04-AB-ADM の所属「東京店」は、メンバー登録画面の所属の選択肢の先頭（共通の部品の作り）。

## 流す前から分かっていること（アプリのソースを読んだ見立て。流して確かめる）
- アプリはフリーコメントを要求の本文（フォームの値）から読む。ケースの文のとおりクエリパラメータで送ると、「コメントを入力してください」で 400 になる見込み。
- 成功の応答は処理結果コード 200 だけの JSON（ケースの「レスポンスデータがない」と違う見込み）。
- 拡張子の無いパス（003）は、アプリに経路が無い（既存の下書き a06-04-otc-buy-order-free-comment-extensionless-route-missing.md）。
