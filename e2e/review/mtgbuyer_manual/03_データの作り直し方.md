# データの作り直し方（MTGバイヤー手動試験 O01-01・O01-02）

端末を操作する人がすることではなく、データを用意する担当（こちら）の手順。

## 1. 考え方
- 受注は、実施のたびに新しく作り直さない。同じ受注（同じ番号）の状態を、ケースの記載の値へ戻す。新しく申し込み直すと受注の番号が変わり、同じ査定番号の行が2つ並ぶため。
- 戻すのは、ケース専用の受注（使い捨て）だけ。戻す値は、シード表の記載（状態・査定担当者・フリーコメント・本人確認の種別・登録番号の確認・申込日時・査定番号）。
- 戻せるのは、この手順書用に作った受注（申込者の姓が「査定O0101-」で始まるもの）だけ。ほかの方のデータは触らない。
- 端末側（端末のフォルダの査定途中データ・身分証画像、保管先のファイル）は、人が消す。ケース表の「端末で人がする準備」に書いてある。

## 2. 戻す・作り直すコマンド
```
cd e2e
set -a; . ./.env.dev; set +a
tools/dev_db_tunnel.sh --once            # DB のトンネル（127.0.0.1:15432）が開いているか
PW_SLOTS=3 PW_BATCH=2 nice -n 19 tools/pw_run.sh O01-01 spec/o01/o01_prep.spec.ts <番号> [<番号>]
```
- 番号は、ケースのテストIDの末尾の3桁（cases の番号。項目表のテストIDとは違う。対応は `data/項目表対応.tsv`）。例: `IT-O01-01-003` → `003`。
- 同時に1本、1回に2件まで。回と回のあいだは2分以上あける（共通の決まり）。
- 受注があれば（`data/控えた番号.tsv` に呼び名があり、その受注の姓が一致すれば）、新しく作らず、記載の値へ戻す。無ければ、画面から作る。
- 結果は `data/準備結果.tsv`（作成済み／作れなかった）。控えた番号は `data/控えた番号.tsv`。
- そのあと、手順書を作り直す: `python3 review/mtgbuyer_manual/build_manual.py`。

## 3. 実施の直前に作り直すもの
- 日時に依存するデータは無い（申込日時は 2026-10-01 10:00:00 固定）。
- 使い捨ての受注（実施すると状態が変わる）: 身分証の選択・「査定を中断する」などで状態・査定担当者が変わる。もう一度実施する前に、上のコマンドで戻す。
- 保管先（S3）のファイル（`c{受注ID}.csv`・`n{受注ID}.csv`）と端末のフォルダの査定途中データ・身分証画像は、人が消す。

## 4. 作れないもの（今回の限り）
`data/準備結果.tsv` の「作れなかった」と、`01_`・`02_` の「データの状態」「準備の備考」を見る。
