## 1. 端末の設定（端末を操作する人がすること）

### 1-1 アプリを置く
1. Windows の試験端末（O01-01・O01-02 は端末A・端末Bの2台）に MTGバイヤーを置く。配置先は `C:\DeepLearning`（ケースの文が端末のフォルダをこの下の `Export\Csv\DempDirectory\`・`Resource\IdImages\EncryptedImages\` で書いている）。
2. 動作環境は .NET Framework 4.7.2。初回起動で資源（Resource.zip など）を保管先から取り込むので、取り込めるまで待つ。

### 1-2 接続先を開発環境へ向ける
アプリの接続先は、`Configuration\System.config` の `Environment`（Dev・Stg・Prod・StgTmp）と、`Configuration\Api.config` のその環境の行で決まる（`MTGBuyer\Util\ApiUtil.cs`）。

1. `Configuration\System.config` の `Environment` を `Dev` にする。
2. `Configuration\Api.config` の次の2行を書き換える。
   - `Api.ProtocolName.Dev` = `https`
   - `Api.HostName.Dev` = `replace-dev.hareruyamtg.com:8443`（ポート番号まで書く。アプリは `プロトコル://ホスト名/パス` をそのまま組み立てる）
3. `Configuration\System.config` の `NetPurchaseShop`・`Configuration\Csv.config` の `HeadOfficeNames` は、既存の値「トーナメントセンター 東京」のまま。
4. 設定を直したらアプリを起動し直す。

### 1-3 ファイル保管先（S3）— 設定ではなく、環境名で決まる
- 査定途中データ（`c{受注ID}.csv`・`n{受注ID}.csv`）の保管先は、アプリの中（`MTGBuyer\Util\TransferUtil.cs`）に環境名ごとに書かれている。`Environment` が `Dev` のときは、バケット `dev.mtgbuyer.files.api` の `assessment` 配下を使う（鍵もアプリの中にある。設定ファイルで保管先は変えられない）。
- つまり、ケースの文の「試験用保管先」は、この Dev のバケットを指す。
- 保管先の確かめ・削除（ケースの事前準備に出る）は、**このケース表の受注IDのファイル（`c{受注ID}.csv`・`n{受注ID}.csv`）だけ**を対象にする。ほかのファイルには触らない。だから、バケットがほかの用途と共有でも差し支えない（2026-11-24 に 6c が決めた）。
- 確かめ・削除は Claude が AWS CLI で行う。依頼者は、実施の日の前に WSL の Claude Code で `! aws login` を打ち、ログインをし直す。そのアカウントでこのバケットを読めない場合は、AWS の管理コンソール（S3）でバケットを見られる人に、受注IDのファイルの確かめ・削除を頼む。

### 1-4 API の送信元IP
- 開発環境の API は、送信元IPを許可した端末だけを受ける作りの可能性がある（A06 の準備で「試験端末の送信元IPの許可」が出てくる）。ログインで接続エラーになるときは、端末の送信元IPが許可されているかを環境の管理者に確かめる。IPの許可は共有の設定なので、こちらは書き換えていない。
- 実施の前に、端末のブラウザで `https://replace-dev.hareruyamtg.com:8443/admin` を開く。ログイン画面が出れば、つながっている。出なければ（タイムアウト・403）、端末の送信元IPを環境の管理者に伝え、許可を頼む。

### 1-6 ログインに使うアカウント
- 手順の1番目に、ログインIDとパスワードがケースの文のとおりに書いてある（O01-01: `o0101-adm-tc`、O01-02: `o0102-adm-tc` ほか）。パスワードはケースの文から取る（この手順書には重ねて書かない）。
- O01-01 の `o0101-adm-tc` は、開発環境に登録済み（`data/控えた番号.tsv` の `〔管理者ID-O0101-共有〕`）。管理画面（ECCUBE）にも同じ ID・パスワードでログインできる。

### 1-7 「DBで確認」の手順
- O01-01 の18ケース、O01-02 の7ケースは「DBで確認する」手順がある。
- 端末を操作する人は、DBを読まなくてよい。端末での操作が終わったら、テストID（例: IT-O01-01-012）を Claude に伝える。Claude が開発環境のDBを読み、期待結果と比べ、記入欄の備考に結果を書く（2026-11-24 に 6c が決めた）。

4. 記入欄（実施者・実施日・実施結果・備考）は、ケース表の最後の4列。項目表（Excel）へは、こちらは書き込まない。
