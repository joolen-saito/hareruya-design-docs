# DB に直接書くシードの仕分け直し（2026-11-14）

依頼者の「続けて」（2026-11-14）を受けて、流せない一覧のうち「シードの投入方法が DB への直接の設定」の理由で止めていたケースを、シードの中身で仕分けた。
仕分けは機械的に3つ（A: E2E の行だけに書く／B: ほかの方の行・全員が使うマスタ・共有の設定／C: DB では作れない）に分けたあと、A の多い機能を1つずつ確かめた。

## A15-04 他ユーザー情報参照（流せる形に直した・16件）
- 選手はフロントの会員登録で作り、ニックネーム・プロフィールなど画面で指定できない値だけ、E2E の選手の行に DB で書く（lib/db_write.ts）。
- 記録は review/A15-04_progress_2026-11-14_dev.md。

## 確かめた結果、A ではなかった機能（流せないまま。理由を config/sheet_not_runnable.tsv に書き直した）
| 機能 | 件数 | 理由 |
| --- | --- | --- |
| A15-12 デッキ情報参照 | 39 | フォーマット・アーキタイプ・カード・カード画像のマスタ（S-A15-12-MASTERS）を新しく作る前提。全員が使うマスタ（カードのマスタを作るかは判断待ち） |
| A15-13 デッキ情報検索 | 41 | 同じくマスタの DB シード（S-A15-13-MASTERS）とキャッシュの初期化が要る。005 だけは共有シード S-A15-13-PLAYERS（試験会員6人）だけで流せる見込みがあるが、1件のために6人を作るのは見送った |
| B16-09 サイトマップ | 22 | サイトマップ1ファイルあたりの件数・画像の配信の基点（S-B16-09-WEB）を書き換える前提。共有の開発環境の設定。店舗を作るシードもある |
| B08-03 ポイント有効期限通知 | 17 | 基準データのフィクスチャ再投入（S-B08-03-DB）・バッチの起動・試験用メール受信環境 |
| B06-01 買取自動入庫 | 17 | 店舗マスタの DB 投入とバッチを起動するタスクの設定（S-B06-01-ENV） |
| B02-01 販売数集計 | 27 | バッチ・実行コンソール・アプリケーションの設定の書き換えとバッチの起動、集計用の店舗の登録 |
| A05-04 スマレジ取引 | 20 | スマレジ API 試験環境への取引応答の登録と Webhook の設定 |

件数は、流せない一覧のうちこの理由だった件数（機能ごと。理由を書き直したのは計170件）。

## 見えてきたこと
- 機械的な仕分けで A に入った機能でも、ケースが共有シード（マスタ・環境の設定）を併せて使っていると流せない。A の数（520件）は、実際に流せる数よりかなり多い見込み。
- 次に確かめる候補は、件数の少ない A の機能（ケース専用のシードだけで閉じるもの）。
