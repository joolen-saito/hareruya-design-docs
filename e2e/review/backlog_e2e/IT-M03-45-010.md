# 期待される挙動【必須】
- ケースの期待結果（IT-M03-45-010）は、「ルートカテゴリA・子カテゴリA1・孫カテゴリA1から第4階層カテゴリA1までの経路だけが開き、子カテゴリA2と空カテゴリの経路は閉じていること」。開く枝は、ルートカテゴリA・子カテゴリA1・孫カテゴリA1の3つで、表示中の「第4階層カテゴリA1」自身の枝（その子の「第5階層カテゴリA1」を含む）は開かない。
- 設計書の現行仕様「一覧の構成」は、「ツリーは初期状態では閉じており、表示中のカテゴリまでの経路だけを開く」と定める。表示中のカテゴリは「第4階層カテゴリA1」で、そこへ至る経路を開けば、ツリーに「第4階層カテゴリA1」の行が見える。その子の枝まで開くことは、定められていない。

# 現在の挙動【必須】
- 開いている枝は、ルートカテゴリA・子カテゴリA1・孫カテゴリA1の3つに加えて、表示中の「第4階層カテゴリA1」の枝も開いている（4つ）。その子の「第5階層カテゴリA1」が、ツリーに最初から見えている。子カテゴリA2（ルートカテゴリAの別の子）と空カテゴリの枝は閉じており、これは期待どおり。
- 原因は、ツリーを開く対象を作る処理が、親に指定されたカテゴリ（表示中のカテゴリ）の祖先に加えて、そのカテゴリ自身のIDも入れていること。ツリーの各枝は「開く対象」に入っているものだけ開いて表示する。
- 前回（2026-10-20・2026-10-27、手元の環境）も同じ落ち方だった。
- 一覧の左側には、表示中のカテゴリの直下のカテゴリ（ここでは「第5階層カテゴリA1」）が行として出るため、画面から子の存在が読み取れなくなるわけではない。差は、ツリーの初期の開き方にある。

# 根拠
- 設計：
  - 現行仕様「一覧の構成」: ツリーは初期状態では閉じており、表示中のカテゴリまでの経路だけを開く: `hareruya-design-docs/excel_to_html/output/0204_基本設計仕様書(商品管理).html:3942`
  - カテゴリ一覧の画面項目定義（識別ID 1〜10）には、ツリーの開き方の記述は無い（Excel由来の部分に定めが無く、この現行仕様の1文だけが根拠）
- ec-cube-enterprise：
  - 開く対象に親（表示中のカテゴリ）自身を含め、その枝を開く: `ec-cube-enterprise/src/Eccube/Controller/Admin/Product/CategoryController.php:653-666`、`ec-cube-enterprise/src/Eccube/Resource/template/admin/Product/category.twig:530-545`
- ベース実装：
  - pf-eccube3 は表示中のカテゴリの祖先の枝だけを開き、表示中のカテゴリ自身の子の枝は閉じる: `pf-eccube3/app/Plugin/HareruyaEc/Resource/template/admin/Product/category.twig:77-90`、`pf-eccube3/app/Plugin/HareruyaEc/Resource/template/admin/Product/category.twig:243-258`
  - 探した範囲: pf-eccube3 のカテゴリ一覧テンプレート（app/Plugin/HareruyaEc）と、ec-cube 標準のカテゴリ一覧のコントローラー。EC-CUBE 標準は親自身も開く
