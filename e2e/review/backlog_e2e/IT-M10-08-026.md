# 基本情報【必須】
分類：基本情報設定
機能：自動送信メール（M10-08）
課題カテゴリ：不具合_基本情報設定
課題：【要確認】基本情報設定_自動送信メール_テンプレート未指定の登録要求への応答が、設計書の表示メッセージの節（500エラー応答）と違いHTTP400になる
設計書：0209_基本設計仕様書(基本情報設定).xlsx

# 再現手順【必須】
1. 開発環境（https://replace-dev.hareruyamtg.com:8443）の管理画面で、自動送信メール（基本情報設定）のテンプレート未指定の画面を開く
2. 開発者ツールで、フォームの送信を止めるブラウザ側の処理を解除する
3. 設定ボタンを押す
4. 登録要求への応答（HTTPステータスと表示）を確認する

# 期待される挙動【必須】
- 設計書の表示メッセージの節は M10-08-MSG-003 を「表示位置: 500エラー応答／文言: 新規作成は許可されていません。／表示条件: 新しいメールテンプレートの画面へ、対象のメールテンプレートが未指定のまま登録したとき／後続処理: 異常終了として500エラー応答を返す」と定める。ケース（項目表 IT-M10-08-024。E2E のテストID IT-M10-08-026）の期待結果も「HTTP 500のエラー応答が表示されること」。

# 現在の挙動【必須】
- 手順3 の要求への応答はHTTP400。画面には「アクセスできません。新規作成は許可されていません。」が表示される。保存はされない。文言と「保存しない」は設計書どおりだが、ステータスが500でなく400になる。
- 原因は、コントローラーがテンプレート未指定の送信で、500になる一般の例外ではなく「不正な要求」の例外（400）を投げていること。意図して選んだ作りとみられるため、アプリの直しか設計書の記述（500）の直しかの判断を要する。
- ベース実装は、テンプレート未指定の送信を500にはせず、エラーメッセージを付けて画面へ戻す（リダイレクト）。表示メッセージの節の「500」はベース実装の挙動でもない。

ec-cube-enterprise 未指定の送信で400の例外を投げる: `ec-cube-enterprise/src/Eccube/Controller/Admin/Mall/MallAutoMailController.php:94-97`
```php
        if ($request->getMethod() === 'POST') {
            if ($Mail === null || $Mail->getId() === null) {
                throw new BadRequestHttpException(trans('admin.setting.shop.custom_automail.new'));
            }
```

ベース実装 pf-eccube3 は未指定の登録を「現時点では未実装」とし、エラーを付けて画面へ戻す: `pf-eccube3/app/Plugin/HareruyaEc/Controller/Admin/Setting/Shop/MailController.php:159-164`
```php
            // 新規登録は現時点では未実装とする.
            if (is_null($mail)) {
                $app->addError('admin.shop.mail.save.error', 'admin');

                return $app->redirect($app->path('admin_setting_shop_auto_mail'));
            }
```

  - 現行仕様の節 業務ロジック・入出力には、テンプレート未指定の登録の応答（500）の記述は無い（失敗時出力は再表示・404・アクセス拒否）: `hareruya-design-docs/excel_to_html/output/0209_基本設計仕様書(基本情報設定).html:1826`

  - `ec-cube-enterprise/src/Eccube/Controller/Admin/Mall/MallAutoMailController.php:94-97`（400の例外）
