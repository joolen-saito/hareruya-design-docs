# 基本情報【必須】
分類：受注管理機能
機能：ピッキングリスト印刷（M05-21）
課題カテゴリ：不具合_受注管理機能
課題：【実装乖離】受注管理機能_ピッキングリスト印刷_並び順で、レアリティを持たないカードの行が、レアリティを持つカードの行より後に表示される（設計はレアリティ「無→有」）
設計書：0203_基本設計仕様書(受注管理機能).xlsx
対象のケース：結合試験項目表 IT-M05-21-038（E2E IT-M05-21-041）

# 再現手順【必須】
1. 開発環境（https://replace-dev.hareruyamtg.com:8443）で、1件の受注に次の2つのカードの明細（同じ価格帯・数量1）を入れ、その受注を含む出荷指示リストを用意する。2つのカードは、レアリティの有無だけが違う（棚番号・言語・状態・Foil・略称タグ・色順・カード番号は同じ）
   - 並び確認A：カード詳細のレアリティが「レア」
   - 並び確認B：カード詳細のレアリティなし
2. 受注管理＞出荷指示リストの詳細画面を開き、その受注を選択する
3. 「ピッキングリスト印刷」ボタンを押す
4. 開いたピッキングリストで、同じグループに並んだ並び確認A・B の行の順序を確認する

# 期待される挙動【必須】
- 設計書のソート順は「レアリティ（無→有）」なので、レアリティを持たない並び確認B の行が、レアリティを持つ並び確認A の行より上に表示されること。
- ケースの期待結果も、「商品単位_980円未満」のグループで「M0521-CB041-並びB」「M0521-CB041-並びA」の順に表示されること。

# 現在の挙動【必須】
- 「商品単位_980円未満」のグループに、並び確認A（レアリティあり）→ 並び確認B（レアリティなし）の順で表示された（E2E 2026-11-23 の開発環境。添付の画像）。
- 同じ受注の、サプライの主明細の行（ピック数2にまとめ・言語/状態「サプライ品」・略称と色/R が空）は期待どおりだった。
- 並び替えは、レアリティが無い行に 1・有る行に 0 を付けて昇順で並べている。そのため、レアリティを持つ行が先になる（設計の「無→有」と逆）。ベース実装も同じ並び。
- 補足：レアリティは、カード詳細(登録)画面では必須の選択で外せない。E2E では、注文のあとで E2E のカード詳細の行だけ DB でレアリティを外して、レアリティを持たないカードを作った。並びはこの値だけで決まり、外し方は結果に効かない。

ec-cube-enterprise 並び替えの式と順序: `ec-cube-enterprise/src/Eccube/Repository/Traits/SortProductTrait.php:78-79`、`:93-94`
```php
                $wrap('CASE WHEN r.id IS NULL THEN 1 ELSE 0 END')." AS {$hiddenOrNot['isRarityNull']} isRarityNull",
                $wrap('CASE WHEN r.id IN (:rareId, :mythicId) THEN :rareOrderVal ELSE r.id END')." AS {$hiddenOrNot['rarityOrder']} rarityOrder",
...
            ->addOrderBy('isRarityNull', 'ASC')
```

ベース実装（pf-eccube3）も同じ式・同じ順序: `pf-eccube3/app/Plugin/HareruyaEc/Repository/SortProductTrait.php:47-48`、`:62-63`
