# 期待される挙動【必須】
- ケースの期待結果（項目表 IT-M03-10-034、E2E のテストID IT-M03-10-043）は「NM規格の買取価格が12000、SP規格とMP規格が12000に既定の率75%を掛けた9000、HP規格が12000に既定の率50%を掛けた6000で保存されること」。
- 設計書（Excel由来の処理概要）は、買取価格(NM) ＞ 基準価格(NM) の登録をエラーと定めている。「エラー制御について：買取価格の方が基準価格より高い場合はエラーとする」「「登録ボタン」押下のサーバー側処理にて、全商品に対する 買取価格(NM) ＞ 基準価格(NM) チェックを実施。1件でも該当する場合は、すべての登録/更新処理を破棄して、画面にエラーメッセージを出力する」。表示メッセージ M03-10-MSG-002 は「ID:%productId%（%language%）の買取価格は基準価格「%standardPrice%」以下を指定してください。」で、登録処理を行わず画面を再表示すると定める。
- したがって、入力値が買取価格12000・基準価格3000のこのケースは、設計書ではエラーで登録されない入力であり、ケースの期待結果（保存される）は設計書と食い違う。
- 設計書の中の食い違いは、現行仕様の節（保存の判定順序・買取価格の決め方）に、買取価格が基準価格を超えるときのエラーが載っていないこと。現行仕様の節は現行システム（pf-eccube3）の挙動を写したもので、現行システムにはこの検査が無い。設計書の優先順位（Excel由来＞表示メッセージ節＞現行仕様節）により、Excel由来の定めとメッセージ節が正になる。
- ケースの直し方（案）: 「上限（10000）を超える高額帯で、買取減額率が無いときは入力値に状態ごとの率を掛けて保存する」を確かめるのが狙いなので、基準価格(NM)を買取価格以上の値（例: 20000。同じ機能の IT-M03-10-035 は買取価格10050・基準価格20000）に直す。シードの登録前の基準価格（3000）も、買取価格の入力値以上に合わせるか、手順で基準価格を12000以上に入れ直す。

```php
    public function validatePriceLoss(array $products, ExecutionContextInterface $context): void
    {
        foreach ($products as $key => $product) {
            $buyPriceRaw = $product['buy_price_nm'] ?? null;
            $standardPriceRaw = $product['standard_price_nm'] ?? null;

            if ($buyPriceRaw === null || $standardPriceRaw === null) {
                continue;
            }

            $buyPrice = (int) $buyPriceRaw;
            $standardPrice = (int) $standardPriceRaw;

            if ($buyPrice > $standardPrice) {
                $context->buildViolation($this->translator->trans('admin.product.buy_price_exceeds_standard'))
                    ->setParameter('%standardPrice%', (string) $standardPrice)
                    ->setParameter('%language%', $product['language'] ?? '')
                    ->setParameter('%productId%', $product['product_id'] ?? '')
                    ->atPath('['.$key.'][buy_price_nm]')
                    ->addViolation();
            }
        }
    }
```
