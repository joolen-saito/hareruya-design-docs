# 再現手順【必須】
1. 開発環境（https://replace-dev.hareruyamtg.com:8443）の管理画面で、受注管理＞出荷指示から、受注A（注文番号 00006310）だけを含む出荷指示リストAと、受注B（注文番号 00006311）だけを含む出荷指示リストBを用意する（両受注は本店・海外向けの配送方法で、会員・プレイヤー・配送先を持つ。受注BはリストAには含まれない）
2. 出荷指示リストAの出荷指示リスト編集画面（/admin/standby/<出荷指示リストAのID>/edit）を開く
3. 一覧の受注A（注文番号 00006310）を選択する（一覧にはAの受注しか出ない）
4. 開発者ツールで、画面の送信用フォームへ、印刷要求の選択受注として受注Bの受注IDを足す（ケースでは、フォームに選択受注の入力項目を足して代えた）
5. 「納品書印刷（英語）」ボタンを押す
6. 開いた窓に出る納品書の注文番号を確認する

# 期待される挙動【必須】
- 設計書の現行仕様の節（出荷指示ー納品書印刷（英語）の業務ロジック「印刷対象」）は「出荷指示リストに含まれない受注を選択したときも、その受注の納品書を出す。選択した受注が出荷指示リストに属するかどうかは確かめない」と定める。ケースの期待結果（項目表 IT-M05-23-004）も「受注Aと、出荷指示リストAに含まれない受注Bの納品書がそれぞれ表示されること」。
- Excel 由来の部分は「一覧でチェックされた注文について、各ボタンに応じた出力処理を実行する」とだけ述べ、一覧に無い受注の扱いは定めていない。表示メッセージの節は画面メッセージを持たないとだけ述べる。この件を定めているのは現行仕様の節だけ。

# 現在の挙動【必須】
- 開いた窓には受注A（注文番号 00006310）の納品書（1/1）だけが出て、受注B（注文番号 00006311）の納品書は出ない（項目表 IT-M05-23-004）。納品書の窓は開き、受注Aは期待どおり出る。
- 原因は、印刷の対象を「出荷指示リストに属する受注のうち、選ばれたもの」だけに絞る作りのため。リスト外の受注IDを足しても対象から外れる。この絞り込みは 2026-04-27 のコミット（「納品書印刷のため注文IDから配送IDを抽出する処理を追加」）で入ったもの。
- 画面の通常の操作では、一覧に出荷指示リストの受注しか出ないため、リスト外の受注を選べない。この動きになるのは送信内容を書き換えたときだけで、業務の操作には影響しない。
- 設計書の現行仕様は、ベース実装がリストの所属を確かめず、送られた受注IDをそのまま使うことを写したもの。同じ設計書のピッキングリスト印刷の現行仕様は逆に「その出荷指示リストに属する受注だけが対象。含まれない受注を選んだときは明細を出さない」と定めており、納品書だけが所属を確かめない書き方になっている。
- 設計の乖離監査は、この記述を「選択受注の所属を検証していないという副作用の記述で、機能として定義された挙動ではない（踏襲対象外）」と判定し、ee が所属する受注だけを対象にする点を踏まえて起票していない（Backlog に該当の課題なし）。
