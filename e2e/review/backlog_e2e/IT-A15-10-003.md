# 期待される挙動【必須】
- フォーマット・アーキタイプ・デッキ名・キャンペーンタグ・採用カードなどは、指定が無いときは扱わない（設計書 A15-10 入出力）。HTTP 200 で、指定が無い項目は更新前の値のまま。
- 項目表 IT-A15-10-003：デッキ名・フォーマット・アーキタイプ・代表カード画像・キャンペーンタグ・採用カードが更新前から変わらない。IT-A15-10-004・005：指定したキャンペーンタグが保存される。IT-A15-10-006・007：公開範囲が更新され、限定公開のときだけ閲覧用トークンが返る。IT-A15-10-018・019：指定したデッキ名と採用カードが保存される。

# 現在の挙動【必須】
- どのケースも HTTP 400「フォーマットを指定してください。」で拒まれ、公開範囲・キャンペーンタグ・デッキ名・採用カードのいずれも保存されない（2026-11-26 開発環境。項目表 IT-A15-10-003〜007・018・019）。更新前の値は変わらない。
- 原因は、フォーマットの指定が無いとフォーマットを「なし」として扱い、デッキの属性の検査がフォーマット必須として400を返すこと。

# 確認したいこと
- 項目表 IT-A15-10-018・019（E2E の IT-A15-10-031・032）は、事前準備にフォーマットのマスタがあるのに、手順にフォーマットの指定が無い。ケース側の抜けの可能性がある。手順にフォーマットを足せば、この2件だけは通る見込み（他の5件は、フォーマットを指定しないこと自体が内容）。
- 設計書は「指定が無いときは扱わない」だが、現行もフォーマット未指定は400。設計書とベース実装のどちらを正とするかの確認が要る（Excel 由来＞現行仕様の節の決まりに従い、設計書を正として実装差異で起票した）。
