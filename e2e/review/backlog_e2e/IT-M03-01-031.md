# 期待される挙動【必須】
- 項目表のケースの期待結果は「買取・基準価格一括編集画面へ遷移すること」。
- 設計書は、ボタン（識別ID 9）の説明を「買取・基準価格一括編集に遷移する」とだけ書き、遷移の対象は一覧の「一括編集対象(個別チェック)」（識別ID 14。チェックを付けた商品が一括編集の対象になる）で決まる。商品を選ばずに押したときは、同じ設計書の買取・基準価格一括編集の節が「選択が空のときは編集画面を開かず、商品一覧へ戻る。戻り先は商品一覧で最後に表示していたページとする」「商品が未選択: 商品一覧へ戻り、選択を促すメッセージを表示する」と定め、表示メッセージ M03-10-MSG-001「1つ以上の商品を選択してください」（表示条件は商品を選択せずに一括編集画面を開いたとき、後続処理は商品一覧画面に遷移する）を置いている。
- つまり、設計書の中は食い違っておらず、「一括編集画面へ遷移する」のは商品を1件以上選んで押したときの動き。食い違いはケースの手順にある。項目表 IT-M03-01-029 の手順は、手順3の検索のあと商品を選ばずに手順4で押していて、選ぶ操作が無い。手順3と手順4の間に「検索結果の商品 〔商品ID-M0301-031〕 の行の先頭のチェックボックスを選択する」を足す案（事前準備のとおり、対象は1件だけ表示される商品）。足せば、期待結果の「一括編集画面へ遷移する」はそのまま確かめられる。

# 現在の挙動【必須】
- 手順3の検索で、商品「一覧表示商品-031」の1件が一覧に出る。チェックボックスは選ばれていない。
- 手順4で「買取・基準価格一括編集」を押すと、画面は買取・基準価格一括編集には進まず、商品一覧（検索結果は直前のまま。ページ1）へ戻り、画面上部に「1つ以上の商品を選択してください」の警告が出る。期待結果の確認では、開いたURLが一括編集画面でなく商品一覧のページ1だった。
- これは設計書の定め（選択が空のときは商品一覧へ戻り、M03-10-MSG-001 を出す）と同じ動き。アプリは、選択された商品の番号の一覧が空のとき、エラー表示を積んで、商品一覧の最後に表示したページへ戻す。ボタンは選択の有無にかかわらず押せる作りで、押下を止める処理は他の一括操作のボタンにだけ付いている。
- E2E は、手順4の前に「正本に商品選択手順はない」（0件）を確かめたうえで押している。ケースを直さずに流した結果。
