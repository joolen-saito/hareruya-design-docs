# 現在の挙動【必須】
- HTTP ステータスは 400、本文は {"code":400,"message":"リクエストパラメータが不正です"}（開発環境。応答は日本語の文字が \uXXXX の形で入った JSON）。ステータスとコード 400 は期待どおりで、合わないのはメッセージの文字列だけ（IT-A15-04-010 の別の確認項目「応答本文が JSON として読める」は合格）。
- 原因は、アプリがこのメッセージを翻訳の部品（trans）で出し、日本語の語彙に日本語の文が入っていること。既定のロケールは ja（`ECCUBE_LOCALE` の既定値）で、Accept-Language を読む処理はデッキビルダー API の側に見当たらない。日本語の設定では日本語になり、英語（en）の語彙だけが設計どおりの「Invalid request parameters」になる。

# 根拠
- 設計：
  - 0515 の HTML は、冒頭に「専用の基本設計（Excel）シートが無い機能群の現行仕様をまとめたページです」とあり、A15-04 に Excel 由来の部分は無い（全体が現行仕様の節と表示メッセージ節）。優先順位（Excel 由来＞表示メッセージ節＞現行仕様節）の上でも、表示メッセージ節と現行仕様節は同じ文言で、設計の中の食い違いは無い。
  - 表示メッセージ節: 表示位置「API応答の処理結果メッセージ」・画面上の文言「Invalid request parameters」・表示条件「デッキユーザーIDに一致するプレイヤーがないとき」・後続処理「入力不正（HTTP 400）で終了する」: `hareruya-design-docs/excel_to_html/output/0515_基本設計仕様書(API_デッキビルダー).html:395`
  - 業務ロジック「取得できる条件」: 「該当するプレイヤーがないときは入力不正（HTTP 400）とし、メッセージ『Invalid request parameters』を返す。該当が無いときもHTTP 404ではなく入力不正（HTTP 400）で返す」: `hareruya-design-docs/excel_to_html/output/0515_基本設計仕様書(API_デッキビルダー).html:382`
  - 業務ロジック「エラー時の扱い」: 「入力不正（HTTP 400）とし、メッセージ『Invalid request parameters』だけを返す」: `hareruya-design-docs/excel_to_html/output/0515_基本設計仕様書(API_デッキビルダー).html:388`
  - 入出力「失敗時出力」: 「HTTP 400。処理結果コードとメッセージ『Invalid request parameters』」: `hareruya-design-docs/excel_to_html/output/0515_基本設計仕様書(API_デッキビルダー).html:390`
- ec-cube-enterprise：
  - 他ユーザー情報参照の該当なしは PlayerNotFoundException を翻訳したメッセージで 400 にする: `ec-cube-enterprise/src/Eccube/Controller/App/DeckBuilder/UserController.php:69-74`。例外を投げるのは `ec-cube-enterprise/src/Eccube/Service/App/DeckBuilder/GetUserAction.php:43-48`
  - 既定のロケールは ja: `ec-cube-enterprise/app/config/eccube/services.yaml:8`（`env(ECCUBE_LOCALE): 'ja'`）・`:11`（`locale: '%env(ECCUBE_LOCALE)%'`）。開発環境の応答が日本語だったことと合う。
- ベース実装：
  - 英語の固定文言: `deck-api/src/Controller/CustomerController.php:58-61`（他ユーザー情報参照・認証した本人の参照）・`:87-90`（ユーザー情報変更のユーザー名未指定）
  - 探した範囲: deck-api の CustomerController、ec-cube-enterprise の UserController・GetUserAction・messages.ja.yaml・messages.en.yaml・services.yaml・framework.yaml。応答のメッセージを読む呼び出し元は、deck-builder（pages/user/[id].tsx と redux/actions/api.ts の fetchOtherAccount）を確かめた。この画面は応答の code が成功（200）かどうかだけを見て、成功でなければ 404 の画面へ移し、message の本文は読まない。確かめた範囲では、メッセージの文字列を表示したり判定に使ったりする箇所は見つからなかった。このため重要度は文言のP3とした（手元の deck-builder は2025-01-16 時点のもの。現行のデッキビルダーの本番の画面で別の読み方をしていれば、影響は変わる）。
