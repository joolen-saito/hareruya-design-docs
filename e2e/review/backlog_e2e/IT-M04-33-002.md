# 期待される挙動【必須】
- ケースの期待結果（項目表 IT-M04-33-002。E2E のテストID IT-M04-33-002。同じ原因で 004・006 もまとめた）は、ピッキング区分が「4800円未満」（基準価格が閾値未満）、「4800円以上」（閾値以上）で出力されること。

- 設計書内で桁区切りの有無を明示した記述は無く、備考の現行運用の書き方に合わせるか、ケースの期待を桁区切りありに直すかを決める。

# 現在の挙動【必須】
- ピッキング区分が「4,800円未満」「4,800円以上」と、金額に桁区切りが入って出力される（実施は 2026-11-17、開発環境。IT-M04-33-002 は「4,800円未満」、004・006 は「4,800円以上」「4,800円未満」）。
- ほかの項目（データ行の数、列の並び、棚番号、言語/状態、略称、色/R、数、商品名、基準価格）は期待どおり。
- 原因は、ピッキング区分の文字列を組み立てるときに、閾値の金額を number_format（3桁区切り）で整えていること。この整形は、店頭買取・ネット買取の戻しリストと共用する処理（RestockListCsvRowFormatter）にあり、在庫移動の戻しリストCSVも同じ処理を通る。
- ベース実装（現行）には戻しリストの機能が無く（新規）、比べる表記は無い。


# 関連
- 結合テスト：結合試験項目表「テストケース」シート IT-M04-33-002・004・006（E2E のテストID も同じ番号。まとめた）。E2E（Playwright）で開発環境にて実施（2026-11-17）。
- 決め方：設計書は桁区切りを定めていない。備考の現行運用の書き方（桁区切りなし）に合わせるなら、アプリの整形（number_format）を外す。桁区切りありを正とするなら、ケースの期待（004・006 を含む）を「4,800円未満」に直す。なお、この整形は店頭買取・ネット買取の戻しリストとも共用で、直すなら3つの出力が同時に変わる。
- 店頭・ネット買取の戻しリストの同じ表記の扱いは、別の課題がある場合はそちらに合わせる（この課題では確かめていない）。
