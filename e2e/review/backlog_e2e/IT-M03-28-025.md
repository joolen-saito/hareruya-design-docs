# 再現手順【必須】
1. 開発環境（https://replace-dev.hareruyamtg.com:8443）の管理画面で、商品管理＞商品CSV管理の商品タグ更新CSV登録画面（見出し「商品タグ更新CSVアップロード」）を開く（項目表 IT-M03-28-017・018）
2. 「ファイルを選択」でファイルを選ばないまま、「CSVファイルをアップロード」を押す
3. 画面と画面上部のメッセージを確認する
4. 同じ操作を、売上分析タグ更新CSV登録画面（見出し「売上分析タグ更新CSVアップロード」）でも行う（項目表 IT-M03-29-022）

# 期待される挙動【必須】
- ケースの期待結果は、商品タグ更新CSV登録が「商品タグ更新CSV登録画面へ遷移すること」（項目表 IT-M03-28-017）と「CSVの形式不一致を示すエラーが表示されること」（項目表 IT-M03-28-018）、売上分析タグ更新CSV登録が「形式エラーが表示された売上分析タグ更新CSV登録画面へ遷移すること」（項目表 IT-M03-29-022）。
- 設計書の商品タグ更新CSV登録は、現行仕様の節の取込の判定順序 2「取込ファイルの有無」で「ファイルが無いときはフォーマット不一致のエラーを表示して中止する」と定め、表示メッセージ M03-28-MSG-002「CSVのフォーマットが一致しません」（管理画面上部。表示条件は「フォームが有効であるにもかかわらず、取込ファイルが無いとき」。後続は商品タグ更新CSV登録画面）を置いている。売上分析タグ更新CSV登録も、現行仕様の節の取込の前提・エラー時の扱いで「ファイル未選択は形式エラーを表示してアップロード画面へ戻す」、表示メッセージ M03-29-MSG-002「CSVのフォーマットが一致しません」を定めている。
- Excel 由来の画面項目定義は、アップロードのボタン（識別ID 2）を「CSVファイルのアップロードと入力チェックを実施」とだけ書き、ファイル選択の欄の必須チェックにもブラウザの入力チェックにも触れていない。
- 判定の食い違いは、ケースの手順にある。手順のとおり画面だけを操作すると、取込ファイルの欄に付く必須のチェックをブラウザが先に行い、要求がサーバーへ送られないので、設計書の判定順序 2 を確かめられない。確かめるには、ブラウザの必須チェックを外してファイル無しの要求を送る手順（同じ売上分析タグ更新CSV登録のなりすまし対策トークンのケースは、手順に「開発者ツールで」と書いている）をケースに足すか、期待結果を「ブラウザの入力チェックが送信を止め、取込が始まらないこと」に改める。
- 同じ型の既存の課題 ECCUBE_HARERUYA-2632（高額商品価格変更CSVアップロード。完了）は、ブラウザの必須チェックは残したまま、必須チェックを通って届いたときのサーバー側の表示を直す修正で閉じている。

# 現在の挙動【必須】
- 商品タグ更新CSV登録で手順2 のとおり押すと、取込ファイルの欄の下にブラウザの吹き出し（Please select a file.）が出て、要求は送られない。画面上部のメッセージは出ず、画面は同じアップロード画面のまま（見出し「商品タグ更新CSVアップロード」）。ケースの判定項目のうち、遷移先の画面と見出しは期待どおりで、不合格は「取込の要求が送られた」（期待 true・実際 false）と、項目表 IT-M03-28-018 の「画面上部の形式不一致のエラー」が出ないこと（実際は表示なし）。
- 売上分析タグ更新CSV登録も同じ吹き出しが出て要求は送られず、画面上部に「CSVのフォーマットが一致しません」は出ない。
- 原因は、二つの画面が共通のCSV取込フォームを使い、そのファイル欄が必須（画面の入力欄の必須チェックと、空でないことの検証の両方）になっていること。取込の送信フォームには、ブラウザの検証を止める指定が無い。ベース実装（pf-eccube3）も同じ作りで、新しく持ち込んだ差ではない。
- ソースの読みでは、ブラウザの必須チェックを外してファイル無しの要求を送っても、先に「フォームが妥当か」の判定で必須違反となり、フォームの検証エラーを表示して画面へ戻る分岐に入る。設計書の MSG-002 に当たる「取込ファイルが無いとき」に形式不一致を表示する分岐は、その後段にあり届かない。この経路は今回動かして確かめていない。
