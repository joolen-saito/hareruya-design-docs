# 再現手順【必須】
（項目表 IT-F07-04-047：申込の登録で支払方法が空）
1. 参加費のある大会の日程M1と、同じ大会の別日程M2を用意する（合計1000円）
2. 開発環境（https://replace-dev.hareruyamtg.com:8443）に会員でログインし、日程M1のイベント申込画面で別日程の日程M2にもチェックを入れ、支払方法に「クレジットカード」を選び、申込同意にチェックを入れて「支払いへ進む」を押す
3. 申込確定画面で、申込の登録（POST /ja/events/register）の要求に含まれる支払方法を、開発者ツールで空に変えて「申込する」を押す
4. 申込の登録の応答を確認する

（項目表 IT-F07-04-026・027：申込内容の確認で支払方法が空・未設定の値）
1. 参加費のある日程A1のイベント申込画面を開く
2. 開発者ツールで支払方法を空にする（027 は、大会に設定されていない値 999999 にする）
3. 申込同意にチェックを入れて「支払いへ進む」を押し、申込内容の確認（POST /ja/events/confirm）の応答を確認する

# 期待される挙動【必須】
- 項目表 IT-F07-04-047（E2E のテストID IT-F07-04-067）: 合計1000円で支払方法が空のため、申込の登録が HTTP400 になること。設計書の現行仕様の節「申込の登録」の判定順序4（合計が0円か、正しい支払方法があるか。いずれでもなければ不正要求（HTTP400））と、エラー時の扱い「支払方法が不正・空（有料） → 不正要求（HTTP400）」のとおり。現行（ベース実装）も HTTP400 を返す。
- 項目表 IT-F07-04-026・027（E2E のテストID IT-F07-04-033・034）: 申込内容の確認でも、支払方法が空・大会に設定されていない値のとき HTTP400 になること（出典はエラー時の扱いの表）。
  - ただし設計書の「申込内容の確認」の段落は、支払方法の検証を挙げていない（主対象・追加対象の判定とチーム戦のメンバーの検証だけ）。現行も申込内容の確認では支払方法を確かめていない。申込内容の確認での扱い（HTTP400 にするか、新アプリのように申込画面へ戻すか）は確認が要る。
