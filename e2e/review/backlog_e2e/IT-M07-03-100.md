# 再現手順【必須】
1. 買取金額の合計が1550の買取（査定内容承諾）を用意する。明細は、サプライ品（300×1、売却は未定）、カード（査定価格800×1、売却は未定）、まとめて買取（15×3、売却する）、個別入力商品（200×2、売却する）
2. 管理者でログインし、その買取の買取情報編集画面を開く
3. サプライ品の「削除」を押し、確認ダイアログで「OK」を押す
4. 買取金額の合計（画面の査定金額合計の欄・保存されている値）を確認する

# 期待される挙動【必須】
- ケースの期待結果（項目表 IT-M07-03-088。E2E のテストID IT-M07-03-100）は、買取金額の合計が1550から、残る明細の査定価格×数量の合計1245（800＋45＋400）を10円単位に切り上げた1250に更新されること。
- 設計書（現行仕様の節）は、明細を1件削除したときは、買取金額の合計を残っている明細（選んで買取・まとめて買取・個別入力商品）の査定価格×数量の合計から計算し直し、10円単位に切り上げると定める。売却の可否で絞る記述は無い。
- 現行（ベース実装）は、残る全明細の査定価格×数量を合計して10円単位に切り上げる。売却の可否は見ない。

# 現在の挙動【必須】
- 削除は成功し「削除しました」と出る。画面の査定金額合計の表示は1250、査定承諾金額合計は450だが、保存される買取金額の合計は450になる（2026-11-18 開発環境）。
- 450は、売却するの明細（まとめて買取15×3＝45、個別入力商品200×2＝400）の合計445を10円単位に切り上げた値で、画面の査定承諾金額合計と同じ。売却が未定のカード（800）は含まれない。削除したサプライ品（300）の額ではない。
- 買取金額の合計は本人確認の要否の判定（設計書で設定値10000と比較）にも使われる。売却が未定の明細が多いと、合計が実際より小さく保存され、判定や金額表示がずれる。
