# 現在の挙動【必須】
- 手順4の行は、変更前在庫10・変更後在庫7・変更前総原価5000・変更後総原価3500・在庫変動理由は期待どおり。違うのは次の2点（実施は 2026-11-13、開発環境。同じ値は IT-F04-04-044・046・055 の3件でも出た）。
  - 在庫変動数が -3 でなく 3 と表示される（同じ行の「総原価増減数」は -￥1,500 で、在庫変動数と向きが合わない）。044 は 1（期待 -1）、046 は 1 と 2（期待 -1 と -2）、055 は 2回の注文とも 3（期待 -3）。
  - 登録者が空で表示される（期待は「システム」）。
- 開発環境のデータを参照だけで確かめた（2026-11-13）。この行の保存値は在庫変動数 3・操作メンバー名と登録メンバーが空。同じ環境の在庫変動理由区分「受注/受注」（受注による減算）の履歴 1,230 件は、すべて在庫変動数がプラスで、操作メンバー名と登録メンバーが空。一方、同じ出庫でも、在庫編集の廃棄の履歴と受注編集の欠品減算（受注）の履歴は負の値で、買取自動入庫バッチ（登録元「買取自動入庫バッチ」）の履歴は操作メンバー名に「システム」が入っている。
- 在庫は注文数を引いて更新され、総原価も減算で計算されるので在庫・総原価の値は合っているが、履歴へは注文数がそのまま（正の値で）渡されるため、履歴の在庫変動数の符号だけがずれる。登録者は、保存する値（操作メンバー名・登録メンバー）が空のまま渡されている。一覧の「登録者」の列は登録メンバーの名前だけを出す作りで、操作メンバー名の欄を出す箇所は一覧に無い。
- 直す場合の案: 注文確定の在庫減算の履歴には注文数の負の値を渡し、登録者には「システム」を保存して一覧に出す（一覧の「登録者」が登録メンバーしか見ないので、操作メンバー名の表示側の確認も要る）。注文キャンセルの戻し（プラス）は今のままで合っている。
