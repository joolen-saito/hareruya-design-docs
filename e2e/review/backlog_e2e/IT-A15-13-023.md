要件元：現行踏襲（現行の deck-api も、限定公開のデッキだけトークンを返す）

# 再現手順【必須】
1. 開発環境に、プレイヤーAが所有する非公開（公開範囲2）のユーザーデッキを用意し、そのデッキに限定公開トークン「display-<デッキID>」を設定する（項目表の事前準備のとおり。トークンは画面で指定できず DB で書く）
2. 開発環境の API（https://replace-dev.api.hareruyamtg.com）の GET /api/decks に、mode=private・プレイヤーAの有効な jwt-token・format にそのデッキのフォーマットを付けて送る（項目表 IT-A15-13-009）

# 期待される挙動【必須】
- プレイヤーAが所有するデッキだけが返り、deck_user_id・nickname と、display_token が「display-<デッキID>」で返る（項目表 IT-A15-13-009 の期待結果）。
- 設計書の display_token の説明は「限定公開トークン。自分のデッキ検索のときだけ含める」で、公開範囲による出し分けは書かれていない。

# 現在の挙動【必須】
- デッキの一覧は期待どおり（プレイヤーAのデッキ1件だけ・deck_user_id・nickname も一致）だが、display_token が null で返る（2026-11-25 開発環境）。
- 原因: 自分のデッキ検索で、公開範囲が限定公開（3）のデッキだけトークンを返し、それ以外は null にしている。現行（deck-api）も同じ出し分けで、画面（管理画面・デッキビルダー）で作る非公開デッキにはトークンが付かないので、ケースの前提（非公開デッキがトークンを持つ）は通常の操作では起きない。

ec-cube-enterprise 自分のデッキ検索の display_token: `ec-cube-enterprise/src/Eccube/Controller/App/DeckBuilder/DeckController.php:509-511`
```php
            if ($isPrivate) {
                $item['display_token'] = $Deck->getDisp()->getId() === self::DISPLAY_UNLISTED ? $Deck->getDisplayToken() : null;
            }
```
ベース実装（deck-api） 限定公開のときだけトークンを選ぶ: `deck-api/src/Repository/DtbDeckRepository.php:509`
```php
$qb->addSelect('CASE WHEN d.dispId = ' . MtbDisp::DISPLAY_UNLISTED . "THEN d.displayToken ELSE d.deletedAt END AS display_token")
```

# 根拠
- 設計: A15-13 の出力項目 display_token（限定公開トークン。自分のデッキ検索のときだけ含める）
- ec-cube-enterprise・ベース実装（deck-api）: 上の抜き書き

# 関連
- ケースの期待値の側の確認が要る（限定公開でないデッキにトークンを持たせた前提が、設計書と現行の動きに合うか）。
