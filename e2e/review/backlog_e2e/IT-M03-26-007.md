# 期待される挙動【必須】
- ケースの期待結果は「商品、商品サブ情報、規格、商品カテゴリ、商品タグ、売上分析タグおよび規格画像がCSVの1行の値で追加されること」。NMの規格の買取価格はCSVの値の15。
- 設計書は、NMの規格の買取価格の扱いを機能ごとに別に定めていて、食い違っている。
  - 買取・基準価格一括編集: 買取減額率があるときは状態ごとの率を掛けて100円単位で切り上げる。「良品（NM）には率を掛けないため、入力値を100円単位で切り上げた額になる」（15なら100）。
  - 基準価格変更CSVアップロード: 「規格のカード状態がNMのときはCSVの値をそのまま使う」（15なら15）。
  - カード商品CSV登録: 買取価格は「状態別の買取計算の入力」とあるだけで、NMの扱いの定めが無い。Excel 由来のカード商品CSVフォーマットの表も、買取減額率(ID)（例 1）・買取価格（例 15）に計算の定めは無い。
- カード商品CSV登録で、買取減額率を指定した行のNMの規格の買取価格を、CSVの値のままにするか、100円単位に切り上げるかを確認したい。

# 現在の挙動【必須】
- NMの規格の買取価格は100で登録された。ほかの10項目（商品・カテゴリ・タグ・規格画像など）と、NMの規格の基準価格300・販売価格300・販売制限数25は、CSVどおりだった。
- カード商品CSV登録は、行に買取減額率があると、NMの規格にもその率を掛けて100円単位で切り上げる。買取減額率ID1のNMの率は1.00なので、15が100になる。
- 同じアプリでも、基準価格変更CSVなどが使う買取価格の再計算の部品は、NMには率を掛けずにCSVの値をそのまま返す。アプリの中で、NMの扱いが二通りある。
- ベース実装のカード商品CSV登録も、同じ計算（NMにも率を掛けて100円単位で切り上げる）をしている。新しいアプリは現行どおり。

    {

            $discountedPrice = bcdiv(bcmul((string) $nmPrice, (string) $buyDiscountRate, 4), '100', 4);
