# 期待される挙動【必須】
- ケースの期待結果（項目表 IT-M04-32-007。E2E のテストID IT-M04-32-110）は、承認後の在庫変動数 3 の行で、変更前在庫 10・変更後在庫 13・仕入単価 300・変更前総原価 1000・変更後総原価 1900 などが表示されること。
- 設計書の在庫履歴検索一覧(検索結果)の画面項目定義 識別ID 2-16「仕入単価」は、「「在庫編集」シート識別ID:3-4仕入単価を参照」「値がない場合は "-" を表示」と定める。在庫編集の識別ID 3-4 は在庫変動区分の親区分が「入庫」のとき必須入力（0以上）、「廃棄」のとき入力不可。つまり履歴の仕入単価は、在庫編集で入庫に入れた仕入単価（この例では 300）で、入庫でない行は "-" になる。

- 同じ在庫履歴検索一覧(検索結果)のシートのカスタマイズ要件には「既存の在庫変動履歴に、変更時の商品の買取価格を持たせるようにする」とも書かれている。これは履歴が買取価格を保持することを求める記述で、仕入単価の列の値を買取価格に置き換える指定ではない（識別ID 2-16 の参照先は在庫編集の仕入単価）。

# 現在の挙動【必須】
- 承認は成功し、在庫変動数 3 の行は、店舗・在庫区分・登録元「在庫編集」・在庫変動理由・変更前在庫 10・変更後在庫 13・変更前総原価 1000・変更後総原価 1900・登録者・承認者・承認日まで期待どおり。不合格は「仕入単価」だけで、画面には「￥1」と出る（期待は 300。実施は 2026-11-13、開発環境）。
- 同じ商品の最初の入庫（在庫増減数 10、仕入単価 100 で入庫して承認した行）も「仕入単価 ￥1」と出る。履歴の仕入単価が入力値と無関係に、商品規格の買取価格（この商品は 1）になっている。
- 開発環境のデータを参照だけで確かめた（2026-11-13）。在庫編集の申請の明細には仕入単価 300.00（最初の入庫は 100.00）が正しく残り、承認後に作られた在庫変動履歴の買取価格の欄は 1（商品規格の買取価格と同じ）。総原価は申請の明細の 300 で計算されているので、仕入単価が履歴へ渡っていないのは表示の値だけ。
- 原因は、入庫の承認で在庫変動履歴を作る処理が、申請の明細の仕入単価を受け取らず、履歴の保存処理が「変更時買取価格」の欄へ商品規格の買取価格を入れていること。在庫履歴の一覧はその欄を「仕入単価」の列に出し、仕入単価での検索（From・To）も同じ欄を使う。履歴には在庫編集で入れた仕入単価を持つ欄が無い。
- シードの補い（商品公開ステータスを「1」にした・部門は選択肢の先頭を選んだ・承認の検索は「承認可能な在庫のみ表示」を初期のままにした）は、この値に影響しない。申請の明細は 300 で保存され、履歴が 1 になるのは上のとおりアプリの処理による。
