# 再現手順【必須】
1. 開発環境（https://replace-dev.hareruyamtg.com:8443）の管理画面で、商品管理＞部門登録/編集を開く（新規登録モードの画面）
2. 部門名と部門コードを空にし、免税区分を未選択にしようとする（選択欄の選択肢は「対象外」「一般品」「消耗品」だけで、未選択の選択肢は無い。選択欄は変えずに進める）
3. 画面下部の「登録」を押す
4. 画面を確認する（項目表 IT-M03-18-017）

# 期待される挙動【必須】
- ケースの期待結果（項目表 IT-M03-18-017）は「必須入力のエラーを表示した部門登録/編集画面が再表示されること」。出典は設計書の現行仕様の節 保存の判定順序 3「入力が項目定義の条件を満たすか」（満たさないなら登録・更新を行わず、満たさなかった内容をエラーとして表示する）と、表示メッセージ M03-18-MSG-001「登録できませんでした。」（後続は部門登録／編集画面に留まる）。
- 設計書の画面項目定義は、部門名（識別ID 4）・部門コード（5）・免税区分（6）を必須（〇）としている。空のまま保存しようとしたときに、保存されないことと、エラーを示すことが期待される。
- 判定の食い違いは、ケースの手順にある。手順2・3 のとおり画面だけを操作すると、部門名・部門コードの欄に付く必須のチェックをブラウザが先に行い、要求がサーバーへ送られない。設計書の判定順序 3 を確かめるには、ブラウザの必須チェックを外して空の要求を送る手順（同じ型のほかの画面のケースは手順に「開発者ツールで」と書いている）をケースに足すか、期待結果を「ブラウザの入力チェックが送信を止め、部門が追加されないこと」に改める。免税区分を「未選択にする」操作は、選択肢に未選択が無く画面からはできないので、手順から外すか、開発者ツールで空の値を送る手順にする。

# 現在の挙動【必須】
- 手順3 で「登録」を押すと、部門名の欄の下にブラウザの吹き出し（Please fill out this field.）が出て、要求は送られない。部門コードの欄にも同じ吹き出しが出る。画面上部のメッセージ（「登録できませんでした。」）は出ず、画面は再表示されない（見出しは「新規追加」のまま）。
- 部門名・部門コードの必須は、アプリの部門の入力欄の定義が両方を必須にしているため、画面の入力欄の必須チェックとして働く。ベース実装（pf-eccube3）も同じ作りで、新しく持ち込んだ差ではない。
- ブラウザの必須チェックを通って要求が届いた場合の処理は、ソースの読みでは設計書どおり（入力の検証に失敗したら「登録できませんでした。」を出して部門登録/編集画面を描き直す）。この経路は、今回は画面で動かして確かめていない。
