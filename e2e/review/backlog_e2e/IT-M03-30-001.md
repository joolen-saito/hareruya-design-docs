# 期待される挙動【必須】
- ケースの期待結果（IT-M03-30-001）は、設計のフォーマットの5列（商品ID・言語ID・基準価格・買取価格・原価単価）のファイルを取り込むと、セールフラグ無効の規格の基準価格・販売価格・買取価格が1200・1200・500に更新されること。同じ5列のファイルを使う21件のケースも、取込が通ることを前提にしている。
- 設計書のフォーマット表は識別ID 5「原価単価」を必須（◯）・入力例500の5列目に載せ、機能仕様にも「★識別ID:5「原価単価」を新規追加」とある。一方、同じ行の備考は「※カスタマイズ対応、新規追加→こちら対応なし」とあり、原価単価を取り込むのか取り込まないのか読み取れない。基準価格変更CSVアップロードのシートの機能仕様（識別ID 3）は、販売価格を基準価格へ変える点だけを書き、原価単価の追加には触れていない。

# 現在の挙動【必須】
- 画面の「基準価格変更CSVファイルフォーマット」の表は商品ID・言語ID・基準価格・買取価格の4行で、雛形ファイルも4列。設計のフォーマット表どおりの5列のファイルを送ると、取込は始まらず、画面上部に「CSVのフォーマットが一致しません。 2 行目のデータを確認してください。」が出て、取込履歴も価格履歴も増えず、規格の価格は取込前のまま（基準価格1000・販売価格900・買取価格400）だった。
- 同じ開発環境・同じ実行で、画面の雛形（4列）に合わせたファイルを使う IT-M03-30-093 は取込のあとの価格が変わり合格している。取込そのものは動き、5列目の有無だけで止まる。
- 原因は、取込が定義する列が4つ（商品ID・言語ID・基準価格・買取価格）だけで、行の列数が定義の数と違うと1行目のデータ行（画面上の2行目）で打ち切ること。原価単価の列の定義は、同じ取込の仕組みの中にあり、グッズ商品CSVの取込では使われているが、基準価格変更CSVでは使われていない。
- この1件で、ケース22件（下の「関連」）が取込のあとの確認（価格・価格履歴・取込履歴・エラー文言）まで進めず、不合格になっている。同じ形で落ちた前回（2026-10-26、手元の環境）の IT-M03-30-037・055・059（項目表 IT-M03-30-029・036・040）も同じ原因。
