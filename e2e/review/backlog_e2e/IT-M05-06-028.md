# 期待される挙動【必須】
- ケースの期待結果（項目表 IT-M05-06-023）は、「メッセージ本文の注文者名に「本店 太郎」が表示されること」。ケースの出典は「0203 メール一括送信 / 画面項目定義 識別ID 3」。
- 設計書（Excel 由来）の画面項目定義 識別ID 3 は「メッセージ本文-注文者名」（ラベル。説明は「注文者名を表示させないメールの場合は非表示」）。識別ID 5「メッセージ本文-本文」もラベルで、入力画面でどの値に置き換わるかの記述は無い。
- 同じ Excel のシートの画面イメージ（メール一括送信・入力画面）は、メッセージ本文の先頭行を「{{ Order.name01 }}　{{ Order.name02 }}　様」、本文の中も「{{ orderNumber }}」「{{ Order.orderDate|date… }}」などの差し込み記号のまま描いている。注文者名の実名（「テスト 太郎」など）は、画面右の「メール送信先情報一覧」の表にだけ出る。
- 差し込みを解決するのは送信のときで、設計書の業務ロジック「送信」に「送信は対象受注ごとに 1 通ずつ行う。本文は受注ごとに差し込みを解決して組み立てるため、受注ごとに内容が変わる」とある（現行仕様の節）。入力画面の本文欄で差し込みを解決して見せる記述は、設計書のどの節にも無い。
- したがって、設計書に従えば、入力画面のメッセージ本文は差し込み記号のままで正しく、ケースの期待結果（本文に「本店 太郎」が表示される）が設計書の画面イメージと合っていない。
- どちらを正とするかの確認が要る。
  - A. 設計書どおり（画面イメージ・現行どおり）入力画面は差し込み記号のまま表示する場合: ケース IT-M05-06-023 の期待結果を、「本文の先頭に差し込み記号が表示される」あるいは確認画面・送信後のメールで「本店 太郎」が出ることを確かめる形に直す（アプリはそのまま）。
  - B. 入力画面の本文欄でも差し込みを解決して見せる場合: 設計書の画面イメージと説明を直し、アプリを変える。

# 現在の挙動【必須】
- メール一括送信画面でテンプレートを選ぶと、メッセージ本文は先頭行が「{{ Order.name01 }}　{{ Order.name02 }}　様」、「【注文番号】{{ orderNumber }}」「【ご注文者】{{ Order.name01 }}　{{ Order.name02 }}　様」など、差し込み記号のまま表示された。「本店 太郎」は本文には出ず、画面右の送信先の表（注文番号 00008945・注文者名「本店 太郎」）にだけ出た（E2E 2026-11-16、開発環境。E2E の期待結果の確かめ1件の不合格）。この画面は設計書の画面イメージと同じ見え方である。
- 受注ごとの差し込みは送信のときに行われている。同じ機能の別ケース IT-M05-06-015（E2E IT-M05-06-015）は、2件の受注に送った2通の本文に、各受注の注文番号・注文者氏名が差し込まれた異なる内容で届いたことを確かめ、合格している。
- 新しいアプリの入力画面は、選んだテンプレートの原文（差し込み記号を含む）を、ヘッダー・フッターの入力欄を埋め込んだだけで本文欄へ渡す。受注ごとの差し込みの組み立ては、確認画面（先頭の受注の本文を組み立てて見せる）と送信のときにだけ行う。
- ベース実装（現行）の入力画面も同じで、テンプレートの原文を本文欄へ渡し、受注ごとの本文の組み立ては送信のときに行う。つまり、現行も入力画面は差し込み記号のまま表示する。
- 結論: アプリの動きは設計書の画面イメージ・ベース実装（現行踏襲）と同じで、ケースの期待結果だけが合っていない見込み。
