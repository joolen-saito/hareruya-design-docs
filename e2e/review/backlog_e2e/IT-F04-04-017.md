# 期待される挙動【必須】
- ケースの期待結果（項目表 IT-F04-04-016。E2E のテストID IT-F04-04-017）は、カートに商品が数量3のまま残ること。
- 同じ原因のケース:
  - 項目表 IT-F04-04-012（E2E IT-F04-04-013）: 非公開にした商品が、カートに数量1のまま残ること。
  - 項目表 IT-F04-04-014（E2E IT-F04-04-015）: 購入制限数を超えた商品が、カートに数量3のまま残ること。
- 設計書（0304 決済~購入完了 機能仕様 処理概要「画面遷移時の処理」・Excel 由来）は、購入処理の前に、非公開の商品・購入制限数を超える数量・在庫の無い数量をエラーとし、「エラーの場合、カート内の商品そのままの状態でシステムエラーの画面へ遷移する」と定める。
- 在庫不足は、表示メッセージ F04-04-MSG-001・002「「%name%」の在庫が足りません。」で、更新を取り消し、エラーメッセージを表示して購入エラー画面へ遷移する。

# 現在の挙動【必須】
- 在庫不足（在庫2・数量3）: 「注文する」を押すと、購入エラー画面ではなく、ご注文方法指定画面（/ja/shopping）に戻り、「在庫が不足しております。一度に在庫数を超える購入はできません。」と出る。ご注文の商品とカートの数量は、在庫数の2に減らされている（2026-11-20 16:16 開発環境）。
- 購入制限数超え（制限2・数量3）: 購入エラー画面（/ja/shopping/error）へ移るが、カートの数量は2に減らされている（15:34）。
- 非公開: 購入エラー画面（/ja/shopping/error）へ移るが、カートからその商品が消えている（14:51）。
- 新しいアプリは、注文の前に購入の流れの確かめ（PurchaseFlow の validate）を通す。確かめの中で、数量を在庫数・購入制限数まで減らしたり、非公開の商品を外したりする。減らした場合は「警告」としてご注文方法指定画面へ戻し、外した場合は「エラー」として購入エラー画面へ移す。
