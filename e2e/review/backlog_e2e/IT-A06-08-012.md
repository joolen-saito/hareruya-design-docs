# 期待される挙動【必須】
- ケースの期待結果（項目表 IT-A06-08-011。E2E のテストID IT-A06-08-012）は、指定した名称に当たる商品が無いとき HTTP 404 になること。
- 設計書（Excel 由来）は、リクエスト書式を「クエリ」、パラメータを name と定め、指定された名称に紐づく商品が見つからなかった場合のステータスコードを 404 と定める。
- 現行（ベース実装の pf-api）は、name をクエリで受け取り、該当する商品が無ければ 404 を返す。

# 現在の挙動【必須】
- name をクエリで渡すと読まれず、カード名が空のときの扱いになって、HTTP 200 と本文 {"cards":{}} が返る（2026-11-21 開発環境。項目表 IT-A06-08-011）。
- name を本文で渡した場合も、該当する商品が無ければ 404 にはならず、空のカード一覧が返る作り。
- 0件の応答を {"cards":{}} にする扱いは、ECCUBE_HARERUYA-4237（A06-07・A06-10 の0件の応答）で開発が意図して選んだ形。この API でも同じ考えなら、設計書の 404 の定めが追いついていない。
- 買取アプリ（MTGバイヤー）がクエリと本文のどちらで送っているかは確かめていない。
