# 再現手順【必須】
1. 開発環境（https://replace-dev.hareruyamtg.com:8443）の管理画面で、状態が「査定中」の買取受注の手動メール通知(入力画面)を開く
2. テンプレ選択で「02査定テンプレ」を選ぶ（選ぶと画面が更新され、件名とメール本文にテンプレートの内容が入る）
3. 件名を空にして、メール本文に任意の文字列（例: 件名必須確認本文）を入力する
4. 開発者ツールで、件名の必須属性（ブラウザ側の必須チェック）を外す
5. 「確認」を押す
6. 戻ってきた入力画面の、件名・メール本文の値と、画面上のメッセージを確認する
7. 同じ手順で、件名に任意の文字列（例: 本文必須確認件名）を入れてメール本文を空にし、メール本文の必須属性を外して「確認」を押す場合も確認する（IT-M07-04-014）

# 期待される挙動【必須】
- 設計書の現行仕様の節 業務ロジック「検証に通らなかったときの扱い」は「入力の検証に通らなかったときはメールを送らない。このとき項目ごとのエラーは表示せず、手動メール通知の入力画面を開き直すため、入力していた件名と本文は残らない」と定める。ケースの期待結果（項目表 IT-M07-04-013・IT-M07-04-014。E2E のテストID は同じ）も「手動メール通知(入力画面)が開き直され、項目ごとのエラーが表示されず、件名と入力したメール本文（014 は入力した件名とメール本文）が残らないこと」。
- Excel 由来の部分は、機能仕様に「確認ボタン押下時、フォーム内容の入力チェックをサーバ側で行う」とあり、画面項目定義は件名・メール本文を必須とし、初期値を「テンプレ選択が未選択なら空欄、選択されていれば選ばれたテンプレートの件名・本文を初期セット」と定めるだけで、検証に通らないときに入力値を残すか・エラーを出すかは定めていない（現行仕様の節と食い違いはない）。
- したがって設計書どおりにするなら、検証に通らないときは項目ごとのエラーを出さず、送られた値でなく選択中テンプレートの内容で入力画面を開き直す。一方、現行仕様の節のこの記述は、ベース実装が送信後に必ず開き直す作りの副産物を書き写したもので、入力値を失わせ理由も示さない動きでもあるため、現行どおりに戻すか、記述を直して今の動き（入力値を残して理由を示す）を認めるかの判断を要する。

# 現在の挙動【必須】
- 手順5 の「確認」を押すと、確認画面へは進まず手動メール通知の入力画面に戻る。テンプレ選択は選んだもの（02査定テンプレ）が保たれる。
- IT-M07-04-013: 件名は空のまま、入力したメール本文「件名必須確認本文」も残り、件名欄は赤枠になり、その下に「エラー 入力されていません。」が出る。テンプレートの初期値（件名「刷新件名Ａ1」と選択時の本文）には戻らない。
- IT-M07-04-014: 入力した件名「本文必須確認件名」が残り、メール本文は空のまま赤枠になり、その下に「エラー 入力されていません。」が出る。
- 設計書の現行仕様の節は「項目ごとのエラーは表示せず」「入力していた件名と本文は残らない」と定めるので、エラー表示も入力値の保持も現行仕様の記述と違う。Excel 由来の部分・表示メッセージの節にはこのエラー表示の記述は無い。
- 原因は、確認の要求で入力の検証に通らないとき、送られた値でフォームを描き直して返す作りにあること。ベース実装は、送信のあと検証の成否にかかわらず必ずリダイレクトで開き直し、テンプレートの値から描き直すので、入力値は残らずエラーも出ない。
