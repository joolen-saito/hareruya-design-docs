# 再現手順【必須】
1. 開発環境（https://replace-dev.hareruyamtg.com:8443）の管理画面でイベント管理＞イベント一覧から任意のイベントの編集画面を開く
2. イベント名(日)を変更して「更新」ボタンを押す
3. 遷移後の画面を確認する（イベント一覧でなく、同じイベントの編集画面 /admin/event/<イベントID>/edit のまま）

# 期待される挙動【必須】
- 設計書内で2通りの記述がある。Excelの画面遷移図は「更新 → イベント一覧」、現行仕様の業務ロジックは「更新に成功したら完了メッセージを表示し、当該イベントの編集画面へ戻す」
- ベース実装（現行踏襲）は編集画面へ戻る。どちらを正とするかを設計書で確定し、ケースか実装を揃える

# 現在の挙動【必須】
- 更新に成功すると完了メッセージを出し、遷移せずに同じイベントの編集画面を再表示する（一覧へのリダイレクトは無い）。

ec-cube-enterprise イベント編集の保存処理: `ec-cube-enterprise/src/Eccube/Controller/Admin/Event/EventController.php:320-339`
```php

                $event = new EventArgs(
```
