# 現在の挙動【必須】
- 手順3で押すと取込の要求は送られ（応答は302）、取込は始まらず、画面上部に「CSVのフォーマットが一致しません。」が出て、アップロード画面へ戻る。「列順変更カテゴリ-040」は0件（期待は1件）。ケースの判定項目のうち、不合格はこの件数だけ。
- 原因は、取込の前に見出し行を「期待する列名の一覧（雛形と同じ並び）」と、列名と並びの両方で完全に一致するか比べる検査が入っていて、並びが違うと不一致で全体を止めること。この検査は、ECCUBE_HARERUYA-3371（CSV取込の見出し検証の共通課題）の一つとして2026-11-02にカテゴリ登録CSVの取込へ加わった（コミット 2d330e9399）。
- 検査より後の取込は、値を列名で引く作りなので、並びが違っても取り込める。検査が無かった版は並びを問わない（前回 2026-10-27・手元の環境の実行は、検査が入る前のアプリ（2026-10-19 のコミット 95fd74af4c）で合格した）。今回の開発環境のアプリの版は記録に無いが、いまの ec-cube-enterprise（develop）には検査があり、症状と合う。
- 検査を足したときのコードのコメントは「新規のCSVで現行に合わせる形式がないため、任意列は設けない」。しかしカテゴリ登録CSVには現行（pf-eccube3）に取込があり、見出し名で値を読み、並びは見ない。
- ベース実装（pf-eccube3）は、見出し行から必須の列名「カテゴリ名」だけを確かめ、データ行は列名で値を引く。並びは何も見ない。

# 関連
- 結合テスト：結合試験項目表「テストケース」シート IT-M03-41-037（E2E のテストID IT-M03-41-040）。E2E（Playwright）で開発環境にて実施（2026-11-13）。前回（2026-10-27、手元の環境）は合格

- 見出し検証が絡む同じ型の課題：ECCUBE_HARERUYA-4023（セール用価格変更CSV。見出しの名前の違い）・ECCUBE_HARERUYA-4037（売上分析タグ更新CSV）・ECCUBE_HARERUYA-4042（在庫移動実績CSV）
