# 期待される挙動【必須】

- 現行（ベース実装の pf-api）は、どちらもクエリでも本文でも受け取る。

# 現在の挙動【必須】
- ステータス更新: status をクエリで渡すと読まれず、どの受注でも「正しい店頭買取ステータスIDを入力してください」が返る。業務の条件（査定終了からの戻しの禁止など）の判定まで進まない（2026-11-19 開発環境。項目表 IT-A07-04-009・017・018・021・022・023）。
- 商品一覧の取得: ids をクエリで渡すと読まれず、HTTP 200 で空の配列が返る（2026-11-19 開発環境。項目表 IT-A07-06-002〜007・012〜019）。同じ ids を要求の本文（フォームの値）で送ると、受注の買取代表カードが返ることを確かめた（例：IT-A07-06-003 で2件）。
- 買取アプリ（MTGバイヤー）がどちらで送っているかは確かめていない。本文で送っているなら実害は無く、クエリで送っているなら、ステータス更新と商品一覧の取得が働かない。
