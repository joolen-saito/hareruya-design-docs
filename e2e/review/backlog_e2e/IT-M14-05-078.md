# 再現手順【必須】
1. 使用可能フォーマットがPioneerで紐付いている既存カードを登録しておく
2. 同じカード名(英語)の行で、使用可能フォーマット列を空にし、使用制限フォーマット列にVintageを書いたCSVを用意する
3. 開発環境（https://replace-dev.hareruyamtg.com:8443）の管理画面でカード登録CSVアップロード画面を開き、アップロードする
4. 取込後のカードの使用可能フォーマットを確認する（Pioneerの紐付けが消えて0件になる。使用制限のVintageだけが残る）

# 期待される挙動【必須】
- 使用可能フォーマットは、行に挙がっていない既存の紐付けを削除する。ただし値が空の行では、既存の紐付けを変更しない（現行仕様 業務ロジック「列ごとの取り込み方」）。この例ではPioneerの紐付けが残る

# 根拠
- 設計：
  - 現行仕様 業務ロジック「列ごとの取り込み方」使用可能フォーマット: 行に挙がっていない既存の紐付けを削除する。値が空の行では既存の紐付けを変更しない: `hareruya-design-docs/excel_to_html/output/0208_基本設計仕様書(カード管理).html:1759`
  - Excel 項目表 18〜20（使用可能・使用制限・使用禁止。制限・禁止はカスタマイズで追加。互いの空欄の扱いは書かれていない）: `hareruya-design-docs/excel_to_html/output/0208_基本設計仕様書(カード管理).html:1822-1824`
- ec-cube-enterprise：
  - 3列のどれかに値があれば入れ替え: `ec-cube-enterprise/src/Eccube/Service/Csv/CardCsv.php:503-509`
  - 挙がっていない既存の紐付けを削除: `ec-cube-enterprise/src/Eccube/Service/Csv/CardCsv.php:694-699`
- ベース実装：
  - 使用可能フォーマットが空でなければ入れ替える（空なら変更しない）: `pf-eccube3/app/Plugin/HareruyaEc/Service/Csv/CardCsv.php:96-98`
  - 探した範囲: pf-eccube3 の Service/Csv/CardCsv.php（updateCardFormat）
- 補足: 使用制限・使用禁止の列が追加された要件は、空欄の列の扱いを定めていない。設計書の「使用可能フォーマットが空なら変えない」を守る前提で実装バグとした。同じ原因で IT-M14-05-086 も不合格。
