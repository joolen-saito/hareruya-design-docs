# 期待される挙動【必須】
- ケースの期待結果（項目表 IT-F09-08-089。E2E のテストID IT-F09-08-095）は、誤りの一覧が「先頭に商品なしの誤りの総括の文言（商品が存在しないカードが含まれています。）、続けて「1行目: （カード名）」」の2件だけで、買い物かご画面へ移らないこと。
- 設計書（0309 F09-08）は、検索の条件として「商品: 削除されておらず、公開中の商品だけを対象とする」と定め、判定の順序の3番目に「商品が見つからないカードがある → 商品なしとして通知し、以降を判定しない」、4番目に「指定した条件で在庫を引けないカードがある → 在庫不足として通知する」と定める。

# 現在の挙動【必須】
- 誤りの一覧は「指定された条件で在庫が不足しているカードがあります。」、続けて「1行目: （カード名）」の2件になる（2026-11-23 開発環境）。買い物かご画面へは移らず、処理結果は失敗で、商品規格と数量の組は返らない（ここはケースどおり）。
- 新アプリは、判定の3番目の「商品が見つからない」を、公開の状態も削除も見ずに「そのカードに紐づく商品が1件でもあるか」だけで判定している。公開中かどうかは4番目の在庫を引く検索の側で見ており、非公開の商品しか無いカードは3番目を通り抜け、4番目で候補が0件になって「在庫不足」の総括になる。
- ベース実装（pf-eccube3）も、商品の存在判定は商品とのつながりだけで行い（公開の状態を見ない）、存在すれば在庫の判定へ進む。同じ入力で新アプリと同じく「条件に合う在庫が無い」側の総括になる（現行踏襲）。

- 確認したいこと: 非公開の商品しか無いカードを「商品なし」とするか「在庫不足」とするか。
  - A. 設計書の「公開中の商品だけを対象とする」を商品なしの判定にも当てる: 新アプリの存在判定に公開・削除の条件を足す（ケースの期待結果のとおりになる）。
  - B. 現行どおり、存在判定は商品の有無だけとし、非公開は「在庫不足」とする: 設計書の判定の順序の3番目に「公開の状態は見ない」と明記し、ケースの期待結果を「在庫不足の総括」に直す。設計書の「公開中だけ」は「在庫を引く条件」の節にあり、商品なしの判定にも及ぶかは書かれていない。
- 影響: 非公開の商品しか無いカードをカードリストに入れた利用者に出る誤りの総括の文言（行ごとの誤り「1行目: …」と、買い物かごへ進めないことは変わらない）。
