# 再現手順【必須】
1. 公開・固定のセールタグありの商品を用意する。同じ商品の規格は、カード状態が最小（NM）の規格Aと、2番目の状態の規格Bの2つで、いずれも日本語・販売価格1円以上とする
   - 例1: 規格Aはセール中でなく在庫あり、規格Bはセール中・在庫あり
   - 例2: 規格Aはセール中だが在庫0、規格Bはセール中・在庫あり
2. 開発環境（https://replace-dev.hareruyamtg.com:8443）の日本語版の支店ECTOPをログアウト状態で開く
3. 「SALE中の商品」にその商品が載っているかを確認する

# 期待される挙動【必須】
- SALE中の商品に載せるのは、同一商品の全規格（セール中かどうか・在庫の有無・表示対象かどうかを問わない）のうちカード状態IDが最も小さい規格だけ。その規格がセール中でないときは、その商品を載せない（例1は載せない）。最小状態の規格に在庫が無いときも、より後ろの状態の規格に置き換えて載せない（例2も載せない。ベース実装は在庫なしの最小状態の規格を載せず、他の状態の規格にも置き換えない）

# 現在の挙動【必須】
- 例1・例2のどちらも、規格Bが「SALE中の商品」に載る（表示数 期待0に対し実際1）。最小状態の規格Aがセール中でない／在庫が無いのに、規格Bで代表されている。

# 根拠
- 設計：
  - SALE中の商品は同一商品のすべての商品規格のうちカード状態IDが最も小さいものだけを載せる。比べる相手はセール中・在庫の有無・表示対象を問わない。最小の規格がセール中でないときはその商品を載せない: `hareruya-design-docs/excel_to_html/output/0301_基本設計仕様書(フロント_トップ).html:2677`
- ec-cube-enterprise：
  - セール中・在庫ありなどで絞り込んだ規格だけから代表を選ぶ: `ec-cube-enterprise/src/Eccube/Repository/ProductRepository.php:424-447`
  - 代表の選出は絞り込み後の候補の中だけで比べる: `ec-cube-enterprise/src/Eccube/Repository/ProductRepository.php:718-731`
- ベース実装：
  - 同一商品にカード状態が小さい規格があれば載せない（絞り込みに関係なく全規格と比べる）: `ec-cube/app/Customize/Repository/ProductClassRepository.php:147-159`
  - 探した範囲: ec-cube（支店）の Customize/Repository/ProductClassRepository.php の getSaleProductClasses と Controller/Block/FirstViewController.php:140
