# 再現手順【必須】
1. 数量2・欠品0・価格900・値引き0・送料0・手数料0・ポイント率0・発生0・使用0・在庫10の商品を含む受注を用意する（受注した会員のポイントは0）
2. 開発環境（https://replace-dev.admin.hareruyamtg.com:8443）の管理画面で、その受注の受注情報編集画面（/admin/order/<受注ID>/edit）を開き、「欠品登録」を押す
3. 数量2、欠品数量1、価格1000、値引き100、送料500、手数料200、ポイント還元率5、ポイント発生50、ポイント使用100を入れる
4. 「受注情報を登録」を押す
5. 画面のエラーを確認する

# 期待される挙動【必須】
- 入力した整数値が各項目へ保存される（ケースの期待）。設計書の画面項目定義 11-3〜11-5 は、ポイント還元率・ポイント発生・ポイント使用を整数の必須項目とするだけで、会員の所有ポイントを超える使用の扱いは定めていない
- 所有ポイントを超える使用を保存できるか、できないかを設計書で確定する。できないなら、ケースのシードで会員に使用額以上のポイントを付ける。できるなら、新アプリの検査を外す

# 現在の挙動【必須】
- 「利用ポイントが所有ポイントを上回っています。」が出て保存されない。ケースのシードは、受注の会員にポイントを付けていない（所有ポイント0）ため、使用100は所有ポイントを上回る。
- 新アプリは、受注の更新時に使用ポイントの増分が会員のポイント残高を超えるとエラーにする。
- ベース実装は、使用ポイントをフォームの値のまま保存しており、会員の所有ポイントとの突き合わせは無い。新アプリの検査は設計書にもベース実装にも無い。
