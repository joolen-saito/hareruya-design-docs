# 期待される挙動【必須】
- ケースの期待結果（項目表 IT-A06-07-011。E2E のテストID IT-A06-07-011）は、HTTP 200 で、応答本文が空配列であること。項目表 IT-A06-10-001（商品IDリストが空）も同じ。
- 設計書の現行仕様の節（入出力）は、成功時出力を「最上位のカード一覧の配下をカードIDでキー付けした階層構造。該当が0件のときは空配列を返す」と定める。Excel 由来の部分に0件のときの応答の形の記述は無い。現行（ベース実装の pf-api）も0件のときは空配列（[]）を返す。
- 一方、開発は ECCUBE_HARERUYA-3000（カード名から買取用商品情報を取得、完了）の対応（PR #2965、2026-09-04）で、0件のときの応答を {"cards":{}} にそろえている。テストの注記は「空の場合も C# の Dictionary<int,Card> でデシリアライズできるよう {} (stdClass) を返す」で、買取アプリが読めるようにするための決定とみられる。この整形は商品IDリストからの取得でも使われている。
- 設計書とケースが、この決定に追いついていないとみられる。どちらを正とするかの確認が要る。
  - A. {"cards":{}} を正とする場合（ECCUBE_HARERUYA-3000 の決定どおり）: 設計書の現行仕様の節の「該当が0件のときは空配列を返す」を {"cards":{}} に直し、ケース IT-A06-07-011・IT-A06-10-001 の期待結果も直す。
  - B. 空配列を正とする場合: 新アプリの応答を空配列に変える（買取アプリが空配列を読めるかの確認が要る）。
