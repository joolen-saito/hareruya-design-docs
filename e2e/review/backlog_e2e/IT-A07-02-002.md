# 基本情報【必須】
分類：API_ネット買取管理
機能：ネット買取受注一覧取得（A07-02）ほか、MTGバイヤー向けの API（A06 店頭買取管理・A07 ネット買取管理）
課題カテゴリ：不具合_API_ネット買取管理
課題：【要確認】API_ネット買取管理_MTGバイヤー向けAPI全般_経路が設計書の「/api/admin/…」「/api/buying/…」でなく「/api/v1/…」で公開され、設計書の経路は404になる（設計書が経路にバージョンを入れた決定に追いついていない）
設計書：0507_基本設計仕様書(API_ネット買取管理).xlsx・0506_基本設計仕様書(API_店頭買取管理).xlsx

# 再現手順【必須】
1. 買取アプリ用ログインで認証トークンを取得する
2. 開発環境の API サーバー（https://replace-dev.api.hareruyamtg.com）の GET /api/admin/buyOrders.json（設計書の経路）に、認証トークンのヘッダを付けて送る → HTTP 404
3. 同じ要求を GET /api/v1/admin/buyOrders.json に送る → HTTP 200 で受注の一覧が返る
4. 店頭買取管理の API（例 POST /api/admin/login.json と /api/v1/admin/login.json、POST /api/buying/products と /api/v1/buying/products）でも同じ（設計書の経路は 404、/api/v1 を付けた経路は応答する）

# 期待される挙動【必須】
- 設計書（Excel 由来）のエンドポイントURLは、ネット買取受注一覧取得が「/api/admin/buyOrders.json」、買取アプリ用ログインが「/api/admin/login.json」、商品IDリストから買取用商品情報を取得が「/api/buying/products」で、経路にバージョンが無い。ケース（項目表 IT-A07-02-002 ほか A06・A07 の全ケース）もこの経路で書かれている。
- 一方、新アプリは、MTGバイヤー向けの API の経路の頭を設定値（既定は「api/v1」）で決める作りで、開発環境も /api/v1 で公開している。ECCUBE_HARERUYA-328（まとめて買取商品IDの取得）の PR のレビュー（2026-01-07）で、「MTGBuyer 向けなので、経路にバージョンを入れておくと API と MTGBuyer の変更を別々にできる」として、/api/v1/admin/… にすると決めた記録がある。設計書はこの決定に追いついていないとみられる。
- 確認したいこと:
  - A. /api/v1 を正とする場合: 設計書の A06・A07 のエンドポイントURLを /api/v1/… に直し、ケースの経路も直す。あわせて、MTGバイヤー（買取アプリ）の呼び先を /api/v1/… に変える予定（リリースの順番を含む）があるかを確かめる。
  - B. 現行どおり /api/… を正とする場合: 本番の設定（経路の頭）を「api」にするのか、アプリの経路を変えるのかを決める（現行の買取アプリは /api/admin/… を呼んでいる前提）。

# 現在の挙動【必須】
- 開発環境の API サーバーで、設計書の経路（/api/admin/buyOrders.json）は HTTP 404。/api/v1/admin/buyOrders.json は HTTP 200 で、応答の11項目はケースの期待どおり（IT-A07-02-002 は経路を読み替えたうえで合格）（2026-11-17 開発環境）。
- 店頭買取管理の API（買取アプリ用ログイン・商品IDリストから買取用商品情報を取得）も、E2E は同じく /api/v1 に読み替えて確かめている。

ec-cube-enterprise 経路の頭の設定（既定は api/v1）: `ec-cube-enterprise/app/config/eccube/packages/eccube.yaml:6`、`ec-cube-enterprise/app/config/eccube/packages/eccube.yaml:77`
```yaml
    env(ECCUBE_API_V1_ROUTE): 'api/v1'
    ...
    eccube_api_v1_route: '%env(ECCUBE_API_V1_ROUTE)%'
```

ec-cube-enterprise MTGバイヤー向けの API の経路（例）: `ec-cube-enterprise/src/Eccube/Controller/App/MTGBuyer/V1/Admin/LoginController.php:45`、`ec-cube-enterprise/src/Eccube/Controller/App/MTGBuyer/V1/Admin/BuyingController.php:67`
```php
    #[Route('/%eccube_api_v1_route%/admin/login.json', name: 'api_admin_login', methods: ['POST'])]
    ...
    #[Route('/%eccube_api_v1_route%/buying/products', name: 'api_buying_products', methods: ['POST'])]
```

- ベース実装（pf-api）は、経路にバージョンを持たない（/admin/login.json・/buying/products。API サーバーの /api の下で公開）。

ベース実装 pf-api 経路の定義: `pf-api/config/routes.yaml:1-4`、`pf-api/config/routes.yaml:113-116`
```yaml

    path: /admin/login.json
    controller: App\Controller\Admin\LoginController::postAction
    methods: POST
...

    controller: App\Controller\ProductController::postBuyingProductsAction
```
