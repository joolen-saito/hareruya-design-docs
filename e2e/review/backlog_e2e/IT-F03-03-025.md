# 再現手順【必須】
1. 開発環境（https://replace-dev.hareruyamtg.com:8443）の本店・日本語で、カードID・並び順「価格(高い順)」・ページ番号2を指定した商品一覧（/ja/products/search?cardId=<カードID>&orderby=3&pageno=2）を開く
2. 「詳細検索」を押す
3. 商品名に任意の文字列を入れて「検索」を押す
4. ブラウザのアドレス欄を確認する（並び順の値 3 が含まれる。ページ番号は 1 に戻り、カードIDは含まれない）

# 期待される挙動【必須】
- ケースの期待結果（項目表 IT-F03-03-022、E2E のテストID IT-F03-03-025）は「検索後のURLに遷移元の並び順、ページ番号、カードIDが含まれないこと」。出典は「0303 商品詳細検索 / 現行仕様 業務ロジック 送信」。
- 設計書の送信の節は「並び順・ページ番号・カードIDは引き継がず、詳細検索から検索を実行したときは送らない」と定める。

# 現在の挙動【必須】
- 検索後のアドレスは `/ja/products/search?mode=&pageno=1&disp_number=60&orderby=3&product=<商品名>&colorsType=0&cardtypesType=0&subtype=&format=&illustrator=&stock=0&priceFrom=&priceTo=` となり、遷移元の並び順（3）が残る。カードIDは含まれず、ページ番号は 1 に戻る（この2点は期待どおり）（2026-11-18 開発環境）。
- 検索後の画面でも、並び順は遷移元の「価格（高い順）」が選ばれた表示のまま（キャプチャ）。
- 新アプリの詳細検索モーダルは、表示中の並び順を隠し入力として必ず検索フォームに入れて送る作り。

ec-cube-enterprise 並び順を隠し入力で送る: `ec-cube-enterprise/src/Eccube/Resource/template/default/Block/product_detailed_search_modal.twig:27-31`
```twig
                {% if current_product_list_order_by_id is defined %}
                    <input type="hidden" name="{{ search_form.orderby.vars.full_name }}" value="{{ current_product_list_order_by_id }}"/>
                {% elseif search_form.orderby.vars.value is not empty %}
                    <input type="hidden" name="{{ search_form.orderby.vars.full_name }}" value="{% if search_form.orderby.vars.value.id is defined %}{{ search_form.orderby.vars.value.id }}{% else %}{{ search_form.orderby.vars.value }}{% endif %}"/>
                {% endif %}
```
- ベース実装（現行）の詳細検索フォームは並び順を送らない（隠し入力はカードIDのみ）。
