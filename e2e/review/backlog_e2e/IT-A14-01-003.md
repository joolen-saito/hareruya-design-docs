# 現在の挙動【必須】
- HTTP 200 では返るが、関連情報の項目名が大文字始まり（Cardtypes・Subtypes・Specialtypes・Colors）で、中身は {"id":4} のように ID だけ。name_jp・name_en・product_search_flg が無く、設計書の小文字の項目名は応答に無い（2026-11-25 開発環境。項目表 IT-A14-01-003）。
- card_details は無く、大文字始まりの CardDetails が空の配列で返る。カード詳細の項目も card_images も応答に出ない（項目表 IT-A14-01-009・011）。
- 関連情報が0件のカードでも、小文字の cardtypes 等の空の一覧は返らず、項目名自体が大文字始まり（Cardtypes: []）（項目表 IT-A14-01-010）。
- color_sequence は id と sort_no だけで、設計書の name が無い（項目表 IT-A14-01-014）。
- 原因は、カードの応答を「エンティティの項目を写し、関連はキー（ID）だけに縮める」関数でそのまま作っていること。名前・フラグ・カード詳細の中身は縮められて消える。色順だけは id と sort_no を個別に組み直しているが name を足していない。
- 完了済みの ECCUBE_HARERUYA-3171（色順の並び順 sort_no が応答に現れない）は、同じ原因の一部（色順の sort_no）だけを直した形で、関連情報の名前・カード詳細は直っていない。
