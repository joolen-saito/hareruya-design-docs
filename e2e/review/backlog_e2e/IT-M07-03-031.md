設計書：0206_基本設計仕様書(ネット買取管理機能).xlsx

# 再現手順【必須】
1. フロントのネット買取で、適格請求書発行事業者「いいえ」（非事業者）として買取を申し込む
2. 開発環境（https://replace-dev.admin.hareruyamtg.com:8443）の管理画面に管理者でログインし、その買取の買取情報編集画面を開く
3. 買取依頼者情報の「編集」を押す
4. 電話番号に「09012345678」、口座番号に「1234567」、事業者状況に「事業者」、登録番号に「T1234567890123」を入れる
5. 「確定」を押してから「保存」を押す
6. 画面を開き直し、登録番号を確認する

# 期待される挙動【必須】
- 電話番号（11文字）・口座番号（7文字）・登録番号（14文字）の値が保存される
- 事業者状況が「事業者」のとき、登録番号（"T"+13桁の数字）は必須の入力項目で、入れた値が保存される（設計書 0206 買取情報編集 画面項目定義 識別ID 3-1「事業者情報」・3-2「事業者番号」）

# 現在の挙動【必須】
- 「登録が完了しました。」と出て、電話番号・口座番号は保存され、事業者区分は事業者になるが、登録番号は空のまま（保存後の画面でも登録番号の欄は空で、例の文字だけが出る）（IT-M07-03-028。E2E のテストID IT-M07-03-031。開発環境 2026-11-13 15:09 ごろ実施）
- フロントの申込みで非事業者のときは、買取に適格請求書発行事業者情報（登録番号を持つ情報）を作らない。
- 管理画面の保存では、買取に適格請求書発行事業者情報が無いとき、登録番号のフォームは買取と結び付かないまま入力を受ける。保存の処理は、非事業者で保存するときだけ事業者情報を作って登録番号を空にし、事業者で保存するときは事業者区分を立てるだけで、事業者情報を作らない。そのため入れた登録番号はどこにも保存されない。
- 設計書の記述は現行（pf-eccube3）のふるまいから起こしたもの。この端末に pf-eccube3 のチェックアウトが無く、ベース実装の抜き書きは確認できていない（設計書の出典は pf-eccube3 の PurchaseController.php:264）。
