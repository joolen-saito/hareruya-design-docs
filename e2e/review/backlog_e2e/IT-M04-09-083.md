# 期待される挙動【必須】
- ケースの期待結果（項目表 IT-M04-09-064。E2E のテストID IT-M04-09-083）は「ステータスが入庫完了となり、入庫承認日・承認者（承認者本人）とステータス変更履歴が保存され、振替先在庫数が4から7、仕入総原価が600から900となり、在庫変動履歴が登録され、在庫振替完了画面へ遷移すること」。
- 設計書（在庫移動・振替登録 編集(振替)）の承認の処理は「全ての処理が完了したら、ステータスを入庫完了にし、入庫承認日 / 承認者を登録する」。別添資料（シナリオ⑦ 在庫振替）についても、過去の課題 ECCUBE_HARERUYA-3620 が「承認日、承認者を保存する」を期待として挙げている。
- 画面項目定義の 1-6「承認日」・1-9「承認者」は在庫振替の完了画面に表示される項目。
- したがって、在庫振替の承認では、承認の日時・承認者が入庫承認の項目に保存され、完了画面の承認日・承認者にも表示される。

# 現在の挙動【必須】
- 承認は成功し、完了画面の承認日（2026/11/16 22:19:33）・承認者（承認した本人）は表示される。在庫（振替先 4→7）・仕入総原価（600→900）・在庫変動履歴・ステータス変更履歴も期待どおり（実施は 2026-11-16、開発環境）。
- 不合格は、データベースで読んだ入庫承認日・入庫承認者がどちらも空（null）だったこと。同じ行の出庫承認日（2026-11-16 13:19:33 UTC）・出庫承認者（承認者本人）には値が入っている。
- 原因は、在庫振替の承認の処理が、承認の日時・承認者を「入庫承認」でなく「出庫承認」の項目に保存し、入庫承認の項目は渡さない（空で上書きする）こと。完了画面の承認日・承認者は出庫承認の項目を表示するため、画面の見た目は設計どおりに出る。在庫移動の入庫承認は入庫承認の項目に保存しているので、在庫振替だけが違う。
- 目に見える影響は、入庫承認の項目を読む処理で値が取れない点。例として在庫移動・振替検索一覧の「入庫日時」は、入庫完了の在庫振替でも空になる（別の項目が原因。ECCUBE_HARERUYA-4022）。承認日・承認者を入庫承認の項目に置くか、出庫承認の項目に置いたままにするかは、設計書に項目の置き場所の定めが無く、画面の表示だけで見れば設計どおりなので、実装の誤りと言い切れない。
- なお「ステータスが入庫完了」の不合格（実際は「入庫済み」）は別の論点で、課題「在庫移動・振替登録 編集(移動)(振替)_ステータスが「入庫済み」と表示され…」（E2E の IT-M04-09-038）で扱う。
