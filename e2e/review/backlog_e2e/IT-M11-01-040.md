# 再現手順【必須】

2. 「新規登録」で、編集可能店舗に店舗を1つ以上選んだメンバーを登録する（ほかのデータからは使われていないメンバー）
3. メンバー管理一覧で、登録したメンバーの行の削除アイコン（×）を押す
4. 確認のモーダルで削除を実行する

# 期待される挙動【必須】
- ケースの期待結果（項目表 IT-M11-01-031。E2E のテストID IT-M11-01-040）は、メンバー管理一覧画面が再表示され、外部参照の無い「大阪システム担当-040」が削除済みになり（表示順は削除前の値でなくなる）、ほかのメンバーの表示順と所属・権限・稼働の各マスタが変わらないこと。
- 設計書（0201 メンバー管理一覧 の業務ロジック「削除」）は、削除は対象メンバーを削除済みにし、削除対象より大きい表示順の全行を1つ繰り下げるとする。表示メッセージ M11-01-MSG-010「削除しました」は削除が完了したとき、M11-01-MSG-011「関連するデータがあるため「%name%」を削除できませんでした」は、削除しようとしたメンバーが関連データで使用されているときに出す。
- 編集可能店舗は、このリプレースで追加したメンバーの設定項目（設計書 機能仕様「項目の追加」識別ID 1-9「編集可能店舗」）で、ほかのデータがメンバーを使っている「関連データ」ではない。

# 現在の挙動【必須】
- 削除を実行すると「関連するデータがあるため「大阪システム担当-040-MWO7T5WQ」を削除できませんでした」と出て、メンバーは削除されない（2026-11-20 09:08 開発環境）。
- このメンバーを参照しているのは、本人の編集可能店舗の行（試験支店）だけだった（開発環境の DB を読んで確かめた。ほかの参照は0件）。
- 同じ理由で、項目表 IT-M11-01-001・002・003（E2E 同じ番号）の事前準備も止まった（「削除済みメンバー」を一覧の削除で作れず、「関連するデータがあるため…削除できませんでした」）。
- 新しいアプリの削除は、メンバーの行そのものを消す。メンバーと編集可能店舗のつながりに、削除に合わせて消す指定が無いので、編集可能店舗が1つでもあると、外部キーの制約で削除に失敗し、関連データのメッセージになる。編集可能店舗は必須ではないので、選んでいないメンバーは削除できる。

ec-cube-enterprise 削除は行を消す（編集可能店舗の行は消さない）: `ec-cube-enterprise/src/Eccube/Repository/MemberRepository.php:117-136`
```php
    public function delete($Member): void
    {
        $this->createQueryBuilder('m')
            ->update()
            ->set('m.sort_no', 'm.sort_no - 1')
            ->where('m.sort_no > :sort_no')
            ->setParameter('sort_no', $Member->getSortNo())
            ->getQuery()
            ->execute();

        $em = $this->getEntityManager();

        // ログインしたメンバーの外部参照制約を解除する
        // https://github.com/EC-CUBE/ec-cube/issues/5119
        $Member->setCreator();
        $em->flush();

        $em->remove($Member);
        $em->flush();
    }
```

ec-cube-enterprise メンバーと編集可能店舗のつながり（削除に合わせて消す指定なし）: `ec-cube-enterprise/src/Eccube/Entity/Member.php:182-183`
