# 再現手順【必須】
1. 管理者の表示件数を初期値（300件）のままにしておく
2. 同じ注文番号の語を含む受注を11件（店舗A・注文受領）用意し、その注文番号の語を条件にした検索パターン（保存済み検索条件）を受注一覧で保存する
3. 開発環境（https://replace-dev.admin.hareruyamtg.com:8443）の管理画面で受注管理 > 受注一覧（/admin/order）を開く
4. 開発者ツールで、その検索パターンのリンクのアドレスに「?page_count=10」を付け足して押す（/admin/order/search/pattern/<検索パターンのID>?page_count=10）
5. 検索結果の一覧の件数とページングを確認する

# 期待される挙動【必須】
- 保存済み検索条件の呼び出しでは、リクエストで指定した表示件数（10）を採用しない。
- 表示件数は管理者の表示件数（300件）のままで、11件すべてが1ページ目に表示され、2ページ目は無い。

# 現在の挙動【必須】
- 指定した表示件数10が採用され、1ページ目に10件だけが表示され、2ページ目のリンクが出る（IT-M05-01-063。E2E のテストID IT-M05-01-068。開発環境 2026-11-13）。
- 保存済み検索条件の呼び出し（admin_order_search_pattern）でも、リクエストの表示件数が表示件数マスタの値と一致すれば採用し、セッションの受注検索の表示件数にも保存している（以後のページ送りなども10件で続く）。
- 画面の表示件数の切り替え（プルダウン）は別のルート（admin_order_page）へ表示件数を送っており、検索パターンのリンクは表示件数を付けない。保存済み検索条件の呼び出しで表示件数を無視しても、画面の操作には影響しない。
