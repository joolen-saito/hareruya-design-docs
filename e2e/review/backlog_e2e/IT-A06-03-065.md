# 現在の挙動【必須】
- 項目表 IT-A06-03-038：応答は200で、ステータス・端末取引ID・買取成立日・合計金額・個別入力商品・実在庫は期待どおりだが、履歴は開始時の1件から2件増えて合計3件になる。成立への変更と、未登録在庫ありへの移行の2件が付く（2026-11-25 開発環境）。
- 項目表 IT-A06-03-039：応答は200で、ほかの確認項目は期待どおりだが、履歴が開始時の1件から1件増えて2件になる。更新前と同じ買取成立を送っても、入庫待ちへの移行の1件が付く。
- 原因は、買取成立のとき、更新前と異なる場合の履歴の保存とは別に、「2段階目のステータス更新と履歴保存」（個別入力商品があれば未登録在庫あり、なければ入庫待ち）を必ず行っていること。コードのコメントも「合わせて2件の履歴が必要」としている。設計書は履歴を1件に限っている。

ec-cube-enterprise 店頭買取情報更新の履歴の保存: `ec-cube-enterprise/src/Eccube/Service/App/MTGBuyer/V1/Admin/OtcBuyOrder/UpdateOtcBuyOrderAction.php:81-95`
```php
            // 以降前システムの仕様に合わせて、ステータスが変更された場合のみステータス履歴を保存する
            if ($PrevStatus !== $OtcBuyOrderStatus) {
                $this->otcBuyOrderStatusHistoryEntityManager->save($input->OtcBuyOrder, $OtcBuyOrderStatus, $input->Member, $currentTime);
            }
            // 買取成立の場合は2段階目のステータス更新と履歴保存を行う
            // (合わせて2件の履歴が必要のため、上記と分けて更新を行なっている)
            if ($OtcBuyOrderStatus->isComplete()) {
                $PostCompleteStatus = $this->entityManager->find(
                    MtbOtcBuyOrderStatus::class,
                    $input->OtcBuyOrder->resolvePostCompleteStatusId(),
                );
                $this->otcBuyOrderEntityManager->updateStatusWithHistory($input->OtcBuyOrder, $PostCompleteStatus, $input->Member, $currentTime);
            }
```

- ベース実装（pf-api）は、更新前と異なるときだけ履歴を1件登録し、2段階目の更新・履歴は無い。
