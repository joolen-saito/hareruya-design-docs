# 期待される挙動【必須】
- ケースの期待結果（項目表 IT-M04-13-092。E2E のテストID IT-M04-13-102）は、「結合元2商品の欠品点数と欠品登録者が保存されず、欠品の在庫変動履歴が両商品とも0件のままであること」。
- 設計書（Excel 由来）は、承認申請するボタン押下時に「仮登録された欠品情報に元づいて対象の商品の欠品登録を行う」とし、結合元商品の保存項目を「欠品点数＝入力値（仮登録された値）」「欠品登録者＝承認申請するボタン押下時のユーザー」と定める。欠品点数の入力は1～1000000で、0は欠品の値として扱わない。結合承認の画面は「欠品点数が入力された商品から表示する」。
- ただし、仮登録が無い結合元の明細に何を保存するか（空か0か）は書いていない。
- 確認したいこと: 欠品を登録しなかった結合元の明細の欠品点数をどうするか。
  - A. 空のままにする（ケースの期待どおり）: 新アプリの承認申請で、欠品の無い明細には欠品点数を書かないようにする。
  - B. 0 を正とする: 画面・CSV・在庫の結果は空と同じなので、ケースの期待結果を「欠品点数が0、欠品登録者が空、欠品の在庫変動履歴が0件」に直す。

# 現在の挙動【必須】
- 結合元2商品とも、欠品点数は0、欠品登録者は空、欠品の在庫変動履歴は0件（2026-11-17 開発環境）。ケースの判定項目のうち合わないのは欠品点数（期待は空、実際は0）だけ。
- 結合承認の画面の結合元商品一覧は、2商品とも欠品点数「0」・欠品登録者「—」と表示される（キャプチャ）。
- 新アプリは、承認申請のときに全部の結合元の明細へ欠品点数を書き、欠品の仮登録が無い明細は0にする。欠品点数を読む側（結合承認の画面・承認・却下・欠品CSV出力・在庫の集計）は、どれも空を0として扱うので、0と空で画面・CSV・在庫の結果は変わらない。
