# 基本情報【必須】
分類：API_デッキビルダー
機能：デッキ情報参照（A15-12）
課題カテゴリ：不具合_API_デッキビルダー
課題：【実装乖離】API_デッキビルダー_デッキ情報参照_採用カードの要素に不明カード可否の項目（is_unknown）が付かない（通常のカードでは0が付くはずが、不明カードの行にしか付かない）
設計書：0515_基本設計仕様書(API_デッキビルダー).html（A15-12 デッキ情報参照・出力項目「採用カード」）
要件元：現行踏襲（現行の deck-api は、すべての採用カードの要素に is_unknown を付ける）

# 再現手順【必須】
1. 開発環境に、プレイヤーが所有する公開デッキを用意し、採用カードとして通常のカードを2枚入れる（管理画面のデッキ新規登録）
2. 開発環境の API（https://replace-dev.api.hareruyamtg.com）の GET /api/deck/{デッキID} に、認証なしで要求を送る
3. 応答の採用カード（cards）の各要素の項目を確認する（項目表 IT-A15-12-030・IT-A15-12-038・IT-A15-12-039）

# 期待される挙動【必須】
- 採用カードの各要素に「不明カード可否」の項目が含まれる（項目表 IT-A15-12-030。設計書の採用カードの出力項目に「ステッカー可否・アトラクション可否・不明カード可否」）。
- 通常のカードの不明カード可否は「不可」を表す値（項目表 IT-A15-12-039。現行は 0）。
- 項目表 IT-A15-12-038 は、不明カード可否が「可」の登録済みカードで「可」を表す値が返ることを求めているが、現行の仕組みでも通常のカードの値は常に0で、不明カード（カードの番号が無い行）だけが1になる。この期待結果の前提（カードごとの可否の登録）は、現行・新しいアプリのどちらにも無い（正本の側の確認が要る）。

# 現在の挙動【必須】
- 採用カードの要素は、ステッカー可否（is_sticker）・アトラクション可否（is_attraction）は期待どおりに付くが、不明カード可否（is_unknown）の項目が無い（2026-11-24 開発環境。IT-A15-12-030 の応答で確認）。
- 原因: 新しいアプリは、通常のカードの要素に is_unknown を付けず、カードの番号が無い行（不明カード）にだけ is_unknown を1で付ける。現行は、通常のカードの要素にも is_unknown を0で付ける。

ec-cube-enterprise 通常のカードの要素: `ec-cube-enterprise/src/Eccube/Service/DeckService.php:600-611`
```php
            $result[$cardId] = [
                'id' => $cardId,
                'name_jp' => $row['name_jp'],
                ...
                'is_sticker' => (int) $row['is_sticker'],
                'is_attraction' => (int) $row['is_attraction'],
            ];
```
ec-cube-enterprise 不明カードの行だけ is_unknown が付く: `ec-cube-enterprise/src/Eccube/Controller/App/DeckBuilder/DeckController.php:1043-1058`
```php
        foreach ($unknownRows as $row) {
            $cards[] = [
                'id' => null,
                ...
                'is_unknown' => 1,
```
ベース実装（deck-api） 通常のカードの要素にも is_unknown を0で付ける: `deck-api/src/Repository/DtbDeckRepository.php:323-326`
```sql
            dc.count AS count,
            dc.board_id AS board_id,
            0 AS is_unknown
```
