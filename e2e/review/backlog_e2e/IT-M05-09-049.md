# 現在の挙動【必須】
- 納品書の窓は開くが、中身は空で、注文番号も商品の行も1つも出ない。送り主の会員番号の行も無い（2026-11-24 開発環境。項目表 IT-M05-09-043・054）。
- ゲスト受注は会員とプレイヤーの紐付けを外して作った（E2E が作った行だけ）。アプリは会員なしの受注を必ず除外するので、この補いが原因ではない。
- 原因は、納品書の対象にする受注を選ぶ検索が、受注に会員とプレイヤーの両方があるものだけを内部結合で絞っていること。ゲスト受注は結合で落ち、納品書に載らない。
- 設計書の中に食い違いがある。同じ 0203 の現行仕様の節（業務ロジック「納品書に出る受注と明細」）は、納品書に出る受注の条件の先頭を「会員情報とプレイヤー情報を持つ」としており、アプリの動きはこちらと一致する。2026-10-16 の決まり（Excel 由来＞現行仕様の節）に従い、Excel 由来の識別ID 16 を正として実装差異で起票する。

ec-cube-enterprise 納品書の対象の受注の絞り込み: `ec-cube-enterprise/src/Eccube/Repository/DtbShippingStandbyRepository.php:246-248`
```php
            // 会員情報とプレイヤー情報の両方を持つ受注だけを納品書対象とする
            ->join('o.Customer', 'cus')
            ->join('cus.Player', 'player');
```

- ベース実装（pf-eccube3）も会員とプレイヤーを内部結合しており、ゲスト受注は納品書に出ない（現行どおり）。

ベース実装 pf-eccube3 納品書の対象の受注の絞り込み: `pf-eccube3/app/Plugin/HareruyaEc/Repository/DtbShippingStandbyRepository.php:273-274`
