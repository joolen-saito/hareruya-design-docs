# 期待される挙動【必須】
- ケースの期待結果（項目表 IT-M04-03-002。E2E のテストID IT-M04-03-002）は、「在庫一覧画面へ遷移すること」。出典は「0202 在庫一括編集 / 表示メッセージ『商品が選択されていません。』」で、手順2は商品を選ばずに「在庫一括編集」ボタンを押すこと。
- 設計書の表示メッセージ（在庫一括編集）は、画面上部に「商品が選択されていません。」を出す条件を「商品を選択せずに在庫一括編集を開いたとき」、後続処理を「在庫一覧画面に遷移する」と定める。
- 一方、設計書の画面項目定義（Excel 由来。在庫検索一覧の識別ID 4-4「在庫一括編集」ボタン）は、「商品を選択した場合に活性状態とする」と定める。商品を選ばないとボタンが押せない。
- 設計書の中で、「商品を選ばずに開く」ことを前提にしたメッセージと、「商品を選ばないと開けない」ボタンの定義が両立しない。設計書の優先順位（Excel 由来＞表示メッセージ節）では、ボタンの定義が正となり、メッセージは画面の操作からは到達できない。
- どちらを正とするかの確認が要る。
  - A. ボタンの定義（商品を選ばないと非活性）を正とする場合: 設計書の表示メッセージから「商品が選択されていません。」の行を外し、ケース IT-M04-03-002 を対象外にする。
  - B. 現行（ベース実装）どおり、商品を選ばなくても押せて、押すとメッセージを出して在庫一覧へ戻す作りを正とする場合: 画面項目定義 4-4 の活性条件を直し、アプリを変える。

# 現在の挙動【必須】
- 在庫一覧で行のチェックを入れない状態では、「在庫一括編集」ボタンは非活性（薄い色）で、押せない。画面項目定義 4-4 のとおり。移動・振替・分割・結合の各登録ボタンも同じく非活性（キャプチャ）。手順2の「商品を選択せずにボタンを押す」は画面で実行できず、メッセージにも在庫一覧への遷移にも至らない（E2E は、ボタンが押せるかの確かめで不合格。実施は 2026-11-14、開発環境）。
- 新しいアプリには、この文言「商品が選択されていません。」そのものが無い。画面のボタンを通らず、アドレスを直接開いて在庫の指定が無い場合は、別の文言「指定された在庫が見つかりませんでした。」を出し、同じアドレスへリダイレクトする（リダイレクトが繰り返される。別の課題 ECCUBE_HARERUYA-3905）。設計書のメッセージ「商品が選択されていません。」と「在庫一覧画面に遷移する」とは違う。
- ベース実装（現行の在庫一括編集）は、ボタンが常に押せ、商品を選ばずに押すとメッセージ「商品が選択されていません。」を出して商品一覧へ戻す。設計書の表示メッセージは、この現行の挙動を写したもので、リニューアルで変えた画面項目定義 4-4 の活性条件に合わせて見直されていない。
