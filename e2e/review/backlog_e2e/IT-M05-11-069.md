# 再現手順【必須】
1. 問い合わせが「初期問い合わせ」の受注を用意する
2. 開発環境（https://replace-dev.admin.hareruyamtg.com:8443）の管理画面で、その受注の受注情報編集画面（/admin/order/<受注ID>/edit）を開く

# 期待される挙動【必須】
- 設計書の画面項目定義 10-23「問い合わせ」の最大は3000文字。99999文字は設計書の最大を超えるため、保存できないのが設計どおり
- ケース（99999文字が保存される期待）は、同じ項目を最大の3000文字で保存する別のケース（IT-M05-11-118）と食い違う。ケースの文字数を設計書に合わせて直す

# 現在の挙動【必須】
- 「長すぎます。この値は3000文字以下で入力してください。」と出て保存できない。これは設計書の最大（3000文字）どおりの動き。
- 新アプリの問い合わせの上限は長文の設定値3000で、ベース実装も同じ3000文字。

ec-cube-enterprise 問い合わせの上限: `ec-cube-enterprise/src/Eccube/Form/Type/Admin/OrderType.php:228-233`
```php

            ])
```

ec-cube-enterprise 上限の設定値: `ec-cube-enterprise/app/config/eccube/packages/eccube.yaml:121`
```yaml

```
