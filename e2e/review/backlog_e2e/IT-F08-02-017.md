# 期待される挙動【必須】
- ケースの期待結果は次の2つ。
  - 項目表 IT-F08-02-016（E2E のテストID IT-F08-02-017）: 存在しない店舗識別名のエントリー画面・申込フォーム・会員登録フォームの各要求が HTTP 404 になること。
  - 項目表 IT-F08-02-018（E2E のテストID IT-F08-02-019）: エントリーを開始せずに会員登録フォームのURLを直接開くと、店頭買取査定申込前ログイン画面へ遷移すること。
- 設計書の現行仕様の節は、エントリー・申込フォーム・会員登録フォームのいずれも店舗が特定できないときは 404 とし、会員登録フォームは「エントリー開始済みかつ申込フォームが送信済み」のときだけ進め、満たさないときはエントリーへ戻すと定める（Excel 由来の部分には、この画面の進み方の定めは無い）。
- 現行（ベース実装の pf-eccube3）は、会員登録フォームの経路をメソッドで限らず、GET でも店舗の確認と進行条件の確認を行い、店舗が無ければ 404、条件を満たさなければエントリーへ戻す。

# 現在の挙動【必須】
- 会員登録フォームの経路は POST だけを受ける作りで、GET で開くと店舗の確認や進行条件の確認の前に HTTP 405（「No route found for "GET …/register_customer": Method Not Allowed (Allow: POST)」）になる（2026-11-17 開発環境）。
- そのため、存在しない店舗識別名でも会員登録フォームは 404 でなく 405 になる。エントリー画面と申込フォームは期待どおり 404。
- エントリー未開始で会員登録フォームを GET で開いても、エントリーへ戻らず上記の 405 の画面になる。
- 同じ会員登録フォームの経路に POST で送ったときの進行条件の確認は、別の課題（項目表 IT-F08-02-049）に分けている。
