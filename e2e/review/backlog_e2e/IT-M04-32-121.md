# 再現手順【必須】
1. 開発環境（https://replace-dev.hareruyamtg.com:8443）の管理画面に、承認者としてログインする（申請者とは別のメンバー。2人とも同じ支店を編集できる）
2. 在庫管理＞在庫編集承認一覧で、店舗に支店、登録者に申請者を指定し、「承認可能な在庫のみ表示」のチェックを外して「検索」を押す。検索結果に、申請者が登録した在庫編集（入庫/問屋仕入・在庫増減数 3・仕入単価 300）の行が、承認状態「スマレジ連携失敗」で出る
3. 検索結果のその行の左端のチェックボックスを見る
4. 承認対象「在庫編集」のリンクを押して確認モーダルを開き、「承認する」「却下する」を見る

（試験データについて：承認状態「スマレジ連携失敗」の承認は画面から作れない。E2E は、E2E が作った承認の行にだけデータベースで承認状態を「スマレジ連携失敗」に変えて前提にした。一覧の承認状態の表示は「スマレジ連携失敗」になり、足し方は合っている。スマレジ連携失敗の行の表示と明細CSVの出力（IT-M04-32-145・146）は期待どおりだった。）

# 期待される挙動【必須】
- 設計書の在庫編集承認一覧(検索結果)の画面項目定義 識別ID 2-1「チェックボックス」は、表示条件を「承認状態が「未承認」、「スマレジ連携失敗」」「承認対象が「在庫編集」「在庫一括編集」「在庫変更CSV登録」」「登録者がログインしているユーザー以外の場合のみ」と定める。承認状態「スマレジ連携失敗」の行（登録者が承認者と別）には、チェックボックスが表示され、一括承認・一括却下の対象にできる。
- 識別ID 7-2「承認する」ボタンは、「承認対象押下時に承認状態が「未承認」「スマレジ連携失敗」の場合」「登録者がログインしているユーザー以外の場合」に表示し、押して確認画面で OK を押すと承認処理を実行する、と定める。承認状態「スマレジ連携失敗」の行の確認モーダルに「承認する」が表示される（ケースの期待結果は「承認する」だけ表示され、「却下する」は出ない）。
- 以上は Excel 由来の画面項目定義の記述で、スマレジ連携に失敗した申請を、承認者がもう一度承認して連携をやり直せることを求めている。

# 現在の挙動【必須】
- 検索結果の承認状態は「スマレジ連携失敗」と出るが、その行にチェックボックスが出ない（承認済の行と同じ）。承認対象「在庫編集」を押した確認モーダルには、明細と CSVダウンロードだけが出て「承認する」「却下する」とも出ない（実施は 2026-11-26、開発環境）。承認者が、スマレジ連携に失敗した申請を一括承認でも個別の確認モーダルからも再承認できない。同じ行から再承認する入口が、このアプリのほかの画面にも見当たらない。
- 原因は、チェックボックスと確認モーダルの操作可否を決める判定が、承認状態が「未承認」の行だけを対象にしていて、「スマレジ連携失敗」の行を含めていないこと。確認モーダルは、この判定が偽の行を「参照専用」として開き、「承認する」「却下する」を隠す。一覧の表示とモーダル内の明細の計算は、承認状態「スマレジ連携失敗」を「未承認」と同じ扱いにしている（登録者が別のメンバーである条件はどちらも満たしている）。
- IT-M04-32-128（項目表 IT-M04-32-022。承認状態が「スマレジ連携失敗」の在庫編集と在庫変更CSV登録の2行を選んで一括承認の確認モーダルを開く）も、手順3の行にチェックボックスが無いところで止まり、期待結果を確かめられなかった。同じ原因なので、この課題にまとめる。
- シードの補いは、承認状態を画面でなくデータベースで「スマレジ連携失敗」にしたことだけ。承認状態の表示と登録者が別のメンバーである条件は期待どおりで、結果に影響しない。
