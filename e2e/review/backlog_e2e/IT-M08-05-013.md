# 期待される挙動【必須】
- ケースの期待結果（項目表 IT-M08-05-013）は「ページが見つからない扱い（404）になること」。
- 設計書の現行仕様（M08-05 ポイント付与）は、ポイントの付与について「会員または選手情報が存在しないときは、ページが見つからない扱い（404）とする」と定め、エラー時の扱いの表にも「会員・選手情報が存在しない」は「ページが見つからない扱い（404）とする」、入出力の失敗時出力にも「会員・選手情報が無いときは404」と書く。
- この定めの出どころはベース実装で、ベース実装は付与の保存（POST）で、会員または選手情報が無ければ404を返す。Excel 由来の部分にはこの場合の定めは無く、現行仕様の節が唯一の定めなので、これを期待値にする。
- 補足: 設計書の「ポイント履歴の表示」の節は「会員が存在しないときは404」としか書かない。選手情報が無い会員の画面表示（GET）にも404を求めるのはケースの読み方で、ベース実装も表示（GET）側に選手情報の確認は持たない（表示側のテンプレートが選手情報の会員IDを使うため、404でなくエラーになると読めるが、ベース実装は動かして確かめていない）。保存（POST）側の404は設計書どおりに必要。

# 現在の挙動【必須】
- 手順3でポイント付与（キャンペーン、特別対応）画面（/admin/customer/point/{会員ID}/granted）を開くと、404でなく「システムエラーが発生しました。大変お手数ですが、サイト管理者までご連絡ください。」の画面（応答500）になる（実施は 2026-11-15、開発環境）。
- 新しいアプリのコントローラーは、会員の存在だけを引数の取得で確かめ、選手情報の有無を確かめない。表示のテンプレートは選手情報のポイント残高をそのまま参照し、保存の処理も入力チェックと保存のどちらでも選手情報の有無を確かめずに使うので、選手情報が無いと404にならずエラーで落ちる。画面表示の500は、開発環境のデバッグモード（テンプレートの変数参照が厳密）で選手情報が空のため残高を参照できないことが原因と読める（開発環境のログは未確認）。
- 保存（POST）側も、コードの上では、選手情報が無いと入力チェックの中で選手情報のポイント残高を参照して落ちると読める（ベース実装は404を返す。POST は今回のケースの対象外で動かしていない）。
