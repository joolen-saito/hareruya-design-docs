# 再現手順【必須】
1. 数量2の商品を含む受注を用意する（受注明細の商品名は「受注時名称」、商品マスタの商品名は別の「変更後名称」にしておく）
2. 開発環境（https://replace-dev.admin.hareruyamtg.com:8443）の管理画面で、その受注の受注情報編集画面（/admin/order/<受注ID>/edit）を開く。受注の商品明細のIDを控える

4. 登録後の受注の商品明細のIDと商品名を確認する

# 期待される挙動【必須】
- 受注全体の更新では、配送先が持つ配送商品をすべて削除してから更新後の明細をもとに作り直す。数量を変えただけでも作り直す。作り直す配送商品の商品名は商品の名称（変更後名称）を写し、明細に記録した受注時の商品名とは違う値になることがある。受注の商品明細のIDは更新前と異なる値になる（設計書 業務ロジック「配送商品の作り直し」）
- なお新アプリは配送商品を受注明細と別に持たない作りで、「作り直す」が何を指すか（明細のIDを変えるか、商品名を商品マスタの名称へ更新するか）を設計書で確定する必要がある

# 現在の挙動【必須】
- 数量を変えて登録しても、受注の商品明細のIDは更新前と同じまま（2明細とも同じID）で、作り直されない。
- 商品名は、変更後名称ではなく受注時名称のまま（登録後の画面にも受注時名称が出る）。
- 新アプリには配送商品の独立したエンティティが無く、受注明細そのものをフォームの値で更新する。商品名は明細が新規のときだけ商品から写し、既存の明細では触らない。画面から外した明細だけを削除する。
