# 再現手順【必須】
1. 開発環境（https://replace-dev.hareruyamtg.com:8443）で、日本語版の商品規格NM（税込550円）とSP（税込440円）を持つグッズ商品を、グッズ商品CSV登録で作る（項目表 IT-F10-03-017 のシード S-F10-03-DET-SWSPECN-019 の作り方）
2. 未ログインで、その商品の商品詳細画面を、言語・商品規格の指定なしで開く
3. 価格の表の見出しと行を確認し、商品規格をNMからSPへ切り替える操作を探す

# 期待される挙動【必須】
- ケースの手順2「画面上で商品規格をNMからSPへ切り替える」を行え、そのあとの手順3で受け渡し領域に商品詳細の値（項目名 `gtm_product_value`）を持つ要素が1件であること（項目表 IT-F10-03-017。同じ作りの IT-F10-03-018 は、切替後の値が500であること）。
- 設計書（0310 F10-03）は、商品規格を切り替えても積み直さず、値は画面を開いた時点の商品規格のものと定める。

# 現在の挙動【必須】
- 商品詳細画面の価格の表は、規格ごとの行（税込550円・440円）が並ぶだけで、状態の欄と切替のリンクが出ない。手順2が実行できず、期待結果の確かめまで進めない（E2E のテストID IT-F10-03-019・020。2026-11-23 開発環境）。
- 新アプリの商品詳細は、状態の欄（切替のリンク）をカード商品にだけ出す。グッズ商品（シードの作り方はグッズ商品CSV）には出ない。ケースの「商品規格NM・SP」はカードの状態を指しているため、シードを作る側（グッズ商品CSV）と手順の組み合わせが成り立たない。
- 確認したいこと: IT-F10-03-017・018 のシードを、カード商品CSVで状態NM・SPを持つ商品として作り直してよいか。
- 参考: 新アプリの商品詳細では、値を積む読み込み自体がコメントアウトされている（項目表 IT-F10-03-001 の課題と同じ原因。商品詳細の値のケースは、シードを直したあとで落ちる見込み）。
