# 期待される挙動【必須】
- ケースの期待結果は、「白/R」が色/Rの欄に表示され、商品名の欄からは当該表記が除かれること（例: 末尾なら商品名「末尾カード」）。
- 設計書は、画面項目の「色/R」を「色名とレアリティコード」、「商品名」を「受注詳細の商品名に含まれる略称・言語・状態・色・レアリティを取り除く」とだけ定め、業務ロジックの「商品名の整形」でも、色とレアリティの取り出し方を表記の現れる位置（末尾・開き括弧の直前・途中・角括弧の直前）ごとに「一致した部分をそのまま取り出す」などと定めている。商品名の中の色とレアリティの表記の形（間にスラッシュを入れるか）は設計書のどこにも書かれていない。
- 結合試験の試験データの商品名は、実際の商品名の形である「白R」（色1字＋レアリティ1字。例「《…/…》 白R」）に直し、色/Rの欄の期待値も「白R」にそろえる（スラッシュ入りの「白/R」はアプリが出力しない値）。

# 現在の挙動【必須】
- 4件とも、色/Rの欄は空になり、商品名の欄は元の商品名のまま表示された（E2E 2026-11-14 の開発環境）。
  - 末尾カード 白/R → 色/R: 空、商品名: 「末尾カード 白/R」（期待は色/R「白/R」・商品名「末尾カード」）
  - 括弧カード 白/R(限定) → 色/R: 空、商品名: 「括弧カード 白/R(限定)」
  - 前半 白/R 後半 → 色/R: 空、商品名: 「前半 白/R 後半」
  - 角括弧カード 白/R[注記] → 色/R: 空、商品名: 「角括弧カード 白/R」（角括弧の中は、商品名に略称タグが無いため設計書どおり取り除かれた）
- アプリの取り出し処理は、色の1字（無・白・青・黒・赤・緑・金・茶・分・混・土地。末尾だけ「か」も）に、レアリティの1字（M・R・U・C・L・S・T）が任意で続く形だけを取り出す。間にスラッシュが入る「白/R」は、どの位置のパターンにも当たらない。
- 同じ画面でカードを選んで商品名を自動で組み立てると、「《…/…》 白R」のようにスラッシュなしの形に書き換わる（E2E のシード作成時に確認。同じ書き換えが4件とも起きたため、試験データの商品名は入力し直した）。ベース実装の商品の表示名も「【JPN】《ベナリア史/History of Benalia》[DOM] 白R」の形（スラッシュはカードの日本語名と英語名の間だけ）。
- 結論: アプリは設計書・ベース実装どおりに動いており、ケースの試験データの表記「白/R」が実際の商品名の形と合っていない（期待結果の色/Rの欄「白/R」も、アプリが出さない値）。
- 補足（直すときに併せて確認する点）: 角括弧の直前のパターンは、色の直後に角括弧が続く形（レアリティなし。例「白[…]」）だけが対象で、レアリティが付く「白R[注記]」は当たらない。また商品名に略称タグが含まれないと、その前の処理で角括弧の部分がすべて取り除かれる。4件目は表記を「白R」に直しても、期待結果の「角括弧を残した『角括弧カード [注記]』」はアプリでは得られない見込み。
