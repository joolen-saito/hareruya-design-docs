# 再現手順【必須】
1. 開発環境（https://replace-dev.hareruyamtg.com:8443）の管理画面に、在庫編集の権限を持つ管理者（M04-02担当者）でログインする
2. 試験支店の在庫（在庫数10・総原価10,000。E2E では実行ごとの印を付けた商品・在庫）の在庫編集画面を開く
3. 在庫変動区分に「入庫/問屋仕入」、在庫変動理由に半角英字「a」を65535回連結した文字列、在庫増減数に1、仕入単価に0、承認通知先メンバーに承認権限のあるメンバーを入力する（項目表 IT-M04-02-014。手順3）
4. 「登録する」を押す（手順4）

# 期待される挙動【必須】
- ケースの期待結果（項目表 IT-M04-02-014。E2E のテストID IT-M04-02-018）は、「在庫変動理由に半角英字aが65535文字保存された入庫承認待ち在庫情報が1件登録されること」。ケースの出典は「画面部品一覧 識別ID 3-2（最大文字数原データ: 65535byte）」で、換算前のバイト数（65535）をそのまま文字数に使っている。
- 設計書（Excel 由来）の在庫編集 画面部品一覧 識別ID 3-2 在庫変動理由は、最大値「16383文字」、説明「入力上限数は現行踏襲（65535byte→16383文字に変換）」と定める。上限は16383文字で、65535文字は上限を超える。
- 同じ項目表の16383文字ちょうどの確認（E2E のテストID IT-M04-02-054）は、設計書どおり登録でき合格している。設計書に従えば、65535文字は「16383文字以下」のエラーで登録されないのが正しく、ケース IT-M04-02-014 の期待結果が設計書と合っていない。
- どちらを正とするかの確認が要る。
  - A. 設計書どおり16383文字を上限とする場合: ケース IT-M04-02-014 の期待結果を「16384文字以上は登録されず、16383文字以下でエラーが出ること」の形に直す（アプリはそのまま）。
  - B. 65535文字まで保存できるようにする場合: 設計書の最大値を直し、アプリの上限を変える（TEXT 列に4バイト文字を入れる前提の換算を見直す）。

# 現在の挙動【必須】
- 在庫変動理由に半角英字「a」を65535文字入れて「登録する」を押すと、在庫変動理由の欄に「長すぎます。この値は16383文字以下で入力してください。」と出て、画面上部に「保存に失敗しました」が出る。入庫承認待ち在庫情報は登録されない（0件。E2E は、期待結果の「入庫承認待ち在庫情報が1件登録される」の確かめで不合格。実施は 2026-11-14、開発環境）。
- 新しいアプリは、在庫変動理由の最大文字数を文字数の設定値（16383。設定のコメントは「4バイト文字で65535byte以内」）で検査する。設計書の上限と同じ。
- ベース実装（現行）には在庫編集（承認通知つき）の画面が無い（新規の機能。pf-eccube3 の app で「承認通知先」「stock_approval」「StockApproval」を探したが該当なし）。
