# 再現手順【必須】
1. 開発環境（https://replace-dev.hareruyamtg.com:8443）で、必須項目に有効値のある複製元のイベントを用意し、そのイベントを編集できる管理者でログインする
2. 複製元のイベントの複製新規画面（/admin/event/<イベントID>/copy）を開く
3. イベント名(日)を別の名前（例：遷移確認イベント）に変えて「登録」ボタンを押す
4. 登録後に表示される画面を確認する（イベント一覧ではなく、登録した新しいイベントの編集画面 /admin/event/<新しいイベントID>/edit が表示される）

# 期待される挙動【必須】
- ケースの期待結果（項目表 IT-M13-05-028。E2E のテストID IT-M13-05-036）は「イベント一覧画面へ遷移すること」。出典は「0214 複製新規 / レイアウト図 遷移一覧（登録→イベント一覧）、現行仕様 保存・入出力（登録したイベントの編集画面）」で、ケース自身が食い違う2つの記述を並べて出典にしている。
- 設計書の Excel 由来の部分は、遷移先を「イベント一覧」とする。画面遷移図の遷移一覧に「登録 → イベント一覧」（コネクタ20）があり、画面項目定義の 3-3「登録」ボタンは「フォームに入力された値でイベント登録」、3-2「イベント一覧」ボタンは「イベント一覧（検索結果）へ戻る」と書く（登録後の画面は画面遷移図だけが示す）。
- 一方、同じ設計書の現行仕様の節（業務ロジックの「保存」、入出力の「成功時出力」）は、「保存に成功したときは、登録したイベントの編集画面へ遷移する」「成功メッセージを表示し、登録したイベントの編集画面へ遷移する」と定める。同じ設計書の中で、登録後の遷移先が「イベント一覧」か「登録したイベントの編集画面」かが食い違う。
- 設計書の中の優先順位（Excel 由来＞表示メッセージの節＞現行仕様の節。2026-10-16 決定）では Excel 由来の「イベント一覧」が正となり、新アプリは現行仕様の節のとおりに作られている。どちらを正とするかの確認が要る。
  - A. Excel 由来の部分（イベント一覧）を正とする場合: 複製新規の登録成功後の遷移先をイベント一覧に変える（ケースの期待結果はそのまま）。
  - B. 現行仕様の節（登録したイベントの編集画面）を正とする場合: 画面遷移図の「登録 → イベント一覧」を編集画面へ直し、ケースの期待結果と出典も直す。
- 同じ型の既存の課題（未対応）: ECCUBE_HARERUYA-3917（イベント編集の更新後の遷移先）・ECCUBE_HARERUYA-3922（日程登録の更新後の遷移先）・ECCUBE_HARERUYA-3964（イベント新規申込登録の登録後の遷移先）。いずれも別の機能で、複製新規の登録後の遷移先を扱う課題は無い。

# 現在の挙動【必須】
- 複製新規画面で「登録」を押すと、新しいイベントが登録され、イベント一覧ではなく登録した新しいイベントの編集画面（/admin/event/<新しいイベントID>/edit）が表示される（2026-11-18 開発環境。新しいイベントID 100008852）。
- 新アプリの複製新規画面のフォームは、新規登録と同じ送り先（イベント新規登録の処理）へ送られ、成功すると成功メッセージを出して、登録したイベントの編集画面へリダイレクトする。

ec-cube-enterprise 複製新規画面（isNew のとき）のフォームの送り先は新規登録の処理: `ec-cube-enterprise/src/Eccube/Resource/template/admin/Event/edit.twig:57-60`
```twig
    <form name="event_form" role="form" id="event_form" method="post" action="{% if not (isNew|default(false)) -%}
                {{ url('admin_event_edit', {id: Event.id}) }}
    {%- else -%}
                {{ url('admin_event_create') }}
```

ec-cube-enterprise 登録に成功すると登録したイベントの編集画面へ遷移する: `ec-cube-enterprise/src/Eccube/Controller/Admin/Event/EventController.php:262-265`
```php
                $this->addSuccess('admin.common.save_complete', 'admin');

                return $this->redirectToRoute('admin_event_edit', ['id' => $form->getData()->getId()]);
```

- ベース実装（現行）も、登録に成功すると登録したイベントの編集画面へ遷移する（実装は設計書の現行仕様の節と同じ）。

ベース実装 pf-eccube3 登録後の遷移: `pf-eccube3/app/Plugin/HareruyaEc/Controller/Admin/EventController.php:144-147`
```php
        // 完了メッセージ表示

        return $app->redirect($app->url('admin_event_edit', array('id'=> $event->getEventId())));
```
