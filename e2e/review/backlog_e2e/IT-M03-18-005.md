# 再現手順【必須】
1. 開発環境（https://replace-dev.hareruyamtg.com:8443）の管理画面で、商品管理＞部門登録/編集を開き、既存の部門（ケースでは部門名「編集前部門-005」・部門コード64）の編集モードを開く（一覧のIDまたは部門名を押す）
2. 画面上部のボタンを確認し、「新規登録はこちら」ボタンを探して押す（項目表 IT-M03-18-005）

# 期待される挙動【必須】
- 設計書の Excel 由来の画面項目定義 識別ID 15「新規登録はこちらボタン」は「クリックすると新規登録モードになる」と定め、レイアウト図の編集モードの画面も、上部に「新規登録はこちら」「CSV出力」「CSV入力」のボタンを並べている。
- ケースの期待結果（項目表 IT-M03-18-005）は、手順2「新規登録はこちらボタンを押す」のあと「新規登録モードの部門登録フォームが表示されること」。
- 設計書の現行仕様の節は同じ導線を「編集モードのときだけ、新規登録へ戻る導線を表示する。」と書くが、ボタンの名称は決めておらず、名称は Excel 由来の画面項目定義とレイアウト図の「新規登録はこちら」が定める（設計書の中の優先順位は Excel由来＞現行仕様の節）。二つは食い違っておらず、画面の名称を「新規登録はこちら」にする。

# 現在の挙動【必須】
- 編集モードの画面の上部には、「新規登録へ戻る」「CSV出力」「CSV入力」のボタンが並ぶ。「新規登録はこちら」という名前のボタンは無く、押せない。名前の違う「新規登録へ戻る」はあるが、ケースの手順は「新規登録はこちらボタンを押す」なので、E2E は代わりに押していない。
- 「新規登録へ戻る」は部門登録/編集画面（編集対象を指定しない画面）へのリンクで、押せば新規登録モードに移ると見込まれる（ソースの読み。今回は押していない）。違いはボタンの名称だけ。
- 原因は、編集モードで出すボタンの文言に、文言表の「新規登録へ戻る」を使っていること。ベース実装（pf-eccube3）は、同じ位置のボタンに「新規登録」に「はこちら」を続けた文言を出す。

ec-cube-enterprise 編集モードのときだけ出る新規登録のボタン（文言表の「新規登録へ戻る」）: `ec-cube-enterprise/src/Eccube/Resource/template/admin/Product/section.twig:42-46`、`ec-cube-enterprise/src/Eccube/Resource/locale/messages.ja.yaml:1632`
```twig
                            {% if id is not null %}
                                <a href="{{ path('admin_product_section') }}" class="btn btn-primary btn-csv ml-2">
                                    {{ 'admin.common.back_to_new_registration'|trans }}
                                </a>
                            {% endif %}
```
```yaml
admin.common.back_to_new_registration: 新規登録へ戻る
```

ベース実装 pf-eccube3 編集モードのときだけ出る新規登録のボタン（文言は「…はこちら」）: `pf-eccube3/app/Plugin/HareruyaEc/Resource/template/admin/Product/section.twig:8-12`
```twig

        </a>
```
