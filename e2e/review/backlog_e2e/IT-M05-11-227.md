# 期待される挙動【必須】
- ケースの期待結果（項目表 IT-M05-11-149）は、商品Xの在庫が7から6、商品総原価が3500から3000、受注数量が3から4、受注総原価が1500から2000になり、増減数-1の在庫変動履歴が1件登録され、配送先1件に商品X・価格1000・数量4の配送商品が登録されること。

# 現在の挙動【必須】
- 在庫は7から6、商品総原価は3500から3000、受注数量・受注総原価・配送商品は期待どおりに更新される。違うのは履歴の増減数だけで、変更前7・変更後6の履歴の増減数が -1 でなく 1（プラス）で記録される（2026-11-23 開発環境。ほかの5項目は期待どおり）。
- 履歴の在庫変動理由は「受注編集（注文数増）による在庫減 注文番号：… 増減数：1」で、別添資料の「受注による減算 注文番号：XXXXX」とも文面が違う。
- 受注編集の注文数増の履歴は、開発環境に3,741件あり、すべてプラスの値で、うち在庫が減ったものは3,741件ある（同じ環境で、欠品の加算・減算の履歴や在庫編集の廃棄は負の値を持つ）。
- 新アプリは、通常の注文数の変更を履歴に残すとき、増減数に絶対値（先頭の「-」を除いた値）を渡している。向きは在庫変動区分でしか分からない。フロントの注文完了の履歴が同じ症状になる件は ECCUBE_HARERUYA-4091 で起票済み（別の処理）。
- ベース実装（現行）には在庫変動履歴の機能が無い（新規）。
