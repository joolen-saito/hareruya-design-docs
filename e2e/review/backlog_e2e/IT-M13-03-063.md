# 再現手順【必須】
1. 開発環境（https://replace-dev.hareruyamtg.com:8443）の管理画面で、支払方法を設定していないイベントの日程追加画面を開く
2. 開始時間・定員・参加費1000・公開状態を入れ、オンライン受付ありをオンにしてオンライン受付開始・終了日時を入れ、「登録」を押す
3. 日程は追加されず入力画面に留まるが、画面上部に「保存に失敗しました」は出ず、参加費の直下に入力エラーが出る

# 期待される挙動【必須】
- 日程の保存に失敗したときは、画面上部に「保存に失敗しました」を表示し、日程入力画面に留まる（設計書 M13-03-MSG-002）。ベース実装は入力の検証に失敗したときも画面上部に保存失敗のメッセージを出す
- オンライン受付ありかつ参加費が有料で親イベントの支払方法が未設定のときはエラーとする

# 現在の挙動【必須】

# 根拠
- 設計：
  - 表示メッセージ M13-03-MSG-002「保存に失敗しました（日程追加の保存中にエラーが起きたとき）→ 日程入力画面に留まる」: `hareruya-design-docs/excel_to_html/output/0214_基本設計仕様書(イベント管理).html:1722`
  - 機能仕様: オンライン受付ありかつ有料で登録・更新するときは親イベントの支払方法をチェックし、無ければエラーとする: `hareruya-design-docs/excel_to_html/output/0214_基本設計仕様書(イベント管理).html:1667`
- ec-cube-enterprise：
  - 検証失敗時に上部メッセージなし: `ec-cube-enterprise/src/Eccube/Controller/Admin/Event/ScheduleController.php:68-98`
  - 参加費に付くエラー: `ec-cube-enterprise/src/Eccube/Form/Type/Admin/ScheduleType.php:214-225`
- ベース実装：
  - 検証失敗で保存失敗の上部メッセージ: `pf-eccube3/app/Plugin/HareruyaEc/Controller/Admin/ScheduleController.php:138-150`
  - 探した範囲: pf-eccube3 の ScheduleController。設計書の MSG-002 の条件は「保存中にエラーが起きたとき」で、入力検証失敗を含むかは読み分けられないため、含まないなら設計書の側を明確にする
