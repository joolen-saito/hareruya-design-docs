# 期待される挙動【必須】
- ケースの期待結果（項目表 IT-M03-38-021。E2E のテストID IT-M03-38-030）は、削除済みの商品の2種類の公開ステータスが取込前から変わらず、取込履歴が追加されないこと。
- 設計書（0204 商品公開CSV登録 業務ロジック「取込の判定順序」順序7・「エラー時の扱い」・入出力: 永続化）は、「商品IDの商品が実在すること。削除済みの商品を指す行は、存在しない商品として扱う」「存在しないときは以降の行を処理しない」「検証エラーまたは商品未存在が1件でもあると、その時点で取込を打ち切り、それまでに反映した行を含めて変更を確定しない」「取込がエラーなく完了したときに、取込履歴を1件記録する」と定める。

# 現在の挙動【必須】
- エラーは出ず、「登録が完了しました。」が表示され、CSVインポート履歴に「m03-38-deleted-product-030.csv」が1件記録される（2026-11-21 02:45 開発環境）。削除済みの商品の公開ステータスは変わらない（行は黙って飛ばされている）。
- 新しいアプリの取込は、商品が無いときと廃止のときに、その行をエラーにせず「処理しない」で次へ進む。エラーが1件も無い扱いになるので、取込は成功として履歴が記録される。存在しない商品IDでも同じ作り。

ec-cube-enterprise 商品が無い・廃止の行は、エラーにせず処理しない: `ec-cube-enterprise/src/Eccube/Service/Csv/Importer/Event/ProductStatusUpdateImportHandler.php:75-92`
```php

    {
        $row = $event->getRow();
        $productId = (int) $this->productIdColumn->getValue($row);
        ...
        $Product = $this->productRepository->find($productId);
        // 商品がない場合および廃止の場合処理をしない
```

- ベース実装（pf-eccube3）は、更新する商品が無いとき「商品が存在しない」エラーを積んで、取込全体を打ち切る。

pf-eccube3 商品が無いときはエラーにして打ち切る: `pf-eccube3/app/Plugin/HareruyaEc/Service/Csv/Importer/Event/ProductStatusImportHandler.php:61-79`
```php
    public function onReadRow(ReadCsvRowEvent $event)
    {
        $row = $event->getRow();

        $productIdValue = $this->productIdColumn->find($row);
        if (!$productIdValue->hasValue() || !$this->isProductExists($productIdValue->getValue())) {
            // 更新対象の商品がないのでエラー。
            $event->getMessageStore()
                ->addProductNotExistsError(
                    $row->getRowNumber(),
                    $this->productIdColumn->getLabel()
                );
            $event->breakAll();

            return false;
        }
```
