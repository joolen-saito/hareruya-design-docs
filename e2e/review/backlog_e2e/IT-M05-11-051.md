# 期待される挙動【必須】
- 合計金額の上限は9999999999で、上限を超えるときだけ手数料の欄にエラーを出して更新しない。上限ちょうどの合計金額9999999999の受注は更新できる（設計書 業務ロジック「更新できないとき」）。画面項目 6-13「価格」の最大値の定めは無い

# 現在の挙動【必須】
- 価格の欄に「この値は-2147483647以上2147483647以下でなければなりません。」と出て保存できず、合計金額9999999999の受注にならない。
- 合計金額の上限（9999999999）は設定されているが、その手前の明細の価格の入力チェックが±2147483647の範囲に固定されている。単独の明細で9999999999に届くには、この範囲を超える価格が要る。
- ベース実装も明細の価格に桁数の入力チェック（9桁）を付けており、価格9999999999（10桁）は同様に入力できない。ベース実装の合計金額の上限は9999999999で、超えるときだけ手数料の欄にエラーを出す。

# 根拠
- 設計：
  - 更新できないとき（合計金額が上限9999999999を超えるとき手数料の欄にエラー）: `hareruya-design-docs/excel_to_html/output/0203_基本設計仕様書(受注管理機能).html:3206`
  - 画面項目 6-13「価格」の最大値は「-」: `hareruya-design-docs/excel_to_html/output/0203_基本設計仕様書(受注管理機能).html:2957`
- ec-cube-enterprise：
  - 価格の入力範囲は±2147483647: `ec-cube-enterprise/src/Eccube/Form/Type/PriceType.php:52-58`
  - 合計金額の上限は別に9999999999: `ec-cube-enterprise/src/Eccube/Service/PurchaseFlow/Processor/PaymentTotalLimitValidator.php:46-49`
- ベース実装：
  - 明細の価格は桁数の入力チェック: `pf-eccube3/src/Eccube/Form/Type/Admin/OrderDetailType.php:61-72`
  - 合計金額の上限は9999999999: `pf-eccube3/src/Eccube/Controller/Admin/Order/EditController.php:137-139`
  - 探した範囲: pf-eccube3 の src/Eccube/Form/Type/Admin/OrderDetailType.php、src/Eccube/Controller/Admin/Order/EditController.php、src/Eccube/Resource/config/constant.yml.dist（int_len: 9、max_total_fee: 9999999999）

保留の理由: ケースは「1明細の価格9999999999」で合計金額の上限ちょうどを試すが、ベース実装でも1明細にその価格は入らない。ケースの作り方（複数明細で合計を上限ちょうどにする）と、設計書に明細の価格の最大値を書き足すかの確認が先。
