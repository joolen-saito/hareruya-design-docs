# 再現手順【必須】
1. 開発環境（https://replace-dev.hareruyamtg.com:8443）で、店頭買取査定申込前ログイン画面（/ja/otcbuy/<店舗の識別名>/entry）を新しいブラウザで開き、ログインせずにゲスト向けの導線を押して、店頭買取査定申込情報入力画面を開く（エントリー開始済み。入力も送信もしない）
2. 同じブラウザセッションで、会員登録フォームのURL（/ja/otcbuy/<店舗の識別名>/register_customer）へ、申込フォームの入力内容を含めずに POST で送る（試験用のフォームで入力項目なしの POST を送る）
3. 画面を確認する（エントリーへ戻らず、URL が register_customer のまま「システムエラーが発生しました。」の画面になる）

# 期待される挙動【必須】
- ケースの期待結果（項目表 IT-F08-02-049。E2E のテストID IT-F08-02-066）は、店頭買取査定申込前ログイン画面（エントリー）へ遷移すること。
- 設計書の現行仕様の節は、会員登録フォームは「エントリー開始済みかつ申込フォームが送信済み」のときだけ進め、満たさないときはエントリーへ戻すと定める（Excel 由来の部分には、この画面の進み方の定めは無い）。
- 現行（ベース実装の pf-eccube3）は、申込フォームの内容が送られていなければ（フォームが送信済みと判定されなければ）エントリーへ戻す。

# 現在の挙動【必須】
- エントリー開始済みで申込フォームの内容を含まない POST を会員登録フォームへ送ると、エントリーへ戻らず、会員登録フォームの URL のまま「システムエラーが発生しました。大変お手数ですが、サイト管理者までご連絡ください。」の画面になる（2026-11-17 開発環境）。システムエラーの直接の原因は開発環境のログを見ていないため未特定。
- 新アプリは、フォームの送信済み判定の前に、要求から取り出した申込内容（無ければ空）を電話番号の補完処理に通して同じ名前で要求へ書き戻している。書き戻しにより、申込フォームの内容が送られていなくても申込内容が「ある」ものとして扱われ、「送信済みでなければエントリーへ戻す」判定が働かない。
