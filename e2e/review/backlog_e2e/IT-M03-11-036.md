# 再現手順【必須】
1. 開発環境（https://replace-dev.hareruyamtg.com:8443）の管理画面で、商品管理＞カテゴリ登録/編集から、子カテゴリを持つカテゴリ（ケースでは「削除試験親-036」）を選んでカテゴリ登録/編集画面を開く。下の一覧に、商品が1つ紐づいた子カテゴリ（ケースでは「関連カテゴリ-036」。商品コード REL-001-036 の商品と関連）が出る
2. 「関連カテゴリ-036」の行の×アイコン（削除）にカーソルを合わせ、押す
3. 削除の確認ポップアップが出るかを確認する（ケースの手順は、ポップアップの「OK」を押すこと）
4. 画面の一覧に「関連カテゴリ-036」が残っているかを確認する

# 期待される挙動【必須】
- ケースの手順と期待結果は、商品が関連するカテゴリの×アイコンを押し、削除の確認ポップアップで「OK」を押すと、削除に失敗して「関連カテゴリ-036」が引き続き一覧に表示されること（出典は表示メッセージ M03-11-MSG-003「関連するデータがあるため「%name%」を削除できませんでした」、後続処理はカテゴリ一覧画面に遷移）。M03-11 の表示メッセージは、関連するデータがあるカテゴリを削除しようとしたときに出す定めである。
- 一方、同じ設計書のカテゴリ一覧（M03-45）の現行仕様は「子カテゴリを持つカテゴリ、および商品が紐づいているカテゴリは削除できない。一覧では削除の入口を選べない状態にし、…」と定めており、商品が紐づくカテゴリは削除そのものを試みられない（確認ポップアップも出ない）。この定めに従うと、ケースの手順（×を押して「OK」）は実行できない。
- 設計側で、商品が紐づくカテゴリの削除を「×を選べない」とするのか、「押せて、削除に失敗して表示メッセージを出す」とするのかを決め、設計書（M03-11 の表示メッセージの表示条件とカテゴリ一覧の定め）とケースの手順をそろえる。

# 現在の挙動【必須】
- 商品が紐づく「関連カテゴリ-036」の×アイコンは押せない状態（無効）で表示される。押しても削除の確認ポップアップは出ず、削除は試みられない。「関連カテゴリ-036」は一覧に残る（ケースの期待結果の「引き続き表示される」状態にはなるが、表示メッセージ「関連するデータがあるため…削除できませんでした」は出ない）。
- 子カテゴリがある場合に加え、商品が紐づく場合も×を押せなくするのは、テンプレートの条件による。削除の処理自体（表示メッセージ「関連するデータがあるため…」を出す側）は、×を押せるカテゴリでデータの関連エラーになったときにだけ働く。
