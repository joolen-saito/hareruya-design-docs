# 再現手順【必須】
1. 開発環境（https://replace-dev.hareruyamtg.com:8443）の管理画面で、会員管理＞ブラックリスト管理を開く
2. 既存の氏名の行（例「編集前氏名-024」）のキーワードを「一括更新予定」に書き換える
3. 新規登録行で項目「電話番号」を選び、キーワードに「090A」（数字でない文字を含む）を入れる
4. 「登録」を押す

# 期待される挙動【必須】
- ケースの期待結果（項目表 IT-M08-13-016。E2E のテストID IT-M08-13-024）は、保存済みの一覧が開き直され、「編集前氏名-024」が表示され、入力した「一括更新予定」と「090A」が画面に残らないこと。
- 設計書（0207 ブラックリスト登録/編集/削除 の業務ロジック「一括保存と中断」）は、途中で入力不備または重複を見つけた時点で以降を行わず、その回の変更は1件も保存しないとし、中断したときは一覧画面を開き直し、保存済みの内容を読み直して表示するため、入力途中の内容は画面に残らないと定める。

# 現在の挙動【必須】
- 「保存に失敗しました」と、新規登録行の電話番号に「入力が正しくありません」が出る。変更は保存されない（DB の行は「編集前氏名-024」のまま）。
- ただし、一覧は開き直されず、登録の送り先のアドレス（/admin/customer/blacklist/update）のまま、送った値で同じ画面が表示される。書き換えた行には「一括更新予定」、新規登録行には「090A」が残る（2026-11-20 08:39 開発環境）。
- 画面に出ている値が保存済みの値と違うため、そのまま直して「登録」を押すと、保存されていない書き換えも一緒に送られる。
