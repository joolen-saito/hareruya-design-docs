# 期待される挙動【必須】
- ケースの期待結果（項目表 IT-B16-09-042。E2E のテストID IT-B16-09-061）は、恒久的な転送となり、転送先が言語区分 ja を付けた日本語サイトの sitemap.xml のアドレス（https://replace-dev.hareruyamtg.com:8443/ja/sitemap.xml）であること。
- 同じ原因のケース: 項目表 IT-B16-09-044（E2E IT-B16-09-063）は、ルート直下の sitemap-b1609-063.xml の転送先が、日本語サイトの同名のアドレスであること。
- 設計書（0416 サイトマップ生成処理 業務ロジック「旧サイトのアドレスの維持」）は、「サイトマップのファイル名（sitemap で始まり .xml で終わるもの）がルート直下で要求されたときは、日本語サイトの同名のアドレスへ恒久的に転送する。検索条件は引き継ぐ」と定める。

# 現在の挙動【必須】
- 恒久的な転送（301）になり、パスと検索条件は期待どおり（/ja/sitemap.xml、/ja/sitemap.xml?a=1）だが、転送先のアドレスが http://replace-dev.hareruyamtg.com:8443/ja/sitemap.xml と、http で始まる（2026-11-21 14:00 開発環境。/sitemap_page.xml も同じ）。サイトは https で、この転送先は https のサイトのアドレスではないため、転送をたどっても日本語サイトのサイトマップに届かない。
- 転送の応答は Web サーバー（応答のサーバー名 Apache）が返している。新しいアプリのソースには、ルート直下のサイトマップを転送する処理が無い（サイトマップの経路は言語区分の下だけ。言語区分の無い要求を転送するアプリの処理は、転送先がトップページ /ja/ の相対アドレスで、この転送とは別）。転送の決まりは、開発環境の Web サーバーの設定にあると見られ、https を終端する前段から http で受けているため、転送先の組み立てに http が使われていると見られる（見立て。Web サーバーの設定はリポジトリに無く、確かめていない）。そのため不具合解析結果は保留とした。
