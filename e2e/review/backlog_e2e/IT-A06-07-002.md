# 現在の挙動【必須】
- HTTP 200 で、応答本文は {"cards":{}}（カード一覧が空）。商品IDリストをクエリで渡すと読まれず、指定していないのと同じ扱いになる（2026-11-17 開発環境）。
- 同じ商品IDリストを要求の本文（フォームの値）で送ると商品が返ることは、別のケース（項目表 IT-A06-18-001。E2E のテストID IT-A06-18-002。合格）で確かめた。
- 同じ原因で、項目表 IT-A06-07-008（状態の階層の販売価格・基準価格の確認）も商品が返らず、確かめられていない。
- 買取アプリ（MTGバイヤー）が商品IDリストをどちらで送っているかは確かめていない。本文で送っているなら実害は無く、クエリで送っているなら査定表の印刷で商品情報が取れない。新アプリのテストは本文で送るものだけで、本文からだけ読むと決めた記録は見当たらない。

```php
    #[Route('/%eccube_api_v1_route%/buying/products', name: 'api_buying_products', methods: ['POST'])]
    public function getByProductIds(Request $request): JsonResponse
    {
        $idsParam = $request->request->get('ids', '');

        // カンマ区切りを配列に変換し、数字のみをフィルタリング
        $productIds = array_filter(
            explode(',', $idsParam),
            static fn (string $id) => preg_match('/^\d+$/', trim($id)) === 1
        );
        $productIds = array_map('intval', $productIds);

        // カード商品以外のIDだけが来た場合、0件となり得るためエラーとはしない
        if (empty($productIds)) {
            return new JsonResponse($this->buyingCardsFormatter->format([]));
        }
```
