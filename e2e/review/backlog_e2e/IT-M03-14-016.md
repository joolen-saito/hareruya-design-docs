# 再現手順【必須】
1. 開発環境（https://replace-dev.hareruyamtg.com:8443）の管理画面で、商品管理＞略称タグ登録/編集を開き、一覧の件数を12000件にして、既存の略称タグ（ケースでは「編集前略称-016」・並び順10・商品との紐付けなし）の「編集」を押す
2. 名称を空にし、並び順を123へ変更し、アルファベット順ソートフラグをONにする
3. 「登録」を押す
4. 画面を確認する

# 期待される挙動【必須】
- ケースの期待結果（IT-M03-14-016）は「略称タグ登録/編集画面の新規入力欄に戻り、並び順123とアルファベット順ソートフラグONが復元されず、入力欄の直下にエラーが表示されないこと」。設計書の保存の判定順序 2「入力の検証を満たすか」は、満たさないとき「保存せず、一覧画面へ戻す。入力した値は復元せず、入力欄の直下にもエラーを出さない」と定め、表示メッセージ M03-14-MSG-001「登録できませんでした。」の後続処理も略称タグ登録／編集画面への遷移である。
- 名称は設計書の画面項目定義（識別ID 3）で必須（◯）。空の名称が「入力の検証を満たさない」入力にあたる。
- 判定の食い違いは、ケースの手順にある。手順2・3 のとおり画面だけを操作すると、名称の欄に付く必須のチェックをブラウザが先に行い、要求がサーバーへ送られない。設計書の判定順序 2 を確かめるには、ブラウザの必須チェックを外して名称が空の要求を送る手順（同じ型の売上分析タグ登録編集のケースは手順に「開発者ツールで」と書いている）をケースに足すか、期待結果を「ブラウザの必須チェックが送信を止め、編集の画面のまま」に改める必要がある。

# 現在の挙動【必須】
- 手順3 で「登録」を押すと、名称の欄の下にブラウザの吹き出し（Please fill out this field.）が出て、要求は送られない。画面上部のメッセージは出ず、URL は編集中の略称タグの画面のまま。見出しは「編集」で、並び順123・アルファベット順ソートフラグONが入力欄に残る。新規入力欄にはならない。
- 名称の必須は、アプリの略称タグの入力欄の定義が名称を必須にしているため、画面の入力欄の必須チェックとして働く。ベース実装（pf-eccube3）も同じ作りで、新しく持ち込んだ差ではない。
- ブラウザの必須チェックを通って要求が届いた場合の処理は、ソースの読みでは設計書どおり（入力の検証に失敗したら「登録できませんでした。」を出して一覧画面へ戻す）。この経路は、今回は画面で動かして確かめていない。
- 同じ画面の項目表 IT-M03-14-014・015（名称・並び順を空にして登録しても追加・更新されないこと）は、期待結果が「保存されないこと」なので、ブラウザの必須チェックが送信を止めても合格している。
