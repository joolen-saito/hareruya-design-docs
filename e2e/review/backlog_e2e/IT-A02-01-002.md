# 根拠
- 設計：
  - Excel 項目定義: subFileName は「サブ画像」、fileName は「画像」。名前は分けているが、どちらが商品規格画像・商品画像かは書いていない: `hareruya-design-docs/excel_to_html/output/0502_基本設計仕様書(API_商品管理).html:1078-1079`
  - Excel レスポンスサンプル: subFileName と fileName が同じ値（img/goods/L/AER/jp/22_jpn.jpg）。このサンプルは商品画像と商品規格画像が同じ商品の例で、2つが別の商品での返し方は決められない: `hareruya-design-docs/excel_to_html/output/0502_基本設計仕様書(API_商品管理).html:1098-1099`
  - 現行仕様 値の取り方: 「商品規格画像のファイル名と商品画像のファイル名は、該当が無いときはnullとする」。2つを別の値として扱うが、応答のどの項目に入れるかは書いていない: `hareruya-design-docs/excel_to_html/output/0502_基本設計仕様書(API_商品管理).html:1127`
  - 設計の中で食い違うわけではなく、設計が決めていない部分（結合試験項目表の期待結果は現行の pf-api の返し方に合わせた読み）
- ec-cube-enterprise：
  - fileName は商品規格画像を先にし、無いときだけ商品画像: `ec-cube-enterprise/src/Eccube/Service/App/Popup/PopupResponseBuilder.php:41`
  - 商品直下の先頭画像は取得しているが、規格画像があるときは使わない: `ec-cube-enterprise/src/Eccube/Repository/ProductRepository.php:2705-2710`
  - 自動テストも規格画像を返すことを確かめている（コミット fb62e7c100）: `ec-cube-enterprise/tests/Eccube/Tests/Web/App/ProductControllerTest.php`
- ベース実装：
  - 商品IDのポップアップは fileName に商品直下の画像: `pf-api/src/Repository/DtbProductSubClassRepository.php:60-62`
  - 探した範囲: pf-api の DtbProductSubClassRepository（商品ID・カードID）と ProductController。利用側（デッキ詳細・deck-builder）の fileName の使い方は手元のソースでは見つからず、確かめていない。
