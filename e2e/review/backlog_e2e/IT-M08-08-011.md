# 期待される挙動【必須】
- 設計書の現行仕様の節 業務ロジック「送信できないとき」は「入力の検証に通らないときは送信せず作成画面へ戻す。このとき通らなかった理由は画面に表示せず、編集していた件名と本文も保持されず、選択中テンプレートの初期値に戻る」と定める。ケースの期待結果（項目表 IT-M08-08-010。E2E のテストID IT-M08-08-011）も「手動メール通知(入力画面)へ戻り、選択したテンプレートが選択された状態で件名とメール本文が同テンプレートの初期値へ戻ること」。
- Excel 由来の画面項目定義は、件名・本文を必須とし、初期値を「テンプレ選択が未選択なら空欄、選択されていれば選ばれたテンプレートの件名・本文を初期セット」と定めるだけで、入力の誤りのときに入力値を残すか戻すかは定めていない（上の現行仕様の節と食い違いはない）。
- したがって設計書どおりにするなら、入力の誤りのときは、送られた値でなく選択中テンプレートの件名・本文で入力欄を描き直す。一方、現行仕様の節のこの記述は、ベース実装が送信後に必ず開き直す作りの副産物を書き写したもので、入力値を失わせ、理由も示さない動きでもあるため、現行どおりに戻すか、記述を直して今の動き（入力値を残して理由を示す）を認めるかの判断を要する。

# 現在の挙動【必須】
- 手順4 の「確認」を押すと、確認画面へは進まず手動メール通知の入力画面に戻る（応答は200）。テンプレートの選択は選んだものが保たれるが、件名とメール本文は空のまま（送った値のまま）で、選択中テンプレートの初期値（件名「【晴れる屋】お問い合わせについて」と案内文入りの本文）には戻らない。
- 件名と本文の入力欄は赤枠になり、それぞれの下に「入力されていません。」のエラーが出る。設計書の現行仕様の節は「通らなかった理由は画面に表示せず」と定めるので、この点も現行仕様の記述と違う。Excel 由来の部分・表示メッセージの節にはこのエラー表示の記述は無い。
- 原因は、入力の検証に通らないとき、送られた値でフォームを描き直して返す作りにあること。テンプレートの初期値は、要求の取り込みの前に入力欄へ入れているが、要求の取り込みで送られた空の値に上書きされる。ベース実装は、送信のあと検証の成否にかかわらず必ずリダイレクトで開き直し、テンプレートの値から描き直すので、入力値は残らない。
