# 再現手順【必須】
1. 開発環境（https://replace-dev.hareruyamtg.com:8443）で、日本語表示のブラウザに会員でログインし、商品をカートに入れて、ご注文方法指定画面を開く（アドレス帳は0件）
2. ご注文方法指定画面から配送先の新規登録・変更画面を開く（項目表 IT-F04-03-006 の手順1）
3. 国に「Japan」を選択する（手順2）
4. 郵便番号欄の脇にある外部リンクを探して押す（手順3。画面にあるリンクは、フォーム下部の「戻る」だけ）

# 期待される挙動【必須】
- 設計書の現行仕様の節（業務ロジック「郵便番号欄の外部リンク」）は、「国が日本のときは、郵便番号欄の脇に日本郵便の郵便番号検索ページを開く外部リンクを置く。英語ページでは『Search post code』と表示する。」と定める。
- ケースの期待結果（項目表 IT-F04-03-006）は、手順3のあと「日本郵便の郵便番号検索ページが開くこと」。
- 設計書の Excel 由来の部分（画面項目定義・初期表示の記述）は、この外部リンクについて記述しておらず、リンクを置かないとも書いていない（郵便番号については「ECCUBE4標準機能により入力値に基づいて都道府県・住所1を自動補完する」「現行に表示していた『郵便番号から自動入力』のボタンを除去する」とあるだけで、このボタンの除去とリンクは別のもの）。設計書の中の優先順位（Excel由来＞表示メッセージ節＞現行仕様の節）の上で食い違う記述は無く、現行仕様の節の記述が有効。

# 現在の挙動【必須】
- 国に「Japan」を選ぶと、郵便番号の2つの入力欄（〒　ー）は表示されるが、その脇に日本郵便の郵便番号検索へのリンクは無い。画面にあるリンクは、フォーム下部の「戻る」（ご注文方法指定へ戻る）だけで、押す対象が無いため、E2E は手順3で止まっている（期待結果の「検索ページが開く」までは確かめていない）。
- 同じ新アプリの非会員のお客様情報入力画面と、複数配送のお届け先画面には、郵便番号欄の脇に日本郵便の郵便番号検索ページ（https://www.post.japanpost.jp/zipcode/）を別タブで開くリンクがあり、この画面だけに無い。
- 原因は、配送先の新規登録・変更画面のテンプレートが、国が日本のときの郵便番号欄（2つの入力欄とエラー表示）を出すだけで、リンクを出していないこと。ベース実装（pf-eccube3）は同じ位置に日本郵便の郵便番号検索へのリンクを出す。
