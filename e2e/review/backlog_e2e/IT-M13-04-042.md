# 再現手順【必須】
1. 開発環境（https://replace-dev.hareruyamtg.com:8443）の管理画面で、支払方法を設定していないイベントの繰返日程追加画面を開く
2. 期間From・期間To・曜日を入れ、開始時間を空にし、受付ありとオンライン受付ありをオンにして各時刻を入れ、「登録」を押す
3. ブラウザの入力チェック（必須）が出て送信されず、画面上部の「保存に失敗しました」は出ない

# 期待される挙動【必須】
- 入力の検証に失敗したときは、保存に失敗した旨を表示して入力画面を再表示する（設計書の登録の判定順序 2）。支払方法未設定のメッセージ（判定順序 3）はこの検証が通ったあとの判定である
- ベース実装は入力の検証に失敗したとき画面上部に保存失敗のメッセージを出す

# 現在の挙動【必須】
- 入力の検証に失敗しても上部の保存失敗メッセージは出ない（例外時のみ）。開始時間の入力欄は必須としてブラウザの必須チェックが働き、サーバーの検証まで届かない。

# 根拠
- 設計：
  - 登録の判定順序 2「入力の検証に失敗したとき → 保存に失敗した旨を表示し、入力画面を再表示する」: `hareruya-design-docs/excel_to_html/output/0214_基本設計仕様書(イベント管理).html:1877-1880`
  - 表示メッセージ M13-04-MSG-003「保存に失敗しました」・MSG-004: `hareruya-design-docs/excel_to_html/output/0214_基本設計仕様書(イベント管理).html:1891`
- ec-cube-enterprise：
  - 検証失敗の上部メッセージなし: `ec-cube-enterprise/src/Eccube/Controller/Admin/Event/RepeatScheduleController.php:62-95`
  - 開始時間は NotBlank（ブラウザの必須属性が付く）: `ec-cube-enterprise/src/Eccube/Form/Type/Admin/RepeatScheduleType.php:127-134`
- ベース実装：
  - 検証失敗で保存失敗の上部メッセージ: `pf-eccube3/app/Plugin/HareruyaEc/Controller/Admin/RepeatScheduleController.php:60-80`
  - 探した範囲: pf-eccube3 の RepeatScheduleController。ブラウザ側の必須チェックが先に働くため、このケースの手順（開始時間を空のまま送信）は画面の操作だけでは再現できない。設計書の判定順序をケースに使うなら、ケース側で必須チェックを外す手順（入力欄の必須属性を外す）にする必要がある
