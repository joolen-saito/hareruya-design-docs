# 期待される挙動【必須】
- 項目表の期待結果は、011 が「対応状況が注文受領からピック中へ更新される」、012 が「ブラウザ印刷フラグが立っていない状態へ更新される」、014 が「ブラウザ印刷フラグが立っていない・対応状況がピック中・注文確定日が送信直前から応答受信までの日時」。
- ただし、ECCUBE_HARERUYA-3031（完了・2026-09-04）で「プリンタの仕様としてエンドポイントを URL で分けることはできないので、現実装（同じ受け口で ConnectionType により処理を分ける形）で問題ない。設計書を実装に合わせて直す」と決まっている。
- この決定に従えば、印刷結果の受信には ConnectionType=SetResponse が要る。ConnectionType を付けずに送って更新を期待するケース（011・012・014）の手順の側が、決定に追いついていない。
- 一方、設計書（Excel 由来）のこの機能のカスタマイズ説明は、いまも「クエリ『ConnectionType』で処理が分岐しているので、A05-02 とエンドポイントを分ける」のままで、リクエストパラメータも「印刷結果(XML)（引数は ResponseFile）」だけ。設計書の側も決定に追いついていない。
- 確認したい点：ケースの手順に ConnectionType=SetResponse を足して流し直してよいか。あわせて、設計書のカスタマイズ説明とリクエストパラメータを、3031 の決定に合わせて直すか。

# 現在の挙動【必須】
- 011・012・014 とも、POST の応答は 400（種類 text/plain・本文は空）。受注は更新されない。
  - 011：受注ID 50017852 の対応状況は注文受領のまま（期待はピック中）
  - 012：受注ID 50017857 のブラウザ印刷フラグは立ったまま（期待は立っていない）
  - 014：受注ID 50017858 の対応状況は注文受領のまま、注文確定日は未設定のまま（期待はピック中・送信時の日時）
