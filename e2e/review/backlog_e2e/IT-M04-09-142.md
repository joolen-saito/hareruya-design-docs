# 期待される挙動【必須】
- ケースの期待結果（項目表 IT-M04-09-112。E2E のテストID IT-M04-09-142）は「振替先の商品コード欄から M0409-142-B を選んで決定すると、振替先商品コードに入力され、商品名・言語・状態・Foil・基準価格が表示されること」。差分商品追加（項目表 IT-M04-09-165・166。E2E の IT-M04-09-195・196）も、検索した商品の行が検索結果に出ること。
- 設計書は、商品検索モーダルの検索を「商品名・商品ID・商品コード、カテゴリーを条件として商品を検索できる」とし、項目 2 のカテゴリを「単一選択（セレクトボックス）・必須の記載なし・初期値なし」としている。カテゴリは任意の条件で、指定しなくても商品名・商品ID・商品コードだけで検索できる。
- したがって、カテゴリを選ばないで検索できる（未選択の選択肢があり、開いた時点では未選択）。カテゴリを選ばなければ、商品はカテゴリで絞り込まれない。
- 完了済みの ECCUBE_HARERUYA-3486 は、受注情報編集の商品検索で同じ現象を不具合とし、期待を「カテゴリの初期表示が『選択してください』（未選択）で、未選択のまま検索したときはカテゴリで絞り込まない」とした。

# 現在の挙動【必須】
- 商品検索モーダルのカテゴリの選択欄に未選択の選択肢が無く、開いた時点で先頭のカテゴリ（開発環境では「テストカテゴリA」）が選ばれたままになる（キャプチャ）。未選択に戻す手段が無い。
- 検索は、画面で選ばれているカテゴリを必ず条件に付けて送るので、そのカテゴリに属さない商品は検索結果に出ない。IT-M04-09-142 は手順4（商品名「M0409-142-B 振替候補」で検索）で、結果の行が0件になって止まった。IT-M04-09-195・196（差分商品追加の商品検索）も同じ形で、検索結果に商品の行が出なかった（実施は 2026-11-16、開発環境）。
- 原因は、商品検索の入力欄の定義がカテゴリを複数選択として作っており、複数選択の定義では未選択の選択肢が作られないこと。振替の登録画面と移動の入庫承認申請画面は、これを単一選択に切り替えて描画するときに、未選択の選択肢を指定し直していない。
- 比較：同じ入力欄を使う受注情報編集・店頭買取の買取詳細・購買の詳細は、描画のときに未選択の選択肢を指定している（`placeholder: 'admin.common.select'`）。在庫管理の画面（振替の登録・移動の入庫承認申請・在庫結合・在庫分割）だけが指定していない。ベース実装（pf-eccube3）の商品検索のカテゴリは、先頭に「選択してください」がある。
