設計書：0204_基本設計仕様書(商品管理).xlsx

# 再現手順【必須】
1. 開発環境（https://replace-dev.hareruyamtg.com:8443）の管理画面で、商品管理＞売上分析登録/編集を開き、一覧の件数を12000件にして、既存の売上分析タグ（ケースでは並び順10のタグ）の「編集」を押す
2. 並び順に0を入れて「登録」を押す（項目表 IT-M03-17-013）
3. 画面とタグの並び順を確認する
4. 別の既存の売上分析タグの編集画面で、並び順に32768を入れて「登録」を押す（項目表 IT-M03-17-016・017）
5. 画面上部のメッセージ、入力欄、一覧の並び順を確認する

# 期待される挙動【必須】
- 設計書の画面項目定義（識別ID 2「並び順」）は必須で、範囲を0〜32767と定めている。0と32767は登録でき、32768は範囲外として登録されない。
- ケースの期待結果は、項目表 IT-M03-17-013「並び順が刷新後の下限値0で更新されること」、IT-M03-17-014「上限値32767で更新されること」（合格）、IT-M03-17-016「32768を入れると並び順が10から更新されないこと」。項目表 IT-M03-17-017 の期待結果「32768の入力内容が保持されず、新規登録の入力欄と一覧が表示されること」のうち、入力欄の戻り先の部分は、検証に失敗したあとの画面の食い違い（別の課題）にあたる。範囲外の値が保存されないことは、016 と同じ。
- 設計書の表示メッセージの節 M03-17-MSG-011 は「並び順が1〜65535の範囲外の状態で保存したとき」と書き、Excel由来の画面項目定義（0〜32767）と食い違っている。設計書の中の優先順位（Excel由来の部分＞表示メッセージの節。2026-10-16 決定）で、0〜32767を正とする。表示メッセージの節の範囲の記述も0〜32767に合わせて直す。

# 現在の挙動【必須】
- 並び順に0を入れて「登録」を押すと、ブラウザの入力チェック（Value must be greater than or equal to 1.）が出て、要求は送られない。並び順は10のまま更新されない（項目表 IT-M03-17-013）。
- 並び順に32768を入れて「登録」を押すと、応答は302で「登録が完了しました。」が出て、並び順32768で保存される（項目表 IT-M03-17-016）。保存したタグの編集の入力欄に移り、並び順の欄に32768が出る（項目表 IT-M03-17-017）。一覧にも並び順32768の行が並ぶ。
- 原因は、入力欄の定義の範囲が並び順を1〜65535としていること（ブラウザ側の最小・最大の指定と、保存時の範囲の検証の両方）。ベース実装（pf-eccube3）も同じ1〜65535で、新アプリはその値を引き継いでいる。

ec-cube-enterprise 並び順の入力欄の定義（ブラウザ側 min/max と保存時の Range がどちらも1〜65535）: `ec-cube-enterprise/src/Eccube/Form/Type/Admin/TagSalesAnalysisType.php:49-64`
```php
            ->add('rank', IntegerType::class, [
                'label' => '並び順',
                'required' => true,
                'attr' => [
                    'min' => 1,
                    'max' => 65535,
                ],
                'constraints' => [
                    new NotBlank(),
                    new Range([
                        'min' => 1,
                        'max' => 65535,
                        'notInRangeMessage' => '並び順は {{ min }} から {{ max }} の間で入力してください。',
                    ]),
                ],
            ]);
```

ベース実装 pf-eccube3 並び順の入力欄の定義（同じく1〜65535）: `pf-eccube3/app/Plugin/HareruyaEc/Form/Type/Admin/Product/TagSalesAnalysisType.php:34-48`
```php
            ->add('rank', 'integer', [
                'attr' => [
                    'min' => 1,
                    'max' => 65535,
                ],
                'constraints' => [
                    new Assert\NotBlank(),
                    new Assert\Range([
                        'min' => 1,
                        'max' => 65535,
                    ]),
                ],
                'label' => '並び順',
                'required' => true,
            ])
```
