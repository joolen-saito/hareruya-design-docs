# 期待される挙動【必須】
- ケースの期待結果（項目表 IT-M04-02-005。E2E のテストID IT-M04-02-007）は、「所属には在庫を保持する店舗に関連付く『在庫管理部』『東京販売部』が並び順昇順で表示され、メンバーには同店舗に所属して承認権限を持つ『青木承認者』『伊藤承認者』が名前昇順で表示されること」。ケースは「名前昇順」を読み順（あおき→いとう）と解釈し、青木が伊藤より先に並ぶことを期待している。
- 設計書（Excel 由来）の共通処理 画面共通部品 識別ID 1-2 メンバー選択は、メンバーの表示順を「メンバーの名前昇順とする」と定める。在庫編集の画面部品 3-7 承認通知先（メンバー選択）はこの識別ID 1-2 を参照する。
- 設計書は、「名前昇順」を文字コード順とするのか読み順（五十音）とするのかを定めていない。メンバーの情報に読み仮名の項目は無く、名前の文字列だけでは読み順に並べられない。
- どちらを正とするかの確認が要る。
  - A. 文字コード順（名前の文字列の昇順）を正とする場合: ケース IT-M04-02-005 の期待結果を「伊藤承認者→青木承認者」の並びへ直す（アプリはそのまま）。
  - B. 読み順を正とする場合: メンバーに読み仮名を持たせるか、日本語の照合順序で並べる実装に変え、設計書に「読み順」と明記する。

# 現在の挙動【必須】
- 所属の選択肢は、所属マスターの並び順どおり（在庫管理部 → 東京販売部）で出る。承認権限のない担当者・対象店舗に所属しない承認者は、メンバーの選択肢に出ない（いずれもケースの期待どおり）。
- メンバーの選択肢は、名前の文字コード順（先頭から英数字、次に「伊」「承」「試」「青」の順）で並ぶ。試験支店の選択肢227件のうち、「伊藤承認者」は174番目、「青木承認者」は179番目に出て、伊藤承認者が青木承認者より先になる。ケースの期待（青木→伊藤）と逆（E2E は、「メンバーは名前昇順（青木承認者が先）」の確かめで不合格。実施は 2026-11-14、開発環境）。
- 試験支店は共有で、ほかの試験用のメンバーも所属しているため、選択肢は2人だけにならない。ケースの確認は、足した2人の相対的な並びで行っている。
- 新しいアプリは、承認権限のあるメンバーを SQL の「ORDER BY 名前」で取得してそのまま選択肢に並べる。並べ替えの指定は名前の列だけで、読み順にする処理は無い。メンバーのエンティティにも読み仮名の項目は無い。
- ベース実装（現行）には、在庫編集の承認通知先（所属・メンバー選択）に当たる機能が無い（新規の機能。pf-eccube3 の app・src で「承認通知先」「approval_notification」「stock_approval」を探したが該当なし）。
