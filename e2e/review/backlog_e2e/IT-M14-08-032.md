# 期待される挙動【必須】
- ケースの期待結果（項目表 IT-M14-08-024。E2E のテストID IT-M14-08-032）は、「既存の青色画像が、同名の赤色画像へ置き換わって表示されること」。出典は現行仕様の節のシンボル画像「同じ名称の画像が既に置かれているときは、古いものを削除してから置き換える」。
- 設計書の画面項目定義（Excel 由来）の識別ID 16 は、画像を登録/更新するとファイルを S3 にアップロードすると定めている。保存後の編集画面では、置き換えた画像が見えることが必要。

# 現在の挙動【必須】
- 登録は成功し「保存しました」が出るが、編集画面のシンボル画像は青色のまま（2026-11-19 00:08 開発環境）。
- 原因は画像の取り違えや上書きの失敗ではない。操作の記録（通信）では、登録の直後に画像のアドレスを取りに行くと配信（CloudFront）が「Hit from cloudfront」・経過7〜8秒・更新日時が更新前（15:09:14）・内容の識別値も更新前のままの古い画像を返している。保存の約1秒後（15:09:23）に S3 のファイルは赤色の画像に置き換わっており、課題の調査時に同じアドレスを取り直すと更新日時 15:09:23・赤色の画像（内容がケースで用意した赤色の画像と完全に一致）が返った。
- 新アプリはシンボル画像を「cardset_symbol_image_＋カードセットID＋拡張子」の決まった名前で置くため、同じカードセットの画像を何度更新してもアドレスが変わらない。編集画面の画像のアドレスにも更新を示す印が無く、配信の保存が切れるまで更新前の画像が出る。
- ベース実装は毎回一意の自動の名前（uniqid＋乱数）で保存するので、更新のたびにアドレスが変わり、古い画像が残る問題は起きない。
