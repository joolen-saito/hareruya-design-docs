# 期待される挙動【必須】
- 項目表 IT-M03-17-012（E2E のテストID IT-M03-17-013）の期待結果は「65文字の名称が保持されず、新規登録の入力欄と一覧が表示されること」、項目表 IT-M03-17-009（同 IT-M03-17-010）の期待結果は「空にした入力内容が保持されず、新規登録の入力欄と一覧が表示されること」。出典は設計書の現行仕様の節の保存の判定順序 2「入力の検証を満たさないときは、保存せず、入力内容を保持しないまま新規登録の入力欄と一覧を表示する」。
- 一方、同じ設計書の表示メッセージの節は、M03-17-MSG-001「登録できませんでした。」を管理画面上部に出し、後続を「売上分析タグ登録/編集画面に留まる」と定める。M03-17-MSG-008〜011 は名称・並び順の欄の直下にエラー（「入力されていません。」「長すぎます。この値は{{ limit }}文字以下で入力してください。」など）を出し、同じく「画面に留まる」。現行仕様の節の入出力の失敗時出力も「一覧と入力欄を含む画面にエラーを表示する」。つまり同じ設計書の中で、入力の検証に失敗したあとの画面が「入力内容を保持しない新規登録の入力欄」と「入力欄の直下にエラーを出して留まる画面」に分かれている。
- 設計書の中の優先順位（Excel由来の部分＞表示メッセージの節＞現行仕様の節。2026-10-16 決定）では、Excel由来の部分にこの挙動の記述は無いので、表示メッセージの節が先に立つ。設計書の現行仕様の節の判定順序 2・3 と失敗時出力を表示メッセージの節に合わせて一つに決め、ケースの期待結果も合わせて直す。

# 現在の挙動【必須】
- 項目表 IT-M03-17-012（E2E のテストID IT-M03-17-013）の手順どおり65文字の名称で「登録」を押すと、応答は200で、画面上部に「登録できませんでした。」、名称の欄の直下に「長すぎます。この値は64文字以下で入力してください。」が出る。見出しは「編集」、入力欄の送り先は編集中の売上分析タグの保存のままで、名称の欄に入れた65文字が残る。新規登録の入力欄（見出し「新規追加」）にはならない。名称は保存されない（同じ操作でDBの名称が変わらないことは項目表 IT-M03-17-011 が合格）。これは表示メッセージの節の記述どおり。
- 項目表 IT-M03-17-009（E2E のテストID IT-M03-17-010）は、名称と並び順を空にして「登録」を押すと、ブラウザの必須チェック（Please fill out this field.）が送信を止め、要求は送られない。画面は見出し「編集」・送り先が編集中の売上分析タグの保存のままで、サーバー側の検証後の画面には届かない。ブラウザが止めない値でサーバーの検証に届いた場合は、上のとおり編集の入力欄に留まる作りなので、期待結果の「新規登録の入力欄」にはならない。
- 原因は、保存の処理が入力の検証に失敗したとき、一覧とともに「送られた入力欄のまま（編集対象を変えずに）」描き直す作りであること。入力欄の定義は名称・並び順とも必須で、ブラウザの必須チェックも付く。

# 根拠
- 設計：
  - 現行仕様の節 保存の判定順序 2「入力の検証を満たすか」: 満たさないときは保存せず、入力内容を保持しないまま新規登録の入力欄と一覧を表示する（3「登録済みの値と重複しないか」も同様）: `hareruya-design-docs/excel_to_html/output/0204_基本設計仕様書(商品管理).html:2967`
  - 現行仕様の節 入出力 失敗時出力: 一覧と入力欄を含む画面にエラーを表示する: `hareruya-design-docs/excel_to_html/output/0204_基本設計仕様書(商品管理).html:2973`
  - 表示メッセージの節 M03-17-MSG-001（登録できませんでした。・後続は売上分析タグ登録/編集画面に留まる）、M03-17-MSG-008〜011（名称・並び順の欄の直下のエラー。画面に留まる）: `hareruya-design-docs/excel_to_html/output/0204_基本設計仕様書(商品管理).html:2978`
- ec-cube-enterprise：
  - 入力の検証に失敗したときは、送られた入力欄のまま（編集対象を変えずに）エラーつきで描き直す: `ec-cube-enterprise/src/Eccube/Controller/Admin/Product/TagSalesAnalysisController.php:132-150`、`ec-cube-enterprise/src/Eccube/Form/Type/Admin/TagSalesAnalysisType.php:38-48`
- ベース実装：
  - pf-eccube3 は入力の検証に失敗したら一覧画面へ戻す: `pf-eccube3/app/Plugin/HareruyaEc/Controller/Admin/Product/TagSalesAnalysisController.php:52-58`
  - 探した範囲: pf-eccube3 の売上分析タグのコントローラーと入力欄の定義。入力値を保持して編集の入力欄に留める処理は無い
