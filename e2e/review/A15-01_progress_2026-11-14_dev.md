# A15-01 ログイン（デッキビルダーの API）— 開発環境で流せる形にした（2026-11-14）

## 書いたケース（9件）
001・002・003・005・006・007・009・012・021（spec/a15/a15-01.spec.ts・seeds/a15-01.ts・db/a15_01.ts）

## 作り方と読み替え（正本の外の補い）
- 会員はフロントの新規会員登録で作る。メールアドレスはシード表の値の @ の前に実行の印を付けた（パスワードはシード表の値）。選手が要る会員は MTG Companion登録名を入れて登録する（登録で選手ができる）。
- 「本会員ではない」「削除済み」（005）は画面で作れないので、E2E の会員の区分（仮会員）・削除の印だけを DB で書いた（lib/db_write.ts）。
- 「開発者ツールで要求を送る」は、試験ブラウザのコンテキストから API へ要求を送る形に読み替えた（Cookie はブラウザと同じ入れ物に入る）。
- アクセストークンの内容と署名方式（002）は、トークンを「.」で分けて第1部・第2部を読む（署名鍵は使わない）。
- 021 のシード表は選手の有無を書いていないが、ログインの API は選手の無い会員にトークンを出さないので、選手のある会員として作った。

## 流す前から分かっていること（実ソース）
- ログインの API はアクセストークンを Cookie に設定しない（003 は期待と違う見込み）。
- ログインの API は選手の無い会員を「Authentication failed」の 401 で断るので、009 の手順2（プレイヤーを持たない会員のトークン）はトークンが返らない見込み。

## 流さないケース
- 008（受注ID 150111008・商品規格ID 150121008 の決め打ちの番号）、013〜018・020（デッキの登録が要る・署名鍵で作るトークン）は流せないままにした（流せない一覧）。
