## 作り方と読み替え（正本の外の補い）
- 要求の送り方: 開発者ツールの代わりに、試験ブラウザ（ケースのコンテキスト）からデッキ登録インポート API へ要求を送り、HTTP ステータスと応答本文（JSON）を読む（A15-02 と同じ）。
- アクセストークン: シード表のログインフォーム操作の代わりに、シードの会員でログインの API を呼んで受け取る（値は記録しない）。署名不正（013）は署名部の末尾1文字を変えて作る。
- 会員: フロントの新規会員登録（A15-01 の 会員を作る）。メールアドレスは @ の前に実行の印、パスワードはシード表の値のまま。選手は MTG Companion登録名を入れて作る。
- 共有可のシード（フォーマット・カード・アーキタイプ・キャンペーンタグ・統率者フォーマット・カードC・上限500カード）は「あれば DB で確かめて使い、無ければ管理画面で登録」。名前はシード表の値のまま（実行の印は付けない。ケースが名前そのものを使うため）。
  - カードはカード登録CSV（画像URL(英語)は設計書の入力例の形式）。カードセット・レアリティ・レイアウトは登録済みのものを読んで使う。
  - キャンペーンタグの番号・アーキタイプの番号は、マスタ検索の応答・一覧の代わりに DB を名前で引いて控える（読むだけ）。
- AUTH-CONFIG（署名方式・署名シークレット）は共有の設定なので書き換えず、設定済みの値をそのまま使う。SCOPES・DECK-MASTERS は登録済みであることを DB で読んで確かめるだけ。
- 「デッキ名のデッキ／存在しないカードがあれば DB から削除する」は行わない。会員は毎回新しく登録するので、会員が持つ同名デッキは 0 件で始まる。
  持ち主を問わないデッキ名の件数を見る 012・013・028 は、送信の前後の差で見る（「増加しない」は差で確かめられる）。存在しないカードは DB で 0 件を読み、あれば止める。
- EXISTING-002 の既存同名デッキは、デッキビルダーの画面操作の代わりに、持ち主（別の試験会員）のトークンでデッキ登録インポート API を呼んで作る（非公開・結合試験カードAが1枚）。
- 公開区分の識別子は DB から名前で引く（公開・非公開・限定公開）。キャンペーンタグは、001・002 では1件の値、003 だけ配列で送る（正本の文のとおり）。
