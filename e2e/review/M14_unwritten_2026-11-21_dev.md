# M14 群 テスト未作成のケースの理由（2026-11-21・開発環境）

書き足した分は spec/m14/m14-03.spec.ts・m14-05-e.spec.ts・m14-08-e.spec.ts・m14-10-f.spec.ts（M14-03-002・M14-05-073・M14-08-048・049・M14-10-030）。
下のケースは、書けない前提が分かったので書いていない（正本・期待結果は変えていない）。

| ケース | 理由 |
| --- | --- |
| M14-01-036 | 12001件のカードをDBシードで一括登録する前提。画面から12001件は作れない |
| M14-01-045 | 約20種の共有のマスタ値（英語名固定）の登録・キーワード能力のDB設定・マナ・コストの入れ直し・固定のカード詳細IDのカード2件が要る。出力値は正本の英語名と一致させるため、実行の印を付けると期待値が変わる。規模が大きく今回は着手していない（書けないとは限らない） |
| M14-01-065・101・103 | 開始時にカード名リストの公開ファイル（全員の画面が読む）を削除する前提。ユーザーデータのファイルは画面から消せず、公開ファイルの削除・上書きは全員が使う設定の書き換えになる |
| M14-04-028・062・068・069 | シードが「商品サブ規格行」（削除済み商品が指定するカード詳細の行）をDBで作る前提。新しいアプリには該当する表が無く（カード詳細を指す列があるのは商品と画像だけ）、画面でも作れない。期待結果（その行の指定が未設定になる）も確かめられない。028 は買取メインカード・メイビーカードなど画面にない関連も要る |
| M14-04-051 | 固有色（カラーのマスタ）がちょうど6種である前提。共有のマスタには試験で足された値（M1404-049-A など）が残り、既存の行は消せないので「6種だけ」が成り立たない |
| M14-05-020 | カード詳細IDが未設定の画像の行を作る前提。画面では作れず、DBで足す行には持ち主を確かめる印（カード名）が付けられない |
| M14-06-011・019・021・022 | カードセット12001件をDBシードで登録する前提（021・022 は既存データの退避・復元も要る） |
| M14-06-031・032 | 既存のカードセット・カード詳細・画像・プロモ設定を退避・復元する前提。カードセットを選ばない画像ダウンロードは、共有の「カードセット未設定のプロモカード」全件（開発環境で約17,600件）が対象で、件数を制御できない。ダウンロードの処理は人の画像の行のデッドリンクも書き換える |
| M14-06-046・047・048・050 | カードセットを60件だけにする前提（既存のカードセットとカード詳細を取り除く）。共有のデータは消せない |
| M14-07-005・006・027・032・034 | カードセットを選ばない画像ダウンロードの対象が共有の全データ（上のとおり約17,600件）で、期待どおりの少数のZIPにならない。032・034 はデッドリンクの書き換えが人の行にも及ぶ。同じ理由で前回までも未実装 |
| M14-08-042・058・059・060・054 | 画像の実体を置く画面がなく（テスト用画像配置処理が要る）、カード検索・採用枚数ランキングの表示キャッシュも画面で消せない。042・058〜060 は商品をDBで足す前提もある。054 はさらに11分待つ。共有のキャッシュ・画像保存先は書き換えない |
| M14-09-004 | フォーマットを0件にしたDBスナップショットを復元する前提。共有のフォーマットは消せない |
