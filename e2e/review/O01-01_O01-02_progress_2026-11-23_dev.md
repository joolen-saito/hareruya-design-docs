# O01-01・O01-02 MTGバイヤー（試験端末のアプリ）— E2E で流せない理由の記録（2026-11-23）

依頼者は 11/23 に、「シードの投入方法が DB への直接の設定」という理由で流せない一覧に載せていたケースのうち、E2E が作った行の列だけを DB に書けば流せるものを、一覧から外して流すことを了承した（メモリ e2e-finish-saito-blank-rows-1123）。O01-01（126件）と O01-02（51件）は、11/23 の仕分け（review/blank_rows_1123.tsv）で、このうちの「流せる」（O01-01 の126件、O01-02 の30件）と「判断が要る」（O01-02 の21件）に入っていた。

ケースを読み直した結果、どちらも流せないと分かった。そのため、流せない一覧からは外していない。

## 流せない理由

- **全件が、端末のアプリの画面を操作する手順**
  - O01-01 の126件と O01-02 の51件は、どれも MTGバイヤーの試験端末のアプリ（デスクトップのアプリ）の画面を操作して確かめる。ログイン画面、業務選択画面、お客様選択画面（店頭買取・ネット買取）、査定の画面などで、期待結果も「アプリの画面で確認」と書かれている。
  - 手順と期待結果で、端末のアプリ・業務選択画面・端末を使わないケースは0件だった（手順と期待結果の文で数えた）。
- **Playwright では操作できない**
  - Playwright は、ブラウザの画面しか操作できない。試験端末のアプリの画面の表示（行の項目、査定状況の画像、ボタンが灰色かどうか など）は、MTGバイヤー向けの API の応答に置き換えても確かめられない。
  - その API そのものは、A06・A07 で別に確かめている。O01-03 と同じ扱い（review/O01-03_progress_2026-11-20_dev.md）。
- **シードを書けても流せない**
  - DB の直接の設定（査定番号・申込日時・買取ステータスなど）は、E2E の行だけなら db_write.ts で書ける。
  - ただ、手順と期待結果が端末のアプリの画面なので、それだけでは流せない。
