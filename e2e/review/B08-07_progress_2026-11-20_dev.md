# B08-07 身分証有効期限切れ通知（バッチ）— E2E の記録（2026-11-20・開発環境）

## 結論：E2E では書かない（36件すべて）

正本の36件は、どれも手順1が「バッチB08-07『身分証有効期限切れ通知』を起動し、終了するまで待つ」になっている。開発環境では、E2E からこのバッチを起動できない。また、起動すると、共有の DB にあるほかの方の会員も書き換えてしまう。この2つの理由で、テストを書かない。

| 理由 | 根拠 |
| --- | --- |
| E2E から起動する手段が無い | バッチはアプリのコンソールのコマンド（身分証有効期限切れ通知バッチ）で、開発環境ではアプリのコンテナの定期実行で動く。管理画面にも API にも、起動の入口は無い。E2E が届くのは管理画面・フロント・API・DB（読むだけと、E2E の行への書き足し）だけで、開発環境のコンテナでコマンドを動かす手段は無い（手元の docker 用の lib/app_config.ts の docker exec は、開発環境では使えない）。 |
| 起動すると、ほかの方の会員を書き換える | バッチは、有効期限が近い選手を全員選び、身分証有効期限を消し（未設定）、本人確認ステータスを「未確認」にする（簡易書留確認済みは除く）。そのうえで、会員と管理者へメールを送る。共有の開発環境の DB には、ほかの方の試験の会員もいるので、E2E の行だけに絞れない（「ほかの方のデータを書き換えない」に当たる）。 |

- 正本のケース（cases/B08-07_test_cases.tsv）と、シード表（S-B08-07-DB・S-B08-07-MAIL ほか）は変えていない。
- 流すには、次のどちらかが要る。
  - 手元の環境（docker）でバッチを起動する形にする。手元の WSL では、いまは docker が使えない。
  - 流せない一覧（config/sheet_not_runnable.tsv）に載せる。
  どちらにするかは、依頼者が決める。
