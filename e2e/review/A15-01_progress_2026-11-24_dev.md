## 書いたケース（4件）
013・016・018・020（spec/a15/a15-01-b.spec.ts・seeds/a15-01-b.ts・db/a15_01_deck.ts）。判定済みの a15-01.spec.ts の指紋を守るため、別の spec にした。

## 作り方と読み替え（正本の外の補い）
- 会員の作り方は seeds/a15-01.ts と同じ。MTG Companion登録名は英数字だけを受け付けるので、シード表の「A1501-…-PLAYER」の代わりに姓「Shiken」・名「A1501…」にした。
- 「プレイヤーを持たない会員」（013A・CB020A）は、シード表のとおり、会員登録で同時にできた選手を DB で取り除いた（E2E の選手の行に削除日時を書く。行は消さない）。
  ログインの API は削除済みの選手でも会員にトークンを出す作りなので、手順のとおりトークンを受け取れる見込み（受け取れないときは、送れなかったことを記録する）。
- デッキは管理画面のデッキ新規登録で、ユーザーデッキとして登録した。プレイヤーはプレイヤー検索で名「A1501…」を探し、ID が最大の行を選び、控えた選手IDと同じことを確かめた。
- 「登録済みの任意のフォーマット・アーキタイプ」は、実行ごとに1度、印つきの名前で登録したものを使った（共有のマスタは書き換えない）。
- 限定公開トークン「A1501-016-VIEW」「A1501-018-VIEW」は画面で指定できないので、E2E のデッキの行にだけ DB で書いた。アプリはデッキを一時保存からも読むので、書き換えが見えないことがある。ケースは一致しない「…-WRONG」を送るので、期待結果に効かない。
- 事前準備の「Cookie と Network 記録を削除して未認証状態」は、ケースごとに新しいブラウザのコンテキストで始めることで満たす。
