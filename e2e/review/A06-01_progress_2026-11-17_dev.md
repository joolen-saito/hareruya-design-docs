## 正本の外の補い（読み替え）
- 「ブラウザの開発者ツールから POST で送る」「Network で確かめる」は、ブラウザのページから API サーバー（開発環境は https://replace-dev.api.hareruyamtg.com。`config/env.ts` の API_BASE_URL）へ要求を送り、送った要求と応答（HTTP ステータス・応答本体）をページに表として出して読む形にした。各手順のあとの画面にその表が写る。認証トークンの値は記録しない（長さだけ）。
- API の入口は `/api/v1/…`。ケースの `/api/admin/login.json` は `/api/v1/admin/login.json` に当たる（11/14 の見直し `A06_A07_api_recheck_2026-11-14.md`。`/api/admin/login.json` は 404）。入口だけ読み替えた。
- ログイン API は、ログインID・パスワードを本文のフォームの値で送る（アプリがフォームの値で読む）。
- 管理者ごとの専用店舗「A06-01店舗-NNN」（店舗住所 東京都千代田区晴海1-1）は、試験店舗の使い回し（2026-11-13 依頼者決定）で作らず、試験支店（店舗ID 1574）に所属させた。002 の店舗名・店舗住所は、試験支店の DB の値（店名・住所の1行目と2行目をつなげた値）として確かめた。
- 管理者の名前・ログインIDには、実行をまたいで使い回す決まった印（-E2E。ログインIDは小文字）を付けた。002 の管理者名は印つきの名前として確かめた。
- 008 の「ペイロードの復号」は、トークンの2つ目の区切りを base64 で復号して読み、ページに出した。

## 流した結果
- 2026-11-17 16:08 試しに 002 を1件だけ流した（PW_SLOTS=2・並べて）。シード（試験支店に所属する管理者のメンバー登録）と、API サーバーへのログインの要求が通ることを確かめた。
  - 002: 不合格（実装差異）。応答の管理者IDが数値（100013267）で返り、文字列でない。設計（0506 買取アプリ用ログイン レスポンスデータ・design.txt L0043）は 管理者IDを文字列と定める。ほかの7項目（HTTP 200・管理者名・店舗名・店舗住所が DB の値と一致・認証トークンが空でない文字列・所属店舗）は期待どおり。値の型の違いは並べたせいでないので、1本だけでの流し直しはしていない（基盤が始めた1本だけの流し直しは、ほかの流しを止めないよう止めた）。
- 残りの 007・008 は昼の列に積んだ。006 はデータを消すシードとして流れない（消してよいの一覧への追記は依頼者の了承待ち）。
