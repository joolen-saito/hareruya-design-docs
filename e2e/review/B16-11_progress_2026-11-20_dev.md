# B16-11 S3画像サイズチェック処理 — E2E にできない理由（2026-11-20）

正本は integration_test/casegen/cases/B16-11_test_cases.tsv（61件）。項目表の齋藤さんの担当の「未実施」のうち、B16-11 は61件すべてが、テストが無い。

## 結論：E2E（開発環境の Playwright）では書けない

61件のどのケースも、次の3つを前提にしている。そのどれも、E2E からはできない。

1. バッチの手動起動（S-B16-11-RUN）
   - 正体は、アプリの外の運用スクリプト ec-cube-enterprise/script/ops/imgcheck/bigfilefinder.sh。cron で15分ごとに動く。
   - 動く場所は本番の EC2 で、中身は AWS CLI の s3 ls と sendmail。
   - 開発環境（ECS）でこのスクリプトを起動する手段は、E2E には無い。手元から ECS・SSM には届かず、aws CLI も入っていない。
2. 試験環境の S3 バケットの対象フォルダを空にする（S-B16-11-S3ENV）
   - 投入方法は「s3 rm --recursive で対象の各フォルダ以下を削除」。
   - 開発環境のバケット（replace-dev-filepool-resized）の img/goods/L・C・I・banner・product・set は、みんなが使う商品の画像が入っている。消すと、ほかの方のデータを消すことになる。
   - 消すシードの決まり（コードの確かめと依頼者の了承。ほかの方の行は消さない）にも当たる。
3. メール試験サーバーの通知先メールボックスを空にし、バッチの設定でメールの送信可否を true にする（S-B16-11-MAIL・MAILON）
   - 宛先は本番の hareruya_filesize_alert@hareruyamtg.com と it_common@hareruyamtg.com で、スクリプトの sendmail から届く先。開発環境のメールの受け口とはつながっていない。

## 流せるようにするには（依頼者の判断が要る）

- 案A：手元の docker（localstack の S3 と手元のメールの受け口）で、スクリプトを直接起動して確かめる。
  - スクリプトの既定値は localstack。
  - いまの WSL では docker が使えない（Docker Desktop の WSL 連携が切れている）。
  - 11/10 の「全部を開発環境で」の決まりの例外になる。
- 案B：流せない一覧（config/sheet_not_runnable.tsv）に載せる。項目表の4列は空欄のままにする。
