## 注記

- 正本の「基準価格変更CSVアップロード画面」は、メニュー「商品管理」→「CSV管理」の画面（見出し「基準価格変更CSVアップロード」）。正本の「CSVファイルのアップロードボタン」は画面の「CSVファイルをアップロード」ボタン（文言の違い）。
- 取込ファイルの列名は、ケースの手順2が書く「商品ID、言語ID、基準価格、買取価格、原価単価」（設計書 L0139〜L0143 と同じ）。UTF-8・タブ区切り・LF・末尾に改行1個（正本は改行の種類を書かない。fixtures の README と同じ決め方）。
- S-M03-30-ADM: メンバー管理で、所属店舗に選択肢の先頭、権限にシステム管理者を付けて登録した（M03-29 と同じ作り方）。
- S-M03-30-MASTER: 「DBシードで言語ID=1を登録」は行わず、画面で確かめた（言語の欄に値1「日本語」があり、値999が無い。商品マスターで商品ID 999999999 が0件）。このため、これを使うケース（014・055・059）は合格しても「条件付き合格」になる。
- DATA-055・059 の商品はグッズ商品CSV登録（雛形は画面から取得）で作った。「商品カテゴリ(ID)と購入グループ名称=登録済みのもの」は、サプライ・グッズ直下の並びの先頭のカテゴリ（ID 100000002）と、購入グループ一覧の先頭。商品公開ステータス・支店の商品公開ステータスは、画面の説明で「公開」に当たる値。
- DATA-055 の「カード検索ポップアップで登録済みのカードを1つ選び」は、カード名を入れずに検索した結果の先頭（カード詳細ID 100000014「M0323-042カードOT」）。「商品を登録」で必須の販売制限に「制限なし」を選び、割引率は画面が最初から選んでいた「1」のまま保存された（商品の割引率が1になった。NM規格の換算には効かない。055 は不合格なので区分には影響しない）。

## 裁定案（直すかどうかは依頼者が決める）

1. 原価単価の列: 設計書の基準価格変更CSVフォーマットは5列目に「原価単価」を置き（L0143）、カスタマイズ説明は「原価単価を新規追加」（L0154〜L0155・L0168）とするが、L0143 の備考は「新規追加→こちら対応なし」。アプリは4列（見出しの定義・取込の列定義とも）。5列を正とするならアプリの直し（037・055・059・014 が影響）、4列を正とするなら設計書とケース（手順2の5列、037 の期待結果）の直しになる。M03-30 の多くのケース（001〜036 など）も5列のファイルを使う。
2. 032 の期待結果「セール用価格変更CSVアップロード画面へ遷移すること」（設計書 L0119・L0120・L0122 の MSG-002・003・005 の後続処理も同じ）: 基準価格変更の画面から、別の機能（M03-31）の画面へ遷移するという定め。M03-31 の設計書からの写し誤りとみられる（アプリは基準価格変更CSVアップロード画面へ戻す）。設計書と、032・025 などの期待結果の確認が要る。あわせて、ファイル未選択はブラウザの入力チェックで止まる（HANDOFF 4章の19 と同じ型）。
3. QC-MASTERS（073〜076 と M03-31 の 071〜076 が共用）: 「割引率A」「部門ショーケース」「販売種別A」を選べることの確かめが、ケースの確かめに使われていない（073・075 は割引率・部門を使わない）。確かめの対象から外せば、073・075（と M03-31 の 071・073・074）は画面で準備できる。
4. 割引率なしのシングルカード商品（043・054・056〜058・063・064）: 画面の「商品を登録」では割引率が必須で「割引率設定なし」にできない。割引率を許す作り（CSVで作る・既存の率で期待値を出し直す）にするか、判断が要る。
5. THRESH: 投入方法「設定画面で閾値を300円にする」の画面が無い（アプリに固定）。「アプリの閾値が300円であることを前提にする」へ直す案。
