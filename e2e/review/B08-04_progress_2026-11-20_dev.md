# B08-04 必須項目が空欄の会員発生通知（開発環境・2026-11-20）

## 結論：E2E では書かない

テストがまだ無い10件（003〜010・014・019）は、どれも手順1が「バッチ B08-04『必須項目が空欄の会員発生通知』を起動し、終了するまで待つ」になっている。開発環境では、このバッチを E2E から起動できない。

## 起動できない理由
- このバッチは、アプリのコンソールのコマンド（必須項目空欄会員通知バッチ）として作られている。管理画面にも API にも、起動の入口が無い。
- 開発環境では、バッチの EC2 が毎日1回、自動で流している。開発環境のメールの受け口に、件名「必須項目が空欄である会員の存在を通知するメール」が 11/16〜11/19 に毎日1通ずつ届いている（受け口の時刻で 19:05）。
- バッチは、共有の DB の会員を全件読んで、必須項目が空欄の会員を1通のメールにまとめて送る。書き込みはしない。ただし、ほかの方の会員も対象になる。そのため、次のケースは開発環境では成り立たない。
  - 006：対象が0件でメールが0通になる、というケース。ほかの方の空欄の会員が常にいるので、0通にならない。
  - 019：送信元を本店の店舗設定で変える、というケース。全員が使う共有の設定を、自動の実行の時刻まで書き換えたままにすることになる。

## 流すとしたら（依頼者の判断が要る）
- 案1：E2E のシードで、必須項目が空欄の試験会員を作っておく。毎日の自動の実行のあとに、届いたメールの本文に、その会員ID が載っているか・抜粋行の形がどうかを確かめる（003〜005・007〜010・014）。
  - 空欄の会員は画面では作れないので、E2E の会員の行だけを DB で空欄にする（11/10 の決まり）。
  - 準備と確かめを2回に分けて流す形を、ハーネスに足す必要がある。手順1は「自動の実行を待つ」に読み替える（正本の外の補い）。
  - 006・019 は、開発環境では成り立たないので外す。
- 案2：流せない一覧（config/sheet_not_runnable.tsv）に載せて、項目表は「実施不可」にする。
