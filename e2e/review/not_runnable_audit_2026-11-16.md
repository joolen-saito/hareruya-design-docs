## 判断が要る決まり（件数の多い順）

1. **親になる行を DB に足してよいか（539件）**: 受注・マスタ・CSV 種別・定義など、親になる行そのものを E2E が DB に新しく足す必要がある。
   - 今の窓口 `lib/db_write.ts` は「E2E が作った親にぶら下がる行を足す・書き換える」だけ。
   - 「親の行を、持ち主の確かめ（決めた ID の範囲＋実行の印）付きで足してよい」と決めれば流せる。
   - 型: CSVTYPE 167・WIPE 134・PRICE 99・LINK 47・HISTORY 37・POINTHIST 28 ほか。
2. **ほかの方のデータの全件削除・件数そろえ・環境の初期化（476件）**: 「0件」「この数件だけ」や一覧全体の件数・並びを確かめるケースと、環境の初期化・再投入。
   - 共有の開発環境では条件を作れない。
   - E2E 専用の環境（別の DB か、流す時間帯を決めた戻し）を用意するかの判断が要る。
   - 型: WIPE 261・ENV 146・DATE 19・HISTORY 16 ほか。
3. **スマレジ・外部の試験環境（109件）**: スマレジは後回しと決めていた（11/11）。
   - スマレジの試験環境で取引を作り、アプリに取り込まれた番号を DB の参照で控える形で流してよいかの判断が要る。
   - 外部（ユニサーチ・決済・送信元 IP の中継）は、試験環境の用意が要る。
4. **管理者の所属店舗を2つ持たせる（52件・栗野さんの機能）**: アプリの管理者は所属店舗を1つしか持てない作り。
   - 設計どおりに2つ持たせる方法が無い。実装の不足として不合格にするか、設計の判断を仰ぐかの判断が要る。
5. **共有の設定を書き換えるケース（16件）とバッチ（9件）**: 夜の回（22:00〜6:00・1本だけ）で、書き換えて戻す形にすれば流せる見込み。
   - 夜の回は、高額商品閾値などをすでにこの形で扱っている。
