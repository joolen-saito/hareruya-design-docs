## 正本の外の補い（エビデンスの注記に出す）

| 何を | どう読み替えたか | 理由 |
| --- | --- | --- |
| カード名の「A1508-NNN」 | 実行の印を付けた「A1508-NNN-〈印〉」で作り、検索語も同じにした | 決め打ちのカード名のままだと、2回目の実行で前の回のカードにも当たる（案A。依頼者決定 2026-10-28）。048・049 の「該当なし」の語は、どのカードにも含まれないので印を付けない |
| カードの作り方 | シード表のカード新規登録画面の代わりに、カードCSV登録（同じ管理画面の取込）でまとめて作った | 登録される値は同じ。047 の101件などは、画面で1件ずつ作ると時間がかかりすぎる |
| カード詳細のカードセット・レイアウト、指定の無いレアリティ | 登録済みのもの（カード一覧のCSV出力の先頭のカードの値）を使った | シード表の「登録済みのものを1つ」 |
| 画像URL(英語) | シード表が定めないカードには https://example.invalid/a1508-NNN/en.jpg を入れた | CSV の必須列のため。画像を確かめるケース（002・006・007）は、シード表の値を入れた |
| ステッカー区分（005B） | CSV で作ったあと、カード詳細(編集)画面の「ステッカー」に印を付けて登録した | CSV に列が無い |
| 画像を持たないカード（007） | カード新規登録画面で作った。007A の日本語のカード画像URLは DB で足した（E2E が作ったカード詳細だけ。lib/db_write.ts） | CSV は画像URL(英語)が必須。シード表も「DB へ直接設定する」としている |
| 更新日時（052） | DB で 2026-01-01 00:00:00（日本時間）に書いた（E2E が作ったカードだけ） | シード表のとおり、画面では指定できない |
| カード・マスタの番号 | DB をカード名(英)・マスタの日本語名で引いて控えた（読むだけ） | カード一覧の「カードID」列や、マスタの入力欄の名前を読む代わり |
| マスタ | 「マスタ種別甲」などの行は、無いときだけ登録し、あれば使う | シード表の「同じ名称の行は追加しない」。レアリティのコードは、開発環境の既存のコードと重ならない K1〜K3 にした |

## 気をつけること

- 052 の「カード全体の登録件数」は、共有の開発環境でほかの方がカードを登録すると変わる。そこで、検索の直前と直後に DB で読んで比べる。
- カード検索 API は、同じ条件の結果を Redis に置く。検索語に実行の印が付くので、前の回の結果が返ることは無い。
