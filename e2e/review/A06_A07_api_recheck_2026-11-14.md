# A06（MTGBuyer の API）・A07（買取の API）の見直し（2026-11-14・開発環境）

## 疎通の結果（11/14 昼・1回ずつ）
- API の入口は `/api/v1/…`（ケースの手順の `/api/admin/…` は `/api/v1/admin/…` に当たる）。`/api/admin/login.json` は 404。
- 送信元の IP では止められていない（誤ったログインIDで `POST /api/v1/admin/login.json` → 401）。
- 試験管理者（E2E が作った、ログインできるメンバー）で `POST /api/v1/admin/login.json` → **500「システムエラーが発生しました」**。誤ったログインID・パスワードなら 401 なので、認証は通ったあと、トークンを作るところで落ちている。
- デッキビルダーのログイン（`POST /api/user/login`、A15-04 の会員）も同じく **500**。どちらも同じ部品（JwtTokenService）でトークンを作る。
- 見立て: 開発環境のアプリに、トークンの署名の鍵（環境変数 JWT_SECRET。空のとき「JWT secret is not configured」で落ちる作り）が設定されていない。鍵が無いと、トークンを受け取る・確かめるのどちらもできないので、A06・A07 の API は、トークンが要らない一部を除いて開発環境では流せない。
- シード表の S-A06-02-AUTH-ENV などは「認証用署名シークレットを決まった試験用の値にし、API を再起動する」前提。環境の設定（共有）で、E2E からは設定できない。
