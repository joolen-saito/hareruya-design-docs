## 作り方
- 試験管理者（S-M05-09-ADM）: 受注管理を操作できるシステム管理者。ログインID・名前に実行の印（開発環境に手動テスト用の同じログインIDのメンバーがありうる）。
- 会員: ケースごとにフロントの会員登録で本会員を作る（メールの前半に実行の印）。受注情報検索を会員のメールアドレスで絞ると、そのケースの受注だけが出る。
- 商品: グッズ商品CSV登録＋在庫変更CSV＋別のメンバーの承認（pages/admin/f04_setup.ts の 商品を作って入庫する）。商品コード・商品名に実行の印。
- 受注: 会員でフロントの購入（pages/front/m05_front_order.ts の 会員が商品を注文する）。配送方法がゆうパックでなければ受注情報編集でゆうパックにする。
- 受注情報編集で入れるもの: 注文者・お届け先の都道府県／国／海外郵便番号・住所・電話・氏名（003・018・019・041・042）、配送方法（004 の B を EMS、020 をスムーズ店頭受取）、値引き（024）、送料・手数料（028）。
- 025: 注文のあとで商品登録編集で商品名を「変更後商品名」（印つき）に変える。
- 出荷指示リスト（002・010・016）: M05-21 と同じく、範囲に入るのが自分の受注だけであることを DB の参照で確かめてから生成する（自分以外が入れば生成せず止める）。
- 納品書: 「納品書印刷（日本語）」で開く新しい窓は HTML の納品書（PDF ではない）。ページ・注文番号・受取人署名・お届け先・送り主・会社・金額・明細を画面の文字で読む。

## DB で書き足したもの（E2E の行だけ。lib/db_write.ts。持ち主＝ケースの試験会員のメールアドレス）
- 全シード: 受注日時を 2026-09-29 10:00:00（日本時間）。ケースは受注日時を確かめない。
- 002・010・016: 出荷指示リストの生成で「出荷指示」に変わった対応状況を「注文受領」へ戻す。
- 010 の B: 注文者の都道府県を未設定。012: 配送先の都道府県を未設定。013: 配送先の国を未設定（どれも画面では必須）。
- 047 の NG: 明細の商品規格の紐付けを外す（画面では商品規格を持たない明細を作れない）。
- 007・008 の A: 会員のプレイヤーのスマレジ会員ID（SMR-50907-007・SMR-50907-008。ケースがこの値を確かめる→判定は条件付き）。008 の B: 会員からプレイヤーを外す。

## シードでの解釈
- 受注状態「注文受付」は開発環境の対応状況「注文受領」（ID 1）。都道府県「海外」は「日本国外」（ID 48）、国「日本」は「Japan」。
- 019: 会員は既定の住所（東京都）で登録し、受注情報編集で注文者の都道府県を大阪府にした。お届け先は東京都・Japan。
- 003・018: 海外郵便番号はシード表の値（003 は「任意の値」なので 12345）。
- 008: A・B は別の会員（B だけプレイヤーを外すため）。2人の受注を1つの検索結果に出すため、メールアドレスに共通する先頭「m0509-008-」で検索する（前の実行の 008 の受注も出ることがある。選ぶのはこの実行の2件だけ。注記「正本の外の補い」）。
- S-M05-09-DELIVERY: 配送方法・都道府県・国のマスタは書き換えず、使う値があることを DB の参照で確かめるだけ。
- 023（S-M05-09-BASEINFO）: 本店の適格請求書発行事業者登録番号は全員が使う店舗基本設定。開発環境の値は T1011101061821。ケースの開始時に T1234567890123 にし、終わるたびに元の値へ戻して DB で確かめる。
