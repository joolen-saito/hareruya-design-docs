## シードでの解釈（正本の外の補い）
- カードのマスタ（カードセット・カード・カード詳細）は全員が使うので新しく作らない。開発環境に既にある、商品の付いていないカード詳細を1商品に1件ずつ選んで、商品登録編集の「カード指定」で紐付ける（M04-03 と同じ）。カード名・Foil・カードセットはそのカード詳細の値のまま。〔カードID-…〕〔カード詳細ID-…〕はそのカード・カード詳細の番号。
- シード表の「カード商品CSV登録」は、グッズ商品CSV登録（スマレジ連携は0）＋カード指定で代えた。カード商品CSV登録は基準価格からスマレジ連携を決め、外部のスマレジへ送ることがあるため。
- 取込で作る1件目の商品規格は状態NM。状態NMの規格が無い商品（009B・009C）と、販売価格0の規格だけの商品（006D）は、残りの規格を商品規格一覧の「新規作成」で足したあと、取込の規格を画面で削除した。
- 店舗ID 1（シード表の「TC東京」）は、開発環境の店舗ID 1（本店）。在庫は本店・EC-CUBE へ入庫し、別の試験管理者が承認した（A17-05 の部品）。
- 商品コードに実行の印を付けた。商品名は付けない（API は商品IDで引き、期待結果が商品名そのものを見る）。
- 画面で作れない状態だけ、E2E の行に DB で書き足した（lib/db_write.ts の持ち主の確かめつき）:
  - 通常価格（003 の 123。商品規格登録編集画面に入力欄が無い）
  - 週間販売数量（店舗ID 1・EC販売分。001・002・011・016・024）
  - 商品画像・規格画像と規格画像の順位（001・002・014・016・020・021・023・025。決まったファイル名の画像を画面から置けない。画像の実体は置かない。API はファイル名だけを返す）
  - 006C の唯一の商品規格を削除済み（廃止・非表示）にする（画面で最後の1件は削除できない。シード表のとおり）
- 006A の「削除済みで商品レコードが無い商品」は、画面で登録して商品IDを控えたあと、商品登録編集の「削除」で消した（シード表のとおり。消すのはその実行で作った商品だけ）。
- S-A02-01-ENV・MASTER は開発環境に既にあるもの（API は EC-CUBE の /api）。

## 流したときに出そうなこと（アプリのソースから。期待結果は変えていない）
- 002: アプリは fileName に規格画像を先に入れる（規格画像が無いときだけ商品画像）。期待結果の fileName＝商品画像（main-…）と合わない見込み。
- 006・018: 該当なしの応答本文は code と errors（配列）の2項目。期待結果の「メッセージ（message）」の項目名と合わない見込み。
- 016・020: 新しいアプリのフロントに、「最近チェックした商品」のカード画像から goods_api/get_goods を呼ぶ作りが見当たらない。要求が出ずに落ちる見込み。
- foilFlg は真偽で返る（カード詳細の Foil の値）。ケースは値を見ない。

## 流すときに要るもの
- E2E_DB_WRITE=1。
- 消すシード（shared_env_delete_ok.tsv の仕分けが要る）: 投入方法に「削除」を含む23シード。実際に消すのは、その実行で作った商品規格（取込でできた余分の規格・ケースの「削除済み」の規格）と 006A の商品だけ。
- 1本だけで流すケース: 無し。全員が使う設定は書き換えない。
- カード詳細を1ケースで1〜4件使う（商品の付いていないものから選ぶ。開発環境に約250件）。流すたびに、そのカード詳細に試験用の商品が付く（カード検索などで見える）。
