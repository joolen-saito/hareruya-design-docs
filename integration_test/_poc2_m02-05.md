## §1. 全ケース共通前提
- **入口/認証**: 認証済み管理者がホーム画面 `GET /%eccube_admin_route%/` を開く（L240）。本カード専用のクエリパラメータ・フォーム入力は無い（L266）。未認証はホーム画面自体に到達できず、管理領域の認証要件に従いログイン等へ誘導される（L240,L275）。
- **参照系**: 本カードのレンダリングのみでは、お知らせ内容に関するデータベース更新やキャッシュ書き込みを行わない（L266）。セッション更新・Cookie 追加設定・業務監査ログ追加出力・業務トランザクションを持たない（L280,L289,L295,L298,L301）。
- **応答**: 成功時出力はお知らせカードを含むホーム画面 HTML で、情報iframe の `src` に設定 URL が出力される（L266）。以後の本文取得はブラウザが `src` に対して行う HTTP GET に委ねる（L247,L263）。
- **カード構造**: `#ec-cube-news` をルートとするカード。見出しはロケールにより「お知らせ」等となる翻訳キー由来のタイトル、本体は `name="information"` の情報iframe、フッタは固定高さの空領域（L237,L243）。
- **オラクル独立性**: 期待は正本（詳細設計HTML）由来で実装から独立。正本に無い挙動は断定せず「要実機確認」とする。実装との差は付帯表4で乖離＝バグ候補として扱う。
- **正本内部の留意**: L291 は「設計書上も具体的な URL を例示のために転記しない」とする一方、L226 は同梱 `eccube.yaml` の既定宣言として具体URLを明示している。本書は**既定値の出所を L226 の宣言に限って**参照し（§2 SEED-URL-DEFAULT）、差し替え検証には合成URLを用いる。両記述の整合は**要実機確認**（§5）。
