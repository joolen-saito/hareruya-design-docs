## §1. 全ケース共通前提
- **入口/認証**: 認証済み管理メンバーが管理画面コンテンツ管理から利用。ルートは一覧 `GET /{admin_route}/content/block`、新規 `GET|POST /{admin_route}/content/block/new`、編集 `GET|POST /{admin_route}/content/block/{id}/edit`、削除 `DELETE /{admin_route}/content/block/{id}/delete`（L331）。未ログインは管理画面共通のログイン誘導に従い、ログイン済みはアクセス制御リストがURLを許可するとき到達する（L390）。
- **端末種別**: 本機能は PC 端末種別を取得して対象に固定する（L320,L340,L361）。
- **言語**: 登録・編集画面は日本語/英語の単一選択を持ち、選択言語に応じた画面・ファイル拡張子で動作する（Excel 0210:L2581,L2584,L2603）。
- **CSRF**: 新規・編集はフォーム名 `block` と CSRF、削除は ID と CSRF を入力とする（L375）。
- **副作用**: データベース更新、ブロックファイルの作成・更新・削除、キャッシュ破棄、処理イベント通知、フラッシュメッセージ（L375）。属性はDB、テンプレート本文はファイルへ分けて保存し、**DB更新のあとにファイル書き出し**を行う（L369,L410）。
- **DB**: 永続化の正は ec-cube-enterprise（列名は移行先を主・現行名を括弧で添える）。承認ワークフローを介さず persist/flush で直接確定する（L383,L384）。
- **オラクル独立性**: 期待はオラクル（Excel優先・沈黙部は詳細設計HTML）由来で実装から独立。実装との差は付帯表4で乖離＝バグ候補として扱う。

- gen の期待は詳細設計HTMLの節verbatim（「観点 内容 表示要素 一覧は検索ボックスと…」等）が同一文で反復し、具体オラクルになっていなかった。→ 全行を **Excel優先＋詳細設計補完**の具体挙動へ差し替え、Excel 2シート（一覧／登録・編集）の処理概要・画面項目（0210:L2344-L2383／L2581-L2612）を期待の主根拠として各セルに `0210:Lxxx` を明記した。
- gen が **言語切替（日本語/英語）・.ja.twig/.en.twig・日英2ファイル作成・twig構文チェック・2本目の正規表現・各ヘルプ文言**を1件も持っていなかった（詳細設計HTMLが言語切替に沈黙し、コードを「任意・制約なし」と記すため）。→ Excel 0210:L2581-L2594,L2603-L2610 を一次オラクルとして RG-026〜031,036〜038・§3 DV-10,13,14,15 を新設した。
- gen が CSRF を `DELEG-STATIC`、未認証を `EXEC-UI` としていたが、CSRF は L375（新規・編集はフォーム名 block・CSRF／削除は ID と CSRF）により `EXEC-UI`（RG-049）へ、未認証は L390（共通ログイン誘導・ACL）により `DELEG-STATIC`（RG-050）へ是正。
- gen が数値バリデーション8件を `要判定` としていた点は維持（本機能に数値入力欄が無く、明示的否定文も無いため OUT にしない）。gen が文字列長・文字種を全て `要判定` としていたのは Excel 0210:L2606,L2608 に最大文字数255・2正規表現の明示があるため `EXEC-UI:DDT`（§3 DV-02〜DV-10）へ是正した。
- gen の `CONTRACT` 3件（HTTPステータス／URL／URL直接アクセスの総称）は、本機能が管理画面のHTML応答であり公開APIを扱わない（L372）ため、403/404/302 の具体条件を持つ実施行（RG-023〜025,048）へ吸収し、汎用の全ルート×ステータス直積は採らない。
