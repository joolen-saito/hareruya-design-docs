種別: batch（ポイント失効が近い会員に対し、失効予定日と失効予定ポイントを案内する通知メールを送信するコンソールバッチ。事前通知日数を2段階で設定し、各段階で対象会員を抽出して通知する。画面を伴わない機能仕様）。期待結果はバッチ終了ステータス・標準出力（開始/完了）・メール送信操作の有無など、API/統合レイヤ（コマンド起動）で観測できる結果で判定する。**期待結果は仕様（正本md・観点表・基本設計）由来**とし、実装の現挙動・終了コード実値・出力メッセージ文言・メール本文/件名/ヘッダの内容をオラクル化しない（オラクル独立性）。pf-eccube3リバース＝基本設計・観点表を上位オラクルとし、乖離は付帯表4に出す。**メール送信系は送信操作・送信有無までを期待値にし、本文・件名・宛先・実受信は手動／別機能委譲（メールテンプレート管理を正とする）**。TSV は既存IT casesの10列に実施管理欄（実施者・実施日・結果・失敗理由）を加えた14列固定。E2E固有情報（コマンド/根拠・自動化区分・仕様根拠・シード・不具合候補）は TSV 後の付帯表に `テストID` で対応づける。Playwright は本リポジトリでは実行しない（構造参考のみ）。未確定の判定・閾値・内部挙動は `要実機確認`。

## 起動口（コンソールコマンド）の特定状況：実装済み（コマンド実在）

本機能の起動口は刷新先 `ec-cube-enterprise` に実装済みであることを `#[AsCommand]` の grep で確認した。

- コマンド名: `eccube:customer:point-expire-notification`（`src/Eccube/Command/PointExpireNotificationCommand.php:25`、`#[AsCommand(name: 'eccube:customer:point-expire-notification', description: 'ポイント有効期限通知バッチ')]`）。引数は取らない。
- 通知本体: `Eccube\Service\Admin\Customer\PointExpireNotificationAction::handle()`（`src/Eccube/Service/Admin/Customer/PointExpireNotificationAction.php:33`）。設定の事前通知日数2段階（`eccube_point_expire_prior_1`／`eccube_point_expire_prior_2`、同:35-38）ごとに、失効予定日＝現在日＋日数（同:41）を求め、`DtbPointHistoryRepository::getPlayersForNotificationPointExpire()`（同:42）で対象会員を抽出し、失効予定ポイント＝`min([保有ポイント, 付与+利用の集計, 対象ポイント])`（同:46-50）を算出して `MailService::sendPointExpireNotificationMail()`（同:52／`src/Eccube/Service/MailService.php:1090`）で通知メールを送信する。
- ただし Playwright の `request` ではコンソールバッチを直接起動できない（起動口は実機/シェル依存）。区分は `E2E自動化(API/統合)` とし、コマンド名は実在根拠で確定する一方、spec では `bin/console` 実行が実機依存のため `test.fixme`（理由付き）で残す前提とする（コマンド未特定ではなく起動手段依存）。
- 正本md の利用者視点の入口は現行（pf-eccube3）コマンド文字列 `customer:batch pointExpireNotification` を記載するが、刷新先の実コマンド名は `eccube:customer:point-expire-notification` であり差異がある（付帯表4-1）。本書のコマンド根拠は刷新先の実在コマンドで確定する。
- メール本文・件名・宛先・ヘッダの内容検証、および実メール送受信は本機能の範囲外（正本md「本書で扱わないこと＝通知メールの本文・件名（メールテンプレート管理を正とする）」md:28）であり、`手動`／`対象外`（別機能委譲）に分類する。
