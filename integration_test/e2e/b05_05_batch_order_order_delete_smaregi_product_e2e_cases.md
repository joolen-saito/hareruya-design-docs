種別: batch（手続きが完了した店頭受取注文を抽出し、スマレジ側商品を削除する連携を行うコンソールバッチ。画面を伴わない機能仕様）。期待結果はバッチ終了ステータス・標準出力（開始/完了・処理件数）・削除連携の有無・スマレジ削除フラグ（`smaregi_del_flg`）の反映など、API/統合レイヤ（コマンド起動）で観測できる結果で判定する。**期待結果は仕様（正本md・観点表）由来**とし、実装の現挙動・終了コード実値・出力メッセージ文言・抽出ステータスの内部値・非同期ワーカーの実装をオラクル化しない（オラクル独立性）。pf-eccube3リバース＝基本設計・観点表を上位オラクルとし、乖離は付帯表4に出す。TSV は既存IT casesと同一の 10 列固定。E2E固有情報（コマンド/根拠・自動化区分・仕様根拠・シード・不具合候補）は TSV 後の付帯表に `テストID` で対応づける。Playwright は本リポジトリでは実行しない（構造参考のみ）。未確定の判定・閾値・内部挙動は `要実機確認`。

## 起動口（コンソールコマンド）の特定状況：実装済み（コマンド実在）

本機能の起動口は刷新先 `ec-cube-enterprise` に実装済みであることを `#[AsCommand]` の grep で確認した。

- コマンド名: `eccube:smaregi:otc:delete`（`src/Eccube/Command/SmaregiOtcDeleteCommand.php:39`、`#[AsCommand(name: 'eccube:smaregi:otc:delete', description: '店頭受取注文スマレジ商品削除バッチ (MessengerJob を enqueue する)')]`）。オプションは `--order-id`（単一受注指定・:54）／`--limit`（一括上限・既定100・:55）。
- 削除対象抽出: `Eccube\Repository\OrderRepository::getDeleteSmaregiProduct()`（`src/Eccube/Repository/OrderRepository.php:856`）。`OrderStatus IN (CANCEL, DELIVERED, PASSED)` AND `smaregi_code IS NOT NULL` AND `smaregi_del_flg = false`、`id ASC`、`setMaxResults($limit)`。
- 連携本体（非同期）: バッチは受注1件ごとに `SmaregiOtcDeleteDispatcher::dispatch()`（`src/Eccube/Service/Smaregi/Otc/SmaregiOtcDeleteDispatcher.php`）で MessengerJob を enqueue するのみ。実削除（`DELETE /pos/products/{productId}`）と `smaregi_del_flg` の ON 更新は `SmaregiOtcDeleteService::delete()`（同 `SmaregiOtcDeleteService.php:92-107,135-138`）が Messenger ワーカー上で消化する。
- Playwright の `request` ではコンソールバッチを直接起動できない（起動口は実機/シェル依存）。区分は `E2E自動化(API/統合)` とし、コマンド名は実在根拠で確定する一方、spec では `bin/console` 実行が実機依存のため `test.fixme`（理由付き）で残す前提とする（コマンド未特定ではなく起動手段依存）。
- 削除連携の最終結果（外部スマレジ側商品の削除連携完了）は非同期ワーカーの消化を前提とするため、バッチ単体では完結しない（付帯表4-3）。当該観測は `要実機確認`。なお `smaregi_del_flg` の ON 反映はDB内部値であり、E2E主判定にはせずIT層のDB副作用検証で担保する。
