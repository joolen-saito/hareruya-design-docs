種別: batch（店頭注文番号テーブル `dtb_waiting_number` の全レコードを削除し、採番カウンタ `dtb_waiting_number_counter`〔現行は `dtb_waiting_number` の AUTO_INCREMENT〕を初期化して、次回の店頭注文番号を最初の番号から再採番できる状態にするコンソールバッチ。抽出条件による絞り込みはなくテーブル全体が対象。画面を伴わない機能仕様）。期待結果はバッチ終了ステータス・標準出力（開始/完了・エラー）・DB更新結果（店頭注文番号テーブルの全削除／採番カウンタ初期化）など、API/統合レイヤ（コマンド起動）で観測できる結果で判定する。**期待結果は仕様（正本md・観点表）由来**とし、実装の現挙動・終了コード実値・出力メッセージ文言・採番カウンタの内部初期値（0/1）・トランザクション粒度をオラクル化しない（オラクル独立性）。pf-eccube3リバース＝基本設計・観点表を上位オラクルとし、乖離は付帯表4に出す。TSV は既存IT casesと同一の 10 列固定。E2E固有情報（コマンド/根拠・自動化区分・仕様根拠・シード・不具合候補）は TSV 後の付帯表に `テストID` で対応づける。Playwright は本リポジトリでは実行しない（構造参考のみ）。未確定の判定・挙動は `要実機確認`。

## 起動口（コンソールコマンド）の特定状況：実装済み（コマンド実在）

本機能の起動口は刷新先 `ec-cube-enterprise` に実装済みであることを `#[AsCommand]` の grep で確認した。

- コマンド名: `eccube:order:truncate-waiting-number`（`src/Eccube/Command/TruncateWaitingNumberCommand.php:25`、`#[AsCommand(name: 'eccube:order:truncate-waiting-number', description: '店舗注文番号初期化')]`）。引数は取らない。**正本mdが記載する起動コマンド `order:batch truncateWaitingNumber`（L59,67）とは綴りが異なる**（現行 pf-eccube3 のコマンド体系。刷新先は専用コマンドへ変更）＝乖離（付帯表4-1）。TSV・付帯表は実装の実効コマンド名に統一する。
- 初期化本体: `Eccube\Service\Admin\Order\TruncateWaitingNumberAction::handle()`（`src/Eccube/Service/Admin/Order/TruncateWaitingNumberAction.php:34`）。`DtbWaitingNumberRepository::truncateWaitingNumber()`（`src/Eccube/Repository/DtbWaitingNumberRepository.php:37-41`＝`TRUNCATE TABLE dtb_waiting_number`）／`DtbWaitingNumberCounterRepository::truncateWaitingNumberCounter()`（`src/Eccube/Repository/DtbWaitingNumberCounterRepository.php:69-73`＝`TRUNCATE TABLE dtb_waiting_number_counter`）で削除し、店舗（`BaseInfo`）ごとに採番カウンタを `current_value=0` で再作成する（同Action:44-49）。
- ただし Playwright の `request` ではコンソールバッチを直接起動できない（起動口は実機/シェル依存）。区分は `E2E自動化(API/統合)` とし、コマンド名は実在根拠で確定する一方、spec では `bin/console` 実行が実機依存のため `test.fixme`（理由付き）で残す前提とする（コマンド未特定ではなく起動手段依存）。
- 結果のUI観測（整理番号モニタ等の店頭注文番号表示）は、本機能の正本mdが「整理番号モニタ画面（画面側の設計を正とする）」「店頭注文番号の採番そのもの（店頭販売・受注処理を正とする）」として**本書で扱わない**と明記しているため、UI観測・再採番観測は別機能委譲＝`手動`（要実機確認）に分類する。
