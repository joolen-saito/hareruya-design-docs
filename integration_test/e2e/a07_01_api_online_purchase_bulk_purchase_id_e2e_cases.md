本機能は画面を伴わない機能仕様（オプションマスタのまとめ買取商品IDの設定値を返すJSON API・GET参照系・パラメータなし）であり、**両レイヤで網羅**する。本APIはブラウザ向け画面を持たず（正本md「対象はJSON APIエンドポイントであり、ブラウザ向けの画面を持たない」）、結果が管理画面に現れる範囲も無いため、**UIレイヤ＝0、API/統合レイヤ中心**で分類する。API/統合レイヤ＝Playwright `request`（APIRequestContext）でエンドポイントへ`jwt-token`ヘッダ付きGET送信し、HTTPステータス・応答本体（単一string値）・認証拒否・冪等性で判定する。

**期待結果は仕様（設計書・観点表・基本設計）由来**とし、実装のレスポンス形・型・HTTPライブラリ既定値を期待値に流用しない（オラクル独立性）。pf-apiの正本mdは現行（旧システム）のリバース設計であり、正本md「リニューアル移行時の扱い」が**挙動は現行（pf-api）を正・DB関連はec-cube-enterpriseを正**と定める。刷新先 ec-cube-enterprise との乖離（エンドポイントパスの`/api/v1`プレフィックス・認可方式・設定未設定時の応答〔現行500相当失敗⇔移行先200空文字列〕等）は**正本mdの「挙動は現行pf-apiを正」と観点表を上位オラクル**として扱い、付帯表4（不具合候補／移行差異／要確認）に出す。実装からは位置情報（APIパス・メソッド・認可属性）のみを `file:line` 根拠で取得し、取れないものは `要実機確認`。送信先パスは実装の実効パス `GET /api/v1/admin/optionBulkPurchaseId.json`（`OptionController.php:35`）に統一し（テストが実在経路へ届くため）、合否は正本md/観点表の意味（正常取得＝設定値文字列＋200／認証不備＝認証拒否で正常取得200とならない／設定未設定＝現行pf-api基準で設定値の参照が例外となりHTTP 500相当の失敗）で判定する。設定が無い場合の応答は正本mdが「挙動は現行（pf-api）を正とする」と定めるため**現行pf-api基準（設定値の参照で例外＝HTTP 500相当失敗）を期待値**とし、刷新先実装（ec-cube）の `??
