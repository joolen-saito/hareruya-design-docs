# m08-06_admin_customer_point（会員管理_ポイント付与・ポイント履歴） E2Eテストケース

元設計: `function_spec_html_preview/pf-eccube3/m08-06_admin_customer_point.html`（正本 `functions/pf-eccube3/m08-06_admin_customer_point.md`）

テスト観点: `integration_test/integration-test-viewpoints.md` ／ 既存IT: `integration_test/m08_06_admin_customer_point_it_cases.md`（母集合 計90観点行）

期待結果は画面表示・遷移・URL・履歴一覧での間接確認などブラウザで観測できる結果で判定する。**期待結果は仕様（設計書・観点表・基本設計）由来**とし、実装/POM由来の表示文言（messages.ja.yaml の trans 値・Form 制約）をオラクル化しない。設計は pf-eccube3（HareruyaEcプラグイン）由来のリバースであり、刷新先 ec-cube-enterprise に同一画面（`admin_customer_point_select` / `admin_customer_point_history` / `admin_customer_point_update`）が実在するため E2E 化した。設計と実装の食い違いは付帯表4（不具合候補）に出し、テストは仕様どおりに書く。TSV は既存IT casesと同一の 10 列固定。E2E固有情報は TSV 後の付帯表に `テストID` で対応づける。Playwright は本リポジトリでは実行しない（構造参考のみ）。未検証セレクタは `要実機確認`。

## 関連ID対応概要

| 関連ID | 本機能でのE2E確認範囲 |
|--------|------------------------|
| IT-25 | 種別選択/履歴確認画面のUI部品（種別カード・付与フォーム・履歴一覧・注文番号列・ポイント残高）・種別ごとの履歴表示（付与/利用）・HTTPステータス（404） |
| IT-03 | 画面遷移（会員編集→種別選択→履歴確認、付与成功→履歴画面、検証失敗→履歴画面再表示） |
| IT-13 | URL直接アクセス（未ログイン誘導・存在しない会員ID） |
| IT-22 | 必須（ポイント増減量）・数値・相関（残高0未満不可）・DB相関（当該会員が持たない注文番号＝異常022／当該会員が保有する注文番号＝正常012）。注文番号の桁数（8桁）は設計「入力項目」に定義が無くForm Regex由来＝オラクル混入のため自動化対象外（付帯表4 #7・要確認） |
| IT-15 | 未認証ガード・CSRF（フレームワーク内部）・保有ポイント（間接） |
| IT-26 | ポイント履歴追加の間接確認（一覧表示）。DB原値・更新値・同時更新は手動/間接 |
| IT-23 | DB検索（本機能は検索を行わない＝対象外） |
| IT-20 | ログ出力抑止（Cookie値・セッションID）＝ブラウザ観測外 |
