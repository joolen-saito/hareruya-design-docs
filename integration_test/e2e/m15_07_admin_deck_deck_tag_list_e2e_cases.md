## 最重要前提：刷新先に「デッキタグ一覧」専用画面は存在しない（screenExists=false）

本設計書は現行 pf-eccube3 のカスタムプラグイン `HareruyaEc` が提供する専用画面 `deckTag.twig`（一覧＋モーダル編集＋件数/並び順ドロップダウン＋ページネーション＋行単位の利用中チェック付き削除）のリバースである。

刷新先 ec-cube-enterprise を全文調査した結果、**この専用画面・専用ルート（`/{admin_route}/deckTag`・`admin_decktag_sort`・`admin_decktag_update`・`admin_decktag_delete`）は存在しない**。`mtb_deck_tag` エンティティ（`src/Eccube/Entity/Master/MtbDeckTag.php`）はコア標準として取り込まれているが、デッキタグの管理は**汎用「MTGマスターデータ管理」画面**（`admin_data_mtg_master_data`＝`GET|POST /{admin_route}/data/mtg_master_data`、`MtgMasterDataController.php:333`、テンプレート `@admin/Data/mtg_master_data.twig`）の `entity=deck_tag` 選択により行う。ラベル `admin.deck.deck_tag_list:「デッキタグ一覧」`（messages.ja.yaml:4036）は側メニュー `eccube_nav.yaml:343-346`（`deck_management > deck_tag_list`、`url: admin_data_mtg_master_data`／`param: { entity: deck_tag }`）から参照されており、**孤立リソースではなく、汎用マスターデータ画面へ意図的に集約された導線**である。すなわち専用画面の汎用画面への置換は実装都合の偶然ではなく刷新後の設計判断（基本設計＝刷新後要件）として確認できる。

刷新先の代替画面は設計書の画面と UI・挙動が根本的に異なる:
- エンティティ選択ドロップダウン（件数/並び順ドロップダウンではない）
- 全行インラインの一括テーブル編集（Bootstrap モーダル `#editModal` は無い）
- 単一「登録」ボタンで全行を一括保存し成功フラッシュ「保存しました」（`admin.common.save_complete` messages.ja.yaml:1398）。**行の全値を空にすると当該行を削除**（`MtgMasterDataStoreAction.php:75-79`）
- 行単位の削除ボタン・利用中（デッキ/アーキタイプ）チェック・確認ダイアログ・ページネーション・並び順ドロップダウン・更新時 ID 不整合 404 は**いずれも存在しない**
- 必須文字列が空の新規行は**エラーを出さず黙って登録スキップ**（`MtgMasterDataStoreAction.php:65-67`）。表示順（sort_no）の重複カスタム制約も無い

したがって設計書の各画面要素・分岐の大半は刷新先で再現不能であり `対象外/要確認`（理由付き）に分類する。観測可能な「デッキタグ行の表示・インライン編集保存・新規追加・未認証ガード」のみ、代替画面（`admin_data_mtg_master_data?entity=deck_tag`）に対する `E2E自動化` として残す（期待結果は刷新後要件由来）。設計書と刷新先の食い違いは付帯表4（不具合候補）に列挙する。

> **要確認（上位オラクルの確定）**: 本設計書は挙動面を「現行 pf-eccube3 実装を正」と明記している（正本 `functions/pf-eccube3/m15-07_admin_deck_deck_tag_list.md`）。本ケース表は刷新先 ec-cube-enterprise の汎用マスターデータ画面を「刷新後要件＝上位オラクル」と仮置きして分類しているが、これは**移行方針の決定がまだ確認できていないための暫定判断**である。専用デッキタグ画面（`/deckTag`・モーダル・ページング・並び順ドロップダウン・利用中削除ガード・更新時404）が「意図的な汎用画面集約」なのか「機能欠落（要復元）」なのかが未確定のため、後者と確定した場合は付帯表4・付帯表5で `対象外` とした節は**「正典未実装（要復元）／カバー保留」へ再分類**する必要がある。したがって付帯表5の「未カバー0」は**代替画面で観測できる範囲に限定した暫定値**であり、設計書（現行=正）基準での網羅判定としては未確定（要確認）である。
