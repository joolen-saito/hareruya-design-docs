## 重要前提：刷新先に「該当の専用設定画面」が存在しない（screenExists=false）

本機能は pf-eccube3 の「店舗設定配下の利用規約設定画面」（`GET/POST /{admin_route}/setting/shop/customer_agreement`・単一の「利用規約」`textarea`・`NotBlank`・送信ボタン「規約を登録」・保存先 `dtb_help.customer_agreement`）である。**刷新先 ec-cube-enterprise には当該ルート・画面・`dtb_help`/`customer_agreement` 列がいずれも存在しない**（grep 確認: `src/Eccube` 配下に `customer_agreement` のヒット 0／`Controller/Admin/Setting/Shop/` に該当 Controller なし）。

利用規約本文の編集は、ページ管理（コンテンツ管理）側の固定ページ編集へ委譲されている。`src/Eccube/Resource/template/admin/Content/page_edit.twig:18-21` が `?return=agreement` のとき `page_title = 'admin.setting.shop.agreement_setting'`（=「利用規約設定」 messages.ja.yaml:2777）／ナビ `['setting','basic_info','shop_agreement']` を出すルート `admin_content_page_edit`（`PageController.php:90`）が移行先である。これは別機能 **m09_04（admin_content_content_page＝ページ管理）** の画面そのものであり、入力UIも `textarea`(NotBlank) ではなく **Ace エディタ（`#editor` / `tpl_data`）を中心としたページ編集フォーム** に全面置換されている。なお当編集フォームの本体は `MainEditType`（getBlockPrefix=`main_edit`。`Form/Type/Admin/MainEditType.php:278`）であり、本文 hidden は `#main_edit_tpl_data`（`page_edit.twig:70` で実装確定・創作でない）。`PageType`（getBlockPrefix=`admin_page`）は同画面の**レイアウト副フォーム**のみで、本文セレクタの根拠ではない（以前の「`admin_page` vs `main_edit` 不一致＝要確認」は誤認識のため訂正）。

そのため本書は SKILL「刷新先に画面が存在しない場合は screenExists=false とし、E2Eは対象外/要確認で理由明記（創作しない）」に従い、**pf-eccube3 の専用画面に対する E2E は原則 対象外/要確認**とする。観測可能な範囲（移行先のページ編集画面＝m09_04 を経由した利用規約ページ本文編集）の最小限スモークのみを `要実機確認` として残し、entry route（利用規約ページ page id=19 への到達導線）が未確定、かつ本文編集可否が要確認（既定ページ=editor readOnly。不具合候補#6）のため **spec では全件 `test.fixme`** とする（DOM id は `main_edit` で確定済み・不一致なし）。利用規約本文編集そのものの正式な E2E は **m09_04 の E2E に委譲**するのが妥当である（付帯表4 参照）。

## 列の対応（E2E固有→納品10列への落とし込み）
- `テストID`＝E2EケースID（`E2E-M10-03-NNN`）。`I/FID`・`テスト観点`は観点表に一致。
