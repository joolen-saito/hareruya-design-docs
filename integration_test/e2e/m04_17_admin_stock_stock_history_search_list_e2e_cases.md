**重要（設計源と刷新先の乖離）**: 本機能の正本は pf-eccube3（HareruyaEc プラグイン）のリバース設計であり、刷新先 ec-cube-enterprise の実装とは画面・URL・文言が大きく異なる。基本設計・観点表を上位オラクルとし、乖離は付帯表4（不具合候補）に列挙する。

- **正典（オラクル）側のURL**: 入口 `GET /%eccube_admin_route%/product/history`、検索 `POST /%eccube_admin_route%/product/history/search/1`、ページ送り `…/product/history/search/{page_no}`（設計書「利用者視点の入口」由来）。期待結果（画面挙動・遷移・文言）はこの正典仕様を不変のオラクルとする。
- **刷新先（実行系）側のURL**: E2Eが実際に走る ec-cube-enterprise では同画面が `admin_stock_history`（`GET,POST /%eccube_admin_route%/product/stock/history`、ページ `…/page/{page_no}`、件数 `…/page/{page_no}/count/{page_count}`、Twig `@admin/Stock/history.twig`、Form `StockHistoryType` getBlockPrefix=`admin_stock_history`）として存在する。
- TSVの操作手順・spec の `toHaveURL` で参照する `/product/stock/history` 系URLは**実行系での画面同定（ナビゲーション錨）**であってオラクル（合否判定の根拠）ではない。「同一画面に留まる／別画面（ログイン）へ遷移する」という遷移判定そのものが設計書由来のオラクルであり、URL文字列は正典との乖離（付帯表4 #1）を承知のうえで実行系に合わせている。正典URL `/product/history` との不一致は付帯表4 #1 に明記し監査可能とする＝`要確認`（実行系URLが将来正典へ寄せられるか）。

刷新先には「在庫履歴検索/一覧」画面が上記ルートで存在し、セレクタは導出できた（screenExists=true）。ただし pf-eccube3 の「価格変更履歴一覧の併記」は刷新先に存在せず（在庫履歴単独＋欠品検索）、価格履歴一覧は刷新先では本画面に未移行＝乖離（付帯表4 #1）。正典では価格変更履歴一覧は本機能の中核（2表表示）であるため、当該挙動は網羅マトリクスで**未カバー（乖離理由付き）**として扱う（後述の付帯表5）。
