# バッチ インフラ — S3のファイルを自サーバに転送 E2Eテストケース

元設計（正本md）: `functions/pf-eccube3/batch_s3_file_sync.md` ／ 機能詳細HTML: `function_spec_html_preview/pf-eccube3/batch_s3_file_sync.html`

テスト観点: `integration_test/integration-test-viewpoints.md` ／ 既存IT: `integration_test/batch_s3_file_sync_it_cases.md`（母集合 計90観点行・関連ID IT-16/IT-27/IT-24/IT-17/IT-33/IT-30/IT-12）

種別: batch（インフラバッチ。cronで毎分〔`* * * * * /usr/local/bin/file_sync_command`〕起動し、S3バケットの3プレフィックス〔テンプレート既定・テンプレートユーザーデータ・HTMLユーザーデータ〕をアプリケーションサーバのローカルディレクトリへ同期する。S3を基準にローカルを一致させ、ローカルの余分なファイルは削除する〔タイムスタンプ厳密一致で差分判定〕。ロックファイルで多重起動を防止し、変更があった経路のみ所有者・権限を設定してキャッシュをクリアする。開始・終了・ロック取得/解放・変更ファイル・多重起動をローカルログとCloudWatchへ記録する。画面もHTTP APIレスポンスも持たないインフラバッチ）。期待結果はジョブ起動・同期結果（ローカル反映・余分削除・多重起動防止）・キャッシュクリア後のフロント反映・ログで判定する。**期待結果は仕様（正本md・観点表）由来**とし、実装の現挙動・終了コード実値・ログ文言をオラクル化しない（オラクル独立性）。pf-eccube3リバース＝正本md・観点表を上位オラクルとし、乖離は付帯表4に出す。既存IT casesの90行は機械生成の汎用テンプレート由来（画面・JSON・フォーマット定義・最大長検証などの本機能に存在しない観点を多く含む）であり、正本mdの実挙動へ写像したうえで、本機能に該当処理がない観点は理由付きで `対象外`、サーバ内部（ローカルファイル属性・権限・ログ）でしか観測できない観点は `手動/間接` に分類する。TSV は既存IT casesと同一の 10 列固定。Playwright は本リポジトリでは実行しない（構造参考のみ）。未確定の起動口・内部挙動は `要実機確認`。

## 起動口（cron/シェル）の特定状況：実機/コンテナ依存（本リポジトリに実装なし）

本機能の起動口は ec-cube-enterprise のコンテナ用cron定義（`dockerbuild/eccube/crontab`）と同期スクリプト（`dockerbuild/eccube/file_sync_command.sh`＝`/usr/local/bin/file_sync_command`）であり、`bin/console` コマンドではない。当該スクリプト/cron定義は本リポジトリに未取込のため、`file:line` 根拠は取得できず、コマンド名・cron定義は正本md記載（正本md L54,62／L133 等）を根拠とし、実装詳細は `要実機確認`。

- 起動口: cron 毎分（`* * * * * /usr/local/bin/file_sync_command`・正本md L54,56／利用者視点の入口）。Playwright の `request` からコンソール/シェルバッチを直接起動できない（起動口は実機/シェル/コンテナ依存）ため、区分は `E2E自動化(API/統合)`（シェル手動起動＋同期結果/フロント反映観測）とし、spec は `test.fixme`（理由「cron/シェル起動は実機依存」）で残す。
- ジョブ起動・3経路同期・S3基準の余分削除・多重起動防止（ロック）・変更なし時の未処理終了・キャッシュクリア後のフロント反映は、ジョブ実行後に同期結果/フロント表示を観測できるため `E2E自動化(API/統合)`（要実機確認）。
- 所有者・権限設定（サーバ内部のファイル属性）・ログ記録（ローカルログ/CloudWatch）・秘匿値のログ非出力・エンドポイント切替（環境変数）は、サーバ内部/内部ログ/環境設定の検査に依存するため `手動/間接`（一部は観測外＝対象外）。
