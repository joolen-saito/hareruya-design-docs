# A17-03（ポイント付与） E2Eテストケース

元設計md（正本一次／pf-eccube3リバース）: `functions/pf-eccube3/a17-03_api_other_point_granter.md`
機能詳細HTML: `function_spec_html_preview/pf-eccube3/a17-03_api_other_point_granter.html`

テスト観点: `integration_test/integration-test-viewpoints.md` ／ 既存IT: `integration_test/a17_03_api_other_point_granter_it_cases.md`（母集合 計38観点行）

本機能は**ブラウザ向けの画面を持たない**機能仕様（PointGranter（任意門）からの呼び出しを受け、スマレジ取引APIへ中継し、取引更新（`transaction_upd`）時に会員ポイントを付与してポイント履歴を登録する JSON API。正本md「対象はJSON APIエンドポイントであり、ブラウザ向けの画面を持たない」）であり、**API/統合レイヤ単独で網羅**する。Playwright `request` で `POST /admin_api/point_granter` へ送信し、HTTPステータス・レスポンス本文で判定する。更新副作用（会員ポイント残高の加算・ポイント履歴の登録）は永続化先テーブルを直接DB照合（DB副作用観測）して判定する。本機能は画面を持たないため、別機能（管理画面）の表示は合否条件にしない。**自動化(UI)は0**とする。

**期待結果は仕様（正本md・観点表・基本設計）由来**とし、実装のレスポンス形・スマレジ実装挙動・HTTPライブラリ既定値・Entity制約を期待値に流用しない（オラクル独立性）。pf-eccube3リバースの正本mdを上位オラクル、観点表（基本設計）と食い違う箇所も上位オラクルとして扱い、乖離は付帯表4に出す。実装からは位置情報（APIパス・メソッド・認証方式・DB永続先）のみを `file:line` 根拠で取得し、取れないものは `要実機確認`。TSV は既存IT casesの10列に実施管理欄（実施者・実施日・結果・失敗理由）を加えた14列固定。Playwright は本リポジトリでは実行しない（構造参考のみ）。

**スマレジ外部連携の扱い**: 入力検証（必須ヘッダ・本文の欠落）は中継前に判定されるため外部依存なしで自動化できる。一方、中継成功（HTTP 200・`result` キー）以降のパス（成功応答・会員特定・ポイント付与・履歴登録・会員未特定時のスルー）はスマレジ取引APIの応答を要するため、`E2E自動化(API/統合)（要実機確認）`（スマレジ・サンドボックス等で中継応答を供給する前提・環境ガード）とする。スマレジ実環境（外部POS）への実連携・中継応答の異常（`result` キー欠落の強制）・例外注入・同時実行・タイムアウトは `手動（要実機確認）` に置き、自動化したことにしない。

**更新系の補正**: 本APIは取引更新時に会員ポイント残高を加算（更新）し、ポイント履歴を登録（登録）する更新系APIである。既存IT casesの対象外観点表は「登録（IT-23, IT-26）本機能に登録処理がないため」「更新（IT-05, IT-23, IT-26）本機能に更新処理がないため」「DB操作（IT-08）本機能に更新処理がないため」と**誤って除外**している。これを上位オラクル（正本md 処理フロー#5・副作用節・DBカラム節・DB操作節）に照らして補正し、DB更新（IT-26）・例外時のロールバック挙動（IT-05・正典未定義のため固定期待にせず要実機確認）を設計書補完ケースとして追加した（母集合外・別管理）。当該誤分類は付帯表4#5に記録する。
