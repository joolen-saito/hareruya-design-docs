# A17-02（関連記事） E2Eテストケース

元設計md（正本一次）: `functions/pf-api/a17-02_api_other_article_related.md`
機能詳細HTML: `function_spec_html_preview/pf-api/a17-02_api_other_article_related.html`

テスト観点: `integration_test/integration-test-viewpoints.md` ／ 既存IT: `integration_test/a17_02_api_other_article_related_it_cases.md`（母集合 計38観点行）

本機能は画面を伴わない機能仕様（記事IDに関連する記事情報をJSONで返す参照系GET API）であり、**両レイヤで網羅**する。正本md「対象はJSON APIエンドポイントであり、ブラウザ向けの画面を持たない」ため結果が管理画面に現れる範囲も無く、**UIレイヤ＝0、API/統合レイヤ中心**で分類する。API/統合レイヤ＝Playwright `request`（APIRequestContext）でエンドポイントへGET送信し、HTTPステータス・レスポンス配列構造・フィールド型契約・共有度順の並び・関連なし時の404で判定する。

**期待結果は仕様（設計書・観点表・基本設計）由来**とし、実装のレスポンス形・型・HTTPライブラリ既定値を期待値に流用しない（オラクル独立性）。pf-apiの正本mdは現行（旧システム）のリバース設計であり、刷新先 ec-cube-enterprise との乖離（応答フィールドの型〔hasSame*〕・論理削除の除外有無・認可方式・無効パラメータ時の具体ステータス等）は**設計書/観点表を上位オラクル**として扱い、付帯表4（不具合候補／要確認）に出す。実装からは位置情報（APIパス・メソッド・処理位置）のみを `file:line` 根拠で取得し、取れないものは `要実機確認`。送信先パスは実装の実効パス `GET /article/related/{id}`（`ArticleController.php:81`、App配下に追加prefix無し）に統一し、合否は設計書の意味（関連記事の取得＝配列JSON＋200／関連記事なし＝404 Not Found／不正パラメータ〔欠落・0以下・非数値〕は正しい関連記事が取得されない＝正常取得200とならない）で判定する。仕様で固定される404は関連記事なし（結果が空）時のみであり、不正id・不正limit・型不正時の具体ステータスは要実機確認とする。TSV は既存IT casesと同一の 10 列固定。Playwright は本リポジトリでは実行しない（構造参考のみ）。
