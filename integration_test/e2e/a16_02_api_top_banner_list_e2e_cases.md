本機能は画面を伴わない機能仕様（言語コードを指定して設定済みトップバナー一覧を返すJSON API・GET参照系）であり、**両レイヤで網羅**する。本APIはブラウザ向け画面を持たず（正本md「対象はJSON APIエンドポイントであり、ブラウザ向けの画面を持たない」）、結果が管理画面に現れる範囲も無いため、**UIレイヤ＝0、API/統合レイヤ中心**で分類する。API/統合レイヤ＝Playwright `request`（APIRequestContext）でエンドポイントへGET送信し、HTTPステータス・レスポンス本文（配列構造・フィールド・型契約）・データ整合・該当なし時の404で判定する。

**期待結果は仕様（設計書・観点表・基本設計）由来**とし、実装のレスポンス形・型・プロパティ命名・HTTPライブラリ既定値を期待値に流用しない（オラクル独立性）。pf-apiの正本mdは現行（旧システム）のリバース設計であり、刷新先 ec-cube-enterprise との乖離（応答プロパティ命名 camelCase⇔snake_case・404本文形〔message⇔errors〕・404条件の設計書内不整合・`.json`余剰ルート・認可方式）は**設計書/観点表を上位オラクル**として扱い、付帯表4（不具合候補／要確認）に出す。実装からは位置情報（APIパス・メソッド・認可属性）のみを `file:line` 根拠で取得し、取れないものは `要実機確認`。送信先パスは実装の実効パス `GET /topBanners/{languageCode}`（`ContentController.php:87`）に統一し、合否は設計書の意味（正常取得＝設定済みトップバナーの配列JSON＋200／言語不存在・設定済みバナー0件＝404／応答プロパティは camelCase）で判定する。仕様で固定される404は「言語不存在」「設定済みバナー0件」のみであり、想定外クエリ・タイムアウト等の具体ステータスは要実機確認とする。設計⇔実装のプロパティ命名・本文・条件の差異は付帯表4でのみ一元管理し、TSV期待値に実装の現挙動を固定しない。TSV は既存IT casesの10列に実施管理欄（実施者・実施日・結果・失敗理由）を加えた14列固定。Playwright は本リポジトリでは実行しない（構造参考のみ。未検証は `要実機確認`）。
