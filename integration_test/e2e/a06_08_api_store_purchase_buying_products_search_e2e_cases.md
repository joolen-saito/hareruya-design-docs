本機能は画面を伴わない機能仕様（カード名から買取用商品情報を返すJSON API・参照系検索）であり、**両レイヤで網羅**する。本APIはブラウザ向け画面を持たず（正本md「対象はJSON APIエンドポイントであり、ブラウザ向けの画面を持たない」）、結果が管理画面に現れる範囲も無いため、**UIレイヤ＝0、API/統合レイヤ中心**で分類する。API/統合レイヤ＝Playwright `request`（APIRequestContext）でエンドポイントへ送信し、HTTPステータス・レスポンス階層構造・前方一致絞り込み・カードの索引付け・該当なし時の404で判定する。

**期待結果は仕様（設計書・観点表・基本設計）由来**とし、実装のレスポンス形・型・HTTPライブラリ既定値・Form制約を期待値に流用しない（オラクル独立性）。pf-apiの正本mdは現行（旧システム）のリバース設計であり、刷新先 ec-cube-enterprise との乖離（エンドポイントパス・HTTPメソッド・パラメータ位置・該当なし時の応答・カード索引付け・応答型・フィールド名・店舗コンテキスト等）は**設計書/観点表を上位オラクル**として扱い、付帯表4（不具合候補／要確認）に出す。実装からは位置情報（APIパス・メソッド・認可属性）のみを `file:line` 根拠で取得し、取れないものは `要実機確認`。送信先パスは実装の実効パス `POST /api/v1/search`（`BuyingController.php:99`）に統一し（テストが実在経路へ届くため）、合否は設計書の意味（正常取得＝買取商品情報JSON＋カード索引付け＋200／該当なし＝404 Not Found／前方一致検索／`%`・`_`はエスケープしてリテラル扱い／参照のみ・副作用なし）で判定する。設計書はメソッド `GET`・`name` をクエリパラメータ・該当なし `404` と定めるが、実装はメソッド `POST`・`name` をリクエストボディ・該当なし `200`（空 `cards`）で食い違うため、これらは付帯表4でのみ一元管理し、TSV期待値に実装の現挙動を固定しない（テストは仕様どおりに書き、実装が違えば落ちて検出する）。仕様で固定される404は該当なし時のみであり、name未指定・想定外項目・タイムアウト・DB障害時の具体応答は正典に定義が無いため期待値を固定せず要実機確認とする。TSV は既存IT casesと同一の 10 列固定。Playwright は本リポジトリでは実行しない（構造参考のみ）。
