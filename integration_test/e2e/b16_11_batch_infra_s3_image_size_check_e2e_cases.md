種別: batch（インフラバッチ。Step Functions により15分間隔で起動し、対象S3パス〔goods L/C/I・goods L/NUM・banner・product・set〕からファイル名とサイズの一覧を取得し、種別ごとの閾値〔商品サムネ250kB・オリジナル画像400kB・バナー500kB・商品画像400kB・絵文字5kB〕以上のファイルを検出、超過があれば画像ファイルサイズ超過アラートメールを通知する。画面もHTTP APIレスポンスも持たないインフラバッチ）。期待結果はジョブ終了ステータス・取得ファイル一覧・超過検出一覧・通知メール・ログなどで判定する。**期待結果は仕様（IT観点表・既存IT cases）由来**とし、実装の現挙動・閾値実装値・メール文言をオラクル化しない（オラクル独立性）。設計mdが存在しないため既存IT cases・観点表を上位オラクルとし、観測不能な観点（メール実受信・内部ログのみ）は理由付きで `手動`／`対象外` に落とす。TSV は既存IT casesの10列に実施管理欄（実施者・実施日・結果・失敗理由）を加えた14列固定。Playwright は本リポジトリでは実行しない（構造参考のみ）。未確定の起動口・閾値・内部挙動は `要実機確認`。

## 起動口（ジョブ）の特定状況：AWS実機依存（本リポジトリに実装なし）

本機能の起動口は AWS Step Functions（15分間隔）であり、`ec-cube-enterprise` のコンソールコマンドでも本リポジトリのソースでもない。刷新先ソース（Lambda/チェック実装）は本リポジトリに未取込のため、コマンド/エンドポイント/閾値の `file:line` 根拠は取得できず全項目 `要実機確認`。

- 起動口: AWS Step Functions（15分間隔・元設計HTML sheet-13／IT-B16-11-...-001）。Playwright の `request` から直接叩けないため区分は `E2E自動化(API/統合)`（ジョブ手動起動＋検出結果観測）とし、spec は `test.fixme`（理由「起動口＝AWS Step Functions実機依存」）で残す。
- 取得ファイル一覧・超過検出一覧・終了ステータスは、ジョブ実行後の実行結果/出力を検査すれば観測できるため `E2E自動化(API/統合)`（要実機確認）。
- 通知メールの宛先（From/To/CC/BCC）・件名・本文（URL/サイズ）・超過0件時の非送信は、外部メール経路への実送信/実受信に依存するため `手動`（メールキャプチャ/受信トレイ依存）。
