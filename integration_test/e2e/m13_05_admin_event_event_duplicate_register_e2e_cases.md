期待結果は画面表示・遷移・DB状態(間接)・URL・HTTPステータス等の観測可能な結果で判定する。**期待結果は仕様(設計書/観点表/基本設計)由来**であり、実装(ec-cube-enterprise)の現挙動を写さない（オラクル独立性）。実装からはセレクタ(file:line)のみを取得する。

Playwright は本リポジトリでは実行しない（未実行雛形）。セレクタ等のE2E固有情報は後述の付帯表に分離し、Twig由来の根拠が無いものは `要実機確認`。

**重要(仕様乖離)**: 本設計書は pf-eccube3 / HareruyaEc プラグインのリバースであり、刷新先 ec-cube-enterprise では複製ルート名・パス・送信ボタン文言・フォームプレフィックスが相違する（付帯表4）。E2Eは**到達(ナビゲーション)のため**実装ルート `/event/{id}/copy` を使うが、相違は不具合候補として管理し、テストの期待値は仕様どおりに保つ。

**オラクル独立性(入口URL)**: 入口の合否判定には実装ルート名(`/copy`)を期待値として固定しない。E2E-001 は「複製元の値を載せた新規登録画面へ遷移」を、URL一致ではなく**新規登録フォームの表示＋複製元の初期値が載ること**で判定する（設計の入口URLは `/duplicate` であり、`/copy` は実装由来のため）。保存後遷移先の `/{newId}/edit` は設計書「画面遷移(保存成功→編集画面)」由来のため期待値として用いる。

要確認(残課題): (1)エラー表示セレクタ `.invalid-feedback/.text-danger`(付帯表4#5)・日程一覧ブロックの限定セレクタは実機確認で確定する。(2)複製対象「全項目」の網羅はM13-02入力仕様へ委譲し、本機能では代表複数項目の複製元⇔複製新規同値比較で担保(E2E-002は部分カバー。残る店舗/会場/フォーマット/公開状態/バナーURL/賞品/備考/支払方法等の個別セレクタは要実機確認)。(3)検索条件セッション保持(E2E-070)/新規Cookie非設定(E2E-071)/送信ボタン文言(E2E-062)の自動化要否と実機文言確認。
