注記:
- 本機能は**画面を伴わない機能仕様（コンソールバッチ）**である。SKILL.md「両レイヤ網羅」に従い、**API/統合レイヤ（バッチ起動＋DB更新観測）** と **UIレイヤ（集計対象の在庫数を在庫検索一覧で観測）** に分けて網羅する。
- 期待結果は**仕様（正本md／基本設計＝移行先要件／観点表）由来**で判定する（オラクル独立性）。実装の現挙動・終了コードの実値・SQL構造を「実装がそうだから」で期待値にしない。位置情報（コマンド名・セレクタ・テーブル名）のみ実装由来。
- **終了ステータスはコード実値（0／非0）を期待値にしない**。正本md・観点表とも終了コードの実値を規定しない（正本md:106-114、viewpoints:434-437）。「正常終了として扱われること」「異常終了として扱われること」を観測し、コード値は断定しない。
- **出力方式は移行先（ec-cube-enterprise）を正典とし DB 方式で判定する**。正本md リニューアル移行表（正本md:41-44）が「集計結果を一時テーブル `dtb_weekly_stock_history_temp` へ INSERT し本テーブル `dtb_weekly_stock_history` へコピーする DB 方式。CSV 出力ではない」と明記する。現行（pf-eccube3）の CSV 出力は移行前挙動のため E2E 期待値にしない（CSV 関連の母集合行は DB 更新観測へ写像）。差異は付帯表4で管理する。
- **集計結果（週間在庫履歴）は管理画面に直接反映されない**（支店在庫移動リコメンドが消費する別機能データ）。よって UI レイヤは「**集計対象の入力条件（商品在庫の在庫数）の在庫検索一覧での確認**」に限定し、「バッチ結果の UI 観測」として扱わない。
- **コマンドは刷新先に実在**＝`eccube:update-weekly-stock-history`（`src/Eccube/Command/UpdateWeeklyStockHistoryCommand.php:33,35`）。よって API/統合レイヤは設計可能だが、**起動口（コンソール実行）と DB 観測が実機依存**のため spec では `test.fixme`（`要実機確認`）前提とし、区分は `E2E自動化(API/統合)（要実機確認）` とする。
- Playwright は本リポジトリでは実行しない。セレクタ・コマンド・自動化区分は後述の付帯表に分離する。根拠が取れないものは `要実機確認`。
