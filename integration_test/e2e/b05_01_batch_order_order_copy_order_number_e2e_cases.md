種別: batch（注文番号テーブルに採番された注文番号を受注（移行先`dtb_order`／現行`dtb_order_sub`）へコピーし、コピー対象のうち店頭受取注文についてはスマレジ用商品コード〔バーコード〕を生成・登録してスマレジへ商品・在庫を連携するコンソールバッチ。画面を伴わない機能仕様）。期待結果はバッチ終了ステータス・標準出力（開始/完了・エラー）・連携ジョブ登録・DB更新結果（注文番号／スマレジ用商品コード）など、API/統合レイヤ（コマンド起動）で観測できる結果で判定する。**期待結果は仕様（正本md・観点表）由来**とし、実装の現挙動・終了コード実値・出力メッセージ文言・スマレジ用コードの桁構成・対象抽出の内部条件をオラクル化しない（オラクル独立性）。pf-eccube3リバース＝基本設計・観点表を上位オラクルとし、乖離は付帯表4に出す。TSV は既存IT casesの10列に実施管理欄（実施者・実施日・結果・失敗理由）を加えた14列固定。E2E固有情報（コマンド/根拠・自動化区分・仕様根拠・シード・不具合候補）は TSV 後の付帯表に `テストID` で対応づける。Playwright は本リポジトリでは実行しない（構造参考のみ）。未確定の判定・閾値・内部挙動は `要実機確認`。

## 起動口（コンソールコマンド）の特定状況：店頭受取スマレジ連携サブバッチのみ実在／注文番号コピーの起動口は未特定（要実機確認・test.fixme前提）

本機能の起動口は刷新先 `ec-cube-enterprise` に `#[AsCommand]` の grep で確認した。現行（pf-eccube3）の単一バッチ `order:batch copyOrderNumber`（注文番号コピー＋店頭受取スマレジ連携）は刷新先で機能分割されており、**実在が確認できるコンソールコマンドは店頭受取スマレジ連携サブバッチ `eccube:order:otc-smaregi-post` のみ**である。**正本mdの中核「注文番号テーブル→受注への注文番号コピー」を起動するバッチ（コンソールコマンド）は刷新先に存在せず＝注文番号コピーの起動口は未特定**であり、`eccube:order:otc-smaregi-post` を注文番号コピーの起動口として扱わない（誤った起動口で自動化を確定しない）。刷新先の注文番号は受注処理 `OrderSequenceNoProcessor::prepare()`（受注処理内採番、OrderSequenceNoProcessor.php:42）が設定するためバッチ起動口を持たない。したがって注文番号コピー観点（E2E-005）は**起動口未特定として `要実機確認(test.fixme前提)`** に倒す（移行差異は付帯表4-1に明示）。

- コマンド名: `eccube:order:otc-smaregi-post`（`src/Eccube/Command/OtcOrderSmaregiPostCommand.php:25`、`#[AsCommand(name: 'eccube:order:otc-smaregi-post', description: '店頭受取注文のスマレジ連携バッチ')]`、引数なし）。本コマンドが正本md「店頭受取注文のスマレジ用商品コード生成・登録・スマレジ連携」に対応する。
- 連携本体: `Eccube\Service\Smaregi\SmaregiOtcOrderPostAction::handle()`（`SmaregiOtcOrderPostAction.php:40`）。対象抽出 `OrderRepository::findTargetOrdersForSmaregiPost()`（`OrderRepository.php:1798`、配送が店頭受取〔`Delivery::OTC`/`Delivery::SMOOTH_OTC`〕・スマレジ未連携フラグ等で抽出）→ スマレジ用商品コード生成（`SmaregiOtcOrderPostAction.php:57` の `getProductBarcode()`／別実装 `Smaregi/Otc/SmaregiOtcProductCodeGenerator.php`）→ `Order::setSmaregiCode()`・persist（同:59-60）→ 連携ジョブ enqueue（`SmaregiOtcSyncDispatcher::dispatch()`、同:64）→ 失敗受注があれば `RuntimeException`（同:79-81）。
- **注文番号コピー（注文番号テーブル→受注サブ）は刷新先ではバッチとして存在しない**＝刷新先は受注処理の `OrderSequenceNoProcessor::prepare()`（`OrderSequenceNoProcessor.php:41`、シーケンスから0埋め8桁で `dtb_order.order_number` を直接設定）で採番・設定し、補助表 `dtb_order_sub` も廃止して `dtb_order` に統合済み。よって正本mdの「コピー」観点は刷新先では別経路（受注処理）に移行している（付帯表4-1の重大移行差異・要確認）。
- Playwright の `request` ではコンソールバッチを直接起動できない（起動口は実機/シェル依存）。店頭受取スマレジ連携サブバッチ（E2E-001〜004,006,007,009〜014）は区分 `E2E自動化(API/統合)` とし、コマンド名は実在根拠（`eccube:order:otc-smaregi-post`）で確定する一方、spec では `bin/console` 実行が実機依存のため `test.fixme`（理由「起動手段依存」）で残す前提とする。一方、注文番号コピー観点（E2E-005）は起動口（コンソールコマンド）自体が未特定のため、起動手段依存ではなく『起動口未特定』を理由に `test.fixme`（要実機確認）で残す。
- 結果のUI観測（受注管理画面での注文番号・スマレジ用商品コード表示）は本機能の正本mdが「対象はコンソールコマンドであり、ブラウザ経由の画面を持たない」と明記するため、UI観測は別機能（受注管理画面）委譲＝`手動`（要実機確認）に分類する。
