種別: batch（指定受注で使用したポイントを、スマレジ側の会員ポイントへ減算連携するコンソールバッチ。受注IDを引数に取り、購入完了処理・購入完了再処理から別プロセスで呼び出される。画面を伴わない機能仕様）。期待結果はバッチ終了ステータス（正常終了／異常終了の扱い）・標準出力（開始/完了）・連携失敗時のエラー状態記録（管理画面の受注編集画面に現れる範囲）など、API/統合レイヤ（コマンド起動）およびUIレイヤ（受注編集画面）で観測できる結果で判定する。**期待結果は仕様（正本md・観点表・基本設計）由来**とし、実装の現挙動・終了コード実値・出力メッセージ文言・エラーメッセージのjson構造・スマレジ実装挙動をオラクル化しない（オラクル独立性）。pf-eccube3リバース＝基本設計・観点表を上位オラクルとし、乖離は付帯表4に出す。TSV は既存IT casesと同一の 10 列固定。E2E固有情報（コマンド/セレクタ・根拠・自動化区分・仕様根拠・シード・不具合候補）は TSV 後の付帯表に `テストID` で対応づける。Playwright は本リポジトリでは実行しない（構造参考のみ）。未確定の判定・終了コード・外部連携挙動は `要実機確認`。

## 起動口（コンソールコマンド）の特定状況：実装済み（コマンド実在）

本機能の起動口は刷新先 `ec-cube-enterprise` に実装済みであることを `#[AsCommand]` の grep で確認した。

- コマンド名: `eccube:smaregi:update-point`（`src/Eccube/Command/SmaregiUpdatePointCommand.php:26`、`#[AsCommand(name: 'eccube:smaregi:update-point', description: 'スマレジ使用ポイント連携バッチ')]`）。引数 `orderId` は任意（`SmaregiUpdatePointCommand.php:38`、`InputArgument::OPTIONAL`、既定値は空文字）。正本mdの起動例 `smaregi:batch updatePoint <受注ID>` は現行（pf-eccube3）由来表記で、刷新先の実効コマンド名は上記に統一する（差異は付帯表4-8）。
- 連携本体: `Eccube\Service\Smaregi\SmaregiUpdatePointAction::handle()`（`src/Eccube/Service/Smaregi/SmaregiUpdatePointAction.php:32`）。受注取得→消費ポイント取得→会員（選手情報）取得→`SmaregiCustomerService::postSmaregiPoint(smaregiId, -消費ポイント, false)` で減算連携し、失敗時に受注へエラーメッセージ・連携エラーフラグを記録する。
- Playwright の `request` ではコンソールバッチを直接起動できない（起動口は実機/シェル依存）。区分は `E2E自動化(API/統合)` とし、コマンド名は実在根拠で確定する一方、spec では `bin/console` 実行が実機依存のため `test.fixme`（理由付き）で残す前提とする（コマンド未特定ではなく起動手段依存）。
- 結果のUI観測: 連携失敗時に受注へ記録されるポイント連携エラーメッセージは、管理画面の受注編集画面「ポイントエラーメッセージ」欄（`admin/Order/edit.twig:1805` `form.pointErrorMessage` ＝ `#order_pointErrorMessage`）に表示される範囲のみ `E2E自動化(UI)` とする。`smaregi_error_flg` 等はDB内部値のみで画面に現れないためIT層（DB副作用検証）で担保（対象外）。スマレジ会員ポイントの実減算反映は外部POSのため `手動`。
