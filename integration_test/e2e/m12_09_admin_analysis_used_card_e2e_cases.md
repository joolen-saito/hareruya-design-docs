# m12-09_admin_analysis_used_card（デッキ採用枚数集計 ／ 特集タグ編集CSVダウンロード） E2Eテストケース

元設計（一次オラクル）: `function_spec_html_preview/pf-eccube3/m12-09_admin_analysis_used_card.html`（正本 `functions/pf-eccube3/m12-09_admin_analysis_used_card.md`）

テスト観点: `integration_test/integration-test-viewpoints.md` ／ 既存IT: `integration_test/m12_09_admin_analysis_used_card_it_cases.md`（母集合 計90観点行）

期待結果は画面表示・遷移・URL・ダウンロード発火・HTTP応答などブラウザで観測できる結果で判定する。**期待結果は仕様（設計書・観点表・基本設計）由来**とし、実装/POM由来の表示文言・Form制約（NotBlank/Count等）をオラクル化しない。TSV は既存IT casesの10列に実施管理欄（実施者・実施日・結果・失敗理由）を加えた14列固定。E2E固有情報は TSV 後の付帯表に `テストID` で対応づける。Playwright は本リポジトリでは実行しない（構造参考のみ）。未検証セレクタは `要実機確認`。

> 重要（オラクル独立性・仕様乖離）: 本機能の設計書は pf-eccube3（旧 HareruyaEc プラグイン）のリバースであり、**基本設計・観点表を上位オラクル**とする。刷新先 ec-cube-enterprise の該当画面 `admin/Analysis/used_card.twig`＋`UsedCardController` は存在するが、設計書が定める「検索→集計結果表示画面」「出力条件のセッション保持・CSVへの引き継ぎ」「CSVダウンロードの形式指定 `/export/{mode}`」「初期表示でのセッション条件消去」「なりすまし対策トークン」が**実装に存在しない**（POSTで即CSV直ダウンロード／セッション保持なし／`{mode}`なし／`csrf_protection=false`）。これらは付帯表4（不具合候補・仕様乖離）に列挙し、テストは仕様どおりの期待で書く（乖離は失敗で検出する）。観測可能な範囲は CSVエクスポート画面（`csv_export` 画面タイプ）として自動化する。
