## 付帯表1：E2E自動化区分・対象セレクタ・仕様根拠・元IT（TSV外）

DOM id は Symfony Form `CsvImportType` の getBlockPrefix=`admin_csv_import`（`Form/Type/Admin/CsvImportType.php:80-83`）から導出（`import_file`→`#admin_csv_import_import_file`）。行番号は ec-cube-enterprise 現行ソース基準。期待文言は `messages.ja.yaml`／設計書本文（行番号付き打ち切りメッセージはコントローラ実装の固定文字列で、設計書「部門CSV登録時の判定順序」「処理フロー」に同文が引用されており設計書由来とする）。

**spec実装状況（自動化区分の補足）**: 正常系 010／011／035 は `mtb_section` を INSERT/UPDATE する破壊的ケースのため、spec では `test.fixme`（理由付き未実行）として残し、シード（付帯表3）と後始末整備後に実行可能化する。下表・付帯表2b・付帯表5の「E2E自動化／カバー」はいずれも **010/011/035 は `(spec=test.fixme・要シード/後始末で未実行)`** を含意する（抜け漏れではなく実行保留の明示）。異常系（020-034・024・025・031・036）は打ち切り＝ロールバックで非破壊のため即時実行可（036 は2行目失敗で全体ロールバックされ非破壊）。050（サイズ上限・大容量ファイル生成要）・051（表示フラグのDB原値照合）は手動でケース表のみ管理（spec に fixme を残さない）。
