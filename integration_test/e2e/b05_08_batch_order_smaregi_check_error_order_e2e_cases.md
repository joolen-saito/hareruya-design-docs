種別: batch（スマレジ連携エラーフラグが立つEC受注を抽出し、会員のスマレジID・ポイントでスマレジポイント連携をリトライ＝再連携し、成功でエラーフラグ解除・失敗でエラーメッセージ記録を行うコンソールバッチ。リクエスト上限に配慮し受注ごとにインターバルを挟む。画面を伴わない機能仕様）。期待結果はバッチ終了ステータス・標準出力（開始/完了）・連携状態の更新（エラーフラグ／エラーメッセージ）など、API/統合レイヤ（コマンド起動）または外部スマレジ連携の成否で観測できる結果で判定する。**期待結果は仕様（正本md・観点表）由来**とし、実装の現挙動・終了コード実値・出力メッセージ文言・スマレジ実装挙動をオラクル化しない（オラクル独立性）。pf-eccube3リバース＝基本設計・観点表を上位オラクルとし、乖離は付帯表4に出す。TSV は既存IT casesの10列に実施管理欄（実施者・実施日・結果・失敗理由）を加えた14列固定。E2E固有情報（コマンド/根拠・自動化区分・仕様根拠・シード・不具合候補）は TSV 後の付帯表に `テストID` で対応づける。Playwright は本リポジトリでは実行しない（構造参考のみ）。未確定の判定・閾値・内部挙動・外部スマレジ連携の成否は `要実機確認`。

## 起動口（コンソールコマンド）の特定状況：刷新先にコマンド未実装（要実機確認）

本機能の起動口（コンソールコマンド）について、刷新先 `ec-cube-enterprise` の `src/Eccube/Command/*.php` の `#[AsCommand]` を全件 grep したが、**スマレジ連携エラー注文の再連携バッチに相当するコマンドは実在しない**（既存スマレジ系コマンドは `eccube:smaregi:update-point`＝受注ID指定の使用ポイント連携／`eccube:smaregi:stock:backfill`＝在庫変動Webhook再連携／`eccube:order:otc-smaregi-post`＝店頭受取注文連携 のいずれも本機能と別物）。

- 正本md（上位オラクル）の起動口は `smaregi:batch checkSmaregiErrorOrder`（正本md L62「利用者視点の入口」）。これは現行 pf-eccube3 のコマンド表記。
- 刷新先には**対象抽出のリポジトリメソッドは実在**する＝`OrderRepository::getSmaregiErrorOrder()`（`src/Eccube/Repository/OrderRepository.php:877`、`where('o.smaregi_error_flg = 1')`／`DtbPlayer` と join し受注・会員・ポイントを返す）。ただし**このメソッドの呼び出し元（Command）は存在しない**（grep で確認）。
- 受注本体への状態統合は実在＝`Order::$smaregi_error_flg`（`src/Eccube/Entity/Order.php:697`）・`Order::$point_error_message`（同:703）。正本md移行表 L43「補助表 `dtb_order_sub` は移行先に存在せず `dtb_order` へ統合」と一致する。
- 以上より、起動口コマンドは**刷新先未実装＝要実機確認**（コマンド名は正本md由来で確定する一方、実コマンド名・引数・終了コードは creation せず `要実機確認`）。区分は `E2E自動化(API/統合)（要実機確認）` とし、spec は `bin/console` 起動が実機/シェル依存かつコマンド未実装のため `test.fixme`（理由付き）で残す前提とする。詳細は付帯表4-1。
- 連携の成否（成功＝フラグ解除／失敗＝メッセージ記録）は外部スマレジ（外部POS）への実連携結果に依存するため、当該観点は `手動`（外部スマレジ実連携・DB状態は要実機確認）に分類する。受注管理画面での連携状態表示は別機能委譲＝`手動`。
