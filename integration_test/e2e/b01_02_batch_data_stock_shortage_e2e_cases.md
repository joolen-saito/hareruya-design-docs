注記:
- 本機能は**画面を伴わない機能仕様（バッチ）**である。SKILL.md「両レイヤ網羅」に従い、**API/統合レイヤ（バッチ起動）** と **UIレイヤ（抽出対象の入力条件を在庫検索一覧で観測）** に分けて網羅する。
- 期待結果は**仕様（正本md／Excel基本設計／観点表）由来**で判定する（オラクル独立性）。実装の現挙動・終了コードの実値・出力形式を「実装がそうだから」で期待値にしない。位置情報（コマンド名・セレクタ）のみ実装由来。
- **終了ステータスはコード実値（0／非0）を期待値にしない**。正本md・観点表とも終了コードの実値を規定していない（正本md:45-50、viewpoints:434-437）。よって「正常終了として扱われること」「異常終了として扱われること」を観測し、コード値は断定しない。
- **本機能の入力はDB上の対象データ・起動条件**（正本md:41,121-130）であり、JSON取込の仕様は設計書に無い。観点表の汎用行（viewpoints:448 JSON形式）のみを根拠にした「入力JSON形式不正」は本機能仕様から導けないため対象外とする。
- **抽出結果（CSV）はUIに反映されない**。在庫検索一覧（admin_stock_list）に出るのは既存の在庫表示であって本バッチの出力ではない。よってUIレイヤのケースは「**抽出対象の入力条件（在庫数0／≥1）のUI確認**」に限定し、「バッチ結果のUI観測」として扱わない。
- Playwright は本リポジトリでは実行しない。セレクタ・コマンド・自動化区分は後述の付帯表に分離する。根拠が取れないものは `要実機確認`。
- **重要（コマンド未特定）**: 「在庫数0の抽出＋CSV出力」を行う在庫切れバッチの**コンソールコマンドは ec-cube-enterprise に未特定**（付帯表4参照）。正本mdも「在庫切れバッチ本体は Ph2 対応・Ph1 では実装しない」と明記。よって API/統合レイヤのケースは設計のみ行い、実装段階は `test.fixme`（`要実機確認`）前提とする。起動方式（AWS Step Functions・3時間ごと）も本リポジトリから叩けないため `手動／要実機確認`。
