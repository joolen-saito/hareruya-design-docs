本機能は画面を伴わない機能仕様（MTGバイヤーで同一所属店舗に属するメンバー候補を取得するJSON API・GET参照系・ログイン会員の所属店舗で絞り込み）であり、**両レイヤで網羅**する。本APIはブラウザ向け画面を持たず、結果が管理画面に固有に現れる範囲も無いため、**UIレイヤ＝0、API/統合レイヤ中心**で分類する。API/統合レイヤ＝Playwright `request`（APIRequestContext）でエンドポイントへGET送信し、同一所属店舗メンバーの取得有無・絞り込み（他店舗会員の除外）・0件時の取得なし・冪等参照を設計の意味で判定する。専用GETルート・応答項目・成功/失敗の詳細ステータスが正典で未確定（正本md:38・95・100）のため、具体HTTPステータス（200等）・応答形式（JSON配列・ラッパ）・フィールド型（メンバーID数値／氏名文字列）・0件時の具体形（空配列か否か）は期待値として固定せず `要実機確認` とする（付帯表4#1/#2/#3/#4）。

**期待結果は仕様（設計書・観点表・基本設計）由来**とし、実装のレスポンス形・型・HTTPライブラリ既定値・Form制約を期待値に流用しない（オラクル独立性）。正本mdは新規実装機能でExcel基本設計を主・実装を補完とするが、**正本mdに本機能（取得）専用シートが無く、Excel抽出はダブルチェック者更新（A06-16・PUT）のものである**点、および**MTGバイヤー向け店頭買取APIに同一所属店舗メンバー取得専用のGETルートが実装で確認できない**点を、設計書/観点表を上位オラクルとして扱い付帯表4（不具合候補／要確認）に出す。実装で本機能の取得ロジックに対応するのは `MemberRepository::getApprovalAuthorityMembers($BaseInfo)`（同一所属店舗の会員を `dtb_member_base_info.base_info_id` で絞り込み、`/approval_authority` 拒否権限者を除外し氏名昇順で返す）だが、これは管理画面の在庫フォーム／コントローラ内部利用で、MTGバイヤーAPIの公開GETルートとして露出していない。したがって**送信先パス・応答項目・絞り込みキーは確定できず `要実機確認`**とし、合否は設計書の意味（正常取得＝同一所属店舗のメンバー候補一覧＋200／0件＝空の一覧／同一所属店舗のみ＝他店舗会員の除外／認可されないアクセスは正常取得とならない）で判定する。設計⇔実装のパス・応答項目・絞り込みキー・認可方式・除外条件・並び順の差異は付帯表4でのみ一元管理し、TSV期待値に実装の現挙動を固定しない。TSV は既存IT casesの10列に実施管理欄（実施者・実施日・結果・失敗理由）を加えた14列固定。Playwright は本リポジトリでは実行しない（構造参考のみ）。
