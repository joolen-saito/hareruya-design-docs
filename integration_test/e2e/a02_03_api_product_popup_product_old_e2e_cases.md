# A02-03（ポップアップ用商品情報取得(旧)） E2Eテストケース

元設計md（正本一次）: `functions/pf-api/a02-03_api_product_popup_product_old.md`
機能詳細HTML: `function_spec_html_preview/pf-api/a02-03_api_product_popup_product_old.html`

テスト観点: `integration_test/integration-test-viewpoints.md` ／ 既存IT: `integration_test/a02_03_api_product_popup_product_old_it_cases.md`（母集合 計38観点行）

本機能は画面を伴わないJSON API（旧商品IDによるポップアップ用商品情報取得・言語指定なし）であり、結果を反映する管理画面を持たない参照系（副作用なし）である。よってE2Eは **API/統合レイヤ単独**で網羅し、UIレイヤ観測ケースは生じない（在庫・金額の更新が無く管理画面に現れる副作用がないため UI=0）。API/統合レイヤ＝Playwright `request`（APIRequestContext）で `GET /popup/old/{oldProductId}` を呼び、HTTPステータス・レスポンス本文（JSON）・冪等性で判定する。

**期待結果は仕様（設計書・観点表）由来**とし、実装のレスポンス形（`PopupResponseBuilder` の出力フィールド・型）・HTTPライブラリ既定値・例外実装を期待値に流用しない（オラクル独立性）。実装からは位置情報（APIパス・メソッド・認可方式）のみを `file:line` 根拠で取得し、取れないものは `要実機確認`。設計書と実装の食い違い（成功応答フィールド・`stock`型・失敗応答本文・パス型・ルート/メソッド名・認可方式）は付帯表4にのみ不具合候補/要確認として一元管理し、TSV期待値・本文には実装の現挙動を固定しない。TSV は既存IT casesと同一の 10 列固定。Playwright は本リポジトリでは実行しない（構造参考のみ）。

**旧版エンドポイントの刷新先存在可否（重要確認）**: 設計の `GET /popup/old/{oldProductId}`（言語指定なし）は刷新先 ec-cube-enterprise に **実装あり**（`src/Eccube/Controller/App/ProductController.php:317-318` ルート、メソッド `getPopupCardByOldProductId`:319、リポジトリ `findPopupProductByOldProductIdWithoutLang`（`ProductRepository.php:2381`））。旧版だが刷新先に実在するため、全API/統合ケースを「要実機確認」に丸めず、実在経路（`file:line` 根拠）に対する自動化ケースとして設計した。ただし実装ルート名/メソッド名が `..._card_...`（カード）系で設計の「商品情報取得」と名称が食い違うため、その点は付帯表4#6で要確認とする。
