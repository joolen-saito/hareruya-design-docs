# m14-05_admin_card_card_csv_import（カード管理 — カード CSV 登録（取込）） E2Eテストケース

元設計(一次オラクル): `function_spec_html_preview/pf-eccube3/m14-05_admin_card_card_csv_import.html`（正本 `functions/pf-eccube3/m14-05_admin_card_card_csv_import.md`）

テスト観点: `integration_test/integration-test-viewpoints.md` ／ 既存IT: `integration_test/m14_05_admin_card_card_csv_import_it_cases.md`（母集合 計90観点行）

期待結果は画面表示・遷移・フラッシュメッセージ・URL・DB状態(間接)など、ブラウザで観測できる結果で判定する。**期待結果は仕様（設計書・観点表・基本設計）由来**とし、実装/POM由来の表示文言をオラクル化しない。設計源は pf-eccube3（HareruyaEc プラグイン）であり、刷新先 `ec-cube-enterprise` はカードCSV取込を**コア機能**として実装している。両者の挙動差（ルート名・TSV可否・必須列・除外列）は **付帯表4（不具合候補）** に出し、テストは上位オラクル（基本設計・観点表）どおりに書く。

取込後のDB値（mtb_card / mtb_card_detail / dtb_card_format / mtb_card_image の登録・更新・削除）は画面から直接観測できないため、原則 **手動/間接（取込結果メッセージで代表）** とする。TSV は既存IT casesの10列に実施管理欄（実施者・実施日・結果・失敗理由）を加えた14列固定。E2E固有情報は TSV 後の付帯表に `テストID` で対応づける。Playwright は本リポジトリでは実行しない（構造参考のみ）。未検証セレクタは `要実機確認`。

## 刷新先（ec-cube-enterprise）の入口（実装由来＝セレクタ/ナビゲーションの位置情報のみ）

- GET アップロード画面: `admin_card_csv_upload` … `/{admin_route}/card/csv_upload` … 描画 `@admin/Card/csv_card.twig`（`CardCsvController.php:60-68`）
- POST 取込: `admin_card_csv_import` … `/{admin_route}/card/import`（`CardCsvController.php:73-138`）
- 雛形DL: `admin_card_csv_template` … `/{admin_route}/card/csv_template`（`CardCsvController.php:45-53`）
- 入口リンク: カード一覧 `@admin/Card/index.twig:167-169`「CSV取り込み」（trans `admin.common.csv_import`）

> 注: 旧設計（pf-eccube3）はGET/POSTとも `/{admin_route}/card/csvimport`・ルート名 `admin_card_csv` で、TSVも受理した。刷新先はルート名・パスが異なり TSV を拒否する。ナビゲーションは刷新先パスを用い、合否は上位オラクル（観点表・基本設計）で判定する（付帯表4 参照）。
