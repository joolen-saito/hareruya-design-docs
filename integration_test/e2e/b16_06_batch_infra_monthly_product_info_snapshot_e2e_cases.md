# B16-06（月次商品情報スナップショット） E2Eテストケース

元設計: 設計md無し。基盤オラクルは既存IT `integration_test/b16_06_batch_infra_monthly_product_info_snapshot_it_cases.md`（母集合 計20観点行・関連ID IT-30/IT-23/IT-27/IT-24/IT-10/IT-15/IT-26）と観点表 `integration_test/integration-test-viewpoints.md`。元HTML `excel_to_html/output/0416_基本設計仕様書(バッチ_インフラ).html#sheet-8`。

種別: batch（インフラバッチ。Step Functions により毎月1日01:00に起動し、リニューアル後環境の本番DBクラスタから最新スナップショットを選択、一時DBクラスタ〔monthly-inventory-check〕とインスタンス〔restore-for-inventory〕へ復元し、DBが利用可能になるまで待機してから商品規格・店舗・在庫区分を抽出し、ZIP〔stock_YYYYMMDD.txt.zip〕を生成して s3://inventorycheck/ へアップロード、完了後に一時RDSリソースを削除する。画面もHTTP APIレスポンスも持たないインフラバッチ）。期待結果はジョブ終了ステータス・RDSリソースの作成/削除・抽出条件と出力ファイル内容・S3オブジェクト・ログで判定する。**期待結果は仕様（IT観点表・既存IT cases）由来**とし、実装の現挙動・終了コード実値・ログ文言をオラクル化しない（オラクル独立性）。設計mdが存在しないため既存IT cases・観点表を上位オラクルとし、観測不能な観点（待機時間の実時刻依存・抽出元DBの内部状態差分・秘匿値のログ非出力）は理由付きで `手動`／`対象外` に落とす。TSV は既存IT casesと同一の 10 列固定。Playwright は本リポジトリでは実行しない（構造参考のみ）。未確定の起動口・リソース名・抽出条件・内部挙動は `要実機確認`。

## 起動口（ジョブ）の特定状況：AWS実機依存（本リポジトリに実装なし）

本機能の起動口は AWS Step Functions（毎月1日01:00）であり、`ec-cube-enterprise` のコンソールコマンドでも本リポジトリのソースでもない。刷新先ソース（ステートマシン/抽出SQL/クリーンアップ実装）は本リポジトリに未取込のため、コマンド/リソース名/抽出条件の `file:line` 根拠は取得できず全項目 `要実機確認`。

- 起動口: AWS Step Functions（毎月1日01:00・元設計HTML sheet-8／IT-B16-06-...-001）。Playwright の `request` から直接叩けないため区分は `E2E自動化(API/統合)`（ステートマシン手動起動＋RDS/出力観測）とし、spec は `test.fixme`（理由「起動口＝AWS Step Functions実機依存」）で残す。
- RDSリソース（一時クラスタ/インスタンスの作成/削除）・抽出条件と出力ファイル（ZIP内容・ファイル名）・S3オブジェクト・終了ステータスは、ジョブ実行後にAWSリソース/出力を検査すれば観測できるため `E2E自動化(API/統合)`（要実機確認）。
- DB利用可能待機（30分以上）の待機時間は実時刻に依存するため `手動`。抽出元DBの実行前後の非更新は、実機DBの内部状態差分検査に依存するため `手動/間接`。秘匿値（DB接続情報・AWS認証情報）のログ非出力は内部ログ検査に依存するため `手動`。
