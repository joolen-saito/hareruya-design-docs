本機能は画面を伴わない機能仕様（直近に開催された大会の一覧〔大会日・フォーマット・大会名・参加者数〕を返すJSON API・GET参照系）であり、**両レイヤで網羅**する。本APIはブラウザ向け画面を持たず（正本md「対象はJSON APIエンドポイントであり、ブラウザ向けの画面を持たない」）、結果が管理画面に現れる範囲も無いため、**UIレイヤ＝0、API/統合レイヤ中心**で分類する。API/統合レイヤ＝Playwright `request`（APIRequestContext）でエンドポイントへGET送信し、HTTPステータス・レスポンス構造・データ整合・抽出条件・並び順・該当なし時の空配列で判定する。

**期待結果は仕様（設計書・観点表・基本設計）由来**とし、実装のレスポンス形・型・日時整形・HTTPライブラリ既定値を期待値に流用しない（オラクル独立性）。pf-apiの正本mdは現行（deck-api）のリバース設計であり、刷新先 ec-cube-enterprise との乖離（エンドポイントパス・大会日の整形形式・OPTIONS/CORS挙動・呼び出しクライアント制御）は**設計書/観点表を上位オラクル**として扱い、付帯表4（不具合候補／要確認）に出す。実装からは位置情報（APIパス・メソッド・抽出条件・並び順）のみを `file:line` 根拠で取得し、取れないものは `要実機確認`。送信先パスは実装の実効パス `GET /api/recent_event`（`DeckController.php:643`）に統一し（テストが実在経路へ届くため）、合否は設計書の意味（直近大会一覧＝大会日・フォーマット・大会名・参加者数のJSON＋200／大会日設定済かつ大会名が空でない有効行のみ／識別子の昇順／該当なしは空配列＋200／認証不要の公開参照系）で判定する。本APIは入力パラメータを持たず、必須欠落・型不正・不正パラメータ値の検証対象が無いため、異常系は「該当なし（0件）」「抽出除外」「想定外項目の無視」「取得処理中の例外（500）」に集約される。設計⇔実装のパス・大会日形式・CORSの差異は付帯表4でのみ一元管理し、TSV期待値に実装の現挙動を固定しない。TSV は既存IT casesの10列に実施管理欄（実施者・実施日・結果・失敗理由）を加えた14列固定。Playwright は本リポジトリでは実行しない（構造参考のみ）。
