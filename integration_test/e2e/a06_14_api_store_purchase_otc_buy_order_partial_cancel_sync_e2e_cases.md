本機能は**ブラウザ向けの画面を持たない**機能仕様（MTGバイヤーから店頭買取の一部キャンセル情報を連携し、買取明細・在庫情報・一部キャンセル情報を更新するPUT API）であり、**API/統合レイヤ単独で網羅**する。Playwright `request` で `PUT /api/otcBuyOrder/{id}/partiallyCancelUpdate.json`（Excel定義のエンドポイント）へ送信し、HTTPステータス（成功＝200）・レスポンス（Excel「レスポンスデータ：なし」＝ステータスコードのみ）で判定する。更新副作用（一部キャンセル情報の新規記録・買取明細・在庫情報・在庫履歴・買取キャンセル日時・個別入力商品）は永続化先テーブルを直接DB照合（DB副作用観測）して判定する。

**重要前提（Ph2未実装）**: 本APIの本処理（一部キャンセル連携）は ec-cube-enterprise に**未実装**であり、Excel基本設計の図形注記にも「このAPIはPh2で対応するため、Ph1では実装しない」とある。実装の `App/MTGBuyer/V1/Admin/OtcBuyOrderController` には `partiallyCancelUpdate` 用のルートが存在しない（update/freeComment/status/doubleCheckMember/identification のみ）。よって**エンドポイント・認証方式・専用テーブル・処理順序・異常時ステータスは実装で確定できず、API/統合レイヤの全ケースに `要実機確認: Ph2未実装` を付す**（区分は4区分本体の `E2E自動化(API/統合)` に数え、`要実機確認` は修飾子）。設計⇔実装の差異は付帯表4で一元管理する。

**期待結果は仕様（Excel基本設計＝正本md・観点表）由来**とし、実装のレスポンス形・HTTPライブラリ既定値・Form/DTO制約・他APIの実装挙動を期待値に流用しない（オラクル独立性）。Excel基本設計を上位オラクルとし、Excel未定義の挙動（対象なし応答・想定外項目の許容/無視/エラー・異常時HTTPステータス）は固定期待にせず `要実機確認`。実装からは位置情報（APIパス・メソッド・認証方式）のみを `file:line` 根拠で取得し、取れないものは `要実機確認`。TSV は既存IT casesと同一の 10 列固定。Playwright は本リポジトリでは実行しない（構造参考のみ）。

一部キャンセル連携には order_details の入力検証（name必須/最大65535・quantity必須・price必須）とDB更新（一部キャンセル記録・在庫/明細更新）が存在するが、既存IT casesの対象外観点表は「本機能に入力検証対象がないため」「該当する処理・I/Fがないため」と誤って除外している。これを上位オラクル（Excel基本設計）に照らして補正し、入力検証（IT-22）・DB更新（IT-26/IT-05）を設計書補完ケースとして追加した（母集合外・別管理）。当該誤分類は付帯表4#8に記録する。
