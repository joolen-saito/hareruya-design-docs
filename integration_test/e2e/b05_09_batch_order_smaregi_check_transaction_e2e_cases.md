# B05-09（バッチ_受注_スマレジ取引チェック） E2Eテストケース

元設計（正本md）: `functions/pf-eccube3/b05-09_batch_order_smaregi_check_transaction.md` ／ 機能詳細HTML: `function_spec_html_preview/pf-eccube3/b05-09_batch_order_smaregi_check_transaction.html`

テスト観点: `integration_test/integration-test-viewpoints.md` ／ 既存IT: `integration_test/b05_09_batch_order_smaregi_check_transaction_it_cases.md`（母集合 計35観点行・関連ID IT-30/IT-12/IT-16/IT-27/IT-33/IT-32/IT-10）

種別: batch（スマレジの取引参照APIを呼び出して連携エラーのスマレジ取引を取得し、取引情報をもとに取引連携を更新〔取引IDに対応するポイント履歴・会員ポイントの登録・取消〕するコンソールバッチ。画面を伴わない機能仕様）。期待結果はバッチ終了ステータス・標準出力／コンソール出力（取得失敗時の失敗内容）など、API/統合レイヤ（コマンド起動）で観測できる結果で判定する。**期待結果は仕様（正本md・観点表）由来**とし、実装の現挙動・終了コード実値（正本mdは「戻り値1」と記載するが実値はオラクル化しない）・出力メッセージ文言・取引参照APIのレスポンス形・スマレジ実装挙動をオラクル化しない（オラクル独立性）。pf-eccube3リバース＝基本設計・観点表を上位オラクルとし、乖離は付帯表4に出す。TSV は既存IT casesと同一の 10 列固定。E2E固有情報（コマンド/根拠・自動化区分・仕様根拠・シード・不具合候補）は TSV 後の付帯表に `テストID` で対応づける。Playwright は本リポジトリでは実行しない（構造参考のみ）。未確定の判定・閾値・内部挙動・起動口は `要実機確認`。

## 起動口（コンソールコマンド）の特定状況：刷新先に該当コマンドが存在しない（要実機確認）

本機能の起動口は刷新先 `ec-cube-enterprise` に**該当する `#[AsCommand]` が存在しない**ことを grep で確認した（重大乖離・付帯表4-1）。

- 正本md（pf-eccube3）の起動口: `smaregi:batch checkSmaregiTransaction`（正本md 利用者視点の入口 L62）。本コマンド名は pf-eccube3 のオラクルとして採用する。
- 刷新先での確認結果: `src/Eccube/Command/` 全コマンド（計42件の `#[AsCommand]`）に `checkSmaregiTransaction`／`smaregi:batch`／取引参照／取引連携エラー再連携 に対応する起動口は無い（`grep -rn` で src 全体ヒット0）。取引同期は Webhook 駆動（`src/Eccube/Service/Smaregi/Webhook/Transaction/` 以下の各 Handler）として再設計されている。取引参照APIクライアント自体は実在する（`SmaregiTransactionApiClient::getTransaction`〔SmaregiTransactionApiClient.php:53〕／`listTransactions`〔同:99〕）が、これを「連携エラー再連携バッチ」として起動するコンソールコマンドは見当たらない。
- 近接コマンド（参考・本機能の起動口ではない）: `eccube:smaregi:update-point`（SmaregiUpdatePointCommand.php:26＝受注ID単位の使用ポイント連携）、`eccube:smaregi:stock:backfill`（SmaregiStockBackfillCommand.php:32＝在庫変動Webhook再連携）。いずれも取引参照APIによる「取引連携エラー再連携」とは目的が異なる。
- したがってAPI/統合レイヤの全ケースは、コマンド名を正本md由来で確定する一方、**刷新先の起動口が未特定／未実装のため `要実機確認`** とし、spec では `bin/console` 実行が実機依存かつ起動口未確定のため `test.fixme`（理由付き）で残す前提とする。
- 取引連携更新の主たるDB副作用（ポイント履歴・会員ポイント）は本バッチに画面を持たず、値の整合はDB内部値であり**IT層のDB副作用検証で担保**する。E2Eは終了ステータス・コンソール出力で観測できる範囲を対象とし、DB値整合（片側更新防止を含む）は付帯表4・対象外（理由付き・IT層）に置く。UIに現れる会員ポイント反映のみ管理画面観測（E2E-012）で扱う。
