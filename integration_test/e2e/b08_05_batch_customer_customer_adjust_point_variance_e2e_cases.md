種別: batch（会員の保有ポイント〔`dtb_player.point`〕とポイント履歴合計〔`dtb_point_history.point_change` の合計〕に差分がある会員を検出し、保有ポイントを履歴合計へ補正したうえで差分一覧を管理者へ通知メール送信するコンソールバッチ。画面を伴わない機能仕様）。期待結果はバッチ終了ステータス・標準出力（開始/完了）・DB更新結果（保有ポイントの補正）・通知メール送信有無など、API/統合レイヤ（コマンド起動）で観測できる結果で判定する。**期待結果は仕様（正本md・観点表）由来**とし、実装の現挙動・終了コード実値・出力メッセージ文言・差分算出の内部表現・メール本文をオラクル化しない（オラクル独立性）。pf-eccube3リバース＝基本設計・観点表を上位オラクルとし、乖離は付帯表4に出す。TSV は既存IT casesの10列に実施管理欄（実施者・実施日・結果・失敗理由）を加えた14列固定。E2E固有情報（コマンド/根拠・自動化区分・仕様根拠・シード・不具合候補）は TSV 後の付帯表に `テストID` で対応づける。Playwright は本リポジトリでは実行しない（構造参考のみ）。未確定の判定・閾値・内部挙動は `要実機確認`。

## 起動口（コンソールコマンド）の特定状況：実装済み（コマンド実在）

本機能の起動口は刷新先 `ec-cube-enterprise` に実装済みであることを `#[AsCommand]` の grep で確認した。

- コマンド名: `eccube:customer:adjust-point-variance`（`src/Eccube/Command/AdjustPointVarianceCommand.php:25`、`#[AsCommand(name: 'eccube:customer:adjust-point-variance', description: 'ポイント差分発生通知バッチ')]`）。引数は取らない。
- 補正本体: `Eccube\Service\Admin\Customer\AdjustPointVarianceAction::handle()`（`src/Eccube/Service/Admin/Customer/AdjustPointVarianceAction.php:33`）。差分会員抽出は `DtbPointHistoryRepository::getCustomersWithPointDifferential()`（`src/Eccube/Repository/DtbPointHistoryRepository.php:252`、`HAVING p.point <> SUM(ph.pointChange)`:262）。通知は `MailService::sendAdjustPointVarianceMail()`（`src/Eccube/Service/MailService.php:1314`）。
- ただし Playwright の `request` ではコンソールバッチを直接起動できない（起動口は実機/シェル依存）。区分は `E2E自動化(API/統合)` とし、コマンド名は実在根拠で確定する一方、spec では `bin/console` 実行が実機依存のため `test.fixme`（理由付き）で残す前提とする（コマンド未特定ではなく起動手段依存）。
- 通知メールの本文・件名・宛先・実受信は正本mdが「本書で扱わないこと」（L29-30＝メール設定・テンプレート管理を正とする）と明記するため、メール内容・宛先・実送信の検証は別機能委譲＝`手動`（要実機確認）に分類する。送信操作の有無（差分一覧があれば送信）は仕様判定として残す。
