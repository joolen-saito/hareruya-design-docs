# B17-01（バッチ_その他_最新記事リスト生成） E2Eテストケース

元設計（正本md）: `functions/pf-eccube3/b17-01_batch_other_create_latest_article_list.md` ／ 機能詳細HTML: `function_spec_html_preview/pf-eccube3/b17-01_batch_other_create_latest_article_list.html`

テスト観点: `integration_test/integration-test-viewpoints.md` ／ 既存IT: `integration_test/b17_01_batch_other_create_latest_article_list_it_cases.md`（母集合 計90行・関連ID IT-16/IT-17/IT-23/IT-24/IT-26/IT-27）

種別: batch（外部記事サイト〔WordPress〕の公開APIから最新記事を最大20件取得し、取得結果を json ファイル〔`latestArticleList.json`〕として作成・上書きするコンソールバッチ。DBは更新しない。画面を伴わない機能仕様）。期待結果はバッチ終了ステータス・標準出力（エラー／完了の結果メッセージ）・出力ファイル（作成有無・出力先・出力内容）など、API/統合レイヤ（コマンド起動）で観測できる結果で判定する。**期待結果は仕様（正本md・観点表）由来**とし、実装の現挙動・終了コード実値・出力メッセージ文言・出力JSONの列定義（フィールドマッピング）・具体ファイルパスをオラクル化しない（オラクル独立性）。pf-eccube3リバース＝基本設計・観点表を上位オラクルとし、乖離は付帯表4に出す。TSV は既存IT casesの10列に実施管理欄（実施者・実施日・結果・失敗理由）を加えた14列固定。E2E固有情報（コマンド/根拠・自動化区分・仕様根拠・シード・不具合候補）は TSV 後の付帯表に `テストID` で対応づける。Playwright は本リポジトリでは実行しない（構造参考のみ）。未確定の判定・閾値・内部挙動は `要実機確認`。

## 起動口（コンソールコマンド）の特定状況：実装済み（コマンド実在）

本機能の起動口は刷新先 `ec-cube-enterprise` に実装済みであることを `#[AsCommand]` の grep で確認した。

- コマンド名（移行先）: `eccube:create:latest-article-list`（`src/Eccube/Command/CreateLatestArticleListCommand.php:34`、`#[AsCommand(name: 'eccube:create:latest-article-list', description: 'Wordpress記事取得バッチ')]`、docブロックに「Wordpress記事取得バッチ」「WordpressURLから記事を取得、JSONにしてuser_dataに格納する」と明記）。引数は取らない。
- 取得・出力本体: `Eccube\Service\CreateLatestArticleListAction::handle()`（`src/Eccube/Service/CreateLatestArticleListAction.php:38`）。外部記事API（`WP_API_URL` 定数 `.../wp/v2/posts/?per_page=20`、同:29）へ GET（同:61）し、本文を `json_decode`（同:43）して `latestArticleList.json`（`LIST_FILENAME` 同:27）を `list` ディレクトリ（`LIST_DIRECTORY` 同:25）配下へ `uploadContent`（同:100）で書き出す。
- 現行（pf-eccube3）コマンド名は `list:batch createLatestArticleList`（正本md L45・L66）。刷新先の汎用コマンド `list:batch`（`ListTextBatchCommand.php:28-31`）は `createCardNameList` のみ登録（同:34-37）であり、最新記事リスト生成は専用コマンド `eccube:create:latest-article-list` へ分離されている（付帯表4-1）。
- ただし Playwright の `request` ではコンソールバッチを直接起動できない（起動口は実機/シェル依存）。区分は `E2E自動化(API/統合)` とし、コマンド名は実在根拠で確定する一方、spec では `bin/console` 実行が実機依存のため `test.fixme`（理由付き）で残す前提とする（コマンド未特定ではなく起動手段依存）。
- 外部記事API（`article.hareruyamtg.com`）への実接続は時刻依存・外部依存のため、決定的な検証は HTTP クライアントのスタブ（SEED環境スタブ）で表現し、実APIからの実記事取得・実JSON生成は `手動`（要実機確認）に分類する。
