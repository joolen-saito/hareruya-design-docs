期待結果は画面表示・遷移・HTTP応答・URL・別ウィンドウ・読み取り専用などブラウザで観測できる結果で判定する。**期待結果は仕様（設計書・観点表・基本設計）由来**とし、実装／POM由来の表示文言・Form制約をオラクル化しない。TSV は既存IT casesの10列に実施管理欄（実施者・実施日・結果・失敗理由）を加えた14列固定。E2E固有情報（セレクタ・自動化区分・仕様根拠・シード・不具合候補）は TSV 後の付帯表に `テストID` で対応づける。

本機能の設計源リポは pf-eccube3（HareruyaEc プラグイン）であり、刷新先 ec-cube-enterprise には該当画面が実在する（route `admin_event_entry_decklist`／template `@admin/Event/Entry/decklist.twig`）。設計書（pf-eccube3 リバース）と刷新先実装の食い違い（40枚ページ分割・サイドボード描画・DCIナンバー表示・イベント名英表記・セッションキー名）は **付帯表4 不具合候補** に出力し、テストは仕様どおりに書く（実装が違えば落ちて検出）。Playwright は本リポジトリでは実行しない（構造参考のみ）。未検証セレクタは `要実機確認`。

本画面は印刷向けの**読み取り専用**画面で、入力フォーム・更新操作・バリデーション・登録/更新のDB副作用を持たない。このため既存IT cases のうち IT-22（バリデーション全般・35行）は全行 `対象外`（入力検証が存在しない）、IT-26 の登録系・IT-23/IT-26 の DB 書込系は `対象外`（読み取り専用で書込なし）に分類する。デッキ内容（プレイヤー名・DCI・枚数・ページ分割・サイドボード・カナ代替・抽出結果）は**要シード**で内容依存のため `手動` とする。
