## 起動口（ジョブ）の特定状況：AWS実機依存（本リポジトリに実装なし）

本機能の起動口は AWS EventBridge（毎日4:00）→ Lambda であり、`ec-cube-enterprise` のコンソールコマンド（`bin/console`）でも本リポジトリのソースでもない。刷新先ソース（Lambda/クローラ実装）は本リポジトリに未取込のため、コマンド/エンドポイントの `file:line` 根拠は取得できず、全項目 `要実機確認`。

- 起動口: AWS EventBridge スケジュール（毎日4:00）→ Lambda 起動（元設計HTML sheet-11／IT-B16-09-...-001）。Playwright の `request` からは AWS のスケジュール起動を直接叩けないため、区分は `E2E自動化(API/統合)`（ジョブ手動起動＋生成物観測）とし、spec は `test.fixme`（理由「起動口＝AWS EventBridge/Lambda実機依存」）で残す。
- 生成サイトマップの内容（含有URL・除外URL）・S3オブジェクトの有無/更新時刻は、ジョブ実行後にS3/生成ファイルを検査すれば観測できるため `E2E自動化(API/統合)`（要実機確認）。ただし取得はAWS認証を伴うため spec は `test.fixme`。
- 失敗理由のログ記録（CloudWatch）・pingエンドポイント非送信の外部通信キャプチャは、外部ログ/ネットワークの実キャプチャに依存するため `手動`。
