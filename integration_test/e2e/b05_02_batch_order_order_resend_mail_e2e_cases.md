種別: batch（購入完了処理が完了しきらず注文完了メールが未送信となった受注について、ポイント処理・在庫更新・注文完了メールの再送信をやり直すコンソールバッチ。二重実行防止のためロックを取得し、受注ごとにトランザクションで処理する。画面を伴わない機能仕様）。期待結果はバッチ終了ステータス・コンソール出力（実行中検知の未完了出力／受注処理失敗のエラー出力）・注文完了メールの再送信操作の有無など、API/統合レイヤ（コマンド起動）で観測できる結果で判定する。**期待結果は仕様（正本md・観点表）由来**とし、実装の現挙動・終了コード実値・処理件数出力・メール本文/件名/ヘッダ・ポイント/在庫のDB内部値をオラクル化しない（オラクル独立性）。**メール送信は送信操作・送信有無までを期待値にし、本文・件名・宛先・実受信はメールテンプレート管理／メール設計書を正とする別機能委譲＝手動**。pf-eccube3リバース＝基本設計・観点表を上位オラクルとし、乖離は付帯表4に出す。TSV は既存IT casesの10列に実施管理欄（実施者・実施日・結果・失敗理由）を加えた14列固定。E2E固有情報（コマンド/根拠・自動化区分・仕様根拠・シード・不具合候補）は TSV 後の付帯表に `テストID` で対応づける。Playwright は本リポジトリでは実行しない（構造参考のみ）。未確定の判定・閾値・内部挙動は `要実機確認`。

## 起動口（コンソールコマンド）の特定状況：未特定＝要実機確認

本機能の起動口は刷新先 `ec-cube-enterprise` の `src/Eccube/Command` に該当コマンドが見当たらず、コマンド名を実在根拠で確定できなかった（要実機確認）。

- 正本mdの記載コマンド（pf-eccube3）: `order:batch resendMail`（`functions/pf-eccube3/b05-02_batch_order_order_resend_mail.md` 利用者視点の入口 L62-63）。これは現行pf-eccube3のコマンド表現であり、刷新先の `#[AsCommand]` 名ではない。
- grep確認: `src/Eccube/Command/` を `resend`／`未送信`／`再送`／`order.?complete`／`purchase.?complete` で走査したが、購入完了手続き再処理（注文完了メール再送）に対応する `#[AsCommand]` は実在せず（未実装/未移行の可能性）。刷新先コマンド名は創作せず `要実機確認` とする。
- 関連で実在するコマンド: スマレジポイント連携の別プロセス実行に対応しうる `eccube:smaregi:update-point`（`src/Eccube/Command/SmaregiUpdatePointCommand.php:26`、`#[AsCommand(name: 'eccube:smaregi:update-point', description: 'スマレジ使用ポイント連携バッチ')]`）。正本mdの「消費ポイントがある場合スマレジポイント連携を別プロセスで実行」（L83,104）に対応するが、本バッチからの別プロセス起動方式は要実機確認（付帯表4-2）。
- 区分は `E2E自動化(API/統合)（要実機確認）` とし、起動口（本バッチ本体コマンド）が未特定かつ `bin/console` 実行が実機/シェル依存のため、spec では `test.fixme`（理由付き）で残す前提とする。
- 本機能は自前の画面を伴わないため `自動化(UI)` は 0。ただし中核副作用であるポイント処理・在庫更新は、既存の管理画面（受注詳細・商品管理）で観測できる範囲を `手動`（UI観測）で、ポイント履歴・在庫履歴等の管理画面に現れない内部値は IT層＋手動／要実機確認で担保する（完全対象外にしない）。注文完了メールの本文・件名はメールテンプレート管理を正とする別機能委譲＝手動。
