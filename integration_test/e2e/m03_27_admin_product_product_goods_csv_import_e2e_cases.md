元設計: `function_spec_html_preview/pf-eccube3/m03-27_admin_product_product_goods_csv_import.html`（正本 `functions/pf-eccube3/m03-27_admin_product_product_goods_csv_import.md`）

テスト観点: `integration_test/integration-test-viewpoints.md` ／ 既存IT: `integration_test/m03_27_admin_product_product_goods_csv_import_it_cases.md`（母集合 計90観点行）

期待結果は画面表示・遷移・URL・フラッシュメッセージ・ダウンロード発火・(間接)DB状態などブラウザで観測できる結果で判定する。**期待結果は仕様（設計書・観点表・基本設計）由来**とし、実装/POM由来の表示文言・Form制約をオラクル化しない（messages.ja.yaml は刷新先ロケール資源＝仕様の表示文言の正として参照する）。TSV は既存IT casesの10列に実施管理欄（実施者・実施日・結果・失敗理由）を加えた14列固定。E2E固有情報は TSV 後の付帯表に `テストID` で対応づける。Playwright は本リポジトリでは実行しない（構造参考のみ）。未検証セレクタは `要実機確認`。

**設計書＝pf-eccube3 リバース／DB・画面は刷新先 ec-cube-enterprise を正典**。本機能は刷新先に画面が存在し（`GoodsCsvController` + `csv_product_goods.twig`/`base_csv_upload.twig`）、設計書のURL・ルート名と刷新先実装が一致するため URL 乖離はない。グッズCSV取込は「商品本体・規格・カテゴリ・タグ・画像・価格履歴・在庫枠」を更新する重い処理で、取込内容・DBレコードの照合は完全な有効CSV＋商品マスタを要するため大半が**手動/間接**。ブラウザで観測できる範囲（画面表示・UI部品・雛形DL発火・フラッシュ成否・リダイレクト・未認証ガード・件数プルダウン遷移）を E2E自動化する。
