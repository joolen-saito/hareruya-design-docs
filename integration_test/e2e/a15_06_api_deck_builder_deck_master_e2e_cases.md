# A15-06（デッキビルダー_マスタ取得） E2Eテストケース

元設計md（正本一次）: `functions/pf-api/a15-06_api_deck_builder_deck_master.md`
機能詳細HTML: `function_spec_html_preview/pf-api/a15-06_api_deck_builder_deck_master.html`

テスト観点: `integration_test/integration-test-viewpoints.md` ／ 既存IT: `integration_test/a15_06_api_deck_builder_deck_master_it_cases.md`（母集合 計38観点行）

本機能は画面を伴わない機能仕様（パスで指定したマスタ名に対応するマスタの全件を `{code, results}` ラッパで返すJSON API・GET参照系）であり、**両レイヤで網羅**する。本APIはブラウザ向け画面を持たず（正本md「対象はJSON APIエンドポイントであり、ブラウザ向けの画面を持たない」）、結果が管理画面に現れる範囲も無いため、**UIレイヤ＝0、API/統合レイヤ中心**で分類する。API/統合レイヤ＝Playwright `request`（APIRequestContext）でエンドポイントへGET送信し、HTTPステータス・レスポンスのラッパ構造（code/results）・データ整合・該当なし時の404で判定する。

**期待結果は仕様（設計書・観点表・基本設計）由来**とし、実装のレスポンス形・型・HTTPライブラリ既定値・Form制約を期待値に流用しない（オラクル独立性）。pf-apiの正本mdは現行（deck-api）のリバース設計であり、刷新先 ec-cube-enterprise との乖離（エンドポイントパス・応答キー命名・404本文/メッセージ・Format公開フィールド・サブテーブル取得・対象マスタのエンティティ解決等）は**設計書/観点表を上位オラクル**として扱い、付帯表4（不具合候補／要確認）に出す。実装からは位置情報（APIパス・メソッド・公開/非公開判定の位置）のみを `file:line` 根拠で取得し、取れないものは `要実機確認`。送信先パスは実装の実効パス `GET /api/master/{name}`（`MasterController.php:77`）に統一し（テストが実在経路へ届くため）、合否は設計書の意味（公開マスタ＝全件取得200／0件＝200かつ results 空配列／公開しない・存在しないマスタ名＝該当なし404）で判定する。仕様で固定される404は「対象クラスが存在しない・公開しないマスタ」時のみであり、name 欠落・型不正時の具体ステータス（ルート不一致/404等）は要実機確認とする。設計⇔実装のパス・本文・キー命名・公開フィールドの差異は付帯表4でのみ一元管理し、TSV期待値に実装の現挙動を固定しない。TSV は既存IT casesの10列に実施管理欄（実施者・実施日・結果・失敗理由）を加えた14列固定。Playwright は本リポジトリでは実行しない（構造参考のみ）。
