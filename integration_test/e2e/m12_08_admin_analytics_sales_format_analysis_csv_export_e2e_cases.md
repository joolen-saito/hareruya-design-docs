# m12-08_admin_analytics_sales_format_analysis_csv_export（フォーマット売上分析 CSVダウンロード） E2Eテストケース

元設計（機能詳細HTML）: `function_spec_html_preview/pf-eccube3/m12-08_admin_analytics_sales_format_analysis_csv_export.html`（正本 `functions/pf-eccube3/m12-08_admin_analytics_sales_format_analysis_csv_export.md`）

テスト観点: `integration_test/integration-test-viewpoints.md` ／ 既存IT: `integration_test/m12_08_admin_analytics_sales_format_analysis_csv_export_it_cases.md`（母集合 計90観点行）

期待結果は画面表示・遷移・ダウンロード発火・HTTP応答・ファイル名・URL など、ブラウザで観測できる結果で判定する。**期待結果は仕様（設計書・観点表・基本設計）由来**とし、実装の現挙動・Symfony Form 制約（NotBlank/Regex/相関）・実装ファイル名・セッション参照などを期待値に流用しない（オラクル独立性）。CSV の集計値そのものはシード依存で **手動**とする。なお BOM・ヘッダ行（「日」＋各フォーマット＋「合計」）・ファイル名・基本的な行構造は Playwright の `Download.path()` で保存ファイルを読めば自動検証可能であり、ここでは未実行雛形のため **手動**だが将来自動化候補（要確認）として扱う（「機械検証不可」ではない）。

本機能は設計源リポが pf-eccube3（旧システムのリバース）であり、**基本設計・観点表を上位オラクル**とする。刷新先 ec-cube-enterprise との乖離は「付帯表4 不具合候補」に列挙し、テストは仕様どおりに書く（実装が違えば落ちて検出する）。

TSV は既存IT casesと同一の 10 列固定。E2E固有情報（自動化区分・セレクタ・仕様根拠・分類・シード・不具合候補・網羅マトリクス）は TSV 後の付帯表に `テストID` で対応づける。Playwright は本リポジトリでは実行しない（構造参考のみ）。未検証セレクタは `要実機確認`。
