業務ルール補助根拠: `excel_to_html/output/0202_基本設計仕様書(在庫管理機能).html`（スマレジ連携・共通処理）、`excel_to_html/output/0501_基本設計仕様書(API_在庫管理).html`

本機能は画面を伴わない機能仕様（スマレジ取引通知の受信→会員ポイント加減算・ポイント履歴登録/削除・店頭注文の出荷完了反映・支店明細の支店システム転送）であり、**API/統合レイヤ（DB副作用判定）を一次オラクルに網羅**する。API/統合レイヤ＝Playwright `request` で受信エンドポイントへ送信し、HTTPステータス・更新件数応答・副作用（ポイント残高/履歴/受注の整合・不変・冪等）で判定。受信結果が管理画面（会員ポイント残高・ポイント履歴一覧・受注ステータス）に現れる範囲のブラウザ観測は、DB副作用を確かめる補助観測として併用する（本機能は画面なしAPIのため一次判定はDB副作用に置く）。

**期待結果は仕様（設計書・観点表・基本設計）由来**とし、実装のレスポンス形・スマレジ実装挙動・HTTPライブラリ既定値・Form制約を期待値に流用しない（オラクル独立性）。設計書はリバース詳細設計（挙動=pf-eccube3、永続化=ec-cube-enterprise）であり、設計書と観点表・基本設計を上位オラクルとする。設計書はレスポンスを「HTTP 200・`result[].TransactionHead`（更新件数）」、認証を「要求しない（匿名許可）」、解釈不可・取引ヘッダ不足を「HTTP 500（標準例外ハンドラ）」、会員/履歴/注文なしを「件数0で継続し200」と定める。実装からは位置情報（APIパス・メソッド・認証方式・セレクタ）のみを `file:line` 根拠で取得し、取れないものは `要実機確認`。設計書（pf-eccube3）と刷新先実装（ec-cube-enterprise）の食い違いは付帯表4に出す。TSV は既存IT casesの10列に実施管理欄（実施者・実施日・結果・失敗理由）を加えた14列固定。Playwright は本リポジトリでは実行しない（構造参考のみ）。
