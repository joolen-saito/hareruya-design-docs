# B01-03（在庫警告） E2Eテストケース

元設計（正本md）: `functions/ec-cube-enterprise/b01-03_batch_data_stock_warning.md` ／ 機能詳細HTML: `function_spec_html_preview/ec-cube-enterprise/b01-03_batch_data_stock_warning.html`

テスト観点: `integration_test/integration-test-viewpoints.md` ／ 既存IT: `integration_test/b01_03_batch_data_stock_warning_it_cases.md`（母集合 計27観点行・関連ID IT-30/IT-12/IT-16/IT-27）

種別: batch（在庫警告／在庫警戒バッチ。画面を伴わない機能仕様）。期待結果はバッチ終了ステータス・標準出力（処理件数）・出力CSVファイル・DB更新結果・処理ログ・エラー通知など、API/統合レイヤ（コマンド起動）で観測できる結果で判定する。**期待結果は仕様（基本設計仕様書〔在庫管理 基本設計・在庫警戒バッチ B01-03〕・Excel設計書・観点表）由来**とし、実装の現挙動・終了コード実値・出力形式をオラクル化しない（オラクル独立性）。TSV は既存IT casesと同一の 10 列固定。E2E固有情報（コマンド/APIパス・自動化区分・仕様根拠・シード・不具合候補）は TSV 後の付帯表に `テストID` で対応づける。Playwright は本リポジトリでは実行しない（構造参考のみ）。未検証のコマンド/セレクタ／閾値判定は `要実機確認`。

## 重要前提：在庫警戒バッチのコンソールコマンドが特定できない（コマンド未特定）

本機能は基本設計仕様書上「**在庫警戒バッチはPh2で対応するため、Ph1では実装しない**」と明記された新規機能であり、現行（pf-eccube3）にも同等機能は存在しない。刷新先 `ec-cube-enterprise/src/Eccube/Command/` を全 `#[AsCommand]` について精査した結果、**在庫警戒（バックヤード在庫有・通販在庫無の規格を抽出しCSV出力）に一致する専用コンソールコマンドは未実装**であることを確認した。近接する在庫系コマンドは機能不一致（`eccube:aggregate-stock-up`＝期間別入庫数集計／`eccube:update-weekly-stock-history`＝週間在庫履歴更新／`eccube:buy-order:auto-stock`＝買取自動入庫／`eccube:initial-stock-registration`＝在庫初期化）。

したがって本書では:
- **起動口（コンソールコマンド名）を実装から導出できないため創作しない**。API/統合レイヤの起動コマンドはすべて `要実機確認`（Ph2実装時に確定）とし、spec では `test.fixme`（理由付き）で残す前提とする。**操作手順の「手動起動」は、Ph2でコマンドが確定するまで実機で手動投入する想定を指し、本リポジトリでは自動実行しない（＝全API/統合ケースは `要実機確認`／`test.fixme` 前提）**。
- 画面を伴わない機能仕様のため、各観点は原則 **API/統合レイヤ（バッチ起動）** に分類する（起動口未特定でも観測対象＝終了ステータス・処理件数・出力CSV・DB更新結果・処理ログは仕様上存在するため、`E2E自動化(API/統合)（要実機確認）` とし、画面に出ないことを理由に対象外にしない）。
- 結果のUI観測先（在庫警戒リストCSV出力画面 M04-07）も Ph2 未実装であり、CSV本文/フォーマットの厳密検査は本来手動のため、CSV本文検査（005）とUI突合（030）の2件は `手動` に分類する。
- 期待結果は仕様（抽出条件＝規格単位でバックヤード在庫有・通販在庫無／在庫数が指定閾値以下／状態NMも対象／Excel設計の17列CSV／エラー時はエラー通知）から記述する。コマンド名・閾値判定・出力先・終了コード実値は実装由来にしない。
