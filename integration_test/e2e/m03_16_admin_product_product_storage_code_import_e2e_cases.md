元設計: `function_spec_html_preview/pf-eccube3/m03-16_admin_product_product_storage_code_import.html`（正本 `functions/pf-eccube3/m03-16_admin_product_product_storage_code_import.md`）

テスト観点: `integration_test/integration-test-viewpoints.md` ／ 既存IT: `integration_test/m03_16_admin_product_product_storage_code_import_it_cases.md`（母集合 計90観点行）

期待結果は画面表示・遷移・URL・フラッシュメッセージ・(間接)DB状態などブラウザで観測できる結果で判定する。**期待結果は仕様（設計書・観点表・基本設計）由来**とし、実装/POM由来の表示文言・Form制約をオラクル化しない（messages.ja.yaml/validators.ja.yaml は刷新先のロケール資源＝仕様の表示文言の正として参照する）。TSV は既存IT casesと同一の 10 列固定。E2E固有情報は TSV 後の付帯表に `テストID` で対応づける。Playwright は本リポジトリでは実行しない（構造参考のみ）。未検証セレクタは `要実機確認`。

**設計書と刷新先実装の URL 乖離（重要）**: 設計書は「CSV取込フォーム表示」を GET `/{admin_route}/product/storage_code/import` としているが、刷新先 ec-cube-enterprise では表示画面 GET は `admin_product_storage_code_csv`=`/{admin_route}/product/storage_code/csv`、取込 POST のみ `admin_product_storage_code_import`=`/{admin_route}/product/storage_code/import`（`StorageCodeController.php:224,245`）。表示画面の入口URLが設計書と異なるため、E2Eは刷新先の実画面（`/csv` および一覧の「CSV入力」リンク）を観測対象とし、乖離は付帯表4に記録する（オラクル独立性：テストは「取込フォームが表示される／取込せず取込画面を再表示する」という仕様の挙動で判定する）。
