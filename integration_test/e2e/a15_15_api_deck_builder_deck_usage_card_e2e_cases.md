本機能は画面を伴わない機能仕様（指定フォーマットで採用率（採用枚数）の高いカードの平均採用枚数を集計し上位から返すJSON API・GET参照系）であり、**両レイヤで網羅**する。本APIはブラウザ向け画面を持たず（正本md「対象はJSON APIエンドポイントであり、ブラウザ向けの画面を持たない」）、結果が管理画面に現れる範囲も無いため、**UIレイヤ＝0、API/統合レイヤ中心**で分類する。API/統合レイヤ＝Playwright `request`（APIRequestContext）でエンドポイントへGET送信し、HTTPステータス・ラッパ応答（`code`／`cards`）・土地限定/除外・アーキタイプ/ボード絞り込み・件数制限・並び順・集計対象が0件のときの空配列・該当フォーマットなし時の404で判定する。

**期待結果は仕様（設計書・観点表・基本設計）由来**とし、実装のレスポンス形・型・HTTPライブラリ既定値を期待値に流用しない（オラクル独立性）。pf-apiの正本mdは現行（deck-api）のリバース設計であり、刷新先 ec-cube-enterprise との乖離（エンドポイントパス・パス名（usage_card⇔usage_analysis）・土地切替パラメータ名（type⇔is_land）・件数/アーキタイプ/ボードの絞り込みパラメータの有無・応答フィールド名（id⇔card_id・count⇔totalCount）・name_en/画像URLの有無・404メッセージ文言）は**設計書/観点表を上位オラクル**として扱い、付帯表4（不具合候補／要確認）に出す。実装からは位置情報（APIパス・メソッド・集計条件位置・404分岐位置）のみを `file:line` 根拠で取得し、取れないものは `要実機確認`。送信先パスは実装の実効パス `GET /api/deck/usage_analysis/{formatId}`（`DeckController.php:522`）に統一し（テストが実在経路へ届くため）、合否は設計書の意味（集計取得＝カード別平均採用枚数のラッパ応答＋200／該当フォーマットなし＝404／土地限定・除外・アーキタイプ・ボード絞り込み・上位count件・降順並び）で判定する。設計⇔実装のパス差異・絞り込みパラメータ差異・応答フィールド差異は付帯表4でのみ一元管理し、TSV期待値に実装の現挙動を固定しない。本APIは入力の追加検証を行わない（正本md バリデーション「形式の追加検証は行わない」）ため許容値違反400のエラーパスは持たず、異常系は該当フォーマットなし404・formatId欠落・絞り込み結果0件で対をなす。TSV は既存IT casesと同一の 10 列固定。Playwright は本リポジトリでは実行しない（構造参考のみ）。
