# A06-05（店頭仕入_買取注文ステータス） E2Eテストケース

元設計md（正本一次）: `functions/pf-api/a06-05_api_store_purchase_otc_buy_order_status.md`
機能詳細HTML: `function_spec_html_preview/pf-api/a06-05_api_store_purchase_otc_buy_order_status.html`

テスト観点: `integration_test/integration-test-viewpoints.md` ／ 既存IT: `integration_test/a06_05_api_store_purchase_otc_buy_order_status_it_cases.md`（母集合 計38観点行）

本機能は画面を伴わないJSON API（買取アプリ＝MTGバイヤーが店頭買取受注のステータスを更新する）であり、**一次オラクルはAPI/統合レイヤに置く**。Playwright `request` でステータス更新エンドポイントへ送信し、HTTPステータス・失敗時の `{code, errors}` 本文・成功時の `{code:200}` で判定し、副作用（受注ステータス・査定担当者・更新日時・ステータス変更履歴）は永続化先テーブル（`dtb_otc_buy_order`・`dtb_otc_buy_order_status_history`）のDB観測で判定する。正典が「ブラウザ向けの画面を持たない／ステータスの画面表示は買取アプリの設計を正とする」と定めるため、**管理画面でのUI確認はスコープ外**とし、母集合外の補助観測（要実機確認）として付帯表に分離する（本体TSV・母集合分類には組み込まない）。

**期待結果は仕様（正本md・観点表・基本設計）由来**とし、実装のレスポンス形・エラーメッセージ文言・ステータスマスタ定義・HTTPライブラリ既定値・Form制約を期待値に流用しない（オラクル独立性）。pf-apiリバースの正本mdは基本設計・観点表を上位オラクルとし、実装からは位置情報（APIパス・メソッド・認証方式・ステータス定数・遷移判定の所在）のみを `file:line` 根拠で取得する。取れないものは `要実機確認`。正本mdと実装の食い違い（パス接頭辞・別名・エラーメッセージ文言・ステータスマスタの値定義）は付帯表4にのみ出し、TSV期待値・本文へ実装の現挙動を写さない。TSV は既存IT casesと同一の 10 列固定。Playwright は本リポジトリでは実行しない（構造参考のみ）。

## 関連ID対応概要

| 関連ID | 本機能でのE2E確認範囲 |
|--------|------------------------|
| IT-32 | 資格情報・受信検証（jwt-token認証）・必須条件（`status`必須）・リクエスト（不正値／想定外項目）・レスポンス（`{code}`／`{code,errors}`契約）・データなし（受注404）。バージョニングは正典にAPIバージョン指定が無く対象外 |
| IT-09 | 正常更新のHTTPステータス・実行結果（更新反映の観測）・外部取得（受注・ステータスマスタ・会員の特定） |
| IT-19 | 同時実行数の制限。正本md「排他制御を持たず後勝ち」＝同時実行数制限の処理が無く対象外 |
| IT-10 | HTTPステータス・通信・正常／異常系・エラー（査定終了拒否・占有拒否）。複数バリデーション一括返却／ソート順・外部キャッシュ・決済代行・転送再連携は本機能に非該当で対象外。タイムアウト・保存例外（500）は手動 |
| IT-33 | 区分整合（更新対象外項目＝買取合計金額・成立日時等の不変）・エラー（拒否時のステータス／履歴の部分更新なし）。数量金額の増減・自動加算・実数更新・売上返品・外部連携は本機能に非該当で対象外 |
