種別: batch（直近1時間以内のSPLINKS決済の受注でポイント利用が反映されていない決済を検知し、該当があれば管理者へアラートメールを送信するコンソールバッチ。画面を伴わない機能仕様）。期待結果はバッチ終了ステータス・標準出力（開始/完了・検出件数）・検出有無・アラートメール送信有無など、API/統合レイヤ（コマンド起動）で観測できる結果で判定する。**期待結果は仕様（正本md・観点表）由来**とし、実装の現挙動・終了コード実値・出力メッセージ文言・抽出クエリの内部条件・メール送信ゲートをオラクル化しない（オラクル独立性）。pf-eccube3リバース＝基本設計・観点表を上位オラクルとし、乖離は付帯表4に出す。メール本文・件名・宛先・ヘッダの内容は正本md「本書で扱わないこと（通知メールの本文・宛先設定はメール設定・テンプレート管理を正とする）」により別機能委譲＝手動。TSV は既存IT casesと同一の 10 列固定。E2E固有情報（コマンド/根拠・自動化区分・仕様根拠・シード・不具合候補）は TSV 後の付帯表に `テストID` で対応づける。Playwright は本リポジトリでは実行しない（構造参考のみ）。未確定の判定・閾値・抽出列・内部挙動は `要実機確認`。

## 起動口（コンソールコマンド）の特定状況：実装済み（コマンド実在）

本機能の起動口は刷新先 `ec-cube-enterprise` に実装済みであることを `#[AsCommand]` の grep で確認した。

- 起動コマンド名（正典）: `order:batch checkNotReflectedPointUsage`（正本md L62）。**期待値・入力はこの正典コマンド名を基準とする**（実装寄せをしない＝オラクル独立性）。実装の実在コマンドは `eccube:check-not-reflected-point-usage`（`src/Eccube/Command/CheckNotReflectedPointUsageCommand.php:34`、`#[AsCommand(name: 'eccube:check-not-reflected-point-usage', description: 'ポイント利用未反映チェックバッチ')]`、引数なし、docブロックに「ポイント利用未反映チェックバッチ（B05-07）」と明記）であり、正典コマンド名と相違する。**実装名乖離は付帯表4-1で管理し、期待値化しない**。位置情報としての file:line は実装根拠として併記する。
- 検出本体: `Eccube\Service\Admin\Order\CheckNotReflectedPointUsageAction::handle()`（`src/Eccube/Service/Admin/Order/CheckNotReflectedPointUsageAction.php:34`）。`OrderRepository::getNotReflectedPointsUsage()`（`src/Eccube/Repository/OrderRepository.php:1824`）で未反映の受注を抽出し、該当があれば `MailService::sendNotReflectedPointUsageAlertMail()`（`src/Eccube/Service/MailService.php:2279`）で通知、検出件数を返す。0件なら通知せず 0 を返す。
- ただし Playwright の `request` ではコンソールバッチを直接起動できない（起動口は実機/シェル依存）。区分は `E2E自動化(API/統合)` とし、コマンド名は実在根拠で確定する一方、spec では `bin/console` 実行が実機依存のため `test.fixme`（理由付き）で残す前提とする（コマンド未特定ではなく起動手段依存）。
- メールの本文・件名・宛先・ヘッダ内容は正本md「本書で扱わないこと」（L31＝メール設定・テンプレート管理を正とする）により別機能委譲＝`手動`。アラートメール送信の有無（成功時出力の主観測）も実送信・実受信は `手動` に分類する。
