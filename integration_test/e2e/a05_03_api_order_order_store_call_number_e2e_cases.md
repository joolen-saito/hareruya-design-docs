本機能は画面を伴わない機能仕様（店内モニター向けの店頭注文番号取得 JSON API。`GET` 参照系）であり、**両レイヤで網羅**する。本APIの観測可能な結果はJSON配列レスポンスであり、結果は管理画面ではなくフロントの店頭注文番号表示画面（別機能）に現れるため、主レイヤは **API/統合**（Playwright `request` でエンドポイントへGET送信し、HTTPステータス・レスポンス本文の配列・型・順序・空配列で判定）。UIレイヤは0件（店頭注文番号表示画面の描画・定期取得は正本md「本書で扱わないこと」で別機能委譲のため）。

**期待結果は仕様（正本md＝pf-eccube3挙動／観点表）由来**とし、実装のレスポンス形・フレームワーク既定値・Form制約を期待値に流用しない（オラクル独立性）。pf-eccube3はリバース設計のため、基本設計・観点表を上位オラクルとし、移行先 ec-cube-enterprise 実装からは位置情報（APIパス・メソッド・認証方式）のみを `file:line` 根拠で取得し、取れないもの・刷新先の独自挙動は `要実機確認` とする。設計（pf-eccube3）と実装（ec-cube-enterprise）の食い違いは付帯表4に出す。TSV は既存IT casesの10列に実施管理欄（実施者・実施日・結果・失敗理由）を加えた14列固定。Playwright は本リポジトリでは実行しない（構造参考のみ）。
