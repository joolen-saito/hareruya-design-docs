# Codexレビュー結果と対応（m01 ログインE2Eパイロット）

codex exec(gpt-5.5・読み取り専用)でパイロット成果物（E2Eケース表・Playwright雛形）をレビュー。自検証のうえ反映。

## 自検証で裏付けた事実
- 認証失敗は **validators.ja.yaml:20-24 に2行**（「ログインできませんでした。」「入力内容に誤りがないかご確認ください。」）＝文言は静的確認可。要確認は nl2br の2行レンダリングのみ。
- 試行制限の分数あり/なし文言も validators.ja.yaml:25-27 で確定。
- 既存IT case接頭辞 `IT-M01-01-ADMIN-LOGIN-LOGIN-NNN`、関連IDは IT-22/25/03/13/15/20/23/26。

## 対応（深刻度高を中心に）
| 指摘 | 深刻度 | 対応 |
|------|--------|------|
| A: 認証失敗オラクルが1行だけ＝2行目欠落を検出不可 | 高 | spec `expectAuthFailure` で **2行とも検証**。ケース表も2行明記 |
| A: 既知ケースまで test.fixme 過多 | 中 | ID/PW未入力・不存在ID・PW不一致を **実装(非fixme)**。fixme は要シード/要実機のみ |
| A: 元ITケースID が仮ID | 中 | 接頭辞 `IT-M01-01-ADMIN-LOGIN-LOGIN-` を明記し `（要対応付け）` で残課題化 |
| B: DB副作用(失敗履歴・login_date)欠落 | 高 | **090成功履歴/091失敗履歴/092 login_date更新** を追加(間接・別画面) |
| B: 分類サマリ未分類0の裏付け不足 | 高 | 既存IT casesの **全関連ID(IT-15/20/23/26含む)を分類表に網羅**、合計・未分類0を照合 |
| B: 試行制限が1件のみ | 中 | 分数なし/成功リセット/30分解除/判定単位 を追加(自動化/手動/対象外に分類) |
| B: CSRFを対象外にしている | 中 | hidden tokenはDOMにあり **DOM改ざんで自動化候補**に変更 |
| B: 2FAが遷移のみ | 中 | 「**追加認証完了まで保護画面利用不可**」(071)を追加 |
| C: #password 根拠がTwig単独 | 中 | render由来＋既存POM(login.page.ts:18)併記。不具合候補#3にも |
| C: ログアウト根拠にfile:line無し | 中 | login.page.ts:38-41 を明記 |
| C: ボタン根拠にtransキー無し | 低 | `admin.login.login`(login.twig:37)を併記 |
| D: spec相対importは配置先前提 | 高 | ヘッダで「配置先(ec-cube-enterprise/e2e-tests/spec/admin/)前提・本リポでは未解決」を明記 |
| D: 自動化ケースがspec未実装 | 中 | PW未入力/保護URL/ログイン済み→ホーム を spec 追加 |
| E: SEED-LOCKが非べき等 | 高 | **専用ID＋IP隔離＋リミッタ(Redis)初期化でべき等化**、自然解除依存を排除 |
| E: 停止/2FAシードが薄い | 中 | 安定キー(専用login_id)・状態カラム・base_info・既知PW を明記 |
| E: 失敗履歴/login_dateのシード欠落 | 中 | SEED-M01-ADMIN で対応 |
| F: validators文言は静的確認可 | 中 | 不具合候補#1を「nl2brの2行レンダリング確認」に修正 |
| F: 不具合候補にDB副作用が無い | 中 | 不具合候補#2(DB副作用の観測限界)を追加 |
| F: #password要確認 | 低 | 不具合候補#3に追加 |

## 総評(codex)→ 反映後
