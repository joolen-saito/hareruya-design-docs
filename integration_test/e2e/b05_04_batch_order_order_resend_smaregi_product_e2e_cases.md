## 起動口（コンソールコマンド）の特定状況：実装済み（コマンド実在・名称は刷新先で改称）

本機能の起動口は刷新先 `ec-cube-enterprise` に実装済みであることを `#[AsCommand]` の grep で確認した。

- コマンド名（刷新先実装）: `eccube:order:otc-smaregi-post`（`src/Eccube/Command/OtcOrderSmaregiPostCommand.php:25`、`#[AsCommand(name: 'eccube:order:otc-smaregi-post', description: '店頭受取注文のスマレジ連携バッチ')]`）。引数は取らない。
- 正本md（pf-eccube3）が記す入口コマンド名 `order:batch resendSmaregiProduct`（正本md L58）とは名称が異なる。コマンド名の差異は付帯表4#1で不具合候補（要確認）として一元管理し、E2E期待値・本文には実装コマンド名を期待値として固定しない（送信先＝起動口の実体は実装名で確定）。
- 再連携本体: `Eccube\Service\Smaregi\SmaregiOtcOrderPostAction::handle()`（`src/Eccube/Service/Smaregi/SmaregiOtcOrderPostAction.php:39`）。対象抽出 `OrderRepository::findTargetOrdersForSmaregiPost()`（`src/Eccube/Repository/OrderRepository.php:1798`）→ 受注ごとに `SmaregiOtcSyncDispatcher::dispatch()`（`src/Eccube/Service/Smaregi/Otc/SmaregiOtcSyncDispatcher.php:42`）で MessengerJob を enqueue する。
- 連携状態フラグは受注 `dtb_order` の `smaregi_product_flg`／`smaregi_stock_flg`（`src/Eccube/Entity/Order.php:688-692`、既定 false）。抽出は両フラグ false の受注を対象とする（`OrderRepository.php:1798` の andWhere）。
- ただし Playwright の `request` ではコンソールバッチを直接起動できない（起動口は実機/シェル依存）。区分は `E2E自動化(API/統合)` とし、コマンド名は実在根拠で確定する一方、spec では `bin/console` 実行が実機依存のため `test.fixme`（理由付き）で残す前提とする（コマンド未特定ではなく起動手段依存）。
- 本機能は画面を持たない（正本md L9「対象はコンソールコマンドであり、ブラウザ経由の画面を持たない」）ため `自動化(UI)` は 0。
