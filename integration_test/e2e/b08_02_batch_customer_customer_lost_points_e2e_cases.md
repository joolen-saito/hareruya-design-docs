種別: batch（有効期限を過ぎたポイントを失効させるコンソールバッチ。失効対象会員ごとに失効分をスマレジへ連携し、連携成功時のみ会員の保有ポイントを残ポイントへ更新してポイント履歴を記録する。会員ごとに短いインターバルを挟む。画面を伴わない機能仕様）。期待結果はバッチ終了ステータス・標準出力（開始/完了）・スマレジ連携・DB更新結果（保有ポイント・ポイント履歴の副作用）など、API/統合レイヤ（コマンド起動）で観測できる結果で判定する。**期待結果は仕様（正本md・観点表）由来**とし、実装の現挙動・終了コード実値・出力メッセージ文言・ポイント履歴の内部表現（符号・発行日の加算日数）・スマレジ連携の内部仕様をオラクル化しない（オラクル独立性）。pf-eccube3リバース＝基本設計・観点表を上位オラクルとし、乖離は付帯表4に出す。TSV は既存IT casesの10列に実施管理欄（実施者・実施日・結果・失敗理由）を加えた14列固定。E2E固有情報（コマンド/根拠・自動化区分・仕様根拠・シード・不具合候補）は TSV 後の付帯表に `テストID` で対応づける。Playwright は本リポジトリでは実行しない（構造参考のみ）。未確定の判定・閾値・内部挙動は `要実機確認`。

## 起動口（コンソールコマンド）の特定状況：実装済み（コマンド実在）

本機能の起動口は刷新先 `ec-cube-enterprise` に実装済みであることを `#[AsCommand]` の grep で確認した。

- コマンド名: `eccube:customer:lost-points`（`src/Eccube/Command/LostPointsCommand.php:25`、`#[AsCommand(name: 'eccube:customer:lost-points', description: 'ポイント失効バッチ')]`）。引数は取らない。正本mdが記す `customer:batch lostPoint` は現行（pf-eccube3）のコマンド形であり、刷新先コマンド名と差異がある（付帯表4-1）。
- 失効本体: `Eccube\Service\Admin\Customer\LostPointsAction::handle()`（`src/Eccube/Service/Admin/Customer/LostPointsAction.php:40`）。失効対象抽出は `DtbPointHistoryRepository::getPlayersForLostPoint()`（`src/Eccube/Repository/DtbPointHistoryRepository.php:293`）。スマレジ連携は `SmaregiCustomerService::postSmaregiPoint()`（`src/Eccube/Service/Smaregi/SmaregiCustomerService.php:31`）。
- ただし Playwright の `request` ではコンソールバッチを直接起動できない（起動口は実機/シェル依存）。区分は `E2E自動化(API/統合)` とし、コマンド名は実在根拠で確定する一方、spec では `bin/console` 実行が実機依存のため `test.fixme`（理由付き）で残す前提とする（コマンド未特定ではなく起動手段依存）。
- 本機能は画面を持たず（正本md L9「対象はコンソールコマンドであり、ブラウザ経由の画面を持たない」）、保有ポイント・ポイント履歴を表示する管理画面を設計範囲としないため `UI観測` は無い。判定軸は次の2層に分ける。(a) 保有ポイント更新・ポイント履歴記録の **発生有無**（更新されること／記録されること自体）は正本mdが定義するバッチの結果（処理フロー L74-75／入出力 L100-107）であり、コマンド起動後の副作用として `自動化(API/統合)` で観測する（実DB照合は実機/IT層で実施するが、判定軸は仕様由来の副作用であって生のDBカラム値そのものではない）。(b) これに対し **DB内部値そのもの**（dtb_player.point・dtb_point_history の create_date 等の内部値、ポイント増減量の符号、発行日の加算日数など**内部表現のみ**）は終了ステータス/標準出力に現れず判定軸にしないため `対象外`（IT層のDB副作用検証で担保。CHECKLIST「バッチで頻出の落とし穴」）とする。E2E-004/005/006/007/008/010/011/016 は (a) の発生有無のみを判定し、(b) の内部表現はオラクル化しない。
