# A14-03（カード単一検索） E2Eテストケース

本機能は画面を伴わない機能仕様（検索クエリに一致するカード情報を1件返すJSON API・GET参照系）であり、**両レイヤで網羅**する。本APIはブラウザ向け画面を持たず（正本md「対象はJSON APIエンドポイントであり、ブラウザ向けの画面を持たない」）、結果が管理画面に現れる範囲も無いため、**UIレイヤ＝0、API/統合レイヤ中心**で分類する。API/統合レイヤ＝Playwright `request`（APIRequestContext）でエンドポイントへGET送信し、HTTPステータス・レスポンスのフィールド構成と型・データ整合・該当なし時の404で判定する。

**期待結果は仕様（設計書・観点表・基本設計）由来**とし、実装のレスポンス形・型・HTTPライブラリ既定値・Form制約を期待値に流用しない（オラクル独立性）。pf-apiの正本mdは現行（旧システム）のリバース設計であり、刷新先 ec-cube-enterprise との乖離（認可方式・応答整形のキー命名・想定外クエリの扱い・障害時応答等）は**設計書/観点表を上位オラクル**として扱い、付帯表4（不具合候補／要確認）に出す。実装からは位置情報（APIパス・メソッド・認可属性）のみを `file:line` 根拠で取得し、取れないものは `要実機確認`。送信先パスは実装の実効パス `GET /card`（`CardController.php:41`、App配下プレフィクスなし＝`routes.yaml:5-7`）に統一し、合否は設計書の意味（正常取得＝カード1件JSON＋200／該当なし・`name`空相当＝404「Not Found」／異常・特殊文字は正しいカードが取得されない＝正常取得200とならない）で判定する。仕様で固定される404は該当なし・`name`空時のみであり、想定外クエリ・障害・タイムアウト時の具体応答は正典未定義のため固定せず要実機確認とする。設計⇔実装の差異（認可方式・`image_url`の命名・障害時500応答）は付帯表4でのみ一元管理し、TSV期待値に実装の現挙動を固定しない。TSV は既存IT casesと同一の 10 列固定。Playwright は本リポジトリでは実行しない（構造参考のみ）。
