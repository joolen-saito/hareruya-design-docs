# B16-10（ステージングデータベース保守バッチ） E2Eテストケース

元設計: 設計md無し。基盤オラクルは既存IT `integration_test/b16_10_batch_infra_staging_database_maintenance_it_cases.md`（母集合 計12観点行・関連ID IT-30/IT-23/IT-26/IT-27/IT-15/IT-10）と観点表 `integration_test/integration-test-viewpoints.md`。元HTML `excel_to_html/output/0416_基本設計仕様書(バッチ_インフラ).html#sheet-12`。

種別: batch（インフラバッチ。Step Functions により毎月1日3時に起動しFargateで実行する。本番DBのスナップショットを取得してテンポラリDBを作成・復元し、テンポラリDBからスマレジID/トークンの削除・個人情報マスク等の加工を行い、現行ステージングDBを削除して加工済みテンポラリDBスナップショットから新規ステージングDBを作成、ステージング用スマレジIDを追加する。あわせて本番S3からステージングS3へ商品画像・絵文字を同期し、テンポラリDB/スナップショットを削除する。画面もHTTP APIレスポンスも持たないインフラバッチ）。期待結果はジョブ終了ステータス・RDSリソースの作成/削除・ステージングDBの内容加工・S3同期結果・ログで判定する。**期待結果は仕様（IT観点表・既存IT cases）由来**とし、実装の現挙動・終了コード実値・ログ文言をオラクル化しない（オラクル独立性）。設計mdが存在しないため既存IT cases・観点表を上位オラクルとし、観測不能な観点（DB内部値のマスク/削除/追加・実機DB依存）は理由付きで `手動/間接` に落とす。TSV は既存IT casesの10列に実施管理欄（実施者・実施日・結果・失敗理由）を加えた14列固定。Playwright は本リポジトリでは実行しない（構造参考のみ）。未確定の起動口・リソース名・加工条件・内部挙動は `要実機確認`。

## 起動口（ジョブ）の特定状況：AWS実機依存（本リポジトリに実装なし）

本機能の起動口は AWS Step Functions（毎月1日3時）→ Fargate であり、`ec-cube-enterprise` のコンソールコマンドでも本リポジトリのソースでもない。刷新先ソース（ステートマシン/加工スクリプト/S3同期実装）は本リポジトリに未取込のため、コマンド/リソース名/加工条件の `file:line` 根拠は取得できず全項目 `要実機確認`。

- 起動口: AWS Step Functions（毎月1日3時）→ Fargate（元設計HTML sheet-12／IT-B16-10-...-001）。Playwright の `request` から直接叩けないため区分は `E2E自動化(API/統合)`（ジョブ手動起動＋RDS/S3観測）とし、spec は `test.fixme`（理由「起動口＝AWS Step Functions/Fargate実機依存」）で残す。
- RDSリソース（本番スナップショット取得・テンポラリDB作成/復元・ステージングDB削除/作成・テンポラリ削除）・S3同期（商品画像/絵文字）・終了ステータスは、ジョブ実行後にAWSリソースを検査すれば観測できるため `E2E自動化(API/統合)`（要実機確認）。
- テンポラリDB/ステージングDBの内部加工（スマレジID/トークン削除・ステージング用スマレジID追加・個人情報マスク）は、DB内部値の検査に依存し実機DBアクセスが必要なため `手動/間接`。
