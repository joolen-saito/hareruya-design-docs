## §1. 全ケース共通前提
- **入口/認証**: 認証済み管理者が管理画面「設定」（システム設定）から利用する。入口は L325 のとおり ①`GET /%eccube_admin_route%/setting/system/masterdata`（マスタ未選択）②`POST` 同URL（マスタ選択送信）③`GET|POST /%eccube_admin_route%/setting/system/masterdata/{entity}/edit`（マスタ選択済み・`{entity}`＝マスタキー）④`GET /%eccube_admin_route%/setting/system/masterdata/edit`（編集入口へGETのみ）。未認証は利用不可＝管理画面のログイン要件に従う（L365）。
- **CSRF**: 入力は GET または POST のフォームで、CSRF は Symfony フォームの Hidden で運用する（L355）。CSRF 検証失敗は共通の拒否処理（L375）。
- **副作用**: 対象マスタテーブルの行の追加・更新・削除・`sort_no` 更新、および拡張イベントの dispatch に限る（L355）。検索条件セッション等の専用サーバ状態は増やさない（L372,L386）。独自 Cookie は増やさない（L389）。
- **応答**: 成功時出力は HTML 画面。保存成功時は成功フラッシュ付きで一覧状態へ再遷移する。検証エラーは同一レスポンスでフィールドエラー。`flush` 失敗はエラーフラッシュとリダイレクト（L355,L369,L375）。
- **並び順**: 一覧読込は `sort_no` 昇順。保存時は送信された行の並び順で `sort_no` を 0 から連番で付け直す（L342,L359）。
- **排他**: 行バージョンや楽観ロックは持たず、同時編集は後勝ち（L349,L392）。
- **オラクル独立性**: 期待は正本HTML（詳細設計）由来で実装から独立。正本が沈黙する箇所は断定せず「要実機確認」とする。実装との差は付帯表4で乖離＝バグ候補として扱う。
