## §1. 全ケース共通前提
- **入口/認証**: 認証済み管理者がブラウザ経由の管理画面で利用（L309「対象はブラウザ経由の管理画面に限定する」）。サイドバー「カード管理」→「フォーマット管理」から到達（L316）。ルートは 一覧 GET `/{admin_route}/format`、新規 GET `/{admin_route}/format/new`、登録 POST `/{admin_route}/format/new`、編集 GET `/{admin_route}/format/{formatId}/edit`、更新 POST `/{admin_route}/format/{formatId}/edit`、削除 DELETE `/{admin_route}/format/{formatId}/delete`（`formatId` は1以上の整数・正規表現 `^[1-9][0-9]*$`）（L400）。
- **CSRF**: POST はフォーム名に紐づくトークンを検証し無効なら HTTP 403、検証後はトークンを更新する。DELETE はアンカー用の既定トークンを検証し無効なら HTTP 403（L329,L334,L345,L375）。
- **更新系**: 本機能は登録・更新・削除を行う（0208:L3746）。永続化は承認ワークフローを介さず persist/flush で直接確定＝即時反映（L361）。副作用は DB の INSERT/UPDATE/DELETE（ソフトデリート時は `deleted_at` 更新）、セッションのフラッシュメッセージ、POST フォーム検証時の CSRF トークン更新（L354）。
- **応答**: 登録/更新の検証成功は保存後に当該フォーマット ID の編集画面へ HTTP リダイレクト（新規でも更新でも同じ）＋成功フラッシュ `admin.register.complete`（L332,L354,L370）。検証失敗は `admin.register.failed` を積み同一編集画面を再表示（L329,L354,L370,L375）。削除成功は一覧へリダイレクト＋`admin.delete.complete`（L334,L370）。
- **除去項目の不在**: §0 のとおりカードセット・禁止カード・制限カードの入力欄、および (32)(33)(34)(35) ボタンは画面に存在しない（0208:L3808-3819,L3886,L3899,L3900,L3909-3912）。
- **オラクル独立性**: 期待はオラクル（Excel優先・沈黙部は詳細設計HTML）由来で実装から独立。実装との差は付帯表4で乖離＝バグ候補として扱う。

## §7. gen(74) からの是正（オラクル差し替え）
- gen の期待は詳細設計HTMLの総称verbatim（「対象機能を実行する」等）で、機能区分＝カスタマイズのオラクル（Excel優先）に差し替えられていなかった。→ 全行を Excel識別ID表＋カスタマイズ要件を一次、詳細設計HTMLを補完とする具体挙動へ差し替え。
- **gen は Excel カスタマイズ要件（除去項目）を反映していなかった**（詳細設計HTMLのみを見てカードセット・禁止カード・制限カードの観点を生成）。→ Excel優先により §0 の対象外へ移し、TSVから非生成（`superseded` 相当の逆捏造防止）。逆に Excel が追加する「イベントに表示」(18) は詳細設計HTMLの入力項目表に無いが RG-040 として実施へ追加。
- gen はバリデーションを「要正本照合」のまま8行の `EXEC-UI:DDT` に留めていた。→ Excel識別ID表（0208:L3878-3905）が必須・最大文字数/最大値・文言を規定するため、全入力項目×境界を §3 の DV-01〜39（固定オラクル）へ具体化し、オラクルが沈黙する3件のみ要実機確認（件数外）へ縮退。
