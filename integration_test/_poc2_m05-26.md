## §1. 全ケース共通前提
- **入口/認証**: 認証済み管理者が管理画面で利用。ルートは `admin_shipping_result_csv_import`（GET `/{admin_route}/order/shipping_result_csv/import`＝アップロード画面）と `admin_shipping_result_csv_upload`（POST `/{admin_route}/order/shipping_result_csv/upload`＝取込）（正本 L311,L317,L319,L379）。管理画面共通ログイン前提で、本機能固有のロール分岐は正本が固定しない（L350）＝未認証拒否は共通認証仕様へ委譲（§5台帳）。
- **CSRF**: アップロードPOSTは multipart/form-data＋CSRF用トークンで送信される（正本 L340）。
- **副作用系**: 取込は参照でなく更新。成功時は受注ステータス・注文サブ（出荷実施日時・送り状No.）・配送（出荷コミット日時）を更新し、更新された受注についてポイント付加・出荷完了メール・スマレジ付与ポイント送信を同期実行（Excel 0203:L7750-7756）。DB更新は Doctrine トランザクション内で行い、例外時はロールバックする（正本 L340,L356）。外部HTTP API は呼ばずプラグインメソッドの副作用に委ねる（正本 L337）。
- **排他制御**: 名前付き接続ロックで同種CSV処理の並行を回避。既に処理中は「既に処理中」メッセージを表示し一覧へリダイレクト復帰（正本 L331,L370）。
- **応答**: 成功は成功フラッシュ付きで一覧GET（`…/shipping_result_csv/import` 相当）へリダイレクト、失敗は失敗フラッシュとともに同URLへ復帰し、フラッシュのみが変わる（正本 L340,L353）。
- **オラクル独立性**: 期待はオラクル（Excel優先・沈黙部は詳細設計HTML）由来で実装から独立。実装との差は付帯表4で乖離＝バグ候補として扱う（期待値には使わない）。
