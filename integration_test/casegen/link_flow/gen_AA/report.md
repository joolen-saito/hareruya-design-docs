## 作らなかった候補と価値のある連携
- A05-04 の取消・打消 → ポイント履歴の削除（M08-06・F06-10）: 「取引に一致するポイント履歴」の一致の基準が設計書に無く、取引IDの結び付け方を作れない。
- A05-04 の取消 → 在庫履歴（M04-17）と受注のキャンセル表示（M05-11）: 上のとおりシードが画面から作れない。0202 別添資料のシナリオ②③に書かれた価値のある連携。

## 設計書の不備・要確認
1. 通常取引の利用ポイント履歴の増減量の符号（マイナスで保存するか）が無い。M08-06・F06-10 の使用行の増減量を書けず、行の表示だけにした。
2. 0207 会員登録編集の識別ID52「ポイント確認ボタン」の遷移先が「ポイント確認画面」とだけあり、M08-06（ポイント履歴確認）か M08-05 かの明記が無い。手順は「ポイント確認」ボタンで書いた。
3. 保有ポイント（A05-04）と選手情報のポイント残高（M08-06）の対応は、A05-04 には明記が無い。
4. 0202 在庫履歴の「登録元」の選択肢にスマレジ連携が無い（別添資料には「スマレジ在庫連携API」がある）。そのため登録元は期待結果に入れていない。
5. 実行上の懸念: Webhook 送信に付ける認証情報（open_preconditions の S-A05-04-API）は未確定のまま。既存ケース IT-A05-04-047〜060 と同じ前提を引き継いだ。
