# レビュー指摘の反映（群 RA・1巡目）

codex のレビュー指摘が `integration_test/casegen/link_flow/review/RA_r1_findings.md` にある。

1. **指摘を鵜呑みにしない。** 1件ずつ、指摘が挙げた file:line と、関係する設計書（機能設計書・HTML設計書）を自分で開いて確かめ、採用／一部採用／却下を決める。
   レビュアーの修正案に書かれた語・値もそのまま採らず、設計書の表現で書く。レビュアーも誤る（存在しない記述を引く、範囲を取り違える）。
2. 採用した指摘はケース表・シード表を直す。直せない（設計書に根拠が無い）ケースは削除する。削除・追加したら、テストIDとケース専用シードIDの番号を振り直し、連番を保つ。
   取りこぼしの指摘でケースを足すときも、元の依頼文 `gen_RA/prompt.md` の規則（範囲、ケースにしてよい条件、縛り、出力）にすべて従う。
3. 裁定を `integration_test/casegen/link_flow/review/RA_r1_dispositions.tsv` に書く。タブ区切り・ヘッダ付き:
   `指摘	裁定	確認した根拠	直したこと`（指摘は「指摘1」など。裁定は 採用／一部採用／却下。根拠は file:line。却下の理由は根拠の列に書く。直したことは、変えたテストID・削除・追加）
4. `gen_RA/report.md` の末尾に「レビュー1巡目の反映」の節（件数の増減と、削除・追加したケース）を足す。
5. `python3 integration_test/casegen/link_flow/verify_flow.py RA` を合格させる。

ファイルの書き込みを拒否されたときは、回避せず、書くはずだった本文を返答に載せる（依頼元が保存する）。
触ってよいのは群 RA のケース表・シード表・report.md・裁定ファイルと gen_RA/ の作業用ファイルだけ。git の変更操作はしない。

返答は3行以内: 採用・一部採用・却下の件数、ケース数の増減、verify の結果。
