## 到達可能性
| ケース | 前提と根拠 | シード |
| --- | --- | --- |
| RG001・RG002 | 入庫待ちから入庫済みへ変更できる。特別な権限は不要（0206 ステータス変更権限について）。入庫先は本店の設定。店舗は在庫履歴・在庫検索の検索条件で本店を選ぶ。承認不要の区分で入庫される（別添 マスタ） | S-M07-03-RG-STOCKORDER-001/002、ADM、REF、CONFIG |
| RG003 | 注文から査定内容承諾へ直接変更でき、売却する明細から実在庫が作られる。振込依頼済みは身分証明書が未登録以外で、合計1万円未満なら本人確認は要らない（2200）。振込完了へ変更できる。検索のステータスは設計書の4種を全部選ぶ | S-M07-03-RG-NEWORDER-003 |
| RG004 | 振込依頼済みは身分証明書が登録済みで合計1万円未満（1100）なら本人確認は要らない。会員登録編集は買取履歴欄のリンクから買取詳細へ行ける（識別ID 47-2） | S-M07-03-RG-ACCEPTED-004 |
| M07-04 RG001 | 手動メール通知は買取受注の状態を問わない。テンプレートは買取向けの種別で自動送信専用でない。メール配送は店舗設定とテスト受信箱への接続が要る。会員検索のメール履歴アイコンから履歴画面へ行ける | S-M07-04-RG-ORDER-001、SHOP、TEMPLATE、ADM |
シードはすべて画面から作る（商品・在庫・会員・買取申込・状態変更）。DB直接投入は無い。

## 作らなかった候補と範囲外の連携
| 候補 | 理由 |
| --- | --- |
| 査定価格変更 → 会員登録編集の査定金額（47-4） | 「査定金額」と「査定金額合計」を同じ値とする記述が下流に無く、推測になる |
| 実在庫登録（個別入力商品）→ 買取商品履歴 | RG003と同じ組で、項目違いの水増しになる |
| 買取商品履歴の買取価格の列 | 実在庫の買取単価が選んで買取の査定価格に由来すると上流が書いていない。期待結果に入れていない |
| 入庫済み・バッチ（B06-01）→ 在庫 | バッチは IT-0334 の範囲 |
範囲外で価値のあるもの: 買取申込（公開側）→ 買取検索/一覧（IT-0332）、買取自動入庫バッチ → 在庫履歴（IT-0334）。

## 設計書の不備
| 内容 | 扱い |
| --- | --- |
| 登録元IDが、上流（0206 買取情報編集）は「査定ID」、下流（0202 在庫履歴検索一覧 識別ID 2-9）は「ネット買取は買取番号」と食い違う | 期待結果に登録元IDを入れていない。在庫変動理由の「買取番号：XXXXX」は別添に定めがあるので入れた |
| メール配信履歴の「処理日」と手動メール通知の「送信日時」を同じ値とする記述が無い | 処理日を期待結果に入れていない |
| 買取商品履歴(検索入力)に、ステータスを選ばないときどの買取を出すかの記述が無い。機能設計書（M07-10）も未作成 | ステータスの4種を全部選ぶ形で書いた |
| 買取受付など他のメールの送信履歴が会員のメール配信履歴に出るかの記述が無い | 件名を固有にして、行の有無だけを見る |
| 在庫検索/一覧に原価単価の算出式が無い（別添にある在庫履歴側のみ） | 割り切れる値（850）にして端数処理に依存しない |
| 在庫履歴の「在庫変動理由区分」の表示形式（親/子）が結果の列に書かれていない | 期待結果に入れていない |
