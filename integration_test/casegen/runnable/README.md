# 書かれたとおりに実行できるようにする直し（2026-10-19〜）

結合テストケースの一覧（`../all_test_cases.tsv`）に、書かれたとおりには実行できないケースが残っていた。人が実行するなら補う操作をケースとシードに書き足し、作り方が未確定で外していたケースのうち試験環境を用意すれば作れるものを戻す。

## 依頼者の決定（2026-10-19）

| 決定 | 中身 |
| --- | --- |
| 「おすすめで進めて」 | 人なら補って実行できるもの（決まった番号の読み替え、必須のチェック、確認モーダルの確定）はケースに書き足す。画面で作れない状態は、理由を添えて DB へ直接入れる書き方にする（2026-10-09 の決まり。`../seed_screen/README.md`） |
| 「バッチの実行、スマレジなど外部の試験環境、メールの受け取りは環境準備できる」 | それだけが理由で作り方が未確定だった項目は、作り方を書いて解消する |
| 中継・模擬応答、時刻の固定、障害を起こす手段は「どれも用意しない」 | これらが残る項目は解消しない |

扱わないもの（判断が要る）: IT-M07-01-065（返品の並び順のデータの値が決まっていない。決めると期待結果を左右する）、IT-M03-01-026・053（支店の在庫を編集できる管理者を誰にするか）、IT-M03-18-004（設計書の中の食い違い）。

## 仕組み

| 何 | どこ |
| --- | --- |
| 入力を作る | `build.py kept env`（いまのケース一覧と除外表から）、戻したあと `build.py restored` |
| 今あるケースの直し | `KEPT_PROMPT.md` → `kept/in/<機能ID>.tsv` を `kept/out/<機能ID>.tsv` へ（項目: 商品・控えた番号・割引率・規約同意・確認モーダル） |
| 外したケースを止めている項目の判定と書き直し | `ENV_PROMPT.md` → `env/in/<機能ID>.tsv`（大きい機能は `@1`…に分けた）を `env/out/` へ。`env/in/<機能ID>_cases.tsv` は外したケースと止めている項目 |
| 戻るケースの直し | `build.py restored` → `restored/in/` を `restored/out/`（kept と同じ形） |
| 検査 | `gate.py`（K1〜K9・E1〜E5。env を検査すると戻るケースの一覧 `env/restored.tsv` を作り直す） |
| ケースの正本へ当てる | `apply.py`（gate に合格したファイルだけ。`../datapattern/conflicts/apply_rulings.py` が最後に呼ぶ） |
| レビュー | `review/`（codex の事実確認） |

流す順は今までと同じ: merge → `seed_screen/apply.py` → `datapattern/conflicts/apply_rulings.py`（ここで `product_csv/apply.py` とこの `apply.py` も当たる）→ `exclude_open.py` → `exclude_scope.py` → `build_all_test_cases.py` → `precond/gate_precond.py --all`・`datapattern/gate_dp.py`。

`apply.py` がすること:
- シードとケースの列を置き換える。今の文が in の「今の文」なら置き換え、新しい文なら済み、前にこれが当てた文（`work/applied.tsv` のハッシュ）なら置き換え。どれでもなければ止める（上流で文が変わったので書き直す）。
- 外した表（`../excluded_open_seeds.tsv`・`../excluded_open_cases.tsv` の「元_」列）も直す。`exclude_open.py` が戻すときに直った文で戻る。
- 環境で解消した前提の行を `../precond/open_preconditions.tsv` から `../precond/resolved_preconditions.tsv` へ移す（解消の書き方・区分・根拠・決定つき）。
- 基線のケースの手順・期待結果を変えたら宣言を書く。控えた番号は類型T4（承認「類型承認T4」、手順の種別「発番値控え」）で、`../precond/screen_noted_cases.tsv` に足す。ほかの手順の変更は種別「裁定訂正」。

## 流し直しのための作り（2026-10-20）

- `apply.py` は、同じ列を1回目・2回目・3回目で続けて直したとき、最後の直しの文になっていれば途中の直しを「済み」とみなす。
- 前段の `datapattern/conflicts/apply_rulings.py` と `product_csv/apply.py` は、この直しが当てた文（`work/applied.tsv` のハッシュ）を「済み」とみなす。流し直しのたびに前段が「上流で変わった」と誤って止まらないようにするため。
- 裁定 E04 で足したシード S-M03-01-PAGING-043 は `apply_rulings.py` が毎回 `added_seeds.tsv` から置き直すので、確認モーダルの書き足しを `added_seeds.tsv` の側にも入れた。
- `datapattern/gate_dp.py` は、監査が「除外済み」としたケースが一覧へ戻っていれば通し、件数を参考として出す（66件）。
