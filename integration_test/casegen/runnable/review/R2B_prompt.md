## 確かめること

1. 直した手順が、設計書にある画面・項目・ボタンで書かれ、そのとおりに実行できるか（必須項目、確認モーダル、入力チェック）。
2. 直したシードが作るデータが、元のシードが作ろうとしていたもの（使うケースが確かめる点）と同じか。DB へ直接設定する部分が、画面で作れない部分に限られ、業務名で書かれているか（物理名を書いていないか）。
3. 控えた番号: 呼び名が定義され（どの画面のどこで控えるか）、ケースの置き換えが元の番号と同じものを指すか。期待結果が呼び名の置き換え以外で変わっていないか。番号の大小・並び順に依るケースを見落としていないか。
4. 書き足しが、直す必要の無いところ（ネット買取でない申込み、商品を編集していない「商品を登録」など）に入っていないか。「直さない」の行が本当に直さなくてよいか。
5. 直したところ以外の文が変わっていないか。

## 指摘にしないもの

- 直した部分以外の元の不備（理由の欄に書いてあるものも含む）
- ケースそのものの不備、言い回しの好み、細かくする提案
- 何度も流したときの重複（試験は新しいDBで流す前提）
