## 2回目で増えた項目

### 在庫の承認（シードの投入方法）

在庫変更CSV登録（M04-21）で在庫を入れているのに、承認していない。承認されるまで在庫に入らない（M04-21 L0071〜L0072、M04-32 L0112）。`integration_test/casegen/product_csv/PROMPT.md` の「在庫と価格」の型どおりに、承認通知先（所属選択・メンバー選択）と、登録したメンバーと別の承認権限を持つメンバーが承認一覧で承認する操作を書き足す。承認するメンバーがシードに無ければ、同じ機能の既存のシードの管理者のうち在庫を登録したメンバーと別の者を使い、理由の欄に書く。在庫変更CSV登録が在庫を入れる操作でない（取り込みのエラーを確かめるだけ、など）なら「直さない」。

### 在庫無制限（シードの投入方法）

規格の画面（商品規格登録編集画面）で「在庫無制限」にチェックを入れる書き方になっている。規格の画面に在庫数・在庫無制限の入力欄は無い（M03-09 L0095・L0097）。その部分を「DBで、この商品の規格の在庫無制限を有効にする（規格の画面に入力欄が無いため）」に直す（2026-10-09 の決まり。画面で作れないものは理由を添えて DB へ直接入れる）。ケースが在庫数を使うだけなら、在庫変更CSV登録で十分な数（例 100）を入庫して承認する書き方でもよい。

### 控えた番号（戻るケースの事前準備・手順・期待結果）

戻るケースのシードを試験環境で作る書き方に直したとき、シードが会員IDなどを「登録時に画面が振る番号を控える」呼び名〔…〕で定義した（手がかりに呼び名がある）。ケースの事前準備・手順・期待結果に残っている固定の番号（例 会員ID 807001001）を、その呼び名に置き換える。**期待結果は番号を呼び名に置き換えるだけ**。固定の番号が無い列は「直さない」。シードの呼び名が、ケースのどの番号を指すかは、シードの状態・属性・投入方法（今の文は `runnable/env/out/` の新しい投入方法）で確かめる。
