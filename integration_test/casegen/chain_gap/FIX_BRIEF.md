# レビュー指摘の反映（群 {CODE}・{ROUND}巡目）

codex のレビュー指摘が `integration_test/casegen/chain_gap/review/{CODE}_r{ROUND}_findings.md` にある。

1. **指摘を鵜呑みにしない。** 1件ずつ、指摘が挙げた file:line と、関係する設計書（機能設計書・HTML設計書）・既存ケースを自分で開いて確かめ、採用／一部採用／却下を決める。
   レビュアーの修正案に書かれた語・値もそのまま採らず、設計書の表現で書く。レビュアーも誤る（存在しない記述を引く、範囲を取り違える）。
2. 採用した指摘は、ケース表・シード表・判定表（`gen_{CODE}/chain_judgement.tsv`）を直す。直せない（設計書に根拠が無い）ケースは削除し、判定表の判定と根拠も直す。
   削除・追加したら、テストIDとケース専用シードIDの番号を振り直し、連番を保つ。
   判定を「作成」に変えてケースを足すときも、元の依頼文 `gen_{CODE}/prompt.md` の規則（ケースにしてよい条件、縛り、出力）にすべて従う。
   **作業用の生成スクリプトでケース表を作り直さない**（依頼元が手で直した箇所が消える）。表は直接直す。
3. 裁定を `integration_test/casegen/chain_gap/review/{CODE}_r{ROUND}_dispositions.tsv` に書く。タブ区切り・ヘッダ付き:
   `指摘	裁定	確認した根拠	直したこと`（指摘は「指摘1」など。裁定は 採用／一部採用／却下。根拠は file:line。却下の理由は根拠の列に書く。直したことは、変えたテストID・判定・削除・追加）
4. `gen_{CODE}/report.md` の末尾に「レビュー{ROUND}巡目の反映」の節（判定の変更、件数の増減、削除・追加したケース）を足す。
5. `python3 integration_test/casegen/chain_gap/verify_chain.py {CODE}` を合格させる。

ファイルの書き込みを拒否されたときは、回避せず、書くはずだった本文を返答に載せる（依頼元が保存する）。
触ってよいのは群 {CODE} のケース表・シード表・判定表・report.md・裁定ファイルと gen_{CODE}/ の作業用ファイルだけ。git の変更操作はしない。

返答は3行以内: 採用・一部採用・却下の件数、判定とケース数の増減、verify の結果。
