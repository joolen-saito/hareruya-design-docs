# レビュー指摘の反映（群 CB・1巡目）

codex のレビュー指摘が `integration_test/casegen/chain_gap/review/CB_r1_findings.md` にある。

1. **指摘を鵜呑みにしない。** 1件ずつ、指摘が挙げた file:line と、関係する設計書（機能設計書・HTML設計書）・既存ケースを自分で開いて確かめ、採用／一部採用／却下を決める。
   レビュアーの修正案に書かれた語・値もそのまま採らず、設計書の表現で書く。レビュアーも誤る（存在しない記述を引く、範囲を取り違える）。
2. 採用した指摘は、ケース表・シード表・判定表（`gen_CB/chain_judgement.tsv`）を直す。直せない（設計書に根拠が無い）ケースは削除し、判定表の判定と根拠も直す。
   削除・追加したら、テストIDとケース専用シードIDの番号を振り直し、連番を保つ。
   判定を「作成」に変えてケースを足すときも、元の依頼文 `gen_CB/prompt.md` の規則（ケースにしてよい条件、縛り、出力）にすべて従う。
   **作業用の生成スクリプトでケース表を作り直さない**（依頼元が手で直した箇所が消える）。表は直接直す。
3. 裁定を `integration_test/casegen/chain_gap/review/CB_r1_dispositions.tsv` に書く。タブ区切り・ヘッダ付き:
   `指摘	裁定	確認した根拠	直したこと`（指摘は「指摘1」など。裁定は 採用／一部採用／却下。根拠は file:line。却下の理由は根拠の列に書く。直したことは、変えたテストID・判定・削除・追加）
4. `gen_CB/report.md` の末尾に「レビュー1巡目の反映」の節（判定の変更、件数の増減、削除・追加したケース）を足す。
5. `python3 integration_test/casegen/chain_gap/verify_chain.py CB` を合格させる。

ファイルの書き込みを拒否されたときは、回避せず、書くはずだった本文を返答に載せる（依頼元が保存する）。
触ってよいのは群 CB のケース表・シード表・判定表・report.md・裁定ファイルと gen_CB/ の作業用ファイルだけ。git の変更操作はしない。

返答は3行以内: 採用・一部採用・却下の件数、判定とケース数の増減、verify の結果。

## この巡だけの注意

- 既存ケース（`integration_test/casegen/cases/` の IT-M03-05-011 など）は変更しない。レビュアーが既存ケースの書き換えを修正案にしていても、この作業の範囲外なので採らず、裁定の根拠に「既存ケースは変更しない（依頼文の制約）」と書く。必要なら report.md の「設計書の不備」の後ろに「既存ケースの気づき」として書く。
- 判定を「作成」に変えてケースを足すときは、同じ契機の保留ケース（`excluded_hold_cases.tsv` の IT-M03-02-044 など）の保留の理由を読み、新しいケースがその理由を抱えないことを確かめる。抱えるなら「作れない」のままにし、理由を根拠に書く。
