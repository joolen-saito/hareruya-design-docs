# 類似・重複ケースの判定の事実確認（V_02）

作業場所は `/home/y-saito/Developments/hareruya-design-docs`。読むだけで、ファイルは書き換えない。

結合テストケースのうち「ほかのケースと同じことを確かめていて、外しても見つけられる不具合が減らない」とされたケースが、本当にそうかを確かめる。判定の決まりは `integration_test/casegen/dedup/DEDUP_PROMPT.md`（機能をまたぐ組は `CROSS_PROMPT.md` も）。依頼者の線引きは「同じ確認に加えて、設計書上で同じ扱いになる値（同値）を別々のケースで確かめているものは代表1件に絞る。境界の両側と、設計書が別の結果を定める値は残す」。

## 確かめる対象

`integration_test/casegen/dedup/review/V_02_targets.tsv`（外すテストID・残すテストID・種別・根拠・理由）。各行の両ケースの全文は `integration_test/casegen/dedup/inputs/<機能ID>.md`、設計書の写しは `integration_test/casegen/combination/units/<機能ID>/design.txt`。

## 見ること（行ごと）

1. 外す側が確かめていることを、残す側が全部確かめているか。外す側にしかない条件・操作・確かめる所（画面の表示、DB、メール、CSV の列、遷移先など）が1つでもあれば誤り。
2. 同値なら、根拠の行に、両方の値が同じ1つの定めの同じ側に入ることが書かれているか。設計書が別々の条件・別々の結果として書いた値、境目の値とその隣の値、設計書がはっきり同じ扱いと書いていない表記・画面・言語・店舗・会員区分・権限の違いは、外してはいけない。
3. 要因の組合せのケース（inputs の `[組 …]`）を、組の値が違うのに外していないか。
4. 機能をまたぐ組は、同じ画面の同じ操作で同じ結果を確かめているか。

疑わしいときは「戻す」にする（外しすぎはテストの抜けになる）。外す側の見落とし（ほかにも重複がある）は探さなくてよい。

## 出力

最後に次の形の表だけを、`===BEGIN===` と `===END===` の行で挟んで出す（タブ区切り、1行目は見出し、対象の全行に1行ずつ）。

```
===BEGIN===
外すテストID	判定	理由
IT-XXX-XX-NNN	採る	（短く）
IT-XXX-XX-NNN	戻す	外す側にしかない確かめる所: …
===END===
```

判定は「採る」か「戻す」。戻すときは理由に、外す側にしかないもの、または同値と言えない根拠（設計書の行）を書く。
