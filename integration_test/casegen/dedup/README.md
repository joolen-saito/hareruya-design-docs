# 類似・重複ケースの除外（2026-10-21〜）

依頼者（2026-10-21）: 「結合テストケースにおいて、類似および重複のテストケースがないかチェックして。あれば、除外して」

## 依頼者決定（同日 AskUserQuestion）

線引きは「**同じ扱いの値もまとめる**」: 条件・操作・確かめる結果が同じで ID・名前・言い回しだけ違うもの、別のケースに丸ごと含まれるものに加えて、設計書上で同じ扱いになる値（同値）を別々のケースで確かめているものは代表1件に絞る。境界の両側と、設計書が別の結果を定める値は残す。外したケースは削除せず除外表へ移し、Playwright・E2E のあるケースは残す側にする。

## 調べたこと（判定の前）

- 文字の完全一致は0組（事前準備・手順・期待結果）。シードもデータ名もケースごとに番号付きのため。
- 番号とシード名を伏せて比べると、手順と期待結果が同じ組は135組あったが、ほとんどは前提データの値を変えて別の分かれ目を確かめる組（非公開／状態EX／0円、未設定／空、日本語／英語など）。文字の似方では重複と言えないので、全ケースを中身で判定した。

## 合流の順

merge → `seed_screen/apply.py` → `datapattern/conflicts/apply_rulings.py` → `exclude_open.py` → `exclude_scope.py` → **`exclude_dup.py`** → `build_all_test_cases.py` → `precond/gate_precond.py --all`・`datapattern/gate_dp.py`。
gate_precond（G6）・gate_dp は `excluded_dup_cases.tsv` を除外として数える。採番する道具（combination/build_targets.py・link_flow/merge_flow.py・chain_gap/merge_chain.py）は外した番号を使わない。

## 決まり（DEDUP_PROMPT.md の要点）

- 迷ったら残す。
- 設計書が別々に書いた条件（AND の外れ方、列挙の別項目）・境目の値とその隣・確かめる所の違い（画面／DB／メール／CSV）・何が不正かの違いは残す。
- 表記・画面・言語・店舗・会員区分・権限の違いは、設計書が同じ扱いとはっきり書いているときだけ同値。
- 組合せのケースどうしは組の値が全部同じときだけ外せる。組でないケースは組合せのケースに含まれれば包含で外してよい。
- E2E・Playwright のあるケースは外さない。
