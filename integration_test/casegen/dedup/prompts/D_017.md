# 類似・重複ケースの判定（機能 F01-01・F01-02）

作業場所は `/home/y-saito/Developments/hareruya-design-docs`。結合テストケースのうち、ほかのケースと同じことを確かめていて、外しても見つけられる不具合が減らないケースを選ぶ。**迷ったら残す。** 外しすぎはテストの抜けになり、残しすぎは手間が増えるだけなので、外す側に倒さない。

依頼者の決定（2026-10-21）: 「類似および重複のテストケースがあれば除外する」。線引きは「同じ確認に加えて、設計書上で同じ扱いになる値（同値）を別々のケースで確かめているものは代表1件に絞る。境界の両側と、設計書が別の結果を定める値は残す」。

## 読むもの

- 機能ごとのケース一覧: `integration_test/casegen/dedup/inputs/<機能ID>.md`（先頭に設計書の写しと要因表の場所）
- 設計書の写し: `integration_test/casegen/combination/units/<機能ID>/design.txt`（行頭 L0001…）。共通シートは `combination/units/_common/`
- 要因表（あれば）: `combination/factors/<機能ID>_factors.tsv`。値は設計書の分かれ目ごとに選んだ代表で、値が違えば別の扱い

ケースの印: `[E2E]` テストコードがある、`[PW:合格]` などは Playwright の結果がある、`[組 CB-…: …]` 要因の組合せのケース（組の値つき）、`[DP]` データパターン監査で足したケース。

## 外してよい3種

| 種別 | どういうときか |
| --- | --- |
| 同一 | 事前準備の条件・操作・確かめる結果が同じ。違うのはテストID、シードの名前・番号、データの名前（商品名・会員名など）、言い回し、確かめる順番だけ |
| 包含 | 残す側が、外す側と同じ条件で同じ操作をし、外す側が確かめる結果を全部確かめている（残す側がそれ以上を確かめるのはよい）。外す側にしかない条件・操作・確かめる所が1つも無い |
| 同値 | 違いのある値（データ・入力値・設定値）が、設計書の同じ1つの定めの同じ側に入り（同じ結果になり）、確かめる結果も同じ。設計書の写しの行を根拠に挙げる。違いが2か所以上あるときは、どの違いも同値であること |

## 外さない（残す）もの

1. 設計書が別々の定め・別々の結果として書いたもの。別のメッセージ、別の分岐、条件の列挙の別の項目は別のケース。例: 「公開・状態NM・買取価格1円以上のものを出す」の外れ方（非公開／NM以外／0円）は別々の条件の確認なのでどれも残す。同値は、**同じ1つの条件**に入る値どうしだけ。
2. 境界。設計書が数・文字数・桁・日時・金額・件数の境目を書いているとき、境目の値とその隣の値（上限と上限+1、下限と下限-1、ちょうどと超え）は残す。境目から離れた値で、同じ側に境目の値のケースがあるものは同値として外してよい（残す側は境目の値のケース）。
3. 表記の違い（大文字と小文字、全角と半角、空と未設定、前後の空白、0 と空）や、画面・表示言語・店舗（本店/支店）・会員区分・権限・端末・ブラウザの違いは、設計書が同じ扱いと**はっきり書いているときだけ**同値。書いていなければ残す。
4. 確かめる所が違うもの（画面の表示だけ／DB／メール／CSV の中身／ログ／遷移先）。同じ操作でも確かめる所が違えば別のケース。ただし包含に当たれば外してよい。
5. 異常系で、何が不正か（どの項目のどんな誤りか）が違うもの。同じエラーメッセージでも項目が違えば残す。同じ項目の同じ種類の誤り（例: 数字欄に英字「abc」と「xyz」）は同値。
6. 要因の組合せのケース（`[組 …]`）どうしは、組の値が全部同じとき（同一・包含）だけ外せる。組の値が違えば同値として外さない（2つの要因の値の組が埋まらなくなる）。組でないケースが組合せのケースに含まれるときは、包含で組でないケースを外してよい。
7. `[E2E]` か `[PW:…]` の付いたケースは外さない。重複の組に入っていれば残す側にする。両方に付いていれば両方残す。
8. 状態を積み上げる一連の確認（前のケースの結果を使う）や、同じデータを2回操作して2回目の動きを確かめるもの（二重登録・再実行）は、1回目だけのケースと別。

## 残す側の選び方

`[E2E]`・`[PW:…]` の付いたもの → 包含で確かめる所が多いもの → 境目の値のもの → テストIDの番号が小さいもの。外すケースの残す側に、外すケースを指さない（残す側は必ず残るケース）。同じ重複の組は1件の残す側にまとめる。

## 進め方の目安

1. ケース一覧で、手順と期待結果が似たケースの組を拾う（並びが離れていても見る。番号が離れた所に、後の監査や組合せで足した同じ確認があることが多い）。
2. 組ごとに事前準備の違いを書き出し、違いが同一・包含・同値のどれかに当たるか、当たらないかを決める。
3. 同値は設計書の写しで、両方の値が入る定めの行を確かめてから書く。行を確かめられなければ残す。

## 書くもの（機能ごとに1ファイル。外すケースが無い機能も見出しだけのファイルを書く）

`integration_test/casegen/dedup/judg/<機能ID>.tsv`（タブ区切り・1行目は見出し）

| 列 | 中身 |
| --- | --- |
| 外すテストID | 外すケース |
| 残すテストID | 同じことを確かめていて残るケース（同じ機能） |
| 種別 | 同一｜包含｜同値 |
| 根拠 | 同値は設計書の写しの行（例 `L0123,L0130-L0132`）。同一・包含は `—` |
| 理由 | 何が同じで、何が違い、その違いがなぜ結果を変えないか。1〜2文。セルの中にタブと改行を入れない |

ほかのファイルは書き換えない（ケースの正本・inputs・設計書には触らない）。最後に、機能ごとの外す件数（種別ごと）と、迷って残した組があれば2〜3件を短く報告する。
