### 指摘（M05-11 / IT-M05-11-230）
- 主張: 230・232・233・235は明細の削除・追加後に在庫を確認するが、商品総原価を期待結果で確認していない。
- 実際: 設計書 L0137 は「数量を減らすとき→総原価に(注文)原価単価を戻す」、L0138 は「数量を増やすとき→総原価から原価単価を引く」と定める。L0189-L0191 には商品をキャンセルした場合、注文総原価を戻す例がある。
- 判定: 要因の結果が欠けている
- 修正案: 4件とも商品総原価の更新結果を期待結果に加える。特に原価単価が変動した232・235では、事前準備の単価に基づく値を確認する。

### 指摘（M05-11 / IT-M05-11-239）
- 主張: 239・240・241は、上限と在庫数の組ごとに更新結果を確かめるが、支店への在庫更新通知を確認しない。
- 実際: 設計書 L0583 は受注全体の更新で「本店の在庫が変わったことを支店へ知らせる」と定める。L0590 は「合計金額が上限を超えたとき」は通知が先に送られ、「明細の数量が在庫数を超えたときは、通知も送らない」と定める。
- 判定: 要因の結果が欠けている
- 修正案: 各組について通知の有無を確認する。少なくとも240の通知なしと241の通知ありは、両組を区別する期待結果として必要である。

### 指摘（M05-11 / IT-M05-11-257）
- 主張: 257〜272はキャンセル後の在庫・週間販売数・会員の保持ポイントを確認するが、ポイント履歴の削除とスマレジ連携を確認しない。
- 実際: 設計書 L0119 はキャンセル時に「ポイント履歴を削除する」と定める。L0611 は、削除した履歴の変動量の合計が0でなければ同じ量をスマレジへ連携し、0ならスマレジに触れないと定める。
- 判定: 要因の結果が欠けている
- 修正案: 257〜272で対象受注のポイント履歴が削除されたことを確認する。あわせて、履歴合計が0のケースでは連携なし、0でないケースでは50の連携を確認する。
