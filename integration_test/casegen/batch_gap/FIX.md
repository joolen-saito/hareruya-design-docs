# レビュー指摘の反映（{ROUND}巡目）

codex のレビュー指摘が `integration_test/casegen/batch_gap/review/r{ROUND}_findings.md` にある。

1. **指摘を鵜呑みにしない。** 1件ずつ、指摘が挙げた file:line と関係する設計書を自分で開いて確かめ、採用／一部採用／却下を決める。レビュアーの修正案の語もそのまま採らず、設計書の表現で書く。
2. 採用した指摘は `questions.tsv` を直す。論点を削除・追加したら、論点IDを BG-001 からの連番に振り直す（`report.md` の参照も合わせる）。
   - 内部の制御用の値で、設計書が画面での扱いを書いていないものは、「画面で表示すべき」という前提を外し、「画面では扱わない内部の値という設計でよいですか」の形で問う。答えが「よい」なら連携先は不要になる問いであることが分かるようにする。
   - 既にある論点（`hold_review/current/issues.tsv` など）が確定するまで問えないものは、論点から外し、`report.md` に「既存の論点 <ID> の確定待ち」と書く。
   - 追加する論点も、元の依頼文 `PROMPT.md` の規則（区分、論点にしないもの、確かめ方、出力の形）にすべて従う。
3. 裁定を `integration_test/casegen/batch_gap/review/r{ROUND}_dispositions.tsv` に書く。タブ区切り・ヘッダ付き:
   `指摘	裁定	確認した根拠	直したこと`（裁定は 採用／一部採用／却下。根拠は file:line。却下の理由は根拠の列に書く）
4. `report.md` を現在の状態に合わせて直し（件数、バッチごとの結論）、末尾に「レビュー{ROUND}巡目の反映」の節を足す。

書いてよいのは `questions.tsv`・`report.md`・裁定ファイルと `work/` の作業用ファイルだけ。git の変更操作と、外部サービスへの書き込みはしない。
ファイルの書き込みを拒否されたときは、回避せず、本文を返答に載せる。

返答は3行以内: 採用・一部採用・却下の件数、論点の件数の増減（区分ごと）。
