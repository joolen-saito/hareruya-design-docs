# 共有の開発環境の設定を書き換えるシードへの書き足し（shared_env/）

依頼者（2026-10-26）「送料無料条件のように、安易にデータを変えると開発環境を触っている他の方に混乱を招く」。

結合テストのケースは共有の開発環境でも人が手で流す。シードの中に、共有の開発環境で全員が使う1件しかない設定
（店舗基本設定・追加システム設定・CSV出力項目設定・既存の配送方法/支払方法・税率・IP許可リスト・外部の接続先など）を
書き換えたり、ほかの人のデータも消える全件削除をしたりするものがある。それらのシードの「投入方法」の末尾に、
扱い方の文（「／≪共有の設定≫…」）を書き足す。ケースの手順・期待結果は変えない。

## 判定と書き足す文

文の正は `apply.py` の TEMPLATES。

| 判定 | 扱い | 依頼者の決定 |
|---|---|---|
| 変えない | 書き足さない（新規登録だけ・参照だけ・ケース専用のものだけを変える） | — |
| 戻す | 書き換える前に今の値を控え、ケースが終わるたびに控えた値へ戻す | 2026-10-26（戻す先は ee の標準値でなく開発環境の今の値。送料無料は 30,000円） |
| 手元だけ | 共有の開発環境では行わず手元の環境で行う（店舗ID 1 の店名・メール、設定ファイル、全件削除など） | 2026-10-26 |
| IP | IP 許可リストは空なら設定しない。空でなければ1行書き足し、後でその行だけ消す | 2026-10-26（1行でも入れるとリストに無い人が全員入れなくなる。`IpAddrListener.php`） |
| API設定済み | API の認証の秘密値・署名方式は書き換えず設定済みの値を使う | 2026-10-26「設定済みの値を使う」 |
| 設定済み | 外部の接続先・資格情報・メール送信先は書き換えず設定済みの値を使う | API の決定にそろえた（親の判断・報告済み） |
| 消す | 全員の一覧や選択肢に出るもの（税率・選択肢）を足したら、ケースの後に削除する | 2026-10-26「終わったら消す」 |

事実（ee で確かめ済み）: 店舗基本設定画面は常に店舗ID 1（`BASE_INFO_ID=1`）を書き換える（`ShopController::index` の `getMallBaseInfo()`）。
税率は適用日が新しいものが勝ち、店舗に関係なく全員に効く（`TaxRuleRepository::getByRule`）。

## ファイル

- `decisions.tsv` … シードID・判定・設定・書き足す文・理由。種類の違う書き換えが混ざるシードは同じシードIDで複数行。
- `apply.py` … decisions.tsv を `../cases/*_seed_data.tsv` と `../excluded_*_seeds.tsv` に当てる。何度流しても同じ。
  `../datapattern/conflicts/apply_rulings.py` の最後（dummy_url/apply.py の後）から呼ばれる。
- `work/` … 候補の拾い出し（candidates.py・candidates.tsv・part3.tsv）、担当への指示（BRIEF.md）、担当の判定（judge1〜3.tsv）。
- `review/` … codex の敵対レビュー（R1・R2）。

## 流す順

merge → seed_screen/apply.py → datapattern/conflicts/apply_rulings.py（最後にこれを呼ぶ）→ exclude_open.py → exclude_scope.py
→ exclude_dup.py → exclude_ut.py → build_all_test_cases.py → precond/gate_precond.py --all。
単独で `python3 shared_env/apply.py` を流してもよい（書き足しは末尾だけで、外した表にも当てる）。
