# 共有の開発環境の設定を書き換えるシードの判定（担当向け）

## 背景
結合テストのケース（`integration_test/casegen/cases/<機能ID>_test_cases.tsv`）は、シード表（`cases/<機能ID>_seed_data.tsv`）のシードを使う。
ケースは共有の開発環境でも人が手で流す。シードの中に、**共有の開発環境で全員が使う1件しかない設定**（例: 店舗基本設定の送料無料条件）を
書き換えるものがあり、流すとほかの開発者の画面・メール・連携が変わって混乱する（依頼者 2026-10-26）。

依頼者の決定（2026-10-26）:
- ② 変えないと試せない設定は、**変える前に今の値を控え、ケースが終わったら控えた値に戻す**手順を足す（戻す先は ee の標準値ではなく、開発環境の今の値）。
- ③ 店舗ID 1 の会社名・店名・メールアドレスのように、一時的にでも変えるとほかの人に大きく影響するものは、**共有の開発環境では行わず手元の環境で行う**と明記する。
- ケースの期待結果・手順は変えない。シードの「投入方法」の末尾に文を書き足すだけ。

## 事実（ee のソースで確かめ済み）
- 管理画面「店舗設定＞基本設定」（店舗基本設定画面・旧ショップマスター）は、ログインした管理者の所属に関係なく**常に店舗ID 1（モール全体）**を書き換える（`BASE_INFO_ID=1`）。
  送料無料条件(金額/数量)・7つのトグル（商品ごとの送料・複数配送・仮会員・マイページの注文状況表示・お気に入り商品・自動ログイン・在庫切れ商品の非表示）・会社名・店名・各メールアドレスなど。
  カートの「送料無料まであと○円」もこの値。開発環境の値は 送料無料(金額)=30,000・(数量)=空・自動ログイン=有効 など。
- 「追加システム設定」は mtb_option（モール全体で1件ずつ）。まとめて買取商品ID・固定価格商品部門ID・入荷通知最大数・各種通知メールアドレス・Small packet 閾値・管理画面自動ログアウト時間・スマレジ接続先/トークン など。
- 「セキュリティ管理」の IP 許可リスト（管理画面用・フロント用）は、**1行でも入れると、リストに無い人は全員アクセスできなくなる**（`IpAddrListener.php`）。空なら全員許可。
- 既存のメールテンプレート・CSV出力項目設定・既存の配送方法/支払方法の料金や手数料・既存の権限グループ・税率・ポイント設定・会員規約/特商法の本文も、変えれば全員に影響する。
- 試験環境の設定ファイル・環境変数を書き換えて再起動するものは、サーバー全体に効く。

## やること
入力: `integration_test/casegen/shared_env/work/part{N}.tsv`（列: 機能・シードID・共有・拾った語・使うケース数・論理名・状態・属性・用途・投入方法）。
語で広めに拾った候補なので、大半は「新しい店舗・配送方法・管理者・権限グループ・テンプレートを**新規登録するだけ**」で共有設定を変えない。

各行について判定し、`integration_test/casegen/shared_env/work/judge{N}.tsv` に書く。列（タブ区切り・1行目は見出し）:
`シードID	判定	設定	書き足す文	理由`

判定は次のどれか1つ:
- `変えない` … 新規登録だけ、参照だけ、ケース専用に新しく作ったもの（新規の店舗・配送方法・権限グループ・テンプレート等）を変えるだけ、確かめるだけ。書き足す文は空。
- `戻す` … 共有の既存設定を書き換える（②）。
- `手元だけ` … 店舗ID 1 の会社名・店名・店名(英語)・各メールアドレス・住所・電話等の基本情報を書き換える／設定ファイル・環境変数を書き換えて再起動する／スマレジなど外部の接続先・アクセストークンを書き換える（③）。
- `IP` … セキュリティ管理・API の IP 許可リストに試験端末の IP を入れる。
- `要相談` … 上のどれか決められないもの（例: 共有の認証の秘密値・署名方式を書き換える、既存店舗の店舗種別を変える、税率を足す）。理由に何が決められないかを書く。

「設定」には書き換える設定を画面の言葉で書く（例: 店舗基本設定の送料無料条件(金額)・送料無料条件(数量)）。

書き足す文は判定ごとに次の形をそのまま使い、{ } だけを埋める（言い回しを変えない。文はシードごとに1つ）:
- 戻す: `〔共有の設定〕{設定}は共有の開発環境で全員が使う1件だけの設定なので、書き換える前に今の値を控え、このシードを使うケースが終わるたびに控えた値へ戻す。`
- 手元だけ: `〔共有の設定〕{設定}を書き換えると共有の開発環境を使うほかの人に影響するため、共有の開発環境では行わず手元の環境で行う。`
- IP: `〔共有の設定〕IP許可リストは1行でも入れるとリストに無い人が全員アクセスできなくなる。リストが空のときは設定しない。空でないときは今の行を残したまま試験端末のIPを1行書き足し、このシードを使うケースが終わったら書き足した行だけを消す。`
- 要相談: 空。

複数の種類が1つのシードに混ざるとき（例: IP と認証の秘密値）は、判定は重いほう（手元だけ＞要相談＞IP＞戻す）にし、理由に混ざっていることを書く。

## 守ること
- **書き足す文以外は作らない。シード表・ケース表は書き換えない**（読むだけ）。
- 判定は投入方法の文から根拠を持って行う。ケースの事前準備を読む必要があれば `cases/<機能ID>_test_cases.tsv` の使用シード列で引く。
- 「各ケースが開始時に必要な値を自分で設定する」と書かれた共有のシードは、たいてい既存の1件だけの設定を書き換えている（`戻す` 候補）。
- 新規に作った自分専用のもの（例: 「ケース専用の店舗」「試験店舗A」、新規登録した配送方法）を編集するのは `変えない`。
- 店舗基本設定画面は常に店舗ID 1 を書き換えるので、「基本設定で〇〇を入れて設定」は新しい店舗の登録ではなく既存の書き換え。店舗の新規登録は「店舗登録」画面（M10-15 等）で別物。
- 入力の全行を判定する（判定漏れ 0）。最後に `judge{N}.tsv` の行数が入力の行数と一致することを確かめる。
- マシンが重いので、重い処理・全体検索はしない（対象ファイルだけ読む）。

## 返すもの
判定ごとの件数、`要相談` の一覧（シードID・理由を短く）、迷った例を3つまで。

## 追記（2026-10-26・part3 から）
依頼者の決定と codex R1 の確認で、判定の種類を足した。part3 はこの追記も含めて判定する。
- `設定済み` … 外部の接続先・資格情報・メール送信先（試験用メール受信環境へ向ける等）・オブジェクトストレージの接続先などを設定する。共有の開発環境では書き換えず設定済みの値を使う。
  文: `〔共有の設定〕共有の開発環境では{設定}を書き換えず、環境に設定済みの値を使う（値は環境の管理者から受け取る）。手元の環境では記載の値を設定してよい。`
- `API設定済み` … APIの認証の秘密値・署名方式を設定する（IP許可を含んでもよい）。文は apply.py の TEMPLATES["API設定済み"] をそのまま使う（{設定}なし）。
- `消す` … 全員の一覧に出る共有のものを足す（税率など）。文: `〔共有の設定〕{設定}は共有の開発環境で全員の一覧に出て、適用日が来ると全員に効くため、このシードを使うケースが終わったら、このシードで足したものを削除する。`
- **既存データの全件削除・「既存の行があればすべて削除」・DBで直接の全件削除**（ケース専用でない、ほかの人のデータも消えるもの）は `手元だけ`。
  ケース専用に作ったものだけを消す（例: 「F…-N で始まるデッキ」を検索して消す）なら `変えない`。条件で絞った削除が他人のデータに当たりうるかは文から判断し、当たりうるなら `手元だけ`。
- 1つのシードに種類の違う書き換えが混ざるときは、**同じシードIDの行を複数**書く（種類ごとに1行。例: `戻す` の行と `設定済み` の行）。
- 文の正は `integration_test/casegen/shared_env/apply.py` の TEMPLATES。書き足す文は TEMPLATES の {設定} を埋めた文と完全に一致させる。
