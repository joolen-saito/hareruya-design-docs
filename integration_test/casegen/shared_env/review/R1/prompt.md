# 敵対レビュー: 共有の開発環境の設定を書き換えるシードの判定（R1）

あなたは独立したレビュアーです。著者（別の担当）が付けた判定の誤りを探してください。ファイルは読むだけで、書き換えないでください。

## 対象
- 判定表: `integration_test/casegen/shared_env/review/R1/input.tsv`（1,744行。列: 機能・シードID・判定・設定・理由・共有・使うケース数・用途・投入方法）

- シードを使うケースの事前準備・手順は `integration_test/casegen/cases/<機能ID>_test_cases.tsv`（使用シード列で引く）

## 依頼者の決定（2026-10-26。正として扱う）
共有の開発環境で全員が使う1件しかない設定をケースが書き換えると、ほかの開発者が混乱する。
- 変えないと試せない設定は、変える前に今の値を控え、ケースが終わったら控えた値に戻す（判定「戻す」）。
- 一時的にでも変えるとほかの人に大きく影響するもの（店舗ID 1 の会社名・店名・メール等、設定ファイル・環境変数・外部接続先の書き換え、全件削除など）は共有の開発環境では行わず手元の環境で行う（判定「手元だけ」）。
- IP 許可リストは判定「IP」。決められないものは「要相談」。
- 新規登録だけ・参照だけ・ケース専用に新しく作ったものを変えるだけなら「変えない」。

## 重点
1. **「変えない」なのに、共有の既存設定・既存マスタ（店舗ID 1 や既存店舗の設定、追加システム設定、既存の配送方法・支払方法・メールテンプレート・権限グループ・CSV出力項目、税率、ページレイアウト、設定ファイル等）を書き換えている行**（見逃し。最重要）。
2. 「戻す」なのに、控えて戻すだけでは済まない行（全件削除・DB直接書き換え・設定ファイル・外部接続先・店舗ID 1 の店名やメール）＝「手元だけ」にすべきもの。逆に「手元だけ」だが控えて戻せば済む行。
3. 「戻す」「手元だけ」なのに、実際は新規に作ったケース専用のもの（新しく登録した店舗・配送方法など）しか変えていない行＝「変えない」。
4. 「設定」欄の名前が投入方法の文と合っていない行（別の設定名を書いている）。

候補の拾い方（語で拾った1,744行）自体の漏れ（候補に入っていない共有設定の書き換え）に気づいたら、それも指摘してよい（シード表 `cases/*_seed_data.tsv` を語で引く範囲で）。

## 対象外
- 書き足す文の言い回し（形は決まっている）。
- ケースの期待結果や手順そのものの良し悪し。
- 「要相談」の行の結論（依頼者が決める）。

## 出力
指摘が無ければ `NONE` の1語。あれば1件ずつ:
`シードID / 今の判定 / 正しい判定 / 根拠（file:行 または 投入方法の該当句）`
同じ理由の行がまとまっていれば、まとめて書いてよい（シードIDを列挙）。
