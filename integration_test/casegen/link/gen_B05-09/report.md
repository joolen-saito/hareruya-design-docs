# B05-09 連携ケース報告

## 作成したケース数
2件（IT-B05-09-L001、IT-B05-09-L002）。採用した上流→下流は B05-09→M08-06、B05-09→F06-05。

## 判定IDごとの評価表
判定IDは台帳が当てている IT-0334（バッチ→画面）のみ。

| 下流候補 | 評価 | 理由 |
| --- | --- | --- |
| M08-06 | 採用（L001） | 会員のポイント残高と履歴の増減量・備考を表示する。B05-09が補正する保有ポイントとポイント履歴と同じデータ |
| F06-05 | 採用（L002） | 共通ヘッダーの保有ポイントを選手情報から取得して表示する。補正後の保有ポイントの受け渡しを見る |
| F06-10 | 不採用 | 機能設計書が「刷新後は実装しない（廃止）」としている |
| M08-05 | 不採用 | 設計書の表示範囲は履歴の絞り込みなし・有効期限のみで、本件で確かめる増減量・備考の記述がM08-06より弱く、M08-06で判定済み |
| M08-04 | 不採用 | ポイント確認画面への遷移ボタンの記述のみで、ポイントの値の表示を定めていない |
| F02-05 | 不採用 | 通知の設計書に再連携の登録データを取得する記述が確認できない |
| F06-01, F06-02, F06-08, F06-09, F06-13, F06-14, F06-16, F06-17, F06-18, F06-21, F06-26, F07-04 | 不採用 | 再連携が更新する受注・保有ポイント・ポイント履歴を取得・表示する記述が無い（候補は機械抽出で、連携が実在しない） |
| M07-01 | 不採用 | ネット買取の検索一覧で、スマレジ取引とは別のデータ |
| M08-03, M08-10 | 不採用 | 顧客情報CSV・本人確認の機能で、ポイント履歴を扱う根拠が設計書に無い（M08-03はポイントを含むが列定義が設計書から断定できないため作らない） |
| M12-01, M12-02, M12-05, M12-06 | 不採用 | 日別/月別集計・入荷通知依頼が対象で、再連携の更新データと対応しない |

別の判定IDの検討: 画面遷移（IT-0338/0339）の連鎖は無く、台帳もB05-09に当てていない。

取消・打消の再連携（B05-09要求R018・R019）で受注がキャンセルになる点は、受注一覧・受注編集の機能が下流候補に無いため作らなかった。
