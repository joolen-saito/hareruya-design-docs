# 範囲を広げた判定単位でケースを足す作業（依頼者決定 2026-10-06）

リポジトリ: `/home/y-saito/Developments/hareruya-design-docs/`。作業場所は `integration_test/casegen/link/`。出力はすべて日本語で書く。

依頼者が次を決めた。

- 設定値の判定（IT-0337）に限り、**CSV出力・帳票**を下流に含める。
- **IT-0340** を足した:「管理画面でデータを登録または更新した場合、そのデータを取得元と定められた別機能の参照画面に、設計どおり受け渡されること。」
  マスタ・設定に限らない管理画面の更新を上流とし、別機能の参照画面（一覧・詳細・履歴・入力欄の初期表示）を下流とする。

書き方の規則は `GEN_LINK_PROMPT_TEMPLATE.md` の全文に従う（「判定IDごとの範囲」「ケースにしてよい条件」「縛り」「出力」）。`AGENT_BRIEF.md` の 3・4・9・10 も守る。
`{FID}` などの置き換え文字は、渡された機能IDに読み替えよ。

## あなたの作業

渡された機能IDを上流として、下の表の「見る連携」を設計書で確かめ、書けるものだけを**既存のケースの後ろに足す**。

- `cases/<機能ID>_link_test_cases.tsv` と `cases/<機能ID>_link_seed_data.tsv` に既にある行は変えない（ファイルが無ければ規定のヘッダで作る）。
- テストIDは既存の続きの番号。ケース専用シードIDの末尾はケース番号に合わせる。
- 表の連携は、これまでの著者が「範囲外だが価値がある」と報告した手がかりにすぎない。**設計書の両側に記述があること**を自分で確かめ、無ければ書かない。0件でよい。
- 上流と下流が同じ機能（同じ機能IDの一覧・編集）の中で完結する確認は書かない。
- 既存ケース（`integration_test/casegen/all_test_cases.tsv` と `link/cases/`）に、同じ上流操作をして同じ下流を確かめるものがあれば書かない。
- 件数は1機能につき最大4件。同じ判定を項目違いで増やさない。
- `gen_<機能ID>/report.md` の末尾に「範囲を広げて足したケース」の節を足す（判定IDごとの評価、対応表、重複の確認、到達可能性、書かなかったものと理由）。report.md が無ければ作る。
  保存を拒否されたら、回避せず、足す節の本文だけを返答に載せよ。
- 最後に `python3 integration_test/casegen/link/verify_link.py <機能ID>` を実行し、合格するまで直せ。
- 触ってよいのは、その機能IDの `cases/` の2ファイルと `gen_<機能ID>/report.md` だけである。
