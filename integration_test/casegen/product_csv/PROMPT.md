# 商品登録画面で商品を作るシードの書き直し（担当 {BATCH}: {FIDS}）

あなたは結合テストのシード（テストデータの作り方）を書き直す担当です。作業ディレクトリは `/home/y-saito/Developments/hareruya-design-docs`。

## 背景

- 依頼者決定（2026-10-19「商品登録画面で商品を作るシードも直して」）。
- 刷新後は、商品の新規登録が禁止されている（`integration_test/casegen/datapattern/units/M03-02/design.txt` L0075〜L0077「商品新規登録のアクセスを禁止する」、URL は404を返す）。E2E の実機でも、商品登録画面はどの権限でも開けない（403）。
- 商品を新しく作れるのは **グッズ商品CSV登録（M03-27）** と **カード商品CSV登録（M03-26）** だけ。
- 刷新後も使えるもの: 既存の商品の編集（商品登録編集画面。M03-02）、規格の追加・編集（商品規格一覧の「新規作成」→ 商品規格登録編集画面。M03-08 L0059、M03-09）。
- 同じ直しを先に2件している。お手本として読むこと: `integration_test/casegen/datapattern/conflicts/rulings.tsv` の E03（S-M03-11-DELETE-036）と K03（S-F06-15-MYPAGE-006）。

## 入力

担当の機能ごとに `integration_test/casegen/product_csv/in/<機能ID>.tsv`。シード表の行（シードID・区分・論理名・状態・属性・用途・投入方法・共有）に「使うケース」を足したもの。「商品登録」などの語で機械的に拾ったので、直す必要のないシードも混ざっている。
ケースは `integration_test/casegen/cases/<機能ID>_test_cases.tsv`（事前準備・手順・期待結果）。シードがケースの何を支えているかを、使うケースを読んで確かめる。

## 判定

シードごとに次のどれかに決める。

| 判定 | いつ |
| --- | --- |
| 直す | 投入方法が、商品登録画面（商品登録編集画面の新規、「商品を登録」、カード指定から商品を登録、/admin/product/product/new など）で**商品を新しく作っている** |
| 直さない | 既存の商品を開いて編集しているだけ／CSV で作った商品を編集しているだけ／「商品を登録しない」のように作らない／商品以外（会員・店舗など）の登録 |
| 直せない | CSV と編集画面では、ケースが要る商品の状態を作れない（理由を書く） |

## 直し方

**直すのは、商品を新しく作る部分だけ。** それ以外（会員・店舗・注文・在庫の操作、DBへの直接設定、控える番号）は一字も変えない。商品の属性のうち、ケースが使うもの（商品名・商品コード・価格・状態・言語・カテゴリ・公開状態・タグ・画像・カード・販売制限など）は、元のシードと同じ値になるようにする。

### 商品はいつもグッズ商品CSV登録で作る（カード商品も）

- 商品そのものは、カード商品も含めて **グッズ商品CSV登録** で作る。
- カード商品（元のシードがカード指定・カード詳細を使う）は、取り込んだあと商品登録編集画面（既存の商品の編集）を開き、「カード指定 >」ボタン（M03-02 L0092）で表示されるカード検索ポップアップから元のシードのカードを選び、商品カテゴリを元のシードのカテゴリ（単体カードなど）に付け替え、割引率を選んで「商品を登録」を押す。既存のケース IT-M03-02-006 と同じ操作。カードを作る部分（カード新規登録画面など）は元のシードのまま。
- 規格は元のシードのとおりに作る。グッズ商品CSVが作ったニアミントの規格は、元のシードがニアミントの規格を作っていれば、その規格を商品規格一覧から開いて元のシードの値（言語・商品コード・価格・公開ステータスなど）に直す。ほかの状態・言語の規格は、元のシードのとおり商品規格一覧の「新規作成」から商品規格登録編集画面で足す。
- カード商品CSV登録（M03-26）は使わない。カード商品CSVは、選んだ割引率に登録されたカードの状態ごとに規格を作り、価格も状態ごとの率で計算し直す（M03-26 L0150「規格生成の前提」・L0165、現行の ProductCardImportHandler）。どの状態の規格がいくつ・いくらで作られるかが環境の割引率の設定で変わり、元のシードを再現できないため。ケースがカード商品CSV登録で作った商品であることそのものに依るときだけは「直せない」にして理由を書く。
- カード指定でカードを選ぶと、商品名などにカードの値が自動で入る。元のシードの商品名と違うときは、カードを選んだあと商品名(日)・商品名(英)を元のシードの値に入れ直してから「商品を登録」を押す。
- 割引率は、元のシードが指定していればその値、無ければ「販売割引率に登録済みのもの」と書く。買取減額率はグッズ商品CSVに列が無いので、元のシードが指定していれば編集画面で選ぶ。
- カードセットを付けるだけの商品（カード詳細を使わない）は、グッズ商品CSVのカードセット(ID)の列（M03-27 L0223）で入れる（IDを控えていなければ、取り込んだあと商品登録編集画面でカードセットを選ぶ。シングルカードでない商品はカードセットを編集できる M03-02 L0073）。

### グッズ商品CSV登録（M03-27）

`integration_test/casegen/datapattern/units/M03-27/design.txt` を読むこと。
- 列（Excel L0194〜L0238）。必須: 商品コード・言語(ID)・商品公開ステータス（1 非公開／2 公開／3 廃止）・支店の商品公開ステータス（0 非公開／1 公開）・商品名(日)・商品名(英)・サイズ・重量・商品カテゴリ(ID)・購入グループ名称・基準価格・販売価格・買取価格・原価単価。商品IDは新規なら空。スマレジ連携フラグが有効のときはスマレジ商品コードと部門IDも必須（L0236〜L0237）。
- 商品カテゴリは、サプライ・グッズ・予約グッズ・情報商材の配下だけを選べる（L0123）。ケースが別のカテゴリを要るときは、CSV ではサプライ・グッズのカテゴリIDを入れて取り込み、そのあと商品登録編集画面で商品カテゴリを付け替える（カテゴリの木を動かさない）。
- 規格は、状態ニアミントの規格が1件だけ作られる（L0124）。言語は言語(ID)の列で決まる（Excel L0196）。ほかの状態・言語の規格が要るときは、取り込んだあと商品規格一覧の「新規作成」から商品規格登録編集画面で足す（M03-09。新規登録のとき言語・状態を選べる L0130〜L0134）。元のシードにニアミントの規格が無く、余るニアミントの規格がケースを崩すとき（規格の数・一覧の行・CSV の行を確かめる、など）は「直せない」にして理由を書く。
- 商品コードは規格のコードに使い、既存の規格コードと重複できない（L0134）。元のシードに商品コードがあればその値、無ければ機能IDとシードIDから作ったシード専用の値（例「A0706-CARDS-A」）にする。商品IDは、その商品コードで商品マスターを検索して控える。
- 買取価格は販売価格を上回れない（L0119）。
- 新しく作る規格はセールフラグ無効で作られ、販売価格は基準価格と同じ値になる（M03-09 L0086〜L0087 の基準価格と販売価格の関係。ee の取り込みも新規の規格は基準価格を販売価格にする）。CSV の基準価格と販売価格は同じ値にする。元のシードが基準価格と違う販売価格（セール中など）を要るときは、取り込んだあと商品規格登録編集画面でセールフラグにチェックを入れて販売価格を入れる。
- 新しく作る規格は、販売種別が「通常」、在庫0、在庫無制限なしで作られる（ee の取り込み。在庫は M03-27 L0129）。在庫数や在庫無制限が要るときは、元のシードと同じ画面で入れる（規格の画面では在庫数を変えられない M03-09 L0095・L0097。在庫は在庫の画面・在庫変更CSV登録などで入れる）。
- 「CSVファイルのアップロード」は押下後に確認モーダルを表示する（L0092）。

書き方の型（値は埋める。括弧の中で列と値を全部挙げる）:

> グッズ商品CSV登録で雛形ファイルをダウンロードし、1行を書いたCSVをCSVファイル選択で選んで「CSVファイルのアップロード」を押し、表示された確認モーダルでアップロードを確定する（商品IDは空・商品コードは「…」・商品名(日)は「…」・商品名(英)は「…」・言語(ID)は日本語のID・商品公開ステータスは2（公開）・支店の商品公開ステータスは1（公開）・サイズ1・重量1・商品カテゴリ(ID)はサプライ・グッズのカテゴリID（カテゴリ登録/編集画面の最上位の一覧で「サプライ・グッズ」の行のID欄に表示された値）・購入グループ名称は既存の購入グループの名称・基準価格…・販売価格…・買取価格…・原価単価…・部門IDは空）。グッズ商品は状態ニアミントの規格が1件作られる。商品マスター(検索入力)で商品コードに「…」を入れて「検索する >」を押し、商品マスター(検索結果)の行の商品IDに表示された番号を控える（〔…〕）。

複数の商品は、1つのCSVに行を並べてよい（行ごとに値を書く）。

### 在庫と価格

- 価格は税込みで登録する（晴れる屋の仕様。ee の ProductClass「価格は『税込み』で登録される」、F04-02 L0319 は合計から内税を割り出す）。元のシードの税込みの額は、そのまま CSV の基準価格・販売価格に入れる（1.1 で割らない）。
- 規格の画面（商品規格登録編集画面）には、在庫数と在庫無制限の入力欄が無い（M03-09 L0095・L0097、Excel の画面項目。ee の編集画面も在庫数を表示するだけ）。グッズ商品CSVで作る規格は在庫0・在庫無制限なし。
- 元のシードが在庫数や「在庫数無制限」を商品登録画面で入れていたときは、取り込んだあと在庫変更CSV登録（M04-21）で入庫し、別のメンバーが承認一覧（M04-32）で承認する。「無制限」は、使うケースが買う・動かす数より十分多い数（例 100）を入庫する。ケースが在庫無制限そのもの（在庫が減らない、など）を確かめるときは「直せない」にする。
- 書き方の型:

> 在庫変更CSV登録画面で、店舗に「…」、在庫区分に「EC-CUBE」、在庫変動区分に入庫の区分、在庫変動理由に「シード作成」を入れ、承認通知先（所属選択）で承認するメンバーの所属を選び、承認通知先（メンバー選択）で承認するメンバーを選び、商品コード「…」・在庫増減数「…」・仕入単価「100」の1行を書いたCSVを「ファイルを選択」で選んで「一括登録を実行」を押す（M04-21 L0127〜L0135・L0166〜L0168）。在庫を登録したメンバーとは別の、その店舗の承認権限を持つメンバーで承認一覧を開き、この申請の行にチェックを入れて「一括承認」を押し、表示された確認モーダルで「承認する」を押し、表示された確認画面で「OK」を押す（M04-32 L0108・L0110・L0141・L0218・L0297・L0301）。

- 1つの規格で100以上の増減（在庫増減数100以上・-100以下）があるときは、「一括登録を実行」を押したあと表示された確認モーダルで「OK」を押す（M04-21 L0056〜L0058）。
- 承認通知先は所属選択・メンバー選択のどちらも必須（M04-21 L0131・L0132）。在庫編集画面（M04-02）で入庫するときは、メンバー選択だけが必須（M04-02 L0190・L0193）。
- 承認一覧では「承認する」を押したあと確認画面が出て、「OK」で承認される（M04-32 L0218・L0301）。複数の申請を承認するときは、その全部の行にチェックを入れる。承認するメンバーは、承認するすべての店舗の承認権限を持つ者にする（M04-32 L0108）。

- 店舗は、元のシードが在庫を入れていた店舗（書いていなければ注文を受ける店舗。本店のフロントで買うなら本店）。承認するメンバーが元のシードに無ければ、同じ機能の既存のシードの管理者のうち、在庫を登録したメンバーと別の者を使い、理由の欄に書く。

### 共通

- 元のシードが商品登録画面でしか書けなかった属性（商品画像、販売制限、タグ、商品説明など）は、CSV の列にあれば列で入れ、無ければ取り込んだあと商品登録編集画面（既存の商品の編集）で入れる。
- 取り込んだ商品を商品登録編集画面で編集するときの登録ボタンは「商品を登録」（M03-02 識別ID 35。編集でも同じ名前）。空・未選択では登録できない項目は 商品名・商品名(英)・商品カテゴリ・購入グループ・サイズ・重量・割引率・販売制限・商品公開ステータス（`functions/pf-eccube3/m03-02_admin_product_product_edit.md` 17行目）。グッズ商品CSVには割引率の列が無いので、編集するときは割引率を販売割引率に登録済みのものから選ぶと書く。販売制限は CSV の地域別販売制限（0 は日英の両サイト）で入れておく。
- 元のシードが控えていた番号（〔商品ID-…〕など）は、同じ呼び名のまま、CSV で作ったあとの画面から控える。呼び名を変えない・増やさない（ケースが呼び名で参照している）。
- 「任意の値」「取り込める値」のような曖昧な書き方を CSV の必須列に使わない。上の型のように具体的な値か、登録済みのマスタの指し方で書く。
- 設計書に無い操作・画面・ボタン名を作らない。確かめた設計書の行番号を根拠の欄に書く。
- 元のシードのほかの部分に誤りを見つけても直さない。理由の欄に書く。
- ケース（事前準備・手順・期待結果）は変えない。ケースが「商品登録画面で作った商品」に依っていて書き直しで崩れるとき（規格の数、カテゴリ、登録した画面そのものを確かめる、など）は、理由の欄に「ケースに影響: …」と書く。

## 出力

機能ごとに `integration_test/casegen/product_csv/out/<機能ID>.tsv` を書く。タブ区切り・ヘッダ付き・UTF-8。入力のシードを1行ずつ、漏れなく同じ順で。

`シードID	判定	新しい投入方法	新しい状態・属性	根拠	理由`

- 新しい投入方法: 「直す」のときだけ。元の投入方法の全文を、商品を作る部分だけ書き換えた全文。「直さない」「直せない」は空。
- 新しい状態・属性: 状態・属性の欄の書き換えが要るときだけ全文（例: 「商品登録画面で登録した」と書いてある）。要らなければ空。
- 根拠: 確かめた設計書の行（例: M03-27 L0124、M14-04 L0094）。
- 理由: 直さない・直せないの理由、ケースへの影響、スマレジ連携、気づいた誤り。無ければ空。
- セルの中にタブと改行を入れない。書くときは Python で `"\t".join(...)` を使う（csv.writer は使わない）。

## 守ること

- 書いてよいのは `integration_test/casegen/product_csv/out/` の担当の機能のファイルと、担当の作業用フォルダ `integration_test/casegen/product_csv/work/{BATCH}/` だけ。ほかのファイル（ほかの担当の out・work を含む）は読むだけ。
- **git の変更操作（add・commit・push・checkout・stash など）は一切しない。** 外部サービスへの書き込みもしない。
- 書き終えたら `python3 integration_test/casegen/product_csv/gate.py {FIDS}` を流し、不合格が無くなるまで直す。
- 返答は3行以内: 機能ごとの 直す／直さない／直せない の件数、ケースに影響のある件数、gate の結果。
