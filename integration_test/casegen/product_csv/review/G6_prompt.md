# 商品のシードの書き直しの事実確認（G6、1巡目）

あなたはレビュアーです。結合テストのシード（テストデータの作り方）の書き直しが、設計書どおりで、元のシードと同じデータを作れるかを確かめてください。ファイルは読むだけにし、書き換えないでください。

## 何をしたか

刷新後は商品の新規登録画面が使えない（`integration_test/casegen/datapattern/units/M03-02/design.txt` L0075〜L0077）。そこで、商品登録画面で商品を作っていたシードを、グッズ商品CSV登録（M03-27）で作る書き方に直した。カード商品は、グッズ商品CSVで作ったあと、商品登録編集画面（既存の商品の編集）の「カード指定 >」でカードを付ける。規格は、元のシードのとおり商品規格登録編集画面で足す・直す。
書き直しの決まりは `integration_test/casegen/product_csv/PROMPT.md`。

- 元のシード: `integration_test/casegen/product_csv/in/<機能ID>.tsv`（投入方法の列。使うケースの列もある）
- 書き直し: `integration_test/casegen/product_csv/out/<機能ID>.tsv`（判定・新しい投入方法・新しい状態・属性・根拠・理由）
- ケース: `integration_test/casegen/cases/<機能ID>_test_cases.tsv`

対象の機能: A07-05、M04-23、M06-12、F03-01、M05-09、M12-10、F09-08、M03-33、M14-05

## 正本

- 設計書の写し: `integration_test/casegen/datapattern/units/<機能ID>/design.txt`（行頭の L0001 が行番号）。M03-02（商品登録編集）、M03-08（商品規格一覧）、M03-09（商品規格登録編集）、M03-27（グッズ商品CSV登録）、M14-04（カード登録）と、各ケースの機能
- 商品登録編集画面の入力の検証: `functions/pf-eccube3/m03-02_admin_product_product_edit.md`
- 設計書の中で食い違うときは Excel 由来の本文 ＞ 埋め込みの表示メッセージの節 ＞ 埋め込みの現行仕様の節

## 確かめること

1. 直したシードの手順で、グッズ商品CSV登録が行を取り込めるか（必須の列、値、価格の整合、商品カテゴリの制限、確認モーダル）。
2. 取り込んだあとの編集（カード指定、カテゴリの付け替え、割引率など）と規格の追加・修正が、設計書にある画面・項目・ボタンで書かれているか。編集画面の必須項目を満たすか。
3. 書き直しで作られる商品・規格が、元のシードが作っていたもの（商品名・商品コード・言語・状態・価格・公開状態・カテゴリ・カード・規格の数など）と、使うケースが確かめる点で同じか。余る規格（CSV が作るニアミントの規格）や、変わった値がケースの期待結果を崩さないか。
4. 判定が「直さない」の行が、本当に商品を新しく作っていないか。「直す」の行で、商品を作る部分以外を変えていないか。
5. 控える番号の呼び名〔…〕が、元と同じ意味で控えられているか。

## 指摘にしないもの

- 元のシードのうち、商品を作る部分以外の不備（書き直しの範囲外。理由の欄に書いてあるものも含む）
- ケースそのものの不備
- 言い回しの好み、細かくする提案
- 何度も流したときの重複（試験は新しいDBで流す前提）
- DB へ直接入れる部分の書き方

## 分かっている論点（指摘にしない）

次は別に扱うので指摘しない（`integration_test/casegen/product_csv/work/notes.md` に一覧がある）。
- 規格が0件の商品は画面で作れない件（M03-09 の直せない・ケースに影響の行）
- 販売種別を入れる手段が無い件（直せないの行）
- 判定が「直せない」の行、理由の欄に「ケースに影響」と書いた行（別に1件ずつ判断する）
- M04-31 の「商品CSV登録」、買取の申込みの規約同意、元のシードの編集で割引率が無いもの（範囲外）
- 規格の公開ステータス（ee の初期値は公開）、新しく作る規格は販売価格＝基準価格（セールフラグ無効）であることは確かめ済み

## 出力

指摘が無ければ `NONE` の1語だけを出力してください。
指摘があれば、1件ごとに次の形で書いてください。同じ型の誤りが多くの行にあるときは、1件にまとめ、該当するシードIDを全部挙げてください。

```
### 指摘N（重大度: Major / Minor）対象: <機能ID> <シードID>
主張: 書き直しの記述
実際: 設計書・ケースの記述（file:line）
判定: 事実の誤り／前提不成立／手順不備／再現しない／推測
修正案:
```
