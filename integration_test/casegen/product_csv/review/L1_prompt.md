# 商品のシードの書き直しの事実確認（L1、3巡目）

あなたはレビュアーです。2巡目の指摘を受けた直しが設計書どおりか、新しい事実の誤りを入れていないかを確かめてください。ファイルは読むだけにし、書き換えないでください。

対象の機能: M05-10、M05-02、M05-09、F10-03、F03-01、M05-01（M05-01 は型の当て方の確かめとして5件ほど見れば足りる）

## 確かめること

1. 型の事実: 在庫変更CSV登録の承認通知先（所属選択・メンバー選択）の必須、100以上の増減の確認モーダル、承認一覧の「承認する」のあとの確認画面と「OK」が、設計書の画面・項目・ボタンの名前どおりか（M04-21、M04-32）。在庫編集（M04-02）の承認通知先・登録ボタン・確認の有無と、M05-09・F10-03・F03-01 の書き方が合っているか。
2. M05-10 の29件: 入庫の店舗（STORES-001 の支店用商品と SORTBRANCH-026 は支店、ほかは本店）が、元のシード（in/M05-10.tsv の本店の管理者・支店の管理者）とケースの購入する店舗に合うか。商品コード・在庫増減数がケースの使う数を満たすか。1件の申請・2件の申請の承認が合っているか。
3. M05-02 の4件: 書き直した承認の文が、在庫変更CSV登録の申請の承認として成り立つか。
4. 直しで、入庫・承認以外の部分（商品の作り方、控える番号〔…〕、注文の手順）を変えていないか。
## 何をしたか（3巡目。これが最後の巡）

刷新後は商品の新規登録画面が使えない（`integration_test/casegen/datapattern/units/M03-02/design.txt` L0075〜L0077）。そこで、商品登録画面で商品を作っていたシードを、グッズ商品CSV登録（M03-27）で作る書き方に直した（書き直しの決まりは `integration_test/casegen/product_csv/PROMPT.md`）。元のシードが商品登録画面で在庫数を入れていたときは、在庫変更CSV登録（M04-21）か在庫編集（M04-02）で入庫し、別のメンバーが承認一覧（M04-32）で承認する。

2巡目（`integration_test/casegen/product_csv/review/J1〜J3_prompt.md`）の指摘と裁定は `integration_test/casegen/product_csv/review/R2_dispositions.tsv`。直しは `integration_test/casegen/product_csv/fix_stock.py` で機械的に当てた。

- 書き直しで新しく書いた入庫・承認の文 430件（18機能）を、次の型にそろえた
  - 在庫変更CSV登録の承認通知先は、所属選択とメンバー選択の両方を選ぶ（M04-21 L0131・L0132）
  - 1つの規格で100以上の増減があるときは、「一括登録を実行」のあと確認モーダルで「OK」を押す（M04-21 L0056〜L0058）
  - 承認一覧で「承認する」を押したあと、確認画面で「OK」を押す（M04-32 L0218・L0301）
- 型から外れていた書き方を型で書き直した: M05-10（「在庫増減数に10を入れたCSVを取り込む」だけ）、M05-02（「一括承認ボタンを押して承認する」）、F03-01（「在庫編集承認一覧で承認する」）
- 個別の直し: M12-07 DATA-003（本店と支店の2件の申請を承認）、A06-03 AB-PRODUCT（AB試験店舗の承認権限を持つメンバーをこのシードの中で作る）、F04-04 INSTORE-023・024・026・028（TC東京へ入庫）、F04-02 STORE-CARTS-020（本店カートの商品は本店へ）・SMAREGI-051（支店へ）、M05-23 の17件（本店へ）、M05-10 STORES-001（支店公開の記述の食い違いを消した）

直す前と後の対照表: `integration_test/casegen/product_csv/review/L_diff.tsv`（機能ID・シードID・直し・直す前の入庫と承認の文・直した後の入庫と承認の文）。全文は `integration_test/casegen/product_csv/out/<機能ID>.tsv` の「新しい投入方法」。元のシードは `integration_test/casegen/product_csv/in/<機能ID>.tsv`、ケースは `integration_test/casegen/cases/<機能ID>_test_cases.tsv`、シード表は `integration_test/casegen/cases/<機能ID>_seed_data.tsv`。

## 正本

- 設計書の写し: `integration_test/casegen/datapattern/units/<機能ID>/design.txt`（行頭の L0001 が行番号）。M04-21（在庫変更CSV登録）、M04-02（在庫編集）、M04-32（在庫編集承認一覧）、M11-03（権限管理）、M11-02（メンバー登録）、M03-27（グッズ商品CSV登録）と、各ケースの機能
- 設計書の中で食い違うときは Excel 由来の本文 ＞ 埋め込みの表示メッセージの節 ＞ 埋め込みの現行仕様の節

## 指摘にしないもの

- 元のシードにもともとあった文の不備（入庫・承認の文を含む。今回の範囲外で、別に一覧にしてある）
- 「その店舗の承認権限を持つメンバー」「承認するメンバー」と書くだけで、そのメンバーを作るシードが無いこと（環境の前提として別に扱う。A06-03 だけは、名指ししたメンバーが承認できなかったので作る形にした）
- 「在庫変動区分に入庫の区分」の書き方（1巡目・2巡目で確かめ済み）
- ケースそのものの不備、言い回しの好み、細かくする提案、何度も流したときの重複（試験は新しいDBで流す）、DB へ直接入れる部分
- 1巡目・2巡目で指摘が無かった点の再提示、2巡目で裁定済みの点の蒸し返し
- `integration_test/casegen/product_csv/work/notes.md` の「別の論点」に挙げたもの

```
判定: 事実の誤り／前提不成立／手順不備／再現しない／推測
修正案:
```
