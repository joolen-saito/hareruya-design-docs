# R1 指摘の扱い

| # | 指摘 | 扱い |
| --- | --- | --- |
| 1 | Webhook許可IPはテスト実行元でない | 反映。S-A01-01-ENV を「スマレジの送信元IPが許可IPに入る」に |
| 2 | 接続・契約・店舗対応の前提が無い | 反映。S-A01-01-ENV に接続設定・店舗対応・ワーカー・共有シークレット。全ケースが参照 |
| 3 | 001 のWebhook応答の観測手段が無い | 反映。中継 S-A01-01-RELAY を共有シードにし、手順を中継の記録で確認に変更（step_changes） |
| 4 | 004 の取引が特定できず両側の状態も保証されない | 反映。取引IDを控え、両側8を確認、不成立なら実施しない |
| 5 | 006 店頭受取分の作り方が無い | 設計書にも ee にも作り方の手順が無いため open_preconditions.tsv に登録。推測で埋めない |
| 6 | 015〜018 移動元・移動先が無い | 反映。ee の在庫場所（ECCUBE/スマレジ）で移動元・移動先と各在庫を値付きで定義 |
| 7 | CSVフィクスチャが実体化されていない | 一部反映。列（商品コード・在庫増減数、ee実装）と各行の値、画面入力値 S-A01-01-CSVFORM を定義。ファイルの実体化はE2E実装段階（M0 manifest）の担当 |
| 8 | 問い合わせIDが事前状態に入っている | 反映。シード・事前準備から外し、手順中で中継の記録から控える（step_changes）。ゲート G8 追加 |
| 9 | 非同期コールバックの競合 | 反映。中継で結果通知を保留し、試験者が転送・送信する |
| 10 | 031/032 エラーの起こし方・循環 | 反映。エラー結果は中継から固定値 E-A01-001 で送る。E の改名は撤回 |
| 11 | 003 の 1001 がオラクル変更 | 別案で解消。手順中で発番値を控え「以下この値を 1001 と呼ぶ」。期待結果は基線のまま |
| 12 | P3 接尾辞 | 反映。全ケース専用シードに接尾辞。G4 で検査 |
| 13 | G6 改名で任意変更が通る | 反映。改名は識別子どうしに限定。それ以外は oracle_changes（承認必須） |
| 14 | G1/G2 時系列を見ない | 反映。G8 |
| 15 | G3 が数値だけ照合 | 却下（機械化の限界）。レビューで見る |
| 16 | G4/G5 範囲・接尾辞 | 反映。範囲を展開して照合、接尾辞検査 |
| 17 | G7 未文書化・無制限 | 反映。README に G7 と許す変更の種類（P8）を明記。内容の妥当性はレビューで見る |

ee 実装との差（/smaregi/stocks が無い、一括相対更新とコールバックが無い 等）はテストで検出されるべき乖離であり、ケースは設計書どおりに据え置く。
