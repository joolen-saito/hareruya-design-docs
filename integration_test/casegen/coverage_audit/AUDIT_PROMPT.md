# 依頼: HTML設計書のシート1枚が、結合テストケースに漏れなく起こされているかの監査

対象の単位: `{UNIT}`（書番 {BOOK} / {SID} / シート名「{NAME}」 / 対応機能 {FIDS}）

これは監査である。ケースも設計書も直さない。事実は自分でファイルを読んで確かめ、推測で「ケースあり」としない。

## 読むもの（/home/y-saito/Developments/hareruya-design-docs/ 配下）

| 何 | パス |
| --- | --- |
| 設計書（このシートを文字に起こしたもの。行頭 L0001 が行番号。表は1行＝1レコードでタブ区切り） | `integration_test/casegen/coverage_audit/units/{UNIT}/sheet.txt` |
| 対応機能のケース（実行区分=保留除外 は、正解が設計書に無いためテストから外したケース） | `integration_test/casegen/coverage_audit/units/{UNIT}/cases.tsv` |
| 全ケース（他機能のファイルで確かめている場合の検索用。出典列は「書番 冊子名 / シート名 / …」） | `integration_test/casegen/all_test_cases.tsv` |
| 結合テストの範囲（対象・対象外の基準） | `integration_test/SCOPE.md` |
| 観点表（観点ID の意味） | `integration_test/viewpoint_canonical/viewpoints_canonical.tsv` |

検索は `grep` を使う（`rg` は同じ入力で0件を返すことがあるので使わない）。
cases.tsv が空、またはこのシートのふるまいが別機能のケースで確かめられていそうなときは、all_test_cases.tsv を書番 `{BOOK}` とキーワードで検索する。

## やること

sheet.txt の全行を上から順に読み、**設計書の記述1件ごと**に、それを確かめるケースがあるかを判定する。
1件は「合否を判定できる1つの定め」。表の1行、条件分岐の1枝、箇条書きの1項目が目安。1行に定めが複数あれば行を分けて複数件にする。
見出しや前置きなど連続する行は範囲（L0010-L0014）でまとめてよいが、**全行がいずれかの行に含まれること**（判定漏れ0）。

判定は次のいずれか。

| 判定 | 意味 | 必須の欄 |
| --- | --- | --- |
| ケースあり | 手順と期待結果を読んで、その定めを実際に確かめているケースがある。要求ID列や出典列に載っているだけでは不可 | テストID |
| 一部抜け | ケースはあるが、定めの一部（別の枝・逆側の条件・別の項目・境界）が確かめられていない | テストID・理由（何が足りないか） |
| 抜け | 結合テストで確かめるべき定めなのに、確かめるケースが無い | 理由（何を確かめるケースが要るか） |
| 保留除外 | 保留除外のケースが該当する（正解が無くテストできないと判断済み） | テストID |
| 対象外 | SCOPE.md の基準で結合テストの担当でない（単体・e2e・性能、画面文言の逐語照合、レイアウト）。または廃止・フェーズ2・「Ph1では実装しない」と設計書自身が書いている | 理由（SCOPE.md のどの基準か、または設計書のどの記述か） |
| 説明文 | 見出し・前置き・用語の説明・改訂履歴など、単独で合否を判定できない | — |

注意:

- 項目定義の「DBへ保存する項目の桁数・必須・書式」「初期値」「画面部品のふるまい」は結合テストの対象（SCOPE.md）。同じ種類の判定なら複数項目を1ケースにまとめてあってよいが、その項目がケースの手順・期待結果に実際に入っていること。
- 「現行仕様」と Excel の刷新指示が食い違うときは刷新が正。廃止節（「Excel基本設計により廃止された仕様」等）配下の現行仕様は対象外。
- 「抜け」「一部抜け」は安易に付けない。付ける前に all_test_cases.tsv をキーワードで検索して、他機能のケースに無いことを確かめる。逆に、近い題のケースがあるだけで「ケースあり」としない。
- 設計書の記述どうしが矛盾している、期待結果が設計書から決まらない、という場合は「抜け」とし、理由の頭に「【正解未定】」と書く。

## 出力

`integration_test/casegen/coverage_audit/units/{UNIT}/judgement.tsv` に、ヘッダつきTSV（タブ区切り・セル内に改行とタブを入れない）で書く。

```
行	記述	判定	テストID	理由
L0001-L0006	（見出し・基本情報）	説明文		
L0007	検索ボタン押下で検索条件に一致する受注を一覧表示する	ケースあり	IT-M05-01-003,IT-M05-01-004	
L0008	受注日(開始)が受注日(終了)より後のときエラー	抜け		開始＞終了の入力で検索が拒否されることを確かめるケースが無い
```

- 行: `L0007` または `L0007-L0012`。同じ行を複数の記述に分けるときは同じ行番号を複数行に書いてよい。
- 記述: 設計書の定めを自分の言葉で短く（60字程度まで）。
- テストID: カンマ区切り。実在するIDだけ。

書いたら次を実行し、エラーが無くなるまで直す。

```
python3 integration_test/casegen/coverage_audit/gate_judgement.py {UNIT}
```

最後の返答は、判定ごとの件数と、「抜け」「一部抜け」の行番号と一言だけを短く書く。
