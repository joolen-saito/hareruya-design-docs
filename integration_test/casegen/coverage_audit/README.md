# HTML設計書 → 結合テストケースの被覆監査（2026-10-09）

HTML設計書に書かれている内容が、結合テスト観点で漏れなくテストケースに起こされているかを、シート1枚ずつ・記述1件ずつ確かめた。

- 監査の途中で、ケースが1件も無い機能が14あると分かり（F09-01〜08、A15-02・03・04・08・12、B17-01）、依頼者決定でケースを作った（585件。`../nosheet/`）。上の数字は、その合流後に14シートを監査し直した結果を含む。合流前のこの14シートの指摘は508件、合流後は63件（うち妥当28）。

依頼者決定で、妥当な抜け 1,788件のケースを作った。1,640件をケース化（追加 1,942件・254機能）、142件はケースにせず理由を残し、4件は既存ケースで確認済み、2件は割り当て先の機能が無い。

## やり方

| 段 | 何をしたか | 道具 |
| --- | --- | --- |
| 単位を作る | いまのHTMLをシートごとに文字へ起こし（行番号つき）、対応機能のケースと、除外済みの保留ケースを添える | `build_units.py` → `units/<書番>_<シートID>/sheet.txt`・`cases.tsv`、`units.tsv` |
| 1巡目 | 1シート1エージェントが、全行をいずれかの判定に割り当てる（ケースあり／一部抜け／抜け／保留除外／対象外／説明文） | `AUDIT_PROMPT.md`・`mk_prompt.py` → `units/*/judgement.tsv` |
| 検査 | 判定漏れ0（全行が判定に含まれる）、テストIDの実在、理由の記載 | `gate_judgement.py` |
| 集計 | | `collect.py` → `judgement_all.tsv`・`gaps.tsv`・`summary.tsv` |
| 2巡目 | 抜け・一部抜けを約60件ずつ codex に渡し、反証させる | `mk_verify.py`・`mk_verify14.py` → `verify/V*・W*_prompt.md`、`collect_verify.py` → `verified.tsv` |
| 仕分け | | `finalize.py` → `confirmed_gaps.tsv`・`spec_questions.tsv`・`dropped.tsv`・`by_unit.tsv` |

機械だけの被覆判定は過去に4方式とも使えなかった（`../GAPS.md`）。今回は全数を読ませ、機械は「読み飛ばしが無いこと」だけを検査している。

## 読むときの注意

- 判定は著者と別のモデル（codex）が反証したが、1,788件を人が全数読んだわけではない。無作為10件の目視では具体的で検証可能な指摘だった。
- 「ケースあり」17,791件の側は反証に掛けていない（近い題のケースがあるだけで「あり」とした誤りは残りうる）。
- 画像の中にしか無い記述（画面レイアウト図・遷移図の画像）は文字に起こしていないので監査していない。
- 対応機能の無いシート（別添資料、共通処理、【新規】受注情報履歴、手動メール通知(確認画面) など24枚）は、同じ冊子の他機能のケースで確かめられているかで判定した。妥当な抜けのうち183件がこれらのシートの分。
- 0211 の「_詳細設計」版は 0211 本体とほぼ同じ内容なので監査していない。
- `round1_zero_case/` は、14機能のケースが0件だったときの判定（参考）。
- 最初の分割で、Excel の無い冊子（0309・0310・0417・0508・0515）が黙って落ちていた。HTMLの節の作りが違うため。`build_units.py` は両方の作りを読む。
