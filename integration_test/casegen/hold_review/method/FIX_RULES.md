# codex指摘の検証と反映

codex が保留ケースの判定（`S/judge/bNN.tsv`）をレビューした。その指摘を**1件ずつ設計書で確かめてから**反映する。
codex は誤指摘も出す。そのまま適用してはならない。

## 読むもの（S = このファイルのあるディレクトリ）

- 判定規約: `S/JUDGE_RULES.md`（判定の基準。指摘の採否もこれで決める）
- codexの指摘: `S/review/<グループ>.out.txt` の**末尾**（`tokens used` の行より後）。同じ指摘が2回繰り返されていることがあるので、重複は1件として扱う
- 設計書: `S/src/<機能ID>.txt`、`.diff.txt`、`.ref.txt`

## 手順

1. 指摘ごとに、codex が挙げた行を `src` で開き、**前後の文脈まで**読む。行番号ずれ・引用の誤りも確かめる
2. 採否を決める
   - **採用**: 指摘どおり判定規約に反している
   - **一部採用**: 誤りは事実だが、修正案が規約に合わない（例: 修正案が設計書に無い値を補っている）。規約に合う形で直す
   - **却下**: 指摘が事実でない、または規約上は著者の判定が正しい
3. 採用・一部採用したものを `S/judge/bNN.tsv` に反映する。指摘の無い行は変えない
   - codex が「保留誤り」「解消」への変更を求めるときは特に慎重に。**保留の理由に挙がった未定義事項が全部、引用だけで決まる**ことを自分で確かめられたときだけ採る。一部しか決まらないなら「維持」のまま分類・論点を直す
   - 同じ論点に統一するよう求められたら、同じ機能の同じ未定義事項に**一字一句同じ論点**を書く
4. `python3 S/gate.py S <bNN...>` を通す
5. 採否の記録を `S/review/<グループ>.decisions.tsv` に書く（ヘッダーあり、1指摘1行）

```
テストID	codex判定	採否	理由	反映内容
```

- `理由`: 採否の根拠を1〜2文。却下なら、なぜ指摘が当たらないかを設計書の行で示す
- `反映内容`: 変えた列と、変更前→変更後（例: `分類 矛盾→結果／論点 …`）。却下なら `—`

## 判定規約の補足（2026-09-28 追加）

- **削除による解消**: 食い違っていた片側の記述が生成後に削除され（`diff.txt` の「消えた行」）、残る記述だけで期待結果が決まるものは「解消」にしてよい。
  このときの根拠引用は残った記述（`src` に実在するもの）を引き、`説明` に「消えた行」の該当文を書く。gate はこの形を通す

最後に、採用・一部採用・却下の件数と、判断に迷ったものを短く報告すること。
