# 敵対レビュー依頼（2巡目）: 機能横断の共通論点

これは**レビューの依頼**である。書き直すのではなく、誤りを指摘すること。

結合テストの保留ケースのうち保留のまま残るものを、機能ごとの論点（1150件）にまとめ、
さらに機能をまたいで同じことを聞いている論点を「共通論点」（105件）に束ねた。束ね方が正しいか確かめてほしい。

## 重点

1. **束ねすぎ。** 共通論点の中に、1回の質問では答えが出ない論点（答えが機能ごとに違い、共通の決まりでは決まらないもの）が混ざっていないか。
   混ざっていれば、どの論点IDを外すべきか指摘する
2. **共通論点の文が中身を言い当てていない。** 束ねた論点の一部しか覆っていない、範囲（どの機能群か）が違う
3. **決める人の取り違え。** 設計者に聞くべきもの（仕様・期待結果の未定義）が「異常の作り方」（テスト側）の共通論点に入っていないか。
   逆に、テスト側で決められる試験技法の話が設計者側に入っていないか
4. **束ね漏れ（明らかなものだけ）。** 同じ共通論点の文にそのまま当てはまるのに単独で残っている論点。
   分類が違うと別の共通論点になる点は、規約どおりなので指摘しない

## 指摘しないもの

- 論点そのものの判定（維持・解消など）の正否（別のレビューで見ている）
- 言い回し
- 束ねるかどうか判断が分かれるだけで、どちらでも規約に反しないもの

## 出力形式

指摘が1件も無ければ `NONE` の1語だけを出力する。指摘があれば、1件ごとに次の形で書く。

```
### <共通論点ID または 論点ID>
主張: <どう束ねられているか>
実際: <論点の文・設計書の記述と file:line>
判定: 束ねすぎ / 共通論点の文の誤り / 決める人の誤り / 束ね漏れ
修正案: <どの論点IDをどう動かすか>
```
