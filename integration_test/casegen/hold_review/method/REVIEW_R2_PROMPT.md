## 重点

1. **対象行（`r2_targets_<PART>.txt`）の判定の正しさ。** 特に「解消」「保留誤り」は、引用だけで保留の理由の未定義事項が**全部**決まるか。
   一部しか決まらない、推論や一般常識で補っているものは指摘する。最も重い
2. **1巡目の採否の誤り。** 1巡目で却下された指摘が実は正しかった、採用した修正が規約に反する、というもの
3. **論点台帳の分割漏れ・統合漏れ（__PART__ の機能だけ）。** `issues.tsv` で、
   - 同じ機能の中で、同じ未定義事項なのに論点が別になっているもの（統合すべき）
   - 1つの論点に、別々の未定義事項が混ざっているもの（分けるべき）
   - 論点の「決める人」（設計者／テスト側）が、中身と合わないもの

## 指摘しないもの

- 設計書に無い値を「こうすべき」と提案すること
- 実装コードに基づく指摘
- 説明文の言い回し
- 1巡目で指摘され、採否記録に理由付きで却下された件と**同じ主張の繰り返し**（新しい根拠が無い限り）

## 出力形式

指摘が1件も無ければ `NONE` の1語だけを出力する。指摘があれば、1件ごとに次の形で書く。

```
### <テストID または 論点ID>
主張: <判定・分類・論点のどれが、どうなっているか>
実際: <設計書の記述（逐語）と file:line>
判定: 解消の誤り / 保留誤りの誤り / 維持の見落とし / 対象外の誤り / 分類の誤り / 矛盾の誤り / 論点の誤り / 採否の誤り / 統合漏れ / 分割漏れ
修正案: <どう直すか>
```
