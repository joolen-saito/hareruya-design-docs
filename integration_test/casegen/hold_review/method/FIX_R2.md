# 2巡目の codex 指摘の検証と反映

手順・採否の考え方は `S/FIX_RULES.md` と同じ（1件ずつ設計書で確かめる。そのまま適用しない）。
2巡目で加わった指摘の種類と、その直し方を次に定める。

| 指摘の種類 | 直す場所 |
| --- | --- |
| 判定・分類・論点・根拠引用の誤り | `S/judge/bNN.tsv` の該当行（どのバッチかは `S/batch/*.tsv` を grep して探す） |
| 論点の統合漏れ（同じ機能・同じ未定義事項なのに論点の文言が違う） | 該当する全行の `論点` を一字一句同じ文にそろえる |
| 論点の分割漏れ（1つの論点に別々の未定義事項が混ざる） | 片方の行の `論点` を、その事項を言い当てる別の文に直す |
| 採否の誤り（1巡目の却下・採用が誤り） | 設計書で確かめ、誤りなら該当行を直す |

- 反映後に `python3 S/gate.py S <触ったバッチ...>` を通す
- 採否記録: `S/review/r2_<PART>.decisions.tsv`（ヘッダーあり、1指摘1行）
  `指摘ID	codex判定	採否	理由	反映内容`
- 指摘は `S/review/r2_<PART>.out.txt` の末尾（`tokens used` の最後の出現より後）。重複は1件として扱う
- 担当範囲の外の行・ファイルは変更しない

最後に、採用・一部採用・却下の件数と、判断に迷ったものを短く報告すること。
