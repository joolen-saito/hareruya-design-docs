# 論点を機能横断の「共通論点」に束ねる（手順2）

`S/out/issues.tsv` は、保留のまま残るケースを機能ごとの論点（1150件）にまとめた台帳である。
論点は機能ごとに書かれているので、**機能をまたいで同じことを聞いている**ものが多い。
それを「共通論点」に束ね、設計者（またはテスト側）への質問の数を減らす。

## 束ねてよいもの

**1回の質問で、その全部に答えが出せる**ものだけを束ねる。

- 良い例: 「管理画面API群で、IP制限の許可IP範囲と不許可IPからの応答が未定義」→ API 12機能の論点を1つに
- 良い例: 「共通エラー処理（システムエラー）に委ねた後に表示する画面・HTTP応答・DB更新の有無が未定義」
- 良い例（テスト側）: 「DB例外を試験環境で発生させる方法」→ 例外の作り方が同じ技法で済むもの
- 悪い例: 「並び順が未定義」というだけで、画面も項目も違う並び順をまとめる。答えは機能ごとに違い、1回の質問では済まない
- 悪い例: 分類（仕様値／結果など）や決める人が違うものを混ぜる

迷ったら束ねない。束ねない論点は単独のままでよい（共通論点IDを空にする）。
**論点の文言や判定は変えない。** 束ねるだけである。

## 出力

`S/out/group_<担当分類のコード>.tsv`（ヘッダーあり、担当分類の論点を**全件**・issues.tsv と同じ順で1行ずつ）

```
論点ID	共通論点ID	共通論点
```

- `共通論点ID`: `G-<コード>-NN`（コードは担当分類のもの。例: G-T-01）。単独の論点は空
- `共通論点`: 束ねた質問を1文で。`<対象の範囲>で<何>が未定義` の形。単独の論点は空
- 同じ共通論点IDには一字一句同じ共通論点の文を書く
- 1つの共通論点に束ねるのは2件以上

最後に、共通論点の数、束ねた論点の数、単独のまま残した数、迷ったものを短く報告すること。
