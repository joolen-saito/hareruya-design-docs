# 反映作業への codex 指摘の検証と反映

codex が、機能設計書（md）への書き足しとテストケースの書き換えをレビューした。指摘を**1件ずつ現行ソース・md で確かめてから**反映する。
そのまま適用しない。作業規約は `S/reflect/REFLECT_RULES.md`（R・S の定義もそこにある）。

## 手順

1. 指摘の対象（md の文・ケースの行）と、codex が挙げた根拠の両方を開き、現行ソースは処理を末端まで読む。ec-cube-enterprise は読まない
2. 採否を決める（採用／一部採用／却下）
   - **加筆の要求は却下する**（このレビューは事実確認だけで、記述を増やさない）
   - 「既存の記述と矛盾」は、どちらが現行ソースと合っているかを確かめる。足した文が誤りなら足した文を直す。**既存の文が誤りなら既存の文を直してよい**（根拠を md の `## 出典` に足す。直した既存の文は採否記録に逐語で残す）
3. 直す
   - md: 足した文を削る・直す。削ったら作業記録 `S/reflect/out/rNN.tsv` の `mdに書いた文` も合わせる。md から文を削ってケースの根拠が無くなったら、そのケースは元の保留の行（`S/reflect/base/cases/<機能ID>_test_cases.tsv` の同じテストIDの行）に戻し、作業記録の `結果` を「見送り」、`テストID` から外して `補足` に理由を書く
   - ケース: 期待結果・手順・事前準備・シードを直す。直せないなら上と同じく保留の行に戻す
4. `python3 S/reflect/gate_reflect.py S <担当の rNN...>` を通す
5. 採否の記録を `S/reflect/review/<グループ>.decisions.tsv` に書く（ヘッダーあり、1指摘1行）

```
指摘ID	codex判定	採否	理由	反映内容
```

担当のバッチの機能以外は触らない。最後に、採用・一部採用・却下の件数、保留に戻したケース、直した既存の文を短く報告すること。
