## 重点（上ほど重い）

1. **md に足した文が現行ソースと食い違う。** 別の画面・別のルート・別の分岐のコードを根拠にしている、処理順を取り違えている、設定値・DB値で変わるものを固定値として書いている
2. **根拠の範囲を超えた記述。** 答えや根拠のコードから言えないことを書いている（推測・一般論・他機能からの補い）。粒度ゲートを通すための水増し（`R/.cursor/skills/reverse-design/GRANULARITY.md` 5）
3. **既存の記述との食い違い。** 足した文が、同じ md の既存の文と矛盾する（どちらが現行ソースと合っているかも示す）
4. **ケースの期待結果が md（書いた文または既存の文）から言えない。** 一般知識・推測に頼る期待結果、画面表示文言の逐語照合（`R/integration_test/SCOPE.md` で e2e の担当）、1ケースに複数の期待結果
5. **ケースの手順が実行できない。** 画面・操作・コマンド名・シードが現行と合わない
6. **規約違反。** 物理名（テーブル名・翻訳キー・ルート名）を本文やケースに書いている、画面操作を md 本文に書いている、現行の実装不備（効かない判定・到達しない分岐）を仕様として書いている

## 指摘しないもの

- 設計書やケースへの**加筆**を求めること（「〜も書くべき」）。このレビューは事実確認だけで、記述を増やさない
- 言い回し・文体
- 書き換え前からある md・ケースの問題（今回の差分に関係しないもの）
- 見送った論点を反映すべきだという主張（見送りの理由が事実誤認のときだけ指摘してよい）

## 出力形式

指摘が1件も無ければ `NONE` の1語だけを出力する。指摘があれば、1件ごとに次の形で書く。

```
### <論点ID または テストID>
主張: <md の文・ケースのどこが、どうなっているか>
実際: <現行ソースまたは md の記述（逐語）と file:line>
判定: 現行との食い違い / 根拠の範囲を超える / 既存の記述と矛盾 / 期待結果の根拠なし / 手順が実行できない / 規約違反
修正案: <削る・直す内容>（加筆の要求はしない）
```
