### 指摘（B05-02 / DP-B05-02-007）
- 主張: 支店通知の方式や記録手段が未確定なので「ケースにしない」。
- 実際: design.txt L0081 は「在庫履歴を登録するとき、対象になった商品規格の在庫数を支店へ通知する」と定める。
- 判定: ケースにできる
- 修正案: 別規格の明細2行について、それぞれの在庫数が支店へ通知されるケースを作る。通知の形式を期待結果に足す必要はない。

### 指摘（B05-02 / DP-B05-02-022）
- 主張: 外部連携環境と確認画面が未確定なので「ケースにしない」。
- 実際: design.txt L0027 は「ポイント履歴を作成し、ポイント残高を減らす」、L0051–L0053 は残高減算・履歴登録・スマレジ同期を定める。
- 判定: ケースにできる
- 修正案: 残高と使用ポイントが等しいデータで、DBの残高0と履歴を確かめるケースを作る。外部連携の準備が未確定なら投入方法に記す。

### 指摘（B05-02 / IT-B05-02-040）
- 主張: 2回起動した後に在庫履歴が1件なら、2回目は対象外だったと判定する。
- 実際: design.txt L0024 は送信履歴がない注文を対象とし、L0035–L0036 は処理後のメール送信と履歴登録を定める。ケースは1回目終了後の送信履歴・在庫履歴を確かめていない。
- 判定: 抜けを確かめていない
- 修正案: 1回目に送信履歴と在庫履歴ができたことを確認してから再起動する。現状の最終1件だけでは、2回目に初めて処理された場合と区別できない。
