### 指摘（M07-03 / IT-M07-03-080）
- 主張: 判定ID `IT-0035` で、「売却しない」商品の実在庫が削除されず残ることを確認している。
- 実際: `0206_sheet-11` L0084 は「買取承諾時に売却する商品のみ実在庫をつくるようになったため、削除処理をなくす」と定める。一方、IT-0035の判定単位は「無効な値が削除条件に指定された場合、レコードが削除対象とならないこと」であり、本ケースには削除条件の指定自体がない。
- 判定: 判定IDの誤り
- 修正案: IT-0035から付け替える。削除処理廃止を受ける判定単位がなければ、裁定C'に従ってIT-0156を使用する。

### 指摘（M07-03 / IT-M07-03-085）
- 主張: 過去に査定内容承諾の履歴がある買取で実在庫が再作成されないことを、IT-0128で判定している。
- 実際: `0206_sheet-11` L0089 は「過去に査定内容承諾済みにしたステータス変更履歴がある場合は上記の実在庫作成を行わない」と定める。IT-0128は「DB更新後、同画面の更新を行った場合、再度DBが更新されないこと」であり、本ケースは同画面の再更新・二重サブミットを行っていない。
- 判定: 判定IDの誤り
- 修正案: IT-0128から付け替える。履歴の存在を条件とする実在庫作成抑止を受ける判定単位がなければIT-0156とする。

### 指摘（M07-03 / IT-M07-03-093）
- 主張: 査定確定後について「送料と管理者用メモの入力欄が非活性になること」だけを確認して、G1009・G1012をケース化している。
- 実際: `0206_sheet-11` L0263 は「送料、買取情報、選んで買取、まとめて買取、個別入力商品情報が編集不可となる」と対象を列挙している。ケースは選んで買取・まとめて買取・個別入力商品情報の編集不可を確認していない。
- 判定: 抜けを確かめていない
- 修正案: 列挙された各明細区分を事前準備に用意し、査定確定後にそれぞれの編集対象が編集不可になることまで確認する。

### 指摘（M07-03 / IT-M07-03-108）
- 主張: IT-0108の1ケースで、「会員の本人確認情報を取得できません。」の表示と、買取状況が更新されないことを期待している。
- 実際: `0206_sheet-11` L0445 は当該エラー時の画面再表示を定め、L0413 は失敗時に「入力内容は保存しない」と定める。画面上のエラー結果とDB非更新は異なる判定結果だが、IT-0108はエラーメッセージの判定単位である。
- 判定: 判定IDの誤り
- 修正案: ケースを画面再表示の確認とDB非更新の確認に分け、それぞれ対応する判定IDを付ける。

### 指摘（M07-03 / IT-M07-03-109）
- 主張: IT-0120の1ケースで、「入力エラーが表示された画面の再表示」と「生年月日が更新されないこと」を期待している。
- 実際: `0206_sheet-11` L0445 は不正な生年月日のとき買取詳細画面を再表示すると定め、L0413 は入力内容を保存しないと定める。IT-0120の判定単位は検証失敗時のデータ非反映であり、画面再表示を受けない。
- 判定: 判定IDの誤り
- 修正案: 画面再表示とDB非更新を別ケースに分ける。IT-0120はDB非更新側だけに使用する。
