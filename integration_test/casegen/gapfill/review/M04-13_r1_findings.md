### 指摘（M04-13 / IT-M04-13-084）
- 主張: 「CSVの記載順」で3商品が表示されることを期待している。
- 実際: 0202_sheet-18 L0199 は「分割先商品は登録された順に表示される」とするだけで、CSVの行順を登録順とする定めはない。画面登録分についてのみ「一番上に表示」と明記されている。
- 判定: 設計書に無い期待
- 修正案: CSV行順を期待値にしない。CSV登録時の「登録された順」を一意に特定できないなら、G0146はケースにしない。

### 指摘（M04-13 / IT-M04-13-089・090）
- 主張: IT-0013・IT-0016を使い、CSVの商品コード必須・最大255文字を分割先商品一覧への追加有無で判定している。
- 実際: 0202_sheet-18 L0194 は、CSVの商品登録ボタン押下時について「画面に分割先商品が表示される（データベースへの登録は行わない）」と明記する。一方、IT-0013・IT-0016はDBへのレコード登録を判定する単位である。
- 判定: 判定IDの誤り
- 修正案: 現在の手順・期待結果にはDB登録用の判定IDを割り当てない。画面上だけの必須・桁数検証として扱うなら、結合テストケースから外す。

### 指摘（M04-13 / IT-M04-13-091〜095）
- 主張: IT-0013・IT-0016〜0019を使い、CSVの分割先分割在庫数の境界を一覧への追加有無で判定している。
- 実際: 0202_sheet-18 L0194 は、この段階では「データベースへの登録は行わない」とする。IT-0013・IT-0016〜0019はいずれもDB登録内容の必須・境界値を受ける判定単位である。
- 判定: 判定IDの誤り
- 修正案: 現在の画面上だけの確認にはこれらの判定IDを使用しない。DB保存まで確認しない単項目制限なら、SCOPEに従って結合テスト対象外とする。

### 指摘（M04-13 / G0281）
- 主張: 「結合の出庫が登録される操作が設計書どうしで決まらない」ためケースにしないとしている。
- 実際: 0202_sheet-51 L0321 は「結合を登録し、入庫完了にした」、L0322 は「在庫結合登録を行い、結合を承認（入庫完了）する」と、いずれも入庫完了までの操作を定める。L0326〜L0328には結合元ごとの出庫履歴と、自動記載する同一形式の理由が示されている。
- 判定: ケースにできる
- 修正案: 食い違う区分名だけを期待結果から外し、入庫完了時に結合元の出庫履歴が登録され、自動理由が記録される共通部分をケース化する。

### 指摘（M04-13 / IT-M04-13-102）
- 主張: 自動理由を「結合元：M0413-JOIN-A-102、M0413-JOIN-B-102」の順序まで固定している。
- 実際: 0202_sheet-51 L0045 は「在庫結合棄却による戻し 結合元：A、B、C 結合先：D…」と理由の構成を示すが、複数の結合元を登録順・商品コード順などのどの順序で並べるかは定めていない。
- 判定: 設計書に無い期待
- 修正案: 結合元商品コードの並び順を合否条件にしない。区分、理由の固定部分、必要な商品コードと結合先・番号が含まれることを確認する。

### 指摘（M04-13 / IT-M04-13-103・104）
- 主張: 分割先の自動理由を「M0413-DST-A…、M0413-DST-B…」の順序まで固定している。
- 実際: 0202_sheet-51 L0047〜L0048 は「分割先：A、B、C」を含む理由形式を示すが、複数の分割先をどの順序で記載するかは定めていない。
- 判定: 設計書に無い期待
- 修正案: 分割先商品コードの順序を期待結果から外す。理由の固定部分と、分割元・全分割先・在庫結合分割番号の包含を判定する。

### 指摘（M04-13 / G0302）
- 主張: 結合の出庫時点が登録時と承認時で食い違うため、総原価減算と出庫履歴をケースにしないとしている。
- 実際: 0202_sheet-51 L0321〜L0322はいずれも登録後に承認して入庫完了にする一連のシナリオを記載する。L0326〜L0328は結合元A・B・Cについて、変更前総原価2000・3000・4000から変更後1400・1650・1600への減少と各出庫履歴を具体的に示す。
- 判定: ケースにできる
- 修正案: 区分名の食い違いとは分け、入庫完了時の結合元総原価の減少と履歴登録をケース化する。異なる判定単位になる場合はケースを分ける。
