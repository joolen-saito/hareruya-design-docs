### 指摘（M04-09 / IT-M04-09-127）
- 主張: G0125・G0126をケース化し、「DBで在庫変動履歴を確認する」としている。
- 実際: 0202_sheet-15 L0086-L0089は「在庫変動履歴は、下記の内容を表示する」「在庫数、増減」「店舗移動の移動元と移動先を表示する」と定めている。DB確認だけでは画面表示を確認していない。
- 判定: 抜けを確かめていない
- 修正案: 在庫変動履歴の画面を開き、在庫数・増減数・移動元店舗・移動先店舗の表示を確認するケースにする。

### 指摘（M04-09 / G0127）
- 主張: IT-M04-09-135・136は、2明細の振替元または振替先を「両方」ロックし、全件が更新されないことを期待している。
- 実際: 0202_sheet-15 L0159-L0160は「一部の在庫のみ更新するのではなく、全件更新せず処理をロールバックする」と定めている。両方を事前にロックすると最初の更新前に失敗できるため、先行明細の更新が後続明細の失敗でロールバックされることを確認できない。
- 判定: 抜けを確かめていない
- 修正案: 実行順序を確定したうえで後続明細だけをロックし、先行明細を含む全更新が巻き戻ることを確認する。

### 指摘（M04-09 / G0288）

### 指摘（M04-09 / IT-M04-09-119）
- 主張: 判定ID IT-0142を付け、期待結果を「在庫数が10のまま、総原価が7692のまま」としている。
- 実際: 0202_sheet-51 L0277-L0287は、欠品時に加算履歴と減算履歴を作り、それぞれ所定の在庫変動理由を持たせる。IT-0142の判定単位も「最終数量・金額・理由が仕様通り整合すること」だが、本ケースは理由を確認していない。
- 判定: 判定IDの誤り
- 修正案: 数量・金額だけを受ける判定IDへ付け替える。IT-0142を使うなら、最終状態に対応する理由の確認も期待結果へ含める。
