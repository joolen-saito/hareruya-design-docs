### 指摘（F03-02 / IT-F03-02-099）
- 主張: 手順4で「確認の『OK』を押す」としている。
- 実際: 0303_sheet-4 L0284-L0285 は「入荷通知機能を追加」「別紙『入荷時通知』参照」とし、0303_sheet-9 L0074-L0078 はログイン済みなら押下時に登録し、入荷通知依頼確認のOKは「リニューアルでは非表示とする」と定める。
- 判定: 成立しない前提・手順
- 修正案: 確認モーダルのOKを押す手順を削除し、通知ボタンの押下後にDBを確認する。完了モーダルを閉じる必要があるなら「OK(入荷通知依頼完了)」と特定する。

### 指摘（F03-02 / IT-F03-02-109）
- 主張: 入荷通知ボタンを押した後に「確認の『OK』を押す」としている。
- 実際: 0303_sheet-9 L0074-L0078 は、ログイン済みの場合はボタン押下時に登録し、確認モーダルを刷新後は非表示と定める。0303_sheet-9 L0088-L0089 にある押下可能なOKは「OK(入荷通知依頼完了)」である。
- 判定: 成立しない前提・手順
- 修正案: 刷新仕様に合わせ、確認モーダルを経由しない手順に直す。表示確認のため完了モーダルを閉じるなら、完了モーダルのOKと明記する。

### 指摘（F03-02 / IT-F03-02-110）
- 主張: 「通知待ち」押下後に「確認の『OK』を押す」としている。
- 実際: 0303_sheet-9 L0102-L0105 は「通知待ち」の押下時にキャンセルしてモーダルを表示し、「OK(入荷通知キャンセル確認)」は「リニューアルでは非表示とする」と定める。完了側のOKはL0109の別ボタンである。
- 判定: 成立しない前提・手順
- 修正案: キャンセル確認のOKを押す手順を削除する。完了モーダルを閉じる操作が必要なら「OK(入荷通知キャンセル完了)」と書く。

### 指摘（F03-02 / G1695）
- 主張: IT-F03-02-096・097は専用会員を「ログイン可能・選手情報あり」とするが、両会員シードの投入方法はお気に入り関係の登録しか記載していない。
- 実際: 0303_sheet-4 L0277-L0279 は「会員がログイン済みの場合」にお気に入り状態を表示すると定める。専用会員を作成する共有シードも使用しておらず、記載された投入方法ではログイン前提を作れない。
- 判定: 成立しない前提・手順
- 修正案: 会員、ログイン可能状態、選手情報およびお気に入り関係を作成する投入方法に直す。

### 指摘（F03-02 / IT-F03-02-099・109・110）
- 主張: 各専用会員シードはログイン可能な会員・選手情報を状態に掲げる一方、投入方法は入荷通知依頼の削除または登録しか行わない。
- 実際: 0303_sheet-9 L0074-L0077 は、ログイン済みかどうかで登録処理が分かれると定める。記載された投入方法では、各手順に必要な専用会員と選手情報を作成できない。
- 判定: 成立しない前提・手順
- 修正案: 各投入方法に会員と選手情報の作成を明記し、その後にケースごとの依頼0件または既存依頼を設定する。
