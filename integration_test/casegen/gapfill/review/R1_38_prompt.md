## 意図的であり指摘対象外のもの

- 連鎖IDが空欄、要求IDが空欄であること。保留のケースが無いこと。既存ケースを変えていないこと。
- 単体テスト・e2e へ送られるもの（画面上だけの入力制限の検証、表示文言の逐語照合、見た目、計算式そのもの）のケースが無いこと。
- シードの投入方法が「未確定: …」と書かれていること。
- 裁定に従っている箇所（B: 「観点内で確定」の判定単位は適用条件が設計書から言えれば使える／C': 受ける判定単位が無いものは IT-0156）。
- 抜けの一覧に無い定めのケースが無いこと（今回の範囲は抜けの一覧だけ）。

## 重点観点

1. 追加ケースの期待結果が設計書の記述から一意に出るか。設計書に無い値・ふるまいを期待していないか。現行仕様と刷新の指示が食い違うとき、刷新を採っているか。
2. 事前準備の状態から手順を実行して期待結果に到達できるか。単独で成立するか。期待結果の値が事前準備の値から決まるか。
3. 追加ケースが、指摘ID列の抜け（gaps.tsv の記述と理由）を実際に確かめているか。
4. 判定IDの当て方、1ケースに複数の期待結果、既存ケースとの重複、物理名の混入。
5. 「ケースにしない」とした抜けのうち、設計書の記述から期待結果が一意に決まるもの。「既存ケースで確認済み」としたもののうち、挙げたケースが実際には確かめていないもの。

## 出力形式

指摘が無ければ `NONE` の1語。あれば1件ごとに次の形で、機能IDの順に書く。1機能あたり最大8件。確信の持てないものは挙げない。見出しの括弧の先頭は必ず機能ID。

```
### 指摘（<機能ID> / <テストID または 指摘ID>）
- 主張: ケースまたは仕分けの記述（要点の引用）
- 実際: 設計書の事実（単位と行番号。原文を引く）
- 判定: 期待結果の誤り／設計書に無い期待／成立しない前提・手順／抜けを確かめていない／判定IDの誤り／重複／ケースにできる／確認済みでない
- 修正案: 結論を先に置いた1〜2文
```
