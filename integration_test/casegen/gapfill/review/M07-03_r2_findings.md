### 指摘（M07-03 / G1000）
- 主張: IT-M07-03-081〜083で、査定内容承諾時の実在庫・履歴の洗い替えを確認済みとしている。
- 実際: `0206_sheet-11` L0088は「選んで買取とまとめて買取の売却する商品の明細から実在庫と実在庫履歴を洗い替えする」と定める。081・082は実在庫、083は選んで買取の履歴だけを確認し、まとめて買取の履歴を確認していないうえ、全ケースが既存実在庫・履歴0件なので洗い替えも確認できない。
- 判定: 抜けを確かめていない
- 修正案: まとめて買取からの履歴登録を確認するケースを足す。洗い替えについても、既存の実在庫・履歴がある前提で置換結果を別ケースにする。

### 指摘（M07-03 / IT-M07-03-091）
- 主張: 選んで買取のサプライ品`M0703-091-SUP`を変更し、実在庫`M0703-091-STK`が変わらないことでG1005を確認している。
- 実際: `0206_sheet-11` L0121は「選んで買取明細の明細内容変更に伴う実在庫情報への反映は行わない」と定める。しかし事前準備とシードには、`M0703-091-STK`が変更対象の`M0703-091-SUP`に対応する実在庫である記述がない。
- 判定: 抜けを確かめていない
- 修正案: 変更対象明細に対応する実在庫であることを事前準備とシードに明記する。その対応実在庫の数量・単価・小計が不変であることを確認する。

### 指摘（M07-03 / IT-M07-03-099）
- 主張: IT-0035の1ケースで「エラー表示」と「カード明細が削除されないこと」を期待している。
- 実際: `0206_sheet-11` L0432は「エラーを表示して、買取情報編集（買取詳細）画面に遷移する」と定める。一方、`viewpoints_canonical.tsv`のIT-0035は「無効な値が削除条件に指定された場合、レコードが削除対象とならないこと」だけを判定し、エラー表示・遷移は受けない。
- 判定: 判定IDの誤り
- 修正案: エラー表示・遷移とDB非削除を別ケースに分ける。IT-0035はDB非削除側だけに付ける。

### 指摘（M07-03 / IT-M07-03-101）
- 主張: IT-0106の1ケースで、OK後の閲覧表示への切替と、再編集時に増減数が空であることを確認している。
- 実際: `0206_sheet-11` L0419はOK時の「閲覧表示に切り替える」を、L0438はOK時の「編集内容を破棄」をそれぞれ定める。`viewpoints_canonical.tsv`のIT-0106は項目・文言の表示状態を判定するもので、入力内容の破棄は受けない。
- 判定: 判定IDの誤り
- 修正案: 閲覧表示への切替と編集内容の破棄を別ケースに分ける。破棄側は対応する判定単位がなければ裁定C'に従いIT-0156とする。

### 指摘（M07-03 / IT-M07-03-110）
- 主張: MTGBuyer査定完了の買取を手動で「査定内容連絡済み」に変更することでG1036を確認している。
- 実際: `0206_sheet-17` L0024-L0026は「手動メール通知でお客様宛に査定内容メールを送信したタイミングで」「管理画面からこのステータスに切り替える」と定める。ケースの事前準備・手順には査定内容メールの送信がない。
- 判定: 抜けを確かめていない
- 修正案: 手動メール通知で査定内容メールを送信してから、査定内容連絡済みへ変更する手順にする。

### 指摘（M07-03 / IT-M07-03-111）
- 主張: 1万円以上かつ本人確認未確認の買取を「簡易書留送付済み」に変更することでG1038・G1043を確認している。
- 実際: `0206_sheet-17` L0029-L0031はトレードチームからお客様へ簡易書留を送付した該当ケースで管理画面から切り替えると定め、L0127-L0130も「お客様宛簡易書留発送」から「簡易書留送付済み」への遷移を示す。ケースには簡易書留発送済みの前提がない。
- 判定: 抜けを確かめていない
- 修正案: お客様宛簡易書留を発送済みであることを事前準備に明記してから、簡易書留送付済みへ変更する。
