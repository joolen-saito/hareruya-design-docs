# シードを画面で作る形への書き直し（2026-10-09〜13）

依頼者決定（2026-10-09）: 結合テストのテストデータは、実際には画面から入力して作る。画面で作れるシードは、投入方法を画面操作に書き直す。
画面が自動で振る番号（注文番号・受注ID・イベントIDなど）を固定値で名指ししていたケースは、**データを画面で作ったときに振られた番号を控え、その控えた番号を使う**形に直す。

## 結果

対象は、作り方が確定していて投入方法がDBへの直接投入に触れていたシード 10,862件・357機能。

| 判定 | 件数 |
| --- | --- |
| 画面（すべて画面操作で作れる） | 5,363 |
| 画面+DB（画面で作り、一部の値だけDBへ直接設定する） | 4,403 |
| DB（画面では作れない。投入方法は変えていない） | 1,096 |

番号を控えた番号へ置き換えたケースは 8,686件。全シード 13,549件の投入方法は、書き直し前が「DBだけ 約7,900・画面だけ 約700」、書き直し後が「画面だけ 6,128・画面+DB 4,415・DBだけ 992・その他（外部の試験環境・ファイル配置など）1,053・未確定 961」。

画面で作れない理由（画面+DB と DB の計 5,499件。`all.tsv` の理由欄の先頭）:

| 理由 | 件数 | 中身 |
| --- | --- | --- |
| 入力欄なし | 1,656 | その項目を入力・変更する画面が実装に無い |
| 過去日時 | 1,431 | 登録日時・受注日などを過去や特定の日時にする必要がある |
| 隔離 | 1,049 | 同じ条件に当たる他のデータの削除・初期化が要り、削除の画面が無い |
| 不整合 | 602 | 画面の入力チェックが通さない状態 |
| 外部・バッチ | 361 | 外部システムやバッチ・非同期処理が作るデータ |
| その他 | 158 | |
| 固定番号 | 138 | 番号の桁数・並び順・境界そのものを確かめるなど、控えた番号では成り立たない |
| 大量 | 104 | 100件以上 |

## 控えた番号の書き方

- シードの状態・属性: 固定の番号を消し、「<番号の名前>は登録時に画面が振る（控える。以下〔注文番号-M0526-012〕）」と書く。呼び名は番号の名前＋機能ID＋ケース番号（共有シードは「-共有」）。
- シードの投入方法: 画面で登録したあと、どの画面のどこに表示された番号を控えるかを書く。
- ケース: 事前準備・手順・期待結果の固定の番号を呼び名〔…〕に置き換える。手順の8,039件・期待結果の8,427件は、番号と呼び名の違いだけ（それ以外は文の言い回しの小さな違い）。
- 試験者が画面で入力する値（名称・コード・メールアドレス・CSVの中身）は固定値のまま。判定がDBのシードの番号も固定値のまま。

## 仕組み

| 何 | どこ |
| --- | --- |
| 対象のシード | `build_in.py` → `in/<機能ID>.tsv`・`targets.tsv` |
| 書き直し（機能ごとに1担当。画面と入力項目の実在を実装・設計書で確かめる） | `SCREEN_PROMPT.md`・`mk.py` → `out/<機能ID>.tsv`（シードID／判定／新しい状態・属性／新しい投入方法／理由／根拠）、`cases/<機能ID>.tsv`（テストID／新事前準備／新手順／新期待結果） |
| 検査 | `gate.py`（全シードが1行ずつ、画面なのにDBの語が無いこと、消した番号がケースに残っていないこと、呼び名がシード側に定義されていること など）→ `all.tsv` |
| ケースの正本へ当てる | `apply.py`（`../cases/` のシード表とケースを置き換える。何度流しても同じ） |
| 前提条件の検査の不合格の直し | `GATEFIX_PROMPT.md`・`mk_gatefix.py`・`gatefix/` |

**`apply.py` は上書きの重ね書きである。** `sheetmap/`・`nosheet/`・`gapfill/`・`ga/` の `merge_into_cases.py` を流すと `../cases/` は作業ファイルの内容（書き直し前）へ戻るので、そのあとに必ず `python3 seed_screen/apply.py` → `python3 build_all_test_cases.py` を流す。

前提条件の検査（`../precond/gate_precond.py`）との関係:
- 期待結果・手順を変えた基線のケースには、`apply.py` が `precond/oracle_changes/`・`step_changes/` へ宣言を書く（類型T4: 画面が自動で振る番号は、画面で登録したときに控えた値を使う。2026-10-09 依頼者）。
- 控えた番号へ置き換えたケースの一覧は `precond/screen_noted_cases.tsv`。検査は、これらのケースの改名先の検査を外し、〔…〕の呼び名を識別子として数えない。

## 読むときの注意

- 書き直しは codex などの別担当のレビューに掛けていない。画面と入力項目の実在は担当が実装・設計書を読んで確かめたもので、実機では試していない。
- 「画面+DB」は、画面で登録したあとDBで一部の値を直す二度手間になる。件数が多い理由（入力欄なし・過去日時・隔離）は、試験用の補助機能を用意するか、ケースの組み方を変えるかで減らせる可能性がある。
- 状態・属性に、刷新後の画面にも実装にも項目が無いもの（例: イベントの会場）が残っているシードがある。理由欄に書いてある。
- `pilot_v1/` は、番号の扱いを決める前の試行（参考）。
- 2026-10-13 の再開分（109機能）で、担当のサブエージェント104本が依頼文の禁止に反して `out/`・`cases/` の結果を main へ個別にコミット・プッシュした（中身は結果ファイルの追加だけ）。
