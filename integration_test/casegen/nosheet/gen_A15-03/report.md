# A15-03 ユーザー情報参照 ケース作成報告

ケース10件（IT-A15-03-001〜010）、シード11件（共有可1・ケース専用10）。根拠は 0515 A15-03 の節と、トークンのヘッダ名jwt-tokenおよび GET /user を書いている 0515 A15-01 の「以降の認可」（REQ-0515-sheet-1-R013）。

## 対応表（設計書の記述 → 判定ID → テストID）

| 設計書の記述 | 判定ID | テストID |
| --- | --- | --- |
| 業務ロジック 取得対象（指定が無ければ自分の情報）、入出力 成功時出力、出力: フィールド code（R003, R011, R015） | IT-0215 | 001 |
| 出力: フィールド user_name・profile・deck_user_id の取得元（R016〜R018） | IT-0010 | 002 |
| 認証「返すのは認証したプレイヤー自身の情報だけ」（R006） | IT-0219 | 003 |
| 未設定のときはnull（R016〜R018）：全項目未設定／一部のみ未設定 | IT-0156 | 004, 005 |
| 認証 ヘッダ欠落→401、入力 認証用トークンのヘッダ（必須）（R005, R008, R010, R012） | IT-0224 | 006 |
| 認証 署名不正→401（R005, R008, R012） | IT-0224 | 007 |
| 認証 該当するプレイヤーなし→401（R005, R008, R012） | IT-0224 | 008 |
| 参照機能であること（取得対象、R003）。更新しない | IT-0225 | 009 |
| 認証通過後に対象プレイヤーを取得できない→HTTP 400「Invalid request parameters」（R005, R009, R012） | IT-0156 | 010 |

- 未設定時のnull表現を受ける判定単位が観点表に無い（IT-0145は画面表示、IT-0216・0217は0件表現）ので IT-0156 を使った。
- 成功例（R019〜R025）は代表値の例示で、ケース001・002が同じ項目構成を確かめる。
- 要求表に行が無い記述は無い。

## ケースにしなかったもの

| 設計書の記述 | 理由 |
| --- | --- |
| デッキユーザーIDを指定したときの分岐（R003, R010） | 設計書が「本書では扱わない」としている（A15-04 の範囲） |
| 署名方式はHS256（R005） | HS256以外で署名したトークンの扱いが書かれておらず、期待結果が決まらない。HS256の署名が有効であることはケース001〜003、009が使う |
| 他のクライアントからの呼出しの拒否（R006） | 拒否のふるまいが書かれていない。デッキビルダーアプリからの正常呼出しはケース001で確かめる |
| 認証拒否のメッセージが「Access Token is incorrect」か「Authentication failed」のどちらになるか（R012） | 条件ごとの対応が書かれていないため、どちらかであることまでを期待結果にした |
| 「キーは区切り記号付きの小文字で組み立てる」（R011） | 変換結果そのものであり単体テストの範囲。キー名はケース001が確かめる |
| 表示メッセージ「本APIは画面メッセージを扱わない」（R026）、トークン原値・署名シークレットを記載しない（R006） | 検証できる挙動が無い |

## 設計書の不備として報告すること

- 認証拒否（401）の2種類のメッセージを、どの条件でどちらにするか書いていない。
- HTTP 400（プレイヤー取得不可）に至る条件が書かれていない。ケース010は投入方法を「未確定」で残した（裁定L・H）。
- 認証用トークンのヘッダ名とエンドポイントは A15-03 の節に無く、A15-01 の節にだけある。
- リニューアル後の仕様の節は見出しだけで中身が無い。

## 試験環境に要るもの

- ケース001の「呼び出し元がデッキビルダーアプリ」を実現する手段（設計書に識別方法の記載なし）。
- 顧客IDとプレイヤーIDが異なる値で対応付けられた顧客・プレイヤーの登録（ケース001〜003）。
- 試験用署名鍵「A15-03-JWT-KEY」をHS256で設定する手段（S-A15-03-ENV）。
- 顧客・プレイヤーを記載値で登録するDBシード手段（ニックネーム・プロフィール・デッキユーザーIDを未設定にできること、更新日時を固定できること）。
- 認証通過後に対象プレイヤーを取得不可にする方法（S-A15-03-NOTFOUND-010、未確定）。
- 顧客IDを指定して有効なjwt-tokenを発行するテスト用認証データ作成機構。顧客IDだけを持つ署名が正しいトークン（プレイヤー無し）も発行できること。
- ブラウザの開発者ツールからjwt-tokenヘッダを付けて GET /user を送れること、ケース009でデータベースを参照できること。
