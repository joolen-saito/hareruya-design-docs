## 判定単位の選び方

- 結果に応じたHTTPステータス（200・404）だけを IT-0182 に当てる。処理結果コード・メッセージ・デッキ名は IT-0182 に混ぜず、正常応答の内容は IT-0215（034）、下書きが参照された確認は IT-0156（018・020）に分けた。参照範囲の限定は IT-0219。認証トークンの欠落・不正は IT-0224（A15-12 は401でなく404と定めている）。
- 出力項目の構成・並びを受ける判定単位はファイル出力用のみで、APIの項目値は IT-0215（応答の必須項目・値型が期待形式と一致）に当てた。優先順位・補完・区別しない応答は受ける判定単位が無いので IT-0156 を使った。
- IT-0225 は、設計書が参照機能として書いている（永続化の節が無い）ことから適用した（裁定B）。
- 確認したい値は事前準備に書いた値から決まる。日時は表記形式が書かれていないので、同じ日時を表すことで照合する。

## ケースにしなかったもの

| 記述 | 理由（何が書かれていないから決まらないか） |
| --- | --- |
| トークンは有効だがプレイヤーが存在しない顧客IDのとき | 「無い、または有効でない」に当たるかが書かれていない。A15-01 は「GET /deck/{id} を除く」が401を返さないとだけ書く |
| 大会デッキの所有プレイヤーのニックネーム | 「ユーザーデッキのときのニックネーム」とあるだけで、ほかの種別で含めるか値なしかが書かれていない |
| 限定公開トークンを所有者以外・公開デッキで返すか | 項目は無条件に挙がるが、条件が書かれていない（A15-13 は自分のデッキ検索のときだけ） |
| デッキタグ以外の項目（採用カード・キャンペーンタグ）が0件のとき | 「タグがあるときに含める」はデッキタグだけで、ほかは0件時の表現が書かれていない |
| 下書きが参照不可のとき保存済みへ切り替えるか | 「下書きがあればそれを参照対象」とのみ。017・019は下書きを対象とする記述から導いた |
| 処理中の例外・共通例外処理 | 中身が書かれていない |

| 開始・終了日時から開催前0・開催中1・開催後2を決める算出 | 日時から状態を決める規則・境界が書かれていない。算出そのものは単体テストの担当（裁定F）。029は開催状態の項目が0・1・2の整数で含まれることだけを確かめる |
| 採用カードの並び順 | 配列要素の並びが書かれていない。030は順不同で確かめる |
| 採用カードの不明カード可否の値 | 既知カードのマスタから決まるとは書かれていない。値は照合しない。項目が採用カードの要素に含まれることだけを031で確かめる |

## 設計書の不備として報告すること

- 開催状態を開始・終了日時からどう決めるか、採用カードの並び順、不明カード可否が何から決まるかが書かれていない。

- 閲覧用トークンの入力項目名と指定位置（クエリかヘッダか）が書かれていない。エンドポイントは A15-12 に無く、A15-01 の一覧から取った。
- 応答の項目名（JSON のキー）、日時の表記形式、デッキ種別・可否の値の表現（真偽か数値か）、404時の処理結果コードの値が書かれていない。
- 所有者判定は「顧客IDからプレイヤーを引く」と書かれているが、所有者との一致をプレイヤーのどの属性で見るか（デッキ利用者ID）が書かれていない。
- 要求表に行が無い記述は無い（R001〜R042 で足りた）。

## 試験環境に要るもの

- 試験用署名鍵（呼び名「A15-12-JWT-KEY」。実際の設定値は標準のBase64として復号できる文字列にする）と一時保存先（S-A15-12-ENV）、会員・プレイヤー2人（S-A15-12-PLAYERS）、マスタ（S-A15-12-MASTERS。採用カード用カードは日本語・英語の言語別の画像行だけ、代表カード画像用カード1512923・1512924は最新画像の行だけを登録する。キャンペーンタグは終了日時を必ず持たせる）。
- デッキを固定IDで登録するDBシード（デッキ登録APIはIDが発番される）。デッキID 91512015・91512016 は存在しない状態にする。
- 下書きの限定公開トークンを指定値にする方法（S-A15-12-DRAFTUNLWRONG-019、S-A15-12-DRAFTUNLMATCH-020 の投入方法は「未確定」）。デッキ更新APIは閲覧用トークンを入力に持たず応答で返す。
- 閲覧用トークンの指定位置は、実機のAPIで確かめて手順に反映する。
