## ケースにしなかったもの

| 設計書の記述 | 理由 |
| --- | --- |
| 結合論理 NOT の意味（カード名・カードテキスト・カード種別・サブタイプ・レアリティ。R028, R030, R032, R039, R042） | 許容語としてあるだけで、語どうしをどう結ぶのかが書かれておらず、期待する絞り込み結果が決まらない |
| 並び替えキー「色順」の具体的な並び（R010, R054） | 色の並び順が書かれていない。既定が色順・昇順であることは同じ並びとして039で確かめた |
| 範囲指定の下限・上限ちょうどの扱い、下限が上限より大きいときの扱い（R006） | 書かれていない |

## 設計書の不備として報告すること

- エンドポイントのパス・HTTPメソッド、検索条件の問い合わせの項目名（英字名）が A15-08 の節にも同じ冊子の他の節にも無い。手順は設計書の項目名（カード名、色 など）で書いた。
- 応答の項目名も日本語の説明名だけで、実際のキー名が無い。
- 結合論理 NOT、色順の並び、範囲の境界、複数値の結び方、アトラクション・ステッカーの判定条件、完全一致の対象が書かれていない（上の表）。
- フォーマットで区分が登録されていないカードの扱いは書かれていない。「使用可および制限のカードに限定」から除かれるとしてケース027に含めた（裁定待ち）。
- 裁定待ち：ee 実装は許容値に反する並び順などを既定値へ置き換えて HTTP 400 にしない旨のコメントを持ち、設計書の HTTP 400 と食い違う。設計書を正としてケース053〜058を書いた（実装は期待値の根拠にしていない）。

## 試験環境に要るもの

- カード・カード種別・サブタイプ・色・レアリティ・フォーマットを記載値で登録するDBシード手段（日本語名・英語名・テキスト・マナ総量・パワー・タフネス・ロイヤルティ・画像URL・イラストレーター・更新日時、フォーマットでの区分を設定できること）。
- シード077：検索処理中に例外が起きる状態の作り方（投入方法に「未確定」と書いた。HTTPステータス500だけを期待結果にした）。
- シード061：1枚のカードに複数のレアリティを持たせる投入手段（投入方法に「未確定」と書いた）。
- シード005：アトラクション・ステッカーと判定されるカードの作り方（投入方法に「未確定」と書いた）。
- ブラウザの開発者ツールから jwt-token ヘッダの有無・値を変えて要求を送れること。
- ケース052でデータベースのカード全体の登録件数と更新日時を参照できること。
- カード全件を含む環境でも、カード名の語「A1508-nnn」で他のカードと分離できる前提（語に当たる他のカードが無いことを事前に確認する）。
