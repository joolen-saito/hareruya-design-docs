## 判定単位の選択の注記
- IT-0156（ITA-02）008 / 009: 「コマンド名が未指定・不一致 → 処理を行わずに終了」を受ける判定単位が観点表に無い（IT-0159 は「エラーとなる」、IT-0351 は「異常として定められた」ことが前提で、設計書は異常と書いていない）。
- IT-0156（ITA-02）011: 表示メッセージ表の「後続処理: 処理を終了する」を、取得失敗の後にファイルの書き出しを行わない定めと読んだ。設計書は「異常終了」と書いていないので IT-0352（適用条件は異常終了）は使えず、受ける判定単位が観点表に無いため IT-0156 とした。
- IT-0088 / IT-0089: 設計書は「所定のファイルへ書き出す」とだけ書く。同名の1ファイルへの書き出しなので、観点表（観点内で確定）の上書き・混在なしを適用した（裁定B）。006 は旧データが無く新3件だけになること、007 は記事レコードとして新2件が各1件で旧記事が0件であることを確かめる（文字列の出現回数ではなく記事レコードで数える）。002 も出力された記事の合計が20件であることを確かめる。
- IT-0084（所定のディレクトリへの作成）は、設計書が格納先と後続の参照を書いていないので使わず、ファイル名の確認（IT-0070）だけにした。
- 出力記事の並び順は設計書に書かれていないので、位置は確かめない。

## ケースにしなかったもの
| 記述・判定単位 | 理由（何が書かれていないから決まらないか） |
| --- | --- |
| 記事情報の項目構成（IT-0087 必須キー、IT-0095 / IT-0096 フロントの読み取り期待） | 記事情報にどの項目が入るか、読み取る側の期待が設計書に無い |
| 応答の本文から記事情報を取り出す（IT-0071 値の同値確認） | 記事情報の出力項目（タイトル等）が設計書に無く、何の値を応答と同値確認するか一意に決まらない。2巡目の指摘でタイトルを期待にしたケースを外した |
| 格納先ディレクトリ（IT-0069、IT-0093 / IT-0094） | 「所定のファイル」とあるだけで、格納先と、公開側が読む参照先が書かれていない。格納先は「所定の格納先」と呼び、場所は共有シードに未確定で残した |
| 文字コード（IT-0085） | 文字コードの定めが無い |
| 作成結果を返す（IT-0167 終了コード） | 「作成結果を返す」の中身（終了コードか戻り値か）が書かれていない |
| 取得失敗の各原因（IT-0201 HTTP 200以外、IT-0202〜0204 タイムアウト・DNS失敗・接続拒否で未処理例外にならないこと） | 取得失敗に当たる条件が列挙されていない。接続できない場合だけは取得失敗に当たると言えるので011 / 012に使った |
| エラー文言（IT-0354） | 表示メッセージ表が「文言は正本に記載が無い」としている |
| 取得失敗時に出力ファイルを書くか（IT-0201 の「保存・出力せず」） | 012 は表示メッセージ表の「処理を終了する」だけを根拠にした。異常時のファイルの扱いを直接書いた記述は無い |
| 空本文・JSON構文不正の応答（IT-0170〜0172、IT-0168） | 取得した応答が空・不正のときの扱いが書かれていない |
| 出力先に書けない場合（IT-0092） | 書き出し失敗時の扱いが書かれていない |
| リトライ・タイムアウト（IT-0205、IT-0164） | 再試行・待ち時間の定めが無い |
| 更新抑止（IT-0225） | DBを使わず、設計書も参照専用の機能とは書いていない |

## 設計書の不備として報告
- 外部記事サイトの公開APIの宛先、所定のファイルの格納先、正規のコマンド名の値が書かれていない。
- 「作成結果を返す」の返し方、記事情報の項目構成、取得失敗の条件、失敗時のファイルの扱いが書かれていない。
- 表示メッセージ表の文言が空（正本に記載が無い）。
- 要求ID列は materials/B17-01_requirements.tsv の行に拠る（sheet.txt 本体には要求IDの表示が無いが、要求表に対応する行があり、検査も空欄を不合格にする）。裁定待ち（不具合とみられる現行のふるまい）は無い。

## 試験環境に要るもの
- 外部記事サイトの公開APIの代わりの模擬API（応答の記事・要求件数の上限・受信記録・停止ができるもの）と、バッチの宛先をそこへ向ける手段。未確定: 実装では宛先が固定値。
- 所定の格納先の場所（実装ではユーザーデータ配下のlistフォルダ）。
- バッチを正規のコマンド名で起動する手段（実装ではeccube:create:latest-article-list。設計書に値は無い）。
- JSON構文の検査手段（jq等）。
- 全ケースが同じ格納先を使うため、順に実行する。
- 取得失敗のケース（010 / 011）には模擬APIを停止または接続不能にする操作が要る。具体的な操作は未確定（シードの投入方法に明記）。
