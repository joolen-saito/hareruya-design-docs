### 指摘1（A15-03）
- 主張: report.md は「認証を通ったのちに対象プレイヤーを取得できない状態の作り方が設計書に書かれていない」ため、HTTP 400のケースを作成していない。
- 実際: `A15-03_sheet.txt:8` は「認証を通ったのちに対象プレイヤーを取得できないときは入力不正（HTTP 400）」、同13行は「『Invalid request parameters』を返す」、同18行も同じHTTPステータスとメッセージを明記している。期待結果は一意であり、前提の作成方法が不明でも裁定Lによりケースを残す対象である。
- 判定: 取りこぼし
- 修正案: HTTP 400と「Invalid request parameters」を確認するケースを追加する。前提の作成方法はシードへ「未確定: 認証通過後に対象プレイヤーを取得不可にする方法」と記載する。

### 指摘2（IT-A15-03-009）
- 主張: 期待結果は「プレイヤーの総件数が要求の前後で変わらないこと」だが、事前準備には開始時の総件数がなく、手順も要求後にだけ総件数を確認している。
- 実際: `A15-03_sheet.txt:6` はプレイヤー情報を返す参照処理を定めるだけで、試験開始時の総件数は与えていない。ケースの事前準備から決まるのはプレイヤーID 7150309の値だけであり、要求前の総件数を観測・固定していないため前後比較が成立しない。
- 判定: 成立しない前提・手順
- 修正案: 事前準備に開始時のプレイヤー総件数を具体値で定め、要求後も同じ件数であることを確認する。

### 指摘3（IT-A15-03-006）
- 主張: 「jwt-tokenヘッダを付けず」送信するケースに判定ID `IT-0214` を付けている。
- 実際: `A15-03_sheet.txt:8` は「ヘッダ欠落」を認証拒否条件としている。観点表の `IT-0224` は「認証ヘッダ、署名、トークン…の前提が欠落または不正な場合」を判定単位としており、この条件に直接一致する。
- 判定: 判定IDの誤り
- 修正案: 判定IDを `IT-0224`、観点IDを `ITB-04` に変更する。
