## 書かなかったもの

| 根拠 | 理由 |
| --- | --- |
| IT-0214 `ids` 欠落（R012 必須〇） | 必須とあるだけで、欠落時のステータス・エラー形式が根拠のどこにも無い |
| 許可IPによる制限（R004 認証方式 IP制限） | 「IP制限」とあるだけで、拒否時のステータスなどが無い。許可IPの設定は試験条件（S-A07-07-API）としてのみ使う |
| 500（取得中の例外） | 例外を起こす手段が根拠に無い |
| R001 メソッド一覧（POST以外） | POST以外を受けたときのふるまいが無い。POST「有」のみ001で使用 |
| R013・R026 リクエスト／レスポンスのサンプル | 内容が空で、値の根拠にならない |
| 返す順序 | 定めていないため期待結果にしない |
| 0507シート9の現行仕様の埋め込み | A07-06のものの取り違えなので使わない |

## 試験環境に要るもの

- 試験実行端末の送信元IPを許可IPにできるAPI設定と、認証トークンの生成と検証に使う試験用秘密値（A07-06と同じ作り方）
- 管理者ログインAPI、管理者会員が存在しない利用者IDのトークンを作るeeの結合試験補助コード
- ネット買取受注・個別入力商品のDBシード投入と、実行前後にDBを確認する手段（IT-A07-07-002・012）
- 識別子は 97〜91 の接頭辞＋0707＋ケース番号3桁（9桁整数）。`grep -r` で cases/ と重ならないことを確認済み

## レビュー1巡目の反映（2026-10-06）

- `saleFlg` の型は期待結果にしない。HTML設計書は「文字列(true,false)」、現行ソースは真偽値を返しており、どちらを正とするかが決まっていない（設計の確認事項）。値（true／false）だけを照合する。
- `ids` を付けない要求のケースは作らない。HTML設計書は必須としているが、欠落時のふるまいが書かれていない（現行ソースは検証せずに抽出を行う）。設計の確認事項。
- 署名不正のトークンは、署名部分の先頭の文字を変えて作る（末尾の文字は変えても署名が変わらない場合がある）。
