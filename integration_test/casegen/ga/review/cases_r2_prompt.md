## 重点観点

1. 期待結果が設計書の記述から出るか。設計書に無い値・挙動を期待していないか。事前準備の値から期待結果の値が一意に決まるか（税込と税抜の取り違え、文字列と数値の取り違え、8桁ゼロ埋め、並び順、重複除去の単位）。現行ソースで実際にそうなるかも確かめよ。
2. 判定IDの当て方が判定単位の文に合うか。
3. 各ケースが単独で成立するか。事前準備の状態から手順を実行して期待結果の画面に到達できるか（現行ソースの画面遷移・ログイン要否・注文完了までの条件に照らして、到達できない手順・成立しない前提を挙げよ）。事前準備が手順の結果を先取りしていないか。
4. 設計書の表の行（条件・項目・エッジケース）のうち、ケースが無いもの。report.md の「書かなかった理由」が妥当か。
5. 同じことを確かめている重複ケース。1ケースに期待結果が複数入っているもの。
6. 実行できない確認方法（開発者ツールのコンソールで受け渡し領域を表示する、という方法で観測できない期待結果）。
