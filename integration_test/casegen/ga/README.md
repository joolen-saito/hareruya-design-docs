# アクセス解析（Googleアナリティクス）連携の結合テスト

依頼者決定（2026-10-06）: 現行システムのアクセス解析連携を刷新後へ移植するので、結合テストで確かめる。
期待値の正は現行どおり／根拠は設計書を先に起こす／範囲はアクセス解析側の受信まで。

## 仕組み

現行は、画面がページ内の受け渡し領域（`dataLayer`）へ値を積み、タグの管理サービス（Googleタグマネージャ）がそれを読んでアクセス解析へ送る、の2段。
現行リポジトリにあるのは前段だけで、後段（どの値をどのイベント・項目で送るか）はタグの管理サービス側の設定で決まり、リポジトリに無い。

## 判定単位と範囲

| 判定ID | 見るもの | ケース |
| --- | --- | --- |
| IT-0341 | 受け渡し領域へ積む項目名・型・入れ子の構造 | あり |
| IT-0342 | 積む値が取得元の業務データと一致 | あり |
| IT-0343 | 積む条件（ログインの有無・対象の画面・言語）で積む／積まないが切り替わる | あり |
| IT-0344 | 0件・空のときの表現 | あり |
| IT-0345 | 表示1回あたりの件数、同じ取引が重複して積まれない | あり |
| IT-0346 | タグの管理サービスを経由したアクセス解析への送信が発生する | **未作成** |
| IT-0347 | アクセス解析が受信した値が積んだ値と一致 | **未作成** |

IT-0346・0347 は、タグの管理サービスのコンテナ設定（どの値をどのイベント名・項目名で送るか）と、試験用のアクセス解析の受け口が手元に無く、期待値を決められないので作っていない。コンテナ設定の書き出しを入手したら、設計書に「送信する内容」を足してからケースを書く。

## 確認方法

手順の最後でブラウザの開発者ツールのコンソールから受け渡し領域の内容を表示し、項目名と値と件数で判定する。
タグの管理サービス自身が積む要素を除くため、環境シードでタグの管理サービスのスクリプトを読み込まない状態にしているケースがある。

## 直すときの手順

1. `ga/cases/<機能ID>_ga_test_cases.tsv`・`_ga_seed_data.tsv` を直す
2. `python3 ga/verify_ga.py`
3. `python3 ga/merge_into_cases.py`（cases/ の F10 のファイル、`ga_map.tsv`、`precond/added_cases.tsv` の F10 の行を作り直す）
4. `python3 build_all_test_cases.py` と `python3 precond/gate_precond.py --all`

識別子の注意: シードの名称・コードは、英数字とハイフンの連なり1つ1つに機能とケース番号を入れる（「F1002商品001」は「F1002」で切れて全ケースで重なり、ゲート G5 で落ちる。「F1002-001-A」と書く）。
