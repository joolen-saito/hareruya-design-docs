# M07-07 買取商品（キャンセル）CSV 作成報告（レビュー1巡目反映後）

対象: 0206 【新規】買取商品一覧（キャンセル）CSV出力項目（要求10件）と、同じ冊子の 0206 買取一覧(検索結果)（出力対象の条件。裁定A）。ケース12件。

## 対応表（設計書の記述 → 判定ID → テストID）

| 要求ID | 記述 | 判定ID | テストID |
| --- | --- | --- | --- |
| R001 | 買取商品一覧CSV出力項目（概要） | IT-0080 | 012 |
| 検索結果シート sheet-4 R046〜R050・R075 | 出力対象の条件・一括チェック | IT-0072 | 005, 006, 007, 008, 009 |
| 検索入力シート sheet-3 R082 / R081 | 未選択時の警告 / 0件時に出力操作が出ない | IT-0156 / IT-0107 | 010 / 011 |
| R002〜R010 | 識別ID1〜9 の9項目の構成と並び | IT-0156 | 001 |
| R002,R004〜R010 | 同、値が取得元と同値（言語ID・空欄の規則を含む） | IT-0071 | 002, 003, 004 |
| R003 | 識別ID2 キャンセル数（位置は001で確認、値は下記） | IT-0156（位置のみ） | 001 |

001=項目の構成と並び、002=日本語・状態SPの値、003=個別入力商品、004=状態なし。005〜008は商品データ行の件数と商品名まで確認する（005=チェックした買取情報だけ、006=キャンセル済みを除く、007=売却しないのみ、008=えらんで買取・まとめて買取・個別入力）。009=タイトルのチェックによる一括、010=未選択時の警告、011=0件時、012=CSV出力が買取・在庫を更新しない（IT-0080）。010は未選択を受ける判定単位が観点表に無く、他観点に割り当たらない機能仕様としてIT-0156を使った。
出力項目の構成・並びを受ける判定単位が観点表に無いので IT-0156 を使った。

## ケースにしなかったもの

| 対象 | 理由 |
| --- | --- |
| R003 キャンセル数の値（第2項目） | 「キャンセルの個数を表示する」とあるが、買取明細のどの属性か（数量か、別の個数か）が書かれていない。取得元の不足。第2項目は値の照合から外す（9項目の構成は001で確認） |
| 出力の並び順 | 検索結果シートの並び順の記述は買取商品一覧CSVの節にあり、キャンセルCSVは「同様のフォーマット」とだけある。フォーマットと並び順が同じか決まらない |
| 見出し行の有無・データ開始行、ファイル名、文字コード、権限 | 設計書に記述が無い。データ行は商品名・商品コードで特定する |
| 取り消し線・廃止・不要・Ph2 | 対象のシートに該当記述なし |

## 設計書の不備として報告すべきもの

1. シート名は「（キャンセル）」だが、機能名は「【新規】買取商品一覧CSV出力項目」、概要は「買取商品一覧CSVの出力」、機能NoはM07-05（入金CSVと重なる）。
2. キャンセル数の取得元、買取価格・商品名の備考が空。
3. 「状態がない場合」の状態が、買取明細の状態未設定を指すと読めるが明記が無い。
4. キャンセルCSVに並び順が適用されるかが書かれていない。

## 試験環境に要るもの

- 管理者アカウント（S-M07-07-ADM。管理者IDは自動採番のため固定しない）、略称タグ・レアリティ（M、C）・状態（NM、SP）・言語（ID 1、2）の共有マスタ。
- 003・008: 個別入力商品、まとめて買取の明細の作り方が未確定。
- 004: 状態を未設定にした買取明細を作れるかが未確定。
- 検索入力の期間絞り込みに初期値があるため、買取依頼日は試験実施日にしている。専用DBで、同じ注文者名・買取番号の他データが無いこと。
