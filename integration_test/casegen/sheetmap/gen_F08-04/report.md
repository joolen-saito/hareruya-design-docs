# F08-04 会員登録フォーム ケース作成レポート

対象シート「0308 会員登録フォーム」。ケース42件、シード47件（共有可2・ケース専用45）。レビュー1巡目でメール書式不正のケースを外し、2巡目で2件（確認画面の項目17〜21、10分超過後の入力内容の消去）を足した。今回、HTML設計書に載った現行仕様（業務ロジック・入出力・表示メッセージ）で見直し、14件を足し、6件の期待結果と8件の出典を直した（仕分けは review/F08-04_cur_dispositions.md）。
別シートの根拠（裁定A）: 0308 店頭買取査定申込情報入力（sheet-4）の「画面の進み方」、同 登録確認～完了（sheet-5）の表示メッセージと判定順序、同 申込確認（sheet-7）の項目16〜21と「入力データの併合の優先順位」。
sheet.txt を正とした。要求表（2026-09-01抽出）のR014・R015は「最大32・8～32文字」だが現HTMLは「最大50・最低12～最大50」で、現HTMLを採った。
現行仕様の文は要求表に行が無い。ケースの要求ID欄には、同じ項目のExcel由来の行か別シートの項目行のIDを書き、出典に「現行仕様 <小見出し>」を書いた。

## 設計書の不備として報告すべきもの

1. 項目定義の書式列が、入力欄のはずの識別ID2〜5を「ラベル」「ボタン」としている。
2. 不一致エラーの扱いが Excel 由来（エラーとして確認へ進まない読み）と現行仕様（確認画面に表示）で食い違う。009・010 は Excel 由来を採った。
3. 入力時間の10分超過が、操作せずに自動遷移するのか、次の操作の時に遷移するのかが書かれていない。
4. 現行仕様の「エントリー」と Excel 由来の「店頭買取査定申込前ログイン画面」が同じ画面かが書かれていない。026〜028・039・040 は同じ画面として書いた。
5. sheet-7 の項目21「査定申込み」ボタンは「会員登録フォームで入力した場合は表示」で、スキップ時の申込み確定方法が読み取れない。
6. 利用規約モーダルの内容が書かれていない。
7. sheet-4 は10分超過で「入力内容を消去」、F08-04 は「事業者の入力は消さない」とし、sheet-7 も事業者の保持データは残ると書く。039 は後2者に合わせた（sheet-4 の「入力内容」に事業者入力が入るかが書かれていない）。

## 試験環境に要るもの

- 会員登録フォームのURLへ店舗識別名つきでPOST送信する手段（026〜028。URLは設計書に無い）。店舗識別名は英数字とアンダースコアだけ。
- 10分を超える待機（023・024・039・040は約10分30秒、025は合計12分以上）。039は2回入力するため操作が長い。
- DB確認: 012・014（会員が登録されていないこと）。DB投入: 016・033・034（会員1件ずつ。必須列は試験用の値で埋める）。店舗の追加（共有1件、026・027用に2件）。
- パスワード欄の値を見る開発者ツール（034）。パスワードの受理条件（文字種）が設計書に無いため、英数字・ハイフン・@・ピリオドの値が拒否されないこと（036）。
- 英語表示への切り替えは申込情報入力画面のLanguageで行う（040）。投入方法が未確定のシードは無い。
