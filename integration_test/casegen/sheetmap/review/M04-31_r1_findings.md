# 前半（001〜063）担当のレビュー
### 指摘1（IT-M04-31-011）
- 主張: 判定IDをIT-0284とし、存在しない3ページ目を指定すると2ページ目が表示されることを確認している。
- 実際: IT-0284の判定単位は「ページング一覧で全ページを走査した場合、ソートキー重複時も含めてレコードの重複・欠落が発生せず、総件数と一致すること。」である。本ケースは全ページの重複・欠落や総件数を判定していない。
- 判定: 判定IDの誤り
- 修正案: IT-0284を外し、存在しないページからの表示ページ切替に合う判定単位へ付け替える。IT-0284は010・035のように全ページを走査するケースへ限定する。

### 指摘2（IT-M04-31-013）
- 主張: 在庫反映日時が「2026/10/12 15:30:00」のシードに対し、「在庫反映日2026/10/12」が表示されるとしている。
- 実際: REQ-0202-sheet-37-R019は「2-5 在庫反映日 … 在庫反映を実行した場合のみ表示」とするだけで、時刻の非表示や`yyyy/mm/dd`形式を定めていない。`yyyy/mm/dd`の指定があるのは別項目の計画作成日だけである。
- 判定: 設計書に無い期待
- 修正案: `2026/10/12`という表示形式の断定を除き、反映実行時だけシードの在庫反映日時に対応する値が表示されることを判定する。

### 指摘3（IT-M04-31-018）
- 主張: 存在しない棚卸計画を指定すると「HTTPステータス404」になるとしている。
- 実際: REQ-0202-sheet-37-R028の原文は「対象の棚卸計画が存在しない場合はページが見つからない扱いとする。」であり、HTTPステータスコードは指定していない。
- 判定: 設計書に無い期待
- 修正案: HTTP 404の断定を削除し、「ページが見つからない扱いとなり、棚卸計画編集画面が表示されないこと」までにする。これに伴いHTTPステータス用のIT-0126も見直す。

### 指摘4（IT-M04-31-021）
- 主張: IT-0012の1ケースで、登録、編集画面への遷移、成功メッセージ、棚卸名・店舗・在庫区分・備考・商品数の表示をすべて期待している。
- 実際: IT-0012の判定単位は「全項目に値が指定された場合、レコードが登録されること。」である。画面遷移はIT-0295、画面項目の表示はIT-0010等の別判定単位であり、規約も「判定の種類が違えば分ける」としている。
- 判定: 判定IDの誤り
- 修正案: IT-0012のケースは全項目が登録された結果の確認に絞る。遷移や表示項目まで判定する場合は別ケースに分ける。

### 指摘5（M04-31：IT-M04-31-056〜061）
- 主張: 商品登録CSVの商品コードに`M0431-056-P1`、`M0431-057-P1`などハイフンを含む値を使い、056では正常登録、057〜061では重複・在庫不存在・必須など別の判定結果を期待している。
- 実際: REQ-0202-sheet-40-R008は「商品コード　半角英数　〇」と明記する。ハイフンは英字でも数字でもないため、各CSVは目的とする条件とは別に書式制限へ違反している。
- 判定: 成立しない前提・手順
- 修正案: 056〜061の商品コードを、ケース番号を含む半角英数字だけの一意な値へ変更する。これにより正常登録または各異常条件だけを単独で成立させる。

### 指摘6（M04-31：REQ-0202-sheet-40-R008）
- 主張: report.mdは「『半角英数』違反は、エラー文言・結果が書かれていない」としてケース化していない。
- 実際: REQ-0202-sheet-40-R008は商品コードを「半角英数」に制限する。さらにREQ-0202-sheet-37-R049は、棚卸商品CSVの形式・内容に不備がある場合について「登録を取り消し、棚卸計画編集画面に遷移する」と定めているため、少なくとも非登録と後続遷移は一意に決まる。
- 判定: 取りこぼし
- 修正案: 半角英数以外の商品コードを含むCSVについて、棚卸商品が登録されず編集画面へ遷移するケースを追加する。設計から決まらないエラー文言の逐語照合は含めない。

### 指摘7（M04-31：REQ-0202-sheet-37-R049）
- 主張: report.mdはR049を057〜064・066で網羅した扱いにしている。
- 実際: R049には「棚卸計画に店舗または在庫区分が設定されていないため、CSV登録できません。」という個別条件と、「登録を取り消し、棚卸計画編集画面に遷移する」という結果がある。全125件に、店舗または在庫区分が未設定の棚卸計画で商品CSVを登録するケースはない。
- 判定: 取りこぼし
- 修正案: 店舗または在庫区分が未設定の棚卸計画を専用シードで用意し、規定メッセージ、登録取消し、編集画面への遷移を確認するケースを追加する。

### 指摘8（M04-31：REQ-0202-sheet-37-R049）
- 主張: report.mdはR049のCSV形式不備を062で確認済みとしているが、062は見出し全体の不一致だけを扱う。
- 実際: R049には、汎用の「CSVのフォーマットが一致しません。」とは別に、「CSVのフォーマットが一致しません。 %d 行目のデータを確認してください。」という行単位の不備に対する結果が定義されている。該当する期待結果を持つケースはない。
- 判定: 取りこぼし
- 修正案: データ行の列構成が定義された1列形式と一致しないCSVを用い、行単位の形式不備と登録取消しを確認するケースを追加する。

### 指摘9（M04-31：REQ-0202-sheet-39-R046）
- 主張: report.mdはR046を031・035で確認済みとしている。
- 実際: R046の原文は「初期値100件、選択肢: 10件 50件 100件 300件 500件 1000件 2000件 10000件 12000件」。031は初期値100件、035は10件を選択できることしか確認しておらず、残る選択肢をどのケースも確認していない。
- 判定: 取りこぼし
- 修正案: 棚卸計画編集画面の表示件数選択肢9件を確認するケースを追加する。一覧画面の003は別画面の部品なので代替にならない。

# 後半（064〜125）担当のレビュー（指摘番号は前半と重なるので、後半は「後半-指摘N」と呼ぶ）
### 指摘1（IT-M04-31-067、068、069、080）
- 主張: 商品CSVを1列、数量CSVを2列で作成し、正常登録を期待している。

### 指摘2（IT-M04-31-089、092、093、099、112）
- 主張: 明細IDが小さい商品を先に置き、登録後や差異確認後に特定の商品へ遷移すると期待している。
- 実際: `sheet.txt` 374行は「次の商品」、376行は「次の差異未確認商品」としか定めていない。編集一覧にも並び順の記載はなく、明細ID昇順が明記されているのはCSV出力だけ（317行）。
- 判定: 設計書に無い期待
- 修正案: 明細ID順を前提にした遷移先の特定を除く。並び順が決まるまで、特定の商品が「次」であることを期待するケースは report.md の未確定事項とする。
