# 依頼文の型：新しく載った現行仕様でのケースの見直し

機能設計書を起こして HTML 設計書へ埋め込んだ機能について、既存の結合テストケースを見直すときの依頼文。`<FID>` は機能ID。

## 読むもの（この順）

1. `sheetmap/GEN_SHEETMAP_PROMPT.md`（ケースの書式と決まり）、`sheetmap/FIX_R1_BRIEF.md`（裁定A〜L、C'）、`sheetmap/FIX_R2_BRIEF.md`（決まりM〜O）
2. `integration_test/SCOPE.md`（結合テストの範囲。単体・e2e へ送るもの）、`casegen/precond/README.md`（前提条件 P1〜P13）
3. `integration_test/viewpoint_canonical/viewpoints_canonical.tsv`（判定単位。IT-0348 出力項目の構成・並び、IT-0349 レコードの並び順、IT-0350 通知メールの内容、IT-0351〜0354 バッチの異常終了の状態・異常終了後の後続処理・一時的な資源の後片付け・出力メッセージを含む）
4. `sheetmap/materials/<FID>_sheet.txt`。**「Source:」の行より後ろが、今回新しく載った現行仕様**。それより前が Excel 由来の本文
5. 既存の `sheetmap/cases/<FID>_sm_test_cases.tsv`・`<FID>_sm_seed_data.tsv`、`sheetmap/gen_<FID>/report.md`
6. 手本: `sheetmap/review/B08-07_cur_dispositions.md`（仕分けの書き方）

## やること

1. 現行仕様を1文ずつ仕分ける。行き先は次のどれか。
   - 既存のケースで確かめている（テストIDを挙げる。本当に確かめているかをケースの手順と期待結果で確認する）
   - 新しいケースにする
   - 既存のケースを直す（出典・前提・期待結果。現行仕様で細部が決まったもの、現行仕様と矛盾していたもの）
   - ケースにしない（理由: 単体テスト送り／e2e 送り／期待結果が決まらない／外から確かめる手段が無い運用上の記述／Excel 由来と食い違う など）
2. ケースを足し、直す。**既存ケースのテストIDは変えない**。新しいケースは既存の続き番号。削除が要るときは番号を詰めない。
3. 仕分けを `sheetmap/review/<FID>_cur_dispositions.md` に書く（現行仕様の小見出しごとに、文 → 行き先 → テストIDまたは理由）。
4. `sheetmap/gen_<FID>/report.md` を今の内容に合わせて直す（対応表、ケースにしなかったもの、設計書の不備、試験環境に要るもの）。
5. `python3 integration_test/casegen/sheetmap/verify_sheetmap.py <FID>` を通す。

## 決まり

- **現行仕様と Excel 由来の本文が同じ事柄について食い違うときは Excel 由来を採る。** Excel 由来が項目名や上位の言い方しか書いておらず細部が無いときは、現行仕様で細部を決めてよい。食い違いに気づいたらケースにせず report.md に挙げる。
- 期待結果は設計書（sheet.txt）の記述から一意に出るものだけ。実装やソースを読んで期待結果を決めない。実装は、事前準備・シードの作り方と手順の実行可能性を確かめるためにだけ読んでよい（スクリプトやコマンドは読むだけで、絶対に実行しない）。
- 1ケース1期待結果。各ケースは単独で成立する。期待結果の値は事前準備の値から決まるようにする。
- 受ける判定単位が観点表に無いものだけ IT-0156。作り方が分からない前提は、シードの投入方法を「未確定: …」として残す（裁定H・L）。保留のケースは作らない。
- 要求表に行が無い記述は、近い見出し行の要求IDで代えず、出典欄に「現行仕様 <小見出し>」と書く（既存の B08-07 のケースの出典の書き方に合わせる）。
- 物理名（テーブル・カラム・クラス・変数・環境変数の名前）を書かない。秘密情報・個別の会員の識別子を書かない。
- 異常系は「起こし方」が設計書に無くても、期待結果が設計書に書いてあればケースにする（起こし方は「未確定」）。

## してはいけないこと

- 上の3種のファイル（cases の2つ、dispositions、report.md）以外を変更しない。`merge_into_cases.py` は流さない。git の変更操作をしない。
- `sheetmap/review/` にある他の機能のファイルと `*_out.txt` は読まない（手本の B08-07_cur_dispositions.md を除く）。
- Write が拒否されたら理由を読んで直す。report.md が書けなければ全文を返答に貼る。
- 一時ファイルはスクラッチパッドに、名前へ機能IDを入れて作る。

## 返答

(1) 件数（見直し前 → 後、足したテストID、直したテストID）、(2) verify の結果、(3) ケースにしなかった現行仕様の文と理由の要約、(4) Excel 由来と現行仕様の食い違い、(5) 投入方法が未確定のシード。
