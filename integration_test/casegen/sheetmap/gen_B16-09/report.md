# B16-09 サイトマップ生成処理 ケース作成レポート

根拠は 0416 サイトマップ生成処理（Excel 由来の本文と、埋め込まれた現行仕様）。ケース88件（001〜011はExcel由来、012〜088は現行仕様の細部。069以降はcodexレビューで追加）、シード90件（共有2・ケース専用88）。別シートは使っていない。
現行仕様の仕分けは `review/B16-09_cur_dispositions.md`。現行仕様のケースは出典を「現行仕様 <小見出し>」とし、要求表に現行仕様の行が無いため要求ID欄は R002（概要の機能）で代えた（要求表に行が無い）。
出力項目の構成・並びは IT-0348/0349 を使った（017・018・060・019・041・045・055・058）。

## 方式の違いと扱い（依頼者確認 2026-10-07）
Excel 由来は日次バッチ、現行仕様は要求のたびに XML を返す画面側の機能。新システムでは画面側の機能が B16-09 の実装。食い違う事柄は Excel 由来を採り、既存の001〜011は変更しない。Excel 由来が定めていない事柄（要求先、索引、掲載条件、並び、0件、本店と支店、旧アドレス）を012以降でケースにした。

## Excel 由来と現行仕様の食い違い（ケースにしなかった）
- 実行の契機: Excel 由来は Eventbridge+Lambda による毎日4:00のバッチ。現行仕様は要求のたびに組み立てる。
- 出力先: Excel 由来は S3 へアップロード。現行仕様は応答として XML を返す。
- 差異があるときだけ上げる: Excel 由来は前日との比較で差異があるときだけ上げる。現行仕様は毎回組み立てる。
- 作り方: Excel 由来はクローラーで到達できるURLを集める。現行仕様はデータの掲載条件で選ぶ（リンクの無い公開ページも載る）。
- 疑い（Excel 由来はURLを書かず判定できないのでケースにしたもの）: 商品・買取商品・デッキ詳細のサイトマップの掲載（017・044〜058）は、商品検索・カードリスト購入・デッキ検索ページ以降に当たらないと見なした。当たる場合は Excel 由来を採り、該当ケースを外す。
- 疑いがありケースにしなかったもの: カテゴリのサイトマップ（絞った商品一覧のURLを掲載。商品検索ページ以降に当たる疑い。現行仕様自身も商品一覧は既定ページに載せないと書く）。

## ケースにしなかったもの
| 記述 | 理由 |
| --- | --- |
| R001,R003,R011,R029〜R033 | 見出し・空の表の項目名だけで、期待結果になる記述が無い |
| R007〜R010,R012 | 前提条件・利用ツール名。挙動の記述でない |
| R024〜R026 | pingを含めない。送信先が書かれず、通信が無いことを観測する宛先が決まらない |
| 出力ファイルの名前・保存先・初回実行・差異が無いとき・複数リンクや外部ドメイン・実行失敗 | 書かれていない |
| 現行仕様の組み立て方式の文 | 上記の食い違い |
| カテゴリのサイトマップ（並び・掲載・言語区分の引き継ぎ） | 上記の疑い |
| XMLの書式、タイムゾーンの値、言語区分と店舗コードの区切り | 書かれていない（タイムゾーンは添えられていることだけ、区切りはパスの先頭の順だけ確認） |
| ページ番号が数字以外のときの応答の種類 | 「要求先に一致しない」とだけ書かれる（015は内容が返らないことだけ） |
| 表示メッセージ | 画面が無い |

## 設計書の不備として報告すべきもの
- 方式が違う記述が同じシートに載っている（実行の契機・出力先・差異判定）。どれを新システムの正とするか整理が要る。
- 「取得しない」ページのURLが無く、現行仕様の掲載対象との関係が判定できない。「それ以降」も曖昧。
- 要求先の言語区分・店舗コードの区切り、日時のタイムゾーン、XMLの書式が無い。「既定ページの確認用」の意味が無い。
- 「入力データ検索条件」「実行結果詳細」「エラーハンドリング」が見出しだけで空。前日分の保管場所、初回実行時の扱いが無い。
- 実行トリガーの表記が「Eventbridge+Lamdba」（誤記と思われる）。
