## ケースにしなかったもの

| 要求ID | 理由 |
| --- | --- |
| S14-R001, S15-R001 | 「履歴画面を追加する」は要件の総則。個別の記述でケース化した |
| S14-R031, R032（言語・状態の項目） | 何を絞り込むか、選択肢は何か、複数選択の結合が書かれておらず期待結果が決まらない（同冊子の別シートにも定義なし） |
| S15-R002, R004 | 「買取店舗以外は店頭買取と同一」。参照先の店頭買取は別冊子（0205）で根拠にできない |
| S15-R003, R009〜R012 | CSV出力・CSVダウンロード・対象チェック。M07-11（全件）と M07-12（選択）が担当 |
| S15-R006 | CSVの出力順。M07-11/12 が担当（IT-0349） |
| S15-R014 | 申込者=姓+半角空白+名は連結の結果そのもの。単体テストへ送った（裁定F） |
| S15-R023 | 増減数=変更後在庫-変更前在庫は差の計算そのもの。単体テストへ送った（裁定F） |
| S15-R025 | 更新日時の取得元（何の更新日時か）が書かれていない（裁定E） |
| 異なる項目の組合せ検索 | 項目どうしをANDで結ぶとは書かれていない。各ケースは単一項目で絞る |
| 日付の境界・From のみ・To のみ | 境界を含むか書かれていない。015は範囲の内外を境界から離して確かめた |

廃止・不要・Ph2・取り消し線の記述は対象シートに無かった。

## 設計書の不備として報告すべきもの

1. 申込者名の空白区切りは、本シートが「いずれかの入力が一致していれば出力」（S14-R006）、買取一覧(検索入力)の現行仕様は語どうしをAND。S14-R005「買取一覧と同仕様（以下記載の仕様）」の括弧は本シート下の記述を指すと読み、刷新の指示であるOR（S14-R006）を008の期待結果にした。
2. 「買取日時」「査定申込日時」「更新日時」が買取情報のどの項目に当たるか不明。031・032は名称のまま事前準備に書き、投入方法を未確定にした。
3. 一覧の1行が何の単位か（買取明細1行か実在庫履歴1行か）と、該当件数の数え方（買取情報か行か）が書かれていない。020・021は1買取情報に明細1行で、どちらでも同じ値になるように組んだ。
4. ステータス一覧の表示名に「★」が付いている（新ステータスの注記か名称か不明）。009は★を除いた名称を期待した。
5. 検索結果の項目定義の表記ゆれ: 識別ID 3 CSVダウンロードに「選択した商品履歴取得」「検索結果全件取得」の2行（M07-11/12側で扱う）。
6. 画面への入口（メニュー位置）が書かれていない。手順は「買取商品履歴(検索入力)画面を開く」とした。
7. 日付・金額の表示書式、件数の既定値が書かれていない。025は日付を年月日の意味で、026は桁区切りなしの数値で書いた。

## 試験環境に要るもの

- ネット買取の買取情報（買取注文・買取明細・実在庫・実在庫履歴・買取状況の変更履歴）を登録するDBシード。管理画面からは作れない。各ケース専用（001〜030）。
- 031・032: 未確定。買取日時・査定申込日時が買取情報のどの項目か設計書に無い。
- 025・015: 未確定。振込完了日を、ステータス変更履歴の日付として持つのか買取情報の項目として持つのかが設計書に無い。
- 028: 未確定。個別入力商品を実在庫情報へ紐づけて登録する方法が設計書に無い（ee実装のスキーマ確認が要る）。
- 買取状況マスタ（共有可。別添資料の一覧どおり）。管理者アカウント m0710_admin（共有可）。
- 011・015〜018は検索条件が広いので、事前準備のとおり「他に当たる買取情報が無い」状態にする。専用DBで流す前提。
- 030のDB確認は実在庫・実在庫履歴・買取明細・買取状況を読めるDB参照環境。
