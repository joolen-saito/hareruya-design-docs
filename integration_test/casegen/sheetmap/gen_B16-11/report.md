## ケースにしなかったもの

| 要求ID | 理由 |
| --- | --- |
| R029,R031,R033,R035,R037 の「以上」の境界ちょうど | 「kB」が1000バイトか1024バイトか書かれていない。境界ちょうどのサイズでは期待結果が決まらない。ケースはどちらの定義でも結果が同じになるバイト数（例: 250kB規定に300000バイト）にした |
| 規定を超えるファイルが0件のときの扱い（メールを送らないか） | 「超えるファイルがある場合、通知する」とだけ書かれ、無いときに何もしない・通知なしとは書かれていない（エラーハンドリング欄は空） |
| img/goods/L/NUM/ 配下で250kB以上400kB未満のファイル | goods/L/ と img/goods/L/NUM/ は包含関係で、NUM配下を商品サムネイル(250kB)と見るか(400kB)と見るか決まらない。002・006のNUM配下の値は両方の規定で同じ結果になる値（450000／200000バイト）にした |
| メール本文のファイルサイズの数値（例: 312 kb）の照合 | kBの定義と丸めの定め（切り捨て・四捨五入、小数桁）が無い。011は「数値と kb」の形式だけを見る |
| 本文のURL組み立て（goods/L 以外） | 例示は goods/L の1件だけ。banner・product・set のURLが決まらない。002-005・006・007は本文にファイル名が記載されることだけを期待にした |
| R005,R006（実行環境: バッチ処理用EC2インスタンス） | 実行基盤の指定で、外から見える結果が無い |
| R001,R002,R003,R007,R013,R038,R049-R051,R052 | 見出し・概要・注記・記号。R052「エラーハンドリング」は本文が空 |

廃止・不要・Ph2・取り消し線の記述はシートに無い。

## 設計書の不備として報告すべきもの

- 本文例に「https://files.hareruyamtg.com//img/goods/M/xxxxxxx.png」があるが、対象フォルダ（①〜⑤）に goods/M/ は無い。M を対象に含めるのか、例の誤記かが決まらない（判断を避け、goods/M はケースにしていない）。
- 本文例のURLは「//img」と二重スラッシュ。011は例示どおりに期待しているので、誤記なら直す必要がある。
- 「kB」の定義、サイズの丸め、「以上」と goods/L と img/goods/L/NUM の包含関係の扱い、対象0件時の通知有無、「15分毎」の起点（毎時0・15・30・45分か）、エラーハンドリング（空欄）、BCC宛先（外部Slack連携用）の確認方法。
- 「実行結果詳細 ※主にDBの登録・更新結果について記載」とあるが、DB更新の記述が無い（メール送信のみ）。014はこれを参照のみの機能とみなしてIT-0225を当てた。
