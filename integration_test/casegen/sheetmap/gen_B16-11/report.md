## ケースにしなかったもの

| 現行仕様／要求ID | 理由 |
| --- | --- |
| 同時実行の排他が無いこと | 外から確かめる手段が無い運用上の記述 |
| 設定の既定値（バケット名・公開URL・作業用保存先・接続先） | 既定値が書かれておらず期待結果が決まらない |
| iwatatest 配下（512000バイト以上） | Excel由来（対象は①〜⑤）に無い対象。食い違いとしてケースにしない |
| サイズ数値（バイト数÷1024）そのもの | 単一の変換の結果で単体テスト送り（裁定F）。丸め・小数桁も定めが無い |
| 設定した差出人等を変えて届き先が変わること | 設定値をそのまま使うだけ |
| goods/M（R048）、R005,R006,R001-R003,R007,R013,R038,R049-R052 | 例示の誤記疑い／実行基盤の指定・見出し・記号・空欄 |

廃止・不要・Ph2・取り消し線の記述はシートに無い。

## Excel由来と現行仕様の食い違い・設計書の不備

- 件名: Excel は「画像ファイルサイズ超過アラート」だけ。現行仕様は件名の生成で日時を取得すると読め、件名に日時が付く可能性がある。009 はExcel由来のまま（件名の一致）。
- 対象: Excel は①〜⑤のみ。現行仕様は img/goods/iwatatest/ を加える（ケースにしていない）。
- 「250kB以上」と「超えている」の言い方が混在するが、現行仕様が iwatatest を「512000バイト以上を超過」と書くため、018-022 は「以上」で期待した。
- 本文例に「goods/M」があるが対象フォルダに無い。本文例のURLは「//img」と二重スラッシュで、現行仕様の「s3://とバケット名」の置き換えと公開URLの先頭部分（末尾スラッシュの有無）の関係が決まらない。011・015 は例示どおり。
- 「15分毎」の起点、対象0件のエラーハンドリング欄（空欄）、BCC宛先（外部Slack連携用）の確認方法。「主にDBの登録・更新結果」とあるがDB更新の記述が無い（014はIT-0225）。
- 現行仕様の出力文言「[MAIL_ENABLED=false] …」に設定の名前が含まれる。030 は出力の文言として引用した。

## 試験環境に要るもの

- 設計書と同じフォルダ構成のS3試験バケットとAWS CLI。ダミー画像は指定バイト数で作る。メール試験サーバー（2つの受信箱。033・034・035は受信メールのヘッダ・送信元アドレスも見られること）。
- 設定の変更（送信可否・接続先・作業用の保存先）を与えてバッチを起動できること。031・032 は到達できない接続先（http://127.0.0.1:9）、036 は作業用の保存先の削除。
- 未確定: BCC宛先の受信確認手段（S-B16-11-BCC。008）。
- 未確定: バッチB16-11の手動起動（S-B16-11-RUN。013以外の全ケース）。ee の運用スクリプトを直接実行すれば出力と終了コードは見られるが、スケジューラ（Step Functions）を介さず動かせるバッチ実行環境の用意が要る。
- 未確定: メール送信が失敗する状態の作り方（S-B16-11-MAILFAIL-033）、件名生成・切り分け・判定を異常にする手段（041〜045）。
- 未確定: 設定のBCCを設計書記載値にする手段（S-B16-11-BCC。008）。
- 未確定: スケジュール起動の有効化・時刻操作・実行記録の閲覧（S-B16-11-SCHED-013）。
- 順に実行する: 送信可否（S-B16-11-MAILON）や宛先の設定は共有で、027-030 が書き換えるため、同じ設定を使うケースを同時に実行しない。
