# Codexレビュー結果と対応（ハーネス/skills＋ログインパイロット）

実施: codex exec (gpt-5.5, 読み取り専用) でハーネス・skills・生成スクリプト・ログインパイロットをレビュー。以下、所見と対応。

## 対応した指摘

| 指摘(codex) | 深刻度 | 対応 |
|------|--------|------|
| m01-02 DB操作に「削除」混入（実装は two_factor_auth_key 更新のみ） | 中 | m01-02 DB操作を「更新 / dtb_member / 秘密鍵更新・削除なし」に是正 |
| m01-02 見出しが `m01-02_m01-01_...` でファイル名/TODOと不整合 | 中 | 見出しを `m01-02_admin_login_two_factor_auth（管理画面_二段階認証）`へ |
| TOTP許容ウィンドウを未記録（実装は verifyCode(...,2)） | 中 | 実装確認値「前後2ステップ」を追記 |
| 汎用書込ノートが「（登録／更新／削除）」で不要な削除を列挙 | 中 | 全172docのノートから誤った削除列挙を除去 |
| SKILL本体に衝突時優先順位が明文化されておらず1b/1b-1が逆転して読める | 中 | SKILL 1d（DB=ece＞Excel重複＞実装確認値の優先順位）を追記 |
| 在庫の承認ワークフロー固有がルール文書に無い／DB操作1語規約 | 低/中 | SKILL 1e（承認ワークフローは在庫固有・DB操作は1語始まり）を追記 |
| m01-01 入力項目の最大長が「Length制約に従う」止まり | 低 | 実装確認値50文字（eccube_id/password_max_len）を表へ反映 |
| 表セル内のインラインコード（バッククォート）が未レンダリング | 中 | convert_function_spec_html.py の render_cell を render_inline 経由に修正 → 全HTML再生成で `<code>` 描画 |

## 保留（妥当だが任意/別対応）
- integrate_function_docs_into_excel_html.py のシート自動割当（閾値未満は親追記）リスク → レポート確認運用で対応。
- generate_it_cases.py が `### DB操作` 表を構造的に読まない（本文語ベース）→ 将来の精緻化候補。
- 操作手順の汎用性 → DB操作表から具体操作を差し込む将来改善。

## ログインパイロット評価（codex）
条件付き合格。大筋ec-cube-enterprise実装と整合。上記の中以上の指摘は本対応で是正済み。再生成後の0215で表セルコード描画・見出し整合・削除混入0を確認。
