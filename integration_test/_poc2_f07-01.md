## §1. 全ケース共通前提
- **入口**: フロントの公開画面。イベント大会TOPは `GET /{_locale}/events`（L326）、Excel の URL例は `/ja/events/?shop=19`（0307:L1077）。クエリは `shop`（店舗ID・省略時はCookie等を参考に暗黙指定）を規定（0307:L1071）。日別ルート `GET /{_locale}/events/{eventId}/{eventDate}/` はExcel沈黙のため詳細設計 L326,L337 を補完オラクルとする。
- **権限**: 会員ログインを要しない公開画面。未ログインは閲覧可・会員専用の表示（選手情報）は付かない。ログイン済み会員は日別表示で選手情報を画面へ渡す（L370,L371）。
- **参照系・副作用**: 月間表示・日別表示は参照のみ（L401）。副作用は「クエリ店舗とクッキーが異なる場合のクッキー `shop` 更新」に限る（L356,L397）。セッションは更新しない（L393）。
- **データ供給**: 初期読込で表示対象イベントを json で取得し、既定の絞り込み・日付絞り込み・タブ切替はクライアント側で読込済み json を用いて非同期に処理する（0307:L1050,L1053,L1054,L1056）。したがってタグ絞り込み・日付選択・タブ切替の期待は「再読込を伴わない表示更新」である。
- **祝日**: 祝日管理に登録されている日付を参照する（0307:L1082・詳細設計 L340,L344 も当月祝日を日付セル装飾に用いる旨を規定）。
- **オラクル独立性**: 期待はオラクル（Excel優先・沈黙部は詳細設計HTML）由来で実装から独立。実装との差は付帯表4で乖離＝バグ候補として扱う。オラクルに無い挙動は断定せず「要実機確認」とする。

- gen の期待は詳細設計HTMLの総称verbatim（「観点 内容 表示要素 選択中の店舗名と月…」等）が33件（登録内容17／更新内容16）で反復し、しかも本機能に無い「登録内容/更新内容」観点にDBカラム節の前置き（L359）を機械的に貼っていた。→ 全行を Excel優先＋詳細設計補完の具体挙動へ差し替え、登録/更新は §5 で `要判定`（正本内競合）とし RG-059（副作用=クッキー更新のみ）へ縮退。
- gen が CSRF を `DELEG-STATIC`（根拠は権限節 L370）、未認証を `EXEC-UI`（同 L370）としていたが、本画面はフォーム送信を持たない公開画面（L331,L345,L370,L371）のため、CSRF は §5 で `要判定`（要実機確認）、未認証は公開画面の閲覧可（RG-055）へ是正。
- gen が「確認ダイアログ」を3件 `EXEC-UI` 化していたが、Excel・詳細設計とも確認ダイアログを規定しないため `要判定` へ縮退。代わりに Excel が規定するタブ・タグ・アコーディオン・14日/10日/月送り・受付状況・バナー/特設/協賛を実施ケースへ追加（gen は Excel カスタマイズ範囲を1件も拾っていなかった）。
- gen の `CONTRACT`（HTTPステータス/URL）は、本機能が規定するのは404のみで個別エラー文言は共通例外に委ねる（L380）ため、404 は RG-005,056,057 の `EXEC-UI` へ統合し、汎用ステータスは §5 で `要判定`。
