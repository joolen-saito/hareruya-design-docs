## §1. 全ケース共通前提
- **入口**: `GET /user?deck_user_id={deckUserId}`（JSON API・ブラウザ向け画面を持たない）。自分参照と専用ルートは分かれておらず、同一の `GET /user` のクエリ `deck_user_id` の有無で分岐する。専用のエンドポイントや管理向けコントローラは持たない（L217,L235,L236）。
- **認証・認可**: クエリに `deck_user_id` が指定されている場合、本分岐では `jwt-token` の検証を行わない。デッキユーザーIDを知る任意の呼び出し元が公開向け情報（ニックネーム・プロフィール・デッキユーザーID）を取得できる。呼び出し可能なクライアントはデッキビルダーアプリ（L239,L285）。
- **参照系**: 副作用は無し（参照のみ）。DBは `dtb_player` の検索のみ（L267,L281,L282）。
- **応答**: 応答形式はJSON。成功は HTTP 200・ラッパオブジェクト・JSONキーは snake_case（`code`・`user_name`・`profile`・`deck_user_id`）。`serialize_null` は有効で、未設定項目は null で返す（L236,L253,L254,L268）。
- **オラクル独立性**: 期待は詳細設計HTML（Excel該当なし）由来で実装から独立。実装との差は付帯表4で乖離＝バグ候補として扱う。正本が沈黙する挙動は断定せず「要実機確認」。
