## 未達の層（次フェーズ・品質担保できていない）

**これらが埋まるまで「結合テストとしての品質担保」とは言えない。**

1. **【最重要】各ケースの具体オラクル未整備**（プロジェクト原点の問題）
   - 現状の生成器は「観点文 × HTML表セル」の粗い組合せで、期待値が汎用文言。
     テスト実施者が**そのケースだけを見て入力実値・照合実値を持てず、合否判定できない**。
   - 例: F01-01/CSRFケースの期待値が「標準のページ設定ブロック構成で描画」でCSRF防御を判定していない。
   - 汎用期待値の規模: バリデーション約2,240 / DB約4,865 / 認証手順約2,046。
   - **必要な作業**: `a02-01` の手本（SEED固定値＋設計書由来の具体期待値・各行を実値照合）を全機能へ展開。
     これが「テスト実行可能な品質」の本体であり、本セッションでは未着手。
2. **RISK観点524/528は「薄証拠のリスク候補」（該当と確定はできない）**
   - 冪等キー(524)・Outbox(528)の該当2件ずつは、引用文は実設計書に存在するが、
     **観点が要求する性質そのものを証明していない**（codex指摘）:
     - 524 `a15-02`「冪等な成功応答」は冪等キーの存在・保存・重複排除を示さない。
       `a01-01` の `smaregi_event_id` も、冪等キーとして一意制約で重複排除する、までは書かれていない。
     - 528 `a05-04`/`a17-03` はDB更新と外部転送/中継を規定するが、**Outbox＝DB更新と送信の原子性**は規定していない。
   - よって「証拠駆動で確定」ではなく「冪等性・外部副作用の**リスク調査対象として証拠駆動で選定**」が正確。
     冪等キー/Outboxを合否オラクルにするには、設計または実装方針の追加根拠が要る。
3. **未確定オラクル 33件**（0.13%）
   - 期待値に「実装で要確認/移行先で要確認/記載通り」を含む。設計書自体がTBDの箇所を
     正直に伝播したもの（捏造ではない）。設計確定後に具体化が要る。
4. **超売り(No.518)の合否オラクル未定義**
   - `ESCALATION_oversell_risk.md` の通り、在庫の同時実行ポリシーが業務未確定。
     仕様決定または明示的リリース受容まで No.518 は「完了」扱いにできない。

## この区切りで主張できること・できないこと

- **できる**: 「どの機能に、どの観点の結合テストを、手動/Playwrightどちらで、何件やるか」の
  設計図が、証拠に基づき過不足是正され、監査可能な形で確定した。
- **できない**: 「この25,561件を実施すれば結合テストの品質が担保される」とは言えない。
  各ケースのオラクルが未整備で、実施者は現状のケースだけでは合否判定できない。
