## §1. 全ケース共通前提
- **入口/起動**: コンソールのバッチコマンドで起動する（詳細設計 L314「コンソールのバッチコマンド／`order:batch checkDuplicatePoint`」）。HTTPで届く画面を持たず、外部から引数を受け取らない（Excel 0405:L1763）。Excelの実行トリガーはスケジュール起動(Step Functions)・毎日4時（Excel 0405:L1748）。※移行先の実コマンド名は付帯表4#1。
- **処理骨子**（詳細設計 L319・Excel 0405:L1746,L1747）: ①メール送信経路を準備 → ②二重登録されたポイント履歴を取得（Excelの抽出条件＝対象期間1日・増減量<0・注文ID×増減量の組合せ重複）→ ③該当が無ければ処理終了（メール送らず完了）→ ④該当履歴の受注から注文番号(order_no)を取得 → ⑤管理者へ注文番号を添えた通知メールを送信。
- **副作用**: 二重登録検知時のみ管理者への通知メール送信（詳細設計 L333 副作用／Excel 0405:L1749 出力=メール）。本機能は参照系（検索）でありDBの登録・更新・削除を行わず、ポイント残高の再計算・補正登録も行わない（詳細設計 L325,L339）。
- **エラーハンドリング**: 外部システム連携も外部引数受領も無いため専用のエラーハンドリングは持たない（Excel 0405:L1763 が正）。取得・送信時に例外が生じた場合の挙動は一次オラクル（Excel 0405:L1763「特になし」）と詳細設計 L343（エラーメッセージのコンソール出力）が競合し確定できない＝要実機確認（実装差は付帯表4#2）。
- **排他制御**: 検知・通知が主で楽観/悲観ロックの対象を持たず、多重実行時の重複検知・通知抑止は保証しない（詳細設計 L327,L351）。
- **オラクル独立性**: 期待はオラクル（Excel優先・沈黙部は詳細設計HTML）由来で実装から独立。実装との差は付帯表4で乖離＝バグ候補として扱う（期待値には使わない）。

## §2. SEED固定値（合成既知値。※fixtureでありオラクルではない・複数構成で抽出境界/通知/該当なしを検証）
| SEEDキー | 内容（固定値） | 用途 |
|----------|----------------|------|
| SEED-BATCH-TIME | バッチ実行基準時刻＝`2026-07-15 04:00:00`（Excel 0405:L1748 毎日4時に相当） | 対象期間（現在日時から1日前まで）の基準 |
| SEED-ORDER-8001 | `dtb_order.id=8001`／`order_no=OD-8001`（通知に添える注文番号） | 注文番号取得・通知 |
| SEED-PH-DUP | `dtb_point_history` 2件：ともに `order_id=8001`／`point_change=-10`／`point_type_id=2`／`issue_date=2026-07-15 03:00:00`（基準から1時間前＝期間内） | 二重登録検知の陽性 |
| SEED-PH-OLD | SEED-PH-DUPと同構成だが `issue_date=2026-07-14 02:00:00`（基準から26時間前＝1日超で期間外） | 対象期間外の除外 |
| SEED-PH-POSITIVE | `order_id=8002` に `point_change=+10` を2件（`issue_date` 期間内） | 増減量が0以上で対象外 |
| SEED-PH-SINGLE | `order_id=8003` に `point_change=-10` を1件のみ（期間内） | 組合せが1件＝重複でない |
| SEED-PH-DIFFAMT | `order_id=8004` に `point_change=-10` と `point_change=-20` を各1件（期間内） | 注文IDは同一だが増減量が異なり組合せ不一致＝重複でない |
| SEED-PH-NONE | 上記いずれの二重登録条件にも該当する履歴が存在しない状態 | 該当なし（メール送らず完了） |
| SEED-MAILADDR | 管理者通知先メールアドレスが設定済み（送信可能状態）。※宛先設定はメール設定を正（L303） | 通知メール送信の陽性化 |
