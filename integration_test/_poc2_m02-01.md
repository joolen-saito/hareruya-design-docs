## §1. 全ケース共通前提
- **入口/認証**: 認証済み管理者が管理画面ホーム（`GET /%eccube_admin_route%/`）を開く。受注状況カードはホーム画面の一ブロックである（L224,L245）。未認証は本カードに到達できない（L245,L294）。
- **参照系**: 本ブロックは表示時点の永続化済みデータを読むだけで、受注台帳・ステータスマスタを更新せず、本ブロックの表示のためにセッションも書き換えない（L275,L281,L315）。※ただし正本 L287-288（DB操作節）は登録/更新を記す＝**設計内部矛盾**につき §5 で `要判定`・付帯表4#3。
- **フォームなし**: 本ブロックはフォーム・テキスト入力を持たず、操作はステータス行／カード見出しのリンク押下のみ（L248,L291）。
- **応答**: ホーム画面の HTML をサーバ側でレンダリングして返す。件数取得のための専用 API 呼び出し・非同期取得は行わない（L248,L278,L281）。
- **除外リスト**: 受注状況カードの「表示対象マスタ行」と「件数集計」の双方から除く受注ステータス識別子の集合。既定値があり、拡張が差し替える場合がある（L242,L252,L264）。
- **オラクル独立性**: 期待はすべて詳細設計HTML由来で実装から独立。実装との差は付帯表4で乖離＝バグ候補として扱う。正本に無い挙動は「要実機確認」とし断定しない。
