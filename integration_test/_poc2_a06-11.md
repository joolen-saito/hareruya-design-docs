## §1. 全ケース共通前提
- **入口/認証**: MTGバイヤー（買取アプリ）から呼び出す JSON API。認証あり＝認証方式は「IP制限・トークン」（Excel 0506:L3111）。認可方式はpf-apiの方針に従う（詳細設計 L357）。ブラウザ向け画面は持たない（詳細設計 L297）。
- **エンドポイント/メソッド**: Excel は `/api/section.json`（0506:L3110）、詳細設計の現行は `GET /section.json`（L312）。メソッドは **GET**（Excel 0506:L3111・詳細設計 L312,L316）。エンドポイント文字列の差（`/api` 接頭辞有無）は付帯表4#4。
- **参照系**: 本APIは参照のみで副作用なし（詳細設計 L341,L353）。DBへの登録・更新・削除を行わず、楽観/悲観ロックの対象を持たない（L363）。DB関連のテーブル名は ec-cube-enterprise（`mtb_section`）を正典とする（L350）。
- **応答契約**: 成功時 HTTP 200 で `code`／`message`／`sections` を返す（Excel 0506:L3133-L3135・詳細設計 L326,L327）。`sections` 各要素は `section_id`／`name`／`code`（Excel 0506:L3136-L3138）。応答フィールド名 `section_id`・`name`・`code` はAPI契約（詳細設計 L309）。
- **オラクル独立性**: 期待はオラクル（Excel優先・沈黙部は詳細設計HTML）由来で実装から独立。実装との差は付帯表4で乖離＝バグ候補として扱う（期待には使わない）。
