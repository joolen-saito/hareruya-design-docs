## §1. 全ケース共通前提
- **入口/認証**: クライアントは MTGバイヤー（買取アプリ）。査定表印刷時に表示する商品情報取得のために呼ばれる（Excel 0506:L2280／詳細設計 L293,L384）。プロトコルHTTP・メソッドPOST・認証の有無=有（IP制限/トークン）（Excel 0506:L2274）。認可方式はpf-apiの方針に従う（詳細設計 L384）。リクエスト書式は Excel 0506:L2274=クエリ、応答形式はJSON（Excel 0506:L2274／詳細設計 L309,L323）。ids の位置は Excel 0506:L2274=クエリと詳細設計 L320=ボディで競合し、競合ルール（Excel優先）により契約オラクル＝クエリを正とし、ボディ実挙動は補完・要実機確認に縮退する（付帯表4#10）。
- **エンドポイント**: Excel 0506:L2273 は `/api/buying/products`、詳細設計 L308 は `POST /buying/products`（`/api` なし）。URL文字列の差異は付帯表4#1 のオラクル差異として明記し、期待は「カンマ区切り ids に対応する買取用商品情報をPOSTで取得しJSONで返す」までを共通の正とする。
- **処理フロー**: リクエストの ids（カンマ区切り）を受け取りIDの配列に分解 → 商品リポジトリから当該商品IDリストに対応する買取用商品を取得 → カード商品以外のIDのみで0件でもエラーとせず取得結果（空を含む）をJSONで返す（Excel 0506:L2281,L2282／詳細設計 L313）。
- **取得条件（Excel処理概要）**: ①商品IDに紐づく商品および商品規格情報を取得（0506:L2282）②商品および商品規格情報が削除済みのものは取得しない（0506:L2283／詳細設計 L305 削除除外は現行踏襲）③高額商品コードがはいっていないものを取得する（0506:L2284）。
- **★カスタマイズ（Excel優先・オラクル）**: 販売価格を取得していたところを**基準価格**を取得する（0506:L2276,L2285）／商品の在庫を取得していたところを明示的に**本店ECの在庫**を取得する（0506:L2277,L2286）／追加開発で**ログイン者の所属店舗のEC在庫**を取得する（0506:L2278,L2287）。詳細設計 L325 の price=販売価格・stock=在庫数は現行（未カスタマイズ）記述＝付帯表4#2,#3 に乖離明示。
- **参照系・副作用**: 本機能は参照系（検索）でありDBへの登録・更新・削除を行わない（詳細設計 L370「無し（参照のみ）」・L380）。金額・税・ポイント・在庫数量の再計算・丸めは行わない（詳細設計 L316）。テーブル名・列名は ec-cube-enterprise を正とする（詳細設計 L305,L377,L380）。
- **応答**: 成功はHTTP200（Excel 0506:L2304）。応答は cards（カードID をキー）を最上位に持ち、配下に details（カード詳細ID）→ languageClasses（言語コード）→ conditionClasses（状態コード）の順で入れ子（詳細設計 L323,L325）。0件のときは空配列 `[]` を返す（詳細設計 L324,L327）。専用の失敗ステータスは持たず 0件も HTTP200（詳細設計 L327,L387）。レスポンス定義はカード詳細IDから買取用商品情報取得APIと同一（同じ定義を使用・Excel 0506:L2319）。
- **オラクル独立性**: 期待はオラクル（Excel優先・沈黙部は詳細設計HTML）由来で実装から独立。実装との差は付帯表4で乖離＝バグ候補として扱う。オラクルが沈黙する挙動（重複ID時の集約・並び順など）は断定せず「要実機確認」とする。
