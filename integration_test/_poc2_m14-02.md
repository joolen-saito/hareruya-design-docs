## §1. 全ケース共通前提
- **入口/認証**: 認証済み管理者が管理画面のカード検索一覧（M14-01）から実行。ルートは `m14-02_admin_card_card_csv_export`＝**POST `/{admin_route}/card/csvexport`**（L319,L402）。ルート定義上は個別のアノテーションを持たず、**管理画面共通の認証・認可**が適用される（L368）。
- **トリガ**: 一覧でカードをチェック（`name="cardIds[]"`）して「CSV出力」を押す。同一 HTML フォームの既定 action は検索用 `POST /{admin_route}/card/search/1` だが、「CSV出力」は `formaction` で本機能にだけ差し替えて送信する（L319,L320,L323／Excel `0208:L1520`）。
- **CSRF**: 検索フォームは**カード検索機能側の実装どおり CSRF を無効にした型**で生成されるため、「CSV出力」送信にも **CSRF トークンフィールドは付かない**（L324）。
- **参照系**: 読み取りクエリとログ出力のみ。該当マスタを更新しない（L355,L361）。セッションは読み取りのみで更新しない（L388）。
- **成功時応答**: `text/csv` のストリーム（`StreamedResponse`）。`Content-Disposition: attachment`・ファイル名 `cards_YmdHis.csv`・先頭 UTF-8 BOM（L328,L355）。
- **出力対象**: POST で明示されたカード ID に対応し、**かつリポジトリで検索できたカードのみ**（L335）。一覧にチェックを付けたカード ID のみで、検索ヒット全件を自動出力しない（L349）。
- **オラクル独立性**: 期待はオラクル（Excel優先・沈黙部は詳細設計HTML）由来で実装から独立。実装との差は付帯表4で乖離＝バグ候補として扱う。

## §7. gen(55) からの是正（オラクル差し替え）
- gen は `oracle_router` の `excel_ok:False` を信じて **詳細設計HTML単独をオラクル**にしていた。→ **Excel 0208 に M14-02 実体シートが存在する（偽陰性）** ことを突き止め、出力列・出力値・未選択時エラーを **Excel 一次オラクル**へ差し替えた（§4 の期待セル内 `0208:Lxxx`）。
- gen の期待verbatimは詳細設計HTML（＝現行 pf-eccube3 のリバース）の**33列**をそのまま期待にしていたが、機能区分＝カスタマイズであり Excel が **35列（識別ID 1〜37 − 除去 29・32）** を規定するため全面差し替え。**Foilフラグ・プロモフラグを期待に残すことは Excel 設計違反**となるため RG-018 で非出力を検証する側に反転させた。
