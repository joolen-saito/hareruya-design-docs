## §1. 全ケース共通前提
- **入口/呼び出し元**: デッキビルダーアプリが `GET /archetypes/{formatId}` を呼ぶ。応答形式はJSON。ブラウザ向け画面を持たないJSON APIであり、UI操作・画面遷移の観点は本機能に存在しない（L217,L234,L235）。
- **認証・認可**: 認証を行わない。`jwt-token`ヘッダを参照せず、トークン検証もプレイヤー照合も行わない。認証処理を持たないため認証起因の拒否（HTTP 401）を返さない。利用者の状態によらず参照できる（L238,L296）。
- **参照系**: 副作用は無し（参照のみ）。取得クエリにフォーマット単位の結果キャッシュ（既定の保持時間つき）を用いるが、業務データの更新・履歴・通知は行わない。DBへの登録・更新・削除を行わない（L276,L292,L306）。
- **応答の骨格**: 成功は HTTP 200 で `code` と `archetypes` のラッパに包む。失敗（フォーマット不存在）は HTTP 404 で `{code, message}` 形式のJSON（L243,L253,L257）。
- **DB**: 抽出元はアーキタイプ（`dtb_archetype`）と実在判定用のフォーマットマスタ（`mtb_format`）。テーブル名・列名は ec-cube-enterprise の定義を正とする（L289,L290,L293）。
- **オラクル独立性**: 期待は正本（詳細設計HTML）由来で実装から独立。実装との差は付帯表4で乖離＝バグ候補として扱う。Excelは該当なしのため参照しない。
