# 結合テスト実行属性スキーマ（データ契約）

> 確定: 2026-07-21 ／ codex・fable5 レビュー反映 ／ 実装: `assign_execution_mode.py`（多軸化はP2で全件適用）

台帳 `all_it_cases.tsv`（26,188行）は**完了母数であり削らない**。本スキーマが定めるのは
「各行を**どう実行するか**」だけである。件数削減ではなく実行工数の圧縮が目的。

## 0. 唯一の入力は トレース台帳

実行属性の付与は `integration_test/case_viewpoint_trace.tsv`
（`テストID × 観点No × 適用ルールID × 根拠HTML`）を**唯一の入力**とする。

**ケース側の (IT-ID, 小項目) からの逆引きを使ってはならない。** このキーは一意でなく
（187キー中55キーが衝突・ケースの67%が衝突キー上）、観点マスタの行順で結果が反転する。
実害として (IT-10,異常系) で観点496(外部取得フォールバック)が観点509(外部決済異常＝
二重課金・二重返金)を隠蔽し、130件が automated-API/聖域0 に誤付与された。

## 1. 単一・排他の「実行区分」は誤り

`contract` / `DB原子性` / `API` / `UI` / `人手承認` は**同時に成立する**。
1列の先勝ち分類では観測層が消える。典型例が観点No.528（Outbox）で、
DB更新↔下流通知・送信失敗後の再送・重複通知を見るのに、単一分類では
`automated-API` に潰れ、**contract＋DB原子性＋障害注入**という必要要件が消えていた。

よって以下を**独立列**として持つ。

## 2. 軸の定義

| 列 | 型 | 値 | 意味 |
|---|---|---|---|
| `実行チャネル` | 複数可 | `UI` / `API` / `DB` / `batch` | どこから叩くか |
| `必須観測層` | 複数可 | `Form` / `DB` / `外部` / `通知` | **どこをアサートしないと不合格を検出できないか** |
| `実環境依存` | 単一 | `実決済` / `スタブ` / `契約試験` / `障害注入` / `なし` | 環境前提 |
| `人手承認` | 単一 | `毎回` / `初回のみ` / `不要` | 人が合否を承認する頻度 |
| `並行実行` | 0/1 | | 複数セッション/プロセスの同時実行が要る |
| `障害注入` | 0/1 | | タイムアウト・通信断・部分失敗の注入が要る |
| `VRT初回承認` | 0/1 | | 視覚回帰のベースラインを人が承認する |
| `聖域` | 0/1 | | **全数実行必須・代表/サンプリング禁止** |
| `未解決` | 0/1 | | 環境・fixture・権限が無く現時点で実行不能 |

### 必須観測層は必ず明示する
`必須観測層` に `Form` だけを置いてはならない対象がある。バリデーションは
pf=MySQL（バイト長）/ ee=PostgreSQL（文字長）の意味論差があるため、
**Form層とDB層の両方**をアサートしないと移行退行を観測できない。片層省略は不可。

### 「自動化可能」と「今この環境で自動実行可能」を混同しない
`実行チャネル` が自動でも、`実環境依存`=`実決済` や `未解決`=1 なら、
その行は現時点で人手・準備待ちである。工数見積は後者で行う。

## 3. 聖域（全数実行必須）

**優先度（P1/P2/P3）で聖域を判定してはならない。** 実測でロールバック観点256件が
**全件P3**であり、「P3は後回し」を機械適用すると原子性の中核が黙って落ちる。

聖域の対象は「ドメイン名が一致するから」ではなく、**適用根拠を伴うこと**。
（例: No.109 排他制御は「書込みがある」だけでなく、排他・版数・同時更新・競合時の
扱いが設計書にある機能に限る。グローバルナビが商品リンクを持つだけで捺印しない。）

不可侵領域: 決済金額・返金/取消 ／ 在庫の競合・負在庫（1点物） ／ 注文・買取の状態遷移 ／
外部I/Fの重複・順序逆転・再送 ／ 認可境界 ／ DB更新と通知の原子性。

## 4. 完了条件

RISK観点は「生成件数が1以上」を完了条件にしない。単一画面の結合試験に閉じない
横断リスクを含むため、以下のいずれかを満たすことを完了とする。

1. 根拠付きの結合テストケース
2. 根拠付きのシナリオ／障害・並行試験ケース
3. 明示的な対象外・未仕様台帳＋是正チケット

## 5. 対外提示の規約

単一値を出さない。前提が異なる数値を平均して一本化してはならない。

- **確定値**: 再生成・根拠台帳・多軸割当の完了後に確定する
- **暫定下限**: 自動化ゲート通過を前提とした約4,500（楽観ケース）
- **計画用リスク上限**: 未確定・障害注入・初回VRTを含む約6,000（計画予備）
- **VRT初回人手**: 60〜130人時（対象画面数・差分基準・承認回数を明示）

`逆引き曖昧` で悲観側へ倒した行は**対外見積から除外**し、解消をリリースゲートとする。
