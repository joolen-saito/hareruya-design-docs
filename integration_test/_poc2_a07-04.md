## §1. 全ケース共通前提
- **入口/認証**: 認証済み管理者会員（買取アプリ MTGバイヤー）が呼ぶ JSON API。ルートは `put_buy_status_json`（PUT `/admin/buyOrder/{id}/status.json`、移行先は `%eccube_api_v1_route%` 配下）。認証は `jwt-token` ヘッダの JWT（署名 HS256、ペイロードの利用者IDから管理者会員を引く）。ヘッダ欠落・署名不正・該当管理者会員なしはいずれも認証拒否 HTTP 401（本文なし）（L322,L340,L368,Excel 0507:L1475）。
- **リクエスト**: パス `id`（integer 必須・対象受注ID）、ボディ `status`（フォーム値 integer 必須・買取ステータスID）（L334）。
- **副作用**: 更新前後でステータスが異なる場合のみ、`dtb_buy_order` のステータス(`buy_order_status_id`)・更新担当者(`member_id`)・更新日時(`update_date`)を更新し、買取ステータス履歴 `dtb_buy_order_status_histry`（現行 `dtb_buy_order_status_history`）を1件登録（受注ID・更新後ステータスID・更新担当者ID・登録日時）。保存はトランザクション内で確定、例外時ロールバック（L346-348,L359,L361,L368,L371,L376,Excel 0507:L1504,L1505）。
- **応答**: 成功は HTTP 200・`{code:200}`（更新前後が同一ステータスでも200）（L337-338,L343-345）。JSON整形は camelCase・日時 ISO8601・`serialize_null` 有効（L348）。失敗は 401/404/400/500。
- **オラクル独立性**: 期待はオラクル（Excel優先・沈黙部は詳細設計HTML）由来で実装から独立。実装との差は付帯表4で乖離＝バグ候補として扱う。
