## §1. 全ケース共通前提
- **入口/認証**: ログイン済み会員が会員マイページで利用。ルートは一覧 `GET /{_locale}/mypage/delivery`、編集/確認振り分け `GET/POST …/new/edit`・`…/{id}/edit`、登録確定 `POST …/new/confirm`・`…/{id}/confirm`、削除 `DELETE …/{id}/delete`（正本 L329,L338-345）。`/{_locale}` は言語別プレフィックス。`/mypage` 配下は会員ログインを要する（正本 L331,L380）。未ログインアクセスは会員ログインへ誘導する（会員ログイン機能を正とする＝正本 L380,L388）。
- **なりすまし対策トークン（CSRF）**: 削除 DELETE はなりすまし対策トークンを検証する（正本 L345,L377）。§4 RG-012 で実施。
- **参照/更新の別**: 一覧表示は読み取りのみ。登録確定は配送先本体＋配送先名称を persist/flush で即時確定（正本 L343,L374）。削除は削除フラグを立てる論理削除（正本 L345）。本機能では API 呼び出し・バッチ実行を扱わない（正本 L364＝§5 台帳 OUT の根拠）。
- **メッセージ表示**: 入力項目ごとの必須・形式エラーは各項目直下に表示する。本機能はフラッシュ・トーストを生成しない（正本 L350）。上限超過のみ一覧画面上部のエラー枠に表示する（正本 L349）。
- **オラクル独立性**: 期待はオラクル（Excel優先・沈黙部は詳細設計HTML）由来で実装から独立。実装との差は付帯表4で乖離＝バグ候補として扱う。オラクルに書かれていない挙動は「要実機確認」とし、限定（「〜の場合のみ」）を落とさない。
