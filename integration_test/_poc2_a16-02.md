## §1. 全ケース共通前提
- **入口**: `GET /topBanners/{言語コード}.json`（Excel 0516:L1104・リクエストサンプル `/api/topBanners/JP.json` 0516:L1125）。プロトコル HTTP／メソッド **GET**／リクエスト書式 クエリ／レスポンス書式 **JSON**（0516:L1105）。詳細設計 L310 は拡張子なしの `GET /topBanners/{languageCode}` を併記するが、Excel（0516:L1104,L1125）を正とする。
- **認証・認可**: Excel 0516:L1105「認証の有無 無 認証方式 無」＝**認証なしで呼び出せる**。詳細設計 L358「クライアントから呼び出す。認可方式はpf-apiの方針に従う」は非確定のためExcelを正とする。
- **参照系**: 本APIは参照のみ。副作用は無し（L342「無し（参照のみ）。」／L348「本APIはデータを更新しない」／L354）。`mtb_top_banner`・`dtb_top_banner_language`・`mtb_language` に対する登録・更新・削除は行わない（L352,L355）。
- **応答形式**: 成功は HTTP 200（Excel 0516:L1128「200 正常」）で、**トップバナーオブジェクトの配列をそのまま返す**（ラップオブジェクトを持たない・L324）。失敗は 404 で `{code, message}`（L327）。
- **応答プロパティ命名**: Excel 0516:L1138-L1145 のスネークケース（`id`／`image_url`／`link`／`disp_type`／`languages.id`／`languages.name_jp`／`languages.name_en`／`languages.code`）。※詳細設計 L325,L343 の camelCase 記述はExcelと競合し不採用＝付帯表4#1。
- **オラクル独立性**: 期待はオラクル（Excel優先・沈黙部は詳細設計HTML）由来で実装から独立。オラクルが沈黙する挙動は断定せず「要実機確認」とする。実装との差は付帯表4で乖離＝バグ候補として扱う。

## §7. gen(35) からの是正（オラクル差し替え）
- gen の実施35行は期待が詳細設計HTMLの総称verbatim（「エラー内容 処理 一覧が空・言語が存在しない コード404のJSONを返す。」「パラメータ 位置 型 必須／任意 説明 languageCode パス string 必須…」）の反復で、同一文が最大14行に重複し具体オラクルになっていなかった。→ 全行を Excel優先＋詳細設計補完の具体挙動（ステータス・応答項目名・SEED等値照合）へ差し替え。
- gen が期待に用いた詳細設計の応答項目 camelCase（L325）は、Excel 0516:L1138-L1145 のスネークケースと競合するため **Excel優先で不採用**（付帯表4#1）。
- gen が 404 を「一覧が空・言語が存在しない」の一文で扱っていたが、Excel 0516:L1129 は「言語コード未設定」「言語コードに紐づいたトップバナーIDがない場合」の**2条件を列挙**するため、RG-009／RG-010 に分割し、後者（言語在り・紐付き0件）を独立ケース化した。
- gen が「資格情報」を `DELEG-STATIC`（認可方式はpf-apiの方針に従う＝非確定）としていたが、Excel 0516:L1105「認証の有無 無 認証方式 無」により `EXEC`（RG-015・未認証で200）へ是正。
