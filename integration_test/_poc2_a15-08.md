## §1. 全ケース共通前提
- **入口/認証**: 入口は `GET /cards`（L235）。応答形式はJSON、呼び出し元はデッキビルダーアプリ（L236）。**認証を行わない**ため未認証でも参照でき、利用者の状態によらず結果は変わらない（L239,L301）。
- **入力**: すべてクエリパラメータで受け取る。配列を取る項目（カード種別・色など）は複数値で渡す（L251）。全パラメータが**任意**であり、未指定のパラメータには定義された既定値（条件の論理は AND、ページは1、1ページ件数は20、並びは色の昇順など）を補う（L244,L252）。
- **参照系**: 副作用は無し（参照のみ）。検索クエリには検索条件に応じたキーの結果キャッシュ（既定の保持時間つき）を用いるが、業務データの更新・履歴・通知は行わない（L281）。DBへの登録・更新・削除は行わない（L297）。
- **応答**: 成功は HTTP 200 で `code`・`total_count`・`cards` のラッパに包む（L244,L254,L255）。応答配列要素のキーは取得クエリのエイリアスのまま snake_case（`name_jp`・`mana_value`・`is_attraction` 等）で返す（L256,L282）。
- **失敗**: クエリパラメータが許容値制約に反する場合は HTTP 400（クエリパラメータ検証に委ねる）、検索処理中の例外は HTTP 500（共通例外処理に委ねる）（L258,L304）。該当が一件も無い場合は失敗ではない（L259）。
- **DB**: テーブル名・列名は ec-cube-enterprise の定義を正とする（L294,L297）。マナ総量は `cmc`、応答 `mana_value` に対応（L228,L295）。
- **オラクル独立性**: 期待はすべて詳細設計HTML由来で実装から独立。実装との差は付帯表4で乖離＝バグ候補として扱う。正本に無い挙動は断定せず「要実機確認」とする。
