## §1. 全ケース共通前提
- **入口/実行方法**: 本機能は HTTP 画面を持たないコンソールのバッチコマンド。詳細設計の起動コマンドは `order:batch deleteSmaregiProduct`（正本 L311,L315）。Excel の実行トリガーはスケジュール起動（Step Functions）毎日4時（`0405:L1633`）。コマンド名が一致しない/未指定の場合は処理を行わずに終了する（正本 L312,L339）。
- **処理フロー**: メール送信用の経路を準備 → スマレジ削除対象の受注（サブ）を抽出 → 受注ごとにスマレジへ商品削除の連携を行う（正本 L316）。連携区分はスマレジへ「削除区分」で連携（正本 L319）。
- **抽出条件（Excel が正）**: DB から「スマレジ商品コードが登録されている」かつ「スマレジ削除フラグが立っていない」かつ「注文ステータスが『キャンセル』もしくは『引き渡し済み』」の店頭注文を取得（`0405:L1626-1629`,`0405:L1636-1639`）。※Excel 内で L1629/L1639 は「引き渡し済み」、検索条件表 L1644 は「出荷完了」と表記が割れる＝Excel 内不整合（付帯表4#2・§3/RG-005 で要実機確認明示）。
- **論理削除・カスタマイズ**: 取得注文をスマレジ連携し商品をスマレジ上で論理削除（`0405:L1630,L1631,L1646`）。カスタマイズ＝呼び出しを廃止予定のスマレジ API からプラットフォーム API に変更（`0405:L1624`）。
- **成功時の副作用**: スマレジ登録が成功したら当該注文のスマレジ削除フラグを立てる（`0405:L1647`）。永続化は承認ワークフローを介さず persist/flush で直接確定（正本 L332）。対象テーブルは dtb_order（現行は dtb_order_sub）の smaregi_del_flg（正本 L330,L333）。
- **失敗時**: 連携に失敗した場合はスマレジ通信エラーメールを送信（`0405:L1632`）。エラーが発生した場合、発生したスマレジ連携ごとにメールで管理者に通知（`0405:L1649`）。失敗時出力はエラーメッセージのコンソール出力（正本 L325,L339）。
- **対象なし**: 対象が無ければ何もせず完了する（正本 L322）。
- **排他制御**: 本バッチは削除連携が主であり、楽観ロック・悲観ロックの対象を持たない（正本 L347）。
- **ログ**: 開始・完了のコンソール出力（日時付き）（正本 L342）。ログにスマレジ連携の認証情報を出してはいけない（正本 L343,L344）。
- **オラクル独立性**: 期待はオラクル（Excel 優先・沈黙部は詳細設計 HTML）由来で実装から独立。実装との差は付帯表4で乖離＝バグ候補として扱う。オラクルが沈黙する挙動（終了コードの具体値・一部失敗時のループ継続可否・メール件名/本文/ヘッダ内容）は「要実機確認」とし断定しない。
