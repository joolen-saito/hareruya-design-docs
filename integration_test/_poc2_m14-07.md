## §1. 全ケース共通前提
- **入口/認証**: 認証済み管理者が管理画面「カードセット管理」一覧から利用。ルートは `admin_cardset_download`（POST `/{admin_route}/cardset/download`）と `admin_cardset_download_lang`（POST `/{admin_route}/cardset/download_lang`）。未ログインは管理画面の共通認証により当POSTに到達しない（L319,L368,L401）。細かいロール差は本書で確定せず＝要実機確認。
- **送信経路**: 一覧フォームの既定 action は POST `/{admin_route}/cardset`（一覧表示）で、2ボタンは `formaction` でダウンロードルートへだけ差し替えて送信する（L320）。
- **CSRF**: フォーム種別はカードセット用フォームで、CSRFトークンフィールドがテンプレートに出力される（L324,L345）。検証失敗時のふるまいはFW・管理画面共通処理に従い本書では確定しない＝要実機確認。
- **共通前処理（両ルート）**: cardsetIds が空なら `[0]` に読み替え → `set_time_limit(0)` → ストレージ接頭辞 `set/` → `download` を0777で作成 → `download` 配下を全削除。言語別のみ続けて画像が存在する全言語のディレクトリを作成（L328）。
- **副作用**: ローカル `download` ツリーへのファイル作成・削除、`mtb_card_image.dead_link_flg` の更新、セット別のみ finish イベントでの `download` 掃除（L336,L356）。※L361「DBへの登録・更新・削除は行わない」は同書 L330/L356/L359 と矛盾（付帯表4#7）。
- **応答**: ZIP があれば HTTP 200 で `card_image.zip` を `sendFile`。無ければフラッシュ＋`admin_cardset_page` へリダイレクト（L334,L356,L371）。
- **オラクル独立性**: 期待はオラクル（Excel優先・沈黙部は詳細設計HTML）由来で実装から独立。実装との差は付帯表4で乖離＝バグ候補として扱う。

## §7. gen(65) からの是正（オラクル差し替え）
- gen の期待verbatimは詳細設計HTMLの節本文（L328/L323/L330 等）が丸ごと反復し、**同一文が最大16行に重複**（RG-037〜065の「検索条件」「実行結果」等）していた。本機能に検索条件は存在せず（入力はチェックボックスとCSRFのみ・L345）、gen の「検索条件」16件は**母集合直積の無差別適用**＝偽陽性。→ 全廃し、Excel の ZIP フォルダ構成（0208:L2845,L2855,L2858,L2868,L3095,L3105）と未選択分岐（0208:L2857,L3107）を軸に再構成。
