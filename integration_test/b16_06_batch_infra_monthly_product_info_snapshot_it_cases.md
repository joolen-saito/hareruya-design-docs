# B16-06（月次商品情報スナップショット） 結合試験テストケース

元設計: `../excel_to_html/output/0416_基本設計仕様書(バッチ_インフラ).html#sheet-8`

テスト観点: `integration-test-viewpoints.md`

期待結果は画面表示、遷移、DB状態、ファイル、レスポンス、ログなど試験で観測できる結果で判定する。TSV は 10 列固定で、`テストレベル` 列は含めない。

## 関連ID対応概要

| 関連ID | 本機能での主な確認範囲 |
|--------|------------------------|
| IT-30 | Step Functions月次起動、バッチ実行結果、入力DB、終了ステータス、ログ |
| IT-23 | スナップショット由来DBからの商品規格・店舗・在庫区分の抽出条件、件数、並び順 |
| IT-27 | ZIPファイル生成、S3アップロード、出力先異常時の扱い |
| IT-24 | 出力ファイル名、出力項目、圧縮後ファイル内容、文字化け・欠落の確認 |
| IT-10 | AWS/RDS/S3/Step Functions連携の通信失敗、タイムアウト、リトライ・異常終了 |
| IT-15 | 本番DBスナップショット、復元DB、S3オブジェクト、ログに対する権限・機密情報の扱い |
| IT-26 | 参照・出力のみを行うバッチとして、抽出元DBを更新しないこと |

## テストケースTSV

以下はタブ区切りで、実質はExcelのCSVと同様に、改行や`"`を含むセルはダブルクォートで囲む。

**1行目**が列見出し（先頭列は `機能名`、**テストレベル列なし**）。**2行目以降**がケース（各10列）。`機能名` 列に元設計の表示名を入れる。`テストID`で一意に識別する。優先度は **P1／P2／P3**。

Excel／Googleスプレッドシートへはコードフェンス内を A1 に貼り付ける。

前提条件・入力データ・操作手順など、**期待結果以外**の列で複数項目がある場合は、同一セル内でLF改行する。

**期待結果／レスポンスは1行1判定**とする。複数の期待がある場合は行を分割し、**テスト項目名は当該行の判定内容が分かるよう具体化**する。

## 対象外観点

| 分類・範囲 | 理由 |
|-----------|------|
| バリデーション / 単項目・相関バリデーション（IT-22） | 本機能は利用者入力を受け付けないスケジュールバッチであるため |
| データベースアクセス / 登録・更新・削除（IT-05, IT-07, IT-26） | 業務DBに対する登録・更新・削除ではなく、RDS一時リソースの作成削除と参照出力を確認対象にするため |
| ファイル処理 / ファイル取込・アップロード（IT-16, IT-17, IT-24） | 入力ファイル取込ではなくDB抽出とS3出力の機能であるため |
| ウェブアプリケーション / 画面操作（IT-15, IT-22, IT-27, IT-33） | 管理画面・フロント画面の操作導線を持たないため |
| メール処理（IT-11, IT-28） | 元設計HTMLにメール送信仕様がないため |
| 決済連携・Webhook・外部通知（IT-10, IT-15, IT-33） | 本機能の外部連携はAWS/RDS/S3/Step Functionsであり、決済・Webhook通知を扱わないため |
