## 具体化ケース（代表・台帳のテストIDへ紐付け）

### 認証の中核

**[IT-…-LOGIN-002 / 観点500 未認証]**
- 前提: 未ログイン（認証Cookie・共有トークンなし）
- 入力: なし
- 手順: `GET /ja/mypage/login` を開く
- 期待: ログイン画面が表示され、見出し「ログイン」・メールアドレス欄（プレースホルダ「メールアドレス」）・パスワード欄・「ログイン」ボタンが出る [md:81,155-159]。会員機能(マイページ)へは未ログインではアクセスできずログイン画面へ誘導される [md:295]

**[認証成功 / 観点=ログイン送信の成立]**
- 前提: MEMBER-VALID を dtb_customer に投入・未ログイン・失敗回数0
- 入力: login_email=`member900001@test.example` / login_pass=`Passw0rd-900001` / 有効な `_csrf_token`
- 手順: ログイン画面から `POST /ja/login_check` を送信
- 期待: (1)認証成功しマイページ（既定遷移先）へ遷移 [md:120] (2)失敗回数・制限日時がリセットされる [md:118] (3)本店・支店共有トークンがCookieに発行される [md:143] (4)成功メッセージは出ない [md:179]

**[パスワード不一致 / 観点=判定順序4]**
- 前提: MEMBER-VALID 投入・未ログイン・失敗回数0
- 入力: login_email=`member900001@test.example` / login_pass=`Wrong-000000`（MEMBER-WRONGPASS）
- 手順: `POST /ja/login_check`
- 期待: (1)認証エラーとしてログイン画面へ戻る [md:142] (2)エラー枠に赤文字で**「ログインできませんでした。入力内容に誤りがないかご確認ください。」**（理由は画面上区別しない）[md:170] (3)ログイン失敗回数が+1される（セッション保持）[md:347]

**[存在しないメール / 観点=判定順序3]**
- 入力: login_email=`nobody900999@test.example`（MEMBER-NONE）/ login_pass=任意
- 手順: `POST /ja/login_check`
- 期待: パスワード不一致と**同一のメッセージ・同一挙動**（会員存在有無を画面上区別しない）[md:145,171]

### 試行制限（観点は聖域・全数）

**[試行制限の発動 / 観点=試行制限]**
- 前提: MEMBER-VALID 投入・失敗回数0
- 手順: 誤ったパスワードで `POST /ja/login_check` を**10回**連続実行 [md:348]
- 期待: 10回目で制限日時が「現在＋10分」に設定され、失敗回数がリセットされる [md:349-351]。以降ログイン画面表示時、入力欄に代えて**「誤ったメールアドレスやパスワードを繰り返し入力されたため、ログインを制限しました。しばらく待ってから、お試しください。」**が表示され、入力欄は出ない [md:139,171,348]

**[制限中の判定優先 / 観点=判定順序1]**
- 前提: 制限日時が現在より後（上記で制限発動済み）
- 手順: 正しい認証情報で `POST /ja/login_check`
- 期待: 判定順序1が最優先のため、正しい資格情報でも認証されず制限メッセージ表示 [md:139]

### バリデーション（単項目・UT粒度と重複しない結合観点のみ）

**[login_email 最大長 / 観点=文字列長]**
- 入力: login_email=`（"a"×308）@test.example`（合計320文字・境界）
- 手順: `POST /ja/login_check`
- 期待: 320文字は最大長内で形式検証を通過し、以降の認証判定へ進む [md:202]（321文字はフォーム検証で不受理）
- 注: 文字数の**単位**は文字（ee=PostgreSQL）。pf=MySQLとのバイト差に注意（両層観測）

**[必須未入力 / 観点=必須]**
- 入力: login_email・login_pass ともに空
- 手順: `POST /ja/login_check`
- 期待: 認証基盤が受けるため未入力も**認証失敗**として扱われログイン画面へ戻る（専用の必須エラーでなく認証失敗メッセージ）[md:203,170]

### セキュリティ

**[CSRFトークン不整合 / 観点422 CSRF]**
- 前提: MEMBER-VALID 投入
- 入力: 正しい資格情報だが `_csrf_token` を欠落/改ざん
- 手順: `POST /ja/login_check`
- 期待: 判定順序2により認証せずログイン画面へ戻る（副作用=ログイン成立なし）[md:140]
- 注: ログインフォーム種別自体はCSRF保護を無効化し、画面の `_csrf_token` を認証基盤が検証する [md:287]

**[機密情報のログ非出力 / 観点502/503]**
- 手順: 上記の各認証操作を実行しログを確認
- 期待: Cookie値・セッションIDの完全値がログに出ない [md:365] 。login_pass の平文がログ・エラーに出ない【TBD: 設計書はパスワードのログ禁止を明示せず→要判定】
