## 具体化ケース（実テストIDに紐付け）

**[IT-F06-03-FRONT-MEMBER-CUSTOMER-LOGIN-002 / 観点No.500 未認証]**
- 前提: 未ログイン（認証Cookie・共有トークンなし）
- 手順: `GET /{_locale}/mypage/login` を開く（例 `/ja/mypage/login`）
- 期待: ログイン画面が表示され、見出し「ログイン」・メールアドレス欄・パスワード欄・「ログイン」ボタンが出る [md:81,154|pf現行回帰]。未ログインでマイページ（会員機能）へ直接アクセスするとログイン画面へ誘導される [md:295|pf現行回帰]

**[IT-…-LOGIN-001 / 観点No.422 CSRF]**
- 前提: MEMBER-VALID を dtb_customer に投入・未ログイン
- 入力: 正しい資格情報だが画面の `_csrf_token` を欠落/改ざん
- 手順: `POST /{_locale}/login_check`
- 期待: 判定順序②により認証せずログイン画面へ戻る（ログイン成立の副作用なし）[md:140|pf現行回帰]
- 注: ログインフォーム種別自体はCSRF保護を無効化し、画面の `_csrf_token` を認証基盤が検証する [md:287|pf現行回帰]

**[IT-…-LOGIN-004 / 観点No.502 機密情報の出力抑止]**
- 手順: 各認証操作を実行しログを確認
- 期待: **Cookie値・セッションIDの完全値・パスワードがログに出ない**（設計書のログ禁止リストに明記）[md:365-368|pf現行回帰]
  （前版はこれを【TBD】としたが誤り。設計書に明記あり。）

**[IT-…-LOGIN-010 / 観点No.1 必須バリデーション（login_email）]**
- 入力: login_email 空・login_pass=MEMBER-VALID
- 手順: `POST /{_locale}/login_check`
- 期待: 認証基盤が受けるため未入力も**認証失敗**として扱われログイン画面へ戻り、
  **「ログインできませんでした。入力内容に誤りがないかご確認ください。」** が表示される
  （専用の必須エラーではない）[md:203,170|pf現行回帰]

**[IT-…-LOGIN-012 / 観点No.8 文字列長バリデーション（login_email）]**
- 入力: BOUNDARY-320（320文字ちょうど）
- 手順: `POST /{_locale}/login_check`
- 期待: 320文字は最大長内で形式検証を通過し、以降の認証判定へ進む [md:202|pf現行回帰]
- 対（境界＋1）: BOUNDARY-321（321文字）はフォーム検証（最大長320）で不受理 [md:202|pf現行回帰]
- 注（pf/ee移行）: 文字数の単位はDB＝ee(PostgreSQL/文字)。pf(MySQL/バイト)との差はDB列制約の観測が必要
  だが、**本設計書は文字/バイトの別を明示していない【TBD】**（要 item_definition_audit 突合）

## 機能横断オラクル（この機能で照合する期待の正・すべて pf現行回帰）
- 認証失敗（存在しないメール／パスワード不一致／トークン不整合を区別しない）:
  **「ログインできませんでした。入力内容に誤りがないかご確認ください。」** [md:170]
- 試行制限（失敗が上限到達で発動）:
  **「誤ったメールアドレスやパスワードを繰り返し入力されたため、ログインを制限しました。しばらく待ってから、お試しください。」** [md:171]
  上限 `login_retry_limit`＝10回・制限 `login_restriction_minutes`＝10分 [md:348-349]
  ※これは `config.yml` の確認値（環境で変わり得る）[md:353]。合否は「設定値通りに発動」で判定し**値は環境から注入**する。
- 判定順序: ①試行制限中 ②CSRFトークン不整合 ③会員不在 ④パスワード不一致 ⑤成功 [md:139-143]

## この機能で「設計適合オラクル(Excel)」が使えない理由
フロント会員ログインはExcel基本設計に独立仕様が無い（0207は管理画面会員管理）。よって本機能は
**移行回帰オラクル(pf現行回帰)のみ**。「eeがpf現行のログイン挙動（メッセージ・試行制限・判定順序）を
保持するか」を検証する。設計意図の妥当性そのものは業務判断（設計適合は別途）。
