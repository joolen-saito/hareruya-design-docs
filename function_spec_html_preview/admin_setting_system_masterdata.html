admin_setting_system_masterdata（管理画面_設定_システム設定_マスタデータ管理）

管理画面の「設定」（システム設定）に属するマスタデータの選択と、ID・名称・表示順の一覧編集・保存。

概要

本画面は、Doctrine 上マスタとして定義されたエンティティのうち、共通形状（識別子・名称・並び順）を持つものをプルダウンで選び、テーブル形式で各行の ID・名称を編集したうえで一括保存する。

本書は実装手順ではなく、誰が・いつ・どの条件で・結果どうなるかを読むためのリバース詳細設計とする。 既存実装のふるまい、参照するデータ、検証境界、副作用、拡張イベントによる差し替え可能性を確認し、仕様の確からしさを把握することを目的とする。

対象はブラウザ経由の管理画面におけるマスタデータ管理である。 メニュー上の「システム情報」（サーバ環境などの参照専用表示）は別画面・別機能とする。

本書では Symfony の route 名、URL パス、Controller クラス名は扱わない。

本書で扱うこと

  • マスタ候補の構築条件（Doctrine メタデータ）と、プルダウンから除外されるエンティティクラス
  • マスタ選択送信後の再表示、編集フォームの表示条件、保存成功・失敗時のフラッシュと再遷移
  • ID・名称フィールドのバリデーション、重複 ID 検証、削除相当（行クリア）の判定
  • 保存時の永続化（新規・更新・削除、sort_no の振り直し方）
  • 店舗系権種によるアクセス拒否の確認値（PHPUnit）
  • 本体が dispatch する拡張イベントのタイミングと、レスポンス差し替えが起き得る地点

本書で扱わないこと

以下は本書では仕様確定せず、実装または別機能の設計を正とする。

  • 管理画面ログイン、二段階認証、権限マスタ編集 UI の詳細
  • 権限評価アルゴリズムの全分岐（共通セキュリティコンポーネントの実装を正とする）
  • 各マスタテーブルを参照する業務画面・API・バッチの個別仕様
  • 具象マスタに AbstractMasterEntity 以外の列がある場合の業務的意味（例: 受注ステータスの一覧件数表示フラグ）
  • 外部キー制約違反時の DB エラーコードや例外型の列挙
  • MTG 専用の別マスタ管理画面（データメニュー配下）の仕様

処理フロー

マスタ選択フォーム組み立て（マスタ管理画面の初期表示および再入）

  1. マスタ選択用フォームビルダを生成する。
  2. 拡張イベントを dispatch し、リスナーがビルダを変更し得る。
  3. マスタ選択が POST され検証に成功した場合、完了イベントを dispatch する。リスナーがレスポンスを設定した場合はそれを返し終了する。
  4. リスナーがレスポンスを返さなければ、一覧表示用の入口へリダイレクトする。リダイレクト先のパス引数には、3の直前に送信されたマスタキーが載る。
  5. 入口にマスタキーのパス引数があり、かつマスタ選択フォーム上そのキーが有効なら、当該エンティティのリポジトリで sort_no 昇順の findBy を実行する。
  6. 各行について、配列データに主キー・名称を格納する。主キーは行キーにも用いる。
  7. 配列末尾に、ID・名称が空の1行を追加する。
  8. メタデータ解釈に失敗した場合（マッピング例外）は、6のデータ読込を行わず、編集テーブル用データを空に近い状態にする。
  9. 編集用フォームビルダを、7または8で得たデータを初期値として生成する。
  10. 別の拡張イベントで編集フォームビルダを改変し得る。
  11. 2つのフォームのビューを返し、テンプレートを描画する。

保存（編集テーブル送信）

  1. 編集用フォームのみリクエストから組み立て、拡張イベントで初期化し得る。
  2. POST なら handleRequest 後、検証する。
  3. 検証失敗なら、マスタ選択フォームを別イベントで初期化し、リクエストボディと編集フォーム内 hidden のマスタ名を merge した値でマスタ選択フォームを submit し、2つのフォームビューを返す（同一画面でエラー再表示）。
  4. 検証成功なら、隠しフィールドのマスタキーからクラス名を復元する。
  5. 送信データの各行について、非 null の ID と非 null の名称が両方ある行は、主キーで既存を検索し、無ければ新規インスタンスを生成する。setId・setName のあと、ループの 0 始まり連番で setSortNo する。persist する。
  6. ID と名称が両方そろわない行のうち、行キーが「他行で使われている ID 一覧」に含まれないものは削除候補とし、行キーを主キーとして find した結果があれば remove する。
  7. flush を試みる。成功時は保存完了イベントを dispatch し、成功フラッシュに admin.common.save_complete を積む。失敗時（コメント上は外部キー制約など）は例外を握り潰し、エラーフラッシュに admin.common.save_error を積む。
  8. 選択中マスタの一覧表示入口へリダイレクトする。

編集入口への GET のみ

  1. 編集用フォームを空のデフォルトで生成し、初期化イベントを dispatch する。
  2. マスタ選択フォームを生成し、別イベントで初期化したあと、リクエストの POST パラメータ全体と、編集フォーム hidden のマスタ名を merge して submit する。GET では POST パラメータは空に近い。
  3. 2つのフォームビューを返す。編集データが空ならテンプレートは編集テーブルを出さない。

業務ルール・計算
