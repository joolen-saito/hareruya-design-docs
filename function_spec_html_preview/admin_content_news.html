admin_content_news（管理画面_新着情報管理）

管理画面のコンテンツ管理配下で、フロントTOPページ等に表示する新着情報の一覧表示・新規登録・編集・削除を行う機能。

概要

新着情報管理は、管理者がフロント向けに告知する新着情報を登録・編集・削除し、公開状態と公開日時を管理するための機能である。各新着情報は公開日時・タイトル・リンクURL・本文・公開状態を持ち、フロント側の新着情報表示はこの登録内容を参照する。

本書は実装手順ではなく、誰が・いつ・どの条件で・結果どうなるかを読むためのリバース詳細設計とする。既存実装のふるまい、参照するデータ、判定境界、副作用、拡張による差し替え可能性を確認し、仕様の確からしさを把握することを目的とする。

対象はブラウザ経由の管理画面のコンテンツ管理「新着情報管理」である。フロント側で新着情報を一覧・抜粋表示する処理は別機能として切り離す。

管理画面プレフィックスは環境変数ECCUBE_ADMIN_ROUTEを基にした設定値eccube_admin_routeで決まる。本書では入口のパスを%eccube_admin_route%で示す。ルート識別子の網羅は本文では扱わず、利用者視点の入口にHTTPメソッドとサイトルートからのパスパターンを実装確認値として記載する。

本書で扱うこと

  • 新着情報一覧の抽出条件・並び順・ページング単位
  • 新規登録・編集画面の入力項目と保存先、初期値、検証ルール
  • 公開状態（公開／非公開）と公開日時の扱い
  • リンクURL未入力時に「別ウィンドウで開く」設定が無効へ戻る実装
  • 登録成功・削除成功・削除失敗時のメッセージと画面遷移
  • 削除時の確認モーダル、なりすまし対策トークン検証、関連データ存在時のエラー扱い
  • 保存・削除完了時のDoctrineキャッシュ削除と作成日時・更新日時・作成者の自動設定
  • 一覧表示・編集初期化・編集完了・削除完了の各タイミングで拡張イベントがディスパッチされ、プラグイン等が差し込めること

本書で扱わないこと

以下は本書では仕様確定せず、実装または別機能の設計を正とする。

  • フロント側での新着情報の表示・抜粋・公開日時による絞り込みの画面仕様
  • 管理画面ログイン、セッション、認可、IP制限の詳細（名称や値の環境依存を含む）。削除操作のトークン検証は行う実装であるが、トークン値そのものは扱わない。
  • ルート名・コントローラ実装の手順、ナビゲーション登録の内部仕様
  • フォーム拡張（エンティティ拡張）による追加項目の具体的な項目名・検証
  • Doctrineの二次キャッシュ・マルチテナント・接続種別による行集合や反映タイミングの詳細

用語

用語説明
新着情報フロントTOPページ等に表示する告知1件。`dtb_news`の1行として保持される。
公開日時新着情報を公開扱いとする日時。フロント側の表示判定や一覧の並び順に使われる。
公開状態当該新着情報をフロントへ表示するか否かの区分。公開と非公開の2値。
別ウィンドウで開くリンクURLを別ウィンドウ（別タブ）で開くか否かの設定。リンクURLが無い場合は無効に揃えられる。
管理者管理画面にログイン可能な管理者アカウント。新着情報の編集には管理画面の認可が前提となる。

利用者視点の入口

入口URLエンドポイント期待されるふるまい
ナビから新着情報一覧を開く`GET /%eccube_admin_route%/content/news`登録済みの新着情報が公開日時の新しい順に並ぶ。各行に公開日時・公開状態・タイトルと、編集・削除の導線がある。0件なら見出し行のみ表示する。
一覧の2ページ目以降を開く`GET /%eccube_admin_route%/content/news/page/{page_no}`指定ページの新着情報を1ページ10件単位で表示する。
「新規作成」ボタンを押す`GET /%eccube_admin_route%/content/news/new`新規登録用の編集画面が開く。公開日時には現在日時が初期表示される。
一覧からタイトルまたは編集アイコンを押す`GET /%eccube_admin_route%/content/news/{id}/edit`既存の新着情報が読み込まれ、各入力項目に現行値が表示される。対象が存在しなければ見つからない扱い（HTTP404）になる。
「登録」を押す（編集画面）`POST /%eccube_admin_route%/content/news/new` または `POST /%eccube_admin_route%/content/news/{id}/edit`検証に成功すれば保存され、成功メッセージが積まれたうえで当該新着情報の編集画面へ遷移する。失敗すれば同一編集画面に留まり、項目エラーが表示される。
削除確認モーダルで削除を実行する`DELETE /%eccube_admin_route%/content/news/{id}/delete`なりすまし対策トークンを伴う削除リクエストが送信される。削除できれば成功メッセージを積み一覧へ戻る。関連データがあり削除できなければエラーメッセージを積み一覧へ戻る。
未ログインまたは認可で拒否される利用者上記パス（到達前）管理画面の共通ルールに従いアクセスできない（詳細は管理画面認証・認可の実装を正とする）。

フロント挙動

観点内容
表示要素（一覧）見出し行に「公開日時」「公開状態」「タイトル」を表示する。各行は公開日時、公開状態（公開／非公開の文言）、タイトルのリンク、編集アイコン、削除アイコンで構成する。フッタに「新規作成」ボタンを置く。
表示要素（編集）カード見出し「新着情報登録」。入力欄として公開日時、タイトル、URL、「別ウィンドウで開く」チェックボックス、本文がある。フォーム下部に公開状態の選択（公開／非公開）と「登録」ボタンがある。URLと本文の各見出しには補足ツールチップを表示する。
JS挙動削除アイコン押下でBootstrapのモーダルを開く。本文欄は複数行入力（textarea、表示行数8）。公開日時は単一テキストの日時入力ウィジェット。一覧の並び替え保存処理は持たない（並び替え用UI要素はあるがサーバー保存の入口は本機能に無い）。
CSS・レイアウト管理画面標準のBootstrap系レイアウト。編集は横型フォームテーマを適用する。
モーダル・ポップアップ一覧の削除アイコン押下で確認モーダルを表示し、本文に対象タイトルを差し込む。キャンセルでモーダルを閉じ、削除ボタンで削除リクエストを送る。
入力項目編集画面のフォーム項目は後述の「入力項目」を参照する。

処理フロー

一覧を開く（GET）

  1. 管理画面の認証・認可の各ルールを通過する。
  2. 全件取得用のクエリを組み立て、公開日時の降順、同一公開日時では識別子の降順で並べる。
  3. 一覧初期化イベントをディスパッチする（プラグイン等がクエリビルダを参照・加工できる）。
  4. 1ページ10件でページングし、テンプレートを描画する。

新規登録画面を開く（識別子が新規）

  1. 新規の新着情報を組み立て、公開日時に現在日時を設定する。
  2. フォームビルダーを生成し、編集初期化イベントをディスパッチする。
  3. フォームを構築する。POSTでなければテンプレートを描画する。

既存編集画面を開く（識別子が既存）

  1. 識別子で新着情報を取得する。取得できなければ見つからない扱い（HTTP404）とする。
  2. 以降はフォームビルダー生成・編集初期化イベント・フォーム構築まで新規と同様に進む。POSTでなければテンプレートを描画する。

「登録」押下（POST、検証成功）

  1. フォームをリクエストで処理する。
  2. 検証成功時、リンクURLが空であれば「別ウィンドウで開く」設定を無効に揃える。
  3. 新着情報を永続化する。新規ならこの時点で識別子が採番される。作成日時・更新日時・作成者は永続化前のDoctrineイベントで設定される。
  4. 編集完了イベントをディスパッチする。
  5. 管理画面向け成功メッセージを積む。
  6. Doctrineの二次キャッシュを削除する。
  7. 当該新着情報の編集画面へリダイレクトする。

「登録」押下（POST、検証失敗）

  1. フォームをリクエストで処理する。
  2. 検証失敗時、同一編集テンプレートを再描画する。成功メッセージは積まない。

削除実行（DELETE）

  1. なりすまし対策トークンを検証する。失敗時はアクセス拒否（HTTP例外）となる。
  2. 識別子で対象の新着情報を取得する。取得できなければ見つからない扱い（HTTP404）になる。
  3. 削除処理を試みる。成功時は削除完了イベントをディスパッチし、成功メッセージを積み、二次キャッシュを削除する。
  4. 削除中に例外が発生した場合は、対象タイトルを差し込んだ関連データ存在エラーのメッセージを積む。
  5. 一覧へリダイレクトする。

集計条件

本機能では一覧件数・合計などの集計表示を行わない。一覧はページングのみを行う。

業務ルール・計算

項目内容
一覧の対象公開・非公開を問わず登録済みの全新着情報。管理画面側では公開日時による絞り込みは行わない。
一覧の並び公開日時の降順を主、識別子の降順を従とする。
ページング単位1ページ10件（既定ページ件数の確認値）。
新規の公開日時初期値新規登録画面表示時の現在日時。
公開状態公開（保存値は真）／非公開（保存値は偽）の2択。新規の初期選択は公開（DB既定が真）。
別ウィンドウで開くの整合リンクURLが空の場合、保存直前に「別ウィンドウで開く」を無効（偽）へ揃える。
本文のHTML本文は保存時にHTML浄化（purify）を通す。HTMLタグの利用は可能だが、浄化により一部の記述は除去・整形される。
計算金額計算・税計算・丸めは行わない。

入力項目

項目名必須／任意最大長初期値保存先・扱い
公開日時必須—新規は現在日時、既存はDB値`dtb_news.publish_date`。秒まで含む日時。下限は0003-01-01より前を不正日付として拒否する。
タイトル必須200文字既存値または空`dtb_news.title`。DB列は255文字だが、フォーム検証は200文字（`eccube_mtext_len`確認値）。
URL任意200文字既存値または空`dtb_news.url`。DB列は4000文字。入力時はURL形式制約。フォーム検証は200文字（`eccube_mtext_len`確認値）。
別ウィンドウで開く任意—既存値または未チェック（偽）`dtb_news.link_method`。チェック時に真。URL未入力時は保存直前に偽へ上書きする。
本文任意3000文字既存値または空`dtb_news.description`。複数行入力（textarea、表示行数8）。HTML浄化を通す。フォーム検証は3000文字（`eccube_ltext_len`確認値）。
公開状態必須—新規は公開、既存はDB値`dtb_news.visible`。公開で真、非公開で偽を保存する。

最大長の数値はコア設定のeccube_mtext_len（確認値200）、eccube_ltext_len（確認値3000）を記載する。運用環境で上書きされている場合はその環境の値が正とする。

エッジケース

ケース扱い
編集対象の識別子が存在しない見つからない扱い（HTTP404）となる。新規相当の扱いにはならない。
削除対象の識別子が存在しない見つからない扱い（HTTP404）となる。
削除時に関連データがある等で例外発生関連データ存在エラーのメッセージを積み、一覧へリダイレクトする。物理削除は完了しない。
URL未入力で別ウィンドウチェックあり保存直前に別ウィンドウ設定を偽へ揃える。
公開日時が下限より前不正日付として検証エラーになり保存しない。
一覧が0件見出し行のみ表示し、明細行を出さない。

データ整合性

観点内容
一覧と編集一覧は全件（公開・非公開とも）を公開日時降順で表示する。編集は識別子指定で取得した行を対象とする。
フロント表示との整合管理側の一覧は公開日時による絞り込みをしない。フロント側の表示・抜粋・公開日時判定は別機能の実装を正とし、本機能の一覧表示と一致を保証しない。
二次キャッシュ保存・削除の成功時にDoctrineの二次キャッシュを削除する。これにより次回読み取りで最新状態を反映する。
作成日時・更新日時・作成者永続化直前のDoctrineイベントで、新規時は作成日時・更新日時、更新時は更新日時が設定される。管理者ログイン下では作成者がログインユーザに設定される。
同時更新楽観ロックによる版管理は持たない。複数管理者が同一新着情報を同時編集した場合は最後に保存した内容が残る。

セッション

本機能におけるセッション

観点内容
成功・エラーメッセージリダイレクト後の編集画面や一覧で一度表示するためにフラッシュバッグへ格納する。

セッションへ保存しない情報

新着情報の本文やフォームの下書きをセッションへ長期保存する処理は当機能では行わない。

Cookie

本機能単体で特有のCookieは定義しない。セッションCookieは管理画面全体の実装を正とする。

排他制御・トランザクション

当機能のコア実装はDoctrineの典型パターンによる永続化であり、新着情報を楽観ロックで版管理する実装は持たない。複数管理者が同一新着情報を同時編集した場合の結果は最後に保存された内容が残る。
