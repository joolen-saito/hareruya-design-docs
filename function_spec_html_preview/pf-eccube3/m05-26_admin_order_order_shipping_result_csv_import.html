受注管理 — 出荷実績インポート登録

業務ロジック

受け付けるファイル

カンマ区切りとタブ区切りの両方を受け付ける。拡張子が tsv のときはタブ区切りとして読み、それ以外は設定の区切り文字で読む。

二重実行の防止

同じ取り込みが同時に走らないよう実行権を取る。すでに別の取り込みが動いているときは登録せず、実行中である旨を伝える。実行権を取れなかったときも登録しない。

実行権を取るのは、ファイルの受け取りと行データの生成が終わったあとだけである。ファイルの読み込みまでは同時に走りうる。

取り込み前の検査

実行権を取ったあと、順に次を確かめる。引っかかったときは 1 件も登録しない。

  • ヘッダ行の項目が想定の 63 項目と一致すること。必須は注文番号だけで、それ以外は無くてもよい。
  • データ行が 1 行以上あること。

行ごとの処理

各行について上から順に判定し、引っかかったときはその行を示してエラーとし、取り込み全体を取り消す。

順判定
1列数がヘッダ行と一致しないときはエラーとする
2注文番号が空のときはエラーとする
3注文番号を 8 桁のゼロ埋めに整えて受注を探し、見つからないときはエラーとする
4出荷日が空のときは、この行を読み飛ばす。読み飛ばした行は何も更新しない
5注文者が会員でないときはエラーとする
6出荷日が日時として解釈できないときはエラーとする

受注の更新

受注に出荷日がまだ入っていないときだけ、対応状況を出荷完了に変え、出荷日と送り状No.を設定する。この受注は登録後の処理の対象になる。

受注にすでに出荷日が入っているときは、対応状況も出荷日も送り状No.も更新しない。登録後の処理の対象にもならない。

配送先の発送日は、受注に出荷日が入っているときも入っていないときも、取り込んだ出荷日で更新する。更新するのはその受注のすべての配送先である。

登録後の処理

受注の更新を確定したあと、更新した受注ごとに上から順に次を行う。

順処理
1ポイントを付与する。付与ポイントが空のとき、0 のときは付与しない
2出荷完了メールを送信する
3スマレジ側のポイントを加算する。外部からの応答に成功の結果が無いときは、加算完了とせずエラーとして記録する

これらは受注の更新を確定したあとに動くため、途中で失敗したときも取り消されない。確定済みの受注更新、先行する受注へ付与済みのポイント、送信済みのメールは戻らない。

一時ファイル

処理を終えるとき、取り込みに使った一時ファイルを削除する。削除に失敗しても処理は続ける。

入出力

出力: メール

更新した受注ごとに出荷完了メールを送信する。受注にすでに出荷日が入っていたときは送信しない。

入出力: 永続化

操作契機
対応状況・出荷日・送り状No.の更新受注に出荷日が入っていないときだけ
配送先の発送日の更新出荷日の有無にかかわらず、その受注のすべての配送先
ポイントの付与更新した受注のうち、付与ポイントが空でも 0 でもないとき
スマレジ側のポイント加算更新した受注ごと
