カード管理 — フォーマット一覧

概要

HareruyaEc プラグインが管理画面の「カード管理」メニューから提供する、フォーマットマスタ（mtb_format）の全件一覧表示である。表示順はランクの昇順、同一ランク内は ID の昇順とする。各行から編集画面へのリンクと、操作メニュー経由の削除要求（別 HTTP メソッド）に接続する。

本書は実装手順ではなく、誰が・いつ・どの条件で・結果どうなるかを読むためのリバース詳細設計とする。pf-eccube3 に配置された HareruyaEc プラグインのソースを確認値とする。

本機能のカスタマイズ区分は現行踏襲である。挙動は現行リポ（pf-eccube3 の HareruyaEc プラグイン）を参照し、DB関連は ec-cube-enterprise を正とする。

対象はブラウザ経由の管理画面に限定する。フォーマットの新規登録・更新フォームの項目定義や禁止・制限カードの保存手順の細部は本書の主題としない。

本文ではフレームワークのコントローラ型名やメソッド名を主説明としない。本文ではルートbind名やSymfonyのルートnameの網羅は主説明としない。「利用者視点の入口」にHTTPメソッドとサイトルートからのパスパターンを書く。コード探索でbind名が必要なときだけ「調査補助」へ書く。

リニューアル移行時の扱い

  • ec-cube-enterprise にフォーマットマスタが実装されており、本機能の参照先は移行先に存在する。
  • フォーマットマスタ（mtb_format）は、主キー id と列（name_jp、name_en、code、certification_id、rank、deleted_at ほか）が現行 pf-eccube3 と同一スキーマである。
  • 並びの第一キーは現行・移行先とも rank（予約語のためバッククォート付き）であり、sort_no への改称はない。第二キーは id。
  • 論理削除列 deleted_at を現行・移行先とも持ち、一覧取得は論理削除済み行を除外する。
  • 認定参照（certification_id）は認定マスタへの外部キーで、現行・移行先とも同じ関連である。
  • 移行先 mtb_format には現行に無い列（イベント表示フラグ is_shown_in_event 等）が追加されているが、一覧表示では参照しない。

処理フロー

一覧を表示する（GET m14-09_admin_card_format_list）

  1. 管理画面の認証・共通制約を通過する。
  2. フォーマット向けリポジトリで、ソフト削除拡張がマッピング上で有効な通常稼働では、論理削除済み行を除いた集合に対し、空の検索条件、並び rank 昇順、id 昇順でDoctrine の findBy 相当が実行される。
  3. 得られた配列をそのまま Twig に渡し、テーブル行をループで描画する。
  4. 0 件の場合も表ヘッダは表示され、データ行は出力されない（空の tbody）。

一覧の行メニューから削除する（DELETE admin_format_delete）

  1. 管理画面の認証・共通制約および CSRF 検証を通過する。
  2. パスの ID に対応するフォーマットが存在しなければ HTTP 404 とする。
  3. 当該フォーマットに紐づくイベント、デッキ、アーキタイプのいずれかのコレクションが空でない場合、対応するエラーメッセージキー（イベント: admin.product.format.error.delete.registered_event / デッキ: admin.product.format.error.delete.registered_deck / アーキタイプ: admin.product.format.error.delete.registered_archetype）をフラッシュに積み、admin_format_list へ HTTP リダイレクトする。削除は行わない。
  4. 上記がすべて成立する場合、当該フォーマットに紐づくカード別制限行（カードとフォーマットと制限の交差）をすべて削除し、その後フォーマット行を削除し、成功メッセージを積んで m14-09_admin_card_format_list へリダイレクトする。
