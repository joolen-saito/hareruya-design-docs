店舗設定／特定商取引法（ヘルプ情報の表記編集）

概要

管理画面の「店舗設定」配下にある「特定商取引法」編集画面から、dtb_help に保持される特定商取引法に関する表記（販売業者・所在地・連絡先・各種約款項目など）を入力し、永続化する機能である。画面見出しは「ショップ設定」「特定商取引法管理」、ボックス見出しは「特定商取引法」として表示される。

メニュー構造上は「SHOPマスター（基本情報設定）」とは別画面である。保存先も店舗基本情報（dtb_base_info）ではなく、識別子固定で1件とみなされるヘルプ情報（dtb_help）である。

本書は実装手順ではなく、誰が・いつ・どの条件で・結果どうなるかを読むためのリバース詳細設計とする。既存実装のふるまい、参照するデータ、判定境界、副作用、プラグイン拡張の差し込み点を確認し、仕様の確からしさを把握することを目的とする。

対象はブラウザ経由の管理画面に限定する。

本機能のカスタマイズ区分は現行踏襲であり、画面・処理の挙動は現行リポ（pf-eccube3）の実装を確認値とし、DB関連（テーブル名・列名・型・保存先）は ec-cube-enterprise を正とする。

コントローラクラスやメソッドの解剖は本文の主題としない。本文ではルートbind名やSymfonyのルートnameの網羅は主説明としない。「利用者視点の入口」にHTTPメソッドとサイトルートからのパスパターンを書く。コード探索でbind名が必要なときだけ「調査補助」へ書く。

リニューアル移行時の扱い

現行（pf-eccube3）は特定商取引法の表記をヘルプ情報（dtb_help）の固定列（law_company・law_manager・law_zip01〜law_term06 等）に保持する。移行先（ec-cube-enterprise）には dtb_help テーブルが存在せず、特定商取引法は dtb_tradelaw（名称 name・説明 description・表示順 sort_no・画面表示フラグ display_order_screen の行リスト）として保持する設計である。販売業者・所在地・連絡先・各約款を個別列に持つ現行モデルとは構造が異なる。

処理フロー

画面を開く（GET）

  1. 管理画面の認証・IP 制限・権限拒否の各ルールを通過する。
  2. ヘルプ情報をリポジトリの取得メソッド（既定識別子）で読み込む。
  3. tradelaw 名前のフォームビルダを当該エンティティに対して生成する。
  4. イベントディスパッチャに「店舗設定／特定商取引／初期化」相当のイベントを通知する。引数にフォームビルダとヘルプ情報実体が含まれる。プラグイン等がフィールド追加・変更する場合がある。
  5. フォームを組み立て、リクエストを処理する（GET のため送信済みにならない）。
  6. テンプレートを描画する。

「登録」押下（POST、検証成功）

  1. フォームが送信済みとなり、入力がヘルプ情報実体にマッピングされる。
  2. 検証が成功した場合、永続化コンテキストへヘルプ情報を登録し、flush する。
  3. Doctrine の保存前更新イベントにより、実体に setUpdateDate があれば現在日時で更新される。
  4. 「店舗設定／特定商取引／完了」相当のイベントを通知する。引数にフォームとヘルプ情報が含まれる。
  5. 管理画面向け成功メッセージキー（登録完了メッセージ）を積む。
  6. 同一編集画面へのリダイレクト応答を返す。

「登録」押下（POST、検証失敗）

  1. フォームが送信済みで検証エラーとなる。
  2. 同一テンプレートを再描画し、各項目のエラーを表示する。成功メッセージは積まない。
  3. DBは更新しない。
