店舗設定／利用規約（ヘルプ情報の本文編集）

概要

管理画面の「設定→基本情報設定」配下にある「利用規約設定」画面から、dtb_help の「利用規約」本文相当の列を入力して永続化する機能である。メニューおよび関連ヘッダでは「利用規約」「利用規約管理」と表示される。フロントの会員登録まわりでは同一文言へのリンクから規約ページへ誘導する構成があるため、運用上はユーザー側では「会員規約」「ご利用規約」と読まれていることがあり得るが、当画面の編集対象はコア実装上この1項目に限定される。

メニュー構造上は「ショップマスター（店舗基本情報の単一フォーム）」とは別画面である。保存先も店舗基本情報（dtb_base_info）ではなく、識別子固定で1件とみなされるヘルプ情報（dtb_help）である。

本書は実装手順ではなく、誰が・いつ・どの条件で・結果どうなるかを読むためのリバース詳細設計とする。既存実装のふるまい、参照するデータ、判定境界、副作用、プラグイン拡張の差し込み点を確認し、仕様の確からしさを把握することを目的とする。

対象はブラウザ経由の管理画面に限定する。

本機能のカスタマイズ区分は現行踏襲であり、画面・処理の挙動は現行リポ（pf-eccube3）の実装を確認値とし、DB関連（テーブル名・列名・型・保存先）は ec-cube-enterprise を正とする。

本書の本文ではルート名の網羅やコントローラ実装の手順は扱わない。ただし「利用者視点の入口」には、HTTP メソッドとサイトルートからの相対パスを {admin_route} を含む形で記載する（ホスト名・絶対 URL は書かない）。

本書で扱うこと

  • 「利用規約設定」画面の表示要素・入力項目・送信ボタン
  • 入力値の検証ルールと、エラー時・成功時に利用者へ見える結果
  • 保存先（dtb_help／Doctrine上のヘルプ情報エンティティ）と、flush時に共通購読処理で更新される日時項目
  • 保存完了後の画面遷移と成功メッセージ
  • 同一データを参照するフロントの「利用規約」ページとの対応（本文の出力方法の要点）
  • 表示初期化時・保存完了時のイベントディスパッチ（プラグイン等がフォームや保存結果に介入する境界）

処理フロー

画面を開く（GET）

  1. 管理画面の認証・IP制限・権限拒否の各ルールを通過する。
  2. ヘルプ情報をリポジトリの取得メソッド（既定識別子）で読み込む。
  3. 利用規約用フォームビルダを当該エンティティに対して生成する。
  4. イベントディスパッチャに「店舗設定／利用規約／初期化」相当のイベントを通知する。引数にフォームビルダとヘルプ情報実体が含まれる。プラグイン等がフィールド追加・変更する場合がある。
  5. フォームを組み立て、リクエストを処理する（GET のため送信済みにならない）。
  6. テンプレートを描画する。

送信成功（POST、検証成功）

  1. フォームが送信済みとなり、入力がヘルプ情報実体にマッピングされる。
  2. 検証が成功した場合、永続化コンテキストへヘルプ情報を登録し、flushする。
  3. Doctrine の保存前更新イベントにより、実体に setUpdateDate があれば現在日時で更新される。
  4. 「店舗設定／利用規約／完了」相当のイベントを通知する。引数にフォームとヘルプ情報が含まれる。
  5. 管理画面向け登録完了メッセージキーを積む。
  6. 同一編集画面へのリダイレクト応答を返す。

送信失敗（POST、検証失敗）

  1. フォームが送信済みで検証エラーとなる。
  2. 同一テンプレートを再描画し、該当フィールドにエラーを表示する。成功メッセージは積まない。
  3. DBは更新しない。
