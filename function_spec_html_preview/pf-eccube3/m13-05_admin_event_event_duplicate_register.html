M13-05（複製新規）

刷新後は実装不要本節は現行実装（pf-eccube3）からのリバースです。次の記述は Excel基本設計により廃止されており、刷新後に実装する必要はありません。

  • チーム人数 は チーム戦フラグ（dtb_event.is_team_battle、真偽） へ変更（0214 イベント編集 識別ID:1-12）これに伴い実装不要: チームメンバーのメールアドレス・席次の入力／メールのみの仮選手（dtb_player）の作成／チームメンバー招待メールの送信／未承認（confirm_flg=UNCONFIRMED）での申込選手登録／招待リンクからのチームプレイヤー認証（events_team_player_activate）

管理画面「イベント管理」で、登録済みイベントの内容をフォームへ複製した状態で新規登録画面を開き、別のイベントとして登録できるようにする機能である。

概要

複製新規は、既存イベントの編集画面から複製新規ボタンを押すことで、複製元イベントの入力値を引き継いだ新規登録フォームを表示する機能である。表示時点で複製元の値をフォームに載せるだけであり、保存は新規登録として行う。日程・申込・登録者などは引き継がない。

本書は実装手順ではなく、誰が・いつ・どの条件で・結果どうなるかを読むためのリバース詳細設計とする。既存実装が複製する項目と複製しない項目、表示と保存の関係、副作用を確認し、仕様の確からしさを把握することを目的とする。

対象はブラウザ経由の管理画面イベント複製新規画面である。本機能は晴れる屋向けプラグインで提供され、EC-CUBE3系のSilexアプリケーション上で動作する。管理画面プレフィックスはアプリケーション設定admin_route（$app['config']['admin_route']）で決まり、ルートはこの値を連結して登録される。確認観点はイベント用サービスプロバイダのルート登録とする。

複製新規の画面表示は、新規登録・編集と同一のフォーム生成・テンプレート（eventdetail.twig）を用いる。入力項目の詳細・検証・保存後の永続化はM13-02を正とし、本書は複製時に引き継ぐ値と引き継がない値、保存経路の違いに範囲を限定する。一覧検索はM13-01、申込検索はM13-06、デッキ表示はM13-08を正とする。

本機能のカスタマイズ区分はカスタマイズである。挙動の参照リポはpf-eccube3（HareruyaEcプラグイン）の現行実装とし、DB関連（永続化先のテーブル名・列名、DBカラム節、保存先・扱い、副作用のDB更新）はec-cube-enterpriseを正とする。現行と移行先でスキーマが異なる箇所はリニューアル移行時の扱いに集約する。

本書で扱うこと

  • 複製新規ボタンから複製新規画面を開いたときの、複製元イベントの値の引き継ぎ
  • 複製される項目（イベント情報の入力値）と複製されない項目（日程・申込・登録者・採番）
  • 複製新規画面の保存が新規登録として扱われること
  • 存在しない複製元IDのときのふるまい

本書で扱わないこと

以下は本書では仕様確定せず、実装または別機能の設計を正とする。

  • イベント情報の入力項目・最大長・検証・保存後の永続化（M13-02を正とする）
  • イベント一覧の検索・ページング（M13-01を正とする）
  • イベント申込の検索・登録（M13-06を正とする）
  • デッキ表示（M13-08を正とする）
  • 日程（イベント詳細）の登録ルール
  • 管理画面へのアクセス制御、ログイン、権限設定の詳細

処理フロー

複製新規画面を表示する

  1. 管理者が編集画面で複製新規ボタンを押す。
  2. パスの複製元IDで複製元イベントを読む。存在しなければ404とする。
  3. パスのIDは渡されない（複製ルートはIDを持たない）ため、日程の読み込み・申込人数の集計は行わない。
  4. 複製元イベントを初期データとしてイベント登録フォーム（フォーム名admin_event_detail）を生成する。
  5. テンプレートを描画する。IDを渡さないため、画面は新規登録モードとして表示される。送信先は新規登録（admin_event_create）になる。

複製新規画面を保存する

  1. 複製新規画面の保存は新規登録の送信経路に入る。
  2. 新規イベントを用意し、フォームにリクエストを反映して検証する（M13-02の新規登録フロー）。
  3. 登録者IDにログイン中の管理者IDを設定し、新規イベントとして永続化する。
  4. 完了メッセージを表示し、登録したイベントの編集画面へリダイレクトする。

複製新規の画面表示では一覧件数の集計や金額計算を行わない。日程ごとの申込人数の集計も行わない（複製ルートではパスのIDを持たないため）。
