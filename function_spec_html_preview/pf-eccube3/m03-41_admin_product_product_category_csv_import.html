m03-41_admin_product_product_category_csv_import（管理画面_商品管理_カテゴリCSV登録）

概要

管理画面でカテゴリマスタ（dtb_category）へCSVをアップロードし、行単位で新規作成・更新・削除をまとめて適用する機能である。画面タイトルの翻訳キーは admin.product.category_csv_uploadで、日本語では「カテゴリCSV登録」と表示される。CSVの列見出しは多言語メッセージ（日本語環境では「カテゴリID」「カテゴリ名」など）であり、dtb_csvの項目定義は使わない。一覧からダウンロードするカテゴリCSV出力（ルート admin_product_category_export）や、「カテゴリ登録CSV」として別コントローラが提供する一括取込（ルート admin_product_category_bulk_csv_upload）とは別経路である。

本書は実装手順ではなく、誰が・いつ・どの条件で・結果どうなるかを読むためのリバース詳細設計とする。確認値はEC-CUBE Enterpriseのsrc/Eccube配下および配布 app/config/eccube/packages/eccube.yamlとする。

本機能のカスタマイズ区分はカスタマイズである。挙動の参照リポは現行のpf-eccube3とし、DB関連（テーブル名・列名・型・制約・関連、保存先・扱い、副作用のDB更新）はec-cube-enterpriseを正とする。

対象はブラウザ経由の管理画面に限定する。

コントローラのメソッド単位の解剖は本文の主題としない。本文ではルートbind名やSymfonyのルートnameの網羅は主説明としない。「利用者視点の入口」にHTTPメソッドとサイトルートからのパスパターンを書く。コード探索でbind名が必要なときだけ「調査補助」へ書く。

処理フロー

画面を表示する（GET m03-41_admin_product_product_category_csv_import）

  1. 管理画面の認証・共通制約を通過する。
  2. CsvImportTypeのフォームを生成する。
  3. getCategoryCsvHeader()の結果をheadersとしてテンプレートへ渡し、renderWithErrorで描画する。

CSVを取り込む（POST m03-41_admin_product_product_category_csv_import）

  1. フォームをhandleRequestする。Symfonyの検証で失敗した場合はテンプレートがエラー状態で返る（ファイル未選択やサイズ超過など）。
  2. import_fileが空なら取込処理ブロックに入らず、ログもフラッシュも付けない実装である（フォーム妥当性だけが通った場合に該当しうる）。
  3. 情報ログに「カテゴリCSV登録開始」を記録する。
  4. アップロードファイルを一時ディレクトリ（eccube_csv_temp_realdir）へ保存し、CsvImportServiceで読む。先頭行をヘッダとみなせない場合は falseとなり、admin.common.csv_invalid_formatをエラーに積み、rollback=falseで renderWithErrorする（このときDBトランザクションは開始前）。
  5. 必須ヘッダに対応する列名が CSVの1行目にすべて含まれていなければ、同上フォーマットエラーとして終了する。
  6. データ行が1行も無ければ admin.common.csv_invalid_no_dataを積んで終了する。
  7. ORMの設定でSQLロガーを更新する呼び出しを行ったうえでDBトランザクションを開始する。
  8. 各行について順に以下を適用する。途中でエラーを積んだら renderWithErrorで打ち切り、ロールバックされる。
  • 新規のカテゴリオブジェクトを用意する。
  • 「カテゴリID」列が非空白のとき、数字のみでなければ「◯行目のカテゴリIDが存在しません。」で終了。数字ならIDで検索し、無ければ「更新対象のカテゴリIDが存在しません。…空で登録」メッセージで終了。カテゴリIDと親カテゴリIDが同一文字列なら「同じです。」で終了。
  • 「削除フラグ」列が非空白かつトリム後が 1のとき、既存IDがあれば削除を試みる。外部キー制約違反時は翻訳キー admin.common.delete_error_foreign_key（カテゴリ名埋め込み）で終了。削除処理後は continueし、名前や親の更新は行わない。
  • 「カテゴリ名」が未設定または空白のみなら「◯行目のカテゴリ名が設定されていません。」で終了。非空白なら前後空白除去して名前をセットする。
  • 「親カテゴリID」が非空白のとき、数字のみでなければ親不存在メッセージで終了。数字なら親を検索し、無ければ親不存在メッセージで終了。空白なら親なし。
  • 親オブジェクトへ関連をセットする。
  • 「階層」キーが存在し空白でないとき、その値をトリムした文字列を階層として使う。このとき親が無いのに階層が 1でない場合も「親カテゴリIDが存在しません。」という同一文言で終了する（実装上のメッセージである）。
  • 「階層」が無いか空白のときは、親が無ければ 1、親があれば親の階層に1を加えた値とする。
  • 算出した階層が設定 eccube_category_nest_levelを超えると「最大レベルを超えているため設定できません。」で終了する。
  • persistのうえ categoryRepository.saveを呼ぶ（内部で flushが走る）。
  1. 全行が成功したらコミットする。
  2. 情報ログに「カテゴリCSV登録完了」を記録する。
  3. フラッシュバッグ種別 eccube.admin.successにメッセージキー admin.common.csv_upload_completeを積む（日本語環境の確認値は「CSVファイルをアップロードしました」）。
  4. Doctrineのキャッシュユーティリティでクリアする。
  5. renderWithErrorでテンプレートを返す。エラーが無ければロールバックは走らず、アップロード一時ファイルは削除される。
