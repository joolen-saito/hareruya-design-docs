商品管理 — タグ登録/編集

概要

dtb_tag（商品タグマスタ）を管理画面で新規登録・編集し、一覧・ページ送り・表示件数変更とあわせて同一画面に配置する機能である。ナビゲーション上の名称は「タグ登録/編集」である。優先表示用の規格紐付けは保存処理のなかで dtb_tag_sort を再構成する。

本書は実装手順ではなく、誰が・いつ・どの条件で・結果どうなるかを読むためのリバース詳細設計とする。確認値は ec-cube-enterprise コアの管理画面「商品タグ」ルート群、タグフォーム定義、保存処理サービス、Twig テンプレート tag.twig、および dtb_tag と dtb_tag_sort を扱うリポジトリを正とする。HareruyaEc プラグインのカード管理系とは別系統である。カスタマイズ区分は現行踏襲であり、現行挙動は pf-eccube3 を参照し、DB関連（テーブル名・列名・型・制約・関連）は ec-cube-enterprise を正とする。

対象はブラウザ経由の管理画面に限定する。

本文ではフレームワークのコントローラ型名やメソッド名を主説明としない。本文ではルートbind名やSymfonyのルートnameの網羅は主説明としない。「利用者視点の入口」にHTTPメソッドとサイトルートからのパスパターンを書く。コード探索でbind名が必要なときだけ「調査補助」へ書く。

フロント挙動

観点内容
表示要素画面タイトルは翻訳キー admin.product.tag_management（例: タグ管理）。サブタイトルは商品管理。メニューは product と tags。上半分はカード内フォーム add_new_product_tag。見出しは編集時は「編集」、新規時は新規登録系ラベル。1 行目に名称(日)・名称(英)・並び順。折りたたみ「その他の設定 (クリックで展開)」内にフリーエリア(日)(英)、優先表示商品、タイトル(日)(英)、説明(日)(英)。下半分は一覧表（ID・名称(日)(英)・並び順・編集ボタン）と表示件数セレクト、ページャ。フッタ conversion に「登録」ボタン（form 属性で上半分フォームに送信）。
JS 挙動.js-page-count 変更時に現在 URL に page_count クエリを付けて location を置き換える。一覧行に sortable-item クラスと data 属性があるが、当テンプレート内に並べ替え用のスクリプトは無い。
CSS・レイアウト行ホバー、sortable-item のカーソル、折りたたみ矢印の回転。Bootstrap 4 横型フォームテーマ。
モーダル・ポップアップ本画面専用のモーダルは無い。

補足（フォーム型とテンプレートの差）: フォーム型にはチェックボックス「優先表示商品のみを表示」（hide_normal_products_flg）が定義されているが、当 Twig では form_row されておらず画面上に出ない。POST にも含まれないため、フォーム処理での値の扱いは未送信フィールドの既定に依存する（保存先列は dtb_tag.hide_normal_products_flg）。

処理フロー

画面を表示する（GET 各ルート）

  1. 管理画面の認証・権限チェックを通過する。ロールに deny_url が /product/tag のエントリがあれば、パス先頭が /{admin_route}/product/tag に一致する要求は拒否される。
  2. ルートに id が無い、またはルート引数としてマスタ行が解決されない場合は新規用の空インスタンスをフォームに載せる。ルート …/product/tag/{id} ではパスの id から既存行がフォームに載る。
  3. セッション admin.product.tag.page_no に、引数 page_no があればその値、なければ既存セッション値、初期値 1 を書き込む。
  4. 表示件数はクエリ page_count があれば整数化してセッション admin.product.tag.page_count に格納。無ければセッション値、なければ 10。
  5. dtb_tag を sort_no 昇順でクエリし、アプリケーションのページネータで（上記ページ番号・件数）分割してテンプレートへ渡す。

登録・更新する（POST m03-13_admin_product_product_tag_store）

  1. 管理画面の認証・権限を通過する。
  2. パスに id があれば既存のタグ行を取得し、なければ新規インスタンスでタグ用フォームを生成し、POST を取り込む。
  3. 未送信または検証失敗時、フラッシュに admin.register.failed を積み、直前のページ番号・件数で一覧を再構成して同テンプレートを返す（リダイレクトしない）。
  4. 検証成功時、タグ保存用のトランザクション処理に渡す。処理はトランザクション内で次のとおり。
  • タグ行を persist し flush し、主キーを得る。
  • dtb_tag_sort について当該 tag_id を DQL delete で一括削除する。
  • priority_products 文字列を \r\n で分割し、空要素を除き、先頭から順に一意化する。
  • コード列が空でなければ、各コードについて「当該タグが付いた商品の規格」「規格コード一致」「visible が true」の条件で規格を検索し、見つからないコードがあると例外を投げ、メッセージは admin.error.not_exist_code（コードとタグ名を埋める）。
  • 見つかった規格ごとに dtb_tag_sort 行を作成する。ランクは「列の長さ − 現在のインデックス」で、先頭のコードが最も大きい rank となる。
  • 成功時 commit する。例外時は rollback し再送出する。
  1. 保存処理が例外で終わった場合、例外メッセージをフラッシュに積み、同テンプレートを返す。
  2. 成功時、フラッシュに admin.register.complete を積み、m03-13_admin_product_product_tag へリダイレクトする。リダイレクト引数に保存後の主キー id を渡すため、生成 URL にはクエリ ?id= が付く。

削除する（DELETE m03-13_admin_product_product_tag_delete）

  1. 共通のトークン検証（isTokenValid）を通過する。
  2. 当該タグに dtb_product_tag 行が 1 件でもあれば、admin.tag.delete.failed をフラッシュし m03-13_admin_product_product_tag へリダイレクト（パスパラメータ id は付けない）。
  3. 紐付けが無ければ永続化層でタグ本体を削除予約し、dtb_tag_sort を tag_id で一括 DELETE し、flush する。DB 制約等で失敗した場合は admin.common.delete_error_foreign_key をフラッシュする。
  4. いずれの場合も m03-13_admin_product_product_tag へリダイレクトし、第 3 引数として id を渡す実装になっている（削除成功後はインスタンス上の主キー値がクエリに乗る）。

集計条件

本機能では一覧件数の総数表示に依存する独自集計は行わない。ページャが内部で総件数を求めるのみである。

指標集計の要点
一覧総件数dtb_tag 全件を sort_no 昇順で対象とし、表示件数で分割する。

登録・更新時の判定順序

順序判定結果
1フォーム送信の有無とフィールド検証失敗ならエラーフラッシュと再描画。
2トランザクション開始後、タグ行の persist・flush主キーを確定する。
3当該タグ ID の dtb_tag_sort 全削除古い優先順位を消す。
4優先商品コード列を分割・一意化し、各コードの規格解決欠けるコードがあれば例外（rollback）。
5各行を rank 付きで insert し commit成功時は成功フラッシュへ遷移。

業務ルール・計算

項目内容
一覧の並びsort_no 昇順。一覧の並び替え UI は無く、フォームの「並び順」で制御する。
優先表示の rank入力テキストの先頭に近いコードほど大きい rank。行数を n、0 始まりインデックスを i とすると rank は n − i。
優先表示の対象規格渡したコードが「表示中の規格」かつ「当該タグが商品に付いている」必要がある。登録直後の新規タグでは、まだ商品に付いていないため優先コードを保存しても規格解決に失敗し得る。

エッジケース

ケース扱い
新規タグに優先商品コードだけ入力規格検索は「タグが商品に付いている」条件を含むため、該当なしで例外となり rollback する。
改行が LF のみ\r\n 分割のため 1 行として扱われる。
同一コードを複数行array_unique 維持順で 1 回だけ使う。
削除時に商品タグ紐付けありDB 削除は行わずエラーメッセージを出して一覧へ戻る。
hide_normal_products_flgフォーム型に存在するが当画面に無い。POST に無い場合の更新挙動に注意する。

データ整合性

観点内容
一覧とフォーム一覧は常に DB 現行の全タグからページ分割したスナップショット。フォームはルート id で特定した 1 行（新規時は空）。同一画面でも一覧行とフォーム内容が別エンティティ由来である。
保存と dtb_tag_sort保存成功後、当該タグ ID のソート行は入力に完全一致する集合に置き換わる。空入力ならソート行は 0 件。
同時更新楽観ロックは持たない。後勝ちで flush される。
