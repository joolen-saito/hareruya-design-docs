デッキ管理 — 検索一覧からの一括編集

処理フロー

一括編集を実行する（POST m15-04_admin_deck_deck_bulk_update）

  1. 管理画面の認証・共通制約を通過する。
  2. フォーム名 m15-04_admin_deck_deck_bulk_update でリクエストを処理し、CSRF を検証する。失敗時はアクセス拒否（HTTP 403）の扱いになる（共通ヘルパの実装に従う）。
  3. フォーム検証に失敗した場合、エラーメッセージをフラッシュに積み、Referer ヘッダの URL へ HTTP リダイレクトする。
  4. 検証成功時、フォーム項目名とエンティティ更新用セッター名の対応表に従い、各 change_flgs[項目名] が存在する項目だけについて、フォームの値をセッターに渡して各デッキ行を更新する。change_flgs に無い項目は既存値を保持する。
  5. リクエストの deckId を配列として取得し、各要素が非空かつ半角数字のみであることを検査する。1 つでも不一致なら HTTP 404 で打ち切る。
  6. デッキ ID 集合に対応する行をリポジトリから取得する（取得方法は「エッジケース」参照）。
  7. 取得した各行について手順 4 の更新を適用し、最終更新者として操作者の管理者 ID を member_id に記録する。永続化コンテキストへ登録する。
  8. まとめて flush する。
  9. 成功メッセージキー admin.register.complete をフラッシュに積み、Referer へリダイレクトする。

一覧に一括編集フォームを載せる（表示時）

  1. デッキ検索一覧用のコントローラが bulkUpdateForm として空の m15-04_admin_deck_deck_bulk_update フォームビューをテンプレートへ渡す（トークンのみ実体化し、入力は未送信状態）。

一括更新時の判定順序

順序判定結果
1CSRF トークン無効ならアクセス拒否。
2送信フォームの検証（全項目。変更フラグは検証対象の絞り込みに使わない）失敗ならエラーフラッシュと Referer へリダイレクト。
3各 deckId が半角数字のみか1 件でも不正なら HTTP 404。
4各行について各列change_flgs にキーがある列だけ、フォーム値で上書きする。

入出力

種類内容
入力POST ボディに m15-04_admin_deck_deck_bulk_update フィールド群、_token、change_flgs[...]、deckId[]。
成功時出力HTTP 302 前後で成功フラッシュ。
失敗時出力検証失敗時はエラーフラッシュと Referer へリダイレクト。ID 形式不正時は HTTP 404。CSRF 失敗時は共通の拒否応答。
副作用dtb_deck 行の更新、member_id の更新、多対多タグの付け替え（該当フラグ時）、代表カード画像の更新（アーキタイプ変更フラグ時かつ画像ありの場合）。

ログ・監査

明示的な監査ログ出力は本処理内に限定しては定義されていない（管理画面共通のリクエストログの有無は基盤実装を正とする）。

ログに出してはいけないもの

  • なりすまし対策トークン
  • Cookie 値
  • セッション ID の完全値

業務ロジック

業務ルール・計算

項目内容
変更対象列format, archetype, disp, privateFlg, eventNameJp, eventNameEn, eventDate, ranking, result, winCount, lossCount, drawCount, dciNo, playerName, deckTags, sourceUrl のいずれかについて、対応する変更フラグが POST に含まれるときだけ、その列の現在のフォーム値を全対象デッキに適用する。
フォーマット空の選択（プレースホルダ相当）で上書きすると、永続化層では外部参照なしとして解釈され得る（未選択時の解釈はフォーム送信値に従う）。
アーキタイプエンティティの「アーキタイプと代表カード画像を同時設定」用の更新経路を使う。アーキタイプに代表カード画像が無い場合は画像参照の更新は行われない実装である。
デッキタグ多値選択。変更フラグが付いた場合の値で既存のタグ紐付けが置き換わる（空選択は空コレクションとして解釈され得る）。
編集者各対象デッキの member_id は操作した管理者アカウント ID に更新される。

本機能では売上・順位計算などの業務計算は行わない。

エッジケース

ケース扱い
POST された deckId の一部が DB に存在しない取得できたデッキ行だけを更新する。存在しない ID についてエラーにはしない。
サーバ実装でのリポジトリ呼び出しコントローラ側の取得メソッド呼び出し名と、リポジトリに定義された複数 ID 取得メソッド名が一致しないソースがあり得る。その場合は未定義メソッド呼び出しとなる（調査補助でファイルとメソッド名を照合すること）。
変更フラグを 1 つも付けずに送信クライアントの「一括編集実行」でブロックされる。サーバ側は変更フラグが無くても検証が通れば flush だけ行い、実質データ変化はセッターが呼ばれない。
deckId を付けずに POSTクライアントではブロックされない経路があり得る。サーバでは deckId を foreach しており、PHP の版によっては致命的エラーまたは警告となり得る。
Referer が無いリダイレクト先が空や不正 URL になり得る。ブラウザとクライアント実装に依存する。

データ整合性

観点内容
一覧との一致更新直後は Referer で戻った検索一覧の内容は、検索条件が同じでも再検索タイミング・他操作の有無に依存する。
詳細画面一括編集はデッキ本文（カードリスト）や latest_flg 等を変更しない。詳細画面で見える項目の一部のみが対象。
同時更新楽観ロックは用いない。後勝ちで上書きされる。

権限・認可

利用者状態デッキ検索一覧・一括編集 POST
未ログインまたは管理画面のアクセス拒否管理画面共通の壁で到達できない（詳細は管理画面認証を正とする）。
デッキ管理メニューを利用できる管理者一覧表示と POST が行える実装になっている（ルート単位の細かなロール差分はコア設定を正とする）。

セッション

検索条件・ページ番号はデッキ一覧のセッションキー admin.deck.search 系で保持されるが、一括編集処理本体はそれを書き換えない。フラッシュメッセージはセッションを用いる。

セッションへ保存しない情報

フォームに入力された一括編集の各値を、処理成功後にセッションへ永続化する実装にはなっていない（次回表示は初期空フォーム）。
