M12-03（受注/売上分析 集計一覧表示）

概要

分析・集計メニューの受注/売上分析は、管理者が指定した集計日・使用日付・集計単位・各種絞り込みに従い、注文明細を集計単位ごとに集計し、平均単価・数量・合計・件数とその割合を一覧表で提示する機能である。

本書は実装手順ではなく、誰が・いつ・どの条件で・結果どうなるかを読むためのリバース詳細設計とする。確認値はpf-eccube3（EC-CUBE3系）のHareruyaEcプラグインの受注/売上分析処理、注文明細の集計用リポジトリ、検索フォーム種別、一覧テンプレートを正とする。本機能のカスタマイズ区分はカスタマイズであり、挙動は現行リポpf-eccube3を参照し、DB関連の記述はec-cube-enterpriseを正とする。現行と移行先でテーブル名・列の所在が異なる箇所は「リニューアル移行時の扱い」に集約する。

対象はブラウザ経由の管理画面に限定する。本文ではフレームワークのコントローラ型名やメソッド名を主説明としない。管理画面プレフィックスは環境により変わる（admin_route）。「利用者視点の入口」にHTTPメソッドとサイトルートからのパスパターンを書く。

CSVダウンロードはM12-04で扱う。本書は集計一覧の表示までを扱う。

本書で扱うこと

  • 受注/売上分析の初期表示時に設定される検索条件の既定値
  • 検索条件（集計日・使用日付・集計単位・各種絞り込み）の指定による集計結果一覧の表示
  • 集計の対象データ・結合・除外条件・集計単位・期間の取り扱い
  • 一覧に表示する列と割合・合計行の算出

本書で扱わないこと

以下は本書では仕様確定せず、実装または別機能の設計を正とする。

  • 集計結果のCSVダウンロード（M12-04を正とする）
  • 日次/月次集計、入荷通知依頼、フォーマット売上分析の各集計（M12-01・M12-02・M12-05〜M12-08を正とする）
  • 管理画面へのアクセス制御・ログイン・権限設定の詳細
  • 受注・会員・商品の各台帳の更新業務（各機能を正とする）

リニューアル移行時の扱い

挙動は現行リポpf-eccube3を正とし、DB関連はec-cube-enterpriseを正とする。現行（pf-eccube3）と移行先（ec-cube-enterprise）でスキーマが異なる箇所を記録する。

観点現行（pf-eccube3）移行先（ec-cube-enterprise）
注文明細テーブルdtb_order_detaildtb_order_item（列 price・quantity・product_code・product_name は同名）
使用日付の日付列注文日・入金日は dtb_order（order_date・payment_date）、注文確定日・出荷日・売上確定日・キャンセル日は補助表 dtb_order_sub の各日付列dtb_order に集約。order_date・payment_date に加え confirm_date・shipping_date・commit_date・cancel_date 等の日付列を直接保持する。補助表 dtb_order_sub は移行先に存在しない。各使用日付と移行先列の正確な対応は ec-cube-enterprise 実装で要確認。
誕生日の絞り込みdtb_order.birthdtb_order.birth（同名）
都道府県・性別会員の都道府県・性別dtb_order.pref_id・dtb_order.sex_id 等。集計時の参照元の正確な対応は ec-cube-enterprise 実装で要確認。

DB列に言及する箇所は移行先（ec-cube-enterprise）の名称を主とし、現行名を括弧で添える。移行先に該当が見当たらない箇所は推測でスキーマ化せず「ec-cube-enterprise 実装で要確認」と残す。

処理フロー

検索画面初期表示（/{admin_route}/analysis/sales）

  1. 管理画面の認証・権限を通過する。
  2. 検索条件セッションを破棄する。
  3. 集計日Fromに当月初日、集計日Toに当月末日、使用日付に注文日、集計単位に商品、並び順に昇順を設定する。
  4. 検索フォームを表示する。集計結果は無しとする。

集計実行・一覧表示（/{admin_route}/analysis/sales/result）

  1. 検索フォームへ送信値を取り込む。
  2. 検索条件を検索条件セッションへ保存する。
  3. 注文明細の集計用リポジトリへ検索条件を渡し、集計結果と合計を取得する。
  4. 集計結果一覧と合計行、割合を同一画面に表示する。
