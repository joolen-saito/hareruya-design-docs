m03-34_admin_product_product_discount_csv_import（管理画面_商品管理_割引率変更CSV登録）

処理フロー

画面を表示する（GET m03-34_admin_product_product_discount_csv_import）

  1. 管理画面の認証・共通制約を通過する。
  2. 共通フォーム種別 admin_csv_import でフォームを生成する（ファイル項目と CSRF のみ）。
  3. 割引率変更用のヘッダー連想配列（「商品ID」「割引率(ID)」および説明）を組み立てる。
  4. ソフトデリート管理者向けフィルタ解除のうえ、CSV 種別 ID が割引率変更（定数値 10）に一致する履歴を作成日時降順で最大 100 件取得し、テンプレートへ渡す。
  5. レスポンス本文として割引率用の子 Twig を描画する。

CSV を取り込む（POST admin_product_discount_csv_upload）

  1. 管理画面の認証を通過する。
  2. set_time_limit(0) で PHP の実行時間制限を無効にする。
  3. フォームを handleRequest し、共通のバリデーションヘルパで妥当性を検証する。失敗時はフォームエラーをフラッシュに積み、GET 時と同様の描画で終了する。
  4. アップロードファイルを取り出す。フォーム妥当性の範囲外で null になる経路は在庫 CSV 等と違い明示チェックしないが、フォームのファイル項目は必須制約付きである。
  5. アップロードファイルに対し、引用符で囲まれたフィールドを除いたうえで改行を数え、行数が定数 5010 以上なら件数超過メッセージをフラッシュに積み、再描画で終了する（ヘッダ行を含むカウント方式である）。
  6. 情報ログに「割引率変更CSV登録開始」を記録する。
  7. CsvImporter に割引率用ハンドラを渡して import を実行する（詳細は次節および「業務ルール」）。
  8. 戻り値にエラー配列があるとき、情報ログに「割引率変更CSV登録 異常終了」を記録する。
  9. エラーが無いとき、フラッシュ成功（翻訳キー admin.product.csv_import.save.complete）、情報ログに完了と取込件数、履歴テーブルへファイル名と種別とログイン管理者を記録する。
  10. 取込結果のメッセージ配列をテンプレートの errors として渡し、同一 URL の画面を再描画する（リダイレクトしない）。

雛形をダウンロードする（GET admin_product_csv_template、type=discount）

  1. set_time_limit(0) を実行する。
  2. 割引率変更用ヘッダー連想配列からキー名のみを 1 行として fputcsv 相当で出力する。区切り文字は設定 csv_export_separator。先頭に UTF-8 の BOM バイト列を書く。
  3. Content-Type は application/octet-stream、Content-Disposition は product_discount.csv を添付指定する。

割引率変更 CSV 取込時の判定順序

順序判定結果
1フォーム（CSRF・必須ファイル・MIME・サイズ上限）失敗時はフラッシュエラーで同画面再描画。
2行数が 5010 行以上か（改行カウント方式）該当時はフラッシュエラーで同画面再描画。
3一時ファイル作成・ヘッダ行・データ行有無失敗時は取込結果エラー配列で再描画（フラッシュ成功なし）。
4各行で列数が 2 かつヘッダ名の列が存在するか失敗時はメッセージを蓄積しループ打ち切り後ロールバック。
5商品 ID・割引率 ID の形式とマスタ存在失敗時は同上。
6商品本体が未削除で存在するか失敗時は同上。
7商品サブ行の取得と更新 SQLサブ行が無いなど取得失敗時は別機能の例外として取込前段で失敗しうる（実装を確認値とする）。

業務ロジック

業務ルール・計算

項目内容
更新単位CSV の 1 データ行が 1 商品 ID に対応。規格単位の分割はない。
上書き範囲移行先 ec-cube-enterprise では dtb_product.discount_id（現行 pf-eccube3 は dtb_product_sub.discount_id）のみ。他列は既存値を維持するために UPDATE 文へそのまま渡す。
同一商品の複数行同一ファイル内で同じ商品 ID が複数回出た場合、トランザクション内で順に上書きされ、最終行の値が残る。支店通知の ID 一覧は重複除去される。
価格再計算本ハンドラは価格列を更新しない。

エッジケース

ケース扱い
ヘッダ列名の順序が違う行の連想配列はヘッダ名で解決するため、列順の厳密一致は不要だが、必須列名「商品ID」「割引率(ID)」が欠けると列存在エラーとなる。
商品はあるがサブ行が無い更新処理が既存サブ行に依存するため、実行時例外になりうる。商品存在チェックだけでは防げない。
取込エラーと成功フラッシュ取込エラー時は成功用フラッシュを積まず、errors で画面表示する。

データ整合性

観点内容
