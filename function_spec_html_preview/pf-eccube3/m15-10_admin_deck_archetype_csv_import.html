m15-10_admin_deck_archetype_csv_import（デッキ管理 — アーキタイプ登録 CSV / TSV 取込）

概要

管理画面サイドバーの「デッキ管理」配下にあるアーキタイプ一覧から辿れる「CSV インポート」画面で、アップロードした CSV / TSV の各行に基づき dtb_archetype と関連テーブルを新規作成またはキー同一の既存行を更新する機能である。

本書は実装手順ではなく、誰が・いつ・どの条件で・結果どうなるかを読むためのリバース詳細設計とする。

対象はブラウザ経由の管理画面に限定する。カスタマイズ区分は「カスタマイズ」。画面・挙動は pf-eccube3 上の HareruyaEc プラグインのソースを確認値とし、DB関連（テーブル・列・型・制約・関連）は ec-cube-enterprise の実装を正とする。

ルート処理の名前は本文の主題としない。本文ではルートbind名やSymfonyのルートnameの網羅は主説明としない。「利用者視点の入口」にHTTPメソッドとサイトルートからのパスパターンを書く。コード探索でbind名が必要なときだけ「調査補助」へ書く。

リニューアル移行時の扱い

  • DB関連は移行先 ec-cube-enterprise を正とする。アーキタイプ dtb_archetype は両リポに存在するが、主キー列名が異なる。現行 pf-eccube3 は archetype_id、移行先 ec-cube-enterprise は id である。中間テーブル dtb_archetype_color・dtb_archetype_deck_tag・dtb_article_archetype の結合列名はいずれも archetype_id で一致する。
  • 色・デッキタグ・記事の多対多関連は、両リポとも dtb_archetype_color・dtb_archetype_deck_tag・dtb_article_archetype の結合表で表す。色は dtb_archetype_color（archetype_id / color_id）であり、CSV 取込で色を解決して置き換える対象もこの結合表である。
  • 公開状態は両リポとも disp_id（公開状態マスタ参照）で表す。CSV 取込のたびに表示状態へ上書きする副作用は移行先で同等。
  • 解説列 comment_jp / comment_en（最大2048）は、現行 pf-eccube3 では NULL 可、移行先 ec-cube-enterprise では非 NULL という差がある。CSV 取込ではいずれも更新しない。
  • 論理削除は両リポとも deleted_at（NULL 可日時）で表し、CSV 取込では設定しない。旧アーキタイプ ID は両リポとも old_archetype_id（最大16）。
  • 画面・挙動は現行（pf-eccube3）の確認値。MTG 固有マスタの参照（mtb_format・mtb_color）も移行先 ec-cube-enterprise に存在する。

処理フロー

アップロード画面の表示（GET）

  1. 名前 admin_csv_import のフォームビルダで空フォームを生成し、リクエストをマージしても入力は増えない。
  2. Twig にフォームビューと、コントローラ内で定義したヘッダ連想配列を渡して描画する。

送信と取込（POST）

  1. 取込用サービスに、Twig パス、archetype という名前のセッション区分子、ヘッダ定義連想配列、必須データ列だけを抜いた必須ヘッダ定義を渡して生成する。
  2. admin_csv_import フォームを handleRequest し、checkFormValid で検証する。Symfony のフォームが無効の場合は各エラー文言をフラッシュ種別エラーへ積み、取込サービスの render を返す。この経路でも CSRF 検証およびトークン更新が走る。
  3. 送信ファイルを取り出し、処理開始ログ「アーキタイプCSV登録開始」を出す。
  4. getImportData が、一時ディレクトリへランダム名で保存後、プラットフォームと PHP バージョンに応じて文字コード正規化、改行正規化、ゼロ幅文字・ BOM 削除を行う。拡張子が tsv のときタブ、その他 CSV のとき csv_import_delimiter（既定はカンマ）と csv_import_enclosure（既定は二重引用）で CsvImportService にパースさせる。
  5. パース結果が失敗すると render が呼ばれ、取込 GET へリダイレクトされる（フラッシュ処理は親が積んだものに依存）。
  6. 成功時、checkHeaderValues で「期待する論理ヘッダ配列」とファイル第 1 行の並びが一致するか検査する。「任意列」リストは空であり、すべての定義列がファイル上に同じ順で存在する必要がある。
  7. checkDataSize でデータ行が 1 行以上あることを確認する。
  8. ORM の SQL ロガーをオフにし、トランザクション開始する。
  9. register 内でデータ行ごとに列数一致、必須 3 項目の空白判定、フォーマット英名でのマスタ解決、その後 UPSERT と関連更新を実行する。
  10. 途中で論理または実行時例外になったときはロールバックし、ログにメッセージを載せ、フラッシュエラーへ例外メッセージをそのまま積んだうえで render が返される。
  11. 完全成功時は「アーキタイプCSV登録完了」ログ、成功フラッシュ（文言キー admin.register.complete）、render による取込 GET へリダイレクトとなる。

アーキタイプ登録 CSV 処理時の判定順序

順序判定結果
1アップロードフォームおよび CSRF無効ならフラッシュのみでレスポンス、その場で処理を打ち切る
2ファイルサイズ・アップロード妥当性・MIME は Symfony 制約失敗ならフラッシュのみで終了
3パース成否（ヘッダ行番号初期化）失敗時はサービス側 render のみが返される
4第 1 行が期待ヘッダ配列と並び順も含め完全一致逸脱時はヘッダ形式エラー（メッセージキー admin.csv.error.format.header。翻訳有無は表示層依存）で例外終了しロールバック
5データ行件数が 1 以上0 件のみならデータ空エラーで例外終了
6各行の列数がヘッダ列数と一致不一致なら行番号付き体裁エラー
7必須 3 列（日本語名・英語名・フォーマット）が空文字でないこと違反ならメッセージキー経由で行番号付き必須エラー
8フォーマット列が findOneByNameEn で解決可能解決できなければマスタ未定義として行番号付き実行時例外
9既存検索：nameJp、nameEn、format、deleted_at が nullヒットしない場合は新規エンティティを生成して永続キューへ入れる
10代表カード名列が PHP の empty で偽になる場合のみ画像解決へ進む英名ヒットしない場合でも例外にはせず、画像参照だけ null 側へ変わり得る
11「色」列からカンマを除いた結果が空でないときのみ、explode(',', ...) と重複削除後、color リポジトリの findByNameJp へ渡す解決結果が論理偽になると未定義データとして実行時例外
12100 の倍数行および最後で flush、ループ終了後に commit、キャッシュクリアすべて成功するとトランザクション確定

業務ルール・計算

本機能での「計算」とは読み込み済みデータの検証およびマスタ解決のみであり、画面上の売上計算などの業務計算は行わない。

項目内容
UPSERT のキー日本語名・英語名・フォーマット・論理削除でないことを条件に検索した 1 行を更新単位とする。該当しなければ新規となる。論理削除済みとの突き合わせは行わず、名前とフォーマットが同じ削除済み行があれば別 PK の新規行が作られ得る。
表示区分CSV 処理のたびに「表示」を表す値（dtb_archetype の disp、コア側表示区分マスタにおける整数定数 DISPLAY_SHOW と一致する参照へ）へ上書きする。
旧アーキタイプ IDセルをそのまま setOldArchetypeId に渡す。桁数チェックなど CSV 専用検証は入っていない。画面フォームとは別経路であり、画面上の桁上限は適用されない。
説明文などCSV 経路では comment_jp、comment_en、デッキタグ、記事紐付けは更新しない。既存データを上書きしない。
代表画像入力が無いときは画像参照の setter を呼ばないため、既存行では前回状態が残る可能性がある。入力があるとき英名ヒットしない場合でも例外にせず、参照が空になる側に進み得る。
アーキタイプカラー「色」を空またはカンマのみにしたときは setColors を呼ばないため、既存行では色が残り得る。値があるときは日本語彩色名リストで解決し、コレクションを丸ごと置き換える。

入力項目

項目名必須／任意最大長初期値保存先・扱い
CSV, TSVファイル選択必須アップロード上限は環境により csv_size（メガバイト単位、コア既定 5）、Symfony File 制約。MIME は CsvMimeType により text/plain、text/csv、text/tab-separated-values、application/vnd.ms-excel のいずれか（なし）一時パスへ移動されたうえで CsvImportService に渡され、処理後の render で一時ファイルは削除試行される。フォーム項目型は admin_csv_import の import_file。

画面ラベルは「CSV, TSVファイル選択」。MIME は実装上許可されている集合を列挙したものであり、許可セットの増減はプラグイン内のアップロード MIME チェック実装およびバリデータ登録側を参照する。

アップロードファイル内の列（第 1 行ヘッダの文言と順序）

以下の並び順がソース上固定されており、ファイル第 1 行はこの並びとの完全一致になる。並び換えのみをしたファイルはヘッダ形式エラーとなる。

順序（1 から）第 1 行に書くヘッダ文字列データ側のルール概要
1アーキタイプ名（日本語）値は必須。UPSERT のキーの一部。
2アーキタイプ名（英語）値は必須。同上。
3代表カード名任意。与えられるとカード英名により最適な表面画像へ解決される。未定義でも行は処理され得る。
4色任意。カンマ区切りの日本語彩色名を列挙。カンマ以外が空だけなら色は更新しない。そうでなければ一覧がすべて mtb_color に存在する必要がある。
5フォーマット値は必須。フォーマットマスタの英名による解決。
6旧アーキタイプID任意。ヘッダは欠かせず、データセルを空にもできる。セット時も桁や形式の個別チェックは CSV 側にない。

エッジケース

ケース扱い
ヘッダ行は正しいが列の順のみ入れ替わっている文字列完全一致のためヘッダ形式エラーとなる。
代表カード名に存在しないカード英名を入れる例外にはせず、画像参照のみ null 側となり得る。
同一 CSV 内に同一 UPSERT キーの行が複数行ごとに flush されていくため後勝ちとなり、その時点での任意列入力の有無で画像・色情報が段落ちする可能性がある。
プラグイン無効やルート未登録で admin_route 配下に到達しないHTTP 側のふるまいは共通セキュリティ設定に依存し、本書では確定しない。

データ整合性

観点内容
一覧との一致UPSERT と同一トランザクションで一覧 API が読むときは一覧・詳細側と一致する。この画面はコミット後に GET だけを返すので、フラッシュ間に別タブ一覧を開いた場合でも通常は確定済みデータを読む。
削除済みとの関係論理削除済み行との名前重複検出はしない。名前が同じ新規または別状態の複数レコードがあり得る。
CSV と画面編集との混在同一レコードについて画面で変更した項目（説明など）も CSV は触れないので保持される一方、表示区分は CSV が毎回上書きする。

DB操作

永続化の正は ec-cube-enterprise（テーブル名・操作は ec-cube-enterprise を正典）。当ドメインは承認ワークフローを介さず persist/flush で直接確定する（承認ワークフローは在庫機能固有）。

操作種別対象テーブル契機・条件
登録/更新dtb_archetype / dtb_archetype_color / mtb_color / mtb_format当機能が行う登録・更新で対象テーブルを直接保存する（不要な削除は含まない）。確定は persist/flush による即時反映。DB=ec-cube-enterprise を正典とする。

バリデーション

項目内容
ファイルNotBlank、サイズ、CsvMimeType、アップロード妥当性チェックがある。
CSV 構造ヘッダ完全一致、データ行ごとの列数一致、データ行最低 1 行。
必須フィールド値「アーキタイプ名（日本語・英語）」「フォーマット」は値が空文字になると各行で拒否。その他ヘッダ列についてはヘッダ行の欠落のみが検証対象。
参照整合フォーマット英名および色の日本語名はマスタ必須。代表カード名は未定義でも通過し得る。

権限・認可

管理画面共通の認証に通過した運用ユーザーのみ /{admin_route}/ にマウントされたルートに到達できる前提とする。この画面にだけ追加で付く認可フラグやロールでの分離はプラグイン内で個別設定されておらず、ソース上は管理グループ共通の権限モデルへ委ねられる。

画面遷移

条件遷移先
アップロード処理の完了（成功・失敗のいずれか）HTTP 302 で GET /{admin_route}/archetype/csvimport。
フォームのみ無効・CSRF 失敗経路など render 相当同上またはフレームワークの例外レスポンス。CSRF が不正なときは共通の無効処理へ。

遷移時に引き継ぐ状態

アーキタイプ検索一覧の並び順や結果件数をセッションへ保存する処理は、この取込機能では行わない。検索状態はクエリにもセッションキーにも本画面から載せられない。

エラー処理

エラー内容処理
フォーム入力・CSRF・アップロード制約に違反フラッシュエラー複数および赤枠、render 後の一覧相当画面ではなく取込画面へ戻す。
CSV ヘッダ不一致・データ無し・行欠損実行時例外でロールバックしフラッシュへメッセージ。
フォーマット名や色がマスタに無い翻訳付き実行時例外（行番号入りパターン）でロールバックしフラッシュ表示。

試行制限

本機能ではレートリミットやロックアウトの専用制御は行わない。アップロードサイズは Symfony 制約に依存する。

ログ・監査

タイミング記録内容
送信取込処理の開始時log_info('アーキタイプCSV登録開始')。
取込異常終了時メッセージ文字列のみをログに載せた log_info（コンテキスト配列には例外メッセージ）。致命的度の高いログ API とは別関数にしていないコードパスもある。
すべて成功終了後log_info('アーキタイプCSV登録完了')。

ログに出してはいけないもの

アップロードファイルの業務データ全文をログ出力する処理はソース上読み取れなかったが、共通方針として次を避ける。

  • CSRF の秘匿すべき入力原値そのもののダンプ（トークンの一部マスクは共通基盤の責務）
  • アップロードファイルのサーバ側一時ファイル絶対パスを開発者ログ以外に転送しない運用であること

セッション

本機能におけるセッション

コンストラクタに渡される sessionKey = 'archetype' は、取込サービス側に保持されるのみで、この取込機能のソース断片では一覧検索状態の読み書きを行わない（利用はエクスポート系や別機能に委ねる実装になり得る）。

セッションへ保存しない情報
