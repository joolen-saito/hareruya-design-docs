M04-19（欠品履歴検索/一覧）

受注時に在庫不足で計上できなかった欠品の履歴を、日付帯で検索して一覧表示する画面。

概要

欠品履歴検索/一覧は、受注処理などで在庫が不足し欠品となった記録を、登録日の日付帯で検索して一覧表示する機能である。検索条件・表示件数・ソート条件はセッションに保持し、ページ送り後も同一条件で再検索する。一覧の各行は商品規格編集画面・受注編集画面へのリンクを持つ。

本書は実装手順ではなく、誰が・いつ・どの条件で・結果どうなるかを読むためのリバース詳細設計とする。HareruyaEc プラグインの実装と、検索一覧を駆動する共通処理（SearchControllerTrait）を確認値とする。

本機能のカスタマイズ区分はカスタマイズである。画面・処理の挙動は現行リポ（pf-eccube3 の HareruyaEc プラグイン）を参照し、DB関連（永続化先のテーブル名・列名・制約）は ec-cube-enterprise を正とする。現行と移行先でスキーマが異なる箇所は「リニューアル移行時の扱い」に集約する。

対象はブラウザ経由の管理画面に限定する。管理画面プレフィックスは HareruyaEc プラグインの設定キー admin_route で決まるため、本書では %eccube_admin_route% で示す。

本書の本文ではコントローラのメソッド名は主題としない。ルート bind 名は調査補助へ退避する。

本書で扱うこと

  • 欠品履歴一覧を開く入口と、検索フォーム送信・ページ送りの挙動
  • 日付帯（開始・終了）の指定と保持、登録日での絞り込み
  • 一覧の列構成と件数表示、各行から規格編集・受注編集への遷移
  • 検索条件・表示件数・ソート条件のセッション保持キー

本書で扱わないこと

以下は本書では仕様確定せず、実装または別機能の設計を正とする。

  • 欠品履歴のCSV出力（本機能には存在しない。後述の「本書で扱わないこと」末尾参照）
  • 欠品履歴の生成（受注処理で在庫不足が起きたときの記録）
  • 規格編集画面・受注編集画面の仕様（各機能を正とする）
  • 管理画面の認証・ログイン・権限マスタの詳細

本機能には欠品履歴のCSV出力ルート・エクスポート処理が存在しない。CSV出力が必要な場合は別機能の追加実装を要する。

リニューアル移行時の扱い

DB関連は ec-cube-enterprise を正とする。現行（pf-eccube3 の HareruyaEc プラグイン）と移行先（ec-cube-enterprise）でスキーマ・仕様が異なる主な点を記録する。確認できない点は推測せず要確認として残す。

処理フロー

欠品履歴一覧を開く（初期表示）

  1. 利用者が欠品履歴一覧を開く。
  2. 検索条件・ページ番号・表示件数のセッションを消去する。
  3. 検索フォームを空で初期化し、一覧は空で画面を表示する。

検索する・ページ送りする

  1. 「検索する」または件数変更・ページ送りで検索ルートへ届く。
  2. リクエストの並び順が想定外（ASC・DESC 以外）のときは並び順エラーを表示して初期表示へ戻す。
  3. 表示件数はリクエスト値がページマスタに存在すればセッションへ保存し、無ければセッションまたは既定件数を使う。
  4. 検索条件はフォーム値、無ければセッション値を復元して用いる。
  5. 欠品履歴の検索用クエリと件数を組み立て、ページネーションで一覧を作る。
  6. 検索条件・ページ番号・表示件数・ソート条件をセッションへ保存する。
  7. 一覧を画面へ渡して表示する。

集計条件

指標集計の要点
一覧の件数欠品履歴に検索条件を適用した件数。共通処理が件数取得経路で数える。
一覧の対象欠品履歴を、規格・規格拡張・商品・言語・状態・操作者・受注補助へ結合して並べる。

業務ルール・計算

項目内容
