M13-01（イベント一覧検索）

管理画面「イベント管理」のイベント一覧で、登録済みのイベントをイベント名・開催日・会場・フォーマット・ルール適用度の条件で検索し、該当イベントを一覧表示する機能である。

概要

イベント一覧検索は、管理者が登録済みのイベントを絞り込み、一覧から編集・削除・新規登録へ進むための入口となる機能である。検索条件・表示件数・ソート条件はセッションに保持し、ページ送りや再表示で復元する。

本書は実装手順ではなく、誰が・いつ・どの条件で・結果どうなるかを読むためのリバース詳細設計とする。既存実装のふるまい、参照するデータ、検索条件の保持、ページング、ソートの挙動を確認し、仕様の確からしさを把握することを目的とする。

カスタマイズ区分はカスタマイズであり、挙動の参照リポはpf-eccube3、DB関連の記述はec-cube-enterpriseを正とする。

対象はブラウザ経由の管理画面イベント一覧である。本機能は晴れる屋向けプラグインで提供され、EC-CUBE3系のSilexアプリケーション上で動作する。管理画面プレフィックスはアプリケーション設定admin_route（$app['config']['admin_route']）で決まり、ルートはこの値を連結して登録される。確認観点はプラグインのルート登録（イベント用サービスプロバイダ）とする。

イベントの編集・削除はM13-02、複製新規はM13-05、申込検索はM13-06、デッキ表示はM13-08を正とする。本書ではコントローラのメソッド単位の解剖を主題としない。

本書で扱うこと

  • イベント一覧の初期表示と、検索フォーム送信による絞り込みのふるまい
  • 検索条件（イベント名・開催日From／To・会場・フォーマット・ルール適用度）の判定
  • 表示件数・ソート条件・検索条件・ページ番号のセッション保持と復元
  • ページング、最終ページのデータ消失時の前ページ表示
  • 一覧から編集・削除・新規登録への導線（入口としての役割に限る）

本書で扱わないこと

以下は本書では仕様確定せず、実装または別機能の設計を正とする。

  • イベントの編集・削除・複製新規の業務ルール（M13-02、M13-05を正とする）
  • イベント申込の検索・一覧（M13-06を正とする）
  • 日程登録・繰返し日程登録の入力ルール
  • 管理画面へのアクセス制御、ログイン、権限設定の詳細
  • 検索パターンの保存・呼び出し（本一覧フォームでは画面に出していない）
  • マスタ（会場・フォーマット・ルール適用度・店舗）の管理画面での編集ルール

リニューアル移行時の扱い

現行（pf-eccube3）と移行先（ec-cube-enterprise）の差を記録する。DB関連はec-cube-enterpriseを正とする。検索・ページング・ソートの挙動は現行（pf-eccube3）を正とする。

用語

用語説明
イベントイベント管理で登録される大会・大会企画の1レコード。テーブルはdtb_event。
イベント詳細1つのイベントにぶら下がる開催日程の1レコード。テーブルはdtb_event_detail。開催日Fromや開催日Toの絞り込みはこの開始日時を参照する。
検索条件セッション表示件数、検索条件、ページ番号、ソートキー、並び順を保持するセッション領域。セッションキー接頭辞はadmin.event。
ルール適用度イベントに紐づくルール適用度マスタ（MtbRel）。検索条件の1つ。
フォーマットイベントに紐づくフォーマットマスタ（MtbFormat）。1イベントに複数紐づき得る。検索条件の1つ。

利用者視点の入口

入口URLエンドポイント期待されるふるまい
イベント一覧を開くGET /%admin_route%/event/list検索フォームを表示し、検索条件セッションを初期化する。一覧結果は表示しない。
検索フォームを送信POST /%admin_route%/event/search/{page_no}検索条件で絞り込み、該当イベントを一覧表示する。条件・表示件数・ソートをセッションに保存する。
ページ送り・表示件数変更・ソート変更GET /%admin_route%/event/page/{page_no}セッションの検索条件を復元し、指定ページ・件数・ソートで再検索して表示する。
新規登録ボタンGET /%admin_route%/event/newイベント登録フォームへ遷移する（M13-02の範囲）。
行の編集リンクGET /%admin_route%/event/{id}/editイベント編集画面へ遷移する（M13-02の範囲）。
行の削除リンクDELETE /%admin_route%/event/{id}/deleteイベント削除を実行する（M13-02の範囲）。

/event/search/{page_no}はGETとPOSTの両方を受け付けるルート（match）として登録される。一覧テンプレートのフォームはPOSTで送信する。

フロント挙動

観点内容
表示要素検索ボックスにイベント名の一行テキスト、開催日From・開催日Toの日付入力、フォーマット・会場・ルール適用度のセレクトを表示する。検索結果がある場合は「検索結果 N件が該当しました」と件数を表示し、イベントID・イベント名（日と英を半角空白区切りで連結）・操作メニューの表を表示する。0件時は「検索条件に該当するデータがありませんでした。」を表示する。
JS挙動select2による会場セレクトの装飾、bootstrap-datetimepickerによる日付入力、検索ボックスの開閉トグル、ソート表示制御のスクリプトを読み込む。件数取得や一覧の非同期差し替えは行わない。
CSS・レイアウト管理画面共通のアコーディオン検索ボックス、表組み、ドロップダウンメニューを用いる。専用CSSはeventlist.css。
モーダル・ポップアップ削除リンクは確認ダイアログ（「このイベント情報を削除してもよろしいですか？」）を経て送信する。検索自体はモーダルを使わない。
入力項目検索フォームの各入力はいずれも任意。開催日Fromは初期表示時に既定値が設定される（後述）。

処理フロー

イベント一覧を初期表示する

  1. 管理者がイベント一覧を開く。
  2. 検索フォームを生成する。フォーム名はadmin_event_list、CSRF保護は無効。
  3. 検索条件セッション（admin.event.search、admin.event.search.page_no、admin.event.search.page_count）を削除する。
  4. ソート参照用にイベントリポジトリをセットする。
  5. 一覧結果を空、ページ番号を1、表示件数を既定（default_page_count）として一覧テンプレートを描画する。検索結果テーブルは描画しない。

検索フォームを送信して絞り込む

  1. 管理者が検索条件を入力し、検索ボタンを押す。
  2. 検索フォームを生成し、リクエストを反映する。
  3. ソートキーを決める。優先順位はリクエストのsort、次にセッションのソートキー、無ければ既定（default）。並び順も同様にリクエストのorder、セッション、既定（DESC）の順で決める。並び順がASC／DESC（大文字小文字可）以外なら並び順エラーを表示し、初期表示へ戻す。
  4. 表示件数を決める。優先はセッション値、無ければ既定。リクエストのpage_countがページ表示件数マスタに存在する値なら採用しセッションへ保存する。
  5. フォームから検索条件を取り出す。検索条件が空でセッションに条件が残っていれば、それを復元して再構築する。条件もセッションも無ければ初期表示へ戻す。
  6. 検索条件にソートキー・並び順を付与し、イベントリポジトリで検索クエリと件数を取得する。
  7. 最終ページのデータ削除等で当該ページに表示対象が無くなった場合（件数が前ページまでの件数と一致する場合）、ページ番号を1つ前に補正する。
  8. ページ番号・検索条件・ソートキー・並び順・表示件数をセッションへ保存する。
  9. ページネーターで該当ページを取得し、一覧テンプレートを描画する。

ページ送り・表示件数変更・ソート変更

  1. ページ送り・表示件数・ソートのリンクは検索処理と同じ処理を呼ぶ。
  2. リクエストにフォーム検索条件が無いため、セッションの検索条件を復元して再検索する。
  3. リクエストのsort・order・page_countがあればそれを優先して反映する。

集計条件

指標集計の要点
検索結果件数検索条件で絞り込んだイベント（dtb_eventのe）の件数。件数取得は同一の検索クエリビルダに対しcount(e)を実行する。イベント詳細・フォーマットを左外部結合するため、開催日条件やフォーマット条件で同一イベントが複数行に展開され得るが、件数はcount(e)で求める。

業務ルール・計算

項目内容
イベント名検索入力値の全角空白を半角化したうえで、半角空白・全角空白・カンマで分割する。分割した各語について、イベント名（日）・イベント名（英）・略称（日）・略称（英）の4列に対する部分一致（前後ワイルドカード）をORで結び、語ごとの条件をANDで結ぶ。
開催日From入力日時以降にイベント詳細の開始日時があるイベントを対象とする（ed.startDate >= From）。
開催日To入力日付に1日加算した日時より前にイベント詳細の開始日時があるイベントを対象とする（ed.startDate < To+1日）。実質、指定日を含む日までを対象とする。
フォーマット指定フォーマットIDがイベントのフォーマットに含まれるイベントを対象とする（フォーマット結合のef.formatIdとの一致）。
ルール適用度指定ルール適用度IDに一致するイベントを対象とする（e.rel）。
会場指定会場に一致するイベントを対象とする（e.venue）。
店舗一覧検索フォームには店舗欄が定義されるが、一覧テンプレートでは表示せず、検索クエリでも条件に用いない。
ソートソートキーはdefault（イベントID）またはeventName（イベント名・日）。並び順はソートキーごとに指定の昇順／降順を適用する。
表示形式件数は整数で表示する。一覧の行はイベントIDとイベント名（日と英を半角空白で連結）で構成する。金額計算・税計算・丸め処理は行わない。

検索フォームの入力項目

項目名必須／任意最大長初期値保存先・扱い
イベント名任意stext_len（確認値50、Lengthの最大に適用）空検索条件キーmulti。永続化しない。イベント名（日）・イベント名（英）・略称（日）・略称（英）への部分一致検索に用いる。
開催日From任意日付（yyyy-MM-dd）現在日時からsearch_form.default_from_term（確認値-3 month）を適用した日検索条件キーstart_date_from。永続化しない。dtb_event_detail.start_dateの下限。
開催日To任意日付（yyyy-MM-dd）空検索条件キーstart_date_to。永続化しない。dtb_event_detail.start_dateの上限（指定日に1日加算した未満）。
フォーマット任意セレクト（単一）未選択検索条件キーformats。永続化しない。フォーマットマスタ（MtbFormat）。dtb_event_format.format_idとの一致。
会場任意セレクト（単一）未選択検索条件キーvenue。永続化しない。会場マスタ（MtbVenue）。dtb_event.venue_idとの一致。
ルール適用度任意セレクト（単一）未選択検索条件キーrel。永続化しない。ルール適用度マスタ（MtbRel）。dtb_event.rel_idとの一致。

最大長の数値はプラグイン設定およびコア設定の確認値を記載する。運用環境で上書きされている場合はその環境の値が正とする。店舗欄（キーshop）はフォーム定義に存在するが一覧画面では表示・利用しない。

エッジケース

ケース扱い
イベント名が空白・カンマのみ分割後の各語が空になり、イベント名条件を追加しない。
開催日FromとToが逆転両条件をANDで適用するため、該当が無ければ0件になる。範囲整合のバリデーションは行わない。
開催日条件があり詳細が無いイベント詳細を左外部結合するが開催日条件は詳細列を参照するため、詳細が無いイベントは開催日条件に一致せず除外される。
並び順に不正値並び順エラーを表示し初期表示へ戻す。
最終ページのデータが削除され表示対象が無くなったページ番号を1つ前に補正して表示する。
該当0件「検索条件に該当するデータがありませんでした。」を表示する。

データ整合性

観点内容
参照時点一覧の件数と行は、検索実行時にデータベースから読み取った値である。表示後にイベントが更新・削除されても表示中の一覧は自動更新しない。
検索条件の保持検索条件・表示件数・ソートキー・並び順・ページ番号はセッションに保存し、ページ送り・再表示で復元する。一覧初期表示（/event/list）ではこれらを削除する。
一覧と編集の整合性一覧の行から編集・削除へ遷移した後の値の正は、遷移先（M13-02）の処理時点のデータとする。
件数と行の整合性件数はcount(e)で求め、表示行はページネーターが取得する。詳細・フォーマットの左外部結合により内部のSQL行は重複し得るが、表示はイベント単位で行う。

API/バッチ結果

本機能ではAPI呼び出し・バッチ実行を扱わない。検索結果の一覧表示のためにデータベースを読み取るのみである。
