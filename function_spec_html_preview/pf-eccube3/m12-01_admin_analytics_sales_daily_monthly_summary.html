M12-01（日別/月別集計 集計一覧表示）

概要

分析・集計メニューの日別集計・月別集計は、管理者が指定した集計タイプ（日次/月次）・集計日範囲・表示項目に従い、注文・明細・会員・来客の各指標を期間単位で集計し、一覧表で提示する機能である。

本書は実装手順ではなく、誰が・いつ・どの条件で・結果どうなるかを読むためのリバース詳細設計とする。本機能のカスタマイズ区分はカスタマイズであり、現行挙動の確認値はpf-eccube3（EC-CUBE3系）のHareruyaEcプラグインの分析・集計（日次/月次集計）処理、集計用リポジトリ、検索フォーム種別、一覧テンプレートを正とする。DB関連の記述は ec-cube-enterprise の実装を正とする。

対象はブラウザ経由の管理画面に限定する。本文ではフレームワークのコントローラ型名やメソッド名を主説明としない。管理画面プレフィックスは環境により変わる（admin_route）。「利用者視点の入口」にHTTPメソッドとサイトルートからのパスパターンを書く。

CSVダウンロードはM12-02で扱う。本書は集計一覧の表示までを扱う。

本書で扱うこと

  • 日次集計・月次集計の初期表示時に設定される検索条件の既定値
  • 検索条件（集計タイプ・集計日・利用端末・表示項目）の指定による集計結果一覧の表示
  • 集計の対象データ・結合・除外条件・集計単位・期間の取り扱い
  • 一覧に表示する列と合計行の算出

本書で扱わないこと

以下は本書では仕様確定せず、実装または別機能の設計を正とする。

  • 集計結果のCSVダウンロード（M12-02を正とする）
  • 受注/売上分析、入荷通知依頼、フォーマット売上分析の各集計（M12-03〜M12-08を正とする）
  • 管理画面へのアクセス制御・ログイン・権限設定の詳細（認証は別設計を正とする）
  • 受注・会員・商品の各台帳の更新業務（各機能を正とする）

リニューアル移行時の扱い

  • 本機能のカスタマイズ区分はカスタマイズであり、現行（pf-eccube3／HareruyaEc プラグイン）の集計挙動を正としつつ、DB関連の記述は ec-cube-enterprise を正とする。
  • 受注の集計対象列のうち、現行は注文明細を dtb_order_detail、受注ステータスを dtb_order.status で参照する。ec-cube-enterprise では注文明細テーブルが dtb_order_item、受注ステータスが dtb_order.order_status_id（受注ステータスマスタへの外部キー）に相当する。本書のDBカラム節は移行先名を主とし、現行名を括弧で添える。
  • 会員の集計対象テーブル dtb_player（登録日 create_date、メールマガジン配信フラグ mail_magazine_flg）は現行・移行先（ec-cube-enterprise）で同一スキーマであり、移行先でもそのまま参照する。
  • 注文日 order_date・顧客 customer_id・利用端末 device_type_id、明細の price・quantity・product_code・product_name は現行・移行先で同名であり、テーブル名のみ上記の差がある。
  • 本集計機能（HareruyaEc の日次/月次集計）自体は現行プラグインのカスタマイズであり、ec-cube-enterprise 側の集計画面・集計ロジックの有無と差は移行設計で確認する。

処理フロー

検索画面初期表示（/{admin_route}/analysis/summary/daily または /monthly）

  1. 管理画面の認証・権限を通過する。
  2. 検索条件セッションを破棄する。
  3. 集計日Fromに当月初日、集計日Toに当月末日を設定する。
  4. URLにdailyを含む場合は集計タイプを日次にする。含まない場合は集計タイプを月次にし、集計日Fromを2か月前へ繰り上げる。
  5. 検索フォームを表示する。集計結果は空とする。

集計実行・一覧表示（/{admin_route}/analysis/summary/result）

  1. 検索フォームへ送信値を取り込む。
  2. 検索条件を検索条件セッションへ保存する。
  3. 選択した表示項目から、画面に出す列の見出しを組み立てる。
  4. 集計用リポジトリへ検索条件と表示項目を渡し、期間単位の集計結果と合計を取得する。
  5. 集計結果一覧と合計行を同一画面に表示する。

集計条件

指標集計の要点
集計単位集計タイプが日次なら注文日を%Y/%m/%d、月次なら%Y/%mでグループ化する。会員数の集計は会員の登録日（create_date）を同じ単位でグループ化する。
期間集計日Fromから集計日Toまで。来客数の基準となる注文の抽出では、集計日Toに23時間59分59秒を加えて当日終端まで含める。
来客数・購買数・購買率注文を集計日範囲で抽出し、期間単位の注文件数（購買数）を数える。来客数は期間・会員単位でまとめた注文者数を数える。購買率は来客数を購買数で割り100倍して小数点以下を切り捨てる。
注文・注文確認・入金・出荷指示・出荷・キャンセル注文と注文明細を結合し、期間単位で件数・金額・平均単価を算出する。注文は全件、その他の指標は対象の注文ステータスに該当する明細のみを件数・金額に算入する。
商品別（明細）注文と注文明細を結合し、商品名・商品コードの絞り込みを加えたうえで、明細の件数・金額・平均単価を期間単位で算出する。
会員数・メールニュース登録数会員（dtb_player）を登録日の期間単位でグループ化し、登録数とメールマガジン登録フラグが立つ件数を数える。
リピート注文数注文回数が2回以上の会員の注文を、期間単位で件数として数える。
利用端末利用端末が指定された場合、来客数・注文・商品別・リピート・来客者数の各副問い合わせに端末IDの絞り込みを加える。

平均単価は金額合計を数量合計で割った値とし、表示時に切り上げる。期間内で集計結果が無い日付・月は、件数等を0で補完して一覧に並べる。

業務ルール・計算

項目内容
件数・金額の算入条件注文確認は受注ステータスが新規受付・入金待ち・保留、入金は決済処理中、出荷指示は出荷準備・ピッキング、出荷は出荷済み・対応済み、キャンセルはキャンセルの各ステータスに属する明細のみを算入する。
平均単価金額合計を数量合計で割る。表示時は切り上げる。
購買率来客数を購買数で割り100倍し、小数点以下を切り捨てる。購買数が0の場合は0とする。
合計行一覧の各列について期間分を合算する。購買率の合計は来客数合計を購買数合計で割り100倍して切り上げる。日付列・購買率列は単純合算の対象外とする。
期間の補完集計結果に存在しない日付・月は、表示項目の各列を0として一覧へ補完する。
商品名・商品コードの絞り込み入力語を空白・カンマで分割し、商品コードまたは商品名の部分一致のいずれかに合致する明細を商品別の集計対象とする。
