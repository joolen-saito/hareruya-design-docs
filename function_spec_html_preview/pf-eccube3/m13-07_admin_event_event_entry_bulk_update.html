イベント管理 — イベント申込一括編集

概要

管理画面で、選択した複数のイベント申込について、申込ステータスを一括で変更する機能である。非同期（XHR）で送信し、選択した各申込のステータスを更新して申込履歴を記録する。結果はJSONで返す。

本書は実装手順ではなく、誰が・いつ・どの条件で・結果どうなるかを読むためのリバース詳細設計とする。確認値はpf-eccube3（EC-CUBE3系）のHareruyaEcプラグインの管理画面イベント申込一括更新処理、一括更新フォーム、イベント申込・申込履歴を扱うリポジトリを正とする。

本機能のカスタマイズ区分は現行踏襲である。挙動の参照リポはpf-eccube3（HareruyaEcプラグイン）の現行実装とし、DB関連（永続化先のテーブル名・列名、DBカラム節、副作用のDB更新）はec-cube-enterpriseを正とする。現行と移行先でスキーマが異なる箇所はリニューアル移行時の扱いに集約する。

対象はブラウザ経由の管理画面に限定する。

本文ではフレームワークのコントローラ型名やメソッド名を主説明としない。管理画面プレフィックスは環境により変わる（admin_route）。「利用者視点の入口」にHTTPメソッドとサイトルートからのパスパターンを書く。

本書で扱うこと

  • 選択した複数のイベント申込の申込ステータス一括変更
  • 非同期送信と結果のJSON応答
  • 申込履歴の記録

本書で扱わないこと

以下は本書では仕様確定せず、実装または別機能の設計を正とする。

  • イベント申込の検索・一覧（イベント申込登録検索を正とする）
  • 申込の個別編集（個別編集機能を正とする）
  • イベント・日程の管理（イベント機能を正とする）

処理フロー

申込を一括編集する（POST /{admin_route}/entry/bulk_update）

  1. 管理画面の認証・権限を通過する。
  2. 非同期リクエストでない場合は失敗メッセージのJSONを返す。
  3. 一括更新フォームを検証する。検証に失敗した場合はエラー内容をJSONで返す。
  4. 指定された申込IDの申込を取得する。
  5. 申込ごとに申込ステータスを指定値へ更新し、申込履歴を記録する。
  6. 変更を確定し、完了メッセージのJSONを返す。
