F03-03（商品詳細検索）

刷新後は実装不要本節は現行実装（pf-eccube3）からのリバースです。次の記述は Excel基本設計により廃止されており、刷新後に実装する必要はありません。

  • 商品詳細検索画面（独立画面） は廃止し、商品一覧上のモーダル（モーダル外またはフッターの詳細検索ボタンで閉じる）へ再編（0303 商品詳細検索）これに伴い実装不要: 独立した詳細検索画面の表示とその画面遷移
  • カードセット（検索条件） は削除（0303 商品詳細検索）

概要

フロントの商品詳細検索は、利用者が商品名・カテゴリ・カードセット・色・レアリティ・カードタイプ・フォーマット・価格帯・フォイル・言語・在庫・マナコスト・サブタイプといった条件を組み合わせて入力し、商品一覧へ検索条件を送る詳細検索フォームの機能である。フォームはGETで商品一覧の検索エンドポイントへ送信し、入力値はクエリ文字列として一覧（F03-01）へ引き渡される。

本書は実装手順ではなく、誰が・いつ・どの条件で・結果どうなるかを読むためのリバース詳細設計とする。確認値はpf-eccube3（EC-CUBE3系）のHareruyaEcプラグインの商品検索フォーム種別（front_product_search）、商品一覧処理、テンプレート（Product/search.twig・Product/product_list_unisearch.twig内の検索フォーム表示）を正とする。本機能のカスタマイズ区分はカスタマイズであり、画面挙動の参照リポはpf-eccube3、DB関連の記述はec-cube-enterpriseを正とする。

対象はブラウザ経由のフロントに限定する。フロントのルートはロケールを先頭に付けた/{_locale}配下に配置される。

本文ではフレームワークのコントローラ型名やメソッド名を主説明としない。本文ではルートbind名の網羅は主説明とせず、「利用者視点の入口」にHTTPメソッドとサイトルートからのパスパターンを書く。コード探索でbind名が必要なときだけ「調査補助」へ書く。

本書で扱うこと

  • 詳細検索フォームの入力項目とその選択肢・初期値
  • フォーム送信先と送信方式（GET）と、検索条件のクエリへの引き渡し
  • 各入力項目が商品の抽出・絞り込みにどう作用するか（一覧側の抽出はF03-01を正とする）
  • 並び順・タグ等の隠しパラメータの引き継ぎ

本書で扱わないこと

以下は本書では仕様確定せず、実装または別機能の設計を正とする。

  • 商品一覧側の抽出・件数・ページング・上限超過（F03-01 を正とする）
  • カテゴリ一覧画面（F03-04 を正とする）
  • ユニサーチ（外部検索API）・ユニサジェスト（入力補助）の内部仕様
  • 商品名・色・レアリティ等のマスタ管理

リニューアル移行時の扱い

本機能は検索フォームの表示と送信のみで、入力値を永続化しない。画面挙動はpf-eccube3を確認値とし、選択肢提示に参照するマスタのスキーマはec-cube-enterpriseを正とする。現行と移行先で次の点を確認する。

処理フロー

フォームを表示する

  1. 検索条件が空のとき、詳細検索フォームと共通要素のみを表示する。
  2. カテゴリの選択肢は、フロント検索で非表示とする親配下を除いて提示する。
  3. カードセットはリリース日の降順、イラストレーター・サブタイプは名称順で選択肢を提示する。

フォームを送信する

  1. 利用者が条件を入力・選択して送信する。
  2. 入力値をクエリ文字列として商品一覧の検索エンドポイントへGETで送る。
  3. 並び順（sort・order）・カードID・タグ・セールフラグがある場合は隠しパラメータとして引き継ぐ。
  4. 一覧側で条件に合致する商品を抽出して表示する（抽出はF03-01を正とする）。
