F06-25（店頭モニターに受注管理から登録した番号札を表示）

概要

店頭の店内モニターに、商品準備が完了した注文の呼び出し番号（番号札）を一覧表示する機能である。モニター画面は一定間隔で注文番号取得APIをポーリングし、ピック完了済みの数字の番号札と、受注管理側で登録したアルファベットの番号札を取得して画面へ並べる。前回より新しい番号が増えたときは呼び出し音を鳴らす。表示枠を超える場合は連続する数字をまとめて整形する。

本書は実装手順ではなく、誰が・いつ・どの条件で・結果どうなるかを読むためのリバース詳細設計とする。確認値はpf-eccube3（EC-CUBE3系）のHareruyaEcプラグインの注文番号表示処理、注文番号表示テンプレート（Waiting/waiting_number.twig）、ポーリング用JS（Block/js/waiting_get_js.twig・モニター用waiting_monitor.js）、注文番号取得処理、番号札を扱うリポジトリを正とする。

本機能のカスタマイズ区分はカスタマイズであり、画面・挙動の参照はpf-eccube3を正とし、永続化（テーブル・列）に関する記述はリニューアル移行先のec-cube-enterpriseを正とする。

対象はブラウザ経由のフロント（店内モニター画面）に限定する。フロントのルートはサイトルート直下に言語別プレフィックス/{_locale}を付けて公開する。

本文ではフレームワークのコントローラ型名やメソッド名を主説明としない。ルートbind名の網羅は主説明とせず、「利用者視点の入口」にHTTPメソッドとサイトルートからのパスパターンを書く。

本書で扱うこと

  • 店内モニター画面の入口とポーリングによる注文番号の取得・表示
  • 表示対象の番号札（数字・アルファベット）の集計条件
  • 表示最大件数を超えた場合の整形と、間の出荷完了番号の補完
  • 新着時の呼び出し音

本書で扱わないこと

以下は本書では仕様確定せず、実装または別機能の設計を正とする。

  • 数字の番号札を採番する受注側の処理（店頭注文の受注時に番号を生成する。受注・購入機能を正とする）
  • アルファベットの番号札を登録・削除する受注管理の管理画面（番号札管理機能を正とする）
  • 受注ステータス（ピック完了・出荷完了等）の遷移そのもの（受注管理機能を正とする）

処理フロー

モニター画面を表示する（GET /{_locale}/waiting_number_1・/waiting_number_2）

  1. 注文番号表示画面を表示する。番号表示枠・音声要素・ポーリング用JSを読み込む。

ポーリングで番号札を取得する（JSが定期実行）

  1. 画面読込時に注文番号取得APIを呼び、その後10秒ごとに呼ぶ。
  2. 取得結果が前回リストより新しい番号を含むなら呼び出し音を鳴らす。
  3. 取得結果を現在リストへ更新する。
  4. 取得結果を表示枠へ流し込み、件数に応じて区画・文字サイズを調整する。
  5. 取得が失敗した場合は表示を変えない。

注文番号取得API（GET /{_locale}/waiting_api/get_waiting）

  1. 受注ステータスがピック完了の数字番号札を取得する。
  2. アルファベットの番号札を全件（ID昇順）取得する。
  3. 数字とアルファベットの合計が表示最大件数を超える場合は、数字番号札のあいだに位置する出荷完了済みの番号も補完して並べる（連続性の確保のため）。
  4. 数字番号札・アルファベット番号札の順に並べた配列をJSONで返す。

業務ルール・計算

アルファベット番号札の対象登録済みのアルファベット番号札を全件（ID昇順）対象とする。

出荷完了の補完数字とアルファベットの合計が上限を超える場合、直前に並べた数字の次番号からピック完了の次番号の手前までがすべて出荷完了なら、その区間の番号も並べる。

新着判定取得結果が前回より長い、または前回に含まれない要素があるとき新着とみなし音を鳴らす。
