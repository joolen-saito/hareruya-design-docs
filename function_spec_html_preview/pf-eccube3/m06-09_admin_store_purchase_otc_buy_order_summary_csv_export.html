m06-09_admin_store_purchase_otc_buy_order_summary_csv_export（管理画面_店頭買取管理_買取集計データCSV出力）

概要

管理画面の「店頭買取管理」配下「買取集計データ」画面で検索を実行したあとに表示される「日別」ブロックから、POSTで要求するストリーム応答として、集計日×部門単位の買取・販売金額を列にしたCSVをダウンロードする機能である。ナビゲーションの表示名は翻訳キー admin.purchase.store.summary で「買取集計データ」となり、画面内の送信ボタンラベルは「CSVダウンロード」である。店頭買取一覧や買取商品履歴のCSV出力とは別ルートであり、列レイアウトは買取集計用サービス内の固定定義である。

本書は実装手順ではなく、誰が・いつ・どの条件で・結果どうなるかを読むためのリバース詳細設計とする。カスタマイズ区分は現行踏襲であり、現行挙動の参照はpf-eccube3（HareruyaEcプラグイン）、DB関連はec-cube-enterpriseを正とする。現行と移行先のスキーマ差は後述の「リニューアル移行時の扱い」にまとめる。

対象はブラウザ経由の管理画面に限定する。

コントローラのメソッド名は本文の主題としない。本文ではルートbind名やSymfonyのルートnameの網羅は主説明としない。「利用者視点の入口」にHTTPメソッドとサイトルートからのパスパターンを書く。コード探索でbind名が必要なときだけ「調査補助」へ書く。

買取集計データCSV出力は現行踏襲機能であり、現行はpf-eccube3のHareruyaEcプラグインに実装される。挙動の参照は現行リポ、DBスキーマと移行後の扱いはec-cube-enterpriseを正とする。現行と移行先で確認できた差は次のとおり。

フロント挙動

観点内容
表示要素「CSVダウンロード」は検索後かつ日別テーブルに少なくとも1行あるときだけ、「日別」見出し横に描画される。本体は引数の無い form method=post と submit ボタンだけである。
JS 挙動資産 otc-buy-order-summary.js で日付入力に日付ピッカー、部門・店舗にselect2を付与する。CSV押下にクライアント側の追加検証は無い。
CSS・レイアウト本CSV専用の追加スタイルはない。
モーダル・ポップアップ出力前の確認ダイアログはない。

処理フロー

検索してセッションに条件を置く（POST admin_otcbuyorder_summary_search）

  1. 管理画面の認証・共通制約を通過する。
  2. 検索フォームを受け取り、未送信または無効なら結果なしのテンプレートを返し、セッションキーは更新しない。
  3. 有効ならフォーム実装付属のユーティリティで、送信内容を再表示用のネストした配列に落とし、セッションキー eccube.admin.otcbuyorder_summary.search に保存する。
  4. 同一検索データで、期間全体の部門別集計と、日別集計の2系統をリポジトリから取得し、テンプレートへ渡す。

CSVをダウンロードする（POST admin_otcbuyorder_summary_export）

  1. 管理画面の認証・共通制約を通過する。
  2. PHPの実行時間制限を解除する（実装では制限0秒相当の呼び出し）。
  3. セッションから eccube.admin.otcbuyorder_summary.search を読む。無ければ管理向けエラーフラッシュに固定和文「検索条件がありません。先に検索を実行してください。」を積み、admin_otcbuyorder_summary へリダイレクトする。
  4. 空の検索フォームにセッション値を再適用し、型どおりに正規化された検索データ配列を得る。
  5. 買取集計CSVエクスポートサービスに検索データを渡し、返却されたストリーミング形式のHTTP応答をそのまま返す。

ストリームコールバック内（エクスポートサービス）

  1. 共通CSV出力サービスで標準出力へのハンドルを開く。設定 eccube_csv_export_encoding が UTF-8 のとき先頭にBOMを書き込む。
  2. ヘッダ行を1行書く。列順はコード内の固定定義で並べた日本語ラベル（集計日、部門コード、部門、買取金額、販売金額）である。
  3. リポジトリの日別検索用クエリビルダから結果を取得し、行ごとに連想配列へ整形する。集計日は Y/m/d 形式の文字列、部門名欠落時は 未設定 文字列、金額は整数（欠損は0）である。
  4. 各行をヘッダと同じキー順に文字列化し、設定の区切り文字・引用符・エスケープに従ってCSVの1行として書き出す。セル値は設定 eccube_csv_export_encoding に合わせて変換される。
  5. ハンドルを閉じる。
  6. 応答組み立て時点で情報ログに「買取集計CSV出力完了」とファイル名接頭辞を残す。

出力列とデータの対応

ヘッダ1行目の並びは次のとおり。2行目以降は日別×部門の集計行ごとに1行である。

列名（ヘッダ）内容
集計日グループ化した summary_date。Y/m/d の文字列。
部門コード結合した部門の code。結合欠落時は空文字に近い値。
部門結合した部門の name。欠落時は 未設定。
買取金額グループ内 buy_price の合計。整数。欠損は0扱い。
販売金額グループ内 sell_price の合計。整数。欠損は0扱い。

集計条件

画面の日別表とCSVは、同一のクエリビルダ（日付範囲・任意の店舗・任意の部門）を通した結果である。

指標集計の要点
対象テーブルdtb_otc_buy_order_summary（エイリアス otcs）。部門は左外部結合 Section。
期間summary_date_from の日付を Y-m-d 00:00:00、summary_date_to を Y-m-d 23:59:59 として summary_date が両端に収まる行。
店舗絞り込みフォームの店舗が1件以上選ばれているときだけ BaseInfo IN (:shop)。未選択（空配列）のとき店舗条件は付かず、テナント横断で集計テーブルに存在する店舗行すべてが対象となる。
部門絞り込みフォームの部門が1件以上選ばれているときだけ s.id IN (:section)。
グループ化otcs.summaryDate と s.id の組ごとに SUM(buy_price)・SUM(sell_price)。
並び集計日昇順、同一日内は部門コード昇順。
部門なし行左外部結合のため部門が無い行は部門IDがNULLのグループにまとまり、コード・名は空に近い値となる。CSVでは部門名を 未設定 で埋める。

期間全体の「集計」ブロックは、同じ絞り込みのうえ部門IDのみでグループ化し直した別クエリであり、CSVの行とは一致しない（CSVは日別×部門である）。

業務ルール・計算

本機能のCSVは、SQL集計結果をほぼそのまま列に写すのみで、画面専用の丸めや換算は行わない。金額は整数。

データ整合性

観点内容
画面日別表とCSV同一クエリの結果を、画面はエンティティ投影・CSVは配列投影で表示しているため、同一検索条件・同一DB状態なら行内容は対応する。
