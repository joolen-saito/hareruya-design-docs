会員管理 — 配送先一覧表示/編集

概要

管理画面で、会員が追加登録した配送先（お届け先）を一覧表示し、各配送先の編集・削除を行う機能である。編集では住所等の内容と配送先名称を保存する。

本書は実装手順ではなく、誰が・いつ・どの条件で・結果どうなるかを読むためのリバース詳細設計とする。確認値はpf-eccube3（EC-CUBE3系）のHareruyaEcプラグインの管理画面会員配送先処理、配送先フォーム、配送先を扱うリポジトリ、テンプレート（Customer/delivery.twig・delivery_detail.twig）を正とする。

本機能のカスタマイズ区分は現行踏襲であり、挙動はpf-eccube3を参照し、DB関連はec-cube-enterpriseを正とする。

対象はブラウザ経由の管理画面に限定する。

本文ではフレームワークのコントローラ型名やメソッド名を主説明としない。管理画面プレフィックスは環境により変わる（admin_route）。「利用者視点の入口」にHTTPメソッドとサイトルートからのパスパターンを書く。

本書で扱うこと

  • 会員の追加配送先の一覧表示
  • 配送先の編集（住所・配送先名称）
  • 配送先の削除

本書で扱わないこと

以下は本書では仕様確定せず、実装または別機能の設計を正とする。

  • 会員本体の住所編集（会員情報変更を正とする）
  • フロントの配送先登録・変更（配送先登録機能を正とする）

挙動はpf-eccube3を参照し、永続化先の記述はec-cube-enterpriseを正とする。

観点現行（pf-eccube3）移行先（ec-cube-enterprise）
配送先本体配送先（dtb_customer_address）配送先（dtb_customer_address）。同一テーブル名。
配送先名称の保持補助テーブル（dtb_customer_address_sub、列address_name・default_flg）に分離して保持する。配送先（dtb_customer_address）の列address_name（届け先名称、128桁）に統合して保持する。補助テーブルは持たない。

配送先名称の保存先は、現行は補助テーブルに分離しているが、移行先では配送先テーブルの列へ統合される。移行時は補助テーブルのaddress_nameを配送先テーブルのaddress_nameへ移送する点に注意する。

処理フロー

配送先一覧を表示する（GET /{admin_route}/customer/{id}/delivery）

  1. 管理画面の認証・権限を通過する。
  2. 当該会員の追加配送先を一覧表示する。

配送先を編集する（GET/POST /{admin_route}/customer/delivery/{id}/update）

  1. 管理画面の認証・権限を通過する。
  2. 配送先IDが無い、または該当配送先が無い場合はページが見つからない扱い（404）とする。
  3. 配送先フォームを生成する。
  4. 送信され検証に通り、郵便番号の整合確認を満たす場合、配送先名称があれば配送先名称を保存し、内容を確定して成功メッセージを表示する。
  5. 配送先の編集画面を表示する。

配送先を削除する（DELETE /{admin_route}/customer/delivery/{id}/delete）

  1. 管理画面の認証・権限を通過する。
  2. 当該配送先を削除する。

データ整合性

観点内容
参照時点画面表示またはCSV・帳票出力の実行時点で検索条件に一致するデータを参照する。本機能は参照・出力を主とし、業務データを更新しない。
一覧・出力の整合一覧、CSV、帳票に出る値はそれぞれの実行時点のDB値を基準にする。画面表示後に他処理で更新された値は、再検索または再出力するまで反映しない。
同時更新出力中に他処理が対象データを更新した場合のスナップショット保証は持たない。行ロックを取得せず、読み取り時点の値を出力する。
