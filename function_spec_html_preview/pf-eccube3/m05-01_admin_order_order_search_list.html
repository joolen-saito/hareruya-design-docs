支払方法の選択肢は、削除済みでない支払方法から旧・大会専用の 2 件を除き、表示順の降順に並べたものである。

入力値の扱い

文字列の条件は、前後の半角空白・タブ・改行を除いた長さが 0 より大きいときだけ付く。全角スペースは除かないため、全角スペースだけの入力でも条件が付く。

フリーワード 3 欄、配送先のお名前・フリガナ・電話番号・郵便番号、店頭注文番号は、空文字・数値の 0・文字列の "0" では条件が付かない。購入商品コードと注文番号は "0" でも条件が付く。配送先の都道府県と国・地域、配送方法・顧客グループ・注文備考の有無も、値が空とみなされる場合は条件が付かない。

フリーワード 3 欄と購入商品名の 3 欄は、入力値のワイルドカード文字 % と _ をエスケープして文字そのものとして扱う。それ以外の部分一致条件はエスケープしないため、入力したワイルドカード文字がそのまま働く。エスケープしないのは、注文番号、配送先のお名前・フリガナ・電話番号・郵便番号、注文者のお名前・フリガナ・メールアドレス・電話番号である。

フリーワード欄の実際の検索対象は画面表示と一致しない。画面のプレースホルダは「注文者会社名・注文備考」だが、実際にはショップ用メモと受注明細の商品コードも検索対象になる。

複数条件を同時に指定したときの上書き

一部の条件は値の置き場所を共有しており、同時に指定すると後から設定した値で上書きされる。

同時に指定した条件結果

日付の終了側どうし開始側と同じ。開始側と終了側のあいだでは上書きは起きない

フリーワードの分割と検索

フリーワード 3 欄は、半角空白・全角空白・カンマ・タブなどの連続で語に分割する。各語について対象項目それぞれへの部分一致を OR で束ね、語どうしを AND で積み上げる。空文字と文字列 "0" の語は読み飛ばすため条件にならない。

購入商品名の AND / OR 切替

購入商品名の入力欄は画面に 3 つあり、AND/OR 選択でこの 3 欄の関係を切り替える。

  • OR を選んだとき: 入力済みの各欄について受注明細の商品名への部分一致を OR で束ねる。
  • それ以外のとき: 入力済みの各欄ごとに受注明細を個別に絞り込むため、語どうしは AND になる。

選択肢は「AND検索」と「OR検索」である。

検索の成立条件

  • 検索フォームの検証結果は検索実行の可否に影響しない。検証エラーがあっても、入力された条件のまま検索する。
  • 検索条件を受け取れないときは、セッションに保持した前回の検索条件で検索する。セッションにも無ければ検索しない。

初期表示

一覧の初期表示では、セッションの受注検索条件・受注検索のページ番号・受注検索の表示件数を破棄し、空の検索フォーム・空の一覧・ページ番号 1・既定の表示件数で表示する。受注検索のソートキーと並び順は破棄しない。

保存済み検索条件

保存済み検索条件の特定は ID だけで行い、画面キーを確認しない。受注一覧以外の画面キーを持つ検索条件でも、IDを指定すれば呼び出し・削除・件数取得の対象になる。保存で上書きすると画面キーが受注一覧のものへ変わる。画面キーで絞るのは一覧への列挙だけである。

保存・呼び出し・件数取得のいずれも、フォームの検証結果を処理の可否に使わない。

保存

  • 検索パターン名が未入力または空文字のときは保存しない。
  • 入力された保存済み検索条件IDに一致するものがあればそれを更新し、無ければ新規に作成する。
  • 入力中の検索条件一式と名称を保存し、受注一覧の画面キーを付ける。
  • 保存後は画面遷移せず、保存した条件を適用した一覧を表示する。

削除

  • IDの指定が無い、または該当する保存済み検索条件が存在しないときは削除しない。
  • 存在するときは削除し、一覧の初期表示へ遷移する。

呼び出し

  • 保存済みの条件を検索フォームへ復元し、セッションの受注検索条件にも保存する。
  • ページ番号は常に 1 とする。

計算方法

表示件数の決定

  1. セッションの受注検索の表示件数を用いる。未設定時の既定値は 10 である。
  2. リクエストで指定された表示件数は、表示件数マスタに登録された値のいずれかと一致するときだけ採用し、セッションへ保存する。一致しない値は無視する。

保存済み検索条件の呼び出し時は、リクエストで指定された表示件数を採用しない。

該当件数

保存済み検索条件の該当件数は、明細が複数ある受注を重複して数えるため、実際の受注件数より多くなることがある。配送方法・顧客グループ・購入商品名・配送先の各条件・店頭注文番号を指定すると、重複はさらに増える。同じ保存済み検索条件については最大 10 秒間、前回取得した件数をそのまま返す。

一覧画面に表示する該当件数はこれとは別の算出である。

相対日数条件の算出

「〜日以内」「〜日以上前」の入力から、現在日時を基準に境界日時を計算する。

  • 開始日時: 現在日時から「日以内」の日数を引き、時刻を 00:00:00 に設定する。条件は開始日時以上。
  • 終了日時: 「日以上前」の日数を 1 だけ減じたうえで、現在日時からその日数を引き、時刻を 00:00:00 に設定する。条件は終了日時未満。
  • 「日以上前」が 1 以上のとき、終了日時は現在日時から入力値より 1 少ない日数を引いた日の 0 時になる。画面からは 0 も送れる。その場合と負値の場合のふるまいは正本コードからは確認できない。

相対日数を指定できるのは、注文日・ピック中・出荷日・入金日・出荷指示日・キャンセル日・売上確定日・店頭予約・更新日の 9 項目である。

Excel設計書との乖離

[乖離] を付けた記述は、現行ソースにあって Excel設計書に無いふるまいである。

現行ソースのふるまいExcel設計書の記載
注文日を期間と相対日数で絞り込める注文日の項目が無い
ピック中を期間・相対日数・未入力／入力済で絞り込めるピック中の項目が無い

入出力

出力: 保存済み検索条件の該当件数

保存済み検索条件ごとに、その条件で検索したときの該当件数を返す。該当する保存済み検索条件が無いときは件数を返さない。この経路では検索条件をセッションへ保存しないため、一覧の検索状態は変わらない。

呼び出すのは一覧画面の検索条件欄である。個別の再取得ボタンは非同期で 1 件だけ取り直し、全件更新ボタンは各条件を同期で順に呼ぶ。取得した件数は当該条件の件数表示へ差し込む。

入出力: 永続化

保存済み検索条件は検索パターンテーブルに保持する。項目はID・パターン名・検索パターン・画面キーである。

操作契機
登録・更新検索条件保存
削除検索条件削除

受注側のデータは更新しない。
