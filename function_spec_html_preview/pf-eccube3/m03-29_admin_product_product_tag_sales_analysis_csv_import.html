m03-29_admin_product_product_tag_sales_analysis_csv_import（管理画面_商品管理_売上分析タグ更新CSV登録）

概要

管理画面の「商品管理」→「商品CSV管理」→「売上分析タグ更新CSVアップロード」から開く画面で、dtb_product_tag_sales_analysis に対する商品単位の売上分析タグ紐付けを CSV で一括置換する機能である。CSV は「商品ID」と「売上分析タグ(ID)」（カンマ区切り複数）の 2 列を前提とし、同一ファイル内で同一商品 ID が複数行あるときは末尾行の指定が残る。

本書は実装手順ではなく、誰が・いつ・どの条件で・結果どうなるかを読むためのリバース詳細設計とする。確認値は EC-CUBE Enterprise の src/Eccube 配下とする。

本機能のカスタマイズ区分は現行踏襲である。現行挙動は pf-eccube3（HareruyaEc プラグイン）を参照し、永続化に関わるテーブル名・列名などのDB関連は ec-cube-enterprise を正とする。

対象はブラウザ経由の管理画面に限定する。

コントローラのメソッド名は本文の主題としない。本文ではルートbind名やSymfonyのルートnameの網羅は主説明としない。「利用者視点の入口」にHTTPメソッドとサイトルートからのパスパターンを書く。コード探索でbind名が必要なときだけ「調査補助」へ書く。

リニューアル移行時の扱い

DB関連の記述は ec-cube-enterprise の実装を正とする。売上分析タグの置換対象テーブル・列は現行（pf-eccube3 の HareruyaEc プラグイン）と移行先（ec-cube-enterprise）で同一スキーマである。

置換（DELETE 後の INSERT）の挙動・検証順序・トランザクション制御は現行（pf-eccube3）を参照し、移行先でも同等の標準実装が ec-cube-enterprise に取り込まれている。

処理フロー

アップロード画面を表示する（GET m03-13_admin_product_product_tag_sales_analysis_csv_upload）

  1. 管理画面の認証・共通制約を通過する。
  2. 管理者向け CSV 取込フォーム種別の空フォームを組み立て、リクエストをバインドする。
  3. クエリ page_count が許容リストに含まれる場合のみセッションキー文字列 admin.product.tag_sales_analysis_csv.page_count に保存する。含まれない場合はセッション値または既定 10 を採用する。
  4. page_no はクエリまたはセッション admin.product.tag_sales_analysis_csv.page_no から決め、セッションへ書き戻す。
  5. 取込種別が売上分析タグ更新 CSV の履歴だけを対象とするクエリビルダをページネーションし、テンプレートへ渡す。

雛形をダウンロードする（GET m03-13_admin_product_product_tag_sales_analysis_csv_template）

  1. 管理画面の認証・共通制約を通過する。
  2. コントローラが返す「列見出し→説明文」の連想配列について、array_keys の並びで 1 行目だけを書いた CSV をストリーミング応答する。ファイル名は product_tag_sales_analysis_template.csv。Content-Type は application/octet-stream。

CSV を取込む（POST m03-13_admin_product_product_tag_sales_analysis_import）

  1. ログイン利用者を取込処理に渡す前提を満たす。
  2. 管理者向け CSV 取込フォーム種別を組み立てて送信をバインドする。妥当でなければフォームエラーをフラッシュに積み、GET m03-13_admin_product_product_tag_sales_analysis_csv_upload へリダイレクトする。
  3. import_file が null なら共通キー admin.common.csv_invalid_format をフラッシュし、同様にリダイレクトする。
  4. アップロードファイル全文から、ダブルクォート内の改行を除いたうえでの改行数を数え、その値が抽象コントローラ定数 ADMIN_CSV_IMPORT_MAX_ROWS（5010）以上なら admin.csv.error.upload.maxrecord をパラメータ付きでフラッシュし、リダイレクトする。
  5. 情報ログに「売上分析タグ更新CSV登録開始」を書く。
  6. 汎用インポータに売上分析タグ更新用ハンドラを渡してファイルを取込む（詳細は次節）。
  7. 返却結果にエラーが 1 件でもあれば情報ログに「売上分析タグ更新CSV登録 異常終了」を書き、各メッセージをエラーフラッシュに積む。
  8. エラーが無ければ成功フラッシュ（キー admin.register.complete）、完了ログ（件数付きキー付きコンテキスト）、取込履歴 INSERT（種別 ID は売上分析タグ更新 CSV 用定数、ファイル名はクライアントオリジナル名、利用者 ID）を行う。
  9. 常に GET m03-13_admin_product_product_tag_sales_analysis_csv_upload へリダイレクトする。

本コントローラはカード商品 CSV 取込などと異なり、取込直前に PHP の実行時間制限を無効化しない。

汎用インポータ内部（確認値）

  1. アップロードファイルを設定の CSV 一時ディレクトリへ移し、逐次読込できるファイルハンドルとして開く。拡張子が tsv のときはタブ区切り、それ以外は設定 eccube_csv_import_delimiter と eccube_csv_import_enclosure を使う（配布値はカンマと二重引用符）。
  2. 1 行目をヘッダとみなせなければエラー集合を返して終了する。ヘッダのみでデータ行が無ければエラー集合を返して終了する。
  3. DB 接続でトランザクションを開始し、行ロックタイムアウトをハンドラが返す秒数（既定 5）に設定する。
  4. データ行ごとに「列数がハンドラが持つ列定義と一致」「ヘッダ名が各列の名前と対応」「各列の単体検証」「商品が DB に存在するか」を通過させたうえで行処理へ進む。商品が存在しない行ではエラーを記録し全体中断する。
  5. 行処理では売上分析タグ ID 配列を求め、dtb_product_tag_sales_analysis を一旦 DELETE したうえで指定 ID を INSERT する置換を実行する。同一 CSV で同一商品 ID が複数回現れる場合、各回で置換が走り最終行の内容が残る。処理成功件数としてカウントされるのは「その CSV で初めて処理した商品 ID」のみである。
  6. 100 行ごとに flush と clear を挟む（インポータ既定）。
  7. 全行処理後、flush と clear を再度行う。
  8. コミット条件は汎用インポータが「エラー件数が 0」「または処理全体の中断フラグが立っていない」のいずれかを満たすときコミットする式になっている。本ハンドラでは検証エラー時に中断フラグも立てるため、エラーがある通常経路ではロールバックに収束する。
  9. 処理件数・エラー配列・情報配列を結果オブジェクトに載せて返す。

集計条件

本機能では売上集計や一覧件数の算出は行わない。履歴一覧は「CSV 取込種別が売上分析タグ更新」の履歴行を時系列クエリでページングするだけである。

CSV 取込時の判定順序（データ行）

順序判定結果
1ヘッダ行が解釈できるか否なら取込中止（事前検証エラー）。
2ヘッダ直下にデータ行が 1 行以上あるか否なら取込中止（事前検証エラー）。
3データ行の列数が 2 と一致するか否ならエラー記録し全体中断。
4「商品ID」「売上分析タグ(ID)」のセルが列定義どおり検証できるか（商品 ID は必須かつ符号なし整数体系、タグ列は未入力も可、入力時は要素ごとに数値検証とマスタ存在）否ならエラー記録し全体中断。
5商品 ID が dtb_product に存在するか（公開状態による除外なし）否ならエラー記録し全体中断。
6置換 SQL を実行するコミットまでロールバックされなければ反映される。

業務ルール・計算

項目内容
タグの意味CSV で指定された売上分析タグ ID の集合が、その商品について最終的な紐付けになる。タグ列が空または未入力相当のときは紐付けがすべて削除される。
複数値「売上分析タグ(ID)」セルはカンマ区切りの複数整数を許す。検証開始時点でマスタに存在する ID の一覧を読み込み照合する。
同一商品の複数行末尾行の指定が実データとして残る。成功件数はユニークな商品 ID の個数として数える。
マスタ側の削除との競合取込処理の検証で読み込んだ ID 集合と異なる状態への変化が並行して起きた場合の整合は本書では確定しない。実装は検証開始時スナップショットに基づく。

入力項目

項目名必須／任意最大長初期値保存先・扱い
CSVファイル選択必須アップロード上限は設定 eccube_csv_size をメガバイト単位として Symfony のファイル制約に渡す（配布 eccube.yaml の確認値は 5）。サーバ側の upload_max_filesize / post_max_size が実効上限となる場合がある。未選択フォームキー admin_csv_import[import_file]。送信後は一時ディレクトリへ移動され逐次処理される。ページにはラベル無しのファイルウィジェットのみが明示される。

補足: 画面上は項目ラベルがフォーム種別では無効化されているため、利用者にはカード内のファイル入力と送信ボタンとして見える。

エッジケース

ケース扱い
タグ ID に重複を書く置換前に ID 配列を一意化するため、結果として重複は残らない。
タグ列のみ空検証は通り、その商品の紐付けはすべて削除される。
存在しない売上分析タグ IDマスタ不存在エラーとなり全体ロールバック。
存在しない商品 ID商品不存在エラーとなり全体ロールバック。
改行カウントが閾値以上取込処理に入らず、ADMIN_CSV_IMPORT_MAX_ROWS を上限としてエラーフラッシュのみ。

データ整合性

観点内容
一覧との一致取込成功後、商品詳細や一覧検索が参照する売上分析タグは置換結果と一致する（同一トランザクション内でコミットされた場合）。
履歴との関係取込履歴は成功時のみ 1 件追加される。失敗時は履歴を増やさない。履歴のファイル名はアップロード時のオリジナル名。
部分成功実装はファイル単位でコミットまたはロールバックする。途中まで成功した行だけを残す動きにはしない。
