m03-30_admin_product_product_product_price_csv_import（管理画面_商品管理_セール用価格変更CSV登録）

概要

管理画面の「商品管理」配下で、CSV ファイルをアップロードして商品の販売価格・買取価格・セール区分・帯 URL・商品タグを一括更新する機能である。ナビの翻訳キー admin.product.product_price_csv では「セール用価格変更CSVアップロード」と表示される。サーバログでは「セール用価格変更CSV登録」と記録される。一覧から出力する「セール用価格変更CSV出力」とは別ルートであり、取込 CSV の列構成は雛形ダウンロードの 7 列定義を正とする。

本書は実装手順ではなく、誰が・いつ・どの条件で・結果どうなるかを読むためのリバース詳細設計とする。ec-cube-enterprise のコア実装を確認値とする。

本機能のカスタマイズ区分はカスタマイズである。挙動は現行リポ pf-eccube3 の実装を参照し、DB関連の記述（テーブル名・列名・保存先・副作用のDB更新）は ec-cube-enterprise を正とする。価格変更CSV登録は ec-cube-enterprise にも同等実装がある。

対象はブラウザ経由の管理画面に限定する。

コントローラのメソッド名は本文の主題としない。本文ではルートbind名やSymfonyのルートnameの網羅は主説明としない。「利用者視点の入口」にHTTPメソッドとサイトルートからのパスパターンを書く。コード探索でbind名が必要なときだけ「調査補助」へ書く。

リニューアル移行時の扱い

  • 買取価格・セールフラグ・帯URL・高額商品コードの保存先: 現行 pf-eccube3 ではこれらを規格補助テーブル（dtb_product_sub_class）に分けて持つが、移行先 ec-cube-enterprise では規格テーブル dtb_product_class に統合している。本書のDBカラム節・保存先の記述は移行先 dtb_product_class を正とする。
  • 商品タグの紐付け列: 現行 pf-eccube3 は dtb_product_tag の tag 列、移行先 ec-cube-enterprise は dtb_product_tag の tag_id 列で保持する。本書は移行先の tag_id を正とする。
  • 価格履歴・取込履歴: dtb_price_history・dtb_csv_import_history は現行と移行先で同一スキーマである。
  • 取込種別ID: 価格変更取込は ec-cube-enterprise の取込種別マスタで ID 6（PRODUCT_PRICE_IMPORT_CSV_ID）に対応する。

フロント挙動

観点内容
表示要素画面タイトルは「セール用価格変更CSVアップロード」。カード見出しは「セール用価格変更CSV」「セール用価格変更CSVファイルフォーマット」。フォーマット表は列名と説明。必須列にはバッジ表示。取込履歴はファイル名・日時・操作者。履歴のページ件数プルダウンとページネーションがある。
JS 挙動ファイル選択でラベルにファイル名を表示する。フォーム送信時に共通のローディング表示をオンにする。
CSS・レイアウト本機能専用の大きな追加スタイルはなく、custom-file の見た目調整程度である。
モーダル・ポップアップ取込前の確認ダイアログはない。

処理フロー

アップロード画面を開く（GET admin_product_product_price_csv_upload）

  1. 管理画面の認証・共通制約を通過する。
  2. CSV 取込用のフォーム（ファイル項目と CSRF）を生成する。
  3. クエリ page_count とセッションキー admin.product.product_price_csv.page_count でページ件数を解決する。許容値は 10, 50, 100, 300, 500, 1000, 2000, 10000, 12000 のいずれか。不正なら既定 50。
  4. クエリ page_no とセッションキー admin.product.product_price_csv.page_no でページ番号を解決する。
  5. 取込種別 ID が商品価格取込の履歴を日付降順で問い合わせ、指定ページでページングする。
  6. 雛形と同じ列見出し・必須列キー一覧をビューへ渡して描画する。

雛形をダウンロードする（GET admin_product_product_price_csv_template）

  1. 管理画面の認証・共通制約を通過する。
  2. ストリーム応答で CSV を開き、1 行目に次の日本語見出しだけを fputcsv する（データ行は無い）。Content-Type は application/octet-stream。Content-Disposition のファイル名は product_price_template.csv。
  3. 見出しの順序は「商品ID」「言語(ID)」「販売価格」「買取価格」「セールフラグ」「帯URL」「タグ(ID)」である。

取込を実行する（POST admin_product_product_price_import）

  1. 管理画面の認証・共通制約を通過する。
  2. フォームをバインドする。不正なら各エラーを admin フラッシュに積み、アップロード画面へリダイレクトする。
  3. アップロードファイルが null なら admin.common.csv_invalid_format をエラーに積みリダイレクトする。
  4. アップロードファイルの「改行の個数」を概算する（ダブルクォート内の改行は除く）。この値が 5010 以上なら admin.csv.error.upload.maxrecord（埋め込み %maxRecord% は 5010）をエラーに積みリダイレクトする。
  5. 情報ログに「セール用価格変更CSV登録開始」を記録する。
  6. 商品価格取込ハンドラと汎用 CSV インポータを組み立て、インポータにファイルを渡す。
  7. インポータは一時ファイルへ保存し、1 行目をヘッダとして解釈できるか・2 行目以降にデータがあるかを事前検証する。失敗時は結果にエラーを載せ、ファイルを削除して返す。
  8. DB 接続でトランザクションを開始し、行ロック待ちのタイムアウトをハンドラが規定する秒数に設定する（確認値は 5 秒前後の実装定数）。
  9. 各行について、列数がハンドラ定義の列数と一致しない場合はフォーマットエラーとし、処理を打ち切る。
  10. 各行について、必須列の検証、言語 ID のマスタ存在、数値・桁数、セールフラグの 0 または 1、タグ ID の存在などを列バリデータが順に検証する。販売価格列・買取価格列については「買取価格が販売価格を超える」場合にエラーとする（比較対象は CSV に書かれた両列の値）。
  11. 商品 ID が商品マスタに存在しない場合はエラーとし、全件打ち切りになる。
  12. 検証を通過した行では、商品タグを指定 ID 一覧で全置換し、続けて該当商品かつ該当言語かつ高額商品コード NULL の規格行をすべて走査する。
  13. 各規格行について、CSV のセールフラグと DB 上のセール状態の組み合わせに応じて新しい販売価格を決める。買取価格は CSV の値を基に、カード状態や特価区分・買取割引マスタから規格単位に換算する。帯 URL は CSV が空なら NULL、非空ならその文字列を載せる。セールフラグは CSV の値をそのまま永続化する更新配列に載せる。
  14. 規格ごとにリポジトリの一括更新用メソッドで dtb_product_class を更新し、販売・買取・基準価格のいずれかが変わっていれば価格履歴をネイティブ INSERT する（基準価格は本処理では変えないため、新旧は同一値になる）。
  15. スマレジ連携向けコーディネータに、条件を満たす規格を「後で送る」リストへ載せる。
  16. 行カウンタが一定件数ごとに flush と clear が走る（確認値は 100 行ごとの実装）。
  17. 全行処理後に flush と clear を行い、メッセージストアにエラー種のメッセージが無い、または打ち切りが無いときにコミットし、それ以外はロールバックする。実装式は「エラー件数が 0 であるか、打ち切りでないか」の論理和として解釈されるが、メッセージの種類は後述のとおりエラーと注意喚起が同じ経路に載りうる。
  18. ハンドラの後片付けでスマレジコーディネータに取込成否を伝え、コーディネータが完了処理を行う。
  19. 行ロックタイムアウトを元に戻す。一時ファイルを削除する。
  20. 結果にエラー配列がある場合、情報ログに「セール用価格変更CSV登録 異常終了」と記録し、各メッセージを admin フラッシュのエラーとして積む。エラーが無い場合、成功メッセージ admin.register.complete を積み、情報ログに完了と件数を記録し、取込履歴テーブルへファイル名と操作者を挿入する。
  21. いずれの場合も HTTP 302 でアップロード画面ルートへリダイレクトする。

集計条件

本機能では売上集計や件数サマリーは行わない。取込履歴一覧は「当該取込種別の履歴」を日付降順でページング表示するだけである。

セール区分と販売価格の決定順序

同一データ行のうち、その商品・言語に紐付く各規格について、次の順で新販売価格が決まる。買取価格の換算はこのあと規格ごとに必ず行う。

順序条件新しい販売価格
1DB がセール中かつ CSV のセールフラグが無効DB の基準価格を床関数で整数化した値。CSV に販売価格列が埋まっていても、その値は採用されない（同一データ行につき最大 1 回、注意メッセージが付く）。
2DB が通常かつ CSV のセールフラグが無効既存の販売価格を変更しない。同一データ行につき最大 1 回、注意メッセージが付く。
3上記以外（CSV でセール有効、または DB と CSV の両方でセール有効など）CSV の販売価格を床関数で整数化した値。

項目内容
対象規格SQL で product_id と language_id が一致し、high_price_code IS NULL の規格のみ。該当が 0 件でもデータ行は「成功扱い」でカウントされ、商品タグの置換だけが行われうる。

エッジケース

ケース扱い
一覧からダウンロードした「セール用価格変更CSV出力」列数が 7 ではない（基準価格・原価単価などが増える）。取込の列数検証でエラーになり、ロールバックされる。
対象規格が 0 件価格更新ループは回らない。タグ置換は実行されうる。取込成功件数には当該データ行が含まれる。
注意メッセージのみ付き、打ち切りなしトランザクションはコミットされうるが、結果の hasError が真になり、フラッシュはエラー表示中心となり、取込履歴への INSERT は行われない実装である。
ファイル行数改行個数 5010 以上でアップロード拒否（リダイレクト・エラーフラッシュ）。

データ整合性

観点内容
一覧エクスポートとの一致出力 CSV は列が多い。取込雛形と同一レイアウトのファイルでないと取れない。
高額商品コード付き規格本取込では更新対象外。別 CSV 機能の対象と排他的。
同時実行トランザクションと行ロックタイムアウトに依存。競合時はタイムアウト系メッセージが付きうる（汎用 CSV 基盤の挙動に従う）。
