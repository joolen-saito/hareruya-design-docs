会員管理 — 会員登録仮登録完了メール再送

概要

管理画面の会員一覧から、対象会員に対して仮会員登録完了メール（本登録用のアクティベートURLを含む案内）を再送する機能である。会員ごとの再送操作で、当該会員の秘密キーから本登録用URLを生成し、メールを送信する。

本書は実装手順ではなく、誰が・いつ・どの条件で・結果どうなるかを読むためのリバース詳細設計とする。確認値はpf-eccube3（EC-CUBE3系）のHareruyaEcプラグインの管理画面会員処理（仮登録完了メール再送）、メール送信処理、会員を扱うリポジトリを正とする。

本機能のカスタマイズ区分は現行踏襲であり、挙動はpf-eccube3を参照し、DB関連はec-cube-enterpriseを正とする。

対象はブラウザ経由の管理画面に限定する。

本文ではフレームワークのコントローラ型名やメソッド名を主説明としない。管理画面プレフィックスは環境により変わる（admin_route）。「利用者視点の入口」にHTTPメソッドとサイトルートからのパスパターンを書く。

本書で扱うこと

  • 会員一覧からの仮登録完了メール再送操作
  • 本登録用URL（秘密キー付き）の生成と送信
  • 対象会員が存在しない場合の扱い

本書で扱わないこと

以下は本書では仕様確定せず、実装または別機能の設計を正とする。

  • 本会員登録（アクティベート）そのもの（本会員登録機能を正とする）
  • 仮登録完了メールの本文・件名（メールテンプレート管理を正とする）
  • 会員一覧・検索の仕様（会員一覧機能を正とする）

リニューアル移行時の扱い

挙動はpf-eccube3を参照し、永続化先の記述はec-cube-enterpriseを正とする。本機能が参照する会員（dtb_customer）の列は現行と移行先で同一スキーマである。

観点現行（pf-eccube3）移行先（ec-cube-enterprise）
本登録用キー会員（dtb_customer）の列secret_key同一（dtb_customer.secret_key）。
宛先メール会員（dtb_customer）の列email同一（dtb_customer.email）。

本機能は会員を更新せず、secret_keyとemailを読み取ってメールを再送するのみである。参照する列名は現行と移行先で一致するため、移行に伴う差は無い。

処理フロー

仮登録完了メールを再送する（PUT /{admin_route}/customer/{id}/resend）

  1. 管理画面の認証・権限を通過する。
  2. なりすまし対策トークンを検証する。
  3. パスの会員IDで会員を取得する。存在しない場合はページが見つからない扱い（404）とする。
  4. 当該会員の秘密キーから本登録用URL（アクティベートURL）を生成する。
  5. 仮登録完了メールを当該会員へ送信する。
  6. 成功メッセージを表示して会員一覧へ戻る。
