m05-18_admin_order_order_shipping_standby_list_create（受注管理 — 出荷指示リスト作成）

概要

管理画面「受注管理」配下の「出荷指示」画面から、注文番号レンジと受注日時レンジで条件を付け、条件に合う受注を抽出し、区分（通常・予約・大量）ごとに出荷指示リストを新規登録する。登録と同時に、対象受注へ出荷指示日時を記録し、対応状況を「出荷指示」（マスタID 9）へ一括更新する。

本書は実装手順ではなく、誰が・いつ・どの条件で・結果どうなるかを読むためのリバース詳細設計とする。確認対象はec-cube-enterpriseの現行実装とする。

対象はブラウザ経由の管理画面に限定する。出荷指示一覧の検索表示・ページング、リストの編集・削除・CSV・印刷・送り状出力、受注一覧・受注編集の個別操作の詳細は別範囲とする。

コントローラのメソッド名単位の解剖は本文の主題としない。本文ではルートbind名やSymfonyのルートnameの網羅は主説明としない。「利用者視点の入口」にHTTPメソッドとサイトルートからのパスパターンを書く。コード探索でbind名が必要なときだけ「調査補助」へ書く。

本機能のカスタマイズ区分は現行踏襲であり、出荷指示機能は現行リポ（pf-eccube3 の HareruyaEc プラグイン）と移行先（ec-cube-enterprise コア）の双方に同名で実装される。挙動は現行リポの実装を踏襲し、DB（永続化先のテーブル・列）は ec-cube-enterprise の実装を正とする。

リニューアル移行時の扱い

出荷指示機能は、現行は pf-eccube3 の HareruyaEc プラグイン（app/Plugin/HareruyaEc）に、移行先は ec-cube-enterprise コア（src/Eccube）に同名で実装される。永続化先の出荷指示リスト（dtb_shipping_standby）・出荷指示と受注の中間表（dtb_order_shipping_standby）・受注（dtb_order）・受注タイプマスタ（mtb_order_type）は、両者で同一スキーマである。dtb_shipping_standby の列構成（id・member_id・order_type_id・create_date・update_date・comment）と中間表の列（standby_id・order_id）は ec-cube-enterprise の定義を正とする。対応状況「出荷指示」（ID 9）への更新先 dtb_order.order_status_id、出荷指示日の dtb_order.commit_date も両者同一である。現行と移行先で差異が判明した場合は、DB記述は ec-cube-enterprise 実装を正とする。

処理フロー

出荷指示リストを作成する（POST admin_order_generate_standby_list）

  1. 管理画面の認証・共通制約を通過する。
  2. 生成専用フォーム種別をリクエストにバインドする。ブロックプレフィックスはadmin_generate_shipping_standby。
  3. 未送信または検証失敗の場合、管理向けエラーフラッシュ（キーadmin.common.save_error）を積み、admin_shipping_standbyへリダイレクトする。
  4. 検証成功時、フォーム配列を条件として、出荷指示リスト除外が偽の配送方法エンティティ一覧を取得し、受注リポジトリの待機対象抽出に渡す。
  5. 戻りが空配列なら、admin.common.save_errorを積み同ルートへリダイレクトする（永続化処理は呼ばない）。
  6. 空でない場合、区分別の受注配列と操作者の管理者アカウントを引数に、リスト生成用アクションを呼ぶ。
  7. アクションはトランザクション開始後、区分IDごとに次を繰り返す。
  • mtb_order_typeを区分IDで取得する。行がなければ引数例外を投げる。
  • 出荷指示リスト行を新規作成し、当該区分の受注コレクション・操作者の会員ID・区分参照を設定して永続化する（ORMのpersistとflush）。
  • 続けて受注リポジトリの一括更新を呼び、当該受注すべての対応状況を「出荷指示」（ID 9）にし、commit_dateを処理実行時刻（日時をY-m-d H:i:s形式の文字列としてバルク更新）にする。
  1. 全区分処理後にコミットする。途中で例外が出ればロールバックし例外を再送出する。
  2. コントローラは引数例外だけを捕捉し、そのメッセージをフラッシュに載せadmin_shipping_standbyへリダイレクトする。
  3. 成功時は成功フラッシュ（admin.common.save_complete）を積みadmin_shipping_standbyへリダイレクトする。
