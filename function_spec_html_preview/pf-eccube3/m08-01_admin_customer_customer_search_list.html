M08-01（会員検索/一覧）

概要

管理画面「会員管理」の会員マスターで、検索条件を指定して会員を絞り込み、一覧表示する機能である。会員ID・メールアドレス・お名前のフリーワードに加え、会員種別・性別・誕生日・住所・購入実績・買取実績・DCI関連情報・本人確認ステータス等で検索し、該当した会員を一覧として表示し、各会員の編集・削除・メール通知・仮会員メール再送・メール履歴・CSVダウンロードへの導線を提供する。

本書は実装手順ではなく、誰が・いつ・どの条件で・結果どうなるかを読むためのリバース詳細設計とする。確認値はpf-eccube3（EC-CUBE3系）の会員一覧処理（コア会員一覧）、HareruyaEcプラグインが追加する検索フォーム拡張・検索パターン保存処理、会員一覧テンプレート（Customer/index.twig）を正とする。

本機能のカスタマイズ区分はカスタマイズであり、挙動の参照は現行リポ（pf-eccube3）、DB関連はec-cube-enterpriseを正とする。会員本体dtb_customerは現行と移行先で同名・同一スキーマである。検索パターンは移行先ではコアのdtb_search_pattern、会員メール送信履歴はdtb_user_mail_historyを正とする。

対象はブラウザ経由の管理画面に限定する。会員の編集・登録（M08-04を正とする）、メール一括送信・手動メール通知（M08-08を正とする）、本人確認の確認操作（M08-10を正とする）、会員CSV出力（会員CSV出力機能を正とする）、ポイント管理・配送先・ブラックリストは別機能とする。

本文ではフレームワークのコントローラ型名やメソッド名を主説明としない。管理画面プレフィックスはコア設定admin_routeで決まり、環境により変わる。「利用者視点の入口」にHTTPメソッドとサイトルートからのパスパターンを書く。コード探索でルートbind名が必要なときだけ「調査補助」へ書く。

本書で扱うこと

  • 会員マスターの検索フォーム入力と検索結果一覧の表示
  • フリーワード検索と各絞り込み条件の対応
  • 検索条件・表示件数・ページ番号のセッション保持
  • 検索パターンの保存・適用・削除
  • 一覧から各会員操作（編集・削除・メール通知・仮会員メール再送・メール履歴）への導線

本書で扱わないこと

以下は本書では仕様確定せず、実装または別機能の設計を正とする。

  • 会員の登録・編集の入力項目と保存（M08-04を正とする）
  • メール一括送信・手動メール通知（M08-08を正とする）
  • 本人確認画像の閲覧・確認済への変更（M08-10を正とする）
  • 会員CSVの出力内容・出力項目設定（会員CSV出力機能・CSV出力項目設定を正とする）
  • 移行インポート（会員CSV取込機能を正とする）
  • 会員削除の論理削除フラグ運用の詳細（会員削除を正とする）

リニューアル移行時の扱い

挙動の参照は現行リポ（pf-eccube3 / HareruyaEcプラグイン）、DB関連の正典はec-cube-enterpriseとする。現行と移行先で永続化先が異なる項目は次のとおり。

JS挙動アコーディオンの開閉。日付入力は日時ピッカーを用いる。チェックボックスの全選択。操作メニュー（編集・削除・メール通知・仮会員メール再送）はドロップダウンで開く。検索条件をクリアは入力欄を初期化する。

処理フロー

会員マスターを表示する（GET /{admin_route}/customer）

  1. 管理画面の認証・権限を通過する。
  2. 検索フォームを生成する。プラグインの検索フォーム拡張により、都道府県（複数）・MTG Companion登録本名・DCIナンバー・DCI確認フラグ・国・買取総額範囲・買取件数範囲・検索パターン関連・本人確認ステータスの各欄を追加する。
  3. ページ番号指定が無く再開指定も無い場合は、会員検索用セッション（検索条件・ページ番号・表示件数）を削除する。
  4. ページ番号指定または再開指定がある場合は、セッションの検索条件を復元して該当ページを表示する。
  5. 検索フォームと一覧（初回は空）を表示する。

検索を実行する（POST /{admin_route}/customer）

  1. 検索フォームを送信状態で受け取り、検証する。
  2. 検証に通った場合、検索条件から会員検索のクエリを組み立て、1ページ目を取得する。
  3. 拡張イベントで検索クエリを拡張し得る。
  4. 検索条件（ビューデータ）とページ番号を会員検索用セッションへ保存する。
  5. 検索結果一覧と該当件数を表示する。

ページを送る（GET /{admin_route}/customer/page/{page_no}）

  1. セッションの検索条件を復元する。
  2. 表示件数指定があり、表示件数マスターに存在する値なら表示件数を更新してセッションへ保存する。
  3. 指定ページの検索結果を表示する。

検索パターンを保存する（POST /{admin_route}/customer/save/pattern）

  1. 入力中の検索条件を受け取る。
  2. パターン名が空の場合はエラーを表示し、検索結果を再表示する。
  3. パターンID指定があれば既存パターンを更新、無ければ新規にパターンを作成する。検索条件を直列化し、パターン名・表示キーcustomerとともに保存する。
  4. 保存成功を表示し、保存した条件で一覧を表示する。

保存した検索パターンを適用する（GET /{admin_route}/customer/search/pattern/{patternId}）

  1. 指定パターンを取得する。存在しない場合はページが見つからない扱い（404）とする。
  2. 直列化された条件を復元し、会員検索用セッションへ保存する。
  3. 復元した条件で1ページ目の一覧を表示する。

検索パターンを削除する（DELETE /{admin_route}/customer/delete/pattern/{patternId}）

  1. なりすまし対策トークンを検証する。
  2. 指定パターンが無い場合はエラーを表示し、検索結果を再表示する。
  3. パターンを削除し、削除成功を表示して会員マスターへ戻す。

集計条件

指標集計の要点
検索結果件数検索条件で組み立てたクエリの該当会員数。表の見出しに「該当しました」として件数を表示する。
ページ件数表示件数マスターのいずれか、または既定表示件数。セッション保持の表示件数を優先する。

会員検索クエリの結合・除外条件・退会会員の扱いはコアの会員検索とプラグインの検索拡張を正とする。本書では条件の全列挙はしない。

業務ルール・計算

項目内容
フリーワード会員ID・メールアドレス・お名前を横断して検索する。
検索条件の保持検索実行時に検索条件・ページ番号・表示件数を会員検索用セッションへ保存する。会員編集から検索画面に戻る導線は保持したページ番号と再開指定を用いる。
検索条件のクリア初期表示でページ番号も再開指定も無い場合は会員検索用セッションを削除する。
表示件数表示件数マスターに存在する値のみ採用し、セッションへ保存する。
検索パターン会員用パターンは表示キーcustomerで区別し、検索条件は直列化して保存する。
一覧の操作導線会員IDのリンクと操作メニューの編集は会員編集へ、削除は会員削除へ、メール通知は手動メール通知へ、メール履歴はメール送信履歴へ、CSVダウンロードは会員CSV出力へ遷移する。会員種別が仮会員（ステータスID1）のときのみ仮会員メール再送を表示する。

本機能は閲覧と絞り込みが中心であり、会員データの更新は行わない。

データ整合性

観点内容
参照時点一覧はリクエスト時点の永続化済み会員を読む。表示後に会員が更新されても自動更新しない。
件数と一覧該当件数とページ内行はクエリ結果に基づく。会員編集・削除後はセッションのページ番号と再開指定で一覧へ戻り得る。
検索条件の引き継ぎ会員ホームのショップ状況から本会員条件で遷移した場合、その条件を会員検索用セッションに保存して一覧を開く（ホームショップ状況機能を正とする）。

API/バッチ結果

本機能ではAPI呼び出し・バッチ実行を扱わない。CSVダウンロードは会員CSV出力機能を正とする。

入出力

種類内容
入力検索条件（フォームadmin_search_customer）、ページ番号、表示件数、検索パターンID。
成功時出力検索結果一覧と該当件数。検索パターンの保存・削除成功フラッシュ。

副作用会員検索用セッションへの検索条件・ページ番号・表示件数の保存。検索パターンの永続化・削除。
