概要

管理画面の「店頭買取管理」直下メニュー「買取一覧」で、店頭買取受注を検索条件で絞り込み、一覧としてページング表示する機能である。ナビゲーションのラベルは admin.purchase.store.list で「買取一覧」、親見出しは admin.purchase.store.title で「店頭買取管理」と表示される。

本書は実装手順ではなく、誰が・いつ・どの条件で・結果どうなるかを読むためのリバース詳細設計とする。ec-cube-enterprise のコア実装を確認値とする。

カスタマイズ区分はカスタマイズである。挙動はec-cube-enterpriseの実装を確認値とし、DB関連もec-cube-enterpriseを正とする。現行（pf-eccube3のHareruyaEcプラグイン）との差は「リニューアル移行時の扱い」に記録する。

対象はブラウザ経由の管理画面に限定する。

コントローラのメソッド名は本文の主題としない。本文ではルートbind名やSymfonyのルートnameの網羅は主説明としない。「利用者視点の入口」にHTTPメソッドとサイトルートからのパスパターンを書く。コード探索でbind名が必要なときだけ「調査補助」へ書く。

リニューアル移行時の扱い

店頭買取の永続化先は、現行（pf-eccube3のHareruyaEcプラグイン）と移行先（ec-cube-enterprise）でテーブル名・主要列名が一致し、概ね同一スキーマである。検索・一覧で参照するdtb_otc_buy_order・dtb_otc_buy_order_detail・mtb_otc_buy_order_status等は同名である。確認できた差分は次のとおりで、DB関連はec-cube-enterpriseを正とする。

処理フロー

初期表示（GET admin_otcbuyorder、クエリに有効な page_no / pageno がない）

  1. 管理画面の認証・共通制約を通過する。
  2. 店頭買取検索用フォームを項目既定値つきで生成する（後述の入力項目の初期値）。
  3. ページング情報は空配列、表示件数マスタは渡さず、page_count だけ設定ファイルの eccube_default_page_count を渡してテンプレートを返す。一覧ブロックは pagination が偽のため出ない。

検索実行（POST admin_otcbuyorder）

  1. 共通トレイトの検索処理に入る。フォームをリクエストでバインドする。
  2. ソートキーはリクエストまたはセッション、なければ識別子 default。並び順はリクエストまたはセッション、なければ DESC。値が ASC/DESC（大小無視）に合致しないときはソートエラーメッセージを積み、処理を打ち切る経路がある（共通トレイトの実装に従う）。
  3. 表示件数はセッションまたは既定値、リクエストに妥当な page_count があればセッションを更新する。
  4. 検索データが空に見える場合はセッションに保存した検索条件を復元する。
  5. 検索条件とソートをセッションキー eccube.admin.otcbuyorder.search、ページ番号、eccube.admin.otcbuyorder.sort、eccube.admin.otcbuyorder.order、eccube.admin.otcbuyorder.search.page_count に保存する。
  6. リポジトリが検索条件からクエリビルダを組み立て、ページャで指定ページを取得する。
  7. 最終ページで件数がちょうどページ境界になった直後に空ページになる場合はページ番号を1つ戻して再ページングする（共通トレイトの補正）。
  8. テンプレートへフォームビュー、ページネーション結果、表示件数マスタ、現在ページ、ソート情報、is_search_filter_active を渡す。

ページ移動・表示件数変更（GET、クエリに page_no または pageno、またはパス admin_otcbuyorder_page）

  1. admin_otcbuyorder の単一路由では、メソッド引数 page_no が0のときクエリの pageno または page_no を読む。正の値なら検索処理へ進む。
  2. admin_otcbuyorder_page/{page_no} は引数が正のとき常に検索処理へ進む。
  3. 検索処理はセッションの検索条件を復元して該当ページを表示する。

一覧から詳細へ

  1. 査定IDのリンクは GET admin_otcbuyorder_detail へ遷移する（本書では詳細を扱わない）。

集計条件

一覧上部に表示する「検索結果 N 件」は、ページングオブジェクトの総件数である。一覧テーブル内で金額や件数をさらに集計して表示する処理はない。

指標集計の要点
総件数検索条件と既定のキャンセル除外を満たす店頭買取受注の件数。ページサイズで分割される。

業務ルール・計算

  • 検索・一覧・取得条件はリクエストパラメータ、ログイン状態、公開状態、店舗・支店条件、既存リポジトリの絞り込み順序を正とする。
  • 件数、ページ番号、表示順は既存実装のデフォルトと上限に従い、取得後に業務値を再計算しない。
  • 金額、ポイント、数量、ステータス、日時はDBまたは連携元の永続化済み値を返却し、レスポンス生成時の丸め・補正は行わない。
  • 条件に一致しない、権限がない、または非公開のデータは空結果または既存のエラー形式で返す。

試行制限

本機能では試行制限を扱わない。

ログ・監査

一覧の表示・検索のみでは専用の業務ログ出力は設けていない。CSV出力時のログは別サービス。

ログに出してはいけないもの

  • パスワード
  • なりすまし対策トークン
  • Cookie 値
  • セッション ID の完全値
  • Remember Me トークンの原値

セッション

本機能におけるセッション

観点内容
検索ヒット後eccube.admin.otcbuyorder.search にフォームのビューデータ、eccube.admin.otcbuyorder.search.page_no にページ番号、eccube.admin.otcbuyorder.sort / order にソート状態、eccube.admin.otcbuyorder.search.page_count に表示件数を保存する。

セッションへ保存しない情報

パスワードやトークン原文を検索条件として保存する設計ではない。保存内容はフォームの通常フィールドに限られる。

Cookie

管理画面のセッション維持に用いる一般的なセッション Cookie に依存する。明細なしでよい。

排他制御・トランザクション

検索・一覧表示は読み取り中心であり、当画面の表示処理だけで楽観ロックや明示トランザクションを扱わない。
