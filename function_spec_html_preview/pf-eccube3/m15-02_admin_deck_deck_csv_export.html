デッキ管理 — デッキ CSV 出力

概要

HareruyaEc プラグインが管理画面のデッキ検索一覧から、一覧のチェックボックスで選択したデッキ ID に対応するデータを CSV ファイルとしてダウンロード応答で返す機能である。運用フォーマット用の標準出力と、旧サイト連携向けにカード明細まで行単位で展開する別形式の 2 系統がある。

本書は実装手順ではなく、誰が・いつ・どの条件で・結果どうなるかを読むためのリバース詳細設計とする。pf-eccube3 配下の HareruyaEc プラグインのソースを確認値とする。

本機能のカスタマイズ区分は現行踏襲である。挙動は現行リポ（pf-eccube3 の HareruyaEc プラグイン）を参照し、DB関連は ec-cube-enterprise を正とする。

対象はブラウザ経由の管理画面に限定する。

コントローラのメソッド名は本文の主題としない。本文ではルートbind名やSymfonyのルートnameの網羅は主説明としない。「利用者視点の入口」にHTTPメソッドとサイトルートからのパスパターンを書く。コード探索でbind名が必要なときだけ「調査補助」へ書く。

リニューアル移行時の扱い

  • ec-cube-enterprise にデッキ関連テーブル一式が実装されており、本機能の出力対象は移行先に存在する。
  • デッキ（dtb_deck）の主キー列名が異なる。移行先 ec-cube-enterprise では id、現行 pf-eccube3 では deck_id である。本書が dtb_deck.deck_id と記す主キー参照は、移行先では dtb_deck.id に対応する。デッキ内カード（dtb_deck_card）側の外部キー列は現行・移行先とも deck_id のままである。
  • デッキの出力対象列（disp_id、private_flg、text_main、text_side、old_deck_id、event_detail_id ほか）は現行と同一スキーマである。
  • 旧サイトレイアウトで繰り返し行のソースとするデッキ内カード（dtb_deck_card、列 deck_id、board_id、card_id、count）、および表示フラグ変換で参照する表示マスタ（mtb_disp）は移行先に存在し同一スキーマである。

処理フロー

標準レイアウト CSV をダウンロードする（POST m15-02_admin_deck_deck_csv_export）

  1. 管理画面の認証および共通 middleware を通過する。
  2. PHP の実行時間制限を無効にする（set_time_limit(0)）。
  3. ORM の SQL ロガーを無効にする。
  4. リクエストボディから deckId を取得する。HTML では deckId[] だが、Request::request->get('deckId') で取得する実装であり、チェックされていれば配列として届く。
  5. deckId が empty() に該当する場合、admin.csv.error.export.require をフラッシュして Referer ヘッダの URL へ HTTP リダイレクトする。
  6. サービス側で標準レイアウト用ヘッダ定義つきでエクスポート処理を実行する。
  7. リポジトリで dtb_deck.deck_id IN (...) に該当するデッキを取得する。JOIN で代表カード画像からカード名（英）を読むための関連が張られる。結果が PHP の論理値で偽となる空配列ならランタイム例外としメッセージキーは admin.csv.error.export.not_registered。
  8. 各デッキについて 1 CSV データ行へ変換する。統率者名は統率者ボード（ボード種別値 3）に紐づくカードあれば英語名を、無ければ空文字とする。
  9. ストリーミング応答を組み立てる。標準レイアウトでは組み込みの CSV エクスポート用サービス経由で、開く、UTF-8 の BOM を書く、論理キー行（連想配列のキーを array_keys で得た並び）、データ行の順に出力し、閉じる。
  10. 応答ヘッダの Content-Type は設定 csv_export_encoding に基づき text/csv;charset=… とする（値が SJIS-win 系なら Charset 文字列だけ windows-31j に読み替える）。Content-Disposition は attachment とファイル名を付ける。
  11. ファイル名は接頭辞 deck_、YmdHis、拡張子 .csv。情報ログへファイル名メッセージキーごと出力する応答オブジェクトが返る。実装ではコールバック内で送信も試みられる。

ランタイム例外が送出されたとき（標準・旧サイト共通）

  1. サーバ側の catch でメッセージ文字列をフラッシュエラーへ積み、Referer へ HTTP 302 などで返す。
  2. ダウンロードは開始されない。

旧サイト向けレイアウト CSV をダウンロードする（POST m15-02_admin_deck_deck_csv_export_old）

手順は標準出力とほぼ同じだが、次が異なる。

  • ヘッダ定義および行変換は旧サイト仕様に切り替える。
  • データ行生成時、各デッキについて dtb_deck_card をカードと結び付けて列挙し、カードごとに 1 データ行出力する。その際アーキタイプの「旧システム用 ID」を読み取り、空ならランタイム例外で翻訳キー admin.csv.error.data.old_archetype のメッセージを構成する。
  • format_by_age 列には、紐付くフォーマットの主キーが標準（ソース上 mtb_format の標準規制 ID 整数 1）に等しい場合はリテラル KLD_M19 を、それ以外は Archive を連結用文字列へ使う規則で埋める実装となる。
  • ストリーム書き込みはコア CSV サービスではなく標準関数で php://output に直接書き込み、Content-Type やファイル名ヘッダ付与は共通ヘルパに委ねる。

POST の ID と DB の整合

  • クエリ結果が空だけがエラー条件である。部分的に存在しない ID が混じっていも、ほかが 1 件以上ヒットしていれば処理は進み、ヒットしない ID は出力に現れない。

集計条件

本機能では販売金額のような業務集計は行わない。出力される行は、標準レイアウトでは取得できたデッキの件数分、旧サイトレイアウトでは該当デッキに紐づくデッキカード行の合計分である。
