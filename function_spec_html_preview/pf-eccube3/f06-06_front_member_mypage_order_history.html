F06-06（購入履歴一覧）

概要

購入履歴一覧は、ログイン済み会員が自身の注文（購入）の履歴を一覧で確認する機能である。会員の注文を新しい順にページングして表示し、各行に注文日・注文番号・注文内容・注文金額合計・支払方法・処理状態を出す。注文番号のリンクから購入履歴詳細へ遷移し、注文内容から再購入（カートへの再投入）を行える。処理中（カート操作中相当）の注文は一覧から除外する。

本書は実装手順ではなく、誰が・いつ・どの条件で・結果どうなるかを読むためのリバース詳細設計とする。確認値はpf-eccube3（EC-CUBE3系）のHareruyaEcプラグインの購入履歴一覧処理、購入履歴一覧テンプレート（Mypage/shopping_history.twig）、会員の注文を取得するリポジトリ、注文番号取得処理を正とする。

本機能のカスタマイズ区分はカスタマイズであり、画面・処理フローの挙動はpf-eccube3を参照リポとする。DB関連（テーブル名・列名・保存先）はec-cube-enterpriseを正とする。

対象はブラウザ経由のフロント（会員マイページ）に限定する。フロントのページは言語別パスセグメント/{_locale}を前提とし、本書のパスは/{_locale}配下の確認値として記載する。/mypage配下は会員ログインを要する。

本文ではフレームワークのコントローラ型名やメソッド名を主説明としない。ルートbind名の網羅は主説明とせず、「利用者視点の入口」にHTTPメソッドとサイトルートからのパスパターンを書く。

  • 一覧対象の抽出条件・並び順・ページング
  • 注文番号からの詳細遷移、再購入の入口
  • 未ログイン時の扱い

本書で扱わないこと

以下は本書では仕様確定せず、実装または別機能の設計を正とする。

  • 購入履歴詳細画面の仕様（購入履歴詳細機能を正とする）
  • 再購入後の購入手続き・カート処理の仕様（カート・購入機能を正とする）
  • 注文ステータス・注文番号の付番ロジック（注文機能を正とする）
  • 会員ログイン認証そのもの（会員ログイン機能を正とする）

リニューアル移行時の扱い

DB関連の記述はec-cube-enterpriseを正とする。注文ヘッダ（dtb_order）の列名（customer_id・order_status_id・order_date・payment_total）は現行（pf-eccube3）と移行先（ec-cube-enterprise）で同一スキーマである。

注文明細の保持先テーブル名は現行と移行先で異なる。現行の注文明細テーブルdtb_order_detailは、移行先（ec-cube-enterprise）ではdtb_order_itemに相当する。注文内容・再購入に用いるproduct_name・quantityは同名の列、商品規格はproduct_class_idの関連で保持する。本書のDB記述は移行先名（dtb_order_item）を主とし、現行名（dtb_order_detail）を括弧で添える。

一覧表示・再購入内容の取得は参照のみで業務データを更新しないため、移行に伴う保存処理の差分は生じない。

処理フロー

購入履歴一覧を表示する（GET /{_locale}/mypage/shopping_history）

  1. 会員ログインを要求する。未ログインの場合は会員ログインへ誘導する（会員ログイン機能を正とする）。
  2. クエリからページ番号・1ページ件数を決める（既定は1ページ目・10件）。
  3. 当該会員の注文を、処理中の注文を除外して新しい順（注文IDの降順）に取得する。
  4. ページングして、対象注文の注文番号を取得する。
  5. 件数・一覧・ページ送りを表示する。

再購入する（POST /{_locale}/mypage/shopping_history/repurchase）

  1. 注文IDを受け取る。注文IDが無い場合は不正要求（HTTP404）とする。
  2. ログイン会員と注文IDで注文を特定する。該当が無い場合は不正要求（HTTP404）とする。
  3. 注文明細の商品・数量からカート投入用の内容を組み立てる。
  4. 成功とカート投入内容をJSONで返す。
