データ管理 — 買取価格対応表（一覧）

概要

HareruyaEc プラグインが管理画面「データ管理」配下に提供する「買取価格対応表」の一覧である。NM（ニアミント）基準価格ごとに、カード状態（SP・MP・HP 等）と通常版／Foil・プロモ版の組み合わせごとの買取価格をマスタ表 mtb_buy_price_list としてマトリクス表示し、各セルは主キー付きの編集画面へのリンクになる。

編集画面の表示・POST 更新・CSRF・入力検証・成功時リダイレクトは別紙「データ管理 — 買取価格対応表（編集）」（m16-07_admin_data_data_buy_price_list_edit.md）を正とする。

本書は実装手順ではなく、誰が・いつ・どの条件で・結果どうなるかを読むためのリバース詳細設計とする。カスタマイズ区分は「現行踏襲」。画面・挙動は pf-eccube3 配下の HareruyaEc プラグインのソースを確認値とし、DB関連（テーブル・列・型・制約・関連）は ec-cube-enterprise の実装を正とする。本機能のマスタは両リポで同一スキーマである。

対象はブラウザ経由の管理画面に限定する。

本文ではコントローラのメソッド単位の解剖を主題としない。本文ではルートbind名やSymfonyのルートnameの網羅は主説明としない。「利用者視点の入口」にHTTPメソッドとサイトルートからのパスパターンを書く。コード探索でbind名が必要なときだけ「調査補助」へ書く。

リニューアル移行時の扱い

  • 本機能の DB は現行（pf-eccube3 の HareruyaEc プラグイン）と移行先（ec-cube-enterprise コア）で同一スキーマである。mtb_buy_price_list・mtb_card_condition のテーブル名・列名・型は一致するため、DB記述はそのまま移行先の正とする。
  • 画面・挙動は現行（pf-eccube3）の確認値。NM基準価格×カード状態×通常/Foil・プロモの買取価格マトリクス表示という機能は移行先でも同等で、現行はプラグイン提供、移行先はコア提供である。
  • 現行と移行先でスキーマ差・挙動差は確認されていない。差が生じた場合のみ本節に追記する。

処理フロー

一覧を表示する（GET admin_buy_price_list）

  1. 管理画面の認証・共通制約を通過する。
  2. カード状態マスタを識別子昇順で全件取得する。
  3. 買取価格対応表マスタを識別子順で全件取得する（リポジトリの findAll に依存。並びは DB 層の既定順である）。
  4. 取得した各行について、nm_price・special_flg・card_condition_id をキーとする三次元の連想配列に、price と行 id を格納する。
  5. Twig で一覧表を描画する。行の並びは手順 4 の最外层キー（NM価格）の列挙順に従う。各セルは path('admin_buy_price_list_edit', {id: buyPrice.id}) のリンクで金額を表示する。
