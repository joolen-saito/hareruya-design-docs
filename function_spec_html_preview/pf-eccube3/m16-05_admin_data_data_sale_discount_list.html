データ管理 — 販売割引率一覧

概要

HareruyaEc プラグインが管理画面の「データ管理」から提供する、販売用の割引率マスタ（行）× カード状態マスタのコード（列）に対応する割引率（数値）を矩形式で一覧表示する閲覧専用画面である。交差情報は dtb_discount_card_condition を読み、その組み合わせが無いセルには固定文言「未定義」を出す。

本書は実装手順ではなく、誰が・いつ・どの条件で・結果どうなるかを読むためのリバース詳細設計とする。カスタマイズ区分は「現行踏襲」。画面・挙動は pf-eccube3 に配置された HareruyaEc プラグインのソースを確認値とし、DB関連（テーブル・列・型・制約・関連）は ec-cube-enterprise の実装を正とする。本機能のマスタは両リポで同一スキーマである。

対象はブラウザ経由の管理画面に限定する。

本文ではフレームワークのコントローラ型名やメソッド名を主説明としない。本文ではルートbind名やSymfonyのルートnameの網羅は主説明としない。「利用者視点の入口」にHTTPメソッドとサイトルートからのパスパターンを書く。コード探索でbind名が必要なときだけ「調査補助」へ書く。

リニューアル移行時の扱い

  • 本機能の DB は現行（pf-eccube3 の HareruyaEc プラグイン）と移行先（ec-cube-enterprise コア）で同一スキーマである。mtb_discount・mtb_card_condition・dtb_discount_card_condition のテーブル名・列名・型は一致するため、DB記述はそのまま移行先の正とする。
  • 画面・挙動は現行（pf-eccube3）の確認値。割引率（行）×カード状態コード（列）のマトリクス閲覧という機能は移行先でも同等で、現行はプラグイン提供、移行先はコア提供である。
  • 現行と移行先でスキーマ差・挙動差は確認されていない。差が生じた場合のみ本節に追記する。

処理フロー

一覧を表示する（GET admin_discount_list）

  1. 管理画面の認証・共通制約を通過する。
  2. mtb_card_condition に対応するエンティティをリポジトリの findAll() で読み込む。
  3. mtb_discount に対応するエンティティを同様に findAll() で読み込む。
  4. dtb_discount_card_condition の全行を findAll() で読み込む。
  5. dtb_discount_card_condition ごとに、カード状態 ID と割引 ID をキーの二段配列 $discountMap[stateId][discountId] に浮動小数 rate を格納する（同一キーへの二重代入は後勝ち）。
  6. 上記データを Twig に渡し、discounts と cardConditions の二重ループで表を出力する。
  7. 各セルでは discountMap[condition.id][discount.id] が定義されていれば値を、その他は「未定義」を表示する。
  8. サーバ側はこのリクエスト中にフラッシュやセッション検索状態を設定する処理を持たない。
