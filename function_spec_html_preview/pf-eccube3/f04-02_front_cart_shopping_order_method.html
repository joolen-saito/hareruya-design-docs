F04-02（ご注文方法指定 — 注文情報の入力・確認・注文）

概要

ご注文方法指定画面において、ロック済みカートをもとに受注情報を作成し、お届け先・配送方法・お支払い方法・ポイント利用・要望欄などの注文情報を入力・確認し、最終的に注文を確定する機能である。配送業者の変更、お支払い方法の変更、お届け先の選択を同一画面の部分送信で反映し、最終送信で購入処理（受注確定）まで行う。

本書は実装手順ではなく、誰が・いつ・どの条件で・結果どうなるかを読むためのリバース詳細設計とする。確認値はpf-eccube3（EC-CUBE3系）のHareruyaEcプラグインの購入処理、テンプレート（Shopping/index.twig）、購入処理サービスを正とする。

本機能のカスタマイズ区分はカスタマイズであり、挙動の確認は現行リポ（pf-eccube3）の実装を参照する。DB関連の記述はリニューアル移行先の ec-cube-enterprise を正とする。

対象はブラウザ経由のフロント（購入手続き）に限定する。フロントのルートはロケールセグメント付きで提供され、サイトルートからのパスパターンは/{_locale}配下になる（/{_locale}はサービスプロバイダのマウントで決まる確認値）。

コントローラのメソッド単位の解剖は本文の主題としない。本文ではルートbind名の網羅を主説明とせず、「利用者視点の入口」にHTTPメソッドとサイトルートからのパスパターンを書く。

本書で扱うこと

  • ロック済みカートから受注情報を作成し、ご注文方法指定画面を表示する流れ
  • お届け先選択・配送業者変更・お支払い方法変更・ポイント利用・要望欄入力の各部分送信
  • 最終送信（確認・注文確定）での購入処理と完了画面への遷移
  • 会員・非会員（ゲスト購入）・未ログインの分岐
  • 入力・確認・注文の段階で受注情報・セッションが引き継ぐ状態

本書で扱わないこと

以下は本書では仕様確定せず、実装または別機能の設計を正とする。

  • 買い物かごの表示・数量更新（F04-01 買い物かごを正とする）
  • 注文確定後の購入完了処理（受注ステータス判定・メール・在庫・ポイント反映・完了画面）はカートの決済〜購入完了機能（f04-04_front_cart_shopping_complete）を正とする
  • 配送先の新規登録・変更（F04-03 注文時の配送先登録・変更を正とする。本書は選択結果の反映のみ触れる）
  • 各決済手段の内部仕様、ポイント計算サービスの内部仕様
  • ログイン・非会員登録画面（購入手続き内のログイン・非会員入口）の認証仕様

リニューアル移行時の扱い

受注明細テーブルは、現行（pf-eccube3）の dtb_order_detail に対し、移行先（ec-cube-enterprise）では dtb_order_item に名称が変わる。本書のDB記述は移行先名称 dtb_order_item を主とし、現行名を括弧で添える。受注 dtb_order（支払方法・手数料 charge・割引 discount・メッセージ message・受注ステータス等）、配送 dtb_shipping、お届け先住所 dtb_customer_address は移行先でも同名で同一に扱う。注文確定後の購入完了処理（受注ステータス判定・メール・在庫・ポイント反映・完了画面）はカートの決済〜購入完了機能（F04-04）を正とする。

処理フロー

ご注文方法指定を表示する（GET /{_locale}/shopping）

  1. 表示ロケールをセッションに保存する。
  2. カートがロックされていない、またはカートが空のときは買い物かごへ戻す。
  3. 処理中ステータスの受注情報を取得する。無ければ受注情報を作成する。
  • 未ログインかつ非会員未登録ならログイン画面へ誘導する。
  • 非会員登録済みまたは会員なら、その顧客で受注情報を作成し、プレオーダーIDをCookieへ保存し、明細サブ情報を作成し、ポイント使用量0で登録する。
  1. 受注を最新化し、受注IDをセッションへ保存する。
  2. 配送・支払フォームを組み立て、受注金額がマイナスなら注文エラーへ遷移する。
  3. 配送先が複数の場合、複数配送設定が無効ならエラーで買い物かごへ戻し、有効なら一度だけ複数配送の案内を表示する。
  4. お届け先一覧・税相当額などを渡してご注文方法指定画面を表示する。

配送業者を変更する（POST /{_locale}/shopping/delivery）

  1. カート・受注情報を確認する。POST以外はご注文方法指定へ戻す。
  2. ポイント使用量を0で登録し直し、合計を再計算する。
  3. フォーム送信時は配送データを受注へ反映して保存し、ご注文方法指定画面へ戻る。

お支払い方法・要望・ポイントを変更する（POST /{_locale}/shopping/payment）

  1. 受注情報を確認する。POST以外はご注文方法指定へ戻す。
  2. ポイント利用指定からポイント使用量を登録し、合計を再計算する。
  3. お支払い方法が有効なら受注へ設定し手数料を反映する。無効なら支払いを未設定にして手数料を0にする。
  4. 要望欄を受注へ保存し、ポイント使用量を再更新して合計を再計算し保存する。
  5. ご注文方法指定画面へ戻る。

お届け先を選択する（POST /{_locale}/shopping/shipping/{id}）

  1. カートを確認する。
  2. 選択されたお届け先IDを、リクエスト・セッション・Cookieの順で取得する。未選択ならご注文方法指定へ戻す。
  3. 当該顧客のお届け先住所を取得する。存在しなければお届け先が見つからない旨で扱う。
  4. 配送先情報を更新し、国内・国外で郵便番号の設定を切り替える。
  5. 配送方法をリセットし、ポイント使用量0で再登録、配送料を設定して合計を再計算し保存する。
  6. 選択したお届け先IDをセッションとCookieへ保存し、ご注文方法指定画面へ戻る。

確認・注文を確定する（POST /{_locale}/shopping/confirm）

  1. 表示ロケールをセッションから復元する。
  2. カート・受注情報を確認する。受注情報が無ければ注文エラーへ遷移する。POST以外は買い物かごへ戻す。
  3. フォームを検証し、お支払い方法が有効なら購入処理に進む。
  4. トランザクション内でお支払い方法の一致を検証し、ポイント使用量を登録し、購入処理（受注確定）を行ってコミットする。
  5. 購入処理の例外時はロールバックして注文エラーへ遷移する。
  6. カートを空にし、受注IDをセッションへ保存し、ポイントを使用して購入完了画面へ遷移する。
  7. 検証エラー時はご注文方法指定画面を再描画する。

注文確定 時の判定順序

順序判定結果
1カートがロックされているか未ロックなら買い物かごへ戻す
2処理中の受注情報があるか無ければ注文エラーへ遷移する
3リクエストがPOSTかPOST以外は買い物かごへ戻す
4フォーム検証とお支払い方法の妥当性不備なら同画面を再描画する
5お支払い方法が受注の保持値と一致するか不一致なら注文エラーへ遷移する
6購入処理が成功するか失敗ならロールバックして注文エラーへ遷移する
7上記を通過カートを空にし、受注IDを保存し、購入完了画面へ遷移する
