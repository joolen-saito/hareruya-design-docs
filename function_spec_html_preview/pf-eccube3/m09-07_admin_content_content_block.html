M09-07（ブロック管理）

概要

管理画面コンテンツ管理のブロック管理は、レイアウト上に配置するブロックの属性（ブロック名・ファイル名）と、ブロックのテンプレート本文（Twig）を一覧から選んで編集する機能である。EC-CUBE コアのブロック管理を、HareruyaEc プラグインが新規作成・編集・更新の各操作で差し替えている。

本書は実装手順ではなく、誰が・いつ・どの条件で・結果どうなるかを読むためのリバース詳細設計とする。一覧表示・削除はコアのブロック管理実装、新規作成・編集フォームの表示・保存は HareruyaEc のブロック管理実装を確認値とする。

本機能のカスタマイズ区分はカスタマイズであり、挙動は現行リポ（pf-eccube3）を正とし、DB関連（テーブル名・列名・保存先）は ec-cube-enterprise を正とする。現行と移行先で dtb_block の列構成が異なるため、本書のDB記述は移行先名を主とし現行名を括弧で添える。差分は「リニューアル移行時の扱い」に集約する。

対象はブラウザ経由の管理画面コンテンツ管理のブロック管理に限定する。ブロックのページへの配置（レイアウト管理）、ページ管理、CSS管理、JavaScript管理、ファイル管理は別機能として切り離す。

管理画面プレフィックスは設定キー admin_route（path.yml の ${ADMIN_ROUTE} 由来）で決まる。本書ではパスを /{admin_route}/ のプレースホルダで示し、ルート bind 名は調査補助に隔離する。コントローラのメソッド名は本文の主説明としない。

本書で扱うこと

  • ブロック一覧の表示対象と表示項目
  • ブロック新規作成フォーム・編集フォームの表示と入力項目
  • ブロック属性の保存と、テンプレート本文（Twig）のブロックファイル保存
  • 削除不可ブロック（初期投入ブロック）で編集・更新がアクセス拒否（HTTP 403）になること
  • 保存後のキャッシュ破棄とリダイレクト
  • 削除可能ブロックの削除可否

本書で扱わないこと

以下は本書では仕様確定せず、実装または別機能の設計を正とする。

  • レイアウト管理（m09-03_admin_content_content_layout）でのブロック配置・並び順
  • ページ管理・ファイル管理・キャッシュ管理・CSS管理・JavaScript管理の動作
  • フロント側でのブロック描画、ロジックブロックの動的処理
  • 端末種別（PC以外）ごとのブロック管理。本機能は PC 端末種別を対象に固定する
  • 管理画面のログイン・権限設定の詳細仕様

リニューアル移行時の扱い

本機能はカスタマイズ区分がカスタマイズである。挙動は現行リポ（pf-eccube3 の HareruyaEc 実装・コア実装）を正とし、DBスキーマは移行先 ec-cube-enterprise を正とする。dtb_block の列は現行（EC-CUBE 3 系）と移行先（ec-cube-enterprise）で名称・型が異なる。ec-cube-enterprise の dtb_block 実装で確認した差分を以下に記す。

項目現行（pf-eccube3、EC-CUBE 3 系）移行先（ec-cube-enterprise）
ブロック名dtb_block.namedtb_block.block_name
削除可否区分dtb_block.deletable_flg（整数。削除可能=正の値、削除不可=0）dtb_block.deletable（真偽値。削除可能=真、削除不可=偽）
ロジック区分dtb_block.logic_flg（整数。新規作成は0）dtb_block.use_controller（真偽値。コントローラ実行ブロックか否か）
ファイル名dtb_block.file_namedtb_block.file_name（同一）
端末種別dtb_block.device_type_iddtb_block.device_type_id（同一。device_type_id と file_name の複合一意制約あり）
ブロックファイルパス該当列なし（テンプレート本文はファイルへ書き出し）dtb_block.path（移行先で追加。現行に対応列が無い）

テンプレート本文を dtb_block に保存しない点は現行・移行先で共通である。移行先で追加された path 列に対応する現行列は無い。本文中のDB記述は移行先名を主とし、現行名を括弧で添える。

フロント挙動

観点内容
表示要素一覧は検索ボックスと、ブロック名・ファイル名の2列、操作ドロップダウンを並べる。編集フォームはブロック名・ファイル名の入力欄と、ブロックデータ（テンプレート本文）の複数行入力欄を持つ。削除可能ブロックでだけ削除操作を表示する。
JS 挙動一覧の操作はドロップダウンメニューで開く。削除リンクは確認ダイアログ「このブロックを削除してもよろしいですか？」を出し、data-method="delete" でHTTP DELETE 相当の送信を行う。専用のリッチエディタや非同期保存は持たない。
CSS・レイアウト管理画面共通のテーブル風レイアウトと横型フォームテーマを使う。ブロックデータ欄は行数15・等幅小サイズで表示する。
モーダル・ポップアップ削除確認のダイアログ以外のモーダルは持たない。
入力項目ブロックデータは複数行入力（textarea）であり、リッチテキスト化やプレビュー切替は行わない。

フロントエンド側ビジネスロジック

起点参照する値判定順序更新する表示値・送信値サーバ側再検証
削除リンク押下対象ブロックの削除URL、確認文言確認ダイアログを表示し、承認された場合だけ削除送信へ進む。data-method="delete"の送信を実行する。フォーム値は更新しない。ブロック存在、削除可否、初期ブロック制限、トークン、権限はサーバ側で判定する。
ブロックデータ編集ブロックデータ入力欄の値ブラウザ側ではTwig構文検証やテンプレート展開を行わない。入力されたブロックデータを送信値にする。必須、ファイル名、テンプレートファイル保存可否はサーバ側で判定する。
ドロップダウン操作対象行の操作メニューメニューを開閉するだけで業務値を変更しない。送信値は変更しない。実行された操作ごとにサーバ側で対象と権限を判定する。

処理フロー

ブロック一覧を表示する

  1. PC 端末種別を取得する。
  2. 検索語が入力されている場合は、ブロック名・ファイル名を部分一致条件にする。
  3. その端末種別のブロックを ID 降順で取得する。
  4. 一覧表示完了の拡張イベントを発火し、ブロック一覧を渡す。
  5. 一覧テンプレートを描画する。

新規作成フォームを表示する

  1. ブロック ID 未指定で新規ブロックを生成し、PC 端末種別・ロジック区分（0）・削除可否区分（削除可能）を設定する。
  2. ブロック用フォームを組み、初期化完了イベントを発火する。イベント結果でテンプレート本文の初期値を上書きできる。
  3. ブロックデータ欄に、設定ファイル群から見つかった既定テンプレートの内容を初期表示する。見つからなければ空文字を初期表示する。
  4. 編集フォームを描画する。

編集フォームを表示する

  1. ブロック ID から該当ブロックを取得する。該当が無ければ見つからない扱い（HTTP 404）とする。
  2. 削除可否区分が削除不可のとき、アクセス拒否（HTTP 403）とする。
  3. ブロック用フォームを組み、初期化完了イベントを発火する。イベント結果でテンプレート本文を上書きできる。
  4. ブロックデータ欄に読込先ファイルの内容を初期表示する。読込先はアプリのブロック領域・プラグイン既定・コア既定の順に探す。
  5. 編集フォームを描画する。

新規作成を送信する

  1. 初期化完了イベントを発火し、フォームに送信値を反映する。
  2. 検証が通らなければ同一フォームを再描画する。
  3. 検証済みなら、フォーム内容でブロック情報を更新し、データベースへ保存する。
  4. テンプレート本文をアプリのブロック領域のファイルへ書き出す。
  5. キャッシュを破棄する。
  6. 編集完了イベントを発火し、登録完了メッセージを追加する。
  7. 登録したブロックの編集画面へリダイレクトする。

編集を送信する

  1. ブロック ID から該当ブロックを取得する。削除不可ブロックのときアクセス拒否（HTTP 403）とする。
  2. 初期化完了イベントを発火し、フォームに送信値を反映する。
  3. 検証が通らなければ同一フォームを再描画する。
  4. 検証済みなら、フォーム内容でブロック情報を更新し、データベースへ保存する。
  5. テンプレート本文をアプリのブロック領域のファイルへ書き出す。ファイル名が変更され旧ファイルが存在すれば旧ファイルを削除する。
  6. キャッシュを破棄し、編集完了イベントを発火し、登録完了メッセージを追加する。
  7. 編集画面へリダイレクトする。

業務ルール・計算

本機能では金額計算・件数集計を行わない。ブロック属性の検証と、テンプレート本文のブロックファイル保存が主な処理である。

項目内容
保存先テンプレート本文はアプリのブロック領域へ書き出す。読込はアプリのブロック領域・プラグイン既定・コア既定の順に探す。
ファイル名の一意性同一端末種別でファイル名が重複するとき検証エラーとする。編集時は自身の ID を除外して重複判定する。
編集・削除の制限削除可否区分が削除不可のブロックは編集・更新でアクセス拒否（HTTP 403）とし、削除も行わない。
一覧の対象PC 端末種別のブロックを ID 降順で表示する。検索語がある場合はブロック名・ファイル名を部分一致で絞り込む。

入力項目

項目名必須／任意最大長初期値保存先・扱い
ブロック名必須255文字（NotBlank と Length）新規は空、編集は現行値dtb_block.block_name（現行 name）。キー name。
ファイル名必須255文字（NotBlank・Length・正規表現）新規は空、編集は現行値dtb_block.file_name。キー file_name。半角英数字と _ / のみ許可。テンプレート本文の書き出しファイル名になる。
ブロックデータ任意フォーム上限なし。ファイルへ書き出す新規は既定テンプレート内容、編集は読込先ファイル内容テーブルには保存せず Twig ファイルへ書き出す。キー block_html（mapped 偽）。改行コードを変換して書き込む。

最大長の数値は src/Eccube/Resource/config/constant.yml.dist の確認値とする。運用環境で上書きされている場合はその環境の値が正とする。端末種別とブロック ID は隠し項目として送信し、ブロック ID はキー id、端末種別はキー DeviceType で扱う。

データ整合性

観点内容
属性とファイルの整合ブロック属性はデータベース、テンプレート本文はファイルへ分けて保存する。保存はデータベース更新のあとにファイル書き出しを行う。両者の整合は保存処理の成否に依存する。
一覧と編集の整合一覧は保存後の最新レコードを ID 降順で読む。本文の表示は読込先ファイルの現行内容を反映する。
キャッシュ保存・削除のあとキャッシュを破棄する。テンプレートのキャッシュが古いまま残り続ける設計にはしない。

API/バッチ結果

本機能では管理画面外の公開 API 呼び出しやバッチ起動本体を扱わない。

入出力

種類内容

副作用データベース更新、ブロックファイルの作成・更新・削除、キャッシュ破棄、処理イベント通知、フラッシュメッセージ。
