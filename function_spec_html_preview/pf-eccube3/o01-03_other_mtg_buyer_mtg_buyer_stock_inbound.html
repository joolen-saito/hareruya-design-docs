o01-03_other_mtg_buyer_mtg_buyer_stock_inbound（その他_MTGバイヤー_入庫モード）

処理フロー

入庫（ステータス遷移 入庫待ち→入庫済み）

  1. 買取受注のステータスを入庫済みへ更新する（管理画面の詳細更新、またはステータス更新API、または一括入庫バッチ）。
  2. EC-CUBE側の入庫サービスが、当該受注の買取在庫（dtb_buy_order_stock）を商品在庫（ProductStock）へ反映する。
  3. 在庫数の変化を在庫履歴（dtb_buy_order_stock_history、更新前数量・更新後数量・登録者・登録日時）として記録する。
  4. ステータスを入庫済みとして保存する。例外時はロールバックし、未反映として残す。

一括入庫（バッチ）

入庫待ち状態の全受注を対象に、上記入庫処理を順に実行し、入庫済みへ遷移させる。

ログ・監査

入庫の数量変化は在庫履歴（dtb_buy_order_stock_history）で追跡する。専用ログは ec-cube-enterprise の入庫サービス実装を正とする。

業務ロジック

集計・判定・計算

指標要点
入庫数量買取在庫（dtb_buy_order_stock）の数量を商品在庫へ加算する。商品在庫の最終的な在庫数計算は在庫管理の実装を正とする。
入庫対象ステータスが入庫待ちの買取受注を対象とする。未登録在庫がある場合の扱いはステータス（未登録在庫あり）で表す。

データ整合性

観点内容
買取在庫と商品在庫入庫により買取在庫の数量が商品在庫へ反映される。入庫履歴の更新前後数量で変化を追跡できる。
ステータスと入庫入庫処理はステータス遷移に連動する。入庫済みの受注は入庫処理が実行済みであることを表す。
二重入庫同一受注の再入庫を避けるため、ステータスにより実行済みを判定する。詳細な冪等性保証は ec-cube-enterprise の入庫サービス実装を正とする。

排他制御・トランザクション

入庫は買取在庫の反映・商品在庫の更新・在庫履歴の作成・ステータス更新をまとめて行い、例外時はロールバックする。二重入庫はステータス判定で防ぐ（実装を正とする）。
