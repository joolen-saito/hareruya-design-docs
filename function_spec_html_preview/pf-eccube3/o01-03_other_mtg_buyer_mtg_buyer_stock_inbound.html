o01-03_other_mtg_buyer_mtg_buyer_stock_inbound（その他_MTGバイヤー_入庫モード）

概要

MTGバイヤーの入庫モードで行う「入庫」（買取成立後の商品を在庫へ登録する業務）を、EC-CUBE側のネット買取データ・在庫データ・ステータス遷移から見たリバース詳細設計である。査定（O01-01 店頭買取／O01-02 ネット買取）の後工程にあたる。

本書は実装手順ではなく、誰が・いつ・どの条件で・結果どうなるかを読むためのリバース詳細設計とする。カスタマイズ区分は「現行踏襲」。入庫処理の実体は EC-CUBE側（ec-cube-enterprise）の在庫登録処理にあり、DB関連も含め ec-cube-enterprise の実装を正とする。

MTGバイヤー本体は本リポジトリ内に実装が無い外部アプリである。重要な確認結果として、入庫（stock-in）専用の外部APIエンドポイントは pf-api に存在しない。入庫は、買取受注のステータスが入庫待ち→入庫済みへ遷移する際に EC-CUBE側で内部的に実行される。本書ではこの内部処理と、MTGバイヤーが関与し得る入口（ステータス更新）を扱う。

本書で扱うこと

  • 入庫の意味（買取成立商品を在庫 ProductStock へ登録し、在庫履歴を残す処理）
  • 入庫が起動する条件（ステータス遷移 入庫待ち→入庫済み、および一括入庫バッチ）
  • 入庫で更新するデータ（買取在庫・在庫履歴・商品在庫）
  • 外部API（pf-api）に入庫専用エンドポイントが無いこと、MTGバイヤーの関与点

本書で扱わないこと

以下は本書では仕様確定せず、実装または別機能の設計を正とする。

  • 査定そのもの（店頭買取は O01-01、ネット買取は O01-02 を正とする）
  • 在庫管理画面・在庫移動・在庫履歴一覧（M04／在庫管理の各設計を正とする）
  • MTGバイヤー本体の入庫モード画面・UI・操作（リポジトリ外）
  • 商品在庫（ProductStock）の在庫数計算ロジック全般（在庫管理の実装を正とする）

リニューアル移行時の扱い

  • 入庫処理は現行 pf-api には外部APIとして存在せず、移行先 ec-cube-enterprise の内部サービスとして実装される。挙動・DBとも ec-cube-enterprise を正とする。
  • 入庫の実体は ec-cube-enterprise のサービス（買取在庫の登録・商品在庫への反映・在庫履歴作成）であり、ステータス遷移（入庫待ち→入庫済み）または一括入庫バッチで起動する。
  • ステータス値（入庫待ち・入庫済み・未登録在庫あり 等）の定義は ec-cube-enterprise の Master\MtbBuyOrderStatus を正とする。現行 pf-api のステータス定数はこれらを持たない。
  • MTGバイヤーが入庫モードで行う操作は、外部APIとしてはステータス更新（O01-02 の PUT /admin/buyOrder/{id}/status.json 等）に集約され得る。専用入庫APIの要否は移行設計で確定する（要確認）。

用語

用語説明
入庫買取で取得した商品を在庫（ProductStock）へ登録すること。買取受注が入庫済みへ遷移する際に行う。
買取在庫入庫の作業単位として買取受注に紐づく在庫行。dtb_buy_order_stock。
在庫履歴入庫に伴う数量変化の履歴。dtb_buy_order_stock_history。
入庫待ち入庫前の状態。mtb_buy_order_status の入庫待ち（移行先で値 16）。
入庫済み入庫完了の状態。入庫済み（移行先で値 14）。
商品在庫商品規格ごとの在庫（ProductStock）。入庫により増加する。

利用者視点の入口

入口URLエンドポイント期待されるふるまい
MTGバイヤー入庫モードでステータスを進めるPUT /admin/buyOrder/{id}/status.json（ネット買取）／店頭買取は O01-01 の status API買取受注のステータスを入庫待ち・入庫済みへ更新する。入庫済みへの遷移時に EC-CUBE側で入庫処理が起動する。専用の入庫APIは存在しない。
管理画面で入庫を確定するEC-CUBE管理画面の買取詳細更新ステータスを入庫済みへ遷移させると、買取在庫を商品在庫へ反映し在庫履歴を作成する（内部サービス）。
一括入庫（バッチ）入庫待ちの受注を対象とする自動入庫バッチ入庫待ちの全受注を入庫済みへ遷移させ、入庫処理を実行する。

入庫処理そのものは外部HTTPエンドポイントを持たず、EC-CUBE側の内部処理として実行される。

フロント挙動

MTGバイヤー本体の入庫モード画面・UIはリポジトリ外のため本書では仕様確定しない。EC-CUBE側で確認できるのは管理画面の買取詳細・在庫表示（M04／M07系）である。

処理フロー

入庫（ステータス遷移 入庫待ち→入庫済み）

  1. 買取受注のステータスを入庫済みへ更新する（管理画面の詳細更新、またはステータス更新API、または一括入庫バッチ）。
  2. EC-CUBE側の入庫サービスが、当該受注の買取在庫（dtb_buy_order_stock）を商品在庫（ProductStock）へ反映する。
  3. 在庫数の変化を在庫履歴（dtb_buy_order_stock_history、更新前数量・更新後数量・登録者・登録日時）として記録する。
  4. ステータスを入庫済みとして保存する。例外時はロールバックし、未反映として残す。

一括入庫（バッチ）

入庫待ち状態の全受注を対象に、上記入庫処理を順に実行し、入庫済みへ遷移させる。

集計・判定・計算

指標要点
入庫数量買取在庫（dtb_buy_order_stock）の数量を商品在庫へ加算する。商品在庫の最終的な在庫数計算は在庫管理の実装を正とする。
入庫対象ステータスが入庫待ちの買取受注を対象とする。未登録在庫がある場合の扱いはステータス（未登録在庫あり）で表す。

データ整合性

観点内容
買取在庫と商品在庫入庫により買取在庫の数量が商品在庫へ反映される。入庫履歴の更新前後数量で変化を追跡できる。
ステータスと入庫入庫処理はステータス遷移に連動する。入庫済みの受注は入庫処理が実行済みであることを表す。
二重入庫同一受注の再入庫を避けるため、ステータスにより実行済みを判定する。詳細な冪等性保証は ec-cube-enterprise の入庫サービス実装を正とする。

API/バッチ結果

種類内容
API入庫専用の外部APIは pf-api に存在しない。MTGバイヤーは買取のステータス更新APIを通じて間接的に入庫を起動し得る。
バッチ入庫待ちの受注を対象とする自動入庫バッチが ec-cube-enterprise に存在する。実行で入庫処理とステータス遷移を行う。
成功結果商品在庫の更新、買取在庫・在庫履歴の作成、ステータスの入庫済みへの更新。
失敗結果例外時はロールバックし、当該受注は未入庫（入庫待ち）として残る。
再実行時ステータス判定により実行済みは再入庫しない（実装を正とする）。

入出力

種類内容
入力買取受注ID（入庫待ち）、ステータス更新、または一括入庫の起動。
成功時出力商品在庫の増加、買取在庫・在庫履歴の作成、ステータス入庫済み。
失敗時出力入庫未実行（入庫待ちのまま）。
副作用商品在庫（ProductStock）の更新、在庫履歴の作成、ステータス変更。
