会員 — パスワード変更（パスワード再発行・再設定）

概要

会員がパスワードを失念した際に、登録メールアドレス宛に再設定用URLを送り、そのURLから新しいパスワードを設定し直す機能である。パスワードの再発行（メールアドレス入力・再設定メール送信）、再発行メール送信完了、パスワード再設定（新パスワード入力）、パスワード更新完了の4画面を、メール内のリセットキー付きURLを介して連結する。ログイン状態を前提とせず、メールアドレスとリセットキーで本人到達性を担保する。

本書は実装手順ではなく、誰が・いつ・どの条件で・結果どうなるかを読むためのリバース詳細設計とする。確認値はpf-eccube3（EC-CUBE3系）のHareruyaEcプラグインのパスワード再発行・再設定処理、再設定フォーム定義、テンプレート（Forgot/index.twig・Forgot/complete.twig・Forgot/reset.twig・Forgot/resetcomplete.twig）、エラー文言（message.ja.yml）、会員を扱うリポジトリ、再設定通知メール送信処理を正とする。

本機能のカスタマイズ区分は現行踏襲であり、画面・処理フロー・表示メッセージの挙動はpf-eccube3を参照リポとする。DB関連（テーブル名・列名・保存先）はec-cube-enterpriseを正とする。

対象はブラウザ経由のフロントに限定する。

本文ではフレームワークのコントローラ型名やメソッド名を主説明としない。本文ではルートbind名の網羅は主説明とせず、「利用者視点の入口」にHTTPメソッドとサイトルートからのパスパターンを書く。コード探索でbind名が必要なときだけ「調査補助」へ書く。

本書で扱うこと

  • パスワード再発行（メールアドレス入力・再設定メール送信）の入口と処理
  • 再設定URL（リセットキー）の妥当性・有効期限の判定順序
  • パスワード再設定（新パスワード入力・更新）の入口と処理
  • 入力項目・バリデーション・利用者に表示するメッセージ
  • 会員の存在を秘匿する完了画面の扱い

本書で扱わないこと

以下は本書では仕様確定せず、実装または別機能の設計を正とする。

  • ログイン中の会員情報編集に含まれるパスワード変更（会員情報変更機能を正とする）
  • 再設定通知メールの本文・件名（メールテンプレート管理機能を正とする）
  • ログイン認証そのもの（会員ログイン機能を正とする）

リニューアル移行時の扱い

DB関連の記述はec-cube-enterpriseを正とする。リセットキー・有効期限・パスワードは会員テーブル（dtb_customer）のreset_key・reset_expire・password／salt、再発行検索の照合はemailである。これらの列名は現行（pf-eccube3）と移行先（ec-cube-enterprise）で同一スキーマであり、同名で扱う。

挙動として移行時に保証する対象は、名称ではなく次のとおりである。

  • 登録メールアドレス宛にリセットキー付きの再設定URLを送る。
  • リセットキーが正当かつ有効期限内のときのみ新パスワードを設定できる。
  • 更新成功時にリセットキーを消去し、同一URLの再使用を不可にする。
  • 該当会員が無い場合も再発行完了画面を表示し、会員の有無を画面で区別しない。

リセットキーの有効期限の長さ・パスワードの最大長などの設定値は現行実装の確認値として扱い、移行先の設定値で上書きされる場合がある。

処理フロー

パスワード再発行を申し込む（GET/POST /forgot）

  1. メールアドレス入力フォームを生成する。未送信または検証失敗時は再発行画面を再表示する。
  2. 入力メールアドレスで有効な会員を検索する。
  3. 会員が見つからない場合は、警告ログを残し、再発行を行わずに再発行完了画面へ遷移する（会員の有無を画面で区別しない）。
  4. 会員が見つかった場合、リセットキーと有効期限（発行時刻から設定時間後）を設定して保存する。
  5. リセットキー付きの再設定URLを生成し、再設定通知メールを送信する。
  6. 送信ログを残し、再発行完了画面へ遷移する。

パスワード再設定フォームを表示する（GET /forgot/reset/{resetKey}）

  1. リセットキーの妥当性を確認する。不正な場合はエラー画面（アクセスできません）を表示して終了する。
  2. リセットキーから有効期限内の有効会員を取得する。取得できない場合はエラー画面（有効期限が切れているか、無効なURLです）を表示して終了する。
  3. 新パスワード入力フォーム（再設定画面）を表示する。

パスワードを更新する（POST /forgot/resetcomplete/{resetKey}）

  1. リセットキーの妥当性を確認する。不正な場合はエラー画面（アクセスできません）を表示して終了する。
  2. リセットキーから有効期限内の有効会員を取得する。取得できない場合はエラー画面（お探しのページが見つかりません）を表示して終了する。
  3. 送信フォームを検証する。検証失敗時は再設定画面を再表示する。
  4. 検証成功時、新パスワードを会員のソルトで暗号化して保存し、リセットキーを消去する。
  5. 更新ログを残し、更新完了画面を表示する。

再設定URL到達 時の判定順序

順序判定結果
1リセットキーが妥当か不正なら「アクセスできません。」エラー画面
2リセットキーで有効期限内の有効会員を取得できるか（表示時）取得不可なら「アクセスできません。／有効期限が切れているか、無効なURLです。」エラー画面
2'リセットキーで有効期限内の有効会員を取得できるか（更新時）取得不可なら「404 Page Not Found／お探しのページが見つかりません。」エラー画面
3新パスワードの検証に通るか失敗なら再設定画面を再表示
4上記をすべて通過パスワードを更新しリセットキーを消去、更新完了画面を表示
