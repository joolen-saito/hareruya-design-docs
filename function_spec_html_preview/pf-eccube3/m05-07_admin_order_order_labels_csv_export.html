m05-07_admin_order_order_labels_csv_export（管理画面_受注管理_送り状CSV出力）

概要

管理画面の受注一覧、および出荷指示の編集画面から、チェックした行に対応する出荷単位の情報を固定レイアウトの CSV としてダウンロード応答で返す機能である。画面上のボタン文言は翻訳キー admin.order.output_labels_Export で「送り状出力」と表示される。コメントや情報ログでは「送り状CSV」と呼ばれる。列集合は dtb_csv や店舗の配送 CSV 設定とは無関係で、サービス内のヘッダー定数で固定される。

本書は実装手順ではなく、誰が・いつ・どの条件で・結果どうなるかを読むためのリバース詳細設計とする。ec-cube-enterprise のコア実装を確認値とする。

対象はブラウザ経由の管理画面に限定する。

本機能のカスタマイズ区分は現行踏襲である。現行挙動は pf-eccube3 のHareruyaEcプラグイン実装を参照し、リニューアル移行後の挙動とDBは ec-cube-enterprise を確認値とする。DB関連の記述は ec-cube-enterprise を正とする。

コントローラのメソッド名は本文の主題としない。本文ではルートbind名やSymfonyのルートnameの網羅は主説明としない。「利用者視点の入口」にHTTPメソッドとサイトルートからのパスパターンを書く。コード探索でbind名が必要なときだけ「調査補助」へ書く。

リニューアル移行時の扱い

送り状CSV出力は現行 pf-eccube3 では HareruyaEc プラグインで実装する。受注の確定日・出荷日・注文番号などは、現行では補助テーブル dtb_order_sub に分割保持するが、移行先 ec-cube-enterprise では dtb_order に統合される。DB関連は ec-cube-enterprise を正とし、本書のテーブル・列名は移行先名で記す。

処理フロー

CSV をダウンロードする（admin_labels_export）

  1. 管理画面の認証・共通制約を通過する。
  2. set_time_limit(0) で PHP の実行時間制限を無効にする。
  3. リクエストから ids を取得する。配列でない、または空配列のとき HTTP 404 を返す。
  4. エクスポート種別文字列 labels と ids を渡し、送り状 CSV 用エクスポータを呼ぶ。
  5. エクスポータは StreamedResponse を生成する。コールバック内で共通の CSV エクスポートサービスを開き、UTF-8 の場合は BOM を付与する実装に従う。
  6. ヘッダ行を fputcsv で 1 行書く。列名はサービス定数 CSV_TYPES['labels']['header'] の順序どおりである。
  7. 受注リポジトリの「ラベル CSV 用」取得処理に出荷 ID 配列を渡し、返った各行について fputcsv する。0 件のときはヘッダのみのファイルとなる。
  8. ストリームを閉じる。
  9. ファイル名は接頭辞 labels_ と日時（YmdHis）と拡張子 .csv を連結する。
  10. 応答ヘッダに Content-Type: application/octet-stream と Content-Disposition: attachment; filename=… を付与する。
  11. リクエスト処理の流れのなかで情報ログに「送り状CSV出力完了」とファイル名が記録される。

不正なエクスポート種別をコードから渡した場合

  1. エクスポータは例外を送出する。通常の受注画面からは種別文字列 labels 以外は呼ばれない。

集計条件

指標集計の要点
商品総重量受注に結合した各受注明細について「商品マスタの重量 × 数量」を積み上げ、同一受注 ID でグループ化した合計値を 1 行に載せる。出荷 ID だけがクエリの絞り込み条件である。

データ取得クエリの要点

  • 受注を起点に、都道府県マスタ・会員・受注明細・商品・出荷・配送方法を結合する。
  • 出荷の主キーが ids に含まれる行に限定する。
  • 受注 ID でグループ化するため、同一受注に複数の出荷が ids に含まれる場合、SQL 上は 1 行に畳み込まれる。データ行の配送先などは受注に紐づく出荷コレクションの先頭要素を参照する実装であり、どの出荷 ID に対応する行かと一致しない場合がある（実装を確認値とする）。
  • 受注明細と商品の内部結合のため、該当する明細が存在しない受注は結果に現れない。
