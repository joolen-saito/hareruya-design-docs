F04-03（注文時の配送先登録・変更）

概要

ご注文方法指定の途中でお届け先を新規登録または変更する機能である。お届け先編集画面で配送先名称・氏名・氏名カナ・電話番号・国・郵便番号・住所・会社名を入力し、確認画面を経てアドレス帳へ登録し、登録したお届け先を当該注文の配送先として選択した状態でご注文方法指定へ戻る。

本書は実装手順ではなく、誰が・いつ・どの条件で・結果どうなるかを読むためのリバース詳細設計とする。確認値はpf-eccube3（EC-CUBE3系）のHareruyaEcプラグインの購入手続き中の配送先編集・確認処理、テンプレート（Shopping/delivery_edit.twig・Shopping/delivery_confirm.twig）、配送先サービスを正とする。

本機能のカスタマイズ区分はカスタマイズであり、挙動の確認は現行リポ（pf-eccube3）の実装を参照する。DB関連の記述はリニューアル移行先の ec-cube-enterprise を正とする。

対象はブラウザ経由のフロント（購入手続き中の配送先登録・変更）に限定する。フロントのルートはロケールセグメント付きで提供され、サイトルートからのパスパターンは/{_locale}配下になる（/{_locale}はサービスプロバイダのマウントで決まる確認値）。

コントローラのメソッド単位の解剖は本文の主題としない。本文ではルートbind名の網羅を主説明とせず、「利用者視点の入口」にHTTPメソッドとサイトルートからのパスパターンを書く。

本書で扱うこと

  • 購入手続き中のお届け先の新規登録・編集画面の表示と入力項目
  • 入力→確認→登録の段階遷移と、登録後の配送先選択への遷移
  • お届け先登録数の上限判定
  • 国と都道府県の整合検証

本書で扱わないこと

以下は本書では仕様確定せず、実装または別機能の設計を正とする。

  • ご注文方法指定本体の表示・配送業者・お支払い方法・注文確定（F04-02 注文情報の入力・確認・注文を正とする）
  • マイページの配送先登録・変更（マイページ配送先機能を正とする）
  • 注文確定後の購入完了処理（カートの決済〜購入完了機能を正とする）
  • 住所自動入力の外部サービス仕様

リニューアル移行時の扱い

配送先名称（address_name）は、現行（pf-eccube3）では補助テーブル dtb_customer_address_sub に分離して保持するが、移行先（ec-cube-enterprise）には dtb_customer_address_sub が存在せず、お届け先住所テーブル dtb_customer_address の address_name 列（長さ128）に統合されている。本書のDB記述は移行先（統合後の dtb_customer_address.address_name）を主とし、現行の補助テーブル名を括弧で添える。お届け先住所の氏名・氏名カナ・電話番号・国・郵便番号・都道府県・住所・会社名は移行先でも dtb_customer_address で同名に扱う。登録上限・配送先反映の挙動は現行リポ（pf-eccube3）の実装を確認値とする。

処理フロー

お届け先編集画面を表示・送信する（/{_locale}/shopping/delivery/{id|new}/edit）

  1. 登録上限判定を行う。新規（IDなし）でアドレス帳が上限に達していれば、上限超過のエラーを出してご注文方法指定へ戻す。
  2. 編集対象の住所を取得または新規生成し、配送先名称を初期化したフォームを組む。
  3. 入力変更の再描画指定がある、または未送信・検証不備のときは編集画面を表示する。
  4. 送信が妥当なときは確認画面を表示する。

確認画面から登録する（/{_locale}/shopping/delivery/{id|new}/confirm）

  1. 登録上限判定を行う。上限超過ならご注文方法指定へ戻す。
  2. 住所を登録し、お届け先入力フォームを組む。
  3. 戻る送信でなく、かつ検証通過のときは配送先名称を登録して永続化する。
  4. セッションの受注の最初の配送に対して、登録したお届け先IDをセッションとCookieへ保存し、当該注文の配送先選択（お届け先反映）へ遷移する。
  5. 戻る送信や検証不備のときは編集画面を表示する。
