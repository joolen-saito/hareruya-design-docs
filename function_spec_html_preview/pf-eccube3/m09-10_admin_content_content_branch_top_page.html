M09-10（支店トップページ管理）

概要

支店トップページ管理は、支店ごとのトップページに表示するバナー画像、バナーに紐づくタグ、タイル配置、タイル属性、タイルタグを管理者が編集する機能である。対象支店を選択して画面を開き、支店共通設定を適用するか、支店固有のトップページ設定を保存するかを選ぶ。リニューアル後は限定品タグ2項目を画面の表示・送信対象から除外する。

本書は実装手順ではなく、誰が・いつ・どの条件で・結果どうなるかを読むためのリバース詳細設計とする。確認値は../ec-cubeの管理画面トップページ管理コントローラ、フォーム、Twig、支店トップ表示コントローラを正とする。

本機能のカスタマイズ区分はカスタマイズであり、挙動は現行リポ（ec-cube のカスタマイズ実装）を正とし、DB関連（テーブル名・列名・保存先）は ec-cube-enterprise を正とする。dtb_base_info・dtb_tile・mtb_tile_type・dtb_tag は ec-cube-enterprise にも実装があり、dtb_tile の支店参照列が現行と異なる。差分は「リニューアル移行時の扱い」に集約する。

管理画面プレフィックスは設定キーeccube_admin_routeで決まる。本書ではパスを/{admin_route}/のプレースホルダで示す。

本書で扱うこと

  • 支店を選択して支店トップページ管理画面を表示すること
  • 支店共通設定を適用するフラグだけを保存すること
  • 支店固有のバナー画像、バナータグ、タイル設定を保存すること
  • 画像ファイルをS3のbanner/top/{支店省略名}配下へアップロードし、既存画像を置き換えること
  • タイル位置の重複、タイル属性とタグの組み合わせを検証すること
  • 管理画面JavaScriptによるサムネイル表示、支店共通設定時の入力無効化、ピックアップ商品選択時のタグ入力無効化

本書で扱わないこと

  • タグマスタそのものの登録・編集
  • 商品に対するタグ付け
  • S3サービスの認証設定、バケットポリシー、実ファイル配信経路
  • 支店マスタの登録・編集
  • フロント支店トップページのHTML詳細レイアウト
  • 管理画面ログイン、管理権限、CSRF共通処理の詳細

リニューアル移行時の扱い

本機能はカスタマイズ区分がカスタマイズである。挙動は現行リポ（ec-cube のカスタマイズ実装）を正とし、DBスキーマは移行先 ec-cube-enterprise を正とする。ec-cube-enterprise の各エンティティで確認した差分を以下に記す。

タイル配置ランダムフラグdtb_base_info.random_tile_flgdtb_base_info.random_tile_flg（DB列は同一。リニューアル後の管理画面では項目除去）

フロントエンド側ビジネスロジック

起点参照する値判定順序更新する表示値・送信値サーバ側再検証
支店選択変更支店選択セレクトの値。空なら0。変更後の値を取得し、管理画面のトップページ管理URL末尾に付与する。画面遷移だけを行い、フォーム値は送信しない。遷移後のGETでURLのIDに対応する支店を読み込む。
画像ファイル選択ファイル入力の選択ファイル、既存バナー画像hidden値。選択ファイルが0件なら何もしない。1件以上なら既存バナー画像hidden値を空にし、一時URLでサムネイルを表示する。送信時は新しいファイルがimage_fileに入り、既存画像パスは空になる。サーバ側でファイルサイズ5MB、許可拡張子、S3保存可否を検証する。
サムネイル削除サムネイル削除アイコン、ファイル入力、既存バナー画像hidden値。削除アイコン押下時にサムネイルを消し、ファイル選択欄を再表示する。ファイル入力と既存バナー画像hidden値を空にする。支店共通設定が無効で画像が空の場合、サーバ側でバナー画像エラーになる。
支店共通設定切替支店共通設定チェックボックス。チェックありならトップページ固有設定の入力を無効化し、チェックなしなら再度有効化する。画像ファイル、バナータグ、タイル設定の各入力のdisabled属性を切り替える。サーバ側ではPOST値の共通設定フラグが真なら他項目を保存せず、共通設定フラグだけ保存する。
タイル属性変更各タイルのタイル属性ID。ピックアップ商品IDは4。選択値がピックアップ商品なら同じ行のタイルタグを空にして無効化する。ピックアップ商品以外ならタイルタグを有効化する。タイルタグの選択値とdisabled属性を切り替える。サーバ側でもピックアップ商品以外でタグが空なら保存せずエラーにする。
画面初期化既存タイルフォーム数、リニューアル後タイル位置4枠、支店共通設定、各タイル属性。不足タイルフォームを4枠まで生成し、生成後に共通設定とタイル属性に応じてdisabled制御を実行する。未設定タイルの送信項目を追加し、タイル位置を上段左、上段右、下段左、下段右の順で初期化する。サーバ側ではタイル位置重複とタグ必須条件を検証する。

処理フロー

支店トップページ管理画面を表示する

  1. URLの支店IDで支店情報を取得する。
  2. 支店情報をデータとしてトップページ管理フォームを生成する。
  3. 送信値がある場合はフォームへ反映する。
  4. 支店IDが0以外なら支店選択欄に対象支店を設定する。
  5. フォームビューと支店IDをテンプレートへ渡し、トップページ管理画面を表示する。

支店共通設定を保存する

  1. POSTされたcommon_setting_flgを真偽値に変換する。
  2. 対象支店の支店共通設定フラグへ保存する。
  3. フラグが有効の場合は支店情報だけを永続化してflushする。
  4. 保存完了メッセージを設定し、同じ支店のトップページ管理画面へリダイレクトする。
  5. バナー画像、バナータグ、タイル設定は保存しない。

支店固有設定を保存する

  1. POSTされたフォーム値をトップページ管理フォームへ反映する。
  2. バナー画像の上書き処理を行う。
  3. 既存画像をそのまま使う場合は既存画像パスを保存値とする。
  4. 新規画像がある場合は既存画像をS3から削除し、新規画像をS3のbanner/top/{支店省略名}へアップロードして保存後パスを取得する。
  5. 画像が空、またはS3保存に失敗した場合はエラーメッセージを設定し、DB保存せず同じ画面へ戻る。
  6. タイルごとにタイル位置の重複を検査する。重複があれば保存せずエラーで戻る。
  7. タイル属性がピックアップ商品以外でタイルタグが空なら、保存せずエラーで戻る。
  8. 新規タイルには対象支店を設定する。
  9. 対象支店へタイルを追加し、バナー画像パスとバナータグを設定する。
  10. 支店情報を永続化してflushする。
  11. 保存完了メッセージを設定し、同じ支店のトップページ管理画面へリダイレクトする。

支店トップ表示への反映

  1. フロントトップ表示は現在の支店情報を取得する。
  2. 支店共通設定フラグが有効な場合は、共通店舗IDの支店情報を表示元として使う。
  3. 表示元支店のタイルを読み込み、タイル属性がピックアップ商品ならピックアップ商品を3件取得する。
  4. ピックアップ商品以外のタイルはタイルタグがあればタグに紐づく商品規格を3件取得し、タグがなければ空配列にする。
  5. 未設定のタイル位置は、リニューアル後の4枠（上段左、上段右、下段左、下段右）を対象に補完する。
  6. リニューアル後の支店トップページではタイル配置ランダム化を行わない。

業務ルール・計算

本機能では金額・税・ポイント計算を行わない。主な業務ルールは支店共通設定、画像保存、タイル位置、タイル属性とタグの整合である。

観点内容
支店共通設定優先支店共通設定フラグが有効なPOSTでは、トップページ固有設定を検証・保存せず、共通設定フラグだけを保存する。
バナー画像必須支店共通設定が無効の場合、既存画像を維持するか新規画像を選択する必要がある。既存画像も新規画像もない場合は保存しない。
画像置換新規画像を選択した場合、既存画像がS3に存在すれば削除してから新規画像をアップロードする。
タイル数画面上は4つのタイル位置を扱う。既存タイルが4件未満でもJavaScriptで不足分を生成する。
タイル位置4つのタイルは異なる位置を選択する必要がある。重複があれば保存しない。
タイルタグタイル属性がピックアップ商品の場合はタグを使わない。ピックアップ商品以外はタグ必須とし、空なら保存しない。
フロント表示件数支店トップ表示では各タイルの商品規格を最大3件取得する。
未設定タイル補完フロント表示時に未設定のタイル位置があれば、リニューアル後の4枠を対象に補完する。補完条件は支店トップページ側の表示設計を正とする。
ランダム配置リニューアル後の支店トップページではタイル配置ランダム化を行わない。現行のランダム配置フラグは移行後の表示制御対象にしない。

排他制御・トランザクション

観点内容
トランザクション境界明示トランザクションは開始しない。支店情報とタイルは1回のflushでDBへ反映する。支店共通設定だけを保存する分岐も1回のflushで確定する。
S3とDBS3画像削除・アップロードはDBのflushより前に実行する。S3操作とDB保存は同一トランザクションではないため、S3操作後にDB保存で例外が起きてもS3操作はロールバックされない。
ロック支店情報、タイル、タグに対する行ロック・悲観ロック・楽観ロック・ロックファイルは使用しない。同じ支店を同時更新した場合は後から確定したDB値が残る。
例外時flush前の例外ではDB更新は確定しない。flush後の例外では確定済みDB更新は戻らない。S3で削除・保存済みのファイル操作はDBロールバック対象ではない。
