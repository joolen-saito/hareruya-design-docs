イベント管理 — イベント編集/削除

刷新後は実装不要本節は現行実装（pf-eccube3）からのリバースです。次の記述は Excel基本設計により廃止されており、刷新後に実装する必要はありません。

  • チーム人数 は チーム戦フラグ（dtb_event.is_team_battle、真偽） へ変更（0214 イベント編集 識別ID:1-12）これに伴い実装不要: チームメンバーのメールアドレス・席次の入力／メールのみの仮選手（dtb_player）の作成／チームメンバー招待メールの送信／未承認（confirm_flg=UNCONFIRMED）での申込選手登録／招待リンクからのチームプレイヤー認証（events_team_player_activate）
  • 支払方法の選択肢「コンビニ決済」 は クレジットカード決済のみ（コンビニ決済を削除） へ変更（0214 イベント編集 識別ID:1-13）これに伴い実装不要: B13-02 コンビニ支払チェックバッチ（0413で明示的に廃止）
  • 備考（日）・備考（英） は廃止し、フリー入力エリア1〜3（項目名・内容の日英、free_text_area1〜3）へ再編（0214 イベント編集 識別ID:2-3）

業務ロジック

編集画面の表示

登録済みイベントの編集画面は、当該イベントの日程を開始日時の降順で並べ、日程ごとの申込人数を集計して表示する。新規登録画面は空のフォームを表示し、支払方法の初期値をクレジットカードとする。

支払方法の選択肢は、イベント申込で利用できる支払方法に絞り、ランク昇順で並べる。

更新の判定順序

順序判定結果
1パスの識別子のイベントが存在するか存在しなければアクセス拒否とする
2申込済みの日程があり、送信された支払方法が現在値と異なるか該当すれば支払方法変更不可のエラーを表示し、直前画面へ戻す
3入力の検証失敗なら登録失敗のエラーを表示し、編集画面を再表示する
4保存成功なら完了メッセージを表示し、編集画面へ戻す

新規登録は、検証に成功した場合にイベントを登録し、登録したイベントの編集画面へ遷移する。

イベント削除の判定順序

順序判定結果
1パスの識別子のイベントが存在するか存在しなければアクセス拒否とする
2なりすまし対策トークン不正なら共通のアクセス拒否として扱う
3日程が残っているか1件でも残っていれば削除せず、削除不可のエラーを表示して直前画面へ戻す
4削除完了メッセージを表示し、検索結果ページへ戻す。ページ番号は保持した検索ページ番号、無ければ1ページ目とする

日程一括削除の判定順序

順序判定結果
1削除対象の日程識別子が空でないか空なら該当なしとして扱う
2当該イベントに該当する日程が存在するか無ければ該当なしとして扱う
3なりすまし対策トークン不正なら共通のアクセス拒否として扱う
4各日程にデッキ登録があるかあればデッキ登録のエラーを表示し、直前画面へ戻す
5各日程に申込があるかあれば申込のエラーを表示し、直前画面へ戻す
6削除日程削除の完了メッセージを表示し、編集画面へ戻す

登録者と入力値の扱い

新規登録・更新の保存前に、ログイン中の管理者を登録者として設定する。参加費・定員・チーム人数は入力値をそのまま整数として保存し、金額計算・税計算・丸めは行わない。

  • Excel基本設計 0214 識別ID:1-13 により廃止。刷新後は実装しない。現行実装のふるまいは本書に残すが、刷新後の実装・テストの対象外とする
  • Excel基本設計 0214 識別ID:2-3 により廃止。刷新後は実装しない。現行実装のふるまいは本書に残すが、刷新後の実装・テストの対象外とする

エラー内容処理

入出力

種類内容
入力編集画面・新規登録画面の表示要求、イベント登録・更新の送信（なりすまし対策トークンを含む）、イベント削除の送信、日程一括削除の送信
成功時出力更新・登録は編集画面への遷移と成功メッセージ。イベント削除は検索結果ページへの遷移と成功メッセージ。日程一括削除は編集画面への遷移と成功メッセージ
失敗時出力検証失敗・支払方法変更不可・削除不可は該当のエラーメッセージと、編集画面の再表示または直前画面への復帰。存在しない識別子はアクセス拒否または該当なし
