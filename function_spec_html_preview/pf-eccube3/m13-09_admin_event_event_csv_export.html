M13-09（CSVダウンロード）

概要

イベント管理のイベント申込一覧から、申込済みのイベント申込情報をCSVファイルとしてダウンロードする機能である。管理者がイベント申込一覧で絞り込んだ検索条件（セッション保持）に従い、申込・プレイヤー情報をストリーミングでCSV出力する。

本書は実装手順ではなく、誰が・いつ・どの条件で・結果どうなるかを読むためのリバース詳細設計とする。確認値はpf-eccube3（EC-CUBE3系）のHareruyaEcプラグインのイベント申込CSV出力処理、申込CSV種別の出力項目定義、コアのCSV出力サービスを正とする。

本機能のカスタマイズ区分はカスタマイズである。挙動の参照リポはpf-eccube3（HareruyaEcプラグイン）の現行実装とし、DB関連（永続化先のテーブル名・列名、DBカラム節）はec-cube-enterpriseを正とする。現行と移行先でスキーマが異なる箇所はリニューアル移行時の扱いに集約する。

対象はブラウザ経由の管理画面に限定する。

本文ではフレームワークのコントローラ型名やメソッド名を主説明としない。管理画面プレフィックスは環境により変わり、プラグイン設定のadmin_routeで決まる。「利用者視点の入口」にHTTPメソッドとサイトルートからのパスパターンを書く。

本書で扱うこと

  • イベント申込一覧のCSV出力（全件・検索条件適用）
  • イベント詳細指定でのCSV出力
  • 出力対象データ、出力項目、文字コード、ファイル名、抽出条件
  • 雛形（テンプレート）CSVのダウンロードとの区別

本書で扱わないこと

以下は本書では仕様確定せず、実装または別機能の設計を正とする。

  • イベント申込一覧の検索フォーム・絞り込み条件の業務定義（イベント申込一覧機能を正とする）
  • CSV出力項目の設定・編集（申込CSV出力項目設定を正とする）
  • 一括CSV登録（取込）の仕様（M13-13を正とする）
  • 雛形CSVの列内容そのものの妥当性（M13-13の取込仕様を正とする）

リニューアル移行時の扱い

CSV出力の抽出・出力項目の挙動は現行（pf-eccube3）を正とし、出力元の列名は移行先（ec-cube-enterprise）を正とする。出力項目は申込CSV種別の定義に従い、移行で論理的な出力項目は変わらない。

観点現行（pf-eccube3）移行先（ec-cube-enterprise）
論理削除dtb_event_entry・dtb_entry_playerともdeleted_atによる論理削除同一方式（deleted_atによる論理削除を維持）
申込の主キー列dtb_event_entry.event_entry_iddtb_event_entry.id（主キー列名をidに統一。参照列event_detail_id・payment_id・entry_status_id・paying_customer_idは同名維持）
申込プレイヤーの主キー列dtb_entry_playerの識別列dtb_entry_player.id（参照列event_entry_id・player_idは同名維持）
支払期限列の有無は実装によるdtb_event_entry.payment_limitを保持

会員・プレイヤーの論理削除済みデータを出力対象に含めるソフトデリート無効化の挙動は現行を正とする。移行先でも論理削除（deleted_at）を維持するため同じ方針で扱える。

申込CSV種別イベント申込の出力項目・並びを定義したCSV種別。本機能の出力項目はこの種別で決まる。

デッキ登録検索モード申込一覧の検索モードの一種。出力時は申込ではなくデッキ情報を起点に対象を取得する。

処理フロー

イベント申込CSVを出力する（/%eccube_admin_route%/entry/export、/%eccube_admin_route%/entry/{eventDetailId}/export）

  1. 管理画面の認証・権限を通過する。
  2. ソフトデリートフィルタを調整し、会員は論理削除済みでも対象に含め、プレイヤーはソフトデリート無効化で対象に含める。
  3. 実行時間制限を無効化し、SQLロガーを無効化してストリーミング出力に備える。
  4. 申込CSV種別で出力サービスを初期化し、BOMとヘッダ行を出力する。
  5. 申込一覧の検索条件セッションadmin.event_entry.searchをフォームに流し込み、ソートをdefault・並び順をASCに固定する。
  6. 検索モードがregistedDeckでなければプレイヤー（申込プレイヤー）起点のクエリ、registedDeckであればデッキ起点のクエリで対象データを取得する。
  7. 対象行ごとに、申込プレイヤー・イベント申込・プレイヤー・イベント詳細・デッキ・イベントの関連を解決し、CSV出力項目に合致する値を1行ずつ出力する。
  8. ファイル名event_entry_<YmdHis>.csvを添付名としてレスポンスを送出し、ファイル名をログに記録する。

雛形CSVを出力する（/%eccube_admin_route%/entry/entry_csv_template）

  1. 一括登録用ヘッダ定義の見出し行のみをBOM付きで1行出力する。
  2. 添付名event_entry.csvでダウンロードする。区切り文字はcsv_export_separator（確認値カンマ）を用いる。

集計条件

指標集計の要点
出力対象申込一覧の検索条件セッションで絞り込んだイベント申込（申込プレイヤー単位）。イベント詳細指定時は当該詳細に絞る。

出力項目申込CSV種別の出力項目定義に従う。

業務ルール・計算

項目内容
出力項目の適用申込CSV種別の定義に従って出力項目・並びを決める。各出力項目は申込プレイヤー・イベント申込・プレイヤー・イベント詳細・デッキ・イベントのいずれかから最初に非NULLで得られた値を採用する。
文字コードBOMを先頭に付与する。区切り文字はcsv_export_separator（確認値カンマ）。
ファイル名一覧・詳細指定ともevent_entry_<YmdHis>.csv。雛形はevent_entry.csv。

本機能は画面上の入力フォームを持たない。出力項目は申込CSV種別の定義による。本機能では金額計算・件数の丸めを行わない。

データ整合性

観点内容
一覧表示とCSVCSVは申込一覧の検索条件セッションを再適用するため、直前に一覧で確定した絞り込みと同じ母集合を対象とする。並び順のみ出力用に固定する。

出力中の更新ストリーミング出力中の他者更新は保証しない。出力開始時点のクエリ結果を正とする。
