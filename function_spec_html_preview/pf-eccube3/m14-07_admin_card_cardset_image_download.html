カードセット管理 — 収録カード画像 ZIP ダウンロード（セット別／言語別）

概要

HareruyaEc プラグインが管理画面の「カードセット管理」一覧から、チェックで選んだカードセット（または未選択時はプロモーション系の特殊扱い）に紐づくカード画像をオブジェクトストレージから取得し、ローカル作業用ディレクトリへ書き出したうえで単一 ZIP（ファイル名 card_image.zip）としてブラウザに返す機能である。画面上は「画像ダウンロード(セット別)」と「画像ダウンロード(言語別)」の 2 ボタンがあり、ZIP 内のディレクトリ構造だけが異なる。

本書は実装手順ではなく、誰が・いつ・どの条件で・結果どうなるかを読むためのリバース詳細設計とする。pf-eccube3 に配置された HareruyaEc プラグインのソースを確認値とする。

本機能のカスタマイズ区分は現行踏襲である。現行挙動は pf-eccube3 の HareruyaEc プラグインを参照し、永続化に関わるテーブル名・列名などのDB関連は ec-cube-enterprise を正とする。

対象はブラウザ経由の管理画面に限定する。

コントローラのメソッド名は本文の主題としない。本文ではルートbind名やSymfonyのルートnameの網羅は主説明としない。「利用者視点の入口」にHTTPメソッドとサイトルートからのパスパターンを書く。コード探索でbind名が必要なときだけ「調査補助」へ書く。

リニューアル移行時の扱い

DB関連の記述は ec-cube-enterprise の実装を正とする。ダウンロードが参照するカード画像・カード詳細・カードセットのテーブル名・列名は現行（pf-eccube3）と移行先（ec-cube-enterprise）で同一スキーマである。

観点現行（pf-eccube3）移行先（ec-cube-enterprise）
カード画像mtb_card_image（url/language_id/dead_link_flg）同一スキーマ（mtb_card_image、列名一致）。
カード詳細mtb_card_detail（cardset_id、ホイル相当フラグ）同一スキーマ（mtb_card_detail）。
カードセットmtb_cardset（略称コード等）同一スキーマ（mtb_cardset）。

ZIP 構成・ファイル名規則・デッドリンク更新の挙動は現行（pf-eccube3）を参照する。永続化で書き換わる mtb_card_image.dead_link_flg は移行先でも同名列である。

いずれかのダウンロードボタンを、チェック無しで押す同左（実際に送信されるルートは押したボタンの formaction）確認ダイアログでプロモカード一覧相当のダウンロードへ進むか尋ねる。進む場合はカードセット ID として 0 を含む扱いで POST が進む想定だが、実装値として確認ダイアログ確定後の戻り値に誤記があり得る（フロント挙動を参照）。

一覧フォームの既定 action は POST /{admin_route}/cardset（一覧表示）であるが、上記 2 ボタンは formaction でそれぞれのダウンロードルートへだけ差し替えて送信する。

フロント挙動

観点内容
表示要素「画像ダウンロード(言語別)」「画像ダウンロード(セット別)」は一覧ボックス上部に並ぶ。各行に name="cardsetIds[]" のチェックボックスがある。表頭 #allCheck で [cardsetId] 属性を持つチェックボックスを一括オンオフする。
JS 挙動上記 2 ボタンのクリック時、チェックが 1 つも無ければ confirm('プロモカード一覧をダウンロードしますか?') を出す。チェックがあればそのまま送信を許可する。確認で OK のときに return tre と書かれており、識別子 tre は一般的な JavaScript では未定義であり、実行時は例外または意図しない戻り値になり得る（実装を確認値とする）。
CSS・レイアウト本機能専用の追加スタイルはない。
モーダル・ポップアップネイティブの confirm のみ。Bootstrap モーダルは使わない。

フォーム種別はカードセット用フォームであり、CSRF 用トークンフィールドがテンプレートで出力される。

処理フロー

共通（両ルート）

  1. 管理画面の認証・共通制約を通過する。
  2. リクエストから cardsetIds を読む。PHP の empty() が真なら配列 [0] に置き換える。
  3. set_time_limit(0) で PHP の実行時間制限を無効にする。
  4. オブジェクトストレージアクセス用サービスを生成し、アップロード先ディレクトリ接頭辞として文字列 set/ を設定する。
  5. 相対パス名 download がディレクトリでなければ 0777 で再帰的に作成する（umask を一時変更）。
  6. download 配下のファイル・サブディレクトリをすべて削除する（空のツリーにする）。
  7. 言語別のみ、この後すぐに「カード画像が 1 件以上存在する言語マスタ」をすべて列挙し、各言語コード名のサブディレクトリを download 直下に作成する。

ZIP を返すまで（セット別、admin_cardset_download）

  1. 選択された各カードセット ID について次を繰り返す。
  2. ID が実在するカードセットなら、サブディレクトリ download/{セット略称コード} を作成し、そのパス文字列を $dirName とする。実在しない場合はダミーのプロモーション集合として扱い、プロモーション名（英字）ごとに download/{その英字} を作成する。
  3. 当該 ID を引数にカード詳細を取得する。ID が 0 のときは cardset_id IS NULL かつカード画像およびプロモーションが結合できる行に限定されるクエリになる。
  4. カード詳細が 0 件なら、フラッシュに admin.cardset.download.failed.set_not_exist_card を積み（セット名はダミー時は固定文言側のデータ）、セッションキー eccube.admin.cardset.page_no（無ければ 1）のページへ admin_cardset_page にリダイレクトして終了する。
  5. 各カード詳細について、紐付くカード画像を language_id 昇順で取得する。
  6. 画像が無ければそのカード詳細はスキップする。
  7. ID が 0 の場合は $dirName を download/{当該カード詳細のプロモーション英名} に差し替える。
  8. 各カード画像についてオブジェクトストレージから download サブツリーへ保存を試みる。ローカルファイル名は「カード詳細 ID + .jpg」であり、カード詳細のホイル相当フラグが真なら先頭に F を付ける。
  9. 保存に成功しなかった場合、デッドリンクフラグが偽なら真へ更新して即時永続化する。成功しデッドリンクフラグが真なら偽へ戻して即時永続化する。
  10. ZIP アーカイブをパス download/card_image.zip に対して開くたびに、保存に成功したファイルがあれば ZIP に追加し、continue 2 でカード詳細の残り画像ループを打ち切る（同一カード詳細で複数言語があっても、先に保存に成功した 1 枚だけが ZIP に載る）。
  11. いずれの画像でも保存に至らなかったカード詳細では、フラッシュに admin.download.card.not_found を積む（カード詳細 ID を埋め込む）。
  12. 内側のループを抜けたら ZIP をクローズする。

ZIP を返すまで（言語別、admin_cardset_download_lang）

  1. 選択された各カードセット ID について、カード詳細をセット別と同じ取得経路で繰り返す。
  2. カード詳細が 0 件のセットはエラーにせず continue で次の ID へ進む。
  3. 各カード詳細の各カード画像について、保存先ディレクトリを download/{画像の言語コード} とし、オブジェクトストレージから同じファイル名規則で保存する。
  4. デッドリンク更新は即時ではなく、リストに溜め、全 ID 処理後にまとめて永続化する（同一画像行が複数回リストに載った場合は後勝ちになり得る）。
  5. 保存成功したファイルはすべて ZIP に追加する（セット別のような 1 枚打ち切りはしない）。
  6. 各 ID の処理の末尾で ZIP をクローズする。

応答（両ルート共通）

  1. download/card_image.zip が存在しなければ、フラッシュに admin.cardset.download.failed.image_not_exist を積み、admin_cardset_page（ページ番号はセッション確認値）へリダイレクトする。
  2. 存在すればロケールを ja_JP.UTF-8 に設定し、sendFile で本体を返す。Content-Type は aplication/octet-stream; と記載されている（スペルは実装どおり）。Content-Disposition は RFC 5987 形式の filename* で ZIP のベース名を UTF-8 でエンコードして付与する。

コントローラ終了後

  1. イベント eccube.event.controller.admin_cardset_download.finish がフックされており、セット別ルートの処理完了後に download 配下の内容を再度すべて削除する。言語別ルート名に対応する finish イベントは event 定義に無い。

集計条件

本機能では売上・件数集計などの業務集計は行わない。ZIP に含まれるファイル数は、選択セット数・各セットのカード詳細数・画像の有無・オブジェクトストレージ取得の成否・セット別モードでは「カード詳細あたり最大 1 枚」に依存する。

業務ルール・計算

項目内容
対象カード詳細findByCardsetId の結果。ID が 0 のときはカードセット NULL のカード詳細に限定され、カード画像およびプロモーションが無い行はクエリ段階で除外される。
カード画像の列挙順リポジトリは language_id 昇順で並べる。エンティティ定数上は日本語 ID が英語 ID より小さいため、昇順では日本語側が先に列挙される。コントローラコメントに「英語優先」とあるが、並べ替え SQL は昇順のみであり、コメントとコードが一致しない場合は実装を確認値とする。
ローカルファイル名{カード詳細ID}.jpg またはホイル時 F{カード詳細ID}.jpg。拡張子はサービス側で固定文字列 .jpg としている（オブジェクトストレージ側キーの拡張子とは独立）。
ホイル除外の有無コメントに「非プロモ、プレリプロモのフォイルは除外する」とあるが、ダウンロードループ内ではホイルフラグに応じてファイル名へ F を付けるのみで、画像行をスキップする条件は見当たらない。実装を確認値とする。
