商品管理 — 買取/販売価格履歴（検索・一覧・CSV出力）

概要

管理画面「商品管理」配下から開く、dtb_price_history を対象とする買取価格・販売価格・基準価格の変動履歴の検索・一覧表示および CSV ダウンロードである。キーワード・商品属性・日付レンジ・変更後の価格帯などで絞り込み、ページ分割して表示する。検索ビューデータ・ページ番号・表示件数・ソート項目の文字列はセッションにも保存される一方、クエリ本体の並びは実装上ほぼ固定である。

本体実装はアプリケーションコード（src/Eccube 配下の管理画面ルートおよびテンプレート）に置かれ、eccube_nav.yaml で商品メニューの子として参照される。

本書は実装手順ではなく、誰が・いつ・どの条件で・結果どうなるかを読むためのリバース詳細設計とする。

本機能のカスタマイズ区分は現行踏襲である。挙動の参照は現行リポ pf-eccube3 の HareruyaEc プラグイン実装を正とし、DB関連は ec-cube-enterprise を正とする。現行と移行先のスキーマ差は「リニューアル移行時の扱い」へ集約する。

対象はブラウザ経由の管理画面のみとする。

本文では Symfony のコントローラ型やメソッド名を主題としない。本文ではルートbind名やSymfonyのルートnameの網羅は主説明としない。「利用者視点の入口」にHTTPメソッドとサイトルートからのパスパターンを書く。コード探索でbind名が必要なときだけ「調査補助」へ書く。

リニューアル移行時の扱い

DB関連の正典は ec-cube-enterprise とする。挙動は現行リポ pf-eccube3 の HareruyaEc プラグインを正とし、移行先との差は本節へ集約する。

観点現行（pf-eccube3）移行先（ec-cube-enterprise）
価格履歴の主キー列dtb_price_history の主キーは price_history_id。主キーは id。本書の DBカラム・JOIN 記述は移行先の id を正とする。
基準価格の列dtb_price_history に standard_price／old_standard_price 列が無く、販売価格・買取価格の履歴のみを保持する。standard_price（基準価格）と old_standard_price（変更前基準価格）が加わる。本書の基準価格レンジ検索・基準価格列は移行先の列を正とする。
商品規格への参照product_class_id は商品規格の主キー product_class_id を参照する。product_class_id は商品規格の主キー id を参照する（参照先マスタの主キー名が id へ変更）。列名 product_class_id 自体は同じ。
並び順・登録者・日時sell_price／old_sell_price／buy_price／old_buy_price／member_id／create_date を保持。並びは作成日時降順。同名の列。同一スキーマである（基準価格列を除く）。

dtb_price_history の product_class_id／sell_price／old_sell_price／buy_price／old_buy_price／member_id／create_date は現行と移行先で同名である（主キー名と基準価格列の差分を除く）。

処理フロー

初回にフォームだけ表示する（GET m03-23_admin_product_product_buy_sale_price_history）

  1. 管理画面の認証および共通処理を通過する。
  2. 本機能の検索フォーム種別で空入力のフォームを生成して Twig を返す。pagination は null を渡す。表示件数候補はコントローラ内配列により 10,50,100,300,500,1000,2000,10000,12000。初期表示件数字列は設定 eccube_default_page_count の文字列表現。

検索および一覧を更新する（POST または復元済みセッション付き GET m03-23_admin_product_product_buy_sale_price_history_search）

  1. 管理画面の認証および共通処理を通過する。
  2. page_no が 1 以上のとき、GET クエリに product_id または code があれば、セッションの検索ビューデータ配列へ同キーの値をマージして保存してから処理を進める（送信ボディ側の入力ではない）。
  3. 管理画面共通の検索トレイトの search に従い、ページ番号セッション、ソート用文字列、order、page_count、検索ビューを載せたセッションキー関連を読み書きする。
  4. フォームの handleRequest で送信が無いときは、セッションに保存済みの検索ビューデータを FormUtil::submitAndGetData でフォームへ再入力し、その配列データをクエリ入力として使う。
  5. dtb_price_history を基点に検索入力から組んだクエリビルダをページャへ渡し、一覧と送信後の検索フォームビューを返す。
  6. 表示ページが最終ページのみを指しており総件数の境界上で行がなくなった場合、トレイト内の補正で 1 つ前のページ番号へ再ページングする。

CSV をダウンロードする（GET m03-23_admin_product_product_buy_sale_price_history_export）

  1. 管理画面の認証を通過する。
  2. セッションキー eccube.admin.product.buy_sale_price_history.search が無い場合、管理フラッシュへ「検索条件を指定してからCSVをダウンロードしてください。」を積み、GET /{admin_route}/product/buy_sale_price_history へHTTP リダイレクト応答を返す。
  3. PHP の実行時間制限を無制限へ寄せ、getQueryBuilderForExport で一覧と同じクエリを組む（フォーム種別作成時のみ csrf_protection は無効化される）。
  4. PHP のチャンク送出型 HTTP 応答のコールバック内で BOM 処理は共通サービスに任せ、ヘッダ行とデータ行を逐次出力する。
  5. ファイル名は buy_sale_price_ と実行時刻から YmdHis で .csv。Content-Type は application/octet-stream。Attachment で同名を提示する。

集計条件

一覧および CSV での対象集合は共通のクエリであり、論理削除や公開状態は商品／規格側の結合および商品履歴向け共通クエリ付与関数が載せた条件により間接的に効く。

指標集計の要点
該当件数ページングコンポーネントの総件数。NULL だった pagination が初回表示で渡る場合でも Twig 側でコンテナのみ描画される。
CSV 行数ストリーム内で iterate された履歴エンティティ数。ページングは掛けない。

並び順は履歴作成日時の降順および履歴行 ID の降順がクエリ側で固定になる（共通処理に渡されるキー一覧が固定であり、共通クエリ関数内でも降順のみが適用される）。

利用者やトレイトが URL に持ち込む sort および order のクエリ値は、この機能のクエリ組み関数では読まれずセッション保持に留まる（実装を確認値とする）。

一覧・CSV 共通のクエリ構成上の順序の要点

  1. dtb_price_history をルートとし、商品規格および商品へ内部結合する。カード詳細およびカードは multi 入力時のみ左結合で追加され得る。登録管理者は作成者側の外部キーにより会員へ左結合する。
  2. 共通関数がテキスト multi、カテゴリ、ステータス、セット、レアリティ、言語、状態、箔、プロモ、登録日付レンジ、ソート順を処理する。
  3. 共通関数の処理のあと、product 配下キーにより変更後側の値で sellPrice・buyPrice・standardPrice に下限および上限レンジ条件を別々に付ける。いずれの境界も入力が空で無いときのみ有効。
  4. プロモ検索については共通関数が、promotion 配列の要素数ちょうど 1 のときだけ promotion_flg へ写像する選択肢のみをクエリへ付与する。

業務ルール・計算

本機能自体は画面上で価格を再計算しない。一覧は DB の履歴値をそのまま数値または空表示に近い形で出力するのみである。

複合キーワードは共通関数により半角／全角スペースおよびカンマでトークン化され、トークンごとに複数カラムの部分一致および、数値条件を満たす場合のみ商品本体の整数主キー完全一致を OR で足し込む規則に従う。トークンの最大長チェックなどは共通関数側の規則による。

検索側の変更後／変更前の別ではなく変更後側の現在値にのみレンジが掛かるため、変更前のみに値がある履歴より、変更後側が NULL の行は売買単独のレンジ指定では結果から落ちやすい（SQL の NULL と比較は真にならない）。

データ整合性

観点内容
一覧と CSV入力条件およびセッションの検索ビューデータが同一ならクエリ構成は同等（エクスポートは iterate のため順序や遅延ロードタイミングは別）。
変更前後の値履歴行ごとに片側のみ NULL の列があり得る。一覧は Twig でそのまま描画されるため画面上は空セルになり得る。CSV は空セルと文字列整数の切替関数で空文字に落とす。
同時更新検索中に他利用者が価格変更しても一覧は読取時点のスナップショットであり、自動更新はしない。

API/バッチ結果

本機能では公開 JSON API およびバッチ起動処理を挟まない。CSV はブラウザ向け単発ストリームである。
