M12-05（入荷通知依頼 一覧表示）

刷新後は実装不要本節は現行実装（pf-eccube3）からのリバースです。次の記述は Excel基本設計により廃止されており、刷新後に実装する必要はありません。

  • キーワード検索の会員名条件 は削除（0211 入荷通知依頼 一覧表示(検索項目)）

概要

分析・集計メニューの入荷通知依頼は、会員が登録した入荷通知（再入荷お知らせ）依頼を、依頼日・購入日・販売金額・購入状況・売上分析タグなどの条件で検索し、商品規格・会員・購入実績とともに一覧表示する機能である。

本書は実装手順ではなく、誰が・いつ・どの条件で・結果どうなるかを読むためのリバース詳細設計とする。確認値はpf-eccube3（EC-CUBE3系）のHareruyaEcプラグインの入荷通知依頼の検索処理、入荷通知依頼の検索用リポジトリ、検索フォーム種別、一覧テンプレートを正とする。本機能のカスタマイズ区分はカスタマイズであり、挙動は現行リポpf-eccube3を参照し、DB関連の記述はec-cube-enterpriseを正とする。現行と移行先でテーブル名・列の所在が異なる箇所は「リニューアル移行時の扱い」に集約する。

対象はブラウザ経由の管理画面に限定する。本文ではフレームワークのコントローラ型名やメソッド名を主説明としない。管理画面プレフィックスは環境により変わる（admin_route）。「利用者視点の入口」にHTTPメソッドとサイトルートからのパスパターンを書く。

CSVダウンロードはM12-06で扱う。本書は一覧の表示までを扱う。

本書で扱うこと

  • 入荷通知依頼の初期表示時に設定される検索条件の既定値
  • 検索条件（依頼日・販売金額・購入日・購入状況・並べ替え・表示件数・売上分析タグ）の指定による一覧の表示
  • 抽出の対象データ・結合・除外条件・集計単位の取り扱い
  • 一覧に表示する列と行ごとの操作メニュー

本書で扱わないこと

以下は本書では仕様確定せず、実装または別機能の設計を正とする。

  • 検索結果のCSVダウンロード（M12-06を正とする）
  • 入荷通知依頼の削除・規格編集など行操作の遷移先機能（各機能を正とする）
  • フロントの入荷通知依頼の登録（フロント機能を正とする）
  • 管理画面へのアクセス制御・ログイン・権限設定の詳細

処理フロー

検索画面初期表示（/{admin_route}/analysis/request）

  1. 管理画面の認証・権限を通過する。
  2. 検索条件セッションを破棄する。
  3. 依頼日Fromに当月初日、依頼日Toに当月末日、並び順に昇順を設定する。
  4. 検索フォームを表示する。一覧は無しとする。

検索・一覧表示（/{admin_route}/analysis/request/result）

  1. 検索フォームへ送信値を取り込む。
  2. 検索条件を検索条件セッションへ保存する。
  3. 論理削除フィルタを無効化する。これにより通知設定が削除済み（論理削除済み）の依頼も抽出対象とする。
  4. 入荷通知依頼の検索用リポジトリへ検索条件を渡し、結果を取得する。
  5. 一覧を同一画面に表示する。
