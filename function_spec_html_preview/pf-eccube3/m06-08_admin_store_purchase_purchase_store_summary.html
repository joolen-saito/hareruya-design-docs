店頭買取管理 — 買取集計データ（検索・一覧表示）

概要

リポジトリ本体の標準構成（コメントで pf-eccube3 の HareruyaEc に由来することが示されている）において、dtb_otc_buy_order_summary に蓄積された店頭買取集計行を、summary_date の期間および任意の買取店舗・部門で絞り込み、期間全体の部門別合計と日別×部門の一覧を検索結果として表示する管理画面機能である。

本書は実装手順ではなく、誰が・いつ・どの条件で・結果どうなるかを読むためのリバース詳細設計とする。集計データの算出・登録（コンソールコマンド・バッチ置換処理）、CSVファイルの体裁とストリーム出力の詳細は本書では仕様確定しない。カスタマイズ区分は現行踏襲であり、現行挙動の参照はpf-eccube3（HareruyaEcプラグイン）、DB関連はec-cube-enterpriseを正とする。現行と移行先のスキーマ差は後述の「リニューアル移行時の扱い」にまとめる。

対象はブラウザ経由の管理画面に限定する。

本文ではフレームワークのハンドラー名やコントローラ型・メソッド名を主説明としない。本文ではルートbind名やSymfonyのルートnameの網羅は主説明としない。「利用者視点の入口」にHTTPメソッドとサイトルートからのパスパターンを書く。コード探索でbind名が必要なときだけ「調査補助」へ書く。

フロント挙動

観点内容
表示要素タイトルは翻訳キー admin.purchase.store.title（店頭買取管理）。サブタイトルは admin.purchase.store.summary（買取集計データ）。メニューは purchase_store と summary。検索は単一の search_form で、search-box 内に「集計日」の開始・終了の二欄、部門、買取店舗、フッタに「検索する」ボタン。検索後のみ、上段に見出し「集計」と部門別の4列表、下段に見出し「日別」と日付付き5列表を表示する。該当行が無いブロックはそれぞれ定型の空メッセージ見出しを表示する。
JS 挙動assets/js/OtcBuyOrder/otc-buy-order-summary.js で、識別子末尾が _date_from または _date_to の入力に datetimepicker（ロケール日本語、表示形式 YYYY-MM-DD）を付与する。#admin_otc_buy_order_summary_shop と #admin_otc_buy_order_summary_section に select2（幅100%）を付与する。
CSS・レイアウト管理画面既定の default_frame、Bootstrap横型フォームテーマ、検索ボタンにアイコンSVG。
モーダル・ポップアップ本画面専用のモーダルはない。

処理フロー

初期表示する（GET admin_otcbuyorder_summary）

  1. 管理画面の認証・共通制約を通過する。
  2. 検索用フォーム型の空インスタンスを生成し、Twigへ渡す。searched は偽、entirePeriodSummary と daysSummary は nullである。
  3. 利用者は集計日が未入力の検索欄を見る。買取店舗はメンバーのデフォルト検索店舗が取れた場合のみ1件選択済みで初期化される。

検索して一覧を表示する（POST admin_otcbuyorder_summary_search）

  1. 管理画面の認証・共通制約を通過する。
  2. リクエストをフォームに取り込む。
  3. 未送信またはフォームが検証に通らない場合、searched は偽のまま、集計結果は null のまま同テンプレートを返す。フィールドエラーは各ウィジェット直下に表示される。
  4. 検証に成功した場合、フォームの正規化済みデータを検索データとして用いる。
  5. セッションキー eccube.admin.otcbuyorder_summary.search に、FormUtil::getViewData で得たフォームのビュー用データを保存する。以降のCSVPOSTはこの値を読み戻して同じ条件を再構成する。
  6. リポジトリの「期間全体・部門別」クエリビルダを実行し、配列結果を entirePeriodSummary に渡す。結果が空ならTwig上で期間全体の空メッセージのみ出す。
  7. リポジトリの「日別・部門別」クエリビルダを実行し、配列結果を daysSummary に渡す。結果が空なら日別の空メッセージのみ出す。
  8. searched を真にし、フォームのビューと二つの結果を同テンプレートで返す。

集計条件

検索はいずれも dtb_otc_buy_order_summary を起点とし、部門は Section への左結合とする。

指標集計の要点
期間summary_date がフォームの開始日0時0分0秒以上、かつ終了日23時59分59秒以下。
買取店舗の絞り込みフォームで1件以上選ばれている場合のみ、BaseInfo がその集合に属する行に限定する。未選択のときは店舗条件を付けない。
部門の絞り込みフォームで1件以上選ばれている場合のみ、結合先部門の識別子がその集合に属する行に限定する。未選択のときは部門条件を付けない。
日別一覧集計日（日単位）と部門識別子ごとに sell_price の合計を sellPriceTotal、buy_price の合計を buyPriceTotal として取得する。並びは集計日昇順、部門コード昇順。
期間全体一覧上記と同一のWHERE条件のうえ、部門識別子のみでグループ化し、金額は期間を通じ合算する。並びは部門コード昇順。
部門未設定集計行の section_id が欠け、結合先が無い場合、部門名はTwigで定数「未設定」に置き換えて表示する。部門コードはNULLのまま表示され、空欄になり得る。

業務ルール・計算

画面は既存の集計行の参照のみであり、検索POSTで dtb_otc_buy_order_summary を書き換えない。金額はTwigの価格フィルタで通貨表示に整形する。

本機能では画面からの業務計算（再集計や按分）は行わない。

エッジケース

ケース扱い
開始日のみ・終了日のみ欠落、または日付不正フォーム検証に通らず一覧は出さずエラーを表示する。セッションの検索退避も行わない。
期間および条件は妥当だが行が0件「集計」「日別」それぞれ別メッセージのボックスのみ表示する。
複数店舗・複数部門の合算表示日別一覧は同一日かつ同一部門内で複数店舗を横断した合計が既にクエリ側でまとめられる一方、画面上は店舗列を持たず、複数店舗を選んだ場合はその合算値として見える。
