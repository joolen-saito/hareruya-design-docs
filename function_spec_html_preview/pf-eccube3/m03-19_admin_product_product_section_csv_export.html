商品管理 — 部門 CSV 出力

概要

管理画面の「商品管理」配下である部門一覧・編集画面から、部門マスタ（mtb_section）の全行を 1 ファイルにストリーミング出力する機能である。出力列はソース上で固定されており、店舗設定の CSV 項目マスタ（dtb_csv）は参照しない。行の並びは部門コード昇順である。

本書は実装手順ではなく、誰が・いつ・どの条件で・結果どうなるかを読むためのリバース詳細設計とする。確認値は EC-CUBE Enterprise の src/Eccube 配下（Symfony ルートプレフィックス %eccube_admin_route%）とする。

本機能のカスタマイズ区分は現行踏襲である。挙動の参照は現行リポ pf-eccube3 の HareruyaEc プラグイン実装を正とし、DB関連は ec-cube-enterprise を正とする。現行と移行先のスキーマ差は「リニューアル移行時の扱い」へ集約する。

対象はブラウザ経由の管理画面に限定する。

コントローラのメソッド単位の解剖は本文の主題としない。本文ではルートbind名やSymfonyのルートnameの網羅は主説明としない。「利用者視点の入口」にHTTPメソッドとサイトルートからのパスパターンを書く。コード探索でbind名が必要なときだけ「調査補助」へ書く。

リニューアル移行時の扱い

DB関連の正典は ec-cube-enterprise とする。挙動は現行リポ pf-eccube3 の HareruyaEc プラグインを正とし、移行先との差は本節へ集約する。

観点現行（pf-eccube3）移行先（ec-cube-enterprise）
出力元の部門マスタ列mtb_section は部門ID・部門名（name）・部門コード（code）・表示フラグ（visible）のみを持ち、免税区分の列が無い。mtb_section に免税区分（tax_free_division）とスマレジ部門ID（smaregi_category_id）が加わる。
出力列セット現行の固定列セットには免税区分が含まれない。本書の 5 列固定（ID・部門名・部門コード・免税区分・表示フラグ）は移行先の mtb_section の列を正とし、免税区分列は移行先で確定する。

mtb_section の id／name／code／visible の列名は現行と移行先で同一スキーマである（免税区分・スマレジ部門ID列を除く）。

処理フロー

CSV をダウンロードする（GET m03-18_admin_product_product_section_export）

  1. 管理画面の認証・共通制約を通過する。
  2. リポジトリで部門マスタを部門コード昇順かつ条件無しで全件取得する。
  3. 各エンティティについて、列順どおりにスカラー配列を組み立てる。順は「ID（整数）」「部門名（文字列）」「部門コード（文字列）」「免税区分（整数の getter 値）」「MTGBuyer 表示フラグ（表示なら 1、非表示なら 0）」。
  4. StreamedResponse のコールバック内で CSV 出力サービスを開き、固定の見出し配列を 1 行目に書く。
  5. 手順 3 で得た各行を順に書く。
  6. ストリームを閉じる。
  7. 応答ヘッダに Content-Type: application/octet-stream と Content-Disposition: attachment; filename=section_YYYYMMDDhhmmss.csv を付与する。

部門 0 件のとき

  • 手順 4 の見出しのみ書き、データ行は無いファイルとなる。

カテゴリ CSV 出力など他エクスポートとの差

  • 本処理では PHP の実行時間無効化（set_time_limit(0)）や ORM の SQL ロガー向け初期化呼び出しは行わない。
  • 本処理では情報ログにファイル名を残す実装は無い（カテゴリ CSV 出力とは異なる）。

本機能では売上・注文件数・件数の DISTINCT 集計などは行わない。出力対象は mtb_section の全行で、並びは部門コード昇順のみである。
