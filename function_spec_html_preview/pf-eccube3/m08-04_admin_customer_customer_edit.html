M08-04（会員登録/編集）

概要

管理画面「会員管理」で、会員を新規登録したり、既存会員の会員情報を更新したりする機能である。氏名・住所・連絡先・メールアドレス・パスワード・会員ステータス等のコア会員項目に加え、HareruyaEcプラグインが追加するDCI関連情報・本人確認ステータス・身分証有効期限・会員グループ・メールマガジン配信フラグ・スマレジIDを同一フォームで扱う。編集画面には購入履歴・買取履歴の参照と、ポイント管理・配送先一覧・手動メール通知・メール送信履歴・オンライン本人確認への導線も載る。

本書は実装手順ではなく、誰が・いつ・どの条件で・結果どうなるかを読むためのリバース詳細設計とする。確認値はpf-eccube3（EC-CUBE3系）の会員登録・編集処理（コア会員編集）、HareruyaEcプラグインの会員登録フォーム拡張、会員編集テンプレート（Customer/edit.twig）を正とする。

本機能のカスタマイズ区分はカスタマイズであり、画面・挙動の確認はpf-eccube3を参照し、DB関連の記述（保存先・テーブル名・列名）はec-cube-enterpriseを正とする。

対象はブラウザ経由の管理画面に限定する。会員検索・一覧（M08-01を正とする）、手動メール通知（M08-08を正とする）、オンライン本人確認の確認済への変更操作・身分証画像の閲覧（M08-10を正とする）、ポイント管理・配送先・ブラックリストは別機能とする。

本文ではフレームワークのコントローラ型名やメソッド名を主説明としない。管理画面プレフィックスはコア設定admin_routeで決まり、環境により変わる。「利用者視点の入口」にHTTPメソッドとサイトルートからのパスパターンを書く。コード探索でルートbind名が必要なときだけ「調査補助」へ書く。

本書で扱うこと

  • 会員の新規登録フォームと既存会員の編集フォームの表示
  • 入力項目（コア項目とプラグイン拡張項目）と保存先
  • 新規登録時の会員と会員住所の同時生成、パスワード暗号化、シークレットキー採番
  • 編集時のパスワード初期値（既定パスワード）の扱いと、変更時のみの再暗号化
  • 本人確認用情報変更時に本人確認ステータスを未確認へ戻す確認ダイアログ
  • 編集画面の購入履歴・買取履歴の参照と各機能への導線

本書で扱わないこと

以下は本書では仕様確定せず、実装または別機能の設計を正とする。

  • 会員検索・一覧の検索条件（M08-01を正とする）
  • 手動メール通知・メール一括送信（M08-08を正とする）
  • オンライン本人確認モーダルでの確認済への変更・身分証画像表示（M08-10を正とする）
  • ポイント管理・履歴、配送先一覧・編集、仮会員メール再送、会員削除
  • パスワードハッシュ方式・ソルト生成の暗号仕様（フレームワーク・コア実装を正とする）

処理フロー

会員登録・編集フォームを表示する（GET /{admin_route}/customer/new・/{admin_route}/customer/{id}/edit）

  1. 未完了受注を隠すフィルタを有効にする。
  2. 編集時はパス会員IDで会員を取得する。存在しない場合はページが見つからない扱い（404）とする。取得後、パスワード欄に既定パスワードをセットして元のパスワードを退避する。
  3. 新規時は会員の新規インスタンスを生成し、購入回数・購入金額を0で初期化する。
  4. 会員登録フォームを生成する。プラグインのフォーム拡張により、DCIナンバー・DCI登録本名・国・本人確認ステータス・DCI確認フラグ・本人確認フラグ・身分証有効期限・会員グループ・メールマガジン配信フラグ・スマレジID（読み取り専用）の各欄を追加し、氏名カナ・郵便番号の必須を解除する。
  5. 拡張イベントでフォームを拡張し得る。
  6. フォームと（編集時は）購入履歴・買取履歴を表示する。

会員登録・編集を送信する（POST /{admin_route}/customer/new・/{admin_route}/customer/{id}/edit）

  1. フォームを送信状態で受け取り、検証する。検証に失敗した場合は同一画面でエラーを表示する。
  2. 新規（会員IDが無い）場合は、ソルトとシークレットキーを採番し、会員の氏名・カナ・会社名・郵便番号・都道府県・住所・電話・FAXを写した会員住所を生成して保存対象にする。
  3. パスワードが既定パスワードのままなら退避した既存パスワードを維持する。変更されている場合はソルトを必要に応じて生成し、パスワードを暗号化する。
  4. 会員を保存する。新規時は会員住所も保存する。
  5. 拡張イベントで保存完了を通知し得る。
  6. 保存成功を表示し、保存した会員の編集画面へ遷移する。

本人確認ステータスを戻す確認（登録ボタン押下時、画面側）

  1. 会員が確認済みまたは簡易書留確認済みのとき、住所関連（国・郵便番号・海外用郵便番号・都道府県・住所1・住所2）が変更されていれば本人確認用情報の変更とみなす。
  2. 確認済みのとき、お名前・お名前（フリガナ）・生年月日の変更も本人確認用情報の変更とみなす。
  3. 変更があれば確認ダイアログを表示し、続行を選ぶと本人確認ステータスの送信値を未確認へ書き換えてからフォームを送信する。取消なら送信しない。

エッジケース

ケース扱い
編集でパスワード欄を変更しない既定パスワードのままなら既存パスワードを維持する。
新規登録会員と会員住所を同時に生成し、シークレットキー・ソルトを採番する。

データ整合性

観点内容
会員と会員住所新規登録時、会員情報を写した会員住所を同時に保存する。以後の配送先の追加・編集は配送先機能を正とする。
パスワード既定パスワードと一致するかで再暗号化の要否を判定する。原値は保持・表示しない。
本人確認ステータス画面側で未確認へ降格する判定は確認済み・簡易書留確認済みの会員に限る。確認済への変更はM08-10を正とする。
購入履歴・買取履歴編集画面の履歴は表示時点の永続化済みデータを各100件まで読む。

API/バッチ結果

本機能ではAPI呼び出し・バッチ実行を扱わない。スマレジ連携はスマレジ関連機能を正とする。

入出力

種類内容
入力会員登録フォーム（フォーム名admin_customer）、なりすまし対策トークン。
成功時出力会員情報の保存と保存成功フラッシュ。保存後の編集画面へリダイレクト。
