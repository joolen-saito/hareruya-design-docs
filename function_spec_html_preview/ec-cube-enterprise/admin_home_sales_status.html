admin_home_sales_status（管理画面_トップ売上状況）

管理画面ホームに表示される、期間別の売上金額・件数のサマリと、週間・月間・年間の売上金額棒グラフ。

概要

管理画面ホームの売上状況は、管理者がログイン後に最初に見るダッシュボード上で、受注台帳に基づく売上金額と売上件数を期間ごとに集計して提示する機能である。画面上部には「今月」「今日」「昨日」のサマリがサーバ側レンダリングで示され、その下のタブでは週間・月間・年間の推移を棒グラフで表示する。グラフ用データはページ表示後にブラウザから非同期で取得される。

本書は実装手順ではなく、誰が・いつ・どの条件で・結果どうなるかを読むためのリバース詳細設計とする。 既存実装のふるまい、参照するデータ、集計境界、拡張による差し替え可能性を確認し、仕様の確からしさを把握することを目的とする。

対象はブラウザ経由の管理画面ホームの「売上状況」ブロックである。受注ステータス別件数のカード、ショップ状況ブロック、プラグイン案内、お知らせ iframe は別機能として切り離す。

本書では Symfony の route 名、URL パス、Controller 構成は扱わない。 代わりに、ホーム画面表示、売上サマリの表示、グラフデータの非同期取得、タブ切替、権限に至れない利用者といった利用者視点の入口ごとに期待されるふるまいを記載する。

本書で扱うこと

  • ホーム画面表示時に「今月」「今日」「昨日」の売上金額・件数がどのように集計されるか
  • 売上集計から除外する受注ステータスの既定集合と、受注状況カード側の除外との差
  • 除外リストが拡張処理により書き換わる場合があること
  • グラフ用データの取得契機と、週間・月間・年間それぞれの集計区間と日次バケットの扱い
  • 集計が参照する受注の属性と日時境界
  • グラフは売上金額のみをデータ系列として描画し、件数はバックエンドでバケットごとに保持する場合があるが当該グラフでは利用しないこと
  • 非同期取得が失敗したときの画面上のふるまい
  • 管理画面共通の Ajax 設定により CSRF 検証が行われることの概要
  • 本ブロックが受注台帳やマスタを更新しないこと、専用の業務監査ログが無いこと
  • 受け入れテストで確認されている範囲と、その外側

本書で扱わないこと

以下は本書では仕様確定せず、実装または別機能の設計を正とする。

  • Symfony の route 名、URL パス、Controller クラス名・メソッド名の一覧
  • 管理画面へのアクセス制御、ログイン、二段階認証、権限設定の詳細
  • 受注一覧・売上レポート・会計上の売上定義との完全一致要件
  • payment_total の計上ルール、税・送料・値引の内訳、為替
  • プラグインのイベント識別子やフックの直列名の確定表記
  • Doctrine のクエリキャッシュ、ソフトデリットやマルチテナント等により受注が一覧から除外される場合の詳細な条件列挙
  • データベース接続失敗時の HTTP ステータスや例外型の列挙
  • Chart.js のバージョン固有の表示仕様の細部

利用者視点の入口

入口URLエンドポイント期待されるふるまい
ホーム画面を開く`GET /%eccube_admin_route%/`売上状況カードに、今月・今日・昨日の売上金額と件数が表示される。集計結果が無い場合は金額・件数とも 0 として表示される。グラフ領域は読み込み中表示のあと、データ取得成功時には週間・月間・年間それぞれの棒グラフが描画される。
売上グラフ用データの非同期取得`GET /%eccube_admin_route%/sale_chart`（XHR・CSRF 付与が前提）ホーム画面のレイアウトで共通設定されている Ajax 用ヘッダにより CSRF トークンが付与され、サーバは XMLHttpRequest かつ CSRF が妥当な場合にのみ JSON を返す。条件を満たさない場合はグラフ用データは得られず、失敗時ハンドラは実質空でありグラフは描画されない。
週間・月間・年間タブを切り替える—（同一 `GET /%eccube_admin_route%/` ページ内の表示切替）同一ページ内でタブ表示が切り替わり、事前に取得済みのデータセットに対応する canvas にグラフが描画されている。タブ切替自体で追加のサーバ問い合わせは行わない。
売上状況カード見出しのリンク—（見出しはリンクではない）見出しはリンクではなく静的文言であり、押下による画面遷移は設けられない。
非管理者・未認証`GET /%eccube_admin_route%/` 等（到達前にログインへ）ホーム画面自体に到達できないため、本ブロックも利用できない。

観点内容

JS 挙動ページ表示後にグラフ用データを非同期取得し、取得成功時に三つの canvas へ棒グラフを描画する。タブ切替では取得済みグラフの表示領域を切り替え、追加のサーバ問い合わせは行わない。
CSS・レイアウト管理画面共通のカード、タブ、グラフ領域、ローディング表示のクラスを使う。売上値の大小による CSS 条件分岐は本ブロックでは扱わない。
モーダル・ポップアップ本ブロックはモーダル、ポップアップ、トースト、確認ダイアログを表示しない。グラフ取得失敗時も利用者向けの専用通知は表示しない。
入力項目本ブロックはフォーム・テキスト入力を持たない。タブ切替は表示領域の切替のみで、新たな利用者入力は発生しない。

処理フロー

ホーム画面表示・売上対象外リストの確定

  1. 管理者がホーム画面にアクセスしたとする。
  2. システムは売上集計用の売上対象外ステータス配列を用意する。既定ではキャンセル、決済処理中、購入処理中、返品を除外する。注文受領、入金待ち、対応中、出荷完了、入金済み、出荷指示、ピック中、店頭予約、ピック完了、引渡し済みは、既定の売上集計対象に含まれる。
  3. 売上向けの拡張フックにより、プラグイン等が上記配列を差し替える場合がある。差し替え後の配列が、その後のサマリ集計とグラフ用データ取得の双方に使われる。
  4. ホーム全体のコンテキストを公開する別の拡張フックにより、売上サマリを含むダッシュボード値が最終的に上書きされる場合がある。拡張処理が値を上書きした場合、画面表示は上書き後の値に従う。

売上サマリの取得

  1. 「今日」について、当日 0 時から翌日 0 時未満の order_date を持つ受注のうち、既定実装では注文受領、入金待ち、対応中、出荷完了、入金済み、出荷指示、ピック中、店頭予約、ピック完了、引渡し済みの受注を対象に、payment_total の合計と件数を求める。
  2. 「昨日」について、前日の日付で同様の境界を用いて合計と件数を求める。
  3. 「今月」について、当月 1 日 0 時から翌月 1 日 0 時未満の order_date を持つ受注のうち、既定実装で売上集計対象となるステータスの受注を対象に、合計と件数を求める。終端日の解釈は実装が用いる相対日付指定に依存し、タイムゾーンは永続化層および実行環境の設定に従う。
  4. 問い合わせ結果が無い場合、実装は空の結果として扱い、画面は 0 を表示する。

売上グラフ用データの取得と変換

  1. ブラウザがホーム画面表示後、グラフ用データを非同期で要求する。
  2. サーバは再度売上対象外リストを拡張フックで確定したうえで、次の三つの区間について、確定後の売上集計対象ステータスの受注を読み取り、日付または年月単位のバケットに売上金額と件数を累積する。
  • 週間相当。当日から見て過去にさかのぼった約一週間の範囲と当日現在までの upper bound を持つ区間。バケットキーは日単位である。
  • 月間相当。当月 1 日から現在までの区間。バケットキーは日単位である。
  • 年間相当。現在から過去にさかのぼった約一年と現在までの区間。バケットキーは年月単位である。
  1. 各区間について、範囲内の各日または各年月キーに対し、売上が無い期間も値が 0 のバケットとして用意される。これによりグラフの横軸ラベルが欠けない。
  2. 返却される JSON は三つのバケット集合からなる配列であり、画面側はこれを順に週間・月間・年間の canvas に対応付けて棒グラフを生成する。

画面への描画

  1. 売上サマリはテンプレートが通貨表示および件数の桁区切りを適用して出力する。
  2. グラフは売上金額のみを縦棒として表示する。ツールチップは通貨記号付きで値を整形する。
  3. 非同期取得が完了すると読み込みインジケータが非表示となる。取得に失敗した場合も読み込み表示は消えるが、グラフは描画されない。

集計条件

指標集計の要点
今月の売上金額・件数当月 1 日 0 時から翌月 1 日 0 時未満の `order_date` を持ち、売上対象外ステータスに含まれない受注について、`payment_total` の合計と受注件数を求める。
今日の売上金額・件数当日 0 時から翌日 0 時未満の `order_date` を持ち、売上対象外ステータスに含まれない受注について、`payment_total` の合計と受注件数を求める。
昨日の売上金額・件数前日 0 時から当日 0 時未満の `order_date` を持ち、売上対象外ステータスに含まれない受注について、`payment_total` の合計と受注件数を求める。
週間グラフ当日を含む過去約一週間の区間を日単位バケットに分け、各日に売上金額と件数を累積する。画面では売上金額のみを棒グラフに使う。
月間グラフ当月 1 日から現在までの区間を日単位バケットに分け、各日に売上金額と件数を累積する。画面では売上金額のみを棒グラフに使う。
年間グラフ現在から過去約一年の区間を年月単位バケットに分け、各月に売上金額と件数を累積する。画面では売上金額のみを棒グラフに使う。

売上対象外ステータスは既定値を持つが、拡張処理が差し替えた場合は、差し替え後のリストをサマリ集計とグラフ用データ取得の双方に適用する。

順序判定結果

受注状況カードとの除外の違い

観点受注状況カード売上状況

決済処理中・購入処理中・キャンセル・返品相当除外に含まれる除外に含まれる

業務ルール・計算

項目内容
売上金額条件に一致する受注の `payment_total` を合計する。税、送料、値引、手数料の内訳は本ブロックでは再計算しない。
売上件数条件に一致する受注行を数える。受注明細行数、商品点数、配送件数では数えない。
除外条件既定ではキャンセル、決済処理中、購入処理中、返品に相当するステータスを除外する。拡張処理が除外リストを差し替えた場合は、そのリストを確認値とする。
期間境界サマリは今日、昨日、今月の境界で `order_date` を判定する。グラフは週間・月間・年間ごとの区間をバケット化する。
表示形式金額は通貨表示として整形し、件数は整数として表示する。画面上の棒グラフは売上金額だけを系列にする。

エッジケース

ケース扱い
該当受注が 0 件サマリは金額・件数とも 0 として表示する。グラフは期間内の各バケットを 0 で埋める。
売上対象外ステータスの受注金額・件数のいずれにも含めない。
`payment_total` が 0 の受注ステータスと期間条件に一致する場合、売上件数には含め、売上金額には 0 として加算する。
表示後に受注が更新された表示中のサマリとグラフは自動更新しない。ホーム画面再表示またはグラフ再取得時の読み取り結果に従う。
サマリ取得時点とグラフ取得時点の間に受注が変わったサマリとグラフは別リクエストで取得されるため、同一スナップショットで一致することは保証しない。
グラフ用 JSON に件数が含まれる画面の棒グラフ描画では売上金額のみを使う。件数は当該グラフの表示系列として扱わない。

データ整合性

観点内容
参照時点売上サマリはホーム画面 HTML 表示時に読み取った結果である。グラフ用データはページ表示後の Ajax で別途読み取る。
サマリとグラフサマリとグラフは同一トランザクションで固定しない。表示直後に受注が更新された場合、両者の値が一致しない場合がある。
一覧・レポートとの整合性受注一覧、売上レポート、会計上の売上定義との完全一致は本ブロックでは保証しない。それぞれの機能の検索条件、対象ステータス、集計定義を正とする。
更新との整合性本ブロックは参照のみであり、受注台帳やマスタを更新しない。受注更新との排他制御や再集計タイミングは各更新機能の設計を正とする。
外部連携との整合性外部連携やバッチにより受注が更新される場合の反映タイミングは、外部連携機能またはバッチ機能の設計を正とする。本ブロックは読み取り時点の永続化済みデータだけを読む。

API/バッチ結果

種類内容
API売上サマリはホーム画面 HTML レンダリング時にサーバ側で取得する。グラフ用データはページ表示後に管理画面内の Ajax として JSON を取得する。
バッチ本ブロックはバッチを起動しない。バッチによって受注が更新済みの場合、次回のサマリ取得またはグラフ取得時にその時点の永続化済みデータを読む。
成功時グラフ用データ取得が成功した場合、週間・月間・年間のバケット集合を返し、画面は対応する canvas に棒グラフを描画する。
失敗時Ajax 要件または CSRF 検証を満たさない場合、グラフ用データは得られない。フロント側は専用の利用者向けメッセージを表示せず、グラフ未描画の状態になる。

入出力

種類内容
入力ホーム画面の GET 表示。売上サマリはクエリやボディ入力を受け取らない。グラフ用データは認証済みセッションのもとでの Ajax GET。
成功時出力売上サマリを含む HTML。続いてグラフ用の JSON 配列。
失敗時出力グラフ用データが Ajax 要件を満たさない場合、グラフデータは取得できず JSON エラー相当の本文が返る。サマリはホーム描画時に既に決まっている。データベース障害時はアプリケーションの共通例外処理に委ねられ、ホーム全体が表示されないことがある。
副作用本ブロックの処理だけを見ると、受注台帳やマスタを更新しない。グラフ取得でもセッションを本ブロック専用に書き換えない。

画面遷移

条件遷移先
ホーム画面を開く同一画面内に売上状況を表示。
週間・月間・年間タブ操作同一画面内のタブ表示切替。サーバへの追加遷移はない。
グラフ取得失敗同一画面のまま。グラフ未描画。

エラー処理

エラー内容処理
グラフ用 Ajax が CSRF または XMLHttpRequest 条件を満たさないグラフデータを返さない。フロントは失敗コールバックが実質空のため利用者向けメッセージは出さない。
データベース読み取りの障害アプリケーションの共通例外処理に委ねる。本ブロック専用の利用者向けメッセージは設けない。
表示直後に台帳が変化サマリとグラフは同一瞬間のスナップショットではない。リアルタイムダッシュボードではない。

試行制限

本機能では試行制限を扱わない。

ログ・監査

タイミング記録内容
売上状況の表示およびグラフデータ取得のみ本ブロック単体では業務監査ログを追加で書く処理は持たない。

ログに出してはいけないもの

  • CSRF トークンの原値や Cookie の原値
  • セッション識別子の完全値
  • 個別受注の識別子や住所など、ダッシュボードの説明に不要な個人情報の列挙

本機能は集計値のみを扱うため、設計書上も個別受注の内容を例示しない。

セッション

本機能におけるセッション

観点内容
ホーム画面表示時売上サマリのためだけにセッションを更新しない。
グラフ用 Ajax認証済みセッションのもとで実行されるが、本ブロック専用のセッションキー書き込みは持たない。

Cookie

本機能は売上表示のためだけに新たな Cookie を設定しない。ブラウザのセッション Cookie はフレームワークおよび管理画面全体の認証に用いられる。

排他制御・トランザクション

本ブロックの売上表示とグラフデータ生成は参照のみであり、業務トランザクションを張って受注を変更しない。受注台帳に対する楽観ロックや悲観ロックの対象ではない。 同時に複数の管理者がホームを開いても、ロックを取り合う要件は持たない。
