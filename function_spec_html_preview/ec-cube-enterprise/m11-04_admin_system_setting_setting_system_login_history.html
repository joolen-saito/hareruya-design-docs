m11-04_admin_system_setting_setting_system_login_history（管理画面_ログイン履歴）

管理画面システム情報設定配下のログイン履歴一覧で、管理画面ログインの試行記録を検索・閲覧する機能。

概要

ログイン履歴は、管理画面へのログイン試行で記録された行を、ログインID・IPアドレス・ログイン試行日時・成功失敗区分とともに一覧で閲覧し、期間や成功失敗などの条件で絞り込むための参照機能である。記録の発生源は認証処理側であり、本機能はその記録を読み取って表示する。

本書は実装手順ではなく、誰が・いつ・どの条件で・結果どうなるかを読むためのリバース詳細設計とする。 既存実装のふるまい、参照するデータ、検索条件、表示列、副作用を確認し、仕様の確からしさを把握することを目的とする。

本機能のカスタマイズ区分は標準であり、挙動・DB関連ともにリニューアル後（ec-cube-enterprise）の標準実装を正とする。

対象はブラウザ経由の管理画面のログイン履歴一覧である。履歴を生成する認証成功・失敗の判定そのものは別機能とし、本書では確認できる範囲で記録の発生源を整理する。

管理画面プレフィックスは環境変数ECCUBE_ADMIN_ROUTEをeccube.yamlのeccube_admin_routeへ束ねた値で決まる。本書では%eccube_admin_route%で示し、ホスト名やクエリを含む具体URLは書かない。Symfonyのルートname、Controllerの構成は本文の主題としない。

本書で扱うこと

  • ログイン履歴一覧の表示時に、どの記録がどの順序で表示されるか
  • キーワード検索と詳細検索の各条件が、どの列にどう作用するか
  • 一覧の表示列（ID・ログインID・IPアドレス・ログイン試行日時・成功失敗区分）
  • 検索条件・ページ番号・表示件数がセッションへ保存され、再表示時に引き継がれること
  • 成功失敗区分の値と画面表示の対応
  • 履歴行を生む操作が認証成功・認証失敗であることの整理（記録の確定は別機能）

本書で扱わないこと

以下は本書では仕様確定せず、実装または別機能の設計を正とする。

  • 管理ログインの認証判定、試行制限、二段階認証の詳細は管理画面_認証機能の設計を正とする
  • ログイン成功・失敗の履歴を書き込む処理の確定仕様（本機能は読み取り側であり、記録経路は確認値として整理する）
  • Symfonyのルートname、Controllerクラス名・メソッド名の一覧
  • 管理画面の認証・認可の共通基盤、左ナビゲーション全体の構成
  • ページネーション部品、ページ表示件数マスタの管理画面での編集
  • マルチテナント・店舗文脈による参照範囲の絞り込み詳細（永続化層の共通規則を正とする）

リニューアル移行時の扱い

  • 本機能のカスタマイズ区分は標準であり、リニューアル後（ec-cube-enterprise）の標準実装を挙動・DBともに正とする。
  • ログイン履歴は ec-cube-enterprise の標準テーブル dtb_login_history と区分マスタ mtb_login_history_status に保存する。dtb_login_history はテナント文脈を表す base_info_id 列を含む標準スキーマである。
  • 区分マスタの保存値は失敗が0、成功が1で、ec-cube-enterprise の標準初期データと同一とする。
  • 現行（pf-eccube3／EC-CUBE3系）に相当する一覧画面・テーブル構成との差がある場合は、移行時に ec-cube-enterprise の標準スキーマへ揃える。現行との具体差は ec-cube-enterprise 実装を正として移行設計で確認する。

処理フロー

一覧表示

  1. 利用者がログイン履歴一覧を開く。
  2. 表示件数はセッションキーeccube.admin.login_history.search.page_countから取得し、未保存ならアプリ既定の表示件数を用いる。リクエストに有効なpage_countがあり、かつ表示件数マスタに一致する場合はその値を採用し、同セッションキーへ保存する。
  3. ページ番号付きURLまたはresumeでの再表示では、保存済みの検索条件eccube.admin.login_history.searchと保存済みページ番号を読み出して絞り込む。
  4. ページ番号も再表示指定もない初回表示では、検索条件を空にしてセッションへ保存し、1ページ目を全件対象で表示する。
  5. 絞り込み結果を作成日時の降順、同一日時内はID降順で並べ、ページ送りして一覧表に表示する。

検索実行

  1. 利用者が検索条件を入力して検索ボタンを押す。
  2. 入力値の検証に成功した場合、検索条件をセッションeccube.admin.login_history.searchへ保存し、ページ番号を1へ初期化してセッションへ保存する。
  3. 保存した条件で絞り込み、1ページ目を表示する。検索結果件数を画面に表示する。
  4. 入力値の検証に失敗した場合は一覧を出さず、詳細検索ブロックを開いた状態で再描画し、条件の見直しを促す表示にする。この場合は検索条件をセッションへ保存しない。

ページ送り・表示件数変更

  1. ページャのリンクまたは表示件数プルダウンで遷移する。
  2. ページ番号はURLの値をセッションeccube.admin.login_history.search.page_noへ保存する。表示件数は前述の判定でセッションへ保存する。
  3. 保存済みの検索条件のまま、指定ページ・指定件数で一覧を表示する。

データ整合性

観点内容
参照時点一覧は表示要求時点でdtb_login_historyから読み取った行である。表示後に新たな試行が記録されても表示中の一覧は自動更新しない。
記録との整合性表示する履歴は認証処理側が記録した行であり、本機能は更新しない。記録の有無・内容は認証機能の設計を正とする。
失敗履歴の保存失敗失敗履歴の書き込みに失敗した場合は履歴行が作られず、認証機能側でサーバログに記録される。本機能はその場合に該当行を表示しない。
表示列との整合性一覧の各列は履歴行の保存値をそのまま表示する。ログインIDは試行時の入力文字列であり、現在の管理者レコードのログインIDと一致するとは限らない。
件数との整合性検索結果件数はページネーション部品が数えた総件数であり、表示中ページの行数とは別である。

API/バッチ結果

本機能ではAPI呼び出し・バッチ実行を扱わない。一覧表示はサーバ側でHTMLを組み立てる処理の中でdtb_login_historyを読み取る。

入出力

種類内容
入力一覧表示要求、検索条件のPOST、ページ番号・表示件数を含むGET。
成功時出力検索条件に一致する履歴行を、ID・ログインID・IPアドレス・ログイン試行日時・成功失敗区分の列でページ表示する。
失敗時出力検索条件の検証失敗時は一覧を出さず、詳細検索を開いた状態で見直しメッセージを表示する。
副作用検索条件・ページ番号・表示件数のセッション保存のみ。台帳・履歴の更新はしない。
