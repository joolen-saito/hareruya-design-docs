m02-06_admin_home_home_recommend_plugins（管理画面_トップおすすめプラグイン）

管理画面ホームに表示される、おすすめプラグイン一覧、プラグイン詳細モーダル、オーナーズストアへの導線。

概要

管理画面ホームのおすすめプラグインは、管理者がダッシュボード上でオーナーズストア上の推奨プラグインを確認し、詳細確認、無料プラグインのインストール確認、有料プラグイン購入、オーナーズストア検索へ進めるようにする機能である。

本書は実装手順ではなく、誰が・いつ・どの条件で・結果どうなるかを読むためのリバース詳細設計とする。 既存実装のふるまい、外部 API から取得するデータ、表示条件、失敗時の扱い、副作用、拡張による差し替え可能性を確認し、仕様の確からしさを把握することを目的とする。

対象はブラウザ経由の管理画面ホームの「おすすめのプラグイン」ブロックである。プラグイン検索画面、認証キー設定、インストール確認以降の Composer 実行、プラグイン有効化・無効化・削除は別機能として切り離す。

本書では Symfony の route 名、URL パス、Controller 構成は扱わない。 代わりに、ホーム画面表示、プラグイン詳細表示、インストール確認・購入・オーナーズストア検索への遷移といった利用者視点の入口ごとに期待されるふるまいを記載する。

本機能のカスタマイズ区分は標準であり、挙動・画面とも移行先のec-cube-enterpriseの実装を正とする。DB関連の記述（テーブル名・列名）もec-cube-enterpriseを正とする。

本書で扱うこと

  • ホーム画面表示時に、おすすめプラグイン一覧をどの外部連携から取得し、どの情報を画面に表示するか
  • 取得したプラグインごとに、インストール済み・アップデートあり・購入が必要といった状態をどの条件で判定するか
  • プラグイン名または画像を押下したときに詳細モーダルを表示し、モーダル内でどの導線を出し分けるか
  • おすすめ一覧の取得に失敗した場合、ホーム画面表示を継続し、プラグイン行を表示しないこと
  • 本ブロックに固有の DB 更新、キャッシュ更新、専用の業務監査ログが無いことの明示

本書で扱わないこと

以下は本書では仕様確定せず、実装または別機能の設計を正とする。

  • Symfony の route 名、URL パス、Controller クラス名・メソッド名の一覧
  • 管理画面へのアクセス制御、ログイン、二段階認証、権限設定の詳細
  • オーナーズストア検索画面の検索条件、ページネーション、カテゴリ一覧取得、検索結果の表示
  • プラグイン認証キーの発行・保存・検証
  • 無料プラグインのインストール確認後の Composer 実行、メンテナンスモード切替、キャッシュ削除
  • 有料プラグイン購入先での決済、購入完了後の状態反映
  • プラグイン有効化、無効化、アップデート、アンインストールの業務フロー
  • 外部 API のレスポンススキーマ全体、並び順、推薦ロジック
  • 外部 API 接続先の実 URL、認証キー原値、HTTP ヘッダの秘密値

リニューアル移行時の扱い

本機能はカスタマイズ区分が標準であり、リニューアル後はec-cube-enterpriseの標準実装を正とする。挙動・画面・DBスキーマとも移行先のec-cube-enterpriseに基づいて記述しており、現行（pf-eccube3）独自の差分は本書では仕様確定しない。

本書のDBカラム節で参照するテーブル・列（dtb_base_infoのauthentication_key、dtb_pluginのsource・version）は、いずれもec-cube-enterpriseのエンティティ定義で実在を確認した名称である。外部プラグインAPI通信に用いる認証キーはauthentication_key、インストール済み判定の突き合わせ元はsource、アップデート判定の比較値はversionであり、いずれも移行先の列名と一致する。現行リポと移行先でスキーマが食い違う列は本機能の参照範囲には見当たらないため、移行先の名称をそのまま正とする。確認できない差分が生じた場合は推測でスキーマを補わず、ec-cube-enterprise実装で要確認とする。

用語

用語説明
おすすめプラグインカードホーム画面に配置される、#ec-cube-plugin 領域。見出し文言はロケールにより「おすすめのプラグイン」等となる。
おすすめプラグイン外部のプラグイン API から取得する、ホーム画面に掲載する推奨プラグインの配列。推薦条件や並び順は外部 API の結果を正とする。
プラグイン詳細モーダルおすすめプラグインの画像または名称から開く、価格、対応バージョン、公開日、制作者、説明、インストール・購入導線を表示するモーダル。
インストール状態外部 API のプラグイン ID、購入要否、購入済み情報と、ローカルに登録済みのプラグイン情報を突き合わせて算出する表示・操作状態。
オーナーズストアプラグイン検索、購入、入手、詳細確認を行う外部ストアおよび管理画面内の関連機能。

利用者視点の入口

入口URLエンドポイント期待されるふるまい
ホーム画面を開くGET /%eccube_admin_route%/おすすめプラグインカードに、外部 API から取得できたプラグインの画像、名称、短い説明が縦に表示される。
おすすめ一覧の取得に失敗した状態でホーム画面を開くGET /%eccube_admin_route%/ホーム画面の表示は継続し、おすすめプラグインの行は表示されない。取得失敗を示す専用メッセージは本カード内に表示しない。
プラグイン画像または名称を押下—（同一 GET /%eccube_admin_route%/ 上でモーダル表示）同一画面上で対象プラグインの詳細モーダルを開く。
詳細モーダルで「入手する」または「アップデート」を押下GET /%eccube_admin_route%/store/plugin/install 等（対象プラグインに応じルーティング。実装を正とする）対象プラグインのインストール確認へ遷移する。
詳細モーダルで「購入する」を押下—（外部ストア URL へのフォームまたは window.open。当アプリのパスではない）外部ストアの購入導線を別ウィンドウで開くフォームを送信する。
詳細モーダルで「インストール済み」を表示—インストール確認や購入には進めず、状態表示として扱う。
詳細モーダルで「資料請求・お問い合わせ」または「マニュアルダウンロード」を押下—（外部 URL）外部 URL を別ウィンドウで開く。URL が無い項目のボタンは表示しない。
カード下部の「オーナーズストア」を押下GET /%eccube_admin_route%/store/plugin管理画面内のオーナーズストア検索へ遷移する。
非管理者・未認証GET /%eccube_admin_route%/ 等（到達前にログインへ）ホーム画面自体に到達できないため、本カードも利用できない。

フロント挙動

観点内容
表示要素おすすめプラグインカードには、見出し、プラグイン画像、プラグイン名、短い説明、カード下部のオーナーズストアリンクを表示する。プラグインごとに詳細モーダルも同一 HTML 内に出力する。
一覧レイアウトカード本文は最大高さを持ち、縦スクロールする。プラグインが 0 件の場合、本文内に空表示用の文言は出さず、カード下部のオーナーズストアリンクだけを表示する。
モーダル表示プラグイン画像または名称のリンクは Bootstrap のモーダル属性で対象プラグインの詳細モーダルを開く。モーダルは閉じるボタン、キャンセルボタンで閉じる。
モーダル内容画像、名称、短い説明、税込価格、ダウンロード数、バージョン、対応 EC-CUBE バージョン、公開日、最終更新日、ライセンス、制作者、問い合わせ URL、マニュアル URL、長い説明を表示する。
対応バージョン警告現在の EC-CUBE バージョンが対象プラグインの対応バージョン一覧に含まれない場合、モーダル内に警告を表示する。
JS 挙動本ブロック固有の JavaScript ファイルは持たない。モーダルの開閉は管理画面共通の Bootstrap 挙動に従う。おすすめ一覧の非同期再取得や表示中の自動更新は行わない。
CSS・レイアウト管理画面共通のカード、行、画像、モーダル、ボタンクラスを使う。本ブロック独自の条件分岐 CSS は持たない。
入力項目本ブロックは登録・更新のためのフォーム POST を持たない。プラグイン画像・名称からモーダルを開く操作、モーダル内の外部 URL ボタン押下、カード下部のオーナーズストア導線のみ。

処理フロー

ホーム画面表示・おすすめ一覧取得

  1. 管理者がホーム画面にアクセスしたとする。
  2. システムは受注状況、売上状況、ショップ状況を組み立て、ホーム表示組み立て完了時の拡張イベントを発火する。
  3. 拡張イベントの後に、おすすめプラグイン一覧を外部のプラグイン API から取得する。
  4. 外部 API へは、プラグイン認証キー、現在のサイト URL、EC-CUBE バージョンをヘッダとして送信する。認証キー原値は本書では扱わない。
  5. 外部 API のレスポンスを配列として読み込み、各プラグインにインストール状態と対応バージョン判定を付与する。
  6. 取得・加工に成功した場合、テンプレートへおすすめプラグイン配列を渡す。
  7. 外部 API 通信またはレスポンス処理でプラグイン API 例外が発生した場合、例外はホーム表示処理内で握りつぶし、テンプレートへ空配列を渡す。
  8. テンプレートは配列内の各プラグインを一覧表示し、プラグインごとの詳細モーダルを出力する。

インストール状態の付与

  1. システムはローカルに登録済みのプラグインを全件取得する。
  2. 各おすすめプラグインの状態を、初期値として「未インストール・未購入扱い」にする。
  3. ローカルプラグインの取得元 ID が外部 API のプラグイン ID と一致する場合、「インストール済み」にする。
  4. インストール済みで、ローカルのバージョンが外部 API のバージョンより古い場合、「アップデートあり」にする。
  5. 外部 API 上で未購入かつ購入が必要なプラグインの場合、「未購入の有料プラグイン」にする。この判定はインストール済み・アップデートあり判定の後に評価され、条件に一致した場合は表示状態を上書きする。
  6. 現在の EC-CUBE バージョンが外部 API の対応バージョン一覧に含まれるかを判定し、詳細モーダルの警告表示に使う。

詳細モーダル表示

  1. 利用者がプラグイン画像または名称を押下する。
  2. ブラウザは対象プラグイン ID に対応する詳細モーダルを同一画面上で開く。
  3. モーダルには API 取得値とインストール状態に基づく詳細情報、警告、導線を表示する。
  4. 利用者が閉じるボタンまたはキャンセルボタンを押下すると、モーダルを閉じてホーム画面へ戻る。サーバ通信は発生しない。

インストール確認・購入・外部 URL への導線

  1. 無料または入手可能な未インストールプラグインの場合、モーダルの主導線としてインストール確認へのリンクを表示する。
  2. インストール済みで更新が不要なプラグインの場合、モーダルの主導線は「インストール済み」の状態表示になる。
  3. インストール済みで外部 API 上のバージョンが新しいプラグインの場合、モーダルの主導線としてアップデート確認へのリンクを表示する。
  4. 未購入の有料プラグインの場合、モーダルの主導線として外部ストア購入用フォームの送信ボタンを表示する。フォームはプラグイン ID と公開鍵を送信し、外部ストアを別ウィンドウで開く。
  5. 問い合わせ URL またはマニュアル URL がある場合、モーダル内に外部リンクを表示する。押下時は別ウィンドウで開く。

集計条件

本機能では DB レコードの件数集計を行わない。 ただし、おすすめプラグイン配列の各要素に対して、ローカル登録済みプラグイン全件との突き合わせを行い、表示状態を算出する。

指標集計の要点
おすすめプラグイン件数外部 API が返した配列件数をそのまま表示対象件数とする。ホーム画面側で件数表示は行わない。
ローカルプラグイン突き合わせローカルの登録済みプラグイン全件を取得し、外部 API のプラグイン ID とローカルの取得元 ID が一致するかをプラグインごとに確認する。

インストール状態判定順序

順序判定結果
1外部 API から取得したプラグインを処理対象にする初期状態を「未インストール・未購入扱い」にする。
2ローカル登録済みプラグインの取得元 ID が外部 API のプラグイン ID と一致する「インストール済み」にする。
3手順 2 に一致し、ローカルのバージョンが外部 API のバージョンより古い「アップデートあり」にする。
4外部 API 上で未購入、かつ購入が必要である「未購入の有料プラグイン」にする。
5現在の EC-CUBE バージョンが対象プラグインの対応バージョン一覧に含まれる対応バージョン警告を表示しない。
6現在の EC-CUBE バージョンが対象プラグインの対応バージョン一覧に含まれない詳細モーダル内に非対応の警告を表示する。

画面上の主導線はインストール状態に応じて変わる。未インストール・未購入扱いでは「入手する」、インストール済みでは「インストール済み」、アップデートありでは「アップデート」、未購入の有料プラグインでは「購入する」を表示する。

業務ルール・計算

項目内容
外部 API の取得先設定値で定義されたプラグイン API の基底 URL に、おすすめ取得用のエンドポイントを連結して取得する。実 URL は環境値を確認値とし、本書では仕様固定しない。
送信ヘッダプラグイン認証キー、現在のサイト URL、EC-CUBE バージョンを送信する。認証キーの原値は表示・記録しない。
通信タイムアウト外部 API 通信にはタイムアウトが設定されている。タイムアウトまたは HTTP 200 以外はプラグイン API 例外として扱う。
レスポンスの扱い外部 API から返却された JSON を配列として扱い、ホーム画面側では推薦順や絞り込みを変更しない。
バージョン比較ローカルプラグインのバージョンが外部 API のバージョンより小さい場合、アップデートありと判定する。
対応バージョン現在の EC-CUBE バージョンが、外部 API 取得値の対応バージョン一覧に含まれるかで判定する。
価格表示モーダルでは価格を税込表記として表示する。無料プラグインではダウンロード数も表示する。

エッジケース

ケース扱い
外部 API が空配列を返すおすすめプラグイン行は表示しない。カード下部のオーナーズストアリンクは表示する。
外部 API 通信に失敗するホーム画面表示を継続し、おすすめプラグイン行は表示しない。本カード内にエラー文言は表示しない。
HTTP ステータスが 200 ではないプラグイン API 例外として扱い、ホーム画面では空配列表示にフォールバックする。
ローカルプラグインが 0 件すべてのおすすめプラグインは、購入要否判定を除き、未インストール・未購入扱いから判定する。
同じ取得元 ID のローカルプラグインが複数ある実装上は全件を走査し、一致したものに基づき状態を上書きする。重複登録時の正規化や一意制約は本機能では扱わない。
未購入かつ購入が必要なプラグインが、ローカル取得元 ID とも一致する購入要否判定が後段で評価されるため、表示状態は「購入する」側に上書きされる。
対応バージョン一覧に現在バージョンが含まれない一覧行は表示する。詳細モーダルに非対応警告を表示する。
問い合わせ URL またはマニュアル URL が空該当する外部リンクボタンは表示しない。
プラグイン画像が空一覧の画像は API 取得値をそのまま参照する。詳細モーダルでは代替画像を表示する。

データ整合性

観点内容
参照時点おすすめプラグイン一覧はホーム画面表示時に外部 API から取得した結果である。表示後に外部ストア側の推薦内容やローカルプラグイン状態が変わっても、表示中の内容は自動更新しない。
外部 API との整合性推薦対象、並び順、価格、説明、対応バージョンは外部 API の返却値を正とする。ホーム画面側では返却値の内容を業務的に補正しない。
ローカルプラグインとの整合性インストール状態は、ホーム画面表示時点のローカル登録済みプラグインと外部 API 取得値の突き合わせ結果である。インストール確認以降で状態が変わった場合、次回ホーム表示までカード内表示は更新しない。
一覧と詳細の整合性一覧行と詳細モーダルは同じ API 取得配列から同一 HTML 内に出力する。同一表示内では、対象プラグインの名称・説明・画像・状態は同じ取得値に基づく。
更新との整合性本ブロック自体はプラグインのインストール、購入、アップデート、DB 更新を実行しない。各導線の遷移後の整合性は、オーナーズストア検索・インストール確認・購入機能の設計を正とする。

API/バッチ結果

種類内容
APIホーム画面表示時に外部プラグイン API へおすすめ一覧取得の GET 通信を行う。入力は認証キー、サイト URL、EC-CUBE バージョンを含むヘッダであり、クエリ条件は付与しない。成功時はおすすめプラグイン配列を取得し、表示用状態を付与する。
API 失敗時通信失敗、HTTP 200 以外、実行結果 false はプラグイン API 例外として扱う。ホーム画面では例外を捕捉し、空配列として表示を継続する。
バッチ本ブロックはバッチを起動しない。外部 API やローカルプラグイン情報が別処理で更新済みの場合、次回のホーム画面表示時にその時点の値を読む。
再実行ホーム画面を再表示すると、外部 API への取得処理も再度実行する。カード内に手動更新ボタンはない。

入出力

種類内容
入力ホーム画面表示要求、外部 API のおすすめプラグインレスポンス、ローカル登録済みプラグイン、認証キー、サイト URL、EC-CUBE バージョン。
成功時出力おすすめプラグインカード、プラグイン行、詳細モーダル、状態別の導線。
失敗時出力外部 API 取得失敗時は、おすすめプラグイン行を表示しない。ホーム画面全体の表示は継続する。本カード専用のエラーメッセージは出さない。
副作用ホーム画面表示のみでは DB を更新しない。外部 API へサイト情報と認証キーを含む通信を行い、通信情報をログへ出力する。購入導線では外部ストアへのフォーム送信が発生する。

DBカラム

セッション

本機能はおすすめプラグインカードの表示、詳細モーダル表示、オーナーズストアリンク押下のためだけに専用セッションを更新しない。 カード下部のオーナーズストア検索へ遷移した後の検索条件セッションは、オーナーズストア検索機能の範囲とする。

Cookie

本機能はおすすめプラグインカードの表示のためだけに新たな Cookie を設定しない。ブラウザのセッション Cookie はフレームワークおよび管理画面全体の認証に用いられる。
