m02-03_admin_home_home_sales_chart（管理画面_トップ売上状況グラフ）

管理画面ホームに表示される、週間・月間・年間の売上金額推移を示す棒グラフ。

概要

管理画面ホームの売上状況グラフは、管理者がログイン後に最初に見るダッシュボード上で、受注台帳に基づく売上金額の推移を週間・月間・年間の3区間に分けて棒グラフで提示する機能である。グラフ用データはホーム画面表示後にブラウザから非同期で取得され、週間・月間・年間それぞれの canvas へ縦棒グラフとして描画される。週間・月間・年間はタブで切り替え、切替自体ではサーバへ再問い合わせしない。

本書は実装手順ではなく、誰が・いつ・どの条件で・結果どうなるかを読むためのリバース詳細設計とする。 既存実装のふるまい、参照するデータ、集計境界、描画方式、拡張による差し替え可能性を確認し、仕様の確からしさを把握することを目的とする。

対象はブラウザ経由の管理画面ホームの売上状況グラフである。今月・今日・昨日の売上サマリ数値、受注状況カード、ショップ状況、プラグイン案内、お知らせ iframe は別機能として切り離す。グラフと同じ受注集計の対象外ステータスやpayment_totalの扱いは売上サマリと共通であり、その既定集合・拡張差し替え・サマリとの関係は m02-02_admin_home_home_sales_status.md を正とし、本書では区間バケットとグラフ描画に限定して記載する。

管理画面プレフィックスはeccube.yamlのeccube_admin_routeで決まり、本書ではURLエンドポイントを%eccube_admin_route%で示す。Symfonyのroute名、Controllerクラス名・メソッド名は本文の主説明にしない。

本機能のカスタマイズ区分は標準であり、挙動・画面とも移行先のec-cube-enterpriseの実装を正とする。DB関連の記述（テーブル名・列名・集計列）もec-cube-enterpriseを正とする。

本書で扱うこと

  • ホーム画面表示後にグラフ用データを非同期取得する契機と、取得結果をどの canvas へ対応づけるか
  • 週間・月間・年間それぞれの集計区間の開始・終了境界とバケット単位
  • 年間区間でバケットキーを年月へ丸めることにより、月単位へ集約される実装上のふるまい
  • 売上が無い期間を 0 のバケットで埋め、横軸ラベルを欠けさせないこと
  • グラフが売上金額のみを系列として描画し、件数はデータに含まれるが当該グラフでは利用しないこと
  • 棒グラフのツールチップ・縦軸目盛りに通貨記号と桁区切りを適用し、縦軸目盛りは整数値のみを表示すること
  • 週間・月間・年間タブの切替が同一ページ内の表示切替であり、追加のサーバ問い合わせを伴わないこと
  • 非同期取得の前提条件（XMLHttpRequestかつCSRF検証）と、満たさないときの画面上のふるまい
  • 本グラフが受注台帳やマスタを更新せず、専用の業務監査ログを持たないこと

本書で扱わないこと

以下は本書では仕様確定せず、実装または別機能の設計を正とする。

  • Symfonyのroute名、Controllerクラス名・メソッド名の一覧
  • 今月・今日・昨日の売上サマリ数値の集計と表示（m02-02_admin_home_home_sales_status.mdを正とする）
  • 売上対象外ステータスの既定集合の確定列挙、拡張フックによる差し替え、受注状況カードとの除外の違い（m02-02_admin_home_home_sales_status.mdを正とする）
  • payment_totalの計上ルール、税・送料・値引・手数料の内訳、為替
  • 管理画面へのアクセス制御、ログイン、二段階認証、権限設定の詳細
  • 受注一覧・売上レポート・会計上の売上定義との完全一致要件
  • Chart.jsのバージョン固有の表示仕様の細部（配色・余白・アニメーション等）
  • Doctrineのクエリキャッシュ、ソフトデリートやマルチテナント等により受注が集計から除外される場合の詳細な条件列挙
  • データベース接続失敗時のHTTPステータスや例外型の列挙

リニューアル移行時の扱い

本機能はカスタマイズ区分が標準であり、リニューアル後はec-cube-enterpriseの標準実装を正とする。挙動・画面・DBスキーマとも移行先のec-cube-enterpriseに基づいて記述しており、現行（pf-eccube3）独自の差分は本書では仕様確定しない。

本書のDBカラム節・集計条件で参照するテーブル・列（dtb_orderのorder_date・payment_total・order_status_id）は、いずれもec-cube-enterpriseのエンティティ定義で実在を確認した名称である。グラフのバケットキーへの変換元はorder_date、棒の値はpayment_totalであり、いずれも移行先の列名と一致する。現行リポと移行先でスキーマが食い違う列は本機能の参照範囲には見当たらないため、移行先の名称をそのまま正とする。確認できない差分が生じた場合は推測でスキーマを補わず、ec-cube-enterprise実装で要確認とする。

フロント挙動

観点内容
表示要素売上状況カードのグラフ部分には、週間・月間・年間の3タブ、各タブに対応する canvas（chart-0・chart-1・chart-2）、読み込み中インジケータ（#loading）を配置する。初期状態は週間タブが選択済みである。
JS挙動ホーム画面表示後にグラフ用データを非同期で1回取得する。取得成功時、返却された配列の各要素を順にchart-0・chart-1・chart-2へ対応づけ、各canvasにChart.jsの棒グラフを生成する。各グラフはバケットキーを横軸ラベル、売上金額を縦棒の値とする。取得の成否にかかわらず完了時に読み込み中インジケータを非表示にする。
グラフ整形縦棒の値は売上金額のみを用いる。ツールチップの値は通貨記号を前置し、3桁区切りのカンマを付して整形する。縦軸目盛りは整数値のときのみ通貨記号と桁区切りを付して表示し、整数でない目盛り値はラベルを表示しない。各canvasの高さは100に設定する。
タブ切替週間・月間・年間タブは管理画面共通のピル型タブとして表示領域を切り替える。タブ切替では追加のサーバ問い合わせやグラフ再生成を行わない。
CSS・レイアウト管理画面共通のカード、タブ、グラフ領域、ローディング表示のクラスを使う。売上値の大小によるCSS条件分岐は本グラフでは扱わない。
モーダル・ポップアップ本グラフはモーダル、ポップアップ、トースト、確認ダイアログを表示しない。グラフ取得失敗時も利用者向けの専用通知は表示しない。
入力項目本グラフはフォーム・テキスト入力を持たない。タブ切替は表示領域の切替のみで、新たな利用者入力は発生しない。

処理フロー

ホーム画面表示・グラフ領域の初期描画

  1. 管理者がホーム画面にアクセスしたとする。
  2. サーバはホーム画面のHTMLを組み立て、売上状況カードに週間・月間・年間のタブと、各タブに対応する空のcanvas、読み込み中インジケータを出力する。この時点ではグラフは未描画である。
  3. ページ読み込み完了後、ブラウザがグラフ用データを非同期で要求する。

売上グラフ用データの取得と変換

  1. ブラウザがグラフ用データを非同期で要求する。要求はXMLHttpRequestであり、管理画面共通のAjax設定によりCSRFトークンが付与される。
  2. サーバはXMLHttpRequestかつCSRFが妥当かを判定する。いずれかを満たさない場合はHTTP400で{"status":"NG"}を返し、以降の集計を行わない。
  3. 条件を満たす場合、サーバは売上対象外ステータスを拡張フックで確定したうえで、次の三つの区間について確定後の売上集計対象の受注を読み取り、バケットに売上金額と件数を累積する。
  • 週間相当。当日0時から現在時刻までの区間。開始は当日から過去へ約一週間さかのぼった日とし、バケットキーは日単位（Y/m/d）である。
  • 月間相当。当月1日0時から現在時刻までの区間。バケットキーは日単位（Y/m/d）である。
  • 年間相当。現在時刻から過去へ約一年さかのぼった月の1日0時から現在時刻までの区間。バケットキーは年月単位（Y/m）である。
  1. 各区間について、開始日から終了日まで1日ずつ進めながらバケットを初期化し、各バケットの売上金額と件数を0で用意する。年間区間ではバケットキーが年月単位のため、同一月内の各日が同一キーへ集約され、結果として月単位のバケットになる。
  2. 範囲内の各受注を、その受注日をバケットキー書式へ変換して該当バケットへ加算する。売上金額はバケットの値へ加算し、件数はバケットの件数を1増やす。
  3. 三つのバケット集合を週間・月間・年間の順に並べた配列をJSONで返す。

画面への描画

  1. ブラウザは返却された配列を順にchart-0・chart-1・chart-2へ対応づける。
  2. 各バケット集合について、キーを横軸ラベル、売上金額を縦棒の値とする棒グラフを生成する。件数はバケットに含まれるが、棒グラフの系列としては使わない。
  3. 縦棒の系列ラベルは売上金額を示す文言とする。
  4. 非同期取得が完了すると読み込み中インジケータを非表示にする。取得に失敗した場合も読み込み表示は消えるが、グラフは描画されない。

集計条件

指標集計の要点
週間グラフ当日から過去へ約一週間さかのぼった日0時から現在時刻までのorder_dateを持ち、売上対象外ステータスに含まれない受注を、日単位（Y/m/d）のバケットへ集計する。各日に売上金額と件数を累積し、画面では売上金額のみを棒グラフに使う。
月間グラフ当月1日0時から現在時刻までのorder_dateを持ち、売上対象外ステータスに含まれない受注を、日単位（Y/m/d）のバケットへ集計する。各日に売上金額と件数を累積し、画面では売上金額のみを棒グラフに使う。
年間グラフ現在時刻から過去へ約一年さかのぼった月の1日0時から現在時刻までのorder_dateを持ち、売上対象外ステータスに含まれない受注を、年月単位（Y/m）のバケットへ集計する。各月に売上金額と件数を累積し、画面では売上金額のみを棒グラフに使う。

各区間とも開始日時以上かつ終了日時以下のorder_dateを対象とし、両端を含む範囲条件で受注を読み取る。終了日時は取得処理開始時の現在時刻である。タイムゾーンは永続化層および実行環境の設定に従う。売上対象外ステータスの既定集合と拡張差し替えは m02-02_admin_home_home_sales_status.md を正とする。

業務ルール・計算

項目内容
グラフ系列棒グラフの縦棒は売上金額のみを用いる。バケットの件数はJSONに含まれるが、グラフの系列としては使わない。
売上金額の累積バケット単位で、条件に一致する受注のpayment_totalを加算する。税、送料、値引、手数料の内訳は本グラフでは再計算しない。
バケットの初期化各区間について開始日から終了日まで1日ずつ進めてバケットキーを生成し、売上金額・件数を0で初期化する。これにより売上が無い期間も横軸ラベルとして残る。
年間の月集約年間区間はバケットキーを年月（Y/m）で生成するため、日単位で進めても同一月の各日が同一キーへ集約される。結果として年間グラフは月単位の棒になる。
表示形式ツールチップと縦軸目盛りは通貨記号を前置し、3桁区切りのカンマを付す。縦軸目盛りは整数値のときのみラベルを表示する。横軸ラベルはバケットキー（週間・月間はY/m/d、年間はY/m）をそのまま用いる。

本グラフは入力フォームを持たないため、保存・更新に紐づく入力項目表は持たない。タブ切替は表示領域の切替のみであり、サーバへ送る入力値を生成しない。

エッジケース

ケース扱い
該当受注が0件各区間のバケットはすべて0で埋まる。横軸ラベルは区間内の各日（年間は各月）が残り、棒の高さは0になる。
売上対象外ステータスの受注バケットへ加算しない。除外集合の確定は m02-02_admin_home_home_sales_status.md を正とする。
payment_totalが0の受注ステータスと期間条件に一致する場合、バケットの件数を1増やし、売上金額には0を加算する。棒グラフでは高さ0として扱う。
売上が無い日・月0で初期化済みのバケットが残り、横軸ラベルが欠けない。
月末・月またぎ週間・月間は日単位のためバケットが日ごとに並ぶ。年間は年月単位のため、同一月内の受注が同一バケットへ集約される。
表示後に受注が更新された描画済みのグラフは自動更新しない。ホーム画面再表示時に再度非同期取得した結果に従う。
グラフ用JSONに件数が含まれる棒グラフ描画では売上金額のみを使う。件数は当該グラフの表示系列として扱わない。

データ整合性

観点内容
参照時点グラフ用データはホーム画面表示後のAjaxで読み取った結果である。三つの区間は同一リクエスト内で順に集計され、終了境界はいずれも取得処理開始時の現在時刻に基づく。
サマリとグラフ今月・今日・昨日の売上サマリはホーム画面HTML表示時に読み取り、グラフは別リクエストで読み取る。両者を同一トランザクションで固定せず、表示直後に受注が更新された場合は値が一致しないことがある。
区間間の整合性週間・月間・年間は同一リクエスト内で順に集計するが、それぞれ独立した問い合わせ結果であり、スナップショットを固定しない。重なる期間（例: 当月の各日）の合計が区間間で厳密に一致することは保証しない。
一覧・レポートとの整合性受注一覧、売上レポート、会計上の売上定義との完全一致は本グラフでは保証しない。それぞれの機能の検索条件、対象ステータス、集計定義を正とする。
更新との整合性本グラフは参照のみであり、受注台帳やマスタを更新しない。受注更新との排他制御や再集計タイミングは各更新機能の設計を正とする。
外部連携との整合性外部連携やバッチにより受注が更新される場合の反映タイミングは、外部連携機能またはバッチ機能の設計を正とする。本グラフは読み取り時点の永続化済みデータだけを読む。

API/バッチ結果

種類内容
APIグラフ用データはホーム画面表示後に管理画面内のAjaxとしてJSONを取得する。サーバは週間・月間・年間のバケット集合を並べた配列を返す。
バッチ本グラフはバッチを起動しない。バッチによって受注が更新済みの場合、次回のグラフ取得時にその時点の永続化済みデータを読む。
成功時取得が成功した場合、週間・月間・年間のバケット集合を返し、画面は対応するcanvasに棒グラフを描画する。
失敗時XMLHttpRequestまたはCSRF検証の要件を満たさない場合、HTTP400で{"status":"NG"}を返す。フロント側は専用の利用者向けメッセージを表示せず、グラフ未描画の状態になる。

入出力

種類内容
入力ホーム画面のGET表示、およびグラフ用データのAjax GET。グラフ用データはクエリやボディでの利用者入力を受け取らず、認証済みセッションとCSRFトークンを前提とする。
成功時出力週間・月間・年間のバケット集合を並べたJSON配列。各バケットはキーごとに売上金額と件数を持つ。
失敗時出力Ajax要件またはCSRF検証を満たさない場合、HTTP400のJSON（statusがNG）を返す。データベース障害時はアプリケーションの共通例外処理に委ねられる。
副作用本グラフの処理だけを見ると、受注台帳やマスタを更新しない。グラフ取得でもセッションを本グラフ専用に書き換えない。

DBカラム
