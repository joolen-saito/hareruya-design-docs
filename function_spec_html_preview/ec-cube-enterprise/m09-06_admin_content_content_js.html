コンテンツ管理 — JavaScript管理

管理画面のコンテンツ管理配下で、店舗フロント全ページへ読み込まれるカスタマイズ用JavaScriptファイル（customize.js）の内容を編集画面のエディタで編集し、保存する機能である。

概要

JavaScript管理は、管理者がフロント共通テンプレートから読み込まれるカスタマイズ用JavaScriptの中身を画面上のコードエディタで編集し、登録ボタンで保存する機能である。保存先はデータベースの設定値ではなく、フロント側公開ディレクトリ配下のJavaScriptファイル1本である。保存と同時に、ファイルアダプタ経由でフロントのテーマ公開ディレクトリへも同名ファイルを配置する。

本機能のカスタマイズ区分は標準であり、挙動・DB関連ともに ec-cube-enterprise の実装を正とする。本機能は永続化先がサーバ上のJavaScriptファイルとフロント公開先であり、データベースへは保存しないため、DBスキーマを持たない。

本書は実装手順ではなく、誰が・いつ・どの条件で・結果どうなるかを読むためのリバース詳細設計とする。既存実装のふるまい、参照するファイル、保存経路、副作用、フロントへの出力経路を確認し、仕様の確からしさを把握することを目的とする。

対象はブラウザ経由の管理画面のJavaScript管理画面である。コントローラのメソッド単位の解剖は本文の主題としない。本文ではルート識別子の網羅は扱わず、利用者視点の入口にHTTPメソッドとサイトルートからのパスパターンを書く。管理画面プレフィックスは環境変数で決まる値であり、本書では設定キー eccube_admin_route のプレースホルダ %eccube_admin_route% で示す。

本書で扱うこと

  • JavaScript管理画面を開いたときに、既存のカスタマイズ用JavaScriptファイルの内容がエディタへ読み込まれる条件
  • 登録押下時に、入力内容がどのファイルへどの順序で保存されるか、保存後にフロント公開ディレクトリへ配置される経路
  • 保存成功時・保存失敗時の画面メッセージと画面遷移
  • コードエディタ（Ace）の構文エラー検知による登録ボタンの活性・非活性
  • 保存した内容がフロント全ページへ読み込まれる出力経路
  • ファイルアップロード機能の利用頻度に関する案内メッセージの初回表示

本書で扱わないこと

以下は本書では仕様確定せず、実装または別機能の設計を正とする。

  • 管理画面ログイン、権限マスタ、IP制限、CSRFの仕様の詳細（名称や値の環境依存を含む）
  • ファイルアダプタの選択（ローカルファイルアダプタ・S3アダプタ）の切替条件と各アダプタの内部実装の詳細
  • フロント共通テンプレートの全体構成、フロント側の表示・スタイルの詳細
  • コードエディタ（Ace）ライブラリの内部実装、JavaScript構文解析エンジンの判定精度
  • 環境変数 ECCUBE_RESTRICT_FILE_UPLOAD によるファイルアップロード機能無効化時の全体挙動
  • ページ管理（コンテンツ管理の他画面）の入力・保存ルール

本機能はカスタマイズ区分が標準であり、挙動・DB関連ともに ec-cube-enterprise の実装を正とする。

処理フロー

画面を開く（GET）

  1. 管理画面の認証・権限・IP制限の各ルールを通過する。
  2. ファイルアップロードの利用頻度に関する案内メッセージを、未表示であれば1回だけ管理画面向け情報メッセージとして積む。
  3. コード入力1つを持つフォームを組み立てる。コード入力は必須指定をフォーム側では付与しない（required=false）。
  4. 編集対象ファイル eccube_html_dir 配下 /user_data/assets/js/customize.js が存在し、かつ書き込み可能であれば、その内容をコード入力の初期値として設定する。いずれかを満たさない場合は初期値を設定せず空のまま表示する。
  5. テンプレートを描画する。エディタへフォーム値を流し込んで表示する。

登録押下（POST、書き込み成功）

  1. 送信されたコード入力でフォームを処理する。
  2. フォームが送信済みかつ妥当であれば保存処理へ進む。
  3. 編集対象ファイルへコード入力の内容を書き出す（ファイルが無ければ作成、あれば上書き）。
  4. 管理画面向けの保存完了メッセージを積む。
  5. 既定のファイルアダプタを取得し、編集対象ファイルをフロント公開先 /html/user_data/assets/js/customize.js としてファイル名 customize.js で配置する。
  6. 同一のJavaScript管理画面へリダイレクトする。

登録押下（POST、書き込み失敗）

  1. 送信されたコード入力でフォームを処理する。
  2. 編集対象ファイルへの書き出しで入出力例外が発生した場合、保存に失敗した旨のエラーメッセージを画面に表示する。
  3. 同内容をアプリケーションログにエラーとして記録する（対象ファイルパスと例外を含む）。
  4. リダイレクトせず同一画面のテンプレートを描画する。保存完了メッセージは積まない。

フロント側の読み込み

  1. フロント共通テンプレートが、フロント公開先のJavaScriptアセットを読み込むスクリプトタグを出力する。
  2. 配置済みの customize.js がフロント全ページで読み込まれる。

業務ルール・計算

項目内容
読み込み条件編集対象ファイルが存在し、かつ書き込み可能なときに限り、その内容をエディタへ初期表示する。書き込み不可・不存在なら空表示。
保存単位コード入力1つの内容をそのまま1ファイルへ書き出す。差分管理・履歴は持たない。常に全文上書きである。
保存経路まず管理サーバ上の編集対象ファイルへ書き出し、続いてファイルアダプタでフロント公開先へ配置する2段の経路である。
必須表示と検証の差画面のコード見出しには必須バッジを表示するが、フォーム側のコード入力は必須指定を付与しない。空文字でも検証を通過し、空内容で上書き保存され得る。
構文チェックの扱い構文エラーの検知と登録ボタン非活性はブラウザ側のエディタ機能である。サーバ側ではJavaScript構文の妥当性を検証しない。
フロント反映保存とフロント公開先への配置が成功すれば、以後フロント全ページの読み込み対象が更新後の内容になる。

入力項目

項目名必須／任意最大長初期値保存先・扱い
コード任意（画面表示は必須バッジ、フォームは required=false）フォーム上限なし（Symfony Length制約なし）。保存先はファイルのためDB列長の制約は受けない。編集対象ファイルが存在し書き込み可能なら当該ファイル内容、そうでなければ空eccube_html_dir 配下 /user_data/assets/js/customize.js へ全文書き出し（フォームキー js、複数行入力）。書き込み成功後、ファイルアダプタでフロント公開先 /html/user_data/assets/js/customize.js（ファイル名 customize.js）へ配置する。DBへは保存しない。

コード入力は複数行入力（textarea）であり、画面ではAceエディタで覆って編集する。送信時にエディタの現在値が非表示textareaへ書き戻されてサーバへ送られる。

エッジケース

ケース扱い
編集対象ファイルが存在しないエディタは空で表示する。登録すると新規にファイルを作成して書き込む。
編集対象ファイルが存在するが書き込み不可既存内容を初期表示しない（空表示）。登録時の書き込みで入出力例外となればエラーメッセージを表示する。
コードを空文字で登録フォーム検証を通過し、空内容でファイルを上書きする。フロント公開先も空内容で配置する。
ブラウザ側でJavaScript構文エラーを検知登録ボタンが非活性となり送信できない。サーバ側では構文の妥当性を検証しない。
ファイル書き込み中の入出力例外保存完了メッセージを積まず、保存失敗メッセージを表示し、アプリケーションログにエラーを記録する。

データ整合性

観点内容
編集対象ファイルとフロント公開先登録成功時は編集対象ファイルへ書き込んだ後にフロント公開先へ配置する。配置段階で例外が発生した場合、編集対象ファイルは更新済みでフロント公開先が未更新となる不一致が起き得る。
画面表示と保存値画面初期表示は編集対象ファイルの内容を読む。保存後はリダイレクトで再表示し、保存後の内容を読み直す。
同時編集複数管理者が同時に登録した場合、最後に書き込んだ内容がファイルに残る。版管理・楽観ロックは持たない。
フロント反映タイミングフロントは各ページ表示時にフロント公開先のアセットを読み込む。ブラウザキャッシュやCDNの反映遅延は本機能の管理範囲外とする。

API/バッチ結果

本機能ではAPI呼び出し・バッチ実行を扱わない。フロント公開先への配置はファイルアダプタによるファイル出力であり、外部API実行ではない。

入出力

種類内容
入力ブラウザからのGET（画面表示）、POST（登録）。フォーム項目はコード入力1つとなりすまし対策トークン。
成功時出力保存完了フラッシュを伴う同一画面へのリダイレクト応答。編集対象ファイルとフロント公開先のファイル更新。
失敗時出力書き込み失敗時は保存失敗メッセージ付きの同一画面HTML。
副作用編集対象ファイルの作成・上書き、フロント公開先ファイルの配置、フラッシュメッセージ、書き込み失敗時のアプリケーションログ記録。

DBカラム

本機能では入力内容をデータベースに保存しない。保存先はファイルシステム上の customize.js であり、当機能に直接関係するDB列は持たない。

バリデーション

項目内容
コードフォーム側で必須指定・Length制約・形式制約を付与しない。空文字を含めて任意の文字列を受け付ける。サーバ側でJavaScript構文の妥当性を検証しない。
構文チェックブラウザ側のエディタによる注釈で構文エラーを検知し、エラー時のみ登録ボタンを非活性にする。これはクライアント側の補助であり、サーバ側の検証ではない。
なりすまし対策トークン送信フォームにトークンを含める。検証はフレームワークの管理範囲とし、トークン値は本書では扱わない。

ログイン済み管理者（通常）許可（権限マスタ・IP制限を通過する場合）許可
ログイン済みだが権限マスタで当該パスが拒否拒否拒否

本画面に固有の追加権限判定はコントローラ実装からは読み取らない。アクセス可否は管理画面共通の認証・認可ルールに従う。
