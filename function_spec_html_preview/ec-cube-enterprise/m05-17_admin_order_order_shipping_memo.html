m05-17_admin_order_order_shipping_memo（管理画面_受注管理_配達用メモ登録）

受注編集画面および出荷編集画面の出荷情報にある「出荷用メモ欄」に、出荷作業者や配送業者向けのメモを出荷ごとに入力・保存する機能。

概要

管理画面の受注管理において、出荷ごとに出荷作業者や配送業者へのメモを記録するための機能である。受注編集画面の出荷情報ブロック、または出荷編集画面（お届け先編集）の各出荷ブロックに置かれた「出荷用メモ欄」へ文字列を入力し、受注（出荷）の保存に同梱して出荷へ保存する。保存した内容は出荷用CSV出力で参照できる。

本書は実装手順ではなく、誰が・いつ・どの条件で・結果どうなるかを読むためのリバース詳細設計とする。既存実装のふるまい、入力欄の制約、保存先、保存経路、CSV出力での参照、複数お届け先時の扱いを確認し、仕様の確からしさを把握することを目的とする。

対象はブラウザ経由の管理画面に限定する。管理画面プレフィックスはルート定義の%eccube_admin_route%で決まり、環境により異なる。本書の本文ではコントローラのメソッド一覧やSymfonyのルートIDの網羅は扱わず、「利用者視点の入口」にHTTPメソッドとサイトルートからのパスパターンを実装確認値として書く。

本機能のカスタマイズ区分は標準であり、挙動・画面およびDB（永続化先のテーブル・列）はともに ec-cube-enterprise の実装を正とする。

本書で扱うこと

  • 出荷用メモ欄が受注編集画面と出荷編集画面のどこに表示され、どの入力種別・制約を持つか
  • 出荷用メモの保存先列と最大長、未入力時の扱い
  • 出荷ごとにメモを持つこと、複数お届け先（出荷が複数）の場合の入力経路の違い
  • 出荷用メモが受注編集の保存または出荷編集の保存に同梱されて保存されること
  • 保存した出荷用メモが出荷用CSVの列として出力で参照されること
  • 本欄に固有のJavaScript・モーダル・専用API・専用バッチ・専用監査ログが無いこと

本書で扱わないこと

以下は本書では仕様確定せず、実装または別機能の設計を正とする。

  • 受注のショップ用メモ欄（受注本体のメモ、TODO上のM05-16）の入力・保存
  • 問い合わせ番号（出荷伝票番号、M05-13）の入力・保存
  • 受注ステータス変更（M05-14）の操作
  • 出荷情報のうち配送業者・お届け時間・お届け希望日・送料・氏名・住所など出荷用メモ以外の項目の編集仕様
  • 出荷登録時の在庫・購入フロー検証、商品明細の追加・削除、出荷メール送信の詳細
  • CSV出力機能そのものの画面操作・出力カラム設定・文字コード等の詳細
  • 管理画面ログイン、権限マスタ、IP制限、CSRFの値や名称の詳細
  • SymfonyのルートID・コントローラクラス名・メソッド名の一覧

リニューアル移行時の扱い

本機能は標準機能のため、現行と移行先（ec-cube-enterprise）で固有のスキーマ差分は生じない。出荷用メモの保存先である出荷（dtb_shipping.note）は ec-cube-enterprise のスキーマを正とし、同一スキーマとして扱う。dtb_shipping.note は文字列型・桁4000・NULL許容（ec-cube-enterprise 実装確認値）であり、フォーム側の最大長（eccube_ltext_len 確認値3000文字）の方が小さいため、保存可能な実効上限はフォーム側で決まる。CSV項目「配達用メモ」が参照する列も同一（dtb_shipping.note）である。現行実装との差異が判明した場合は ec-cube-enterprise 実装を正とする。

観点内容

表示要素（出荷編集）各出荷ブロックの中に、ラベル「出荷用メモ欄」と複数行入力欄（行数8）を表示する。出荷が複数あるときは出荷ごとに入力欄を表示する。
入力種別textareaによる複数行入力。受注編集画面ではテンプレート既定の行数、出荷編集画面では行数8で描画する。

CSS・レイアウト管理画面標準のフォームレイアウトに従い、ラベルと入力欄を1行に並べる。出荷用メモ欄の表示・非表示をクライアントスクリプトで切り替えない。
モーダル・ポップアップ出荷用メモ欄はモーダル、ポップアップ、トースト、確認ダイアログを表示しない。ラベルのツールチップのみ表示する。

処理フロー

受注編集画面を開く（出荷1件）

  1. 管理画面の認証・権限・IP制限の各ルールを通過する。
  2. 受注フォームを組み立てる際、受注が複数お届け先でない場合に限り、先頭の出荷を対象とした出荷フォームを受注フォームへ追加する。
  3. 出荷フォームの出荷用メモ欄には、対象出荷に保存済みのメモが初期値として載る。新規登録時は空となる。
  4. テンプレートを描画し、出荷情報ブロックに出荷用メモ欄を表示する。

受注編集画面で登録する（出荷1件）

  1. 受注フォームをリクエストで処理する。出荷用メモ欄の入力値は、受注フォームに紐づいた先頭の出荷へ反映される。
  2. 検証に成功した場合、出荷用メモを含む出荷情報が受注の保存に同梱されて永続化される。出荷が新規の場合は作成日時・更新日時が設定される。
  3. 検証に失敗した場合、同一編集画面を再描画し、入力値とエラーを表示する。出荷用メモは保存しない。

出荷編集画面を開く

  1. 認証・権限・IP制限の各ルールを通過する。
  2. 受注に紐づく出荷の集合を取得し、出荷ごとの入力ブロックを持つコレクションフォームを組み立てる。
  3. 各出荷ブロックの出荷用メモ欄に、当該出荷に保存済みのメモが初期値として載る。
  4. テンプレートを描画し、出荷ごとに出荷用メモ欄を表示する。

出荷編集画面で登録する

  1. 出荷コレクションフォームをリクエストで処理する。各出荷ブロックの出荷用メモ欄の入力値は、対応する出荷へ反映される。
  2. 購入フロー検証を行う。検証に成功し、かつ登録モードのときに各出荷を永続化する。新規の出荷は作成日時・更新日時を設定する。
  3. 保存に成功した場合、出荷登録の情報フラッシュと保存完了フラッシュを積み、出荷編集画面へリダイレクトする。
  4. 検証または保存に失敗した場合、エラーフラッシュを積み、同一画面を再描画する。出荷用メモは保存しない。

業務ルール・計算

項目内容
保存単位出荷用メモは出荷ごとに1つ持つ。1受注に複数の出荷があれば、出荷の数だけ独立してメモを持つ。
受注編集画面での入力範囲受注が複数お届け先でない場合のみ、受注編集画面で先頭の出荷の出荷用メモを編集できる。複数お届け先の受注では受注編集画面に出荷用メモ欄を表示しない。
複数お届け先での入力範囲複数お届け先を含む全出荷の出荷用メモは出荷編集画面で出荷ごとに編集する。
保存経路受注編集画面では受注の保存に同梱して保存する。出荷編集画面では出荷の保存に同梱して保存する。出荷用メモ単独の保存ボタン・専用APIは持たない。
未入力時の扱い出荷用メモ欄は任意項目。未入力のまま保存すると保存先列はNULL相当となる。
CSV出力での参照保存した出荷用メモは出荷用CSV・受注用CSVの項目「配達用メモ」として出力で参照できる。
計算出荷用メモに対する金額計算・税計算・丸めは行わない。

入力項目

項目名必須／任意最大長初期値保存先・扱い
出荷用メモ欄任意3000文字（フォームのLength上限。確認値eccube_ltext_len=3000）既存値または空（新規登録時は空）dtb_shipping.note（フォームキー note、複数行入力textarea）。ロケールキー admin.order.shop_memo_for_shipped。受注編集または出荷編集の保存に同梱して保存。未入力はNULL相当。出荷用CSVの項目「配達用メモ」として出力で参照する。

エッジケース

ケース扱い
出荷用メモを空のまま保存保存先列はNULL相当となる。エラーにはならない。
出荷用メモが3000文字を超えるフォームのLength検証で違反となり、保存しない。同一画面にエラーを表示する。

出荷編集画面でお届け先を追加追加された出荷の出荷用メモ欄は空で表示され、登録時に当該出荷へ保存される。
出荷編集画面でお届け先を削除削除対象の出荷は明細とともに削除され、その出荷の出荷用メモも保持されない。

データ整合性

観点内容
画面と保存値出荷用メモ欄の表示値は、画面を開いた時点で出荷に保存済みのメモである。表示後に別経路で出荷が更新されても表示中の値は自動更新しない。
受注編集と出荷編集の整合同一出荷の出荷用メモは、受注編集画面（出荷1件時）と出荷編集画面のどちらから編集しても同じ保存先列を更新する。最後に保存された内容が残る。
CSVとの整合出荷用CSVの「配達用メモ」列は、出力時点で出荷に保存済みのメモを出力する。画面表示中の未保存の入力はCSVに反映しない。
同時更新同一出荷を複数の管理者が同時に編集した場合、最後に保存された内容が残る。出荷用メモ単独の楽観ロックは持たない。

API/バッチ結果

本機能では出荷用メモの入力・保存のために専用のAPI呼び出し・バッチ実行を扱わない。保存した出荷用メモはCSV出力機能から参照されるが、CSV出力自体は別機能の範囲とする。

入出力

種類内容
入力受注編集画面または出荷編集画面のフォーム送信に含まれる出荷用メモ欄の文字列。
成功時出力検証成功時、出荷用メモを含む出荷情報を保存し、保存完了のフラッシュメッセージを伴って画面を再表示またはリダイレクトする。
失敗時出力検証失敗時は同一画面を再描画し、入力値とエラーを表示する。出荷用メモは保存しない。
副作用dtb_shipping.noteの更新。出荷新規時の作成日時・更新日時の設定。フラッシュメッセージ。

エラー処理

エラー内容処理
出荷用メモの最大長超過該当項目にエラーを表示し、同一画面を再描画する。保存しない。
出荷情報全体の検証失敗同一画面を再描画する。出荷用メモを含め保存しない。
出荷編集の保存処理で例外エラーフラッシュを積み、同一画面を再描画する。

試行制限

本機能では試行制限を扱わない。

ログ・監査

タイミング記録内容
出荷編集画面での出荷登録開始・完了受注識別子を伴うアプリケーションログを出力する。出荷用メモ欄に特化した監査ログは持たない。
受注編集画面での保存出荷用メモ欄単独の監査ログは持たない。受注保存全体のログに含まれる。

ログに出してはいけないもの

  • パスワード
  • なりすまし対策トークン
  • Cookie値
  • セッションIDの完全値

出荷用メモの本文に個人情報が含まれ得るため、ログに本文をそのまま出力しない。

セッション

本機能におけるセッション

観点内容
保存完了・エラーの通知リダイレクト後の画面で一度表示するため、保存完了やエラーのメッセージをフラッシュバッグへ格納する。

セッションへ保存しない情報

出荷用メモの本文や下書きをセッションへ長期保存する処理は持たない。

Cookie

本機能単体で特有のCookieは定義しない。セッションCookieは管理画面全体の実装を正とする。

排他制御・トランザクション

出荷用メモ欄に固有の楽観ロック・悲観ロックは持たない。同一出荷を同時に編集した場合は最後に保存された内容が残る。永続化の境界は受注編集・出荷編集の保存処理の実装を正とする。
