コンテンツ管理 — レイアウト管理

管理画面のコンテンツ管理にあるレイアウト管理。ページに配置するブロックを、テンプレートのセクションごとに割り当てたレイアウトとして作成・編集・削除し、プレビューする機能。

処理フロー

レイアウト一覧表示

  1. 管理者が一覧を開く。
  2. システムはレイアウトを取得する。プレビュー用の固定レイアウト（id0）は一覧から除外する。
  3. 取得結果を端末種別降順、id昇順で並べる。PCはモバイルより前に並ぶ。
  4. 各レイアウトについて、割り当て済みページを折りたたみ内に表示する。既定レイアウト（id0・1・2）には削除ボタンを表示しない。

レイアウト新規作成・編集表示

  1. 管理者が新規作成または編集を開く。
  2. 新規の場合は空のレイアウトを用意する。編集の場合は指定idのレイアウトを配置とブロックごと取得し、見つからなければ存在しない（HTTP404）として扱う。
  3. 配置済みブロックがあればそれを除いた残りを未使用ブロックとし、無ければ全ブロックを未使用ブロックとする。
  4. 名称・端末種別・プレビュー対象ページのフォームを組み立て、各セクションへ配置済みブロックを、未使用欄へ未使用ブロックを並べて表示する。

レイアウト保存（新規・編集共通）

  1. 管理者が登録ボタンで送信する。
  2. なりすまし対策トークンとフォーム検証を通す。名称が未入力なら検証エラーで保存しない。
  3. 検証を通れば、まずレイアウト本体（名称・端末種別）を保存する。
  4. 当該レイアウトの既存ブロック配置をすべて削除する。
  5. 送信されたブロックごとの隠しフィールド（ブロックID・配置先・行番号）を順に読み、配置先が未使用（target_id0）の行とブロックIDが取れない行は除外し、残りをブロック配置として作成する。
  6. Doctrineキャッシュを削除する。
  7. プレビュー送信でない通常保存のときは、保存しましたのフラッシュを積み、編集画面へリダイレクトする。

画面プレビュー

  1. 管理者がプレビューボタンで送信する。送信先はプレビューURLである。
  2. システムはプレビューモードで保存処理と同じ流れを実行し、レイアウトとブロック配置を更新する。
  3. 選択ページを取得し、見つからなければ存在しない（HTTP404）として扱う。
  4. ページの編集種別が既定以上で、URLが商品詳細のときは、表示中の商品を1件取り、その商品詳細をプレビュー付きで開く。表示商品が無ければ存在しない（HTTP404）として扱う。
  5. 商品詳細以外の既定以上のページは、そのページURLをプレビュー付きで開く。
  6. それ以外のページは利用者データ用ルートへ、対象ページURLとプレビュー指定を付けて開く。
  7. プレビューでは保存しましたのフラッシュを積まない。

レイアウト削除

  1. 管理者が削除を確認して送信する。
  2. なりすまし対策トークンを検証する。
  3. 当該レイアウトに割り当てページがあると削除不可と判定し、関連データがあるため削除できない旨の警告を積み一覧へ戻す。
  4. 削除可能なら削除し、削除しましたのフラッシュを積み、Doctrineキャッシュを削除して一覧へ戻す。

ブロックのコードプレビュー取得

  1. クライアントがコードプレビューを開いたときにAjaxでブロックIDを送る。
  2. Ajaxでない要求は不正な要求（HTTP400）として扱う。
  3. ブロックIDが無いと不正な要求（HTTP400）として扱う。
  4. ブロックが見つからなければ存在しない（HTTP404）として扱う。
  5. ブロックのテンプレートソースを読み、ブロックIDとソースをJSONで返す。

入出力

種類内容
入力一覧・編集表示のGET要求、保存・プレビュー・削除のPOST／DELETE要求、コードプレビューのAjax GET要求。
成功時出力一覧・編集画面のHTML、保存・削除後のリダイレクトとフラッシュ、プレビューでのフロント画面、コードプレビューのJSON。
失敗時出力検証エラー時は編集画面を再表示しインラインエラーを出す。対象未検出は存在しない（HTTP404）、不正なAjaxは不正な要求（HTTP400）。
副作用レイアウト本体とブロック配置の永続化、Doctrineキャッシュ削除、フラッシュメッセージ。

業務ロジック

業務ルール・計算

項目内容
一覧の対象プレビュー用固定レイアウト（id0）を除く全レイアウトを対象とする。端末種別降順・id昇順で並べる。
削除可否割り当てページが1件でもあるレイアウトは削除しない。既定レイアウト（id0・1・2）は一覧で削除ボタンを表示しない。
ブロック配置の再構築保存のたびに当該レイアウトの既存配置を全削除し、送信値から作り直す。差分更新はしない。
未使用ブロックの扱い配置先が未使用（target_id0）の行とブロックIDが取れない行は配置として保存しない。
行番号各セクション内のブロックの並び順は、クライアントが0始まりで再採番した行番号（block_row）として送信し、保存する。表示時はこの行番号の昇順で並べる。
端末種別レイアウトはPCまたはモバイルのいずれかの端末種別を持つ。新規時は選択、既存編集時は変更せず保持する。

データ整合性

観点内容
一覧と編集一覧はプレビュー用固定レイアウトを除く全件。編集はid指定で配置・ブロックごと取得する。
ブロック配置保存のたびに当該レイアウトの配置を全削除して再作成する。途中失敗時の整合はトランザクション境界の実装を正とする。
ドラッグ＆ドロップと送信画面上の並びと隠しフィールドの行番号・配置先は、移動確定時のクライアント処理で同期する。送信されるのはこの隠しフィールド値である。
プレビューと保存画面プレビューは保存処理を伴うため、プレビュー実行時点でレイアウトとブロック配置が更新される。
キャッシュ保存・削除のたびにDoctrineキャッシュを削除する。フロント表示への反映タイミングはキャッシュ実装を正とする。
割り当てページレイアウトとページの紐付け自体の編集はページ設定機能の範囲とし、本機能は削除可否判定で参照するだけである。
