m09-01_admin_content_content_news（管理画面_新着情報管理）

管理画面のコンテンツ管理配下で、フロントTOPページ等に表示する新着情報の一覧表示・新規登録・編集・削除を行う機能。

処理フロー

一覧を開く（GET）

  1. 管理画面の認証・認可の各ルールを通過する。
  2. 全件取得用のクエリを組み立て、公開日時の降順、同一公開日時では識別子の降順で並べる。
  3. 一覧初期化イベントをディスパッチする（プラグイン等がクエリビルダを参照・加工できる）。
  4. 1ページ10件でページングし、テンプレートを描画する。

新規登録画面を開く（識別子が新規）

  1. 新規の新着情報を組み立て、公開日時に現在日時を設定する。
  2. フォームビルダーを生成し、編集初期化イベントをディスパッチする。
  3. フォームを構築する。POSTでなければテンプレートを描画する。

既存編集画面を開く（識別子が既存）

  1. 識別子で新着情報を取得する。取得できなければ見つからない扱い（HTTP404）とする。
  2. 以降はフォームビルダー生成・編集初期化イベント・フォーム構築まで新規と同様に進む。POSTでなければテンプレートを描画する。

「登録」押下（POST、検証成功）

  1. フォームをリクエストで処理する。
  2. 検証成功時、リンクURLが空であれば「別ウィンドウで開く」設定を無効に揃える。
  3. 新着情報を永続化する。新規ならこの時点で識別子が採番される。作成日時・更新日時・作成者は永続化前のDoctrineイベントで設定される。
  4. 編集完了イベントをディスパッチする。
  5. 管理画面向け成功メッセージを積む。
  6. Doctrineの二次キャッシュを削除する。
  7. 当該新着情報の編集画面へリダイレクトする。

「登録」押下（POST、検証失敗）

  1. フォームをリクエストで処理する。
  2. 検証失敗時、同一編集テンプレートを再描画する。成功メッセージは積まない。

削除実行（DELETE）

  1. なりすまし対策トークンを検証する。失敗時はアクセス拒否（HTTP例外）となる。
  2. 識別子で対象の新着情報を取得する。取得できなければ見つからない扱い（HTTP404）になる。
  3. 削除処理を試みる。成功時は削除完了イベントをディスパッチし、成功メッセージを積み、二次キャッシュを削除する。
  4. 削除中に例外が発生した場合は、対象タイトルを差し込んだ関連データ存在エラーのメッセージを積む。
  5. 一覧へリダイレクトする。

入出力

種類内容
入力ブラウザからのGET（一覧・ページング・編集）、POST（登録）、DELETE相当のリクエスト（削除モーダル経由）。
成功時出力HTMLページまたはリダイレクト応答。登録成功時は編集画面へ、削除成功時は一覧へ遷移し、管理画面向け成功メッセージが付く。
失敗時出力フォーム検証失敗時は同一編集画面にエラー表示。削除失敗時は一覧にエラーメッセージ。トークン不正時はアクセス拒否。対象不存在は見つからない扱い（HTTP404）。
副作用dtb_newsの登録・更新・削除。作成日時・更新日時・作成者の設定。フラッシュメッセージ。二次キャッシュ削除。削除時のアプリケーションログ出力。プラグインイベントの発火。

業務ルール・計算

項目内容

新規の公開日時初期値新規登録画面表示時の現在日時。
公開状態公開（保存値は真）／非公開（保存値は偽）の2択。新規の初期選択は公開（DB既定が真）。
別ウィンドウで開くの整合リンクURLが空の場合、保存直前に「別ウィンドウで開く」を無効（偽）へ揃える。
本文のHTML本文は保存時にHTML浄化（purify）を通す。HTMLタグの利用は可能だが、浄化により一部の記述は除去・整形される。

入力項目

項目名必須／任意最大長初期値保存先・扱い
公開日時必須—新規は現在日時、既存はDB値dtb_news.publish_date。秒まで含む日時。下限は0003-01-01より前を不正日付として拒否する。
タイトル必須200文字既存値または空dtb_news.title。DB列は255文字だが、フォーム検証は200文字（eccube_mtext_len確認値）。
URL任意200文字既存値または空dtb_news.url。DB列は4000文字。入力時はURL形式制約。フォーム検証は200文字（eccube_mtext_len確認値）。
別ウィンドウで開く任意—既存値または未チェック（偽）dtb_news.link_method。チェック時に真。URL未入力時は保存直前に偽へ上書きする。
本文任意3000文字既存値または空dtb_news.description。複数行入力（textarea、表示行数8）。HTML浄化を通す。フォーム検証は3000文字（eccube_ltext_len確認値）。
公開状態必須—新規は公開、既存はDB値dtb_news.visible。公開で真、非公開で偽を保存する。

最大長の数値はコア設定のeccube_mtext_len（確認値200）、eccube_ltext_len（確認値3000）を記載する。運用環境で上書きされている場合はその環境の値が正とする。

エッジケース

ケース扱い
編集対象の識別子が存在しない見つからない扱い（HTTP404）となる。新規相当の扱いにはならない。
削除対象の識別子が存在しない見つからない扱い（HTTP404）となる。
削除時に関連データがある等で例外発生関連データ存在エラーのメッセージを積み、一覧へリダイレクトする。物理削除は完了しない。
URL未入力で別ウィンドウチェックあり保存直前に別ウィンドウ設定を偽へ揃える。
公開日時が下限より前不正日付として検証エラーになり保存しない。
一覧が0件見出し行のみ表示し、明細行を出さない。

データ整合性

観点内容
一覧と編集一覧は全件（公開・非公開とも）を公開日時降順で表示する。編集は識別子指定で取得した行を対象とする。
フロント表示との整合管理側の一覧は公開日時による絞り込みをしない。フロント側の表示・抜粋・公開日時判定は別機能の実装を正とし、本機能の一覧表示と一致を保証しない。
二次キャッシュ保存・削除の成功時にDoctrineの二次キャッシュを削除する。これにより次回読み取りで最新状態を反映する。
作成日時・更新日時・作成者永続化直前のDoctrineイベントで、新規時は作成日時・更新日時、更新時は更新日時が設定される。管理者ログイン下では作成者がログインユーザに設定される。
同時更新楽観ロックによる版管理は持たない。複数管理者が同一新着情報を同時編集した場合は最後に保存した内容が残る。
