admin_content_cache（管理画面_コンテンツ管理_キャッシュ管理）

管理画面のコンテンツ管理にあるキャッシュ管理画面で、管理者がボタン操作によりアプリケーションのキャッシュを削除する機能。

概要

キャッシュ管理は、本番環境にTwigファイルなどを差し替えた際に画面表示へ反映させるため、管理者がボタン押下でアプリケーションのキャッシュを削除できるようにする機能である。削除はSymfonyのキャッシュ全体を対象とし、レスポンス送出後に実行する。

本書は実装手順ではなく、誰が・いつ・どの条件で・結果どうなるかを読むためのリバース詳細設計とする。既存実装のふるまい、削除されるキャッシュの範囲、メンテナンスモードとの関係、表示メッセージ、副作用を確認し、仕様の確からしさを把握することを目的とする。

対象はブラウザ経由の管理画面のキャッシュ管理画面である。

管理画面プレフィックスは環境により変わるため、本書では%eccube_admin_route%で表す。値はeccube.yamlのeccube_admin_route（環境変数ECCUBE_ADMIN_ROUTE由来）で決まる。bind名やSymfonyのルートnameの網羅は本文では扱わず、必要な照合値は「調査補助」に隔離する。

本書で扱うこと

  • キャッシュ管理画面の表示と、キャッシュ削除ボタン押下時のふるまい
  • 削除されるキャッシュの種類と、削除がレスポンス送出後に実行される実装上の特性
  • メンテナンスモードを許可する設定が有効な場合に、削除前後でメンテナンスモードへ切り替え・解除する挙動
  • 削除完了時に表示するフラッシュメッセージ
  • 本画面が入力フォーム項目を持たず、ボタン操作中心であること

処理フロー

キャッシュ管理画面の表示

  1. 管理者がキャッシュ管理画面を開く。
  2. システムは空のフォーム（なりすまし対策トークンのみ）を生成し、説明文と削除ボタンを表示する。
  3. この時点ではキャッシュ削除を行わない。

キャッシュ削除ボタン押下

  1. 利用者がキャッシュ削除ボタンを押下し、同一URLへPOSTする。
  2. システムはなりすまし対策トークンを検証する。送信が妥当でない場合はキャッシュ削除を行わず画面を再表示する。
  3. メンテナンスモード許可設定が有効な場合、自動メンテナンスモードへ切り替える。無効な場合は切り替えない。
  4. キャッシュ削除を予約する。この時点では削除コマンドを実行せず、レスポンス送出後に実行する予約だけを行う。
  5. メンテナンスモード許可設定が有効な場合、メンテナンス解除フラグのフラッシュを登録する。
  6. 削除完了のフラッシュメッセージを登録し、同一画面を再表示する。
  7. レスポンス送出が完了した後、予約に従いキャッシュ削除コマンドを実行する。あわせてopcache・APC・WinCacheのユーザーキャッシュをリセットする。
  8. メンテナンスモード許可設定が有効な場合、再表示された画面のJSがメンテナンス解除エンドポイントへ非同期POSTし、自動メンテナンスモードを解除する。
