m02-04_admin_home_home_shop_status（管理画面_トップショップ状況）

管理画面ホームに表示される、在庫切れ商品数・取扱商品数・本会員数の要約と、商品一覧・会員一覧への導線。

概要

管理画面ホームのショップ状況は、管理者がログイン後に最初に見るダッシュボード上で、商品マスタと会員マスタに基づく3種類の件数を提示し、必要に応じて該当する一覧画面へ遷移して業務を始められるようにする機能である。

本書は実装手順ではなく、誰が・いつ・どの条件で・結果どうなるかを読むためのリバース詳細設計とする。 既存実装のふるまい、参照するデータ、集計境界、拡張による差し替え可能性を確認し、仕様の確からしさを把握することを目的とする。

対象はブラウザ経由の管理画面ホームの「ショップ状況」ブロックである。受注ステータス別件数、売上サマリ・グラフ、プラグイン案内、お知らせ iframe は別機能として切り離す。

本書では Symfony の route 名、Controller 構成は扱わない。 URL エンドポイントは利用者視点の入口に限り、実装確認値として記載する。

本機能のカスタマイズ区分は標準であり、挙動・画面とも移行先のec-cube-enterpriseの実装を正とする。DB関連の記述（テーブル名・列名・集計列）もec-cube-enterpriseを正とする。

本書で扱うこと

  • ホーム画面表示時に、在庫切れ商品数・取扱商品数・本会員数がどの条件で集計されるか
  • 各指標のリンクから一覧へ遷移したとき、検索条件セッションにどのように値が書き込まれるか（入口としての役割に限る）
  • 取扱商品数のリンクでは検索条件を事前セットしないこと
  • ホーム組み立て完了時の拡張イベントにより、イベント引数にショップ状況用の集計値が公開されること、および画面表示がイベント引数の書き換えから自動的に追随しない実装上の注意
  • 本ブロックに固有の Ajax 取得、台帳・マスタの更新、専用の業務監査ログが無いことの明示

本書で扱わないこと

以下は本書では仕様確定せず、実装または別機能の設計を正とする。

  • Symfony の route 名、Controller クラス名・メソッド名の一覧
  • 管理画面へのアクセス制御、ログイン、二段階認証、権限設定の詳細
  • 商品一覧の検索フォーム全般、ページネーション、CSV、一括操作、在庫改定業務
  • 会員一覧の検索フォーム全般、ページネーション、CSV、会員編集
  • 商品ステータス・会員ステータスのマスタ管理画面での編集ルール
  • プラグインのイベント識別子やフックの直列名の確定表記
  • Doctrine のグローバルフィルタ、マルチテナント、ソフトデリートにより行集合が変わる場合の詳細な条件列挙
  • データベース接続失敗時の HTTP ステータスや例外型の列挙

リニューアル移行時の扱い

本機能はカスタマイズ区分が標準であり、リニューアル後はec-cube-enterpriseの標準実装を正とする。挙動・画面・DBスキーマとも移行先のec-cube-enterpriseに基づいて記述しており、現行（pf-eccube3）独自の差分は本書では仕様確定しない。

本書のDBカラム節・集計条件で参照するテーブル・列（dtb_productのid・product_status_id、dtb_product_classのproduct_id・stock・stock_unlimited・visible、dtb_customerのid・customer_status_id）は、いずれもec-cube-enterpriseのエンティティ定義で実在を確認した名称である。在庫切れ判定のstock・stock_unlimited・visible、取扱商品判定のproduct_status_id、本会員判定のcustomer_status_idは、いずれも移行先の列名と一致する。現行リポと移行先でスキーマが食い違う列は本機能の参照範囲には見当たらないため、移行先の名称をそのまま正とする。確認できない差分が生じた場合は推測でスキーマを補わず、ec-cube-enterprise実装で要確認とする。

用語

用語説明
ショップ状況カードホーム画面に配置される、#shop-statistical 領域。見出し文言はロケールにより「ショップ状況」等となる。
在庫切れ商品数表示可能な商品規格のうち、在庫無制限でなく在庫数量が 0 の規格を少なくとも一つ持つ商品の件数。同一商品に複数規格が該当しても商品は 1 として数える。
取扱商品数商品ステータスが「公開」または「非公開」である商品の件数。「廃止」は含めない。
本会員数会員ステータスが本会員である会員の件数。日本語ロケールでは見出しを「会員数」と表示するが、集計は本会員に限定する。
検索条件セッション商品一覧・会員一覧が初回表示や再表示で参照する検索条件を格納したセッション領域。ショップ状況の一部リンクは、この領域へ値を書き込んでから一覧へ誘導する。
ホーム画面管理者認証後に表示されるダッシュボード。ショップ状況はその一部ブロックである。

利用者視点の入口

入口URLエンドポイント期待されるふるまい
ホーム画面を開くGET /%eccube_admin_route%/ショップ状況カードに、在庫切れ商品数・取扱商品数・本会員数が数値で表示される。
在庫切れ商品数の行を押下GET /%eccube_admin_route%/search_nonstock在庫なし条件を商品一覧向け検索条件として保存し、商品一覧へ遷移する。
取扱商品数の行を押下GET /%eccube_admin_route%/product商品一覧へ遷移する。ショップ状況側では商品一覧向けの検索条件を事前に書き込まない。
会員数の行を押下GET /%eccube_admin_route%/search_customer本会員条件を会員一覧向け検索条件として保存し、会員一覧へ遷移する。
非管理者・未認証GET /%eccube_admin_route%/ などの管理側URLホーム画面自体に到達できないため、本カードも利用できない。

フロント挙動

観点内容
表示要素ショップ状況カードには、見出しと、在庫切れ商品数・取扱商品数・本会員数に対応する3行を表示する。各行はアイコン・ラベル・件数で構成し、件数は桁区切りで表示する。
JS 挙動本ブロック専用の JavaScript は持たない。件数の取得、表示切替、非同期更新は行わない。
CSS・レイアウト管理画面共通のカード、行、アイコン、余白、枠線のクラスを使い、3行を縦に並べて表示する。CSS による条件分岐表示や状態変更は本ブロックでは扱わない。
モーダル・ポップアップ本ブロックはモーダル、ポップアップ、トースト、確認ダイアログを表示しない。
入力項目本ブロックはフォーム・テキスト入力を持たない。件数行のリンク押下のみ。

処理フロー

ホーム画面表示・ショップ状況用集計

  1. 管理者がホーム画面にアクセスしたとする。
  2. システムはデータベースへ問い合わせ、在庫切れ商品数・取扱商品数・本会員数をそれぞれ集計する。詳細は後述の「集計条件」を参照する。
  3. ホーム表示組み立ての終盤で、ダッシュボード全体向けの拡張イベントが発火し、イベント引数として受注状況・売上サマリに加え、上記の3指標も渡される。
  4. 画面へ渡す最終的なテンプレート変数は、イベント dispatch の直前に保持したローカル変数から組み立てられる。リスナーがイベント引数内の集計値を書き換えても、dispatch 後にその引数から再読込しない限り、画面表示は自動では変わらない。

在庫切れ商品数から商品一覧へ

  1. 利用者が在庫切れ商品数の行を押下する。
  2. システムは商品一覧向けの検索条件セッションに、「在庫なし」に相当する条件だけを格納した連想配列を保存する。既存の検索条件は本処理ではマージせず、当該セッション領域をこの配列で上書きする。
  3. 商品一覧の1ページ目へリダイレクトする。
  4. 以降の一覧の検索UI・件数・ページ送りは商品一覧機能の実装に従う。

取扱商品数から商品一覧へ

  1. 利用者が取扱商品数の行を押下する。
  2. 商品一覧へ遷移する。ショップ状況側では検索条件セッションを更新しない。
  3. 以降の一覧の初期状態は商品一覧機能の実装に従う。

会員数から会員一覧へ

  1. 利用者が会員数の行を押下する。
  2. システムは会員一覧向けの検索条件セッションに、「本会員」に相当する会員ステータス条件だけを格納した連想配列を保存する。既存の検索条件は本処理ではマージせず、当該セッション領域をこの配列で上書きする。
  3. 会員一覧の1ページ目へリダイレクトする。
  4. 以降の一覧の検索UI・件数・ページ送りは会員一覧機能の実装に従う。

集計条件

指標集計の要点
在庫切れ商品数商品とその商品規格を内部結合する。規格について stock_unlimited が偽、かつ stock が 0、かつ visible が真である行が存在する商品について、商品 ID を一意に数える。商品本体のステータスでさらに絞り込む条件は課していない。
取扱商品数商品のステータスが「公開」または「非公開」に属する商品を数える。「廃止」は対象外とする。
本会員数会員のステータスが本会員である行のみを数える。

グローバルフィルタや永続化層の共通規則による対象行の扱いは、各共通機能の設計を正とする。本書ではその詳細を列挙しない。

業務ルール・計算

項目内容
在庫切れ商品数商品規格単位で在庫無制限でなく、在庫数量が 0、かつ表示対象の規格を抽出し、その規格を持つ商品 ID を一意に数える。同じ商品に複数の在庫切れ規格がある場合も、商品数としては 1 件で数える。
取扱商品数商品ステータスが公開または非公開の商品を数える。廃止ステータスの商品は数えない。
本会員数会員ステータスが本会員の会員を数える。仮会員、退会、その他の会員ステータスは数えない。
表示形式3 指標はいずれも整数件数として表示し、画面では桁区切りを適用する。金額計算、税計算、丸め処理は行わない。
リンク時の条件在庫切れ商品数からの遷移では在庫なし条件を保存する。会員数からの遷移では本会員条件を保存する。取扱商品数からの遷移では検索条件を保存しない。

エッジケース

ケース扱い
商品規格を持たない商品在庫切れ商品数では商品規格と内部結合するため数えない。取扱商品数では商品規格の有無を条件にしないため、商品ステータスが公開または非公開なら数える。
在庫無制限の商品規格在庫数量が 0 でも在庫切れ商品数には数えない。
在庫数量が 0 ではない商品規格在庫数量が正数、負数、NULL のいずれでも、在庫数量 0 の条件に一致しないため在庫切れ商品数には数えない。
非表示の商品規格在庫数量が 0 でも在庫切れ商品数には数えない。
1 商品に複数の在庫切れ商品規格がある商品 ID を一意に数えるため、在庫切れ商品数では 1 件として数える。
廃止ステータスの商品取扱商品数には数えない。在庫切れ商品数では商品本体のステータスを条件にしないため、表示対象の在庫切れ商品規格があれば数える。
仮会員・退会会員本会員数には数えない。
該当データが 0 件件数は 0 として表示する。
在庫切れ商品数のリンク押下前に商品一覧検索条件が残っている既存の検索条件をマージせず、在庫なし条件だけの検索条件で上書きする。
会員数のリンク押下前に会員一覧検索条件が残っている既存の検索条件をマージせず、本会員条件だけの検索条件で上書きする。
取扱商品数のリンク押下前に商品一覧検索条件が残っているショップ状況側では検索条件セッションを更新しない。遷移後の初期状態は商品一覧機能の既定動作に従う。

データ整合性

観点内容
参照時点ショップ状況の3指標は、ホーム画面表示時にそれぞれデータベースから読み取った件数である。表示後に商品・商品規格・会員が更新されても、表示中の数値は自動更新しない。
指標間の整合性3 指標はそれぞれ独立した問い合わせ結果であり、同一トランザクションでスナップショットを固定しない。
一覧との整合性在庫切れ商品数は商品単位で数える。一覧側の表示単位、検索条件、ページング、検索条件解除後の状態との件数一致は保証しない。取扱商品数と本会員数も、遷移後の一覧機能側の検索条件と表示ルールを正とする。
更新との整合性本ブロックは参照のみであり、商品、商品規格、会員の更新は行わない。更新処理との排他制御や再集計タイミングは各更新機能の設計を正とする。
外部連携との整合性在庫や会員情報を外部連携で更新する場合の反映タイミングは、外部連携機能またはバッチ機能の設計を正とする。本ブロックは表示時点の永続化済みデータだけを読む。

API/バッチ結果

種類内容
API本ブロックは件数表示のために専用 API を呼び出さない。ホーム画面の画面全体をサーバ側で HTML として組み立てる処理のなかで、件数だけをデータベースから読み取る。
バッチ本ブロックはバッチを起動しない。バッチによって商品・商品規格・会員が更新済みの場合、次回のホーム画面表示時にその時点の永続化済みデータを読む。
失敗時API 呼び出しやバッチ実行の成否を本ブロック内で判定しない。件数取得のデータベース読み取りに失敗した場合は、アプリケーションの共通例外処理に委ねる。

入出力

種類内容
入力ホーム画面表示要求、および各リンクの GET 要求。フォーム POST は持たない。
成功時出力ホーム画面ではサーバ側が HTML を組み立て、その一部としてショップ状況カードに在庫切れ商品数・取扱商品数・本会員数の各件数を載せる。各指標行を押したあとはリダイレクトにより、商品一覧画面または会員一覧画面がサーバ側で再描画される。
失敗時出力データ取得失敗時はフレームワークの例外処理に委ねられ、ホーム画面全体の表示が成立しないことがある。本ブロック単体のフォールバック文言は専用に定義しない。
副作用ホーム表示処理だけを見ると、商品・会員・受注等の台帳を更新しない。リンク経由では検索条件セッションへの書き込みとリダイレクトが起きる。

バリデーション

項目内容
利用者入力本ブロックはフォームを持たない。リンク経由の遷移のみ。

権限・認可

利用者状態ショップ状況カード

画面遷移

条件遷移先
ホーム画面を開く同一画面内にショップ状況を表示。
在庫切れ商品数を押下商品一覧。在庫なし条件を検索条件として保存してから遷移する。
取扱商品数を押下商品一覧。ショップ状況側の検索条件事前セットはない。
会員数を押下会員一覧。本会員条件を検索条件として保存してから遷移する。

遷移時に引き継ぐ検索条件

起点遷移前の処理遷移後の初期状態
在庫切れ商品数商品一覧向けの検索条件セッションへ、在庫なしに相当する条件を保存する。商品一覧の1ページ目で、保存した在庫なし条件を初期条件として扱う。
取扱商品数ショップ状況側では検索条件セッションを書き換えない。商品一覧の初期状態は商品一覧機能の既定動作に従う。
会員数会員一覧向けの検索条件セッションへ、本会員に相当する条件を保存する。会員一覧の1ページ目で、保存した本会員条件を初期条件として扱う。

各遷移は別ウィンドウや非同期差し替えではなく、通常の管理画面内ページ遷移として扱う。遷移後の一覧における検索結果件数、表示列、ページ送り、検索条件の保持・解除は、それぞれ商品一覧・会員一覧の機能範囲とする。

Cookie

本機能はショップ状況表示のためだけに新たな Cookie を設定しない。ブラウザのセッション Cookie はフレームワークおよび管理画面全体の認証に用いられる。
