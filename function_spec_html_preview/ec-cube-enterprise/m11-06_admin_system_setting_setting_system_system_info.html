m11-06_admin_system_setting_setting_system_system_info（管理画面_設定_システム設定_システム情報）

管理画面の「設定」配下「システム設定」から開く、EC-CUBEのバージョン・サーバ・DB・PHP・ブラウザUser-Agentを一覧表示し、環境変数によりPHPのphpinfo出力をiframe内に埋め込む参照専用機能。

概要

本機能は管理者が運用環境の把握のために現行の実行時情報を閲覧するためのものである。フォームによる保存やマスタ更新は行わない。

本書は実装手順ではなく、誰が・いつ・どの条件で・結果どうなるかを読むためのリバース詳細設計とする。 既存実装のふるまい、参照するデータ、判定境界、副作用を確認し、仕様の確からしさを把握することを目的とする。

本機能のカスタマイズ区分は標準であり、挙動・DB関連ともにリニューアル後（ec-cube-enterprise）の標準実装を正とする。

対象はブラウザ経由の管理画面のシステム情報画面および、同一文脈で読み込まれるPHP情報（phpinfo）の埋め込み表示である。 メンバー管理、権限設定画面でのURL許可マスタ編集、セキュリティ設定の各機能は別途切り離す。

本書では Symfony の route 名、URL パス、Controller 構成は扱わない。

本書で扱うこと

  • システム情報カードに並ぶ各行のラベルと値の組み立て規則
  • データベースサーバー行に表示する文字列の取得方法と接続先プラットフォーム別の接頭辞
  • PHP行に含めるphpversion、拡張一覧、WEBサーバー行の元データ
  • 環境変数ECCUBE_PHPINFO_ENABLEDが偽のときPHP情報カードを出さないこと、真のときiframeで別GETを読み込むこと
  • 店舗オーナー・店舗オペレーター権限で管理画面のパス先頭一致拒否により本画面および同系統のphpinfo応答にアクセスできないこと
  • phpinfo応答が管理画面共通レイアウトを経由せず生のHTMLであること

本書で扱わないこと

以下は本書では仕様確定せず、実装または別機能の設計を正とする。

  • 管理画面ログイン、二段階認証、セッション確立の手順
  • 権限マスタ画面で拒否URLを変更した場合の運用ルールと監査
  • Doctrine接続失敗時のHTTPステータス、例外型、エラーページの文言
  • phpinfoに表示される各PHPディレクティブの値そのものの意味解釈
  • 環境変数ECCUBE_PHPINFO_ENABLEDを運用で true にするかの判断基準

リニューアル移行時の扱い

  • 本機能のカスタマイズ区分は標準であり、リニューアル後（ec-cube-enterprise）の標準実装を挙動・DBともに正とする。
  • システム情報の各行は実行時情報の表示であり、マスタ列への永続化はない。本機能が永続化として参照するのは認可判定に用いる dtb_authority_role（authority_id・deny_url）であり、ec-cube-enterprise の標準スキーマに従う。
  • PHP情報カードの表示可否は設定パラメータ eccube_phpinfo_enabled（環境変数 ECCUBE_PHPINFO_ENABLED）で決まり、ec-cube-enterprise の標準どおり既定は偽とする。
  • 現行（pf-eccube3／EC-CUBE3系）の相当画面との差がある場合は、移行時に ec-cube-enterprise の標準実装へ揃える。現行との具体差は ec-cube-enterprise 実装を正として移行設計で確認する。

処理フロー

システム情報画面の表示

  1. 利用者がシステム情報の画面表示を要求する。
  2. 認証・認可により許可された場合、コントローラは情報行の配列を組み立てる。先頭から順に、EC-CUBEバージョン定数、php_uname の結果、データベース接続経由のバージョン文字列、SERVER_SOFTWARE サーバ変数、PHPバージョン文字列にカンマ区切りで拡張名一覧を括弧付きで連結した値、User-Agentヘッダ値を並べる。各見出しは翻訳キー由来のラベルとする。
  3. テンプレートへ情報配列と、環境由来のPHP情報有効フラグを渡し、HTMLを応答する。要求クエリの有無やキーは上記の組み立てに使われない。

PHP情報（iframe内）

  1. eccube_phpinfo_enabled が偽の場合、PHP情報カード自体を出力しない。真の場合のみiframeのsrcにphpinfo用の別GETを設定する。
  2. そのGETが許可された場合、標準のphpinfo出力をバッファに取り、そのHTMLをそのまま応答ボディとする。管理画面の共通フレームTwigは通さない。

権限拒否時

  1. ログイン中メンバーの権限に紐付く各行の拒否URLが、現在の要求パス（パス情報のみ、クエリは含めない）と、設定された管理ルート接頭辞付きで先頭一致するかを検査する。
  2. 一致する拒否が一つでもあればアクセス拒否となり、画面本文の描画に至る前に403応答となる。システム情報の本体と、より長いパスを持つphpinfo側のGETは同一の拒否パターン先頭により両方拒否され得る。

集計・判定・計算

本機能は台帳件数の集計や業務判定を行わない。画面に出すのは実行時に取得した文字列の表示のみである。
