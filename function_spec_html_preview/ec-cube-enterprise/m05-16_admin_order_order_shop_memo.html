m05-16_admin_order_order_shop_memo（管理画面_受注編集_ショップ用メモ登録）

受注編集（詳細）画面の右カラムに置かれた「ショップ用メモ欄」へ、ショップ運営者が確認するためのメモを入力し、受注情報の保存に同梱して登録する機能。

処理フロー

受注編集画面を開いたとき（GET、メモ欄の初期表示）

  1. 管理画面の認証・権限・IP制限の各ルールを通過する。
  2. 既存受注の編集では識別子で受注を取得し、フォームを生成する。ショップ用メモ欄には受注の現行メモ（受注テーブルのショップ用メモ）が初期値として載る。新規受注の登録ではメモ欄は空で表示される。
  3. 受注編集テンプレートを描画し、右カラムにショップ用メモ欄カードを表示する。

ショップ用メモを入力して「登録」を押したとき（POST、メモ欄の保存）

  1. 受注編集フォームをリクエストで処理する。ショップ用メモ欄の入力値はフォーム項目 note として受注に束ねられる。
  2. フォーム検証を行う。ショップ用メモ欄については最大長（3000文字）の制約を満たすかを判定する。違反時は同一編集画面を再表示し、メモを含む入力値が再表示される。
  3. 検証成功時、受注編集の保存処理（購入フローの prepare・commit を含む同一DBトランザクション）の中で受注を永続化する。ショップ用メモは受注の他項目とともに同じ flush で 受注テーブルのショップ用メモ に保存される。メモ単独の保存処理・専用 flush は持たない。
  4. 保存成功後、同一受注の編集画面へリダイレクトする。

入出力

種類内容
入力受注編集（詳細）画面のショップ用メモ欄への自由文入力。送信は受注編集フォーム全体のPOSTに含まれる。
成功時出力検証成功時、メモを含む受注が永続化され、同一受注の編集画面へリダイレクトする。
失敗時出力検証失敗時は同一編集画面を再表示し、入力したメモを再表示する。
副作用受注テーブルのショップ用メモ の更新（受注他項目とともに）。メモ単独の追加ログ・キュー・キャッシュ更新は持たない。

業務ロジック

業務ルール・計算

項目内容
メモの保存契機受注編集の「登録」押下時に、受注情報の保存に同梱して保存する。メモだけを単独で保存する経路は持たない。
メモの保存単位受注1件につきメモ1件。受注テーブルのショップ用メモ の1列に自由文を保持する。
未入力時任意項目のため空のまま保存できる。空入力時は当該列が空（NULL許容列）として保持される。
フロント表示ショップ運営者の確認用であり、購入者側のフロント画面には表示しない。
計算処理メモに対する金額計算・丸め・集計は行わない。

入力項目

項目名必須／任意最大長初期値保存先・扱い
ショップ用メモ欄任意フォーム上限3000文字（Length制約 eccube_ltext_len、eccube.yaml 確認値3000）。保存先列は最大4000文字既存受注はDB現行値、新規受注は空受注テーブルのショップ用メモ（フォームキー note）。複数行入力のテキストエリア。受注編集の保存処理に同梱して永続化する。未入力は許容する。

最大長はフォームの Length制約が eccube_ltext_len（app/config/eccube/packages/eccube.yaml の確認値3000）であり、保存先列 受注テーブルのショップ用メモ は文字列型で桁4000である。運用環境で eccube_ltext_len が上書きされている場合はその環境の値が正とする。出荷用メモ欄（「出荷用メモ欄」、フォームキーは出荷側の note）は本項目とは別であり、本書では扱わない。

エッジケース

ケース扱い
メモ未入力で登録任意項目のため空のまま保存する。
メモが3000文字を超えるフォームの最大長検証でエラーとなり保存しない。同一編集画面を再表示する。
改行を含むメモ複数行入力のテキストエリアのため改行を含めて保存する。
受注編集の他項目で検証失敗受注全体が保存されないため、メモも保存されない。入力したメモは再表示される。

データ整合性

観点内容
編集画面と保存値編集画面の初期表示は永続化済みの 受注テーブルのショップ用メモ を読む。保存成功後の再表示も同一列を読むため一致する。
受注全体との整合メモは受注の他項目と同一トランザクション・同一 flush で保存されるため、登録成功時はメモと受注他項目が一括で確定する。途中で検証・購入フローのエラーが起きた場合は受注全体が保存されず、メモも確定しない。
他画面との整合メモを参照する他画面（受注一覧・CSV等）の表示・抽出ルールは各機能の設計を正とする。本書は編集画面での入力・保存のみを扱う。
同時編集複数管理者が同一受注を同時編集した場合の結果は、受注編集の保存処理（最後にflushされた内容）に従う。メモ専用の排他制御は持たない。

権限・認可

利用者状態ショップ用メモ欄の表示・保存
未ログイン（一般利用者）受注編集画面に到達できないため利用不可。管理画面の共通認証に従いログイン等へ誘導される。
ログイン済み管理者（受注編集の権限あり）メモ欄を表示・入力・保存できる。
ログイン済みだが権限マスタで受注編集パスが拒否、またはIP制限で拒否受注編集画面に到達できないためメモ欄も利用できない。

メモ欄単独の権限制御は持たず、受注編集（詳細）画面の認可に従う。

エラー処理

エラー内容処理
