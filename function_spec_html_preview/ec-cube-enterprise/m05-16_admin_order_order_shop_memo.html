m05-16_admin_order_order_shop_memo（管理画面_受注編集_ショップ用メモ登録）

受注編集（詳細）画面の右カラムに置かれた「ショップ用メモ欄」へ、ショップ運営者が確認するためのメモを入力し、受注情報の保存に同梱して登録する機能。

概要

管理画面の受注編集（詳細）画面に配置されたショップ用メモ欄は、ショップ運営者が当該受注について社内で確認するためのメモを自由文で入力し、保存できるようにする機能である。入力した内容はフロント画面（購入者側）には表示しない。

本書は実装手順ではなく、誰が・いつ・どの条件で・結果どうなるかを読むためのリバース詳細設計とする。既存実装のふるまい、保存先、入力制約、保存経路、副作用を確認し、仕様の確からしさを把握することを目的とする。

対象はブラウザ経由の管理画面の受注編集（詳細）画面のうち、ショップ用メモ欄（ロケールキー admin.common.shop_memo）への入力と保存に限定する。メモの保存は受注編集の保存処理（M05-11受注編集）に同梱されるため、本書はメモ欄の挙動・保存先・制約のみを切り出して扱い、受注編集全体の処理は受注編集の設計を正とする。

管理画面プレフィックスは環境変数 ECCUBE_ADMIN_ROUTE を eccube.yaml の eccube_admin_route が受け取って決まる。ルート定義上は %eccube_admin_route% として展開される。本文ではルート名の網羅やコントローラ実装の手順は扱わず、「利用者視点の入口」に HTTP メソッドとサイトルートからのパスパターンを実装確認値として記載する。

本機能のカスタマイズ区分は標準であり、挙動・画面およびDB（永続化先のテーブル・列）はともに ec-cube-enterprise の実装を正とする。

本書で扱うこと

  • 受注編集（詳細）画面の「ショップ用メモ欄」がどのフォーム項目・保存先列に対応するか
  • メモ欄の入力種別、必須／任意、フォーム上の最大長、保存先 dtb_order.note の桁、未入力時の扱い
  • メモ欄の入力内容が受注編集の保存（受注編集の登録 POST）に同梱して永続化される経路
  • メモ欄の内容がフロント画面（購入者側）に表示されないこと
  • メモ欄のツールチップ文言

本書で扱わないこと

以下は本書では仕様確定せず、実装または別機能の設計を正とする。

  • 出荷用メモ欄（ロケールキー admin.order.shop_memo_for_shipped、配送用メモ、M05-17）。これは出荷に紐づく別項目であり、保存先も別である。
  • 受注ステータスの変更（M05-14）、受注金額・明細・お客様情報など受注編集の他項目の入力・検証・保存
  • 受注編集（詳細）画面全体の表示・保存処理フロー、購入フロー処理、在庫・ポイント連携（M05-11受注編集の設計を正とする）
  • 管理画面ログイン、権限マスタ、IP制限、CSRFの詳細仕様
  • メモを表示・検索・出力する他画面（受注一覧、CSV出力など）の表示ルール

リニューアル移行時の扱い

本機能は標準機能のため、現行と移行先（ec-cube-enterprise）で固有のスキーマ差分は生じない。ショップ用メモの保存先である受注（dtb_order.note）は ec-cube-enterprise のスキーマを正とし、同一スキーマとして扱う。dtb_order.note は文字列型・桁4000・NULL許容（ec-cube-enterprise 実装確認値）であり、フォーム側の最大長（eccube_ltext_len 確認値3000文字）の方が小さいため、保存可能な実効上限はフォーム側で決まる。現行実装との差異が判明した場合は ec-cube-enterprise 実装を正とする。

処理フロー

受注編集画面を開いたとき（GET、メモ欄の初期表示）

  1. 管理画面の認証・権限・IP制限の各ルールを通過する。
  2. 既存受注の編集では識別子で受注を取得し、フォームを生成する。ショップ用メモ欄には受注の現行メモ（dtb_order.note）が初期値として載る。新規受注の登録ではメモ欄は空で表示される。
  3. 受注編集テンプレートを描画し、右カラムにショップ用メモ欄カードを表示する。

ショップ用メモを入力して「登録」を押したとき（POST、メモ欄の保存）

  1. 受注編集フォームをリクエストで処理する。ショップ用メモ欄の入力値はフォーム項目 note として受注に束ねられる。
  2. フォーム検証を行う。ショップ用メモ欄については最大長（3000文字）の制約を満たすかを判定する。違反時は同一編集画面を再表示し、メモを含む入力値が再表示される。
  3. 検証成功時、受注編集の保存処理（購入フローの prepare・commit を含む同一DBトランザクション）の中で受注を永続化する。ショップ用メモは受注の他項目とともに同じ flush で dtb_order.note に保存される。メモ単独の保存処理・専用 flush は持たない。
  4. 保存成功後、同一受注の編集画面へリダイレクトする。

入力項目

項目名必須／任意最大長初期値保存先・扱い
ショップ用メモ欄任意フォーム上限3000文字（Length制約 eccube_ltext_len、eccube.yaml 確認値3000）。保存先列は最大4000文字既存受注はDB現行値、新規受注は空dtb_order.note（フォームキー note）。複数行入力のテキストエリア。受注編集の保存処理に同梱して永続化する。未入力は許容する。

最大長はフォームの Length制約が eccube_ltext_len（app/config/eccube/packages/eccube.yaml の確認値3000）であり、保存先列 dtb_order.note は文字列型で桁4000である。運用環境で eccube_ltext_len が上書きされている場合はその環境の値が正とする。出荷用メモ欄（admin.order.shop_memo_for_shipped、フォームキーは出荷側の note）は本項目とは別であり、本書では扱わない。

観点内容
編集画面と保存値編集画面の初期表示は永続化済みの dtb_order.note を読む。保存成功後の再表示も同一列を読むため一致する。
