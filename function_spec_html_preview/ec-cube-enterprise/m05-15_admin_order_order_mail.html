受注管理 — 受注詳細メール通知

受注詳細画面から1件の受注に対し、メールテンプレートを選んで件名・本文を編集し、確認画面を経て注文者へメールを送信する機能。送信内容は送信履歴として記録する。

処理フロー

メール通知画面を開く（GET）

  1. 管理画面の認証・権限・IP制限の各ルールを通過する。
  2. URLの受注識別子で受注1件を取得する。取得できない場合はアクセスできない（受注は必須パラメータとして解決される）。
  3. 当該受注に紐づく送信履歴を取得する。
  4. メール入力フォームを組み立て、初期化イベントをディスパッチする（プラグイン等がフォームへ差し込める）。
  5. テンプレート未選択・件名空・本文空の編集画面を描画する。

テンプレートを選択し件名・本文を読み込む（POST、モード change）

  1. フォームをリクエストで処理する。
  2. テンプレート選択フィールドが妥当な場合のみ進む。
  3. 選択テンプレートのファイル名を本文テンプレートとする。ファイル名が無い場合は既定の受注メールテンプレートを用いる。
  4. 当該受注を渡して本文テンプレートを描画し、本文の初期値を作る。描画元が見つからない場合はエラーメッセージを積み、本文は空のままとする（後述「表示メッセージ」）。
  5. フォームを再生成し、テンプレート変更イベントをディスパッチする。
  6. 件名フィールドに選択テンプレートの件名をセットし、本文フィールドに描画結果をセットして編集画面を再描画する。

送信内容を確認する（POST、モード confirm）

  1. フォームをリクエストで処理する。
  2. 送信済みかつ検証成功であれば、件名・本文を編集不可（freeze）にしたフォームを再構築する。
  3. 件名・本文を確認用に表示する確認画面を描画する。本文は改行を反映して表示する。
  4. 検証失敗時は確認画面へ進まず、編集画面に留まり項目エラーを表示する。

送信する（POST、モード complete）

  1. フォームをリクエストで処理する。
  2. 送信済みかつ検証成功であれば、フォームデータと本文を取り出す。
  3. 件名・本文を用いて注文者宛にメールを送信する（宛先・差出人等は後述「業務ルール・計算」を参照）。
  4. 送信したメールの件名・本文・送信日時・宛先会員・受注を送信履歴として保存する。
  5. 送信完了イベントをディスパッチする。
  6. 成功メッセージを積み、受注編集画面へリダイレクトする。

戻る・その他のモード（POST、モード back ほか）

  1. テンプレート変更・確認・送信のいずれにも該当しないモードでは、分岐処理を行わない。
  2. 現在のフォーム状態で編集画面を再描画する。
