m09-02_admin_content_content_file（管理画面_コンテンツ管理_ファイル管理）

管理画面のコンテンツ管理にあるファイル管理。公開領域のuser_data配下に対し、画像ファイル等のアップロード、フォルダ作成、ファイル・フォルダの削除、ファイルの表示・ダウンロードを行う。

概要

ファイル管理は、管理者がuser_data配下のディレクトリツリーをたどりながら、画像ファイル等のアップロード、フォルダの新規作成、ファイル・フォルダの削除、ファイルの表示とダウンロードを1画面で行うための機能である。アップロードしたファイルは公開URLとして参照でき、各ファイルの公開パスをコピーする補助も持つ。

本書は実装手順ではなく、誰が・いつ・どの条件で・結果どうなるかを読むためのリバース詳細設計とする。既存実装のふるまい、参照するディレクトリ、許可・拒否の判定境界、ディレクトリトラバーサル対策、ファイル名・拡張子の検証、副作用を確認し、仕様の確からしさを把握することを目的とする。

本機能のカスタマイズ区分は標準であり、挙動はec-cube-enterpriseのファイル管理を正とする。本機能はファイル・フォルダをデータベースへ保存しないため、DB関連の永続化記述は持たないが、永続化に関わる記述が生じる場合はec-cube-enterpriseを正典とする。

対象はブラウザ経由の管理画面のファイル管理画面である。操作対象のルート領域はアプリケーションのhtml/user_data配下に固定する。

管理画面プレフィックスは環境変数ECCUBE_ADMIN_ROUTE由来のeccube_admin_routeで決まり、app/config/eccube/packages/eccube.yamlのeccube_admin_routeに展開される。本書では入口節で%eccube_admin_route%プレースホルダとして示す。コントローラのメソッド単位の解剖は本文の主題としない。

本書で扱うこと

  • ファイル管理画面の表示時に、どのディレクトリを起点とし、どの範囲のファイル・フォルダ一覧とディレクトリツリーを表示するか
  • ファイルアップロード時の保存先、許可する拡張子、拒否するファイル名・拡張子、同名フォルダ存在時の扱い、複数ファイルの成功件数表示
  • フォルダ作成時の名前の検証（使用可能文字、先頭ピリオド禁止、既存名重複）
  • ファイル・フォルダ削除時のトークン検証、空フォルダ以外の削除可否、ストレージアダプタへの削除連携
  • ファイルの表示（別タブ）とダウンロードの境界、ダウンロード時のファイル名エンコード
  • user_data配下に閉じ込めるためのディレクトリトラバーサル対策（..を含むパスと領域外パスの拒否）
  • アップロード機能の無効化（環境変数によるファイル管理メニュー非表示とアクセス拒否）
  • 画面に表示するフォルダツリー・パンくず・パスコピーなどのフロント挙動

本書で扱わないこと

以下は本書では仕様確定せず、実装または別機能の設計を正とする。

  • Symfonyのroute名・Controllerクラス名・メソッド名の網羅
  • 管理画面へのログイン、認証、二段階認証、権限ロール設定の詳細
  • ストレージアダプタ（S3等）の接続・認証・同期の内部仕様。本書ではアップロード成功時と削除時にアダプタへ連携する事実のみ扱う
  • ブロック管理・ページ管理・CSS管理・JS管理・テンプレート管理など、同じアップロード制限対象に含まれる他機能の詳細
  • 画像のサムネイル生成・リサイズ・最適化
  • ファイルサイズの上限（PHPやWebサーバ側のアップロード上限）の具体値

リニューアル移行時の扱い

本機能はカスタマイズ区分が標準であり、挙動はec-cube-enterpriseのファイル管理を正とする。本機能はファイル・フォルダをデータベースへ保存せず、操作対象はファイルシステム（user_data配下）に限られるため、テーブル名・列名の移行差分は持たない。アップロード制限の環境変数（ECCUBE_RESTRICT_FILE_UPLOAD）、許可拡張子（eccube_file_uploadable_extensions）、ストレージアダプタ連携の挙動はec-cube-enterprise実装を正とする。

処理フロー

ファイル管理画面の表示

  1. 管理者がファイル管理画面を開く。
  2. アップロード制限の案内を一度だけ情報メッセージとして表示する。
  3. カレントディレクトリを決める。tree_select_fileで指定された相対パスがuser_data配下であればそのディレクトリ、そうでなければuser_data領域のトップを起点とする。
  4. ディレクトリツリー（user_data配下のフォルダ階層）と、カレントディレクトリ直下のファイル・フォルダ一覧、パンくず用データを組み立てる。
  5. 一覧はカレントディレクトリ直下（深さ0）のフォルダとファイルを名前順に並べる。各フォルダには空かどうかの判定を付与する。各ファイルにはサイズ・更新日時・拡張子を付与する。
  6. 画面を表示する。

フォルダ移動

  1. 利用者がツリーのフォルダ名、パンくず、または一覧のフォルダ名を押下する。
  2. 移動先パスをtree_select_fileに設定してmode空でPOST送信する。
  3. サーバは移動先がuser_data配下であることを確認し、当該ディレクトリをカレントディレクトリとして一覧・ツリーを再表示する。配下でなければトップを起点に戻す。

ファイルアップロード

  1. 利用者がファイルを選択し、アップロードボタンを押下する。mode=uploadでPOST送信する。
  2. ファイル未選択のときは「選択されていません」を表示して終了する。
  3. 保存先はカレントディレクトリ（now_dir）とする。now_dirがuser_data配下でなければアップロード先不正としてエラーを表示し終了する。
  4. 選択ファイルごとに次を検証する。順序は、同名フォルダ存在チェック、ファイル名の使用可能文字チェック、先頭ピリオド禁止チェック、拡張子の許可チェックとする。いずれかに外れたファイルはエラー文言を記録し、そのファイルをスキップする。同一文言は重複して表示しない。
  5. 検証を通ったファイルをカレントディレクトリへ保存し、ストレージアダプタへもアップロードする。保存に失敗したファイルはアップロード失敗の文言を記録する。
  6. 成功件数が1件以上のとき、「○件のファイルをアップロードしました。(成功/選択件数)」を成功メッセージとして表示する。

フォルダ作成

  1. 利用者がフォルダ名を入力し、作成ボタンを押下する。mode=createでPOST送信する。
  2. フォルダ名を検証する。空のとき、使用できない文字を含むとき、ピリオドで始まるときは、それぞれのエラー文言を表示して終了する。
  3. 作成先はカレントディレクトリ（now_dir）とし、user_data配下でなければトップを起点とする。
  4. 同名のファイル・フォルダが既に存在するときは「既に使用されています」を表示して終了する。
  5. 重複がなければフォルダを作成し、「作成しました」を表示する。作成に失敗したときはアップロード失敗の文言を表示する。

ファイル・フォルダ削除

  1. 利用者が一覧の削除ボタンを押下し、モーダルの削除を確定する。削除URLへトークン付きでDELETE相当のリクエストを送る。
  2. なりすまし対策トークンを検証する。
  3. 対象パスが空、未指定、または/のときは、削除せずファイル管理画面へ戻る。
  4. 対象がuser_data配下であることを確認する。配下のとき、ファイルシステム上に存在すればストレージアダプタからの削除とファイルシステムからの削除を行い、「削除しました」を表示する。あわせて選択パスに対応するアダプタ側エントリも削除する。
  5. 削除実行時のカレントディレクトリ（対象の親ディレクトリ）を表示するよう、ファイル管理画面へ戻る。

ファイル表示

  1. 利用者がファイル行の表示ボタンを押下する。別タブで表示URLを開く。
  2. 対象ファイルがuser_data配下であればファイル内容をそのまま返す。配下でなければ見つからない（HTTP404）として扱う。

ファイルダウンロード

  1. 利用者がファイル行のダウンロードボタンを押下する。
  2. 対象がuser_data配下かつディレクトリでないファイルのとき、添付ファイルとしてダウンロードさせる。ファイル名に通常文字以外しか含まれない場合は記号類を除去した結果が空になるため、ファイル名指定なしの添付として返す。それ以外はUTF-8でエンコードしたファイル名を付けて返す。
  3. 対象がフォルダ、または領域外のときは見つからない（HTTP404）として扱う。

項目内容
操作領域の固定全操作の対象ルートをuser_data領域（html/user_data）に固定する。カレントディレクトリ・移動先・アップロード先・削除対象・表示/ダウンロード対象は、いずれもこの配下であることを確認してから処理する。
ディレクトリトラバーサル対策対象パスに..を含む場合は領域外とみなして拒否する。実パスがuser_data領域の実パスで始まらない場合も領域外として拒否する。
フォルダ名の使用可能文字英数字、アンダースコア、ピリオド、ハイフンのみを許可する。これら以外を含むと使用できない文字として拒否する。
フォルダ名の先頭ピリオド禁止ピリオドで始まる名前は拒否する。
フォルダ名の必須フォルダ名は空にできない。
アップロードファイル名の使用可能文字英数字、半角スペース、アンダースコア、ハイフン、ピリオド、丸括弧のみを許可する。これら以外を含むと拒否する。
アップロードファイルの先頭ピリオド禁止ピリオドで始まるファイルは拒否する。
許可拡張子小文字化した拡張子が許可一覧に含まれるファイルのみアップロードできる。許可一覧はeccube_file_uploadable_extensionsで、jpg, jpeg, png, gif, webp, svg, ico, html, htm, js, css, txt, pdfとする。一覧は設定で上書きできる。
同名フォルダとの衝突アップロードファイル名と同名のフォルダがカレントディレクトリに存在するとき、そのファイルはアップロードしない。
削除対象の制限空・未指定・/の選択は削除しない。フォルダは空でない場合、画面上の削除ボタンを無効化して削除させない。
成功件数表示アップロードは選択ファイルごとに検証し、成功件数と選択件数を「成功/選択」の形で表示する。
計算金額計算・税計算・丸めは行わない。ファイルサイズは人が読める単位へ整形して表示する。

データ整合性

観点内容
参照時点一覧・ツリーは画面表示時にファイルシステムを走査した結果である。表示後に他操作でファイルが増減しても、表示中の一覧は自動更新しない。
ファイルシステムとアダプタの整合性アップロード成功時はファイルシステムとストレージアダプタの双方へ書き込む。削除時は双方から削除する。アダプタ側に対象が存在しない削除では、その旨をログに残しファイルシステムの削除は続行する。両者の完全同期は本書では保証しない。
同名処理フォルダ作成は同名重複を拒否する。ファイルアップロードは同名フォルダのみ拒否し、同名ファイルは上書きとなる。
公開URLとの整合性パスコピーや表示・ダウンロードで参照する公開パスは、user_data配下の相対パス（jail表現）に基づく。実体ファイルの有無は参照時点のファイルシステムに従う。
