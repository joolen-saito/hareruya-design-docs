1. スマレジ連携処理

機能の目的と役割

スマレジWebhookを受け、取引・在庫に関する連携処理を非同期で実行する。

本機能のカスタマイズ区分は新規実装であり、仕様・挙動は基本設計仕様書（Excel）を正とし、DB関連の記述はec-cube-enterprise実装（スマレジWebhook受信テーブル dtb_smaregi_webhook_request）を正とする。

リニューアル移行時の扱い

本機能は新規実装のため対応する現行実装は無い。永続化先はec-cube-enterprise実装のスマレジWebhook受信テーブル dtb_smaregi_webhook_request を正とする。当テーブルの列は id、contract_id（契約ID）、smaregi_event_id（スマレジイベントID）、event（イベント）、action（アクション）、request_headers（リクエストヘッダー）、request_body（リクエストボディ）、received_at（受信日時）、started_at（開始日時）、completed_at（完了日時）、status（ステータス）、create_date、update_date を確認値とする。基本設計が描くAPI個別連携・Patch一括連携・在庫相対値更新等のうち、ec-cube-enterprise実装で未確認の処理範囲は実装確認後に確定する。

  • Excel設計書に未記載のURLエンドポイント、DBカラム、実処理順序は ../ec-cube-enterprise の実装を正とする。
  • 権限、ログイン状態、管理画面プレフィックスなどの共通判定は共通設計および実装側のセキュリティ設定に従う。

プロセスフロー

  1. 利用者または外部システムが対象機能を開始する。
  2. 入力値、検索条件、アップロードファイル、またはリクエスト本文を受け付ける。
  3. Excel設計書に定義された対象データを取得し、実装側の検証・権限・状態条件を適用する。
  4. 登録・更新・出力・連携のいずれかの主処理を実行する。
  5. 成功時は結果画面、CSV/PDF/APIレスポンス、またはバッチ結果を返す。失敗時はエラー内容を返し、更新が必要な処理では不整合が残らないように扱う。

例外処理

  • **入力不備**: 必須項目、CSVヘッダ、CSV行、APIリクエスト本文、検索条件が不正な場合はエラーとして処理し、登録・更新対象を確定しない。
  • **対象なし**: 検索条件や対象IDに該当するデータがない場合は、空の一覧、空CSV、またはエラーレスポンスとして扱う。扱いの細部は対象画面/API/バッチの実装に従う。
  • **状態不整合**: 既に処理済み、キャンセル済み、承認不可、在庫不足など状態条件に合わない場合は処理対象外またはエラーとする。
  • **外部連携失敗**: スマレジ等の外部連携で失敗した場合は、実装側の再連携・エラーログ・エラーメール・ステータス更新仕様を正とする。
