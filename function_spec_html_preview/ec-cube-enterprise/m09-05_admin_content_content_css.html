コンテンツ管理 — CSS管理

管理画面のコンテンツ管理配下で、店舗フロント向けのカスタマイズ用CSSを1ファイル単位で編集・保存し、保存後にファイルストレージへ反映する機能である。

処理フロー

CSS管理画面を開く（GET）

  1. 管理画面の認証・権限の各ルールを通過する。ファイルアップロード制限が有効で当URLが制限対象なら、この時点でアクセス拒否（HTTP403）となり以降へ進まない。
  2. ファイルアップロード制限に関する案内メッセージを、情報フラッシュとして一度だけ積む。
  3. CSS用のフォーム（コード入力1項目、任意）を組み立てる。
  4. customize.cssの絶対パスを組み立て、ファイルが存在し、かつ書き込み可能であれば、その内容をフォームのコード値へセットする。存在しない、または書き込み不可の場合はセットしない。
  5. テンプレートを描画する。Aceエディタにフォームのコード値を初期表示する。

「登録」押下（POST、保存成功）

  1. フォームをリクエストで処理する。送信直前にエディタ値が隠しtextareaへ同期されているため、送信値はエディタ内容となる。
  2. フォームが送信済みかつ検証成功であれば保存処理へ進む。
  3. customize.cssへフォームのコード値を全文書き込みする（ファイルが無ければ作成、あれば上書き）。
  4. 管理画面向け成功メッセージ（「保存しました」）を積む。
  5. 既定のファイルストレージアダプタを取得し、書き込んだローカルファイルを配信用パス/html/user_data/assets/css/にcustomize.cssとしてアップロードする。
  6. 同一のCSS管理画面へリダイレクトする。

「登録」押下（POST、書き込み失敗）

  1. フォームをリクエストで処理し、検証成功で保存処理へ進む。
  2. ファイル書き込みで入出力例外が発生した場合、保存に失敗したと判断する。
  3. 管理画面向けエラーメッセージ（「保存に失敗しました」）を画面に表示する。
  4. 失敗の詳細（対象パスと例外）をアプリケーションログへ記録する。
  5. リダイレクトせず、同一画面のフォームビューを再描画する。

「登録」押下（POST、検証不成立）

  1. フォームが送信済みでも検証が成立しない場合は保存処理へ進まない。
  2. 同一画面のフォームビューを再描画する。コード項目は任意のため、空でも検証自体は妨げない実装である。

入出力

種類内容
入力ブラウザからのGET（画面表示）と、コード値を含むPOST（登録）。
成功時出力保存成功時は成功フラッシュを積み、同一画面へリダイレクトする。
失敗時出力書き込み失敗時はエラーフラッシュを表示し同一画面に留まる。アップロード制限時はアクセス拒否（HTTP403）。
副作用customize.cssの書き込み、ファイルストレージへのアップロード、フラッシュメッセージ、失敗時のアプリケーションログ。

業務ロジック

業務ルール・計算

本機能では金額計算・集計・丸めなどの業務計算を行わない。保存対象は単一のCSSファイルであり、入力されたコードを解釈・整形せず全文をそのまま保存する。

項目内容
保存対象単一ファイルcustomize.cssのみ。複数ファイルや差分保存は行わない。
保存方式フォームのコード値でファイル全文を上書きする。既存内容とのマージは行わない。
初期表示の条件対象ファイルが存在し、かつ書き込み可能なときに限り、現行内容をエディタへ初期表示する。書き込み不可・不存在のときは空表示。
ストレージ反映ローカルへ書き込み後、既定のファイルストレージへ同名でアップロードする。アップロードは書き込み成功後にのみ行う。
構文検証サーバー側でCSS構文の妥当性検証は行わない。クライアント側エディタのエラー注釈は「登録」ボタンの活性制御にのみ用いる。

入力項目

項目名必須／任意最大長初期値保存先・扱い
コード任意Symfony Length制約なし（複数行テキスト入力。サーバー側の文字数上限を課さない）対象ファイルが存在し書き込み可能なら現行内容、そうでなければ空ファイルhtml/user_data/assets/css/customize.css（フォーム項目キー css、TextareaType、requiredは偽）。検証成功時に全文上書き保存し、続けて既定ファイルストレージへ/html/user_data/assets/css/customize.cssとして同名アップロードする。

コードは画面ではAceエディタとして表示されるが、送信値は背面の複数行テキスト入力（textarea）が保持する。サーバー側ではフォーム制約として文字数上限を課しておらず、CSS内容の構文検証も行わない。フォーム項目自体は任意であるが、画面上は必須バッジを表示する。

エッジケース

ケース扱い
対象ファイルが存在しない初期表示はせず空のエディタとなる。「登録」時は新規作成として書き込みする。
対象ファイルが存在するが書き込み不可初期表示で現行内容を読み込まない（空表示）。「登録」時の書き込みに失敗すればエラーメッセージとログ記録となる。
コードを空のまま登録項目は任意のため検証は妨げない。空内容でファイルを上書きし、空のCSSが保存・反映される。
ファイル書き込みで入出力例外保存失敗メッセージを表示し、ログへ対象パスと例外を記録し、同一画面へ留まる。ストレージアップロードは行わない。
ファイルアップロード制限が有効当URLは到達前にアクセス拒否（HTTP403）となる。GET・POSTのいずれも遮断される。

データ整合性

観点内容
画面とローカルファイル保存成功後にリダイレクトで再表示するため、エディタには直前に保存したローカルファイル内容が再度初期表示される。
ローカルとストレージローカルファイルへの書き込みが成功した後にストレージへアップロードする。書き込みは成功したがアップロードで例外が出た場合の挙動は、フレームワークの例外処理に委ねる。
店舗フロントとの整合店舗フロントが参照するのはストレージ配信またはローカルの同パスファイルである。配信キャッシュ・CDNの反映タイミングは配信側の設定に依存し、本機能は保存・アップロードの時点までを担う。
同時編集複数の管理者が同時に保存した場合、最後に書き込まれた内容が残る。版管理・楽観ロックは行わない。

権限・認可

利用者状態CSS管理画面
未ログイン（一般利用者）管理画面の共通認証により拒否される。
ログイン済み管理者（通常）権限ルールを通過すれば閲覧・編集・保存が可能。
ログイン済みだが権限で当該パスが拒否拒否される。
ファイルアップロード制限が有効な状態利用者の権限に関わらず、当URLは到達前にアクセス拒否（HTTP403）となる。
