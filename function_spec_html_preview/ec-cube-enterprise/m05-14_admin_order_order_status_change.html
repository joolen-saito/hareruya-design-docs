受注管理 — 受注対応状況の変更

受注編集（詳細）画面で、受注の対応状況（受注ステータス）を別のステータスへ変更し、変更後の状態と関連する日時を保存する処理。

処理フロー

受注編集（詳細）画面の表示

  1. 管理者が受注編集（詳細）画面を開く。
  2. システムは対象受注を取得し、受注編集フォームを組み立てる。
  3. 既存受注のとき、対応状況プルダウンに、受注ステータス遷移の許可規則で現在のステータスから到達できる遷移先ステータスを選択肢として表示する。到達できないステータスおよび現在のステータス自身は選択肢から除外する。
  4. 「現在のステータス」として現在の対応状況の表示名を表示する。

対応状況変更操作の送信

  1. 利用者が対応状況プルダウンで遷移先ステータスを選び、対応状況変更ボタンを押す。
  2. ブラウザ側で、取消への変更または取消からの変更にあたる場合は確認ダイアログを表示し、取り消されたら送信しない。
  3. 送信種別 status_change で受注編集（詳細）画面のパスへ送信する。
  4. システムは受注ステータス以外の明細サブフォームが妥当であることを前提に、対応状況変更の確定処理に入る。
  5. 変更前ステータスと変更後ステータスのいずれかが取得できない、または両者が同一の場合は、何も変更せず受注編集（詳細）画面へリダイレクトする。
  6. 受注フォーム全体が妥当でない場合は、何も変更せず受注編集（詳細）画面へリダイレクトする。
  7. 変更後ステータスに応じて、出荷日・取消日・入金日・確認日を後述の判定順序でセットする。
  8. 受注のステータスをいったん変更前ステータスへ戻したうえで、トランザクション内で受注ステータス遷移の許可規則に従い変更後ステータスへ遷移を適用する。許可されない遷移のときは遷移適用が失敗し、トランザクションを巻き戻す。
  9. 受注の更新者を操作中の管理者、更新日時を現在日時として保存する。
  10. 出荷完了へ新たに遷移した場合は、付与ポイントを会員残高へ反映し、外部在庫連携サービスへ発生ポイントを連携する。
  11. 受注に外部連携コードがあり、かつ変更後ステータスが取消でない場合は、外部連携サービスへ商品情報を連携する。
  12. 変更後ステータスが取消のときは取消完了のフラッシュ、それ以外のときは保存完了のフラッシュを表示し、受注編集（詳細）画面へリダイレクトする。

受注ステータス変更時の判定順序

変更前ステータスと変更後ステータスが異なり、かつ受注フォームが妥当な場合に、現在日時を一度だけ取得し、次の順で日時をセットする。各日時は条件を満たすときだけ更新する。

順序判定結果
1変更後が発送済み（DELIVERED）かつ変更前が発送済みでない受注の出荷日に現在日時をセットし、受注配下の各配送の出荷日にも現在日時をセットする。
2変更後が取消（CANCEL）かつ変更前が取消でなく、取消日が未設定受注の取消日に現在日時をセットする。
3変更後が入金済み（PAID）かつ変更前が入金済みでなく、入金日が未設定受注の入金日に現在日時をセットする。
4変更後がピック中（PICKING）かつ変更前がピック中でなく、確認日が未設定受注の確認日に現在日時をセットする。
5上記の日時セット後受注のステータスを変更前ステータスへ戻す。
6トランザクション開始後受注ステータス遷移の許可規則に従い変更後ステータスへ遷移を適用する。許可されない遷移のときは遷移適用が失敗する。
7遷移適用後受注の更新者を操作中の管理者、更新日時を現在日時としてセットして永続化する。
8変更後が発送済みかつ変更前が発送済みでない場合のみ付与ポイントを会員残高へ反映し、外部在庫連携サービスへ発生ポイントを連携する。
9受注に外部連携コードがあり、変更後ステータスが取消でない場合のみ外部連携サービスへ商品情報を連携する。

順序 1 から 4 の日時セットは、受注ステータス遷移の許可規則による遷移可否の判定より前に行う。遷移が許可されずトランザクションを巻き戻した場合、これらの日時セットは永続化されない。入金日は受注ステータス遷移側でも入金遷移時にセットされるが、本操作では遷移適用の前に未設定時の入金日を補完する。

入力項目

項目名必須／任意最大長初期値保存先・扱い
対応状況必須単一選択（受注ステータスマスタの 1 行）現在のステータス受注テーブルの対応状況ID。受注フォームのキー order[OrderStatus]。受注フォーム側ではマッピング対象外で扱い、確定処理が変更前後のステータスを比較してから受注へ反映する。選択肢は受注ステータス遷移の許可規則で絞り込む。未選択は不可（空送信は検証エラー）。

対応状況は受注ステータスマスタ（対応状況マスタ）の行から選ぶ単一選択であり、自由入力ではない。選択肢の絞り込みと遷移可否の最終判定は受注ステータス遷移の許可規則で行う。
