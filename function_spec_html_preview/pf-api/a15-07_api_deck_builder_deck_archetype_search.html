API デッキビルダー — アーキタイプ検索

概要

デッキビルダーアプリが、指定したフォーマットに属するアーキタイプ（デッキの型）の一覧を取得するためのAPIである。deck-api（デッキビルダー用のAPIアプリケーション）が提供するJSON APIで、URLのパスで指定したフォーマットIDに紐づくアーキタイプの識別子と日英の名称を返す。

本書は実装手順ではなく、誰が・いつ・どの条件で・結果どうなるかを読むためのリバース詳細設計とする。確認値はdeck-apiのアーキタイプ取得処理、ルート定義（config/routes.yaml）、フォーマットマスタおよびアーキタイプのリポジトリを正とする。本機能のカスタマイズ区分は現行踏襲であり、挙動はデッキビルダーAPI（deck-api）の実装を参照し、DB関連の記述はec-cube-enterpriseを正とする。

対象はJSON APIエンドポイントであり、ブラウザ向けの画面を持たない。本文ではフレームワークのコントローラ型名やメソッド名を主説明としない。「利用者視点の入口」にHTTPメソッドとパスパターンを書く。

本書で扱うこと

  • フォーマットIDからアーキタイプ一覧を取得するふるまい
  • 指定フォーマットが存在しない場合のふるまい
  • 応答に含めるアーキタイプの項目

本書で扱わないこと

以下は本書では仕様確定せず、実装または別APIの設計を正とする。

  • アーキタイプIDから単一アーキタイプを取得する処理（本APIの入口に含めない）
  • フォーマットマスタそのものの取得（マスタ検索の設計を正とする）
  • アーキタイプの登録・更新（管理側の設計を正とする）

リニューアル移行時の扱い

DB関連の記述はec-cube-enterpriseを正とする。挙動の参照元であるデッキビルダーAPI（deck-api）は提供リポジトリに含まれないため、現行deck-apiと移行先ec-cube-enterpriseでスキーマが異なる場合はec-cube-enterpriseを正とし、確認できない差異はec-cube-enterprise実装で要確認とする。ec-cube-enterpriseでは、アーキタイプ（dtb_archetype）が識別子（archetype_id／id）・日本語名（name_jp）・英語名（name_en）・所属フォーマット（format_id）を持ち、フォーマット（mtb_format）でフォーマットの実在を判定する。

処理フロー

アーキタイプ一覧を取得する（GET /archetypes/{formatId}）

  1. パスのフォーマットIDを受領し、フォーマットマスタから該当フォーマットを取得する。
  2. フォーマットが存在しない場合は、該当なし（HTTP 404）として{code, message}形式のJSONを返す。
  3. 該当フォーマットに紐づくアーキタイプを取得し、識別子・日本語名・英語名を選択する。
  4. 取得結果をcodeとarchetypesのラッパに包んで返す（HTTP 200）。

集計条件

本APIは指定フォーマットに属するアーキタイプの全件取得であり、件数集計・ページングを行わない。対象範囲は次のとおり。

指標集計の要点

抽出項目アーキタイプ識別子・日本語名・英語名のみを選択する。
並び順取得クエリに明示の並び替えは無く、既定順で返す。
ページング行わない。全件を一括で返す。

副作用

無し（参照のみ）。取得クエリにはフォーマット単位の結果キャッシュ（既定の保持時間つき）を用いるが、業務データの更新・履歴・通知は行わない。

応答はJSON応答整形を経て返す。プロパティはcamelCase、日時はISO8601、serialize_nullは有効とする。本APIの配列要素キーは取得クエリのエイリアス（snake_case）に従う。

業務ルール・計算

  • 検索・一覧・取得条件はリクエストパラメータ、ログイン状態、公開状態、店舗・支店条件、既存リポジトリの絞り込み順序を正とする。
  • 件数、ページ番号、表示順は既存実装のデフォルトと上限に従い、取得後に業務値を再計算しない。
  • 金額、ポイント、数量、ステータス、日時はDBまたは連携元の永続化済み値を返却し、レスポンス生成時の丸め・補正は行わない。
  • 条件に一致しない、権限がない、または非公開のデータは空結果または既存のエラー形式で返す。
