API ネット買取管理 — ネット買取注文の査定終了処理

業務ロジック

処理できる条件

順序判定結果
1認証トークンが無いとき、署名が不正なとき、または該当する管理者会員がないとき認証拒否（HTTP 401）
2パスの受注IDに一致するネット買取受注がないとき該当なし（HTTP 404）
3入力検証に1件以上失敗したとき入力不正（HTTP 400）とし、エラーメッセージの配列を返す
4上記以外のとき査定終了処理を実行する

認証は要求ヘッダのトークンを検証し、その利用者IDに対応する管理者会員を特定する。署名方式はHS256とする。トークンの原値と署名の秘密値は本書に記載しない。呼び出せるのは買取アプリだけである。認証した管理者会員を受注の更新担当者として記録し、ステータス変更時の履歴にも記録する。

入力検証

対象条件
ステータス選択が必須で、買取受注ステータスマスタに存在すること
明細の配列1件以上あること
明細の商品名必須。最大65535
明細の数量・単価・商品規格ID・買取カテゴリ整数であること

明細の処理

明細は1件ずつ処理する。商品規格IDが0の明細は個別入力商品として扱い、同名の既存があるときは更新し、無いときは新規に作る。それ以外の明細は商品規格から買取代表カードを特定し、同一条件の既存があるときは更新し、無いときは新規に作って既存明細から申込時買取価格を引き継ぐ。買取代表カードの言語・状態・フォイル区分は明細処理で参照する。

各明細の単価×数量を合計額に加算する。

受注に既存登録されているカードのうち、まとめ買取商品は申込時買取価格を削除する。カード詳細IDが未設定の明細はサプライ・パック相当として合計額に加算して保持する。

合計額と受注の更新

合計額は10円単位で切り上げる。受注にはステータス・合計額・買取代表カード・個別入力商品・更新担当者・更新日時を設定する。今回保持しない既存の買取代表カード・個別入力商品と、それに紐づく申込時買取価格は削除する。

更新前後でステータスが変わったときは、受注のステータスと更新日時を再設定し、ステータス履歴を1件登録する。

本処理では金額・税・ポイント・在庫数量の再計算や丸めを、上記の合計額の切り上げを除いて行わない。応答値は独自集計せず、処理結果コードを返す。

エラー時の扱い

事象扱い
認証できないとき認証拒否（HTTP 401）とする
受注が存在しないとき該当なし（HTTP 404）とする
ステータスまたは明細の入力検証に失敗したとき入力不正（HTTP 400）とし、処理結果コードとエラーメッセージの配列を返す
更新処理中に例外が発生したとき更新内容を取り消し、内部エラー（HTTP 500）とし、処理結果コードと例外メッセージの配列を返す

受注の更新から履歴登録までは一括で確定し、途中で失敗したときは全体を取り消す。
