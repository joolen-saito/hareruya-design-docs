API デッキビルダー — ユーザー情報参照

概要

デッキビルダーアプリが、ログイン中の自分のユーザー情報（ニックネーム・プロフィール・デッキユーザーID）を取得するためのAPIである。deck-api（デッキビルダー用のAPIアプリケーション）が提供するJSON APIで、jwt-tokenヘッダのトークンから特定したプレイヤーの公開向け情報を返す。

本書は実装手順ではなく、誰が・いつ・どの条件で・結果どうなるかを読むためのリバース詳細設計とする。確認値はdeck-apiのユーザー情報参照処理、ルート定義（config/routes.yaml）、プレイヤーを扱うエンティティ、共通の認証処理を正とする。

本機能のカスタマイズ区分は現行踏襲であり、挙動はデッキビルダー用APIの現行実装（deck-api）を、DB関連はec-cube-enterpriseの実装を正とする。

対象はJSON APIエンドポイントであり、ブラウザ向けの画面を持たない。本文ではフレームワークのコントローラ型名やメソッド名を主説明としない。「利用者視点の入口」にHTTPメソッドとパスパターンを書く。

本書で扱うこと

  • 認証したプレイヤー自身のニックネーム・プロフィール・デッキユーザーIDの取得
  • 認証、該当なし時の応答

本書で扱わないこと

以下は本書では仕様確定せず、実装または別APIの設計を正とする。

  • デッキユーザーIDを指定した他ユーザー情報の参照（同一エンドポイントのdeck_user_id指定の分岐は他ユーザー情報参照APIの設計を正とする）
  • ユーザー情報の変更（ユーザー情報変更APIの設計を正とする）
  • トークンの発行（デッキビルダー用ログインの設計を正とする）
  • プレイヤーの本名・メールアドレス・ポイント等、本APIの応答に含めない項目

リニューアル移行時の扱い

DB関連の記述はec-cube-enterpriseの実装を正とする。挙動は現行のデッキビルダー用API（deck-api）を正とする。現行と移行先でプレイヤーテーブルの主キー列名が異なる。

観点現行（deck-api）移行先（ec-cube-enterprise）
プレイヤーテーブルdtb_playerdtb_player
プレイヤーの主キー列player_idid
応答に用いる列customer_id・nickname・profile・deck_user_id同一の列名（差分なし）

応答3項目（ニックネーム・プロフィール・デッキユーザーID）の取得元列は現行と移行先で同一であり、主キー列名（現行player_id、移行先id）のみ異なる。移行に伴う応答仕様の変更は本書では確定しない。

応答形式はJSON。呼び出し元はデッキビルダーアプリ。クエリパラメータdeck_user_idを付けた場合は他ユーザー情報参照の分岐となり、本書では扱わない。

認証・認可

観点内容
認証方式jwt-tokenヘッダのJWTを検証し、ペイロードのaudの顧客IDから顧客IDに対応するプレイヤーを引く。署名方式はHS256。
認証失敗時ヘッダ欠落・署名不正・該当するプレイヤーなしのいずれも認証拒否（HTTP 401）とする。本文は{code, message}で返す。
認可認証したプレイヤー自身の情報のみを返す。呼び出し可能なクライアントはデッキビルダーアプリ。

トークン原値・署名シークレットは本書に記載しない。

処理フロー

自分のユーザー情報を取得する（GET /user）

  1. クエリのdeck_user_idを確認する。deck_user_idが指定されている場合は他ユーザー情報参照の分岐に進む（本書では扱わない）。
  2. deck_user_idが未指定の場合、jwt-tokenヘッダのトークンを検証し、audの顧客IDからプレイヤーを特定する。検証できない、または該当するプレイヤーがない場合は認証拒否（HTTP 401）とし、{code, message}を返す。
  3. 特定したプレイヤーが取得できない場合は入力不正（HTTP 400）とし、{code, message}（メッセージは「Invalid request parameters」）を返す。
  4. プレイヤーのニックネーム・プロフィール・デッキユーザーIDを連想配列に詰め、コード200のJSONで返す。

副作用

無し（参照のみ）。

応答はJSON応答整形を経て返す。本APIは連想配列を組み立てて返すため、JSONキーは実装で記述したsnake_case（code・user_name・profile・deck_user_id）となり、エンティティのプロパティ名（camelCase）はそのままは現れない。serialize_nullは有効で、未設定項目はnullで返す。
