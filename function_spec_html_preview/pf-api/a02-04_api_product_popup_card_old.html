API 商品管理 — ポップアップ用カード情報取得（旧商品ID）

概要

旧商品IDと言語を指定して、記事内ポップアップ用の商品情報を取得するAPIである。pf-apiが提供するJSON APIで、旧システムの商品IDと言語を用いる呼び出しに対応する。

本書は実装手順ではなく、誰が・いつ・どの条件で・結果どうなるかを読むためのリバース詳細設計とする。確認値はpf-apiの旧商品IDと言語によるポップアップ取得処理、ルート定義、商品規格を扱うリポジトリを正とする。

本機能のカスタマイズ区分は現行踏襲で、挙動の参照リポはpf-api、DB関連の記述はec-cube-enterpriseを正とする。

対象はJSON APIエンドポイントであり、ブラウザ向けの画面を持たない。

実装上は旧商品IDと言語から商品規格のポップアップ用情報を取得する。

本書で扱うこと

  • 旧商品IDと言語によるポップアップ用商品情報の取得
  • 該当が無い場合の応答

本書で扱わないこと

以下は本書では仕様確定せず、実装または別機能の設計を正とする。

  • 言語指定なしの旧商品IDによるポップアップ取得（ポップアップ用商品情報取得（旧商品ID）を正とする）
  • 現行商品ID・カードIDによるポップアップ取得（各APIを正とする）

リニューアル移行時の扱い

挙動は現行（pf-api）を正とし、DBスキーマは移行先のec-cube-enterpriseを正とする。現行と移行先で次の差がある。

観点現行（pf-api）移行先（ec-cube-enterprise）

言語言語マスタmtb_languageのcodeで判別する。同一スキーマ。mtb_language.codeで判別する。

応答フィールドの命名（camelCase）は移行後も挙動仕様としてpf-apiを正とする。

応答形式はJSON。

処理フロー

旧商品IDと言語で取得する（GET /popup/old/{lang}/{oldProductId}）

  1. パスの旧商品ID・言語を受け取る。
  2. 商品規格のリポジトリから、旧商品ID・言語に対応するポップアップ用商品情報を取得する。
  3. 取得できない場合はコード404・「Not Found」のJSONを返す。
  4. 取得できた場合は商品情報をJSONで返す。
