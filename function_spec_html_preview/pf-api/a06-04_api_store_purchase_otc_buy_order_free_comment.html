API 店頭買取管理 — 店頭買取受注コメント更新

概要

買取アプリ（MTGバイヤー）が店頭買取受注のフリーコメントを更新するためのAPIである。pf-api（買取連携用のAPIアプリケーション）が提供するJSON APIで、受注IDで対象を特定し、コメントと更新担当者を保存する。

本書は実装手順ではなく、誰が・いつ・どの条件で・結果どうなるかを読むためのリバース詳細設計とする。確認値はpf-apiのコメント更新処理、ルート定義（config/routes.yaml）、店頭買取受注を扱うエンティティ、共通の認証処理を正とする。

本機能のカスタマイズ区分は現行踏襲で、挙動の参照リポはpf-apiとする。DB関連の記述（テーブル名・列名・永続化先）はec-cube-enterpriseを正とする。

対象はJSON APIエンドポイントであり、ブラウザ向けの画面を持たない。本文ではフレームワークのコントローラ型名やメソッド名を主説明としない。「利用者視点の入口」にHTTPメソッドとパスパターンを書く。

本書で扱うこと

  • 受注IDによる店頭買取受注の特定と、フリーコメント・更新担当者の保存
  • 認証、対象なし、コメント未入力時の応答

本書で扱わないこと

以下は本書では仕様確定せず、実装または別APIの設計を正とする。

  • 店頭買取受注そのものの登録・査定・ステータス更新（各店頭買取APIの設計を正とする）
  • ネット買取受注のコメント更新（ネット買取受注コメント更新APIの設計を正とする）
  • トークンの発行（買取アプリ用ログインの設計を正とする）

リニューアル移行時の扱い

コメントと更新担当者の更新挙動は現行（pf-api）を正とし、永続化に関わるテーブル・列名は移行先（ec-cube-enterprise）を正とする。

区分現行（pf-api）移行先（ec-cube-enterprise）
店頭買取受注dtb_otc_buy_order（フリーコメント・更新担当者を保持）同一スキーマ（dtb_otc_buy_order）
更新担当者dtb_member（member_id）dtb_member（id）。会員の主キー名がidになる

更新する列（フリーコメント・更新担当者）と入力検証（コメント未指定で入力不正）はリニューアル後も同じ前提とするが、更新担当者として記録する会員の主キー名が現行のmember_idから移行先のidへ変わる。

入口URLエンドポイント期待されるふるまい

応答形式はJSON。呼び出し元は買取アプリ（MTGバイヤー）。

認証・認可

観点内容
認証方式jwt-tokenヘッダのJWTを検証し、ペイロードの利用者IDから管理者会員を引く。署名方式はHS256。
認証失敗時ヘッダ欠落・署名不正・該当する管理者会員なしのいずれも認証拒否（HTTP 401）とする。
認可認証した管理者会員が更新担当者として記録される。呼び出し可能なクライアントは買取アプリ。

トークン原値・署名シークレットは本書に記載しない。

処理フロー

店頭買取受注のコメントを更新する（PUT /admin/otcBuyOrder/{id}/freeComment）

  1. jwt-tokenヘッダのトークンを検証し、管理者会員を特定する。検証できない場合は認証拒否（HTTP 401）とする。
  2. パスの受注IDで店頭買取受注を1件取得する。該当が無い場合は該当なし（HTTP 404）とする。
  3. リクエストのコメントが未指定（null）の場合は入力不正（HTTP 400）とし、エラーメッセージを返す。
  4. 店頭買取受注のフリーコメントを指定値で更新し、更新担当者に認証した管理者会員を設定して保存する。
  5. コード200のJSONを返す。

業務ルール・計算

項目内容
更新対象リクエストで指定されたID・入力値に対応する業務データを対象にする。対象特定、入力不正、認証・認可の判定順序は処理フローとバリデーションの各節を正とする。
更新方法入力値を対象データへ上書きまたは追加登録する。履歴登録や関連データ更新がある場合は入出力の副作用およびDBカラムの節を正とする。
計算処理本APIでは金額・税・ポイント・在庫数量の再計算や丸めを行わない。ステータスやコメント等の更新は、実装で定義された遷移・存在確認・担当者判定に従う。
応答値成功時は処理結果コードまたは更新後に取得した値を返す。レスポンス値は本API内で独自集計せず、保存結果または取得結果をJSON応答へ整形する。

ログ・監査

ログに出してはいけないもの

  • JWTトークンの原値
  • 署名シークレット（auth_magic）
  • Cookie値・セッションIDの完全値

排他制御・トランザクション

本APIはフリーコメントと更新担当者の更新を行う。楽観ロック・悲観ロックの対象は持たず、同一受注への同時更新は後勝ちとなる。
