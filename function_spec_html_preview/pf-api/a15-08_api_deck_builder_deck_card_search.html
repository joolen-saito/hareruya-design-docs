API デッキビルダー — カード検索

概要

デッキビルダーアプリが、カード名・カード種別・色・マナ総量などの条件でカードを検索し、一覧と総件数を取得するためのAPIである。deck-api（デッキビルダー用のAPIアプリケーション）が提供するJSON APIで、クエリパラメータで検索条件・並び順・ページングを受け取り、条件に一致するカードの配列と総件数を返す。

本書は実装手順ではなく、誰が・いつ・どの条件で・結果どうなるかを読むためのリバース詳細設計とする。確認値はdeck-apiのカード検索処理、ルート定義（config/routes.yaml）、クエリパラメータ定義、カードのリポジトリを正とする。本機能のカスタマイズ区分は現行踏襲であり、挙動はデッキビルダーAPI（deck-api）の実装を参照し、DB関連の記述はec-cube-enterpriseを正とする。

対象はJSON APIエンドポイントであり、ブラウザ向けの画面を持たない。本文ではフレームワークのコントローラ型名やメソッド名を主説明としない。「利用者視点の入口」にHTTPメソッドとパスパターンを書く。

本書で扱うこと

  • クエリパラメータによるカードの絞り込み・並び替え・ページングのふるまい
  • 各条件パラメータの既定値・許容値の制約
  • 応答に含めるカード項目と総件数

本書で扱わないこと

以下は本書では仕様確定せず、実装または別APIの設計を正とする。

  • カードIDからの単一カード取得・カード詳細取得・単一カード検索（別入口であり本書で扱わない）
  • カード画像の生成・管理（カード画像側の設計を正とする）
  • イラストレーター条件（実装上コメントアウトされ有効でないため扱わない）

リニューアル移行時の扱い

DB関連の記述はec-cube-enterpriseを正とする。挙動の参照元であるデッキビルダーAPI（deck-api）は提供リポジトリに含まれないため、現行deck-apiと移行先ec-cube-enterpriseでスキーマが異なる場合はec-cube-enterpriseを正とし、確認できない差異はec-cube-enterprise実装で要確認とする。ec-cube-enterpriseでは、カード（mtb_card）が識別子（card_id／id）・日本語名（name_jp）・英語名（name_en）・マナ総量（cmc）・パワー（power）・タフネス（toughness）・ロイヤルティ（loyalty）・ステッカー区分（is_sticker）を持つ。種別・色・サブタイプ・レアリティ・フォーマットは各マスタおよびカードとの関連で絞り込む。

処理フロー

カードを検索する（GET /cards）

  1. クエリパラメータを受領する。未指定のパラメータには定義された既定値（条件の論理はAND、ページは1、1ページ件数は20、並びは色の昇順など）を補う。
  2. 値が指定された条件のみを検索条件に積む。カード名・テキストは空白・カンマで語分割し、語ごとに日英の名称／テキストに対して部分一致を取り、条件の論理（AND／OR／NOT）で結合する。
  3. カード種別・サブタイプ・色・レアリティは配列で受け取り、各論理（AND／OR／NOT、色はAND／OR）で絞り込む。除外色は指定色を持つカードを除外する。
  4. フォーマットを指定した場合は、そのフォーマットで使用可（および制限）のカードに限定する。非合法を含める指定があれば禁止区分も対象に加える。
  5. マナ総量・パワー・タフネス・ロイヤルティは、範囲指定（下限・上限）・一致指定・除外指定で絞り込む。
  6. 絞り込み後の総件数を算出する。
  7. 並び替え用の値（色順・マナ総量・パワー・タフネスのいずれか）と昇順／降順で並べ、ページと1ページ件数でページングして対象ページのカードを取得する。完全一致優先が指定された場合はカード名の完全一致行を先頭へ寄せる。
  8. 種別・色をカードごとの数値配列に整形し、各カードの日本語・英語のカード画像URLを付与する。
  9. 総件数とカード配列をcode・total_count・cardsのラッパに包んで返す（HTTP 200）。

集計条件

指標集計の要点
対象データカードを基点に、カード詳細・カードセット・カード種別・色を結合する。条件に応じてサブタイプ・レアリティ・フォーマット・除外色のサブクエリを加える。
一意化カード識別子で集約し、種別・色は集約値を数値配列へ展開する。総件数はカード識別子の重複排除で数える。
除外除外色・除外マナ総量・除外パワー・除外タフネス・除外ロイヤルティを満たす行を除外する。フォーマット指定時は使用可（必要に応じて禁止を含む）区分に限定する。
並び順sort（色順・マナ総量・パワー・タフネス）をorder（昇順／降順）で並べ、続いて英語名で整える。完全一致優先時はカード名完全一致を最優先する。
ページングpageとper_pageで算出する。1ページ件数は上限100に丸める。

副作用

無し（参照のみ）。検索クエリには検索条件に応じたキーの結果キャッシュ（既定の保持時間つき）を用いるが、業務データの更新・履歴・通知は行わない。

応答はJSON応答整形を経て返す。プロパティはcamelCase、日時はISO8601、serialize_nullは有効とする。本APIの配列要素キーは取得クエリのエイリアス（snake_case）に従う。

業務ルール・計算

  • 検索・一覧・取得条件はリクエストパラメータ、ログイン状態、公開状態、店舗・支店条件、既存リポジトリの絞り込み順序を正とする。
  • 件数、ページ番号、表示順は既存実装のデフォルトと上限に従い、取得後に業務値を再計算しない。
  • 金額、ポイント、数量、ステータス、日時はDBまたは連携元の永続化済み値を返却し、レスポンス生成時の丸め・補正は行わない。
  • 条件に一致しない、権限がない、または非公開のデータは空結果または既存のエラー形式で返す。
