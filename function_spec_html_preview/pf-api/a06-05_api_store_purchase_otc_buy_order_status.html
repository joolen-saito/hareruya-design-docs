API 店頭買取管理 — 店頭買取受注ステータス更新

業務ロジック

認証と担当者

トークンはリクエストヘッダで受け取る。トークンの欠落・署名不正・該当する管理者会員なしのいずれのときも認証拒否（HTTP 401）とし、受注も履歴も書き換えない。認証で特定した管理者会員を、更新時に記録する査定担当者として扱う。トークンの原値と署名の秘密値は本書に記載しない。

更新の判定順序

順序判定結果
1認証できるかできないなら認証拒否（HTTP 401）
2受注IDに該当する店頭買取受注があるか無ければ該当なし（HTTP 404）
3指定ステータスIDが店頭買取ステータスに存在するか存在しなければ入力不正（HTTP 400）
4更新前ステータスと指定ステータスが異なるか異なるときだけ書き込む。同じときは受注も履歴も書き換えず成功として応答する

ステータスIDを省略したときも、店頭買取ステータスに存在しないときと同じく入力不正（HTTP 400）とし、受注も履歴も書き換えない。

更新の内容

更新前後のステータスが異なるときだけ書き込みを行う。このとき店頭買取受注には、査定担当者と更新日時も記録する。金額・税・ポイント・在庫数量の再計算や丸めは行わない。

エラー時の扱い

事象扱い
認証不可認証拒否（HTTP 401）とする。errors配列を持つ応答本文は返さない
受注が存在しない該当なし（HTTP 404）とする。errors配列を持つ応答本文は返さない
ステータスIDが不正入力不正（HTTP 400）とし、エラー内容を含むJSONを返す

入出力

種類内容
成功時出力更新前後が同じステータスでも成功（HTTP 200）を返す
失敗時出力HTTP 401（認証不可）、HTTP 404（受注なし）、HTTP 400（入力不正）

入出力: 永続化

操作契機
更新更新前後のステータスが異なるとき、店頭買取受注に査定担当者と更新日時を記録する
追加同じ契機で、ステータス変更履歴を1件残す。履歴は対象の受注、設定したステータス、登録した管理者会員、登録日時を持つ
