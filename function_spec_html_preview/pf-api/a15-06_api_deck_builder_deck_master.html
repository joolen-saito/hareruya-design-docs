API デッキビルダー — マスタ検索

概要

デッキビルダーアプリが、カード検索やデッキ編集の選択肢として用いる各種マスタ情報を取得するためのAPIである。deck-api（デッキビルダー用のAPIアプリケーション）が提供するJSON APIで、URLのパスで指定したマスタ名に対応するマスタの全件を返す。

本書は実装手順ではなく、誰が・いつ・どの条件で・結果どうなるかを読むためのリバース詳細設計とする。確認値はdeck-apiのマスタ取得処理、ルート定義（config/routes.yaml）、対象マスタのリポジトリを正とする。本機能のカスタマイズ区分は現行踏襲であり、挙動はデッキビルダーAPI（deck-api）の実装を参照し、DB関連の記述はec-cube-enterpriseを正とする。

対象はJSON APIエンドポイントであり、ブラウザ向けの画面を持たない。本文ではフレームワークのコントローラ型名やメソッド名を主説明としない。「利用者視点の入口」にHTTPメソッドとパスパターンを書く。

本書で扱うこと

  • パスで指定したマスタ名から公開対象マスタを特定し、全件を返すふるまい
  • 公開しないマスタ・サブテーブルを持つマスタ・フォーマットマスタの扱いの違い
  • 該当マスタが無い場合のふるまい

本書で扱わないこと

以下は本書では仕様確定せず、実装または別APIの設計を正とする。

  • 各マスタの個々のカラム定義の網羅（対象マスタのスキーマを正とする）
  • カード検索・アーキタイプ検索（別APIの設計を正とする）
  • マスタ値の登録・更新（マスタ管理側の設計を正とする）

リニューアル移行時の扱い

DB関連の記述はec-cube-enterpriseを正とする。挙動の参照元であるデッキビルダーAPI（deck-api）は提供リポジトリに含まれないため、現行deck-apiと移行先ec-cube-enterpriseでスキーマが異なる場合はec-cube-enterpriseを正とし、確認できない差異はec-cube-enterprise実装で要確認とする。ec-cube-enterpriseでは、フォーマット（mtb_format）にデッキビルダー対象フラグ（deckbuilder_flg）を持ち、カード種別（mtb_cardtype）・色（mtb_color）・レアリティ（mtb_rarity）・サブタイプ（mtb_subtype）・キャンペーンタグ（mtb_campaign_tag）・デッキタグ（mtb_deck_tag）等のマスタ群と、カテゴリ・タグの親子（サブテーブルを持つdtb系）を持つ。各マスタの個々の列名はec-cube-enterpriseの当該マスタ定義を正とし、現行との列差は要確認とする。

処理フロー

マスタを取得する（GET /master/{name}）

  1. パスのマスタ名を受領し、アンダースコア区切りをキャメルケースへ変換した上で先頭を大文字化したマスタ識別名を組み立てる。
  2. マスタ識別名が追加公開対象（カテゴリ・カテゴリ並び順・会員区分・割引カード条件・タグ並び順）であればDtb系のマスタ、それ以外はMtb系のマスタを対象とする。
  3. 対象マスタのクラスが存在しない、または公開しないマスタ（権限・カード・カード詳細）に該当する場合は、該当なし（HTTP 404）として{code, message}形式のJSONを返す。
  4. マスタ識別名がフォーマットの場合は、デッキビルダー対象フラグが立つフォーマットのみを取得する。
  5. マスタ識別名がサブテーブルを持つマスタ（カテゴリ・タグ）の場合は、サブテーブルを含めて取得する。
  6. それ以外は全件を取得する。
  7. 取得結果をcodeとresultsのラッパに包んで返す（HTTP 200）。

集計条件

本APIは指定マスタの全件取得であり、件数集計・ページングを行わない。対象範囲は次のとおり。

指標集計の要点
取得対象パスで指定したマスタの全件。フォーマットのみデッキビルダー対象フラグが真の行に限定する。
結合カテゴリ・タグはサブテーブルを含めて取得する。それ以外は単一マスタの全件取得。
並び順各マスタのリポジトリの既定取得順に従う。本APIで明示の並び替えは行わない。
ページング行わない。全件を一括で返す。

副作用

無し（参照のみ）。取得クエリには結果キャッシュ（既定の保持時間つき）を用いるが、業務データの更新・履歴・通知は行わない。

応答はJSON応答整形を経て返す。プロパティはcamelCase、日時はISO8601、serialize_nullは有効とする。

バリデーション

項目内容
name形式バリデーションは行わず、マスタ識別名に変換した上で対象クラスの存在と公開可否を判定する。対象外・不存在は該当なし（HTTP 404）とする。

業務ルール・計算

  • 検索・一覧・取得条件はリクエストパラメータ、ログイン状態、公開状態、店舗・支店条件、既存リポジトリの絞り込み順序を正とする。
  • 件数、ページ番号、表示順は既存実装のデフォルトと上限に従い、取得後に業務値を再計算しない。
  • 金額、ポイント、数量、ステータス、日時はDBまたは連携元の永続化済み値を返却し、レスポンス生成時の丸め・補正は行わない。
  • 条件に一致しない、権限がない、または非公開のデータは空結果または既存のエラー形式で返す。
