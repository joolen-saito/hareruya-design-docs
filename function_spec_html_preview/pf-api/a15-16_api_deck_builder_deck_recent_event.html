API デッキビルダー — 直近大会情報取得

概要

デッキビルダーアプリが、直近に開催された大会の一覧情報を取得するためのAPIである。deck-api（デッキビルダー用のAPIアプリケーション）が提供するJSON APIで、最新大会デッキのマスタから、大会日・フォーマット・大会名・参加者数を一覧で返す。

本書は実装手順ではなく、誰が・いつ・どの条件で・結果どうなるかを読むためのリバース詳細設計とする。確認値はdeck-apiの直近大会取得処理、ルート定義（config/routes.yaml）、最新大会デッキを扱うリポジトリを正とする。

本機能のカスタマイズ区分は現行踏襲とする。挙動はdeck-api（デッキビルダー用APIアプリケーション）の実装を確認値とし、DB関連の記述（テーブル名・列名・永続化先）はec-cube-enterpriseの実装を正とする。

対象はJSON APIエンドポイントであり、ブラウザ向けの画面を持たない。本文ではフレームワークのコントローラ型名やメソッド名を主説明としない。「利用者視点の入口」にHTTPメソッドとパスパターンを書く。

本書で扱うこと

  • 直近大会の一覧（大会日・フォーマット・大会名・参加者数）の取得
  • 大会日・大会名が有効な行のみを返すこと

本書で扱わないこと

以下は本書では仕様確定せず、実装または別APIの設計を正とする。

  • 大会に紐づく個々のデッキ内容・順位の参照（デッキ関連APIの設計を正とする）
  • 大会情報そのものの登録・更新（最新大会デッキマスタの生成バッチ・管理機能の設計を正とする）
  • メタゲームの集計（メタゲーム情報参照APIの設計を正とする）

リニューアル移行時の扱い

デッキビルダー関連テーブルは、現行（deck-api）と移行先（ec-cube-enterprise）で同一スキーマであり、テーブル名も一致する。本機能の参照に関わる主な対応は次のとおり。

項目現行（deck-api）移行先（ec-cube-enterprise）差分・注意
最新大会デッキマスタmtb_latest_event_deck。大会日（event_date）・大会名（event_name_jp・event_name_en）・参加人数（participants）同一テーブル・列名大会日が設定済みかつ大会名が空でない行のみを対象とする。
フォーマットマスタmtb_format。識別子（id）・名称（name_jp・name_en）同一テーブル・列名結合してフォーマット名を取得する。

現行と移行先でスキーマに差はなく、移行時に追加・改廃する列は本書では確認していない。

認証・認可

観点内容
認証方式本APIは認証を行わない。jwt-tokenヘッダの検証・プレイヤーの特定をいずれも行わず、誰でも呼び出せる参照系である。

処理フロー

直近大会情報を取得する（GET /recent_event）

  1. リクエストパラメータを受け取らない。
  2. 最新大会デッキのマスタから、大会日が設定済みかつ大会名（日本語・英語）が空でない行を抽出し、識別子の昇順で並べる。
  3. 大会日・フォーマット識別子・フォーマット名（日本語・英語）・大会名（日本語・英語）・参加者数を一覧（events）にまとめ、コード200のJSONで返す。

副作用

無し（参照のみ）。一覧は結果キャッシュするが、業務データの更新は行わない。

応答はJSON応答整形を経て返す。本APIは連想配列を組み立てて返すため、JSONキーは実装で記述したsnake_case（code・events・event_date・format_name_jp等）となる。日時はISO8601文字列とし、serialize_nullは有効とする。

バリデーション

本APIは入力パラメータを持たないため、入力検証を行わない。

業務ルール・計算

  • 検索・一覧・取得条件はリクエストパラメータ、ログイン状態、公開状態、店舗・支店条件、既存リポジトリの絞り込み順序を正とする。
  • 件数、ページ番号、表示順は既存実装のデフォルトと上限に従い、取得後に業務値を再計算しない。
  • 金額、ポイント、数量、ステータス、日時はDBまたは連携元の永続化済み値を返却し、レスポンス生成時の丸め・補正は行わない。
  • 条件に一致しない、権限がない、または非公開のデータは空結果または既存のエラー形式で返す。
