API ネット買取管理 — ネット買取受注コメント更新

概要

買取アプリ（MTGバイヤー）がネット買取受注のフリーコメントを更新するためのAPIである。pf-api（買取連携用のAPIアプリケーション）が提供するJSON APIで、受注IDで対象を特定し、コメントと更新担当者を保存する。

本書は実装手順ではなく、誰が・いつ・どの条件で・結果どうなるかを読むためのリバース詳細設計とする。確認値はpf-apiのコメント更新処理、ルート定義（config/routes.yaml）、ネット買取受注を扱うエンティティ、共通の認証処理を正とする。

本機能のカスタマイズ区分は現行踏襲であり、挙動の参照リポはpf-api、DB関連（テーブル名・列名・永続化先）の記述はec-cube-enterpriseを正とする。

対象はJSON APIエンドポイントであり、ブラウザ向けの画面を持たない。本文ではフレームワークのコントローラ型名やメソッド名を主説明としない。「利用者視点の入口」にHTTPメソッドとパスパターンを書く。

本書で扱うこと

  • 受注IDによるネット買取受注の特定と、フリーコメント・更新担当者の保存
  • 認証、対象なし、コメント未入力時の応答

本書で扱わないこと

以下は本書では仕様確定せず、実装または別APIの設計を正とする。

  • ネット買取受注そのものの登録・査定・ステータス更新（ネット買取受注ステータス更新APIおよび各買取APIの設計を正とする）
  • 店頭買取受注のコメント更新（店頭買取受注コメント更新APIの設計を正とする）
  • トークンの発行（買取アプリ用ログインの設計を正とする）

認証・認可

観点内容
認証方式jwt-tokenヘッダのJWTを検証し、ペイロードの利用者IDから管理者会員を引く。署名方式はHS256。
認証失敗時ヘッダ欠落・署名不正・該当する管理者会員なしのいずれも認証拒否（HTTP 401）とする。
認可認証した管理者会員が更新担当者として記録される。呼び出し可能なクライアントは買取アプリ。

トークン原値・署名シークレットは本書に記載しない。

処理フロー

ネット買取受注のコメントを更新する（PUT /admin/buyOrder/{id}/freeComment.json）

  1. jwt-tokenヘッダのトークンを検証し、管理者会員を特定する。検証できない場合は認証拒否（HTTP 401）とする。
  2. パスの受注IDでネット買取受注を1件取得する。該当が無い場合は該当なし（HTTP 404）とする。
  3. リクエストのコメント（free_comment）が未指定（null）の場合は入力不正（HTTP 400）とし、エラーメッセージを返す。
  4. ネット買取受注のメモ（フリーコメント）を指定値で更新し、更新担当者に認証した管理者会員を設定して保存する。保存はトランザクション内で行う。
  5. コード200のJSONを返す。

業務ルール・計算

項目内容
更新対象リクエストで指定されたID・入力値に対応する業務データを対象にする。対象特定、入力不正、認証・認可の判定順序は処理フローとバリデーションの各節を正とする。
更新方法入力値を対象データへ上書きまたは追加登録する。履歴登録や関連データ更新がある場合は入出力の副作用およびDBカラムの節を正とする。
計算処理本APIでは金額・税・ポイント・在庫数量の再計算や丸めを行わない。ステータスやコメント等の更新は、実装で定義された遷移・存在確認・担当者判定に従う。
応答値成功時は処理結果コードまたは更新後に取得した値を返す。レスポンス値は本API内で独自集計せず、保存結果または取得結果をJSON応答へ整形する。

副作用

ネット買取受注のメモ（フリーコメント）と更新担当者を更新する（DB更新）。参照のみではない。更新はトランザクション内で確定し、例外時はロールバックする。

応答はJSON応答整形を経て返す。プロパティはcamelCase、日時はISO8601、serialize_nullは有効とする。

ログ・監査

ログに出してはいけないもの

  • JWTトークンの原値
  • 署名シークレット（auth_magic）

排他制御・トランザクション

本APIはメモ（フリーコメント）と更新担当者の更新をトランザクション内で行う。楽観ロック・悲観ロックの対象は持たず、同一受注への同時更新は後勝ちとなる。
