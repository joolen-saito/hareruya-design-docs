# 機能ごとのFPと結合テストケース数の妥当性

ec-cube-enterprise（ee）の機能量をファンクションポイント（FP）で機能ごとに測った。
IPA の密度から結合テストのケース数の目安を出し、実際のケース数（`integration_test/casegen/all_test_cases.tsv`）と比べた。

| | |
| --- | --- |
| 測定対象 | `ec-cube-enterprise` develop `95fd74af4c`（2026-10-19）。ルートは 2026-10-23 に動作中のコンテナで `debug:router` から採取 |
| 比べたケース | 作業ツリーの一覧 12,164件 / 346機能（2026-10-23 時点。除外を当てた後） |
| 手法 | 概算FP法（IFPUG 未調整FP・全項目を平均複雑度）。数え方は `../README.md` と同じ |
| 密度 | IPA『ソフトウェア開発分析データ集2022』表5-2-1 全開発種別 結合テスト **P25 668.8 / 中央 1,782.3 / P75 3,450.8 件/KFP** |
| レビュー | 割り当てを codex で3巡反証（指摘 8→3→5件。採用13件・却下3件。`review/`） |

## 1. 答え

### 1.1 FPから見た妥当なケース数（全体）

> **ケースが要る機能（371機能）の規模は 5,211 FP。妥当な結合テストケース数は中央値で約 9,300件
> （ありうる幅 3,500〜18,000件）。いまの 12,164件は中央値の 1.31倍で、幅の中に入っている。**

| 見方 | FP | P25 | **中央** | P75 |
| --- | ---: | ---: | ---: | ---: |
| **ケースが要る機能**（ケースあり346＋ケース0件25。標準・フェーズ2見送り・実装しないを除く） | 5,211 | 3,485 | **9,287** | 17,981 |
| ee 全量（対象外の処理・標準機能・バッチ込み） | 5,871 | 3,926 | 10,464 | 20,259 |
| 参考: パッケージ標準からの純増だけを数える方式（`../PACKAGE_STANDARD_DELTA.md` と同じ式） | 4,026＋標準341 | ― | 7,886 | ― |

- **実際の 12,164件 ＝ 2,334 件/KFP。** 業界の中央値（1,782.3）よりやや多く、P75（3,450.8）までは余裕がある。
- 純増方式（前回採用の約8,000件）と比べると 1.54倍。純増方式は「パッケージ標準のまま使う部分は回帰だけ」とみなす数え方で、
  標準由来の画面にカスタマイズを入れた機能（カスタマイズ160機能）も純増分しか数えない。今回のケースはそれらの画面全体を試しているので、
  **比べる相手は上の「ケースが要る機能」の行**とするのが合う。

## 3. この数字の限界

| # | 限界 | 影響 |
| :-: | --- | --- |
| 1 | **概算FP法は画面の中身の量を測らない。** 1アクション＝1処理、全項目を平均複雑度で数えるので、表示ルールの多い画面ほど過小に出る | 機能ごとの「多い」は信用できない。「少ない」は、処理単位が多いのにケースが少ないもの（M04-13・M10-06）ほど信用できる |
| 2 | **IPA の密度はプロジェクト単位の統計。** 機能1つに当てるのは本来の使い方ではない | 機能ごとの判定は並べ替えと候補出しの道具として使う。合否の基準にはしない |
| 3 | **データFP（42%）は按分。** テーブル1つ10 FP を、設計書の「更新するテーブル」の機能で等分した（153テーブル）。無ければ「使うテーブル」の機能（27）、どちらも無い64テーブルと外部連携は処理FPの比で配った | 処理単位の少ない機能ほど、按分の仮定に結果が左右される |
| 4 | **割り当ては判断を含む。** 819件をソースと設計書で割り当て、codex で3巡反証した。確度「低」は23件。共有する処理（31件）は機能で等分した。対象外は65件（266 FP。インストーラ・オーナーズストア・機能一覧に無い標準画面など） | `work/assign_G*.tsv` の根拠欄で1件ずつ確かめられる |
| 5 | **重複登録の機能**（A06-06≡A06-17、A06-07≡A06-10≡A06-18、A06-09≡A17-05）は FP を等分した | ケースは片方にだけあるので、ケースのある側が「少ない」寄りに出る。まとめて見ること |
| 6 | バッチのコマンド34件（139 FP）は、元の FP 調査（ルートだけ）に無かったものを足した | 全体の FP は 5,732（ルートだけ）→ 5,871 |
