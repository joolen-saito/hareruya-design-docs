# 機能間依存関係定義書スキル

## 前提

- 常に `.cursor/design/基本設計方針.md` を正とする。
- 機能間依存関係定義書は全体で管理する。
- 個別機能仕様には依存先と依存理由の概要を記載し、依存関係の横断管理は本設計書へ寄せる。

## 出力先

- `.cursor/design/機能間依存関係定義書.md`

## 記載観点

- 依存関係ID
- 依存元機能
- 依存先機能
- 依存タイプ
- 依存度
- 依存内容
- 呼出方式
- 変更時の影響範囲
- リスク
- 軽減策
- 検証方法
- 備考

## 作業手順

1. 機能仕様書、画面一覧、API、DB、帳票、外部IFを確認する。
2. 機能間の呼出、参照、状態連動、データ依存、権限依存を抽出する。
3. 依存度と変更時の影響範囲を整理する。
4. リスク、軽減策、検証方法を記載する。

## 注意

- 単なる関連リンク集にしない。変更時に何が壊れるかを分かるように書く。
- DB共有、状態値共有、認証・権限依存、外部連携依存を見落とさない。
- 未確定の依存は `要確認` または `TODO` として残す。
