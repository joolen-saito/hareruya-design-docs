# 正本・閲覧版整合性チェックスキル

## 目的

Markdown、YAML、CSVなどの正本とHTML閲覧版の差異を検出する。HTMLは原則として派生成果物であり、仕様内容の正本ではないため、正本に存在する内容の欠落と、HTML側だけに存在する仕様情報の混入を重点的に確認する。

本スキルは正本↔派生（HTML）の一致を扱う。**ソースコードと設計書（正本）の双方向の網羅**（実装の漏れ・無根拠・誤混入）は対象外であり、それは `../reverse-design/SOURCE-COVERAGE-CHECKLIST.md` で確認する。正本自体に混入した内容は両者に伝播するため本スキルでは検出できない点に注意する。

## 対象

- Markdown正本とHTML閲覧版
- CSV/YAML正本とHTML表
- OpenAPI YAMLとAPI閲覧表示
- 画面項目定義MarkdownとHTML版画面項目定義書
- 機能仕様MarkdownとHTML版機能仕様書

## チェック観点

- 見出し構成が一致しているか。
- 正本の本文がHTMLに反映されているか。
- HTMLに正本由来でない仕様説明が追加されていないか。
- 表の列名、列順、行数、No.が一致しているか。
- TODO、未確定項目、注記が欠落していないか。
- リンク先、ファイル参照、アンカーが壊れていないか。
- 画面項目定義の場合、画面項目、計算式、アクションイベント、特殊系バリデーションが一致しているか。
- HTML側の変更が見た目、アンカー、レイアウト、埋め込み表示など閲覧性の変更に留まっているか。

## 判定方針

- 正本にありHTMLにない内容は欠落として扱う。
- HTMLにあり正本にない仕様内容は混入として扱う。
- 表示順や装飾差分は、意味や参照性が変わらない限り問題にしない。
- 文言が完全一致しなくても、意味が同じなら軽微差分として扱う。
- 意味が変わる要約、条件の省略、例外処理の脱落は不一致として扱う。

## ワークフロー

1. 正本ファイルと閲覧版ファイルの組み合わせを特定する。
2. 見出し、表、TODO、リンク、注記を抽出する。
3. 欠落と混入を分類する。
4. 重要度を付け、正本修正か閲覧版修正かを提案する。

## 出力

- 欠落: 正本にあるが閲覧版にない内容。
- 混入: 閲覧版にあるが正本にない仕様内容。
- 構造差分: 見出し、表、No.、リンクの不一致。
- 修正提案: どちらのファイルをどう直すべきか。
