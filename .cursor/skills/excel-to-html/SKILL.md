# Excel設計書HTML変換スキル

## 目的

Excelの基本設計仕様書（`.xlsx/.xlsm/.xltx/.xltm`）を、見た目の完全再現ではなく「読みやすいHTML」へ変換する。1ブック=1HTML（自己完結・画像はbase64埋め込み）。Excel図形で作られた画面遷移図・フロー図は、DrawingMLの図形座標・サイズ・コネクタ形状を保持したHTML/SVG図と遷移一覧へ再構成する。配色・レイアウトは [[doc-html-render]] / [[html-sidebar]] / [[html-sidebar-color]] の2アクセント（clay/olive）＋左サイドバーに統一する。

実体ツール: `tools/excel_to_html/convert.py`（変換）, `tools/excel_to_html/verify.py`（検証）。実行は `uv run python convert.py` / `uv run python verify.py`。詳細は `tools/excel_to_html/README.md`。

補助ツール: 関連MarkdownをExcel HTMLへ追記している場合は、Excel変換後に `functions/todo-list.md` 駆動の統合スクリプトを再実行する。この統合はHTML派生成果物への後段処理であり、Markdown正本とExcel正本は変更しない。Excel由来本文とMarkdown由来ブロックに同一機能・同一仕様の内容が重複している場合は、Excel基本設計仕様書を正とし、Markdown由来ブロックはExcel本文を上書きしない。

## 使う場面

- Excelの画面項目定義・画面イメージ・CSVフォーマット等をHTML閲覧版へ変換する。
- Excel図形（矩形ノード＋コネクタ）で作られた画面遷移図・フロー図を、文字一覧ではなく、Excel上の図形座標・サイズ・コネクタ形状を保持したHTML/SVG図として再構成する。
- レイアウト図（画面イメージ）上の番号ピンを画像へ復元し、項目定義テーブルのNo.と相互リンクする。
- 変換結果が正本Excelを欠落なく反映しているか検証する。

## 変換原則

- セル値・結合セル・改行・シート順を保持する。方眼の空行・空列は省き、表は横スクロール可能にする。
- 数式セルは `data_only=False` で式本文を保持する。表示値だけでなく式本文（取得できる場合はキャッシュ値も）を原本仕様として扱い、要約・推測で置換しない。連番・計算値などの仕様が式に含まれる場合に落とさない。
- Excelで非表示またはveryHiddenのシートは、HTML変換・左サイドバーの一覧・検証対象から除外する。除外対象は原則としてシート名ではなくExcelの表示状態で判定する。
- 例外（2026-07-25 ユーザー決定）: シート名が「画面遷移図」の専用シートは、表示状態がvisibleでも除外する。理由=このシートを取り込むと後続シートの序数(`sheet-<N>`)が全てシフトし、既存の相互リンク（`item-sheet-<N>-<No>` / `pin-sheet-<N>-<No>`）と `functions/superseded_specs.json` 台帳・各種引用が破綻するため。画面遷移図の遷移内容は各画面シート内の埋め込み要素・図形テキスト全件表で担保し、専用シートそのものはサイドバー・変換・検証対象から外す。この1点に限りシート名による除外を許可する（他のシートは引き続き表示状態のみで判定）。
- Excelの表示書式を、HTML本文・表・検証で同じように扱う。特に識別ID/No.列で `m-d` 書式の日付型として読まれる値は、内部値の年を出さず、Excel表示どおり `1-1`、`2-5` などに戻す。これを怠ると画像上の `(1-1)` と項目表No.が一致せず、番号ピンのオーバーレイ判定が落ちる。
- セル全体またはリッチテキスト内の一部文字列に設定された取り消し線は、HTMLでも同じ文字列範囲へ反映する。本文・箇条書き・表セルのどこに出ても装飾を落とさない。取り消し線の検出は、特定ブック・シート・文言に依存するハードコード補正で代替しない。`styles.xml` / `sharedStrings.xml` / `inlineStr` の `rPr` を直接読み、`<strike val="0">` は偽として、run 単位・セル継承で全機能を堅牢に判定する。
- `処理概要`・`機能仕様` などの本文ブロックで、`★` や箇条書き記号を先頭にした説明行が複数列に分かれているだけの場合は、列が揃って見えても表組にしない。正式な表ヘッダ（例: `識別ID`、`No` など）を持つデータ定義表とは分ける。
- 表ヘッダ（例: `識別ID / ラベル / 書式・制限 / 必須 / 最大値 / 初期値 / 画面部品の説明`）とデータ行の間に `共通部品`・`検索条件`・`フッター` などの1セル区分行が挟まる場合も、ヘッダ・区分行・データ行を同一表として扱う。区分行は表内の全列結合行として出力し、ヘッダや先頭データ行を本文見出しへ分離しない。
- `Ph1` / `Ph2` など段階前提が明示された機能は、その注記を目次・機能名・要件説明・処理概要のいずれかで保持し、HTML化時に「Ph1では実装しない」「Ph2対応」などの条件を落とさない。
- openpyxlが読まないテキストボックス/図形内テキスト・コネクタは、DrawingMLを直接パースして抽出する。
- DrawingMLから抽出したテキストボックス/図形内テキストは、画像ピンや画面遷移図に重複表示されていても除外しない。各シート末尾の「図形・テキストボックス内テキスト」全件表へ、抽出順の連番（`data-shape-index`）・セル位置（`data-shape-ref`）・本文を1件ずつ出力する。
- 引用規約: 本文・表セル・図形・番号ピン・画像の各要素に、原本の実Excelセル座標を `data-excel-ref`（`0203:シート名!B50` 形式＝ブック番号:シート名!セル）として付与する。HTMLの表示行番号・DOM順・スクリーンショット座標を引用の根拠にしない。オラクル（`e2e-test-cases` / `integration-test-cases`）が設計書を根拠に引用する際は、必ずこの実Excel座標を使い、旧来のHTML行番号引用（例 `0204:6285`＝実在しない行）は使わない。
- 画像を持たず、テキスト付き図形ノードと `cxnSp` コネクタを持つシートは、画面遷移図/フロー図としてHTML/SVGステージに再構成する。図本体はExcelの図形座標・図形サイズ・コネクタ形状を保持して描画し、`stCxn/endCxn` と `headEnd/tailEnd` から「遷移元 / 遷移先」の一覧表を補助生成する。特に状態遷移図は横方向の配置、列見出し、`NG` などのラベルに意味があるため、接続関係だけで階層レイアウトへ再配置しない。ただしシート名「画面遷移図」の専用シート自体は上記の除外規約により変換対象外なので、本ステージ化は残置対象シートに埋め込まれた図（画像なし・図形ノード＋コネクタを持つ領域）に対してのみ適用する。未解決コネクタ台帳・検証exit1・connector inventoryの規約は残置対象シート内の図に対して引き続き有効。
- 状態遷移図の矢印は、コネクタ自身のboxだけで近似しない。`stCxn/endCxn` の接続先図形IDと接続点indexを使い、背面の空図形（テキストを持たない角丸矩形・判断図形など）も内部オブジェクトとして保持して、図形外周の接続点へ線端を合わせる。図本体ではExcel上の `cxnSp` を全件描画し、遷移一覧だけ重複排除してよい。
- 画面遷移図の矢印が同一接続点から多数分岐して重なる場合は、Graphviz/Mermaid等で全体を再配置せず、Excel座標を保ったまま始点近傍に短い引き出し線とレーンを追加して判読性を上げる。端点は必ず `stCxn/endCxn` の接続点へ残し、レーン調整で図形への接地を崩さない。
- DrawingML上に画像がなくても openpyxl フォールバック画像がある場合は、画面イメージ/資料画像として扱い、図形ステージ化で番号ピンのフォールバックリンクを消さない。
- グラフ・条件付き書式・印刷範囲は再現せず「未変換要素」に列挙する。
- HTML側に正本にない仕様内容を足さない（要約・推測・補足を加えない）。
- 関連Markdownを追記統合する場合でも、Excel基本設計仕様書とMarkdown正本に同一仕様の重複があればExcelを正とする。食い違いを見つけた場合はHTMLだけで調整せず、Markdown正本をExcelに合わせて更新するか、差分を移行後の扱い・実装確認値として分離してから再変換する。

## 関連Markdownの追記統合

関連Markdownを `excel_to_html/output/*.html` の対象画面シート末尾へ追記している場合は、次の順で行う。

1. Excelを更新した場合は `cd excel_to_html && uv run python convert.py` でExcel HTMLを再生成する。
2. リポジトリルートで `python3 .cursor/skills/function-spec-html-render/scripts/integrate_function_docs_into_excel_html.py` を実行する。
3. `cd excel_to_html && uv run python verify.py` で既存Excel由来の検証を実行する。この検証には、Excel基本設計が廃止を宣言した仕様の明示（[[superseded-spec]]）も含まれる。台帳に載る機能設計書の埋め込み節・プレビューに「刷新後は実装不要」バナーが無い場合、台帳とMarkdownの記述が同期していない場合、未判定の新規廃止指示がある場合はNGになる。

追記対象は `functions/todo-list.md` の機能No、区分、分類、機能名、Markdownリンクを基準に特定し、対象シート末尾へ入れる。別タブ化や `index.html` への統合一覧追加は行わない。追記ブロックは `<!-- function-design-embed:start ... -->` / `<!-- function-design-embed:end ... -->` のマーカーで差し替え、再実行時に重複させない。

Excel由来の機能仕様・画面項目定義・処理概要・CSV/帳票項目と、追記するMarkdown本文が同一仕様に触れている場合、HTML上ではExcel由来部分を正として読む。Markdown本文は補助的な詳細設計として追記し、Excel本文の同一仕様を置き換える扱いにはしない。

Markdownファイル名は `todo-list.md` の機能No・区分・分類・機能名に対応する命名を正とし、リンク切れや誤統合がある場合は先に `todo-list.md` とファイル名の対応を直す。Excel側に対応シートがない、または安全に一意判定できないMarkdownは `functions/function-doc-excel-integration-report.md` の未統合一覧に残す。

## レイアウト図のナンバリング ↔ 識別IDの連携（中核仕様）

画面イメージはラスター画像として埋め込まれ、その上に重なる番号ピン（`(1-2)`,`(1)` 等のテキストボックス）はExcel上は別図形のため、素朴に変換すると画像から剥がれて番号が欠落する。これを次の方法で復元・連携する。

### 1. 座標復元（EMU幾何）

- 番号ピンと画像 `pic` は同一 drawing パートの **入れ子 `grpSp`** 内にある。各図形のローカル座標を、全祖先グループの変換を内側→外側へ適用して絶対EMUへ写す。
  - 変換一般式: `abs = grp.off + (child - grp.chOff) * grp.ext / grp.chExt`（x,y各軸。`chOff/chExt` 欠落は恒等、`chExt=0` はゼロ除算回避で恒等）。外側グループが恒等でも内側はスケールし得るので必ず全段適用する。
  - 画像ボックスは `pic/spPr/a:xfrm` の `off,ext`（祖先グループのスケール積を乗算）。
- 画像上の%位置: `left=(pin中心x - img.x)/img.cx*100`, `top=(pin中心y - img.y)/img.cy*100`。

### 2. 画像バイトも自前パースから取得（整合性の要）

- **openpyxl の `worksheet._images` を座標・対応付けに使わない**。openpyxlの画像列挙数とDrawingMLの `<pic>` 数はズレることがあり（例: 9 vs 10）、index対応が破綻する。
- `pic` の `blipFill/a:blip/@r:embed` → drawing の rels（`xl/drawings/_rels/drawingN.xml.rels`）→ media パート（`xl/media/*`）を解決し、**ボックスと画素を同一 `<pic>` 由来**で取得する。openpyxlは drawing が無い場合のフォールバックのみ。
- DrawingMLの画像ボックス同士が重なる場合、または同一シート内で画面イメージとして縦に連続する分割画像群は、同じ画像レイヤー群としてHTMLへ描画する。レイヤー群は全画像ボックスのunionをステージにし、各画像を相対配置して、後に出現した `<pic>` が上に重なるようにする。
- ただし、別の見出し/セクションに属する離れた画像まで同一レイヤー群へ結合しない。非重複画像を「縦に連続する分割画像」とみなすのは、横方向の帯が揃い、かつExcel上のアンカー行が近い場合に限る。例: `レイアウト図 在庫移動指示検索画面` の画像群と `レイアウト図 在庫移動実績CSV登録モーダル` の画像は別セクションとして、それぞれの見出し付近に出力する。
- `レイアウト図...` の行は文書フロー上の見出しとして扱い、識別ID表や項目表の単一セル区分行へ吸収しない。見出し直後のDrawingML画像（例: `在庫移動指示検索 / D155 / image 1`）がその見出しの直下へ出力されることを確認する。
- 画像上のラベルやボタン列がExcel上で別 `pic` になっている場合、caption/altへ「画像内ラベル」などの手書き補足を足さない。DrawingML画像そのものをレイヤーとして再現し、正本Excelにない仕様文言をHTMLへ追加しない。

### 3. ピン→画像の割当（取りこぼし防止）

- 各ピンを**最近接の画像ボックス**へ割り当てる（内包なら距離0）。番号ピンは画像の左マージン等に数mmはみ出すため、厳密内包だと脱落する。
- ピン中心が箱の外でも、最近接距離が `0.5 * max(box幅, box高)` 以内なら割当（%は0–100にクランプ）。それより遠いピン（シナリオ注記・図形描画画面・断片化画像など画像に乗らないもの）は割り当てない。
- 画像上に復元するピンは、正規化後に `^\d+(?:-\d+)*$` へ一致するDrawingML図形テキストだけに限定する。`アクション`、`ステータス`、`NG` などの非番号図形テキストは画像ピン化せず、図形テキストまたは遷移図として保持する。

### 4. 画面イメージ判定（成立条件）

- 「画像あり」かつ「正規化ピンの一定割合（`PIN_MATCH_RATIO=0.6`）が項目表No.集合に一致」するシートのみオーバーレイ。
- 画像なしで `cxnSp` コネクタを持つ画面遷移図・フロー図は、図形テキスト表ではなくExcel座標保持のHTML/SVG図と遷移一覧へ回る。別添資料やNo.非対応の画像資料は従来どおり画像/図形テキスト表へ回る。

### 5. 識別IDの正規化と相互リンク

- 正規化: 括弧・記号を除き `[0-9A-Za-z-]` のみ残す（`(2-13-1)`→`2-13-1`,`（1）`→`1`）。階層型と単純整数型の両方を扱う。
- 項目表（`render_table`）: No.が正規化後に項目表に存在する行へ `id="item-<sheet>-<no>"` を付与し、No.セルを `#pin-<sheet>-<no>` への逆リンクにする。
- 番号ピン（`render_image_pins`）: `id="pin-<sheet>-<no>"`＋`#item-<sheet>-<no>` への順リンク。:target でピン・行を相互ハイライト。
- `識別ID` ヘッダ行の直後に区分行（例: `CSVファイルアップロード`、`移動指示リスト検索`、`CSV`）が挟まる場合も、区分行とその直後の先頭データ行（例: `1-1`、`2-1`）を同一表に残す。区分行テキスト自体は識別IDとして扱わない。
- **画像に乗らない番号も連携を維持**: フォールバックの「図形・テキストボックス内テキスト」表でも、No.が項目表に一致する行は `#item` へリンクし、`pin-<sheet>-<no>` アンカーを担う（画像ピンが無い番号の逆リンク先になる）。
- アンカー一意性: 同一Noはピン・項目行とも最初の出現のみ id を付与（重複は href のみ）。doc行で分割された継続テーブルの先頭データ行はヘッダ扱いせず id/リンクを維持する。
- 結果として「項目表No.に対応する全番号は、画像ピンか図形表のいずれかで必ず相互リンクされ、デッドリンクを生じない」。

## 図形・テキストボックス全件表のPDCA

`output/shape_textbox_sheets.csv` は、DrawingML図形・テキストボックスの**未変換残件リスト**として扱う。`uv run python convert.py` はHTML生成後にこのCSVも自動生成し、全件HTML化できている場合はヘッダのみ（データ0件）になる。

1. Plan: `shape_textbox_sheets.csv` の各行（`file_name`, `sheet_name`, `shape_index`, `cellref`, `text`, `reason`）を未変換対象とする。CSVにデータ行がある場合は、その図形テキストをHTMLへ変換する処理が不足している。
2. Do: 各対象シートの末尾に `shape-block` を出し、全図形テキストを `data-shape-index="1..."` と `data-shape-ref="<セル位置>"` 付きの行としてHTML化する。画像上の番号ピン、画面遷移図ノード、注釈、非番号ラベルも、重複を理由に全件表から除外しない。
3. Check: `uv run python verify.py --input-dir input --output-dir output` で、DrawingML抽出件数、HTML上の全件表の行数・連番・セル位置・本文が一致し、さらに `shape_textbox_sheets.csv` のデータ行が0件であることを確認する。`VERIFY OK` でない場合は未潰し込みが残っている。
4. Act: 不一致またはCSV残件が出たら、該当ブック/シート/図形番号の抽出・配置・リンク処理を修正し、`convert.py` → `verify.py` を再実行する。CSVを手で空にして合格扱いにしない。

## 変換の検証（`verify.py`）

`uv run python verify.py` で各ブックについて次を機械検証し、不合格なら非ゼロ終了する。

1. シート網羅: 表示ワークシート名がサイドバー/パネルに存在し、非表示/veryHiddenシート名がサイドバー/パネル見出しに存在しない。
2. セル値カバレッジ: 表示シートの全非空セル値がHTML本文に出現（目標100%、99.5%未満で失敗）。
3. 取り消し線カバレッジ: 表示シートで取り消し線が設定されたセル値またはリッチテキスト部分が、HTMLの同じ文字列範囲に `cell-strike` として出現。
4. 画像網羅: 表示シートのDrawingMLの `<pic>` 数とHTML埋め込み `data:image/` 数が一致。画像がレイヤーステージへ統合される場合も、対象シート単位でDrawingML画像件数とHTML内の画像件数/`data-image-layer-count` を比較し、分割されたラベル画像が落ちていないことを確認する。
5. 画面遷移図再構成: HTML/SVG図として復元対象のDrawingML図について、図本体がExcel座標ベース（`data-diagram-layout="excel"`）で出力され、`data-diagram-connectors` が元の `cxnSp` 件数を満たし、SVG上にも同数のコネクタpathが描画され、`data-transition-edges` が抽出した遷移数を満たす。状態遷移図では列見出しや `NG` など、接続されていないが図の意味を持つラベルも落とさない。
6. リンク整合: `#item`/`#pin` の参照先が全て実在（デッドリンク0）。
7. 図形・テキストボックス内テキスト非欠落: 表示シートのDrawingMLから抽出した全図形テキストがHTML本文に存在し、さらに各シートの「図形・テキストボックス内テキスト」全件表に抽出順・セル位置・本文一致で1件ずつ存在する。`shape_textbox_sheets.csv` は未変換残件0件（ヘッダのみ）である。不合格時はシート名・セル位置・該当テキスト・正規化Noを出し、人間が修正対象を特定できるようにする。
8. 鮮度: 入力Excelの更新時刻が出力HTMLより新しい場合は、HTMLが古いものとして失敗させる。

表示シートのみを対象にした合格基準の実測（0203/0204）: セル値100%、画像53/53・76/76、デッドリンク0、図形テキスト678/678・556/556。

Excelを更新した後は、必ず `uv run python convert.py` でHTMLを再生成してから `uv run python verify.py` を実行する。検証だけを先に実行して古いHTMLを合格扱いしない。
