# ログ管理仕様書スキル

## 前提

- 常に `.cursor/design/基本設計方針.md` を正とする。
- ログ管理仕様書は実装ログの書き方ではなく、基本設計として何を記録し、どう運用・調査で使うかを定義する。
- 実装時の詳細なコーディング規約は `.cursor/rules/` 側へ委ねる。

## 出力先

- `.cursor/design/アーキテクチャ/ロギング/`

## 記載観点

- ログ種別
- 出力契機
- 出力項目
- ログレベル
- 個人情報・機密情報のマスキング
- 保存期間
- 検索・閲覧権限
- アラート条件
- 障害調査で利用する相関ID、リクエストID

## 作業手順

1. 関連する機能仕様、API、外部IF、認証・認可要件を確認する。
2. 記録すべき業務イベントと操作イベントを抽出する。
3. ログ種別、出力項目、保存・閲覧・マスキング方針を整理する。
4. 個別機能側には記録契機、操作種別、記録対象の概要だけを残す。

## 注意

- 機能仕様書にログ項目の詳細を二重記載しない。
- 個人情報や機密情報をそのまま記録する前提にしない。
- 権限不足、認証失敗、外部連携失敗などの監査・調査に必要なイベントを漏らさない。
