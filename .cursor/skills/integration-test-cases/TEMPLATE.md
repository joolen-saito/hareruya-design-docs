# 結合試験テストケース出力テンプレート

Markdown ファイルを新規作成・追記するときの構成例である。見出し名はプロジェクトに合わせて調整してよい。

## 推奨ファイルパス

- `.cursor/design/integration_test/<機能識別子>_it_cases.md`（結合試験テストケースのみ。元設計は引き続き `.cursor/design/functions/` に置く）

## 冒頭概要

- 元設計へのリンク。例 `.cursor/design/functions/<機能>.md`
- テスト観点へのリンク。例 `.cursor/docs/テスト観点.md`
- 環境依存の記載方針の一文（期待結果は観測・試験計画ベースとし、特定設計書の文言を合格判定の正にしないこと。[TERMINOLOGY.md](TERMINOLOGY.md)「期待結果に書かないこと」参照）。**テストレベル列は TSV に含めない**
- 用語は必ず [TERMINOLOGY.md](TERMINOLOGY.md) に従う旨を一文で書く。試験本文に「または」を使わない。試行制限・レートリミットの記述は同ファイル「試行制限・レートリミット」の平易語に合わせる。

## 関連ID対応概要

`.cursor/docs/テスト観点.md` の **関連ID** と **観点** に合わせる。TSV の **I/FID** 列＝関連ID、**テスト観点** 列＝テスト観点.md の観点。

| 関連ID | 本機能での主な確認範囲 |
|--------|------------------------|
| IT-01 | （例）入力値の受け渡し |
| IT-04 | （例）ログイン状態判定 |

## テストケース TSV

Excel／スプレッドシート貼り付け用の注意を短く書く。次の定型文をそのまま使ってよい（機能名・パスだけ差し替え）。

```markdown
## テストケースTSV

以下はタブ区切りで、実質はExcelのCSVと同様に、改行や`"`を含むセルはダブルクォートで囲む。

**1行目**が列見出し（先頭列は `機能名`、**テストレベル列なし**）。**2行目以降**がケース（各10列）。`機能名` 列に元設計の表示名を入れる。`テストID`で一意に識別する。優先度は **P1／P2／P3**（[TERMINOLOGY.md](../../skills/integration-test-cases/TERMINOLOGY.md)）。

Excel／Googleスプレッドシートへはコードフェンス内を A1 に貼り付ける。

前提条件・操作手順など、**期待結果以外**の列で複数項目がある場合は、同一セル内でLF改行する。

**期待結果／レスポンスは1行1判定**とする。複数の期待がある場合は行を分割し、**テスト項目名は当該行の判定内容が分かるよう具体化**する。同一シナリオで分割した行は、前提・入力・操作を繰り返してよい。手編集後は `format_tsv.py --check` で列数・ID一意を確認する。
```

### 記載ルール（TSV データ行）

- フェンスは ` ```tsv ` で開始する。
- **1行目**：列見出し。先頭列は `機能名`。通し番号（No）は置かない。
- **データ行**：先頭列に元設計の表示名（例 `管理画面_認証機能`）。全データ行で同一値とする。
- **期待結果列**：1セル1判定。複数UI要素・複数HTTP/DB確認は**別データ行**（[TERMINOLOGY.md](TERMINOLOGY.md)「期待結果とテスト項目名」参照）。
- **テスト項目名列**：行の期待結果と対応する具体名。親シナリオの複合名を全行にコピーしない。
- **前提・入力・操作**：分割行では同一内容の繰り返し可。複数手順はセル内 LF。
- 整形: `expand_expect_rows.py` → `refine_test_item_names.py` → `format_tsv.py`（[SKILL.md](SKILL.md)）。

### TSV 列構成（10列）

ヘッダーは次の通りである（**4列目は `テスト観点`。`I/F種別`・`テストレベル` は使わない**）。

```text
機能名	テストID	I/FID	テスト観点	優先度	テスト項目名	前提条件	入力データ/リクエスト内容	操作手順/実行方法	期待結果／レスポンス
```

| 列 | 記載元 |
|----|--------|
| I/FID | テスト観点.md の **関連ID** |
| テスト観点 | テスト観点.md の **観点** 列 |
| テスト項目名 | 当該行の判定が分かる一文 |

データ行はタブ区切り。各データ行が **ちょうど10列** とする。`format_tsv.py --check` がヘッダ行・機能名の一致も検証する。

### 優先度列

優先度は **[TERMINOLOGY.md](TERMINOLOGY.md) の「優先度（リスク基準）」**に従い、`P1`／`P2`／`P3` のいずれかを入れる。High／Medium／Low は使わない。

## 対象外観点

テスト観点一覧のうち本機能に当てはめない行を表で列挙し、理由を書く。

| 分類・ID | 理由 |
|---------------|------|
| 例 IT-42 | 本機能に検索一覧がない |
