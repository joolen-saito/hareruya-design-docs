# Codexレビュー結果と対応（E2Eテスト生成ハーネス）

codex exec (gpt-5.5, 読み取り専用) で `e2e-test-cases` skill(SKILL/TEMPLATE/CHECKLIST)をレビュー。指摘と対応。

## A オラクル独立性
| 指摘 | 深刻度 | 対応 |
|------|--------|------|
| `Form/Type` をセレクタ源に含め、制約を期待結果へ流用する余地 | 高 | Form/Type は **id/name 確認(セレクタ)のみ**に限定、制約の期待値流用を明示禁止（SKILL入力・CHECKLIST） |
| セレクタ例に file:line が無く規約を自破り | 中 | テンプレ例に `twig:LINE` を付与、Locatorコメントも file:line 必須化 |
| ケース表に仕様根拠列が無くレビュー不能 | 中 | **`仕様根拠(設計書節/行・IT-ID)` 列を追加**（期待結果が仕様由来である証跡） |

## B ハッピー/エラーパス網羅
| 指摘 | 深刻度 | 対応 |
|------|--------|------|
| 判定順序番号・設計書行のマッピング列が無い | 中 | `仕様根拠` 列で判定順序番号/節を記録（第三者が漏れ検出可能に） |
| 観点全行分類の全量照合ができない | 中 | **分類サマリ表(IT-ID別 自動化/手動/対象外件数・未分類0)** を必須化 |
| 境界値が IT-22 前提で設計書側の境界を取りこぼす | 低 | 境界の一次情報源を**設計書の入力項目定義**にも拡張 |

## C 構造整合・実行不可前提
| 指摘 | 深刻度 | 対応 |
|------|--------|------|
| spec雛形が admin fixture/loginPage 固定でフロント不整合 | 高 | **フロントspec雛形(`@playwright/test`直接)を追加**、admin/front別を明記 |
| Page Object が expect を import せず TS が壊れる | 高 | Page Object雛形に **`expect` import を追加**（独立形/fixture経由） |
| AdminAbstractPage 継承形との整合が曖昧 | 中 | **継承形(gotoViaMenu)と独立形の2雛形**を提示 |
| import相対パスが浅い階層前提 | 中 | 相対パス(`../`数)を生成先階層で算出する規則を追記 |

## その他
| 指摘 | 深刻度 | 対応 |
|------|--------|------|
| test.fixme で手動/対象外まで残すとノイズ | 中 | **手動/対象外はケース表で全量管理、specには自動化予定(未実装/要実機確認)のみ fixme** に変更 |
| 1ケース1観測と複合(間接確認)フローの衝突 | 低 | **主観測/副観測の分離ルール**を追加（複合E2Eを限定許容） |

## 総評(codex)
「オラクル独立性・判定順序ごとの異常系・未検証セレクタ明示の重要思想は入っている。ただし Form/Type からの実装由来オラクル混入余地と、Playwright雛形が実構造とずれて壊れる点が修正必須」→ いずれも本対応で是正。
