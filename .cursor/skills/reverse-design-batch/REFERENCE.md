# リバース詳細設計書（バッチ）— 詳細ルール（参照用）

このファイルは Skill 本体を短く保つための補足。作成・レビュー時に必要なら開く。リバース設計の共通原則は [reverse-design の REFERENCE.md](../reverse-design/REFERENCE.md) を正とし、ここではバッチ固有の確認観点だけを足す。

## 守るべき原則（バッチ固有）

1. リバース設計であること — 既存実装のふるまい、対象抽出、判定境界、更新・生成・連携、副作用、再実行の扱いを確認する。コマンド型名・サービス型名の列挙で代替しない。
2. 起点の明示 — 「利用者視点の入口」に実行方法（コマンド名・cron）を実装どおり書く。HTTP の画面を持たない旨を書く。
3. スケジュールは運用を正とする — 起動スケジュールは原則仕様確定しない。実装で確認できる cron 式・ロック・タイムアウトのみ確認値で書く。
4. 冪等性・排他の明示 — 多重実行時の重複防止、再実行時の対象再抽出、ロックの有無を必ず確認する。
5. 秘匿情報の禁止 — パスワード・トークン・接続秘密値・Cookie 値・セッションID完全値を書かない。
6. リポジトリ外の明示 — 起動・処理がインフラ構成にあり確認できない範囲は推測せず「インフラ構成を正とする」と明示する。

## コマンド起動パターン（確認値）

- pf-eccube3 HareruyaEc: `Command/*Batch.php`（カテゴリ別のバッチコマンド）が定数の対応表でジョブ名→サービスを対応づける。起動は `bin/console <category>:batch <jobName> [args]`（例 `order:batch copyOrderNumber`、`product:batch updateProductSummary`）。引数は任意で複数取り得る。サービスは `execute()` を持ち、長時間処理では実行時間制限を解除し、逐次フラッシュ／クリアでメモリを管理することがある。
- EC-CUBE Enterprise コア: Symfony の `#[AsCommand(name: 'eccube:...')]` 属性とコンストラクタ注入。`bin/console eccube:<name>` で起動し、終了コードで成否を返す（例 `eccube:aggregate-sales`）。
- deck-api: `app:redis:save`（Redis のデッキ下書きを DB へ保存）。
- 本文ではコマンド名・ジョブ名を確認値で書き、Command/Service の FQCN は調査補助に留める。

## cron／シェル／インフラ同期（確認値）

- 起動定義は `dockerbuild/eccube/crontab`、処理は `dockerbuild/eccube/file_sync_command.sh` 等のシェルにあることがある。
- S3 同期スクリプトの確認観点: 同期方向（S3→ローカル等）、対象パス、`aws s3 sync` のオプション（`--delete`・`--exact-timestamps` 等）、多重起動防止のロックファイル（例 `/var/tmp/...-sync-lock`）、権限調整（所有者・パーミッション）、キャッシュクリア、変更検知、ログ出力先（CloudWatch 等）。
- cron 式は確認できれば入口に書く。スケジュールの妥当性・運用変更は運用設定を正とする。
- WordPress→S3 転送のように本リポジトリ群に成果物が無いバッチは、推測で書かず「インフラ構成を正とする」と明示し、実装不在なら todo-list 上の扱いをユーザーに確認する。

## 副作用の確認観点

- DB 更新: 対象テーブル・列、更新条件、未反映フラグの更新。
- ファイル生成: 出力パス（設定キー由来か）、形式（CSV／JSON）、ヘッダ行、文字コード・BOM。
- 外部連携: スマレジ等への商品・在庫・取引・ポイント連携。連携の成功・失敗の扱いと再連携の有無。
- 通知: 管理者・会員へのメール送信条件と宛先の決まり方。
- ログ: 開始・終了・件数・例外。秘匿値は出さない。

## 冪等性・再実行・排他（確認観点）

- 対象抽出が「未反映・未連携・期限超過」等の条件で行われ、再実行で重複しないか。
- 多重起動をロックファイル等で防ぐか。防がない場合の同時実行リスク。
- 途中失敗時に部分反映が残るか、次回実行で回収されるか。

## 章構成（必須 / 任意）

| 章 | 区分 | 要点 |
|----|------|------|
| 概要 | 必須 | 目的・起動系統・確認値の出所 |
| 本書で扱うこと / 扱わないこと | 必須 | 範囲。スケジュールは運用を正とする |
| 用語 | 必須 | ドメイン語彙 |
| 利用者視点の入口 | 必須 | 実行方法（コマンド・cron）+ ふるまい |
| 処理フロー | 必須 | 起点ごとに番号付き。対象なし時の早期終了 |
| 業務ルール・計算 | 必須 | 対象・抽出条件・除外・判定順序 |
| 集計条件 | 任意 | 件数・合計・期間集計を行うバッチ |
| API・バッチ結果 | 必須 | 入力・実行条件・成功・失敗・再実行時 |
| 入出力 | 必須 | 生成ファイル・DB 更新・外部連携・通知・副作用 |
| データ整合性 | 必須 | 多重実行・途中失敗・再実行・参照時点 |
| DBカラム | 必須 | 関係する列のみ |
| エラー処理 | 必須 | エラー内容 / 処理 |
| ログ・監査 | 必須 | 記録内容、出してはいけないもの |
| 通知 | 任意 | メール送信を行うバッチ |
| 排他制御・トランザクション | 必須 | ロック・_tx・メモリ管理の有無 |
