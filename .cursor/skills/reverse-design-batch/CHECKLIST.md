# リバース詳細設計書（バッチ）— 出力前チェックリスト

設計書を保存する直前に、以下をすべて確認する。

## スコープ・体裁

- [ ] リバース設計の目的が概要に書かれている（実装手順の代替になっていない）
- [ ] 本書で扱うこと / 扱わないことがある（扱わないものは実装または別機能・運用の設計を正とする旨がある。起動スケジュールは運用を正とすると分けている）
- [ ] 「利用者視点の入口」があり、実行方法（コマンド名・cron 式）が実装に基づき書かれている。HTTP の画面を持たない旨がある
- [ ] Command クラス名・Service クラス名を本文の主説明として列挙していない（grep の手がかりは「調査補助」に一行程度）
- [ ] `され得る` などのあいまい表現を避け、確認できたふるまいは断定し、未確定事項は対象外・確認値・運用として分けている
- [ ] 本文・表セル・箇条書きに Markdown 太字や HTML strong が無い
- [ ] 和文トークン同士、およびコード／英数字記号トークンと直後の助詞のあいだに不要な半角空白が無い（コードフェンス・URL・パス・カンマ列挙は除外）
- [ ] PHP クラス名・例外クラス名・エンティティ短名・サービス短名を主説明にしていない（論理名へ。コマンド名・ジョブ名・テーブル・列・設定キー・cron 式・生成ファイルパスは除外）

## 起動・冪等性・排他

- [ ] 入口に実行方法（コマンド名／cron）があり、コマンド名が一致しないときの挙動が分かる
- [ ] 処理フローがコマンド（または cron）起点で番号付きに追え、対象が無い場合の早期終了が書かれている
- [ ] API・バッチ結果に、入力（引数・設定）・実行条件・成功結果・失敗結果・再実行時の扱いが整理されている
- [ ] 冪等性（多重実行・再実行時の重複防止、未反映条件による再抽出）が明示されている
- [ ] 排他制御（ロックファイル等の有無）が明示されている。長時間処理での実行時間制限・逐次フラッシュ等のメモリ管理が確認値で書かれている（該当バッチのみ）
