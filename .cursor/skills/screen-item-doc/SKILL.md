# 画面項目定義書作成スキル

## 前提

- 常に `.cursor/design/基本設計方針.md` を正とする。
- 画面項目定義書は画面単位で作成し、機能仕様の詳細は含めない。
- 項目名、状態名、表示文言は `.cursor/docs/用語集.md` と既存設計に合わせる。

## 出力先

- 画面一覧: `.cursor/design/html/画面一覧.html`
- 画面項目定義書: `.cursor/design/html/functions/<機能名>/`

## ファイル名

- Markdown版画面項目定義書: `<画面名>_画面項目定義.md`
- HTML版画面項目定義書: `<画面名>_画面項目定義.html`

## 画面項目定義書の構成

1. 文書情報
2. 改訂履歴
3. TODO（未確定項目）
4. 概要
5. 画面項目定義
6. 計算式
7. アクションイベント
8. 特殊系バリデーション
9. 画面イメージ

担当者欄にはAI名ではなく、実際の担当者名または `TODO: 担当者名` を入れる。
文書情報は、`画面ID`、`画面名`、`機能ID`、`作成日`、`担当者` を横1行の表でコンパクトに記載する。

## 表の列順

画面項目定義CSV:

`No.,項目名,種別,I/O,文字種,フォーマット,端数処理,文字揃え,必須,プレースホルダー,最小文字数/最小値,最大文字数/最大値,入力選択肢,データ取得元,初期値,ソート対象,初期ソート,初期活性状態,初期表示状態,ツールチップ表示内容,備考`

計算式CSV:

`No.,参照データパス,式,備考`

アクションイベントCSV:

`No.,項目名,種別,トリガー,イベント動作,遷移先,呼び出しAPI,備考`

Markdown正本のアクションイベントはCSVコードブロックで記載する。`遷移先` には画面名またはURLをテキストで記載し、Markdownリンクは設定しない。HTML閲覧版では、同じ画面項目定義配下に存在する遷移先画面へリンクしてよい。

特殊系バリデーションCSV:

`No.,項目名,バリデーション,バリデーションメッセージ`

## 記載ルール

- 入力は `I`、出力は `O`、表示かつ編集可能な場合のみ `I/O` とする。
- 真偽値は `TRUE` / `FALSE`、該当なし・未確定・適用外は `-` とする。
- HTML閲覧版の真偽値列は `TRUE` を `◯`、`FALSE` を空セルとして表示する。正本の Markdown / CSV は `TRUE` / `FALSE` のまま維持する。
- アクションイベント表の `呼び出しAPI` は、`METHOD /path` 形式を HTML 閲覧版でメソッドチップ + パスに分けて表示する。`-` や未設定はそのまま表示する。パスは `swagger.html` の該当 operation へリンクする。
- 画面項目は、要件定義の入出力仕様を主な根拠にする。
- 入出力仕様にない項目、ボタン、列、状態値は、同じ確認済み画面に対する別の明示要件がある場合だけ追加する。
- アクションやプロセスフローから補った項目は `備考` に根拠を書く。
- 排他制御トークン、バージョン、監査用値など画面に表示しない技術項目は画面イメージに含めない。
- `種別`、`フォーマット`、`トリガー`、`文字種` などは `.cursor/design/UI/画面項目定義選択値.md` の値から選ぶ。
- 項目間、重複、条件付き、複数レコードに関わる検証は特殊系バリデーションへ記載する。

## 画面イメージ

- 画面イメージは実装デザインの正本ではなく、画面構成、項目配置、操作導線を確認するワイヤーフレームとして扱う。
- 画面イメージは、原則としてHTML版画面項目定義書に同一HTML内で静的に埋め込む。
- 単体の画面イメージ用HTMLファイルは作成しない。
- `.cursor/design/UI/画面イメージガイドライン.md` と `doc-html-render` のHTML閲覧版方針を参照する。
- 画面項目定義と画面イメージを紐づける場合は、表の行に `id="item-N"`、画面イメージ上の番号に `id="pin-N"` を付ける。
- 項目名から `#pin-N` へ、番号ピンから `#item-N` へリンクする。
- 番号ピンには `title` と `aria-label` で `No.N 項目名` を設定する。
- HTML閲覧版では、レビュー補助として `:target` により遷移先の番号ピンと表行をハイライトする。
- 画面イメージのプレビュー領域（`.wireframe`）は、文書本文と区別できるよう太枠（4px）・角丸・控えめなシャドウで囲む。内部ワイヤーフレーム自体の装飾はシンプルに保つ。
- 一覧画面は検索フォームを上、一覧テーブルを下に置く。
- 一覧の日時は要件で日付のみと指定されない限り `YYYY/MM/DD HH:mm:ss` とする。

## HTML閲覧版

- HTML版画面項目定義書はMarkdown正本の閲覧版として扱う。
- HTMLだけに仕様内容を追加しない。
- Markdown/CSVとHTMLの列名、列順、行数、No.を一致させる。
- 画面イメージは原則として同一HTML内に静的埋め込みする。

## 画面一覧

- HTML閲覧版のレイアウト、目次、成果物マップ、表の表示は `doc-html-render` の方針に従う。
- 列は `No.`、`領域`、`機能`、`画面名称`、`画面種別`、`タイトル`、`画面ID` とする。
- URL列は設けない。
- `画面名称` にHTML版の画面項目定義書へのリンクを設定する。
- 同一領域・同一機能が続く行は、2行目以降の `領域` と `機能` を空欄にする。
