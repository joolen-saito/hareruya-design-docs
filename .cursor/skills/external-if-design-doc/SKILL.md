# 外部インターフェース仕様書スキル

## 前提

- 常に `.cursor/design/基本設計方針.md` を正とする。
- 外部インターフェース仕様は内部API設計と分けて扱う。
- 外部連携では相手先、責任分界点、障害時の扱いを必ず明記する。

## 出力先

- `.cursor/design/API/外部インターフェース仕様書/`
- 一覧・共通方針: `外部インターフェース仕様書.md` / `外部インターフェース仕様書.html`
- 個別外部IF定義: `<外部IF ID>_<連携名>.md` / `<外部IF ID>_<連携名>.html`

## 記載観点

- 外部IF一覧
- 連携先システム
- 連携目的
- API、ファイル、CSVなどの連携方式
- 送受信タイミング
- リクエスト、レスポンス、ファイル項目
- 文字コード、改行コード
- 認証方式
- リトライ、冪等性、タイムアウト
- エラーコード
- 連携失敗時の復旧方法
- 監査ログ、連携ログ
- 責任分界点

## 注意

- 内部APIのOpenAPI仕様と外部IF仕様を混同しない。
- 外部IFが複数ある場合、一覧・共通方針と個別外部IF定義を分ける。
- 一覧・共通方針には外部IF ID、連携名、連携先、方式、タイミング、関連機能を書く。個別外部IF定義がある場合は、連携名に個別定義へのリンクを設定する。
- HTML閲覧版の一覧でも個別仕様列は設けず、連携名を対応する `.html` へリンクする。未作成の場合はリンクなしの名称とする。
- 個別外部IF定義には連携概要、ファイル/API項目、エラー・リトライ、ログ、責任分界点を書く。
- 外部連携の障害時運用を未記載にしない。
- 機能仕様書には外部連携の契機と概要を書き、詳細は外部IF仕様書へ寄せる。
- 未確定事項は `TODO` に残す。
